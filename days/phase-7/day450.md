
# Day 450 · 支持所有房间连接方向

> Day 447-449 限制了"新房必须比旧房小,在共享墙居中"。今天 Casey 移除这个限制——新房可以任意大小、任意方向、共享墙任意位置。这是迷宫生成的"通用版"。

## 0 · 为什么要有这一天

Day 447 的 `place_adjacent` 有个隐含约束:新房在共享墙方向上居中,假设新房比旧房小。如果你生成的新房比旧房大,会发生什么?

数学上,`bz0 = a.min.z + (a.size().z - b_size.z) * 0.5` 在 `b_size.z > a.size().z` 时变成负偏移。结果是新房的 Z 范围超出旧房,走廊角度对不齐——视觉和寻路都乱。

更糟的是,当两个房间尺寸差别巨大时(比如 5×5 vs 20×20),共享墙的有效范围是"交集"而不是任一个房间的全宽。Day 450 Casey 把"共享墙范围"显式计算出来,把门放在共享范围内,允许任意大小房间的连接。

让我把这个问题彻底讲清楚——它是 Day 447 简化的代价。

**Day 447 的假设**。设旧房 A,新房 B 放在 A 的东边(`A.max.x = B.min.x`)。Day 447 假设 B 的 Z 范围在 A 的 Z 范围内,门在 Z 方向居中:

```
公式:B.min.z = A.min.z + (A.depth - B.depth) / 2
要求:A.depth >= B.depth(否则公式给负偏移)
```

**问题场景 1**:B 比 A 深。

```
A.depth = 8, B.depth = 12
B.min.z = 0 + (8 - 12) / 2 = -2  ← 负数
```

B 的 z 范围是 [-2, 10],A 的 z 范围是 [0, 8]。共享墙的实际范围(两房间 z 都覆盖)是 [0, 8]——A 的全深。B 的 [-2, 0) 和 (8, 10] 是"悬空"——它超出共享墙,玩家从门出去看到的是空旷,怪异。

**问题场景 2**:B 的 Z 方向偏移,门不在中间。

```
        ┌─────────────┐
        │             │
        │      B      │
        │             │
────────┼─────────────┼────────
        │             │
        │      A      │
        │             │
        └─────────────┘
```

共享墙只是 B 的左墙一部分——对应 A 的右墙。门放在 B 左墙中心,可能超出 A 的范围。

**Day 450 的解决方案**:不假设 B 比 A 小,也不假设居中。**显式计算共享墙范围**。

```
共享墙的 Z 范围 = max(A.min.z, B.min.z) to min(A.max.z, B.max.z)
                = "A 和 B 在 Z 轴的投影交集"
```

如果 `max(A.min.z, B.min.z) < min(A.max.z, B.max.z)`,有交集;否则两房间在 Z 轴不重叠,**无共享墙**,连接失败。

**为什么这更重要?** 当迷宫生成随机房间时,房间大小变化大,任意大小连接让生成器更鲁棒——不依赖"恰好小"的运气。工业游戏(如 The Binding of Isaac 的房间)都支持任意大小,这是 procedural generation 的成熟标志。

完成这一天后,你能做到:实现任意大小房间之间的连接(共享墙 = 两个房间投影的交集),并能解释为什么"任意方向 + 任意大小"是迷宫生成器的"通用版",比 Day 447 的简化版更适合工业。

## 2 · 心智模型

### 类比:两块地相邻

两块矩形地相邻,共享一段栅栏。**共享栅栏的范围**取决于两块地的边界。如果 A 地是 [0, 10],B 地是 [5, 15],共享段是 [5, 10]。如果 A 是 [0, 10],B 是 [3, 7],共享段是 [3, 7](B 完全嵌入)。

共享墙是 A 和 B 投影的**交集**,不是任一个的"全宽"。

### 严谨原理:共享墙的范围

设房间 A 在 B 东边(A.min.x = B.max.x)。共享墙是 YZ 平面上的矩形。X 坐标固定(`shared_x = A.min.x = B.max.x`)。Y 和 Z 范围是 A 和 B 在 Y、Z 轴上的投影交集:

让我把"区间交集"这个核心数学操作讲清楚。

**区间交集**。两个一维区间 `[a_lo, a_hi]` 和 `[b_lo, b_hi]`,它们的交集是:

```
intersection = [max(a_lo, b_lo), min(a_hi, b_hi)]
```

如果 `max(a_lo, b_lo) < min(a_hi, b_hi)`,交集非空;否则空。

举例:
- [0, 10] ∩ [5, 15] = [5, 10](部分重叠)
- [0, 10] ∩ [3, 7] = [3, 7](B 完全嵌入 A)
- [0, 10] ∩ [15, 20] = ∅(不重叠)
- [0, 10] ∩ [10, 20] = ∅(只接触,不算重叠)

**Rust 实现**:

```rust
fn interval_intersection(a: (f32, f32), b: (f32, f32)) -> Option<(f32, f32)> {
    let lo = a.0.max(b.0);
    let hi = a.1.min(b.1);
    if lo < hi {
        Some((lo, hi))
    } else {
        None
    }
}
```

**3D 共享墙**。两个房间 A、B 在某个轴上邻接(比如 X 轴),共享墙是 YZ 平面上的矩形。Y、Z 范围 = A 和 B 在 Y、Z 的投影交集。

```rust
fn shared_wall_yz(a: &AABB, b: &AABB) -> Option<((f32, f32), (f32, f32))> {
    let y_range = interval_intersection((a.min.y, a.max.y), (b.min.y, b.max.y))?;
    let z_range = interval_intersection((a.min.z, a.max.z), (b.min.z, b.max.z))?;
    Some((y_range, z_range))
}
```

如果返回 `None`,两个房间在 Y 或 Z 轴不重叠,**无法连接**(技术上可连但玩家走不过)。

**门的位置**。有了共享墙范围,门放在范围内任意位置:

```rust
fn place_door_in_shared_wall(
    shared: ((f32, f32), (f32, f32)),
    door_width: f32,
    door_height: f32,
    offset: f32,  // [0, 1] 决定门在墙上的横向位置
) -> AABB {
    let ((y_lo, y_hi), (z_lo, z_hi)) = shared;
    let z_span = z_hi - z_lo;
    let z_pos = z_lo + offset * (z_span - door_width);
    AABB {
        min: Vec3::new(shared_x, y_lo, z_pos),
        max: Vec3::new(shared_x, y_lo + door_height, z_pos + door_width),
    }
}
```

`offset` 是 [0, 1]:
- `offset = 0`:门贴墙左端
- `offset = 0.5`:门居中(Day 447 风格)
- `offset = 1`:门贴墙右端

工业游戏通常 `offset` 随机,让门位置多样——避免每个走廊都"门居中"的视觉单调。

### 工业迷宫生成器:Room-First 的高级版

Day 450 的"任意大小连接"让 Room-First 算法达到工业可用级别。让我对比下商业游戏的迷宫生成:

**The Binding of Isaac**。每个房间是固定大小的方格(7×7 tile),连接是"门 → 门"。简单但有效——所有房间大小一致,共享墙是房间的整面。

**Spelunky**。房间大小变化但仍然网格对齐。每个房间在网格上占若干 cell,门在 cell 边界。比 Isaac 灵活,比 HH 简单。

**Hades**。手工设计的房间,不是 procedural——每个房间美术精心摆放。procedural 不总是对的,有时手工更好。

**Dark Souls 地下城**。完全手工设计,因为是 narrative-driven 体验。Casey HH 的 procedural 学习适合教学,但商业游戏有时反而回归手工。

**Don't Starve**。地形 procedural(Perlin noise),但 build 和 entity 是手工放置。

**结论**:procedural 适合"无限内容"(Minecraft、Rogue-like),手工适合"精心体验"(叙事游戏)。Casey HH 教学 procedural 是因为它**有挑战**,练算法能力。

### 通用版本的优势

Day 450 后的生成器相比 Day 447 简化版的优势:

1. **房间大小任意**:生成器不再受"小房贴大房"约束,可以生成大房接小房、长走廊接宽厅。

```rust
fn interval_intersect(a_min: f32, a_max: f32, b_min: f32, b_max: f32) -> Option<(f32, f32)> {
    let lo = a_min.max(b_min);
    let hi = a_max.min(b_max);
    if lo < hi {
        Some((lo, hi))
    } else {
        None
    }
}

fn compute_shared_wall_yz(a: &AABB, b: &AABB) -> Option<(Vec3, Vec3)> {
    // 共享墙 X 假设相等(已经邻接)
    let y_range = interval_intersect(a.min.y, a.max.y, b.min.y, b.max.y)?;
    let z_range = interval_intersect(a.min.z, a.max.z, b.min.z, b.max.z)?;
    let shared_x = a.min.x.max(b.min.x).min(a.max.x.min(b.max.x));
    Some((
        Vec3 { x: shared_x, y: y_range.0, z: z_range.0 },
        Vec3 { x: shared_x, y: y_range.1, z: z_range.1 },
    ))
}
```

每行解释:
- `interval_intersect` — 返回交集范围,空则 None。
- `shared_x` — 假设 A 和 B 在 X 方向紧贴,A.min.x == B.max.x,所以 shared_x 就是这个值。
- 共享墙 = `shared_x` 处的 YZ 矩形,范围 `[y_lo, y_hi] × [z_lo, z_hi]`。

### 门在共享墙任意位置

Day 448 的门强制"居中"。Day 450 放宽:门可以在共享墙的任意位置,只要门宽 ≤ 共享墙宽。

```rust
fn place_door_anywhere(
    shared_min: Vec3,
    shared_max: Vec3,
    rng: &mut Pcg32,
    door_width: f32,
    door_height: f32,
) -> Door {
    // 共享墙的 Z 范围
    let z_lo = shared_min.z;
    let z_hi = shared_max.z;
    // 门可以放在 [z_lo, z_hi - door_width] 范围内
    let z_avail = (z_hi - z_lo - door_width).max(0.0);
    let z_offset = rng.next_f32() * z_avail;
    let door_min_z = z_lo + z_offset;
    let door_max_z = door_min_z + door_width;

    Door {
        plane: AxisPlane::YZ,
        center: Vec3 {
            x: shared_min.x,
            y: shared_min.y + door_height * 0.5,
            z: (door_min_z + door_max_z) * 0.5,
        },
        width: door_width,
        height: door_height,
        // ...
    }
}
```

每行解释:
- `z_avail = (z_hi - z_lo - door_width).max(0)` — 门可放置范围,非负。
- `z_offset` 随机决定门在范围内的位置。
- `door_min_z` 是门左边界,`door_max_z = door_min_z + door_width`。

### 验证连接

```rust
fn can_connect(a: &AABB, b: &AABB, door_width: f32) -> bool {
    if let Some((shared_min, shared_max)) = compute_shared_wall_yz(a, b) {
        // 共享墙 Z 范围至少要能容纳门
        (shared_max.z - shared_min.z) >= door_width
    } else {
        false
    }
}
```

每行解释:
- `compute_shared_wall_yz` 返回 None 说明 A 和 B 在 YZ 没共享(垂直分离)。
- 共享墙 Z 宽度 ≥ 门宽才能连接。

### L 形和 T 形连接

Day 450 的算法支持任意方向连接:
- **直线走廊**:A → 东 → B → 东 → C
- **L 形**:A → 东 → B → 北 → C
- **T 形**:A → 东 → B,A → 北 → C(B 和 C 都连 A)
- **十字**:A → 四方向都连

只要每个新房间检查重叠 + 算共享墙,就能生成任意结构。

### 3.1 · 游戏编程视角

工业迷宫生成器还要考虑:

- **房间"重要性"**:boss 房、安全屋特殊,不在随机位置

- **可达性**:每个房间都能到达(DFS / BFS 验证)
- **房间类型**:战斗房、谜题房、商店,各有连接偏好

Casey HH 是简化版,但概念清晰。工业级(如 Spelunky)在这些基础上加约束。

### 3.2 · 图形学视角

共享墙计算在 CSG(构造实体几何)里也常见:

- **CSG 减法**:`A - B` 得到 A 中不在 B 的部分
- **CSG 交集**:`A ∩ B`,类似共享墙
- **CSG 并集**:`A ∪ B`,合并物体

`parry3d` 等库提供完整 CSG。HH 用基本几何(交集区间)就够。

### 3.3 · Linux 系统编程视角

Linux 的"区间交集":
- **`/proc/<pid>/maps`**:多个 `vma_struct` 不重叠,但**映射同一文件的不同段可以共享**
- **`mmap(MAP_SHARED)`**:多个进程映射同一文件,共享页
- **`mremap`**:调整映射大小,可能和邻居冲突

这些场景都要"区间交集/差异"操作,和房间共享墙同构。

### 3.4 · Rust 生态视角

Rust 的区间库:

- `interval` crate:通用区间运算
- `rangemap` / `ininterval`:区间映射
- `parry3d`:3D 几何,含 AABB 交集

HH 手写简单区间操作,适合教学。

完整通用迷宫生成器:

```rust
#[derive(Debug, Clone, Copy)]
struct Vec3 { x: f32, y: f32, z: f32 }

#[derive(Debug, Clone, Copy)]
struct AABB { min: Vec3, max: Vec3 }

impl AABB {
    fn size(&self) -> Vec3 {
        Vec3 {
            x: self.max.x - self.min.x,
            y: self.max.y - self.min.y,
            z: self.max.z - self.min.z,
        }
    }
}

fn interval_intersect(a_min: f32, a_max: f32, b_min: f32, b_max: f32) -> Option<(f32, f32)> {
    let lo = a_min.max(b_min);
    let hi = a_max.min(b_max);
    if lo < hi { Some((lo, hi)) } else { None }
}

// 计算两个房间(A 在东、B 在西)的共享墙 YZ 矩形
fn shared_wall_yz(a: &AABB, b: &AABB) -> Option<AABB> {
    let y_range = interval_intersect(a.min.y, a.max.y, b.min.y, b.max.y)?;
    let z_range = interval_intersect(a.min.z, a.max.z, b.min.z, b.max.z)?;
    // X 假设 a.min.x == b.max.x
    let shared_x = a.min.x;
    Some(AABB {
        min: Vec3 { x: shared_x, y: y_range.0, z: z_range.0 },
        max: Vec3 { x: shared_x, y: y_range.1, z: z_range.1 },
    })
}

const DOOR_WIDTH: f32 = 1.5;
const DOOR_HEIGHT: f32 = 2.5;

struct Pcg32 { state: u64, inc: u64 }
impl Pcg32 {
    fn new(seed: u64, seq: u64) -> Self {
        let mut r = Self { state: 0, inc: (seq << 1) | 1 };
        r.next();
        r.state = r.state.wrapping_add(seed);
        r.next();
        r
    }
    fn next(&mut self) -> u32 {
        let old = self.state;
        self.state = old.wrapping_mul(6364136223846793005).wrapping_add(self.inc);
        let xs = (((old >> 18) ^ old) >> 27) as u32;
        let rot = (old >> 59) as u32;
        (xs >> rot) | (xs << ((!rot).wrapping_add(1) & 31))
    }
    fn next_f32(&mut self) -> f32 { self.next() as f32 / u32::MAX as f32 }
}

fn place_door_anywhere(rng: &mut Pcg32, wall: &AABB) -> (f32, f32, f32) {
    // 返回 (door_min_z, door_max_z, door_top_y)
    let z_lo = wall.min.z;
    let z_hi = wall.max.z;
    let z_avail = (z_hi - z_lo - DOOR_WIDTH).max(0.0);
    let z_offset = rng.next_f32() * z_avail;
    let door_min_z = z_lo + z_offset;
    let door_max_z = door_min_z + DOOR_WIDTH;
    (door_min_z, door_max_z, wall.min.y + DOOR_HEIGHT)
}

fn main() {
```

## 10 · 补充:区间代数与工业碰撞引擎

数学上,Day 450 处理的是"两个区间在共享维度上的交集"问题。让我推广这个抽象,因为它在游戏几何里反复出现。

**区间代数**。一维区间 `[a, b]` 和 `[c, d]`(假设 `a < b, c < d`):

- **交集**:`[max(a,c), min(b,d)]`(可能空)
- **并集**(连续时):`[min(a,c), max(b,d)]`
- **差集 A - B**:可能是一个或两个区间

**3D AABB 的"广义共享"**。两个任意 AABB A 和 B:

- X 方向:`interval_intersection(A.x, B.x)`
- Y 方向:`interval_intersection(A.y, B.y)`
- Z 方向:`interval_intersection(A.z, B.z)`

三个方向都有交集 → A 和 B 的"广义共享"是个 AABB(它们的体积交集)。三个方向都不交集 → A 和 B 完全分离。

**Day 450 的特例**:A 和 B 在 X 方向"精确接触"(`A.max.x == B.min.x`),所以 X 方向交集是空(单点不算)。Y 和 Z 方向的交集定义共享墙。

**推广**。这个抽象适用于:

- **碰撞检测**:两 AABB 是否相交(三个区间都相交)
- **共享面**:两 AABB 是否共享面(一个区间精确接触,另两个相交)
- **共享边**:两个区间精确接触,一个相交(2D 共享点 / 3D 共享线)
- **共享点**:三个区间都精确接触(角对角)

工业游戏引擎(BepuPhysics、PhysX)内部大量用这些区间代数操作。理解这个抽象让你能读它们的源码——看起来复杂的"碰撞矩阵"本质就是区间操作。

**多房间走廊的拓扑保证**。Day 450 的"任意大小连接"还隐含一个拓扑问题:**当生成 5 个房间链时,怎么保证连通**?

```
R1 ─ R2 ─ R3 ─ R4 ─ R5
```

每个箭头是一对 `place_adjacent + 凿门`。连通性来自:

1. 每个新房间 R(i+1) 都 attach 到已有房间 R(i)
2. attach 时共享墙被凿门(玩家可通行)
3. 因此 R(1) 到 R(N) 是路径

**问题**:如果生成失败(比如重叠),链接断开。R3 没接到 R4,链断在 R3。这是"链状生成"的脆弱性。

**工业解决方案**:

- **Backtracking**:失败时回退到 R2,换 R3 的位置再试
- **Graph-based**:先确定房间图(R1 → R2 → R3 → ...),然后逐个 place
- **Constraint Propagation**:维护"已放置房间"集合,新房间 place 时检测所有约束

Casey HH 在 Day 450 用简单 retry——失败就跳过,接受链可能断。商业游戏必然用 graph-based 或更复杂方案。

### 算法正确性的形式化验证

工业级 procedural generation 通常配测试套件,验证算法的几个性质:

**性质 1:连通性**。生成的房间图必须连通(从任意房间可走到任意其他房间)。

测试:对生成的迷宫跑 BFS/DFS,看是否能遍历所有房间。

```rust
fn is_connected(rooms: &[Room], connections: &[Connection]) -> bool {
    if rooms.is_empty() { return true; }
    let mut visited = HashSet::new();
    let mut queue = vec![0];
    visited.insert(0);
    while let Some(i) = queue.pop() {
        for c in connections.iter().filter(|c| c.a == i || c.b == i) {
            let neighbor = if c.a == i { c.b } else { c.a };
            if visited.insert(neighbor) {
                queue.push(neighbor);
            }
        }
    }
    visited.len() == rooms.len()
}
```

**性质 2:无重叠**。任何两个房间 AABB 不相交。

```rust
fn no_overlap(rooms: &[AABB]) -> bool {
    for i in 0..rooms.len() {
        for j in (i+1)..rooms.len() {
            if rooms[i].intersects(&rooms[j]) {
                return false;
            }
        }
    }
    true
}
```

**性质 3:种子可复现**。同一种子永远生成同一迷宫。

```rust
#[test]
fn seed_reproducibility() {
    let r1 = generate_world(42);
    let r2 = generate_world(42);
    assert_eq!(r1, r2);
}
```

**性质 4:分布均匀**。生成的房间大小、方向分布均匀(没有偏好)。

测试:生成 10000 个迷宫,统计房间大小直方图,看是否符合预期分布。

工业 procedural generation 库(如 Unity 的 PCG、Unreal 的 PCG Graph)都内置这些验证。Casey HH 教学简化,但理解这些性质是工业实践的基础。

**Fuzzing 测试**。除了显式性质,工业用 fuzz testing——喂大量随机种子,看是否有崩溃或 invariant 违反:
