# Day 494 · 为对齐点准备实体部件

> 一个"骑士"实体不只是 sprite——它有头、身体、左手、右手、剑、盾。每个部件有"连接点"——头连到脖子,手连到肩膀,剑连到手。Day 494 给 entity 加"alignment point"(对齐点)系统:每个部件可以声明"我连在父部件的哪个点上"。

## 0 · 为什么要有这一天

到目前为止,HH 的 entity 都是一个 sprite:画一个图,移动它,搞定。但真正游戏的角色是**分层**的:

- **骑马的角色**:角色 + 马,两层 sprite,马的腿动不影响角色上半身。
- **拿武器的角色**:角色 + 武器,武器从手的位置开始画,手抬起来武器跟着抬。
- **装备系统**:玩家换装备,只换"胸甲 sprite",其他不动。

这种"部件化"的角色叫 **paper doll**(纸娃娃)系统,或 **layered sprite**。每件装备是一个 sprite layer,按顺序叠加。

每个 layer 有"挂载点"——胸甲挂在角色的"chest"点,头盔挂在"head"点,武器挂在"hand"点。这些点叫 **alignment point**(对齐点)或 **attachment point**(挂载点)或 **socket**(插槽)。

Day 494 做的事:**给 entity 数据结构加 alignment point 字段**,为 Day 495 的 UI 编辑做准备。

为什么必须先准备数据结构?因为 UI 编辑器操作的是数据。如果 entity 没有 alignment point 字段,UI 怎么编辑?所以**先扩字段,再做 UI**。这是 Casey 反复强调的"data first"原则——先有数据,后有 UI。

完成这一天,你能:

- 设计 paper doll 系统(layered sprite)
- 用相对坐标(相对于父部件)表达 attachment
- 设计 entity 数据结构的扩展(向后兼容)
- 理解 forward kinematics(正向运动学)基础——子部件跟随父部件变换

第三步,他写 "compute_world_transform" 函数:递归算每个 piece 的世界变换。

```rust
fn compute_world_transform(piece_id: EntityPieceId, pieces: &[EntityPiece]) -> Transform {
    let piece = &pieces[piece_id];
    match &piece.parent_attachment {
        None => Transform::translation(piece.offset),
        Some((parent_id, parent_point_name)) => {
            let parent_transform = compute_world_transform(*parent_id, pieces);
            let parent = &pieces[*parent_id];
            let point = parent.alignment_points.iter()
                .find(|p| &p.name == parent_point_name).unwrap();
            parent_transform
                .then_translate(point.offset)
                .then_translate(piece.offset)
        }
    }
}
```

第四步,他给现有 entity 加默认 alignment point:每个 entity 有 "center"(中心)、"top"(顶部)、"bottom"(底部)三个标准点。

第五步,他验证:简单 entity(1 piece)和复杂 entity(3 pieces)都能正确渲染。

第六步,他为 Day 495 的 UI 编辑预留接口:`get_alignment_points(piece_id)`、`set_alignment_point_offset(piece_id, name, new_offset)` 等。

## 2 · 心智模型

### 类比:乐高人偶

想象一个乐高人偶:头、身体、左手、右手、腿。每个部件有"接口"——头下面有个圆洞,身体上面有个圆点,头插到身体上。

乐高的接口就是 **alignment point**。每个部件声明"我有什么接口"(我提供的 alignment points)和"我连到哪"(parent_attachment)。

更复杂的:右手拿剑——剑也有接口(柄的尾部),插到右手的"握把"点上。

这就是 paper doll 系统的本质:**层次化的部件 + 命名接口**。

### 层次化 vs 扁平化

两种设计:

**扁平化**:每个 entity 是一个 sprite,所有部件画在一起。换装备 = 换 sprite。

**层次化**:每个 entity 是部件树,每个部件独立 sprite。换装备 = 换某个 piece。

扁平化简单,但不灵活。层次化复杂,但灵活——可以单独动某个 piece(角色挥手时只手动,身体不动)。

Casey Day 494 选层次化,因为后面 Day 540+ 要做装备系统、动态姿势(角色受伤时上半身前倾)。

### 相对坐标 vs 绝对坐标

Alignment point 用**相对坐标**——相对于父 piece 的某个固定点(通常是 piece 原点)。

为什么不用绝对坐标(直接存世界坐标)?因为:

1. **复用**:同一个 piece 在不同 entity 里用,绝对坐标没意义;相对坐标有意义。
2. **变换继承**:父 piece 移动,子 piece 跟着——相对坐标自动正确,绝对坐标要重算。
3. **编辑直观**:设计者想"头在脖子正上方",直接设 `offset = (0, -10)`,不用算世界坐标。

### Forward Kinematics(正向运动学)

层次化部件的位置计算叫 forward kinematics(FK)——从根开始,逐层算子部件的世界位置。

```
root_piece: 世界位置 (10, 20)
    └ child_a: parent_alignment_point = "right_shoulder"
              alignment_points["right_shoulder"] = (5, -10) 相对 root
              → 世界位置 = (10+5, 20-10) = (15, 10)
              自己的 offset = (0, 0)
              → 最终世界位置 = (15, 10)
        └ grandchild: parent_alignment_point = "tip"
                      alignment_points["tip"] = (20, 0) 相对 child_a
                      → 世界位置 = (15+20, 10+0) = (35, 10)
```

每个 piece 的世界位置 = 父世界位置 + 父 alignment point 偏移 + 自己的 offset。

数学公式:

```
world_pos(piece) = world_pos(parent) + parent.alignment_point.offset + piece.offset
```

递归。

逆向(Inverse Kinematics,IK)反过来:给定目标位置,算每个 piece 的角度。复杂得多,Day 494 不做。

### 变换矩阵的链式

如果 piece 还有旋转 / 缩放,简单加法不够,要用矩阵:

```
world_transform(piece) = world_transform(parent) * T(parent.alignment_point.offset) * T(piece.offset) * R(piece.rotation)
```

每个 piece 的局部变换(local transform)是 Translation + Rotation + Scale。世界变换(world transform)是父世界变换乘以自己的局部变换。

矩阵乘法不交换:`A * B ≠ B * A`。所以变换链顺序很重要:**先 translate 再 rotate** 不等于 **先 rotate 再 translate**。

Casey Day 494 简化只做 translation,不做 rotation。Day 540+ 加 rotation。

### 3.1 · 🎮 游戏编程视角

Paper doll 系统在游戏开发圈是标配。

**RPG 装备系统**:《暗黑破坏神》《魔兽世界》玩家的装备显示就是 paper doll。每个装备 slot(head、chest、legs、feet、main_hand、off_hand)是一个 attachment point。

**2D 骨骼动画**:Spine、DragonBones 是工业化工具。每个 bone 是一个 piece,bone 之间用 attachment point 连。动画 = 时间线上每个 bone 的旋转 / 位移。

**3D 骨骼**:3D 模型有 skeleton(骨骼),bone 是 piece。同样的层次结构。glTF 的 `skin` 和 `node` hierarchy 表达这个。

**Mod 系统**:Bethesda 游戏(《上古卷轴》《辐射》)的 mod 工具有"object hierarchy",玩家可以编辑 attachment。

游戏开发圈术语:

- **Bone**:骨骼,3D 角色的层次部件
- **Socket**:插槽,attachment point 的别名(Unreal 用这个)
- **Hardpoint**:挂点,武器 / 道具的 attachment(军事模拟游戏用)
- **Mount**:坐骑系统,角色 mount 到马上,马是 parent

### 3.2 · 🎨 图形学视角

层次化变换是图形学核心概念。

**Scene graph**(场景图):3D 引擎用 scene graph 组织物体,每个节点有 local transform,世界变换递归算。Unity、Unreal、Godot 都有 scene graph。

**Matrix stack**:OpenGL 1.x 有 `glPushMatrix/glPopMatrix`,手动维护变换栈。现代 OpenGL 用 shader + uniform 传 world matrix。

**Skinning**:3D 角色动画,每个 vertex 受多个 bone 影响(skinning weight),公式:

```
v_world = sum(w_i * M_i * v_local) for each influencing bone i
```

`w_i` 是 weight,`M_i` 是 bone i 的 world matrix。

**glTF node hierarchy**:glTF 规范里每个 node 有 `children` 数组,`matrix` 或 `translation/rotation/scale`。一个 glTF 模型就是一个 piece 树。

Casey Day 494 的 piece 树和 glTF node tree 同构。理解这个,看 glTF 规范秒懂。

### 3.3 · 🐧 Linux 系统编程视角

层次化结构在 Linux 系统里到处都是。

**进程树**:每个进程有 parent(`getppid()`),子进程 fork 后默认继承 parent 的环境变量、文件描述符。和 piece 树同构——子进程的"环境"相对 parent 算。


**文件系统**:`/usr/share/doc/bash/` 是层次化路径,每个目录相对父目录。

**DBus 对象路径**:`/org/freedesktop/Notifications`,层次化命名。

**CGroup hierarchy**:cgroup v2 是树状,子 cgroup 继承父的限制。

这些系统都遵循相同模式:**层次 + 相对 + 继承**。 Casey 的 piece 系统是这种模式在游戏数据上的体现。

### 3.4 · 🦀 Rust 生态视角

Rust 表达层次化数据结构有几种方式。

**索引而非指针**:`Vec<Piece>` + `piece_id: usize`。避免循环引用(borrow checker 难处理)。

```rust
struct Entity {
    pieces: Vec<Piece>,
}

struct Piece {
    id: usize,
    parent: Option<usize>,    // 父 piece 的 index
    parent_alignment_point: Option<String>,
    offset: Vec2,
    alignment_points: Vec<AlignmentPoint>,
}
```

**Slot map**:`slotmap` crate,带 generational index,删除后 ID 自动失效。比 `usize` 安全。

**Arena**:`typed_arena` 或自建 arena,分配的 piece 不会 move。

**递归计算**:用迭代而非递归避免栈溢出(piece 树很深时)。拓扑排序 piece(父先于子),再迭代计算。

```rust
fn topo_sort(pieces: &[Piece]) -> Vec<usize> {
    // 拓扑排序:parent 在 child 之前
    let mut order = Vec::new();
    let mut visited = vec![false; pieces.len()];
    
    fn visit(idx: usize, pieces: &[Piece], visited: &mut [bool], order: &mut Vec<usize>) {
        if visited[idx] { return; }
        visited[idx] = true;
        if let Some(parent) = pieces[idx].parent {
            visit(parent, pieces, visited, order);
        }
        order.push(idx);
    }
    
    for i in 0..pieces.len() {
        visit(i, pieces, &mut visited, &mut order);
    }
    
    order
}
```

Rust 编译器考验:`compute_world_transform` 递归读 `&pieces`,但同一个函数内可能要 mutate——必须先收集 IDs,再迭代 mutate。

```rust
// 错:同时借 &pieces 和 &mut pieces
fn update(pieces: &mut [Piece]) {
    for p in pieces.iter() {
        let parent_pos = pieces[p.parent.unwrap()].world_pos;  // 借 &pieces
        p.world_pos = parent_pos + p.offset;                  // 借 &mut pieces
    }
}

// 对:迭代而非递归,且分两步
fn update(pieces: &mut [Piece]) {
    let order = topo_sort(pieces);
    for &i in &order {
        let parent_pos = pieces[i].parent
            .map(|p| pieces[p].world_pos);   // 这里借 &pieces
        // 然后单独 mutate
        let parent_pos = parent_pos.unwrap_or(Vec2::ZERO);
        pieces[i].world_pos = parent_pos + pieces[i].offset;
    }
}
```

## 5 · 对照与变奏

Paper doll 系统在不同游戏类型的表现。

**JRPG**(《勇者斗恶龙》《最终幻想》):角色 paper doll + 装备 paper doll。换装备立即显示。

**Action RPG**(《暗黑破坏神》):同上,加上动作动画(挥剑、施法)。每个动作有 bone 动画。

**Fighting game**(《街头霸王》):最复杂的 paper doll——每个角色的每帧都是手工调整的 bone 姿势。

**Sandbox game**(《Minecraft》):简化版,玩家头是单独 cube,身体是 cube,四肢是 cube。换装备换 layer。

**Strategy game**(《文明》《星际》):单位简单 sprite,不做 paper doll。换装备不显示。

历史演化:

- **1980s**:单 sprite,固定姿势。
- **1990s**:多层 sprite(SNES RPG),装备分层。
- **2000s**:骨骼动画(Flash、《魔兽世界》)。
- **2010s**:实时骨骼 + 物理(布料、头发)。
- **2020s**:机器学习动画(NPC 自动姿势)。

跨领域对照:

- **CAD 装配**:SolidWorks 装配体,每个 part 相对 mate 装。同构。
- **机器人学**:机械臂的 joint chain,FK 算末端位置。
- **网页 DOM**:HTML 元素树,子元素 position 相对父。
- **音频效果链**:吉他效果器串联,信号从前级→失真→混响。线性 chain(无分支)。

学会 piece 树 + alignment point 抽象,任何"层次 + 相对位置"问题都能秒解。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 alignment point 用"相对偏移"而不是"绝对位置"?

**参考解答**:三个理由:

第一,**复用**。一个 piece(比如"剑")在不同 entity(战士、盗贼、法师)里都用。绝对位置每个 entity 都要重设;相对位置一处定义,各处复用。

第二,**变换继承**。父 piece 移动,子 piece 自动跟随——相对坐标数学上自动正确(子世界 = 父世界 + 偏移)。绝对坐标要每帧重新指定,容易出错。

第三,**编辑直观**。设计者想"剑在右手掌心",直接设 `offset = (5, 0)`(右手掌心右偏 5 像素),不用算 entity 在世界哪里。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现最小 piece 树。entity 有 3 个 piece:body、head、sword。head 连到 body 的 "neck" point,sword 连到 body 的 "hand_r" point。计算每个 piece 的世界位置,println 出来。

完成标准:`cargo run` 输出 3 个 piece 的世界位置,符合手算结果。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    const fn new(x: f32, y: f32) -> Self { Self { x, y } }
    const ZERO: Self = Self::new(0.0, 0.0);
}

impl std::ops::Add for Vec2 {
    type Output = Vec2;
    fn add(self, o: Vec2) -> Vec2 { Vec2::new(self.x + o.x, self.y + o.y) }
}

#[derive(Clone, Debug)]
struct AlignmentPoint {
    name: String,
    offset: Vec2,
}

#[derive(Clone, Debug)]
struct Piece {
    name: String,
    offset: Vec2,                       // 相对于父 alignment point 的偏移
    alignment_points: Vec<AlignmentPoint>,
    parent: Option<(usize, String)>,    // (父 piece index, 父 alignment point name)
    world_pos: Vec2,                    // 计算结果
}

struct Entity {
    pieces: Vec<Piece>,
}

impl Entity {
    fn compute_world_transforms(&mut self) {
        // 拓扑排序:parent 在 child 前
        let order = self.topo_sort();
        
        for &i in &order {
            let (parent_idx, parent_point_name, my_offset) = {
                let p = &self.pieces[i];
                match &p.parent {
                    None => {
                        // root:世界位置 = self.offset
                        let world = self.pieces[i].offset;
                        self.pieces[i].world_pos = world;
                        continue;
                    }
                    Some((pi, pn)) => (*pi, pn.clone(), p.offset),
                }
            };
            
            let parent_world = self.pieces[parent_idx].world_pos;
            let parent_point_offset = self.pieces[parent_idx].alignment_points
                .iter()
                .find(|ap| &ap.name == &parent_point_name)
                .map(|ap| ap.offset)
                .expect("parent alignment point not found");
            
            self.pieces[i].world_pos = parent_world + parent_point_offset + my_offset;
        }
    }
    
    fn topo_sort(&self) -> Vec<usize> {
        let mut order = Vec::new();
        let mut visited = vec![false; self.pieces.len()];
        
        fn visit(idx: usize, pieces: &[Piece], visited: &mut [bool], order: &mut Vec<usize>) {
            if visited[idx] { return; }
            visited[idx] = true;
            if let Some((parent, _)) = &pieces[idx].parent {
                visit(*parent, pieces, visited, order);
            }
            order.push(idx);
        }
        
        for i in 0..self.pieces.len() {
            visit(i, &self.pieces, &mut visited, &mut order);
        }
        
        order
    }
}

fn main() {
    let mut entity = Entity {
        pieces: vec![
            Piece {
                name: "body".into(),
                offset: Vec2::new(100.0, 100.0),   // entity 原点
                alignment_points: vec![
                    AlignmentPoint { name: "neck".into(), offset: Vec2::new(0.0, -20.0) },
                    AlignmentPoint { name: "hand_r".into(), offset: Vec2::new(15.0, 0.0) },
                ],
                parent: None,
                world_pos: Vec2::ZERO,
            },
            Piece {
                name: "head".into(),
                offset: Vec2::new(0.0, 0.0),       // 正好挂在 neck 上
                alignment_points: vec![],
                parent: Some((0, "neck".into())),
                world_pos: Vec2::ZERO,
            },
            Piece {
                name: "sword".into(),
                offset: Vec2::new(2.0, 0.0),       // hand_r 偏右 2
                alignment_points: vec![],
                parent: Some((0, "hand_r".into())),
                world_pos: Vec2::ZERO,
            },
        ],
    };
    
    entity.compute_world_transforms();
    
    for p in &entity.pieces {
        println!("{}: world_pos = ({}, {})", p.name, p.world_pos.x, p.world_pos.y);
    }
    
    // 验证:
    // body: (100, 100)
    // head: 100 + 0(neck.x), 100 + (-20)(neck.y) + 0(offset) = (100, 80)
    // sword: 100 + 15(hand_r.x) + 2(offset) = 117, 100 + 0 + 0 = 100
    println!("\n预期:");
    println!("  body:  (100, 100)");
    println!("  head:  (100, 80)");
    println!("  sword: (117, 100)");
}
```

为什么这么写:`topo_sort` 确保父先算。`parent: Option<(usize, String)>` 表达 piece 间的连接。每个 piece 的 world_pos 由父的 world_pos + 父 alignment point offset + 自己 offset 算出。

### Lv3 · 迁移设计(换场景用同一原理)

**题**:把"piece 树 + alignment point"迁移到**电路板设计**。设计:PCB 有 component,component 有 pin(类似 alignment point)。Component 之间通过 pin 连接(类似 parent_attachment)。如何表达?如何算每个 component 在 PCB 上的位置?

**提示**:Altium / KiCad 的 schematic 和 PCB 视图就是这种结构。component = piece,pin = alignment point,net = connection。

```rust
// ============================================================
// Day 494 · 为对齐点准备实体部件
// ============================================================

use std::fmt;

// ============================================================
// 数学
// ============================================================

#[derive(Copy, Clone, Debug, PartialEq)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    const fn new(x: f32, y: f32) -> Self { Self { x, y } }
    const ZERO: Self = Self::new(0.0, 0.0);
}

impl std::ops::Add for Vec2 {
    type Output = Vec2;
    fn add(self, o: Vec2) -> Vec2 { Vec2::new(self.x + o.x, self.y + o.y) }
}

impl std::ops::Sub for Vec2 {
    type Output = Vec2;
    fn sub(self, o: Vec2) -> Vec2 { Vec2::new(self.x - o.x, self.y - o.y) }
}

impl fmt::Display for Vec2 {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "({:.1},{:.1})", self.x, self.y)
    }
}

// ============================================================
// Piece system
// ============================================================

#[derive(Clone, Debug)]
struct AlignmentPoint {
    name: String,
    offset: Vec2,
}

impl AlignmentPoint {
    fn new(name: &str, x: f32, y: f32) -> Self {
        Self { name: name.to_string(), offset: Vec2::new(x, y) }
    }
}

#[derive(Clone, Debug, PartialEq, Eq, Hash, Copy)]
struct PieceId(usize);

#[derive(Clone, Debug)]
struct Piece {
    id: PieceId,
    name: String,
    sprite_name: String,
    offset: Vec2,                        // 相对父 alignment point 的偏移
    alignment_points: Vec<AlignmentPoint>,
    parent: Option<(PieceId, String)>,   // (父 piece ID, 父 alignment point 名)
    world_pos: Vec2,                     // 计算缓存
}

impl Piece {
    fn new(id: PieceId, name: &str, sprite: &str, offset: Vec2) -> Self {
        Self {
            id, name: name.into(), sprite_name: sprite.into(), offset,
            alignment_points: Vec::new(),
            parent: None,
            world_pos: Vec2::ZERO,
        }
    }
    
    fn with_alignment_points(mut self, points: Vec<AlignmentPoint>) -> Self {
        self.alignment_points = points;
        self
    }
    
    fn with_parent(mut self, parent_id: PieceId, point_name: &str) -> Self {
        self.parent = Some((parent_id, point_name.into()));
        self
    }
    
    fn find_point(&self, name: &str) -> Option<&AlignmentPoint> {
        self.alignment_points.iter().find(|p| p.name == name)
    }
}

struct PieceTree {
    pieces: Vec<Piece>,
}

impl PieceTree {
    fn new() -> Self { Self { pieces: Vec::new() } }
    
    fn add(&mut self, piece: Piece) -> PieceId {
        let id = piece.id;
        self.pieces.push(piece);
        id
    }
    
    fn get(&self, id: PieceId) -> &Piece { &self.pieces[id.0] }
    fn get_mut(&mut self, id: PieceId) -> &mut Piece { &mut self.pieces[id.0] }
    
    // 拓扑排序:parent 先于 child
    fn topo_order(&self) -> Vec<usize> {
        let mut order = Vec::new();
        let mut visited = vec![false; self.pieces.len()];
        
        for start in 0..self.pieces.len() {
            if !visited[start] {
                self.visit(start, &mut visited, &mut order);
            }
        }
        
        order
    }
    
    fn visit(&self, idx: usize, visited: &mut [bool], order: &mut Vec<usize>) {
        if visited[idx] { return; }
        visited[idx] = true;
        
        if let Some((parent, _)) = &self.pieces[idx].parent {
            self.visit(parent.0, visited, order);
        }
        
        order.push(idx);
    }
    
    fn compute_world_transforms(&mut self) {
        let order = self.topo_order();
        
        for &i in &order {
            let (parent_world, parent_point_offset, my_offset) = {
                let p = &self.pieces[i];
                match &p.parent {
                    None => {
                        // root:世界位置 = offset(相对 entity 原点)
                        self.pieces[i].world_pos = p.offset;
                        continue;
                    }
                    Some((parent_id, point_name)) => {
                        let parent = self.get(*parent_id);
                        let parent_world = parent.world_pos;
                        let point_offset = parent.find_point(point_name)
                            .map(|p| p.offset)
                            .unwrap_or(Vec2::ZERO);
                        (parent_world, point_offset, p.offset)
                    }
                }
            };
            
            self.pieces[i].world_pos = parent_world + parent_point_offset + my_offset;
        }
    }
    
    // 标准 alignment points(每个 piece 默认有)
    fn standard_points() -> Vec<AlignmentPoint> {
        vec![
            AlignmentPoint::new("center", 0.0, 0.0),
            AlignmentPoint::new("top", 0.0, -10.0),
            AlignmentPoint::new("bottom", 0.0, 10.0),
            AlignmentPoint::new("left", -10.0, 0.0),
            AlignmentPoint::new("right", 10.0, 0.0),
        ]
    }
}

// ============================================================
// Entity(包含 piece tree)
// ============================================================

struct Entity {
    name: String,
    world_offset: Vec2,    // entity 在世界里的位置
    pieces: PieceTree,
}

impl Entity {
    fn new(name: &str, world_offset: Vec2) -> Self {
        Self { name: name.into(), world_offset, pieces: PieceTree::new() }
    }
    
    fn compute_world_transforms(&mut self) {
        // 先把 root piece 的 offset 加上 entity world_offset
        // (简化:这里假设 root piece 是 pieces[0])
        if !self.pieces.pieces.is_empty() {
            let original_offset = self.pieces.pieces[0].offset;
            self.pieces.pieces[0].offset = original_offset + self.world_offset;
            self.pieces.compute_world_transforms();
            self.pieces.pieces[0].offset = original_offset;
        }
    }
}

// ============================================================
// 示例:骑士 entity
// ============================================================

fn make_knight() -> Entity {
    let mut e = Entity::new("knight", Vec2::new(50.0, 50.0));
    
    // body piece(root)
    let body_id = e.pieces.add(
        Piece::new(PieceId(0), "body", "knight_body", Vec2::new(0.0, 0.0))
            .with_alignment_points(vec![
                AlignmentPoint::new("neck", 0.0, -20.0),
                AlignmentPoint::new("hand_r", 15.0, 0.0),
                AlignmentPoint::new("hand_l", -15.0, 0.0),
                AlignmentPoint::new("foot_r", 8.0, 25.0),
                AlignmentPoint::new("foot_l", -8.0, 25.0),
            ])
    );
    
    // head piece
    let head_id = e.pieces.add(
        Piece::new(PieceId(1), "head", "knight_head", Vec2::new(0.0, 0.0))
            .with_parent(body_id, "neck")
    );
    
    // sword piece
    let sword_id = e.pieces.add(
        Piece::new(PieceId(2), "sword", "iron_sword", Vec2::new(2.0, 0.0))
            .with_parent(body_id, "hand_r")
    );
    
    // shield piece
    let shield_id = e.pieces.add(
        Piece::new(PieceId(3), "shield", "wood_shield", Vec2::new(-2.0, 0.0))
            .with_parent(body_id, "hand_l")
    );
    
    e
}

// ============================================================
// 渲染(简化为 println)
// ============================================================

fn render_entity(e: &Entity) {
    println!("Entity '{}' at world {}:", e.name, e.world_offset);
    
    // 排序:parent 先,这样视觉上 root 在上
    for p in &e.pieces.pieces {
        let parent_str = match &p.parent {
            None => "(root)".to_string(),
            Some((pid, pn)) => format!("parent={:?} via {}", pid, pn),
        };
        println!("  piece {:?} '{}' sprite={} offset={} {}",
                 p.id, p.name, p.sprite_name, p.offset, parent_str);
        if !p.alignment_points.is_empty() {
            println!("    alignment_points:");
            for ap in &p.alignment_points {
                println!("      {}: {}", ap.name, ap.offset);
            }
        }
        println!("    -> world_pos = {}", p.world_pos);
    }
}

// ============================================================

fn main() {
    println!("=============================================\n");
    println!(" Day 494 · 为对齐点准备实体部件\n");
    println!("=============================================\n");
    
    let mut knight = make_knight();
    knight.compute_world_transforms();
    render_entity(&knight);
    
    println!("\n--- 验证 ---\n");
    // body world = entity_world + body_offset = (50, 50) + (0, 0) = (50, 50)
    let body = knight.pieces.get(PieceId(0));
    println!("body world: {} (预期 50,50)", body.world_pos);
    
    // head world = body_world + neck_offset + head_offset = (50, 50) + (0, -20) + (0, 0) = (50, 30)
    let head = knight.pieces.get(PieceId(1));
    println!("head world: {} (预期 50,30)", head.world_pos);
    
    // sword world = body_world + hand_r_offset + sword_offset = (50, 50) + (15, 0) + (2, 0) = (67, 50)
    let sword = knight.pieces.get(PieceId(2));
    println!("sword world: {} (预期 67,50)", sword.world_pos);
    
    // shield world = (50, 50) + (-15, 0) + (-2, 0) = (33, 50)
    let shield = knight.pieces.get(PieceId(3));
    println!("shield world: {} (预期 33,50)", shield.world_pos);
    
    println!("\n--- 改 entity 位置后 ---\n");
    knight.world_offset = Vec2::new(200.0, 100.0);
    knight.compute_world_transforms();
    render_entity(&knight);
    
    println!("\n--- 加标准 alignment points 到 head ---\n");
    {
        let head = knight.pieces.get_mut(PieceId(1));
        head.alignment_points = PieceTree::standard_points();
    }
    render_entity(&knight);
}
```
