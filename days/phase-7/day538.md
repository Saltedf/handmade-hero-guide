# Day 538 · 制作基于网格的布局助手

> Day 493-495 Casey 做了编辑器 UI,但 UI 元素的位置都是手写绝对坐标(写"这个按钮在 (10, 20),大小 80x24")。Day 538 他把布局抽象出来——做一个**Grid Layout Helper**:开发者声明"放 5 个按钮,2 列 3 行,间距 4",helper 自动算每个按钮的位置。这是 immediate-mode UI(参考 Dear ImGui)的核心组件。

## 0 · 为什么要有这一天

手写 UI 坐标的痛苦:

```rust
draw_button(10, 10, "Button 1");   // 手动算位置
draw_button(10, 40, "Button 2");   // 改了字号,全要重算
draw_button(10, 70, "Button 3");
// 加第 4 个按钮,所有 y 都要调
```

更糟的是:如果你想加 padding、改间距、加滚动条,每个手写坐标都要改。

**布局系统**(layout system)的解决:声明**意图**("5 个按钮垂直排列"),系统算**坐标**。开发者改"5 个"为"6 个",坐标自动调整。

布局系统的两大流派:

- **Retained mode**(保留模式):Qt、GTK、HTML CSS。UI 是树,系统维护布局状态,改属性触发重排。
- **Immediate mode**(立即模式):Dear ImGui、Casey 的 HH 编辑器。每帧重新画 UI,布局状态在调用栈里。

Casey 选 immediate mode,因为它代码量少,适合游戏调试 UI。

#### Immediate Mode UI 的核心思想

让我把 immediate mode UI(IM-GUI)的精髓讲清楚,因为这是 Casey 选择的设计,也是工业级游戏调试 UI 的主流。

**Retained mode**(传统 UI 框架):
```rust
// 创建 button 一次,存到 state
let button = Button::new("Click me");
button.set_position(10, 10);
button.set_callback(on_click);
window.add_child(button);

// 后续修改
button.set_label("Clicked!");  // 触发重排
```

特点:UI 元素是**持久对象**,有 ID,有状态。框架维护树形结构,属性变化触发重排。

**Immediate mode**:
```rust
// 每帧重新声明 UI
fn draw_ui(ui: &mut Ui) {
    if ui.button("Click me", (10, 10)) {
        // 点击时返回 true,在这里处理
        println!("Clicked!");
    }
}
```

特点:UI 元素是**临时**——每帧重新创建,函数返回后消失。状态(鼠标是否 hover、点击次数)存在 framework 提供的"持久存储"里,通过 ID 索引。

**对比**:

| 维度 | Retained (Qt/GTK) | Immediate (Dear ImGui) |
|---|---|---|
| 代码量 | 多(声明 + 配置 + 信号槽) | 少(一行画一个 widget) |
| 状态管理 | 显式(state in widget) | 隐式(state by ID) |
| 重绘 | 增量(只画变化的) | 全量(每帧全画) |
| 性能 | 静态 UI 好 | 动态 UI 好 |
| 学习曲线 | 陡(OOP + 信号系统) | 平(API 就是函数调用) |
| 适合 | 桌面应用 | 游戏调试 UI、实时可视化 |

游戏开发选 immediate mode 的理由:
- 调试 UI 频繁改动(加按钮、改属性),immediate 不需要"销毁旧的、创建新的"
- 游戏循环已经是"每帧画",UI 跟随同样节奏
- 不需要 CSS 那种复杂样式系统(调试 UI 简单)

Dear ImGui(C++)是这一派的旗舰,Rust 生态有 `egui`、`iced`、`druid`。

#### Immediate Mode 的"ID 系统"

immediate mode 的关键问题:**怎么记住 widget 的状态?**(鼠标 hover、点击、输入框内容)

答案:**每帧用 ID 查询状态**。ID 通常是"调用栈位置 + 字符串标签"的哈希。

```rust
// egui 风格
ui.button("Save");  // ID = "Save"
ui.button("Load");  // ID = "Load"
ui.text_field("name");  // ID = "name"
```

framework 内部有 `HashMap<Id, State>`,每帧 button 调用时:
1. 计算 ID = hash("Save")
2. 从 HashMap 查 state(hover、click count)
3. 处理输入(鼠标位置、点击)
4. 更新 state
5. 画 button

下一帧再调用 `button("Save")`,framework 用同样的 ID 取出上一帧的 state,继续处理。

这种"ID 索引的持久存储 + 每帧重新调用"是 immediate mode 的核心。学会这个,你看 egui / Dear ImGui 源码都豁然开朗。

## 2 · 心智模型

### 类比:HTML table 布局

HTML 早期用 `<table>` 做布局:声明行列,浏览器自动算每个 `<td>` 的位置。`<tr>` 是行,`<td>` 是单元格。

```html
<table>
  <tr><td>B1</td><td>B2</td></tr>
  <tr><td>B3</td><td>B4</td></tr>
</table>
```

Casey 的 grid layout 是 immediate-mode 版本——没有 DOM 树,但概念一致:声明行列,系统算坐标。

### 严谨展开:Immediate-mode UI

immediate-mode UI 的核心:**每帧调用绘制函数,函数内部决定 UI 状态**。

```rust
fn draw_ui() {
    if ui_button("Save", 10, 10) {
        save_game();
    }
    if ui_button("Load", 10, 40) {
        load_game();
    }
}
```

`ui_button` 函数:

1. 画 button(立即渲染)
2. 检查鼠标是否点击(返回 bool)
3. 返回值驱动业务逻辑

#### Immediate-mode 的栈式布局

让我把 Casey 这天用的"栈式布局"(stack-based layout)讲清楚,这是 immediate-mode UI 的精华。

栈式布局的思想:**当前 widget 的位置 = 上一个 widget 结束位置 + spacing**。布局 helper 维护一个"cursor",每画一个 widget,cursor 推进。

```rust
struct LayoutCursor {
    x: f32,
    y: f32,
    max_x: f32,  // 当前行最远的位置(用于换行)
}

struct ColumnLayout {
    cursor: LayoutCursor,
    spacing: f32,
    width: f32,
}

impl ColumnLayout {
    fn next(&mut self, height: f32) -> (f32, f32) {
        let pos = (self.cursor.x, self.cursor.y);
        self.cursor.y += height + self.spacing;
        pos
    }
}
```

每画一个 widget:

```rust
let (x, y) = layout.next(24.0);  // 24 像素高
draw_button(x, y, 24.0, "Save");
```

布局 helper 自动算位置。加 1 个 widget 只多一行代码,不影响其他 widget 的位置。

#### Grid Layout:二维版本

Day 538 的 grid layout 是 column/row layout 的二维扩展:

```rust
struct GridLayout {
    cols: u32,
    rows: u32,
    cell_width: f32,
    cell_height: f32,
    spacing: f32,
    origin: (f32, f32),
}

impl GridLayout {
    fn cell_pos(&self, col: u32, row: u32) -> (f32, f32) {
        let x = self.origin.0 + col as f32 * (self.cell_width + self.spacing);
        let y = self.origin.1 + row as f32 * (self.cell_height + self.spacing);
        (x, y)
    }
    
    fn next_cell(&self, idx: u32) -> (f32, f32) {
        let col = idx % self.cols;
        let row = idx / self.cols;
        self.cell_pos(col, row)
    }
}
```

每画一个 widget:

```rust
let grid = GridLayout { cols: 2, rows: 3, cell_width: 100.0, cell_height: 24.0, spacing: 4.0, origin: (10.0, 10.0) };

for (i, label) in ["B1", "B2", "B3", "B4", "B5", "B6"].iter().enumerate() {
    let (x, y) = grid.next_cell(i as u32);
    draw_button(x, y, grid.cell_width, grid.cell_height, label);
}
```

声明"2 列 3 行,间距 4",helper 算所有坐标。改 cols/rows/spacing,所有 widget 自动重排。这是 immediate-mode UI 的力量。



每帧都跑一遍。优点:**无状态、无同步问题**(没有"我改了 model 但 UI 没刷新")。缺点:**重复计算**(每帧都算位置)。

Dear ImGui 是 immediate-mode 的标杆,游戏开发几乎都用它。

### Grid Layout 的实现

```rust
struct GridLayout {
    start_x: f32,
    start_y: f32,
    cell_w: f32,
    cell_h: f32,
    spacing: f32,
    col: usize,
    row: usize,
    cols: usize,
}

impl GridLayout {
    fn new(x: f32, y: f32, cols: usize, cell_w: f32, cell_h: f32, spacing: f32) -> Self {
        Self {
            start_x: x, start_y: y,
            cell_w, cell_h, spacing,
            col: 0, row: 0, cols,
        }
    }
    
    /// 取下一个 cell 的位置,自动换行
    fn next_cell(&mut self) -> (f32, f32) {
        let x = self.start_x + (self.col as f32) * (self.cell_w + self.spacing);
        let y = self.start_y + (self.row as f32) * (self.cell_h + self.spacing);
        
        self.col += 1;
        if self.col >= self.cols {
            self.col = 0;
            self.row += 1;
        }
        
        (x, y)
    }
}
```

使用:

```rust
let mut grid = GridLayout::new(10.0, 10.0, 2, 100.0, 24.0, 4.0);  // 2 列,100x24 cell,间距 4

for i in 0..6 {
    let (x, y) = grid.next_cell();
    draw_button(x, y, 100.0, 24.0, &format!("Button {}", i+1));
}
```

布局自动:(0,0)(104,0)(0,28)(104,28)(0,56)(104,56)——2 列 3 行的 grid。

### RAII Guard 模式

更高级用法:用 RAII(Rust 的 Drop trait)自动管理嵌套布局。

```rust
struct GridGuard<'a> {
    layout: GridLayout,
    parent: &'a mut UiStack,
}

impl<'a> GridGuard<'a> {
    fn button(&mut self, label: &str) -> bool {
        let (x, y) = self.layout.next_cell();
        ui_button(x, y, self.layout.cell_w, self.layout.cell_h, label)
    }
}

impl<'a> Drop for GridGuard<'a> {
    fn drop(&mut self) {
        // 自动 pop,恢复父布局
        self.parent.pop();
    }
}

fn ui_grid<'a>(parent: &'a mut UiStack, x: f32, y: f32, cols: usize) -> GridGuard<'a> {
    parent.push();
    GridGuard {
        layout: GridLayout::new(x, y, cols, 100.0, 24.0, 4.0),
        parent,
    }
}

// 使用
let mut grid = ui_grid(&mut ui_stack, 10.0, 10.0, 2);
grid.button("Save");
grid.button("Load");
// grid 离开作用域时自动 pop,无需手动清理
```

这是 Rust 风格——用 ownership 保证状态一致性。

### 3.2 · 图形学视角

UI 渲染的特殊需求:

- **字体抗锯齿**:UI 文字必须清晰
- **9-slice**:图像分成 9 块,边缘不拉伸,中间拉伸。用于按钮背景
- **subpixel rendering**:LCD 屏幕特有

GPU 上 UI 渲染:用专门的 batched renderer,一次绘制所有 quad。

#### 9-slice 详解

9-slice 是 UI 渲染的基础技术。让我把它讲清楚。

一个 100x100 的按钮背景,你想:
- 角落(20x20)保持原样(圆角、装饰)
- 边缘拉伸适应宽/高
- 中间填充

朴素做法:整个图拉伸,角落变形丑陋。

9-slice:把图分成 9 块:
```
[corner] [edge-top   ] [corner]
[edge-L] [center     ] [edge-R]
[corner] [edge-bottom] [corner]
```

- 4 个角:不变形
- 4 个边:单向拉伸(顶/底水平拉伸,左/右垂直拉伸)
- 中心:双向拉伸

实现:用 9 个独立的 textured quad,每个有自己的 UV 坐标和位置。这是 9-slice 的本质。

工业级 UI 库(egui、Dear ImGui、Iced)都内置 9-slice。CSS 的 `border-image` 属性也是同一思想。学会这个,你的 UI 在任意大小都好看。

## 5 · 对照与变奏

- **2000s**:HTML + CSS、Flexbox。声明式,样式分离
- **2010s**:React、Flutter。声明式 + virtual DOM / widget 树
- **2020s**:egui、Slint、Xilem。Rust native,各种模式

每种都解决当时的痛点:Mac/Win 解决"无 OS 支持"问题,Qt/GTK 解决"跨平台"问题,CSS 解决"样式与逻辑分离",React 解决"状态同步",Rust UI 解决"内存安全 + 性能"。

### Casey 的 grid helper vs 工业 UI 库

| 特性 | Casey 简化版 | egui | Dear ImGui | Iced |

### Elm Architecture:声明式 UI 的另一条路

Iced 借鉴 Elm 的架构,核心是 **MVU**(Model-View-Update):

```rust
// Model: 应用状态
struct App { count: i32 }

// Message: 用户操作
enum Message { Increment, Decrement }

// View: 根据 model 画 UI,返回可能的 message
fn view(app: &App) -> Element<Message> {
    column![
        button("+").on_press(Message::Increment),
        text(app.count),
        button("-").on_press(Message::Decrement),
    ].into()
}

// Update: 处理 message,返回新 model
fn update(app: &mut App, msg: Message) {
    match msg {
        Message::Increment => app.count += 1,
        Message::Decrement => app.count -= 1,
    }
}
```

这种"纯函数式 UI"比 immediate-mode 更严格(状态显式管理,无隐藏),但代码更冗长。Elm、Redux(React)、Iced 都用这个模式。

对比 immediate-mode:

```rust
// egui 风格
fn view(ui: &mut Ui, app: &mut App) {
    if ui.button("+").clicked() { app.count += 1; }
    ui.label(format!("{}", app.count));
    if ui.button("-").clicked() { app.count -= 1; }
}
```

代码更短,但状态隐式。两种风格各有优劣,工业级项目按团队偏好选。

学会这些 UI 范式,你看任何 UI 框架都能立刻识别它的设计哲学。



UI 布局演化:

- **1980s** :Mac/Windows API 手写坐标
- **1990s**:Visual Basic 的拖拽布局(retained)
- **2000s**:HTML CSS 的盒模型 + flexbox + grid
- **2010s**:Flutter/Compose 的声明式(react 风格)
- **2020s**:egui/iced 的 Rust 声明式

每种风格都有取舍。Casey 选 immediate-mode,因为 HH 编辑器需要快速迭代。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Casey 选 immediate-mode 而不是 retained-mode。immediate-mode 的缺点是什么?

**参考解答**:immediate-mode 的缺点是**无动画状态**——如果按钮要"鼠标悬停时颜色渐变"(0.3s 动画),immediate-mode 难做,因为没有持久的 UI 对象。retained-mode 系统维护 UI 树,每个对象有 hover_time 等属性,可以做复杂动画。Casey 不在乎动画(编辑器是工具 UI,够用就行),所以 immediate-mode 合适。游戏内 UI(主菜单、设置面板)可能需要 retained-mode 做精美动画。

### Lv2 · 动手实践

**题**:用 Rust 实现一个 Grid Layout Helper,支持 (1) N 列 M 行的 grid;(2) 自动换行(超过 N 列自动到下一行);(3) 自定义 cell 大小和间距。运行后:画一个 3 列 grid,放 7 个按钮,打印每个按钮的位置。

**参考解答**:

```rust
#[derive(Debug)]
pub struct GridLayout {
    start_x: f32,
    start_y: f32,
    cell_w: f32,
    cell_h: f32,
    spacing: f32,
    cols: usize,
    current_col: usize,
    current_row: usize,
}

impl GridLayout {
    pub fn new(
        start_x: f32, start_y: f32,
        cols: usize,
        cell_w: f32, cell_h: f32,
        spacing: f32,
    ) -> Self {
        Self {
            start_x, start_y,
            cell_w, cell_h, spacing, cols,
            current_col: 0, current_row: 0,
        }
    }
    
    pub fn next(&mut self) -> (f32, f32) {
        let x = self.start_x + self.current_col as f32 * (self.cell_w + self.spacing);
        let y = self.start_y + self.current_row as f32 * (self.cell_h + self.spacing);
        
        self.current_col += 1;
        if self.current_col >= self.cols {
            self.current_col = 0;
            self.current_row += 1;
        }
        
        (x, y)
    }
    
    /// 当前行剩余的 cell 数
    pub fn remaining_in_row(&self) -> usize {
        self.cols - self.current_col
    }
    
    /// 当前 grid 占据的总宽高
    pub fn total_size(&self) -> (f32, f32) {
        let w = self.cols as f32 * self.cell_w + (self.cols - 1) as f32 * self.spacing;
        let h = (self.current_row + 1) as f32 * self.cell_h + self.current_row as f32 * self.spacing;
        (w, h)
    }
}

fn draw_button_mock(x: f32, y: f32, label: &str) {
    println!("  Button at ({:.0}, {:.0}): {}", x, y, label);
}

fn main() {
    let mut grid = GridLayout::new(10.0, 10.0, 3, 100.0, 24.0, 4.0);
    
    println!("=== Grid Layout(3 列,7 按钮)===");
    for i in 1..=7 {
        let (x, y) = grid.next();
        draw_button_mock(x, y, &format!("Btn {}", i));
    }
    
    let (w, h) = grid.total_size();
    println!("\n总大小: {:.0} x {:.0}", w, h);
}
```

```bash
#   Button at (114, 10): Btn 2
#   Button at (218, 10): Btn 3
#   Button at (10, 38): Btn 4
#   Button at (114, 38): Btn 5
#   Button at (218, 38): Btn 6
#   Button at (10, 66): Btn 7

```

为什么这么写:`current_col` / `current_row` 是内部状态,每次 `next` 推进。`total_size` 计算 grid 整体大小,用于后续布局(比如把 grid 放到父容器里)。`f32` 因为 UI 坐标用浮点(支持 DPI scaling)。

```rust
// 完整的 grid layout + RAII guard

use std::cell::RefCell;

#[derive(Debug, Clone, Copy)]
pub struct Rect { pub x: f32, pub y: f32, pub w: f32, pub h: f32 }

pub struct GridLayout {
    rect: Rect,
    cell_w: f32,
    cell_h: f32,
    spacing: f32,
    cols: usize,
    col: usize,
    row: usize,
}

impl GridLayout {
    pub fn new(x: f32, y: f32, cols: usize, cell_w: f32, cell_h: f32, spacing: f32) -> Self {
        Self {
            rect: Rect { x, y, w: 0.0, h: 0.0 },
            cell_w, cell_h, spacing, cols,
            col: 0, row: 0,
        }
    }
    
    pub fn next_rect(&mut self) -> Rect {
        let x = self.rect.x + self.col as f32 * (self.cell_w + self.spacing);
        let y = self.rect.y + self.row as f32 * (self.cell_h + self.spacing);
        
        self.col += 1;
        if self.col >= self.cols {
            self.col = 0;
            self.row += 1;
        }
        
        // 更新总大小
        let total_w = self.cols as f32 * self.cell_w + (self.cols.saturating_sub(1)) as f32 * self.spacing;
        let total_h = (self.row + 1) as f32 * self.cell_h + self.row as f32 * self.spacing;
        self.rect.w = total_w;
        self.rect.h = total_h;
        
        Rect { x, y, w: self.cell_w, h: self.cell_h }
    }
    
    /// 跳到下一行
    pub fn new_row(&mut self) {
        self.col = 0;
        self.row += 1;
    }
}

/// 模拟 UI 框架
pub struct UiContext {
    pub draw_calls: RefCell<Vec<(Rect, String)>>,
}

impl UiContext {
    pub fn new() -> Self {
        Self { draw_calls: RefCell::new(Vec::new()) }
    }
    
    pub fn button(&self, rect: Rect, label: &str) -> bool {
        self.draw_calls.borrow_mut().push((rect, label.to_string()));
        true  // 假装点击了
    }
}

fn main() {
    let ui = UiContext::new();
    
    // 工具栏 grid:1 列 4 按钮
    println!("=== 工具栏 ===");
    let mut toolbar = GridLayout::new(10.0, 10.0, 1, 80.0, 24.0, 2.0);
    for label in ["Save", "Load", "New", "Quit"] {
        let rect = toolbar.next_rect();
        ui.button(rect, label);
        println!("  {} at ({}, {})", label, rect.x, rect.y);
    }
    
    // 主 grid:3 列 6 按钮(资产选择)
    println!("\n=== 资产选择 ===");
    let mut asset_grid = GridLayout::new(100.0, 10.0, 3, 32.0, 32.0, 4.0);
    for i in 1..=6 {
        let rect = asset_grid.next_rect();
        ui.button(rect, &format!("Asset {}", i));
        println!("  Asset {} at ({:.0}, {:.0})", i, rect.x, rect.y);
    }
    
    // 调试 grid:4 列 8 按钮(标签)
    println!("\n=== 标签(4 列 8 行)===");
    let mut tag_grid = GridLayout::new(10.0, 120.0, 4, 60.0, 18.0, 2.0);
    for i in 1..=8 {
        let rect = tag_grid.next_rect();
        ui.button(rect, &format!("Tag {}", i));
        println!("  Tag {} at ({:.0}, {:.0})", i, rect.x, rect.y);
    }
    
    // 总 draw calls
    println!("\n总 draw calls: {}", ui.draw_calls.borrow().len());
}
```

出错怎么办:

- **layout 越界**:cell 总宽超出父容器,需要 overflow 处理。
- **f32 精度问题**:UI 像素位置用 f32 可能有锯齿,改 i32 整数对齐。
- **嵌套 layout 状态丢失**:子 layout 创建时 push 父状态,destroy 时 pop。Rust 的 Drop 自动处理。
