# Day 559 · 实验片段光采样

> 之前光探针查询在 vertex shader(每顶点一次,3 个顶点插值到整个三角形)。Day 559 Casey 把查询**移到 fragment shader**——每像素独立查 voxel grid,光照细节更准。这是 day553 cosine-weighted sampling 的具体应用。

## 0 · 为什么要有这一天

先讲清楚两种光照查询位置。

**Per-vertex lighting**(之前):vertex shader 算每个顶点的光照,然后 GPU 在三角形内部 **线性插值**(Gouraud shading)。优点:便宜(3 个顶点 vs 几千像素)。缺点:三角形大时光照细节丢失,因为顶点光照被"抹平"了。

**Per-pixel lighting**(新方向):fragment shader 算每个像素的光照(Phong shading)。优点:每像素独立,光照细节准确(高光、阴影边界清晰)。缺点:贵 1000 倍(每像素 vs 每顶点)。

Casey 之前用 per-vertex 是性能妥协。Day 559 他试 per-pixel——虽然慢,但视觉质量提升明显,看后续能不能优化回来。

为什么这一天叫"实验"?因为它不是确定的迁移,Casey 在试:per-pixel 在 voxel probe 系统上效果如何,值不值得性能代价。如果太慢,可能保留 per-vertex。

完成这一天之后,你具备:

- 理解 per-vertex vs per-pixel shading 的区别
- 能在 fragment shader 实现 voxel probe 查询
- 知道 query frequency 对视觉的影响

## 1 · Casey 今天做了什么

Casey 的实验:

第一步,他在 fragment shader 加 voxel probe 查询代码——`voxel_color = sample_voxel(world_pos)`。

## 2 · 心智模型

### 类比:油画 vs 喷漆

**Per-vertex shading** 像油画——画家在画布几个关键点调色,其他地方用刷子抹开。抹出的渐变平滑但缺细节,大块面感觉"模糊"。

**Per-pixel shading** 像喷漆——每个像素独立喷色,细节精确到 1 像素。可以画出尖锐的高光、清晰的阴影边界。代价:喷得慢。

游戏里的对比:Quake 3(per-vertex)的模型光照"塑料感"重,因为顶点少。Doom 3(per-pixel)的模型光照"真实",因为每像素独立算 normal map。

### 严谨展开:per-vertex vs per-pixel in shader

**Per-vertex**(Gouraud):

```glsl
// vertex shader
in vec3 world_pos;
out vec3 v_light_color;  // 输出到 fragment

void main() {
    vec3 voxel = texture(voxel_grid, world_pos / voxel_size).rgb;
    v_light_color = surface_color * voxel;
    gl_Position = ...;
}

// fragment shader
in vec3 v_light_color;
out vec4 frag_color;

void main() {
    frag_color = vec4(v_light_color, 1.0);  // 直接用插值结果
}
```

**Per-pixel**(Phong):

```glsl
// vertex shader
out vec3 v_world_pos;
out vec3 v_normal;

void main() {
    v_world_pos = world_pos;
    v_normal = normal;
    gl_Position = ...;
}

// fragment shader
in vec3 v_world_pos;
in vec3 v_normal;
out vec4 frag_color;

void main() {
    vec3 voxel = texture(voxel_grid, v_world_pos / voxel_size).rgb;
    vec3 normal = normalize(v_normal);
    vec3 final_color = surface_color * voxel * dot(normal, light_dir);
    frag_color = vec4(final_color, 1.0);
}
```

Per-pixel 在 fragment shader 跑——每像素一次 voxel texture fetch。1080p = 2M 像素,2M 次 fetch。Voxel texture 在 GPU L2 cache 里有命中率,实际带宽小,但仍比 per-vertex 多 1000 倍。

### Voxel fetch 的 cache 命中

如果两相邻像素的 world_pos 很近,它们查 voxel texture 的位置也近——cache line 命中。Trilinear 是 8 邻居,如果两像素共享 4 个邻居,4 个 fetch 命中 cache。

实测:per-pixel voxel fetch 比 per-vertex 慢 3-10 倍(不是 1000 倍),因为 cache 友好。这是为什么工业 GI 都用 per-pixel。

### Cosine-weighted sampling 应用

Day 553 cosine-weighted 用在**采样方向**——fragment shader 从某像素位置,沿 normal 方向射 N 条 ray,查 voxel 累加。

```glsl
// fragment shader
uniform sampler3D voxel_grid;
uniform vec3 sample_dirs[64];  // cosine-weighted 采样方向

vec3 compute_irradiance(vec3 world_pos, vec3 normal) {
    vec3 sum = vec3(0);
    mat3 tbn = build_tangent_space(normal);
    for (int i = 0; i < 64; i++) {
        vec3 dir = tbn * sample_dirs[i];  // 转到世界坐标
        // ray march:沿 dir 走,累加 voxel 光照(被墙衰减)
        vec3 hit = ray_march(world_pos, dir);
        sum += hit;
    }
    return sum / 64.0;
}
```

`ray_march` 沿方向走,每步查 voxel,如果 voxel occupied 就停(墙挡光),否则累加 voxel 光照。

## 3 · 四域深入

### 3.1 · 游戏编程视角

per-pixel shading 的工业用法:

- **Normal mapping**:每像素从 normal map 读微细节法线
- **Parallax mapping**:每像素从 height map 算"虚拟位移"
- **Screen-space reflections**:每像素 raycast 屏幕空间
- **Voxel GI**:每像素从 voxel probe 采

现代游戏几乎所有光照都是 per-pixel(per-vertex 只在 LOD 远景用)。

### 3.2 · 图形学视角

per-pixel shading 是 **Phong interpolation**(Phong 1975)提出。在那之前 Gouraud shading(1971)是 per-vertex,因为便宜。GPU 早期(2000-2005)per-pixel 贵,现在标配。

Voxel GI 的 per-pixel 查询有几种:

- **Trilinear**:8 邻居线性插值,基础
- **Tricubic**:64 邻居三次插值,质量高但贵 8 倍
- **Cone tracing**:沿圆锥方向采样,模拟 soft shadow
- **Ray march**:沿射线步进,精确

Casey 用 trilinear,后面可能加 ray march。

### 3.3 · Linux 系统编程视角

"per-element vs per-batch"模式:

- **CPU vectorization**:SIMD 一次 4 元素(per-element 视角)
- **Network packet processing**:XDP / DPDK 每包独立处理
- **GPU compute**:每 thread 独立算

性能 trade-off 一致:per-element 准确但贵,per-batch 快但失细节。

```wgsl
// fragment shader
@group(0) @binding(0) var voxel_tex: texture_3d<f32>;
@group(0) @binding(1) var voxel_sampler: sampler;

@fragment
fn fs_main(
    @location(0) world_pos: vec3<f32>,
    @location(1) normal: vec3<f32>,
) -> @location(0) vec4<f32> {
    let voxel_coord = world_pos / voxel_size;
    let voxel_color = textureSample(voxel_tex, voxel_sampler, voxel_coord);
    let n = normalize(normal);
    let ndl = max(dot(n, vec3(0.0, 1.0, 0.0)), 0.0);  // 假设光源向上
    return vec4(surface_color * voxel_color.rgb * ndl, 1.0);
}
```

## 5 · 对照与变奏

shading frequency 历史:

- **1971 Gouraud**:per-vertex interpolation
- **1975 Phong**:per-pixel normal interpolation
- **2001 Normal mapping**:per-pixel normal from texture
- **2008 Deferred shading**:G-buffer,per-pixel light accumulation
- **2020+ Voxel per-pixel GI**:real-time GI 标配

每代都"per-pixel 化"更多东西。Voxel GI 是 per-pixel 的最新一步。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:per-pixel 比 per-vertex 慢多少?为什么 GPU cache 能缓解?

**参考解答**:朴素估算:per-vertex 每三角形 3 次查询,per-pixel 每像素 1 次。1080p 每帧 2M 像素,三角形 5M(覆盖屏幕,平均 0.4 像素/三角形),所以 per-vertex 5M * 3 = 15M 查询 vs per-pixel 2M 查询——其实 per-pixel 可能更少(三角形多但每三角形少像素)?不对,per-vertex 是每三角形 3 顶点(共享),unique 顶点数约 1M;per-pixel 是每像素,2M。所以 per-pixel 多 2 倍。但 cache 命中让 per-pixel 实际只多 3-10 倍 cache miss,而非 1000 倍——因为相邻像素查的 voxel 邻近,共享 cache line。

### Lv2 · 动手实践

**题**:CPU 模拟 per-vertex vs per-pixel voxel sampling 的差异。

要求:
- 一个 4x4 voxel grid,内容 `[i+j+k] mod 4 / 4.0` 的浮点值
- 一个 100x100 像素的 quad,4 个顶点
- Per-vertex:4 顶点查 voxel,像素线性插值
- Per-pixel:每个像素独立查 voxel
- 对比两种结果,找出 per-vertex 漏掉的细节

**参考解答**:

```rust
fn voxel_value(grid: &[[[f32; 4]; 4]; 4], x: f32, y: f32, z: f32) -> f32 {
    let i = x.floor() as usize;
    let j = y.floor() as usize;
    let k = z.floor() as usize;
    let i = i.min(3); let j = j.min(3); let k = k.min(3);
    grid[k][j][i]
}

fn lerp(a: f32, b: f32, t: f32) -> f32 { a + (b - a) * t }

fn bilinear(a: f32, b: f32, c: f32, d: f32, tx: f32, ty: f32) -> f32 {
    lerp(lerp(a, b, tx), lerp(c, d, tx), ty)
}

fn main() {
    // 创建 voxel grid
    let mut grid = [[[0.0f32; 4]; 4]; 4];
    for k in 0..4 { for j in 0..4 { for i in 0..4 {
        grid[k][j][i] = ((i + j + k) % 4) as f32 / 4.0;
    }}}

    let quad_corners = [(0.5, 0.5), (3.5, 0.5), (3.5, 3.5), (0.5, 3.5)];
    let y_layer = 1;  // 看 y=1 这层

    // Per-vertex: 4 个角各查一次
    let corners_v = quad_corners.map(|(x, _)| {
        voxel_value(&grid, x as f32, y_layer as f32, 0.0)
    });

    // Per-pixel:每个像素查
    let mut per_pixel_image = vec![0.0; 100 * 100];
    for py in 0..100 {
        for px in 0..100 {
            let x = 0.5 + 3.0 * (px as f32 / 100.0);
            let z = 0.5 + 3.0 * (py as f32 / 100.0);
            per_pixel_image[py * 100 + px] = voxel_value(&grid, x, y_layer as f32, z);
        }
    }

    // Per-vertex 插值
    let mut per_vertex_image = vec![0.0; 100 * 100];
    for py in 0..100 {
        for px in 0..100 {
            let u = px as f32 / 100.0;
            let v = py as f32 / 100.0;
            let c = bilinear(corners_v[0], corners_v[1], corners_v[3], corners_v[2], u, v);
            per_vertex_image[py * 100 + px] = c;
        }
    }

    // 对比 4 个像素
    for (px, py) in [(10, 10), (50, 50), (90, 90), (50, 10)] {
        println!("({},{}): per-pixel={:.3}, per-vertex={:.3}",
            px, py,
            per_pixel_image[py * 100 + px],
            per_vertex_image[py * 100 + px]);
    }
}
```

per-vertex 全是同色(因为 4 个角查询值相同),per-pixel 有细节差异——这就是 Gouraud 失真的来源。

## 8 · Rust / Arch 落地代码

CPU 模拟 fragment light sampling:

```rust
// 一个简化 voxel probe grid
struct VoxelGrid {
    data: Vec<[f32; 3]>,  // RGB 光照
    dim: [usize; 3],
}

impl VoxelGrid {
    fn new(dim: [usize; 3]) -> Self {
        let mut g = VoxelGrid {
            data: vec![[0.0; 3]; dim[0]*dim[1]*dim[2]],
            dim,
        };
        // 放一个虚拟光源
        g.set(8, 8, 8, [1.0, 0.8, 0.6]);
        g
    }
    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim[1] + j) * self.dim[0] + i
    }
    fn set(&mut self, i: usize, j: usize, k: usize, c: [f32; 3]) {
        if i < self.dim[0] && j < self.dim[1] && k < self.dim[2] {
            self.data[self.idx(i, j, k)] = c;
        }
    }
    fn sample_trilinear(&self, x: f32, y: f32, z: f32) -> [f32; 3] {
        let i = x.floor() as usize;
        let j = y.floor() as usize;
        let k = z.floor() as usize;
        let fx = x - i as f32;
        let fy = y - j as f32;
        let fz = z - k as f32;
        let corners: [[f32; 3]; 8] = [
            *self.data.get(self.idx(i, j, k)).unwrap_or(&[0.0; 3]),
            *self.data.get(self.idx(i+1, j, k)).unwrap_or(&[0.0; 3]),
            *self.data.get(self.idx(i, j+1, k)).unwrap_or(&[0.0; 3]),
            *self.data.get(self.idx(i+1, j+1, k)).unwrap_or(&[0.0; 3]),
            *self.data.get(self.idx(i, j, k+1)).unwrap_or(&[0.0; 3]),
            *self.data.get(self.idx(i+1, j, k+1)).unwrap_or(&[0.0; 3]),
            *self.data.get(self.idx(i, j+1, k+1)).unwrap_or(&[0.0; 3]),
            *self.data.get(self.idx(i+1, j+1, k+1)).unwrap_or(&[0.0; 3]),
        ];
        let lerp3 = |a: [f32; 3], b: [f32; 3], t: f32| -> [f32; 3] {
            [a[0]+(b[0]-a[0])*t, a[1]+(b[1]-a[1])*t, a[2]+(b[2]-a[2])*t]
        };

        let c00 = lerp3(corners[0], corners[1], fx);
        let c10 = lerp3(corners[2], corners[3], fx);
        let c01 = lerp3(corners[4], corners[5], fx);
        let c11 = lerp3(corners[6], corners[7], fx);

        let c0 = lerp3(c00, c10, fy);
        let c1 = lerp3(c01, c11, fy);
        lerp3(c0, c1, fz)
    }
}

// 一个"像素"片段
struct Fragment {
    world_pos: [f32; 3],
    normal: [f32; 3],
}

// Per-pixel fragment light
fn per_pixel_light(grid: &VoxelGrid, frag: &Fragment, surface_color: [f32; 3]) -> [f32; 3] {
    let voxel_color = grid.sample_trilinear(
        frag.world_pos[0],
        frag.world_pos[1],
        frag.world_pos[2],
    );
    // Lambertian: dot(normal, up)
    let ndl = frag.normal[1].max(0.0);  // 假设光来自上方
    [
        surface_color[0] * voxel_color[0] * ndl,
        surface_color[1] * voxel_color[1] * ndl,
        surface_color[2] * voxel_color[2] * ndl,
    ]
}

fn main() {
    let grid = VoxelGrid::new([16, 16, 16]);

    // 一组像素(模拟一个三角形的 fragments)
    let fragments: Vec<Fragment> = (0..100).map(|i| {
        let t = i as f32 / 100.0;
        Fragment {
            world_pos: [7.0 + t * 2.0, 8.0, 8.0],
            normal: [0.0, 1.0, 0.0],
        }
    }).collect();

    let surface = [0.8, 0.8, 0.8];

    for (i, f) in fragments.iter().enumerate() {
        if i % 25 == 0 {
            let c = per_pixel_light(&grid, f, surface);
            println!("Pixel {}: pos={:?} color=({:.3}, {:.3}, {:.3})",
                i, f.world_pos, c[0], c[1], c[2]);
        }
    }
}
```
