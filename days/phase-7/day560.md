
# Day 560 · 直接从体素查询辐照度

> Day 559 在 fragment shader 用 ray-march 沿方向采——慢且复杂。Day 560 Casey **简化**:每 voxel 预存 "irradiance(辐照度)"——所有方向的光照总和,fragment shader 一次直接查。

## 0 · 为什么要有这一天

让我们把镜头贴近 GPU profiler。你跟着 Handmade Hero 走到 Day 559——Casey 把 voxel 查询移到 fragment shader,每像素 64 个 ray,每 ray 几十步 ray-march。光照质量好,但**fragment shader 占了 GPU frame 的 50%**——1080p 60 FPS frame budget 16 ms,fragment shader 吃了 8 ms。如果场景复杂(mesh 多、overdraw 高),撑不住 60 FPS。

为什么这么慢?**因为每像素独立计算 irradiance**——对每个像素,fragment shader 沿 64 个方向 ray-march,每个方向累加 voxel 光照,最后除以 64。一个像素做 64 × 几十 = 几千次 voxel fetch。1080p 200 万像素 × 几千 fetch = 几十亿次 fetch——GPU 撑不住。

**关键洞察**:**大部分像素的 irradiance 是相似的**。如果两个像素位置接近,它们的 irradiance 也接近(光照场是空间平滑的)。所以**为每个 voxel 预算一次 irradiance**(独立于像素数),然后 fragment shader 一次 fetch 拿到——开销从"每像素几千 fetch"变成"每像素 1 fetch"。**1000 倍加速**。

回忆 irradiance 的定义:从所有方向来的入射光总和。一个 voxel 的 irradiance 是个标量(或 RGB),代表"这点整体多亮"。它**没有方向信息**——所以只能算 diffuse reflection(各向同性散射)。要算 specular reflection 还需要方向(那是 Day 561 学的 reflection vector)。

Day 560 的优化:**预计算**每个 voxel 的 irradiance(在 CPU 端 offline 或 GPU 上预跑),存进 voxel grid。Fragment shader 直接一次 fetch 拿到 irradiance——快 1000 倍。

代价:irradiance 是 precomputed,不能实时变光源。如果要动态光源,每帧重新算 irradiance(慢)。**这是经典的 trade-off:精确 vs 速度**——Day 559 选精确(实时计算),Day 560 选速度(预计算)。

Casey 这天用静态场景的预计算——地图固定时,lighting 可以 offline 烘焙。这是工业游戏开发的标准做法——Quake 1 用 baked lightmap,Doom 3 用 dynamic,Half-Life 2 hybrid,现代游戏(Unreal Lumen)hybrid + 智能 precompute。后面 Day 565+ 才处理动态光源。

完成这一天之后,你具备:

- 理解 irradiance 预计算 vs 实时计算的取舍,以及"光照场空间平滑性"为什么让 precompute 可行
- 能用 precomputed voxel grid 加速 fragment shader,把 1000 倍 fetch 减到 1 倍
- 知道 baked vs real-time lighting 的边界,以及为什么工业游戏都是 hybrid
- 理解 Spherical Harmonics(SH)作为 irradiance 的紧凑表示——为什么 9 个 RGB 系数够表达低频光照

## 1 · Casey 今天做了什么

Casey 的简化:

第一步,他改 voxel grid 存储——之前存 "outgoing radiance(沿方向的光)",现在存 "irradiance(无方向的标量)"。

第二步,他在 CPU 端 offline 计算 irradiance:对每个 voxel,ray-march 64 方向,累加 radiance,把平均存进 voxel。

第三步,fragment shader 极简——一次 texture fetch。

视频里他演示:fragment shader 时间从 5ms 降到 0.5ms——10 倍加速。代价:光源动了,irradiance 没变,看起来"光没动"。但因为大部分光源是静态的(太阳、固定灯),这个 trade-off 值得。

## 2 · 心智模型

### 2.1 类比:天气预报

天气预报可以两种方式给你"今天温度":

- **方式 A(实时计算)**:你每次问天气,气象局实时跑大气模型,告诉你当前温度——准但每次问要等几分钟
- **方式 B(预计算)**:气象局早上 6 点算一次,把今天的温度表发布。你查询就 0.1 秒——快,但如果突然寒潮,温度表还显示早上算的值

方式 B 是 precompute,适合"一天内变化不大"的数据。光照在静态场景里就是这种——光源不动,光照不变。

Day 560 选方式 B,Day 559 选方式 A。前者快但不能动光源,后者慢但灵活。**这是计算机科学的经典 trade-off**:precompute vs runtime,cache vs compute,静态 vs 动态。Compiler 也是这个 trade-off——AOT 编译(precompute)vs JIT 编译(runtime)。

**类比延伸:温度表的"分辨率"**。气象局发布温度表,可以选择"每城市一个温度"(粗)或"每街区一个温度"(细)。粗的低成本,但温度场空间变化大时失真。Voxel grid 也是——16³ voxel 是"粗分辨率 irradiance table",细到 256³ 是"细分辨率"。Casey 用 16³(粗)是因为大场景下 voxel 数量爆炸。

### 2.2 严谨展开:irradiance precomputation

让我把 precompute 算法彻底展开,你会看到为什么这是"重计算一次,轻查询 N 次"的优化模式。

```rust
// Precompute irradiance for every voxel(offline)
fn precompute_irradiance(
    radiance_grid: &VoxelGrid<[f32; 3]>,  // 各方向 radiance(SH 或 cube)
    sample_dirs: &[[f32; 3]],              // 球面方向
    occupied: &VoxelGrid<bool>,
) -> VoxelGrid<[f32; 3]> {  // 输出:每 voxel 的 irradiance
    let mut irradiance = VoxelGrid::new(radiance_grid.dim);

    for k in 0..radiance_grid.dim[2] {
        for j in 0..irradiance.dim[1] {
            for i in 0..irradiance.dim[0] {
                let world_pos = voxel_center(i, j, k);
                let mut sum = [0.0; 3];

                for dir in sample_dirs {
                    // ray-march 沿 dir,累加 voxel radiance
                    let contribution = ray_march_radiance(
                        radiance_grid, occupied, world_pos, *dir,
                    );
                    sum[0] += contribution[0];
                    sum[1] += contribution[1];
                    sum[2] += contribution[2];
                }

                let n = sample_dirs.len() as f32;
                irradiance.set(i, j, k, [sum[0]/n, sum[1]/n, sum[2]/n]);
            }
        }
    }
    irradiance
}
```

这个 precompute 可能花几秒(16³ voxel × 64 方向 × 32 步 ray-march = 134M 操作)。但**一次性**,之后 fragment shader 直接 fetch。

**关键数字**:16³ = 4096 voxel。每 voxel 64 方向 ray-march,每 ray 32 步——总 ray-march 步数 4096 × 64 × 32 = 8.4M。CPU 单核跑 8.4M 操作约 30 ms——一帧能跑完。但如果场景变化(光源动),每帧重算 30 ms,60 FPS frame budget 16 ms 撑不住。**所以 precompute 只适合静态**。

**存储代价**:16³ × 3 f32 (RGB) = 192 KB。GPU 上 192 KB texture,cache 友好。如果用 SH(2 阶,9 个 RGB = 27 f32),16³ × 27 × 4 = 700 KB——还能接受。Cube map 方向是 16³ × 6 面 × 16² 像素 × 3 = 25 MB——爆炸,所以 voxel 不能存 cube map。

### 2.3 Fragment shader 极简化

Day 559 → Day 560 的 fragment shader 简化:

```glsl
// 之前(Day 559):每像素 ray-march 64 方向
vec3 light = vec3(0);
for (int i = 0; i < 64; i++) {
    light += ray_march(world_pos, sample_dirs[i]);
}
return light / 64.0;

// 之后(Day 560):一次 fetch
vec3 light = texture(irradiance_grid, world_pos / voxel_size).rgb;
return light;
```

**fragment shader 时间从 5ms 降到 0.5ms——10 倍加速**。代价:光源动了,irradiance 没变,看起来"光没动"。但因为大部分光源是静态的(太阳、固定灯),这个 trade-off 值得。

**为什么 10 倍而非 1000 倍?**理论 precompute 把"每像素 64 ray × 32 步"简化到"每像素 1 fetch",应该是 2000 倍。实际 10 倍,因为 fragment shader 还有其他工作(BRDF 计算、texture fetch for albedo、tonemap)——voxel fetch 只是其中一部分。**优化收益受 Amdahl's law 限制**——你只能加速"那部分",其他部分不变。

### 2.4 Static vs dynamic 场景的工程现实

Precompute 适合**静态场景**——墙、地板、家具不动。光源不动(太阳、固定灯)。

动态场景怎么办?三个方案:

- **重新 precompute**:每帧重算 irradiance。代价:30 ms per frame,撑不住 60 FPS。**适合 30 FPS 单机游戏**——如某些 RPG 的"day/night cycle"每几分钟重算一次
- **局部更新**:只更新光源附近的 voxel。光源半径 5 米,只算 5 米内 voxel(约 125 个),每帧 125 × 64 × 32 = 256K 操作 = 1 ms——可承受。**这是工业游戏的标准做法**
- **探针融合**:静态 irradiance + 动态光源每帧叠加(在 Day 565 学)。最优解,但实现复杂

Casey 这天先做静态(全 precompute),Day 565 加动态(分离 baked + dynamic grid)。这就是 hybrid lighting 的诞生——大部分游戏都用这套。

## 3 · 四域深入

### 3.1 · 游戏编程视角

baked vs real-time lighting 是游戏开发永恒话题:

- **Quake 1**:全 baked lightmap
- **Half-Life 2**:lightmap + 动态物体用 light probe
- **Doom 3**:全 dynamic(stencil shadow volumes)
- **Crysis**:hybrid(baked 大部分 + dynamic 局部)
- **Unreal 5 Lumen**:real-time GI(but still uses precomputed data)

每代硬件更强,real-time 比例越高。但 baked 在节省性能上的优势永远存在。

### 3.2 · 图形学视角

Irradiance 的数学:`E(p) = ∫_hemisphere L(p, ω) cos(θ) dω`。

如果 L(p, ω) 全方向已知,可以算 E(p)。但 L 是 4D 函数(位置 3D + 方向 2D),存储贵。

**Spherical Harmonics(SH)** 是 L 的紧凑表示——2 阶 SH(9 个系数)够表示低频 irradiance。这样 voxel 存 9 个 RGB = 27 个 f32,而非整 cube map。

Casey 这天简化为 1 RGB(无方向),后面可能加 SH。

### 3.3 · Linux 系统编程视角

"precompute vs runtime"模式:

- **CRC table**:预计算 256 项 CRC,运行时 O(1) 查
- **Sin/cos table**:嵌入式常用,避免 fpu 计算
- **Hash table**:预计算 optimal hash function
- **JIT vs AOT**:Java JIT(运行时编译)vs C++ AOT(预先编译)

### 3.4 · Rust 生态视角

Rust 写 precomputation:

```rust
use rayon::prelude::*;

fn precompute_irradiance_parallel(
    radiance: &VoxelGrid<[f32; 3]>,
    dirs: &[[f32; 3]],
) -> VoxelGrid<[f32; 3]> {
    let mut result = VoxelGrid::new(radiance.dim);

    // 并行:每 voxel 独立
    result.data.par_iter_mut().enumerate().for_each(|(idx, voxel)| {
        let (i, j, k) = unravel(idx, radiance.dim);
        let world_pos = voxel_center(i, j, k);
        let mut sum = [0.0; 3];
        for dir in dirs {
            let c = ray_march(radiance, world_pos, *dir);
            sum[0] += c[0];
            sum[1] += c[1];
            sum[2] += c[2];
        }
        let n = dirs.len() as f32;
        *voxel = [sum[0]/n, sum[1]/n, sum[2]/n];
    });

    result
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 irradiance 可以是"无方向标量"?不是光来自所有方向吗?

**参考解答**:irradiance 是从所有方向入射光的**积分**(加总),结果是"这点接收到的总能量"——是个标量(或 RGB)。要区分"方向"的话,需要 radiance(每方向独立)。Irradiance 是 radiance 的积分,丢方向信息但紧凑。Lambertian(漫反射)表面用 irradiance 就够,因为光从任何方向来都被均匀反射。镜面反射(高光)需要 radiance。

### Lv2 · 动手实践

**题**:实现 irradiance precompute,验证 fragment shader 速度。

要求:
- 16³ voxel grid,有一个虚拟光源
- Precompute irradiance(简化:每个 voxel 直接读自己位置的光源)
- Per-pixel shader 一次 fetch
- 打印 fragment 处理时间

**参考解答**:

```rust
use std::time::Instant;

struct VoxelGrid {
    data: Vec<[f32; 3]>,
    dim: [usize; 3],
}

impl VoxelGrid {
    fn new(dim: [usize; 3]) -> Self {
        VoxelGrid { data: vec![[0.0; 3]; dim[0]*dim[1]*dim[2]], dim }
    }
    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim[1] + j) * self.dim[0] + i
    }
    fn get(&self, i: usize, j: usize, k: usize) -> [f32; 3] {
        self.data[self.idx(i, j, k)]
    }
    fn set(&mut self, i: usize, j: usize, k: usize, v: [f32; 3]) {
        self.data[self.idx(i, j, k)] = v;
    }
    fn sample_trilinear(&self, x: f32, y: f32, z: f32) -> [f32; 3] {
        let i = x.floor() as usize; let j = y.floor() as usize; let k = z.floor() as usize;
        let i = i.min(self.dim[0]-2); let j = j.min(self.dim[1]-2); let k = k.min(self.dim[2]-2);
        let fx = x - i as f32; let fy = y - j as f32; let fz = z - k as f32;
        let c000 = self.get(i, j, k);
        let c100 = self.get(i+1, j, k);
        let c010 = self.get(i, j+1, k);
        let c110 = self.get(i+1, j+1, k);
        let c001 = self.get(i, j, k+1);
        let c101 = self.get(i+1, j, k+1);
        let c011 = self.get(i, j+1, k+1);
        let c111 = self.get(i+1, j+1, k+1);
        let lerp3 = |a: [f32; 3], b: [f32; 3], t: f32| -> [f32; 3] {
            [a[0]+(b[0]-a[0])*t, a[1]+(b[1]-a[1])*t, a[2]+(b[2]-a[2])*t]
        };
        let c00 = lerp3(c000, c100, fx);
        let c10 = lerp3(c010, c110, fx);
        let c01 = lerp3(c001, c101, fx);
        let c11 = lerp3(c011, c111, fx);
        let c0 = lerp3(c00, c10, fy);
        let c1 = lerp3(c01, c11, fy);
        lerp3(c0, c1, fz)
    }
}

// 模拟光源在 (8, 8, 8),强度 (1.0, 0.8, 0.6)
fn precompute_irradiance(grid: &mut VoxelGrid) {
    let light_pos = [8.0; 3];
    let light_color = [1.0, 0.8, 0.6];

    for k in 0..grid.dim[2] {
        for j in 0..grid.dim[1] {
            for i in 0..grid.dim[0] {
                let pos = [i as f32, j as f32, k as f32];
                let dx = pos[0] - light_pos[0];
                let dy = pos[1] - light_pos[1];
                let dz = pos[2] - light_pos[2];
                let dist2 = dx*dx + dy*dy + dz*dz;
                let falloff = 1.0 / (1.0 + dist2 * 0.1);
                grid.set(i, j, k, [
                    light_color[0] * falloff,
                    light_color[1] * falloff,
                    light_color[2] * falloff,
                ]);
            }
        }
    }
}

fn main() {
    let mut grid = VoxelGrid::new([16, 16, 16]);

    let t_precompute = Instant::now();
    precompute_irradiance(&mut grid);
    println!("Precompute time: {:?}", t_precompute.elapsed());

    // 模拟 fragment shader:1000 个像素,各查一次
    let fragments: Vec<[f32; 3]> = (0..1000).map(|i| {
        let t = (i as f32) / 1000.0;
        [t * 16.0, t * 16.0, t * 16.0]
    }).collect();

    let t_render = Instant::now();
    let mut sum = [0.0; 3];
    for pos in &fragments {
        let light = grid.sample_trilinear(pos[0], pos[1], pos[2]);
        sum[0] += light[0];
        sum[1] += light[1];
        sum[2] += light[2];
    }
    println!("Fragment shader time: {:?}", t_render.elapsed());
    println!("Total light sum: {:?}", sum);
}
```

## 8 · Rust / Arch 落地代码

完整 precompute + 一次性查询:

```rust
use std::time::Instant;

#[derive(Clone, Copy, Default)]
struct Irradiance { r: f32, g: f32, b: f32 }

struct VoxelGrid<T: Copy + Default> {
    data: Vec<T>,
    dim: [usize; 3],
}

impl<T: Copy + Default> VoxelGrid<T> {
    fn new(dim: [usize; 3]) -> Self {
        VoxelGrid { data: vec![T::default(); dim[0]*dim[1]*dim[2]], dim }
    }
    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim[1] + j) * self.dim[0] + i
    }
    fn get(&self, i: usize, j: usize, k: usize) -> T { self.data[self.idx(i, j, k)] }
    fn set(&mut self, i: usize, j: usize, k: usize, v: T) {
        self.data[self.idx(i, j, k)] = v;
    }
}

// 光源
struct Light {
    pos: [f32; 3],
    color: Irradiance,
}

// Precompute:每 voxel 的 irradiance(从所有光源贡献)
fn precompute_irradiance(
    grid: &mut VoxelGrid<Irradiance>,
    lights: &[Light],
    occupied: &VoxelGrid<bool>,
) {
    for k in 0..grid.dim[2] {
        for j in 0..grid.dim[1] {
            for i in 0..grid.dim[0] {
                let pos = [i as f32, j as f32, k as f32];
                let mut total = Irradiance::default();

                for light in lights {
                    let dx = pos[0] - light.pos[0];
                    let dy = pos[1] - light.pos[1];
                    let dz = pos[2] - light.pos[2];
                    let dist = (dx*dx + dy*dy + dz*dz).sqrt();
                    let falloff = 1.0 / (1.0 + dist * 0.3);

                    // 简化:不考虑遮挡(实际要 ray-march 测可见性)
                    let occluded = if dist > 0.0 && check_occlusion(occupied, light.pos, pos) { 0.0 } else { 1.0 };

                    total.r += light.color.r * falloff * occluded;
                    total.g += light.color.g * falloff * occluded;
                    total.b += light.color.b * falloff * occluded;
                }

                grid.set(i, j, k, total);
            }
        }
    }
}

fn check_occlusion(
    occupied: &VoxelGrid<bool>,
    from: [f32; 3],
    to: [f32; 3],
) -> bool {
    // 简化:沿 from->to 等距采样几个点,任一 occupied 就算遮挡
    let steps = 10;
    for s in 1..steps {
        let t = s as f32 / steps as f32;
        let p = [
            from[0] + (to[0]-from[0])*t,
            from[1] + (to[1]-from[1])*t,
            from[2] + (to[2]-from[2])*t,
        ];
        let i = p[0] as usize;
        let j = p[1] as usize;
        let k = p[2] as usize;
        if i < occupied.dim[0] && j < occupied.dim[1] && k < occupied.dim[2] {
            if occupied.get(i, j, k) { return true; }
        }
    }
    false
}

fn main() {
    let mut grid = VoxelGrid::<Irradiance>::new([16, 16, 16]);
    let occupied = VoxelGrid::<bool>::new([16, 16, 16]);

    let lights = vec![
        Light { pos: [8.0, 12.0, 8.0], color: Irradiance { r: 1.0, g: 0.9, b: 0.7 } },
        Light { pos: [3.0, 3.0, 3.0], color: Irradiance { r: 0.5, g: 0.5, b: 1.0 } },
    ];

    // Precompute
    let t0 = Instant::now();
    precompute_irradiance(&mut grid, &lights, &occupied);
    let precompute_time = t0.elapsed();
    println!("Precompute: {:?} (one-time cost)", precompute_time);

    // 模拟 fragment shader:1080p = 2M pixels
    let t1 = Instant::now();
    let mut total_light = [0.0f64; 3];
    for px in 0..1920 {
        for py in 0..1080 {
            // 模拟像素 world_pos(简化:平面 z=8)
            let wx = (px as f32 / 1920.0) * 16.0;
            let wy = 8.0;
            let wz = (py as f32 / 1080.0) * 16.0;
            let i = wx as usize;
            let j = wy as usize;
            let k = wz as usize;
            if i < 16 && j < 16 && k < 16 {
                let v = grid.get(i, j, k);
                total_light[0] += v.r as f64;
                total_light[1] += v.g as f64;
                total_light[2] += v.b as f64;
            }
        }
    }
    let render_time = t1.elapsed();
    println!("Render (2M pixel query): {:?}", render_time);
    println!("Sum RGB: ({:.2}, {:.2}, {:.2})",
        total_light[0], total_light[1], total_light[2]);

    println!("\nPerformance: precompute {:?} + render {:?} = total {:?}",
        precompute_time, render_time, precompute_time + render_time);
    println!("vs Day 559 way (每 pixel ray-march): would be {:?}+",
        render_time * 64);  // 64x slower
}
```
