# Day 511 · 将 HHT 解析集成到资产系统

> Day 509-510 做了 HHT 解析器。Day 511 把 HHT 集成进游戏资产系统——读 HHT,构建 tag database,游戏代码用 TagId 查资产。

## 0 · 为什么要有这一天

### 真实场景:从"独立 demo"到"集成系统"

你跟着 Casey 做到 Day 510。这两天你实现了完整的 HHT 解析器——给它一个 `assets.hht` 文件,它能解析成内存里的 `TagDatabase`,提供 `lookup(section, name) -> TagId` API。在 unit test 里它跑得完美。

但你**还没把它接到游戏里**。游戏代码还在用旧的硬编码 enum:
```rust
enum BitmapType { Player, Sword, Goblin, /* ... 50 个 */ }
fn render_player(state: &State) {
    render.bitmap(BitmapType::Player, ...);
}
```

每次你想加新 sprite,要改 `BitmapType` enum、改渲染代码、改 asset load 代码,**重新编译游戏**。开发节奏慢——加一个 sprite 要 5 分钟编译。

Day 511 把 HHT 系统集成进游戏。集成后:
```rust
fn render_player(state: &State) {
    let player_tag = state.tag_db.lookup("bitmaps", "player");
    render.bitmap(player_tag, ...);
}
```

加新 sprite 只需在 HHT 文件里加一行,**不用重新编译**。开发节奏快——加一个 sprite 1 秒。

### 为什么"集成"这件事难

很多程序员觉得"我有了解析器,接进游戏还不容易?"——但**集成**本身是工程难题,原因:

**第一,数据流改造**。旧代码用 enum,enum 是编译时常量,直接 `BitmapType::Player` 就能用。新代码用 TagId,TagId 是运行时查的——必须从某处拿 `tag_db` 引用。每个使用 enum 的函数,签名要改成接受 `&TagDatabase`。函数签名变,调用方也要变,链式反应。

**第二,生命周期管理**。`TagDatabase` 何时创建?何时销毁?如果游戏热重载 HHT,TagDatabase 要重建,但旧 TagId 还指向老 database——use-after-free 风险。

**第三,错误处理**。HHT 解析失败(语法错误、字段缺失)怎么办?游戏启动时失败?降级到默认 sprite?工业级游戏有完整 fallback 体系。

**第四,性能验证**。`lookup` 函数被调几千次/帧,必须快。如果你用 HashMap,O(1) 但有 hash 计算 + 内存访问。如果用 Vec + 二分搜索,O(log n) 但 cache 友好。Casey 在视频里讨论了这个权衡。

**第五,迁移策略**。游戏有 50 处使用 enum,你**一次全迁移**还是**逐个迁移**?前者 risk 高(一次大 PR),后者慢(50 个 PR)。Casey 选了"一次全迁移 + 端到端测试"——教学场景,可以承受。工业项目通常用 feature flag 渐进迁移。

### 工业级集成的纪律

成熟项目的模块集成遵循这些纪律:

**纪律 1:接口稳定性**。集成前先把模块的 API 钉死——签名、错误类型、生命周期。后续大改要走 deprecation。

**纪律 2:端到端测试**。集成后必须跑完整流程,不只 unit test。HHT → load → render → 像素对比。

**纪律 3:性能 baseline**。集成前测一次,集成后测一次。性能退化 > 5% 要调查。

**纪律 4:回滚预案**。集成失败时能回滚。git tag 标记 pre-integration。

**纪律 5:文档同步**。集成后更新架构文档。新人能看懂"为什么用 TagId 不用 enum"。

Casey Day 511 演示的是这套纪律的教学版。

## 2 · 心智模型

### 类比:从手动挡到自动挡

旧系统:代码硬编码 enum,程序员手动维护。

新系统:HHT 数据驱动,加 tag 只改 HHT。

类似手动挡 → 自动挡:功能一样(都开车),但操作简化(不用踩离合)。

### 集成的步骤

模块集成的标准流程:

1. **接口设计**:模块对外暴露什么 API
2. **数据流**:数据怎么从模块 A 流到 B
3. **生命周期**:模块何时创建、何时销毁
4. **错误处理**:模块失败时整体怎么办

HHT 集成:

1. **API**:`TagDatabase::lookup(section, name) -> TagId`
2. **数据流**:HHT 文件 → TagDatabase → game code
3. **生命周期**:游戏启动创建,游戏退出销毁
4. **错误**:HHT 解析失败 → 报错退出(或降级到默认 HHT)

### Tag ID 系统的稳定性

HHT 修改后,TagId 可能变(新 tag 加在中间,旧 tag ID 偏移)。问题:旧存档(HHA)存的 TagId 失效。

工业级解决:**Tag ID 用 hash**——hash("bitmaps/sword") 作为 ID,稳定。

```rust
fn tag_id(section: &str, name: &str) -> u32 {
    let full = format!("{}/{}", section, name);
    let mut hasher = DefaultHasher::new();
    full.hash(&mut hasher);
    hasher.finish() as u32
}
```

不同次启动,同一 tag 的 ID 一致。

Casey Day 511 简化——用递增 ID,存档兼容留作未来。

### Tag ID vs 字符串

游戏内查 tag ID 比字符串快(hash + compare vs string compare)。

但启动时构建 DB 才是开销——O(N) 解析 + N 次 hash。

游戏跑起来后,tag ID lookup 是 O(1),极快。

### Lv1 · 概念辨析

**题**:集成时为什么用 singleton(Lazy)而不是参数传递?

**参考解答**:权衡:

**Singleton 优势**:代码简洁,任何地方 `TAG_DB.lookup(...)` 即可。
**Singleton 劣势**:隐式依赖,测试难(全局状态污染)。

**参数传递优势**:显式依赖,易测试。
**参数传递劣势**:代码冗长,每个函数都要带 `&TagDatabase` 参数。

Casey 选 singleton 因为 HH 是单进程游戏,不需要测试隔离。大型项目(SaaS、库)倾向参数传递或 DI。

use std::collections::HashMap;
use std::fmt;

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
struct TagId(u32);

impl fmt::Display for TagId {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "#{}", self.0)
    }
}

#[derive(Debug, Default, Clone)]
struct HhtFile {
    sections: HashMap<String, Vec<String>>,
}

fn parse_hht(text: &str) -> HhtFile {
    let mut file = HhtFile::default();
    let mut section = String::new();
    for line in text.lines() {
        let line = line.trim();
        if line.is_empty() || line.starts_with('#') { continue; }
        if line.starts_with('[') && line.ends_with(']') {
            section = line[1..line.len()-1].to_string();
        } else if !section.is_empty() {
            file.sections.entry(section.clone()).or_default().push(line.into());
        }
    }
    file
}

struct TagDatabase {
    name_to_id: HashMap<(String, String), TagId>,
    next_id: u32,
}

impl TagDatabase {
    fn new() -> Self { Self { name_to_id: HashMap::new(), next_id: 0 } }
    
    fn from_hht(hht: &HhtFile) -> Self {
        let mut db = Self::new();
        for (section, tags) in &hht.sections {
            for tag in tags {
                let id = TagId(db.next_id);
                db.next_id += 1;
                db.name_to_id.insert((section.clone(), tag.clone()), id);
            }
        }
        db
    }
    
    fn lookup(&self, section: &str, name: &str) -> Option<TagId> {
        self.name_to_id.get(&(section.into(), name.into())).copied()
    }
    
    fn len(&self) -> usize { self.name_to_id.len() }
}

// 模拟 HHA
struct HhaFile {
    bitmaps: HashMap<TagId, Vec<u8>>,
    sounds: HashMap<TagId, Vec<u8>>,
}

struct AssetSystem {
    tag_db: TagDatabase,
    hha: HhaFile,
}

impl AssetSystem {
    fn boot(hht_text: &str) -> Self {
        println!("[BOOT] Reading HHT...");
        let hht = parse_hht(hht_text);
        println!("[BOOT] HHT parsed: {} sections", hht.sections.len());
        
        println!("[BOOT] Building tag database...");
        let tag_db = TagDatabase::from_hht(&hht);
        println!("[BOOT] Tag DB: {} tags", tag_db.len());
        
        println!("[BOOT] Loading HHA...");
        let mut hha = HhaFile { bitmaps: HashMap::new(), sounds: HashMap::new() };
        for (section, tags) in &hht.sections {
            for tag in tags {
                let id = tag_db.lookup(section, tag).unwrap();
                let fake_data = vec![0u8; 256];
                match section.as_str() {
                    "bitmaps" => { hha.bitmaps.insert(id, fake_data); }
                    "sounds" => { hha.sounds.insert(id, fake_data); }
                    _ => {}
                }
            }
        }
        println!("[BOOT] HHA loaded: {} bitmaps, {} sounds",
                 hha.bitmaps.len(), hha.sounds.len());
        
        Self { tag_db, hha }
    }
    
    fn get_bitmap(&self, name: &str) -> Option<&Vec<u8>> {
        let id = self.tag_db.lookup("bitmaps", name)?;
        self.hha.bitmaps.get(&id)
    }
    
    fn get_sound(&self, name: &str) -> Option<&Vec<u8>> {
        let id = self.tag_db.lookup("sounds", name)?;
        self.hha.sounds.get(&id)
    }
}

        ("render", "sword"),
        ("render", "goblin"),
        ("render", "missing"),

                None => println!("[GAME] WARN: sound '{}' not found!", name),
            },
            _ => {}
        }
    }

use std::collections::HashMap;

// ============================================================
// HHT 解析器(简化版,Day 510 已实现)
// ============================================================
#[derive(Debug, Clone, PartialEq)]
struct HhtFile {
    sections: HashMap<String, HhtSection>,
}

#[derive(Debug, Clone, PartialEq)]
struct HhtSection {
    tags: HashMap<String, String>,  // tag_name → value(简化)
}

impl HhtFile {
    fn parse(text: &str) -> Result<Self, String> {
        let mut sections = HashMap::new();
        let mut current_section: Option<String> = None;
        let mut current_tags: HashMap<String, String> = HashMap::new();

        for (line_num, line) in text.lines().enumerate() {
            let line = line.trim();
            if line.is_empty() || line.starts_with('#') {
                continue;  // 空行 / 注释
            }

            if line.starts_with('[') && line.ends_with(']') {
                // 保存上一个 section
                if let Some(name) = current_section.take() {
                    sections.insert(name, HhtSection { tags: current_tags.clone() });
                    current_tags.clear();
                }
                current_section = Some(line[1..line.len()-1].to_string());
            } else if let Some(eq_pos) = line.find('=') {
                let key = line[..eq_pos].trim().to_string();
                let value = line[eq_pos+1..].trim().to_string();
                current_tags.insert(key, value);
            } else {
                return Err(format!("line {}: syntax error: {}", line_num + 1, line));
            }
        }

        // 保存最后一个 section
        if let Some(name) = current_section {
            sections.insert(name, HhtSection { tags: current_tags });
        }

        Ok(HhtFile { sections })
    }
}

// ============================================================
// TagDatabase - HHT 集成的核心
// ============================================================
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
struct TagId(u32);  // 不透明 ID,内部 u32

struct TagDatabase {
    // 双向映射:name ↔ ID
    by_id: Vec<(String, String, String)>,  // (section, name, value)
    by_name: HashMap<(String, String), TagId>,
}

impl TagDatabase {
    fn from_hht(hht: &HhtFile) -> Self {
        let mut db = Self {
            by_id: Vec::new(),
            by_name: HashMap::new(),
        };

        for (section_name, section) in &hht.sections {
            for (tag_name, value) in &section.tags {
                let id = TagId(db.by_id.len() as u32);
                db.by_id.push((section_name.clone(), tag_name.clone(), value.clone()));
                db.by_name.insert((section_name.clone(), tag_name.clone()), id);
            }
        }
        db
    }

    fn lookup(&self, section: &str, name: &str) -> Result<TagId, String> {
        self.by_name
            .get(&(section.to_string(), name.to_string()))
            .copied()
            .ok_or_else(|| format!("tag '{}' not found in section '{}'", name, section))
    }

    fn name_of(&self, id: TagId) -> &(String, String, String) {
        &self.by_id[id.0 as usize]
    }

    fn tag_count(&self) -> usize {
        self.by_id.len()
    }
}

    // ... 其他游戏状态

        let tag = self.tag_db.lookup("sounds", "sword_swing")?;

        Ok(())
    }
}

### 8.2 性能测试:TagDatabase lookup 开销

```rust
use std::time::Instant;
use std::collections::HashMap;

fn bench_lookup(db: &TagDatabase, n_iterations: usize) {
    let start = Instant::now();
    let mut sum = 0u64;
    for i in 0..n_iterations {
        let id = db.lookup("bitmaps", "player").unwrap();
        sum += id.0 as u64 + i % 7;
    }
    let elapsed = start.elapsed();
    let per_lookup_ns = elapsed.as_nanos() as f64 / n_iterations as f64;
    println!("{} iterations, {:.2} ns/lookup, sum={}", n_iterations, per_lookup_ns, sum);
}

fn main() {
    // 大量 tag,模拟真实场景
    let mut hht_text = String::new();
    hht_text.push_str("[bitmaps]\n");
    for i in 0..1000 {
        hht_text.push_str(&format!("tag_{} = file_{}.png\n", i, i));
    }
    let hht = HhtFile::parse(&hht_text).unwrap();
    let db = TagDatabase::from_hht(&hht);

    bench_lookup(&db, 1000);
    bench_lookup(&db, 10000);
    bench_lookup(&db, 100000);
    bench_lookup(&db, 1000000);
}
```

预期:
- 1M lookup 大概 30-50 ms(30-50 ns/lookup)
- HashMap lookup 是 O(1) 但有 hash 计算开销

如果用 Vec + 二分,O(log n) 但 cache 友好,可能更快(对于小 n)。

### 8.3 工业级 TagDatabase 设计

游戏引擎(Unreal、Unity)的 asset system 是 Day 511 的进化版:

**Unreal**: `UObject` 系统 + FName(全局字符串 ID,内部 u32 index)。FName 的 lookup 是 O(1) 数组访问,比 HashMap 快。

**Unity**: `AssetDatabase.LoadAssetAtPath` + GUID 系统。每个 asset 有 GUID(128 bit),用 GUID 查资产。

**Bevy**: `Handle<T>` + `Assets<T>` 资源系统。Handle 是 generational index,支持热重载。

工业级特性:
- **异步加载**:lookup 不阻塞,asset 在后台线程加载
- **依赖追踪**:asset A 依赖 asset B,卸载 B 前要确认 A 不再用
- **生命周期管理**:引用计数 / 弱引用 / GC
- **序列化**:Tag ID 在 save file 里稳定

### 8.5 Troubleshooting

**问题1**:迁移后游戏崩,"TagId not found"。
诊断:HHT 文件里少了某个 tag,或 tag 名拼写不一致。
解决:HHT parse 后立刻 verify 所有游戏代码需要的 tag 都存在,缺哪个报哪个。

**问题2**:lookup 性能不够(每帧 100μs+)。
诊断:HashMap 占主导,hash 计算开销。
解决:
- 用 `FxHashMap`(Rust 生态 fast hash)替代 `HashMap`
- 或者用完美哈希(perfect hashing,n 个 key 用 O(n) build + O(1) lookup)
- 或者用 Vec + binary search(对小 n)

**问题3**:热重载后,旧 TagId 指向错数据。
诊断:热重载重建 TagDatabase,但旧 TagId 的 u32 index 在新 db 里指向不同 tag。
解决:
- 用 generational index(每个 slot 加 generation,旧引用 generation 不匹配)
- 或不允许热重载 add/remove tag,只允许改 value
- 或热重载时通知所有引用失效

**问题4**:HHT 文件大(10000+ tag),parse 慢。
诊断:HashMap insert 慢,要 hash + 可能 rehash。
解决:
- 预估 size,`HashMap::with_capacity(n)` 避免 rehash
- 用 BTreeMap 替代(O(log n) 但稳定)
- 或者两阶段:先扫一遍统计大小,再分配,再填

**问题5**:HHT parse 失败,游戏无法启动。
诊断:缺少 fallback。生产环境必须能优雅降级。
解决:
- 加 default HHT(嵌入 binary 里),文件读失败用 default
- 加 strict / lax 模式,strict 报错,lax 跳过坏 tag
- 加 schema 验证,parse 前验证
