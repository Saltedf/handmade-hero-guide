# Day 564 · 改进三线性采样结果

> Day 562 加了 smoothstep 缓解 trilinear 闪烁,但 smoothstep 让结果"模糊"。Day 564 Casey 试更高级的过滤——**Catmull-Rom**(双三次),锐利且平滑。

## 0 · 为什么要有这一天

让我们把镜头贴近屏幕。你跟着 Handmade Hero 走到 Day 562——Casey 加了 smoothstep 缓解 trilinear voxel 采样的闪烁。你跑游戏,远处光源周围稳定了,**但是**——你发现光源**比实际位置暗**了。光照"摊开"在 voxel 网格上,从一个集中的"亮点"变成了一个"模糊的色斑"。光照原本应该在 voxel 6 处达到峰值 10,经过 trilinear smoothstep 后,采到的最大值可能只有 6——光源被"稀释"了 40%。

这是 trilinear / smoothstep 这一族 filter 的**根本问题**:**它们是低通滤波器**。低通滤波器去掉高频——包括"光源峰值"这种**应该保留**的高频信息。光源本来是个 sharp 的尖峰,经过低通变成 broad 的山丘——视觉上光源不亮了、边缘不锐利了。

工业界的答案叫 **bicubic interpolation(双三次插值)**,具体实现用 **Catmull-Rom spline**(Catmull-Rom 样条)。bicubic 不是低通滤波器——它是**锐化滤波器**,能在采样点之间重建出更尖锐的峰,光源在 voxel 之间过渡时,峰值被保留甚至放大,边缘锐利。代价是计算量——bicubic 需要 4x4x4=64 个邻居(trilinear 只要 2x2x2=8),8 倍的计算量。

回顾 Day 562 的过滤选项光谱:

- **Nearest**(最近邻):每像素采一个 voxel,锯齿重
- **Trilinear**(三线性):8 邻居线性插值,平滑但模糊
- **Smoothstep**:trilinear 的"S 形"变体,稍好但仍是模糊
- **Bicubic / Catmull-Rom**:64 邻居三次插值,锐利且平滑

工程取舍:**Nearest** 最快,锯齿;**Trilinear** 中等,模糊;**Bicubic** 慢 4-8 倍,锐利。在 CPU 端这个 4-8 倍开销是 prohibitive 的,但 **GPU 端 fragment shader 完全负担得起**——GPU 的并行算力和 texture cache 让 bicubic 实际只慢 2-3 倍,不是 8 倍。Casey 在 voxel GI 的 fragment shader 里用 bicubic,就是工业实践。

工业游戏(如 Gears 5、Cyberpunk 2077 的 voxel GI)在 fragment shader 用 bicubic filter,因为 GPU 算力够。Casey 这天加 bicubic filter。

**学完今天,你应该能**:
- 解释为什么 trilinear 是低通、Catmull-Rom 是锐化,以及这两种 filter 的频域响应差别
- 推导 Catmull-Rom 样条的数学公式(4 个点 → 1 个三次多项式)
- 在 fragment shader 实现 3D Catmull-Rom 采样,理解 64 fetch 在 GPU 上为什么"只慢 2-3 倍"
- 用 `textureGather`(GLSL / WGSL)把 64 fetch 优化到 16,理解 GPU texture cache 的工作方式
- 判断"什么时候该用 bicubic、什么时候 trilinear 够"——质量 vs 性能的权衡

## 2 · 心智模型

### 类比:照片放大

让我们用一个真实的对比建立直觉。你手上有一张 64x64 的小图——你不知道它本来该是什么,你想把它"重建"成 256x256 的更高分辨率图(这在游戏开发里叫"upscaling")。你试三种算法:

**Nearest**(最近邻):每个新像素直接取原图一个像素。结果锯齿明显,像素化严重——你看到大块方块。频域解释:Nearest 在频域是"复制频谱",产生 aliasing 锯齿。

**Bilinear**(双线性):每个新像素取 4 邻居加权平均。结果平滑但**模糊**——你看到边缘晕开,细节消失。频域解释:Bilinear 在频域是 sinc²,主瓣宽,过滤掉了一些"该保留"的高频。

**Bicubic**(双三次):每个新像素取 16 邻居(4x4)用三次多项式拟合。结果**锐利且平滑**——边缘清晰,无锯齿,看起来像"真原图"。频域解释:Bicubic 在频域是 sinc³(或 sinc⁴,看具体实现),主瓣窄,sidelobe 也控制得更好,**保留更多高频**。

Voxel 采样也一样。Nearest 锯齿,trilinear 模糊,bicubic 锐利。Casey 之前用 trilinear,光源周围模糊;今天换成 bicubic,光源边界清晰。

### 严谨展开:Catmull-Rom spline

让我把 Catmull-Rom 样条彻底推导出来,这样你不只是会调 API。给定 4 个点 (p0, p1, p2, p3),我们要构造一条三次多项式曲线 P(t),满足四个约束:
- P(0) = p1(曲线在 t=0 处穿过 p1)
- P(1) = p2(曲线在 t=1 处穿过 p2)
- P'(0) = (p2 - p0) / 2(在 p1 处的导数 = p0 到 p2 的"中心差分")
- P'(1) = (p3 - p1) / 2(在 p2 处的导数 = p1 到 p3 的"中心差分")

第三、四条很关键——**用相邻两点的差分作为导数估计**,这就是 Catmull-Rom 的核心特征(称为 cardinal spline 的一种)。它保证了曲线**穿过所有控制点**(不像 Bezier 那样只在端点穿过),并且**导数连续**(所以曲线平滑)。

```rust
fn catmull_rom(p0: f32, p1: f32, p2: f32, p3: f32, t: f32) -> f32 {
    let t2 = t * t;
    let t3 = t2 * t;
    0.5 * (
        2.0 * p1 +
        (-p0 + p2) * t +
        (2.0*p0 - 5.0*p1 + 4.0*p2 - p3) * t2 +
        (-p0 + 3.0*p1 - 3.0*p2 + p3) * t3
    )
}
```

3D Catmull-Rom:每维做一次。

**为什么"每维做一次"就够了?**因为 Catmull-Rom 是**可分离 filter**(separable filter)——一个 N 维的 separable filter 可以分解成 N 个 1D filter 依次应用。具体步骤:

1. 沿 X 维度,对每个 (y, z) 组合做 4 点 Catmull-Rom,得到 4x4=16 个中间值(从 4x4x4=64 voxel 降维到 4x4=16)
2. 沿 Y 维度,对每个 z 做 4 点 Catmull-Rom,得到 4 个值(16 → 4)
3. 沿 Z 维度,做一次 4 点 Catmull-Rom,得到最终 1 个值(4 → 1)

这是 separable filter 的关键效率优化——O(4·N²) 而非 O(N³),对 4x4x4 是 48 次操作 vs 64 次。对更大的 filter kernel(如 6x6x6)节省更明显。

```rust
fn catmull_rom_3d(
    grid: &VoxelGrid,
    x: f32, y: f32, z: f32,
) -> f32 {
    let ix = x.floor() as i64;
    let iy = y.floor() as i64;
    let iz = z.floor() as i64;
    let fx = x - x.floor();
    let fy = y - y.floor();
    let fz = z - z.floor();

    // 4x4x4 = 64 voxel,沿每维 catmull-rom
    let mut intermediate = [[[0.0f32; 4]; 4]; 4];
    for dz in 0..4 {
        for dy in 0..4 {
            for dx in 0..4 {
                let v = grid.get_or_default(
                    ix + dx as i64 - 1,
                    iy + dy as i64 - 1,
                    iz + dz as i64 - 1,
                );
                intermediate[dz][dy][dx] = v;
            }
        }
    }

    // X 维度 catmull-rom
    let mut after_x = [[0.0f32; 4]; 4];
    for dz in 0..4 {
        for dy in 0..4 {
            after_x[dz][dy] = catmull_rom(
                intermediate[dz][dy][0],
                intermediate[dz][dy][1],
                intermediate[dz][dy][2],
                intermediate[dz][dy][3],
                fx,
            );
        }
    }

    // Y 维度
    let mut after_y = [0.0f32; 4];
    for dz in 0..4 {
        after_y[dz] = catmull_rom(
            after_x[dz][0], after_x[dz][1], after_x[dz][2], after_x[dz][3],
            fy,
        );
    }

    // Z 维度
    catmull_rom(after_y[0], after_y[1], after_y[2], after_y[3], fz)
}
```

64 个 voxel fetch + 21 次 catmull_rom 计算。GPU 上每像素 64 fetch 慢,但 cache 命中好(邻居 voxel 共享 cache line)。

### Bicubic vs Bilinear 视觉差别

考虑一个 voxel 光照值:

```
voxel[5] = 0
voxel[6] = 10  (光源)
voxel[7] = 0
```
voxel[6] = 10  (光源)
voxel[7] = 0
```

在 x=6.5 处采样:

- Nearest:voxel[6] = 10
- Trilinear:(10+0)/2 = 5(光源被稀释)
- Catmull-Rom:用 [0, 10, 0, 0] 算 catmull-rom,t=0.5
  - = 0.5 * (2*10 + (-0+0)*0.5 + (2*0-5*10+4*0-0)*0.25 + (-0+3*10-3*0+0)*0.125)
  - = 0.5 * (20 - 12.5 + 3.75) = 5.6
  - 接近 trilinear 但略高,因为 catmull-rom 保留"峰"

光源周围 catmull-rom 让光"更集中",trilinear 让光"摊开"。视觉差别光源周围 catmull-rom 锐利,trilinear 模糊。

### GPU 实现 tip

GPU fragment shader 实现:

```glsl
float catmull_rom(float p0, float p1, float p2, float p3, float t) {
    float t2 = t * t;
    float t3 = t2 * t;
    return 0.5 * (
        2.0 * p1 +
        (-p0 + p2) * t +
        (2.0*p0 - 5.0*p1 + 4.0*p2 - p3) * t2 +
        (-p0 + 3.0*p1 - 3.0*p2 + p3) * t3
    );
}

// GPU 优化:64 fetch 可以合并成 8 个 textureGather(取 2x2 邻居)
```

`textureGather`(GLSL / WGSL)一次性取 2x2 = 4 个 voxel,64 voxel 只需 16 次而非 64 次。GPU 友好。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Texture filtering 在工业游戏里的应用远不止 voxel GI:

**Bicubic upscaling(图像放大)**:PS4/Xbox One 时代很多游戏用 bicubic 把 720p 渲染缓冲放大到 1080p 输出。这种"渲染时降分辨率 + 输出时 bicubic 放大"的策略叫 dynamic resolution scaling,在 PS5/Xbox Series 时代仍然是性能救命稻草——GTA V 在 PS4 上就这样做,确保 30 FPS。bicubic 让放大的图像不像 bilinear 那样糊。

**Catmull-Rom for UI**:UI 文字、HUD 元素缩放时保持锐利。如果你的游戏支持多个分辨率(720p、1080p、4K),UI 不能用 bilinear 否则文字模糊。常用做法:用 Catmull-Rom 缩放 bitmap font,或者用 signed distance field(SDF)字体(更高级,质量更好)。

**Bicubic GI filtering**:Voxel GI(本仓库 Phase 7)、irradiance volume、light probe interpolation 都用 bicubic 让光照边界平滑且锐利。Crytek 在 Ryse: Son of Rome 里用 bicubic filter voxel GI,得到接近静态光照的质量。**业界惯例**:GI 用 bicubic 不是"奢侈",而是"必需"——否则光照显得"塑料感"(过度模糊)。

**Sharper bicubic 变体(Mitchell filter)**:Catmull-Rom 有一个缺陷——它对**高频输入**会"过冲"(overshoot),产生 ringing artifact(振铃)。Mitchell-Netravali filter 是 Catmull-Rom 的"软化版",引入一个 B(blur)参数和一个 C(锐度)参数,推荐 B+C=1。Casey 用纯 Catmull-Rom(B=0, C=0.5),为最大锐利度;Mitchell 推荐 B=1/3, C=1/3,锐利但少 ringing。商业游戏多选 Mitchell。

**Anti-aliased cone sampling**:更高级的 voxel 采样用"cone tracing"——把采样点看作一个小圆锥,在 voxel grid 上做积分。这是 voxel global illumination(如 Crassin et al. 2011)的核心思想。比 bicubic 还贵,但能处理"软阴影"和"光泽反射"。

### 3.2 · 🎨 图形学视角

Texture filtering 的数学本质是 **reconstruction filter(重建滤波器)**:从离散样本(像素值)重建出连续信号(图像函数 f(x,y))。不同 filter 是不同 trade-off:

- **Box filter**(Nearest):频域响应是 sinc 函数,sidelobe 大,泄漏严重。在空域表现为"采一个点",丢失所有邻居信息。
- **Triangle filter**(Bilinear):频域响应是 sinc²,主瓣宽,sidelobe 较少。在空域是 4 邻居加权,平滑但有低通损失。
- **Cubic filter**(Bicubic):频域响应是 sinc³(或 sinc⁴),主瓣窄,sidelobe 更少。在空域是 16 邻居三次拟合,锐利且平滑。
- **Lanczos filter**:sinc-windowed sinc,频域最理想(主瓣窄 + sidelobe 极小),但 6-8 邻居,贵。

更深入的视角:**filtering 在频域就是滤波**——你把图像做 FFT,看每个频率被 filter 衰减多少。Box 在频域是 sinc,响应不平坦——低频被保留,但中频有衰减,某些高频完全保留(就是 aliasing 的根源)。Bicubic 的频域响应更"平",中频和低频都保留得更好,高频被合理抑制。

**Nyquist 视角**:当 texture 被 downsample(mipmap level 高时),高频必须先低通。这是 mipmap 的原理(见 day546)。**但 mipmap 的低频版本之间的 interpolation,用 bicubic 比 bilinear 更好**——bicubic 在 mipmap level 间的"重建"保留更多低频细节,bilinear 把低频也模糊掉。

**Convolution 视角**:filtering 数学上是 convolution: `(f * g)(x) = sum_k f(k) g(x-k)`。bicubic 的 kernel 是 4-tap(4 点权重),Lanczos 是 6-tap,box 是 1-tap。**Tap 数越高,质量越好,代价越高**。

### 3.3 · 🐧 Linux 系统编程视角

"高阶插值"在 DSP / 音频 / 视频里也无处不在。让我列举几个关键场景:

**音频重采样**:CD 是 44.1kHz,DVD/蓝光是 48kHz,VoIP 常用 16kHz。在它们之间转换必须重采样——线性插值会有可听见的"高频失真",所以专业 resampler(`sox`、`libsamplerate`)用更高级的 filter。`sox` 默认用 band-limited sinc(类似 Lanczos),质量最高。Casey 用 Catmull-Rom 思想是相同的——但音频更敏感(耳朵对失真的容忍度比眼睛低),所以音频用比 bicubic 还高级的 filter。

**视频缩放**:YouTube 把上传的 4K 视频转码成 720p、1080p 多版本。downscale 时用 bicubic 或 Lanczos。FFmpeg 的 `lanczos`、`bicubic`、`spline` 选项对应不同 filter——专业视频制作者会指定 `-sws_flags lanczos` 获得最佳缩放质量。

**ImageMagick 的 resize**:`convert input.png -resize 50% -filter CatmullRom output.png`。ImageMagick 支持几十种 filter,工业 PS 操作者会用 CatmullRom 或 Lanczos。

**Linux 字体渲染(FreeType + HarfBuzz)**:字体 outline 是矢量(连续),光栅化到屏幕像素时,FreeType 用 anti-aliasing filter(类似 bicubic)让边缘平滑。这就是为什么 Linux 桌面字体比 Windows GDI 字体"更平滑"(Windows 用 ClearType,针对 LCD 子像素)。

**数字示波器**:硬件示波器采样率有限,要在两点之间"插值"显示。Keysight、Tektronix 用 sinc 插值(`sin(x)/x`)——这是理论上完美的低通重建(满足 Nyquist 的信号可由 sinc 完美重建)。

所有这些场景,本质都是"从离散样本重建连续信号"——bicubic 是其中一个候选 filter,Nyquist-Shannon 理论告诉你"理论上完美"是 sinc,实践上 bicubic 是 sinc 的好近似。

### 3.4 · 🦀 Rust 生态视角

Rust 的 `image` crate 提供基础 filter:

```rust
use image::{imageops, FilterType};

let img = image::open("input.png")?;
let resized = imageops::resize(&img, 256, 256, FilterType::CatmullRom);
```

`FilterType` 选项值得记住:
- `Nearest`:最近邻,最快但锯齿
- `Triangle`:双线性,中等质量
- `CatmullRom`:双三次,锐利(默认推荐)
- `Gaussian`:模糊,适合 downsample 抗 aliasing
- `Lanczos3`:窗口 sinc,最高质量但最慢(3 倍 CatmullRom 时间)

**生产环境的优化选择**:`fast_image_resize` crate 用 SIMD 加速(宽 4 个 f32 同时算),在 x86_64 AVX2 上比 `image::imageops` 快 5-10 倍。它支持 Catmull-Rom 和各种 filter。如果你做实时图像处理(视频流、屏幕共享),必须用它。

**Rust 生态的 filter crate**:
- `imageproc` 提供更多 filter(separable filter、cubic spline 等)
- `ab_glyph` / `rusttype` 用 bicubic 渲染字体 outline
- `resvg` 渲染 SVG 时用 bicubic 缩放图像

**自己在 Rust 实现 separable filter**:

```rust
// 通用 separable filter:对每行先做 1D filter,再对每列做 1D filter
fn apply_kernel_1d(samples: &[f32], kernel: &[f32], offset: f32) -> f32 {
    // kernel 长度 = 4(Catmull-Rom)
    // samples[0..4] 对应 p0, p1, p2, p3
    // offset 是 t (0..1)
    let t = offset;
    let t2 = t * t;
    let t3 = t2 * t;
    // Catmull-Rom 的 kernel 在每个 t 处算出来
    let w0 = -0.5*t + 1.0*t2 - 0.5*t3;
    let w1 = 1.0 + (-2.5)*t2 + 1.5*t3;
    let w2 = 0.5*t + 2.0*t2 - 1.5*t3;
    let w3 = -0.5*t2 + 0.5*t3;
    samples[0]*w0 + samples[1]*w1 + samples[2]*w2 + samples[3]*w3
}
```

这种"把 1D filter 应用到每个维度"的模式在 Rust 里用 trait + generic 写得很优雅——`fast_image_resize` 的源码就是这么组织的。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Catmull-Rom 64 fetch,为什么 GPU 慢不到 8 倍?

**参考解答**:GPU cache 友好——64 个邻居在 voxel grid 里**位置邻近**,共享 cache line。第一像素的 64 fetch 把它们加载到 cache,后续邻居像素的 fetch 大部分命中 cache。实测:Catmull-Rom 比 trilinear 慢 2-3 倍而非 8 倍。如果 voxel grid 内存布局好(Morton 排序),cache 命中率 90%+。

```rust
type V3 = [f32; 3];

fn catmull_rom_1d(p0: f32, p1: f32, p2: f32, p3: f32, t: f32) -> f32 {
    let t2 = t * t;
    let t3 = t2 * t;
    0.5 * (
        2.0 * p1 +
        (-p0 + p2) * t +
        (2.0*p0 - 5.0*p1 + 4.0*p2 - p3) * t2 +
        (-p0 + 3.0*p1 - 3.0*p2 + p3) * t3
    )
}

struct VoxelGrid {
    data: Vec<V3>,
    dim: usize,
}

impl VoxelGrid {
    fn new(dim: usize) -> Self {
        VoxelGrid { data: vec![[0.0; 3]; dim*dim*dim], dim }
    }
    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim + j) * self.dim + i
    }
    fn get_clamped(&self, i: i64, j: i64, k: i64) -> V3 {
        let i = i.max(0).min(self.dim as i64 - 1) as usize;
        let j = j.max(0).min(self.dim as i64 - 1) as usize;
        let k = k.max(0).min(self.dim as i64 - 1) as usize;
        self.data[self.idx(i, j, k)]
    }
}

fn sample_trilinear(grid: &VoxelGrid, x: f32, y: f32, z: f32) -> V3 {
    let i = x.floor() as i64;
    let j = y.floor() as i64;
    let k = z.floor() as i64;
    let fx = x - x.floor();
    let fy = y - y.floor();
    let fz = z - z.floor();
    let lerp3 = |a: V3, b: V3, t: f32| -> V3 {
        [a[0]+(b[0]-a[0])*t, a[1]+(b[1]-a[1])*t, a[2]+(b[2]-a[2])*t]
    };
    let c000 = grid.get_clamped(i, j, k);
    let c100 = grid.get_clamped(i+1, j, k);
    let c010 = grid.get_clamped(i, j+1, k);
    let c110 = grid.get_clamped(i+1, j+1, k);
    let c001 = grid.get_clamped(i, j, k+1);
    let c101 = grid.get_clamped(i+1, j, k+1);
    let c011 = grid.get_clamped(i, j+1, k+1);
    let c111 = grid.get_clamped(i+1, j+1, k+1);
    let c00 = lerp3(c000, c100, fx);
    let c10 = lerp3(c010, c110, fx);
    let c01 = lerp3(c001, c101, fx);
    let c11 = lerp3(c011, c111, fx);
    let c0 = lerp3(c00, c10, fy);
    let c1 = lerp3(c01, c11, fy);
    lerp3(c0, c1, fz)
}

fn sample_catmull(grid: &VoxelGrid, x: f32, y: f32, z: f32) -> V3 {
    let i = x.floor() as i64;
    let j = y.floor() as i64;
    let k = z.floor() as i64;
    let fx = x - x.floor();
    let fy = y - y.floor();
    let fz = z - z.floor();

    // X 维度 catmull-rom(对每个 yz 组合)
    let mut after_x = [[V3::default(); 4]; 4];
    for dk in 0..4 {
        for dj in 0..4 {
            let p0 = grid.get_clamped(i-1, j+dj as i64-1, k+dk as i64-1);
            let p1 = grid.get_clamped(i,   j+dj as i64-1, k+dk as i64-1);
            let p2 = grid.get_clamped(i+1, j+dj as i64-1, k+dk as i64-1);
            let p3 = grid.get_clamped(i+2, j+dj as i64-1, k+dk as i64-1);
            after_x[dk][dj] = [
                catmull_rom_1d(p0[0], p1[0], p2[0], p3[0], fx),
                catmull_rom_1d(p0[1], p1[1], p2[1], p3[1], fx),
                catmull_rom_1d(p0[2], p1[2], p2[2], p3[2], fx),
            ];
        }
    }

    // Y 维度
    let mut after_y = [V3::default(); 4];
    for dk in 0..4 {
        after_y[dk] = [
            catmull_rom_1d(after_x[dk][0][0], after_x[dk][1][0], after_x[dk][2][0], after_x[dk][3][0], fy),
            catmull_rom_1d(after_x[dk][0][1], after_x[dk][1][1], after_x[dk][2][1], after_x[dk][3][1], fy),
            catmull_rom_1d(after_x[dk][0][2], after_x[dk][1][2], after_x[dk][2][2], after_x[dk][3][2], fy),
        ];
    }

    // Z 维度
    [
        catmull_rom_1d(after_y[0][0], after_y[1][0], after_y[2][0], after_y[3][0], fz),
        catmull_rom_1d(after_y[0][1], after_y[1][1], after_y[2][1], after_y[3][1], fz),
        catmull_rom_1d(after_y[0][2], after_y[1][2], after_y[2][2], after_y[3][2], fz),
    ]
}

fn main() {
    let mut grid = VoxelGrid::new(8);
    // 中央放光源
    let mut idx = |x: usize, y: usize, z: usize| (z * 8 + y) * 8 + x;
    grid.data[idx(4, 4, 4)] = [10.0, 8.0, 6.0];

    // 在 (4.5, 4.5, 4.5) 采样(光源边缘)
    let pos = (4.5, 4.5, 4.5);
    let tri = sample_trilinear(&grid, pos.0, pos.1, pos.2);
    let cat = sample_catmull(&grid, pos.0, pos.1, pos.2);
    println!("Position {:?}: trilinear={:?}, catmull={:?}", pos, tri, cat);

    // 在 (4.9, 4.9, 4.9) 采样(接近光源中心)
    let pos = (4.9, 4.9, 4.9);
    let tri = sample_trilinear(&grid, pos.0, pos.1, pos.2);
    let cat = sample_catmull(&grid, pos.0, pos.1, pos.2);
    println!("Position {:?}: trilinear={:?}, catmull={:?}", pos, tri, cat);

    // 性能对比
    use std::time::Instant;
    let n = 100_000;

    let t = Instant::now();
    for _ in 0..n {
        let _ = sample_trilinear(&grid, 4.5, 4.5, 4.5);
    }
    println!("Trilinear: {:?} for {} queries", t.elapsed(), n);

    let t = Instant::now();
    for _ in 0..n {
        let _ = sample_catmull(&grid, 4.5, 4.5, 4.5);
    }
    println!("Catmull-Rom: {:?} for {} queries", t.elapsed(), n);
}
