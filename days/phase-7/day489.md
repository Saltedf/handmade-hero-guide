
# Day 489 · 实现撤销与重做

> 编辑器有"删错了"这种事故——你按 Delete 删掉宝箱,结果发现删错了。Day 489 给编辑器加 undo/redo,让你能"反悔"。这是工业编辑器的标配功能。

## 0 · 为什么要有这一天

任何允许用户修改数据的工具都需要 undo/redo——文本编辑器(Vim/Emacs/VSCode)、图形工具(Photoshop/GIMP)、CAD(AutoCAD)、IDE、3D 建模(Blender)。没有 undo 的工具用户没法用——错一次就毁所有。

Undo/Redo 的核心思想:**记录每次操作的"逆操作"**。删除了 entity?记录"重新创建该 entity"。移动了 entity?记录"移回原位置"。Undo 时按逆序执行这些逆操作。

工业级实现叫 **Command Pattern**(设计模式):

- 每个用户操作封装成一个 Command 对象
- Command 有两个方法:`do()`(执行)和 `undo()`(撤销)
- 维护两个栈:undo 栈(已执行的操作)和 redo 栈(被 undo 的操作)
- 用户执行新操作 → push 到 undo 栈,清空 redo 栈
- 用户 undo → 从 undo 栈 pop,执行 `undo()`,push 到 redo 栈
- 用户 redo → 从 redo 栈 pop,执行 `do()`,push 到 undo 栈

这套模式所有编辑器都用。Casey 在 Day 489 给 HH 编辑器加 undo/redo,完全按 Command Pattern。

完成这一天之后,你具备了:

- Command Pattern 的设计和实现
- Undo/redo 栈的管理
- 理解为什么"逆操作"比"快照"高效

## 2 · 心智模型

### 类比:后悔药 + 时间机器

想象你有两个超能力:

- **后悔药**:吃一颗,撤销你最近做的一件事
- **时间机器**:回到过去某时刻,但仅限"最近的过去"

Undo = 后悔药。Redo = "我后悔吃了后悔药"——回到吃药前的状态。

实现这两个超能力的代价:**每次做事都记录"反着做"的方法**。删除了文件 → 记录"恢复这个文件"(需要存文件备份)。发了一封邮件 → 记录"撤回邮件"(需要邮件服务器支持)。

有些操作"无法 undo"——比如烧掉一张纸(物理上不可逆)。软件里这种操作必须明确标记("此操作不可撤销"),警告用户。

### Command Pattern 详解

每个用户操作封装成 Command 对象,有两个核心方法:`do()` 和 `undo()`。

```rust
trait Command {
    fn do(&mut self, state: &mut State);
    fn undo(&mut self, state: &mut State);
    fn describe(&self) -> &'static str;
}
```

举例:删除 entity 的 Command:

```rust
struct DeleteEntityCommand {
    entity: Entity,    // 保存被删 entity 的完整副本(用于 undo 时恢复)
}

impl Command for DeleteEntityCommand {
    fn do(&mut self, state: &mut State) {
        state.entities.retain(|e| e.id != self.entity.id);
    }
    
    fn undo(&mut self, state: &mut State) {
        state.entities.push(self.entity.clone());
    }
    
    fn describe(&self) -> &'static str {
        "Delete entity"
    }
}
```

注意 `do` 和 `undo` 是对称的——`do` 删除,`undo` 重新添加。**undo 需要"完整恢复信息"**(entity 的所有字段),所以 Command 必须存足够数据。

### Undo/Redo 栈管理

```
执行 Command A:
  undo_stack: [A]
  redo_stack: []
  
执行 Command B:
  undo_stack: [A, B]
  redo_stack: []
  
Undo:
  从 undo_stack pop B
  调用 B.undo()
  push B 到 redo_stack
  undo_stack: [A]
  redo_stack: [B]
  
Undo again:
  从 undo_stack pop A
  调用 A.undo()
  push A 到 redo_stack
  undo_stack: []
  redo_stack: [B, A]
  
Redo:
  从 redo_stack pop A
  调用 A.do()
  push A 到 undo_stack
  undo_stack: [A]
  redo_stack: [B]
  
执行新 Command C:
  清空 redo_stack(被 undo 的命令"作废")
  push C 到 undo_stack
  undo_stack: [A, C]
  redo_stack: []
```

关键规则:**新操作清空 redo 栈**。因为 redo 是"重做被 undo 的操作",但用户既然做了新操作,redo 路径已经无效。

### Command 的合并(Macro)

有时多个操作应该作为一个 undo 单元。比如:

- 拖动 entity 时,每帧 mouse_move 都生成 MoveCommand
- Undo 时只 undo 一次,不要逐步回退拖动

解决:**合并连续 Command**。MoveCommand 检测"上一个 Command 也是 MoveCommand 且 id 相同",合并(只保留最初的 old_pos)。

```rust
fn push_command(&mut self, cmd: Box<dyn Command>) {
    // 检查能否合并
    if let Some(last) = self.undo_stack.last_mut() {
        if last.try_merge(&*cmd) {
            return;   // 合并成功,不 push 新 command
        }
    }
    self.undo_stack.push(cmd);
    self.redo_stack.clear();
}
```

`try_merge` 是可选 trait method,默认返回 false,特定 Command 实现。

### 内存管理:Command 的生命周期

每个 Command 在栈里待到被 pop。如果栈满了(比如限制 100 步),最早 push 的被丢弃。

```rust
const MAX_UNDO_HISTORY: usize = 100;

fn push_command(&mut self, cmd: Box<dyn Command>) {
    self.undo_stack.push(cmd);
    if self.undo_stack.len() > MAX_UNDO_HISTORY {
        self.undo_stack.remove(0);   // 丢弃最老的
    }
    self.redo_stack.clear();
}
```

工业编辑器(Photoshop)有"无限 undo",但内存占用大。Casey 设上限 100 步,平衡。

### 替代方案:Snapshot / Memento

另一种 undo 实现是 **Snapshot(Memento)模式**——每次操作前保存整个状态的快照,undo 时恢复快照。

优点:实现简单(任何操作都能 undo)。
缺点:内存爆炸(每次快照整个状态)。

Command Pattern 内存高效(只存"差异"),但实现复杂(每个操作都要写 Command 类)。

权衡:

- 操作少、状态小:Snapshot 简单
- 操作多、状态大:Command Pattern 必选

Casey 选 Command Pattern,因为 HH entity 多,Snapshot 会爆内存。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏开发里 undo/redo 有两个层次:

第一,**编辑器层**。Unity、Unreal、Godot 编辑器都有 undo,基于 Command Pattern。Unity 的 `Undo.RecordObject`、Unreal 的 `Transaction`、Godot 的 `UndoRedo` 类。

第二,**游戏内层**。游戏玩法本身有时需要 undo——棋类游戏(国际象棋的 take back move)、回合制 RPG(reload turn)、策略游戏(revert turn)。这些用同样的 Command Pattern。

游戏开发的 Command Pattern 有几个高级变种:

- **Reversible Command**:Command 不只存"逆操作"数据,还存"逆操作的逆操作"——多层 undo
- **Time-replay**:记录所有用户输入,undo 时回滚状态到某时刻,重新播放输入
- **State diff**:类似 git,存状态的 diff,undo 时反向应用 diff

Casey 用基础 Command Pattern,够 HH 用。后面 Phase 8 如果加 turn-based gameplay 可能扩展。

### 3.2 · 🎨 图形学视角

图形软件的 undo 通常用 **state snapshot** 而不是 Command Pattern——因为画笔操作复杂(Command 化困难),且画布大但快照可压缩。

Photoshop 的历史面板(History panel)是 state snapshot 的典型——每个 history entry 是一个完整状态快照,跳到任意 entry 即恢复。

3D 建模软件(Maya、Blender)用 Command Pattern,因为模型状态大但操作明确(move、rotate、scale)。

理解两种模式的取舍,看不同工具的 undo 实现。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上有几个"系统级 undo"对应:

**Git**:git 的 commit 历史就是 undo 序列。`git revert` 创建一个"逆操作"commit,而不是删除原 commit——这是 Command Pattern 的"只追加"思想。

**btrfs / ZFS snapshot**:文件系统级 snapshot。每次大操作前 snapshot,出问题回滚。这是 state snapshot 模式。

**`/proc/sys/kernel/printk`**:实时改内核参数,但重启丢失——这种是"无 undo"操作。Linux 内核参数很多是这样,改了不能 undo(除非重启)。

**systemd journal**:记录系统事件,理论上可"undo"事件——但实际事件不可逆。

**数据库事务**:BEGIN ... COMMIT/ROLLBACK。这是工业级 undo,基于 WAL(write-ahead log)。每个事务的操作记到 log,失败时 rollback 按 log 反向执行。

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
-- 如果第二步失败
ROLLBACK;   -- 撤销第一步
```

这是数据库版的 Command Pattern + 自动 undo。

### 3.4 · 🦀 Rust 生态视角

Rust 里实现 Command Pattern 的 idiomatic 方式。

第一,**trait + Box<dyn Command>**:

```rust
trait Command {
    fn execute(&mut self, state: &mut State);
    fn undo(&mut self, state: &mut State);
    fn describe(&self) -> &str;
    fn try_merge(&mut self, _other: &dyn Command) -> bool { false }
}

struct CommandStack {
    undo: Vec<Box<dyn Command>>,
    redo: Vec<Box<dyn Command>>,
}
```

动态分发,运行时多态。Casey 的 C 用函数指针表对应这种。

第二,**enum dispatch**(避免 dynamic dispatch):

```rust
enum Command {
    AddEntity(AddEntityCommand),
    DeleteEntity(DeleteEntityCommand),
    MoveEntity(MoveEntityCommand),
}

impl Command {
    fn execute(&mut self, state: &mut State) {
        match self {
            Self::AddEntity(c) => c.execute(state),
            // ...
        }
    }
    
    fn undo(&mut self, state: &mut State) {
        match self {
            Self::AddEntity(c) => c.undo(state),
            // ...
        }
    }
}
```

更 Rust 风格,性能略好(match 比 vtable 快)。但加新 Command 要改 enum。

第三,**redo crate**。现成的 Command Pattern 库,提供 `History<T>` 类型自动管理 undo/redo 栈:

```rust
use redo::History;

let mut history = History::new();
history.add(add_entity_cmd);
history.undo(&mut state);
history.redo(&mut state);
```

工业 Rust 项目用 `redo` 减少样板代码。

## 5 · 对照与变奏

Casey 在 Day 489 的 undo/redo 在不同领域有不同对应:

**文本编辑器**:Vim 的 `u` (undo)、Ctrl-R (redo)。每个文本操作(insert、delete)是 Command。

**图像编辑器**:Photoshop 的 History panel。状态快照模式。

**IDE**:IntelliJ 的 Local History。文件级快照 + 自动定时。

**Office**:Word/Excel 的多级 undo。Command Pattern。

**数据库**:事务 rollback。基于 WAL 的 undo。

**游戏**:棋类的悔棋、RPG 的存档。

**Web 浏览器**:Back/Forward 按钮。本质是 navigation command 的 undo/redo。

**OS**:macOS 的 Time Machine。系统级快照。

理解"操作可逆"是工程师的核心素养。每次你设计用户可改的数据,问自己:**怎么让用户能反悔?**

另一个对照:**Linear undo vs Tree undo**。Linear 是栈,只能线性回退。Tree 是分支,undo 后做了新操作,之前的"分支"保留(可回去)。Vim 的 undo-tree、Emacs 的 undo 都是 tree。Casey 用 linear,简单。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 Casey 在执行新操作时清空 redo 栈?

**参考解答**:两个理由:

第一,**语义正确**。Redo 是"重做刚才被 undo 的操作"。如果用户 undo 了删除,然后做了新操作(比如修改另一个 entity),原来的"重做删除"已经不适用——状态变了,重做可能导致数据损坏。

第二,**避免混乱**。如果不清空 redo,用户 redo 会跳到"被 undo 之前"的状态,但中间已经做了新操作,结果不合逻辑。清空 redo 强制"线性前进"——一旦新操作,之前 undo 路径作废。

替代是 tree-undo(保留所有分支),但实现复杂,大多数编辑器用 linear。

**参考解答**:

```rust
#[derive(Debug, Clone, PartialEq)]
struct Entity {
    id: u32,
    name: String,
    pos: [f32; 3],
}

#[derive(Default)]
struct EditorState {
    entities: Vec<Entity>,
    next_id: u32,
}

trait Command: std::fmt::Debug {
    fn execute(&mut self, state: &mut EditorState);
    fn undo(&mut self, state: &mut EditorState);
    fn describe(&self) -> &str;
}

#[derive(Debug)]
struct AddEntityCommand {
    entity: Entity,
}

impl Command for AddEntityCommand {
    fn execute(&mut self, state: &mut EditorState) {
        state.entities.push(self.entity.clone());
    }
    
    fn undo(&mut self, state: &mut EditorState) {
        state.entities.retain(|e| e.id != self.entity.id);
    }
    
    fn describe(&self) -> &str { "Add entity" }
}

#[derive(Debug)]
struct DeleteEntityCommand {
    entity: Entity,    // 保存副本用于恢复
}

impl Command for DeleteEntityCommand {
    fn execute(&mut self, state: &mut EditorState) {
        if let Some(idx) = state.entities.iter().position(|e| e.id == self.entity.id) {
            self.entity = state.entities.remove(idx);
        }
    }
    
    fn undo(&mut self, state: &mut EditorState) {
        state.entities.push(self.entity.clone());
    }
    
    fn describe(&self) -> &str { "Delete entity" }
}

#[derive(Debug)]
struct MoveEntityCommand {
    id: u32,
    old_pos: [f32; 3],
    new_pos: [f32; 3],
}

impl Command for MoveEntityCommand {
    fn execute(&mut self, state: &mut EditorState) {
        if let Some(e) = state.entities.iter_mut().find(|e| e.id == self.id) {
            e.pos = self.new_pos;
        }
    }
    
    fn undo(&mut self, state: &mut EditorState) {
        if let Some(e) = state.entities.iter_mut().find(|e| e.id == self.id) {
            e.pos = self.old_pos;
        }
    }
    
    fn describe(&self) -> &str { "Move entity" }
}

struct CommandStack {
    undo: Vec<Box<dyn Command>>,
    redo: Vec<Box<dyn Command>>,
}

impl CommandStack {
    fn new() -> Self {
        Self { undo: Vec::new(), redo: Vec::new() }
    }
    
    fn execute(&mut self, mut cmd: Box<dyn Command>, state: &mut EditorState) {
        cmd.execute(state);
        self.undo.push(cmd);
        self.redo.clear();   // 新操作清空 redo
    }
    
    fn undo(&mut self, state: &mut EditorState) -> bool {
        if let Some(mut cmd) = self.undo.pop() {
            cmd.undo(state);
            self.redo.push(cmd);
            true
        } else {
            false
        }
    }
    
    fn redo(&mut self, state: &mut EditorState) -> bool {
        if let Some(mut cmd) = self.redo.pop() {
            cmd.execute(state);
            self.undo.push(cmd);
            true
        } else {
            false
        }
    }
    
    fn can_undo(&self) -> bool { !self.undo.is_empty() }
    fn can_redo(&self) -> bool { !self.redo.is_empty() }
}

fn main() {
    let mut state = EditorState::default();
    let mut stack = CommandStack::new();
    
    println!("=== Undo/Redo 演示 ===\n");
    
    // 加 entity A
    stack.execute(
        Box::new(AddEntityCommand {
            entity: Entity { id: 1, name: "A".into(), pos: [0.0; 3] },
        }),
        &mut state,
    );
    println!("Added A: entities = {}", state.entities.len());
    
    // 加 entity B
    stack.execute(
        Box::new(AddEntityCommand {
            entity: Entity { id: 2, name: "B".into(), pos: [10.0, 0.0, 0.0] },
        }),
        &mut state,
    );
    println!("Added B: entities = {}", state.entities.len());
    
    // 移动 A
    stack.execute(
        Box::new(MoveEntityCommand {
            id: 1, old_pos: [0.0; 3], new_pos: [20.0, 0.0, 0.0],
        }),
        &mut state,
    );
    println!("Moved A to (20, 0, 0)");
    let a = state.entities.iter().find(|e| e.id == 1).unwrap();
    println!("  A.pos = {:?}", a.pos);
    
    // Undo 移动
    println!("\nUndo move:");
    stack.undo(&mut state);
    let a = state.entities.iter().find(|e| e.id == 1).unwrap();
    println!("  A.pos = {:?} (应该 [0,0,0])", a.pos);
    
    // Undo add B
    println!("\nUndo add B:");
    stack.undo(&mut state);
    println!("  entities count = {} (应该 1)", state.entities.len());
    
    // Undo add A
    println!("\nUndo add A:");
    stack.undo(&mut state);
    println!("  entities count = {} (应该 0)", state.entities.len());
    println!("  can_undo = {} (应该 false)", stack.can_undo());
    
    // Redo
    println!("\nRedo:");
    stack.redo(&mut state);
    println!("  entities count = {} (应该 1)", state.entities.len());
    
    stack.redo(&mut state);
    println!("  entities count = {} (应该 2)", state.entities.len());
    
    println!("\n  redo 栈里还有 move command");
    stack.redo(&mut state);
    let a = state.entities.iter().find(|e| e.id == 1).unwrap();
    println!("  A.pos = {:?} (应该 [20,0,0])", a.pos);
    
    // 新操作清空 redo
    println!("\n做完所有 redo 后做新操作:");
    stack.execute(
        Box::new(DeleteEntityCommand {
            entity: state.entities.iter().find(|e| e.id == 2).unwrap().clone(),
        }),
        &mut state,
    );
    println!("  Deleted B, entities count = {}", state.entities.len());
    println!("  can_redo = {} (应该 false,redo 已清空)", stack.can_redo());
}

    }
    
    #[test]
    fn test_new_command_clears_redo() {
        let mut state = EditorState::default();
        let mut stack = CommandStack::new();
        
        // Add A, B
        stack.execute(Box::new(AddEntityCommand {
            entity: Entity { id: 1, name: "A".into(), pos: [0.0; 3] },
        }), &mut state);
        stack.execute(Box::new(AddEntityCommand {
            entity: Entity { id: 2, name: "B".into(), pos: [0.0; 3] },
        }), &mut state);
        
        // Undo B
        stack.undo(&mut state);
        assert!(stack.can_redo());
        
        // New command (Add C)
        stack.execute(Box::new(AddEntityCommand {
            entity: Entity { id: 3, name: "C".into(), pos: [0.0; 3] },
        }), &mut state);
        
        assert!(!stack.can_redo());   // redo 被清空
    }
    
    #[test]
    fn test_move_undo() {
        let mut state = EditorState {
            entities: vec![Entity { id: 1, name: "X".into(), pos: [0.0; 3] }],
            next_id: 2,
        };
        let mut stack = CommandStack::new();
        
        stack.execute(Box::new(MoveEntityCommand {
            id: 1, old_pos: [0.0; 3], new_pos: [10.0, 0.0, 0.0],

        stack.undo(&mut state);
        assert_eq!(state.entities[0].pos, [0.0, 0.0, 0.0]);
    }
    
    #[test]
    fn test_delete_undo_restores_entity() {
        let mut state = EditorState {
            entities: vec![Entity { id: 1, name: "X".into(), pos: [5.0; 3] }],
            next_id: 2,
        };
        let mut stack = CommandStack::new();
        
        let entity_snapshot = state.entities[0].clone();
        stack.execute(Box::new(DeleteEntityCommand {
            entity: entity_snapshot,
        }), &mut state);
        
        assert_eq!(state.entities.len(), 0);
        
        stack.undo(&mut state);
        assert_eq!(state.entities.len(), 1);
        assert_eq!(state.entities[0].name, "X");
        assert_eq!(state.entities[0].pos, [5.0; 3]);
    }
```

为什么这么写:`Box<dyn Command>` 让 undo/redo 栈存不同类型的 Command——AddEntityCommand 和 MoveEntityCommand 都可以 push 到同一个栈。这是 Rust 表达"异质集合"的标准方式。

```rust
// 复用 Lv2 的 Entity / EditorState / Command trait / CommandStack

// ========================================
// 扩展:Command 合并(用于连续 Move)
// ========================================

trait MergeableCommand: Command {
    fn try_merge(&mut self, other: &dyn Command) -> bool {
        false   // 默认不合并
    }
}

impl MergeableCommand for MoveEntityCommand {
    fn try_merge(&mut self, other: &dyn Command) -> bool {
        // 如果 other 也是 MoveEntityCommand 且 id 相同,合并
        // 但 trait object 不能 downcast,所以这里简化
        // 实际工程用 enum dispatch 处理
        false
    }
}

// ========================================
// 扩展:历史限制
// ========================================

struct BoundedCommandStack {
    undo: Vec<Box<dyn Command>>,
    redo: Vec<Box<dyn Command>>,
    max_history: usize,
}

impl BoundedCommandStack {
    fn new(max_history: usize) -> Self {
        Self {
            undo: Vec::new(),
            redo: Vec::new(),
            max_history,
        }
    }
    
    fn execute(&mut self, mut cmd: Box<dyn Command>, state: &mut EditorState) {
        cmd.execute(state);
        self.undo.push(cmd);
        self.redo.clear();
        
        // 限制历史长度
        while self.undo.len() > self.max_history {
            self.undo.remove(0);   // 丢弃最老的
        }
    }
    
    fn undo(&mut self, state: &mut EditorState) -> bool {
        if let Some(mut cmd) = self.undo.pop() {
            cmd.undo(state);
            self.redo.push(cmd);
            true
        } else {
            false
        }
    }
    
    fn redo(&mut self, state: &mut EditorState) -> bool {
        if let Some(mut cmd) = self.redo.pop() {
            cmd.execute(state);
            self.undo.push(cmd);
            true
        } else {
            false
        }
    }
}

// ========================================
// 演示:编辑器集成
// ========================================

struct Editor {
    state: EditorState,
    history: BoundedCommandStack,
}

impl Editor {
    fn new() -> Self {
        Self {
            state: EditorState::default(),
            history: BoundedCommandStack::new(100),   // 最多 100 步 undo
        }
    }
    
    fn add_entity(&mut self, name: &str, pos: [f32; 3]) -> u32 {
        let id = self.state.next_id;
        self.state.next_id += 1;
        
        self.history.execute(
            Box::new(AddEntityCommand {
                entity: Entity {
                    id, name: name.to_string(), pos,
                },
            }),
            &mut self.state,
        );
        
        println!("  + {} (id={}, pos={:?})", name, id, pos);
        id
    }
    
    fn delete_entity(&mut self, id: u32) {
        let entity = match self.state.entities.iter().find(|e| e.id == id) {
            Some(e) => e.clone(),
            None => return,
        };
        
        self.history.execute(
            Box::new(DeleteEntityCommand { entity }),
            &mut self.state,
        );
        println!("  - entity {}", id);
    }
    
    fn move_entity(&mut self, id: u32, new_pos: [f32; 3]) {
        let old_pos = match self.state.entities.iter().find(|e| e.id == id) {
            Some(e) => e.pos,
            None => return,
        };
        
        self.history.execute(
            Box::new(MoveEntityCommand { id, old_pos, new_pos }),
            &mut self.state,
        );
        println!("  → entity {} to {:?}", id, new_pos);
    }
    
    fn undo(&mut self) {
        if self.history.undo(&mut self.state) {
            println!("  ← undo");
        } else {
            println!("  (nothing to undo)");
        }
    }
    
    fn redo(&mut self) {
        if self.history.redo(&mut self.state) {
            println!("  → redo");
        } else {
            println!("  (nothing to redo)");
        }
    }
    
    fn dump(&self) {
        println!("  Entities ({}):", self.state.entities.len());
        for e in &self.state.entities {
            println!("    {} {} pos={:?}", e.id, e.name, e.pos);
        }
    }
}

fn main() {
    println!("=== Editor with Undo/Redo ===\n");
    let mut editor = Editor::new();
    
    println!("[1] Add entities:");
    editor.add_entity("hero", [0.0; 3]);
    editor.add_entity("goblin", [50.0, 0.0, 0.0]);
    editor.add_entity("chest", [0.0, 50.0, 0.0]);
    editor.dump();
    
    println!("\n[2] Move hero:");
    editor.move_entity(1, [10.0, 10.0, 0.0]);
    editor.move_entity(1, [20.0, 20.0, 0.0]);
    editor.dump();
    
    println!("\n[3] Delete goblin:");
    editor.delete_entity(2);
    editor.dump();
    
    println!("\n[4] Undo 5 times:");
    for _ in 0..5 {
        editor.undo();
    }
    editor.dump();
    
    println!("\n[5] Redo 3 times:");
    for _ in 0..3 {
        editor.redo();
    }
    editor.dump();
    
    println!("\n[6] New operation (clears redo):");
    editor.add_entity("torch", [30.0, 30.0, 0.0]);
    editor.dump();
    
    println!("\n[7] Try redo (should fail):");
    editor.redo();
    
    // 验证历史限制
    println!("\n=== 历史限制测试 ===");
    let mut small_editor = Editor {
        state: EditorState::default(),
        history: BoundedCommandStack::new(3),    // 只允许 3 步 undo
    };
    
    println!("Adding 5 entities (max undo = 3):");
    for i in 0..5 {
        small_editor.add_entity(&format!("e{}", i), [i as f32; 3]);
    }
    
    println!("Undo 5 times:");
    for _ in 0..5 {
        small_editor.undo();
    }
    println!("Final state: {} entities (应该至少 2,因为只能 undo 3 步)",
             small_editor.state.entities.len());
}

#[cfg(test)]
mod bounded_tests {
    use super::*;
    
    #[test]
    fn test_bounded_history() {
        let mut state = EditorState::default();
        let mut stack = BoundedCommandStack::new(3);
        
        // Add 5 entities
        for i in 0..5 {
            stack.execute(Box::new(AddEntityCommand {
                entity: Entity { id: i, name: format!("e{}", i), pos: [0.0; 3] },
            }), &mut state);
        }
        
        assert_eq!(state.entities.len(), 5);
        assert_eq!(stack.undo.len(), 3);   // 被限制到 3
        
        // Undo 3 次,只能撤回最后 3 个
        for _ in 0..3 {
            assert!(stack.undo(&mut state));
        }
        assert_eq!(state.entities.len(), 2);   // 5 - 3 = 2
        
        // 第 4 次 undo 应该失败
        assert!(!stack.undo(&mut state));
    }
}
```
