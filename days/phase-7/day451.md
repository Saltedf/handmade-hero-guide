让我把屏幕到世界的坐标变换链路彻底讲清楚,这是 unproject 的数学基础。

**四个坐标空间**。3D 图形渲染涉及四个坐标空间:

```
世界空间 (World Space)
    ↓ view matrix (从相机位置和朝向)
视图空间 (View Space,或 Eye Space,相机本地)
    ↓ projection matrix (透视/正交)
裁剪空间 (Clip Space)
    ↓ perspective divide (除以 w)
NDC (Normalized Device Coordinates, [-1,1]³)
    ↓ viewport transform (缩放到屏幕)
屏幕空间 (Screen Space,像素)
```

正向渲染时从上往下——物体的世界坐标 → 视图 → 投影 → 屏幕。**反向(unproject)** 从下往上——屏幕像素 → NDC → 视图 → 世界。

**屏幕 → NDC**。屏幕坐标 `(sx, sy)`(像素,左上角为 (0,0)),转 NDC `(-1, 1)`(中心为 (0,0)):

```
ndc_x = (2 * sx / screen_width) - 1
ndc_y = 1 - (2 * sy / screen_height)  // 注意 Y 反转!
```

Y 反转是因为屏幕 Y 向下增长,NDC Y 向上增长。

**NDC → Clip**。NDC 是已经做过 perspective divide 的(perspective divide 后 w=1)。要回到 clip space,我们设 `z = -1`(近平面)和 `z = +1`(远平面),w = 1。这两个点对应相机射线的起点和终点。

**Clip → View**。乘以 `projection_matrix.inverse()`,得到 view space 的两个点——相机射线的起点(近)和终点(远)。

**View → World**。乘以 `view_matrix.inverse()`,得到世界空间的两个点。从这两个点构造一条 3D 射线。

**简化**:对透视投影,view space 的射线起点永远是原点(相机位置)。所以 world space 的射线起点就是相机世界位置,方向是变换后的点 - 相机位置。

**视图矩阵从四元数构造**。Day 443 之后,相机朝向是四元数。视图矩阵:

```rust
fn view_matrix(camera_pos: Vec3, orientation: Quat) -> Mat4 {
    let rot = orientation.to_matrix4();        // 旋转部分
    let trans = Mat4::translation(-camera_pos); // 平移到相机原点
    rot.transposed() * trans  // 注意:视图矩阵是相机变换的逆
}
```

视图矩阵把"世界坐标"变换到"相机本地坐标"——平移(让相机在原点)+ 旋转(让相机看向 -Z)。

unproject 的核心步骤:

```rust
fn unproject(screen_x: f32, screen_y: f32, camera: &Camera, proj: &Mat4) -> Ray {
    // 1. 屏幕 → NDC
    let ndc_x = (2.0 * screen_x / screen_width) - 1.0;
    let ndc_y = 1.0 - (2.0 * screen_y / screen_height);
    
    // 2. NDC → Clip(两个点:近、远)
    let near_clip = Vec4::new(ndc_x, ndc_y, -1.0, 1.0);
    let far_clip = Vec4::new(ndc_x, ndc_y, 1.0, 1.0);
    
    // 3. Clip → View
    let proj_inv = proj.inverse();
    let near_view = proj_inv * near_clip;
    let far_view = proj_inv * far_clip;
    // perspective divide
    let near_view = near_view.truncate() / near_view.w;
    let far_view = far_view.truncate() / far_view.w;
    
    // 4. View → World
    let view = view_matrix(camera.pos, camera.orientation);
    let view_inv = view.inverse();
    let near_world = view_inv * near_view.extend(1.0);
    let far_world = view_inv * far_view.extend(1.0);
    
    // 5. 构造射线
    Ray {
        origin: near_world.truncate(),
        direction: (far_world - near_world).truncate().normalize(),
    }
}
```

**射线和地面求交**。得到世界射线后,和地面(y=0 平面)求交:

```rust
fn ray_plane_intersect(ray: &Ray, plane_y: f32) -> Option<Vec3> {
    if ray.direction.y.abs() < 1e-6 { return None; }  // 射线水平
    let t = (plane_y - ray.origin.y) / ray.direction.y;
    if t < 0.0 { return None; }  // 射线反向
    Some(ray.origin + ray.direction * t)
}
```

## 补充:射线-AABB 求交(3D 拾取的核心)

除了"射线-地面求交",编辑器经常需要"射线-AABB 求交"——点击选物体。给定一条射线 `origin + t*direction` 和一个 AABB,求交点。

**Slab Method(平板法)**。AABB 是 3 对平行平面(slab)的交集:X 平板、Y 平板、Z 平板。射线进每个平板有个进/出时间。射线进 AABB 的条件:**进所有平板的时间 max < 出所有平板的时间 min**。

```rust
fn ray_aabb_intersect(ray: &Ray, aabb: &AABB) -> Option<f32> {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    
    for axis in 0..3 {  // X, Y, Z
        let o = ray.origin[axis];
        let d = ray.direction[axis];
        if d.abs() < 1e-6 {
            // 射线平行于这个轴的平板
            if o < aabb.min[axis] || o > aabb.max[axis] {
                return None;  // 不在平板内
            }
        } else {
            let t1 = (aabb.min[axis] - o) / d;
            let t2 = (aabb.max[axis] - o) / d;
            let (t1, t2) = if t1 < t2 { (t1, t2) } else { (t2, t1) };
            t_min = t_min.max(t1);
            t_max = t_max.min(t2);
            if t_min > t_max { return None; }
        }
    }
    
    if t_min < 0.0 { return None; }  // AABB 在射线后面
    Some(t_min)
}
```

每行解释:
- `t1, t2` 是射线进入/离开这个轴平板的时间。
- `t_min = max(...)` 是射线进入所有平板的时间(最晚进入)。
- `t_max = min(...)` 是射线离开所有平板的时间(最早离开)。
- 如果 `t_min > t_max`,射线"提前"离开——不相交。
- 如果 `t_min < 0`,相交点在射线起点之后(射线方向反向)——根据需求返回或拒绝。

这个算法是 **3D 拾取(picking)** 的核心——点击屏幕,射线穿过物体,选最近的 AABB。

**多个 AABB 的最近相交**。场景有 N 个物体,点击鼠标选最近的:

```rust
fn pick_object(ray: &Ray, objects: &[(EntityId, AABB)]) -> Option<EntityId> {
    let mut closest: Option<(f32, EntityId)> = None;
    for (id, aabb) in objects {
        if let Some(t) = ray_aabb_intersect(ray, aabb) {
            if closest.map(|(c, _)| t < c).unwrap_or(true) {
                closest = Some((t, *id));
            }
        }
    }
    closest.map(|(_, id)| id)
}
```

每行解释:
- 遍历所有物体,求射线和它们 AABB 的相交时间。
- 保留最小 t(最近)。
- 返回最近物体的 ID。

## 补充:投影矩阵的几何推导

unproject 用 `projection_matrix.inverse()`,所以理解投影矩阵本身很重要。让我推导透视投影。

**透视投影的几何**。设相机在原点,看向 -Z 方向,近平面距离 `n`,远平面距离 `f`,视野 FOV(field of view,垂直角度),宽高比 aspect。

世界点 `(x, y, z)`(在 view space,z 是负的,因为我们看 -Z)投影到近平面的 `(x_p, y_p, n)`。由相似三角形:

```
x_p / n = x / (-z)   →   x_p = n * x / (-z)
y_p / n = y / (-z)   →   y_p = n * y / (-z)
```

近平面是个矩形,宽 `2 * n * tan(FOV/2) * aspect`,高 `2 * n * tan(FOV/2)`。投影到 NDC 归一化:

```
ndc_x = x_p / (n * tan(FOV/2) * aspect) = x / (-z * tan(FOV/2) * aspect)
ndc_y = y_p / (n * tan(FOV/2)) = y / (-z * tan(FOV/2))
```

Z 方向稍微复杂(NDC 是线性的 [-1, 1],但 view space z 是非线性的):

```
ndc_z = (f + n) / (f - n) + 2 * f * n / ((f - n) * (-z))
```

写成矩阵形式 `clip = projection * view_point`:

```
projection = [
    [1/(tan(FOV/2)*aspect), 0, 0, 0],
    [0, 1/tan(FOV/2), 0, 0],
    [0, 0, (f+n)/(n-f), 2*f*n/(n-f)],
    [0, 0, -1, 0]
]
```

注意 clip.w = -z,这就是 perspective divide 的来源——后面除以 w 实际是除以 -z。

**unproject 反向**。从 NDC `(nx, ny, nz)` 和 `w=1`,乘 `proj.inverse()`,得到 `clip = (nx, ny, nz, 1) * (n*tan(FOV/2)*aspect / -z, ...)`,然后 perspective divide 把 w 缩回 1。

这些细节在工业图形库里(glm、nalgebra)已经实现,你只要调 `Mat4::perspective(fov, aspect, near, far)`。但理解推导让你能调 bug——比如"远物消失"是 far plane 不够远,"鱼眼"是 FOV 太大。

## 补充:浮点精度的反投影陷阱

unproject 涉及大量矩阵运算,浮点精度问题不容忽视。让我讲讲几个常见陷阱:

**陷阱 1:perspective divide 除以 0**。某些点 clip.w 可能是 0(无穷远),除会得 NaN。unproject 时通常假设 w=1,但如果投影矩阵特殊(比如正交投影 w=1 始终),要分情况。

**陷阱 2:矩阵求逆的数值稳定性**。`proj.inverse()` 在投影矩阵接近奇异(far=∞ 或 near=0)时不稳定。要用 stable inverse 算法。

**陷阱 3:Y 反转**。屏幕坐标 Y 向下,NDC Y 向上。少一个负号就反了——这是常见 bug。检查:`(0, 0)` 像素应该对应 NDC `(-1, +1)`(左上角)。

**陷阱 4:坐标系 handedness**。OpenGL 用右手系(+X 右,+Y 上,+Z 出屏幕),DirectX 用左手系(+Z 进屏幕)。数学库不同导致同一矩阵在两系统下行为不同。

**陷阱 5:近平面太近**。near=0.001 时,远处的 z 在 NDC 上挤到一起(z-fighting)。常用 near=0.1。

工业实践:**用 nalgebra / glm 这种成熟库,不要自己写矩阵运算**。它们已经处理了所有陷阱。Casey HH 教学手写,但他也是 30 年经验的图形程序员,知道陷阱在哪。

## 2 · 心智模型

### 类比:从照片反推拍照位置

正投影(project)是从 3D 世界生成 2D 照片。反投影(unproject)反过来:从照片的某个像素,推断 3D 世界里的射线。

直觉:照片上每个像素对应相机镜头出的一根射线。射线起点是相机,方向由像素位置决定。射线穿过 3D 空间,可能撞到地面、墙壁、怪物——反投影只给你射线,撞到什么要后续求交算。

### 严谨原理:坐标变换链路

3D 渲染涉及四个坐标空间,层层变换:

```
屏幕坐标 (Screen space)
  ↓ (减去 viewport 偏移,除以 viewport 大小,缩放到 [-1, 1])
NDC (Normalized Device Coordinates)
  ↓ (乘 projection 矩阵的逆)
视图坐标 (View/Eye space,相机为原点)
  ↓ (乘 view 矩阵的逆)
世界坐标 (World space)
  ↓ (乘 model 矩阵的逆,如果需要)
模型坐标 (Model/Object space)
```

**正投影** = Model → World → View → NDC → Screen(顶点变换到屏幕)。
**反投影** = Screen → NDC → View → World(像素反推到世界)。

### 反投影的实现

```rust
struct Camera {
    position: Vec3,
    orientation: Quat,  // 四元数朝向
    fov: f32,           // 视场角
    aspect: f32,        // 宽高比
    near: f32,
    far: f32,
}

fn unproject(
    screen_x: f32, screen_y: f32,
    screen_w: f32, screen_h: f32,
    camera: &Camera,
) -> Ray {
    // 1. 屏幕到 NDC:像素坐标 → [-1, 1]
    let ndc_x = (screen_x / screen_w) * 2.0 - 1.0;
    let ndc_y = 1.0 - (screen_y / screen_h) * 2.0;  // Y 翻转(屏幕 Y 朝下)
    // NDC 深度 -1(near plane)
    let ndc_near = Vec3 { x: ndc_x, y: ndc_y, z: -1.0 };
    // NDC 深度 +1(far plane)
    let ndc_far = Vec3 { x: ndc_x, y: ndc_y, z: 1.0 };

    // 2. 反投影矩阵
    let proj_inv = perspective_inv(camera.fov, camera.aspect, camera.near, camera.far);
    let view_inv = view_matrix_inv(camera);

    // 3. NDC → View → World
    let view_near = proj_inv.transform(ndc_near);
    let view_far = proj_inv.transform(ndc_far);
    let world_near = view_inv.transform(view_near);
    let world_far = view_inv.transform(view_far);

    // 4. 构造射线
    let direction = (world_far - world_near).normalize();
    Ray { origin: world_near, direction }
}
```

每行解释:
- `ndc_y = 1.0 - ...` — 屏幕 Y 朝下,NDC Y 朝上,要翻转。
- `ndc_near / far` — 同一像素在 near 和 far 平面的 NDC 坐标,差只在 Z。
- `proj_inv.transform()` — 4×4 矩阵乘 4D 向量(齐次坐标),返回 3D。
- 射线从 near 点出发,指向 far 点。

### View 矩阵(相机变换)

视图矩阵把世界坐标变换到"相机为原点、相机朝 -Z"的坐标系。**直觉**:把整个世界向后移动相机位置,再旋转使相机朝向对齐 -Z。

```rust
fn view_matrix_inv(camera: &Camera) -> Mat4 {
    // 先平移到 -position,再旋转 -orientation 的逆
    let t = Mat4::translation(-camera.position);
    let r = Mat4::from_quat(camera.orientation).transpose();  // 转置 = 正交矩阵的逆
    r * t  // 注意顺序
}
```

每行解释:
- `Mat4::translation(-position)` — 把世界平移,使相机到原点。
- `from_quat` — 四元数转旋转矩阵。
- `.transpose()` — 旋转矩阵正交,转置 = 逆。避免昂贵的通用矩阵求逆。

### 反投影 + 地面求交

得到世界射线后,求它和地面(Y=0 平面)的交点:

```rust
fn ray_plane_intersect(ray: &Ray, plane_y: f32) -> Option<Vec3> {
    // 平面法线 = (0, 1, 0),平面 y = plane_y
    // 射线 P(t) = origin + t * direction
    // P.y = plane_y → t = (plane_y - origin.y) / direction.y
    if direction.y.abs() < 1e-6 { return None; }  // 射线平行地面
    let t = (plane_y - ray.origin.y) / ray.direction.y;
    if t < 0.0 { return None; }  // 反向,看不到
    Some(ray.origin + ray.direction * t)
}
```

每行解释:
- 解 `origin.y + t * direction.y = plane_y`,得 `t`。
- `t < 0` 说明交点在射线背后(相机背后),不算。
- `direction.y.abs() < 1e-6` 说明射线和地面平行,永远不会相交。

### 3.2 · 图形学视角

坐标系变换是图形学最基础的概念:

| 空间 | 坐标系 |
|---|---|
| 模型(Model) | 物体自身原点 |
| 世界(World) | 全局坐标 |
| 视图(View) | 相机为原点 |
| 裁剪(Clip) | 投影后,NDC 前 |
| NDC | [-1, 1] |
| 屏幕(Screen) | 像素坐标 |

变换链:Model → World(模型矩阵)→ View(视图矩阵)→ Clip(投影矩阵)→ NDC(透视除法)→ Screen(viewport 变换)。

反投影是逆链。

**深度精度**:Z buffer 在 NDC 空间是 [-1, 1],但实际场景深度可能 1 米到 1000 米。Z 精度集中在 near 附近(far 精度低)。所以 unproject 用 near/far 两个点而不是直接用 NDC Z。

### 3.4 · Rust 生态视角

Rust 的 unproject 库:

- `glam::Mat4::project_vector3` / `unproject`
- `nalgebra::Matrix4::try_inverse`
- `rendology::Camera` 封装完整变换

```rust
use glam::{Mat4, Vec3};

fn unproject(screen: Vec3, viewport: Vec4, proj_view_inv: Mat4) -> Vec3 {
    let ndc_x = (screen.x - viewport.x) / viewport.z * 2.0 - 1.0;
    let ndc_y = (screen.y - viewport.y) / viewport.w * 2.0 - 1.0;
    let ndc_z = screen.z * 2.0 - 1.0;
    let world = proj_view_inv * Vec3::new(ndc_x, ndc_y, ndc_z).extend(1.0);
    world.truncate() / world.w  // 透视除法
}
```

每行解释:
- `viewport = (x, y, w, h)` — 屏幕视口位置和大小。
- `screen.z` 是 [0, 1] 的深度(读 depth buffer)。
- `.extend(1.0)` — Vec3 扩展为 Vec4(齐次坐标)。
- `world.w` 是齐次坐标 w 分量,除以它完成透视除法。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么屏幕 Y 要翻转(`1.0 - ...`)而 X 不用?

**参考解答**:屏幕坐标 Y 朝下(像素 0 在屏幕顶端),NDC Y 朝上(1 在顶部)。两者方向相反,所以要 `1.0 - y`。

X 屏幕坐标和 NDC 都是朝右,方向一致,不需要翻转。

### Lv2 · 动手实践

**题**:实现 unproject + ray_plane_intersect。给定相机和屏幕坐标,返回地面上的点。

**参考解答**:

```rust
#[derive(Debug, Clone, Copy)]
struct Vec3 { x: f32, y: f32, z: f32 }

impl Vec3 {
    fn zero() -> Self { Self { x: 0.0, y: 0.0, z: 0.0 } }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
    fn normalize(self) -> Self {
        let len = self.dot(self).sqrt();
        Self { x: self.x/len, y: self.y/len, z: self.z/len }
    }
}

impl std::ops::Sub for Vec3 {
    type Output = Self;
    fn sub(self, o: Self) -> Self { Self { x: self.x-o.x, y: self.y-o.y, z: self.z-o.z } }
}

impl std::ops::Add for Vec3 {
    type Output = Self;
    fn add(self, o: Self) -> Self { Self { x: self.x+o.x, y: self.y+o.y, z: self.z+o.z } }
}

impl std::ops::Mul<f32> for Vec3 {
    type Output = Self;
    fn mul(self, k: f32) -> Self { Self { x: self.x*k, y: self.y*k, z: self.z*k } }
}

struct Ray { origin: Vec3, direction: Vec3 }

fn ray_plane_y_intersect(ray: &Ray, plane_y: f32) -> Option<Vec3> {
    if ray.direction.y.abs() < 1e-6 { return None; }
    let t = (plane_y - ray.origin.y) / ray.direction.y;
    if t < 0.0 { return None; }
    Some(Vec3 {
        x: ray.origin.x + ray.direction.x * t,
        y: plane_y,
        z: ray.origin.z + ray.direction.z * t,
    })
}

fn main() {
    // 相机在 (0, 5, 10),朝向 -Z 方向看(简化,不用四元数)
    let camera_pos = Vec3 { x: 0.0, y: 5.0, z: 10.0 };
    let camera_forward = Vec3 { x: 0.0, y: -0.5, z: -1.0 }.normalize();

    // 模拟:屏幕中心点对应"地平线下方"的射线
    let center_ray = Ray {
        origin: camera_pos,
        direction: camera_forward,
    };

    let hit = ray_plane_y_intersect(&center_ray, 0.0);
    println!("Center ray hits ground at: {:?}", hit);
    // 应该返回某个 (x, 0, z),z 在相机前方

    // 屏幕角落射线
    let corner_ray = Ray {
        origin: camera_pos,
        direction: Vec3 { x: 0.5, y: -0.5, z: -1.0 }.normalize(),
    };
    let hit2 = ray_plane_y_intersect(&corner_ray, 0.0);
    println!("Corner ray hits ground at: {:?}", hit2);
}
```

每行解释:
- 实现 `Sub/Add/Mul` 让 Vec3 用运算符,代码更清晰。
- `camera_forward` 简化朝向(实际用四元数 + forward 计算)。
- 中心射线应朝正前方(略向下),撞地面在 (0, 0, z)。
- 角落射线偏右下,撞地面在 (正, 0, 略前)。

完成标准:
- 中心射线撞地面 z > 0(在相机前方)
- 角落射线撞地面 x > 0(偏右)

## 8 · Rust / Arch 落地代码

完整 unproject demo:

```rust
// (Vec3, Ray 实现见 Lv2)

// 4x4 矩阵(列主序)
#[derive(Debug, Clone, Copy)]
struct Mat4 {
    m: [[f32; 4]; 4],
}

impl Mat4 {
    fn identity() -> Self {
        let mut m = [[0.0; 4]; 4];
        for i in 0..4 { m[i][i] = 1.0; }
        Self { m }
    }
    fn translation(t: Vec3) -> Self {
        let mut m = Self::identity();
        m.m[3][0] = t.x; m.m[3][1] = t.y; m.m[3][2] = t.z;
        m
    }
    fn perspective(fov_y: f32, aspect: f32, near: f32, far: f32) -> Self {
        let f = 1.0 / (fov_y * 0.5).tan();
        let nf = 1.0 / (near - far);
        let mut m = [[0.0; 4]; 4];
        m[0][0] = f / aspect;
        m[1][1] = f;
        m[2][2] = (far + near) * nf;
        m[2][3] = -1.0;
        m[3][2] = 2.0 * far * near * nf;
        Self { m }
    }
    fn transform_point(&self, p: Vec3) -> Vec3 {
        // p.extend(1) * M
        let px = p.x; let py = p.y; let pz = p.z;
        let x = self.m[0][0]*px + self.m[1][0]*py + self.m[2][0]*pz + self.m[3][0];
        let y = self.m[0][1]*px + self.m[1][1]*py + self.m[2][1]*pz + self.m[3][1];
        let z = self.m[0][2]*px + self.m[1][2]*py + self.m[2][2]*pz + self.m[3][2];
        let w = self.m[0][3]*px + self.m[1][3]*py + self.m[2][3]*pz + self.m[3][3];
        Vec3 { x: x/w, y: y/w, z: z/w }
    }
}

fn main() {
    let camera_pos = Vec3 { x: 0.0, y: 5.0, z: 10.0 };
    let view = Mat4::translation(Vec3 { x: -camera_pos.x, y: -camera_pos.y, z: -camera_pos.z });
    let proj = Mat4::perspective(
        std::f32::consts::FRAC_PI_3, 0.5, 1.0, 100.0,
    );

    // 屏幕中心 → NDC (0, 0)
    let center = Vec3 { x: 0.0, y: 0.0, z: -1.0 };  // NDC near plane
    let view_point = proj.transform_point(center);
    let world_point = view.transform_point(view_point);
    println!("Screen center on near plane → world: {:?}", world_point);
    // (变换后坐标,近似相机前方)
}
```

每行解释:
- `Mat4::translation` — 列主序存储,`m[3]` 是平移分量(列)。
- `perspective` — 透视投影矩阵,标准公式。
- `transform_point` — 矩阵乘齐次坐标,最后做透视除法。
