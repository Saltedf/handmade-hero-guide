# Day 481 · 编码立方体 UV

> 大纹理瓦片化做完了,接下来 Casey 要处理**立方体贴图(cube map)**的 UV 编码问题。立方体贴图用于天空盒、反射、点光源阴影,但它的 UV 编码方式和普通 2D 纹理完全不同——不是 (u, v) 二维,而是 (x, y, z) 三维方向向量。

## 0 · 为什么要有这一天

普通 2D 纹理用 (u, v) 在 [0, 1] 范围采样。立方体贴图(cube map)不一样——它由 6 张 2D 纹理组成,对应立方体的 6 个面(+X、-X、+Y、-Y、+Z、-Z)。Sample 时传一个**3D 方向向量** (x, y, z),GPU 用这个方向决定:

1. 方向射线击中立方体哪个面
2. 击中点在该面的 2D 坐标

这就是 cube map 的采样原理——**用方向采样,不用 (u, v)**。

为什么需要这种纹理?几个典型场景:

- **天空盒**(skybox):相机往任何方向看,都看到天空。Cube map 的 6 个面分别存天空的上、下、东、南、西、北。
- **环境反射**(environment reflection):水面上反射的景象,本质是"沿反射方向看环境"。Cube map 存环境。
- **点光源阴影**(omnidirectional shadow map):点光源往 360 度照,阴影信息存在 cube map 里,采样时按"从光源到点"的方向查。
- **IBL**(image-based lighting):PBR 渲染里,环境光照预计算成 cube map,运行时按法线/视线采样。

Casey 在 Day 481 处理的是 cube map 的 UV 编码问题。具体说:HH 用 texture array,但 cube map 需要 OpenGL 的 GL_TEXTURE_CUBE_MAP 类型。怎么把 cube map 和 texture array 统一?

答案:**在 vertex 端把 3D 方向向量编码进 UV 字段**。UV 是 vec2,方向是 vec3,需要"打包"。Day 481 实现这个打包。

完成这一天之后,你具备了:

- Cube map 的原理和采样方法
- 把 vec3 打包进 vec2 的编码技巧
- 理解天空盒、反射、IBL 的纹理基础

## 2 · 心智模型

### 类比:房间里的鱼眼相机

想象你在房间中央,有一台鱼眼相机往任何方向都能拍到一张图。把房间想象成立方体(6 个面),鱼眼相机拍 6 张图,每张是立方体一个面看到的景象。

如果你站在房间中央,朝东北上方看,你看到的图像是哪一张?是"+Z"(北)面的右上角(东上)部分。

Cube map 采样完全对应——给一个 3D 方向(东北上方),GPU 找出最大分量(Z),确定方向射到哪个面(+Z 面),然后用其他两个分量(X、Y)在该面内查找 UV。

### Cube map 采样的数学

给定方向向量 d = (x, y, z),采样算法:

1. 找出 |x|、|y|、|z| 中最大的,确定主轴
2. 主轴方向决定哪个面:
   - |x| 最大且 x > 0 → +X 面
   - |x| 最大且 x < 0 → -X 面
   - 同理 y、z
3. 其他两个分量在 [-|主轴|, +|主轴|] 范围,归一化到 [0, 1] 得到 UV

例如 d = (0.3, 0.5, 0.8):

- |z| 最大,z > 0,所以是 +Z 面
- 在 +Z 面上,U 方向是 X,V 方向是 Y
- u = (x / |z| + 1) / 2 = (0.375 + 1) / 2 = 0.6875
- v = (y / |z| + 1) / 2 = (0.625 + 1) / 2 = 0.8125

OpenGL 的 cube map 采样规则更复杂(每个面的 UV 方向不同,左手 vs 右手系),但核心思想一样——方向向量决定面 + UV。

### 把 vec3 编码进 vec2

Casey 的难点:vertex UV 字段是 vec2,方向需要 vec3。怎么打包?

方案 A:**用 3 个 vertex attribute**。把方向放进一个新 attribute vec3 direction。简单但增加顶点大小。

方案 B:**用 face index + UV**。在 push 时就计算出方向属于哪个面、UV 多少。vertex 只存 face_index(int)+ uv(vec2)。这和 texture array 的 layer + uv 一致。

Casey 选 B。具体做法:

```rust
fn encode_cube_direction(dir: Vec3) -> (i32 /* face */, Vec2 /* uv */) {
    let abs_x = dir.x.abs();
    let abs_y = dir.y.abs();
    let abs_z = dir.z.abs();
    
    // 找出主轴
    if abs_x >= abs_y && abs_x >= abs_z {
        if dir.x > 0.0 {
            // +X 面
            let u = (dir.z / abs_x + 1.0) / 2.0;
            let v = (dir.y / abs_x + 1.0) / 2.0;
            (0, Vec2::new(u, v))
        } else {
            // -X 面
            let u = (-dir.z / abs_x + 1.0) / 2.0;
            let v = (dir.y / abs_x + 1.0) / 2.0;
            (1, Vec2::new(u, v))
        }
    } else if abs_y >= abs_x && abs_y >= abs_z {
        // ... 类似处理 y 主轴
    } else {
        // ... z 主轴
    }
}
```

这个函数在 CPU 端 push 时调,把方向编码成 face + UV。Vertex 数据紧凑,shader 端直接用。

### Cube map 的 6 个面方向约定

OpenGL cube map 的 6 个面有固定约定(右手坐标系):

| Face index | 方向 | U 轴 | V 轴 |
|---|---|---|---|
| 0 | +X (right) | -Z | -Y |
| 1 | -X (left) | +Z | -Y |
| 2 | +Y (top) | +X | +Z |
| 3 | -Y (bottom) | +X | -Z |
| 4 | +Z (front) | +X | -Y |
| 5 | -Z (back) | -X | -Y |

每个面的 UV 方向不同,这是 OpenGL 规范规定的(为了 cube map seamless filter)。Casey 必须按这个约定编码,否则采样的图错位。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Cube map 在游戏里几乎必备:

- **天空盒**:每个游戏都有,玩家看到的天空
- **反射**:水面、车漆、金属的反射效果
- **Irradiance map**:PBR 渲染的 diffuse IBL
- **Prefilter map**:PBR 渲染的 specular IBL
- **环境探针**(env probe):静态环境的反射预计算

Unity 的 ReflectionProbe、Unreal 的 Reflection Capture、Godot 的 ReflectionProbe 都基于 cube map。

Casey 在 Day 481 做的是基础 cube map 支持,后面 HH 进入 PBR / 光照探针时大量用。

游戏开发里 cube map 有几个变种:

- **Static cube map**:静态环境,启动时计算一次
- **Dynamic cube map**:实时更新(反射玩家、动态物体)。每个动态反射对象需要 6 个 render pass,代价高
- **Planar reflection**:平面反射,不用 cube map,用普通 2D 纹理 + 镜像矩阵
- **Screen-space reflection (SSR)**:屏幕空间反射,延迟渲染里用 G-buffer 重算反射

Casey Day 481 做的是 static cube map 的基础。

### 3.2 · 🎨 图形学视角

图形学里 cube map 有几个微妙概念。

**Seamless filtering**:cube map 边缘采样的特殊处理。普通 cube map 在面与面之间有缝,OpenGL 的 `GL_TEXTURE_CUBE_MAP_SEAMLESS` 启用无缝过滤——采样时跨面 filter。

**Mipmap**:cube map 也有 mipmap,但每级 mipmap 的 6 个面要一起算(filter 时可能跨面)。Casey 简化,不用 mipmap。

**Equirectangular vs Cube map**:HDR 环境图通常存成 equirectangular(球面展开,2:1 比例的 2D 图),但 GPU 采样需要 cube map。转换公式:

```
给定 cube map 方向 (x, y, z):
theta = atan2(z, x)   # 经度 [-π, π]
phi = asin(y / length)  # 纬度 [-π/2, π/2]
u = (theta + π) / (2π)
v = (phi + π/2) / π
```

工业级 PBR 渲染管线在加载时把 equirectangular 转成 cube map,运行时 GPU 直接 cube 采样。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上 cube map 的 GPU 实现没什么特别——driver 把 6 个面打包成 array-like 结构,采样时硬件解码方向。Mesa 的实现可以看 `src/mesa/main/teximage.c` 的 cube map 部分。

Linux 上有个有趣的应用:**VR 立体渲染**。VR 头显左右眼各看一个 cube map 的部分(因为视野受限),需要 cube map 子采样。这就是 why VR 渲染比传统渲染贵——需要双 cube map 或者双相机。

## 5 · 对照与变奏

Casey 在 Day 481 的 cube map 思想在不同领域有不同对应:

**地理**:地球的球面投影。Mercator 投影(equirectangular)、立方体投影(cube map)、Robinson 投影(其他参数化)。地图学家和图形学家在解同一问题。

**摄影**:360 度全景相机。Insta360、Ricoh Theta 拍的照片本质是 cube map 或 equirectangular,后期拼接。

**音频**:Ambisonics(三维音频)。和 cube map 对应的是"麦克风录的 360 度音频",也用 4-8 通道(类似 cube map 的 6 个面)。

**天文学**:全天图(all-sky map)。Milky Way 的全天空图用 equirectangular 存,渲染时转 cube map。

理解"高维数据的低维参数化"是工程师的核心素养。每次你处理球面/3D 数据,问自己:**用哪种参数化最合适?**

另一个对照:**Cube map vs octahedral**。Octahedral 把球面映射到八面体然后展开成正方形,内存效率高(2D 纹理,不是 cube map)。但采样复杂度高。Cube map 是 GPU 原生支持,所以工业首选。这是"通用性 vs 效率"的经典 trade-off。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 cube map 用 6 个 2D 面,而不是 1 张球面展开(equirectangular)?

**参考解答**:三个理由:

第一,**GPU 硬件支持**。OpenGL/DirectX/Vulkan 都原生支持 cube map,采样指令单一(`texture(cube_sampler, dir3)`)。Equirectangular 不是原生类型,要自己实现采样 shader,慢且复杂。

第二,**均匀采样**。Cube map 6 个面分布均匀,每个方向采样密度相近。Equirectangular 在极点(南北极)采样密度极高(畸变),赤道处密度低。这导致 mipmap / filter 困难。

第三,**seamless filter**。Cube map 边缘的 filter 是 GPU 原生支持(跨面采样)。Equirectangular 的接缝(经度 ±π 处)filter 困难,容易出缝。

Equirectangular 的优点是**存储紧凑**(单张 2:1 图,内存少 30%),所以适合**存储/传输**,不适合**采样**。工业流程是:HDR 环境图存 equirectangular,加载时转 cube map 用于采样。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现完整的 cube map 方向编码。给定方向向量 (x, y, z),返回 (face_index, u, v),face_index 在 0-5。验证:8 个角方向(±1, ±1, ±1)各映射到对应面的角。

**参考解答**:

```rust
#[derive(Debug, Clone, Copy)]
enum CubeFace {
    PosX = 0, NegX = 1,
    PosY = 2, NegY = 3,
    PosZ = 4, NegZ = 5,
}

#[derive(Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }

impl Vec3 {
    const fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn abs(&self) -> Self {
        Self::new(self.x.abs(), self.y.abs(), self.z.abs())
    }
}

fn encode_cube_direction(d: Vec3) -> (CubeFace, f32, f32) {
    let abs = d.abs();
    let ax = abs.x;
    let ay = abs.y;
    let az = abs.z;
    
    // OpenGL cube map 约定:
    // 每个面的 UV 方向不同(为了维持右手系)
    if ax >= ay && ax >= az {
        // 主轴 X
        if d.x > 0.0 {
            // +X 面:U = -Z, V = -Y
            let u = (-d.z / ax + 1.0) / 2.0;
            let v = (-d.y / ax + 1.0) / 2.0;
            (CubeFace::PosX, u, v)
        } else {
            // -X 面:U = +Z, V = -Y
            let u = (d.z / ax + 1.0) / 2.0;
            let v = (-d.y / ax + 1.0) / 2.0;
            (CubeFace::NegX, u, v)
        }
    } else if ay >= ax && ay >= az {
        // 主轴 Y
        if d.y > 0.0 {
            // +Y 面:U = +X, V = +Z
            let u = (d.x / ay + 1.0) / 2.0;
            let v = (d.z / ay + 1.0) / 2.0;
            (CubeFace::PosY, u, v)
        } else {
            // -Y 面:U = +X, V = -Z
            let u = (d.x / ay + 1.0) / 2.0;
            let v = (-d.z / ay + 1.0) / 2.0;
            (CubeFace::NegY, u, v)
        }
    } else {
        // 主轴 Z
        if d.z > 0.0 {
            // +Z 面:U = +X, V = -Y
            let u = (d.x / az + 1.0) / 2.0;
            let v = (-d.y / az + 1.0) / 2.0;
            (CubeFace::PosZ, u, v)
        } else {
            // -Z 面:U = -X, V = -Y
            let u = (-d.x / az + 1.0) / 2.0;
            let v = (-d.y / az + 1.0) / 2.0;
            (CubeFace::NegZ, u, v)
        }
    }
}

fn main() {
    let test_dirs = [
        (Vec3::new(1.0, 0.0, 0.0),  "+X 方向"),
        (Vec3::new(-1.0, 0.0, 0.0), "-X 方向"),
        (Vec3::new(0.0, 1.0, 0.0),  "+Y 方向"),
        (Vec3::new(0.0, -1.0, 0.0), "-Y 方向"),
        (Vec3::new(0.0, 0.0, 1.0),  "+Z 方向"),
        (Vec3::new(0.0, 0.0, -1.0), "-Z 方向"),
        (Vec3::new(1.0, 1.0, 1.0),  "等比斜方向"),
        (Vec3::new(0.577, 0.577, 0.577), "归一化斜方向"),
    ];
    
    for (dir, desc) in test_dirs {
        let (face, u, v) = encode_cube_direction(dir);
        println!("方向 {:?} ({}): face={:?}, uv=({:.3}, {:.3})",
                 (dir.x, dir.y, dir.z), desc, face, u, v);
    }
}
```

为什么这么写:`encode_cube_direction` 严格按 OpenGL cube map 规范实现。注意每个面的 UV 方向不同——这是为了维持右手坐标系在 cube map 内的一致性。如果你的 UV 方向算错,天空盒会上下颠倒、左右翻转。

## 8 · Rust / Arch 落地代码

下面是 Day 481 完整的 cube map UV 编码 + 集成进渲染管线。

```rust
// ========================================
// Cube map face 枚举
// ========================================

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[repr(u32)]
enum CubeFace {
    PosX = 0,
    NegX = 1,
    PosY = 2,
    NegY = 3,
    PosZ = 4,
    NegZ = 5,
}

impl CubeFace {
    fn to_layer(self, cube_first_layer: u32) -> u32 {
        cube_first_layer + (self as u32)
    }
}

// ========================================
// 方向 → (face, uv) 编码
// ========================================

#[derive(Debug, Clone, Copy)]
struct Vec3 { x: f32, y: f32, z: f32 }

impl Vec3 {
    const fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn abs(&self) -> Self {
        Self::new(self.x.abs(), self.y.abs(), self.z.abs())
    }
    fn length(&self) -> f32 {
        (self.x*self.x + self.y*self.y + self.z*self.z).sqrt()
    }
    fn normalize(self) -> Self {
        let l = self.length();
        if l > 1e-6 {
            Self::new(self.x/l, self.y/l, self.z/l)
        } else {
            Self::new(0.0, 0.0, 1.0)  // 默认 +Z
        }
    }
}

fn encode_cube(d: Vec3) -> (CubeFace, f32, f32) {
    let d = d.normalize();
    let abs = d.abs();
    let ax = abs.x;
    let ay = abs.y;
    let az = abs.z;
    
    if ax >= ay && ax >= az {
        if d.x > 0.0 {
            (CubeFace::PosX, (-d.z/ax + 1.0)*0.5, (-d.y/ax + 1.0)*0.5)
        } else {
            (CubeFace::NegX, (d.z/ax + 1.0)*0.5, (-d.y/ax + 1.0)*0.5)
        }
    } else if ay >= ax && ay >= az {
        if d.y > 0.0 {
            (CubeFace::PosY, (d.x/ay + 1.0)*0.5, (d.z/ay + 1.0)*0.5)
        } else {
            (CubeFace::NegY, (d.x/ay + 1.0)*0.5, (-d.z/ay + 1.0)*0.5)
        }
    } else {
        if d.z > 0.0 {
            (CubeFace::PosZ, (d.x/az + 1.0)*0.5, (-d.y/az + 1.0)*0.5)
        } else {
            (CubeFace::NegZ, (-d.x/az + 1.0)*0.5, (-d.y/az + 1.0)*0.5)
        }
    }
}

// ========================================
// Vertex layout(集成 cube map 支持)
// ========================================

#[repr(C)]
#[derive(Copy, Clone, Debug, bytemuck::Pod, bytemuck::Zeroable)]
struct CubeMapVertex {
    pos: [f32; 3],
    direction: [f32; 3],       // 采样方向
    face_layer: i32,           // = cube_first_layer + face_index
    _padding: [u32; 2],
}

// ========================================
// 演示:天空盒
// ========================================

fn make_skybox_vertices(cube_first_layer: u32) -> Vec<CubeMapVertex> {
    // 天空盒是一个大立方体,从内部看
    // 6 个面,每面 4 个顶点(用 indexed drawing)
    // 这里简化:每面只生成 1 个代表顶点
    
    let s = 100.0;   // 天空盒大小
    let mut verts = Vec::new();
    
    let faces = [
        // (face, 4 个角的 pos, 对应的 direction)
        (CubeFace::PosX, [[s,-s,-s], [s,s,-s], [s,s,s], [s,-s,s]],
         Vec3::new(1.0, 0.0, 0.0)),
        (CubeFace::NegX, [[-s,-s,s], [-s,s,s], [-s,s,-s], [-s,-s,-s]],
         Vec3::new(-1.0, 0.0, 0.0)),
        (CubeFace::PosY, [[-s,s,-s], [-s,s,s], [s,s,s], [s,s,-s]],
         Vec3::new(0.0, 1.0, 0.0)),
        (CubeFace::NegY, [[-s,-s,s], [-s,-s,-s], [s,-s,-s], [s,-s,s]],
         Vec3::new(0.0, -1.0, 0.0)),
        (CubeFace::PosZ, [[-s,-s,s], [-s,s,s], [s,s,s], [s,-s,s]],
         Vec3::new(0.0, 0.0, 1.0)),
        (CubeFace::NegZ, [[s,-s,-s], [s,s,-s], [-s,s,-s], [-s,-s,-s]],
         Vec3::new(0.0, 0.0, -1.0)),
    ];
    
    for (face, corners, dir) in faces.iter() {
        let layer = face.to_layer(cube_first_layer);
        for c in corners.iter() {
            verts.push(CubeMapVertex {
                pos: [c[0], c[1], c[2]],
                direction: [dir.x, dir.y, dir.z],
                face_layer: layer as i32,
                _padding: [0; 2],
            });
        }
    }
    
    verts
}
```

出错怎么办:

- **天空盒上下颠倒** —— V 坐标方向反了。OpenGL cube map 的 V 是从下到上(+V up),如果你 texture 数据是从上到下存的,要 flip。
- **天空盒左右镜像** —— U 方向反了。同上,检查每个面的 U 方向约定。
- **face 接缝可见** —— 没启用 `GL_TEXTURE_CUBE_MAP_SEAMLESS`。`glEnable(GL_TEXTURE_CUBE_MAP_SEAMLESS)`。
- **方向归一化** —— cube map 采样要 normalize 方向,否则主轴判断错。

## 10 · 复习要点

读完这一天你应该能用 30 秒回答以下问题:

**Q1**:Cube map 用什么采样?
> 3D 方向向量 (x, y, z)。GPU 用方向决定击中立方体哪个面 + 在该面的 UV。

**Q2**:Cube map 的 6 个面对应什么方向?
> +X、-X、+Y、-Y、+Z、-Z。OpenGL 规定了每个面的 UV 方向(为了维持右手系)。

**Q3**:为什么 cube map 比 equirectangular 适合采样?
> GPU 原生支持(单条 sample 指令)、均匀采样(无极点畸变)、seamless filter(跨面边缘)。

**Q4**:Casey 怎么把 cube map 集成到 texture array?
> 6 个连续 layer 充当 cube 的 6 个面。Vertex 数据带 face_index + uv,shader 用 layer = base + face_index 采样。

**Q5**:cube map 的典型应用?
> 天空盒(任何方向看天空)、环境反射(水面、金属)、点光源阴影(360 度阴影)、IBL(PBR 环境光照)。
