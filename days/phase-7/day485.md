# Day 485 · 世界生成器加实体放置

> HH 的世界是程序化生成的——Day 55 之后用 hash-based 存储,每个 tile 知道自己是什么地形。Day 485 在生成地形的同时**放置实体**(怪物、宝箱、装饰物),让世界从"光秃秃的地板墙"变成"有内容的关卡"。

## 0 · 为什么要有这一天

你之前的世界生成器是这样的:

```rust
fn generate_chunk(chunk_x, chunk_y) -> Chunk {
    let tiles = [[Terrain::Floor; 16]; 16];
    // 简单噪声决定 floor/wall
    for y in 0..16 {
        for x in 0..16 {
            let h = noise(x, y);
            tiles[y][x] = if h > 0.7 { Terrain::Wall } else { Terrain::Floor };
        }
    }
    Chunk { tiles }
}
```

生成的世界只有墙和地板,空荡荡。Day 485 加 entity placement:

- 在 floor tile 上随机放怪物(按 tag "goblin" 查 asset)
- 在角落放宝箱(按 tag "chest" 查 asset)
- 在 wall 边放火把(按 tag "torch" 查 asset)

为什么这件事重要?因为玩家看到的世界如果没内容,就只是"一个地图生成器"——好玩度低。游戏需要**实体分布**(entity distribution)让世界有玩头。

实体放置涉及几个设计决策:

第一,**确定性 vs 随机性**。同一个 seed 应该生成同一个世界(玩家可以分享 seed)。Casey 用 hash(world_x, world_y, seed) 决定放置,不是 rand()。

第二,**密度控制**。每个房间怪物太多/太少都不好。需要"目标密度"参数。

第三,**避免重叠**。两个怪物不能在同一位置。需要 collision check 或 spatial hash。

第四,**关联资产**。放什么怪物?用 Day 482 的 tag 系统查 asset。

完成这一天之后,你具备了:

- 程序化内容生成(PCG)的基础
- 实体放置算法(网格 + 密度)
- 把地形生成 + 实体放置组合的能力

## 2 · 心智模型

### 类比:城市规划

想象你规划一座新城。你要决定:

- 道路在哪(对应 floor tile)
- 建筑在哪(对应 entity)
- 不同区域的建筑密度(住宅区高密度、工业区低密度)

城市规划有原则——不能把工厂放住宅区,不能把医院放高速公路中间,密度要平衡。

游戏世界生成完全一样——按 tile 类型决定能放什么 entity,按区域决定密度,避免冲突。

### 确定性生成的关键:Hash 函数

Casey 用 hash 函数而不是 rand(),因为 rand() 是状态依赖的(每次调不一样,顺序敏感)。Hash 是无状态的(同样输入永远同样输出),适合程序化生成。

```rust
fn placement_hash(x: i32, y: i32, seed: u32) -> u32 {
    // 简单 hash:多个素数混合
    let mut h = seed;
    h = h.wrapping_mul(31).wrapping_add(x as u32);
    h = h.wrapping_mul(31).wrapping_add(y as u32);
    h = h.wrapping_mul(2654435761);   // Knuth's multiplicative hash
    h
}
```

给定 `(x, y, seed)`,返回一个 `u32`。同样输入永远同样输出。

把 hash 当 PRNG:

```rust
let h = placement_hash(tile_x, tile_y, seed);
if h % 100 < 5 {
    // 5% 概率放 entity
    place_entity(tile_x, tile_y);
}
```

Casey 在 Day 55 (hash-based world storage) 已经用了类似 hash,Day 485 复用。

### 多种 entity 的概率分配

如果 5% 放 goblin、3% 放 bat、2% 放 chest,怎么算?

方案 A:多次 hash(慢):

```rust
if hash(x, y, seed, "goblin") % 100 < 5 { place_goblin(); }
if hash(x, y, seed, "bat") % 100 < 3 { place_bat(); }
```

方案 B:一次 hash,按区间分配(快):

```rust
let h = hash(x, y, seed) % 100;
if h < 5 { place_goblin(); }
else if h < 8 { place_bat(); }   // 5..8 = 3%
else if h < 10 { place_chest(); }  // 8..10 = 2%
// else: 不放
```

Casey 用方案 B——单次 hash,区间分配。性能好且语义清晰。

### Spatial Hash 避免重叠

如果两个 tile 都决定放 entity,它们的位置不会重叠(tile 是离散的)。但**避免放在 wall 上**或**避免放在已占用 tile 上**需要检查。

简单做法:每 tile 只放最多一个 entity,所以 hash 决定就好。复杂做法(放多个 entity):spatial hash。

Spatial hash 思想:把空间分成 grid,每 cell 存一个 entity list。检查重叠时只看相邻 cell,不全遍历。

Casey 用简单做法——每 tile 最多一个 entity,所以不需要 spatial hash。后面 Day 487 (3D hit-testing) 才用 spatial hash。

### 关联资产:tag 查询

放在 `(x, y)` 的 goblin 用哪张 sprite?用 Day 482 的 tag 系统:

```rust
let goblin_assets = library.find_by_tag("goblin");
let goblin_sprite = goblin_assets[0];   // 取第一个匹配的
```

这是 tag 系统的典型用法——按语义查 asset,不按文件名。

如果 goblin 有多个动画状态(idle、walk、attack),tag 系统也支持:

```rust
let goblin_idle = library.find_by_all_tags(&["goblin", "idle"]);
let goblin_walk = library.find_by_all_tags(&["goblin", "walk"]);
```

游戏运行时按 entity 当前状态选 sprite。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

程序化内容生成(PCG)是游戏开发的子领域,有自己的会议和教科书。

经典 PCG 算法:

- **Cellular automata**:洞穴生成(Day 55 之前 Casey 用过)
- **Wave function collapse**:基于约束的生成(类似数独)
- **L-systems**:植物、河流分形
- **Perlin/Simplex noise**:连续噪声,适合地形
- **Dungeon generation**:房间 + 走廊(roguelike 经典)
- **Voronoi diagram**:生物群系划分

Casey 用最简单的 hash-based 决定 placement,这是 PCG 的入门级。工业级游戏(No Man's Sky、Minecraft)用复杂得多的算法,但核心思想一致——**确定性 hash + 区间分配**。

游戏开发里 entity placement 有几个高级模式:

- **Zone-based placement**:不同区域放不同 entity(森林放狼,沙漠放蛇)
- **Difficulty scaling**:玩家等级高 → 怪物多/强
- **Narrative placement**:任务相关的特殊 entity(NPC、关键道具)
- **Player-driven**:玩家行为影响放置(杀光一个区域 → 新怪物迁入)

Casey 的简单 hash-based 放置够 HH 用,后面 Day 488 编辑器允许手动放置覆盖程序化结果。

### 3.2 · 🎨 图形学视角

从图形学角度,entity placement 影响渲染负载。如果一帧有 1000 个 entity,每个独立 draw call,性能差。Day 477 的 batching 把所有 entity 的 vertex 收集到一起,一次画完。

Casey 在 Day 485 放置 entity 时,数据结构是 Vec<Entity>。Day 477 的 batching 端遍历 Vec 生成 vertex。这两个系统天然配合——放置决定"画什么",batching 决定"怎么画"。

图形学还有个相关概念:**LOD(level of detail)**。远处的 entity 用低多边形模型、低分辨率纹理,近处用高清。Casey 在 HH 里没用(场景小),工业大世界游戏必备。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上的"程序化生成"对应是 **udev 设备命名**。系统启动时 udev 根据设备属性(PCI slot、MAC address)生成稳定 ID。这是 hash-based 程序化生成在系统编程的应用。

```bash
# 看网卡的稳定命名
ip link show
# enp0s3 ← en(ethernet) + p0(bus 0) + s3(slot 3)
# 这是 udev 根据 PCI slot hash 出来的名字

# udev rules
cat /etc/udev/rules.d/*.rules
# ATTR{address}=="aa:bb:cc:dd:ee:ff", NAME="eth0"
# 类似 entity placement:满足条件 → 命名
```

Linux 内核的 memory layout 也是程序化生成的——根据物理内存分布、CPU 拓扑、NUMA 决定。和 Casey 的世界生成同构——都是**根据输入数据生成结构**。

### 3.4 · 🦀 Rust 生态视角

Rust 写 PCG 有几个 crate:

- `noise`:Perlin/Simplex noise 库
- `rand`:PRNG(伪随机数)
- `pcg`:PCG 算法集合
- `vek`:向量数学(便于 spatial 处理)

Casey 自己手写 hash,因为简单。工业 Rust 项目用 `noise` 或 `rand` 加自定义 hash。

Rust 写 entity placement 的 idiomatic 模式:

```rust
struct WorldGenerator {
    seed: u32,
    entity_density: u32,   // 每 100 tile 多少 entity
}

impl WorldGenerator {
    fn generate_chunk(&self, cx: i32, cy: i32) -> Chunk {
        let mut chunk = Chunk::new();
        for ly in 0..16 {
            for lx in 0..16 {
                let tx = cx * 16 + lx as i32;
                let ty = cy * 16 + ly as i32;
                
                let terrain = self.generate_terrain(tx, ty);
                chunk.set_terrain(lx, ly, terrain);
                
                if terrain == Terrain::Floor {
                    if let Some(entity) = self.try_place_entity(tx, ty) {
                        chunk.add_entity(entity);
                    }
                }
            }
        }
        chunk
    }
    
    fn try_place_entity(&self, x: i32, y: i32) -> Option<Entity> {
        let h = self.placement_hash(x, y);
        let roll = h % 100;
        
        if roll < 5 {
            Some(Entity::new("goblin", x, y))
        } else if roll < 8 {
            Some(Entity::new("bat", x, y))
        } else if roll < 10 {
            Some(Entity::new("chest", x, y))
        } else {
            None
        }
    }
    
    fn placement_hash(&self, x: i32, y: i32) -> u32 {
        let mut h = self.seed;
        h = h.wrapping_mul(31).wrapping_add(x as u32);
        h = h.wrapping_mul(31).wrapping_add(y as u32);
        h ^= h >> 16;
        h.wrapping_mul(0x85ebca6b)
    }
}
```

注意 `wrapping_mul` —— Rust 默认 debug build 检查溢出 panic,hash 函数故意要溢出(wrap),所以用 wrapping。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 Casey 用 hash 函数决定 entity placement,而不是用 rand()?

**参考解答**:三个理由:

第一,**确定性**。同样的 seed 生成同样的世界。玩家可以分享 seed,看别人的世界。多人游戏里所有玩家看到同一个世界(seed 同步)。

第二,**无状态**。Hash 函数不需要顺序调用,任意顺序调用结果一样。rand() 必须按顺序调(否则结果变)。这意味着 hash 可以并行生成 chunk(多线程),rand() 不行(线程间状态同步复杂)。

第三,**可重现性**。Bug 出现在 (100, 50) tile 时,你能直接 hash(100, 50, seed) 调试,不需要从头跑游戏到那个位置。

代价:hash 函数的"随机性"通常比专用 PRNG 差(分布不均)。但游戏生成的需求是"看起来随机",不是密码学强度,所以够用。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现一个简单的 entity placement。给定 16×16 chunk,每个 floor tile 有 10% 概率放 goblin、5% 概率放 bat、2% 概率放 chest。用 hash 决定放置。生成 chunk (0, 0) 和 chunk (1, 0),验证两个 chunk 不同。

完成标准:`cargo run` 输出两个 chunk 的 entity 数量,goblin 总数 > bat 总数 > chest 总数(因为概率不同)。

**参考解答**:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
enum Terrain {
    Floor,
    Wall,
}

#[derive(Debug, Clone, PartialEq)]
struct Entity {
    kind: String,
    x: i32,
    y: i32,
}

struct Chunk {
    cx: i32,
    cy: i32,
    tiles: [[Terrain; 16]; 16],
    entities: Vec<Entity>,
}

impl Chunk {
    fn new(cx: i32, cy: i32) -> Self {
        Self {
            cx,
            cy,
            tiles: [[Terrain::Floor; 16]; 16],
            entities: Vec::new(),
        }
    }
}

struct WorldGenerator {
    seed: u32,
}

impl WorldGenerator {
    fn new(seed: u32) -> Self {
        Self { seed }
    }
    
    fn placement_hash(&self, x: i32, y: i32) -> u32 {
        let mut h = self.seed;
        h = h.wrapping_mul(31).wrapping_add(x as u32);
        h = h.wrapping_mul(31).wrapping_add(y as u32);
        h ^= h >> 16;
        h.wrapping_mul(0x85ebca6b)
    }
    
    fn generate_terrain(&self, x: i32, y: i32) -> Terrain {
        // 简单规则:边缘 wall,内部 floor
        let local_x = ((x % 16) + 16) % 16;
        let local_y = ((y % 16) + 16) % 16;
        if local_x == 0 || local_x == 15 || local_y == 0 || local_y == 15 {
            Terrain::Wall
        } else {
            Terrain::Floor
        }
    }
    
    fn try_place_entity(&self, x: i32, y: i32) -> Option<Entity> {
        let h = self.placement_hash(x, y) % 100;
        if h < 10 {
            Some(Entity { kind: "goblin".into(), x, y })
        } else if h < 15 {
            Some(Entity { kind: "bat".into(), x, y })
        } else if h < 17 {
            Some(Entity { kind: "chest".into(), x, y })
        } else {
            None
        }
    }
    
    fn generate_chunk(&self, cx: i32, cy: i32) -> Chunk {
        let mut chunk = Chunk::new(cx, cy);
        
        for ly in 0..16 {
            for lx in 0..16 {
                let tx = cx * 16 + lx as i32;
                let ty = cy * 16 + ly as i32;
                
                let terrain = self.generate_terrain(tx, ty);
                chunk.tiles[ly][lx] = terrain;
                
                if terrain == Terrain::Floor {
                    if let Some(entity) = self.try_place_entity(tx, ty) {
                        chunk.entities.push(entity);
                    }
                }
            }
        }
        
        chunk
    }
}

fn main() {
    let gen = WorldGenerator::new(42);
    
    for (cx, cy) in [(0, 0), (1, 0), (0, 1), (1, 1)] {
        let chunk = gen.generate_chunk(cx, cy);
        
        // 统计 entity 类型
        let mut counts = std::collections::HashMap::new();
        for e in &chunk.entities {
            *counts.entry(&e.kind).or_insert(0) += 1;
        }
        
        println!("Chunk ({}, {}): {} entities", cx, cy, chunk.entities.len());
        for (kind, count) in &counts {
            println!("  {}: {}", kind, count);
        }
    }
    
    // 验证确定性:同样 seed 同样输出
    let gen2 = WorldGenerator::new(42);
    let chunk_a = gen.generate_chunk(0, 0);
    let chunk_b = gen2.generate_chunk(0, 0);
    assert_eq!(chunk_a.entities.len(), chunk_b.entities.len());
    println!("\n确定性验证通过:同 seed 同输出");
    
    // 验证不同 seed 不同输出
    let gen3 = WorldGenerator::new(99);
    let chunk_c = gen3.generate_chunk(0, 0);
    println!("\nSeed 99 的 chunk (0,0) entity 数: {}", chunk_c.entities.len());
}
```

为什么这么写:`wrapping_mul` 和 `wrapping_add` 是 Rust 表达"故意溢出"的方式——hash 函数依赖溢出混合,这是预期行为。如果用普通 `*`,debug build 会 panic。

## 8 · Rust / Arch 落地代码

下面是 Day 485 完整的 entity placement 系统。

```rust
use std::collections::HashMap;

// ========================================
// Asset Library(复用 Day 482)
// ========================================

struct AssetLibrary {
    /// tag → 哪些 asset
    tag_to_assets: HashMap<String, Vec<usize>>,
    assets: Vec<AssetInfo>,
}

#[derive(Debug, Clone)]
struct AssetInfo {
    name: String,
    bitmap_id: u32,
}

impl AssetLibrary {
    fn new() -> Self {
        Self {
            tag_to_assets: HashMap::new(),
            assets: Vec::new(),
        }
    }
    
    fn add(&mut self, name: &str, tags: &[&str]) -> usize {
        let idx = self.assets.len();
        self.assets.push(AssetInfo {
            name: name.to_string(),
            bitmap_id: idx as u32,
        });
        for tag in tags {
            self.tag_to_assets.entry(tag.to_string())
                .or_default()
                .push(idx);
        }
        idx
    }
    
    fn find_by_tag(&self, tag: &str) -> Vec<&AssetInfo> {
        self.tag_to_assets.get(tag)
            .map(|indices| indices.iter().map(|&i| &self.assets[i]).collect())
            .unwrap_or_default()
    }
}

// ========================================
// World + Entity
// ========================================

#[derive(Debug, Clone, Copy, PartialEq)]
enum Terrain {
    Floor,
    Wall,
    Water,
}

#[derive(Debug, Clone)]
struct Entity {
    asset_idx: usize,
    x: i32,
    y: i32,
    z: i32,
    state: EntityState,
}

#[derive(Debug, Clone, Copy)]
enum EntityState {
    Idle,
    Walking,
    Attacking,
}

struct Chunk {
    cx: i32,
    cy: i32,
    tiles: Vec<Terrain>,        // 16x16 = 256 tiles
    entities: Vec<Entity>,
}

impl Chunk {
    const SIZE: usize = 16;
    
    fn new(cx: i32, cy: i32) -> Self {
        Self {
            cx,
            cy,
            tiles: vec![Terrain::Floor; Self::SIZE * Self::SIZE],
            entities: Vec::new(),
        }
    }
    
    fn tile_index(lx: usize, ly: usize) -> usize {
        ly * Self::SIZE + lx
    }
    
    fn get_terrain(&self, lx: usize, ly: usize) -> Terrain {
        self.tiles[Self::tile_index(lx, ly)]
    }
    
    fn set_terrain(&mut self, lx: usize, ly: usize, t: Terrain) {
        self.tiles[Self::tile_index(lx, ly)] = t;
    }
}

// ========================================
// World Generator
// ========================================

struct WorldGenerator {
    seed: u32,
    library: AssetLibrary,
    
    // Entity placement config
    goblin_density: u32,    // 0..100,百分比
    bat_density: u32,
    chest_density: u32,
}

impl WorldGenerator {
    fn new(seed: u32, library: AssetLibrary) -> Self {
        Self {
            seed,
            library,
            goblin_density: 10,
            bat_density: 5,
            chest_density: 2,
        }
    }
    
    fn placement_hash(&self, x: i32, y: i32) -> u32 {
        let mut h = self.seed;
        h = h.wrapping_mul(31).wrapping_add(x as u32);
        h = h.wrapping_mul(31).wrapping_add(y as u32);
        h ^= h >> 16;
        h.wrapping_mul(0x85ebca6b)
    }
    
    fn generate_terrain(&self, x: i32, y: i32) -> Terrain {
        let h = self.placement_hash(x, y) ^ self.seed.wrapping_mul(0x9e3779b9);
        let r = h % 100;
        
        if r < 70 {
            Terrain::Floor
        } else if r < 95 {
            Terrain::Wall
        } else {
            Terrain::Water
        }
    }
    
    fn try_place_entity(&self, x: i32, y: i32) -> Option<Entity> {
        let h = self.placement_hash(x, y) % 100;
        
        let asset_idx = if h < self.goblin_density {
            // 查 goblin asset
            let candidates = self.library.find_by_tag("goblin");
            candidates.first().map(|a| a.bitmap_id as usize)?
        } else if h < self.goblin_density + self.bat_density {
            let candidates = self.library.find_by_tag("bat");
            candidates.first().map(|a| a.bitmap_id as usize)?
        } else if h < self.goblin_density + self.bat_density + self.chest_density {
            let candidates = self.library.find_by_tag("chest");
            candidates.first().map(|a| a.bitmap_id as usize)?
        } else {
            return None;
        };
        
        Some(Entity {
            asset_idx,
            x,
            y,
            z: 0,
            state: EntityState::Idle,
        })
    }
    
    fn generate_chunk(&self, cx: i32, cy: i32) -> Chunk {
        let mut chunk = Chunk::new(cx, cy);
        
        for ly in 0..Chunk::SIZE {
            for lx in 0..Chunk::SIZE {
                let tx = cx * Chunk::SIZE as i32 + lx as i32;
                let ty = cy * Chunk::SIZE as i32 + ly as i32;
                
                let terrain = self.generate_terrain(tx, ty);
                chunk.set_terrain(lx, ly, terrain);
                
                // 只在 floor 上放 entity
                if terrain == Terrain::Floor {
                    if let Some(entity) = self.try_place_entity(tx, ty) {
                        chunk.entities.push(entity);
                    }
                }
            }
        }
        
        chunk
    }
}

// ========================================
// 演示
// ========================================

fn setup_library() -> AssetLibrary {
    let mut lib = AssetLibrary::new();
    lib.add("goblin_idle", &["goblin", "idle", "enemy"]);
    lib.add("goblin_walk", &["goblin", "walk", "enemy"]);
    lib.add("bat_fly", &["bat", "fly", "enemy"]);
    lib.add("chest_closed", &["chest", "closed", "item"]);
    lib.add("chest_open", &["chest", "open", "item"]);
    lib.add("torch", &["torch", "decoration"]);
    lib
}

fn main() {
    let library = setup_library();
    let gen = WorldGenerator::new(42, library);
    
    println!("=== 生成多个 chunk ===");
    
    for (cx, cy) in [(0, 0), (1, 0), (0, 1), (-1, -1)] {
        let chunk = gen.generate_chunk(cx, cy);
        
        // 统计
        let floor_count = chunk.tiles.iter()
            .filter(|&&t| t == Terrain::Floor).count();
        let wall_count = chunk.tiles.iter()
            .filter(|&&t| t == Terrain::Wall).count();
        let water_count = chunk.tiles.iter()
            .filter(|&&t| t == Terrain::Water).count();
        
        // entity 按 asset_idx 分组
        let mut entity_groups: HashMap<u32, usize> = HashMap::new();
        for e in &chunk.entities {
            *entity_groups.entry(e.asset_idx as u32).or_insert(0) += 1;
        }
        
        println!();
        println!("Chunk ({}, {}):", cx, cy);
        println!("  Terrain: {} floor, {} wall, {} water",
                 floor_count, wall_count, water_count);
        println!("  Entities: {} total", chunk.entities.len());
        for (asset_idx, count) in &entity_groups {
            // 查 asset 名字
            // 简化:asset_idx 就是 bitmap_id,通过索引推断
            let kind = match *asset_idx {
                0 => "goblin (idle)",
                1 => "goblin (walk)",  // 不太可能,我们只放 idle
                2 => "bat",
                3 => "chest (closed)",
                4 => "chest (open)",
                _ => "unknown",
            };
            println!("    {} (asset {}): {}", kind, asset_idx, count);
        }
    }
    
    println!();
    println!("=== 确定性验证 ===");
    let library2 = setup_library();
    let gen2 = WorldGenerator::new(42, library2);
    
    let chunk1 = gen.generate_chunk(0, 0);
    let chunk2 = gen2.generate_chunk(0, 0);
    
    assert_eq!(chunk1.entities.len(), chunk2.entities.len());
    for (e1, e2) in chunk1.entities.iter().zip(chunk2.entities.iter()) {
        assert_eq!(e1.x, e2.x);
        assert_eq!(e1.y, e2.y);
        assert_eq!(e1.asset_idx, e2.asset_idx);
    }
    println!("✓ 同 seed 同 chunk,完全一致");
    
    println!();
    println!("=== 不同 seed ===");
    let library3 = setup_library();
    let gen3 = WorldGenerator::new(999, library3);
    let chunk3 = gen3.generate_chunk(0, 0);
    println!("Seed 42 chunk (0,0): {} entities", chunk1.entities.len());
    println!("Seed 999 chunk (0,0): {} entities", chunk3.entities.len());
    if chunk1.entities.len() != chunk3.entities.len() {
        println!("✓ 不同 seed 不同输出");
    }
    
    // Density 统计:在大范围上,goblin:bat:chest 应该接近 10:5:2
    println!();
    println!("=== 密度统计(100 个 chunk)===");
    let mut total_goblin = 0;
    let mut total_bat = 0;
    let mut total_chest = 0;
    let mut total_floor = 0;
    
    for cy in -5..5 {
        for cx in -5..5 {
            let chunk = gen.generate_chunk(cx, cy);
            total_floor += chunk.tiles.iter()
                .filter(|&&t| t == Terrain::Floor).count();
            for e in &chunk.entities {
                match e.asset_idx {
                    0 => total_goblin += 1,   // goblin_idle
                    2 => total_bat += 1,
                    3 => total_chest += 1,
                    _ => {}
                }
            }
        }
    }
    
    println!("Total floor tiles: {}", total_floor);
    println!("Goblins: {} ({:.1}%)", total_goblin, total_goblin as f64 * 100.0 / total_floor as f64);
    println!("Bats: {} ({:.1}%)", total_bat, total_bat as f64 * 100.0 / total_floor as f64);
    println!("Chests: {} ({:.1}%)", total_chest, total_chest as f64 * 100.0 / total_floor as f64);
    println!("(目标:goblin 10%, bat 5%, chest 2%)");
}
```
