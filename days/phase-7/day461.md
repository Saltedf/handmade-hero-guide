让我把"热重载架构"完整讲清楚,这是 Day 461 的核心。

**资产管线的数据流**。一个资产(贴图)从文件到 GPU 的路径:

```
1. AssetManager 检测 asset.png 的 mtime 变化
       ↓
2. 调用 png::decode() 重新解码 → Vec<u8> 像素数据
       ↓
3. 把像素数据上传到 GPU → 新的 GPU texture handle
       ↓
4. 替换 AssetTable 里的旧 handle(老 handle 被 free)
       ↓
5. 下一帧渲染时,渲染器查到新 handle,绘制新纹理
```

每一步都可能失败:

- 解码失败:新 PNG 损坏(美术保存到一半)
- 上传失败:GPU 内存不足
- 替换时序:某帧渲染器正在用旧 handle,如果立刻 free 会崩

**关键架构选择:不可变句柄**。工业 AssetManager 通常返回**不可变句柄(Handle)**而不是直接数据:

```rust
pub struct TextureHandle(u32);  // 内部 ID

pub struct AssetManager {
    textures: HashMap<PathBuf, TextureEntry>,
}

struct TextureEntry {
    gpu_handle: GpuTexture,
    mtime: SystemTime,
    // ...
}

impl AssetManager {
    pub fn load(&mut self, path: &Path) -> TextureHandle {
        let mtime = fs::metadata(path).unwrap().modified().unwrap();
        let pixels = png::decode(fs::read(path).unwrap().as_slice());
        let gpu_handle = self.gpu.upload_texture(&pixels);
        let entry = TextureEntry { gpu_handle, mtime };
        let id = self.next_id();
        self.textures.insert(path.to_path_buf(), entry);
        TextureHandle(id)
    }
    
    pub fn update(&mut self) {
        for (path, entry) in &mut self.textures {
            let mtime = match fs::metadata(path).and_then(|m| m.modified()) {
                Ok(t) => t,
                Err(_) => continue,  // 文件被删,跳过
            };
            if mtime != entry.mtime {
                // 文件变了,重新加载
                if let Ok(data) = fs::read(path) {
                    if let Ok(pixels) = png::decode(&data) {
                        entry.gpu_handle = self.gpu.upload_texture(&pixels);
                        entry.mtime = mtime;
                    }
                    // 解码失败:保留旧纹理
                }
            }
        }
    }
}
```

**关键设计**:`update` 失败时**保留旧纹理**——游戏继续跑,美术看到的是上次成功的版本。这种"容错"是工业级 asset pipeline 的标志。

**句柄 vs 引用**。为什么用 `TextureHandle(u32)` 而不是 `&Texture`?

1. **生命周期**:`&Texture` 绑定 AssetManager 借用,渲染时可能撞 borrow checker。Handle 是 Copy 的 u32,随便传。
2. **间接性**:AssetManager 可以**替换** entry 内部的 gpu_handle,持有 Handle 的代码下次查询时自动看到新版本。
3. **跨线程**:Handle 是 Send + Sync,可以传到渲染线程。

**双缓冲(double buffering)策略**。如果上传纹理到 GPU 慢(大纹理几 MB),要避免阻塞游戏帧。工业方案:**双缓冲**——后台线程解码新纹理,GPU 上传到 secondary handle,完成后 swap。游戏帧不卡顿。

**Editor vs Runtime 模式**。Casey HH 在 cfg 里区分:

```rust
fn update_assets(am: &mut AssetManager) {
    #[cfg(feature = "hot_reload")]
    am.update();  // 检查 mtime,触发重载
    
    #[cfg(not(feature = "hot_reload"))]
    {}  // 发行版不查
}
```

发行版省掉每帧的 `stat` syscall——零开销。

**热重载的实战扩展**:

- **多文件监听**:不只监听 PNG,还有 shader(`.glsl`)、配置(`.json`)、动画(`.gltf`)
- **依赖追踪**:shader 改变,所有用这个 shader 的材质重载
- **重载通知**:某些代码要"知道资产重载"——比如脚本里 `on_texture_reloaded` 回调
- **未保存的修改检测**:编辑器里"如果资产被改但没保存,显示警告"

工业级引擎(Unreal、Unity)的热重载系统有完整团队维护。Casey HH 的简化版教基础。

## 补充:资产管线的"异步加载"

让我讲讲工业 asset manager 的"异步加载",这是 Day 461 的进阶。

**问题**:大资产(几 MB 纹理)的 IO + 解码 + GPU 上传可能阻塞游戏帧几十 ms。玩家看到卡顿。

**解决方案**:异步加载——后台线程做 IO 和解码,主线程继续渲染。

```rust
struct AssetManager {
    loaded: HashMap<PathBuf, Asset>,
    loading: HashMap<PathBuf, Arc<Mutex<Option<Asset>>>>,
    io_thread: ThreadPool,
}

impl AssetManager {
    fn load_async(&mut self, path: PathBuf) -> Arc<Mutex<Option<Asset>>> {
        if let Some(arc) = self.loading.get(&path) {
            return arc.clone();
        }
        let arc = Arc::new(Mutex::new(None));
        let arc_clone = arc.clone();
        let path_clone = path.clone();
        self.io_thread.spawn(move || {
            let data = fs::read(&path_clone).unwrap();
            let asset = decode(&data);
            *arc_clone.lock().unwrap() = Some(asset);
        });
        self.loading.insert(path, arc.clone());
        arc
    }
    
    fn poll(&mut self) -> Vec<PathBuf> {
        let mut completed = vec![];
        for (path, arc) in &self.loading {
            let mut guard = arc.lock().unwrap();
            if guard.is_some() {
                let asset = guard.take().unwrap();
                self.loaded.insert(path.clone(), asset);
                completed.push(path.clone());
            }
        }
        for p in &completed { self.loading.remove(p); }
        completed
    }
}
```

每帧主线程调 `poll()`,把完成的资产从 loading 移到 loaded。

**游戏端的"加载状态"**。代码用资产时要处理"还没加载完"的情况:

```rust
match asset_manager.get(asset_id) {
    AssetState::Loaded(asset) => render(asset),
    AssetState::Loading => render_placeholder(),
    AssetState::Failed(err) => render_error(err),
}
```

placeholder 是"加载中"的占位资产(白色 / 旋转图标)。

**预加载策略**:

- **场景切换时预加载**:进新场景前,加载该场景所有资产,显示 loading screen
- **流式加载**:玩家接近某区域,后台加载该区域资产,无缝过渡(《GTA》、《蜘蛛侠》)
- **LRU cache**:内存有限,最近最少用的资产卸载,腾空间给新的

工业级 asset manager(如 Unreal 的 Streamable Manager)实现这些复杂逻辑。Casey HH 教学简化,但理解异步让你能扩展。

**线程安全的 GPU 上传**。GPU 上传必须在主线程(OpenGL)或专门线程(Vulkan)。所以异步加载线程**解码**资产,但 GPU 上传交给主线程:

```rust
// 后台线程:解码
let pixels = png_decode(&data);  // 后台
// 把 pixels 传给主线程
main_thread_queue.push(move || {
    gpu.upload(&pixels);  // 主线程
});

// 主线程:
while let Some(task) = main_thread_queue.pop() {
    task();
}
```

这种"任务队列"是游戏引擎的常见架构——后台线程做 CPU 重活,主线程顺序消费结果。

## 2 · 心智模型

### 类比:烘焙店换产品

烘焙店每天上新产品。流程:
1. **观察**:店员发现新产品到货(对应 asset_manager.update)
2. **拿货**:把新货放到货架上(对应 reload_asset)
3. **更新价签**:用新 ID 但同位置(对应 GPU texture ID 不变)
4. **客人看到**:客人看到新货(对应游戏渲染新纹理)

如果新货有问题(损坏),保留旧货——不"空货架"。

### 严谨原理:重载流程

```
游戏主循环
  ↓
asset_manager.update() → changed: Vec<AssetId>
  ↓ for each id
reload_asset(id)
  ↓
re-read file bytes
  ↓
decode (PNG → raw pixels)
  ↓
update GPU texture (same TextureId)
  ↓
game uses new pixels next frame
```

每步都可能失败。错误处理:

```rust
fn reload_asset(&mut self, id: AssetId) -> Result<(), ReloadError> {
    let path = &self.assets[id].path;
    let data = std::fs::read(path)
        .map_err(|e| ReloadError::ReadFailed(e))?;
    let image = png_decoder::decode_from_bytes(&data)
        .map_err(|e| ReloadError::DecodeFailed(e))?;
    self.gpu.textures[id].update(&image.pixels, image.width, image.height);
    Ok(())
}
```

每行解释:
- 错误用 enum,精确报告哪一步失败。
- 失败时 GPU 纹理不更新,保留旧版本。

### 主循环集成

```rust
fn game_main_loop(game: &mut Game, asset_mgr: &mut AssetManager) {
    loop {
        let changed = asset_mgr.update();
        for id in changed {
            if let Err(e) = game.reload_asset(id) {
                eprintln!("Reload failed for {}: {:?}", asset_mgr.get_path(id), e);
                // 保留旧资产,继续运行
            }
        }
        game.update();
        game.render();
    }
}
```

每行解释:
- 每帧先处理资产变化,再 update/render。
- 重载失败不 panic,继续运行(让玩家看到旧资产比崩溃好)。

### GPU 纹理更新

OpenGL 更新纹理:

```rust
fn update_texture(&mut self, id: TextureId, pixels: &[u8], w: u32, h: u32) {
    let tex = self.textures[id.0].gl_handle;
    unsafe {
        gl::BindTexture(gl::TEXTURE_2D, tex);
        gl::TexSubImage2D(
            gl::TEXTURE_2D, 0,
            0, 0, w as i32, h as i32,
            gl::RGBA, gl::UNSIGNED_BYTE,
            pixels.as_ptr() as *const _,
        );
    }
}
```

每行解释:
- `BindTexture` 选定要更新的纹理。
- `TexSubImage2D` 替换纹理内容,**复用现有纹理 ID**(`tex`)。
- 不重新生成纹理对象(`GenTextures`),避免 ID 变化。

**关键**:**Texture ID 不变**。游戏代码引用 `TextureId(42)`,重载后 42 仍指向新纹理。这要求资源管理器在 init 时分配固定 ID。

## 3 · 四域深入

### 3.1 · 游戏编程视角

工业游戏引擎的热重载更复杂:

- **依赖追踪**:贴图改了,所有用这张贴图的材质刷新;材质改了,所有用这个材质的网格刷新
- **资产图**:节点(资产)+ 边(依赖),变化向上传播
- **构建管线**:编辑器保存 → 触发构建 → 导入器运行 → 更新引擎内表示

Unreal Engine 的资产系统庞大而复杂,几千行代码。Casey HH 简化版 100 行,但概念相同。

工业坑:
- **大资产重载卡顿**:100MB 纹理重载要几百毫秒,游戏卡顿
- **重载死循环**:资产改了触发保存,保存又触发重载...
- **多人编辑冲突**:多人改同一资产,合并时混乱

### 3.2 · 图形学视角

GPU 纹理热重载的细节:

- **格式兼容**:新纹理格式(如 RGB → RGBA)和旧的不一致,要重新分配
- **mipmap 重生成**:重载后重新生成 mipmap
- **压缩纹理**:BCn 纹理重载要重新压缩,CPU 开销大

**进阶**:增量重载——只更新变化的纹素(texel)。但 PNG 是全量,无法增量。需要专门格式(如"diff 纹理")。

### 3.3 · Linux 系统编程视角

Linux 上 stat 性能:


## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么重载失败时保留旧纹理,而不是 panic?

**参考解答**:游戏运行时崩掉用户体验差。如果开发者正在编辑贴图,中途按保存,文件可能短暂损坏(写入一半)——这时重载必失败。但下次保存成功(写完整),再下次重载成功。如果中途 panic,开发者要重启游戏,丢失当前进度。

保留旧纹理 = 优雅降级(graceful degradation)。这是工业代码的"鲁棒性"原则。

### Lv2 · 动手实践

**题**:完整实现"PNG 文件监听 → 重新解码 → 替换纹理"流程,在 CLI 程序里验证。

**参考解答**:

```rust
use std::collections::HashMap;
use std::path::PathBuf;

#[derive(Debug)]
pub enum ReloadError {
    ReadFailed(std::io::Error),
    DecodeFailed(String),
}

impl std::fmt::Display for ReloadError {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        match self {
            ReloadError::ReadFailed(e) => write!(f, "Read: {}", e),
            ReloadError::DecodeFailed(s) => write!(f, "Decode: {}", s),
        }
    }
}

// 简化版 GPU 纹理(实际用 OpenGL / wgpu)
#[derive(Debug, Clone)]
struct Texture {
    width: u32,
    height: u32,
    pixels: Vec<u8>,  // RGBA
}

struct AssetManager {
    paths: Vec<PathBuf>,
    mtimes: Vec<Option<std::time::SystemTime>>,
    textures: Vec<Texture>,
}

impl AssetManager {
    fn new() -> Self {
        Self {
            paths: Vec::new(),
            mtimes: Vec::new(),
            textures: Vec::new(),
        }
    }
    
    fn load(&mut self, path: &str) -> usize {
        let path = PathBuf::from(path);
        let mtime = std::fs::metadata(&path).and_then(|m| m.modified()).ok();
        let data = std::fs::read(&path).expect("Failed to read");
        let image = png_decoder::decode_from_bytes(&data).expect("Failed to decode");
        let texture = Texture {
            width: image.width,
            height: image.height,
            pixels: image.pixels,
        };
        let id = self.paths.len();
        self.paths.push(path);
        self.mtimes.push(mtime);
        self.textures.push(texture);
        id
    }
    
    fn update(&mut self) -> Vec<usize> {
        let mut changed = Vec::new();
        for (i, path) in self.paths.iter().enumerate() {
            let current = std::fs::metadata(path).and_then(|m| m.modified()).ok();
            if current != self.mtimes[i] {
                self.mtimes[i] = current;
                changed.push(i);
            }
        }
        changed
    }
    
    fn reload(&mut self, id: usize) -> Result<(), ReloadError> {
        let path = &self.paths[id];
        let data = std::fs::read(path).map_err(ReloadError::ReadFailed)?;
        // 模拟解码
        if data.is_empty() {
            return Err(ReloadError::DecodeFailed("empty file".into()));
        }
        let image = png_decoder::decode_from_bytes(&data)
            .map_err(|e| ReloadError::DecodeFailed(format!("{:?}", e)))?;
        self.textures[id] = Texture {
            width: image.width,
            height: image.height,
            pixels: image.pixels,
        };
        println!("[OK] Reloaded {}: {}x{}", path.display(), image.width, image.height);
        Ok(())
    }
}

    pub struct Image { pub width: u32, pub height: u32, pub pixels: Vec<u8> }
    pub enum DecodeError { Dummy }
    pub fn decode_from_bytes(data: &[u8]) -> Result<Image, DecodeError> {
        // 占位实现(实际用 day459 的解码器)
        Ok(Image { width: 1, height: 1, pixels: data.iter().take(4).cloned().collect() })
    }
}

fn main() {
    let args: Vec<_> = std::env::args().collect();
    if args.len() < 2 {
        eprintln!("Usage: hot_reload <file>");
        return;
    }
    
    let mut mgr = AssetManager::new();
    let id = mgr.load(&args[1]);
    println!("Loaded asset {} ({}x{})", id, mgr.textures[id].width, mgr.textures[id].height);
    println!("Watching. Modify the file to trigger reload.");
    
    loop {
        std::thread::sleep(std::time::Duration::from_millis(500));
        let changed = mgr.update();
        for id in changed {
            if let Err(e) = mgr.reload(id) {
                eprintln!("[ERR] Reload failed: {} (kept old version)", e);
            }
        }
    }
}
```

每行解释:
- `load` 启动时调,加载初始数据。
- `update` 检查变化,返回 ID 列表。
- `reload` 重新加载指定 ID,失败时保留旧纹理。
- `png_decoder` 模块用占位实现,实际用 day459 的。

完成标准:程序运行时你 `echo "data" > /tmp/file.png`(模拟修改),程序检测到并"重载"。

## 8 · Rust / Arch 落地代码

完整热重载集成(简化版,聚焦数据流):

```rust
use std::path::PathBuf;
use std::time::{Duration, SystemTime};

#[derive(Debug)]
struct Texture {
    width: u32,
    height: u32,
    pixels: Vec<u8>,
}

#[derive(Debug)]
enum ReloadError {
    ReadFailed(std::io::Error),
    DecodeFailed(String),
}

impl std::fmt::Display for ReloadError {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        match self {
            ReloadError::ReadFailed(e) => write!(f, "Read: {}", e),
            ReloadError::DecodeFailed(s) => write!(f, "Decode: {}", s),
        }
    }
}

struct AssetWatcher {
    paths: Vec<PathBuf>,
    mtimes: Vec<Option<SystemTime>>,
    textures: Vec<Texture>,
    last_errors: Vec<Option<String>>,
}

impl AssetWatcher {
    fn new() -> Self {
        Self {
            paths: Vec::new(),
            mtimes: Vec::new(),
            textures: Vec::new(),
            last_errors: Vec::new(),
        }
    }
    
    fn register(&mut self, path: &str) -> usize {
        let path = PathBuf::from(path);
        let mtime = std::fs::metadata(&path).and_then(|m| m.modified()).ok();
        let id = self.paths.len();
        self.paths.push(path);
        self.mtimes.push(mtime);
        self.textures.push(Texture { width: 0, height: 0, pixels: Vec::new() });
        self.last_errors.push(None);
        id
    }
    
    fn update_and_reload(&mut self) {
        let now = SystemTime::now();
        for i in 0..self.paths.len() {
            let current = match std::fs::metadata(&self.paths[i]).and_then(|m| m.modified()) {
                Ok(t) => t,
                Err(_) => continue,
            };
            if Some(current) == self.mtimes[i] {
                continue;
            }
            self.mtimes[i] = Some(current);
            
            // 尝试重载
            match self.reload(i) {
                Ok(()) => {
                    self.last_errors[i] = None;
                    let age = now.duration_since(current).unwrap_or(Duration::ZERO);
                    println!("[{}] Asset {} reloaded (modified {:.1}s ago)",
                        humantime::format_rfc3339(now), i, age.as_secs_f32());
                }
                Err(e) => {
                    self.last_errors[i] = Some(format!("{}", e));
                    eprintln!("[{}] Asset {} reload failed: {} (keeping old version)",
                        humantime::format_rfc3339(now), i, e);
                }
            }
        }
    }
    
    fn reload(&mut self, id: usize) -> Result<(), ReloadError> {
        let data = std::fs::read(&self.paths[id]).map_err(ReloadError::ReadFailed)?;
        if data.len() < 8 || data[..8] != [0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A] {
            // 不是有效 PNG,模拟 decode 失败
            return Err(ReloadError::DecodeFailed("not a PNG".into()));
        }
        // 模拟 decode(实际调 png_decoder)
        let texture = Texture {
            width: 1,
            height: 1,
            pixels: vec![data.len() as u8, 0, 0, 255],  // 占位
        };
        self.textures[id] = texture;
        Ok(())
    }
    
    fn print_status(&self) {
        for (i, path) in self.paths.iter().enumerate() {
            let status = match &self.last_errors[i] {
                None => format!("OK ({}x{})", self.textures[i].width, self.textures[i].height),
                Some(e) => format!("FAILED: {}", e),
            };
            println!("  [{}] {}: {}", i, path.display(), status);
        }
    }
}

fn main() {
    let args: Vec<_> = std::env::args().collect();
    let mut watcher = AssetWatcher::new();
    
    for arg in args.iter().skip(1) {
        let id = watcher.register(arg);
        println!("Registered [{}] {}", id, arg);
    }
    
    if watcher.paths.is_empty() {
        // 创建测试文件
        std::fs::write("/tmp/test.png", &[0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A])
            .expect("Failed to write test file");
        watcher.register("/tmp/test.png");
        println!("Created and registered /tmp/test.png");
    }
    
    println!("\nWatching. Modify files to trigger reload.\n");
    
    loop {
        std::thread::sleep(Duration::from_millis(500));
        watcher.update_and_reload();
    }
}
```

每行解释:
- `update_and_reload` 把检查和重载合并。
- 时间戳用 `humantime::format_rfc3339` 友好显示(需加 `humantime` crate)。
- 重载失败保留旧纹理,记录错误。
