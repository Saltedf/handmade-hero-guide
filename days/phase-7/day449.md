```
房间 1 → 东 房间 2 → 北 房间 3 → 西 房间 4
                                            ↓
                                          房间 1(撞!)
```

如果不管,你看到的是房间 4 把房间 1 切成两半——视觉怪异、碰撞出错、玩家迷失。

### AABB 重叠算法的几何推导

让我把"两个 AABB 是否重叠"的算法推导清楚,这是 Day 449 的核心数学。

**问题**:两个 AABB,A 和 B,判断它们是否相交(共享任何体积)。

**分离轴定理(SAT,Separating Axis Theorem)**。对于凸体(包括 AABB),如果存在任何"轴"使得 A 和 B 在该轴上的投影不重叠,则 A 和 B 不相交。等价地:**A 和 B 相交当且仅当在所有轴上投影都重叠**。

对 AABB,只有 3 个轴可考虑(X、Y、Z)——因为 AABB 的边对齐这 3 个轴。所以判断 3 次:

```
A 和 B 相交
  ⟺  X 轴投影重叠 AND Y 轴投影重叠 AND Z 轴投影重叠
  ⟺  (A.max.x > B.min.x AND A.min.x < B.max.x)
  AND (A.max.y > B.min.y AND A.min.y < B.max.y)
  AND (A.max.z > B.min.z AND A.min.z < B.max.z)
```

**为什么这是对的?** 在每个轴上,A 和 B 都是一个区间 `[A.min.axis, A.max.axis]`。两个区间相交当且仅当一个的左端点小于另一个的右端点(双向):

```
区间 1: [a1, a2]
区间 2: [b1, b2]
相交 ⟺ a1 < b2 AND b1 < a2
```

3 个轴都满足 → 整个 3D 相交。

**边界 case**:如果 `A.max.x == B.min.x`(精确接触,不重叠),按上面的公式 `A.max.x > B.min.x` 是 false——不算相交。这是对的,精确接触不算相交(它们共享一个 0 体积的面)。但工程上你可能想"接触 = 相交",改 `>=` 即可。

**实现**:

```rust
impl AABB {
    fn intersects(&self, other: &AABB) -> bool {
        // 严格小于 / 大于:接触不算重叠
        self.max.x > other.min.x && self.min.x < other.max.x &&
        self.max.y > other.min.y && self.min.y < other.max.y &&
        self.max.z > other.min.z && self.min.z < other.max.z
    }
}
```

这个函数 6 个比较 + 5 个 AND,**约 10 条汇编指令**,极快。

**碰撞响应**。检测到重叠后,通常还要算"重叠多少"——这用于物理推开:

```rust
fn penetration(a: &AABB, b: &AABB) -> Vec3 {
    // 在每个轴上算最小穿透量
    let overlap_x = (a.max.x - b.min.x).min(b.max.x - a.min.x);
    let overlap_y = (a.max.y - b.min.y).min(b.max.y - a.min.y);
    let overlap_z = (a.max.z - b.min.z).min(b.max.z - a.min.z);
    Vec3::new(overlap_x, overlap_y, overlap_z)
}
```

物理推开选最小穿透轴(因为这是"最容易"分离的方向)。Day 449 不需要推开(直接丢弃房间),但理解 penetration 是 Day 460+ 物理碰撞的基础。

**全部对检测**。对 N 个房间的列表,检测任何一对重叠:

```rust
fn any_overlap(rooms: &[AABB]) -> Option<(usize, usize)> {
    for i in 0..rooms.len() {
        for j in (i+1)..rooms.len() {
            if rooms[i].intersects(&rooms[j]) {
                return Some((i, j));
            }
        }
    }
    None
}
```

复杂度 O(N²)。N=100 是 5000 次比较,N=1000 是 50 万次。Casey HH 房间数 < 50,O(N²) 够用。

### "重试"策略的工程权衡

Casey Day 449 选"重试"策略——失败就换方向。这个简单选择有几个隐藏的工程问题。

**问题 1:重试次数**。无限制重试可能死循环(房间密集到任何方向都失败)。Casey HH 通常设 MAX_RETRY=5 或 10,超过就放弃这条分支。

**问题 2:重试的方向选择**。失败的方向"东"不再试,但还有 3 个方向(西/南/北)。如何选?

- **顺序**:固定顺序(N → E → S → W),失败跳下一个
- **随机**:每次随机选未试过的方向
- **统计**:记录每个方向的失败率,优先选低失败率方向

Casey HH 用随机——简单且自然。

**问题 3:重试 vs 回溯**。重试是"换方向再试同一父房间"。回溯是"放弃父房间,回到祖父房间"。回溯更深,但代价大。

**问题 4:重试的确定性**。给同一种子,重试结果应该可复现。所以重试用的 RNG 必须从主 RNG 继承——不能每次重试用新种子。

```rust
fn generate_room_with_retry(rng: &mut Rng, parent: &Room, rooms: &[Room]) -> Option<Room> {
    let mut tried_directions = HashSet::new();
    while tried_directions.len() < 4 {
        let dir = random_direction_excluding(rng, &tried_directions);
        tried_directions.insert(dir);
        let candidate = place_adjacent(parent, dir, random_size(rng));
        if !any_overlap(&candidate, rooms) {
            return Some(candidate);
        }
    }
    None  // 4 个方向都试过,失败
}
```

**问题 5:失败的统计**。如果生成 100 个房间,99 个成功,1 个失败——可接受。但 50 个失败——参数空间太挤,要调宽。

工业 procedural generation 库(Unity PCG、Unreal PCG)有统计 dashboard,实时显示成功率,帮助设计师调参。

### 防重叠的算法选择

检测两个 AABB(轴对齐包围盒)是否重叠的算法:

```
两个 AABB 重叠 ⟺
    (A.min.x <= B.max.x) AND (A.max.x >= B.min.x) AND
    (A.min.y <= B.max.y) AND (A.max.y >= B.min.y) AND
    (A.min.z <= B.max.z) AND (A.max.z >= B.min.z)
```

简单 O(1) 测试。N 个房间,新房间要和所有 N 个测试,O(N) per query。

工业级加速:
- **BVH(Bounding Volume Hierarchy)**:层次包围盒,O(log N) per query。
- **Spatial hash**:空间哈希,O(1) per query(但常数大)。
- **Uniform grid**:均匀网格,O(1) per query。

Casey Day 449 用 O(N)(简单),N 小(几十个房间),够用。工业级游戏(几万物体)必须用 BVH 或 spatial hash。

让我把 spatial hash 和 uniform grid 讲清楚,这是工业碰撞检测的核心数据结构。

**Uniform Grid(均匀网格)**。把世界划成大小为 `cell_size` 的立方体格子,每个格子维护一个 AABB 列表。查询"X 和谁碰"时,只查 X 占据的格子里的 AABB。

```rust
struct UniformGrid {
    cell_size: f32,
    cells: HashMap<(i32, i32, i32), Vec<usize>>,  // 格子坐标 → AABB 索引列表
}

impl UniformGrid {
    fn insert(&mut self, aabb_idx: usize, aabb: &AABB) {
        let (x0, y0, z0) = self.cell_coord(aabb.min);
        let (x1, y1, z1) = self.cell_coord(aabb.max);
        for x in x0..=x1 {
            for y in y0..=y1 {
                for z in z0..=z1 {
                    self.cells.entry((x, y, z)).or_default().push(aabb_idx);
                }
            }
        }
    }
    
    fn query(&self, aabb: &AABB) -> Vec<usize> {
        let mut result = Vec::new();
        let (x0, y0, z0) = self.cell_coord(aabb.min);
        let (x1, y1, z1) = self.cell_coord(aabb.max);
        for x in x0..=x1 {
            for y in y0..=y1 {
                for z in z0..=z1 {
                    if let Some(cell) = self.cells.get(&(x, y, z)) {
                        result.extend(cell.iter());
                    }
                }
            }
        }
        result.sort();
        result.dedup();  // 跨多个格子的 AABB 出现多次,去重
        result
    }
    
    fn cell_coord(&self, p: Vec3) -> (i32, i32, i32) {
        (
            (p.x / self.cell_size) as i32,
            (p.y / self.cell_size) as i32,
            (p.z / self.cell_size) as i32,
        )
    }
}
```

`cell_size` 选择关键——太大退化到暴力(每格含很多 AABB),太小查询要查很多格子(overhead)。常见选择:`cell_size ≈ 平均 AABB 大小`。

**Spatial Hash**。Uniform Grid 用 `HashMap<(i32,i32,i32), Vec<usize>>`。三维坐标哈希有点贵。Spatial hash 用**单维哈希**——把三维坐标哈希成一个 u64:

```rust
fn hash_coord(x: i32, y: i32, z: i32) -> u64 {
    // 简单混合:每个轴 21 位
    ((x as u64) << 42) | ((y as u64 & 0x1FFFFF) << 21) | (z as u64 & 0x1FFFFF)
}
```

这样用 `HashMap<u64, Vec<usize>>`,查找稍快。代价:坐标范围受限(±1M 格子),但游戏世界通常够。

**BVH(Bounding Volume Hierarchy)**。树形结构,每个节点存自身 AABB,父节点 AABB = 子节点 AABB 并集。查询时从根递归——根不重叠则整个子树跳过。

```rust
struct BvhNode {
    aabb: AABB,
    left: Option<Box<BvhNode>>,
    right: Option<Box<BvhNode>>,
    leaf_aabb_idx: Option<usize>,  // 叶子节点存实际 AABB 索引
}
```

BVH 适合"动态场景"(AABB 移动时,只更新相关节点),uniform grid 适合"静态场景"(房间不动,grid 不变)。Day 449 房间不动,uniform grid 最合适,但 Casey HH 简化用暴力。

### "重新生成"的工程现实

检测到重叠后怎么办?选项:

**选项 A:重试**。换一个方向,再生成。简单,但如果迷宫密度高,可能多次重试都失败——浪费时间。

**选项 B:回退**。撤销之前的几个房间,换个布局。复杂(要 undo log),但更彻底。

**选项 C:接受**。允许小重叠,生成时"合并"或"覆盖"。简单但视觉差。

**选项 D:拒绝整次生成**。如果迷宫太难生成,放弃,从头开始。最简单但慢。

工业级选择:**A + B 混合**。重试 N 次(N=5-10),失败则回退几步。如果整体失败率高,完全重生成。

## 2 · 心智模型

### 类比:停车

停车场里停车,先看你要进车位周围有没有车。如果撞到别人,你重新找一个空位。

房间生成同理:放新房前,看它和已存在的房间有没有重叠。重叠 = 撞车,要换位置。

### 严谨原理:AABB-AABB 重叠测试

两个 AABB A 和 B,AABB 重叠 ⟺ **三个轴都重叠**。

每个轴上,区间 `[a_min, a_max]` 和 `[b_min, b_max]` 重叠 ⟺ `a_min < b_max && b_min < a_max`。

```rust
fn intervals_overlap(a_min: f32, a_max: f32, b_min: f32, b_max: f32) -> bool {
    a_min < b_max && b_min < a_max
}

fn aabbs_overlap(a: &AABB, b: &AABB) -> bool {
    intervals_overlap(a.min.x, a.max.x, b.min.x, b.max.x) &&
    intervals_overlap(a.min.y, a.max.y, b.min.y, b.max.y) &&
    intervals_overlap(a.min.z, a.max.z, b.min.z, b.max.z)
}
```

每行解释:
- 每个轴独立判断,三个都重叠才算 AABB 重叠。
- `a_min < b_max` — A 的左端在 B 的右端左边。
- `b_min < a_max` — B 的左端在 A 的右端左边。
- 注意用严格 `<` 而不是 `<=`,共享边界不算重叠(房间贴墙不算撞)。

**为什么这等价于"重叠"?** 在 X 轴上,AABB 在 [a_min, a_max],B 在 [b_min, b_max]。它们 X 投影重叠 ⟺ 两个区间相交 ⟺ 上述条件。三维 AABB 重叠 ⟺ 三个轴投影都相交。这是 **分离轴定理(SAT)** 的特殊情况——对 AABB 只有 3 个轴(X、Y、Z)需要检查。

### 与已有房间比较

```rust
fn overlaps_any(new_room: &AABB, existing: &[AABB]) -> bool {
    for r in existing {
        if aabbs_overlap(new_room, r) {
            return true;
        }
    }
    false
}
```

O(N) per query。N=100 时够用;N=10000+ 用 BVH 加速到 O(log N)。

### 重试逻辑

```rust
const MAX_ATTEMPTS: usize = 8;

fn try_place_room(rng: &mut Pcg32, anchor: &AABB, existing: &[AABB]) -> Option<AABB> {
    for _ in 0..MAX_ATTEMPTS {
        let dir = match rng.next() % 4 {
            0 => Direction::East,
            1 => Direction::West,
            2 => Direction::North,
            _ => Direction::South,
        };
        let new_size = generate_size(rng);
        let new_room = place_adjacent(anchor, dir, new_size);
        if !overlaps_any(&new_room, existing) {
            return Some(new_room);
        }
    }
    None  // 8 次都失败
}
```

每行解释:
- `for _ in 0..MAX_ATTEMPTS` — 最多试 8 次。
- 每次随机方向 + 随机大小,生成新房间候选。
- `overlaps_any` 检查。
- 成功 → 返回 `Some(room)`;失败 → 返回 `None`。

调用方处理 `None`:
```rust
match try_place_room(&mut rng, &anchor, &existing) {
    Some(room) => { rooms.push(room); /* 继续扩展 */ }
    None => { /* 死胡同,停止这条走廊分支 */ }
}
```

### BVH 加速(进阶)

N=10000 时,每放一个新房扫 10000 个 AABB 太慢。**BVH(Bounding Volume Hierarchy)** 把房间组织成树:

```
              根 AABB
             /        \
          左子         右子
         /    \       /    \
       ...    ...   ...    ...
```

每个内部节点的 AABB 是子节点 AABB 的并集。查询"新房是否撞已有"时:
- 从根开始
- 若新房与某节点 AABB 不相交,跳过整个子树
- 否则递归

平均 O(log N)。这是大型场景的标配(光线追踪、碰撞检测)。

Casey HH N ≤ 100,不用 BVH。后面 Day 530+ 大世界会引入。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏里的"防撞"层次:

- **静态(本日)**:生成时检查,生成后不变
- **动态**:每帧检查实体碰撞(Minkowski,Day 050)
- **物理**:连续碰撞检测(CCD),防止"穿墙"
- **AI**:路径规划绕开障碍

每层用不同算法,不能混用。本日是"静态生成时检查",简单但够用。

工业坑:**重试可能死锁**。如果地图小、房间大,8 次重试都可能失败。需要"放弃当前分支"逻辑,否则算法卡住。

### 3.2 · 图形学视角

AABB 重叠是图形学最常见的几何查询:

- **视锥剔除**:每帧检查每个物体的 AABB 是否在视锥内
- **光线相交**:射线和 AABB 相交,加速结构(BVH)基础
- **碰撞预判**:精确碰撞(OBB / mesh)前用 AABB 预判
- **场景图**:父节点 AABB 包含所有子节点,层次剔除

**Slab method**:射线和 AABB 相交的标准算法。每个轴计算"进入"和"退出"时间,三者最大的"进入" < 三者最小的"退出" ⟺ 相交。

### 3.3 · Linux 系统编程视角

Linux 也有"重叠检测":

- **`/proc/<pid>/maps`**:进程的虚拟内存区域,内核保证不重叠
- **物理内存分配**:伙伴系统(buddy allocator)管理物理页,合并相邻 free block
- **文件锁(`fcntl`)**:`F_RDLCK / F_WRLCK` 锁住文件区间,检测重叠

```bash
# 看进程的内存区域(每个都不重叠)
cat /proc/$$/maps
# 输出形如:
# 555555554000-555555556000 r--p ...
# 555555556000-555555558000 r-xp ...
# (区间不重叠)
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 `a_min < b_max` 用严格 `<` 而不是 `<=`?如果用 `<=` 会怎样?

**参考解答**:严格 `<` 让"贴墙不算重叠"。Day 447 的 `place_adjacent` 让两房间共享墙——共享墙意味着 `a.max.x == b.min.x`。如果用 `<=`,`intervals_overlap` 会判定它们重叠,新房间被拒绝。

用 `<` 时,`a.min < b.max && b.min < a.max`,当 `a.max == b.min` 时 `b.min < a.max` 不成立(`b.min == a.max`),不重叠。正确。

## 8 · Rust / Arch 落地代码

完整迷宫生成器,带重叠检测:

```rust
// (省略 Vec3 / AABB / Pcg32 / Direction / place_adjacent 等,见 day446-448)

fn intervals_overlap(a_min: f32, a_max: f32, b_min: f32, b_max: f32) -> bool {
    a_min < b_max && b_min < a_max
}

fn aabbs_overlap(a: &AABB, b: &AABB) -> bool {
    intervals_overlap(a.min.x, a.max.x, b.min.x, b.max.x) &&
    intervals_overlap(a.min.y, a.max.y, b.min.y, b.max.y) &&
    intervals_overlap(a.min.z, a.max.z, b.min.z, b.max.z)
}

fn overlaps_any(new_room: &AABB, existing: &[AABB]) -> bool {
    for r in existing {
        if aabbs_overlap(new_room, r) {
            return true;
        }
    }
    false
}

const MAX_ATTEMPTS: usize = 16;

fn try_place_room(rng: &mut Pcg32, anchor: &AABB, existing: &[AABB]) -> Option<AABB> {
    for _ in 0..MAX_ATTEMPTS {
        let dir = match rng.next() % 4 {
            0 => Direction::East,
            1 => Direction::West,
            2 => Direction::North,
            _ => Direction::South,
        };
        // 随机大小
        let w = 8.0 + rng.next_f32() * 8.0;  // 8..16 米
        let h = 3.0 + rng.next_f32() * 1.0;  // 3..4 米
        let d = 8.0 + rng.next_f32() * 8.0;
        let new_size = Vec3 { x: w, y: h, z: d };
        let new_room = place_adjacent(anchor, dir, new_size);
        if !overlaps_any(&new_room, existing) {
            return Some(new_room);
        }
    }
    None
}

fn generate_maze(seed: u64, target_rooms: usize) -> Vec<AABB> {
    let mut rng = Pcg32::new(seed, 1);
    let first_size = Vec3 { x: 10.0, y: 3.0, z: 10.0 };
    let mut rooms = vec![AABB {
        min: Vec3::ZERO,
        max: Vec3 { x: first_size.x, y: first_size.y, z: first_size.z },
    }];

    while rooms.len() < target_rooms {
        // 从随机已有房间扩展
        let anchor_idx = (rng.next() as usize) % rooms.len();
        let anchor = rooms[anchor_idx];
        match try_place_room(&mut rng, &anchor, &rooms) {
            Some(room) => rooms.push(room),
            None => {
                // 死路:换 anchor 再试
                if rooms.len() < 2 { break; }
            }
        }
    }
    rooms
}

fn main() {
    let maze = generate_maze(42, 20);
    println!("Generated {} rooms", maze.len());
    for (i, r) in maze.iter().enumerate() {
        let s = r.size();
        println!("Room {}: origin=({:.1},{:.1},{:.1}) size=({:.1}x{:.1}x{:.1})",
            i, r.min.x, r.min.y, r.min.z, s.x, s.y, s.z);
    }

    // 验证无重叠
    for i in 0..maze.len() {
        for j in (i+1)..maze.len() {
            assert!(!aabbs_overlap(&maze[i], &maze[j]),
                "Rooms {} and {} overlap!", i, j);
        }
    }
    println!("All {} rooms are non-overlapping", maze.len());

    // 跑 100 种子统计
    let mut success_count = 0;
    for seed in 0..100u64 {
        let maze = generate_maze(seed, 20);
        if maze.len() == 20 {
            success_count += 1;
        }
    }
    println!("\nSuccess rate (20 rooms): {}/100 seeds", success_count);
}
```

每行解释:
- `MAX_ATTEMPTS = 16` — 比单一尝试多,适应密集场景。
- `anchor_idx = rng.next() % rooms.len()` — 从已有房间随机选一个作为新扩张起点(不是纯线性走廊,而是树状迷宫)。
- 双重循环 `for i ... for j ...` 验证所有对不重叠。O(N²),N=20 没问题。
- 跑 100 种子统计成功率,验证算法稳定性。
