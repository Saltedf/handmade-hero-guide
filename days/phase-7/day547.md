# Day 547 · 开始转向光探针(光探针系统大重构起点)

> 前 100 多天 Casey 的光照是 **mesh-based**(每 mesh 算光照)。Day 547 他宣布彻底换思路:**光探针(light probes)**——把光照从"挂在物体上"变成"挂在空间上"。这是 Phase 7 最重要的一天,光照系统从这里开始彻底重构,直到 day575 才完工。

## 0 · 为什么要有这一天

先讲清楚两种光照模型的根本区别。

**Mesh-based lighting**(之前的做法):每个 mesh 上挂"我现在被多少光照到"。光照计算时,遍历每个 mesh 的每个顶点,问"附近有哪些光源影响我"。问题:同一个空间点的光照,被周围多个 mesh 算了很多遍;静态物体(墙)和动态物体(玩家)的光照算了两遍;实时改动光源时,所有 mesh 都要重算。

**Probe-based lighting**(新的做法):把空间分成 3D 网格,每个网格点放一个"探针"——预先记录"这个点的光照是什么样"。渲染时,物体不在 mesh 上查光照,而是查"我在哪个网格点附近,那里光照如何"。

这就是 **spatial lighting field**(空间光照场),类比物理学里的"场"——电磁场不挂在物体上,挂在空间上,物体在空间某点感受到场强。

为什么 Casey 要换?因为他发现 mesh-based 有几个无法解决的问题:

- **动态光源贵**:每帧重算每个 mesh 的光照,CPU/GPU 都吃紧
- **间接光(光 bounced 几次后)难**:光从墙弹到地板,地板再弹到天花板,mesh-based 跟踪这种 bounce 极复杂
- **大场景存储爆炸**:每个 mesh 都存自己的光照,信息重复

Probe-based 把这些一并解决:**光照预计算存到空间网格里**,渲染时只查询,不计算。

这是现代游戏引擎(Unreal Lumen、Unity HDRP、CryEngine SVOGI)的核心思想。Day 547 是 Casey 走向"现代光照"的第一步,后面 28 天(Day 548-575)都是这个重构的不同部分。

完成这一天之后,你具备:

- 理解 mesh-based vs probe-based 的根本区别
- 知道 voxel(体素)是什么,怎么把空间切成网格
- 能预判后面 28 天 Casey 要做什么(全局地图)

## 2 · 心智模型

### 类比:从"贴标签"到"地图"

旧光照(Mesh-based):每个物体贴一个标签"我现在被光照多少"。物体走了,标签也走了。新物体来,要重新算标签。

新光照(Probe-based):整个房间铺一张**光照地图**。地图上每个点写"这个位置的光照是 X"。物体来了,**查地图**就知道光照。地图不动,物体来来去去都查同一张地图。

更精确的类比:**温度场**。气象局在每个城市放温度计,把全国温度画成一张温度图(温度场)。任何人在地图上某点,知道那里温度——不用每个行人自带温度计。

光照 = 视觉版的温度。光探针 = 温度计。空间光照场 = 温度图。

### 严谨展开:体素网格

**Voxel(体素)** 是 "volume pixel"(体积像素)的简称——3D 的像素。像素是 2D 网格的小方格,voxel 是 3D 网格的小立方体。

把游戏世界切成 1 米一个的立方体网格,每个 1m³ 是一个 voxel。Voxel 内的光照认为是均匀的(或用 trilinear 插值近似连续)。

```
世界坐标 (x, y, z) → voxel index (i, j, k)
i = floor(x / voxel_size)
j = floor(y / voxel_size)
k = floor(z / voxel_size)
```

**Voxel size** 是关键参数:

- 太大(10 米):粗糙,光照细节丢失
- 太小(0.1 米):数量爆炸,1km³ = 10¹² voxel
- 折中(1-2 米):够看清大物体,数量可控

Casey 选 1 米 voxel,1km³ = 10⁹ voxel。每个 voxel 存 RGBA(发光颜色 + alpha)= 8 字节,总 8 GB——太大!所以必须做 **sparse storage**(稀疏存储):只存有内容的部分,空区域不存。这是后续天的工作。

### 光探针是什么

光探针 = voxel + 光照数据。具体存什么:

- **Irradiance(辐照度)**:从这点出发,所有方向的入射光总和
- **Radiance(辐射度)**:从这点出发,沿特定方向的出射光
- **Visibility(可见性)**:这点看向各方向,被什么遮挡

最简单形式:每个 voxel 存一个 RGB 颜色 = "这点的环境光颜色"。复杂形式:cubemap(六个面,每个面记录方向光)。Casey 从简单形式开始,逐步演化。

### 渲染时的查询

像素渲染时:

1. 算出像素的世界坐标 P
2. 算出 P 在哪个 voxel(可能跨 voxel 边界,用 trilinear 插值 8 个邻居)
3. 从 voxel 取光照值,作用到物体表面

伪代码:

```glsl
// fragment shader
vec3 world_pos = ...;        // 像素世界坐标
vec3 normal = ...;           // 像素法线
vec3 voxel_coord = world_pos / voxel_size;
vec4 light = texture(light_voxel_texture, voxel_coord);
vec3 color = surface_color * light.rgb * max(0.0, dot(normal, light_dir));
```

### 光探针 vs 光照贴图

老的光照贴图(lightmap,Quake 时代):只在**静态表面**预计算光照。问题是动态物体(玩家)享受不到。

光探针:**空间任意点**都有光照,玩家在空间中走,实时查询,享受同样质量的光照。

这是为什么光探针叫"探针"——它**采样空间**而非采样表面。

## 3 · 四域深入

### 3.1 · 游戏编程视角

光探针在工业游戏里的几种实现:

- **Light Propagation Volumes (LPV)**:CryEngine 3 用,光在体素网格间传播(类似流体)
- **Sparse Voxel Octree (SVO)**:CryEngine 用八叉树加速
- **Voxel Cone Tracing**:Unreal 用,从一点沿圆锥方向采样体素,模拟 soft shadow / GI
- **Real-time GI(Unreal Lumen)**:2020+,用 card capture + voxel 混合,全自动
- **Probe-based(本项目)**:Casey 自己造,接近 LPV

光探针的工程挑战:

- **更新**:光源动了,探针要重算——real-time GI 是圣杯
- **存储**:几亿 voxel 内存爆——稀疏存储必备
- **过滤**:离散 voxel 在屏幕上有锯齿——三线性 / 三次插值

### 3.2 · 图形学视角

从渲染方程(Rendering Equation,Kajiya 1986)看:

```
L_o(x, ω_o) = L_e(x, ω_o) + ∫ f_r(x, ω_i, ω_o) L_i(x, ω_i) cos(θ_i) dω_i
```

- L_o:出射光
- L_e:自发光
- f_r:BRDF(材质)
- L_i:入射光(从所有方向)

光探针的本质:**预计算 L_i**(每个 voxel 看向所有方向的入射光)。渲染时 f_r * L_i 是简单乘法,实时算。

注意 L_i 是 4D 函数(位置 3D + 方向 2D),完整存储很贵。简化为 RGB(位置 3D,方向用低阶 SH 表示)。

**Spherical Harmonics(球面谐波)**:用一组正交基函数表示球面函数,通常用 2 阶(9 个系数)或 3 阶(16 个系数)就够存 irradiance。这是 Casey 后面会用到的。

### 3.3 · Linux 系统编程视角

"把空间切成网格查询"在系统编程常见:

- **Page table**:虚拟地址 → 物理地址,4 KB 一格
- **Huge pages**:2 MB / 1 GB 粗粒度网格
- **buddy allocator**:内存分配,2 的幂大小
- **Database B-tree**:类似八叉树的空间索引

GPU 上的体素网格通常用 3D texture(OpenGL `GL_TEXTURE_3D`)或 storage buffer。Casey 用 3D texture,因为硬件 trilinear 采样免费。

### 3.4 · Rust 生态视角

Rust 表达 voxel grid:

```rust
struct VoxelGrid<T: Copy> {
    data: Vec<T>,
    dim: [usize; 3],  // x, y, z 维度
    voxel_size: f32,
}

impl<T: Copy + Default> VoxelGrid<T> {
    fn new(dim: [usize; 3], voxel_size: f32) -> Self {
        VoxelGrid {
            data: vec![T::default(); dim[0] * dim[1] * dim[2]],
            dim,
            voxel_size,
        }
    }

    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim[1] + j) * self.dim[0] + i
    }

    fn get(&self, i: usize, j: usize, k: usize) -> &T {
        &self.data[self.idx(i, j, k)]
    }

    // 世界坐标 → voxel,带 trilinear 插值
    fn sample_trilinear(&self, world: [f32; 3]) -> T
    where T: Lerp + Copy {
        let v = [world[0] / self.voxel_size, world[1] / self.voxel_size, world[2] / self.voxel_size];
        let i = v[0].floor() as usize;
        let j = v[1].floor() as usize;
        let k = v[2].floor() as usize;
        let fx = v[0] - i as f32;
        let fy = v[1] - j as f32;
        let fz = v[2] - k as f32;

        let c000 = self.get(i, j, k);
        let c100 = self.get(i+1, j, k);
        // ... 8 个角点
        // 三次 lerp
        T::lerp(
            T::lerp(
                T::lerp(*c000, *c100, fx),
                T::lerp(*c010, *c110, fx),
                fy,
            ),
            T::lerp(
                T::lerp(*c001, *c101, fx),
                T::lerp(*c011, *c111, fx),
                fy,
            ),
            fz,
        )
    }
}

trait Lerp {
    fn lerp(a: Self, b: Self, t: f32) -> Self;
}
```

`block-mesh`、`ilattice` 等 crate 提供现成的 voxel grid 实现。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Mesh-based lighting 和 Probe-based lighting 的根本区别是什么?为什么 mesh-based 难以做间接光(光 bounce)?

**参考解答**:Mesh-based 把光照"绑"在 mesh 上,每 mesh 算"我收到多少光"。间接光需要"我的光是别人的反射光"——也就是查询"别的 mesh 反射了什么"。这要么每 mesh 互相通信(复杂),要么有一个"中间场"存所有人的反射(那不就是 probe-based?)。所以 mesh-based 在物理上**没有空间概念**,无法表达"光从一个空间点传播到另一个空间点"。Probe-based 把光脱离物体,放在空间上,自然能传播。

### Lv2 · 动手实践

**题**:写一个最小 voxel grid,验证"世界坐标 → voxel 索引"和"插值采样"。

要求:
- 创建 8x8x8 的 voxel grid,voxel size = 1.0
- 每个 voxel 存一个 f32(模拟"光照")
- 用 `(i+j+k) * 0.1` 填充 voxel 值
- 在世界坐标 (1.5, 2.5, 3.5) 采样,期望返回 8 个邻居的平均

**参考解答**:

```rust
struct VoxelGrid {
    data: Vec<f32>,
    dim: [usize; 3],
}

impl VoxelGrid {
    fn new(dim: [usize; 3]) -> Self {
        VoxelGrid { data: vec![0.0; dim[0]*dim[1]*dim[2]], dim }
    }

    fn get(&self, i: usize, j: usize, k: usize) -> f32 {
        self.data[(k * self.dim[1] + j) * self.dim[0] + i]
    }

    fn set(&mut self, i: usize, j: usize, k: usize, v: f32) {
        self.data[(k * self.dim[1] + j) * self.dim[0] + i] = v;
    }

    fn sample_trilinear(&self, world: [f32; 3]) -> f32 {
        let i = world[0].floor() as usize;
        let j = world[1].floor() as usize;
        let k = world[2].floor() as usize;
        let fx = world[0] - i as f32;
        let fy = world[1] - j as f32;
        let fz = world[2] - k as f32;

        let c000 = self.get(i, j, k);
        let c100 = self.get(i+1, j, k);
        let c010 = self.get(i, j+1, k);
        let c110 = self.get(i+1, j+1, k);
        let c001 = self.get(i, j, k+1);
        let c101 = self.get(i+1, j, k+1);
        let c011 = self.get(i, j+1, k+1);
        let c111 = self.get(i+1, j+1, k+1);

        let lerp = |a, b, t| a + (b - a) * t;

        let c00 = lerp(c000, c100, fx);
        let c10 = lerp(c010, c110, fx);
        let c01 = lerp(c001, c101, fx);
        let c11 = lerp(c011, c111, fx);

        let c0 = lerp(c00, c10, fy);
        let c1 = lerp(c01, c11, fy);
        lerp(c0, c1, fz)
    }
}

fn main() {
    let mut grid = VoxelGrid::new([8, 8, 8]);
    for i in 0..8 {
        for j in 0..8 {
            for k in 0..8 {
                grid.set(i, j, k, (i + j + k) as f32 * 0.1);
            }
        }
    }

    let v = grid.sample_trilinear([1.5, 2.5, 3.5]);
    println!("Sampled at (1.5, 2.5, 3.5): {}", v);

    // 预期:8 个邻居的平均
    // 邻居 (1..3, 2..4, 3..5)
    let mut sum = 0.0;
    for i in 1..=2 { for j in 2..=3 { for k in 3..=4 {
        sum += grid.get(i, j, k);
    }}}
    println!("Expected: {}", sum / 8.0);
}
```

## 8 · Rust / Arch 落地代码

完整的"voxel grid + 光源注入"演示:

```rust
// 一个 RGBA voxel
#[derive(Clone, Copy, Debug, Default, PartialEq)]
struct Voxel {
    r: u8, g: u8, b: u8,  // RGB 光照
    a: u8,                // alpha:用于"密度"(墙=255,空=0)
}

struct LightGrid {
    data: Vec<Voxel>,
    dim: [usize; 3],
    voxel_size: f32,
}

impl LightGrid {
    fn new(dim: [usize; 3], voxel_size: f32) -> Self {
        LightGrid {
            data: vec![Voxel::default(); dim[0]*dim[1]*dim[2]],
            dim,
            voxel_size,
        }
    }

    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim[1] + j) * self.dim[0] + i
    }

    fn get(&self, i: usize, j: usize, k: usize) -> Voxel {
        self.data[self.idx(i, j, k)]
    }

    fn set(&mut self, i: usize, j: usize, k: usize, v: Voxel) {
        self.data[self.idx(i, j, k)] = v;
    }

    // 在世界坐标处放一个点光源
    fn inject_point_light(&mut self, world: [f32; 3], color: [u8; 3], radius: f32) {
        let center = [
            (world[0] / self.voxel_size) as i64,
            (world[1] / self.voxel_size) as i64,
            (world[2] / self.voxel_size) as i64,
        ];
        let r = (radius / self.voxel_size) as i64;

        for dk in -r..=r {
            for dj in -r..=r {
                for di in -r..=r {
                    let d2 = di*di + dj*dj + dk*dk;
                    if d2 > r*r { continue; }
                    let i = (center[0] + di) as usize;
                    let j = (center[1] + dj) as usize;
                    let k = (center[2] + dk) as usize;
                    if i >= self.dim[0] || j >= self.dim[1] || k >= self.dim[2] { continue; }

                    let falloff = 1.0 - (d2 as f32).sqrt() / r as f32;
                    let existing = self.get(i, j, k);
                    self.set(i, j, k, Voxel {
                        r: (existing.r as f32 + color[0] as f32 * falloff) as u8,
                        g: (existing.g as f32 + color[1] as f32 * falloff) as u8,
                        b: (existing.b as f32 + color[2] as f32 * falloff) as u8,
                        a: existing.a,
                    });
                }
            }
        }
    }

    // 在某点采样光照(trilinear)
    fn sample(&self, world: [f32; 3]) -> [f32; 3] {
        let v = [
            world[0] / self.voxel_size,
            world[1] / self.voxel_size,
            world[2] / self.voxel_size,
        ];
        let i = v[0].floor() as usize;
        let j = v[1].floor() as usize;
        let k = v[2].floor() as usize;
        let fx = v[0] - i as f32;
        let fy = v[1] - j as f32;
        let fz = v[2] - k as f32;

        let mut sum = [0.0f32; 3];
        for dk in 0..=1 {
            for dj in 0..=1 {
                for di in 0..=1 {
                    let vox = self.get(i+di, j+dj, k+dk);
                    let w = (if di == 0 { 1.0 - fx } else { fx })
                          * (if dj == 0 { 1.0 - fy } else { fy })
                          * (if dk == 0 { 1.0 - fz } else { fz });
                    sum[0] += vox.r as f32 * w;
                    sum[1] += vox.g as f32 * w;
                    sum[2] += vox.b as f32 * w;
                }
            }
        }
        sum
    }
}

fn main() {
    let mut grid = LightGrid::new([16, 16, 16], 1.0);

    // 放一个红光源
    grid.inject_point_light([5.0, 8.0, 5.0], [255, 0, 0], 5.0);

    // 在几个点采样
    for p in [[5.0, 8.0, 5.0], [6.0, 8.0, 5.0], [10.0, 8.0, 5.0]] {
        let l = grid.sample(p);
        println!("Sample at {:?}: rgb=({:.0}, {:.0}, {:.0})", p, l[0], l[1], l[2]);
    }
}
```

Arch 性能分析:大 voxel grid 是 cache miss 重灾区。用 `perf stat -e cache-misses`:

```bash
cargo build --release
perf stat -e cache-misses,cache-references,LLC-load-misses ./target/release/light_grid_demo

# 输出:
# 5,432,109    cache-misses      # 25% miss rate
# 21,000,000   cache-references
# 2,100,000    LLC-load-misses   # L3 cache miss
```

如果 miss 高,改 `data` 布局——`Vec<Voxel>` 是 SoA 的一种(已经 cache 友好)。如果要更优化,用 `Vec<u8>` + 索引:

```rust
struct LightGrid {
    r: Vec<u8>,  // 单独一个数组
    g: Vec<u8>,
    b: Vec<u8>,
    a: Vec<u8>,
    dim: [usize; 3],
}
```

这样遍历"所有 R"时 cache 完美。但 trilinear 采样要查 4 个数组,慢。设计时权衡。
