
# Day 443 · 更新玩家移动代码

> 在大改世界生成器之前,Casey 决定先清理玩家移动——把相机控制从"手动 Euler 角"升级到"基于四元数",同时支持新的房间几何体。这一步看起来是边角清理,实则为后面"房间连接 / 自动相机放置"打基础。

## 0 · 为什么要有这一天

玩家移动是游戏体验的核心。HH 此前的玩家移动用简单 Euler 角:Yaw(左右转)、Pitch(上下看)直接累加角度。这种方法在小范围(±90° Pitch)够用,但有几个问题:

第一,**Gimbal lock(万向节锁)**。当 Pitch 接近 ±90° 时,Yaw 和 Roll 的轴对齐,相机突然"翻转"——视觉上突兀,操作上混乱。

第二,**不连续**。当 Yaw 从 359° 转到 1°,玩家感受是"短转",但程序里数值跳了 358°,插值会走长路径。

第三,**难以表达 3D 房间几何**。Casey 接下来要生成的房间可能任意方向倾斜(垂直走廊、倾斜天花板),Euler 角不能优雅表达"相机相对房间"。

四元数(quaternion)是工程解决方案。它用 4 个数(x, y, z, w)表达旋转,没有 Gimbal lock,插值平滑(SLERP),组合简单(四元数乘法对应旋转复合)。

完成这一天后,你能做到:用四元数表达相机朝向,实现 mouse look 没有翻转,并能解释为什么四元数在游戏开发中是工业标配。

## 2 · 心智模型

### 类比:用魔方表达朝向

Euler 角(yaw, pitch, roll)像三根独立的转轴,你分别告诉魔方"绕 Y 转 30°,绕 X 转 20°,绕 Z 转 10°"。但顺序很重要——先 Y 后 X 转出的姿态和先 X 后 Y 不同。这是 Euler 角的根本缺陷:**它依赖顺序**。

四元数像"一根复合轴 + 一个角度"——你告诉魔方"绕 (1,2,3) 这个轴转 30°",这是 Euler 旋转定理:任何 3D 旋转都能用单轴 + 角度表达。

**直觉**:四元数把"旋转"看作一个数学对象(像复数扩展到 3 维),可以加、乘、求逆、插值。所有操作都连续,不会出现 Gimbal lock。

### 从 Euler 角到四元数:Gimbal Lock 的彻底剖析

要理解为什么四元数是工业标准,必须先彻底搞懂 Gimbal lock。让我用一个具体例子推导。

**Euler 角的旋转顺序约定**。最常见的是 yaw-pitch-roll(YXZ 顺序):先绕世界 Y 转 yaw,再绕新局部 X 转 pitch,最后绕新局部 Z 转 roll。这等价于矩阵乘法 `R = Ry(yaw) · Rx(pitch) · Rz(roll)`。

**Gimbal lock 发生的角度**:pitch = ±90°。让我推导当 pitch = 90° 时矩阵发生什么:

```
Rx(90°) = [1  0  0]   Ry(yaw) = [cy  0  sy]
          [0  0 -1]              [ 0  1   0]
          [0  1  0]              [-sy  0  cy]

Rz(roll) = [cz -sz  0]
           [sz  cz  0]
           [ 0   0  1]
```

矩阵相乘 `R = Ry(yaw) · Rx(90°) · Rz(roll)`,把矩阵乘开:

```
R = Ry(yaw) · Rx(90°) · Rz(roll)
  = Ry(yaw) · [1  0  0]   [cz -sz  0]
              [0  0 -1] · [sz  cz  0]
              [0  1  0]   [ 0   0  1]
```

先算 `Rx(90°) · Rz(roll)`:

```
= [1  0  0]   [cz -sz  0]   [cz    -sz   0]
  [0  0 -1] · [sz  cz  0] = [ 0     0   -1]
  [0  1  0]   [ 0   0  1]   [sz     cz   0]
```

注意第二行——本来 Z 轴应该有 roll 的影响,现在被"压平"了。继续乘 `Ry(yaw)`:

```
R = [cy  0  sy]   [cz -sz  0]
    [ 0   1   0] · [ 0  0  -1]
    [-sy 0  cy]   [sz  cz  0]

  = [cy·cz + sy·sz,  -cy·sz + sy·cz,  0]
    [     0,                0,         -1]
    [-sy·cz + cy·sz, sy·sz + cy·cz,    0]

  = [cos(yaw-roll),  sin(yaw-roll),  0]   (用和差化积)
    [     0,              0,         -1]
    [-sin(yaw-roll), cos(yaw-roll),   0]
```

**关键观察**:整个矩阵只依赖 `yaw - roll` 这个组合,**无法分辨 yaw 和 roll 的单独贡献**。物理上,这意味着无论你 yaw 转 30°+roll 转 0°,还是 yaw 转 0°+roll 转 -30°,结果是同一个旋转——**失去一个自由度**。这就是 Gimbal lock。

**操作上的灾难**:当玩家在 pitch = 89° 处移动鼠标左右,期望 yaw 变化。但 yaw 轴已经"对齐"到 roll 轴,鼠标左右实际控制的是(yaw - roll),玩家感受到的是"画面翻转"或"控制反了"。这就是 FPS 玩家偶尔在贴着天花板时镜头疯转的原因。

**四元数为什么没有这个问题**。四元数不存"yaw-pitch-roll"三个独立角度,它存"绕轴 (nx,ny,nz) 转 θ"。任何时刻,旋转都是单一轴 + 角度,**不存在三轴对齐的可能**。从四元数构造旋转矩阵 `R = qMat(q)`,矩阵永远是有效的正交矩阵,行列式 = 1,无奇异点。

让我从数学上证明这一点。单位四元数 `q = (sin(θ/2)·n, cos(θ/2))`,其中 n 是单位向量。从 q 解出 n 和 θ:

```
θ = 2 · acos(q.w)
n = q.xyz / sin(θ/2) = q.xyz / |q.xyz|
```

唯一有歧义的是 `q.xyz = 0`(零向量),此时 θ = 0,n 任意——但此时旋转就是单位矩阵,无奇异。

所以**四元数对所有 θ ∈ [0, 2π] 都有良好定义,不存在 Euler 角那种"自由度坍缩"的位置**。这就是 Gimbal lock 在四元数表达下自动消失的根本原因。

### 四元数的严谨定义

四元数 `q = w + xi + yj + zk`,其中 `i, j, k` 是三个虚单位,满足:

```
i² = j² = k² = -1
ij = k, jk = i, ki = j
ji = -k, kj = -i, ik = -j
```

在游戏里我们存成 `(x, y, z, w)` 四个 f32。**单位四元数**(长度=1)表达旋转:

```
旋转轴 n(单位向量),旋转角度 θ
q = (sin(θ/2) * n.x, sin(θ/2) * n.y, sin(θ/2) * n.z, cos(θ/2))
```

**关键性质**:
- 长度 `|q| = sqrt(x² + y² + z² + w²) = 1`(单位)
- 共轭 `q* = (-x, -y, -z, w)`
- 逆 `q⁻¹ = q* / |q|²`,对单位四元数 `q⁻¹ = q*`
- 乘法 `q1 * q2`(组合两个旋转,类似矩阵乘法)

**为什么四元数是 4 维而不是 3 维?** 直觉上,3D 旋转应该可以用 3 个数表达——但事实是,**3 个数无法表达所有 3D 旋转而不引入奇异点**。这是拓扑学的事实:3D 旋转群 SO(3) 的拓扑结构不允许用 3 个连续参数无奇异覆盖。

证明思路:3D 旋转集合在数学上等价于"实射影空间 RP³"——一个 3 维球面 S³ 把对径点(antipodal points)等同起来。S³ 是 4 维球面,但每个点 (x,y,z,w) 和 (-x,-y,-z,-w) 是同一旋转(这就是**双覆盖**)。所以最少需要 4 个数表达。

**双覆盖的意义**:`q` 和 `-q` 表达同一旋转。这看似冗余,实际是必须的——任何 3 个数的表达(Euler、轴-角等)都会有奇异点(Gimbal lock 就是 Euler 的奇异)。4 个数 + 单位约束是"无奇异覆盖"的最小代价。

**Hamilton product 推导**。四元数乘法 `q1 * q2` 来自虚单位的乘法规则:

```
i² = j² = k² = -1
ij = k, jk = i, ki = j  (循环)
ji = -k, kj = -i, ik = -j  (反向取负)
```

把 `q1 = w1 + x1 i + y1 j + z1 k` 和 `q2 = w2 + x2 i + y2 j + z2 k` 乘开,合并同类项:

```
q1·q2 = (w1 w2 - x1 x2 - y1 y2 - z1 z2)         ← 实部 w
      + (w1 x2 + x1 w2 + y1 z2 - z1 y2) i       ← x
      + (w1 y2 - x1 z2 + y1 w2 + z1 x2) j       ← y
      + (w1 z2 + x1 y2 - y1 x2 + z1 w2) k       ← z
```

这是 Hamilton product 公式。注意实部的"-x1x2-y1y2-z1z2"——这就是点积的负数。如果 `q1 = q2`,实部 = `w² - x² - y² - z²` = `2w² - 1`(因为 w² + x² + y² + z² = 1)。

**几何意义**:`q1 · q2` 表示"先 q2 再 q1"的复合旋转。注意**顺序**:`q1·q2 ≠ q2·q1`(除非共轴),这是 3D 旋转群的非交换性——和矩阵乘法一样。

### 四元数旋转点

要旋转点 `p = (px, py, pz)`:

```
1. 把 p 写成纯四元数:p' = (px, py, pz, 0)
2. 旋转后的点:p_rot = q * p' * q⁻¹
3. 取 p_rot 的 (x, y, z) 分量
```

**直觉**:这看起来很神秘,但本质是"用 q 把 p 包起来",共轭操作让结果仍然是纯四元数(实部 0)。可以证明这等价于"绕轴 n 旋转 θ"。

**实际计算**:游戏不直接算 `q * p * q⁻¹`(太慢),而是把四元数转成 3×3 旋转矩阵,然后用矩阵乘点。Rust 实现:

```rust
fn quat_to_matrix(q: Quat) -> [[f32; 3]; 3] {
    let (x, y, z, w) = (q.x, q.y, q.z, q.w);
    let xx = x*x; let yy = y*y; let zz = z*z;
    let xy = x*y; let xz = x*z; let yz = y*z;
    let wx = w*x; let wy = w*y; let wz = w*z;
    [
        [1.0 - 2.0*(yy+zz), 2.0*(xy-wz),       2.0*(xz+wy)],
        [2.0*(xy+wz),       1.0 - 2.0*(xx+zz), 2.0*(yz-wx)],
        [2.0*(xz-wy),       2.0*(yz+wx),       1.0 - 2.0*(xx+yy)],
    ]
}
```

每行解释:
- 这是单位四元数到旋转矩阵的标准公式。
- 对角线 `1 - 2(yy+zz)` 等是简化 `w² + x² - y² - z²`(因为 `w²+x²+y²+z² = 1`,可以化简)。
- 矩阵的 9 个元素直接由 (x,y,z,w) 算出,约 18 次乘加。

### Mouse Look 的四元数实现

```rust
struct Camera {
    orientation: Quat,  // 当前朝向(单位四元数)
    position: Vec3,
}

impl Camera {
    fn apply_mouse_look(&mut self, dx: f32, dy: f32) {
        let sensitivity = 0.003;
        // 鼠标左右移动 = 绕世界 Y 轴旋转
        let yaw_rot = Quat::from_axis_angle(Vec3::Y, -dx * sensitivity);
        // 鼠标上下移动 = 绕相机右方向(局部 X)旋转
        let right = self.orientation * Vec3::X;  // 当前右方向
        let pitch_rot = Quat::from_axis_angle(right, -dy * sensitivity);
        // 组合:先 yaw(世界系),再 pitch(局部系)
        self.orientation = pitch_rot * yaw_rot * self.orientation;
        // 重新归一化(浮点误差累积,定期归一化防漂移)
        self.orientation = self.orientation.normalize();
    }
    fn forward(&self) -> Vec3 {
        self.orientation * Vec3::new(0.0, 0.0, -1.0)  // -Z 是相机前方
    }
}
```

每行解释:
- `from_axis_angle(axis, angle)` — 构造绕 axis 转 angle 弧度的四元数。
- `Quat * Vec3` — 标准库(glam/nalgebra)把 Vec3 视为纯四元数,做 `q * v * q⁻¹`,返回旋转后的 Vec3。
- 乘法顺序:`pitch * yaw * orientation`,先 yaw(世界系)再 pitch(局部系),最后乘到当前 orientation。**顺序很重要**:四元数乘法不交换。
- `normalize()` — 强制 |q|=1。浮点运算会让长度慢慢漂移,定期归一化(每帧或每 N 帧)保证精度。

### 为什么没有 Gimbal lock

Euler 角的 Gimbal lock 来自"中间旋转把一个轴对齐到另一个轴"。比如先 yaw 90°,原本"局部 X"变成"世界 Z",后续 pitch 实际变成 roll。

四元数没有这个问题——它直接表达"绕一根轴转一个角度",不可能让两根轴对齐。任何朝向下,mouse look 的"绕世界 Y"和"绕局部右"都是真的绕这两个独立方向。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏里四元数的应用:

- **相机/玩家朝向**:本日主题,避免 Gimbal lock
- **骨骼动画**:每根骨头相对父骨头的旋转,四元数比矩阵省 4 倍内存
- **物理引擎**:刚体姿态、角速度积分,四元数避免奇异点
- **粒子旋转**:粒子朝向插值,SLERP 平滑
- **空间天文模拟**:卫星姿态控制,NASA 标准

工业坑:
- **四元数双覆盖**:`q` 和 `-q` 表达同一旋转。在做 SLERP 插值时,要先 `dot(q1, q2) < 0` 则 negate 一个,保证走最短路径。
- **累积误差**:每次乘法都让长度漂移,定期归一化。
- **优化**:很多计算不需要 explicit 四元数(如把 forward vector 缓存起来,避免每帧重算)。

### 3.2 · 图形学视角

图形学里四元数 vs 矩阵:

| 操作 | 四元数 | 3×3 矩阵 |
|---|---|---|
| 存储 | 16 字节(4f32) | 36 字节(9f32) |
| 组合(乘) | 16 乘 + 12 加 | 27 乘 + 18 加 |
| 应用到点 | ~30 操作(转矩阵再乘) | 9 乘 + 6 加 |
| 插值 | SLERP 简洁 | 矩阵插值不闭合 |
| Gimbal lock | 无 | 无(直接用矩阵) |
| 数值稳定 | 优(归一化即可) | 良(正交化复杂) |

**结论**:
- 多次组合旋转 → 四元数
- 单次应用大量点 → 矩阵
- 插值动画 → 四元数

实际渲染时把四元数转矩阵,统一进 GPU。

**进阶**:对偶四元数(dual quaternion)表达"旋转 + 平移",用于骨骼蒙皮。Spherical cubic interpolation(SQUAD)是 SLERP 的 cubic 版,更平滑。

### 3.4 · Rust 生态视角

Rust 数学库对四元数的支持:

**A. `glam`**(推荐,游戏优化):

```rust
use glam::{Quat, Vec3};

let q = Quat::from_axis_angle(Vec3::Y, std::f32::consts::FRAC_PI_2);
let v = q * Vec3::X;  // 旋转 X 轴绕 Y 转 90°,得 Z 轴
```

- SIMD 优化(4 个 f32 装进一个 128-bit 寄存器)
- API 简洁

**B. `nalgebra`**(科学计算):

```rust
use nalgebra::{Quaternion, UnitQuaternion, Vector3};

let q = UnitQuaternion::from_axis_angle(&Vector3::y_axis(), std::f32::consts::FRAC_PI_2);
let v = q * Vector3::x();
```

- 更严格(单位四元数用 `UnitQuaternion` 类型保证)
- 但 API 啰嗦

**C. 手写**(像 Casey):

```rust
#[derive(Copy, Clone, Debug)]
struct Quat { x: f32, y: f32, z: f32, w: f32 }

impl Quat {
    fn identity() -> Self { Self { x: 0.0, y: 0.0, z: 0.0, w: 1.0 } }
    fn from_axis_angle(axis: Vec3, angle: f32) -> Self {
        let half = angle * 0.5;
        let s = half.sin();
        Self {
            x: axis.x * s, y: axis.y * s, z: axis.z * s,
            w: half.cos(),
        }
    }
    fn mul(self, other: Self) -> Self {
        // Hamilton product
        Self {
            x: self.w*other.x + self.x*other.w + self.y*other.z - self.z*other.y,
            y: self.w*other.y - self.x*other.z + self.y*other.w + self.z*other.x,
            z: self.w*other.z + self.x*other.y - self.y*other.x + self.z*other.w,
            w: self.w*other.w - self.x*other.x - self.y*other.y - self.z*other.z,
        }
    }
    fn normalize(self) -> Self {
        let len = (self.x*self.x + self.y*self.y + self.z*self.z + self.w*self.w).sqrt();
        Self {
            x: self.x/len, y: self.y/len, z: self.z/len, w: self.w/len,
        }
    }
}
```

每行注释:
- `identity()` — 单位四元数,表示"不旋转"。
- `from_axis_angle` — 用半角公式构造,因为四元数表达"双倍角"。
- `mul` — Hamilton product,四元数乘法的标准公式。看起来复杂,但对称。**乘法顺序**:`a * b` 表示"先 b 后 a"。
- `normalize` — 强制单位长度。

| 游戏 | 四元数 | 平滑插值,无 Gimbal lock |
| 机器人 | Euler 角(DH 参数) | 直观,机械关节是 Euler 的 |
| 物理 | 轴-角 / Rodrigues | 积分友好 |
| 航空 | Euler 角(yaw-pitch-roll) | 历史悠久,飞行员理解 |
| 数学/物理 | 李代数 so(3) | 理论分析 |

**历史**:
- 1843:Hamilton 发明四元数(刻在都柏林桥上)
- 1985:Shoemake 引入图形学(SIGGRAPH)
- 2000s:四元数成为游戏标配
- 2010s:对偶四元数用于蒙皮

**SLERP 公式**:
```
slerp(q1, q2, t) = sin((1-t)θ) / sin(θ) * q1 + sin(tθ) / sin(θ) * q2
```
其中 `θ = acos(q1 · q2)`。当 θ 接近 0 时,LERP 即可(避免除零)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么四元数没有 Gimbal lock,而 Euler 角有?给出几何直觉。

**参考解答**:Euler 角的 Gimbal lock 来自"三个旋转依次作用,中间旋转可能把一个轴对齐到另一个"。比如 yaw 90° 后,原本局部 X 轴变成世界 Z 轴,此时再 pitch 实际是绕世界 Z 轴 = roll,失去自由度。

四元数表达"绕单一轴转一个角度",没有"中间对齐"的概念。任何四元数对应一个明确的旋转轴 + 角度,不可能让两根世界轴融合。

**直觉**:Euler 像三根独立转轴,可能互相干扰;四元数像一根任意方向转轴,永远只有一个方向。

### Lv2 · 动手实践

**题**:在 Rust 里实现四元数,从 Euler 角构造,验证 Gimbal lock 消失。具体测试:把 pitch 设为 89°,再设为 91°,相机应该平滑过渡,不翻转。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Quat { x: f32, y: f32, z: f32, w: f32 }

impl Quat {
    fn identity() -> Self { Self { x: 0.0, y: 0.0, z: 0.0, w: 1.0 } }
    fn from_axis_angle(ax: (f32,f32,f32), angle: f32) -> Self {
        let len = (ax.0*ax.0 + ax.1*ax.1 + ax.2*ax.2).sqrt();
        let (nx, ny, nz) = (ax.0/len, ax.1/len, ax.2/len);
        let half = angle * 0.5;
        let s = half.sin();
        Self { x: nx*s, y: ny*s, z: nz*s, w: half.cos() }
    }
    fn mul(self, o: Self) -> Self {
        Self {
            x: self.w*o.x + self.x*o.w + self.y*o.z - self.z*o.y,
            y: self.w*o.y - self.x*o.z + self.y*o.w + self.z*o.x,
            z: self.w*o.z + self.x*o.y - self.y*o.x + self.z*o.w,
            w: self.w*o.w - self.x*o.x - self.y*o.y - self.z*o.z,
        }
    }
    fn rotate_vec(self, v: (f32,f32,f32)) -> (f32,f32,f32) {
        // 公式 v' = v + 2*cross(q.xyz, cross(q.xyz, v) + q.w*v)
        let (qx, qy, qz, qw) = (self.x, self.y, self.z, self.w);
        // cross(q.xyz, v)
        let cv_x = qy*v.2 - qz*v.1;
        let cv_y = qz*v.0 - qx*v.2;
        let cv_z = qx*v.1 - qy*v.0;
        // cross(q.xyz, v) + q.w*v
        let u_x = cv_x + qw*v.0;
        let u_y = cv_y + qw*v.1;
        let u_z = cv_z + qw*v.2;
        // cross(q.xyz, u)
        let cu_x = qy*u_z - qz*u_y;
        let cu_y = qz*u_x - qx*u_z;
        let cu_z = qx*u_y - qy*u_x;
        (v.0 + 2.0*cu_x, v.1 + 2.0*cu_y, v.2 + 2.0*cu_z)
    }
}

fn main() {
    // Pitch 89° 和 91°,验证相机 forward 平滑
    let q1 = Quat::from_axis_angle((1.0, 0.0, 0.0), 89.0_f32.to_radians());
    let q2 = Quat::from_axis_angle((1.0, 0.0, 0.0), 91.0_f32.to_radians());

    let forward = (0.0, 0.0, -1.0);
    let f1 = q1.rotate_vec(forward);
    let f2 = q2.rotate_vec(forward);

    println!("Pitch 89° forward: ({:.4}, {:.4}, {:.4})", f1.0, f1.1, f1.2);
    println!("Pitch 91° forward: ({:.4}, {:.4}, {:.4})", f2.0, f2.1, f2.2);
    // 89°: forward 应该几乎指向上方但稍前
    // 91°: forward 应该几乎指向上方但稍后(过头顶)
    // 没有 Euler 角的"翻转"现象
}
```

每行解释:
- `from_axis_angle((1,0,0), angle)` — 绕 X 轴转 angle(就是 pitch)。
- `rotate_vec` 用了优化公式 `v' = v + 2 cross(q.xyz, cross(q.xyz, v) + q.w v)`,比 `q * v * q⁻¹` 快。
- 89° 时 forward ≈ (0, -0.9998, -0.017)(几乎朝上稍偏前);91° 时 forward ≈ (0, -0.9998, +0.017)(几乎朝上稍偏后)。两者平滑过渡,没有突变。

### Lv3 · 迁移设计

**题**:实现 SLERP(球面线性插值),在两个朝向之间平滑过渡。给两个朝向 `q1`、`q2`,t ∈ [0,1],返回中间朝向。**提示**:
- `cos_theta = q1 · q2`(四元数点积)
- 如果 `cos_theta < 0`,negate `q2`,走最短路径
- 如果 `cos_theta > 0.9995`,直接 LERP + 归一化(避免除以 sin(0))
- 否则 `slerp = (sin((1-t)θ)/sin θ) q1 + (sin(tθ)/sin θ) q2`,θ = acos(cos_theta)

```rust
use std::f32::consts::PI;

#[derive(Copy, Clone, Debug)]
struct Quat { x: f32, y: f32, z: f32, w: f32 }

impl Quat {
    fn identity() -> Self { Self { x:0.0, y:0.0, z:0.0, w:1.0 } }
    fn from_axis_angle(ax: (f32,f32,f32), angle: f32) -> Self {
        let len = (ax.0*ax.0 + ax.1*ax.1 + ax.2*ax.2).sqrt();
        let (nx, ny, nz) = (ax.0/len, ax.1/len, ax.2/len);
        let half = angle * 0.5;
        let s = half.sin();
        Self { x: nx*s, y: ny*s, z: nz*s, w: half.cos() }
    }
    fn mul(self, o: Self) -> Self {
        Self {
            x: self.w*o.x + self.x*o.w + self.y*o.z - self.z*o.y,
            y: self.w*o.y - self.x*o.z + self.y*o.w + self.z*o.x,
            z: self.w*o.z + self.x*o.y - self.y*o.x + self.z*o.w,
            w: self.w*o.w - self.x*o.x - self.y*o.y - self.z*o.z,
        }
    }
    fn normalize(self) -> Self {
        let len2 = self.x*self.x + self.y*self.y + self.z*self.z + self.w*self.w;
        let len = len2.sqrt();
        Self { x: self.x/len, y: self.y/len, z: self.z/len, w: self.w/len }
    }
    fn rotate_vec3(self, v: (f32,f32,f32)) -> (f32,f32,f32) {
        let (qx,qy,qz,qw) = (self.x,self.y,self.z,self.w);
        let cv = (qy*v.2 - qz*v.1, qz*v.0 - qx*v.2, qx*v.1 - qy*v.0);
        let u = (cv.0 + qw*v.0, cv.1 + qw*v.1, cv.2 + qw*v.2);
        let cu = (qy*u.2 - qz*u.1, qz*u.0 - qx*u.2, qx*u.1 - qy*u.0);
        (v.0 + 2.0*cu.0, v.1 + 2.0*cu.1, v.2 + 2.0*cu.2)
    }
}

struct Camera {
    orientation: Quat,
}

impl Camera {
    fn new() -> Self { Self { orientation: Quat::identity() } }
    fn apply_mouse(&mut self, dx: f32, dy: f32) {
        let s = 0.003;
        // 绕世界 Y 转 dx
        let yaw = Quat::from_axis_angle((0.0, 1.0, 0.0), -dx * s);
        // 当前右方向(从 orientation 变换 (1,0,0))
        let right = self.orientation.rotate_vec3((1.0, 0.0, 0.0));
        let pitch = Quat::from_axis_angle(right, -dy * s);
        // 组合
        self.orientation = (pitch.mul(yaw)).mul(self.orientation).normalize();
    }
    fn forward(&self) -> (f32,f32,f32) {
        self.orientation.rotate_vec3((0.0, 0.0, -1.0))
    }
}

fn main() {
    let mut cam = Camera::new();
    // 模拟连续鼠标移动:绕一圈,然后上下打转
    let moves = [
        (100.0, 0.0),    // 大幅向右
        (0.0, 50.0),     // 向上
        (0.0, 50.0),     // 继续向上(过头顶)
        (0.0, 50.0),     // 再向上
        (-100.0, 0.0),   // 向左
    ];
    let mut step = 0;
    for (dx, dy) in moves {
        cam.apply_mouse(dx, dy);
        let f = cam.forward();
        println!("Step {}: forward = ({:+.3}, {:+.3}, {:+.3})", step, f.0, f.1, f.2);
        step += 1;
    }
    println!("At no point should forward 'flip' (sudden sign change).");
}
```
