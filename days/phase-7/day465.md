让我把"二进制格式迁移"的工程原则讲清楚,这是 Day 465 的核心。

**迁移的根本难题**。格式升级时,你有 N 个旧文件、M 个用户(或开发者)依赖这些文件。简单"换格式"会 break 所有依赖——用户重新生成所有资产。

迁移工具的目的:**自动转换旧文件到新格式**,让用户无感升级。

```bash
# Casey HH 的迁移
./hha_migrate old_v0.hha > new_v1.hha
# 或批量
for f in assets/*.hha; do
    ./hha_migrate "$f" > "${f%.hha}.v1.hha"
done
```

**迁移的实现**。读 V0 格式,转 V1 内存结构,写 V1 格式:

```rust
fn migrate_v0_to_v1(v0_data: &[u8]) -> Result<Vec<u8>> {
    let v0 = parse_hha_v0(v0_data)?;
    let mut v1 = HhaV1 {
        version: 1,
        ..Default::default()
    };
    
    // 转换 asset table
    for v0_asset in &v0.assets {
        let v1_asset = AssetEntryV1 {
            id: v0_asset.id,
            kind: convert_kind_v0_to_v1(v0_asset.kind),
            // 加 V1 新字段(默认值)
            ..Default::default()
        };
        v1.assets.push(v1_asset);
    }
    
    // 转换 tag table(可能需要补充 V1 新 tag)
    // ...
    
    // 序列化 V1
    Ok(serialize_hha_v1(&v1))
}

fn convert_kind_v0_to_v1(kind_v0: u32) -> AssetKindV1 {
    match kind_v0 {
        0 => AssetKindV1::Bitmap,
        1 => AssetKindV1::Sound,
        2 => AssetKindV1::Font,
        _ => AssetKindV1::Unknown,
    }
}
```

**字段映射**。V0 → V1 字段对应可能:

- **直接复制**:ID、宽高、像素数据不变
- **类型转换**:u16 → u32(扩展范围)
- **默认值填充**:V1 新字段没有 V0 对应,用默认值
- **重组**:某些字段在 V0 是 inline,V1 是 offset table

每个字段单独处理。Casey 在 Day 465 视频里逐字段做这个,展示如何系统化迁移。

**完整性校验**。迁移后验证:

1. **CRC**:V1 加 CRC,V0 没有。迁移时算 CRC 写入。
2. **Asset count**:V0 和 V1 的 asset 数应该一样
3. **Asset ID 唯一性**:V1 里所有 ID 不能重复
4. **像素数据完整性**:V0 的像素 → V1 的像素,字节相同

测试:

```rust
#[test]
fn migrate_preserves_pixel_data() {
    let v0 = generate_test_hha_v0(/* ... */);
    let v1 = migrate_v0_to_v1(&v0).unwrap();
    
    let v0_parsed = parse_hha_v0(&v0).unwrap();
    let v1_parsed = parse_hha_v1(&v1).unwrap();
    
    for (a0, a1) in v0_parsed.assets.iter().zip(v1_parsed.assets.iter()) {
        assert_eq!(a0.width, a1.width);
        assert_eq!(a0.height, a1.height);
        let pixels_0 = extract_pixels(&v0, a0);
        let pixels_1 = extract_pixels(&v1, a1);
        assert_eq!(pixels_0, pixels_1);  // 像素必须一样
    }
}
```

**线性 vs 增量迁移**。两种策略:

- **线性**:V0 → V1 → V2 → V3,每次升级一级
- **跳级**:V0 → V3,直接跳到最新

线性更简单(每次迁移代码小),跳级更快(不用多次序列化)。Casey HH 单步迁移(V0 → V1)是线性。商业系统(Unity、Unreal)维护所有版本的迁移函数,V(n) → V(n+1),然后链式调用做 V0 → V5。

## 补充:资产管线的 CI/CD 集成

Day 465 的资产管线应该接入 CI/CD,让"美术 push 资产 → 自动构建 HHA"流程化。这是工业级 asset pipeline 的标志。

**典型 CI/CD 流程**:

```yaml
# .github/workflows/assets.yml
name: Build Assets
on:
  push:
    paths:
      - 'assets/**'  # 只在资产变化时触发
      - 'tools/asset_importer/**'

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true  # 大文件用 Git LFS
      
      - name: Build importer
        run: cargo build --release --bin asset_importer
      
      - name: Import all assets
        run: |
          for src in assets/*.png assets/*.wav; do
            ./target/release/asset_importer "$src" >> build/assets.hha
          done
      
      - name: Verify HHA
        run: ./target/release/hha_verify build/assets.hha
      
      - name: Upload artifact
        uses: actions/upload-artifact@v3
        with:
          name: game-assets
          path: build/assets.hha
      
      - name: Compute hash
        run: sha256sum build/assets.hha > build/assets.hha.sha256
```

每次美术 push 新 PNG,CI 自动:

1. 跑 importer,生成新 HHA
2. 验证 HHA(完整性 + asset count)
3. 上传 HHA 为 artifact
4. 计算 SHA256(用于下载验证)

**版本化资产**。资产应该和代码一起版本化——git LFS 存大文件,普通 git 存代码。每次 release 时,资产和代码打同一 tag:

```rust
fn diff_hha(old: &HhaFile, new: &HhaFile) -> HhaDiff {
    let added: Vec<_> = new.assets.iter()
        .filter(|a| !old.assets.iter().any(|o| o.id == a.id))
        .collect();
    let removed: Vec<_> = old.assets.iter()
        .filter(|o| !new.assets.iter().any(|a| a.id == o.id))
        .collect();
    let modified: Vec<_> = new.assets.iter()
        .filter(|a| old.assets.iter().any(|o| o.id == a.id && o.data_size != a.data_size))
        .collect();
    HhaDiff { added, removed, modified }
}
```

资产 diff 让你看到"这次更新改了哪些资产",决定是否要发新 release。

## 2 · 心智模型

### 类比:房屋装修

V0 房子住了一段时间,要重装(V1)。装修期间住户要继续住(数据不丢)。装修策略:

- **逐步迁移**:一间一间装(本日做法,完全转换)
- **并行居住**:V0 和 V1 同时存在,逐步替换(不推荐,维护双份代码)
- **大爆炸**:一次性切换(风险高,如果出问题回滚困难)

工程上选"逐步迁移",风险最低。

### V0 vs V1 字段对比

| 字段 | V0 | V1 |
|---|---|---|
| Magic | "HHA0" | "HHA1" |
| Version | 0 | 1 |
| CRC | 无 | 有(文件级) |
| String | null-terminated | length-prefix |
| Type | 4 字节 | 2 字节 |
| Deps | 无 | 有 |
| Asset CRC | 无 | 有(每 asset) |

### V0 解析器

```rust
struct HhaV0Header {
    magic: [u8; 4],
    version: u32,
}

struct HhaV0Tag {
    name: String,
}

struct HhaV0Asset {
    type_code: u32,
    name: String,
    data_offset: u32,
    data_size: u32,
}

struct HhaV0 {
    header: HhaV0Header,
    tags: Vec<HhaV0Tag>,
    assets: Vec<HhaV0Asset>,
    data: Vec<u8>,  // 整个 data 块
}

fn parse_v0(data: &[u8]) -> Result<HhaV0, String> {
    let mut cursor = 0;
    
    // Magic
    let mut magic = [0u8; 4];
    magic.copy_from_slice(&data[cursor..cursor+4]);
    cursor += 4;
    if &magic != b"HHA0" { return Err(format!("bad magic: {:?}", magic)); }
    
    // Version
    let version = read_u32_le(data, &mut cursor)?;
    
    // Tags
    let tag_count = read_u32_le(data, &mut cursor)? as usize;
    let mut tags = Vec::with_capacity(tag_count);
    for _ in 0..tag_count {
        // V0: null-terminated
        let start = cursor;
        while cursor < data.len() && data[cursor] != 0 { cursor += 1; }
        let name = String::from_utf8(data[start..cursor].to_vec())
            .map_err(|_| "bad utf8")?;
        cursor += 1;  // skip null
        tags.push(HhaV0Tag { name });
    }
    
    // Assets
    let asset_count = read_u32_le(data, &mut cursor)? as usize;
    let mut assets = Vec::with_capacity(asset_count);
    for _ in 0..asset_count {
        let type_code = read_u32_le(data, &mut cursor)?;
        let name_start = cursor;
        while cursor < data.len() && data[cursor] != 0 { cursor += 1; }
        let name = String::from_utf8(data[name_start..cursor].to_vec())
            .map_err(|_| "bad utf8")?;
        cursor += 1;
        let data_offset = read_u32_le(data, &mut cursor)?;
        let data_size = read_u32_le(data, &mut cursor)?;
        assets.push(HhaV0Asset { type_code, name, data_offset, data_size });
    }
    
    // Data 块
    let data = data[cursor..].to_vec();
    
    Ok(HhaV0 {
        header: HhaV0Header { magic, version },
        tags, assets, data,
    })
}

fn read_u32_le(data: &[u8], cursor: &mut usize) -> Result<u32, String> {
    if *cursor + 4 > data.len() { return Err("EOF".into()); }
    let v = u32::from_le_bytes([data[*cursor], data[*cursor+1], data[*cursor+2], data[*cursor+3]]);
    *cursor += 4;
    Ok(v)
}
```

每行解释:
- `read_u32_le` 抽出读 LE u32 模式。
- V0 字符串 null-terminated,while 循环找 \0。
- data 块是文件剩余部分(包含所有 asset 的实际像素数据)。

### V1 序列化器

```rust
fn write_v1(v0: &HhaV0) -> Vec<u8> {
    let mut out = Vec::new();
    
    // Header
    out.extend_from_slice(b"HHA1");
    out.extend_from_slice(&1u32.to_le_bytes());  // version
    out.extend_from_slice(&0u32.to_le_bytes());  // CRC placeholder
    
    // Tags
    out.extend_from_slice(&(v0.tags.len() as u32).to_le_bytes());
    for tag in &v0.tags {
        out.extend_from_slice(&(tag.name.len() as u32).to_le_bytes());
        out.extend_from_slice(tag.name.as_bytes());
    }
    
    // Assets
    out.extend_from_slice(&(v0.assets.len() as u32).to_le_bytes());
    for asset in &v0.assets {
        // name length-prefixed
        out.extend_from_slice(&(asset.name.len() as u32).to_le_bytes());
        out.extend_from_slice(asset.name.as_bytes());
        // type 2 字节(V1 改进)
        out.extend_from_slice(&(asset.type_code as u16).to_le_bytes());
        // data offset 和 size 不变
        out.extend_from_slice(&asset.data_offset.to_le_bytes());
        out.extend_from_slice(&asset.data_size.to_le_bytes());
        // V1 加 asset CRC(可选)
        let crc = crc32(&v0.data[asset.data_offset as usize..(asset.data_offset + asset.data_size) as usize]);
        out.extend_from_slice(&crc.to_le_bytes());
    }
    
    // Data 块
    out.extend_from_slice(&v0.data);
    
    // 最后填文件 CRC
    let mut for_crc = out.clone();
    for_crc[8..12].copy_from_slice(&0u32.to_le_bytes());
    let file_crc = crc32(&for_crc);
    out[8..12].copy_from_slice(&file_crc.to_le_bytes());
    
    out
}
```

每行解释:
- 标签和资产用 length-prefix 字符串(V1 改进)。
- type code 2 字节(V0 是 4 字节,V1 减半)。
- 每 asset 加 CRC(检测单个 asset 损坏)。
- 文件级 CRC 最后填。

### 迁移工具主逻辑

```rust
fn migrate_dir(input_dir: &str, output_dir: &str) -> Result<usize, String> {
    std::fs::create_dir_all(output_dir).map_err(|e| e.to_string())?;
    let mut count = 0;
    
    for entry in std::fs::read_dir(input_dir).map_err(|e| e.to_string())? {
        let entry = entry.map_err(|e| e.to_string())?;
        let path = entry.path();
        
        if path.extension().and_then(|e| e.to_str()) != Some("hha") {
            continue;
        }
        
        let data = std::fs::read(&path).map_err(|e| e.to_string())?;
        
        // 检测版本
        if data.len() < 8 { continue; }
        let magic = &data[..4];
        if magic == b"HHA0" {
            let v0 = parse_v0(&data)?;
            let v1_bytes = write_v1(&v0);
            let out_path = std::path::Path::new(output_dir)
                .join(path.file_name().unwrap());
            std::fs::write(&out_path, v1_bytes).map_err(|e| e.to_string())?;
            println!("Migrated: {} → {}", path.display(), out_path.display());
            count += 1;
        } else if magic == b"HHA1" {
            println!("Already V1: {}", path.display());
        } else {
            eprintln!("Unknown format: {}", path.display());
        }
    }
    
    Ok(count)
}
```

每行解释:
- 扫描目录找 .hha 文件。
- 看 magic 决定 V0 还是 V1。
- V0 → 解析 → 写 V1 到输出目录。
- V1 跳过(已迁移)。

### 端到端验证

```rust
fn verify_hha_v1(path: &str) -> Result<(), String> {
    let data = std::fs::read(path).map_err(|e| e.to_string())?;
    
    if data.len() < 12 { return Err("too short".into()); }
    if &data[..4] != b"HHA1" { return Err("not HHA1".into()); }
    
    let stored_crc = u32::from_le_bytes([data[8], data[9], data[10], data[11]]);
    let mut for_crc = data.clone();
    for_crc[8..12].copy_from_slice(&0u32.to_le_bytes());
    let computed_crc = crc32(&for_crc);
    
    if stored_crc != computed_crc {
        return Err(format!("CRC mismatch: stored {:08x}, computed {:08x}",
            stored_crc, computed_crc));
    }
    
    println!("V1 file {}: OK (CRC match)", path);
    Ok(())
}
```

每行解释:
- 重算文件 CRC,和存储的对比。
- 一致 = 文件未损坏。

## 3 · 四域深入

### 3.1 · 游戏编程视角

资产格式演化是工业游戏常态:

- **Unreal**:每版本(5.0、5.1、5.2)都升级 .uasset 格式
- **Unity**:每个 LTS 版本资产格式可能变化
- **Casey HH**:V0 → V1 一次性升级

迁移策略:
- **大爆炸**:Casey 选(一次性换)
- **渐进**:Unreal 选(版本号兼容 N-1)
- **混合**:Unity 选(老版本可读,新版本写入新格式)

**为什么 Casey 选大爆炸?** HH 是个人项目,没有外部用户依赖 V0。商业游戏必须渐进——玩家存档、社区 mod 都依赖格式稳定。

### 3.2 · 图形学视角

格式演化的图形学维度:

- **新压缩格式**:BC1 → BC7 → ASTC → Basis Universal
- **新维度**:2D 纹理 → 3D 纹理 → 纹理数组
- **新元数据**:sRGB 标志、premultiplied alpha、ICCP profile

每次升级要么 breaking change(版本 +1),要么加 chunk(PNG 风格,向后兼容)。

### 3.3 · Linux 系统编程视角

Linux 的"格式迁移"工具:

- **`ext2 → ext3 → ext4`**:`tune2fs -j`(向上兼容,加 journal)
- **`/etc/passwd → shadow`**:迁移到更安全的格式
- **systemd init**:从 init.d 迁移到 unit files

每个都有迁移工具,保证平滑升级。

```bash
# ext2 → ext3(加 journal)
tune2fs -j /dev/sda1

# /etc/passwd → shadow(历史迁移,已完成)
# 现代 Linux 都用 shadow
```

### 3.4 · Rust 生态视角

Rust 处理多版本格式:

```rust
enum HhaVersion {
    V0(HhaV0),
    V1(HhaV1),
}

fn parse(data: &[u8]) -> Result<HhaVersion, String> {
    if data.len() < 4 { return Err("too short".into()); }
    match &data[..4] {
        b"HHA0" => Ok(HhaVersion::V0(parse_v0(data)?)),
        b"HHA1" => Ok(HhaVersion::V1(parse_v1(data)?)),
        _ => Err("unknown".into()),
    }
}
```

每行解释:
- 用 enum 包装多版本,Rust 的强大表达力。
- 上层代码 `match` 处理各版本。
- 类似于 `serde` 的 versioned deserialization。

## 4 · 认知地图

### 4.1 上级

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 V1 加 CRC 让格式"更安全",但 V0 没有 CRC 也能工作?

**参考解答**:V0 没有 CRC 意味着文件损坏不易检测——玩家下载的 .hha 可能传输中部分字节翻转,加载时崩溃或表现异常。CRC 让加载器第一时间拒绝损坏文件,而不是产生神秘 bug。

V0 没有 CRC 是简化设计(早期 Casey 优先功能)。V1 加 CRC 是"工程成熟"——开始重视鲁棒性。

## 8 · Rust / Arch 落地代码

完整迁移工具:

```rust
use std::fs;
use std::path::{Path, PathBuf};

fn crc32(data: &[u8]) -> u32 {
    let mut crc: u32 = 0xFFFFFFFF;
    for &b in data {
        crc ^= b as u32;
        for _ in 0..8 {
            crc = if crc & 1 != 0 { 0xEDB88320 ^ (crc >> 1) } else { crc >> 1 };
        }
    }
    crc ^ 0xFFFFFFFF
}

fn read_u32_le(data: &[u8], cursor: &mut usize) -> Result<u32, String> {
    if *cursor + 4 > data.len() { return Err("EOF".into()); }
    let v = u32::from_le_bytes([data[*cursor], data[*cursor+1], data[*cursor+2], data[*cursor+3]]);
    *cursor += 4;
    Ok(v)
}

fn read_null_string(data: &[u8], cursor: &mut usize) -> Result<String, String> {
    let start = *cursor;
    while *cursor < data.len() && data[*cursor] != 0 { *cursor += 1; }
    let s = String::from_utf8(data[start..*cursor].to_vec()).map_err(|_| "bad utf8")?;
    *cursor += 1;
    Ok(s)
}

#[derive(Debug)]
struct HhaV0 {
    version: u32,
    tags: Vec<String>,
    assets: Vec<(u32, String, u32, u32)>,  // (type, name, data_offset, data_size)
    data: Vec<u8>,
}

fn parse_v0(data: &[u8]) -> Result<HhaV0, String> {
    let mut cursor = 0;
    if &data[..4] != b"HHA0" { return Err("bad magic".into()); }
    cursor = 4;
    let version = read_u32_le(data, &mut cursor)?;
    let tag_count = read_u32_le(data, &mut cursor)? as usize;
    let mut tags = Vec::with_capacity(tag_count);
    for _ in 0..tag_count {
        tags.push(read_null_string(data, &mut cursor)?);
    }
    let asset_count = read_u32_le(data, &mut cursor)? as usize;
    let mut assets = Vec::with_capacity(asset_count);
    for _ in 0..asset_count {
        let type_code = read_u32_le(data, &mut cursor)?;
        let name = read_null_string(data, &mut cursor)?;
        let data_offset = read_u32_le(data, &mut cursor)?;
        let data_size = read_u32_le(data, &mut cursor)?;
        assets.push((type_code, name, data_offset, data_size));
    }
    let data_block = data[cursor..].to_vec();
    Ok(HhaV0 { version, tags, assets, data: data_block })
}

fn write_v1(v0: &HhaV0) -> Vec<u8> {
    let mut out = Vec::new();
    out.extend_from_slice(b"HHA1");
    out.extend_from_slice(&1u32.to_le_bytes());
    out.extend_from_slice(&0u32.to_le_bytes());  // CRC placeholder
    
    out.extend_from_slice(&(v0.tags.len() as u32).to_le_bytes());
    for tag in &v0.tags {
        out.extend_from_slice(&(tag.len() as u32).to_le_bytes());
        out.extend_from_slice(tag.as_bytes());
    }
    
    out.extend_from_slice(&(v0.assets.len() as u32).to_le_bytes());
    for (type_code, name, offset, size) in &v0.assets {
        out.extend_from_slice(&(name.len() as u32).to_le_bytes());
        out.extend_from_slice(name.as_bytes());
        out.extend_from_slice(&(*type_code as u16).to_le_bytes());
        out.extend_from_slice(&offset.to_le_bytes());
        out.extend_from_slice(&size.to_le_bytes());
        // Asset CRC(V1 新增)
        let start = *offset as usize;
        let end = start + *size as usize;
        let crc = if end <= v0.data.len() {
            crc32(&v0.data[start..end])
        } else { 0 };
        out.extend_from_slice(&crc.to_le_bytes());
    }
    
    out.extend_from_slice(&v0.data);
    
    // 文件 CRC
    let mut for_crc = out.clone();
    for_crc[8..12].copy_from_slice(&0u32.to_le_bytes());
    let file_crc = crc32(&for_crc);
    out[8..12].copy_from_slice(&file_crc.to_le_bytes());
    out
}

fn make_test_v0() -> Vec<u8> {
    let mut v0 = Vec::new();
    v0.extend_from_slice(b"HHA0");
    v0.extend_from_slice(&0u32.to_le_bytes());  // version
    v0.extend_from_slice(&2u32.to_le_bytes());  // tag count
    v0.extend_from_slice(b"hero\0");
    v0.extend_from_slice(b"enemy\0");
    v0.extend_from_slice(&2u32.to_le_bytes());  // asset count
    
    // Asset 0: hero bitmap
    v0.extend_from_slice(&0u32.to_le_bytes());  // type=0
    v0.extend_from_slice(b"hero_bitmap\0");
    v0.extend_from_slice(&0u32.to_le_bytes());  // data_offset
    v0.extend_from_slice(&4u32.to_le_bytes());  // data_size
    // Asset 1: enemy bitmap
    v0.extend_from_slice(&0u32.to_le_bytes());
    v0.extend_from_slice(b"enemy_bitmap\0");
    v0.extend_from_slice(&4u32.to_le_bytes());
    v0.extend_from_slice(&4u32.to_le_bytes());
    
    // Data block
    v0.extend_from_slice(&[0xAA, 0xBB, 0xCC, 0xDD, 0x11, 0x22, 0x33, 0x44]);
    
    v0
}

fn main() {
    // 构造 V0 文件
    let v0_bytes = make_test_v0();
    println!("V0 file: {} bytes", v0_bytes.len());
    fs::write("/tmp/test_v0.hha", &v0_bytes).unwrap();
    
    // 解析 V0
    let v0 = parse_v0(&v0_bytes).expect("parse V0");
    println!("Parsed V0: version={}, {} tags, {} assets, {} data bytes",
        v0.version, v0.tags.len(), v0.assets.len(), v0.data.len());
    for (i, (t, n, o, s)) in v0.assets.iter().enumerate() {
        println!("  Asset {}: type={}, name='{}', offset={}, size={}", i, t, n, o, s);
    }
    
    // 迁移到 V1
    let v1_bytes = write_v1(&v0);
    println!("\nV1 file: {} bytes", v1_bytes.len());
    fs::write("/tmp/test_v1.hha", &v1_bytes).unwrap();
    
    // 验证 V1
    let stored_crc = u32::from_le_bytes(v1_bytes[8..12].try_into().unwrap());
    let mut for_crc = v1_bytes.clone();
    for_crc[8..12].copy_from_slice(&0u32.to_le_bytes());
    let computed = crc32(&for_crc);
    println!("V1 CRC: stored 0x{:08x}, computed 0x{:08x}, match={}",
        stored_crc, computed, stored_crc == computed);
    
    // 模拟损坏
    let mut corrupted = v1_bytes.clone();
    corrupted[20] ^= 0xFF;
    let stored_crc2 = u32::from_le_bytes(corrupted[8..12].try_into().unwrap());
    let mut for_crc2 = corrupted.clone();
    for_crc2[8..12].copy_from_slice(&0u32.to_le_bytes());
    let computed2 = crc32(&for_crc2);
    println!("\nCorrupted file CRC: stored 0x{:08x}, computed 0x{:08x}, match={}",
        stored_crc2, computed2, stored_crc2 == computed2);
    println!("(CRC mismatch = corruption detected, as expected)");
}
```

每行解释:
- 构造一个 V0 文件(2 tags + 2 assets + 8 字节数据)。
- 解析 V0 得内存表示。
- 序列化 V1,加 CRC。
- 验证 CRC 通过。
- 模拟损坏,CRC 不匹配(检测到)。
