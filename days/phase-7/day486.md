
# Day 486 · 加多个对齐点

> 每个 entity sprite 在屏幕上画一个 quad,但这个 quad 的"原点"在哪?之前的简单做法是左下角。但实际游戏需要多个对齐点——hero 的原点在脚下(地板上),飞行 bat 的原点在中心,墙壁挂火把的原点在右上。Day 486 给每个 asset 加多对齐点系统。

## 0 · 为什么要有这一天

想象你画一个 hero sprite,64×64 像素。这个 sprite 在屏幕上画的位置 (100, 100) 是 sprite 的哪里?

**方案 A**:左下角。`(100, 100)` 是 sprite 的左下角,画在屏幕像素 100-164, 100-164 区域。

**方案 B**:中心。`(100, 100)` 是 sprite 中心,画在 68-132, 68-132。

**方案 C**:脚下。`(100, 100)` 是 sprite 底部中央,画在 68-132, 68-100。

不同 entity 类型需要不同的对齐:

- **角色**(hero、goblin):原点在脚下(底部中央),因为角色站在地板上,脚的位置才是逻辑位置
- **飞行单位**(bat):原点在中心,因为飞行单位的位置是身体中心
- **挂墙物体**(火把):原点在挂点(右上角),因为火把贴在墙的右上
- **物品**(宝箱):原点在底部中央,像角色一样

如果所有 sprite 都用同一个对齐(比如左下角),美术必须确保每个 sprite 的"逻辑位置"都对齐到左下角。比如 hero 必须把脚画在 sprite 左下角——这浪费像素(头部上方留空),不自然。

正确做法:**每个 asset 自带多个对齐点**,运行时按 entity 类型选。

Asset 的对齐点通常存为元数据:

```rust
struct Asset {
    bitmap_id: u32,
    align_points: Vec<AlignPoint>,
}

struct AlignPoint {
    name: String,       // "foot", "center", "head"
    offset: Vec2,       // 相对 sprite 左下角的偏移
}
```

绘制时:`screen_pos = world_pos - align_point.offset`。

完成这一天之后,你具备了:

- 多对齐点系统的设计
- Sprite 元数据的扩展
- 理解"逻辑位置"和"绘制位置"的区别

## 2 · 心智模型

### 类比:相框的悬挂点

想象你要在墙上挂几个相框。每个相框背后有不同位置的挂钩:

- 普通 wood 相框:挂钩在顶部中央(挂在钉子上,自然下垂)
- 重型金属相框:挂钩在两侧(用钢丝连接,挂两点)
- 大型壁画:挂钩在四角(用滑轮组)

每个相框的"逻辑位置"(墙上的中心点)和"挂钩位置"不同。同样道理,sprite 的"逻辑位置"(世界坐标)和"对齐点"(绘制 anchor)可以不同。

### 对齐点的数学

给定:

- sprite 尺寸 `(w, h)`
- 对齐点 offset `(ax, ay)`(相对 sprite 左下角)
- 世界坐标(逻辑位置)`(wx, wy)`

绘制位置(屏幕坐标):

```
screen_x = wx - ax
screen_y = wy - ay
```

举例:hero sprite 64×64,foot align 在 (32, 64)(底部中央),世界坐标 (100, 50)(脚踩的 tile):

```
screen_x = 100 - 32 = 68
screen_y = 50 - 64 = -14
```

sprite 画在屏幕 (68, -14) 到 (132, 50) 区域,脚刚好在 y=50(tile 底部)。

### 常见 align 点

| Align 名称 | Offset(sprite 64×64) | 用途 |
|---|---|---|
| bottom_left | (0, 0) | UI 元素 |
| bottom_center | (32, 0) | 站立角色 |
| center | (32, 32) | 飞行 / 漂浮 |
| top_center | (32, 64) | 悬挂物 |
| top_left | (0, 64) | UI 标签 |
| head | (32, 56) | 顶部稍下,角色头 |
| foot | (32, 64) | 底部中央,角色脚 |

不同游戏定义不同,Casey 用语义命名(`foot`、`center`、`head`)而不是位置命名(`bottom_center`),这样美术改 sprite 大小时 align 名称不变。

### 多对齐点的应用

为什么 asset 需要多个 align 点,而不止一个?

**动画切换**:hero 走路动画的脚位置可能每帧不同(脚抬起来)。每个动画帧可以有自己的 "foot" 点,运行时按帧选。

**特殊技能**:hero 普通走路用 "foot",释放技能用 "center"(因为技能让 hero 漂浮)。

**特效绑定**:hero 头顶有 HP 条(用 "head"),手中有武器(用 "hand")。一个 asset 提供多个 align 点,不同子系统用不同点。

Casey 在 Day 486 给 asset 加多 align 点,后面动画 / 特效系统都能用。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

商业引擎都有 align 点概念。Unity 的 Sprite 有 Pivot(类似 align),可以是 9 个预设位置之一或自定义。Unreal 的 Paper2D Sprite 有 pivot。Godot 的 Sprite2D 有 offset 和 centered 选项。

工业级 align 系统更复杂:

- **Bone attach**:角色骨骼的某节作为 attach 点(手、头、背)。武器 attach 到手,帽子 attach 到头。
- **Socket**:骨骼上的具名 attach 点。Unity 的 Animator Socket、Unreal 的 Socket 都是这种。
- **Tag point**:场景里的标记点,角色走到这触发事件。

Casey 的简单 align 系统是 socket 的入门版——一个具名点,attach 用。

游戏开发里 align 还用于:

- **粒子绑定**:特效从角色的 "hand" 点发射
- **音效定位**:3D 音效从角色 "head" 点采样
- **碰撞盒**:碰撞盒相对 align 点偏移

### 3.2 · 🎨 图形学视角

图形学里 align 影响渲染的"变换链"。Sprite 的最终位置:

```
世界坐标(world position) → 减 align offset → 加 viewport → 屏幕坐标
```

如果不减 align,sprite 的"逻辑位置"和"显示位置"耦合,bug 多。Align 把这两个解耦——逻辑用 world coord,显示用 world coord - align。

工业级渲染管线还涉及:

- **Sprite scaling**:放大 sprite 时 align 点怎么变?(应该相对 sprite 中心缩放,然后 align offset 也缩放)
- **Sprite rotation**:旋转 sprite 时 align 点怎么变?(应该绕 align 点旋转,不是绕左下角)

Casey 暂时只做平移 align,缩放和旋转后面 Day 540+ 才需要。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上"对齐点"的对应是**坐标系约定**。不同 GUI 工具包有不同约定:

- **X11**:窗口 (0, 0) 是左上角
- **Wayland**:surface (0, 0) 是左上角
- **OpenGL**:clip space (-1, -1) 是左下角,NDC (0, 0) 是中心
- **PNG**:像素 (0, 0) 是左上角
- **SVG**:(0, 0) 是左上角
- **PDF**:(0, 0) 是左下角

跨工具包传递数据时,"原点位置"必须显式约定,否则画反。Casey 在 Day 473 处理过类似问题——坐标系统一。

Linux 桌面的"窗口位置"也是个 align 概念——窗口的 (x, y) 是窗口的左上角(不是中心)。如果你想"窗口中心在屏幕 (1000, 500)",要算 `window_x = 1000 - w/2`。

### 3.4 · 🦀 Rust 生态视角

Rust 里实现 align 系统的几个 idiomatic 选择。

第一,**`enum` 表达标准 align**(如果只有几个预设):

```rust
enum Align {
    BottomLeft,
    BottomCenter,
    Center,
    TopCenter,
    TopLeft,
}

impl Align {
    fn offset(self, w: f32, h: f32) -> (f32, f32) {
        match self {
            Align::BottomLeft => (0.0, 0.0),
            Align::BottomCenter => (w * 0.5, 0.0),
            Align::Center => (w * 0.5, h * 0.5),
            Align::TopCenter => (w * 0.5, h),
            Align::TopLeft => (0.0, h),
        }
    }
}
```

第二,**`HashMap<String, Vec2>`** 表达具名 align:

```rust
let aligns: HashMap<String, Vec2> = [
    ("foot".to_string(), Vec2::new(32.0, 64.0)),
    ("center".to_string(), Vec2::new(32.0, 32.0)),
].into_iter().collect();
```

Casey 用具名,因为美术需要自定义任意 align 点。

第三,**`Vec<AlignPoint>`** 数组(顺序访问快):

```rust
let aligns = vec![
    AlignPoint { name: "foot", offset: Vec2::new(32.0, 64.0) },
    AlignPoint { name: "center", offset: Vec2::new(32.0, 32.0) },
];

fn find_align(aligns: &[AlignPoint], name: &str) -> Option<Vec2> {
    aligns.iter().find(|a| a.name == name).map(|a| a.offset)
}
```

线性查找,O(N)。align 点通常很少(3-5 个),线性查找够快。

## 5 · 对照与变奏

Casey 在 Day 486 的 align 思想在不同领域有不同对应:

**CSS**:`transform-origin` 决定旋转/缩放的中心点。同 align——元素变换的"基准点"。

**SVG**:`<g transform="translate(x, y)">` 决定子元素的偏移。同 align。

**PDF / PostScript**:图形原点变换。`translate(x, y)` 后续绘制都偏移。同 align。

**CAD**:每个 Part 有 "origin" 点(通常中心或某角),装配时 origin 对齐。同 align。

**3D 建模**:每个 mesh 有 pivot point(原点)。旋转、缩放绕 pivot 进行。同 align。

理解"坐标系基准点"是工程师的核心素养。每次你处理图形/几何,问自己:**这个位置相对什么?**

另一个对照:**Align vs Pivot**。Align 是"绘制时减去",pivot 是"变换时绕"。本质都是"逻辑位置 vs 显示位置"。Casey 用 align,3D 建模用 pivot,概念一样。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 Casey 让美术自定义 align 点(用 sidecar `.align` 文件),而不是用预设的 9 个标准点(左下、下中、右下、左中、中央、右中、左上、上中、右上)?

**参考解答**:三个理由:

第一,**精确控制**。美术需要把 align 放在任意像素位置,不局限于 1/3 划分。比如 hero 的 "foot" 可能在 (32, 60) 而不是 (32, 64),因为鞋底有 4 像素厚。

第二,**多语义**。一个 sprite 可能需要 "foot"、"head"、"hand"、"back" 四个 align,9 个预设无法表达 "hand" 这种语义。

第三,**未来扩展**。如果以后需要 "shoulder"、"neck"、"knee" 等,9 个预设不够。自定义 sidecar 灵活。

预设的优点是简单(美术选 1-9),但牺牲灵活性。Casey 选自定义,因为 HH 的 sprite 已经在 sprite sheet 里,美术能精确知道每个像素位置。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现完整的 align 系统。给定 sprite 64×64,带 align 点 "foot" (32, 64)、"center" (32, 32)、"head" (32, 8)。写函数 `compute_screen_pos(world: Vec2, align: &str, sprite_size: Vec2) -> Vec2`。验证:world (100, 50) + align "foot" → screen (68, -14)。

完成标准:三个 align 各测试一次,打印结果验证。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    const fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
}

#[derive(Debug, Clone)]
struct AlignPoint {
    name: String,
    offset: Vec2,
}

struct Asset {
    name: String,
    width: f32,
    height: f32,
    align_points: Vec<AlignPoint>,
}

impl Asset {
    fn find_align(&self, name: &str) -> Option<&AlignPoint> {
        self.align_points.iter().find(|a| a.name == name)
    }
}

fn compute_screen_pos(world: Vec2, asset: &Asset, align_name: &str) -> Option<Vec2> {
    let align = asset.find_align(align_name)?;
    Some(world.sub(align.offset))
}

fn main() {
    let hero = Asset {
        name: "hero".to_string(),
        width: 64.0,
        height: 64.0,
        align_points: vec![
            AlignPoint { name: "foot".to_string(),   offset: Vec2::new(32.0, 64.0) },
            AlignPoint { name: "center".to_string(), offset: Vec2::new(32.0, 32.0) },
            AlignPoint { name: "head".to_string(),   offset: Vec2::new(32.0, 8.0) },
        ],
    };
    
    let world = Vec2::new(100.0, 50.0);
    
    for align_name in &["foot", "center", "head"] {
        let screen = compute_screen_pos(world, &hero, align_name).unwrap();
        println!("world ({}, {}) + align '{}' → screen ({}, {})",
                 world.x, world.y, align_name, screen.x, screen.y);
        
        // 验证:screen + align offset = world
        let align = hero.find_align(align_name).unwrap();
        let reconstructed = Vec2::new(screen.x + align.offset.x, screen.y + align.offset.y);
        assert!((reconstructed.x - world.x).abs() < 0.001);
        assert!((reconstructed.y - world.y).abs() < 0.001);
    }
    
    println!();
    
    // 测试多个 entity
    let entities = vec![
        ("hero",   Vec2::new(100.0, 50.0),  "foot"),
        ("bat",    Vec2::new(200.0, 150.0), "center"),
        ("torch",  Vec2::new(300.0, 200.0), "head"),
    ];
    
    println!("=== Entity 绘制 ===");
    for (name, world, align) in entities {
        let screen = compute_screen_pos(world, &hero, align).unwrap();
        println!("{:8} world ({:5.0}, {:5.0}) align {:6} → screen ({:5.0}, {:5.0})",
                 name, world.x, world.y, align, screen.x, screen.y);
    }
    
    // Align 找不到的情况
    println!();
    let missing = compute_screen_pos(world, &hero, "nonexistent");
    println!("Align 'nonexistent' result: {:?}", missing);
}
```

为什么这么写:`compute_screen_pos` 返回 `Option`,因为 align 可能找不到。Caller 显式处理 `None`(用默认 align 或报错)。

## 8 · Rust / Arch 落地代码

下面是 Day 486 完整的多 align 系统。

```rust
use std::collections::HashMap;
use std::fs;

// ========================================
// 数据结构
// ========================================

#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    const fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
    fn add(self, o: Self) -> Self { Self::new(self.x + o.x, self.y + o.y) }
}

#[derive(Debug, Clone)]
struct AlignPoint {
    name: String,
    offset: Vec2,
}

#[derive(Debug, Clone)]
struct Asset {
    name: String,
    width: u32,
    height: u32,
    align_points: Vec<AlignPoint>,
}

impl Asset {
    fn find_align(&self, name: &str) -> Option<&AlignPoint> {
        self.align_points.iter().find(|a| a.name == name)
    }
    
    fn compute_screen_pos(&self, world: Vec2, align_name: &str) -> Result<Vec2, String> {
        let align = self.find_align(align_name)
            .ok_or_else(|| format!("align '{}' not found on asset '{}'", align_name, self.name))?;
        Ok(world.sub(align.offset))
    }
}

// ========================================
// Sidecar .align 文件解析
// ========================================

fn parse_align_file(content: &str) -> Vec<AlignPoint> {
    let mut points = Vec::new();
    
    for line in content.lines() {
        let line = line.trim();
        if line.is_empty() || line.starts_with('#') {
            continue;
        }
        
        // 格式:name x y
        let parts: Vec<&str> = line.split_whitespace().collect();
        if parts.len() != 3 {
            eprintln!("Invalid align line: {:?}", line);
            continue;
        }
        
        let name = parts[0].to_string();
        let x: f32 = match parts[1].parse() {
            Ok(v) => v,
            Err(_) => continue,
        };
        let y: f32 = match parts[2].parse() {
            Ok(v) => v,
            Err(_) => continue,
        };
        
        points.push(AlignPoint { name, offset: Vec2::new(x, y) });
    }
    
    points
}

// ========================================
// Asset Library(带 align)
// ========================================

struct AssetLibrary {
    assets: HashMap<String, Asset>,
}

impl AssetLibrary {
    fn new() -> Self {
        Self { assets: HashMap::new() }
    }
    
    fn add(&mut self, asset: Asset) {
        self.assets.insert(asset.name.clone(), asset);
    }
    
    fn get(&self, name: &str) -> Option<&Asset> {
        self.assets.get(name)
    }
    
    /// 加载 asset:读 PNG(假装)+ sidecar
    fn load(&mut self, name: &str, width: u32, height: u32) {
        // 假装读 sidecar
        let align_content = format!(
            "# {}.align\nfoot {} {}\ncenter {} {}\nhead {} {}",
            name, width / 2, height,
            width / 2, height / 2,
            width / 2, height / 8,
        );
        let align_points = parse_align_file(&align_content);
        
        let asset = Asset {
            name: name.to_string(),
            width,
            height,
            align_points,
        };
        
        self.add(asset);
    }
}

// ========================================
// Entity 系统(用 align)
// ========================================

#[derive(Debug)]
struct Entity {
    asset_name: String,
    world_pos: Vec2,
    align_name: String,
}

impl Entity {
    fn new(asset: &str, world: Vec2, align: &str) -> Self {
        Self {
            asset_name: asset.to_string(),
            world_pos: world,
            align_name: align.to_string(),
        }
    }
    
    fn render_pos(&self, library: &AssetLibrary) -> Vec2 {
        match library.get(&self.asset_name) {
            Some(asset) => asset.compute_screen_pos(self.world_pos, &self.align_name)
                .unwrap_or(self.world_pos),
            None => self.world_pos,  // 找不到 asset,直接用 world pos
        }
    }
}

// ========================================
// 演示
// ========================================

fn main() {
    let mut library = AssetLibrary::new();
    library.load("hero", 64, 64);
    library.load("bat", 32, 32);
    library.load("torch", 16, 32);
    
    // 打印 asset 信息
    println!("=== Loaded assets ===");
    for (name, asset) in &library.assets {
        println!("{}: {}x{}, aligns: {:?}",
                 name, asset.width, asset.height,
                 asset.align_points.iter().map(|a| &a.name).collect::<Vec<_>>());
    }
    
    // 测试 align 计算
    println!();
    println!("=== Align 计算 ===");
    let hero = library.get("hero").unwrap();
    let world = Vec2::new(100.0, 50.0);
    for align_name in &["foot", "center", "head"] {
        let screen = hero.compute_screen_pos(world, align_name).unwrap();
        println!("hero world ({}, {}) + align '{}' → screen ({}, {})",
                 world.x, world.y, align_name, screen.x, screen.y);
    }
    
    // 多个 entity
    println!();
    println!("=== Entity 渲染 ===");
    let entities = vec![
        Entity::new("hero",  Vec2::new(100.0, 50.0),  "foot"),
        Entity::new("hero",  Vec2::new(200.0, 50.0),  "foot"),
        Entity::new("bat",   Vec2::new(150.0, 180.0), "center"),
        Entity::new("torch", Vec2::new(80.0, 100.0),  "head"),
    ];
    
    for e in &entities {
        let render = e.render_pos(&library);
        println!("{:8} world ({:5.0}, {:5.0}) align {:6} → render ({:5.0}, {:5.0})",
                 e.asset_name, e.world_pos.x, e.world_pos.y, e.align_name,
                 render.x, render.y);
    }
    
    // 验证:hero 站在 tile 上
    println!();
    println!("=== Tile 对齐验证 ===");
    println!("假设 tile 大小 64,hero 应该站在 tile 底部");
    println!("hero world_pos = tile 底部中央 = (tile_x + 32, tile_y + 64)");
    let tile_pos = Vec2::new(64.0, 0.0);    // tile (1, 0) 的左下角
    let hero_world = Vec2::new(tile_pos.x + 32.0, tile_pos.y + 64.0);
    let hero_render = hero.compute_screen_pos(hero_world, "foot").unwrap();
    println!("Tile 左下角: ({}, {})", tile_pos.x, tile_pos.y);
    println!("Hero world (脚): ({}, {})", hero_world.x, hero_world.y);
    println!("Hero render (sprite 左下角): ({}, {})", hero_render.x, hero_render.y);
    println!("→ Hero sprite 占据 ({}, {}) 到 ({}, {})",
             hero_render.x, hero_render.y,
             hero_render.x + 64.0, hero_render.y + 64.0);
    println!("→ Hero 脚 (y={}) 应该 = tile 底 (y={})",
             hero_render.y + 64.0, tile_pos.y + 64.0);
    assert!((hero_render.y + 64.0 - (tile_pos.y + 64.0)).abs() < 0.001);
    println!("✓ Hero 正确站在 tile 上");
    
    // 演示 align 找不到的处理
    println!();
    println!("=== 错误处理 ===");
    let bad_entity = Entity::new("hero", Vec2::new(0.0, 0.0), "nonexistent_align");
    let pos = bad_entity.render_pos(&library);
    println!("未知 align 的 entity,fallback to world: {:?}", pos);
    
    let unknown_entity = Entity::new("unknown_asset", Vec2::new(0.0, 0.0), "foot");
    let pos = unknown_entity.render_pos(&library);
    println!("未知 asset 的 entity,fallback to world: {:?}", pos);
}
```
