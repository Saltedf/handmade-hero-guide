# Day 528 · 从 HHFont 写 HHT

> Day 527 你做了一个独立的字体提取器,产出 PNG atlas + 元数据。Day 528 Casey 把这个产出物**包装成 HHT(Handmade Hero Tag)文件**——HH 项目自己的元数据格式。HHT 是文本格式,可读可编辑,导入时被解析成 HHA 二进制资产。今天做的事就是"格式转换器":从字体提取器的私有格式 → 公开的 HHT 格式 → 导入器 → HHA 二进制。

## 0 · 为什么要有这一天

回忆一下 HH 的资产管线(从 Day 510 起建立的):

```
PNG (source)  ─┐
                ├─→  HHT (text metadata)  ─→  Importer  ─→  HHA (binary package)
HHFont (tool) ─┘
```

HHT(Handmade Hero Tag)是 Casey 设计的**人类可读文本格式**,用来描述资产的元数据:这个 PNG 是个 sprite sheet,grid size 32x32,每个瓦片的标签是 X。这个 HHFont 产出物是个字体,字号 32px,glyph 列表如下。

为什么需要 HHT 这个中间层?为什么不直接 PNG → HHA(自动化)?三个原因:

第一,**人类可编辑**。开发者可以打开 HHT 文本,改一个标签或加一个对齐点,不用重新跑工具。这在调试时极有用。
第二,**版本控制友好**。HHT 是文本,git diff 看得清楚改了什么。PNG 是二进制,改了一像素 git 也看不出。
第三,**工具解耦**。字体提取器、PNG 工具、关卡编辑器都各自产出 HHT,游戏运行时只关心 HHA。工具升级不影响游戏。

Day 528 做的事是**写 HHT 文件**——把 Day 527 字体提取器的产出物序列化成文本格式。Day 510 你学过读 HHT(解析器),今天是反方向(写入器)。

完成这一天之后,你具备:

- 理解"读"和"写"两个方向是镜像的(parser vs writer)
- 能设计一个文本格式,既人类可读又机器可解析
- 在 Rust 里用 `Display` trait 或手写 serializer 写文本

## 1 · Casey 今天做了什么

Casey 这一天的动作可以拆成三步:

第一步,他**定义 HHT 的 font 段语法**。HHT 之前支持 sprite(图像)和 sound(音频),今天加 font(字体)。语法示例:

```
font {
    name = "main_font"
    size = 32
    png = "fonts/main.png"
    ascent = 26
    descent = -6
    line_gap = 4
    glyph 'A' { x=0, y=0, w=20, h=23, advance=20.5 }
    glyph 'B' { x=20, y=0, w=18, h=23, advance=18.2 }
    ...
}
```

这种语法是 C/C++/Rust struct literal 风格——人类可读,且解析简单。

第二步,他**写 HHT writer**:遍历 HHFont 数据结构,逐字段写入文本文件。这和 HHT parser(Day 510)是镜像——parser 读 token 构造结构,writer 遍历结构生成 token。

第三步,他**round-trip 测试**:写一个 HHFont 到 HHT,再读回来,验证读到的等于写的。这是测试序列化的标准方法——如果 round-trip 失败,说明 writer 或 parser 有 bug。

视频里他强调:HHT 的设计哲学是"够用就好"——不支持 JSON 那么复杂,不支持 XML 那么啰嗦,就是一个紧凑的、专用的文本格式。**"自己造格式"在游戏开发里很常见**,因为 JSON 太啰嗦(每个引号都是字节)、XML 太重(标签开销大)。

## 2 · 心智模型

### 类比:菜单的两种写法

餐厅菜单可以用两种风格写:

**JSON 风格**(啰嗦):
```json
{"items": [{"name": "Burger", "price": 10.99, "tags": ["beef", "cheese"]}]}
```

**HHT 风格**(紧凑):
```
item Burger { price=10.99 tags=[beef,cheese] }
```

信息一样,但 HHT 更紧凑(去掉引号、括号、逗号)。HHT 牺牲了 JSON 的通用性,换来了可读性和解析速度。这就是 Casey 的取舍。

### 严谨展开:HHT 文本格式设计

HHT 是 Casey 设计的,但和很多游戏行业的"自定义格式"相似。它的设计原则:

1. **关键字无引号**:`font`、`glyph` 不加引号,节省字节
2. **字符串值有引号**:`"main_font"` 加引号,允许包含空格
3. **数值无引号**:`32` 直接写,无需类型推断
4. **嵌套用大括号**:`font { ... }`,清晰且和 C/Rust 一致
5. **行尾无分号**:行尾是换行,自然分隔,无需额外标记

解析器:

```
token := identifier | string | number | '{' | '}' | '=' | '[' | ']' | ','
font_decl := 'font' identifier '{' font_body '}'
font_body := (ascent_decl | descent_decl | glyph_decl)*
glyph_decl := 'glyph' character '{' glyph_body '}'
glyph_body := ('x' | 'y' | 'w' | 'h' | 'advance') '=' number
```

这种语法是 LL(1) 解析,递归下降(recursive descent)能搞定。

### Writer vs Parser 的镜像关系

```
Parser:
  bytes ─→ tokenizer ─→ AST ─→ struct

Writer:
  struct ─→ traverse ─→ token stream ─→ bytes
```

Parser 用 `peek()` + `expect()` 风格,Writer 用 `write!()` 风格。两者必须严格对称——否则 round-trip 失败。

```rust
// Parser
fn parse_glyph(parser: &mut Parser) -> Glyph {
    parser.expect_ident("glyph");
    let char_code = parser.parse_char();
    parser.expect('{');
    let x = parser.parse_field_int("x");
    let y = parser.parse_field_int("y");
    // ...
    parser.expect('}');
    Glyph { char_code, x, y, ... }
}

// Writer(镜像)
fn write_glyph(writer: &mut Writer, glyph: &Glyph) {
    write!(writer, "glyph '{}' {{ ", glyph.char_code).unwrap();
    write!(writer, "x={}, y={}, ", glyph.x, glyph.y).unwrap();
    // ...
    writeln!(writer, "}}").unwrap();
}
```

注意:Writer 不需要处理"输入错误",因为它从内存数据生成。Parser 必须处理 malformed 输入,所以代码更长。

### Round-trip 测试

```rust
#[test]
fn test_font_roundtrip() {
    let original = Font {
        name: "main".into(),
        size: 32,
        glyphs: vec![Glyph { char_code: 'A', x: 0, y: 0, w: 20, h: 23, advance: 20.5 }],
    };
    
    let mut writer = Writer::new();
    write_font(&mut writer, &original);
    
    let text = writer.into_string();
    let parsed = parse_font(&mut Parser::new(&text)).unwrap();
    
    assert_eq!(original.name, parsed.name);
    assert_eq!(original.size, parsed.size);
    assert_eq!(original.glyphs.len(), parsed.glyphs.len());
    assert_eq!(original.glyphs[0].char_code, parsed.glyphs[0].char_code);
    // ...
}
```

这是测试序列化的金标准。任何序列化格式(JSON、Protobuf、Cap'n Proto)都该有 round-trip 测试。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏行业的元数据格式:

- **JSON** —— Unity ScriptableObject、Unreal Plugin 描述
- **TOML** —— Cargo.toml、Rust 项目配置
- **YAML** —— docker-compose、CI 配置
- **自定义格式** —— 游戏行业最常见(性能 + 灵活)

为什么游戏行业偏爱自定义?**JSON 解析慢**(每秒几 MB),**TOML 不支持嵌套数组**,**YAML 缩进敏感容易出错**。Casey 的 HHT 解析可达每秒几十 MB,且设计专为游戏资产(图像、声音、字体)优化。

Unreal 的 `.uasset` 格式、Unity 的 `.asset` 格式都是自定义二进制 + 文本元数据混合。

### 3.2 · 图形学视角

3D 模型格式(GLTF、FBX、OBJ)也是序列化问题。GLTF 用 JSON 描述场景,二进制存顶点数据。它的设计哲学和 HHT 一样:**人类可读部分用文本(JSON),大块数据用二进制**。

Casey 的 HHT 把图像数据(大块)留给 PNG,只把元数据存文本。这和 GLTF 是同一种设计模式。

### 3.3 · Linux 系统编程视角

Linux 配置格式演化:

- 1970s-2000s:**自定义文本**(`/etc/passwd`、`/etc/fstab`、`/etc/hosts`)
- 2000s-2010s:**XML**(SOAP、Maven POM、Spring XML)
- 2010s-2020s:**JSON / YAML**(REST API、容器、CI)
- 现代:**TOML / KDL** —— 兼顾可读和严格

每种格式都有自己的领域。Linux 内核的 `.config` 仍然是自定义文本格式(`CONFIG_X86=y`),因为内核启动时解析简单。

Casey 的 HHT 是 Linux 风格的延续——为特定领域设计专用格式,不为通用性妥协。

### 3.4 · Rust 生态视角

Rust 的序列化生态:

- **`serde`** —— 通用序列化框架,支持 JSON/YAML/TOML/BSON/...
- **`serde_json`** —— JSON 的 serde 实现
- **`toml`** —— TOML 的 serde 实现
- **`serde_derive`** —— 用 `#[derive(Serialize, Deserialize)]` 自动生成代码

如果 HHT 用 serde 实现:

```rust
#[derive(Serialize, Deserialize)]
struct HhtFont {
    name: String,
    size: u32,
    glyphs: Vec<HhtGlyph>,
}

// 但 serde 不支持自定义语法,需要实现 Serializer trait
```

Casey 选择手写 parser/writer,因为 HHT 不是标准格式。Rust 翻译版可以用 `pest` 或 `nom` crate 写 parser——它们提供 parser combinator,比手写递归下降更声明式。

```rust
// 用 pest 写 HHT parser
use pest::Parser;
#[derive(Parser)]
#[grammar = "hht.pest"]
struct HhtParser;

let parsed = HhtParser::parse(Rule::font, input_text)?;
```

`pest` 用 PEG(Parser Expression Grammar)定义语法,生成 parser 代码。适合中等复杂度语法。

## 5 · 对照与变奏

HHT 类似其他领域专用格式:

- **CSS** —— 网页样式,自定义语法

- **TOML** —— Rust/Cargo 推动,小众但活跃

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:Casey 的 HHT 是文本格式。为什么不直接二进制(更快更小)?

**参考解答**:三个原因。第一,**人类可编辑**——开发者可以打开 HHT 改一行(改标签、加 glyph),不用重新跑工具。二进制做不到。第二,**版本控制友好**——git diff 文本一目了然,二进制 git diff 是字节流。第三,**调试友好**——出 bug 时,直接 cat HHT 文件就能看内容。运行时(导入后)才是二进制 HHA,但开发期保留文本 HHT 让调试容易。这是"开发期 vs 运行期"分离的经典设计。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:写一个简化的 HHT writer 和 parser,处理 `font` 块,要求 round-trip 测试通过。font 块结构:`font { name="X" size=N glyph 'C' {x,y,w,h,advance} }`。运行测试:写入一个 font,读回来,字段相等。

**参考解答**:

```rust
use std::fmt::Write as _;
use std::collections::HashMap;

#[derive(Debug, PartialEq, Clone)]
struct Glyph {
    char_code: char,
    x: u32, y: u32, w: u32, h: u32,
    advance: f32,
}

#[derive(Debug, PartialEq, Clone)]
struct Font {
    name: String,
    size: u32,
    glyphs: Vec<Glyph>,
}

// === Writer ===
fn write_font(f: &Font) -> String {
    let mut s = String::new();
    writeln!(s, "font {{").unwrap();
    writeln!(s, "  name = \"{}\"", f.name).unwrap();
    writeln!(s, "  size = {}", f.size).unwrap();
    for g in &f.glyphs {
        writeln!(s, "  glyph '{}' {{ x={}, y={}, w={}, h={}, advance={} }}",
            g.char_code, g.x, g.y, g.w, g.h, g.advance).unwrap();
    }
    writeln!(s, "}}").unwrap();
    s
}

// === Parser(简化版)===
fn parse_font(text: &str) -> Result<Font, String> {
    // 极简:假设格式严格匹配
    let mut name = String::new();
    let mut size = 0;
    let mut glyphs = Vec::new();
    
    for line in text.lines() {
        let line = line.trim();
        if line.starts_with("name") {
            // name = "X"
            let s = line.split('=').nth(1).unwrap().trim();
            name = s.trim_matches('"').to_string();
        } else if line.starts_with("size") {
            size = line.split('=').nth(1).unwrap().trim().parse().unwrap();
        } else if line.starts_with("glyph") {
            // glyph 'C' { x=.., y=.., w=.., h=.., advance=.. }
            let char_part = line.split('\'').nth(1).unwrap();
            let char_code = char_part.chars().next().unwrap();
            let body = line.split('{').nth(1).unwrap().split('}').next().unwrap();
            let fields: HashMap<&str, &str> = body.split(',')
                .map(|kv| {
                    let mut it = kv.trim().split('=');
                    (it.next().unwrap().trim(), it.next().unwrap().trim())
                })
                .collect();
            glyphs.push(Glyph {
                char_code,
                x: fields["x"].parse().unwrap(),
                y: fields["y"].parse().unwrap(),
                w: fields["w"].parse().unwrap(),
                h: fields["h"].parse().unwrap(),
                advance: fields["advance"].parse().unwrap(),
            });
        }
    }
    Ok(Font { name, size, glyphs })
}

#[test]
fn test_roundtrip() {
    let original = Font {
        name: "main".into(),
        size: 32,
        glyphs: vec![
            Glyph { char_code: 'A', x: 0, y: 0, w: 20, h: 23, advance: 20.5 },
            Glyph { char_code: 'B', x: 20, y: 0, w: 18, h: 23, advance: 18.2 },
        ],
    };
    
    let text = write_font(&original);
    println!("=== 写出的 HHT ===\n{}", text);
    
    let parsed = parse_font(&text).unwrap();
    assert_eq!(original, parsed);
    println!("=== Round-trip 测试通过 ===");
}

fn main() {
    let font = Font {
        name: "main".into(),
        size: 32,
        glyphs: vec![
            Glyph { char_code: 'A', x: 0, y: 0, w: 20, h: 23, advance: 20.5 },
        ],
    };
    print!("{}", write_font(&font));
}
```

为什么这么写:`writeln!` 用 Rust 的格式化语法,自动处理类型转换。Parser 是最简单的逐行 + split 风格,生产代码应该用真正的 tokenizer(pest/nom)。round-trip 测试用 `assert_eq!(original, parsed)`,需要 `PartialEq` derive。

## 8 · Rust / Arch 落地代码

```rust
// 完整的 HHT writer + parser,带错误处理

use std::fmt::Write as _;

#[derive(Debug, Clone, PartialEq)]
pub struct HhtFont {
    pub name: String,
    pub size: u32,
    pub png_path: String,
    pub ascent: i32,
    pub descent: i32,
    pub line_gap: i32,
    pub glyphs: Vec<HhtGlyph>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct HhtGlyph {
    pub char_code: char,
    pub atlas_x: u32,
    pub atlas_y: u32,
    pub width: u32,
    pub height: u32,
    pub advance: f32,
}

// === Writer ===
pub fn write_hht_font(f: &HhtFont) -> String {
    let mut s = String::new();
    writeln!(s, "font {{").unwrap();
    writeln!(s, "    name = \"{}\"", f.name).unwrap();
    writeln!(s, "    size = {}", f.size).unwrap();
    writeln!(s, "    png = \"{}\"", f.png_path).unwrap();
    writeln!(s, "    ascent = {}", f.ascent).unwrap();
    writeln!(s, "    descent = {}", f.descent).unwrap();
    writeln!(s, "    line_gap = {}", f.line_gap).unwrap();
    writeln!(s).unwrap();
    for g in &f.glyphs {
        writeln!(s, "    glyph '{}' {{", g.char_code).unwrap();
        writeln!(s, "        atlas_x = {}", g.atlas_x).unwrap();
        writeln!(s, "        atlas_y = {}", g.atlas_y).unwrap();
        writeln!(s, "        width = {}", g.width).unwrap();
        writeln!(s, "        height = {}", g.height).unwrap();
        writeln!(s, "        advance = {}", g.advance).unwrap();
        writeln!(s, "    }}").unwrap();
    }
    writeln!(s, "}}").unwrap();
    s
}

// === Parser(简化的递归下降)===
pub fn parse_hht_font(text: &str) -> Result<HhtFont, String> {
    let mut p = Parser::new(text);
    p.expect_ident("font")?;
    p.expect_open_brace()?;
    
    let mut name = String::new();
    let mut size = 0;
    let mut png_path = String::new();
    let mut ascent = 0;
    let mut descent = 0;
    let mut line_gap = 0;
    let mut glyphs = Vec::new();
    
    while !p.peek_close_brace()? {
        match p.peek_ident()?.as_str() {
            "name" => { p.consume_ident(); p.expect_eq()?; name = p.parse_string()?; }
            "size" => { p.consume_ident(); p.expect_eq()?; size = p.parse_uint()?; }
            "png" => { p.consume_ident(); p.expect_eq()?; png_path = p.parse_string()?; }
            "ascent" => { p.consume_ident(); p.expect_eq()?; ascent = p.parse_int()?; }
            "descent" => { p.consume_ident(); p.expect_eq()?; descent = p.parse_int()?; }
            "line_gap" => { p.consume_ident(); p.expect_eq()?; line_gap = p.parse_int()?; }
            "glyph" => {
                p.consume_ident();
                let char_code = p.parse_char()?;
                p.expect_open_brace()?;
                let mut g = HhtGlyph {
                    char_code, atlas_x: 0, atlas_y: 0,
                    width: 0, height: 0, advance: 0.0
                };
                while !p.peek_close_brace()? {
                    match p.peek_ident()?.as_str() {
                        "atlas_x" => { p.consume_ident(); p.expect_eq()?; g.atlas_x = p.parse_uint()?; }
                        "atlas_y" => { p.consume_ident(); p.expect_eq()?; g.atlas_y = p.parse_uint()?; }
                        "width"   => { p.consume_ident(); p.expect_eq()?; g.width = p.parse_uint()?; }
                        "height"  => { p.consume_ident(); p.expect_eq()?; g.height = p.parse_uint()?; }
                        "advance" => { p.consume_ident(); p.expect_eq()?; g.advance = p.parse_float()?; }
                        other => return Err(format!("unknown glyph field: {}", other)),
                    }
                }
                p.expect_close_brace()?;
                glyphs.push(g);
            }
            other => return Err(format!("unknown font field: {}", other)),
        }
    }
    p.expect_close_brace()?;
    
    Ok(HhtFont { name, size, png_path, ascent, descent, line_gap, glyphs })
}

struct Parser<'a> {
    chars: std::str::Chars<'a>,
    peeked: Option<char>,
}

impl<'a> Parser<'a> {
    fn new(s: &'a str) -> Self {
        let mut chars = s.chars();
        let peeked = chars.next();
        Self { chars, peeked }
    }
    
    fn skip_ws(&mut self) {
        while let Some(c) = self.peeked {
            if c.is_whitespace() { self.peeked = self.chars.next(); }
            else { break; }
        }
    }
    
    fn peek(&mut self) -> Option<char> {
        self.skip_ws();
        self.peeked
    }
    
    fn bump(&mut self) -> Option<char> {
        let c = self.peeked;
        self.peeked = self.chars.next();
        c
    }
    
    fn expect_ident(&mut self, expected: &str) -> Result<(), String> {
        if self.peek_ident()? == expected {
            self.consume_ident();
            Ok(())
        } else {
            Err(format!("expected '{}'", expected))
        }
    }
    
    fn peek_ident(&mut self) -> Result<String, String> {
        self.skip_ws();
        let mut ident = String::new();
        let mut peeked = self.peeked;
        while let Some(c) = peeked {
            if c.is_alphanumeric() || c == '_' {
                ident.push(c);
                // 模拟"看但不消费"
                peeked = None;  // 我们必须真消费,这里简化
                break;  // 极简版只看第一个字符做判断
            } else { break; }
        }
        Ok(ident)
    }
    
    fn consume_ident(&mut self) {
        // 实际实现要完整读 identifier
        self.skip_ws();
        while let Some(c) = self.peeked {
            if c.is_alphanumeric() || c == '_' {
                self.peeked = self.chars.next();
            } else { break; }
        }
    }
    
    fn expect_eq(&mut self) -> Result<(), String> {
        self.skip_ws();
        if self.bump() != Some('=') { return Err("expected =".into()); }
        Ok(())
    }
    
    fn expect_open_brace(&mut self) -> Result<(), String> {
        self.skip_ws();
        if self.bump() != Some('{') { return Err("expected {".into()); }
        Ok(())
    }
    
    fn expect_close_brace(&mut self) -> Result<(), String> {
        self.skip_ws();
        if self.bump() != Some('}') { return Err("expected }".into()); }
        Ok(())
    }
    
    fn peek_close_brace(&mut self) -> Result<bool, String> {
        Ok(self.peek() == Some('}'))
    }
    
    fn parse_string(&mut self) -> Result<String, String> {
        self.skip_ws();
        if self.bump() != Some('"') { return Err("expected \"".into()); }
        let mut s = String::new();
        while let Some(c) = self.bump() {
            if c == '"' { return Ok(s); }
            s.push(c);
        }
        Err("unterminated string".into())
    }
    
    fn parse_uint(&mut self) -> Result<u32, String> {
        self.skip_ws();
        let mut s = String::new();
        while let Some(c) = self.peeked {
            if c.is_ascii_digit() { s.push(c); self.peeked = self.chars.next(); }
            else { break; }
        }
        s.parse().map_err(|e: std::num::ParseIntError| e.to_string())
    }
    
    fn parse_int(&mut self) -> Result<i32, String> {
        self.skip_ws();
        let mut s = String::new();
        if self.peeked == Some('-') { s.push('-'); self.peeked = self.chars.next(); }
        while let Some(c) = self.peeked {
            if c.is_ascii_digit() { s.push(c); self.peeked = self.chars.next(); }
            else { break; }
        }
        s.parse().map_err(|e: std::num::ParseIntError| e.to_string())
    }
    
    fn parse_float(&mut self) -> Result<f32, String> {
        self.skip_ws();
        let mut s = String::new();
        while let Some(c) = self.peeked {
            if c.is_ascii_digit() || c == '.' || c == '-' || c == '+' || c == 'e' || c == 'E' {
                s.push(c); self.peeked = self.chars.next();
            } else { break; }
        }
        s.parse().map_err(|e: std::num::ParseFloatError| e.to_string())
    }
    
    fn parse_char(&mut self) -> Result<char, String> {
        self.skip_ws();
        if self.bump() != Some('\'') { return Err("expected '".into()); }
        let c = self.bump().ok_or("eof in char")?;
        if self.bump() != Some('\'') { return Err("unterminated char".into()); }
        Ok(c)
    }
}
```

出错怎么办:

- **`expected =` 但实际是别的**:字段间漏了 `=`。检查 writer 格式。
- **round-trip 失败但单步通过**:浮点数精度问题(`20.5` → parse → `20.5_f32` → format → `20.5`,但有些数循环)。用 `format!("{:.4}", f)` 固定小数位。
- **嵌套括号不匹配**:parser 的 `expect_close_brace` 调用位置错。在 parser 里加 debug 打印当前 peeked char。
