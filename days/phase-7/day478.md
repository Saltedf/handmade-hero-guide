
# Day 478 · 改为每 pass 单次 dispatch(第二部分)

> Day 477 把顶点 batch 起来了,但每个纹理还要一次 draw call。Day 478 用 **texture array**(纹理数组)解决——所有纹理叠在一个 GL_TEXTURE_2D_ARRAY 里,shader 用 layer index 选,真正做到一帧一次 draw call。

## 0 · 为什么要有这一天

Day 477 之后,你的渲染流程是这样的:

```
1. 收集所有 entry 的顶点
2. 按纹理 ID 分组
3. 对每个纹理组:
   - glBindTexture(tex_id)
   - glDrawArrays(group 的顶点)
```

如果场景里有 10 种纹理,你还要 10 次 draw call。比 500 次好,但不如 1 次。

为什么不能所有 entry 一次 draw call?因为 OpenGL 的 `glBindTexture` 只能绑一个纹理(每个 unit),shader 只能 sample 一个。如果顶点用不同纹理,你必须分多次。

Texture array 解决这个:**把所有纹理打包成"3D 纹理"——一个 GL_TEXTURE_2D_ARRAY,有 N 个 layer,每个 layer 是一张 2D 纹理**。Shader 用 `texture(sampler2DArray, vec3(u, v, layer))` 采样,layer 指定哪一张。

这样,顶点 buffer 里每个顶点带 `layer_index` 字段(整数),shader 用这个选 layer。所有 entry 共用一个 draw call。

但有个限制:**texture array 里所有 layer 必须同尺寸**。你不能把 32×32 和 1024×1024 混在一个 array 里(OpenGL 要求)。解决:所有纹理 rescale 到统一尺寸(比如 1024×1024)。浪费一点显存,但简化逻辑。

Day 478 做的就是这个——texture array + layer index。

完成这一天之后,你具备了:

- Texture array 的实操经验
- 顶点属性扩展(加 layer 字段)
- 真正的"一帧一次 draw call"实现

## 2 · 心智模型

### 类比:餐盘架 vs 单独餐盘

想象两种餐盘管理方式:

**方式 A(单纹理)**:每种食物一个独立餐盘。你吃牛排拿牛排盘,吃沙拉拿沙拉盘,吃面包拿面包盘。每次取餐盘要走到橱柜,换盘子很麻烦。

**方式 B(texture array)**:一个**多层餐盘架**,每层放一种食物的餐盘。你坐在桌前,手一伸就能拿到任何一层。一次"伸"可以拿多层。

texture array 就是多层餐盘架。所有纹理在一个"架"(GL_TEXTURE_2D_ARRAY)里,shader 想用哪张就指定 layer(层号),不需要"换餐盘"(bind texture)。

### 为什么 texture array 必须同尺寸

Texture array 要求所有 layer 同宽同高同 format。为什么?

因为 GPU 用 SIMD 处理 texture fetch——它同时采样多个 layer 的同一位置(u, v)。如果 layer 0 是 32×32,layer 1 是 1024×1024,GPU 没法同时处理(地址计算完全不同)。

这个限制是个 trade-off:**强制同尺寸换 O(1) 切换**。Game engine 接受这个 trade-off——所有纹理 rescale 到 1024×1024 或 2048×2048,浪费一点显存(小纹理被放大),换极大的性能。

工业实践:

- **Texture Atlas**:多张小纹理拼成一张大纹理(无需 array 支持,但 UV 计算复杂)
- **Texture Array**:GL 3.0+,所有 layer 同尺寸
- **Bindless Textures**:NV 扩展,任意纹理直接用 handle,无 bind

Casey 用 texture array,这是 OpenGL 3.0+ 的标准方案,兼容性最好。

### Layer Index 怎么传递

Vertex buffer 里每个顶点带 `layer` 字段。但是 layer 是整数,OpenGL 顶点属性的整数传递要用 `glVertexAttribIPointer`(注意 I),不能用 `glVertexAttribPointer`。后者会把整数转成 float,精度损失。

```rust
// 整数 attribute
glVertexAttribIPointer(3, 1, GL_INT, stride, offset);
glEnableVertexAttribArray(3);

// Shader 端
#version 330
layout(location = 0) in vec3 pos;
layout(location = 1) in vec2 uv;
layout(location = 2) in vec4 color;
layout(location = 3) in int layer;        // int 不是 float
```

Casey 在 Day 478 处理这个细节。如果忘了 `I` 指针,layer 会被解释成 float(比如 3.0 而不是 3),texture fetch 错。

### Shader 修改

旧 shader(per-entry draw call + 单纹理):

```glsl
#version 330
uniform sampler2D tex;
in vec2 uv;
in vec4 color;
out vec4 frag_color;

void main() {
    vec4 tex_color = texture(tex, uv);
    frag_color = tex_color * color;
}
```

新 shader(texture array + layer):

```glsl
#version 330
uniform sampler2DArray tex_array;    // 注意是 Array
in vec2 uv;
in vec4 color;
flat in int layer;                   // flat: 不插值整数
out vec4 frag_color;

void main() {
    // texture() 第三参数是 layer
    vec4 tex_color = texture(tex_array, vec3(uv, layer));
    frag_color = tex_color * color;
}
```

注意两个细节:

第一,`flat in int layer` —— `flat` 表示不插值。整数不能插值(顶点间怎么插 3 和 5?算 4.0 没意义)。`flat` 让 fragment shader 用 provoking vertex 的值。

第二,`texture(tex_array, vec3(uv, layer))` —— texture array 的采样坐标是 vec3,前两位是 uv,第三位是 layer。

这些细节如果错,fragment 颜色全黑或全是错纹理。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Texture array 是游戏引擎标配。Unity 的 Texture2DArray、Unreal 的 Texture Array、Godot 的 Texture3D(类似)都做这件事。

工业实践通常配合 **texture atlas**——把多个小纹理拼成一个大纹理(图集),UV 坐标算偏移。Atlas 比 array 更通用(支持不同尺寸),但 UV 计算复杂,有 mipmap 问题。

游戏开发里有个常用技术叫 **"Texture Atlas + Array"**:把同类型纹理(比如所有 UI 图标)放一个 atlas,不同类型(图标、角色、特效)分别放不同 array layer。这是现代引擎的标准做法。

Casey 的简单 texture array 够 HH 用,但他后面 Day 479 大纹理支持时可能需要 atlas 思想——大纹理(2048×2048)放 array 一个 layer,小纹理放另一个 layer 集合。

### 3.2 · 🎨 图形学视角

Texture array 在图形学里有几个延伸概念。

**Bindless textures**:NV 扩展(后来变成 Vulkan 标准)。每个纹理有 64-bit handle,shader 直接用 handle 采样,无需 bind。极致 batching。

**Sparse textures**:部分驻留纹理(只加载可见部分)。tile-based 游戏、超大世界用。

**Virtual textures(Mega-texture)**:John Carmack 在 Rage(2011)用的技术。整个游戏世界一张巨大虚拟纹理,GPU 按需 page in/out。是 texture streaming 的极致。

Casey 的 texture array 是最基础的纹理批处理。理解了它,你看 Unity/Unreal 的 texture streaming 文档能秒懂。

图形学还有一个相关概念:**sampler array**。你可以声明 `uniform sampler2DArray samplers[8]`,这是 8 个 texture array,每个 array 又有 N 个 layer。这样允许"不同尺寸"——大纹理放一个 array,小纹理放另一个 array。Casey 不用这个,因为 HH 纹理尺寸统一。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上的 GPU driver 在内部就是 texture array 的实现者。Mesa 的 `ralloc` (resource allocator) 管理 GPU 显存,texture 上传时分配 layer,释放时归还。

## 5 · 对照与变奏

Casey 在 Day 478 的 texture array 思想在不同领域有不同对应:

**磁盘**:`tar` 把多个文件打包成一个归档。和 texture array 同构——多文件单 archive。

**内存**:数组 vs 链表。数组是连续内存(同 texture array),链表是分散节点(同多次 bind)。

**网络**:HTTP/2 的 multiplexing,一个 TCP 连接承载多个流。同 texture array——一个 binding 承载多个纹理。

**数据库**:表分区(table partition)。一张大表按 key 分成多个分区,统一查询。同 texture array——一个对象多个 layer。

理解"打包多个为一个"是工程师的核心素养。每次你做性能优化,问自己:**有没有多个对象能打包成一个?** 这通常是大收益点。

另一个对照:**Rust 的 enum vs C 的 union**。Rust enum 把多个 variant 打包在一个类型里(带 tag),C union 也打包但无 tag。Casey 的 Render Group enum entry 也是这种打包——多个 entry 类型打包在一个 Vec 里。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 texture array 的 layer 必须用 `flat in int` 而不是普通 `in int`?

**参考解答**:GPU 的 fragment shader 输入默认会被插值——三个 vertex 的值在三角形内部按重心坐标插值。整数无法"插值"——3 和 5 之间没有"4.0"的概念(没有 4 个 layer,只有 layer 3 和 layer 5)。

`flat` 修饰符告诉 GPU 不插值,fragment shader 用 provoking vertex(默认是三角形的第一个或最后一个顶点,driver 决定)的值。这样所有 fragment 在同一个三角形里用同一个 layer,正确。

如果忘了 flat,GPU 会把 int 转 float 插值,layer 变成 3.7、4.2 这种值,sampler 用错误的 layer 采样,结果错乱。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:扩展 Day 477 的 Vertex,加 `texture_layer: i32` 字段。修改 `push_quad_vertices` 接受 layer 参数。验证:3 个 entry,分别用 layer 0、1、2,buffer 里顶点的 layer 字段正确。

完成标准:`cargo run` 输出每个顶点的 layer,验证三角形内 layer 一致。

**参考解答**:

```rust
#[repr(C)]
#[derive(Copy, Clone, Debug, bytemuck::Pod, bytemuck::Zeroable)]
struct Vertex {
    pos: [f32; 3],
    uv: [f32; 2],
    color: [f32; 4],
    texture_layer: i32,        // 新增
    _padding: [u32; 3],        // padding 让总大小对齐 16 字节
}
// pos: 12, uv: 8, color: 16, layer: 4, padding: 12 = 52 字节
// 实际工业代码会精算 padding 让顶点大小是 16/32/64 字节对齐

#[derive(Debug)]
struct BitmapEntry {
    bitmap_id: u32,           // 这就是 layer
    x: f32, y: f32, z: f32,
    w: f32, h: f32,
    color: [f32; 4],
}

fn push_quad_vertices(verts: &mut Vec<Vertex>, e: &BitmapEntry) {
    let layer = e.bitmap_id as i32;
    let c = e.color;
    let z = e.z;
    let pad = [0; 3];
    
    let p00 = [e.x,     e.y,     z];
    let p10 = [e.x+e.w, e.y,     z];
    let p11 = [e.x+e.w, e.y+e.h, z];
    let p01 = [e.x,     e.y+e.h, z];
    let uv00 = [0.0, 0.0];
    let uv10 = [1.0, 0.0];
    let uv11 = [1.0, 1.0];
    let uv01 = [0.0, 1.0];
    
    // 6 顶点,都带同样的 layer
    verts.push(Vertex { pos: p00, uv: uv00, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p10, uv: uv10, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p11, uv: uv11, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p00, uv: uv00, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p11, uv: uv11, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p01, uv: uv01, color: c, texture_layer: layer, _padding: pad });
}

fn main() {
    let entries = vec![
        BitmapEntry { bitmap_id: 0, x: 0.0,  y: 0.0, z: 0.0, w: 10.0, h: 10.0, color: [1.0; 4] },
        BitmapEntry { bitmap_id: 1, x: 20.0, y: 0.0, z: 0.0, w: 10.0, h: 10.0, color: [1.0; 4] },
        BitmapEntry { bitmap_id: 2, x: 40.0, y: 0.0, z: 0.0, w: 10.0, h: 10.0, color: [1.0; 4] },
    ];
    
    let mut verts = Vec::new();
    for e in &entries {
        push_quad_vertices(&mut verts, e);
    }
    
    println!("Total {} vertices", verts.len());
    for (i, v) in verts.iter().enumerate() {
        println!("  v{}: layer={}", i, v.texture_layer);
    }
    
    // 验证:每个三角形内 layer 一致
    for tri_start in (0..verts.len()).step_by(3) {
        let l0 = verts[tri_start].texture_layer;
        let l1 = verts[tri_start+1].texture_layer;
        let l2 = verts[tri_start+2].texture_layer;
        assert_eq!(l0, l1);
        assert_eq!(l1, l2);
        println!("Triangle {}: all layer {}", tri_start / 3, l0);
    }
}
```

为什么这么写:`_padding` 让顶点对齐 16 字节,虽然浪费 12 字节,但 SIMD 加载更快(顶点数组加载用 movaps 16 字节指令)。工业级 vertex 布局都要考虑对齐。

## 8 · Rust / Arch 落地代码

下面是 Day 478 完整的 texture array 实现。

```rust
// ========================================
// Vertex 布局(带 layer)
// ========================================

#[repr(C)]
#[derive(Copy, Clone, Debug, bytemuck::Pod, bytemuck::Zeroable)]
struct Vertex {
    pos: [f32; 3],
    uv: [f32; 2],
    color: [f32; 4],
    texture_layer: i32,
    _padding: [u32; 3],        // 对齐到 16 字节
}

// ========================================
// Texture Array 管理
// ========================================

struct TextureArray {
    width: u32,
    height: u32,
    layer_count: u32,
    layers: Vec<Vec<[u8; 4]>>,   // 每层一个 RGBA 像素 buffer
}

impl TextureArray {
    fn new(w: u32, h: u32, max_layers: u32) -> Self {
        Self {
            width: w,
            height: h,
            layer_count: 0,
            layers: Vec::with_capacity(max_layers as usize),
        }
    }
    
    // 上传一个新 layer,返回 layer index
    fn upload_layer(&mut self, pixels: Vec<[u8; 4]>) -> u32 {
        assert_eq!(pixels.len() as u32, self.width * self.height,
                   "layer 尺寸必须和 array 一致");
        let idx = self.layer_count;
        self.layers.push(pixels);
        self.layer_count += 1;
        println!("Upload layer {}: {} pixels", idx, self.width * self.height);
        idx
    }
    
    // 模拟 OpenGL 的 TexStorage3D
    fn allocate_gpu(&self) {
        println!("glTexStorage3D(GL_TEXTURE_2D_ARRAY, mip_levels={}, RGBA8, {}, {}, {})",
                 1, self.width, self.height, self.layer_count);
    }
    
    // 模拟 OpenGL 的 TexSubImage3D
    fn upload_to_gpu(&self) {
        for (layer, pixels) in self.layers.iter().enumerate() {
            let bytes: &[u8] = bytemuck::cast_slice(pixels);
            println!("glTexSubImage3D(... layer={}, {} bytes)", layer, bytes.len());
        }
    }
}

// ========================================
// 完整 Batched Renderer
// ========================================

struct BatchedRenderer {
    texture_array: TextureArray,
    vertex_buffer: Vec<Vertex>,
}

impl BatchedRenderer {
    fn new(tex_array: TextureArray) -> Self {
        Self {
            texture_array: tex_array,
            vertex_buffer: Vec::new(),
        }
    }
    
    fn submit(&mut self, entries: &[BitmapEntry]) {
        self.vertex_buffer.clear();
        self.vertex_buffer.reserve(entries.len() * 6);
        
        for e in entries {
            push_quad_vertices(&mut self.vertex_buffer, e);
        }
        
        // 一次性上传 + 一次 draw call
        let bytes: &[u8] = bytemuck::cast_slice(&self.vertex_buffer);
        println!("\n=== Render pass ===");
        println!("Upload {} vertex bytes", bytes.len());
        println!("Bind texture array (single bind)");
        println!("glDrawArrays(GL_TRIANGLES, 0, {})", self.vertex_buffer.len());
        println!("=== 1 draw call total ===");
    }
}

#[derive(Debug)]
struct BitmapEntry {
    bitmap_id: u32,            // 用作 texture layer index
    x: f32, y: f32, z: f32,
    w: f32, h: f32,
    color: [f32; 4],
}

fn push_quad_vertices(verts: &mut Vec<Vertex>, e: &BitmapEntry) {
    let layer = e.bitmap_id as i32;
    let c = e.color;
    let z = e.z;
    let pad = [0; 3];
    
    let p00 = [e.x,     e.y,     z];
    let p10 = [e.x+e.w, e.y,     z];
    let p11 = [e.x+e.w, e.y+e.h, z];
    let p01 = [e.x,     e.y+e.h, z];
    let uv00 = [0.0, 0.0];
    let uv10 = [1.0, 0.0];
    let uv11 = [1.0, 1.0];
    let uv01 = [0.0, 1.0];
    
    verts.push(Vertex { pos: p00, uv: uv00, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p10, uv: uv10, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p11, uv: uv11, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p00, uv: uv00, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p11, uv: uv11, color: c, texture_layer: layer, _padding: pad });
    verts.push(Vertex { pos: p01, uv: uv01, color: c, texture_layer: layer, _padding: pad });
}
```

出错怎么办:

- **黑屏 / 纹理错乱** —— layer 字段没传对。检查 shader 是不是 `flat in int`,vertexAttribPointer 是不是用了 I(integer)版本。
- **`GL_INVALID_VALUE` in TexStorage3D** —— width/height/layer_count 超出 GPU 限制。查 `GL_MAX_ARRAY_TEXTURE_LAYERS`(通常 2048+)和 `GL_MAX_TEXTURE_SIZE`(通常 16384)。
- **layer 0 全黑** —— TexSubImage3D 的 offset 参数错。layer 数据应该写到对应 layer offset,不是写到 0。

## 10 · 复习要点

读完这一天你应该能用 30 秒回答以下问题:

**Q1**:Texture array 解决什么问题?
> 多纹理单 draw call。所有纹理叠在一个 GL_TEXTURE_2D_ARRAY 里,shader 用 layer index 选纹理。

**Q2**:Texture array 的限制是什么?
> 所有 layer 必须同宽同高同 format。因为 GPU 用 SIMD 同时采样多个 layer,要求地址计算一致。

**Q3**:为什么 layer 字段必须用 `flat in int` 而不是普通 `in int`?
> GPU 默认对 fragment shader 输入插值,整数无法插值。`flat` 修饰符告诉 GPU 不插值,用 provoking vertex 的值。

**Q4**:Texture array 和 texture atlas 有什么区别?
> Atlas 是拼图(UV 偏移),支持不同尺寸但 UV 计算复杂。Array 是分层(layer index),要求同尺寸但采样简单。

**Q5**:bindless textures 比 texture array 强在哪?
> Bindless 允许任意尺寸纹理直接用 handle 采样,无 bind。但它是 NV/现代 GPU 扩展,兼容性差。
