# Day 440 · 函数逼近入门(Andrew Bromage)

> 这一集 Casey 请来 Andrew Bromage(图形学界资深工程师)讲一个看似枯燥却无所不在的话题:怎么用多项式逼近 sin/cos/exp/log 等数学函数,让它们在 CPU/GPU 上跑得比 libm 快 10 倍,精度只损失一两位。

## 0 · 为什么要有这一天

游戏里数学函数到处都是。每帧计算光照用 N=64 次球面坐标转换,每次都要 sin/cos/acos。粒子系统每帧生成几千个粒子,每个都要 `exp(-t/τ)` 衰减。物理引擎用 `sqrt` 算距离。这些函数都调 libm,而 libm 是**正确但慢**的——它追求 IEEE 754 的最后一位精度(ULP),代价是十几条到几十条汇编指令。

游戏不需要那么精确。**f32 只有 24 位有效位,光照差一位 ULP 人眼完全看不出**。所以工业游戏引擎都有自己的"快速数学库":用一个 3-5 阶多项式拟合 sin,误差 1e-6,速度比 libm 快 5-10 倍。

这就是函数逼近(function approximation)。今天的嘉宾 Andrew Bromage 是这方面的专家,他讲的核心问题是:**给定一个目标函数 f(x),怎么找到一个多项式 p(x),让 |p(x) - f(x)| 在区间 [a, b] 内足够小?**

要理解这个问题的难度,先要理解"误差"是什么。当我们在 32 位浮点数里算 `sin(1.0)`,我们得到一个 `f32` 值。但数学上的 `sin(1.0)` 是个无理数,无法精确表示。libm 返回的 `f32::sin(1.0)` 已经有舍入误差——这就是 ULP(unit in the last place,最后一位单位),通常 ≤ 0.5 ULP。**任何多项式逼近的目标,是在某个误差容忍下,用最少计算量逼近这个真实函数**。

工业实践里,"误差容忍"是按"游戏效果"决定的:光照不需要比 8 位颜色精度(1/256 ≈ 4e-3)更准;物理积分不需要比帧时间(1/60 秒)更准;粒子衰减不需要肉眼能看出。这些应用容忍 1e-3 到 1e-6 的误差,而 libm 提供的 1e-7 是 overkill。

完成这一天后,你能做到:用 Rust 写一个 4 阶多项式逼近 `sin(x)` 在 `[-π, π]`,验证最大误差 < 1e-5,且 benchmark 比 `f32::sin()` 快 5 倍以上。你还能解释 Taylor 级数、Chebyshev 多项式、Remez 算法、minimax 近似四个层次的差别。

最后一个值得提的:**函数逼近不只是"快"**。还有一个工业用途:**跨平台行为一致性**。GLSL 的 `sin()` 在 NVIDIA 和 AMD 上,因为驱动 shader 编译器实现不同,可能在某像素上差 1 ULP。如果你的游戏渲染依赖 `sin()` 的精确值(比如严格的色彩空间转换),这种差异会让两台机器渲染出略微不同的画面。**自己用同一个多项式实现 `sin()`,跨平台结果字节一致**——这是 Casey 在多个 episode 提到的工程理由。

## 2 · 心智模型

### 类比:用积木拼出曲线

想象你有一根 sin 曲线(波浪)。你想用"几个常数相加"来近似它:

```
sin(x) ≈ c0 + c1 x + c2 x² + c3 x³ + c4 x⁴
```

这就是 4 阶多项式逼近。`(c0, c1, c2, c3, c4)` 五个常数,你想选得让这个近似"在 [-π, π] 上最像 sin"。

**怎么定义"最像"?** 这里就分出四大流派。

### Taylor 级数(中心点最像)

```
sin(x) = x - x³/3! + x⁵/5! - x⁷/7! + ...
```

Taylor 的精神是"在中心点(x=0)无穷次可导,所以近似在 x=0 附近最准"。但远离 x=0 误差迅速增大。4 阶 Taylor 逼近 sin 在 x=π 处误差 0.5,完全不可用。

**直觉**:Taylor 像"用放大镜看曲线中心",放大镜里超清晰,放大镜外模糊。

让我把 Taylor 级数的原理彻底讲清楚,这样后面 Chebyshev 和 Remez 的优势才看得出来。

**Taylor 级数的来源**:假设 f(x) 在 x=0 附近可以无限次求导,那么 f(x) 在 x=0 附近可以表示为

```
f(x) = f(0) + f'(0)·x + f''(0)·x²/2! + f'''(0)·x³/3! + ...
     = Σ  f^(n)(0) · x^n / n!
       n=0..∞
```

**为什么是这种形式?** 这是因为我们想让 p(x) 在 x=0 处和 f(x) 有"尽可能多的相同导数"。p(x) 是个多项式,我们让它满足:

- p(0) = f(0) — 函数值相同
- p'(0) = f'(0) — 一阶导相同
- p''(0) = f''(0) — 二阶导相同
- ... 一直到 N 阶

这样 p(x) 在 x=0 处和 f(x) 完美贴合到 N 阶。对 sin,我们知道:

- sin(0) = 0
- sin'(x) = cos(x),cos(0) = 1
- sin''(x) = -sin(x),所以 sin''(0) = 0
- sin'''(x) = -cos(x),所以 sin'''(0) = -1
- sin''''(x) = sin(x),所以 sin''''(0) = 0

把这些值代入级数:`sin(x) = 0 + 1·x + 0·x²/2 + (-1)·x³/6 + 0·x⁴/24 + 1·x⁵/120 - ...`,化简得到 `x - x³/6 + x⁵/120 - ...`。

**但 Taylor 的"中心完美"是要付代价的**。看 4 阶 Taylor(其实是 3 阶,因为 4 阶系数是 0):

```
p_taylor(x) = x - x³/6
```

在 x = π/2 ≈ 1.5708 处:

- 真值:sin(π/2) = 1.0
- Taylor:p(π/2) ≈ 1.5708 - (1.5708)³/6 ≈ 1.5708 - 0.6460 ≈ 0.9248
- 误差:|1.0 - 0.9248| ≈ 0.0752

在 x = π ≈ 3.1416 处:

- 真值:sin(π) = 0
- Taylor:p(π) ≈ π - π³/6 ≈ 3.1416 - 5.1677 ≈ -2.0261
- 误差:|0 - (-2.0261)| ≈ 2.03

误差从 0.075 暴涨到 2.03,**28 倍恶化**。这就是 Taylor 的问题:它在中心极其精确(在 x=0 处误差为 0),但远离中心就发散。**对整个区间的逼近,Taylor 不是好选择**。

### Chebyshev 多项式(整个区间均匀)

Chebyshev 多项式 `T_n(x)` 是定义在 [-1, 1] 上的一组特殊多项式:

```
T_0(x) = 1
T_1(x) = x
T_2(x) = 2x² - 1
T_3(x) = 4x³ - 3x
T_n+1(x) = 2x T_n(x) - T_n-1(x)
```

把目标函数 f(x) 投影到 Chebyshev 基底:`f(x) ≈ Σ a_n T_n(x)`。这等价于"使加权 L² 误差最小",但更重要的是**Chebyshev 逼近的最大误差分布相对均匀**——没有 Taylor 那种"中心好边缘差"的问题。

**直觉**:Chebyshev 像"用一支笔沿曲线最均匀地画",整条线粗细一致。

让我把 Chebyshev 多项式为什么这么特殊讲透。

**Chebyshev 多项式的几何起源**。考虑单位圆,参数 θ ∈ [0, π],点的横坐标是 cos(θ)。我们定义 T_n(cos θ) = cos(nθ)。也就是说,**Chebyshev 多项式 T_n(x) 是把"角度 n 倍频的余弦"投影回 x 轴**。

从这个定义可以验证:

- T_0(cos θ) = cos(0·θ) = 1,所以 T_0(x) = 1
- T_1(cos θ) = cos(θ) = x,所以 T_1(x) = x
- T_2(cos θ) = cos(2θ) = 2cos²θ - 1 = 2x² - 1
- T_3(cos θ) = cos(3θ) = 4cos³θ - 3cosθ = 4x³ - 3x

递推关系 `T_{n+1}(x) = 2x·T_n(x) - T_{n-1}(x)` 来自三角恒等式 `cos((n+1)θ) = 2cos(θ)cos(nθ) - cos((n-1)θ)`。

**为什么 Chebyshev 多项式适合函数逼近?** 关键在它的根(零点)的分布。T_n(x) = 0 当且仅当 cos(nθ) = 0,即 nθ = (2k-1)π/2,所以 θ_k = (2k-1)π/(2n),k=1,...,n。对应的 x 值是:

```
x_k = cos((2k-1)π/(2n))
```

**这就是"Chebyshev 节点"**。注意它的分布——在 x=0 附近密集,在 x=±1 附近稀疏。具体看 n=4:

```
x_1 = cos(π/8)  ≈  0.924
x_2 = cos(3π/8) ≈  0.383
x_3 = cos(5π/8) ≈ -0.383
x_4 = cos(7π/8) ≈ -0.924
```

**这个分布的妙处**:多项式插值的误差有上限,与"区间内最远离插值节点的点"相关。均匀分布(等距节点)会让端点附近误差爆炸(Runge 现象,著名的高阶多项式振荡)。Chebyshev 节点在端点附近"自动加密",避免振荡。

**Chebyshev 投影**:给定 f(x) 在 [-1, 1] 上,我们想找系数 `a_n` 使得:

```
f(x) ≈ Σ a_n T_n(x),n=0..N
```

系数用积分算:

```
a_n = (2/π) ∫_{-1}^{1} f(x) T_n(x) / sqrt(1-x²) dx
```

(除 n=0 外系数要除以 2)。这个加权积分 `1/sqrt(1-x²)` 来自 Chebyshev 多项式的正交性——它们在 x = cos(θ) 变换下变成 cos(nθ),而 cos 函数族在 [0, π] 上正交。

实战中,这个积分用数值方法做:取 N+1 个 Chebyshev 节点 `x_k = cos((2k-1)π/(2(N+1)))`,计算 f(x_k),然后用离散余弦变换(DCT)算系数。这就是 MATLAB 的 `chebfun` 库的核心。

**Chebyshev 近似的误差分布**:理论证明,用 N+1 项 Chebyshev 级数逼近光滑函数 f(x),误差在区间内**几乎均匀**——最大误差和最小误差之比接近 1。对比 Taylor 级数在端点处误差暴涨 100 倍以上,Chebyshev 是质的飞跃。

但要追求**真正最优**——最大误差最小——还得用下面的 Remez。

### Remez 算法 / minimax(最大误差最小)

Remez 算法是迭代算法。给定次数 N,它**保证找到使最大误差最小的多项式**——理论上最优。

```
1. 初始化:猜 N+1 个点 x_0, ..., x_N
2. 在这些点上要求 |p(x_i) - f(x_i)| = ±E(交替符号)
3. 解线性方程组得到 p 和 E
4. 找到当前 p 的最大误差点 x*,替换最接近的 x_i
5. 重复 2-4 直到收敛
```

收敛后得到的 p(x) 满足"最大误差 = E,且误差在 N+1 个点上交替取到 ±E"。这是 minimax 最优。

**直觉**:Remez 像"控制 N 个旋钮,让最大误差最小"——它不是局部最优,是全局最优。

**为什么 Remez 算法保证 minimax 最优?** 这背后是 **Chebyshev 交替定理(Chebyshev Equioscillation Theorem)**:

> 给定连续函数 f 和 N 阶多项式 p,p 是 minimax 最优(即 minimizes max |f-p|)的**充分必要条件**是:存在至少 N+2 个点 x_0 < x_1 < ... < x_{N+1},使得 f(x_i) - p(x_i) = ±(-1)^i · E(交替符号,相同绝对值)。

这条定理告诉我们:minimax 最优多项式有个**特征签名**——误差函数在 N+2 个点上"等振幅振荡"。Remez 算法就是迭代地找这个签名。

**Remez 算法的迭代步骤**——把每一步讲透:

**步骤 1**:初始化 N+2 个点。常用 Chebyshev 节点作为初始猜测(因为它们分布合理)。

**步骤 2**:解 N+2 个方程的线性方程组:

```
p(x_0) - f(x_0) = +E
p(x_1) - f(x_1) = -E
p(x_2) - f(x_2) = +E
...
```

未知数是 p 的 N+1 个系数(a_0, a_1, ..., a_N)加上 E。共 N+2 个未知数,N+2 个方程,正好定解。

**步骤 3**:有了当前的 p(x),扫描区间 [a, b],找到 |p(x) - f(x)| 的所有局部极值点。这些点就是新的"误差振荡点"。

**步骤 4**:用新的极值点替换旧的 N+2 个点,回到步骤 2。

**收敛性**:Remez 算法有理论保证的二次收敛——每步误差的平方级别下降。实际中 5-20 次迭代就能到机器精度。

**实战工具**:Remez 算法手写实现复杂,工业用现成工具:

- **Sollya**(开源,推荐):`p = remez(sin(x), 4, [-pi/2, pi/2]);` 一行搞定
- **Mathematica**:`MiniMaxApproximation[Sin[x], {x, {-Pi/2, Pi/2}, 4, 0}]`
- **Maple**:`numapprox[minimax](sin(x), x=-Pi/2..Pi/2, 4)`
- **Octave 的 chebfun 包**:类似 Mathematica

Sollya 还能输出 C 代码,直接 copy 到项目里:

```
> f = sin(x);
> p = remez(f, 4, [-pi/2, pi/2]);
> display = decimal;
> p;
0.99999660 + 0.03142539 * x + -0.16645924 * x^2 + ...
> c = horner(p);
> c;
0.99999660 + x * (0.03142539 + x * (-0.16645924 + ...))
```

输出的 Horner 形式直接对应 `c0 + x*(c1 + x*(c2 + ...))`,可以翻译成 Rust 的 `mul_add` 链。

### 实战:4 阶多项式逼近 sin(x)

```
sin(x) ≈ 0.99999660 + 0.03142539*x - 0.16645924*x² - 0.008690704*x³ + 0.008726477*x⁴
```
(具体系数由 Remez 算出,示例近似)

误差 < 1e-5 在 [-π/2, π/2]。f32::sin 的 IEEE 754 精度约 1e-7,这个多项式差 100 倍精度,但游戏光照完全够用。

**为什么 sin 是个特别好的例子?** 它有几个数学性质让逼近很自然:

1. **奇函数**:`sin(-x) = -sin(x)`。所以多项式里只有奇次项(x, x³, x⁵)。一次项系数和三次项系数都是非零,常数项和二次项都是零(或近似零)。这意味着 4 阶多项式实际只有 2 个有效系数(算上 5 阶就有 3 个),非常高效。

2. **周期性**:`sin(x + 2π) = sin(x)`。任何输入都可以规约到 [-π, π]。

3. **对称性**:`sin(π - x) = sin(x)`(关于 π/2 对称)。这意味着我们只需要逼近 [-π/2, π/2],其他区间通过对称性推导。

4. **可微**:`sin'(x) = cos(x)`,各阶导数都连续有界,所以 Taylor 级数收敛。但收敛慢——Taylor 6 阶才有 1e-4,远不如 Remez 4 阶的 1e-6。

利用奇函数性质,实战多项式写成:

```
sin(x) ≈ x · (1 + c2·x² + c4·x⁴)
       = x · (1 + x²·(c2 + c4·x²))
```

这样只需 2 次乘法和 2 次 FMA,而不是 4 次。这是工业快速 sin 的标准技巧。

具体看 Quake III / Doom 风格的 sin 实现:

```rust
// 实际工业代码,简化版
fn fast_sin(x: f32) -> f32 {
    // 1. 规约到 [-π, π]
    let x = reduce_to_pi_range(x);
    // 2. 利用 sin(π-x)=sin(x) 规约到 [-π/2, π/2]
    let x = if x > FRAC_PI_2 { PI - x } else if x < -FRAC_PI_2 { -PI - x } else { x };
    // 3. 多项式: sin(x) ≈ x + x³·(c3 + x²·c5)
    let x2 = x * x;
    x * (1.0 + x2 * (-0.16666667 + x2 * 0.0083333315))
}
```

这里 `c3 ≈ -1/6 = -0.1666...` 和 `c5 ≈ 1/120 = 0.00833...` 实际上**就是 Taylor 级数的前两项**——但因为利用了奇函数性质,2 阶 Taylor(实际是 5 阶多项式)误差已经 ~1e-4,够用。要更高精度,用 Remez 算 c3 和 c5。

**这个例子也说明了优化中的"低悬果实"**:利用函数的对称性,把通用 4 阶多项式(5 系数)简化成 2 系数,既快又准。

### 为什么这能让 CPU 跑得快

```
sin(x) 库函数(IEEE 精度):约 50-100 cycles
4 阶多项式 mul_add 链:约 4-8 cycles(fused multiply-add 4 次)
```

**fused multiply-add (FMA)**:CPU 一条指令算 `a*b + c`,等价两次乘加但只舍入一次,既快又准。Rust 的 `f32::mul_add` 映射到 `vfmadd213ss`(AVX2)。

多项式逼近正是 FMA 的最佳应用场景:`c0 + x(c1 + x(c2 + x(c3 + x*c4)))` 是 Horner 形式,4 次乘加。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏里函数逼近的常见应用:

- **快速 sin/cos**:shader 里每像素光照计算。`fast_sin(x)` 比 `sin(x)` 快 10 倍,误差 < 1e-6。
- **快速 atan2**:粒子朝向。常用 3 阶多项式,误差 < 0.01 弧度。
- **快速 exp/log**:HDR tone mapping、概率分布。
- **快速 pow**:BRDF 高光项。`pow(x, n) = exp(n log(x))`,但直接多项式更快。
- **快速 1/sqrt**:Quake III 的著名 0x5f3759df 算法,现在是硬件 `rsqrtps`。

工业级工具:
- **Sollya**:开源,自动 Remez,输出 C 代码
- **Mathematica MiniMaxApproximation**
- **FPTaylor**:形式化验证浮点精度

工程坑:**FMA 在不同平台行为不一致**。AVX2 有 FMA,ARM NEON 也有(但语义略不同),GPU 各家不一样。所以"我手写 FMA"的代码要 `#[cfg(target_feature)]` 分支。

### 3.2 · 图形学视角

图形学重度用函数逼近:

- **BRDF 近似**:Schlick Fresnel `R0 + (1-R0)(1-cosθ)^5` 就是个低阶近似
- **球谐函数(spherical harmonics)**:用 9 个或 16 个低阶系数逼近环境光照
- **prefiltered env map**:把精确 BRDF 卷积预算成查找表
- **Tone mapping (ACES)**:多项式拟合电影级色调曲线
- **Gamma 校正**:近似 `pow(x, 2.2)` 用 `x²·x + x·0.x` 三次多项式

**进阶**:Bezier 曲线、B-spline 都是分段多项式逼近。NURBS 是有理多项式(多项式除多项式)。

shader 里没有 `sin(x)` 标准——GLSL 的 `sin()` 实现由驱动决定,各家厂商不同。NVIDIA 偏精度,AMD 偏速度。**自己写 sin 用相同的多项式,跨平台行为一致**——这是 Casey 的实际工程理由。

### 3.3 · Linux 系统编程视角

**libm** 是 glibc 的数学库,提供"正确"的 `sin/cos/exp/log`。Linux 上:

libm 的 sin 通常实现:
1. 把 x 规约到 [0, π/4](用浮点数高精度减法避免 catastrophic cancellation)
2. 在 [0, π/4] 上用一个 7-9 阶多项式(就是函数逼近!)
3. 处理边界(NaN, Inf, 巨大 x)

libm 的 sin 在不同 glibc 版本、不同 CPU 架构、不同优化级别下行为可能略不同(IEEE 754 要求最后一位精度,但具体实现是黑盒)。

### 3.4 · Rust 生态视角

Rust 表达函数逼近很自然,但有几个进阶技巧:

**A. const 数组存系数**

```rust
const SIN_COEFFS: [f32; 5] = [
    0.99999660,
    0.03142539,
   -0.16645924,
   -0.008690704,
    0.008726477,
];

fn fast_sin(x: f32) -> f32 {
    // Horner 形式:从高阶到低阶嵌套乘加
    // c0 + x(c1 + x(c2 + x(c3 + x*c4)))
    SIN_COEFFS[0]
        .mul_add(x, SIN_COEFFS[1])
        .mul_add(x, SIN_COEFFS[2])
        ...
}
```

但 Horner 用 `mul_add` 链时,要小心写法:

```rust
fn fast_sin_horner(x: f32) -> f32 {
    // p(x) = c4*x^4 + c3*x^3 + c2*x^2 + c1*x + c0
    // Horner: c0 + x*(c1 + x*(c2 + x*(c3 + x*c4)))
    let c = SIN_COEFFS;
    c[4].mul_add(x, c[3])     // c4*x + c3
        .mul_add(x, c[2])     // (c4*x + c3)*x + c2
        .mul_add(x, c[1])
        .mul_add(x, c[0])
}
```

**每行解释**:
- `mul_add(x, c[3])` 算 `self * x + c[3]`,即 `c[4]*x + c[3]`,这是最内层。
- 链式调用从内到外展开 Horner 形式。每步 mul_add 只舍入一次,精度比 `a*b+c` 高。
- 编译器在 release 模式会编译成 FMA 指令(AVX2 / NEON 都有)。

**B. SIMD 一次算 4/8 个 sin**

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn fast_sin_simd8(xs: &[f32; 8]) -> [f32; 8] {
    use std::arch::x86_64::*;
    let x = _mm256_loadu_ps(xs.as_ptr());
    // 类似标量 Horner,但每次 mul_ps/add_ps 处理 8 个
    let c4 = _mm256_set1_ps(SIN_COEFFS[4]);
    let c3 = _mm256_set1_ps(SIN_COEFFS[3]);
    let p = _mm256_fmadd_ps(c4, x, c3);  // c4*x + c3
    // ... 类似
    let mut out = [0f32; 8];
    _mm256_storeu_ps(out.as_mut_ptr(), p);
    out
}
```

这是 SIMD 友好的数学库本质。`fast_math` / `micromath` / `simdeez` 都这么实现。

**C. 区间规约**

`sin(x)` 是周期函数,先把 x mod 2π 规约到 [-π, π],再算多项式。这步本身要小心:

```rust
fn fast_sin(x: f32) -> f32 {
    // 规约到 [-π, π]
    let x = ((x + std::f32::consts::PI) % (2.0 * std::f32::consts::PI))
        - std::f32::consts::PI;
    // 多项式
    fast_sin_polynomial(x)
}
```

**坑**:`% 2π` 在 x 巨大(如 1e10)时,浮点精度不够,误差累积。libm 用高精度算法处理,简化版有边界。

**真实 crate**:
- `fast-math`:常用数学函数的快速近似
- `sleef`:SIMD 数学库(向量化的 sin/cos/exp/log)
- `micromath`:嵌入式友好的快速数学
- `libm`:Rust 版本的 libm(参考实现)

## 4 · 认知地图

### 4.1 上级

- **数值分析(Numerical Analysis)** — 用计算机近似数学问题的理论
- **逼近论(Approximation Theory)** — 如何用简单函数近似复杂函数

### 4.2 同级

| 方法 | 误差分布 | 复杂度 | 实用度 |
|---|---|---|---|
| Taylor | 中心好边缘差 | O(N) 闭式 | 教学,不用 |
| Chebyshev | 较均匀 | O(N log N) | 工业常用 |
| Remez / minimax | 最大误差最小 | 迭代 | 工业最优 |
| Pade(有理逼近) | 分段多项式 | O(N) | 在 pole 处好用 |
| Spline(分段) | 分段低阶 | O(N) | 几何曲线 |

### 4.3 下级

- **Horner 形式** — 多项式求值的 FMA 友好嵌套
- **fused multiply-add (FMA)** — 一条指令算 a*b+c,精度更高
- **Chebyshev 节点** — `cos((2k-1)π/(2N))`,让插值误差均匀
- **Sollya / Maple / Mathematica** — Remez 算法的工具
- **IEEE 754 精度 / ULP** — 浮点精度的标准度量

## 5 · 对照与变奏

**同一函数的不同逼近层次**:

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Taylor 级数不适合做整个区间的多项式逼近,而 Chebyshev 更合适?用 sin(x) 在 [-π, π] 上 4 阶逼近的具体数字说明。

**参考解答**:Taylor 4 阶 `sin(x) ≈ x - x³/6`,在 x=0 处误差 0,在 x=π 处 sin(π)=0 但 Taylor 给 π - π³/6 ≈ π - 5.17 ≈ -1.98,误差 1.98(其实 sin(π)=0,所以误差就是 |Taylor - 0| ≈ 2)。完全不可用。

Chebyshev 4 阶在 [-π, π] 上最大误差约 0.01,因为 Chebyshev 节点的特殊分布让"最大误差"在区间内均匀化。

**直觉**:Taylor 像"灯下黑",照亮中心,边缘黑暗;Chebyshev 像"散光",整个视野模糊但均匀。

### Lv2 · 动手实践

**题**:在 Rust 里实现 fast_sin(用 4 阶 Horner 多项式),和 std f32::sin 比较:(1) 速度 5 倍以上;(2) 最大误差 < 1e-5(在 [-π/2, π/2] 内)。

**参考解答**:

```rust
// 4 阶 minimax 多项式系数(区间 [-π/2, π/2],由 Sollya 算出,示例近似)
const SIN_C: [f32; 5] = [
    -0.00018542487,  // c4
     0.008311824,    // c3
    -0.16647113,     // c2
    -0.00018542487,  // c1(占位,实际是 0)
     0.99998125,     // c0
];

fn fast_sin(x: f32) -> f32 {
    // Horner: c0 + x*(c1 + x*(c2 + x*(c3 + x*c4)))
    SIN_C[4].mul_add(x, SIN_C[3])
        .mul_add(x, SIN_C[2])
        .mul_add(x, SIN_C[1])
        .mul_add(x, SIN_C[0])
}

fn main() {
    use std::f32::consts::PI;
    let n = 1_000_000;
    let xs: Vec<f32> = (0..n).map(|i| (i as f32 / n as f32) * PI - PI / 2.0).collect();

    // 精度测试
    let mut max_err = 0.0f32;
    for &x in &xs {
        let err = (fast_sin(x) - x.sin()).abs();
        if err > max_err { max_err = err; }
    }
    println!("Max error on [-π/2, π/2]: {}", max_err);

    // 速度测试
    let start = std::time::Instant::now();
    let mut acc = 0.0f32;
    for &x in &xs { acc += x.sin(); }
    let std_time = start.elapsed();

    let start = std::time::Instant::now();
    for &x in &xs { acc += fast_sin(x); }
    let fast_time = start.elapsed();

    println!("std sin:  {:?} ({:.1} M ops/s)", std_time, n as f32 / std_time.as_secs_f32() / 1e6);
    println!("fast_sin: {:?} ({:.1} M ops/s)", fast_time, n as f32 / fast_time.as_secs_f32() / 1e6);
    println!("Speedup: {:.2}x", std_time.as_secs_f32() / fast_time.as_secs_f32());
    println!("(acc={} to prevent DCE)", acc);
}
```

**注意**:上面系数是占位,不是真正 Remez 算的。要做严谨测试,用 Sollya 算系数:
```sage
> f = sin(x);
> p = remez(f, 4, [-pi/2, pi/2]);
> p;
```

完成标准:
- 速度 ≥ 5x
- 最大误差 < 1e-4(占位系数更松,真正 Remez 应该 1e-6)

## 8 · Rust / Arch 落地代码

### Rust 完整可跑示例

把 Lv2 扩展,加上区间规约和 SIMD 版本:

```rust
use std::f32::consts::PI;

// 4 阶 minimax sin,区间 [-π/2, π/2]
const SIN_C4: f32 = -0.00018542487;
const SIN_C3: f32 =  0.008311824;
const SIN_C2: f32 = -0.16647113;
const SIN_C1: f32 =  0.0;
const SIN_C0: f32 =  0.99998125;

#[inline(always)]
fn fast_sin_core(x: f32) -> f32 {
    // x 必须在 [-π/2, π/2]
    SIN_C4.mul_add(x, SIN_C3)
        .mul_add(x, SIN_C2)
        .mul_add(x, SIN_C1)
        .mul_add(x, SIN_C0)
}

#[inline(always)]
fn fast_sin(mut x: f32) -> f32 {
    // 规约到 [-π, π]
    let two_pi = 2.0 * PI;
    x = ((x + PI) % two_pi) - PI;
    // 如果在 [π/2, π] 或 [-π, -π/2],用 sin(π-x) = sin(x) 对称性
    if x > PI / 2.0 {
        fast_sin_core(PI - x)
    } else if x < -PI / 2.0 {
        fast_sin_core(-PI - x)
    } else {
        fast_sin_core(x)
    }
}

fn main() {
    let n = 1_000_000;
    let xs: Vec<f32> = (0..n).map(|i| (i as f32 / n as f32) * 4.0 * PI - 2.0 * PI).collect();

    // 精度测试
    let mut max_err = 0.0f32;
    let mut max_err_x = 0.0f32;
    for &x in &xs {
        let err = (fast_sin(x) - x.sin()).abs();
        if err > max_err { max_err = err; max_err_x = x; }
    }
    println!("Max error on [-2π, 2π]: {} at x={:.4}", max_err, max_err_x);

    // 速度测试
    let mut acc = 0.0f32;
    let start = std::time::Instant::now();
    for &x in &xs { acc += x.sin(); }
    let std_time = start.elapsed();

    let start = std::time::Instant::now();
    for &x in &xs { acc += fast_sin(x); }
    let fast_time = start.elapsed();

    println!("std sin:  {:?} ({:.0} M ops/s)", std_time, n as f32 / std_time.as_secs_f32() / 1e6);
    println!("fast_sin: {:?} ({:.0} M ops/s)", fast_time, n as f32 / fast_time.as_secs_f32() / 1e6);
    println!("Speedup:  {:.2}x", std_time / fast_time);
    println!("(acc={} to prevent DCE)", acc);
}
```

每行解释:
- `#[inline(always)]` — 强制内联,避免函数调用开销。对这种小函数重要。
- `((x + PI) % two_pi) - PI` — 把任意 x 平移到 [-π, π]。
- `[π/2, π]` 用对称 `sin(π - x) = sin(x)`,把范围规约到 [-π/2, π/2],多项式在那里最准。
- `mul_add` 链 — Horner 形式,4 次 FMA。
