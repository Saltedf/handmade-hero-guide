# Day 534 · 多瓦片导入的启发式 alpha 测试

> 一个 sprite sheet PNG 里切出 100 个瓦片(tile),每个瓦片大小不一——有的占 32×32,有的占 64×64。如何**自动判断**每个瓦片的实际"有效边界"(去掉透明边缘)?Day 534 Casey 用**启发式(heuristic)alpha 测试**:扫描每个瓦片,找最小/最大非透明像素,得到实际边界。这是图像处理的基础操作——bbox(bounding box)计算。

## 0 · 为什么要有这一天

美术做一张 sprite sheet,每个角色周围有大量透明像素——美术为了对齐方便,把所有角色放到同样大小的方框里(比如都是 64×64),但实际角色只占 32×40。导入时如果不"裁剪"透明边缘,会浪费 GPU 内存(纹理大)和绘制开销(overdraw 多)。

**启发式 alpha 测试**:对每个瓦片,扫描所有像素,找 alpha > 阈值的像素的 min_x、max_x、min_y、max_y,这就是有效边界。Casey 选阈值 0(任何非完全透明都算),也可以选更高(比如 alpha > 128)容忍半透明边缘。

这种"启发式"叫 heuristic(启发式),因为它是**经验规则**,不是严格证明的最优算法。它对大多数 sprite sheet 工作良好,但偶尔翻车——比如角色身上有意有透明洞(像甜甜圈),启发式会找到错误的内边界。但这种边角情况少见,启发式够用。

启发式算法在工程中无处不在:

- **垃圾回收**:启发式预测哪些对象是垃圾(不是精确分析)
- **TCP 拥塞控制**:启发式估计网络拥塞
- **CSS 选择器匹配**:启发式优化(右到左匹配)
- **缓存替换**:LRU 是启发式(不是真正"最不常用")

#### 启发式 vs 精确算法的工程权衡

让我把"启发式 vs 精确"的工程决策讲清楚,因为这是工业级开发的日常。

**精确算法**:数学上证明正确,但有约束(假设输入满足某种条件)。例:排序算法——保证输出有序。

**启发式算法**:经验上"大多正确",但无严格保证。例:alpha 测试——大多数 sprite sheet 工作,但甜甜圈角色翻车。

工程权衡:

| 算法类型 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|
| 精确 | 100% 正确 | 可能慢 / 复杂 / 不存在 | 安全关键、医疗、金融 |
| 启发式 | 快 / 简单 / 通用 | 偶尔翻车 | 实时系统、大数据、机器学习 |

工业级项目大量用启发式,因为**精确算法往往不存在或代价过高**。比如垃圾回收的"精确版本"需要程序暂停(Stop-The-World),代价 unacceptable;启发式(并发标记)允许少量错误但低延迟。

#### Casey 的 alpha 测试的具体公式

让我把 Casey 的 alpha 测试数学化:

```
对瓦片 W:
  min_x = min { x | 存在 y, alpha(x, y) > threshold }
  max_x = max { x | 存在 y, alpha(x, y) > threshold }
  min_y = min { y | 存在 x, alpha(x, y) > threshold }
  max_y = max { y | 存在 x, alpha(x, y) > threshold }
  bbox = (min_x, min_y, max_x - min_x + 1, max_y - min_y + 1)
```

复杂度:O(N×M) 扫描所有像素。对 64×64 瓦片 = 4096 像素,毫秒级完成。

工业级优化:**并行化**。GPU shader 可以并行扫描多个瓦片,几百倍加速。但 Casey 用 CPU 串行,因为离线工具不在乎速度。

#### "Alpha threshold"的选择

Casey 选 threshold = 0(任何 alpha > 0 都算非透明),但实际有更多选项:

- **threshold = 0**:最严格,任何半透明像素都算。bbox 最大
- **threshold = 128**:中间,容忍抗锯齿边缘。bbox 中等
- **threshold = 254**:最宽松,只算几乎不透明的像素。bbox 最小

选择策略:

- 像素艺术游戏(无 AA):threshold = 0,精确
- 高保真游戏(有 AA):threshold = 128,避免边缘像素影响 bbox
- 特效 sprite(大量半透明):threshold = 254,只算核心像素

Casey 的 HH 接近像素艺术,threshold = 0 合适。你的项目按美术风格选择。

- 能写 bbox(bounding box)计算
- 知道图像处理中的 alpha 测试应用
- 能权衡 alpha threshold 的选择

## 1 · Casey 今天做了什么

Casey 这一天的动作可以拆成三步:

第一步,他**遍历每个瓦片**:对 PNG atlas 里的每个瓦片(已知其在 atlas 中的位置和大小),提取出独立的像素数组。

第二步,他**计算 bbox**:对每个瓦片,扫描所有像素,记录 alpha > 0 的像素的最小/最大 x、y。返回 `(min_x, min_y, max_x, max_y)`。

第三步,他**用 bbox 替代原瓦片大小**:导入时,只保存 bbox 内的像素,atlas metadata 记录 bbox 偏移。运行时画 sprite 时,从 bbox 偏移开始画,不再画整个 64×64 方框。

视频里他强调:这种"自动裁剪"省了大量内存——一张 atlas 100 个瓦片,每个 64×64,如果都"实占"32×40,内存占用减少 60%。

## 2 · 心智模型

### 类比:拍照后的"自动裁剪"

你拍了 100 张照片,每张构图很松(主体居中,周围是空白)。后期处理软件的"自动裁剪"功能:扫描每张照片,找主体的边界,自动裁掉空白。100 张照片每张变紧凑。

Casey 的启发式 alpha 测试就是这种"自动裁剪"——找有效像素的边界,去掉透明边缘。

### 严谨展开:启发式 vs 精确算法

**精确算法(exact algorithm)**:严格证明的正确性。例如排序——quick sort 一定把数据排好序,可证明。

**启发式(heuristic)**:经验规则,大多数情况下工作良好,但不保证最优。例如 LRU 缓存——丢弃"最久未用"项,假设"最近未用的将来也不太用",但不保证。

启发式适用于:

- **NP-hard 问题**:精确解太慢,用启发式找近似解
- **实时系统**:来不及精确分析
- **数据脏**:精确算法对干净数据有效,脏数据用启发式鲁棒

Casey 的 alpha 测试是启发式,因为:(1)美术数据不严格(可能有噪点 alpha);(2)不需要完美 bbox(误差 1-2 像素无视觉影响);(3)速度优先(扫描每个像素一次,O(N))。

### bbox 算法

```rust
fn compute_alpha_bbox(
    pixels: &[u8],
    width: u32,
    height: u32,
    channels: u32,  // 4 = RGBA
    alpha_threshold: u8,
) -> Option<(u32, u32, u32, u32)> {
    let mut min_x = u32::MAX;
    let mut max_x = 0u32;
    let mut min_y = u32::MAX;
    let mut max_y = 0u32;
    let mut found = false;
    
    for y in 0..height {
        for x in 0..width {
            let alpha = pixels[(y * width + x) * channels + 3] as u32;  // 假设 RGBA,alpha 在第 4 字节
            if alpha > alpha_threshold as u32 {
                min_x = min_x.min(x);
                max_x = max_x.max(x);
                min_y = min_y.min(y);
                max_y = max_y.max(y);
                found = true;
            }
        }
    }
    
    if found {
        Some((min_x, min_y, max_x, max_y))
    } else {
        None  // 完全透明,没有有效像素
    }
}
```

时间复杂度:O(width × height)。对 64×64 = 4096 像素的瓦片,极快。对整张 4096×4096 atlas,1600 万像素,在 3 GHz CPU 上约 5ms——可接受。

#### 处理"甜甜圈"问题:连通分量分析

Casey 的启发式对"带洞"的 sprite 翻车——bbox 把洞也算进有效区域。工业级方案:**连通分量分析(connected component analysis)**。

算法:
1. 把图像二值化(alpha > threshold → 1,否则 → 0)
2. 用 flood fill 找所有连通分量
3. 对每个连通分量计算 bbox
4. 选择"最大"或"最中央"的分量作为有效 sprite

这种算法复杂度 O(N),但实现比简单 bbox 复杂 10 倍。Casey 不做,因为他的 sprite sheet 没有甜甜圈。

工业级场景:
- 物体识别(autonomous driving):每辆车是一个连通分量
- 文字识别(OCR):每个字符是独立分量
- 医学图像分割:每个器官是独立分量

OpenCV 的 `connectedComponents` 函数是这个领域的工业标准。Rust 的 `imageproc` 也有。学会这个,你的 sprite 工具能处理任意复杂的 sprite sheet。

### 多瓦片循环

```rust
fn process_sprite_sheet(
    atlas: &[u8],
    atlas_w: u32,
    atlas_h: u32,
    tiles: &[(u32, u32, u32, u32)],  // (tile_x, tile_y, tile_w, tile_h) 列表
) -> Vec<Option<(u32, u32, u32, u32)>> {
    let mut results = Vec::with_capacity(tiles.len());
    for &(tx, ty, tw, th) in tiles {
        // 提取瓦片像素
        let mut tile_pixels = vec![0u8; (tw * th * 4) as usize];
        for y in 0..th {
            for x in 0..tw {
                let src_idx = ((ty + y) * atlas_w + (tx + x)) as usize * 4;
                let dst_idx = (y * tw + x) as usize * 4;
                tile_pixels[dst_idx..dst_idx+4].copy_from_slice(&atlas[src_idx..src_idx+4]);
            }
        }
        // 计算 bbox
        let bbox = compute_alpha_bbox(&tile_pixels, tw, th, 4, 0);
        results.push(bbox);
    }
    results
}
```

### 启发式失败的情况

Casey 的启发式对甜甜圈角色翻车——外边界正常找到,但内洞的边界丢失(因为算法找的是"有效像素的边界",不是"角色形状的边界")。修复:

- **方案 A**:接受失败,美术手工标注
- **方案 B**:更复杂算法(轮廓追踪)
- **方案 C**:要求美术不画有透明洞的角色

Casey 选 A——甜甜圈角色很少,美术手工标注成本低于写复杂算法。

### 3.2 · 图形学视角

GPU 上也有 bbox 计算——**occlusion culling**(遮挡剔除)用 bbox 决定是否绘制物体。计算 shader 可以并行算 bbox(每个线程处理一个像素,原子更新 min/max)。

GPU 算法:

```glsl
shared uvec4 bbox;  // (min_x, min_y, max_x, max_y)

void main() {
    uint x = gl_GlobalInvocationID.x;
    uint y = gl_GlobalInvocationID.y;
    if (pixel_has_alpha(x, y)) {
        atomicMin(bbox.x, x);
        atomicMin(bbox.y, y);
        atomicMax(bbox.z, x);
        atomicMax(bbox.w, y);
    }
}
```

原子操作保证多线程安全。GPU 上 1600 万像素的 bbox 计算可在 0.1ms 内完成。

### 3.3 · Linux 系统编程视角

Linux 内核的 memory compaction 用类似算法——扫描页表找连续可用页。这是"扫描找边界"在内核的应用。

ImageMagick 的 `-trim` 命令做同样的事:

```bash
convert input.png -trim output.png  # 自动裁掉边缘
convert input.png -trim -fuzz 10% output.png  # 容忍 10% 颜色差异
```

让我把"启发式算法"在不同领域的对照列出来:

**游戏开发**:

**编译器**:

- 内联决策(基于代码大小 + 调用频率,启发式)

**机器学习**(全是启发式):
- 梯度下降(找局部最优,不保证全局)
- Dropout(启发式正则化)
- Batch size(经验选择,不是最优)

工业级工程师**对启发式既爱又恨**:爱它快、简单、能用;恨它偶尔翻车、无法证明正确。学会**何时用启发式、何时必须精确**是工程师的判断力。

### 历史回顾:启发式算法的兴起

1970s 以前,计算机科学家追求精确算法。NP 完全性理论(1971)证明很多问题**没有**多项式时间精确解,于是转向启发式。

1990s 互联网兴起,实时性要求让启发式大爆发。Google PageRank 是启发式(网页重要性估计),TCP/IP 拥塞控制是启发式,Web 缓存策略是启发式。

2020s 机器学习时代,几乎所有"智能"系统都是启发式——神经网络本质是高维函数拟合,没有逻辑证明,只有经验效果。

Casey 的 alpha 测试和 PageRank 是同一种思维:**经验上有效就行,不追求完美**。这种"工程现实主义"是软件开发的核心精神。



bbox 计算在不同领域:

- **2D 图像**:Casey 这天做的
- **3D 模型**:mesh 的 AABB(axis-aligned bounding box)
- **物理引擎**:碰撞检测的 AABB
- **字体**:glyph 的 ink box(墨水边界)
- **OCR**:文字检测的字符 bbox

每种场景的算法都是"扫描找 min/max"。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Casey 用 alpha > 0 作为阈值。为什么不用 alpha > 128?

**参考解答**:两种阈值各有道理。alpha > 0 简单——任何有像素都算,边界宽松(包含半透明边缘)。alpha > 128 严格——只有"足够不透明"才算,边界紧(忽略半透明边缘)。Casey 选 alpha > 0 因为他想保留半透明边缘(超采样产生的 anti-aliased 边缘),不裁掉它们——否则字体边缘会变锯齿。如果选 alpha > 128,半透明边缘被忽略,bbox 更紧但边缘像素丢失。

### Lv2 · 动手实践

**题**:写一个函数 `compute_bbox(pixels, width, height) -> Option<(u32, u32, u32, u32)>`,扫描 RGBA 像素找 alpha > 0 的边界。生成一个测试图像:64×64,中间画一个 30×40 的非透明矩形,周围全透明。运行后:bbox 是 (17, 12, 46, 51)(min_x=17 因为矩形从 x=17 开始)。

**参考解答**:

```rust
fn compute_bbox(
    pixels: &[u8],
    width: u32,
    height: u32,
) -> Option<(u32, u32, u32, u32)> {
    let mut min_x = u32::MAX;
    let mut min_y = u32::MAX;
    let mut max_x = 0u32;
    let mut max_y = 0u32;
    let mut found = false;
    
    for y in 0..height {
        for x in 0..width {
            let alpha = pixels[((y * width + x) * 4 + 3) as usize];
            if alpha > 0 {
                min_x = min_x.min(x);
                max_x = max_x.max(x);
                min_y = min_y.min(y);
                max_y = max_y.max(y);
                found = true;
            }
        }
    }
    
    if found {
        Some((min_x, min_y, max_x, max_y))
    } else {
        None
    }
}

fn main() {
    let width = 64u32;
    let height = 64u32;
    let mut pixels = vec![0u8; (width * height * 4) as usize];  // 全透明
    
    // 画一个 30x40 的非透明矩形,从 (17, 12) 开始
    for y in 12..52 {
        for x in 17..47 {
            let idx = ((y * width + x) * 4) as usize;
            pixels[idx..idx+4].copy_from_slice(&[255, 0, 0, 255]);  // 不透明红
        }
    }
    
    match compute_bbox(&pixels, width, height) {
        Some((min_x, min_y, max_x, max_y)) => {
            println!("bbox: ({}, {}) to ({}, {})", min_x, min_y, max_x, max_y);
            println!("大小: {}x{}", max_x - min_x + 1, max_y - min_y + 1);
        }
        None => println!("全透明"),
    }
}
```

```bash
# 大小: 30x40
```

为什么这么写:`min_x = u32::MAX` 是个常用技巧——初始化为最大,任何值都比它小,所以第一个有效像素立刻更新 min_x。`u32::MAX` 是 Rust 的关联常量。`min_x.min(x)` 是 `std::cmp::min` 的方法语法。

### Lv3 · 迁移设计

**题**:3D 模型的 AABB 计算类似——扫描所有顶点,找 x/y/z 的 min/max。设计函数 `compute_mesh_aabb(vertices: &[Vec3]) -> AABB`,返回 `(min: Vec3, max: Vec3)`。考虑:如果 mesh 有几千个顶点,如何并行计算?提示:用 `rayon` crate 的 `par_iter`。

**提示**:`rayon` 提供 `par_iter().reduce(|| initial, |a, b| combine(a, b))` 模式做并行 reduce。

**详细参考**:

```rust
use rayon::prelude::*;

#[derive(Clone, Copy, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }

#[derive(Clone, Copy, Debug)]
struct AABB { min: Vec3, max: Vec3 }

fn compute_mesh_aabb_serial(vertices: &[Vec3]) -> AABB {
    let mut min = Vec3 { x: f32::MAX, y: f32::MAX, z: f32::MAX };
    let mut max = Vec3 { x: f32::MIN, y: f32::MIN, z: f32::MIN };
    for v in vertices {
        min.x = min.x.min(v.x);
        min.y = min.y.min(v.y);
        min.z = min.z.min(v.z);
        max.x = max.x.max(v.x);
        max.y = max.y.max(v.y);
        max.z = max.z.max(v.z);
    }
    AABB { min, max }
}

fn compute_mesh_aabb_parallel(vertices: &[Vec3]) -> AABB {
    vertices.par_iter().fold(
        || AABB {
            min: Vec3 { x: f32::MAX, y: f32::MAX, z: f32::MAX },
            max: Vec3 { x: f32::MIN, y: f32::MIN, z: f32::MIN },
        },
        |acc, v| AABB {
            min: Vec3 {
                x: acc.min.x.min(v.x),
                y: acc.min.y.min(v.y),
                z: acc.min.z.min(v.z),
            },
            max: Vec3 {
                x: acc.max.x.max(v.x),
                y: acc.max.y.max(v.y),
                z: acc.max.z.max(v.z),
            },
        }
    ).reduce(
        || AABB {
            min: Vec3 { x: f32::MAX, y: f32::MAX, z: f32::MAX },
            max: Vec3 { x: f32::MIN, y: f32::MIN, z: f32::MIN },
        },
        |a, b| AABB {
            min: Vec3 {
                x: a.min.x.min(b.min.x),
                y: a.min.y.min(b.min.y),
                z: a.min.z.min(b.min.z),
            },
            max: Vec3 {
                x: a.max.x.max(b.max.x),
                y: a.max.y.max(b.max.y),
                z: a.max.z.max(b.max.z),
            },
        }
    )
}
```

工业级 mesh 通常有 10000-1000000 个顶点,并行计算能省 4-8 倍时间(取决于 CPU 核心数)。这是 rayon 在游戏引擎里的典型应用。

## 8 · Rust / Arch 落地代码

```rust
// 完整的多瓦片 bbox 计算 + 裁剪

#[derive(Debug, Clone)]
pub struct Tile {
    pub atlas_x: u32,
    pub atlas_y: u32,
    pub width: u32,
    pub height: u32,
    pub bbox: Option<(u32, u32, u32, u32)>,  // min_x, min_y, max_x, max_y(相对 tile)
}

pub struct Atlas {
    pub width: u32,
    pub height: u32,
    pub pixels: Vec<u8>,  // RGBA
    pub tiles: Vec<Tile>,
}

impl Atlas {
    /// 启发式计算每个 tile 的 bbox
    pub fn compute_all_bboxes(&mut self, alpha_threshold: u8) {
        for tile in &mut self.tiles {
            tile.bbox = self.compute_tile_bbox(tile, alpha_threshold);
        }
    }
    
    fn compute_tile_bbox(&self, tile: &Tile, alpha_threshold: u8) -> Option<(u32, u32, u32, u32)> {
        let mut min_x = u32::MAX;
        let mut min_y = u32::MAX;
        let mut max_x = 0u32;
        let mut max_y = 0u32;
        let mut found = false;
        
        for local_y in 0..tile.height {
            for local_x in 0..tile.width {
                let global_x = tile.atlas_x + local_x;
                let global_y = tile.atlas_y + local_y;
                let idx = ((global_y * self.width + global_x) * 4) as usize;
                let alpha = self.pixels[idx + 3];
                
                if alpha > alpha_threshold {
                    min_x = min_x.min(local_x);
                    max_x = max_x.max(local_x);
                    min_y = min_y.min(local_y);
                    max_y = max_y.max(local_y);
                    found = true;
                }
            }
        }
        
        if found { Some((min_x, min_y, max_x, max_y)) } else { None }
    }
    
    /// 统计节省的内存
    pub fn memory_savings(&self) -> f32 {
        let mut original_bytes = 0u64;
        let mut bbox_bytes = 0u64;
        
        for tile in &self.tiles {
            let tile_bytes = (tile.width * tile.height * 4) as u64;
            original_bytes += tile_bytes;
            
            if let Some((min_x, min_y, max_x, max_y)) = tile.bbox {
                let bbox_w = max_x - min_x + 1;
                let bbox_h = max_y - min_y + 1;
                bbox_bytes += (bbox_w * bbox_h * 4) as u64;
            } else {
                bbox_bytes += tile_bytes;  // 全透明,不变
            }
        }
        
        if original_bytes == 0 { return 0.0; }
        1.0 - (bbox_bytes as f32 / original_bytes as f32)
    }
}

fn main() {
    // 模拟一个 128x128 atlas,有 4 个 64x64 tile
    let mut atlas = Atlas {
        width: 128, height: 128,
        pixels: vec![0u8; 128 * 128 * 4],
        tiles: vec![
            Tile { atlas_x: 0,   atlas_y: 0,  width: 64, height: 64, bbox: None },
            Tile { atlas_x: 64,  atlas_y: 0,  width: 64, height: 64, bbox: None },
            Tile { atlas_x: 0,   atlas_y: 64, width: 64, height: 64, bbox: None },
            Tile { atlas_x: 64,  atlas_y: 64, width: 64, height: 64, bbox: None },
        ],
    };
    
    // 在每个 tile 中间画一个小矩形(模拟"实际 sprite")
    for tile_idx in 0..4 {
        let tile = &atlas.tiles[tile_idx];
        let offset_x = tile.atlas_x + 16;  // 内边距 16
        let offset_y = tile.atlas_y + 12;
        for y in 0..40 {
            for x in 0..32 {
                let px = offset_x + x;
                let py = offset_y + y;
                let idx = ((py * 128 + px) * 4) as usize;
                atlas.pixels[idx..idx+4].copy_from_slice(&[255, 100, 50, 255]);
            }
        }
    }
    
    // 计算 bbox
    atlas.compute_all_bboxes(0);
    
    // 打印结果
    println!("=== Tile bbox 结果 ===");
    for (i, tile) in atlas.tiles.iter().enumerate() {
        if let Some((min_x, min_y, max_x, max_y)) = tile.bbox {
            println!("Tile {}: bbox ({},{}) to ({},{}) = {}x{}",
                i, min_x, min_y, max_x, max_y,
                max_x - min_x + 1, max_y - min_y + 1);
        }
    }
    
    let savings = atlas.memory_savings();
    println!("\n内存节省: {:.1}%", savings * 100.0);
}
```

出错怎么办:

- **`bbox` 范围错**:检查 `global_x` 和 `local_x` 的转换。bbox 应该是 `local` 坐标,不是 atlas 坐标。
