
# Day 570 · 区分光源与遮挡物

> Voxel grid 里有两类 occupied voxel:光源(发光)和遮挡物(墙,不发光)。Day 569 raycast 把它们都当"挡光",结果光源被错误遮挡。Day 570 Casey 加 **light vs occluder 区分**——raycast 撞光源时,光源的颜色贡献给 ray,不立刻停。

## 0 · 为什么要有这一天

让我们把镜头贴近画面,看到这个 bug。你跟着 Handmade Hero 走到 Day 569——Casey 写了 raycast 让 probe 探测环境。场景里有一个**火把**和一个**墙**。火把在 (5, 5, 5),墙在 (10, 5, 5)。你期待玩家朝火把看时,看到一片火光;玩家朝墙看时,看到墙被火把照亮。

但实际跑游戏,你发现:**玩家朝火把看,周围漆黑一片**。火把本身位置应该是亮的——它是光源——但 probe 收到的颜色是 0(黑)。**玩家朝墙看,墙也是暗的**,因为 probe 没记录"火把照亮了墙"。整个场景像没有火把一样黑。

为什么?让我把 Day 569 的 raycast 逻辑展开:ray 沿方向走,**每步检查当前 voxel 是不是 occupied**(即非空气)。火把 voxel 是 occupied(它有几何形状,代表灯泡/火焰模型)。所以 ray 撞到火把时,**立刻停止**——和撞墙一样处理。ray 没机会"记录火把的颜色",probe 收到 0(黑)。这就解释了"玩家朝火把看周围黑"的现象——ray 没看见火把。

正确做法需要**区分两类 occupied voxel**:
- **光源(Light)**:发光,但 ray 撞它时**应该记录颜色并继续**(它"透明",因为光从它出来后还要传播)
- **遮挡物(Occluder)**:不发光,完全挡光,ray 撞它**立刻停**(它"不透明")

更准确做法:撞任何 occupied voxel 都记录 `albedo * light`(被 albedo 染色的光),但只有"完全遮挡"的(墙)才停 ray。光源是"部分透明"的——光从光源出,光源自身也"被看见"。这种"撞光源不停"的设计符合物理直觉——你直视灯泡,看到的是灯泡本身的高亮光,但灯泡后面背景仍存在(被强光眩目挡住,但 raycast 简化处理为"亮度主导")。

完成这一天之后,你具备:

- 理解 voxel 类别(light / occluder / 空气)的区分,以及为什么这种区分对正确 visibility 至关重要
- 能在 raycast 里正确处理 light voxel(记录 + 继续),知道 attenuation 衰减率怎么选
- 知道 volume rendering 的透射率(transmittance)概念,以及工业级体渲染如何用 optical depth 精确表达"透明度"
- 在 GPU fragment shader 用 alpha 通道编码 voxel kind,理解 packed representation 的取舍

## 2 · 心智模型

### 2.1 类比:玻璃窗 vs 砖墙

你站在街上,沿某方向看:

- **空气**:看穿,什么都没有——眼睛收集 0 光,但视觉路径上无障碍
- **玻璃窗**(对应光源):窗后有光进来,你看到窗,但也能看到窗后的(部分透明)
- **砖墙**(对应遮挡物):看不穿,墙就是你看到的终点——视觉路径在此终止

**Raycast 的三类 voxel 完全对应这三个物理状态**。撞空气继续走,撞"玻璃"(光源)记录看到的光但不停止(它透明),撞"砖墙"停止。这个类比让你记住:**occupied 不等于"撞墙"**——一个 voxel 是否阻挡 ray,取决于它**物理上是透明还是不透明**,不是它"是否有几何形状"。

但要注意——如果光太强(火把直视),它后面的东西会"看不清"(强光眩目)。物理上这是 human eye 的 local adaptation——视野里亮度太高,感光细胞饱和,后面暗的物体看不清。Raycast 简化处理:光源后东西仍记录,但被光源亮度"压倒"——视觉合理。Casey 用 `attenuation *= 0.5` 模拟这种"眩目衰减"。

### 2.2 严谨展开:Voxel kind enum 和 visibility 语义

```rust
#[derive(Clone, Copy, PartialEq)]
enum VoxelKind {
    Air,
    Light,       // 发光,但 ray 可穿透
    Occluder,    // 挡光,ray 撞到停
}

struct Voxel {
    light: V3,
    albedo: V3,
    kind: VoxelKind,
}
```

注意 `kind` 字段和 `light` 字段是**正交**的——它们各自表达不同概念:
- `kind`:几何/物理类别(是空气还是实体?发光还是挡光?)
- `light`:这个 voxel 当前发出的光颜色(可能是光源本身发的,也可能是被别人照亮后反射的)

这意味着一个 Occluder voxel 可以有非零的 `light` 值——比如墙被火把照亮后,墙的 voxel 里存了它反射的光(从其他 voxel 视角看,墙就是"次级光源")。同样,一个 Light voxel 在它"自身熄灭"时(火把没点燃),`light` 可以是 0,但 `kind` 仍是 Light(它有几何形状,代表"灯泡模型")。区分这两个属性让 voxel 表达更精确。

更新 raycast:

```rust
fn ray_march(
    grid: &VoxelGrid,
    origin: V3,
    dir: V3,
    max_steps: usize,
) -> V3 {
    let mut sum = [0.0; 3];
    let mut attenuation = 1.0;

    for step in 1..=max_steps {
        let t = step as f32;
        let p = [
            origin[0] + dir[0] * t,
            origin[1] + dir[1] * t,
            origin[2] + dir[2] * t,
        ];
        let i = p[0] as i64;
        let j = p[1] as i64;
        let k = p[2] as i64;
        if i < 0 || j < 0 || k < 0 ||
           i as usize >= grid.dim || j as usize >= grid.dim || k as usize >= grid.dim {
            break;
        }

        let voxel = grid.get(i as usize, j as usize, k as usize);

        // 累加(不论 kind,都把 voxel 的 light 贡献给 ray)
        sum[0] += voxel.light[0] * attenuation;
        sum[1] += voxel.light[1] * attenuation;
        sum[2] += voxel.light[2] * attenuation;

        // 决定是否停(根据 kind)
        match voxel.kind {
            VoxelKind::Air => {
                attenuation *= 0.95;  // 空气轻微衰减(模拟散射吸收)
            }
            VoxelKind::Light => {
                // 不停,继续看光源后
                attenuation *= 0.5;  // 但衰减快(光后看不太清,模拟眩目)
            }
            VoxelKind::Occluder => {
                break;  // 撞墙,停
            }
        }
    }
    sum
}
```

关键改动在两处:
1. **`sum += voxel.light` 不在 match 里**——任何 kind 的 voxel(包括 Air)的 light 都累加。Air 通常 light=0 所以无贡献,但语义上仍累加(防止 bug)。
2. **`match voxel.kind` 只决定 attenuation 和是否 break**——Air 衰减慢、Light 衰减快、Occluder 停。`break` 在 Occluder 分支里,不在累加之后——这样 Occluder 的 light 也累加(墙被照亮了,反射光),然后停。

### 2.3 Albedo 对反射的影响

更细致:Occluder 的反射光应该被其 albedo 染色——白墙反射白光,红墙反射红光。这是个**颜色物理学**——白光照红墙,墙吸收所有非红波长,只反射红。在 voxel 里我们简化为"反射光 = 入射光 * albedo"——albedo 是 [0,1] 三分量,代表 RGB 各分量反射比例。

```rust
let contribution = [
    voxel.light[0] * voxel.albedo[0],
    voxel.light[1] * voxel.albedo[1],
    voxel.light[2] * voxel.albedo[2],
];
sum[0] += contribution[0] * attenuation;
sum[1] += contribution[1] * attenuation;
sum[2] += contribution[2] * attenuation;
// ...
```

光源的 albedo 是 [1,1,1](不染色,光完全发射),墙的 albedo 是其表面颜色。Albedo 在物理上叫 **BRDF**(Bidirectional Reflectance Distribution Function)的简化——理想 diffuse 表面,albedo 是常数;真实表面 BRDF 还依赖入射角和观察角。

### 2.4 attenuation 系数的物理意义

代码里的 `attenuation *= 0.95`(Air)和 `attenuation *= 0.5`(Light)看起来是"魔法数字",让我解释它们的物理意义。

**Air 的 0.95** 模拟**大气散射和吸收**——空气虽然透明,但远处的物体颜色会被空气"洗"一点(大气透视)。游戏里通常用一个 0.95-0.99 的系数配合"远距离雾"——`attenuation = 0.95^distance`。Casey 用 0.95 让远处 voxel 自动衰减,产生"远处变暗"的视觉效果,符合户外光照直觉。

**Light 的 0.5** 模拟**强光眩目**——直视光源时,视网膜感光细胞饱和,后面的物体视觉上"消失"。物理上不是真的消失,但视觉感知上如此。Raycast 用 0.5 让光源后的 voxel 衰减快——多次撞光源后 attenuation 趋近 0,后续 voxel 贡献可忽略。这模拟了"直视灯泡看不见灯泡后的细节"的直觉。

这两个数字是**艺术调参**,不是物理精确。商业游戏里每个场景有不同的 attenuation 系数——例如室内场景可能用 0.99(Air 衰减慢),户外用 0.95(模拟大气)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业 voxel GI 的 voxel 分类比 Day 570 的三分档更精细。Unreal Engine 5 的 Lumen 把每个 voxel 存储多 attribute:

- **Albedo**(反射率):表面反射的颜色——白墙 [0.9, 0.9, 0.9],红墙 [0.7, 0.2, 0.2]
- **Emissive**(自发光):光源本身发出的光——灯泡 [10, 8, 6],墙 [0, 0, 0]
- **Opacity**(不透明度):0=完全透明,1=完全遮挡。Casey 用离散三档(Air=0, Light=0.5, Occluder=1),Lumen 用连续浮点
- **Normal**(表面法线):表面朝向,影响光照计算
- **Material ID**:对应材质表(金属、塑料、布料),每个有不同的 BRDF

Casey 这天用 3 种 kind 是教学简化。商业游戏至少 5-6 个 attribute。**为什么分这么多?**因为不同 attribute 影响不同的渲染阶段——emissive 影响"光从哪来",albedo 影响"反射什么颜色",opacity 影响"是否挡光",normal 影响"反射方向"。把这些 attribute 打包进 voxel,raycast 能计算物理正确的光照。

**CryEngine SVO(Sparse Voxel Octree)** 用类似多 attribute 设计,加一个"距离场"(distance field)加速 raycast——每个 voxel 存"到最近表面的距离",raycast 用 sphere tracing 加速。这是 SVO GI 的核心思想。

**Unity HDRP 的 ray tracing** 用 mesh-based 而非 voxel-based,但概念类似——hit 时区分"光源 mesh"和"普通 mesh",光源 mesh 记录 emissive 不停 ray。

**Gears 5 的 voxel GI** 用 opacity field——连续的 opacity 而非离散 kind。这样玻璃(0.3 opacity)、水(0.5)、雾(0.1)都能表达,不仅三档。Casey 的 Light 0.5 衰减是 opacity field 的离散近似。

### 3.2 · 🎨 图形学视角

Voxel 类别对应的物理是 **transmittance(透射率)** 和 **emissivity(发射率)**:

- **Air**:transmittance = 1(完全透明),emissivity = 0(不发光)
- **Light**:transmittance = 1(光源本身透明,光从它出来后无障碍),emissivity = 高(自发光)
- **Occluder**:transmittance = 0(完全遮挡),emissivity = 0(不发光,只反射)

更精细的体渲染(volume rendering)用 **optical depth(光学深度)** 和 **Beer-Lambert 定律**:

```
T(s) = exp(-∫₀^s σ(t) dt)  (透射率)
```

σ 是衰减系数(单位长度内的吸收概率)。Air σ=0(完全透射),Light σ≈小(几乎全透射但有少量"亮度散射"),Occluder σ→∞(完全不透射)。

体渲染的渲染方程(Beer-Lambert 累加形式):

```
L = ∫₀^∞ T(s) * (emission(s) + scattering(s)) ds
```

L 是观察者看到的光,T 是透射率,emission 是体素的发光,scattering 是体素散射进来的光。这是**连续形式**,Casey 用**离散形式**(每步累加 light * attenuation)近似:

```
L ≈ Σ_k T_k * emission_k
T_k = T_{k-1} * exp(-σ_k * Δs)
```

每步 attenuation = T_k。Casey 用 σ = 0.05(Air)、0.7(Light)、∞(Occluder)的离散对应——这给出 attenuation 0.95(Air exp(-0.05)≈0.95)、0.5(Light exp(-0.7)≈0.5)、0(Occluder exp(-∞)=0)。**这些"魔法数字"其实是离散化的 optical depth**。

更深入的图形学概念:**phase function**(相位函数)描述散射光的方向分布——各向同性散射(烟雾)用常数,各向异性散射(云、皮肤)用 Henyey-Greenstein 函数。Casey 不考虑散射(只 emission),但工业 GI 必须考虑——次表面散射(SSS)、 participating media 都需要 phase function。

### 3.3 · 🐧 Linux 系统编程视角

"分类 / tagging"是系统设计的核心模式。Linux 内核几乎每个数据结构都有 `kind` / `type` / `flags` 字段区分行为:

**Linux 文件类型**:inode 的 `i_mode` 字段低 4 bit 编码文件类型——regular、directory、socket、char device、block device、pipe、symlink。系统调用 `stat()` 返回这个字段,程序用 `S_ISREG`、`S_ISDIR` 等宏判断。每种类型有不同行为(目录可以 list,socket 可以 accept,regular 只能 read/write)。**和 Casey 的 VoxelKind 完全同构**——`kind` 字段决定如何处理。

**Process state**:`task_struct` 的 `state` 字段是 R(Running)、S(Sleeping)、D(Uninterruptible sleep)、Z(Zombie)、T(Stopped)。每种 state 决定调度器如何处理这个进程——和 raycast 根据 voxel kind 决定如何处理一样。

**Memory page**:`struct page` 的 flags 字段编码 PG_locked、PG_dirty、PG_uptodate、PG_active 等。每个 flag 触发不同行为——dirty page 会被写回磁盘,active page 不被换出。

**iptables 规则**:`-j ACCEPT`、`-j DROP`、`-j LOG`、`-j REJECT`——每个 target 决定包的命运。**ACCEPT 不停 chain(继续后续规则),DROP 立刻停**——这正是 Casey 的 Light vs Occluder 区分。

**eBPF 程序类型**:XDP、TC、kprobe、tracepoint、perf_event——每种类型在内核不同 hook 点运行,看到不同的 context。**type 字段决定 hook 点和处理逻辑**,和 VoxelKind 决定 raycast 处理逻辑完全相同。

**Rust 中的 tagged union**:Rust enum 是这个模式的现代实现。enum 让"kind"和"associated data"耦合——`enum File { Regular(Vec<u8>), Directory(BTreeMap<String, File>), Socket(...) }`。比 C 的 `struct { int kind; void *data; }` 更安全(编译器保证 match exhaustive)。

### 3.4 · 🦀 Rust 生态视角

Rust enum 是表达 voxel kind 的天然方式,而且 Rust enum 比 C union 安全得多。**Rust enum 带 payload**(每个 variant 可以携带不同类型数据),这让 voxel 表达更精确:

```rust
enum VoxelKind {
    Air,
    Light { intensity: f32 },         // 光源带强度
    Occluder { material: MaterialId }, // 墙带材质 ID
    Transparent { transmittance: f32 }, // 玻璃带透射率
}

match voxel.kind {
    VoxelKind::Air => { /* 处理空气 */ }
    VoxelKind::Light { intensity } => { /* 处理光,用 intensity */ }
    VoxelKind::Occluder { material } => { /* 处理墙,查材质表 */ }
    VoxelKind::Transparent { transmittance } => { /* 处理玻璃 */ }
}
```

Rust 编译器强制 `match` exhaustive——如果以后加 `VoxelKind::Fog { density: f32 }`,所有 `match` 都会编译错误,提醒你更新。这是 C enum 做不到的安全保证。

**性能考量**:Rust enum 占用的内存 = max(各 variant 大小) + discriminant tag。`VoxelKind::Light { intensity: f32 }` 占 4 字节,`Occluder { material: u32 }` 占 4 字节,enum 占 4+1=5 字节(对齐到 8)。这比"每个 voxel 都存 intensity + material + transmittance"(12 字节)省内存——Rust enum 让 variant 共享存储。**对 voxel grid 这种大数组,这个节省非常关键**——100 万 voxel 省 7 MB。

**GPU 上的 enum**:GPU shader 通常用 packed representation——一个 f32 的 alpha 通道编码 kind(0.0=Air, 0.33=Light, 0.66=Transparent, 1.0=Occluder)。或者用 R8Uint texture 单独存 kind。这是 Casey 在 GPU 实现会用的模式。

**Rust 的 `bevy_reflect`** 提供 runtime introspection——可以在运行时枚举一个 enum 的所有 variant。这在做 voxel kind 的"编辑器 UI"时有用——编辑器列出所有 kind 让美术选。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么光源 voxel 是 occupied 但 ray 不停?如果不停,会不会"看到"光源后面的太多细节?

**参考解答**:光源 voxel 有几何形状(灯泡模型),所以 occupied = true。但物理上光源本身"发光",光从它出来——ray 撞它时**应该**记录它的颜色(这是玩家眼睛看到光源的方式)。如果立刻停,probe 没记录光源 → 玩家附近 voxel 黑(因为没收到光)。不停的话:ray 继续看光源后,但 attenuation 衰减快(0.5 每步),所以光源后的东西很快模糊。视觉上:光源 + 模糊的光源后景——合理。如果 attenuation=1.0(不衰减),ray 看到光源后所有细节,不真实(光应该"眩目"挡住后面的)。

### Lv2 · 动手实践

**题**:实现 VoxelKind enum,验证光源不被错误遮挡。

要求:
- 8³ voxel grid

```rust
type V3 = [f32; 3];

#[derive(Clone, Copy, PartialEq)]
enum VoxelKind { Air, Light, Occluder }

#[derive(Clone, Copy)]
struct Voxel {
    light: V3,
    albedo: V3,
    kind: VoxelKind,
}

impl Default for Voxel {
    fn default() -> Self {
        Voxel { light: [0.0; 3], albedo: [1.0; 3], kind: VoxelKind::Air }
    }
}

struct VoxelGrid {
    data: Vec<Voxel>,
    dim: usize,
}

impl VoxelGrid {
    fn new(dim: usize) -> Self {
        VoxelGrid { data: vec![Voxel::default(); dim*dim*dim], dim }
    }
    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim + j) * self.dim + i
    }
    fn get(&self, i: usize, j: usize, k: usize) -> Voxel { self.data[self.idx(i, j, k)] }
    fn set(&mut self, i: usize, j: usize, k: usize, v: Voxel) {
        self.data[self.idx(i, j, k)] = v;
    }
}

fn ray_march(grid: &VoxelGrid, origin: V3, dir: V3, max_steps: usize) -> (V3, Vec<(usize, VoxelKind, V3)>) {
    let mut sum = [0.0; 3];
    let mut attenuation = 1.0;
    let mut path = Vec::new();

    for step in 1..=max_steps {
        let t = step as f32;
        let p = [
            origin[0] + dir[0] * t,
            origin[1] + dir[1] * t,
            origin[2] + dir[2] * t,
        ];
        let i = p[0] as i64;
        let j = p[1] as i64;
        let k = p[2] as i64;
        if i < 0 || j < 0 || k < 0 ||
           i as usize >= grid.dim || j as usize >= grid.dim || k as usize >= grid.dim {
            break;
        }
        let voxel = grid.get(i as usize, j as usize, k as usize);

        sum[0] += voxel.light[0] * attenuation;
        sum[1] += voxel.light[1] * attenuation;
        sum[2] += voxel.light[2] * attenuation;

        path.push((i as usize, voxel.kind, voxel.light));

        match voxel.kind {
            VoxelKind::Air => { attenuation *= 0.95; }
            VoxelKind::Light => { attenuation *= 0.5; }
            VoxelKind::Occluder => break,
        }
    }
    (sum, path)
}

fn main() {
    let mut grid = VoxelGrid::new(8);
    grid.set(4, 4, 4, Voxel {
        light: [10.0, 8.0, 6.0], albedo: [1.0; 3], kind: VoxelKind::Light,
    });
    grid.set(6, 4, 4, Voxel {
        light: [0.0; 3], albedo: [0.7, 0.5, 0.3], kind: VoxelKind::Occluder,
    });

    let (sum, path) = ray_march(&grid, [0.0, 4.0, 4.0], [1.0, 0.0, 0.0], 10);

    println!("Ray path:");
    for (i, kind, light) in &path {
        let kind_str = match kind {
            VoxelKind::Air => "Air",
            VoxelKind::Light => "Light",
            VoxelKind::Occluder => "Occluder",
        };
        println!("  voxel {}: {} light=({:.2},{:.2},{:.2})", i, kind_str, light[0], light[1], light[2]);
    }
    println!("\nFinal sum: ({:.2}, {:.2}, {:.2})", sum[0], sum[1], sum[2]);
}
```

```rust
type V3 = [f32; 3];

#[derive(Clone, Copy, PartialEq, Debug)]
enum VoxelKind { Air, Light, Occluder, Transparent }  // Transparent = 玻璃(部分透光)

#[derive(Clone, Copy)]
struct Voxel {
    light: V3,
    albedo: V3,
    kind: VoxelKind,
    transmittance: f32,  // 透射率(Transparent 用)
}

impl Default for Voxel {
    fn default() -> Self {
        Voxel {
            light: [0.0; 3],
            albedo: [1.0; 3],
            kind: VoxelKind::Air,
            transmittance: 1.0,
        }
    }
}

struct VoxelGrid {
    data: Vec<Voxel>,
    dim: usize,
}

impl VoxelGrid {
    fn new(dim: usize) -> Self {
        VoxelGrid { data: vec![Voxel::default(); dim*dim*dim], dim }
    }
    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim + j) * self.dim + i
    }
    fn get(&self, i: usize, j: usize, k: usize) -> Voxel { self.data[self.idx(i, j, k)] }
    fn set(&mut self, i: usize, j: usize, k: usize, v: Voxel) {
        self.data[self.idx(i, j, k)] = v;
    }
}

fn ray_march(
    grid: &VoxelGrid,
    origin: V3,
    dir: V3,
    max_steps: usize,
) -> V3 {
    let mut sum = [0.0; 3];
    let mut attenuation = 1.0;

    for step in 1..=max_steps {
        let t = step as f32;
        let p = [
            origin[0] + dir[0] * t,
            origin[1] + dir[1] * t,
            origin[2] + dir[2] * t,
        ];
        let i = p[0] as i64;
        let j = p[1] as i64;
        let k = p[2] as i64;
        if i < 0 || j < 0 || k < 0 ||
           i as usize >= grid.dim || j as usize >= grid.dim || k as usize >= grid.dim {
            break;
        }
        let voxel = grid.get(i as usize, j as usize, k as usize);

        // 累加(被 albedo 染色)
        let contribution = [
            voxel.light[0] * voxel.albedo[0],
            voxel.light[1] * voxel.albedo[1],
            voxel.light[2] * voxel.albedo[2],
        ];
        sum[0] += contribution[0] * attenuation;
        sum[1] += contribution[1] * attenuation;
        sum[2] += contribution[2] * attenuation;

        // 根据 kind 决定下一步 attenuation
        match voxel.kind {
            VoxelKind::Air => attenuation *= 0.95,
            VoxelKind::Light => attenuation *= 0.5,  // 光源眩目,后面看不清
            VoxelKind::Occluder => break,
            VoxelKind::Transparent => attenuation *= voxel.transmittance,
        }

        if attenuation < 0.01 { break; }  // 完全衰减,停
    }
    sum
}

fn main() {
    let mut grid = VoxelGrid::new(16);

    // 太阳光(远处光源)
    grid.set(0, 12, 0, Voxel {
        light: [10.0, 9.0, 7.0],
        albedo: [1.0; 3],
        kind: VoxelKind::Light,
        transmittance: 1.0,
    });

    // 窗户(透明)
    grid.set(5, 5, 5, Voxel {
        light: [0.0; 3],
        albedo: [0.8; 3],
        kind: VoxelKind::Transparent,
        transmittance: 0.7,  // 70% 光过
    });

    // 墙(遮挡)
    grid.set(10, 5, 5, Voxel {
        light: [0.0; 3],
        albedo: [0.7, 0.5, 0.3],
        kind: VoxelKind::Occluder,
        transmittance: 0.0,
    });

    // 从某点沿 +x 方向看
    let sum = ray_march(
        &grid,
        [0.0, 5.0, 5.0],
        [1.0, 0.0, 0.0],
        20,
    );

    println!("Ray from (0,5,5) along +x:");
    println!("  Sum: ({:.2}, {:.2}, {:.2})", sum[0], sum[1], sum[2]);
    println!("  Expected: 撞窗户(transmittance 0.7),部分光过,撞墙停止");

    // 玩家朝太阳看
    let sum = ray_march(
        &grid,
        [5.0, 5.0, 5.0],
        // 归一化方向 (-5, 7, -5)/length
        {
            let mut d = [-5.0, 7.0, -5.0];
            let mag = (25.0 + 49.0 + 25.0).sqrt();
            d[0] /= mag; d[1] /= mag; d[2] /= mag;
            d
        },
        20,
    );
    println!("\nRay toward sun:");
    println!("  Sum: ({:.2}, {:.2}, {:.2})", sum[0], sum[1], sum[2]);
    println!("  Expected: 撞太阳光源,记录高亮度");
}
```
