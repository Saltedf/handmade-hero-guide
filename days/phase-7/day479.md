
# Day 479 · 大纹理支持

> Texture array 要求所有 layer 同尺寸。但实际游戏里,角色立绘可能是 2048×2048,UI 图标 64×64。Day 479 处理这种"大纹理"问题——给 texture array 加一层"虚拟 layer",让大纹理占据多个 layer 槽位。

## 0 · 为什么要有这一天

Day 478 的 texture array 假设所有纹理 64×64。但实际游戏有这种需求:

- 角色立绘:1024×1024
- 背景图:2048×1024
- 字体 atlas:512×512
- UI 图标:64×64(几十张)

如果都用 2048×2048 的 array,小图标浪费 1024 倍内存(64×64 → 2048×2048 是 1024 倍面积)。如果都用 64×64,大纹理放不下。

解决方案有两个:

**方案 A:多个 array**。建几个 array,每个 array 一种尺寸。比如 `tex_array_64`(64×64)、`tex_array_512`(512×512)、`tex_array_2048`(2048×2048)。每个 array 独立 bind。问题是回到了"多次 bind",batching 优势削弱。

**方案 B:大纹理切瓦片**。一张 2048×2048 大纹理切成 64×64 的瓦片,每瓦片放一个 layer。1024 个瓦片占 1024 layer(OpenGL array 支持几千 layer)。Shader 端 UV 算偏移,跨瓦片采样用 `layer = base_layer + uv_to_tile(uv)`。

Casey 选 B——单个 array,大纹理占据多个连续 layer。这保留了"一帧一次 draw call"的优势。

具体做法:

- 一张 1024×1024 大纹理 → 1024 个 64×64 瓦片 → layer [N, N+1024]
- 每个大纹理在 bitmap 表里记录 `first_layer` 和 `tiles_per_row`
- Shader 用 UV 算出当前像素属于哪个瓦片 + 瓦片内 local UV

这是 **"virtual texture"** 的简化版。John Carmack 在 Rage 里用完整的 virtual texture(GPU 按需加载),Casey 这里只用 CPU 端的瓦片映射。

完成这一天之后,你具备了:

- 瓦片化纹理(tile-based texture)的实操经验
- Shader 里"跨瓦片采样"的 UV 计算
- 理解 virtual texture 的基本原理

## 1 · Casey 今天做了什么

Casey 这一天的工作:

第一步,他改 bitmap 表,加 `tiles_per_row` 和 `tile_count` 字段。小纹理(64×64 以下)tile_count = 1,大纹理 tile_count > 1。

第二步,他写"上传大纹理"逻辑——遍历大纹理的所有瓦片,每瓦片上传到连续 layer。

```c
void upload_large_texture(TextureArray* arr, Bitmap* bmp) {
    u32 first_layer = arr->layer_count;
    u32 tiles_per_row = bmp->w / TILE_SIZE;
    u32 tile_count = tiles_per_row * (bmp->h / TILE_SIZE);
    
    for (u32 tile_idx = 0; tile_idx < tile_count; tile_idx++) {
        u32 tx = tile_idx % tiles_per_row;
        u32 ty = tile_idx / tiles_per_row;
        // 提取瓦片像素
        extract_tile(bmp, tx, ty, tile_buffer);
        // 上传
        upload_layer(arr, tile_buffer);
    }
    
    bmp->first_layer = first_layer;
    bmp->tiles_per_row = tiles_per_row;
}
```

第三步,他改 fragment shader——根据 UV 算出当前像素属于哪个瓦片:

```glsl
flat in int base_layer;
flat in int tiles_per_row;
in vec2 uv;

void main() {
    // UV (0..1, 0..1) 转成瓦片坐标
    float tu = uv.x * tiles_per_row;
    float tv = uv.y * tiles_per_row;
    int tile_x = int(tu);
    int tile_y = int(tv);
    int layer_offset = tile_y * tiles_per_row + tile_x;
    int layer = base_layer + layer_offset;
    
    // 瓦片内 local UV
    vec2 local_uv = vec2(tu - float(tile_x), tv - float(tile_y));
    
    vec4 color = texture(tex_array, vec3(local_uv, float(layer)));
    frag_color = color * vertex_color;
}
```

第四步,他改 vertex layout,加 `base_layer` 和 `tiles_per_row` 字段。这样每个 entry 自带"我的纹理在哪个 base_layer,每行几个瓦片",shader 直接用。

第五步,他跑游戏,大纹理(角色立绘)正确显示。

## 2 · 心智模型

### 类比:大型图书馆的分馆系统

想象一个城市有一个中央图书馆,但只能放标准尺寸的书(比如 32 开)。但有些是巨册地图集(A2 大小),放不进标准书架。

两种方案:

**方案 A(多书架)**:再建一个大书架专放地图集。读者要看地图集去大书架,看普通书去标准书架。问题:读者要"换书架",慢。

**方案 B(瓦片化)**:把地图集按 32 开大小切成多页,每页装订成独立小册子,放在标准书架的连续位置。读者看地图集时,根据"我要看哪页"算出小册子在第几格,翻到对应页。

方案 B 保留了"所有书在标准书架"的优势,代价是切书 + 算页号。Casey 选这个。

### 瓦片化的核心算法

大纹理 1024×1024,瓦片 64×64,切成 16×16 = 256 个瓦片。这 256 个瓦片放在 texture array 的 layer [N, N+256]。

UV 坐标 (0.5, 0.3)(纹理中央偏左)映射到:

- 全局瓦片坐标:`tile_u = 0.5 * 16 = 8`,`tile_v = 0.3 * 16 = 4.8`
- 瓦片 index:`int(tile_v) * 16 + int(tile_u) = 4 * 16 + 8 = 72`
- 实际 layer:`base_layer + 72`
- 瓦片内 local UV:`(tile_u - int(tile_u), tile_v - int(tile_v)) = (0.0, 0.8)`

shader 用 layer + local UV 采样。

### 瓦片化的边界问题

瓦片化有个隐藏坑:**瓦片边界**。如果 linear filter 开启,UV 在瓦片边界会跨越两个瓦片,但 OpenGL 不允许跨 layer 采样,会出现" seams"(缝)。

解决:每个瓦片边缘多存一像素(padding),sample 时 clamp 到瓦片内。或者关闭 linear filter(用 nearest)。

Casey 在 Day 479 用 nearest filter 简化,大纹理可能有锯齿但能跑。Day 480 调试时如果发现问题再加 padding。

工业级 texture streaming(虚拟纹理)都用 padding——每瓦片存 N 像素 padding(N 通常 4-8),sample 时 UV 偏移到 padding 内,filter 边界处不会越界。

### Memory overhead

瓦片化有内存开销吗?没有——1024×1024 切成 256 个 64×64,总像素数相同(1024×1024 = 256×64×64 = 1M)。瓦片化只是改变了组织方式,不增加数据量。

但**采样效率**有差异:瓦片化后,跨瓦片的纹理访问要走两次 layer fetch(理论上)。GPU 通常优化了这种情况(同一 array 内连续 layer 访问 cache 友好),实际开销很小。

### 为什么不直接用 GL_MAX_TEXTURE_SIZE

OpenGL 通常支持 8192×8192 或 16384×16384 单纹理。你完全可以不用瓦片,直接 glBindTexture(2048×2048)。

但这样就回到了"每纹理一次 bind"的问题。瓦片化的目的不是绕过尺寸限制,而是**保持 texture array batching**。

Casey 在 Day 479 反复强调:**texture array batching 的价值 > 大纹理的简化**。即使大纹理切瓦片复杂一点,batching 收益更大。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

瓦片化纹理在游戏开发里有两个工业应用:

**Virtual Texturing(Mega-texture)**:整个游戏世界一张超大虚拟纹理(比如 65536×65536)。GPU 只 cache 可见部分到物理 texture cache(类似 CPU cache + 主存)。采样时通过 page table 把 virtual UV 翻译成物理 cache UV。Carmack 的 id Tech 5(Rage)用这个。

**Texture Streaming**:大纹理分块加载,玩家走到哪加载到哪。Unreal 的 Texture Streaming、Unity 的 Texture Streaming 都做这个。比 virtual texture 简单——不 cache pixel,只 cache 整张 mipmap level。

Casey 的简单瓦片化是 virtual texture 的最简版本——没有 GPU page table,所有瓦片一次性上传,没有 streaming。但概念基础一样。

游戏开发里另一个相关技术:**splattermap / mega-texture for terrain**。地形纹理通常由多层(sand、grass、rock、snow)按权重混合。每层有自己的 mask 纹理。把所有 mask 打包到一个 texture array(每 layer 一个 mask),shader 用 layer index 选 mask。这是 texture array 在地形渲染的典型应用。

### 3.2 · 🎨 图形学视角

图形学里大纹理处理有几个层次。

**Mipmap chain**:大纹理生成多级 mipmap(1024→512→256→128→...→1)。采样时按像素覆盖面积选合适 level,避免远距离采样锯齿。这是 OpenGL 内置功能,Casey 也用。

**Anisotropic filtering**:各向异性过滤。斜视角时,UV 在屏幕一个像素覆盖的纹理区域是细长的(不是正方形)。Anisotropic 在这个细长区域内多次采样取平均,提升远处纹理质量。

**Texture compression**:BC1/BC3/BC7(DXT)、ASTC、ETC2。这些格式把纹理压缩 4-8 倍,GPU 直接采样压缩数据,省显存 + 省带宽。Casey 在 Day 479 没用压缩纹理(他用 RGBA8),后面 Phase 6 讲过压缩纹理。

瓦片化与 mipmap 怎么共存?每个 mipmap level 都要切瓦片,所以瓦片数随 level 减半。layer 0 是 16×16 = 256 瓦片,layer 1 是 8×8 = 64 瓦片。Casey 简化处理,只用 level 0(不切 mipmap)。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上有个类似的概念:**huge pages**(透明大页)。常规 page 4KB,大页 2MB 或 1GB。TLB(translation lookaside buffer)缓存 page 表项,page 越大 TLB 命中率越高。

瓦片化纹理是 GPU 端的"大页"——把多个 64×64 瓦片当成一个"逻辑大纹理",GPU sample 时减少 layer 切换。

你可以观察 Linux 的 huge page:

```bash
# 看 transparent hugepage 状态
cat /sys/kernel/mm/transparent_hugepage/enabled
# 输出 [always] madvise never,说明 always 启用

# 看进程用的大页
cat /proc/meminfo | grep -i huge
# AnonHugePages、HugePages_Total 等

# 让程序用大页(madvise)
# Rust: libc::madvise(ptr, len, MADV_HUGEPAGE)
```

CPU 的大页和 GPU 的瓦片化是同一思想——把多个小单位打包成大单位,减少元数据开销。

### 3.4 · 🦀 Rust 生态视角

Rust 里实现瓦片化纹理有几个 idiomatic 选择。

第一,**二维数组切片**。提取瓦片:

```rust
fn extract_tile(src: &[[u8; 4]], src_w: usize, tile_size: usize, tx: usize, ty: usize) -> Vec<[u8; 4]> {
    let mut tile = vec![[0; 4]; tile_size * tile_size];
    for y in 0..tile_size {
        for x in 0..tile_size {
            let sx = tx * tile_size + x;
            let sy = ty * tile_size + y;
            tile[y * tile_size + x] = src[sy * src_w + sx];
        }
    }
    tile
}
```

第二,**iterator 生成所有瓦片**:

```rust
let tiles = (0..tiles_per_row).flat_map(|ty| {
    (0..tiles_per_row).map(move |tx| {
        extract_tile(src, src_w, TILE_SIZE, tx, ty)
    })
}).collect::<Vec<_>>();
```

第三,**用 ndarray 库处理多维像素**:

```rust
use ndarray::Array3;
let src: Array3<u8> = Array3::from_shape_vec((h, w, 4), pixels)?;
let tile = src.slice(s![ty*TILE_SIZE..(ty+1)*TILE_SIZE, tx*TILE_SIZE..(tx+1)*TILE_SIZE, ..]);
```

Casey 用 C 手写循环,Rust 翻译可以更优雅但本质相同。

## 5 · 对照与变奏

Casey 在 Day 479 的瓦片化思想在不同领域有不同对应:

**OS 内存管理**:虚拟内存把进程的虚拟地址空间分页(4KB),按需映射到物理内存。和瓦片化纹理同构——虚拟 UV 映射到物理 layer。

**数据库**:分表(sharding)把大表分成小表存不同节点。和瓦片化同构——大纹理分成小瓦片存不同 layer。

**Web**:图片 sprite——多个 UI 图标拼成一张大图,前端用 background-position 选 icon。和 texture atlas 同构。

**CDN**:视频分片(HLS、DASH)。大视频切成小段,客户端按需请求。和 virtual texture streaming 同构。

**地图**:Web 地图(谷歌地图)按 zoom level + (x, y) 切瓦片。和瓦片化纹理几乎完全一样——zoom level 对应 mipmap level,x/y 对应 tile_x/tile_y。

理解"分而治之 + 索引访问"是工程师的核心素养。每次你处理大资源,问自己:**能不能切成小单位按需访问?**

另一个对照:**Casey 简化 vs 工业复杂**。Casey 切瓦片,不用 GPU page table、不用 streaming、不用 padding。工业实现都做。这是教学版 vs 工业版的区别——教学版讲清楚原理,工业版填生产细节。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 Casey 选择"切瓦片到 texture array"而不是"用 GL 的单纹理 + 多 bind"?

**参考解答**:两个理由:

第一,**保持 batching**。Texture array 允许一帧一次 draw call,单纹理必须每纹理一次 bind。Day 477/478 已经建立了 batching 优势,Day 479 不能为了大纹理放弃它。

第二,**统一代码路径**。所有纹理(大、小)走同一条 sample 路径——shader 计算 layer,从 array 采样。如果大纹理走单纹理路径,小纹理走 array 路径,shader 要分支,代码复杂。

代价是大纹理的 shader 逻辑稍复杂(算 layer offset)。但相对 batching 收益,值得。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现一个简化的瓦片化系统。给定一张 128×128 假装的大纹理(用 `[u8; 4]` 像素数组),瓦片大小 32×32,提取所有 4×4 = 16 个瓦片。每个瓦片上传到 texture array 一个 layer(假装)。然后写一个 `sample(u, v) -> layer_offset` 函数,返回给定 UV 对应的 layer offset。

完成标准:`cargo run` 输出 16 个瓦片上传成功,以及 5 个 UV 点 (0,0)、(0.5, 0.5)、(1, 1)、(0.25, 0.75)、(0.9, 0.1) 的 layer offset。

**参考解答**:

```rust
const TILE_SIZE: usize = 32;
const SRC_W: usize = 128;
const SRC_H: usize = 128;
const TILES_PER_ROW: usize = SRC_W / TILE_SIZE;   // 4

// 假装的大纹理(每个像素不同颜色,便于区分)
fn make_source_texture() -> Vec<[u8; 4]> {
    let mut pixels = vec![[0u8; 4]; SRC_W * SRC_H];
    for y in 0..SRC_H {
        for x in 0..SRC_W {
            // 每像素颜色按位置编码
            pixels[y * SRC_W + x] = [
                (x * 2) as u8,
                (y * 2) as u8,
                ((x + y) % 256) as u8,
                255,
            ];
        }
    }
    pixels
}

// 提取单个瓦片
fn extract_tile(src: &[[u8; 4]], tx: usize, ty: usize) -> Vec<[u8; 4]> {
    let mut tile = vec![[0u8; 4]; TILE_SIZE * TILE_SIZE];
    for ly in 0..TILE_SIZE {
        for lx in 0..TILE_SIZE {
            let sx = tx * TILE_SIZE + lx;
            let sy = ty * TILE_SIZE + ly;
            tile[ly * TILE_SIZE + lx] = src[sy * SRC_W + sx];
        }
    }
    tile
}

// 假装的 texture array
struct TextureArray {
    layers: Vec<Vec<[u8; 4]>>,
}

impl TextureArray {
    fn new() -> Self { Self { layers: Vec::new() } }
    
    fn upload_layer(&mut self, pixels: Vec<[u8; 4]>) -> usize {
        let idx = self.layers.len();
        self.layers.push(pixels);
        idx
    }
}

// 大纹理上传:返回 first_layer
fn upload_large_texture(arr: &mut TextureArray, src: &[[u8; 4]]) -> usize {
    let first_layer = arr.layers.len();
    for ty in 0..TILES_PER_ROW {
        for tx in 0..TILES_PER_ROW {
            let tile = extract_tile(src, tx, ty);
            arr.upload_layer(tile);
        }
    }
    first_layer
}

// UV → layer offset
fn uv_to_layer_offset(u: f32, v: f32) -> (usize, [f32; 2]) {
    // uv (0..1) → 全局瓦片坐标
    let tu = u * TILES_PER_ROW as f32;
    let tv = v * TILES_PER_ROW as f32;
    let tile_x = tu.floor() as usize;
    let tile_y = tv.floor() as usize;
    
    // clamp 到有效范围(避免 1.0 越界)
    let tile_x = tile_x.min(TILES_PER_ROW - 1);
    let tile_y = tile_y.min(TILES_PER_ROW - 1);
    
    let offset = tile_y * TILES_PER_ROW + tile_x;
    let local_u = tu - tile_x as f32;
    let local_v = tv - tile_y as f32;
    
    (offset, [local_u, local_v])
}

fn main() {
    let src = make_source_texture();
    let mut arr = TextureArray::new();
    let first_layer = upload_large_texture(&mut arr, &src);
    
    println!("Uploaded large texture, first_layer = {}", first_layer);
    println!("Total layers in array: {}", arr.layers.len());
    println!();
    
    // 测试几个 UV 点
    let test_uvs = [
        (0.0, 0.0, "左上"),
        (0.5, 0.5, "中央"),
        (1.0, 1.0, "右下"),     // 边界
        (0.25, 0.75, "中央偏下"),
        (0.9, 0.1, "右上偏右"),
    ];
    
    for (u, v, desc) in test_uvs {
        let (offset, local_uv) = uv_to_layer_offset(u, v);
        let layer = first_layer + offset;
        println!("UV ({}, {}) {}: layer_offset={}, actual_layer={}, local_uv={:?}",
                 u, v, desc, offset, layer, local_uv);
    }
}
```

为什么这么写:`uv_to_layer_offset` 模拟 shader 里的 UV 计算。注意 `(1.0, 1.0)` 边界——必须 clamp,否则 tile_x = 4 越界。实际 shader 里用 `min(int(tu), TILES_PER_ROW - 1)` 处理。

## 8 · Rust / Arch 落地代码

下面是 Day 479 完整的瓦片化纹理实现。

```rust
// ========================================
// 瓦片化大纹理系统
// ========================================

const TILE_SIZE: usize = 64;

#[derive(Debug)]
struct LargeTexture {
    width: u32,
    height: u32,
    first_layer: u32,           // 在 texture array 的起始 layer
    tiles_per_row: u32,
    tiles_per_col: u32,
}

impl LargeTexture {
    fn tile_count(&self) -> u32 {
        self.tiles_per_row * self.tiles_per_col
    }
}

struct TextureArray {
    layer_size: usize,
    layers: Vec<Vec<[u8; 4]>>,
}

impl TextureArray {
    fn new(tile_size: usize) -> Self {
        Self {
            layer_size: tile_size,
            layers: Vec::new(),
        }
    }
    
    fn upload_layer(&mut self, pixels: Vec<[u8; 4]>) -> u32 {
        assert_eq!(pixels.len(), self.layer_size * self.layer_size);
        let idx = self.layers.len() as u32;
        self.layers.push(pixels);
        idx
    }
    
    fn total_layers(&self) -> u32 { self.layers.len() as u32 }
}

// 从大纹理提取瓦片
fn extract_tile(
    src: &[[u8; 4]],
    src_w: usize,
    src_h: usize,
    tx: usize,
    ty: usize,
) -> Vec<[u8; 4]> {
    let mut tile = vec![[0u8; 4]; TILE_SIZE * TILE_SIZE];
    for ly in 0..TILE_SIZE {
        for lx in 0..TILE_SIZE {
            let sx = tx * TILE_SIZE + lx;
            let sy = ty * TILE_SIZE + ly;
            if sx < src_w && sy < src_h {
                tile[ly * TILE_SIZE + lx] = src[sy * src_w + sx];
            } else {
                // 越界填透明黑
                tile[ly * TILE_SIZE + lx] = [0, 0, 0, 0];
            }
        }
    }
    tile
}

// 上传大纹理:切成瓦片,上传到 array
fn upload_large_texture(
    arr: &mut TextureArray,
    src: &[[u8; 4]],
    w: u32,
    h: u32,
) -> LargeTexture {
    let tiles_per_row = (w as usize + TILE_SIZE - 1) / TILE_SIZE;
    let tiles_per_col = (h as usize + TILE_SIZE - 1) / TILE_SIZE;
    let first_layer = arr.total_layers();
    
    for ty in 0..tiles_per_col {
        for tx in 0..tiles_per_row {
            let tile = extract_tile(src, w as usize, h as usize, tx, ty);
            arr.upload_layer(tile);
        }
    }
    
    LargeTexture {
        width: w,
        height: h,
        first_layer,
        tiles_per_row: tiles_per_row as u32,
        tiles_per_col: tiles_per_col as u32,
    }
}

// 模拟 shader 的 UV → layer 映射
fn shader_sample(
    lt: &LargeTexture,
    u: f32,
    v: f32,
) -> (u32, f32, f32) {
    // UV (0..1) → 瓦片坐标
    let tu = u * lt.tiles_per_row as f32;
    let tv = v * lt.tiles_per_col as f32;
    
    // tile_x/y:整数瓦片坐标
    let mut tile_x = tu.floor() as i32;
    let mut tile_y = tv.floor() as i32;
    
    // clamp(避免边界越界)
    tile_x = tile_x.max(0).min(lt.tiles_per_row as i32 - 1);
    tile_y = tile_y.max(0).min(lt.tiles_per_col as i32 - 1);
    
    // layer offset
    let offset = tile_y as u32 * lt.tiles_per_row + tile_x as u32;
    let layer = lt.first_layer + offset;
    
    // 瓦片内 local UV
    let local_u = tu - tile_x as f32;
    let local_v = tv - tile_y as f32;
    
    (layer, local_u, local_v)
}

// ========================================
// 演示
// ========================================

fn main() {
    let mut arr = TextureArray::new(TILE_SIZE);
    
    // 小纹理 64×64,占 1 个 layer
    let small_tex: Vec<[u8; 4]> = vec![[255, 0, 0, 255]; 64 * 64];
    let small_layer = arr.upload_layer(small_tex);
    println!("Small texture (64x64) -> layer {}", small_layer);
    
    // 大纹理 1024×1024,切 16x16 = 256 个瓦片
    let large_src: Vec<[u8; 4]> = (0..1024*1024).map(|i| {
        let x = i % 1024;
        let y = i / 1024;
        [(x / 4) as u8, (y / 4) as u8, 128, 255]
    }).collect();
    let lt = upload_large_texture(&mut arr, &large_src, 1024, 1024);
    println!("Large texture (1024x1024) -> first_layer={}, tiles={}x{}={}",
             lt.first_layer, lt.tiles_per_row, lt.tiles_per_col, lt.tile_count());
    
    println!("Total layers in array: {}", arr.total_layers());
    println!();
    
    // 模拟 sample
    let test_uvs = [
        (0.0, 0.0, "左上角"),
        (0.5, 0.5, "正中"),
        (0.99, 0.99, "右下角(近边界)"),
        (0.0625, 0.0625, "瓦片边界内角"),
    ];
    
    for (u, v, desc) in test_uvs {
        let (layer, lu, lv) = shader_sample(&lt, u, v);
        println!("UV ({:.2}, {:.2}) {}: layer={}, local_uv=({:.3}, {:.3})",
                 u, v, desc, layer, lu, lv);
    }
    
    println!();
    println!("=== Vertex layout for large texture ===");
    println!("pos: [f32; 3]");
    println!("uv: [f32; 2]    <- 输入大纹理的全局 UV (0..1)");
    println!("color: [f32; 4]");
    println!("base_layer: i32");
    println!("tiles_per_row: i32");
    println!("tiles_per_col: i32");
    println!();
    println!("Shader 计算:");
    println!("  tile_x = int(uv.x * tiles_per_row)");
    println!("  tile_y = int(uv.y * tiles_per_col)");
    println!("  layer = base_layer + tile_y * tiles_per_row + tile_x");
    println!("  local_uv = (uv * tiles_per_row - tile_x, uv * tiles_per_col - tile_y)");
    println!("  color = texture(tex_array, vec3(local_uv, layer))");
}
```

出错怎么办:

- **黑屏 / 全部 layer 0** —— shader 里 layer 计算错。检查 `tiles_per_row` 是不是作为 `int` 传(shader 默认 float),`uv * tiles_per_row` 要先 cast。
- **瓦片 seams(接缝可见)** —— linear filter 在瓦片边界跨越两个 layer,OpenGL 不允许跨 layer sample。临时方案:用 nearest filter。彻底方案:加 padding。
- **UV (1.0, 1.0) 越界** —— clamp 没做。`tile_x = min(tile_x, tiles_per_row - 1)`。
