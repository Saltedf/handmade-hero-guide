
# Day 517 · 插入和重写 HHT 对齐点

> Day 516 写 HHT 是"全量重写"。Day 517 加"增量修改"——只改一个 alignment point,不重写整个 HHT 文件。这对大型 HHT 性能关键。

## 0 · 为什么要有这一天

### 真实场景:为什么 Day 516 不够,Day 517 必须

你跟着 Casey 做到 Day 516。你实现了 HHT (Handmade Hero Tag-format) 文件的全量重写——用户改一个 alignment point,你**把整个 HHT 文件序列化出来,覆盖磁盘上的旧版本**。这在 demo 阶段够用,但放到真实工程场景,立刻暴露问题。

假设你的 HHT 文件是游戏的所有角色定义。Hero 角色有 20 个 piece(身体、头、手臂、腿、武器、盾...),每个 piece 平均 5 个 alignment point,加 sprite 引用、metadata,大概 100 行 HHT。整个游戏有 200 个角色,HHT 总量 20000 行 / 1.5 MB。

现在用户在 editor 里调一个 alignment point——hero 的"hand_r"从 (15, 0) 改到 (16, -1)。Day 516 的做法:

1. Parse 整个 HHT(20000 行,大概 50 ms)
2. 改 AST 里的那个 alignment point(< 1 ms)
3. 把整个 AST render 回文本(20000 行,大概 80 ms)
4. 写回磁盘(1.5 MB,大概 20 ms)

总时间:~150 ms。**用户感觉明显卡顿**——他点一下鼠标,150 ms 后屏幕才更新。按 60 FPS 计算,这是 9 帧的延迟。

更糟的是,如果用户在拖拽 alignment point(连续改 offset),每秒可能改 30 次。每次 150 ms,**编辑器直接僵死**——根本跟不上鼠标。

工业级编辑器(VSCode、Blender、Unity Inspector)的延迟应该 < 16 ms(一帧内完成)。要做到这点,必须**只改必要部分**——这就是 Day 517 的核心动机。

### Day 517 的核心策略:AST-level 结构化编辑

Casey Day 517 实现的是**结构化编辑**——以 AST 节点为单位操作,而不是以文本字符为单位。具体三件事:

**第一,精确定位**。改"hero.body 的 alignment point 'hand_r' 的 offset",这个操作在 AST 层面是"找到 hero entity → 找到 body piece → 找到 hand_r alignment point → 改 offset"。每一步是 O(n) 查找,总共 O(n),但 n 是单个 entity 的大小(几十),不是整个 HHT(几万)。

**第二,最小化重渲染**。改一个 alignment point 只影响那个节点的文本表示。Casey 简化版还是全量 render,但**结构上预留了"只 render 改变节点"的能力**。后期升级为 incremental render,从 80 ms 降到 < 1 ms。

**第三,保留身份**。AST 节点有"身份"(ID)。改 offset 不改变身份,UI 上的选中状态、undo 历史、动画过渡都能保留。文本编辑做不到——你改了文本,UI 不知道"这是同一个东西",会重置状态。

### 一个具体的例子

让我把"全量重写" vs "AST edit" 用具体数据对比。Hero 角色 HHT:

```
entity hero {
    piece body {
        sprite: hero_body.png
        alignment_point neck  (0, -20)
        alignment_point hand_r (15, 0)   ← 要改这个
        alignment_point hand_l (-15, 0)
        alignment_point foot_r (8, 30)
        alignment_point foot_l (-8, 30)
    }
    piece head {
        sprite: hero_head.png
        alignment_point top (0, -10)
    }
    # ... 还有 18 个 piece ...
}
```

**全量重写**(Day 516):
1. Read 20000 行,parse 成 AST → 50 ms
2. 改 AST 的一个 leaf → < 1 ms
3. Render 整个 AST → 20000 行 → 80 ms
4. Write 文件 → 1.5 MB → 20 ms

**AST edit**(Day 517):
1. AST 已经在内存(editor 启动时 parse 过)→ 0 ms
2. 找到 hero → body → hand_r → 0.1 ms
3. 改 offset → < 1 ms
4. (可选)Incremental render:只重渲染 hand_r 的文本 → 1 ms
5. (可选)Incremental write:只改文件里对应字节 → 0.1 ms

**单次操作**:全量 150 ms vs AST edit 1 ms,**150 倍加速**。

**连续 30 次操作/秒**:全量直接卡死(150×30 = 4500 ms / 秒 = 4.5 倍实时),AST edit 1×30 = 30 ms / 秒,完全流畅。

这就是为什么工业级编辑器都用 AST-level 编辑。VSCode 重命名变量、Blender 改节点参数、Unreal 改 Blueprint 节点,本质都是 AST edit + incremental render。

## 2 · 心智模型

### 2.1 类比:文档编辑

旧:每次改文档,全量重写。
新:只改一段。

Word / VSCode 都是增量编辑——改一段,其他不动。

AST-level 编辑同构:改 AST 节点,其他 AST 不动,最后 render。

让我把类比再推进一层。想象你写一篇 100 页论文,要改第 50 页第 3 段的一个词。

**全量重写**:把 100 页重新打印一遍。慢得离谱。
**文本编辑**:找到那一页,用涂改液覆盖旧词,写新词。中速,但可能涂坏邻近的词。
**结构化编辑**:论文有目录、章节、段落、句子的层级结构,你定位"第 50 页第 3 段第 7 词",只改这个词。精确,不影响其他。

代码 IDE(LSP、IntelliJ)用结构化编辑,重命名变量只影响真正的同一变量,不是同名。这就是为什么 VSCode 的 "Rename Symbol" 比 sed 安全——VSCode 知道 AST,sed 只知道字符串。

### 2.2 结构化编辑 vs 文本编辑

**文本编辑**:直接操作文本(字符串 replace)。简单,但容易破坏结构(改名字,影响其他同名)。

**结构化编辑**:操作 AST 节点。安全(只改指定节点),但需要 parse → edit → render 流程。

代码 IDE(LSP、IntelliJ)用结构化编辑,重命名变量只影响真正的同一变量,不是同名。

这两条路线的对比:

| 维度 | 文本编辑 | 结构化编辑 |
|---|---|---|
| 实现复杂度 | 简单(string API) | 复杂(需要 parser) |
| 安全性 | 低(可能误改同名) | 高(精确目标) |
| 速度 | 取决于 string size | 通常 O(log n) 或 O(1) |
| 语义理解 | 无 | 完整 |
| 适用场景 | sed/awk 简单替换 | IDE refactor / editor |

工业界典型:
- **`sed -i 's/foo/bar/'`** 是文本编辑,可能误改。
- **rust-analyzer "Rename Symbol"** 是结构化编辑,只改真正的同一符号。
- **VSCode "Find and Replace"** 是文本编辑(简单)。
- **IntelliJ "Rename"** 是结构化编辑(安全)。

### 2.3 AST 节点身份

AST 每个节点有"身份"(identity)。改名字不影响身份,只影响显示。

Rust 用 `Rc<Node>` 或 ID 表达身份。

```rust
struct Ast {
    nodes: Vec<Node>,
}

struct Node {
    id: NodeId,
    kind: NodeKind,
}

enum NodeKind {
    Entity { name: String, pieces: Vec<NodeId> },
    Piece { name: String, ... },
    AlignmentPoint { name: String, offset: Vec2 },
}
```

改节点:`nodes[id].kind = ...`。

**为什么要 ID 而不是指针?**

C/C++ 用指针(`Node*`)表达身份。问题:指针在节点移动时(malloc 重排内存)失效。Rust 的 borrow checker 让指针更难用——你拿了一个节点的 `&mut Node`,就不能同时拿兄弟节点的 `&mut Node`,因为它们共享同一父。

工业级 Rust 编译器(rustc、rust-analyzer)用 **arena allocation + ID index**。每个节点存在 `Vec<Node>` 里,ID 是 `u32` index。引用其他节点用 ID,不用指针。这样:

- 多个 ID 可以同时存在(borrow checker 不阻拦)
- Vec 重分配时,ID 仍然有效(只要不删除节点)
- 删除节点用 "tombstone"(标记为 deleted,不真删),保持 ID 稳定

这是 Rust 写大型 AST 的标配技巧。

### 2.4 Incremental render

只 render 改变的节点,其他保持原文本。

实现:

- 每个节点记录原文本范围(start_byte, end_byte)
- 改节点时,标记 dirty
- Render 时,只重渲染 dirty 节点,替换 [start_byte, end_byte]

复杂但高效。

让我展开实现细节:

```rust
struct Node {
    id: NodeId,
    kind: NodeKind,
    // 节点在最终文本里的位置
    text_range: Option<(usize, usize)>,  // None = 还没 render
    dirty: bool,
}

fn update_alignment_point(ast: &mut Ast, node_id: NodeId, new_offset: Vec2) {
    let node = &mut ast.nodes[node_id.0 as usize];
    if let NodeKind::AlignmentPoint { offset, .. } = &mut node.kind {
        *offset = new_offset;
        node.dirty = true;
        // 同时把所有祖先标记 dirty(因为子节点的字节范围可能变)
        mark_ancestors_dirty(ast, node_id);
    }
}

fn render_incremental(ast: &mut Ast, output: &mut String) {
    // 只重渲染 dirty 节点
    for node in &mut ast.nodes {
        if node.dirty {
            let old_range = node.text_range.unwrap();
            let new_text = render_node(&node.kind);
            output.replace_range(old_range.0..old_range.1, &new_text);
            // 更新本节点和后续节点的 text_range
            update_ranges_after(ast, node.id, new_text.len());
            node.dirty = false;
        }
    }
}
```

这是简化版。工业级实现(rust-analyzer 的 `rowan`)用 red-green tree,**所有节点的字节范围都自动维护**,增量 render 是 O(log n)。

Casey Day 517 简化:全量 render,但 AST 操作不变(便于将来加增量)。

### 2.5 Undo / Redo 的天然接口

AST-level 编辑还有个好处——**undo / redo 天然**。每次 edit 是一个离散操作,你把操作记到 history 栈,undo 反向操作,redo 正向操作。

```rust
enum EditOp {
    InsertAlignmentPoint { entity_id: NodeId, piece_id: NodeId, ap: AlignmentPoint },
    UpdateAlignmentPoint { ap_id: NodeId, old: Vec2, new: Vec2 },
    DeleteAlignmentPoint { entity_id: NodeId, piece_id: NodeId, ap: AlignmentPoint, index: usize },
}

struct History {
    undo_stack: Vec<EditOp>,
    redo_stack: Vec<EditOp>,
}

impl History {
    fn apply(&mut self, ast: &mut Ast, op: EditOp) {
        apply_op(ast, &op);  // 正向应用
        self.undo_stack.push(op);
        self.redo_stack.clear();  // 新操作清空 redo
    }

    fn undo(&mut self, ast: &mut Ast) {
        if let Some(op) = self.undo_stack.pop() {
            reverse_op(ast, &op);  // 反向
            self.redo_stack.push(op);
        }
    }

    fn redo(&mut self, ast: &mut Ast) {
        if let Some(op) = self.redo_stack.pop() {
            apply_op(ast, &op);
            self.undo_stack.push(op);
        }
    }
}
```

每个 op 是 AST 级别,不是文本级别。这意味着 undo 可以跨文本变化保留语义——比如你"重命名 + 改 offset",undo 会同时撤销两步,回到原始状态。

文本编辑做不到这点——文本 undo 只能"撤销最后一段字符变化",不能撤销"逻辑操作"。

### Lv1 · 概念辨析

**题**:AST-based 编辑比文本替换好在哪?

**参考解答**:三个理由:

第一,**精确**。改第 N 个 alignment point,AST edit 只改那个。文本 replace 可能改多个同名。

第二,**安全**。AST edit 保证结构完整(不会改坏 HHT 语法)。文本 replace 可能破坏。

第三,**语义保留**。AST edit 知道"这是 alignment point 名字",可以加约束(如必须唯一)。文本 replace 不懂语义。

代价:需要 parser,实现复杂。但用户编辑场景,这些代价值得。

### Lv2 · 动手实践

**题**:实现 HHT AST 的 insert / update / delete alignment point。验证操作正确。

完成标准:`cargo run` 显示三种操作的结果。

**参考解答**:

```rust
#[derive(Debug, Clone, PartialEq)]
struct Vec2 { x: f32, y: f32 }

#[derive(Debug, Clone, PartialEq)]
struct AlignmentPoint { name: String, offset: Vec2 }

#[derive(Debug, Clone, PartialEq)]
struct Piece {
    name: String,
    sprite: String,
    alignment_points: Vec<AlignmentPoint>,
}

#[derive(Debug, Clone, PartialEq)]
struct Entity {
    name: String,
    pieces: Vec<Piece>,
}

impl Entity {
    fn find_piece_mut(&mut self, name: &str) -> Option<&mut Piece> {
        self.pieces.iter_mut().find(|p| p.name == name)
    }
    
    fn insert_alignment_point(&mut self, piece_name: &str, ap: AlignmentPoint) -> Result<(), String> {
        let piece = self.find_piece_mut(piece_name)
            .ok_or_else(|| format!("piece '{}' not found", piece_name))?;
        
        if piece.alignment_points.iter().any(|p| p.name == ap.name) {
            return Err(format!("alignment_point '{}' already exists", ap.name));
        }
        
        piece.alignment_points.push(ap);
        Ok(())
    }
    
    fn update_alignment_point(&mut self, piece_name: &str, ap_name: &str, new_offset: Vec2) -> Result<(), String> {
        let piece = self.find_piece_mut(piece_name)
            .ok_or_else(|| format!("piece '{}' not found", piece_name))?;
        
        let ap = piece.alignment_points.iter_mut()
            .find(|p| p.name == ap_name)
            .ok_or_else(|| format!("alignment_point '{}' not found", ap_name))?;
        
        ap.offset = new_offset;
        Ok(())
    }
    
    fn delete_alignment_point(&mut self, piece_name: &str, ap_name: &str) -> Result<(), String> {
        let piece = self.find_piece_mut(piece_name)
            .ok_or_else(|| format!("piece '{}' not found", piece_name))?;
        
        let before = piece.alignment_points.len();
        piece.alignment_points.retain(|p| p.name != ap_name);
        
        if piece.alignment_points.len() == before {
            return Err(format!("alignment_point '{}' not found", ap_name));
        }
        Ok(())
    }
}

fn main() {
    let mut entity = Entity {
        name: "hero".into(),
        pieces: vec![
            Piece {
                name: "body".into(),
                sprite: "hero_body".into(),
                alignment_points: vec![
                    AlignmentPoint { name: "neck".into(), offset: Vec2 { x: 0.0, y: -20.0 } },
                ],
            },
        ],
    };
    
    println!("=== Initial ===");
    println!("{:#?}", entity.pieces[0].alignment_points);
    
    println!("\n=== Insert 'hand_r' ===");
    entity.insert_alignment_point("body", AlignmentPoint {
        name: "hand_r".into(), offset: Vec2 { x: 15.0, y: 0.0 },
    }).unwrap();
    println!("{:#?}", entity.pieces[0].alignment_points);
    
    println!("\n=== Update 'neck' to (0, -25) ===");
    entity.update_alignment_point("body", "neck", Vec2 { x: 0.0, y: -25.0 }).unwrap();
    println!("{:#?}", entity.pieces[0].alignment_points);
    
    println!("\n=== Delete 'hand_r' ===");
    entity.delete_alignment_point("body", "hand_r").unwrap();
    println!("{:#?}", entity.pieces[0].alignment_points);
    
    println!("\n=== Error cases ===");
    let r1 = entity.insert_alignment_point("missing_piece", AlignmentPoint {
        name: "x".into(), offset: Vec2 { x: 0.0, y: 0.0 },
    });
    println!("Insert to missing piece: {:?}", r1);
    
    let r2 = entity.delete_alignment_point("body", "missing_ap");
    println!("Delete missing ap: {:?}", r2);
}
```

### 8.1 完整可运行的 HHT AST editor

让我们从零做一个完整的 HHT editor,支持 insert/update/delete + undo/redo。

```bash
cargo new --bin hht-editor
cd hht-editor
```

`src/main.rs`:

```rust
// Day 517 完整 HHT AST editor
// 支持:insert / update / delete alignment point + undo / redo

#[derive(Debug, Clone, PartialEq)]
struct Vec2 { x: f32, y: f32 }

#[derive(Debug, Clone, PartialEq)]
struct AlignmentPoint { name: String, offset: Vec2 }

#[derive(Debug, Clone, PartialEq)]
struct Piece {
    name: String,
    sprite: String,
    alignment_points: Vec<AlignmentPoint>,
}

#[derive(Debug, Clone, PartialEq)]
struct Entity {
    name: String,
    pieces: Vec<Piece>,
}

// Edit operation - 用于 undo / redo
#[derive(Debug, Clone)]
enum EditOp {
    InsertAp {
        entity: String,
        piece: String,
        ap: AlignmentPoint,
    },
    UpdateAp {
        entity: String,
        piece: String,
        ap_name: String,
        old: Vec2,
        new: Vec2,
    },
    DeleteAp {
        entity: String,
        piece: String,
        ap: AlignmentPoint,
        index: usize,
    },
}

struct Editor {
    entities: Vec<Entity>,
    history: Vec<EditOp>,    // undo stack
    redo_stack: Vec<EditOp>, // redo stack
}

impl Editor {
    fn new() -> Self {
        Self { entities: vec![], history: vec![], redo_stack: vec![] }
    }

    // 内部 helper
    fn find_entity_mut(&mut self, name: &str) -> Option<&mut Entity> {
        self.entities.iter_mut().find(|e| e.name == name)
    }

    // 公共操作 - 都返回 Result 错误处理
    fn insert_ap(&mut self, entity: &str, piece: &str, ap: AlignmentPoint) -> Result<(), String> {
        let ent = self.find_entity_mut(entity)
            .ok_or_else(|| format!("entity '{}' not found", entity))?;
        let pce = ent.pieces.iter_mut().find(|p| p.name == piece)
            .ok_or_else(|| format!("piece '{}' not found", piece))?;
        if pce.alignment_points.iter().any(|x| x.name == ap.name) {
            return Err(format!("ap '{}' already exists", ap.name));
        }
        pce.alignment_points.push(ap.clone());
        // 记录到 history
        self.history.push(EditOp::InsertAp {
            entity: entity.into(),
            piece: piece.into(),
            ap,
        });
        self.redo_stack.clear();
        Ok(())
    }

    fn update_ap(&mut self, entity: &str, piece: &str, ap_name: &str, new_offset: Vec2) -> Result<(), String> {
        let ent = self.find_entity_mut(entity)
            .ok_or_else(|| format!("entity '{}' not found", entity))?;
        let pce = ent.pieces.iter_mut().find(|p| p.name == piece)
            .ok_or_else(|| format!("piece '{}' not found", piece))?;
        let ap = pce.alignment_points.iter_mut().find(|x| x.name == ap_name)
            .ok_or_else(|| format!("ap '{}' not found", ap_name))?;
        let old = ap.offset;
        ap.offset = new_offset;
        self.history.push(EditOp::UpdateAp {
            entity: entity.into(),
            piece: piece.into(),
            ap_name: ap_name.into(),
            old,
            new: new_offset,
        });
        self.redo_stack.clear();
        Ok(())
    }

    fn delete_ap(&mut self, entity: &str, piece: &str, ap_name: &str) -> Result<(), String> {
        let ent = self.find_entity_mut(entity)
            .ok_or_else(|| format!("entity '{}' not found", entity))?;
        let pce = ent.pieces.iter_mut().find(|p| p.name == piece)
            .ok_or_else(|| format!("piece '{}' not found", piece))?;
        let idx = pce.alignment_points.iter().position(|x| x.name == ap_name)
            .ok_or_else(|| format!("ap '{}' not found", ap_name))?;
        let ap = pce.alignment_points.remove(idx);
        self.history.push(EditOp::DeleteAp {
            entity: entity.into(),
            piece: piece.into(),
            ap,
            index: idx,
        });
        self.redo_stack.clear();
        Ok(())
    }

    fn undo(&mut self) -> Result<(), String> {
        let op = self.history.pop().ok_or("nothing to undo")?;
        match op {
            EditOp::InsertAp { entity, piece, ap } => {
                // 反向:删除刚插入的
                self.find_entity_mut(&entity).and_then(|e| {
                    e.pieces.iter_mut().find(|p| p.name == piece)
                }).map(|p| {
                    p.alignment_points.retain(|x| x.name != ap.name);
                }).ok_or("undo: entity/piece missing")?;
            }
            EditOp::UpdateAp { entity, piece, ap_name, old, .. } => {
                let ent = self.find_entity_mut(&entity).unwrap();
                let pce = ent.pieces.iter_mut().find(|p| p.name == piece).unwrap();
                let ap = pce.alignment_points.iter_mut().find(|x| x.name == ap_name).unwrap();
                ap.offset = old;
            }
            EditOp::DeleteAp { entity, piece, ap, index } => {
                let ent = self.find_entity_mut(&entity).unwrap();
                let pce = ent.pieces.iter_mut().find(|p| p.name == piece).unwrap();
                pce.alignment_points.insert(index, ap);
            }
        }
        self.redo_stack.push(op);
        Ok(())
    }

    fn redo(&mut self) -> Result<(), String> {
        let op = self.redo_stack.pop().ok_or("nothing to redo")?;
        // 正向:重新 apply
        match &op {
            EditOp::InsertAp { entity, piece, ap } => {
                self.insert_ap(entity, piece, ap.clone())?;
                // insert_ap 会 push 到 history,我们刚 pop 的要在 redo
                self.history.pop();
                self.redo_stack.clear();
                self.redo_stack.push(op);
            }
            EditOp::UpdateAp { entity, piece, ap_name, new, .. } => {
                self.update_ap(entity, piece, ap_name, *new)?;
                self.history.pop();
                self.redo_stack.clear();
                self.redo_stack.push(op);
            }
            EditOp::DeleteAp { entity, piece, ap, .. } => {
                let _ = ap.name.as_str(); // borrow checker
                // 简化:用 ap.name 查找并删
                let ent = self.find_entity_mut(entity).unwrap();
                let pce = ent.pieces.iter_mut().find(|p| p.name == piece.as_str()).unwrap();
                pce.alignment_points.retain(|x| x.name != ap.name);
            }
        }
        Ok(())
    }

    // Render AST 回 HHT 文本(全量,后续可改 incremental)
    fn render(&self) -> String {
        let mut out = String::new();
        for entity in &self.entities {
            out.push_str(&format!("entity {} {{\n", entity.name));
            for piece in &entity.pieces {
                out.push_str(&format!("    piece {} {{\n", piece.name));
                out.push_str(&format!("        sprite: {}\n", piece.sprite));
                for ap in &piece.alignment_points {
                    out.push_str(&format!("        alignment_point {} ({}, {})\n",
                        ap.name, ap.offset.x, ap.offset.y));
                }
                out.push_str("    }\n");
            }
            out.push_str("}\n");
        }
        out
    }
}

fn main() {
    let mut editor = Editor::new();
    editor.entities.push(Entity {
        name: "hero".into(),
        pieces: vec![
            Piece {
                name: "body".into(),
                sprite: "hero_body.png".into(),
                alignment_points: vec![
                    AlignmentPoint { name: "neck".into(), offset: Vec2 { x: 0.0, y: -20.0 } },
                ],
            },
        ],
    });

    println!("=== Initial HHT ===");
    println!("{}", editor.render());

    // Insert
    editor.insert_ap("hero", "body", AlignmentPoint {
        name: "hand_r".into(),
        offset: Vec2 { x: 15.0, y: 0.0 },
    }).unwrap();
    println!("=== After insert hand_r ===");
    println!("{}", editor.render());

    // Update
    editor.update_ap("hero", "body", "hand_r", Vec2 { x: 16.0, y: -1.0 }).unwrap();
    println!("=== After update hand_r ===");
    println!("{}", editor.render());

    // Undo twice
    editor.undo().unwrap();
    editor.undo().unwrap();
    println!("=== After undo ×2 ===");
    println!("{}", editor.render());

    // Redo
    editor.redo().unwrap();
    println!("=== After redo ===");
    println!("{}", editor.render());

    // Delete
    editor.delete_ap("hero", "body", "hand_r").unwrap();
    println!("=== After delete hand_r ===");
    println!("{}", editor.render());

    // Undo delete
    editor.undo().unwrap();
    println!("=== After undo delete (hand_r back) ===");
    println!("{}", editor.render());

    println!("History size: {}", editor.history.len());
    println!("Redo stack size: {}", editor.redo_stack.len());
}
```

### 8.3 用 rowan(工业级 AST 库)

`rowan` 是 rust-analyzer 的底层 AST 库,支持增量重渲染。让我们看一个简化的使用例子。

```toml
# Cargo.toml
[dependencies]
rowan = "0.15"
```

```rust
use rowan::{GreenNodeBuilder, SyntaxNode};

fn main() {
    // 构造一个简单的 AST
    let mut builder = GreenNodeBuilder::new();
    builder.start_node(rowan::SyntaxKind(1));  // Entity node
    builder.token(rowan::SyntaxKind(2), "entity");
    builder.token(rowan::SyntaxKind(3), " hero ");
    builder.start_node(rowan::SyntaxKind(4));  // Piece node
    builder.token(rowan::SyntaxKind(5), "piece");
    builder.finish_node();
    builder.finish_node();
    let green = builder.finish();

    let node: SyntaxNode<Lang> = SyntaxNode::new_root(green);
    println!("AST: {:?}", node);
    // rowan 自动管理节点的字节范围,增量 render 是 O(log n)
}
```

工业级 IDE(rust-analyzer、IntelliJ Rust、Roslyn for C#)都用类似 rowan 的技术。这是结构化编辑的工业金标。

### 8.5 Troubleshooting

**问题1**:undo 后,editor UI 的选中状态错乱。
原因:节点身份在 undo 时丢失(因为是文本级 undo 不是 AST 级)。
解决:用 ID-based undo(本日方案),不是文本级 undo。

**问题2**:大量 op 后 history 占用大量内存。
原因:每个 op 存了完整状态。
解决:对大对象(如完整 entity)存 diff(只存变化字段),不存完整对象。

**问题3**:并发编辑冲突(多用户)。
原因:两个用户同时改同一 HHT。
解决:用 Operational Transformation (OT) 或 CRDT(分布式算法)。VSCode Live Share、Google Docs 都用这套。

**问题4**:Edit op 跨进程(网络)序列化。
原因:远程协作场景。
解决:每个 op 实现 Serialize/Deserialize,通过 WebSocket 同步。

**问题5**:AST render 性能仍然不够。
原因:全量 render 即便用 rowan 也是 O(n)。
解决:用 incremental render(rowan 支持),只 render 改变节点 + 子树。

```rust
#[cfg(test)]
mod tests {
    use super::*;

    fn make_test_editor() -> Editor {
        let mut editor = Editor::new();
        editor.entities.push(Entity {
            name: "hero".into(),
            pieces: vec![
                Piece {
                    name: "body".into(),

    #[test]
    fn test_insert_and_undo() {
        let mut e = make_test_editor();
        e.insert_ap("hero", "body", AlignmentPoint {
            name: "hand".into(),
            offset: Vec2 { x: 10.0, y: 0.0 },
        }).unwrap();
        assert_eq!(e.entities[0].pieces[0].alignment_points.len(), 2);
        e.undo().unwrap();
        assert_eq!(e.entities[0].pieces[0].alignment_points.len(), 1);
    }

    #[test]
    fn test_undo_redo_cycle() {
        let mut e = make_test_editor();
        e.update_ap("hero", "body", "neck", Vec2 { x: 1.0, y: -25.0 }).unwrap();
        let offset_after_update = e.entities[0].pieces[0].alignment_points[0].offset;
        assert_eq!(offset_after_update.y, -25.0);
        e.undo().unwrap();
        let offset_after_undo = e.entities[0].pieces[0].alignment_points[0].offset;
        assert_eq!(offset_after_undo.y, -20.0);  // 回到原始
        e.redo().unwrap();
        let offset_after_redo = e.entities[0].pieces[0].alignment_points[0].offset;
        assert_eq!(offset_after_redo.y, -25.0);  // 又改回去
    }

    #[test]
    fn test_new_op_clears_redo() {
        let mut e = make_test_editor();
        e.update_ap("hero", "body", "neck", Vec2 { x: 1.0, y: -25.0 }).unwrap();
        e.undo().unwrap();
        assert_eq!(e.redo_stack.len(), 1);
        // 新操作应该清空 redo
        e.insert_ap("hero", "body", AlignmentPoint {
            name: "new".into(),
            offset: Vec2 { x: 0.0, y: 0.0 },
        }).unwrap();
        assert_eq!(e.redo_stack.len(), 0);  // redo 清空
    }

            offset: Vec2 { x: 15.0, y: 0.0 },
```
