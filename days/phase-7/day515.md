
# Day 515 · 调试 HHT 到 HHA 打包

> Day 514 分离了图像和元数据 import。Day 515 调试 HHT → HHA 打包过程中的 bug:offset 错位、字段顺序不一致、字符串编码问题。

## 0 · 为什么要有这一天

### 真实场景:打包 bug 的痛苦

你跟着 Casey 做到 Day 514。你实现了 HHT → HHA 的打包器(import PNG + parse HHT → serialize HHA)。表面上跑通了——打包器接受输入,输出 .hha 文件,加载器能读 .hha,游戏能渲染 sprite。

但你做几个 edge case 测试,bug 立刻浮现:

**bug A:第二个 entity 名字乱码**。打包 2 个 entity(hero、goblin),加载后第一个名字 "hero" 正确,第二个变成乱码(类似 "\0\0\0\x05\x64gob")。前端 UI 显示一串不可读字符。

**bug B:alignment_point 数量总是 0**。每个 entity 应该有 3-5 个 alignment_point,但加载后 `ap_count = 0`,所有 alignment_point 都丢。游戏运行时 sprite 位置错乱。

**bug C:某些浮点数 round-trip 后变 NaN**。offset (15.0, -1.0) 打包前正常,加载后变成 (NaN, -inf)。游戏崩溃。

这些是**序列化典型 bug**——任何写过二进制 I/O 的程序员都见过。根本原因:

1. **字节序**:write 用 LE,read 误用 BE(或相反)。导致数字读出来完全错。
2. **变长字段**:字符串长度字段写错(写实际长度 vs 缓冲区长度)。导致字符串读错位。
3. **字段顺序**:serialize 按 [name, count, image_id] 顺序,deserialize 按 [name, image_id, count] 顺序。导致字段值互换。
4. **对齐**:某些字段需要 padding,你写了 padding 但没读(或反之)。导致 offset 计算错位。
5. **浮点位模式**:NaN 的位模式(0x7FC00000)写对了,但 read 时 from_le_bytes 调用错。NaN 变成 0.0。

Day 515 调试这些 bug,让你理解序列化的"陷阱地图"——以后写任何序列化代码都能避开。

### 为什么调试序列化 bug 这么难

序列化 bug 比普通 bug 难,因为:

**第一,不对称性**。serialize 和 deserialize 是两段独立代码。bug 可能在任一边,你看一边的代码找不到。Casey 在视频里反复说:"如果 serialize 看着对,bug 在 deserialize;反之亦然。"**必须同时看两边**。

**第二,二进制不可读**。bug 的表现是"二进制流里有问题",但你看二进制流是 hex dump,人眼很难直接看出 "0x05" 应该是 "0x04"。需要工具辅助(hexdump、readelf、xxd)。

**第三,offset 累积**。一个字段长度算错,后面所有字段的 offset 都错。bug 表现"在最后",根本原因"在最前"。你要从头追到尾。

**第四,bug 不立刻显现**。serialize 写出的二进制"看起来对"(没崩溃),desrialize 读出来"部分对"(几个字段正确,几个错误)。游戏跑半秒才崩,栈追踪指向"使用错误数据"的地方,而不是"数据生成错误"的地方。

工业界的对应场景:
- **网络协议**:client / server 跨语言(Java client, Rust server),序列化格式不一致。bug 难复现(只在特定 payload 出现)。
- **存档兼容**:游戏 v1.0 的存档,v1.1 加载,字段顺序变了。bug 表现是"老存档损坏"。
- **跨平台**:Windows 上写入的 binary,macOS 上读取。字节序 / 对齐差异导致 bug。

### 工业级序列化的纪律

成熟项目的序列化代码遵循这些纪律:

**纪律 1:Round-trip test**。每个数据结构有 round-trip 测试——serialize 后 deserialize,必须得到 equal 的结果。

**纪律 2:Schema 演化协议**。文件格式有版本号。新版本读老版本(向后兼容),老版本读新版本可能跳过未知字段(向前兼容)。

**纪律 3:不手写字节序**。用 helper(`to_le_bytes` / `from_le_bytes`),不直接 cast 指针。Rust 的 helper 自动正确,手写易错。

**纪律 4:Binary format 文档**。写一份"格式规范"文档,说清楚每个字段的 byte offset、类型、字节序。新 contributor 看文档写代码,不看源码。

**纪律 5:Migration test**。CI 自动测试"老版本生成的数据,新版本能正确读"。一旦破坏向后兼容,CI 红灯。

Casey 在 Day 515 演示的是纪律 1(round-trip)和纪律 3(用 helper)的修复过程。完整工业级还有 2、4、5,这些后续天数会涉及。

## 2 · 心智模型

### 类比:打包搬家

搬家时,你把东西装箱子,标签写"厨房:锅碗"。搬完后开箱,按标签归位。

如果标签写错(写了"杂物"),开箱后找不到。或者标签写"12 件",实际箱里 11 件,开箱出错。

HHT → HHA 打包是装箱。HHA → game 是开箱。两端必须严格对称。

### 序列化的对称性

**Serialize**:struct → bytes,write 顺序 X
**Deserialize**:bytes → struct,read 顺序必须 X

任何字段顺序、字节序、长度计算,两端必须一致。

不对称 = 数据损坏。

### 字节序

数字在内存里是字节序列。两种排列:

- **Little Endian(LE)**:低位在前。x86 / ARM 默认。
- **Big Endian(BE)**:高位在前。网络字节序、Java。

Rust 的 `to_le_bytes()` / `from_le_bytes` 是 LE。两端都用 LE,没问题。

历史 bug:不同平台不同字节序,跨平台读文件乱码。现代用 LE 一致。

### 变长字段

字符串、Vec 是变长。序列化标准做法:**先写长度,再写数据**。

```
[len: u32][bytes: len]
```

读时:先读 len,分配 len 字节 buffer,读 bytes。

Casey bug A 错在:用 capacity 而非 len。capacity 可能 > len(buffer 多分配但未填满)。

### 字段对齐

某些格式要 padding,让字段对齐 4 或 8 字节边界。加速 read。

```
[field_a: u8][padding: 3 bytes][field_b: u32]
```

Casey 不用对齐(紧挨),简化。

### Round-trip 测试

```
let original = ...;
let bytes = serialize(&original);
let loaded = deserialize(&bytes);
assert_eq!(original, loaded);
```

每个数据类型必须有 round-trip 测试。是序列化的"金标准"。

### Lv1 · 概念辨析

**题**:为什么 round-trip 测试是序列化的"金标准"?

**参考解答**:三个理由:

第一,**端到端覆盖**。Round-trip 同时测 serialize 和 deserialize。任何一端错,测试失败。

第二,**自动验证**。给定 original,序列化 → 反序列化,应该得到 equal 的结果。无需手算"应该是什么"。

第三,**可扩展**。加新字段,只要 derive `PartialEq`,round-trip 测试自动覆盖。

替代:单测 serialize 输出 byte 流。但 byte 流改变(加字段)就要改测试。Round-trip 更稳定。

```rust
#[derive(Debug, PartialEq, Clone)]
struct Entity {
    name: String,
    alignment_count: u32,
    image_id: u32,
}

// === Buggy 版本:serialize 和 deserialize 字段顺序不同 ===
fn serialize_buggy(e: &Entity) -> Vec<u8> {
    let mut buf = Vec::new();
    buf.extend_from_slice(&(e.name.len() as u32).to_le_bytes());
    buf.extend_from_slice(e.name.as_bytes());
    buf.extend_from_slice(&e.alignment_count.to_le_bytes());
    buf.extend_from_slice(&e.image_id.to_le_bytes());
    buf
}

fn deserialize_buggy(bytes: &[u8]) -> Entity {
    let mut pos = 0;
    let name_len = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap()) as usize;
    pos += 4;
    let name = String::from_utf8(bytes[pos..pos+name_len].to_vec()).unwrap();
    pos += name_len;
    // Bug:先读 image_id,再读 alignment_count
    let image_id = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap());
    pos += 4;
    let alignment_count = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap());
    Entity { name, alignment_count, image_id }
}

// === Fixed 版本:字段顺序一致 ===
fn deserialize_fixed(bytes: &[u8]) -> Entity {
    let mut pos = 0;
    let name_len = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap()) as usize;
    pos += 4;
    let name = String::from_utf8(bytes[pos..pos+name_len].to_vec()).unwrap();
    pos += name_len;
    // Fixed:alignment_count 先
    let alignment_count = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap());
    pos += 4;
    let image_id = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap());
    Entity { name, alignment_count, image_id }
}

fn main() {
    let original = Entity {
        name: "hero".into(),
        alignment_count: 5,
        image_id: 42,
    };
    
    println!("=== Original ===\n  {:?}", original);
    
    let bytes = serialize_buggy(&original);
    println!("\nSerialized: {} bytes", bytes.len());
    println!("Hex: {:02x?}", &bytes);
    
    println!("\n=== Buggy round-trip ===");
    let loaded_buggy = deserialize_buggy(&bytes);
    println!("  {:?}", loaded_buggy);
    println!("  match: {}", original == loaded_buggy);
    
    println!("\n=== Fixed round-trip ===");
    let loaded_fixed = deserialize_fixed(&bytes);
    println!("  {:?}", loaded_fixed);
    println!("  match: {}", original == loaded_fixed);
}
```

### 8.1 完整 HHA 打包器(带 bug + 修复)

让我们从零做一个完整的 HHA 打包器,故意制造 Day 515 的三个 bug,然后用 hex dump 调试 + 修复。

```bash
cargo new --bin hha-packer
cd hha-packer
```

`src/main.rs`:

```rust
use std::fs::File;
use std::io::{Read, Write};

// ============================================================
// 数据结构
// ============================================================
#[derive(Debug, Clone, PartialEq)]
struct AlignmentPoint {
    name: String,
    offset: (f32, f32),
}

#[derive(Debug, Clone, PartialEq)]
struct Entity {
    name: String,
    image_id: u32,
    alignment_points: Vec<AlignmentPoint>,
}

// ============================================================
// BUGGY 版本(故意制造 3 个 bug)
// ============================================================
fn serialize_buggy(entities: &[Entity]) -> Vec<u8> {
    let mut buf = Vec::new();
    buf.extend_from_slice(&(entities.len() as u32).to_le_bytes());

    for e in entities {
        // BUG A: 用 capacity 而非 len
        let bad_len = e.name.capacity() as u32;
        buf.extend_from_slice(&bad_len.to_le_bytes());
        buf.extend_from_slice(e.name.as_bytes());

        // BUG B: 字段顺序写 image_id 在 alignment_points 之前
        buf.extend_from_slice(&e.image_id.to_le_bytes());
        buf.extend_from_slice(&(e.alignment_points.len() as u32).to_le_bytes());

        for ap in &e.alignment_points {
            let bad_len = ap.name.capacity() as u32;
            buf.extend_from_slice(&bad_len.to_le_bytes());
            buf.extend_from_slice(ap.name.as_bytes());

            // BUG C: 用 mem-discriminant 而非 to_le_bytes
            let x_bytes = ap.offset.0.to_le_bytes();
            let y_bytes = ap.offset.1.to_be_bytes();  // BUG: BE 而非 LE
            buf.extend_from_slice(&x_bytes);
            buf.extend_from_slice(&y_bytes);
        }
    }
    buf
}

// ============================================================
// FIXED 版本
// ============================================================
fn serialize_fixed(entities: &[Entity]) -> Vec<u8> {
    let mut buf = Vec::new();
    buf.extend_from_slice(&(entities.len() as u32).to_le_bytes());

    for e in entities {
        // FIX A: 用 len 而非 capacity
        let len = e.name.len() as u32;
        buf.extend_from_slice(&len.to_le_bytes());
        buf.extend_from_slice(e.name.as_bytes());

        // FIX B: 字段顺序 count 先,image_id 后(与 deserialize 一致)
        buf.extend_from_slice(&(e.alignment_points.len() as u32).to_le_bytes());
        buf.extend_from_slice(&e.image_id.to_le_bytes());

        for ap in &e.alignment_points {
            let len = ap.name.len() as u32;
            buf.extend_from_slice(&len.to_le_bytes());
            buf.extend_from_slice(ap.name.as_bytes());

            // FIX C: 都用 LE
            buf.extend_from_slice(&ap.offset.0.to_le_bytes());
            buf.extend_from_slice(&ap.offset.1.to_le_bytes());
        }
    }
    buf
}

fn deserialize(bytes: &[u8]) -> Result<Vec<Entity>, String> {
    let mut pos = 0;
    if bytes.len() < 4 {
        return Err("file too short".into());
    }
    let count = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap()) as usize;
    pos += 4;

    let mut entities = Vec::with_capacity(count);
    for _ in 0..count {
        if pos + 4 > bytes.len() { return Err("truncated name len".into()); }
        let name_len = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap()) as usize;
        pos += 4;

        if pos + name_len > bytes.len() { return Err("truncated name".into()); }
        let name = String::from_utf8(bytes[pos..pos+name_len].to_vec())
            .map_err(|e| e.to_string())?;
        pos += name_len;

        // 字段顺序:count 先
        if pos + 4 > bytes.len() { return Err("truncated ap count".into()); }
        let ap_count = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap()) as usize;
        pos += 4;

        if pos + 4 > bytes.len() { return Err("truncated image_id".into()); }
        let image_id = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap());
        pos += 4;

        let mut aps = Vec::with_capacity(ap_count);
        for _ in 0..ap_count {
            if pos + 4 > bytes.len() { return Err("truncated ap name len".into()); }
            let ap_name_len = u32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap()) as usize;
            pos += 4;

            if pos + ap_name_len > bytes.len() { return Err("truncated ap name".into()); }
            let ap_name = String::from_utf8(bytes[pos..pos+ap_name_len].to_vec())
                .map_err(|e| e.to_string())?;
            pos += ap_name_len;

            if pos + 8 > bytes.len() { return Err("truncated offset".into()); }
            let x = f32::from_le_bytes(bytes[pos..pos+4].try_into().unwrap());
            let y = f32::from_le_bytes(bytes[pos+4..pos+8].try_into().unwrap());
            pos += 8;

            aps.push(AlignmentPoint { name: ap_name, offset: (x, y) });
        }

        entities.push(Entity { name, image_id, alignment_points: aps });
    }

    Ok(entities)
}

fn main() {
    let entities = vec![
        Entity {
            name: "hero".into(),
            image_id: 1,
            alignment_points: vec![
                AlignmentPoint { name: "neck".into(), offset: (0.0, -20.0) },

    match deserialize(&buggy_bytes) {
        Ok(loaded) => {
            println!("Loaded:");
            for e in &loaded {
                println!("  {:?}", e);
            }
            println!("Match: {}", entities == loaded);
        }
        Err(e) => println!("Deserialize error: {}", e),
    }

    // FIXED round-trip
    println!("\n=== FIXED serialize + deserialize ===");
    let fixed_bytes = serialize_fixed(&entities);
    match deserialize(&fixed_bytes) {
        Ok(loaded) => {
            println!("Loaded:");
            for e in &loaded {
                println!("  {:?}", e);
            }
            println!("Match: {}", entities == loaded);
        }
        Err(e) => println!("Deserialize error: {}", e),
    }

    // 写到文件,用 hexdump 看

    file.write_all(&fixed_bytes).unwrap();
}
```

### 8.3 用 bincode 替代手写

工业级推荐用 `bincode`,自动处理字段顺序、字节序、长度前缀。

```toml
# Cargo.toml
[dependencies]
serde = { version = "1", features = ["derive"] }
bincode = "1"
```

```rust
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize, PartialEq, Debug, Clone)]
struct AlignmentPoint {
    name: String,
    offset: (f32, f32),
}

#[derive(Serialize, Deserialize, PartialEq, Debug, Clone)]
struct Entity {
    name: String,
    image_id: u32,
    alignment_points: Vec<AlignmentPoint>,
}

fn main() {
    let entities = vec![
        Entity {
            name: "hero".into(),
            image_id: 1,
            alignment_points: vec![
                AlignmentPoint { name: "neck".into(), offset: (0.0, -20.0) },
            ],
        },
    ];

    // 序列化(自动处理所有边界 case)
    let bytes = bincode::serialize(&entities).unwrap();
    println!("Bincode size: {} bytes", bytes.len());

    // 反序列化
    let loaded: Vec<Entity> = bincode::deserialize(&bytes).unwrap();
    assert_eq!(entities, loaded);
    println!("Round-trip: OK");
}
```

bincode 帮你:
- 自动处理字段顺序(derive 生成对称的 serialize / deserialize)
- 自动用 LE
- 自动写 Vec / String 的长度前缀
- 自动 derive PartialEq,round-trip 测试方便

**代价**:依赖 serde + bincode。但对工业项目,这个 trade-off 划算。

### 8.5 Troubleshooting

**问题1**:deserialize 报 "truncated X"。
诊断:pos 累加错位。在 deserialize 里加 println! 打印每步 pos,看哪步超 out of bounds。
解决:找到字段长度算错的位置。

**问题2**:数字读出来完全错(比如 image_id 应该 1,实际 16777216)。
诊断:字节序错。16777216 = 0x01000000,意思是读 LE 写的 [01, 00, 00, 00] 时按 BE 读成 0x01000000。
解决:统一 to_le_bytes / from_le_bytes。

**问题3**:字符串读出来是 UTF-8 解码错误。
诊断:长度字段算错,读了垃圾字节。
解决:hex dump 看长度字段实际值,对照预期。

**问题4**:f32 的 NaN / Inf round-trip 失败。
诊断:f32::from_le_bytes 处理 NaN 位模式时,某些平台会"规范化"NaN(把 signaling NaN 变成 quiet NaN),导致位模式不同。
解决:对 NaN / Inf 特殊处理——序列化时检查,用 sentinel value 表示。

**问题5**:跨平台 read 文件,Windows 上写入 macOS 上读取。
诊断:endian + alignment + struct padding 在不同平台不同。
解决:永远用 LE、显式 padding(写 `[u8; 3]` 而不是依赖编译器对齐)、用 bincode 等成熟库。
