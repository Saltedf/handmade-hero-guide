## 2 · 心智模型

### 类比:球面上撒芝麻

想象一颗空心玻璃球,你想在它的外表面均匀粘上 N 颗芝麻。如果 N=100,你大概能凭直觉把它们摆得"看上去均匀"。但如果 N=10000 呢?你怎么保证既不挤成一团,也不留大块空地?

物理学家处理过这个问题,化学家也处理过(电子云分布)。**球面螺旋分布(Spiral Distribution)** 是 1958 年 Robert Bauer 提出的一个巧妙答案:把球面当成一根从北极绕到南极的螺旋线,然后在这根线上等弧长取 N 个点。**直觉**:就像你拿一支记号笔在鸡蛋上从顶到底画一根螺旋线,沿途等距盖章。

**蓝噪声**则更像把 N 只互相排斥的电子放到球面上,让它们自动找到平衡位置。它没有简单公式,通常是预先生成(用模拟退火或 Lloyd 松弛)然后存成纹理。

### 严谨原理:球面螺旋公式

**球面坐标**:球面上任意一点可以用两个角表示——`θ`(theta,极角,从北极 0 到南极 π)和 `φ`(phi,方位角,绕赤道 0 到 2π)。转回 3D 笛卡尔坐标:

```
x = sin(θ) cos(φ)
y = sin(θ) sin(φ)
z = cos(θ)
```

**Bauer 螺旋的核心想法**:让 θ 从 0 到 π 线性变化,而 φ 让它"恰好绕 K 圈",K 是一个和 N 有关的常数。具体地:

```
对 i = 0, 1, ..., N-1:
    θ_i = arccos(1 - 2*(i + 0.5)/N)     // 极角,等分 [0, π]
    φ_i = π * (1 + sqrt(5)) * i          // 方位角,按黄金比例旋转
```

**为什么用 `1 + sqrt(5)`?** 这就是**黄金比例 φ ≈ 1.618** 的两倍——数学上叫"黄金角"思想:让相邻两个点的方位角差永远是 `π * (1+√5) ≈ 5.736` 弧度,mod 2π 后变成约 2.3998 弧度(约 137.5°)。这个角度有个奇妙性质:它"最不容易让点重合",所以连续取 N 次后,点的分布在球面上看起来最均匀。这和向日葵种子排列、菠萝皮纹理用的是同一套数学——**叶序(phyllotaxis)**。

**为什么 `(i + 0.5)/N` 而不是 `i/N`?** 用 `i/N` 会让第一个点出现在北极(i=0,θ=0),最后一个出现在南极(i=N-1,θ=π),两端极点会"挤压"。用 `(i+0.5)/N` 是把每个点的位置放到"它所在区间的中点",这是数值积分里**中点法则**的精神。

把这些写成 Rust:

```rust
// N=采样数,i=第几个点,返回 (x, y, z) 单位向量
fn spiral_point(i: usize, n: usize) -> (f32, f32, f32) {
    // (i + 0.5) / n 在 (0, 1) 区间均匀取值
    let t = (i as f32 + 0.5) / n as f32;
    // 极角 θ:1 - 2t 把 (0,1) 翻转成 (1,-1),再 arccos 得到 θ ∈ (0, π)
    let theta = (1.0 - 2.0 * t).acos();
    // 方位角 φ:按黄金角累加
    let phi = std::f32::consts::PI * (1.0 + 5.0_f32.sqrt()) * i as f32;
    let (sin_t, cos_t) = theta.sin_cos();
    let (sin_p, cos_p) = phi.sin_cos();
    (sin_t * cos_p, sin_t * sin_p, cos_t)
}
```

每行注释:
- `t` 是"归一化位置",从 0 到 1,中间 0.5 表示赤道。
- `1.0 - 2.0 * t` 把 t 从 [0,1] 映射到 z 坐标 [1,-1]。**为什么这么绕?** 因为球面上"等面积"对应"z 坐标等分",而不是"θ 等分"。这是球面几何的一个反直觉点:如果 θ 等分,两极会挤(因为靠近极点的"纬度圈"周长变短)。
- `acos` 把 z 反算回 θ,只是为了后面用球面坐标算 x/y。其实可以**绕过 θ**,直接用 z:`x = sqrt(1-z²) cos(φ)`,`y = sqrt(1-z²) sin(φ)`。Casey 在 Day 437 会做这个优化。
- `5.0_f32.sqrt()` 是 √5,写成字面量类型后缀是因为不写时编译器不知道是 f32 还是 f64。
- 最后三行就是球面坐标到笛卡尔坐标的转换公式。

### 蓝噪声:不是公式,是纹理

蓝噪声没有闭式公式。它是一种"频谱特征":功率谱在低频(大块结构)几乎为 0,在高频(细密噪点)有能量。**直觉**:蓝噪声就像白噪声被滤掉了"低频成分",所以画面上没有大块的明暗斑块,只有均匀的细密颗粒。

生成蓝噪声的方法(不在今天实现):
1. **Void-and-cluster**:从一个随机分布开始,找到"最密集"的点移到"最空"的地方,迭代收敛。
2. **Lloyd relaxation**:把所有点用 Voronoi 切分,每个点移动到它所在 Voronoi 单元的重心,迭代收敛。
3. **模拟退火**:让点两两排斥,模拟物理降温。

实践中你不会每次算——你会下载一张预生成好的蓝噪声纹理(比如 64×64),需要 N 个点时,从纹理中取 N 个最亮的像素。

### 为什么这两种比"纯随机"好

纯随机(白噪声)在球面上撒点会出现"团块和空洞"——这是统计学的基本性质:独立采样点的距离方差很大。

蓝噪声和螺旋都把"两两距离"控制得很均匀,方差小。反映在画面上,蓝噪声的噪点更细密不显眼,螺旋甚至完全没有随机性,适合"必须确定性"的场景(测试、debug)。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏中用到球面/半球采样的场景:

- **软阴影(PCF / ray-traced shadows)**:每个像素朝光源方向半球发 N 根射线,统计被遮挡的比例
- **环境光照(IBL / Image-Based Lighting)**:每像素朝半球采样环境贴图,积分得到漫反射/镜面反射光照
- **反射(SSR / ray-traced reflection)**:沿表面法线的反射半球发射线,找碰撞物
- **全局光照(GI)**:半球上反弹光线,积累间接光照

每个场景的采样数 N 在 1(硬阴影)到 1024(path tracing)之间。N 越大,画面越干净,但帧率越低。**分布质量决定"相同 N 下的画面质量"**——这就是为什么 Casey 在乎。

工程坑:**预计算 vs 实时**。N 个点(可能 64 个 float3)只 768 字节,完全可以预计算放进静态数组。但如果你想做"重要性采样"(在亮的地方多采),就得动态生成。Casey Day 437 会展示预计算版本的代码。

### 3.2 · 图形学视角

图形学的核心难题之一:**Monte Carlo 积分**。计算半球上某个函数的积分:

```
∫∫_hemisphere f(ω) dω  ≈  (1/N) Σ f(ω_i)
```

`ω_i` 是 N 个采样方向。这个近似的方差取决于 `f` 和采样分布的匹配度。如果 `f` 很平滑(漫反射),均匀分布就够;如果 `f` 很尖锐(镜面反射),就要用**重要性采样**——在尖锐的方向多采。

球面螺旋在工业界很少用于最终渲染(它不对应任何概率密度函数 PDF),但作为"快速 debug"和"无 RNG 噪声"的工具很受欢迎。蓝噪声则是**实时渲染的工业标配**:Unreal Engine 的 TAA(时序抗锯齿)、SIGGRAPH 论文里的"蓝噪声抖动",都用它。

进阶术语:
- **低差异性序列(low-discrepancy sequence)**:Halton、Sobol、Hammersley。它们比螺旋更严格——数学上有"差异性"度量。
- **Hammersley point set**:和螺旋同源,但用 bit-reversal 算第二个坐标。GPU 友好。
- **Halton sequence**:任意 base 的根数序列,适合"逐步加密"的采样。

### 3.3 · Linux 系统编程视角

这一集基本不涉及 Linux 系统调用——它是纯数学。但有一个工具链角度值得提:

**Linux 上做数值实验的高效工作流**:你写完一段 Rust 采样代码,想"看看分布到底长什么样",Casey 的做法是把点 dump 到一张 debug BMP 里。Linux 上更现代的做法是:

```bash
# 在 Rust 里把点 dump 成 CSV
cargo run --release > /tmp/points.csv

# 用 gnuplot 画极坐标投影
gnuplot -e "
set terminal png size 800,800;
set output '/tmp/spiral.png';
plot '/tmp/points.csv' using 1:2 with points pt 7 ps 0.5;
"

# 用 feh 直接看图
feh /tmp/spiral.png
```

这种"算法 → CSV → gnuplot → 图"的循环是图形学研究者的日常。比 Casey 的"内嵌 debug overlay"更快验证算法本身。

**汇编角度**:球面螺旋每个点要算一次 `acos`、两次 `sin`、两次 `cos`。在 x86_64 上,这些是硬件 transcendental 指令吗?**不是**——x86 没有 `acosss` 指令,`libm` 用多项式近似实现。Rust 的 `f32::acos()` 编译成 `call acosf@PLT`。如果你要算几百万个点,这个 PLT 跳转和函数调用开销会成为瓶颈。

工业级解决:`fast-math` crates(如 `sleef`、`micromath`)用 SIMD 多项式近似,4 倍速。Casey Day 437 不优化,因为他只算一次。

### 3.4 · Rust 生态视角

Rust 写球面螺旋非常简洁。但有几个特性值得专门讲:

**A. `const fn` 让预计算发生在编译期**

```rust
const N: usize = 64;
const SPIRAL: [(f32, f32, f32); N] = {
    let mut arr = [(0.0, 0.0, 0.0); N];
    let mut i = 0;
    while i < N {
        let t = (i as f32 + 0.5) / N as f32;
        let theta = (1.0 - 2.0 * t).acos();
        let phi = std::f32::consts::PI * (1.0 + 5.0_f32.sqrt()) * i as f32;
        let (sin_t, cos_t) = theta.sin_cos();
        let (sin_p, cos_p) = phi.sin_cos();
        arr[i] = (sin_t * cos_p, sin_t * sin_p, cos_t);
        i += 1;
    }
    arr
};
```

`const fn` 在编译期执行,运行时 `SPIRAL` 已经是计算好的常量数组,直接进 `.rodata` 段。**坑**:`const fn` 里不能用 `for` 循环(Rust 1.46 起只能用 `while`),且 `acos`/`sqrt` 在 `const fn` 里需要 Rust 1.65+ 才稳定。

**B. 数组 vs Vec**

```rust
// 栈上数组,编译期已知大小
let points: [(f32,f32,f32); 64] = build_spiral(64);

// 堆上 Vec,运行期决定大小
let points: Vec<(f32,f32,f32)> = (0..n).map(|i| spiral_point(i, n)).collect();
```

N 固定用数组,零分配;N 可变用 Vec,有堆分配开销但灵活。Casey 在 Day 437 选了固定 N(64),所以走数组。

**C. SIMD 友好的布局**

如果你要给每个采样点附加权重、PDF 等元数据,布局选择会影响性能:

```rust
// AoS:每个点连续
struct Sample { dir: (f32,f32,f32), pdf: f32 }
let samples: [Sample; 64] = ...;

// SoA:所有方向连续,所有 PDF 连续
struct SampleSoA { dirs: [(f32,f32,f32); 64], pdfs: [f32; 64] }
```

AoS 适合"每次访问一个点的全部字段";SoA 适合"批量处理所有点的同一字段"。Monte Carlo 积分通常是后者,所以 SoA 更优。

**真实 crate**:`pacquet`、`samples` 等小 crate 实现了常见分布;`rendology`、`bevy_render` 内部用 Hammersley 序列做 IBL 预计算。读 Bevy 的 `crates/bevy_pbr/src/light_probe/mod.rs` 能看到工业级半球采样代码。

## 5 · 对照与变奏

**同一问题在不同维度的变体**:

- 1D:[0,1] 区间上均匀撒点 → 等距网格 + 抖动
- 2D 方盘上:蓝噪声 / Sobol / Halton 都适用,公式不变
- 2D 球面(本集):螺旋是经典选择
- 2D 半球:把球面螺旋限制在 θ ∈ [0, π/2],其余不变
- 3D 球(体):球内均匀采样要 `r = cuberoot(random)`,因为体积 ∝ r³

**历史演化**:

- 1958:Bauer 提出球面螺旋
- 1992:Don Mitchell 写出更严格的"最佳分布"算法(Mitchell's best-candidate)
- 2006:Georgii Tam 等人提出实时蓝噪声生成
- 2016+:SIGGRAPH 论文把蓝噪声和 TAA 结合,成为现代引擎标配

**CPU vs GPU**:

CPU 上预计算 N=64 个点足够,丢进 shader 用 `uniform vec3 samples[64]`。GPU 上每帧算 N 个点不划算——分支多、内存访问不连续。**所以预计算几乎是工业铁律**。

Casey 在 Day 437 就是把今天的 `spiral_point` 改成预计算数组,从 CPU 传到 GPU。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么球面上 `θ` 等分(纬度等分)会导致两极点挤压?用面积公式解释。

**参考解答**:球面上 `[θ, θ+dθ]` 一圈"纬度带"的面积是 `dA = 2π sin(θ) dθ`(球面坐标面积元)。θ=0(北极)和 θ=π(南极)时 sin(θ)=0,面积趋于 0。如果 θ 等分,每个带子的 dθ 一样,但 sin(θ) 在两极小、在赤道大。所以"赤道附近的纬度带面积大,极点附近面积小",但点数一样 → 极点更密。

**正确做法**:`z = cos(θ)` 等分(等价于让 sin(θ) dθ 等价于 dz,面积均匀)。这就是为什么 Bauer 公式用 `t = (i+0.5)/N` 然后 `z = 1 - 2t`,绕过了 θ 等分。

### Lv2 · 动手实践

**题**:在 Rust 项目里实现 `spiral_point` 函数,生成 N=64 个点,把它们 dump 成 CSV(`x,y,z`),然后用 `gnuplot` 画一张俯视图(只看 x,y)。完成标准:看到一张均匀分布、无显眼团块/空洞的点图。

**参考解答**:

```rust
fn spiral_point(i: usize, n: usize) -> (f32, f32, f32) {
    let t = (i as f32 + 0.5) / n as f32;
    // 直接用 z = 1 - 2t,避免 acos(优化版)
    let z = 1.0 - 2.0 * t;
    let r = (1.0 - z * z).sqrt();   // 圈半径 = sin(θ) = sqrt(1-z²)
    let phi = std::f32::consts::PI * (1.0 + 5.0_f32.sqrt()) * i as f32;
    let (sin_p, cos_p) = phi.sin_cos();
    (r * cos_p, r * sin_p, z)
}

fn main() {
    let n = 64;
    println!("x,y,z");
    for i in 0..n {
        let (x, y, z) = spiral_point(i, n);
        println!("{},{},{}", x, y, z);
    }
}
```

每行解释:
- `z = 1.0 - 2.0 * t` 直接得到 z 坐标(北极 z=1,南极 z=-1,赤道 z=0),省掉一次 `acos`。
- `r = sqrt(1-z²)` 是该纬度圈的半径(等价于 `sin(θ)`)。
- `sin_p, cos_p = phi.sin_cos()` 用 `sin_cos` 而不是分别调 `sin` 和 `cos`——前者一次硬件指令算两个值,某些平台是 1.5 倍速。

### Rust 完整可跑示例

把 Lv2 扩展成完整 demo,包含三种分布对比:

```rust
use std::f32::consts::PI;

// 螺旋分布(本日主菜)
fn spiral_point(i: usize, n: usize) -> (f32, f32, f32) {
    let t = (i as f32 + 0.5) / n as f32;
    let z = 1.0 - 2.0 * t;
    let r = (1.0 - z * z).max(0.0).sqrt();
    let phi = PI * (1.0 + 5.0_f32.sqrt()) * i as f32;
    let (sp, cp) = phi.sin_cos();
    (r * cp, r * sp, z)
}

// 纯随机对照(白噪声)
fn random_point(rng: &mut u32) -> (f32, f32, f32) {
    // 简单 xorshift RNG,自包含、无依赖
    *rng ^= *rng << 13;
    *rng ^= *rng >> 17;
    *rng ^= *rng << 5;
    let u1 = (*rng as f32) / (u32::MAX as f32);
    *rng ^= *rng << 13; *rng ^= *rng >> 17; *rng ^= *rng << 5;
    let u2 = (*rng as f32) / (u32::MAX as f32);
    // 在球面上均匀采样:z 均匀,phi 均匀
    let z = 1.0 - 2.0 * u1;
    let r = (1.0 - z * z).max(0.0).sqrt();
    let phi = 2.0 * PI * u2;
    let (sp, cp) = phi.sin_cos();
    (r * cp, r * sp, z)
}

// 简单网格分布(θ,φ 网格,会两极挤压)
fn grid_point(i: usize, n_theta: usize, n_phi: usize) -> (f32, f32, f32) {
    let it = i / n_phi;
    let ip = i % n_phi;
    let theta = (it as f32 + 0.5) / n_theta as f32 * PI;
    let phi = (ip as f32 + 0.5) / n_phi as f32 * 2.0 * PI;
    let (st, ct) = theta.sin_cos();
    let (sp, cp) = phi.sin_cos();
    (st * cp, st * sp, ct)
}

fn main() {
    let n = 64;
    println!("label,x,y,z");
    for i in 0..n {
        let (x, y, z) = spiral_point(i, n);
        println!("spiral,{},{},{}", x, y, z);
    }
    let mut rng = 0xDEADBEEFu32;
    for _ in 0..n {
        let (x, y, z) = random_point(&mut rng);
        println!("random,{},{},{}", x, y, z);
    }
    // 8x8 网格
    for i in 0..64 {
        let (x, y, z) = grid_point(i, 8, 8);
        println!("grid,{},{},{}", x, y, z);
    }
}
```

**关键 Rust 特性**:
- `xorshift` RNG — 一种简单快速的伪随机算法,5 次位移异或就出一个新数,完全自包含。比 `thread_rng()` 简单。
- `.max(0.0).sqrt()` — 防御浮点误差导致 `1-z²` 变成 -1e-7,`sqrt(-x)` 会返回 NaN。
- 元组返回类型 `(f32, f32, f32)` 比 struct 更轻量,但牺牲了命名字段。Casey 在 HH 用 struct。
