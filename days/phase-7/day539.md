
# Day 539 · 为内存分配捕获源信息

> 内存泄漏是游戏开发最常见的 bug——某处分配了内存但没释放,几百帧后内存膨胀,游戏卡顿。Day 539 Casey 给每个内存分配打**源标签(source tag)**:记录"这次分配在哪一行代码发生"。出 bug 时,你能立刻看到"哪个文件、哪一行、哪个函数分配了这块没释放的内存"。这是工业级内存分析的基础。

## 0 · 为什么要有这一天

你跑游戏,内存从 100 MB 涨到 500 MB,显然泄漏。但泄漏在哪里?没有源信息,你只能猜。Casey 的方案:**每次 alloc 时记录调用位置**(文件、行号、函数名),存到分配元数据里。

C/C++ 用 `__FILE__` 和 `__LINE__` 宏自动捕获。Rust 用 `#[track_caller]` + `std::panic::Location`。Linux 工具 Valgrind、AddressSanitizer、Heap Profiler 自动做这件事(运行时插桩),但 Casey 想自己实现,完全控制。

#### 内存泄漏的三大类

让我把"内存泄漏"分类,看 Casey 这天解决的是哪类。

**Leak Type 1:忘记释放**——`malloc` 了但漏写 `free`。最常见,Valgrind 能检测。

**Leak Type 2:逻辑泄漏**——分配的对象存到集合里(`Vec`、`HashMap`),集合永远不清理。技术上有"引用",但实际不再使用。Valgrind 检测不到(因为有引用)。

**Leak Type 3:growth leak**——某些数据结构(如 cache)无限增长,每次都加新条目,不删旧的。看起来像"功能",实际是泄漏。

Casey 的源标签对三类都有效——你能看到"哪个文件、哪行 alloc 了未释放的内存",不管泄漏原因是什么。这是源标签的力量——**它告诉你"罪魁祸首"的位置,不告诉你"为什么"**。

工业级内存分析工具:

- **Valgrind / Memcheck**:运行时插桩,检测 leak type 1
- **AddressSanitizer (ASAN)**:GCC/Clang 编译期插桩,更快
- **Heaptrack / Massif**:valgrind 工具,记录分配时间序列
- **Tracy Memory Profiler**:实时 GPU/CPU/内存分析,游戏开发标配
- **Chrome Memory Profiler**:Web 应用

Rust 由于所有权系统,**leak type 1 几乎不可能**(Rust 自动 drop)。但 leak type 2、3 仍可能——`Rc` 循环引用、`Box::leak`、未清理的 cache。Casey 这天的工具对 Rust 同样有用。

#### `#[track_caller]` 的 Rust 用法

让我把 Rust 捕获调用位置的语法讲清楚,因为这是这一天的核心技术。

```rust
// 1. 标注函数
#[track_caller]
fn my_alloc(size: usize) -> *mut u8 {
    // 拿到调用位置
    let caller = std::panic::Location::caller();
    println!("alloc {} bytes at {}:{}", size, caller.file(), caller.line());
    // 实际分配
    unsafe { std::alloc::alloc(std::alloc::Layout::from_size_align(size, 1).unwrap()) }
}

fn main() {
    let p = my_alloc(1024);  // 输出:alloc 1024 bytes at src/main.rs:9
}
```

`#[track_caller]` 告诉编译器:**这个函数需要知道调用者位置**。Rust 编译器在调用点插入额外的"Location"参数,函数内部通过 `Location::caller()` 取出。

性能:`Location` 是编译期常量,函数调用时直接传 `&'static Location`,零运行时开销。

限制:**只有一层 caller 信息**。如果你想看完整调用栈(谁调用了 alloc 的调用者),需要 backtrace 库(`backtrace` crate),性能慢(几微秒一次)。

Casey 的方案选单层 caller——够用且零开销。工业级 profiler(tracy、heaptrack)用 backtrace 看完整栈,代价是慢。

完成这一天之后,你具备:

- 理解 memory profiler 的工作原理
- 能在 Rust 里用 `#[track_caller]` 捕获调用位置
- 知道 malloc/free 的元数据存储
- 能调试 Rust 项目的内存泄漏

## 2 · 心智模型

### 类比:快递包裹的发货单

每个快递包裹有发货单——发件人、发件时间、发件地址。如果包裹丢失或损坏,快递公司查发货单,知道谁寄的、何时寄的、从哪寄的。

内存分配同样:每次 alloc 是"寄一个包裹",源信息(file、line)是发货单。泄漏(包裹丢失)时,查发货单知道哪个函数分配的。

### 严谨展开:C 的 __FILE__ 和 __LINE__

C 预处理器提供 6 个标准宏:

- `__FILE__` —— 当前文件名(字符串字面量)
- `__LINE__` —— 当前行号(整数)
- `__func__` —— 当前函数名(C99)
- `__DATE__` —— 编译日期
- `__TIME__` —— 编译时间
- `__cplusplus` —— C++ 标志

`__FILE__` 和 `__LINE__` 在编译时由预处理器替换。用法:

```c
void* debug_malloc(size_t size, const char* file, int line) {
    printf("alloc %zu bytes at %s:%d\n", size, file, line);
    return malloc(size);
}

// 宏包装,自动传 __FILE__/__LINE__
#define MALLOC(sz) debug_malloc((sz), __FILE__, __LINE__)

// 调用方
void* p = MALLOC(1024);  // 等价于 debug_malloc(1024, "main.c", 42)
```

**关键技巧**:C 不能直接做"自动传调用位置",必须用**宏**包装。宏在调用点展开,展开时 `__FILE__` 和 `__LINE__` 取调用点的值。

Rust 的 `#[track_caller]` 是更优雅的解决方案——不需要宏,普通函数就能拿调用位置。这是 Rust 编译器的内建支持。

#### Rust 的 `Location::caller()` 详解

```rust
use std::panic::Location;

#[track_caller]
fn alloc(size: usize) -> *mut u8 {
    let loc = Location::caller();
    eprintln!("[alloc] {} bytes at {}:{} in {}", 
        size, loc.file(), loc.line(), loc.column());
    // ...
}

fn main() {
    alloc(100);  // [alloc] 100 bytes at src/main.rs:7:5
    alloc(200);  // [alloc] 200 bytes at src/main.rs:8:5
}
```

`Location` 类型字段:
- `file()`:文件路径(&'static str)
- `line()`:行号(u32)
- `column()`:列号(u32)

`Location` 是 `Copy` + `'static`,所以可以无开销传递、存储。

#### 跨多层调用:链式 track_caller

```rust
#[track_caller]
fn alloc(size: usize) -> *mut u8 { /* ... */ }

#[track_caller]
fn alloc_array<T>(n: usize) -> *mut T {
    let bytes = n * std::mem::size_of::<T>();
    alloc(bytes) as *mut T  // 此时 Location::caller() 是 alloc_array 的调用者
}

fn main() {
    let p: *mut i32 = alloc_array(100);
    // 期望:Location 是 main.rs:某行(调用 alloc_array 的位置)
    // 实际:Location 是 alloc_array 内部调用 alloc 的位置(因为 alloc_array 调了 alloc)
}
```

要让 caller 信息"穿透"多层,需要每层都加 `#[track_caller]`。Rust 自动处理这个传递——`alloc_array` 加了 `track_caller` 后,内部 `Location::caller()` 取的是 alloc_array 的调用者(不是 alloc_array 本身的位置)。

这是 Rust 优于 C 宏的另一个地方——链式 caller 信息自然支持。


    void* ptr = malloc(size + sizeof(AllocHeader));
    AllocHeader* h = (AllocHeader*)ptr;
    h->file = file;
    h->line = line;
    return (char*)ptr + sizeof(AllocHeader);
}

#define DEBUG_MALLOC(size) debug_malloc(size, __FILE__, __LINE__)
```

调用者写 `DEBUG_MALLOC(100)`,预处理器自动展开成 `debug_malloc(100, "main.c", 42)`。

### Rust 的 `#[track_caller]`

Rust 没有 `__FILE__`/`__LINE__`,但有 `#[track_caller]` 属性和 `std::panic::Location`:

```rust
use std::panic::Location;

#[track_caller]
fn alloc(size: usize) -> *mut u8 {
    let loc = Location::caller();
    println!("alloc {} bytes at {}:{}", size, loc.file(), loc.line());
    // 实际分配...
    std::ptr::null_mut()
}

fn main() {
    let _ = alloc(100);  // 自动捕获这里的位置
}
```

`#[track_caller]` 让函数能拿到调用者的位置——Rust 编译器内部维护调用链,这个属性告诉编译器"穿过我,看真正的调用者"。

### 内存分配元数据布局

每次 alloc 返回的指针前有个隐藏的 header:

```
内存布局:
[ AllocHeader ][ 用户数据 ...           ]
                ^
                用户拿到的指针

AllocHeader {
    file: *const str,   // 静态字符串地址
    line: u32,
    size: usize,
    magic: u32,         // 调试用魔数(0xDEADBEEF 等)
}
```

free 时,从用户指针往前减 header 大小,拿到 header,验证 magic(检查 double free),释放整块(包括 header)。

### 工业级工具

**Valgrind**(Linux):运行时内存检查,无需重新编译,慢 20-50 倍。检测泄漏、越界、double free。

```bash

Linux 内核的 `kmemleak` 检测内核内存泄漏,原理类似——给每个 alloc 加元数据,定期扫描。

`/proc/smaps` 显示进程每个 mapping 的内存使用:

```

### 3.4 · Rust 生态视角

Rust 默认用全局分配器(System allocator,通常 malloc),不带元数据。

`tracing-allocator` crate 包装全局分配器,记录每次 alloc:

```rust
use tracing_allocator::TracingAllocator;

#[global_allocator]
static GLOBAL: TracingAllocator<std::alloc::System> = TracingAllocator::new(std::alloc::System);
```

或者用 `stats_alloc` 统计 alloc/free 次数。

`#[track_caller]` 在自定义分配器里很有用:

```rust
use std::alloc::{GlobalAlloc, Layout};
use std::panic::Location;

struct TrackingAlloc;

unsafe impl GlobalAlloc for TrackingAlloc {
    #[track_caller]
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        let loc = Location::caller();
        log::info!("alloc {} bytes at {}:{}", layout.size(), loc.file(), loc.line());
        std::alloc::System.alloc(layout)
    }
    
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        std::alloc::System.dealloc(ptr, layout);
    }
}
```

### Lv2 · 动手实践

**题**:用 `#[track_caller]` 实现一个跟踪分配的 wrapper。每次 alloc 打印调用位置和大小。运行后:能看到每行代码的 alloc。

**参考解答**:

```rust
use std::panic::Location;
use std::sync::atomic::{AtomicUsize, Ordering};

struct AllocTracker {
    total_bytes: AtomicUsize,
    total_allocs: AtomicUsize,
}

impl AllocTracker {
    const fn new() -> Self {
        Self {
            total_bytes: AtomicUsize::new(0),
            total_allocs: AtomicUsize::new(0),
        }
    }
    
    #[track_caller]
    fn alloc(&self, size: usize) -> Vec<u8> {
        let loc = Location::caller();
        self.total_bytes.fetch_add(size, Ordering::Relaxed);
        self.total_allocs.fetch_add(1, Ordering::Relaxed);
        
        println!("[alloc] {} bytes at {}:{}",
            size, loc.file(), loc.line());
        
        vec![0; size]
    }
    
    fn stats(&self) -> (usize, usize) {
        (
            self.total_bytes.load(Ordering::Relaxed),
            self.total_allocs.load(Ordering::Relaxed),
        )
    }
}

static TRACKER: AllocTracker = AllocTracker::new();

fn load_level() {
    let _level_data = TRACKER.alloc(1024);  // 1024 bytes
}

fn load_player() {
    let _player_data = TRACKER.alloc(256);   // 256 bytes
    let _inventory = TRACKER.alloc(64);      // 64 bytes
}

fn main() {
    println!("=== 程序开始 ===");
    load_level();
    load_player();
    
    let (bytes, allocs) = TRACKER.stats();
    println!("\n=== 统计 ===");
    println!("总分配次数: {}", allocs);
    println!("总分配字节: {}", bytes);
}
```

```bash
cargo run
# === 程序开始 ===
# [alloc] 1024 bytes at src/main.rs:31
# [alloc] 256 bytes at src/main.rs:35
# [alloc] 64 bytes at src/main.rs:36
# 
# === 统计 ===
# 总分配次数: 3
# 总分配字节: 1344
```

为什么这么写:`AtomicUsize` 是线程安全的计数器,游戏里多线程访问全局 tracker 需要原子操作。`Location::caller()` 在 `#[track_caller]` 函数里返回**调用者**的位置,不是函数定义位置。`vec![0; size]` 是分配 + 初始化,Rust 的 Vec 自带大小信息,不泄漏。

### Lv3 · 迁移设计

**题**:扩展 tracker 支持 `dealloc`,记录"分配 → 释放"的对。在程序结束时,列出**未释放**的分配(泄漏检测)。提示:用 HashMap<usize, AllocInfo> 存活的分配,alloc 时 insert,dealloc 时 remove。结束时遍历 map 找泄漏。

**详细参考**:

```rust
use std::collections::HashMap;

struct LeakTracker {
    live: HashMap<usize, AllocInfo>,  // ptr_addr → info
    total_allocs: u64,
    total_deallocs: u64,
}

struct AllocInfo {
    size: usize,
    caller: &'static std::panic::Location<'static>,
}

impl LeakTracker {
    #[track_caller]
    fn alloc(&mut self, size: usize) -> usize {
        let addr = self.next_addr();
        let info = AllocInfo {
            size,
            caller: std::panic::Location::caller(),
        };
        self.live.insert(addr, info);
        self.total_allocs += 1;
        addr
    }
    
    fn dealloc(&mut self, addr: usize) {
        if self.live.remove(&addr).is_some() {
            self.total_deallocs += 1;
        } else {
            eprintln!("Warning: double free or untracked dealloc at {}", addr);
        }
    }
    
    fn report_leaks(&self) {
        let total_size: usize = self.live.values().map(|i| i.size).sum();
        eprintln!("=== Leak Report ===");
        eprintln!("Total allocs: {}", self.total_allocs);
        eprintln!("Total deallocs: {}", self.total_deallocs);
        eprintln!("Live allocations: {} (total {} bytes)", self.live.len(), total_size);
        
        // 按调用位置分组
        let mut by_caller: HashMap<&str, (u64, usize)> = HashMap::new();
        for info in self.live.values() {
            let key = format!("{}:{}", info.caller.file(), info.caller.line());
            let entry = by_caller.entry(key.leak()).or_default();
            entry.0 += 1;
            entry.1 += info.size;
        }
        
        // 排序输出
        let mut sorted: Vec<_> = by_caller.into_iter().collect();
        sorted.sort_by(|a, b| b.1.1.cmp(&a.1.1));
        for (caller, (count, size)) in sorted.iter().take(10) {
            eprintln!("  {}: {} allocs, {} bytes", caller, count, size);
        }
    }
}
```

这就是工业级 leak detector 的核心架构。Valgrind / LeakSanitizer 内部用类似设计(加上 binary instrumentation 自动插桩 alloc/dealloc)。

```rust
// 完整的内存分配追踪系统

use std::panic::Location;
use std::sync::atomic::{AtomicU64, AtomicUsize, Ordering};
use std::collections::HashMap;
use std::sync::Mutex;

#[derive(Debug, Clone)]
pub struct AllocInfo {
    pub size: usize,
    pub file: &'static str,
    pub line: u32,
    pub col: u32,
}

pub struct AllocTracker {
    pub total_bytes: AtomicU64,
    pub total_allocs: AtomicU64,
    pub total_deallocs: AtomicU64,
    pub live_allocs: Mutex<HashMap<u64, AllocInfo>>,  // key = id
    pub next_id: AtomicU64,
}

impl AllocTracker {
    pub const fn new() -> Self {
        Self {
            total_bytes: AtomicU64::new(0),
            total_allocs: AtomicU64::new(0),
            total_deallocs: AtomicU64::new(0),
            live_allocs: Mutex::new(HashMap::new()),
            next_id: AtomicU64::new(0),
        }
    }
    
    #[track_caller]
    pub fn tracked_alloc(&self, size: usize) -> u64 {
        let loc = Location::caller();
        let id = self.next_id.fetch_add(1, Ordering::Relaxed);
        
        self.total_bytes.fetch_add(size as u64, Ordering::Relaxed);
        self.total_allocs.fetch_add(1, Ordering::Relaxed);
        
        let info = AllocInfo {
            size,
            file: loc.file(),
            line: loc.line(),
            col: loc.column(),
        };
        
        self.live_allocs.lock().unwrap().insert(id, info);
        id
    }
    
    pub fn tracked_dealloc(&self, id: u64) {
        if let Some(info) = self.live_allocs.lock().unwrap().remove(&id) {
            self.total_bytes.fetch_sub(info.size as u64, Ordering::Relaxed);
            self.total_deallocs.fetch_add(1, Ordering::Relaxed);
        }
    }
    
    /// 找出 leak(还没 dealloc 的)
    pub fn find_leaks(&self) -> Vec<AllocInfo> {
        let live = self.live_allocs.lock().unwrap();
        live.values().cloned().collect()
    }
    
    /// 找 top N 大的活跃分配
    pub fn top_n_largest(&self, n: usize) -> Vec<AllocInfo> {
        let live = self.live_allocs.lock().unwrap();
        let mut sorted: Vec<_> = live.values().collect();
        sorted.sort_by(|a, b| b.size.cmp(&a.size));
        sorted.into_iter().take(n).cloned().collect()
    }
    
    pub fn summary(&self) -> String {
        let bytes = self.total_bytes.load(Ordering::Relaxed);
        let allocs = self.total_allocs.load(Ordering::Relaxed);
        let deallocs = self.total_deallocs.load(Ordering::Relaxed);
        let live_count = self.live_allocs.lock().unwrap().len();
        
        format!(
            "总分配: {} 次 / {} 字节\n总释放: {} 次\n活跃: {} 个",
            allocs, bytes, deallocs, live_count
        )
    }
}

static TRACKER: AllocTracker = AllocTracker::new();

// 便捷宏
macro_rules! tracked_alloc {
    ($size:expr) => {{
        let _id = TRACKER.tracked_alloc($size);
        // 实际项目:这里返回 Box<[u8]> 或类似
        (_id, vec![0u8; $size])
    }};
}

fn load_player() -> Vec<u64> {
    let mut ids = Vec::new();
    let (id1, _data) = tracked_alloc!(256);
    ids.push(id1);
    let (id2, _data) = tracked_alloc!(512);
    ids.push(id2);
    ids
}

fn load_level() -> u64 {
    let (id, _data) = tracked_alloc!(1024);
    id
}

fn main() {
    println!("=== 内存追踪 demo ===\n");
    
    // 模拟游戏加载
    let level_id = load_level();
    let player_ids = load_player();
    
    // 故意不释放一个 player 数据(模拟泄漏)
    println!("--- 释放 level ---");
    TRACKER.tracked_dealloc(level_id);
    
    println!("--- 释放 player 第一个 ---");
    TRACKER.tracked_dealloc(player_ids[0]);
    // player_ids[1] 故意不释放 = leak
    
    // 打印统计
    println!("\n=== 内存统计 ===");
    println!("{}", TRACKER.summary());
    
    // 找泄漏
    println!("\n=== 泄漏 ===");
    let leaks = TRACKER.find_leaks();
    if leaks.is_empty() {
        println!("(无)");
    } else {
        for leak in &leaks {
            println!("  LEAK: {} 字节 at {}:{}",
                leak.size, leak.file, leak.line);
        }
    }
    
    // Top 3 大分配
    println!("\n=== Top 3 大活跃分配 ===");
    for (i, alloc) in TRACKER.top_n_largest(3).iter().enumerate() {
        println!("  #{}: {} 字节 at {}:{}",
            i+1, alloc.size, alloc.file, alloc.line);
    }
}

出错怎么办:

- **`deadlock`**:Mutex 在多线程里嵌套 acquire。确保 alloc 内部不要再次 lock 同一个 mutex。
- **`Location::caller() 返回错位置`**:忘了 `#[track_caller]`。检查每个调用层级都加了。
- **`static Mutex` 初始化**:Rust 的 `const fn new` 必须确保所有字段 const-able。Mutex::new 在 1.63+ 是 const。
