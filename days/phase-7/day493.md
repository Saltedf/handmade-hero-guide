
# Day 493 · 清理编辑器 UI 布局

> Day 492 加完一堆交互后,editor 代码乱:Inspector 里塞着 palette,palette 里塞着 toolbar,布局硬编码到处都是。Day 493 是"收拾屋子"——抽出 layout 系统,把布局逻辑从业务代码里剥离。

## 0 · 为什么要有这一天

Day 492 的 editor 跑起来了,功能有:点击 / 多选 / 框选 / 拖拽 / 复制粘贴 / 旋转 / 对齐。代码量翻倍。

但打开代码一看,问题:

- Inspector 函数里**直接写死了 panel 宽度** `width = 200.0`,改一处要全文搜
- Palette 函数里**位置硬编码** `x = 10.0; y = 10.0`,移动到右边要改 5 处
- Toolbar 按钮**手算位置** `button_x = i * 30.0`,加个按钮要重算
- panel 之间的 gap(间距)是 magic number,各处不一样
- 字体大小各处独立,改一处不全局生效

这是技术债。Day 492 抢功能没收拾,Day 493 收拾。

为什么必须收拾?因为后面 Day 494 要加 "alignment point"编辑,Day 501 要加 "orphan" 导入,Day 514 要重构 image import。**如果布局是硬编码,每加一个 panel 就要改 5 处,很快陷入泥潭**。

收拾的目标:把"布局决策"从"业务代码"剥离。业务代码只声明"我要个 panel,200 宽,显示这些 widget",不关心 panel 在屏幕哪里。Layout 系统决定位置。

这种收拾叫 **layout refactor**(布局重构),或者更通用的 **decoupling layout from content**(布局与内容解耦)。Web 开发里 CSS 干的就是这个——HTML 声明内容,CSS 决定布局。

完成这一天,你能:

- 设计 immediate-mode UI 的 layout 系统(垂直 / 水平 / 网格)
- 把 magic number 提取成常量 / 配置
- 用 Rust 的 `const` / `static` / `config` struct 管理全局参数
- 评估"何时该重构"——技术债超过阈值就要还

## 1 · Casey 今天做了什么

Casey 第一步,列出所有 magic number:panel 宽度、字体大小、间距、颜色。整理成一张表,大约 30 项。

第二步,他建 `Theme` 结构:

```rust

    panel_height: f32,

    font_size: f32,
    color_bg: Color,
    color_fg: Color,
    color_accent: Color,

```

第三步,所有 magic number 替换成 `theme.xxx`。

第四步,他建 layout 抽象。每个 panel 用一个 `Layout` 描述:

```rust
enum Layout {
    Vertical { spacing: f32 },
    Horizontal { spacing: f32 },
    Grid { cols: usize, spacing: f32 },
}
```

UI 框架根据 Layout 自动算 widget 位置。

第五步,他把 Inspector 重写成:

```rust
fn render_inspector(ui: &mut Ui, state: &State) {
    ui.vertical(|ui| {
        ui.label("Inspector");
        ui.horizontal(|ui| {
            ui.label("Name:");
            ui.label(&state.selected_name);

        ui.slider("X", &mut state.x, -100.0, 100.0);
        ui.slider("Y", &mut state.y, -100.0, 100.0);
    });
}
```

不再有 magic number。所有布局由 `vertical` / `horizontal` + Theme 决定。

第六步,他定义 panel 锚点系统:`PanelAnchor::TopLeft`、`PanelAnchor::Right` 等。Layout 系统根据锚点算 panel 的屏幕位置。

第七步,他跑游戏,验证视觉效果和重构前一致(像素级)。

第八步,他加测试:每个 layout 给定输入,断言输出位置正确。

## 2 · 心智模型

### 类比:从手摆书架到宜家收纳

旧 editor 像你把书堆在地上——每本书自己占地方,你想加一本要挪全部。改"书架宽度"无意义,因为没有书架。

新 editor 像宜家收纳系统——有规则的格子(Kallax),每格固定大小,书按规则放。改"格子大小"是改一个参数,全部自动重新布局。

Layout 系统就是你的"宜家收纳规则"。

### Layout 系统的层次

工业级 UI 框架的 layout 通常分三层:

**第一层,widget**(小部件):button、label、slider。每个 widget 知道自己的"自然大小"(intrinsic size),但不知道在哪。

**第二层,box layout**(盒模型):垂直 / 水平排列。一组 widget 排成一列或一行,自动算位置。

**第三层,panel / window**(面板):多个 box layout 组成 panel,panel 锚定到屏幕位置。

CSS 的 Flexbox 是第二层。CSS Grid 是第二层的变种。CSS 的 position 是第三层。

Casey 的简化版三层都有,但都简化。

### Box layout 算法

垂直 layout 的核心算法:

```
current_y = origin_y
for widget in widgets:
    widget.pos = (origin_x, current_y)
    current_y += widget.height + spacing
```

水平 layout 同理,只是 x 和 y 互换。

Grid layout:

```
for i, widget in widgets.enumerate():
    col = i % cols
    row = i / cols
    widget.pos = (origin_x + col * (cell_w + spacing), origin_y + row * (cell_h + spacing))
```

这些算法 trivial,但**封装在框架里**后业务代码极简洁。

### Intrinsic size

每个 widget 有"自然大小"——button 自然是 `(文字宽度 + padding, 文字高度 + padding)`。Layout 系统**先测量**所有 widget 的自然大小,再决定位置。

```rust
trait Widget {
    fn measure(&self, ctx: &Context) -> Vec2;    // 自然大小
    fn render(&self, ctx: &mut Context, pos: Vec2);
}
```

复杂 layout 还要处理**最大子元素**:水平 layout 的总高度 = max(各 widget 高度)。垂直 layout 的总宽度同理。

### Theme 集中管理

所有视觉参数集中在一个 Theme 结构:

```rust
struct Theme {
    // 间距
    panel_padding: f32,        // panel 内边距
    panel_gap: f32,            // panel 之间间距
    widget_gap: f32,           // widget 之间间距
    
    // 尺寸
    panel_width: f32,
    panel_header_height: f32,
    button_height: f32,
    slider_height: f32,
    font_size: f32,
    
    // 颜色
    color_panel_bg: Color,
    color_panel_header: Color,
    color_text: Color,
    color_button: Color,
    color_button_hover: Color,
    color_accent: Color,
    color_selection: Color,
}
```

业务代码用 `theme.panel_width`,不写 `200.0`。换主题(深色 / 浅色)只改 Theme,不改业务。

### Panel 锚点系统

```rust
enum PanelAnchor {
    TopLeft,
    Top,
    TopRight,
    Right,
    BottomRight,
    Bottom,
    BottomLeft,
    Left,
    Center,
    Floating(Vec2),
}
```

给定屏幕尺寸 + panel 尺寸 + anchor,算 panel 原点:

```rust
fn anchor_to_pos(anchor: PanelAnchor, screen: Vec2, panel_size: Vec2, margin: f32) -> Vec2 {
    match anchor {
        PanelAnchor::TopLeft => Vec2::new(margin, margin),
        PanelAnchor::TopRight => Vec2::new(screen.x - panel_size.x - margin, margin),
        PanelAnchor::BottomLeft => Vec2::new(margin, screen.y - panel_size.y - margin),
        PanelAnchor::BottomRight => Vec2::new(screen.x - panel_size.x - margin, screen.y - panel_size.y - margin),
        PanelAnchor::Center => Vec2::new(
            (screen.x - panel_size.x) / 2.0,
            (screen.y - panel_size.y) / 2.0,
        ),
        PanelAnchor::Floating(p) => p,
        // ...
    }
}
```

### Scissor / Clipping

Panel 内容超出边界时要 clip(裁剪)。OpenGL 用 `glScissor`,Casey 的软件渲染器用每像素 if 判断。

```rust
fn draw_in_panel(ui: &mut Ui, panel_rect: Rect, draw_fn: impl FnOnce(&mut Ui)) {
    ui.push_clip(panel_rect);
    draw_fn(ui);
    ui.pop_clip();
}
```

Clip 栈:每个 panel push 一个 clip,渲染时所有像素位置必须通过 clip。nested panel 自动叠加 clip。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

商业游戏引擎的 UI layout 系统复杂得多。

**Unity UI Toolkit**(原 UI Elements):用 CSS-like 样式,UXML(类 XML)+ USS(类 CSS)。Layout 引擎是 Yoga(Flexbox 实现)。

**Unreal UMG**:用 Slate 控件树,有 HorizontalBox、VerticalBox、GridPanel、Canvas Panel。

**Godot Control**:节点树,有 HBoxContainer、VBoxContainer、GridContainer。Margin / Separation 参数。

这些引擎都支持:

- **Anchors**(锚点):9 个位置 + 自定义
- **Margins**(外边距)
- **Paddings**(内边距)
- **Flex / Grid**(弹性 / 网格布局)
- **Layout groups**(布局组)

Casey 的简化版理解后,看 Unity / Godot 文档秒懂——只是 API 不同,概念一样。

游戏 UI layout 的"高级"特性:

- **Responsive layout**:窗口大小变,布局自适应(手机 / 平板 / 桌面)
- **RTL / LTR**:阿拉伯语从右到左布局
- **Localization-aware**:不同语言文字长度不同,布局自动调整
- **Animation**:layout 切换有过渡动画

### 3.2 · 🎨 图形学视角

Layout 在图形学里叫 **"2D spatial arrangement"**。

文字渲染的 layout 特别复杂——叫 **text shaping**。不同字体下文字宽度不同,需要 HarfBuzz / freetype 测量。

Layout 的渲染流程:

1. **Measure pass**:自底向上算每个 widget 自然大小
2. **Arrange pass**:自顶向下分配位置
3. **Render pass**:按位置渲染

类似浏览器渲染 HTML 的 reflow + paint。Layout 是 reflow,paint 是 render。

性能优化:**dirty rect**(脏矩形)。只重绘变化的区域,不全屏重绘。ImGui / egui 没这个,每帧全屏渲染,但简单。

### 3.3 · 🐧 Linux 系统编程视角

Linux 桌面的窗口管理就是巨型 layout 系统。

**Wayland compositor** 把所有 client surface 按 layout 摆到屏幕。Mutter / KWin / Sway 各有 layout 算法。

**Tiling window manager**(i3 / Sway / Hyprland):窗口自动平铺,layout 算法决定每个窗口大小位置。

```bash
# Sway 配置:类似 layout 系统
cat ~/.config/sway/config
# layout default
# layout stacking
# layout tabbed
```

Sway 的 layout 命令对应 Casey 的 Layout 枚举:

- `layout default` = horizontal/vertical 自动
- `layout stacking` = 单个可见,其他堆叠
- `layout tabbed` = 单个可见,其他 tab

**GTK / Qt 的 layout**:GtkBox、QHBoxLayout、QVBoxLayout——和 Casey 完全同构。Qt 文档专门一节讲 layout,代码示例几乎能逐行翻译到 Rust。

理解 layout 系统的抽象,你能秒懂 i3 配置 / Qt 代码 / GTK 代码,因为本质都一样。

### 3.4 · 🦀 Rust 生态视角

Rust UI 库的 layout 实现。

**egui**:内部 `egui::Ui` 有 `vertical` / `horizontal` 方法。Layout 用 `egui::Layout` struct,有主方向、对齐方式、间距。

```rust
egui::Ui::vertical(|ui| {
    ui.label("hello");
    ui.button("click");
});
```

**iced**:`iced::Element` + `Column` / `Row`。比 egui 更"声明式"。

```rust
Column::new()
    .push(text("hello"))
    .push(button("click"))
```

**taffy**:Rust 实现的 Flexbox / Grid layout 引擎,bevy_ui 用它。和 Yoga 同类。

Rust 表达 Theme 的几种方式:

```rust
// 方式 1:const(编译期常量)
const PANEL_WIDTH: f32 = 200.0;

// 方式 2:static(全局可变,需 Sync)
static THEME: Lazy<Theme> = Lazy::new(|| Theme { ... });

// 方式 3:配置 struct(推荐)
struct Theme { ... }
let theme = Theme { panel_width: 200.0, ... };

// 方式 4:serde 加载(运行时配置)
let theme: Theme = serde_json::from_str(&fs::read_to_string("theme.json")?)?;
```

Casey 用方式 3,因为简洁且 type-safe。

Borrow checker 的考验:Theme 要传到所有 widget 函数,要么 `&Theme` 参数,要么 `&self.theme` 字段。Rust 推荐前者(无状态),egui 用后者(stateful Context)。

```rust
// 方式 A:&Theme 参数
fn label(ui: &mut Ui, theme: &Theme, text: &str) { ... }

// 方式 B:Ui 内嵌 theme
struct Ui { theme: Theme, ... }
impl Ui {
    fn label(&mut self, text: &str) { ... use self.theme.panel_width ... }
}
```

方式 B 更简洁,egui 这么做。

## 5 · 对照与变奏

Layout 系统在不同领域的对照。

**Web 浏览器**:CSS Flexbox 是 Casey 的 Horizontal/Vertical,Grid 是 Casey 的 Grid。`position: absolute` 是 Floating。`position: fixed` 是 panel anchor。

**Qt / GTK**:`QHBoxLayout` / `GtkBox` 完全同构。

**Flutter**:`Row` / `Column` widget,语法和 egui 几乎一样。

**React Native**:同 Flutter,`flexDirection: 'row' | 'column'`。

**SwiftUI**:HStack / VStack。

**Android XML**:LinearLayout / RelativeLayout / ConstraintLayout。

历史演化:

- **1990s**:绝对定位(手摆坐标),Win32 / Motif
- **2000s**:Box model(Qt / GTK),Java Swing
- **2010s**:Flexbox(CSS / Yoga),声明式
- **2020s**:Constraint-based(Compose / SwiftUI),更声明式

每代都是"更高抽象",代码更短,但底层都是 measure + arrange。

跨领域对照:

- **电路板 layout**:PCB 设计,元件摆放。Altium / KiCad 都有"对齐"工具,和 editor 的 align 同构。
- **文档排版**(LaTeX):段落 / 行 / 字符的三层 layout。
- **音乐谱排版**:音符按时间 / 音高 layout,类似 grid。

理解 layout 抽象,任何"按规则摆放元素"的问题都能秒解。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 Theme 要做成 struct,而不是用 `const`?

**参考解答**:`const` 适合**编译期固定**的值。Theme 经常需要**运行时可变**——切换深色 / 浅色主题、不同分辨率缩放、用户自定义颜色。struct 作为参数传递灵活。

但 Theme 内部**个别字段**可以用 const 表达默认值:

```rust
const DEFAULT_PANEL_WIDTH: f32 = 200.0;

struct Theme {
    panel_width: f32,
}

impl Default for Theme {
    fn default() -> Self {
        Self { panel_width: DEFAULT_PANEL_WIDTH }
    }
}
```

这样兼顾灵活性(可改)和明确性(默认值有名字)。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:把"乱版"editor 布局(全 magic number)重构为"clean 版"(Theme + Layout)。先写乱版,再写 clean 版,确认输出像素位置一致。

完成标准:两个版本的 `widget_positions()` 输出完全相同。

**参考解答**:

```rust
// ============== 乱版(magic number)==============
fn messy_layout() -> Vec<(String, (f32, f32))> {
    let mut positions = Vec::new();
    
    // Inspector:固定在 (10, 10),宽 200,内部 widget 间距 20
    positions.push(("Inspector_header".into(), (10.0, 10.0)));
    positions.push(("Inspector_name_label".into(), (20.0, 40.0)));
    positions.push(("Inspector_name_value".into(), (80.0, 40.0)));
    positions.push(("Inspector_x_slider".into(), (20.0, 60.0)));
    positions.push(("Inspector_y_slider".into(), (20.0, 80.0)));
    
    // Palette:固定在 (10, 400),宽 200
    positions.push(("Palette_header".into(), (10.0, 400.0)));
    positions.push(("Palette_btn_0".into(), (20.0, 430.0)));
    positions.push(("Palette_btn_1".into(), (20.0, 460.0)));
    positions.push(("Palette_btn_2".into(), (20.0, 490.0)));
    
    positions
}

// ============== Clean 版(Theme + Layout)==============
#[derive(Copy, Clone)]
struct Theme {
    panel_padding: f32,
    widget_gap: f32,
    panel_gap: f32,
    panel_width: f32,
    header_height: f32,
}

impl Default for Theme {
    fn default() -> Self {
        Self {
            panel_padding: 10.0,
            widget_gap: 20.0,
            panel_gap: 90.0,    // (10..400) 中间约 90
            panel_width: 200.0,
            header_height: 30.0,
        }
    }
}

#[derive(Copy, Clone)]
enum Layout {
    Vertical,
}

struct Panel {
    name: String,
    anchor: (f32, f32),
    layout: Layout,
    widgets: Vec<String>,
}

fn clean_layout(theme: Theme) -> Vec<(String, (f32, f32))> {
    let mut positions = Vec::new();
    
    let panels = vec![
        Panel {
            name: "Inspector".into(),
            anchor: (10.0, 10.0),
            layout: Layout::Vertical,
            widgets: vec![
                "header".into(), "name_label".into(), "name_value".into(),
                "x_slider".into(), "y_slider".into(),
            ],
        },
        Panel {
            name: "Palette".into(),
            anchor: (10.0, 400.0),
            layout: Layout::Vertical,
            widgets: vec![
                "header".into(), "btn_0".into(), "btn_1".into(), "btn_2".into(),
            ],
        },
    ];
    
    for panel in panels {
        let (mut x, mut y) = panel.anchor;
        
        for (i, widget) in panel.widgets.iter().enumerate() {
            let widget_x = if i == 0 { x } else { x + theme.panel_padding };
            let widget_y = if i == 0 {
                y
            } else {
                // 第 i 个 widget = header_height + (i-1)*gap + padding
                y + theme.header_height + (i as f32 - 1.0) * theme.widget_gap
            };
            
            let display_x = if widget == "name_value" { widget_x + 60.0 } else { widget_x };
            
            let full_name = format!("{}_{}", panel.name, widget);
            positions.push((full_name, (display_x, widget_y)));
        }
    }
    
    positions
}

fn main() {
    println!("=== 乱版 ===");
    let messy = messy_layout();
    for (name, pos) in &messy {
        println!("  {} at {:?}", name, pos);
    }
    
    println!("\n=== Clean 版 ===");
    let theme = Theme::default();
    let clean = clean_layout(theme);
    for (name, pos) in &clean {
        println!("  {} at {:?}", name, pos);
    }
    
    // 验证:位置应一致
    println!("\n=== 验证一致 ===");
    for (m, c) in messy.iter().zip(clean.iter()) {
        let same = m.1 == c.1;
        let status = if same { "OK" } else { "MISMATCH" };
        println!("  {} vs {}: {} ({:?} vs {:?})",
                 m.0, c.0, status, m.1, c.1);
    }
}
```

为什么这么写:`Panel` struct 把"布局决策"(anchor, layout)和"内容"(widgets)分离。Theme 把视觉参数集中。验证一致确保重构没改行为。

#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    const fn new(x: f32, y: f32) -> Self { Self { x, y } }
}

impl std::ops::Add for Vec2 {
    type Output = Vec2;
    fn add(self, other: Vec2) -> Vec2 { Vec2::new(self.x + other.x, self.y + other.y) }
}

#[derive(Copy, Clone, Debug)]
struct Rect { pos: Vec2, size: Vec2 }

impl Rect {
    fn new(x: f32, y: f32, w: f32, h: f32) -> Self {
        Self { pos: Vec2::new(x, y), size: Vec2::new(w, h) }
    }
}

#[derive(Copy, Clone, Debug)]
struct Color { r: f32, g: f32, b: f32, a: f32 }

impl Color {
    const fn rgb(r: f32, g: f32, b: f32) -> Self { Self { r, g, b, a: 1.0 } }
}

// ============================================================
// Layout: 布局抽象
// ============================================================

#[derive(Copy, Clone)]
enum LayoutDirection {
    Vertical,
    Horizontal,
}

struct LayoutContext {
    cursor: Vec2,
    direction: LayoutDirection,
    max_extent: Vec2,    // 子元素占用的最大尺寸
    theme: Theme,
    clip_stack: Vec<Rect>,
}

impl LayoutContext {
    fn new(theme: Theme) -> Self {
        Self {
            cursor: Vec2::new(0.0, 0.0),
            direction: LayoutDirection::Vertical,
            max_extent: Vec2::new(0.0, 0.0),
            theme,
            clip_stack: Vec::new(),
        }
    }
    
    fn advance(&mut self, size: Vec2) {
        match self.direction {
            LayoutDirection::Vertical => {
                self.cursor.y += size.y + self.theme.widget_gap;
                self.max_extent.x = self.max_extent.x.max(size.x);
                self.max_extent.y += size.y + self.theme.widget_gap;
            }
            LayoutDirection::Horizontal => {
                self.cursor.x += size.x + self.theme.widget_gap;
                self.max_extent.y = self.max_extent.y.max(size.y);
                self.max_extent.x += size.x + self.theme.widget_gap;
            }
        }
    }
    
    fn push_clip(&mut self, rect: Rect) {
        self.clip_stack.push(rect);
    }
    
    fn pop_clip(&mut self) {
        self.clip_stack.pop();
    }
}

// ============================================================
// Panel: 面板,带 anchor
// ============================================================

#[derive(Copy, Clone)]
enum PanelAnchor {
    TopLeft,
    TopRight,
    BottomLeft,
    BottomRight,
    Floating(Vec2),
}

fn anchor_to_pos(anchor: PanelAnchor, screen: Vec2, panel_size: Vec2, margin: f32) -> Vec2 {
    match anchor {
        PanelAnchor::TopLeft => Vec2::new(margin, margin),
        PanelAnchor::TopRight => Vec2::new(screen.x - panel_size.x - margin, margin),
        PanelAnchor::BottomLeft => Vec2::new(margin, screen.y - panel_size.y - margin),
        PanelAnchor::BottomRight => Vec2::new(
            screen.x - panel_size.x - margin,
            screen.y - panel_size.y - margin,
        ),
        PanelAnchor::Floating(p) => p,
    }
}

struct Panel {
    name: &'static str,
    anchor: PanelAnchor,
    render: fn(&mut LayoutContext, &GameState),
}

// ============================================================
// Game state(假数据)
// ============================================================

struct GameState {
    fps: f32,
    entity_count: u32,
    selected_name: Option<&'static str>,
    selected_pos: [f32; 3],
    log_messages: Vec<&'static str>,
}

// ============================================================
// Editor UI(用 Theme + Layout 重构后)
// ============================================================

struct EditorUI {
    panels: Vec<Panel>,
}

impl EditorUI {
    fn new() -> Self {
        Self {
            panels: vec![
                Panel {
                    name: "Performance",
                    anchor: PanelAnchor::TopRight,
                    render: render_performance,
                },
                Panel {
                    name: "Inspector",
                    anchor: PanelAnchor::TopLeft,
                    render: render_inspector,
                },
                Panel {
                    name: "Console",
                    anchor: PanelAnchor::BottomLeft,
                    render: render_console,
                },
            ],
        }
    }
    
    fn render(&self, state: &GameState, screen: Vec2, theme: &Theme) -> Vec<RenderItem> {
        let mut items = Vec::new();
        
        for panel in &self.panels {
            // 第一遍:测量 panel 自然大小
            let mut measure_ctx = LayoutContext::new(theme.clone());
            measure_ctx.cursor = Vec2::new(theme.panel_padding, theme.header_height);
            (panel.render)(&mut measure_ctx, state);
            let panel_size = Vec2::new(
                theme.panel_width,
                measure_ctx.max_extent.y + theme.header_height + theme.panel_padding,
            );
            
            // 算位置
            let pos = anchor_to_pos(panel.anchor, screen, panel_size, theme.screen_margin);
            let rect = Rect::new(pos.x, pos.y, panel_size.x, panel_size.y);
            
            // Panel 背景
            items.push(RenderItem::Rect {
                rect, color: theme.color_panel_bg, label: format!("{}_bg", panel.name),
            });
            
            // Panel header
            items.push(RenderItem::Rect {
                rect: Rect::new(pos.x, pos.y, panel_size.x, theme.header_height),
                color: theme.color_panel_header,
                label: format!("{}_header_bg", panel.name),
            });
            
            items.push(RenderItem::Text {
                pos: Vec2::new(pos.x + theme.panel_padding, pos.y + 8.0),
                text: panel.name.to_string(),
                color: theme.color_text,
                size: theme.font_size,
                label: format!("{}_header", panel.name),
            });
            
            // 第二遍:实际渲染 widget
            let mut ctx = LayoutContext::new(theme.clone());
            ctx.cursor = pos + Vec2::new(theme.panel_padding, theme.header_height);
            ctx.push_clip(rect);
            (panel.render)(&mut ctx, state);
            ctx.pop_clip();
            
            // 把 ctx 内部 widget 转成 RenderItem
            // (简化:我们直接在这里复现)
            let _ = ctx;  // 实际项目这里读取 ctx.widgets
        }
        
        items
    }
}

// ============================================================
// Render item
// ============================================================

#[derive(Debug)]
enum RenderItem {
    Rect { rect: Rect, color: Color, label: String },
    Text { pos: Vec2, text: String, color: Color, size: f32, label: String },
}

impl fmt::Display for RenderItem {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            RenderItem::Rect { rect, color, label } => {
                write!(f, "Rect[{}] at ({:.0},{:.0}) {}x{} color ({:.1},{:.1},{:.1})",
                       label, rect.pos.x, rect.pos.y, rect.size.x, rect.size.y,
                       color.r, color.g, color.b)
            }
            RenderItem::Text { pos, text, color, size, label } => {
                write!(f, "Text[{}] '{}' at ({:.0},{:.0}) size {:.0} color ({:.1},{:.1},{:.1})",
                       label, text, pos.x, pos.y, size, color.r, color.g, color.b)
            }
        }
    }
}

// ============================================================
// Panel render 函数(无 magic number,纯 Theme + Layout)
// ============================================================

fn render_performance(ctx: &mut LayoutContext, state: &GameState) {
    label(ctx, &format!("FPS: {:.1}", state.fps));
    label(ctx, &format!("Frame: {:.2}ms", 1000.0 / state.fps.max(1.0)));
    label(ctx, &format!("Entities: {}", state.entity_count));
}

fn render_inspector(ctx: &mut LayoutContext, state: &GameState) {
    match state.selected_name {
        Some(name) => {
            label(ctx, &format!("Name: {}", name));
            slider(ctx, "X", state.selected_pos[0]);
            slider(ctx, "Y", state.selected_pos[1]);
            slider(ctx, "Z", state.selected_pos[2]);
        }
        None => {
            label(ctx, "(no selection)");
        }
    }
}

fn render_console(ctx: &mut LayoutContext, state: &GameState) {
    label(ctx, "Logs:");
    for msg in state.log_messages.iter().rev().take(3) {
        label(ctx, msg);
    }
}

// Widget helper(自动用 Theme 算大小,自动 advance)
fn label(ctx: &mut LayoutContext, text: &str) {
    let pos = ctx.cursor;
    let size = Vec2::new(
        text.len() as f32 * ctx.theme.font_size * 0.6,
        ctx.theme.font_size,
    );
    println!("  [layout] label '{}' at ({:.0},{:.0})", text, pos.x, pos.y);
    ctx.advance(size);
}

fn slider(ctx: &mut LayoutContext, name: &str, _value: f32) {
    let pos = ctx.cursor;
    let size = Vec2::new(
        ctx.theme.panel_width - 2.0 * ctx.theme.panel_padding,
        ctx.theme.slider_height,
    );
    println!("  [layout] slider '{}' at ({:.0},{:.0})", name, pos.x, pos.y);
    ctx.advance(size);
}

fn main() {
    println!("=============================================");
    println!(" Day 493 · 清理编辑器 UI 布局");
    println!("=============================================\n");
    
    let state = GameState {
        fps: 60.0,
        entity_count: 42,
        selected_name: Some("hero"),
        selected_pos: [10.0, 20.0, 0.0],
        log_messages: vec!["[INFO] Game started", "[WARN] Slow frame", "[ERROR] Asset not found"],
    };
    
    let screen = Vec2::new(1280.0, 720.0);
    
    println!("=== Dark theme ===\n");
    let dark = Theme::dark();
    let editor = EditorUI::new();
    let items = editor.render(&state, screen, &dark);
    println!("\nRender items:");
    for item in &items {
        println!("  {}", item);
    }
    
    println!("\n=== Light theme ===\n");
    let light = Theme::light();
    let items = editor.render(&state, screen, &light);
    println!("\nRender items:");
    for item in &items {
        println!("  {}", item);
    }
    
    println!("\n=== LayoutContext 测量示例 ===\n");
    let mut ctx = LayoutContext::new(Theme::default());
    ctx.cursor = Vec2::new(10.0, 40.0);
    println!("Start cursor: ({}, {})", ctx.cursor.x, ctx.cursor.y);
    label(&mut ctx, "hello");
    println!("After 'hello': cursor ({}, {}), max_extent ({}, {})",
             ctx.cursor.x, ctx.cursor.y, ctx.max_extent.x, ctx.max_extent.y);
    label(&mut ctx, "world");
    println!("After 'world': cursor ({}, {}), max_extent ({}, {})",
             ctx.cursor.x, ctx.cursor.y, ctx.max_extent.x, ctx.max_extent.y);
}

#[cfg(test)]
mod tests {
    use super::*;
    
    #[test]
    fn test_anchor_top_left() {
        let pos = anchor_to_pos(PanelAnchor::TopLeft, Vec2::new(1920.0, 1080.0), Vec2::new(200.0, 100.0), 10.0);
        assert_eq!(pos.x, 10.0);
        assert_eq!(pos.y, 10.0);
    }
    
    #[test]
    fn test_anchor_top_right() {
        let pos = anchor_to_pos(PanelAnchor::TopRight, Vec2::new(1920.0, 1080.0), Vec2::new(200.0, 100.0), 10.0);
        assert_eq!(pos.x, 1710.0);  // 1920 - 200 - 10
        assert_eq!(pos.y, 10.0);
    }
    
    #[test]
    fn test_anchor_bottom_right() {
        let pos = anchor_to_pos(PanelAnchor::BottomRight, Vec2::new(1920.0, 1080.0), Vec2::new(200.0, 100.0), 10.0);
        assert_eq!(pos.x, 1710.0);
        assert_eq!(pos.y, 970.0);  // 1080 - 100 - 10
    }
    
    #[test]
    fn test_layout_vertical_advance() {
        let theme = Theme::default();
        let mut ctx = LayoutContext::new(theme.clone());
        ctx.cursor = Vec2::new(10.0, 10.0);
        
        // 放一个 100x20 widget
        ctx.advance(Vec2::new(100.0, 20.0));
        
        // Y 应该前进 20 + widget_gap
        assert_eq!(ctx.cursor.y, 10.0 + 20.0 + theme.widget_gap);
        // X 不变(垂直)
        assert_eq!(ctx.cursor.x, 10.0);
    }
    
    #[test]
    fn test_layout_horizontal_advance() {
        let theme = Theme::default();
        let mut ctx = LayoutContext::new(theme.clone());
        ctx.direction = LayoutDirection::Horizontal;
        ctx.cursor = Vec2::new(10.0, 10.0);
        
        ctx.advance(Vec2::new(50.0, 20.0));
        
        // X 应该前进 50 + gap
        assert_eq!(ctx.cursor.x, 10.0 + 50.0 + theme.widget_gap);
        // Y 不变(水平)
        assert_eq!(ctx.cursor.y, 10.0);
    }
    
    #[test]
    fn test_theme_dark_light_diff() {
        let dark = Theme::dark();
        let light = Theme::light();
        
        // 不应相同
        assert_ne!(dark.color_panel_bg.r, light.color_panel_bg.r);
    }
    
    #[test]
    fn test_clip_stack_push_pop() {
        let theme = Theme::default();
        let mut ctx = LayoutContext::new(theme);
        
        assert!(ctx.clip_stack.is_empty());
        ctx.push_clip(Rect::new(0.0, 0.0, 100.0, 100.0));
        assert_eq!(ctx.clip_stack.len(), 1);
        ctx.push_clip(Rect::new(10.0, 10.0, 50.0, 50.0));
        assert_eq!(ctx.clip_stack.len(), 2);
        ctx.pop_clip();
        assert_eq!(ctx.clip_stack.len(), 1);
        ctx.pop_clip();
        assert!(ctx.clip_stack.is_empty());
    }
}
