
# Day 448 · 显式放置房间连接

> Day 447 让房间共享墙,但墙完整无缺——你从一个房间看不到另一个。今天 Casey 在共享墙上"凿门":把墙的一段标记为"开口",玩家可以走过去。

## 0 · 为什么要有这一天

迷宫不只是"房间贴房间",还要**可通行**。如果共享墙完全封闭,房间就是孤立的——只是物理相邻但游戏上不连通。

凿门就是在墙上画一个矩形:"这块区域不存在,玩家可以穿过"。在游戏里这有几种实现方式:

第一,**孔洞 geometry**:在墙的 mesh 上挖一个洞,玩家物理穿过。视觉真实但几何复杂。
第二,**碰撞 exception**:墙的碰撞盒在门口处断开。简化但视觉仍要画门。
第三,**trigger zone**:门口放一个 trigger,玩家踩到自动传送。最简化但破坏沉浸。

Casey HH 用第二种——墙的碰撞在门口断开。视觉上墙有"门洞"纹理,逻辑上玩家可以穿过。

让我把"碰撞 mesh 与渲染 mesh 分离"这个工业游戏架构原则讲清楚——这是 Day 448 选择"碰撞 exception"方案的根本原因。

**渲染 mesh** vs **碰撞 mesh**。两者是分开的:

- **渲染 mesh**:GPU 画的三角形,通常高细节(玩家看见的几何)
- **碰撞 mesh**:物理引擎用的简化几何(玩家撞到的几何)

为什么要分开?因为优化目标不同:

- 渲染要**美观**:高多边形数、复杂 shader、精细纹理
- 碰撞要**快**:低多边形、凸包、简单形状(AABB、球、胶囊)

举例:一个雕像渲染 mesh 有 5000 个三角形(细节丰富),但碰撞 mesh 只是 1 个 AABB(简化为盒子)。玩家撞雕像 = 撞盒子。性能飞跃。

**门的实现选择**。在分离架构下,门有三种做法:

**做法 A:渲染 mesh 挖洞**。墙体 mesh 在门口处真的有"洞"(geometry 缺失)。视觉效果最好(光透过门),但 mesh 复杂(需要 CSG boolean 运算)。Unreal/Unity 的 BSP 工具能做。

**做法 B:渲染贴一张"门洞"纹理,碰撞断开**。渲染 mesh 仍然是完整矩形墙,但纹理在门口处是"黑色洞"(假装)。碰撞 mesh 是 4 个矩形(门左、门右、门上、地下),门那个矩形不存在。玩家视觉看见"洞",物理穿过空隙。

**做法 C:trigger zone**。渲染和碰撞都完整,门口放一个 trigger 区域。玩家踩 trigger,代码"传送"他到隔壁房间。最简化但破坏沉浸感(玩家看见墙,但能"穿过")。

Casey HH 是手工渲染(不是 Unreal 那种),没有 CSG 工具。所以他选**做法 B**——简单、有效、玩家感受到"门"。

**门的几何**。具体说,一面墙是矩形 WxH(宽 W,高 H)。门是墙内的矩形 Dw x Dh,位置。剩余"墙体"分 4 块:

```
┌───────────────────────────┐
│         顶部墙              │  高 = H - Dh - Py
├──────┬────────────┬───────┤
│ 左墙  │     门      │  右墙  │  高 = Dh
│      │            │       │
├──────┴────────────┴───────┤
│         底部墙              │  高 = Py
└───────────────────────────┘
        宽 = Px | Dw | W-Px-Dw
```

通常 `Py = 0`(门到底,方便行走),`Px = (W - Dw) / 2`(门居中)。这 4 块墙体各自有碰撞,门那个矩形没碰撞。玩家走到门就过去了。

**Day 448 的核心**:Casey 实现"门数据结构 + 墙体分割逻辑"。这是从"几何存储"到"语义存储"的过渡——开始记录"什么是墙、什么是门",而不是"一堆三角形"。

## 2 · 心智模型

### 类比:在墙上开窗

装修时砸墙开窗,木匠用粉笔在墙上画一个矩形,然后沿粉笔线切。开口的尺寸(宽、高)由你决定,位置由你决定(居中、靠左、靠右)。

凿门同理:在共享墙上画矩形(门),那个矩形不存在。剩下的墙体是几块"碎片",各自有碰撞。

### 门的位置计算:精确数学

让我把"门在共享墙上的位置"算清楚。这是 Day 448 的几何核心。

**问题陈述**:房间 A 和房间 B 共享一面墙。这面墙是矩形 `(W, H)`(宽 W,高 H)。门是矩形 `(Dw, Dh)`(宽 Dw,高 Dh)。门的位置`(Px, Py)`是门左下角在墙内的局部坐标。

**默认约束**:
- `Py = 0`:门贴地(地板水平线),玩家不需要跳
- `Px = (W - Dw) / 2`:门水平居中
- `Dh ≈ 2.0 m`(玩家身高 + 余量),`Dw ≈ 1.0 m`(玩家宽度 + 余量)

**为什么是这些数值?** 游戏人物的胶囊半径约 0.3m,身高约 1.8m。门要给他通过空间——`Dw >= 0.8m`、`Dh >= 2.0m`。Casey HH 用 `Dw=1.0, Dh=2.0`,余量足够。

**墙体分割**。门确定后,墙被分为 4 个矩形(假设 `Py=0`,无底墙):

```
顶部墙: 宽 W, 高 (H - Dh),位置 (0, Dh) → (W, H)
左墙:   宽 Px, 高 Dh,位置 (0, 0) → (Px, Dh)
右墙:   宽 (W - Px - Dw), 高 Dh,位置 (Px + Dw, 0) → (W, Dh)
门:     宽 Dw, 高 Dh,位置 (Px, 0) → (Px + Dw, Dh) — 不创建碰撞!
```

**实现**:

```rust
struct WallSegment {
    aabb: AABB,
    is_solid: bool,  // false = 门,玩家可穿过
}

fn split_wall_with_door(wall: AABB, door_width: f32, door_height: f32) -> Vec<WallSegment> {
    let w = wall.size().x;
    let h = wall.size().y;
    let px = (w - door_width) / 2.0;  // 门居中
    let py = 0.0;                      // 门贴地
    let dw = door_width;
    let dh = door_height;
    
    vec![
        // 顶部墙
        WallSegment {
            aabb: AABB::new(
                Vec3::new(wall.min.x, wall.min.y + dh, wall.min.z),
                Vec3::new(wall.max.x, wall.max.y, wall.max.z),
            ),
            is_solid: true,
        },
        // 左墙
        WallSegment {
            aabb: AABB::new(
                Vec3::new(wall.min.x, wall.min.y, wall.min.z),
                Vec3::new(wall.min.x + px, wall.min.y + dh, wall.max.z),
            ),
            is_solid: true,
        },
        // 右墙
        WallSegment {
            aabb: AABB::new(
                Vec3::new(wall.min.x + px + dw, wall.min.y, wall.min.z),
                Vec3::new(wall.max.x, wall.min.y + dh, wall.max.z),
            ),
            is_solid: true,
        },
        // 门(非 solid)
        WallSegment {
            aabb: AABB::new(
                Vec3::new(wall.min.x + px, wall.min.y, wall.min.z),
                Vec3::new(wall.min.x + px + dw, wall.min.y + dh, wall.max.z),
            ),
            is_solid: false,
        },
    ]
}
```

每行解释:
- `let px = (w - dw) / 2.0` — 门居中,左墙宽度等于右墙宽度。
- 顶部墙从 `y = wall.min.y + dh` 到 `wall.max.y`——门以上的部分。
- 左墙从 `x = wall.min.x` 到 `wall.min.x + px`,y 同门高度。
- 右墙类似。
- 门的 `is_solid = false`,碰撞检测时跳过。

**碰撞系统的对接**。碰撞引擎迭代所有 WallSegment,对 `is_solid == true` 的做碰撞检测。玩家走到门区域,没有 solid segment 挡他,他就过去了。

这是 **CSG(constructive solid geometry)减法**的简化版——把一个矩形"减去"另一个矩形,得到 4 个矩形。真正的 CSG 在 3D mesh 上做布尔运算,复杂得多。Casey HH 简化到 2D 分割,够用。

### 工业碰撞引擎的"碰撞 mask"

商业游戏引擎的碰撞系统比 Day 448 复杂得多。让我介绍几个相关概念:

**Collision Layer / Mask**。每个碰撞体有 layer 属性,每个碰撞体有 mask(对哪些 layer 响应)。这让"子弹不和其他子弹碰,但碰敌人"成为可能:

```rust
const LAYER_WALL: u32 = 1 << 0;
const LAYER_PLAYER: u32 = 1 << 1;
const LAYER_ENEMY: u32 = 1 << 2;
const LAYER_BULLET: u32 = 1 << 3;

struct Collider {
    layer: u32,
    mask: u32,  // 我响应哪些 layer
}

// 玩家:碰墙、碰敌人,不碰自己的子弹
let player = Collider { layer: LAYER_PLAYER, mask: LAYER_WALL | LAYER_ENEMY };

// 子弹:碰墙、碰敌人,不碰玩家(队友伤害关)
let bullet = Collider { layer: LAYER_BULLET, mask: LAYER_WALL | LAYER_ENEMY };
```

`mask` 用位运算高效过滤——`if (a.mask & b.layer) != 0 { check_collision() }`。

**Trigger vs Solid**。Trigger 是"非阻挡碰撞"——玩家可以穿过,但进入时触发事件。门就是个潜在的 trigger——玩家进门触发"加载下一关"或"播放开门音效"。

```rust
enum ColliderKind {
    Solid,    // 阻挡
    Trigger,  // 不阻挡,但触发事件
}
```

HH 的门目前是"碰撞断开"——既不是 Solid 也不是 Trigger。要加"开门音效",改成 Trigger。

**Broadphase / Narrowphase**。N 个碰撞体两两检测是 O(N²)——1000 个碰撞体要 100 万次检测。工业用两阶段:

- **Broadphase**:用 AABB 快速剔除明显不碰撞的对(O(N log N) 用 BVH 或 sweep-and-prune)
- **Narrowphase**:对候选对做精确检测(O(候选数))

门作为"非 solid"的 WallSegment,在 broadphase 就被排除——零开销。

让我再深入讲一下 broadphase 的两个工业算法,因为它们是 Day 449 重叠检测的基础。

**Sweep and Prune(SAP)**。把所有 AABB 沿 X 轴排序,然后扫描。两个 AABB 的 X 区间重叠才算"候选"。X 不重叠的直接排除。

```
按 min.x 排序:A, B, C, D, E
扫描:
  A: 检查 B(X 重叠?), C(X 重叠?)
  B: 检查 C(X 重叠? 是→进一步检查 Y、Z)
  ...
```

复杂度:对几乎不重叠的场景(N 个静态 AABB),期望 O(N + k),k 是候选对数。

**BVH(Bounding Volume Hierarchy)**。把 AABB 组织成树,每个内部节点的 AABB 是子节点 AABB 的并集。查询"谁和 X 碰撞"时,从根开始递归——如果根的 AABB 不和 X 重叠,整个子树跳过。

```
              [根 AABB]
              /        \
        [左子 AABB]  [右子 AABB]
         /   \         /   \
       L1   L2       L3   L4
```

复杂度:O(log N) 查询(理想情况)。

**Day 449 重叠检测**。Casey HH 房间数量不多(<100),用 O(N²) 暴力就够。但理解 SAP / BVH 让你知道**未来怎么扩展**——房间数到 1000 就要升级算法。

```rust
// 暴力:O(N²)
fn any_overlap(rooms: &[AABB]) -> bool {
    for i in 0..rooms.len() {
        for j in (i+1)..rooms.len() {
            if rooms[i].intersects(&rooms[j]) {
                return true;
            }
        }
    }
    false
}

// SAP:O(N log N + k)
fn any_overlap_sap(rooms: &mut [AABB]) -> bool {
    rooms.sort_by(|a, b| a.min.x.partial_cmp(&b.min.x).unwrap());
    for i in 0..rooms.len() {
        let mut j = i + 1;
        while j < rooms.len() && rooms[j].min.x < rooms[i].max.x {
            // X 重叠,检查 Y/Z
            if rooms[i].intersects(&rooms[j]) {
                return true;
            }
            j += 1;
        }
    }
    false
}
```

### 门的方向与朝向:门面 vs 门洞

一个微妙的设计问题:门有"朝向"——玩家穿过时面朝哪个方向?

**轴对齐门**:门总是面向 X 轴(墙是 YZ 平面)或 Z 轴(墙是 XY 平面)。Casey HH 用轴对齐,简化。

**斜门**:门可以斜着(墙是斜的)。需要存法向量,玩家穿过时按法向量旋转。复杂。

实战中 90% 门是轴对齐,因为墙是轴对齐的(房间是 AABB)。少数游戏(如 roguelike 圆形房间)才有斜门。

**门的开合动画**。门关闭时挡路(`is_solid = true`),玩家按 E 键"开门",触发动画 + 改成 `is_solid = false`。这是 industrial game 的 "interactive door"。

```rust
struct Door {
    aabb: AABB,
    is_open: bool,
    open_progress: f32,  // 0 = 关, 1 = 开,动画用
}

impl Door {
    fn is_solid(&self) -> bool {
        !self.is_open && self.open_progress < 0.5
    }
    fn update(&mut self, dt: f32) {
        let target = if self.is_open { 1.0 } else { 0.0 };
        let speed = 4.0;  // 4 倍速开关
        self.open_progress += (target - self.open_progress) * dt * speed;
    }
}
```

### 严谨原理:门的位置和大小

设房间 A 在 B 东边(共享墙是 A 的西墙 = B 的东墙)。共享墙在 X = `B.max.x = A.min.x`,在 YZ 平面上是一个矩形 `[B.min.y, B.max.y] × [B.min.z, B.max.z]`(假设共享范围完全重叠)。

门的位置:
- X = 共享墙 X(常量)
- Y 范围:`[ground_y, ground_y + door_height]`,门从地面到 2 米高
- Z 范围:门居中,宽度 = `door_width`

```rust
struct Door {
    room_a: EntityId,
    room_b: EntityId,
    plane: AxisPlane,  // YZ / XY / XZ
    position: Vec3,    // 门中心
    width: f32,
    height: f32,
}

enum AxisPlane { YZ, XY, XZ }

fn place_door_east(a: &AABB, b: &AABB, door_width: f32, door_height: f32) -> Door {
    let shared_x = a.min.x;  // = b.max.x
    // Z 居中(假设 a.size().z 比 door_width 大)
    let z_center = (a.min.z + a.max.z) * 0.5;
    let z0 = z_center - door_width * 0.5;
    let z1 = z_center + door_width * 0.5;
    let y0 = a.min.y;  // 地面
    let y1 = a.min.y + door_height;

    Door {
        room_a: EntityId(0),
        room_b: EntityId(1),
        plane: AxisPlane::YZ,
        position: Vec3 { x: shared_x, y: (y0+y1)*0.5, z: z_center },
        width: door_width,
        height: door_height,
    }
}
```

每行解释:
- `shared_x = a.min.x` — 共享墙的 X 坐标。
- `z_center = (min+max)/2` — 房间 Z 范围中点,门居中。
- `z0/z1` — 门的 Z 范围。
- `y0 = a.min.y, y1 = a.min.y + height` — 门从地面到 `height` 米。
- `position` 是门中心,便于渲染。

### 墙体拆分

墙原本是单个矩形 `[y0, y1] × [z0, z1]`。凿门后变 4 块:

```
原墙:           凿门后:
[y0, y1] x [z0, z1]
                ┌─────┬───┬─────┐
                │ 上  │   │ 上  │
                ├─────┤ 门├─────┤
                │ 下  │   │ 下  │
                └─────┴───┴─────┘
```

具体:
- 门上方:`[y1, wall_top] × [z_left, z_right]`
- 门左:`[y0, wall_top] × [z0, z_left]`
- 门右:`[y0, wall_top] × [z_right, z1]`

```rust
struct WallPiece {
    aabb: AABB,
}

fn split_wall_for_door(
    wall_min: Vec3, wall_max: Vec3,
    door_min_z: f32, door_max_z: f32,
    door_top_y: f32,
) -> Vec<WallPiece> {
    let mut pieces = Vec::new();
    // 门左
    pieces.push(WallPiece { aabb: AABB {
        min: wall_min,
        max: Vec3 { x: wall_max.x, y: wall_max.y, z: door_min_z },
    }});
    // 门右
    pieces.push(WallPiece { aabb: AABB {
        min: Vec3 { x: wall_min.x, y: wall_min.y, z: door_max_z },
        max: wall_max,
    }});
    // 门上方
    pieces.push(WallPiece { aabb: AABB {
        min: Vec3 { x: wall_min.x, y: door_top_y, z: door_min_z },
        max: Vec3 { x: wall_max.x, y: wall_max.y, z: door_max_z },
    }});
    pieces
}
```

每行解释:
- `WallPiece { aabb }` — 每块墙体是一个 AABB,有独立碰撞盒。
- 三块共同覆盖整个墙减去门洞。
- **门洞本身没有 WallPiece**——这就是"凿"。

### 多个门

一个共享墙可以有多扇门(门 A、门 B)。墙体拆分变复杂,但思路相同:把墙沿每扇门"切片"。复杂度 N 门 → O(N+1) 块。

Casey Day 448 只放一扇门,后面优化时再加多门。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏里的"门"和"连接":

- **实体门**:玩家靠近自动开(EFT、Dishonored)
- **触发门**:踩 trigger 开,触发出关门
- **物理门**:有铰链,玩家推动开关(Half-Life 2)
- **传送门**:不真的开墙,瞬移玩家(Portal)
- **关卡连接**:场景切换(Resident Evil 经典加载门)

每种实现复杂度不同。Casey HH 用最简单的"墙洞"——没有门的物体,只是空缺。

工业坑:**门是寻路系统的关键节点**。AI 路径规划要识别"门"为图节点,连接两个房间的图。这就是 **portal-based rendering** 的基础(Doom 3、Quake 用)。

### 3.2 · 图形学视角

**Portal rendering**:场景由"cell"和"portal"组成。渲染时从相机所在 cell 出发,通过 portal 看到 next cell,递归。这是 1990s 的主流技术,如今仍用于 VR(避免渲染整个场景)。

**Doorway culling**:门外的房间可以延迟渲染,直到相机看到门洞。这节省 fill rate。

### 3.3 · Linux 系统编程视角

Linux 的"凿孔"对应:
- **文件 hole**:`lseek` + `write` 在文件中间创建空洞,ext4 用 sparse file 支持
- **`fallocate(FALLOC_FL_PUNCH_HOLE)`**:在文件中真正释放一段磁盘空间
- **`madvise(MADV_DONTNEED)`**:告诉内核某段内存可以丢弃

这些都是"在连续结构里挖洞"的操作系统级支持。

**题**:为什么凿墙产生 3 块(左、右、上),而不是 1 块"门外的整个墙"?

**参考解答**:一扇门把墙切成 4 个区域(左、右、上、下)。但"下"通常是地面(没有墙),所以实际只剩 3 块。

## 8 · Rust / Arch 落地代码

完整凿墙实现,带可视化:

```rust
#[derive(Debug, Clone, Copy)]
struct Vec3 { x: f32, y: f32, z: f32 }

#[derive(Debug, Clone, Copy)]
struct AABB { min: Vec3, max: Vec3 }

#[derive(Debug, Clone, Copy)]
struct EntityId(usize);

#[derive(Debug, Clone, Copy)]
enum AxisPlane { YZ, XY, XZ }

#[derive(Debug, Clone, Copy)]
struct Door {
    room_a: EntityId,
    room_b: EntityId,
    plane: AxisPlane,
    center: Vec3,
    width: f32,
    height: f32,
}

impl AABB {
    fn size(&self) -> Vec3 {
        Vec3 {
            x: self.max.x - self.min.x,
            y: self.max.y - self.min.y,
            z: self.max.z - self.min.z,
        }
    }
}

const DOOR_WIDTH: f32 = 1.5;
const DOOR_HEIGHT: f32 = 2.5;

// 房间 A 在东(B 的 +X 侧),共享墙 X = a.min.x = b.max.x
fn place_door_east(a_id: EntityId, b_id: EntityId, a: &AABB) -> Door {
    let shared_x = a.min.x;
    let z_center = (a.min.z + a.max.z) * 0.5;
    Door {
        room_a: a_id,
        room_b: b_id,
        plane: AxisPlane::YZ,
        center: Vec3 { x: shared_x, y: DOOR_HEIGHT * 0.5, z: z_center },
        width: DOOR_WIDTH,
        height: DOOR_HEIGHT,
    }
}

// 凿墙:返回 3 个墙体碎片
fn split_wall_for_door_yz(
    wall_x: f32,
    wall_min_y: f32, wall_max_y: f32,
    wall_min_z: f32, wall_max_z: f32,
    door_min_z: f32, door_max_z: f32,
    door_top_y: f32,
    wall_thickness: f32,
) -> Vec<AABB> {
    let x0 = wall_x - wall_thickness * 0.5;
    let x1 = wall_x + wall_thickness * 0.5;
    vec![
        // 门左:[z0, door_min_z]
        AABB {
            min: Vec3 { x: x0, y: wall_min_y, z: wall_min_z },
            max: Vec3 { x: x1, y: wall_max_y, z: door_min_z },
        },
        // 门右:[door_max_z, z1]
        AABB {
            min: Vec3 { x: x0, y: wall_min_y, z: door_max_z },
            max: Vec3 { x: x1, y: wall_max_y, z: wall_max_z },
        },
        // 门上方:[door_top_y, y1] × [door_min_z, door_max_z]
        AABB {
            min: Vec3 { x: x0, y: door_top_y, z: door_min_z },
            max: Vec3 { x: x1, y: wall_max_y, z: door_max_z },
        },
    ]
}

fn main() {
    // 房间 A:0..10 在 X,0..3 在 Y,0..8 在 Z
    let room_a = AABB {
        min: Vec3 { x: 10.0, y: 0.0, z: 0.0 },
        max: Vec3 { x: 20.0, y: 3.0, z: 8.0 },
    };
    // 房间 B:0..10 在 X,与 A 西边相接
    let room_b = AABB {
        min: Vec3 { x: 0.0, y: 0.0, z: 0.0 },
        max: Vec3 { x: 10.0, y: 3.0, z: 8.0 },
    };

    let door = place_door_east(EntityId(0), EntityId(1), &room_a);
    println!("Door: center=({},{},{}) w={} h={}",
        door.center.x, door.center.y, door.center.z, door.width, door.height);

    // 凿墙
    let z_center = (room_a.min.z + room_a.max.z) * 0.5;
    let door_min_z = z_center - door.width * 0.5;
    let door_max_z = z_center + door.width * 0.5;
    let pieces = split_wall_for_door_yz(
        room_a.min.x,  // 共享 X
        room_a.min.y, room_a.max.y,
        room_a.min.z, room_a.max.z,
        door_min_z, door_max_z,
        door.height,
        0.2,  // 墙厚 20cm
    );

    println!("\nWall pieces (after door cut):");
    for (i, p) in pieces.iter().enumerate() {
        println!("  Piece {}: min=({:.2},{:.2},{:.2}) max=({:.2},{:.2},{:.2})",
            i, p.min.x, p.min.y, p.min.z, p.max.x, p.max.y, p.max.z);
    }
}
```

每行解释:
- `wall_thickness = 0.2` — 墙厚 20cm,实际游戏更复杂(空心墙、贴图)。
- 3 个 `WallPiece` 完整覆盖墙减门洞。
- `door.center.x = shared_x`,门的平面在共享墙上。
