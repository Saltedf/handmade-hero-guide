> Day 560 precompute irradiance 假设光源静态,但游戏里有动态光源(火把、子弹爆炸的火光)。Day 565 Casey 加 **multi-light reconstruction**——把多光源的贡献分离存储,fragment shader 重建总和。

## 0 · 为什么要有这一天

让我们把镜头贴近画面。你跟着 Handmade Hero 走到 Day 560——Casey 实现了 precomputed irradiance,把所有光源的贡献**预先算好**存进 voxel grid。你跑游戏,场景里的太阳光、静态反射光看起来很美——但是,**玩家点燃火把,周围墙没变亮**。火把发的光去哪了?**没去哪——baked grid 是 precompute 一次就不变,火把是后加的动态光源,baked grid 不知道**。

这就是 baked lighting(烘焙光照)的根本限制——它只能反映"烘焙那一刻"的光照状态。任何后续添加的、移动的、变化的光源,baked grid 都"看不见"。

工业界有两套解决方案:

**方案一:全 dynamic(全动态)**——每帧重新计算所有光源,包括静态的。优点:光源任意变化都立刻反映。缺点:每帧重算光照很贵,大场景(几千光源、几百万 voxel)撑不住。

**方案二:Hybrid(混合)**——静态光源 baked(不变),动态光源实时算,运行时加起来。这是工业游戏标配。Unreal Engine 5 的 Lumen、Unity HDRP 的 Enlighten、Godot 4 的 SDF GI 都是 hybrid。

**Multi-light reconstruction** 是 hybrid 的核心:**每个光源独立存**自己的贡献,fragment shader 实时把它们加起来:

```
final_light = light_static_baked + light_dynamic_1 + light_dynamic_2 + ...
```

每个 light 单独存 voxel grid?太贵——10 光源 × 16³ × 4 字节 = 几 MB,而且大部分 voxel 不被任何光源照亮,浪费。优化方向:

- **Static light**:baked 一次,不变(墙、地板反射的太阳光)
- **Dynamic light**:实时计算(火把、子弹爆炸)
- **Hybrid**:baked static + real-time dynamic 合并

Casey 这天做 hybrid——分离 baked 和 dynamic,运行时合并。这是从"静态 GI"到"动态 GI"的关键升级。

完成这一天之后,你具备:

- 理解 baked vs dynamic lighting 的边界——为什么不能全 baked,也不能全 dynamic
- 能分离多光源贡献,在 fragment shader 加性合并
- 知道现代游戏的"real-time GI + baked GI"组合,以及各自的性能预算
- 实现动态光源的 voxel 注入,理解 distance-based culling 的省时原理

## 2 · 心智模型

### 2.1 类比:房间的固定灯 vs 手电筒

让我们把 hybrid lighting 的核心直觉用日常场景建立起来。你走进一个房间,房间里有两类光源:

**吸顶灯(static,静态)**:位置固定在天花板,光照固定——开灯时整面墙都亮,关灯时变暗。这类光源的特征是**不会变**——你早上看是这样,晚上看也是这样。可以预先画一张"光照图"——某面墙亮度多少,某角落暗多少——画完挂在墙上,任何时候都准确。

**手电筒(dynamic,动态)**:位置动(你手持移动),光照方向变(你转头)。**这类光源必须实时算**——你不能预先画"手电筒照到哪儿",因为手电筒每秒都在新位置。手电筒照亮的墙,墙的亮度随手电筒位置变化。

吸顶灯的光照可以 baked(关灯前一直这样),手电筒要 real-time(每帧重算)。

最终看到的:墙上 = 吸顶灯的固定光照 + 手电筒的动态光照。两者**加性叠加**(additive)——光的强度叠加,颜色按 RGB 加法。这是物理上光的本性——两个光源同时照射,眼睛接收的总光通量是两个之和。

**为什么 baked + dynamic 加性是正确的?**光波叠加的物理原理——电磁波是线性的,两个光源的电磁场叠加等于各自电磁场的矢量和。眼睛/相机接收到的"亮度"就是总电磁场强度。所以加性合成是物理正确的。这就是为什么 Casey 的 shader 简单 `total_light = baked + dynamic` 就够了。

### 2.2 严谨展开:动态光源的 voxel 注入

让我把动态光源怎么"进 voxel grid"彻底讲清楚——这是 voxel GI 的核心算法之一。

动态光源(如火把)有位置、颜色、半径。火把照亮**周围半径内**的 voxel——离火把越近,voxel 接收的光越强;越远,越弱(距离衰减)。这就是 **inverse-square law**(平方反比定律)的离散近似——物理上点光源的能量随距离平方衰减,我们用更简单的线性衰减(linear falloff)近似。

```rust
struct DynamicLight {
    pos: Vec3,
    color: Vec3,
    radius: f32,  // 光源影响的最大半径,超出此距离光为 0
}

fn inject_dynamic_light(
    grid: &mut VoxelGrid,
    light: &DynamicLight,
) {
    let center = [
        (light.pos.x / VOXEL_SIZE) as i64,
        (light.pos.y / VOXEL_SIZE) as i64,
        (light.pos.z / VOXEL_SIZE) as i64,
    ];
    let r = (light.radius / VOXEL_SIZE) as i64;

    // 遍历光源半径内的所有 voxel(球形遍历)
    for dk in -r..=r {
        for dj in -r..=r {
            for di in -r..=r {
                let d2 = di*di + dj*dj + dk*dk;
                if d2 > r*r { continue; }  // 球形剪枝(立方体内接球)
                let i = (center[0] + di) as usize;
                let j = (center[1] + dj) as usize;
                let k = (center[2] + dk) as usize;
                if i >= grid.dim[0] || j >= grid.dim[1] || k >= grid.dim[2] { continue; }

                // 线性衰减:离中心近 = 1.0,离边缘 = 0.0
                let falloff = 1.0 - (d2 as f32 / (r*r as f32)).sqrt();
                let existing = grid.get(i, j, k);
                // 加性注入:把光的颜色 × falloff 加到现有 voxel 光照
                grid.set(i, j, k, [
                    existing[0] + light.color.x * falloff,
                    existing[1] + light.color.y * falloff,
                    existing[2] + light.color.z * falloff,
                ]);
            }
        }
    }
}
```

**关键设计点**:
1. **球形遍历剪枝**——只在球形半径内迭代,立方体角落(`d2 > r*r`)跳过。这让计算量正比于 `(4/3)π r³`(球体积),而非 `(2r)³`(立方体体积),省 48%。
2. **加性注入**——`existing + new_contribution`,允许多光源叠加。如果两个火把都照亮某 voxel,这个 voxel 接收两个贡献的总和。
3. **线性 falloff**——`falloff = 1 - distance/radius`。物理上应该是 inverse-square(`1/d²`),但线性 falloff 有"hard cutoff"(超出 radius 完全为 0)利于 culling,而 inverse-square 永远不到 0,无法 culling。
4. **每帧重新生成 dynamic grid**——`clear_dynamic_grid(); inject_all_dynamic_lights();`。这样动态光源移动后,grid 立刻反映新位置。

**为什么用 voxel 注入而非 per-pixel 计算?**对少量光源(几十个),per-pixel 直接遍历光源更快(无需 voxel 中介)。但对大量光源(几百几千个)或要考虑间接光照(光在场景里弹射),voxel 注入更有优势——光的传播通过 voxel grid 自动模拟(bounced light)。Casey 这天用 voxel 注入,后面 day572+ 加 ray march 做精确传播。

### 2.3 Fragment shader 重建

```glsl
vec3 baked_light = texture(baked_grid, world_pos / voxel_size).rgb;
vec3 dynamic_light = texture(dynamic_grid, world_pos / voxel_size).rgb;
vec3 total_light = baked_light + dynamic_light;
return surface_color * total_light;
```

简单加法。**但有两个细节**:

**HDR 处理**:baked + dynamic 可能超过 1.0(多个强光源叠加,如白天太阳 + 火把直射)。这叫 HDR(high dynamic range)。如果不处理,fragment shader 把 >1.0 的值 clamp 到 1.0,高亮区域变成"死白"——视觉上不好。**正确做法是 tonemapping**——用 ACES、Reinhard、Unreal Tonemapper 等曲线把 HDR 值映射到 [0,1],保留亮区细节。Casey 这天可能先不加 tonemap,后面优化加。

**Albedo 染色**:total_light 是入射光,surface_color 是表面反射率,`surface * light` 得到反射光——白光照红墙得红光。但如果 light 是 HDR(>1.0),反射光也是 HDR——这点在 tonemap 之前应该保留。

### 2.4 多光源的性能权衡

如果 1000 个动态光源(战斗场景很多子弹爆炸的火光),dynamic grid 更新慢——每帧注入 1000 个光源,每个光源遍历半径内 voxel(可能上千 voxel),总 voxel 操作几百万——CPU/GPU 撑不住。优化方向:

- **Culling**:只更新玩家可见的光源。如果某光源在墙后玩家看不见,跳过
- **Per-pixel lighting**:光源不存 voxel grid,fragment shader 直接遍历光源点积法线。光源少时快,多时慢
- **Tiled/Cluster lighting**:屏幕分 tile(如 64x64 像素),每 tile 只处理影响它的光源。这是现代 forward renderer 的标配
- **Light culling by depth**:Cluster lighting 加 depth slice,3D cluster 比 2D tile 更精确

工业游戏(Unreal Lumen、Unity HDRP)用 Cluster + screen-space——把光源分配到屏幕的 3D cluster(2D tile + depth slice)。**Cluster forward** 让 1000 光源在 60 FPS 跑——这是 Doom Eternal、Cyberpunk 2077 的核心技术。

Casey 这天用 voxel grid 注入,简单但光源多时慢——是教学实现,生产用要切到 cluster。

## 3 · 四域深入

### 3.1 · 游戏编程视角

多光源的工业实现:

- **Forward rendering**:fragment shader 遍历所有光源,慢但准
- **Deferred rendering**:G-buffer 存 normal/pos,光照 pass 一遍算所有
- **Forward+ / Cluster forward**:光源分 cluster,只算影响当前 cluster 的
- **Voxel-based**:光源注入 voxel(本项目)

Forward+ 是现代主流——多光源 + MSAA 兼容。Casey 选 voxel-based 是因为已有 voxel GI 系统。

### 3.2 · 图形学视角

光照方程的多光源形式:

```
L_o = Σ_i L_i * f_r * cos(θ_i) * V_i
```

i 是光源索引,L_i 是光源强度,f_r 是 BRDF,V_i 是 visibility(被遮挡?)。

Deferred 把 L_o 拆成"G-buffer + light loop",光源 loop 在 pixel shader 跑。

### 3.3 · Linux 系统编程视角

"加性贡献"模式在系统编程:

- **Atomic counter**:多线程各加自己的贡献
- **Reduce operation**:MPI/MapReduce 的 reduce
- **Sensor fusion**:多传感器数据融合

都是"N 个独立源 → 1 个加总结果"的模式。

### 3.4 · Rust 生态视角

Rust 表达 light list:

```rust
#[repr(C)]
#[derive(Clone, Copy, bytemuck::Pod, bytemuck::Zeroable)]
struct GpuLight {
    pos: [f32; 4],     // xyz + radius
    color: [f32; 4],   // rgb + intensity

let light_buffer = device.create_buffer_init(&wgpu::util::BufferInitDescriptor {
    contents: bytemuck::cast_slice(&lights),
    usage: wgpu::BufferUsage::STORAGE,

```

WGSL 读:

```wgsl
@group(0) @binding(0) var<storage, read> lights: array<GpuLight>;

@fragment
fn fs_main(...) -> ... {
    var total = vec3<f32>(0.0);
    for (var i: u32 = 0; i < arrayLength(&lights); i = i + 1) {
        let l = lights[i];
        let d = l.pos.xyz - world_pos;
        let dist = length(d);
        if (dist < l.pos.w) {  // w = radius
            let falloff = 1.0 - dist / l.pos.w;
            total = total + l.color.rgb * falloff;
        }
    }
    return vec4<f32>(total, 1.0);
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 baked + dynamic 分离存储,而不是全 real-time?

**参考解答**:(1) Real-time 慢——多光源 per-pixel 计算 GPU 时间长;(2) 静态光源不需要重算,baked 一次省 CPU/GPU;(3) Static baked 可以离线烘焙超高质量(real-time 必须简化算法);(4) Hybrid 让大部分场景 fast(baked) + 少量动态元素 flexible(real-time)。代价:baked 和 dynamic 要分开存,GPU 多一个 texture fetch,但 fetch 开销远小于 real-time 计算。

### Lv2 · 动手实践

要求:

```rust
type V3 = [f32; 3];

struct VoxelGrid {
    data: Vec<V3>,
    dim: usize,
}

impl VoxelGrid {
    fn new(dim: usize) -> Self {
        VoxelGrid { data: vec![[0.0; 3]; dim*dim*dim], dim }
    }
    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim + j) * self.dim + i
    }
    fn get(&self, i: usize, j: usize, k: usize) -> V3 {
        self.data[self.idx(i, j, k)]
    }
    fn set(&mut self, i: usize, j: usize, k: usize, v: V3) {
        self.data[self.idx(i, j, k)] = v;
    }
    fn clear(&mut self) {
        for v in self.data.iter_mut() { *v = [0.0; 3]; }
    }
}

struct Light { pos: V3, color: V3, radius: f32 }

fn inject_light(grid: &mut VoxelGrid, light: &Light) {
    let cx = light.pos[0] as i64;
    let cy = light.pos[1] as i64;
    let cz = light.pos[2] as i64;
    let r = light.radius as i64;

    for dk in -r..=r {
        for dj in -r..=r {
            for di in -r..=r {
                let d2 = di*di + dj*dj + dk*dk;
                if d2 > r*r { continue; }
                let i = (cx + di) as usize;
                let j = (cy + dj) as usize;
                let k = (cz + dk) as usize;
                if i >= grid.dim || j >= grid.dim || k >= grid.dim { continue; }
                let falloff = 1.0 - (d2 as f32 / (r*r as f32)).sqrt();
                let existing = grid.get(i, j, k);
                grid.set(i, j, k, [
                    existing[0] + light.color[0] * falloff,
                    existing[1] + light.color[1] * falloff,
                    existing[2] + light.color[2] * falloff,
                ]);
            }
        }
    }
}

fn main() {
    let mut baked = VoxelGrid::new(16);
    let mut dynamic = VoxelGrid::new(16);

    // baked 太阳光
    let sun = Light { pos: [8.0, 15.0, 8.0], color: [0.5, 0.5, 0.5], radius: 5.0 };
    inject_light(&mut baked, &sun);

    // 模拟 5 帧,火把移动
    for frame in 0..5 {
        dynamic.clear();
        let torch_x = 3.0 + frame as f32 * 2.0;
        let torch = Light { pos: [torch_x, 5.0, 8.0], color: [3.0, 1.5, 0.5], radius: 3.0 };
        inject_light(&mut dynamic, &torch);

        // 中心 voxel 的总光照
        let b = baked.get(8, 5, 8);
        let d = dynamic.get(8, 5, 8);
        println!("Frame {}: torch_x={}, baked={:?}, dynamic={:?}, total=({:.2}, {:.2}, {:.2})",
            frame, torch_x, b, d,
            b[0]+d[0], b[1]+d[1], b[2]+d[2]);
    }
}
```

## 8 · Rust / Arch 落地代码

完整 multi-light hybrid:

```rust
type V3 = [f32; 3];

#[derive(Clone, Copy, Default)]
struct Voxel { light: V3, occupied: bool }

struct VoxelGrid {
    data: Vec<Voxel>,
    dim: usize,
}

impl VoxelGrid {
    fn new(dim: usize) -> Self {
        VoxelGrid { data: vec![Voxel::default(); dim*dim*dim], dim }
    }
    fn idx(&self, i: usize, j: usize, k: usize) -> usize {
        (k * self.dim + j) * self.dim + i
    }
    fn get(&self, i: usize, j: usize, k: usize) -> Voxel { self.data[self.idx(i, j, k)] }
    fn set(&mut self, i: usize, j: usize, k: usize, v: Voxel) {
        self.data[self.idx(i, j, k)] = v;
    }
    fn clear_lights(&mut self) {
        for v in self.data.iter_mut() {
            v.light = [0.0; 3];
        }
    }
}

#[derive(Clone, Copy)]
struct Light {
    pos: V3,
    color: V3,
    radius: f32,
}

fn inject_light(grid: &mut VoxelGrid, light: &Light, occupied_grid: &VoxelGrid) {
    let cx = light.pos[0] as i64;
    let cy = light.pos[1] as i64;
    let cz = light.pos[2] as i64;
    let r = light.radius as i64;

    for dk in -r..=r {
        for dj in -r..=r {
            for di in -r..=r {
                let d2 = di*di + dj*dj + dk*dk;
                if d2 > r*r { continue; }
                let i = (cx + di) as usize;
                let j = (cy + dj) as usize;
                let k = (cz + dk) as usize;
                if i >= grid.dim || j >= grid.dim || k >= grid.dim { continue; }

                // 遮挡检查:从 light 到 voxel 路径上是否有墙?
                if is_occluded(occupied_grid, light.pos, [i as f32, j as f32, k as f32]) {
                    continue;
                }

                let falloff = 1.0 - (d2 as f32 / (r*r as f32)).sqrt();
                let existing = grid.get(i, j, k);
                grid.set(i, j, k, Voxel {
                    light: [
                        existing.light[0] + light.color[0] * falloff,
                        existing.light[1] + light.color[1] * falloff,
                        existing.light[2] + light.color[2] * falloff,
                    ],
                    occupied: existing.occupied,
                });
            }
        }
    }
}

fn is_occluded(grid: &VoxelGrid, from: V3, to: V3) -> bool {
    // 简化:沿 from->to 采样
    let dx = to[0] - from[0];
    let dy = to[1] - from[1];
    let dz = to[2] - from[2];
    let steps = (dx.abs().max(dy.abs()).max(dz.abs())) as usize + 1;
    for s in 1..steps {
        let t = s as f32 / steps as f32;
        let p = [from[0] + dx*t, from[1] + dy*t, from[2] + dz*t];
        let i = p[0] as usize;
        let j = p[1] as usize;
        let k = p[2] as usize;
        if i < grid.dim && j < grid.dim && k < grid.dim {
            if grid.get(i, j, k).occupied { return true; }
        }
    }
    false
}

fn main() {
    let mut baked = VoxelGrid::new(16);
    let mut dynamic = VoxelGrid::new(16);
    let occupied = VoxelGrid::new(16);  // 简化:全空

    // Baked:太阳
    let sun = Light {
        pos: [8.0, 15.0, 8.0],
        color: [0.6, 0.6, 0.5],
        radius: 8.0,
    };
    inject_light(&mut baked, &sun, &occupied);

    // Dynamic:玩家手持火把
    let mut player_pos: V3 = [3.0, 5.0, 8.0];

    // 模拟 5 帧
    for frame in 0..5 {
        dynamic.clear_lights();

        // 火把跟着玩家
        let torch = Light {
            pos: player_pos,
            color: [2.5, 1.0, 0.3],
            radius: 4.0,
        };
        inject_light(&mut dynamic, &torch, &occupied);

        // 采样几个 voxel
        let samples = [
            ([8, 5, 8], "中心"),
            ([player_pos[0] as usize, 5, 8], "玩家位置"),
            ([3, 5, 3], "角落"),
        ];

        println!("\nFrame {} (player at {:?}):", frame, player_pos);
        for (pos, name) in samples.iter() {
            let b = baked.get(pos[0], pos[1], pos[2]);
            let d = dynamic.get(pos[0], pos[1], pos[2]);
            println!("  {}: baked=({:.2},{:.2},{:.2}) + dynamic=({:.2},{:.2},{:.2}) = total ({:.2},{:.2},{:.2})",
                name,
                b.light[0], b.light[1], b.light[2],
                d.light[0], d.light[1], d.light[2],
                b.light[0]+d.light[0], b.light[1]+d.light[1], b.light[2]+d.light[2]);
        }

        // 玩家移动
        player_pos[0] += 1.0;
    }
}
```

GPU 实现的 shader(WGSL):

```wgsl
@group(0) @binding(0) var baked_tex: texture_3d<f32>;
@group(0) @binding(1) var dynamic_tex: texture_3d<f32>;
@group(0) @binding(2) var tex_sampler: sampler;

@fragment
fn fs_main(
    @location(0) world_pos: vec3<f32>,
    @location(1) normal: vec3<f32>,
) -> @location(0) vec4<f32> {
    let uvw = world_pos / 16.0;  // voxel_size = 1, dim = 16

    let baked = textureSample(baked_tex, tex_sampler, uvw).rgb;
    let dynamic = textureSample(dynamic_tex, tex_sampler, uvw).rgb;

    let total_light = baked + dynamic;
    let n = normalize(normal);
    let ndl = max(dot(n, vec3(0.0, 1.0, 0.0)), 0.0);

    return vec4<f32>(total_light * ndl, 1.0);
}
```
