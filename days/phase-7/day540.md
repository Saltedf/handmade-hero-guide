#### 内存可视化的几种图表

针对内存数据,工业级 profiler 提供这些视图:

**柱状图(Bar chart)**:每个 caller 一个柱,Y 轴是字节大小。Casey 用这个。优点:一眼看出"大头"。缺点:caller 多时柱子太挤。

**火焰图(Flame graph)**:调用栈的可视化,每层一个 caller,宽度 = 分配量。Brendan Gregg 2009 年发明,Linux perf / dtrace 标配。优点:看完整调用栈。缺点:需要 backtrace 数据。

**饼图(Pie chart)**:按类别(纹理、缓冲、audio)分组。优点:类别清晰。缺点:不能看 caller。

**时间线(Timeline)**:横轴时间,纵轴内存量。优点:看增长趋势。缺点:不能看 caller。

**Sankey diagram**:数据流图(分配 → 使用 → 释放)。优点:看生命周期。缺点:复杂。

每种视图解决不同问题。Casey 选柱状图,因为简单且对"找最大泄漏"有效。生产级 profiler(Tracy、Unreal Insights)同时支持多种视图。

游戏 debug overlay 要"实时更新"——每秒 60 次重新画。这有几个工程挑战:

### "实时" vs "快照"

Casey 的可视化是"实时"——每帧重画。但工业级 profiler 有两种模式:

**实时模式**(Casey):每帧调用 tracker 接口,显示当前状态。优点:实时反馈。缺点:数据抖动,看不出趋势。

**快照模式**(Linux Massif):每隔 N 秒采样一次,保存快照。优点:数据稳定,可比对历史。缺点:不实时。

混合模式:**实时显示当前 + 历史趋势线**。egui plot 的 line chart 适合这个——X 轴是时间,Y 轴是总内存,实时画一条增长曲线。看曲线"持续上升"就知道泄漏。

你的 Rust 项目应该两种都有:tracy 提供实时 + 历史曲线,自己加 in-game overlay 显示当前 top-N。

## 2 · 心智模型

### 类比:体检报告的可视化

医生给你一份 100 行的化验报告,你看不懂。但护士给你画一个**饼图**:血糖占多少、血脂占多少、肝功能占多少,你立刻看到"血脂超标"。

数据可视化让数字变成图形,大脑处理图形比处理数字快 100 倍。Casey 的内存柱状图就是这种"数字 → 图形"转换。

### 严谨展开:柱状图绘制

柱状图的核心几何:每个柱子是个矩形,宽固定(或自适应),高度 ∝ 数值。

```rust
struct BarChart {
    x: f32, y: f32,    // 左下角
    width: f32,        // 总宽
    height: f32,       // 总高(最大柱子高度)
    bars: Vec<f32>,    // 每个柱子的值(归一化前)
    labels: Vec<String>,
}

impl BarChart {
    fn draw(&self) {
        if self.bars.is_empty() { return; }
        let max_val = self.bars.iter().cloned().fold(0.0f32, f32::max);
        if max_val <= 0.0 { return; }
        
        let bar_width = self.width / self.bars.len() as f32;
        let gap = bar_width * 0.1;
        let actual_bar_w = bar_width - gap;        
        for (i, &val) in self.bars.iter().enumerate() {
            let bar_h = (val / max_val) * self.height;
            let bar_x = self.x + i as f32 * bar_width + gap / 2.0;
            let bar_y = self.y + self.height - bar_h;
            
            draw_rect(bar_x, bar_y, actual_bar_w, bar_h, Color::GREEN);
            draw_text(&self.labels[i], bar_x, self.y + self.height + 5, Color::WHITE);
        }
    }
}
```

每柱子:
- 宽:固定(总宽 / 柱数)
- 高:数值占比 × 最大高度
- Y 位置:从底部向上,所以 `bar_y = base_y - bar_h`

### 数据归一化

数值范围 [0, max],归一化到 [0, 1] 后乘以柱图高度。这叫 **linear normalization**:

```
normalized = (value - min) / (max - min)
```

如果 max = 0(全 0),避免除零。

### 内存数据聚合

按"源位置"聚合 alloc:

```rust
struct SourceAggregate {
    file: String,
    line: u32,
    total_bytes: u64,
    alloc_count: u32,
}

fn aggregate_by_source(allocs: &[AllocInfo]) -> Vec<SourceAggregate> {
    let mut map: HashMap<(String, u32), SourceAggregate> = HashMap::new();
    
    for alloc in allocs {
        let key = (alloc.file.to_string(), alloc.line);
        let entry = map.entry(key).or_insert_with(|| SourceAggregate {
            file: alloc.file.to_string(),
            line: alloc.line,
            total_bytes: 0,
            alloc_count: 0,
        });
        entry.total_bytes += alloc.size as u64;
        entry.alloc_count += 1;
    }
    
    let mut result: Vec<_> = map.into_values().collect();
    result.sort_by(|a, b| b.total_bytes.cmp(&a.total_bytes));
    result
}
```

聚合后,前 10 名是"内存大头"。

### Brendan Gregg 的 FlameGraph 详解

Flame Graph 是工业级 CPU/内存分析的标准可视化,Brendan Gregg 2009 年发明。让我讲一下原理,因为它和 Casey 的柱状图是同一思想的高级版。

Flame Graph 的结构:
- 横轴:调用栈宽度(采样次数)
- 纵轴:调用栈深度(caller → callee)
- 每个色块:一个函数
- 色块宽度:函数被采样到的次数

绘制:从最深一层开始(callee),水平排列,然后上一层(caller)把这些 callee 合并成大色块。

视觉效果:看起来像火焰(底宽顶尖),所以叫 flame graph。

工业级工具:`perf record`、`async-profiler`(Java)、`py-spy`(Python)都能生成 flame graph 数据。Casey 的 alloc tracker 数据稍作聚合就能画 flame graph——把 caller 信息改成"backtrace(完整调用栈)"。

**对你**:今天 Casey 只存单层 caller,如果你想要 flame graph,扩展 tracker 用 `backtrace::Backtrace` 库(慢但有完整栈)。这是工业级 profiler 的扩展方向。

### 实时 profiler 的"采样 vs 全量"

Casey 的 tracker 是"全量"——每次 alloc 都记录。这种 100% 数据捕获适合开发期,但生产期太慢。

工业级 profiler 用**采样**(sampling):每隔一段时间记录一次状态,而不是每次操作都记录。例:

- Tracy 默认采样 100 Hz(每秒 100 个数据点)
- Linux perf 默认 99 Hz
- Visual Studio 默认 1000 Hz

采样丢失细节(99% 的 alloc 没记录),但开销极低(几纳秒/秒)。生产部署用采样,开发调试用全量。

Rust 的 `tracy` crate 提供两种模式:

```rust
// 全量(慢但完整)
tracy_full::frame_mark();

// 采样(快但稀疏)
tracy_sample::sample("expensive_op", start_time);
```

学会这种"采样 vs 全量"权衡,你设计任何 profiler 都能正确选择模式。

### Color coding:数据可视化的秘密武器

Casey 的柱状图可能没特别考虑颜色,但工业级可视化大量用 color coding:

- **冷色调(蓝)**:低值/正常
- **暖色调(红)**:高值/异常
- **绿色**:正常
- **黄色**:警告
- **红色**:错误

例:内存柱状图,>100MB 的 caller 用红色,>10MB 用黄色,其他用绿色。一眼看出"红色那个就是泄漏嫌疑"。

```rust
fn bar_color(value: f32, max: f32) -> (u8, u8, u8) {
    let ratio = value / max;
    if ratio > 0.5 { (255, 100, 100) }  // 红
    else if ratio > 0.2 { (255, 220, 100) }  // 黄
    else { (100, 200, 100) }  // 绿
}
```

这种"semantic color"是工业级 UI 的标配。学会这个,你的 debug overlay 一眼就能识别问题。

### Lv1 · 概念辨析

**题**:柱状图 vs 饼图,内存分析用哪个更合适?

**参考解答**:柱状图更合适。理由:内存分析关注"哪个分配最大"——柱状图直接比较高度,一眼看出 top N。饼图擅长"占比"——如果你的问题是"GPU 内存 50% 是纹理,30% 是 buffer",饼图适合。但内存分析通常是"前 10 大",需要排序比较,柱状图直接。Casey 选柱状图合理。

### Lv2 · 动手实践

**题**:用 Rust 实现一个 ASCII 柱状图,显示前 10 大内存分配。输入:Vec<(String, usize)>(label, bytes)。输出:打印到终端的 ASCII 柱子,高度 ∝ bytes。

**参考解答**:

```rust
fn draw_ascii_bars(data: &[(String, usize)]) {
    if data.is_empty() { return; }
    let max_val = data.iter().map(|(_, v)| *v).max().unwrap_or(1);
    let max_height = 20;  // 最大 20 字符高
    
    for (label, &val) in data {
        let normalized = (val as f64 / max_val as f64) * max_height as f64;
        let height = normalized.round() as usize;
        
        // 标签 + KB
        print!("{:>30}: {:>8} B ", label, val);
        
        // 柱子
        let bar: String = "#".repeat(height);
        println!("[{}]", bar);
    }
}

fn main() {
    let data = vec![
        ("level_data:42".to_string(), 1024 * 1024),
        ("player:88".to_string(), 512 * 1024),
        ("enemy_list:120".to_string(), 256 * 1024),
        ("texture_atlas:15".to_string(), 128 * 1024),
        ("audio_buffer:67".to_string(), 64 * 1024),
    ];
    
    println!("=== Top 5 内存分配 ===\n");
    draw_ascii_bars(&data);
}
```

为什么这么写:`{:>30}` 是右对齐宽度 30。`"#".repeat(height)` 是 Rust 标准的字符串重复。ASCII 柱状图是终端 debug 的常用工具,不依赖 GUI。

### Lv3 · 迁移设计

**进阶**:支持"双击柱子复制 file:line 到剪贴板"——开发者能直接粘到 IDE 跳转。这是工业级 in-game profiler 的常见功能。

// 完整的内存可视化(终端 ASCII + 数据聚合)

use std::collections::HashMap;
use std::panic::Location;

#[derive(Debug, Clone)]
pub struct AllocInfo {
    pub size: usize,
    pub file: &'static str,
    pub line: u32,
}

#[derive(Debug, Clone)]
pub struct SourceAggregate {
    pub label: String,
    pub total_bytes: u64,
    pub alloc_count: u32,
}

pub fn aggregate_by_source(allocs: &[AllocInfo]) -> Vec<SourceAggregate> {
    let mut map: HashMap<String, SourceAggregate> = HashMap::new();
    
    for alloc in allocs {
        let label = format!("{}:{}", alloc.file, alloc.line);
        let entry = map.entry(label.clone()).or_insert_with(|| SourceAggregate {
            label,
            total_bytes: 0,
            alloc_count: 0,
        });
        entry.total_bytes += alloc.size as u64;
        entry.alloc_count += 1;
    }
    
    let mut result: Vec<_> = map.into_values().collect();
    result.sort_by(|a, b| b.total_bytes.cmp(&a.total_bytes));
    result
}

pub fn draw_ascii_bars(data: &[SourceAggregate], top_n: usize) {
    if data.is_empty() { return; }
    let top = &data[..data.len().min(top_n)];
    let max_val = top.iter().map(|d| d.total_bytes).max().unwrap_or(1);
    let max_height = 30;  // 最大 30 字符高
    let max_label_len = top.iter().map(|d| d.label.len()).max().unwrap_or(0).max(20);
    
    println!("\n{:<width$} {:>10} {:>5}  Distribution", "Source", "Bytes", "Allocs", width = max_label_len);
    println!("{}", "-".repeat(max_label_len + 30));
    
    for agg in top {
        let normalized = (agg.total_bytes as f64 / max_val as f64) * max_height as f64;
        let height = normalized.round() as usize;
        let bar: String = "█".repeat(height);
        
        println!("{:<width$} {:>10} {:>5}  {}",
            agg.label,
            format_bytes(agg.total_bytes),
            agg.alloc_count,
            bar,
            width = max_label_len
        );
    }
}

pub fn format_bytes(bytes: u64) -> String {
    if bytes >= 1024 * 1024 {
        format!("{:.1} MB", bytes as f64 / (1024.0 * 1024.0))
    } else if bytes >= 1024 {
        format!("{:.1} KB", bytes as f64 / 1024.0)
    } else {
        format!("{} B", bytes)
    }
}

// 模拟 AllocTracker(参考 day539)
pub struct AllocTracker {
    pub allocs: Vec<AllocInfo>,
}

impl AllocTracker {
    pub fn new() -> Self { Self { allocs: Vec::new() } }
    
    #[track_caller]
    pub fn alloc(&mut self, size: usize) {
        let loc = Location::caller();
        self.allocs.push(AllocInfo {
            size,
            file: loc.file(),
            line: loc.line(),
        });
    }
}

// 模拟游戏代码
fn load_textures(tracker: &mut AllocTracker) {
    tracker.alloc(4 * 1024 * 1024);  // 4 MB
    tracker.alloc(2 * 1024 * 1024);
    tracker.alloc(1 * 1024 * 1024);
}

fn load_sounds(tracker: &mut AllocTracker) {
    tracker.alloc(512 * 1024);
    tracker.alloc(256 * 1024);
}

fn load_level(tracker: &mut AllocTracker) {
    tracker.alloc(8 * 1024 * 1024);  // 8 MB level data
}

fn main() {
    let mut tracker = AllocTracker::new();
    
    println!("=== 模拟游戏加载 ===");
    load_textures(&mut tracker);
    load_sounds(&mut tracker);
    load_level(&mut tracker);
    
    println!("总分配数: {}", tracker.allocs.len());
    
    // 聚合 + 可视化
    let aggregated = aggregate_by_source(&tracker.allocs);
    draw_ascii_bars(&aggregated, 10);
    
    // 总计
    let total: u64 = tracker.allocs.iter().map(|a| a.size as u64).sum();
    println!("\n总内存: {}", format_bytes(total));
}
