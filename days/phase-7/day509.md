# Day 509 · 创建标签文件

> HH 的资产系统一直用"硬编码 tag"——代码里写 `BitmapType_Sword`、`SoundType_Footstep`。Day 509 引入 **HHT(Handmade Hero Tags)文件**——把 tag 从代码挪到外部文件,数据驱动。

## 0 · 为什么要有这一天

### 真实场景:硬编码 tag 的痛苦

让我们把镜头拉近。你跟着 Casey 做到 Day 508。游戏的资产 tag 全部硬编码在 Rust 源码:

```rust
enum BitmapType {
    Player,
    Sword,
    Shield,
    Tree,
    Goblin,
    // 加一个新 bitmap = 改 enum + 改所有 match
}

enum SoundType {
    Footstep,
    SwordSwing,
    Explosion,
    // ...
}

fn draw_bitmap(b: BitmapType) {
    match b {
        BitmapType::Player => render("player.png"),
        BitmapType::Sword => render("sword.png"),
        // ...
    }
}
```

这套系统在游戏早期"够用",但伴随团队扩张开始痛苦:

**痛苦 1:加资产要改代码**。美术师画了一张新怪 `goblin_archer.png`,想加进游戏。她不能直接加——必须让程序员:
1. 改 `enum BitmapType`,加 `GoblinArcher`
2. 改 `match` 分支,加 `BitmapType::GoblinArcher => render("goblin_archer.png")`
3. 重新编译游戏(几分钟)
4. 测试

每次加资产都这样,程序员成了"美术和游戏的瓶颈"。

**痛苦 2:跨进程不能共享**。Editor 工具和游戏各写一份 enum,容易不同步。Editor 加了 `GoblinArcher`,游戏没改,运行时崩。

**痛苦 3:不能配置**。不同关卡用不同 tag 集,但 enum 是全局的。如果你想给"夜行 mode"加几个特殊 sprite,要分支代码。

**痛苦 4:不能 mod**。玩家想做 mod,加自定义 sprite,没法加——enum 写死了。

### 数据驱动设计的解决方案

**数据驱动(data-driven)设计**:行为由外部数据决定,不由代码决定。把 tag 从代码挪到外部文件:

```
# assets.hht
[bitmaps]
player
sword
shield
tree
goblin
goblin_archer

[sounds]
footstep
sword_swing
explosion
```

代码读 HHT,动态构建 tag 数据库。加新 tag = 编辑 HHT,**不改代码**。

美术师流程变成:
1. 美术师把 `goblin_archer.png` 放进 `assets/bitmaps/`
2. 美术师用任意文本编辑器改 `assets.hht`,加一行 `goblin_archer`
3. 重启游戏(或热重载,Day 512)
4. 完事

程序员**不参与**。美术师独立性提升 10 倍。

### 工业级游戏的数据驱动

**Unity Tag Manager**:Edit > Project Settings > Tags and Layers。Tag / Layer 在 UI 里加,代码用 string 引用。新加 tag 不用改 C# 代码。

**Unreal Gameplay Tags**:Editor 里管理 tag 树。`Ability.Tags.Add(FGameplayTag::RequestGameplayTag("Ability.Fire"))`。Tag 是数据,INI 文件管理。

**Godot Input Map**:Project Settings > Input Map。键位绑定在数据里,代码用 `Input.is_action_pressed("ui_left")`。

**Unity Addressables**:资产管理完全数据驱动。Group、Label 都是数据。

游戏开发圈术语:
- **Data-driven**:数据驱动(行为由数据决定)
- **Reflection**:运行时类型查询
- **Code generation**:代码生成(从数据生成代码,获得类型安全)
- **Schema**:数据模式定义
- **Migration**:数据迁移(改 schema 时迁移旧数据)

### HHT vs JSON / TOML / YAML

Casey 选 HHT(自定义 INI 风格格式),为什么不直接用 JSON?

**理由 1:教学**。HH 是教学项目。用现成 JSON 没教学价值——Casey 想教学生"如何设计文本格式"。

**理由 2:领域特定**。HHT 是 tag 列表,INI 风格天然适合(简洁)。JSON 写 tag 列表要 `{"bitmaps": ["player", "sword"]}`,冗长。

**理由 3:parser 写作练习**。学生自己写 parser,学到 tokenizer + AST + parser 的核心能力。用 `serde_json` 跳过这些。

**工业级实践**:生产项目优先用成熟格式(TOML 配置、JSON 数据、Protobuf 二进制)。自定义格式只在特殊需求(教学、极简语法、性能)时用。

## 2 · 心智模型

### 类比:CSS 类名 vs HTML 属性

HTML 早期:`<font color="red">`——颜色硬编码在 HTML。

CSS 引入:`<span class="warning">`,CSS 定义 `.warning { color: red; }`——颜色数据驱动。

HHT 同理。代码不再硬编码 tag,改成从 HHT 读。

### 数据驱动 vs 硬编码的工程权衡

数据驱动不是"万能药"。某些场景硬编码更好:

**硬编码适合**:
- **变化少的常量**:`PI`、`MAX_UINT32`、物理常量
- **性能关键的内层循环**:enum match 比 hashmap 查找快
- **类型安全要求高的 API**:`fn draw(b: BitmapType)` 比 `fn draw(b: u32)` 安全
- **编译时检查需要**:enum 编译时检查穷尽性,字符串运行时才发现 typo

**数据驱动适合**:
- **频繁变化的内容**:资产、配置、关卡
- **非程序员要编辑的**:美术、策划
- **跨进程共享的**:editor 和 game 共用
- **可配置的**:不同模式、不同关卡用不同集合

权衡:数据驱动加运行时开销(查 ID、解析文件),但灵活。性能关键路径可用**代码生成**兜底——从 HHT 编译时生成 Rust 代码,既有数据驱动又有类型安全:

```rust
// build.rs:编译时读 HHT,生成 Rust 代码
use std::env;
use std::fs;

fn main() {
    let hht = fs::read_to_string("assets.hht").unwrap();
    let mut out = String::new();
    out.push_str("// Auto-generated from assets.hht\n");
    out.push_str("pub mod tags {\n");
    // 解析 HHT,生成 pub const SWORD: u32 = 0;
    // ...
    out.push_str("}\n");
    
    let out_dir = env::var("OUT_DIR").unwrap();
    fs::write(format!("{}/tags.rs", out_dir), out).unwrap();
}
```

主代码:
```rust
mod tags {
    include!(concat!(env!("OUT_DIR"), "/tags.rs"));
}

// 用 tags::SWORD(编译时检查)
fn draw(b: u32) { /* ... */ }
draw(tags::SWORD);    // 类型安全
```

这是 Rust 工业级实践。Casey 不用(教学),但工业项目用。

### 文件格式选择:INI vs JSON vs TOML vs YAML vs CSV vs 二进制

HHT 用 INI 风格(简单 key=value + section)。其他选择:

**JSON**:Web 标准,结构化。优点:成熟库(serde_json),IDE 集成好。缺点:没注释、没多行字符串、冗长。

**TOML**:Rust 社区偏好(Cargo.toml 用)。优点:注释、多行、人友好。缺点:嵌套结构表达差(用 `[a.b.c]` 表达嵌套)。

**YAML**:超可读。优点:注释、引用、复杂结构。缺点:spec 极复杂(500+ 页),parser 难写,security bug 多。

**XML**:企业级。优点:schema 强、XSD 验证。缺点:冗长(`<entity><name>hero</name></entity>`)。

**CSV**:表格。优点:Excel 兼容。缺点:无嵌套。

**二进制 + schema**:Protobuf、FlatBuffers、Cap'n Proto。优点:紧凑、快。缺点:不可读、需要 schema 编译。

Casey 选 INI(最简单)。工业项目选 TOML 或 JSON 居多。

### Tag ID 系统:用 u32 替代字符串

每个 tag 一个唯一 ID(u32)。代码用 ID,不用字符串(字符串比较慢):

```rust
// 慢:每次比较字符串
fn lookup(name: &str) -> &Asset {
    for (n, a) in &assets {
        if n == name { return a; }    // O(n) × 每次字符串比较
    }
}

// 快:用 u32 ID
fn lookup(id: TagId) -> &Asset {
    &assets[id.0 as usize]    // O(1)
}
```

Tag ID 数据库提供双向查:
- `name → id`:`db.lookup("bitmaps", "sword") → TagId(42)`
- `id → name`:`db.name_of(TagId(42)) → ("bitmaps", "sword")`

启动时 build 这个 database(map),运行时 O(1) 查找。这是 Unity、Unreal 的 Gameplay Tags 系统的核心。

### Section / Namespace

HHT 用 section 分组:

```
[bitmaps]
sword

[sounds]
sword_swing
```

`sword` 在 bitmaps section,`sword_swing` 在 sounds section。**两个 section 内的名字独立**(sword 在 bitmaps 和 sword 在 sounds 是不同 tag)。

ID 系统两种选择:
- **全局唯一 ID**:`(section, name) → u32` 单调递增。所有 section 共享 ID 空间。
- **Section 内独立 ID**:`(section, name) → (section_id, local_id)`。每 section 有自己 ID 空间。

Casey 用全局唯一(简单)。工业级可能用 section 内独立(便于删 section 重用 ID)。

### Lv1 · 概念辨析

**题**:数据驱动 vs 硬编码,各自何时用?

**参考解答**:

**硬编码适合**:

- 变化少的(数学常量 PI)

**数据驱动适合**:

### Lv2 · 动手实践

**题**:实现最小 HHT 解析器。给定 INI-like 文本,解析出 sections 和 tags。

完成标准:`cargo run` 解析示例 HHT,输出结构化数据。

**参考解答**:

```rust
use std::collections::HashMap;

#[derive(Debug, Default)]
struct HhtFile {
    sections: HashMap<String, Vec<String>>,
}

impl HhtFile {
    fn add_tag(&mut self, section: &str, tag: &str) {
        self.sections.entry(section.into()).or_default().push(tag.into());
    }
    
    fn tags_in(&self, section: &str) -> &[String] {
        self.sections.get(section).map(|v| v.as_slice()).unwrap_or(&[])
    }
}

fn parse_hht(text: &str) -> HhtFile {
    let mut file = HhtFile::default();
    let mut current_section = String::new();
    
    for line in text.lines() {
        let line = line.trim();
        if line.is_empty() || line.starts_with('#') {
            continue;
        }
        
        if line.starts_with('[') && line.ends_with(']') {
            current_section = line[1..line.len()-1].to_string();
        } else if !current_section.is_empty() {
            file.add_tag(&current_section, line);
        }
    }
    
    file
}

fn main() {
    let hht_text = r#"
# Handmade Hero Tags file
[bitmaps]
player
sword
shield
goblin

[sounds]
footstep
sword_swing
explosion
"#;
    
    let file = parse_hht(hht_text);
    
    println!("=== Parsed HHT ===\n");
    for (section, tags) in &file.sections {
        println!("[{}]", section);
        for tag in tags {
            println!("  {}", tag);
        }
        println!();
    }
    
    // Tag ID 系统演示
    println!("=== Tag ID 系统 ===\n");
    let mut next_id = 0u32;
    let mut name_to_id: HashMap<String, u32> = HashMap::new();
    
    for tag in file.tags_in("bitmaps") {
        name_to_id.insert(tag.clone(), next_id);
        next_id += 1;
    }
    for tag in file.tags_in("sounds") {
        name_to_id.insert(tag.clone(), next_id);
        next_id += 1;
    }
    
    for (name, id) in &name_to_id {
        println!("  {} = {}", name, id);
    }
    
    println!("\n查找 'sword': {:?}", name_to_id.get("sword"));
    println!("查找 'explosion': {:?}", name_to_id.get("explosion"));
    println!("查找 'missing': {:?}", name_to_id.get("missing"));
}

#[cfg(test)]
mod tests {
    use super::*;
    
    #[test]
    fn test_parse_basic() {
        let text = "[section1]\ntag1\ntag2\n";
        let file = parse_hht(text);
        assert_eq!(file.tags_in("section1"), &["tag1".to_string(), "tag2".to_string()]);
    }
    
    #[test]
    fn test_parse_comments() {
        let text = "# comment\n[s]\n# also comment\ntag\n";

    }

        let text = "[a]\nt1\n[b]\nt2\n";
        let file = parse_hht(text);
        assert_eq!(file.tags_in("a"), &["t1".to_string()]);
```

## 8 · Rust / Arch 落地代码

下面是 Day 509 完整的 HHT 系统。

```rust
// ============================================================
// Day 509 · 创建标签文件(HHT)
// ============================================================

use std::collections::HashMap;
use std::fmt;

// ============================================================
// HHT 文件
// ============================================================

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
struct TagId(u32);

impl fmt::Display for TagId {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "TagId({})", self.0)
    }
}

#[derive(Debug, Default, Clone)]
struct HhtFile {
    sections: HashMap<String, Vec<String>>,
}

impl HhtFile {
    fn new() -> Self { Self::default() }
    
    fn add_tag(&mut self, section: &str, tag: &str) {
        self.sections.entry(section.into()).or_default().push(tag.into());
    }
    
    fn tags_in(&self, section: &str) -> &[String] {
        self.sections.get(section).map(|v| v.as_slice()).unwrap_or(&[])
    }
    
    fn sections(&self) -> &HashMap<String, Vec<String>> { &self.sections }
    
    fn all_tags(&self) -> Vec<(String, String)> {
        let mut result = Vec::new();
        for (section, tags) in &self.sections {
            for tag in tags {
                result.push((section.clone(), tag.clone()));
            }
        }
        result
    }
}

// ============================================================

#[derive(Debug)]
enum ParseError {
    UnexpectedChar(String, usize),
    SectionOutsideScope(String),
}

impl fmt::Display for ParseError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ParseError::UnexpectedChar(c, line) => write!(f, "Unexpected char '{}' at line {}", c, line),
            ParseError::SectionOutsideScope(s) => write!(f, "Tag '{}' outside any section", s),
        }
    }
}

fn parse_hht(text: &str) -> Result<HhtFile, ParseError> {
    let mut file = HhtFile::new();
    let mut current_section: Option<String> = None;
    
    for (line_num, line) in text.lines().enumerate() {
        let line = line.trim();
        
        // 空 / 注释
        if line.is_empty() || line.starts_with('#') {
            continue;
        }
        
        // Section header
        if line.starts_with('[') {
            if !line.ends_with(']') {
                return Err(ParseError::UnexpectedChar(line.into(), line_num));
            }
            current_section = Some(line[1..line.len()-1].to_string());
            continue;
        }
        
        // Tag
        let section = current_section.as_ref()
            .ok_or_else(|| ParseError::SectionOutsideScope(line.into()))?;
        
        // 简单校验:tag 只允许字母数字下划线
        if !line.chars().all(|c| c.is_alphanumeric() || c == '_') {
            return Err(ParseError::UnexpectedChar(line.into(), line_num));
        }
        
        file.add_tag(section, line);
    }
    
    Ok(file)
}

// ============================================================
// Tag database(构建 ID 系统)
// ============================================================

struct TagDatabase {
    name_to_id: HashMap<(String, String), TagId>,    // (section, name) → ID
    id_to_name: HashMap<TagId, (String, String)>,
    next_id: u32,
}

impl TagDatabase {
    fn new() -> Self {
        Self {
            name_to_id: HashMap::new(),
            id_to_name: HashMap::new(),
            next_id: 0,
        }
    }
    
    fn from_hht(hht: &HhtFile) -> Self {
        let mut db = Self::new();
        for (section, tags) in hht.sections() {
            for tag in tags {
                db.register(section, tag);
            }
        }
        db
    }
    
    fn register(&mut self, section: &str, name: &str) -> TagId {
        let key = (section.into(), name.into());
        if let Some(id) = self.name_to_id.get(&key) {
            return *id;
        }
        let id = TagId(self.next_id);
        self.next_id += 1;
        self.name_to_id.insert(key.clone(), id);
        self.id_to_name.insert(id, key);
        id
    }
    
    fn lookup(&self, section: &str, name: &str) -> Option<TagId> {
        self.name_to_id.get(&(section.into(), name.into())).copied()
    }
    
    fn name_of(&self, id: TagId) -> Option<&(String, String)> {
        self.id_to_name.get(&id)
    }
    
    fn len(&self) -> usize { self.name_to_id.len() }
}

impl fmt::Display for TagDatabase {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        writeln!(f, "TagDatabase ({} tags):", self.len())?;
        for (id, (section, name)) in &self.id_to_name {
            writeln!(f, "  {} [{}]{}", id, section, name)?;
        }
        Ok(())
    }
}

player

explosion
hit

[entities]

"#;

            println!("=== Parsed HHT ===\n");
            for (section, tags) in hht.sections() {
                println!("[{}] ({} tags)", section, tags.len());
                for tag in tags {
                    println!("  - {}", tag);
                }
                println!();
            }
            
            // 构建 tag database
            let db = TagDatabase::from_hht(&hht);
            println!("=== Tag Database ===\n");
            println!("{}", db);
            
            // 查找示例
            println!("=== 查找示例 ===\n");
            for (section, name) in [("bitmaps", "sword"), ("sounds", "explosion"), ("bitmaps", "missing")] {
                match db.lookup(section, name) {
                    Some(id) => println!("  [{}]{} = {}", section, name, id),
                    None => println!("  [{}]{} = NOT FOUND", section, name),
                }
            }
            
            // 模拟代码使用 tag
            println!("\n=== 代码使用 tag(模拟)===");
            
            let sword_id = db.lookup("bitmaps", "sword").unwrap();
            let explosion_id = db.lookup("sounds", "explosion").unwrap();
            
            println!("render_bitmap({})", sword_id);
            println!("play_sound({})", explosion_id);
            
            println!("\n(原本硬编码 BitmapType::Sword,现在用 TagId,数据驱动)");
        }
        Err(e) => println!("Parse error: {}", e),
    }
    
    // 错误情况
    println!("\n=== 错误处理 ===\n");
    
    let bad_text = "tag_outside_section\n[s]\nvalid_tag\n";
    match parse_hht(bad_text) {
        Ok(_) => println!("不应该 OK"),
        Err(e) => println!("错误捕获: {}", e),
    }
    
    let bad_char = "[s]\nbad-tag!\n";
    match parse_hht(bad_char) {
        Ok(_) => println!("不应该 OK"),
        Err(e) => println!("错误捕获(非法字符): {}", e),
    }
    
    // 从文件读
    println!("\n=== 从文件读(模拟)===");
    let path = "/tmp/test.hht";
    std::fs::write(path, hht_text).unwrap();

        Ok(text) => {
            let hht = parse_hht(&text).unwrap();
            println!("从 {:?} 读 HHT,共 {} 个 section", path, hht.sections().len());
        }
        Err(e) => println!("读失败: {}", e),
    }
    
    std::fs::remove_file(path).ok();
}
```
