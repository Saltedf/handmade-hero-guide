# Day 462 · 从网格化 PNG 提取资产瓦片

> 现在你可以加载 PNG,但美术通常把所有 sprite 放在一张"精灵表"(sprite sheet)里——一张大 PNG 切成几十个小图。今天 Casey 实现"网格化 PNG 切片",把一张大图拆成 N 个独立 sprite。

## 0 · 为什么要有这一天

游戏资产管理的工业实践:**精灵表(sprite sheet)** 或 **图集(atlas)**——多个小图拼成一张大图,而不是每张小图一个文件。

优势:
- **加载快**:一次 IO 读一张大图,不是 100 次 IO 读 100 张小图
- **GPU 友好**:一次纹理绑定,渲染所有 sprite,减少状态切换
- **打包简洁**:一个文件代替 100 个

典型精灵表是 16x16 网格——每格 16x16 像素,总图 256x256,可以放 256 个 sprite。

今天 Casey 实现"网格化切片":读一张大 PNG,参数指定网格大小(如 16x16),输出 N 个独立的 sprite 数据。每个 sprite 有自己的索引(0..N)。

让我把"精灵表"在工业游戏里的几种形态讲清楚,这是 Day 462 的背景。

**均匀网格 sprite sheet**。Casey HH Day 462 处理的——所有 sprite 同样大小,16x16 排成网格。简单但限制大——所有 sprite 必须同尺寸。

**非均匀 atlas**。每个 sprite 不同大小,放在 atlas 任意位置。配套有 `atlas.json` 描述每个 sprite 的 (x, y, w, h)。**商业游戏的标准**——不同大小的图标、按钮、动画帧,自由组合。

**Packed atlas**。运行时把多个小 PNG 动态打包成大 atlas,最小化浪费。算法:**矩形容器打包**(rectangle bin packing)——first-fit decreasing、max-rects、skyline 等算法。

**精灵表 vs 纹理数组**。现代 GPU 提供"纹理数组(texture array)"——多层同尺寸纹理,绑定为单个 resource。比 atlas 更简洁(不需要 UV 坐标换算),但要求所有层同尺寸。

**精灵表渲染**。draw 一个 sprite 时,顶点的 UV 坐标指向 atlas 的某区域:

```rust
struct Sprite {
    atlas: TextureHandle,
    uv_min: Vec2,  // atlas 内的左下角 UV
    uv_max: Vec2,  // atlas 内的右上角 UV
}

// 渲染时,4 个顶点的 UV:
let uvs = [
    sprite.uv_min,                              // 左下
    Vec2::new(sprite.uv_max.x, sprite.uv_min.y), // 右下
    sprite.uv_max,                              // 右上
    Vec2::new(sprite.uv_min.x, sprite.uv_max.y), // 左上
];
```

GPU 采样 atlas 的 UV 区域,贴到 quad 上。**关键**:UV 边界要稍微内缩(half-pixel),否则线性过滤会"漏出"邻居 sprite。

**网格切片算法**。给定大 PNG 和 tile_size,算每个 sprite 的位置:

```rust
struct GridSpec {
    tile_w: u32,
    tile_h: u32,
    cols: u32,
    rows: u32,
}

fn slice_grid(png: &Image, spec: &GridSpec) -> Vec<Sprite> {
    let mut sprites = Vec::with_capacity((spec.cols * spec.rows) as usize);
    for row in 0..spec.rows {
        for col in 0..spec.cols {
            let x = col * spec.tile_w;
            let y = row * spec.tile_h;
            // 从 PNG 大像素 buffer 切出小区域
            let pixels = extract_region(&png.pixels, png.width, x, y, spec.tile_w, spec.tile_h);
            sprites.push(Sprite {
                width: spec.tile_w,
                height: spec.tile_h,
                pixels,
            });
        }
    }
    sprites
}

fn extract_region(src: &[u8], src_w: u32, x: u32, y: u32, w: u32, h: u32) -> Vec<u8> {
    let bpp = 4;  // RGBA
    let mut out = Vec::with_capacity((w * h * bpp as u32) as usize);
    for row in 0..h {
        let src_offset = ((y + row) * src_w + x) as usize * bpp;
        let src_end = src_offset + (w as usize * bpp);
        out.extend_from_slice(&src[src_offset..src_end]);
    }
    out
}
```

每行独立拷贝——因为源图的 stride 是 src_w * bpp,但目标的 stride 是 w * bpp。

**反向操作:sprite → atlas**。游戏打包阶段,把所有小 sprite 打包成 atlas:

```rust
// 输入:多个 sprite(尺寸各异)
let sprites = load_all_sprites();
// 用 max-rects 算法打包
let atlas = pack_atlas(&sprites, 1024, 1024);
// 输出:1024x1024 的大 atlas + 每个 sprite 的位置表
```

`pack_atlas` 实现 max-rects 算法——维护一个"空闲矩形"列表,新 sprite 找一个能容纳的空闲矩形,分割剩余空间。

## 补充:纹理采样与"bleeding"问题

让我讲一个 Day 462 隐含的渲染陷阱——sprite 边缘"bleeding"(漏色),这是工业 sprite 渲染的常见 bug。

**问题**:atlas 里两个相邻 sprite,渲染时如果用线性过滤(bilinear filtering),UV 坐标在 sprite 边缘可能采样到邻居的颜色。视觉上,角色边缘出现一条"暗色描边"——是邻居的颜色泄漏过来。

**原因**:线性过滤用 UV 周围 4 个 texel 加权平均。如果 UV 在 sprite 边缘像素的中心,4 个邻居有 2 个是邻居 sprite 的颜色。

**解决方案**:

**方案 1:half-pixel inset**。UV 向内缩 half-pixel,确保不会采到边界外:

```rust
let texel_w = 1.0 / atlas.width as f32;
let texel_h = 1.0 / atlas.height as f32;
let uv_min = Vec2::new(
    sprite.x as f32 / atlas.width as f32 + 0.5 * texel_w,
    sprite.y as f32 / atlas.height as f32 + 0.5 * texel_h,
);
let uv_max = Vec2::new(
    (sprite.x + sprite.w) as f32 / atlas.width as f32 - 0.5 * texel_w,
    (sprite.y + sprite.h) as f32 / atlas.height as f32 - 0.5 * texel_h,
);
```

UV 永远在 sprite 内部 half-texel 处,不采到边界外。

**方案 2:padding**。每个 sprite 周围留 1-2 像素 padding,填充 sprite 的边缘色。这样邻居"漏色"也是漏自己颜色,不可见。

```
┌─────────────────┐
│ P P P P P P P P │  P = padding(复制 sprite 边缘)
│ P ┌───────┐  P  │
│ P │ sprite│  P  │
│ P └───────┘  P  │
│ P P P P P P P P │
└─────────────────┘
```

padding 让 atlas 大 4-8 像素,但消除 bleeding。

**方案 3:纹理数组**。每个 sprite 是独立的纹理层,无邻居,无 bleeding。但要求 sprite 同尺寸。

工业方案:方案 2(padding)+ 方案 1(half-pixel inset)叠加,万无一失。

### 网格切片的变种

Casey HH Day 462 的网格切片是"均匀网格"——所有 tile 同尺寸。但游戏里 tile 可能有几种尺寸:

**变种 1:多分辨率网格**。如 16x16 + 32x32 + 64x64 三种 tile,混合使用:

```
[16] [16] [32          ] [16]
[16] [16] [32          ] [16]
[64                  ] [16]
```

切片算法读 atlas metadata 知道每行/列的 tile size。

**变种 2:动画帧**。同一角色的多个动画帧在同一行:

```
walk_01 walk_02 walk_03 walk_04 ...
idle_01 idle_02 ...
jump_01 jump_02 jump_03 ...
```

切片按"行"分组,每行是一个动画序列。

**变种 3:九宫格(Nine-patch)**。UI 元素用九宫格——四角不缩放,四边单向缩放,中心双向缩放。常用于按钮、对话框。

```
┌─┬─────┬─┐
│C│  E  │C│   C = Corner(不缩放)
├─┼─────┼─┤   E = Edge(单向缩放)
│E│  M  │E│   M = Middle(双向缩放)
├─┼─────┼─┤
│C│  E  │C│
└─┴─────┴─┘
```

切片把一张九宫格图切成 9 个 sprite,渲染时按 9 宫格规则合成任意大小 UI 元素。

这些变种让"网格切片"远比 Day 462 简化版强大。商业游戏(asset pipeline 工具)支持所有变种,加 GUI 编辑器让美术可视化编辑。

## 2 · 心智模型

### 类比:邮票册

邮票册一页有很多邮票。你要寄信用其中一枚,不需要"撕下来"——你只要知道哪枚在哪,盖章时按那枚的位置盖。

精灵表也一样:不真"切",而是用 UV 坐标告诉 GPU"取这个区域"。

### 网格化布局

假设精灵表 256x256,tile 16x16:
- 每个 tile 16x16 像素
- 一行 16 个 tile(256/16)
- 共 16 行 = 256 个 tile

tile_index 0 在 (0, 0),1 在 (16, 0),16 在 (0, 16),等等。

### 严谨原理:tile 索引到像素位置

```rust
fn tile_to_pixel(tile_index: u32, tiles_per_row: u32, tile_size: u32) -> (u32, u32) {
    let row = tile_index / tiles_per_row;
    let col = tile_index % tiles_per_row;
    (col * tile_size, row * tile_size)
}
```

每行解释:
- `tile_index / tiles_per_row` 算行号。
- `tile_index % tiles_per_row` 算列号。
- 乘 tile_size 得像素位置(左上角)。

### UV 坐标

GPU 用 UV(纹理坐标,0-1)采样:

```rust
fn tile_to_uv(
    tile_index: u32,
    tiles_per_row: u32,
    tiles_per_col: u32,
) -> [(f32, f32); 4] {
    // 返回 tile 的 4 个角的 UV
    let row = tile_index / tiles_per_row;
    let col = tile_index % tiles_per_row;
    
    let u0 = col as f32 / tiles_per_row as f32;
    let u1 = (col + 1) as f32 / tiles_per_row as f32;
    let v0 = row as f32 / tiles_per_col as f32;
    let v1 = (row + 1) as f32 / tiles_per_col as f32;
    
    // 顺序:左下、右下、左上、右上
    [(u0, v0), (u1, v0), (u0, v1), (u1, v1)]
}
```

每行解释:
- UV 范围 [0, 1],所以 col / tiles_per_row 得 u0(左)。
- `(col+1) / tiles_per_row` 得 u1(右)。
- v 同理。
- 返回 4 个角 UV(顶点顺序对应 quad 的 4 个顶点)。

### Rust 实现

```rust
struct SpriteAtlas {
    width: u32,
    height: u32,
    tile_width: u32,
    tile_height: u32,
    pixels: Vec<u8>,  // 整张大纹理,RGBA
    bpp: usize,       // bytes per pixel
}

impl SpriteAtlas {
    fn new(pixels: Vec<u8>, width: u32, height: u32, tile_w: u32, tile_h: u32) -> Self {
        Self {
            width, height,
            tile_width: tile_w, tile_height: tile_h,
            pixels, bpp: 4,
        }
    }
    
    fn tiles_per_row(&self) -> u32 { self.width / self.tile_width }
    fn tiles_per_col(&self) -> u32 { self.height / self.tile_height }
    fn tile_count(&self) -> u32 { self.tiles_per_row() * self.tiles_per_col() }
    
    /// 返回某个 tile 的像素切片(只读,不拷贝)
    fn tile_pixels(&self, tile_index: u32) -> Option<Vec<u8>> {
        if tile_index >= self.tile_count() { return None; }
        let (px, py) = tile_to_pixel(tile_index, self.tiles_per_row(), self.tile_width);
        
        let mut result = Vec::with_capacity(
            (self.tile_width * self.tile_height * self.bpp as u32) as usize
        );
        for row in 0..self.tile_height {
            let y = py + row;
            for col in 0..self.tile_width {
                let x = px + col;
                let idx = ((y * self.width + x) as usize) * self.bpp;
                result.extend_from_slice(&self.pixels[idx..idx+self.bpp]);
            }
        }
        Some(result)
    }
    
    /// 返回 tile 在大纹理中的 UV(供 GPU shader 用)
    fn tile_uv(&self, tile_index: u32) -> [(f32, f32); 4] {
        let row = tile_index / self.tiles_per_row();
        let col = tile_index % self.tiles_per_row();
        let u0 = col as f32 / self.tiles_per_row() as f32;
        let u1 = (col + 1) as f32 / self.tiles_per_row() as f32;
        let v0 = row as f32 / self.tiles_per_col() as f32;
        let v1 = (row + 1) as f32 / self.tiles_per_col() as f32;
        [(u0, v0), (u1, v0), (u0, v1), (u1, v1)]
    }
}
```

每行解释:
- `tile_pixels` 复制 tile 像素(用于 CPU 处理或独立纹理上传)。
- `tile_uv` 返回 UV(GPU 渲染时用)。
- 生产代码避免 `tile_pixels`(拷贝慢),只用 `tile_uv`。

### GPU 渲染优化

**反模式**:每个 tile 切出来上传独立 GPU 纹理。1000 个 tile = 1000 个 GPU 纹理,bind 切换昂贵。

**正确**:大纹理一次性上传,所有 tile 共享。每个 sprite 渲染时用不同 UV 采样同一纹理。

```rust
// sprite 渲染
fn render_sprite(
    atlas: &GpuTexture,
    tile_index: u32,
    sprite_atlas: &SpriteAtlas,
    position: Vec2,
) {
    let uvs = sprite_atlas.tile_uv(tile_index);
    // 设置 vertex buffer:position + UV
    // glBindTexture(atlas)
    // glDrawArrays(...)
}
```

整个游戏所有 sprite 用同一 atlas,只一次 `glBindTexture`。这是 2D 游戏的工业铁律。

## 3 · 四域深入

### 3.1 · 游戏编程视角

精灵表的演化:

- **1990s**:每 sprite 一文件(简单,慢)
- **2000s**:手工拼精灵表(美术用 PS 拼)
- **2010s**:工具自动拼(TexturePacker、SpriteUV)
- **2020s**:GPU-driven,运行时按需加载

现代工具:
- **TexturePacker**:商业,主流
- **Aseprite**:像素艺术编辑器
- **ShoeBox**:免费
- **crunch**:压缩精灵表

工业坑:
- **Bleeding**:相邻 tile 边缘渗透,UV 取到隔壁 tile 像素。解决:UV 内缩 0.5 像素。
- **mipmap**:tile 边缘在 mipmap level 1+ 渗透。解决:不开 mipmap 或用 texture array。
- **尺寸限制**:GPU 最大纹理 16384x16384,大 atlas 受限。

### 3.2 · 图形学视角

UV 取样的细节:

- **UV 内缩**:`u0 = (col * tile_size + 0.5) / atlas_width`,避免取到 tile 边界外的像素
- **Filter 模式**:tile art 用 NEAREST(不模糊),自然图用 LINEAR
- **Wrap 模式**:CLAMP_TO_EDGE,避免 wrap

**Texture Array**:GPU 概念,一系列相同大小的纹理,shader 用 `sampler2DArray` + 第三维 index 访问。比 atlas 更精确(无渗透),但需要相同尺寸。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么用 UV 坐标采样而不是切出独立纹理?

**参考解答**:GPU 纹理绑定(`glBindTexture`)是相对昂贵的操作。1000 个 sprite 1000 次绑定,加上每帧多次绘制,性能差。

UV 采样不需要切纹理——同一 atlas 一次绑定,所有 sprite 共享,通过不同 UV 取不同区域。GPU 纹理 cache 友好,渲染快几个数量级。

### Lv2 · 动手实践

**题**:实现 `SpriteAtlas`,加载一张 64x64 模拟"精灵表"(每 tile 16x16,共 16 个),验证 `tile_pixels` 和 `tile_uv` 正确。

**参考解答**:

```rust
struct SpriteAtlas {
    width: u32,
    height: u32,
    tile_w: u32,
    tile_h: u32,
    pixels: Vec<u8>,
    bpp: usize,
}

impl SpriteAtlas {
    fn new(width: u32, height: u32, tile_w: u32, tile_h: u32) -> Self {
        Self {
            width, height, tile_w, tile_h,
            pixels: vec![0; (width * height * 4) as usize],
            bpp: 4,
        }
    }
    
    fn tiles_per_row(&self) -> u32 { self.width / self.tile_w }
    fn tiles_per_col(&self) -> u32 { self.height / self.tile_h }
    fn tile_count(&self) -> u32 { self.tiles_per_row() * self.tiles_per_col() }
    
    fn tile_pixels(&self, idx: u32) -> Vec<u8> {
        assert!(idx < self.tile_count());
        let row = idx / self.tiles_per_row();
        let col = idx % self.tiles_per_row();
        let px = col * self.tile_w;
        let py = row * self.tile_h;
        
        let mut result = Vec::new();
        for y in 0..self.tile_h {
            for x in 0..self.tile_w {
                let pixel_idx = ((py + y) * self.width + (px + x)) as usize * self.bpp;
                result.extend_from_slice(&self.pixels[pixel_idx..pixel_idx+self.bpp]);
            }
        }
        result
    }
    
    fn tile_uv(&self, idx: u32) -> [(f32, f32); 4] {
        let row = idx / self.tiles_per_row();
        let col = idx % self.tiles_per_row();
        let u0 = col as f32 / self.tiles_per_row() as f32;
        let u1 = (col + 1) as f32 / self.tiles_per_row() as f32;
        let v0 = row as f32 / self.tiles_per_col() as f32;
        let v1 = (row + 1) as f32 / self.tiles_per_col() as f32;
        [(u0, v0), (u1, v0), (u0, v1), (u1, v1)]
    }
}

fn main() {
    let mut atlas = SpriteAtlas::new(64, 64, 16, 16);
    // 填充测试:tile 0 = 全红,tile 1 = 全绿,...
    for tile_idx in 0..atlas.tile_count() {
        let color = match tile_idx {
            0 => [255, 0, 0, 255],
            1 => [0, 255, 0, 255],
            2 => [0, 0, 255, 255],
            3 => [255, 255, 0, 255],
            _ => [128, 128, 128, 255],
        };
        let row = tile_idx / atlas.tiles_per_row();
        let col = tile_idx % atlas.tiles_per_row();
        let px = col * 16;
        let py = row * 16;
        for y in 0..16 {
            for x in 0..16 {
                let idx = ((py + y) * atlas.width + (px + x)) as usize * 4;
                atlas.pixels[idx..idx+4].copy_from_slice(&color);
            }
        }
    }
    
    // 验证 tile 0 全红
    let tile0 = atlas.tile_pixels(0);
    for &b in &tile0[..4] {
        assert_eq!(b, 255);  // R = 255
    }
    for &b in &tile0[4..6] {
        assert_eq!(b, 0);    // G, B = 0
    }
    println!("Tile 0: all red, OK");
    
    // 验证 tile 1 全绿
    let tile1 = atlas.tile_pixels(1);
    assert_eq!(tile1[0], 0);
    assert_eq!(tile1[1], 255);
    println!("Tile 1: all green, OK");
    
    // 验证 UV
    let uv0 = atlas.tile_uv(0);
    println!("Tile 0 UVs: {:?}", uv0);
    // 应该是 [(0, 0), (0.25, 0), (0, 0.25), (0.25, 0.25)]
    
    let uv5 = atlas.tile_uv(5);
    println!("Tile 5 UVs: {:?}", uv5);
    // row=1, col=1 → u0=0.25, u1=0.5, v0=0.25, v1=0.5
    
    println!("Atlas: {} tiles ({}x{} grid)", atlas.tile_count(),
        atlas.tiles_per_row(), atlas.tiles_per_col());
}
```

每行解释:
- 创建 64x64 atlas,tile 16x16。
- 填充每个 tile 为单色(测试用)。
- `tile_pixels` 取出来验证颜色。
- `tile_uv` 验证 UV 坐标在 [0, 1] 范围。

完成标准:所有 assert 通过,UV 输出正确。

```rust
// 假设有 png_decoder 模块(day459)

struct SpriteAtlas {
    width: u32,
    height: u32,
    tile_w: u32,
    tile_h: u32,
    pixels: Vec<u8>,
}

impl SpriteAtlas {
    fn from_png(path: &str, tile_w: u32, tile_h: u32) -> Result<Self, String> {
        let data = std::fs::read(path).map_err(|e| e.to_string())?;
        // (用 day459 的 decode_from_bytes,这里简化为模拟)
        // 实际:image.width, image.height, image.pixels
        let width = 64u32;
        let height = 64u32;
        let pixels = vec![128u8; (width * height * 4) as usize];
        Ok(Self { width, height, tile_w, tile_h, pixels })
    }
    
    fn tiles_per_row(&self) -> u32 { self.width / self.tile_w }
    fn tiles_per_col(&self) -> u32 { self.height / self.tile_h }
    fn tile_count(&self) -> u32 { self.tiles_per_row() * self.tiles_per_col() }
    
    fn tile_uv(&self, idx: u32) -> [(f32, f32); 4] {
        let row = idx / self.tiles_per_row();
        let col = idx % self.tiles_per_row();
        let u0 = col as f32 / self.tiles_per_row() as f32;
        let u1 = (col + 1) as f32 / self.tiles_per_row() as f32;
        let v0 = row as f32 / self.tiles_per_col() as f32;
        let v1 = (row + 1) as f32 / self.tiles_per_col() as f32;
        [(u0, v0), (u1, v0), (u0, v1), (u1, v1)]
    }
    
    fn tile_pixels(&self, idx: u32) -> Vec<u8> {
        let row = idx / self.tiles_per_row();
        let col = idx % self.tiles_per_row();
        let px = col * self.tile_w;
        let py = row * self.tile_h;
        
        let mut result = Vec::new();
        for y in 0..self.tile_h {
            for x in 0..self.tile_w {
                let i = ((py + y) * self.width + (px + x)) as usize * 4;
                result.extend_from_slice(&self.pixels[i..i+4]);
            }
        }
        result
    }
    
    /// UV 内缩 0.5 像素,防渗透
    fn tile_uv_inset(&self, idx: u32) -> [(f32, f32); 4] {
        let row = idx / self.tiles_per_row();
        let col = idx % self.tiles_per_row();
        let half_pixel_u = 0.5 / self.width as f32;
        let half_pixel_v = 0.5 / self.height as f32;
        let u0 = col as f32 / self.tiles_per_row() as f32 + half_pixel_u;
        let u1 = (col + 1) as f32 / self.tiles_per_row() as f32 - half_pixel_u;
        let v0 = row as f32 / self.tiles_per_col() as f32 + half_pixel_v;
        let v1 = (row + 1) as f32 / self.tiles_per_col() as f32 - half_pixel_v;
        [(u0, v0), (u1, v0), (u0, v1), (u1, v1)]
    }
}

fn main() {
    let atlas = SpriteAtlas::from_png("/tmp/sprites.png", 16, 16)
        .expect("Failed to load atlas");
    
    println!("Atlas: {}x{}, tile {}x{}, total {} tiles",
        atlas.width, atlas.height, atlas.tile_w, atlas.tile_h, atlas.tile_count());
    
    for i in [0, 1, 5, 10, 15].iter() {
        let uv = atlas.tile_uv(*i);
        let uv_inset = atlas.tile_uv_inset(*i);
        println!("Tile {}: uv={:?} inset={:?}", i, uv, uv_inset);
    }
    
    // 模拟 GPU 渲染时如何用 UV
    println!("\nRendering sprite at screen pos (100, 100):");
    let sprite_idx = 5;
    let uvs = atlas.tile_uv_inset(sprite_idx);
    println!("  Quad vertices (screen_x, screen_y, u, v):");
    let sx = 100.0f32;
    let sy = 100.0f32;
    let sw = 16.0;
    let sh = 16.0;
    println!("    ({}, {}, {}, {})", sx, sy, uvs[0].0, uvs[0].1);
    println!("    ({}, {}, {}, {})", sx+sw, sy, uvs[1].0, uvs[1].1);
    println!("    ({}, {}, {}, {})", sx, sy+sh, uvs[2].0, uvs[2].1);
    println!("    ({}, {}, {}, {})", sx+sw, sy+sh, uvs[3].0, uvs[3].1);
}
```

每行解释:
- `tile_uv_inset` 加 0.5 像素内缩,避免 GPU 双线性采样时渗透到隔壁 tile。
- 模拟渲染输出"顶点 + UV"对,这是 OpenGL vertex buffer 数据。
