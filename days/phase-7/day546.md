# Day 546 · GPU MIP 映射

> 远处的草变成"闪烁的噪点"——这是 mipmapping 缺失的经典症状。Day 546 Casey 在 GPU 端开启 mipmap 生成,让远处的纹理自动用低分辨率版本,消除闪烁。

## 0 · 为什么要有这一天

先解释 **flickering(闪烁)**。游戏里玩家在远处看一片带纹理的地砖,每次相机轻微移动,某些像素"突然变白"或"突然变黑",一帧一帧变化——这就是 flickering。

为什么会闪?因为远处的地砖在屏幕上**只占几个像素**,但纹理是 512x512。GPU 用 **point sampling(点采样)** 时,只采纹理上一个像素。相机一动,采到的像素位置突变,颜色就跳变。

正确做法是 **downsampling**:把纹理预先缩成 256x256、128x128、64x64... 一系列小版本,远处用小版本(覆盖屏幕 1 个像素时采 1x1 的版本)。这样远处稳定不闪。

这一系列缩小版本就叫 **mipmap**(多级渐远纹理,来自拉丁语 *multum in parvo* "much in little")。

Casey 之前手贴纹理时一直没开 mipmap——因为 BMP 测试阶段不需要。Day 545 加了草,远处闪烁明显,Day 546 必须修。

完成这一天之后,你具备:

- 理解 mipmap 的目的和原理
- 能用 OpenGL/Vulkan API 生成 mipmap
- 知道 anisotropic filtering(各向异性过滤)等高级采样

## 1 · Casey 今天做了什么

Casey 的 GPU 调用大致是:

第一步,加载纹理后,不再只用 level 0(原图),而是**生成完整 mipmap chain**(链)——从 512x512 到 1x1,共 log2(512)+1 = 10 级。

第二步,在 sampler(采样器)里设置 `min_filter = LINEAR_MIPMAP_LINEAR`(也叫 trilinear filtering):近处用线性插值采 level 0,远处线性插值采合适的 level,中间过渡。

第三步,确认 GPU 自动选 level——根据屏幕像素覆盖的纹理区域大小,选最合适的 level。

视频里他演示了开 mipmap 前后的对比:开之前,远处草地闪得像坏电视;开之后,远处平滑像一张油画。

## 2 · 心智模型

### 类比:看远处的风景照

想象你有一张 8K 分辨率的城市航拍图。把它打印成 A4 大,挂在你眼前 30 厘米——你能看清每辆车。现在把它缩小成 A0(放大 4 倍),挂到 30 米外——你只看到一片模糊的色块。

**关键观察**:大脑不会觉得"这张图坏了"——大脑知道远处的东西本来就该模糊。模糊是**正确的视觉信号**,不是缺陷。

Mipmap 就是让 GPU 模仿这件事——预先准备"远处应该看到的模糊版本",远处用之。如果不准备,GPU 强行用 8K 原图采样 1 个像素,结果不连续地跳变,反而**比真实模糊更难看**。

### 严谨展开:mip chain

mip chain(链)是纹理的多个分辨率版本。每个 level 边长减半:

```
Level 0: 512 x 512   (原图,占用 1 MB)
Level 1: 256 x 256   (1/4 MB)
Level 2: 128 x 128   (1/16 MB)
Level 3:  64 x 64    (1/64 MB)
...
Level 9:   1 x 1     (4 bytes)
```

总内存:`sum = 1 + 1/4 + 1/16 + ... ≈ 4/3 * 原图`。**开启 mipmap 多占 33% 内存**,但视觉质量大幅提升。

每级 level 由上一级**降采样**得到——通常 2x2 像素 box filter(取平均):

```rust
fn downsample_2x2(src: &[u8], src_w: usize) -> Vec<u8> {
    let dst_w = src_w / 2;
    let dst_h = src_w / 2;  // 假设正方形
    let mut dst = vec![0u8; dst_w * dst_h * 4];
    for y in 0..dst_h {
        for x in 0..dst_w {
            for c in 0..4 {
                // 4 个源像素平均
                let s = src[(y*2 * src_w + x*2) * 4 + c] as u32
                      + src[(y*2 * src_w + x*2 + 1) * 4 + c] as u32
                      + src[((y*2+1) * src_w + x*2) * 4 + c] as u32
                      + src[((y*2+1) * src_w + x*2 + 1) * 4 + c] as u32;
                dst[(y * dst_w + x) * 4 + c] = (s / 4) as u8;
            }
        }
    }
    dst
}
```

实际 GPU 用更高级的 filter(高斯、Kaiser)以减少锯齿,但 box filter 演示原理。

### GPU 选 level 的公式

GPU 在 vertex shader 里算 `dFdx(uv)` 和 `dFdy(uv)`——纹理坐标在屏幕 x/y 方向的变化率。变化率大(屏幕动一点,UV 跳很多)说明纹理被压缩了(远处),用高 level。变化率小说明近处,用 level 0。

具体公式(`λ` 是 level):

```
ρ_x = ||dFdx(uv) * textureSize||
ρ_y = ||dFdy(uv) * textureSize||
λ = log2(max(ρ_x, ρ_y))
level = floor(λ + 0.5)  // 或在两个 level 间线性插值(trilinear)
```

这个计算是 GPU 内部硬件做的,你不用写。

### Trilinear vs Bilinear vs Anisotropic

| 过滤方式 | 怎么采 | 何时用 |
|---|---|---|
| Nearest | 1 个像素 | 像素艺术 |
| Bilinear | 同 level 4 像素线性 | 2D 游戏 |
| Trilinear | 两 level 各 4 像素 + level 间线性 | 3D 近距离 |
| Anisotropic | 椭圆形采多个像素 | 3D 斜视角(地板) |

Anisotropic(各向异性)最贵但效果最好——地板斜着看时,一个屏幕像素在 UV 空间是一个长椭圆,各向异性按椭圆采多点,地板清晰。

OpenGL API:

```c
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR_MIPMAP_LINEAR);  // trilinear
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexParameterf(GL_TEXTURE_2D, GL_TEXTURE_MAX_ANISOTROPY_EXT, 8.0f);  // 各向异性 8x
```

### Mipmap 的代价

- **内存 +33%**:多存各级 mipmap
- **加载时间**:首次生成(或预生成)
- **bandwidth**:GPU 采样时根据 level 采不同缓存,可能 cache miss 多

但相比"远处闪烁"的视觉缺陷,这些代价完全值得。

## 3 · 四域深入

### 3.1 · 游戏编程视角

工业级游戏加 mipmap 是默认操作。但有几个细节:

- **Mipmap alpha test 问题**:alpha cutout(像树叶贴图,部分透明)mipmap 后小 level 把 alpha 平均,边缘变成半透明,渲染时 alpha test 失败,叶子消失。解决:用 mipmap alpha scale 或 alpha-to-coverage
- **Texture streaming**:大游戏用虚拟纹理,按需加载 mipmap level。FarCry 系列用 SVT
- **Compressed mipmap**:用 BCn/DXT 压缩每级 level,内存省 4x

### 3.2 · 图形学视角

mipmap 的核心是 **signal processing(信号处理)** ——奈奎斯特定理说:采样频率必须 >= 信号最高频的 2 倍,否则 aliasing(走样)。

纹理在远处变"高频"(因为大纹理塞进小屏幕区域),低于奈奎斯特频率,产生 aliasing = 闪烁。Mipmap 把远处用低频版本(低分辨率),恢复奈奎斯特条件,消除 aliasing。

这就是为什么 `GL_LINEAR_MIPMAP_LINEAR` 也叫 **trilinear filtering** ——UV 空间双线性(2 个轴) + level 空间线性 = 3 个线性。

### 3.3 · Linux 系统编程视角

mipmap 的"多级预生成"思想在系统层也常见:

- **Linux page cache**:热数据放 page cache(L1),冷数据回磁盘(L2)
- **Page table levels**:x86_64 用 4 级页表,粒度从粗到细
- **JPEG thumbnail**:`xdg` 在 `~/.cache/thumbnails/` 存图缩略图

都是"准备多个分辨率版本,按需选"的思路。

### 3.4 · Rust 生态视角

`image` crate 提供 mipmap 生成:

```rust
use image::{imageops, GenericImageView, ImageBuffer, Rgba};

fn generate_mipmaps(
    img: &ImageBuffer<Rgba<u8>, Vec<u8>>,
) -> Vec<ImageBuffer<Rgba<u8>, Vec<u8>>> {
    let mut chain = vec![img.clone()];
    let (mut w, mut h) = img.dimensions();
    while w > 1 || h > 1 {
        w = (w / 2).max(1);
        h = (h / 2).max(1);
        let smaller = imageops::resize(
            chain.last().unwrap(),
            w, h,
            imageops::FilterType::Lanczos3,  // 高质量
        );
        chain.push(smaller);
    }
    chain
}
```

## 4 · 认知地图

### 4.1 上级

### 4.2 同级

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| Mipmap(各向同性) | 圆形采,各向均匀 | 一般场景 | **是** |
| Anisotropic | 椭圆采,沿主轴 | 斜视角(地板) | 后续天 |

| Stochastic filtering | 随机采样 | 漫反射 GI | 否 |

### 4.3 下级

- **Level 0** —— 原图
- **Downsample filter** —— 缩小算法(box/gaussian/lanczos)
- **LOD selection** —— GPU 怎么选 level

## 5 · 对照与变奏

mipmap 的历史:

- **1983**:Williams 首次提出 pyramidal parametric discrete(原始论文)
- **1996**:Consumer GPU(Voodoo)开始支持 bilinear
- **1998**:Trilinear 成为标配
- **2000s**:Anisotropic filtering 进入主流
- **2010s**:Texture compression + mipmap 自动生成是 GPU 标准

工业化方向:从"手动指定各级 mipmap"到"GPU 自动生成",从"box filter"到"sRGB-aware filter"(避免暗化)。

一个有意思的细节:**sRGB texture 的 mipmap 必须在 sRGB 空间采 gamma-correct 平均**,否则远处变暗。Casey 这天没遇到这个问题(他用 linear),实际项目要注意。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 mipmap 用"取平均"做 downsample,而不是"取最近邻"?

**参考解答**:取平均是 box filter,在频域是低通滤波——去掉高频细节(就是远处看不见的细节),保留低频(整体颜色)。取最近邻是抽样,频域是抽样 + 复制频谱——会产生 aliasing(混叠),结果远处仍有闪烁。mipmap 的本质是"用低分辨率表示低频",而低通滤波器(取平均)恰好能取出低频。

### Lv2 · 动手实践

**题**:写一个 Rust 函数,生成 512x512 RGBA 纹理的完整 mipmap chain,返回所有 level。要求:

- 用 box filter(2x2 平均)
- 共 10 级(512 → 1)
- 打印每级的尺寸和字节数
- 验证总内存 < 原图的 4/3

**参考解答**:

```rust
fn downsample_2x2(
    src: &[u8], src_w: usize, src_h: usize,
) -> (Vec<u8>, usize, usize) {
    let dst_w = (src_w / 2).max(1);
    let dst_h = (src_h / 2).max(1);
    let mut dst = vec![0u8; dst_w * dst_h * 4];
    for y in 0..dst_h {
        for x in 0..dst_w {
            for c in 0..4 {
                let mut sum = 0u32;
                let mut count = 0u32;
                for sy in 0..2 {
                    for sx in 0..2 {
                        let px = x * 2 + sx;
                        let py = y * 2 + sy;
                        if px < src_w && py < src_h {
                            sum += src[(py * src_w + px) * 4 + c] as u32;
                            count += 1;
                        }
                    }
                }
                dst[(y * dst_w + x) * 4 + c] = (sum / count) as u8;
            }
        }
    }
    (dst, dst_w, dst_h)
}

fn generate_mipchain(
    mut src: Vec<u8>, mut w: usize, mut h: usize,
) -> Vec<(Vec<u8>, usize, usize)> {
    let mut chain = vec![(src.clone(), w, h)];
    while w > 1 || h > 1 {
        let (new_data, new_w, new_h) = downsample_2x2(&src, w, h);
        chain.push((new_data.clone(), new_w, new_h));
        src = new_data;
        w = new_w;
        h = new_h;
    }
    chain
}

fn main() {
    // 创建 512x512 RGBA 纹理(每像素随机色)
    let w = 512; let h = 512;
    let mut src = vec![0u8; w * h * 4];
    let mut s: u32 = 42;
    for byte in src.iter_mut() {
        s ^= s << 13; s ^= s >> 17; s ^= s << 5;
        *byte = (s & 0xff) as u8;
    }

    let chain = generate_mipchain(src, w, h);
    let mut total_bytes = 0;
    for (i, (data, lw, lh)) in chain.iter().enumerate() {
        println!("Level {}: {}x{} ({} bytes)", i, lw, lh, data.len());
        total_bytes += data.len();
    }
    println!("Total: {} bytes", total_bytes);
    println!("Original: {} bytes", w * h * 4);
    let ratio = total_bytes as f32 / (w * h * 4) as f32;
    println!("Ratio: {:.3} (should be < 1.333)", ratio);
    assert!(ratio < 4.0 / 3.0 + 0.01);
}
```

## 8 · Rust / Arch 落地代码

完整的 mipmap 生成 + 视觉验证:

```rust
// 生成 mipmap chain,带 gamma-correct(sRGB-aware)选项
fn downsample_srgb_aware(
    src: &[u8], src_w: usize, src_h: usize,
) -> (Vec<u8>, usize, usize) {
    let dst_w = (src_w / 2).max(1);
    let dst_h = (src_h / 2).max(1);
    let mut dst = vec![0u8; dst_w * dst_h * 4];

    fn srgb_to_linear(c: u8) -> f32 {
        let c = c as f32 / 255.0;
        if c <= 0.04045 { c / 12.92 } else { ((c + 0.055) / 1.055).powf(2.4) }
    }
    fn linear_to_srgb(c: f32) -> u8 {
        let c = if c <= 0.0031308 { c * 12.92 } else { 1.055 * c.powf(1.0 / 2.4) - 0.055 };
        (c.max(0.0).min(1.0) * 255.0) as u8
    }

    for y in 0..dst_h {
        for x in 0..dst_w {
            let mut linear_sum = [0.0f32; 3];
            let mut alpha_sum = 0u32;
            let mut count = 0u32;
            for sy in 0..2 {
                for sx in 0..2 {
                    let px = x * 2 + sx;
                    let py = y * 2 + sy;
                    if px < src_w && py < src_h {
                        for c in 0..3 {
                            linear_sum[c] += srgb_to_linear(src[(py * src_w + px) * 4 + c]);
                        }
                        alpha_sum += src[(py * src_w + px) * 4 + 3] as u32;
                        count += 1;
                    }
                }
            }
            for c in 0..3 {
                dst[(y * dst_w + x) * 4 + c] = linear_to_srgb(linear_sum[c] / count as f32);
            }
            dst[(y * dst_w + x) * 4 + 3] = (alpha_sum / count) as u8;
        }
    }
    (dst, dst_w, dst_h)
}

fn main() {
    // 简单测试:512x512 全红 + 一个黑点
    let w = 512; let h = 512;
    let mut src = vec![0u8; w * h * 4];
    for px in src.chunks_mut(4) {
        px[0] = 255; px[1] = 0; px[2] = 0; px[3] = 255;
    }
    // 中间一个白点
    let cx = w / 2; let cy = h / 2;
    src[(cy * w + cx) * 4 + 1] = 255;
    src[(cy * w + cx) * 4 + 2] = 255;

    println!("Original: {}x{} first pixel: {:?}", w, h, &src[0..4]);

    let (level1, w1, h1) = downsample_srgb_aware(&src, w, h);
    println!("Level 1: {}x{} first pixel: {:?}", w1, h1, &level1[0..4]);

    // 验证:原图全红 + 一个白点,downsample 后大部分像素还是红
    // (白点被平均到 1/4 像素,实际很难看出来,演示用)
}
```
