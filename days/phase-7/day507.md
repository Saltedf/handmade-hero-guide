
# Day 507 · LRU 纹理句柄复用

> 游戏里同时可能有上千个 sprite,但 GPU 只能装几百个纹理。Day 507 实现 LRU(Least Recently Used,最近最少使用)缓存——纹理超出 GPU 容量时,自动淘汰最久没用的。

## 0 · 为什么要有这一天

### 真实场景:大世界游戏的纹理难题

让我们把镜头拉近。你跟着 Casey 做到 Day 506。游戏有基础相机、entity 系统、相机 polish。看起来不错——一张 50×50 tile 的地图,200 个 sprite,跑 60 FPS。

然后你做大世界游戏。地图扩到 5000×5000 tile,**100 万个 sprite**。每个 sprite 用不同纹理(每棵树、每个石头、每个 NPC 都独特)。

你跑游戏——GPU 内存爆炸。`glTexImage2D` 返回 `GL_OUT_OF_MEMORY`,游戏崩。

为什么?100 万个 sprite × 每个纹理 256KB = **256 GB**。但你的 GPU 只有 8 GB(高端独显),集成显卡只有 256 MB。**装不下**。

工业级大世界游戏(《Minecraft》《赛博朋克 2077》《塞尔达:旷野之息》)都遇到这个问题。它们的数据量远超显存,但游戏能跑。怎么做到?

**LRU 缓存**(Least Recently Used,最近最少使用)。维护一个 GPU 纹理池,容量 N。要加载新纹理时,如果池满,淘汰最久没用的纹理,腾位置加载新的。

LRU 是**操作系统页面置换算法**的同构问题。Linux 的 page cache、CPU 的 L1/L2/L3 cache、浏览器的 image cache、数据库的 buffer pool 都是 LRU。学会 LRU,你看懂所有 cache 系统。

### 为什么不直接装更多显存?

有人会问:"直接买更大显存不就行了?"

工业级答案:**永远不够**。原因:

**1. 数据量增长远快于显存**。2000 年 GPU 64 MB,游戏 100 MB 数据。2024 年 GPU 24 GB,游戏 200 GB 数据(高分辨率纹理 + 多个 LOD + 法线贴图 + 粗糙度贴图)。显存增长 375 倍,数据增长 2000 倍。**数据始终超过显存**。

**2. 移动端受限**。手机 GPU 共享系统内存,通常 2-4 GB。Switch 只有 4 GB。这些平台上,**LRU 是必需品**。

**3. 多游戏共享**。Steam 同时跑多个游戏,每个只能用部分显存。

**4. WebAssembly / 浏览器**。WebGL / WebGPU 限制更严,通常 256 MB-1 GB。

所以工业级游戏必须有 LRU——不管显存多大,**总有比显存多的数据**。

### LRU 的工业级应用范围

LRU 不只是 GPU 纹理。它出现在:

- **OS page cache**:Linux 文件 cache。`echo 3 > /proc/sys/vm/drop_caches` 清空。
- **CPU L1/L2/L3 cache**:硬件 LRU(8-way set associative,伪 LRU 算法)。
- **Browser cache**:Chrome 图片 cache、JS module cache。
- **Database buffer pool**:PostgreSQL、InnoDB 用 LRU + 改良(LRU midpoint、compressed LRU)。
- **Redis maxmemory-policy**:`allkeys-lru` 是常见配置。
- **CDN edge cache**:Cloudflare / Akamai 节点的边缘 cache。
- **HTTP cache**:`Cache-Control: max-age` + `ETag` 实现类似 LRU 行为。

所有这些**核心算法相同**:容量有限,新来要装,淘汰最久没用。

### LRU vs 其他淘汰策略

LRU 不是唯一选择。其他常见策略:

- **LRU(Least Recently Used)**:淘汰最久没用。基于"时间局部性"假设——最近用的还会再用。
- **LFU(Least Frequently Used)**:淘汰用得最少。基于"频率"假设——常用的一直用。
- **FIFO(First In First Out)**:先进先出。最简单,但效果差。
- **Random**:随机淘汰。意外地"够用",Linux 的早期 page replacement 用过。
- **ARC(Adaptive Replacement Cache)**:LRU + LFU 自适应。IBM 发明,ZFS 用。
- **2Q(Two-Queue)**:类似 ARC,PostgreSQL 用变种。
- **Clock(Second Chance)**:近似 LRU,Linux 用。

LRU 最常用,因为时间局部性普遍(玩家看一棵树,几秒内还会看附近树)。但 LRU 有 **thrashing(抖动)** 问题——cache 容量 N,但每帧用 N+1 个不同纹理,LRU 每帧全部淘汰再加载,100% miss。

工业级解法:
- 增大 cache(物理空间换命中率)
- 减少纹理(用 sprite atlas,把多个小纹组合一张大纹)
- 改用 LFU / ARC
- 用 priority cache(重要纹理 pin 住,不淘汰)

## 2 · 心智模型

### 类比:公共图书馆的书架

图书馆书架只能放 256 本书。新书不断到。

LRU:每次有人借书,这本书移到"最前"(最近用)。书架满时,从"最后"淘汰(最久没用)。

Casey 的 LRU cache 同构:GPU 纹理 slot 是书架,sprite 是书,渲染一帧 = 借书。

### LRU 数据结构

经典实现:**HashMap + DoublyLinkedList**。

- HashMap:handle → list node,O(1) 查找
- DoublyLinkedList:维护 LRU 顺序,O(1) 移到 front / 删 back

Rust 标准库无 doubly linked list,常用:

- `Vec<Option<T>>` + `VecDeque<usize>`(slot-based)
- `linked_hash_map` crate
- `lru` crate

Casey 用 slot-based,简单。

### Cache hit / miss 详解

**Hit(命中)**:请求的资源已在 cache。O(1) 返回,无加载开销。

**Miss(未命中)**:请求的资源不在 cache,需要从 backing store(硬盘、网络、慢内存)加载。慢。

**Hit rate = hits / (hits + misses)**。LRU 调优的目标:最大化 hit rate。

工业级 hit rate 标准:
- **CPU L1 cache**:95%+。Miss 惩罚 100 cycles。
- **CPU L2/L3 cache**:80-90%。Miss 惩罚 10-100 cycles。
- **Page cache(OS)**:90%+。Miss 惩罚 1-10ms(磁盘 I/O)。
- **GPU texture cache**:取决于场景。开放世界可能 70%,室内 95%+。
- **Web cache**:80%+。Miss 惩罚 100-500ms(网络)。

低于标准的 hit rate 意味着**用户能感觉到的卡顿**——miss 时阻塞加载,frame drop。

### Thrashing(抖动):cache 的灾难

如果 cache 容量 N,但工作集(working set,实际使用的资源集)大于 N,LRU **每帧全部淘汰再加载**——100% miss,100% eviction。这叫 **thrashing**。

具体场景:
- Cache 容量 256 纹理
- 玩家在森林,每帧看到 300 棵树(300 个不同纹理)
- LRU 每帧淘汰 44 个(256 - 300 = -44,淘汰最旧的 44),下帧再加载这 44 个
- 每帧 256 个 eviction + 256 个 load = 50ms,frame drop 到 20 FPS

解法:
1. **增大 cache**——从 256 涨到 512。物理空间换命中率。但 GPU 显存有限。
2. **减少纹理**——用 sprite atlas,把多棵树打包到一张大纹。300 棵树变成 1 张纹理。
3. **改用 LFU**——LFU 不淘汰常用纹理(树)。但 LFU 对突发访问模式反应慢。
4. **Priority cache / Pin**——把重要纹理(玩家 sprite、HUD)"pin"住,不淘汰。剩余 cache 给可淘汰纹理。
5. **Prefetch**——预测接下来要用的纹理,提前加载(异步 I/O,不阻塞渲染)。

工业级游戏(《赛博朋克 2077》《毁灭战士》)用组合:**sprite atlas + LRU + prefetch + priority**。Hit rate 达到 95%+。

### LRU 的 Rust 实现:HashMap + VecDeque

经典 LRU 用 HashMap + DoublyLinkedList。Rust 没有 std 的 doubly linked list(因为 ownership 复杂),用 `VecDeque<K>` 替代:

```rust
struct LruCache<K, V> {
    capacity: usize,
    map: HashMap<K, V>,        // O(1) 查找
    order: VecDeque<K>,        // 最近用过的顺序,front = 最近用
}

impl<K: Eq + Hash + Clone, V> LruCache<K, V> {
    fn get(&mut self, key: &K) -> Option<&V> {
        if self.map.contains_key(key) {
            // 移到 front(O(n) 的 retain)
            self.order.retain(|k| k != key);
            self.order.push_front(key.clone());
            self.map.get(key)
        } else {
            None
        }
    }

    fn put(&mut self, key: K, value: V) {
        if self.map.contains_key(&key) {
            self.order.retain(|k| *k != key);
        } else if self.map.len() >= self.capacity {
            // 淘汰 LRU back
            if let Some(evicted) = self.order.pop_back() {
                self.map.remove(&evicted);
            }
        }
        self.order.push_front(key.clone());
        self.map.insert(key, value);
    }
}
```

注意:`retain` 是 O(n)。严格 O(1) 要用真 doubly linked list(`linked_hash_map` crate 或 `LinkedList` + 指针)。Casey 用 VecDeque + retain,简单但 O(n)。生产用 `lru` crate(O(1))。

### 工业级 LRU 的优化技巧

**1. O(1) 实现**:HashMap + DoublyLinkedList。每个 map entry 存 `(*mut Node)`,可以直接 splice。Rust 用 `linked_hash_map` 或手写 unsafe doubly linked list。

**2. 并发安全**:`moka` crate 用 sharded locks + 异步 eviction。多线程并发访问,无锁竞争。

**3. Lazy expiration**:每个 entry 带 expire time,访问时检查过期。不在后台定期扫描(省 CPU)。

**4. Hot / cold 分层**:LRU 分两层——hot(最近访问)和 cold(较久)。Hot 不轻易淘汰,cold 优先淘汰。这是 ARC 的核心。

**5. Approximate LRU**:为了性能,不全精确追踪每个 entry。CPU cache 用 8-way set associative + 伪 LRU(1 bit per way),近似但够用。

**6. Read-ahead / Prefetch**:预测接下来要 access 的 key,提前加载到 cache。Linux read-ahead、数据库 sequential prefetch 都是这套。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 LRU 用 HashMap + DoublyLinkedList,而不是单一数据结构?

**参考解答**:两个需求:

1. **O(1) 查找**:给定 key,快速判断在 cache 里。HashMap 擅长。
2. **O(1) 更新顺序**:每次访问,移到 front。DoublyLinkedList 擅长(知道 node 指针,直接 splice)。

单一结构(如 Vec)只能其一:Vec 查找 O(n) 或更新 O(n)。BST 查找 O(log n)。都不如 HashMap + List 的 O(1)。

代价:两个数据结构,内存增加。但 O(1) 优势远超内存代价。

### Lv2 · 动手实践

**题**:实现最小 LRU cache,容量 3,模拟 5 次访问,观察淘汰。

完成标准:`cargo run` 显示每次操作后的 cache 内容。

**参考解答**:

```rust
use std::collections::{HashMap, VecDeque};

struct LruCache<K: Eq + std::hash::Hash + Clone, V> {
    capacity: usize,
    map: HashMap<K, V>,
    order: VecDeque<K>,
}

impl<K: Eq + std::hash::Hash + Clone, V> LruCache<K, V> {
    fn new(capacity: usize) -> Self {
        Self { capacity, map: HashMap::new(), order: VecDeque::new() }
    }
    
    fn get(&mut self, key: &K) -> Option<&V> {
        if self.map.contains_key(key) {
            self.order.retain(|k| k != key);
            self.order.push_front(key.clone());
            self.map.get(key)
        } else {
            None
        }
    }
    
    fn put(&mut self, key: K, value: V) -> Option<V> {
        let mut evicted = None;
        if self.map.contains_key(&key) {
            self.order.retain(|k| *k != key);
        } else if self.map.len() >= self.capacity {
            if let Some(old_key) = self.order.pop_back() {
                evicted = self.map.remove(&old_key);
            }
        }
        self.order.push_front(key.clone());
        self.map.insert(key, value);
        evicted
    }
    
    fn debug(&self) -> String {
        let keys: Vec<String> = self.order.iter().map(|k| format!("{:?}", k)).collect();
        format!("[{}](size={})", keys.join(", "), self.map.len())
    }
}

fn main() {
    let mut cache: LruCache<&str, &str> = LruCache::new(3);
    
    println!("Initial: {}", cache.debug());
    
    cache.put("a", "data-a");
    println!("put(a): {}", cache.debug());
    
    cache.put("b", "data-b");
    println!("put(b): {}", cache.debug());
    
    cache.put("c", "data-c");
    println!("put(c): {}", cache.debug());
    
    // 访问 a,a 变最近用
    cache.get(&"a");
    println!("get(a): {}", cache.debug());
    
    // 加 d,淘汰 b(LRU back)
    let evicted = cache.put("d", "data-d");
    println!("put(d) evicted {:?}: {}", evicted, cache.debug());
    
    // 加 e,淘汰 c
    let evicted = cache.put("e", "data-e");
    println!("put(e) evicted {:?}: {}", evicted, cache.debug());
}

#[cfg(test)]
mod tests {
    use super::*;
    
    #[test]
    fn test_lru_basic() {
        let mut c: LruCache<i32, &str> = LruCache::new(2);
        c.put(1, "a");
        c.put(2, "b");
        assert_eq!(c.get(&1), Some(&"a"));
        c.put(3, "c");    // 淘汰 2
        assert_eq!(c.get(&2), None);
        assert_eq!(c.get(&1), Some(&"a"));
        assert_eq!(c.get(&3), Some(&"c"));
    }
    
    #[test]
    fn test_lru_put_existing_no_evict() {
        let mut c: LruCache<i32, &str> = LruCache::new(2);
        c.put(1, "a");
        c.put(2, "b");
        let evicted = c.put(1, "a2");    // 1 已在,不淘汰
        assert_eq!(evicted, None);
        assert_eq!(c.get(&1), Some(&"a2"));
    }
    
    #[test]
    fn test_lru_capacity_zero() {
        let mut c: LruCache<i32, &str> = LruCache::new(0);
        c.put(1, "a");    // 应不存
        assert_eq!(c.get(&1), None);
    }
}
```

// ============================================================
// Day 507 · LRU 纹理句柄复用
// ============================================================

use std::collections::{HashMap, VecDeque};
use std::fmt;

// ============================================================
// 纹理句柄
// ============================================================

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
struct TextureHandle(u32);

#[derive(Debug, Clone)]
struct TextureData {
    name: String,
    width: u32,
    height: u32,
    bytes: Vec<u8>,    // 假装的 GPU 数据
}

// ============================================================
// LRU Cache (generic)
// ============================================================

struct LruCache<K, V> {
    capacity: usize,
    map: HashMap<K, V>,
    order: VecDeque<K>,
    hits: u64,
    misses: u64,
    evictions: u64,
}

impl<K: Eq + std::hash::Hash + Clone, V> LruCache<K, V> {
    fn new(capacity: usize) -> Self {
        Self {
            capacity,
            map: HashMap::new(),
            order: VecDeque::new(),
            hits: 0, misses: 0, evictions: 0,
        }
    }
    
    fn get(&mut self, key: &K) -> Option<&V> {
        if self.map.contains_key(key) {
            self.order.retain(|k| k != key);
            self.order.push_front(key.clone());
            self.hits += 1;
            self.map.get(key)
        } else {
            self.misses += 1;
            None
        }
    }
    
    fn put(&mut self, key: K, value: V) {
        if self.map.contains_key(&key) {
            self.order.retain(|k| *k != key);
        } else if self.capacity > 0 && self.map.len() >= self.capacity {
            if let Some(old_key) = self.order.pop_back() {
                self.map.remove(&old_key);
                self.evictions += 1;
            }
        }
        if self.capacity > 0 {
            self.order.push_front(key.clone());
            self.map.insert(key, value);
        }
    }
    
    fn contains(&self, key: &K) -> bool { self.map.contains_key(key) }
    fn len(&self) -> usize { self.map.len() }
    fn hit_rate(&self) -> f32 {
        let total = self.hits + self.misses;
        if total == 0 { 0.0 } else { self.hits as f32 / total as f32 }
    }
}

// ============================================================
// 纹理管理器(用 LRU)
// ============================================================

struct TextureManager {
    cache: LruCache<TextureHandle, TextureData>,
    next_handle: u32,
    storage: HashMap<TextureHandle, TextureData>,    // 真正的"硬盘"(所有纹理)
}

impl TextureManager {
    fn new(cache_capacity: usize) -> Self {
        Self {
            cache: LruCache::new(cache_capacity),
            next_handle: 1,
            storage: HashMap::new(),
        }
    }
    
    fn register(&mut self, data: TextureData) -> TextureHandle {
        let handle = TextureHandle(self.next_handle);
        self.next_handle += 1;
        self.storage.insert(handle, data);
        handle
    }
    
    fn bind(&mut self, handle: TextureHandle) -> Option<&TextureData> {
        if self.cache.contains(&handle) {
            return self.cache.get(&handle);
        }
        
        // Miss:从 storage 加载
        if let Some(data) = self.storage.get(&handle) {
            let data = data.clone();
            self.cache.put(handle, data);
        }
        self.cache.get(&handle)
    }
    
    fn stats(&self) -> (u64, u64, u64, f32) {
        (self.cache.hits, self.cache.misses, self.cache.evictions, self.cache.hit_rate())
    }
}

impl fmt::Display for TextureManager {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        let (hits, misses, evictions, hit_rate) = self.stats();
        write!(f, "TextureManager(cache_size={}/{}, total={}, hits={}, misses={}, evictions={}, hit_rate={:.1}%)",
               self.cache.len(), self.cache.capacity,
               self.storage.len(),
               hits, misses, evictions, hit_rate * 100.0)
    }
}

// ============================================================
// Demo
// ============================================================

fn main() {
    println!("=============================================\n");
    println!(" Day 507 · LRU 纹理句柄复用\n");
    println!("=============================================\n");
    
    let mut mgr = TextureManager::new(5);    // GPU 只能装 5 张
    
    // 注册 10 张纹理(模拟游戏所有纹理)
    let mut handles = Vec::new();
    for i in 0..10 {
        let h = mgr.register(TextureData {
            name: format!("texture_{}", i),
            width: 256, height: 256,
            bytes: vec![i as u8; 256 * 256 * 4],    // 256KB
        });
        handles.push(h);
    }
    
    println!("Registered {} textures", handles.len());
    println!("Cache capacity: 5\n");
    
    // 渲染场景 1:用 texture 0,1,2,3,4
    println!("=== Frame 1: 使用 texture 0-4 ===");
    for i in 0..5 {
        mgr.bind(handles[i]);
    }
    println!("{}\n", mgr);
    
    // 渲染场景 2:用 texture 5,6(淘汰 0,1)
    println!("=== Frame 2: 使用 texture 5,6(淘汰 0,1)===");
    mgr.bind(handles[5]);
    mgr.bind(handles[6]);
    println!("{}\n", mgr);
    
    // 渲染场景 3:重新用 0(miss)
    println!("=== Frame 3: 使用 texture 0(应该是 miss)===");
    mgr.bind(handles[0]);
    println!("{}\n", mgr);
    
    // 渲染场景 4:模拟 thrashing(用 10 个不同纹理,但 cache 容量 5)
    println!("=== Frame 4-6: 模拟 thrashing(每帧用全部 10 个)===");
    for frame in 0..3 {
        for h in &handles {
            mgr.bind(*h);
        }
        println!("Frame {}: {}", frame + 4, mgr);
    }
    
    // Stats
    println!("\n=== 最终统计 ===");
    let (hits, misses, evictions, hit_rate) = mgr.stats();
    println!("Total hits: {}", hits);
    println!("Total misses: {}", misses);
    println!("Total evictions: {}", evictions);
    println!("Hit rate: {:.1}%", hit_rate * 100.0);
    println!("\n注:thrashing 时 hit rate 低,因为每帧用 10 个但 cache 容量 5");
    
    // 改进:pin 重要纹理
    println!("\n=== 改进思路:pin 重要纹理(玩家 sprite)===");
    let mut mgr2 = TextureManager::new(5);
    let _player_texture = mgr2.register(TextureData {
        name: "player".into(),
        width: 512, height: 512,
        bytes: vec![0; 512 * 512 * 4],
    });
    for i in 0..10 {
        mgr2.register(TextureData {
            name: format!("tex_{}", i),
            width: 256, height: 256,
            bytes: vec![i as u8; 256 * 256 * 4],
        });
    }
    println!("注册了 11 张纹理(含 player)");
}

#[cfg(test)]
mod tests {
    use super::*;
    
    #[test]
    fn test_lru_basic() {
        let mut c: LruCache<i32, &str> = LruCache::new(2);
        c.put(1, "a");
        c.put(2, "b");
        assert!(c.contains(&1));
        c.get(&1);    // 1 现在最近用
        c.put(3, "c");    // 淘汰 2
        assert!(!c.contains(&2));
        assert!(c.contains(&1));
        assert!(c.contains(&3));
    }
    
    #[test]
    fn test_hit_miss_tracking() {
        let mut c: LruCache<i32, &str> = LruCache::new(2);
        c.put(1, "a");
        c.get(&1);    // hit
        c.get(&2);    // miss
        assert_eq!(c.hits, 1);
        assert_eq!(c.misses, 1);
    }
    
    #[test]
    fn test_eviction_count() {
        let mut c: LruCache<i32, &str> = LruCache::new(2);
        c.put(1, "a");
        c.put(2, "b");
        c.put(3, "c");    // 淘汰 1
        c.put(4, "d");    // 淘汰 2
        assert_eq!(c.evictions, 2);
    }
    
    #[test]
    fn test_texture_manager_load() {
        let mut mgr = TextureManager::new(3);
        let h1 = mgr.register(TextureData {
            name: "test".into(), width: 1, height: 1, bytes: vec![0],
        });
        
        // 第一次 bind:miss
        let data = mgr.bind(h1);
        assert!(data.is_some());
        let (_, misses, _, _) = mgr.stats();
        assert_eq!(misses, 1);
        
        // 第二次 bind:hit
        let data = mgr.bind(h1);
        assert!(data.is_some());
        let (hits, _, _, _) = mgr.stats();
        assert_eq!(hits, 1);
    }
    
    #[test]
    fn test_thrashing_low_hit_rate() {
        let mut mgr = TextureManager::new(3);
        let mut handles = Vec::new();
        for i in 0..10 {
            handles.push(mgr.register(TextureData {
                name: format!("t{}", i),
                width: 1, height: 1, bytes: vec![0],
            }));
        }
        
        // 多帧使用所有 10 个纹理
        for _ in 0..5 {
            for h in &handles {
                mgr.bind(*h);
            }
        }
        
        let (_, _, _, hit_rate) = mgr.stats();
        // hit rate 应低(thrashing)
        assert!(hit_rate < 0.5);
    }
    
    #[test]
    fn test_zero_capacity_cache() {
        let mut c: LruCache<i32, &str> = LruCache::new(0);
        c.put(1, "a");
        assert!(!c.contains(&1));
    }
}
