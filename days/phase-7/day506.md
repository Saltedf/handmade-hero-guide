
# Day 506 · 改进相机运动

> Day 503-505 做了基础缓动 + 探索方案。Day 506 整合:**选 spring 方案**,加 lookahead、speed-based zoom、recentering、boundary cushion。组合多个特性,让相机真正"电影感"。

## 0 · 为什么要有这一天

### 真实场景:从"能用"到"专业"的距离

让我们把镜头拉近。你跟着 Casey 做到 Day 505,相机有基础缓动(Day 503)、能选多种方案(Day 504)、能放多个 entity(Day 505)。功能上,**相机已经"能用"**。但 Casey 跑游戏测试,他皱眉:

- 玩家跑动时,镜头**完全不反应**——画面感觉"死"
- 玩家撞墙时,镜头**硬停**——视觉上一震
- 玩家停下后,镜头**慢慢漂**——因为 lookahead 还在算
- 边界附近,玩家被相机"推出屏幕"——因为 hard clamp 直接切

这些不是 bug——每个特性都"按设计工作"。但**组合后效果不专业**。

工业级游戏开发有一个隐性真理:**功能完成 ≠ 体验完成**。一个相机的"能用"到"专业"之间,有大量 polish 工作要做。这些 polish 不加功能,而是**调组合、调参数、补边界情况**。它们决定了游戏的"手感"。

### 为什么花一整天做 polish

有人会问:"这些 polish 改改参数不就行了,为啥花一整天?"

答案是:**单个 polish 特性可以'显得不错',但多个特性组合后才'感觉专业',组合需要解决冲突**。Day 506 的核心教学不是"加 4 个特性",而是"让 4 个特性协调工作"。

具体冲突例子:

**冲突 1:Spring + lookahead 双重过冲**。Spring 自己有过冲(物理特性),lookahead 让 target 提前移动(玩家方向预判)。两者叠加,玩家跑动时,镜头冲到玩家前面很远,玩家在屏幕角落。解法:给 lookahead **cap**(上限),最多偏移 N 像素。

**冲突 2:Boundary clamp 推玩家出屏幕**。相机 hard clamp 到边界,但玩家继续移动,玩家"超过"相机,被推出屏幕另一侧。解法:加 **boundary cushion**——边界内 50 像素是"减速区",相机速度衰减,慢慢停下。

**冲突 3:Lookahead 让玩家停下后镜头漂**。玩家停下,vel = 0,lookahead factor 应该归零。但 idle_time 还没达到阈值,lookahead 仍生效,target 偏移。镜头漂移 3 秒。解法:加 **recentering**——玩家静止 3 秒后,lookahead 渐变到 0,镜头回到玩家正中。

**冲突 4:速度变化没视觉反馈**。玩家跑动停下,镜头视野不变,画面感觉"瞬停"。解法:加 **speed-based zoom**——跑得快 FOV 变大(看更多前路),停下 FOV 回小,镜头有"动感"。

这 4 个特性单独看都简单,但**组合**需要小心调参——调一个会影响另一个。Casey 在 Day 506 反复跑游戏、改参数、再跑,直到"手感对"。这种迭代是 polish 的核心。

### 工业级相机系统的对比

工业级相机系统都有 Day 506 的特性,只是包装不同:

**Unity Cinemachine**(标准相机 framework):
- **Impulse**:冲量,模拟相机震动(爆炸、撞击)
- **Composer**:自动构图(把目标放在画面 1/3 位置)
- **Group Composer**:多目标构图(把多个角色都放屏幕里)
- **Noise**:相机抖动 noise(走路的呼吸感)
- **Recenter**:Wait + Recenter,玩家停止后镜头回正

**Unreal SpringArm**:
- `CameraLag`:相机滞后,模拟惯性
- `CameraRotationLag`:旋转滞后
- `ProbeSize`:碰撞探测半径(相机不穿墙)

**Godot Camera2D**:
- `smoothing_enabled`:平滑开关
- `smoothing_speed`:平滑速度
- `offset`:镜头偏移(类似 lookahead)
- `limit_left/right/top/bottom`:边界(类似 boundary)
- `position_smoothing`:位置平滑

**Cinemachine 的 4 大特性** ≈ Day 506 的 4 个特性:
- Cinemachine Composer ≈ Day 506 lookahead
- Cinemachine Impulse ≈ Day 506 没有,但 Casey 后续会加
- Cinemachine Group Composer ≈ Day 506 没有(目标多)
- Cinemachine Recenter ≈ Day 506 recentering

学完 Day 506,你看 Unity Cinemachine 的设置面板,**每个参数都对应一个概念**——不是黑魔法,都是 Day 506 的扩展。

- 实现静止后镜头 recenter,改善"等待"体验

## 1 · Casey 今天做了什么

Casey 这一天没有"加新功能",而是**调组合 + 加 polish**。他做 6 步。

**第一步,选 spring 方案**。Day 504 探索了多种方案,Day 506 最终选 spring,带 critical damping(临界阻尼)。具体参数:`spring_k = 50`(刚度),`spring_c = 2 * sqrt(50) ≈ 14.1`(临界阻尼系数)。

为什么选 spring 不选 lerp?因为 spring 有"重量感"——相机加速、减速、过冲,像物理对象。lerp 永远不过冲,感觉"机械"。

**第二步,加 lookahead with cap**。Lookahead 让 target 提前于玩家位置(预判玩家方向):

```rust
let mut target = player.pos + player.vel * lookahead_factor;
// cap:lookahead 不超过 lookahead_max 像素
let offset_from_center = target - player.pos;
if offset_from_center.length() > lookahead_max {
    target = player.pos + offset_from_center.normalize() * lookahead_max;
}
```

`lookahead_factor = 0.2`(预判 200ms),`lookahead_max = 50` 像素(最多偏移)。如果玩家高速,offset 可能很大,cap 到 50。这避免了"玩家高速 → 镜头冲到玩家前面 → 玩家在屏幕角落"。

**第三步,加 speed-based zoom**。玩家跑得快,FOV 变大,镜头"拉远",视野更广:

```rust
let speed = player.vel.length();
let target_fov = base_fov + (speed / max_speed).min(1.0) * max_fov_increase;
camera.fov = lerp(camera.fov, target_fov, dt * 5.0);
```

`base_fov = 60°`(基础),`max_fov_increase = 15°`(最大增量),`max_speed = 100`(满速)。玩家满速时 FOV = 75°,停下回 60°。`lerp(... dt * 5.0)` 让 FOV 平滑变化,不要瞬切。

**第四步,加 boundary cushion**。硬 clamp:相机到达边界,瞬间停。视觉突兀。软 cushion:边界内 50 像素是"减速区",相机移动按距离边界的距离衰减:

```rust
// 计算到最近边界的距离
let dist_to_boundary = (self.target.x - min.x)
    .min(max.x - self.target.x)
    .min(self.target.y - min.y)
    .min(max.y - self.target.y);

let effective_k = if dist_to_boundary < cushion_zone {
    // 在减速区,降低 spring_k,相机变"懒"
    base_k * (dist_to_boundary / cushion_zone)
} else {
    base_k    // 正常
};
```

`cushion_zone = 50` 像素。距离 50 时,effective_k = full;距离 0 时,effective_k = 0(相机完全不动)。中间线性插值。这让相机"自然减速"到边界,不是 hard clamp。

**第五步,加 recentering**。玩家移动时,lookahead 让镜头偏移。玩家停下,镜头应该回到玩家正中:

```rust
// 跟踪静止时间
if player.vel.length() < 0.1 {
    self.idle_time += dt;
} else {
    self.idle_time = 0.0;
}

// 静止 3 秒后,lookahead 渐变到 0
let effective_lookahead = if self.idle_time > 3.0 {
    let t = ((self.idle_time - 3.0) * 0.5).min(1.0);
    lerp(self.lookahead_factor, 0.0, t)
} else {
    self.lookahead_factor
};
```

阈值 3 秒避免"玩家短暂停下镜头就漂"。3 秒后渐变(0.5/秒速率)到 0,大约 2 秒完全归零。

**第六步,反复跑游戏调参**。Casey 跑游戏,改 `lookahead_max`,再跑。`max_fov_increase` 调几次,直到"快但不过分"。`cushion_zone` 试 30、50、70 像素。这个迭代过程是 polish 的核心——**没有公式,只有"试"**。Casey 在视频里说:"这种感觉就是对的,我说不出为什么,但视觉上对。"

最终参数:`lookahead_max = 50, max_fov_increase = 15, cushion_zone = 50, idle_threshold = 3.0`。这就是 Day 506 的成果。

## 2 · 心智模型

### 类比:电影摄影机

专业电影摄影机不只跟着主角跑。它:

- 主角说话时镜头靠近
- 主角跑动时镜头拉远(让观众看到环境)
- 主角停在某处,镜头重新构图(让画面平衡)
- 边缘场景,镜头柔顺减速(不撞墙)

Day 506 的相机特性就是模拟这些电影技巧。

### Speed-based zoom 的视觉效果

玩家跑得快时,相机 FOV 变大——视野更广,边缘物体在屏幕上移动更快(透视效应)。这是赛车游戏的核心效果。

**为什么这模拟"快速"感?** 想象你站在路边,车从你面前开过。车在你的视野中央时"清楚",离开时**很快从你的视野边缘消失**(因为视野有限,边缘角度变化快)。这种"边缘物体刷刷掠过"是大脑感知"快速"的核心线索。

游戏里加这个 effect:FOV 大,视野广,玩家移动时画面边缘的物体快速掠过——大脑读到"快速"。即使玩家速度没变,加 FOV 都让玩家觉得"变快了"。

数学:`target_fov = base_fov + (speed / max_speed) * delta`,其中 `delta` 控制变化幅度。

`delta` 经验值:
- `5°`:轻微,玩家几乎注意不到,但有"动感"
- `10°`:明显,玩家能感觉到加速
- `15°`:强,赛车感
- `20°+`:夸张,过山车感

实际游戏案例:
- **《赛博朋克 2077》**:车辆加速时 FOV 从 70° 增到 90°,强动感
- **《蜘蛛侠》**:Web-swing 时 FOV 拉大,模拟"飞行感"
- **《Super Mario Odyssey》**:Mario 跑动时 FOV 略增(5°),平台游戏的"丝滑"
- **《毁灭战士》**:玩家奔跑 FOV 拉大 + 屏幕震动,极致动感

### Boundary cushion:软边界 vs 硬 clamp

**硬 clamp** 是最简单的边界处理:相机位置算完,如果超出边界,直接 clamp 到边界内。

```rust
// 硬 clamp
camera.pos.x = camera.pos.x.max(min.x).min(max.x);
camera.pos.y = camera.pos.y.max(min.y).min(max.y);
```

问题:玩家持续向边界移动,相机被 clamp 死,玩家"超过"相机,出现在屏幕边缘甚至出屏幕。视觉上"被推出屏幕",体验差。

**软 cushion**:边界内 cushion_zone 像素(比如 50),相机 spring_k 减小。距离边界越近,k 越小,相机越"懒",自然减速。距离 0 时 k=0,相机不动,但不是"瞬间停"——是渐近停下。

数学:在 cushion 区域,effective smoothing 随距离减小:

```rust
let dist_to_boundary = ...;
let effective_k = if dist_to_boundary < cushion_zone {
    base_k * (dist_to_boundary / cushion_zone)
} else {
    base_k
};
```

距离 50(full zone):k = 100% base,正常追。
距离 25(half):k = 50% base,慢一半。
距离 0(edge):k = 0,不动。

但 k=0 意味着相机完全停,但仍在追 target。这种"渐近停下"的视觉感比 hard clamp 自然得多。

实际游戏都用 cushion。Unity 的 Cinemachine 有 `Soft Zone`,Godot Camera2D 有 `smoothing_speed` 自适应,Unreal SpringArm 有 `Camera Lag`。

### Recentering:静止归零

玩家移动时,lookahead 让 target 偏移到玩家前面。玩家停下,**target 仍偏移**(因为 lookahead factor 仍 = 0.2)。结果镜头仍指向"玩家前面的位置",但玩家已停。视觉上**镜头在玩家前面**,玩家在屏幕下方。

**Recentering** 解决这个问题。逻辑:

1. 跟踪 `idle_time`——玩家速度 < 阈值时累加,移动时归零
2. idle_time > 3 秒后,lookahead 渐变到 0
3. 镜头自然回到玩家正中

```rust
if player.vel.length() < 0.1 {
    idle_time += dt;
} else {
    idle_time = 0.0;
}

let effective_lookahead = if idle_time > 3.0 {
    let factor = ((idle_time - 3.0) * 0.5).min(1.0);
    lerp(lookahead, 0.0, factor)
} else {
    lookahead
};
```

阈值 3 秒避免"玩家短暂停下镜头就漂"——3 秒内的停顿不触发 recenter。3 秒后开始渐变,0.5/秒速率,2 秒完全归零。

实际游戏案例:
- **《黑暗之魂》**:玩家停下战斗后,镜头缓慢回到玩家正中
- **《塞尔达:旷野之息》**:Link 停下,镜头自动回正
- **Unity Cinemachine**:有 `Recenter To Target` 设置,可调 Wait 时间和 Recenter 速度

### Lookahead cap:防止过头

不加 cap,玩家高速移动,lookahead 让镜头跑到玩家前面很远。玩家在屏幕角落,看不到自己。

加 cap:lookahead offset 不超过 N 像素:

```rust
let offset = player.vel * lookahead_factor;
if offset.length() > lookahead_max {
    offset = offset.normalize() * lookahead_max;
}
```

`lookahead_max = 50` 像素是经验值——足够看到前方,不太多导致玩家"消失在角落"。

实际游戏案例:
- **《空洞骑士》**:lookahead cap,即使冲刺镜头也不过偏
- **《死亡细胞》**:类似设计
- **Unity Cinemachine Composer**:有 `Dead Zone Width` 和 `Soft Zone Width`,效果类似 cap

### 3.2 · 🎨 图形学视角

FOV 的数学。

`fov` 是相机张角,弧度。FOV 大,看到的广;小,看到的窄。

透视投影矩阵:

```
P = perspective(fov, aspect, near, far)
```

`fov` 影响投影矩阵的 `[0][0]` 和 `[1][1]` 元素。

动态 FOV:每帧重算投影矩阵。

视觉效果:FOV 大 = 鱼眼,物体离得远;FOV 小 = 望远镜,物体离得近。

### 3.4 · 🦀 Rust 生态视角

Rust 实现 polish 后的相机。

```rust
struct PolishedCamera {
    pos: Vec2,
    vel: Vec2,
    target: Vec2,
    
    // Spring
    spring_k: f32,
    spring_c: f32,
    
    // Lookahead
    lookahead_factor: f32,
    lookahead_max: f32,
    idle_time: f32,
    
    // Speed-based zoom
    fov: f32,
    base_fov: f32,
    max_fov_increase: f32,
    
    // Boundary cushion
    bounds: Option<(Vec2, Vec2)>,
    cushion: f32,
}

impl PolishedCamera {
    fn update(&mut self, player_pos: Vec2, player_vel: Vec2, dt: f32) {
        // Idle tracking
        if player_vel.length() < 0.1 {
            self.idle_time += dt;
        } else {
            self.idle_time = 0.0;
        }
        
        // Lookahead with cap + recenter
        let mut lookahead = self.lookahead_factor;
        if self.idle_time > 3.0 {
            let factor = ((self.idle_time - 3.0) * 0.5).min(1.0);
            lookahead = lerp(self.lookahead_factor, 0.0, factor);
        }
        
        let mut offset = player_vel * lookahead;
        if offset.length() > self.lookahead_max {
            offset = offset.normalize() * self.lookahead_max;
        }
        
        self.target = player_pos + offset;
        
        // Boundary cushion:接近边界时减小 smoothing
        let mut effective_k = self.spring_k;
        if let Some((min, max)) = self.bounds {
            let dist = (self.target.x - min.x).min(max.x - self.target.x)
                      .min(self.target.y - min.y).min(max.y - self.target.y);
            if dist < self.cushion {
                effective_k *= dist / self.cushion;
            }
        }
        
        // Spring update
        let force_x = -effective_k * (self.pos.x - self.target.x) - self.spring_c * self.vel.x;
        let force_y = -effective_k * (self.pos.y - self.target.y) - self.spring_c * self.vel.y;
        
        self.vel.x += force_x * dt;
        self.vel.y += force_y * dt;
        self.pos.x += self.vel.x * dt;
        self.pos.y += self.vel.y * dt;
        
        // Speed-based FOV
        let speed = player_vel.length();
        let target_fov = self.base_fov + (speed / 100.0).min(1.0) * self.max_fov_increase;
        self.fov = lerp(self.fov, target_fov, dt * 5.0);
        
        // Hard clamp
        if let Some((min, max)) = self.bounds {
            self.pos.x = self.pos.x.max(min.x).min(max.x);
            self.pos.y = self.pos.y.max(min.y).min(max.y);
        }
    }
}

fn lerp(a: f32, b: f32, t: f32) -> f32 { a + (b - a) * t }
```

## 5 · 对照与变奏

Camera polish 在不同游戏的表现。

**赛车游戏**:速度越高 FOV 越大(强动感),反向时镜头往后看。
**平台游戏**:跳跃时镜头微拉远,落地时回到原 FOV。
**FPS**:开镜(ADS)时 FOV 突然小,模拟望远镜。
**RTS**:鼠标到屏幕边缘,镜头平移。

跨领域对照:

- **电影**:导演控制镜头,每个镜头精心设计。
- **YouTube video**:自动 camera motion(防抖),同 Cushioning。
- **VR**:镜头 = 玩家头部,无 lookahead(防晕动症)。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:为什么 speed-based FOV 让游戏感觉更"快"?

**参考解答**:FOV 大,视野广,边缘物体在屏幕上移动更快(透视效应)。玩家大脑感知"快速"。

实际开车时也有类似感觉——加速时周边物体刷刷掠过。

游戏里加这个 effect,放大"快速"的感觉。赛车游戏、《蜘蛛侠》高速穿梭、《毁灭战士》跑步都用。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现 polished camera,带 lookahead cap + speed-based FOV + boundary cushion。模拟玩家移动,看相机反应。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    const fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn length(self) -> f32 { (self.x * self.x + self.y * self.y).sqrt() }
}

impl std::ops::Add for Vec2 {
    type Output = Vec2;
    fn add(self, o: Vec2) -> Vec2 { Vec2::new(self.x + o.x, self.y + o.y) }
}

impl std::ops::Sub for Vec2 {
    type Output = Vec2;
    fn sub(self, o: Vec2) -> Vec2 { Vec2::new(self.x - o.x, self.y - o.y) }
}

impl std::ops::Mul<f32> for Vec2 {
    type Output = Vec2;
    fn mul(self, s: f32) -> Vec2 { Vec2::new(self.x * s, self.y * s) }
}

fn lerp(a: f32, b: f32, t: f32) -> f32 { a + (b - a) * t }

struct PolishedCamera {
    pos: Vec2,
    vel: Vec2,
    target: Vec2,
    spring_k: f32,
    spring_c: f32,
    lookahead_factor: f32,
    lookahead_max: f32,
    idle_time: f32,
    fov: f32,
    base_fov: f32,
    max_fov_increase: f32,
    bounds: Option<(Vec2, Vec2)>,
    cushion: f32,
}

impl PolishedCamera {
    fn update(&mut self, player_pos: Vec2, player_vel: Vec2, dt: f32) {
        // Idle
        if player_vel.length() < 0.1 {
            self.idle_time += dt;
        } else {
            self.idle_time = 0.0;
        }
        
        // Lookahead
        let mut lookahead = self.lookahead_factor;
        if self.idle_time > 3.0 {
            let factor = ((self.idle_time - 3.0) * 0.5).min(1.0);
            lookahead = lerp(self.lookahead_factor, 0.0, factor);
        }
        
        let mut offset = player_vel * lookahead;
        if offset.length() > self.lookahead_max {
            offset = offset * (self.lookahead_max / offset.length());
        }
        
        self.target = player_pos + offset;
        
        // Boundary cushion
        let mut effective_k = self.spring_k;
        if let Some((min, max)) = self.bounds {
            let dist = (self.target.x - min.x)
                .min(max.x - self.target.x)
                .min(self.target.y - min.y)
                .min(max.y - self.target.y);
            if dist < self.cushion && dist > 0.0 {
                effective_k *= dist / self.cushion;
            }
        }
        
        // Spring
        let force_x = -effective_k * (self.pos.x - self.target.x) - self.spring_c * self.vel.x;
        let force_y = -effective_k * (self.pos.y - self.target.y) - self.spring_c * self.vel.y;
        
        self.vel.x += force_x * dt;
        self.vel.y += force_y * dt;
        self.pos.x += self.vel.x * dt;
        self.pos.y += self.vel.y * dt;
        
        // FOV
        let speed = player_vel.length();
        let target_fov = self.base_fov + (speed / 100.0).min(1.0) * self.max_fov_increase;
        self.fov = lerp(self.fov, target_fov, dt * 5.0);
        
        // Hard clamp
        if let Some((min, max)) = self.bounds {
            self.pos.x = self.pos.x.max(min.x).min(max.x);
            self.pos.y = self.pos.y.max(min.y).min(max.y);
        }
    }
}

fn main() {
    let mut cam = PolishedCamera {
        pos: Vec2::new(0.0, 0.0),
        vel: Vec2::new(0.0, 0.0),
        target: Vec2::new(0.0, 0.0),
        spring_k: 50.0,
        spring_c: 2.0 * 50.0_f32.sqrt(),
        lookahead_factor: 0.2,
        lookahead_max: 50.0,
        idle_time: 0.0,
        fov: 60.0,
        base_fov: 60.0,
        max_fov_increase: 15.0,
        bounds: Some((Vec2::new(-200.0, -200.0), Vec2::new(200.0, 200.0))),
        cushion: 50.0,
    };
    
    let dt = 1.0 / 60.0;
    
    // 模拟玩家移动
    println!("=== 玩家以速度 (50, 0) 移动 ===");
    for i in 0..60 {
        let player_pos = Vec2::new(i as f32 * 50.0 / 60.0, 0.0);
        let player_vel = Vec2::new(50.0, 0.0);
        cam.update(player_pos, player_vel, dt);
        if i % 10 == 0 {
            println!("  frame {}: player.x={:.1}, cam.x={:.1}, fov={:.1}",
                     i, player_pos.x, cam.pos.x, cam.fov);
        }
    }
    
    // 玩家停下
    println!("\n=== 玩家停下,看 recentering ===");
    let last_pos = Vec2::new(50.0, 0.0);
    for i in 0..300 {
        cam.update(last_pos, Vec2::new(0.0, 0.0), dt);
        if i % 30 == 0 {
            println!("  frame {}: cam.x={:.1}, idle_time={:.1}, fov={:.1}",
                     i, cam.pos.x, cam.idle_time, cam.fov);
        }
    }
    
    // 接近边界
    println!("\n=== 玩家接近边界 cushion ===");
    for i in 0..60 {
        let player_pos = Vec2::new(150.0 + i as f32 * 1.0, 0.0);
        let player_vel = Vec2::new(60.0, 0.0);
        cam.update(player_pos, player_vel, dt);
        if i % 10 == 0 {
            println!("  frame {}: player.x={:.1}, cam.x={:.1}",
                     i, player_pos.x, cam.pos.x);
        }
    }
}
```

```rust
mod tests {

    fn test_camera_follows_player() {

            cam.update(Vec2::new(0.0, 0.0), Vec2::new(100.0, 0.0), 1.0 / 60.0);
        }
        assert!(cam.fov > 65.0);    // 应增加

            spring_k: 50.0, spring_c: 14.0,

            bounds: None, cushion: 50.0,

            cam.update(Vec2::new(0.0, 0.0), Vec2::new(0.0, 0.0), 1.0 / 60.0);
```
