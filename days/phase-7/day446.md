# Day 446 · 生成可能的房间体积

> Day 445 工厂已经准备好。今天 Casey 开始填实世界生成器的第一个核心函数:`GenerateRoom`。它要回答一个具体问题:在游戏世界里,一个"房间"应该有多大?位置在哪?形状怎样?

## 0 · 为什么要有这一天

程序化生成(procedural generation)是现代游戏的灵魂。Spelunky 的关卡、《我的世界》的地形、《暗黑破坏神》的地下城,都是算法生成,不是美术手摆。优势:无限内容、玩家每次新体验、节省美术成本。

但程序化生成不是"瞎随机"。好的生成要满足几个约束:

第一,**可玩性**。房间不能小到无法站,不能大到跨越整个屏幕。
第二,**连通性**。每个房间必须能通过门进入,不能孤立。
第三,**多样性**。每个房间要不一样,有特征。
第四,**确定性**。给同一"种子"应该生成同样关卡,方便调试和分享。

Casey Day 446 解决最基础的:**怎么生成一个房间的"体积(volume)"**。体积就是 AABB(axis-aligned bounding box),一个矩形 3D 盒子。看似简单,但 Casey 把它做成可参数化、可扩展、可测试。

让我把程序化生成背后的"随机数与种子"理论讲深一点,因为这是整个 day446-450 的数学基础。

**伪随机数生成器(PRNG)**。计算机的"随机"其实是**伪随机**——给定一个种子(seed),RNG 用确定性算法生成一串"看起来随机"的数列。同样的种子永远产出同样的数列。

```rust
// 简化的 PCG (Permuted Congruential Generator)
struct Pcg32 {
    state: u64,
    inc: u64,
}

impl Pcg32 {
    fn new(seed: u64) -> Self {
        let mut rng = Self { state: 0, inc: (seed << 1) | 1 };
        rng.next();
        rng.state = rng.state.wrapping_add(seed);
        rng.next();
        rng
    }
    fn next(&mut self) -> u32 {
        let old = self.state;
        self.state = old.wrapping_mul(6364136223846793005).wrapping_add(self.inc);
        let xorshifted = (((old >> 18) ^ old) >> 27) as u32;
        let rot = (old >> 59) as u32;
        (xorshifted >> rot) | (xorshifted << ((32u32.wrapping_sub(rot)) & 31))
    }
    fn range(&mut self, lo: u32, hi: u32) -> u32 {
        lo + (self.next() % (hi - lo + 1))
    }
}

let mut rng = Pcg32::new(42);
let a = rng.range(8, 20);  // 12
let b = rng.range(8, 20);  // 17

let mut rng2 = Pcg32::new(42);  // 同样种子
let c = rng2.range(8, 20);  // 12 — 和 a 相同!
let d = rng2.range(8, 20);  // 17 — 和 b 相同!
```

**种子的工程价值**:

1. **可复现性**:玩家报告"我在房间 X 卡死了",你让他给你"种子号 12345",你在自己机器上跑种子 12345,**生成同一个房间**,可以 debug。
2. **多人同步**:多人游戏里,所有玩家从同一服务器拿到种子,各自生成同样的关卡,不用传输整个关卡数据(只传 8 字节种子)。
3. **存档**:存档不存整个世界,只存种子 + 玩家修改过的部分。Minecraft 存档就是这样——一个种子决定了整个世界。
4. **测试**:自动化测试用固定种子,验证"种子 100 应该生成 12 个房间"——这是回归测试。

**Rust 的 RNG 生态**:

- `rand` crate:标准库,RNG trait + 多个实现
- `rand_pcg`:PCG family,确定性,质量好,快
- `rand_chacha`:ChaCha8/12/20,加密级,慢但极可靠
- `splitmix64`:超简单,种子派生

游戏通常用 PCG 或 xorshift——快、确定性、质量足够。

**为什么不用系统熵(/dev/urandom)?** 系统熵是非确定性的——同一台机器两次运行可能给不同种子。这对**加密**好(防止预测),对**游戏可复现性**是灾难。游戏 RNG 必须是确定性 PRNG。

完成这一天后,你能做到:用 Rust 实现一个参数化的房间体积生成器(给定随机种子,返回合理大小、位置的 AABB),并能解释"种子可复现性"和"参数空间"两个概念。

## 2 · 心智模型

### 类比:画房间平面图

建筑师画房间平面图前,先决定:

- 房间多高?(层高)
- 房间在楼里哪个位置?(坐标)
- 房间形状?(矩形、L 形、圆形)

HH 现在选最简单的——矩形(AABB),尺寸在一个范围内随机。后面 Day 447+ 会加位置约束、连接、重叠检测。

### AABB 的严谨定义

**AABB(Axis-Aligned Bounding Box,轴对齐包围盒)** 是 3D 空间中边平行于 X/Y/Z 轴的矩形盒子。用两个点表示:`min = (x0, y0, z0)` 和 `max = (x1, y1, z1)`,要求每个分量 `min < max`。

为什么用 AABB 而不是 OBB(oriented bounding box,有向包围盒)或球?这是工程权衡:

**AABB 的优势**:
- 存储小(6 个 f32,vs OBB 需要 6 个 f32 + 4 元素 quaternion = 10 f32)
- 重叠检测简单:`a.max.x > b.min.x && a.min.x < b.max.x && ...`(3 个 && )
- 包含检测简单:6 个比较
- 内存友好(SIMD 一次装 4 个 f32)

**OBB 的优势**:
- 紧贴旋转物体(比如斜放的枪)
- 碰撞精度高

**球的优势**:
- 4 个 f32(center + radius)
- 旋转不变(球转一下还是球)
- 距离判定快

游戏实践:**AABB 用于关卡几何(墙、地板、房间)**,因为关卡是轴对齐的。**球用于简单碰撞检测(子弹、粒子)**。**OBB 用于精细碰撞(玩家身体、车辆)**,只在必要时用。

**AABB 重叠检测的几何直觉**。两个 AABB 重叠当且仅当在 X、Y、Z 三个轴上**都**重叠。在单个轴上"重叠"意味着 `a.min < b.max && b.min < a.max`(反过来也一样)。

```
   a.min.x           a.max.x
    |======a======|
                    |======b======|
              b.min.x           b.max.x

X 轴上 a.max.x > b.min.x 且 b.max.x > a.min.x → X 重叠
```

三个轴都重叠 → 3D AABB 重叠。这个算法极其快(6 个比较 + 2 个 AND),是游戏物理的基础。

**AABB 的并集和交集**:

```rust
impl AABB {
    fn union(&self, other: &AABB) -> AABB {
        AABB {
            min: Vec3::new(
                self.min.x.min(other.min.x),
                self.min.y.min(other.min.y),
                self.min.z.min(other.min.z),
            ),
            max: Vec3::new(
                self.max.x.max(other.max.x),
                self.max.y.max(other.max.y),
                self.max.z.max(other.max.z),
            ),
        }
    }
    
    fn intersects(&self, other: &AABB) -> bool {
        self.max.x > other.min.x && self.min.x < other.max.x &&
        self.max.y > other.min.y && self.min.y < other.max.y &&
        self.max.z > other.min.z && self.min.z < other.max.z
    }
}
```

`union` 在 BVH(bounding volume hierarchy,层次包围盒)树中是核心操作——多个 AABB 合一个父 AABB,用于快速剔除。

```rust
struct Vec3 { x: f32, y: f32, z: f32 }
struct AABB { min: Vec3, max: Vec3 }

impl AABB {
    fn new(min: Vec3, max: Vec3) -> Self { Self { min, max } }
    fn size(&self) -> Vec3 {
        Vec3 {
            x: self.max.x - self.min.x,
            y: self.max.y - self.min.y,
            z: self.max.z - self.min.z,
        }
    }
    fn center(&self) -> Vec3 {
        Vec3 {
            x: (self.min.x + self.max.x) * 0.5,
            y: (self.min.y + self.max.y) * 0.5,
            z: (self.min.z + self.max.z) * 0.5,
        }
    }
    fn contains(&self, p: Vec3) -> bool {
        p.x >= self.min.x && p.x <= self.max.x &&
        p.y >= self.min.y && p.y <= self.max.y &&
        p.z >= self.min.z && p.z <= self.max.z
    }
}
```

每行解释:
- `size()` — 从 min/max 算盒子尺寸,常用。
- `center()` — 中心点,用于绘制 / AI 寻路。
- `contains()` — 点是否在盒内,用于点击检测、碰撞预判。

### 参数空间:房间大小的范围

定义"合理大小"用范围:

```rust
const ROOM_WIDTH_MIN: f32 = 8.0;
const ROOM_WIDTH_MAX: f32 = 20.0;
const ROOM_HEIGHT_MIN: f32 = 3.0;
const ROOM_HEIGHT_MAX: f32 = 5.0;
const ROOM_DEPTH_MIN: f32 = 8.0;
const ROOM_DEPTH_MAX: f32 = 20.0;

fn random_in_range(rng: &mut Pcg32, min: f32, max: f32) -> f32 {
    let r = rng.next_u32() as f32 / u32::MAX as f32;  // [0, 1]
    min + r * (max - min)
}
```

让我把"参数空间"这个核心概念讲透,这是程序化生成的灵魂。

**参数空间(parameter space)** 是你的生成器所有"可调旋钮"的组合。HH 房间生成器有这些旋钮:

```
(ROOM_WIDTH_MIN, ROOM_WIDTH_MAX)    → 宽度范围
(ROOM_HEIGHT_MIN, ROOM_HEIGHT_MAX)  → 高度范围
(ROOM_DEPTH_MIN, ROOM_DEPTH_MAX)    → 深度范围
(GROUND_Y)                          → 地面高度
SEED                                → RNG 种子
```

每个旋钮是一个"维度",所有维度构成一个**多维空间**。生成器从这个空间里取一个点(具体参数值),输出一个房间。

**为什么思考参数空间?**

第一,**调参就是探索空间**。游戏设计师说"房间太大",你把 `ROOM_WIDTH_MAX` 从 20 改到 15,你是在参数空间里"移动"。每个改动产出不同分布的房间。

第二,**参数空间决定多样性**。如果三个 min/max 都紧贴(比如 width 都在 [9.9, 10.1]),房间几乎一样大,玩家觉得重复。范围宽(比如 [5, 30]),变化大,但风险是出现"怪异房间"(太大太小)。

第三,**好的参数空间来自经验**。你不能凭空想出 [8, 20] 这个范围——你要让玩家实际玩,观察哪些房间"舒服",哪些"别扭",反推范围。这是 game design 和 code 的接口。

**实战调参**。Casey HH 这种小项目,参数手调。商业游戏用 **data-driven**:房间范围在 JSON / TOML 里:

```json
{
  "room_width": [8.0, 20.0],
  "room_height": [3.0, 5.0],
  "room_depth": [8.0, 20.0]
}
```

策划改 JSON 不用重编译,实时调参。游戏发布后,玩家也可以 mod(改 JSON)。

**参数空间的极端**:每个参数都是连续的(实数),组合空间无限。但你只取"合理"的子集。一个 3 维连续参数 + 8 维种子 = 11 维空间。可视化 11 维很难,所以工程上用**采样**:随机取 N 个点,人工评估每个生成的房间,标"好/坏",反推"好参数"区域。

这是 machine learning 在游戏生成里的应用——但 HH 不需要,Casey 手调就够。

### 区间缩放:从 [0,1] 到任意范围

```rust
fn random_in_range(rng: &mut Pcg32, min: f32, max: f32) -> f32 {
    let r = rng.next_u32() as f32 / u32::MAX as f32;  // [0, 1]
    min + r * (max - min)
}
```

让我把"如何把均匀分布的 [0,1] 映射到任意范围"讲清楚,这是所有 PRNG 包装的基础。

**线性映射**:`[0, 1] → [min, max]`,公式 `min + r * (max - min)`。

```
r = 0      →  min
r = 0.5    →  (min + max) / 2
r = 1      →  max
```

这是均匀分布的线性变换——如果 r 在 [0,1] 均匀,output 在 [min, max] 均匀。

**整数范围**:`[0, 2^32 - 1] → [lo, hi]`:

```rust
fn random_int_range(rng: &mut Pcg32, lo: u32, hi: u32) -> u32 {
    lo + (rng.next_u32() % (hi - lo + 1))
}
```

`% (hi - lo + 1)` 是模运算,把 [0, 2^32) 压缩到 [0, hi - lo]。但有**偏差**(modulo bias)——如果 `2^32` 不能整除 `hi - lo + 1`,低值出现概率比高值略高。`rand` crate 用更复杂的算法消除这个偏差。

**非均匀分布**:游戏里很多场景需要**非均匀**随机:

```rust
// 高斯分布(正态分布):多数在中心,少数在两端
fn random_gaussian(rng: &mut Pcg32, mean: f32, std_dev: f32) -> f32 {
    // Box-Muller transform
    let u1 = rng.next_f32();
    let u2 = rng.next_f32();
    let z0 = (-2.0 * u1.ln()).sqrt() * (2.0 * std::f32::consts::PI * u2).cos();
    mean + z0 * std_dev
}

// 三角分布:中点最可能,两端线性衰减
fn random_triangular(rng: &mut Pcg32, min: f32, mode: f32, max: f32) -> f32 {
    let u = rng.next_f32();
    let fc = (mode - min) / (max - min);
    if u < fc {
        min + ((max - min) * (mode - min) * u).sqrt()
    } else {
        max - ((max - min) * (max - mode) * (1.0 - u)).sqrt()
    }
}
```

游戏设计师常用**三角分布**——比均匀"自然"(多数中间),比高斯"可控"(没有长尾)。HH 简化用均匀就够,但工业项目大量用三角。

```rust
fn generate_room_volume(rng: &mut Pcg32, origin: Vec3) -> AABB {
    let width = random_in_range(rng, ROOM_WIDTH_MIN, ROOM_WIDTH_MAX);
    let height = random_in_range(rng, ROOM_HEIGHT_MIN, ROOM_HEIGHT_MAX);
    let depth = random_in_range(rng, ROOM_DEPTH_MIN, ROOM_DEPTH_MAX);
    AABB {
        min: origin,
        max: Vec3 {
            x: origin.x + width,
            y: origin.y + height,
            z: origin.z + depth,
        },
    }
}
```

每行解释:
- `next_u32() as f32 / u32::MAX as f32` — 把 u32 随机数映射到 [0, 1] 浮点。这是标准 uniform [0,1] 采样。
- `min + r * (max - min)` — [0, 1] 映射到 [min, max],线性插值。
- `AABB { min: origin, max: origin + size }` — 用 origin 作为 min,max 自动算。

### 种子可复现性

```rust
let mut rng = Pcg32::new(42, 1);  // 种子 42, 序列 1
let room1 = generate_room_volume(&mut rng, Vec3::ZERO);
// 输出永远是同样的 AABB

let mut rng2 = Pcg32::new(42, 1);
let room2 = generate_room_volume(&mut rng2, Vec3::ZERO);
// room2 == room1
```

**为什么重要?**
- 调试:发现 bug 时可以重现完全相同的房间
- 多人:玩家 A 和玩家 B 用同一种子得到同一关卡
- 持久化:存档只存种子,不存整个关卡

**坑**:**RNG 调用顺序**决定输出。如果你在生成 room 1 中调了 RNG 5 次,生成 room 2 的 RNG 状态就变了——room 2 的输出依赖前面所有调用。**对策**:每个房间用独立的 Pcg32 实例,种子派生自"房间 ID + 全局种子":

```rust
fn generate_room(global_seed: u64, room_id: usize) -> Room {
    let room_seed = global_seed.wrapping_add(room_id as u64 * 0x9E3779B97F4A7C15);
    let mut rng = Pcg32::new(room_seed, 1);
    // ... 生成 room,只在这里用 rng ...
}
```

这样每个房间的生成是独立的,改变 room 1 不会影响 room 2 的输出。

### 黄金比例常数 `0x9E3779B97F4A7C15`

这个魔法常数是 `2^64 / φ`(φ 是黄金比例)。它能让"递增输入产生伪随机分布",常用于 hash 函数。Knuth 推荐。

## 3 · 四域深入

### 3.1 · 游戏编程视角

程序化生成主流技术:

- **随机分布(本日)**:最简单,适合物品掉落
- **L-system**:形式语法递归,适合植物
- **Perlin/Simplex noise**:柏林噪声,适合地形
- **Wave Function Collapse**:基于约束,适合关卡
- **Grammar-based**:图形语法,适合城市

HH 用最基础的随机分布 + 后面的约束检查。这是教学最清晰的方案。

**工业坑**:
- **生成的房间可能不可达**:需要连通性验证
- **生成的房间可能重叠**:Day 449 解决
- **生成的房间可能太多/太少**:需要密度参数
- **生成的房间可能千篇一律**:多样性指标

### 3.2 · 图形学视角

AABB 是图形学最常用的几何原语之一:

- **视锥剔除(frustum culling)**:物体 AABB 是否在相机视锥内
- **碰撞检测**:AABB-AABB 快速检测,OBB 或 mesh 后续精确
- **BVH(Bounding Volume Hierarchy)**:加速结构,AABB 套 AABB
- **GJK / SAT**:复杂形状碰撞,常用 AABB 预判

AABB 的优势:**算法极简**——所有计算只比较坐标。OBB(orient bounding box)更紧,但旋转一次开销大。游戏中大量用 AABB,少数精确碰撞用 OBB / mesh。

### 3.3 · Linux 系统编程视角

Linux 内核里有大量"AABB 类似"结构:
- `struct region`(内存管理)是区间 [start, end]
- `struct resource`(I/O 资源)是 [start, end]
- `struct vm_area_struct`(虚拟内存)是 [start, end]

3D AABB 是 1D 区间的三维扩展,概念相同。

### 3.4 · Rust 生态视角

Rust 数学库的 AABB:

```rust
// glam
use glam::Vec3;
struct AABB { min: Vec3, max: Vec3 }

// 或用 bounding_b prof crate
use parry3d::bounding_volume::Aabb;
let aabb = Aabb::new(Vec3::new(0.0, 0.0, 0.0), Vec3::new(1.0, 1.0, 1.0));
```

`parry3d` / `ncollide` 是 Rust 的碰撞检测库,提供工业级 AABB 和 BVH。Casey HH 手写,所以教学清晰。

**Rust 的整数溢出**:注意 `room_id as u64 * 0x9E37...` 可能在 `room_id` 大时溢出。Rust 默认 debug panic、release 截断。这里用 `wrapping_mul/add` 显式截断,符合 hash 函数需要。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么每个房间用独立 RNG,而不是所有房间共享一个?如果共享会怎样?

**参考解答**:共享 RNG 时,房间 N 的输出依赖前面 N-1 个房间的 RNG 调用次数。如果你修改了 room 1 的代码(比如增加一次 RNG 调用决定房间特征),room 2..N 的输出全部变化——这是"级联失败"。

每个房间独立 RNG:`rng_n = Pcg32::new(global_seed + n * constant, 1)`。修改 room 1 不影响其他房间。这是**软件工程**的关键原则:**减少耦合**。

### Lv2 · 动手实践

**题**:实现 `generate_room_volume`,生成 10 个房间,每个房间用独立 RNG,种子 = global_seed + room_index。验证:改变 room 5 的代码不影响 room 6..9 的输出。

**参考解答**:

```rust
struct Pcg32 {
    state: u64,
    inc: u64,
}
impl Pcg32 {
    fn new(seed: u64, seq: u64) -> Self {
        let mut r = Self { state: 0, inc: (seq << 1) | 1 };
        r.next();
        r.state = r.state.wrapping_add(seed);
        r.next();
        r
    }
    fn next(&mut self) -> u32 {
        let old = self.state;
        self.state = old.wrapping_mul(6364136223846793005).wrapping_add(self.inc);
        let xorshifted = (((old >> 18) ^ old) >> 27) as u32;
        let rot = (old >> 59) as u32;
        (xorshifted >> rot) | (xorshifted << ((!rot).wrapping_add(1) & 31))
    }
    fn next_f32(&mut self) -> f32 {
        self.next() as f32 / u32::MAX as f32
    }
}

#[derive(Debug, Clone, Copy)]
struct Vec3 { x: f32, y: f32, z: f32 }

#[derive(Debug, Clone, Copy)]
struct AABB { min: Vec3, max: Vec3 }

const WIDTH_MIN: f32 = 8.0;
const WIDTH_MAX: f32 = 20.0;
const HEIGHT_MIN: f32 = 3.0;
const HEIGHT_MAX: f32 = 5.0;
const DEPTH_MIN: f32 = 8.0;
const DEPTH_MAX: f32 = 20.0;

fn range(rng: &mut Pcg32, min: f32, max: f32) -> f32 {
    min + rng.next_f32() * (max - min)
}

fn generate_room_volume(global_seed: u64, room_idx: usize, origin: Vec3) -> AABB {
    // 每个房间独立 RNG,种子派生自 room_idx
    let room_seed = global_seed.wrapping_add(
        (room_idx as u64).wrapping_mul(0x9E3779B97F4A7C15)
    );
    let mut rng = Pcg32::new(room_seed, 1);
    let w = range(&mut rng, WIDTH_MIN, WIDTH_MAX);
    let h = range(&mut rng, HEIGHT_MIN, HEIGHT_MAX);
    let d = range(&mut rng, DEPTH_MIN, DEPTH_MAX);
    AABB {
        min: origin,
        max: Vec3 { x: origin.x + w, y: origin.y + h, z: origin.z + d },
    }
}

fn main() {
    let global_seed = 42;
    for i in 0..10 {
        let room = generate_room_volume(global_seed, i, Vec3 { x: 0.0, y: 0.0, z: 0.0 });
        println!("Room {}: min=({:.1},{:.1},{:.1}) max=({:.1},{:.1},{:.1})",
            i, room.min.x, room.min.y, room.min.z,
            room.max.x, room.max.y, room.max.z);
    }

    // 验证可复现性
    let r1 = generate_room_volume(42, 5, Vec3::ZERO);
    let r2 = generate_room_volume(42, 5, Vec3::ZERO);
    assert_eq!(r1.min.x, r2.min.x);
    assert_eq!(r1.max.x, r2.max.x);
    println!("Reproducibility OK");
}
```

每行解释:
- `(room_idx as u64).wrapping_mul(0x9E37...)` — 用 Knuth 常数让索引"扩散"成不同种子。
- `Pcg32::new(room_seed, 1)` — 每个房间新 RNG,seq=1(序列标识)。
- `assert_eq!` 验证同样种子同样输出。

```rust
#[derive(Debug, Clone, Copy)]
struct Vec3 { x: f32, y: f32, z: f32 }

impl Vec3 {
    const ZERO: Self = Self { x: 0.0, y: 0.0, z: 0.0 };
}

#[derive(Debug, Clone, Copy)]
struct AABB { min: Vec3, max: Vec3 }

impl AABB {
    fn size(&self) -> Vec3 {
        Vec3 {
            x: self.max.x - self.min.x,
            y: self.max.y - self.min.y,
            z: self.max.z - self.min.z,
        }
    }
}

struct Pcg32 { state: u64, inc: u64 }

impl Pcg32 {
    fn new(seed: u64, seq: u64) -> Self {
        let mut r = Self { state: 0, inc: (seq << 1) | 1 };
        r.next();
        r.state = r.state.wrapping_add(seed);
        r.next();
        r
    }
    fn next(&mut self) -> u32 {
        let old = self.state;
        self.state = old.wrapping_mul(6364136223846793005).wrapping_add(self.inc);
        let xs = (((old >> 18) ^ old) >> 27) as u32;
        let rot = (old >> 59) as u32;
        (xs >> rot) | (xs << ((!rot).wrapping_add(1) & 31))
    }
    fn next_f32(&mut self) -> f32 {
        self.next() as f32 / u32::MAX as f32
    }
}

fn range(rng: &mut Pcg32, min: f32, max: f32) -> f32 {
    min + rng.next_f32() * (max - min)
}

const ROOM_W: (f32, f32) = (8.0, 20.0);
const ROOM_H: (f32, f32) = (3.0, 5.0);
const ROOM_D: (f32, f32) = (8.0, 20.0);

fn generate_room_volume(seed: u64, idx: usize, origin: Vec3) -> AABB {
    let room_seed = seed.wrapping_add((idx as u64).wrapping_mul(0x9E3779B97F4A7C15));
    let mut rng = Pcg32::new(room_seed, 1);
    let w = range(&mut rng, ROOM_W.0, ROOM_W.1);
    let h = range(&mut rng, ROOM_H.0, ROOM_H.1);
    let d = range(&mut rng, ROOM_D.0, ROOM_D.1);
    AABB {
        min: origin,
        max: Vec3 { x: origin.x + w, y: origin.y + h, z: origin.z + d },
    }
}

fn main() {
    println!("=== 10 rooms with seed=42 ===");
    for i in 0..10 {
        let room = generate_room_volume(42, i, Vec3::ZERO);
        let s = room.size();
        println!("Room {}: {:.1}x{:.1}x{:.1} m", i, s.x, s.y, s.z);
    }

    println!("\n=== Same rooms with seed=43 (different) ===");
    for i in 0..3 {
        let room = generate_room_volume(43, i, Vec3::ZERO);
        let s = room.size();
        println!("Room {}: {:.1}x{:.1}x{:.1} m", i, s.x, s.y, s.z);
    }

    // 验证可复现
    println!("\n=== Reproducibility check ===");
    let r1 = generate_room_volume(42, 3, Vec3::ZERO);
    let r2 = generate_room_volume(42, 3, Vec3::ZERO);
    assert_eq!(r1.max.x, r2.max.x);
    println!("OK: same seed -> same room");

    // 验证不同房间独立
    println!("\n=== Independence check ===");
    let r5_a = generate_room_volume(42, 5, Vec3::ZERO);
    let r5_b = generate_room_volume(42, 5, Vec3::ZERO);
    assert_eq!(r5_a.max.x, r5_b.max.x);
    println!("OK: room 5 is independent of room 1-4");
}
```

每行解释:
- `Vec3::ZERO` 常量,作为 origin 默认。
- 两次循环用相同 idx 不同 seed,验证种子影响输出。
- `r5_a` 和 `r5_b` 独立调用,得到相同结果,验证 RNG 独立性。
