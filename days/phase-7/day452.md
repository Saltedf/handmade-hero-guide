
# Day 452 · 改进相机放置与房间对齐

> 迷宫生成器跑得通了,但相机经常被墙挡住、视角不舒服。今天 Casey 优化相机放置:让相机在房间里自动找最佳位置,避免穿墙,并改善玩家在房间之间的视觉过渡。

## 0 · 为什么要有这一天

经过 Day 444-451,Casey 有了能生成 3D 迷宫的代码。但试玩发现:相机经常被门洞卡住,或者玩家进入新房时相机穿墙。这些不是迷宫的问题,是**相机策略**的问题。

游戏相机的工业级问题:

第一,**相机碰撞**。相机不能穿墙。当玩家背靠墙时,相机要"贴"在前面,不能往后看穿墙。
第二,**视野最大化**。相机位置要让玩家看到最多有用信息(怪物、出口、物品),不被墙挡。
第三,**平滑过渡**。房间之间相机要平滑切换,不要瞬移或抖动。
第四,**自动化**。设计师不可能每个房间手摆相机,要算法自动找位置。

Casey Day 452 用一个简单算法:**相机在玩家正后方 + 上方,用射线检测确保不被墙挡**。

让我把"第三人称跟随相机"的核心问题彻底讲清楚,这是 Day 452 的算法基础。

**理想相机位置**。第三人称相机通常在玩家**正后方 + 上方**——比如玩家后方 4 米,上方 2 米。这样玩家在画面中央偏下,前方视野广阔。

```rust
struct ThirdPersonCamera {
    target_pos: Vec3,        // 玩家位置
    target_orientation: Quat, // 玩家朝向
    distance: f32,           // 相机离玩家距离(如 4.0)
    height: f32,             // 相机高度(如 2.0)
}

fn ideal_camera_pos(cam: &ThirdPersonCamera) -> Vec3 {
    let forward = cam.target_orientation * Vec3::new(0.0, 0.0, -1.0);
    let back = -forward;
    cam.target_pos + back * cam.distance + Vec3::new(0.0, cam.height, 0.0)
}
```

**问题**:理想位置可能在墙里。玩家背靠墙时,"正后方"就是墙内。

**相机碰撞检测**。从玩家位置发射一条射线,方向"理想相机位置 - 玩家位置",长度 = camera_distance。射线和墙求交:

- 如果没相交,相机在理想位置(正常)。
- 如果相交,相机放在**交点 + 一点偏移**(贴墙前)。

```rust
fn camera_pos_with_collision(
    cam: &ThirdPersonCamera,
    walls: &[AABB],
) -> Vec3 {
    let ideal = ideal_camera_pos(cam);
    let direction = (ideal - cam.target_pos).normalize();
    let distance = cam.target_pos.distance(ideal);
    
    // 射线:从玩家朝理想方向
    let ray = Ray { origin: cam.target_pos, direction };
    
    // 找最近墙的相交距离
    let mut hit_distance = distance;
    for wall in walls {
        if let Some(t) = ray_aabb_intersect(&ray, wall) {
            if t < hit_distance {
                hit_distance = t;
            }
        }
    }
    
    // 相机放在 hit_distance - margin(避免穿墙)
    let margin = 0.2;
    let safe_distance = (hit_distance - margin).max(0.5);
    cam.target_pos + direction * safe_distance
}
```

**平滑过渡**。理想相机位置每帧变化(玩家移动),但相机不能瞬移——会头晕。用**插值**让相机平滑跟随:

```rust
struct CameraState {
    current_pos: Vec3,
    target_pos: Vec3,
    smoothing: f32,  // 0=不跟随, 1=立即跟随, 中间值=平滑
}

impl CameraState {
    fn update(&mut self, dt: f32) {
        let alpha = 1.0 - (-self.smoothing * dt).exp();
        self.current_pos = self.current_pos.lerp(self.target_pos, alpha);
    }
}
```

`lerp` + 指数衰减是游戏平滑的标准技巧——`alpha = 1 - exp(-k*dt)` 保证 FPS 无关(60 FPS 和 144 FPS 行为一致)。

**工业第三人称相机的复杂度**。Casey Day 452 简化版只是入门。商业游戏(GTA、Dark Souls、Splatoon)的相机系统有这些额外特性:

1. **多个相机目标**:不一定是玩家,可能是 boss 战的"瞄准点"
2. **相机 shake**:爆炸、伤害时的相机震动
3. **FOV 动画**:跑步时 FOV 扩大,营造速度感
4. **自动转视角**:进入房间时相机自动旋转到"最佳角度"
5. **手动 override**:玩家用右摇杆手动转,松手后回正
6. **避障躲避**:不只是射线检测,是空间搜索(找最近的"无遮挡点")
7. **预测**:根据玩家速度预测下一帧位置,相机提前移动避免抖动

**典型相机 bug**:

- **穿墙**:射线没检测到所有墙(只检测了玩家附近)
- **抖动**:smoothing 太小,相机跟玩家位置高频变化
- **卡顿**:相机被某物"卡住",玩家走远了相机没跟上
- **失向**:相机突然旋转,玩家失去方向感

商业游戏专门有"camera engineer"岗位,几十人团队只做相机。

## 补充:相机系统的设计模式

让我总结工业游戏里相机系统的几个常见模式,这是 Day 452 的扩展。

**模式 1:固定相机(Resident Evil 风格)**。每个房间一个固定相机位置,玩家进房间就切换。优势:电影感强(可以精心设计镜头),劣势:玩家失去控制感。

**模式 2:第一人称相机(FPS)**。相机就在玩家眼睛位置,无第三人称模型。简单无穿墙,但看不见自己。Day 443 之前的 HH 是这种。

**模式 3:第三人称跟随相机(GTA、Mario 64)**。本日主题。相机在玩家后上方,跟随玩家移动。

**模式 4:轨道相机(Souls 系列)**。相机围绕玩家旋转,玩家可以手动控制。比固定跟随灵活,但复杂。

**模式 5:isometric 相机(Diablo、Age of Empires)**。固定角度(通常是 45 度俯视),玩家在屏幕中心。RTS 和 ARPG 标准。

**模式 6:自由相机(debug)**。开发者用,不受任何约束。Casey HH 的 debug mode 用。

**相机切换的过渡**。游戏经常在多种相机模式间切换——比如 GTA 步行是第三人称,上车切到车内相机。切换要平滑:

```rust
enum CameraMode {
    FirstPerson(CameraState),
    ThirdPerson(ThirdPersonState),
    Isometric(IsoState),
}

impl CameraMode {
    fn transition_to(&mut self, new_mode: CameraMode, duration: f32) {
        // 启动一个 transition,在 duration 内平滑切换
    }
}
```

过渡用 slerp(球面线性插值,对朝向)+ lerp(线性插值,对位置)。

**相机 shake**。爆炸、撞击时的"震动"——给相机位置加随机偏移:

```rust
fn shake(camera: &mut CameraState, intensity: f32, decay: f32, dt: f32) {
    let offset = Vec3::new(
        rng::random(-1.0, 1.0),
        rng::random(-1.0, 1.0),
        rng::random(-1.0, 1.0),
    ) * intensity;
    camera.position += offset;
    // intensity 随时间衰减
}
```

工业实现用 Perlin noise 而不是纯随机——更平滑、可控。

**FOV 动画**。跑步时 FOV 从 70 扩到 90,营造速度感:

```rust
fn update_fov(camera: &mut Camera, player_speed: f32, dt: f32) {
    let target_fov = 70.0 + (player_speed / MAX_SPEED) * 20.0;
    camera.fov += (target_fov - camera.fov) * dt * 5.0;
}
```

这些扩展让相机系统从"跟随"升级到"表达"——相机不只是工具,是体验的一部分。

## 补充:相机 ray cast 的精确实现

让我把"相机射线检测墙"的精确实现讲清楚——这是 Day 452 算法的关键步骤。

**算法**。给定玩家位置 P 和理想相机位置 I,从 P 射向 I。沿途检测墙:

```rust
fn camera_collision_check(
    player_pos: Vec3,
    ideal_cam_pos: Vec3,
    walls: &[AABB],
) -> Vec3 {
    let direction = ideal_cam_pos - player_pos;
    let distance = direction.length();
    if distance < 0.001 { return ideal_cam_pos; }
    let direction = direction / distance;  // 单位向量
    
    let ray = Ray {
        origin: player_pos,
        direction,
    };
    
    let mut t_max = distance;
    for wall in walls {
        // 用一个"球"代表相机(半径 camera_radius)
        // 射线-AABB 交点,加上 camera_radius 的偏移
        let expanded_wall = AABB {
            min: wall.min - Vec3::splat(CAMERA_RADIUS),
            max: wall.max + Vec3::splat(CAMERA_RADIUS),
        };
        if let Some(t) = ray_aabb_intersect(&ray, &expanded_wall) {
            if t < t_max {
                t_max = t;
            }
        }
    }
    
    // 相机放在 t_max - margin 处
    player_pos + direction * (t_max - CAMERA_MARGIN).max(0.5)
}
```

**关键细节**:

1. **camera_radius**:相机不是点,有体积。把墙扩展 camera_radius,等效"相机中心离墙至少 camera_radius"。
2. **margin**:相机离墙再留点余量(避免视觉上贴近)。
3. **max(0.5)**:最小距离,避免相机贴脸玩家(完全失向)。

**问题:墙不连续**。多个墙拼成"墙链",可能有缝。射线可能从缝穿过,导致相机瞬移。**对策**:用 sweep test 而非 ray test——一段连续的胶囊形状 vs 墙。

**问题:相机卡在角落**。玩家在 L 形角落,所有方向都撞墙。相机可能完全看不到玩家。**对策**:fallback 到第一人称(相机在玩家头部)。

**问题:相机"穿越"瞬时**。玩家快速移动,相机一帧从位置 A 跳到 B,中间没检测,可能穿墙。**对策**:连续 sweep——从 A 到 B 多步检测,确保整条路径无碰撞。

这些是工业 camera collision 的细节。Casey HH 简化版只演示基本原理。

## 1 · Casey 今天做了什么

Casey 这一天的动作分四步:

第一,他定义相机目标位置:玩家位置 + 玩家朝向的反方向 * 距离 + 上偏移。比如距离 5 米、高 3 米。

## 2 · 心智模型

### 类比:摄影师跟随演员

拍纪录片的摄影师扛着相机跟演员走。他要:
- 保持适当距离(不远不近)
- 在演员背后稍偏(能看到演员脸和前方)
- 不撞墙、不撞家具
- 演员突然转向时,相机滞后一点点(平滑过渡)

游戏相机就是这种"虚拟摄影师"。

### 严谨原理:第三人称跟随相机

**目标位置计算**:

```rust
struct Camera {
    position: Vec3,
    orientation: Quat,
}

fn compute_camera_target(
    player_pos: Vec3,
    player_forward: Vec3,
    distance: f32,
    height: f32,
) -> Vec3 {
    // 相机在玩家正后方 distance 米,高 height 米
    player_pos - player_forward * distance + Vec3::Y * height
}
```

每行解释:
- `player_pos - player_forward * distance` — 玩家位置往"背后"走 distance 米。"背后" = forward 反方向。
- `+ Vec3::Y * height` — 加高度,相机俯视玩家。

**碰撞检测(相机推回)**:

```rust
fn adjust_for_collision(
    camera_target: Vec3,
    player_pos: Vec3,
    walls: &[AABB],
) -> Vec3 {
    // 从玩家到目标的射线
    let direction = camera_target - player_pos;
    let max_dist = direction.length();
    let direction = direction.normalize();
    
    let mut adjusted_dist = max_dist;
    for wall in walls {
        if let Some(t) = ray_aabb_intersect(player_pos, direction, wall) {
            if t < adjusted_dist {
                adjusted_dist = t - 0.1;  // 留 10cm 间隙
            }
        }
    }
    player_pos + direction * adjusted_dist.max(0.5)  // 至少 50cm,防止贴脸
}
```

每行解释:
- 对每堵墙算射线-AABB 交,取最近的。
- `adjusted_dist - 0.1` 留小间隙,避免相机"贴墙"画到墙里。
- `.max(0.5)` 防止玩家完全被墙包围时相机变成 0 距离。

**平滑过渡**:

```rust
fn smooth_update(camera: &mut Camera, target: Vec3, dt: f32) {
    let smoothing = 5.0;  // 越大越"硬"(响应快)
    let alpha = 1.0 - (-smoothing * dt).exp();
    camera.position = camera.position.lerp(target, alpha);
}
```

每行解释:
- `lerp(a, b, t) = a + (b-a) * t` 线性插值。
- `alpha = 1 - exp(-smoothing * dt)` 是"指数平滑",帧率独立。dt=1/60 时 alpha ≈ 0.078,每帧拉近 7.8%。
- 越大的 smoothing 越快接近目标(响应快但抖),越小越慢(平滑但滞后)。

### Ray-AABB 相交(Slab method)

```rust
fn ray_aabb_intersect(origin: Vec3, dir: Vec3, aabb: &AABB) -> Option<f32> {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    
    for axis in 0..3 {
        let o = [origin.x, origin.y, origin.z][axis];
        let d = [dir.x, dir.y, dir.z][axis];
        let min = [aabb.min.x, aabb.min.y, aabb.min.z][axis];
        let max = [aabb.max.x, aabb.max.y, aabb.max.z][axis];
        
        if d.abs() < 1e-6 {
            // 射线和这个轴平行,不在 slab 内 → 不相交
            if o < min || o > max { return None; }
        } else {
            let t1 = (min - o) / d;
            let t2 = (max - o) / d;
            let (t1, t2) = if t1 > t2 { (t2, t1) } else { (t1, t2) };
            t_min = t_min.max(t1);
            t_max = t_max.min(t2);
            if t_min > t_max { return None; }
        }
    }
    
    if t_min < 0.0 { None } else { Some(t_min) }
}
```

每行解释:
- **Slab method**:对每个轴,计算射线进入/离开 AABB 在该轴的"slab"(平行平面之间的区域)的时间。三个轴的"进入时间"取最大,"离开时间"取最小。
- 如果"最大进入时间 ≤ 最小离开时间",射线穿过 AABB。
- `t_min < 0` 说明交点在射线背后(从原点反向才算),不算相交。
- 复杂度 O(1) per query。

### 视野最大化(进阶)

工业级相机系统还考虑:
- **多候选位置**:在玩家周围撒 N 个候选位置,选视野最大的
- **可见性查询**:每个候选位置渲染"深度 buffer",计算"未被墙挡的像素数",选最大的
- **遮挡查询(GL_occlusion_query)**:GPU 异步查询物体是否被遮挡

Casey HH 不做到这种程度,只用单条射线。

## 3 · 四域深入

### 3.1 · 游戏编程视角

第三人称相机系统是游戏开发大坑。经典游戏:

- **Mario 64**:第一个现代 3D 第三人称相机,Lakitu 云
- **GTA**:动态相机 + 玩家手动微调
- **Souls 系列**:锁定敌人时相机优先,墙后自动调
- **Zelda: Breath of the Wild**:开放世界相机,自动避障

**坑**:
- **相机在墙外**:玩家在室内,相机被推到室外,看穿墙
- **相机抖动**:每帧位置剧烈变化,玩家晕眩
- **视野被挡**:小空间里相机被墙挤,看不到玩家
- **相机和 AI 失同步**:玩家加速,相机跟不上

工业方案:
- **Spring arm**(虚幻引擎):弹簧臂模型,射线探测自动缩短
- **Camera collision volume**:相机周围一个碰撞球,被墙推回
- **Adaptive FOV**:小空间自动放大 FOV,避免挤

### 3.2 · 图形学视角

Ray-AABB 相交是图形学最常见的几何查询:

- **光线追踪(ray tracing)**:每像素发射线,扫 BVH 找最近交点
- **阴影射线**:点光源朝场景发射线,有遮挡 = 阴影
- **可见性测试**:物体是否被遮挡(GL occlusion query)
- **鼠标拾取**:unproject + ray-AABB(本日)

Slab method 是标准算法,出现在每个图形学教材。

### 3.3 · Linux 系统编程视角

"相机平滑"对应 Linux 上的输入平滑:

- **鼠标加速**:`xset m acceleration`(legacy)或 libinput 配置
- **滚轮惯性**:`kernel evdev` 自带平滑
- **触摸板手势**:`libinput` 用物理模型做惯性

游戏自己处理平滑,不依赖桌面环境(否则不同发行版行为不同)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么用 `1 - exp(-smoothing * dt)` 而不是直接 `smoothing * dt`?

**参考解答**:线性 `smoothing * dt` 在 dt 大时(低帧率)会超过 1,导致 overshoot(超过目标)。指数 `1 - exp(-smoothing * dt)` 永远 < 1,任何帧率都不会 overshoot。这就是"帧率独立"平滑的本质——指数衰减是自然界 RC 电路、阻尼振动的标准模型。

### Lv2 · 动手实践

**题**:实现完整的第三人称跟随相机,玩家在 (0, 0, 0),朝 +X 走,墙在玩家背后 5 米。验证相机被推到墙前(不穿墙)。

**参考解答**:

```rust
#[derive(Debug, Clone, Copy)]
struct Vec3 { x: f32, y: f32, z: f32 }

impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn length(self) -> f32 {
        (self.x*self.x + self.y*self.y + self.z*self.z).sqrt()
    }
    fn normalize(self) -> Self {
        let l = self.length();
        Self { x: self.x/l, y: self.y/l, z: self.z/l }
    }
    fn lerp(self, other: Self, t: f32) -> Self {
        Self {
            x: self.x + (other.x - self.x) * t,
            y: self.y + (other.y - self.y) * t,
            z: self.z + (other.z - self.z) * t,
        }
    }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
}

impl std::ops::Add for Vec3 {
    type Output = Self;
    fn add(self, o: Self) -> Self { Self { x: self.x+o.x, y: self.y+o.y, z: self.z+o.z } }
}

impl std::ops::Sub for Vec3 {
    type Output = Self;
    fn sub(self, o: Self) -> Self { Self { x: self.x-o.x, y: self.y-o.y, z: self.z-o.z } }
}

impl std::ops::Mul<f32> for Vec3 {
    type Output = Self;
    fn mul(self, k: f32) -> Self { Self { x: self.x*k, y: self.y*k, z: self.z*k } }
}

#[derive(Debug, Clone, Copy)]
struct AABB { min: Vec3, max: Vec3 }

fn ray_aabb_intersect(origin: Vec3, dir: Vec3, aabb: &AABB) -> Option<f32> {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    let os = [origin.x, origin.y, origin.z];
    let ds = [dir.x, dir.y, dir.z];
    let mins = [aabb.min.x, aabb.min.y, aabb.min.z];
    let maxs = [aabb.max.x, aabb.max.y, aabb.max.z];
    for i in 0..3 {
        if ds[i].abs() < 1e-6 {
            if os[i] < mins[i] || os[i] > maxs[i] { return None; }
        } else {
            let t1 = (mins[i] - os[i]) / ds[i];
            let t2 = (maxs[i] - os[i]) / ds[i];
            let (t1, t2) = if t1 > t2 { (t2, t1) } else { (t1, t2) };
            t_min = t_min.max(t1);
            t_max = t_max.min(t2);
            if t_min > t_max { return None; }
        }
    }
    if t_min < 0.0 { None } else { Some(t_min) }
}

fn compute_camera_pos(
    player: Vec3,
    forward: Vec3,
    walls: &[AABB],
    distance: f32,
    height: f32,
) -> Vec3 {
    let target = player - forward * distance + Vec3::new(0.0, height, 0.0);
    let dir = (target - player).normalize();
    let mut best_t = (target - player).length();
    for wall in walls {
        if let Some(t) = ray_aabb_intersect(player, dir, wall) {
            if t < best_t {
                best_t = t - 0.1;  // 10cm gap
            }
        }
    }
    player + dir * best_t.max(0.5)
}

fn main() {
    let player = Vec3::new(0.0, 0.0, 0.0);
    let forward = Vec3::new(1.0, 0.0, 0.0);
    // 墙在玩家 -X 方向 3 米(本来 camera 想去 -5 米,被墙挡)
    let walls = vec![
        AABB {
            min: Vec3::new(-4.0, -2.0, -5.0),
            max: Vec3::new(-3.0, 2.0, 5.0),
        },
    ];
    let camera = compute_camera_pos(player, forward, &walls, 5.0, 3.0);
    println!("Camera: {:?}", camera);
    // 应该被推到墙前(-3 - 0.1 = -3.1 之前)
    // 即 camera.x ≈ -2.9,而不是 -5
    assert!(camera.x > -3.0, "Camera should be in front of wall");
    println!("OK: camera doesn't penetrate wall");
}
```

每行解释:
- 玩家在原点,朝 +X 走。
- 相机目标位置在 (-5, 3, 0)(背后 5 米,高 3 米)。
- 墙在 (-4, -3) 处,玩家到目标射线必过墙。
- `ray_aabb_intersect` 返回墙的近端 t,大约 4 米。
- `best_t - 0.1` 留间隙,相机位置在 -2.9 附近。

```rust
// (Vec3, AABB 实现见 Lv2)

struct CameraState {
    pos: Vec3,
    vel: Vec3,
}

fn spring_arm_update(
    state: &mut CameraState,
    target: Vec3,
    walls: &[AABB],
    dt: f32,
) {
    // 物理参数
    let k = 50.0;       // 刚度
    let d = 8.0;        // 阻尼
    
    let displacement = state.pos - target;
    let force = displacement * (-k) + state.vel * (-d);
    let accel = force;  // 假设质量=1
    
    // Euler 积分
    state.vel = state.vel + accel * dt;
    state.pos = state.pos + state.vel * dt;
    
    // 碰撞调整
    let player_to_cam = state.pos - target;
    let dist = player_to_cam.length();
    let dir = player_to_cam.normalize();
    let mut best_t = dist;
    for wall in walls {
        if let Some(t) = ray_aabb_intersect(target, dir, wall) {
            if t < best_t {
                best_t = t - 0.1;
            }
        }
    }
    if best_t < dist {
        state.pos = target + dir * best_t.max(0.5);
        state.vel = Vec3::new(0.0, 0.0, 0.0);  // 撞墙时速度清零
    }
}

fn main() {
    let player = Vec3::new(0.0, 0.0, 0.0);
    let mut state = CameraState {
        pos: Vec3::new(-5.0, 3.0, 0.0),
        vel: Vec3::new(0.0, 0.0, 0.0),
    };
    let walls = vec![
        AABB {
            min: Vec3::new(-4.0, -2.0, -5.0),
            max: Vec3::new(-3.0, 2.0, 5.0),
        },
    ];

    // 模拟 60 帧
    let dt = 1.0 / 60.0;
    for i in 0..60 {
        spring_arm_update(&mut state, player, &walls, dt);
        if i % 10 == 0 {
            println!("Frame {}: camera={:?}", i, state.pos);
        }
    }
}
```

每行解释:
- `k, d` 是弹簧参数,k 越大越刚硬,d 越大越阻尼。
- `force = -k*x - d*v` 是弹簧-阻尼方程。
- Euler 积分:每帧用当前加速度更新速度和位置。
- 碰撞调整后清零速度,防止弹簧继续推相机进墙。
