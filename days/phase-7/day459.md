# Day 459 · 拆分 PNG 读取器以便集成

> PNG 解码器跑通了,但代码全堆在一个文件、几百行。今天 Casey 把它拆成模块,设计 API,集成到 HH 项目的资产管线。

## 0 · 为什么要有这一天

Day 453-458 的 PNG 解码器是"教学版"——所有代码堆在 `main.rs` 或 `png_decoder.rs`。这不适合真实项目使用:

第一,**重用难**。其他模块要用 PNG 解码,要 copy 大段代码,维护多份。
第二,**测试难**。所有逻辑在 main 里,无法独立测试单个组件。
第三,**API 不清晰**。`PngReader` 直接吃 `&[u8]`,但游戏里资产经常是 `AssetId` 或 `Path`。

Day 459 把 PNG 解码器重构为模块化的 Rust crate,提供清晰 API。这是从"教学代码"到"工业代码"的跨越。

让我把 Rust module 系统讲清楚,这是 Day 459 重构的核心工具。

**Rust module 系统**。一个 crate 是一个编译单元(一个 Cargo.toml)。crate 内部用 `mod` 划分模块:

```
src/
  lib.rs       — crate 根,声明 pub mod ...
  png/
    mod.rs     — png 子模块根
    decoder.rs — 子子模块
    filter.rs
    huffman.rs
  asset.rs     — 另一个模块
```

`lib.rs`:

```rust
pub mod png;
pub mod asset;
```

`png/mod.rs`(或 `png.rs`,2018 edition 后):

```rust
pub mod decoder;
pub mod filter;
pub mod huffman;

pub use decoder::decode;  // re-export,简化外部使用
```

**可见性**。Rust 默认所有 item(函数、struct、mod)私有。`pub` 让它公开:

```rust
// 私有,只在模块内用
fn helper() { ... }

// 公开,任何 use 你 crate 的人能调
pub fn decode(data: &[u8]) -> Image { ... }

// crate 内可见(同 crate 其他模块用)
pub(crate) fn internal() { ... }
```

**API 设计**。公开 API 是 crate 的"接口契约"。改 API 要慎重——下游会 break。Rust 的 `pub` 是这个契约的物理表达。

**Rust module vs C++ namespace**。两者都是"逻辑分组",但 Rust module 同时是**文件路径**(mod png 对应 png.rs 或 png/mod.rs),C++ namespace 纯逻辑(与文件无关)。Rust 的"路径 = 文件"减少认知负担——你看到一个 mod 名,立刻知道去哪个文件找。

**重用模式**。Rust 重用代码有几种:

1. **Copy-paste**:简单,但维护多份。
2. **mod**:同 crate 内重用。Day 459 用这个。
3. **Workspace + crate**:跨 crate 重用。Cargo workspace 让多个 crate 共享 target 目录。
4. **Publish to crates.io**:跨项目重用。`png` crate 就是公开的 PNG 解码器,所有人能用。

Casey HH 选 2——把 PNG 拆成内部 module,不发布 crates.io。因为他想保持教学代码的"自包含"——所有代码可见,不依赖外部库。但工业项目经常走 4——发布到 crates.io 让其他项目用。

## 补充:Rust crate 的 API 设计原则

让我把"如何设计好的 Rust crate API"讲清楚,这是 Day 459 的核心工程技能。

**原则 1:小而美的公开 API**。公开的 item 越少越好。每多一个 `pub`,就多一份未来要维护的契约。

```rust
// 反模式:全 pub
pub struct PngDecoder {
    pub data: Vec<u8>,
    pub position: usize,
    pub bit_reader: BitReader,
    // ...
}

// 好:封装内部细节
pub struct PngDecoder { /* 私有字段 */ }

impl PngDecoder {
    pub fn new(data: Vec<u8>) -> Self { /* ... */ }
    pub fn decode(&mut self) -> Result<Image, DecodeError> { /* ... */ }
}
```

公开 API 只有 `new` 和 `decode`。内部字段(data、position、bit_reader)私有,可以未来重构,不 break 下游。

**原则 2:用 trait 抽象,用 struct 实现**。

```rust
// 公开 trait,让用户可以替换实现
pub trait ImageDecoder {
    fn decode(&mut self) -> Result<Image, DecodeError>;
}

pub struct PngDecoder { /* ... */ }
impl ImageDecoder for PngDecoder { /* ... */ }

pub struct JpegDecoder { /* ... */ }
impl ImageDecoder for JpegDecoder { /* ... */ }
```

用户代码:`fn process<D: ImageDecoder>(d: &mut D) { ... }`,可以传任何 decoder。

**原则 3:错误类型明确**。不要 `Box<dyn Error>`,要具体的 enum:

```rust
#[derive(Debug)]
pub enum DecodeError {
    InvalidSignature,
    InvalidChunk { chunk_type: [u8; 4], reason: String },
    DecompressFailed(String),
    InvalidFilter(u8),
    Io(std::io::Error),
}

impl std::fmt::Display for DecodeError { /* ... */ }
impl std::error::Error for DecodeError { /* ... */ }
```

每个 variant 是一类错误,用户可以 match:

```rust
match decoder.decode() {
    Ok(img) => render(&img),
    Err(DecodeError::InvalidSignature) => panic!("not a PNG"),
    Err(DecodeError::InvalidChunk { chunk_type, reason }) => {
        eprintln!("Bad chunk {}: {}", String::from_utf8_lossy(&chunk_type), reason);
    }
    Err(_) => /* 其他 */,
}
```

**原则 4:Builder pattern 处理多参数**。如果 decoder 有 10 个可选配置,不要写 10 个参数函数:

```rust
// 不好
pub fn decode(data: &[u8], allow_progressive: bool, max_size: Option<usize>, strict_crc: bool, /* ... */) -> Result<Image>

// 好:Builder
pub struct DecoderBuilder { /* 私有字段 */ }

impl DecoderBuilder {
    pub fn new() -> Self { /* 默认值 */ }
    pub fn allow_progressive(mut self, v: bool) -> Self { self.allow_progressive = v; self }
    pub fn max_size(mut self, s: usize) -> Self { self.max_size = Some(s); self }
    pub fn build(self) -> PngDecoder { /* ... */ }
}

let decoder = DecoderBuilder::new()
    .allow_progressive(true)
    .max_size(1024 * 1024)
    .build();
```

**原则 5:文档注释(doc comment)**。每个 pub item 有 `///`:

```rust
/// PNG image decoder.
///
/// # Example
/// ```rust
/// use my_crate::PngDecoder;
/// let data = std::fs::read("image.png")?;
/// let mut decoder = PngDecoder::new(&data);
/// let image = decoder.decode()?;
/// ```
pub struct PngDecoder<'a> { /* ... */ }
```

`cargo doc` 生成 HTML 文档。好文档是 Rust crate 质量的标志。

Casey HH 的简化代码不严格遵循所有原则(教学代码可以"松"),但理解这些原则让你能读工业 Rust crate。

## 2 · 心智模型

### 类比:从作坊到工厂

单文件代码像手工作坊——一个工匠什么都做,熟练但无法扩大。模块化代码像工厂——分工明确,每道工序独立,可扩展、可重用。

Rust 的 module 系统让这种"工厂化"特别自然:`mod` 声明子模块,`pub` 控制可见性,`use` 引入。

### Rust 的模块结构

```
png_decoder/
├── Cargo.toml
└── src/
    ├── lib.rs          ← crate 根,声明子模块
    ├── header.rs       ← PNG 头部解析
    ├── zlib.rs         ← zlib 包装
    ├── deflate/
    │   ├── mod.rs      ← DEFLATE 子模块根
    │   ├── bit_reader.rs
    │   ├── huffman.rs
    │   └── lz77.rs
    ├── filters.rs      ← 5 个滤镜
    └── decoder.rs      ← 主解码逻辑,组合上面所有
```

每个文件一个模块,职责单一。

### lib.rs:模块声明和公开 API

```rust
// src/lib.rs

mod header;       // 私有模块,只在 crate 内可见
mod zlib;
mod deflate;
mod filters;
mod decoder;

// 重导出主要类型
pub use decoder::{Image, ColorType, decode_from_path, decode_from_bytes};

/// PNG 解码错误
#[derive(Debug)]
pub enum DecodeError {
    InvalidMagic,
    InvalidIHDR,
    InvalidZlibHeader,
    DeflateError(String),
    InvalidFilterType(u8),
    Io(std::io::Error),
}

impl std::fmt::Display for DecodeError {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        match self {
            DecodeError::InvalidMagic => write!(f, "Invalid PNG magic"),
            DecodeError::InvalidIHDR => write!(f, "Invalid IHDR"),
            DecodeError::InvalidZlibHeader => write!(f, "Invalid zlib header"),
            DecodeError::DeflateError(s) => write!(f, "DEFLATE error: {}", s),
            DecodeError::InvalidFilterType(t) => write!(f, "Invalid filter type {}", t),
            DecodeError::Io(e) => write!(f, "IO error: {}", e),
        }
    }
}

impl std::error::Error for DecodeError {}

impl From<std::io::Error> for DecodeError {
    fn from(e: std::io::Error) -> Self { DecodeError::Io(e) }
}

pub type Result<T> = std::result::Result<T, DecodeError>;
```

每行解释:
- `mod` 默认私有(只 crate 内可见),`pub mod` 公开。
- `pub use` 重导出,让用户写 `use png_decoder::Image` 而不是 `use png_decoder::decoder::Image`。
- `DecodeError` enum 列出所有可能的错误,精确报告。
- `impl From<std::io::Error>` 让 `?` 自动转换 IO 错误。

### decoder.rs:主逻辑

```rust
// src/decoder.rs

use crate::{header, zlib, deflate, filters};
use crate::{DecodeError, Result};

#[derive(Debug)]
pub enum ColorType {
    Grayscale,
    Rgb,
    GrayscaleAlpha,
    Rgba,
}

#[derive(Debug)]
pub struct Image {
    pub width: u32,
    pub height: u32,
    pub color_type: ColorType,
    pub bit_depth: u8,
    pub pixels: Vec<u8>,
}

pub fn decode_from_path(path: &std::path::Path) -> Result<Image> {
    let data = std::fs::read(path)?;
    decode_from_bytes(&data)
}

pub fn decode_from_bytes(data: &[u8]) -> Result<Image> {
    // 1. PNG header
    let (ihdr, idat) = header::parse_png(data)?;
    
    // 2. zlib + DEFLATE
    let decompressed = zlib::decompress(&idat)?;
    
    // 3. 反滤镜
    let pixels = filters::reconstruct(
        &decompressed,
        ihdr.width as usize,
        ihdr.height as usize,
        ihdr.bpp(),
    )?;
    
    Ok(Image {
        width: ihdr.width,
        height: ihdr.height,
        color_type: ihdr.color_type_enum(),
        bit_depth: ihdr.bit_depth,
        pixels,
    })
}
```

每行解释:
- `decode_from_path` 包装文件 IO,转给 `decode_from_bytes`。
- 主函数把 4 个子模块串起来:header → zlib/DEFLATE → filters。
- 每个子模块独立,可以单独测试。

### 子模块:header.rs

```rust
// src/header.rs
use crate::{DecodeError, Result};

pub struct Ihdr {
    pub width: u32,
    pub height: u32,
    pub bit_depth: u8,
    pub color_type: u8,
    pub compression: u8,
    pub filter: u8,
    pub interlace: u8,
}

impl Ihdr {
    pub fn bpp(&self) -> usize {
        let channels = match self.color_type {
            0 => 1,  // Gray
            2 => 3,  // RGB
            4 => 2,  // Gray+Alpha
            6 => 4,  // RGBA
            _ => 0,
        };
        channels * (self.bit_depth / 8) as usize
    }
    pub fn color_type_enum(&self) -> crate::decoder::ColorType {
        match self.color_type {
            0 => crate::decoder::ColorType::Grayscale,
            2 => crate::decoder::ColorType::Rgb,
            4 => crate::decoder::ColorType::GrayscaleAlpha,
            6 => crate::decoder::ColorType::Rgba,
            _ => panic!("invalid color_type"),
        }
    }
}

pub fn parse_png(data: &[u8]) -> Result<(Ihdr, Vec<u8>)> {
    // (代码见 day453)
    // 验证 magic,解析 IHDR,收集 IDAT
    // ...
    let _ = data;
    Ok((Ihdr { width: 0, height: 0, bit_depth: 0, color_type: 0, compression: 0, filter: 0, interlace: 0 }, Vec::new()))
}
```

每行解释:
- `Ihdr::bpp()` 计算 bytes per pixel。
- `color_type_enum()` 把数字转 enum。
- 子模块返回 crate 自己的错误类型,不是 String。

### 集成到游戏

```rust
// 在游戏代码里
use png_decoder;

fn load_texture(path: &Path) -> Texture {
    let image = png_decoder::decode_from_path(path)
        .unwrap_or_else(|e| panic!("Failed to load {}: {}", path.display(), e));
    Texture {
        width: image.width,
        height: image.height,
        format: match image.color_type {
            png_decoder::ColorType::Rgba => TextureFormat::Rgba8,
            png_decoder::ColorType::Rgb => TextureFormat::Rgb8,
            _ => TextureFormat::Rgb8,
        },
        pixels: image.pixels,
    }
}
```

每行解释:
- 游戏代码只调 `decode_from_path`,不关心内部细节。
- 错误传播给上层决定(panic / 默认纹理 / 退出)。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏引擎的"资产管线"通常分层:

```
原始资产(.png, .obj, .wav)
  ↓ 资产导入器
引擎内部格式(Texture, Mesh, AudioClip)
  ↓ 序列化
打包格式(.pak, .hha)— Casey 用 HHA
  ↓ 运行时加载
GPU / 音频系统
```

PNG 解码器在最上游——把 .png 变成引擎 Texture。Casey 接下来(Day 462+)会用这个解码器导入游戏资产,打包成 HHA(Handmade Asset)格式。

**工业实践**:Unity 用 `AssetImporter`,Unreal 用 `AssetManager`,都允许自定义格式。Casey HH 手写。

### 3.2 · 图形学视角

PNG 解码后得到 raw 像素,但 GPU 不直接吃 raw 像素。要:
1. **格式转换**:RGB → RGBA(GPU 通常要 4 字节对齐)
2. **mipmap 生成**:LOD 用
3. **压缩**:转 BCn / ETC(GPU 友好)
4. **上传**:glTexImage2D 或 vkCmdCopyBufferToImage

这四步是"GPU 纹理管线",PNG 解码只是第一步。Casey Day 462+ 详细讲。

### 3.3 · Linux 系统编程视角

Linux 库设计哲学:**做一件事,做好**。PNG 解码器只做"PNG → raw 像素",不掺其他。

类似 Unix 工具:`cat` 只拼接文件,`grep` 只搜索。组合起来构成强大系统。

Rust crate 生态也遵循这个:`flate2` 只做 zlib,`png` 只做 PNG,`image` 组合多个解码器。

### 3.4 · Rust 生态视角

Rust 模块系统设计:

**A. 文件即模块**
`mod foo;` 自动找 `foo.rs` 或 `foo/mod.rs`。

**B. pub 可见性阶梯**
```rust
pub          // 完全公开
pub(crate)   // crate 内可见
pub(super)   // 父模块可见
pub(self)    // 当前模块(默认)
```

**C. re-export**
```rust
// 在 lib.rs
mod internal;
pub use internal::PublicType;  // 内部模块,但类型公开
```

**D. prelude 模式**
```rust
// src/lib.rs
pub mod prelude {
    pub use crate::{Image, ColorType, decode_from_path, decode_from_bytes};
}
// 用户:use png_decoder::prelude::*;
```

提供"一键导入所有常用"的便捷。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么把内部类型设为 `pub(crate)` 而不是 `pub`?

**参考解答**:`pub(crate)` 让 crate 内所有模块可见,但外部用户看不到。这让你的代码可以自由组合内部类型,不暴露实现细节。

公开太多 API 是反模式——以后想改实现就要 break 用户代码。最小化公开 API 是 Rust 生态的最佳实践。

## 8 · Rust / Arch 落地代码

完整模块化 PNG 解码器(简化版,聚焦结构):

```rust
// Cargo.toml
// [package]
// name = "png_decoder"
// version = "0.1.0"
// edition = "2021"
//
// [dependencies]
// flate2 = "1.0"

// src/lib.rs
mod header;
mod zlib;
mod deflate;
mod filters;
mod decoder;

pub use decoder::{Image, ColorType, DecodeError, Result, decode_from_path, decode_from_bytes};

// src/header.rs
#[derive(Debug)]
pub struct Ihdr {
    pub width: u32,
    pub height: u32,
    pub bit_depth: u8,
    pub color_type: u8,
    pub compression: u8,
    pub filter: u8,
    pub interlace: u8,
}

impl Ihdr {
    pub fn bpp(&self) -> usize {
        let ch = match self.color_type {
            0 => 1, 2 => 3, 4 => 2, 6 => 4, _ => 1,
        };
        ch * (self.bit_depth as usize / 8)
    }
}

// src/zlib.rs
pub fn decompress(data: &[u8]) -> Result<Vec<u8>, String> {
    use std::io::Read;
    let mut d = flate2::read::ZlibDecoder::new(data);
    let mut out = Vec::new();
    d.read_to_end(&mut out).map_err(|e| e.to_string())?;
    Ok(out)
}

// src/filters.rs
pub fn reconstruct(
    data: &[u8],
    width: usize,
    height: usize,
    bpp: usize,
) -> Result<Vec<u8>, String> {
    // (见 day457)
    let row_size = 1 + width * bpp;
    let mut output = Vec::with_capacity(height * width * bpp);
    let mut prev_row: Vec<u8> = Vec::new();
    
    for row in 0..height {
        let row_start = row * row_size;
        if row_start + row_size > data.len() {
            return Err("filtered data too short".into());
        }
        let filter_type = data[row_start];
        let mut current: Vec<u8> = data[row_start + 1..row_start + row_size].to_vec();
        
        reconstruct_row(filter_type, &mut current, &prev_row, bpp)?;
        output.extend_from_slice(&current);
        prev_row = current;
    }
    Ok(output)
}

fn reconstruct_row(ft: u8, cur: &mut [u8], prev: &[u8], bpp: usize) -> Result<(), String> {
    let n = cur.len();
    match ft {
        0 => Ok(()),
        1 => {
            for i in bpp..n { cur[i] = cur[i].wrapping_add(cur[i - bpp]); }
            Ok(())
        }
        2 => {
            if !prev.is_empty() {
                for i in 0..n { cur[i] = cur[i].wrapping_add(prev[i]); }
            }
            Ok(())
        }
        3 => {
            for i in 0..n {
                let l = if i >= bpp { cur[i - bpp] as u16 } else { 0 };
                let u = if !prev.is_empty() { prev[i] as u16 } else { 0 };
                cur[i] = cur[i].wrapping_add(((l + u) / 2) as u8);
            }
            Ok(())
        }
        4 => {
            for i in 0..n {
                let a = if i >= bpp { cur[i - bpp] as i32 } else { 0 };
                let b = if !prev.is_empty() { prev[i] as i32 } else { 0 };
                let c = if i >= bpp && !prev.is_empty() { prev[i - bpp] as i32 } else { 0 };
                let p = a + b - c;
                let pa = (p - a).abs();
                let pb = (p - b).abs();
                let pc = (p - c).abs();
                let pred = if pa <= pb && pa <= pc { a } else if pb <= pc { b } else { c };
                cur[i] = cur[i].wrapping_add(pred as u8);
            }
            Ok(())
        }
        _ => Err(format!("Invalid filter type {}", ft)),
    }
}

// src/decoder.rs
use crate::header::Ihdr;

#[derive(Debug)]
pub enum ColorType {
    Grayscale,
    Rgb,
    GrayscaleAlpha,
    Rgba,
}

#[derive(Debug)]
pub struct Image {
    pub width: u32,
    pub height: u32,
    pub color_type: ColorType,
    pub bit_depth: u8,
    pub pixels: Vec<u8>,
}

#[derive(Debug)]
pub enum DecodeError {
    InvalidMagic,
    InvalidIHDR,
    InvalidZlibHeader,
    DeflateError(String),
    InvalidFilterType(u8),
    Io(std::io::Error),
}

impl std::fmt::Display for DecodeError {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        match self {
            DecodeError::InvalidMagic => write!(f, "Invalid PNG magic"),
            DecodeError::InvalidIHDR => write!(f, "Invalid IHDR"),
            _ => write!(f, "{:?}", self),
        }
    }
}

impl std::error::Error for DecodeError {}

impl From<std::io::Error> for DecodeError {
    fn from(e: std::io::Error) -> Self { DecodeError::Io(e) }
}

pub type Result<T> = std::result::Result<T, DecodeError>;

const MAGIC: [u8; 8] = [0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A];

pub fn decode_from_path(path: &std::path::Path) -> Result<Image> {
    let data = std::fs::read(path)?;
    decode_from_bytes(&data)
}

pub fn decode_from_bytes(data: &[u8]) -> Result<Image> {
    if data.len() < 8 || data[..8] != MAGIC {
        return Err(DecodeError::InvalidMagic);
    }
    
    // IHDR
    let ihdr_len = u32::from_be_bytes([data[8], data[9], data[10], data[11]]) as usize;
    let ihdr_type = &data[12..16];
    if ihdr_type != b"IHDR" || ihdr_len != 13 {
        return Err(DecodeError::InvalidIHDR);
    }
    let ihdr = Ihdr {
        width: u32::from_be_bytes([data[16], data[17], data[18], data[19]]),
        height: u32::from_be_bytes([data[20], data[21], data[22], data[23]]),
        bit_depth: data[24],
        color_type: data[25],
        compression: data[26],
        filter: data[27],
        interlace: data[28],
    };
    
    // 收集 IDAT
    let mut cursor = 8 + 4 + 4 + 13 + 4;
    let mut idat = Vec::new();
    loop {
        if cursor + 8 > data.len() { break; }
        let len = u32::from_be_bytes([data[cursor], data[cursor+1], data[cursor+2], data[cursor+3]]) as usize;
        let t = &data[cursor+4..cursor+8];
        cursor += 8;
        if t == b"IDAT" {
            idat.extend_from_slice(&data[cursor..cursor+len]);
        } else if t == b"IEND" { break; }
        cursor += len + 4;
    }
    
    // DEFLATE
    let decompressed = crate::zlib::decompress(&idat)
        .map_err(DecodeError::DeflateError)?;
    
    // 反滤镜
    let pixels = crate::filters::reconstruct(
        &decompressed,
        ihdr.width as usize,
        ihdr.height as usize,
        ihdr.bpp(),
    ).map_err(DecodeError::DeflateError)?;
    
    let color_type_enum = match ihdr.color_type {
        0 => ColorType::Grayscale,
        2 => ColorType::Rgb,
        4 => ColorType::GrayscaleAlpha,
        6 => ColorType::Rgba,
        _ => return Err(DecodeError::InvalidIHDR),
    };
    
    Ok(Image {
        width: ihdr.width,
        height: ihdr.height,
        color_type: color_type_enum,
        bit_depth: ihdr.bit_depth,
        pixels,
    })
}
