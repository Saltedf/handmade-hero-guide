# Day 447 · 放置相邻房间

> Day 446 生成单个房间体积;今天 Casey 把多个房间"贴"在一起——给定房间 A 和一个方向(东/南/西/北),生成房间 B 使 B 与 A 共享一面墙。这是迷宫的基础。

## 0 · 为什么要有这一天

如果只生成一堆随机位置的房间,你得到的是"散落的盒子",不是迷宫。真正的迷宫房间之间有结构关系——A 通向 B,B 通向 C,通过门连接。Day 447 解决最基础的"结构关系":**怎么把房间 B 紧贴在房间 A 旁边**。

具体来说:给定已存在的房间 A 和一个方向(比如"东边"),算出房间 B 应该放在哪里,使得:
- B 的西墙 = A 的东墙(共享墙)
- B 的底面 y = A 的底面 y(同一楼层)
- B 的大小是新随机的

这样 A 和 B 共享一面墙,可以打通成门(Day 448)。

为什么"共享墙"是迷宫生成的核心?让我把背后的拓扑学讲清楚。

**迷宫的拓扑**。一个迷宫本质上是**图(graph)**:房间是节点,门是边。这个图必须**连通**(connected)——从任何房间能走到任何房间,否则玩家被困。一个空旷的大房间不是迷宫——迷宫要"有结构",有岔路、死胡同、回路。

生成连通图有两种基本方法:

**方法 1:先放后连**。随机放置 N 个房间,然后找哪些房间靠近,连门。问题:**容易产生孤立房间**(没人靠近它),要补救(强制连一个门)。

**方法 2:先连后放(本日)**。从入口房间开始,每次"附着"一个新房间到已有房间。这种方式**保证连通**(每个新房间至少连一个老房间)。Casey 选这个方法。

工业例子:**BSP(binary space partitioning)树**——Doom/Quake 用的方法。递归地把空间切两半,每半再切,叶子节点是房间。BSP 天生连通(树)且无重叠(切分保证)。**Cellular automata**——《 meinercraft 》洞穴生成,从随机噪声迭代收敛到连通形状。**Wave function collapse**——基于约束的生成,模仿 Sudoku 风格的"传播约束"。

Casey HH 用最简单的"附着式"——好教学,足够灵活。

**附着式算法的本质**:

```
房间列表 = []
房间列表.push(初始房间)

loop N 次:
    选一个已有房间 P(随机)
    选一个方向 D(随机,4 个方向)
    新大小 S(随机)
    新房间 Q = place_adjacent(P, D, S)
    如果 Q 不和任何已有房间重叠:
        房间列表.push(Q)
```

每次循环"附着一个新房间到老房间",保证新房间和某个老房间共享墙——这就是连通性的来源。

**Day 447 的具体目标**:实现 `place_adjacent`。重叠检测 Day 449 再做(本日假设不重叠,生成结果可能"穿插",但思路正确)。

完成这一天后,你能做到:实现一个"邻接放置"算法,把一串房间贴成一条走廊,并能解释为什么"共享墙"比"任意放置"更适合迷宫生成。

## 2 · 心智模型

### 类比:搭积木

把房间想成积木。如果两块积木"紧贴"——比如红积木东边贴蓝积木西边——它们共享一个面。蓝积木的位置完全由红积木的位置 + 蓝积木的尺寸决定。

数学上,这就是"轴对齐盒子的邻接约束"。

### 严谨原理:共享墙的位置计算

设 A 是已有房间,AABB A.min = (ax0, ay0, az0),A.max = (ax1, ay1, az1)。

新房间 B 大小 `(bw, bh, bd)`,要放在 A 的**东边**(正 X 方向)。

约束:
- B 西墙 = A 东墙 → `bx0 = ax1`
- B 底面 = A 底面 → `by0 = ay0`
- B 高度独立 → `by1 = by0 + bh`

让我把四个方向的位置公式都展开,这是 Day 447 的核心数学。

**东方向(正 X)**:B 在 A 的 X 大边。B 的西墙(小 X)对齐 A 的东墙(大 X)。

```
       ┌────────┐
       │   B    │
       │        │
───────┼────────┼───────
       │   A    │
       │        │
       └────────┘
       ^A       ^B
       A.min.x  A.max.x = B.min.x
                          B.max.x = B.min.x + B.width
```

公式:
- `B.min.x = A.max.x`
- `B.max.x = B.min.x + bw`
- `B.min.y = A.min.y`(底面对齐)
- `B.max.y = B.min.y + bh`
- `B.min.z = ?`(Z 位置待定,可以是 `A.min.z` 或随机)
- `B.max.z = B.min.z + bd`

Z 位置的选择有几种策略:

1. **平齐**:`B.min.z = A.min.z`(北墙对齐)
2. **居中**:`B.min.z = A.center.z - bd/2`(B 沿 A 的东墙居中)
3. **随机**:`B.min.z = A.min.z + rng() * (A.depth - bd)`(B 沿 A 东墙随机滑)

策略 3 给最多变化,但 B 可能"探出"A 的 Z 范围——如果 `A.depth < bd`,随机范围是负数,要 clamp。Casey HH 选策略 1 或 2 的简化版。

**西方向(负 X)**:B 在 A 的 X 小边。B 的东墙(大 X)对齐 A 的西墙(小 X)。

- `B.max.x = A.min.x`
- `B.min.x = B.max.x - bw`

**北方向(正 Z)**:B 在 A 的 Z 大边。B 的南墙(小 Z)对齐 A 的北墙(大 Z)。

- `B.min.z = A.max.z`
- `B.max.z = B.min.z + bd`
- X 方向"自由"(策略 1/2/3 同上,但 X 轴)

**南方向(负 Z)**:B 在 A 的 Z 小边。

- `B.max.z = A.min.z`
- `B.min.z = B.max.z - bd`

**上方向(正 Y)**:B 在 A 的 Y 大边(楼上一楼层)。这是 3D 迷宫的扩展。

- `B.min.y = A.max.y`
- `B.max.y = B.min.y + bh`

**下方向(负 Y)**:B 在 A 的 Y 小边(地下一层)。但游戏里 y < 0 通常是"地下",可能不可达。Casey HH 限制只用 2D(4 个方向),不做 3D 多楼层。

实现时用一个 `Direction` enum + `match`:

```rust
enum Direction { East, West, North, South }

impl Direction {
    fn place_adjacent(self, existing: &AABB, new_size: Vec3) -> AABB {
        match self {
            Direction::East => AABB {
                min: Vec3::new(existing.max.x, existing.min.y, existing.min.z),
                max: Vec3::new(existing.max.x + new_size.x,
                              existing.min.y + new_size.y,
                              existing.min.z + new_size.z),
            },
            Direction::West => AABB {
                min: Vec3::new(existing.min.x - new_size.x, existing.min.y, existing.min.z),
                max: Vec3::new(existing.min.x,
                              existing.min.y + new_size.y,
                              existing.min.z + new_size.z),
            },
            Direction::North => AABB {
                min: Vec3::new(existing.min.x, existing.min.y, existing.max.z),
                max: Vec3::new(existing.min.x + new_size.x,
                              existing.min.y + new_size.y,
                              existing.max.z + new_size.z),
            },
            Direction::South => AABB {
                min: Vec3::new(existing.min.x, existing.min.y, existing.min.z - new_size.z),
                max: Vec3::new(existing.min.x + new_size.x,
                              existing.min.y + new_size.y,
                              existing.min.z),
            },
        }
    }
}
```

每个分支把新房间的两个角坐标算出来。**这是几何约束的直接翻译**——一个 direction 一个 case。

### 走廊生成的工业方案

商业游戏不会用 Casey 的"附着式"做整个迷宫。它们用更复杂的算法,每种有自己的特点和适用场景:

**BSP 树(Binary Space Partitioning)**。Doom/Quake 经典算法。递归地把矩形空间切两半,切到最小尺寸停止,叶子节点是房间。

```
初始空间 ────► 切 X ────► 切 Y (左) ────► ...
                  │
                  └► 切 Y (右) ────► ...
```

优势:无重叠(切分保证)、连通(叶子间走廊)、平衡(每次切两半)。劣势:房间形状单调(都是矩形)。

**Drunkard's Walk(醉汉漫步)**。从随机点开始,随机走 N 步,走出来的轨迹变走廊。

优势:有机、洞穴感。劣势:不可预测(可能很奇怪),房间分布不均。

**Cellular Automata**。从随机噪声开始,迭代应用规则(如"如果周围少于 4 个邻居,变空;否则变墙")。

优势:自然、洞穴感。劣势:需要后处理(找连通分量、删除孤立小区域)。

**Wave Function Collapse**。基于约束的"propagation",模仿 Sudoku 风格。

优势:模仿特定艺术风格(给你一组"地砖样例",生成同风格的地图)。劣势:难调参,失败时(无解)难调试。

**Room-First(本日 Casey 风格)**。先放房间,再连走廊。

优势:直观,房间形状可控。劣势:需要重叠检测、连通性强制。

Casey HH 是教学项目,选最直观的 Room-First。每种算法都是工程权衡——**没有银弹**,理解每种的特点让你能选择合适工具。

### 共享墙的精确数学

让我把 Day 447 的核心数学彻底讲清楚——这是 Day 448 凿门的基础。

**问题陈述**:给定旧房间 A 和新房大小,新房 B 放在 A 的某个方向(东/西/南/北),共享一面墙。具体约束:

- 共享墙的两个房间在共享轴上"贴在一起"
- 在共享墙的垂直方向(墙的法向量)上,新房大小独立
- 在第三个方向(墙的切向),新房位置可以是"对齐 / 居中 / 随机"

**示例:东方向**。A 在西边,B 在东边。共享墙在 X 方向:`A.max.x = B.min.x`。B 的大小 `(bw, bh, bd)`,位置待定。

- B.min.x = A.max.x(共享墙 X)
- B.max.x = B.min.x + bw(新房 X 范围)
- B.min.y = A.min.y(底面对齐)
- B.max.y = B.min.y + bh
- B.min.z = ?(Z 位置策略)

Z 位置三策略:

1. **平齐**:`B.min.z = A.min.z` ——北墙对齐
2. **居中**:`B.min.z = A.center().z - bd/2`
3. **随机**:`B.min.z = A.min.z + rng() * (A.depth - bd)`(如果 A.depth >= bd,否则用策略 2)

Casey Day 447 选策略 1(最简单),Day 450 升级到策略 2 或 3。

**几何直觉**:两房间共享墙的"连接"——玩家从一个房间通过共享墙到另一个房间。共享墙的范围(B.min.z 到 B.max.z 之间,如果策略 1)是 A 和 B 在 Z 方向的**交集**:

```
A: [A.min.z, A.max.z] = [0, 10]
B: [B.min.z, B.max.z] = [0, 8]  (策略 1,如果 bd=8)
共享墙 Z 范围 = [0, 8]
```

这是 Day 450 的核心——共享墙范围是两房间投影的交集,门要在这个范围内。

## 3 · 四域深入
- B 的 Z 范围(深度)在 A 的 Z 范围内,可以居中 → `bz0 = az0 + (ad - bd) / 2`,`bz1 = bz0 + bd`(假设 `ad >= bd`)

```rust
fn place_east(a: &AABB, b_size: Vec3) -> AABB {
    let bx0 = a.max.x;
    let by0 = a.min.y;
    let bz0 = a.min.z + (a.size().z - b_size.z) * 0.5;
    AABB {
        min: Vec3 { x: bx0, y: by0, z: bz0 },
        max: Vec3 { x: bx0 + b_size.x, y: by0 + b_size.y, z: bz0 + b_size.z },
    }
}
```

每行解释:
- `bx0 = a.max.x` — 新房间西墙 = 旧房间东墙,共享。
- `by0 = a.min.y` — 同一地面。
- `bz0 = ... + (... - ...) * 0.5` — 在 Z 方向居中,保证两房间在走廊方向对齐。
- `max = min + size`,标准 AABB 构造。

### 四个方向

类似实现 North/South/West:

```rust
enum Direction { North, South, East, West }

fn place_adjacent(a: &AABB, dir: Direction, b_size: Vec3) -> AABB {
    match dir {
        Direction::East => {
            // 新房在 A 的 +X 方向
            let bx0 = a.max.x;
            let bz0 = a.min.z + (a.size().z - b_size.z) * 0.5;
            AABB {
                min: Vec3 { x: bx0, y: a.min.y, z: bz0 },
                max: Vec3 { x: bx0 + b_size.x, y: a.min.y + b_size.y, z: bz0 + b_size.z },
            }
        }
        Direction::West => {
            // 新房在 A 的 -X 方向
            let bx1 = a.min.x;  // 新房东墙 = A 西墙
            let bx0 = bx1 - b_size.x;
            let bz0 = a.min.z + (a.size().z - b_size.z) * 0.5;
            AABB {
                min: Vec3 { x: bx0, y: a.min.y, z: bz0 },
                max: Vec3 { x: bx1, y: a.min.y + b_size.y, z: bz0 + b_size.z },
            }
        }
        Direction::North => {
            // 新房在 A 的 +Z 方向(假设 North = +Z)
            let bz0 = a.max.z;
            let bx0 = a.min.x + (a.size().x - b_size.x) * 0.5;
            AABB {
                min: Vec3 { x: bx0, y: a.min.y, z: bz0 },
                max: Vec3 { x: bx0 + b_size.x, y: a.min.y + b_size.y, z: bz0 + b_size.z },
            }
        }
        Direction::South => {
            // 新房在 A 的 -Z 方向
            let bz1 = a.min.z;
            let bz0 = bz1 - b_size.z;
            let bx0 = a.min.x + (a.size().x - b_size.x) * 0.5;
            AABB {
                min: Vec3 { x: bx0, y: a.min.y, z: bz0 },
                max: Vec3 { x: bx0 + b_size.x, y: a.min.y + b_size.y, z: bz1 },
            }
        }
    }
}
```

每行解释:
- `match dir` — Rust 的模式匹配,穷尽性保证每个方向都处理。
- East/West 在 X 方向紧贴,North/South 在 Z 方向紧贴。
- "在另一个轴上居中"——East 房在 Z 居中,North 房在 X 居中——保证视觉上走廊对齐。
- **注意**:这种"居中"假设新房比旧房小。如果新房更大,`a.size() - b_size` 为负,新房会"溢出"。Day 450 处理。

### 走廊生成

把 N 个房间串成走廊:

```rust
fn generate_corridor(seed: u64, n: usize) -> Vec<AABB> {
    let mut rooms = Vec::with_capacity(n);
    // 第一个房间在原点
    let first = generate_room_volume(seed, 0, Vec3::ZERO);
    rooms.push(first);

    for i in 1..n {
        let prev = rooms[i - 1];
        // 随机选一个方向
        let dir_seed = seed.wrapping_add((i as u64).wrapping_mul(0x123456789));
        let mut rng = Pcg32::new(dir_seed, 2);
        let dir = match rng.next() % 4 {
            0 => Direction::East,
            1 => Direction::West,
            2 => Direction::North,
            _ => Direction::South,
        };
        // 新房间大小
        let new_size = generate_size(seed, i);
        let new_room = place_adjacent(&prev, dir, new_size);
        rooms.push(new_room);
    }
    rooms
}
```

每行解释:
- `rooms[i-1]` — 复制前一个房间(Copy 类型),用作下一个的参照。
- `rng.next() % 4` — 把 u32 映射到 [0, 4),选方向。**注意**:modulo bias(`u32::MAX % 4 != 0`),严格要做拒绝采样,但教学忽略。
- `place_adjacent` — 上面实现的紧贴算法。

### 3.1 · 游戏编程视角

迷宫生成的两大流派:

- **房间优先(room-first)**:先生成房间,再连接(本日 Casey)
- **走廊优先(corridor-first)**:先挖走廊,再扩房间

经典 roguelike(NetHack、Brogue)用房间优先。Spelunky 用走廊优先。

工业级算法:**BSP(binary space partition)**——递归地把空间二分,叶子节点放房间。生成树状结构,房间天然有连接关系。

```
                全空间
                /    \
            左半     右半
            /  \     /  \
          R1   R2   R3   R4
```

每个分支点变成"走廊",叶子是房间。这是 Doom(1993)用的算法,经典且高效。

### 3.2 · 图形学视角

AABB 邻接约束在物理引擎里也常见:

- **接触约束**:两个刚体接触,沿接触法线方向不能相对移动
- **关节约束**:铰链、滑动关节,约束相对运动
- **触发器**:进入 AABB 触发事件(开门、播 CG)

物理引擎用 LCP(Linear Complementarity Problem)求解约束系统。HH 不用物理,但概念相通。

### 3.3 · Linux 系统编程视角

Linux 内核"邻接约束"出现在:

- **NUMA 内存分配**:CPU 节点的内存优先在本节点分配
- **巨页(huge pages)**:连续 2MB 物理页,要求地址对齐
- **IOMMU**:设备 DMA 缓冲区要求连续物理地址

这些场景都是"位置受另一对象约束",和房间邻接同构。

### 3.4 · Rust 生态视角

Rust 表达"邻接约束"用 enum + match(本日风格)或 trait(更灵活):

```rust
trait Adjacency {
    fn place_adjacent(&self, a: &AABB, b_size: Vec3) -> AABB;
}

struct East;
impl Adjacency for East {
    fn place_adjacent(&self, a: &AABB, b_size: Vec3) -> AABB { ... }
}
```

trait 风格更灵活(可以加任意方向,如对角),但 enum 更简洁。Casey 用 enum。

**真实 crate**:`parry3d` 提供 AABB 相交测试。`hecs` / `bevy_ecs` 提供组件化实体,适合更复杂的房间属性。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么"新房在另一轴上居中"假设新房比旧房小?如果新房更大怎么办?

**参考解答**:居中公式 `bz0 = a.min.z + (a.size().z - b_size.z) * 0.5`。如果 `b_size.z > a.size().z`,`(a.size().z - b_size.z) < 0`,`bz0` 会"反向偏移"——新房 Z 范围超出旧房 Z 范围,走廊"歪"。

实际后果:走廊角度对不齐,视觉怪异。Day 450 Casey 会处理"任意方向连接",允许不对齐。

### Lv2 · 动手实践

**题**:实现 `place_adjacent` 的所有 4 个方向,生成一条 5 个房间的走廊,每个房间紧贴前一个,方向随机。

**参考解答**:

```rust
#[derive(Debug, Clone, Copy)]
struct Vec3 { x: f32, y: f32, z: f32 }

#[derive(Debug, Clone, Copy)]
struct AABB { min: Vec3, max: Vec3 }

impl AABB {
    fn size(&self) -> Vec3 {
        Vec3 {
            x: self.max.x - self.min.x,
            y: self.max.y - self.min.y,
            z: self.max.z - self.min.z,
        }
    }
}

#[derive(Debug, Clone, Copy)]
enum Direction { East, West, North, South }

fn place_adjacent(a: &AABB, dir: Direction, b_size: Vec3) -> AABB {
    match dir {
        Direction::East => {
            let bx0 = a.max.x;
            let bz0 = a.min.z + (a.size().z - b_size.z) * 0.5;
            AABB {
                min: Vec3 { x: bx0, y: a.min.y, z: bz0 },
                max: Vec3 { x: bx0 + b_size.x, y: a.min.y + b_size.y, z: bz0 + b_size.z },
            }
        }
        Direction::West => {
            let bx1 = a.min.x;
            let bx0 = bx1 - b_size.x;
            let bz0 = a.min.z + (a.size().z - b_size.z) * 0.5;
            AABB {
                min: Vec3 { x: bx0, y: a.min.y, z: bz0 },
                max: Vec3 { x: bx1, y: a.min.y + b_size.y, z: bz0 + b_size.z },
            }
        }
        Direction::North => {
            let bz0 = a.max.z;
            let bx0 = a.min.x + (a.size().x - b_size.x) * 0.5;
            AABB {
                min: Vec3 { x: bx0, y: a.min.y, z: bz0 },
                max: Vec3 { x: bx0 + b_size.x, y: a.min.y + b_size.y, z: bz0 + b_size.z },
            }
        }
        Direction::South => {
            let bz1 = a.min.z;
            let bz0 = bz1 - b_size.z;
            let bx0 = a.min.x + (a.size().x - b_size.x) * 0.5;
            AABB {
                min: Vec3 { x: bx0, y: a.min.y, z: bz0 },
                max: Vec3 { x: bx0 + b_size.x, y: a.min.y + b_size.y, z: bz1 },
            }
        }
    }
}

// 用 Day 446 的 Pcg32
include!("day446_pcg.rs");  // 假设你已经把 Pcg32 提到共享文件

fn generate_size(rng: &mut Pcg32) -> Vec3 {
    let w = 8.0 + rng.next_f32() * 12.0;
    let h = 3.0 + rng.next_f32() * 2.0;
    let d = 8.0 + rng.next_f32() * 12.0;
    Vec3 { x: w, y: h, z: d }
}

fn main() {
    let mut rng = Pcg32::new(42, 1);
    let mut rooms = Vec::new();
    // 第一个房间
    let first_size = generate_size(&mut rng);
    rooms.push(AABB {
        min: Vec3 { x: 0.0, y: 0.0, z: 0.0 },
        max: Vec3 { x: first_size.x, y: first_size.y, z: first_size.z },
    });

    for i in 1..5 {
        let prev = rooms[i - 1];
        let dir = match rng.next() % 4 {
            0 => Direction::East,
            1 => Direction::West,
            2 => Direction::North,
            _ => Direction::South,
        };
        let new_size = generate_size(&mut rng);
        let new_room = place_adjacent(&prev, dir, new_size);
        rooms.push(new_room);
    }

    for (i, r) in rooms.iter().enumerate() {
        println!("Room {}: min=({:.1},{:.1},{:.1}) max=({:.1},{:.1},{:.1})",
            i, r.min.x, r.min.y, r.min.z, r.max.x, r.max.y, r.max.z);
    }
}
```

每行解释:
- `include!()` — Rust 内嵌文件。实际工程用 `mod day446_pcg;` 分模块。
- `rng.next() % 4` — 简化,有 modulo bias 但教学忽略。
- 验证输出:每个房间的位置应该紧贴前一个(共享墙)。

完成标准:
- 5 个房间连续生成
- 每个相邻房间共享一面墙(`prev.max.x == next.min.x` 等)

// (Pcg32 / Vec3 / AABB / Direction / place_adjacent 同上,省略)

fn dump_corridor_svg(rooms: &[AABB], filename: &str) -> std::io::Result<()> {
    use std::io::Write;
    let mut f = std::fs::File::create(filename)?;
    writeln!(f, "<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"800\" height=\"600\">")?;
    writeln!(f, "<rect width=\"100%\" height=\"100%\" fill=\"black\"/>")?;
    // 找坐标范围
    let mut min_x = f32::INFINITY;
    let mut max_x = f32::NEG_INFINITY;
    let mut min_z = f32::INFINITY;
    let mut max_z = f32::NEG_INFINITY;
    for r in rooms {
        min_x = min_x.min(r.min.x);
        max_x = max_x.max(r.max.x);
        min_z = min_z.min(r.min.z);
        max_z = max_z.max(r.max.z);
    }
    let scale = 20.0;
    let offset_x = -min_x;
    let offset_z = -min_z;
    for (i, r) in rooms.iter().enumerate() {
        let x = (r.min.x + offset_x) * scale;
        let y = (r.min.z + offset_z) * scale;
        let w = r.size().x * scale;
        let h = r.size().z * scale;
        writeln!(f, "<rect x=\"{}\" y=\"{}\" width=\"{}\" height=\"{}\" \
            fill=\"none\" stroke=\"cyan\" stroke-width=\"2\"/>",
            x, y, w, h)?;
        writeln!(f, "<text x=\"{}\" y=\"{}\" fill=\"white\">{}</text>",
            x + w/2.0, y + h/2.0, i)?;
    }
    writeln!(f, "</svg>")?;
    Ok(())
}

fn main() {
    // ... 生成 5 个房间 ...
    // (见 Lv2)
    
    dump_corridor_svg(&rooms, "/tmp/corridor.svg").unwrap();
    println!("Saved SVG to /tmp/corridor.svg");
}
