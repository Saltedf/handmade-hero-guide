## 0 · 为什么要有这一天

世界生成器在世界里放置场景物体——树、石头、花。每种物体有多个"变体(variant)":树可能是松树、橡树、白桦。Casey 之前用 `rand() % 3` 选变体,假设三种均匀分布。

问题:**`rand() % N` 不是均匀分布**(当 RAND_MAX 不是 N 的整数倍时)。例如 `RAND_MAX = 32767`,`N = 3`,则 0 出现 10923 次,1 出现 10923 次,2 出现 10922 次。轻微偏差,但累积下来分布失真。

更严重的问题:**权重分布**。松树应该占 50%(常见),橡树 30%,白桦 20%。`rand() % 3` 给三者均等机会,不符合真实分布。

Day 536 Casey 实现**加权随机选择**:

```rust
let r = random_f32();  // [0, 1)
let mut sum = 0.0;
for (variant, weight) in variants.iter().zip(weights) {
    sum += weight;
    if r < sum {
        return variant;
    }
}
```

这种算法叫 **inverse transform sampling**(逆变换采样),是统计学的基础算法。

#### 让我把"inverse transform sampling"的数学讲清楚

这是统计学最基础的采样算法之一,Casey 用它没有讲解,但对自学的你,我应该展开。

**问题**:给你一个离散分布——三个事件 A, B, C,概率分别是 0.5, 0.3, 0.2。如何用均匀随机数(从 [0,1) 均匀分布)生成符合这个分布的样本?

**算法**:

1. 计算累积分布函数(CDF):
   - A 的累积概率 = 0.5
   - B 的累积概率 = 0.5 + 0.3 = 0.8
   - C 的累积概率 = 0.8 + 0.2 = 1.0
2. 生成均匀随机数 r ∈ [0, 1)
3. 找到第一个 CDF > r 的事件:
   - r < 0.5 → 选 A(概率 0.5)
   - 0.5 ≤ r < 0.8 → 选 B(概率 0.3)
   - 0.8 ≤ r < 1.0 → 选 C(概率 0.2)

为什么这个算法正确?**因为 r 落在每个区间的长度 = 该事件的概率**。区间 [0, 0.5) 长度 0.5 → A 概率 0.5。区间 [0.5, 0.8) 长度 0.3 → B 概率 0.3。完美匹配目标分布。

数学证明:对于事件 X 的概率 P(X) = 区间长度 = CDF(X) - CDF(X-1) = P(X)。QED。

这就是 inverse transform sampling——用 CDF 的"逆函数"把均匀分布转换成任意分布。术语"逆变换"指:正常方向是"事件 → 概率",我们反过来"概率 → 事件"。

#### 连续分布的 inverse transform sampling

同样的思想对连续分布也适用。给你一个概率密度函数 PDF(如正态分布),你想生成符合这个分布的样本:

1. 积分 PDF 得到 CDF
2. 生成均匀 r ∈ [0, 1)
3. 求解 CDF^(-1)(r) = 样本值

正态分布的 CDF 没有闭式解,所以工业级用 Box-Muller transform(直接从两个均匀分布生成正态样本)。但**思想是一致的**:用 CDF 的逆变换。

工业级随机数库(`rand` crate)用类似算法生成各种分布:
- `Uniform`:`rand() % N` 的精确版本(无模偏差)
- `Normal`:Box-Muller
- `WeightedIndex`:inverse transform sampling for 离散加权分布

## 2 · 心智模型

### 类比:轮盘抽奖

抽奖转盘有 3 个扇区:50% 松树、30% 橡树、20% 白桦。转盘指针停下时,落在哪个扇区就抽中哪个。这是**加权随机**的物理直观——扇区大小=权重。

数学实现:把权重累加,得到 [0%, 50%, 80%, 100%] 边界。`rand()` 生成 [0, 100) 的数,看落在哪个区间。`r < 50` → 松树;`50 <= r < 80` → 橡树;`r >= 80` → 白桦。

### 严谨展开:modulo bias

`rand() % N` 的问题:**输出空间不均**。

假设 `rand()` 返回 [0, RAND_MAX) 的整数,RAND_MAX = 32767,N = 3。

- 输出 0:0, 3, 6, ..., 32766 → 10923 个值
- 输出 1:1, 4, 7, ..., 32767 → 10923 个值
- 输出 2:2, 5, 8, ..., 32765 → 10922 个值

输出 0 和 1 各比输出 2 多 1 次。偏差 1/10923 ≈ 0.01%。看起来小,但累积 100 万次,分布失真明显。

正确做法:**拒绝采样(rejection sampling)**。如果 `rand()` 落在"多余"区间(RAND_MAX - RAND_MAX % N 到 RAND_MAX),重新生成。

```rust
fn uniform_rand_below(n: u32) -> u32 {
    loop {
        let r = rand();
        if r < RAND_MAX - (RAND_MAX % n) {
            return r % n;
        }
    }
}
```

#### Modulo bias 的安全影响:为什么密码学极度关注

Modulo bias 在普通游戏里影响小,但在**密码学**里是严重安全漏洞。

历史上著名的例子:CVE-2013-6286(Android kernel `get_user` 函数的 modulo bias)。攻击者通过多次观测带 bias 的随机输出,推断出系统内部状态,破解加密。

GitHub 2013 年也踩过坑——他们的 session token 生成用 `rand() % 62`(从 alphanumeric 字符集选),因为 modulo bias,某些字符比其他更常见,session token 熵低于设计值。攻击者能暴力搜索 session。

教训:**密码学场景绝不用 modulo**,必须用 `crypto::rand` 库的 `fill_bytes` + 拒绝采样。

Rust 的 `rand` crate 提供 `Uniform` 分布,内部用拒绝采样,无 modulo bias。你的游戏代码用 `rand::random::<u32>() % N` 仍有 bias,用 `rand::seq::index::sample` 或 `rand::distributions::Uniform` 才精确。

```rust
use rand::distributions::Uniform;

// 错误(有 bias)
let v = rand::random::<u32>() % 3;

// 正确(无 bias)
let dist = Uniform::from(0..3);
let v = rand::thread_rng().sample(dist);
```

工业级代码处处注意这种"看似简单实际有坑"的细节。Casey 在 HH 简化用 modulo(不是密码学场景),但你的生产代码应该用精确算法。


```

### 加权随机选择

```rust
fn weighted_random<'a, T>(items: &'a [T], weights: &[f32]) -> &'a T {
    let total: f32 = weights.iter().sum();
    let r = rand::random::<f32>() * total;  // [0, total)
    
    let mut cumulative = 0.0;
    for (item, weight) in items.iter().zip(weights) {
        cumulative += weight;
        if r < cumulative {
            return item;
        }
    }
    items.last().unwrap()  // fallback
}
```

时间复杂度:O(N)(N = items 数量)。如果 N 大,用 **alias method**(O(1) 查询,O(N) 预处理)。

### 统计测试

```rust
#[test]
fn test_weighted_distribution() {
    let items = vec!["pine", "oak", "birch"];
    let weights = vec![0.5, 0.3, 0.2];
    let mut counts = vec![0; 3];
    
    for _ in 0..10000 {
        let picked = weighted_random(&items, &weights);
        let idx = items.iter().position(|x| *x == picked).unwrap();
        counts[idx] += 1;
    }
    
    let freq: Vec<f32> = counts.iter().map(|&c| c as f32 / 10000.0).collect();
    println!("频率: {:?}", freq);
    
    // 验证接近权重(允许 ±2% 误差)
    assert!((freq[0] - 0.5).abs() < 0.02);
    assert!((freq[1] - 0.3).abs() < 0.02);
    assert!((freq[2] - 0.2).abs() < 0.02);
}
```

这是**大数定律**的体现——N 越大,样本频率越接近真实分布。

### 3.4 · Rust 生态视角

`rand` crate 是 Rust 生态的标准 PRNG 库。API 分层:

- `rand::random<T>()` —— 简单用法,返回 `T` 类型的随机值
- `rand::thread_rng()` —— 线程本地 PRNG(默认 ChaCha12)
- `rand::distributions::*` —— 各种分布(Uniform、Normal、WeightedIndex 等)
- `rand::seq::*` —— 序列随机(choose、shuffle、sample)

工业级模式:

```rust
use rand::prelude::*;
use rand::distributions::WeightedIndex;

// 1. 创建 RNG(每个线程独立)
let mut rng = thread_rng();

// 2. 创建分布
let weights = [50, 30, 20];  // 松树、橡树、白桦
let dist = WeightedIndex::new(&weights).unwrap();

// 3. 采样
let variant_idx = rng.sample(dist);
let tree = &variants[variant_idx];
```

为什么 `thread_rng` 而不是全局 RNG?线程本地避免锁竞争,多核并行友好。C `rand()` 有全局状态,多线程需要 mutex,慢且易错。Rust 的设计直接绕过这个问题。

`WeightedIndex` 内部用 **alias method**(Vose's algorithm)做 O(1) 采样:

- 构造:O(N) 时间预处理
- 采样:O(1) 每次采样

对比 inverse transform sampling:
- 构造:O(N)(累积权重)
- 采样:O(log N)(二分查找)

alias method 适合"采样次数 >> N"的场景——比如 1 万首歌选 100 万次。Casey 的世界生成器是 "N=3,采样次数=1000",inverse transform 够用。但工业级 loot 系统(N=10000 items, 每秒采样 100 万次)必须用 alias method。

#### Rust 生态的 PRNG 对比

| crate | PRNG 类型 | 用途 |
|---|---|---|
| `rand` | ChaCha12(默认) | 通用 |
| `rand_pcg` | PCG family | 高质量统计 |
| `rand_xorshift` | xorshift | 极快,统计略差 |
| `rand_chacha` | ChaCha20 | CSPRNG |
| `getrandom` | OS 熵源 | 密码学 |
| `nanorand` | wyrand | 嵌入式,极小 |

游戏开发选 `rand_pcg`(速度 + 质量平衡),或者直接用 `rand` 默认(ChaCha12 已经够快)。密码学场景必须 `getrandom`。



Rust 的 `rand` crate:

```rust

### 4.4 "Seed 调试"工程实践

```rust
struct GameRng {
    inner: rand_pcg::Pcg64,
    seed: u64,
}

impl GameRng {

#### "Deterministic mode" 的工程价值

多人游戏要求**所有玩家的随机数序列相同**(deterministic),否则 desync(状态不一致)。这要求:

1. 所有玩家用相同 seed
2. 所有玩家用相同 PRNG 算法(不能用 OS 熵源)
3. 所有玩家按相同顺序调用 PRNG(任何分支差异导致 desync)

工业级 lockstep 多人(StarCraft、Age of Empires)实现这套严格 deterministic PRNG。Casey 的 HH 是单机,不需要,但你做多人游戏必须掌握。
## 5 · 对照与变奏

游戏行业的随机数最佳实践:

- **不要用 `rand()`**(C 标准库):有 modulo bias,全局状态非线程安全
- **用 `xorshift` 或 `PCG`**:现代 PRNG,质量高速度快
- **Rust `rand` crate**:thread-safe,无 bias
- **`getrandom` 系统调用**:密码学安全

### PRNG 算法的家族谱

让我把伪随机数生成器(PRNG)的家族讲清楚:

**Linear Congruential Generator(LCG)**:`x = (a*x + c) % m`,1958 年 D.H.Lehmer 设计。简单快,但统计性质差。C 标准库 `rand()` 是 LCG 变种,被批评几十年。

**Mersenne Twister(MT19937)**:1997 年 Matsumoto-Nishimura 设计。周期 2^19937 - 1(天文数字),统计性质极好,2000-2010 是科学计算默认选择。Python `random` 模块默认用 MT。**缺点**:状态大(2.5 KB),不适合 GPU/SIMD,不抗密码学攻击。

**xorshift / xoshiro**:2003-2018 Sebastiano Vigna 设计。极快(几纳秒一次),状态小(16-32 字节),统计性质好。Rust `rand` crate 的默认 PRNG 是 xoshiro256**。

**PCG(PCG family)**:2014 Melissa O'Neill 设计。统计性质比 xorshift 更好,Vigna 自己承认 PCG 在某些测试上优于 xorshift。Rust 的 `rand_pcg` crate 提供。

**ChaCha20**:密码学安全的 PRNG(CSPRNG)。Linux `getrandom`、OpenBSD `arc4random` 用 ChaCha20。游戏服务器生成 session token、随机 loot 等敏感场景应该用 CSPRNG。

**Intel RDRAND**:Intel/AMD CPU 硬件指令,直接从物理噪声源生成随机数。Linux `/dev/random` 用 RDRAND + 其他熵源混合。

游戏开发选 PCG 或 xoshiro(快、统计好),密码学选 ChaCha20(安全但慢)。Casey 用 C `rand()` 是教学简化,你生产用 `rand` crate。

### 随机数在游戏里的应用谱

- **世界生成**:PCG seed → 地形、生物群落、城堡位置(Minecraft、Caves of Qud)
- **AI 决策**:随机选择行为(敌人 70% 攻击、20% 防御、10% 逃跑)
- **Loot drop**:加权随机选择掉落物(WoW legendary 0.01% 概率)
- **Critical hit**:概率判定(D&D 5e 用 d20 + crit range)
- **Particle effect**:粒子初速度抖动(爆炸碎片向随机方向飞)
- **Cryptography**:玩家 session、anti-cheat token(必须 CSPRNG)

每种应用对随机数要求不同。Casey 的变体分布属于"世界生成"——统计质量要求高(分布必须正确),但不要密码学。`rand_pcg` 是正确选择。

### Lv2 · 动手实践

**题**:用 `rand` crate 实现加权随机,生成 10000 个样本,验证分布。运行后:频率应接近权重。

**参考解答**:

```rust
// Cargo.toml:
// [dependencies]
// rand = "0.8"

use rand::distributions::WeightedIndex;
use rand::prelude::*;
use std::collections::HashMap;

fn main() {
    let items = vec!["pine", "oak", "birch"];
    let weights = vec![50u32, 30, 20];
    let dist = WeightedIndex::new(&weights).unwrap();
    let mut rng = thread_rng();
    
    let mut counts: HashMap<&str, u32> = HashMap::new();
    for _ in 0..10000 {
        let idx = dist.sample(&mut rng);
        *counts.entry(items[idx]).or_insert(0) += 1;
    }
    
    println!("=== 分布结果 ===");
    for (item, weight) in items.iter().zip(&weights) {
        let count = counts.get(item).copied().unwrap_or(0);
        let freq = count as f32 / 10000.0;
        let expected = *weight as f32 / 100.0;
        println!("{}: 实际 {:.3}, 期望 {:.3}, 差 {:+.4}",
            item, freq, expected, freq - expected);
    }
}
```

### Lv3 · 迁移设计

**题**:你要做一个音乐播放器的"随机播放"功能。要求:每首歌有"喜爱度"(用户打分,1-5 星),5 星的歌播放概率是 1 星的 5 倍。设计加权随机算法。考虑:已播放的歌暂时不再选(避免重复)。提示:动态权重——已播放的权重设为 0。

**详细参考**:

```rust
use rand::distributions::WeightedIndex;
use rand::prelude::*;

struct Song { name: String, rating: u32, played: bool }

fn weighted_shuffle(songs: &mut [Song]) -> Option<&Song> {
    let weights: Vec<u32> = songs.iter()
        .map(|s| if s.played { 0 } else { s.rating })
        .collect();
    
    // 如果所有权重都是 0(所有歌都播放过),返回 None
    if weights.iter().sum::<u32>() == 0 {
        return None;
    }
    
    let dist = WeightedIndex::new(&weights).unwrap();
    let idx = rand::thread_rng().sample(dist);
    Some(&songs[idx])
}
```

工业级播放器(Spotify、Apple Music)用更复杂算法:
- "最近播放惩罚":权重 = rating / (1 + recency)
- "全局热度":其他用户喜欢度影响权重
- "Genre diversity":避免连续 5 首同 genre

这些扩展都在"加权随机"基础上加维度。学会 Casey 这一天的核心算法,你就能扩展到任何复杂场景。

// 完整的加权随机 + 统计测试 + issue cleanup 模拟

use rand::distributions::WeightedIndex;
use rand::prelude::*;

/// 加权随机选择
pub fn weighted_choice<'a, T>(items: &'a [T], weights: &[u32]) -> &'a T {
    assert_eq!(items.len(), weights.len());
    assert!(!items.is_empty());
    let dist = WeightedIndex::new(weights).unwrap();
    let mut rng = thread_rng();
    &items[dist.sample(&mut rng)]
}

/// 统计测试:验证实际分布接近权重
pub fn verify_distribution(
    items: &[&str],
    weights: &[u32],
    sample_count: usize,
) -> Vec<f32> {
    let dist = WeightedIndex::new(weights).unwrap();
    let mut rng = thread_rng();
    let mut counts = vec![0u32; items.len()];
    
    for _ in 0..sample_count {
        let idx = dist.sample(&mut rng);
        counts[idx] += 1;
    }
    
    counts.iter()
        .map(|&c| c as f32 / sample_count as f32)
        .collect()
}

/// 模拟 issue cleanup
struct Issue {
    id: u32,
    title: String,
    status: IssueStatus,
}

#[derive(Debug, PartialEq)]
enum IssueStatus {
    Open,
    Fixed,
    WontFix,
    Duplicate,
}

fn cleanup_issues(issues: &mut Vec<Issue>) {
    for issue in issues.iter_mut() {
        match issue.title.as_str() {
            t if t.contains("typo") => {
                println!("Fix #{}: {} (typo fix)", issue.id, t);
                issue.status = IssueStatus::Fixed;
            }
            t if t.contains("already fixed") => {
                println!("Close #{}: {} (duplicate)", issue.id, t);
                issue.status = IssueStatus::Duplicate;
            }
            t if t.contains("not a bug") => {
                println!("Close #{}: {} (wontfix)", issue.id, t);
                issue.status = IssueStatus::WontFix;
            }
            _ => {}  // keep open
        }
    }
}

fn main() {
    // === Part 1: 变体分布 ===
    println!("=== 变体分布测试 ===");
    let items = vec!["pine", "oak", "birch"];
    let weights = vec![50u32, 30, 20];
    
    let freqs = verify_distribution(&items, &weights, 10000);
    for (item, weight, freq) in items.iter().zip(&weights).zip(&freqs) {
        let expected = *weight as f32 / 100.0;
        let diff = freq - expected;
        let status = if diff.abs() < 0.02 { "OK" } else { "FAIL" };
        println!("{}: 期望 {:.2}, 实际 {:.3} (差 {:+.4}) [{}]",
            item, expected, freq, diff, status);
    }
    
    // 实际用例:世界生成
    println!("\n=== 世界生成(放置 5 棵树) ===");
    let mut rng = thread_rng();
    for i in 0..5 {
        let tree = weighted_choice(&items, &weights);
        println!("树 {}: {}", i, tree);
    }
    
    // === Part 2: Issue Cleanup ===
    println!("\n=== GitHub Issue Cleanup ===");
    let mut issues = vec![
        Issue { id: 1, title: "Particle system crashes on load".into(), status: IssueStatus::Open },
        Issue { id: 2, title: "Typo in README".into(), status: IssueStatus::Open },
        Issue { id: 3, title: "Already fixed in PR #42".into(), status: IssueStatus::Open },
        Issue { id: 4, title: "Feature request: dark mode".into(), status: IssueStatus::Open },
        Issue { id: 5, title: "Not a bug, expected behavior".into(), status: IssueStatus::Open },
    ];
    
    cleanup_issues(&mut issues);
    
    println!("\n剩余 open issues:");
    for issue in &issues {
        if issue.status == IssueStatus::Open {
            println!("  #{}: {}", issue.id, issue.title);
        }
    }
}
