> HH 有两套独立的 UI 系统——debug overlay(显示 FPS、entity count,Day 5+ 做的)和 editor UI(选中 entity、属性面板,Day 488 做的)。两套重叠多、互相干扰。Day 490 把它们合并成一个统一的开发者 UI。

## 0 · 为什么要有这一天

你做的 HH 现在有两套 UI:

**Debug overlay**:右上角小窗,显示 FPS、frame time、entity count、内存占用。Phase 5 引入。

**Editor UI**:全屏编辑器,选中 entity 显示 inspector,palette 窗口,Day 488 引入。

两套 UI 各自独立,问题:

- 同一屏幕同时显示时位置冲突(debug 在右上,editor 也在右上)
- 两者都有自己的 immediate-mode 代码,样式不统一
- 用户切换编辑器开关时 debug overlay 也消失(因为 editor 占满)
- 数据展示重叠(debug 的 entity count 和 editor 的 entity list 显示同样信息)

Day 490 合并这两套,做统一的"Developer UI",有几个面板:

- **Performance overlay**:FPS、frame time(原 debug)
- **Inspector**:选中 entity 属性(原 editor)
- **Palette**:entity 类型选择(原 editor)
- **Console**:debug 日志输出(新增)
- **Profiler**:函数级耗时(新增,简化)

所有面板用同一套 immediate-mode UI 框架,样式统一,位置可配置。

这件事在工业界叫 **UI consolidation**(UI 合并)——系统演化时多个独立 UI 子系统逐渐融合成统一框架。VSCode 把 git/lint/debug 都集成到主界面,Unity Editor 把各种 window 合并成 docking system,都是这种合并。

完成这一天之后,你具备了:

- UI 系统的合并和重构
- Docking / 布局系统的设计
- 多 immediate-mode panel 的状态管理

## 2 · 心智模型

### 类比:厨房里的小家电

想象你厨房里有几个独立小家电——烤面包机、榨汁机、咖啡机。各自占地方,各有控制面板。

新设计:**集成厨具中心**——一个台面,几个小家电内嵌,统一控制面板(触摸屏),按按钮选模式。

原来的小家电是 HH 的"独立 UI 子系统",集成厨具中心是 Day 490 的"统一 Developer UI"。

合并的好处:

- **空间**:不再各自占地方,统一布局
- **交互**:同样按钮风格,学一次会全部
- **数据共享**:统一框架,数据流通容易(性能 panel 显示 entity 数,inspector 也显示,共享同一份数据)

### Immediate-mode UI 框架的核心

所有 immediate-mode UI 框架(ImGui、egui、Nuklear)都有几个核心概念:

第一,**Context / Ui 对象**。每帧创建,管理 widget 状态。

第二,**Layout**(布局)。widget 怎么排列?垂直 / 水平 / grid?

第三,**Widget**(小部件)。button、slider、label、checkbox 等基础元素。

第四,**Input**(输入)。鼠标、键盘事件传递给 widget。

第五,**Draw list**(绘制列表)。widget 渲染命令收集,frame 末统一绘制。

Casey Day 490 实现简化版,核心是 widget + layout。

### Panel 系统

Developer UI 由多个 panel 组成。每个 panel:

- 有名字("Performance"、"Inspector")
- 有开关状态(open / closed)
- 有屏幕位置和大小
- 有渲染函数(绘制内容)

```rust
struct Panel {
    name: String,
    is_open: bool,
    rect: Rect,    // 屏幕位置 + 大小
    render_fn: fn(&mut Ui, &mut State),
}
```

每帧遍历所有 open 的 panel,调 render_fn。

### Docking:面板布局

工业级 UI(IDE、3D 软件)有 docking system——panel 可以拖到任意位置,粘附到屏幕边缘。实现复杂(需要 hit testing、约束求解)。

Casey 简化:固定位置(Performance 在右上,Inspector 在右侧,Palette 在左侧)。后期可以扩展。

固定位置的实现:

```rust
enum PanelPosition {
    TopLeft,
    TopRight,
    BottomLeft,
    BottomRight,
    Left,
    Right,
    Floating(Vec2),   // 自由位置
}
```

每个 panel 配置一个默认 position,渲染时算 rect。

### Input 路由

UI 有多个 panel,鼠标点击该谁响应?这是 **input routing**(输入路由)。

简单规则:**z-order 从顶到底,第一个 hit 的 panel 处理**。最后画的 panel 在最上层,优先响应。

```rust
fn route_click(panels: &mut [Panel], click: Vec2) -> Option<usize> {
    // 反向遍历(后画的在前)
    for (i, p) in panels.iter().enumerate().rev() {
        if p.is_open && p.rect.contains(click) {
            return Some(i);
        }
    }
    None
}
```

如果点击在 panel 内,panel 处理;否则点击传到游戏世界(editor hit test entity)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业游戏引擎的 UI 系统复杂得多。

**Unity**:有 IMGUI(老式 immediate,用于编辑器)、UI Toolkit(新式 retained,Web 风格)、uGUI(中间)。三套并存,因为历史。

**Unreal**:UMG(Unreal Motion Graphics)是 retained mode,Slate 是底层 immediate。编辑器用 Slate,游戏 UI 用 UMG。

**Godot**:Control 节点系统,retained mode,树形组织。

这些引擎都有 docking system、panel 系统、widget 库。Casey 的简化版理解后能秒懂商业引擎的 UI 架构。

游戏开发里 UI 合并的另一个例子:**HUD vs Menu vs Inventory**。早期游戏三套独立,现代游戏合并成统一 UI 系统(玩家可能没察觉,但代码共享)。

### 3.2 · 🎨 图形学视角

UI 合并涉及几个图形学概念。

第一,**Scissor rect**(裁剪矩形)。Panel 内容超出 panel 边界时裁剪,OpenGL 用 `glScissor`。Panel 滚动时只显示裁剪区。

第二,**Depth override**。UI 通常画在 3D 之上,不受深度测试影响。`glDisable(GL_DEPTH_TEST)` 或单独 render pass。

第三,**Alpha blending**。Panel 半透明,需要 blend。OpenGL 的 `GL_BLEND`。

第四,**Text rendering**。UI 大量文字,需要高效 text renderer。FreeType + 字体 atlas 是工业标准。

Casey 简化:不裁剪、UI 单独 pass、不透明、文字用简单 sprite。后期可以加高级特性。

### 3.3 · 🐧 Linux 系统编程视角

Linux 桌面就是个统一 UI 系统——窗口管理器( Mutter、KWin、Sway)合并所有客户端的输出。

- **Wayland compositor**:接收所有客户端 surface,合成到屏幕
- **Panel / Taskbar**:桌面边缘的面板(GNOME Shell、KDE Panel)
- **Dock / App launcher**:应用启动器
- **Notification**:系统通知(右上角弹出)

这些元素和 Casey 的 Developer UI 同构——都是 panel + 状态 + 输入路由。

Linux 桌面的 docking 例子:**GNOME Shell 的 top bar**、**KDE Plasma 的 panels**、**Sway/i3 的 workspaces**。每个都是 panel,可配置位置。


### 3.4 · 🦀 Rust 生态视角

Rust 生态有几个成熟 UI 库适合游戏集成。

**egui**:最受欢迎的 Rust immediate-mode UI,集成到游戏容易。bevy_egui 是 Bevy 的 egui plugin。

**iced**:retained mode,适合应用 UI(非游戏)。

**druid**(已弃用,被 Xilem 取代):retained mode。

**makepad**:专为游戏设计的 UI 框架。

Casey 自己写,因为 HH 没有 egui 依赖。但理解 egui 概念后,你看任何 Rust UI 库都能秒懂。

egui 集成游戏的代码骨架:

```rust
let mut egui_state = egui_winit::State::new(...);

// 每帧
fn update(game_state: &mut GameState, raw_input: egui::RawInput) {
    let (output, paint_commands) = egui_state.run(raw_input, |ctx| {
        egui::TopBottomPanel::top("menu").show(ctx, |ui| {
            ui.menu_button("File", |ui| {
                if ui.button("Save").clicked() {
                    save_level();
                }
            });
        });
        
        egui::SidePanel::right("inspector").show(ctx, |ui| {
            ui.heading("Inspector");
            if let Some(e) = &game_state.selected_entity {
                ui.label(format!("Name: {}", e.name));
                ui.add(egui::Slider::new(&mut e.pos.x, -100.0..=100.0).text("X"));
            }
        });
        
        egui::Window::new("Performance")
            .anchor(egui::Align2::RIGHT_TOP, [0.0, 0.0])
            .show(ctx, |ui| {
                ui.label(format!("FPS: {}", game_state.fps));
            });
    });
    
    // 用 paint_commands 渲染到游戏 framebuffer
}
```

这就是工业级 immediate-mode UI 的样子。Casey Day 490 做的简化版同构。

## 5 · 对照与变奏

Casey 在 Day 490 的 UI 合并在不同领域有不同对应:

**IDE 合并**:VSCode 把 git、lint、debug、terminal 都集成到主界面。Eclipse、IntelliJ 同样。

**3D 软件**:Blender 把 modeling、sculpting、animation 的 UI 都合并到主界面。Maya、3ds Max 同样。

**DAW**(数字音频):Ableton、FL Studio 把音轨、效果器、混音器合并。

**Office**:Microsoft Office Ribbon 把所有功能合并到顶部 ribbon。

**游戏引擎**:Unity、Unreal、Godot 编辑器都是统一 UI 系统。

理解"多 UI 合并成统一"是工程师的核心素养。每次你做"多个独立 UI 子系统",问自己:**能不能合并?会不会更易用?**

另一个对照:**Consolidation vs Specialization**。合并的好处是统一,坏处是失去专门化。有时独立 UI 更好(比如游戏内 vs 主菜单,语义完全不同,强行合并反而怪)。Casey 合并 Developer UI 因为都是"开发工具",语义一致。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:Casey 为什么选 immediate-mode 而不是 retained-mode 做 Developer UI?

**参考解答**:三个理由:

第一,**数据驱动**。Developer UI 实时反映游戏状态——FPS、entity 位置、选中状态。Immediate mode 每帧从数据重建 UI,永远同步。Retained mode 要手动同步 widget 和数据。

第二,**简单**。Immediate mode 代码短:

```rust
ui.label(format!("FPS: {}", fps));
```

Retained mode 要先创建 label,每帧 update text:

```rust
let label = Label::new("");
fn update(&mut self, fps: f32) {
    self.label.set_text(format!("FPS: {}", fps));
}
```

第三,**灵活**。Developer UI 经常加新面板。Immediate mode 加一个面板就是写一个函数,不用维护 widget 树。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现一个最小 Developer UI 框架。定义 `Ui` 结构,有 `label`、`button`、`slider` 方法。再定义 `Panel`,有名字、位置、内容函数。实现 3 个 panel:Performance(假装 FPS)、Inspector(假装 entity 属性)、Console(假装日志)。每帧渲染所有 panel。

完成标准:`cargo run` 输出 3 个 panel 的"渲染"结果(用 println 模拟)。

**参考解答**:

```rust
use std::cell::RefCell;
use std::rc::Rc;

// 假装的 game state
struct GameState {
    fps: f32,
    selected_entity_name: Option<String>,
    selected_entity_pos: [f32; 3],
    log_messages: Vec<String>,
}

// UI 框架
struct Ui {
    current_panel: String,
    output: Vec<String>,    // 简化:用 println 而不是真正渲染
}

impl Ui {
    fn new() -> Self { Self { current_panel: String::new(), output: Vec::new() } }
    
    fn label(&mut self, text: &str) {
        self.output.push(format!("[{}] {}", self.current_panel, text));
    }
    
    fn button(&mut self, label: &str) -> bool {
        self.output.push(format!("[{}] [Button: {}]", self.current_panel, label));
        false   // 简化:从不点击
    }
    
    fn slider(&mut self, label: &str, value: &mut f32, min: f32, max: f32) {
        self.output.push(format!(
            "[{}] [Slider: {} = {:.2} (range {}..{})]",
            self.current_panel, label, value, min, max
        ));
    }
    
    fn checkbox(&mut self, label: &str, value: &mut bool) {
        self.output.push(format!(
            "[{}] [Checkbox: {} = {}]",
            self.current_panel, label, value
        ));
    }
}

// Panel 定义
struct Panel {
    name: String,
    position: PanelPosition,
    is_open: bool,
}

#[derive(Debug)]
enum PanelPosition {
    TopLeft,
    TopRight,
    BottomLeft,
    BottomRight,
}

impl Panel {
    fn new(name: &str, position: PanelPosition) -> Self {
        Self {
            name: name.to_string(),
            position,
            is_open: true,
        }
    }
}

// Developer UI 容器
struct DeveloperUI {
    panels: Vec<Panel>,
}

impl DeveloperUI {
    fn new() -> Self {
        Self {
            panels: vec![
                Panel::new("Performance", PanelPosition::TopRight),
                Panel::new("Inspector", PanelPosition::Right),
                Panel::new("Console", PanelPosition::BottomLeft),
            ],
        }
    }
    
    fn render(&mut self, state: &mut GameState) {
        let mut ui = Ui::new();
        
        for panel in &self.panels {
            if !panel.is_open { continue; }
            
            ui.current_panel = format!("{} ({:?})", panel.name, panel.position);
            ui.output.push(format!("=== {} ===", ui.current_panel));
            
            match panel.name.as_str() {
                "Performance" => render_performance(&mut ui, state),
                "Inspector" => render_inspector(&mut ui, state),
                "Console" => render_console(&mut ui, state),
                _ => {}
            }
        }
        
        // 输出
        for line in &ui.output {
            println!("{}", line);
        }
    }
    
    fn toggle_panel(&mut self, name: &str) {
        if let Some(p) = self.panels.iter_mut().find(|p| p.name == name) {
            p.is_open = !p.is_open;
            println!(">> Toggled panel '{}' to {}", name, p.is_open);
        }
    }
}

fn render_performance(ui: &mut Ui, state: &GameState) {
    ui.label(&format!("FPS: {:.1}", state.fps));
    ui.label(&format!("Frame time: {:.2}ms", 1000.0 / state.fps));
    ui.label(&format!("Entities: 0"));
    ui.label(&format!("Memory: 0 MB"));
}

fn render_inspector(ui: &mut Ui, state: &mut GameState) {
    match &state.selected_entity_name {
        Some(name) => {
            ui.label(&format!("Selected: {}", name));
            ui.slider("X", &mut state.selected_entity_pos[0], -100.0, 100.0);
            ui.slider("Y", &mut state.selected_entity_pos[1], -100.0, 100.0);
            ui.slider("Z", &mut state.selected_entity_pos[2], -100.0, 100.0);
            ui.button("Delete");
        }
        None => {
            ui.label("(No selection)");
        }
    }
}

fn render_console(ui: &mut Ui, state: &GameState) {
    ui.label("Recent logs:");
    for msg in state.log_messages.iter().rev().take(5) {
        ui.label(msg);
    }
}

fn main() {
    let mut state = GameState {
        fps: 60.0,
        selected_entity_name: Some("hero".to_string()),
        selected_entity_pos: [10.0, 20.0, 0.0],
        log_messages: vec![
            "[INFO] Game started".to_string(),
            "[WARN] Slow frame detected".to_string(),
            "[ERROR] Asset not found: foo.png".to_string(),
        ],
    };
    
    let mut dev_ui = DeveloperUI::new();
    
    println!("=== Frame 1: All panels open ===\n");
    dev_ui.render(&mut state);
    
    println!("\n=== Frame 2: Toggle console off ===\n");
    dev_ui.toggle_panel("Console");
    dev_ui.render(&mut state);
    
    println!("\n=== Frame 3: Toggle inspector off (no entity UI) ===\n");
    dev_ui.toggle_panel("Inspector");
    dev_ui.render(&mut state);
    
    println!("\n=== Frame 4: Toggle inspector back on ===\n");
    dev_ui.toggle_panel("Inspector");
    dev_ui.render(&mut state);
}
```

为什么这么写:`Ui` 结构持有当前 panel 名字(用于 prefix 输出),`output` 收集渲染命令。每个 render 函数接受 `&mut Ui` 和 `&mut GameState`,immediate mode 风格。这就是 egui / ImGui 的核心模式。

## 8 · Rust / Arch 落地代码

下面是 Day 490 完整的 Developer UI 框架。

```rust
use std::collections::HashMap;

// ========================================
// 数学库(简化)
// ========================================

#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    const fn new(x: f32, y: f32) -> Self { Self { x, y } }
}

#[derive(Copy, Clone, Debug)]
struct Rect {
    pos: Vec2,
    size: Vec2,
}

impl Rect {
    fn new(x: f32, y: f32, w: f32, h: f32) -> Self {
        Self { pos: Vec2::new(x, y), size: Vec2::new(w, h) }
    }
    
    fn contains(&self, p: Vec2) -> bool {
        p.x >= self.pos.x && p.x <= self.pos.x + self.size.x &&
        p.y >= self.pos.y && p.y <= self.pos.y + self.size.y
    }
}

// ========================================
// UI Framework
// ========================================

struct UiContext {
    cursor: Vec2,           // 当前 widget 位置
    current_panel: String,
    line_height: f32,
    widgets: Vec<Widget>,
}

#[derive(Debug)]
enum Widget {
    Label { text: String, pos: Vec2 },
    Button { label: String, pos: Vec2, size: Vec2, clicked: bool },
    Slider { label: String, value: f32, min: f32, max: f32, pos: Vec2 },
    Rect { rect: Rect, color: [f32; 4] },
}

impl UiContext {
    fn new() -> Self {
        Self {
            cursor: Vec2::new(0.0, 0.0),
            current_panel: String::new(),
            line_height: 16.0,
            widgets: Vec::new(),
        }
    }
    
    fn start_panel(&mut self, name: &str, origin: Vec2) {
        self.current_panel = name.to_string();
        self.cursor = origin;
        // 画 panel 背景
        self.widgets.push(Widget::Rect {
            rect: Rect::new(origin.x, origin.y, 200.0, 100.0),
            color: [0.2, 0.2, 0.2, 0.8],
        });
        // cursor 跳过 panel 标题栏
        self.cursor.y += self.line_height;
    }
    
    fn label(&mut self, text: &str) {
        self.widgets.push(Widget::Label {
            text: text.to_string(),
            pos: self.cursor,
        });
        self.cursor.y += self.line_height;
    }
    
    fn button(&mut self, label: &str) -> bool {
        let pos = self.cursor;
        let size = Vec2::new(80.0, self.line_height);
        self.widgets.push(Widget::Button {
            label: label.to_string(),
            pos,
            size,
            clicked: false,    // 简化
        });
        self.cursor.y += self.line_height;
        false
    }
    
    fn slider(&mut self, label: &str, value: f32, min: f32, max: f32) {
        self.widgets.push(Widget::Slider {
            label: label.to_string(),
            value, min, max,
            pos: self.cursor,
        });
        self.cursor.y += self.line_height;
    }
    
    fn end_panel(&mut self) {
        self.current_panel.clear();
    }
}

// Developer UI

#[derive(Debug)]
enum PanelPosition {
    TopLeft,
    TopRight,
    BottomLeft,
    BottomRight,
}

struct Panel {
    name: String,
    position: PanelPosition,
    is_open: bool,
}

struct DeveloperUI {
    panels: Vec<Panel>,
}

impl DeveloperUI {
    fn new() -> Self {
        Self {
            panels: vec![
                Panel { name: "Performance".to_string(), position: PanelPosition::TopRight, is_open: true },
                Panel { name: "Inspector".to_string(), position: PanelPosition::TopLeft, is_open: true },
                Panel { name: "Console".to_string(), position: PanelPosition::BottomLeft, is_open: true },
                Panel { name: "Profiler".to_string(), position: PanelPosition::BottomRight, is_open: false },
            ],
        }
    }
    
    fn toggle(&mut self, name: &str) {
        if let Some(p) = self.panels.iter_mut().find(|p| p.name == name) {
            p.is_open = !p.is_open;
        }
    }
    
    fn render(&self, state: &GameState) -> Vec<Widget> {
        let mut ctx = UiContext::new();
        
        for panel in &self.panels {
            if !panel.is_open { continue; }
            
            let origin = match panel.position {
                PanelPosition::TopLeft => Vec2::new(10.0, 10.0),
                PanelPosition::TopRight => Vec2::new(800.0 - 210.0, 10.0),
                PanelPosition::BottomLeft => Vec2::new(10.0, 600.0 - 110.0),
                PanelPosition::BottomRight => Vec2::new(800.0 - 210.0, 600.0 - 110.0),
            };
            
            ctx.start_panel(&panel.name, origin);
            ctx.label(&format!("[{}]", panel.name));   // panel 标题
            
            match panel.name.as_str() {
                "Performance" => self.render_performance(&mut ctx, state),
                "Inspector" => self.render_inspector(&mut ctx, state),
                "Console" => self.render_console(&mut ctx, state),
                "Profiler" => self.render_profiler(&mut ctx, state),
                _ => {}
            }
            
            ctx.end_panel();
        }
        
        ctx.widgets
    }
    
    fn render_performance(&self, ctx: &mut UiContext, state: &GameState) {
        ctx.label(&format!("FPS: {:.1}", state.fps));
        ctx.label(&format!("Frame: {:.2}ms", 1000.0 / state.fps.max(1.0)));
        ctx.label(&format!("Entities: {}", state.entity_count));
        ctx.button("Reset stats");
    }
    
    fn render_inspector(&self, ctx: &mut UiContext, state: &GameState) {
        match &state.selected_entity_name {
            Some(name) => {
                ctx.label(&format!("Name: {}", name));
                ctx.slider("X", state.selected_pos[0], -100.0, 100.0);
                ctx.slider("Y", state.selected_pos[1], -100.0, 100.0);
                ctx.slider("Z", state.selected_pos[2], -100.0, 100.0);
                ctx.button("Delete");
            }
            None => {
                ctx.label("(No entity selected)");
            }
        }
    }
    
    fn render_console(&self, ctx: &mut UiContext, state: &GameState) {
        ctx.label("Logs:");
        for msg in state.log_messages.iter().rev().take(3) {
            ctx.label(msg);
        }
    }
    
    fn render_profiler(&self, ctx: &mut UiContext, state: &GameState) {
        ctx.label("Function timings:");
        ctx.label(&format!("  update: {:.2}ms", state.update_time_ms));
        ctx.label(&format!("  render: {:.2}ms", state.render_time_ms));
        ctx.label(&format!("  total:  {:.2}ms", state.update_time_ms + state.render_time_ms));
    }
}

struct GameState {
    fps: f32,
    entity_count: u32,
    selected_entity_name: Option<String>,
    selected_pos: [f32; 3],
    log_messages: Vec<String>,
    update_time_ms: f32,
    render_time_ms: f32,
}

fn main() {
    let mut state = GameState {
        fps: 60.0,
        entity_count: 42,
        selected_entity_name: Some("hero".to_string()),
        selected_pos: [10.0, 20.0, 0.0],
        log_messages: vec![
            "[INFO] Game started".to_string(),
            "[WARN] Slow frame".to_string(),
            "[ERROR] Asset not found: foo.png".to_string(),
        ],
        update_time_ms: 2.3,
        render_time_ms: 8.1,
    };
    
    let mut dev_ui = DeveloperUI::new();
    
    println!("=== Developer UI 演示 ===\n");
    println!("Screen size: 800x600\n");
    
    for frame in 1..=4 {
        println!("--- Frame {} ---", frame);
        
        // 切换 panel
        match frame {
            2 => dev_ui.toggle("Console"),
            3 => { dev_ui.toggle("Profiler"); dev_ui.toggle("Console"); }
            4 => state.selected_entity_name = None,
            _ => {}
        }
        
        let widgets = dev_ui.render(&state);
        
        // 输出 widgets
        for w in &widgets {
            println!("  {:?}", w);
        }
        
        // 状态
        let open_count = dev_ui.panels.iter().filter(|p| p.is_open).count();
        println!("  ({} panels open, {} widgets)", open_count, widgets.len());
        println!();
    }
    
    // 模拟鼠标点击 hit test
    println!("=== Input 路由演示 ===\n");
    
    let click_positions = [
        (Vec2::new(50.0, 50.0), "Inspector 区域"),
        (Vec2::new(700.0, 50.0), "Performance 区域"),
        (Vec2::new(50.0, 500.0), "Console 区域"),
        (Vec2::new(400.0, 300.0), "中央(无 panel)"),
    ];
    
    for (pos, desc) in click_positions {
        let mut hit: Option<&str> = None;
        for p in &dev_ui.panels {
            if !p.is_open { continue; }
            let origin = match p.position {
                PanelPosition::TopLeft => Vec2::new(10.0, 10.0),
                PanelPosition::TopRight => Vec2::new(590.0, 10.0),
                PanelPosition::BottomLeft => Vec2::new(10.0, 490.0),
                PanelPosition::BottomRight => Vec2::new(590.0, 490.0),
            };
            let rect = Rect::new(origin.x, origin.y, 200.0, 100.0);
            if rect.contains(pos) {
                hit = Some(&p.name);
                break;
            }
        }
        
        match hit {
            Some(name) => println!("Click ({}, {}) {}: → {}", pos.x, pos.y, desc, name),
            None => println!("Click ({}, {}) {}: → (game world)", pos.x, pos.y, desc),
        }
    }
}

mod tests {
    use super::*;

    fn test_panel_toggle() {
        let mut ui = DeveloperUI::new();

    fn test_rect_contains() {
        let r = Rect::new(10.0, 10.0, 100.0, 50.0);
        
        assert!(r.contains(Vec2::new(50.0, 30.0)));
        assert!(r.contains(Vec2::new(10.0, 10.0)));    // 左上角
        assert!(r.contains(Vec2::new(110.0, 60.0)));   // 右下角
        
        assert!(!r.contains(Vec2::new(5.0, 30.0)));    // 太左
        assert!(!r.contains(Vec2::new(50.0, 5.0)));    // 太上
        assert!(!r.contains(Vec2::new(150.0, 30.0)));  // 太右
        assert!(!r.contains(Vec2::new(50.0, 100.0)));  // 太下
    }
    
    #[test]
    fn test_render_open_vs_closed() {
        let mut ui = DeveloperUI::new();
        let state = GameState {
            fps: 60.0, entity_count: 0,
            selected_entity_name: None, selected_pos: [0.0; 3],
            log_messages: vec![], update_time_ms: 0.0, render_time_ms: 0.0,
        };
        
        let widgets_open = ui.render(&state);
        let open_count = ui.panels.iter().filter(|p| p.is_open).count();
        assert_eq!(open_count, 3);  // Performance, Inspector, Console
        assert!(widgets_open.len() > 10);  // 应该有很多 widget
        
        // 关掉所有 panel
        for p in &ui.panels {
            if p.is_open { ui.toggle(&p.name); }
        }
        
        let widgets_closed = ui.render(&state);
        assert!(widgets_closed.is_empty());
    }
```
