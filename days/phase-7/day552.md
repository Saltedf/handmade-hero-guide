
# Day 552 · 生成采样球到 INL

> 光探针要采样"球面方向"——每个 voxel 从自己位置向各方向射采样射线,看光来自哪里。Day 552 Casey 把**球面上均匀分布的方向向量**生成并打包到 INL(include file / inline lookup),后续 raycast 复用。

## 0 · 为什么要有这一天

### 真实场景:为什么需要"预生成采样球"

光探针的查询是这样的:voxel 在某点,要看"我从所有方向接收了多少光"。理论上,光从球面所有方向(4π 立体角)来,我们要积分所有方向的入射光。

球面是连续的,采样要离散——选 N 个方向,raycast 每个方向,累加。**采样越多越准,但越慢**。

让我们把镜头拉近。假设你做光探针系统,每个 voxel 在每帧渲染时,从自己位置发射 64 条射线,采样 64 个方向的光。每条射线做 raycast(检查命中物体 + 取颜色)。

如果这 64 个方向**每帧重新计算**(用 PRNG 生成),有两个问题:

**第一,随机性导致闪烁**。每帧的方向不同,raycast 结果不同,光照值不同,**画面闪烁**。这破坏视觉稳定。

**第二,性能浪费**。生成 64 个均匀分布的方向不便宜(要算法 + sqrt + 三角函数),每帧每 voxel 都算,浪费 CPU。

工业做法:用预计算的**球面均匀分布**——N 个方向均匀撒在球面上。这 N 个方向可以离线生成,程序运行时直接读取。

Casey 把这 N 个方向**预生成**到 INL(`.inl` 文件,Casey 自己造的格式,意为"inline lookup")。运行时不需要每次重新算,直接用。

### 球面均匀分布为什么难

直觉上"在球面上均匀撒点"听起来简单——随便撒就行。但**实际很难**:

**朴素方法**:球坐标 (θ, φ),θ ∈ [0, π],φ ∈ [0, 2π]。均匀撒 θ 和 φ,转笛卡尔坐标。

```
x = sin(θ) cos(φ)
y = sin(θ) sin(φ)
z = cos(θ)
```

但这**不均匀**——两极(θ ≈ 0 / θ ≈ π)密集,赤道(θ ≈ π/2)稀疏。原因是球坐标的面积元素 `sin(θ) dθ dφ` 有个 sin(θ) 因子,极点 sin 接近 0,赤道 sin = 1。

**修正方法 1**:θ 用 `acos(1 - 2*u)` 而不是均匀,修正面积元素。这是 inversion method。

**修正方法 2(更好)**:**Fibonacci 球面**——基于黄金分割比的螺旋分布,天然均匀,无需随机。

Fibonacci 球面的算法:
```rust
fn fibonacci_sphere(n: usize) -> Vec<[f32; 3]> {
    let golden = (1.0 + 5.0_f32.sqrt()) / 2.0;  // 黄金比
    let angle_inc = 2.0 * PI * golden;
    (0..n).map(|i| {
        let t = i as f32 / n as f32;
        let inclination = (1.0 - 2.0 * t).acos();
        let azimuth = angle_inc * i as f32;
        [
            inclination.sin() * azimuth.cos(),
            inclination.sin() * azimuth.sin(),
            inclination.cos(),
        ]
    }).collect()
}
```

这就是 Day 552 的核心算法。Fibonacci 球面是工业级金标,Unreal、Unity、path tracer 都用它。

### INL(Inline Lookup)的设计

Casey 自创的 INL 格式:**离线生成 + 嵌入 binary**。流程:

1. **Build 时**:运行生成器,算 64 个 Fibonacci 方向,写到 `.inl` 文件(二进制)
2. **Compile 时**:`include_bytes!("samples.inl")` 把文件嵌入 binary
3. **Runtime**:直接读 binary 里的字节,转 Vec3 数组

优势:
- **零运行时计算**:64 个方向在编译时已经算好
- **稳定**:每次运行得到相同方向(确定性)
- **可移植**:不依赖 PRNG 算法实现细节

劣势:
- **不可变**:换 N(比如 64 → 128)要重 build
- **binary 变大**:每方向 12 字节(Vec3),64 个 = 768 字节。可接受。

工业级类比:
- **OpenGL shaders**:编译时嵌入 binary(类似 INL)
- **Embedded assets**:游戏的图片 / 音频 / 模型都嵌入 binary
- **Lookup tables**:数学函数(sin / cos)的预计算表

## 2 · 心智模型

### 类比:全景相机的多镜头

想象你要拍一张全景照片(360 度)。你可以用一个旋转的相机(慢),或者多个相机围成球(快)。后者:8 个相机各拍 45 度,拼起来就是全景。

但 8 个相机有缝隙(45 度太宽),图像不连续。64 个相机,每个拍 5.6 度,缝隙小很多。256 个相机,缝隙几乎不可见。

光探针也是这样:每个方向是一条"虚拟相机视线",N 个方向拼成"球面光场"。N 越多,采样越细。

### 严谨展开:Fibonacci 球面算法

最简单又均匀的球面分布算法:

```rust
fn fibonacci_sphere(n: usize) -> Vec<[f32; 3]> {
    let mut points = Vec::with_capacity(n);
    let golden_ratio = (1.0 + 5.0_f32.sqrt()) / 2.0;
    let angle_increment = std::f32::consts::TAU * golden_ratio;

    for i in 0..n {
        let t = i as f32 / n as f32;
        let inclination = (1.0 - 2.0 * t).acos();  // 极角 [0, π]
        let azimuth = angle_increment * i as f32;  // 方位角 [0, 2π)

        let x = inclination.sin() * azimuth.cos();
        let y = inclination.sin() * azimuth.sin();
        let z = inclination.cos();
        points.push([x, y, z]);
    }
    points
}
```

原理:

- **黄金比例**(`golden_ratio`)是无理数,保证连续点不重合
- **inclination**(极角)从北极均匀扫到南极
- **azimuth**(方位角)每步旋转黄金比例 * 2π

结果:点在球面上分布均匀,无聚集无空隙。

### 为什么不用"经纬度网格"?

经纬度网格(等距分割 latitude 和 longitude)有两个问题:

- 极点附近点密集(纬度圈短)
- 赤道附近点稀疏

Fibonacci 球面通过黄金比例的螺旋分布,完美避免这个——点面积近似均匀。

### 球谐函数 vs 直接采样

更高级的方法是 **Spherical Harmonics(球谐函数)**——用一组正交基函数表示球面函数。2 阶 SH = 9 个系数,3 阶 = 16 个。

SH 的优点:存储少(9 个 f32 vs 64 个 3D 向量 = 192 个 f32),且支持解析积分。

缺点:对"高频细节"(尖锐阴影)拟合差——SH 是低通滤波器。

Casey 用直接采样,因为简单直观。后面可能加 SH 优化。

## 3 · 四域深入

### 3.1 · 游戏编程视角

球面采样的工业用法:

- **IBL(image-based lighting)**:HDR 环境贴图采样,做反射
- **AO(ambient occlusion)**:多个方向 raycast,平均遮挡
- **Soft shadows**:从光源采样多个点,平均可见性
- **Reflection probes**:cube map 渲染,6 个方向

Fibonacci 球面在所有这些场景都是默认选择——简单又均匀。

### 3.2 · 图形学视角

球面采样的数学:**蒙特卡洛积分**。

```
∫_sphere f(ω) dω ≈ (4π / N) * Σ f(ω_i)
```

ω_i 是球面上的采样方向,N 是采样数。N 越大,方差越小,近似越好。

**Stratified sampling**(分层采样)比纯随机更优——把球面分成 N 个等面积区域,每区域采一个点。Fibonacci 球面是隐式的 stratified sampling。

**Importance sampling**(重要性采样):采样分布匹配被积函数的分布。如果光主要来自上方,采样上方密集,减少方差。

### 3.3 · 🐧 Linux 系统编程视角

"预生成数据 + 内嵌"模式在系统编程无处不在:

- **Lookup table(查找表)**:数学函数预计算,运行时 O(1) 查。CRC32 表(256 项)、AES S-box(256 字节)
- **sin/cos 表**:嵌入式常用,避免浮点计算。早期 8-bit 时代必备,现在 FPU 快了但仍是某些 SIMD 路径优化
- **Random seed table**:预生成的随机数序列,Linux 内核的 `/dev/random` 初始化用
- **ML weights**:模型权重内嵌到二进制——TensorFlow Lite、ONNX Runtime 的 embedded model 模式
- **Font rasterization cache**:字体 outline 预渲染,文字渲染时 O(1) 查
- **Unicode normalization table**:Unicode 标准的 lookup table,UTF-8 处理必备

Linux 内核也有:LUT 表(`DECLARE_LUT`)、`linux/random.h` 的种子表、`crc32c_table` 的预计算表、SCTP/Network 协议的 CRC 表。

**Precompute 的本质**:**把 runtime 计算换成 memory lookup**——空间换时间。如果数据用很多次(64 个方向 × 200 万像素 × 60 FPS = 75 亿次),precompute 一次省 75 亿次计算,值得 768 字节内存。**这就是编译器的哲学**——AOT 编译把"runtime 计算字节码"换成"compile time 翻译机器码",runtime 直接执行。

### 3.4 · 🦀 Rust 生态视角

Rust 用 `include_bytes!` 或 `include_str!` 内嵌数据:

```rust
// 编译时把生成的采样数据嵌入二进制
const SAMPLING_SPHERE_64: &str = include_str!("../data/sphere64.inl");

fn load_sphere() -> Vec<[f32; 3]> {
    SAMPLING_SPHERE_64
        .lines()
        .map(|line| {
            let parts: Vec<f32> = line.split_whitespace()
                .map(|s| s.parse().unwrap())
                .collect();
            [parts[0], parts[1], parts[2]]
        })
        .collect()
}
```

更高效用二进制:

```rust
// build.rs 生成 sphere.bin
const SPHERE: &[u8] = include_bytes!("../data/sphere64.bin");

fn load_sphere_bin() -> Vec<[f32; 3]> {
    SPHERE.chunks_exact(12)
        .map(|chunk| {
            let x = f32::from_le_bytes(chunk[0..4].try_into().unwrap());
            let y = f32::from_le_bytes(chunk[4..8].try_into().unwrap());
            let z = f32::from_le_bytes(chunk[8..12].try_into().unwrap());
            [x, y, z]
        })
        .collect()
}
```

二进制更紧凑(每点 12 字节 vs 文本约 30 字节),且加载快。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Fibonacci 球面比经纬度网格"均匀"?怎么量化"均匀性"?

**参考解答**:经纬度网格在极点附近点密集(因为纬度圈短),赤道稀疏。Fibonacci 球面通过黄金比例的螺旋,每个点的"领地面积"近似相等。量化均匀性:计算每个点到最近邻居的距离,标准差越小越均匀。Fibonacci 的标准差比经纬度低 5-10 倍。

### Lv2 · 动手实践

**题**:生成 64 个 Fibonacci 球面方向,验证均匀性。

要求:
- 生成 64 个方向
- 打印前 5 个
- 计算每个点到最近邻居的距离的平均值和标准差
- 标准差 < 0.1 表示均匀

**参考解答**:

```rust
fn fibonacci_sphere(n: usize) -> Vec<[f32; 3]> {
    let mut points = Vec::with_capacity(n);
    let golden = (1.0_f32 + 5.0_f32.sqrt()) / 2.0;
    let angle_inc = std::f32::consts::TAU * golden;
    for i in 0..n {
        let t = i as f32 / n as f32;
        let inc = (1.0 - 2.0 * t).acos();
        let az = angle_inc * i as f32;
        points.push([inc.sin() * az.cos(), inc.sin() * az.sin(), inc.cos()]);
    }
    points
}

fn main() {
    let pts = fibonacci_sphere(64);

    for p in pts.iter().take(5) {
        println!("({:.4}, {:.4}, {:.4})", p[0], p[1], p[2]);
    }

    let mut min_dists = Vec::new();
    for i in 0..pts.len() {
        let mut min_d = f32::MAX;
        for j in 0..pts.len() {
            if i == j { continue; }
            let dx = pts[i][0] - pts[j][0];
            let dy = pts[i][1] - pts[j][1];
            let dz = pts[i][2] - pts[j][2];
            let d = (dx*dx + dy*dy + dz*dz).sqrt();
            if d < min_d { min_d = d; }
        }
        min_dists.push(min_d);
    }

    let mean = min_dists.iter().sum::<f32>() / min_dists.len() as f32;
    let variance = min_dists.iter().map(|d| (d - mean).powi(2)).sum::<f32>() / min_dists.len() as f32;
    let stddev = variance.sqrt();
    println!("Mean nearest distance: {:.4}", mean);
    println!("Stddev: {:.4}", stddev);
}
```

## 8 · Rust / Arch 落地代码

完整 Fibonacci sphere + INL 生成 + 加载:

```rust
use std::fs::File;
use std::io::{Write, Read};
use std::path::Path;

// 生成 Fibonacci sphere,返回 N 个 3D 单位向量
fn fibonacci_sphere(n: usize) -> Vec<[f32; 3]> {
    let mut points = Vec::with_capacity(n);
    let golden = (1.0_f32 + 5.0_f32.sqrt()) / 2.0;
    let angle_increment = std::f32::consts::TAU * golden;
    for i in 0..n {
        let t = i as f32 / n as f32;
        let inclination = (1.0 - 2.0 * t).acos();
        let azimuth = angle_increment * i as f32;
        let sin_inc = inclination.sin();
        points.push([
            sin_inc * azimuth.cos(),
            sin_inc * azimuth.sin(),
            inclination.cos(),
        ]);
    }
    points
}

// 保存到二进制 INL 文件
fn save_inl_bin(path: &Path, points: &[[f32; 3]]) -> std::io::Result<()> {
    let mut file = File::create(path)?;
    for p in points {
        file.write_all(&p[0].to_le_bytes())?;
        file.write_all(&p[1].to_le_bytes())?;
        file.write_all(&p[2].to_le_bytes())?;
    }
    Ok(())
}

// 从二进制 INL 文件加载
fn load_inl_bin(path: &Path) -> std::io::Result<Vec<[f32; 3]>> {
    let mut file = File::open(path)?;
    let mut buf = Vec::new();
    file.read_to_end(&mut buf)?;

    let mut points = Vec::with_capacity(buf.len() / 12);
    for chunk in buf.chunks_exact(12) {
        let x = f32::from_le_bytes(chunk[0..4].try_into().unwrap());
        let y = f32::from_le_bytes(chunk[4..8].try_into().unwrap());
        let z = f32::from_le_bytes(chunk[8..12].try_into().unwrap());
        points.push([x, y, z]);
    }
    Ok(points)
}

fn main() {
    let path = std::path::Path::new("/tmp/sphere64.inl");

    // 生成 + 保存
    let pts = fibonacci_sphere(64);
    save_inl_bin(path, &pts).expect("save failed");
    println!("Saved 64 sampling directions to {:?}", path);

    // 加载
    let loaded = load_inl_bin(path).expect("load failed");
    println!("Loaded {} directions", loaded.len());

    // 验证:都是单位向量
    for p in &loaded {
        let mag = (p[0]*p[0] + p[1]*p[1] + p[2]*p[2]).sqrt();
        assert!((mag - 1.0).abs() < 0.001);
    }
    println!("All vectors are unit-length ✓");

    // 验证保存/加载一致
    for i in 0..loaded.len() {
        for c in 0..3 {
            assert_eq!(loaded[i][c].to_bits(), pts[i][c].to_bits());
        }
    }
    println!("Round-trip OK ✓");

    // 内嵌使用(运行时不需要文件)
    // 在 build.rs 生成 + include_bytes!:
    // const SPHERE: &[u8] = include_bytes!("sphere64.inl");
}
```

### 附录:Fibonacci 球面的数学美

Fibonacci 球面看起来简单,但背后有深数学。让我们欣赏一下。

#### 黄金比例的"最无理"性质

黄金比 φ = (1+√5)/2 ≈ 1.618。它的连分数展开:

```
φ = 1 + 1/(1 + 1/(1 + 1/...))
```

全 1 的连分数,意味着 φ 是**最难被有理数逼近**的无理数。换句话说,φ 在数轴上"最远离"任何简单分数。

应用到球面采样:用 φ 作为螺旋的"步长",每个点的角度增量是 2π × φ。因为 φ 最难被分数逼近,**每个点和前面所有点的角度差异最大**——分布最均匀。

对比其他无理数:
- √2 ≈ 1.414:连分数 [1; 2, 2, 2, ...],逼近较快(2 比 1 远)
- π ≈ 3.14159:连分数复杂
- e ≈ 2.71828:连分数有规律

φ 的"最难逼近"性质让它成为球面采样的金标。

#### Vogel 1995 的论文

Fibonacci 球面最早的现代形式来自 Helaman Vogel 1979 论文 "A better way to construct the sunflower head"。这个算法是从向日葵种子分布启发——向日葵的种子也用 φ 螺旋分布,保证每颗种子得到最多阳光。

数学和自然的连接——Day 552 的算法是**仿生学**。

#### Blue noise 的优势

Fibonacci 球面是"低偏差"(low-discrepancy)分布。它的特点是**没有聚集点 + 没有大缝隙**。这就是 blue noise 的频域特征——低频(聚集)被抑制,高频(均匀)被保留。

Blue noise 在图形学中很重要——避免"锯齿"(aliasing)。AA (anti-aliasing) 的 MSAA / TAA 都用 blue noise 样本。

#### 工业级采样库

Rust 生态的采样库:
- **`blue-noise-sampler`**:Rust blue noise 库
- **`low-discrepancy-sequence`**:Halton / Sobol 序列
- **`rand`**:通用 PRNG(不直接产球面均匀)

工业级 GI 系统(Unreal Lumen、Unity HDRP)用更高级的采样——基于**Hammersley sequence** 或 **Owen-scrambled Sobol**。这些是 Day 552 的进化版。
