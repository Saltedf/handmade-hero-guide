# Day 149 · 把资产写入资产文件

> Day 148 写了 16 字节 header。今天 Casey 把真实资产——BMP 文件解出来的像素、WAV 解出来的 sample——按 (offset, size) 写进 .hha 末尾的 blob 段,并在中间写每个 asset 的索引。难点是**怎么算 offset**:每个 asset 的 data_offset 必须是它实际数据在文件里的字节位置,这要求你在写之前知道前面所有 asset 的大小。

## 0 · 为什么要有这一天

打包器要做两件事:

1. **遍历输入目录**,列出所有要打包的资产
2. **写出 .hha**,内容是 header + asset 索引 + 数据 blob

第二件事拆开看:

```
file: [header 16B] [asset[0] 24B] [asset[1] 24B] ... [asset[N-1] 24B] [data blob]
```

每个 `asset[i]` 里的 `data_offset` 是它的数据在 blob 段中的绝对文件偏移。所以:

```
blob_start = 16 + N * 24
asset[i].data_offset = blob_start + sum(asset[0..i].data_size)
```

这要求**先知道每个 asset 的 size**——也就是要先读一遍所有源文件,算 size,才能开始写。

**两阶段写**就来了:

- 阶段 1:**扫描 + 计算**。读每个 BMP/WAV header,知道 dimension/format,算 size,记下来
- 阶段 2:**写**。按顺序写每个 asset 索引 + blob 数据

或者**单阶段 + seek**:

- 阶段 1:写 header + 写空 asset 索引(留位置)
- 阶段 2:逐个 asset 写,记下 (offset, size),先写 blob 数据
- 阶段 3:回头 seek 到 asset 索引区,填具体内容

Casey 用单阶段 + seek,代码紧凑。

今天的真正主题是 **二进制写入的工程模式**:

- 怎么用 `Write` trait 的链式 buffer
- 怎么跟踪文件 cursor 位置
- 怎么从 BMP/WAV 提取原始数据(已经有了,Day 138 / 147)

心理锚点:看完今天,你能写一个打包器,把 5 个 BMP + 3 个 WAV 打包成单个 .hha,文件结构正确,asset_count 和 data_offset 都对。

## 1 · Casey 今天做了什么

Casey 的代码大致结构:

1. 写 16 字节 header(`asset_count = 0` 占位)
2. 在内存里维护 `Vec<HhaAsset>` 索引,先不写文件
3. 对每个输入文件:
   - 读 BMP / WAV header,得到 size + format
   - 把 asset 数据追加写到文件末尾(`file.seek(End)` 然后写)
   - 记下此时的 offset 和 size,加进 `Vec<HhaAsset>`
4. 全部写完后,seek 回 asset 索引区,把 `Vec<HhaAsset>` 写进去
5. 更新 header 的 `asset_count`,seek 回开头重写 header
6. fsync

Casey 还讨论:

- **BMP 格式**:24-bit BMP 每像素 3 字节(BGR),要转成 RGBA8(4 字节)。size 变化。
- **WAV 格式**:PCM 16-bit mono。size 直接。
- **对齐**:每个 asset 的 data_offset 要不要 16 字节对齐?Casey 选不对齐(因为运行时 mmap 后访问随机,对齐优势消失)。但**SIMD 友好的 asset**(如 framebuffer)值得对齐——Day 127 Casey 做过。

## 2 · 心智模型

### 类比:打包搬家

你要搬家,有几箱东西。搬家公司给你一个大集装箱:

1. 先在集装箱门口放一张清单(头部 + 索引),写每个箱子的位置
2. 把箱子一个个推进集装箱,记下每个的"距门口多远"(offset)和"多大"(size)
3. 装完后,回头把清单写完整

如果清单先写完整,你必须先扫一遍所有箱子知道总大小;如果边装边写,可以单 pass。两种都可以,看你数据特性。

### 严谨模型:文件布局

```
+--------------------------------+
| header (16 B)                  |  ← offset 0
+--------------------------------+
| asset[0] descriptor (24 B)     |  ← offset 16
| asset[1] descriptor (24 B)     |  ← offset 40
| ...                            |
| asset[N-1] descriptor (24 B)   |  ← offset 16 + (N-1)*24
+--------------------------------+
| data[0] bytes (data_size[0])   |  ← offset 16 + N*24
| data[1] bytes (data_size[1])   |
| ...                            |
| data[N-1] bytes                |
+--------------------------------+
```

写入流程:

```rust
// 1. 先写空 header
file.write_all(&HhaHeader::zero())?;
let blob_start = 16 + N * 24;  // 但我们还不知道 N,因为还没扫描
```

等等——如果 N 未知,怎么算 blob_start?

**两种解法**:

**解法 A:两阶段**

```rust
// 阶段 1:扫描得到所有 asset 的 size
let mut sizes = Vec::new();
for path in &input_files {
    let size = compute_asset_size(path)?;
    sizes.push(size);
}
let n = sizes.len();
let blob_start = 16 + n * 24;

// 阶段 2:写 header + 索引占位 + blob
let mut header = HhaHeader::zero();
header.asset_count = n as u32;
file.write_all(header.as_bytes())?;

// 写空索引(下面会被覆盖)
let mut assets = Vec::with_capacity(n);
let mut offset = blob_start;
for &size in &sizes {
    assets.push(HhaAsset { data_offset: offset, data_size: size, ..zero() });
    offset += size;
}
for a in &assets {
    file.write_all(a.as_bytes())?;
}

// 写 blob
for path in &input_files {
    let data = read_asset_data(path)?;
    file.write_all(&data)?;
}
```

**解法 B:单阶段 + seek**

```rust
// 1. 写空 header
file.write_all(&HhaHeader::zero())?;

// 2. 写 N 个空 asset 索引(N 已知或最大值预留)
// ... 或不写,直接跳过

// 3. seek 到 blob_start 位置
// 但 blob_start = 16 + N * 24,N 未知...
```

解法 B 的难点是 N 未知时没法算 blob_start。**实际工程中常用解法 A**。Casey 在 HH 也是先扫描(遍历目录),算出 asset_count,再开始写。

**第三种:内存 buffer + 一次写**

```rust
// 全部在 Vec<u8> 里拼好,一次 write
let mut buf = Vec::new();
buf.extend_from_slice(&header_bytes);
buf.extend_from_slice(&asset_descriptors_bytes);
buf.extend_from_slice(&blob_bytes);
file.write_all(&buf)?;
```

适合小文件(.hha 通常 < 100 MB)。大文件用流式写。

### Asset 数据的转换

BMP 24-bit 到 RGBA8:

```rust
fn bmp_to_rgba(data: &[u8], width: usize, height: usize) -> Vec<u8> {
    let mut out = Vec::with_capacity(width * height * 4);
    for y in 0..height {
        for x in 0..width {
            let src_idx = (y * width + x) * 3;
            let b = data[src_idx];
            let g = data[src_idx + 1];
            let r = data[src_idx + 2];
            out.push(r);  // R
            out.push(g);  // G
            out.push(b);  // B
            out.push(255);// A
        }
    }
    out
}
```

注意 BMP 是 **BGR** 而非 RGB,且很多 BMP **行颠倒**(从下往上存)。这是格式坑。

WAV 16-bit mono:已经是 PCM,直接拷贝 sample 字节。

## 3 · 四域深入

### 3.1 · 游戏编程视角

工业打包器的几个加成:

- **去重**:多个关卡用同一张纹理,只打包一次,索引指向同一 offset
- **压缩**:LZ4 / Zstd 压缩 blob。Casey 不做(教学),Day 156+ 可能讲
- **mipmap**:纹理在打包时生成 mipmap 链
- **platform variants**:Windows / Mac / Linux 各自的格式(`.hha.win`, `.hha.mac`)
- **incremental**:基于源文件 hash,只重打包改动部分

### 3.2 · Linux 系统编程视角

Linux 大文件写的两个工具:

1. **`fallocate(2)`**:预分配磁盘空间,避免写时反复扩容。
   ```rust
   use std::os::unix::io::AsRawFd;
   libc::fallocate(file.as_raw_fd(), 0, 0, total_size as i64);
   ```
2. **`posix_fadvise(2)`**:告诉内核"我会顺序写",内核优化 page cache 策略。

打包器写 1 GB .hha 时,先 fallocate 整文件大小,然后顺序写,性能比"边写边扩"快 2-5 倍。

### 3.3 · Rust 生态视角

Rust 写二进制文件的两个流派:

**流派 A:`bytes_of` + `write_all`(Casey 风格)**

```rust
use bytemuck::bytes_of;
f.write_all(bytes_of(&header))?;
```

简单。padding 风险靠 `#[repr(C)]` + 设计避免。

**流派 B:`serde + bincode`**

```rust
bincode::serialize_into(&mut f, &header)?;
```

简洁。隐藏字节序。

**流派 C:manual `to_le_bytes`**

```rust
f.write_all(&header.magic)?;
f.write_all(&header.version.to_le_bytes())?;
// ...
```

啰嗦但完全控制。本日推荐 C。

### 3.4 · build 系统视角

打包器作为独立 exe,如何融入 cargo build?

**最简单**:在 build.rs 调用:

```rust
fn main() {
    println!("cargo:rerun-if-changed=assets");
    let status = std::process::Command::new("./target/release/asset_builder")
        .arg("target/game.hha")
        .arg("assets/")
        .status()
        .expect("failed to run asset_builder");
    if !status.success() {
        panic!("asset_builder failed");
    }
}
```

但这样**循环依赖**:asset_builder 还没 build 时 build.rs 跑不了。解决:用 Just / Make 把 asset_builder 和 game 分两个 target。

## 5 · 对照与变奏

### 不同打包器的写入策略

| 工具 | 策略 | 适合 |
|---|---|---|
| tar | 流式,边读边写 | 通用归档 |
| zip | 先建索引(Central Directory),数据在前 | 增量修改 |
| .hha(本日) | 先 header 占位,seek 改 | 简单 |
| ELF | section header 在文件末尾,数据在前 | 链接器需求 |
| PE | section header 在文件中,数据在后 | Windows 习惯 |

zip 是个有趣例子:它的 Central Directory(索引)在文件**末尾**,数据在中间。这样**追加新文件**容易——直接在末尾追加 + 重写 Central Directory。

### Asset 大小估算

游戏 asset 通常大小:

| 类型 | 单个大小 |
|---|---|
| 2D sprite (64×64) | 16 KB |
| 2D sprite (256×256) | 256 KB |
| 3D texture (1024²) | 4 MB |
| 3D texture (4096²) | 64 MB |
| SFX (1s WAV 48kHz) | 192 KB |
| BGM (3min Ogg) | 3 MB |
| Font (256 glyphs) | 256 KB |

中型游戏总 asset 1-10 GB。打包器性能重要——10 GB 写盘可能 30-60 秒。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:如果用"单阶段 + seek"写 .hha,asset_count 未知,怎么决定 blob_start?

**参考解答**:两种思路:

1. **预留最大 asset_count**:比如假设最多 10000 个 asset,blob_start = 16 + 10000 * 24 = 240016。所有 .hha 文件至少这么大,空间浪费。
2. **两阶段必经**:即使在写时用单阶段,也必须先扫描目录得 N,才能算 blob_start。所以实际上"单阶段"也包含一个"扫描阶段"。

工业级方案是扫描阶段 + 写阶段。Casey 用扫描目录得 N,然后写。

### Lv2 · 动手实践

**题**:扩展 Day 148 的打包器,扫描 `assets/` 目录所有 `.txt` 文件(假装是 asset),把每个文件作为 asset 打进 .hha。要求:

1. 每个 asset 的 data 是文件内容(UTF-8 文本)
2. asset_type = 0(text)
3. 写完正确填充 asset_count、data_offset、data_size

**参考解答**:

```rust
use std::fs::{self, File};
use std::io::{BufWriter, Write, Seek, SeekFrom};
use std::path::Path;

#[repr(C)]
#[derive(Copy, Clone, Debug)]
pub struct HhaHeader {
    pub magic: [u8; 4],
    pub version: u32,
    pub tag_count: u32,
    pub asset_count: u32,
}

#[repr(C)]
#[derive(Copy, Clone, Debug)]
pub struct HhaAsset {
    pub asset_type: u32,
    pub first_tag_index: u32,
    pub one_past_last_tag_index: u32,
    pub data_offset: u64,
    pub data_size: u64,
}

const HHA_MAGIC: [u8; 4] = *b"HHA2";
const HHA_VERSION: u32 = 2;

fn write_header<W: Write>(w: &mut W, h: &HhaHeader) -> std::io::Result<()> {
    w.write_all(&h.magic)?;
    w.write_all(&h.version.to_le_bytes())?;
    w.write_all(&h.tag_count.to_le_bytes())?;
    w.write_all(&h.asset_count.to_le_bytes())
}

fn write_asset<W: Write>(w: &mut W, a: &HhaAsset) -> std::io::Result<()> {
    w.write_all(&a.asset_type.to_le_bytes())?;
    w.write_all(&a.first_tag_index.to_le_bytes())?;
    w.write_all(&a.one_past_last_tag_index.to_le_bytes())?;
    w.write_all(&a.data_offset.to_le_bytes())?;
    w.write_all(&a.data_size.to_le_bytes())
}

fn build(out: &Path, input_dir: &Path) -> std::io::Result<()> {
    // 1. 扫描目录
    let mut entries: Vec<_> = fs::read_dir(input_dir)?
        .filter_map(|e| e.ok())
        .map(|e| e.path())
        .filter(|p| p.extension().map_or(false, |e| e == "txt"))
        .collect();
    entries.sort();

    // 2. 读所有文件内容
    let mut blobs: Vec<Vec<u8>> = Vec::with_capacity(entries.len());
    for path in &entries {
        let data = fs::read(path)?;
        blobs.push(data);
    }
    let n = blobs.len();

    // 3. 算 blob_start
    let blob_start = 16 + n * std::mem::size_of::<HhaAsset>();

    // 4. 算每个 asset 的 (offset, size)
    let mut offset = blob_start as u64;
    let assets: Vec<HhaAsset> = blobs.iter().map(|b| {
        let a = HhaAsset {
            asset_type: 0,
            first_tag_index: 0,
            one_past_last_tag_index: 0,
            data_offset: offset,
            data_size: b.len() as u64,
        };
        offset += b.len() as u64;
        a
    }).collect();

    // 5. 写文件
    let file = File::create(out)?;
    let mut w = BufWriter::new(file);

    let header = HhaHeader {
        magic: HHA_MAGIC, version: HHA_VERSION,
        tag_count: 0, asset_count: n as u32,
    };
    write_header(&mut w, &header)?;

    for a in &assets {
        write_asset(&mut w, a)?;
    }

    for b in &blobs {
        w.write_all(b)?;
    }

    w.flush()?;
    println!("wrote {} with {} assets", out.display(), n);
    Ok(())
}

fn main() -> std::io::Result<()> {
    let dir = Path::new("assets");
    fs::create_dir_all(dir)?;
    fs::write("assets/a.txt", b"hello")?;
    fs::write("assets/b.txt", b"world!")?;

    build(Path::new("test1.hha"), dir)
}
```

## 8 · Rust / Arch 落地代码

完整 .hha 打包器(Lv2 的版本),加读回验证:

```rust
use std::fs::{self, File, OpenOptions};
use std::io::{BufWriter, BufReader, Write, Read, Seek, SeekFrom};
use std::path::Path;

#[repr(C)]
#[derive(Copy, Clone, Debug)]
pub struct HhaHeader { pub magic: [u8; 4], pub version: u32, pub tag_count: u32, pub asset_count: u32 }

#[repr(C)]
#[derive(Copy, Clone, Debug)]
pub struct HhaAsset { pub asset_type: u32, pub first_tag_index: u32, pub one_past_last_tag_index: u32, pub data_offset: u64, pub data_size: u64 }

const HHA_MAGIC: [u8; 4] = *b"HHA2";
const HHA_VERSION: u32 = 2;

fn write_struct<W: Write, T>(w: &mut W, _t: &T, fields: &[&[u8]]) -> std::io::Result<()> {
    for f in fields { w.write_all(f)?; }
    Ok(())
}

fn main() -> std::io::Result<()> {
    let dir = Path::new("assets");
    fs::create_dir_all(dir)?;
    fs::write("assets/a.txt", b"hello")?;
    fs::write("assets/b.txt", b"world!!")?;
    fs::write("assets/c.txt", b"rust lang")?;

    // 1. 扫描
    let mut paths: Vec<_> = fs::read_dir(dir)?
        .filter_map(|e| e.ok())
        .map(|e| e.path())
        .filter(|p| p.extension().map_or(false, |e| e == "txt"))
        .collect();
    paths.sort();

    // 2. 读内容
    let blobs: Vec<Vec<u8>> = paths.iter().map(|p| fs::read(p).unwrap()).collect();
    let n = blobs.len();
    let blob_start = (16 + n * std::mem::size_of::<HhaAsset>()) as u64;

    // 3. 写
    let file = File::create("test1.hha")?;
    let mut w = BufWriter::new(file);

    // header
    w.write_all(&HHA_MAGIC)?;
    w.write_all(&HHA_VERSION.to_le_bytes())?;
    w.write_all(&0u32.to_le_bytes())?;  // tag_count
    w.write_all(&(n as u32).to_le_bytes())?;

    // asset 索引
    let mut offset = blob_start;
    for b in &blobs {
        let a = HhaAsset {
            asset_type: 0,
            first_tag_index: 0,
            one_past_last_tag_index: 0,
            data_offset: offset,
            data_size: b.len() as u64,
        };
        w.write_all(&a.asset_type.to_le_bytes())?;
        w.write_all(&a.first_tag_index.to_le_bytes())?;
        w.write_all(&a.one_past_last_tag_index.to_le_bytes())?;
        w.write_all(&a.data_offset.to_le_bytes())?;
        w.write_all(&a.data_size.to_le_bytes())?;
        offset += b.len() as u64;
    }

    // blob
    for b in &blobs {
        w.write_all(b)?;
    }

    w.flush()?;
    drop(w);

    // fsync
    let f = OpenOptions::new().write(true).open("test1.hha")?;
    f.sync_all()?;

    println!("wrote {} assets", n);

    // 读回验证
    let f = File::open("test1.hha")?;
    let mut r = BufReader::new(f);
    let mut magic = [0u8; 4];
    r.read_exact(&mut magic)?;
    assert_eq!(magic, HHA_MAGIC);

    let mut b4 = [0u8; 4];
    r.read_exact(&mut b4)?;
    assert_eq!(u32::from_le_bytes(b4), HHA_VERSION);
    r.read_exact(&mut b4)?;  // tag_count
    r.read_exact(&mut b4)?;
    let count = u32::from_le_bytes(b4);
    assert_eq!(count as usize, n);

    for i in 0..count {
        let mut a_bytes = [0u8; std::mem::size_of::<HhaAsset>()];
        r.read_exact(&mut a_bytes)?;
        // 拆 offset/size
        let offset = u64::from_le_bytes(a_bytes[12..20].try_into().unwrap());
        let size = u64::from_le_bytes(a_bytes[20..28].try_into().unwrap());
        println!("asset[{}]: offset={} size={}", i, offset, size);
    }

    Ok(())
}
```

**关键 Rust**:
- `try_into().unwrap()` —— `[u8; 8]` 转 `[u8; 8]`(其实直接拷贝)。`try_into` 用于不同长度的 array 转换。
- `BufReader` —— 读缓冲,对应 BufWriter。
- `read_exact` —— 严格读 N 字节,不够报 EOF。

**预期输出**:
```
wrote 3 assets
asset[0]: offset=88 size=5
asset[1]: offset=93 size=7
asset[2]: offset=100 size=9
```

每个 asset descriptor 是 28 字节(4+4+4+8+8),不是 24 字节,因为我们用了 u64 而不是 u32。重新算:4+4+4+8+8 = 28。3 个 asset 索引 = 84 字节。header 16 字节。blob_start = 16 + 84 = 100。第一个 asset offset 应该是 100,不是 88。

修正:让 asset descriptor 是 24 字节,把 data_offset 和 data_size 用 u32 而非 u64(假设 asset < 4 GB)。或者接受 28 字节,算清楚。

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
