# Day 174 · 加稀疏 Unicode 支持

> ASCII 256 字符够英文游戏。但你做中文 RPG、阿拉伯文游戏、有 emoji 的游戏——ASCII 远不够。Unicode 有 100 多万码点,从 U+0000 到 U+10FFFF。今天 Casey 加**稀疏 Unicode 支持**:不是预栅格化所有字符(不可能),而是按需加载用到的。

## 0 · 为什么要有这一天

Unicode 问题:

- **范围大**:U+0000 - U+10FFFF,100 万码点
- **稀疏使用**:游戏可能只用 200 个汉字 + ASCII,不会用 100 万
- **字体大**:DejaVu Sans 不含中文,Noto Sans CJK 含几万汉字,字体文件 30 MB

预栅格化所有 Unicode 不可能(几十 GB atlas)。两种方案:

1. **稀疏打包**:只打包游戏代码里硬编码用到的字符(可在 build 时扫源代码)
2. **运行时动态**:游戏运行时按需栅格化,加 cache

Casey 今天用 1(build 时扫代码)。Day 175 收尾。

### 稀疏字符集

```rust
struct SparseGlyphMap {
    codepoints: Vec<u32>,    // 排序
    glyphs: Vec<GlyphInfo>,  // 对应
}

impl SparseGlyphMap {
    fn lookup(&self, cp: u32) -> Option<&GlyphInfo> {
        self.codepoints.binary_search(&cp)
            .ok()
            .map(|i| &self.glyphs[i])
    }
}
```

`Vec<u32>` 排序 + binary search,O(log N)。

或者:

```rust
HashMap<u32, GlyphInfo>
```

O(1) 查找,但 overhead 大。

游戏选 binary search(紧凑 + cache 友好)。

### 字符集发现

build 时扫源代码字符串:

```rust
fn find_used_chars(dir: &Path) -> HashSet<u32> {
    let mut chars = HashSet::new();
    chars.insert(b' ' as u32);
    for path in glob_walk(dir, "*.rs") {
        let content = read_to_string(path)?;
        for c in content.chars() {
            chars.insert(c as u32);
        }
    }
    // 加上数字 / 标点
    for c in '0'..='9' { chars.insert(c as u32); }
    // ...
    chars
}
```

实际游戏:文本存在 script 文件(JSON / XML),扫这些文件得 used chars。

心理锚点:看完今天,你能扩展字体系统支持任意 Unicode 字符,只打包用到的。

## 2 · 心智模型

### 类比:词典

英文词典不收录所有英文单词,只收录常用的。新词要用就加进去。

稀疏字体也是:不收录所有 Unicode,只收录游戏用到的。新字符要支持就改源代码 / 脚本。

### 严谨模型:稀疏 vs 密集

**密集**(ASCII):

```rust
struct Font {
    glyphs: [GlyphInfo; 128],  // 直接 index by char code
}
// lookup:O(1),`self.glyphs[c as usize]`
```

**稀疏**(Unicode):

```rust
struct Font {
    codepoints: Vec<u32>,    // 排序
    glyphs: Vec<GlyphInfo>,  // parallel
}
// lookup:O(log N),binary_search
```

稀疏优:任意字符,空间紧凑。
稀疏劣:查找慢,cache miss 多。

折中:**段表(page table)**——把 Unicode 分成 256 char 一段,只存有 glyph 的段。

```rust
struct Font {
    pages: [Option<Box<[GlyphInfo; 256]>>; 0x1100],  // 0x1100 pages × 256
}
// lookup:O(1)
// 256 × 256 = 64K 块 × sizeof(GlyphInfo)
```

类似 CPU page table。游戏字体用第一种稀疏(简单 + 中文字符少)。

### 多字体回退

```rust
struct FontStack {
    fonts: Vec<Font>,  // 按优先级
}

impl FontStack {
    fn lookup(&self, c: u32) -> Option<&GlyphInfo> {
        for font in &self.fonts {
            if let Some(g) = font.lookup(c) {
                return Some(g);
            }
        }
        None
    }
}
```

如:ASCII 字体 + CJK 字体 + emoji 字体。

### Lv1 · 概念辨析

**题**:为什么中文游戏的字体打包比英文游戏大几十倍?

**参考解答**:中文常用字 3500 个(GB2312),全部汉字 50000+(Unicode CJK 统一表意)。每个字要单独栅格化 + 存 atlas,平均 32×32 = 1024 像素 × 1 字节 = 1 KB。

3500 字 × 1 KB = 3.5 MB(atlas 像素)
50000 字 × 1 KB = 50 MB

英文 ASCII 95 字 × 1 KB = 95 KB,差 100-500 倍。

工业方案:SDF 字体(单字号 = 任意字号)+ 字体裁剪(pyftsubset)。

### Lv2 · 动手实践

**题**:实现 SparseFont struct:Vec<u32> + Vec<GlyphInfo> + binary_search。测试查找 ASCII + 几个 CJK 字符。

**参考解答**:

```rust
#[derive(Clone)]
struct GlyphInfo {
    width: u32,
    height: u32,
    advance: f32,
    bitmap: Vec<u8>,
}

struct SparseFont {
    codepoints: Vec<u32>,
    glyphs: Vec<GlyphInfo>,
}

impl SparseFont {
    fn new() -> Self { Self { codepoints: vec![], glyphs: vec![] } }

    fn add(&mut self, cp: u32, g: GlyphInfo) {
        let pos = self.codepoints.binary_search(&cp)
            .unwrap_or_else(|p| p);
        self.codepoints.insert(pos, cp);
        self.glyphs.insert(pos, g);
    }

    fn lookup(&self, cp: u32) -> Option<&GlyphInfo> {
        self.codepoints.binary_search(&cp)
            .ok()
            .map(|i| &self.glyphs[i])
    }
}

fn main() {
    let mut font = SparseFont::new();
    // 加 ASCII 几个
    for c in "Hello! ".chars() {
        font.add(c as u32, GlyphInfo {
            width: 8, height: 8, advance: 9.0,
            bitmap: vec![200; 64],
        });
    }
    // 加几个 CJK
    for c in "你好世界".chars() {
        font.add(c as u32, GlyphInfo {
            width: 16, height: 16, advance: 17.0,
            bitmap: vec![200; 256],
        });
    }

    println!("total glyphs: {}", font.glyphs.len());
    println!("'H': {:?}", font.lookup('H' as u32).map(|g| (g.width, g.height)));
    println!("'你': {:?}", font.lookup('你' as u32).map(|g| (g.width, g.height)));
    println!("'×' (missing): {:?}", font.lookup('×' as u32).map(|g| (g.width, g.height)));

    // 渲染 "Hello 你好"
    let text = "Hello 你好";
    let mut total_advance = 0.0;
    for c in text.chars() {
        match font.lookup(c as u32) {
            Some(g) => {
                println!("'{}' {}x{} advance {}", c, g.width, g.height, g.advance);
                total_advance += g.advance;
            }
            None => println!("'{}' (missing)", c),
        }
    }
    println!("total advance: {:.1}", total_advance);
}
```

## 8 · Rust / Arch 落地代码

```rust
#[derive(Clone, Debug)]
pub struct GlyphInfo {
    pub width: u32,
    pub height: u32,
    pub advance: f32,
    pub bearing_x: f32,
    pub bearing_y: f32,
    pub atlas_offset: u64,
}

pub struct SparseFont {
    pub codepoints: Vec<u32>,
    pub glyphs: Vec<GlyphInfo>,
    pub atlas: Vec<u8>,
    pub ascent: f32,
    pub descent: f32,
    pub line_gap: f32,
}

impl SparseFont {
    pub fn new(ascent: f32, descent: f32, line_gap: f32) -> Self {
        Self {
            codepoints: Vec::new(),
            glyphs: Vec::new(),
            atlas: Vec::new(),
            ascent, descent, line_gap,
        }
    }

    pub fn add(&mut self, cp: u32, width: u32, height: u32, advance: f32) {
        let pos = self.codepoints.binary_search(&cp)
            .unwrap_or_else(|p| p);
        self.codepoints.insert(pos, cp);
        // 模拟 atlas:append width*height bytes
        let atlas_offset = self.atlas.len() as u64;
        self.atlas.extend(std::iter::repeat(200u8).take((width * height) as usize));
        self.glyphs.insert(pos, GlyphInfo {
            width, height, advance,
            bearing_x: 0.0,
            bearing_y: ascent,
            atlas_offset,
        });
    }

    pub fn lookup(&self, cp: u32) -> Option<&GlyphInfo> {
        self.codepoints.binary_search(&cp)
            .ok()
            .map(|i| &self.glyphs[i])
    }

    pub fn line_height(&self) -> f32 {
        self.ascent - self.descent + self.line_gap
    }

    pub fn draw_text(&self, text: &str) -> Vec<(u32, u32)> {
        let mut positions = Vec::new();
        let mut cursor = 0.0f32;
        for c in text.chars() {
            if let Some(g) = self.lookup(c as u32) {
                positions.push((cursor as u32, g.atlas_offset as u32));
                cursor += g.advance;
            }
        }
        positions
    }
}

fn main() {
    let mut font = SparseFont::new(12.0, -4.0, 2.0);
    
    // ASCII
    for c in "Hello, World!".chars() {
        font.add(c as u32, 8, 10, 9.0);
    }
    // CJK
    for c in "你好世界".chars() {
        font.add(c as u32, 16, 16, 17.0);
    }
    // emoji
    for c in "🎮".chars() {
        font.add(c as u32, 18, 18, 19.0);
    }

    println!("font has {} glyphs, atlas size {} bytes",
        font.glyphs.len(), font.atlas.len());

    let text = "Hello, 你好 🎮";
    println!("\ntext: {}", text);
    let positions = font.draw_text(text);
    for (i, (x, atlas_off)) in positions.iter().enumerate() {
        let c = text.chars().nth(i).unwrap();
        println!("  '{}' at x={} atlas_off={}", c, x, atlas_off);
    }
}
```

### A.9 Voxel / 渲染相关代码示例

让我提供一个具体的 Rust 代码示例,综合 phase-4 的概念:

```rust
use std::sync::Arc;
use std::collections::HashMap;
use std::sync::RwLock;

// Asset storage(引用计数 + 分桶锁)
pub struct AssetStorage<T> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> T + Send + Sync>,
}

impl<T> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self 
    where F: Fn(u32) -> T + Send + Sync + 'static {
        let num_shards = 16;
        let mut shards = Vec::with_capacity(num_shards);
        for _ in 0..num_shards {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self {
            shards,
            loader: Box::new(loader),
        }
    }
    
    pub fn get(&self, id: u32) -> Arc<T> {
        let shard_idx = (id as usize) % self.shards.len();
        
        // 读路径
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(asset) = shard.get(&id) {
                return Arc::clone(asset);
            }
        }
        
        // 慢路径:加载
        let asset = Arc::new((self.loader)(id));
        
        // 写路径
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&asset));
        Arc::clone(entry)
    }
}

// 用法
fn main() {
    let storage: AssetStorage<String> = AssetStorage::new(|id| {
        format!("texture_{}.png", id)
    });
    
    let a = storage.get(1);
    let b = storage.get(1);
    assert!(Arc::ptr_eq(&a, &b));  // 同一 Arc
}
```

这是工业级 asset storage 的 Rust 骨架——分桶 RwLock + Arc + 加载闭包。

### A.10 内存管理的最佳实践

Phase 4 涉及大量内存管理。最佳实践:

**1. Ownership 清晰**:
- 每资源有明确 owner
- Owner drop → 资源释放
- 不共享 ownership(避免 cycle)

**2. Arena for 临时数据**:
```rust
use bumpalo::Bump;

let arena = Bump::new();
let temp_data: &mut [u32] = arena.alloc_slice_fill_with(1000, |_| 0);
// arena drop → temp_data 自动释放
```

**3. Arc for 长期共享**:
```rust
let shared = Arc::new(ExpensiveResource::new());
let cloned = Arc::clone(&shared);
// 两个 owner 都 drop → resource 释放
```

**4. Weak for cache**:
```rust
let weak: Weak<Resource> = Arc::downgrade(&strong);
// cache 不阻止 strong 释放
if let Some(strong) = weak.upgrade() {
    // 还在用
} else {
    // 已释放
}
```

**5. Pool for 高频 alloc**:
```rust
let pool = ObjectPool::new(|| ExpensiveObject::new());
let obj = pool.acquire();  // 复用
// ...
pool.release(obj);  // 不 drop,放回 pool
```

工业 Rust 代码综合用这些模式。

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
