# Day 145 · SSE 混音器主循环

> 昨天 Day 144 留了个空位:pre 和 post 用标量写好了,中间的 main loop 占位。今天 Casey 把 main loop 用真正的 SIMD 填上。难点不是 SIMD 本身,而是 **变调 mixer 的 cursor 是浮点步进的**,4 个相邻输出 sample 对应的源位置不是连续的整数,你要在 SIMD 寄存器里同时算 4 个独立的插值——这需要"横着算"和"竖着算"组合起来。

## 0 · 为什么要有这一天

标量变调 mixer 的核心代码是:

```
对每个输出 sample:
    i = floor(cursor)
    frac = cursor - i
    y = src[i] * (1 - frac) + src[i+1] * frac
    dst[out] += y * volume
    cursor += d_sample
```

每个输出 sample 涉及:1 次 floor、1 次 sub、2 次 load、2 次 mul、1 次 add、1 次 mul(volume)、1 次 add(到 dst)、1 次 cursor add。**总共 9 次浮点运算 + 2 次内存读 + 1 次内存读写**。

10 个声音 × 48000 sample × 9 = 4.3 M op/s。CPU 一个核 ~10 G op/s,理论上单核能撑 200 个声音。听起来够。**但**:

1. **CPU 不会"自动"把你这段 SIMD 化**——Rust 编译器自动向量化对 cursor 浮点累加这种数据依赖重的循环效果不好。
2. **浮点 floor 是个慢指令**——在某些微架构上 4-10 cycles。
3. **memory random access**(cursor 跳着读 src)让 cache 不好预测。

手写 SIMD main loop 把这 9 次运算**并行**算 4 个 sample,理论 4 倍加速。结合 Day 144 的 pre/post,整个 mixer ~3-4 倍速度。

但 SIMD 化变调 mixer 比 SIMD 化"普通乘法"难多了,因为:

- **4 个输出 sample 的 cursor 不连续**:`cursor, cursor+d, cursor+2d, cursor+3d`,4 个浮点数,需要打包成 SIMD 寄存器
- **4 个 floor 同时算**:SSE 没有 floor 指令(直到 SSE4.1 才有 `_mm_floor_ps`),早期要手动用 bit trick
- **4 个 src 位置可能重叠**:如果 `d_sample < 1`,4 个 cursor 可能落在同两个源 sample 之间;如果 `d_sample > 1`,4 个 cursor 跨越多个源 sample
- **gather 指令**:AVX2 才有,一次从 4 个不连续地址 load。SSE2 没有,要标量 load 再打包

今天 Casey 把这些难点逐一解决。结果是个"看起来复杂但每行有理由"的 SIMD main loop。

心理锚点:看完今天,你能解释变调 mixer 的 main loop 为什么不能简单地"load 4 个连续 src,scale 4 个 frac,add",以及 Casey 怎么绕过这个限制。

## 1 · Casey 今天做了什么

Casey 的 main loop 实现思路(简化版):

1. 把 4 个连续 cursor 值算成 SIMD 寄存器:`[c, c+d, c+2d, c+3d]`
2. 用 `_mm_floor_ps`(SSE4.1)同时算 4 个 floor,得到 4 个整数索引 `[i0, i1, i2, i3]`
3. **4 个索引可能不同**,所以用 4 次标量 `_mm_load_ss`(或 `gather` 如果 AVX2)分别 load
4. 同样 load `i+1` 位置的 4 个值
5. 算 4 个 `frac = cursor - floor`,得到 `[f0, f1, f2, f3]`
6. 计算 `y = s0 * (1 - f) + s1 * f`,4 个 lane 独立
7. 乘 volume(SIMD 寄存器 set1)
8. load 4 个 dst(对齐)、SIMD add、store 回 dst
9. cursor 推进 4 × d_sample

视频里 Casey 反复演示:

- 如果 `d_sample = 1.0`(原速),4 个索引是连续的 `[i, i+1, i+2, i+3]`,可以一次 `_mm_load_ps(src[i..].as_ptr())` 加载,不用 gather。
- 如果 `d_sample != 1.0`,4 个索引一般不同,要 4 次标量 load 然后打包(`_mm_set_ps(a, b, c, d)`)。
- 他**分支特化**:如果 `d_sample == 1.0`,走快速路径;否则走通用路径。

这是个常见 SIMD 优化技巧:**对常见情况特化**。

## 2 · 心智模型

### 类比:邮件分拣

4 个工人围着一张桌子。每秒钟一条传送带送来 4 个信封,4 个工人**同时**各拿一个,根据信封地址(对应 src 索引)去对应的箱子取信息。

- 如果 4 个信封地址相同:4 个工人都去同一个箱子,可以"一拖三"(一个工人取,广播给其他三个)
- 如果 4 个信封地址相邻:可以让一个工人从 4 个相邻箱子里一次取 4 份(连续 load)
- 如果 4 个信封地址随机:4 个工人各自跑各自的(gather),慢

SIMD 也是一样:4 个 lane 的数据访问模式决定 main loop 怎么写最快。

### 严谨模型:变调 mixer 的 SIMD 化

**情况 A:d_sample == 1.0(原速播放)**

4 个 cursor 是连续整数 `[i, i+1, i+2, i+3]`。可以连续 load:

```rust
// pseudo-SIMD
let s = _mm_loadu_ps(src[i..].as_ptr());    // [src[i], src[i+1], src[i+2], src[i+3]]
let v = _mm_set1_ps(volume);
let scaled = _mm_mul_ps(s, v);
let d = _mm_loadu_ps(dst[i..].as_ptr());
let added = _mm_add_ps(d, scaled);
_mm_storeu_ps(dst[i..].as_mut_ptr(), added);
i += 4;
```

这是 Day 144 已经写的"普通 SIMD 混音",没有插值,没有 cursor。

**情况 B:d_sample != 1.0(变调)**

4 个 cursor 是 `[c, c+d, c+2d, c+3d]`,可能落在 src 任意位置。

```rust
// pseudo-SIMD,详细的 unsafe 都省略
// 1. 算 4 个 cursor
let c0 = cursor;
let c1 = cursor + d_sample;
let c2 = cursor + 2.0 * d_sample;
let c3 = cursor + 3.0 * d_sample;
let cursors = _mm_set_ps(c3, c2, c1, c0);   // 逆序!_mm_set_ps 参数倒序

// 2. 同时 floor 4 个
let floors = _mm_floor_ps(cursors);
let i0 = _mm_extract_ps(floors, 0) as i32 as usize;
let i1 = _mm_extract_ps(floors, 1) as i32 as usize;
let i2 = _mm_extract_ps(floors, 2) as i32 as usize;
let i3 = _mm_extract_ps(floors, 3) as i32 as usize;

// 3. 算 frac = cursor - floor
let fracs = _mm_sub_ps(cursors, floors);

// 4. 标量 load 4 个 src[i] 和 4 个 src[i+1]
let s0 = _mm_set_ps(src[i3], src[i2], src[i1], src[i0]);
let s1 = _mm_set_ps(src[i3+1], src[i2+1], src[i1+1], src[i0+1]);

// 5. 1 - frac
let ones = _mm_set1_ps(1.0);
let one_minus_f = _mm_sub_ps(ones, fracs);

// 6. y = s0 * (1-f) + s1 * f
let y = _mm_add_ps(_mm_mul_ps(s0, one_minus_f), _mm_mul_ps(s1, fracs));

// 7. 乘 volume
let v = _mm_set1_ps(volume);
let scaled = _mm_mul_ps(y, v);

// 8. 加到 dst
let d = _mm_loadu_ps(dst[out..].as_ptr());
let added = _mm_add_ps(d, scaled);
_mm_storeu_ps(dst[out..].as_mut_ptr(), added);

// 9. 推进
cursor += 4.0 * d_sample;
out += 4;
```

这一段代码做的事和标量版完全一样,但 4 个 sample 并行。

**关键问题:_mm_extract_ps 提取整数索引用于标量 load**。这是 SIMD 的"出口"——你算出 4 个索引后,如果它们不同,只能"出 SIMD"做标量 load,再"进 SIMD"打包。

**SSE4.1 之前没有 `_mm_floor_ps`**,要手动实现 floor:

```rust
fn floor_ps(x: __m128) -> __m128 {
    // 转换到 int 截断,然后转回 float(对正数等价于 floor)
    let i = _mm_cvttps_epi32(x);   // 截断
    _mm_cvtepi32_ps(i)
}
```

但这只对正数对。负数 floor 不同(`floor(-1.5) = -2`,但截断 `-1.5 → -1`)。变调 mixer 的 cursor 永远 ≥ 0,所以没问题。

### 分支特化

Casey 的代码大致是:

```
if d_sample == 1.0 {
    // 情况 A:快速 main loop
} else {
    // 情况 B:通用 main loop
}
```

分支预测:大部分时间 d_sample 是 1.0(不变调),所以预测准,代价 ~0。少数变调情况下,正确性仍然保证,只是走慢路径。

这是 SIMD 优化的通用模式:**为常见情况特化**。Casey 的代码里到处都是这种"特化"——比如"如果 src 和 dst 都是 stereo,跳过 channel 提取"。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏音频的 SIMD 化常见三个层次:

1. **单声音 SIMD**:像今天,一个声音的 4 个 sample 并行。Casey 选这条。
2. **多声音 SIMD**:同时处理 4 个声音的 1 个 sample。需要 SoA 布局。
3. **多声音 + 多 sample**:4 个声音 × 4 个 sample = 16 个并行。AVX-512 才够。

业界标准做法(如 FMOD、Wwise)是层次 2 + SoA 布局:

```rust
// SoA: 4 个声音的位置/速度/音量分开存
struct Voices4 {
    src: [*const f32; 4],          // 4 个声音的源
    cursors: [f64; 4],             // 4 个 cursor
    volumes: [f32; 4],
}
```

这样 main loop 可以 SIMD-load 4 个声音的 src[i],并行算。Casey 没走这条,因为他的 voices 数量动态变化(0-100 个),SoA 化要在每帧"重排"voice 到固定槽位,代码复杂。

### 3.2 · Rust 生态视角

Rust 表达今天 main loop 的两种方式:

**方式 A:`std::arch::x86_64` 直接写 intrinsics**(Casey 风格)

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn main_loop_sse(...) {
    let cursors = _mm_set_ps(c3, c2, c1, c0);
    let floors = _mm_floor_ps(cursors);
    // ...
}
```

**方式 B:`std::simd`(portable_simd,Rust nightly)**

```rust
#![feature(portable_simd)]
use std::simd::{f32x4, SimdFloat};

let cursors = f32x4::from_array([c0, c1, c2, c3]);
let floors = cursors.floor();   // 跨平台
let fracs = cursors - floors;
// ...
```

`portable_simd` 还在 nightly(2024 中),但已经是 Rust SIMD 的未来。**Casey 风格在 Rust 上推荐用 `wide` crate**(稳定 + 跨平台 + 类似 portable_simd 的 API):

```rust
use wide::f32x4;

let cursors = f32x4::from([c0, c1, c2, c3]);
let floors = cursors.floor();
```

### 3.3 · 系统视角:CPU 上的 floor

不同 ISA 的 floor 指令:

| ISA | 指令 | 何时引入 |
|---|---|---|
| x86 SSE4.1 | `ROUNDPS` | 2007 (Penryn) |
| x86 SSE4.4(无) | — | — |
| x86 AVX512 | `VRNDSCALEPS` | 2017 |
| ARM NEON | `vcvtm.f32.s32`(转 int)+ `vcvt.s32.f32`(转回 float) | 2000s |
| ARM NEON + FPCR | round mode 设 floor,直接转 | 现代 ARM |
| WASM | `f32.floor` | 2017 |

Casey 用 SSE4.1。如果你的 CPU 不支持 SSE4.1(>2007 的 Intel 都支持),用上面的 bit trick fallback。

### 3.4 · 数据布局

今天的 SIMD main loop 假设 dst 是连续 `[f32]`。如果 dst 是 stereo interleaved `[L, R, L, R, ...]`,你要么:

1. 把 stereo 拆成两个 mono buffer,L 一个 [f32],R 一个 [f32](deinterleave),各自 SIMD,再合并(interleave)
2. 直接 SIMD 处理 4 个 frame = 8 个 sample(L0 R0 L1 R1 ...),用 `_mm_shuffle_ps` 重排

Casey 的 HH 是 stereo,他用方式 2 的变种。今天的示例代码简化为 mono。

## 4 · 认知地图

### 4.1 上级

- **SIMD main loop 优化** —— 把循环主体向量化
- **数据并行(data parallelism)** —— 同一操作作用在多个独立数据上
- **特化(specialization)** —— 为常见情况写更快的代码路径

### 4.2 同级

| 方案 | 复杂度 | 速度 | 何时用 |
|---|---|---|---|
| 全标量 | 低 | 1x | 性能不关键 |
| 编译器自动向量化 | 低 | 1.5-3x | 简单循环 |
| 手写 SIMD + 分支特化(本日) | 高 | 3-4x | 性能关键 ✅ |
| 多线程 + SIMD | 极高 | N×4x | 大数据 |
| GPU | 极高 | 100x+ | 海量数据 |

### 4.3 下级

- **cursor 寄存器** —— `[c, c+d, c+2d, c+3d]` 的 SIMD 寄存器
- **floor_ps** —— SSE4.1 floor 指令
- **frac 寄存器** —— `[f0, f1, f2, f3]` 的 SIMD 寄存器
- **gather / scatter** —— 不连续地址的 SIMD load/store(AVX2+)
- **shuffle** —— SIMD 寄存器内部重排 lane

## 5 · 对照与变奏

### 不同 SIMD 宽度下的 main loop

SSE 4 lane 写完后,迁移到 AVX 8 lane:

| SSE (4 lane) | AVX (8 lane) |
|---|---|
| `_mm_set1_ps` | `_mm256_set1_ps` |
| `_mm_floor_ps` | `_mm256_floor_ps` |
| `_mm_add_ps` | `_mm256_add_ps` |
| 一次处理 4 sample | 一次处理 8 sample |
| pre 0-3 | pre 0-7 |

理论上 AVX 是 SSE 的 2 倍速。实际在游戏里往往只快 1.5-1.7 倍,因为:

- AVX 时钟降频(CPU 用 AVX 时降频 10-20%)
- 内存带宽瓶颈
- gather / shuffle 在 AVX 上更贵

Casey 在 HH 后期(Day 200+)会评估是否上 AVX。教学版用 SSE 就够。

### GPU 上的"SIMD"

GPU 是超大规模 SIMD:一个 warp/wavefront 32/64 个 lane。GPU 编程(CUDA / GLSL / WGSL)的内核本质上是 SIMD 程序。**所有今天讲的 pre/post 思路在 GPU 上也适用**——比如 shader 里处理任意长度数组,要保证 warp 内所有 lane 都在边界内。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 `_mm_set_ps(a, b, c, d)` 加载到寄存器是 `[d, c, b, a]`(逆序)?这是 SSE 设计的失误还是有意?

**参考解答**:有意。SSE 用 **小端序** —— 寄存器低位(对应数组下标 0)存在内存低地址。`_mm_set_ps(a, b, c, d)` 是按 C 函数参数顺序(从右到左压栈),所以 d 在最低内存地址 = 寄存器低位 = lane 0。a 在最高内存地址 = 寄存器高位 = lane 3。结果是寄存器里 `[d, c, b, a]`(从 lane 0 到 lane 3)。

这个设计可以"从内存连续加载"语义清晰:`_mm_load_ps(ptr)` 等价于 `_mm_set_ps(ptr[3], ptr[2], ptr[1], ptr[0])`,加载 `[ptr[0], ptr[1], ptr[2], ptr[3]]`,符合数组顺序。

### Lv2 · 动手实践

**题**:写一个函数 `mix_main_loop_simd(dst: &mut [f32], src: &[f32], cursor: &mut f64, d_sample: f64, volume: f32)`,假设 dst 长度是 4 的倍数(已经过 pre 处理),用 SSE 4 个一组 SIMD 化。**只处理 d_sample == 1.0 的快速路径**。验证:dst 起始为 [0; 8],src 为 [10, 20, 30, 40, 50, 60, 70, 80],volume = 0.5,调用后 dst = [5, 10, 15, 20, 25, 30, 35, 40]。

完成标准:`cargo test` 通过。

**参考解答**:

```rust
#[cfg(target_arch = "x86_64")]
use std::arch::x86_64::*;

#[cfg(target_arch = "x86_64")]
pub fn mix_main_loop_simd(
    dst: &mut [f32],
    src: &[f32],
    cursor: &mut f64,
    d_sample: f64,
    volume: f32,
) {
    assert!(dst.len() % 4 == 0, "main loop needs multiple of 4");
    assert!((d_sample - 1.0).abs() < 1e-9, "this fast path only supports d_sample=1");

    let mut i = *cursor as usize;
    let v = unsafe { _mm_set1_ps(volume) };

    for out_chunk in dst.chunks_exact_mut(4) {
        unsafe {
            let s = _mm_loadu_ps(src[i..].as_ptr());
            let scaled = _mm_mul_ps(s, v);
            let d = _mm_loadu_ps(out_chunk.as_ptr());
            let added = _mm_add_ps(d, scaled);
            _mm_storeu_ps(out_chunk.as_mut_ptr(), added);
        }
        i += 4;
    }
    *cursor = i as f64;
}

fn main() {
    let src: Vec<f32> = (10..=80).map(|x| x as f32 * 1.0).collect();
    let mut dst = vec![0.0f32; 8];
    let mut cursor = 0.0f64;
    mix_main_loop_simd(&mut dst, &src, &mut cursor, 1.0, 0.5);
    println!("{:?}", dst);
    assert_eq!(dst, vec![5.0, 10.0, 15.0, 20.0, 25.0, 30.0, 35.0, 40.0]);
    println!("OK");
}
```

## 8 · Rust / Arch 落地代码

完整 SSE 变调 mixer(简化为 mono,处理 d_sample != 1 通用路径):

```rust
#[cfg(target_arch = "x86_64")]
use std::arch::x86_64::*;

/// SSE main loop:d_sample != 1.0 的通用变调路径
#[cfg(target_arch = "x86_64")]
unsafe fn main_loop_pitched(
    dst: &mut [f32],
    src: &[f32],
    cursor: &mut f64,
    d_sample: f64,
    volume: f32,
) {
    let n_src = src.len();
    let v_reg = _mm_set1_ps(volume);

    let mut out_idx = 0;
    while out_idx + 4 <= dst.len() {
        // 1. 算 4 个 cursor
        let c0 = *cursor;
        let c1 = c0 + d_sample;
        let c2 = c0 + 2.0 * d_sample;
        let c3 = c0 + 3.0 * d_sample;

        // 越界检查(简化:不处理循环)
        if c3 >= (n_src - 1) as f64 { break; }

        // 2. 打包 cursor 到 SIMD
        let cursors = _mm_set_pd(c1, c0);  // 仅 __m128 setr 的话,这里用 set_ps
        let cursors = _mm_set_ps(c3 as f32, c2 as f32, c1 as f32, c0 as f32);

        // 3. floor
        let floors = _mm_floor_ps(cursors);

        // 4. frac
        let fracs = _mm_sub_ps(cursors, floors);

        // 5. 提取 4 个整数索引
        let i0 = _mm_cvtss_si32(floors) as usize;
        let i1 = _mm_cvtss_si32(_mm_shuffle_ps(floors, floors, 0x55)) as usize;
        let i2 = _mm_cvtss_si32(_mm_shuffle_ps(floors, floors, 0xAA)) as usize;
        let i3 = _mm_cvtss_si32(_mm_shuffle_ps(floors, floors, 0xFF)) as usize;

        // 6. 4 个 src[i] 和 src[i+1]
        let s0 = _mm_set_ps(src[i3], src[i2], src[i1], src[i0]);
        let s1 = _mm_set_ps(src[i3+1], src[i2+1], src[i1+1], src[i0+1]);

        // 7. y = s0 * (1-f) + s1 * f
        let ones = _mm_set1_ps(1.0);
        let one_minus_f = _mm_sub_ps(ones, fracs);
        let y = _mm_add_ps(_mm_mul_ps(s0, one_minus_f), _mm_mul_ps(s1, fracs));

        // 8. 乘 volume
        let scaled = _mm_mul_ps(y, v_reg);

        // 9. 加到 dst
        let d = _mm_loadu_ps(dst[out_idx..].as_ptr());
        let added = _mm_add_ps(d, scaled);
        _mm_storeu_ps(dst[out_idx..].as_mut_ptr(), added);

        // 10. 推进
        *cursor += 4.0 * d_sample;
        out_idx += 4;
    }
}

#[cfg(target_arch = "x86_64")]
fn main() {
    if !is_x86_feature_detected!("sse4.1") {
        eprintln!("requires SSE4.1");
        return;
    }
    let mut src: Vec<f32> = Vec::with_capacity(48000);
    for i in 0..48000 {
        let t = i as f32 / 48000.0;
        src.push((2.0 * std::f32::consts::PI * 220.0 * t).sin() * 0.5);
    }
    let mut dst = vec![0.0f32; 4000];

    unsafe {
        let mut cursor = 0.0f64;
        main_loop_pitched(&mut dst, &src, &mut cursor, 1.5, 0.7);
    }
    println!("max abs: {}", dst.iter().cloned().fold(0.0f32, f32::max));
}

#[cfg(not(target_arch = "x86_64"))]
fn main() { println!("SSE only on x86_64"); }
```

**关键 Rust**:

- `_mm_set_ps(c3, c2, c1, c0)` —— 参数逆序,生成 `[c0, c1, c2, c3]`。
- `_mm_floor_ps` —— SSE4.1 指令,4 个 lane 同时 floor。
- `_mm_cvtss_si32` —— 取寄存器低位一个 f32 转 i32。
- `_mm_shuffle_ps(x, x, imm)` —— 重排 lane。`0x55` 表示取 lane 1,`0xAA` lane 2,`0xFF` lane 3。
- `is_x86_feature_detected!("sse4.1")` —— 运行时检测 CPU 是否支持。

**预期**:`dst` 是 4000 个 sample,被插值过的 220 Hz 正弦在 1.5x 速率下变成 330 Hz。

## 10 · 深度推导:float 操作的 SIMD 化

今天 Casey 把 floor / ceil / round 等 float 操作 SIMD 化。看起来简单,但 float 在 IEEE 754 表示下,SIMD 化有微妙细节。这一节走通。

### 10.1 为什么 float 操作要 SIMD?

游戏代码大量用 float:坐标、速度、矩阵、颜色。这些操作常常批量:

```rust
for pos in &mut positions {
    pos.x = pos.x.floor();  // 整数化
    pos.y = pos.y.floor();
    pos.z = pos.z.floor();
}
```

每个 `.floor()` 在标量上是 1 function call,涉及 branch + bit manipulation。SIMD 化 4 个 floor 一起算,加速 3-4x。

### 10.2 IEEE 754 float 回顾

f32 = 1 bit sign + 8 bit exponent + 23 bit mantissa。

```
1.0 = 0 01111111 00000000000000000000000
     ^ sign(0=正) ^ exponent(127) ^ mantissa(1.0)
2.0 = 0 10000000 00000000000000000000000
3.0 = 0 10000000 10000000000000000000000
```

floor(1.5) = 1.0。如何实现?

- 标量:转 int 1,转回 float 1.0
- IEEE trick:加一个大数让小数部分溢出,再减回去

```rust
fn floor_naive(x: f32) -> f32 {
    x as i32 as f32  // 转换丢弃小数
}

fn floor_ieee(x: f32) -> f32 {
    let magic = 1 << 23;  // 2^23 = 8388608
    let biased = x + magic as f32;
    biased - magic as f32
}
```

IEEE trick 比分支快。但**有限制**:< 2^23 才对。大数失效。

### 10.3 SSE 4.1 的 roundps

SSE 4.1 引入 `_mm_round_ps`,一条指令做 floor / ceil / round / trunc:

```rust
use std::arch::x86_64::*;

#[target_feature(enable = "sse4.1")]
unsafe fn floor_4(x: &[f32; 4]) -> [f32; 4] {
    let v = _mm_loadu_ps(x.as_ptr());
    // _MM_FROUND_FLOOR = floor 模式
    let result = _mm_round_ps::<{ _MM_FROUND_FLOOR }>(v);
    let mut out = [0f32; 4];
    _mm_storeu_ps(out.as_mut_ptr(), result);
    out
}
```

一条指令处理 4 个 float。SSE 4.1 之前用 IEEE trick + mask。

### 10.4 Round 模式

`_mm_round_ps` 支持四种模式:

- `_MM_FROUND_FLOOR`:向下取整 floor(1.5) = 1.0
- `_MM_FROUND_CEIL`:向上取整 ceil(1.5) = 2.0
- `_MM_FROUND_TRUNC`:向零取整 trunc(1.5) = 1.0
- `_MM_FROUND_NINT`:四舍五入 round(0.5) = 1.0(银行家舍入:round(0.5)=0,round(1.5)=2)

游戏代码常混用——坐标用 floor,颜色用 round。

### 10.5 完整代码示例

```rust
use std::arch::x86_64::*;

pub struct Vec4([f32; 4]);

impl Vec4 {
    #[target_feature(enable = "sse4.1")]
    pub unsafe fn floor(&self) -> Vec4 {
        let v = _mm_loadu_ps(self.0.as_ptr());
        let r = _mm_round_ps::<{ _MM_FROUND_FLOOR }>(v);
        let mut out = [0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), r);
        Vec4(out)
    }

    #[target_feature(enable = "sse4.1")]
    pub unsafe fn ceil(&self) -> Vec4 {
        let v = _mm_loadu_ps(self.0.as_ptr());
        let r = _mm_round_ps::<{ _MM_FROUND_CEIL }>(v);
        let mut out = [0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), r);
        Vec4(out)
    }

    #[target_feature(enable = "sse4.1")]
    pub unsafe fn round(&self) -> Vec4 {
        let v = _mm_loadu_ps(self.0.as_ptr());
        let r = _mm_round_ps::<{ _MM_FROUND_NINT }>(v);
        let mut out = [0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), r);
        Vec4(out)
    }

    #[target_feature(enable = "sse4.1")]
    pub unsafe fn abs(&self) -> Vec4 {
        let v = _mm_loadu_ps(self.0.as_ptr());
        // 清除 sign bit
        let mask = _mm_set1_epi32(0x7FFFFFFF);
        let r = _mm_and_ps(v, _mm_castsi128_ps(mask));
        let mut out = [0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), r);
        Vec4(out)
    }

    #[target_feature(enable = "sse4.1")]
    pub unsafe fn min(&self, other: &Vec4) -> Vec4 {
        let a = _mm_loadu_ps(self.0.as_ptr());
        let b = _mm_loadu_ps(other.0.as_ptr());
        let r = _mm_min_ps(a, b);
        let mut out = [0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), r);
        Vec4(out)
    }

    #[target_feature(enable = "sse4.1")]
    pub unsafe fn max(&self, other: &Vec4) -> Vec4 {
        let a = _mm_loadu_ps(self.0.as_ptr());
        let b = _mm_loadu_ps(other.0.as_ptr());
        let r = _mm_max_ps(a, b);
        let mut out = [0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), r);
        Vec4(out)
    }

    #[target_feature(enable = "sse4.1")]
    pub unsafe fn clamp(&self, lo: &Vec4, hi: &Vec4) -> Vec4 {
        let v = _mm_loadu_ps(self.0.as_ptr());
        let lo_v = _mm_loadu_ps(lo.0.as_ptr());
        let hi_v = _mm_loadu_ps(hi.0.as_ptr());
        let r = _mm_max_ps(_mm_min_ps(v, hi_v), lo_v);
        let mut out = [0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), r);
        Vec4(out)
    }
}

fn main() {
    if !is_x86_feature_detected!("sse4.1") {
        eprintln!("No SSE4.1");
        return;
    }

    let v = Vec4([1.5, 2.7, -1.5, -2.7]);
    unsafe {
        println!("Original: {:?}", v.0);
        println!("Floor:    {:?}", v.floor().0);
        println!("Ceil:     {:?}", v.ceil().0);
        println!("Round:    {:?}", v.round().0);
        println!("Abs:      {:?}", v.abs().0);
        let hi = Vec4([2.0, 2.0, -1.0, -1.0]);
        let lo = Vec4([1.0, 1.0, -2.0, -2.0]);
        println!("Clamp:    {:?}", v.clamp(&lo, &hi).0);
    }
}
```

### 10.6 portable_simd 抽象

直接用 `_mm_*` intrinsic 不可移植。Rust nightly 的 `std::simd` 提供高级抽象:

```rust
#![feature(portable_simd)]
use std::simd::{f32x4, StdFloat};

let v = f32x4::from([1.5, 2.7, -1.5, -2.7]);
let floored = v.floor();  // 一行!
let ceiled = v.ceil();
let abs_v = v.abs();
```

portable_simd 在 x86 编译为 `_mm_round_ps`,在 ARM 编译为 `frintm`(floor instruction)。**一份代码,跨平台**。

stable 替代品是 `wide` crate:

```rust
use wide::f32x4;

let v = f32x4::from([1.5, 2.7, -1.5, -2.7]);
let floored = v.floor();
```

### 10.7 工业级应用

游戏代码大量用 Vec4 / Vec3:

- 物理碰撞:Vec3 位置 + Vec3 速度,每帧更新
- 矩阵乘法:4×4 矩阵 × Vec4 = Vec4,SIMD 4 lane 并行
- 颜色:RGBA = Vec4,blend 用 SIMD add/mul
- UV 坐标:Vec2 pairs = Vec4,SIMD 一次采样两个 texel

工业引擎(Bevy / Unreal / Unity)的 math 库(glam / nalgebra / cgmath)全部 SIMD 化。你写 `Vec3::new(x, y, z).normalize()`,内部已经是 SIMD。

## 11 · 工业级的额外考量

### 11.1 FMA(Fused Multiply-Add)

`a * b + c` 可以用 FMA 指令(`_mm_fmadd_ps`),一条指令完成,无中间 round,精度更高 + 速度更快。

```rust
#[target_feature(enable = "fma")]
unsafe fn fma_ps(a: __m128, b: __m128, c: __m128) -> __m128 {
    _mm_fmadd_ps(a, b, c)
}
```

游戏矩阵乘法、物理积分大量用 FMA。Haswell(2013+)起所有 x86 支持FMA3。

### 11.2 Approximate recip / sqrt

`1.0 / x` 和 `sqrt(x)` 是慢指令。SSE 提供 approximate 版本:

```rust
let recip = _mm_rcp_ps(v);  // ~12-bit 精度,~1 cycle
let sqrt_recip = _mm_rsqrt_ps(v);  // 1/sqrt(x),~12-bit,~1 cycle

// Newton-Raphson 一次迭代提升精度
let nr = _mm_mul_ps(_mm_rcp_ps(v), _mm_set1_ps(1.0));
// ... (略)
```

图形学(像素 shader)大量用 approximate,精度够用且快 5x。

### 11.3 Gather / scatter

SIMD 处理连续内存最有效。但有时数据是 scattered(比如多个 entity 的位置分散在内存)。AVX2 引入 gather:

```rust
let indices = _mm_set_epi32(3, 7, 11, 15);  // 不连续索引
let gathered = _mm_i32gather_ps(base_ptr, indices, 4);  // gather
```

但 gather 慢——4 次 cache 访问打包成 1 指令,总时间仍是 4 次访问。AVX-512 引入 scatter(反向)。

工业 SIMD 代码尽量**重组数据布局**让访问连续,避免 gather。

### 11.4 ARM NEON

ARM 的 SIMD 叫 NEON。和 SSE 类似,128-bit register。`vrev64q_f32` 等指令做类似 `_mm_round_ps` 的事。

```rust
#[cfg(target_arch = "aarch64")]
use std::arch::aarch64::*;

#[target_feature(enable = "neon")]
unsafe fn floor_neon(x: f32x4) -> f32x4 {
    vrndmq_f32(x)  // floor
}
```

portable_simd 抽象这些。Apple Silicon(M1/M2/M3)的 NEON 性能极佳,游戏开发必须支持。
