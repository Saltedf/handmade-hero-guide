
# Day 132 · 资产流式加载

> Day 131 的 chunk streaming 模式扩展到所有资产(纹理、模型、音频)。开放世界游戏的核心技术:启动只加载最小集,玩家走到哪资产加载到哪,后台异步进行,主线程不阻塞。

## 0 · 为什么要有这一天

启动一个游戏,你期望多久进入主菜单?3 秒?5 秒?如果游戏要等"所有资产(纹理 + 模型 + 音频 + 关卡数据)全部加载完"才能进菜单,启动时间会变成几分钟。

商业游戏全部采用**资产流式加载**:

- 启动只加载**最小必需资产**:主菜单 UI、第一关的入口、加载提示画面
- 进入游戏后,玩家走到新区域,后台**按需加载**该区域的资产
- 不再需要的资产(远离玩家的区域)**卸载**,腾出内存

这就是 GTA V、塞尔达、Skyrim、Horizon Zero Dawn 这些开放世界游戏的标配技术。Casey 在 Day 132 把 Day 131 的 chunk streaming 模式扩展到所有资产类型:

| 资产类型 | 启动加载 | 按需加载 | 大小 |
|---|---|---|---|
| 主菜单 UI | ✅ | - | KB |
| 玩家角色模型 | ✅ | - | MB |
| 第一关地形 | ✅ | - | MB |
| 第一关怪物 | ✅ | - | MB |
| 远处关卡 1 资产 | - | 玩家靠近时 | MB |
| 远处关卡 2 资产 | - | 玩家靠近时 | MB |
| 全部音效 | ✅(小) | 大音频按需 | KB-MB |
| BGM | - | 进入场景时 | MB |

启动加载总量:几十 MB(快速)。全部资产总量:几 GB(无法一次加载)。

**今天的核心**:把 Day 131 的 chunk streaming 框架扩展为通用的 asset streaming,管理多种资产类型,实现 LRU 淘汰。

心理锚点:做完今天你能(1)解释"启动加载 vs 流式加载"的工程权衡;(2)在你的引擎里加一个 `AssetHandle` 系统,引用计数 + 自动卸载;(3)用 io_uring 或线程池加速文件 IO;(4)说出"资产加载完但还没在 GPU 上传"时的状态机。

## 1 · Casey 今天做了什么

Casey 把 chunk streaming 模式扩展到所有资产:

1. 定义 `AssetSlot` 概念:每个资产一个槽位,状态(Unloaded / Loading / Loaded),数据指针
2. 实现 `AssetHandle`:轻量级引用(AssetId + generation),玩家代码持有时资产保持加载,所有 handle 释放后资产可卸载
3. 工作线程:从 work queue 接收 "LoadAsset(id)" 任务,从磁盘读 + 解析 + 转化为运行时格式
4. LRU(Least Recently Used)淘汰:当资产总内存超过 budget 时,卸载最久没用的(且 refcount = 0)
5. 启动序列:加载最小集(menu + 角色 + 第一关),其他延迟

Casey 的设计有几个有意思的取舍:
- 资产用 ID(AssetId = u32)而不是路径,运行时不关心文件位置
- 资产加载是"懒"的:第一次访问时才进入 Loading 状态
- 资产卸载是"启发式"的:LRU + refcount 双重判断

这一天的工程量比 Day 131 更大(资产类型多、生命周期管理复杂),但概念上是 Day 131 的扩展。

## 2 · 心智模型

### 类比:图书馆 vs 私人书房

**全部预加载(同步启动)** 像私人书房:你买所有书,放书架,随时拿。代价:房间大、买书贵、搬家难。

**流式加载(异步 streaming)** 像公共图书馆:书的总量巨大,你只借当前要看的几本。看完还回去,要新的再借。代价:每次拿书要等几分钟(等图书馆员去找)。

游戏的资产管理:大部分时间像图书馆(streaming),少量像书房(预加载关键资产)。

### 严谨原理:AssetHandle 和生命周期

资产的"生命周期"复杂:

```
[ Disk ] → [ Memory ]
              ↑↓
        [ AssetSlot ]
              ↑↓
         [ Handle ]
              ↑↓
         [ Game Code ]
```

- **Disk**:资产在磁盘上的原始文件(.png、.wav、.hha 数据)
- **Memory**:加载到内存的运行时格式(`Vec<u32>` 像素、`Vec<f32>` 样本)
- **AssetSlot**:管理一个资产的容器,带状态和 refcount
- **Handle**:游戏代码持有的"引用",智能指针,析构时 refcount--
- **Game Code**:实际使用资产的逻辑

关键问题:**什么时候加载?什么时候卸载?**

#### 加载时机

- **预加载**(pre-load):游戏启动时主动加载关键资产。无延迟,但启动慢
- **懒加载**(lazy load):第一次访问时才加载。简单,但首次访问有延迟
- **预测加载**(predictive):基于游戏状态预测"玩家接下来会需要什么",提前加载。最优,但预测逻辑复杂
- **触发加载**(triggered):玩家触发某事件(进入新区域)时加载该区域资产。半预测,实用

Casey 用预加载(启动)+ 触发加载(进新区域)。预测加载留 Lv4。

#### 卸载时机

- **手动卸载**:游戏代码显式调用 `unload(asset)`。简单,易出错(忘记卸载 → 内存泄漏)
- **引用计数**(refcount):所有 handle 释放后自动卸载。智能,但循环引用不会卸载
- **LRU**(Least Recently Used):最久没访问的优先卸载。配合 refcount(refcount > 0 不能卸)
- **内存压力触发**:当总内存超 budget 时主动卸载 LRU 资产

Casey 用 refcount + LRU。

### 资产状态机

资产状态比 chunk 多一阶段:

```
   ┌────────────┐
   │ Unloaded   │ ← 初始 / 已卸载
   └─────┬──────┘
         │ 加载请求
         ↓
   ┌────────────┐
   │ Loading    │ ← 工作线程读磁盘 + 解析
   └─────┬──────┘
         │ 加载完
         ↓
   ┌────────────┐
   │ Loaded     │ ← 主线程可用
   └─────┬──────┘
         │ LRU 决定卸载
         ↓
   ┌────────────┐
   │ Unloading  │ ← 工作线程释放内存
   └─────┬──────┘
         │
         ↓
   ┌────────────┐
   │ Unloaded   │
   └────────────┘
```

四态。每个状态转移用 CAS,逻辑同 Day 131。

### Rust 表达:Arc + Weak

Rust 的所有权系统天然适合 refcount:

```rust
use std::sync::{Arc, Weak};

struct Asset {
    data: Vec<u8>,  // 解析后的数据
    id: AssetId,
}

struct AssetSlot {
    asset: Mutex<Option<Arc<Asset>>>,  // Loaded 时 Some,否则 None
    state: AtomicU32,
    last_used: AtomicI64,  // 时间戳,LRU 用
}

// 游戏代码持有 Arc,析构自动 refcount--
type AssetHandle = Arc<Asset>;
```

加载完:`slot.asset = Some(Arc::new(asset))`。游戏代码拿 `let handle = slot.asset.lock().unwrap().clone().unwrap()`。
卸载:`slot.asset = None`(如果外部还有 Arc 副本,数据不会被释放,直到所有副本 drop)。

这套自动 refcount 比手写 refcount 安全,代价是 Arc 的原子操作开销(每次 clone / drop 都 fetch_add / fetch_sub)。

LRU 需要 Weak 引用:`Weak<Asset>` 不增加 refcount。AssetManager 持有 Weak,游戏代码持有 Arc。游戏代码全部 drop 后 refcount = 0,资产释放,Weak 失效。AssetManager 检测到 Weak 失效,把 slot 标记 Unloaded。

### Asset ID 系统

资产用 `AssetId(u32)` 标识(u32 是 newtype,防混)。AssetManager 维护 `HashMap<AssetId, AssetSlot>`。

AssetId 怎么分配?两种方案:

**方案 A:编译时分配**。资产构建工具(Build step)扫描所有资产文件,每个分配一个唯一 ID,写到 `assets.rs`。游戏代码引用 `AssetId::SWORD_ICON`。优点:运行时快(无需字符串查找)。缺点:加新资产要重新 build。

**方案 B:运行时分配**。AssetManager 启动时读 `assets.json`,运行时 `manager.load("sword_icon")` 返回 `AssetHandle`。优点:灵活。缺点:字符串查找慢(但只在加载时,可忽略)。

Casey 用方案 A(编译时分配),因为他有自己的资产打包工具(`asset_builder`)。我们 Rust 教学版用方案 B 简化。

### 文件 IO 异步

资产加载的瓶颈是文件 IO。Linux 上几种异步方案:

**方案 1:多线程同步 read**(最简单)
```rust
fn worker_load(path: &str) -> Vec<u8> {
    std::fs::read(path).unwrap()
}
```
每个工作线程独立 read,OS 调度。简单,但每个线程的 read 是阻塞的。

**方案 2:`aio_read`**(POSIX AIO)
```c
struct aiocb cb = {0};
cb.aio_fildes = open(...);
cb.aio_buf = buffer;
cb.aio_nbytes = size;
aio_read(&cb);
// 主线程做其他事
aio_suspend(&cb, 1, NULL);  // 等待
```
POSIX 标准,但 Linux 上的 user-space 实现通常还是基于多线程。

**方案 3:`io_uring`**(Linux 5.1+)
```rust
// 用 io-uring crate
use io_uring::{IoUring, SubmissionQueue};
let mut ring = IoUring::new(256)?;
// 提交 read 请求到 SQ
// 主线程做其他事
// 从 CQ 取完成事件
```
真正的高性能异步 IO,Google、Cloudflare 用。游戏开发也越来越多用。Rust 的 `rio`、`tokio-uring` crate 封装了。

**方案 4:`mmap` + 缺页处理**
```rust
let file = std::fs::File::open(path)?;
let mmap = unsafe { MmapOptions::new().map(&file)? };
// mmap 立即返回,实际读取延迟到第一次访问
let data = &mmap[0..1024];  // 这里触发缺页,OS 读磁盘
```
延迟加载,OS 负责。但缺页处理是同步的(线程阻塞),不是真异步。适合"读一点点"的场景。

Casey 用方案 1(简单)。Rust 教学版我们也用 1,lv4 探索 io_uring。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

资产流式加载是商业游戏的核心技术。具体案例:

**GTA V**:整个城市无缝,玩家开车飞驰,周围建筑、车辆、NPC 实时加载。RAGE 引擎用 LOD streaming + 资产压缩包(降低单文件 IO 开销)。GDC 演讲透露他们用 64KB 块为单位流式传输。

**Minecraft**:每个 chunk 16×16×256 方块,大约 50KB 压缩。玩家移动时新 chunk 异步生成 + 加载。简单但有效。

**塞尔达:野炊**:整个海拉鲁大陆无缝。任天堂用 "two-stage streaming":第一阶段 metadata(几 KB),第二阶段几何 + 纹理(几 MB)。中间允许玩家短暂看到低 LOD 版本。

**Horizon Zero Dawn**:Decima 引擎用 "asset layering":世界分多层(terrain / vegetation / props / NPCs),每层独立 streaming。

游戏开发圈的设计模式:

**Asset Pack**:把多个小资产打成一个包(.hha、.pak),一次 IO 读多个。降低 syscall 开销。Casey 在 Day 147 做 .hha。

**Asset Manifest**:构建工具生成的清单,记录每个资产的 ID、类型、依赖、大小。游戏启动时读 manifest,知道有什么资产可用。

**Async compression**:资产在磁盘上是压缩的(zstd、LZ4),加载时解压。解压在 IO 线程做,主线程拿到的是已解压数据。

**Reference counting + auto-unload**:每个资产有 refcount,游戏代码持 Arc,所有 Arc 释放后资产自动 unload。配合 LRU 控制内存上限。

**Hot reload**:开发模式下,美工修改资产文件 → 自动重新加载到内存。生产模式关闭。Casey Day 159 专门讨论。

### 3.2 · 🐧 Linux 系统编程视角

Linux 上文件 IO 的几个层次:

#### `read(2)` —— 同步阻塞

```c
int fd = open(path, O_RDONLY);
char buf[1024];
ssize_t n = read(fd, buf, 1024);  // 阻塞,直到读到 1024 字节或 EOF
close(fd);
```

最常用。OS 调度,线程阻塞。

#### `pread(2)` —— 同步定位读

```c
pread(fd, buf, 1024, offset);  // 不修改文件指针
```

并发从同一 fd 不同 offset 读。适合多线程读同一文件。

#### `mmap(2)` —— 内存映射

```c
void *addr = mmap(NULL, size, PROT_READ, MAP_SHARED, fd, 0);
// 现在 addr 是文件内容的内存视图
char c = ((char *)addr)[0];  // 触发缺页,OS 读磁盘
```

OS 按需读,page cache 加速重复读。适合"大文件,稀疏访问"。

#### `aio_read(3)` / `io_uring(2)` —— 真·异步

```c
// io_uring (Linux 5.1+)
struct io_uring ring;
io_uring_queue_init(256, &ring, 0);
struct io_uring_sqe *sqe = io_uring_get_sqe(&ring);
io_uring_prep_read(sqe, fd, buf, 1024, offset);
io_uring_submit(&ring);
// 主线程做其他事
struct io_uring_cqe *cqe;
io_uring_wait_cqe(&ring, &cqe);  // 等待完成
```

单线程可以提交多个 IO 请求,都异步执行,主线程做其他事。性能极高。

#### Linux page cache

Linux 文件系统维护一个全局 page cache:读过的文件块缓存在内存。下次读同一文件命中 cache,不查磁盘。case 在 `/proc/meminfo` 看:

```bash
grep -E "Cached|Buffers" /proc/meminfo
# Cached:  4 GB   ← page cache
# Buffers: 100 MB ← 块设备 buffer
```

游戏资产第一次读慢(磁盘),第二次快(cache)。所以"启动加载同一资产"很快,"第一次加载新资产"慢。

#### `posix_fadvise(2)` —— 提示 OS

```c
posix_fadvise(fd, 0, 0, POSIX_FADV_WILLNEED);  // 提示 OS 提前 readahead
posix_fadvise(fd, 0, 0, POSIX_FADV_DONTNEED);  // 提示 OS 释放 cache
```

让 OS 知道你的访问模式,优化 readahead 和 cache。

```bash
# 看 Linux readahead 设置
cat /sys/block/sda/queue/read_ahead_kb
# 128 (KB)
```

#### Arch Linux 上的 SSD 优化

```bash
# 看 SSD trim 是否启用
sudo systemctl status fstrim.service
# 启用周期 trim
sudo systemctl enable --now fstrim.timer

# 看 IO 调度器(SSD 用 mq-deadline 或 none)
cat /sys/block/nvme0n1/queue/scheduler
# 应该看到 [mq-deadline] kyber bfq none

# SSD 上 game asset streaming 性能调优:
echo none > /sys/block/nvme0n1/queue/scheduler  # NVMe SSD 不需要复杂调度
```

### 3.3 · 🦀 Rust 生态视角

Rust 表达 asset streaming 的几个层次:

#### 流派 1:`Arc<Mutex<Option<T>>>`(简单)

```rust
struct AssetSlot<T> {
    data: Arc<Mutex<Option<Arc<T>>>>,
    state: AtomicU32,
}
```

每资产一个 Mutex,简单但有锁开销。

#### 流派 2:`arc_swap::ArcSwapOption<T>`(无锁读者)

```toml
[dependencies]
arc-swap = "1"
```

```rust
use arc_swap::ArcSwapOption;
use std::sync::Arc;

struct AssetSlot<T> {
    data: ArcSwapOption<T>,  // 无锁读,原子写
}
```

主线程读 `slot.data.load()`(返回 Guard,无锁),工作线程写 `slot.data.store(Some(...))`(原子替换)。最优。

#### 流派 3:`crossbeam_epoch`(无锁 + GC)

适合"读者持有引用很久,写者要立即释放"的场景。复杂,游戏开发不常用。

#### 流派 4:Bevy / Unity 风格(Handle + AssetStore)

```rust
type AssetId = u32;

struct AssetStore<T> {
    slots: HashMap<AssetId, AssetSlot<T>>,
}

impl<T: Clone> AssetStore<T> {
    fn get(&self, id: AssetId) -> Option<Arc<T>> {
        self.slots.get(&id)?.data.load_full()
    }
    fn load_async(&self, id: AssetId) {
        // push 到 work queue
    }
}

// 游戏代码:
let sword = store.get(AssetId::SWORD_ICON)?;
// 用 sword
// sword 析构时 refcount--
```

#### IO 异步:tokio vs async-std vs 自己造

- **tokio**:最流行的 Rust async runtime。游戏开发不太用,因为游戏的"实时性"和 async task 模型不完全契合
- **async-std**:类似 tokio,API 更接近 std
- **smol / async-executor**:更轻量
- **自己造**(rayon、crossbeam):用线程池 + 同步 IO。游戏开发最常用

Casey 用"自己造"风格(N 个工作线程 + work queue)。Rust 教学版我们同。

### 3.4 · 资产格式

资产在磁盘上怎么存?几个层次:

**原始格式**:每个资产单独文件(`sword.png`、`bgm.wav`)。简单,但小文件多,IO 开销大。

**打包格式**:多个资产合并到一个大文件(`assets.pak`、`.hha`)。一次 IO 读多个,降低 syscall。Casey Day 147 做 .hha。

**压缩格式**:打包 + 压缩(LZ4、zstd)。磁盘小,加载时解压。商业游戏标配。

**Diff / Patch**:增量资产(只有变化的部分)。游戏更新用,Day 235+ 不做。

Casey Day 132 用原始格式,Day 147 切到打包。

## 5 · 对照与变奏

### 启动加载量 vs 启动时间

| 启动加载 | 启动时间 | 进入游戏后 |
|---|---|---|
| 0% | < 1 秒 | 玩家走哪都加载,初始体验差 |
| 20% | 5 秒 | 平衡,商业游戏常见 |
| 50% | 15 秒 | 较慢启动,游戏内加载少 |
| 100% | 60 秒+ | 玩家放弃 |

20% 是个经验值:加载 menu + 角色 + 第一关的入口资产,5 秒以内。

### LRU vs LFU vs ARC

LRU(Least Recently Used):淘汰最久没访问的。简单,但"扫描访问"会污染 cache(临时访问大量资产)。

LFU(Least Frequently Used):淘汰访问次数最少的。抗扫描,但旧数据访问次数高难淘汰。

ARC(Adaptive Replacement Cache):LRU + LFU 自适应混合。复杂,但效果好。ZFS 用。

Casey 用 LRU(简单)。Linux page cache 也是 LRU。

### 资产版本控制

资产有版本——美工改了 sword.png,新版要替换。两种处理:

**热重载**(hot reload):不重启游戏,工作线程检测文件变化(mtime),自动重新加载。开发模式用。

**冷重载**:重启游戏才生效。生产模式用。

Casey 在 Day 159 加热重载。

### 历史演化

- **1980s**:全部预加载(游戏整张卡带 ROM,几 KB)
- **1990s**:启动加载全部(光盘游戏,几 MB)
- **2000s**:流式加载(开放世界,几 GB)
- **2010s**:LOD streaming(3A 大作,几十 GB)
- **2020s**:SSD streaming(PS5、Xbox Series X),I/O 大幅加速

每个时代硬件 IO 速度决定 streaming 策略。Casey HH 假设 HDD / 普通 SSD,没有 PS5 那种瞬时加载。

### Lv1 · 概念辨析

**题**:

1. 游戏启动时,为什么不能"加载所有资产"?给出 3 个理由。
2. 一个 AssetHandle 持有期间,资产会被卸载吗?为什么?
3. LRU 卸载策略遇到"扫描访问"(玩家短暂访问大量资产)会怎样?怎么缓解?
4. 启动加载 20% 资产,5 秒进游戏;剩余 80% 玩家进入游戏后异步加载。如果玩家在加载完成前就跑到边缘区域,会怎样?

**参考解答**:
1. (a) 启动时间:几十 GB 资产加载要几分钟,玩家放弃。(b) 内存:全加载占几十 GB RAM,普通机器跑不起。(c) 浪费:大部分资产玩家整个游戏流程都不会访问(开放世界只探索 20%),全加载浪费 IO 和内存。
2. 不会。AssetHandle 是 `Arc<Asset>`,持有时 refcount > 0,LRU 不会卸载(refcount > 0 是卸载的硬约束)。所有 handle drop 后 refcount = 0,LRU 才可能选这个资产卸载。
3. LRU 会把"扫描时访问的资产"放到 cache 顶部,挤掉"实际常用的资产"。缓解:用 LFU(频率)或扫描抗性 LRU(给新访问的资产"试用期",期间不计入 LRU)。Linux page cache 用 two-list LRU(active + inactive)缓解。
4. 玩家跑到未加载区域,资产状态 = Unloaded 或 Loading,主线程渲染时用 fallback(灰色 / 占位纹理)。如果工作线程跟得上,几百毫秒后资产加载完,无缝切到真实纹理。如果跟不上(玩家跑太快,资产请求积压),fallback 显示更久,体验差。解法:prefetch——根据玩家速度方向预测"接下来会到哪",提前加载。

### Lv2 · 动手实践

**题**:Rust 实现简化的 AssetManager。

要求:
1. `AssetId(u32)` newtype
2. `Asset` struct:`{ id: AssetId, data: Vec<u8> }`
3. `AssetSlot`:`{ data: Mutex<Option<Arc<Asset>>>, state: AtomicU32, last_used_ms: AtomicU64 }`
4. `AssetManager`:`{ slots: HashMap<AssetId, AssetSlot>, queue: Arc<Mutex<VecDeque<AssetId>>> }`
5. `load_async(id)`:推到 queue,worker 加载
6. `get(id) -> Option<Arc<Asset>>`:已加载返回 Arc,否则 None
7. worker 线程:从 queue pop,模拟加载(sleep),set 数据 + state = Loaded
8. 测试:5 个资产,2 个预加载(同步),3 个异步加载,观察哪些立刻可用

完成标准:`cargo run` 打印每个资产的 load 状态,看到同步加载的立刻 Loaded,异步加载的几秒后才 Loaded。

**参考解答**:

```rust
use std::collections::{HashMap, VecDeque};
use std::sync::atomic::{AtomicU32, AtomicU64, Ordering};
use std::sync::{Arc, Mutex};
use std::thread;
use std::time::{Duration, Instant, SystemTime};

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
struct AssetId(u32);

#[repr(u32)]
#[derive(Copy, Clone, Debug, PartialEq)]
enum State { Unloaded = 0, Loading = 1, Loaded = 2 }
impl State {
    fn from_u32(v: u32) -> Self {
        match v { 0 => Self::Unloaded, 1 => Self::Loading, 2 => Self::Loaded, _ => unreachable!() }
    }
}

struct Asset {
    id: AssetId,
    data: Vec<u8>,
}

struct AssetSlot {
    data: Mutex<Option<Arc<Asset>>>,
    state: AtomicU32,
    last_used_ms: AtomicU64,
}

impl AssetSlot {
    fn new() -> Self {
        Self {
            data: Mutex::new(None),
            state: AtomicU32::new(State::Unloaded as u32),
            last_used_ms: AtomicU64::new(0),
        }
    }
}

struct AssetManager {
    slots: Mutex<HashMap<AssetId, AssetSlot>>,
    queue: Arc<Mutex<VecDeque<AssetId>>>,
}

impl AssetManager {
    fn new() -> Self {
        Self {
            slots: Mutex::new(HashMap::new()),
            queue: Arc::new(Mutex::new(VecDeque::new())),
        }
    }

    fn register(&self, id: AssetId) {
        let mut slots = self.slots.lock().unwrap();
        slots.entry(id).or_insert_with(AssetSlot::new);
    }

    fn load_sync(&self, id: AssetId, data: Vec<u8>) {
        let slots = self.slots.lock().unwrap();
        let slot = slots.get(&id).expect("must register first");
        // 模拟同步加载(瞬时)
        *slot.data.lock().unwrap() = Some(Arc::new(Asset { id, data }));
        slot.state.store(State::Loaded as u32, Ordering::Release);
        slot.last_used_ms.store(current_ms(), Ordering::Relaxed);
    }

    fn load_async(&self, id: AssetId) {
        let slots = self.slots.lock().unwrap();
        if let Some(slot) = slots.get(&id) {
            if slot.state.compare_exchange(
                State::Unloaded as u32, State::Loading as u32,
                Ordering::AcqRel, Ordering::Acquire,
            ).is_ok() {
                drop(slots);
                self.queue.lock().unwrap().push_back(id);
            }
        }
    }

    fn get(&self, id: AssetId) -> Option<Arc<Asset>> {
        let slots = self.slots.lock().unwrap();
        let slot = slots.get(&id)?;
        if State::from_u32(slot.state.load(Ordering::Acquire)) == State::Loaded {
            slot.last_used_ms.store(current_ms(), Ordering::Relaxed);
            slot.data.lock().unwrap().clone()
        } else {
            None
        }
    }

    fn state(&self, id: AssetId) -> State {
        let slots = self.slots.lock().unwrap();
        slots.get(&id).map(|s| State::from_u32(s.state.load(Ordering::Acquire))).unwrap_or(State::Unloaded)
    }
}

fn current_ms() -> u64 {
    SystemTime::now().duration_since(SystemTime::UNIX_EPOCH).unwrap().as_millis() as u64
}

fn main() {
    let manager = Arc::new(AssetManager::new());

    // 注册 5 个资产
    let ids: Vec<AssetId> = (0..5).map(AssetId).collect();
    for id in &ids { manager.register(*id); }

    // 启动 worker 线程
    let manager_w = manager.clone();
    let queue_w = manager_w.queue.clone();
    let _worker = thread::spawn(move || {
        loop {
            let next = queue_w.lock().unwrap().pop_front();
            if let Some(id) = next {
                println!("  [worker] loading asset {:?}", id);
                thread::sleep(Duration::from_millis(200));  // 模拟加载
                let data = vec![id.0 as u8; 1024];  // 假数据
                let slots = manager_w.slots.lock().unwrap();
                if let Some(slot) = slots.get(&id) {
                    *slot.data.lock().unwrap() = Some(Arc::new(Asset { id, data }));
                    slot.state.store(State::Loaded as u32, Ordering::Release);
                    slot.last_used_ms.store(current_ms(), Ordering::Relaxed);
                    println!("  [worker] asset {:?} loaded", id);
                }
            } else {
                thread::sleep(Duration::from_millis(10));
            }
        }
    });

    // 预加载 AssetId(0) 和 AssetId(1)(同步)
    println!("Pre-loading AssetId(0) and AssetId(1) sync...");
    manager.load_sync(AssetId(0), vec![0; 1024]);
    manager.load_sync(AssetId(1), vec![1; 1024]);

    // 异步加载 AssetId(2) / (3) / (4)
    println!("Requesting async load of AssetId(2), (3), (4)...");
    manager.load_async(AssetId(2));
    manager.load_async(AssetId(3));
    manager.load_async(AssetId(4));

    // 监控状态
    for frame in 0..15 {
        println!("Frame {}: states = {:?}", frame,
            ids.iter().map(|id| (id.0, manager.state(*id))).collect::<Vec<_>>());
        thread::sleep(Duration::from_millis(100));
    }

    // 取资产
    for id in &ids {
        match manager.get(*id) {
            Some(asset) => println!("Got asset {:?}: data len {}", id, asset.data.len()),
            None => println!("Asset {:?} not loaded yet", id),
        }
    }
}
```

## 8 · Rust / Arch 落地代码

### Rust 完整项目:资产 streaming + LRU

```rust
// Cargo.toml: 无依赖

use std::collections::{HashMap, VecDeque, BTreeMap};
use std::sync::atomic::{AtomicU32, AtomicU64, Ordering};
use std::sync::{Arc, Mutex};
use std::thread;
use std::time::{Duration, SystemTime};

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, PartialOrd, Ord)]
struct AssetId(u32);

#[repr(u32)]
#[derive(Copy, Clone, Debug, PartialEq)]
enum State { Unloaded = 0, Loading = 1, Loaded = 2 }
impl State {
    fn from_u32(v: u32) -> Self {
        match v { 0 => Self::Unloaded, 1 => Self::Loading, 2 => Self::Loaded, _ => unreachable!() }
    }
}

struct Asset {
    id: AssetId,
    size_bytes: usize,
    data: Vec<u8>,
}

struct AssetSlot {
    data: Mutex<Option<Arc<Asset>>>,
    state: AtomicU32,
    last_used_ms: AtomicU64,
    size_bytes: AtomicU64,
}

impl AssetSlot {
    fn new() -> Self {
        Self {
            data: Mutex::new(None),
            state: AtomicU32::new(State::Unloaded as u32),
            last_used_ms: AtomicU64::new(0),
            size_bytes: AtomicU64::new(0),
        }
    }
}

struct AssetManager {
    slots: Mutex<HashMap<AssetId, AssetSlot>>,
    queue: Arc<Mutex<VecDeque<AssetId>>>,
    budget_bytes: usize,
}

fn current_ms() -> u64 {
    SystemTime::now().duration_since(SystemTime::UNIX_EPOCH).unwrap().as_millis() as u64
}

impl AssetManager {
    fn new(budget_bytes: usize) -> Self {
        Self {
            slots: Mutex::new(HashMap::new()),
            queue: Arc::new(Mutex::new(VecDeque::new())),
            budget_bytes,
        }
    }

    fn current_memory(&self) -> u64 {
        let slots = self.slots.lock().unwrap();
        slots.values().map(|s| s.size_bytes.load(Ordering::Relaxed)).sum()
    }

    fn trigger_lru_eviction(&self) {
        // 收集 Loaded 的资产,按 last_used 排序,从最旧开始卸载
        let mut loaded: Vec<(AssetId, u64, u64)> = {
            let slots = self.slots.lock().unwrap();
            slots.iter().filter_map(|(id, slot)| {
                if State::from_u32(slot.state.load(Ordering::Acquire)) == State::Loaded {
                    // 检查 refcount:data.lock().unwrap().as_ref().map(|arc| Arc::strong_count(arc))
                    let strong_count = slot.data.lock().unwrap().as_ref()
                        .map(|arc| Arc::strong_count(arc)).unwrap_or(0);
                    if strong_count <= 1 {
                        Some((*id, slot.last_used_ms.load(Ordering::Relaxed),
                              slot.size_bytes.load(Ordering::Relaxed)))
                    } else { None }
                } else { None }
            }).collect()
        };
        loaded.sort_by_key(|&(_, t, _)| t);
        let mut mem = self.current_memory();
        for (id, _, size) in loaded {
            if mem <= self.budget_bytes as u64 { break; }
            let slots = self.slots.lock().unwrap();
            if let Some(slot) = slots.get(&id) {
                if slot.state.compare_exchange(
                    State::Loaded as u32, State::Unloaded as u32,
                    Ordering::AcqRel, Ordering::Acquire,
                ).is_ok() {
                    *slot.data.lock().unwrap() = None;
                    slot.size_bytes.store(0, Ordering::Relaxed);
                    mem = mem.saturating_sub(size);
                    println!("  [LRU] evicted asset {:?} (freed {} bytes)", id, size);
                }
            }
        }
    }

    fn load_async(&self, id: AssetId, size: usize) {
        self.slots.lock().unwrap().entry(id).or_insert_with(AssetSlot::new);
        let slots = self.slots.lock().unwrap();
        if let Some(slot) = slots.get(&id) {
            if slot.state.compare_exchange(
                State::Unloaded as u32, State::Loading as u32,
                Ordering::AcqRel, Ordering::Acquire,
            ).is_ok() {
                drop(slots);
                self.queue.lock().unwrap().push_back(id);
                println!("  [main] requesting load {:?} ({} bytes)", id, size);
            }
        }
    }

    fn get(&self, id: AssetId) -> Option<Arc<Asset>> {
        let slots = self.slots.lock().unwrap();
        let slot = slots.get(&id)?;
        if State::from_u32(slot.state.load(Ordering::Acquire)) == State::Loaded {
            slot.last_used_ms.store(current_ms(), Ordering::Relaxed);
            slot.data.lock().unwrap().clone()
        } else { None }
    }
}

fn main() {
    // 4 KB budget - 很小,会触发 LRU
    let manager = Arc::new(AssetManager::new(4096));

    // 启动 worker
    let manager_w = manager.clone();
    let queue_w = manager_w.queue.clone();
    let _worker = thread::spawn(move || {
        loop {
            let next = queue_w.lock().unwrap().pop_front();
            if let Some(id) = next {
                thread::sleep(Duration::from_millis(50));
                let fake_data = vec![id.0 as u8; 1024];  // 每资产 1KB
                let asset = Arc::new(Asset { id, size_bytes: fake_data.len(), data: fake_data });
                let slots = manager_w.slots.lock().unwrap();
                if let Some(slot) = slots.get(&id) {
                    let prev_size = slot.size_bytes.swap(asset.size_bytes as u64, Ordering::Relaxed);
                    let _ = prev_size;
                    *slot.data.lock().unwrap() = Some(asset);
                    slot.state.store(State::Loaded as u32, Ordering::Release);
                    slot.last_used_ms.store(current_ms(), Ordering::Relaxed);
                    println!("  [worker] loaded {:?}, mem now {} bytes", id, manager_w.current_memory());
                }
                // 触发 LRU
                manager_w.trigger_lru_eviction();
            } else {
                thread::sleep(Duration::from_millis(5));
            }
        }
    });

    // 加载 10 个资产,每个 1KB,总 10KB,budget 4KB
    for i in 0..10 {
        manager.load_async(AssetId(i), 1024);
        thread::sleep(Duration::from_millis(80));
    }

    thread::sleep(Duration::from_millis(500));
    println!("\nFinal memory: {} bytes (budget {})", manager.current_memory(), manager.budget_bytes);
}
```

  [main] requesting load AssetId(2) (1024 bytes)
