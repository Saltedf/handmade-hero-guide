# Day 138 · 加载 WAV 文件

> 今天手写 WAV 文件解析器。这是 HH 第一个完整的二进制格式解析实战——RIFF 容器 + chunk 结构 + PCM 数据。比 BMP 还简单,但每个细节都讲透,为后面 Day 147 的 .hha 自定义格式铺路。

## 0 · 为什么要有这一天

游戏需要声音。直到 Day 138,Casey 用的是 DirectSound 内置的简单 sine wave(代码生成),不是真实音频文件。今天开始用真实 WAV 文件——脚步声、武器声、BGM。

WAV(波形音频文件格式)是 Microsoft / IBM 1991 年设计的音频容器。和 BMP 一样,简单到教学友好:

- **无压缩**(基本):直接存 PCM(Pulse-Code Modulation)样本
- **RIFF 容器**:chunk 结构,可扩展
- **小端字节序**(Intel CPU native)
- **元数据**少(采样率、声道数、位深)

WAV 文件结构:
```
[RIFF header: 'RIFF' + size + 'WAVE']
[fmt chunk:   'fmt ' + size + format data]
[data chunk:  'data' + size + PCM samples]
[可能其他 chunk:LIST(元数据)、fact(压缩信息)等]
```

学习 WAV 解析的真正价值:**掌握"二进制格式解析"这门手艺**。所有二进制格式(PNG、JPG、MP4、PDF、ELF、PCAP...)都是同一套路:

1. 读 magic number 验证
2. 读 header(版本、大小、布局)
3. 按 chunk / section 读 payload
4. 处理字节序(little/big endian)
5. 处理对齐和 padding

Casey 在 Day 138 教 WAV,Day 147 教自定义 .hha,Day 436+ 教 PNG。一次掌握,终身受用。

心理锚点:做完今天你能(1)读 WAV 文件并解析出 PCM 样本;(2)解释 RIFF 容器和 chunk 结构;(3)用 Rust 的 byte slice 处理二进制(不用 serde,理解底层);(4)说出 PCM 是什么,WAV 和 MP3 的本质差别。

## 2 · 心智模型

### 类比:快递包裹

WAV 文件像一个快递包裹:

- **外包装**(RIFF header):贴"音频包裹"标签(RIFF/WAVE magic)+ 总重量(size)
- **说明书**(fmt chunk):包裹里是什么——单声道/立体声?采样率?位深?
- **实际货物**(data chunk):PCM 样本数据,按说明书格式读
- **可能的小附件**(LIST / fact 等):发货单、备注——可忽略

读 WAV = 拆包裹:先看外包装验货,读说明书知道怎么拆,然后取货物。

### 严谨原理:RIFF 容器

**RIFF**(Resource Interchange File Format)是 Microsoft 1991 设计的容器格式。核心概念 **chunk**:

```
每个 chunk:
  [4 字节 FourCC 标识]
  [4 字节 chunk 大小(不含这 8 字节 header)]
  [size 字节数据]
  [可能 1 字节 padding(如果 size 是奇数,补 0 让下一个 chunk 对齐 2 字节)]
```

FourCC(Four Character Code)是 4 字节 ASCII 标识:`'RIFF'`、`'WAVE'`、`'fmt '`、`'data'`、`'LIST'`。注意 `'fmt '` 末尾是空格(凑齐 4 字符)。

WAV 文件结构(RIFF 容器内):

```
Offset  Bytes  Description
0       4      'RIFF'              ← magic
4       4      file_size - 8       ← 余下文件大小(little-endian u32)
8       4      'WAVE'              ← RIFF 类型
12      4      'fmt '              ← fmt chunk ID
16      4      fmt_chunk_size      ← 通常是 16(PCM)
20      2      audio_format        ← 1 = PCM(线性,无压缩)
22      2      num_channels        ← 1 = mono, 2 = stereo
24      4      sample_rate         ← 44100 / 48000 / 22050 等
28      4      byte_rate           ← sample_rate * num_channels * bits_per_sample / 8
32      2      block_align         ← num_channels * bits_per_sample / 8
34      2      bits_per_sample     ← 8 / 16 / 24 / 32
36      4      'data'              ← data chunk ID
40      4      data_chunk_size     ← 实际音频字节数
44      ...    PCM samples         ← 音频数据
```

注意 44 字节的 WAV header 是"标准 WAV"(无扩展)。现代 WAV 可能有扩展格式(WAVE_FORMAT_EXTENSIBLE,audio_format = 0xFFFE),fmt chunk 更大。

### 字节序(Endianness)

WAV 是 little-endian(低字节在前)。Intel x86 也是 little-endian,所以解析时可以直接 `u32::from_le_bytes(buf[..4].try_into().unwrap())`,无需字节交换。

```rust
// 读 4 字节 little-endian u32
fn read_u32_le(buf: &[u8]) -> u32 {
    u32::from_le_bytes([buf[0], buf[1], buf[2], buf[3]])
}

// 或更安全:
fn read_u32_le_safe(buf: &[u8]) -> Option<u32> {
    Some(u32::from_le_bytes(buf.get(..4)?.try_into().ok()?))
}
```

### PCM 是什么

**PCM**(Pulse-Code Modulation,脉冲编码调制):音频的数字表示。

模拟音频(连续波形)→ ADC(模数转换)→ 离散样本。

```
连续波形:
   /\
  /  \    /\
 /    \__/  \___
                 → 每隔 T 秒采样一次,得到 [0.5, 1.0, 0.5, -0.3, -0.8, ...]
```

每个样本是一个数,代表那一刻的波形振幅。WAV 存这些数。

**采样率**(sample_rate):每秒多少样本。CD 音质 44100 Hz(每秒 44100 个样本)。电话 8000 Hz。

**位深**(bits_per_sample):每样本多少 bit。CD 是 16-bit(振幅范围 -32768..32767)。专业录音 24-bit 或 32-bit float。

**声道**(channels):1=mono,2=stereo(左右)。5.1 环绕=6 声道。

### PCM 数据布局

16-bit stereo:每样本 4 字节(L 16bit + R 16bit)。

```
[L0_lo][L0_hi][R0_lo][R0_hi][L1_lo][L1_hi][R1_lo][R1_hi]...
```

block_align = num_channels * bits_per_sample / 8 = 2 * 16 / 8 = 4 字节 / sample frame。

每 sample frame 包含同时刻所有声道。所以"音频长度"(样本数) = data_chunk_size / block_align。

### 归一化到 f32

不同位深的 PCM 范围不同:

- 8-bit PCM:**unsigned**,0..=255,中点 128(沉默)
- 16-bit PCM:**signed**,-32768..=32767
- 24-bit PCM:signed,-8388608..=8388607
- 32-bit float:signed,**已经**是 -1.0..1.0(浮点 PCM)

游戏开发通常归一化到 f32 [-1.0, 1.0],方便混音(Day 139-140):

```rust
fn normalize_16bit(sample: i16) -> f32 {
    sample as f32 / 32768.0  // 归一化到 [-1.0, 1.0)
}

fn normalize_8bit(sample: u8) -> f32 {
    (sample as i32 - 128) as f32 / 128.0
}

fn normalize_24bit(bytes: [u8; 3]) -> f32 {
    // 24-bit signed,手动拼
    let v = (bytes[0] as i32) | ((bytes[1] as i32) << 8) | ((bytes[2] as i32) << 16);
    // 符号扩展
    let v = if v & 0x800000 != 0 { v | !0xFFFFFF } else { v };
    v as f32 / 8388608.0
}
```

**坑**:不要用 `i16 as f32 / 32767.0`!32767 会让 1.0 不准确(32767/32767=1,但 -32768/32767=-1.00003 略超)。正确是 `/32768.0`,所有值在 [-1.0, 1.0)。

### Rust 实现

完整 WAV 解析:

```rust
#[derive(Debug)]
struct WavFile {
    sample_rate: u32,
    num_channels: u16,
    bits_per_sample: u16,
    samples: Vec<f32>,  // 归一化到 [-1.0, 1.0],交错排列(L0, R0, L1, R1, ...)
}

impl WavFile {
    fn parse(data: &[u8]) -> Result<Self, String> {
        // 1. 验证 RIFF magic
        if data.len() < 12 { return Err("too short".into()); }
        if &data[0..4] != b"RIFF" { return Err("not RIFF".into()); }
        if &data[8..12] != b"WAVE" { return Err("not WAVE".into()); }

        // 2. 遍历 chunks
        let mut offset = 12;
        let mut fmt: Option<FmtChunk> = None;
        let mut pcm_data: Option<&[u8]> = None;

        while offset + 8 <= data.len() {
            let chunk_id = &data[offset..offset+4];
            let chunk_size = u32::from_le_bytes(
                data[offset+4..offset+8].try_into().unwrap()
            ) as usize;
            offset += 8;
            if offset + chunk_size > data.len() { break; }
            let chunk_data = &data[offset..offset + chunk_size];

            match chunk_id {
                b"fmt " => {
                    fmt = Some(FmtChunk::parse(chunk_data)?);
                }
                b"data" => {
                    pcm_data = Some(chunk_data);
                }
                _ => {}  // 忽略 LIST / fact 等其他 chunk
            }

            // chunk 对齐 2 字节,奇数 size 补 padding
            offset += chunk_size + (chunk_size & 1);
        }

        let fmt = fmt.ok_or("missing fmt chunk")?;
        let pcm = pcm_data.ok_or("missing data chunk")?;

        // 3. 解码 PCM 样本
        let samples = decode_pcm(pcm, fmt.bits_per_sample, fmt.num_channels)?;

        Ok(Self {
            sample_rate: fmt.sample_rate,
            num_channels: fmt.num_channels,
            bits_per_sample: fmt.bits_per_sample,
            samples,
        })
    }
}

#[derive(Debug)]
struct FmtChunk {
    audio_format: u16,
    num_channels: u16,
    sample_rate: u32,
    byte_rate: u32,
    block_align: u16,
    bits_per_sample: u16,
}

impl FmtChunk {
    fn parse(data: &[u8]) -> Result<Self, String> {
        if data.len() < 16 { return Err("fmt chunk too short".into()); }
        Ok(Self {
            audio_format: u16::from_le_bytes(data[0..2].try_into().unwrap()),
            num_channels: u16::from_le_bytes(data[2..4].try_into().unwrap()),
            sample_rate: u32::from_le_bytes(data[4..8].try_into().unwrap()),
            byte_rate: u32::from_le_bytes(data[8..12].try_into().unwrap()),
            block_align: u16::from_le_bytes(data[12..14].try_into().unwrap()),
            bits_per_sample: u16::from_le_bytes(data[14..16].try_into().unwrap()),
        })
    }
}

fn decode_pcm(data: &[u8], bits: u16, _channels: u16) -> Result<Vec<f32>, String> {
    let mut samples = Vec::with_capacity(data.len() / (bits as usize / 8));
    match bits {
        8 => {
            for &b in data {
                samples.push((b as i32 - 128) as f32 / 128.0);
            }
        }
        16 => {
            for chunk in data.chunks_exact(2) {
                let v = i16::from_le_bytes([chunk[0], chunk[1]]);
                samples.push(v as f32 / 32768.0);
            }
        }
        24 => {
            for chunk in data.chunks_exact(3) {
                let v = (chunk[0] as i32) | ((chunk[1] as i32) << 8) | ((chunk[2] as i32) << 16);
                let v = if v & 0x800000 != 0 { v | !0xFFFFFF } else { v };
                samples.push(v as f32 / 8388608.0);
            }
        }
        32 => {
            // 32-bit 可能是 signed int 或 float
            for chunk in data.chunks_exact(4) {
                // 假设 signed int
                let v = i32::from_le_bytes(chunk.try_into().unwrap());
                samples.push(v as f32 / 2147483648.0);
            }
        }
        _ => return Err(format!("unsupported bits_per_sample: {}", bits)),
    }
    Ok(samples)
}
```

## 5 · 对照与变奏

### WAV vs MP3

WAV 和 MP3 都装音频,但本质不同:

| | WAV | MP3 |
|---|---|---|
| 容器 | RIFF | MPEG-1 Layer III |
| 数据 | 原始 PCM | Huffman + MDCT 压缩 |
| 大小(3 分钟 stereo) | 30 MB | 3 MB |
| 加载 | 直接 memcpy | 必须 decode(Huffman + IMDCT) |
| 质量 | 无损 | 有损(听感损失) |
| 适合 | 短音效、内部 | 分发、BGM |

MP3 是有损压缩,丢掉人耳听不到的频率。WAV 全部保留。

### 历史演化

- **1980s**:AIFF(Apple)、AU(Sun),无压缩 PCM
- **1991**:WAV(Microsoft / IBM),RIFF 容器
- **1990s**:MP3 标准化,有损压缩革命
- **2000s**:Ogg Vorbis(开源)、FLAC(无损)
- **2010s**:Opus(语音 / 低延迟)
- **2020s**:Opus + AV1 codec,流媒体主流

Casey Day 138 用 1991 年的 WAV,简单且教学价值高。BGM(Day 141)用现代格式。

### 二进制格式共性

学 WAV 后,你看任何二进制格式都能拆解:

- **PNG**:'\x89PNG' magic + IHDR chunk + IDAT chunks(压缩像素)+ IEND chunk。和 WAV 同款 chunk 结构
- **ELF**:'\x7fELF' magic + ELF header + program headers + section headers
- **PDF**:'%PDF-1.4' magic + objects
- **ZIP**:'PK\x03\x04' magic + central directory

每个格式都有 magic + header + chunks/sections。一次掌握,终身受用。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:

1. WAV 文件 44100 Hz,16-bit stereo,3 分钟。文件大约多大?
2. WAV 的 fmt chunk 里 audio_format=1 和 audio_format=3 各表示什么?
3. 8-bit PCM 为什么是 unsigned,而 16-bit 是 signed?
4. 一个 100ms 的 8-bit mono WAV,data chunk size 是多少?

**参考解答**:
1. 3 × 60 × 44100 × 2 × 2 = 31,752,000 字节 ≈ 30 MB(无压缩)。
2. 1 = PCM(linear integer),3 = IEEE Float(32-bit float sample)。Casey 只支持 1。现代 DAW 录音常用 3(浮点更精确)。
3. 历史原因。1980s 早期 ADC(模数转换器)输出 unsigned 8-bit(0-255,128 = 0V)。16-bit ADC 出现时 IEEE 标准 signed(更直观,-32768 = 负振幅)。两种都保留下来。
4. 100ms × 8000 Hz × 1 channel × 1 byte = 800 字节(假设 8kHz 采样)。如果是 44.1kHz,则是 4410 字节。

### Lv2 · 动手实践

**题**:完整实现 WAV 解析,加载一个真实 WAV 文件并打印信息。

要求:
1. `WavFile` struct,字段:sample_rate、num_channels、bits_per_sample、samples(Vec<f32>)
2. `WavFile::parse(data: &[u8]) -> Result<Self, String>`
3. `WavFile::duration_seconds(&self) -> f32`
4. main:用 `std::fs::read` 加载 WAV 文件,parse,打印信息

完成标准:用 ffmpeg 生成一个测试 WAV,parse 后打印正确信息。

**参考解答**:

```rust
use std::fs;
use std::path::Path;

#[derive(Debug)]
struct WavFile {
    sample_rate: u32,
    num_channels: u16,
    bits_per_sample: u16,
    samples: Vec<f32>,
}

#[derive(Debug)]
struct FmtChunk {
    audio_format: u16,
    num_channels: u16,
    sample_rate: u32,
    byte_rate: u32,
    block_align: u16,
    bits_per_sample: u16,
}

impl FmtChunk {
    fn parse(data: &[u8]) -> Result<Self, String> {
        if data.len() < 16 { return Err("fmt chunk too short".into()); }
        Ok(Self {
            audio_format: u16::from_le_bytes([data[0], data[1]]),
            num_channels: u16::from_le_bytes([data[2], data[3]]),
            sample_rate: u32::from_le_bytes([data[4], data[5], data[6], data[7]]),
            byte_rate: u32::from_le_bytes([data[8], data[9], data[10], data[11]]),
            block_align: u16::from_le_bytes([data[12], data[13]]),
            bits_per_sample: u16::from_le_bytes([data[14], data[15]]),
        })
    }
}

impl WavFile {
    fn parse(data: &[u8]) -> Result<Self, String> {
        if data.len() < 12 { return Err("file too short".into()); }
        if &data[0..4] != b"RIFF" { return Err("missing RIFF magic".into()); }
        if &data[8..12] != b"WAVE" { return Err("not WAVE format".into()); }

        let mut offset = 12;
        let mut fmt: Option<FmtChunk> = None;
        let mut pcm_data: Option<&[u8]> = None;

        while offset + 8 <= data.len() {
            let chunk_id = &data[offset..offset+4];
            let chunk_size = u32::from_le_bytes(
                [data[offset+4], data[offset+5], data[offset+6], data[offset+7]]
            ) as usize;
            offset += 8;
            if offset + chunk_size > data.len() { break; }
            let chunk_data = &data[offset..offset + chunk_size];

            match chunk_id {
                b"fmt " => fmt = Some(FmtChunk::parse(chunk_data)?),
                b"data" => pcm_data = Some(chunk_data),
                _ => {}
            }
            offset += chunk_size + (chunk_size & 1);  // 奇数补 padding
        }

        let fmt = fmt.ok_or("missing fmt chunk")?;
        let pcm = pcm_data.ok_or("missing data chunk")?;

        if fmt.audio_format != 1 {
            return Err(format!("unsupported audio_format: {} (only PCM=1)", fmt.audio_format));
        }

        let samples = decode_pcm(pcm, fmt.bits_per_sample)?;

        Ok(Self {
            sample_rate: fmt.sample_rate,
            num_channels: fmt.num_channels,
            bits_per_sample: fmt.bits_per_sample,
            samples,
        })
    }

    fn duration_seconds(&self) -> f32 {
        let frames = self.samples.len() / self.num_channels as usize;
        frames as f32 / self.sample_rate as f32
    }

    fn num_frames(&self) -> usize {
        self.samples.len() / self.num_channels as usize
    }
}

fn decode_pcm(data: &[u8], bits: u16) -> Result<Vec<f32>, String> {
    let mut samples = Vec::new();
    match bits {
        8 => for &b in data { samples.push((b as i32 - 128) as f32 / 128.0); },
        16 => for c in data.chunks_exact(2) {
            let v = i16::from_le_bytes([c[0], c[1]]);
            samples.push(v as f32 / 32768.0);
        },
        24 => for c in data.chunks_exact(3) {
            let v = (c[0] as i32) | ((c[1] as i32) << 8) | ((c[2] as i32) << 16);
            let v = if v & 0x800000 != 0 { v | !0xFFFFFF } else { v };
            samples.push(v as f32 / 8388608.0);
        },
        32 => for c in data.chunks_exact(4) {
            let v = i32::from_le_bytes([c[0], c[1], c[2], c[3]]);
            samples.push(v as f32 / 2147483648.0);
        },
        _ => return Err(format!("unsupported bits: {}", bits)),
    }
    Ok(samples)
}

fn main() {
    let path = std::env::args().nth(1).unwrap_or_else(|| "test.wav".to_string());
    if !Path::new(&path).exists() {
        eprintln!("File {} not found. Generate one with:", path);
        eprintln!("  ffmpeg -f lavfi -i 'sine=frequency=440:duration=1' -c:a pcm_s16le test.wav");
        std::process::exit(1);
    }
    let data = fs::read(&path).expect("read failed");
    println!("Loaded {} ({} bytes)", path, data.len());

    let wav = WavFile::parse(&data).expect("parse failed");
    println!("Sample rate:     {} Hz", wav.sample_rate);
    println!("Channels:        {}", wav.num_channels);
    println!("Bits per sample: {}", wav.bits_per_sample);
    println!("Total samples:   {}", wav.samples.len());
    println!("Frames:          {}", wav.num_frames());
    println!("Duration:        {:.2} seconds", wav.duration_seconds());
    println!("\nFirst 5 samples: {:?}", &wav.samples[..5.min(wav.samples.len())]);
}
```

### Lv3 · 迁移设计

**题**:用 WAV 解析的思路,**手写 BMP 解析**(类似但更简单)。

BMP 结构:
```
[BM magic (2 bytes)]
[file_size (4 bytes LE)]
[reserved (4 bytes)]
[pixel_offset (4 bytes LE)]
[DIB header: size, width, height, planes, bits_per_pixel, ...]
[pixel data]
```

要求:解析 BMP 拿到 width、height、bits_per_pixel、pixels。

**提示**:
- BMP magic 是 'BM'(2 字符)
- DIB header 通常 BITMAPINFOHEADER(40 字节)
- 像素数据从底向上扫描(行 0 是图像底部)
- 每行 4 字节对齐(可能 padding)

Lv3 答案要点:BMP 和 WAV 同款 chunk / header 模式。Casey Day 1-25 已经加载 BMP,这里只是复习。

**Troubleshooting**:
- `unsupported audio_format: 3` —— 你的 WAV 是 float PCM(32-bit float)。在 parser 里加 audio_format=3 支持,32-bit 时按 f32 解析
- `chunks_exact panic` —— 数据长度不对齐 bits/8,文件损坏
- 噪音 / 杂音 —— 字节序错了。WAV 是 LE,确认 `from_le_bytes` 不是 `from_be_bytes`
- 8-bit WAV 解码后振幅偏大 —— 8-bit 是 unsigned,要 `(b - 128) / 128.0`
