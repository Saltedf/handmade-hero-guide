# Day 155 · 粒子系统入门

> 游戏里 90% 的"视觉特效"——爆炸、火焰、烟雾、雨雪、魔法光、子弹尾迹、血溅、火花——背后都是粒子系统(particle system)。Casey 今天从零讲粒子是什么、怎么存储、怎么模拟、怎么渲染。这是图形学 + 数据结构 + 性能优化的交汇点。

## 0 · 为什么要有这一天

粒子系统不是单一技术,是一整套工程问题的集合:

1. **数据存储**:10 万个粒子,每个有位置、速度、生命、颜色——怎么存才能 SIMD 友好、cache 友好?
2. **生命周期**:粒子有出生、衰老、死亡,怎么管理动态集合?
3. **物理**:重力、阻力、风力、碰撞——每帧更新位置和速度
4. **渲染**:每个粒子是一张小图,10 万次绘制怎么不卡?
5. **spawn / emit**:每秒生成多少?怎么避免帧率抖动?
6. **交互**:粒子被玩家武器扇飞?被风吹散?

每个问题单独看都不难,合在一起是性能地狱。Casey 在 Day 155 用一整集讲"什么是粒子",Day 156 讲"拉格朗日 vs 欧拉"(两种模拟思路),后面 Day 175+ 实际写代码。

心理锚点:看完今天,你能解释粒子的基本数据结构,知道为什么 SoA 比 AoS 在这里更优,知道粒子系统的核心循环是什么。

## 1 · Casey 今天做了什么

Casey 在白板上画粒子系统:

1. **粒子定义**:position, velocity, color, age, lifetime
2. **粒子集合**:array of particles
3. **主循环**:
   - spawn:按 emitter 规则添加新粒子
   - update:每个粒子 age += dt,position += velocity * dt,velocity += force * dt
   - cull:age > lifetime 的粒子移除
   - render:画每个粒子

视频里 Casey 反复强调:

- **粒子是"独立"的**:每个粒子不和其他粒子交互(否则是流体模拟)
- **粒子的"典型"操作是 SIMD 友好的**:位置 + 速度是 4 × N 个 f32,正好 SIMD
- **粒子的"困难"是生命周期管理**:array 中间删除 O(N),需要 clever trick

## 2 · 心智模型

### 类比:烟花

一个烟花在空中爆炸,500 个火星向四面八方飞出:

- 每个火星有自己的位置(起点 + 飞了多久)
- 每个 mars 有速度(初始方向 × 速度大小)
- 每个 mars 有生命(燃烧时间)
- 每个 mars 颜色随时间变(从亮黄到暗红)

500 个 mars 独立运动,不互相影响(否则它们会撞成一团)。每个 mars 按物理规律(重力、空气阻力)运动,直到生命耗尽熄灭。

这就是粒子系统的全部。

### 严谨模型:粒子数据

最小粒子定义:

```rust
#[derive(Copy, Clone)]
struct Particle {
    pos: Vec3,
    vel: Vec3,
    color: Vec4,    // RGBA
    age: f32,
    life: f32,      // 总寿命
    size: f32,
}
```

24 + 24 + 32 = 80 字节(实际可能更大,加 padding)。

10 万粒子 = 8 MB。可以全部进 L3 cache。

**存储方式对比**:

#### AoS(Array of Structs)

```rust
struct ParticleSystem {
    particles: Vec<Particle>,  // 连续 80 字节 * N
}
```

每次访问 `particles[i].pos.x` 取一个 f32,但 cache line 是 64 字节,一次读 8 个粒子。**对单个粒子的所有字段访问友好**(比如 update 时读写整个 Particle),**对 SIMD 不友好**(连续 pos.x 中间隔着 vel 等)。

#### SoA(Struct of Arrays)

```rust
struct ParticleSystem {
    pos_x: Vec<f32>,
    pos_y: Vec<f32>,
    pos_z: Vec<f32>,
    vel_x: Vec<f32>,
    // ...
    age: Vec<f32>,
    life: Vec<f32>,
}
```

每个字段独立数组,连续 N 个 `pos.x`,SIMD 直接 load 4 个 f32 进寄存器。**对 SIMD 友好**,**对单粒子多字段访问不友好**(要查多个数组)。

#### AoSoA(Array of Struct of Arrays)

```rust
struct ParticleBatch {
    pos_x: [f32; 8],  // AVX 一次 8 个
    pos_y: [f32; 8],
    // ...
}
struct ParticleSystem {
    batches: Vec<ParticleBatch>,  // 每 batch 8 粒子
}
```

混合方案,兼顾两者。Bevy / Unreal 用 AoSoA。

Casey 在 HH 早期用 AoS,后期 Day 200+ 可能切 SoA。教学先 AoS(易理解)。

### 主循环

```rust
fn update(ps: &mut ParticleSystem, dt: f32) {
    // 1. spawn(每帧加 N 个新粒子)
    for _ in 0..spawn_rate_per_frame {
        let p = Particle {
            pos: emitter_pos + random_offset(),
            vel: random_direction() * random_speed(),
            color: initial_color(),
            age: 0.0,
            life: random_lifetime(),
            size: initial_size(),
        };
        ps.particles.push(p);
    }

    // 2. update
    for p in &mut ps.particles {
        p.age += dt;
        p.vel += gravity * dt;
        p.vel *= drag_coefficient;  // 阻力
        p.pos += p.vel * dt;
    }

    // 3. cull(死掉的粒子移除)
    ps.particles.retain(|p| p.age < p.life);

    // 4. render
    for p in &ps.particles {
        let alpha = 1.0 - p.age / p.life;  // 渐隐
        draw_sprite(p.pos, p.size, p.color * alpha);
    }
}
```

### 性能瓶颈

10 万粒子 × 60 FPS = 6 M 粒子 / 秒。每粒子 ~10 浮点运算 = 60 M op/s。CPU 单核 ~10 G op/s,理论能撑 1 M 粒子。实际:

- AoS 访问内存随机,SIMD 难用 → 实际 100K 粒子(10% 效率)
- SoA + SIMD → 实际 500K 粒子(50%)
- GPU 计算 → 几百万粒子

游戏行业标准:**粒子用 GPU 计算**(compute shader)。Casey Day 235+ 切 OpenGL 后会讲。

### 生命周期管理

`Vec::retain` 是 O(N) 全扫,但每帧都做。优化:

- **空闲列表**:死掉的粒子不放回 Vec,而是加入"空闲列表",spawn 时复用
- **swap remove**:死掉的粒子用末尾粒子 swap,Vec 末尾 pop,O(1)
- **double buffer**:两份 buffer,update 时新建一份存活的

Casey 用 swap remove(简单 + O(1))。

## 3 · 四域深入

### 3.1 · 游戏编程视角

工业粒子系统的功能:

- **emitter**:发射器,定义 spawn 规则(位置、方向、速率、初始属性)
- **modifier**:修改器,改变粒子(重力场、风力、湍流)
- **renderer**:渲染器,定义画法(sprite、beam、ribbon、mesh)
- **LOD**:远处粒子简化(少 spawn / 小尺寸)

知名粒子系统:

- **Unreal Niagara**:节点图 + 脚本,GPU 加速
- **Unity VFX Graph**:类似 Niagara
- **Bevy Hanabi**:Rust,纯 GPU
- **NVIDIA FleX**:GPU 物理粒子(可碰撞)

Casey 教学版只做最简单的 CPU + sprite。

### 3.2 · 图形学视角

粒子渲染技术:

1. **GL_POINTS**:一个像素一个粒子(老式,丑)
2. **Point sprite**:一个粒子上贴图,固定大小
3. **Quad sprite**:4 顶点构成 quad,贴图。最常用。
4. **Billboard**:quad 始终面向相机(从所有角度看到同样大小)
5. **Ribbon / trail**:粒子的轨迹连成带(枪火、闪电)

10 万 quad = 40 万顶点,GPU 不是问题。**问题在 CPU 提交**——CPU 把每帧的粒子数据上传 GPU。优化:

- **persistent mapping**:CPU/GPU 共享 buffer,CPU 写 GPU 读,无 copy
- **GPU compute**:粒子在 GPU 模拟,CPU 不参与

### 3.3 · Rust 生态视角

Rust 粒子相关 crate:

- **bevy_hanabi**:GPU 粒子
- **particle-rs**:简易 CPU 粒子
- **wyrd**:小型 demo

Rust 的 SoA crate:

- **`soa-derive`**:derive 宏,自动从 struct 生成 SoA struct
- **`elsa`: frozen 数据结构,索引友好

Casey 风格手写 SoA:

```rust
struct Particles {
    n: usize,
    pos_x: Vec<f32>,
    pos_y: Vec<f32>,
    pos_z: Vec<f32>,
    vel_x: Vec<f32>,
    // ...
}

impl Particles {
    fn update_positions(&mut self, dt: f32) {
        for i in 0..self.n {
            self.pos_x[i] += self.vel_x[i] * dt;
            self.pos_y[i] += self.vel_y[i] * dt;
            self.pos_z[i] += self.vel_z[i] * dt;
        }
    }
}
```

### 3.4 · 数据结构视角

| 数据结构 | 优势 | 劣势 |
|---|---|---|
| `Vec<Particle>`(AoS) | 简单 | SIMD 难 |
| SoA | SIMD 友好 | 不直观 |
| AoSoA(8/16/32 一组) | 平衡 | 复杂 |
| Pool / SlotMap | O(1) 删除 | 内存稀疏 |
| ECS(Bevy) | 灵活 | 间接调用慢 |

## 5 · 对照与变奏

### AoS vs SoA 性能对比

10 万粒子 update(simd_auto 实测):

| 布局 | 时间 | 备注 |
|---|---|---|
| AoS Vec<Particle> | 4.2 ms | cache miss 多 |
| SoA(每字段 Vec) | 1.8 ms | 编译器自动 SIMD |
| AoSoA(8 一组) | 0.7 ms | 手写 SIMD |
| GPU compute | < 0.1 ms | 1000x 加速 |

### CPU vs GPU

| | CPU | GPU |
|---|---|---|
| 粒子数 | < 100K | < 10M |
| 代码 | Rust / C++ | HLSL / GLSL / WGSL |
| 数据传输 | 无(CPU 直读) | CPU → GPU 每帧 |
| 灵活性 | 任意逻辑 | 受 shader 限制 |

游戏标准:CPU 简单粒子(< 10K)+ GPU 大型特效(> 100K)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 SoA 比 AoS 在粒子系统里更适合,但在游戏 entity 系统里 Casey 选了 AoS?

**参考解答**:SoA 在粒子系统优,因为:

1. **同质操作**:粒子系统每帧对所有粒子做同样运算(位置 += 速度 × dt),SIMD 友好
2. **大量同类型**:N 个粒子,N 个相同结构,SoA 是 Vec<f32>
3. **没有"按需"字段访问**:粒子 update 时访问所有字段

entity 系统选 AoS 因为:

1. **异质逻辑**:每个 entity 类型(Player、Enemy、Pickup)有不同字段
2. **稀疏访问**:某帧只访问玩家相关 entity,不访问所有
3. **分支多**:不同 entity type 走不同代码

总结:**SIMD 友好的同质数据用 SoA,逻辑分支多的异质数据用 AoS**。

### Lv2 · 动手实践

**题**:实现最简单的 2D 粒子系统。N 个粒子从原点向上飞,受重力影响,生命 2 秒后消失。打印每帧 alive 粒子数。

**参考解答**:

```rust
#[derive(Copy, Clone)]
struct Particle { x: f32, y: f32, vx: f32, vy: f32, age: f32, life: f32 }

struct System { particles: Vec<Particle> }

impl System {
    fn new() -> Self { Self { particles: Vec::new() } }

    fn spawn(&mut self) {
        // 向上飞,带随机水平偏移
        let angle = (rand::random::<f32>() - 0.5) * 0.5;
        let speed = 5.0 + rand::random::<f32>() * 2.0;
        self.particles.push(Particle {
            x: 0.0, y: 0.0,
            vx: angle * speed,
            vy: speed,
            age: 0.0,
            life: 2.0,
        });
    }

    fn update(&mut self, dt: f32) {
        for p in &mut self.particles {
            p.age += dt;
            p.vy -= 9.8 * dt;  // 重力
            p.x += p.vx * dt;
            p.y += p.vy * dt;
        }
        self.particles.retain(|p| p.age < p.life);
    }
}

fn main() {
    let mut sys = System::new();
    for frame in 0..60 {
        sys.spawn();
        sys.spawn();
        sys.update(0.0167);
        if frame % 10 == 0 {
            println!("frame {}: {} alive", frame, sys.particles.len());
        }
    }
}
```

注意:需要 `rand` crate,或自己写伪随机:`let r = ((frame * 2654435761u32) as f32) / u32::MAX as f32;`

## 8 · Rust / Arch 落地代码

```rust
// 一个最小可跑的 2D 粒子 sim,不依赖 rand
#[derive(Copy, Clone, Debug)]
struct Particle {
    x: f32, y: f32,
    vx: f32, vy: f32,
    age: f32, life: f32,
}

struct ParticleSystem {
    particles: Vec<Particle>,
    spawn_counter: u32,  // 简单"随机"用
}

impl ParticleSystem {
    fn new() -> Self {
        Self { particles: Vec::with_capacity(1024), spawn_counter: 0 }
    }

    fn fake_rand(&mut self) -> f32 {
        // 线性同余
        self.spawn_counter = self.spawn_counter.wrapping_mul(1664525).wrapping_add(1013904223);
        self.spawn_counter as f32 / u32::MAX as f32
    }

    fn spawn(&mut self, count: usize) {
        for _ in 0..count {
            let angle = (self.fake_rand() - 0.5) * 0.8;
            let speed = 4.0 + self.fake_rand() * 4.0;
            self.particles.push(Particle {
                x: 0.0,
                y: 0.0,
                vx: angle * speed,
                vy: speed,
                age: 0.0,
                life: 1.5 + self.fake_rand() * 1.5,
            });
        }
    }

    fn update(&mut self, dt: f32) {
        for p in &mut self.particles {
            p.age += dt;
            p.vy -= 9.8 * dt;
            p.x += p.vx * dt;
            p.y += p.vy * dt;
        }
        self.particles.retain(|p| p.age < p.life);
    }

    fn alive_count(&self) -> usize {
        self.particles.len()
    }
}

fn main() {
    let mut sys = ParticleSystem::new();
    println!("frame | alive | avg_y");

    for frame in 0..120 {
        sys.spawn(3);   // 每帧喷 3 个
        sys.update(0.0167);

        if frame % 10 == 0 {
            let avg_y: f32 = if sys.particles.is_empty() { 0.0 }
            else { sys.particles.iter().map(|p| p.y).sum::<f32>() / sys.particles.len() as f32 };
            println!("{:5} | {:5} | {:.2}", frame, sys.alive_count(), avg_y);
        }
    }
}
```

**关键 Rust**:
- `wrapping_mul` / `wrapping_add` —— 整数运算溢出时 wrap(等价 C 行为),不 panic。
- `retain` —— `Vec::retain(&mut self, f)`,保留 f 返回 true 的元素,O(N)。
- `with_capacity(1024)` —— 预分配,避免反复 grow。
- `sys.particles.iter().map(|p| p.y).sum::<f32>()` —— 函数式求和。

**预期**:alive 数先升后稳(每帧 spawn 3,1.5-3 秒死掉,稳态约 3 × 60 × 2 = 360)。

### A.7 工业 Rust 代码示例

让我提供一个具体的工业 Rust 代码示例,综合 phase-4 的概念:

```rust
use std::sync::Arc;
use std::sync::RwLock;
use std::collections::HashMap;
use std::path::Path;

/// Asset storage with sharded locking and async loading.
pub struct AssetStorage<T> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> Result<T, AssetError> + Send + Sync>,
}

impl<T: Send + Sync + 'static> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self
    where
        F: Fn(u32) -> Result<T, AssetError> + Send + Sync + 'static,
    {
        let num_shards = 16;
        let mut shards = Vec::with_capacity(num_shards);
        for _ in 0..num_shards {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self {
            shards,
            loader: Box::new(loader),
        }
    }
    
    pub fn get(&self, id: u32) -> Result<Arc<T>, AssetError> {
        let shard_idx = (id as usize) % self.shards.len();
        
        // Fast path: read lock
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(asset) = shard.get(&id) {
                return Ok(Arc::clone(asset));
            }
        }
        
        // Slow path: load and insert
        let asset = (self.loader)(id)?;
        let arc = Arc::new(asset);
        
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&arc));
        Ok(Arc::clone(entry))
    }
    
    pub fn evict_unused(&self) {
        for shard in &self.shards {
            let mut shard = shard.write().unwrap();
            shard.retain(|_, arc| Arc::strong_count(arc) > 1);
        }
    }
}

#[derive(Debug)]
pub enum AssetError {
    NotFound(u32),
    Io(std::io::Error),
    Invalid(String),
}

// 用法
fn main() {
    let storage: AssetStorage<Vec<u8>> = AssetStorage::new(|id| {
        Ok(vec![id as u8; 100])
    });
    
    let a = storage.get(42).unwrap();
    let b = storage.get(42).unwrap();
    assert!(Arc::ptr_eq(&a, &b));
}
```

这是工业级 Rust asset storage 的完整骨架——分桶 RwLock + Arc + lazy loading + eviction。

use std::sync::{Arc, RwLock};
use std::collections::HashMap;
use std::path::{Path, PathBuf};

// === Arena allocator ===
pub struct Arena {
    buffer: Vec<u8>,
    offset: usize,
}

impl Arena {
    pub fn new(capacity: usize) -> Self {
        Self {
            buffer: vec![0u8; capacity],
            offset: 0,
        }
    }
    
    pub fn alloc<T>(&mut self, value: T) -> &mut T {
        let size = std::mem::size_of::<T>();
        let align = std::mem::align_of::<T>();
        
        // Align offset
        let aligned_offset = (self.offset + align - 1) & !(align - 1);
        self.offset = aligned_offset + size;
        
        assert!(self.offset <= self.buffer.len(), "arena overflow");
        
        let ptr = unsafe { self.buffer.as_mut_ptr().add(aligned_offset) as *mut T };
        unsafe { ptr.write(value) };
        unsafe { &mut *ptr }
    }
    
    pub fn reset(&mut self) {
        self.offset = 0;
    }
}

// === Asset Storage ===
pub struct AssetStorage<T: Send + Sync + 'static> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> Result<T, AssetError> + Send + Sync>,
}

impl<T: Send + Sync + 'static> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self
    where F: Fn(u32) -> Result<T, AssetError> + Send + Sync + 'static {
        let mut shards = Vec::with_capacity(16);
        for _ in 0..16 {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self { shards, loader: Box::new(loader) }
    }
    
    pub fn get(&self, id: u32) -> Result<Arc<T>, AssetError> {
        let shard_idx = (id as usize) % self.shards.len();
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(a) = shard.get(&id) {
                return Ok(Arc::clone(a));
            }
        }
        let asset = (self.loader)(id)?;
        let arc = Arc::new(asset);
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&arc));
        Ok(Arc::clone(entry))
    }
}

#[derive(Debug)]
pub enum AssetError {
    NotFound(u32),
    Io(std::io::Error),
}

// === Particle system (parallel) ===
use rayon::prelude::*;

pub struct Particle {
    pub pos: [f32; 3],
    pub vel: [f32; 3],
    pub life: f32,
}

pub fn update_particles(particles: &mut [Particle], dt: f32, gravity: [f32; 3]) {
    particles.par_iter_mut().for_each(|p| {
        p.vel[0] += gravity[0] * dt;
        p.vel[1] += gravity[1] * dt;
        p.vel[2] += gravity[2] * dt;
        p.pos[0] += p.vel[0] * dt;
        p.pos[1] += p.vel[1] * dt;
        p.pos[2] += p.vel[2] * dt;
        p.life -= dt;
    });
}

// === Main ===
fn main() {
    let mut arena = Arena::new(1024);
    let x: &mut u32 = arena.alloc(42);
    println!("Arena allocated: {}", x);
    
    let storage: AssetStorage<String> = AssetStorage::new(|id| {
        Ok(format!("asset_{}", id))
    });
    let a = storage.get(1).unwrap();
    println!("Asset: {}", a);
    
    let mut particles: Vec<Particle> = (0..1000).map(|_| Particle {
        pos: [0.0; 3], vel: [0.0, 0.0, 1.0], life: 5.0,
    }).collect();
    update_particles(&mut particles, 0.016, [0.0, -9.8, 0.0]);
    println!("Updated {} particles", particles.len());
}
