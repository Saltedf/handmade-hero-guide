
# Day 150 · 从资产文件加载资产

> Day 149 写了打包器。今天 Casey 在**游戏端**写加载代码:打开 .hha,读 header,按 asset_id 索引访问任意资产。这是打包的对称面:写时把多份合一,读时按需取出。难点不是格式,而是**何时读、读多少、读到哪里**——这决定了游戏的内存占用和启动速度。

## 0 · 为什么要有这一天

加载策略有三种,各有适用场景:

1. **Eager(预加载)**:启动时把所有 asset 全读进内存。简单,但启动慢、内存大。
2. **Lazy(按需加载)**:用到才读。启动快,但首次使用有卡顿。
3. **Streaming(流式)**:背景线程异步预读,接近使用时刚好就绪。最优,代码复杂。

Casey 今天先实现 **eager + lazy 混合**:索引(eager 加载,几 KB)+ 数据(lazy 按需加载)。后续 Day 158 会加 usage tracking,Day 165 修线程 bug 时再加异步。

加载端的核心数据结构是 **asset storage**(资产存储):

```rust
struct AssetStorage {
    file: File,                    // .hha 句柄
    header: HhaHeader,             // 16 字节头部(已读)
    assets: Box<[HhaAsset]>,       // 索引数组(已读)
    loaded: HashMap<u32, LoadedAsset>,  // id -> 已加载到内存的数据
}

enum LoadedAsset {
    Bitmap { width: u32, height: u32, pixels: Box<[u32]> },
    Sound { samples: Box<[f32]> },
}
```

`get(asset_id) -> &LoadedAsset` 接口:

- 如果已在 `loaded` 里,直接返回
- 否则从 `assets[id]` 拿 (offset, size),seek+read 数据,decode 成 LoadedAsset,缓存,返回

这就是 **lazy loading + caching** 的最简形态。

心理锚点:看完今天,你能给 .hha 写一个加载器,启动只读 header + 索引(几 KB),按 ID 取任意 asset 才读数据(几 KB-MB),启动时间 < 100ms。

## 1 · Casey 今天做了什么

Casey 在游戏端做了三件事:

1. 添加 `OpenAssetFile(path)` 接口,平台层打开 .hha,返回 handle
2. 添加 `ReadAssetData(handle, offset, size, dst)` 接口,seek + read

视频里 Casey 强调:

- **游戏代码不能直接调 Win32 `CreateFile`**:平台层抽象。Linux 上是 `open`,Windows 上是 `CreateFile`,游戏代码不该关心。
- **decode 一次,缓存**:同一个 asset 第二次取,直接返回缓存,不再读盘。
- **内存管理**:loaded 缓存里每个 asset 是 `Box<[u8]>`,显式 heap 分配。Casey 后面 Day 157+ 会换成 arena。

## 2 · 心智模型

### 类比:咖啡店点单

你去咖啡店,菜单上 50 种咖啡(索引)。你点一杯"卡布奇诺"(asset_id),吧员:

1. 如果做好的卡布奇诺还在保温箱(缓存),直接给你(快)
2. 否则现场做(读盘 + decode),做完放进保温箱

启动时把菜单读进内存(几 KB),只在你点单时才做。这就是 lazy loading。

### 严谨模型:三种加载策略对比

| | eager | lazy | streaming |
|---|---|---|---|
| 启动时间 | 慢(全读) | 快(只读索引) | 快 |
| 内存 | 大(所有 asset 都在) | 小(只用到的) | 中(预读窗) |
| 首次访问 | 0ms | 卡(读盘+decode) | 0ms(已预读) |
| 代码复杂度 | 低 | 中 | 高 |

游戏体验关键:**首次访问不能卡**。所以工业级用 streaming,游戏代码访问时永远已在缓存。

streaming 实现:

- 背景线程监听"预读请求"队列
- 主线程触发预读(如玩家靠近一个 NPC,把它的语音预读)
- 背景线程完成预读后,把数据放进缓存
- 主线程访问时,缓存命中

Casey 今天不实现 streaming(Day 165+ 才有),但留好接口。

### 数据结构:三段

```rust
struct AssetStorage {
    // 1. 元数据(启动时全读)
    file: File,
    header: HhaHeader,
    assets: Box<[HhaAsset]>,  // 索引

    // 2. 已加载缓存(运行时增长)
    loaded: HashMap<u32, LoadedAsset>,

    // 3. 配置
    base_path: PathBuf,
}
```

为什么 `assets` 用 `Box<[HhaAsset]>` 而非 `Vec<HhaAsset>`?Box<[T]> 是"固定大小数组"(没有 push/capacity 等额外字段),内存少 16 字节。Casey 在 HH 后期都会用 Box<[T]> 替代 Vec<T> 当 array 不会变时。

### 接口设计

```rust
impl AssetStorage {
    pub fn open(path: &Path) -> Result<Self, LoadError> {
        let mut file = File::open(path)?;
        // 读 header
        let mut header_buf = [0u8; 16];
        file.read_exact(&mut header_buf)?;
        let header = parse_header(&header_buf)?;
        // 读 asset 索引
        let asset_size = std::mem::size_of::<HhaAsset>();
        let mut assets = Vec::with_capacity(header.asset_count as usize);
        for _ in 0..header.asset_count {
            let mut a = [0u8; 28];
            file.read_exact(&mut a)?;
            assets.push(parse_asset(&a)?);
        }
        Ok(Self {
            file, header,
            assets: assets.into_boxed_slice(),
            loaded: HashMap::new(),
            base_path: path.to_path_buf(),
        })
    }

    pub fn get_bitmap(&mut self, id: u32) -> Result<&LoadedAsset, LoadError> {
        if !self.loaded.contains_key(&id) {
            let asset = &self.assets[id as usize];
            // seek + read raw bytes
            self.file.seek(SeekFrom::Start(asset.data_offset))?;
            let mut buf = vec![0u8; asset.data_size as usize];
            self.file.read_exact(&mut buf)?;
            // decode
            let loaded = decode_bitmap(&buf)?;
            self.loaded.insert(id, loaded);
        }
        Ok(self.loaded.get(&id).unwrap())
    }
}
```

注意 `&mut self` —— 因为可能要插入缓存。如果游戏代码并发访问,要加锁。

### 内存所有权

- `Box<[HhaAsset]>` —— owned 索引,跟随 storage
- `HashMap<u32, LoadedAsset>` —— owned 缓存,跟随 storage
- `LoadedAsset::Bitmap { pixels: Box<[u32]> }` —— owned 像素数据

`&LoadedAsset` 返回值是借用的,生命周期绑 storage。游戏代码不能存它(下次访问 storage 时可能已失效),要用 `Rc<LoadedAsset>` 或克隆。

Casey 在 HH 里设计成"游戏代码每次需要时调用 get_bitmap",不存指针。这是 immediate-mode 风格。

## 3 · 四域深入

### 3.1 · 游戏编程视角

工业 asset 加载的关键概念:

- **asset ID**:全局唯一,通常 hash 字符串("player_walk_01") → u64
- **asset handle**:轻量引用,内部是 ID + generation(检测失效)
- **asset state**:NotLoaded / Loading / Ready / Unloading
- **dependency**:A 依赖 B(B 是 A 的纹理),加载 A 时自动加载 B
- **reference counting**:asset 用完自动 unload(没人引用就释放)

Bevy 的 `Handle<T>`、Unreal 的 `TAssetPtr`、Unity 的 `AssetReference` 都是这套。Casey 教学版简化:只有 ID + HashMap。

### 3.2 · Linux 系统编程视角

Linux 加载 asset 的两个高级技巧:

1. **mmap**:把 .hha 整个映射到虚拟内存,按指针访问。
   ```rust
   let mmap = unsafe { Mmap::map(&file)? };
   let asset_data = &mmap[offset..offset+size];
   ```
   优点:不需要 `read` syscall,内核按需 page in。缺点:如果 mmap 区域大但访问少,page table 占用高。

2. **`readahead(2)`**:告诉内核"我会读这块",内核预读。
   ```c
   readahead(fd, offset, size);
   ```
   异步预读,不阻塞。Rust 没标准封装,用 libc。

Casey 用 `read` + 显式 `seek`,简单。生产代码 mmap 更好。

### 3.3 · Rust 生态视角

Rust 加载 asset 的 ownership 难题:

- 多个游戏对象引用同一 asset(共享)
- asset 在另一个线程异步加载(并发)
- asset 可能被卸载释放(生命周期)

三种解:

**1. `Rc<LoadedAsset>`(单线程)**

```rust
loaded: HashMap<u32, Rc<LoadedAsset>>
```

简单。引用计数到 0 时 Drop。不能跨线程。

**2. `Arc<LoadedAsset>`(多线程)**

```rust
loaded: HashMap<u32, Arc<LoadedAsset>>
```

原子计数,慢一点。可跨线程。

**3. ID + 全局 storage(Casey 风格)**

```rust
// 不存 asset 指针,每次需要时查
let bitmap = storage.get_bitmap(id)?;
```

无 ownership 复杂度。但每次访问要 HashMap lookup(慢)。

Casey 选 3。游戏代码每次访问都 lookup,HashMap 查询 < 100ns,可以接受。

### 3.4 · 数据结构视角

`HashMap<u32, LoadedAsset>` 性能:

- 查询:平均 O(1),最坏 O(N)(hash collision)
- 内存:每个 entry 几十字节
- cache:每次查询是 random memory access,cache miss 高

替代:

- `Vec<Option<LoadedAsset>>` —— index 直接是 ID,O(1),cache-friendly。要求 ID 是连续整数。
- `SlotMap<u32, LoadedAsset>` —— 代际索引,自动处理删除/重用。

Casey 用 Vec(因为 HH 的 asset ID 就是连续整数)。如果 asset 数 > 10000,SlotMap 更好。

## 5 · 对照与变奏

### 不同引擎的 asset 加载

| 引擎 | 策略 |
|---|---|
| Casey HH | lazy + HashMap |
| Bevy | `Assets<T>` Resource + Handle |
| Unreal | StreamableManager + soft refs |
| Unity | Addressables + AssetReference |
| Godot | ResourceLoader.load_threaded |

所有现代引擎都支持异步加载(避免主线程卡顿)。

### 历史

- **1980s**:全 eager load(内存小,无选择)
- **1990s**:CD-ROM 引入,加载慢,lazy 兴起
- **2000s**:多核普及,streaming 兴起
- **2010s**:SSD 让 streaming 更实用,开放世界大行其道
- **2020s**:DirectStorage / PS5 I/O 让"按需加载到 GPU"成为可能

### mmap 优势场景

| 场景 | mmap | read |
|---|---|---|
| 只读大文件 | 好 | 一般 |
| 频繁随机访问 | 好(已 page in) | 差(每次 syscall) |
| 多进程共享 | 好(COW) | 不行 |
| 写入 | 麻烦(要 msync) | 直接 |

游戏 asset 是只读,mmap 是理想选择。Casey 用 read 教学清楚,生产用 mmap。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 `get_bitmap` 用 `&mut self` 而非 `&self`?有什么办法让它用 `&self`?

**参考解答**:`get_bitmap` 可能要插入 HashMap,需要 `&mut`。改成 `&self` 的方法:

1. **`RwLock<HashMap>`**:读时 shared lock,写时 exclusive lock。运行时开销。
2. **预加载所有 asset**:`loaded` 在 open 时填满,get 只读不写。
3. **分离 storage**:`metadata: &self`(不可变) + `cache: &Mutex<HashMap>`。

生产代码常 1+3。Casey 用 `&mut self` 简单,游戏代码单线程所以够。

### Lv2 · 动手实践

**题**:基于 Day 149 生成的 .hha,写一个加载器,提供 `get_text(id: u32) -> &str`。要求:

1. open .hha
2. 读 header + 索引
3. `get_text(0)` 返回 "hello",`get_text(1)` 返回 "world!!"
4. 第二次调用 `get_text(0)` 不再读盘(从缓存返回)

完成标准:打印两次访问,第二次明显快(或代码中明确没读盘)。

**参考解答**:

```rust
use std::collections::HashMap;
use std::fs::File;
use std::io::{BufReader, Read, Seek, SeekFrom};

struct AssetStorage {
    file: File,
    asset_count: u32,
    asset_offsets: Vec<u64>,
    asset_sizes: Vec<u64>,
    cache: HashMap<u32, String>,
}

impl AssetStorage {
    fn open(path: &str) -> std::io::Result<Self> {
        let mut file = File::open(path)?;
        // 读 header(假设 magic+version 都对)
        let mut b16 = [0u8; 16];
        file.read_exact(&mut b16)?;
        let asset_count = u32::from_le_bytes(b16[8..12].try_into().unwrap());

        let mut offsets = Vec::with_capacity(asset_count as usize);
        let mut sizes = Vec::with_capacity(asset_count as usize);

        for _ in 0..asset_count {
            let mut a = [0u8; 28];  // asset descriptor
            file.read_exact(&mut a)?;
            // 假设结构:u32 type, u32 first_tag, u32 last_tag, u64 offset, u64 size
            let offset = u64::from_le_bytes(a[12..20].try_into().unwrap());
            let size = u64::from_le_bytes(a[20..28].try_into().unwrap());
            offsets.push(offset);
            sizes.push(size);
        }

        Ok(Self { file, asset_count, asset_offsets: offsets, asset_sizes: sizes, cache: HashMap::new() })
    }

    fn get_text(&mut self, id: u32) -> std::io::Result<&str> {
        if !self.cache.contains_key(&id) {
            // 读盘
            self.file.seek(SeekFrom::Start(self.asset_offsets[id as usize]))?;
            let mut buf = vec![0u8; self.asset_sizes[id as usize] as usize];
            self.file.read_exact(&mut buf)?;
            let s = String::from_utf8(buf).map_err(|_| std::io::Error::new(
                std::io::ErrorKind::InvalidData, "not utf8"))?;
            self.cache.insert(id, s);
        }
        Ok(self.cache.get(&id).unwrap())
    }
}

fn main() -> std::io::Result<()> {
    let mut s = AssetStorage::open("test1.hha")?;
    println!("asset[0] = {}", s.get_text(0)?);
    println!("asset[1] = {}", s.get_text(1)?);
    println!("asset[0] again = {}", s.get_text(0)?);  // 走缓存
    Ok(())
}
```

## 8 · Rust / Arch 落地代码

```rust
use std::collections::HashMap;
use std::fs::File;
use std::io::{Read, Seek, SeekFrom};
use std::path::Path;

#[derive(Debug)]
pub enum LoadedAsset {
    Text(String),
    Bitmap { width: u32, height: u32, pixels: Vec<u32> },
    Sound { samples: Vec<f32> },
}

pub struct AssetStorage {
    file: File,
    asset_count: u32,
    descriptors: Vec<(u32, u64, u64)>,  // (type, offset, size)
    cache: HashMap<u32, LoadedAsset>,
    cache_hits: u64,
    cache_misses: u64,
}

impl AssetStorage {
    pub fn open(path: &Path) -> std::io::Result<Self> {
        let mut file = File::open(path)?;

        // 读 header(16 字节)
        let mut header = [0u8; 16];
        file.read_exact(&mut header)?;
        let magic = &header[0..4];
        if magic != b"HHA2" {
            return Err(std::io::Error::new(std::io::ErrorKind::InvalidData, "bad magic"));
        }
        let version = u32::from_le_bytes(header[4..8].try_into().unwrap());
        if version != 2 {
            return Err(std::io::Error::new(std::io::ErrorKind::InvalidData, "bad version"));
        }
        let asset_count = u32::from_le_bytes(header[8..12].try_into().unwrap());

        // 读 asset descriptors
        let mut descriptors = Vec::with_capacity(asset_count as usize);
        for _ in 0..asset_count {
            let mut d = [0u8; 28];
            file.read_exact(&mut d)?;
            let asset_type = u32::from_le_bytes(d[0..4].try_into().unwrap());
            let offset = u64::from_le_bytes(d[12..20].try_into().unwrap());
            let size = u64::from_le_bytes(d[20..28].try_into().unwrap());
            descriptors.push((asset_type, offset, size));
        }

        Ok(Self {
            file, asset_count, descriptors,
            cache: HashMap::new(),
            cache_hits: 0, cache_misses: 0,
        })
    }

    pub fn get(&mut self, id: u32) -> std::io::Result<&LoadedAsset> {
        if self.cache.contains_key(&id) {
            self.cache_hits += 1;
        } else {
            self.cache_misses += 1;
            let (atype, offset, size) = self.descriptors[id as usize];
            self.file.seek(SeekFrom::Start(offset))?;
            let mut buf = vec![0u8; size as usize];
            self.file.read_exact(&mut buf)?;

            let loaded = match atype {
                0 => LoadedAsset::Text(String::from_utf8(buf).map_err(|_|
                    std::io::Error::new(std::io::ErrorKind::InvalidData, "utf8"))?),
                _ => LoadedAsset::Text(format!("<unknown type {}>", atype)),
            };
            self.cache.insert(id, loaded);
        }
        Ok(self.cache.get(&id).unwrap())
    }

    pub fn stats(&self) -> (u64, u64) {
        (self.cache_hits, self.cache_misses)
    }
}

fn main() -> std::io::Result<()> {
    let path = Path::new("test1.hha");
    if !path.exists() {
        eprintln!("run day149 first to generate test1.hha");
        std::process::exit(1);
    }

    let mut s = AssetStorage::open(path)?;
    println!("opened asset file with {} entries", s.asset_count);

    for id in 0..s.asset_count {
        let a = s.get(id)?;
        if let LoadedAsset::Text(t) = a {
            println!("asset[{}] = {:?}", id, t);
        }
    }

    // 再次访问,应走缓存
    for id in 0..s.asset_count {
        let _ = s.get(id)?;
    }

    let (hits, misses) = s.stats();
    println!("cache: {} hits, {} misses", hits, misses);
    Ok(())
}
```

**预期**:

```
asset[0] = "hello"
asset[1] = "world!!"
asset[2] = "rust lang"
cache: 3 hits, 3 misses
```

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
