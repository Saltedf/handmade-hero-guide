## 0 · 为什么要有这一天

让我们先想一个真实场景。你跟着 Handmade Hero 写到 Day 154。你的 asset 系统支持加载单个 .hha 文件——但你**硬编码**了文件路径 `assets/base.hha`。今天你打算发布游戏,你想做两件事:

这件事听起来简单——`ls *.hha` 一行 shell 命令——但要做对、做跨平台、做稳健,涉及很多细节。让我把今天的学习目标列清楚:

**为什么这件事比看起来难**:

我列几个真实工程里出过的坑,你会看到这不是"调一个 API 就行":

- **大小写陷阱**:开发机是 Windows,你测试 `*.hha` 能找到 `BASE.HHA`(NTFS case-insensitive)。移植到 Linux 上,同样代码找不到(`BASE.HHA` 不匹配 `*.hha` 模式)。Casey 在视频里特别强调跨平台必须**显式处理大小写**。
- **Unicode 陷阱**:macOS APFS 默认用 NFD(decomposed)Unicode,即 `é` 存成 `e` + `´` 两个码点。Windows 用 NFC(composed)一个码点。同一文件名跨 OS 复制后名字"看起来一样"但字节不同,glob 失配。
- **symlink 循环**:目录 `a/` 里 symlink 指向 `b/`,`b/` 里 symlink 指回 `a/`。递归遍历要检测这种环,否则无限循环栈溢出。
- **并发修改**:你在遍历时另一个进程删了文件。下一次 `readdir` 可能返回已删除的文件名,后面 `stat` 失败。要处理 `ENOENT`。
- **网络文件系统**:NFS / SMB 网络断了,syscall 卡住或返回 `ESTALE`。要重试或 fail-fast。
- **大目录性能**:一个目录里 10 万文件(某些日志系统、缓存系统),`readdir` 一次性读完要几秒,可能阻塞游戏启动。

这些坑 Casey 在今天和后续几集里都会触及。**今天的目标是先把基本盘做好——能正确枚举、过滤、排序**——后面 Day 165+ 的多线程议题会回来加强健壮性。

## 1 · Casey 今天做了什么

Casey 在 Win32 上写一个 `FindAllHhaFiles(dir, &mut result)` 函数。完整代码骨架:

```c
// 输入:目录路径(如 "assets/")
// 输出:result 数组填满所有匹配 .hha 的文件路径
void FindAllHhaFiles(char *dir, std::vector<char *> *result) {
    // 1. 拼接 pattern:"assets/*.hha"
    char pattern[MAX_PATH];
    snprintf(pattern, sizeof(pattern), "%s/*.hha", dir);

    // 2. 把 UTF-8 pattern 转 UTF-16(Win32 W 系列函数要求宽字符)
    wchar_t wide_pattern[MAX_PATH];
    MultiByteToWideChar(CP_UTF8, 0, pattern, -1, wide_pattern, MAX_PATH);

    // 3. FindFirstFileW:打开查找,返回 handle + 第一个匹配的文件信息
    WIN32_FIND_DATAW fd;
    HANDLE h = FindFirstFileW(wide_pattern, &fd);

    // INVALID_HANDLE_VALUE 表示"没匹配"或"路径错"
    if (h != INVALID_HANDLE_VALUE) {
        do {
            // 4. fd.cFileName 是 UTF-16 文件名(不含路径),转 UTF-8
            char name_utf8[MAX_PATH];
            WideCharToMultiByte(CP_UTF8, 0, fd.cFileName, -1,
                                name_utf8, sizeof(name_utf8), 0, 0);

            // 5. 拼完整路径:"assets/" + name_utf8
            char full_path[MAX_PATH];
            snprintf(full_path, sizeof(full_path), "%s/%s", dir, name_utf8);

            // 6. 加入结果
            result->push_back(strdup(full_path));
        } while (FindNextFileW(h, &fd));  // 7. 下一个匹配

        // 8. 关闭查找 handle(必做,否则 handle 泄漏)
        FindClose(h);
    }
}
```

视频里 Casey 重点讨论几件事:

**`FindFirstFile` 的设计哲学**。Win32 用"打开 handle / 迭代 / 关闭"三段式,和 Unix `opendir`/`readdir`/`closedir` 完全同构。原因是**目录内容可能很多**,不能一次 syscall 全部返回(内核 buffer 有限),必须流式迭代。handle 就是"目录遍历游标"。

**pattern 内置过滤**。`FindFirstFile(L"assets/*.hha", ...)` 直接接受 `*` 通配符,**内核层面**过滤——只返回匹配的文件名,不返回全部再让你筛。这比"列全部然后应用 filter"快得多(对大目录明显)。Linux `opendir` 没这个功能,要自己应用 glob。

**大小写**:Win32 默认 case-insensitive,所以 `*.hha` 也匹配 `BASE.HHA`。Casey 没在视频里纠结这个,但**跨平台代码必须注意**——Linux `readdir` 返回原始名字,大小写敏感,你 filter `*.hha` 不会匹配 `.HHA`。

**Unicode**:Casey 用 W 系列(`FindFirstFileW`,W = wide = UTF-16),不用 A 系列(ANSI,只能表示当前 code page)。**这是 Windows 跨语言项目的标准做法**——任何文件名含非 ASCII 字符(.hha 文件名是中文、阿拉伯文等),A 系列会乱码,W 系统正常。

Casey 最后用 `FindClose(h)` 关闭 handle——这步**不能漏**。每个 `FindFirstFileW` 都打开一个 kernel object(handle),不关会泄漏。Windows 默认每进程 16384 个 handle 上限,泄漏多了系统调用开始失败。

## 2 · 心智模型

### 2.1 类比:电话簿

你想找城市里所有姓"Smith"的人。两种方式:

**方式一,顺序翻电话簿**:从第一页翻到最后一页,看到 Smith 就记下来。慢但完整。这就是 `opendir`/`readdir`——拿一个"目录迭代器",从头到尾过一遍。返回顺序由文件系统决定(ext4 通常按 hash,NTFS 按字母,Btrfs 按 B-tree key)。

**方式二,索引查找**:电话簿已按姓排序,直接翻到 "Smith" 段。快但要预先有索引。**文件系统通常没有"按扩展名排序的索引"**——你看到 `*.hha` 的过滤,实际是 readdir 列出**全部**文件,然后字符串匹配过滤。所以单层 readdir 性能 = O(N)(N = 目录里文件数)。

Win32 的 `FindFirstFile(pattern)` 看起来像"索引查找",其实**内核也是 O(N)**——它内部就是把全部 dirent 读出来再匹配 pattern。所以"pattern 内置过滤"主要是 API 方便性,不是性能优势(对单层小目录差异不大,大目录才有意义)。

**真实性能决定因素**:**每个文件 stat 不 stat**。`dirent.d_type` 在大多数文件系统(ext4、NTFS)直接给出文件类型(regular / dir / symlink),**不需要再 stat**。如果你写 `entry.metadata()`(Rust)或 `stat(path)`(C),会触发额外 syscall——10 万文件就 10 万 syscall,慢成狗。

### 2.2 严谨模型:目录遍历的跨平台 API

让我把每个平台的目录遍历 API 完整列出来,你能看清它们的同构和差异。

#### POSIX(`opendir` / `readdir` / `closedir`)

```c
#include <dirent.h>

DIR *d = opendir("/path/to/dir");
if (!d) { perror("opendir"); exit(1); }

struct dirent *e;
// readdir 返回 NULL 表示遍历完(或出错,要看 errno)
while ((e = readdir(d)) != NULL) {
    // e->d_name:文件名(不含路径),最长 NAME_MAX(255)字节
    // e->d_ino:inode 号
    // e->d_type:文件类型,DT_REG / DT_DIR / DT_LNK / DT_UNKNOWN
    //           (DT_UNKNOWN 出现在某些文件系统,要 fallback 到 stat)
    printf("%s (ino=%lu, type=%d)\n", e->d_name, e->d_ino, e->d_type);
}

closedir(d);
```

**关键细节**:
- `readdir` 不是 thread-safe(返回的 `dirent *` 指向静态 buffer)。多线程用 `readdir_r`(已废弃)或自己加锁。
- `readdir` 是 buffered 的——内核一次给一批 dirent,libc 缓冲。大批量遍历比每次 syscall 快。
- `d_type == DT_UNKNOWN` 时必须 `stat()` 才能确定类型(某些文件系统如 ReiserFS、某些 FUSE 不填 d_type)。
- `readdir` 顺序**未定义**。多人游戏要确定性必须自己 sort。

#### Win32(`FindFirstFileW` / `FindNextFileW` / `FindClose`)

```c
#include <windows.h>

WIN32_FIND_DATAW fd;  // W = UTF-16
HANDLE h = FindFirstFileW(L"C:\\path\\to\\dir\\*", &fd);
//                                                  ^^^^
// 必须有通配符,光给目录路径会失败

if (h == INVALID_HANDLE_VALUE) {
    // GetLastError() 看错——ERROR_FILE_NOT_FOUND 表示没匹配
    DWORD err = GetLastError();
    if (err != ERROR_FILE_NOT_FOUND) {
        // 真错(权限、路径不存在)
    }
    return;
}

do {
    // fd.cFileName:UTF-16 文件名(不含路径),最长 MAX_PATH(260)wchars
    // fd.dwFileAttributes:FILE_ATTRIBUTE_DIRECTORY / HIDDEN / ...
    // fd.ftCreationTime / ftLastWriteTime:FILETIME 结构
    // fd.nFileSizeHigh / nFileSizeLow:文件大小(64-bit 拆两半)
    wprintf(L"%s (attr=0x%x)\n", fd.cFileName, fd.dwFileAttributes);
} while (FindNextFileW(h, &fd));

// FindNextFile 返回 0 表示遍历完(或出错,看 GetLastError)
// ERROR_NO_MORE_FILES 是正常结束

FindClose(h);  // 必做
```

**关键细节**:
- pattern 是**必填**——`L"C:\\dir"` 失败,必须 `L"C:\\dir\\*"` 或 `L"C:\\dir\\*.hha"`。
- `MAX_PATH = 260` 是 Windows 历史 8.3 时代的限制。新版 Windows 10+ 可启用 long path(组策略 / manifest),上限 32767。
- W 系列用 UTF-16,**任何非 ASCII 文件名都必须用 W**。A 系列(ANSI)在中文 Windows 用 GBK,英文 Windows 用 CP1252,跨机器移植会乱码。
- `dwFileAttributes` 直接给出 `FILE_ATTRIBUTE_DIRECTORY` 等,**不用 stat**。

#### Rust(`std::fs::read_dir`)

```rust
use std::fs;

let entries: Vec<_> = fs::read_dir("/path/to/dir")?
    .filter_map(|e| e.ok())      // 跳过错误条目(权限、并发删除)
    .collect();

for entry in entries {
    let path = entry.path();     // 完整路径(PathBuf)
    let name = entry.file_name(); // 文件名(OsString,跨平台字符串)
    let metadata = entry.metadata()?; // 注意:这会触发 stat
    let file_type = entry.file_type()?; // 用 dirent.d_type,不 stat
    println!("{:?} {:?} {:?}", path, file_type, metadata.len());
}
```

**关键细节**:
- `read_dir` 跨平台——Linux 内部 `opendir` + `getdents64`,Windows 内部 `FindFirstFileW` + `FindNextFileW`。
- `entry.file_type()` 用 dirent.d_type,**不 stat**(快)。`entry.metadata()` 才 stat(慢,要文件大小、时间戳)。
- `entry.file_name()` 返回 `OsString`——Rust 跨平台字符串类型。Linux 是字节序列,Windows 是 UTF-16,Rust 用 `OsStr` 抽象。
- 默认**非递归**。要递归用 `walkdir` crate。

### 2.3 Glob 模式:从 shell 到 libc

`*.hha` 不是 regex——它是 **glob**,一种简化的模式语言。Glob 比 regex 简单,语义明确,适合文件名匹配。

| 模式 | 含义 | 例子 |
|---|---|---|
| `*` | 任意字符(不含 `/`) | `*.hha` 匹配 `base.hha`,不匹配 `dir/base.hha` |
| `?` | 单字符 | `base?.hha` 匹配 `base1.hha`,不匹配 `base.hha` |
| `[abc]` | 集合中任一字符 | `base[12].hha` 匹配 `base1.hha` 或 `base2.hha` |
| `[a-z]` | 范围 | `base[0-9].hha` 匹配 `base0` 到 `base9` |
| `[!abc]` | 否定集合 | `base[!0-9].hha` 匹配 `baseA.hha`,不匹配数字 |
| `**` | 任意层级(递归) | `**/*.hha` 匹配任意深度的 .hha |

**Glob 在三个地方出现**:

1. **Shell 展开**:你在 shell 输 `ls *.hha`,**shell 自己**(bash/zsh)展开 `*.hha` 为匹配的文件名,再传给 `ls`。`ls` 收到的可能是 `ls base.hha music.hha`,不是 `ls *.hha`。这是为什么 `echo *` 也能工作——echo 不懂 glob,shell 替它展开。
2. **libc glob(3)**:C 标准库提供 `glob()` 函数,程序内部也能用 glob。
3. **Win32 FindFirstFile**:`FindFirstFile` pattern 内置 glob 解析。`?` 和 `*` 支持,`[abc]` 部分支持。

**Rust `glob` crate** 提供 Rust 版:

```rust
use glob::glob;

// 递归找所有 .hha
for entry in glob("assets/**/*.hha").expect("Failed to read glob pattern") {
    match entry {
        Ok(path) => println!("found: {}", path.display()),
        Err(e) => eprintln!("error: {}", e),
    }
}
```

`glob` crate 内部用 `walkdir`,把 `**` 翻译成递归。

### 2.4 排序与确定性

`readdir` / `FindFirstFile` 返回顺序**由文件系统决定**:

- **ext4**:按目录 hash(默认 half-MD4),完全无规律。
- **NTFS**:按字母顺序(默认),但短文件名优先(8.3 兼容)。
- **Btrfs**:按 B-tree key,通常是 inode 号顺序。
- **APFS**(macOS):按 B-tree,inode 顺序。

**为什么顺序重要**:

- **多人游戏**:服务器和客户端枚举同一目录,得到不同顺序,加载的 asset 顺序不同,内存地址不同,浮点误差累积导致 desync。
- **测试**:你的测试 `assert_eq!(found_files, expected)`,顺序不确定就 flaky。
- **资源 precedence**:`base.hha` 必须先加载,`patch.hha` 后加载(覆盖 base)。如果随机顺序,patch 可能先加载被 base 覆盖。

**解决**:枚举后必排序。Casey 在视频里强调这点——`qsort` by name。

```rust
let mut entries: Vec<_> = fs::read_dir(dir)?
    .filter_map(|e| e.ok())
    .map(|e| e.path())
    .collect();
entries.sort();  // PathBuf 实现 Ord,按 Unicode codepoint 排
```

### 2.5 性能:大目录、stat 陷阱、并行

10 万文件的目录(极端案例:浏览器缓存、日志归档)遍历时间:

| 操作 | 时间 |
|---|---|
| 单层 readdir(只用 d_type) | ~50 ms |
| 递归 walkdir | ~500 ms |
| 每文件 stat 取 metadata | ~5 s(10 万 syscall) |
| 并行 walkdir(jwalk,8 核) | ~150 ms |

**避免 stat 的方法**:用 `dirent.d_type`(POSIX)或 `dwFileAttributes`(Win32)判断类型,这些字段随 readdir 返回,**不需要额外 syscall**。

**Rust 陷阱**:`entry.metadata()` 在 Linux 上调 `stat`,在 Windows 上调 `GetFileInformationByHandle`(也是 syscall)。如果只想要文件类型,用 `entry.file_type()`,它从 dirent 读,**不 syscall**。

**并行加速**:`jwalk` crate 用 rayon 并行遍历。10 万文件 8 核能加速 3-5x。适合启动时扫描 asset 目录。

### 2.6 符号链接:循环、相对、绝对

Symlink(符号链接)是文件系统的"快捷方式"。`mods/extra.hha` 可以 symlink 到 `/home/user/extra.hha`,遍历 `mods/` 时看到这个名字但实际文件在别处。

**三种处理策略**:

1. **跟随 symlink**(follow):遍历时把 symlink 解析到目标,继续递归。`walkdir` 用 `follow_links(true)`。
2. **不跟随**(default):symlink 当普通文件列出,不递归进去。Rust `read_dir` / `walkdir` 默认。
3. **检测循环**:如果跟随,要检测 `a → b → a` 这种环。用 inode 集合去重。`walkdir` 用 `same_file_system` 选项。

**Asset 系统的选择**:**默认不跟随**。玩家 symlink 一个文件到 `/dev/zero` 或 `/proc/self/mem` 是攻击向量。Asset loader 应该**拒绝 symlink**,只加载真实文件。Casey 在 Day 165 多线程议题里会讨论安全相关。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏 asset 自动发现的典型用法:

```rust
use std::path::{Path, PathBuf};

/// 找目录下所有 .hha 文件(非递归),按文件名排序
pub fn find_asset_files(root: &Path) -> std::io::Result<Vec<PathBuf>> {
    let mut files: Vec<_> = std::fs::read_dir(root)?
        .filter_map(|e| e.ok())
        .map(|e| e.path())
        .filter(|p| {
            // 只接受 .hha 扩展名(case-insensitive,跨平台)
            p.extension()
                .map_or(false, |x| x.to_ascii_lowercase() == "hha")
        })
        .filter(|p| {
            // 拒绝 symlink(安全)
            p.symlink_metadata()
                .map(|m| !m.file_type().is_symlink())
                .unwrap_or(false)
        })
        .collect();
    files.sort();  // 确定顺序
    Ok(files)
}

fn main() -> std::io::Result<()> {
    let asset_files = find_asset_files(Path::new("assets/"))?;
    for f in &asset_files {
        println!("found: {}", f.display());
    }
    Ok(())
}
```

工业游戏引擎的 asset 自动发现还要处理:

- **AssetBundle / Package**:Unity 的 Addressables、Unreal 的 .uasset,都是"目录里找 .meta 文件 → 解析 → mount"。
- **Mod 加载顺序**:Skyrim 的 mod loader 要按依赖关系排序(load order)。这通常通过 mod 自己的 .toml / .json 描述依赖。
- **Hot reload**:开发时改 asset,游戏自动重载。要文件系统 watch(Linux inotify / Win32 ReadDirectoryChangesW / Rust `notify` crate)。

### 3.2 · 🐧 Linux 系统编程视角

Linux 目录遍历的底层 syscall 是 `getdents64`(不是 readdir——readdir 是 libc 包装)。

```c
// getdents64 直接返回多个 dirent 在一个 buffer 里
#include <dirent.h>
#include <fcntl.h>
#include <sys/syscall.h>

struct linux_dirent64 {
    ino64_t        d_ino;    /* 64-bit inode number */
    off64_t        d_off;    /* 64-bit offset to next structure */
    unsigned short d_reclen; /* Size of this dirent */
    unsigned char  d_type;   /* File type */
    char           d_name[]; /* Filename (null-terminated) */
};

int fd = open("/path", O_DIRECTORY | O_RDONLY);
char buf[8192];
ssize_t n;
while ((n = syscall(SYS_getdents64, fd, buf, sizeof(buf))) > 0) {
    char *p = buf;
    while (p < buf + n) {
        struct linux_dirent64 *entry = (struct linux_dirent64 *)p;
        printf("%s\n", entry->d_name);
        p += entry->d_reclen;  // 跳到下一个
    }
}
```

**为什么不用 readdir?** 因为 readdir 单线程慢。**io_uring**(Linux 5.1+)能批量发 readdir 请求,大目录遍历快几倍。Rust `io-uring` crate 包装。

**strace 观察 readdir 的 syscall**:

```bash
# 跑你的程序,trace 文件相关 syscall
strace -e trace=openat,getdents64,close ./target/release/day154 2>&1 | tail -30

# 典型输出:
# openat(AT_FDCWD, "/path", O_RDONLY|O_DIRECTORY) = 3
# getdents64(3, /* 25 entries */, 8192) = 968
# getdents64(3, /* 0 entries */, 8192) = 0  ← 表示读完
# close(3) = 0
```

**Linux 文件名规则**:

- 文件名只能含 `/`(目录分隔符)和 `\0`(C 字符串终止符)以外的任意字节。**任何 8-bit 字节序列都合法**(包括非 UTF-8)。这意味着 Linux 上文件名可能是**无效 UTF-8**,Python / Java 处理会失败,Rust 用 `OsStr` 处理。
- 最长 `NAME_MAX = 255` 字节(不是字符!)。一个中文 UTF-8 是 3 字节,所以纯中文文件名最长 85 字符。
- 路径最长 `PATH_MAX = 4096` 字节。

### 3.3 · 🦀 Rust 生态视角

Rust 目录遍历的选项全景:

- **`std::fs::read_dir`** —— 标准库,单层,跨平台。简单需求用这个。
- **`walkdir` crate** —— 递归,可控顺序,处理 symlink 循环。工业代码首选。
- **`glob` crate** —— glob 模式匹配,内部用 walkdir。API 简洁。
- **`ignore` crate** —— gitignore-aware 遍历。`ripgrep` 内部用它,跳过 .gitignore 里的文件。
- **`jwalk` crate** —— 并行遍历,用 rayon。大目录快。
- **`notify` crate** —— 文件系统事件监听(inotify / kqueue / ReadDirectoryChangesW)。hot reload 用。

工业代码常用模式:

```rust
use walkdir::WalkDir;
use ignore::WalkBuilder;

// 简单递归
for entry in WalkDir::new("assets").follow_links(true) {
    let entry = entry?;
    if entry.path().extension() == Some("hha".as_ref()) {
        println!("found: {}", entry.path().display());
    }
}

// gitignore-aware + 并行
let walker = WalkBuilder::new("src")
    .hidden(true)          // 跳过隐藏文件
    .git_ignore(true)      // 跳过 .gitignore 里的文件
    .git_global(true)      // 跳过 global gitignore
    .threads(8)            // 8 线程
    .build_parallel();
for entry in walker {
    let entry = entry?;
    println!("{}", entry.path().display());
}
```

### 3.4 · 错误处理视角

目录遍历的错误分类:

| 错误 | 处理策略 |
|---|---|
| `NotFound` —— 路径不存在 | 启动时致命错误,panic 或 exit |
| `NotADirectory` —— 路径是文件不是目录 | 同上,编程错误 |
| `PermissionDenied` —— 没读权限 | 跳过该条目,继续 |
| `StaleFileHandle`(NFS) | 网络断了,重试或退出 |
| `ENOENT`(并发删除) | 跳过,继续 |
| `ENAMETOOLONG` | 跳过,记录日志 |
| `EIO`(磁盘错) | 致命,告知用户 |

游戏代码的策略:**NotADirectory/NotFound 报错退出,其他跳过继续**。Rust 用 `filter_map(|e| e.ok())` 简单跳过所有错误。

```rust
fn robust_read_dir(dir: &Path) -> Vec<PathBuf> {
    let mut result = Vec::new();
    match std::fs::read_dir(dir) {
        Ok(entries) => {
            for entry in entries {
                match entry {
                    Ok(e) => result.push(e.path()),
                    Err(e) => {
                        // 单个条目失败,跳过
                        eprintln!("warn: skipping entry in {}: {}", dir.display(), e);
                    }
                }
            }
        }
        Err(e) if e.kind() == std::io::ErrorKind::NotFound => {
            eprintln!("warn: directory not found: {}", dir.display());
        }
        Err(e) => {
            eprintln!("error: cannot read {}: {}", dir.display(), e);
            std::process::exit(1);
        }
    }
    result
}
```

### 不同 OS 的目录遍历差异

| | Linux ext4 | Windows NTFS | macOS APFS |

### Lv1 · 概念辨析

**题**:`*.hha` 在 Windows 上匹配 `BASE.HHA` 吗?在 Linux 上呢?

**参考解答**:Windows NTFS 默认 case-insensitive,`*.hha` 匹配 `BASE.HHA`、`Base.Hha` 等。Linux ext4 默认 case-sensitive,`*.hha` 只匹配全小写 `.hha`。

跨平台代码要 case-insensitive 比较扩展名,或显式匹配两种(`*.hha` 和 `*.HHA`)。Rust `Path::extension()` 保留原 case,需要 `to_lowercase()` 比较。

### Lv2 · 动手实践

**题**:用 `std::fs::read_dir` 扫描 `/tmp` 下所有 `.txt` 文件,排序后打印。

**参考解答**:

```rust
use std::fs;
use std::path::PathBuf;

fn find_txt(root: &str) -> Vec<PathBuf> {
    let mut files: Vec<_> = fs::read_dir(root)
        .into_iter()
        .filter_map(|e| e.ok())
        .filter_map(|e| e.ok())
        .filter(|e| e.path().extension().map_or(false, |x| x == "txt"))
        .map(|e| e.path())
        .collect();
    files.sort();
    files
}

fn main() {
    for f in find_txt("/tmp") {
        println!("{}", f.display());
    }
}
```

## 8 · Rust / Arch 落地代码

```rust
use std::fs;
use std::path::{Path, PathBuf};

/// 找目录下所有 .hha 文件(非递归),按文件名排序
pub fn find_hha_files(dir: &Path) -> std::io::Result<Vec<PathBuf>> {
    let mut files: Vec<_> = fs::read_dir(dir)?
        .filter_map(|e| e.ok())
        .map(|e| e.path())
        .filter(|p| p.extension().map_or(false, |x| x == "hha"))
        .collect();
    files.sort();
    Ok(files)
}

/// 递归查找(用 walkdir 风格手写)
pub fn find_hha_recursive(dir: &Path) -> std::io::Result<Vec<PathBuf>> {
    let mut result = Vec::new();
    let mut stack = vec![dir.to_path_buf()];
    while let Some(d) = stack.pop() {
        for entry in fs::read_dir(&d)? {
            let entry = entry?;
            let path = entry.path();
            let file_type = entry.file_type()?;
            if file_type.is_dir() {
                stack.push(path);
            } else if file_type.is_file() {
                if path.extension().map_or(false, |x| x == "hha") {
                    result.push(path);
                }
            }
            // 忽略 symlink(避免循环)
        }
    }
    result.sort();
    Ok(result)
}

fn main() -> std::io::Result<()> {
    let dir = Path::new(".");

    println!("non-recursive:");
    for f in find_hha_files(dir)? {
        println!("  {}", f.display());
    }

    println!("recursive:");
    for f in find_hha_recursive(dir)? {
        println!("  {}", f.display());
    }
    Ok(())
}
```
