
# Day 162 · 字体入门

## 2 · 心智模型

### 类比:刻印章

每个汉字一个印章,印章刻了字的轮廓。要"打印"这个字:

1. 选印章(选 glyph)
2. 调大小(缩放)
3. 蘸墨(决定颜色)
4. 按(栅格化到像素)

数字字体就是把每个"印章"用数学曲线描述。屏幕显示时按当前字号"盖"。

### 严谨模型:TrueType

`.ttf` 文件是二进制容器,里面多个 table:

| Table | 内容 |
|---|---|
| `cmap` | Unicode → glyph index 映射 |
| `glyf` | glyph 轮廓数据(Bezier) |
| `head` | 字体元数据(units per em) |
| `hmtx` | horizontal metrics(advance width) |
| `kern` | kerning 字母对 |
| `loca` | glyph 数据索引 |
| `maxp` | 最大参数 |
| `name` | 字体名称(可读) |
| `post` | PostScript 名字 |
| `OS/2` | OS/2 metrics |

每个 table 是 TLV(type-length-value)。Casey 在 Day 163+ 用 stb 解析,自己手写要细致。

### Glyph 轮廓

一个 glyph 由若干 **contour**(闭合曲线)组成,每条 contour 由若干 segment:

- **on-curve point**:轮廓上的点
- **off-curve point**:Bezier 控制点

3 个连续点(P0 on, P1 off, P2 on)定义一个二次 Bezier 曲线:

```
B(t) = (1-t)² P0 + 2(1-t)t P1 + t² P2
```

t ∈ [0, 1],从 P0 到 P2 的曲线,P1 控制"鼓"的方向。

### 字体度量(metrics)

- **em square**:字体设计空间,通常 1000 或 2048 units
- **ascender**:基线以上的最高点
- **descender**:基线以下的最低点
- **line gap**:行间额外空间
- **advance width**:当前 glyph 占的水平宽度(光标前进多少)

字号 12 像素:1 em = 12 px。所以 advance width = (glyph_advance_in_em * 12) px。

### 栅格化(光栅化)

把 Bezier 曲线变成像素:

1. **采样**:对每条曲线在 t ∈ [0, 1] 上采样 N 点,近似为多边形
2. **扫描线**:对每条水平扫描线,算与多边形的交点
3. **填充**:扫描线内像素涂色(或带 anti-aliasing 加权)

这就是 polygon rasterization,游戏光栅化器也是这思路。

**Anti-aliasing**:边缘像素不简单 on/off,按覆盖面积加权。Coverage = 像素内多边形覆盖的比例。

**Subpixel rendering**:针对 LCD 屏,把每像素当 RGB 3 子像素,提高水平分辨率(ClearType)。

### Hinting

小字号(12 px)下 Bezier 栅格化会失真(2 像素宽的"|"可能变成 1 或 3)。**hinting** 是字体设计师手写的指令,告诉栅格化器"这种字号下,把这条线对齐到 2 像素"。

TrueType 的 hinting 是完整的字节码解释器,字体可以内嵌程序。

工业级 FreeType 支持 hinting。Casey 用 stb 默认不开(简单)。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏字体的几种方案:

1. **Bitmap font**:每个字预栅格化成 PNG,运行时 blit。最简单,字大不好(锯齿),不灵活(改字号要重生)
2. **TrueType + runtime 栅格化**:FreeType / stb_truetype。灵活,中等复杂
3. **SDF(Signed Distance Field)**:预栅格化成 SDF texture,shader 运行时算像素。任意缩放都锐利。**现代游戏标准**——Valve 2007 论文
4. **GPU 标量**:用 compute shader 直接栅格化 Bezier。极快,复杂

工业引擎支持 1 + 3。Casey 教学用 2(经典思路)。

### 3.2 · 图形学视角

字体渲染在图形学里两个位置:

- **CPU 栅格化**(FreeType):把 glyph 变成像素 buffer,运行时上传 GPU 当 texture
- **GPU 栅格化**:glyph 轮廓上传 GPU,shader 算每个像素覆盖

GPU 路径适合动态字号(每帧重算)。CPU 路径适合 cache 后多帧用。

### 3.3 · Rust 生态视角

Rust 字体 crate:

- **`rusttype`**:纯 Rust,简化 FreeType
- **`ab_glyph`**:rusttype 继任,纯 Rust
- **`fontdb`**:字体数据库
- **`swash`**:复杂文字 shaping(shaping + 栅格化)
- **`freetype-rs`**:FreeType binding

使用:

```rust
use ab_glyph::{Font, FontRef, Glyph};

let font_data = std::fs::read("DejaVuSans.ttf")?;
let font = FontRef::try_from_slice(&font_data)?;

// 拿 'A' 的 glyph id
let glyph_id = font.glyph_id('A');

// 栅格化成像素
let glyph = glyph_id.with_scale_and_position(24.0, ab_glyph::point(0.0, 0.0));
if let Some(outline) = font.outline_glyph(glyph) {
    let bounds = outline.px_bounds();
    let mut pixels = vec![0u8; (bounds.width() * bounds.height()) as usize];
    outline.draw(|x, y, coverage| {
        pixels[(y * bounds.width() as u32 + x) as usize] = (coverage * 255.0) as u8;
    });
}
```

### 3.4 · 国际化视角

不同语言文字:

- **拉丁**(英文 / 法文):少量字母(26 + 变种),左到右
- **中文**:几万汉字,左到右(横排)或上到下(竖排)

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 SDF(signed distance field)字体在任意缩放下都锐利,而 bitmap 不行?

**参考解答**:SDF texture 存的是**每个像素到字形边缘的距离**(signed:内部正、外部负)。渲染时 shader 读 SDF 值,和阈值比较决定像素是字内还是字外。

任意缩放时,shader 在 SDF 上插值,得到平滑的距离场。阈值化后是平滑边缘——无论缩放多少,边缘都是 SDF = 0 的等值线,看起来一样锐利。

bitmap 是已栅格化的像素,放大时每个像素变大方块(锯齿),缩小会丢细节。SDF 是数学表示,任意缩放都正确。

### Lv2 · 动手实践

**题**:用 `ab_glyph` 渲染字母 "A" 到 16×16 grayscale bitmap,打印 ASCII art。

**参考解答**:

```rust
// Cargo.toml: ab_glyph = "0.2"
use ab_glyph::{Font, FontRef, GlyphId};

fn main() {
    let data = std::fs::read("/usr/share/fonts/TTF/DejaVuSans.ttf")
        .or_else(|_| std::fs::read("/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf"))
        .expect("font not found");
    let font = FontRef::try_from_slice(&data).unwrap();

    let glyph_id: GlyphId = font.glyph_id('A');
    let glyph = glyph_id.with_scale(16.0);
    if let Some(outline) = font.outline_glyph(glyph) {
        let bounds = outline.px_bounds();
        outline.draw(|x, y, coverage| {
            if x == 0 {
                println!();
            }
            let c = if coverage > 0.7 { '#' }
                else if coverage > 0.3 { '*' }
                else if coverage > 0.1 { '.' }
                else { ' ' };
            print!("{}", c);
        });
        println!();
        println!("bounds: {:?}", bounds);
    }
}
```

## 8 · Rust / Arch 落地代码

```rust
// Cargo.toml: ab_glyph = "0.2"

use ab_glyph::{Font, FontRef, GlyphId, point};

fn find_font() -> Vec<u8> {
    let candidates = [
        "/usr/share/fonts/TTF/DejaVuSans.ttf",
        "/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf",
        "/usr/share/fonts/noto/NotoSans-Regular.ttf",
        "/usr/share/fonts/liberation-fonts/LiberationSans-Regular.ttf",
    ];
    for p in &candidates {
        if let Ok(d) = std::fs::read(p) { return d; }
    }
    panic!("no font found");
}

fn main() {
    let data = find_font();
    let font = FontRef::try_from_slice(&data).expect("parse font");

    println!("font family: {:?}", font.name());
    println!("units per em: {}", font.units_per_em());

    // 渲染 'A',字号 16
    let glyph_id: GlyphId = font.glyph_id('A');
    let glyph = glyph_id.with_scale_and_position(16.0, point(0.0, 16.0));

    if let Some(outlined) = font.outline_glyph(glyph) {
        let bounds = outlined.px_bounds();
        println!("bounds: {:?}", bounds);

        let w = bounds.width() as usize;
        let h = bounds.height() as usize;
        println!("size: {}x{}", w, h);

        let mut pixels = vec![0f32; w * h];
        outlined.draw(|x, y, cov| {
            pixels[(y as usize) * w + x as usize] = cov;
        });

        // ASCII art
        let scale_x = 2;  // 字符比像素窄,放大显示
        for y in 0..h {
            for sx in 0..scale_x {
                let _ = sx;
                let mut line = String::new();
                for x in 0..w {
                    let c = pixels[y * w + x];
                    let ch = if c > 0.7 { '#' }
                        else if c > 0.4 { '*' }
                        else if c > 0.15 { '.' }
                        else { ' ' };
                    line.push(ch);
                }
                println!("{}", line);
            }
        }
    }

    // kerning:AV vs A_V
    let a_id = font.glyph_id('A');
    let v_id = font.glyph_id('V');
    let advance_a = font.glyph_bounds(a_id.with_scale(24.0)).unwrap().width();
    println!("advance A: {:.1}", advance_a);
}
```

### A.4 性能优化的工业实践

工业性能优化的层次:

**L1:算法选择**
- O(N²) → O(N log N) → O(N)
- 选择合适数据结构

**L2:数据布局**
- AoS vs SoA
- Cache line alignment
- Branchless code

**L3:并行化**
- multi-threading
- SIMD(单指令多数据)
- GPU compute

**L4:架构调整**
- streaming 替代 load-all
- 增量计算替代全量

**L5:硬件利用**
- GPU 加速
- RTX 核心
- NPU(AI 加速)

每层收益递减但难度递增。Casey 的 phase-4 主要在 L1-L3。

### A.9 Voxel / 渲染相关代码示例

让我提供一个具体的 Rust 代码示例,综合 phase-4 的概念:

```rust
use std::sync::Arc;
use std::collections::HashMap;
use std::sync::RwLock;

// Asset storage(引用计数 + 分桶锁)
pub struct AssetStorage<T> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> T + Send + Sync>,
}

impl<T> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self 
    where F: Fn(u32) -> T + Send + Sync + 'static {
        let num_shards = 16;
        let mut shards = Vec::with_capacity(num_shards);
        for _ in 0..num_shards {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self {
            shards,
            loader: Box::new(loader),
        }
    }
    
    pub fn get(&self, id: u32) -> Arc<T> {
        let shard_idx = (id as usize) % self.shards.len();
        
        // 读路径
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(asset) = shard.get(&id) {
                return Arc::clone(asset);
            }
        }
        
        // 慢路径:加载
        let asset = Arc::new((self.loader)(id));
        
        // 写路径
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&asset));
        Arc::clone(entry)
    }
}

// 用法
fn main() {
    let storage: AssetStorage<String> = AssetStorage::new(|id| {
        format!("texture_{}.png", id)
    });
    
    let a = storage.get(1);
    let b = storage.get(1);
    assert!(Arc::ptr_eq(&a, &b));  // 同一 Arc
}
```

这是工业级 asset storage 的 Rust 骨架——分桶 RwLock + Arc + 加载闭包。

### A.10 内存管理的最佳实践

Phase 4 涉及大量内存管理。最佳实践:

**1. Ownership 清晰**:
- 每资源有明确 owner
- Owner drop → 资源释放
- 不共享 ownership(避免 cycle)

**2. Arena for 临时数据**:
```rust
use bumpalo::Bump;

let arena = Bump::new();
let temp_data: &mut [u32] = arena.alloc_slice_fill_with(1000, |_| 0);
// arena drop → temp_data 自动释放
```

**3. Arc for 长期共享**:
```rust
let shared = Arc::new(ExpensiveResource::new());
let cloned = Arc::clone(&shared);
// 两个 owner 都 drop → resource 释放
```

**4. Weak for cache**:
```rust
let weak: Weak<Resource> = Arc::downgrade(&strong);
// cache 不阻止 strong 释放
if let Some(strong) = weak.upgrade() {
    // 还在用
} else {
    // 已释放
}
```

**5. Pool for 高频 alloc**:
```rust
let pool = ObjectPool::new(|| ExpensiveObject::new());
let obj = pool.acquire();  // 复用
// ...
pool.release(obj);  // 不 drop,放回 pool
```

工业 Rust 代码综合用这些模式。
