# Day 137 · 匹配周期性标签

> Day 136 的多 tag 系统升级到"周期性":动画帧标签 "walk_0" / "walk_1" / ... / "walk_7" 自动循环。今天给 tag 查询加一个"周期匹配"模式,让游戏代码不用关心当前帧是第几帧,只需说"给我下一帧 walk 动画"。

## 0 · 为什么要有这一天

游戏角色的动画是一系列连续帧。比如玩家走路动画有 8 帧:`walk_0` / `walk_1` / ... / `walk_7`。播放时按顺序循环:

```
frame 0: walk_0
frame 1: walk_1
...
frame 7: walk_7
frame 8: walk_0  ← 绕回
frame 9: walk_1
...
```

Day 136 的 tag 系统可以这样查:
```rust
let frame = store.lookup(&format!("walk_{}", current_frame));
```

但游戏代码每帧都要拼字符串(`format!("walk_{}"`)——慢且啰嗦。

更糟糕的是,如果美工加了新动画 "walk" 共 10 帧(从 walk_0 到 walk_9),游戏代码也要改("8" 改成 "10")。耦合。

**今天的核心**:加周期性 tag 匹配。游戏代码:

```rust
let frame = store.lookup_periodic("walk", current_frame);
// 内部自动取模:walk_0, walk_1, ..., walk_N, walk_0, ...
```

`store` 知道 "walk" 动画有多少帧(查询反向索引),自动绕回。游戏代码只关心 "current_frame" 一个变量,加新帧不用改代码。

这就是动画系统的最简实现。商业引擎(Unity Mecanim、Unreal AnimGraph)更复杂(状态机、混合、IK),但底层都是"周期性 tag / index 匹配"。

心理锚点:做完今天你能(1)在你的引擎里实现 `lookup_periodic(tag, index)`;(2)用 Day 130 的 wrap 概念解释为什么周期匹配等价于模运算;(3)实现一个最简 sprite 动画系统;(4)说出 sprite 动画 vs骨骼动画的差别。

## 1 · Casey 今天做了什么

Casey 在 Day 136 的多 tag 系统上加周期性匹配:

1. tag 格式约定:`"anim_frame_N"`(N 从 0 开始)
2. 实现 `lookup_periodic(base_tag, frame_index) -> AssetId`:`frame_index` 自动绕回 [0, N)
3. 维护 `anim_lengths: HashMap<String, u32>` 记录每个动画的帧数
4. 游戏代码:`let frame = store.lookup_periodic("walk", current_frame); current_frame += 1;`
5. 渲染器拿到 AssetId 渲染对应 bitmap

Casey 还做了一个优化:**动画速度**(每秒 N 帧)和**游戏帧率**(60 FPS)解耦。current_frame 不是每游戏帧 +1,而是按动画速度推进(可能是 0.5 = 每 2 游戏帧 +1)。

## 2 · 心智模型

### 类比:八音盒 vs 视频播放器

**Day 136 普通 tag** 像八音盒:你转动凸轮,每个凸轮位置对应一个固定音。位置 = tag。

**周期 tag** 像视频播放器:你按播放,视频循环播放。你给个"播放头位置"(current_frame),播放器自动取对应帧。

视频播放器的"绕回"等价于 Day 130 的 wrap,也等价于 Day 126 ring buffer 的 head 推进——都是**模运算**。

### 严谨原理:周期匹配

```rust
impl<T> AssetPool<T> {
    fn lookup_periodic(&self, base_tag: &str, frame: u32) -> Option<AssetId<T>> {
        // 找 base_tag 对应的帧数 N
        let n = self.anim_lengths.get(base_tag)? as usize;
        if n == 0 { return None; }
        // frame 自动绕回 [0, N)
        let wrapped = (frame as usize) % n;
        let full_tag = format!("{}_{}", base_tag, wrapped);
        // 内部查 reverse[full_tag]
        let ids = self.reverse.get(&full_tag)?;
        ids.first().map(|&id| AssetId { id, _ty: PhantomData })
    }
}
```

关键操作:`frame % N`。这正是 Day 130 的 `wrap_uv(u) = u - floor(u)`,不过是整数版。

### 动画速度解耦

游戏帧率 60 FPS(每帧 16.67ms)。动画速度可能 10 FPS(每帧 100ms)。怎么同步?

```rust
struct AnimationPlayer {
    current_frame: f32,  // 浮点 frame!
    speed: f32,           // 帧 / 秒
}

impl AnimationPlayer {
    fn update(&mut self, dt: f32) {
        self.current_frame += self.speed * dt;
    }

    fn get_current_frame_id(&self, store: &AssetPool<Bitmap>) -> Option<AssetId<Bitmap>> {
        let int_frame = self.current_frame.floor() as u32;
        store.lookup_periodic("walk", int_frame)
    }
}
```

`current_frame` 是 f32,可以 0.5(表示在 frame 0 和 1 之间,后面 Day 350+ 加帧间插值)。`speed` 是动画速度(帧/秒)。

游戏循环:
```rust
loop {
    let dt = 0.0167;  // 60 FPS
    player.update(dt);
    let frame_id = player.get_current_frame_id(&store).unwrap();
    render(store.get(frame_id));
}
```

每帧 dt=16.67ms 推进,speed=10 帧/秒,每帧 frame += 10 * 0.0167 = 0.167,大约 6 帧推进一次动画。

### Rust 表达:动画系统

```rust
struct AnimationPlayer {
    current_frame: f32,
    speed: f32,             // frames per second
    loop_mode: LoopMode,
}

enum LoopMode {
    Loop,                    // 周期循环(walk 动画)
    OneShot,                 // 播一次停止(攻击动画)
    PingPong,                // 正向 → 反向 → 正向(机械运动)
}

impl AnimationPlayer {
    fn update(&mut self, dt: f32, n_frames: u32) {
        self.current_frame += self.speed * dt;
        match self.loop_mode {
            LoopMode::Loop => {
                if n_frames > 0 {
                    self.current_frame = self.current_frame.rem_euclid(n_frames as f32);
                }
            }
            LoopMode::OneShot => {
                if self.current_frame >= n_frames as f32 {
                    self.current_frame = (n_frames - 1) as f32;  // 停在最后帧
                }
            }
            LoopMode::PingPong => {
                let cycle = 2 * n_frames as f32;
                let mut t = self.current_frame.rem_euclid(cycle);
                if t >= n_frames as f32 { t = cycle - t; }
                self.current_frame = t;
            }
        }
    }
}
```

`rem_euclid` 是 Rust 的"欧几里得除法"——总是返回非负余数。比 `%` 更安全(`%` 对负数保留符号)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

sprite 动画在 2D 游戏里是核心机制:

- **2D 游戏**:每个动画是一组 sprite(walk_0..7, attack_0..5)
- **3D 游戏**:骨骼动画(skeletal animation),不是 sprite 序列。但概念类似——animation 是一组 keyframes
- **混合动画**:walk 和 run 混合,基于玩家速度(case:平滑过渡)

游戏开发圈的动画系统演化:

**阶段 1**(Day 137):硬编码 sprite 序列,周期匹配
**阶段 2**:动画 state machine(state machine graph),状态间转移(走 → 跑 → 跳)
**阶段 3**:动画混合(blend tree),多个动画按权重混合
**阶段 4**:骨骼动画(skeleton + bone matrices)
**阶段 5**:IK / FK(forward / inverse kinematics),程序化动画
**阶段 6**:物理动画(ragdoll、cloth)

商业引擎到阶段 4-6。Casey Day 137 在阶段 1。后面 Day 350+ 可能升级到状态机。

### 3.2 · 🎨 图形学视角

动画在图形学里的角色:

**Sprite animation**:2D,bitmap 序列。简单,内存大(每帧一张图)。Casey 现在。
**Vertex animation**:3D,每帧存顶点位置。内存爆炸,基本不用。
**Skeletal animation**:3D,存 skeleton + bone 变换。现代 3D 标准。
**Morph target animation**:3D,blend shapes(脸表情)。
**Procedural animation**:运行时算法生成(物理、IK)。

骨骼动画的核心数学:
- 骨骼是树(每 bone 有 parent)
- 每 bone 有 local pose(相对父)
- world pose = parent.world * bone.local(矩阵链)
- skinning:顶点受多个 bone 影响(weights)

Casey 软件光栅化阶段不做骨骼,只 sprite。Day 400+ 切 GPU 后才考虑骨骼。

### 3.3 · 🐧 Linux 系统编程视角

周期性概念在 Linux 上:

**jiffies**:Linux 内核的时钟计数器。每秒 HZ 个 jiffy(通常 HZ=1000)。计数器是 u64,要 `jiffies % 2^64` 才溢出(2^64 / 1000 = 几亿年)。所以永不绕回,但本质是周期计数。

**TCP 序列号**:32 位,每字节 +1,2^32 后绕回。绕回时(seq < last_seq 但实际是 seq + 2^32),Linux TCP 协议栈特殊处理。

**进程 PID**:Linux 默认 32768,绕回。`/proc/sys/kernel/pid_max` 设置上限。

```bash
cat /proc/sys/kernel/pid_max
# 4194304(现代 Linux)

ps -eo pid,comm | tail  # 看当前 PID 范围
```

这些都和 Day 137 的周期匹配同构——"整数计数 + 模运算"。

## 5 · 对照与变奏

### 周期匹配 vs ring buffer

Day 126 ring buffer:`(index + 1) % CAP`。
Day 137 周期匹配:`frame % N`。

完全一样的数学。Day 126 用于多线程任务调度,Day 137 用于动画帧。同构概念。

### 不同 LoopMode

**Loop**(默认):0,1,2,...,N-1,0,1,2,...。永远循环。
**OneShot**:0,1,2,...,N-1。停在最后。
**PingPong**:0,1,...,N-1,N-2,...,1,0,1,...。来回。
**Random**:每次随机选 frame。某些粒子动画用。

游戏开发圈最常见的 Loop 和 OneShot。PingPong 用于"开门关门"等往复动画。

### 历史演化

- **1970s**:硬编码 sprite table + frame counter
- **1980s**:动画 ROM 数据(NES、SNES 卡带)
- **1990s**:动画文件格式(.ani、.spr)
- **2000s**:状态机(Mecanim、AnimGraph)
- **2010s**:骨骼动画 + IK
- **2020s**:机器学习动画(AI 生成)

Casey Day 137 在 1980s-1990s 水平,但概念是所有动画系统的基础。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:

1. 一个动画 8 帧,frame=10 时 `lookup_periodic` 返回哪个 tag?
2. 为什么 `current_frame` 是 f32 而不是 u32?
3. PingPong mode N=4,frame 序列是什么?
4. 一个动画速度 12 FPS,游戏 60 FPS,frame 增量 per 游戏帧是多少?

**参考解答**:
1. `frame % 8 = 10 % 8 = 2`,返回 "anim_2"。
2. f32 支持"frame 之间的位置"(如 2.5 = frame 2 和 3 之间)。后续可以加帧间插值(双线性,Day 130 同款)。u32 只能表示整数 frame,无法插值。另外 f32 的累积推进(`current_frame += speed * dt`)有浮点误差,长时间运行后可能漂移,但游戏动画短,可接受。
3. PingPong N=4:0,1,2,3,2,1,0,1,2,3,2,1,0,...(周期 = 2*(N-1) = 6)
4. `speed * dt = 12 * (1/60) = 0.2`。每游戏帧 current_frame += 0.2。5 个游戏帧推进 1 个动画帧。

### Lv2 · 动手实践

**题**:在 Day 136 的 AssetPool 上加 lookup_periodic + AnimationPlayer。

要求:
1. `AssetPool::add_animation_frame(anim_name, frame_idx, item)` —— 注册动画帧
2. `AssetPool::lookup_periodic(anim_name, frame) -> Option<AssetId>` —— 周期查询
3. `AnimationPlayer { current_frame: f32, speed: f32 }`
4. main:加 8 帧 walk 动画,speed=10 FPS,模拟 1 秒(60 game frames)的播放

完成标准:`cargo run` 看到 walk 动画从 frame 0 播到 frame 9.99(绕回到 frame 2),每游戏帧推进 0.167。

**参考解答**:

```rust
use std::collections::HashMap;
use std::marker::PhantomData;

struct AssetId<T> { id: u32, _ty: PhantomData<fn() -> T> }
impl<T> Copy for AssetId<T> {}
impl<T> Clone for AssetId<T> { fn clone(&self) -> Self { *self } }

struct AssetPool<T> {
    items: Vec<T>,
    anim_frames: HashMap<(String, u32), u32>,  // (anim_name, frame_idx) -> item_idx
    anim_lengths: HashMap<String, u32>,         // anim_name -> frame_count
}

impl<T> AssetPool<T> {
    fn new() -> Self {
        Self {
            items: Vec::new(),
            anim_frames: HashMap::new(),
            anim_lengths: HashMap::new(),
        }
    }

    fn add_animation_frame(&mut self, anim_name: &str, frame_idx: u32, item: T) -> AssetId<T> {
        let id = self.items.len() as u32;
        self.items.push(item);
        self.anim_frames.insert((anim_name.to_string(), frame_idx), id);
        let entry = self.anim_lengths.entry(anim_name.to_string()).or_insert(0);
        if frame_idx + 1 > *entry { *entry = frame_idx + 1; }
        AssetId { id, _ty: PhantomData }
    }

    fn lookup_periodic(&self, anim_name: &str, frame: u32) -> Option<AssetId<T>> {
        let n = *self.anim_lengths.get(anim_name)?;
        if n == 0 { return None; }
        let wrapped = frame % n;
        let id = *self.anim_frames.get(&(anim_name.to_string(), wrapped))?;
        Some(AssetId { id, _ty: PhantomData })
    }

    fn get(&self, aid: AssetId<T>) -> &T {
        &self.items[aid.id as usize]
    }

    fn anim_length(&self, anim_name: &str) -> u32 {
        *self.anim_lengths.get(anim_name).unwrap_or(&0)
    }
}

struct AnimationPlayer {
    current_frame: f32,
    speed: f32,  // frames per second
}

impl AnimationPlayer {
    fn new(speed: f32) -> Self {
        Self { current_frame: 0.0, speed }
    }
    fn update(&mut self, dt: f32) {
        self.current_frame += self.speed * dt;
    }
    fn current_int_frame(&self) -> u32 {
        self.current_frame.floor() as u32
    }
}

struct Frame { name: &'static str }

fn main() {
    let mut pool: AssetPool<Frame> = AssetPool::new();

    // 注册 walk 动画 8 帧
    for i in 0..8u32 {
        let name = match i {
            0 => "walk_0 (standing)",
            1 => "walk_1 (right foot forward)",
            2 => "walk_2 (mid step)",
            3 => "walk_3 (left foot forward)",
            4 => "walk_4 (standing)",
            5 => "walk_5 (right foot back)",
            6 => "walk_6 (mid step back)",
            7 => "walk_7 (left foot back)",
            _ => unreachable!(),
        };
        pool.add_animation_frame("walk", i, Frame { name });
    }
    println!("walk animation: {} frames", pool.anim_length("walk"));

    let mut player = AnimationPlayer::new(10.0);  // 10 FPS animation
    let dt = 1.0 / 60.0;  // 60 FPS game

    for game_frame in 0..60u32 {  // 模拟 1 秒
        let anim_frame = player.current_int_frame();
        let frame_id = pool.lookup_periodic("walk", anim_frame).unwrap();
        let frame = pool.get(frame_id);
        if game_frame % 6 == 0 {  // 每 6 game frames (=1 anim frame) print 一次
            println!("game_frame={:>2} current_frame={:.2} anim_frame={} -> {}",
                     game_frame, player.current_frame, anim_frame, frame.name);
        }
        player.update(dt);
    }
}
```

**预期输出**(片段):
```
walk animation: 8 frames
game_frame= 0 current_frame=0.00 anim_frame=0 -> walk_0 (standing)
game_frame= 6 current_frame=1.00 anim_frame=1 -> walk_1 (right foot forward)
game_frame=12 current_frame=2.00 anim_frame=2 -> walk_2 (mid step)
game_frame=18 current_frame=3.00 anim_frame=3 -> walk_3 (left foot forward)
game_frame=24 current_frame=4.00 anim_frame=4 -> walk_4 (standing)
game_frame=30 current_frame=5.00 anim_frame=5 -> walk_5 (right foot back)
game_frame=36 current_frame=6.00 anim_frame=6 -> walk_6 (mid step back)
game_frame=42 current_frame=7.00 anim_frame=7 -> walk_7 (left foot back)
game_frame=48 current_frame=8.00 anim_frame=0 -> walk_0 (standing)  ← 绕回!
```

## 10 · 深度推导:sprite 动画的完整演化

今天 Casey 加周期标签匹配,用于 sprite 动画。这看起来简单(就是"按 frame index 切换 sprite"),但背后涉及游戏动画的所有基础。这一节走通。

### 10.1 起点:静态 sprite

Day 134 你有"sword" tag 对应一个 Bitmap。游戏代码:

```rust
let sword = store.get_by_tag("sword");
draw(sword, x, y);
```

每帧画同一张图。这是"静态 sprite"——适合 UI 图标、墙壁、地板。但角色要"走路"——多帧循环播放。

### 10.2 第一阶段:多 tag 多 sprite

加几个 frame:

```rust
store.add("walk_0", walk_frame_0_bmp);
store.add("walk_1", walk_frame_1_bmp);
store.add("walk_2", walk_frame_2_bmp);
store.add("walk_3", walk_frame_3_bmp);
```

游戏代码每帧切 frame:

```rust
let frame = (time / 100) % 4;
let tag = format!("walk_{}", frame);
let bmp = store.get_by_tag(&tag);
draw(bmp, x, y);
```

问题:

- **String 分配每帧**:format! 创建 String,堆分配,慢
- **HashMap lookup 每帧**:hash + 探测,几百 ns
- **tag 拼写错误**:写错 walk_1,运行时崩溃

### 10.3 第二阶段:周期标签

Day 136 的多 tag 系统。每帧 sprite 一个 tag,加一个共同 prefix:

```rust
store.add_with_tags(&["walk", "walk_0"], walk_frame_0_bmp);
store.add_with_tags(&["walk", "walk_1"], walk_frame_1_bmp);
store.add_with_tags(&["walk", "walk_2"], walk_frame_2_bmp);
store.add_with_tags(&["walk", "walk_3"], walk_frame_3_bmp);
```

启动时查询:

```rust
let walk_frames = store.find_all("walk");  // Vec<AssetId>,4 个
// 排序确保 walk_0, walk_1, walk_2, walk_3 顺序
walk_frames.sort();
```

游戏代码:

```rust
let frame = (time / 100) % walk_frames.len() as u32;
let bmp = store.get(walk_frames[frame as usize]);
draw(bmp, x, y);
```

收益:

- **启动时一次性查询**,缓存 walk_frames,hot path 只用缓存数组
- **无 string 拼接**——纯整数索引,1 ns/op
- **sort 保证顺序**——避免"哪个 frame 是 0"的歧义

### 10.4 第三阶段:AnimationClip 数据结构

把"4 帧 walk 动画"抽象成结构:

```rust
pub struct AnimationClip<T> {
    pub frames: Vec<AssetId<T>>,
    pub frame_duration_ms: u32,  // 每 100ms 一帧
    pub loop_mode: LoopMode,     // Loop / Once / PingPong
}

pub enum LoopMode {
    Loop,         // 0,1,2,3,0,1,2,3,...
    Once,         // 0,1,2,3,然后停在 3
    PingPong,     // 0,1,2,3,2,1,0,1,2,3,...
}

impl<T> AnimationClip<T> {
    pub fn current_frame(&self, elapsed_ms: u32) -> AssetId<T> {
        let frame_count = self.frames.len() as u32;
        let frame_idx = match self.loop_mode {
            LoopMode::Loop => (elapsed_ms / self.frame_duration_ms) % frame_count,
            LoopMode::Once => (elapsed_ms / self.frame_duration_ms).min(frame_count - 1),
            LoopMode::PingPong => {
                let cycle = 2 * (frame_count - 1);
                let pos = (elapsed_ms / self.frame_duration_ms) % cycle;
                if pos < frame_count { pos } else { cycle - pos }
            }
        };
        self.frames[frame_idx as usize]
    }
}
```

游戏代码:

```rust
struct Player {
    anim: AnimationClip<Bitmap>,
    elapsed_ms: u32,
}

fn update(player: &mut Player, dt_ms: u32) {
    player.elapsed_ms += dt_ms;
}

fn render(player: &Player, store: &AssetStore) {
    let frame = player.anim.current_frame(player.elapsed_ms);
    let bmp = store.bitmaps.get(frame);
    draw(bmp, player.x, player.y);
}
```

这就是完整 sprite 动画系统。Casey 的 Day 137 演化到这里。

### 10.5 多动画 + 状态切换

角色有 walk / idle / attack 多个动画。状态机切换:

```rust
enum PlayerState { Idle, Walking, Attacking }

struct Player {
    state: PlayerState,
    elapsed_in_state: u32,
    animations: HashMap<PlayerState, AnimationClip<Bitmap>>,
}

impl Player {
    fn current_frame(&self, store: &AssetStore) -> &Bitmap {
        let anim = &self.animations[&self.state];
        let frame_id = anim.current_frame(self.elapsed_in_state);
        store.bitmaps.get(frame_id)
    }

    fn transition(&mut self, new_state: PlayerState) {
        self.state = new_state;
        self.elapsed_in_state = 0;
    }
}
```

这是工业级 2D 角色动画的雏形。商业引擎(Unreal / Unity)有更复杂的状态机(状态间 transition、blend、parameter),但核心是"animation clip + state + elapsed time"。

### 10.6 Sprite sheet:多 frame 一张图

工业实践:不是每个 frame 一张 PNG,而是**多 frame 合一张 sprite sheet**(节省加载 + cache):

```
walk_sheet.png (128x64, 4 个 frame 每个 32x64):
[0][1][2][3]
```

加载:

```rust
let sheet = parse_png("walk_sheet.png");
let walk_frames: Vec<Bitmap> = (0..4).map(|i| {
    Bitmap {
        width: 32, height: 64,
        pixels: sheet.crop(i * 32, 0, 32, 64).to_vec(),
    }
}).collect();
```

更激进:不切图,直接用 sub-rect:

```rust
struct SpriteRef {
    sheet: AssetId<Bitmap>,  // 引用整张 sheet
    rect: Rect,              // sub-rectangle
}

draw_sprite_ref(&SpriteRef { sheet, rect: Rect::new(0, 0, 32, 64) }, x, y);
```

draw 时只用 sub-rect 部分。这种"虚拟分割"是工业 2D 引擎(Starling / Phaser / Cocos2d)的标准。

### 10.7 完整代码示例

```rust
use std::collections::HashMap;
use std::marker::PhantomData;

pub struct AssetId<T> { id: u32, _ty: PhantomData<fn() -> T> }
impl<T> Copy for AssetId<T> {}
impl<T> Clone for AssetId<T> { fn clone(&self) -> Self { *self } }
impl<T> PartialEq for AssetId<T> { fn eq(&self, o: &Self) -> bool { self.id == o.id } }
impl<T> Eq for AssetId<T> {}
impl<T> PartialOrd for AssetId<T> { fn partial_cmp(&self, o: &Self) -> Option<std::cmp::Ordering> { Some(self.id.cmp(&o.id)) } }
impl<T> Ord for AssetId<T> { fn cmp(&self, o: &Self) -> std::cmp::Ordering { self.id.cmp(&o.id) } }

pub struct Bitmap { pub width: u32, pub height: u32, pub pixels: Vec<u32> }

pub struct AssetPool<T> {
    items: Vec<T>,
    reverse: HashMap<String, Vec<u32>>,
}

impl<T> AssetPool<T> {
    pub fn new() -> Self {
        Self { items: Vec::new(), reverse: HashMap::new() }
    }

    pub fn add(&mut self, tags: &[&str], item: T) -> AssetId<T> {
        let id = self.items.len() as u32;
        self.items.push(item);
        for tag in tags {
            self.reverse.entry(tag.to_string()).or_default().push(id);
        }
        AssetId { id, _ty: PhantomData }
    }

    pub fn find_all_sorted(&self, tag: &str) -> Vec<AssetId<T>> {
        let mut ids: Vec<u32> = self.reverse.get(tag).cloned().unwrap_or_default();
        ids.sort();
        ids.into_iter().map(|id| AssetId { id, _ty: PhantomData }).collect()
    }

    pub fn get(&self, aid: AssetId<T>) -> &T { &self.items[aid.id as usize] }
}

pub enum LoopMode { Loop, Once, PingPong }

pub struct AnimationClip<T> {
    pub frames: Vec<AssetId<T>>,
    pub frame_duration_ms: u32,
    pub mode: LoopMode,
}

impl<T> AnimationClip<T> {
    pub fn current_frame(&self, elapsed_ms: u32) -> AssetId<T>
    where T: Copy {  // bound to satisfy compiler
        let n = self.frames.len() as u32;
        if n == 0 { panic!("empty animation"); }
        let frame_idx = match self.mode {
            LoopMode::Loop => (elapsed_ms / self.frame_duration_ms) % n,
            LoopMode::Once => (elapsed_ms / self.frame_duration_ms).min(n - 1),
            LoopMode::PingPong => {
                let cycle = 2 * (n - 1);
                let pos = (elapsed_ms / self.frame_duration_ms) % cycle;
                if pos < n { pos } else { cycle - pos }
            }
        };
        self.frames[frame_idx as usize]
    }
}

fn main() {
    let mut pool: AssetPool<Bitmap> = AssetPool::new();

    // 4 frame walk 动画
    for i in 0..4 {
        pool.add(&["walk", &format!("walk_{}", i)],
            Bitmap { width: 32, height: 64, pixels: vec![i; 32*64] });
    }
    // 2 frame idle 动画
    for i in 0..2 {
        pool.add(&["idle", &format!("idle_{}", i)],
            Bitmap { width: 32, height: 64, pixels: vec![100+i; 32*64] });
    }

    let walk_frames = pool.find_all_sorted("walk");
    println!("walk has {} frames", walk_frames.len());

    let walk = AnimationClip {
        frames: walk_frames,
        frame_duration_ms: 100,
        mode: LoopMode::Loop,
    };

    // 模拟时间播放
    for t in [0, 50, 100, 150, 200, 250, 300, 350, 400] {
        let frame = walk.current_frame(t);
        let bmp = pool.get(frame);
        println!("t={}ms: frame pixel[0]={}", t, bmp.pixels[0]);
    }
}
```

跑起来看输出:

```
walk has 4 frames
t=0ms: frame pixel[0]=0
t=50ms: frame pixel[0]=0
t=100ms: frame pixel[0]=1
t=150ms: frame pixel[0]=1
t=200ms: frame pixel[0]=2
...
t=400ms: frame pixel[0]=0  ← 循环回来
```

这就是 Day 137 的核心产出。后续 Day 138+ 进入音频,但 sprite 动画的"周期 + state + clip"模式贯穿整个游戏开发。

## 11 · 工业级的额外考量

### 11.1 Sprite atlas

不只是单 sheet,多个 sprite 共享一张 atlas:

```
character_atlas.png:
[walk_0][walk_1][walk_2][walk_3]
[idle_0][idle_1][___________][___________]
[jump_0][jump_1][jump_2][jump_3]
```

加载一次 atlas,所有 sprite 共享。GPU 上传一次,renderer 一次绑定。

### 11.2 9-slice / 9-patch

UI 元素(button 背景)用 9-slice:四角不拉伸,中间拉伸。这样 button 可以任意大小不变形。

```rust
struct NineSlice {
    texture: AssetId<Bitmap>,
    corner_size: u32,  // 角的尺寸
    // 9 个 region:4 角 + 4 边 + 中
}

fn draw_nine_slice(ns: &NineSlice, dst_rect: Rect) {
    let center_size = ...;
    // 4 角不拉伸
    draw_subimage(ns.texture, corner_rect(0), dst_rect.top_left());
    draw_subimage(ns.texture, corner_rect(1), dst_rect.top_right());
    // 4 边拉伸
    draw_subimage_stretched(...);
    // 中拉伸
    draw_subimage_stretched(ns.texture, center_rect, dst_rect.center());
}
```

UI 引擎必备。

### 11.3 Spine / DragonBones 骨骼动画

复杂 2D 角色(行走 + 挥剑 + 跳跃)用骨骼动画——不存每帧图,存"骨骼 + 关节角度 + 时间"。运行时插值生成帧。Spine / DragonBones 是工业标准。

Casey HH 不做骨骼动画,但 sprite 动画 + 状态机已经够 2D RPG / 平台跳跃 / 弹幕射击。

### 11.4 动画事件

某些动画在特定 frame 触发事件(播放音效、生成粒子、伤害判定):

```rust
struct AnimationClip<T> {
    frames: Vec<AssetId<T>>,
    events: Vec<(u32, AnimationEvent)>,  // (frame_index, event)
}

enum AnimationEvent {
    PlaySound(String),
    SpawnParticle(...),
    DealDamage(u32),
}
```

每帧 update 时检查 events:

```rust
fn update(anim: &AnimationClip, current_frame: u32) {
    for &(frame, ref event) in &anim.events {
        if frame == current_frame {
            trigger_event(event);
        }
    }
}
```

商业引擎(Unreal 的 Anim Notify、Unity 的 Animation Event)都这套。
