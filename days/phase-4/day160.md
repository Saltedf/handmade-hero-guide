# Day 160 · 基础通用分配

> Day 157 讲了分配器的概念,Day 159 清理了代码。今天 Casey 写出第一个**可用的**通用分配器:free list + coalesce。这是从理论到实践的关键一步。

## 0 · 为什么要有这一天

理论课讲完,今天 hand-by-hand 实现。Casey 的核心数据结构:

```
arena = 一块大内存(N 字节)
free_list = 链表,每个节点 = (offset, size, prev, next)

allocate(size):
    遍历 free_list 找 first fit
    split:返回前 size 字节,后 (block_size - size) 字节留 list

deallocate(ptr):
    把 (offset, size) 加回 free_list
    coalesce:检查 prev/next,合并相邻 free
```

今天的核心难点是 **coalesce**——把相邻 free 块合并成大块,否则反复 alloc/free 后全是碎片。

coalesce 算法:

- 维护 free_list 按 offset 排序
- free 时插入到正确位置 + 检查前后合并
- 或者用 boundary tag(footer)常数时间找 prev

Casey 用前者(简单)。Day 161 优化。

心理锚点:看完今天,你能写一个工作的 free list allocator,alloc/dealloc 正确,coalesce 工作,能跑简单测试。

## 2 · 心智模型

### 类比:乐高积木

你有一长条底板(arena),上面拼积木。每块积木是 alloc 的块。

- **alloc**:找一段够长的空位,放积木
- **free**:拿走积木,空位变 free
- **coalesce**:如果两块空位相邻,合成一块大的(便于放更大的积木)

不 coalesce,反复拿走积木后空位零散,放不下大积木(外碎片)。

### 严谨模型:free list 排序

```rust
struct FreeBlock {
    offset: usize,
    size: usize,
}

struct Allocator {
    memory: *mut u8,
    size: usize,
    free_list: Vec<FreeBlock>,  // 按 offset 排序
}
```

**alloc**:

```rust
fn allocate(&mut self, size: usize) -> Option<*mut u8> {
    // first fit
    let idx = self.free_list.iter().position(|b| b.size >= size)?;
    let block = self.free_list[idx];

    if block.size > size + MIN_BLOCK_SIZE {
        // split:前 size 给用户,后剩余留 list
        self.free_list[idx] = FreeBlock {
            offset: block.offset + size,
            size: block.size - size,
        };
    } else {
        // 整块给用户(多给一点)
        self.free_list.remove(idx);
    }

    Some(unsafe { self.memory.add(block.offset) })
}
```

**dealloc**:

```rust
fn deallocate(&mut self, ptr: *mut u8, size: usize) {
    let offset = unsafe { ptr.offset_from(self.memory) as usize };

    // 找插入位置(保持 offset 排序)
    let idx = self.free_list.iter()
        .position(|b| b.offset > offset)
        .unwrap_or(self.free_list.len());

    self.free_list.insert(idx, FreeBlock { offset, size });

    // coalesce
    self.coalesce();
}

fn coalesce(&mut self) {
    let mut i = 0;
    while i + 1 < self.free_list.len() {
        let cur = self.free_list[i];
        let next = self.free_list[i + 1];
        if cur.offset + cur.size == next.offset {
            // 合并
            self.free_list[i].size += next.size;
            self.free_list.remove(i + 1);
        } else {
            i += 1;
        }
    }
}
```

### 边界情况

1. **alloc 大于 arena**:`position` 返回 None,返回 None
2. **free 后 free_list 全合并**:整个 arena 都是 free
3. **free 相邻两个 free 块**:第一次 coalesce 合并两个,可能继续合并第三个
4. **alloc 0 字节**:返回任意指针(或报错)

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏 allocator 实际使用:

- **每帧临时**:用 frame_arena(bump),不用 free list
- **持久 asset**:用 reference count + free list
- **粒子**:pool allocator(固定 size)
- **通用**:free list,但不频繁调

Casey 的 free list allocator 主要给 asset 用(每个 asset 大小不同)。

### 3.2 · Linux 系统编程视角

Linux 内核的 allocator:

- **buddy system**:物理页管理
- **slab allocator**:固定 size 对象(inode, task_struct)
- **vmalloc**:虚拟地址连续,物理分散

用户态的 allocator 是 libc 的事,内核不管。

### 3.3 · Rust 生态视角

Rust 现成 allocator:

- **`bumpalo`**:bump arena
- **`typed-arena`**:typed arena
- **`slotmap`**:slot + generation
- **`generational-arena`**:同上

自己写 free list allocator 的好处:

- 完全控制
- 学习数据结构
- 特定优化(如游戏场景)

### 3.4 · 性能视角

free list allocator 性能:

- alloc:first fit O(N)(N = free block 数)
- dealloc:insert O(N) + coalesce O(N)

如果 N < 100,够快(< 1 μs)。如果 N 大,需要:

- **size-segregated list**:8B 一个 list, 16B 一个 list...O(1)
- **red-black tree**:按 size 索引,O(log N)
- **boundary tag**:O(1) coalesce

Day 161 优化。

## 5 · 对照与变奏

### fit 策略对比

```
free_list = [(0,100), (200,50), (300,200)]
alloc(80)

first fit: 选 (0,100),split → (0,80) alloc, (80,20) free
best fit: 选 (200,50)?不对,50<80。选 (300,200)?或 (0,100)?
          实际 best fit 是 ≥80 中最小的,即 (0,100)
worst fit: 选最大的 (300,200)
```

游戏用 first fit(快)。理论 best fit 碎片少但慢。

### 不同 free_list 表达

- **Vec<FreeBlock>**:简单,但 insert/remove O(N)
- **LinkedList<FreeBlock>**:O(1) insert/remove,但 cache 不友好
- **Intrusive list**(在 free block 内嵌 next 指针):零分配,但 unsafe

工业级用 intrusive list + boundary tag。

### 历史

- **1960s**:basic free list
- **1980s**:boundary tags(dlmalloc)
- **2000s**:thread-local cache(jemalloc)
- **2010s+**:size class(mimalloc)

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 first fit 比 best fit 在游戏中常用?有什么代价?

**参考解答**:first fit 在 free list 中找第一个够大的,O(N) 但常数小。best fit 要遍历所有块找最小够大的,O(N) 常数大。游戏每帧 alloc/free 几千次,first fit 性能优势明显。

代价:first fit 倾向于在前部 alloc,留下大块碎片。best fit 留下的小碎片多但能利用大块。游戏通过 coalesce 缓解,通常足够。

## 8 · Rust / Arch 落地代码

```rust
#![allow(dead_code)]

pub struct FreeBlock {
    pub offset: usize,
    pub size: usize,
}

pub struct Allocator {
    memory: Vec<u8>,
    free_list: Vec<FreeBlock>,
}

const MIN_BLOCK_SIZE: usize = 16;

impl Allocator {
    pub fn new(size: usize) -> Self {
        Self {
            memory: vec![0u8; size],
            free_list: vec![FreeBlock { offset: 0, size }],
        }
    }

    pub fn allocate(&mut self, size: usize) -> Option<*mut u8> {
        // 对齐到 8
        let size = (size + 7) & !7;

        let idx = self.free_list.iter().position(|b| b.size >= size)?;
        let block = self.free_list[idx];

        if block.size > size + MIN_BLOCK_SIZE {
            // split
            self.free_list[idx] = FreeBlock {
                offset: block.offset + size,
                size: block.size - size,
            };
        } else {
            // 整块给用户
            self.free_list.remove(idx);
        }

        // 安全:memory 在 self 上有稳定地址(Vec 不 realloc 因为我们不再 push)
        let ptr = self.memory.as_mut_ptr().wrapping_add(block.offset);
        Some(ptr)
    }

    pub fn deallocate(&mut self, ptr: *mut u8, size: usize) {
        let size = (size + 7) & !7;
        let base = self.memory.as_mut_ptr() as usize;
        let offset = (ptr as usize).saturating_sub(base);

        // 找插入位置(按 offset 排序)
        let idx = self.free_list.iter()
            .position(|b| b.offset > offset)
            .unwrap_or(self.free_list.len());

        self.free_list.insert(idx, FreeBlock { offset, size });
        self.coalesce();
    }

    fn coalesce(&mut self) {
        let mut i = 0;
        while i + 1 < self.free_list.len() {
            let cur_end = self.free_list[i].offset + self.free_list[i].size;
            let next_start = self.free_list[i + 1].offset;
            if cur_end == next_start {
                self.free_list[i].size += self.free_list[i + 1].size;
                self.free_list.remove(i + 1);
                // 不增加 i,可能继续合并
            } else {
                i += 1;
            }
        }
    }

    pub fn free_block_count(&self) -> usize {
        self.free_list.len()
    }

    pub fn total_free(&self) -> usize {
        self.free_list.iter().map(|b| b.size).sum()
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn alloc_basic() {
        let mut a = Allocator::new(1024);
        let p = a.allocate(64).unwrap();
        assert!(!p.is_null());
        assert_eq!(a.free_block_count(), 1);  // split 后剩一个
    }

    #[test]
    fn dealloc_coalesce_full() {
        let mut a = Allocator::new(1024);
        let p1 = a.allocate(64).unwrap();
        let p2 = a.allocate(64).unwrap();
        let p3 = a.allocate(64).unwrap();
        a.deallocate(p1, 64);
        a.deallocate(p2, 64);
        a.deallocate(p3, 64);
        assert_eq!(a.free_block_count(), 1);
        assert_eq!(a.total_free(), 1024);
    }

    #[test]
    fn dealloc_partial_no_coalesce() {
        let mut a = Allocator::new(1024);
        let p1 = a.allocate(64).unwrap();
        let _p2 = a.allocate(64).unwrap();  // 中间
        let p3 = a.allocate(64).unwrap();
        a.deallocate(p1, 64);
        a.deallocate(p3, 64);
        // 被 p2 隔开,不合并
        assert!(a.free_block_count() >= 2);
    }
}

fn main() {
    let mut a = Allocator::new(4096);
    println!("initial: {} free blocks, {} bytes free",
        a.free_block_count(), a.total_free());

    let p1 = a.allocate(100).unwrap();
    let p2 = a.allocate(200).unwrap();
    let p3 = a.allocate(50).unwrap();
    println!("after 3 allocs: {} blocks, {} bytes free",
        a.free_block_count(), a.total_free());

    a.deallocate(p1, 100);
    a.deallocate(p2, 200);
    println!("after 2 deallocs: {} blocks, {} bytes free",
        a.free_block_count(), a.total_free());

    a.deallocate(p3, 50);
    println!("after all deallocs: {} blocks, {} bytes free",
        a.free_block_count(), a.total_free());
}
```

**关键 Rust**:
- `(size + 7) & !7` —— 向上对齐到 8 字节
- `wrapping_add` —— 指针算术
- `saturating_sub` —— 减法溢出时返 0(防 ptr 不在 arena)
- `coalesce` 不增 i 当合并发生(继续尝试)

**预期**:
```
initial: 1 free blocks, 4096 bytes free
after 3 allocs: 1 blocks, 3712 bytes free  (split 后还是 1,因为剩余够大)
after 2 deallocs: 2 blocks, 4012 bytes free (中间还有 p3)
after all deallocs: 1 blocks, 4096 bytes free
```

```rust
use std::sync::Arc;
use std::collections::HashMap;

// Phase 4 的 asset storage 完整示例
pub struct AssetStorage<T: Send + Sync + 'static> {
    cache: HashMap<u32, Arc<T>>,
    loader: Box<dyn Fn(u32) -> Result<T, AssetError> + Send + Sync>,
    next_id: u32,
    name_to_id: HashMap<String, u32>,
}

#[derive(Debug)]
pub enum AssetError {
    NotFound(String),
    InvalidFormat(String),
    IoError(std::io::Error),
}

impl<T: Send + Sync + 'static> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self
    where
        F: Fn(u32) -> Result<T, AssetError> + Send + Sync + 'static,
    {
        Self {
            cache: HashMap::new(),
            loader: Box::new(loader),
            next_id: 1,
            name_to_id: HashMap::new(),
        }
    }
    
    pub fn load_by_name(&mut self, name: &str) -> Result<Arc<T>, AssetError> {
        let id = if let Some(id) = self.name_to_id.get(name) {
            *id
        } else {
            let id = self.next_id;
            self.next_id += 1;
            self.name_to_id.insert(name.to_string(), id);
            id
        };
        
        self.load_by_id(id)
    }
    
    pub fn load_by_id(&mut self, id: u32) -> Result<Arc<T>, AssetError> {
        if let Some(cached) = self.cache.get(&id) {
            return Ok(Arc::clone(cached));
        }
        
        let asset = (self.loader)(id)?;
        let arc = Arc::new(asset);
        self.cache.insert(id, Arc::clone(&arc));
        Ok(arc)
    }
    
    pub fn evict_unused(&mut self) {
        self.cache.retain(|_, arc| Arc::strong_count(arc) > 1);
    }
}

// 用法示例
fn main() {
    let mut storage: AssetStorage<Vec<u8>> = AssetStorage::new(|id| {
        Ok(vec![id as u8; 100])  // 模拟加载
    });
    
    let a = storage.load_by_name("test").unwrap();
    let b = storage.load_by_name("test").unwrap();
    assert!(Arc::ptr_eq(&a, &b));  // 同一 Arc
}
```

- ID-based 查询(避免字符串比较)

```rust
// Linux: /usr/share/my_game/assets/texture.png
// Windows: C:\Program Files\MyGame\assets\texture.png
// macOS: MyGame.app/Contents/Resources/assets/texture.png

pub fn get_asset_path(name: &str) -> PathBuf {
    #[cfg(target_os = "linux")]
    {
        // XDG_DATA_DIRS 或 /usr/share
        let data_dir = std::env::var("XDG_DATA_DIRS")
            .unwrap_or_else(|_| "/usr/local/share:/usr/share".to_string());
        for dir in data_dir.split(':') {
            let path = PathBuf::from(dir).join("my_game").join("assets").join(name);
            if path.exists() {
                return path;
            }
        }
        // fallback: ~/.local/share
        let home = std::env::var("HOME").unwrap();
        PathBuf::from(home).join(".local/share/my_game/assets").join(name)
    }
    
    #[cfg(target_os = "windows")]
    {
        let program_files = std::env::var("PROGRAMFILES").unwrap();
        PathBuf::from(program_files).join("MyGame").join("assets").join(name)
    }
    
    #[cfg(target_os = "macos")]
    {
        let home = std::env::var("HOME").unwrap();
        PathBuf::from(home).join("Library/Application Support/MyGame/assets").join(name)
    }
}
```

跨平台 asset 加载是工业级游戏的基础。Rust 的 `cfg` 让单一代码库支持多平台。

```rust
#[derive(Debug, thiserror::Error)]
pub enum GameError {
    #[error("Asset not found: {0}")]
    AssetNotFound(String),
    
    #[error("Asset invalid format: {0}")]
    AssetInvalidFormat(String),
    
    #[error("IO error: {0}")]
    Io(#[from] std::io::Error),
    
    #[error("Parse error: {0}")]
    Parse(String),
}

pub type GameResult<T> = Result<T, GameError>;

pub fn load_texture(path: &Path) -> GameResult<Texture> {
    let data = std::fs::read(path)?;  // IO error → GameError
    let texture = parse_png(&data).map_err(|e| GameError::Parse(e.to_string()))?;
    Ok(texture)
}
```

### A.23 Phase 4 的核心主题深度回顾

让我深度回顾 phase-4 的几个核心主题:

**1. Arena allocator 的工业价值**

Arena allocator 是 phase-4 的开篇主题。核心思想:**一大块内存,scope 退出整体释放**。

适用场景:
- 一帧的临时数据(frame arena)
- 一个关卡的临时数据(level arena)
- 一次操作的临时数据(operation arena)

工业 Rust 实现:`bumpalo` crate

```rust
use bumpalo::Bump;

let bump = Bump::new();
let temp_strings: Vec<&mut String> = (0..1000).map(|i| {
    bump.alloc(format!("string_{}", i))
}).collect();
// bump drop → 所有 temp_strings 释放
```

性能:O(1) allocation(指针前进),O(1) deallocation(整个 arena 一次释放)。比标准 alloc 快 10-100x。

**2. Asset streaming 的工程挑战**

Asset streaming 让"加载不阻塞游戏":

```
主线程:
  get(texture_id) → cache 有 → 立即返回
  get(texture_id) → cache 无 → 返回 placeholder + 排队加载
  
Background thread:
  循环:
    pop job from queue
    load texture from disk
    insert to cache
    signal main thread(可选)
```

工程挑战:
- placeholder 显示(避免黑屏)
- 优先级(玩家附近 asset 先加载)
- 内存预算(满时 LRU 驱逐)
- 线程安全(分桶锁 / lock-free)

Casey phase-4 教基础 streaming,工业实现(bevy_asset)更复杂。

**3. Particle simulation 的并行化**

大量粒子(几万到几百万)的物理更新:

```rust
// 串行
for particle in &mut particles {
    particle.velocity += gravity * dt;
    particle.position += particle.velocity * dt;
}

// 并行(rayon)
use rayon::prelude::*;
particles.par_iter_mut().for_each(|p| {
    p.velocity += gravity * dt;
    p.position += p.velocity * dt;
});

// SIMD(wide crate)
use wide::f32x4;
let gravity_x4 = f32x4::splat(gravity);
let dt_x4 = f32x4::splat(dt);
for chunk in particles.chunks_exact_mut(4) {
    let mut vx = f32x4::from([chunk[0].vx, chunk[1].vx, chunk[2].vx, chunk[3].vx]);
    let mut px = f32x4::from([chunk[0].px, chunk[1].px, chunk[2].px, chunk[3].px]);
    vx += gravity_x4 * dt_x4;
    px += vx * dt_x4;
    // 写回
}
```

并行 + SIMD 让粒子性能 8-16x 提升。

```rust
// Audio callback(高优先级线程)
fn audio_callback(output_buffer: &mut [f32], state: &AudioState) {
    let mix_buffer = state.mix_buffer.lock().unwrap();
    for sample in output_buffer.iter_mut() {
        let mut mixed = 0.0;
        for channel in &state.channels {
            mixed += channel.get_next_sample();
        }
        *sample = mixed * state.master_volume;
    }
}
```

- 多 channel mixing
