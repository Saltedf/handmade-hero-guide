
# Day 151 · 新平台文件 API

> Day 150 让游戏代码直接调 `File::open` / `read`。但 HH 的核心架构原则是 **平台无关**:游戏代码不该知道是 Windows 还是 Linux。今天 Casey 把所有文件操作抽象成一个 `platform_file_api` 结构,游戏代码通过函数指针调用,平台层(Linux / Windows)各自实现。这是 HH 架构的核心抽象。

## 0 · 为什么要有这一天

HH 的分层架构(从 Day 026 起):

```
+------------------+
|  Game code       |  ← 业务逻辑(实体、AI、渲染)
+------------------+
|  Platform layer  |  ← 平台抽象(开窗、文件、音频)
+------------------+
|  OS kernel       |  ← Windows / Linux
+------------------+
```

游戏代码不能直接调 OS API。所有 OS 操作通过 platform layer 提供的函数指针。这样:

1. **跨平台**:游戏代码不变,换 platform 就能跑(Win → Linux → Mac → Web)
2. **测试**:mock platform layer,游戏代码可单测
3. **热重载**:platform layer 不动,游戏代码热替换

文件操作是 platform API 的重要部分。今天 Casey 设计:

```c
// 平台层提供
typedef struct {
    PlatformOpenFile *open;
    PlatformRead *read;
    PlatformWrite *write;
    PlatformClose *close;
    PlatformGetFileSize *get_size;
} PlatformFileApi;
```

游戏代码用 `platform->open(...)` 而不是直接 `CreateFile`。

Rust 表达这个抽象有几个方式:

- **trait 对象**(`dyn PlatformApi`)
- **泛型**(`<P: PlatformApi>`)
- **函数指针 struct**(对应 Casey 风格)

Casey 在 HH 用 C 函数指针 struct,Rust 等价是 trait。今天我们用 trait。

心理锚点:看完今天,你能定义一个 `trait FileApi`,写 Linux 实现(`std::fs::File`),mock 实现(测试用),让游戏代码通过 `Box<dyn FileApi>` 调用。

## 1 · Casey 今天做了什么

Casey 重新组织代码:

1. 定义 `platform_file_api` struct,5 个函数指针(open/read/write/close/get_size)
2. Win32 平台层实现这 5 个,包装 `CreateFile` / `ReadFile` 等
3. 游戏代码所有文件操作改为通过 api 调用
4. 把 api 指针作为参数传给 `GameUpdate` / `GameGetBitmap`

视频里 Casey 讨论:

- **为什么不用宏?** C 宏可以做到"自动指向平台函数",但宏不透明,debug 难。函数指针显式。
- **为什么用 struct 不全局变量?** 让游戏代码可测(传不同 api 测不同场景),也便于多 platform 同时(罕见但可能)。
- **Rust 等价:trait + dyn**。Casey 是 C,但 Rust trait 完全等价。

## 2 · 心智模型

### 类比:UPS 接口

你写一个电商应用,要发货。你不直接调用 FedEx / UPS / DHL,你定义一个 `ShippingProvider` 接口:

```rust
trait ShippingProvider {
    fn ship(&self, package: &Package) -> Result<TrackingId>;
    fn track(&self, id: &TrackingId) -> Status;
}
```

应用代码用 `provider.ship(...)`,具体哪个 provider 在运行时决定。可以换 FedEx 到 UPS 不改应用。

platform API 也是一样:游戏代码用 `file_api.open(...)`,具体是 Linux 还是 Windows 在编译时决定。

### 严谨模型:Rust trait 对象

```rust
pub trait FileApi {
    fn open(&mut self, path: &str, mode: OpenMode) -> Result<FileHandle, IoError>;
    fn read(&mut self, h: &mut FileHandle, buf: &mut [u8]) -> Result<usize, IoError>;
    fn write(&mut self, h: &mut FileHandle, buf: &[u8]) -> Result<usize, IoError>;
    fn close(&mut self, h: FileHandle);
    fn get_size(&mut self, h: &FileHandle) -> Result<u64, IoError>;
}

pub enum OpenMode { Read, Write, ReadWrite, Append }

pub struct FileHandle {
    inner: usize,  // 平台特定的 handle(OS fd / Windows HANDLE)
}
```

Linux 实现:

```rust
pub struct LinuxFileApi;

impl FileApi for LinuxFileApi {
    fn open(&mut self, path: &str, mode: OpenMode) -> Result<FileHandle, IoError> {
        let mut opts = std::fs::OpenOptions::new();
        match mode {
            OpenMode::Read => { opts.read(true); }
            OpenMode::Write => { opts.write(true).create(true).truncate(true); }
            // ...
        }
        let f = opts.open(path)?;
        Ok(FileHandle { inner: Box::into_raw(Box::new(f)) as usize })
    }

    fn read(&mut self, h: &mut FileHandle, buf: &mut [u8]) -> Result<usize, IoError> {
        let f = unsafe { &mut *(h.inner as *mut std::fs::File) };
        use std::io::Read;
        Ok(f.read(buf)?)
    }
    // ...
}
```

Mock 实现(测试用):

```rust
pub struct MockFileApi {
    pub files: HashMap<String, Vec<u8>>,
}

impl FileApi for MockFileApi {
    fn open(&mut self, path: &str, _mode: OpenMode) -> Result<FileHandle, IoError> {
        if self.files.contains_key(path) {
            Ok(FileHandle { inner: ... })
        } else {
            Err(...)
        }
    }
    // ...
}
```

游戏代码:

```rust
pub fn game_get_bitmap(api: &mut dyn FileApi, file_id: u32) -> Bitmap {
    let path = format!("assets/{}.bmp", file_id);
    let mut h = api.open(&path, OpenMode::Read).unwrap();
    let mut buf = vec![0u8; api.get_size(&h).unwrap() as usize];
    api.read(&mut h, &mut buf).unwrap();
    api.close(h);
    decode_bmp(&buf)
}
```

游戏代码不知道是 Linux 还是 Mock,只通过 trait 调用。

### trait 对象 vs 泛型

两种方式选哪个?

| | `dyn Trait` | `<T: Trait>` 泛型 |
|---|---|---|
| 性能 | 动态分派(虚调用) | 静态分派(单态化) |
| 二进制大小 | 小(一份代码) | 大(每个 T 一份) |
| 异质集合 | 支持(Vec<Box<dyn T>>) | 不支持 |
| 编译时间 | 快 | 慢(每 T 重新编译) |

游戏开发:`dyn` 用于跨平台抽象(运行时换 platform 少见),泛型用于性能关键。Casey 用 C 函数指针(等价 dyn),Rust 翻译推荐 dyn。

### Rust 生态 trait 应用

Rust 标准库的类似 trait:

- `std::io::Read` / `Write` —— 读 / 写抽象
- `std::io::Seek` —— seek 抽象
- `AsRawFd` —— 拿到 OS fd

你可以直接用 `Read + Write + Seek` 而不重新发明:

```rust
fn game_get_bitmap<R: Read>(mut r: R) -> Bitmap {
    let mut buf = Vec::new();
    r.read_to_end(&mut buf).unwrap();
    decode_bmp(&buf)
}
```

这样 `R` 可以是 `File`、`Cursor<Vec<u8>>`(内存)、`TcpStream`、加密流等。**多态免费**。

## 3 · 四域深入

### 3.1 · 游戏编程视角

工业引擎的平台抽象:

- **SDL2**:跨平台 layer,封装窗口 / 输入 / 音频
- **GLFW**:窗口 + 输入,OpenGL 渲染
- **winit**(Rust):窗口 + 输入,跨平台
- **cpal**(Rust):音频
- **gilrs**(Rust):手柄

Rust 游戏生态主要用 winit + softbuffer(或 wgpu)。文件操作通常直接用 `std::fs`,因为 OS 差异小。

但 Casey HH 是教学,**显式抽象** 让学生理解为什么有这层。Rust 翻译可以用 `dyn FileApi` 模拟,也可以直接用 std::fs。

### 3.2 · Linux 系统编程视角

Linux 文件 API 层次:

```
应用代码
  ↓
std::fs::File(Rust)        stdio(C)              syscall 调用
  ↓                         ↓                     ↓
glibc open/read/write     glibc fopen/fread     libc::syscall
                                                  ↓
                                              Linux kernel
```

Linux 上 `open(2)` 是 syscall,每次调用内核切换。`fopen`(C stdio)有 buffer,减少 syscall。Rust `File` 没有 buffer,要配 `BufReader` / `BufWriter`。

平台抽象的最高层是 Rust trait,跨 OS 统一 API。Casey 在 C 里手动做,因为 C 标准库不跨 OS。

### 3.3 · Rust 生态视角

Rust 现成的"文件 API" trait:

- `std::io::Read::read` / `read_to_end` / `read_exact`
- `std::io::Write::write` / `write_all` / `flush`
- `std::io::Seek::seek`
- `std::io::BufRead::fill_buf` / `consume`(buffered read)

`File` 实现了 Read + Write + Seek。`Cursor<T>` 也实现(用于内存)。`TcpStream` 实现 Read + Write。

**你可以把游戏代码写成**:

```rust
fn load_bitmap<R: Read + Seek>(r: &mut R) -> Bitmap { ... }
```

这样 `R` 可以是文件、内存、网络、加密流。

### 3.4 · 测试视角

平台抽象的最大好处:**可测试**。

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_load_bitmap() {
        // 用内存数据,不读磁盘
        let fake_bmp = vec![/* fake BMP bytes */];
        let mut cursor = std::io::Cursor::new(fake_bmp);
        let bitmap = load_bitmap(&mut cursor);
        assert_eq!(bitmap.width, 64);
    }
}
```

如果游戏代码直接调 `File::open`,测试要么 mock 文件系统(tempfile crate),要么跳过测试。trait 抽象让单测 trivial。

## 4 · 认知地图

### 4.1 上级

- **抽象层(abstraction layer)** —— 隔离高层和低层的中间层
- **依赖反转(dependency inversion)** —— 高层不依赖低层,都依赖抽象
- **多态(polymorphism)** —— 同一接口,多种实现

### 4.2 同级

| 方案 | 表达 | 何时用 |
|---|---|---|
| 函数指针 struct(Casey C 风格) | `struct Api { open: fn(...) }` | C / 显式控制 |
| Rust trait + dyn | `&dyn Api` | 运行时多态 |
| Rust 泛型 | `<A: Api>` | 编译时多态,零开销 |
| 直接调 std::fs | 无抽象 | 单平台项目 |

### 4.3 下级

- **trait object** —— `&dyn Trait` / `Box<dyn Trait>`
- **vtable** —— trait object 的虚函数表
- **monomorphization** —— 泛型的代码生成

## 5 · 对照与变奏

### 不同语言的抽象

| 语言 | 平台抽象方式 |
|---|---|
| C | 函数指针 struct / 宏 |
| C++ | 虚函数 / 模板 |
| Rust | trait (dyn 或泛型) |
| Go | interface(隐式) |
| Java | interface + 类 |
| Python | duck typing |

Rust trait 是 Java interface + C++ 模板的合体。

### 直接 std::fs 还是抽象?

Rust 的 `std::fs::File` 已经跨平台。如果你的游戏只跑在 Win + Mac + Linux,**直接 std::fs** 没问题。

需要抽象的场景:

- WebAssembly(没有文件系统,要 Emscripten 伪 FS)
- Android(`AssetManager` 不是文件)
- iOS(bundle 不是文件系统)
- 加密 / 网络资源(像 asset)

对这些场景,trait 抽象值得。

### 测试驱动设计

trait 抽象的真正价值不在跨平台,而在**可测**:

```rust

// 生产
struct FileAssetSource { root: PathBuf }
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Casey 在 C 里用函数指针 struct,Rust 翻译应该用 `dyn Trait` 还是 `<T: Trait>` 泛型?为什么?

**参考解答**:推荐 `dyn Trait`,理由:

1. Casey 的 C 代码用 struct + 函数指针,等价 `dyn`(运行时分派)
2. Platform 只在程序启动时选一次,不需要单态化
3. `dyn` 让游戏代码不带泛型参数,API 简洁
4. 虚调用开销 ~3ns,在文件 I/O 面前可忽略

泛型适合**性能关键** + **多种 T 同时存在**(如集合类)。文件 API 用 dyn。

### Lv2 · 动手实践

**题**:定义 `trait FileApi` + `LinuxFileApi` 实现 + `MockFileApi` 实现。`LinuxFileApi::open` 调 `std::fs::File::open`,`MockFileApi::open` 从内部 `HashMap<String, Vec<u8>>` 拿数据。写测试用 mock 读一个假文件。

**参考解答**:

```rust
pub trait FileApi {
    type Handle;
    fn open(&mut self, path: &str) -> Result<Self::Handle, String>;
    fn read_all(&mut self, h: &mut Self::Handle) -> Result<Vec<u8>, String>;
    fn close(&mut self, h: Self::Handle);
}

pub struct LinuxFileApi;
impl FileApi for LinuxFileApi {
    type Handle = std::fs::File;
    fn open(&mut self, path: &str) -> Result<Self::Handle, String> {
        std::fs::File::open(path).map_err(|e| e.to_string())
    }
    fn read_all(&mut self, h: &mut Self::Handle) -> Result<Vec<u8>, String> {
        use std::io::Read;
        let mut buf = Vec::new();
        h.read_to_end(&mut buf).map_err(|e| e.to_string())?;
        Ok(buf)
    }
    fn close(&mut self, _h: Self::Handle) {}  // Drop 自动关
}

#[cfg(test)]
pub struct MockFileApi {
    pub files: std::collections::HashMap<String, Vec<u8>>,
}

#[cfg(test)]
impl FileApi for MockFileApi {
    type Handle = Vec<u8>;
    fn open(&mut self, path: &str) -> Result<Self::Handle, String> {
        self.files.get(path).cloned().ok_or_else(|| format!("not found: {}", path))
    }
    fn read_all(&mut self, h: &mut Self::Handle) -> Result<Vec<u8>, String> {
        Ok(std::mem::take(h))
    }
    fn close(&mut self, _h: Self::Handle) {}
}

#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn mock_read() {
        let mut api = MockFileApi { files: std::collections::HashMap::new() };
        api.files.insert("hello.txt".to_string(), b"hello world".to_vec());
        let mut h = api.open("hello.txt").unwrap();
        let data = api.read_all(&mut h).unwrap();
        api.close(h);
        assert_eq!(data, b"hello world");
    }
}

fn main() {
    println!("run with: cargo test");
}
```

## 8 · Rust / Arch 落地代码

```rust
use std::collections::HashMap;
use std::io::{Read, Seek, SeekFrom};

/// 平台无关文件 API
pub trait FileApi {
    type Handle;
    fn open(&mut self, path: &str) -> Result<Self::Handle, String>;
    fn size(&mut self, h: &Self::Handle) -> Result<u64, String>;
    fn read_at(&mut self, h: &mut Self::Handle, offset: u64, buf: &mut [u8]) -> Result<usize, String>;
    fn close(&mut self, h: Self::Handle);
}

/// Linux 实现
pub struct LinuxFileApi;
impl FileApi for LinuxFileApi {
    type Handle = std::fs::File;
    fn open(&mut self, path: &str) -> Result<Self::Handle, String> {
        std::fs::File::open(path).map_err(|e| e.to_string())
    }
    fn size(&mut self, h: &Self::Handle) -> Result<u64, String> {
        Ok(h.metadata().map_err(|e| e.to_string())?.len())
    }
    fn read_at(&mut self, h: &mut Self::Handle, offset: u64, buf: &mut [u8]) -> Result<usize, String> {
        h.seek(SeekFrom::Start(offset)).map_err(|e| e.to_string())?;
        h.read(buf).map_err(|e| e.to_string())
    }
    fn close(&mut self, _h: Self::Handle) {}
}

/// Mock 实现(测试 / 内存 asset)
pub struct MockFileApi {
    pub files: HashMap<String, Vec<u8>>,
}
impl FileApi for MockFileApi {
    type Handle = (String, u64);  // (path, 总大小)
    fn open(&mut self, path: &str) -> Result<Self::Handle, String> {
        self.files.get(path).map(|v| (path.to_string(), v.len() as u64))
            .ok_or_else(|| format!("not found"))
    }
    fn size(&mut self, h: &Self::Handle) -> Result<u64, String> {
        Ok(h.1)
    }
    fn read_at(&mut self, h: &mut Self::Handle, offset: u64, buf: &mut [u8]) -> Result<usize, String> {
        let data = self.files.get(&h.0).unwrap();
        let start = offset as usize;
        let end = (start + buf.len()).min(data.len());
        if start >= end { return Ok(0); }
        buf[..(end - start)].copy_from_slice(&data[start..end]);
        Ok(end - start)
    }
    fn close(&mut self, _h: Self::Handle) {}
}

/// 游戏代码:通过 trait 加载 asset
fn load_asset_bytes<A: FileApi>(api: &mut A, path: &str) -> Result<Vec<u8>, String> {
    let mut h = api.open(path)?;
    let size = api.size(&h)? as usize;
    let mut buf = vec![0u8; size];
    let read = api.read_at(&mut h, 0, &mut buf)?;
    buf.truncate(read);
    api.close(h);
    Ok(buf)
}

fn main() {
    // 用 Linux 实现
    let mut linux = LinuxFileApi;
    if let Ok(data) = load_asset_bytes(&mut linux, "/etc/hostname") {
        println!("hostname: {:?}", String::from_utf8_lossy(&data));
    }

    // 用 Mock 实现
    let mut mock = MockFileApi { files: HashMap::new() };
    mock.files.insert("fake.txt".to_string(), b"hello mock".to_vec());
    let data = load_asset_bytes(&mut mock, "fake.txt").unwrap();
    println!("mock: {:?}", String::from_utf8_lossy(&data));
}
```

**关键 Rust**:
- `type Handle;` —— associated type,每个 FileApi 实现定义自己的 handle 类型。
- `<A: FileApi>` —— 泛型约束,函数对任意 FileApi 实现工作。
- `(String, u64)` —— tuple 作为 mock 的 handle,简单。

### A.7 工业 Rust 代码示例

让我提供一个具体的工业 Rust 代码示例,综合 phase-4 的概念:

```rust
use std::sync::Arc;
use std::sync::RwLock;
use std::collections::HashMap;
use std::path::Path;

/// Asset storage with sharded locking and async loading.
pub struct AssetStorage<T> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> Result<T, AssetError> + Send + Sync>,
}

impl<T: Send + Sync + 'static> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self
    where
        F: Fn(u32) -> Result<T, AssetError> + Send + Sync + 'static,
    {
        let num_shards = 16;
        let mut shards = Vec::with_capacity(num_shards);
        for _ in 0..num_shards {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self {
            shards,
            loader: Box::new(loader),
        }
    }
    
    pub fn get(&self, id: u32) -> Result<Arc<T>, AssetError> {
        let shard_idx = (id as usize) % self.shards.len();
        
        // Fast path: read lock
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(asset) = shard.get(&id) {
                return Ok(Arc::clone(asset));
            }
        }
        
        // Slow path: load and insert
        let asset = (self.loader)(id)?;
        let arc = Arc::new(asset);
        
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&arc));
        Ok(Arc::clone(entry))
    }
    
    pub fn evict_unused(&self) {
        for shard in &self.shards {
            let mut shard = shard.write().unwrap();
            shard.retain(|_, arc| Arc::strong_count(arc) > 1);
        }
    }
}

#[derive(Debug)]
pub enum AssetError {
    NotFound(u32),
    Io(std::io::Error),
    Invalid(String),
}

// 用法
fn main() {
    let storage: AssetStorage<Vec<u8>> = AssetStorage::new(|id| {
        Ok(vec![id as u8; 100])
    });
    
    let a = storage.get(42).unwrap();
    let b = storage.get(42).unwrap();
    assert!(Arc::ptr_eq(&a, &b));
}
```

这是工业级 Rust asset storage 的完整骨架——分桶 RwLock + Arc + lazy loading + eviction。
