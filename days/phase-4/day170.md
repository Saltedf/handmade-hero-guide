
# Day 170 · 定义字体元数据

> Day 162-169 累积了大量字体代码:glyph data、kerning、metrics、atlas。今天 Casey 把这些**抽象成"font metadata"**——一个统一的 struct 描述字体的所有属性,可以序列化进 .hha,运行时反序列化使用。这是工程化的"模块化"日。

## 0 · 为什么要有这一天

字体系统涉及的数据:

- **基本属性**:family, style, size, weight
- **metrics**:ascent, descent, line gap, em size
- **glyph 数据**:atlas(像素)+ per-glyph metadata(位置/大小/advance/bearing)
- **kerning**:字母对表
- **features**(OpenType):ligature, contextual alternates

如果不抽象,这些散落各处,改一个改动多处。**metadata struct** 把它们打包,易于:

1. **序列化**:写进 .hha 文件
2. **传递**:函数参数一个 struct 代替多个
3. **多字体支持**:metadata 数组管理多字体
4. **版本化**:metadata 字段含 version

今天 Casey 定义 `font_metadata` struct,把所有字体相关数据收进去。

心理锚点:看完今天,你能定义一个完整的字体 metadata schema,序列化到二进制。

## 1 · Casey 今天做了什么

Casey 定义:

```rust
struct font_metadata {
    // 标识
    font_id: u32,
    family_name: [u8; 64],    // 固定长度
    style_name: [u8; 32],
    
    // 度量
    size_px: u32,
    ascent: f32,
    descent: f32,
    line_gap: f32,
    em_size: u32,             // units per em
    
    // glyph 索引
    glyph_count: u32,
    glyph_first_codepoint: u32,  // ASCII 起始
    glyph_data_offset: u64,      // glyph 数组在 .hha 偏移
    atlas_data_offset: u64,      // atlas 像素偏移
    atlas_width: u32,
    atlas_height: u32,
    
    // kerning
    kerning_pair_count: u32,
    kerning_data_offset: u64,
    
    // 版本
    version: u32,
    bitmap_format: u32,   // 0=grayscale 8, 1=SDF 8
};
```

视频里 Casey 讨论:

- **固定大小 vs 变长**:name 用 `[u8; 64]` 固定,避免变长字段(便于读取)。家庭名超 64 字节截断
- **offset + size 而非 inline**:大块数据(atlas / glyph 数组)在 .hha 末尾,前面只存 offset
- **bitmap_format 字段**:将来支持 SDF 时不用破坏兼容

## 2 · 心智模型

### 类比:身份证

身份证是个 metadata struct:固定字段(姓名、生日、身份证号、地址)统一格式,机器可读。

字体 metadata 是字体的"身份证":任何程序读 metadata 就知道字体长什么样、有什么数据。

### 严谨模型:metadata 设计原则

1. **固定大小**:header / metadata 是固定大小,方便一次 read 完
2. **明确字节序**:LE(本机)
3. **版本字段**:未来兼容
4. **offset 引用大块数据**:数据本体在文件末尾,前面只引
5. **enum 用整数**:不存 string,存数字 ID
6. **pad 到对齐**:字段顺序考虑 alignment

### Rust 表达

```rust
#[repr(C)]
#[derive(Copy, Clone, Debug)]
pub struct FontMetadata {
    pub version: u32,
    pub font_id: u32,
    pub size_px: u32,
    pub bitmap_format: u32,    // 0=grayscale, 1=SDF
    pub ascent: f32,
    pub descent: f32,
    pub line_gap: f32,
    pub em_size: u32,
    pub atlas_width: u32,
    pub atlas_height: u32,
    pub atlas_offset: u64,
    pub glyph_count: u32,
    pub glyph_first_codepoint: u32,
    pub glyph_offset: u64,
    pub kerning_count: u32,
    pub kerning_offset: u64,
    pub family_name: [u8; 64],
    pub style_name: [u8; 32],
}
```

总大小:4 × 11 + 8 × 3 + 64 + 32 = 44 + 24 + 96 = 164 字节。可能加 padding 到 168。

### Offset 引用

```
.hha 文件:
+--------------------------------+
| HHA header                     |
+--------------------------------+
| FontMetadata                  |  ← 字段含 atlas_offset, glyph_offset, kerning_offset
+--------------------------------+
| Glyph[glyph_count] 数组        |  ← glyph_offset 指这里
+--------------------------------+
| Kerning[kerning_count] 数组    |  ← kerning_offset 指这里
+--------------------------------+
| Atlas 像素数据                  |  ← atlas_offset 指这里
+--------------------------------+
```

加载流程:

1. 读 .hha header
2. 读 FontMetadata(160 字节)
3. 按 metadata 的 offset seek 到 glyph 数组,读 N 个
4. 按 offset seek 到 kerning,读 K 个
5. 按 offset seek 到 atlas,读 width * height 字节

### 多字体

`font_set` struct 管理多个 metadata:

```rust
struct FontSet {
    fonts: Vec<FontMetadata>,
}

impl FontSet {
    fn find_by_id(&self, id: u32) -> Option<&FontMetadata> {
        self.fonts.iter().find(|f| f.font_id == id)
    }
    
    fn find_by_name(&self, name: &str) -> Option<&FontMetadata> {
        self.fonts.iter().find(|f| {
            let n = std::str::from_utf8(&f.family_name).unwrap_or("");
            n.trim_end_matches('\0') == name
        })
    }
}
```

## 3 · 四域深入

### 3.1 · 游戏编程视角

工业 metadata 设计:

- **统一 schema**:引擎有 schema 定义所有 asset type 的 metadata
- **versioned**:每个 type 有 version,旧版兼容
- **editor integration**:编辑器读 metadata 显示属性
- **cooking**:build 时把 dev metadata → runtime metadata(去掉 debug 字段)

Unreal 的 `FAssetData`、Unity 的 `AssetMeta`、Godot 的 `.import` 文件都是 metadata。

### 3.2 · 数据建模视角

metadata 是 **schema** 的实例。schema 设计的好坏决定:

- **扩展性**:加字段破坏旧版?
- **空间**:字段是否冗余?
- **解析**:固定 vs 变长?

经典 schema 系统:protobuf / FlatBuffers / Cap'n Proto。它们解决"通用 metadata",但 .hha 自定义更紧凑。

### 3.3 · Rust 生态视角

Rust 的 metadata 序列化:

- **`serde` + bincode**:通用,但 black box
- **`#[repr(C)]` + bytemuck**:手写紧凑,Casey 风格
- **`zerocopy`**:类似 bytemuck

```rust
use bytemuck::{Pod, Zeroable};

#[repr(C)]
#[derive(Copy, Clone, Pod, Zeroable)]
struct FontMetadata { ... }

// 写
let bytes: &[u8] = bytemuck::bytes_of(&metadata);
file.write_all(bytes)?;

// 读
let metadata: &FontMetadata = bytemuck::from_bytes(&buf[..size_of::<FontMetadata>()]);
```

### 3.4 · 版本化视角

metadata 加新字段的兼容策略:

1. **不破坏旧版**:新字段加在末尾,旧版读不到忽略
2. **major/minor version**:minor 改兼容,major 改不兼容
3. **schema evolution**(protobuf 风格):每个字段有 tag,可以可选 / 必选

Casey 用 1 + 2:小改加末尾,大改加 version。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 metadata 里 `family_name` 用 `[u8; 64]` 而不是 `String`?

**参考解答**:

1. **固定大小**:metadata 整体大小固定,可以一次 read 完
2. **零分配**:`[u8; 64]` 在 stack,String 在 heap
3. **可序列化**:`#[repr(C)]` + bytemuck 直接 cast,String 不行
4. **跨平台一致**:所有平台 size 一样

代价:family name 超 64 字节截断(罕见)。

### Lv2 · 动手实践

**题**:定义 FontMetadata struct + 序列化到二进制 + 反序列化。验证 round-trip。

**参考解答**:

```rust
use std::io::{Read, Write};

#[repr(C)]
#[derive(Copy, Clone, Debug)]
pub struct FontMetadata {
    pub version: u32,
    pub font_id: u32,
    pub size_px: u32,
    pub bitmap_format: u32,
    pub ascent: f32,
    pub descent: f32,
    pub line_gap: f32,
    pub em_size: u32,
    pub atlas_width: u32,
    pub atlas_height: u32,
    pub atlas_offset: u64,
    pub glyph_count: u32,
    pub glyph_first_codepoint: u32,
    pub glyph_offset: u64,
    pub kerning_count: u32,
    pub kerning_offset: u64,
    pub family_name: [u8; 64],
    pub style_name: [u8; 32],
}

const METADATA_SIZE: usize = std::mem::size_of::<FontMetadata>();

impl FontMetadata {
    fn new(family: &str, size: u32) -> Self {
        let mut family_name = [0u8; 64];
        let bytes = family.as_bytes();
        let len = bytes.len().min(63);
        family_name[..len].copy_from_slice(&bytes[..len]);

        Self {
            version: 1,
            font_id: 1,
            size_px: size,
            bitmap_format: 0,
            ascent: size as f32 * 0.85,
            descent: -(size as f32 * 0.25),
            line_gap: size as f32 * 0.1,
            em_size: 2048,
            atlas_width: 512,
            atlas_height: 512,
            atlas_offset: 0,
            glyph_count: 96,
            glyph_first_codepoint: 32,
            glyph_offset: 0,
            kerning_count: 0,
            kerning_offset: 0,
            family_name,
            style_name: [0u8; 32],
        }
    }

    fn write<W: Write>(&self, w: &mut W) -> std::io::Result<()> {
        // 逐字段写(避免 padding 问题)
        w.write_all(&self.version.to_le_bytes())?;
        w.write_all(&self.font_id.to_le_bytes())?;
        w.write_all(&self.size_px.to_le_bytes())?;
        w.write_all(&self.bitmap_format.to_le_bytes())?;
        w.write_all(&self.ascent.to_le_bytes())?;
        w.write_all(&self.descent.to_le_bytes())?;
        w.write_all(&self.line_gap.to_le_bytes())?;
        w.write_all(&self.em_size.to_le_bytes())?;
        w.write_all(&self.atlas_width.to_le_bytes())?;
        w.write_all(&self.atlas_height.to_le_bytes())?;
        w.write_all(&self.atlas_offset.to_le_bytes())?;
        w.write_all(&self.glyph_count.to_le_bytes())?;
        w.write_all(&self.glyph_first_codepoint.to_le_bytes())?;
        w.write_all(&self.glyph_offset.to_le_bytes())?;
        w.write_all(&self.kerning_count.to_le_bytes())?;
        w.write_all(&self.kerning_offset.to_le_bytes())?;
        w.write_all(&self.family_name)?;
        w.write_all(&self.style_name)?;
        Ok(())
    }

    fn read<R: Read>(r: &mut R) -> std::io::Result<Self> {
        let mut b4 = [0u8; 4];
        let mut b8 = [0u8; 8];
        macro_rules! read_u32 { () => {
            r.read_exact(&mut b4)?; u32::from_le_bytes(b4)
        }; }
        macro_rules! read_u64 { () => {
            r.read_exact(&mut b8)?; u64::from_le_bytes(b8)
        }; }
        macro_rules! read_f32 { () => {
            r.read_exact(&mut b4)?; f32::from_le_bytes(b4)
        }; }

        let version = read_u32!();
        let font_id = read_u32!();
        let size_px = read_u32!();
        let bitmap_format = read_u32!();
        let ascent = read_f32!();
        let descent = read_f32!();
        let line_gap = read_f32!();
        let em_size = read_u32!();
        let atlas_width = read_u32!();
        let atlas_height = read_u32!();
        let atlas_offset = read_u64!();
        let glyph_count = read_u32!();
        let glyph_first_codepoint = read_u32!();
        let glyph_offset = read_u64!();
        let kerning_count = read_u32!();
        let kerning_offset = read_u64!();
        let mut family_name = [0u8; 64];
        r.read_exact(&mut family_name)?;
        let mut style_name = [0u8; 32];
        r.read_exact(&mut style_name)?;

        Ok(Self {
            version, font_id, size_px, bitmap_format,
            ascent, descent, line_gap, em_size,
            atlas_width, atlas_height, atlas_offset,
            glyph_count, glyph_first_codepoint, glyph_offset,
            kerning_count, kerning_offset,
            family_name, style_name,
        })
    }
}

fn main() -> std::io::Result<()> {
    let original = FontMetadata::new("DejaVu Sans", 24);
    println!("metadata size: {}", METADATA_SIZE);

    // 写
    let mut buf = Vec::new();
    original.write(&mut buf)?;
    println!("serialized: {} bytes", buf.len());

    // 读回
    let mut cursor = std::io::Cursor::new(buf);
    let loaded = FontMetadata::read(&mut cursor)?;

    assert_eq!(loaded.version, original.version);
    assert_eq!(loaded.size_px, original.size_px);
    assert_eq!(loaded.ascent, original.ascent);
    let name = std::str::from_utf8(&loaded.family_name).unwrap();
    let name = name.trim_end_matches('\0');
    assert_eq!(name, "DejaVu Sans");
    println!("round-trip OK: family={:?} size={} ascent={}", name, loaded.size_px, loaded.ascent);
    Ok(())
}
```

### A.9 Voxel / 渲染相关代码示例

让我提供一个具体的 Rust 代码示例,综合 phase-4 的概念:

```rust
use std::sync::Arc;
use std::collections::HashMap;
use std::sync::RwLock;

// Asset storage(引用计数 + 分桶锁)
pub struct AssetStorage<T> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> T + Send + Sync>,
}

impl<T> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self 
    where F: Fn(u32) -> T + Send + Sync + 'static {
        let num_shards = 16;
        let mut shards = Vec::with_capacity(num_shards);
        for _ in 0..num_shards {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self {
            shards,
            loader: Box::new(loader),
        }
    }
    
    pub fn get(&self, id: u32) -> Arc<T> {
        let shard_idx = (id as usize) % self.shards.len();
        
        // 读路径
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(asset) = shard.get(&id) {
                return Arc::clone(asset);
            }
        }
        
        // 慢路径:加载
        let asset = Arc::new((self.loader)(id));
        
        // 写路径
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&asset));
        Arc::clone(entry)
    }
}

// 用法
fn main() {
    let storage: AssetStorage<String> = AssetStorage::new(|id| {
        format!("texture_{}.png", id)
    });
    
    let a = storage.get(1);
    let b = storage.get(1);
    assert!(Arc::ptr_eq(&a, &b));  // 同一 Arc
}
```

这是工业级 asset storage 的 Rust 骨架——分桶 RwLock + Arc + 加载闭包。

### A.10 内存管理的最佳实践

Phase 4 涉及大量内存管理。最佳实践:

**1. Ownership 清晰**:
- 每资源有明确 owner
- Owner drop → 资源释放
- 不共享 ownership(避免 cycle)

**2. Arena for 临时数据**:
```rust
use bumpalo::Bump;

let arena = Bump::new();
let temp_data: &mut [u32] = arena.alloc_slice_fill_with(1000, |_| 0);
// arena drop → temp_data 自动释放
```

**3. Arc for 长期共享**:
```rust
let shared = Arc::new(ExpensiveResource::new());
let cloned = Arc::clone(&shared);
// 两个 owner 都 drop → resource 释放
```

**4. Weak for cache**:
```rust
let weak: Weak<Resource> = Arc::downgrade(&strong);
// cache 不阻止 strong 释放
if let Some(strong) = weak.upgrade() {
    // 还在用
} else {
    // 已释放
}
```

**5. Pool for 高频 alloc**:
```rust
let pool = ObjectPool::new(|| ExpensiveObject::new());
let obj = pool.acquire();  // 复用
// ...
pool.release(obj);  // 不 drop,放回 pool
```

工业 Rust 代码综合用这些模式。
