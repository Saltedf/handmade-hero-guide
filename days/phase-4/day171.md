# Day 171 · 资产构建器加字体元数据

> Day 170 定义了 FontMetadata struct。今天 Casey 把它集成进 asset_builder.exe——打包器在写 .hha 时,把字体 metadata 写进去。这是"打包字体"的最后一步。

## 0 · 为什么要有这一天

asset_builder 现在要做:

1. 读 .ttf 文件
2. 用 GDI / FreeType 栅格化所有需要的字符
3. 用 stb_truetype 或 GDI 拿 metrics(ascent/descent)
4. 提取 kerning 表
5. 把所有 glyph + atlas + metadata 写进 .hha

整个流程对应 Day 149(asset_writer)的扩展,增加一种 asset type(字体)。

打包后的 .hha 含:

- 主 header
- 多个 asset descriptor(bitmap / sound / **font**)
- FontMetadata 在 font asset 的数据段开头
- glyph 数组、kerning 数组、atlas 像素跟在后面

游戏运行时:

1. 用 asset_id 取 font asset descriptor
2. 按 descriptor.data_offset seek
3. 读 FontMetadata
4. 按 metadata 内的 offset 算其他数据位置
5. 加载 / cache

心理锚点:看完今天,你能扩展 asset_builder 把字体打包进 .hha。

## 1 · Casey 今天做了什么

Casey 在 asset_builder 加 `AddFont(path, size, asset_id)`:

```c
void AddFont(asset_builder* b, const char* ttf_path, u32 size, u32 asset_id) {
    // 1. 加载 ttf
    font_data* fd = load_ttf(ttf_path);
    
    // 2. 栅格化字符 + atlas packing
    atlas_packed* atlas = rasterize_to_atlas(fd, size);
    
    // 3. 提取 kerning
    kerning_table* kern = extract_kerning(fd);
    
    // 4. 写 FontMetadata + 数据进 .hha
    font_metadata meta = build_metadata(fd, atlas, kern, size);
    write_to_hha(b, asset_id, ASSET_TYPE_FONT, &meta, atlas, kern);
}
```

视频里 Casey 重点:

- **metadata 在前**:加载时先读 metadata,知道后面有什么
- **offset 在 metadata 里**:metadata 给出 glyph 数组、kerning 数组、atlas 的偏移
- **count 字段**:glyph_count / kerning_count 让加载器知道读多少

## 2 · 心智模型

### 类比:图书编目

图书馆收新书,要:

1. 给书分类(小说 / 物理 / 历史)
2. 写目录卡片(书名、作者、ISBN)
3. 卡片上写书架位置(7 排 5 层)
4. 把书放上书架

font asset 同样:

- 类 = ASSET_TYPE_FONT
- 卡片 = FontMetadata
- 位置 = asset descriptor 的 data_offset
- 书 = atlas + glyph + kerning 数据

### 严谨模型:文件布局

```
.hha:
+--------------------------------+
| HhaHeader (16 B)               |
+--------------------------------+
| HhaAsset[N] 索引               |  ← 每个 asset 的 (offset, size)
+--------------------------------+
| ... 其他 asset 数据 ...         |
+--------------------------------+
| FontMetadata (164 B)           |  ← asset[id].data_offset 指这里
+--------------------------------+
| Glyph[glyph_count] 数组        |  ← metadata.glyph_offset 指这里(相对 metadata)
+--------------------------------+
| KerningPair[kerning_count]     |  ← metadata.kerning_offset
+--------------------------------+
| Atlas 像素(atlas_w*atlas_h)    |  ← metadata.atlas_offset
+--------------------------------+
```

注意:metadata 里的 offset 是**相对 metadata 起点**的偏移(简化)。或绝对文件偏移(更通用)。Casey 选相对 metadata 的偏移,加载时算 absolute = base + rel。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:metadata 里的 offset 是绝对还是相对?各有什么优缺点?

**参考解答**:**相对 metadata 起点**:

- 优点:metadata 可整体移动(在文件任何位置)
- 缺点:加载时要算 absolute = metadata_file_offset + relative_offset

**绝对文件偏移**:

- 优点:直接 seek
- 缺点:metadata 移动后所有 offset 失效

Casey 选相对(更灵活)。生产可能用绝对(简单)。

## 8 · Rust / Arch 落地代码

```rust
use std::io::{Read, Write, Seek, SeekFrom};

#[repr(C)]
#[derive(Copy, Clone, Debug)]
struct HhaHeader { magic: [u8; 4], version: u32, tag_count: u32, asset_count: u32 }

#[repr(C)]
#[derive(Copy, Clone, Debug)]
struct HhaAsset {
    asset_type: u32,
    first_tag_index: u32,
    one_past_last_tag_index: u32,
    data_offset: u64,
    data_size: u64,
}

const ASSET_TYPE_BITMAP: u32 = 0;
const ASSET_TYPE_SOUND: u32 = 1;
const ASSET_TYPE_FONT: u32 = 2;

const HHA_MAGIC: [u8; 4] = *b"HHA2";
const HHA_VERSION: u32 = 2;

// FontMetadata 简化
#[repr(C)]
#[derive(Copy, Clone, Debug)]
struct FontMetadata {
    version: u32,
    size_px: u32,
    ascent: f32,
    descent: f32,
    line_gap: f32,
    atlas_width: u32,
    atlas_height: u32,
    atlas_offset: u32,    // 相对 metadata
    glyph_count: u32,
    glyph_offset: u32,
    kerning_count: u32,
    kerning_offset: u32,
}

struct AssetBuilder {
    out: std::fs::File,
    header: HhaHeader,
    asset_descriptors: Vec<HhaAsset>,
}

impl AssetBuilder {
    fn new(path: &str) -> std::io::Result<Self> {
        let out = std::fs::File::create(path)?;
        Ok(Self {
            out,
            header: HhaHeader {
                magic: HHA_MAGIC, version: HHA_VERSION,
                tag_count: 0, asset_count: 0,
            },
            asset_descriptors: Vec::new(),
        })
    }

    fn write_header_placeholder(&mut self) -> std::io::Result<()> {
        self.out.write_all(&self.header.magic)?;
        self.out.write_all(&self.header.version.to_le_bytes())?;
        self.out.write_all(&self.header.tag_count.to_le_bytes())?;
        self.out.write_all(&self.header.asset_count.to_le_bytes())?;
        Ok(())
    }

    fn add_font(&mut self, size: u32) -> std::io::Result<()> {
        // 计算 data_offset(在所有 asset descriptor 之后)
        let n_assets = self.asset_descriptors.len() + 1;
        let asset_desc_size = std::mem::size_of::<HhaAsset>();
        let blob_start = (16 + n_assets * asset_desc_size) as u64;
        // 假设前面 asset 占了多少
        let prev_data_end = self.asset_descriptors.iter()
            .map(|a| a.data_offset + a.data_size)
            .max().unwrap_or(blob_start);
        let data_offset = prev_data_end;

        // 构造 font data(metadata + 模拟 glyph + atlas)
        let metadata_size = std::mem::size_of::<FontMetadata>() as u32;
        let glyph_size = 16 * 4;  // 假设 4 个 glyph,每个 16 字节
        let atlas_size = 64 * 64;  // 假设 64x64 grayscale

        let mut font_buf: Vec<u8> = Vec::new();

        // 写 metadata
        let metadata = FontMetadata {
            version: 1,
            size_px: size,
            ascent: size as f32 * 0.85,
            descent: -(size as f32 * 0.25),
            line_gap: size as f32 * 0.1,
            atlas_width: 64,
            atlas_height: 64,
            atlas_offset: metadata_size + glyph_size as u32,
            glyph_count: 4,
            glyph_offset: metadata_size,
            kerning_count: 0,
            kerning_offset: 0,
        };
        font_buf.extend_from_slice(&metadata.version.to_le_bytes());
        font_buf.extend_from_slice(&metadata.size_px.to_le_bytes());
        font_buf.extend_from_slice(&metadata.ascent.to_le_bytes());
        font_buf.extend_from_slice(&metadata.descent.to_le_bytes());
        font_buf.extend_from_slice(&metadata.line_gap.to_le_bytes());
        font_buf.extend_from_slice(&metadata.atlas_width.to_le_bytes());
        font_buf.extend_from_slice(&metadata.atlas_height.to_le_bytes());
        font_buf.extend_from_slice(&metadata.atlas_offset.to_le_bytes());
        font_buf.extend_from_slice(&metadata.glyph_count.to_le_bytes());
        font_buf.extend_from_slice(&metadata.glyph_offset.to_le_bytes());
        font_buf.extend_from_slice(&metadata.kerning_count.to_le_bytes());
        font_buf.extend_from_slice(&metadata.kerning_offset.to_le_bytes());

        // glyph data(占位)
        font_buf.extend(std::iter::repeat(0u8).take(glyph_size));
        // atlas(占位)
        font_buf.extend(std::iter::repeat(128u8).take(atlas_size));

        let total_size = font_buf.len() as u64;

        self.asset_descriptors.push(HhaAsset {
            asset_type: ASSET_TYPE_FONT,
            first_tag_index: 0,
            one_past_last_tag_index: 0,
            data_offset,
            data_size: total_size,
        });

        // seek 到 data_offset 写
        self.out.seek(SeekFrom::Start(data_offset))?;
        self.out.write_all(&font_buf)?;
        Ok(())
    }

    fn finish(mut self) -> std::io::Result<()> {
        self.header.asset_count = self.asset_descriptors.len() as u32;

        // 重写 header
        self.out.seek(SeekFrom::Start(0))?;
        self.out.write_all(&self.header.magic)?;
        self.out.write_all(&self.header.version.to_le_bytes())?;
        self.out.write_all(&self.header.tag_count.to_le_bytes())?;
        self.out.write_all(&self.header.asset_count.to_le_bytes())?;

        // 写 asset descriptor(假设空位在 16-(16+N*size))
        let asset_desc_size = std::mem::size_of::<HhaAsset>();
        let mut pos = 16u64;
        for a in &self.asset_descriptors {
            self.out.seek(SeekFrom::Start(pos))?;
            self.out.write_all(&a.asset_type.to_le_bytes())?;
            self.out.write_all(&a.first_tag_index.to_le_bytes())?;
            self.out.write_all(&a.one_past_last_tag_index.to_le_bytes())?;
            self.out.write_all(&a.data_offset.to_le_bytes())?;
            self.out.write_all(&a.data_size.to_le_bytes())?;
            pos += asset_desc_size as u64;
        }

        self.out.sync_all()?;
        Ok(())
    }
}

fn main() -> std::io::Result<()> {
    let mut builder = AssetBuilder::new("font_test.hha")?;
    builder.write_header_placeholder()?;
    builder.add_font(16)?;
    builder.add_font(24)?;
    builder.finish()?;
    println!("built font_test.hha with 2 fonts");
    Ok(())
}
```

### A.9 Voxel / 渲染相关代码示例

让我提供一个具体的 Rust 代码示例,综合 phase-4 的概念:

```rust
use std::sync::Arc;
use std::collections::HashMap;
use std::sync::RwLock;

// Asset storage(引用计数 + 分桶锁)
pub struct AssetStorage<T> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> T + Send + Sync>,
}

impl<T> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self 
    where F: Fn(u32) -> T + Send + Sync + 'static {
        let num_shards = 16;
        let mut shards = Vec::with_capacity(num_shards);
        for _ in 0..num_shards {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self {
            shards,
            loader: Box::new(loader),
        }
    }
    
    pub fn get(&self, id: u32) -> Arc<T> {
        let shard_idx = (id as usize) % self.shards.len();
        
        // 读路径
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(asset) = shard.get(&id) {
                return Arc::clone(asset);
            }
        }
        
        // 慢路径:加载
        let asset = Arc::new((self.loader)(id));
        
        // 写路径
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&asset));
        Arc::clone(entry)
    }
}

// 用法
fn main() {
    let storage: AssetStorage<String> = AssetStorage::new(|id| {
        format!("texture_{}.png", id)
    });
    
    let a = storage.get(1);
    let b = storage.get(1);
    assert!(Arc::ptr_eq(&a, &b));  // 同一 Arc
}
```

这是工业级 asset storage 的 Rust 骨架——分桶 RwLock + Arc + 加载闭包。

### A.10 内存管理的最佳实践

Phase 4 涉及大量内存管理。最佳实践:

**1. Ownership 清晰**:
- 每资源有明确 owner
- Owner drop → 资源释放
- 不共享 ownership(避免 cycle)

**2. Arena for 临时数据**:
```rust
use bumpalo::Bump;

let arena = Bump::new();
let temp_data: &mut [u32] = arena.alloc_slice_fill_with(1000, |_| 0);
// arena drop → temp_data 自动释放
```

**3. Arc for 长期共享**:
```rust
let shared = Arc::new(ExpensiveResource::new());
let cloned = Arc::clone(&shared);
// 两个 owner 都 drop → resource 释放
```

**4. Weak for cache**:
```rust
let weak: Weak<Resource> = Arc::downgrade(&strong);
// cache 不阻止 strong 释放
if let Some(strong) = weak.upgrade() {
    // 还在用
} else {
    // 已释放
}
```

**5. Pool for 高频 alloc**:
```rust
let pool = ObjectPool::new(|| ExpensiveObject::new());
let obj = pool.acquire();  // 复用
// ...
pool.release(obj);  // 不 drop,放回 pool
```

工业 Rust 代码综合用这些模式。

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
