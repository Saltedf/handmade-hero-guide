# Day 153 · 合并多个资产文件

> 现代游戏不是单一 .hha 了。一份 base asset(game.hha),若干 DLC(dlc1.hha, dlc2.hha),用户模组(mods/user1.hha)。运行时要**逻辑合并**:游戏代码用 asset_id 查询,加载器决定从哪个 .hha 拿。今天 Casey 实现这个合并层,核心是 **ID 空间设计** 和 **优先级**。

## 0 · 为什么要有这一天

单一 .hha 的局限:

1. **DLC**:游戏本体外加 DLC,玩家可能没买。把 DLC 数据放进主 .hha 是浪费(几十 MB 没用的)。
2. **mods**:玩家自制内容,不能进主 .hha。
3. **patch**:发行后修 bug 改 asset,不想让玩家重下整个游戏。
4. **多语言**:每个语言一份 .hha,按用户语言加载。

合并策略:

- **串联 ID**:base .hha 的 asset_id 0-999,dlc .hha 是 1000-1999,mod .hha 是 2000-2999
- **独立 ID + 优先级**:每个 .hha 有独立 ID 空间,合并时优先级高的覆盖低的(mod > dlc > base)
- **命名查找**:asset 用 hash 名字查找,合并时按优先级搜各个 .hha

工业级做法是 3(mod 用 hash 名字覆盖 base)。Casey 今天先用 1(简单)。

ID 空间设计的关键:

- **连续 vs 稀疏**:连续 cache-friendly,稀疏灵活
- **静态 vs 动态**:静态编译期定,动态运行时分配
- **全局 vs 分区**:全局所有 asset 共用一个 ID 空间,分区每类型独立

Casey 选连续 + 静态 + 全局。简单且对教学清楚。

心理锚点:看完今天,你能设计一个支持多 .hha 文件的 asset 系统,实现"先查 base,没找到查 dlc,再没找到报错"的查询逻辑。

## 1 · Casey 今天做了什么

Casey 在加载器加一层 `asset_file_set`:

```rust
struct AssetFileSet {
    files: Vec<AssetStorage>,  // 多个 .hha,顺序是优先级
}
```

查询 asset 时:

```rust
fn get_bitmap(&mut self, id: u32) -> Option<&Bitmap> {
    // id 高位是文件索引,低位是该文件内 ID
    let file_idx = (id >> 24) as usize;
    let local_id = id & 0xFFFFFF;
    self.files[file_idx].get_bitmap(local_id).ok()
}
```

Casey 用 32-bit ID,高 8 位是文件索引(最多 256 个文件),低 24 位是文件内 ID(每个文件最多 16M asset)。

视频里 Casey 讨论:

- **为什么不用 hash 查找?** hash 灵活,但有冲突,且编译期 ID 难管理。整数 ID 简单。
- **为什么不用 String?** String 慢,且 Rust enum ID 类型安全。
- **优先级 vs 覆盖**:Casey 选优先级(files 数组顺序),不选覆盖(后者需要 hash 名字)。

## 2 · 心智模型

### 类比:图书馆分馆

图书馆有总馆和几个分馆:

- 总馆有 1-1000 号书
- 分馆 A 有 1-500 号书(独立编号,不冲突)
- 分馆 B 有 1-200 号书

你查书时,管理员先问"哪个馆":

- "总馆 100 号" → 总馆 100
- "分馆 A 50 号" → A 馆 50

合并 ID 方案:总馆是 0_001 到 0_999(高 8 位 0 表示总馆),分馆 A 是 1_001 到 1_500(高 8 位 1 表示 A),分馆 B 是 2_001 到 2_200。

### 严谨模型:ID 空间设计

#### 方案 A:高位分段(Casey 用)

```
asset_id = u32
|  file_idx (8 bits) | local_id (24 bits) |
```

- 优点:简单,O(1) 查找
- 缺点:每文件 asset 数硬限 16M;新增文件改全局 ID scheme

#### 方案 B:每文件独立 ID + 优先级查找

```
get_bitmap(name: u64) -> Option<Bitmap> {
    for file in self.files.iter().rev() {  // 倒序优先级高的先
        if let Some(b) = file.get_by_name(name) {
            return Some(b);
        }
    }
    None
}
```

- 优点:无 ID 冲突,灵活
- 缺点:每次查找 O(N) (N = 文件数),或要 hash map

#### 方案 C:全局 hash

```
all_assets: HashMap<u64, (FileId, LocalId)>

get(name) {
    let (fid, lid) = self.all_assets[name];
    self.files[fid].get(lid)
}
```

- 优点:O(1) 查找,支持覆盖(mod hash 同 base,后者覆盖前者)
- 缺点:加载时要全读所有 .hha 的索引,内存大

工业级(Bevy、Unreal)用 C + 名字 hash。Casey 教学用 A。

### AssetStorage 改造

Day 150 的 AssetStorage 只管一个文件。改成多文件:

```rust
pub struct AssetSet {
    files: Vec<AssetStorage>,
}

impl AssetSet {
    pub fn new() -> Self { Self { files: Vec::new() } }

    pub fn add_file(&mut self, path: &Path) -> Result<usize, LoadError> {
        let storage = AssetStorage::open(path)?;
        self.files.push(storage);
        Ok(self.files.len() - 1)
    }

    pub fn get(&mut self, id: u32) -> Result<&LoadedAsset, LoadError> {
        let file_idx = (id >> 24) as usize;
        let local_id = id & 0xFFFFFF;
        self.files[file_idx].get(local_id)
    }

    pub fn make_id(file_idx: usize, local_id: u32) -> u32 {
        ((file_idx as u32) << 24) | (local_id & 0xFFFFFF)
    }
}
```

游戏代码:

```rust
let base_id = AssetSet::make_id(0, 42);  // base 文件的 asset 42
let dlc_id = AssetSet::make_id(1, 7);    // dlc1 文件的 asset 7
game.get_bitmap(base_id);
game.get_bitmap(dlc_id);
```

### 优先级与覆盖

如果想要 mod 覆盖 base,改成 hash 查找:

```rust
pub struct AssetSet {
    files: Vec<AssetStorage>,  // 顺序:base, dlc, mods...,mod 在后(覆盖)
    by_name: HashMap<u64, (usize, u32)>,  // hash_name -> (file_idx, local_id)
}

pub fn add_file(&mut self, path: &Path) -> Result<(), LoadError> {
    let file_idx = self.files.len();
    let storage = AssetStorage::open(path)?;
    // 读所有 asset 的 hash,加入 by_name(后者覆盖前者)
    for local_id in 0..storage.asset_count() {
        let hash = storage.get_name_hash(local_id);
        self.by_name.insert(hash, (file_idx, local_id));
    }
    self.files.push(storage);
    Ok(())
}

pub fn get_by_name(&mut self, hash: u64) -> Result<&LoadedAsset, LoadError> {
    let (file_idx, local_id) = self.by_name[&hash];
    self.files[file_idx].get(local_id)
}
```

加载顺序决定优先级:`base` 先加,`mod` 后加,mod 的 hash 覆盖 base,查询时返回 mod。

## 3 · 四域深入

### 3.1 · 游戏编程视角

工业 asset 系统:

- **Unreal**:`FAssetManager`,primary asset + secondary asset,DLC 支持
- **Unity**:`Addressables`,group + label,运行时合并
- **Bevy**:`Assets<T>` + `Handle<T>`,每个 type 独立 ID 空间
- **HH**:AssetSet,简单优先级

DLC 的关键概念:

- **mount**:运行时挂载 DLC .pak
- **unmount**:卸载 DLC,清理 asset
- **dependency**:DLC 依赖基础包,卸载基础包前先卸 DLC

### 3.2 · Linux 系统编程视角

Linux 文件系统层面的"合并":

- **union mount**(overlayfs):多层文件系统叠加,上层覆盖下层。Docker 镜像就是 overlayfs。
- **bind mount**:把一个目录挂到另一个位置
- **FUSE**:用户态文件系统,可实现任意合并逻辑

游戏 asset 不用 OS 层合并,自己管(性能 + 跨平台)。但理解 overlayfs 有助于启发——它和 asset set 思路一致。

### 3.3 · Rust 生态视角

Rust 的多文件加载:

- **`assets_manager`**:支持 source(物理 FS、内存、ZIP)
- **`bevy_asset`**:处理器 + source 抽象
- **简单方案**:`Vec<AssetStorage>`

Rust enum + match 在 ID 空间表达上很好:

```rust
enum AssetId {
    Base(u32),
    Dlc1(u32),
    Mod(ModId, u32),
}

match id {
    AssetId::Base(x) => base_files.get(x),
    // ...
}
```

类型安全,编译期检查所有分支。

### 3.4 · 数据结构视角

| 数据结构 | 适合 |
|---|---|
| `Vec<Storage>` + 高位分段(本日) | 少量文件,固定结构 |
| `HashMap<Name, (File, LocalId)>` | 任意覆盖,mod 友好 |
| `BTreeMap<Name, ...>` | 范围查询 |
| Trie(前缀树) | 字符串前缀查找 |

## 4 · 认知地图

### 4.1 上级

- **命名空间(namespace)** —— ID 冲突避免的抽象
- **优先级(priority)** —— 多个源同时存在时的选择
- **覆盖(override)** —— 高优先级替换低优先级

### 4.2 同级

| 方案 | ID 设计 | 适合 |
|---|---|---|
| 高位分段(本日) | u32: file 8bit + local 24bit | 固定结构 ✅ |
| 独立 ID + 优先级 | 每文件独立 | mod |
| 全局 hash | HashMap<hash, id> | 工业 |

### 4.3 下级

- **file_idx** —— 文件索引
- **local_id** —— 文件内 ID
- **global_id** —— 全局唯一 ID
- **mount / unmount** —— 加载 / 卸载文件
- **name_hash** —— 名字 hash(用于覆盖)

## 5 · 对照与变奏

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Casey 的方案是 `file_idx << 24 | local_id`,所以 base 文件 asset 0 的 ID 是 `0x00000000`,asset 1 是 `0x00000001`。但 dlc1 文件 asset 0 是 `0x01000000`,asset 1 是 `0x01000001`。这样设计有什么好处?有什么隐患?

**参考解答**:好处:

- 单个 u32 即可表示全局 ID,内存紧凑
- 通过位运算可瞬时拆分 file_idx 和 local_id(shift + mask)
- 排序 ID 等于排序文件 + 文件内 ID,缓存友好

隐患:

- 每文件硬限 16M asset,巨型项目可能不够(纹理几十万种变体)
- 文件数限 256,DLC 多了不够
- 添加新文件需要决定其 file_idx,不能动态分配

工业级做法:用 64-bit ID 或 hash 字符串。

```rust
use std::collections::HashMap;
use std::fs::File;
use std::io::{Read, Seek, SeekFrom};
use std::path::Path;

pub struct AssetStorage {
    pub file: File,
    pub asset_count: u32,
    pub descriptors: Vec<(u32, u64, u64)>,
    pub cache: HashMap<u32, String>,
}

impl AssetStorage {
    fn open(path: &Path) -> std::io::Result<Self> {
        let mut file = File::open(path)?;
        let mut header = [0u8; 16];
        file.read_exact(&mut header)?;
        let asset_count = u32::from_le_bytes(header[8..12].try_into().unwrap());
        let mut descriptors = Vec::with_capacity(asset_count as usize);
        for _ in 0..asset_count {
            let mut d = [0u8; 28];
            file.read_exact(&mut d)?;
            let at = u32::from_le_bytes(d[0..4].try_into().unwrap());
            let off = u64::from_le_bytes(d[12..20].try_into().unwrap());
            let sz = u64::from_le_bytes(d[20..28].try_into().unwrap());
            descriptors.push((at, off, sz));
        }
        Ok(Self { file, asset_count, descriptors, cache: HashMap::new() })
    }

    fn get(&mut self, local_id: u32) -> std::io::Result<&str> {
        if !self.cache.contains_key(&local_id) {
            let (_, off, sz) = self.descriptors[local_id as usize];
            self.file.seek(SeekFrom::Start(off))?;
            let mut buf = vec![0u8; sz as usize];
            self.file.read_exact(&mut buf)?;
            self.cache.insert(local_id, String::from_utf8(buf).unwrap());
        }
        Ok(self.cache.get(&local_id).unwrap())
    }
}

pub struct AssetSet {
    pub files: Vec<AssetStorage>,
}

impl AssetSet {
    pub fn new() -> Self { Self { files: Vec::new() } }

    pub fn add(&mut self, path: &Path) -> std::io::Result<usize> {
        let s = AssetStorage::open(path)?;
        self.files.push(s);
        Ok(self.files.len() - 1)
    }

    pub fn make_id(file_idx: usize, local_id: u32) -> u32 {
        ((file_idx as u32) << 24) | (local_id & 0xFFFFFF)
    }

    pub fn get(&mut self, id: u32) -> std::io::Result<&str> {
        let f = (id >> 24) as usize;
        let l = id & 0xFFFFFF;
        self.files[f].get(l)
    }
}

#[cfg(test)]
mod tests {
    use super::*;
    use std::io::Write;

    fn make_hha(path: &str, contents: &[&str]) -> std::io::Result<()> {
        // 简化的 .hha 写入器,asset_type=0,无 tag,数据是 UTF-8 文本
        let mut f = File::create(path)?;
        let n = contents.len() as u32;
        f.write_all(b"HHA2")?;
        f.write_all(&2u32.to_le_bytes())?;
        f.write_all(&0u32.to_le_bytes())?;  // tag
        f.write_all(&n.to_le_bytes())?;
        // 描述符
        let blob_start = 16 + n as usize * 28;
        let mut offset = blob_start as u64;
        for c in contents {
            f.write_all(&0u32.to_le_bytes())?;  // type
            f.write_all(&0u32.to_le_bytes())?;  // first_tag
            f.write_all(&0u32.to_le_bytes())?;  // last_tag
            f.write_all(&offset.to_le_bytes())?;
            f.write_all(&(c.len() as u64).to_le_bytes())?;
            offset += c.len() as u64;
        }
        for c in contents { f.write_all(c.as_bytes())?; }
        Ok(())
    }

        let id_c = AssetSet::make_id(1, 0);
```

## 8 · Rust / Arch 落地代码

```rust
use std::collections::HashMap;
use std::fs::File;
use std::io::{Read, Seek, SeekFrom};
use std::path::{Path, PathBuf};

pub struct AssetFile {
    file: File,
    descriptors: Vec<(u64, u64)>,  // (offset, size)
    cache: HashMap<u32, Vec<u8>>,
}

impl AssetFile {
    pub fn open(path: &Path) -> std::io::Result<Self> {
        let mut file = File::open(path)?;
        let mut header = [0u8; 16];
        file.read_exact(&mut header)?;
        let asset_count = u32::from_le_bytes(header[8..12].try_into().unwrap());

        let mut descriptors = Vec::with_capacity(asset_count as usize);
        for _ in 0..asset_count {
            let mut d = [0u8; 28];
            file.read_exact(&mut d)?;
            let off = u64::from_le_bytes(d[12..20].try_into().unwrap());
            let sz = u64::from_le_bytes(d[20..28].try_into().unwrap());
            descriptors.push((off, sz));
        }
        Ok(Self { file, descriptors, cache: HashMap::new() })
    }

    pub fn get(&mut self, local_id: u32) -> std::io::Result<&[u8]> {
        if !self.cache.contains_key(&local_id) {
            let (off, sz) = self.descriptors[local_id as usize];
            self.file.seek(SeekFrom::Start(off))?;
            let mut buf = vec![0u8; sz as usize];
            self.file.read_exact(&mut buf)?;
            self.cache.insert(local_id, buf);
        }
        Ok(self.cache.get(&local_id).unwrap())
    }

    pub fn count(&self) -> usize { self.descriptors.len() }
}

pub struct AssetSet {
    files: Vec<AssetFile>,
    paths: Vec<PathBuf>,
}

impl AssetSet {
    pub fn new() -> Self { Self { files: Vec::new(), paths: Vec::new() } }

    pub fn add(&mut self, path: &Path) -> std::io::Result<usize> {
        let f = AssetFile::open(path)?;
        self.paths.push(path.to_path_buf());
        self.files.push(f);
        println!("mounted {} ({} assets) as file_idx {}",
            path.display(), self.files.last().unwrap().count(), self.files.len() - 1);
        Ok(self.files.len() - 1)
    }

    pub fn make_id(file_idx: usize, local_id: u32) -> u32 {
        ((file_idx as u32) << 24) | (local_id & 0xFFFFFF)
    }

    pub fn get(&mut self, id: u32) -> std::io::Result<&[u8]> {
        let file_idx = (id >> 24) as usize;
        let local_id = id & 0xFFFFFF;
        if file_idx >= self.files.len() {
            return Err(std::io::Error::new(std::io::ErrorKind::InvalidInput,
                format!("file_idx {} out of range ({})",
                    file_idx, self.files.len())));
        }
        self.files[file_idx].get(local_id)
    }
}

fn main() -> std::io::Result<()> {
    let mut set = AssetSet::new();

    // 假设你有 Day 149 生成的 test1.hha
    if Path::new("test1.hha").exists() {
        set.add(Path::new("test1.hha"))?;
    }

    println!("total mounted: {} files", set.files.len());

    if set.files.len() > 0 {
        let id = AssetSet::make_id(0, 0);
        let data = set.get(id)?;
        println!("file[0].asset[0] = {:?}", String::from_utf8_lossy(data));
    }
    Ok(())
}
```

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。

**4. Rust 工程模式**:

```rust
// 错误处理
#[derive(Debug, thiserror::Error)]
pub enum Error {
    #[error("IO error: {0}")]
    Io(#[from] std::io::Error),
    #[error("Parse error: {0}")]
    Parse(String),
}
pub type Result<T> = std::result::Result<T, Error>;

// Trait 抽象
pub trait AssetLoader: Send + Sync {
    fn load(&self, id: u32) -> Result<Vec<u8>>;
}

// Builder pattern
pub struct GameBuilder {
    title: String,
    width: u32,
    height: u32,
}
impl GameBuilder {
    pub fn new() -> Self { ... }
    pub fn title(mut self, t: &str) -> Self { self.title = t.to_string(); self }
    pub fn build(self) -> Game { ... }
}

// RAII resource
pub struct Texture { id: u32 }
impl Drop for Texture {
    fn drop(&mut self) {
        unsafe { gl::DeleteTextures(1, &self.id); }
    }
}
```
