## 0 · 为什么要有这一天

## 2 · 心智模型

### 2.1 类比:四车道高速

想象一条 4 车道高速公路。标量 CPU 是 1 车道——每秒通过 1000 辆车。SIMD 是 4 车道同时通车——每秒通过 4000 辆车。

但车道加宽不等于自动快 4 倍。瓶颈在于:

- **车必须排成 4 列**(数据布局:4 个独立运算)
- **不同车不能挤同一列**(避免数据依赖)
- **下高速要"收口"**(horizontal reduce:把 4 个 lane 汇总成 1 个值)

把数学运算改成 SIMD,本质就是**重新组织"车流"**让它能用 4 车道。

### 2.2 哪些运算能 SIMD 化

逐个看常用的数学运算:

| 运算 | 标量写法 | SIMD 写法 | 备注 |
|---|---|---|---|
| `a + b`(两个 Vec4) | 4 个 addss | 1 个 addps | 完美匹配 |
| `a * b`(逐元素乘) | 4 个 mulss | 1 个 mulps | 完美匹配 |
| `a.x * b.x + a.y * b.y`(2D dot) | 2 mul + 1 add | 难直接 SIMD | 数据太少 |
| 4 个 2D dot 同时算 | 8 mul + 4 add | 2 mulps + 1 hadd | SoA 后才能 |
| `a.length()`(Vec4) | dot + sqrtss | dot + sqrtss | dot 还是要 hadd |
| `clamp(x, lo, hi)` | per-element min/max | minps / maxps | 完美匹配 |
| `lerp(a, b, t)` | per-element | 1 个 fma | 完美匹配 |

**规律**:同样的运算**重复多次**(4 个、8 个、16 个)→ SIMD 完美;**单次运算**(1 个 dot)→ SIMD 难以受益(可能更慢,因为要 hadd)。

### 2.3 Vec4 = SIMD 寄存器

游戏里 Vec4 用得非常多(齐次坐标、RGBA 颜色、四元数)。一个 Vec4 正好 128 位,正好一个 xmm 寄存器。所以游戏行业约定:**Vec4 内部直接用 __m128,而不是 [f32; 4]**。

```rust
// 标量版
#[derive(Copy, Clone)]
struct Vec4 { e: [f32; 4] }

impl Vec4 {
    fn add(self, other: Self) -> Self {
        Self { e: [self.e[0]+other.e[0], self.e[1]+other.e[1],
                   self.e[2]+other.e[2], self.e[3]+other.e[3]] }
    }
}

// SIMD 版
use std::arch::x86_64::*;

#[derive(Copy, Clone)]
#[repr(transparent)]
struct Vec4(__m128);

impl Vec4 {
    #[target_feature(enable = "sse2")]
    unsafe fn add(self, other: Self) -> Self {
        Self(_mm_add_ps(self.0, other.0))
    }
}
```

`#[repr(transparent)]` 告诉 Rust:`Vec4` 在内存里和 `__m128` 一模一样(没有额外包装),可以直接当 __m128 传 / 取。

**好处**:

- 一条指令处理 4 个 lane
- 寄存器里直接运算,不需要 load/store
- ABI 简洁(函数参数直接传 __m128)

**坏处**:

- 不安全(unsafe)
- 调试时看不懂 __m128 的位(需要 gdb 特殊命令)
- 不跨平台(ARM 上要 NEON)

### 2.4 dot product 的 SIMD 困境

dot product 是常见运算(`a·b = ax*bx + ay*by + az*bz + aw*bw`)。看起来 4 个独立乘法 + 3 个加法,SIMD 完美匹配?其实有坑。

#### 第一次尝试

```rust
unsafe fn dot_v4(a: Vec4, b: Vec4) -> f32 {
    let prod = _mm_mul_ps(a.0, b.0);  // [ax*bx, ay*by, az*bz, aw*bw]
    // 现在要把 4 个 lane 加成 1 个标量
    // _mm_hadd_ps(X, Y):把 X 的相邻 lane 两两相加
    let s = _mm_hadd_ps(prod, prod);  // [axbx+ayby, azbz+awbw, axbx+ayby, azbz+awbw]
    let s = _mm_hadd_ps(s, s);        // [total, total, total, total]
    _mm_cvtss_f32(s)                  // 取 lane 0
}
```

`_mm_hadd_ps`(horizontal add)是个慢指令(在 Skylake 上 2 个周期,且占用 port 5,该端口只有一个)。两次 hadd = 4+ 周期。整个 dot 是 `mulps(4) + hadd(2) + hadd(2) + cvtss(1) = 9 周期`。

而标量版 `ax*bx + ay*by + az*bz + aw*bw` 用 FMA 是 `mul + fma + fma + fma`,每条 4 周期,但有 ILP,大概 6 周期。

**结论**:SIMD 版**反而更慢**!

#### 解决方案 1:同时算多个 dot

如果有 4 对 Vec4 要算 dot:

```rust
unsafe fn dot_v4x4(a: &[Vec4; 4], b: &[Vec4; 4]) -> [f32; 4] {
    // 把 4 个 Vec4 拆成 SoA:xs, ys, zs, ws
    // 然后一次性 SIMD 算 4 个 dot
    // (代码略)
}
```

这样 hadd 只需要 1 次(把 4 个独立的 dot 结果汇总成 4 个标量),效率高。

#### 解决方案 2:不用 hadd,用 shuffle + add

```rust
unsafe fn dot_v4(a: Vec4, b: Vec4) -> f32 {
    let prod = _mm_mul_ps(a.0, b.0);   // [p0, p1, p2, p3]
    let shuf = _mm_shuffle_ps(prod, prod, 0b00_01_10_11);  // 倒序: [p3, p2, p1, p0]
    let sum1 = _mm_add_ps(prod, shuf); // [p0+p3, p1+p2, p2+p1, p3+p0]
    let shuf2 = _mm_shuffle_ps(sum1, sum1, 0b01_01_01_01);  // [sum1[1], ...]
    let sum2 = _mm_add_ps(sum1, shuf2);
    _mm_cvtss_f32(sum2)
}
```

shuffle 比 hadd 快。但代码复杂。

#### 解决方案 3:批量 dot + 不 reduce

如果调用者本来要继续 SIMD 处理(比如光照计算 `light = dot * color`,color 是 Vec4),那么不 reduce,直接返回 __m128,4 个 lane 都填同样的 dot 值(用 shuffle 广播)。

```rust
unsafe fn dot_v4_broadcast(a: Vec4, b: Vec4) -> __m128 {
    let prod = _mm_mul_ps(a.0, b.0);
    let sum = /* 上面任一方法算出 sum,但 lane 0 有结果 */
    _mm_shuffle_ps(sum, sum, 0)  // broadcast lane 0 到所有 lane
}
```

### 2.5 Vec3 的处理:W lane 怎么办

3D 游戏里 Vec3 远比 Vec4 多(位置、方向、法线)。但 SIMD 寄存器是 4 lane 的,第 4 个 lane 怎么办?

**约定 1:W = 0**(方向向量)
```rust
let dir = Vec4(x, y, z, 0.0);  // dot 自动忽略 W
```

**约定 2:W = 1**(位置 / 点)
```rust
let point = Vec4(x, y, z, 1.0);  // 齐次坐标
```

**约定 3:W = 任意**(代码不关心 W,只在需要时清零)

游戏行业基本统一:**Vec3 内部用 f32x4,W lane 视情况填 0 或 1**。Casey 在 HH 里早期用 Vec2,Day 70+ 进入 3D 后转 Vec3,Phase 4 SIMD 化时全部转 Vec4。

### 2.6 FMA:Fused Multiply-Add

FMA 指令(Haswell 2013+ 引入):一条指令做 `a * b + c`,比分开的 `mul + add` 快一倍,且精度更高(只舍入一次)。

```rust
unsafe fn fma_v4(a: Vec4, b: Vec4, c: Vec4) -> Vec4 {
    Vec4(_mm_fmadd_ps(a.0, b.0, c.0))  // a*b+c
}
```

`_mm_fmadd_ps` 对应 `vfmadd213ps` 指令。需要 FMA feature(`#[target_feature(enable = "fma")]`)。

FMA 是 SIMD 数学库的核心。`dot(a, b)` 用 FMA 写:`ax*bx` fma=`ay*by` fma=`az*bz` fma=`aw*bw`,4 个 FMA,有依赖链,但比 mul+add 快。

### 2.7 horizontal reduce 的真实代价

`_mm_hadd_ps` / `_mm_reduce_add_ps` 把多个 lane 合成一个标量。代价:

- **Skylake**:hadd 2 周期,占 port 0/5(都稀缺)
- **AMD Zen 3**:hadd 4 周期
- **Apple M1**:hadd 比较快(NEON 的 `addv` 是 1-2 周期)

所以 horizontal reduce 是 SIMD 的"必要之恶"。**能避免就避免**:让算法保持"4 lane 同时算"的形态,不要过早 reduce。

### 2.8 改写流程

把数学函数 SIMD 化,标准流程:

1. **识别热点**:用 Day 113 profiler 找
2. **写 baseline + 测试**(Day 114)
3. **看数据布局**:是 AoS(Vec4 一组)还是 SoA(4 个 Vec4 的 X 在一起)
4. **选 SIMD 策略**:
   - 单个 Vec4 运算 → 用 __m128 直接算(每条指令 4 lane)
   - 多个 Vec4 同时 → SoA,一次处理 4 个
5. **改写函数**(用 intrinsic)
6. **测正确性**(对 baseline)
7. **测性能**(对比 baseline)
8. **看汇编**(确认真的生成了 SIMD 指令)

### 3.2 · 🎨 图形学视角

图形学里 Vec3 / Vec4 是核心。每个 shader 都在算这些。

**重要约定**:

- **位置点**:`Vec4(x, y, z, 1)`(W=1 让矩阵平移生效)
- **方向向量**:`Vec4(x, y, z, 0)`(W=0 不被平移影响)
- **法线**:`Vec3` 但用 transpose(inverse(M)) 变换(避免非均匀缩放错误)

SIMD 让矩阵 × 向量这种高频运算提速 4x。一帧几十万次顶点变换,SIMD 累计省 ms 级时间。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上 SIMD 数学库:

- `libmvec`(glibc 的一部分):提供 `_ZGVbN4v_sin` 这种"向量化 sin"函数,SSE 4 个 sin 一次
- `libm` 的 `sinf` / `cosf`:标量,慢

如果你需要"4 个 sin 一起算",用 `libmvec` 或自己写 polynomial approximation(用 SIMD 多项式逼近)。

#### 为什么不用 libm 的 sin

`libm` 的 `sinf` 追求 1 ULP 精度(正确),但慢(~50 周期)。游戏不需要这么精确,常用多项式逼近(`x - x³/6 + x⁵/120 - ...`),SIMD 化后 4 个 sin 一次 ~10 周期。

### Lv1 · 概念辨析

**题**:下面两个版本,哪个对 SIMD 更友好?为什么?

```rust
// A: 一次算一个 dot
fn dots(a: &[Vec3], b: &[Vec3], out: &mut [f32]) {
    for i in 0..a.len() {
        out[i] = a[i].dot(b[i]);
    }
}

// B: 一次算 4 个 dot
fn dots_soa(xs_a: &[f32], ys_a: &[f32], zs_a: &[f32],
            xs_b: &[f32], ys_b: &[f32], zs_b: &[f32],
            out: &mut [f32]) {
    // 一次 SIMD 处理 4 个
}
```

**参考解答**:B 更友好。原因:

- A 是 AoS(Vec3 一组),SIMD load 会得到 [a.x, a.y, a.z, ?] 三个有用 + 一个垃圾,需要 shuffle / mask 处理
- B 是 SoA,一次 load 4 个 x,得到 [a0.x, a1.x, a2.x, a3.x],完美匹配 SIMD 4 lane

加速比 B 通常比 A 快 3-4 倍(接近理论上限 4x)。

### Lv2 · 动手实践

**题**:实现 Vec4 加法 + 点乘,有标量和 SIMD 两版,bench 对比。

```rust
use std::arch::x86_64::*;

#[derive(Copy, Clone, Debug)]
pub struct Vec4Scalar { pub e: [f32; 4] }

impl Vec4Scalar {
    pub fn add(self, o: Self) -> Self {
        Self { e: [self.e[0]+o.e[0], self.e[1]+o.e[1],
                   self.e[2]+o.e[2], self.e[3]+o.e[3]] }
    }
    pub fn dot(self, o: Self) -> f32 {
        self.e[0]*o.e[0] + self.e[1]*o.e[1] + self.e[2]*o.e[2] + self.e[3]*o.e[3]
    }
}

#[derive(Copy, Clone)]
#[repr(transparent)]
pub struct Vec4Simd(__m128);

impl Vec4Simd {
    pub fn from_slice(s: &[f32; 4]) -> Self {
        Self(unsafe { _mm_loadu_ps(s.as_ptr()) })
    }
    pub fn to_array(self) -> [f32; 4] {
        let mut out = [0.0f32; 4];
        unsafe { _mm_storeu_ps(out.as_mut_ptr(), self.0) }
        out
    }
    #[target_feature(enable = "sse2")]
    pub unsafe fn add(self, o: Self) -> Self {
        Self(_mm_add_ps(self.0, o.0))
    }
    #[target_feature(enable = "sse4.1")]  // sse4.1 有 dpps
    pub unsafe fn dot(self, o: Self) -> f32 {
        // dpps imm:lane 选择 + 最终 reduce
        let r = _mm_dp_ps(self.0, o.0, 0b1111_0001);
        _mm_cvtss_f32(r)
    }
}
```

注意 `_mm_dp_ps`(SSE 4.1 的 dot product)是单条指令做 mul + horizontal sum,但实际比手动 shuffle 慢(占 port 0/5)。Casey 一般手写。

bench 1000 次 add + 1000 次 dot,看加速比。

### Rust:完整的 Vec4 SIMD 数学

```rust
use std::arch::x86_64::*;

#[derive(Copy, Clone)]
#[repr(transparent)]
pub struct Vec4(pub __m128);

impl Vec4 {
    pub const fn new(x: f32, y: f32, z: f32, w: f32) -> Self {
        // const fn 不能用 unsafe intrinsic,只能用数组初始化
        // 真实代码里 new 通常不是 const
        Self(unsafe { _mm_set_ps(w, z, y, x) })
    }

    #[target_feature(enable = "sse2")]
    pub unsafe fn from_array(a: [f32; 4]) -> Self {
        Self(_mm_loadu_ps(a.as_ptr()))
    }

    #[target_feature(enable = "sse2")]
    pub unsafe fn to_array(self) -> [f32; 4] {
        let mut out = [0.0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), self.0);
        out
    }

    #[target_feature(enable = "sse2")]
    pub unsafe fn add(self, o: Self) -> Self { Self(_mm_add_ps(self.0, o.0)) }

    #[target_feature(enable = "sse2")]
    pub unsafe fn mul(self, o: Self) -> Self { Self(_mm_mul_ps(self.0, o.0)) }

    #[target_feature(enable = "fma")]
    pub unsafe fn fma(self, mul: Self, add: Self) -> Self {
        Self(_mm_fmadd_ps(self.0, mul.0, add.0))
    }

    /// 4-lane dot,broadcast 到所有 lane
    #[target_feature(enable = "sse3")]
    pub unsafe fn dot_broadcast(self, o: Self) -> Self {
        let prod = _mm_mul_ps(self.0, o.0);
        let shuf = _mm_movehdup_ps(prod);  // [p1, p1, p3, p3]
        let sum = _mm_add_ps(prod, shuf); // [p0+p1, p1+p1, p2+p3, p3+p3]
        let shuf2 = _mm_movehl_ps(sum, sum);  // 取高半:[p2+p3, p3+p3, ...]
        let sum2 = _mm_add_ss(sum, shuf2);    // lane 0 加 lane 2
        Self(_mm_shuffle_ps(sum2, sum2, 0))   // 广播 lane 0
    }

    #[target_feature(enable = "sse2")]
    pub unsafe fn length(self) -> f32 {
        let sq = self.dot_broadcast(self).0;
        _mm_cvtss_f32(_mm_sqrt_ss(sq))
    }

    #[target_feature(enable = "sse2")]
    pub unsafe fn normalized(self) -> Self {
        let len_sq = self.dot_broadcast(self).0;
        let inv = _mm_rcp_ps(len_sq);  // 快速近似倒数(11-bit 精度)
        // 精确版用 _mm_div_ps(慢 5x),但游戏可以容忍 rcpps 的误差
        Self(_mm_mul_ps(self.0, _mm_sqrt_ps(inv)))
    }
}

// 用法
fn main() {
    let a = unsafe { Vec4::from_array([1.0, 2.0, 3.0, 4.0]) };
    let b = unsafe { Vec4::from_array([5.0, 6.0, 7.0, 8.0]) };
    let c = unsafe { a.add(b) };
    let dot = unsafe { a.dot_broadcast(b) };
    let len = unsafe { a.length() };
    println!("a + b = {:?}", unsafe { c.to_array() });
    println!("dot (broadcast) = {:?}", unsafe { dot.to_array() });
    println!("|a| = {}", len);
}
```

```bash
# 编译

# 看汇编
cargo rustc --release -- --emit asm

grep -E 'addps|mulps|fmadd|rcp|sqrt' $ASM
# 典型输出:
#   vaddps
#   vmulps

```

**Troubleshooting**:

- `_mm_fmadd_ps` not found:CPU 不支持 FMA,加 `#[target_feature(enable = "fma")]` 时编译会跳过这个函数;在调用前用 `is_x86_feature_detected!("fma")` 判断
- normalized 用 rcp_ps 后长度不是 1:`rcp_ps` 是 11-bit 精度近似(误差 ~1/2048),需要 1 次 Newton-Raphson 精化:
  ```rust
  let nr = _mm_mul_ps(inv, _mm_sub_ps(three, _mm_mul_ps(two_x, inv)));
  ```
- bench 显示 SIMD 比 scalar 慢:可能 horizontal reduce 太频繁,或者数据量不够,或者编译器已经自动向量化了标量版
