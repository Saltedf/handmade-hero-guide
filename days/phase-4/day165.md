
# Day 165 · 修复资产系统线程 bug

> 你测试新加的字体加载,游戏偶尔崩溃。重启又正常。崩溃点不固定,有时在 get_bitmap,有时在 deallocate。**这是数据竞争(race condition)** —— Day 158 引入的引用计数没考虑多线程。今天 Casey 排查 + 修。

## 0 · 为什么要有这一天

多线程 bug 是工程里**最坑**的:

- 不确定性:每次跑结果不同(取决于调度)
- 难复现:可能跑 100 次才出现一次
- 调试器一介入就消失(Heisenbug)
- 可能藏几年才爆发

数据竞争(data race)定义:

- 两个或更多线程**同时**访问同一变量
- 至少一个是**写**
- 没有**同步机制**(锁 / 原子)保护

后果:undefined behavior(C/C++)、错乱数据、随机崩溃。Rust 借用检查器防止单线程 UB,但多线程要靠 `Send` / `Sync` + 显式同步。

Casey 的 bug:

- 主线程:`get(id)` 调 `ref_count[id] += 1` + 加载 + cache
- streaming 线程:同时调 `get(other_id)` 读写 cache

两个线程同时改 `HashMap`,内部状态破坏。修:

- 全部用 `Arc<Mutex<HashMap>>` 包
- 或:只让主线程访问 cache,streaming 线程通过消息队列请求

Casey 选第一个(简单)。Day 166 优化。

心理锚点:看完今天,你能用 Rust 写线程安全的 asset cache,知道 Arc / Mutex / RwLock 的差别。

## 2 · 心智模型

### 类比:共享白板

办公室一块白板,大家都能写。规则:

- 任何人擦白板前,先看是不是有人在写——是则等
- 写完后说"写完了",别人才可以写

如果没规则,两人同时写,字会重叠变成乱码。

线程同步的"规则"就是 **锁**(mutex):

- lock:检查没人用,标记"我在用"
- unlock:标记"我用完了"

### 严谨模型:数据竞争

```rust
// 错误代码(数据竞争)
let counter = Arc::new(Mutex::new(0));  // 实际这里是普通的 RefCell 或 Cell

let c1 = Arc::clone(&counter);
thread::spawn(move || {
    for _ in 0..1000 { *c1.lock().unwrap() += 1; }
});
// ...
```

如果不加 Mutex,直接 `Arc<i32>`,多线程 += 不是原子(读 / 加 / 写三步,中间可能被打断)。最后 counter 不是 2000 而是任意值。

Rust **Send / Sync** trait 防止这种:

- `Cell<T>` 不是 Sync,不能跨线程共享
- `Arc<T>` 要求 `T: Send + Sync`
- `Mutex<T>` 让 `T` Sync

所以 `Arc<i32>` 在 Rust **不能编译**(i32 是 Send,但 `Arc` 要 Sync)。必须 `Arc<Mutex<i32>>` 或 `Arc<AtomicU32>`。

### Mutex vs RwLock vs Atomic

| 同步原语 | 适合 | 开销 |
|---|---|---|
| `Mutex<T>` | 多写 | 中 |
| `RwLock<T>` | 多读少写 | 中 |
| `AtomicU32` 等 | 单数值 | 低 |
| `AtomicPtr<T>` | 指针 | 低 |
| lock-free MPSC queue | 单生产单消费 | 极低 |

asset cache 适合:

- ref_count:`AtomicU32`(单值原子)
- cache 本身:`RwLock<HashMap>`(多读少写)
- 或:`Mutex<HashMap>`(简单)

### Casey 修复后的 cache

```rust
struct AssetStorage {
    cache: Mutex<HashMap<u32, Arc<LoadedAsset>>>,
    ref_counts: Mutex<HashMap<u32, AtomicU32>>,
}

impl AssetStorage {
    fn get(&self, id: u32) -> Arc<LoadedAsset> {
        // 先尝试读(无写时快速路径)
        {
            let cache = self.cache.lock().unwrap();
            if let Some(a) = cache.get(&id) {
                return Arc::clone(a);
            }
        }
        // 慢路径:加载
        let asset = Arc::new(self.load_from_disk(id));
        let mut cache = self.cache.lock().unwrap();
        cache.insert(id, Arc::clone(&asset));
        asset
    }
}
```

注意:**两次 lock**——读时一次(查),写时一次(插)。两次之间可能其他线程也插入,导致重复加载。**double-checked locking** 解决:

```rust
fn get(&self, id: u32) -> Arc<LoadedAsset> {
    let cache = self.cache.lock().unwrap();  // 一次锁
    if let Some(a) = cache.get(&id) {
        return Arc::clone(a);
    }
    drop(cache);  // 释放锁
    let asset = Arc::new(self.load_from_disk(id));
    let mut cache = self.cache.lock().unwrap();
    // 二次检查
    if let Some(existing) = cache.get(&id) {
        return Arc::clone(existing);
    }
    cache.insert(id, Arc::clone(&asset));
    asset
}
```

或更简单:`load_from_disk` 时一直持锁(慢,但正确)。

### 3.3 · Rust 生态视角

Rust 同步 crate:

- **`std::sync::{Mutex, RwLock, Arc}`**:标准
- **`parking_lot::{Mutex, RwLock}`**:更快,不返回 Result
- **`crossbeam`**:lock-free 数据结构
- **`tokio::sync`**:异步版本
- **`flume` / `crossbeam-channel`**:消息队列

`parking_lot` 优势:

- 比 std 快 2-5x
- 不会 poison(不返回 Result)
- 更好的 fairness

```rust
use parking_lot::Mutex;
let m = Mutex::new(0);
let mut g = m.lock();  // 不返回 Result
*g += 1;
```

### 3.4 · 性能视角

锁的代价:

- 加锁:~20 ns(uncontended)
- 加锁:~10 μs(contended + 上下文切换)
- 原子操作:~5 ns
- lock-free queue:~50 ns

游戏每帧几千次锁 = 几十 μs。可接受。但要避免**长持锁**——锁内做 I/O(读盘),其他线程等几 ms。

- **2000s**:TSan / Helgrind
- **2010s+**:Rust Send/Sync 编译期检测

### 死锁条件(Coffman 4 条)

1. 互斥(资源不可共享)
2. 持有等待(持锁时等别的)
3. 不可剥夺(锁不能强制夺走)
4. 循环等待(线程图成环)

打破任意一条避免死锁。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 `Arc<RefCell<T>>` 不能跨线程?要怎么改?

**参考解答**:`RefCell<T>` 不是 `Sync`(运行时借用检查无锁,跨线程不安全)。`Arc<T>` 要求 `T: Send + Sync`,所以 `Arc<RefCell<T>>` 不 Send,不能跨线程。

改成:

- `Arc<Mutex<T>>`:Mutex 让 T Sync,可跨线程
- `Arc<RwLock<T>>`:类似,多读优
- `Arc<AtomicX>`:若 T 是数值

### Lv2 · 动手实践

**题**:写一个**多线程** asset cache。10 个线程同时请求 100 个 asset。验证:每个 asset 只加载一次(用计数器)。

**参考解答**:

```rust
use std::collections::HashMap;
use std::sync::{Arc, Mutex};
use std::thread;

struct AssetCache {
    cache: Mutex<HashMap<u32, Arc<String>>>,
    load_count: Mutex<u32>,
}

impl AssetCache {
    fn new() -> Self {
        Self { cache: Mutex::new(HashMap::new()), load_count: Mutex::new(0) }
    }

    fn get(&self, id: u32) -> Arc<String> {
        // 快速路径:已 cache
        {
            let cache = self.cache.lock().unwrap();
            if let Some(a) = cache.get(&id) {
                return Arc::clone(a);
            }
        }
        // 慢路径:加载
        std::thread::sleep(std::time::Duration::from_millis(1));  // 模拟 I/O
        let asset = Arc::new(format!("asset_{}", id));
        let mut cache = self.cache.lock().unwrap();
        // 二次检查
        if let Some(existing) = cache.get(&id) {
            return Arc::clone(existing);
        }
        *self.load_count.lock().unwrap() += 1;
        cache.insert(id, Arc::clone(&asset));
        asset
    }
}

fn main() {
    let cache = Arc::new(AssetCache::new());
    let mut handles = Vec::new();
    for _ in 0..10 {
        let c = Arc::clone(&cache);
        handles.push(thread::spawn(move || {
            for id in 0..100u32 {
                let _ = c.get(id);
            }
        }));
    }
    for h in handles { h.join().unwrap(); }
    let lc = *cache.load_count.lock().unwrap();
    println!("loaded {} times (expected 100)", lc);
    assert_eq!(lc, 100);
}
```

## 8 · Rust / Arch 落地代码

```rust
use std::collections::HashMap;
use std::sync::{Arc, Mutex};
use std::thread;

struct AssetCache {
    cache: Mutex<HashMap<u32, Arc<String>>>,
    stats: Mutex<Stats>,
}

#[derive(Default)]
struct Stats {
    hits: u64,
    misses: u64,
    loads: u64,
}

impl AssetCache {
    fn new() -> Self {
        Self {
            cache: Mutex::new(HashMap::new()),
            stats: Mutex::new(Stats::default()),
        }
    }

    fn get(&self, id: u32) -> Arc<String> {
        // 双检锁模式
        {
            let cache = self.cache.lock().unwrap();
            if let Some(a) = cache.get(&id) {
                self.stats.lock().unwrap().hits += 1;
                return Arc::clone(a);
            }
        }

        // 慢路径:加载(锁外)
        self.stats.lock().unwrap().misses += 1;
        let asset = self.load(id);

        let mut cache = self.cache.lock().unwrap();
        // 二次检查:其他线程可能已插入
        if let Some(existing) = cache.get(&id) {
            return Arc::clone(existing);
        }
        self.stats.lock().unwrap().loads += 1;
        cache.insert(id, Arc::clone(&asset));
        asset
    }

    fn load(&self, id: u32) -> String {
        // 模拟 I/O
        std::thread::sleep(std::time::Duration::from_micros(100));
        format!("loaded_asset_{}", id)
    }

    fn stats(&self) -> (u64, u64, u64) {
        let s = self.stats.lock().unwrap();
        (s.hits, s.misses, s.loads)
    }
}

fn main() {
    let cache = Arc::new(AssetCache::new());
    let num_threads = 8;
    let ids_per_thread = 50;

    let mut handles = Vec::new();
    for _ in 0..num_threads {
        let c = Arc::clone(&cache);
        handles.push(thread::spawn(move || {
            for id in 0..ids_per_thread {
                let _ = c.get(id);
            }
        }));
    }
    for h in handles { h.join().unwrap(); }

    let (hits, misses, loads) = cache.stats();
    println!("threads: {}", num_threads);
    println!("ids per thread: {}", ids_per_thread);
    println!("hits: {} (重复访问)", hits);
    println!("misses: {} (首次访问)", misses);
    println!("loads: {} (实际加载,期望 {})", loads, ids_per_thread);
    // loads 应该 == ids_per_thread(每 id 只加载一次)
    assert_eq!(loads, ids_per_thread as u64);
    println!("OK: no duplicate loads");
}
```

**关键 Rust**:
- `Mutex::lock()` 返回 `Result<MutexGuard, _>`——poisoned(锁持有者 panic)时 Err
- `unwrap()` 在 poison 时 panic,生产代码可能要 `match`
- `Arc::clone(&a)` 增加 ref count(原子操作)
- `parking_lot::Mutex` 替代 std,更快不 poison

```rust
use std::sync::Arc;
use std::collections::HashMap;
use std::sync::RwLock;

// Asset storage(引用计数 + 分桶锁)
pub struct AssetStorage<T> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> T + Send + Sync>,
}

impl<T> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self 
    where F: Fn(u32) -> T + Send + Sync + 'static {
        let num_shards = 16;
        let mut shards = Vec::with_capacity(num_shards);
        for _ in 0..num_shards {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self {
            shards,
            loader: Box::new(loader),
        }
    }
    
    pub fn get(&self, id: u32) -> Arc<T> {
        let shard_idx = (id as usize) % self.shards.len();
        
        // 读路径
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(asset) = shard.get(&id) {
                return Arc::clone(asset);
            }
        }
        
        // 慢路径:加载
        let asset = Arc::new((self.loader)(id));
        
        // 写路径
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&asset));
        Arc::clone(entry)
    }
}

// 用法
fn main() {
    let storage: AssetStorage<String> = AssetStorage::new(|id| {
        format!("texture_{}.png", id)
    });
    
    let a = storage.get(1);
    let b = storage.get(1);
    assert!(Arc::ptr_eq(&a, &b));  // 同一 Arc
}
```

这是工业级 asset storage 的 Rust 骨架——分桶 RwLock + Arc + 加载闭包。

### A.10 内存管理的最佳实践

Phase 4 涉及大量内存管理。最佳实践:

**1. Ownership 清晰**:
- 每资源有明确 owner
- Owner drop → 资源释放
- 不共享 ownership(避免 cycle)

**2. Arena for 临时数据**:
```rust
use bumpalo::Bump;

let arena = Bump::new();
let temp_data: &mut [u32] = arena.alloc_slice_fill_with(1000, |_| 0);
// arena drop → temp_data 自动释放
```

**3. Arc for 长期共享**:
```rust
let shared = Arc::new(ExpensiveResource::new());
let cloned = Arc::clone(&shared);
// 两个 owner 都 drop → resource 释放
```

**4. Weak for cache**:
```rust
let weak: Weak<Resource> = Arc::downgrade(&strong);
// cache 不阻止 strong 释放
if let Some(strong) = weak.upgrade() {
    // 还在用
} else {
    // 已释放
}
```

**5. Pool for 高频 alloc**:
```rust
let pool = ObjectPool::new(|| ExpensiveObject::new());
let obj = pool.acquire();  // 复用
// ...
pool.release(obj);  // 不 drop,放回 pool
```

工业 Rust 代码综合用这些模式。
