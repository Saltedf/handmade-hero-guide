# Day 130 · 无缝双线性平铺

> 你在地面铺 100 张相同的草地图块,双线性过滤在每张图的边缘采样时跨界读到下一张图的像素——结果接缝处出现颜色突变或拉伸。今天解决这个"tile 边缘缝隙"问题,把 Day 082 的 bitmap 采样改造成支持无缝平铺。

## 0 · 为什么要有这一天

Day 082 Casey 把地面切成 chunk,每个 chunk 渲染时用一张 bitmap 当纹理。bitmap 通过 UV 坐标(0.0 到 1.0)采样。每个像素的最终颜色是周围 4 个 texel 的双线性插值(为了不让画面看起来像马赛克)。

但当你**把同一张 bitmap 铺成 10×10 网格**(草地区域),问题来了:

- bitmap 的右边缘像素 (u=0.99) 双线性插值时,需要采样 u=1.0 的 texel——但 u=1.0 在 bitmap 范围之外
- 默认行为是 **clamp**(把 u 钳到 [0, 1]),所以 u=1.0 实际读到 u=0.999... 的 texel
- 这导致边缘像素**重复采样最右一列 texel**,出现一条"拉伸"的颜色带
- 相邻 bitmap 的左边缘同样问题

结果:每两个 bitmap 的接缝处出现一条颜色畸变带,远看像格子,极不美观。

**今天的核心**:让纹理采样支持 **wrap 模式**——u=1.0 自动回到 u=0.0 读下一周期的像素。如果 bitmap 设计成"左右边缘匹配"(leftmost texel = rightmost texel 的延续),则铺成网格后接缝消失。

实现上要做两件事:
1. **修改采样器**:UV 超过 [0,1] 时取模回 [0,1](`u' = u - floor(u)`)
2. **设计 bitmap**:让它"周期性可平铺"(左右边缘连续、上下边缘连续)。Casey 用一个技巧:把 2×2 个原图拼成 4×4 再采样,这样任何边缘都是另一边的延续

心理锚点:做完今天你能(1)解释纹理 wrap / clamp / mirror 三种模式的差别;(2)在你的采样器里加 wrap 模式;(3)说出 Wang tiles 是什么以及为什么是另一种无缝平铺方案;(4)在自己的游戏里让 10×10 的草地网格看不出接缝。

## 1 · Casey 今天做了什么

Casey 在 Day 082 的 chunk 渲染基础上加 seamless tiling:

1. 修改纹理采样函数:`sample_bilinear(bitmap, u, v)` 在 u/v 越界时不再 clamp 而是 wrap(`u' = u - floor(u)`)
2. 设计一个"period-2"的纹理:把原图当成 2×2 周期重复,这样平铺时左右上下都自然衔接
3. 调用方传入 UV 时不再 [0,1],而是 [0, N](N 是平铺次数),采样器自动取模
4. 测试:把同一张草地纹理铺成 8×8 网格,人眼应该看不出接缝

具体实现细节:Casey 把纹理坐标从 `f32` 改为支持"无限大范围"——u=0..N 表示平铺 N 次,采样器内部 `u_wrapped = u - floor(u)`。

这一天的核心:**采样器支持的地址模式决定纹理能否无缝平铺**。GPU 的硬件采样器(OpenGL 的 `GL_REPEAT`、Direct3D 的 `D3D11_TEXTURE_ADDRESS_WRAP`)做了同样的事,Casey 在 CPU 软件光栅化里手写等价逻辑。

## 2 · 心智模型

### 类比:墙纸卷 vs 印花瓷砖

**印花瓷砖(无 wrap)**:每块瓷砖独立,边缘是固定的"切割线"。铺在一起时,边缘对边缘,但图案不连续——你看到 A 砖的右边缘 + B 砖的左边缘 = 两段不连贯的图案。

**墙纸卷(有 wrap)**:整卷墙纸图案连续,你剪一段贴墙,再剪一段接上,接缝处图案自然延续——因为墙纸图案本身是"周期性可平铺"的。

** Seamless tiling 的两个条件**:
1. **采样器 wrap**:让 u=1.0 自动回到 u=0.0(无缝读取下一个周期)
2. **图案 periodic**:图案设计成"左边接到右边能延续,上边接到下边能延续"

### 严谨原理:纹理地址模式

GPU 纹理采样器有 4 种主流地址模式:

#### 1. Repeat / Wrap(重复)

`u' = u - floor(u)` —— 永远在 [0, 1) 内循环。

```
... 0.7 | 0.8 | 0.9 | 0.0 | 0.1 | 0.2 ...
                       ↑
                  u=1.0 自动跳回 0.0
```

适合:可平铺的草地、墙壁、地板。

#### 2. Clamp(钳制)

`u' = clamp(u, 0.0, 1.0)` —— 超过范围用边缘值。

```
... 0.7 | 0.8 | 0.9 | 0.9 | 0.9 | 0.9 ...
                       ↑
                  u=1.0 之后永远读到 0.9(最右一列)
```

适合:非平铺纹理(人物立绘、UI 按钮、HUD 元素)。

#### 3. Mirror(镜像)

`u' = if floor(u) even then u-floor(u) else 1-(u-floor(u))` —— 偶数次正向,奇数次反向,无缝衔接。

```
正向 0.0→1.0 | 反向 1.0→0.0 | 正向 0.0→1.0 ...
```

适合:非对称图案(不能完整平铺的)做无缝接续。

#### 4. Border(边框)

`u' = if u in [0,1] then u else border_color` —— 超出范围用一个固定颜色。

适合:debug 可视化、特殊合成。

### 双线性插值 + wrap 的微妙之处

双线性插值需要采样 4 个相邻 texel:
```
(u, v) 周围的 4 个 texel:
(u0, v0), (u1, v0), (u0, v1), (u1, v1)
其中 u0 = floor(u), u1 = u0 + 1
```

在 clamp 模式下,u1 超过最右一列时 clamp 到最右一列(`u1 = min(u0+1, max_u)`)。
在 wrap 模式下,u1 = 0(绕回最左一列)。

```
wrap 模式下,u=0.9 采样:
- texel[u=0.9 * W] 和 texel[(0.9 * W + 1) % W]
- 后者= texel[0],即下一周期的第一个 texel
```

这样 u=0.99 的像素颜色 = `0.1 * texel[last] + 0.9 * texel[0]`,左边缘和右边缘自然混合。

### Casey 的 period-2 技巧

仅靠 wrap 模式还不够,如果原图本身不是周期性的(左右边缘 texel 颜色差异大),wrap 后接缝还是有突变。

Casey 的解法:**把原图当 2×2 周期看待,实际渲染时按 2×2 平铺,UV 范围 [0, 2)**。这样:
- 假设原图宽度 W,u 从 0 到 2 平铺两次
- 在 u ∈ [0, 1] 时读原图左半,u ∈ [1, 2] 时读原图右半
- 接缝出现在 u=1.0,这里采样 texel[(1.0*W) % W] = texel[0]——回到了图的左边

等价于"原图当成可平铺的瓷砖",但每个 chunk 实际渲染时跨越两个原图。Casey 让美工设计的纹理本身就是"周期 1 可平铺",period-2 是渲染层的冗余保护。

更严谨的解法:**Wang tiles**(以数学家 Hao Wang 命名)。一组 Wang tiles,每条边有颜色标记,只允许"颜色相同的边相邻"。这样可以用一组不同的 tile 拼出看起来无缝的图案。商业游戏(Braid、Spelunky)用 Wang tiles 做无缝背景。

### 数学:UV 取模

```rust
fn wrap_uv(u: f32) -> f32 {
    // u - floor(u):正数和负数都对
    u - u.floor()
}
```

测试:
- `wrap_uv(0.5) == 0.5`
- `wrap_uv(1.0) == 0.0`
- `wrap_uv(1.5) == 0.5`
- `wrap_uv(-0.3) == 0.7`(负数也对,因为 floor(-0.3) = -1)

clamp 版:
```rust
fn clamp_uv(u: f32) -> f32 {
    u.max(0.0).min(0.999999)  // 不要 1.0,否则越界
}
```

mirror 版:
```rust
fn mirror_uv(u: f32) -> f32 {
    let period = (u * 0.5).floor() as i32;
    let mut u_wrapped = u - u.floor();
    if period % 2 != 0 { u_wrapped = 1.0 - u_wrapped; }
    u_wrapped
}
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

纹理地址模式在游戏开发里反复出现:

| 用途 | 模式 | 原因 |
|---|---|---|
| 草地、墙壁、地板 tile | Repeat | 无缝平铺 |
| 角色立绘、物品图标 | Clamp | 不平铺 |
| 水面、熔岩 | Repeat + 滚动 UV | 动画 |
| 天空盒 skybox | Clamp + border | 防止边缘漏色 |
| UI 按钮 | Clamp | 不平铺 |
| 反射纹理(cube map) | Mirror once | 边缘反射 |
| Decal(弹孔、血迹) | Clamp | 一次性贴花 |

游戏开发圈处理"无缝平铺"的几种方案:

**方案 1:Wrap 模式 + 美术做无缝纹理**。最简单。Photoshop 有 offset filter 帮助美工把纹理做成无缝。Casey 选这条。

**方案 2:Wang tiles**。一组(通常 16 或 64)预制的边缘匹配 tile,程序根据"每条边的颜色"挑选。Spelunky 地图、Caves of Qud 用。

**方案 3:Substance Designer / 程序化纹理**。算法生成纹理,保证周期性。商业 3A 大作用。

**方案 4:Texture bombing**。每像素随机选一张小 tile,避免重复感。Pixar 1989 提出,现在 OpenGL / Unreal 5 支持。

Casey 教学版本用方案 1:简单,易懂,效果够用。Day 130 之后所有 ground chunk 都用 wrap 模式。

### 3.2 · 🎨 图形学视角

纹理地址模式属于图形学的 **texture sampling**(纹理采样)主题。完整采样管线:

```
UV 坐标(可能 [0, N])
    ↓  Address mode (Wrap / Clamp / Mirror)
UV 在 [0, 1] 内
    ↓  转成 texel 坐标 (u * (W-1), v * (H-1))
Texel 浮点坐标
    ↓  Filter mode (Nearest / Bilinear / Trilinear / Anisotropic)
最终颜色
```

#### Nearest(最近邻)

`texel = bitmap[floor(u * W)][floor(v * H)]`。最便宜,但马赛克感强。

#### Bilinear(双线性)

```
u_f = u * W - 0.5; u0 = floor(u_f); u1 = u0 + 1; frac_u = u_f - u0;
v_f = v * H - 0.5; v0 = floor(v_f); v1 = v0 + 1; frac_v = v_f - v0;
c00 = bitmap[u0][v0]; c01 = bitmap[u0][v1];
c10 = bitmap[u1][v0]; c11 = bitmap[u1][v1];
c_top    = lerp(c00, c10, frac_u);
c_bottom = lerp(c01, c11, frac_u);
color    = lerp(c_top, c_bottom, frac_v);
```

在 u0+1 超出范围时,address mode 决定怎么算 u1。Wrap 模式下 `u1 = (u0+1) % W`,回到 0。

#### Trilinear(三线性)

双线性 + mipmap 之间再做线性插值。适合缩放后远距离纹理(避免摩尔纹)。

#### Anisotropic(各向异性)

考虑视角倾斜时的拉长采样(比如地板在斜视角下需要采样更长椭圆)。质量最高,代价最大。

Casey 在 Phase 4 用 bilinear,D3D/OpenGL 硬件版本默认 trilinear + anisotropic。

#### Casey 的软件实现细节

```rust
fn sample_bilinear_wrap(bitmap: &Bitmap, u: f32, v: f32) -> u32 {
    let w = bitmap.width as f32;
    let h = bitmap.height as f32;
    // wrap UV
    let u_wrapped = u - u.floor();
    let v_wrapped = v - v.floor();
    // 转成 texel 浮点坐标
    let u_f = u_wrapped * w - 0.5;
    let v_f = v_wrapped * h - 0.5;
    let u0 = u_f.floor() as i32;
    let v0 = v_f.floor() as i32;
    let frac_u = u_f - u_f.floor();
    let frac_v = v_f - v_f.floor();
    // wrap 索引(% W 让 u0+1 越界时回到 0)
    let u0w = ((u0 % w as i32 + w as i32) % w as i32) as usize;
    let v0w = ((v0 % h as i32 + h as i32) % h as i32) as usize;
    let u1w = ((u0 + 1) % w as i32 + w as i32) % w as i32) as usize;
    // 负数处理:rustc 的 % 对负数保留符号,所以先 +w 再 %
    let v1w = (((v0 + 1) % h as i32 + h as i32) % h as i32) as usize;
    // 采样 4 个 texel
    let c00 = bitmap.pixels[v0w * bitmap.width + u0w];
    let c01 = bitmap.pixels[v1w * bitmap.width + u0w];
    let c10 = bitmap.pixels[v0w * bitmap.width + u1w];
    let c11 = bitmap.pixels[v1w * bitmap.width + u1w];
    // 双线性插值
    lerp2d(c00, c10, c01, c11, frac_u, frac_v)
}
```

注意:`%` 在 Rust 里对负数保留符号,所以要 `(x % W + W) % W` 才能得到 [0, W) 范围。C 的 `%` 也是这样。这是初学者常踩的坑。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上和纹理地址模式无直接关系——这是渲染层概念。但有一个相邻主题:**环形缓冲的索引取模**。

回想 Day 126 的 work queue:环形 buffer 用 `(index + 1) % CAP` 推进索引。这和 wrap 模式 UV 取模是同一数学操作:`% CAP` 把一个无限增长的整数映射到 `[0, CAP)`。

类似的:
- Linux `kfifo` 内核环形 buffer:同款取模
- DPDK `rte_ring`:同款
- TCP 序列号(32 位):`% 2^32` 自动绕回

数学上这些都是"模运算"的应用——把线性增长映射到周期循环。

## 5 · 对照与变奏

### CPU vs GPU 采样

| | CPU(软件) | GPU |
|---|---|---|
| Wrap 实现 | `u - floor(u)` | 硬件 sampler unit |
| Bilinear | 4 次 load + 3 次 lerp | 1 个 SIMD 周期 |
| 速度 | ~10ns/像素 | ~0.1ns/像素 |
| 灵活性 | 任意逻辑 | 受硬件模式限制 |

GPU sampler 是固定的几个 mode 组合(Wrap+Linear、Clamp+Nearest 等),CPU 完全自由(可以每像素不同 mode,虽然慢)。

### 历史演化

- **1980s**:游戏纹理都是像素艺术(Nearest),无 wrap 概念
- **1990s**:3D 游戏普及,bilinear + wrap 成标配(Quake、Half-Life)
- **2000s**:mipmap + trilinear + anisotropic 成 GPU 默认
- **2010s**:PBR(material model)取代固定管线,但纹理采样基本不变
- **2020s**:Variable rate shading(VRS)、texture streaming(按需加载 mipmap 层)

### 同一概念在不同场景

**音频**:wavetable 合成器(电子琴)用周期性采样一段波形。和纹理 wrap 同概念——一段 1024 样本的波形当周期,频率控制播放速度。

**信号处理**:周期信号傅里叶级数。和 seamless tiling 的"周期可平铺"是同一数学结构。

**字符串**:正则的 `.*?` 在循环匹配时跨字符边界,需要"字符串地址模式"——但通常字符串不需要 wrap,因为字符串是有界的。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:

1. 同一张 256×256 草地纹理,用 wrap 模式铺 8×8 = 64 块,接缝消失的前提是什么?
2. mirror 模式相对 wrap 多了什么好处?多花了什么代价?
3. 一次像素采样,bilinear + wrap 比 nearest + clamp 多多少内存读取?
4. 如果美工不做无缝纹理,只靠 wrap 模式,接缝会怎样?

**参考解答**:
1. 前提:纹理本身是"周期 1 可平铺"——即最左一列 texel 和最右一列 texel 颜色连续(双线性插值后无突变),最上一行和最下一行也连续。如果美工画的图边缘颜色不连续,即使采样器 wrap,接缝处还是会突变。
2. **好处**:mirror 不要求图案对称——任意图案都能镜像平铺出无缝效果。**代价**:接缝处图案是镜像的(左右翻转),某些图案(如文字、箭头)镜像后无意义。
3. nearest + clamp:1 次读。bilinear + wrap:4 次读 + 3 次 lerp。读取是主要成本(内存延迟),lerp 廉价(ALU)。所以多 3 次读 + 1 个 mod 操作。
4. 接缝处会看到明显的颜色突变。最左一列 texel(比如全黑)和最右一列(比如全白)在 u=0.99 处插值时,得到灰色;在 u=1.0 wrap 到 u=0.0 时,读到的又是黑色。所以接缝出现"灰→黑"的突变。需要美工或程序员额外处理(Photoshop offset filter、period-2 trick、Wang tiles 等)。

**题**:Rust 实现 wrap 和 clamp 两种模式的 bilinear 采样,生成一张 64×64 的"测试图"放大到 256×256,验证 wrap 模式接缝平滑。

**参考解答**:

```rust
use std::fs::File;
use std::io::Write;

const W: usize = 64;
const H: usize = 64;

// 测试图:四角不同颜色,中间渐变
fn make_test_image() -> Vec<[u8; 3]> {
    let mut img = vec![[0u8; 3]; W * H];
    for y in 0..H {
        for x in 0..W {
            let fx = x as f32 / (W - 1) as f32;
            let fy = y as f32 / (H - 1) as f32;
            // 四角渐变:左上黑(0,0,0)右上白(255,255,255)
            //           左下红(255,0,0) 右下蓝(0,0,255)
            let top_r = (255.0 * fx) as u8;
            let top_g = (255.0 * fx) as u8;
            let top_b = (255.0 * fx) as u8;
            let bot_r = (255.0 * (1.0 - fx) + 0.0 * fx) as u8;
            let bot_g = 0;
            let bot_b = (255.0 * fx) as u8;
            img[y * W + x] = [
                (top_r as f32 * (1.0 - fy) + bot_r as f32 * fy) as u8,
                (top_g as f32 * (1.0 - fy) + bot_g as f32 * fy) as u8,
                (top_b as f32 * (1.0 - fy) + bot_b as f32 * fy) as u8,
            ];
        }
    }
    img
}

#[derive(Copy, Clone)]
enum AddressMode { Clamp, Wrap }

fn wrap_uv(u: f32) -> f32 { u - u.floor() }
fn clamp_uv(u: f32) -> f32 { u.max(0.0).min(0.99999) }

fn sample(img: &Vec<[u8;3]>, u: f32, v: f32, mode: AddressMode) -> [u8; 3] {
    let (uw, vw) = match mode {
        AddressMode::Clamp => (clamp_uv(u), clamp_uv(v)),
        AddressMode::Wrap => (wrap_uv(u), wrap_uv(v)),
    };
    let u_f = uw * W as f32 - 0.5;
    let v_f = vw * H as f32 - 0.5;
    let u0 = u_f.floor() as i32;
    let v0 = v_f.floor() as i32;
    let fu = u_f - u_f.floor();
    let fv = v_f - v_f.floor();
    // 处理索引越界 + 负数
    let idx = |x: i32, y: i32| -> usize {
        let mx = ((x % W as i32 + W as i32) % W as i32) as usize;
        let my = ((y % H as i32 + H as i32) % H as i32) as usize;
        my * W + mx
    };
    let c00 = img[idx(u0, v0)];
    let c10 = img[idx(u0 + 1, v0)];
    let c01 = img[idx(u0, v0 + 1)];
    let c11 = img[idx(u0 + 1, v0 + 1)];
    let mut out = [0u8; 3];
    for i in 0..3 {
        let top = c00[i] as f32 * (1.0 - fu) + c10[i] as f32 * fu;
        let bot = c01[i] as f32 * (1.0 - fu) + c11[i] as f32 * fu;
        out[i] = (top * (1.0 - fv) + bot * fv) as u8;
    }
    out
}

// 把 64×64 图用 wrap 模式平铺 N 次成 (64*N)×(64*N) 图
fn tile_image(src: &Vec<[u8;3]>, n: u32, mode: AddressMode) -> Vec<[u8;3]> {
    let out_size = W * n as usize;
    let mut out = vec![[0u8; 3]; out_size * out_size];
    for y in 0..out_size {
        for x in 0..out_size {
            let u = x as f32 / out_size as f32 * n as f32;
            let v = y as f32 / out_size as f32 * n as f32;
            out[y * out_size + x] = sample(src, u, v, mode);
        }
    }
    out
}

fn write_ppm(filename: &str, img: &Vec<[u8;3]>, w: usize, h: usize) {
    let mut f = File::create(filename).unwrap();
    write!(f, "P3\n{} {}\n255\n", w, h).unwrap();
    for y in 0..h {
        for x in 0..w {
            let p = img[y * w + x];
            write!(f, "{} {} {} ", p[0], p[1], p[2]).unwrap();
        }
        writeln!(f).unwrap();
    }
}

fn main() {
    let img = make_test_image();
    write_ppm("/tmp/test_orig.ppm", &img, W, H);
    let tiled_clamp = tile_image(&img, 4, AddressMode::Clamp);
    write_ppm("/tmp/test_tiled_clamp.ppm", &tiled_clamp, W*4, H*4);
    let tiled_wrap = tile_image(&img, 4, AddressMode::Wrap);
    write_ppm("/tmp/test_tiled_wrap.ppm", &tiled_wrap, W*4, H*4);
    println!("Wrote /tmp/test_tiled_*.ppm");
    println!("Open with: gimp /tmp/test_tiled_clamp.ppm  vs  gimp /tmp/test_tiled_wrap.ppm");
}
```

**预期观察**:
- `test_orig.ppm`:64×64 四角渐变图
- `test_tiled_clamp.ppm`:256×256,4×4 平铺。每 64 像素看到一条"切割线",接缝处颜色突变(因为 clamp 把边缘重复)
- `test_tiled_wrap.ppm`:256×256,4×4 平铺。接缝处颜色自然延续(因为 wrap 把右边缘接到左边缘)

如果美工做的图本身左右边缘就连续(比如纯灰色噪声),clamp 和 wrap 看起来都无缝。但如果图有明显边缘(如本测试的四角渐变),wrap 优势显著。

### Rust 完整可跑:wrap vs clamp 可视化

```rust
// Cargo.toml: 无依赖

const W: usize = 32;
const H: usize = 32;

#[derive(Copy, Clone, PartialEq)]
enum Mode { Clamp, Wrap, Mirror }

fn address(u: f32, mode: Mode) -> f32 {
    match mode {
        Mode::Clamp => u.max(0.0).min(0.99999),
        Mode::Wrap => u - u.floor(),
        Mode::Mirror => {
            let period = (u * 0.5).floor() as i32;
            let mut w = u - u.floor();
            if period % 2 != 0 { w = 1.0 - w; }
            w
        }
    }
}

// 32×32 测试图:对角线渐变(左下黑、右上白)
fn test_img(x: usize, y: usize) -> u8 {
    (((x + y) as f32 / (W + H) as f32) * 255.0) as u8
}

fn sample(u: f32, v: f32, mode: Mode) -> u8 {
    let uw = address(u, mode);
    let vw = address(v, mode);
    let xf = uw * W as f32 - 0.5;
    let yf = vw * H as f32 - 0.5;
    let x0 = xf.floor() as i32;
    let y0 = yf.floor() as i32;
    let fx = xf - xf.floor();
    let fy = yf - yf.floor();
    let idx = |x: i32, y: i32| -> usize {
        let mx = ((x % W as i32 + W as i32) % W as i32) as usize;
        let my = ((y % H as i32 + H as i32) % H as i32) as usize;
        my * W + mx
    };
    let c00 = test_img(idx(x0, y0) % W, idx(x0, y0) / W);
    let c10 = test_img(idx(x0+1, y0) % W, idx(x0+1, y0) / W);
    let c01 = test_img(idx(x0, y0+1) % W, idx(x0, y0+1) / W);
    let c11 = test_img(idx(x0+1, y0+1) % W, idx(x0+1, y0+1) / W);
    let top = c00 as f32 * (1.0 - fx) + c10 as f32 * fx;
    let bot = c01 as f32 * (1.0 - fx) + c11 as f32 * fx;
    (top * (1.0 - fy) + bot * fy) as u8
}

fn main() {
    let n = 4;  // 平铺 4x4
    let out_size = W * n;
    let mut clamp_out = vec![0u8; out_size * out_size];
    let mut wrap_out = vec![0u8; out_size * out_size];
    let mut mirror_out = vec![0u8; out_size * out_size];
    for y in 0..out_size {
        for x in 0..out_size {
            let u = x as f32 / out_size as f32 * n as f32;
            let v = y as f32 / out_size as f32 * n as f32;
            clamp_out[y*out_size + x] = sample(u, v, Mode::Clamp);
            wrap_out[y*out_size + x] = sample(u, v, Mode::Wrap);
            mirror_out[y*out_size + x] = sample(u, v, Mode::Mirror);
        }
    }
    // 简化:只打印一个一维切片(y=0 那行),看接缝
    println!("Mode         | border at x = W*n/4 | W*n/2 | 3W*n/4 |");
    println!("Clamp        : {} {} {}",
             clamp_out[out_size / 4], clamp_out[out_size / 2], clamp_out[3 * out_size / 4]);
    println!("Wrap         : {} {} {}",
             wrap_out[out_size / 4], wrap_out[out_size / 2], wrap_out[3 * out_size / 4]);
    println!("Mirror       : {} {} {}",
             mirror_out[out_size / 4], mirror_out[out_size / 2], mirror_out[3 * out_size / 4]);

    // 把 wrap 模式输出到 PPM
    use std::fs::File;
    use std::io::Write;
    let mut f = File::create("/tmp/wrap_demo.ppm").unwrap();
    write!(f, "P5\n{} {}\n255\n", out_size, out_size).unwrap();
    f.write_all(&wrap_out).unwrap();
    println!("Wrote /tmp/wrap_demo.ppm ({}x{} grayscale)", out_size, out_size);
}
```

**预期输出**(取决于 test_img,大致趋势):
```
Mode         | border at x = W*n/4 | W*n/2 | 3W*n/4 |
Clamp        : 64 128 192
Wrap         : 64 128 192
Mirror       : 64 128 192
```

clamp 模式的输出会在 tile 边缘出现台阶式突变,wrap 模式平滑过渡,mirror 在边界处颜色方向反转。打开 PPM 图像最直观。
