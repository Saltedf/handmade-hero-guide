
# Day 169 · 文本对齐到基线

> Day 168 渲染时用了 `bearing_y`,但没完全解释。今天 Casey 仔细讲**字体度量(font metrics)**:ascent / descent / line gap / baseline,以及如何让多行文本**基线对齐**,看起来整齐。

## 0 · 为什么要有这一天

看一段文字:

```
Hello
abcde
```

"a"、"b"、"c" 在基线(baseline)上,"d" 也在基线,但顶部高于"a"。"g"、"p" 顶部在基线,但**底部低于基线**(descender)。

如果不用 baseline 对齐,不同字母看起来"东倒西歪":

```
bad:
HelLo     ← L 高
abcde

good:
Hello
abcde
```

baseline 是字体的"地平线"。所有字符在 baseline 上下浮动。文本行的"位置"= baseline 位置,不是顶部。

字体度量:

- **ascent**:baseline 到最高点(如 "h" 顶部)
- **descent**:baseline 到最低点(如 "g" 底部,负数)
- **line gap**:额外行间距
- **line height**:ascent - descent + line gap

`line_height` 决定多行文本的行间距。

心理锚点:看完今天,你能让多行文本整齐对齐,理解为什么 "Hello" 和 "abcde" 在同一基线上看起来对。

## 2 · 心智模型

### 类比:小学生写字本

写字本有横线,每条横线是 baseline。学生被要求把字母写在 baseline 上:

- 大写字母占满 baseline 到上方
- 小写 "a" 在 baseline 上,顶部在 x-height
- 小写 "g" 在 baseline 上下(下到 descender)

不同字母高低不一,但**共享 baseline**,看起来整齐。

### 严谨模型:字体度量

```
                  ─── ascent(最高点,baseline 上方)
                  ↑
              h   │
H   b   d   e     │ cap height(大写顶部)
                  │
a   c   e   x     │ x height(小写顶部)
                  ↓
─────────────── baseline ───
                  ↑
g   p   q   y     │ descent(底部,baseline 下方,负数)
                  ↓
                  ─── bottom of em square
```

字体在 em square 里设计。1 em = font_size(像素)。

度量数值(以 DejaVu Sans 16px 为例):

- ascent: 14px
- descent: -4px
- line gap: 1px
- line height: 19px

所以 16px 字体行高约 19px。

### glyph 的 bearing_y

每 glyph 有 bearing_y:glyph 顶部相对 baseline 的距离。

```
baseline_y - bearing_y = glyph 顶部 y
```

例:`'H'` 的 bearing_y = 12,顶部在 baseline - 12。`'g'` 的 bearing_y = 12(顶部),但 height = 16(包含 4px descender),底部在 baseline + 4。

### 多行布局

```rust
let line_height = font.line_height;
let mut baseline_y = y + font.ascent;  // y 是 line top,ascent 后到 baseline

for line in lines {
    draw_string_at_baseline(fb, font, line, x, baseline_y, color);
    baseline_y += line_height;
}
```

注意:**y 是 line top**,不是 baseline。baseline = y + ascent。

### 不同字体的度量差异

```
Times:ascent 13, descent -3, line 16
Arial:ascent 14, descent -4, line 19
DejaVu:ascent 14, descent -4, line 19
```

不同字体同样字号,行高不同。要混排时,用 max(line_height)统一。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 line_height = ascent - descent + line_gap,而不是 ascent + descent?

**参考解答**:descent 通常是负数(baseline 下方距离用负值)。ascent 是正(baseline 上方)。`ascent - descent` = ascent + |descent| = 整行高度。再加 line_gap 是额外间距。

如果 descent 是正数(某些 API),则 ascent + descent。约定问题。

### Lv2 · 动手实践

**题**:修改 Day 168 的代码,加 baseline 概念:

1. Font 加 ascent / descent / line_gap 字段
2. draw_string 接受 baseline_y 参数(不是 top y)
3. 多行用 line_height 间距
4. 测试:"Hello\nabcde" 应该 baseline 对齐

**参考解答**:

```rust
struct Font {
    glyphs: Vec<Glyph>,
    ascent: f32,
    descent: f32,        // 负数
    line_gap: f32,
}

impl Font {
    fn line_height(&self) -> f32 {
        self.ascent - self.descent + self.line_gap
    }
}

fn draw_text(fb: &mut [u32], fb_w: u32, fb_h: u32,
             font: &Font, text: &str, top_x: f32, top_y: f32, color: [u8; 3]) {
    let mut baseline = top_y + font.ascent;
    let mut cx = top_x;
    for c in text.bytes() {
        if c == b'\n' {
            cx = top_x;
            baseline += font.line_height();
            continue;
        }
        let g = match font.glyphs.get(c as usize) {
            Some(g) if g.char == c as u32 => g,
            _ => continue,
        };
        // glyph 顶部 = baseline - bearing_y
        for yy in 0..g.height {
            for xx in 0..g.width {
                let alpha = g.bitmap[(yy * g.width + xx) as usize];
                if alpha == 0 { continue; }
                let px = (cx + g.bearing_x + xx as f32) as i32;
                let py = (baseline - g.bearing_y + yy as f32) as i32;
                if px < 0 || px >= fb_w as i32 || py < 0 || py >= fb_h as i32 { continue; }
                let idx = (py as u32 * fb_w + px as u32) as usize;
                let a = alpha as f32 / 255.0;
                fb[idx] = (255 << 24)
                    | ((color[0] as f32 * a) as u32) << 16
                    | ((color[1] as f32 * a) as u32) << 8
                    | (color[2] as f32 * a) as u32;
            }
        }
        cx += g.advance;
    }
}
```

## 8 · Rust / Arch 落地代码

```rust
#[derive(Clone)]
struct Glyph {
    char: u32,
    bitmap: Vec<u8>,
    width: u32,
    height: u32,
    advance: f32,
    bearing_x: f32,
    bearing_y: f32,  // glyph 顶部相对 baseline
}

struct Font {
    glyphs: Vec<Glyph>,
    ascent: f32,
    descent: f32,     // 负数
    line_gap: f32,
}

impl Font {
    fn line_height(&self) -> f32 {
        self.ascent - self.descent + self.line_gap
    }

    fn demo() -> Self {
        // 模拟字体
        let make_glyph = |c: u8, w: u32, h: u32, advance: f32, bx: f32, by: f32| {
            let mut bitmap = vec![0u8; (w * h) as usize];
            for y in 0..h as usize {
                for x in 0..w as usize {
                    bitmap[y * w as usize + x] = ((x + y + c as usize) % 4 == 0) as u8 * 200;
                }
            }
            Glyph { char: c as u32, bitmap, width: w, height: h, advance, bearing_x: bx, bearing_y: by }
        };

        let mut glyphs = vec![make_glyph(0, 0, 0, 0.0, 0.0, 0.0); 256];
        // 大写:8x10,bearing_y = 10(顶部到 baseline)
        for c in b'A'..=b'Z' {
            glyphs[c as usize] = make_glyph(c, 8, 10, 9.0, 0.0, 10.0);
        }
        // 小写:8x7,bearing_y = 7(顶部到 baseline)
        for c in b'a'..=b'z' {
            glyphs[c as usize] = make_glyph(c, 8, 7, 8.0, 0.0, 7.0);
        }
        // 'g','p','q','y' 是 descender:height 10,bearing_y = 7
        for c in [b'g', b'p', b'q', b'y'] {
            glyphs[c as usize] = make_glyph(c, 8, 10, 8.0, 0.0, 7.0);
        }
        // space
        glyphs[b' ' as usize] = make_glyph(b' ', 0, 0, 5.0, 0.0, 0.0);

        Self {
            glyphs,
            ascent: 12.0,
            descent: -4.0,
            line_gap: 2.0,
        }
    }
}

fn draw_text(fb: &mut [u32], fb_w: u32, fb_h: u32,
             font: &Font, text: &str, top_x: f32, top_y: f32, color: [u8; 3]) {
    let mut baseline = top_y + font.ascent;
    let mut cx = top_x;

    for c in text.bytes() {
        if c == b'\n' {
            cx = top_x;
            baseline += font.line_height();
            continue;
        }
        let g = match font.glyphs.get(c as usize) {
            Some(g) if g.char == c as u32 => g,
            _ => continue,
        };
        for yy in 0..g.height {
            for xx in 0..g.width {
                let alpha = g.bitmap[(yy * g.width + xx) as usize];
                if alpha == 0 { continue; }
                let px = (cx + g.bearing_x + xx as f32) as i32;
                let py = (baseline - g.bearing_y + yy as f32) as i32;
                if px < 0 || px >= fb_w as i32 || py < 0 || py >= fb_h as i32 { continue; }
                let idx = (py as u32 * fb_w + px as u32) as usize;
                let a = alpha as f32 / 255.0;
                fb[idx] = (255 << 24)
                    | (((color[0] as f32 * a) as u32) << 16)
                    | (((color[1] as f32 * a) as u32) << 8)
                    | (color[2] as f32 * a) as u32;
            }
        }
        cx += g.advance;
    }
}

fn main() {
    let fb_w = 256u32;
    let fb_h = 128u32;
    let mut fb = vec![0xFF000000u32; (fb_w * fb_h) as usize];

    let font = Font::demo();
    println!("ascent: {}, descent: {}, line_height: {}",
        font.ascent, font.descent, font.line_height());

    // 多行文本
    let text = "Hello\nabcde\nfghij";
    draw_text(&mut fb, fb_w, fb_h, &font, text, 10.0, 10.0, [255, 255, 255]);

    // 输出 PPM
    use std::io::Write;
    let mut f = std::fs::File::create("baseline.ppm").unwrap();
    writeln!(f, "P3\n{} {}\n255", fb_w, fb_h).unwrap();
    for y in 0..fb_h {
        for x in 0..fb_w {
            let p = fb[(y * fb_w + x) as usize];
            write!(f, "{} {} {}  ", (p >> 16) & 0xFF, (p >> 8) & 0xFF, p & 0xFF).unwrap();
        }
        writeln!(f).unwrap();
    }
    println!("wrote baseline.ppm");
}
```

**关键点**:
- `baseline = top_y + font.ascent`
- `glyph_y = baseline - bearing_y + yy`
- descender("g")的 bottom 在 baseline + (g.height - g.bearing_y)

## 10 · 补充材料:baseline、metrics 与排版

### A.1 字体 metrics 的完整结构

字体 metrics 是"字体的几何信息"—— Casey Day 169 处理 baseline 是其中一部分。完整 metrics 包括:

```
       ┌─────────────────┐ ← ascender line
       │      ┌───┐      │
       │      │ A │      │ ← cap height(大写字母顶部)
       │      └───┘      │
       │      ┌─┐        │
       │      │x│        │ ← x-height(小写字母 x 顶部)
       │      └─┘        │
       │     p           │ ← baseline(基线)
       ├─────────────────┤ ← descender line
       │      q  y        │ ← descender(下沉部分)
       └─────────────────┘
```

**Ascender**:字符上升部分的最大高度(从 baseline 算)
**Descender**:字符下沉部分的最大深度(从 baseline 算,负值)
**Cap height**:大写字母(A、B、C)的高度
**x-height**:小写字母 x 的高度(典型 = ascender 的 50-60%)
**Line gap**:行间距(ascender + descender + line gap = line height)

每个字体都有自己的 metrics,存在 OS/2 表和 hhea 表里。FreeType 提供 API 读取:

```rust
let size_metrics = face.size_metrics();
let ascender = size_metrics.ascender / 64;  // 26.6 fixed-point
let descender = size_metrics.descender / 64;
let height = size_metrics.height / 64;  // line height
```

### A.2 baseline 的精确定义

baseline 是"字符的视觉对齐线"。对拉丁字符,这是大写字母 A、B、C 的底部,也是小写字母 a、c、e 的底部。但有下沉的字符(q、y、p)会越过 baseline 进入 descender 区域。

为什么 baseline 重要?**字符在垂直方向的"位置"都相对于 baseline**。glyph 的 bearing_y(垂直 bearing)是"glyph 顶部相对 baseline 的偏移"。

```
绘制字符 'A':
- bearing_y = +10(glyph 顶部在 baseline 上方 10 像素)
- glyph 高度 = 10
- 所以 glyph 占据 [baseline-10, baseline]

绘制字符 'g'(有 descender):
- bearing_y = +7
- glyph 高度 = 12(超出 baseline 5 像素)
- 所以 glyph 占据 [baseline-7, baseline+5]
```

Casey 的 Day 169 修这个 bug——之前的代码 bearing_y 错误,glyph 位置上下偏。

### A.3 不同字体的 metrics 差异

同一字号的 Arial 和 Times New Roman metrics 不同:

```
                Arial 12px           Times 12px
Ascender        9px                  10px
Descender       -3px                 -3px
x-height        6px                  5px
Line height     14px                 15px
```

混合字体时(metrics 不一致),baseline 要对齐——所有字体的 baseline 在同一水平线,但 ascender / descender 不同。

CSS 的 `vertical-align: baseline` 就是这个语义。

### A.4 多行文本的 line height

多行文本的行间距 = line height(从一行 baseline 到下一行 baseline)。

```rust
fn draw_multiline(text: &str, x: f32, y: f32, line_height: f32) {
    let mut cursor_y = y;
    for line in text.lines() {
        draw_text(line, x, cursor_y);
        cursor_y += line_height;  // 下一行 baseline
    }
}
```

line height 通常 = font size × 1.2(印刷标准)。也可以由字体指定(face.size_metrics().height)。

CSS 的 `line-height: 1.5` 是相对 font-size 的倍数。

### A.5 垂直对齐

UI 设计常需要垂直居中文本:

```rust
fn draw_text_centered(text: &str, box_y: i32, box_height: i32, line_height: f32) {
    let text_height = line_height;
    let baseline_y = box_y + (box_height as f32 - text_height) / 2.0 + text_height * 0.8;
    // 0.8 是经验值——baseline 通常在 line height 的 80% 处
    draw_text(text, 0, baseline_y as i32);
}
```

或者用 metrics 精确计算:

```rust
fn draw_text_centered(face: &Face, text: &str, box_y: i32, box_height: i32) {
    let ascender = face.size_metrics().ascender / 64;
    let descender = face.size_metrics().descender / 64;
    let text_height = ascender - descender;
    let baseline_y = box_y as f32 + (box_height as f32 - text_height) / 2.0 + ascender;
    draw_text(text, 0, baseline_y as i32);
}
```

CSS 的 `line-height: box_height; vertical-align: middle` 是这个语义的简化。

### A.6 跨字号的 baseline 一致性

同一行文本里混合字号(如 H2 标题 + 小字注释),baseline 应该一致:

```
The Quick Brown Fox           ← 24px
The quick brown fox jumps     ← 12px
```

实现:每字号都有自己的 baseline,渲染时按各自的 baseline 对齐:

```rust
let baseline_y = 30;  // 共享 baseline
draw_text_at_baseline("The Quick Brown Fox", 24, baseline_y);
draw_text_at_baseline("The quick brown fox jumps", 12, baseline_y);
```

每个 `draw_text_at_baseline` 用自己字号的 metrics,但 y 坐标是同一 baseline。

### A.7 数字字体的特殊排版

数字字体有两套:tabular(等宽)和 proportional(变宽)。

- **Tabular**:"1" 和 "8" 等宽。适合对齐数字(财务报表)
- **Proportional**:"1" 比 "8" 窄。适合正文(更紧凑)

OpenType 的 `tnum` feature flag 控制。一般 UI 数字(分数、计时器)用 tabular。

```rust
// FreeType / HarfBuzz 启用 tnum
face.load_char('1', LoadFlag::RENDER);
// 通过 feature tag
shaper.set_feature("tnum", true);
```

游戏 UI 显示分数、生命值、时间——必须 tabular,否则数字跳动("100" → "200" 的 "0" 位置变化,视觉抖动)。

### A.8 行末对齐(justification)

两端对齐(justified)文本:每行的左右都对齐到边界。词与词之间加额外间距。

```
普通左对齐:
The quick brown fox jumps
over the lazy dog.

两端对齐:
The quick  brown  fox jumps   ← 词之间加宽
over  the  lazy  dog.
```

实现:测量每行总宽度,计算"需要填充多少",平均分配到词间。

```rust
fn justify_line(line: &str, target_width: f32, current_width: f32) -> Vec<f32> {
    let n_spaces = line.chars().filter(|&c| c == ' ').count();
    let extra = (target_width - current_width) / n_spaces as f32;
    // 每个空格的宽度 = 默认 + extra
    vec![extra; n_spaces]
}
```

最后一段不 justify(没有"行末"概念)。

### A.9 书写方向(RTL / TTB)

不同语言书写方向不同:

- **LTR**(left to right):英文、中文、俄文
- **RTL**(right to left):阿拉伯文、希伯来文
- **TTB**(top to bottom):传统中文、日文(竖排)

UI 必须支持 RTL/TTB,否则阿拉伯 / 希伯来用户没法用。CSS 的 `direction: rtl` 控制。

实现:Bidi algorithm(双向算法)分析每段文字的方向。Unicode 有专门的 Bidi 字符(U+202D LRE 等)。

```rust
use unicode_bidi::BidiInfo;

let text = "Hello سلام";  // 混合 LTR 和 RTL
let bidi_info = BidiInfo::new(text, None);
let paragraph = &bidi_info.paragraphs[0];
let line = paragraph.range;
let levels = bidi_info.levels[line.clone()];
// levels 告诉你每个字符的方向
```

工业级 RTL 支持需要 HarfBuzz + Bidi algorithm + layout 调整。复杂但必要。

### A.10 阅读体验的科学

排版不只是审美——有科学依据。眼动追踪研究显示:

- **行长度** 50-75 字符最适合阅读。太长眼睛回不到下一行,太短频繁换行打断节奏。
- **行间距** 1.4-1.6 倍字号最舒适。
- **字号** 16px 是 body text 的标准(印刷是 12pt = 16px @ 96DPI)。
- **对比度** 文本 vs 背景至少 4.5:1(WCAG AA 标准)。
- **字距** 别太紧(字粘在一起),别太松(看着像散沙)。

游戏 UI 设计时记住这些。Casey 的 HH 不重视阅读体验(教学项目),生产游戏必须。

### A.12 Casey 在视频里的具体修法

让我严肃讲讲 Casey Day 169 的实际代码改动。背景:之前的文本渲染代码把 glyph 的左上角放到 cursor 位置——错误。glyph 应该按 baseline 对齐,不是按顶部对齐。

**改动前**(错误):

```rust
fn draw_glyph(glyph: &Glyph, dst_x: i32, dst_y: i32) {
    // dst_y 当成"顶部"位置
    let top_y = dst_y;
    for y in 0..glyph.height {
        for x in 0..glyph.width {
            draw_pixel(dst_x + x, top_y + y, glyph.bitmap[y * glyph.width + x]);
        }
    }
}

fn draw_text(text: &str, x: i32, y: i32) {
    let mut cursor_x = x;
    for c in text.chars() {
        let glyph = get_glyph(c);
        draw_glyph(glyph, cursor_x, y);  // y 当顶部
        cursor_x += glyph.advance as i32;
    }
}
```

问题:不同字号的字符顶部对齐,但 baseline 不对齐。视觉上"字符底部不对齐",像漂浮。

**改动后**(正确):

```rust
fn draw_glyph(glyph: &Glyph, dst_x: i32, baseline_y: i32) {
    // dst_y 现在是 baseline,不是顶部
    // glyph 的顶部 = baseline_y - glyph.bearing_y
    let top_y = baseline_y - glyph.bearing_y;
    for y in 0..glyph.height {
        for x in 0..glyph.width {
            draw_pixel(dst_x + x + glyph.bearing_x, top_y + y,
                       glyph.bitmap[y * glyph.width + x]);
        }
    }
}

fn draw_text(text: &str, x: i32, baseline_y: i32) {
    let mut cursor_x = x;
    for c in text.chars() {
        let glyph = get_glyph(c);
        draw_glyph(glyph, cursor_x, baseline_y);
        cursor_x += glyph.advance as i32;
    }
}
```

**关键改动**:
1. 参数 `dst_y` 改名 `baseline_y`,语义明确
2. 计算 `top_y = baseline_y - glyph.bearing_y`(从 baseline 推回顶部)
3. 加 `glyph.bearing_x`(水平 bearing,glyph 不一定从 cursor 起始)

效果:字符按 baseline 对齐,视觉上"坐在"同一水平线。

### A.13 bearing_x 的必要性

某些字符的 glyph 不从 cursor 起始。例如 italic "f"——glyph 可能向左伸出 bearing_x = -2(超出 cursor 2 像素)。

如果不加 bearing_x,italic "f" 看起来错位(应该突出 cursor 但实际从 cursor 开始)。加 bearing_x 后,glyph 正确向左突出。

```rust
// 模拟 italic "f"
let italic_f_glyph = Glyph {
    bitmap: ...,
    width: 6,
    height: 12,
    advance: 4,    // advance 比 width 小!因为斜体"侵占"下一个字符位置
    bearing_x: -2, // 向左突出 2 像素
    bearing_y: 10,
};

// 渲染时:
// glyph 顶部 = baseline_y - 10
// glyph 左边 = cursor_x + (-2) = cursor_x - 2
// 即 glyph 向左超出 cursor 2 像素
```

工业字体大量有 italic / bearing_x 调整。Casey 的 HH 暂不处理 italic,但理解这个概念重要。

### A.14 kerning 和 metrics 的协同

kerning 是"字符对的特殊间距",和 metrics 不同:
- metrics 是"单字符的几何"(advance、bearing)
- kerning 是"字符对的间距修正"

两者协同:渲染时先按 metrics 排,再按 kerning 修正。

```rust
fn draw_text_with_kerning(text: &str, x: f32, baseline_y: i32) {
    let mut cursor_x = x;
    let chars: Vec<char> = text.chars().collect();
    
    for i in 0..chars.len() {
        let c = chars[i];
        let glyph = get_glyph(c);
        
        // Blit
        draw_glyph(glyph, cursor_x, baseline_y);
        
        cursor_x += glyph.advance;
        
        // 加 kerning 修正(下一个字符的间距)
        if i + 1 < chars.len() {
            let next_c = chars[i + 1];
            let kerning = get_kerning(c, next_c);
            cursor_x += kerning;
        }
    }
}
```

某些 kerning 是负值("AV" 之间收紧),某些是正值(罕见)。

### A.16 总结

Day 169 的核心修复是**baseline 对齐**——把"顶部对齐"改成"baseline 对齐"。这看似小改动,但视觉效果巨大。

**核心心智**:
- 字符位置以 baseline 为参考,不是顶部
- bearing_y 是 glyph 顶部相对 baseline 的偏移
- bearing_x 是 glyph 左边相对 cursor 的偏移
- kerning 是字符对的间距修正

**典型 bug**:
- ❌ 把 cursor_y 当顶部 → 字符底部不对齐
- ❌ 忽略 bearing_x → italic / 突出字符错位
- ❌ 忽略 kerning → 字符间距不均匀

**生产代码**:用 cosmic-text 或 HarfBuzz,自动处理所有 metrics 和 kerning。

Casey 的 Day 169 是手写实现的简化版,演示了 metrics 对齐的原理。
