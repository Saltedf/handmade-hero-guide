# Day 143 · 混音器中的变调

> 想象一个赛车的引擎声,转速从怠速 800 RPM 涨到 8000 RPM,声音的频率从低吼变成尖锐啸叫。如果你的音频系统只能"按原速播放",你只能预先录几十段不同 RPM 的音,做交叉淡入淡出——又丑又占空间。今天的任务:让 mixer **在播放时按任意速率重采样**,这样你只录一段,运行时调速率。

## 0 · 为什么要有这一天

声音的本质是空气压强随时间变化。**PCM 采样**是它在固定间隔(比如每 1/48000 秒)上的瞬时值。如果你按原速播放,频率就是录制时的频率;**如果你播放时跳过/重复一些 sample,就改变了频率**——这就是变调(pitch shifting)的核心思路。

为什么游戏需要变调?有 4 个典型场景:

1. **赛车引擎**:RPM 决定声音频率。一档怠速到红线转速频率差 10 倍。
2. **脚步声变化**:玩家加速跑,脚步频率加快。你不能录 10 套脚步,只能一套录音变速。
3. **战斗音乐**:进入战斗时音乐"加速"或"变调"提升紧张感。
4. **慢动作 / fast-forward**:游戏慢动作模式,所有声音也慢下来。

最朴素的变调方法叫 **线性插值重采样**(linear interpolation resampling)。Casey 今天实现的就是它。它简单、快,但有 artifacts(伪声)——对于 SFX 完全够用,对于音乐可能不够干净,工业级做法是 sinc 重采样(更贵但更准)。

今天除了变调本身,还要学两个新概念:

1. **采样率转换(sample rate conversion, SRC)** —— 数字信号处理的入门题
2. **定点数算术(fixed-point arithmetic)** —— 用整数模拟小数,既快又精确

定点数在游戏开发中无处不在(物理积分、动画时间、纹理坐标),今天是你第一次手写它。

心理锚点:看完今天,你能给 mixer 加一个 `playback_speed: f32` 字段,任意时刻外部设为 0.5(降八度)或 2.0(升八度),混音器内自动重采样,声音连续不爆音。

## 1 · Casey 今天做了什么

Casey 的代码改动是给每个 playing sound 加一个 `dSample` 字段(播放速率),并在 mixer 循环里改用"按 dSample 步进"的方式读源 buffer:

1. 引入一个浮点 / 定点的"播放指针"`sample_cursor`,初始化为 0
2. 每次输出一个 sample 时,从 `src[sample_cursor 整数部分]` 和 `src[sample_cursor 整数部分 + 1]` **线性插值**得到值
3. 把 `sample_cursor += dSample`(`dSample = 1.0` 是原速,`2.0` 是升一倍频率,`0.5` 是降一倍)
4. 当 `sample_cursor` 超过 src 长度时,如果循环就 mod,如果不循环就结束

Casey 在视频里讨论了几件事:

- **为什么用线性插值而不是直接取整?** 直接取整数位置相当于 nearest-neighbor,有可闻的"锯齿"伪声。线性插值平滑很多。
- **要不要用更高阶插值(三次、sinc)?** 线性对游戏 SFX 够用。sinc 是工业级,但每个输出要算 16+ 个输入,CPU 开销大。
- **dSample 大于 1 时,会跳过源 sample(降采样,downsampling);小于 1 时,会重复(上采样,upsampling)。两者都有 aliasing 问题**,但游戏里可以接受。

最终 Casey 选择了"浮点 cursor + 线性插值"。Day 145 用 SIMD 优化时这部分会再演化。

## 2 · 心智模型

### 类比:翻书

假设你有一本 100 页的书,我想听你"翻"它,但翻的速度可变:

- **原速**:翻 1 页/秒,100 页读完用 100 秒
- **快一倍**:翻 2 页/秒,50 秒读完
- **慢一半**:每 2 秒翻 1 页,200 秒读完
- **任意速率 1.7**:第 0 秒翻到第 0 页,第 1 秒翻到第 1.7 页...

但书是离散的——你不能"翻到第 1.7 页"。**两种做法**:

1. **Nearest-neighbor**:四舍五入,翻到第 2 页。会出现"跳过第 1 页"或"重复第 2 页"的伪声。
2. **线性插值**:看第 1 页和第 2 页的内容,按 0.7:0.3 混合。看起来更连续。

变调就是"翻音频缓冲这本册子",速率可变。

### 严谨模型:重采样数学

源 buffer 是离散序列 `s[0], s[1], ..., s[N-1]`。播放指针 `t` 是连续浮点数,初始 0。每个输出 sample:

```
i = floor(t)              // 整数部分
frac = t - i              // 小数部分
y = s[i] * (1 - frac) + s[i+1] * frac    // 线性插值
t += dSample              // 推进指针
```

`dSample` 含义:

- `1.0` —— 原速播放,每个输出对应一个输入
- `2.0` —— 升频一倍(每个输入跳一个),播放时长减半,频率升高一倍(变高八度)
- `0.5` —— 降频一倍,播放时长加倍,频率降低(变低八度)
- `1.5` —— 完美五度(音乐理论)

**为什么 dSample > 1 时有 aliasing?** 假设源信号有 20 kHz 分量,sample rate 48 kHz,根据奈奎斯特定理,48 kHz 能表示的最高频率是 24 kHz。当 dSample = 2,等于把 20 kHz 的"速率"提到 40 kHz,超过 24 kHz 的部分会"折回"产生伪声。

工业解决方案是 **插值前低通滤波**(抗混叠),但这超出今天范围。

### 定点数表示

如果用浮点 `t`,CPU 浮点加法每次 ~4 cycles,够快但有精度问题:百万次累加后浮点误差累积,小数部分漂移。

游戏行业用 **定点数**:把整数当小数用,比如 Q32.32 表示"32 位整数 + 32 位小数",整体是个 u64。

```
fixed_t = u64,其中高 32 位是整数,低 32 位是小数

dSample_fixed = (1.5 * 2^32) as u64   // 1.5 的定点表示
t = 0
loop:
    i = (t >> 32) as usize    // 整数部分
    frac = (t & 0xFFFF_FFFF) as f32 / 2^32   // 小数部分
    y = s[i] * (1 - frac) + s[i+1] * frac
    t = t.wrapping_add(dSample_fixed)
```

定点加法是整数加法,1 cycle,无精度漂移。Q32.32 精度足够大文件(数十亿 sample)。

**今天 Casey 没用定点,先用 f64**(浮点),够用。Day 145 SIMD 时如果需要会改成定点。

### 边界处理

变调时容易出错的边界:

1. **`t` 接近 src 末尾**:`i+1` 可能越界。要么 clamp 到最后一个 sample,要么循环回去。
2. **循环音**:t 超过 src 长度,mod 回去,无缝循环。
3. **dSample 极大(>10)**:线性插值几乎失效,等于跳读,失真严重。
4. **dSample 为负**:倒放,从末尾往开头读。

Casey 处理:不循环时 t 超过则停;循环时 t = t mod N。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏音效的常见变调用例:

| 场景 | dSample 范围 | 实现要点 |
|---|---|---|
| 引擎 RPM | 0.5-2.0 连续 | RPM 映射到 dSample,平滑过渡 |
| 脚步(走/跑) | 1.0(走)、1.5-2.0(跑) | 不变调,只改速率(对应步频) |
| 慢动作 | 0.2-1.0 | 全局 dSample(所有声音都受影响) |
| 倒放 | 负数 | t 从末尾递减 |
| 随机变调 | 0.95-1.05 | 避免多次播放同一声音"机器感" |

**关键概念:Pitch 和 Tempo 是两件事**。

- 改 dSample 同时改 pitch 和 tempo(快 = 高 + 短)。
- 你可以只改 tempo 不改 pitch(时间拉伸),用相位声码器(phase vocoder)算法。
- 你可以只改 pitch 不改 tempo(变调不变速),用 PSOLA 算法。

Casey 的 mixer 是最简单的同时改两者。够用。

**为什么有时要不变调?** 比如语音对话,变调让人听起来像花栗鼠。这时需要专业算法。

### 3.2 · 图形学视角

变调和图形学的"纹理采样"高度同构:

| 概念 | 音频 | 图形 |
|---|---|---|
| 离散数据 | PCM sample | 纹理 texel |
| 任意位置采样 | sample_cursor | UV 坐标 |
| Nearest | floor | GL_NEAREST |
| 线性插值 | 线性插值 | GL_LINEAR |
| 高阶(三次/sinc) | 高质量重采样 | 三次 B 样条 |
| 抗混叠 | SRC 前低通 | mipmap |

图形学里 **mipmap** 就是音频里的"预先做好的低通版本"——避免实时降采样的 aliasing。Day 130 的 seamless bilinear tiling 用的就是这个思路。

### 3.3 · Rust 生态视角

Rust 的 `f64::floor()` 和 `f64::fract()` 直接给出整数和小数部分。注意:

- `floor()` 对负数向下取整(`-1.5 → -2.0`),你要小心倒放时的 cursor 处理。
- `fract()` 返回 `t - floor(t)`,范围 [0, 1)。

简化实现:

```rust
fn resample_linear(src: &[f32], t: f64, d_sample: f64, dst: &mut [f32]) -> f64 {
    let mut t = t;
    for out in dst.iter_mut() {
        let i = t.floor() as usize;
        let frac = (t - t.floor()) as f32;
        // 边界:i+1 越界时取最后一个
        let s0 = src.get(i).copied().unwrap_or(0.0);
        let s1 = src.get(i + 1).copied().unwrap_or(s0);
        *out = s0 * (1.0 - frac) + s1 * frac;
        t += d_sample;
        if i >= src.len() { break; }  // 不循环,结束
    }
    t  // 返回新的 cursor
}
```

**关键 Rust**:
- `src.get(i).copied().unwrap_or(0.0)` —— 安全越界检查。`get` 返回 `Option<&f32>`,`copied` 转 `Option<f32>`,`unwrap_or` 出错时给默认。
- `t.floor() as usize` —— 浮点 floor 后转 usize。`as` 会截断。
- 注意返回新的 `t` 让调用者继续用。

### 3.4 · Linux 视角

Linux 上和变调有关的两个工具:

1. **ALSA 的 `snd_pcm_hw_params_set_rate`** —— 声卡硬件 sample rate。如果应用给的是 44.1 kHz,声卡硬件是 48 kHz,ALSA 用 `libasound` 的 SRC 插件自动重采样(质量可选)。游戏想自己控制质量,通常设硬件 48 kHz 然后自己 SRC。
2. **FFmpeg / SoX 的 `aresample` filter** —— 离线重采样,质量极高。游戏内置不必,知道有这工具即可。

## 5 · 对照与变奏

### 同一思路在不同维度

- **1D 音频**:本日,沿时间轴重采样
- **2D 纹理**:UV 采样,bilinear 是 2D 版的线性插值
- **3D 体素**:三线性插值(3D 版)
- **动画时间**:骨骼动画按任意时刻采样,插值姿势
- **物理积分**:子步进(substepping),任意 dt

### 历史演化

- **1980s**:游戏音频用 MIDI + AdLib/SoundBlaster,频率由合成器硬件控制,无 SRC
- **1990s**:CD 音频引入,游戏第一次需要 SRC。早期用 nearest(伪声严重)
- **2000s**:线性插值普及,质量可接受
- **2010s+**:多核 CPU 充足,高质量 sinc 重采样成为高端引擎标配(如 FMOD)

### dSample 和音乐理论

| dSample | 频率比 | 音乐意义 |
|---|---|---|
| 1.0 | 1 | 同音 |
| 1.0595 | 2^(1/12) | 升半音 |
| 1.1225 | 2^(2/12) | 升全音 |
| 1.5 | 3/2 | 完美五度 |
| 2.0 | 2 | 升八度 |
| 0.5 | 1/2 | 降八度 |

12 平均律(钢琴键盘)用 2^(n/12) 表示半音。dSample = 2^(7/12) ≈ 1.4983 是"完美五度"(实际上略不完美,平均律的五度比纯律略低)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:`dSample = 2.0` 和 `dSample = 0.5`,哪个是上采样,哪个是下采样?为什么下采样需要抗混叠滤波,上采样不需要?

**参考解答**:`dSample = 2.0` 是下采样(每输出一个 sample,跳过源中 2 个),输出 sample rate 等效降低。`dSample = 0.5` 是上采样(每输出一个 sample,源只前进 0.5),输出 sample rate 等效升高。

下采样时,源信号的高频成分(比如原本 30 kHz 的部分)在新的"较低 sample rate"下无法表示,会折叠成低频伪声(aliasing),所以需要先低通滤波去掉高于新奈奎斯特的部分。上采样时,新 sample rate 更高,原本能表示的频率都能表示,不会产生新的 aliasing(但也不会"无中生有"恢复高频)。

### Lv2 · 动手实践

**题**:写一个 Rust 程序,生成 2 秒的 220 Hz 正弦波(f32 mono, 48 kHz)。然后用 dSample = 1.5 重采样它,输出 2/1.5 ≈ 1.33 秒的样本。把结果写进 `pitch_up.raw`。用 Audacity 打开看频谱,应该看到主峰从 220 Hz 移到 330 Hz。

完成标准:文件长度正确(64000 sample),频谱主峰在 330 Hz。

**参考解答**:

```rust
use std::io::Write;

const SR: usize = 48000;

fn main() {
    // 1. 源:2 秒 220 Hz
    let src: Vec<f32> = (0..(2 * SR))
        .map(|i| {
            let t = i as f32 / SR as f32;
            (2.0 * std::f32::consts::PI * 220.0 * t).sin() * 0.5
        })
        .collect();

    // 2. 变调:线性插值重采样,dSample = 1.5
    let d_sample = 1.5;
    let mut dst = Vec::new();
    let mut t: f64 = 0.0;
    while t < src.len() as f64 - 1.0 {
        let i = t.floor() as usize;
        let frac = (t - t.floor()) as f32;
        let y = src[i] * (1.0 - frac) + src[i + 1] * frac;
        dst.push(y);
        t += d_sample;
    }
    println!("dst has {} samples (expected ~{})", dst.len(), (2 * SR) as f64 / 1.5);

    // 3. 写文件
    let mut f = std::fs::File::create("pitch_up.raw").unwrap();
    for s in &dst {
        f.write_all(&s.to_le_bytes()).unwrap();
    }
}
```

## 8 · Rust / Arch 落地代码

```rust
// Cargo.toml: 纯 std

use std::io::Write;

const SR: usize = 48000;

/// 变调重采样器:浮点 cursor + 线性插值
pub struct Voice {
    pub src: Vec<f32>,
    pub cursor: f64,           // 当前播放位置(浮点)
    pub d_sample: f64,         // 步进速率
    pub looping: bool,
    pub volume: f32,
}

impl Voice {
    pub fn new(src: Vec<f32>, d_sample: f64) -> Self {
        Self { src, cursor: 0.0, d_sample, looping: false, volume: 1.0 }
    }

    /// 混到 dst 上,返回 true 表示还在播放,false 表示已结束
    pub fn mix_into(&mut self, dst: &mut [f32]) -> bool {
        let n_src = self.src.len();
        if n_src == 0 { return false; }

        for out in dst.iter_mut() {
            // 边界:cursor 超过 src
            if self.cursor >= n_src as f64 - 1.0 {
                if self.looping {
                    self.cursor = self.cursor % (n_src as f64 - 1.0);
                } else {
                    return false;
                }
            }

            let i = self.cursor.floor() as usize;
            let frac = (self.cursor - self.cursor.floor()) as f32;
            let s0 = self.src[i];
            let s1 = self.src[i + 1.min(n_src - 1)];
            let y = s0 * (1.0 - frac) + s1 * frac;
            *out += y * self.volume;
            self.cursor += self.d_sample;
        }
        true
    }
}

fn main() {
    // 1. 生成 1 秒 220 Hz 正弦
    let src: Vec<f32> = (0..SR)
        .map(|i| {
            let t = i as f32 / SR as f32;
            (2.0 * std::f32::consts::PI * 220.0 * t).sin() * 0.5
        })
        .collect();

    // 2. 创建 voice,升 1.5x(完美五度)
    let mut voice = Voice::new(src, 1.5);

    // 3. 混到 0.5 秒的目标 buffer
    let mut dst = vec![0.0f32; SR / 2];
    let still_playing = voice.mix_into(&mut dst);
    println!("still playing after 0.5s: {}", still_playing);
    println!("voice cursor: {:.1}", voice.cursor);

    // 4. 改变速率为 0.5(降八度)
    voice.d_sample = 0.5;
    let mut dst2 = vec![0.0f32; SR / 2];
    voice.mix_into(&mut dst2);
    println!("voice cursor after slow: {:.1}", voice.cursor);

    // 5. 写文件
    let mut f = std::fs::File::create("pitch.raw").unwrap();
    for s in dst.iter().chain(dst2.iter()) {
        f.write_all(&s.to_le_bytes()).unwrap();
    }
}
```

**关键 Rust 概念**:
- `voice.cursor` 是 `f64` —— 双精度浮点,避免长 buffer 累积误差。
- `i + 1.min(n_src - 1)` —— 安全的 i+1,边界处不越界。`.min()` 是 `Ord::min`。
- `self.cursor % (n_src as f64 - 1.0)` —— 循环时 mod 回开头。
- `dst.iter().chain(dst2.iter())` —— 两个迭代器链接,一次写完。

## 10 · 深度推导:resampling 的算法

今天 Casey 教 resampling。音频要换 sample rate(44.1k → 48k),需要重新采样。这一节把核心算法讲清。

### 10.1 问题描述

44.1 kHz 录的声音 sample 0, 1, 2, ..., 44100 个/秒。在 48 kHz 设备播放,如何"插入"额外的 3900 sample/秒?

朴素:每 11 个 44.1k sample 后插一个 0:

```rust
for i in 0..output.len() {
    let src_idx = (i as f32 * 44100.0 / 48000.0) as usize;
    output[i] = input[src_idx];
}
```

这就是 nearest-neighbor resampling。问题:**插值不准确**,听感有 aliasing(伪频率)。

### 10.2 Linear interpolation

```rust
for i in 0..output.len() {
    let src_pos = i as f32 * 44100.0 / 48000.0;
    let idx = src_pos as usize;
    let frac = src_pos - idx as f32;
    let s0 = input[idx];
    let s1 = input[idx + 1];
    output[i] = s0 * (1.0 - frac) + s1 * frac;
}
```

两个邻居 sample 加权平均,听感比 nearest 好。但仍然有 aliasing——linear 是"硬"插值,引入高频伪影。

### 10.3 Sinc interpolation(理想)

理论上完美 resampling 是 **sinc function** 插值:

```
output[i] = sum over all j: input[j] * sinc((i * ratio) - j)
```

sinc(x) = sin(πx) / (πx)。这是 bandlimited 信号的最优插值。

但 sinc 是无限长的——实际用 windowed sinc(只算 ±16 个邻居):

```rust
fn sinc(x: f32) -> f32 {
    if x.abs() < 1e-9 { return 1.0; }
    let px = std::f32::consts::PI * x;
    px.sin() / px
}

fn resample_sinc(input: &[f32], ratio: f32, output: &mut [f32]) {
    let window = 16;  // 邻居数
    for i in 0..output.len() {
        let src_pos = i as f32 / ratio;
        let center = src_pos as isize;
        let mut sum = 0.0;
        for j in -window..=window {
            let idx = center + j;
            if idx < 0 || idx >= input.len() as isize { continue; }
            let x = src_pos - idx as f32;
            // Hann window 减少 sinc 截断 artifact
            let w = 0.5 * (1.0 - (std::f32::consts::PI * x / window as f32).cos());
            sum += input[idx as usize] * sinc(x) * w;
        }
        output[i] = sum;
    }
}
```

高质量但慢——每个 output sample 要算 33 次乘加。44.1k → 48k,1 秒音频 = 48000 output sample × 33 = 1.58M ops。

### 10.4 Polyphase filter(工业级)

工业 resampler(SoX / SRC / Secret Rabbit Code)用 polyphase filter:

- 预计算 N 个 filter taps(通常 32-128 个)
- 每个 output sample 用的 filter 由 fractional position 决定
- 用 SIMD 加速 32-tap filter 卷积

实现复杂但极快。Casey HH 用 linear,工业用 polyphase。

### 10.5 完整 linear resampler 代码

```rust
pub struct LinearResampler {
    input_rate: u32,
    output_rate: u32,
    last_sample: f32,
    position: f32,  // 输入位置(浮点)
}

impl LinearResampler {
    pub fn new(input_rate: u32, output_rate: u32) -> Self {
        Self {
            input_rate,
            output_rate,
            last_sample: 0.0,
            position: 0.0,
        }
    }

    /// 处理一个输入 sample,产生 0 个或多个 output sample
    pub fn process(&mut self, input: f32, output: &mut Vec<f32>) {
        let step = self.input_rate as f32 / self.output_rate as f32;
        loop {
            if self.position <= 1.0 {
                // 插值:在 last_sample 和 input 之间
                let interpolated = self.last_sample * (1.0 - self.position) + input * self.position;
                output.push(interpolated);
                self.position += step;
            } else {
                self.position -= 1.0;
                break;
            }
        }
        self.last_sample = input;
    }

    /// 批量处理
    pub fn process_buffer(&mut self, input: &[f32], output: &mut Vec<f32>) {
        for &s in input {
            self.process(s, output);
        }
    }
}

fn main() {
    // 44.1 kHz → 48 kHz
    let mut resampler = LinearResampler::new(44100, 48000);

    // 生成 1 秒 440 Hz 正弦
    let input: Vec<f32> = (0..44100).map(|i| {
        let t = i as f32 / 44100.0;
        (t * 440.0 * 2.0 * std::f32::consts::PI).sin()
    }).collect();

    let mut output = Vec::new();
    resampler.process_buffer(&input, &mut output);

    println!("Input: {} samples (44.1 kHz)", input.len());
    println!("Output: {} samples (48 kHz)", output.len());
    println!("Expected: ~48000 samples");

    // 检查输出频率
    // 在 48000 sample 中找过零点
    let mut zero_crossings = 0;
    for i in 1..output.len() {
        if (output[i-1] < 0.0 && output[i] >= 0.0) || (output[i-1] > 0.0 && output[i] <= 0.0) {
            zero_crossings += 1;
        }
    }
    let detected_freq = zero_crossings as f32 / 2.0;  // 每周期 2 个过零点
    println!("Detected frequency: {} Hz", detected_freq);
    // 应该接近 440 Hz
}
```

跑起来:

```bash
cargo run --release
# Input: 44100 samples (44.1 kHz)
# Output: ~48000 samples (48 kHz)
# Detected frequency: ~440 Hz
```

这就是 Day 143 的核心——linear resampler。Casey 在 HH 用这个,工业用 polyphase(更快 + 质量更高)。

### 10.6 Pitch shifting(变调)

Resampling 改 sample rate 不改 pitch。但变调(改 pitch 不改 tempo)是另一种算法——更复杂,涉及 FFT / phase vocoder。Day 143 不涉及,但要知道区别。

Casey 的 day143 做的是 **simple pitch shift by playback rate**——播放速度变化,pitch 跟着变(磁带机效果)。这是 resampling 的副产品。

### 10.7 Latency

Resampling 引入延迟。Linear resampler 的延迟 = 1 sample(等下一个 input 到才能插值)。Polyphase 延迟 = filter length / 2 sample(通常 16 sample,0.4 ms)。

游戏音频总延迟 < 50 ms 可接受。resampling 的延迟通常忽略。

## 11 · 工业级的额外考量

### 11.1 Anti-aliasing filter

下采样(48k → 22k)时,22k 以上的频率会"折叠"产生 aliasing。要先低通滤波:

```rust
// 22 kHz 低通滤波器
let lp_filter = design_lowpass(22000, 48000);
let filtered = lp_filter.process(&input);
// 然后 downsample
```

不做 anti-aliasing → 听感有"金属感"的伪影。

### 11.2 多种 resampling 质量

工业音频提供多档质量:

- **Fast**:nearest neighbor,极致速度(实时变调)
- **Medium**:linear,日常够用
- **Good**:cubic / Lagrange interpolation
- **Best**:sinc / polyphase,离线渲染 / 录音棚

游戏运行时用 Fast / Medium,资源预处理用 Best。

### 11.3 实时变调(磁带机效果)

某些游戏效果(慢动作时声音变低)用 resampling:

```rust
// 慢动作:0.5x speed,pitch 也降一半
let resampler = LinearResampler::with_ratio(0.5);  // output_rate / input_rate = 0.5
let slow_sound = resampler.process(&normal_sound);
// 慢一倍,音调也降一倍(磁带机效果)
```
