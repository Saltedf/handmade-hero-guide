
# Day 163 · 用 STB TrueType 处理资产

> Day 162 讲了字体理论。今天 Casey 用 **stb_truetype.h**——单文件 C 库——栅格化 TrueType 字体,把字符变 bitmap,塞进 .hha 资产。这是 build 期处理(build-time),不在游戏运行时跑。

## 0 · 为什么要有这一天

字体处理的两种思路:

1. **运行时栅格化**:游戏加载 .ttf,运行时用 FreeType / ab_glyph 渲染。灵活,但每帧 CPU。
2. **build 时栅格化**:打包器预先栅格化所有字符,把 bitmap 存进 .hha。运行时直接 blit,无 CPU。

Casey 选 2(build-time)。stb_truetype 是单文件 C 库,易集成。Rust 对应是 `ab_glyph` 或 `rusttype`。

今天的工作:

1. 列出要栅格化的字符(ASCII 32-127)
2. 对每个字符,用 stb 算 outline → bitmap
3. 把 bitmap 打包到一张大 atlas(图集)texture
4. atlas + 每个 glyph 的 metadata(在 atlas 中位置、advance、kerning)存进 .hha

这是游戏字体管线的标准做法。Valve 在 TF2 / L4D2 / Portal 用同样思路(加 SDF)。

心理锚点:看完今天,你能写一个 build 期字体打包器,把 .ttf 转 .hha 里的 glyph atlas。

## 2 · 心智模型

### 类比:活字印刷

印刷厂要排印一本书。两种做法:

1. **每行现刻**(运行时栅格化):每排一行,临时刻所有字。慢但灵活。
2. **预先备好活字**(build 时打包):把所有可能用到的字预先刻好,排印时直接拼。快但要预知字符集。

数字字体同样:build 时把 ASCII 全部 95 个字栅格化成 bitmap,放 atlas。运行时按字符串查 atlas 拼出文本。

### 严谨模型:Glyph Atlas

```
atlas texture(512×512 像素,grayscale):

+----+----+----+----+----+----+
| A  | B  | C  | D  | E  | F  |  ← 每 cell 一个 glyph
+----+----+----+----+----+----+
| G  | H  | I  | J  | K  | L  |
+----+----+----+----+----+----+
| ...                       |
+----+----+----+----+----+----+
```

每 glyph 的 metadata:

```rust
struct GlyphInfo {
    char: u32,
    atlas_x: u32,   // 在 atlas 中的位置
    atlas_y: u32,
    width: u32,
    height: u32,
    advance: f32,   // 光标前进量
    bearing_x: f32, // 起始偏移
    bearing_y: f32,
}
```

文本渲染:

```rust
fn draw_text(atlas: &Texture, glyphs: &[GlyphInfo], text: &str, x: f32, y: f32) {
    let mut cursor_x = x;
    for c in text.chars() {
        let g = glyphs.iter().find(|g| g.char == c as u32).unwrap();
        draw_image(atlas, g.atlas_x, g.atlas_y, g.width, g.height, cursor_x + g.bearing_x, y + g.bearing_y);
        cursor_x += g.advance;
    }
}
```

### Atlas 打包

glyph 大小不一(逗号小,"W" 大),如何 pack 进方形 texture?

**简单方案**:每 cell 固定大小 = max glyph 尺寸。空间浪费(小 glyph 周围是空白)。

**矩形打包算法**:用矩形装箱(rectangle bin packing)算法。常用:

- **shelf packing**:按高度分行,每行从左到右放
- **guillotine**:递归切分空闲区域
- **maxrects**:维护空闲矩形列表,选最优放
- **skyline**:维护顶部轮廓,选最低点放

游戏字体常用 **shelf packing**(简单 + 字体大小相对一致)。

### 字号策略

ASCII 95 个字符 × 4 字号(12, 16, 24, 32)= 380 glyph。每 glyph 平均 32×32 = 1024 像素。380 × 1024 = 390 KB。可接受。

如果支持多语言(中文 5000 字),5000 × 1024 = 5 MB。**中文用 SDF 更省**(SDF 单字号 = 任意字号)。

```rust
let font = FontRef::try_from_slice(&data)?;
let glyph = font.glyph_id('A').with_scale(24.0);
if let Some(outlined) = font.outline_glyph(glyph) {
    let bounds = outlined.px_bounds();
    let mut pixels = vec![0u8; (bounds.width() * bounds.height()) as usize];

        pixels[(y * bounds.width() as u32 + x) as usize] = (c * 255.0) as u8;
```

### 3.3 · 数据结构视角

glyph metadata 存储选项:

- **`Vec<GlyphInfo>`** 按 glyph id 索引
- **`HashMap<char, GlyphInfo>`** 按 Unicode 查
- **`[GlyphInfo; 128]`** ASCII only(直接 index)

ASCII only 时 array 最快(O(1) 直接 index,cache friendly)。

### 3.4 · 渲染视角

blit 一个 glyph:

```rust
// 把 atlas 上 (gx, gy, gw, gh) 区域 blit 到屏幕 (sx, sy)
for y in 0..gh {
    for x in 0..gw {
        let alpha = atlas[(gy + y) * atlas_w + (gx + x)];
        if alpha > 0 {
            let dst = screen[(sy + y) as usize * screen_w + (sx + x) as usize];
            // alpha blend:dst = src * alpha + dst * (1-alpha)
            screen[...] = blend(dst, color, alpha);
        }
    }
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:build-time 栅格化 vs runtime 栅格化,各自的优缺点?

**参考解答**:build-time:

- 优点:运行时无 CPU 开销,直接 blit
- 缺点:字符集预知,改字号要重 build,内存固定

runtime:

- 优点:灵活(任意字符 / 字号 / 效果)
- 缺点:每帧 CPU,需要缓存

工业混合:**runtime + smart cache**(常用字符 cache,罕见字符动态栅格化)。Casey 教学用 build-time 简单。

### Lv2 · 动手实践

**题**:用 ab_glyph 栅格化 ASCII 32-127 所有字符(字号 16),pack 到 512×512 atlas。打印 atlas 利用率和总像素数。

**参考解答**:

```rust
// Cargo.toml: ab_glyph = "0.2"
use ab_glyph::{Font, FontRef, GlyphId, point};

fn main() {
    let data = std::fs::read("/usr/share/fonts/TTF/DejaVuSans.ttf")
        .or_else(|_| std::fs::read("/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf"))
        .unwrap();
    let font = FontRef::try_from_slice(&data).unwrap();

    const ATLAS_W: usize = 512;
    const ATLAS_H: usize = 512;
    let mut atlas = vec![0u8; ATLAS_W * ATLAS_H];

    // shelf packing
    let mut cursor_x = 0;
    let mut cursor_y = 0;
    let mut row_height = 0;
    let mut packed = 0;
    let mut used_pixels = 0;

    for c in 32u8..128u8 {
        let glyph_id: GlyphId = font.glyph_id(c as char);
        let glyph = glyph_id.with_scale_and_position(16.0, point(0.0, 16.0));
        let outlined = match font.outline_glyph(glyph) { Some(o) => o, None => continue };
        let bounds = outlined.px_bounds();
        let w = bounds.width() as usize;
        let h = bounds.height() as usize;

        if w == 0 || h == 0 { continue; }

        // 换行?
        if cursor_x + w > ATLAS_W {
            cursor_x = 0;
            cursor_y += row_height;
            row_height = 0;
        }
        if cursor_y + h > ATLAS_H {
            eprintln!("atlas full at char {}", c);
            break;
        }

        // 写入 atlas
        outlined.draw(|x, y, cov| {
            let px = cursor_x + x as usize;
            let py = cursor_y + y as usize;
            if px < ATLAS_W && py < ATLAS_H {
                atlas[py * ATLAS_W + px] = (cov * 255.0) as u8;
            }
        });

        cursor_x += w;
        row_height = row_height.max(h);
        used_pixels += w * h;
        packed += 1;
    }

    println!("packed {} glyphs", packed);
    println!("used pixels: {}", used_pixels);
    println!("atlas capacity: {}", ATLAS_W * ATLAS_H);
    println!("utilization: {:.1}%", used_pixels as f32 / (ATLAS_W * ATLAS_H) as f32 * 100.0);
}
```

## 8 · Rust / Arch 落地代码

```rust
// Cargo.toml: ab_glyph = "0.2"

use ab_glyph::{Font, FontRef, GlyphId, point};

struct GlyphInfo {
    char_code: u32,
    atlas_x: u32,
    atlas_y: u32,
    width: u32,
    height: u32,
    advance: f32,
}

struct FontAtlas {
    atlas: Vec<u8>,         // grayscale
    atlas_width: u32,
    atlas_height: u32,
    glyphs: Vec<GlyphInfo>,
    font_size: f32,
}

impl FontAtlas {
    fn build(font_data: &[u8], size: f32) -> Self {
        let font = FontRef::try_from_slice(font_data).expect("font");
        const W: u32 = 512;
        const H: u32 = 512;
        let mut atlas = vec![0u8; (W * H) as usize];
        let mut glyphs = Vec::new();

        let mut cursor_x = 0u32;
        let mut cursor_y = 0u32;
        let mut row_h = 0u32;

        for c in 32u32..128u32 {
            let gid: GlyphId = font.glyph_id(char::from_u32(c).unwrap());
            let glyph = gid.with_scale_and_position(size, point(0.0, size));
            let outlined = match font.outline_glyph(glyph) { Some(o) => o, None => continue };
            let bounds = outlined.px_bounds();
            let w = bounds.width() as u32;
            let h = bounds.height() as u32;
            if w == 0 || h == 0 { continue; }

            if cursor_x + w > W {
                cursor_x = 0;
                cursor_y += row_h;
                row_h = 0;
            }
            if cursor_y + h > H { break; }

            outlined.draw(|x, y, cov| {
                let px = cursor_x as usize + x as usize;
                let py = cursor_y as usize + y as usize;
                if px < W as usize && py < H as usize {
                    atlas[py * W as usize + px] = (cov * 255.0) as u8;
                }
            });

            let advance = font.glyph_bounds(glyph).map(|b| b.width()).unwrap_or(size / 2.0);
            glyphs.push(GlyphInfo {
                char_code: c,
                atlas_x: cursor_x,
                atlas_y: cursor_y,
                width: w,
                height: h,
                advance,
            });

            cursor_x += w;
            row_h = row_h.max(h);
        }

        Self {
            atlas, atlas_width: W, atlas_height: H, glyphs, font_size: size,
        }
    }

    fn find(&self, c: char) -> Option<&GlyphInfo> {
        self.glyphs.iter().find(|g| g.char_code == c as u32)
    }
}

fn main() {
    let data = std::fs::read("/usr/share/fonts/TTF/DejaVuSans.ttf")
        .or_else(|_| std::fs::read("/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf"))
        .expect("font");

    let atlas = FontAtlas::build(&data, 24.0);
    println!("built atlas: {}x{}, {} glyphs, font size = {}",
        atlas.atlas_width, atlas.atlas_height, atlas.glyphs.len(), atlas.font_size);

    // 模拟 draw_text
    let text = "Hello";
    let mut cursor_x = 0f32;
    for c in text.chars() {
        if let Some(g) = atlas.find(c) {
            println!("'{}' at atlas ({},{}) {}x{}, advance {}",
                c, g.atlas_x, g.atlas_y, g.width, g.height, g.advance);
            cursor_x += g.advance;
        }
    }
    println!("total advance: {:.1}", cursor_x);
}
```

**预期**:输出 "Hello" 5 个字符的 atlas 坐标 + advance。

### A.17 该 Day 的具体 Rust 实现细节

让我提供具体 Rust 实现细节,综合 phase-4 概念:

```rust
use std::sync::Arc;
use std::collections::HashMap;

// Phase 4 的 asset storage 完整示例
pub struct AssetStorage<T: Send + Sync + 'static> {
    cache: HashMap<u32, Arc<T>>,
    loader: Box<dyn Fn(u32) -> Result<T, AssetError> + Send + Sync>,
    next_id: u32,
    name_to_id: HashMap<String, u32>,
}

#[derive(Debug)]
pub enum AssetError {
    NotFound(String),
    InvalidFormat(String),
    IoError(std::io::Error),
}

impl<T: Send + Sync + 'static> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self
    where
        F: Fn(u32) -> Result<T, AssetError> + Send + Sync + 'static,
    {
        Self {
            cache: HashMap::new(),
            loader: Box::new(loader),
            next_id: 1,
            name_to_id: HashMap::new(),
        }
    }
    
    pub fn load_by_name(&mut self, name: &str) -> Result<Arc<T>, AssetError> {
        let id = if let Some(id) = self.name_to_id.get(name) {
            *id
        } else {
            let id = self.next_id;
            self.next_id += 1;
            self.name_to_id.insert(name.to_string(), id);
            id
        };
        
        self.load_by_id(id)
    }
    
    pub fn load_by_id(&mut self, id: u32) -> Result<Arc<T>, AssetError> {
        if let Some(cached) = self.cache.get(&id) {
            return Ok(Arc::clone(cached));
        }
        
        let asset = (self.loader)(id)?;
        let arc = Arc::new(asset);
        self.cache.insert(id, Arc::clone(&arc));
        Ok(arc)
    }
    
    pub fn evict_unused(&mut self) {
        self.cache.retain(|_, arc| Arc::strong_count(arc) > 1);
    }
}

// 用法示例
fn main() {
    let mut storage: AssetStorage<Vec<u8>> = AssetStorage::new(|id| {
        Ok(vec![id as u8; 100])  // 模拟加载
    });
    
    let a = storage.load_by_name("test").unwrap();
    let b = storage.load_by_name("test").unwrap();
    assert!(Arc::ptr_eq(&a, &b));  // 同一 Arc
}
```

这是 phase-4 asset storage 的 Rust 完整实现。包括:
- ID-based 查询(避免字符串比较)

### A.18 跨平台 asset 加载

Phase 4 的 asset 系统要跨平台:

```rust
// Linux: /usr/share/my_game/assets/texture.png
// Windows: C:\Program Files\MyGame\assets\texture.png
// macOS: MyGame.app/Contents/Resources/assets/texture.png

pub fn get_asset_path(name: &str) -> PathBuf {
    #[cfg(target_os = "linux")]
    {
        // XDG_DATA_DIRS 或 /usr/share
        let data_dir = std::env::var("XDG_DATA_DIRS")
            .unwrap_or_else(|_| "/usr/local/share:/usr/share".to_string());
        for dir in data_dir.split(':') {
            let path = PathBuf::from(dir).join("my_game").join("assets").join(name);
            if path.exists() {
                return path;
            }
        }
        // fallback: ~/.local/share
        let home = std::env::var("HOME").unwrap();
        PathBuf::from(home).join(".local/share/my_game/assets").join(name)
    }
    
    #[cfg(target_os = "windows")]
    {
        let program_files = std::env::var("PROGRAMFILES").unwrap();
        PathBuf::from(program_files).join("MyGame").join("assets").join(name)
    }
    
    #[cfg(target_os = "macos")]
    {
        let home = std::env::var("HOME").unwrap();
        PathBuf::from(home).join("Library/Application Support/MyGame/assets").join(name)
    }
}
```

跨平台 asset 加载是工业级游戏的基础。Rust 的 `cfg` 让单一代码库支持多平台。

```rust
#[derive(Debug, thiserror::Error)]
pub enum GameError {
    #[error("Asset not found: {0}")]
    AssetNotFound(String),
    
    #[error("Asset invalid format: {0}")]
    AssetInvalidFormat(String),
    
    #[error("IO error: {0}")]

    #[error("Parse error: {0}")]
    Parse(String),
}

pub type GameResult<T> = Result<T, GameError>;

pub fn load_texture(path: &Path) -> GameResult<Texture> {
    let data = std::fs::read(path)?;  // IO error → GameError
    let texture = parse_png(&data).map_err(|e| GameError::Parse(e.to_string()))?;
    Ok(texture)
}
```

### A.23 Phase 4 的核心主题深度回顾

让我深度回顾 phase-4 的几个核心主题:

**1. Arena allocator 的工业价值**

Arena allocator 是 phase-4 的开篇主题。核心思想:**一大块内存,scope 退出整体释放**。

适用场景:
- 一帧的临时数据(frame arena)
- 一个关卡的临时数据(level arena)
- 一次操作的临时数据(operation arena)

工业 Rust 实现:`bumpalo` crate

```rust
use bumpalo::Bump;

let bump = Bump::new();
let temp_strings: Vec<&mut String> = (0..1000).map(|i| {
    bump.alloc(format!("string_{}", i))
}).collect();
// bump drop → 所有 temp_strings 释放
```

性能:O(1) allocation(指针前进),O(1) deallocation(整个 arena 一次释放)。比标准 alloc 快 10-100x。

**2. Asset streaming 的工程挑战**

Asset streaming 让"加载不阻塞游戏":

```
主线程:
  get(texture_id) → cache 有 → 立即返回
  get(texture_id) → cache 无 → 返回 placeholder + 排队加载
  
Background thread:
  循环:
    pop job from queue
    load texture from disk
    insert to cache
    signal main thread(可选)
```

工程挑战:
- placeholder 显示(避免黑屏)
- 优先级(玩家附近 asset 先加载)
- 内存预算(满时 LRU 驱逐)
- 线程安全(分桶锁 / lock-free)

Casey phase-4 教基础 streaming,工业实现(bevy_asset)更复杂。

**3. Particle simulation 的并行化**

大量粒子(几万到几百万)的物理更新:

```rust
// 串行
for particle in &mut particles {
    particle.velocity += gravity * dt;
    particle.position += particle.velocity * dt;
}

// 并行(rayon)
use rayon::prelude::*;
particles.par_iter_mut().for_each(|p| {
    p.velocity += gravity * dt;
    p.position += p.velocity * dt;
});

// SIMD(wide crate)
use wide::f32x4;
let gravity_x4 = f32x4::splat(gravity);
let dt_x4 = f32x4::splat(dt);
for chunk in particles.chunks_exact_mut(4) {
    let mut vx = f32x4::from([chunk[0].vx, chunk[1].vx, chunk[2].vx, chunk[3].vx]);
    let mut px = f32x4::from([chunk[0].px, chunk[1].px, chunk[2].px, chunk[3].px]);
    vx += gravity_x4 * dt_x4;
    px += vx * dt_x4;

}
```

并行 + SIMD 让粒子性能 8-16x 提升。

```rust
// Audio callback(高优先级线程)
fn audio_callback(output_buffer: &mut [f32], state: &AudioState) {
    let mix_buffer = state.mix_buffer.lock().unwrap();
    for sample in output_buffer.iter_mut() {
        let mut mixed = 0.0;
        for channel in &state.channels {
            mixed += channel.get_next_sample();
        }
        *sample = mixed * state.master_volume;
    }
}
```
