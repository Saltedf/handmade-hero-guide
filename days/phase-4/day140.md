## 2 · 心智模型

### 类比:DJ 控制台

**DJ 控制台** = 音频混音器:

- **每个 channel 一首歌**(PlayingSound)
- **通道推子**(volume per channel)
- **pan 旋钮**(左右平衡)
- **效果按钮**(loop / mute / solo)
- **主输出**(Master,接到音箱)
- **音轨结束自动停止**(播完清理)

混音器管理多个 channel,每秒产生输出样本。

### 严谨原理:游戏音频循环

游戏 + 音频的循环架构:

```
┌─────────────────────────────────────────────────────┐
│  Game Thread(60 FPS)                               │
│  - update(): 玩家事件 → mixer.play(sword_sound)    │
└─────────────────────────────────────────────────────┘
                       ↓
                  (thread-safe queue)
                       ↓
┌─────────────────────────────────────────────────────┐
│  Audio Callback(44100 Hz,实时)                    │
│  - mixer.mix(output_buffer)                         │
│  - 遍历所有 playing sounds,逐 sample 累加         │
│  - 填充 output_buffer 给声卡                        │
└─────────────────────────────────────────────────────┘
                       ↓
                  (声卡播放)
```

**关键约束**:audio callback 在声卡的实时线程上,必须快(几毫秒内完成),不能阻塞。所以:

- 不能在 callback 里 alloc / dealloc 内存
- 不能在 callback 里 lock(可能死锁)
- 不能在 callback 里 IO(read 文件)

Casey 用 lock-free queue 把"play request"从游戏线程传到 audio 线程。Rust 教学版用 Mutex 简化(实际项目用 crossbeam 或 lock-free)。

### 完整 Rust 实现

```rust
use std::sync::{Arc, Mutex};

#[derive(Clone)]
struct SoundData {
    samples: Vec<f32>,  // mono 或 stereo 交错
    sample_rate: u32,
    is_stereo: bool,
}

struct PlayingSound {
    data: SoundData,
    next_sample: usize,
    volume: f32,
    pan: f32,           // -1 (full left) ~ 1 (full right)
    looping: bool,
    speed: f32,         // 1.0 = normal, 2.0 = double speed (for pitch shift)
    done: bool,
}

impl PlayingSound {
    fn new(data: SoundData, volume: f32, pan: f32, looping: bool) -> Self {
        Self {
            data, next_sample: 0, volume, pan, looping,
            speed: 1.0, done: false,
        }
    }

    // 取下一对样本
    fn next_pair(&mut self) -> (f32, f32) {
        if self.done { return (0.0, 0.0); }

        // 检查播完
        let samples_per_frame = if self.data.is_stereo { 2 } else { 1 };
        let total_frames = self.data.samples.len() / samples_per_frame;

        if self.next_sample >= self.data.samples.len() {
            if self.looping {
                self.next_sample = 0;
            } else {
                self.done = true;
                return (0.0, 0.0);
            }
        }

        // 取样本
        let (left_raw, right_raw) = if self.data.is_stereo {
            let l = self.data.samples[self.next_sample];
            let r = self.data.samples[self.next_sample + 1];
            self.next_sample += 2;
            (l, r)
        } else {
            let s = self.data.samples[self.next_sample];
            self.next_sample += 1;
            (s, s)
        };

        // 应用 pan:简单线性
        // pan = -1: 左 = volume, 右 = 0
        // pan = 0: 左 = 右 = volume
        // pan = 1: 左 = 0, 右 = volume
        let left_mult = (1.0 - self.pan.max(0.0)) * self.volume;
        let right_mult = (1.0 + self.pan.min(0.0)) * self.volume;
        (left_raw * left_mult, right_raw * right_mult)
    }
}

struct AudioMixer {
    sounds: Vec<PlayingSound>,
    sample_rate: u32,
}

impl AudioMixer {
    fn new(sample_rate: u32) -> Self {
        Self { sounds: Vec::with_capacity(64), sample_rate }
    }

    fn play(&mut self, data: SoundData, volume: f32, pan: f32, looping: bool) {
        // 找空闲槽位(优化:用 pool 而不是 Vec::push)
        self.sounds.push(PlayingSound::new(data, volume, pan, looping));
    }

    fn mix(&mut self, output: &mut [f32]) {
        // output: stereo interleaved [L0, R0, L1, R1, ...]
        for chunk in output.chunks_exact_mut(2) {
            let (mut left, mut right) = (0.0f32, 0.0f32);
            for sound in self.sounds.iter_mut() {
                let (l, r) = sound.next_pair();
                left += l;
                right += r;
            }
            // Soft clip
            chunk[0] = left.tanh();
            chunk[1] = right.tanh();
        }
        // 清理 done 的 sound(从后往前,索引稳定)
        for i in (0..self.sounds.len()).rev() {
            if self.sounds[i].done {
                self.sounds.remove(i);
            }
        }
    }
}

// Thread-safe wrapper(给跨线程用)
struct SharedMixer(Arc<Mutex<AudioMixer>>);
impl SharedMixer {
    fn new(sample_rate: u32) -> Self { Self(Arc::new(Mutex::new(AudioMixer::new(sample_rate)))) }
    fn play(&self, data: SoundData, volume: f32, pan: f32, looping: bool) {
        self.0.lock().unwrap().play(data, volume, pan, looping);
    }
    fn mix(&self, output: &mut [f32]) {
        self.0.lock().unwrap().mix(output);
    }
}
```

### 集成 cpal

```rust
use cpal::traits::{DeviceTrait, HostTrait, StreamTrait};
use cpal::{SampleFormat, StreamConfig};

fn main() {
    let host = cpal::default_host();
    let device = host.default_output_device().expect("no output device");
    let config = device.default_output_config().unwrap();
    let sample_rate = config.sample_rate().0;
    let channels = config.channels() as usize;
    println!("Audio: {} Hz, {} channels", sample_rate, channels);

    let mixer = SharedMixer::new(sample_rate);

    // 加载几个 WAV 模拟播放
    let wav_data = std::fs::read("test.wav").unwrap();
    let wav = parse_wav(&wav_data).unwrap();
    let sound_data = SoundData {
        samples: wav.samples,
        sample_rate: wav.sample_rate,
        is_stereo: wav.num_channels == 2,
    };

    // 播放
    mixer.play(sound_data.clone(), 0.5, 0.0, true);   // BGM 循环
    mixer.play(sound_data.clone(), 1.0, -0.5, false); // 一次播放,pan 左
    mixer.play(sound_data.clone(), 1.0, 0.5, false);  // 一次播放,pan 右

    // 创建 cpal 输出流
    let mixer_clone = mixer.0.clone();
    let stream = match config.sample_format() {
        SampleFormat::F32 => device.build_output_stream(
            &StreamConfig::from(&config),
            move |data: &mut [f32], _: &_| {
                mixer_clone.lock().unwrap().mix(data);
            },
            |err| eprintln!("stream error: {}", err),
            None,
        ).unwrap(),
        _ => panic!("unsupported sample format"),
    };
    stream.play().unwrap();

    // 主循环
    println!("Playing for 5 seconds...");
    std::thread::sleep(std::time::Duration::from_secs(5));
}
```

### 处理 sample rate 转换

如果 WAV 是 22050 Hz,声卡 44100 Hz,直接播放会变 2 倍速(快进)。要做 sample rate conversion:

```rust
// 简化:线性插值
fn resample(samples: &[f32], src_rate: u32, dst_rate: u32) -> Vec<f32> {
    if src_rate == dst_rate { return samples.to_vec(); }
    let ratio = src_rate as f32 / dst_rate as f32;
    let dst_len = (samples.len() as f32 / ratio) as usize;
    let mut out = Vec::with_capacity(dst_len);
    let mut src_idx = 0.0f32;
    for _ in 0..dst_len {
        let i = src_idx as usize;
        let frac = src_idx - i as f32;
        let s = if i + 1 < samples.len() {
            samples[i] * (1.0 - frac) + samples[i + 1] * frac
        } else {
            samples[i]
        };
        out.push(s);
        src_idx += ratio;
    }
    out
}
```

更好的算法:三角窗插值、sinc 插值。商业音频库(LIBSOXR、Secret Rabbit Code)。

Casey Day 143 pitch shift 用类似算法。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏音频循环架构:

- **Game thread** 60 FPS:玩家事件 → `mixer.play(...)` 加 PlayingSound
- **Audio thread** 44100 Hz:实时调 `mixer.mix(output)` 填充声卡 buffer
- **线程间通信**:lock-free queue 或 Mutex

游戏开发圈的优化:

**Sound pool**:固定 N 槽位,play 时找空槽位填充,done 时标记可重用。避免动态 Vec 分配。Casey 用 pool。

**Channel groups**:声音分类(SFX / Music / Voice),每类独立音量。玩家能调"BGM 音量"不影响 SFX。

**Ducking**:玩家说话时自动降低 BGM 音量。商业游戏标配。

**Audio scene**:场景切换时停止所有声音(进入菜单),暂停 BGM。商业游戏标配。

### 3.2 · 🐧 Linux 系统编程视角

#### 实时调度


### 标量 vs SIMD 混音

Day 140 标量:

```rust
for sound in sounds {
    let samples = _mm_loadu_ps(&sound.samples[idx..]);
```

### Game thread vs Audio thread

| | Game thread | Audio thread |
|---|---|---|
| 频率 | 60 Hz | 44100 Hz / buffer_size |
| 优先级 | 普通 | 实时(SCHED_FIFO) |
| 限制 | 16 ms / frame | 几 ms / buffer |
| 不能做 | 阻塞 IO 太久 | 任何阻塞、alloc、lock |
| 通信 | play request 进 queue | 出 queue 播放 |

两个线程解耦,中间 queue 传递 play / stop 命令。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:

1. 为什么 audio callback 不能 alloc / lock?违反会怎样?
2. Game thread 和 Audio thread 怎么通信?
3. Sample rate 转换(22050 → 44100)不做的后果是什么?
4. 为什么 `sounds: Vec<PlayingSound>` 用 Vec 而不是固定大小数组?

**参考解答**:
1. audio callback 在声卡的实时线程上,buffer underrun 会"卡顿"(声音断续)。alloc 触发 malloc(几微秒到几毫秒),lock 可能死锁(主线程持有锁时被抢占),都可能导致 underrun。规则:callback 内只做内存已分配、无锁的计算。
2. Lock-free queue 或 Mutex 共享状态。Game thread `mixer.play(...)`,audio thread `mixer.mix(...)`。中间需要 thread-safe 容器(Mutex 或 lock-free queue)。
3. 不做 SRC,22050 Hz 的样本直接以 44100 Hz 速度播放,听起来像快进(2 倍速 + 高八度)。需要 SRC 重采样到目标 rate。
4. Vec 灵活(声源数动态)。固定大小数组省 alloc 但有上限(N 槽位)。Casey 实际用固定 pool(避免 alloc),我们教学版用 Vec 简化。生产代码用 pool + index 复用。

## 10 · 深度推导:从混音器到硬件

今天 Casey 把 Day 139 的混音器接到 cpal,真实播放。这一步看起来"调用 API",但背后涉及 Linux 音频栈的所有层次。这一节走通。

### 10.1 cpal 的核心抽象

cpal 提供 4 个抽象:

- **Host**:平台相关的"音频系统"。Linux 上是 ALSA host。
- **Device**:具体输出设备(扬声器 / 耳机)。
- **Stream**:打开设备后得到的流,可以 write sample。
- **StreamConfig**:sample rate / channel / format。

最小用法:

```rust
use cpal::{Host, StreamConfig, SampleFormat, traits::*};

fn main() {
    let host = cpal::default_host();
    let device = host.default_output_device().expect("no output device");
    let config = device.default_output_config().unwrap();
    let sample_rate = config.sample_rate().0;
    let channels = config.channels();
    let fmt = config.sample_format();

    println!("Output: {} Hz, {} channels, {:?}", sample_rate, channels, fmt);

    let stream = match fmt {
        SampleFormat::F32 => build_stream::<f32>(&device, &config.into()),
        SampleFormat::I16 => build_stream::<i16>(&device, &config.into()),
        _ => panic!("unsupported format"),
    };
    stream.play().unwrap();

    std::thread::sleep(std::time::Duration::from_millis(1000));
}

fn build_stream<T: cpal::Sample>(
    device: &cpal::Device,
    config: &cpal::StreamConfig,
) -> cpal::Stream {
    let sample_rate = config.sample_rate.0 as f32;
    let mut phase = 0.0f32;
    device.build_output_stream(
        config,
        move |data: &mut [T], _| {
            for sample in data.iter_mut() {
                let value = (phase * 2.0 * std::f32::consts::PI).sin() * 0.2;
                *sample = T::from(&value);
                phase += 440.0 / sample_rate;
                if phase > 1.0 { phase -= 1.0; }
            }
        },
        |err| eprintln!("stream error: {}", err),
        None,
    ).unwrap()
}
```

跑起来你能听到 440 Hz 正弦波(中央 A 音)。

### 10.2 Callback 模型

cpal 用 **callback 模型**:你提供一个 closure,音频线程定期调用它,cpal 给你一个 buffer,你填 sample。

```rust
device.build_output_stream(config, |buffer: &mut [f32], info| {
    // 音频线程,实时优先级,不能 lock / malloc / IO
    for sample in buffer.iter_mut() {
        *sample = generate_next_sample();
    }
}, error_callback, None);
```

关键约束:

- **不能 lock**:Mutex / RwLock 在音频线程会优先级反转,导致 glitch
- **不能 malloc**:分配内存涉及 lock,且耗时不定
- **不能 IO**:磁盘 / 网络慢,会卡住音频
- **不能做长计算**:每帧 ~10ms,你超时就是 glitch

工业音频代码用 **lock-free ring buffer**:主线程 push sample 到 buffer,音频线程 lock-free pop。Day 141 详细讨论。

### 10.3 接入 Day 139 的混音器

把 Day 139 的 Mixer 接到 cpal callback:

```rust
use cpal::traits::*;
use std::sync::{Arc, Mutex};

fn main() {
    let mixer = Arc::new(Mutex::new(Mixer::new()));

    // 主线程:加载样本到 mixer
    {
        let mut m = mixer.lock().unwrap();
        let bgm: Vec<f32> = (0..44100).map(|i| {
            let t = i as f32 / 44100.0;
            (t * 220.0 * 2.0 * std::f32::consts::PI).sin() * 0.3
        }).collect();
        m.play(bgm, 0.3, true);
    }

    // 打开音频流
    let host = cpal::default_host();
    let device = host.default_output_device().unwrap();
    let config = device.default_output_config().unwrap();
    let mixer_clone = Arc::clone(&mixer);

    let stream = device.build_output_stream(
        &config.into(),
        move |buffer: &mut [f32], _| {
            let mut m = mixer_clone.lock().unwrap();
            let output = m.render(buffer.len());
            buffer.copy_from_slice(output);
        },
        |err| eprintln!("error: {}", err),
        None,
    ).unwrap();

    stream.play().unwrap();
    std::thread::sleep(std::time::Duration::from_secs(5));
}
```

**问题**:cpal callback 里 `mixer.lock()` 会优先级反转。工业代码用 lock-free。但 demo 阶段 mutex 够,你能听到 BGM。

### 10.4 双缓冲模式

更稳健的设计:**主线程渲染下一个 buffer**,音频线程只 copy。

```rust
let mixer = Arc::new(Mutex::new(Mixer::new()));
let buffer_a: Arc<Mutex<Vec<f32>>> = Arc::new(Mutex::new(vec![0.0; 1024]));
let buffer_b: Arc<Mutex<Vec<f32>>> = Arc::new(Mutex::new(vec![0.0; 1024]));
let active = Arc::new(AtomicUsize::new(0));  // 0=A, 1=B

// 主线程:渲染到非活跃 buffer
loop {
    let inactive = 1 - active.load(Relaxed);
    {
        let mut buf = if inactive == 0 { buffer_a.lock() } else { buffer_b.lock() };
        let output = mixer.lock().render(1024);
        buf.copy_from_slice(output);
    }
    active.store(inactive, Relaxed);
    std::thread::sleep(Duration::from_millis(10));
}

// 音频线程:copy 活跃 buffer
move |output: &mut [f32], _| {
    let active_idx = active.load(Relaxed);
    let buf = if active_idx == 0 { buffer_a.lock() } else { buffer_b.lock() };
    output.copy_from_slice(&buf[..]);
}
```

主线程慢点没关系,音频线程只 copy 几百 ns。这就是双缓冲模式,降低音频线程负担。Day 141 lock-free ring buffer 是更通用的方案。

### 10.5 ALSA 后端

cpal 在 Linux 用 ALSA 后端。ALSA 直接和内核驱动通信,延迟最低,但要正确配置:

ALSA 默认 period size 1024 frame,buffer size 4096 frame。buffer 大 = 延迟高但稳定。buffer 小 = 延迟低但容易 glitch。


工业音频(实时合成、现场演奏)用 < 256 frame buffer,延迟 < 6 ms。

### 10.7 完整代码:命令行播放器

```rust
use cpal::traits::*;
use std::sync::{Arc, Mutex};

fn main() {
    let host = cpal::default_host();
    let device = host.default_output_device().expect("No output device");
    let supported = device.default_output_config().unwrap();
    let config: cpal::StreamConfig = supported.into();
    let sample_rate = config.sample_rate.0 as f32;
    let channels = config.channels() as usize;

    println!("Output: {} Hz, {} ch", sample_rate, channels);

    // 命令行参数:频率
    let freq: f32 = std::env::args().nth(1)
        .and_then(|s| s.parse().ok())
        .unwrap_or(440.0);
    println!("Playing {} Hz sine wave. Ctrl-C to exit.", freq);

    let mut phase = 0.0f32;

    let stream = device.build_output_stream(
        &config,
        move |buffer: &mut [f32], _| {
            for frame in buffer.chunks_mut(channels) {
                let value = (phase * 2.0 * std::f32::consts::PI).sin() * 0.2;
                phase += freq / sample_rate;
                if phase > 1.0 { phase -= 1.0; }
                for sample in frame.iter_mut() {
                    *sample = value;
                }
            }
        },
        |err| eprintln!("stream error: {}", err),
        None,
    ).unwrap();

    stream.play().unwrap();
    // 等 Ctrl-C
    std::thread::park();
}
```
