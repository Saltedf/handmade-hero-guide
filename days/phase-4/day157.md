# Day 157 · 通用分配入门

> 到现在为止,Casey 用 `malloc`/`free`(C)或 `Box::new`(Rust)分配一切。但是游戏运行 30 分钟后,堆碎片化严重,每次分配几百微秒。今天开始 Casey 自己写 **通用内存分配器**(general-purpose allocator):`Allocate(size)` / `Deallocate(ptr)` 接口,但内部策略可控。这是性能工程的硬仗。

## 0 · 为什么要有这一天

通用分配器(`malloc`/`free`)的问题:

1. **碎片化**:频繁 alloc/free 大小不一的块,堆变成千疮百孔。最终大块分配失败(尽管总空闲够)。
2. **慢**:每次 malloc 几百纳秒到几微秒(取决于实现)。游戏每帧几千次分配 = 几毫秒。
3. **不可预测**:malloc 的延迟 variance 大,有 GC 的语言更糟(Java GC pause 100 ms)。
4. **thread contention**:多线程同时 malloc,内部锁竞争。
5. **leak tracking 难**:malloc 不知道谁分配的,leak 难定位。

游戏行业的对策:

- **arena / scratch**:每帧一次性分配,帧末整体丢弃(Day 160 arena allocator)
- **pool**:固定大小块的 free list(粒子、entity)
- **slab**:多 size pool(类似 kmalloc)
- **custom allocator**:专门化的分配策略

Casey 今天开始写一个**通用分配器**,接口和 malloc 一样,但内部用 free list + coalesce 管理。Day 160 基础版,Day 161 完整版。

这是 HH 最难的一天之一。Casey 用 2 小时讲。我们也仔细讲。

心理锚点:看完今天,你能解释为什么 `Box::new` 不够用,知道 free list + coalesce 是什么,知道 arena vs pool vs general allocator 的差别。

## 1 · Casey 今天做了什么

Casey 在白板画一个内存块:

```
[used 32B][free 64B][used 16B][free 128B][used 8B]
```

分配器的核心数据结构是 **free list**(空闲链表):链表节点描述每个 free 块的 (offset, size)。alloc 时找合适 free 块,split,返回。free 时把块加回 free list,可选 coalesce(合并相邻 free)。

Casey 的核心思路:

1. 初始化:`arena` 一大块内存(比如 1 GB)
2. **维护一个 free list**,初始一项:[0, 1GB]
3. `allocate(size)`:
   - 遍历 free list 找 >= size 的块
   - 取第一个或最小的(best fit / first fit)
   - split:返回前 size 字节,后 size 字节保留在 list
4. `deallocate(ptr, size)`:
   - 把 (ptr, size) 加回 list
   - **coalesce**:检查前后相邻 free 块,合并成大块

视频里 Casey 讨论:

- **first fit vs best fit**:first fit 快但碎片多;best fit 慢但碎片少。游戏用 first fit(性能优先)。
- **coalesce 必要性**:不合并的话,反复 alloc/free 后全是小块,大块分配失败。
- **元数据放哪?**:在 arena 内部(prelude header)还是外部(单独 vector)?Casey 选内部——每个分配前面加 header 记 size。
- **alignment**:分配返回的指针必须 16 字节对齐(SIMD 友好)。

## 2 · 心智模型

### 类比:停车场

一个停车场(arena),开始全空。两件事:

1. **停车(alloc)**:有车来要 1 个位。找一段够长的空位,放车,标记这段为"占用"。
2. **离开(free)**:车走了,标记这段为"空闲"。如果两边都空,**合并**(碎片整理)。

停车场管理员的"空闲位列表"就是 free list。

碎片化:如果 100 辆车交替停走,留下大小不一的空位,大车(巴士)可能停不下,即使总空位够。**coalesce 是关键**。

### 严谨模型:分配器数据结构

#### Free List(链表)

```rust
struct FreeBlock {
    offset: usize,
    size: usize,
    next: Option<usize>,  // 下一个 free block 的 offset
}
```

每个 free 块一个 entry,链表连起来。`alloc` 遍历链表,`free` 插入 + coalesce。

简单,但遍历慢(O(N) blocks)。

#### Implicit Free List

不在 free 块存链表,而是 **每个块(used 或 free)都有 header**,header 含 size + used/free flag:

```
+--------+--------+--------+--------+
| hdr    | payload| hdr    | payload| ...
| 32B    | data   | 16B    | data   |
| FREE   |        | USED   |        |
+--------+--------+--------+--------+
```

遍历整个 arena(从开头跳到结尾)找 free 块。简单,极慢。

#### Explicit Free List

只在 free 块里维护链表指针(前后)。alloc 只遍历 free 块,不遍历 used。快几倍。

#### Segregated Free List

按 size 分桶:8B free list, 16B free list, 32B free list, ... alloc 时直接查对应桶,O(1)。**这是工业级 `jemalloc` / `mimalloc` 的核心思想**。

#### Buddy Allocator

把 arena 反复二分:1MB → 512K → 256K → ... → 64B。alloc 时找最小够大的,递归二分。free 时合并 buddy(对的两个 64B 合并成 128B)。极快,但内碎片(分配 65B 实际用 128B)。

### Coalesce 算法

free 时检查:

1. **prev block** 是否 free?是则合并
2. **next block** 是否 free?是则合并
3. 否则单独加入 list

为了快速找 prev/next,通常在 header 里加 footer 或 boundary tag:

```
| prev_size | size | used_flag | payload ... | prev_size | size | used_flag | ...
```

footer 是 size 的副本,从当前 block 开头减去 footer 大小 = 上个 block 的 size。常数时间找 prev。

### Alignment

每个 alloc 返回的指针必须 16 字节对齐:

```
allocate(64) → ptr 是 16 的倍数
allocate(7) → ptr 也是 16 的倍数(payload 至少 16,内部 padding)
```

实现:

```rust
fn aligned_offset(raw: usize) -> usize {
    (raw + 15) & !15  // 向上取整到 16 的倍数
}
```

### Rust 的 alloc trait

Rust 1.28+ 有 `std::alloc::Allocator` trait(unstable),stable 后可以自定义全局分配器:

```rust
use std::alloc::{GlobalAlloc, Layout};

struct MyAllocator;

unsafe impl GlobalAlloc for MyAllocator {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        // 自己实现
    }
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        // 自己实现
    }
}

#[global_allocator]
static GLOBAL: MyAllocator = MyAllocator;
```

但 Casey 风格不替换全局,自己写显式的 `Arena` struct,游戏代码用 `arena.alloc(...)` 而不是 `Box::new(...)`。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏分配器的典型分层:

```
全局 malloc(C 后备)
      ↓
game_arena(整个游戏的生命周期)
      ↓
frame_arena(单帧分配,帧末丢弃)
      ↓
scratch_arena(临时,函数返回前丢弃)
```

具体:

- **持久 entity / asset**:game_arena,游戏结束才释放
- **每帧临时数据(渲染命令)**:frame_arena,帧末重置
- **函数内临时**:scratch_arena,函数返回前 pop

这是 Casey 后面 Day 200+ 的架构,Day 157-161 是基础设施。

### 3.2 · Linux 系统编程视角

Linux 上的 alloc 层次:

```
应用 malloc() → libc(glibc malloc / mimalloc / jemalloc)
                ↓
                brk() / mmap()  (Linux syscall)
                ↓
                内核 page allocator(buddy system)
                ↓
                硬件 page table
```

`brk` 调整 data segment 大小(小分配);`mmap` 申请匿名页(大分配,> 128KB 默认)。

Linux 内核用 **buddy allocator** 管物理页。glibc malloc 用 **ptmalloc**(类似 Doug Lea's dlmalloc),free 后不立即还内核(避免 thrash),保留在 user space arena。

替换 glibc malloc:

```bash
LD_PRELOAD=/usr/lib/libmimalloc.so ./my_game
# 比 glibc 快 10-30%
```

Rust 默认用 `jemalloc`(1.32 前)或系统 malloc(1.32+)。

### 3.3 · Rust 生态视角

Rust 的分配器生态:

- **`bumpalo`**:arena 分配器(只 alloc,不 free,整体丢弃)
- **`typed-arena`**:类型化 arena(同类型连续)
- **`slotmap`**:slot-based,带 generation
- **`mimalloc`** / **`jemallocator`**:全局分配器替换

`bumpalo` 示例:

```rust
use bumpalo::Bump;

let bump = Bump::new();
let x = bump.alloc(42);  // 不需要 free,整个 bump drop 时释放
let y = bump.alloc([1, 2, 3]);
// 函数末 bump drop,所有分配同时释放
```

这是 Day 160-161 的工业级实现。Casey 自己写,我们今天用 bumpalo 类比理解。

### 3.4 · 性能视角

malloc 性能对比(分配 64 字节):

| 分配器 | 时间 |
|---|---|
| glibc malloc | ~150 ns |
| jemalloc | ~80 ns |
| mimalloc | ~30 ns |
| arena bump | ~5 ns |
| stack alloc | ~1 ns |
| slab (固定 size) | ~5 ns |

arena 比 malloc 快 30 倍,这是为什么游戏大量用 arena。

## 5 · 对照与变奏

### 分配器家族

```
General Malloc
├── dlmalloc(classic)
├── ptmalloc(glibc)
├── jemalloc(Facebook)
├── mimalloc(Microsoft)
└── scudo(Google)

Specialized
├── Arena(整体释放)
├── Pool(固定 size)
├── Slab(多 size pool)
└── Buddy(二分合并)
```

### 内碎片 vs 外碎片

- **内碎片**:分配 65B,实际占 128B(对齐 + 块大小)。多出来的 63B 是内碎片。
- **外碎片**:总空闲够,但不连续,大块分配失败。

减少内碎片:小 size 用小 pool。
减少外碎片:coalesce + 移动内存(compact,慢)。

- **1960s**:basic free list

- **1990s**:Linux slab allocator
- **2000s**:jemalloc(Facebook)
- **2010s**:mimalloc(Microsoft,极快)
- **2020s**:Rust custom allocators 稳定化

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:arena bump allocator 没有 free,内存会泄漏吗?

**参考解答**:不会"泄漏"——arena 是短生命周期,整体丢弃时不释放单个分配,而是把整个 arena 的内存一次还回 OS(或保留复用)。这是"短期空间换时间"的策略。

如果 arena 一直不 drop,那确实占着内存。游戏里通常:

- frame_arena 每帧重置(`frame_arena.reset()`),不 drop
- game_arena 在游戏结束时 drop
- scratch_arena 在函数返回时 pop(标记之前的位置)

### Lv2 · 动手实践

**题**:用 `bumpalo` crate 写一个 demo,在一个 arena 里分配 1000 个 Vec<u8>,每个 1024 字节。然后整体 drop。打印分配前后 arena 的内存使用。对比直接用 `Vec::new` 的内存分配次数。

**参考解答**:

```rust
// Cargo.toml: bumpalo = "3"

use bumpalo::Bump;

fn main() {
    let bump = Bump::new();
    println!("arena allocated: {} bytes", bump.allocated_bytes());

    let mut ptrs = Vec::new();
    for i in 0..1000 {
        let v: &mut [u8] = bump.alloc_slice_fill_copy(1024, (i % 256) as u8);
        ptrs.push(v.as_mut_ptr());
    }
    println!("after 1000 allocs: {} bytes", bump.allocated_bytes());

    // 不需要 free 单个,bump drop 时整体释放
    drop(bump);
    println!("done");
}
```

对比 Vec::new 需要 1000 次 malloc,bumpalo 用一次大 mmap + 1000 次 bump pointer。

## 8 · Rust / Arch 落地代码

最简单的 free-list allocator(教学版):

```rust
use std::alloc::Layout;

const BLOCK_HEADER_SIZE: usize = 16;  // size + flags

#[repr(C)]
struct BlockHeader {
    size: usize,        // payload 大小(不含 header)
    is_free: bool,
}

pub struct FreeListAllocator {
    memory: Vec<u8>,
    free_list: Vec<(usize, usize)>,  // (offset, size)
}

impl FreeListAllocator {
    pub fn new(capacity: usize) -> Self {
        let mut s = Self {
            memory: vec![0u8; capacity],
            free_list: Vec::new(),
        };
        s.free_list.push((0, capacity));
        s
    }

    pub fn allocate(&mut self, size: usize, align: usize) -> Option<*mut u8> {
        let total_size = (size + BLOCK_HEADER_SIZE + align - 1) & !(align - 1);

        // first fit
        let mut found_idx = None;
        for (i, &(offset, block_size)) in self.free_list.iter().enumerate() {
            if block_size >= total_size {
                found_idx = Some(i);
                break;
            }
        }

        let idx = found_idx?;
        let (offset, block_size) = self.free_list[idx];

        // 写 header
        let header = BlockHeader { size: total_size, is_free: false };
        let header_bytes = unsafe {
            std::slice::from_raw_parts(&header as *const BlockHeader as *const u8, BLOCK_HEADER_SIZE)
        };
        self.memory[offset..offset + BLOCK_HEADER_SIZE].copy_from_slice(header_bytes);

        // 更新 free list
        let remaining = block_size - total_size;
        if remaining > 0 {
            self.free_list[idx] = (offset + total_size, remaining);
        } else {
            self.free_list.remove(idx);
        }

        let ptr = self.memory.as_mut_ptr().wrapping_add(offset + BLOCK_HEADER_SIZE);
        Some(ptr)
    }

    pub fn deallocate(&mut self, ptr: *mut u8, _size: usize) {
        let base = self.memory.as_mut_ptr() as usize;
        let p = ptr as usize;
        if p < base || p >= base + self.memory.len() {
            return;
        }
        let offset = p - base - BLOCK_HEADER_SIZE;
        // 读 header 拿 size
        let header_size = u64::from_le_bytes(
            self.memory[offset..offset+8].try_into().unwrap()
        ) as usize;
        // 简化:加回 free list,不 coalesce
        self.free_list.push((offset, header_size));
        // TODO Day 161: coalesce
    }
}

fn main() {
    let mut alloc = FreeListAllocator::new(1024 * 1024);
    let p1 = alloc.allocate(64, 8).unwrap();
    let p2 = alloc.allocate(128, 8).unwrap();
    let p3 = alloc.allocate(64, 8).unwrap();
    println!("allocated 3 blocks: {:p}, {:p}, {:p}", p1, p2, p3);

    alloc.deallocate(p2, 128);
    println!("freed p2");

    let p4 = alloc.allocate(64, 8).unwrap();
    println!("allocated p4: {:p}", p4);
}
```

**关键 Rust**:
- `vec![0u8; capacity]` —— heap 分配大块。生产用 mmap + unsafe。
- `wrapping_add(offset)` —— 指针算术,wrap-around 安全。
- `*mut u8` —— 裸指针,绕过 Rust 借用规则。**这是 unsafe 区,要在 unsafe 块里 deref**。
- 简化版不 coalesce(留 Day 161)。

### A.7 工业 Rust 代码示例

让我提供一个具体的工业 Rust 代码示例,综合 phase-4 的概念:

```rust
use std::sync::Arc;
use std::sync::RwLock;
use std::collections::HashMap;
use std::path::Path;

/// Asset storage with sharded locking and async loading.
pub struct AssetStorage<T> {
    shards: Vec<RwLock<HashMap<u32, Arc<T>>>>,
    loader: Box<dyn Fn(u32) -> Result<T, AssetError> + Send + Sync>,
}

impl<T: Send + Sync + 'static> AssetStorage<T> {
    pub fn new<F>(loader: F) -> Self
    where
        F: Fn(u32) -> Result<T, AssetError> + Send + Sync + 'static,
    {
        let num_shards = 16;
        let mut shards = Vec::with_capacity(num_shards);
        for _ in 0..num_shards {
            shards.push(RwLock::new(HashMap::new()));
        }
        Self {
            shards,
            loader: Box::new(loader),
        }
    }
    
    pub fn get(&self, id: u32) -> Result<Arc<T>, AssetError> {
        let shard_idx = (id as usize) % self.shards.len();
        
        // Fast path: read lock
        {
            let shard = self.shards[shard_idx].read().unwrap();
            if let Some(asset) = shard.get(&id) {
                return Ok(Arc::clone(asset));
            }
        }
        
        // Slow path: load and insert
        let asset = (self.loader)(id)?;
        let arc = Arc::new(asset);
        
        let mut shard = self.shards[shard_idx].write().unwrap();
        let entry = shard.entry(id).or_insert(Arc::clone(&arc));
        Ok(Arc::clone(entry))
    }
    
    pub fn evict_unused(&self) {
        for shard in &self.shards {
            let mut shard = shard.write().unwrap();
            shard.retain(|_, arc| Arc::strong_count(arc) > 1);
        }
    }
}

#[derive(Debug)]
pub enum AssetError {
    NotFound(u32),
    Io(std::io::Error),
    Invalid(String),
}

// 用法
fn main() {
    let storage: AssetStorage<Vec<u8>> = AssetStorage::new(|id| {
        Ok(vec![id as u8; 100])
    });
    
    let a = storage.get(42).unwrap();
    let b = storage.get(42).unwrap();
    assert!(Arc::ptr_eq(&a, &b));
}
```

这是工业级 Rust asset storage 的完整骨架——分桶 RwLock + Arc + lazy loading + eviction。
