## 2 · Phase 4 整体回顾

### 2.1 五大子系统的耦合关系

让我把 Phase 4 学到的所有东西画成一张依赖图。这张图你脑子里要永远清晰——它就是工业游戏引擎的"地基拓扑":

```
                        ┌──────────────────┐
                        │  Asset 系统      │  ← .hha 文件格式 / 打包 / 流式
                        │  (Day 132-154)   │

                                 │
                ┌────────────────┼─────────────────┐
                ↓                ↓                 ↓
        ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
        │ 字体系统     │  │ 音频/混音器  │  │ Bitmap 渲染  │
        │ (Day 162-175)│  │ (Day 140-146)│  │              │
        └──────┬───────┘  └──────┬───────┘  └──────────────┘
               │                 │
               ↓                 ↓
        ┌────────────────────────────────┐
        │  通用内存分配器                │  ← Free list / coalesce / boundary tag
        │  (Day 157-161)                 │
        └────────────┬───────────────────┘
                     │
        ┌────────────┴───────────────────┐
        ↓                                ↓
```

**关键洞察**——Phase 4 的真正价值不是单个组件,而是这套依赖结构本身。同样的结构在 bevy、Unity、Unreal 里都能找到(只是组件名不同)。学完后你能"看懂任何引擎的骨架"。

### 2.2 五段子时间线

让我把 64 天分成 5 段,每段单独看:

#### Day 112-121:性能基础 + SIMD
- **CPU 性能心智模型**:吞吐 vs 延迟,port pressure,μops 调度
- **SIMD 基础**:SSE 寄存器(XMM, 128-bit)、AVX(YMM, 256-bit)、intrinsics(`_mm_add_ps`)
- **Day 121 tiled rendering marathon**:4+ 小时一集,把 SIMD + 多线程 + 渲染整合。这是 Handmade Hero 历史上最长的几集之一
- **学到的核心**:CPU 不是"快"或"慢",而是"哪个 port 在跑"

#### Day 122-131:多线程
- **线程基础**:thread create/join、TLS(thread-local storage)
- **Atomic**:memory order(acquire/release/relaxed/seq_cst)、atomic 重排
- **Work queue 设计**:SPSC(单生产者单消费者)、MPMC、lock-free ring buffer
- **异步 ground chunk composition**:大世界 chunk 后台生成,主线程不卡
- **学到的核心**:并发不是"加锁",是"设计通信协议"

#### Day 132-146:Asset 系统 + 音频
- **.hha 文件格式设计**:magic number、version、header、asset table、data blob
- **打包 / 加载 / 多文件合并**:多个 .hha 文件挂载成虚拟文件系统
- **WAV 加载 + 流式 + 混音**:解码 PCM、变调播放、多音轨混合
- **SSE 混音器**:4 个 sample 一组、linear interp、volume
- **学到的核心**:二进制文件格式 = "把内存结构磁盘化"

#### Day 147-154:.hha 完整实现
- **Asset 文件定义 / header / writer / loader**:从设计到完整实现
- **多文件合并 / 文件查找**:hash table 索引、generation counter 防止 dangling
- **学到的核心**:reference counting 不是辅助功能,是核心架构

#### Day 155-156:粒子系统
- **粒子数据结构**:AoS(Array of Struct)vs SoA(Struct of Array)
- **拉格朗日 vs 欧拉模拟**:粒子追踪 vs 网格追踪
- **学到的核心**:数据布局决定性能(缓存友好)

#### Day 157-161:通用分配器
- **Free list + coalesce + boundary tag**:工业级 malloc/free
- **O(1) dealloc**:不传 size 也能正确释放
- **学到的核心**:分配器是"工程品味的试金石"

#### Day 162-175:字体系统
- **TrueType 理论**:bezier 曲线、grid fitting、hinting
- **Win32 GDI**:GetGlyphOutline、字符到 glyph index
- **Kerning**:字符对的间距调整
- **文本渲染**:baseline、em-square、精确像素对齐
- **Unicode 稀疏支持**:binary search + sparse table,处理 CJK 大 codepoint 范围
- **学到的核心**:文本渲染是"工程 + 美学"的交叉

### 3.1 · 🎮 游戏编程视角

工业游戏引擎的"Phase 4 等价物"是什么?让我对比:

**Unreal Engine 5**:
- **Asset 系统**:`.uasset` + `.uexp` + `.ubulk` 三件套,等同 .hha
- **分配器**:FMalloc 接口,多个后端(binned、tbb、jemalloc)

- **字体**:TextMesh Pro(SDF)+ FontEngine
- **音频**:AudioMixer + Audio Source
- **多线程**:C# Job System + Burst 编译器(自动 SIMD!)

**Godot**:

- **音频**:AudioServer + AudioStream

**Bevy**:

### 3.2 · 🎨 图形学视角

Phase 4 的图形学能力清单:

**字体渲染**:理解了 em-square、baseline、ascent/descent、line gap、kerning pair、Unicode codepoint vs glyph index。这是从"画字符"升级到"专业排版"。

**Bitmap 渲染**:理解了精灵 blit、alpha 混合、premultiplied alpha、双线性插值。Phase 5 加 OpenGL 后这些概念直接迁移——texture sampling 就是"GPU 上自动做的双线性"。

**SIMD 渲染**:Day 121 的 tiled rendering marathon 教你"软件光栅化"。即便以后用 GPU,知道光栅化在 CPU 上怎么做,才能理解 GPU 在做什么、为什么会瓶颈。

**坐标系**:Handmade Hero 用 top-left 原点 + y-down,这是 2D 像素艺术惯例。3D 引擎一般用 bottom-left + y-up(GLFW / Vulkan 默认)。Phase 5 切 OpenGL 时这个差异要小心。

### 3.3 · 🐧 Linux 系统编程视角

Phase 4 学的许多概念,Linux 用户态工具直接相关:

**多线程 + atomic**:你写的 SPSC queue,和 Linux 内核的 `kfifo`、`lqueue` 是同一种数据结构。`std::sync::atomic` 的 `Ordering::Acquire / Release` 直接对应 C11 atomic 和 Linux 内核 `smp_store_release / smp_load_acquire`。

**分配器**:你写的 free list,工业上有 tcmalloc / jemalloc / mimalloc。**装来替换系统 malloc**:
```bash
# Arch
sudo pacman -S jemalloc mimalloc

# 用 LD_PRELOAD 替换(不影响编译)
LD_PRELOAD=/usr/lib/libmimalloc.so.2 ./your_game
LD_PRELOAD=/usr/lib/libjemalloc.so.2 ./your_game

# 测量哪种分配器对你的负载最快
hyperfine --warmup 3 \
    './target/release/game' \
    'LD_PRELOAD=/usr/lib/libmimalloc.so.2 ./target/release/game' \
    'LD_PRELOAD=/usr/lib/libjemalloc.so.2 ./target/release/game'
```

**文件 I/O**:你的 .hha 加载用了 `read()` / `mmap()`。Linux 上 `mmap` 大文件比 `read` 快(零拷贝),但小文件 `read` 更快(避免 page fault 开销)。**经验法则**:< 64KB 用 read,>= 64KB 用 mmap。

**字体**:你的字体系统用了 Win32 GDI,移植到 Linux 要用 FreeType + FontConfig:
```bash
# 查看系统装了哪些字体
fc-list | head -20
fc-list :lang=zh | head -5  # 中文字体

# 字体信息
fc-query /usr/share/fonts/noto/NotoSansCJK-Regular.ttc

# FontForge 编辑
fontforge /path/to/font.ttf
```

**音频**:你的 SSE 混音器,Linux 用户态用 ALSA / PulseAudio / PipeWire 后端。PipeWire 现代发行版默认,低延迟。

## 5 · 对照与变奏

### 5.1 历史演化

游戏引擎"基础设施层"的演化:

- **1980s**:一切手写,无标准。游戏 ROM 直接放二进制数据。
- **1990s**:开始有"资源文件"概念(Blizzard 的 MPQ、id Software 的 WAD)。
- **2000s**:引擎内置 asset 系统(Unreal Package、Unity AssetBundle)。
- **2010s**:分布式构建 + 增量打包(Unreal Engine 4 的 .uasset + .uexp + .ubulk 三件套)。
- **2020s**:基于 Git LFS / Perforce 的版本化 asset + 实时编辑(Unity Addressables、Unreal Engine 5 One File Per Actor)。

字体系统演化:
- **1980s**:点阵字体,8x8 或 16x16
- **1990s**:TrueType / Type 1 矢量字体普及
- **2000s**:OpenType 整合 + ClearType 子像素渲染
- **2010s**:SDF(Signed Distance Field)字体,Valve 论文推广
- **2020s**:GPU glyph atlas + 实时矢量整形(cosmic-text / HarfBuzz + FreeType)

每一步 Casey 都演示了**原理版**,工业版只是更成熟。

### 5.2 Phase 5 之后这些组件会怎么演化?

- **分配器**:Phase 5 加 debug overlay 后,debug UI 也用同一个分配器。Phase 6+ 加 GPU buffer 后,GPU 内存也要分配(类似 vulkan allocator)
- **Asset 系统**:Phase 5 加 OpenGL 后,asset 里的 bitmap 升级为 GPU texture,加 .dds / .ktx 压缩格式
- **字体**:Phase 5 切 GPU 后,字体用 SDF texture atlas,可在 GPU 上任意缩放不糊
- **音频**:Phase 5 后基本稳定,Phase 6+ 可能加 3D 空间音频
- **多线程**:Phase 5 加 OpenGL 后,渲染线程独立(经典渲染线程架构)

### 8.3 SIMD 模块

```rust
// src/simd.rs
// 用 std::arch x86_64 SSE intrinsics,4 个 f32 一组求和。
// 这是 Day 112-121 学的概念的 Rust 实现。

#[cfg(target_arch = "x86_64")]
use std::arch::x86_64::*;

#[cfg(target_arch = "x86_64")]
pub fn sum_sse(data: &[f32]) -> f32 {
    // 安全性:CPU 必须支持 SSE2(x86_64 必然支持)
    assert!(data.len() >= 4, "data too short for SSE");
    unsafe {
        // _mm_setzero_ps:创建一个全 0 的 __m128(4 个 f32)
        let mut acc = _mm_setzero_ps();

        // 4 个一组,用 _mm_loadu_ps 加载(对齐不要求,稍慢但通用)
        let chunks = data.chunks_exact(4);
        for chunk in chunks {
            // unaligned load:从 chunk.as_ptr() 读 16 字节
            let v = _mm_loadu_ps(chunk.as_ptr());
            // _mm_add_ps:逐元素加
            acc = _mm_add_ps(acc, v);
        }

        // horizontal add:SSE 没有直接"4 个 f32 → 1 个 f32"指令
        // _mm_hadd_ps 做横向加:v[0]+v[1], v[2]+v[3], ...
        // 做两次后 acc = [s, s, s, s],取 [0]
        acc = _mm_hadd_ps(acc, acc);
        acc = _mm_hadd_ps(acc, acc);

        // _mm_cvtss_f32:取最低 32 位作为 f32
        let mut sum = _mm_cvtss_f32(acc);

        // 处理 remainder(不能被 4 整除的尾巴)
        let remainder = data.chunks_exact(4).remainder();
        for &x in remainder {
            sum += x;
        }
        sum
    }
}

// 跨平台 fallback:不支持 SSE 时走标量
#[cfg(not(target_arch = "x86_64"))]
pub fn sum_sse(data: &[f32]) -> f32 {
    data.iter().sum()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn sum_works() {
        let data: Vec<f32> = (0..100).map(|i| i as f32).collect();
        let expected: f32 = (0..100).map(|i| i as f32).sum();
        assert!((sum_sse(&data) - expected).abs() < 1e-3);
    }
}
```

### 8.4 分配器模块

```rust
// src/alloc.rs
// Bump allocator:最简单的分配器。分配 O(1),释放只能整体 reset。
// 适合"一帧的临时分配"。

pub struct BumpAllocator {
    memory: Vec<u8>,
    offset: usize,
}

impl BumpAllocator {
    pub fn new(size: usize) -> Self {
        Self {
            memory: vec![0u8; size],
            offset: 0,
        }
    }

    /// 分配 size 字节,按 align 对齐。返回 None 表示 OOM。
    pub fn allocate(&mut self, size: usize, align: usize) -> Option<&mut [u8]> {
        // 对齐 offset 向上到 align 的倍数
        let mask = align - 1;
        let aligned_offset = (self.offset + mask) & !mask;

        let new_offset = aligned_offset.checked_add(size)?;
        if new_offset > self.memory.len() {
            return None;
        }

        let slice = &mut self.memory[aligned_offset..new_offset];
        self.offset = new_offset;
        Some(slice)
    }

    pub fn used(&self) -> usize {
        self.offset
    }

    pub fn reset(&mut self) {
        self.offset = 0;
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn allocates_and_aligns() {
        let mut alloc = BumpAllocator::new(1024);

        let a = alloc.allocate(10, 8).unwrap();
        assert_eq!(a.len(), 10);

        let b = alloc.allocate(20, 16).unwrap();
        // b 应该 16 字节对齐
        let b_addr = b.as_ptr() as usize;
        assert_eq!(b_addr % 16, 0);
    }

    #[test]
    fn oom_returns_none() {
        let mut alloc = BumpAllocator::new(64);
        alloc.allocate(60, 1).unwrap();
        assert!(alloc.allocate(60, 1).is_none());
    }
}
```

### 8.5 稀疏字体模块

```rust
// src/font.rs
// Sparse font:只保存已添加的 codepoint,用 binary search 查找。
// 适合 CJK 这种 codepoint 范围巨大(2万+)但只用到一小部分的场景。

#[derive(Debug)]
pub struct SparseFont {
    // 两个并行数组:codepoints 排序,advances 对应
    codepoints: Vec<u32>,
    advances: Vec<f32>,
}

impl SparseFont {
    pub fn new() -> Self {
        Self {
            codepoints: vec![],
            advances: vec![],
        }
    }

    /// 添加 codepoint -> advance 映射。保持 codepoints 排序。
    pub fn add(&mut self, codepoint: u32, advance: f32) {
        match self.codepoints.binary_search(&codepoint) {
            Ok(i) => {
                // 已存在,更新 advance
                self.advances[i] = advance;
            }
            Err(pos) => {
                // 不存在,在 pos 位置插入(保持排序)
                self.codepoints.insert(pos, codepoint);
                self.advances.insert(pos, advance);
            }
        }
    }

    /// 查找 codepoint 的 advance。未找到返回 None。
    pub fn lookup(&self, codepoint: u32) -> Option<f32> {
        self.codepoints
            .binary_search(&codepoint)
            .ok()
            .map(|i| self.advances[i])
    }

    /// 计算字符串在当前字体下的渲染宽度(像素)。
    pub fn text_width(&self, text: &str) -> f32 {
        let mut width = 0.0;
        for c in text.chars() {
            // c as u32 把 Rust char(UTF-32)转成 Unicode codepoint
            if let Some(adv) = self.lookup(c as u32) {
                width += adv;
            }
            // 未找到的字符跳过(实际引擎应显示 .notdef)
        }
        width
    }

    pub fn len(&self) -> usize {
        self.codepoints.len()
    }

    pub fn is_empty(&self) -> bool {
        self.codepoints.is_empty()
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn sparse_lookup_works() {
        let mut font = SparseFont::new();
        // ASCII
        font.add(b'H' as u32, 8.0);
        font.add(b'e' as u32, 7.0);
        font.add(b'l' as u32, 5.0);
        font.add(b'o' as u32, 8.0);
        // CJK(U+4F60 = 你,U+597D = 好)
        font.add(0x4F60, 16.0);
        font.add(0x597D, 16.0);

        assert_eq!(font.lookup(b'H' as u32), Some(8.0));
        assert_eq!(font.lookup(0x4F60), Some(16.0));
        assert_eq!(font.lookup(0xFFFF), None);  // 没添加的
    }

    #[test]
    fn mixed_text_width() {
        let mut font = SparseFont::new();
        font.add(b'H' as u32, 8.0);
        font.add(b'i' as u32, 5.0);
        font.add(0x4F60, 16.0);  // 你

        // "Hi你" = 8 + 5 + 16 = 29
        assert_eq!(font.text_width("Hi你"), 29.0);
    }
}
```

### 8.6 SSE 混音器

```rust
// src/mixer.rs
// 简化版混音器:把两个音轨相加,用 SSE 加速。
// 真实的混音器还要处理 sample rate conversion,这里略。

#[cfg(target_arch = "x86_64")]
use std::arch::x86_64::*;

#[cfg(target_arch = "x86_64")]
pub fn mix_sse(dst: &mut [f32], src: &[f32]) {
    let n = dst.len().min(src.len());
    let (dst_sse, dst_tail) = dst[..n].split_at_mut(n - n % 4);
    let (src_sse, src_tail) = src[..n].split_at(n - n % 4);

    unsafe {
        for (d_chunk, s_chunk) in dst_sse.chunks_exact_mut(4).zip(src_sse.chunks_exact(4)) {
            let d = _mm_loadu_ps(d_chunk.as_ptr());
            let s = _mm_loadu_ps(s_chunk.as_ptr());
            // 逐元素加,clip 到 [-1, 1] 防止爆音(简化:不 clip)
            let sum = _mm_add_ps(d, s);
            _mm_storeu_ps(d_chunk.as_mut_ptr(), sum);
        }
    }

    // 处理 tail
    for (d, s) in dst_tail.iter_mut().zip(src_tail.iter()) {
        *d += *s;
    }
}

#[cfg(not(target_arch = "x86_64"))]
pub fn mix_sse(dst: &mut [f32], src: &[f32]) {
    let n = dst.len().min(src.len());
    for i in 0..n {
        dst[i] += src[i];
    }
}
```
