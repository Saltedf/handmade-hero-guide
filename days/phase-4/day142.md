# Day 142 · 逐样本音量插值

> Day 140 的 mixer 在每个 sample 上乘一个固定的 volume。结果:你按音量键想从 0.3 调到 0.5,听到的不是平滑过渡,而是"咔"的一下,因为相邻两段 sample 之间跳变几十甚至几百的振幅——这就是 **zipper noise**(拉链噪声)。今天 Casey 要让音量在每两个 sample 之间线性过渡,使增益变化听不见。

## 0 · 为什么要有这一天

声音是空气压强的连续变化。**离散 PCM 采样**是它的等间距瞬时值,但人耳仍然把相邻 sample 当作连续信号的近似——前提是 **相邻 sample 的差不至于太大**。

考虑一个 1 kHz 的正弦波,采样率 48 kHz,每个周期 48 个 sample。相邻 sample 的最大差大约是 `2π · 1000/48000 ≈ 0.131` 倍峰值。如果你的输出限幅在 ±1.0,相邻差最多 0.131,人耳听不出"阶梯感"。

但**音量突然改变时**问题来了:sample N 的振幅是 0.3,sample N+1 突然变成 0.5(因为外面那一帧把 `Volume = 0.5` 写进来了),相邻差变成 0.2 × 信号,在 1 kHz 上听起来像叠加了一个高频"咔哒"声。专业叫法是 **discontinuity**(不连续),听感叫 zipper noise。

修复方法很直接:**不要让 `Volume` 在一个 sample 上跳变,让它在一段 sample 上线性插值过去**。具体说,如果你这一帧开始时 `Volume = 0.3`,结束时目标 `Volume = 0.5`,那么第 i 个 sample 用 `Volume = 0.3 + (0.5-0.3) * i/N`。

这听起来简单,但里面藏着几个工程坑:

1. **谁来设定"目标 Volume"?** 不可能是音频线程自己——它每秒只跑 480 次,UI 线程的玩家输入来得随时。需要共享一个 atomic float。
2. **多少 sample 内插值?** 太快(1 ms)听不见过渡但仍有 zipper;太慢(100 ms)响应迟钝。30-50 ms 是甜区。
3. **声音源本身在变化时怎么办?** 比如音乐淡入,开始的目标是 0,5 秒后是 0.5。如果用 50 ms 插值,每帧重新设目标,实际曲线是阶梯状而不是斜线。

这套问题是 **数值控制 / 自动化(automation)** 的入门。所有 DAW(Digital Audio Workstation,如 Ableton、FL Studio)、合成器、视频剪辑软件都面对它。游戏里同样普遍——相机跟随、AI 平滑移动、UI 动画,背后都是同一招:interpolation。

心理锚点:看完今天,你能写出一个能任意时刻被外部线程改变音量目标值、混音器内部用 30 ms 线性插值的 mixer,人耳完全听不出突变。

## 1 · Casey 今天做了什么

Casey 的改动看起来很小,但思路转折很重要:

1. 把 `playing_sound` 结构里的 `Volume` 字段从单一值改成 `current_volume` + `target_volume` 两个值
2. 在 mixer 循环里,**每处理一个 sample,就把 `current_volume` 向 `target_volume` 逼近一小步**:
   - 步长 = `(target - current) / fade_samples`
   - `fade_samples` 在他代码里用了一个工程经验值,约等于一帧的样本数
3. 当外部代码(玩家按键 / 游戏逻辑)改变音量时,它**只改 `target_volume`**,不直接碰 `current_volume`
4. 这样 mixer 内部的"音量曲线"就是逐 sample 平滑的

Casey 反复强调一件事:**音频线程绝不能从外部直接读 `target_volume` 然后跳变,因为它和主线程是异步的**。如果外部线程任意时刻能写 `current_volume`,而 mixer 也在写,会出现 torn write(撕裂写)——一个 32 位 float 在 x86 上理论是原子的,但语义上你不能让"中间状态"被听到。所以严格做法是:**主线程只写 `target`,mixer 线程独占 `current`**。

 Casey 还讨论了"为什么不用指数插值":线性插值听起来已经够好,指数对人耳更自然(感知是对数),但代码复杂,先用线性。这是典型的 "够用即可" 工程判断。

## 2 · 心智模型

### 类比:刹车

你开车 100 km/h,看到红灯想停。**最差做法**:瞬间把速度变 0 —— 撞墙,你飞出去。**最好做法**:踩刹车,速度从 100 在 50 米内降到 0。

音量也是一样。你不能让 sample N 的振幅 0.3、sample N+1 突然 0 —— 听者耳膜感受到的就是"撞墙"。你要让它在 ~30 ms 内匀减速到 0,这就是 fade-out。反过来从 0 到 0.3 就是 fade-in。

刹车距离取决于车速和刹车力度。音量的"刹车距离"取决于 sample rate 和 fade 时长:48 kHz × 30 ms = 1440 个 sample。

### 严谨模型:线性插值公式

设当前 sample 索引 i = 0,这一段 fade 的总 sample 数是 N。设起始音量 v0,目标音量 v1。则第 i 个 sample 的实际音量是:

```
v(i) = v0 + (v1 - v0) * (i / N)       for i = 0..N
```

N 个 sample 后到达 v1。如果外部还没改 `target`,继续以 v1 输出。如果中途 target 又变了怎么办?重新以"当前 current"为 v0、新 target 为 v1,继续 N 个 sample。

实现上更紧凑的写法是 **exponential smoothing**(指数平滑):

```
current += (target - current) * alpha    每个 sample
```

`alpha = 1/N` 时,大 N 步后收敛到 target。这是 Casey 实际用的形式,因为不需要记 `i`,只要 `current` 一个状态。

**线性 vs 指数对比**:
- 线性:**严格**在 N 个 sample 内到达 target,代码需要 N 计数器
- 指数:**渐近**到达(理论上永远到不了,实际 alpha 步长够小忽略误差),代码简单

对人耳,两者听感几乎无差别。Casey 选了指数(简洁)。

### 边界:Volume = 0 的浮点除法

如果你用线性插值 `(v1 - v0) / N`,只要 N > 0 就没问题。但如果你想"瞬时跳变"(N = 0),会除零。游戏代码常见错误:玩家按 Mute 键,N 设成 0,结果 NaN 横扫整段 buffer,扬声器输出刺耳噪音。

防御性写法:**永远不让 N = 0**。要么 `if N == 0 { N = 1 }`,要么改用指数平滑(没有除法)。

### Rust 的 f32 atomic 问题

`std::sync::atomic::AtomicF32` 在稳定 Rust 里**不存在**(截至 2024)。能 atomic 的整数和指针类型有(`AtomicU32` 等),但 f32 没有。怎么共享一个 float?

三种做法:

1. **用 `AtomicU32` 装位模式**:把 f32 的 bits 当 u32 存,用 `AtomicU32::load/store`。`f32::to_bits()` / `f32::from_bits()`。安全、零开销。
2. **用 `Mutex<f32>`**:简单但有锁,音频线程锁住会卡。不推荐。
3. **用 `parking_lot::RwLock<f32>`**:多读单写锁。比 Mutex 好,但仍不适合音频线程。

Casey 在 C 里没有这个问题(Windows 上 aligned 32-bit write 是原子的),Rust 上要显式表达。今天 §8 给出 `AtomicF32` 的封装。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏中插值无处不在,音量只是入门:

- **相机跟随**:玩家位置变了,相机不要瞬间跳过去,要 lerp(linear interpolation)过去。
- **UI 动画**:按钮 hover 时颜色渐变 200 ms。
- **AI 平滑**:敌人朝向转向玩家时,不要瞬移方向,要 100 ms 转。
- **手柄震动**:强度从 0 到 1 用 50 ms 渐入。
- **光照过渡**:进入洞穴时,环境光 200 ms 内变暗。

**通用模式**:外部世界(玩家输入、游戏事件)产生"目标值",内部状态(相机位置、UI 颜色、音量)以一定速度向目标逼近。这套叫 **smooth damp**(Unity 术语)或 **critically damped spring**(物理术语)。

工业级做法不是线性插值,而是 **critically damped smoothing**:

```
current = current + dt * velocity
velocity = velocity + dt * (-omega * omega * (current - target) - 2 * omega * velocity)
```

omega 是响应速度(2/omega = 时间常数)。这套对玩家手感更好(没有突变,但有惯性感),Casey 在 Day 178 详细讲。

### 3.2 · Rust 生态视角

`AtomicF32` 封装:

```rust
use std::sync::atomic::{AtomicU32, Ordering};

struct AtomicF32 {
    bits: AtomicU32,
}

impl AtomicF32 {
    fn new(v: f32) -> Self {
        Self { bits: AtomicU32::new(v.to_bits()) }
    }
    fn load(&self, ord: Ordering) -> f32 {
        f32::from_bits(self.bits.load(ord))
    }
    fn store(&self, v: f32, ord: Ordering) {
        self.bits.store(v.to_bits(), ord);
    }
}
```

**关键 Rust 概念**:

- `f32::to_bits()` —— 把 f32 的位模式按 IEEE 754 解释为 u32。这是 zero-cost 的 reinterpret。
- `AtomicU32::new(x)` —— 创建原子 u32。
- `Ordering::Relaxed` —— 不需要跨线程同步,只要原子性,用 Relaxed(最快)。
- `Ordering::Release` / `Acquire` —— 配套用,发布者 Release 写,读者 Acquire 读,保证看到对应的内存写入。

在 §8 给完整代码。

### 3.3 · Linux 系统编程视角

Linux 上和音频插值相关的两个工具:

1. **ALSA 的 period**:ALSA 把环形 buffer 分成若干 period,每个 period 中断一次。我们之前在 Day 138 讲过。`period_size` 决定了"音频线程被唤醒的频率",也决定了 mixer 每次循环处理多少 sample。典型值 1024 sample(21 ms @ 48 kHz)。如果你想让 fade 时间精确到 1 ms,period 必须小于 1 ms,这就对调度延迟要求很高。
2. **PIPEWIRE** 的 quantum:PipeWire(现代 Linux 音频服务器)有 dynamic quantum,可以低到 32 sample(0.67 ms)。专业音乐制作用 PipeWire + 32 sample quantum,延迟极低。

## 4 · 认知地图

### 4.1 上级

- **插值(interpolation)** —— 在两个已知值之间生成中间值的整套数学
- **数值控制** —— 用数值参数驱动连续变化
- **去毛刺 / 防混叠** —— 信号处理里消除不连续的通用思路

### 4.2 同级

| 方案 | 公式 | 听感 | 代码复杂度 |
|---|---|---|---|
| 阶跃(无插值) | `v = target` | zipper noise | 最低 |
| 线性 | `v = v0 + (v1-v0) * i/N` | 自然 | 中(需要 i 和 N) |
| 指数平滑 | `v += (target-v) * alpha` | 自然,响应略钝 | 中(只需要 v 和 alpha) |
| Critical damp | 二阶 ODE | 最佳(有惯性) | 高 |
| S 曲线(cubic) | smoothstep | 自然,起止平缓 | 中 |

游戏音量推荐:**指数平滑**(简单 + 自然)。
游戏相机推荐:**critical damp**(手感最佳)。

### 4.3 下级

- **current_volume / target_volume** —— 两个状态变量
- **fade_samples** —— 插值时长(sample 数)
- **alpha** —— 指数平滑系数(等价于 1/fade_samples)
- **zipper noise** —— 阶跃音量的可闻伪声

## 5 · 对照与变奏

### 不同 sample rate 下的 fade 时间

fade 时间是 sample 数除以 sample rate:

| sample rate | N=1440 的 fade 时间 | N=64 的 fade 时间 |
|---|---|---|
| 8 kHz(电话) | 180 ms | 8 ms |
| 44.1 kHz(CD) | 33 ms | 1.5 ms |
| 48 kHz(专业) | 30 ms | 1.3 ms |
| 96 kHz(高解析) | 15 ms | 0.67 ms |

工程经验:**fade 时间要按"听感时间"算,不是按 sample 数**。所以代码里应写 `const FADE_SECS: f32 = 0.030;` 然后算 `fade_samples = (FADE_SECS * sample_rate) as usize`,这样在不同设备上听感一致。

### 历史演化

- **1990s 之前**:游戏音频用 MIDI / tracker,音量是事件式的(开/关),没有插值
- **1990s**:CD 音频引入,游戏用 crossfade 处理音乐切换,但单 sample 音量仍是阶跃
- **2000s**:PC 游戏普及混音,引入 zipper noise 概念,引擎开始做插值
- **2010s+**:所有引擎默认插值,玩家听不到 zipper

### 音量 vs 平移 vs 滤波

音量是 1 维(0 到 1)。平移(pan)是 2 维(左右声道)。低通滤波是无穷维(每个频率衰减不同)。所有这些参数变化时都要插值,否则都有 zipper。但插值的代价随维度变化:

| 操作 | 维度 | per-sample 计算 |
|---|---|---|
| 音量 | 1 | 1 乘 |
| 平移 | 2 | 2 乘 |
| 3-band EQ | 3 | 3 biquad filter |
| 卷积混响 | 数千 | 数千乘(FIR) |

所以混响参数永远不变(或只在 frame 边界变),音量才 per-sample 插值。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 zipper noise 在低频信号(50 Hz 鼓声)上几乎听不见,在 5 kHz 高频上特别明显?

**参考解答**:音量突变引入的高频成分,频谱和原信号叠加。低频信号的 sample-to-sample 差本来就不大(50 Hz @ 48 kHz = 1 周期 960 sample),突变相对幅度小。高频信号 5 kHz @ 48 kHz = 1 周期 9.6 sample,sample-to-sample 差大,突变比例上虽然相同,但突变频率高,更容易进入人耳敏感区(2-5 kHz)。

### Lv2 · 动手实践

**题**:写一个 Rust 程序,生成 2 秒的 220 Hz 正弦波 (f32 mono),前 1 秒音量 0.3,后 1 秒音量 0.6。先做"阶跃版"(1 秒边界直接跳),再做"插值版"(在边界处用 30 ms 线性插值)。把两版写进两个文件 `step.raw` 和 `interp.raw`。用 Audacity 打开看波形,你应该在 `step.raw` 第 48000 个 sample 处看到不连续尖刺,`interp.raw` 处是平滑斜面。

完成标准:两个文件都生成,且文件大小相同(2 × 48000 × 4 字节)。

**参考解答**:

```rust
use std::io::Write;

const SR: usize = 48000;
const DURATION: usize = 2 * SR;
const FADE: usize = (0.030 * SR as f32) as usize; // 30 ms

fn main() {
    let mut step = std::fs::File::create("step.raw").unwrap();
    let mut interp = std::fs::File::create("interp.raw").unwrap();

    for i in 0..DURATION {
        let t = i as f32 / SR as f32;
        let base = (2.0 * std::f32::consts::PI * 220.0 * t).sin();

        // 阶跃版:前 1 秒 0.3,后 1 秒 0.6
        let v_step = if i < SR { 0.3 } else { 0.6 };
        let s_step = base * v_step;
        step.write_all(&s_step.to_le_bytes()).unwrap();

        // 插值版:在边界 ±15 ms 内线性过渡
        let boundary = SR;
        let v_interp = if i < boundary - FADE/2 {
            0.3
        } else if i < boundary + FADE/2 {
            let frac = (i - (boundary - FADE/2)) as f32 / FADE as f32;
            0.3 + (0.6 - 0.3) * frac
        } else {
            0.6
        };
        let s_interp = base * v_interp;
        interp.write_all(&s_interp.to_le_bytes()).unwrap();
    }
    println!("wrote step.raw and interp.raw");
}
```

**关键点**:
- `to_le_bytes()` —— f32 转 4 字节小端。Audacity "Import Raw" 选 32-bit float little-endian。
- 边界检测用 `boundary - FADE/2` 和 `boundary + FADE/2`,插值在边界两侧 15 ms 内进行,实际过渡跨过边界。

## 8 · Rust / Arch 落地代码

```rust
// Cargo.toml: 纯 std,无依赖

use std::sync::atomic::{AtomicU32, Ordering};
use std::sync::Arc;

// 1. AtomicF32 封装
#[derive(Debug)]
pub struct AtomicF32 {
    bits: AtomicU32,
}
impl AtomicF32 {
    pub fn new(v: f32) -> Self {
        Self { bits: AtomicU32::new(v.to_bits()) }
    }
    pub fn load(&self) -> f32 {
        f32::from_bits(self.bits.load(Ordering::Relaxed))
    }
    pub fn store(&self, v: f32) {
        self.bits.store(v.to_bits(), Ordering::Relaxed);
    }
}

// 2. 一个 playing sound 的状态
pub struct PlayingVoice {
    pub current_volume: AtomicF32,   // mixer 线程更新
    pub target_volume: AtomicF32,    // 外部线程更新
}

impl PlayingVoice {
    pub fn new(initial: f32) -> Arc<Self> {
        Arc::new(Self {
            current_volume: AtomicF32::new(initial),
            target_volume: AtomicF32::new(initial),
        })
    }
    // 外部线程调用:设目标
    pub fn set_volume(&self, target: f32) {
        self.target_volume.store(target);
    }
}

// 3. mixer 一次循环:处理 N 个 sample
pub fn mix_chunk(voice: &PlayingVoice, src: &[f32], dst: &mut [f32]) {
    // 指数平滑:alpha = 1 / fade_samples
    // fade_samples = 30 ms × 48000 = 1440
    const FADE_SECS: f32 = 0.030;
    const SR: f32 = 48000.0;
    let alpha = 1.0 / (FADE_SECS * SR);

    let mut cur = voice.current_volume.load();
    let n = dst.len().min(src.len());
    for i in 0..n {
        let target = voice.target_volume.load();
        // 指数平滑逼近 target
        cur += (target - cur) * alpha;
        // 混音:加到 dst 上
        dst[i] += src[i] * cur;
    }
    voice.current_volume.store(cur);
}

fn main() {
    let voice = PlayingVoice::new(0.3);

    // 假装 100 ms 的源(4800 sample)
    let src: Vec<f32> = (0..4800)
        .map(|i| (i as f32 * 0.01).sin() * 0.5)
        .collect();
    let mut dst = vec![0.0f32; 4800];

    // 模拟:第一段 50 ms,然后外部改音量到 0.9,再 50 ms
    mix_chunk(&voice, &src[..2400], &mut dst[..2400]);
    println!("after first chunk, current = {:.3}", voice.current_volume.load());

    // 主线程改目标
    voice.set_volume(0.9);
    println!("target changed to 0.9");

    mix_chunk(&voice, &src[2400..], &mut dst[2400..]);
    println!("after second chunk, current = {:.3}", voice.current_volume.load());
    // current 应该接近 0.9 但没完全到(指数渐近)
}
```

**关键 Rust 概念**:

- `AtomicF32` 自定义类型 —— 用 AtomicU32 装 f32 位模式。`to_bits`/`from_bits` 零开销。
- `Ordering::Relaxed` —— 我们只关心原子性(不会读到撕裂值),不需要跨线程内存序保证。
- `Arc<PlayingVoice>` —— 多线程共享。外部线程和 mixer 线程各持一个 clone。
- `dst[i] += src[i] * cur` —— 累加混音。多个声音的 dst 都加到一起就是 polyphony。
- `cur += (target - cur) * alpha` —— 指数平滑的核心一行。

**预期输出**:
```
after first chunk, current = 0.300   (没收到新目标,cur 不变)
target changed to 0.9
after second chunk, current = 0.628   (50 ms 内从 0.3 → 0.628,指数趋近 0.9)
```

50 ms 是 1440 sample 的 0.5/0.030 ≈ 1.67 个时间常数。指数平滑 1 个时间常数后剩 37%,1.67 个后剩 19%,所以达到 0.3 + (0.9-0.3) × (1-0.19) ≈ 0.78...。你具体算出来的值可能因 alpha 计算略不同,趋势是指数趋近 target。

## 10 · 深度推导:平滑过渡的信号处理

今天 Casey 教 volume ramping。听起来简单("渐变音量"),但背后是音频信号处理的核心概念。这一节走通。

### 10.1 为什么需要平滑?

朴素代码:用户按按钮静音,代码立即设 gain = 0:

```rust
voice.gain = 0.0;  // 立即静音
```

听感:**POP** —— 一个尖锐的"咔"声。为什么?

sample 0:gain=1.0,output = 0.5(原信号)
sample 1:gain=0.0,output = 0.0

这个 0.5 到 0.0 的瞬时跳变,频谱分析:

- 直流分量(0 Hz)突然变 → 高频分量
- 高频分量 → 听感是 click / pop

修复:**渐变**。在 ~5 ms 内从 1.0 渐变到 0.0,听感是平滑的"fade out"。

### 10.2 Linear ramp(线性渐变)

```rust
struct Voice {
    gain: f32,
    target_gain: f32,
    ramp_speed: f32,  // 每 sample gain 变化量
}

impl Voice {
    fn render(&mut self, num_samples: usize, output: &mut [f32]) {
        for i in 0..num_samples {
            // gain 朝 target 推进
            if self.gain < self.target_gain {
                self.gain = (self.gain + self.ramp_speed).min(self.target_gain);
            } else if self.gain > self.target_gain {
                self.gain = (self.gain - self.ramp_speed).max(self.target_gain);
            }
            output[i] = self.sample_buffer[i] * self.gain;
        }
    }
}
```

每个 sample,gain 加/减 ramp_speed。5 ms 内从 1.0 到 0.0 = 220 sample(44.1kHz),ramp_speed = 1.0 / 220 ≈ 0.0045。

### 10.3 Exponential ramp(指数渐变)

Linear ramp 的问题:听感是"开始慢、中间快、结束慢"。人类听觉对音量是对数尺度,所以 linear ramp 在听感上不自然。

Exponential ramp:gain *= factor 每 sample。

```rust
fn render(&mut self, num_samples: usize, output: &mut [f32]) {
    for i in 0..num_samples {
        self.gain *= self.factor;  // 0.99 = 每 sample 衰减 1%
        if self.gain < 0.0001 { self.gain = 0.0; }  // 接近 0 就停
        output[i] = self.sample_buffer[i] * self.gain;
    }
}
```

factor = 0.99 意味着每 sample gain 乘 0.99。10 ms(441 sample)后 gain ≈ 0.99^441 ≈ 0.012,衰减到 1%。

听感自然,但实现稍复杂(乘法比加法贵)。

### 10.4 One-pole low-pass filter

更专业的做法:用低通滤波器平滑 gain:

```rust
struct Smoother {
    current: f32,
    coefficient: f32,  // 0.99 表示 99% 保留当前,1% 接受 target
}

impl Smoother {
    fn process(&mut self, target: f32) -> f32 {
        // y[n] = coef * y[n-1] + (1 - coef) * target
        self.current = self.coefficient * self.current + (1.0 - self.coefficient) * target;
        self.current
    }
}
```

这是**one-pole low-pass filter**(一阶低通滤波器)。signal processing 经典算法。Ableton / Logic 的 smoothing 用这个。

coefficient = 0.99 = 99% 沿用旧值,1% 接受新值。响应慢但平滑。coefficient = 0.9 = 快响应但仍平滑。

### 10.5 完整代码

```rust
pub struct Voice {
    samples: Vec<f32>,
    position: usize,
    gain_smoother: Smoother,
    target_gain: f32,
    active: bool,
    looping: bool,
}

pub struct Smoother {
    current: f32,
    coefficient: f32,
}

impl Smoother {
    pub fn new(coefficient: f32) -> Self {
        Self { current: 0.0, coefficient }
    }

    pub fn process(&mut self, target: f32) -> f32 {
        self.current = self.coefficient * self.current + (1.0 - self.coefficient) * target;
        self.current
    }

    pub fn set_immediate(&mut self, value: f32) {
        self.current = value;
    }
}

impl Voice {
    pub fn new(samples: Vec<f32>, initial_gain: f32) -> Self {
        let mut smoother = Smoother::new(0.99);
        smoother.set_immediate(initial_gain);
        Self {
            samples,
            position: 0,
            gain_smoother: smoother,
            target_gain: initial_gain,
            active: true,
            looping: false,
        }
    }

    pub fn set_gain(&mut self, gain: f32) {
        self.target_gain = gain;
    }

    pub fn render(&mut self, output: &mut [f32]) {
        if !self.active { return; }
        for slot in output.iter_mut() {
            if self.position >= self.samples.len() {
                if self.looping {
                    self.position = 0;
                } else {
                    self.active = false;
                    *slot = 0.0;
                    break;
                }
            }
            let raw = self.samples[self.position];
            let gain = self.gain_smoother.process(self.target_gain);
            *slot = raw * gain;
            self.position += 1;
        }
    }
}

fn main() {
    // 测试:开始音量 1.0,中间设到 0.0,看平滑过渡
    let samples: Vec<f32> = (0..44100).map(|i| {
        let t = i as f32 / 44100.0;
        (t * 440.0 * 2.0 * std::f32::consts::PI).sin() * 0.5
    }).collect();

    let mut voice = Voice::new(samples, 1.0);

    // 前 220 sample:gain = 1.0
    let mut buf = vec![0.0; 220];
    voice.render(&mut buf);
    println!("Initial gain: {:.4}", buf[219]);

    // 第 221 sample:设到 0.0,看平滑过渡
    voice.set_gain(0.0);
    let mut buf = vec![0.0; 220];
    voice.render(&mut buf);

    // 输出 gain 曲线
    for i in [0, 50, 100, 150, 200, 219] {
        println!("  sample {}: output = {:.4}", 220 + i, buf[i].abs());
    }
    // 应该看到 gain 从 1.0 平滑衰减到接近 0
}
```

跑起来你会看到 gain 从 1.0 在 ~220 sample 内衰减到接近 0,**无瞬时跳变**,听感平滑。

### 10.6 为什么 5 ms?

5 ms 是听感"瞬时但平滑"的甜区:

- < 1 ms:听感仍是 click / pop
- 5 ms:平滑,听感近似瞬时
- 50 ms:能听出 fade
- 200 ms:明显的渐变效果

工业音频用 5-10 ms 的 fade。Wwise / FMOD 默认 5 ms。

### 10.7 Pop-free stop / start

启动 / 停止 voice 也需要平滑:

```rust
fn start_voice(&mut self, voice: &mut Voice) {
    voice.gain_smoother.set_immediate(0.0);  // 从 0 开始
    voice.set_gain(self.target_volume);       // 渐变到目标
}

fn stop_voice(&mut self, voice: &mut Voice) {
    voice.set_gain(0.0);  // 渐变到 0
    // 不要立即设 active = false——等 gain 真的到 0
}

fn update(&mut self) {
    for voice in &mut self.voices {
        voice.render(&mut buf);
        // 检查 voice 是否真的"静默"(gain 接近 0)
        if voice.target_gain == 0.0 && voice.gain_smoother.current < 0.001 {
            voice.active = false;
        }
    }
}
```

启动从 0 fade in,停止 fade out 到 0 再 deactivate。这是工业混音器的标准做法。

## 11 · 工业级的额外考量

### 11.1 AtomicF32:跨线程设 gain

主线程(UI 触发)要设 audio 线程的 voice gain。Rust 没有内置 AtomicF32,但可以用 AtomicU32 + transmute:

```rust
pub struct AtomicF32 {
    inner: AtomicU32,
}

impl AtomicF32 {
    pub fn new(value: f32) -> Self {
        Self { inner: AtomicU32::new(value.to_bits()) }
    }
    pub fn load(&self, ordering: Ordering) -> f32 {
        f32::from_bits(self.inner.load(ordering))
    }
    pub fn store(&self, value: f32, ordering: Ordering) {
        self.inner.store(value.to_bits(), ordering);
    }
}
```

主线程 store,audio 线程 load。无 lock。

### 11.2 Parametric smoothing

不只是 gain,frequency(EQ)、pitch 也要平滑。同一 Smoother 服务多个参数。

### 11.3 Slew limiting

某些参数变化太快会产生 artifact(谐波失真)。slew limiter 限制变化率,即便 target 跳变,实际变化也慢:

```rust
fn process(&mut self, target: f32) -> f32 {
    let delta = target - self.current;
    let max_delta = self.max_slew_per_sample;
    let clamped_delta = delta.max(-max_delta).min(max_delta);
    self.current += clamped_delta;
    self.current
}
```

### 11.4 测试 pop

写测试检测 pop:用 FFT 分析输出,检查高频分量:

```rust
#[test]
fn test_no_pop_on_gain_change() {
    let mut voice = Voice::new(sine_wave(440.0, 44100), 1.0);
    voice.set_gain(0.0);
    let mut output = vec![0.0; 1024];
    voice.render(&mut output);

    // FFT 看 high frequency 能量
    let fft = compute_fft(&output);
    let hf_energy: f32 = fft[200..].iter().map(|x| x.norm()).sum();
    assert!(hf_energy < 1.0, "Too much HF energy, likely pop");
}
```
