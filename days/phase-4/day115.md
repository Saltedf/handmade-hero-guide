
# Day 115 · SIMD 基础

> 一条 CPU 指令,本来一次算一个数。SIMD 让它一次算 4 个、8 个、16 个甚至 32 个数。这是 CPU 给你的"并行免费午餐",但你必须知道怎么摆数据它才肯吃。今天把 SIMD 的来龙去脉彻底讲透。

## 0 · 为什么要有这一天

你的软渲染器在 Day 113 的 profiler 下显示:`draw_bitmap` 占了 80% 的帧时间。你打开了 release 模式,编译器也开了 `-C target-cpu=native`,但帧率还是 30 FPS。

为什么?因为你写的标量代码长这样:

```rust
for pixel in pixels {
    let r = pixel.r * a;
    let g = pixel.g * a;
    let b = pixel.b * a;
    *pixel = (r, g, b);
}
```

每条 `*` 是一条 `mulss` 指令,一次处理 1 个 f32。CPU 周围的 SIMD 单元在打瞌睡——它的 `mulps` 指令可以**一条指令同时处理 4 个 f32**,但你没让它工作。

CPU 的 SIMD 单元不是"自动激活"的。Rust 编译器在 release 下会做 SIMD 自动向量化(auto-vectorization),但只对最简单的循环有效;复杂一点的算法、嵌套条件、跨字段访问,编译器不敢动,只能跑标量。

**SIMD 是 Phase 4 的核心技术**。从今天开始,你要学:

1. SIMD 是什么,寄存器长什么样
2. 怎么手写 SIMD 代码(用 Rust 的 `std::arch`)
3. 怎么把数据布局成 SIMD 友好的形态(SoA)
4. 怎么调试 SIMD 代码(看汇编,确认真的生成了 `mulps`)
5. 什么时候 SIMD 不会更快(避免反模式)

心理锚点:读完这一天,你能:

- 在 Rust 里写出一次处理 4/8/16 个 f32 的 SIMD 函数
- 解释 `__m128` / `__m256` / `__m512` 这些类型的区别
- 看 `cargo rustc --emit asm` 的输出,认出 `mulps` / `vmulps` / `vfmadd231ps` 这些指令
- 知道 SSE / AVX / AVX2 / AVX-512 的演进关系

## 1 · Casey 今天做了什么

Casey 在 Day 114 把 `DrawBitmap` 准备好之后,这一天进入 SIMD 入门。他在白板上画:

2. 标量版:`addss xmm0, xmm1` —— 只加 xmm0 的最低 32 位
3. SIMD 版:`addps xmm0, xmm1` —— 同时加 4 个 32 位

他还讲解了 SIMD 的两个核心概念:

- **packed**:把 4 个 f32 "打包"在一个寄存器里,一条指令并行处理(我们关心的)
- **scalar**:只处理最低 32 位(基本就是"标量"操作,SIMD 寄存器的"未使用模式")

最后他强调:**SIMD 不是银弹**。它要求:

1. 数据量足够大(否则启动开销 > 收益)
2. 数据布局 SIMD 友好(SoA 或者横切)
3. 算法本身能 SIMD 化(控制流少)
4. 对齐(SIMD load 最好 16/32/64 字节对齐)

## 2 · 心智模型

### 2.1 类比:超市结账

想象超市结账台。普通标量 CPU 是"1 个收银员"——每分钟处理 1 个顾客。

如果你想让超市吞吐量翻倍,有两种思路:

**思路 A:多开收银台**(多核 / 多线程)
- 加收银员,每人独立结账
- 优点:多个顾客并行
- 缺点:每个收银员需要自己的工作台、收银机(占用资源)

**思路 B:同一个收银员,一次扫 4 件商品**(SIMD)
- 收银员有 4 个扫码枪,左右开弓
- 优点:同一个收银员,扫一件的时间扫了 4 件
- 缺点:商品必须摆成"4 件一组"才能这样扫

SIMD 就是思路 B。CPU 不增加核心数,但**单个核心内的执行单元加宽**——一条指令同时处理多个数据。代价是你的数据必须能"4 件一组"地摆好。

### 2.2 SIMD 寄存器长什么样

x86_64 CPU 有 16 个 SIMD 寄存器,叫 `xmm0` 到 `xmm15`(128 位)或 `ymm0` 到 `ymm15`(256 位,AVX)或 `zmm0` 到 `zmm31`(512 位,AVX-512)。

一个 128 位的 `xmm` 寄存器可以装:

```
+--------+--------+--------+--------+
| f32[3] | f32[2] | f32[1] | f32[0] |   ← 4 个 f32(每个 32 位)
+--------+--------+--------+--------+

或:

+----+----+----+----+----+----+----+----+
| u8  | u8  | u8  | u8  | u8  | u8  | u8  | u8  | × 4 组 = 16 个 u8
+----+----+----+----+----+----+----+----+

或:

+--------+--------+
|  f64[1]|  f64[0]|   ← 2 个 f64
+--------+--------+
```

具体怎么"看"这 128 位,取决于你用的指令。`addps` 把它当 4 个 f32,`paddb` 把它当 16 个 u8。

### 2.3 intrinsic:Rust/C 怎么"喊"SIMD 指令

汇编里你写 `addps xmm0, xmm1`。Rust/C 不能直接写汇编(可以 inline asm,但不方便),而是用 **intrinsic**:一些看起来像普通函数的 API,内部对应一条 SIMD 指令。

```rust
use std::arch::x86_64::*;

let a = _mm_set_ps(4.0, 3.0, 2.0, 1.0);  // a = [1, 2, 3, 4](注意参数顺序!)
let b = _mm_set_ps(8.0, 7.0, 6.0, 5.0);  // b = [5, 6, 7, 8]
let c = _mm_add_ps(a, b);                // 一条 addps,c = [6, 8, 10, 12]
```

**术语**:

- `__m128`(C)/ `__m128`(Rust):一个 128 位 SIMD 寄存器的 Rust 类型,被当作 4 个 f32
- `_mm_add_ps`:SSE 的 packed single 加法(`_mm_` = SSE 128 位,`add` = 加,`ps` = packed single precision)
- `_mm_set_ps(a, b, c, d)`:**倒序**填装——参数顺序是高地址到低地址,所以 `_mm_set_ps(4, 3, 2, 1)` 装进去是 `[1, 2, 3, 4]`(lane 0 是 1,lane 3 是 4)

### 2.4 命名规则:x86_64 intrinsic 怎么读

x86_64 intrinsic 名字有结构,看懂结构就能猜含义:

```
_mm_<op>_<suffix>
_mm256_<op>_<suffix>
_mm512_<op>_<suffix>
```

- 前缀 `_mm_`:128 位 SSE
- 前缀 `_mm256_`:256 位 AVX/AVX2
- 前缀 `_mm512_`:512 位 AVX-512

`<suffix>` 的字母含义:

| 字母 | 含义 |
|---|---|
| `ps` | packed single(f32,4/8/16 个) |
| `pd` | packed double(f64,2/4/8 个) |
| `ss` | scalar single(只对最低一个 f32) |
| `sd` | scalar double(只对最低一个 f64) |
| `epi8` / `epi16` / `epi32` / `epi64` | extended packed integer(有符号整数) |
| `epu8` 等 | 无符号整数 |
| `si128` / `si256` | 整个寄存器当一个整数 |

**例子**:

- `_mm_add_ps`:128 位 packed f32 加法(4 个 f32 同时加)
- `_mm256_mul_ps`:256 位 packed f32 乘法(8 个 f32 同时乘)
- `_mm_add_ss`:只加最低一个 f32(其余不变)——基本上就是标量加法
- `_mm_mullo_epi32`:128 位 packed i32 乘法,取低 32 位
- `_mm_set1_ps(x)`:把 x 复制到所有 4 个 lane(广播)

### 2.5 load 和 store:从内存进/出 SIMD 寄存器

SIMD 寄存器在 CPU 内部,数据在内存。要做 SIMD,先把数据"加载"(load)到寄存器,算完再"存回"(store)。

```rust
let data: [f32; 4] = [1.0, 2.0, 3.0, 4.0];
let v = unsafe { _mm_loadu_ps(data.as_ptr()) };  // unaligned load
// v = [1, 2, 3, 4]

let mut out = [0.0f32; 4];
unsafe { _mm_storeu_ps(out.as_mut_ptr(), v); }
// out = [1, 2, 3, 4]
```

**术语**:

- `loadu` / `storeu`:**unaligned**,可以读任意地址
- `load` / `store`:**aligned**,地址必须是 16 字节(SSE)/ 32 字节(AVX)/ 64 字节(AVX-512)对齐,否则 segfault
- aligned 版本更快(对齐读不需要"边界检测"),但要求严格的内存布局

Rust 里把数据按 16 字节对齐:

```rust
#[repr(C, align(16))]
struct Aligned16<T>(T);

let data: Aligned16<[f32; 4]> = Aligned16([1.0, 2.0, 3.0, 4.0]);
let v = unsafe { _mm_load_ps(&data.0 as *const f32) };  // aligned load
```

### 2.6 SoA vs AoA:数据布局决定 SIMD 利用率

回到 §2.1 的超市类比——"商品必须摆成 4 件一组"。在代码里,这对应**数据布局**。

考虑你有 4 个 Vec2:

#### AoS(Array of Structs)

```rust
struct Vec2 { x: f32, y: f32 }
let points: [Vec2; 4] = [...];
// 内存: [x0, y0, x1, y1, x2, y2, x3, y3]
// 想一次处理 4 个 x?不行!x 之间隔着 y
```

#### SoA(Struct of Arrays)

```rust
struct Vec2s { xs: [f32; 4], ys: [f32; 4] }
let points: Vec2s = ...;
// 内存: [x0, x1, x2, x3, y0, y1, y2, y3]
// 一次 SIMD load xs:得到 [x0, x1, x2, x3]——完美!
```

SoA 把同类型的字段连续摆放,SIMD 可以一次 load 完整的 4 个。AoS 把不同字段交错,SIMD load 会得到混合数据,要么需要"shuffle"重新排列(代价高),要么放弃 SIMD。

**HH 的选择**:Casey 在 Day 1-114 用 AoS(`struct Vec2`),从 Day 115 开始转 SoA。这是性能优化的核心:为 SIMD 重新设计数据布局。

#### 混合布局:AoSoA

```rust
struct Vec2Block { xs: [f32; 4], ys: [f32; 4] }  // 一个 block 4 个 Vec2,SoA
let blocks: Vec<Vec2Block> = ...;  // 多个 block,AoS
```

每 4 个一组 SoA,组之间 AoS。这是游戏引擎常用的折中。

### 2.7 Rust 里写 SIMD 的三种方式

#### 方式 1:`std::arch::x86_64`(底层 intrinsic)

```rust
use std::arch::x86_64::*;

#[target_feature(enable = "sse2")]
pub unsafe fn dot4_soa(xs: &[f32; 4], ys: &[f32; 4]) -> f32 {
    let a = _mm_loadu_ps(xs.as_ptr());
    let b = _mm_loadu_ps(ys.as_ptr());
    let prod = _mm_mul_ps(a, b);            // [x0*y0, x1*y1, x2*y2, x3*y3]
    // 水平加总 4 个 lane 成 1 个值
    let sum = _mm_hadd_ps(prod, prod);      // [a+b, c+d, a+b, c+d]
    let sum = _mm_hadd_ps(sum, sum);        // [a+b+c+d, ...]
    _mm_cvtss_f32(sum)                      // 取 lane 0
}
```

- **优点**:和 Casey 的 C 一一对应,完全控制
- **缺点**:`unsafe`,平台耦合(x86_64 only),需要运行时检测

#### 方式 2:`std::simd`(portable_simd)

```rust
#![feature(portable_simd)]
use std::simd::f32x4;

pub fn dot4_soa(xs: &[f32; 4], ys: &[f32; 4]) -> f32 {
    let a = f32x4::from_slice(xs);
    let b = f32x4::from_slice(ys);
    let prod = a * b;
    prod.reduce_sum()
}
```

- **优点**:safe,跨平台,语义清晰
- **缺点**:nightly only(截至 2026/06)

#### 方式 3:`wide` crate

```rust
use wide::f32x4;

pub fn dot4_soa(xs: &[f32; 4], ys: &[f32; 4]) -> f32 {
    let a = f32x4::from_slice(xs);
    let b = f32x4::from_slice(ys);
    let prod = a * b;
    prod.reduce_add()
}
```

- **优点**:safe,跨平台,stable
- **缺点**:额外依赖,某些操作没有底层 intrinsic 灵活

**推荐**:Phase 4 学习 SIMD 用方式 1(理解原理);Phase 5+ 实际项目用方式 2 或 3。

### 2.8 unsafe 边界:为什么 SIMD intrinsic 是 unsafe

```rust
let v: __m128 = unsafe { _mm_set_ps(1.0, 2.0, 3.0, 4.0) };
```

为什么 `_mm_set_ps` 是 unsafe?

**理由 1**:目标 CPU 可能不支持 SSE。Pentium III 之前的 CPU 没有 SSE,调用这条指令会触发非法指令异常(illegal instruction)。Rust 编译器没法静态检查"目标 CPU 支持这个"。

**理由 2**:`_mm_loadu_ps(ptr)` 接受任意指针,编译器无法验证指针有效(空指针 / 释放后的指针 / 越界)。

**应对**:

```rust
// 静态保证:整段函数要求 SSE2(目标 CPU 必须支持)
#[target_feature(enable = "sse2")]
unsafe fn my_simd_fn(x: &[f32]) -> f32 {
    // 这里 _mm_* 是安全的(因为 sse2 已经声明)
}

// 动态检测:运行时判断 CPU 支持
fn my_simd_fn_safe(x: &[f32]) -> f32 {
    if std::is_x86_feature_detected!("sse2" /* */) {
        unsafe { my_simd_fn(x) }
    } else {
        // fallback 标量版本
        x.iter().sum()
    }
}
```

实际工程:在 x86_64 上 SSE2 是 baseline(2003 年后所有 x86_64 都有 SSE2),所以可以直接用。AVX/AVX2/AVX-512 必须运行时检测。

### 2.9 什么时候 SIMD 不会更快

避免反模式:

1. **数据太少**(< 4 个 f32):SIMD 启动开销(load + store)大于收益。继续用标量。
2. **大量分支**:SIMD 的 lane 必须走同一条指令路径。如果某个 lane 需要 if,要么 mask 要么 all-or-nothing,效率下降。
3. **不对齐访问**:用 `loadu`/`storeu` 比 aligned 慢 ~20%,如果数据经常不对齐,SIMD 收益打折。
4. **horizontal reduction**:`hadd` 系列指令把多个 lane 加成一个值,这条指令本身慢(2-3 周期),频繁 horizontal 加总会拖累 SIMD。
5. **跟 GPU 抢任务**:大批量同质运算(SIMD 的强项)其实更适合 GPU。CPU 用 SIMD 处理"中等批量 + 复杂控制流"。

### 2.10 编译器的"自动 SIMD"

Rust 编译器(用 LLVM)在 `-O` 下会尝试把普通循环自动转成 SIMD 代码,叫 **auto-vectorization**。

```rust
pub fn sum_array(data: &[f32]) -> f32 {
    let mut sum = 0.0f32;
    for &x in data {
        sum += x;
    }
    sum
}
```

`-C opt-level=3 + target-cpu=native` 下,LLVM 会把这段转成 SIMD 版本(`_mm_add_ps` + 累加器)。你什么都不用做。

但自动向量化**只对最简单的循环**有效。任何以下情况,编译器会放弃:

- 循环里有 `if`(分支)
- 数据不连续(比如 `data[i*stride]`)
- 浮点精度敏感(`-ffast-math` 才允许重排浮点运算,默认不允许)
- 复杂的数据流

**结论**:能用自动向量化就用,不能就手写。

### 3.2 · 🎨 图形学视角

软渲染里 SIMD 用得最猛。每个像素都要做几乎相同的事(采样纹理、blend、写 framebuffer),非常适合 SIMD。

Casey 在 Day 121 把渲染器拆成 tile(每 tile 64×64 像素),每个 tile 内部 SIMD 处理 4 个像素一组,是软渲染 SIMD 应用的巅峰。

GPU 是 SIMD 的"超级放大版"。一个 GPU warp / wavefront 是 32 或 64 个核心,执行同一条指令(NVIDIA 叫 SIMT,AMD 叫 SIMT,本质就是 SIMD 加 mask)。GPU 编程的本质就是"把算法写得 SIMD 友好"——这正是 CPU 软渲染 SIMD 的扩展。

#### 颜色空间转换 SIMD 示例

YCbCr(RAW 相机 / JPEG 格式)→ RGB 转换,4 个像素一组:

```rust
// 标量版:每像素 9 个乘加
for pixel in pixels {
    let y = pixel.y;
    let cb = pixel.cb;
    let cr = pixel.cr;
    let r = y + 1.402 * (cr - 128.0);
    let g = y - 0.344 * (cb - 128.0) - 0.714 * (cr - 128.0);
    let b = y + 1.772 * (cb - 128.0);
    pixel.rgb = (r, g, b);
}

// SIMD 版:一次 4 像素,3 个 mulps + 几个 addps
```

#### AVX 频率降频(AVX throttling)

注意一个反直觉的现象:**用 AVX-512 会让 CPU 频率显著下降**(降低 30-50%)。Intel CPU 的"license"机制:AVX-512 指令触发热 / 功耗限制,CPU 主动降频。

所以:**用 AVX-512 不一定比 SSE 快**——降频可能让总耗时反而长。测了才知道。

Linux 上看当前频率:

```bash
watch -n 0.5 'cat /proc/cpuinfo | grep "MHz" | head'
```

### 3.4 · 🦀 Rust 生态视角

#### `#[target_feature(enable = "...")]`

```rust
#[target_feature(enable = "avx2")]
#[target_feature(enable = "fma")]
unsafe fn my_avx2_fma_fn(x: &[f32]) -> f32 {
    // 这里可以用 avx2 + fma 指令
}
```

把多个 feature 叠加。函数本身 unsafe(调用方必须保证 CPU 支持)。

#### `#[cfg(target_feature = "...")]`

```rust
#[cfg(target_feature = "avx2")]
mod avx2_impl {
    pub fn compute() { /* AVX2 版 */ }
}

#[cfg(not(target_feature = "avx2"))]
mod fallback_impl {
    pub fn compute() { /* 标量版 */ }
}
```

编译时静态决定走哪个版本。配合 `RUSTFLAGS="-C target-cpu=native"` 用。

#### `cargo-gpu` / `std::simd`

`std::simd`(portable_simd)未来稳定化后,会是 Rust SIMD 的"官方"方案。现在(2026/06)还在 nightly。

```rust
#![feature(portable_simd)]
use std::simd::{f32x4, SimdFloat};

fn compute(xs: &[f32; 4], ys: &[f32; 4]) -> f32 {
    let a = f32x4::from_array(*xs);
    let b = f32x4::from_array(*ys);
    (a * b).reduce_sum()
}
```

跨平台:在 x86_64 编译成 `mulps + hadd`,在 ARM 编译成 `fmul + faddp`,在 WASM 编译成 `f32x4.mul + f32x4.extract_lane + sum`。

#### `wide` crate(stable,生产可用)

```rust
use wide::f32x4;

let a = f32x4::from([1.0, 2.0, 3.0, 4.0]);
let b = f32x4::from([5.0, 6.0, 7.0, 8.0]);
let c = a + b;
let arr: [f32; 4] = c.into();
// arr = [6, 8, 10, 12]
```

`wide` 在内部根据目标 CPU 选择 SSE / AVX / NEON。stable Rust 可用,生产推荐。

## 4 · 认知地图

### 4.1 上级

- **数据级并行(Data-Level Parallelism, DLP)** —— 同时处理多个数据
- **SIMD / Vector processing** —— 同一条指令处理多个数据的整体范式
- **CPU 微架构** —— SIMD 单元(port 0/1 上的 ALU)是 CPU 内部资源

### 4.2 同级

| 并行方式 | 关键差别 | 何时用 |
|---|---|---|
| SIMD | 同指令,同时间,多数据 | 大批量同质运算 |
| 多线程 | 多核,多指令流 | 任务并行 |
| SIMD + 多线程 | 结合两者 | Day 121 的渲染 |
| GPU | 几千个简单 SIMD 核 | 极大规模同质运算 |
| 自动向量化 | 编译器帮你 SIMD | 简单循环 |

### 4.3 下级

- **SIMD 寄存器**(xmm/ymm/zmm) —— 128/256/512 位容器
- **intrinsic 函数**(`_mm_*`) —— SIMD 指令的 Rust/C API
- **数据布局**(AoS/SoA/AoSoA) —— 决定 SIMD 能否高效 load
- **mask / shuffle** —— 控制不同 lane 的不同行为
- **alignment**(16/32/64 字节) —— 决定 load 是 aligned 还是 unaligned

## 5 · 对照与变奏

### 同一问题的不同 ISA 解法

**问题**:4 个 f32 加法。

| ISA | 指令 | 寄存器 | 备注 |
|---|---|---|---|
| x86 SSE | `addps` | xmm(128) | 4 个 f32 |
| x86 AVX | `vaddps` | ymm(256) | 8 个 f32 |
| x86 AVX-512 | `vaddps` | zmm(512) | 16 个 f32 |
| ARM NEON | `fadd` | v(128) | 4 个 f32 |
| ARM SVE | `fadd z0.s, p0/m, z0.s, z1.s` | z(可变长 128-2048) | 向量长度可变 |
| RISC-V V | `vfadd.vv` | v(可变长) | 向量长度可变 |
| WebAssembly | `f32x4.add` | v128 | 4 个 f32 |

同一个数学操作,每个 ISA 有自己的"方言"。portable_simd 抽象掉这些差异。

### 历史演化

- **1999**:Intel 推出 Pentium III + SSE(128 位,4 个 f32)
- **2001**:SSE2(integer + double precision)
- **2004**:SSE3 / SSSE3(specialized ops)
- **2006**:SSE4.1 / SSE4.2
- **2008**:AVX(256 位,8 个 f32)
- **2013**:AVX-2(integer 256 位)+ FMA(融合乘加)
- **2017**:AVX-512(Xeon Scalable,512 位,16 个 f32)
- **2020+**:Apple NEON 普及(M1)、SVE2(Android 手机)

Casey 在 HH 上用 SSE2 + AVX,因为大部分观众 CPU 支持。AVX-512 他不推荐(降频问题)。

### "SIMD 自动就好了"的迷思

初学者以为"开 release 就 SIMD 了"。真相:自动向量化覆盖率有限,大概 30-40% 的可向量化循环会被 LLVM 自动处理。剩下 60-70% 要手写。

测量方法:

```bash
# 编译时打印向量化报告
RUSTFLAGS="-C opt-level=3 -C target-cpu=native -C llvm-args=--vectorize-loop" \
  cargo build --release

# 看汇编里有没有 SIMD 指令
cargo rustc --release -- --emit asm
grep -E 'mulps|addps|movups' target/release/deps/my_crate-*.s
```

如果你的热点函数汇编里只有 `mulss` / `addss`(标量),没 `mulps` / `addps`(SIMD),说明自动向量化没成功,要手写。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:下面三个函数,哪个最可能被编译器自动 SIMD 化?为什么?

```rust
fn a(data: &[f32]) -> f32 { data.iter().sum() }

fn b(data: &[f32], mask: &[bool]) -> f32 {
    let mut s = 0.0;
    for (i, &m) in mask.iter().enumerate() {
        if m { s += data[i]; }
    }
    s
}

fn c(data: &[f32]) -> Vec<f32> {
    data.iter().map(|&x| x * 2.0 + 1.0).collect()
}
```

**参考解答**:

- **a** 最容易:无分支、顺序访问、简单加法。LLVM 几乎肯定向量化。
- **c** 也容易:map + 简单运算,LLVM 会向量化成 `mulps + addps`。
- **b 难**:有 `if m`,编译器需要把 mask 转成 SIMD mask 然后用 masked add。LLVM 在 `-O3` 下能做,但需要数据布局合适。

验证:用 `cargo rustc --release -- --emit asm` 看汇编,看 a 和 c 是不是有 `mulps` / `addps`,b 是不是 fallback 到标量。

### Lv2 · 动手实践

**题**:实现一个 Rust 函数 `sum_squares(data: &[f32]) -> f32`,有标量和 SSE 两个版本。写 bench 对比。

完成标准:

1. 标量版用普通 `for`
2. SSE 版用 `_mm_mul_ps + _mm_add_ps + horizontal sum`
3. 用 `cargo bench` 测,数据是 1024 个 f32
4. 输出 baseline 和 SIMD 的耗时,计算加速比
5. `cargo test` 通过:两个版本给出相同的和(浮点误差 < 1e-3)

**参考解答**:

```rust
// src/lib.rs
use std::arch::x86_64::*;

pub fn sum_sq_scalar(data: &[f32]) -> f32 {
    let mut s = 0.0f32;
    for &x in data {
        s += x * x;
    }
    s
}

#[target_feature(enable = "sse2")]
pub unsafe fn sum_sq_sse(data: &[f32]) -> f32 {
    let mut sum = _mm_setzero_ps();  // [0, 0, 0, 0]
    let mut i = 0;
    let n4 = data.len() / 4 * 4;     // 4 的倍数
    while i < n4 {
        let v = _mm_loadu_ps(data.as_ptr().add(i));
        let sq = _mm_mul_ps(v, v);    // [x0², x1², x2², x3²]
        sum = _mm_add_ps(sum, sq);    // 累加
        i += 4;
    }
    // horizontal sum: 4 个 lane 加成 1 个 f32
    let mut buf = [0.0f32; 4];
    _mm_storeu_ps(buf.as_mut_ptr(), sum);
    let mut total = buf[0] + buf[1] + buf[2] + buf[3];
    // 处理尾部(data.len() 不是 4 的倍数)
    for &x in &data[n4..] {
        total += x * x;
    }
    total
}

pub fn sum_sq(data: &[f32]) -> f32 {
    if std::is_x86_feature_detected!("sse2") {
        unsafe { sum_sq_sse(data) }
    } else {
        sum_sq_scalar(data)
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn eq() {
        let data: Vec<f32> = (0..100).map(|i| (i as f32) * 0.1).collect();
        let a = sum_sq_scalar(&data);
        let b = unsafe { sum_sq_sse(&data) };
        assert!((a - b).abs() < 1e-3, "scalar={}, sse={}", a, b);
    }
}
```

```rust
// benches/bench.rs
use criterion::*;
use my_crate::*;

fn bench(c: &mut Criterion) {
    let data: Vec<f32> = (0..1024).map(|i| (i as f32) * 0.01).collect();
    c.bench_function("scalar", |b| b.iter(|| black_box(sum_sq_scalar(black_box(&data)))));
    c.bench_function("sse", |b| b.iter(|| black_box(unsafe { sum_sq_sse(black_box(&data)) })));
}

criterion_group!(benches, bench);
criterion_main!(benches);
```


## 8 · Rust / Arch 落地代码

### Rust:完整 SIMD demo(包含 fallback、检测、bench)

```rust
// src/lib.rs
use std::arch::x86_64::*;

/// 标量基线
pub fn clamp_scalar(data: &mut [f32], lo: f32, hi: f32) {
    for x in data.iter_mut() {
        *x = x.max(lo).min(hi);
    }
}

/// SSE 4 个一组
#[target_feature(enable = "sse2")]
pub unsafe fn clamp_sse(data: &mut [f32], lo: f32, hi: f32) {
    let lo_v = _mm_set1_ps(lo);  // [lo, lo, lo, lo]
    let hi_v = _mm_set1_ps(hi);
    let mut i = 0;
    let n4 = data.len() / 4 * 4;
    while i < n4 {
        let v = _mm_loadu_ps(data.as_ptr().add(i));
        // max 然后 min: SIMD 没有标量那种 .max().min() 链式,要两次调用
        let clamped = _mm_max_ps(v, lo_v);
        let clamped = _mm_min_ps(clamped, hi_v);
        _mm_storeu_ps(data.as_mut_ptr().add(i), clamped);
        i += 4;
    }
    for x in &mut data[n4..] {
        *x = x.max(lo).min(hi);
    }
}

/// 自动选择最优实现
pub fn clamp(data: &mut [f32], lo: f32, hi: f32) {
    if std::is_x86_feature_detected!("sse2") {
        unsafe { clamp_sse(data, lo, hi) }
    } else {
        clamp_scalar(data, lo, hi)
    }
}
```

- `_mm_*` not found:加 `use std::arch::x86_64::*;`(注意路径)
