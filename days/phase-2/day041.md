## 2 · 心智模型

### 类比:数学是游戏世界的"语法"

你写自然语言,不是先想语法再说话,但你如果说错语法,别人听不懂。游戏世界里的"语法"就是**数学**。你看不到它,但它决定一切——一个角色怎么动、两个物体怎么撞、光怎么照、声音怎么传。

具体到游戏开发,有 6 套"语法"反反复复出现:

#### 2.1 向量(Vec2 / Vec3)

**直觉**:向量就是"带方向的箭头"。在 2D 里它有两个数 `(x, y)`,在 3D 里它有三个 `(x, y, z)`。你可以用它表示**位置**(小人现在在哪)、**速度**(小人每秒往哪走多远)、**方向**(小人面朝哪)、**位移**(从 A 到 B 走了多远)。

**为什么用 `(x, y)` 一个对象而不是两个独立变量?** 因为很多操作天然作用在"整体"上:加(位移合成)、减(求位移)、乘标量(加速)、归一化(只留方向)。如果用两个变量,你写的代码会变成 `x1 + x2, y1 + y2` 而不是 `v1 + v2`——前者啰嗦、易错、无法泛化到 3D。

**严谨定义**:向量是线性空间里的元素,满足 8 条公理(加法交换、结合、零元、负元、标量乘法……)。在游戏里我们不关心公理,关心**怎么算**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn add(self, other: Self) -> Self { Self::new(self.x + other.x, self.y + other.y) }
    fn scale(self, k: f32) -> Self { Self::new(self.x * k, self.y * k) }
    fn length(self) -> f32 { (self.x * self.x + self.y * self.y).sqrt() }
    fn normalized(self) -> Self {
        let len = self.length();
        if len > 1e-6 { self.scale(1.0 / len) } else { Self::new(0.0, 0.0) }
    }
}
```

**Rust 注释**:
- `#[derive(Copy, Clone)]` — 让 Vec2 可以按值复制(因为里面只有两个 f32,共 8 字节,复制比引用还快)。Copy 是 Rust 表达"这个类型小到可以随便复制"的方式。
- `Debug` 让 `println!("{:?}", v)` 能打印。
- `length` 用勾股定理:`|v| = √(x² + y²)`。这就是从原点 (0,0) 到点 (x,y) 的直线距离。
- `normalized` 把长度变成 1,只保留方向。**注意除零保护**:零向量没有方向,我们返回零向量而不是 panic。

Casey 在 Day 42 详细写这个结构,他甚至会自己手写 SIMD 优化版本(Day 112+)。但**起步阶段,f32 + 普通运算足够**。

#### 2.2 运动方程(位置 / 速度 / 加速度)

**直觉**:
- **位置 p** — 小人在哪
- **速度 v** — 每秒走多远(向量)
- **加速度 a** — 每秒速度变化多少(向量)

**关系**:速度是位置的变化率,加速度是速度的变化率。用微积分符号:`v = dp/dt`,`a = dv/dt`。但游戏不解析解,我们用**Euler 积分**(最简单的数值积分):

```
每帧:
    v += a * dt        // 速度加上"这一帧的加速度"
    p += v * dt        // 位置加上"这一帧的速度"
```

`dt` 是这一帧耗时(秒)。60 FPS 时 `dt ≈ 0.0167s`。

**为什么不用更精确的积分?** 因为游戏世界里我们的 `dt` 已经很小(1/60 秒),Euler 的误差小到看不出来;而更精确的(如 RK4)代价是 4 倍计算量。**够用就是最好**。

**这个"够用"思维是工程核心**——你后面看任何 Casey 的代码,会发现他反复在"刚好够用"和"理论最优"之间选前者。这不是懒,是知道什么时候该停。

#### 2.3 点积(dot product)

**定义**:`a · b = ax * bx + ay * by`(2D 向量)。

**几何意义**:`a · b = |a| |b| cos(θ)`,θ 是 a 和 b 的夹角。

**直觉**:点积衡量"两个箭头有多对齐"。
- 同向(θ=0):点积 = `|a| |b|`,最大正值
- 垂直(θ=90°):点积 = 0
- 反向(θ=180°):点积 = `-|a| |b|`,最大负值

**游戏里干嘛用**:
1. **光照**:Lambert 漫反射 = `max(0, N · L)`,N 是表面法线,L 是指向光源的向量。N·L=1 → 光直射表面,最亮;N·L=0 → 光平行掠过表面,边缘最暗;N·L<0 → 光在背面,全黑。
2. **AI 视野**:NPC 能不能看到玩家?算 NPC 朝向·NPC 到玩家的向量,>0 在前半球视野内,<0 在背后。
3. **投影**:把一个向量分解到另一个向量方向上,投影长度 = `a · b / |b|`。
4. **判断朝向**:玩家面朝北,敌人是不是在玩家北边?算 (0,1) · (敌人-玩家),>0 就是。

```rust
impl Vec2 {
    fn dot(self, other: Self) -> f32 { self.x * other.x + self.y * other.y }
}
```

#### 2.4 叉积(2D 版)

2D 叉积是个**标量**(不是向量),定义:`a × b = ax * by - ay * bx`。

**几何意义**:`a × b = |a| |b| sin(θ)`,符号告诉你 a 到 b 是顺时针(负)还是逆时针(正)。

**游戏里干嘛用**:
1. **判断点在直线哪侧**:有向线段 AB,点 P,算 `(B-A) × (P-A)`,>0 在左侧,<0 在右侧,=0 在线上。
2. **三角形面积**:`|AB × AC| / 2`。
3. **线段相交**:两条线段相交当且仅当每条线段的两端点都在另一条线段的两侧。

```rust
impl Vec2 {
    fn cross(self, other: Self) -> f32 { self.x * other.y - self.y * other.x }
}
```

3D 叉积是向量,垂直于 a 和 b,右手定则确定方向。游戏里用于算三角形法线、力矩等。Casey 在 Day 70+ 进入 3D 后才大量用。

#### 2.5 反射向量

**问题**:速度 v 撞到墙(法线 n)后,反弹的速度是什么?

**公式**:`v' = v - 2 (v · n) n`

**推导**:把 v 分解成"沿墙"和"垂直墙"两个分量。沿墙分量不变(墙没摩擦),垂直分量反向。垂直分量 = `(v · n) n`。反向就是 `-2 (v · n) n`。

**游戏里干嘛用**:
- 弹球游戏
- 光线追踪(镜子反射)
- FPS 里子弹跳

Casey 在 Day 44 完整手推这个公式,并应用到游戏的"小人撞墙"逻辑。

#### 2.6 Minkowski 差(碰撞检测核心)

**问题**:两个矩形 A 和 B,判断有没有重叠。

**Minkowski 的天才想法**:不要直接判断"两个矩形相交",把它转化为"一个点是否在另一个矩形里"。

具体做法:把 A 当作"中心点",B 不变。定义一个新矩形 C,它的宽 = A 宽 + B 宽,高 = A 高 + B 高,中心 = B 中心。**A 和 B 相交 ⟺ A 中心点在 C 内**。

```
A 和 B 相交 ⟺ |A中心.x - B中心.x| < (A宽+B宽)/2 且
               |A中心.y - B中心.y| < (A高+B高)/2
```

这就是 Day 50 碰撞检测的核心。Casey 完整推导用了一整集,核心思路就这一段。

#### 2.7 矩阵和变换(后面才用)

矩阵主要在 Day 70+ 进入 3D 后大量使用:
- **平移**:加一个向量
- **旋转**:2D 用 2×2 矩阵(编码 cos/sin),3D 用 3×3 或四元数
- **缩放**:对角矩阵
- **复合**:矩阵乘法

游戏里把"模型空间 → 世界空间 → 相机空间 → 屏幕空间"的链式变换用 4×4 矩阵一次表达(MVP 矩阵)。这是 Phase 3+ 的核心。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏开发里"数学"的真正用法和学校学的数学很不一样。理解这个差别很重要:

| 学校数学 | 游戏数学 |
|---|---|
| 任意精度(分数、符号解) | f32 / f64 浮点(够用) |
| 严格证明 | 工程正确(看得过去就行) |
| 普适解法 | 针对具体场景的"刚好够用"解 |
| 公式为中心 | 数据布局为中心(向量在内存里怎么放) |
| 解析推导 | 数值积分(Euler / Verlet) |

**关键差异:数据布局**。学校数学里向量是抽象的"两个数";游戏里向量是**内存里连续 8 字节**。这影响一切:
- CPU cache 一次读 64 字节,把 8 个 Vec2 连续放,遍历极快(cache-friendly)
- SIMD 指令一次处理 4 个 f32,如果布局是 SoA(struct of arrays)而不是 AoS(array of structs),SIMD 利用率翻倍
- 内存对齐:Vec2 是 8 字节,可以放在任何 8 字节边界;Vec3 加 padding 才能对齐到 16 字节

Casey 在 Day 112+ 讲性能时会把这些讲到极致。**现在的你只需要知道:游戏数学 = 抽象数学 + 内存感知**。

### 3.2 · 🎨 图形学视角

数学在图形学里几乎是**唯一**的工具。每一帧画面的每个像素,背后都是数学:

- **光栅化**:决定哪些像素属于一个三角形 → 重心坐标(Barycentric coordinates)、扫描线算法
- **投影**:3D → 2D → 透视除法 / NDC / 视口变换
- **深度**:z-buffer 算法 → 比较浮点数大小
- **光照**:
  - Ambient(环境光):常数
  - Diffuse(漫反射):Lambert = `N · L`(点积!)
  - Specular(镜面反射):Phong / Blinn-Phong = `(R · V)^n`(反射 + 点积)
  - PBR(基于物理):Cook-Torrance BRDF,涉及微表面分布、几何遮蔽、菲涅尔
- **纹理**:UV 坐标 → 双线性插值 / 三线性 / 各向异性
- **法线贴图**:在 tangent space 里算光照,需要 TBN 矩阵
- **抗锯齿**:MSAA / FXAA / TAA,本质是信号处理(采样定理)
- **色彩管理**:sRGB / Linear / HDR / Tone Mapping

今天的概览只是个开头。**Phase 3(3D 渲染)和 Phase 6(深度缓冲/光照)是数学密度最高的阶段**。

色彩空间是初学者最常踩的坑:**PNG 文件存的是 sRGB(非线性编码),但光照计算必须在线性空间**。流程是:`sRGB PNG → 转 Linear → 算光照 → 转 sRGB → 显示`。Casey 在 Day 83+ 详细讲这个。

### 3.3 · 🐧 Linux 系统编程视角

这集 Casey 几乎不涉及系统编程(纯数学概念)。但有一条 Linux 相关的边角值得注意:

**Linux 上的数学库**:
- `libm`(glibc 的一部分)提供 `sqrt`, `sin`, `cos` 等。Rust 调用 `f32::sqrt()` 底层是 `libm` 的 `sqrtf`
- `libm` 在 x86_64 上会用到 `sqrtsd` 指令(硬件 sqrt)
- 高性能场景绕开 `libm` 用 SIMD 直接算:`_mm_sqrt_ps`(SSE)/ `_mm256_sqrt_ps`(AVX)
- Casey 在 Day 112+ 自己手写 SIMD intrinsic 版本的向量运算

**Arch Linux 上的工具链验证**:
```bash
# 看 libm 提供什么
nm -D /usr/lib/libm.so.6 | grep sqrt
# 输出类似:00000000000342a0 W sqrtf

# 看 Rust 编译出的 sqrt 调用是不是硬件指令
echo 'fn f(x: f32) -> f32 { x.sqrt() }' | rustc --emit asm -O -o /tmp/a.s - && cat /tmp/a.s | grep sqrt
# 应该看到 sqrtsd 而不是 call sqrtf@PLT
```

这条"从源码到汇编"的追踪能力是系统程序员的日常。Phase 0 的 `15-c-and-assembly-reading.md` 详细讲。

### 3.4 · 🦀 Rust 生态视角

Rust 表达数学有几个流派,各有取舍:

#### 流派 1:手写(像 Casey 一样)

```rust
#[derive(Copy, Clone, Debug, PartialEq)]
pub struct Vec2 { pub x: f32, pub y: f32 }

impl std::ops::Add for Vec2 {
    type Output = Vec2;
    fn add(self, rhs: Self) -> Self { Self { x: self.x + rhs.x, y: self.y + rhs.y } }
}
impl std::ops::AddAssign for Vec2 {
    fn add_assign(&mut self, rhs: Self) { self.x += rhs.x; self.y += rhs.y; }
}
impl std::ops::Mul<f32> for Vec2 {
    type Output = Vec2;
    fn mul(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
}
// ... 几十行trait实现
```

**优点**:完全控制布局 / 对齐 / 内联 / SIMD,无依赖。
**缺点**:重复造轮子,容易漏 trait(`MulAssign`, `Neg`, `Index`……)。

Casey 选这条——他要的就是完全控制。Day 1-234 你也应该走这条,**理解每一行**。

#### 流派 2:用 `glam` crate(游戏优化)

```toml
# Cargo.toml
[dependencies]
glam = "0.29"
```

```rust
use glam::Vec2;
let v = Vec2::new(1.0, 2.0);
let len = v.length();
let unit = v.normalize();
```

**优点**:工业级,已经优化好 SIMD(WASM / SSE / NEON 全覆盖),API 简洁。
**缺点**:黑盒,看不到内部布局。

适合"已经懂原理,只想用"的项目阶段。Phase 5 之后你可以考虑切换。

#### 流派 3:用 `nalgebra`(科学计算)

```rust
use nalgebra::Vector2;
let v = Vector2::new(1.0, 2.0);
```

**优点**:泛型维度(`Vector2<f32>`, `Vector3<f32>`, `DVector<f32>`),可做线性代数(矩阵特征值、SVD……)。
**缺点**:泛型带来编译时间和性能开销,游戏不推荐。

适合科学计算 / 仿真。

#### 推荐路径

- **Phase 1-3**(学习原理):手写
- **Phase 4-5**(性能 / 工程化):手写 + 局部 SIMD
- **Phase 6+**(实际项目):手写核心数学 + 用 glam 做周边

**所有权和 lifetime**:Vec2 是 `Copy` 类型(8 字节),函数传递用值,不用 `&Vec2`。这避免了"借用规则打架"的常见问题:
```rust
// 推荐写法
fn add(a: Vec2, b: Vec2) -> Vec2 { a + b }

// 不推荐(Copy 类型用引用是反模式)
fn add(a: &Vec2, b: &Vec2) -> Vec2 { **a + **b }
```

**真实 crate 引用**:`glam` 是 Bevy 引擎的默认数学库。GitHub: https://github.com/bitshifter/glam
- 读源码:`src/f32/vec2.rs`(理解工业级 Vec2 实现)
- 看测试:`src/f32/vec2.rs` 文件末尾的 `#[cfg(test)] mod tests`,看人家怎么测数学函数

### 4.2 同级(并行方案)

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| Euler 积分 | 最简单,误差 O(dt) | 60 FPS 游戏 | ✅ Casey 选了 |
| Verlet 积分 | 中等复杂,更稳定,能量守恒更好 | 布料模拟、粒子系统 | Day 175+ 用 |
| RK4 (Runge-Kutta 4) | 4 倍计算量,误差 O(dt⁴) | 轨道力学、精确物理 | HH 不用,太重 |
| Symbolic math | 解析解,无误差 | 学校数学 | 游戏不用,无法实时 |

| 数据布局 | 内存表现 | SIMD 友好 |
|---|---|---|
| AoS (Array of Structs): `[Vec2; N]` | 每个向量连续,适合顺序访问 | 中等 |
| SoA (Struct of Arrays): `{ xs: [f32; N], ys: [f32; N] }` | xs 和 ys 分开 | 高(SIMD 直接 load) |

Casey 在 Day 1-200 用 AoS,Day 200+ 性能优化阶段会讨论 SoA。

### 4.3 下级

- **Vec2 / Vec3 结构体** — 容器
- **基本运算**(add, sub, mul, dot, cross) — 操作
- **几何函数**(length, normalize, distance, reflect) — 派生
- **数值积分**(Euler / Verlet) — 时间演化
- **SIMD intrinsics**(_mm_add_ps 等) — 硬件加速
- **Shader 数学**(GLSL) — GPU 端

## 5 · 对照与变奏

### 同一问题在不同语境下的变体

**问题**:计算"两个方向有多对齐"。

| 语境 | 工具 | 算法 |
|---|---|---|
| 2D 游戏光照 | 2D 向量点积 | `ax*bx + ay*by` |
| 3D 游戏光照 | 3D 向量点积 | `ax*bx + ay*by + az*bz` |
| 文本相似度 | 高维向量点积 | 余弦相似度 = `a·b / (|a||b|)` |
| 信号处理 | 互相关 | `sum(a[i] * b[i])` |
| 神经网络 | 全连接层 | `W·x + b` |

数学家会说"这些都是同一件事的内积空间实例"。工程师会说"它们的代码结构都是 `sum(a[i] * b[i])`,只是数据类型不同"。这两种视角都对,后者更实用。

### 历史演化

- **1960s**:游戏开发直接用整数算位置(因为浮点硬件慢)
- **1990s**:浮点普及,游戏开始用 f32
- **2000s**:SIMD 普及(SSE / Altivec),游戏引擎大改数学库
- **2010s**:GPU 通用计算,大量数学搬到 shader
- **2020s**:Tensor cores 用于游戏光线追踪和 AI 插帧

你跟 HH 学,本质是走完这个演化的前 30 年——从 f32 标量到 SIMD 向量。

### CPU 数学 vs GPU 数学

| | CPU | GPU |
|---|---|---|
| 数据布局 | AoS 或 SoA 都行 | SoA 为主(vertex buffer) |
| 运算单元 | 标量 + SIMD (AVX 512) | 大规模并行 |
| 适合 | 复杂控制流、低延迟 | 大批量同质运算 |
| 程序 | Rust | GLSL / HLSL / WGSL |

游戏开发是 CPU 和 GPU 协作:CPU 算游戏逻辑,AI,物理;GPU 算光照,光栅化,后处理。HH 在 Day 235 之前全 CPU(软渲染),之后切 OpenGL 把渲染搬到 GPU。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:点积 `a · b = 0` 意味着什么?在 3 种不同游戏场景里,这个性质各自解决什么问题?

**参考解答**:`a · b = 0` ⟺ `|a||b|cos(θ) = 0` ⟺ θ = 90°(假设两向量都不为零)⟺ **两向量垂直**。

三个场景:
1. **光照**:表面法线 N 和光源方向 L 垂直时,光平行掠过表面,Lambert 漫反射 = `max(0, N·L)` = 0,表面最暗(边缘光)。这是日落时地平线的样子。
2. **AI 视野**:NPC 朝向 F 和 NPC 到玩家向量 V 垂直时,玩家在 NPC 的"正侧面"。如果视野是 90° 半锥,这是视野的极限。
3. **物理**:绳子上挂重物,如果绳子方向和重力方向垂直(水平绳子),重力对绳子张力贡献为 0(角度上是无法实现的,但数学上是这样)。

### Lv2 · 动手实践

**题**:在 Rust 项目里实现 `Vec2` 结构体,包括 `add`, `sub`, `mul(f32)`, `dot`, `cross`, `length`, `normalized`, `reflect`。写一个 `main` 测试:
- `Vec2::new(3.0, 4.0).length()` 应该等于 5.0
- `Vec2::new(1.0, 0.0).dot(Vec2::new(0.0, 1.0))` 应该等于 0.0(垂直)
- `Vec2::new(1.0, -1.0).reflect(Vec2::new(0.0, 1.0))` 应该约等于 `Vec2::new(1.0, 1.0)`(撞地反弹)

完成标准:`cargo run` 打印三个 `assert_eq!` 都通过。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug, PartialEq)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
    fn sub(self, o: Self) -> Self { Self { x: self.x - o.x, y: self.y - o.y } }
    fn mul(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
    fn dot(self, o: Self) -> f32 { self.x * o.x + self.y * o.y }
    fn cross(self, o: Self) -> f32 { self.x * o.y - self.y * o.x }
    fn length(self) -> f32 { (self.x * self.x + self.y * self.y).sqrt() }
    fn normalized(self) -> Self {
        let len = self.length();
        if len > 1e-6 { self.mul(1.0 / len) } else { Self::new(0.0, 0.0) }
    }
    // 反射:v' = v - 2(v·n)n,n 必须是单位向量
    fn reflect(self, n: Self) -> Self {
        let d = self.dot(n);
        self.sub(n.mul(2.0 * d))
    }
}

fn main() {
    // 勾股数 3-4-5
    assert_eq!(Vec2::new(3.0, 4.0).length(), 5.0);
    // x 轴和 y 轴垂直
    assert_eq!(Vec2::new(1.0, 0.0).dot(Vec2::new(0.0, 1.0)), 0.0);
    // 向下偏右的速度撞地面(法线向上),反射后向上偏右
    let v = Vec2::new(1.0, -1.0);
    let n = Vec2::new(0.0, 1.0);
    let r = v.reflect(n);
    assert!((r.x - 1.0).abs() < 1e-6);
    assert!((r.y - 1.0).abs() < 1e-6);
    println!("All assertions passed!");
}
```

**每行解释**:
- `#[derive(PartialEq)]` — 让 `assert_eq!` 能比较两个 Vec2 是否相等。注意 f32 的相等比较在工程上有精度问题,我们这里用勾股数避免。
- `length` 用 `sqrt`,Rust 的 `f32::sqrt()` 底层是 `libm` 的 `sqrtf`,在 x86_64 上编译成 `sqrtss` 硬件指令。
- `reflect` 公式来自 §2.5。先算 `d = v·n`,然后 `v - 2*d*n`。这里 `n.mul(2.0 * d)` 是 `2*d*n`,标量乘向量。
- 浮点相等用 `abs(...) < 1e-6` 而不是 `==`,因为浮点运算有舍入误差。

## 8 · Rust / Arch 落地代码

### Rust 完整可跑示例

把 §7 Lv2 的代码扩展,加上 SIMD 优化版本对比。

```rust
// Cargo.toml(空即可,纯 std)

use std::arch::x86_64::*;

#[derive(Copy, Clone, Debug, PartialEq)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
    fn dot(self, o: Self) -> f32 { self.x * o.x + self.y * o.y }
    fn length(self) -> f32 { self.x.mul_add(self.x, self.y * self.y).sqrt() }
    // mul_add 是 fused multiply-add,比 a*b+c 更快也更精确(一次舍入而不是两次)
    // Rust 的 f32::mul_add 映射到硬件指令(如 x86 的 VFMADD213SS)
}

// SIMD 版本:一次处理 4 个 Vec2
#[cfg(target_arch = "x86_64")]
fn length_simd4(coords: &[(f32, f32); 4]) -> [f32; 4] {
    unsafe {
        // 把 4 个 (x,y) 加载到两个 SIMD 寄存器
        let xs = _mm_set_ps(coords[3].0, coords[2].0, coords[1].0, coords[0].0);
        let ys = _mm_set_ps(coords[3].1, coords[2].1, coords[1].1, coords[0].1);
        // xs * xs + ys * ys
        let x2 = _mm_mul_ps(xs, xs);
        let y2 = _mm_mul_ps(ys, ys);
        let sum = _mm_add_ps(x2, y2);
        // sqrt
        let len = _mm_sqrt_ps(sum);
        // 取出 4 个结果
        let mut out = [0f32; 4];
        _mm_storeu_ps(out.as_mut_ptr(), len);
        out
    }
}

fn main() {
    let v = Vec2::new(3.0, 4.0);
    println!("v = {:?}", v);
    println!("|v| = {}", v.length()); // 5.0

    let four = [(3.0, 4.0), (5.0, 12.0), (8.0, 15.0), (7.0, 24.0)];
    let lens = length_simd4(&four);
    println!("SIMD lengths: {:?}", lens); // [5, 13, 17, 25]
}
```

**关键 Rust 特性解释**:
- `mul_add` — 融合乘加,一次硬件操作 `a*b+c`,比分开快、比分开准。Rust 的 `f32::mul_add` 是 unsafe-friendly 的安全 API
- `#[cfg(target_arch = "x86_64")]` — 编译条件,只在 x86_64 编译这段代码(ARM / WASM 没有 `_mm_*` 指令)
- `use std::arch::x86_64::*` — 引入 SIMD intrinsics
- `unsafe { ... }` — SIMD intrinsic 是 unsafe,因为编译器无法验证目标 CPU 支持这些指令。生产代码要先用 `is_x86_feature_detected!("avx2")` 运行时检查
- `_mm_set_ps(a, b, c, d)` — 注意参数顺序是反的(因为 SSE 用小端),会加载成 `[d, c, b, a]`
