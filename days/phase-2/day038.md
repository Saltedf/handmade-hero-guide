# Day 038 · 基础线性位图混合

> Day 037 你能 blit 一个 BMP 到屏幕——但 BMP 的所有像素都不透明,**矩形 sprite 看起来就是个矩形**。Day 038 加 alpha 混合:每像素有透明度,让 sprite 边缘"自然过渡"。这是 sprite 渲染的灵魂——没有 alpha,游戏角色都是矩形方块;有 alpha,角色边缘是真实形状(圆头、尖剑、长袍)。

## 0 · 为什么要有这一天

你做完 Day 037 blit,画面上有个红色矩形 sprite。但你想画一个**圆形**角色(比如小球),怎么办?

最朴素的想法:画矩形,但矩形里画一个圆,圆外面是"背景色"。**问题**:背景色是动态的(玩家走草地是绿,走石板是灰),你的 sprite 不可能预知。

**正确解法**:**每像素有透明度**。圆内 alpha=255(完全不透明),圆外 alpha=0(完全透明),边缘 alpha 中间值(柔和过渡)。

这就是 **alpha blending**(alpha 混合)。核心公式:

```
out = src * src_alpha + dst * (1 - src_alpha)
```

**直觉**:src_alpha = 0 → out = dst(完全显示背景);src_alpha = 1 → out = src(完全显示前景);0.5 → 各占一半。

Alpha 混合无处不在:

- 游戏 sprite 边缘(玩家、怪物)
- UI 阴影、玻璃效果(macOS / iOS)
- 文字抗锯齿(字体边缘半透明)
- 粒子效果(烟雾、火焰)
- 渐变(天空、阴影)

但 alpha 混合有几个**非平凡决策**:

1. **公式选择**:"Normal" / "Additive" / "Premultiplied" / "Porter-Duff"——12+ 种
2. **性能**:每像素 alpha 计算开销大,如何优化?
3. **色彩空间**:alpha 混合应该在线性空间,但 BMP 是 sRGB——直接混合会偏色
4. **premultiplied alpha**:把 RGB 预先乘 alpha,公式更简单更快

Casey 这集做的事情:

1. 实现 "Normal" alpha blending 公式
2. 加 fast path(alpha = 0 或 255 时跳过混合)
3. 讨论 premultiplied alpha 的优势
4. 提到色彩空间问题(留到 Day 083+ 完整处理)

心理锚点:看完这集,你应该能:

- 推导 normal alpha blending 公式
- 解释 premultiplied alpha 的优势
- 写出一个带 alpha 的 blit 函数

如果你做不到,反复看 §2 的"alpha 公式推导"和"premultiplied"。Day 083(色彩空间)、Day 094(双线性插值)、Day 235+(GPU alpha)都基于这集。

## 2 · 心智模型

### 类比:彩色玻璃叠加

想象两片**彩色玻璃**叠加:

- 上面玻璃(前景)= src,透明度 alpha
- 下面玻璃(背景)= dst,完全不透明
- 叠加后看到的颜色 = ?

物理直觉:玻璃越透明(alpha 越小),越透出背景颜色。完全不透明(alpha=1)只看到前景,完全透明(alpha=0)只看到背景。中间值是两者的混合。

**公式**:

```
out = src * alpha + dst * (1 - alpha)
```

**推导**:

- 光从背景出,经过前景到眼睛
- 前景阻挡 alpha 比例的光,透过 (1 - alpha) 比例的光
- 最终看到 = 前景颜色 × alpha(前景阻挡部分)+ 背景颜色 × (1 - alpha)(透过部分)

这就是 alpha blending 的物理意义。

### 公式:Normal Alpha Blending

```
out.r = src.r * a + dst.r * (1 - a)
out.g = src.g * a + dst.g * (1 - a)
out.b = src.b * a + dst.b * (1 - a)
```

`a` 是 alpha 值,范围 [0, 1]。在 8-bit BMP 里,alpha 是 0-255 的整数,要除以 255 转成 [0, 1]。

**整数实现**(避免浮点):

```rust
// a 是 0-255 的整数
// out = (src * a + dst * (255 - a)) / 255
let a = src_alpha as u32;  // 0-255
let inv_a = 255 - a;
let out_r = (src_r as u32 * a + dst_r as u32 * inv_a) / 255;
let out_g = (src_g as u32 * a + dst_g as u32 * inv_a) / 255;
let out_b = (src_b as u32 * a + dst_b as u32 * inv_a) / 255;
```

**性能问题**:`/ 255` 整数除法很慢(几十 cycle)。优化:用 `(x + 128) >> 8` 近似(因为 255 ≈ 256 = 2^8)。

```rust
let out_r = (src_r as u32 * a + dst_r as u32 * inv_a + 128) >> 8;
```

误差 < 1,视觉上无差异。但快 5-10 倍(位运算 vs 除法)。

### Fast Path:alpha = 0 / 255

```rust
fn alpha_blit_pixel(dst_pixel: u32, src_pixel: u32, src_alpha: u8) -> u32 {
    if src_alpha == 0 {
        return dst_pixel;  // 完全透明,不动
    }
    if src_alpha == 255 {
        return src_pixel;  // 完全不透明,直接覆盖
    }
    // 中间值,做完整混合
    let dst_r = (dst_pixel >> 16) & 0xFF;
    let dst_g = (dst_pixel >> 8) & 0xFF;
    let dst_b = dst_pixel & 0xFF;
    let src_r = (src_pixel >> 16) & &0xFF;
    let src_g = (src_pixel >> 8) & 0xFF;
    let src_b = src_pixel & 0xFF;
    let a = src_alpha as u32;
    let inv_a = 255 - a;
    let out_r = ((src_r * a + dst_r * inv_a + 128) >> 8) as u32;
    let out_g = ((src_g * a + dst_g * inv_a + 128) >> 8) as u32;
    let out_b = ((src_b * a + dst_b * inv_a + 128) >> 8) as u32;
    (out_r << 16) | (out_g << 8) | out_b
}
```

**为什么 fast path 重要**:大部分 sprite 像素的 alpha 是 0(边缘外)或 255(中心),只有边缘 ~10% 像素是中间值。fast path 跳过 90% 像素的完整混合。

### Premultiplied Alpha(预乘 alpha)

**Normal alpha**:RGB 独立,alpha 单独存。
**Premultiplied alpha**:RGB 已经乘了 alpha,即存 `R' = R * alpha`、`G' = G * alpha`、`B' = B * alpha`。

**Premultiplied 的混合公式**:

```
out = src_premul + dst * (1 - src_alpha)
```

对比 normal 的 `out = src * a + dst * (1 - a)`,premultiplied 少了一次乘法。**性能更好**。

**Premultiplied 的另一个好处**:**没有"光晕"bug**。

Normal alpha 的经典 bug:半透明边缘像素混合时,RGB 通道"溢出"到 alpha 之外。比如 RGBA = (255, 0, 0, 128),normal 混合到白色背景上:

```
out.r = 255 * 0.5 + 255 * 0.5 = 255  (正确)
out.g = 0 * 0.5 + 255 * 0.5 = 128  (从 0 变 128,绿)
out.b = 0 * 0.5 + 255 * 0.5 = 128  (从 0 变 128,蓝)
```

结果颜色 = (255, 128, 128),偏粉红。**红色 sprite 在白色背景边缘出现粉边**。

Premultiplied:RGBA = (128, 0, 0, 128)(R 已经乘 0.5)。

```
out.r = 128 + 255 * 0.5 = 255.5 → 255  (正确)
out.g = 0 + 255 * 0.5 = 128  (OK)
out.b = 0 + 255 * 0.5 = 128  (OK)
```

理论上结果一样,但**premultiplied 让数学一致**,没有 normal 的"边界 bug"。

**为什么 Casey 这集用 normal**:

- 教学清晰(直接推导"加权平均")
- BMP 是 normal 格式
- Day 083+ 切 premultiplied(配合色彩空间讨论)

### 色彩空间问题

**踩坑预警**:**alpha 混合应该在线性空间**,但 BMP/PNG 是 sRGB(非线性)。直接在 sRGB 混合会偏色(具体偏暗)。

正确流程:

1. BMP 加载:sRGB → Linear(`linear = srgb_to_linear(sRGB)`)
2. 线性空间做混合:`out_linear = src_linear * a + dst_linear * (1-a)`
3. 显示:Linear → sRGB(`sRGB = linear_to_sRGB(linear)`)

Casey Day 038 **不处理**色彩空间(简化)。Day 083+ 完整处理。视觉上 8-bit 显示器精度有限,差异不大,但专业项目必须处理。

### Additive Blending(另一种混合)

除了 normal,还有 **additive**(加法):

```
out = src + dst
```

**用途**:

- 火焰、爆炸、激光——亮的东西加到背景上
- 玩家被攻击的红色闪烁
- 黑色背景上 additive = normal,白色背景上 additive 过曝

**游戏里混合模式选择**:

| 模式 | 公式 | 适合 |
|---|---|---|
| Normal | out = src*a + dst*(1-a) | 大部分场景 |
| Additive | out = src + dst | 发光 / 火焰 |
| Multiply | out = src * dst | 阴影 / 染色 |
| Subtract | out = dst - src | 黑暗效果 |
| Screen | out = 1 - (1-src)*(1-dst) | 屏幕混合 |

Casey 这集只做 normal,后面集按需加其他模式。

### Porter-Duff 12 种模式

**Porter-Duff** 是 alpha 混合的完整理论(1984 论文)。12 种模式描述不同 source / destination 交互:

- **Source Over**(`src*a + dst*(1-a)`):normal,最常用
- **Destination Over**(`dst*a + src*(1-a)`):反方向
- **Source In**(`src*a`):只显示 src 重叠 dst 的部分
- **Source Out**(`src*(1-a)`):只显示 src 不重叠 dst 的部分
- ...

PDF / SVG 用 Porter-Duff。Casey HH 用 Source Over 90% 时间,其他模式极少。

### 完整的 alpha blit 函数

```rust
fn alpha_blit(
    fb: &mut [u32], fb_w: i32, fb_h: i32,
    dest_x: i32, dest_y: i32,
    src: &[u32], src_alpha: &[u8],  // 像素 + 独立 alpha 数组
    src_w: i32, src_h: i32,
) {
    let src_x_start = (-dest_x).max(0).min(src_w);
    let src_y_start = (-dest_y).max(0).min(src_h);
    let src_x_end = (fb_w - dest_x).max(0).min(src_w);
    let src_y_end = (fb_h - dest_y).max(0).min(src_h);

    for sy in src_y_start..src_y_end {
        for sx in src_x_start..src_x_end {
            let src_idx = (sy * src_w + sx) as usize;
            let dx = dest_x + sx;
            let dy = dest_y + sy;
            let dst_idx = (dy * fb_w + dx) as usize;

            let a = src_alpha[src_idx];
            if a == 0 { continue; }  // fast path 1
            let src_pixel = src[src_idx];
            if a == 255 {
                fb[dst_idx] = src_pixel;  // fast path 2
                continue;
            }
            // 完整混合
            fb[dst_idx] = alpha_blend_pixel(fb[dst_idx], src_pixel, a);
        }
    }
}

fn alpha_blend_pixel(dst: u32, src: u32, alpha: u8) -> u32 {
    let dst_r = ((dst >> 16) & 0xFF) as u32;
    let dst_g = ((dst >> 8) & 0xFF) as u32;
    let dst_b = (dst & 0xFF) as u32;
    let src_r = ((src >> 16) & 0xFF) as u32;
    let src_g = ((src >> 8) & 0xFF) as u32;
    let src_b = (src & 0xFF) as u32;
    let a = alpha as u32;
    let inv_a = 255 - a;
    let out_r = (src_r * a + dst_r * inv_a + 128) >> 8;
    let out_g = (src_g * a + dst_g * inv_a + 128) >> 8;
    let out_b = (src_b * a + dst_b * inv_a + 128) >> 8;
    (out_r << 16) | (out_g << 8) | out_b
}
```

**关键细节**:

- `src` 和 `src_alpha` 分开存(教学清晰)。实际项目通常合并成 `Vec<[u8; 4]>`(RGBA)
- `+128 >> 8` 是 `/ 255` 的快速近似(`>> 8` = `/ 256`,加 128 是四舍五入)
- fast path 在循环内,每次访问跳过大部分计算

### 性能优化方向

1. **SIMD**:一次处理 4 个像素(SSE)或 8 个像素(AVX2)。Day 121+
2. **Lookup table**(LUT):预先算 256 × 256 个混合结果,运行时查表
3. **Premultiplied alpha**:少一次乘法
4. **GPU**:Day 235+,硬件加速

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Alpha 混合是 sprite 渲染的灵魂。游戏开发圈共识:

**Sprite 必须有 alpha**:矩形 sprite 看起来"假",alpha 让边缘自然。所有现代 2D 游戏都用 alpha sprite。

**Sprite sheet**(精灵图集):一个 PNG 文件包含多个 sprite(动画帧、状态变化)。加载时切分成独立 sprite。Casey Day 236+ 实现这个。

**9-slice rendering**:UI 元素(对话框、按钮)用 9 区域 sprite——4 角不缩放、4 边单向缩放、中间双向缩放。这样 UI 能任意大小而角不变形。

### 3.2 · 🎨 图形学视角

**色彩空间**(再强调一次):

- BMP / PNG:存 sRGB(适配显示器)
- 渲染计算(混合 / 光照):**必须线性空间**
- 显示:转回 sRGB

**为什么混合要线性**:sRGB 是 gamma 编码(≈ 2.2),`sRGB = linear^(1/2.2)`。在 sRGB 空间做线性混合**不是真线性**——结果是 `sRGB^2.2` 的混合,偏暗。

**正确做法**:

```
src_linear = sRGB_to_linear(src_sRGB)
dst_linear = sRGB_to_linear(dst_sRGB)
out_linear = src_linear * a + dst_linear * (1-a)
out_sRGB = linear_to_sRGB(out_linear)
```

Casey Day 038 不做这个(简化),Day 083+ 完整。**8-bit 精度下视觉差异不大,但专业项目必须做**。

**MSAA**(Multi-Sample Anti-Aliasing):边缘像素多次采样,平均——这是另一种"alpha"思路。Day 240+ 简单讨论。

### 3.3 · 🐧 Linux 系统编程视角

- **窗口阴影**:Wayland / X11 compositor 用 alpha 混合画窗口阴影
- **半透明 UI**:macOS 风格半透明面板
- **字体抗锯齿**:freetype + fontconfig 生成 alpha 字体

### 3.4 · 🦀 Rust 生态视角

Rust 表达 alpha 混合有几种方式:

**方式 1:手动位运算(Casey 风格)**

```rust
let out = (src_r * a + dst_r * inv_a) >> 8;
```

最直接,完全控制。但啰嗦。

**方式 2:`fast-math` crate**

```rust
use fast_math::lerp;
let out = lerp(dst, src, a);
```

抽象,但可能不优化到最佳。

**方式 3:SIMD**

```rust
use std::arch::x86_64::*;
unsafe {
    let src_v = _mm_set_epi32(src_r as i32, src_g as i32, src_b as i32, 0);
    let dst_v = _mm_set_epi32(dst_r as i32, dst_g as i32, dst_b as i32, 0);
    let a_v = _mm_set1_epi32(a as i32);
    let inv_a_v = _mm_set1_epi32((255 - a) as i32);
    let out_v = _mm_add_epi32(
        _mm_mullo_epi32(src_v, a_v),
        _mm_mullo_epi32(dst_v, inv_a_v),
    );
    // shift right by 8 ...
}
```

一次处理 4 个像素。Day 121+ Casey 加。

**方式 4:`image` crate**

```rust
use image::RgbaImage;
let mut img: RgbaImage = ...;
img.pixels_mut().for_each(|p| {
    // alpha blend
});
```

高级抽象,但 Casey 不用(他要教你原理)。

**Rust 的所有权和 alpha blit**:

```rust
fn alpha_blit(fb: &mut [u32], src: &[u32], ...) { ... }
//                                    ^ 借用 src
//                  ^ 借用 fb(可变)
```

注意:**fb 和 src 不能是同一段内存**(self-blit)。Rust 借用规则保证。

## 5 · 对照与变奏

### 同一问题在不同语境下的变体

**问题**:混合两种颜色,各自有"权重"。

| 语境 | "混合"叫法 | 公式 |
|---|---|---|
| 2D 游戏 sprite | alpha blending | out = src*a + dst*(1-a) |
| 图像处理 | lerp | out = a + (b-a)*t |
| 音频混合 | weighted sum | out = a*s1 + b*s2 |
| 3D 光照 | Phong diffuse | N·L * light_color |
| 物理 | center of mass | sum(m_i * x_i) / sum(m_i) |
| 统计 | expected value | sum(p_i * x_i) |

所有这些场景的核心思想相同:**加权平均**。

### Alpha 混合的演化

- **1970s**:Alvy Ray Smith 提出 alpha channel 概念
- **1980s**:PNG 标准化 alpha(早期 GIF 只有 1-bit transparency)
- **1990s**:Porter-Duff 论文(1984)成为图形学经典
- **2000s**:Premultiplied alpha 普及
- **2010s**:HDR + alpha(Wider color gamut)
- **2020s**:Neural alpha matting(AI 辅助)

Casey HH 教基础 normal alpha,后面演化到 premultiplied 和高级模式。

### 2D vs 3D 的 alpha

| | 2D(Casey Day 038) | 3D(Day 235+) |
|---|---|---|
| 计算位置 | CPU 软渲染 | GPU fragment shader |
| 速度 | ~100M pixel/s | ~10G pixel/s |
| 灵活 | 任意公式 | 任意 shader |
| 主要用途 | sprite / UI | 透明物体(玻璃、水) |

3D 渲染里 alpha 还有额外问题:**depth buffer 和 alpha 不友好**(透明物体不写 depth)。Casey Day 250+ 处理。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Casey 用 normal alpha,但说 premultiplied alpha 更好。具体好在哪?

**参考解答**:**两个优势:性能 + 正确性**。

**性能**:Normal 公式 `out = src*a + dst*(1-a)`,3 次乘法 + 1 次加法。Premultiplied 公式 `out = src_premul + dst*(1-a)`,2 次乘法 + 1 次加法。**少一次乘法**。

每像素少一次乘法,100 万像素省 100 万次乘法 ≈ 几毫秒。SIMD 友好。

**正确性**:Normal 在某些场景产生"光晕"bug:

- 半透明 sprite 在白色背景上,边缘出现彩色边(不是 sprite 本色)
- 根因:RGB 通道在 alpha 边界"溢出"

Premultiplied 的 RGB 已经预先"按 alpha 缩放",不会溢出。

**为什么 Casey Day 038 用 normal**:教学清晰(直接推"加权平均"),BMP 默认 normal。Day 083+(色彩空间)切换 premultiplied。

### Lv2 · 动手实践

**题**:实现 alpha blit,渲染一个带 alpha 的 sprite。要求:

1. 加载 32-bit BMP(支持 alpha 通道)
2. 实现 `alpha_blend_pixel(dst, src, alpha)` 函数
3. 实现 `alpha_blit(fb, ...)` 带 fast path
4. 测试:画一个"边缘羽化"的圆形 sprite 到不同背景上

完成标准:背景颜色不同时,sprite 边缘自然过渡,没有"矩形 box"痕迹。

**参考解答**:

```rust
// src/main.rs
// cargo new --bin alpha_blit && cd alpha_blit

const FB_W: i32 = 256;
const FB_H: i32 = 256;
const SPRITE_SIZE: i32 = 64;

fn alpha_blend_pixel(dst: u32, src: u32, alpha: u8) -> u32 {
    if alpha == 0 { return dst; }
    if alpha == 255 { return src; }
    let dst_r = ((dst >> 16) & 0xFF) as u32;
    let dst_g = ((dst >> 8) & 0xFF) as u32;
    let dst_b = (dst & 0xFF) as u32;
    let src_r = ((src >> 16) & 0xFF) as u32;
    let src_g = ((src >> 8) & 0xFF) as u32;
    let src_b = (src & 0xFF) as u32;
    let a = alpha as u32;
    let inv_a = 255 - a;
    let out_r = (src_r * a + dst_r * inv_a + 128) >> 8;
    let out_g = (src_g * a + dst_g * inv_a + 128) >> 8;
    let out_b = (src_b * a + dst_b * inv_a + 128) >> 8;
    (out_r << 16) | (out_g << 8) | out_b
}

fn alpha_blit(
    fb: &mut [u32], fb_w: i32, fb_h: i32,
    dest_x: i32, dest_y: i32,
    src_rgba: &[[u8; 4]], src_w: i32, src_h: i32,
) {
    let src_x_start = (-dest_x).max(0).min(src_w);
    let src_y_start = (-dest_y).max(0).min(src_h);
    let src_x_end = (fb_w - dest_x).max(0).min(src_w);
    let src_y_end = (fb_h - dest_y).max(0).min(src_h);

    for sy in src_y_start..src_y_end {
        for sx in src_x_start..src_x_end {
            let src_idx = (sy * src_w + sx) as usize;
            let dx = dest_x + sx;
            let dy = dest_y + sy;
            let dst_idx = (dy * fb_w + dx) as usize;
            let [r, g, b, a] = src_rgba[src_idx];
            if a == 0 { continue; }
            let src_pixel = ((r as u32) << 16) | ((g as u32) << 8) | (b as u32);
            if a == 255 {
                fb[dst_idx] = src_pixel;
                continue;
            }
            fb[dst_idx] = alpha_blend_pixel(fb[dst_idx], src_pixel, a);
        }
    }
}

// 生成圆形 sprite(边缘羽化)
fn make_circle_sprite() -> Vec<[u8; 4]> {
    let mut sprite = vec![[0u8; 4]; (SPRITE_SIZE * SPRITE_SIZE) as usize];
    let center = SPRITE_SIZE as f32 / 2.0;
    let radius = center - 1.0;
    for y in 0..SPRITE_SIZE {
        for x in 0..SPRITE_SIZE {
            let dx = x as f32 + 0.5 - center;
            let dy = y as f32 + 0.5 - center;
            let dist = (dx * dx + dy * dy).sqrt();
            // 距离 < radius-1:完全不透明
            // 距离 > radius+1:完全透明
            // 中间:线性插值
            let alpha = if dist < radius - 1.0 {
                255
            } else if dist > radius + 1.0 {
                0
            } else {
                let t = (radius + 1.0 - dist) / 2.0;
                (255.0 * t) as u8
            };
            let idx = (y * SPRITE_SIZE + x) as usize;
            sprite[idx] = [255, 0, 0, alpha];  // 红色 + alpha
        }
    }
    sprite
}

fn write_ppm(filename: &str, fb: &[u32], w: i32, h: i32) {
    use std::io::Write;
    let mut f = std::fs::File::create(filename).unwrap();
    writeln!(f, "P6\n{} {}\n255", w, h).unwrap();
    let mut bytes = Vec::with_capacity((w * h * 3) as usize);
    for &p in fb {
        bytes.push(((p >> 16) & 0xFF) as u8);
        bytes.push(((p >> 8) & 0xFF) as u8);
        bytes.push((p & 0xFF) as u8);
    }
    f.write_all(&bytes).unwrap();
}

fn main() {
    let mut fb = vec![0u32; (FB_W * FB_H) as usize];

    // 画 4 个不同背景区域
    let half_w = FB_W / 2;
    let half_h = FB_H / 2;
    for y in 0..FB_H {
        for x in 0..FB_W {
            let color = match (x < half_w, y < half_h) {
                (true, true) => 0xFFFFFF,    // 白
                (false, true) => 0x000000,   // 黑
                (true, false) => 0x00FF00,   // 绿
                (false, false) => 0x0000FF,  // 蓝
            };
            fb[(y * FB_W + x) as usize] = color;
        }
    }

    // 生成圆形 sprite
    let sprite = make_circle_sprite();

    // blit 到 4 个区域中心
    alpha_blit(&mut fb, FB_W, FB_H,
        half_w / 2 - SPRITE_SIZE / 2, half_h / 2 - SPRITE_SIZE / 2,
        &sprite, SPRITE_SIZE, SPRITE_SIZE);
    alpha_blit(&mut fb, FB_W, FB_H,
        half_w + half_w / 2 - SPRITE_SIZE / 2, half_h / 2 - SPRITE_SIZE / 2,
        &sprite, SPRITE_SIZE, SPRITE_SIZE);
    alpha_blit(&mut fb, FB_W, FB_H,
        half_w / 2 - SPRITE_SIZE / 2, half_h + half_h / 2 - SPRITE_SIZE / 2,
        &sprite, SPRITE_SIZE, SPRITE_SIZE);
    alpha_blit(&mut fb, FB_W, FB_H,
        half_w + half_w / 2 - SPRITE_SIZE / 2, half_h + half_h / 2 - SPRITE_SIZE / 2,
        &sprite, SPRITE_SIZE, SPRITE_SIZE);

    write_ppm("alpha_demo.ppm", &fb, FB_W, FB_H);
    println!("Wrote alpha_demo.ppm");
    println!("View with: feh alpha_demo.ppm");
    println!("You should see 4 red circles on different backgrounds,");
    println!("each with smooth alpha-blended edges.");
}
```

**预期效果**:打开 PPM 看到 4 个红色圆形,边缘自然过渡,在不同背景上看起来都是"圆"而不是"方"。

// src/main.rs (扩展 Lv2)
// 加:正常 vs fast path 性能对比,以及单元测试

fn bench_alpha() {
    let n_pixels = 1_000_000;
    let dst: Vec<u32> = vec![0x7F7F7F; n_pixels];
    let src: Vec<u32> = vec![0xFF0000; n_pixels];
    let alphas_fast: Vec<u8> = vec![0; n_pixels];      // 全 0 → fast path
    let alphas_slow: Vec<u8> = vec![128; n_pixels];    // 全 128 → 慢路径
    let alphas_full: Vec<u8> = vec![255; n_pixels];    // 全 255 → fast path

    let start = std::time::Instant::now();
    for i in 0..n_pixels {
        let _ = alpha_blend_pixel(dst[i], src[i], alphas_fast[i]);
    }
    let fast_time = start.elapsed();

    let start = std::time::Instant::now();
    for i in 0..n_pixels {
        let _ = alpha_blend_pixel(dst[i], src[i], alphas_full[i]);
    }
    let full_time = start.elapsed();

    let start = std::time::Instant::now();
    for i in 0..n_pixels {
        let _ = alpha_blend_pixel(dst[i], src[i], alphas_slow[i]);
    }
    let slow_time = start.elapsed();

    println!("=== Alpha Blend Performance ({} pixels) ===", n_pixels);
    println!("alpha=0   (fast path): {:?}", fast_time);
    println!("alpha=255 (fast path): {:?}", full_time);
    println!("alpha=128 (full blend): {:?}", slow_time);
    println!("Slow / fast ratio: {:.1}x",
        slow_time.as_secs_f64() / fast_time.as_secs_f64());
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn alpha_0_keeps_dst() {
        let result = alpha_blend_pixel(0x123456, 0xFFFFFF, 0);
        assert_eq!(result, 0x123456);  // 完全透明,不变
    }

    #[test]
    fn alpha_255_uses_src() {
        let result = alpha_blend_pixel(0x123456, 0xFFFFFF, 255);
        assert_eq!(result, 0xFFFFFF);  // 完全不透明,直接覆盖
    }

    #[test]
    fn alpha_128_averages() {
        // dst = 0x000000(黑),src = 0xFFFFFF(白),alpha = 128
        // out = (255 * 128 + 0 * 127 + 128) >> 8 ≈ 128
        let result = alpha_blend_pixel(0x000000, 0xFFFFFF, 128);
        // 结果应该在 127-130 之间(近似 / 255)
        let r = (result >> 16) & 0xFF;
        assert!(r >= 125 && r <= 132);
    }

    #[test]
    fn alpha_preserves_channels() {
        // src 全 0, alpha 任意 → 不变 dst
        let result = alpha_blend_pixel(0xABCDEF, 0x000000, 128);
        // out = (0 * 128 + 0xAB * 127 + 128) >> 8 ≈ 0x55
        let r = (result >> 16) & 0xFF;
        let g = (result >> 8) & 0xFF;
        let b = result & 0xFF;
        // R 应该接近 0x55(原 0xAB 的一半)
        assert!((r as i32 - 0x55).abs() < 3);
        assert!((g as i32 - 0x6F).abs() < 3);
        assert!((b as i32 - 0x77).abs() < 3);
    }
}

fn main() {
    bench_alpha();
}
