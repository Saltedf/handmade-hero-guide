# Day 049 · 调试规范坐标

> Day 032 Casey 把位置表示成 `WorldPos { tile_x, tile_y, offset_x, offset_y }`,看起来优雅但藏着一个 bug:offset 没有正确归一化(超出 [0, TILE_SIZE) 范围),玩家会突然"瞬移"到错误坐标。Day 049 是 Casey 的 debug 一集——演示怎么用"可视化 + 假设验证"找到这种隐蔽 bug,以及怎么用 Rust 类型系统防止再发生。

## 0 · 为什么要有这一天

游戏开发里 80% 的时间不是写新功能,是**调 bug**。但绝大多数教程不教你"怎么调",默认你天生就会。Casey 在 Day 049 用一整集演示调试方法论,核心是:**把不可见的状态变成可见的**。

具体 bug:Day 032 引入的 `WorldPos` 结构:

```rust
pub struct WorldPos {
    pub tile_x: i32,
    pub tile_y: i32,
    pub offset: Vec2,  // 应该在 [0, TILE_SIZE) 范围
}
```

设计意图:位置 = 整数 tile 坐标 + 浮点 offset。offset 永远在 [0, TILE_SIZE) 内,超出就进位到 tile。但 Casey 在 Day 032 没写 normalize 函数,offset 可能变成负数或超过 TILE_SIZE。这导致:

- 玩家位置看起来对(渲染时只看 tile + offset)
- 但跨 tile 边界时,offset 不进位,玩家"瞬移"到隔壁 tile 的对应位置
- Bug 罕见(只在跨边界时触发),难复现

Casey 在 Day 049 用"屏幕上画玩家 tile 坐标 + offset 实时值"的方法,看到 offset 超过 TILE_SIZE,定位 bug,加 normalize 修复。

**这集的教学价值不在 bug 本身**(常见 fencepost error),**在调试方法论**:

1. **现象观察**:玩家瞬移
2. **可视化**:把内部状态(offset 值)画到屏幕
3. **假设验证**:猜"offset 超过 TILE_SIZE 了",验证
4. **定位**:找到具体的代码位置(Day 032 没写 normalize)
5. **修复 + 防御**:加 normalize 函数 + 用 Rust 类型系统保证不变量

心理锚点:做完今天,你应该:

1. 看到一个 bug 时,不会立刻"改代码试试",而是先"让 bug 可见"
2. 知道 Rust 的 private 字段 + 公开方法可以强制不变量(invariant)
3. 能解释"防御式编程"(defensive programming)和"契约式编程"(design by contract)的区别

这是从"会写代码"到"会调代码"的关键转变。

## 1 · Casey 今天做了什么

Casey 在 day049 视频里做了四件事:

1. **重现 bug**:让玩家跨 tile 边界,观察屏幕上玩家位置"瞬移"到错误地方。
2. **可视化内部状态**:在屏幕上画调试 overlay,显示当前 WorldPos 的 tile_x, tile_y, offset 实时值。
3. **观察 + 假设**:看到 offset 在跨边界时短暂变成 -32 或 +64(超出 [0, 32) 范围)。Casey 猜测"offset 没正确进位"。
4. **加 normalize 函数**:每次修改 WorldPos 后调用 normalize,把超出的 offset 转成 tile 进位。Bug 消失。

Casey 强调调试方法论:**先让 bug 复现,再让内部状态可见,最后才动手改**。直接"凭感觉改"往往改错地方,引入新 bug。

视频里 Casey 还讨论了 Rust 类型系统(虽然他用 C,但思路一样):**如果 offset 是 private,只能通过 set_pos() 方法修改,方法里强制 normalize**,bug 在编译期消除。这是 Rust 比 C 的优势——类型系统帮你抓不变量。

## 2 · 心智模型

### 费曼类比:时钟的时针和分针

时钟有时针(慢)和分针(快)。分针走 60 圈,时针走 1 圈。如果你只看时针,粗略知道时间;只看分针,精确但不知道几小时;两者结合才能精确报时。

**WorldPos 类似**:tile 坐标是"时针"(粗略位置),offset 是"分针"(精确位置)。两者结合给出精确世界坐标。

**不变量**:分针永远在 [0, 60)。如果分针跑到 60,必须进位到时针(时针 + 1,分针归零)。否则时钟乱套。

**Day 032 的 bug**:Casey 写了 WorldPos 但没写"进位"逻辑。offset 可能跑到 -5 或 70,玩家位置看起来错乱(就像分针指 70 的时钟)。

### 严谨定义:WorldPos 不变量

**不变量**(invariant):程序状态必须满足的条件。对 WorldPos:

```
invariant: offset.x ∈ [0, TILE_SIZE), offset.y ∈ [0, TILE_SIZE)
```

**所有操作后必须保持不变量**。例:

- `WorldPos::new(tile_x, tile_y, offset)`:构造时必须 normalize
- `world_pos += displacement`:加位移后必须 normalize
- `world_pos.x = 5.0`:**违反不变量**(直接改字段,绕过 normalize)

**Rust 的解决**:字段 private,只通过方法访问。方法保证不变量。

```rust
pub struct WorldPos {
    tile_x: i32,    // private
    tile_y: i32,
    offset: Vec2,
}

impl WorldPos {
    pub fn new(tile_x: i32, tile_y: i32, offset: Vec2) -> Self {
        let mut p = Self { tile_x, tile_y, offset };
        p.normalize();
        p
    }

    pub fn tile_x(&self) -> i32 { self.tile_x }
    pub fn offset(&self) -> Vec2 { self.offset }

    pub fn add(&mut self, disp: Vec2) {
        self.offset += disp;
        self.normalize();
    }

    fn normalize(&mut self) {
        // x 方向
        while self.offset.x < 0.0 {
            self.offset.x += TILE_SIZE as f32;
            self.tile_x -= 1;
        }
        while self.offset.x >= TILE_SIZE as f32 {
            self.offset.x -= TILE_SIZE as f32;
            self.tile_x += 1;
        }
        // y 方向(同理)
        while self.offset.y < 0.0 {
            self.offset.y += TILE_SIZE as f32;
            self.tile_y -= 1;
        }
        while self.offset.y >= TILE_SIZE as f32 {
            self.offset.y -= TILE_SIZE as f32;
            self.tile_y += 1;
        }
    }
}
```

**外部代码**:

```rust
let mut pos = WorldPos::new(5, 5, Vec2::new(10.0, 10.0));
pos.add(Vec2::new(30.0, 0.0));  // offset.x 跨过 TILE_SIZE,自动进位
// 现在 tile_x = 6, offset.x = 8.0(10 + 30 = 40, 40 - 32 = 8)

// 不允许直接改字段(编译报错):
// pos.offset.x = 100.0;  // error: field `offset` of struct `WorldPos` is private
```

### 调试方法论详解

Casey 在视频里演示的调试流程:

**第 1 步:重现 bug**

找到 bug 后,第一步是**可靠重现**。如果 bug 随机出现,你永远不知道修复有没有效。

Casey 找到稳定重现路径:"玩家走到 tile 边界并按右键移动 1 像素"——必现 bug。

**第 2 步:可视化内部状态**

把不可见的内部状态(变量值)显示到屏幕。Casey 用 debug overlay:

```rust
// 渲染调试信息
fn render_debug(state: &GameState, buf: &mut RenderBuf) {
    let text = format!(
        "Player tile=({}, {}) offset=({:.1}, {:.1})",
        state.player.pos.tile_x,
        state.player.pos.tile_y,
        state.player.pos.offset.x,
        state.player.pos.offset.y,
    );
    buf.draw_text(10, 10, &text, WHITE);
}
```

观察 offset 实时值,看到跨边界时 offset 从 31 跳到 -1(应该是 0 跨到下一 tile 的 0),bug 可见。

**第 3 步:形成假设**

"offset 在跨边界时变成负数,而不是进位到下一 tile。"

**第 4 步:验证假设**

加 assert 验证:

```rust
debug_assert!(
    self.offset.x >= 0.0 && self.offset.x < TILE_SIZE as f32,
    "offset.x invariant violated: {}", self.offset.x
);
```

运行,看到 assert 触发——假设成立。

**第 5 步:定位 + 修复**

Day 032 的 WorldPos::add 没调 normalize,所以 offset 没进位。加 normalize。

**第 6 步:防御再发生**

把 offset 设为 private,只通过方法访问。Rust 编译器保证不变量。

### Rust 类型系统防 bug

**类型系统**(type system)不只是检查"传 f32 给 i32"——它能表达**不变量**和**状态机**。

**例子 1:Private 字段 + 方法**

```rust
pub struct WorldPos {
    tile_x: i32,  // private
    tile_y: i32,
    offset: Vec2,
}

impl WorldPos {
    pub fn tile_x(&self) -> i32 { self.tile_x }
    // ... 所有访问通过方法
}
```

外部不能直接改字段,只能通过方法(方法保证不变量)。

**例子 2:Newtype 模式**

```rust
pub struct NormalizedVec2(Vec2);  // 包装类型,承诺已归一化

impl NormalizedVec2 {
    pub fn new(v: Vec2) -> Option<Self> {
        let len = v.length();
        if len > 1e-6 {
            Some(Self(v * (1.0 / len)))
        } else {
            None
        }
    }
    pub fn get(&self) -> Vec2 { self.0 }
}
```

`NormalizedVec2` 只能通过 `new` 构造,构造时归一化。**所有 NormalizedVec2 都是单位向量**,编译期保证。函数签名 `fn reflect(v: Vec2, n: NormalizedVec2)` 表达"n 必须是单位向量"。

**例子 3:状态机 enum**

```rust
pub enum ConnectionState {
    Disconnected,
    Connecting { since: std::time::Instant },
    Connected { session_id: u64 },
    Error { code: u32 },
}

fn handle(state: &ConnectionState) {
    match state {
        ConnectionState::Disconnected => { /* 只能调 connect */ }
        ConnectionState::Connecting { since } => { /* 等待 */ }
        ConnectionState::Connected { session_id } => { /* 发数据 */ }
        ConnectionState::Error { code } => { /* 处理错误 */ }
    }
}
```

match 强制穷尽所有状态,每个状态有自己的字段。编译期保证不会"在 Disconnected 状态发数据"(字段不存在)。

**Rust 的类型系统比 C 强很多**。Casey 在 C 里靠纪律保证不变量,Rust 编译器帮你抓。这是为什么用 Rust 写游戏比 C 安全。

### 调试工具对比

| 工具 | 优点 | 缺点 | 何时用 |
|---|---|---|---|
| printf / println! | 简单,直接 | 难看大量数据 | 第一时间尝试 |
| Debug overlay | 直观,实时 | 要写 UI 代码 | 复杂状态 |
| assert! / debug_assert! | 编译期 / 运行期自动 | 触发就 panic | 不变量检查 |
| gdb / lldb | 强大,断点 / 单步 | 学习曲线 | 难重现 bug |
| valgrind | 内存错误 | 慢 20-100x | 内存问题 |
| perf | 性能分析 | 不抓逻辑 bug | 性能优化 |

游戏开发用 printf + debug overlay 解决 80% bug,gdb 解决 15%,剩下 5% 用 valgrind / perf。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏行业的调试工具:

**1. 内嵌 debug overlay**:游戏运行时显示变量、FPS、内存、碰撞框等。Casey 在 Day 176+ 详细做。

**2. Imgui / egui**:立即模式 GUI,做调试面板。Rust 的 egui 是主流。

**3. Replay 系统**:记录每帧输入,可以"回放"bug 触发过程。

**4. 单元测试 + 集成测试**:Rust 的 cargo test 自动化。

**5. 性能分析**:perf、Tracy(Rust 游戏专用 profiler)、superluminal。

#### 不变量的工程实践

游戏代码里到处是不变量:

- 玩家 HP ∈ [0, MAX_HP]
- 玩家速度 |v| ≤ MAX_SPEED
- 玩家位置不能在墙内
- WorldPos.offset ∈ [0, TILE_SIZE)
- Inventory.items 数量 ≤ MAX_STACK

**Rust 风格**:用类型系统强制不变量(private 字段、newtype、enum)。**C 风格**:靠注释 + 纪律。Casey 在 C 里用大量注释和 assert,但他承认"这是 C 的弱点"。

### 3.2 · 🎨 图形学视角

图形学里的"规范坐标"(canonical coordinates):

**1. UV 坐标**:纹理坐标在 [0, 1]² 内。如果 UV 超出,wrap / clamp / mirror 处理。

**2. NDC**(Normalized Device Coordinates):OpenGL 投影后顶点在 [-1, 1]³。超出 = 裁剪。

**3. Viewport 坐标**:屏幕像素,在 [0, screen_width] × [0, screen_height]。

每个坐标系都有自己的"不变量"(范围)。坐标变换链(model → world → view → projection → viewport)中任一环节出错,渲染就乱。

**经典 bug**:UV 没归一化,纹理显示偏移。Casey 在 Day 237 渲染纹理时会遇到类似问题。

### 3.4 · 🦀 Rust 生态视角

#### Rust 的不变量表达

**1. Private 字段 + builder 方法**

```rust
pub struct WorldPos {
    tile_x: i32,
    tile_y: i32,
    offset: Vec2,
}

impl WorldPos {
    pub fn new(...) -> Self { /* normalize */ }
    pub fn add(&mut self, ...) { /* normalize */ }
}
```

外部只能通过方法,方法保证不变量。

**2. debug_assert!**

```rust
fn expensive_op(x: f32) -> f32 {
    debug_assert!(x >= 0.0, "x must be non-negative");
    x.sqrt()
}
```

`debug_assert!` 在 debug 模式检查,release 模式跳过(零开销)。开发期抓 bug,生产期不付钱。

**3. assert!**

```rust
fn divide(a: f32, b: f32) -> f32 {
    assert!(b.abs() > 1e-6, "division by zero");
    a / b
}
```

`assert!` 在 debug 和 release 都检查。永不违反的不变量用 assert,可能偶尔违反的(性能敏感)用 debug_assert。

**4. 类型状态模式**(typestate pattern)

```rust
pub struct Uninitialized;
pub struct Connected { session: u64 }
pub struct Disconnected;

pub struct Connection<State> {
    state: State,
}

impl Connection<Uninitialized> {
    pub fn connect(self) -> Connection<Connected> {
        Connection { state: Connected { session: 42 } }
    }
}

impl Connection<Connected> {
    pub fn send(&self, data: &[u8]) { /* 发数据 */ }
    pub fn disconnect(self) -> Connection<Disconnected> {
        Connection { state: Disconnected }
    }
}
```

`Connection<Uninitialized>` 没有 send 方法,编译期禁止。`Connection<Connected>` 才能调 send。

这是 Rust 类型系统的极致表达——把状态机编码到类型里。

#### 测试驱动调试

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_offset_stays_in_range() {
        let mut pos = WorldPos::new(5, 5, Vec2::new(0.0, 0.0));
        // 加大位移,应该跨多个 tile
        pos.add(Vec2::new(100.0, 0.0));
        assert!(pos.offset().x >= 0.0 && pos.offset().x < TILE_SIZE as f32);
        assert!(pos.offset().y >= 0.0 && pos.offset().y < TILE_SIZE as f32);
    }

    #[test]
    fn test_negative_offset_wraps() {
        let mut pos = WorldPos::new(5, 5, Vec2::new(0.0, 0.0));
        pos.add(Vec2::new(-50.0, 0.0));  // 向左跨 tile
        assert!(pos.offset().x >= 0.0);  // 仍然 >= 0
        assert!(pos.tile_x() < 5);  // tile_x 减小
    }

    #[test]
    fn test_round_trip() {
        // 加位移再减,应该回到原位
        let mut pos = WorldPos::new(5, 5, Vec2::new(10.0, 10.0));
        pos.add(Vec2::new(100.0, 50.0));
        pos.add(Vec2::new(-100.0, -50.0));
        assert_eq!(pos.tile_x(), 5);
        assert_eq!(pos.tile_y(), 5);
        assert!((pos.offset().x - 10.0).abs() < 1e-6);
        assert!((pos.offset().y - 10.0).abs() < 1e-6);
    }
}
```

测试覆盖:正常 add、负位移、往返。这种"往返测试"特别能抓累积误差 bug。

## 5 · 对照与变奏

### 调试方法论的历史演化

**1970s**:printf debugging。所有 bug 都用 print 解决。

**1980s**:gdb 出现,断点 / 单步调试。

**1990s**:assert 宏普及。设计契约(Eiffel 语言)流行。

**2000s**:单元测试 / TDD 流行。Bug 应该在写代码时预防,不是事后调。

**2010s**:Replay / 时间旅行调试(rr debugger)。可以"倒着"调试。

**2020s**:AI 辅助调试(Copilot、Claude)。AI 看代码猜 bug。

Casey 用 1990s 风格(printf + assert),因为最可靠、最直接。AI 调试是辅助,不能替代理解。

### 类型系统的强度对比

| 语言 | 类型系统 | 不变量表达 |
|---|---|---|
| C | 弱(只检查基本类型) | 靠注释 + assert |
| C++ | 中(模板 + RAII) | 靠 RAII + 运行时检查 |
| Java | 中(接口 + 泛型) | 靠接口 + 异常 |
| Rust | 强(所有权 + trait + enum) | private + 方法 + newtype + typestate |
| Haskell | 极强(类型即文档) | phantom types、monads |

Rust 在"实用"和"严格"之间找到了平衡。Haskell 更严格但学习曲线陡。

### 状态机的不同表达

**C / C++**:enum + 字段 + 运行时检查

```c
enum State { Disconnected, Connected };
struct Conn { enum State s; int session; };

void send(struct Conn* c) {
    if (c->s != Connected) {
        return;  // 运行时检查
    }
    // ...
}
```

**Rust**:enum + 带 payload + match 穷尽

```rust
enum State {
    Disconnected,
    Connected { session: u64 },
}

fn send(c: &State) {
    match c {
        State::Connected { session } => { /* 用 session */ },
        _ => {}  // 显式忽略其他
    }
}
```

match 强制处理所有状态,编译期保证。

**Haskell**:代数数据类型(ADT)

```haskell
data State = Disconnected | Connected Integer

send :: State -> IO ()
send (Connected s) = ...  -- 模式匹配
send _ = return ()
```

类型即文档,极强。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么把 WorldPos 的 offset 字段设为 private 能防止 Day 049 的 bug 再发生?如果字段是 public,即使有 normalize 方法,bug 还能出现吗?

**参考解答**:

**Private 字段 + 强制方法访问** = 类型系统保证不变量。外部代码不能直接写 `pos.offset.x = 100.0`(编译报错),只能通过 `pos.add(...)`(方法内部调 normalize)。

**Public 字段**:即使有 normalize 方法,程序员可能"忘记"调用。比如:

```rust
pub struct WorldPos {
    pub offset: Vec2,  // public
}

impl WorldPos {
    pub fn normalize(&mut self) { /* ... */ }
}

// 外部代码:
let mut pos = WorldPos::new(...);
pos.offset.x += 30.0;  // 直接改,绕过 normalize
// pos.normalize();    // 忘了!
// bug 重现
```

外部代码靠"程序员记得调 normalize"。这是**契约式编程**(design by contract)的弱点——契约在 doc 里,不在类型里。程序员失误 → bug。

**Private + 方法**:外部不能直接改字段。所有修改通过方法,方法保证不变量。这是**类型系统保证不变量**——契约在编译期,不在 doc。

**直觉**:private 把"必须做的"变成"唯一能做的"。外部没选择,bug 在编译期消除。

### Lv2 · 动手实践

**题**:在你的 HH Rust 项目里:

1. 实现 `WorldPos` 结构,字段 private
2. 提供 `new, add, tile_x(), tile_y(), offset() -> Vec2` 方法
3. `add` 内部调用 private `normalize`
4. 写测试覆盖 Lv1 提到的场景
5. **演示 bug**:故意在 `add` 里注释掉 `normalize`,测试应该失败(看到 offset 超出 [0, TILE_SIZE))

完成标准:测试通过。注释掉 normalize 后测试失败(演示 bug 重现)。

**参考解答**:

```rust
// src/world_pos.rs
use crate::math::Vec2;

pub const TILE_SIZE: i32 = 32;

#[derive(Debug, Clone, Copy)]
pub struct WorldPos {
    tile_x: i32,
    tile_y: i32,
    offset: Vec2,
}

impl WorldPos {
    pub fn new(tile_x: i32, tile_y: i32, offset: Vec2) -> Self {
        let mut p = Self { tile_x, tile_y, offset };
        p.normalize();
        p
    }

    pub fn tile_x(&self) -> i32 { self.tile_x }
    pub fn tile_y(&self) -> i32 { self.tile_y }
    pub fn offset(&self) -> Vec2 { self.offset }

    pub fn add(&mut self, displacement: Vec2) {
        self.offset += displacement;
        self.normalize();
    }

    fn normalize(&mut self) {
        let tile_size = TILE_SIZE as f32;
        while self.offset.x < 0.0 {
            self.offset.x += tile_size;
            self.tile_x -= 1;
        }
        while self.offset.x >= tile_size {
            self.offset.x -= tile_size;
            self.tile_x += 1;
        }
        while self.offset.y < 0.0 {
            self.offset.y += tile_size;
            self.tile_y -= 1;
        }
        while self.offset.y >= tile_size {
            self.offset.y -= tile_size;
            self.tile_y += 1;
        }
        debug_assert!(self.offset.x >= 0.0 && self.offset.x < tile_size);
        debug_assert!(self.offset.y >= 0.0 && self.offset.y < tile_size);
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_basic_normalize() {
        let pos = WorldPos::new(0, 0, Vec2::new(40.0, 0.0));
        assert_eq!(pos.tile_x(), 1);  // 40 进位
        assert!((pos.offset().x - 8.0).abs() < 1e-6);  // 40 - 32 = 8
    }

    #[test]
    fn test_negative_offset() {
        let mut pos = WorldPos::new(5, 5, Vec2::new(0.0, 0.0));
        pos.add(Vec2::new(-50.0, 0.0));  // 向左 50
        assert_eq!(pos.tile_x(), 3);  // 5 - 2 = 3(50 / 32 = 1 余 18, 但起点 offset=0
                                       // 加 -50 后 offset = -50,normalize 借 2 个 tile
                                       // -50 + 64 = 14, tile_x = 5 - 2 = 3)
        assert!((pos.offset().x - 14.0).abs() < 1e-6);
    }

    #[test]
    fn test_round_trip() {
        let mut pos = WorldPos::new(5, 5, Vec2::new(10.0, 10.0));
        pos.add(Vec2::new(100.0, 50.0));
        pos.add(Vec2::new(-100.0, -50.0));
        assert_eq!(pos.tile_x(), 5);
        assert_eq!(pos.tile_y(), 5);
        assert!((pos.offset().x - 10.0).abs() < 1e-6);
        assert!((pos.offset().y - 10.0).abs() < 1e-6);
    }

    #[test]
    fn test_invariant_maintained() {
        let mut pos = WorldPos::new(0, 0, Vec2::new(0.0, 0.0));
        // 反复加大位移
        for _ in 0..100 {
            pos.add(Vec2::new(50.0, -30.0));
        }
        // 不变量必须保持
        assert!(pos.offset().x >= 0.0 && pos.offset().x < TILE_SIZE as f32);
        assert!(pos.offset().y >= 0.0 && pos.offset().y < TILE_SIZE as f32);
    }
}
```

**测试 bug 重现**:在 `add` 里临时注释掉 `self.normalize();`,运行测试,看到:

- `test_negative_offset` 失败(offset.x = -50,不在 [0, 32))
- `test_round_trip` 失败(offset 没进位,tile_x 不对)
- `test_invariant_maintained` 失败(debug_assert 触发)

把 normalize 加回来,测试通过。

### Lv3 · 迁移设计

**题**:你在做**血量系统**(Hitpoints),不变量:

- HP ∈ [0, MAX_HP]
- 死亡状态 = (HP == 0)
- HP 减到 0 时触发 on_death 事件

设计:`Hitpoints` 结构,private 字段,方法保证不变量。**不要用 i32 直接表示 HP**(容易写出 hp = -5 这种 bug)。

要求:

1. `Hitpoints::new(max_hp: u32) -> Self`
2. `current(&self) -> u32`
3. `take_damage(&mut self, amount: u32) -> Option<DeathEvent>`(返回死亡事件)
4. `heal(&mut self, amount: u32)`
5. 测试:HP 不会变负、过 max、伤害刚好致死触发事件、过度伤害不重复触发

**提示**:

- 用 saturating_sub 防止下溢:`hp.saturating_sub(amount)` 返回 0 而不是下溢
- 用 `Option<DeathEvent>` 表达"可能死也可能没死"
- 死亡事件可以是 struct,带死亡时间、杀手 ID 等

为什么这个练习有价值?因为游戏里"血量"是经典不变量场景。如果你用裸 i32,迟早写出 `hp = -5` 的 bug。用类型封装,编译期消除。

### Lv4 · 开源贡献

**题**:`slotmap` 是 Rust 的代际索引容器,GitHub: https://github.com/orlp/slotmap

```bash
gh repo clone orlp/slotmap
cd slotmap
grep -rn "fn insert\|invariant\|debug_assert" src/ | head
```

slotmap 的不变量:

- 每个 key 有版本号,旧的 key 不能访问已删除的 slot
- 内部 storage 不能有空 slot(除非被 free list 标记)

读 slotmap 的源码,看它怎么用 private + 方法保证不变量。**可能的贡献**:

- slotmap 的 doc 没明确说"为什么不能直接构造 KeyData",补一段
- slotmap 的 examples 里没有"展示代际索引防止 dangling reference"的对比 demo,加一个
- slotmap 的 tests 里没覆盖"reserve 后旧 key 仍然有效",补测试

写下 PR 描述:

```
标题:docs: explain why SlotMap key is opaque type
文件:src/lib.rs(SlotMap key 类型 doc)
动机:新手常尝试手动构造 KeyData,导致 invariant 破坏。
     slotmap 的 key 是 opaque,只能通过 insert/free 获得。
改动:加一段:
     "Keys returned by `insert` are opaque and must not be constructed

     where a freed slot is reused and a stale key would incorrectly
     access the new data."
```

### Troubleshooting

**问题 1**:`error: field `offset` of struct `WorldPos` is private`

原因:你在测试代码或外部代码直接访问了 private 字段。

修复:用 getter 方法 `pos.offset()` 而不是 `pos.offset`。

**问题 2**:debug_assert 触发,即使 normalize 已调用

原因:可能在 normalize 之外修改了字段(unsafe 或其他路径)。

修复:检查所有修改 offset 的代码路径,确保都经过 normalize。

**问题 3**:normalize 死循环

原因:while 循环条件写错,比如 `while offset >= TILE_SIZE` 但 TILE_SIZE = 0(除零或负数导致永不退出)。

修复:确认 TILE_SIZE > 0。或者用 `if offset >= TILE_SIZE { offset -= TILE_SIZE; tile_x += 1; }`(一次进位,不循环),前提是位移不太大。

**问题 4**:负位移让 tile_x 变成 i32 最小值,溢出

原因:加超大负位移(比如 -1000000),循环很多次,可能 tile_x 下溢。

修复:用 `div_euclid` 和 `rem_euclid` 一次性算进位:

```rust
let tile_size = TILE_SIZE as f32;
let dx = (self.offset.x / tile_size).floor() as i32;
self.offset.x -= dx as f32 * tile_size;
self.tile_x += dx;
```

这样无论位移多大,都一次算完,无循环。
