# Day 040 · 隐藏光标与全屏支持

> Day 026-39 你完成了 Phase 2 的核心:tile map + 碰撞 + 资产 + blit。Day 040 是 Phase 2 前 15 天的"收尾日"——加两个 OS 相关功能:**全屏**和**鼠标隐藏**。功能简单,但涉及 OS 特定行为(Win32 全屏 API)。Linux 上 Rust 的 winit crate 帮你处理跨平台。Casey 这集讨论一个经典 OS 抽象问题:**Exclusive fullscreen vs Borderless fullscreen**。

## 0 · 为什么要有这一天

你做完渲染、碰撞、资产——游戏能玩了。但玩家在窗口模式下玩,体验有缺陷:

- **鼠标光标**:玩游戏时鼠标光标在画面上飘,挡视野,显得"业余"
- **窗口边框**:标题栏、关闭按钮占了屏幕空间,沉浸感弱
- **任务栏**:底部 Windows 任务栏 / Linux 桌面环境 panel 仍然可见,玩家分心

**全屏 + 隐藏鼠标**解决这些。看起来简单(`set_fullscreen(true)` / `set_cursor_visible(false)`),但有几个**非平凡决策**:

**决策 1:Exclusive vs Borderless 全屏**

- **Exclusive**(独占):改变显示器分辨率,OS 桌面暂停渲染,性能最好,但 Alt+Tab 慢(2-3 秒)
- **Borderless**(无边框窗口):窗口没标题栏,占满屏幕,桌面继续渲染。Alt+Tab 即时

老游戏(CS 1.6)用 Exclusive,因为那时性能差,每帧计数。**现代游戏 90% 用 Borderless**——Alt+Tab 流畅、多显示器友好、无 mode switch 闪烁。Exclusive 只在电竞(追求最低延迟)用。

**决策 2:鼠标隐藏时机**

- **永远隐藏**:游戏内永远不显示鼠标(纯键盘 / 手柄游戏,如空洞骑士)
- **隐藏 + 按需显示**:游戏中隐藏,菜单 / 暂停时显示(大部分游戏)
- **永远显示**:鼠标是主要输入(策略游戏、模拟器)

Casey 选"游戏中隐藏,菜单时显示"——适合大多数 2D 游戏。

**决策 3:分辨率**

- 全屏分辨率 = 桌面分辨率(简单,主流)
- 全屏分辨率 = 游戏内部分辨率(可不同,如 720p 游戏在 1080p 屏幕上跑)
- 全屏 + 拉伸(老游戏 4:3 比例在现代 16:9 屏幕上拉)

Casey 这集保持简单:全屏 = 桌面分辨率,游戏内分辨率不变。

**决策 4:退出全屏怎么触发**

- Esc 键(经典)
- Alt+Enter(Windows 传统)
- F11(浏览器 / Linux 传统)
- 鼠标移动到屏幕顶部(现代化)

Casey 选 Alt+Enter。

Casey 这集做的事情:

1. Win32 全屏 API:`ChangeDisplaySettings`(Exclusive) / `WS_POPUP` 样式(Borderless)
2. 鼠标隐藏:`ShowCursor(FALSE)`
3. Alt+Enter 切换全屏
4. Rust 端用 `winit` 跨平台处理

心理锚点:看完这集,你应该能:

- 解释 Exclusive vs Borderless 全屏的差别
- 用 winit 切换全屏和隐藏鼠标
- 解释为什么现代游戏选 Borderless

如果你做不到,反复看 §2 的"两种全屏"和"winit 实现"部分。Day 200+ 加多显示器支持,Day 300+ 加 DPI 缩放,都基于这集的概念。

## 2 · 心智模型

### 类比:电影院 vs 家庭电视

**Exclusive 全屏像电影院**:

- 电影院看电影时,灯光暗(桌面暂停)
- 屏幕 = 整个视野
- 中途想看手机?先离场(Alt+Tab 慢)
- 性能最好(没干扰)

**Borderless 全屏像家庭电视全屏**:

- 全屏看电影,但屋里灯还开着(桌面继续渲染)
- 屏幕 = 整个电视,但你知道屋外世界还在
- 拿手机快(Alt+Tab 即时)
- 性能略低(桌面也在跑)

**窗口模式像在小屏幕看**:

- 边框占空间
- 周围是其他窗口
- 多任务友好

**游戏开发的选择**:大多数游戏提供"Borderless 全屏"和"窗口模式"两种,某些电竞游戏额外提供"Exclusive 全屏"。

### Win32 实现(Casey 用)

**Exclusive**(改变分辨率):

```c
DEVMODE devmode = {0};
devmode.dmSize = sizeof(DEVMODE);
devmode.dmPelsWidth = 1920;
devmode.dmPelsHeight = 1080;
devmode.dmBitsPerPel = 32;
devmode.dmFields = DM_PELSWIDTH | DM_PELSHEIGHT | DM_BITSPERPEL;
ChangeDisplaySettings(&devmode, CDS_FULLSCREEN);

// 窗口设为顶层 + 无边框
HWND hwnd = CreateWindowEx(
    WS_EX_TOPMOST,
    "HandmadeHeroWindowClass",
    "Handmade Hero",
    WS_POPUP | WS_VISIBLE,  // 无边框
    0, 0, 1920, 1080,
    NULL, NULL, hInstance, NULL);
```

**Borderless**(不改分辨率):

```c
// 直接创建无边框窗口,大小 = 屏幕大小
HWND hwnd = CreateWindowEx(
    0,
    "HandmadeHeroWindowClass",
    "Handmade Hero",
    WS_POPUP | WS_VISIBLE,  // 无边框
    0, 0, 1920, 1080,
    NULL, NULL, hInstance, NULL);
```

**鼠标隐藏**:

```c
ShowCursor(FALSE);  // 计数器 -1,0 以下隐藏
// 后续 ShowCursor(TRUE) 计数器 +1
```

`ShowCursor` 用计数器(不是 bool)——多次 `FALSE` 调用需要等量 `TRUE` 才显示。这是 Windows 怪癖。

### Rust + winit 跨平台

```rust
use winit::{
    event_loop::EventLoop,
    window::{Window, WindowBuilder, Fullscreen},
};

let event_loop = EventLoop::new();
let window = WindowBuilder::new()
    .with_title("Handmade Hero")
    .build(&event_loop)
    .unwrap();

// 切换全屏(Borderless)
window.set_fullscreen(Some(Fullscreen::Borderless(None)));

// 退出全屏
window.set_fullscreen(None);

// 隐藏鼠标
window.set_cursor_visible(false);

// 显示鼠标
window.set_cursor_visible(true);
```

**`Fullscreen::Borderless(None)` 的 None**:

- `None` = 让 winit / OS 自动选哪个显示器
- `Some(monitor_handle)` = 指定显示器(多显示器时)

**`Fullscreen::Exclusive(video_mode)`**:Exclusive 全屏,需要指定 video mode(分辨率 + 刷新率)。

### 全屏切换逻辑

```rust
use winit::event::{Event, WindowEvent, KeyboardInput, VirtualKeyCode, ElementState};

let mut is_fullscreen = false;

event_loop.run(move |event, _, control_flow| {
    match event {
        Event::WindowEvent { event: WindowEvent::KeyboardInput {
            input: KeyboardInput {
                state: ElementState::Pressed,
                virtual_keycode: Some(VirtualKeyCode::Return),
                ..
            },
            ..
        }, .. } => {
            // Alt+Enter 切换全屏(简化:这里只检测 Enter,实际要检测 Alt 修饰键)
            is_fullscreen = !is_fullscreen;
            if is_fullscreen {
                window.set_fullscreen(Some(Fullscreen::Borderless(None)));
                window.set_cursor_visible(false);
            } else {
                window.set_fullscreen(None);
                window.set_cursor_visible(true);
            }
        }
        _ => {}
    }
});
```

**关键细节**:

- 检测 Alt+Enter:需要看 `mods.alt()`(winit 的 KeyboardInput 有 modifiers)
- 全屏切换时同步切换鼠标隐藏(用户体验一致)
- 某些 Linux DE 切换全屏会有 1-2 秒黑屏(Wayland compositor 重排)

### Wayland vs X11

Linux 有两种窗口协议:

**X11**(老,1980 年代):

- 客户端 - 服务器架构
- 客户端画像素,服务器合成
- 网络透明(可以远程跑 GUI)
- 但**架构老化**,性能 / 安全有局限

**Wayland**(新,2000 年代):

- 现代设计,合成器即显示服务器
- 性能更好(无 X 中间层)
- 安全更好(应用隔离)
- 但**生态迁移中**,部分老应用需要 XWayland 兼容层

**winit 自动选**:

```bash
# Arch Linux 默认 GNOME / KDE 都支持 Wayland
echo $XDG_SESSION_TYPE
# x11 或 wayland

# winit 会根据环境自动选 backend
# 强制 X11:
export WINIT_X11_SCALE=1
# 强制 Wayland(某些 winit 版本):
export WAYLAND_DISPLAY=wayland-0
```

### KDE Wayland 的 cursor bug

某些 KDE Plasma 5.27 之前版本,`set_cursor_visible(false)` 不生效——cursor 仍可见。这是 KWin(合成器)的 bug,不是 winit 问题。修复:升级 Plasma 到 5.27+。

类似 bug 各 DE 都有,Casey 在 HH 没深入(他用 Win32),Rust + winit 用户要意识到。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏开发圈对"全屏 + 鼠标"的共识:

**全屏选择**:

| 游戏 | 推荐 | 原因 |
|---|---|---|
| 单机 3A(Skyrim、Cyberpunk) | Borderless | 流畅 Alt+Tab |
| 电竞(CS:GO、Valorant) | Exclusive(可选) | 最低延迟 |
| 独立 2D(Celeste、Hollow Knight) | Borderless | 简单 |
| 网页游戏 | Fullscreen API | 浏览器原生 |
| 手机游戏 | 默认全屏 | 设备就是全屏 |

**鼠标显示策略**:

- 键盘 / 手柄游戏:游戏内隐藏
- 鼠标游戏(策略、模拟器):永远显示
- 混合(策略 + 即时战斗):游戏中显示,过场动画隐藏

**多显示器**:玩家有 2+ 显示器,Borderless 全屏只在主显示器。某些游戏支持"窗口在哪个显示器"(Settings 里选)。

### 3.2 · 🐧 Linux 系统编程视角

Linux 上"全屏"涉及多个组件:

```
应用 (你的游戏)
    ↓ 通过
winit / SDL / GLFW (窗口抽象)
    ↓ 调用
Wayland 协议 / X11 协议 (窗口协议)
    ↓ 通过
KWin / Mutter / Sway (合成器)
    ↓ 调用
DRM / KMS (内核显示)
    ↓ 控制
GPU + 显示器
```

**全屏的"链路"**:

- 应用说"我要全屏"(winit API)
- winit 翻译成 Wayland `xdg_toplevel.set_fullscreen` 或 X11 `_NET_WM_STATE_FULLSCREEN`
- 合成器接收,把窗口放到顶层,可能屏蔽 panel
- 合成器调 DRM 让窗口占满屏

**Exclusive 全屏在 Linux**:理论上需要 DRM 直接控制(绕过合成器),复杂。**KDE / GNOME 默认不让你这么做**(出于安全考虑)。所以 Linux 上"Exclusive 全屏"实际是 Borderless + compositor bypass。Valve 的 gamescope 是个例外——它本身就是合成器,可以"真 exclusive"。

**Linux 工具**:

```bash
# 看你的桌面环境
echo $XDG_CURRENT_DESKTOP
# GNOME / KDE / sway / ...

# 看窗口协议
echo $XDG_SESSION_TYPE
# x11 / wayland

# 强制 X11 启动某些程序
GDK_BACKEND=x11 your_program
QT_QPA_PLATFORM=xcb your_program

# 全屏切换的快捷键(各 DE):
# GNOME: F11 或 Super+Up
# KDE Plasma: F11 或 Meta+Up
# Sway: Meta+F

# 用 wmctrl 程序化控制窗口(老 X11 风格)
sudo pacman -S wmctrl
wmctrl -r "Handmade Hero" -b toggle,fullscreen
```

### 3.3 · 🦀 Rust 生态视角

Rust 跨平台窗口库选择:

**`winit`**(主流):

- 跨平台(Windows / macOS / Linux / Web / 移动)
- 仅事件 + 窗口管理,不含渲染
- Bevy / gfx-rs / wgpu 都基于 winit
- Casey HH Rust 翻译用 winit

**`sdl2`**(老牌):

- 跨平台
- 包含窗口 + 输入 + 音频 + 图形
- C 库 + Rust binding
- 比 winit 重

**`glfw`**(经典):

- 跨平台
- 主要为 OpenGL 设计
- C 库 + Rust binding
- 老化

**`minifb`**(极简):

- 跨平台
- 极简:窗口 + framebuffer 显示
- 适合教学(无 GPU 加速)
- HH Phase 1 可能用这个

**`tao`**(winit fork):

- tao 是 winit 的 fork,由 tao company 维护
- 修复 winit 的一些 bug
- Tauri 用 tao

**Casey HH Rust 翻译推荐**:winit(主流,Bevy 用)。

**Rust + winit 的全屏模式**:

```rust
use winit::window::Fullscreen;

// Borderless
window.set_fullscreen(Some(Fullscreen::Borderless(None)));

// Exclusive(需要指定 video mode)
let monitor = event_loop.primary_monitor().unwrap();
let modes = monitor.video_modes();
let mode = modes.find(|m| m.size().width == 1920 && m.size().height == 1080).unwrap();
window.set_fullscreen(Some(Fullscreen::Exclusive(mode)));

// 退出
window.set_fullscreen(None);
```

### 3.4 · 操作系统视角

不同 OS 的"全屏"概念:

**Windows**:

- Exclusive:ChangeDisplaySettings + WS_POPUP
- Borderless:WS_POPUP + 大小 = 屏幕大小
- F11 全屏(部分应用)

**macOS**:

- "Native fullscreen":绿色按钮 + 独立空间
- "Windowed fullscreen"(Borderless):隐藏 dock + menu bar,但窗口在主空间
- Safari / Preview 用前者,iTerm2 / VS Code 可选

**Linux**:

- Wayland:xdg_toplevel.set_fullscreen
- X11:_NET_WM_STATE_FULLSCREEN
- 各 DE 实现略不同

**Web**:

- Fullscreen API:`element.requestFullscreen()`
- 浏览器要求用户手势触发(防滥用)
- Esc 退出

winit 抽象这些差异,你写一份代码全平台跑。

### 全屏的演化

- **1980s**: DOS 游戏 = 默认全屏(没有窗口概念)
- **1990s**:Windows 95 引入窗口,游戏才需要"切全屏"
- **2000s**:多显示器普及,Exclusive 全屏遇到多显示器问题
- **2010s**:Borderless 兴起,解决 Alt+Tab 慢
- **2020s**:HDR + 高刷新率 + 自适应同步,全屏更复杂

Casey HH Day 040 演示的是 2010s+ 主流做法(Borderless)。

### 多显示器的复杂性

现代玩家有 2+ 显示器,引入新问题:

- **全屏在哪个显示器**:主显示器 vs 玩家选择
- **Alt+Tab 后焦点**:全屏应用应该 yield 焦点给其他显示器
- **跨显示器拖动**:从窗口到全屏的过渡
- **DPI 缩放**:每个显示器 DPI 不同

Casey Day 040 假设单显示器,Day 200+ 加多显示器支持。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:现代游戏 90% 用 Borderless 全屏,不用 Exclusive。为什么?Exclusive 性能更好不是吗?

**参考解答**:**Exclusive 性能略好(2-5%),但用户体验差得多**。

**Borderless 的优势**:

1. **Alt+Tab 流畅**:Exclusive 切换要 2-3 秒(切换分辨率、OS 桌面恢复),Borderless 瞬间
2. **多显示器友好**:Exclusive 在主显示器,其他显示器被锁;Borderless 让其他显示器正常工作
3. **无 mode switch 闪烁**:Exclusive 切换时屏幕黑 1-2 秒,Borderless 无缝
4. **流媒体友好**:直播 / 录屏软件(OBS)在 Borderless 下捕获更顺
5. **错误恢复**:Exclusive 模式崩溃容易留下错分辨率(需要重启),Borderless 不影响桌面

**Exclusive 的优势**(什么时候值得):

1. **延迟**:减少 1-2 帧(compositor 不参与),电竞有意义
2. **HDR**:某些 OS 的 HDR 只在 Exclusive 模式工作
3. **特殊刷新率**:G-Sync / FreeSync 某些功能要 Exclusive

CS:GO / Valorant 等电竞游戏提供 Exclusive 选项给职业玩家。**主流 3A 游戏(Skyrim、Cyberpunk)默认 Borderless**。

### Lv2 · 动手实践

**题**:用 winit 写一个最小的全屏切换 demo。要求:

1. 创建一个 800×600 窗口
2. 按 F11 切换全屏(Borderless)
3. 全屏时隐藏鼠标,退出时显示
4. Esc 退出程序

完成标准:跑起来能正常切换全屏,鼠标显示 / 隐藏正确。

**参考解答**:

```rust
// src/main.rs
// cargo new --bin fullscreen_demo && cd fullscreen_demo
// Cargo.toml: winit = "0.29"

use winit::{
    event::{Event, WindowEvent, KeyboardInput, ElementState, VirtualKeyCode},
    event_loop::EventLoop,
    window::{Window, WindowBuilder, Fullscreen},
```

### Rust 完整可跑示例

把 Lv2 扩展,加更多功能:

```rust
// src/main.rs
// cargo new --bin fullscreen_demo && cd fullscreen_demo

use winit::{
    event::{Event, WindowEvent, KeyboardInput, ElementState, VirtualKeyCode, ModifiersState},
    event_loop::EventLoop,
    window::{Window, WindowBuilder, Fullscreen},
    dpi::PhysicalSize,
};

fn main() {
    let event_loop = EventLoop::new();

    let window = WindowBuilder::new()
        .with_title("Fullscreen Demo (F11 / Alt+Enter / Esc)")
        .with_inner_size(winit::dpi::LogicalSize::new(800, 600))
        .build(&event_loop)
        .unwrap();

    let mut is_fullscreen = false;
    let mut modifiers = ModifiersState::empty();

    event_loop.run(move |event, _, control_flow| {
        control_flow.set_wait();

        match event {
            Event::WindowEvent { event: WindowEvent::ModifiersChanged(new_mods), .. } => {
                modifiers = new_mods;
            }
            Event::WindowEvent { event: WindowEvent::KeyboardInput {
                input: KeyboardInput {
                    state: ElementState::Pressed,
                    virtual_keycode: Some(key),
                    ..
                }, ..
            }, .. } => {
                let alt_enter = modifiers.alt() && key == VirtualKeyCode::Return;
                let f11 = key == VirtualKeyCode::F11;
                let escape = key == VirtualKeyCode::Escape;

                if alt_enter || f11 {
                    is_fullscreen = !is_fullscreen;
                    if is_fullscreen {
                        window.set_fullscreen(Some(Fullscreen::Borderless(None)));
                        window.set_cursor_visible(false);
                        let monitor = window.current_monitor().unwrap();
                        println!("Entered fullscreen on {:?}", monitor.name());
                    } else {
                        window.set_fullscreen(None);
                        window.set_cursor_visible(true);
                        println!("Exited fullscreen");
                    }
                } else if escape {
                    if is_fullscreen {
                        // Esc 先退出全屏
                        is_fullscreen = false;
                        window.set_fullscreen(None);
                        window.set_cursor_visible(true);
                        println!("Exited fullscreen (Esc)");
                    } else {
                        // 再按 Esc 退出程序
                        println!("Exiting...");
                        control_flow.set_exit();
                    }
                }
            }
            Event::WindowEvent { event: WindowEvent::Resized(size), .. } => {
                println!("Window resized to {}x{}", size.width, size.height);
            }
            Event::WindowEvent { event: WindowEvent::CloseRequested, .. } => {
                control_flow.set_exit();
            }
            _ => {}
        }
    });
}
```
