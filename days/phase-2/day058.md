# Day 058 · 空间划分三用:碰撞 / 视线 / 渲染剔除

> 昨天 Casey 搭了空间网格,但只用在了玩家碰撞上。今天他一口气把同一个抽象用到了三件事——AI 视线判断、渲染剔除、批量碰撞——验证"好抽象能复用 N 次"的工程美学。

## 0 · 为什么要有这一天

抽象的价值不在它**能做什么**,而在它**被复用了几次**。

举个反例:你写了个 `sort_player_inventory` 函数,只能给玩家背包排序。这个函数能做什么?——只这一件事。它的价值就是 1。

正例:你写了个 `quicksort<T: Ord>(arr: &mut [T])` 函数,能排任何有序类型。它的价值是 N(被调用 N 次)。

昨天的空间网格(SpatialGrid)就是这种"高复用抽象"。它的本质是:

> 给我一个位置,我告诉你"附近有哪些 entity ID"。

只要你的问题能表达成"我在 X 位置,需要附近的 entity",SpatialGrid 就能帮。

Casey 今天证明了这一点:他用同一个 grid 解决了三个看起来不同的问题。仔细一看,**这三个问题在抽象层是同一件事**——"我有一个查询点 / 查询区域,需要附近的 entity"。

具体:

| 问题 | 查询主体 | 用 SpatialGrid 怎么做 |
|---|---|---|
| 玩家撞墙吗 | 玩家位置 | `query_nearby(player.pos)`,对候选做 Minkowski |
| 怪能看见玩家吗 | 怪到玩家的线段 | 查"线段穿过的格子",对每格的墙做线段相交(Day 048) |
| 哪些 entity 在屏幕上 | 屏幕四角覆盖的格子 | 算屏幕 AABB 覆盖哪些 cell,只查这些 cell |

读完今天,你会感受到一种工程美感:**抽象不是越多越好,而是越少越锋利**。Casey 用一个 SpatialGrid 替换了三种潜在的专用数据结构(碰撞 grid / 视线 grid / 渲染 grid)。维护成本降到 1/3。

心理锚点:
- 看完今天你能说出"渲染剔除"和"碰撞 broadphase"在抽象上为什么是同一件事
- 你能动手把 SpatialGrid 应用到第 4 个用例(比如"声音衰减只对附近 entity 播")而不重新发明轮子
- 你理解了"全量重建 vs 增量更新"的权衡

如果你卡在"为什么这三个用例能共用一个 grid",你还没看清它们的共同抽象。回去重读 §2.2。

## 2 · 心智模型

### 2.1 类比:便利店货架

想象一个便利店,有几千种商品。三种员工需要"找商品":

- **理货员**(碰撞):"我要找到 A 货架附近的商品,把它们摆齐。"
- **保安**(视线):"我要看看从门口能不能看到收银台,中间有没有挡视线的大货架。"
- **盘点员**(渲染):"我要看现在顾客视野里(从门口看进去)有哪些商品,只数这些。"

如果三个员工各写一本"商品查找手册",你维护三本。如果有一个通用的"商品按位置索引"系统(就是货架编号 + 货架地图),三个员工都用它,你只维护一份。

SpatialGrid 就是这份"商品位置索引"。它不关心"用来干嘛",只回答"这个位置附近有什么"。

### 2.2 严谨:三个用例的统一抽象

把三个用例写成同一签名:

```rust
impl SpatialGrid {
    /// 给我一个位置 / 一个区域,返回附近的 entity ID
    fn query_nearby(&self, pos: Vec2) -> Vec<EntityId>;  // 点查询
    fn query_in_rect(&self, rect: Aabb) -> Vec<EntityId>;  // 矩形查询
    fn query_along_segment(&self, a: Vec2, b: Vec2) -> Vec<EntityId>;  // 线段查询
}
```

每个查询"用合适的方式"扫格子:

- **点查询**:9 个邻居(昨天做过)
- **矩形查询**:算矩形覆盖的所有格子,逐个查
- **线段查询**:算线段穿过的所有格子(Bresenham 类算法),逐个查

三个查询返回的都是 `Vec<EntityId>`,后续处理不同:

```rust
// 用例 1:玩家碰撞
for id in grid.query_nearby(player.pos) {
    if minkowski_collide(player, entities[id]) { resolve(...); }
}

// 用例 2:怪看玩家
let mut blocked = false;
for id in grid.query_along_segment(monster.pos, player.pos) {
    if entities[id].kind == Wall && segment_intersects_aabb(monster.pos, player.pos, entities[id]) {
        blocked = true; break;
    }
}

// 用例 3:渲染剔除
let visible_rect = camera.world_aabb_from_screen();
for id in grid.query_in_rect(visible_rect) {
    draw(entities[id]);
}
```

**关键洞察**:三个用例的区别在"查询形状"(点 / 线段 / 矩形)和"对结果做什么"(Minkowski / 线段相交 / 渲染),**不在 grid 本身**。grid 是稳定的内核,查询形状是参数。

### 2.3 矩形查询:覆盖多个格子

```rust
impl SpatialGrid {
    fn query_in_rect(&self, rect: Aabb) -> Vec<EntityId> {
        // rect 的最小 / 最大 cell 坐标
        let (min_cx, min_cy) = self.cell_coord(rect.min);
        let (max_cx, max_cy) = self.cell_coord(rect.max);
        let mut result = Vec::new();
        for cx in min_cx..=max_cx {
            for cy in min_cy..=max_cy {
                if let Some(ids) = self.cells.get(&(cx, cy)) {
                    result.extend_from_slice(ids);
                }
            }
        }
        result
    }
}
```

举例:屏幕 1280×720,cell_size=16。屏幕覆盖 80×45 = 3600 个格子。每个格子 ~1 个 entity,共 ~3600 个查询。**仍然比扫 5000 个 entity 快**,因为 hash 查询有 cache locality(连续 cell 坐标)。

矩形查询的常见用法:
- **渲染剔除**:算"相机能看到的世界矩形",只画这个矩形内的 entity
- **AoE 攻击**:火球爆炸,影响半径 R 内的所有 entity。R 算成矩形查询
- **声音传播**:某点发出声音,影响 R 内的 entity

### 2.4 线段查询:沿直线找 entity

这是最有趣的查询。Casey 用它判断"怪物能不能看见玩家"。

朴素想法:在 (a, b) 线段上每隔 1 像素采样一个点,查那个点的格子。但这样要么漏(墙太薄),要么慢(步长太小)。

更好的做法:**Bresenham 算法**遍历"线段穿过的格子":

```rust
impl SpatialGrid {
    fn query_along_segment(&self, a: Vec2, b: Vec2) -> Vec<EntityId> {
        // 用 DDA(Digital Differential Analyzer)算法遍历线段穿过的格子
        let (mut cx, mut cy) = self.cell_coord(a);
        let (end_cx, end_cy) = self.cell_coord(b);
        let dx = b.x - a.x;
        let dy = b.y - a.y;
        let step_x = if dx > 0.0 { 1 } else if dx < 0.0 { -1 } else { 0 };
        let step_y = if dy > 0.0 { 1 } else if dy < 0.0 { -1 } else { 0 };
        // tMaxX / tDeltaX 是"光线行进"算法的参数
        let t_delta_x = (self.cell_size / dx.abs()).max(1e30);
        let t_delta_y = (self.cell_size / dy.abs()).max(1e30);
        let mut t_max_x = ((cx as f32 + 0.5) * self.cell_size - a.x) / dx;
        let mut t_max_y = ((cy as f32 + 0.5) * self.cell_size - a.y) / dy;

        let mut result = Vec::new();
        if let Some(ids) = self.cells.get(&(cx, cy)) {
            result.extend_from_slice(ids);
        }
        while (cx, cy) != (end_cx, end_cy) {
            if t_max_x < t_max_y {
                t_max_x += t_delta_x;
                cx += step_x;
            } else {
                t_max_y += t_delta_y;
                cy += step_y;
            }
            if let Some(ids) = self.cells.get(&(cx, cy)) {
                result.extend_from_slice(ids);
            }
            // 安全限制:不超过 1000 步(防止 bug 死循环)
            if result.len() > 10000 { break; }
        }
        result
    }
}
```

**算法直觉**:想象光从 a 沿 dx,dy 方向前进。每次"穿过一条 cell 边界",记录新进入的 cell。tMaxX 是"水平方向下一次穿边界的 t 值",tMaxY 是垂直。哪个小先穿哪个。

这个算法就是 **Amanatides-Woo voxel traversal**(1987 年 SIGGRAPH 论文),GPU raymarching 和体素光线追踪都用到。Casey 在第 58 集简短实现,没多解释——我们今天补上。

### 2.5 渲染剔除:为什么这是大幅优化

Casey 重构前每帧渲染:

```
for e in &entities { draw(e); }  // 5000 次 draw call
```

5000 次 draw call,每个 sprite 64×64 像素,fillrate 浪费(屏幕只 1280×720 = 921600 像素,5000 sprite 总像素 = 5000 × 4096 = 20M 像素,远超屏幕)。CPU 端每次 draw 还要走"设置 transform → 上传 sprite → 调 blit"。

剔除后:

```
let visible = grid.query_in_rect(camera.visible_rect());  // ~100 个
for id in visible { draw(entities[id]); }
```

100 次 draw call,fillrate 不浪费。**50× 优化**。

更深层:**渲染剔除不是性能优化,是正确性**。如果你不剔除,某些 alpha blending 的 sprite 会画在屏幕外,但因为浮点精度可能溢出到屏幕内,产生闪烁 bug。剔除从根上消灭这种 bug。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏引擎里这三个用例都重要,但**渲染剔除**通常是性能瓶颈大头(尤其 3D):

- **2D 游戏**:玩家碰撞 + AoE 用 grid,渲染剔除用 camera AABB 查 grid(今天做的)
- **3D 游戏**:渲染剔除叫 **frustum culling**(剔除视野外的物体)+ **occlusion culling**(剔除被前面物体挡住的)。这两件事都用 BVH(层次包围盒)。Phase 6+ 会讲
- **MMO / 大世界**:网格化 chunk,每个 chunk 独立模拟 / 渲染 / 加载(叫做 **level streaming**)

**AI 视线**是 stealth 游戏(合金装备、Hitman)的核心机制。这些游戏的 NPC AI 大量用 line-of-sight 查询,每秒几千次。空间网格是必备。

### 3.2 · 🎨 图形学视角

渲染管线里"剔除"贯穿始终:

| 阶段 | 剔除对象 | 算法 |
|---|---|---|
| Application(应用层) | 屏幕 / 视锥外的物体 | Spatial grid / BVH(today) |
| Geometry(几何层) | 三角形 vs 视锥 | Frustum culling(逐三角形) |
| Rasterization(光栅化) | 视口外的 fragment | Scissor test / viewport |
| Pixel(像素层) | 被深度更小的覆盖 | Z-buffer(Day 250+) |
| Blending(混合) | alpha = 0 的 fragment | Alpha test |

每一层都有"剔除"——上一层过了下一层剔除更多。今天讲的是 Application 层的剔除,最粗粒度,但**收益最大**(因为它跳过整个 draw call,后续所有层都省了)。

Phase 5 切到 OpenGL 后,你会在 shader 里看到 `gl_Position` 的 clip space 坐标——GPU 在那一层做视锥剔除(几何着色器之后)。**CPU 端的 spatial grid 剔除 + GPU 端的 clip space 剔除 = 双重过滤**。

### 3.3 · 🐧 Linux 系统编程视角

Linux 内核**也用 line-of-sight 类算法**——叫 **BPF (Berkeley Packet Filter)** 的 packet filtering。

网络包到达网卡,内核要不要传给 socket?用 BPF 程序过滤。BPF 程序遍历包的 byte range,类似 Casey 遍历 segment 的 cell range。

更直接的对应:**iptables 规则匹配**。内核维护一组规则(类似 entity),每个进来的 packet 要判断"哪些规则匹配它"。内核用了若干优化,其中一种就是按 packet 特征(协议 / 端口 / IP)建索引,等价于空间划分(不过是"规则空间"而不是物理空间)。

**启示**:空间划分的本质是"按某维度分桶,加速查询",物理空间只是其中一个维度。

### 3.4 · 🦀 Rust 生态视角

把 SpatialGrid 写成 trait,让多种查询共用:

```rust
trait SpatialQuery {
    fn query_nearby(&self, pos: Vec2) -> Vec<EntityId>;
    fn query_in_rect(&self, rect: Aabb) -> Vec<EntityId>;
    fn query_along_segment(&self, a: Vec2, b: Vec2) -> Vec<EntityId>;
}

struct UniformGrid { /* ... */ }
impl SpatialQuery for UniformGrid { /* ... */ }

struct QuadTree { /* ... */ }
impl SpatialQuery for QuadTree { /* ... */ }
```

这就是 Rust 的 trait 多态——上层代码用 `impl SpatialQuery`,不关心底层是 UniformGrid 还是 QuadTree。**未来切换空间划分算法只改一行**。

Casey 在 C 里用函数指针实现类似效果,但 Rust 的 trait + 泛型能让编译器内联优化(零开销抽象)。

**生产建议**:
- 教学阶段:手写 UniformGrid,理解原理
- Phase 4+:抽 SpatialQuery trait,允许切换实现
- Phase 6+:对动态场景用 BVH,对静态场景用 UniformGrid

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么渲染剔除通常用 AABB(矩形)而不是圆形?即使屏幕在 3D 是 frustum,2D 渲染也用 AABB?

**参考解答**:有几个原因:
1. **算法简单**:AABB 覆盖的格子是连续矩形,`for cx in min..=max` 一行;圆形要遍历外接 AABB 再过滤(每个 entity 检查距离),多一步
2. **覆盖网格友好**:AABB 的格子覆盖是稠密矩形,grid 查询高效
3. **保守正确**:AABB 比实际可见区域大,可能多画几个屏幕外 entity,但不会漏画。漏画是 bug,多画只是浪费
4. **GPU 端会再剔除**:Application 层 AABB 剔除可能多放一些进 GPU,但 GPU 端 frustum culling 会再剔除。双重过滤,不会浪费 draw call 太多

工程美学:**粗筛宁可多放,不可漏放**。漏放 = 漏 entity 闪烁 = bug;多放 = 浪费几微秒 = 不影响玩家。

### Lv2 · 动手实践

**题**:在昨天的 day057 代码基础上,加 `query_in_rect` 和 `query_along_segment`。验证:
1. 屏幕矩形 `(0,0)-(1280,720)` 查询返回的 entity 数,应该约等于 80×45=3600(假设 cell_size=16,world 充满)
2. 从 (50,50) 到 (200,200) 的线段查询,返回线段穿过的格子里的 entity

**完成标准**:用 `assert!` 验证返回的 entity 数在合理范围。

**参考解答**:

```rust
// 在 SpatialGrid impl 里加
#[derive(Clone, Copy)]
struct Aabb { min: Vec2, max: Vec2 }

impl SpatialGrid {
    fn query_in_rect(&self, rect: Aabb) -> Vec<EntityId> {
        let (min_cx, min_cy) = self.cell_coord(rect.min);
        let (max_cx, max_cy) = self.cell_coord(rect.max);
        let mut result = Vec::new();
        for cx in min_cx..=max_cx {
            for cy in min_cy..=max_cy {
                if let Some(ids) = self.cells.get(&(cx, cy)) {
                    result.extend_from_slice(ids);
                }
            }
        }
        result
    }

    fn query_along_segment(&self, a: Vec2, b: Vec2) -> Vec<EntityId> {
        let (mut cx, mut cy) = self.cell_coord(a);
        let (end_cx, end_cy) = self.cell_coord(b);
        let dx = b.x - a.x;
        let dy = b.y - a.y;

        // 处理 dx 或 dy 为 0(竖直 / 水平线)
        let step_x: i32 = if dx > 0.0 { 1 } else if dx < 0.0 { -1 } else { 0 };
        let step_y: i32 = if dy > 0.0 { 1 } else if dy < 0.0 { -1 } else { 0 };

        let t_delta_x = if dx.abs() > 1e-6 { (self.cell_size / dx.abs()).abs() } else { f32::INFINITY };
        let t_delta_y = if dy.abs() > 1e-6 { (self.cell_size / dy.abs()).abs() } else { f32::INFINITY };

        // 起始 cell 边界的 t 值
        let cell_min_x = cx as f32 * self.cell_size;
        let cell_max_x = (cx as f32 + 1.0) * self.cell_size;
        let cell_min_y = cy as f32 * self.cell_size;
        let cell_max_y = (cy as f32 + 1.0) * self.cell_size;
        let mut t_max_x = if dx > 0.0 { (cell_max_x - a.x) / dx } else if dx < 0.0 { (cell_min_x - a.x) / dx } else { f32::INFINITY };
        let mut t_max_y = if dy > 0.0 { (cell_max_y - a.y) / dy } else if dy < 0.0 { (cell_min_y - a.y) / dy } else { f32::INFINITY };

        let mut result = Vec::new();
        let mut steps = 0;
        loop {
            if let Some(ids) = self.cells.get(&(cx, cy)) {
                result.extend_from_slice(ids);
            }
            if (cx, cy) == (end_cx, end_cy) || steps > 1000 { break; }
            if t_max_x < t_max_y {
                cx += step_x;
                t_max_x += t_delta_x;
            } else {
                cy += step_y;
                t_max_y += t_delta_y;
            }
            steps += 1;
        }
        result
    }
}

fn main() {
    let mut world = World::new();  // 沿用 day057 的 World
    world.rebuild_grid();

    let visible = world.grid.query_in_rect(Aabb {
        min: Vec2::new(0.0, 0.0), max: Vec2::new(1280.0, 720.0)
    });
    println!("visible entity count: {}", visible.len());
    // 在 50×100 个墙的布局下,屏幕覆盖大约 80×45 = 3600 个格子
    // 但只有边缘格子有墙(其他是空),所以实际数远小于 3600
    assert!(visible.len() < 3600, "should be sparse");

    let los = world.grid.query_along_segment(
        Vec2::new(50.0, 50.0),
        Vec2::new(200.0, 200.0)
    );
    println!("line of sight entities: {}", los.len());
    // (50,50) 到 (200,200) 跨 9-10 个 cell
    assert!(los.len() > 0 && los.len() < 100);
}
```

**算法解释**:
- DDA 算法:把线段看作"光从 a 出发,沿 dx/dy 方向行进",每"穿过一条 cell 边界"记录新 cell
- `t_delta_x` = 水平方向穿过一个 cell 需要的 t(参数化时间)
- `t_max_x` = 下一次穿水平边界的 t
- 比较 t_max_x 和 t_max_y,小的先发生,沿那个方向 step
- t_max_x = INFINITY 表示 dx=0(竖直线),永远不穿水平边界

### 完整 Rust 示例:三个查询验证

```rust
use std::collections::HashMap;

type EntityId = u32;

#[derive(Clone, Copy, Debug, PartialEq)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
}

#[derive(Clone, Copy)]
struct Aabb { min: Vec2, max: Vec2 }

struct SpatialGrid {
    cells: HashMap<(i32, i32), Vec<EntityId>>,
    cell_size: f32,
}

impl SpatialGrid {
    fn new(cell_size: f32) -> Self {
        Self { cells: HashMap::new(), cell_size }
    }
    fn cell_coord(&self, pos: Vec2) -> (i32, i32) {
        ((pos.x / self.cell_size).floor() as i32,
         (pos.y / self.cell_size).floor() as i32)
    }
    fn insert(&mut self, pos: Vec2, id: EntityId) {
        let c = self.cell_coord(pos);
        self.cells.entry(c).or_default().push(id);
    }
    fn query_nearby(&self, pos: Vec2) -> Vec<EntityId> {
        let (cx, cy) = self.cell_coord(pos);
        let mut r = Vec::new();
        for dx in -1..=1 {
            for dy in -1..=1 {
                if let Some(ids) = self.cells.get(&(cx + dx, cy + dy)) {
                    r.extend_from_slice(ids);
                }
            }
        }
        r
    }
    fn query_in_rect(&self, rect: Aabb) -> Vec<EntityId> {
        let (min_cx, min_cy) = self.cell_coord(rect.min);
        let (max_cx, max_cy) = self.cell_coord(rect.max);
        let mut r = Vec::new();
        for cx in min_cx..=max_cx {
            for cy in min_cy..=max_cy {
                if let Some(ids) = self.cells.get(&(cx, cy)) {
                    r.extend_from_slice(ids);
                }
            }
        }
        r
    }
    fn query_along_segment(&self, a: Vec2, b: Vec2) -> Vec<EntityId> {
        let (mut cx, mut cy) = self.cell_coord(a);
        let (end_cx, end_cy) = self.cell_coord(b);
        let dx = b.x - a.x;
        let dy = b.y - a.y;
        let step_x: i32 = if dx > 0.0 { 1 } else if dx < 0.0 { -1 } else { 0 };
        let step_y: i32 = if dy > 0.0 { 1 } else if dy < 0.0 { -1 } else { 0 };
        let t_delta_x = if dx.abs() > 1e-6 { self.cell_size / dx.abs() } else { f32::INFINITY };
        let t_delta_y = if dy.abs() > 1e-6 { self.cell_size / dy.abs() } else { f32::INFINITY };
        let cell_min_x = cx as f32 * self.cell_size;
        let cell_max_x = cell_min_x + self.cell_size;
        let cell_min_y = cy as f32 * self.cell_size;
        let cell_max_y = cell_min_y + self.cell_size;
        let mut t_max_x = if dx > 0.0 { (cell_max_x - a.x) / dx }
                         else if dx < 0.0 { (cell_min_x - a.x) / dx }
                         else { f32::INFINITY };
        let mut t_max_y = if dy > 0.0 { (cell_max_y - a.y) / dy }
                         else if dy < 0.0 { (cell_min_y - a.y) / dy }
                         else { f32::INFINITY };
        let mut r = Vec::new();
        let mut steps = 0;
        loop {
            if let Some(ids) = self.cells.get(&(cx, cy)) {
                r.extend_from_slice(ids);
            }
            if (cx, cy) == (end_cx, end_cy) || steps > 1000 { break; }
            if t_max_x < t_max_y {
                cx += step_x;
                t_max_x += t_delta_x;
            } else {
                cy += step_y;
                t_max_y += t_delta_y;
            }
            steps += 1;
        }
        r
    }
}

fn main() {
    let mut grid = SpatialGrid::new(16.0);
    // 撒一些 entity
    for i in 0..500 {
        let x = (i as f32) * 7.0 % 800.0;
        let y = (i as f32) * 11.0 % 600.0;
        grid.insert(Vec2::new(x, y), i as EntityId);
    }

    // 用例 1:点查询
    let nearby = grid.query_nearby(Vec2::new(100.0, 100.0));
    println!("nearby (100,100): {} entities", nearby.len());

    // 用例 2:矩形查询
    let in_rect = grid.query_in_rect(Aabb {
        min: Vec2::new(0.0, 0.0),
        max: Vec2::new(128.0, 128.0)
    });
    println!("in rect 0,0 - 128,128: {} entities", in_rect.len());

    // 用例 3:线段查询
    let along = grid.query_along_segment(
        Vec2::new(0.0, 0.0),
        Vec2::new(500.0, 500.0)
    );
    println!("along diagonal: {} entities", along.len());
}
```
