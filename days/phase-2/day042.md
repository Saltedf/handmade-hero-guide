
# Day 042 · 基础 2D 向量

> 从这一集开始,你不再用两个独立的 `x` 和 `y` 变量描述位置——你把它们绑成一个 **Vec2**。听起来只是包装,但这个包装让后面 30 集所有运动、碰撞、AI、相机代码突然变得简洁且可组合。

## 0 · 为什么要有这一天

回想 Day 029 你怎么写玩家移动的:

```rust
let new_x = player.x + vx * dt;
let new_y = player.y + vy * dt;
if can_move_to(map, new_x, player.y, SIZE) { player.x = new_x; }
if can_move_to(map, player.x, new_y, SIZE) { player.y = new_y; }
```

四行代码里 `x` 和 `y` 各出现 6 次。一个游戏里,你会写 1000 行这样的代码:玩家位置、怪物位置、子弹位置、相机位置、sprite 偏移、碰撞法线……每写一次,你都要在脑子里同时跟踪两个变量,容易写错(把 `vx` 加到 `y` 上)、难复用(改速度大小要改两个地方)、无法表达"一个箭头"这个核心概念。

**向量(Vec2)解决的就是这个问题**:把 `(x, y)` 绑成一个对象,提供加、减、乘、点积、归一化这些"整体操作"。一旦你有了 `let disp = target - player;`,你后面所有的运动代码都变成一句话:`player += disp.normalize() * speed * dt;`。这是从"两根手指夹数字"到"用整只手抓箭头"的认知跃迁。

Casey 在 Day 41 已经画了地图,Day 42 开始动手:在 Rust 里**手写一个完整的 Vec2 类型**,包括所有必需的 trait(Add/Sub/Mul/Copy/Debug……)。这一集的核心教学价值不在"Vec2 是什么"(你已经会算 `(3,4) 长度 = 5),而在"**怎么用 Rust 类型系统把数学概念表达成代码**,并且让代码简洁、安全、高效"。

心理锚点:做完今天,你应该能用一行 Rust 代码 `player.pos += (target - player.pos).normalize() * SPEED * dt;` 表达"玩家朝 target 走一步"——而不用拆成 6 行 x/y 操作。如果你觉得这行代码读起来不直观,说明你还没把 Vec2 内化成思维单位,回头把 §2 再读一遍。

## 2 · 心智模型

### 费曼类比:向量的"邮递员思维"

想象你是个邮递员,要从邮局(原点)送信到一栋楼。这栋楼在哪?你脑子里有两个数:东边走 100 米,北边走 50 米。这两个数 `(100, 50)` 就是一个 2D 向量。

向量有两层含义,你今天必须分清:

- **位置向量**(point):相对原点的位置。`(100, 50)` = "向东 100、向北 50 的那个点"。
- **位移向量**(direction + magnitude):不关心起点,只关心"走多远、什么方向"。`(100, 50)` = "向东走 100、向北走 50"。

同一个 `(100, 50)` 既可以是位置也可以是位移——这是数学上的统一,但物理意义不同。游戏里玩家位置 `player.pos` 是位置,玩家速度 `player.vel` 是位移(每秒走多远)。两者都是 Vec2,但语义不同。

**位移的合成**:邮递员先走 `(100, 50)` 到 A 楼,再从 A 楼走 `(30, -20)` 到 B 楼。总位移 = `(100+30, 50-20) = (130, 30)`。这就是 **向量加法的物理意义**:位移合成。在游戏里你写 `pos += vel * dt` 时,`vel * dt` 就是"这一帧的位移",加到位置上 = 位置移动。

**位移的差**:两个位置 `player.pos` 和 `monster.pos`,你想知道"怪物相对玩家在哪"。`monster.pos - player.pos = (mx - px, my - py)`,这就是 **向量减法**:从 player 指向 monster 的位移。

### 严谨定义:向量空间的公理与运算

**形式定义**(线性代数教材版本):向量空间 V 是一个集合,配备了加法和标量乘法,满足 8 条公理(加法交换律、结合律、有零元、有负元、标量乘法对加法分配、标量乘法结合、1 乘不变、0 乘归零)。

游戏开发里我们不验证公理,只关心**怎么算**。在 2D 实数向量空间 ℝ² 里,所有运算归结为对两个 f32 的简单算术:

```rust
#[derive(Copy, Clone, Debug, Default, PartialEq)]
pub struct Vec2 {
    pub x: f32,
    pub y: f32,
}
```

**逐行 Rust 解释**:

- `pub struct Vec2` — 定义一个公开结构体(其他模块能 `use` 它)。`struct` 是 Rust 的"具名字段组合",类似 C 的 struct。
- `pub x: f32, pub y: f32` — 两个公开字段,都是 32 位浮点。游戏用 f32(够用、快、SIMD 友好),不用 f64(精度高但慢一倍)。
- `#[derive(Copy, Clone)]` — 让 Vec2 可以"按值复制"。Copy 是关键 trait:它告诉编译器"这个类型 8 字节,复制比引用还便宜,以后别用 move 语义,直接 bit-copy"。**只有所有字段都是 Copy 的类型才能 derive Copy**(f32 是 Copy,所以 Vec2 是)。
- `Debug` — 让 `println!("{:?}", v)` 能打印成 `Vec2 { x: 1.0, y: 2.0 }`。调试必备。
- `Default` — 让 `Vec2::default()` 返回 `{ x: 0.0, y: 0.0 }`(零向量)。零向量在很多算法里是"安全默认值"。
- `PartialEq` — 让 `==` 和 `!=` 能用。注意 f32 的 `==` 在浮点误差下可能不成立,所以我们更多用 `(a - b).length_sq() < eps`。但有些场景(单元测试用整数坐标)用 `==` 没问题。

### 运算的几何意义和代码实现

#### 2.1 加法 (Add):平行四边形法则

**几何**:把向量 b 的尾巴接到向量 a 的头上,a + b 就是从 a 的尾巴到 b 的头。两个向量和 = 平行四边形对角线。

```
        b
       ↗
  a → ●
       ↘
      a + b(几何:从原点沿 a 走,再沿 b 走)
```

**代码**:

```rust
impl std::ops::Add for Vec2 {
    type Output = Vec2;
    fn add(self, rhs: Self) -> Self {
        Self { x: self.x + rhs.x, y: self.y + rhs.y }
    }
}
```

- `impl Add for Vec2` — 给 Vec2 实现 `std::ops::Add` trait。这样 `a + b` 就会调用这个方法。
- `type Output = Vec2` — 关联类型,告诉编译器 `a + b` 的结果是 Vec2。
- `fn add(self, rhs: Self)` — `self` 按值传入(因为 Vec2 是 Copy,等价于按引用但更便宜),`rhs: Self` 也是按值。

**减法类似**,只是把 `+` 换成 `-`,我们实现 `Sub` trait。同时实现 `AddAssign`/`SubAssign`(对应 `+=`/`-=`),因为 `pos += vel * dt;` 这种写法很常见。

```rust
impl std::ops::AddAssign for Vec2 {
    fn add_assign(&mut self, rhs: Self) {
        self.x += rhs.x;
        self.y += rhs.y;
    }
}
```

注意 `&mut self`——这表示"我需要可变借用 self 来修改它的字段"。AddAssign 不返回值,直接改 self。

#### 2.2 标量乘法 (Mul\<f32\>):缩放

**几何**:把向量拉长/缩短 k 倍。k > 1 拉长,0 < k < 1 缩短,k < 0 反向。

**代码**:

```rust
impl std::ops::Mul<f32> for Vec2 {
    type Output = Vec2;
    fn mul(self, k: f32) -> Self {
        Self { x: self.x * k, y: self.y * k }
    }
}
```

`Mul<f32>` 的 `<f32>` 是泛型参数——表示"乘以 f32"。如果你想 `f32 * Vec2`(顺序反过来),要单独实现 `impl Mul<Vec2> for f32`,今天先不做。

注意 `Mul<Vec2> for Vec2`(向量乘向量)我们**故意不实现**——因为向量乘向量在 2D 里有两个不同含义(点积 / 叉积),容易混淆。Casey 用显式的 `dot(a, b)` / `cross(a, b)` 函数名,Rust 翻译也用方法名 `a.dot(b)`,更清晰。

#### 2.3 点积 (dot product)

**几何意义**:`a · b = |a| × |b| × cos(θ)`。θ 是 a 和 b 的夹角。

- 同向(θ=0°):`cos(0) = 1`,点积 = `|a||b|`,最大正值
- 垂直(θ=90°):`cos(90°) = 0`,点积 = 0
- 反向(θ=180°):`cos(180°) = -1`,点积 = `-|a||b|`,最大负值

**直觉**:点积衡量"两个箭头有多对齐"。游戏里用来判断朝向、算投影、做光照。

**代码公式**:`a · b = ax × bx + ay × by`。**为什么这个公式等价于 `|a||b|cos(θ)`?** 推导:

设 a 和 b 与 x 轴夹角分别是 α 和 β。则 `a = (|a|cos(α), |a|sin(α))`,`b = (|b|cos(β), |b|sin(β))`。
展开 `ax*bx + ay*by = |a||b|(cos(α)cos(β) + sin(α)sin(β))`。
三角恒等式 `cos(α-β) = cos(α)cos(β) + sin(α)sin(β)`。
而 α-β = θ(夹角),所以 `ax*bx + ay*by = |a||b|cos(θ)`。证毕。

```rust
impl Vec2 {
    pub fn dot(self, other: Self) -> f32 {
        self.x * other.x + self.y * other.y
    }
}
```

**游戏用法**:玩家朝向 `(0, -1)`(向上),怪物在玩家 `(50, 30)` 处。怪物在玩家前方还是后方?`dot(facing, monster - player) = dot((0,-1), (50, 30)) = 0*50 + (-1)*30 = -30`。负值 → 怪物在玩家背后(因为朝向向上,怪物在下方=屏幕坐标 y 增大方向=背后)。

#### 2.4 长度 (length / length_sq)

**勾股定理**:`|v| = √(x² + y²)`。这就是从原点到 (x, y) 的直线距离。

```rust
impl Vec2 {
    pub fn length_sq(self) -> f32 {
        self.dot(self)  // x*x + y*y
    }
    pub fn length(self) -> f32 {
        self.length_sq().sqrt()
    }
}
```

**为什么提供 length_sq(平方长度)?** 因为 `sqrt` 是慢操作(现代 CPU 约 15-25 cycle,而乘加 1 cycle)。比较两个 entity 距离时:

```rust
// 慢:length() 内部调用 sqrt
if (a.pos - b.pos).length() < 50.0 { ... }

// 快:跳过 sqrt,直接比平方
if (a.pos - b.pos).length_sq() < 2500.0 { ... }  // 50² = 2500
```

第二种快 4-6 倍。Day 047 我们会专门讲这个优化,今天先记住:**比较距离时永远用平方**。

#### 2.5 归一化 (normalize)

**目的**:把向量长度变成 1,保留方向。单位向量(长度=1)在游戏里叫 **normal** 或 **direction**。

**为什么需要单位向量?** 因为点积公式 `a · b = |a||b|cos(θ)`,如果 a 和 b 都是单位向量,`a · b = cos(θ)`。这让光照、AI 视野判断变成"点积 > 0 就在前半球",简单直观。如果 a 和 b 不归一化,点积受长度影响,得手动除以 `|a||b|`,啰嗦。

**代码**:

```rust
impl Vec2 {
    pub fn normalize(self) -> Self {
        let len = self.length();
        if len > 1e-6 {
            self * (1.0 / len)
        } else {
            Self::default()  // 零向量返回零,避免 NaN
        }
    }
}
```

**除零保护**:零向量 (0, 0) 没有方向(因为它的长度是 0,除以 0 得 NaN 或无穷)。游戏里出现零向量是常态(玩家停下的瞬间速度就是 0)。我们不 panic,而是返回零向量——这是"安全默认值"。

`1e-6` 是 epsilon(ε),一个小阈值。**为什么不用 `len > 0.0`?** 因为浮点误差:`(0, 0).length()` 可能算出 `1e-8`(非常接近 0 但不是 0)。除以 `1e-8` 得到 `1e8` 倍——结果爆炸。用 `1e-6` 阈值,小于这个值就当零处理。

#### 2.6 完整运算集合

为了后面用得舒服,我们还要实现:

- `Sub` 和 `SubAssign`(减法,`a - b` 和 `a -= b`)
- `Neg`(`-a`,取反)
- `Index`(用 `v[0]` 和 `v[1]` 访问 x/y,某些算法写起来更通用)
- `from_tuple`、`to_tuple`(便捷构造)
- `lerp`(线性插值,相机平滑跟随会用)

```rust
impl std::ops::Sub for Vec2 {
    type Output = Vec2;
    fn sub(self, rhs: Self) -> Self {
        Self { x: self.x - rhs.x, y: self.y - rhs.y }
    }
}

impl std::ops::Neg for Vec2 {
    type Output = Vec2;
    fn neg(self) -> Self {
        Self { x: -self.x, y: -self.y }
    }
}

impl std::ops::Index<usize> for Vec2 {
    type Output = f32;
    fn index(&self, i: usize) -> &f32 {
        match i { 0 => &self.x, 1 => &self.y, _ => panic!("Vec2 index out of bounds") }
    }
}

impl Vec2 {
    pub const ZERO: Self = Self { x: 0.0, y: 0.0 };
    pub const X_AXIS: Self = Self { x: 1.0, y: 0.0 };
    pub const Y_AXIS: Self = Self { x: 0.0, y: 1.0 };

    pub fn lerp(self, other: Self, t: f32) -> Self {
        self * (1.0 - t) + other * t
    }
}
```

- `const ZERO` — 关联常量。Vec2::ZERO 等价于 `Vec2 { x: 0.0, y: 0.0 }`,但写起来短。`const` 表示"编译期常量",不占运行时。
- `lerp` — 线性插值。`t=0` 返回 self,`t=1` 返回 other,`t=0.5` 返回中点。相机跟随用 `camera = camera.lerp(player.pos, 0.1)`,让相机滞后一点跟随玩家。

### 内存布局:为什么 Vec2 是 8 字节

Rust 默认对结构体字段按声明顺序排列,不插入 padding(除非对齐要求)。Vec2 有两个 f32(各 4 字节,f32 对齐是 4),总大小 8 字节,对齐 4。

```
内存布局(小端):
偏移:  0   4
       x | y
       4B  4B  = 8 字节
```

验证:

```bash
$ cat > /tmp/size.rs << 'EOF'
#[derive(Copy, Clone)]
struct Vec2 { x: f32, y: f32 }
fn main() {
    println!("size = {}", std::mem::size_of::<Vec2>());
    println!("align = {}", std::mem::align_of::<Vec2>());
}
EOF
$ rustc /tmp/size.rs -o /tmp/size && /tmp/size
size = 8
align = 4
```

8 字节意味着 Vec2 可以**完全塞进一个 64 位寄存器**,传递时不需要指针解引用——这就是为什么 Copy 语义足够。也是为什么后面 Day 112+ 的 SIMD 优化能直接把 4 个 Vec2 塞进一个 128 位 SSE 寄存器。

### 3.2 · 🎨 图形学视角

向量在图形学里是**通用语言**。每个像素、每个顶点、每个法线、每个 UV 坐标都是向量。

- **顶点位置**:Vec3(x, y, z),3D 模型的基本元素
- **法线**:Vec3,垂直于表面,用于光照(Day 235+)
- **UV**:Vec2,纹理坐标,告诉 GPU "这个顶点对应纹理图的哪个像素"
- **切线 / 副切线**:Vec3,组成 TBN 矩阵,用于法线贴图(Day 394+)
- **颜色**:Vec3(r, g, b) 或 Vec4(r, g, b, a),本质也是向量
- **光照方向**:Vec3,从表面指向光源(归一化)

**为什么图形 API(GLSL、HLSL、WGSL)原生支持 vec2/vec3/vec4?** 因为图形编程离不开向量,把它内置成基本类型让 shader 代码极其简洁:

```glsl
// GLSL 例:Lambert 漫反射
vec3 N = normalize(normal);
vec3 L = normalize(light_pos - surface_pos);
float diffuse = max(0.0, dot(N, L));
vec3 color = diffuse * light_color * surface_color;
```

CPU 端的 Rust 代码做"逻辑",GPU 端的 shader 做"渲染",两边都用向量。Vec2 是 CPU/GPU 之间的桥梁。

**注意精度**:GPU shader 默认 f32(highp),有些移动 GPU 用 f16(mediump)省带宽。Vec2 在 CPU 是 f32,传到 GPU 时也是 f32(两个 f32 拼成 8 字节)。如果你 CPU 用 f64 而 GPU 用 f32,会有精度不匹配的 bug。**游戏开发统一用 f32**,避免这个问题。

### 3.3 · 🐧 Linux 系统编程视角

Vec2 本身不涉及 Linux 系统调用,但**Linux 工具链**对 Vec2 的诊断有用:

- `std::mem::size_of::<Vec2>()` — 编译期算出 Vec2 是 8 字节(我们刚验证过)
- `cargo asm` — 看 Vec2 的 add 函数有没有被 inline,有没有用 SIMD 指令
- `perf stat` — 看 Vec2 密集运算时 CPU 的 instruction/cycle 比例

```bash
# 把 Vec2 add 函数标 #[inline(always)],看是否被内联到调用点
$ cargo rustc --release -- --emit asm
$ grep -A 5 "vec2_add" target/release/deps/*.s
# 如果函数体被内联,看不到 call vec2_add,直接看到 addss / mulss 指令

# perf 看 cache miss
$ perf stat -e cache-misses,cache-references ./target/release/mygame
# 如果 Vec2 数组布局差(比如交替存 Vec2 和 f32),cache miss 会高
```

**Linux 内核本身用 vector?** 内核 C 代码不用 vector 类型(Linux 内核避免浮点,只偶尔用 SSE 做内存拷贝)。但**驱动**和**用户态图形栈**(Mesa、Wayland)大量用向量——因为它们处理图形。

Wayland 协议里,鼠标事件 `wl_pointer.motion` 的 x/y 是 `wl_fixed_t`(定点小数,32 位)。客户端收到后转 f64 或 f32 再组装成 Vec2。这就是为什么你的 winit 事件循环里,鼠标坐标是 `(f64, f64)` 而不是整数——Wayland/X11 把定点数传过来,Rust 端转浮点。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写 Vec2 的三种风格

**风格 A:trait 实现 + 运算符重载**(今天我们用这种)

```rust
let v = a + b * 2.0 - c;
```

像数学公式,可读性高。代价:要写 8-10 个 trait impl(Add, Sub, Mul, AddAssign, SubAssign, Neg, Index, IndexMut……)。

**风格 B:方法链**

```rust
let v = a.add(b.mul(2.0)).sub(c);
```

casey 在 C 里用这种(`V2Add(a, V2Mul(b, 2.0))`)。Rust 也可以,但代码比运算符重载长。

**风格 C:函数式**

```rust
let v = Vec2::new(a.x + b.x * 2.0 - c.x, a.y + b.y * 2.0 - c.y);
```

啰嗦,但完全显式。新手最常写这种。

**推荐风格 A**,因为运算符重载就是为了让向量代码读起来像数学公式。Rust 的 trait 系统让这种重载**类型安全**(`Vec2 + Vec2` 编译期就知道返回 Vec2),不像 C++ 可能产生隐式转换的 surprise。

#### 现成 crate 对比

| crate | 风格 | 性能 | 用途 |
|---|---|---|---|
| 手写 | trait 重载 | 取决于你 | 学习,完全控制 |
| `glam` | SIMD 内置 | 最快 | Bevy 默认,游戏工业级 |
| `nalgebra` | 泛型维度 | 中等 | 科学计算,机器人 |
| `cgmath` | 经典 trait 重载 | 快 | 老牌图形库 |
| `vega` | 实验性 | 未知 | 极简 |

`glam` 是当下游戏生态的事实标准。Bevy、Fyrox 都用它。Phase 5 之后你切到 glam,API 几乎和手写 Vec2 一样:

```rust
use glam::Vec2;
let v = Vec2::new(1.0, 2.0);
let len = v.length();  // glam 内部用 SIMD,比手写快 2-4x
```

但今天和接下来 50 天,**你手写**。理解 glam 内部做的事,你才能用它而不被它坑。

#### Copy 语义在 Vec2 上的实战

Vec2 是 Copy,所以函数传参**不需要 `&Vec2`**:

```rust
// 推荐:按值传递
fn distance(a: Vec2, b: Vec2) -> f32 { (a - b).length() }

// 不推荐:引用一个 Copy 类型是反模式
fn distance(a: &Vec2, b: &Vec2) -> f32 { (**a - **b).length() }
```

为什么?因为 Copy 类型按值传 = 编译器直接 bit-copy(8 字节),走 CPU 寄存器,不需要解引用。按引用传 = 传一个 8 字节指针,函数体里要 deref,慢一点。

**反例:Vec3 / Vec4**。Vec3 如果按 `(f32, f32, f32)` 实现是 12 字节,对齐 4。但 SIMD(SSE)需要 16 字节对齐才能高效 load。glam 把 Vec3 加 padding 到 16 字节(`{ x, y, z, _pad }`)。这样 Vec3 是 16 字节 Copy,还是按值传快。

#### 生命周期与 Vec2

Vec2 不持有任何堆数据(只有 f32),所以**没有 lifetime 参数**。这让 Vec2 在所有权系统里极其简单:

```rust
struct Player {
    pos: Vec2,  // 不需要 lifetime
    vel: Vec2,
}
```

如果 Vec2 内部有 String 或 Vec,就要写 lifetime,但 Vec2 内部只有 f32,所以最简单。**这种"无 lifetime 的 Copy 类型"是 Rust 最舒服的代码区域**,新手应该多用 Vec2、i32、f64 这种类型,少用 String、Vec(它们复杂)。

## 5 · 对照与变奏

### 同一抽象在不同语言里的表达

**C / C++**:Casey 的 `v2` struct + `V2Add` 函数。C++ 可以用运算符重载(`Vec2 operator+(const Vec2&)`)。

**Python**:`numpy.array([1.0, 2.0])`,所有运算是 numpy 的 SIMD 实现。但 numpy array 不区分 2D/3D,容易混淆。

**JavaScript / TypeScript**:常用 `gl-matrix` 库或 `{x, y}` 字面量对象。后者没有运算符重载,要写 `add(a, b)`。

**GLSL(OpenGL shader)**:原生 `vec2`,带 `vec2.x` / `vec2.y` / `vec2.xy` / `vec2.yx`(swizzling),非常优雅。Rust 做不到 swizzling 因为它要类型推断每个组合。

**HLSL / WGSL**:类似 GLSL。

**Mojo / Julia**:类似 Python,但能编译到原生 SIMD。

### CPU 端 vs GPU 端

| | CPU(Rust) | GPU(GLSL) |
|---|---|---|
| 类型 | `struct Vec2 { x: f32, y: f32 }` | `vec2` |
| 加法 | `a + b`(trait 调用) | `a + b`(原生) |
| 点积 | `a.dot(b)` | `dot(a, b)` |
| 归一化 | `a.normalize()` | `normalize(a)` |
| 长度 | `a.length()` | `length(a)` |
| swizzling | 不支持 | `a.yx`, `a.xx`, `a.xyxx`(升级到 vec3/vec4) |

GPU 端的优势:原生支持 + 大规模并行(一次处理几千个向量)。CPU 端的优势:复杂控制流 + 灵活的数据结构。

游戏开发 = CPU 算游戏逻辑(实体的 Vec2)+ GPU 算光照(顶点的 vec3/vec4)。Day 235 切 OpenGL 时,你会把 Vec2 数据通过 vertex buffer 传到 GPU,shader 里用 vec2 接收。

### 2D Vec2 vs 3D Vec3

| | Vec2 | Vec3 |
|---|---|---|
| 字段 | x, y | x, y, z |
| 大小 | 8 字节 | 12 字节(无 padding)/ 16 字节(SIMD padding) |
| 叉积 | 标量(`ax*by - ay*bx`) | 向量(垂直于 a 和 b) |
| 旋转 | 2×2 矩阵(cos, -sin / sin, cos) | 四元数或 3×3 矩阵 |
| HH 出现 | Day 042-200 | Day 71+ |

很多 2D 算法可以自然推广到 3D——加一个 z 字段,叉积改成 3D 版本。但 3D 也有 2D 没的复杂(旋转顺序、欧拉角 vs 四元数),Phase 3 再深入。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:点积 `a · b = 5`,`a · b = 0`,`a · b = -5` 三种情况分别对应 a 和 b 的什么几何关系?如果你在做光照(法线 N,光源方向 L),这三种 N · L 各对应什么视觉效果?

**参考解答**:

`a · b = |a||b|cos(θ)`,所以正负看 θ:

- **`= 5`(正值)**:θ < 90°,a 和 b 在同一半球。光照含义:光从表面正面照过来,表面被照亮(强度看 cos(θ))。最亮是 θ=0(光垂直表面),N·L = 1。
- **`= 0`**:θ = 90°,a 和 b 垂直。光照含义:光从表面侧面掠过,边缘最暗(像日落时地平线)。这是漫反射的"边界光"。
- **`= -5`(负值)**:θ > 90°,a 和 b 在不同半球。光照含义:光从表面背面照来,正面全黑。Lambert 公式 `max(0, N·L)` 把负值截断到 0,所以你看到的是黑(背光面)。

**为什么这是基础?** 因为后面所有光照模型(Phong、Blinn-Phong、PBR)都建立在"N · L 给你亮不亮"这个核心计算上。今天懂了,Day 394 光照专题你就轻松。

### Lv2 · 动手实践

**题**:在你的 HH 项目里(或在 playground),创建 `math.rs` 文件,实现完整 Vec2 类型并写单元测试:

1. 实现 `Add, Sub, Mul<f32>, AddAssign, SubAssign, Neg, Index`
2. 实现 `dot, length_sq, length, normalize, lerp`
3. 实现 `from_tuple`, `to_tuple` 便捷方法
4. 写测试验证:
   - `(3.0, 4.0).length() == 5.0`(勾股数)
   - `(3.0, 4.0).normalize() ≈ (0.6, 0.8)`
   - `(1.0, 0.0).dot((0.0, 1.0)) == 0.0`(垂直)
   - `(1.0, 1.0).lerp((3.0, 3.0), 0.5) == (2.0, 2.0)`
   - `Vec2::ZERO.normalize() == Vec2::ZERO`(零向量保护)

完成标准:`cargo test` 全部通过。

**参考解答**:

```rust
// src/math.rs
use std::ops::{Add, Sub, Mul, AddAssign, SubAssign, Neg, Index};

#[derive(Copy, Clone, Debug, Default, PartialEq)]
pub struct Vec2 {
    pub x: f32,
    pub y: f32,
}

impl Vec2 {
    pub const ZERO: Self = Self { x: 0.0, y: 0.0 };

    pub fn new(x: f32, y: f32) -> Self { Self { x, y } }

    pub fn from_tuple(t: (f32, f32)) -> Self { Self { x: t.0, y: t.1 } }

    pub fn to_tuple(self) -> (f32, f32) { (self.x, self.y) }

    pub fn dot(self, o: Self) -> f32 { self.x * o.x + self.y * o.y }

    pub fn length_sq(self) -> f32 { self.dot(self) }

    pub fn length(self) -> f32 { self.length_sq().sqrt() }

    pub fn normalize(self) -> Self {
        let len = self.length();
        if len > 1e-6 { self * (1.0 / len) } else { Self::ZERO }
    }

    pub fn lerp(self, other: Self, t: f32) -> Self {
        self * (1.0 - t) + other * t
    }
}

impl Add for Vec2 {
    type Output = Vec2;
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
}

impl Sub for Vec2 {
    type Output = Vec2;
    fn sub(self, o: Self) -> Self { Self { x: self.x - o.x, y: self.y - o.y } }
}

impl Mul<f32> for Vec2 {
    type Output = Vec2;
    fn mul(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
}

impl AddAssign for Vec2 {
    fn add_assign(&mut self, o: Self) { self.x += o.x; self.y += o.y; }
}

impl SubAssign for Vec2 {
    fn sub_assign(&mut self, o: Self) { self.x -= o.x; self.y -= o.y; }
}

impl Neg for Vec2 {
    type Output = Vec2;
    fn neg(self) -> Self { Self { x: -self.x, y: -self.y } }
}

impl Index<usize> for Vec2 {
    type Output = f32;
    fn index(&self, i: usize) -> &f32 {
        match i { 0 => &self.x, 1 => &self.y, _ => panic!("oob") }
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    fn approx(a: f32, b: f32) -> bool { (a - b).abs() < 1e-6 }

    #[test]
    fn test_length() {
        assert!(approx(Vec2::new(3.0, 4.0).length(), 5.0));
    }

    #[test]
    fn test_normalize() {
        let n = Vec2::new(3.0, 4.0).normalize();
        assert!(approx(n.x, 0.6));
        assert!(approx(n.y, 0.8));
    }

    #[test]
    fn test_dot_perpendicular() {
        assert!(approx(Vec2::new(1.0, 0.0).dot(Vec2::new(0.0, 1.0)), 0.0));
    }

    #[test]
    fn test_lerp() {
        let m = Vec2::new(1.0, 1.0).lerp(Vec2::new(3.0, 3.0), 0.5);
        assert!(approx(m.x, 2.0) && approx(m.y, 2.0));
    }

    #[test]
    fn test_zero_normalize() {
        assert_eq!(Vec2::ZERO.normalize(), Vec2::ZERO);
    }
}
```

**关键决策解释**:

- `approx` 函数:浮点比较用 `(a-b).abs() < 1e-6` 而不是 `==`,因为浮点运算有舍入误差。比如 `0.1 + 0.2 != 0.3` 在 f32/f64 里都是 true。
- `#[cfg(test)]`:Rust 的测试隔离——这些代码只在 `cargo test` 时编译,不进 `cargo build` 产物,生产代码不变重。
- `1e-6` 阈值:对游戏单位(像素)来说,小于 1 微米的误差完全无感。科学计算可能要 `1e-10`,但游戏 `1e-6` 足够。

**src/main.rs**:

```rust
mod math;  // 声明子模块,告诉 Rust 找 src/math.rs

use math::Vec2;

fn main() {
    // === 基础运算演示 ===
    let a = Vec2::new(3.0, 4.0);
    let b = Vec2::new(1.0, 2.0);

    println!("a = {:?}", a);                  // Vec2 { x: 3.0, y: 4.0 }
    println!("b = {:?}", b);
    println!("a + b = {:?}", a + b);          // { 4.0, 6.0 }
    println!("a - b = {:?}", a - b);          // { 2.0, 2.0 }
    println!("a * 2.0 = {:?}", a * 2.0);      // { 6.0, 8.0 }
    println!("-a = {:?}", -a);                // { -3.0, -4.0 }

    // === 几何运算 ===
    println!("\n=== Geometry ===");
    println!("|a| = {}", a.length());         // 5.0
    println!("|a|^2 = {}", a.length_sq());    // 25.0(不开方,快)
    println!("a . b = {}", a.dot(b));         // 11.0
    println!("a normalized = {:?}", a.normalize());  // { 0.6, 0.8 }

    // === 实战:玩家朝目标移动一步 ===
    let player = Vec2::new(0.0, 0.0);
    let target = Vec2::new(100.0, 0.0);
    let speed = 30.0_f32;  // 像素/秒
    let dt = 1.0 / 60.0;   // 一帧 16.7ms

    let direction = (target - player).normalize();  // 单位向量
    let step = direction * speed * dt;              // 这一帧的位移
    let new_player = player + step;
    println!("\n=== Player movement ===");
    println!("Player moved from {:?} to {:?} in one frame", player, new_player);
    // { 0.5, 0.0 } —— 朝目标走 0.5 像素

    // === lerp:相机平滑跟随 ===
    let camera = Vec2::new(0.0, 0.0);
    let player = Vec2::new(50.0, 50.0);
    // 系数 0.1 = 每帧追上 10% 距离
    let new_camera = camera.lerp(player, 0.1);
    println!("\n=== Camera lerp ===");
    println!("Camera lerped from {:?} to {:?}", camera, new_camera);
    // { 5.0, 5.0 } —— 一帧走 10% 距离

    // === 内存布局验证 ===
    println!("\n=== Memory ===");
    println!("size_of(Vec2) = {} bytes", std::mem::size_of::<Vec2>());  // 8
    println!("align_of(Vec2) = {} bytes", std::mem::align_of::<Vec2>()); // 4

    // 验证 Copy:赋值后两个变量都能用
    let v1 = Vec2::new(1.0, 2.0);
    let v2 = v1;  // v1 被 Copy,不是 move
    println!("v1 = {:?}, v2 = {:?}", v1, v2);  // 都能用
}
```

### Troubleshooting

**问题 1**:`cargo build` 报 `cannot find type Vec2 in this scope`

原因:你在 `main.rs` 里用了 Vec2 但忘了 `use math::Vec2;`。Rust 子模块的类型默认不导入父模块。

修复:在 `main.rs` 顶部加 `use math::Vec2;`,或写 `mod math; use math::*;`(导入全部,不推荐大项目用)。

**问题 2**:`cargo run` 报 `'a' does not live long enough`

原因:你可能在 Vec2 内部用了引用(`&f32`)。Vec2 必须是 self-contained(字段都是 f32,不是引用),所以这个错说明你的 struct 定义错了。

修复:检查 `pub struct Vec2 { pub x: f32, pub y: f32 }`,字段都是 f32 而不是 `&f32`。

**问题 3**:`cargo test` 报 `assert_eq! failed: left != right`

原因:f32 直接 `==` 比较有精度问题。比如 `0.1 + 0.2 != 0.3`。

修复:用 `approx(a, b)` 函数(`(a-b).abs() < 1e-6`),或 `assert!((actual - expected).abs() < 1e-6)`。

**问题 4**:你写 `Vec2 * Vec2` 编译报 `Mul<Vec2> is not implemented for Vec2`

原因:我们故意只实现 `Mul<f32>`,没实现 `Mul<Vec2>`。向量乘向量有歧义(点积?叉积?逐元素?),所以用方法名 `dot`/`cross` 显式表达。

修复:改用 `a.dot(b)`(返回 f32)或 `a.x * b.x, a.y * b.y`(如果你要逐元素)。
