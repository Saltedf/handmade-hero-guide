# Day 039 · 基础位图渲染清理

> Day 037-038 你写了 blit 和 alpha blit,代码能跑了。但 Casey 这一天**不写新功能**——他停下来重构。代码里到处是 magic number、重复逻辑、不清晰的接口。Day 039 是"清理日",把这些"代码债"还清,让后续开发更轻松。这是 Day 027 探索式架构的典型应用:**写完之后回头重构**。

## 0 · 为什么要有这一天

新手觉得"能跑就行",老手知道**代码质量决定开发速度**。具体看几个 Day 037-38 留下的"债":

**债 1:Magic number 满天飞**

```rust
let out_r = ((src_r * a + dst_r * inv_a + 128) >> 8) as u32;
//                                          ^^^   ^^^
//                                          这些数字什么意思?
```

`128` 是四舍五入补偿,`>> 8` 是 `/ 256`(近似 `/ 255`)。**没注释**,新人看不懂,改的时候容易破坏。

**债 2:重复逻辑**

```rust
fn blit(...) {
    let src_x_start = (-dest_x).max(0).min(src_w);
    let src_y_start = (-dest_y).max(0).min(src_h);
    let src_x_end = (fb_w - dest_x).max(0).min(src_w);
    let src_y_end = (fb_h - dest_y).max(0).min(src_h);
    // ...
}

fn alpha_blit(...) {
    let src_x_start = (-dest_x).max(0).min(src_w);  // 重复!
    let src_y_start = (-dest_y).max(0).min(src_h);  // 重复!
    let src_x_end = (fb_w - dest_x).max(0).min(src_w);  // 重复!
    let src_y_end = (fb_h - dest_y).max(0).min(src_h);  // 重复!
    // ...
}
```

两个函数有完全相同的"visible 区域计算"。**违反 DRY**(Don't Repeat Yourself)。改一处忘改另一处 → bug。

**债 3:类型不安全**

```rust
let dest_x: i32 = ...;
let src_x: usize = ...;
let pixel: u32 = ...;
let alpha: u8 = ...;
```

`dest_x` 是屏幕坐标(i32),`src_x` 是 sprite 内坐标(usize),`pixel` 是 0x00RRGGBB(u32),`alpha` 是 0-255(u8)。**没有类型保护**,传错编译器不报错。

**债 4:接口不一致**

```rust
fn blit(fb, fb_w, fb_h, dest_x, dest_y, src, src_w, src_h);
fn alpha_blit(fb, fb_w, fb_h, dest_x, dest_y, src, src_alpha, src_w, src_h);
//                                                     ^^^^^^^^^
//                                              alpha_blit 多一个参数
```

两个相似的 blit 函数,签名不一致。新人想用 alpha_blit 替换 blit,参数不对。

**债 5:错误处理散乱**

```rust
fn load_bmp(path) -> Result<BmpImage, BmpError> { ... }
fn blit(...) { /* 不返回 Result,假设输入合法 */ }
```

有的函数返回 Result,有的不返回。**约定不统一**,新人不知道哪里要 `?`。

### 为什么必须重构

如果不重构,**后果复利**:

- 加新功能时,先要理解旧代码 → 时间浪费
- 改旧代码时,可能破坏其他地方 → bug 增多
- 团队协作时,新人看不懂 → onboarding 慢
- 测试时,magic number 边界 case 多 → 测试不全

**Day 039 的核心思想**:**"代码债"像信用卡债,你不还,利息越滚越大**。Day 37-38 借了一点(快速实现),Day 39 还了(重构)。后面 Day 40-50 加新功能(动画、移动、碰撞)就轻松。

### 重构不是浪费

很多新手讨厌重构,觉得"不增加功能,白干"。**恰恰相反**:

- **重构让新功能更快加**:好代码 = 改一处影响一处;坏代码 = 改一处影响十处
- **重构减少 bug**:清晰代码 = 看一眼就懂;混乱代码 = 看十遍才发现 bug
- **重构让你学得更多**:重构强迫你重新审视代码,理解更深

工业界有个概念叫"**Boy Scout Rule**":**离开营地时比来时更干净**。每次接触代码,留一点改善。Casey Day 039 就是这个原则——Day 37-38 留下的债,Day 39 还。

心理锚点:看完这集,你应该能:

- 找出自己代码里的 5 类"债"(magic number / 重复 / 类型不安全 / 接口不一致 / 错误处理散乱)
- 用 Rust trait / newtype / extract function 解决它们
- 解释为什么"重构是投资,不是浪费"

如果你做不到,反复看 §2 的"五类债"和"重构手法"部分。

## 1 · Casey 今天做了什么

Casey 这一天**完全不写新功能**,他做的事:

1. **抽出 visible 区域计算**:把 `src_x_start` 等逻辑提到独立函数 `compute_visible_region`
2. **定义新类型**:`ScreenCoord(i32)` / `Pixel(u32)` / `Alpha(u8)`,用 newtype 加强类型安全
3. **统一 blit 接口**:`fn blit(dst: &mut [Pixel], src: &Bitmap, dest: ScreenPos, mode: BlendMode)` 接收 enum 选择 blit 模式
4. **替换 magic number**:用 `const ALPHA_ROUND: u32 = 128` 等命名常量
5. **统一错误处理**:所有 IO 函数返回 `Result<T, AssetError>`
6. **加文档注释**:每个 public 函数加 `///` 文档,解释参数和返回值

Casey 重构后:

- 代码总行数**减少**(消除重复)
- 测试覆盖率**提高**(因为类型安全,边界 case 更明显)
- 新加 alpha mode(如 additive)只需要加 enum variant + 一个 match arm

**Casey 在这集强调**:

- **重构不动行为**:重构前后,所有现有测试必须仍然通过。这是底线
- **小步快走**:每次只改一个方面,跑测试,再改下一个
- **commit 粒度**:每个小重构一个 commit,方便回滚

## 2 · 心智模型

### 类比:整理衣柜

你的衣柜堆了一堆衣服:

- 上衣、裤子、袜子混在一起
- 有些衣服 5 年没穿(过时代码)
- 同样的衣服买了 3 件(重复代码)
- 没有标签,找东西靠记忆(magic number)

整理步骤:

1. **分类**:上衣一摞、裤子一摞、袜子一摞(extract function / module)
2. **贴标签**:每摞标上"夏装 / 冬装"(命名常量 / 文档)
3. **淘汰**:5 年没穿的衣服扔掉(删除死代码)
4. **统一**:同样的衣服只留一件(消除重复)
5. **维护**:以后新衣服按规则放(后续开发遵循)

重构后的衣柜:找东西 30 秒(代码可读),整理 5 分钟(改一处影响一处),买新衣服 1 分钟(加新功能快)。

### 第一类债:Magic Number

**坏代码**:

```rust
let out = ((src * a + dst * (255 - a) + 128) >> 8) as u32;
```

**好代码**:

```rust
const ALPHA_SCALE: u32 = 255;
const ALPHA_ROUND_BIAS: u32 = 128;  // 加 128 等于 +0.5,四舍五入
const ALPHA_SHIFT: u32 = 8;          // >> 8 ≈ / 256(近似 / 255)

let inv_a = ALPHA_SCALE - a as u32;
let scaled = src as u32 * a as u32 + dst as u32 * inv_a + ALPHA_ROUND_BIAS;
let out = (scaled >> ALPHA_SHIFT) as u32;
```

**为什么好**:

- 名字说明意图(`ALPHA_ROUND_BIAS` 比 `128` 清晰)
- 改算法时改一处(`const` 改定义,所有用处自动更新)
- 编译器优化没差异(`const` 是编译期常量,内联)

### 第二类债:重复代码

**坏代码**(blit 和 alpha_blit 重复 visible 区域计算):

```rust
fn blit(...) {
    let src_x_start = (-dest_x).max(0).min(src_w);
    let src_y_start = (-dest_y).max(0).min(src_h);
    let src_x_end = (fb_w - dest_x).max(0).min(src_w);
    let src_y_end = (fb_h - dest_y).max(0).min(src_h);
    // 主循环
}

fn alpha_blit(...) {
    let src_x_start = (-dest_x).max(0).min(src_w);
    // ... 完全相同
    // 主循环
}
```

**好代码**(提取公共函数):

```rust
struct VisibleRegion {
    src_x_start: i32, src_y_start: i32,
    src_x_end: i32, src_y_end: i32,
}

fn compute_visible_region(
    dest_x: i32, dest_y: i32,
    src_w: i32, src_h: i32,
    fb_w: i32, fb_h: i32,
) -> Option<VisibleRegion> {
    let region = VisibleRegion {
        src_x_start: (-dest_x).max(0).min(src_w),
        src_y_start: (-dest_y).max(0).min(src_h),
        src_x_end: (fb_w - dest_x).max(0).min(src_w),
        src_y_end: (fb_h - dest_y).max(0).min(src_h),
    };
    if region.src_x_start >= region.src_x_end || region.src_y_start >= region.src_y_end {
        None  // 完全在屏幕外
    } else {
        Some(region)
    }
}

fn blit(...) {
    let region = match compute_visible_region(...) {
        Some(r) => r,
        None => return,
    };
    // 主循环(用 region)
}

fn alpha_blit(...) {
    let region = match compute_visible_region(...) {
        Some(r) => r,
        None => return,
    };
    // 主循环(用 region)
}
```

**为什么好**:

- 重复消除
- 改 visible 算法只改一处
- 返回 `Option` 明确表示"可能完全在屏幕外"

### 第三类债:类型不安全

**坏代码**:

```rust
fn move_player(player_x: &mut i32, dx: i32) {
    *player_x += dx;
}

let mut camera_x: i32 = 0;
let mut player_x: i32 = 0;
move_player(&mut camera_x, 10);  // 错把 camera 当 player!编译器不报错
```

**好代码**(newtype):

```rust
#[derive(Copy, Clone, Debug, Default, PartialEq, Eq)]
struct WorldX(i32);

#[derive(Copy, Clone, Debug, Default, PartialEq, Eq)]
struct ScreenX(i32);

#[derive(Copy, Clone, Debug, Default, PartialEq, Eq)]
struct CameraX(i32);

fn move_player(player_x: &mut WorldX, dx: i32) {
    player_x.0 += dx;
}

let mut camera_x = CameraX::default();
let mut player_x = WorldX::default();
move_player(&mut camera_x, 10);  // 编译错误!CameraX 不是 WorldX
```

**为什么好**:

- Rust 编译器在**编译时**检查类型,运行时零开销
- 代码意图明确(看到 `WorldX` 就知道是世界坐标)
- 防止"参数顺序反了"这种 bug

### 第四类债:接口不一致

**坏代码**(blit 和 alpha_blit 参数不同):

```rust
fn blit(fb, fb_w, fb_h, dest_x, dest_y, src, src_w, src_h);
fn alpha_blit(fb, fb_w, fb_h, dest_x, dest_y, src, src_alpha, src_w, src_h);
```

**好代码**(统一接口,enum 选模式):

```rust
#[derive(Copy, Clone, Debug)]
enum BlendMode {
    Opaque,         // 不透明(原 blit)
    AlphaBlend,     // alpha 混合(原 alpha_blit)
    Additive,       // 加法混合(以后扩展)
}

fn blit(
    fb: &mut [Pixel],
    dest: ScreenPos,
    src: &Bitmap,
    mode: BlendMode,
) {
    let region = match compute_visible_region(...) { ... };
    match mode {
        BlendMode::Opaque => { /* 直接复制 */ }
        BlendMode::AlphaBlend => { /* alpha 混合 */ }
        BlendMode::Additive => { /* 加法 */ }
    }
}
```

**为什么好**:

- 一个函数替代两个
- 加新模式只加 enum variant + match arm
- 用户传 `BlendMode::AlphaBlend` 比 "记得调 alpha_blit 而不是 blit" 直观

### 第五类债:错误处理散乱

**坏代码**:

```rust
fn load_bmp(path: &str) -> Result<BmpImage, BmpError> { ... }
fn blit(...) { ... }  // 假设输入合法,不返回 Result
fn load_font(...) -> Font { ... }  // 失败时 panic!
```

**好代码**:

```rust
#[derive(Debug)]
enum AssetError {
    Io(std::io::Error),
    InvalidFormat(String),
    UnsupportedFeature(String),
}

impl From<std::io::Error> for AssetError {
    fn from(e: std::io::Error) -> Self { AssetError::Io(e) }
}

fn load_bmp(path: &str) -> Result<BmpImage, AssetError> { ... }
fn load_font(path: &str) -> Result<Font, AssetError> { ... }
// blit 还是 void(纯计算,不会失败)
```

**为什么好**:

- 统一错误类型(所有 asset 用 `AssetError`)
- `From` impl 让 `?` 操作符自动转换
- 不会失败的纯计算函数保持 void(不强制 Result)

### 重构手法总结

| 手法 | 解决什么 | Rust 工具 |
|---|---|---|
| Extract Function | 重复代码 | 普通函数 |
| Replace Magic Number | 数字含义不清 | `const` |
| Introduce Newtype | 类型不安全 | `struct X(i32)` |
| Unify Interface | 接口不一致 | enum + match |
| Unify Error Handling | 错误处理散乱 | `Result` + `From` |
| Add Doc Comments | 代码不自解释 | `///` |

### 重构流程(安全)

1. **跑测试**:确保现有测试通过(基准)
2. **小步**:一次只改一类问题(如先处理 magic number)
3. **再跑测试**:确认没破坏行为
4. **commit**:每个小重构一个 commit
5. **下一步**:改下一类问题
6. **重复**

**禁忌**:不要"大重构"——一次改 10 个方面,跑测试一堆失败,定位不了哪个改动破坏的。**小步快走,每步可验证**。

### Rust 的重构工具

**`rust-analyzer`**:Rust 的 LSP 实现,提供:

- Rename(自动重命名符号,跨文件)
- Extract function(选代码 → 提取函数)
- Inline function(把函数调用换成函数体)
- Generate impl(自动生成 trait 实现)

VS Code / Neovim 集成 rust-analyzer 后,F2 / Refactor menu 直接调。

**`cargo fmt`**:自动格式化代码。统一风格,避免"风格之争"。

**`cargo clippy`**:Rust 的 linter,提示 200+ 种坏味道:

```bash
cargo clippy
# warning: this expression has a high cognitive complexity
# warning: redundant clone
# warning: useless use of format!
# ...
```

**`cargo fix`**:自动应用部分 clippy 建议。

**`cargo edit`**:管理依赖(`cargo add` / `cargo rm`)。

### 3.2 · 🐧 Linux 系统编程视角

Linux 内核重构非常普遍。Linus 的"never break userspace"原则只约束**用户态可见接口**(syscall),**内核内部**可以随意重构。

Linux 内核重构的几个例子:

- **RCU(Read-Copy-Update)** 替换 rwlock,性能大幅提升
- **CFS(Completely Fair Scheduler)** 替换 O(1) scheduler,公平性更好
- **xarray** 替换 radix tree,接口更现代
- **EEVDF scheduler**(2023)替换 CFS,延迟更可控

这些重构都是"大重构",周期几年,大量测试。Casey 在 HH 教的是"小重构"——每天一点点,持续重构。

**Linux 工具**:

```bash
# 用 coccinelle 做 Linux 风格的批量重构
sudo pacman -S coccinelle
# spatch = semantic patch,能理解 C 语法
# 例:把所有 kmalloc(GFP_KERNEL) 替换成 kmalloc(sizeof(...), GFP_KERNEL)

# 用 cargo clippy 做 Rust 风格的批量重构
cargo clippy --fix  # 自动应用能修的 lint

# 用 cargo fmt 统一格式
cargo fmt --all
# 看 diff
git diff

# 用 rust-analyzer 在编辑器里 refactor
# (在 VS Code: 右键 → Refactor → Extract function)
```

### 3.3 · 🦀 Rust 生态视角

Rust 的所有权系统**让重构更安全**:

**安全 rename**:Rust 的类型系统让 rename 跨文件 100% 可靠(rust-analyzer 帮你做)。C/C++ 的 rename 容易遗漏(特别是 header 和 source 不同步)。

**安全 extract function**:Rust 的借用检查让"提取函数"后接口清晰。提取后函数签名告诉你"读什么、写什么"——编译器验证。

**安全 change interface**:改 trait / struct 字段,所有调用点编译器告诉你。

**安全 delete dead code**:Rust 编译器警告 unused 字段 / 函数,clippy 提示。

**Rust 重构的反模式**:

```rust
// 坏:过度抽象
trait Drawable {
    fn draw(&self, ctx: &dyn DrawContext, ...) -> Result<(), Box<dyn Error>>;
}
// 太通用,实际只有 2 种实现。Rule of Three: 3 次再抽象。

// 坏:过早 optimization
fn fast_add(a: u32, b: u32) -> u32 {
    unsafe { std::arch::x86_64::_addcarryx_u32(0, a, b, &mut 0) }
}
// 用 SIMD 加法,但 u32 加法不需要 SIMD。Premature optimization。

// 好:简单清晰
fn add(a: u32, b: u32) -> u32 { a + b }
```

**Rust 的 trait 选择**:

- `Debug`:调试打印
- `Default`:默认值
- `Clone` / `Copy`:复制语义
- `PartialEq` / `Eq`:相等比较
- `Hash`:HashMap key
- `From` / `Into`:类型转换

重构时该 derive 的 derive,减少手写代码。

### "不重构"的反面教材

**Doom 3 源代码**(id Tech 4):当年为了发游戏硬上,代码债大。后来 Quake Con 时 John Carmack 说"如果我们重构,Doom 3 能早半年发"。

**Duke Nukem Forever**:每次有新技术就推翻重做,14 年才出。**过度重构**也不行。

平衡:**重构到"够好",不要追求完美**。Casey 在 HH 经常说"now this isn't perfect, but it's good enough, let's move on"。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Casey 在 Day 039 强调"重构不动行为"——所有现有测试必须仍然通过。但如果你的代码**没有测试**,怎么验证重构没破坏?

**参考解答**:**先加测试,再重构**。

具体步骤:

1. **加"特征测试"**(characterization test):跑当前代码,记录关键输出(像素颜色、log、返回值)。这些是"已知行为"
2. **手动验证**:在重构前,跑一次游戏,看画面 / 行为。截图保存
3. **重构**:小步走,每步后:
   - 跑特征测试,对比输出
   - 手动跑游戏,看截图是否一致
4. **如果破坏**:回滚 commit,重做这步

**Rust 的特性帮助**:

- 强类型系统:很多"破坏"编译器会告诉你
- `cargo test` 快速跑单元测试
- `debug_assert!`:debug 模式检查运行时假设

**Casey HH 的实践**:Casey 在重构时经常手动跑游戏验证。"重构后画面应该和之前一样,不一样就有 bug"。

### Lv2 · 动手实践

**题**:拿你 Day 037-38 的代码,做 5 类重构:

1. 替换 magic number(`const ALPHA_ROUND_BIAS: u32 = 128`)
2. 提取 `compute_visible_region` 函数
3. 加 newtype(`ScreenX(i32)` / `WorldX(i32)`)
4. 统一 blit 接口(`enum BlendMode`)
5. 统一错误处理(`AssetError` enum)

完成标准:重构后所有 Day 037-38 的测试仍通过。

**参考解答**(简化版,演示手法):

```rust
// src/main.rs(重构后)

use std::ops::{Add, AddAssign};

// === 1. Newtype:坐标类型安全 ===
#[derive(Copy, Clone, Debug, Default, PartialEq, Eq, PartialOrd, Ord)]
struct ScreenX(i32);

#[derive(Copy, Clone, Debug, Default, PartialEq, Eq, PartialOrd, Ord)]
struct ScreenY(i32);

#[derive(Copy, Clone, Debug, Default, PartialEq, Eq)]
struct ScreenPos { x: ScreenX, y: ScreenY }

impl AddAssign<(i32, i32)> for ScreenPos {
    fn add_assign(&mut self, (dx, dy): (i32, i32)) {
        self.x.0 += dx;
        self.y.0 += dy;
    }
}

// === 2. Newtype:像素类型 ===
#[derive(Copy, Clone, Debug, Default, PartialEq, Eq)]
struct Pixel(u32);  // 0x00RRGGBB

impl Pixel {
    fn r(self) -> u32 { (self.0 >> 16) & 0xFF }
    fn g(self) -> u32 { (self.0 >> 8) & 0xFF }
    fn b(self) -> u32 { self.0 & 0xFF }
    fn from_rgb(r: u32, g: u32, b: u32) -> Self {
        Self((r << 16) | (g << 8) | b)
    }
}

// === 3. Magic number 替换 ===
const ALPHA_SCALE: u32 = 255;
const ALPHA_ROUND_BIAS: u32 = 128;  // 加 0.5 for 四舍五入
const ALPHA_SHIFT: u32 = 8;          // >> 8 ≈ / 256

// === 4. 统一 blend mode ===
#[derive(Copy, Clone, Debug)]
enum BlendMode {
    Opaque,
    AlphaBlend,
}

// === 5. 统一错误处理 ===
#[derive(Debug)]
enum AssetError {
    Io(std::io::Error),
    InvalidFormat(&'static str),
}

impl From<std::io::Error> for AssetError {
    fn from(e: std::io::Error) -> Self { AssetError::Io(e) }
}

// === 6. 提取 visible region 计算 ===
struct VisibleRegion {
    src_x_start: i32, src_y_start: i32,
    src_x_end: i32, src_y_end: i32,
}

fn compute_visible_region(
    dest: ScreenPos, src_w: i32, src_h: i32, fb_w: i32, fb_h: i32,
) -> Option<VisibleRegion> {
    let region = VisibleRegion {
        src_x_start: (-dest.x.0).max(0).min(src_w),
        src_y_start: (-dest.y.0).max(0).min(src_h),
        src_x_end: (fb_w - dest.x.0).max(0).min(src_w),
        src_y_end: (fb_h - dest.y.0).max(0).min(src_h),
    };
    if region.src_x_start >= region.src_x_end || region.src_y_start >= region.src_y_end {
        None
    } else {
        Some(region)
    }
}

// === 7. 统一 blit 函数 ===
fn blit(
    fb: &mut [Pixel], fb_w: i32, fb_h: i32,
    dest: ScreenPos,
    src: &[Pixel], src_alpha: Option<&[u8]>, src_w: i32, src_h: i32,
    mode: BlendMode,
) {
    let region = match compute_visible_region(dest, src_w, src_h, fb_w, fb_h) {
        Some(r) => r,
        None => return,
    };

    for sy in region.src_y_start..region.src_y_end {
        for sx in region.src_x_start..region.src_x_end {
            let src_idx = (sy * src_w + sx) as usize;
            let dx = dest.x.0 + sx;
            let dy = dest.y.0 + sy;
            let dst_idx = (dy * fb_w + dx) as usize;

            match mode {
                BlendMode::Opaque => {
                    fb[dst_idx] = src[src_idx];
                }
                BlendMode::AlphaBlend => {
                    let alpha = src_alpha.unwrap()[src_idx];
                    if alpha == 0 { continue; }
                    if alpha == 255 {
                        fb[dst_idx] = src[src_idx];
                        continue;
                    }
                    fb[dst_idx] = alpha_blend_pixel(fb[dst_idx], src[src_idx], alpha);
                }
            }
        }
    }
}

fn alpha_blend_pixel(dst: Pixel, src: Pixel, alpha: u8) -> Pixel {
    let a = alpha as u32;
    let inv_a = ALPHA_SCALE - a;
    let out_r = (src.r() * a + dst.r() * inv_a + ALPHA_ROUND_BIAS) >> ALPHA_SHIFT;
    let out_g = (src.g() * a + dst.g() * inv_a + ALPHA_ROUND_BIAS) >> ALPHA_SHIFT;
    let out_b = (src.b() * a + dst.b() * inv_a + ALPHA_ROUND_BIAS) >> ALPHA_SHIFT;
    Pixel::from_rgb(out_r, out_g, out_b)
}

fn main() {
    println!("Refactored renderer. Run cargo test to verify.");
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn opaque_blit_works() {
        let mut fb = vec![Pixel(0); 10 * 10];
        let src = vec![Pixel(0xFF0000); 2 * 2];
        let dest = ScreenPos { x: ScreenX(5), y: ScreenY(5) };
        blit(&mut fb, 10, 10, dest, &src, None, 2, 2, BlendMode::Opaque);
        assert_eq!(fb[5 * 10 + 5], Pixel(0xFF0000));
    }

    #[test]
    fn alpha_blit_0_does_nothing() {
        let mut fb = vec![Pixel(0x123456); 10 * 10];
        let src = vec![Pixel(0xFFFFFF); 1];
        let alpha = vec![0u8; 1];
        let dest = ScreenPos { x: ScreenX(5), y: ScreenY(5) };
        blit(&mut fb, 10, 10, dest, &src, Some(&alpha), 1, 1, BlendMode::AlphaBlend);
        assert_eq!(fb[5 * 10 + 5], Pixel(0x123456));  // 没变
    }

    #[test]
    fn screen_x_distinct_from_world_x() {
        // 这个测试展示 newtype 让类型不兼容
        // (注释掉,因为编译错误)
        // let sx = ScreenX(5);
        // let wx = WorldX(5);
        // assert_eq!(sx, wx);  // 编译错误:不同类型
    }

    #[test]
    fn compute_visible_handles_negative_dest() {
        let dest = ScreenPos { x: ScreenX(-5), y: ScreenY(0) };
        let region = compute_visible_region(dest, 10, 10, 100, 100);
        let r = region.unwrap();
        assert_eq!(r.src_x_start, 5);  // 前 5 像素在屏幕外
        assert_eq!(r.src_x_end, 10);
    }

    #[test]
    fn compute_visible_returns_none_when_offscreen() {
        let dest = ScreenPos { x: ScreenX(200), y: ScreenY(200) };
        let region = compute_visible_region(dest, 10, 10, 100, 100);
        assert!(region.is_none());
    }
}
```

**关键改动**:

- newtype `ScreenX` / `Pixel` 防止"参数传错"
- `BlendMode` enum 统一接口(替代 blit 和 alpha_blit 两个函数)
- `compute_visible_region` 提取重复代码
- 命名常量(`ALPHA_ROUND_BIAS`)替 magic number

### Rust 完整可跑示例(前后对比)

```rust
// src/main.rs
// 演示重构前后的对比

// ===== 重构前 =====
mod before {
    pub fn alpha_blend(dst: u32, src: u32, alpha: u8) -> u32 {
        // Magic number,不清晰
        let dst_r = (dst >> 16) & 0xFF;
        let dst_g = (dst >> 8) & 0xFF;
        let dst_b = dst & 0xFF;
        let src_r = (src >> 16) & 0xFF;
        let src_g = (src >> 8) & 0xFF;
        let src_b = src & 0xFF;
        let a = alpha as u32;
        let out_r = (src_r * a + dst_r * (255 - a) + 128) >> 8;
        let out_g = (src_g * a + dst_g * (255 - a) + 128) >> 8;
        let out_b = (src_b * a + dst_b * (255 - a) + 128) >> 8;
        (out_r << 16) | (out_g << 8) | out_b
    }
}

// ===== 重构后 =====
mod after {
    const ALPHA_MAX: u32 = 255;
    const ROUND_BIAS: u32 = 128;
    const ALPHA_DIV_SHIFT: u32 = 8;

    #[derive(Copy, Clone, Debug, PartialEq, Eq)]
    pub struct Pixel(pub u32);

    impl Pixel {
        fn channels(self) -> (u32, u32, u32) {
            ((self.0 >> 16) & 0xFF, (self.0 >> 8) & 0xFF, self.0 & 0xFF)
        }
        fn from_rgb(r: u32, g: u32, b: u32) -> Self {
            Self((r << 16) | (g << 8) | b)
        }
    }

    pub fn alpha_blend(dst: Pixel, src: Pixel, alpha: u8) -> Pixel {
        if alpha == 0 { return dst; }
        if alpha == 255 { return src; }
        let a = alpha as u32;
        let inv_a = ALPHA_MAX - a;
        let (dr, dg, db) = dst.channels();
        let (sr, sg, sb) = src.channels();
        let blend = |src_c: u32, dst_c: u32| -> u32 {
            (src_c * a + dst_c * inv_a + ROUND_BIAS) >> ALPHA_DIV_SHIFT
        };
        Pixel::from_rgb(blend(sr, dr), blend(sg, dg), blend(sb, db))
    }
}

fn main() {
    // 验证两个版本输出一致
    let test_cases = [
        (0x123456u32, 0xFFFFFF, 0u8),
        (0x123456, 0xFFFFFF, 128),
        (0x123456, 0xFFFFFF, 255),
        (0x000000, 0xFF0000, 64),
    ];

    for (i, (dst, src, a)) in test_cases.iter().enumerate() {
        let before = before::alpha_blend(*dst, *src, *a);
        let after = after::alpha_blend(after::Pixel(*dst), after::Pixel(*src), *a).0;
        let match_str = if before == after { "OK" } else { "MISMATCH" };
        println!("Case {}: before=0x{:06x}, after=0x{:06x} {}",
            i, before, after, match_str);
        assert_eq!(before, after);
    }

    println!("\nAll outputs match - refactor preserves behavior.");
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn before_after_produce_same_results() {
        for dst in [0u32, 0x123456, 0xFFFFFF, 0x00007F] {
            for src in [0u32, 0xFF0000, 0x00FF00, 0x0000FF] {
                for alpha in [0u8, 1, 64, 128, 200, 255] {
                    let b = before::alpha_blend(dst, src, alpha);
                    let a = after::alpha_blend(after::Pixel(dst), after::Pixel(src), alpha).0;
                    assert_eq!(b, a, "dst=0x{:x} src=0x{:x} a={}", dst, src, alpha);
                }
            }
        }
    }
}
```
