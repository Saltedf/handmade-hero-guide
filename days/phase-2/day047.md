# Day 047 · 向量长度

> Day 042 你写了 `length()`,看起来人畜无害。但 Casey 在 Day 047 抛出一个反直觉的事实:`sqrt` 是 CPU 上最慢的基本运算之一(约 20 cycle,加法是 1 cycle)。每帧调用 1000 次 length,等于 20000 cycle 浪费。今天的核心 trick 一句话:**比较距离用 length_sq,不用 length**——4-6 倍性能提升。

## 0 · 为什么要有这一天

游戏里"算距离"的频率高到夸张:

- 玩家和怪物的攻击距离
- 怪物的视野 / 警戒范围
- 投射物的爆炸半径
- 玩家和物品的拾取范围
- AI 决定追击还是逃跑
- 音效衰减(离声源多远)
- LOD(细节层次)切换

一个商业游戏每帧可能算 10000+ 次距离。如果每次都开方(sqrt),CPU 时间大量浪费在数学运算上,留给游戏逻辑的就少了。

**怎么避免?** 大部分场景**不需要真实距离**,只需要"距离是否 < 阈值"。比如"玩家是否在 100 像素内",数学等价于"距离平方 < 10000"。直接比较平方,跳过 sqrt。

这个看似微不足道的优化,在游戏引擎里**反复使用**。Casey 在 Day 047 把这个习惯训练给观众——以后所有距离比较都用平方。Day 047 的另一个主题是 **IEEE 754 浮点表示**和 **Quake III 的 fast inverse sqrt trick**(魔法常数 0x5f3759df)。这些是浮点数内部原理,理解它们让你深入到"数字不是抽象,是位模式"的层次。

心理锚点:做完今天,你应该:

1. 看到 `(a - b).length() < 100.0` 就立刻改写成 `(a - b).length_sq() < 10000.0`
2. 能解释 IEEE 754 浮点的位结构(符号位 / 指数 / 尾数)
3. 知道为什么现代 CPU 不需要 Quake III 的 trick(硬件 rsqrtss 指令)

这是判断"你懂数值优化"的标志。

## 2 · 心智模型

### 费曼类比:平方比较就像"省一道工序"

你要测两个人谁离你近。一种方法:

- A. 测两人各离你多远(开方),比大小
- B. 测两人各离你的"距离平方"(不开方),比大小

A 和 B 结论一样(距离平方的单调函数),但 B 省了开方这道工序。

**为什么大部分人用 A?** 因为直觉上"距离"是直接量。但工程上,只要比较两个距离,**平方版本和原版本结论一样**。这个习惯一旦养成,你会到处看到优化机会。

### 严谨定义:length 和 length_sq 的关系

**勾股定理**:向量 `v = (x, y)` 的长度 `|v| = √(x² + y²)`。

**平方长度**(length squared):`|v|² = x² + y² = v · v`(点积自己)。

**单调性**:对正数 a, b,`a < b ⟺ a² < b²`(平方函数在正数上单调递增)。所以:

```
|v1| < |v2|   ⟺   |v1|² < |v2|²
|v| < R       ⟺   |v|² < R²
```

比较距离 < R,等价于比较距离平方 < R²。

### 数值例子

3D 空间两点 (0, 0, 0) 和 (3, 4, 0)。距离 = √(9+16+0) = √25 = 5。

- 真实距离:5
- 平方距离:25

判断"距离 < 6":

- 用 length:`5 < 6` ✓
- 用 length_sq:`25 < 36` ✓(6² = 36)

结论一致,length_sq 版本省了一个 sqrt。

### 为什么 sqrt 慢?

CPU 的算术指令的时钟周期数(现代 x86_64):

| 指令 | 含义 | 大约 cycle |
|---|---|---|
| ADDSS | f32 加法 | 3-4 |
| MULSS | f32 乘法 | 3-5 |
| SQRTSS | f32 开方 | 13-18 |
| DIVSS | f32 除法 | 11-14 |
| RSQRTSS | f32 近似 1/√x | 4-5 |

加法和乘法是 1 个 cycle 量级(管线化),开方是 15 cycle 量级——**慢 4-5 倍**。

**为什么 sqrt 这么慢?** 因为硬件实现 sqrt 需要迭代算法(Newton-Raphson 或类似),不像加法那样有直接的组合电路。除法也类似(迭代),所以也慢。

**RSQRTSS**(approximate reciprocal square root)是硬件提供的 1/√x 近似指令,只 4-5 cycle。精度 11-12 bit(相对误差 < 0.0003),游戏足够用。Day 042 的 `normalize` 函数如果用 RSQRTSS,可以快很多。

### IEEE 754 浮点表示

**f32 的位结构**(32 位):

```
符号位 | 指数(8位)  | 尾数(23位)
  1位  |   8位      |   23位
```

例如 `1.0` 在 f32 里:

```
0 | 01111111 | 00000000000000000000000
```

- 符号位 0(正)
- 指数 127(实际指数 = 127 - 127 = 0)
- 尾数 0(隐含的 1,所以值 = 1.0 × 2^0 = 1.0)

**指数的偏置**(bias):f32 的指数用"移码"表示,实际指数 = 存储值 - 127。这让负指数也能用正数存储(浮点的巧妙设计)。

**为什么这影响 sqrt?** 因为浮点数的位表示里,**指数和尾数是分开的**。sqrt 一个浮点数:

- 指数部分:sqrt(2^e) = 2^(e/2),需要除以 2(右移 1 位)
- 尾数部分:sqrt(1.mmmm) 需要开方(复杂)

指数部分的开方简单(右移),尾数部分的开方难(需要迭代)。这就是为什么 sqrt 慢——硬件必须迭代逼近。

### Quake III 的 fast inverse sqrt trick

1999 年,Quake III 源码里有这么一段:

```c
float Q_rsqrt(float number) {
    long i;
    float x2, y;
    const float threehalfs = 1.5F;

    x2 = number * 0.5F;
    y = number;
    i = *(long*)&y;                       // 把 float 的位模式当 long
    i = 0x5f3759df - (i >> 1);             // 魔法!
    y = *(float*)&i;
    y = y * (threehalfs - (x2 * y * y));   // Newton 迭代
    return y;
}
```

这段代码计算 `1/√x`(归一化需要),比标准 `1.0 / sqrt(x)` 快 3-4 倍。**核心魔法**:`0x5f3759df - (i >> 1)`。

**为什么这有效?**

第 1 步:`i = *(long*)&y`,把 float 的位模式当整数读。这是 type punning(类型双关),C 的经典 trick(Rust 用 `f32::to_bits()`)。

第 2 步:`i >> 1`,整数右移 1 位。对 IEEE 754 浮点位模式,右移 1 位**近似** sqrt 的效果——因为指数部分除以 2(右移)+ 尾数部分被"挤"到指数位。

第 3 步:`0x5f3759df - (i >> 1)`,减一个魔法常数修正偏移。0x5f3759df 是经验最优的修正值,让近似误差最小。

第 4 步:`y * (1.5 - 0.5 * x * y * y)`,一次 Newton 迭代提高精度。

结果:相对误差 < 0.175%,4 cycle 算出 1/√x(标准库 30+ cycle)。

**为什么现代不用?** 因为 Intel/AMD 加了 `RSQRTSS` 指令(2000 年 Pentium IV 引入 SSE2),硬件实现 1/√x,4-5 cycle。比软件 trick 还快。所以 Quake III 的 trick 在现代 CPU 上没意义,但**理解它**让你深入浮点。

**Rust 调用 RSQRTSS**:

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn fast_rsqrt(x: f32) -> f32 {
    use std::arch::x86_64::*;
    _mm_cvtss_f32(_mm_rsqrt_ss(_mm_set_ss(x)))
}
```

`_mm_rsqrt_ss` 是 SIMD 的标量版本,内部就是 RSQRTSS 指令。4 cycle 算出近似 1/√x。

### 实战:用 length_sq 替代 length

**场景 1:玩家和怪物的攻击距离**

```rust
// 慢:length()
let dist = (player.pos - monster.pos).length();
if dist < ATTACK_RANGE {
    attack();
}

// 快:length_sq()
let dist_sq = (player.pos - monster.pos).length_sq();
if dist_sq < ATTACK_RANGE * ATTACK_RANGE {
    attack();
}
```

性能差 4-6 倍。1000 个怪物 × 60 FPS × 4 倍 = 每秒节省 240000 个 sqrt 操作。

**场景 2:球形碰撞检测**(圆形 vs 圆形)

```rust
fn circles_collide(c1: Vec2, r1: f32, c2: Vec2, r2: f32) -> bool {
    // 慢
    // (c1 - c2).length() < r1 + r2

    // 快
    let sum_r = r1 + r2;
    (c1 - c2).length_sq() < sum_r * sum_r
}
```

**场景 3:AI 视野判断**

```rust
// 怪物能看到玩家?
fn can_see(monster: &Monster, player: &Player) -> bool {
    let to_player = player.pos - monster.pos;
    let dist_sq = to_player.length_sq();
    if dist_sq > VIEW_RANGE * VIEW_RANGE {
        return false;  // 太远看不见
    }
    let dist = dist_sq.sqrt();  // 这里才需要 sqrt,因为后面用单位向量
    let dir = to_player / dist;  // 归一化
    let dot = dir.dot(monster.facing);
    dot > VIEW_COS  // 视野半锥角
}
```

注意:即使最终要 length,也可以**先用 length_sq 排除**远距离,只对近距离的算 sqrt。这是"提前剔除"的优化思路。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏行业的性能优化习惯:

**1. 平方距离**:所有距离比较都用 length_sq。这是行业默认,所有游戏引擎(Unity、Unreal、Bevy)的内部代码都这么写。

**2. 球形碰撞优于 AABB**(某些场景):球碰撞 = `(c1-c2).length_sq() < (r1+r2)²`,4 个乘 + 2 个加 + 1 个比较,极快。AABB 碰撞需要 6 个比较(2D)或 9 个比较(3D)。但 AABB 更适合方形物体。

**3. 提前剔除**(early-out):先做最便宜的检查,只有通过才做贵的检查。

```rust
// 例子:AI 决策
for monster in &monsters {
    // 第 1 关:距离平方剔除(最快)
    let dist_sq = (player.pos - monster.pos).length_sq();
    if dist_sq > AI_RANGE_SQ { continue; }

    // 第 2 关:视野方向(中等)
    let dir = (player.pos - monster.pos).normalize();
    if dir.dot(monster.facing) < VIEW_COS { continue; }

    // 第 3 关:视线检查(最贵,需要 raycast)
    if !has_line_of_sight(monster.pos, player.pos) { continue; }

    // 通过所有检查,追击
    monster.chase_player();
}
```

绝大多数怪物在第 1 关就被剔除,只有少数到第 3 关。这种"漏斗"设计让性能可控。

### 3.2 · 🎨 图形学视角

图形学大量用 length_sq:

**1. 光源衰减**:`1/distance²`(物理正确的衰减)。distance² 直接用,不开方。

**2. 屏幕空间距离**:像素之间距离比较,用平方。

**3. Shader 优化**:GLSL/HLSL 用 `dot(v, v)` 算平方长度,避免 `length(v)`(内部 sqrt)。

```glsl
// 慢
float dist = length(uv - center);
if (dist < 0.5) { ... }

// 快
float dist_sq = dot(uv - center, uv - center);
if (dist_sq < 0.25) { ... }
```

GPU shader 里这种优化重要,因为 fragment shader 每像素跑一次,1080p 屏幕 200 万像素 = 200 万次。

**4. 球面 harmonics**(球谐函数):光照预计算用 length_sq 算球面上的积分。

**Linux 内核的浮点**:内核默认**禁用浮点**(用 `kernel_fpu_begin()` / `kernel_fpu_end()` 显式开关)。因为浮点上下文切换昂贵。所以内核代码不做 sqrt,需要时手动用整数或调用 libm(慢)。

**SIMD in kernel**:极少数场景内核用 SIMD(AES 加密、CRC32),需要显式保护上下文。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写法

```rust
impl Vec2 {
    pub fn length_sq(self) -> f32 {
        self.dot(self)  // = x*x + y*y
    }
    pub fn length(self) -> f32 {
        self.length_sq().sqrt()  // f32::sqrt()
    }
    pub fn distance_sq(self, other: Self) -> f32 {
        (self - other).length_sq()
    }
    pub fn distance(self, other: Self) -> f32 {
        (self - other).length()
    }
}
```

`f32::sqrt()` 是 Rust 标准库的方法,内部调用硬件 sqrtss(在 x86_64 上)。`libm` 的 sqrtf 在 Linux 上也是这个,但 Rust 不依赖 libm(除了 no_std 环境)。

#### 性能基准测试

```rust
// benches/length_bench.rs
use criterion::{black_box, criterion_group, criterion_main, Criterion};
use mygame::Vec2;

fn bench_length(c: &mut Criterion) {

    let v2 = Vec2::new(50.0, 75.0);

    c.bench_function("length", |b| b.iter(|| {
        black_box((black_box(v1) - black_box(v2)).length())

```

```bash

```

#### SIMD 优化的 length

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn length_simd(v: Vec2) -> f32 {
    use std::arch::x86_64::*;
    let v_packed = _mm_set_ps(v.x, v.y, 0.0, 0.0);
    let sq = _mm_mul_ps(v_packed, v_packed);
    // 水平加(2 个元素):hadd 两次
    let sum = _mm_add_ps(sq, _mm_shuffle_ps(sq, sq, 0b01_00_11_10));
    let result = _mm_cvtss_f32(_mm_sqrt_ss(sum));
    result
}
```

这个 SIMD 版本一次处理 4 个 f32(虽然只用 2 个),配合 SIMD 的 normalize 可以一次处理 4 个 Vec2。Day 112+ 专门讲。

## 5 · 对照与变奏

### 不同精度的浮点

| 类型 | 大小 | 指数位 | 尾数位 | 精度 | 何时用 |
|---|---|---|---|---|---|
| f16(half) | 2 字节 | 5 | 10 | 3 位小数 | GPU mediump,深度缓冲 |
| f32(single) | 4 字节 | 8 | 23 | 7 位小数 | 游戏主流 |
| f64(double) | 8 字节 | 11 | 52 | 15 位小数 | 科学计算、资产坐标 |
| f128(quad) | 16 字节 | 15 | 112 | 34 位小数 | 高精度物理 |

游戏开发统一用 f32(GPU 友好,CPU SIMD 友好)。例外:**大世界坐标**用 f64(避免远离原点时精度不够),渲染前转 f32。

### CPU vs GPU 浮点性能

**CPU**:每核每秒约 10 亿次 f32 运算(SIMD 不算)。

**GPU**:每秒约 10000 亿次 f32 运算(几千核并行)。

游戏开发:CPU 算游戏逻辑(少量复杂运算),GPU 算渲染(大量简单运算)。length_sq 优化在 CPU 端意义大(逻辑代码多),GPU 端 shader 也用但 GPU 太快不太在意。

### 历史演化

**1990s**:浮点慢,Quake III 的 trick 流行。

**2000s**:SSE 引入 RSQRTSS,硬件 trick 替代软件。

**2010s**:AVX 引入 VRSQRTPS(256 位版本),一次处理 8 个 f32。

**2020s**:GPU 通用计算(GPGPU),大量浮点搬到 GPU。

Casey 在 Day 047 教 Quake III trick 是教学价值——让你理解浮点原理。实际写代码,我们用现代 SIMD intrinsic。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 `(a - b).length() < R` 等价于 `(a - b).length_sq() < R²`?数学上严格吗?有没有边界情况?

**参考解答**:

**严格证明**:

length_sq(v) = |v|² = v · v,这是非负实数。

length(v) = √(length_sq(v)) = |v|,也是非负实数。

平方函数 f(x) = x² 在 x ≥ 0 上**严格单调递增**(导数 2x > 0 当 x > 0)。所以对任意 a, b ≥ 0:

```
a < b  ⟺  a² < b²
```

应用到距离比较:

```
|v| < R   (R > 0)
⟺ |v|² < R²   (两边平方,单调性保证等价)
⟺ length_sq(v) < R²
```

**边界情况**:R = 0 时,`|v| < 0` 永远 false,`|v|² < 0` 也永远 false(因为 length_sq ≥ 0)。等价。

R < 0 时无意义(距离不能 < 0),不在讨论范围。

**结论**:**严格等价**,没有边界问题。可以放心替换。

**唯一例外**:如果你需要 length 的具体值(不只是比较),不能省 sqrt。比如"显示距离数字给玩家"必须用 length。

```rust
// math.rs
impl Vec2 {
    pub fn distance_sq(self, other: Self) -> f32 {
        (self - other).length_sq()
    }
    pub fn distance(self, other: Self) -> f32 {
        (self - other).length()
    }
}

// benches/length_bench.rs
use criterion::{black_box, criterion_group, criterion_main, Criterion};
use mygame::Vec2;

fn bench_distances(c: &mut Criterion) {
    let v1 = Vec2::new(100.0, 200.0);
    let v2 = Vec2::new(50.0, 75.0);
    let range = 80.0_f32;
    let range_sq = range * range;

    c.bench_function("compare_length", |b| b.iter(|| {
        black_box(v1.distance(black_box(v2)) < range)
    }));

    c.bench_function("compare_length_sq", |b| b.iter(|| {
        black_box(v1.distance_sq(black_box(v2)) < range_sq)
    }));
}

criterion_group!(benches, bench_distances);
criterion_main!(benches);

// tests
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_distance_sq_equivalent() {
        let a = Vec2::new(0.0, 0.0);
        let b = Vec2::new(3.0, 4.0);
        let r = 6.0;

        let slow = a.distance(b) < r;
        let fast = a.distance_sq(b) < r * r;
        assert_eq!(slow, fast);
    }

    #[test]
    fn test_distance_sq_outside() {
        let a = Vec2::new(0.0, 0.0);
        let b = Vec2::new(10.0, 10.0);
        let r = 5.0;

        let slow = a.distance(b) < r;
        let fast = a.distance_sq(b) < r * r;
        assert_eq!(slow, fast);  // 都应该是 false
    }
}
```

**题**:在 3D 场景里,你有 1000 个粒子,每帧检查"是否进入球形触发器"(半径 R)。怎么写最快?

要求:

**提示**:

- 把 1000 个粒子的 x, y, z 分开存(SoA 布局):`xs: Vec<f32>, ys: Vec<f32>, zs: Vec<f32>`
- SIMD 版一次 load 8 个 x、8 个 y、8 个 z,算 8 个 distance_sq,和 R² 比较

```rust
mod math;

use math::Vec2;

const NUM_POINTS: usize = 10000;

fn main() {
    println!("=== 向量长度优化演示 ===\n");

    // === 数学验证 ===
    println!("--- 数学等价性 ---");
    let a = Vec2::new(0.0, 0.0);
    let b = Vec2::new(3.0, 4.0);
    println!("a = {:?}, b = {:?}", a, b);
    println!("distance(a, b) = {}", a.distance(b));        // 5
    println!("distance_sq(a, b) = {}", a.distance_sq(b));  // 25
    println!("R=6, length < R = {}", a.distance(b) < 6.0);
    println!("R=6, length_sq < R² = {}", a.distance_sq(b) < 36.0);

    // === 性能对比 ===
    println!("\n--- 性能对比(10000 点距离比较) ---");

    // 生成 10000 个随机点(用确定性的伪随机,不依赖 rand crate)
    let mut points = Vec::with_capacity(NUM_POINTS);
    let mut seed = 42u32;
    for _ in 0..NUM_POINTS {
        // 简单 LCG 伪随机
        seed = seed.wrapping_mul(1664525).wrapping_add(1013904223);
        let x = (seed as f32) / (u32::MAX as f32) * 1000.0;
        seed = seed.wrapping_mul(1664525).wrapping_add(1013904223);
        let y = (seed as f32) / (u32::MAX as f32) * 1000.0;
        points.push(Vec2::new(x, y));
    }

    let center = Vec2::new(500.0, 500.0);
    let range = 200.0_f32;
    let range_sq = range * range;

    // 方法 1:用 length(慢)
    let start = std::time::Instant::now();
    let mut count_slow = 0;
    for _ in 0..100 {
        count_slow = 0;
        for p in &points {
            if p.distance(center) < range {
                count_slow += 1;
            }
        }
    }
    let elapsed_slow = start.elapsed();

    // 方法 2:用 length_sq(快)
    let start = std::time::Instant::now();
    let mut count_fast = 0;
    for _ in 0..100 {
        count_fast = 0;
        for p in &points {
            if p.distance_sq(center) < range_sq {
                count_fast += 1;
            }
        }
    }
    let elapsed_fast = start.elapsed();

    println!("length 版本:    {:?}({} 点在范围内)", elapsed_slow, count_slow);
    println!("length_sq 版本: {:?}({} 点在范围内)", elapsed_fast, count_fast);
    println!("加速比: {:.1}x", elapsed_slow.as_secs_f64() / elapsed_fast.as_secs_f64());

    // === IEEE 754 位表示 ===
    println!("\n--- IEEE 754 浮点位表示 ---");
    let x: f32 = 1.0;
    println!("1.0 的位模式:0x{:08x}", x.to_bits());
    let y: f32 = 2.0;
    println!("2.0 的位模式:0x{:08x}", y.to_bits());
    let z: f32 = 0.5;
    println!("0.5 的位模式:0x{:08x}", z.to_bits());
    let neg: f32 = -1.0;
    println!("-1.0 的位模式:0x{:08x}", neg.to_bits());

    // === 汇编验证 ===
    println!("\n--- 汇编验证(自检) ---");
    println!("length 的实现:");
    println!("    fn length(x: f32, y: f32) -> f32 {{ (x*x + y*y).sqrt() }}");
    println!("编译后会包含 sqrtss 指令");
    println!("\nlength_sq 的实现:");
    println!("    fn length_sq(x: f32, y: f32) -> f32 {{ x*x + y*y }}");
    println!("编译后只有 mulss + addss,无 sqrtss");
}
```

### Troubleshooting

**问题 1**:`cargo bench` 报 "no benchmarks available"

原因:你没在 Cargo.toml 加 `[[bench]]` 配置。

修复:Cargo.toml 加:

```toml
[[bench]]
name = "length_bench"
harness = false

[dev-dependencies]
criterion = "0.5"
```

**问题 2**:基准测试结果不稳定,波动大

原因:CPU 频率动态调频(Boost),后台进程干扰。

修复:

- 用 `sudo cpupower frequency-set -g performance` 锁最高频
- 关掉浏览器等后台进程
- criterion 默认跑 100 次取统计,信任其方差报告

**问题 3**:你的 length_sq 没比 length 快多少

原因:可能 release 没开(`cargo bench` 默认 release,但 `cargo run` 默认 debug)。

修复:用 `cargo run --release` 或 `cargo bench`(自动 release)。

**问题 4**:用 SIMD intrinsic 报 "unsafe"

原因:SIMD intrinsic 是 unsafe,因为编译器无法验证目标 CPU 支持。

修复:用 `unsafe { ... }` 包起来,或加 `#[target_feature(enable = "avx2")]`。
