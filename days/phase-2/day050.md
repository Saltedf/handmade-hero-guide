
# Day 050 · 基础 Minkowski 碰撞检测

> Day 029 的 tile 碰撞检查"玩家 AABB 是否覆盖 Wall tile"。但游戏里还有"两个移动的 AABB 互撞"——玩家撞怪物、怪物撞玩家。直接判断"两个矩形重叠"逻辑繁琐(4 个比较)。Casey 在 Day 050 引入一个**数学变换**——Minkowski 差——把"两个矩形碰撞"化为"一个点是否在另一个矩形里"。一个公式:`|c1.x - c2.x| < (h1.x + h2.x) && |c1.y - c2.y| < (h1.y + h2.y)`。极简且高效。

## 0 · 为什么要有这一天

Day 029 的 tile 碰撞只解决一类问题:**静态网格 vs 动态玩家**。但游戏里还有:

- 玩家撞怪物(两个都动)
- 怪物互相撞(群体 AI)
- 投射物撞墙(子弹 vs 静态物体)
- 投射物撞怪物(子弹 vs 动态物体)

每个场景的"碰撞对"形状不同(矩形 vs 矩形、圆 vs 矩形、矩形 vs 三角形)。如果每种都写专用算法,代码爆炸。

**Minkowski 差**(Minkowski difference)是**通用框架**:把"两个形状碰撞"统一化为"一个点是否在变换后的形状内"。对最简单的 AABB(轴对齐矩形),变换后的形状还是 AABB,测试极简。对其他凸形状(圆、三角形),变换后的形状是另一个凸形状,用 GJK 等算法处理。

**Minkowski 的天才想法**:

> 不要判断"A 和 B 是否重叠",而是判断"A 中心相对 B 中心的位置,是否在 (A 大小 + B 大小) / 2 的范围内"。

这句话听起来抽象,但数学上极简:

```
A 和 B 都是 AABB:
  A 中心 = (ax, ay),半宽 (hwa, hha)
  B 中心 = (bx, by),半宽 (hwb, hhb)
  
A 和 B 重叠 ⟺ |ax - bx| < (hwa + hwb) 且 |ay - by| < (hha + hhb)
```

**4 个减法 + 2 个 abs + 2 个加法 + 2 个比较**。无 sqrt,无循环,无分支预测。每次约 5 ns。

Day 050 是 Phase 2 的**碰撞检测高潮**。所有后续碰撞代码(Day 056 tile 改 entity、Day 063 sim region、Day 068 pairwise rules)都基于 Minkowski 公式。

心理锚点:做完今天,你应该能:

1. 在白板上推 Minkowski 差公式(为什么是 abs + 加法)
2. 知道"AABB 碰撞 ⟺ Minkowski 形状包含原点"
3. 理解为什么 Minkowski 思想能推广到任意凸形状(GJK 算法)
4. 用 Rust 写出 5 行的 AABB 碰撞函数,且性能是计算几何最快的

这是判断"你懂碰撞检测"的标志。

## 2 · 心智模型

### 费曼类比:影子合并

想象两个矩形 A 和 B 在阳光下,各自投影到地面。投影是矩形。

**问题**:怎么判断 A 和 B 在 3D 空间重叠?

**Minkowski 的视角转换**:不要看 A 和 B,看它们的"合并投影"。

具体:

1. 把 A "压缩成一个点"(A 的中心点)
2. 把 B "膨胀":每一边外扩 A 的半宽
3. 检查"A 的中心点"是否在"膨胀后的 B"里

如果"是",原来 A 和 B 重叠。如果"否",不重叠。

这个变换的妙处:**两个形状的问题简化成一个点 vs 一个形状的问题**。

### 严谨定义:Minkowski 和与差

**Minkowski 和**(Minkowski sum):`A ⊕ B = { a + b | a ∈ A, b ∈ B }`。所有"A 的某点 + B 的某点"的位置的集合。

**Minkowski 差**(Minkowski difference):`A ⊖ B = A ⊕ (-B) = { a - b | a ∈ A, b ∈ B }`。所有"A 的某点 - B 的某点"的位置的集合。

**核心定理**:**A 和 B 相交 ⟺ 原点 ∈ A ⊖ B**。

**为什么?**

- 如果 A 和 B 相交,存在点 p ∈ A 且 p ∈ B。那么 p - p = 0 ∈ A ⊖ B(取 a = p, b = p)。
- 反过来,如果 0 ∈ A ⊖ B,存在 a ∈ A, b ∈ B 使 a - b = 0,即 a = b。所以 a 既在 A 也在 B,A 和 B 相交。

证毕。

### AABB 的 Minkowski 差

A 和 B 都是 AABB:

- A = [ax_min, ax_max] × [ay_min, ay_max]
- B = [bx_min, bx_max] × [by_min, by_max]

A ⊖ B 是什么形状?

**用中心 + 半宽表示**:A 中心 = (ax, ay),A 半宽 = (hwa, hha)。同理 B。

代入 Minkowski 差定义:

- A ⊖ B 的中心 = A 中心 - B 中心 = (ax - bx, ay - by)
- A ⊖ B 的半宽 = A 半宽 + B 半宽 = (hwa + hwb, hha + hhb)
- A ⊖ B 还是 AABB!

**测试原点是否在 A ⊖ B 内**:

```
原点 ∈ AABB(中心 c, 半宽 h)
⟺ |c.x| < h.x 且 |c.y| < h.y
```

代入 c = (ax - bx, ay - by),h = (hwa + hwb, hha + hhb):

```
|ax - bx| < (hwa + hwb) 且 |ay - by| < (hha + hhb)
```

这就是 AABB 碰撞公式。

### 完整推导(几何版本)

不通过 Minkowski 抽象,直接推:

**A 和 B 重叠的条件**:x 方向重叠 且 y 方向重叠。

**x 方向重叠**:A 的 x 范围和 B 的 x 范围有交集。

```
A 的 x 范围:[ax - hwa, ax + hwa]
B 的 x 范围:[bx - hwb, bx + hwb]

重叠 ⟺ max(ax - hwa, bx - hwb) < min(ax + hwa, bx + hwb)
```

化简:

```
情况 1:ax < bx( A 在 B 左边)
  max(ax - hwa, bx - hwb) = bx - hwb
  min(ax + hwa, bx + hwb) = ax + hwa
  重叠 ⟺ bx - hwb < ax + hwa ⟺ bx - ax < hwa + hwb ⟺ |ax - bx| < hwa + hwb

情况 2:ax >= bx(对称)
  推出相同结论
```

所以 x 方向重叠 ⟺ `|ax - bx| < hwa + hwb`。y 方向同理。

### 数值例子

A 中心 (0, 0),半宽 (10, 10)。B 中心 (15, 0),半宽 (8, 8)。

- |ax - bx| = 15
- hwa + hwb = 10 + 8 = 18
- 15 < 18 ✓(x 重叠)
- |ay - by| = 0 < 18 ✓(y 重叠)
- **A 和 B 重叠**!

视觉验证:A 从 -10 到 +10,B 从 +7 到 +23。x 方向重叠 [7, 10](3 像素)。y 方向完全重叠。

再试:B 中心 (20, 0):

- |ax - bx| = 20
- 20 > 18 ✗(x 不重叠)
- **A 和 B 不重叠**

A 从 -10 到 +10,B 从 +12 到 +28。x 方向不重叠(中间有 [10, 12] 间隙 2 像素)。

### 边界情况

**严格 vs 非严格**(open vs closed):

```rust
// 严格(<):边缘相切不算碰撞
delta.x.abs() < sum_half.x

// 非严格(<=):边缘相切算碰撞
delta.x.abs() <= sum_half.x
```

游戏通常用严格(<),因为"刚好接触"不算"碰撞"(玩家碰到墙但不卡住)。物理引擎可能用非严格。

**精度**:浮点比较,`|ax - bx| < hwa + hwb` 可能在边界附近不稳定(浮点误差)。如果需要严格判定,加 epsilon:

```rust
delta.x.abs() < sum_half.x + epsilon
```

### 代码实现

```rust
use crate::math::Vec2;

pub struct AABB {
    pub center: Vec2,
    pub half_extent: Vec2,
}

impl AABB {
    pub fn new(center: Vec2, half_extent: Vec2) -> Self {
        Self { center, half_extent }
    }

    pub fn collide(&self, other: &Self) -> bool {
        let delta = self.center - other.center;
        let sum_half = self.half_extent + other.half_extent;
        delta.x.abs() < sum_half.x && delta.y.abs() < sum_half.y
    }

    pub fn min(&self) -> Vec2 {
        self.center - self.half_extent
    }

    pub fn max(&self) -> Vec2 {
        self.center + self.half_extent
    }
}
```

**几行代码**,极快。

### 推广到其他形状

**圆 vs 圆**:

- 圆 Minkowski 差是更大的圆,半径 = r1 + r2
- 原点在差内 ⟺ 中心距离 < r1 + r2
- 用 Day 047 的 length_sq:`(c1 - c2).length_sq() < (r1 + r2).powi(2)`

```rust
pub fn circles_collide(c1: Vec2, r1: f32, c2: Vec2, r2: f32) -> bool {
    let sum_r = r1 + r2;
    (c1 - c2).length_sq() < sum_r * sum_r
}
```

**AABB vs 圆**:

- Minkowski 差是"圆角矩形"(矩形 + 圆边)
- 算法:把圆心 clamp 到 AABB,然后看 clamp 后距离 < r

```rust
pub fn aabb_circle_collide(aabb: &AABB, c: Vec2, r: f32) -> bool {
    let closest = Vec2::new(
        c.x.max(aabb.min().x).min(aabb.max().x),
        c.y.max(aabb.min().y).min(aabb.max().y),
    );
    (c - closest).length_sq() < r * r
}
```

**任意凸多边形 vs 凸多边形**:

- Minkowski 差是另一个凸多边形
- 测试原点在差内 = GJK(Gilbert-Johnson-Keerthi)算法
- GJK 迭代构造 simplex,判断原点是否在凸包内
- 复杂但通用,Day 431+ 才深入

**Minkowski 是统一视角**:所有碰撞检测最终都是"原点是否在 Minkowski 差内"。AABB / 圆是特殊情况(差是简单形状,直接测试),任意凸形状用 GJK。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏行业的碰撞检测算法谱系:

**1. AABB**(Day 050):矩形,最快,主流 2D 游戏。

**2. Circle**(球):圆形物体,比 AABB 稍慢但更精确(圆形角色)。

**3. OBB**(Oriented Bounding Box,有向包围盒):旋转的矩形。比 AABB 精确(适用旋转物体),但 SAT 算法稍复杂。

**4. Capsule**(胶囊):2D 是"线段两端加圆",3D 是"圆柱加两端的球"。角色 hitbox 常用(人形角色近似胶囊)。

**5. Convex polygon**(凸多边形):任意凸形状。SAT(Separating Axis Theorem)算法。

**6. Concave / Mesh**(凹多边形 / 网格):分解成凸多边形,或用 BVH 加速。

**7. Voxel**(体素):Minecraft 风。grid-based,直接索引。

Casey 在 HH 主要用 AABB(简单够用)。Day 50 之后所有 entity 碰撞都是 AABB。

#### Broadphase vs Narrowphase

1000 个 entity 两两检测 = 100 万次。AABB 虽快,100 万次还是太多。

**Broadphase**(粗筛):快速排除"绝对不可能碰撞"的对。常用 spatial hash(Day 057)、sweep and prune、BVH。

**Narrowphase**(细查):对粗筛通过的对,精确检测。Minkowski / GJK / SAT 在这里。

游戏物理引擎(Box2D、rapier)的架构都是"broadphase + narrowphase"。Casey 在 Day 057 实现 spatial hash 作为 broadphase。

### 3.2 · 🎨 图形学视角

图形学里 Minkowski 思想的应用:

**1. CSG**(Constructive Solid Geometry,构造实体几何):用布尔运算(并、交、差)组合形状。Minkowski 和是其中之一。

**2. 膨胀 / 腐蚀**(morphological dilation / erosion):图像处理。膨胀 = Minkowski 和一个结构元素。

**3. 路径规划**(path planning):机器人路径规划用 Minkowski 差算"机器人能通过的最小空间"。

**4. 阴影**(shadow volume):实时阴影算法。基于"轮廓 + Minkowski 思想"。

**5. SDF**(Signed Distance Field):字体 / 形状用距离场表示。距离场的 Minkowski 性质让碰撞 / 渲染统一。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写法

```rust
#[derive(Copy, Clone, Debug)]
pub struct AABB {
    pub center: Vec2,
    pub half_extent: Vec2,
}

impl AABB {
    pub fn from_min_max(min: Vec2, max: Vec2) -> Self {
        let center = (min + max) * 0.5;
        let half_extent = (max - min) * 0.5;
        Self { center, half_extent }
    }

    pub fn contains(&self, point: Vec2) -> bool {
        let delta = point - self.center;
        delta.x.abs() < self.half_extent.x && delta.y.abs() < self.half_extent.y
    }

    pub fn collide(&self, other: &Self) -> bool {
        let delta = self.center - other.center;
        let sum_half = self.half_extent + other.half_extent;
        delta.x.abs() < sum_half.x && delta.y.abs() < sum_half.y
    }
}
```

**Copy / Clone**:AABB 16 字节,可以 Copy。函数传 `&AABB` 或 `AABB` 都行。

| 算法 | 形状支持 | 复杂度 | 何时用 |
|---|---|---|---|

详细说明:

- **AABB**:本项目核心。Casey 用。
- **圆**:更精确(圆角色),但 `length_sq` 比 4 个减法稍慢。
- **SAT**(Separating Axis Theorem):任意凸多边形,检查所有可能的"分离轴"。Day 069+ 用。
- **GJK**:基于 Minkowski 差的迭代算法。工业级物理引擎。
- **BVH**:层次包围盒,加速 raycast。
- **Spatial Hash**:broadphase 加速。

## 5 · 对照与变奏

### 2D vs 3D 碰撞

| | 2D | 3D |
|---|---|---|
| 基本形状 | AABB(矩形)、Circle、Polygon | AABB(立方体)、Sphere、OBB、Mesh |
| Minkowski 差 | 2D 形状 | 3D 形状 |
| GJK | 简化版(2D simplex) | 标准版(3D simplex = 四面体) |
| 性能 | 极快(简单形状 O(1)) | 较慢(三角形 mesh O(n)) |

Day 50 的 2D Minkowski 公式直接推广到 3D AABB:

```
3D AABB 碰撞:
|ax - bx| < hwa + hwb &&
|ay - by| < hha + hhb &&
|az - bz| < hwa + hwb
```

加一个 z 维度的检查。Phase 3+ 进入 3D 时直接用。

### 静态碰撞 vs 连续碰撞

**静态**(static,Day 050):检查当前帧的两形状是否重叠。简单快,但有 tunneling(高速穿墙)。

**连续**(continuous / swept):检查"从上一帧位置到当前帧位置的轨迹"是否相交。复杂,但精确。

Day 045 的 temporal search 是连续碰撞的工程近似。Day 048 的线段相交是连续碰撞的精确实现。Day 50 是静态碰撞,需要配合 Day 045 防止 tunneling。

### 碰撞响应

碰撞检测回答"撞了吗"。碰撞响应(C collision response)回答"撞了之后怎么动"。

**响应方式**:

1. **停止**:把速度归零(撞墙就停)
2. **滑动**:沿墙滑(Day 029 分轴)
3. **反弹**:反射(Day 044)
4. **推开**:penetration resolution,把物体分离
5. **触发事件**:触发脚本(踩到陷阱扣血)

Casey 在 HH 主要用 1 + 2(撞墙停 + 滑)。Day 069+ pairwise rules 加更复杂响应。

### Lv1 · 概念辨析

**题**:Minkowski 差的核心洞察是什么?为什么 AABB 的 Minkowski 差还是 AABB(而不是更复杂形状)?

**参考解答**:

**核心洞察**:两个形状 A 和 B 是否相交 ⟺ 原点在 A ⊖ B 内。这把"形状 vs 形状"化为"点 vs 形状"。

**AABB ⊖ AABB 还是 AABB 的原因**:

A ⊖ B = { a - b | a ∈ A, b ∈ B }。

A = 中心 (ax, ay) + 范围 [-hwa, hwa] × [-hha, hha]
B = 中心 (bx, by) + 范围 [-hwb, hwb] × [-hhb, hhb]

a - b 的 x 分量 = ax + α - (bx + β),α ∈ [-hwa, hwa],β ∈ [-hwb, hwb]

α - β ∈ [-hwa - hwb, hwa + hwb](两个对称区间的差还是对称区间)

所以 a - b 的 x 分量 ∈ [ax - bx - hwa - hwb, ax - bx + hwa + hwb]

这是以 (ax - bx) 为中心,半宽 (hwa + hwb) 的区间。**还是对称区间**,所以 A ⊖ B 还是 AABB,只是中心 = A 中心 - B 中心,半宽 = A 半宽 + B 半宽。

**直觉**:AABB 的"对称性"(对中心对称)在 Minkowski 差下保持。如果 A 和 B 不是对称的(比如三角形),差会更复杂。

### Lv2 · 动手实践

**题**:在你的 HH Rust 项目里实现 AABB 碰撞:

2. 实现 `collide(&self, other) -> bool`

4. 实现 `contains(point) -> bool`
5. **测试**:
   - 重叠:两个矩形部分覆盖
   - 不重叠 x 方向
   - 不重叠 y 方向
   - 相切(边缘接触,严格 < 应该 false)
   - 一个包含另一个
6. **应用**:写 `player_collides_any_monster(player: &AABB, monsters: &[AABB]) -> bool`

**参考解答**:

```rust
// src/aabb.rs
use crate::math::Vec2;

#[derive(Copy, Clone, Debug, PartialEq)]
pub struct AABB {
    pub center: Vec2,
    pub half_extent: Vec2,
}

impl AABB {
    pub fn new(center: Vec2, half_extent: Vec2) -> Self {
        Self { center, half_extent }
    }

    pub fn from_min_max(min: Vec2, max: Vec2) -> Self {
        Self {
            center: (min + max) * 0.5,
            half_extent: (max - min) * 0.5,
        }
    }

    pub fn min(&self) -> Vec2 {
        self.center - self.half_extent
    }

    pub fn max(&self) -> Vec2 {
        self.center + self.half_extent
    }

    pub fn contains(&self, point: Vec2) -> bool {
        let d = point - self.center;
        d.x.abs() < self.half_extent.x && d.y.abs() < self.half_extent.y
    }

    pub fn collide(&self, other: &Self) -> bool {
        let d = self.center - other.center;
        let sum_half = self.half_extent + other.half_extent;
        d.x.abs() < sum_half.x && d.y.abs() < sum_half.y
    }
}

pub fn player_collides_any_monster(player: &AABB, monsters: &[AABB]) -> bool {
    for m in monsters {
        if player.collide(m) {
            return true;
        }
    }
    false
}

#[cfg(test)]
mod tests {
    use super::*;

    fn aabb(cx: f32, cy: f32, hw: f32, hh: f32) -> AABB {
        AABB::new(Vec2::new(cx, cy), Vec2::new(hw, hh))
    }

    #[test]
    fn test_overlap() {
        let a = aabb(0.0, 0.0, 10.0, 10.0);
        let b = aabb(15.0, 0.0, 10.0, 10.0);
        // |0-15| = 15 < 20, |0-0| = 0 < 20
        assert!(a.collide(&b));
    }

    #[test]
    fn test_separate_x() {
        let a = aabb(0.0, 0.0, 10.0, 10.0);
        let b = aabb(50.0, 0.0, 10.0, 10.0);
        assert!(!a.collide(&b));
    }

    #[test]
    fn test_separate_y() {
        let a = aabb(0.0, 0.0, 10.0, 10.0);
        let b = aabb(0.0, 50.0, 10.0, 10.0);
        assert!(!a.collide(&b));
    }

    #[test]
    fn test_touch_strict_false() {
        // 边缘正好接触,严格 < 不算
        let a = aabb(0.0, 0.0, 10.0, 10.0);
        let b = aabb(20.0, 0.0, 10.0, 10.0);
        // |0-20| = 20, sum_half = 20, 20 < 20 false
        assert!(!a.collide(&b));
    }

    #[test]
    fn test_contained() {
        let big = aabb(0.0, 0.0, 100.0, 100.0);
        let small = aabb(0.0, 0.0, 10.0, 10.0);
        assert!(big.collide(&small));
    }

    #[test]
    fn test_player_vs_monsters() {
        let player = aabb(50.0, 50.0, 16.0, 16.0);
        let monsters = vec![
            aabb(100.0, 50.0, 10.0, 10.0),  // 远
            aabb(60.0, 60.0, 10.0, 10.0),   // 近,应该撞
            aabb(200.0, 200.0, 5.0, 5.0),   // 远
        ];
        assert!(player_collides_any_monster(&player, &monsters));
    }

    #[test]
    fn test_player_vs_no_monsters() {
        let player = aabb(50.0, 50.0, 16.0, 16.0);
        let monsters = vec![
            aabb(200.0, 50.0, 10.0, 10.0),
            aabb(50.0, 200.0, 10.0, 10.0),
        ];
        assert!(!player_collides_any_monster(&player, &monsters));
    }
}
```

**关键决策解释**:

- `from_min_max` 是常见构造方式(地图编辑器通常用 min/max,游戏内用 center/half)。
- 测试 `test_touch_strict_false` 验证严格 < 行为(边缘不算碰撞)。如果改成 <=,这个测试要改。
- `player_collides_any_monster` 短路返回——第一个撞到的就 true。

### Lv3 · 迁移设计

**题**:实现 **3D AABB vs Sphere** 碰撞:

- AABB 中心 c_a,半宽 (hx, hy, hz)
- Sphere 中心 c_s,半径 r
- 推导公式 + 实现代码 + 测试

**提示**:

- Minkowski 差是"圆角立方体"(立方体外加球壳)
- 算法:把球心 clamp 到 AABB,看 clamp 后距离 < r
- clamp:每个分量取 max(aabb_min, min(sphere_center, aabb_max))
- 距离 < r ⟺ (sphere - clamped).length_sq() < r²

为什么这个练习有价值?因为它把 Minkowski 思想从 2D 推广到 3D 混合形状(AABB + 球)。游戏里玩家经常是 AABB + 球混合 hitbox(身体 AABB + 头球)。理解这个,你能做 3D 游戏的玩家 vs 投射物碰撞。

    println!("  |ax - bx| = |0 - 15| = 15");
    println!("  hwa + hwb = 10 + 10 = 20");

    println!("A vs B_touch:");

        let b = AABB::new(Vec2::new(0.5, 0.0), Vec2::new(1.0, 1.0));

### Troubleshooting

**问题 1**:测试 `test_touch_strict_false` 失败

原因:你的 collide 用 `<=` 而不是 `<`。

修复:改成严格 `<`,或在测试用 `>=`。

**问题 2**:玩家高速穿过怪物

原因:Day 050 是静态碰撞,没有 temporal search。

修复:配合 Day 045 的 temporal search,每步用 collide 检测。

**问题 3**:怪物卡在玩家身上,推不开

原因:collide 只返回 true/false,不告诉"重叠多少"。响应代码不知道推多远。

修复:加 `penetration()` 方法返回穿透深度:

```rust
impl AABB {
    pub fn penetration(&self, other: &Self) -> Vec2 {
        let d = self.center - other.center;
        let sum_half = self.half_extent + other.half_extent;
        Vec2::new(
            sum_half.x - d.x.abs(),
            sum_half.y - d.y.abs(),
        )
    }
}
```

返回两个方向的重叠量。取较小的一个作为"最小推开方向"。

**问题 4**:OBB(旋转 AABB)碰撞

原因:Day 050 只处理轴对齐。旋转的矩形需要 SAT。

修复:用 SAT 算法,或者外部 parry 库。
