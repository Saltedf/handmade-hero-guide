
# Day 060 · 生命值:RPG 战斗的基石

> 小怪有 30 HP,玩家砍一刀 10 伤害,火球 20 伤害。HP 到 0 怪死。这听起来无聊到不值得写,但**怎么实现"死"**这件小事藏着一个反直觉的工程决策——为什么 Casey 不在 hp=0 时立即删 entity?

## 0 · 为什么要有这一天

"加 HP"听起来是 5 分钟的事:

```rust
struct Entity {
    hp: i32,
}
fn take_damage(e: &mut Entity, dmg: i32) {
    e.hp -= dmg;
    if e.hp <= 0 { /* 删除? */ }
}
```

但你立刻撞到三个问题:

**问题 1:删了之后呢?** 
你 `entities.remove(dead_monster_idx)`,然后下一帧 `entities.iter()` 还能拿到它的引用吗?它的攻击目标被删了,投射手还在追它的位置(空坐标)。**死掉的 entity 还在被引用**。

**问题 2:死掉的 entity 应该立刻从屏幕消失,还是先播个倒地动画?**
玩家看到怪"瞬间蒸发"会觉得很 low。应该怪播一段"翻倒 + 渐隐"的动画,大约 0.5 秒,然后才真正消失。**死掉的 entity 还要存在 0.5 秒**。

**问题 3:玩家死了游戏怎么处理?**
玩家 HP=0,你不能 `remove(player_idx)`——玩家不是怪。玩家进入"Dying"状态,相机停留几秒,显示 Game Over UI。**死的处理因 entity 类型而异**。

这三个问题指向同一个设计:**HP=0 不等于"删除",而是"进入 Dying 状态"**。Dying 状态下:
- entity 还在 entity 列表里(不删)
- 不 update AI / 物理(已经死了)
- 仍 update 渲染(播倒地动画)
- 动画结束后,转入"Dead 状态",等待清理
- 清理发生在帧末(不在 update 中间),避免迭代器失效

这套设计叫**两阶段删除(two-phase deletion)**,是游戏开发的常见模式。今天 Casey 实现它。

读完今天,你要做到:
- 看见 `e.hp = 0` 不再条件反射地想 `remove(e)`,而是想"转 Dying 状态"
- 理解"为什么不在 update 循环里 remove"——迭代器失效 / 引用悬空
- 能动手实现 hp / take_damage / Dying / Dead / cleanup 的完整流程
- 知道游戏行业术语"poof"(瞬间消失)vs "fade"(渐隐)

如果你卡在"为什么不能在循环里 remove",回去看 §2.3。

## 1 · Casey 今天做了什么

Casey 第 60 集做的事情:

1. 在 entity struct 里加 `hp: i32` 和 `max_hp: i32` 字段
2. 加 `take_damage(dmg)` 方法,扣血并检查 hp

## 2 · 心智模型

### 2.1 类比:医院急诊

医院的急诊流程:

1. 病人来(Alive),正常处理
2. 病人伤重(Dying),送进 ICU——还在医院里,不送停尸房
3. ICU 里观察 24 小时,确认死亡(Dead),才转停尸房
4. 停尸房定期清理(从系统移除)

为什么不在病人伤重时直接送停尸房?因为:
- **信息还在用**:家属来看他,还在记录生命体征
- **流程未完成**:可能还有未结算的账单 / 器官捐献流程
- **批量清理**:停尸房定期统一处理,效率高

游戏 entity 同理。HP=0 时直接 remove:
- **数据还在用**:其他 entity 引用它(攻击目标、AI 目标)
- **流程未完成**:倒地动画 / 死亡音效还没播
- **批量清理**:帧末统一 remove,避免循环中删除的复杂度

### 2.2 严谨:EntityState 状态机

```rust
#[derive(Clone, Copy, PartialEq, Debug)]
enum EntityState {
    Alive,
    Dying,    // hp=0,正在播死亡动画
    Dead,     // 动画播完,等清理
}

struct Entity {
    pos: Vec2,
    half: Vec2,
    kind: EntityKind,
    state: EntityState,
    hp: i32,
    max_hp: i32,
    dying_timer: f32,  // Dying 状态计时(动画时长)
}

impl Entity {
    fn take_damage(&mut self, dmg: i32) {
        if self.state != EntityState::Alive { return; }
        self.hp = (self.hp - dmg).max(0);
        if self.hp == 0 {
            self.state = EntityState::Dying;
            self.dying_timer = 0.5;  // 0.5 秒倒地动画
            // 播死亡音效
        }
    }

    fn update(&mut self, dt: f32) {
        match self.state {
            EntityState::Alive => {
                // update AI / 物理 / 动画(完整)
            }
            EntityState::Dying => {
                // 只 update 动画,不 update AI / 物理
                self.dying_timer -= dt;
                if self.dying_timer <= 0.0 {
                    self.state = EntityState::Dead;
                }
            }
            EntityState::Dead => {
                // 什么都不做,等帧末清理
            }
        }
    }
}
```

**关键设计**:
- `take_damage` 内部不直接改 hp 到负数——`.max(0)` 钳住
- 检查 `state != Alive` 才允许扣血(死掉的不能再被扣)
- HP=0 立刻转 Dying(不是 Dead)
- Dying 计时到 0 转 Dead
- Dead 等帧末清理

### 2.3 帧末清理:避免迭代器失效

最常见 Rust 坑:

```rust
// 错误!
for (i, e) in entities.iter_mut().enumerate() {
    e.update(dt);
    if e.state == EntityState::Dead {
        entities.remove(i);  // 在循环中删除!
    }
}
```

这段代码的 bug:
1. `remove(i)` 把后面的元素前移,但 `iter_mut` 还在按原索引迭代——跳过下一个元素
2. Rust 编译器拒绝(借用冲突),但 C 会让你写出这个 bug,然后 debug 几小时

正确做法:**收集要删的索引,循环外删**:

```rust
fn frame_update(entities: &mut Vec<Entity>, dt: f32) {
    // 阶段 1:update
    for e in entities.iter_mut() {
        e.update(dt);
    }
    // 阶段 2:过滤掉 Dead
    entities.retain(|e| e.state != EntityState::Dead);
}
```

`Vec::retain` 是 Rust 的标准做法——传一个谓词(`fn(&T) -> bool`),保留谓词返回 true 的元素,删除返回 false 的。**O(N) 一次扫完,无迭代器失效**。

如果用 `HashMap<EntityId, Entity>`:

```rust
world.entities.retain(|_, e| e.state != EntityState::Dead);
```

HashMap 也有 retain。

### 2.4 死亡事件的副作用

HP=0 时除了转 Dying 状态,通常还要做副作用:
- 播死亡音效
- 给玩家加经验值
- 掉落物品
- 触发剧情

这些副作用不能写在 `take_damage` 里(它被很多地方调用,容易重复触发)。Casey 在 `take_damage` 内只设置状态,副作用在专门的 `on_died` 函数:

```rust
impl Entity {
    fn take_damage(&mut self, dmg: i32) {
        if self.state != EntityState::Alive { return; }
        let was_alive = self.hp > 0;
        self.hp = (self.hp - dmg).max(0);
        if was_alive && self.hp == 0 {
            self.state = EntityState::Dying;
            self.dying_timer = 0.5;
        }
    }
}

// 在 frame_update 里,扫一遍刚进入 Dying 的 entity,触发副作用
fn on_died(world: &mut World, id: EntityId) {
    let e = &world.entities[&id];
    match e.kind {
        EntityKind::Monster => {
            world.player.exp += 10;
            world.audio.play(SoundId::MonsterDie);
            spawn_loot_drop(world, e.pos);
        }
        EntityKind::Player => {
            world.audio.play(SoundId::PlayerDie);
            world.game_over_screen = true;
        }
        _ => {}
    }
}
```

把状态变更(在 take_damage)和副作用(在 on_died)分开,代码更易测试和复用。

### 2.5 HP 的常见扩展

基础 HP 系统之上,游戏行业加了无数变种:

| 扩展 | 例子 |
|---|---|
| max_hp | 升级时加,max 不超过 max_hp |
| defense | 减伤:`effective_dmg = dmg - defense` |
| armor / resist | 按百分比减伤:`dmg * (1 - armor_pct)` |
| regen | 每秒回血:`hp += regen * dt` |
| heal | 加血:`hp = (hp + amount).min(max_hp)` |
| damage_over_time | 中毒:`dot_timer += dt; if dot_timer > 1 { take_damage(5); dot_timer = 0 }` |
| critical_hit | 暴击:10% 概率伤害 ×2 |
| damage_type | 物理 / 魔法 / 真实(无视防御) |
| invulnerability | 短暂无敌(被击后 0.5s 无敌) |

Casey 的 HH 不会全部实现,只做 hp / max_hp / heal / take_damage。其他扩展是 Day 180+ 的 debug UI 实时调时加。

### 3.1 · 🎮 游戏编程视角

游戏行业的 HP 系统叫 **combat system** 或 **damage system**,每个引擎都有:

- 可破坏箱(撞碎后播碎片动画再删)

### 3.2 · 🐧 Linux 系统编程视角

Linux 进程的死亡流程和 entity 死亡流程**惊人相似**:

| Entity | Linux 进程 |
|---|---|
| Alive | Running / Sleeping |
| Dying | Zombie(僵尸进程) |
| Dead | Reaped(父进程 wait 后从进程表移除) |
| take_damage | kill(pid, SIGKILL) |
| dying_timer | 信号处理时间 |
| on_died | atexit handler |

**僵尸进程(Zombie)**:进程已经退出(exit() 调用了,相当于 hp=0),但父进程还没 wait()。Zombie 状态下进程的 PID / 退出码 / 资源使用统计还保留,等父进程查询。**这就是 entity 的 Dying 状态——主体没了,数据还在**。

**Reaped**:父进程 wait() 后,Zombie 被彻底清理(从进程表移除)。**这就是 Dead → retain()**。

启示:**操作系统的设计模式和游戏开发惊人一致**。"两阶段删除"不是游戏专属,是处理"异步删除 + 资源清理"的通用模式。

### 3.3 · 🦀 Rust 生态视角

Rust 表达"两阶段删除"最干净的方式是用 enum state:

```rust
enum EntityState { Alive, Dying { timer: f32 }, Dead }
```

variant `Dying` 带数据(timer),这是 Rust enum 的强大之处——**variant 关联数据**。每个 state 的数据存在 union 里:

```rust
match self.state {
    EntityState::Alive => { /* 无 timer */ }
    EntityState::Dying { timer } => {
        // 这里 timer 是 f32,直接可用
        if timer <= 0.0 { self.state = EntityState::Dead; }
    }
    EntityState::Dead => {}
}
```

对比 C 的写法:

```c
// C:state 是 enum,timer 是单独字段,即使 Alive 也占内存
enum EntityState { ALIVE, DYING, DEAD };
struct Entity {
    enum EntityState state;
    float dying_timer;  // 只有 DYING 时有效
};
```

C 的写法每个 entity 都占 timer 字段,即使 99% 的 entity 都是 Alive(没在死亡动画)。Rust 的 enum variant 带数据更紧凑——但因为 Rust enum 取最大 variant 大小,效果一样。

#### Vec::retain 的实现

`retain` 是 Rust 标准库 Vec 的方法,实现大概:

```rust
pub fn retain<F>(&mut self, mut f: F) where F: FnMut(&T) -> bool {
    let mut read = 0;
    let mut write = 0;
    while read < self.len() {
        if f(&self[read]) {
            self[write] = unsafe { std::ptr::read(&self[read]) };
            write += 1;
        } else {
            // 删除:drop 这个元素
            unsafe { std::ptr::drop_in_place(&mut self[read]); }
        }
        read += 1;
    }
    self.set_len(write);
}
```

一次 O(N) 扫描,无额外分配。比 `filter().collect()` 高效(后者要分配新 Vec)。

#### Option<i32> vs i32

如果 entity 类型不需要 HP(比如 Wall),怎么设计?

```rust
// 方案 A:所有 entity 都有 hp,Wall 设一个特殊值
struct Entity { hp: i32 }
// Wall 设 hp = i32::MAX,反正不会被攻击

// 方案 B:Option<i32>
struct Entity { hp: Option<i32> }
// Wall 是 None,怪是 Some(100)

// 方案 C:用 enum 分 kind
enum Entity {
    Wall { pos: Vec2, /* no hp */ },
    Monster { pos: Vec2, hp: i32 },
}
```

Casey 选 A(简单,所有 entity 同布局)。Rust 项目通常选 C(更类型安全)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么不能在 update 循环中直接 remove Dead entity?用 Rust 借用规则解释。

**参考解答**:
```rust
// 假设写法
for (i, e) in entities.iter_mut().enumerate() {
    e.update(dt);
    if e.state == EntityState::Dead {
        entities.remove(i);  // 编译错误!
    }
}
```

Rust 编译错误:`cannot borrow entities as mutable more than once`。`iter_mut()` 已经借用了 entities 的可变引用,在迭代期间不能再次借用(包括 remove 的内部借用)。

即使绕过编译器(用 unsafe 或 unsafe 的 C),也有逻辑 bug:
- `remove(i)` 把后面的元素前移
- iter_mut 的内部游标指向下一个,但因为前移,实际跳过一个元素

**正确做法**:
1. 先 iter_mut update 所有
2. 再 retain 过滤 Dead

这是"读写分离"——一次只做一件事。

### Lv2 · 动手实践

**题**:实现完整的 HP + 两阶段删除系统。验证:
1. 怪 spawn 时 hp = 30, state = Alive
2. take_damage(10) 两次 → hp = 10, state = Alive
3. take_damage(10) → hp = 0, state = Dying, dying_timer = 0.5
4. update(0.3) → state = Dying, dying_timer = 0.2
5. update(0.3) → state = Dead
6. 帧末 retain → entity 从列表消失

**完成标准**:`cargo test` 全部通过。

**参考解答**:

```rust
#[derive(Clone, Copy, PartialEq, Debug)]
enum EntityState { Alive, Dying, Dead }

#[derive(Clone, Debug)]
struct Entity {
    name: String,
    state: EntityState,
    hp: i32,
    max_hp: i32,
    dying_timer: f32,
}

impl Entity {
    fn new(name: &str, hp: i32) -> Self {
        Self {
            name: name.to_string(),
            state: EntityState::Alive,
            hp, max_hp: hp,
            dying_timer: 0.0,
        }
    }

    fn take_damage(&mut self, dmg: i32) {
        if self.state != EntityState::Alive { return; }
        self.hp = (self.hp - dmg).max(0);
        if self.hp == 0 {
            self.state = EntityState::Dying;
            self.dying_timer = 0.5;
        }
    }

    fn heal(&mut self, amount: i32) {
        if self.state != EntityState::Alive { return; }
        self.hp = (self.hp + amount).min(self.max_hp);
    }

    fn update(&mut self, dt: f32) {
        match self.state {
            EntityState::Alive => { /* AI / physics ... */ }
            EntityState::Dying => {
                self.dying_timer -= dt;
                if self.dying_timer <= 0.0 {
                    self.state = EntityState::Dead;
                }
            }
            EntityState::Dead => {}
        }
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn hp_flow() {
        let mut e = Entity::new("goblin", 30);
        e.take_damage(10);
        assert_eq!(e.hp, 20);
        assert_eq!(e.state, EntityState::Alive);

        e.take_damage(10);
        assert_eq!(e.hp, 10);
        assert_eq!(e.state, EntityState::Alive);

        e.take_damage(10);
        assert_eq!(e.hp, 0);
        assert_eq!(e.state, EntityState::Dying);
        assert!((e.dying_timer - 0.5).abs() < 1e-6);

        e.update(0.3);
        assert_eq!(e.state, EntityState::Dying);
        assert!((e.dying_timer - 0.2).abs() < 1e-6);

        e.update(0.3);
        assert_eq!(e.state, EntityState::Dead);

        // Dead 的不会再 update
        e.update(1.0);
        assert_eq!(e.state, EntityState::Dead);
    }

    #[test]
    fn retain_removes_dead() {
        let mut entities = vec![
            Entity::new("a", 10),
            Entity::new("b", 10),
            Entity::new("c", 10),
        ];
        // 让 b 死掉
        entities[1].take_damage(10);
        assert_eq!(entities[1].state, EntityState::Dying);
        // 模拟动画结束
        while entities[1].state == EntityState::Dying {
            entities[1].update(0.6);
        }
        assert_eq!(entities[1].state, EntityState::Dead);
        // 帧末清理
        entities.retain(|e| e.state != EntityState::Dead);
        assert_eq!(entities.len(), 2);
        assert_eq!(entities[0].name, "a");
        assert_eq!(entities[1].name, "c");
    }

    #[test]
    fn dead_doesnt_take_damage() {
        let mut e = Entity::new("goblin", 10);
        e.take_damage(10);
        e.take_damage(100);  // 已经 Dying,不应有效果
        assert_eq!(e.hp, 0);
        assert_eq!(e.state, EntityState::Dying);
    }

    #[test]
    fn heal_clamps_to_max() {
        let mut e = Entity::new("player", 30);
        e.take_damage(10);
        e.heal(50);
        assert_eq!(e.hp, 30);  // 不超过 max_hp
    }
}

fn main() {
    println!("Run with cargo test");
}
```

**关键测试点**:
- 取伤害但不能取负数(`max(0)`)
- Dead 状态的 entity 不再被攻击
- heal 不超过 max_hp
- retain 正确删除 Dead,保留其他

## 8 · Rust / Arch 落地代码

### 关键 Rust 特性

#### enum with data

```rust
enum EntityState {
    Alive,
    Dying { timer: f32 },
    Dead,
}

match state {
    EntityState::Dying { timer } => println!("dying in {}s", timer),
    _ => {}
}
```

variant 可以带数据(命名 struct 字段)。在 match 里 destructure 出来用。

#### Vec::retain

```rust
entities.retain(|e| e.state != EntityState::Dead);
```

闭包 `|e| ...` 接受 &Entity 返回 bool。retain 内部 O(N) 扫描,保留 true 的。

#### derive(Clone, Copy, PartialEq, Debug)

- Clone:可以 `.clone()` 显式复制
- Copy:赋值时自动复制(适合小 enum / 数字)
- PartialEq:可以用 `==` 比较
- Debug:可以用 `{:?}` 打印

EntityState 都 derive,因为它小(1 字节)且需要全方面操作。
