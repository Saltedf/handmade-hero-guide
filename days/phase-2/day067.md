# Day 067 · 条件更新:按状态决定行为

> 一个 entity 有三种状态:活着、垂死、死亡。今天 Casey 让 update 函数根据状态决定"要不要 update AI / 物理 / 动画"。听起来一行 if,但它能省下 80% 的 CPU——因为大部分 entity 在大部分时间是死的或静止的。

## 0 · 为什么要有这一天

朴素 update:

```rust
fn update(e: &mut Entity, dt: f32) {
    e.update_ai(dt);       // AI 思考(50 µs)
    e.update_physics(dt);  // 物理积分(10 µs)
    e.update_animation(dt); // 动画帧(5 µs)
}
```

每帧每个 entity 花费 ~65 µs。1000 个 entity = 65 ms/帧 = 15 FPS。

但仔细想:
- **死的 entity**(state=Dead)等被清理,什么都不应该做
- **垂死的 entity**(state=Dying)在播倒地动画,不该 AI 思考(已死)也不该物理移动(已倒)
- **静止的 entity**(墙)永远不动,AI / 物理都无意义
- **暂停的 entity**(被冰冻 / 眩晕)AI 暂停,但渲染继续

一个 entity 在大部分时间处于这些"不需要完整 update"的状态。**统一 update 浪费了 80% CPU**。

**条件 update**:

```rust
fn update(e: &mut Entity, dt: f32) {
    match e.state {
        EntityState::Alive => {
            e.update_ai(dt);
            e.update_physics(dt);
            e.update_animation(dt);
        }
        EntityState::Dying { timer } => {
            // 只 update 动画(倒地 / 渐隐)
            e.update_animation(dt);
        }
        EntityState::Dead => {
            // 什么都不做
        }
    }
}
```

垂死 / 死亡的 entity 跳过 90% 工作。1000 个 entity 中假设 800 个是 dead,只 200 个完整 update = 13 ms/帧 = 77 FPS。

这就是 **conditional update**——根据状态决定 update 内容。今天 Casey 加这个分支。

读完今天,你要做到:
- 看到任何 update 函数都问"是不是所有状态都需要这个工作"
- 能用 Rust 的 match 实现条件 update,编译器验证完整性
- 理解"90% 工作"和"100% 工作"对 FPS 的指数级影响
- 知道这种优化叫"early exit"——CPU 分支预测友好

如果你卡在"为什么不直接给 Dead entity 删了",回去看 Day 060(两阶段删除)——Dead 状态的 entity 还在等待 cleanup,不能立即删。

## 1 · Casey 今天做了什么

Casey 第 67 集做的事:

1. 把 update 函数改成 match self.state
2. Alive:全 update(AI / 物理 / 动画)
3. Dying:只 update 动画(dying_timer 减,timer 到 0 转 Dead)
4. Dead:不 update(等 retain 清理)
5. 加更多状态(Phase 5+ 会加 Stunned / Frozen / Paused)

视频里 Casey 用了 Casey 喜欢的"早退(early return)"风格:

```c
// Casey C 风格
void update(Entity *e, f32 dt) {
    if (e->state == DEAD) return;
    if (e->state != ALIVE) goto update_animation_only;
    
    update_ai(e, dt);
    update_physics(e, dt);
    
update_animation_only:
    update_animation(e, dt);
}
```

C 风格用 goto。Rust 用 match,更安全。

## 2 · 心智模型

### 2.1 类比:医院的不同病区

医院根据病人状态分病区,每个病区做不同事:

- **急诊病区(Alive)**:全面治疗——检查 / 用药 / 手术 / 监测
- **ICU 病区(Dying)**:只监测生命体征,不做主动治疗
- **太平间(Dead)**:什么都不做,等家属认领

为什么不所有病人都进急诊?因为急诊医生时间宝贵,不能花在"已经死亡"的病人身上。**按状态分病区 = 按状态分 update 强度**。

### 2.2 严谨:状态驱动的 update

```rust
#[derive(Clone, Copy, PartialEq, Debug)]
enum EntityState {
    Alive,
    Dying { timer: f32 },
    Dead,
    Stunned { timer: f32 },    // Phase 5+ 加
    Frozen { timer: f32 },
}

impl Entity {
    fn update(&mut self, world: &World, dt: f32) {
        match self.state {
            EntityState::Dead => {
                // 完全跳过,等 retain 清理
                return;
            }
            EntityState::Dying { ref mut timer } => {
                // 只 update 动画
                self.update_animation(dt);
                *timer -= dt;
                if *timer <= 0.0 {
                    self.state = EntityState::Dead;
                }
                return;
            }
            EntityState::Stunned { ref mut timer } => {
                // 不 update AI(被眩晕),但 update 物理 / 动画
                self.update_physics(dt);
                self.update_animation(dt);
                *timer -= dt;
                if *timer <= 0.0 {
                    self.state = EntityState::Alive;
                }
                return;
            }
            EntityState::Frozen { ref mut timer } => {
                // 完全冻结,只 timer 减
                *timer -= dt;
                if *timer <= 0.0 {
                    self.state = EntityState::Alive;
                }
                return;
            }
            EntityState::Alive => {
                // 完整 update
                self.update_ai(world, dt);
                self.update_physics(dt);
                self.update_animation(dt);
            }
        }
    }
}
```

**Rust match 的强大**:
- 编译器强制覆盖所有 variant(漏一个就编译错)
- variant 带数据(timer),destructure 直接用
- `ref mut timer` 借用可变引用,不 move 出 enum

### 2.3 早退 vs 完整 match

两种风格:

**早退(early return)**:

```rust
fn update(&mut self, dt: f32) {
    if self.state == EntityState::Dead { return; }
    if let EntityState::Dying { ref mut timer } = self.state {
        self.update_animation(dt);
        *timer -= dt;
        if *timer <= 0.0 { self.state = EntityState::Dead; }
        return;
    }
    // 默认:Alive,完整 update
    self.update_ai(dt);
    self.update_physics(dt);
    self.update_animation(dt);
}
```

**完整 match**:

```rust
fn update(&mut self, dt: f32) {
    match self.state {
        EntityState::Dead => {},
        EntityState::Dying { .. } => { /* ... */ },
        EntityState::Alive => { /* ... */ },
    }
}
```

**Casey 偏爱早退**(C 风格)。Rust 项目偏爱 match(编译器强制完整)。

### 2.4 性能:80/20 法则

条件 update 利用了 **80/20 法则**(Pareto principle):

- 80% 的 entity 是 Dead / 静止的(墙 / 已死怪 / 静态装饰)
- 20% 的 entity 是活跃的(玩家 / 活怪 / 投射物)
- 把 80% 的 entity 跳过,只对 20% 做完整 update

收益:
- 1000 个 entity,800 个 Dead
- 朴素 update:1000 × 65 µs = 65 ms
- 条件 update:200 × 65 µs + 800 × 1 µs(几乎跳过)= 13.8 ms
- **4.7× 加速**

更大的好处:**分支预测友好**。`if e.state == Dead { return }` 在 CPU 分支预测器看来是"几乎总是 true"(因为 80% 是 Dead),预测正确率 99%。**指令流水线无 stall**。

### 2.5 加新状态

条件 update 的另一个好处:**加新状态容易**。

举例:加 `Frozen` 状态(被冰冻法术命中,3 秒不动):

```rust
// 加 state
enum EntityState { Alive, Dying { timer: f32 }, Dead, Frozen { timer: f32 } }

// update 里加一个 arm
EntityState::Frozen { ref mut timer } => {
    *timer -= dt;
    if *timer <= 0.0 { self.state = EntityState::Alive; }
    // 不 update AI / 物理 / 动画
}

// 法术命中时设置
fn freeze(e: &mut Entity) {
    if e.state == EntityState::Alive {
        e.state = EntityState::Frozen { timer: 3.0 };
    }
}
```

如果不用状态机,而是 `if e.is_alive && !e.is_dying && !e.is_dead && !e.is_frozen && ...`,逻辑会指数爆炸。状态机干净。

### 2.6 AI 内部也有状态机

EntityState 是 entity 的"宏观状态"(活 / 死)。但活的怪内部也有"微观状态"——巡逻 / 追击 / 攻击 / 逃跑:

```rust
enum MonsterAiState {
    Patrol { waypoint_idx: usize },
    Chase { target_id: EntityId },
    Attack { target_id: EntityId, cooldown: f32 },
    Flee { from_id: EntityId },
}

struct Monster {
    state: EntityState,           // 宏观
    ai_state: MonsterAiState,     // 微观
}

impl Monster {
    fn update_ai(&mut self, world: &World, dt: f32) {
        if self.state != EntityState::Alive { return; }
        match self.ai_state {
            MonsterAiState::Patrol { waypoint_idx } => { /* ... */ },
            MonsterAiState::Chase { target_id } => { /* ... */ },
            // ...
        }
    }
}
```

这是 **嵌套状态机**。Casey 第 67 集只做宏观(EntityState),微观(Phase 4+ 的 brain 系统)后面加。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏的状态机无处不在:

- **EntityState**(今天):活 / 死 / 状态
- **AnimationState**:idle / walk / run / attack / die
- **CombatState**:idle / windup / active / recovery / hit
- **GameState**:menu / loading / playing / paused / cutscene / game_over
- **AIState**:patrol / chase / attack / flee / dead

每个状态机用 match 实现,加状态容易。这是**有限状态机(FSM)**的最简形态。

更复杂的状态机工具:
- **Hierarchical FSM**(分层 FSM):状态可以嵌套(攻击下面有 windup / active / recovery)
- **Behavior Tree**(行为树):分支 / 序列 / 并行节点,比 FSM 灵活
- **GOAP / Planner**:定义目标和动作,AI 自动规划路径

Casey 用最简 FSM,Phase 8 才可能升级。

### 3.2 · 🐧 Linux 系统编程视角

Linux 进程状态机:

- **Running**:在 CPU 上跑
- **Sleeping**:等事件(interruptible / uninterruptible)
- **Stopped**:被信号暂停(SIGSTOP)
- **Zombie**:已 exit,等 parent wait
- **Dead**:被 reap,从进程表移除

`top` 命令的 S 列显示这些状态。kernel scheduler 根据**状态决定 update**——只调度 Running / Sleeping,不调度 Zombie / Dead。**这就是条件 update**。

```
top - 15:30:00 up 1 day
  PID USER      PR  NI    VIRT    RES    SHR S  %CPU %MEM
1234 user       20   0  100000   5000   3000 R   5.0  0.1   <- Running
1235 user       20   0  100000   5000   3000 S   0.0  0.1   <- Sleeping
1236 user       20   0       0      0      0 Z   0.0  0.0   <- Zombie
```

Zombie 进程在进程表里但不调度。和 Casey 的 Dead entity 在列表里但不 update 完全一致。

### 3.3 · 🎨 图形学视角

渲染管线里也有"条件 update":

- **视锥外物体**:跳过 vertex shader(剔除)
- **背面**:背向相机的三角形跳过光栅化(backface culling)
- **深度更远**:被前面物体挡的 fragment 跳过(z-test)
- **alpha = 0**:透明 fragment 跳过(blend skip)

GPU 大量用"早退"——大部分 fragment / vertex 被跳过,只对真正需要计算的做完整 pipeline。这就是 GPU 性能的来源。

CPU 端的 conditional update 是同样思想:**大部分 entity 不需要完整 update,跳过它们**。

### 3.4 · 🦀 Rust 生态视角

Rust 的 match 让条件 update 极其优雅:

```rust
match self.state {
    EntityState::Alive => { /* full update */ }
    EntityState::Dying { timer } if timer > 0.5 => { /* early dying */ }
    EntityState::Dying { timer } => { /* late dying */ }
    EntityState::Dead => {}
}
```

**match guard**(`if timer > 0.5`):在 pattern 后加 if 条件,进一步细分。Casey 在 C 里写 `if (state == DYING && timer > 0.5)`,Rust 写 `Dying { timer } if timer > 0.5`,更紧凑。

**编译时完整性检查**:加新 variant,所有 match 都要更新。这是重构的护栏——不会漏一个分支。

#### 数据导向设计的角度

条件 update 的另一面:**数据布局应该匹配访问模式**。

如果 80% 是 Dead,把 Dead entity 分到单独 Vec:

```rust
struct World {
    alive_entities: Vec<Entity>,    // 完整 update
    dead_entities: Vec<EntityId>,   // 等清理
}
```

每帧 update 只扫 alive_entities(200 个),dead_entities 只在 retain 时一次扫。**比"所有 entity 在一个 Vec + 条件 update"还快**。

这是 **SoA(struct of arrays)** 的思想——按访问模式分组。Phase 4+ 会深入。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:垂死(Dying)状态的 entity 为什么 update 渲染,但不 update AI?

**参考解答**:
- **update 渲染**:倒地 / 渐隐动画要播。如果不 update,entity 突然从屏幕消失,玩家觉得"它瞬间蒸发了",游戏感很差
- **不 update AI**:已经死了,不需要思考"去哪 / 攻击谁"。AI 计算是浪费 CPU
- **不 update 物理**:已经倒地,不需要重力 / 碰撞(它会和地面 / 其他 entity 不必要地交互)
- **timer 减**:倒计时到 0 转 Dead,触发清理

这是状态机的本质——**不同状态做不同事**。所有状态都做同样的事,等于没状态机。

### Lv2 · 动手实践

**题**:实现 conditional update。验证:
1. 1000 个 entity,800 是 Dead,200 是 Alive
2. 模拟 60 帧,测量总耗时
3. 用条件 update 应该比"全部完整 update"快 4×

**完成标准**:打印两种实现的耗时对比。

**参考解答**:

```rust
use std::time::Instant;

#[derive(Clone, Copy, PartialEq, Debug)]
enum EntityState { Alive, Dying { timer: f32 }, Dead }

#[derive(Clone, Debug)]
struct Entity {
    state: EntityState,
    pos_x: f32,
    pos_y: f32,
}

impl Entity {
    fn update_full(&mut self, dt: f32) {
        // 模拟 AI / 物理 / 动画(无脑做)
        self.pos_x += 1.0 * dt;
        self.pos_y += 1.0 * dt;
        // 模拟一些 CPU 工作
        let mut sum = 0.0;
        for i in 0..100 {
            sum += (i as f32).sqrt();
        }
        let _ = sum;
    }

    fn update_conditional(&mut self, dt: f32) {
        match self.state {
            EntityState::Dead => { return; }
            EntityState::Dying { ref mut timer } => {
                *timer -= dt;
                if *timer <= 0.0 { self.state = EntityState::Dead; }
                return;
            }
            EntityState::Alive => {
                self.update_full(dt);
            }
        }
    }
}

fn main() {
    let dt = 1.0 / 60.0;
    let mut entities: Vec<Entity> = Vec::new();
    for i in 0..1000 {
        let state = if i < 800 { EntityState::Dead }
                    else { EntityState::Alive };
        entities.push(Entity { state, pos_x: 0.0, pos_y: 0.0 });
    }

    // 全部完整 update
    let start = Instant::now();
    for _ in 0..60 {
        for e in &mut entities {
            e.update_full(dt);
        }
    }
    let full_time = start.elapsed();
    println!("Full update (all entities): {:?}", full_time);

    // 重置
    for e in &mut entities {
        e.pos_x = 0.0;
        e.pos_y = 0.0;
    }

    // 条件 update
    let start = Instant::now();
    for _ in 0..60 {
        for e in &mut entities {
            e.update_conditional(dt);
        }
    }
    let cond_time = start.elapsed();
    println!("Conditional update: {:?}", cond_time);
    println!("Speedup: {:.1}x", full_time.as_secs_f64() / cond_time.as_secs_f64());
}
```

## 8 · Rust / Arch 落地代码

### 关键 Rust 特性

#### match 完整性

```rust
match self.state {
    EntityState::Alive => { /* ... */ }
    EntityState::Dying { timer } => { /* ... */ }
    EntityState::Dead => { /* ... */ }
    // 漏任意一个就编译错
}
```

Rust 强制 match 完整。C 的 switch 不强制(可漏 case),bug 来源。

#### ref mut pattern

```rust
match self.state {
    EntityState::Dying { ref mut timer } => {
        *timer -= dt;  // 修改 enum 内的字段
    }
}
```

`ref mut` 借用可变引用,不 move 出 enum。如果没有 `ref`,会尝试 move `timer` 出去,Rust 不允许(enum 还在用)。

替代写法:`if let &mut EntityState::Dying { ref mut timer } = &mut self.state { ... }`。但 match 更清晰。

#### Match guard

```rust
match self.state {
    EntityState::Dying { timer } if timer > 0.5 => { /* early */ }
    EntityState::Dying { timer } => { /* late */ }
}
```

`if condition` 进一步过滤 pattern。Casey 在 C 用 `if (state == DYING && timer > 0.5)`,Rust 用 match guard。
