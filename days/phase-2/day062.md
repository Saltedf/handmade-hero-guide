# Day 062 · 投射物:自己移动的伤害源

> 玩家按 K 键,从手心飞出一颗火球,沿前方直线飞行,撞到怪扣 20 血,撞到墙消失,飞 3 秒没撞东西也消失。火球本身就是一个 entity——有 pos / vel / lifetime / damage / owner。今天 Casey 把"投射物"这个游戏概念**正式抽象出来**,从此你有了火球 / 箭 / 子弹 / 陨石共用的骨架。

## 0 · 为什么要有这一天

近战攻击(Day 061)和远程攻击的本质区别:

- 近战:**瞬时的**——按 J 键,立刻在玩家前方判定范围,扣血。整个过程一帧完成
- 远程:**延迟的**——按 K 键,spawn 一个"飞行物",这个飞行物**自己有生命**——每帧移动 / 碰撞 / 计时,直到命中 / 撞墙 / 超时

"飞行物"在游戏术语叫 **projectile(投射物)** 或 **missile(导弹)**。它的本质是**有 vel / pos / lifetime / damage 的临时 entity**。

为什么单独抽象?因为它有独立的物理:
- 自己移动(`pos += vel * dt`)
- 自己碰撞(扫空间网格找命中目标)
- 自己计时(超时消失)
- 自己有 owner(谁发的,防自伤)

如果不抽象成 entity,你会写一坨特殊代码:

```rust
// 反例:不抽象的火球
struct Fireball {
    pos: Vec2,
    vel: Vec2,
    damage: i32,
    // ...
}
struct Arrow {
    pos: Vec2,
    vel: Vec2,
    damage: i32,
    // ...
}
// 每种投射物写一份 update / collision / lifetime
```

抽成 entity 后:

```rust
enum EntityKind {
    Player, Monster, Wall,
    Projectile {  // 通用投射物
        damage: i32,
        lifetime: f32,
        owner: EntityId,
    },
}
```

火球 / 箭 / 子弹的差别变成**spawn 时的参数**(sprite / damage / speed / lifetime),不是不同的 struct。这是**数据驱动设计**——通过参数化差异而不是类型化差异。

读完今天,你要做到:
- 理解"投射物"为什么是一种 entity,而不是独立的 struct
- 能写完整的 projectile update:移动 + 碰撞 + 寿命 + 自伤防护
- 知道 owner 字段为什么必要(否则玩家被自己火球打伤)
- 理解 lifetime 计时器和 Day 060 的 dying_timer 的差别(都是 timer,但语义不同)

如果你卡在"为什么 owner 这么重要",想想多人游戏——玩家的火球不能炸自己,也不能炸队友。owner 不只是防自伤,还决定**碰撞规则**(Day 069)。

## 1 · Casey 今天做了什么

Casey 第 62 集做的事:

1. 给 EntityKind 加 `Projectile` 变体,字段:pos / vel / half / damage / lifetime / owner
2. 玩家按 K 键(just_pressed + cooldown):spawn 一个 projectile,vel = facing × SPEED
3. 投射物 update:每帧 pos += vel * dt,lifetime -= dt,做 grid 碰撞查询
4. 碰撞规则:
   - 碰到 owner 自己 → 忽略
   - 碰到非 owner 的 entity → 应用 take_damage,投射物消失
   - 碰到墙 → 投射物消失(不扣墙血,除非墙是可破坏)
5. lifetime <= 0 → 投射物消失(没飞到任何东西)
6. 用 EntityId 字段标记 owner,update 时 skip owner 的碰撞

视频里 Casey 演示了**owner 字段的重要性**:如果不检查,火球一 spawn 就"撞玩家自己",立即消失,玩家根本没发射成功。owner 字段让火球跳过 owner,直到撞到别人。

## 2 · 心智模型

### 2.1 类比:邮递员送信

邮递员送信的过程:

1. 寄件人写好信,交给邮递员
2. 邮递员带着信**沿固定路线**走
3. 中间如果**遇到收件人**,把信给他,任务完成
4. 中间如果**路断了**(修路 / 桥塌),退回邮局(销毁)
5. 如果**走了一个月**还没找到收件人,信作废(lifetime)

投射物的逻辑完全一样:

| 邮递员 | 投射物 |
|---|---|
| 寄件人 | owner(发射者) |
| 信 | damage(伤害载荷) |
| 路线 | vel * dt(直线运动) |
| 收件人 | 命中的 enemy |
| 路断 | 撞墙 |
| 一个月 | lifetime 到 |

寄件人自己不会"撞自己"——投射物要 skip owner。这是 owner 字段的核心用途。

### 2.2 严谨:Projectile entity 结构

```rust
#[derive(Clone, Debug)]
struct Entity {
    id: EntityId,
    pos: Vec2,
    half: Vec2,
    vel: Vec2,
    kind: EntityKind,
    state: EntityState,
    hp: Option<i32>,             // 投射物通常没 HP(撞了就消失)
    sprite: Option<SpriteId>,
    lifetime: Option<f32>,       // 仅 projectile 有
    damage: Option<i32>,         // 仅 projectile 有
    owner: Option<EntityId>,     // 仅 projectile 有(防止自伤)
}

enum EntityKind {
    Player, Monster, Wall, Projectile,
}
```

`Option<T>` 让"非 projectile 不需要这些字段"成为可能。Wall / Player 这些字段都是 None。

**另一种设计**(enum with data):

```rust
enum Entity {
    Player { pos: Vec2, hp: i32 },
    Monster { pos: Vec2, hp: i32 },
    Wall { pos: Vec2 },
    Projectile {
        pos: Vec2, vel: Vec2, damage: i32,
        lifetime: f32, owner: EntityId,
    },
}
```

更类型安全,但 enum 大小取最大 variant(Projectile 最大),所有 entity 都占 Projectile 大小。Casey 在 C 里用方案 1(struct + tag + Option),Rust 项目通常用方案 2。

### 2.3 Spawn 投射物

```rust
fn spawn_projectile(world: &mut World, owner: EntityId, pos: Vec2, facing: Dir) {
    const PROJECTILE_SPEED: f32 = 200.0;  // 像素/秒
    const PROJECTILE_LIFETIME: f32 = 3.0;  // 秒
    const PROJECTILE_DAMAGE: i32 = 20;

    let vel = facing.to_vec().mul(PROJECTILE_SPEED);
    world.entities.push(Entity {
        id: world.next_id(),  // 自增 ID
        pos: pos.add(facing.to_vec().mul(20.0)),  // 在 owner 前方 20 像素 spawn,避免立即碰撞
        half: Vec2::new(4.0, 4.0),
        vel,
        kind: EntityKind::Projectile,
        state: EntityState::Alive,
        hp: None,
        sprite: Some(SpriteId::Fireball),
        lifetime: Some(PROJECTILE_LIFETIME),
        damage: Some(PROJECTILE_DAMAGE),
        owner: Some(owner),
    });
}
```

**关键细节**:
- spawn 位置在 owner 前方 20 像素——避免立即和 owner 碰撞触发"撞 owner 自己"
- `next_id()` 是 World 的方法,生成唯一 ID(`world.last_id += 1`)
- vel = facing × SPEED,所以火球朝玩家朝向飞

### 2.4 Update 投射物

```rust
fn update_projectile(world: &mut World, projectile_idx: usize, dt: f32) {
    let pos = world.entities[projectile_idx].pos;
    let vel = world.entities[projectile_idx].vel;
    let owner = world.entities[projectile_idx].owner.unwrap();
    let damage = world.entities[projectile_idx].damage.unwrap();

    // 1. 移动(Euler 积分)
    let new_pos = pos.add(vel.mul(dt));
    world.entities[projectile_idx].pos = new_pos;

    // 2. 寿命递减
    let life = world.entities[projectile_idx].lifetime.as_mut().unwrap();
    *life -= dt;
    if *life <= 0.0 {
        world.entities[projectile_idx].state = EntityState::Dead;
        return;
    }

    // 3. 碰撞查询(空间网格)
    let candidates = world.grid.query_nearby(new_pos);
    for id in candidates {
        if id == owner { continue; }  // 跳过 owner
        let i = id as usize;
        if i >= world.entities.len() { continue; }
        let e = world.entities[i];
        // 撞墙
        if e.kind == EntityKind::Wall {
            if minkowski_collide(new_pos, half_projectile, e.pos, e.half) {
                world.entities[projectile_idx].state = EntityState::Dead;
                return;
            }
        }
        // 撞怪 / 撞玩家(非 owner)
        if matches!(e.kind, EntityKind::Monster | EntityKind::Player) {
            if minkowski_collide(new_pos, half_projectile, e.pos, e.half) {
                // 应用伤害
                if let Some(hp) = world.entities[i].hp.as_mut() {
                    *hp = (*hp - damage).max(0);
                    if *hp == 0 {
                        world.entities[i].state = EntityState::Dying;
                        world.entities[i].dying_timer = 0.5;
                    }
                }
                // 投射物消失
                world.entities[projectile_idx].state = EntityState::Dead;
                spawn_explosion_effect(world, new_pos);
                return;
            }
        }
    }
}
```

**逻辑分层**:
1. **移动**:`pos += vel * dt`(物理)
2. **寿命**:`lifetime -= dt`,超时消失
3. **碰撞**:grid 找候选,逐个检查,命中时应用效果

每层独立,顺序重要:**先移动 → 再寿命 → 再碰撞**。否则你检查的是旧位置的碰撞。

### 2.5 owner 字段的多用途

owner 不只是防自伤:

| 用途 | 例子 |
|---|---|
| 防自伤 | 玩家火球不炸玩家自己 |
| 队友伤害 | 多人游戏,火球不炸队友(通过 owner.team 判断) |
| 击杀归属 | 怪被火球打死 → 经验归 owner |
| 击退方向 | 火球从 owner 方向飞来,怪往反方向击退 |
| 触发器 | 触发"火焰成就"(用火球杀 10 个) |

Casey 第 62 集只用 owner 做防自伤。其他用途后面慢慢加。

### 2.6 投射物变体

调整 spawn 参数,得到不同投射物:

```rust
// 火球:直线,中等速度,中等伤害,中等寿命
spawn_projectile(world, owner, pos, facing,
    speed=200.0, lifetime=3.0, damage=20, sprite=Fireball);

// 箭:快,长寿命,小伤害
spawn_projectile(world, owner, pos, facing,
    speed=400.0, lifetime=5.0, damage=10, sprite=Arrow);

// 子弹:极快,短寿命,大伤害
spawn_projectile(world, owner, pos, facing,
    speed=800.0, lifetime=1.0, damage=30, sprite=Bullet);

// 陨石:慢,大伤害,AoE
spawn_projectile(world, owner, pos, facing,
    speed=80.0, lifetime=10.0, damage=100, sprite=Meteor);
```

同一份代码,不同参数得到不同效果。**数据驱动设计的威力**。

更复杂的变体:
- **弧线**(重力影响):update 里 `vel.y += GRAVITY * dt`(箭 / 投掷物)
- **追踪**:`vel = (target.pos - pos).normalize() * speed`(追踪导弹)
- **AoE**(范围伤害):碰撞时对附近 entity 都造成伤害(火球爆炸)
- **piercing**(穿透):碰撞时不消失,继续飞(穿透箭)
- **bounce**(反弹):碰墙反射 vel(Day 044)

每个变体是 update 函数的一个 if 分支,或者用 trait 多态。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

投射物在游戏里无处不在:

| 游戏类型 | 投射物例子 |
|---|---|
| ARPG(暗黑) | 火球 / 冰箭 / 闪电链 |
| FPS(CS) | 子弹(虽然是 hitscan,但有 tracer 投射物模拟) |
| MOBA(LoL) | 各种技能弹道 |
| 弹幕东方 | 各种 enemy bullet |
| RTS(星际) | 机枪兵子弹 / 坦克炮弹 |
| 体育(NBA) | 篮球(球员投出后是 projectile) |

**Hitscan vs Projectile**:
- **Hitscan**(即时):按枪瞬间,raycast 算命中。没有真实的"子弹飞行"。CS 的步枪就是 hitscan——服务器即时算"枪指向哪个玩家"
- **Projectile**(实体):真有飞行物,有 vel / lifetime / collision。HH 的火球是 projectile

FPS 大部分枪是 hitscan(更省服务器带宽,无延迟),火箭筒 / 手雷是 projectile(玩家能看到飞行)。

**Hitscan 的实现**:用 Day 048 的线段相交,从枪口向朝向画线段,看哪个 entity 第一个相交。

### 3.2 · 🎨 图形学视角

投射物的渲染有几种做法:

1. **Static sprite**(简单):一个静态 sprite,按 vel 方向旋转
2. **Animated sprite**(动画):多帧 sprite 循环(火球燃烧)
3. **Particle trail**(拖尾):每帧 spawn 一个粒子,粒子渐隐
4. **Glow / bloom**:发射物用发光 shader(HDR + tone mapping)
5. **Distortion**:玻璃弹 / 等离子球扭曲背景(shader)

Casey 用 static sprite + (Phase 5+)加拖尾粒子。够用。

### 3.3 · 🐧 Linux 系统编程视角

Linux 内核**也用类似"投射物"的设计**:

- **Signal**:进程用 `kill(pid, sig)` 发信号。signal 在内核里"飞行"——从发送进程到目标进程,期间可能被阻塞 / 排队 / 合并。**signal 就是 owner = sender, target = pid 的"消息投射物"**
- **Network packet**:应用程序调 `send()`,数据包经过协议栈 → 网卡 → 网络 → 接收方。**packet 是 owner = src_ip, target = dst_ip 的"数据投射物"**
- **D-Bus message**:桌面进程间通信,通过 D-Bus daemon 转发 message。message 是 owner = sender_bus_name 的"通信投射物"

它们的共同点:
- 有 owner(发送方)
- 有 target(可能未指定,广播)
- 有 lifetime(TTL,Time To Live)
- 有 payload(数据 / 信号 / 伤害)
- 可能被丢弃(超时 / 拒绝)

游戏投射物是这种"消息传递"的视觉化。**理解了游戏投射物,你理解了网络包转发的本质**。

### 3.4 · 🦀 Rust 生态视角

Rust 表达 projectile spawn / despawn 的高效方式:

#### 对象池(Object Pool)

高频 spawn(弹幕游戏每秒 100 个 bullet)不能用 `Vec::push` + `Vec::retain`——内存碎片 + 分配开销。用对象池:

```rust
struct ProjectilePool {
    items: Vec<Projectile>,       // 固定容量
    free_indices: Vec<usize>,     // 空闲槽位
}

impl ProjectilePool {
    fn spawn(&mut self, p: Projectile) -> usize {
        if let Some(i) = self.free_indices.pop() {
            self.items[i] = p;
            i
        } else {
            self.items.push(p);
            self.items.len() - 1
        }
    }
    fn despawn(&mut self, i: usize) {
        self.free_indices.push(i);
        // 不真的 remove,标记为 free
    }
}
```

预分配 N 个槽位,spawn 时复用空闲槽,despawn 时归还。**无内存分配**。

Rust crate:`bloomy` / `slotmap` / `thunderdome`。

#### 并发安全的 projectile(可选)

如果游戏要多线程 update 投射物(Phase 4+),用 `crossbeam::queue::SegQueue` 或 `rayon` 并行 iter。但 Phase 2 不需要。

#### 用 bevy_ecs 的写法

```rust
#[derive(Component)]
struct Projectile { damage: i32, lifetime: f32, owner: Entity }

#[derive(Component)]
struct Vel(Vec2);

fn projectile_system(
    mut q: Query<(Entity, &mut Projectile, &mut Transform, &Vel)>,
    mut commands: Commands,
    time: Res<Time>,
) {
    for (e, mut p, mut tr, vel) in q.iter_mut() {
        tr.translation.x += vel.0.x * time.delta_seconds();
        tr.translation.y += vel.0.y * time.delta_seconds();
        p.lifetime -= time.delta_seconds();
        if p.lifetime <= 0.0 {
            commands.entity(e).despawn();
        }
    }
}
```

bevy_ecs 把 projectile 当一种 component bundle。本质和今天 Casey 写的一样,只是 ECS 包装。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 projectile spawn 位置要在 owner 前方 20 像素,而不是 owner 中心?

**参考解答**:如果在 owner 中心 spawn,第一帧 update 时:
- projectile pos = owner pos
- 碰撞查询 grid.query_nearby(pos) 返回包含 owner 的候选
- minkowski_collide(owner, projectile) = true(完全重叠)
- 应用 take_damage(owner, projectile.damage)
- owner 被自己火球打伤,projectile 消失

为了避免这个,Casey 把 spawn 位置放在 owner 前方 20 像素——刚 spawn 就**离开 owner 的 AABB**,碰撞检测不会命中 owner。

或者另一种做法:碰撞检测时 skip owner(用 owner 字段)。这是更通用的做法,但 spawn 位置仍然要离开 owner,否则第一帧的特效(火球出现的位置)在 owner 内部,看起来怪。

### Lv2 · 动手实践

**题**:实现完整 projectile 系统。验证:
1. 玩家在 (0, 0) 朝右,按 K 键,spawn 火球在 (20, 0),vel = (200, 0)

```rust
type EntityId = u32;

#[derive(Clone, Copy, PartialEq, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
    fn mul(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
    fn sub(self, o: Self) -> Self { Self { x: self.x - o.x, y: self.y - o.y } }
}

#[derive(Clone, Copy, PartialEq, Debug)]
enum EntityState { Alive, Dying, Dead }

#[derive(Clone, Copy, PartialEq, Debug)]
enum EntityKind { Player, Monster, Wall, Projectile }

#[derive(Clone, Debug)]
struct Entity {
    id: EntityId,
    kind: EntityKind,
    pos: Vec2,
    half: Vec2,
    vel: Vec2,
    state: EntityState,
    hp: Option<i32>,
    lifetime: Option<f32>,
    damage: Option<i32>,
    owner: Option<EntityId>,
}

impl Entity {
    fn player(id: EntityId, pos: Vec2) -> Self {
        Self { id, kind: EntityKind::Player, pos, half: Vec2::new(8.0, 8.0),
            vel: Vec2::new(0.0, 0.0), state: EntityState::Alive,
            hp: Some(100), lifetime: None, damage: None, owner: None }
    }
    fn monster(id: EntityId, pos: Vec2) -> Self {
        Self { id, kind: EntityKind::Monster, pos, half: Vec2::new(8.0, 8.0),
            vel: Vec2::new(0.0, 0.0), state: EntityState::Alive,
            hp: Some(30), lifetime: None, damage: None, owner: None }
    }
    fn projectile(id: EntityId, pos: Vec2, vel: Vec2, owner: EntityId) -> Self {
        Self { id, kind: EntityKind::Projectile, pos, half: Vec2::new(4.0, 4.0),
            vel, state: EntityState::Alive,
            hp: None, lifetime: Some(3.0), damage: Some(20), owner: Some(owner) }
    }
}

struct World {
    entities: Vec<Entity>,
    next_id: EntityId,
}

impl World {
    fn new() -> Self { Self { entities: vec![], next_id: 1 } }
    fn alloc_id(&mut self) -> EntityId {
        let id = self.next_id;
        self.next_id += 1;
        id
    }
    fn spawn(&mut self, e: Entity) -> EntityId {
        let id = e.id;
        self.entities.push(e);
        id
    }
    fn find(&self, id: EntityId) -> Option<&Entity> {
        self.entities.iter().find(|e| e.id == id)
    }
    fn find_mut(&mut self, id: EntityId) -> Option<&mut Entity> {
        self.entities.iter_mut().find(|e| e.id == id)
    }
    fn cleanup(&mut self) {
        self.entities.retain(|e| e.state != EntityState::Dead);
    }
}

const PROJECTILE_SPEED: f32 = 200.0;

fn fire_projectile(world: &mut World, owner: EntityId, owner_pos: Vec2, owner_facing: Vec2) {
    let id = world.alloc_id();
    let spawn_pos = owner_pos.add(owner_facing.mul(20.0));
    let vel = owner_facing.mul(PROJECTILE_SPEED);
    world.spawn(Entity::projectile(id, spawn_pos, vel, owner));
}

fn minkowski_collide(p1: Vec2, h1: Vec2, p2: Vec2, h2: Vec2) -> bool {
    let dx = (p1.x - p2.x).abs();
    let dy = (p1.y - p2.y).abs();
    dx < (h1.x + h2.x) && dy < (h1.y + h2.y)
}

fn update_projectiles(world: &mut World, dt: f32) {
    // 收集所有 projectile 的 id(避免借用冲突)
    let proj_ids: Vec<EntityId> = world.entities.iter()
        .filter(|e| e.kind == EntityKind::Projectile && e.state == EntityState::Alive)
        .map(|e| e.id)
        .collect();

    for proj_id in proj_ids {
        let (pos, vel, half, owner, damage, mut lifetime) = {
            let p = world.find(proj_id).unwrap();
            (p.pos, p.vel, p.half, p.owner.unwrap(), p.damage.unwrap(), p.lifetime.unwrap())
        };

        // 1. 移动
        let new_pos = pos.add(vel.mul(dt));
        world.find_mut(proj_id).unwrap().pos = new_pos;

        // 2. 寿命
        lifetime -= dt;
        world.find_mut(proj_id).unwrap().lifetime = Some(lifetime);
        if lifetime <= 0.0 {
            world.find_mut(proj_id).unwrap().state = EntityState::Dead;
            continue;
        }

        // 3. 碰撞(扫所有 entity,简化版,生产用 grid)
        let mut hit_target = None;
        for e in &world.entities {
            if e.id == proj_id { continue; }
            if e.id == owner { continue; }
            if e.state != EntityState::Alive { continue; }
            if matches!(e.kind, EntityKind::Monster | EntityKind::Player | EntityKind::Wall) {
                if minkowski_collide(new_pos, half, e.pos, e.half) {
                    hit_target = Some(e.id);
                    break;
                }
            }
        }
        if let Some(target_id) = hit_target {
            // 应用伤害(如果是怪 / 玩家,不是墙)
            if let Some(t) = world.find_mut(target_id) {
                if matches!(t.kind, EntityKind::Monster | EntityKind::Player) {
                    if let Some(hp) = t.hp.as_mut() {
                        *hp = (*hp - damage).max(0);
                        if *hp == 0 {
                            t.state = EntityState::Dying;
                        }
                    }
                }
            }
            // 投射物消失
            world.find_mut(proj_id).unwrap().state = EntityState::Dead;
        }
    }
}

fn main() {
    let mut world = World::new();
    let player = world.spawn(Entity::player(world.alloc_id(), Vec2::new(0.0, 0.0)));
    world.spawn(Entity::monster(world.alloc_id(), Vec2::new(200.0, 0.0)));

    // 发射火球
    fire_projectile(&mut world, player, Vec2::new(0.0, 0.0), Vec2::new(1.0, 0.0));

    let dt = 1.0 / 60.0;
    for frame in 0..240 {  // 4 秒
        update_projectiles(&mut world, dt);
        world.cleanup();
    }

    let monster = world.entities.iter().find(|e| e.kind == EntityKind::Monster).unwrap();
    assert_eq!(monster.hp, Some(10), "monster should be at 10 hp");
    let proj_count = world.entities.iter().filter(|e| e.kind == EntityKind::Projectile).count();
    assert_eq!(proj_count, 0, "projectile should be gone");
    println!("OK: monster hp = {:?}, projectile despawned", monster.hp);
}
```

## 8 · Rust / Arch 落地代码

### 关键 Rust 特性

#### Option<T> 表达"可能没有"

```rust
hp: Option<i32>,
lifetime: Option<f32>,
owner: Option<EntityId>,
```

投射物有 lifetime,但 Wall 没有。用 `Option<f32>` 让字段对所有 entity 都存在,只是非 projectile 是 None。**避免 enum variant 数据差异**。

`if let Some(x) = opt { ... }` 是 Rust 的 null 检查惯用法。

#### 借用冲突的 workaround:收集 ID

```rust
let proj_ids: Vec<EntityId> = world.entities.iter()
    .filter(|e| e.kind == EntityKind::Projectile)
    .map(|e| e.id)
    .collect();

for proj_id in proj_ids {
    // 这里可以 mutably borrow world
}
```

不能在 `for e in &world.entities` 里 mutable borrow world。先收集 ID(不可变借用),再循环外 mutable 操作。**Rust 游戏开发的日常 workaround**。

更优雅的做法是 `split_at_mut` 或索引,但对 N=小用 ID 收集最简单。

#### matches! 宏

```rust
if matches!(e.kind, EntityKind::Monster | EntityKind::Player) { ... }
```

`matches!` 是 Rust 的宏,展开为 `match e.kind { Monster | Player => true, _ => false }`。比写完整 match 简洁。
