
# Day 061 · 近战攻击:范围 / 冷却 / 反馈

> 玩家按 J 键,前方扇形范围内的怪扣 10 血。听起来就一句 if,但今天 Casey 加了三个细节让这件事从"功能正确"变成"玩家觉得爽":**冷却防连按、范围用空间网格优化、攻击瞬间画一道白色弧线**。每一个都是初学者最容易省略的事。

## 0 · 为什么要有这一天

最朴素的近战攻击实现:

```rust
if input.attack_pressed() {
    for monster in &mut monsters {
        if in_attack_range(player, monster) {
            monster.take_damage(10);
        }
    }
}
```

这段代码"功能上对",但**实际玩起来很糟糕**:

**糟糕 1:每帧都触发**。玩家按住 J 键,你的 input 系统每帧(60 FPS)都返回 `attack_pressed = true`(因为键还按着)。60 帧/秒 × 10 伤害 = 600 伤害/秒。任何怪秒死。这不是攻击,这是核弹。

**糟糕 2:范围判断性能差**。`for monster in &mut monsters` 扫所有怪(N=100),即使玩家在地图一角、怪在另一头。每次攻击都 N 次距离计算。

**糟糕 3:没有反馈**。玩家按 J 键,怪的血条变短了。但**屏幕上看不到任何"攻击"的视觉**——玩家感觉"我没攻击成功"还是"我攻击成功了"?不知道。游戏感极差。

今天 Casey 三个问题一起解:

1. **冷却(attack_timer)**:两次攻击最少 0.3 秒间隔,即使玩家按住
2. **空间网格查询**:用 Day 057 的 grid 找附近怪,只对它们做距离检查
3. **挥砍特效**:攻击瞬间在玩家前方画一道 0.1 秒消失的白色弧线

读完今天,你要做到:
- 看到 input 系统就知道"持续按住"和"刚按下"的差别(just_pressed vs is_down)
- 能写出 attack_timer 冷却逻辑(状态机的一环)
- 知道"视觉反馈"不是装饰,是**核心游戏感**的一部分——没有反馈的功能不算功能

如果你卡在第一点,你的 input 概念还停在"键盘状态 = 按键的 bool 数组"。回去重看 Day 037(GameInput 结构)。

## 1 · Casey 今天做了什么

Casey 第 61 集做的事:

1. 给玩家加 `attack_timer: f32` 字段(初始 0)
2. 每帧 `attack_timer -= dt`,clamp 到 0
3. 检查 input:如果**这帧刚按下** attack 键(`just_pressed`,不是 `is_down`)且 `attack_timer <= 0`,触发攻击
4. 攻击触发:`attack_timer = 0.3`(冷却 0.3 秒)
5. 用 spatial grid 找玩家附近的 entity,过滤 `kind == Monster`,做距离检查(< ATTACK_RANGE)

7. spawn 一个"挥砍特效" entity,0.1 秒后消失

视频里 Casey 演示了"不加冷却"的情况——按住 J 键怪瞬间爆炸,玩家说"这就完了?游戏没意思"。加了 0.3 秒冷却,玩家要"按 J,等 0.3 秒,再按 J",节奏出来了。

他还强调:"挥砍特效"不是装饰,是**让玩家知道攻击发生了**的视觉提示。如果玩家按 J 但屏幕没变化,玩家会以为"键没响应",反复按。视觉反馈**打断这个负反馈循环**。

## 2 · 心智模型

### 2.1 类比:真实武器

想象你拿一把剑砍人。物理上:

1. 你举剑(0.1 秒)
2. 挥下(0.1 秒)
3. 收剑回防(0.3 秒)
4. 这 0.5 秒内你**不能再砍**——剑还没回位

每秒能砍 ~2 次。如果"按住 J"=无限快砍,游戏不符合现实物理直觉,玩家潜意识觉得"假"。

游戏里的 0.3 秒冷却,本质是**模拟剑的物理恢复时间**。每种武器有不同的冷却:匕首 0.2s,长剑 0.4s,斧 0.6s。这就是武器手感 differentiation。

### 2.2 严谨:just_pressed vs is_down

游戏 input 的两个概念:

| API | 含义 | 例子 |
|---|---|---|
| `is_down(Btn)` | 这个键**现在**被按住 | 移动(WASD 长按移动) |
| `just_pressed(Btn)` | 这个键**这帧刚按下**(上一帧 up,这一帧 down) | 攻击 / 跳跃(单次触发) |

底层:input 系统维护两份键盘状态,`prev_keys[]` 和 `curr_keys[]`。每帧:
```
just_pressed(k) = curr_keys[k] && !prev_keys[k]
just_released(k) = !curr_keys[k] && prev_keys[k]
is_down(k) = curr_keys[k]
```

Casey 在 Day 037 实现 GameInput 时就做了这件事。今天是它的典型用例——攻击必须用 just_pressed,否则按住就连击。

### 2.3 冷却 timer 状态机

```rust
struct Player {
    attack_timer: f32,  // > 0 表示在冷却中
}

const ATTACK_COOLDOWN: f32 = 0.3;

impl Player {
    fn update(&mut self, input: &Input, dt: f32) -> bool {
        // 计时器递减
        if self.attack_timer > 0.0 {
            self.attack_timer -= dt;
            if self.attack_timer < 0.0 { self.attack_timer = 0.0; }
        }
        // 触发条件:刚按下 + 冷却结束
        if input.just_pressed(Btn::Attack) && self.attack_timer == 0.0 {
            self.attack_timer = ATTACK_COOLDOWN;
            return true;  // 通知外部"这次 frame 攻击了"
        }
        return false;
    }
}
```

**关键点**:
- `attack_timer == 0.0` 用 `<= 0.0` 更安全(浮点比较)
- 触发后**立即**把 timer 设为冷却值,防止同帧多次触发
- 返回 bool 让外部决定"是否执行攻击逻辑"

这是**最简 FSM**——只有两个状态(冷却中 / 可攻击),用 timer 区分。

### 2.4 攻击范围:扇形 vs 矩形

两种主流做法:

**矩形范围**(Casey 用):
```
+------+
|      |  <- 攻击矩形,在玩家朝向前方
| player ->  朝向
|      |
+------+
```
- 实现:玩家前方一个 AABB,用 Minkowski(第 050 集)
- 优点:简单,代码 5 行
- 缺点:看起来"方",不自然

**扇形范围**(更自然):
```
       /|
      / |
     /  |  <- 攻击扇形,玩家朝向前方
 player -> 朝向
     \  |
      \ |
       \|
```
- 实现:对每个候选怪,检查 1) 距离 < R,2) 玩家朝向 · 怪方向 > cos(half_angle)
- 优点:看起来自然,符合剑挥动的弧形
- 缺点:多一个点积检查

Casey 用矩形——简单,Phase 2 够用。Phase 5+ 可以升级成扇形。

### 2.5 视觉反馈:挥砍特效

```rust
fn spawn_slash_effect(world: &mut World, pos: Vec2, facing: Dir) {
    world.entities.push(Entity {
        kind: EntityKind::SlashEffect,
        pos: pos.add(facing.to_vec().mul(20.0)),  // 在玩家前方 20 像素
        half: Vec2::new(16.0, 16.0),
        sprite: Some(SpriteId::Slash),
        lifetime: 0.1,  // 0.1 秒后消失
        state: EntityState::Alive,
        // ...
    });
}
```

特效是一个**临时 entity**,有 `lifetime` 计时器。每帧:
```rust
fn update_slash_effect(e: &mut Entity, dt: f32) {
    e.lifetime -= dt;
    if e.lifetime <= 0.0 {
        e.state = EntityState::Dead;  // 触发清理
    }
    // 也可以加 alpha 渐变:`sprite_alpha = lifetime / 0.1`
}
```

特效用第 60 集的两阶段删除——Dead 后 retain 清理。

**为什么特效如此重要**:
- **确认感(confirmation)**:玩家按 J,看到白色弧线,知道"这次攻击确实发生了"。没有特效,玩家会怀疑"是不是没按到?"
- **节奏感**:0.1 秒特效 + 0.3 秒冷却 = 0.4 秒"看到 + 等待"。这是攻击的"心跳",让游戏有节奏
- **威力感**:弧线的视觉大小暗示伤害大小。大火球 = 大伤害,玩家直觉

游戏开发者把这件事叫 **"juice"**(果汁)或 **"game feel"**(游戏手感)。Casey 在第 61 集简介这个概念,后面 Day 200+ 大量加 juice(屏幕震动、粒子、卡帧 hitstop)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

近战攻击的标准化设计:

| 要素 | 标准 |
|---|---|
| 触发 | just_pressed(不能 is_down) |
| 冷却 | 0.2-0.5 秒(取决于武器手感) |
| 范围 | 矩形(简单) / 扇形(自然) / 圆形(AoE) |
| 反馈 | 视觉(特效) + 听觉(音效) + 触觉(手柄震动) |
| 命中反馈 | 受击闪烁 + 受击音效 + 击退(可选) |

**Hitstop**(卡帧):命中瞬间游戏冻结 0.05 秒。这个细节让攻击"有分量"——玩家看到时间停止,大脑知道"我刚造成了伤害"。在《超凡战队》《任天堂明星大乱斗》等动作游戏大量用。Phase 5+ Casey 会加。

**Combo 系统**:连续攻击触发 combo。每次攻击 window 内再按 → 算 combo,可能解锁不同动作。需要 combo_timer 状态机。Phase 8 才会涉及。

### 3.2 · 🎨 图形学视角

视觉反馈的几个层次:

1. **Sprite 切换**(今天):攻击时玩家 sprite 换成"挥剑"姿势
2. **附加特效**(今天):spawn 一个白色弧线 sprite,0.1 秒消失
3. **粒子效果**(Phase 4+):命中时喷 10 个粒子
4. **屏幕震动**(Phase 5+):命中时屏幕抖 5 像素
5. **扭曲特效**(Phase 6+):挥砍时屏幕轻微扭曲(shader)
6. **慢动作**(hitstop):命中时游戏暂停 0.05 秒

每多一层,游戏感提升一点。但**也有递减**——多层叠加可能让屏幕混乱。Casey 的原则:够用就好,不过度。

### 3.3 · 🐧 Linux 系统编程视角

just_pressed 在 Linux 输入子系统的对应物:

- **evdev**(/dev/input/event*):每次按键产生一个事件(EV_KEY),包含 `keydown` / `keyrepeat` / `keyup`
- **keyrepeat**:按住一段时间后,系统会发送 keyrepeat 事件(类似 OS 级别的 auto-repeat)
- 游戏通常**忽略 keyrepeat**,自己维护 prev/curr 状态,实现 just_pressed

这是 Day 037 的 GameInput 设计动机——绕开 OS 的 auto-repeat,自己管。

**epoll 边沿触发 vs 水平触发**也是类似概念:
- 水平触发(level-triggered):只要 fd 可读就一直通知(像 is_down)
- 边沿触发(edge-triggered):fd 从不可读变可读时通知一次(像 just_pressed)

游戏 input 偏好"边沿触发"——一次按键算一次事件,不重复触发。Linux 网络编程的 epoll 同样有这个选择,理解了 just_pressed 你就理解了 epoll edge-trigger。

### 3.4 · 🦀 Rust 生态视角

Rust 实现 input 系统:

```rust
#[derive(Default)]
struct Input {
    prev: HashSet<KeyCode>,
    curr: HashSet<KeyCode>,
}

impl Input {
    fn update(&mut self, keys: &HashSet<KeyCode>) {
        self.prev = std::mem::replace(&mut self.curr, keys.clone());
    }
    fn is_down(&self, k: KeyCode) -> bool { self.curr.contains(&k) }
    fn just_pressed(&self, k: KeyCode) -> bool {
        self.curr.contains(&k) && !self.prev.contains(&k)
    }
    fn just_released(&self, k: KeyCode) -> bool {
        !self.curr.contains(&k) && self.prev.contains(&k)
    }
}
```

`std::mem::replace(&mut curr, new)` 原子地"取出 curr 的旧值,放入 new 值"。Rust 惯用法,避免 clone。

`HashSet<KeyCode>` 的 lookup 是 O(1)。也可以用 `[bool; 256]` 数组(更快),但要给 KeyCode 实现 `as usize`。

#### Gilrs(Rust 游戏手柄库)

`gilrs` crate 提供手柄 input,有 `Button::is_pressed` 和 `Button::just_activated`(等同 just_pressed)。

```toml
[dependencies]
gilrs = "0.10"

use gilrs::{Gilrs, Button};

let mut gilrs = Gilrs::new().unwrap();
// 每帧
while let Some(event) = gilrs.next_event() {
    // event 是 EdgeEvent(pressed / released)
}
let gamepad = gilrs.gamepad(0);
let attack_down = gamepad.is_pressed(Button::South);  // A 按钮
```

gilrs 已经做了 just_pressed 抽象,不用自己写 prev/curr。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么攻击用 just_pressed,而移动用 is_down?反过来会有什么问题?

**参考解答**:
- 移动用 is_down:玩家按住 W,角色持续向前。这正是我们想要的——长按 = 持续移动
- 攻击用 just_pressed:玩家按 J,触发一次。如果用 is_down,每帧都触发,60 FPS × 10 dmg = 600 dmg/秒,任何怪秒死
- 跳跃也用 just_pressed:否则按住空格 = 持续跳跃(违反物理)

**反过来**(移动用 just_pressed,攻击用 is_down):
- 移动用 just_pressed:玩家按住 W,只移动一帧,然后不动。玩家必须不停按 W——反人类
- 攻击用 is_down:每帧攻击,失去冷却 / 节奏

**规则**:持续动作用 is_down(移动 / 持续攻击如激光),瞬时事件用 just_pressed(单次攻击 / 跳跃 / 切换武器)。

### Lv2 · 动手实践

**题**:实现完整近战攻击:
1. 玩家按 J 键,just_pressed 触发
2. attack_timer = 0.3,防止再触发
3. 玩家前方矩形 `(pos + facing*40, 60x60)` 范围内的怪扣 10 血
4. spawn 一个 slash effect,0.1 秒消失

**完成标准**:按 J 一次,屏幕闪一下,附近怪扣 10 血。连续按 J,实际触发频率 ≤ 3 次/秒。

**参考解答**:

```rust
use std::collections::HashSet;

#[derive(Hash, Eq, PartialEq, Clone, Copy, Debug)]
enum Key { J, W, A, S, D }

#[derive(Default)]
struct Input {
    prev: HashSet<Key>,
    curr: HashSet<Key>,
}
impl Input {
    fn press(&mut self, k: Key) { self.curr.insert(k); }
    fn release(&mut self, k: Key) { self.curr.remove(&k); }
    fn end_frame(&mut self) {
        self.prev = self.curr.clone();
    }
    fn is_down(&self, k: Key) -> bool { self.curr.contains(&k) }
    fn just_pressed(&self, k: Key) -> bool {
        self.curr.contains(&k) && !self.prev.contains(&k)
    }
}

#[derive(Clone, Copy, PartialEq, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
    fn mul(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
    fn sub(self, o: Self) -> Self { Self { x: self.x - o.x, y: self.y - o.y } }
    fn length(self) -> f32 { (self.x * self.x + self.y * self.y).sqrt() }
}

#[derive(Clone, Copy, PartialEq, Debug)]
enum Dir { Right, Left, Up, Down }
impl Dir {
    fn to_vec(self) -> Vec2 {
        match self {
            Dir::Right => Vec2::new(1.0, 0.0),
            Dir::Left  => Vec2::new(-1.0, 0.0),
            Dir::Up    => Vec2::new(0.0, -1.0),
            Dir::Down  => Vec2::new(0.0, 1.0),
        }
    }
}

const ATTACK_COOLDOWN: f32 = 0.3;
const ATTACK_RANGE: f32 = 60.0;
const ATTACK_DAMAGE: i32 = 10;

#[derive(Clone, Debug)]
struct Entity {
    name: String,
    pos: Vec2,
    hp: i32,
    is_slash_effect: bool,
    lifetime: f32,
}

struct Player {
    pos: Vec2,
    facing: Dir,
    attack_timer: f32,
}

impl Player {
    fn try_attack(&mut self, input: &Input, world: &mut World) -> bool {
        // 计时器递减
        if self.attack_timer > 0.0 {
            self.attack_timer -= 1.0 / 60.0;
            if self.attack_timer < 0.0 { self.attack_timer = 0.0; }
        }
        // 触发条件
        if input.just_pressed(Key::J) && self.attack_timer <= 0.0 {
            self.attack_timer = ATTACK_COOLDOWN;
            self.do_attack(world);
            return true;
        }
        false
    }

    fn do_attack(&self, world: &mut World) {
        let attack_center = self.pos.add(self.facing.to_vec().mul(30.0));
        // 找范围内怪,扣血
        for e in &mut world.entities {
            if e.is_slash_effect { continue; }
            let d = e.pos.sub(attack_center).length();
            if d < ATTACK_RANGE {
                e.hp -= ATTACK_DAMAGE;
                println!("  hit {} (dist {:.1}), hp now {}", e.name, d, e.hp);
            }
        }
        // spawn 视觉特效
        world.entities.push(Entity {
            name: "slash".to_string(),
            pos: attack_center,
            hp: 1,  // 不被攻击
            is_slash_effect: true,
            lifetime: 0.1,
        });
    }
}

struct World {
    entities: Vec<Entity>,
}

impl World {
    fn update(&mut self) {
        // 更新特效
        for e in &mut self.entities {
            if e.is_slash_effect {
                e.lifetime -= 1.0 / 60.0;
            }
        }
        // 帧末清理
        self.entities.retain(|e| !(e.is_slash_effect && e.lifetime <= 0.0));
    }
}

fn main() {
    let mut input = Input::default();
    let mut player = Player { pos: Vec2::new(0.0, 0.0), facing: Dir::Right, attack_timer: 0.0 };
    let mut world = World {
        entities: vec![
            Entity { name: "goblin1".into(), pos: Vec2::new(40.0, 0.0), hp: 30, is_slash_effect: false, lifetime: 0.0 },
            Entity { name: "goblin2".into(), pos: Vec2::new(80.0, 0.0), hp: 30, is_slash_effect: false, lifetime: 0.0 },
            Entity { name: "far_orc".into(), pos: Vec2::new(500.0, 0.0), hp: 100, is_slash_effect: false, lifetime: 0.0 },
        ],
    };

    // 模拟按 J 键,持续 5 帧
    for frame in 0..60 {
        if frame < 5 {
            input.press(Key::J);
        } else {
            input.release(Key::J);
        }
        let attacked = player.try_attack(&input, &mut world);
        if attacked { println!("frame {}: attack!", frame); }
        world.update();
        input.end_frame();
    }

    // 验证:即使按住 5 帧,只攻击一次(冷却)
    // goblin1 在范围内(40 像素),扣血;goblin2 在边缘(80 像素 vs 60 范围),不扣血;far_orc 完全不在
    assert!(world.entities.iter().find(|e| e.name == "goblin1").unwrap().hp == 20);
    assert!(world.entities.iter().find(|e| e.name == "goblin2").unwrap().hp == 30);
    assert!(world.entities.iter().find(|e| e.name == "far_orc").unwrap().hp == 100);
    println!("OK");
}
```

## 8 · Rust / Arch 落地代码

### 关键 Rust 特性

#### HashSet for input

```rust
prev: HashSet<Key>, curr: HashSet<Key>
```

`HashSet::contains` 是 O(1)。对按键不多(< 256)的情况,也可以用 `[bool; 256]`:

```rust
struct Input {
    prev: [bool; 256],
    curr: [bool; 256],
}
```

数组版本更快(array index 1 cycle,hash lookup ~20 cycle),但要给 Key 实现到 usize 的转换。Casey 在 C 里用数组,Rust 用 HashSet 更类型安全。

#### std::mem::replace

```rust
self.prev = std::mem::replace(&mut self.curr, keys.clone());
```

`mem::replace(&mut dest, src)` 返回 dest 的旧值,把 src 放进 dest。**原子操作**(不会被中间打断)。等价于:

```rust
let old = self.curr.clone();
self.curr = keys.clone();
self.prev = old;
```

但少一次 clone(mem::replace 把 self.curr 直接 move 出来)。

#### retain with predicate

```rust
self.entities.retain(|e| !(e.is_slash_effect && e.lifetime <= 0.0));
```

闭包 `|e| ...` 接受 &Entity 返回 bool。复杂的删除条件用组合 predicate。retain 一次扫描 O(N)。
