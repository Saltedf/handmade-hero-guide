# Day 059 · 随从:一只追玩家的宠物

> 玩家走到哪,身后跟一只小精灵(familiar)。听上去是个小事,但今天 Casey 写的 30 行代码是**所有 NPC AI 的祖先**——游戏 AI 最核心的"朝目标移动"(Seek),被压缩到三个向量运算。

## 0 · 为什么要有这一天

游戏 AI 听起来很神秘——"AI"。让人想到神经网络、强化学习、对话机器人。但**游戏 AI 不需要这些**。一个能让你**觉得"它在思考"**的 NPC,核心代码可能就 20 行。

今天 Casey 加一只随从(familiar),它会自动跟在玩家身后。具体行为:
- 离玩家远时,跑过来
- 离玩家近时,停下来
- 玩家拐弯,它也跟着拐

听起来需要"路径规划"、"决策树"、"状态机"……实际上 Casey 只用了一段 10 行的代码:

```
算"从随从到玩家"的向量
距离 > 30 像素 → 朝那个方向移动
否则 → 不动
```

这就是 **Seek 行为**——AI steering(转向行为)的最基本单元。所有更复杂的 AI 都是它的组合:

- **Flee**(逃跑):Seek 的反方向(远离玩家)
- **Arrival**:Seek + 接近时减速(避免冲过头)
- **Wander**(游走):随机小幅度 Seek(无目标方向)
- **Path-following**:沿一条预定路径,每个 waypoint 用 Seek
- **Flocking**(群集):对邻居做 Seek(对齐)+ Flee(避免拥挤)+ Seek(平均方向)

 Reynolds 1999 年的经典论文 "Steering Behaviors For Autonomous Characters" 把游戏 AI 简化为一组"转向行为",影响了一代游戏开发者。今天的随从是这套理论的第一块砖。

读完今天,你要做到:
- 看到"AI"两个字不再神秘——明白游戏 AI = 转向行为的组合
- 手写一个 Seek 行为,然后改成 Flee,看效果反过来
- 理解"距离阈值"为什么重要(否则随从会"贴脸"在玩家身上抖动)
- 知道为什么 Casey 不上"路径规划"——因为对简单 AI 太重

如果你卡在"为什么随从要停下来",你还没看见"距离阈值"的设计意图。重读 §2.2。

## 1 · Casey 今天做了什么

Casey 第 59 集做的事很轻量:

1. 在 entity 列表里加一种 `Kind::Familiar`,有 pos / vel / sprite
2. 写了一个 `update_familiar` 函数,实现 Seek 行为
3. 每帧调一次,随从自动跟玩家

视频里 Casey 特意把代码写得很短,然后说:"这是 AI 的最简形态。所有更复杂的(怪追玩家、怪逃跑、巡逻路径)都是从这个开始加 branch。"

他还演示了"如果不加距离阈值,随从会贴脸玩家抖动"——因为随从速度永远指向玩家,但每帧玩家移动,随从位置也在变,导致它在玩家身上来回震荡。

## 2 · 心智模型

### 2.1 类比:狗追主人

想象一条狗跟着主人散步。狗的行为逻辑(简化):

1. 看主人在哪
2. 算"主人在我的哪个方向"(向量)
3. 如果离得远(> 5 米),朝主人方向跑
4. 如果离得近(< 5 米),停下来等
5. 每秒重复

这就是 Seek。狗不需要"地图"、"路径规划"——只要看见主人就朝那个方向跑。中间有树挡?狗不会预先规划绕路,只会撞树(或者用第 048 集的视线检测)。

游戏 AI 的初代形态就是这样——简单、反应式、足够好玩。

### 2.2 严谨:Seek 行为的代码

```rust
fn update_familiar(familiar: &mut Entity, player_pos: Vec2, dt: f32) {
    // 1. 算"从随从到玩家"的向量
    let to_player = player_pos.sub(familiar.pos);

    // 2. 算距离
    let dist = to_player.length();

    // 3. 距离 > 阈值:Seek(朝玩家移动)
    const FOLLOW_DISTANCE: f32 = 30.0;  // 阈值
    const FAMILIAR_SPEED: f32 = 80.0;   // 像素/秒
    if dist > FOLLOW_DISTANCE {
        // normalize:把 to_player 缩成长度 1 的方向向量
        let dir = to_player.mul(1.0 / dist);
        // pos += dir * speed * dt(Euler 积分,Day 043)
        familiar.pos = familiar.pos.add(dir.mul(FAMILIAR_SPEED * dt));
    }
    // 否则:不动(dist <= 30)
}
```

**逐行解释**:

- `to_player = player_pos.sub(familiar.pos)` —— 向量减法。从 familiar 指向 player 的箭头。Day 042 讲过。

- `dist = to_player.length()` —— 向量长度,勾股定理 `sqrt(x² + y²)`。

- `if dist > FOLLOW_DISTANCE` —— **关键阈值**。如果没有这个 if,随从每帧都朝玩家移动一点点,玩家移动一点,随从也移动一点,在玩家身上抖动。

- `dir = to_player.mul(1.0 / dist)` —— **归一化**。把 to_player 缩成长度 1,只留方向。`1.0 / dist` 是缩放系数。

  - 注意:**先检查 dist > 0**,否则除零。这里因为 if 已经过滤了 dist > 30,所以安全。

- `familiar.pos = familiar.pos.add(dir.mul(FAMILIAR_SPEED * dt))` —— Euler 积分。位置 += 方向 × 速度 × 时间。Day 043 讲过。

**为什么用 normalize + mul(speed * dt),而不是直接 mul(某常数)**?

如果直接 `to_player.mul(0.1)`,随从每帧走 10% 的距离——远的时候大步,近的时候小步,逐渐减速。这叫 Arrival 行为(接近时减速)。Casey 用 normalize + 固定速度,所以**远的时候全速追,到 30 像素内突然停**。这更符合"宠物"直觉——不会减速滑过。

### 2.3 阈值的设计意图

`FOLLOW_DISTANCE = 30.0` 不是随便选的:

- **太小(比如 5)**:随从紧贴玩家,玩家转身时随从"撞"在玩家身上,看起来挤
- **太大(比如 200)**:随从离玩家老远,感觉"它根本没在跟"
- **30 像素**:玩家是 16 像素,30 大约是"两个玩家身位",感觉自然

这个数要**反复试玩调**。Casey 在视频里说"我先试 30,觉得不对再改"。游戏开发大量"magic number"都是这么调出来的——**先随便定,跑起来看,改**。

### 2.4 Flee:反向 Seek

把 Seek 反过来就是 Flee(逃跑):

```rust
fn update_fleeing_monster(monster: &mut Entity, threat_pos: Vec2, dt: f32) {
    let from_threat = monster.pos.sub(threat_pos);  // 注意:反过来
    let dist = from_threat.length();
    const FLEE_DISTANCE: f32 = 100.0;
    if dist < FLEE_DISTANCE {  // 注意:<
        let dir = from_threat.mul(1.0 / dist);
        monster.pos = monster.pos.add(dir.mul(FLEE_SPEED * dt));
    }
}
```

差别两处:
- 向量方向反了(`monster.pos - threat_pos`,从威胁指向自己)
- 条件反了(`dist < 阈值`,近才跑,远了不跑)

这就是"AI 框架"——大部分行为都是从同一段代码微调。

### 2.5 Seek 的局限

Seek 简单但有几个问题:

1. **不绕障**:随从朝玩家方向走,中间有墙就撞墙。Casey 后面(Phase 4+)会加**obstacle avoidance**(避障)。
2. **路径不优化**:随从走直线,不会走最短路径绕山。需要 A* 寻路(Day 200+)。
3. **无群体协调**:多只随从会挤在一起,看起来"集体贴脸"。需要 **flocking**(分离 + 对齐 + 凝聚)。
4. **无状态机**:随从永远在 Seek,不会"玩家跑太快了我累了停 3 秒"。需要 FSM(有限状态机)或行为树。

这些都是后期 Day 287+ 的 brain 系统加。今天只是 Seek——最基础的一块。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏 AI 的层次:

| 层 | 例子 | 复杂度 |
|---|---|---|
| 反应式(reactive) | Seek / Flee(today) | 极简 |
| 状态机(FSM) | 怪物 idle → chase → attack → flee | 中等 |
| 行为树(Behavior Tree) | 复杂 NPC(Halo / FEAR) | 复杂 |
| GOAP(Goal-Oriented Action Planning) | F.E.A.R. 的士兵 AI | 复杂 |
| Utility AI | The Sims 的需求驱动 | 中等 |
| 强化学习 | AlphaStar / OpenAI Five | 极复杂(训练) |

**90% 的游戏 AI 用反应式 + FSM 就够**。Casey 的 HH 不会上更复杂的——因为复杂 AI 在"游戏感"上提升有限,代码却翻几倍。

**Reynolds Steering Behaviors**:1999 年 Craig Reynolds 发表 "Steering Behaviors",列出十几个基础行为(Seek / Flee / Arrival / Pursue / Evade / Wander / Path-following / Separation / Alignment / Cohesion / Flocking)。今天的 Seek 是这套理论的第一块。完整论文:https://www.red3d.com/cwr/steer/

### 3.2 · 🎨 图形学视角

图形学里的 **粒子动画**(动画粒子,比如火花、烟雾)也用 Seek 类行为。每个粒子有一个"目标点"或"目标方向",每帧 Seek(或 Flee / Wander)。

**Boids 算法**(1987 Reynolds)是 flocking 的经典实现——每只鸟对邻居做 Seek(对齐)、Flee(分离)、Seek(凝聚),最终出现"鸟群"现象。今天的随从是 Boids 的简化版(只有 Seek,没分离没凝聚)。

Phase 4+ 的粒子系统会用这些。

### 3.3 · 🐧 Linux 系统编程视角

Linux 内核的 ** Completely Fair Scheduler (CFS)** 算法本质是 Seek——每个进程有 ideal runtime(理想运行时间),scheduler 算"哪个进程当前实际 runtime 离 ideal 最远",选那个。等价于"朝 ideal runtime Seek"。

更直接:**TCP 拥塞控制**。每个 TCP 连接的 cwnd(拥塞窗口)是一个数值,每收到 ACK 增加,丢包减少。本质是"朝最优 cwnd Seek"。

游戏 AI 的 Seek 不是游戏专用——任何"动态系统朝目标移动"都叫 Seek。

### 3.4 · 🦀 Rust 生态视角

Rust 写 AI 的方式:

```rust
trait AiBehavior {
    fn update(&mut self, entity: &mut Entity, world: &World, dt: f32);
}

struct Seek { target_id: EntityId, speed: f32, follow_dist: f32 }
impl AiBehavior for Seek {
    fn update(&mut self, entity: &mut Entity, world: &World, dt: f32) {
        let target_pos = world.entities[&self.target_id].pos;
        let to_t = target_pos.sub(entity.pos);
        let d = to_t.length();
        if d > self.follow_dist {
            let dir = to_t.mul(1.0 / d);
            entity.pos = entity.pos.add(dir.mul(self.speed * dt));
        }
    }
}

struct Flee { threat_id: EntityId, speed: f32, flee_dist: f32 }
impl AiBehavior for Flee {
    fn update(&mut self, entity: &mut Entity, world: &World, dt: f32) {
        let threat_pos = world.entities[&self.threat_id].pos;
        let from_t = entity.pos.sub(threat_pos);
        let d = from_t.length();
        if d < self.flee_dist {
            let dir = from_t.mul(1.0 / d);
            entity.pos = entity.pos.add(dir.mul(self.speed * dt));
        }
    }
}
```

trait `AiBehavior` 让你**组合**行为(用 enum 或 Vec<Box<dyn AiBehavior>>)。

**生产建议**:
- 教学阶段:手写 Seek / Flee,理解每一行
- Phase 4+:抽 AiBehavior trait,允许每个 entity 有多个行为并行
- Phase 5+:用行为树(Behavior Tree)替代 FSM

**Rust 的优势**:enum + match 让"状态机"实现极简:

```rust
enum FamiliarState { Idle, Following, Resting }

impl FamiliarState {
    fn update(&mut self, e: &mut Entity, player_pos: Vec2, dt: f32) {
        match self {
            FamiliarState::Idle => {
                // 检查玩家是否在视野
                if e.pos.sub(player_pos).length() < 200.0 {
                    *self = FamiliarState::Following;
                }
            }
            FamiliarState::Following => {
                seek(e, player_pos, dt);
                if e.pos.sub(player_pos).length() < 5.0 {
                    *self = FamiliarState::Resting;
                }
            }
            FamiliarState::Resting => {
                // 玩家走远了又开始追
                if e.pos.sub(player_pos).length() > 30.0 {
                    *self = FamiliarState::Following;
                }
            }
        }
    }
}
```

C 要用 switch + 函数指针,Rust 的 enum + match 直接且编译器验证完整性。


### 3.5 · 🐧 Linux 系统编程视角(内核空间 / 硬件加速)

Linux 系统里"碰撞 / 相交检测"的核心思想在多处出现,理解这些能让你看 Casey 的 2D / 3D collision 算法在更广的语境里。

**内核的 page fault 处理**。虚拟内存到物理内存的映射,本质是"地址空间相交检测"。CPU 访问虚拟地址,MMU 查 page table,如果地址不在已映射范围内 → page fault。内核接 fault,检查(1)地址合法吗(进程的 VMA 区间)、(2)权限对吗(read / write / exec)、(3)page 在物理内存还是 swap。这套检查就是"区间相交 + 属性匹配",和 Casey 在 day 050 的 Minkowski collision 在抽象上一致——"用几何空间判断两个东西是否接触"。

```bash
# 看你进程的 VMA(虚拟内存区域)
cat /proc/$$/maps
# 输出形如:
# 56001234-56005678 r-xp ...  /usr/bin/bash
# 7f1234560000-7f1234780000 r--p ... /usr/lib/libc.so.6

# 触发 page fault(故意访问非法地址)
python3 -c "import ctypes; ctypes.cast(0xdeadbeef, ctypes.POINTER(ctypes.c_int))[0] = 0"
# 输出:Segmentation fault (core dumped)
```

**epoll / poll / select** 是 IO 多路复用,本质是"时间区间相交"。你给内核 N 个 fd,内核检查"哪个 fd 当前可读 / 可写"。这是 N 路并行等待,内核用红黑树 + ready list 高效管理。和 collision detection 的 broad phase 类似——快速排除不可能相交的对,只在 narrow phase 详细检查。

**文件锁(flock / fcntl)**。Linux 文件锁检测"两个进程是否同时持有冲突锁"——这是"锁区间相交"。flock 用 inode-level 锁,fcntl 用 byte-range 锁(`fcntl(F_SETLK, F_WRLCK, {100..200})` 锁字节 100-200)。内核维护锁列表,新锁请求时遍历检查冲突——这就是 interval intersection 检测。

**网络栈的 TCP / IP header 校验**。每个 TCP/IP 包带 checksum,内核收到包校验——本质是"数据完整性检测"。和 collision detection 不直接相关,但**思想相同**——"用一个数学函数快速判断数据是否合法"。

**cgroup 的资源限制**。`cpu.max = 50000 100000` 表示 cgroup 在每 100ms 周期内最多用 50ms CPU。内核定期检查"当前周期已用多少 CPU",超了 throttle。这是"时间区间累积 + 阈值检测",和 Casey 的"span duration + frame budget"逻辑相同。

**netfilter / iptables** 用 BPF 风格的规则匹配,检查每个网络包。"规则匹配"本质是"包属性 vs 规则区间"——"src IP in 192.168.0.0/16 && dst port == 22"是区间检测。BPF (Berkeley Packet Filter) 让用户写过滤器,内核执行——这种"用户定义函数 + 内核执行"模式是 eBPF 的基础。

**kernel scheduling**。Linux CFS(Completely Fair Scheduler)维护红黑树 of runnable tasks,按 vruntime 排序。每个 tick(1ms / 4ms),CFS 检查当前 task 是否该让出 CPU——"时间片用完了吗"。这是"时间累积 + 阈值切换",和游戏 update 循环的 frame budget 检查同构。

### 3.6 · 🦀 Rust 生态视角

Rust 在游戏物理 / 碰撞领域有几个值得关注的 crate 和模式。

**`rapier`** 是 Rust 的 2D / 3D 物理引擎,由 Dimforge 开发。Rapier 提供 rigid body dynamics、collision detection、joints、rays、sensors——是 Bevy 生态的物理默认选项。Rapier 用 ECS 风格 API,内部用 SOA(struct of arrays)布局,cache 友好。

```rust
use rapier3d::prelude::*;

let mut rigid_body_set = RigidBodySet::new();
let mut collider_set = ColliderSet::new();

let rigid_body = RigidBodyBuilder::dynamic().translation(vector![0.0, 5.0, 0.0]).build();
let handle = rigid_body_set.insert(rigid_body);
let collider = ColliderBuilder::ball(0.5).build();
collider_set.insert_with_parent(collider, handle, &mut rigid_body_set);
```

Rapier 内部用 **broad phase(AABB tree)+ narrow phase(GJK / SAT)**,和工业 C++ 引擎(Box2D、Bullet、PhysX)思路一致。Casey HH 手写简化版,Rapier 是 production-grade。

**`parry`** 是 Rapier 抽出来的纯 collision detection 库。parry 提供 shape(ball、cuboid、convex hull、triangle mesh)、ray cast、point projection、pair collision——不涉及 dynamics。如果你只想要碰撞不想物理,parry 是答案。

**`nalgebra`** 是 Rust 的线性代数库,Dimforge 出品(同 Rapier / parry)。`Vector3`、`Matrix4`、`Quaternion`、`Isometry3`——3D 游戏需要的所有数学类型。比 `cgmath` 现代、比 `euclid` 全面。

**Rust ECS 的 collision pattern**。Bevy + Rapier 的典型代码:

```rust
use bevy::prelude::*;
use bevy_rapier3d::prelude::*;

fn setup(mut commands: Commands) {
    commands.spawn((
        RigidBody::Dynamic,
        Collider::ball(1.0),
        Transform::from_translation(Vec3::new(0.0, 5.0, 0.0)),
    ));
}

fn on_collision(
    mut events: EventReader<CollisionEvent>,
    query: Query<&Name>,
) {
    for event in events.read() {
        if let CollisionEvent::Started(e1, e2, _) = event {
            println!("{:?} collided with {:?}", query.get(*e1), query.get(*e2));
        }
    }
}
```

ECS 风格——entity 加 Collider component,系统处理 CollisionEvent。这是 Rust 风格的 collision 设计——数据导向、零成本、类型安全。Casey HH 用 OOP 风格(`struct Player { collider: Collider }`),简单但不够通用。

**Rust 的 zero-cost abstraction** 让 collision detection 可以既高级又快:

```rust
// 高级 API
let hits = colliders.iter()
    .filter(|c| c.aabb_intersects(&target_aabb))
    .filter(|c| c.shape_intersects(&target_shape))
    .collect::<Vec<_>>();

// LLVM 把这优化成手写 C 的等价代码
```

Rust 的 iterator chain + 闭包,被 LLVM inline + vectorize,生成和手写循环一样快的代码。这是 Rust 在性能敏感领域的杀手锏。

**Rust 的 SIMD** 对 collision 特别有用。AABB 测试 8 个浮点比较,用 SIMD 一次处理 4-8 个 AABB。Rust 的 `std::simd`(unstable)或 `wide` crate(stable)提供 SIMD API。Rapier 内部用 SIMD 加速 broad phase。

**Rust 的多线程 collision**。collision detection 是 embarrassingly parallel——N 个 object pair 互相独立。Rust 的 `rayon` 提供 parallel iterator,`colliders.par_iter().filter(...)` 自动并行。Bevy 用 ECS 的 `query.par_iter()` 同样效果。

**Rust 的 `Send + Sync`**。collision data 跨线程共享,要 `Send + Sync`。Rust 编译时检查——如果你的 Collider 包含 `Rc<...>`,编译失败,因为 Rc 不是 Send。这种类型系统保证的多线程安全,是 Rust 比 C++ 优势的地方。

**Rust 的 `smallvec`** 在 collision 里有用。pair list 经常是空的或只有 1-2 个 pair,用 `SmallVec<[Pair; 4]>` 避免堆分配,大部分情况栈上。

**Rust 的 `ahash`** 在 spatial hash 里替代 `DefaultHasher`——3-5 倍速度。Casey HH 的 hash chunk storage(Phase 2)用 `DefaultHasher`,Rust 版应该用 `ahash` 或 `fxhash`。

|---|---|---|
| Seek(today) | dir = (target - self).normalize(),pos += dir * speed * dt | 追玩家 |
| Flee | dir = (self - target).normalize() | 跑路 |
| Arrival | 速度 = k * dist(dist 近时减速) | 不冲过目标 |
| Pursue | target = target_entity.pos + target_entity.vel * prediction | 预判目标位置(打提前量) |
| Evade | Pursue 的反 | 躲预判 |
| Wander | dir += random()*k,normalize | 随机游走 |
| Path-following | 多个 waypoint,逐个 Seek | 沿路径走 |

### 4.3 下级

- **向量减法** —— 算 to_target
- **Length / Normalize** —— 转换成方向
- **距离阈值** —— 防止贴脸抖动
- **Euler 积分** —— pos += vel * dt
- **Magic number** —— FOLLOW_DISTANCE / SPEED(靠试玩调)

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Seek 为什么需要"距离阈值"?不设会怎样?

**参考解答**:不设的话,随从每帧都朝玩家移动一点点。具体场景:
- 玩家在 (100, 100),随从在 (100, 95)。to_player = (0, 5),dir = (0, 1),随从移动 (0, speed * dt) = (0, 1.3) 大约
- 随从到 (100, 96.3)。玩家移动到 (100, 100.5)。to_player = (0, 4.2),dir = (0, 1),随从到 (100, 97.6)
- ...

随从每帧追 1 像素,玩家每帧移动 1-2 像素。看起来随从"贴在玩家身后"——但它**永远在抖动**,因为每帧玩家方向都在小变。

更严重的情况:随从追到玩家位置(距离 = 0),下一帧 normalize 除零,变成 NaN,entity 飞出屏幕。

距离阈值(30 像素)让随从在"足够近"时停下,避免抖动和除零。

### Lv2 · 动手实践

**题**:在游戏里加一只 familiar。具体:
1. 在 entities 列表里加一个 EntityKind::Familiar,初始位置离玩家 50 像素
2. 每帧调 update_familiar,实现 Seek
3. 用键盘控制玩家(WASD),看到随从跟着跑

**完成标准**:玩家走来走去,随从在身后跟随,玩家停下来随从也停下来。

**参考解答**:

```rust
const FAMILIAR_FOLLOW_DIST: f32 = 30.0;
const FAMILIAR_SPEED: f32 = 80.0;  // 像素/秒

fn update_familiar(familiar: &mut Entity, player_pos: Vec2, dt: f32) {
    let to_player = player_pos.sub(familiar.pos);
    let dist_sq = to_player.x * to_player.x + to_player.y * to_player.y;
    // 用 dist_sq 比较,避免 sqrt(优化)
    if dist_sq > FAMILIAR_FOLLOW_DIST * FAMILIAR_FOLLOW_DIST {
        let dist = dist_sq.sqrt();
        let dir = Vec2::new(to_player.x / dist, to_player.y / dist);
        familiar.pos = familiar.pos.add(dir.mul(FAMILIAR_SPEED * dt));
    }
}
```

**优化点**:
- 用 `dist_sq` 比较,避免开方。`sqrt` 在 f32 上 ~10 cycles,乘法 ~1 cycle。在 hot loop 里有意义
- `dist > 0` 由 `dist > FAMILIAR_FOLLOW_DIST` 保证,不会除零

**演示 main**:

```rust
fn main() {
    let mut player = Entity::player(Vec2::new(100.0, 100.0));
    let mut familiar = Entity::familiar(Vec2::new(150.0, 100.0));

    let dt = 1.0 / 60.0;
    // 模拟玩家向右走
    for frame in 0..180 {
        player.pos = player.pos.add(Vec2::new(50.0 * dt, 0.0));
        update_familiar(&mut familiar, player.pos, dt);
        if frame % 30 == 0 {
            println!("frame {}: player=({:.1},{:.1}) familiar=({:.1},{:.1})",
                frame, player.pos.x, player.pos.y, familiar.pos.x, familiar.pos.y);
        }
    }
    // 玩家停了
    for frame in 180..240 {
        update_familiar(&mut familiar, player.pos, dt);
    }
    println!("final: player={:?} familiar={:?}", player.pos, familiar.pos);
    // 随从应该在玩家身后 30 像素内
    let d = player.pos.sub(familiar.pos).length();
    assert!(d <= 35.0, "familiar should be within follow distance");
    println!("OK");
}
```

## 8 · Rust / Arch 落地代码

### 关键 Rust 特性

#### const 常量

```rust
const FAMILIAR_FOLLOW_DIST: f32 = 30.0;
```

`const` 编译时求值,内联到使用处(没有运行时内存地址)。比 `static` 更轻——`static` 是有地址的全局变量,`const` 是字面值。

Casey 在 C 里用 `#define`,Rust 用 `const`,效果一样。

#### 距离平方比较(优化)

```rust
let dist_sq = to_player.x * to_player.x + to_player.y * to_player.y;
if dist_sq > FAMILIAR_FOLLOW_DIST * FAMILIAR_FOLLOW_DIST { ... }
```

`a² > b² ⟺ a > b`(对正数)。所以**比较距离的平方**等价于比较距离,但**省了一次 sqrt**。

sqrt 在 f32 上约 10-20 cycles,乘法 1 cycle。在每帧执行 1000 次的 hot loop 里,省 sqrt 是显著优化。

Casey 在 C 里也大量用这种"平方比较"。

#### 单元测试 magic number

```rust
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn familiar_follows_player() {
        let mut familiar = Entity::familiar(Vec2::new(0.0, 0.0));
        let player_pos = Vec2::new(100.0, 0.0);
        // 60 帧后,随从应该靠近玩家
        for _ in 0..60 {
            update_familiar(&mut familiar, player_pos, 1.0 / 60.0);
        }
        let d = familiar.pos.sub(player_pos).length();
        assert!(d <= FAMILIAR_FOLLOW_DIST + 1.0);  // +1 容错
    }
}
```

测试 AI 行为比测纯函数难——结果是位置变化,依赖时间步。**固定 dt(1/60),固定帧数(60),验证最终位置在容差内**。
