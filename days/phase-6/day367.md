
# Day 367 · 启用 OpenGL 多重采样

> 立方体画出来了,但**边缘全是锯齿**——一条本该平滑的对角线,放大后是阶梯状的折线。这是光栅化算法的固有产物。今天 Casey 启用 **MSAA(Multisample Anti-Aliasing,多重采样抗锯齿)**,让 GPU 在每个像素采多个样本,边缘锯齿消失。

## 0 · 为什么要有这一天

你的立方体渲染出来了,屏幕上终于有"真正的 3D"了。但你看一眼就觉得**丑**——立方体的轮廓不是平滑的直线,是阶梯状的锯齿,像 1990 年代游戏的低分辨率画面。这种锯齿的官方术语叫 **aliasing(走样)**,它源自信号处理领域的奈奎斯特-香农采样定理:**信号的高频分量如果超过采样频率一半,就会"伪装"成低频信号**,在画面上表现为锯齿/摩尔纹/闪烁。

锯齿不仅是审美问题,还是**功能问题**。想象你做狙击瞄准镜,远处的电线在屏幕上是 0.3 像素宽——一帧画出来,这帧有,下一帧相机移动 0.1 像素,这条电线**完全消失**(因为它的子像素位置变了)。这种"远处物体闪烁"叫 **temporal aliasing(时间走样)**,玩家完全无法瞄准。

消除锯齿的技术统称 **AA(Anti-Aliasing,抗锯齿)**。游戏工业至少有 6 种主流方案:**MSAA, SSAA, FXAA, SMAA, TAA, DLAA**。它们各有取舍:画质、性能、内存、动态适配。今天 Casey 启用的是最古老最稳定的 **MSAA**——GPU 硬件原生支持,实现简单,画质好,代价是显存翻倍。

**为什么 MSAA 是工业级的"默认 AA"**?因为它**只对几何边缘做超采样**,不对 shader 输出做超采样,所以性能损失小(比 SSAA 快 4 倍以上),效果显著(边缘平滑),实现只需 3 步:申请 multisample framebuffer、启用 `GL_MULTISAMPLE`、驱动会自动做 resolve(把多 sample 合成单像素)。

心理锚点:今天之后,你能让任何 OpenGL 渲染启用 4x / 8x / 16x MSAA,理解 GPU 在 framebuffer 里怎么"用空间换质量",知道为什么 MSAA 对 shader 内部产生的锯齿(如透明纹理边缘)无效。

## 1 · Casey 今天做了什么(HH 脉络)

Day 366 立方体渲染后,Casey 注意到锯齿。他选 MSAA 而不是其他 AA,理由:

1. **MSAA 硬件原生**——OpenGL 1.3 起就支持,任何 GPU 都有
2. **改动小**——只需在创建 window 时申请 multisample framebuffer,渲染端几乎不变
3. **画质足够**——HH 是教学项目,4x MSAA 已经够好

Casey 的具体动作:

1. **创建 window 时申请 MSAA**:GLFW 调用 `glfwWindowHint(GLFW_SAMPLES, 4)`,要求 framebuffer 每像素 4 个 sample
2. **初始化时启用 `glEnable(GL_MULTISAMPLE)`**——告诉 OpenGL"对 multisample framebuffer 做抗锯齿"
3. **窗口 swap 后,驱动自动 resolve**——把 4 sample 平均成 1 像素,输出到屏幕

Casey 在视频里展示了**开关 MSAA 前后的对比截图**:开启后立方体边缘平滑,关闭后锯齿明显。他还顺手提了一句:**MSAA 只对几何边缘有效,shader 里写的算法(如 specular 高光)产生的锯齿它管不了**——这是 MSAA 的本质局限,Day 380+ 的延迟渲染会暴露这点。

## 2 · 心智模型

### 类比:MSAA 是"边缘 4 倍精度,内部 1 倍精度"

想象你画一条斜线,用网格纸涂格子代表像素。普通光栅化:**格子中心在线上才涂**,所以斜线变成阶梯:

```
原始像素光栅化(1 sample per pixel):
    ████████
    ███████
    ██████
    ██████        ← 阶梯状边缘
    █████
    ████
```

**SSAA(Supersampling AA,超采样抗锯齿)**:把整个画面分成 4 倍像素(每个原像素内 4 个子像素),shader 跑 4 次,4 个结果平均:

```
SSAA 4x:
    ▓▓▓▓▓▓▓▓      ← ▓ = 半透明(2 个子像素覆盖,2 个没覆盖)
    ▓▓▓▓▓▓▓▓▓
    ▓▓▓▓▓▓▓▓
    ...
```

SSAA 画质最好,但 **shader 跑 4 次,性能损失 75%**,工业不用。

**MSAA(Multisample AA,多重采样抗锯齿)**:**几何覆盖测试**跑 4 次(子像素精度),**shader 只跑 1 次**(像素中心)。Shader 输出按覆盖率混合到 4 个 sample 上。

```
MSAA 4x:
  像素中心:    ▓
  4 个子样本: ● ●
              ● ●      ← 几何覆盖测试 4 次
  shader 跑 1 次,输出按覆盖子样本数加权平均
```

性能损失:**几何部分 4 倍,shader 部分 1 倍**。比 SSAA 快 4 倍以上,边缘画质几乎一样好。

### 严谨原理:覆盖率(coverage)和样本(sample)

GPU 光栅化一个三角形时,对每个像素:
1. **覆盖率测试**:把像素分成 N 个子位置(4x MSAA 是 4 个,8x 是 8 个)。每个子位置看是否在三角形内。结果是一个 N 位掩码(如 `0b1011` = 4 个子位置中 3 个在三角形内)。
2. **Shader 执行**:对像素中心跑一次 fragment shader,得到颜色。
3. **混合**:颜色 × 覆盖率 + framebuffer 原色 × (1 - 覆盖率)。具体到 N 个 sample,每个被覆盖的 sample 都得到 shader 输出的颜色,没被覆盖的保留原色。

```
像素 4 sample,2 个在三角形内:

原始:               MSAA 后:
┌─────┐              ┌─────┐
│ ● ● │ ← 2 in       │ ▓ ▓ │ ← 这两个 sample 是三角形颜色
│ ● ● │ ← 2 out      │ ○ ○ │ ← 这两个保留背景色
└─────┘              └─────┘
                     显示时:平均 4 个 sample → 半透明边缘
```

显示时驱动(resolve):每像素把 N 个 sample 颜色平均,得到最终显示色。这就是为什么 MSAA 让边缘"半透明化"——其实是平均了被覆盖和未被覆盖的 sample。

### 关键限制:shader 跑 1 次

MSAA 美妙之处是 shader 只跑一次。但这意味着** shader 内部的判断/分支产生的锯齿无法消除**。

例子:shader 里写 `if (uv.x < 0.5) color = red else color = blue`,像素中心 uv.x = 0.49 → 整个像素红。但实际 uv = 0.5 处是一条边界,边缘像素本应"半红半蓝"。MSAA 不会重跑 shader,所以边缘是硬切的。

这就是为什么 **alpha test(用 `discard` 切除透明像素)的边缘**——例如树叶纹理——MSAA 处理不了。Casey 在 Day 380+ 用 alpha-tested 几何时会发现这点,需要切到 deferred shading 或用其他 AA(如 TAA)。

### OpenGL 启用 MSAA 的三步

**第 1 步:window 创建时申请 multisample framebuffer**

```c
// C(GLFW)
glfwWindowHint(GLFW_SAMPLES, 4);   // 申请 4x MSAA
window = glfwCreateWindow(1920, 1080, "HH", NULL, NULL);
```

驱动会向 X server / WGL / GLX 请求一个支持 MSAA 的 visual / pixel format。如果硬件支持 4x MSAA,生成的 framebuffer 就是 multisample。

**第 2 步:初始化时启用 multisample**

```c
glEnable(GL_MULTISAMPLE);
```

告诉 OpenGL:对 multisample framebuffer,启用 multisample 光栅化。如果 framebuffer 不是 multisample,这行没效果。

**第 3 步:渲染,swap buffer**

OpenGL 自动处理。`glfwSwapBuffers` 时驱动把 multisample framebuffer resolve(平均 samples)到默认 framebuffer(单 sample),送显示器。

### 自定义 multisample resolve(Day 386 主题)

驱动自动 resolve 是黑盒,Casey 在 Day 386 想自定义 resolve(因为做深度剥离时不能用默认 resolve)。那时他用 `glBlitFramebuffer` 显式 resolve,或者直接在 shader 里读 multisample texture 用 `texelFetch` 取 sample。这是后话。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

AA 在游戏里的实际配置:

| AA 方案 | 性能 | 内存 | 画质 | 动态适配 | HH 用过吗 |
|---|---|---|---|---|---|
| MSAA 4x | 70-90% fps | +50% 显存 | 边缘好,shader 内锯齿没救 | 否 | ✅ |
| SSAA 4x | 25% fps | +300% 显存 | 最好 | 否 | ✕ 太贵 |
| FXAA | 95% fps | 几乎无 | 中等,模糊 | 是 | ✕(后处理) |
| SMAA | 90% fps | 几乎无 | 好,清晰 | 是 | ✕ |
| TAA | 70-90% fps | +1 历史 buffer | 非常好,有鬼影 | 是 | ✕ |
| DLSS (NVIDIA) | 100%+ fps(超分) | 神经网络 | 极好 | 是 | ✕ |

游戏设计选择:
- **竞技射击**(CS:GO, Valorant):关闭 AA,或 MSAA。FXAA 的模糊让远距离敌人难看清。
- **开放世界**(Witcher 3, RDR2):TAA + TAAU/TSR,处理高频细节(植被)更好
- **手机游戏**:FXAA,因为 MSAA 对 tile-based GPU(PowerVR/Mali)不友好
- **VR**:MSAA 必须,TAA 的鬼影在 VR 里非常明显

Casey 用 MSAA 是教学取舍:简单、稳定、效果可见。**理解了 MSAA 你才能理解后续 AA 在解决什么 MSAA 解决不了的问题**。

### 3.2 · 🎨 图形学视角

MSAA 涉及几个深层概念:

**Sample locations(采样位置)**

GPU 厂商决定每个像素的 N 个 sample 的具体位置。NVIDIA 用旋转网格(NQS - Quincunx, RGSS),AMD 用旋转网格,Intel 也类似。位置不是均匀网格,而是经过精心设计的抖动模式,最大化边缘抗锯齿效果。

OpenGL 不直接暴露 sample positions,但可以用 `glGetMultisamplefv(GL_SAMPLE_POSITION, i, &pos)` 查询。这在自定义 resolve(Day 386)时有用。

**Coverage modulation(覆盖率调制)**

更高级的 AA 让 fragment shader 输出"coverage mask",修改默认覆盖率。例如 alpha-to-coverage:shader 输出 alpha,GPU 把 alpha 转 4 位掩码(`alpha > 0.75 → 0b1111`,`0.5 < alpha < 0.75 → 0b0011` 等),用于植被叶片边缘。

**Multisample textures**

OpenGL 3.2+ 引入 `GL_TEXTURE_2D_MULTISAMPLE`,允许在 shader 里读 multisample texture 的单个 sample。这是 Day 386 自定义 resolve 的基础:

```glsl
// fragment shader 读 multisample texture 的某个 sample
uniform sampler2DMS texMS;
ivec2 uv = ivec2(gl_FragCoord.xy);
vec4 s0 = texelFetch(texMS, uv, 0);  // sample 0
vec4 s1 = texelFetch(texMS, uv, 1);  // sample 1
vec4 avg = (s0 + s1) * 0.5;          // 自定义 resolve
```

这是 Casey Day 386 写自定义 resolve 的核心。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 MSAA 不能消除"shader 内部判断产生的锯齿"?举例说明。

**参考解答**:MSAA 在像素级**只跑一次 fragment shader**,像素中心位置决定 shader 输出。如果 shader 内有 `if (uv.x < 0.5)`,像素中心 uv.x = 0.49 → 整像素红。但 uv.x = 0.5 的边界其实横穿这个像素,**本应一半红一半蓝**。MSAA 不知道 shader 内部的逻辑边界,只对几何边界(三角形边缘)做超采样。

举例:树叶纹理。alpha 通道定义叶片形状,alpha = 1 处不透明,alpha = 0 处透明。Shader 写 `if (texture.a < 0.5) discard;`。这产生一棵树的边缘锯齿——**叶子轮廓的锯齿**。MSAA 不解决,因为它是 shader 内部判断。解决方案:alpha-to-coverage(把 alpha 转 coverage mask,让 GPU 在 sample 级别应用透明度),或者切到 alpha blend(预乘 alpha)。

### Lv2 · 动手实践

**题**:在 GLFW 项目里启用 4x MSAA。完成标准:
- 启动后立方体边缘平滑
- 程序里 `glGetIntegerv(GL_SAMPLES, &n)` 打印 n = 4
- 用 `radeontop` / `intel_gpu_top` 看 VRAM 占用比未启用多约 30-50MB

**参考解答**:

```rust
use glfw::{Context, Glfw, Window, WindowEvent, FailOnError};
use gl::types::*;

fn main() {
    let mut glfw = glfw::init(FailOnError).unwrap();

    // 关键:申请 multisample framebuffer
    glfw.window_hint(glfw::WindowHint::Samples(Some(4)));
    glfw.window_hint(glfw::WindowHint::ContextVersion(3, 3));
    glfw.window_hint(glfw::WindowHint::OpenGlProfile(
        glfw::OpenGlProfileHint::Core,
    ));

    let (mut window, events) = glfw
        .create_window(1920, 1080, "MSAA demo", glfw::WindowMode::Windowed)
        .expect("Failed to create window");

    window.make_current();
    window.set_key_polling(true);
    gl::load_with(|s| window.get_proc_address(s) as *const _);

    unsafe {
        // 验证 sample count
        let mut samples = 0;
        gl::GetIntegerv(gl::SAMPLES, &mut samples);
        println!("GL_SAMPLES = {}", samples);   // 应输出 4

        // 启用 multisample
        gl::Enable(gl::MULTISAMPLE);

        // 检查启动状态
        let mut enabled = 0;
        gl::GetIntegerv(gl::MULTISAMPLE, &mut enabled);
        assert_eq!(enabled, 1);
    }

    while !window.should_close() {
        unsafe {
            gl::ClearColor(0.1, 0.1, 0.15, 1.0);
            gl::Clear(gl::COLOR_BUFFER_BIT | gl::DEPTH_BUFFER_BIT);
            // 绘制立方体 ...
        }
        window.swap_buffers();
        glfw.poll_events();
    }
}
```

**关键解释**:
- `glfw.window_hint` 必须在 `create_window` 前调用,告诉 GLFW 向驱动申请带 MSAA 的 framebuffer
- `gl::Enable(gl::MULTISAMPLE)` 必须在 GL context 创建后调用
- 如果驱动不支持 4x MSAA,GLFW 会回退到 0 sample(无 MSAA),`GL_SAMPLES` 返回 0。这时你应该 log 警告
- 不同 sample count 的代价:4x 增加 ~50% 显存,8x 增加 ~100%,16x 增加 ~200%

### Rust:带 MSAA 的 OpenGL 渲染循环

```rust
// Cargo.toml:
// [dependencies]
// gl = "0.14"
// glfw = "0.55"

use glfw::{Context, FailOnError, Glfw, Window, WindowEvent};
use gl::types::*;
use std::sync::mpsc::Receiver;

pub struct GLState {
    pub glfw: Glfw,
    pub window: Window,
    pub events: Receiver<(f64, WindowEvent)>,
    pub samples: GLint,    // MSAA sample count
}

impl GLState {
    pub fn new(width: u32, height: u32, msaa: u32) -> Self {
        let mut glfw = glfw::init(FailOnError).unwrap();

        // 关键:申请 MSAA framebuffer
        glfw.window_hint(glfw::WindowHint::Samples(Some(msaa as u32)));
        glfw.window_hint(glfw::WindowHint::ContextVersion(3, 3));
        glfw.window_hint(glfw::WindowHint::OpenGlProfile(
            glfw::OpenGlProfileHint::Core,
        ));
        glfw.window_hint(glfw::WindowHint::OpenGlForwardCompat(true));

        let (window, events) = glfw
            .create_window(width, height, "Handmade Hero", glfw::WindowMode::Windowed)
            .expect("Failed to create GLFW window.");

        window.make_current();
        window.set_key_polling(true);
        window.set_size_polling(true);

        gl::load_with(|s| window.get_proc_address(s) as *const _);

        let mut samples: GLint = 0;
        unsafe {
            gl::GetIntegerv(gl::SAMPLES, &mut samples);
            println!("Framebuffer sample count: {}", samples);

            if samples > 0 {
                gl::Enable(gl::MULTISAMPLE);
                println!("MSAA enabled ({}x)", samples);
            } else {
                println!("WARNING: MSAA not available, rendering aliased");
            }

            gl::Enable(gl::DEPTH_TEST);
            gl::Enable(gl::CULL_FACE);
            gl::CullFace(gl::BACK);
            gl::FrontFace(gl::CCW);
        }

        Self { glfw, window, events, samples }
    }

    pub fn poll_events(&mut self) -> impl Iterator<Item = WindowEvent> {
        self.glfw.poll_events();
        self.events.try_iter().map(|(_, e)| e)
    }

    pub fn swap(&mut self) {
        self.window.swap_buffers();
    }

    pub fn should_close(&self) -> bool {
        self.window.should_close()
    }

    pub fn viewport(&self) -> (i32, i32) {
        let (w, h) = self.window.get_size();
        (w as i32, h as i32)
    }
}

fn main() {
    let mut gl_state = GLState::new(1920, 1080, 4);

    // (这里加载立方体 mesh、shader,见 day366)
    // let cube = CubeMesh::new();
    // let shader = Shader::new(...);

    while !gl_state.should_close() {
        for event in gl_state.poll_events() {
            match event {
                glfw::WindowEvent::Key(glfw::Key::Escape, _, _, _) |
                glfw::WindowEvent::Key(glfw::Key::Q, _, _, _) => {
                    gl_state.window.set_should_close(true);
                }
                glfw::WindowEvent::Size(w, h) => {
                    unsafe { gl::Viewport(0, 0, w, h); }
                }
                _ => {}
            }
        }

        unsafe {
            gl::ClearColor(0.1, 0.1, 0.15, 1.0);
            gl::Clear(gl::COLOR_BUFFER_BIT | gl::DEPTH_BUFFER_BIT);

            // 渲染立方体
            // shader.use_program();
            // cube.draw();
        }

        gl_state.swap();
    }
}
```

**关键 Rust 特性解释**:
- `glfw::WindowHint::Samples(Some(4))` — `Option<u32>` 表示 sample count,`None` 是默认,`Some(n)` 申请 n 个 sample
- `gl::GetIntegerv(gl::SAMPLES, &mut samples)` — 查询当前 framebuffer 的 sample count。Rust 的 `&mut` 强制要求变量预先声明
- `if samples > 0` 的安全检查 — 不是所有驱动都能给你申请的 sample count,可能回退到 0
- `set_size_polling(true)` — 监听窗口大小变化,实时调整 viewport。MSAA framebuffer 大小变化时驱动自动重建
- `try_iter()` — 非阻塞迭代事件队列,不阻塞主循环

```bash
# 1. 验证 OpenGL 版本和 MSAA 支持

# -d 指定输出文件,-l 60 采 60 次
# 看 vram usage 列,启用 MSAA 应增加

# 5. apitrace 对比 MSAA 前后
sudo pacman -S apitrace
apitrace trace ./target/release/handmade_hero
qapitrace handmade_hero.trace &
# 在 trace GUI 里查看 glDrawElements 调用,
# 应该看到 framebuffer 是 GL_TEXTURE_2D_MULTISAMPLE
```

**Troubleshooting**:

- **`GL_SAMPLES = 0`** — 驱动没给 multisample framebuffer。检查 `glxinfo` 是否支持 multisample;检查 GLFW hint 顺序(Samples 必须在 ContextVersion 之前或同一时机)
- **窗口黑屏但没崩溃** — depth test 没设,multisample framebuffer 没有 depth attachment。MSAA framebuffer 的 depth buffer 也必须是 multisample
- **MSAA 启用后性能掉很多** — sample count 太高。8x MSAA 在 1080p 中端卡上可能掉 30%,4x 通常 < 10%
- **shader 里 `texelFetch` 拿不到 multisample 数据** — 普通纹理和 multisample 纹理是不同类型,必须用 `sampler2DMS`
