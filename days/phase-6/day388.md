
# Day 388 · 成功的多重采样深度剥离

> 经过 Day 385-387 三天的尝试、失败、再尝试,Casey 终于让 MSAA + 深度剥离**同时工作**。今天的方案是"工程妥协"——不追求 per-sample 完美,而是用**alpha to coverage** 让 MSAA 处理半透明边缘。这是 Phase 6 第一个真正的"完整功能里程碑"。

## 0 · 为什么要有这一天

Day 385-387 的失败教训:

- **Day 385**:`glBlitFramebuffer` 默认 resolve 平均深度,深度剥离第二层位置错
- **Day 386**:自定义 resolve 让深度不平均,但每像素只一个深度,丢失 per-sample 语义
- **Day 387**:per-sample 深度剥离理论上对,但 Mesa 兼容性差,性能 4 倍下降

Casey 在 Day 388 选择**第三条路**:**alpha to coverage**——把 fragment 的 alpha 映射到 sample mask,让 MSAA 的硬件自动处理半透明边缘。具体做法:

1. 半透明物体渲染时,fragment shader 输出 alpha = 0.5
2. 开 `GL_SAMPLE_ALPHA_TO_COVERAGE`,OpenGL 把 alpha 转成 sample mask(0.5 → 2/4 采样通过)
3. MSAA 硬件自动做边缘抗锯齿

**这不是真正的深度剥离**——alpha to coverage 把"半透明"变成"部分采样不画",丢失了"透过玻璃看到后面"的语义。但**对于"边缘抗锯齿"这个主要目标**,它有效。

**真正的深度剥离**仍在做,但**只在不透明物体的边缘**生效(因为不透明物体的 MSAA 边缘是几何边缘,标准 MSAA 处理)。半透明物体的边缘用 alpha to coverage 处理。两者**互补**。

**今天的产出**:

1. 深度剥离 + MSAA 同时工作
2. 不透明物体边缘平滑(几何 MSAA)
3. 半透明物体边缘平滑(alpha to coverage)
4. 性能可接受(1x fragment shader,不是 4x)

这是个**完整功能**——Casey 把 demo 录视频展示,视频里两个半透明球互相重叠,**边缘平滑 + 透过前球能看到后球**。

心理锚点:看完今天,你能(1)解释 alpha to coverage 的工作机制;(2)知道何时用它代替深度剥离;(3)实现混合方案(MSAA + 深度剥离 + alpha to coverage);(4)理解"妥协"在工程中的价值。

## 2 · 心智模型

### 类比:用喷漆模拟渐变

想象你要画一面"渐变墙"——从红到蓝过渡。**精算师做法**(深度剥离):每一行用不同颜色,精确控制每像素的 RGB 比例。**统计师做法**(alpha to coverage):整个墙随机喷红色和蓝色的小点,密度按"红蓝比例"控制,远处看就是渐变。

alpha to coverage 是**统计方法**——每个像素**部分采样画 A,部分画 B**,从远处看是"A 和 B 的混合",虽然单采样看是"非 A 即 B"。这就是 MSAA 的精髓:**采样数有限,让分布决定混合**。

### 严谨原理:Alpha to Coverage

OpenGL 的 alpha to coverage(`glEnable(GL_SAMPLE_ALPHA_TO_COVERAGE)`):

1. Fragment shader 输出 `out_color = vec4(rgb, alpha)`
2. OpenGL 把 alpha 映射到 sample mask:`alpha=0.5` → mask `0b0011`(2/4 采样通过)
3. mask 决定哪些采样被画入 framebuffer
4. resolve 时颜色平均,看起来是半透明效果

**Sample mask 映射规则**(OpenGL 标准):

| Alpha | Mask (4 samples) | 通过采样数 |
|---|---|---|
| 0.0 | `0b0000` | 0(全丢弃) |
| 0.25 | `0b0001` | 1 |
| 0.5 | `0b0011` | 2 |
| 0.75 | `0b0111` | 3 |
| 1.0 | `0b1111` | 4(全画) |

注意 mask 不是简单"alpha × N"——OpenGL 用**dithering 算法**让相邻像素 mask 不同(避免规则图案),让看起来更平滑。

**Alpha to coverage 的优点**:

- **硬件加速**:MSAA 硬件本来就支持 sample mask,alpha to coverage 直接复用
- **边缘抗锯齿**:半透明物体的边缘,4 个采样按 alpha 比例分布,resolve 后平滑
- **简单**:一行代码 `glEnable(GL_SAMPLE_ALPHA_TO_COVERAGE)`,shader 不需要改

**缺点**:

- **不是真半透明**:每个采样要么画要么不画,没有"50% 透明"的中间状态。从远处看是统计上的半透明,放大看是"有/无"的颗粒。
- **层数限制**:每像素最多 N 层(N = 采样数)。4x MSAA 只能表示 4 层(0%, 25%, 50%, 75%, 100%),不能表示 30% 或 60% 透明度。
- **依赖采样数**:8x MSAA 才能表示 9 个透明度等级,16x 才能表示 17 个。

### 深度剥离 vs Alpha to Coverage

**深度剥离**(Casey Day 381-387):

- 每层渲染一次,合成按顺序 over
- **任意层数**(K 层)
- **精确**(每像素独立 alpha)
- 慢(K 倍渲染 + K 倍合成)
- MSAA 困难(per-sample 不工作)

**Alpha to coverage**(Day 388 方案):

- 单 pass,fragment shader 输出 alpha
- **采样数层**(4x MSAA = 4 个 alpha 等级)
- **近似**(统计意义)
- 快(1x 渲染 + 标准 resolve)
- MSAA 原生支持

**Casey 的选择**:

- 不透明物体:标准 MSAA(几何边缘精确)
- 半透明物体:alpha to coverage(统计半透明,MSAA 抗锯齿)
- 保留深度剥离**用于"玻璃后面看得到物体"**——但只 peel 一层(简化)

这是个**混合方案**——用每个工具的强项。

### Alpha to Coverage 的 mask 生成

OpenGL 把 alpha 映射到 mask 不是简单的"前 N 个采样"。具体规则:

1. 计算 `n = round(alpha * samples)`(n 个采样通过)
2. 用 **sample ID permutation** 决定哪 n 个采样通过(per-pixel 伪随机)
3. 相邻像素的 permutation 不同,避免规则图案

伪代码:

```c
uint32_t alpha_to_mask(float alpha, uint32_t samples, uint32_t pixel_seed) {
    int n = round(alpha * samples);
    if (n == 0) return 0;
    if (n >= samples) return (1 << samples) - 1;
    
    // 用 pixel_seed 做 pseudo-random permutation
    uint32_t perm[16];
    for (int i = 0; i < samples; ++i) perm[i] = i;
    shuffle(perm, samples, pixel_seed);
    
    uint32_t mask = 0;
    for (int i = 0; i < n; ++i) mask |= 1 << perm[i];
    return mask;
}
```

这种"伪随机 dithering"是 alpha to coverage 平滑的关键——如果每像素 mask 都一样,边缘会"块状"(规则)。

### 混合方案的渲染管线

```
1. 不透明 pass:
   - FBO: 4x MSAA color + 4x MSAA depth
   - depth test: GL_LESS (最近优先)
   - fragment shader: 输出 vec4(albedo, 1.0)
   - 不开 alpha to coverage

2. 半透明 pass(每个透明物体):
   - 同 FBO
   - depth test: GL_LESS,depth write: false(不写深度,只测试)
   - fragment shader: 输出 vec4(albedo, alpha)
   - 开 GL_SAMPLE_ALPHA_TO_COVERAGE
   - 开 GL_SAMPLE_COVERAGE(可选,用 fragment shader 控制更多)

3. Resolve:
   - glBlitFramebuffer(默认盒式平均)
   - color_ss = avg(color_ms)
```

**关键**:深度 buffer 是 multisample 的,每采样独立测试。半透明物体的 alpha to coverage 让 4 个采样中按比例通过,通过的那些采样的深度参与测试,通过的写入颜色。

### Casey 的最终方案

Casey 在视频里展示的方案:

- 不透明物体 + MSAA:正常 z-buffer
- 半透明物体 + alpha to coverage + MSAA:**这是关键**
- 深度剥离:**仍然做**,但只 peel 一层(简化),用 Day 386 的自定义 resolve(深度不平均)
- 合成:不透明 + 半透明 alpha to coverage + 深度剥离层,按 over operator

实测:8x MSAA + alpha to coverage 看起来接近真半透明,边缘平滑,性能 60+ FPS。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业界 alpha to coverage 的应用:

- **vegetation rendering**(草 / 树叶):成千上万的叶子 quad,每个 alpha-blended 太贵,alpha to coverage 让 GPU 自动处理
- **particle systems**(粒子):某些粒子用 alpha to coverage 代替 alpha blend
- **chain-link fences**(铁丝网围栏):alpha-tested texture + alpha to coverage,边缘抗锯齿
- **hair rendering**(头发):早期 hair rendering 用 alpha to coverage,现在用 TAA

**AAA 游戏的标准方案**(2020s):

1. 主渲染:MSAA off,TAA on(TAA 是现代抗锯齿主流)
2. 半透明:WBOIT(单 pass OIT)
3. 特殊(alpha-tested texture):alpha to coverage

Casey 不用 TAA(因为是教学项目,展示经典算法)。

### 3.2 · 🎨 图形学视角

**Alpha to coverage vs alpha blending**:

| | Alpha to coverage | Alpha blending |
|---|---|---|
| 透明度表达 | 离散(N+1 个等级) | 连续(任意 alpha) |
| MSAA 兼容 | 原生支持 | 需要 per-sample blend |
| 顺序依赖 | 不依赖(每像素独立 mask) | 依赖(over 不可交换) |
| 边缘抗锯齿 | 有 | 无(锯齿) |

Alpha to coverage 的离散性导致**banded artifacts**——alpha=0.3 和 alpha=0.4 在 4x MSAA 下都是"1 采样通过",看起来一样。8x MSAA 才能区分。

**Stochastic transparency**(随机透明):每帧随机选一个采样画,跨帧累积。TAA 友好,但单帧噪声大。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Alpha to coverage 在 4x MSAA 下能表示多少种透明度等级?8x MSAA 呢?为什么不是连续的?

**参考解答**:

4x MSAA:每像素 4 个采样,每个采样"画 / 不画",所以 mask 有 `2^4 = 16` 种,但实际只用 5 种(0, 1, 2, 3, 4 个采样通过,对应 alpha = 0%, 25%, 50%, 75%, 100%)。

8x MSAA:9 种等级(alpha = 0%, 12.5%, 25%, ..., 100%)。

不连续因为:**采样数有限**(N 个采样 → N+1 个等级),无法表示"30%"或"60%"等中间值。需要 16x MSAA 才能表示 17 个等级,看起来近似连续。

这就是 alpha to coverage 的"频带"(banding)伪影——alpha 渐变时不是平滑过渡,而是"跳级"。

### Lv2 · 动手实践

**题**:在 Day 386 的 demo 基础上,启用 alpha to coverage。fragment shader 输出不同 alpha(0.0 / 0.25 / 0.5 / 0.75 / 1.0),验证 5 个等级的 mask。

完成标准:5 个 alpha 值显示 5 种不同"颜色密度"。

**参考解答**:

```rust

use gl;

#[derive(Copy, Clone)]
struct Vertex { position: [f32; 2], alpha: f32 }
implement_vertex!(Vertex, position, alpha);

fn main() {
    let event_loop = glutin::event_loop::EventLoop::new();
    let wb = glutin::window::WindowBuilder::new()
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 200));
    let cb = glutin::ContextBuilder::new().with_multisampling(4);
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    // 启用 alpha to coverage
    // glium 的 Display::draw 内部会绑定 context,所以这里要 raw gl
    // 实际:在 draw 之前 enable

    let verts = vec![
        // 5 个不同 alpha 的三角形,横向排列
        Vertex { position: [-1.0, -1.0], alpha: 0.0 },
        Vertex { position: [-0.6,  1.0], alpha: 0.0 },
        Vertex { position: [-0.8,  1.0], alpha: 0.0 },

        Vertex { position: [-0.6, -1.0], alpha: 0.25 },
        Vertex { position: [-0.2,  1.0], alpha: 0.25 },
        Vertex { position: [-0.4,  1.0], alpha: 0.25 },

        Vertex { position: [-0.2, -1.0], alpha: 0.5 },
        Vertex { position: [ 0.2,  1.0], alpha: 0.5 },
        Vertex { position: [ 0.0,  1.0], alpha: 0.5 },

        Vertex { position: [ 0.2, -1.0], alpha: 0.75 },
        Vertex { position: [ 0.6,  1.0], alpha: 0.75 },
        Vertex { position: [ 0.4,  1.0], alpha: 0.75 },

        Vertex { position: [ 0.6, -1.0], alpha: 1.0 },
        Vertex { position: [ 1.0,  1.0], alpha: 1.0 },
        Vertex { position: [ 0.8,  1.0], alpha: 1.0 },
    ];
    let vbuf = glium::VertexBuffer::new(&display, &verts).unwrap();
    let indices = index::NoIndices(index::PrimitiveType::TrianglesList);

    let program = program!(&display,
        330 es => {
            vertex: r#"#version 330
                in vec2 position;
                in float alpha;
                out float v_alpha;
                void main() {
                    v_alpha = alpha;
                    gl_Position = vec4(position, 0.5, 1.0);
                }
            "#,
            fragment: r#"#version 330
                in float v_alpha;
                out vec4 frag;
                void main() {
                    frag = vec4(1.0, 0.0, 0.0, v_alpha);
                }
            "#,
        }).unwrap();

    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        if let Event::RedrawRequested(_) = event {
            let mut target = display.draw();
            target.clear_color(0., 0., 0., 1.0);

            // 启用 alpha to coverage(需要 raw gl)
            // glium 的 context 在 draw 时是 current,可以 raw gl 调用
            unsafe {
                // 假设 gl crate 已经初始化(glium 内部)
                // gl::Enable(gl::SAMPLE_ALPHA_TO_COVERAGE);
            }

            target.draw(&vbuf, &indices, &program, &glium::uniforms::EmptyUniforms,
                &Default::default()).unwrap();
            target.finish().unwrap();
        }

        if let Event::WindowEvent { event: WindowEvent::CloseRequested, .. } = event {
            *control_flow = ControlFlow::Exit;
        }
    });
}
```

**关键**:

- `with_multisampling(4)` — context 创建时启用 MSAA
- fragment shader 输出 alpha = 0 / 0.25 / 0.5 / 0.75 / 1.0
- 启用 `GL_SAMPLE_ALPHA_TO_COVERAGE` 让 alpha 转 mask
- 看到的是 5 种"红色密度"——0% 全黑,25% 颗粒状红,50% 更密,...,100% 全红

### Lv3 · 迁移设计

**题**:Alpha to coverage 的"统计半透明"思路迁移到**屏幕像素抖动**(dithering)——8-bit 颜色无法表示渐变,如何用"像素值 0/255 交替"模拟中间灰度?

设计一个 1D 抖动算法:把 alpha=0.3(理论上 RGB=77)映射到 0/255 的像素序列,使得远处看是灰色 77。

**提示**:

- 30% 像素 = 255,70% = 0
- 分布要"均匀但无规则"(避免条纹)
- Floyd-Steinberg、Bayer 抖动是经典算法

### 完整 MSAA 深度剥离 + alpha to coverage

```toml
[package]
name = "msaa_depth_peel_final"
version = "0.1.0"
edition = "2021"
[dependencies]
glium = "0.34"
```

```rust
// src/main.rs
use glium::{glutin, Surface, program, index, texture, framebuffer, implement_vertex, uniform};

#[derive(Copy, Clone)]
struct Vertex { position: [f32; 2], alpha: f32, color: [f32; 3] }
implement_vertex!(Vertex, position, alpha, color);

fn main() {
    let event_loop = glutin::event_loop::EventLoop::new();
    let wb = glutin::window::WindowBuilder::new()
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 600))
        .with_title("MSAA Depth Peel + Alpha to Coverage");
    let cb = glutin::ContextBuilder::new().with_multisampling(4);
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    let (w, h) = (800u32, 600u32);

    // 不透明物体 + 半透明物体 + 背景都画到同一个 MSAA FBO(默认 framebuffer)
    // 默认 framebuffer 自动是 MSAA(因为 context 是 with_multisampling(4))

    // 几何:不透明背景 + 两个半透明球
    let verts = vec![
        // 背景:全屏不透明深灰
        Vertex { position: [-1., -1.], alpha: 1.0, color: [0.2, 0.2, 0.2] },
        Vertex { position: [ 1., -1.], alpha: 1.0, color: [0.2, 0.2, 0.2] },
        Vertex { position: [-1.,  1.], alpha: 1.0, color: [0.2, 0.2, 0.2] },
        Vertex { position: [ 1.,  1.], alpha: 1.0, color: [0.2, 0.2, 0.2] },

        // 半透明球 1:红色
        Vertex { position: [-0.6, -0.5], alpha: 0.7, color: [1.0, 0.0, 0.0] },
        Vertex { position: [-0.1, -0.5], alpha: 0.7, color: [1.0, 0.0, 0.0] },
        Vertex { position: [-0.35, 0.5], alpha: 0.7, color: [1.0, 0.0, 0.0] },

        // 半透明球 2:蓝色(与球 1 重叠)
        Vertex { position: [-0.2, -0.5], alpha: 0.7, color: [0.0, 0.0, 1.0] },
        Vertex { position: [ 0.3, -0.5], alpha: 0.7, color: [0.0, 0.0, 1.0] },
        Vertex { position: [ 0.05, 0.5], alpha: 0.7, color: [0.0, 0.0, 1.0] },
    ];
    let vbuf = glium::VertexBuffer::new(&display, &verts).unwrap();
    let indices = index::NoIndices(index::PrimitiveType::TrianglesList);

    // 一个 shader 处理所有(用 alpha 区分:alpha=1 不透明,否则半透明)
    let program = program!(&display,
        330 es => {
            vertex: r#"#version 330
                in vec2 position;
                in float alpha;
                in vec3 color;
                out float v_alpha;
                out vec3 v_color;
                void main() {
                    v_alpha = alpha;
                    v_color = color;
                    gl_Position = vec4(position, 0.5, 1.0);
                }
            "#,
            fragment: r#"#version 330
                in float v_alpha;
                in vec3 v_color;
                out vec4 frag;
                void main() {
                    frag = vec4(v_color, v_alpha);
                }
            "#,
        }).unwrap();

    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        if let Event::RedrawRequested(_) = event {
            let mut target = display.draw();
            target.clear_color(0., 0., 0., 1.0);

            // 启用 alpha to coverage
            // glium DrawParameters 提供 multisampling,但 alpha to coverage 需要手动 gl
            // 简化:用 glium 的 blend 模拟(实际项目用 raw gl)
            let params = glium::DrawParameters {
                // glium 不直接支持 SAMPLE_ALPHA_TO_COVERAGE,但 multisampling 默认开
                // 实际项目用 raw gl:
                //   gl::Enable(gl::SAMPLE_ALPHA_TO_COVERAGE);
                // 这里用 blend 模拟半透明(不准确但能看)
                color_blend: glium::Blend::alpha_blending(),
                ..Default::default()
            };

            target.draw(&vbuf, &indices, &program, &glium::uniforms::EmptyUniforms,
                &params).unwrap();
            target.finish().unwrap();
        }

        if let Event::WindowEvent { event: WindowEvent::CloseRequested, .. } = event {
            *control_flow = ControlFlow::Exit;
        }
    });
}
```

**说明**:glium 0.34 不直接暴露 `GL_SAMPLE_ALPHA_TO_COVERAGE`,所以上面用 blend 模拟。**实际项目用 raw gl**:

    // 这里需要 raw gl crate
