> 前 4 天加滑块、加按钮、加柱状图,UI 代码越堆越乱。今天 Casey 不加新功能,做一次纯重构——把"每个 UI 元素自己硬编码位置"改成"布局系统自动算位置",代码量减少一半,加新元素只要写一行。

## 0 · 为什么要有这一天

你的 profiler overlay 现在有这些元素:

- 5 个按钮(Bar / Clocks / Mem / Reset / Save)
- 1 个滑块
- 1 个柱状图
- 1 个状态文字

每个元素的坐标都是手写的:

```rust
let btn1 = Button::new(20,  20, 100, 30, "Bar");
let btn2 = Button::new(130, 20, 100, 30, "Clocks");
let btn3 = Button::new(240, 20, 100, 30, "Mem");
let btn4 = Button::new(350, 20, 100, 30, "Reset");
let btn5 = Button::new(460, 20, 100, 30, "Save");
```

现在你想:

- 把所有按钮往下移 10 像素?要改 5 处
- 把按钮改成 120 宽,中间留 5 间距?要改 10 处(x 和 w)
- 加第 6 个按钮?要心算"460 + 110 + 10 = 580"
- 把按钮换成两行?重新算所有坐标

这就是"魔法数字"的灾难——每个数字都是孤立写的,彼此的关系(等距、对齐)全靠程序员心算维护。一个数字改了,相关的其他数字不会自动跟上,bug 就来了。

更糟糕的是"视觉一致性":你想让所有按钮看起来对齐到同一个网格,但每个按钮的 y 坐标都不同(可能是 20、22、18,因为不同时间写的)。屏幕上一看就有错位。

今天 Casey 引入**布局系统**(layout system):告诉系统"我要 5 个按钮水平排列,从 (20, 20) 开始,每个 100×30,中间留 10 像素",系统自动算出每个按钮的位置。这是所有现代 UI 框架(HTML/CSS flexbox、Flutter Row/Column、egui ui.horizontal)的核心抽象。

心理锚点:重构后,加一个新按钮只要在数组里多写一个 label,布局自动调整。

## 1 · Casey 今天做了什么

Casey 花了一整集做"看似零进度"的重构:

## 2 · 心智模型

### 类比:HTML 的 flexbox

你大概见过这样的 HTML:

```html
<div style="display: flex; gap: 10px;">
  <button>Bar</button>
  <button>Clocks</button>
  <button>Mem</button>
</div>
```

浏览器看到这段 HTML,自动算出 3 个按钮的位置:第一个在 (0, 0),第二个在 (110, 0)(第一个的 width=100 + gap=10),第三个在 (220, 0)。你**不用算坐标**,只声明结构。

这是 layout system 的精髓:**用结构(谁挨着谁)代替坐标(像素位置)**。

Casey 今天实现的就是"原始版 flexbox"——更简单,只有水平和垂直两个方向,没有 wrap / shrink / grow,但思想一致。

### 严谨原理:layout 的算法

水平布局算法:

```
fn layout_horizontal(x0: i32, y0: i32, gap: i32, items: &[Item]) -> Vec<Rect> {
    let mut x = x0;
    let mut rects = Vec::with_capacity(items.len());
    for item in items {
        rects.push(Rect { x, y: y0, w: item.w, h: item.h });
        x += item.w + gap;
    }
    rects
}
```

注意几个细节:

1. **起始位置 `(x0, y0)`**:整个组的左上角
2. **gap 是元素之间的间距**,不是元素外的 padding
3. **每个元素自己的尺寸 `(w, h)` 由元素定义**,layout 只负责位置
4. **下一个元素的 x = 当前元素的 x + w + gap**,这是累加,不是绝对坐标

垂直布局同理,只是把 x 换成 y。

### 复合布局:嵌套

实际 UI 经常是嵌套的。比如:

- 顶部一组水平按钮
- 中间一个柱状图
- 底部一组水平(滑块 + 状态文字)

可以表达成:

```
layout_vertical(0, 0, 0, &[
    Group::Children(layout_horizontal(0, 0, 10, &[...])),
    Group::Single(chart_rect),
    Group::Children(layout_horizontal(0, 0, 10, &[...])),
])
```

但 Rust 写嵌套布局容易引发类型混乱,Casey 选了更简单的"手动调用 layout 函数,拿到 Rect 数组再分发":

```rust
let button_rects = layout_horizontal(20, 20, 10, &button_specs);
let chart_rect = Rect::new(50, 80, 700, 200);
let slider_rect = layout_horizontal(100, 550, 10, &slider_specs)[0];

// 然后用这些 Rect 创建实际控件
for (rect, spec) in button_rects.iter().zip(button_specs.iter()) {
    buttons.push(Button::new(rect.x, rect.y, rect.w, rect.h, spec.label, spec.event));
}
```

代码从"每个按钮硬编码"变成"声明结构 + 循环创建"。

### 布局参数的来源

把"魔法数字"集中到常量:

```rust
const MARGIN: i32 = 20;        // 屏幕边缘留白
const BUTTON_W: i32 = 100;
const BUTTON_H: i32 = 30;
const BUTTON_GAP: i32 = 10;

const CHART_W: i32 = 700;
const CHART_H: i32 = 200;
const CHART_GAP: i32 = 30;
```

所有 layout 调用都用这些常量,改一处全局生效。这就是"参数化"——把容易变化的值抽出来,集中管理。

### 布局变化时怎么办?

Casey 今天做的是**静态布局**:启动时算一次,后面不变。如果你的 UI 元素会动态增减(比如调试时加临时按钮),需要重新跑 layout。

更复杂的布局系统(HTML flexbox、Flutter)支持**动态 layout**:每次重画前重新算布局。代价是 CPU 开销(每帧算一遍),好处是 UI 变化自动适应。

Casey 走静态布局,因为 HH 的 UI 元素固定。后面 Day 268(调试链接和组)会涉及动态 UI,届时再考虑。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏 UI 布局有几个特殊考量:

1. **多分辨率**:游戏要在 1080p / 1440p / 4K / 手机竖屏上都好看。布局必须支持"相对单位"(百分比、anchor)
2. **HUD vs 暂停菜单**:HUD(抬头显示)固定位置(血条在左上),暂停菜单居中
3. **本地化**:中文标签比英文短或长,布局要适应文字宽度
4. **手柄焦点导航**:Tab/方向键在 UI 元素间切换,布局定义了导航顺序

游戏引擎(Unity / Unreal)都内置了 Canvas / Anchor / Layout Widget 系统。Casey 手写最简单的版本——足够教学,生产项目会用更复杂的。

### 3.2 · 🎨 图形学视角

布局系统的几何本质是**矩形的递归组合**。每个 UI 元素是一个 Rect(x, y, w, h),布局是把这些 Rect 按规则摆放。规则可以复杂(HTML CSS 有 200+ 属性),但核心是几个:

- **position**:相对父元素还是绝对
- **flex-direction**:水平还是垂直
- **gap**:间距
- **align**:主轴 / 交叉轴对齐(start / center / end)
- **wrap**:超出后换行

理解这些核心规则,看任何 UI 框架的代码都不会陌生。

布局还有一个图形学细节:**裁剪(clip)**。一个元素的内容可能超出 Rect 边界,要不要画出去?Casey 在 Day 267 专门处理这个。

### 3.3 · 🐧 Linux 系统编程视角

Linux 桌面有几种 layout 系统:

- **X11 / Wayland**:核心是窗口位置,窗口内布局由应用自己决定
- **GTK**:CSS-like 布局,`GtkBox` 类似 flexbox
- **Qt**:`QHBoxLayout` / `QVBoxLayout`,布局类
- **i3 / sway**(tiling WM):把屏幕空间分给各个窗口,本身就是一个 layout system

理解 layout 的本质后,你会发现 i3 的"水平 / 垂直 split"和今天 Casey 写的 layout_horizontal 是同一个东西——把空间按规则分给子元素。

### 3.4 · 🦀 Rust 生态视角

Rust 表达 layout 有几种风格:

#### 风格 1:函数式(返回 Rect 数组)

```rust
fn layout_h(x0: i32, y0: i32, gap: i32, items: &[(i32, i32)]) -> Vec<Rect> {
    let mut x = x0;
    items.iter().map(|&(w, h)| {
        let r = Rect { x, y: y0, w, h };
        x += w + gap;
        r
    }).collect()
}
```

简单,无状态,但是每次调用都 alloc 一个 Vec。

#### 风格 2:迭代器(零分配)

```rust
fn layout_h_iter(x0: i32, y0: i32, gap: i32, items: &[(i32, i32)])
    -> impl Iterator<Item = Rect> + '_
{
    let mut x = x0;
    items.iter().map(move |&(w, h)| {
        let r = Rect { x, y: y0, w, h };
        x += w + gap;
        r
    })
}
```

注意 `move` 捕获 `x0`, `y0`, `gap` by value,但 `x` 是 mut 的——闭包内 mut 捕获是 Rust 1.50+ 的特性。

#### 风格 3:egui 的 immediate-mode

```rust
ui.horizontal(|ui| {
    if ui.button("Bar").clicked() { /* ... */ }
    if ui.button("Clocks").clicked() { /* ... */ }
    if ui.button("Mem").clicked() { /* ... */ }
});
```

`ui.horizontal` 接受一个闭包,闭包里所有 `ui.button` 自动按水平排列。这是 immediate-mode 的简洁写法,但需要 egui 这样的框架。

#### 风格 4:builder pattern

```rust
Layout::horizontal()
    .origin(20, 20)
    .gap(10)
    .item(Button::new("Bar"))
    .item(Button::new("Clocks"))
    .build()
```

链式调用,优雅,但需要写一堆 builder 方法。Casey 不走这条,因为 C 没有这个语法,Rust 端我们也可以简化。

### 3.5 · 软件工程:重构的纪律

今天是一次典型的**重构**(refactoring)。Martin Fowler 在《Refactoring》一书里定义:"重构是改变软件内部结构,但不改变外部行为的过程"。

重构的纪律:

1. **先有测试**:重构前要有自动化测试验证行为不变。Casey 用"视觉一致"作测试——前后截图对比
2. **小步前进**:每次只改一处,跑测试,提交。不要"一次重构 1000 行"
3. **行为不变**:外部 API 不变,功能不变,只改内部实现
4. **提交粒度**:每次重构是一个 commit,commit message 写"refactor: ..."

Casey 在视频里强调:**重构不引入新功能**。如果你想边重构边加新功能,极容易出 bug——重构 bug 和功能 bug 混在一起,定位极难。

## 5 · 对照与变奏

### 不同 UI 框架的布局哲学

| 框架 | 哲学 | 表达方式 |
|---|---|---|
| HTML/CSS | 声明式 + 规则 | `<div style="flex: 1">` |
| Qt | C++ 类 + 属性 | `layout->addWidget(btn)` |
| GTK | CSS-like + Box | `GtkBox.pack_start(btn)` |
| Dear ImGui | immediate + stack | `ImGui::SameLine()` |
| egui | immediate + closure | `ui.horizontal(\|ui\| {...})` |
| Flutter | widget tree | `Row(children: [...])` |
| Casey HH | 手写函数 | `layout_h(...)` |

每种都解决同一问题,差异在表达力 / 易用性 / 性能的 trade-off。

### 静态布局 vs 动态布局

| 类型 | 何时算 | 优点 | 缺点 |
|---|---|---|---|
| 静态(今天做) | 启动时算一次 | 零运行时开销 | UI 变化要重算 |
| 动态(flexbox) | 每帧重算 | 自适应 | CPU 开销 |
| 半静态(egui) | 每帧重算但简化 | 平衡 | 实现复杂 |

Casey 选静态,因为 HH 的 UI 元素固定。如果你的 profiler 加了"展开 / 折叠"功能,需要切到半静态。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:重构前,你的代码里有 5 个按钮的硬编码坐标。重构后,你用 `layout_horizontal` + 一个 button_specs 数组。请论证:**重构后代码行数减少,但可维护性提升大于行数减少**。给出至少 3 个具体理由。

**参考解答**:
1. **修改成本下降**:重构前改"按钮宽 100 → 120"要改 5 处 x 坐标(每个按钮的 x 都依赖前一个的 w);重构后改 BUTTON_W 一处,所有按钮自动跟上
2. **加新元素成本下降**:重构前加第 6 个按钮要心算坐标(460 + 110 + 10 = 580),容易算错;重构后在数组里加一个元素即可,坐标自动算
3. **错误率下降**:重构前每个坐标都是独立硬编码,容易写错(比如某个 y=22 而其他 y=20),视觉错位;重构后所有 y 由 layout 函数统一算,不可能错位
4. **抽象提升**:重构后代码意图明确——"5 个按钮水平排列",读代码的人立刻看懂;重构前要数循环展开后的 5 行硬编码
5. **未来扩展**:重构后改成"垂直排列"或"两行"只是改一个函数调用;重构前要重写所有坐标

行数减少是表面好处,真正的收益是**耦合度下降**——每个数字不再孤立维护,而是按结构关系自动派生。

### Lv2 · 动手实践

**题**:实现 `layout_horizontal` 和 `layout_vertical` 函数,以及一个 `Rect` 结构。要求:

- `Rect { x: i32, y: i32, w: i32, h: i32 }`
- `layout_horizontal(x0, y0, gap, items: &[Item]) -> Vec<Rect>` where Item 是 `(w, h)`
- 同理 `layout_vertical`

测试:`layout_horizontal(20, 20, 10, &[(100, 30), (100, 30), (100, 30)])` 应该返回 3 个 Rect:
- (20, 20, 100, 30)
- (130, 20, 100, 30)
- (240, 20, 100, 30)

完成标准:打印三个 Rect,坐标正确。

**参考解答**:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
struct Rect {
    x: i32, y: i32, w: i32, h: i32,
}

impl Rect {
    fn new(x: i32, y: i32, w: i32, h: i32) -> Self {
        Self { x, y, w, h }
    }
}

type Item = (i32, i32);  // (width, height)

fn layout_horizontal(x0: i32, y0: i32, gap: i32, items: &[Item]) -> Vec<Rect> {
    let mut x = x0;
    let mut result = Vec::with_capacity(items.len());
    for &(w, h) in items {
        result.push(Rect::new(x, y0, w, h));
        x += w + gap;
    }
    result
}

fn layout_vertical(x0: i32, y0: i32, gap: i32, items: &[Item]) -> Vec<Rect> {
    let mut y = y0;
    let mut result = Vec::with_capacity(items.len());
    for &(w, h) in items {
        result.push(Rect::new(x0, y, w, h));
        y += h + gap;
    }
    result
}

fn main() {
    let button_specs: Vec<Item> = vec![(100, 30), (100, 30), (100, 30)];
    let rects = layout_horizontal(20, 20, 10, &button_specs);
    for (i, r) in rects.iter().enumerate() {
        println!("Button {}: {:?}", i, r);
    }
    // 输出:
    // Button 0: Rect { x: 20, y: 20, w: 100, h: 30 }
    // Button 1: Rect { x: 130, y: 20, w: 100, h: 30 }
    // Button 2: Rect { x: 240, y: 20, w: 100, h: 30 }

    // 垂直布局测试
    let v_rects = layout_vertical(20, 100, 5, &[(80, 20), (80, 20)]);
    for r in &v_rects {
        println!("{:?}", r);
    }
    // Rect { x: 20, y: 100, w: 80, h: 20 }
    // Rect { x: 20, y: 125, w: 80, h: 20 }
}
```

**每行解释**:
- `Vec::with_capacity(n)` 预分配容量,避免 push 时 realloc
- `&(w, h)` 是模式匹配:解构 tuple 引用
- `x += w + gap` 累加下一个元素的 x 坐标
- 垂直布局只是把 x 换成 y,完全对称

### Lv3 · 迁移设计

**题**:实现一个 **flexbox 风格的布局**,支持 `MainAlign::Start / Center / End / SpaceBetween`:

- Start: 元素紧靠起点(今天做的)
- Center: 元素居中(整体居中,元素之间间距 = gap)

提示:SpaceBetween 的 gap 计算公式:`gap_actual = (container_w - sum(items_w)) / (n - 1)`,n=2 时除 1,n=1 时直接居中。

## 8 · Rust / Arch 落地代码

### 完整重构:profiler UI 用布局系统

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, MouseMode, MouseButton, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;

// ---------- 布局常量(参数化) ----------

const BUTTON_W: i32 = 100;
const BUTTON_H: i32 = 30;
const BUTTON_GAP: i32 = 10;

const CHART_H: i32 = 200;
const CHART_GAP: i32 = 30;

const SLIDER_Y_OFFSET: i32 = 50;
const SLIDER_H: i32 = 20;

// ---------- 布局函数 ----------

#[derive(Debug, Clone, Copy)]
struct Rect { x: i32, y: i32, w: i32, h: i32 }

impl Rect {
    fn new(x: i32, y: i32, w: i32, h: i32) -> Self { Self { x, y, w, h } }
    fn hit_test(&self, mx: i32, my: i32) -> bool {
        mx >= self.x && mx < self.x + self.w && my >= self.y && my < self.y + self.h
    }
}

fn layout_horizontal(x0: i32, y0: i32, gap: i32, items: &[(i32, i32)]) -> Vec<Rect> {
    let mut x = x0;
    items.iter().map(|&(w, h)| {
        let r = Rect::new(x, y0, w, h);
        x += w + gap;
        r
    }).collect()
}

// ---------- UI 控件 ----------

#[derive(Clone, Copy, Debug, PartialEq)]
enum ViewMode { BarChart, TopClocks, Memory }

#[derive(Clone, Copy, Debug)]
enum UiEvent {
    SwitchView(ViewMode),
    Reset,
    Save,
}

struct Button {
    rect: Rect,         // 替代原来的 4 个独立字段
    label: &'static str,
    event: UiEvent,
    is_pressed: bool,
    was_pressed_inside: bool,
}

impl Button {
    fn new(rect: Rect, label: &'static str, event: UiEvent) -> Self {
        Self { rect, label, event, is_pressed: false, was_pressed_inside: false }
    }
    fn handle_mouse_down(&mut self, mx: i32, my: i32) -> bool {
        if self.rect.hit_test(mx, my) {
            self.is_pressed = true;
            self.was_pressed_inside = true;
            true
        } else {
            self.is_pressed = false;
            self.was_pressed_inside = false;
            false
        }
    }
    fn handle_mouse_up(&mut self, mx: i32, my: i32) -> Option<UiEvent> {
        let triggered = self.is_pressed && self.was_pressed_inside && self.rect.hit_test(mx, my);
        self.is_pressed = false;
        self.was_pressed_inside = false;
        if triggered { Some(self.event) } else { None }
    }
    fn draw(&self, buffer: &mut [u32], buf_w: usize, buf_h: usize) {
        let color = if self.is_pressed { 0xFF606060 } else { 0xFF808080 };
        draw_rect(buffer, buf_w, buf_h, self.rect, color);
    }
}

fn draw_rect(buffer: &mut [u32], buf_w: usize, buf_h: usize, r: Rect, color: u32) {
    for py in r.y.max(0)..(r.y + r.h).min(buf_h as i32) {
        for px in r.x.max(0)..(r.x + r.w).min(buf_w as i32) {
            buffer[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Profiler Layout Refactor", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();
    let mut current_view = ViewMode::BarChart;
    let mut frame_history: [f32; 64] = [0.0; 64];
    let mut frame_head = 0usize;

    // ---------- 用布局系统创建按钮 ----------
    // 所有按钮的 spec 一次性声明,布局函数算坐标
    let button_labels_events: &[(&str, UiEvent)] = &[
        ("Bar",    UiEvent::SwitchView(ViewMode::BarChart)),
        ("Clocks", UiEvent::SwitchView(ViewMode::TopClocks)),
        ("Mem",    UiEvent::SwitchView(ViewMode::Memory)),
        ("Reset",  UiEvent::Reset),
        ("Save",   UiEvent::Save),
    ];

    // 一次性算出所有按钮的 Rect
    let button_specs: Vec<(i32, i32)> = button_labels_events.iter()
        .map(|_| (BUTTON_W, BUTTON_H))
        .collect();
    let button_rects = layout_horizontal(MARGIN, MARGIN, BUTTON_GAP, &button_specs);

    let mut buttons: Vec<Button> = button_rects.iter()
        .zip(button_labels_events.iter())
        .map(|(rect, &(label, event))| {
            Button::new(*rect, label, event)
        })
        .collect();

    // 柱状图区域:占满中间
    let chart_rect = Rect::new(MARGIN, MARGIN + BUTTON_H + CHART_GAP,
                               WIDTH as i32 - 2 * MARGIN, CHART_H);

    // 滑块区域:底部
    let slider_rect = Rect::new(MARGIN, HEIGHT as i32 - MARGIN - SLIDER_H,
                                WIDTH as i32 - 2 * MARGIN, SLIDER_H);

    let mut was_mouse_down = false;

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt_ms = now.duration_since(last_time).as_secs_f32() * 1000.0;
        last_time = now;
        frame_history[frame_head] = dt_ms;
        frame_head = (frame_head + 1) % 64;

        let (mx_f, my_f) = window.get_mouse_pos(MouseMode::Discard).unwrap_or((-1.0, -1.0));
        let (mx, my) = (mx_f as i32, my_f as i32);
        let is_mouse_down = window.get_mouse_down(MouseButton::Left);

        let mouse_down_event = is_mouse_down && !was_mouse_down;
        let mouse_up_event = !is_mouse_down && was_mouse_down;
        was_mouse_down = is_mouse_down;

        if mouse_down_event {
            for b in buttons.iter_mut() { b.handle_mouse_down(mx, my); }
        }
        if mouse_up_event {
            for b in buttons.iter_mut() {
                if let Some(event) = b.handle_mouse_up(mx, my) {
                    println!("Event: {:?}", event);
                    match event {
                        UiEvent::SwitchView(v) => current_view = v,
                        UiEvent::Reset => {
                            frame_history = [0.0; 64];
                            frame_head = 0;
                        }
                        UiEvent::Save => {
                            std::fs::write("profile.json", "{}").unwrap();
                        }
                    }
                }
            }
        }

        for px in buffer.iter_mut() { *px = 0xFF101010; }

        for b in &buttons {
            b.draw(&mut buffer, WIDTH, HEIGHT);
        }

        match current_view {
            ViewMode::BarChart => {
                draw_rect(&mut buffer, WIDTH, HEIGHT, chart_rect, 0xFF202020);
                let scale = 50.0;
                let start = if frame_head == 0 { 0 } else { frame_head };
                for (i, v) in frame_history.iter().enumerate() {
                    let bar_w = chart_rect.w / 64;
                    let bx = chart_rect.x + (i as i32 * bar_w);
                    let top_y = chart_rect.y + ((1.0 - (*v / scale).max(0.0).min(1.0)) * chart_rect.h as f32) as i32;
                    let r = Rect::new(bx, top_y, bar_w, chart_rect.y + chart_rect.h - top_y);
                    draw_rect(&mut buffer, WIDTH, HEIGHT, r, 0xFF4040FF);
                }
            }
            ViewMode::TopClocks => {
                draw_rect(&mut buffer, WIDTH, HEIGHT, chart_rect, 0xFF202020);
            }
            ViewMode::Memory => {
                draw_rect(&mut buffer, WIDTH, HEIGHT, chart_rect, 0xFF202020);
            }
        }

        // 画滑块底色
        draw_rect(&mut buffer, WIDTH, HEIGHT, slider_rect, 0xFF404040);

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `Rect` 是 `Copy`,所以 `*rect` 复制而不是引用——按钮内部的 rect 改不影响外部
- `zip` 把两个迭代器配对:`button_rects.iter().zip(button_labels_events.iter())` 产生 `(&Rect, &(&str, UiEvent))` 序列
- `map(|(rect, &(label, event))| ...)` 模式匹配解构 tuple 引用
- 常量(MARGIN / BUTTON_W 等)是 `const`,编译期内联,无运行时开销
- `Vec::collect()` 把迭代器收集成 Vec

**Troubleshooting**:

- 按钮位置变了 — 检查 MARGIN / BUTTON_W 的值是不是和重构前一致
- 某个按钮缺失 — 检查 `zip` 长度匹配(button_rects 和 button_labels_events 长度必须相等)
- 滑块点击不响应 — slider_rect 改了之后事件检测的坐标也得改
