# Day 283 · 让"站立"成为更严格的概念

> "站在某物上"——听起来简单,但游戏开发里它包含丰富的语义:站在地面上、站在台阶上、站在桥下、站在移动平台上、站在 NPC 头上。今天 Casey 把"站立"从模糊的"位置近似"升级为严格的 entity 关系。

## 0 · 为什么要有这一天

你的游戏现在有"角色站在 tile 上"的概念(Day 270),但是这个概念是**隐式**的:

```rust
let player_tile = world_to_tile(player.pos);
let standing_on = map.is_traversable(player_tile);  // 这个 tile 是"可站立"的吗
```

这有几个问题:

**问题 1:不知道站在哪个 entity 上**。如果有多个 entity 在同一 tile(桥 + 玩家 + 怪物),"玩家站在什么上"不明确。

**问题 2:站在移动物体上不跟随**。一个浮动平台,玩家站在上面时,平台移动,玩家应该跟着移动。隐式 tile 概念做不到。

**问题 3:Z 维度的"站立"模糊**。玩家 z=0 时站在地面,z=20 时站在桥上——怎么区分?

**问题 4:碰撞响应混乱**。玩家"落在"物体上时,应该停在物体顶部(z=物体高度)。隐式概念难表达。

今天 Casey 引入显式的 **StandingOn 关系**:

```rust
struct Player {
    pos: Vec2,
    z: f32,
    standing_on: Option<EntityId>,  // 显式关系
}
```

每个 entity 知道自己"站在谁身上"。这个关系可以查询、修改、跟随。

心理锚点:做完这个,你的游戏可以支持"站在移动平台上"、"层层叠放(NPC 站在玩家头上)"等复杂场景。

## 1 · Casey 今天做了什么

Casey 重构"站立"概念:

1. 每个 entity 加 `standing_on: Option<EntityId>` 字段
2. 更新时,如果 standing_on 是 Some(support),从 support 读"顶部高度",设为自己的 z
3. support 移动时,所有站在它上的 entity 跟随移动
4. 落地检测:z_velocity <= 0 且与某个 entity 顶部碰撞 → 站在它上,清 z_velocity
5. 离开站立:跳起 / 走出 support 范围时,standing_on = None

Casey 演示了"站在移动平台上":平台水平移动,玩家站着不动,玩家跟着平台移动。这是 2.5D 平台游戏(如 Mario)的核心机制。

## 2 · 心智模型

### 类比:叠罗汉

几个人叠罗汉:底层的人是"地基",上层的人"站在"他身上。

- 底层移动,上层跟着移动(否则会摔下)
- 上层跳起,暂时脱离站立关系
- 上层落到下层,重新建立站立关系

游戏里的 standing_on 就是这种关系:支持物(entity A)→ 站立物(entity B),B 跟随 A 移动,B 跳起后可以站到别的 entity 上。

### 严谨原理:StandingOn 关系

#### 数据结构

```rust
struct Entity {
    pos: Vec2,
    z: f32,
    z_velocity: f32,
    standing_on: Option<EntityId>,
    top_z: f32,   // 自己的"顶部高度"(别人可以站在这个高度)
    footprint: Rect,  // 自己占的地面范围
}
```

`top_z` 是关键:这是"自己的顶面",其他 entity 站在自己上时 z = top_z。例如:

- 平台 entity:top_z = 20(平台高度 20)
- 玩家 entity:top_z = 16(玩家身高 16)
- 站在平台上的玩家:z = 20(平台的 top_z)
- 站在玩家上的小精灵:z = 20 + 16 = 36

#### 更新逻辑

```rust
fn update_entities(entities: &mut Vec<Entity>, dt: f32) {
    // 阶段 1:更新非站立物(地面、平台等)
    for e in entities.iter_mut() {
        if e.standing_on.is_none() {
            update_independent(e, dt);
        }
    }

    // 阶段 2:更新站立物,跟随支持物
    for e in entities.iter_mut() {
        if let Some(support_id) = e.standing_on {
            // 从 support 读 pos 和 top_z
            let (support_pos, support_top) = get_support_data(entities, support_id);
            // 跟随移动(support 这一帧的位移)
            let support_delta = compute_delta(entities, support_id);
            e.pos += support_delta;
            e.z = support_top;  // 自己的 z = support 的 top_z
        }
    }

    // 阶段 3:Z 物理(重力 + 落地检测)
    for e in entities.iter_mut() {
        if e.standing_on.is_none() {
            // 自由落体
            e.z += e.z_velocity * dt;
            e.z_velocity -= GRAVITY * dt;

            // 落地检测:有没有 entity 的顶部碰到?
            for other in entities.iter() {
                if other.id == e.id { continue; }
                if is_over_footprint(e, other) && e.z <= other.top_z && e.z_velocity < 0.0 {
                    // 落到 other 上
                    e.z = other.top_z;
                    e.z_velocity = 0.0;
                    e.standing_on = Some(other.id);
                    break;
                }
            }

            // 落到地面
            if e.z < 0.0 {
                e.z = 0.0;
                e.z_velocity = 0.0;
                e.standing_on = Some(GROUND_ID);  // 地面是特殊 entity
            }
        }
    }
}
```

三阶段:独立更新 → 跟随 → Z 物理。

#### 跳跃脱离

```rust
fn jump(e: &mut Entity) {
    if e.standing_on.is_some() {
        e.standing_on = None;  // 脱离站立
        e.z_velocity = JUMP_VELOCITY;
    }
}
```

跳跃时清 standing_on,后续 Z 物理接管。

#### 走出支持物范围

```rust
fn check_walked_off(e: &mut Entity, entities: &[Entity]) {
    if let Some(support_id) = e.standing_on {
        if support_id == GROUND_ID { return; }  // 地面无限大
        let support = find_entity(entities, support_id);
        if !is_over_footprint(e, support) {
            // 走出范围,脱离站立
            e.standing_on = None;
            e.z_velocity = 0.0;  // 开始自由落体
        }
    }
}
```

#### 跟随移动的支持物

```rust
struct MovingPlatform {
    pos: Vec2,
    velocity: Vec2,
    // ...
}

// 平台自己移动
platform.pos += platform.velocity * dt;

// 站在平台上的 entity 自动跟随(阶段 2 处理)
```

这是"站在移动平台上"的核心——玩家不主动移动,但因为 standing_on 关系,被平台拖着走。

### Footprint(足迹)的概念

每个 entity 占地面的一个矩形(footprint),即使它本身可能是圆形 / 不规则。两个 entity 的"X/Y 是否重叠"看 footprint:

```rust
fn is_over_footprint(stander: &Entity, support: &Entity) -> bool {
    // stander 的中心是否在 support 的 footprint 内
    let dx = stander.pos.x - support.pos.x;
    let dy = stander.pos.y - support.pos.y;
    dx.abs() < support.footprint.w / 2.0 && dy.abs() < support.footprint.h / 2.0
}
```

footprint 让站立判断简单(矩形相交),不依赖 entity 的视觉形状。

### StandingOn 图

如果有多个 entity 互相站立,形成一个有向图:

```
Ground <── Player <── Small Sprite
   ↑
   └── Moving Platform
```

每个箭头是 standing_on 关系。这个图必须是**无环的**(否则有循环引用,死锁)。Rust 的 ownership 系统天然防止简单循环,但 entity 间引用要用 id 而不是指针。

#### 拓扑排序

更新时按拓扑顺序:先更新叶节点(被站立的),再更新上层(站立的)。这样上层读到的"support 位置"是最新的。

### 3.4 · 🦀 Rust 生态视角

Rust 表达 standing_on 关系:

#### 用 EntityId 引用

```rust
struct Entity {
    standing_on: Option<EntityId>,
}
```

不用 `*const Entity` 或 `&Entity`——生命周期 / 所有权问题。EntityId 是generational index(Day 277),安全。

#### 双向引用(谨慎)

如果想从 support 反查 riders:

```rust
struct Entity {
    standing_on: Option<EntityId>,
    riders: Vec<EntityId>,  // 站在自己上的
}
```

但维护双向引用容易出 bug(rider 加了 support 的 riders 列表忘了加,反之亦然)。建议:用单向 + 中央查询。

#### 中央 World 查询

```rust
impl World {
    fn riders_of(&self, support_id: EntityId) -> Vec<EntityId> {
        self.entities.iter()
            .filter(|e| e.standing_on == Some(support_id))
            .map(|e| e.id)
            .collect()
    }
}
```

按需查询,避免维护双向。

#### Avoid 循环引用

A.standing_on = B 且 B.standing_on = A 是非法的(死循环)。Rust 不会自动检测,但游戏逻辑要保证:

```rust
fn set_standing_on(e: &mut Entity, target: EntityId, world: &World) {
    // 检查不形成循环
    let mut current = target;
    while let Some(s) = world.get(current).and_then(|e| e.standing_on) {
        if s == e.id {
            // 形成循环,拒绝
            return;
        }
        current = s;
    }
    e.standing_on = Some(target);
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 standing_on 用 `Option<EntityId>` 而不是 `Option<&Entity>`?给出至少 3 个理由。

**参考解答**:
1. **生命周期**:`&Entity` 要绑定 source entity 的生命周期,但 entity 在 Vec 里可能被 reorder / remove,引用会悬空。EntityId 是 generational index,独立于内存位置
2. **可变性**:更新 entity 时要 `&mut Entity`,但同时持有另一个 entity 的 `&Entity` 会违反 borrow 规则。EntityId 解耦了引用和数据
3. **序列化**:`&Entity` 不能直接序列化(指针无意义)。EntityId 是数据,可以保存 / 加载
4. **跨线程**:多线程时 EntityId 可以在线程间传递,引用不行(lifetime 限制)
5. **运行时验证**:EntityId 可以 is_valid 检查(generation 是否过期),引用做不到
6. **一致性**:Vec 的 entity 可能 realloc,所有 & 指针失效。EntityId 通过 index 访问,自动适应

### Lv2 · 动手实践

**题**:实现简单的 standing_on 关系 + 跟随。

测试场景:

- 一个 platform entity(在固定位置)
- 一个 player entity(z=20 站在 platform 上)
- platform.pos.x += 10
- 验证 player.pos.x 也 += 10

完成标准:跟随移动正确。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct EntityId(u32);

#[derive(Clone, Debug)]
struct Entity {
    id: EntityId,
    pos_x: f32,
    pos_y: f32,
    z: f32,
    top_z: f32,
    footprint_w: f32,
    footprint_h: f32,
    standing_on: Option<EntityId>,
}

impl Entity {
    fn new_platform(id: EntityId, x: f32, y: f32) -> Self {
        Self {
            id, pos_x: x, pos_y: y, z: 0.0, top_z: 20.0,
            footprint_w: 80.0, footprint_h: 30.0,
            standing_on: None,
        }
    }

    fn new_player(id: EntityId, x: f32, y: f32, standing_on: EntityId) -> Self {
        Self {
            id, pos_x: x, pos_y: y, z: 20.0, top_z: 36.0,  // 站在 platform 上
            footprint_w: 16.0, footprint_h: 16.0,
            standing_on: Some(standing_on),
        }
    }
}

struct World {
    entities: Vec<Entity>,
}

impl World {
    fn new() -> Self { Self { entities: Vec::new() } }

    fn add(&mut self, e: Entity) -> EntityId {
        let id = e.id;
        self.entities.push(e);
        id
    }

    fn get_mut(&mut self, id: EntityId) -> Option<&mut Entity> {
        self.entities.iter_mut().find(|e| e.id == id)
    }

    fn get(&self, id: EntityId) -> Option<&Entity> {
        self.entities.iter().find(|e| e.id == id)
    }

    /// 把 support 的位移同步到所有 rider
    fn sync_riders(&mut self, support_id: EntityId, delta_x: f32, delta_y: f32) {
        // 先找出所有 rider
        let rider_ids: Vec<EntityId> = self.entities.iter()
            .filter(|e| e.standing_on == Some(support_id))
            .map(|e| e.id)
            .collect();

        // 再更新(避免 borrow 冲突)
        for rider_id in rider_ids {
            if let Some(rider) = self.get_mut(rider_id) {
                rider.pos_x += delta_x;
                rider.pos_y += delta_y;
                // rider 的 z 应该等于 support 的 top_z
                if let Some(support) = self.get(support_id) {
                    rider.z = support.top_z;
                }
            }
        }
    }
}

fn main() {
    let mut world = World::new();

    let platform_id = world.add(Entity::new_platform(EntityId(1), 100.0, 200.0));
    let player_id = world.add(Entity::new_player(EntityId(2), 110.0, 200.0, platform_id));

    println!("Before move:");
    println!("  Platform pos: ({},{})", world.get(platform_id).unwrap().pos_x, world.get(platform_id).unwrap().pos_y);
    println!("  Player pos:   ({},{})", world.get(player_id).unwrap().pos_x, world.get(player_id).unwrap().pos_y);

    // 移动 platform
    let delta_x = 10.0_f32;
    let delta_y = 0.0_f32;
    if let Some(platform) = world.get_mut(platform_id) {
        platform.pos_x += delta_x;
        platform.pos_y += delta_y;
    }
    // 同步 riders
    world.sync_riders(platform_id, delta_x, delta_y);

    println!("\nAfter platform moved by ({},{}):", delta_x, delta_y);
    println!("  Platform pos: ({},{})", world.get(platform_id).unwrap().pos_x, world.get(platform_id).unwrap().pos_y);
    println!("  Player pos:   ({},{})", world.get(player_id).unwrap().pos_x, world.get(player_id).unwrap().pos_y);

    // 验证 player 跟随
    assert_eq!(world.get(player_id).unwrap().pos_x, 120.0);  // 110 + 10
    assert_eq!(world.get(player_id).unwrap().pos_y, 200.0);
    assert_eq!(world.get(player_id).unwrap().z, 20.0);  // 等于 platform 的 top_z

    println!("\nPlayer followed platform correctly!");
}
```

**每行解释**:
- `EntityId(u32)` 是简单 id(教学用,生产用 generational index)
- `sync_riders` 用两阶段(先查 id,后更新)避免 borrow 冲突
- rider 的 z 永远等于 support 的 top_z(自动跟随)
- delta_x / delta_y 是 support 这一帧的位移,rider 复制这个位移

## 8 · Rust / Arch 落地代码

### 完整可跑:standing_on + 移动平台 + 跳跃

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, KeyRepeat, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const GRAVITY: f32 = 800.0;
const JUMP_VELOCITY: f32 = 350.0;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct EntityId(u32);

#[derive(Clone, Debug)]
struct Entity {
    id: EntityId,
    pos_x: f32,
    pos_y: f32,
    z: f32,
    z_velocity: f32,
    top_z: f32,
    width: f32,
    height: f32,
    color: u32,
    standing_on: Option<EntityId>,

}

impl Entity {
    fn player(id: EntityId, x: f32, y: f32) -> Self {
        Self {
            id, pos_x: x, pos_y: y, z: 0.0, z_velocity: 0.0,
            top_z: 32.0, width: 24.0, height: 24.0,
            color: 0xFFFF6040, standing_on: None,
            vx: 0.0, is_platform: false,
        }
    }

    fn platform(id: EntityId, x: f32, y: f32, vx: f32) -> Self {
        Self {
            id, pos_x: x, pos_y: y, z: 0.0, z_velocity: 0.0,
            top_z: 20.0, width: 100.0, height: 20.0,
            color: 0xFF806040, standing_on: None,
            vx, is_platform: true,
        }
    }
}

struct World {
    entities: Vec<Entity>,
}

impl World {
    fn new() -> Self { Self { entities: Vec::new() } }

    fn add(&mut self, e: Entity) -> EntityId {
        let id = e.id;
        self.entities.push(e);
        id
    }

    fn get_mut(&mut self, id: EntityId) -> Option<&mut Entity> {
        self.entities.iter_mut().find(|e| e.id == id)
    }

    fn get(&self, id: EntityId) -> Option<&Entity> {
        self.entities.iter().find(|e| e.id == id)
    }

    fn footprint_overlap(a: &Entity, b: &Entity) -> bool {
        let dx = (a.pos_x - b.pos_x).abs();
        let dy = (a.pos_y - b.pos_y).abs();
        dx < (a.width + b.width) / 2.0 && dy < (a.height + b.height) / 2.0
    }

    fn update(&mut self, dt: f32) {
        // 阶段 1:更新所有 entity 的水平移动
        let mut deltas: Vec<(EntityId, f32, f32)> = Vec::new();
        for e in &mut self.entities {
            if e.is_platform {
                let dx = e.vx * dt;
                e.pos_x += dx;
                deltas.push((e.id, dx, 0.0));
            }
        }
        // 阶段 2:rider 跟随 support
        for (support_id, dx, dy) in &deltas {
            let rider_ids: Vec<EntityId> = self.entities.iter()
                .filter(|e| e.standing_on == Some(*support_id))
                .map(|e| e.id).collect();
            for rider_id in rider_ids {
                if let Some(rider) = self.get_mut(rider_id) {
                    rider.pos_x += dx;
                    rider.pos_y += dy;
                }
            }
        }

        // 阶段 3:Z 物理(只有非站立的 entity)
        for i in 0..self.entities.len() {
            if self.entities[i].standing_on.is_some() { continue; }
            let id = self.entities[i].id;
            // 跳跃
            self.entities[i].z += self.entities[i].z_velocity * dt;
            self.entities[i].z_velocity -= GRAVITY * dt;

            // 落地检测
            if self.entities[i].z_velocity < 0.0 {
                // 检查所有可能的支持物
                for other in &self.entities {
                    if other.id == id { continue; }
                    if !other.is_platform { continue; }
                    let falling_z = self.entities[i].z;
                    if Self::footprint_overlap(&self.entities[i], other)
                        && falling_z <= other.top_z
                        && falling_z >= other.top_z - 10.0  // 容差
                    {
                        self.entities[i].z = other.top_z;
                        self.entities[i].z_velocity = 0.0;
                        self.entities[i].standing_on = Some(other.id);
                        break;
                    }
                }
                // 落到地面
                if self.entities[i].z < 0.0 {
                    self.entities[i].z = 0.0;
                    self.entities[i].z_velocity = 0.0;
                    self.entities[i].standing_on = None;  // 地面用 None 表示
                }
            }
        }

        // 阶段 4:检查 rider 是否走出 support 范围
        let mut to_detach: Vec<EntityId> = Vec::new();
        for e in &self.entities {
            if let Some(support_id) = e.standing_on {
                if let Some(support) = self.get(support_id) {
                    if !Self::footprint_overlap(e, support) {
                        to_detach.push(e.id);
                    }
                }
            }
        }
        for id in to_detach {
            if let Some(e) = self.get_mut(id) {
                e.standing_on = None;
                e.z_velocity = 0.0;  // 开始下落
            }
        }
    }
}

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, x: i32, y: i32, w: i32, h: i32, color: u32) {
    for py in y.max(0)..(y + h).min(buf_h as i32) {
        for px in x.max(0)..(x + w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Standing-on Demo", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();

    let mut world = World::new();
    let player_id = world.add(Entity::player(EntityId(1), 100.0, 400.0));
    let _ = world.add(Entity::platform(EntityId(2), 200.0, 400.0, 80.0));
    let _ = world.add(Entity::platform(EntityId(3), 500.0, 300.0, -60.0));

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32().min(0.05);
        last_time = now;

        // 玩家输入
        let speed = 200.0;
        if let Some(player) = world.get_mut(player_id) {
            if window.is_key_down(Key::A) { player.pos_x -= speed * dt; }
            if window.is_key_down(Key::D) { player.pos_x += speed * dt; }
            if window.is_key_down(Key::W) { player.pos_y -= speed * dt; }
            if window.is_key_down(Key::S) { player.pos_y += speed * dt; }

            if window.is_key_pressed(Key::Space, KeyRepeat::No) {
                if player.standing_on.is_some() || player.z == 0.0 {
                    player.standing_on = None;
                    player.z_velocity = JUMP_VELOCITY;
                }
            }
        }

        world.update(dt);

        // 渲染
        for px in buffer.iter_mut() { *px = 0xFF101010; }

        // 按 z 排序(z 小的先画,即下层先画)
        let mut sorted: Vec<&Entity> = world.entities.iter().collect();
        sorted.sort_by(|a, b| a.z.partial_cmp(&b.z).unwrap());

        for e in &sorted {
            // 阴影(地面位置)
            let shadow_y = e.pos_y;
            let shadow_color = 0xFF202020;
            draw_rect(&mut buffer, WIDTH, HEIGHT,
                      (e.pos_x - e.width / 2.0) as i32,
                      (shadow_y - 4) as i32,
                      e.width as i32, 8, shadow_color);

            // 实体(z 偏移)
            let sprite_y = e.pos_y - e.z;
            draw_rect(&mut buffer, WIDTH, HEIGHT,
                      (e.pos_x - e.width / 2.0) as i32,
                      (sprite_y - e.height / 2.0) as i32,
                      e.width as i32, e.height as i32, e.color);

            // 显示 standing_on 状态(玩家用特殊标记)
            if e.id == player_id && e.standing_on.is_some() {
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          (e.pos_x - 5.0) as i32,
                          (sprite_y - 20.0) as i32,
                          10, 10, 0xFFFFFF40);
            }
        }

        // HUD
        if let Some(player) = world.get(player_id) {
            let color = if player.standing_on.is_some() { 0xFF40FF40 } else { 0xFF404040 };
            draw_rect(&mut buffer, WIDTH, HEIGHT, 10, 10, 100, 20, color);
            println!("\rPlayer z={:.1}, standing_on={:?}    ", player.z, player.standing_on);
        }

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- 阶段 1-4 分离更新逻辑,避免借用冲突
- `footprint_overlap` 是矩形相交检测,用于站立判断
- `sort_by(|a, b| a.z.partial_cmp(&b.z))` 按 z 排序渲染,确保上层覆盖下层
- `standing_on = None` 表示站在地面(特殊语义)
- 平台用 vx 自动移动,玩家通过 standing_on 跟随

**Troubleshooting**:

- 玩家不跟随平台 — 检查 sync_riders 是否调用了
- 跳跃后立即落地 — 落地检测容差太大,改小
- 玩家"穿透"平台 — 落地检测顺序问题,先检查高 z_velocity 的 entity
