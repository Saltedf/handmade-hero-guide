# Day 281 · 房间之间动画相机

> 玩家从一个房间走到另一个房间时,相机不应该"瞬移"——它应该平滑过渡。今天 Casey 用 spring(Day 274 学的)让相机在房间之间优雅地滑动。这是 spring 动画在实际游戏里的第一个重要应用。

## 0 · 为什么要有这一天

你现在的相机大概是这样:紧贴玩家,玩家在哪相机就在哪。

```rust
let camera_pos = player.pos;
```

这种"刚性跟随"有个问题:玩家走过房间边界(进入新房间)时,相机**瞬间跳到新房间**——视觉上很硬,玩家会感觉"被拽过去"。

更好的体验:**相机平滑过渡**。玩家从房间 A 走到房间 B 时,相机用 0.5 秒从 A 中心滑到 B 中心,玩家有"穿越感"。

这种"相机过渡"在游戏里很常见:

- Zelda 的房间切换(玩家走门时镜头切换)
- Mario 的关卡过渡
- Hollow Knight 的大地图导航
- 任何 2D 平台游戏的相机滚动

实现:**相机目标位置用 spring 驱动**。玩家走门时,相机目标改成新房间的中心,spring 平滑过渡过去。

心理锚点:做完这个,你的游戏房间切换有"电影感",不再是硬切。

## 1 · Casey 今天做了什么

Casey 把相机从"刚性跟随玩家"改成"spring 跟随房间中心":

1. 相机目标改为"当前房间中心"(而不是玩家位置)
2. spring 驱动相机当前位置
3. 玩家跨房间边界时,相机目标设为新房间中心,spring 平滑过渡
4. 调参数:stiffness=80, damping=15(较慢,有"漫游感")

Casey 处理了几个细节:

- **过渡中玩家移动**:玩家可以在相机过渡时继续移动,相机最终会跟上
- **边界限制**:相机不能滑出地图边界(clamp 到地图矩形内)
- **过渡时长控制**:通过 spring 的 stiffness / damping 控制,大概 0.3-0.5 秒

最后 Casey 提到"相机方向感":房间之间过渡时,玩家移动方向应该和相机滑动方向一致——避免"玩家朝右走但相机朝左滑"的违和感。

## 2 · 心智模型

### 类比:电影中的运镜

电影导演不会让镜头"瞬移"——它要么"切"(hard cut,场景切换),要么"摇 / 推 / 拉"(smooth motion)。

游戏相机也一样:

- **场景内**:**刚性跟随**(镜头紧贴玩家),玩家移动镜头跟着
- **场景切换**:**平滑过渡**(spring 或缓动),镜头慢慢移动到新位置
- **戏剧时刻**:**特殊运镜**(zoom in / 角度变化)

今天做的是"场景切换的平滑过渡"。

### 严谨原理:Spring 相机

#### 数据结构

```rust
struct Camera {
    pos_x: Spring,
    pos_y: Spring,
    target_room: RoomId,
}

struct Room {
    id: RoomId,
    center: Vec2,
    bounds: Rect,
}
```

相机 pos 是 spring,目标是当前房间的 center。

#### 跨房间过渡

```rust
impl Camera {
    fn transition_to(&mut self, room: &Room) {
        self.pos_x.set_target(room.center.x);
        self.pos_y.set_target(room.center.y);
        self.target_room = room.id;
    }

    fn update(&mut self, dt: f32) {
        self.pos_x.update(dt);
        self.pos_y.update(dt);
    }

    fn current_pos(&self) -> Vec2 {
        Vec2::new(self.pos_x.value, self.pos_y.value)
    }
}
```

#### 玩家跨房间触发

```rust
fn update_player(&mut self, ...) {
    let old_room = self.world.find_room(self.player.tile);
    self.player.move_to(new_tile);
    let new_room = self.world.find_room(self.player.tile);

    if old_room != new_room {
        // 跨房间,触发相机过渡
        let room_data = self.world.get_room(new_room);
        self.camera.transition_to(room_data);
    }
}
```

#### Spring 参数选择

相机过渡的参数和角色动画不同:

- **角色动画**:stiffness=120, damping=12(快速 + 弹性)
- **相机过渡**:stiffness=5, damping=10(慢速 + 几乎无过冲)

为什么相机 spring 软?

- **相机不该有"弹性"**——它应该稳定地停在房间中心,不该来回弹
- **过渡慢一点更好**——给玩家时间适应新房间
- **过冲让人头晕**——相机超出房间边界再弹回,玩家眩晕

临界阻尼 `c = 2*sqrt(k)` = 2*sqrt(5) ≈ 4.47。damping=10 > 4.47 是过阻尼——平滑过渡,无过冲。

#### 边界 clamp

相机不能滑出地图:

```rust
fn update(&mut self, dt: f32, world_bounds: Rect) {
    self.pos_x.update(dt);
    self.pos_y.update(dt);

    // clamp 到地图边界
    let half_w = WIDTH as f32 / 2.0;
    let half_h = HEIGHT as f32 / 2.0;
    self.pos_x.value = self.pos_x.value
        .max(world_bounds.x + half_w)
        .min(world_bounds.x + world_bounds.w - half_w);
    self.pos_y.value = self.pos_y.value
        .max(world_bounds.y + half_h)
        .min(world_bounds.y + world_bounds.h - half_h);
}
```

clamp 在 spring update 之后,防止 spring 把相机推到边界外。

#### "切"vs "过渡"

有时硬切更好(比如玩家瞬间传送):

```rust
impl Camera {
    fn snap_to(&mut self, room: &Room) {
        self.pos_x.value = room.center.x;
        self.pos_x.velocity = 0.0;
        self.pos_x.target = room.center.x;
        self.pos_y.value = room.center.y;
        self.pos_y.velocity = 0.0;
        self.pos_y.target = room.center.y;
        self.target_room = room.id;
    }
}
```

`snap_to` 立即把相机移到目标,无过渡。用于 teleport、过场动画开始时。

```rust
struct Camera {

    zoom: f32,
    rotation: f32,

impl Camera {
    fn world_to_screen(&self, world: Vec2) -> Vec2 {
        let relative = world.sub(self.pos);
        let rotated = rotate(relative, -self.rotation);
        let scaled = rotated.scale(self.zoom);
        scaled.add(Vec2::new(WIDTH as f32 / 2.0, HEIGHT as f32 / 2.0))

```

### 3.4 · 🦀 Rust 生态视角

Rust 表达 spring 相机:

```rust
struct Camera {
    pos: Spring2D,  // 复用 Day 274 的 Spring,升级为 2D
}

struct Spring2D {
    x: Spring,
    y: Spring,
}

impl Spring2D {
    fn new(initial: Vec2, stiffness: f32, damping: f32) -> Self {
        Self {
            x: Spring::new(initial.x, stiffness, damping),
            y: Spring::new(initial.y, stiffness, damping),
        }
    }
    fn set_target(&mut self, target: Vec2) {
        self.x.set_target(target.x);
        self.y.set_target(target.y);
    }
    fn update(&mut self, dt: f32) {
        self.x.update(dt);
        self.y.update(dt);
    }
    fn value(&self) -> Vec2 {
        Vec2::new(self.x.value, self.y.value)
    }
}
```

把 Spring 升级为 Spring2D,代码更简洁。Rust 没有"继承",但可以用组合。

通过 spring 参数调节相机的"重量":

- **stiffness 中 / damping 中**:有弹性,相机"活"

不同游戏风格选不同参数。HH 的相机偏"懒",符合探索游戏的节奏。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么相机过渡用 spring,而不是直接 lerp(线性插值)?

**参考解答**:
1. **响应目标改变**:玩家可能进入房间 A 后立刻又回 B,spring 立即朝新目标,保留当前速度;lerp 要重新算 t∈[0,1]
2. **物理感**:spring 有"惯性",过渡感觉自然;lerp 是机械的线性
3. **可调弹性**:damping < c_critical 时相机会"过冲"一点点,这是电影感的来源;lerp 不会有
4. **dt 无关**:spring 用数值积分,任意 dt 稳定;lerp 需要预先决定时长 + 计算 t = elapsed / duration
5. **多相机融合**:多个 spring(主相机 + shake)可以叠加;lerp 的混合需要预计算
6. **可中断**:spring 任何时候改 target 都平滑;lerp 中断会跳变

### Lv2 · 动手实践

**题**:实现 `Camera` struct(用 spring)+ `transition_to` + `update`,以及一个测试场景。

测试:

- Camera 初始 pos = (0, 0)
- transition_to((100, 0))
- 模拟 2 秒,验证 pos 接近 (100, 0)
- 过渡中再 transition_to((100, 200)),验证立即改向

完成标准:相机平滑过渡,改向后无跳变。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug)]
struct Spring {
    value: f32,
    velocity: f32,
    target: f32,
    stiffness: f32,
    damping: f32,
}

impl Spring {
    fn new(initial: f32, stiffness: f32, damping: f32) -> Self {
        Self { value: initial, velocity: 0.0, target: initial, stiffness, damping }
    }
    fn set_target(&mut self, t: f32) { self.target = t; }
    fn update(&mut self, dt: f32) {
        let force = -self.stiffness * (self.value - self.target) - self.damping * self.velocity;
        self.velocity += force * dt;
        self.value += self.velocity * dt;
    }
}

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 { fn new(x: f32, y: f32) -> Self { Self { x, y } } }

struct Camera {
    pos_x: Spring,
    pos_y: Spring,
}

impl Camera {
    fn new(initial: Vec2) -> Self {
        // 相机用慢 spring:stiffness 低,damping 接近临界(无过冲)
        // c_crit = 2*sqrt(k) = 2*sqrt(5) ≈ 4.47
        // damping = 10 > 4.47,过阻尼,无过冲
        Self {
            pos_x: Spring::new(initial.x, 5.0, 10.0),
            pos_y: Spring::new(initial.y, 5.0, 10.0),
        }
    }

    fn transition_to(&mut self, target: Vec2) {
        self.pos_x.set_target(target.x);
        self.pos_y.set_target(target.y);
    }

    fn snap_to(&mut self, target: Vec2) {
        self.pos_x.value = target.x;
        self.pos_x.velocity = 0.0;
        self.pos_x.target = target.x;
        self.pos_y.value = target.y;
        self.pos_y.velocity = 0.0;
        self.pos_y.target = target.y;
    }

    fn update(&mut self, dt: f32) {
        self.pos_x.update(dt);
        self.pos_y.update(dt);
    }

    fn pos(&self) -> Vec2 {
        Vec2::new(self.pos_x.value, self.pos_y.value)
    }
}

fn main() {
    let mut camera = Camera::new(Vec2::new(0.0, 0.0));
    println!("Initial camera pos: ({},{})", camera.pos().x, camera.pos().y);

    // transition to (100, 0)
    camera.transition_to(Vec2::new(100.0, 0.0));
    println!("Transition to (100, 0)...");

    // 模拟 2 秒,每 0.1 秒打印
    let dt = 0.01;
    for step in 0..200 {
        camera.update(dt);
        if step % 20 == 0 {
            let t = step as f32 * dt;
            let p = camera.pos();
            println!("  t={:.2}s pos=({:.2},{:.2})", t, p.x, p.y);
        }
    }
    println!("Final pos: ({:.2},{:.2})", camera.pos().x, camera.pos().y);
    // 应该接近 (100, 0)

    // 过渡中改向
    camera.transition_to(Vec2::new(100.0, 200.0));
    println!("\nMid-transition, change to (100, 200)...");

    for step in 0..200 {
        camera.update(dt);
        if step % 20 == 0 {
            let t = step as f32 * dt;
            let p = camera.pos();
            println!("  t={:.2}s pos=({:.2},{:.2})", t, p.x, p.y);
        }
    }
    println!("Final pos: ({:.2},{:.2})", camera.pos().x, camera.pos().y);
    // 应该接近 (100, 200),无跳变
}
```

**每行解释**:
- 相机用慢 spring(stiffness=5),过渡时间约 0.5 秒
- damping=10 > 临界阻尼 4.47,无过冲
- transition_to 改 target,spring 立即朝新目标拉
- snap_to 立即跳(用于 teleport 等)
- pos() 返回当前 spring 的 value

## 8 · Rust / Arch 落地代码

### 完整可跑:多房间 + 相机过渡

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, KeyRepeat, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const ROOM_W: f32 = 800.0;  // 每个房间 800x600 像素
const ROOM_H: f32 = 600.0;

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
    fn add(self, o: Self) -> Self { Self::new(self.x + o.x, self.y + o.y) }
}

#[derive(Clone, Copy, Debug)]
struct Spring {
    value: f32,
    velocity: f32,
    target: f32,
    stiffness: f32,
    damping: f32,
}

impl Spring {
    fn new(initial: f32, stiffness: f32, damping: f32) -> Self {
        Self { value: initial, velocity: 0.0, target: initial, stiffness, damping }
    }
    fn set_target(&mut self, t: f32) { self.target = t; }
    fn update(&mut self, dt: f32) {
        let force = -self.stiffness * (self.value - self.target) - self.damping * self.velocity;
        self.velocity += force * dt;
        self.value += self.velocity * dt;
    }
}

struct Camera {
    pos_x: Spring,
    pos_y: Spring,
}

impl Camera {
    fn new(initial: Vec2) -> Self {
        Self {
            pos_x: Spring::new(initial.x, 5.0, 10.0),
            pos_y: Spring::new(initial.y, 5.0, 10.0),
        }
    }
    fn transition_to(&mut self, target: Vec2) {
        self.pos_x.set_target(target.x);
        self.pos_y.set_target(target.y);
    }
    fn update(&mut self, dt: f32) {
        self.pos_x.update(dt);
        self.pos_y.update(dt);
    }
    fn pos(&self) -> Vec2 {
        Vec2::new(self.pos_x.value, self.pos_y.value)
    }
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct RoomId(i32, i32);  // 房间网格坐标

impl RoomId {
    fn center(&self) -> Vec2 {
        Vec2::new(
            self.0 as f32 * ROOM_W + ROOM_W / 2.0,
            self.1 as f32 * ROOM_H + ROOM_H / 2.0,
        )
    }
    fn bounds(&self) -> (f32, f32, f32, f32) {
        (self.0 as f32 * ROOM_W, self.1 as f32 * ROOM_H, ROOM_W, ROOM_H)
    }
}

struct Player {
    pos: Vec2,
    speed: f32,
}

impl Player {
    fn new(pos: Vec2) -> Self { Self { pos, speed: 200.0 } }

    fn update(&mut self, dt: f32, window: &minifb::Window) {
        let mut dx = 0.0;
        let mut dy = 0.0;
        if window.is_key_down(Key::A) { dx -= 1.0; }
        if window.is_key_down(Key::D) { dx += 1.0; }
        if window.is_key_down(Key::W) { dy -= 1.0; }
        if window.is_key_down(Key::S) { dy += 1.0; }

        // 归一化(斜方向不会更快)
        let len = (dx * dx + dy * dy).sqrt();
        if len > 0.0 {
            dx /= len;
            dy /= len;
            self.pos.x += dx * self.speed * dt;
            self.pos.y += dy * self.speed * dt;
        }
    }

    fn current_room(&self) -> RoomId {
        RoomId(
            (self.pos.x / ROOM_W).floor() as i32,
            (self.pos.y / ROOM_H).floor() as i32,
        )
    }
}

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, x: i32, y: i32, w: i32, h: i32, color: u32) {
    for py in y.max(0)..(y + h).min(buf_h as i32) {
        for px in x.max(0)..(x + w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Room Camera Transition", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();

    let start_room = RoomId(0, 0);
    let mut player = Player::new(start_room.center());
    let mut camera = Camera::new(start_room.center());
    let mut current_room = start_room;

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32().min(0.05);
        last_time = now;

        // 更新玩家
        player.update(dt, &window);

        // 检查房间变化
        let new_room = player.current_room();
        if new_room != current_room {
            println!("Transition to room {:?}", new_room);
            camera.transition_to(new_room.center());
            current_room = new_room;
        }

        // 更新相机
        camera.update(dt);

        // 渲染
        for px in buffer.iter_mut() { *px = 0xFF101010; }

        let cam_pos = camera.pos();
        let offset = Vec2::new(cam_pos.x - WIDTH as f32 / 2.0, cam_pos.y - HEIGHT as f32 / 2.0);

        // 画当前房间(及附近几个,如果过渡中)
        for ry in -1..=1 {
            for rx in -1..=1 {
                let room = RoomId(current_room.0 + rx, current_room.1 + ry);
                let (bx, by, bw, bh) = room.bounds();
                let sx = bx - offset.x;
                let sy = by - offset.y;

                // 房间地板
                let base_color = if room == current_room { 0xFF202020 } else { 0xFF181818 };
                draw_rect(&mut buffer, WIDTH, HEIGHT, sx as i32, sy as i32, bw as i32, bh as i32, base_color);

                // 房间边框
                draw_rect(&mut buffer, WIDTH, HEIGHT, sx as i32, sy as i32, bw as i32, 4, 0xFF404040);
                draw_rect(&mut buffer, WIDTH, HEIGHT, sx as i32, (sy + bh - 4.0) as i32, bw as i32, 4, 0xFF404040);
                draw_rect(&mut buffer, WIDTH, HEIGHT, sx as i32, sy as i32, 4, bh as i32, 0xFF404040);
                draw_rect(&mut buffer, WIDTH, HEIGHT, (sx + bw - 4.0) as i32, sy as i32, 4, bh as i32, 0xFF404040);

                // 房间中心标记
                let center_x = sx + bw / 2.0;
                let center_y = sy + bh / 2.0;
                let center_color = if room == current_room { 0xFFFFFF40 } else { 0xFF808040 };
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          (center_x - 5.0) as i32, (center_y - 5.0) as i32,
                          10, 10, center_color);
            }
        }

        // 画玩家(相对屏幕中心)
        let player_screen = player.pos.sub(offset);
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  (player_screen.x - 12.0) as i32, (player_screen.y - 12.0) as i32,
                  24, 24, 0xFFFF6040);

        // 房间指示器
        let _ = window.is_key_pressed(Key::Space, KeyRepeat::No);

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- Camera 内部是两个 Spring(pos_x, pos_y),组合表达 2D 位置
- RoomId 是网格坐标(i32, i32),不是世界坐标
- `player.current_room()` 实时算玩家所在房间
- `transition_to` 改 spring 的 target,update 平滑过渡
- 画 3x3 邻居房间,过渡中能看到下一个房间渐入

### 深度推导:本日相关数学与算法

要真正掌握今天的内容,我们必须把背后的数学推导展开。这一节是"为什么这么做"的论证。

**算法复杂度的精确分析**。今天的代码涉及到对实体集合排序,基准复杂度:

- 最优比较排序下界:O(N log N)(决策树理论)
- Rust `sort_by`:TimSort,平均 O(N log N),最好 O(N)(已部分有序时)
- 拓扑排序:O(V + E),V 是节点数,E 是边数
- Radix sort:O(N × k),k 是 sort key 位数——非比较排序,可突破 O(N log N)

对一个 1000 sprite 的场景,TimSort 大约 10000 次比较,每次比较 5-10 个 cycle(分支少),总 50000-100000 cycle = 20-40 μs。在 60 FPS(16666 μs 预算)占 0.2%——可忽略。100K sprite 时升到 2 ms,开始有压力。Minecraft 这种规模的游戏必须用 radix sort 或 GPU sort。

**内存访问模式**。sort 是**非线性内存访问**的典型——每次比较都可能跳到 Vec 不同位置。CPU prefetcher 抓不到模式,cache miss 频繁。优化:

1. **Sort by index**:先 sort indices(u32 数组,4 字节/项,cache 友好),再 reorder 数据。indices 1000 个 = 4 KB,L1 cache 装得下。
2. **Batch reorder**:indices 排好后,顺序遍历 indices,顺序访问原数据(虽然是间接但 prefetcher 跟得上)。

```rust
let mut indices: Vec<u32> = (0..entities.len() as u32).collect();
indices.sort_by(|&a, &b| sort_rule(&entities[a as usize], &entities[b as usize]));
let sorted: Vec<&Entity> = indices.iter().map(|&i| &entities[i as usize]).collect();
```

100K sprite 的 sort 用这个技巧能加速 30%。

**位运算打包 sort key**。今天 sort_key 是 u64,可以塞进多个字段:

```
bits 63-56: layer (8 bits, 256 layers)
bits 55-40: bottom_y (16 bits, 65536 levels)
bits 39-24: x (16 bits)
bits 23-8: sub_layer (16 bits)
bits 7-0: spawn_id (8 bits, 256 entries per slot)
```

打包:`key = (layer << 56) | (bottom_y << 40) | (x << 24) | (sub << 8) | spawn`。一次 u64 比较,无分支,Rust `sort_by_key` 自动 inline。

**部分序的图论模型**。Day 304 会用拓扑排序处理真正的部分序。每个 sprite 是图节点,如果 A 应该在 B 前面,加边 A→B。拓扑排序给出节点的合法顺序(满足所有约束)。

拓扑排序算法:

1. **Kahn 算法**:每次找入度为 0 的节点,加入结果,删掉它的出边,重复。
2. **DFS 后序**:DFS 遍历,记录后序(post-order),反转得到拓扑序。

如果图有环(循环依赖),拓扑排序失败——意味着 sprite 排序无解,必须**人为拆解**(切开某个 sprite)。

**浮点数的稳定性**。Rust 的 `f32::partial_cmp` 处理 NaN 返回 `None`,sort 会 panic。所以游戏代码里要么保证所有 f32 都不是 NaN(数学保证),要么 `partial_cmp(...).unwrap_or(Equal)`(默认相等)。今天 sort_rule 用后者。

更稳妥的方法:**所有位置用整数**(像素单位)。`pos_y: i32` 没有 NaN 问题,比较无分支。但缩放和旋转要用浮点,所以游戏用 i32 + f32 混合。

### 真实代码片段

Casey 在 HH 视频里实际写的代码风格(简化伪代码):

```c
internal int32
SortRule(entity *A, entity *B)
{
    int32 Result = 0;

    // Layer 比较
    if (A->Layer != B->Layer) {
        Result = (int32)A->Layer - (int32)B->Layer;
    } else {
        // Bounds overlap 检查
        rectangle2 BoundsA = GetEntityBounds(A);
        rectangle2 BoundsB = GetEntityBounds(B);
        if (RectanglesOverlap(BoundsA, BoundsB)) {
            // Bottom y 比较
            real32 BottomA = BoundsA.Max.Y;
            real32 BottomB = BoundsB.Max.Y;
            if (BottomA != BottomB) {
                Result = (BottomA < BottomB) ? -1 : 1;
            } else {
                // x 比较
                Result = SignOf32(A->P.X - B->P.X);
            }
        } else {
            // 不重叠:任意顺序
            Result = A->SpawnID - B->SpawnID;
        }
    }

    return Result;
}
```

注意 Casey 的 C 风格:

- 直接返回 int32(而非 enum Ordering)
- 用 `SignOf32`(返回 -1/0/1)简化比较
- if-else 链而非 Rust 的 `then_with`

Rust 等价:

```rust
fn sort_rule(a: &Entity, b: &Entity) -> Ordering {
    a.layer.cmp(&b.layer)
        .then_with(|| {
            if bounds_overlap(a, b) {
                let ba = bounds(a).max.y;
                let bb = bounds(b).max.y;
                ba.partial_cmp(&bb).unwrap_or(Ordering::Equal)
                    .then(a.pos.x.partial_cmp(&b.pos.x).unwrap_or(Ordering::Equal))
            } else {
                a.spawn_id.cmp(&b.spawn_id)
            }
        })
}
```

### 跨学科联结:从游戏到数据库

sort_rule 的本质是"复杂比较函数",这在很多领域都出现:

- **数据库 ORDER BY**:SQL 的 `ORDER BY layer, y, x` 是同样的 multi-key sort,但 SQL 是声明式(数据库优化器选 sort 算法),Casey 是命令式(手写 sort_by)。
- **React diff**:React 用 sort + key 比较 virtual DOM,决定哪些 component 重渲染。Multi-key sort 决定 diff 顺序。
- **Linux kernel CFS**(Completely Fair Scheduler):按 vruntime 排序进程,选最小 vruntime 的运行。本质是 sort_rule。
- **Git log --sort**:Git commit 按 committer date + author date + subject 排序。

Casey 在 HH 反复说"很多算法本质相同,只是命名不同"。掌握一个领域的 sort_rule,就掌握所有领域。
