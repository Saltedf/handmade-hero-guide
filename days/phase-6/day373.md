
# Day 373 · 反转完整 3D 变换

> 渲染时,顶点经历"模型 → 世界 → 相机 → 裁剪"的正向变换。但 Casey 今天要做**反向**:从屏幕坐标反推世界坐标——例如鼠标点击地板上某点,玩家走过去。这需要 **MVP 矩阵的逆变换**。

## 0 · 为什么要有这一天

你的游戏正在变成熟。玩家想用**鼠标点击地板上某个位置**,玩家角色走过去。这是 RTS / RPG 游戏的核心交互。

但鼠标点击只给你**屏幕坐标**(像素位置,如 (640, 360))。玩家要走到的目标是**世界坐标**(3D 空间,如 (5.0, 0, 7.5))。怎么转换?

渲染时顶点经过这样的链:
```
模型空间(顶点 0.5, 0.5, 0.5)
  ↓ MVP 矩阵
裁剪空间(gl_Position)
  ↓ 透视除法
NDC(-1 ~ +1)
  ↓ 视口变换
屏幕空间(像素)
```

反推世界坐标:**每一步反过来**。屏幕 → NDC → 裁剪 → 相机 → 世界。每一步都需要正向变换的**逆矩阵**或**逆操作**。

这就是为什么需要 **inverting the full 3D transform**(反转完整 3D 变换)。具体来说:
1. 屏幕 → NDC:用视口参数反推(`(pixel - viewport.x) / viewport.width * 2 - 1`)
2. NDC → 裁剪:加回 w 分量(透视除法的逆)
3. 裁剪 → 相机:用 projection 矩阵的逆
4. 相机 → 世界:用 view 矩阵的逆
5. 世界 → 模型(可选):用 model 矩阵的逆

**关键难点**:透视投影的逆。投影矩阵把 3D 投影到 2D,信息丢失(深度方向被压缩)。反推时,**1 个屏幕坐标对应 3D 空间的一条射线**(不是点)。所以反推结果是 ray(射线),需要进一步用射线与场景求交(如 ray vs plane / ray vs AABB),找到具体点。

这就是为什么**鼠标拾取(mouse picking)**的标准做法是:
1. 反推得到一条世界空间射线
2. 射线与地面(plane)求交,得到点击点
3. 或射线与每个 entity 的 AABB 求交,得到点击对象

Casey 今天的工作:**写完整的 3D 变换反转代码**,从屏幕坐标算出世界射线。这是后面 Day 377(改进碰撞体)、Day 433(Ray vs AABB)的基础。

心理锚点:今天之后,你能实现鼠标拾取地板,理解透视投影的"信息丢失"和射线表示,能在 shader 里写反转变换(后面 Day 376 调试 volume 用)。

## 2 · 心智模型

### 类比:正向变换是"打包",反向变换是"拆包"

想象你寄一个包裹:
1. 把物品放进盒子(model)
2. 把盒子装进箱子(view)
3. 把箱子贴标签写地址(projection)
4. 把箱子拍照存档(屏幕像素)

收到包裹(屏幕坐标 → 世界)反着来:
1. 从照片识别箱子(屏幕 → NDC)
2. 撕掉标签看箱子(NDC → 裁剪)
3. 打开箱子看盒子(裁剪 → 相机)
4. 打开盒子看物品(相机 → 世界)

每一步都要"对应的拆包工具"。打包用 `M × V × P` 矩阵,拆包用 `(M × V × P)^-1 = P^-1 × V^-1 × M^-1` 矩阵。**矩阵乘法顺序反过来,每个矩阵取逆**。

### 正向变换链(回顾)

```
顶点 p_model(模型空间)
   │
   │ × model matrix (M)
   ▼
p_world(世界空间)
   │
   │ × view matrix (V)
   ▼
p_camera(相机空间)
   │
   │ × projection matrix (P)
   ▼
p_clip(裁剪空间,4D vec4)
   │
   │ 透视除法:.xyz / .w
   ▼
p_ndc(NDC,3D vec3,xyz ∈ [-1, 1])
   │
   │ 视口变换:0.5 * (p.xy + 1) * viewport_size + viewport_offset
   │ 深度变换:0.5 * (p.z + 1) * depth_range + depth_offset
   ▼
p_screen(屏幕空间,像素 + 深度)
```

### 反向变换链

```
p_screen(屏幕像素)
   │
   │ 视口逆变换:((p.xy - offset) / size) * 2 - 1
   │ 深度逆变换:类似
   ▼
p_ndc(NDC,xyz ∈ [-1, 1])
   │
   │ 透视除法逆:NDC 只是 .xyz / .w 的结果,w 未知
   │ → 假设两个 w(near 和 far),得到两个裁剪点
   │ → 实际上 NDC 反推是一对裁剪点,定义一条射线
   ▼
p_clip_near, p_clip_far(裁剪空间,4D vec4)
   │
   │ × inverse(projection × view) = P^-1 × V^-1
   ▼
p_world_near, p_world_far(世界空间)
   │
   │ 射线 ray = Ray { origin: p_world_near, dir: (far - near).normalize() }
   ▼
世界射线
```

### 关键技巧:用两个深度值构造射线

透视除法 `clip.xyz / clip.w = ndc` 在反推时,**w 是未知的**。但我们可以**任意选两个深度**:

- 选 z_ndc = -1(对应 near plane),w_clip = 1(假设),算出 p_world_near
- 选 z_ndc = +1(对应 far plane),w_clip = 1(假设),算出 p_world_far

这两个世界点定义一条射线。**射线的具体位置由 z_ndc 决定**,但因为我们不在乎绝对位置,只在乎方向,任意选两个不同 z 都能算出同一射线(方向一致,只是起点不同)。

代码:

```rust
use glam::{Mat4, Vec2, Vec3, Vec4};

pub struct Ray {
    pub origin: Vec3,
    pub dir: Vec3,  // normalized
}

pub fn screen_to_world_ray(
    screen_pos: Vec2,         // 鼠标坐标(像素)
    viewport_size: Vec2,      // (width, height)
    inv_view_proj: Mat4,      // inverse(view × projection) 或 inverse(projection × view)
    camera_pos: Vec3,         // 相机世界位置(作为射线起点更方便)
) -> Ray {
    // 1. 屏幕 → NDC
    let ndc_x = (screen_pos.x / viewport_size.x) * 2.0 - 1.0;
    let ndc_y = 1.0 - (screen_pos.y / viewport_size.y) * 2.0;  // y 翻转
    // 注意:NDC y 向上(+1 在顶部),屏幕 y 向下(0 在顶部),要翻转

    // 2. NDC → 裁剪 → 世界(选 z = -1 即 near plane)
    let ndc_near = Vec4::new(ndc_x, ndc_y, -1.0, 1.0);
    let world_near = inv_view_proj * ndc_near;

    // 3. 透视除法(w ≠ 1 时需要除)
    let world_near = world_near / world_near.w;  // 现在 w = 1

    // 4. 射线方向:从相机指向 world_near
    //    (也可以选 z = +1 算 far,方向 = (far - near).normalize(),结果相同)
    let dir = (world_near.xyz() - camera_pos).normalize();

    Ray { origin: camera_pos, dir }
}
```

### 投影矩阵的逆:为什么直接用 `inverse()`

`glam::Mat4::perspective_lh(fovy, aspect, near, far)` 生成投影矩阵 P。这个矩阵的逆可以直接 `P.inverse()` 算出来。

但更高效的做法是**手写投影逆**(因为投影矩阵有特殊结构,通用 4x4 求逆慢)。Casey 暂时用 `inverse()`,Phase 8 性能优化时手写。

### View 矩阵的逆:就是相机变换矩阵

`view = inverse(camera_world_transform)`,所以 `inverse(view) = camera_world_transform`。可以直接用相机位置 + 朝向构造。

### Rust 视角:统一的反推

```rust
pub struct Camera {
    pub pos: Vec3,
    pub forward: Vec3,
    pub up: Vec3,
    pub fov_y: f32,
    pub aspect: f32,
    pub near: f32,
    pub far: f32,
}

impl Camera {
    pub fn view_matrix(&self) -> Mat4 {
        Mat4::look_at_lh(self.pos, self.pos + self.forward, self.up)
    }

    pub fn projection_matrix(&self) -> Mat4 {
        Mat4::perspective_lh(self.fov_y, self.aspect, self.near, self.far)
    }

    pub fn view_projection(&self) -> Mat4 {
        self.projection_matrix() * self.view_matrix()
    }

    pub fn inverse_view_projection(&self) -> Mat4 {
        self.view_projection().inverse()
    }

    pub fn screen_to_ray(&self, screen_pos: Vec2, viewport: Vec2) -> Ray {
        let inv_vp = self.inverse_view_projection();
        screen_to_world_ray(screen_pos, viewport, inv_vp, self.pos)
    }
}
```

**射线 vs 各种几何**:

| 几何 | 算法 | 复杂度 |
|---|---|---|
| Plane | ray 和 plane 代数求交 | O(1) |
| Sphere | 二次方程 | O(1) |
| AABB | slab method | O(1) |
| Triangle | Möller–Trumbore | O(1) |
| Mesh | 遍历所有三角形(或 BVH 加速) | O(N) 或 O(log N) |
| Voxel grid | DDA / Bresenham 3D | O(ray length) |

**鼠标拾取的工业方案**:

1. **CPU 射线求交**:Casey 现在的做法。简单,适合简单几何
2. **GPU picking**:渲染时给每个像素写入"对象 ID",读鼠标位置像素。复杂场景快,但需要读 framebuffer
3. **Color picking**:每帧渲染"不可见"的 ID buffer(每个 entity 纯色),鼠标读像素查 ID

### 3.2 · 🎨 图形学视角

变换矩阵在图形学是核心抽象。关键概念:

**齐次坐标(homogeneous coordinates)**

3D 点用 4D `(x, y, z, w)` 表示:
- w = 1:点(point)
- w = 0:方向(direction)

平移矩阵用 w=1 的列乘出来表示平移效果;旋转 / 缩放矩阵对 w=0 的方向不起作用(方向不变)。

**Affine vs Projective 变换**

- **Affine(仿射)**:平移 + 旋转 + 缩放。M, V 矩阵是仿射。`inverse(M)` 也是仿射
- **Projective(投影)**:透视除法。P 矩阵是 projective。`inverse(P)` 也是 projective,但有奇点

**inverse 矩阵的代数**

4×4 矩阵求逆复杂。`glam` 用 **Laplace expansion** 或 **block inverse**(把矩阵分块,2×2 块的逆)。教学项目用 `inverse()` 库函数,不手写。

**正交投影 vs 透视投影的反推差异**

透视投影(有 perspective divide):反推得到射线(深度方向不确定)
正交投影(无 perspective divide):反推得到唯一世界点(深度直接对应 Z)

正交投影的鼠标拾取:屏幕 (x, y) → NDC (x, y, z=-1) → world (x, y, z=z_near),简单。透视投影复杂(需要构造射线)。

### 3.4 · 🦀 Rust 生态视角

Rust 矩阵库:

**`glam`**(游戏优化):

```rust
use glam::{Mat4, Vec3};
let inv = mat.inverse();  // 4x4 求逆
let det = mat.determinant();
```

**`nalgebra`**(科学计算):

```rust
use nalgebra::{Matrix4, Vector3};
let inv = mat.try_inverse().expect("singular matrix");
// try_inverse 返回 Option,处理奇异矩阵
```

**`cgmath`**(老牌,被 glam 取代):

```rust
use cgmath::{Matrix4, Vector3, Decomposed};
let inv: Matrix4<f32> = transform.invert().unwrap().into();
```

`glam` 是 Bevy 引擎默认,工业最流行。

**矩阵求逆的实现**

`glam::Mat4::inverse` 内部用 cofactor / adjugate 方法。对 4x4 矩阵,具体步骤:

```
1. 计算 16 个 cofactor(每个是 3x3 行列式)
2. 组成 adjugate 矩阵(cofactor 的转置)
3. 行列式 = trace 某种组合
4. inverse = adjugate / det
```

如果 det = 0(奇异矩阵),inverse 不存在。透视投影矩阵 det ≠ 0,可以求逆。但 model matrix 如果 scale 为 0(det = 0),inverse 不存在。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么屏幕坐标反推得到的是射线而不是点?如果用正交投影,反推是什么?

**参考解答**:

透视投影反推得到射线,因为透视除法**丢失了深度信息**。具体:正向时 `clip.xyz / clip.w = ndc`,知道 `ndc.xyz`,但 `w` 未知(被除掉了)。一组 (ndc.x, ndc.y, ndc.z) 对应不同 w 的多个 clip 点,这些 clip 点反推到世界空间形成一条线(射线)。

实际操作:固定 ndc.x 和 ndc.y(来自屏幕坐标),选两个不同 ndc.z(如 -1 和 +1),算出两个世界点,这两个点定义一条射线。

正交投影反推得到**唯一世界点**。正交投影没有 perspective divide(或者 w 永远 = 1),所以 (ndc.x, ndc.y, ndc.z) 直接对应一个世界点。鼠标点击 + 想要的深度(z)能算出唯一 3D 点。

游戏工业里,RTS / 建造游戏常用正交投影(俯视),鼠标拾取简单;FPS / TPS 用透视投影,需要射线求交。

### Lv2 · 动手实践

**题**:用 `glam` 实现完整的 `screen_to_world_ray` + `ray_vs_plane`。完成标准:
- 鼠标在屏幕中央 (960, 540),相机朝 +z,射线方向应该是 +z
- 鼠标在屏幕边缘 (1920, 540),射线应该向 +x +z 方向偏
- 射线 vs 地面(y=0 plane)求交,鼠标点屏幕中央应该得到 (0, 0, near) 附近的点

**参考解答**:

```rust
use glam::{Mat4, Vec2, Vec3, Vec4};

#[derive(Debug, Copy, Clone)]
pub struct Ray {
    pub origin: Vec3,
    pub dir: Vec3,
}

#[derive(Debug, Copy, Clone)]
pub struct Plane {
    pub normal: Vec3,    // 单位向量
    pub distance: f32,   // 平面到原点的距离(plane normal · p = distance)
}

pub struct Camera {
    pub pos: Vec3,
    pub forward: Vec3,
    pub up: Vec3,
    pub fov_y_radians: f32,
    pub aspect: f32,        // width / height
    pub near: f32,
    pub far: f32,
}

impl Camera {
    pub fn view(&self) -> Mat4 {
        Mat4::look_at_lh(self.pos, self.pos + self.forward, self.up)
    }

    pub fn projection(&self) -> Mat4 {
        Mat4::perspective_lh(self.fov_y_radians, self.aspect, self.near, self.far)
    }

    pub fn inverse_view_projection(&self) -> Mat4 {
        (self.projection() * self.view()).inverse()
    }
}

pub fn screen_to_world_ray(
    screen_pos: Vec2,
    viewport_size: Vec2,
    camera: &Camera,
) -> Ray {
    // 1. 屏幕 → NDC
    //    NDC x ∈ [-1, +1],屏幕 x ∈ [0, width]
    //    NDC y ∈ [-1, +1],屏幕 y ∈ [0, height](y 朝下),需要翻转
    let ndc_x = (screen_pos.x / viewport_size.x) * 2.0 - 1.0;
    let ndc_y = -(screen_pos.y / viewport_size.y) * 2.0 + 1.0;
    // 或者:1.0 - (screen_pos.y / viewport_size.y) * 2.0

    // 2. 用 z = -1 (near plane) 和 z = +1 (far plane) 算两个世界点
    let inv_vp = camera.inverse_view_projection();

    let ndc_near = Vec4::new(ndc_x, ndc_y, -1.0, 1.0);
    let ndc_far = Vec4::new(ndc_x, ndc_y, 1.0, 1.0);

    let world_near = inv_vp * ndc_near;
    let world_far = inv_vp * ndc_far;

    // 3. 透视除法(把 w 归 1)
    let world_near = world_near / world_near.w;
    let world_far = world_far / world_far.w;

    // 4. 射线:从 near 指向 far
    let dir = (world_far.xyz() - world_near.xyz()).normalize();

    Ray {
        origin: world_near.xyz(),
        dir,
    }
}

pub fn ray_vs_plane(ray: &Ray, plane: &Plane) -> Option<Vec3> {
    // 平面方程:normal · p = distance
    // 射线:p = origin + t * dir
    // 代入:normal · (origin + t * dir) = distance
    //   → normal · origin + t * (normal · dir) = distance
    //   → t = (distance - normal · origin) / (normal · dir)

    let denom = plane.normal.dot(ray.dir);
    if denom.abs() < 1e-6 {
        // 射线和平面平行,无交点
        return None;
    }

    let t = (plane.distance - plane.normal.dot(ray.origin)) / denom;
    if t < 0.0 {
        // 交点在射线反方向,无效
        return None;
    }

    Some(ray.origin + ray.dir * t)
}

fn main() {
    let camera = Camera {
        pos: Vec3::new(0.0, 5.0, -5.0),
        forward: Vec3::new(0.0, -1.0, 1.0).normalize(),  // 朝前下方
        up: Vec3::new(0.0, 1.0, 0.0),
        fov_y_radians: std::f32::consts::FRAC_PI_4,  // 45 度
        aspect: 1920.0 / 1080.0,
        near: 0.1,
        far: 100.0,
    };

    let viewport = Vec2::new(1920.0, 1080.0);

    // 测试 1:屏幕中央
    let ray = screen_to_world_ray(Vec2::new(960.0, 540.0), viewport, &camera);
    println!("Center ray: origin={:?}, dir={:?}", ray.origin, ray.dir);
    // dir 应该指向相机 forward 方向 ((0,-1,1) 归一化)

    // 测试 2:鼠标 vs 地板 plane (y = 0)
    let floor = Plane {
        normal: Vec3::new(0.0, 1.0, 0.0),
        distance: 0.0,
    };
    let hit = ray_vs_plane(&ray, &floor);
    println!("Floor hit: {:?}", hit);
    // 应该有交点,且 y ≈ 0
}
```

**关键解释**:
- `Mat4::look_at_lh(eye, target, up)` — `_lh` 表示左手坐标系(left-handed)。OpenGL 默认右手,DirectX 左手。glam 提供 `_lh` / `_rh` 两个版本,选匹配你引擎的
- `Mat4::perspective_lh(fov_y, aspect, near, far)` — 同上,左右手版本
- `Vec4 / Vec4` — 4D 向量除法(对应每分量除),这是做透视除法
- `t < 0.0` 检查 — 射线起点是 origin,只考虑 forward 方向(t > 0)

### Lv3 · 迁移设计

**题**:不只是 plane,实现 `ray_vs_sphere(ray, center, radius) -> Option<Vec3>`(射线和球体求交)。**提示**:代入射线方程到球面方程,得到二次方程,解判别式。

**提示**:
- 球面方程:`|p - center|² = radius²`
- 射线:`p = origin + t * dir`(dir 已归一化)
- 代入:`|origin + t*dir - center|² = radius²`
- 展开:`(t*dir + (origin - center)) · (t*dir + (origin - center)) = radius²`
- `t²(dir · dir) + 2t(dir · (origin - center)) + |origin - center|² - radius² = 0`
- 二次方程 at² + bt + c = 0,t = (-b ± √(b² - 4ac)) / 2a
- 判别式 < 0 无解,< 0 一解(相切),> 0 两解(进入和离开)

### Rust:完整鼠标拾取实现

```rust
// Cargo.toml: gl = "0.14", glfw = "0.55", glam = "0.29"

use gl::types::*;
use glfw::{Context, FailOnError, Glfw, Window, WindowEvent};
use glam::{Mat4, Vec2, Vec3, Vec4};
use std::sync::mpsc::Receiver;

pub struct Camera {
    pub pos: Vec3,
    pub yaw: f32,    // 水平角度(弧度)
    pub pitch: f32,  // 垂直角度(弧度)
    pub fov_y: f32,
    pub aspect: f32,
    pub near: f32,
    pub far: f32,
}

impl Camera {
    pub fn forward(&self) -> Vec3 {
        // 球面坐标 → 笛卡尔坐标
        Vec3::new(
            self.pitch.cos() * self.yaw.sin(),
            self.pitch.sin(),
            self.pitch.cos() * self.yaw.cos(),
        ).normalize()
    }

    pub fn view(&self) -> Mat4 {
        Mat4::look_at_lh(self.pos, self.pos + self.forward(), Vec3::new(0.0, 1.0, 0.0))
    }

    pub fn projection(&self) -> Mat4 {
        Mat4::perspective_lh(self.fov_y, self.aspect, self.near, self.far)
    }

    pub fn view_projection(&self) -> Mat4 {
        self.projection() * self.view()
    }

    pub fn inverse_view_projection(&self) -> Mat4 {
        self.view_projection().inverse()
    }
}

#[derive(Copy, Clone, Debug)]
pub struct Ray {
    pub origin: Vec3,
    pub dir: Vec3,
}

pub fn screen_to_world_ray(
    screen_pos: Vec2,
    viewport_size: Vec2,
    inv_vp: Mat4,
) -> Ray {
    let ndc_x = (screen_pos.x / viewport_size.x) * 2.0 - 1.0;
    let ndc_y = 1.0 - (screen_pos.y / viewport_size.y) * 2.0;

    let ndc_near = Vec4::new(ndc_x, ndc_y, -1.0, 1.0);
    let ndc_far = Vec4::new(ndc_x, ndc_y, 1.0, 1.0);

    let inv_vp_times_near = inv_vp * ndc_near;
    let inv_vp_times_far = inv_vp * ndc_far;

    let world_near = inv_vp_times_near / inv_vp_times_near.w;
    let world_far = inv_vp_times_far / inv_vp_times_far.w;

    let dir = (world_far - world_near).xyz().normalize();

    Ray {
        origin: world_near.xyz(),
        dir,
    }
}

pub fn ray_vs_plane(ray: &Ray, normal: Vec3, distance: f32) -> Option<Vec3> {
    let denom = normal.dot(ray.dir);
    if denom.abs() < 1e-6 {
        return None;
    }
    let t = (distance - normal.dot(ray.origin)) / denom;
    if t < 0.0 {
        return None;
    }
    Some(ray.origin + ray.dir * t)
}

struct GameState {
    camera: Camera,
    cursor_pos: Vec2,
    viewport: Vec2,
    floor_hit: Option<Vec3>,
}

impl GameState {
    fn new() -> Self {
        Self {
            camera: Camera {
                pos: Vec3::new(0.0, 5.0, -5.0),
                yaw: std::f32::consts::FRAC_PI_4,
                pitch: -std::f32::consts::FRAC_PI_6,
                fov_y: std::f32::consts::FRAC_PI_4,
                aspect: 1920.0 / 1080.0,
                near: 0.1,
                far: 100.0,
            },
            cursor_pos: Vec2::new(960.0, 540.0),
            viewport: Vec2::new(1920.0, 1080.0),
            floor_hit: None,
        }
    }

    fn update_picking(&mut self) {
        let inv_vp = self.camera.inverse_view_projection();
        let ray = screen_to_world_ray(self.cursor_pos, self.viewport, inv_vp);

        // 地板平面:y = 0,即 normal=(0,1,0),distance=0
        self.floor_hit = ray_vs_plane(&ray, Vec3::new(0.0, 1.0, 0.0), 0.0);

        if let Some(hit) = self.floor_hit {
            println!("Cursor hits floor at: ({:.2}, {:.2}, {:.2})", hit.x, hit.y, hit.z);
        }
    }
}

fn main() {
    let mut glfw = glfw::init(FailOnError).unwrap();
    // (window hints, see day372)
    let (mut window, events) = glfw.create_window(1920, 1080, "Mouse Picking", glfw::WindowMode::Windowed).unwrap();
    window.make_current();
    window.set_cursor_pos_polling(true);
    window.set_key_polling(true);
    gl::load_with(|s| window.get_proc_address(s) as *const _);

    let mut state = GameState::new();

    while !window.should_close() {
        glfw.poll_events();
        for (_, event) in events.try_iter() {
            match event {
                WindowEvent::CursorPos(x, y) => {
                    state.cursor_pos = Vec2::new(x as f32, y as f32);
                }
                WindowEvent::Key(glfw::Key::Escape, _, _, _) => {
                    window.set_should_close(true);
                }
                _ => {}
            }
        }

        state.update_picking();

        // (rendering)
        window.swap_buffers();
    }
}
```

**关键 Rust 特性解释**:
- `Mat4 * Vec4` — glam 的矩阵向量乘法。注意顺序:矩阵在左,列向量在右(OpenGL 风格)
- `Vec4 / f32` — glam 实现了 `Div<f32>`,每分量除以标量
- `.xyz()` — 把 Vec4 转 Vec3,丢掉 w 分量
- `ray.origin + ray.dir * t` — `Ray` 起点 + 方向 × 参数 = 射线上的点
- 球面坐标到笛卡尔:`forward = (cos(pitch)*sin(yaw), sin(pitch), cos(pitch)*cos(yaw))`,这是 FPS 相机标准实现

**Troubleshooting**:

- **射线方向错** — NDC y 翻转方向错。屏幕 y 0 在顶部,NDC y -1 在底部
- **射线方向反** — 左手系 vs 右手系混了。检查 `look_at_lh` vs `look_at_rh`
- **ray_vs_plane 永远返回 None** — 平面法线和射线方向平行(denom 接近 0),或射线方向反(t < 0)
- **inverse matrix 全 NaN** — 矩阵奇异(det=0),检查 scale 是否为 0
- **HiDPI 上鼠标位置错** — 鼠标坐标是 logical pixel,viewport 是 physical pixel,需要乘 content_scale
