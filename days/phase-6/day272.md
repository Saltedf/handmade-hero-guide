# Day 272 · 显式移动过渡

> 昨天的混合移动是"隐式"状态——destination 是 None 还是 Some 决定角色静止还是移动,但代码里没有显式的状态字段。今天 Casey 把"静止 / 过渡"做成显式状态机,让移动逻辑更清晰、扩展性更好。

## 0 · 为什么要有这一天

昨天的 Player 代码:

```rust
struct Player {
    pos: Vec2,
    destination: Option<Vec2>,
    speed: f32,
}
```

`destination: Option<Vec2>` 隐含了两种状态:`None` = 静止,`Some` = 移动中。看起来简洁,但很快你会撞到几个问题:

**问题 1:加新状态困难**。你想加一个"碰撞反弹"状态:撞墙后角色后退一小段再停下。当前架构下,这个状态怎么表达?用 `destination: Some(后退点)` 然后到达后清空?但这个"后退"和"普通移动"语义不同,代码里要 if-else 区分。

**问题 2:状态转换的副作用分散**。"开始移动时播放脚步声"、"到达时播放落地音效"——这些副作用该在哪写?现在的代码:`handle_input` 设 destination(开始移动)、`update` 清 destination(到达)。两个地方分散,加新副作用要找两处改。

**问题 3:并发状态混乱**。角色可能"移动中" + "受伤中" + "无敌中"。三个独立 bool 标志会让代码变成 if-else 的迷宫。

软件工程的标准解决方案是**显式状态机**(State Machine):把所有可能的状态列出来,每个状态有自己的 enter / update / exit 函数,状态转换明确。

今天 Casey 把 Player 从"隐式 Option"改成"显式 enum State"。

心理锚点:做完这个,Player 的行为扩展性强得多,加新状态(攻击 / 跳跃 / 受伤)不会破坏现有逻辑。

## 1 · Casey 今天做了什么

Casey 重构 Player 的数据结构和 update 逻辑:

1. 引入 `enum MoveState { Idle, Moving { destination: Vec2, direction: Direction } }`
2. Player 的 destination 字段从 `Option<Vec2>` 改成 `state: MoveState`
3. update 函数用 match 分发:`match self.state { Idle => {} Moving { destination, .. } => { ... } }`
4. 状态转换显式:`Idle` → `Moving`(玩家按方向键时);`Moving` → `Idle`(到达时)
5. 状态转换的副作用集中在 `enter_idle` / `enter_moving` 函数里

Casey 演示了状态机的好处:他加了一个新状态 `Bouncing { from: Vec2, to: Vec2, t: f32 }`(撞墙后弹回),没有破坏现有 Idle / Moving 逻辑——只在 match 里多了一个分支。

## 2 · 心智模型

### 类比:电梯的状态

电梯是一个经典状态机:

- **Idle**:停在某一层,门关着
- **DoorOpen**:门开着,等待乘客
- **Moving**:门关着,在楼层间移动
- **Emergency**:紧急停止状态

转换:

- Idle + 按按钮 → Moving(门关,开始移动)
- Moving + 到达目标 → DoorOpen(门开)
- DoorOpen + 5 秒后 → Idle(门关)
- 任何时候 + 紧急按钮 → Emergency

每种状态有自己的行为规则,不能混淆:Moving 状态下不能开门(物理上);DoorOpen 状态下不能上下移动(逻辑上)。

Player 状态机也是这个模式:**列出所有可能状态,每个状态行为明确**。

### 严谨原理:状态机的 Rust 表达

#### 用 enum 表达状态

```rust
#[derive(Clone, Debug)]
enum MoveState {
    Idle,
    Moving {
        destination: Vec2,
        direction: Direction,
    },
    Bouncing {
        from: Vec2,
        to: Vec2,
        progress: f32,  // 0..1
    },
}

struct Player {
    pos: Vec2,
    state: MoveState,
    speed: f32,
}
```

注意 enum 变体可以携带数据:`Moving { destination, direction }`。这是 Rust enum 比 C enum / Java enum 强大的地方——每个变体可以有自己的字段。

#### match 分发

```rust
impl Player {
    fn update(&mut self, dt: f32) {
        match &mut self.state {
            MoveState::Idle => {
                // 静止,什么都不做
            }
            MoveState::Moving { destination, direction } => {
                let to_dest = destination.sub(self.pos);
                let distance = to_dest.length();
                if distance < EPSILON {
                    self.enter_idle();
                } else {
                    let velocity = to_dest.scale(self.speed / distance);
                    self.pos = self.pos.add(velocity.scale(dt));
                    if (velocity.scale(dt)).length() >= distance {
                        self.pos = *destination;
                        self.enter_idle();
                    }
                }
            }
            MoveState::Bouncing { from, to, progress } => {
                *progress += dt * 5.0;  // 5 倍速,0.2 秒完成
                if *progress >= 1.0 {
                    self.pos = *to;
                    self.enter_idle();
                } else {
                    // 线性插值
                    self.pos = from.lerp(*to, *progress);
                }
            }
        }
    }

    fn enter_idle(&mut self) {
        // 副作用:到达音效等
        self.state = MoveState::Idle;
    }

    fn enter_moving(&mut self, destination: Vec2, direction: Direction) {
        self.state = MoveState::Moving { destination, direction };
    }
}
```

**关键点**:

- `match &mut self.state` 同时匹配状态并获取字段的可变引用
- 每个分支独立处理,不互相干扰
- 状态转换调用 `enter_xxx` 函数,副作用集中

#### 状态转换图

```
       按方向键
[Idle] ────────> [Moving]
   ▲                │
   │ 到达            │ 撞墙
   │                ▼
   └──────────── [Bouncing]
            完成
```

每个箭头是一次状态转换,由特定事件触发。绘制转换图能让状态机设计更清晰。

### 输入处理的状态感知

输入处理也要看状态:

```rust
fn handle_input(&mut self, dir: Direction, map: &TileMap) {
    match self.state {
        MoveState::Idle => {
            // 静止时,开始新移动
            let next_tile = compute_next_tile(self.pos, dir);
            if map.is_traversable(next_tile) {
                self.enter_moving(tile_center(next_tile), dir);
            }
        }
        MoveState::Moving { .. } => {
            // 移动中,改向(覆盖 destination)
            let current_tile = world_to_tile(self.pos);
            let next_tile = match dir {
                Direction::Up => TilePos(current_tile.0, current_tile.1 - 1),
                // ...
            };
            if map.is_traversable(next_tile) {
                self.enter_moving(tile_center(next_tile), dir);
            }
        }
        MoveState::Bouncing { .. } => {
            // 弹回中,忽略输入
        }
    }
}
```

注意 Bouncing 状态忽略输入——这是状态机的好处:某些状态下不接受输入,代码里直接 `=> {}`,无歧义。

### 状态机的扩展性

加新状态只需:

1. enum 里加变体
2. match 里加分支
3. 加 `enter_xxx` 函数

不需要改其他状态的代码。这是开闭原则(Open-Closed Principle)的体现:对扩展开放,对修改封闭。

### 3.3 · 🦀 Rust 生态视角

Rust 表达状态机的几个考量:

#### 用 enum(推荐)

```rust
enum State { Idle, Moving { dest: Vec2 } }
```

优点:

- 编译器强制覆盖所有变体
- 数据和状态在一起,内存紧凑
- match 表达清晰

缺点:

- 改 enum 要改所有 match(编译器会报错,这是优点也是工作量)
- 跨线程共享状态机需要锁

#### 用 trait object

```rust
trait State {
    fn update(&mut self, player: &mut Player, dt: f32);
    fn handle_input(&mut self, player: &mut Player, input: &Input);
}

struct IdleState;
struct MovingState { dest: Vec2 }

struct Player {
    state: Box<dyn State>,
    // ...
}
```

优点:状态可以独立编译(动态加载)。
缺点:虚函数调用、堆分配、失去编译期穷尽检查。

#### 类型状态(Type State)

Rust 的高级用法:用泛型 + phantom 编码状态:

```rust
struct Player<S> { pos: Vec2, _state: PhantomData<S> }
struct Idle;
struct Moving;

impl Player<Idle> {
    fn start_moving(self, dest: Vec2) -> Player<Moving> {
        Player { pos: self.pos, _state: PhantomData, destination: dest }
    }
}

impl Player<Moving> {
    fn stop(self) -> Player<Idle> {
        Player { pos: self.pos, _state: PhantomData }
    }
}
```

类型状态让非法状态在编译期就拒绝(例如不能对 `Player<Idle>` 调 `stop()`)。但实现复杂,适合关键场景。

### 3.4 · 软件工程:状态机设计原则

设计状态机几个原则:

1. **状态数最少**:每个状态都要有独特行为,否则合并
2. **避免"隐藏状态"**:不要用 bool 标志加"假状态",该用 enum 就用
3. **状态转换集中**:转换逻辑写在一处,不要散在多个函数
4. **副作用在 enter / exit**:不在 update 里写副作用,容易重复触发

Casey 的状态机符合这些原则:Idle / Moving / Bouncing 三个状态,各自行为独立,转换在 enter_idle / enter_moving 等函数。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么用 enum 状态机比"bool is_moving + bool is_bouncing"标志更好?给出至少 3 个理由。

**参考解答**:
1. **状态穷尽**:enum 强制 match 覆盖所有变体,不会"忘了处理某个状态"。bool 标志容易遗漏(例如 is_moving=true, is_bouncing=true 时该怎么处理?冲突状态)
2. **避免非法组合**:`is_moving=true && is_bouncing=true` 是无意义的(不能同时移动和弹回),但 bool 标志允许;enum 不允许(同一个时刻只能有一个 MoveState 变体)
3. **数据局部性**:enum 把"状态相关数据"打包(如 Moving 的 destination 直接在变体里),不需要独立的 destination 字段;bool 标志 + 散落字段会让代码读取割裂
4. **可读性**:match 状态枚举 vs 一堆 if (is_moving && !is_bouncing) 表达式,前者清晰得多
5. **扩展性**:加新状态只需 enum 加变体,match 加分支;bool 标志加新维度要修改所有 if 条件
6. **编译器验证**:enum 加变体后,所有 match 处编译器报错提醒,改完就完事;bool 标志没这个保护

### Lv2 · 动手实践

**题**:把昨天 Player 的 `destination: Option<Vec2>` 改成 `state: MoveState`,其中 `MoveState` 有 Idle 和 Moving 两个变体。

要求:

- MoveState 是 enum,Idle 无数据,Moving 有 destination: Vec2
- enter_idle / enter_moving 函数处理转换 + 打印副作用
- update 用 match 分发

测试:

- Player 初始 Idle
- 按 Right,变 Moving,打印 "Entering Moving state"
- update 若干帧,到达后变 Idle,打印 "Entering Idle state"

**参考解答**:

```rust
#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self { x: self.x - o.x, y: self.y - o.y } }
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
    fn scale(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
    fn length(self) -> f32 { (self.x * self.x + self.y * self.y).sqrt() }
}

#[derive(Clone, Copy, Debug)]
enum MoveState {
    Idle,
    Moving { destination: Vec2 },
}

struct Player {
    pos: Vec2,
    state: MoveState,
    speed: f32,
}

impl Player {
    fn new(pos: Vec2) -> Self {
        Self { pos, state: MoveState::Idle, speed: 120.0 }
    }

    fn enter_idle(&mut self) {
        println!("  [State] Entering Idle at ({},{})", self.pos.x, self.pos.y);
        self.state = MoveState::Idle;
    }

    fn enter_moving(&mut self, destination: Vec2) {
        println!("  [State] Entering Moving, destination ({},{})",
                 destination.x, destination.y);
        self.state = MoveState::Moving { destination };
    }

    fn start_moving(&mut self, destination: Vec2) {
        match self.state {
            MoveState::Idle => self.enter_moving(destination),
            MoveState::Moving { .. } => {
                // 移动中改向
                println!("  [State] Changing destination mid-move");
                self.enter_moving(destination);
            }
        }
    }

    fn update(&mut self, dt: f32) {
        match self.state {
            MoveState::Idle => {
                // 静止,什么都不做
            }
            MoveState::Moving { destination } => {
                let to_dest = destination.sub(self.pos);
                let distance = to_dest.length();
                let epsilon = 1.0_f32;

                if distance < epsilon {
                    self.pos = destination;
                    self.enter_idle();
                    return;
                }

                let velocity = to_dest.scale(self.speed / distance);
                let displacement = velocity.scale(dt);

                if displacement.length() >= distance {
                    self.pos = destination;
                    self.enter_idle();
                } else {
                    self.pos = self.pos.add(displacement);
                }
            }
        }
    }
}

fn main() {
    let mut player = Player::new(Vec2::new(16.0, 16.0));
    println!("Initial state: {:?}", player.state);

    // 开始移动
    player.start_moving(Vec2::new(48.0, 16.0));

    // 模拟 30 帧
    let dt = 1.0 / 60.0;
    for frame in 0..30 {
        player.update(dt);
        if matches!(player.state, MoveState::Idle) {
            println!("  Arrived at frame {}", frame);
            break;
        }
    }

    // 测试移动中改向
    player.start_moving(Vec2::new(48.0, 48.0));
    // 走一帧
    player.update(dt);
    // 立即改向
    player.start_moving(Vec2::new(16.0, 48.0));

    for frame in 0..30 {
        player.update(dt);
        if matches!(player.state, MoveState::Idle) {
            println!("  Arrived at frame {}", frame);
            break;
        }
    }

    println!("Final state: {:?}, pos ({},{})",
             player.state, player.pos.x, player.pos.y);
}
```

**每行解释**:
- `enum MoveState` 用 enum 表达状态,变体可携带数据
- `enter_idle` / `enter_moving` 集中处理副作用和状态切换
- `match self.state` 在 update 中分发,每个状态独立处理
- `matches!(player.state, MoveState::Idle)` 是 macro,简洁地判断状态
- "移动中改向"通过 start_moving 处理,不需要单独的 cancel 函数

## 8 · Rust / Arch 落地代码

### 完整可跑:状态机移动 + 视觉反馈

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, KeyRepeat, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const TILE_SIZE: f32 = 32.0;
const MAP_W: i32 = 25;
const MAP_H: i32 = 18;
const PLAYER_SPEED: f32 = 200.0;

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self { x: self.x - o.x, y: self.y - o.y } }
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
    fn scale(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
    fn length(self) -> f32 { (self.x * self.x + self.y * self.y).sqrt() }
}

#[derive(Clone, Copy, Debug)]
enum Direction { Up, Down, Left, Right }

#[derive(Clone, Copy, Debug)]
enum MoveState {
    Idle,
    Moving { destination: Vec2, direction: Direction },
    Bumping { from: Vec2, to: Vec2, progress: f32 },
}

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

fn tile_center(t: TilePos) -> Vec2 {
    Vec2::new(
        (t.0 as f32 + 0.5) * TILE_SIZE,
        (t.1 as f32 + 0.5) * TILE_SIZE,
    )
}

fn world_to_tile(p: Vec2) -> TilePos {
    TilePos(
        (p.x / TILE_SIZE).floor() as i32,
        (p.y / TILE_SIZE).floor() as i32,
    )
}

struct TileMap {
    width: i32,
    height: i32,
    tiles: Vec<bool>,
}

impl TileMap {
    fn new(width: i32, height: i32) -> Self {
        Self { width, height, tiles: vec![true; (width * height) as usize] }
    }
    fn is_traversable(&self, t: TilePos) -> bool {
        if t.0 < 0 || t.1 < 0 || t.0 >= self.width || t.1 >= self.height { return false; }
        self.tiles[(t.1 * self.width + t.0) as usize]
    }
    fn set(&mut self, t: TilePos, traversable: bool) {
        if t.0 >= 0 && t.1 >= 0 && t.0 < self.width && t.1 < self.height {
            self.tiles[(t.1 * self.width + t.0) as usize] = traversable;
        }
    }
}

struct Player {
    pos: Vec2,
    state: MoveState,
    speed: f32,
}

impl Player {
    fn new(pos: Vec2) -> Self {
        Self { pos, state: MoveState::Idle, speed: PLAYER_SPEED }
    }

    fn enter_idle(&mut self) {
        self.state = MoveState::Idle;
    }

    fn enter_moving(&mut self, destination: Vec2, direction: Direction) {
        self.state = MoveState::Moving { destination, direction };
    }

    fn enter_bumping(&mut self, direction: Direction) {
        // 撞墙后向墙方向走一小段再弹回
        let bump_dist = 8.0;
        let from = self.pos;
        let to = match direction {
            Direction::Up => Vec2::new(from.x, from.y - bump_dist),
            Direction::Down => Vec2::new(from.x, from.y + bump_dist),
            Direction::Left => Vec2::new(from.x - bump_dist, from.y),
            Direction::Right => Vec2::new(from.x + bump_dist, from.y),
        };
        self.state = MoveState::Bumping { from, to, progress: 0.0 };
    }

    fn handle_input(&mut self, dir: Direction, map: &TileMap) {
        match self.state {
            MoveState::Bumping { .. } => {
                // 弹回中,忽略输入
            }
            _ => {
                let current_tile = world_to_tile(self.pos);
                let next_tile = match dir {
                    Direction::Up => TilePos(current_tile.0, current_tile.1 - 1),
                    Direction::Down => TilePos(current_tile.0, current_tile.1 + 1),
                    Direction::Left => TilePos(current_tile.0 - 1, current_tile.1),
                    Direction::Right => TilePos(current_tile.0 + 1, current_tile.1),
                };
                if map.is_traversable(next_tile) {
                    self.enter_moving(tile_center(next_tile), dir);
                } else {
                    // 撞墙:进入 Bumping 状态
                    self.enter_bumping(dir);
                }
            }
        }
    }

    fn update(&mut self, dt: f32) {
        match self.state {
            MoveState::Idle => {}
            MoveState::Moving { destination, .. } => {
                let to_dest = destination.sub(self.pos);
                let distance = to_dest.length();

                if distance < 1.0 {
                    self.pos = destination;
                    self.enter_idle();
                    return;
                }

                let velocity = to_dest.scale(self.speed / distance);
                let displacement = velocity.scale(dt);

                if displacement.length() >= distance {
                    self.pos = destination;
                    self.enter_idle();
                } else {
                    self.pos = self.pos.add(displacement);
                }
            }
            MoveState::Bumping { from, to, progress } => {
                let mut new_progress = progress + dt * 8.0;  // 0.125 秒完成
                if new_progress >= 1.0 {
                    self.pos = to;
                    self.enter_idle();
                } else {
                    // 简单的弹回动画:sin 曲线让进度有"反弹"感
                    let t = new_progress;
                    let eased = if t < 0.5 {
                        // 前半段:冲向墙
                        t * 2.0
                    } else {
                        // 后半段:弹回
                        2.0 - t * 2.0
                    };
                    self.pos = Vec2::new(
                        from.x + (to.x - from.x) * eased,
                        from.y + (to.y - from.y) * eased,
                    );
                    self.state = MoveState::Bumping {
                        from, to,
                        progress: new_progress,
                    };
                }
            }
        }
    }
}

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, x: i32, y: i32, w: i32, h: i32, color: u32) {
    for py in y.max(0)..(y + h).min(buf_h as i32) {
        for px in x.max(0)..(x + w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Movement State Machine Demo", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];

    let mut map = TileMap::new(MAP_W, MAP_H);
    for x in 0..MAP_W {
        map.set(TilePos(x, 0), false);
        map.set(TilePos(x, MAP_H - 1), false);
    }
    for y in 0..MAP_H {
        map.set(TilePos(0, y), false);
        map.set(TilePos(MAP_W - 1, y), false);
    }
    for y in 5..10 {
        map.set(TilePos(10, y), false);
    }

    let mut player = Player::new(tile_center(TilePos(3, 3)));
    let mut last_time = Instant::now();

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32();
        last_time = now;

        if window.is_key_pressed(Key::W, KeyRepeat::No) {
            player.handle_input(Direction::Up, &map);
        }
        if window.is_key_pressed(Key::S, KeyRepeat::No) {
            player.handle_input(Direction::Down, &map);
        }
        if window.is_key_pressed(Key::A, KeyRepeat::No) {
            player.handle_input(Direction::Left, &map);
        }
        if window.is_key_pressed(Key::D, KeyRepeat::No) {
            player.handle_input(Direction::Right, &map);
        }

        player.update(dt);

        for px in buffer.iter_mut() { *px = 0xFF000000; }

        // tile map
        for y in 0..MAP_H {
            for x in 0..MAP_W {
                let traversable = map.is_traversable(TilePos(x, y));
                let color = if traversable { 0xFF404040 } else { 0xFF808080 };
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          x * TILE_SIZE as i32, y * TILE_SIZE as i32,
                          TILE_SIZE as i32, TILE_SIZE as i32, color);
            }
        }

        // 画状态指示器(左上角)
        let state_color = match player.state {
            MoveState::Idle => 0xFF4040FF,
            MoveState::Moving { .. } => 0xFF40FF40,
            MoveState::Bumping { .. } => 0xFFFF4040,
        };
        draw_rect(&mut buffer, WIDTH, HEIGHT, 10, 10, 100, 20, state_color);

        // destination 高亮
        if let MoveState::Moving { destination, .. } = player.state {
            let tile = world_to_tile(destination);
            for offset in 0..4 {
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          tile.0 * TILE_SIZE as i32 + offset,
                          tile.1 * TILE_SIZE as i32 + offset,
                          TILE_SIZE as i32 - offset * 2, 1, 0xFFFFFF40);
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          tile.0 * TILE_SIZE as i32 + offset,
                          tile.1 * TILE_SIZE as i32 + TILE_SIZE as i32 - 1 - offset,
                          TILE_SIZE as i32 - offset * 2, 1, 0xFFFFFF40);
            }
        }

        // player
        let player_color = match player.state {
            MoveState::Bumping { .. } => 0xFFFF8080,  // 弹回时偏粉
            _ => 0xFFFF4040,
        };
        let px = player.pos.x as i32;
        let py = player.pos.y as i32;
        draw_rect(&mut buffer, WIDTH, HEIGHT, px - 8, py - 8, 16, 16, player_color);

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `enum MoveState` 三个变体,每个变体携带不同数据
- `match self.state` 模式匹配 + 数据解构
- `MoveState::Bumping { from, to, progress }` 在 update 中可变借用所有三个字段
- `if let MoveState::Moving { destination, .. } = player.state` 是简化匹配,只关心一种情况
- 撞墙的 Bumping 状态让角色有视觉反馈,体现状态机的扩展性

**Troubleshooting**:

- 撞墙时角色没动画 — 检查 `enter_bumping` 是否被调用,以及 Bumping 状态的 update 是否正确
- 弹回后角色位置偏移 — progress 累加时 dt 太大可能跳过 1.0,检查 `if new_progress >= 1.0` 在累加之后立即检查
- 状态指示器颜色不变 — match 表达式返回值,确保正确
