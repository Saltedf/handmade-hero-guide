
# Day 274 · 弹簧动态动画

> 今天的核心:**用弹簧物理方程驱动动画**。这比线性插值或简单缓动函数自然得多——弹簧会"过冲 + 振荡",像真实世界里有质量 + 弹性的物体。Casey 用它让角色"撞墙后弹回"、"走路时身体微弹"等动画感觉有重量。

## 0 · 为什么要有这一天

你昨天的动画有两类:sprite 切换(硬切) + 简单缓动(sin 振荡)。这两种都有局限:

- **sprite 切换**:每帧独立,没有"过渡"。看起来像早期动画片,流畅但缺少物理感
- **sin 振荡**:周期固定,幅度固定。走路是周期性的,但**碰撞、跳跃、攻击**这些事件不是周期性的——它们是"瞬态响应"

想象角色撞墙。真实世界里,撞墙后角色会"反弹回去",再因为惯性"过冲"一点,最后稳定。这个过程不是 sin 振荡(那是周期性的),也不是线性插值(那没有过冲),它是**弹簧被压缩后释放**——一个"瞬态的、衰减的、有弹性的"运动。

弹簧方程是:

```
F = -k * x - c * v
```

其中 `x` 是位移,`v` 是速度,`k` 是劲度系数(stiffness),`c` 是阻尼(damping)。这个方程描述一个有质量 + 弹性 + 阻尼的物理系统,它的解是**衰减振荡**(damped oscillation):

```
x(t) = A * e^(-γt) * cos(ωt + φ)
```

数学上看是 cos(指数衰减),物理上看是"先过冲再振荡几下稳定"。

工程上,我们不需要解微分方程,用 **Hooke 定律 + Euler 积分**模拟:

```
每帧:
    F = -k * (current - target) - c * velocity
    acceleration = F / mass
    velocity += acceleration * dt
    current += velocity * dt
```

调好 `k` 和 `c`,动画就自然有"弹性感"。

心理锚点:做完这个,你的角色撞墙 / 攻击 / 跳跃会有"过冲振荡"的真实感,而不是死板的线性移动。

## 2 · 心智模型

### 类比:汽车的悬挂系统

你开车过减速带。车轮撞上减速带瞬间被推上去(力的输入),但是车身不是瞬间跟着到位——车身通过**悬挂系统**(弹簧 + 减震器)连接车轮。

- 弹簧(stiffness k):让车身"想"回到平衡位置
- 减震器(damping c):消耗能量,防止车身一直振荡

如果只有弹簧没减震:车身上下颠簸不停(无阻尼振荡)。
如果只有减震没弹簧:车身永远爬不回原位(过阻尼)。
合适的弹簧 + 减震:车身上下颠一下,两三次振荡后稳定。

游戏里的弹簧动画就是这个模型:**目标位置是车轮的实际位置**(车轮跳上减速带),**当前值是车身位置**(跟着弹)。

### 严谨原理:Hooke 定律 + 阻尼

#### 物理模型

考虑一个质量为 `m` 的物体,挂在弹簧上:

- 弹簧力:`F_spring = -k * x`(x 是相对平衡位置的位移,k 是劲度系数)
- 阻尼力:`F_damp = -c * v`(v 是速度,c 是阻尼系数)
- 牛顿第二定律:`m * a = F_spring + F_damp`,即 `a = (-k * x - c * v) / m`

游戏里我们简化:`m = 1`,所以:

```
a = -k * (current - target) - c * velocity
v += a * dt
current += v * dt
```

注意 `(current - target)` 是相对目标的位移——目标是"平衡位置"。

#### Rust 实现

```rust
#[derive(Clone, Copy, Debug)]
struct Spring {
    value: f32,        // 当前值
    velocity: f32,     // 当前速度
    target: f32,       // 目标值(平衡点)
    stiffness: f32,    // 劲度系数 k
    damping: f32,      // 阻尼系数 c
}

impl Spring {
    fn new(initial: f32, stiffness: f32, damping: f32) -> Self {
        Self {
            value: initial,
            velocity: 0.0,
            target: initial,
            stiffness,
            damping,
        }
    }

    fn set_target(&mut self, target: f32) {
        self.target = target;
    }

    fn update(&mut self, dt: f32) {
        // Hooke + damping
        let force = -self.stiffness * (self.value - self.target) - self.damping * self.velocity;
        let acceleration = force;  // mass = 1
        self.velocity += acceleration * dt;
        self.value += self.velocity * dt;
    }
}
```

#### 参数调优

`stiffness`(k)和 `damping`(c)的搭配决定动画感觉:

| stiffness | damping | 行为 |
|---|---|---|
| 高(300+) | 0 | 高频无阻尼振荡(弹簧永不停止) |
| 高(300+) | 高(30+) | 快速到位,几乎不过冲(过阻尼) |
| 中(100) | 中(10) | 1-2 次过冲后稳定(欠阻尼,推荐) |
| 低(20) | 中(10) | 缓慢移动到目标(软弹) |
| 任意 | 0 | 永远振荡(纯无阻尼) |

游戏开发推荐:

- **走路 / 跑步的脚部摆动**:k=150, c=8(中等弹性)
- **撞墙的弹回**:k=200, c=12(快速弹性)
- **UI 元素出现**:k=300, c=20(快速但不过分)
- **角色受击的后退**:k=50, c=5(缓慢振荡,沉重感)

#### 临界阻尼

数学上,临界阻尼系数 `c_critical = 2 * sqrt(k * m)`。当 c 等于这个值时,系统"刚好不振荡"——最快达到平衡而不超过。

- `c < c_critical`:欠阻尼,会过冲 + 振荡(弹性感)
- `c = c_critical`:临界阻尼,最快稳定,不过冲
- `c > c_critical`:过阻尼,慢慢稳定(沉重感)

游戏动画通常用**欠阻尼**(c ≈ c_critical * 0.5-0.7),保留弹性感。

#### 半隐式 Euler(更稳定)

朴素 Euler 积分在大 dt 时可能"发散"(数值爆炸)。半隐式 Euler(symmetric Euler / symplectic Euler)更稳定:

```
v_new = v + a * dt          # 先更新速度
x_new = x + v_new * dt      # 用新速度更新位置(而不是旧速度)
```

差别只在顺序——先更新 v 再用 v_new。这个微小改动让能量近似守恒,长期模拟不会爆炸。

```rust
fn update(&mut self, dt: f32) {
    let force = -self.stiffness * (self.value - self.target) - self.damping * self.velocity;
    let acceleration = force;
    self.velocity += acceleration * dt;       // 先更新 v
    self.value += self.velocity * dt;         // 再用 v_new 更新 x
}
```

Casey 在 HH 用半隐式 Euler,因为游戏 dt 可能波动(卡顿),需要鲁棒性。

### Spring 在动画中的应用

#### 1. 位置过渡(取代线性插值)

```rust
struct Player {
    pos_x_spring: Spring,  // 取代 pos_x: f32
    pos_y_spring: Spring,
    // ...
}

// 移动到目标
player.pos_x_spring.set_target(target_x);
player.pos_y_spring.set_target(target_y);

// 每帧更新
player.pos_x_spring.update(dt);
player.pos_y_spring.update(dt);
let current_x = player.pos_x_spring.value;
let current_y = player.pos_y_spring.value;
```

效果:角色不是匀速移到目标,而是"加速冲过去 + 过冲 + 振荡稳定"。视觉上有"重量感"。

#### 2. 缩放动画(撞墙压扁)

```rust
struct Player {
    scale_x: Spring,  // 水平缩放,1.0 = 正常
    scale_y: Spring,
}

// 撞墙瞬间,水平压扁
player.scale_x.set_target(0.7);
player.scale_y.set_target(1.3);

// 几帧后恢复
player.scale_x.set_target(1.0);
player.scale_y.set_target(1.0);
```

效果:撞墙时角色"压扁"(scale_x=0.7),然后弹回过冲到 1.1,最后稳定到 1.0。这种 squash-and-stretch 是 Disney 12 动画原则之一。

#### 3. 旋转动画(头部转向)

```rust
struct Player {
    head_angle: Spring,  // 弧度
}

// 看向新方向
player.head_angle.set_target(target_angle);
```

效果:头部转动时有"惯性",过冲一点再回稳。比硬切换自然得多。

### 弹簧 vs 缓动函数

| 方式 | 实时改目标 | 物理感 | 实现难度 |
|---|---|---|---|
| Linear lerp | 可以 | 无 | 极简 |
| Easing(贝塞尔) | 不可以(曲线预先决定) | 弱 | 中 |
| Spring(今天) | 可以 | 强 | 中 |

easing 函数(tween)的弱点:**目标改变时要从头开始**(重置 t=0,从头算 ease 曲线)。spring 没这个问题——目标一改,弹簧立即朝新目标拉,保留当前速度。

这就是为什么现代 UI(iOS / macOS / Web CSS `transition` 都用 spring 物理而非缓动函数——更自然,响应更灵敏。

#### Squash and Stretch

Disney 12 动画原则的前两条:

1. **Squash**:物体受冲击时压扁(撞地时球变扁)
2. **Stretch**:物体加速时拉长(快速移动时角色拉长)

游戏里用 spring 控制 scale 实现:撞地瞬间 scale_x 增大、scale_y 减小,然后弹簧回弹。

### 3.2 · 🎨 图形学视角

弹簧物理在图形学是 **particle system** 的基础。粒子系统的核心循环:

```
for each particle:
    F = spring_force + damping + external_force
    a = F / m
    v += a * dt
    p += v * dt
```

这就是 spring 方程的扩展(加了 external_force)。粒子系统模拟火焰、烟雾、爆炸、雨水。

#### Verlet 积分(更高级)

Euler 积分有数值耗散。Verlet 积分更精确:

```
x_new = 2 * x - x_prev + a * dt^2
x_prev = x
x = x_new
```

不需要显式存 velocity——通过当前位置 + 上次位置隐式表达。Verlet 在布料模拟、绳索模拟常用。

Casey 用 Euler,够教学用。性能 / 精度要求高的场景可以升级到 Verlet 或 RK4。

### 3.5 · 数学:常微分方程(ODE)

弹簧方程 `m * x'' = -k * x - c * x'` 是一个二阶线性 ODE。它的解是:

```
x(t) = A * e^(-γt) * cos(ωt + φ)
```

其中:

- `γ = c / (2m)` 是衰减率
- `ω = sqrt(k/m - γ^2)` 是振荡频率
- A, φ 是初始条件决定的常数

这告诉我们弹簧系统的几个特性:

1. **振荡频率 ω** 由 `k / m` 决定(更硬的弹簧振荡更快)
2. **衰减率 γ** 由 `c / (2m)` 决定(更大阻尼衰减更快)
3. **临界阻尼**:`γ = ω0 = sqrt(k/m)`,即 `c = 2 * sqrt(k * m)`

游戏开发者不用记公式,只需调 k 和 c 直到看着对。但理解数学能让你调参更快。

### 不同积分方法对比

| 方法 | 精度 | 稳定性 | 复杂度 | 用途 |
|---|---|---|---|---|
| 显式 Euler | O(dt) | 差(能量泄漏) | 极简 | 教学 |

### Spring 的不同变种

| 变种 | 公式 |
|---|---|
| 简单 spring | F = -kx - cv |
| 受迫 spring | F = -kx - cv + F_ext(加外力) |
| 非线性 spring | F = -k*x^3(硬弹簧) |
| 角度 spring | F = -k*θ(旋转) |
| 双 spring | 两个 spring 串联(更柔) |

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 spring 动画比缓动函数(tween)更适合 UI 交互?给出至少 3 个理由。

**参考解答**:
1. **响应目标改变**:用户中途改主意(从 A 移到 B,中途改到 C),spring 立即朝 C 拉,保留当前速度,过渡平滑。tween 必须重置(从头开始 ease),会跳变
2. **物理感**:spring 自然有"过冲 + 振荡",模仿真实物体的惯性。tween 是预定义曲线,过冲是模拟的,不如 spring 自然
3. **参数直观**:spring 的 stiffness 和 damping 物理意义清晰,设计师容易调。tween 的贝塞尔控制点抽象,需要经验
4. **可组合**:多个 spring 同时驱动(位置 + 旋转 + 缩放)互相独立,代码清晰。tween 的多个属性同步要小心
5. **帧率独立**:spring 用 dt 数值积分,任意帧率稳定。tween 用归一化 t(0-1),需要计算进度,中间打断麻烦
6. **状态保留**:spring 隐式记住 velocity,即使 update 暂停,恢复后速度仍在。tween 的进度可能丢失

### Lv2 · 动手实践

**题**:实现 `Spring` struct + `update(dt)` 函数,用半隐式 Euler 积分。

测试:

- 初始 value=0, target=10, stiffness=100, damping=10
- 模拟 5 秒,每步 0.01 秒
- 输出每 0.5 秒的 value,应该看到"过冲到 ~11,然后稳定到 10"

完成标准:看到 value 过冲然后稳定到 10.0 附近。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug)]
struct Spring {
    value: f32,
    velocity: f32,
    target: f32,
    stiffness: f32,
    damping: f32,
}

impl Spring {
    fn new(initial: f32, stiffness: f32, damping: f32) -> Self {
        Self {
            value: initial,
            velocity: 0.0,
            target: initial,
            stiffness,
            damping,
        }
    }

    fn set_target(&mut self, target: f32) {
        self.target = target;
    }

    fn update(&mut self, dt: f32) {
        // Hooke + damping,半隐式 Euler
        let force = -self.stiffness * (self.value - self.target) - self.damping * self.velocity;
        let acceleration = force;  // mass = 1
        self.velocity += acceleration * dt;       // 先更新速度
        self.value += self.velocity * dt;         // 用新速度更新位置
    }
}

fn main() {
    let mut spring = Spring::new(0.0, 100.0, 10.0);
    spring.set_target(10.0);

    let dt = 0.01;
    let mut elapsed = 0.0_f32;

    println!("t, value, velocity");
    for step in 0..500 {  // 5 秒
        spring.update(dt);
        elapsed += dt;

        if step % 50 == 0 {
            println!("{:.2}, {:.4}, {:.4}", elapsed, spring.value, spring.velocity);
        }
    }
    // 应该看到:
    // 0.50, ~11.0, ~-1.0  (过冲,然后开始反向)
    // 1.00, ~9.5,  ~0.5   (反向过冲)
    // 2.00, ~10.0, ~0.0   (接近稳定)
    // 5.00, ~10.0, ~0.0   (稳定)
}
```

**每行解释**:
- `stiffness=100, damping=10` 是中等弹性参数,会过冲约 10%
- 临界阻尼 c = 2*sqrt(k*m) = 2*sqrt(100*1) = 20,我们的 c=10 < 20 是欠阻尼
- 半隐式 Euler:先更新 v 再用 v_new 更新 x,这个顺序让能量守恒更好
- 模拟 500 步(5 秒)足够看到稳定

### Lv3 · 迁移设计

**题**:实现一个 **Spring2D**(2D 位置 spring),驱动角色从一点平滑弹到另一点。

要求:

- value: Vec2, velocity: Vec2, target: Vec2
- update(dt) 同时更新 x 和 y

### 完整可跑:spring 驱动的角色动画

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, KeyRepeat, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const TILE_SIZE: f32 = 32.0;

#[derive(Clone, Copy, Debug)]
struct Spring {
    value: f32,
    velocity: f32,
    target: f32,
    stiffness: f32,
    damping: f32,
}

impl Spring {
    fn new(initial: f32, stiffness: f32, damping: f32) -> Self {
        Self {
            value: initial,
            velocity: 0.0,
            target: initial,
            stiffness,
            damping,
        }
    }
    fn set_target(&mut self, target: f32) {
        self.target = target;
    }
    fn update(&mut self, dt: f32) {
        let force = -self.stiffness * (self.value - self.target) - self.damping * self.velocity;
        let acceleration = force;
        self.velocity += acceleration * dt;
        self.value += self.velocity * dt;
    }
}

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
}

struct Player {
    pos_x: Spring,
    pos_y: Spring,
    scale_x: Spring,  // 撞墙时压扁
    scale_y: Spring,
    bumping: bool,
}

impl Player {
    fn new(start: Vec2) -> Self {
        Self {
            pos_x: Spring::new(start.x, 150.0, 15.0),
            pos_y: Spring::new(start.y, 150.0, 15.0),
            scale_x: Spring::new(1.0, 200.0, 12.0),
            scale_y: Spring::new(1.0, 200.0, 12.0),
            bumping: false,
        }
    }

    fn move_to(&mut self, target: Vec2) {
        self.pos_x.set_target(target.x);
        self.pos_y.set_target(target.y);
    }

    fn bump(&mut self) {
        // 撞墙:水平压扁,垂直拉长(squash and stretch)
        self.scale_x.set_target(0.7);
        self.scale_y.set_target(1.3);
        self.bumping = true;
    }

    fn unbump(&mut self) {
        // 恢复正常
        self.scale_x.set_target(1.0);
        self.scale_y.set_target(1.0);
        self.bumping = false;
    }

    fn update(&mut self, dt: f32) {
        self.pos_x.update(dt);
        self.pos_y.update(dt);
        self.scale_x.update(dt);
        self.scale_y.update(dt);
    }

    fn current_pos(&self) -> Vec2 {
        Vec2::new(self.pos_x.value, self.pos_y.value)
    }
}

fn draw_player_scaled(buf: &mut [u32], buf_w: usize, buf_h: usize,
                      cx: i32, cy: i32, scale_x: f32, scale_y: f32) {
    let base_size = 24.0;
    let w = (base_size * scale_x) as i32;
    let h = (base_size * scale_y) as i32;

    let color = 0xFFFF4040;
    for py in (cy - h/2).max(0)..(cy + h/2).min(buf_h as i32) {
        for px in (cx - w/2).max(0)..(cx + w/2).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }

    // 画眼睛(随 scale 变化)
    let eye_color = 0xFFFFFFFF;
    let eye_size = 3;
    let eye_y = cy - h/4;
    let eye_l_x = cx - w/4;
    let eye_r_x = cx + w/4;
    for py in eye_y-eye_size/2..eye_y+eye_size/2 {
        for px in eye_l_x-eye_size/2..eye_l_x+eye_size/2 {
            if px >= 0 && (px as usize) < buf_w && py >= 0 && (py as usize) < buf_h {
                buf[(py as usize) * buf_w + (px as usize)] = eye_color;
            }
        }
    }
    for py in eye_y-eye_size/2..eye_y+eye_size/2 {
        for px in eye_r_x-eye_size/2..eye_r_x+eye_size/2 {
            if px >= 0 && (px as usize) < buf_w && py >= 0 && (py as usize) < buf_h {
                buf[(py as usize) * buf_w + (px as usize)] = eye_color;
            }
        }
    }
}

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, x: i32, y: i32, w: i32, h: i32, color: u32) {
    for py in y.max(0)..(y + h).min(buf_h as i32) {
        for px in x.max(0)..(x + w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Spring Animation Demo", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();

    // 多个 tile 中心(玩家可以跳到这些位置)
    let targets = vec![
        Vec2::new(100.0, 300.0),
        Vec2::new(250.0, 200.0),
        Vec2::new(400.0, 350.0),
        Vec2::new(550.0, 250.0),
        Vec2::new(700.0, 300.0),
    ];
    let mut current_target = 0;
    let mut player = Player::new(targets[0]);
    let mut bump_timer = 0.0_f32;

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32().min(0.05);  // clamp dt 防卡顿
        last_time = now;

        // 输入:按 Space 跳到下一个目标
        if window.is_key_pressed(Key::Space, KeyRepeat::No) {
            current_target = (current_target + 1) % targets.len();
            player.move_to(targets[current_target]);
            println!("Move to target {}", current_target);
        }

        // 按 B 模拟撞墙
        if window.is_key_pressed(Key::B, KeyRepeat::No) {
            player.bump();
            bump_timer = 0.2;  // 200ms 后 unbump
            println!("Bump! (squash)");
        }

        // bump 计时
        if bump_timer > 0.0 {
            bump_timer -= dt;
            if bump_timer <= 0.0 {
                player.unbump();
            }
        }

        // 更新
        player.update(dt);

        // 渲染
        for px in buffer.iter_mut() { *px = 0xFF101010; }

        // 画目标点
        for (i, t) in targets.iter().enumerate() {
            let color = if i == current_target { 0xFFFFFF40 } else { 0xFF404040 };
            draw_rect(&mut buffer, WIDTH, HEIGHT,
                      t.x as i32 - 16, t.y as i32 - 16, 32, 32, color);
        }

        // 画 player(spring 驱动位置和 scale)
        let pos = player.current_pos();
        draw_player_scaled(&mut buffer, WIDTH, HEIGHT,
                           pos.x as i32, pos.y as i32,
                           player.scale_x.value, player.scale_y.value);

        // 显示 spring 状态
        if player.bumping {
            draw_rect(&mut buffer, WIDTH, HEIGHT, 10, 10, 200, 20, 0xFFFF4040);
        }

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `Spring` 是 Copy 类型,4 个 f32 = 16 字节,可以高效存储
- `dt.min(0.05)` clamp 防止卡顿时 dt 过大导致 spring 发散
- `bump_timer` 用 dt 倒计时,2D 状态机的简化版
- `player.scale_x.value` 直接读取 spring 当前值渲染
- 多个 spring 并存:位置 / 缩放各自独立,可单独调参
