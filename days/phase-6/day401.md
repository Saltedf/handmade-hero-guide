debug 思路:

1. **隔离**:用最简单场景复现 bug(1 个光源 + 1 个球),排除不相关变量
2. **对照**:CPU 测试床 vs GPU 实现,差异 = bug 在 GPU 实现或数据传输
3. **二分**:逐步注释 / 启用代码,定位 bug 引入位置
4. **可视化**:每个中间结果用 debug 视图显示,人眼对比找异常

### 为什么"组件正确但集成错"最难调

让我深度剖析。新人写代码遇到 bug,直觉是"我哪里写错了"——单点 bug。但系统集成 bug 不是单点:

- **Bug 在交互**:每个组件 API 都对,但组件 A 的输出格式和组件 B 的预期格式不一致。
- **Bug 在隐式假设**:组件 A 假设颜色是 HDR(>1.0),组件 B 假设是 LDR(0-1)。两边都"对",但合起来错。
- **Bug 在数据流**:GPU 纹理传到下一个 pass 时被 sRGB 转换、被 mipmap 缩小、被 wrap mode 改变,任一步都可能引入偏差。

工业案例:

- **Ariane 5 火箭爆炸(1996)**:惯性导航软件从 Ariane 4 移植,组件正确,但 64-bit 浮点转 16-bit 整数溢出,火箭自毁。损失 5 亿美元。
- **Therac-25 医疗放射机(1980s)**:多线程 race condition,组件正确但并发错,导致 6 人过量辐射。
- **Knight Capital 4.5 亿美元损失(2012)**:旧代码在新部署里被激活,组件正确但集成错。

今天的 4 个 bug 都是这种类型——每个组件(AO、GI、Phong、alpha 混合)单独正确,但拼起来出错。**学会调这种 bug** 让你处理任何大型软件的集成问题都从容。

## 2 · 心智模型

### 2.1 类比:医生诊断

医生看病流程:

1. **症状**:病人说"头疼"
2. **检查**:量体温、验血、CT
3. **诊断**:可能是感冒、可能是脑瘤、可能是中暑
4. **治疗**:对症下药
5. **复诊**:看是否好转;不好转重新检查

调试完全一样:

1. **症状**:画面角落亮斑
2. **检查**:RenderDoc 抓帧、CPU 测试床
3. **诊断**:可能是纹理 wrap / 格式 / 公式 / 算法
4. **修复**:改代码
5. **验证**:重跑看是否对;不对回到第 2 步

**关键纪律**:**假设驱动调试**(Hypothesis-Driven Debugging)。每一步对应一个具体假设:

- "我假设 bug 在纹理 wrap"→ 改 wrap 测试
- "我假设 bug 在数值精度"→ 换 float64 测试
- "我假设 bug 在算法"→ 跑 CPU 测试床

**不要无目的试**——改了一堆东西看哪个 work,那是浪费。**每个改动对应一个假设**,假设错就排除一个可能。

工业级的"医生"级 debug 工程师,通常**先列假设清单**,按"最可能"和"最容易验证"排序,逐个排除。

### 2.2 二分定位:复杂 bug 的核心方法

复杂 bug 的核心方法:**二分定位**(bisection)。

**版本二分**(`git bisect`):

```bash
# 找到引入 bug 的 commit
git bisect start
git bisect bad              # 当前版本有 bug
git bisect good v1.0        # v1.0 时没 bug
# git 自动 checkout 中间 commit,你测试
git bisect good  # 或 bad
# 重复 ~log2(N) 次,定位到具体 commit
git bisect reset
```

**代码二分**(逐步注释):

```rust
// 假设渲染管线有 10 步
fn render() {
    step1();
    step2();
    step3();
    // ...
    step10();
}

// bug 出现,逐步注释
fn render() {
    step1();
    // step2();  // 注释
    step3();
    // ...
}

// 如果 bug 消失,bug 在 step2
// 如果还在,继续注释 step3...
```

**中间结果可视化**:每步后输出 debug 视图,人眼对比,定位异常:

```rust
fn render_with_debug(views: &mut DebugViews) {
    let s1 = step1();
    views.show("step1", &s1);

    let s2 = step2(&s1);
    views.show("step2", &s2);

    // ... 异常立即发现
}
```

Casey 今天用**中间结果可视化** + **CPU vs GPU 对比** 双管齐下,把 4 个 bug 都定位到具体步骤。

### 2.3 CPU 测试床作 ground truth

```rust
// CPU 测试床算出 ground truth
let cpu_result = cpu_testbed::compute_lighting(&scene);

// GPU 渲染
let gpu_result = gpu_render(&scene);

// 对比
for pixel in 0..pixel_count {
    let cpu_color = cpu_result[pixel];
    let gpu_color = gpu_result[pixel];
    let diff = (cpu_color - gpu_color).abs();
    assert!(diff < 0.01, "pixel {} mismatch: CPU {:?} vs GPU {:?}",
        pixel, cpu_color, gpu_color);
}
```

如果 CPU 和 GPU 一致,算法对。如果差异大,**算法有 bug**(在 GPU 或 CPU 实现)。

**为什么 CPU 测试床强大**:

- CPU 是**透明**的——Rust `println!` 直接看变量
- GPU 是**黑盒**——你看不到 fragment shader 的中间变量
- CPU 上写**完整算法**(无 GPU 优化),容易理解
- CPU 测试床用**任意精度**(f64),无 GPU 的精度损失

工业实践:**任何严肃的 GPU 算法都应该有 CPU 参考实现**。WebGPU / Vulkan 规范都要求 vendor 提供 CPU reference 用于验证。

### 2.4 Debug 视图:可视化每步

每个 pass 后输出可视化:

```glsl
// Pass 1: G-buffer albedo
frag = texture(g_albedo, v_uv);

// Pass 2: Phong only
frag = vec4(phong_color, 1.0);

// Pass 3: GI only
frag = vec4(gi_color, 1.0);

// Pass 4: AO only
frag = vec4(vec3(ao), 1.0);

// Pass 5: final
frag = vec4(final_color, 1.0);
```

按键切换显示哪个 pass。**人眼对比**每步,异常立即发现。

**Debug 视图设计原则**:

- **单一变量**:每个视图只显示一个量(albedo、normal、AO 各一)
- **可视化映射**:法线 → RGB(每个分量 [-1,1] 映射 [0,1]),标量 → 灰度
- **异常高亮**:NaN 显示亮红,Inf 显示亮黄,负数显示蓝色
- **范围映射**:HDR 值(>1)用 tone map 或 mod 1 显示

### 2.5 4 个 bug 的具体修复

**Bug 1:纹理 wrap mode**

OpenGL 默认 `GL_REPEAT`——UV > 1 时环绕到对面。体素网格的边缘像素采样时,如果 UV 略微超出 [0, 1],会"穿过"到对面取值。

修法:

```rust
let sampler = SamplerBehavior {
    wrap_function: (
        SamplerWrapFunction::ClampToEdge,
        SamplerWrapFunction::ClampToEdge,
        SamplerWrapFunction::ClampToEdge,
    ),
    ..Default::default()
};
```

`ClampToEdge`:UV 越界取边缘值,不环绕。

**Bug 2:纹理格式**

`RGBA8`(8 位每通道)存浮点颜色,精度只有 256 等级。光照计算后颜色可能 > 1(HDR),8 位会 clamp 到 1。多次 pass 累积精度损失,最终颜色严重失真。

修法:`RGBA16F` 或 `RGBA32F`。

```rust
// 错(RGBA8):
let albedo_tex = Texture2d::empty_with_format(
    &display, UncompressedFloatFormat::U8U8U8U8, ...)?;

// 对(RGBA32F):
let albedo_tex = Texture2d::empty_with_format(
    &display, UncompressedFloatFormat::F32F32F32F32, ...)?;
```

**Bug 3:Alpha 公式不一致**

GPU 端用 premul alpha 公式,CPU 测试床用 straight。两者数值不一致。

修法:统一为一种。Casey 选 premul(更现代)。

```rust
// 之前: straight
let final = top * top.a + bot * bot.a * (1 - top.a);

// 改: premul (假设 top 和 bot 已经预乘)
let final = top + bot * (1 - top.a);
```

**Bug 4:V-cycle 发散**

Jacobi 松弛因子 ω 决定收敛速度。如果 ω > 2/λ_max(λ_max 是矩阵最大特征值),迭代发散。

对 3D Laplacian,λ_max ≈ 6(6 邻居),所以 ω 应 ≤ 2/6 ≈ 0.33。

Casey 试 0.7 → 发散;0.5 → 边缘稳定;0.3 → 稳定但慢。选 0.5。

```rust
new_value = center * (1.0 - omega) + avg_neighbors * omega;
// omega = 0.5:稳定
```

**收敛性的数学**:

Jacobi 迭代矩阵 G = I - ωD⁻¹A(D 是 A 的对角部分)。收敛 ⟺ G 的谱半径 ρ(G) < 1。

对 3D Poisson(7 点 stencil),λ_max = 6 - 2cos(π/n) - 2cos(π/n) - 2cos(π/n) ≈ 6(大 n 时)。所以 ω < 2/6 ≈ 0.33 严格收敛。Casey 用 0.5 是"边缘稳定"——通常 work 但极端场景可能发散。

工业级用 **Gauss-Seidel**(比 Jacobi 快 2 倍)或 **Conjugate Gradient**(超快,几步收敛)。

### 3.2 · 🎨 图形学视角

**Debug visualization 经验法则**:

- 颜色编码:用法线 → RGB,标量 → 灰度
- 范围映射:`(value - min) / (max - min)` 到 [0, 1]
- 异常值:NaN 显示亮红,Inf 显示亮黄

**GLSL debug 函数**:

```glsl
vec3 debug_scalar(float v) {
    return vec3(v, v, v);  // 灰度
}

vec3 debug_normal(vec3 n) {
    return n * 0.5 + 0.5;  // [-1,1] → [0,1]
}

vec3 debug_range(float v, float min_v, float max_v) {
    float t = clamp((v - min_v) / (max_v - min_v), 0.0, 1.0);
    return vec3(t, t, t);
}

vec3 debug_nan(vec3 c) {
    if (any(isnan(c))) return vec3(1.0, 0.0, 0.0);  // 红 = NaN
    if (any(isinf(c))) return vec3(1.0, 1.0, 0.0);  // 黄 = Inf
    return c;
}

// 伪彩色:用 HSV 色环映射角度
vec3 debug_angle(float a) {
    float h = mod(a / (2.0 * 3.14159), 1.0);
    return hsv2rgb(vec3(h, 1.0, 1.0));
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 CPU 测试床对 GPU 调试至关重要?

**参考解答**:

GPU 是**黑盒**——你看不到 fragment shader 的中间变量。CPU 是**透明**——Rust `println!` 直接看。

CPU 测试床作为 **ground truth**:

1. CPU 算出"正确"结果(假设算法实现正确)
2. GPU 渲染"实际"结果
3. 对比两者差异,差异 = GPU bug

没有 CPU 测试床,你只能"猜"GPU 出错的位置。有了 CPU 测试床,**直接定位**——某像素 CPU 算 0.5,GPU 算 0.8,差异在 GPU 实现。

### Lv2 · 动手实践

**题**:在 Day 399 测试床加"光照对比"功能——给定 CPU 结果和 GPU 结果(预存),计算每像素差异,打印最大差异位置。

**参考解答**:

```rust
fn compare_results(cpu: &[[f32; 4]], gpu: &[[f32; 4]], threshold: f32) {
    let mut max_diff = 0.0;
    let mut max_idx = 0;
    for (i, (c, g)) in cpu.iter().zip(gpu.iter()).enumerate() {
        let diff = (c[0] - g[0]).abs().max(
                  (c[1] - g[1]).abs()).max(
                  (c[2] - g[2]).abs());
        if diff > max_diff {
            max_diff = diff;
            max_idx = i;
        }
    }
    if max_diff > threshold {
        eprintln!("FAIL: max diff {:.3} at pixel {}", max_diff, max_idx);
        eprintln!("  CPU: {:?}", cpu[max_idx]);
        eprintln!("  GPU: {:?}", gpu[max_idx]);
    } else {
        println!("PASS: max diff {:.3}", max_diff);
    }
}

// 更完整的版本:输出统计 + 差异热图
fn compare_full(
    cpu: &[f32], gpu: &[f32], width: usize, height: usize,
    threshold: f32,
) {
    use std::fs::File;
    use std::io::Write;

    assert_eq!(cpu.len(), gpu.len());
    let n = cpu.len();

    // 计算差异统计
    let mut diffs: Vec<f32> = (0..n)
        .map(|i| (cpu[i] - gpu[i]).abs())
        .collect();
    diffs.sort_by(|a, b| a.partial_cmp(b).unwrap());

    let mean = diffs.iter().sum::<f32>() / n as f32;
    let median = diffs[n / 2];
    let p95 = diffs[(n as f32 * 0.95) as usize];
    let p99 = diffs[(n as f32 * 0.99) as usize];
    let max = diffs[n - 1];

    println!("Diff stats:");
    println!("  mean   = {:.6}", mean);
    println!("  median = {:.6}", median);
    println!("  p95    = {:.6}", p95);
    println!("  p99    = {:.6}", p99);
    println!("  max    = {:.6}", max);

    if max > threshold {
        // 输出差异热图(PGM 格式)
        let mut f = File::create("diff_heatmap.pgm").unwrap();
        writeln!(f, "P2\n{} {}", width, height).unwrap();
        writeln!(f, "255").unwrap();
        for y in 0..height {
            for x in 0..width {
                let i = y * width + x;
                let d = (cpu[i] - gpu[i]).abs();
                let v = (d * 255.0).min(255.0) as u32;
                write!(f, "{} ", v).unwrap();
            }
            writeln!(f).unwrap();
        }
        eprintln!("Diff heatmap written to diff_heatmap.pgm");
    }
}
```

### Lv3 · 迁移设计

**题**:CPU 测试床思路迁移到**网络协议实现**——你写了 TCP 栈,如何验证正确?

需求:

- 用 Linux 内置 TCP 作为 reference(标准实现)
- 你的实现 vs Linux,对比行为
- 边界条件(丢包、重传、乱序)用 netem / tc 模拟

设计文档:

```rust
struct TcpTestbed {
    /// Linux TCP socket(作 reference)
    reference_socket: std::net::TcpStream,
    /// 你的 TCP 实现
    my_stack: MyTcpStack,
    /// 网络模拟器(丢包、延迟)
    netem: NetEmConfig,
}

impl TcpTestbed {
    /// 测试:发送 N 字节,对比收到的数据 + 行为(ACK 时序、重传)
    fn test_send_receive(&mut self, data: &[u8]) -> TestResult {
        let ref_start = Instant::now();
        self.reference_socket.write_all(data).unwrap();
        let ref_received = self.read_reference();
        let ref_time = ref_start.elapsed();

        let my_start = Instant::now();
        self.my_stack.send(data);
        let my_received = self.my_stack.recv_all();
        let my_time = my_start.elapsed();

        TestResult {
            data_match: ref_received == my_received,
            ref_time,
            my_time,
            // 对比时序(ACK 时机、重传次数)
            ref_acks: self.reference_ack_count(),
            my_acks: self.my_stack.ack_count(),
        }
    }
}
```

写出完整测试方案,包括 5 个边界 case:

1. 完美网络(0 丢包)
2. 1% 随机丢包
3. 重传场景(small packet window)
4. Out-of-order(包乱序到达)
5. Connection establishment(handshake)

use glam::Vec3;

/// 数值异常检测
pub fn check_finite(v: Vec3, label: &str) {
    if v.x.is_nan() || v.y.is_nan() || v.z.is_nan() {
        panic!("NaN in {}: {:?}", label, v);
    }
    if v.x.is_infinite() || v.y.is_infinite() || v.z.is_infinite() {
        panic!("Inf in {}: {:?}", label, v);
    }
}

/// CPU vs GPU 对比
pub fn diff_cpu_gpu(cpu: &[f32], gpu: &[f32], threshold: f32) -> bool {
    assert_eq!(cpu.len(), gpu.len());
    let mut max_diff = 0.0f32;
    let mut max_idx = 0;
    for (i, (c, g)) in cpu.iter().zip(gpu.iter()).enumerate() {
        let d = (c - g).abs();
        if d > max_diff {
            max_diff = d;
            max_idx = i;
        }
    }
    if max_diff > threshold {
        eprintln!("Diff: max {:.4} at idx {}", max_diff, max_idx);
        eprintln!("  CPU: {}", cpu[max_idx]);
        eprintln!("  GPU: {}", gpu[max_idx]);
        false
    } else {
        println!("OK: max diff {:.4}", max_diff);
        true
    }
}

/// Debug 视图枚举
#[derive(Copy, Clone)]
pub enum DebugView {
    Final,
    Albedo,
    Normal,
    Depth,
    Phong,
    GI,
    AO,
}

pub fn debug_view_to_str(v: DebugView) -> &'static str {
    match v {
        DebugView::Final => "Final",
        DebugView::Albedo => "Albedo",
        DebugView::Normal => "Normal",
        DebugView::Depth => "Depth",
        DebugView::Phong => "Phong only",
        DebugView::GI => "GI only",
        DebugView::AO => "AO only",
    }
}

fn main() {
    // 模拟 debug session
    let cpu_results = vec![0.5f32; 100];
    let mut gpu_results = vec![0.5f32; 100];
    gpu_results[42] = 0.8;  // 模拟 bug

    if !diff_cpu_gpu(&cpu_results, &gpu_results, 0.01) {
        println!("Bug detected, use debug view to investigate");
    }

    // 检查数值
    let v = Vec3::new(1.0, 2.0, 3.0);
    check_finite(v, "test vector");
    println!("Vector OK: {:?}", v);

    // Debug 视图
    let view = DebugView::AO;
    println!("Current view: {}", debug_view_to_str(view));
}
