# Day 381 · 双 pass 深度剥离

> 透明物体在屏幕上画完之后,后面的物体**透过来**应该能看到——但 GPU 的 z-buffer 只会"画到第一个不透明像素为止"。Casey 今天引入一个新算法:**深度剥离**(depth peeling),用来正确渲染半透明物体。

## 0 · 为什么要有这一天

你已经会做不透明 3D 渲染了:每一个像素写颜色的时候,把它的 z 和 z-buffer 里已有的 z 比,新 z 离相机更近才覆盖。**这保证了不透明物体无论按什么顺序画,结果都对**。

可一旦你想画**玻璃窗**、**水面**、**精灵粒子**、**角色轮廓的描边**(发光体)——这些**半透明**物体,事情就崩了。半透明不能用 z-buffer 那一套,因为:

1. 半透明的"混合公式"是 `final = src * α + dst * (1 - α)`(`α` 是透明度),这个公式**不交换**——`先 A 后 B` 和 `先 B 后 A` 结果不同。
2. 半透明物体不能"直接覆盖" z-buffer,否则后面的物体(透过半透明看到的)**根本不会画**。
3. 半透明物体如果**自己重叠**(比如玻璃窗的玻璃前后两面),需要画两次。

经典做法是**画家算法**(Painter's algorithm):把所有半透明物体**按距离排序,从远到近画**。这在 2D 还行,在 3D 完全不可靠:

- 两个三角形相互穿插(像剪刀交叉)时,**没有正确排序**
- 一帧里几百个粒子,**排序本身就有开销**
- 排序是基于物体中心的,不是基于像素的,**局部仍然会错**

**深度剥离**(Everitt 2001)提出了一个聪明的方案:**不用排序,用多次渲染 pass**。每一"层"渲染找到当前"最前面还没被画过"的那层像素,下一"层"用上一层的深度作为"基准",找"第二前面的",依此类推。最后把这些层**按顺序合成**(back-to-front)。

今天 Casey 实现深度剥离的**最简单 2-pass 版本**:第一个 pass 渲染最近一层(其实就是普通不透明 pass),第二个 pass 用"比第一个 pass 更远"作为深度条件,渲染**第二层**。今天你看到的画面是:**透过玻璃能看见玻璃后面的世界**——而且**没有排序问题**。

心理锚点:看完今天,你能(1)向人解释为什么半透明渲染不能直接用 z-buffer;(2)在白板上手画 2-pass 深度剥离的步骤;(3)读懂 GLSL 里 `gl_FragCoord.z` 的语义;(4)在 Rust 里写一个最小可跑的 2-pass 深度剥离 demo。

## 2 · 心智模型

### 类比:剥洋葱

想象你有一个**透明洋葱**:它的每一层皮都是半透明的,叠在一起你能看到最里面的芯。z-buffer 渲染就像你拿一把刀把洋葱**一刀切**——你只能看到最外面那一层皮。要想看到第二层,你得**把第一层皮剥掉**(用它的深度信息作为"不能再画的位置"),然后再切一刀,看到第二层。再剥第二层,看到第三层……

**深度剥离**就是这个过程的 GPU 实现:

- **Pass 1**:正常渲染。z-buffer 给你最近一层(第一层皮)。
- **Pass 2**:用第一层的深度作为"基准",**只画比基准更远的像素**,这样你看到的是"第二层皮"。
- **Pass 3**(合成):把所有层**从后往前合成**(α-blend),最终颜色就是洋葱的真实样子。

"剥离"(peel)这个词很形象——每次渲染都把"当前最前面的"那层拿掉,露出下面一层。

### 严谨原理:为什么 z-buffer 处理不了半透明

我们用代码写明这件事。普通 z-buffer 测试的 fragment shader 流程是:

```
对每个像素:
    if (fragment.z < zbuffer[pixel]) {   // 比已存深度更近
        zbuffer[pixel] = fragment.z      // 更新深度
        colorbuffer[pixel] = fragment.color  // 直接覆盖颜色
    }
```

这里"直接覆盖颜色"是关键:它假设**新像素完全取代旧像素**,这是不透明物体的语义。

半透明物体的语义不同:新像素**和**旧像素**混合**:

```
final = src.rgb * src.a + dst.rgb * (1 - src.a)
```

这里 `src` 是新 fragment 的颜色和 alpha,`dst` 是当前 framebuffer 里已存在的颜色。

**问题来了**:这个公式**不满足交换律**。

举例:`src = (1,0,0,0.5)`(红色 50% 透明),`dst = (0,0,1)`(蓝色)。

- 先红后蓝:`dst = 0.5*红 + 0.5*蓝 = (0.5, 0, 0.5)`(紫)
- 先蓝后红:`src=蓝, dst=红`,蓝色 alpha=1(假设不透明),`dst = 1.0*蓝 + 0.0*红 = (0,0,1)`(蓝)

结果完全不同!这就是为什么半透明物体**必须按顺序画**。

z-buffer 不会替你排序——它只看 z。所以**画家算法**(按物体中心距离排序)是个 hack,对简单场景够用,对复杂场景(三角形相互穿插)就崩了。

### 深度剥离的精确步骤

我们现在形式化深度剥离。假设场景有 N 个三角形,其中一些是半透明的。目标:得到 K 个"深度层"(K 由你决定,典型 4-8 层),然后按从远到近合成。

```
输入:场景几何 S
输出:合成后的 framebuffer

# Pass 0:渲染所有不透明物体到 framebuffer(普通 z-buffer)
render(opaque_in_S) -> colorbuffer + zbuffer

# Pass 1..K:逐层剥离
min_depth = +∞(初始)
for layer in 1..K:
    # 这一 pass 只画 depth > min_depth 的 fragment
    bind shader(shader_layer)
    shader_layer.min_depth_texture = min_depth_texture(上一层的深度纹理)
    render(transparent_in_S) -> color[layer] + depth[layer]
    # depth[layer] 现在是"第 layer 层"的深度(所有可见的更远 fragment 的最近深度)
    min_depth_texture = depth[layer]

# Pass K+1:合成(从远到近)
for layer in K..1 (倒序):
    blend(color[layer], framebuffer, alpha_blend)
```

**关键洞察**:每一层的深度纹理 `depth[layer]` 是个**屏幕大小的纹理**(texture),它存了"第 layer 层在每个像素处的深度"。下一层的 fragment shader **采样**这个纹理:

```glsl
// fragment shader for layer N
uniform sampler2D prev_depth_texture;
in vec4 gl_FragCoord;

void main() {
    ivec2 px = ivec2(gl_FragCoord.xy);
    float prev_depth = texelFetch(prev_depth_texture, px, 0).r;
    if (gl_FragCoord.z <= prev_depth) {
        discard;  // 这一层我不要,留给前几层
    }
    // 写入颜色和当前深度
    frag_color = compute_color();
    frag_depth = gl_FragCoord.z;
}
```

注意 `<= prev_depth`(不是 `<`)——`<=` 保证下一层**严格更远**。这是细节,但 Casey 在 Day 383 修 bug 时反复回来检查这一条。

### 合成(Compositing)

K 层都拿到之后,合成顺序**必须**是从远到近(即 `K, K-1, ..., 1, 不透明层`)。这是因为 α-blend 公式的非交换性——远处的层先画,近处的层在它上面混合。

```glsl
// fullscreen quad composite
uniform sampler2D color_layers[K];   // color_layers[0] 最近,color_layers[K-1] 最远
uniform sampler2D opaque_color;

out vec4 final_color;

void main() {
    vec4 result = texture(opaque_color, uv);
    for (int i = K - 1; i >= 0; --i) {
        vec4 layer = texture(color_layers[i], uv);
        // 标准过 / 不过(over) 操作
        result = layer * layer.a + result * (1.0 - layer.a);
    }
    final_color = result;
}
```

这就是 PNG 那种"图层叠合"的语义。

### 2-pass 简化版

完整 K 层深度剥离比较重(K 个额外的 framebuffer + 渲染整个场景 K 次)。Casey 今天实现的是 **K=2 的简化版**:

- Pass 1:正常渲染不透明 + 最近一层透明,得到 `color0`、`depth0`
- Pass 2:渲染**比 depth0 更远**的透明 fragment,得到 `color1`(可以包含多个半透明物体的"后面一层")
- 合成:`final = blend(color1, color0)`

K=2 只能正确处理"两层重叠"的场景(玻璃后面的玻璃)。但作为**入门版**,它已经把"玻璃后面看得到东西"这件事做对了——而传统画家算法连这个都做不对(玻璃自身重叠时排序就错)。

### 性能开销

深度剥离的开销:

- **几何**:每层重新光栅化所有半透明三角形(K 倍)
- **带宽**:每层需要额外的颜色 + 深度纹理(K 倍带宽)
- **绘制调用**:每层场景再 draw 一遍

K=4 是工业界常见选择,能处理大多数场景。K=8 用于玻璃 / 烟雾密集场景。

更高级的算法(**Dual-depth peeling**、**A-buffer**、**Weighted blended OIT**)能进一步降低开销,但实现复杂。Casey 后面 Day 385-388 会处理 MSAA + 深度剥离,但**不会**切换到其他 OIT 算法。

### 一个常见误解

很多人(包括初学者)第一次见深度剥离会问:**"为什么不直接在 fragment shader 里对每个像素的所有透明 fragment 排序?"**

答案:**fragment shader 不存在"该像素的所有 fragment"这个概念**。GPU 是并行执行的,每个 fragment shader 调用看到的是**一个** fragment,无法访问其他 fragment。z-buffer 是唯一可以跨 fragment 共享的"全局状态",但它只存"最近深度",无法存"所有 fragment 列表"。

**A-buffer** 算法(1984, Carpenter)确实做到了"每个像素存一个 fragment 链表"——用 GPU 的 SSBO(Shader Storage Buffer Object)+ 原子计数器实现。但开销巨大,Casey 不走这条路。

深度剥离是**模拟**"全部 fragment"的折衷——通过多次 pass,每次提取"当前最近"的一层,迭代 K 次得到 K 层。这是个**算法思路**,值得收藏:GPU 并行 + 全局状态有限 → 用多 pass + 纹理传递信息。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏里**最常见的半透明物体**:

- **粒子系统**(火、烟、爆炸、血迹):几百个 sprite 互相重叠,排序成本极高
- **玻璃**(建筑窗户、温室):玻璃自身重叠时颜色错乱
- **水面**:从上方看水面,水面后面有水底,水底上有石头——三层半透明
- **角色描边**(cel-shading 的描边):是发光的半透明描边,和角色重叠
- **草、树叶**:成千上万的树叶半透明 quad,深度排序不可能

**深度剥离在工业游戏里的实际应用**:

- AAA 游戏常用 **Weighted Blended OIT**(McGuire & Bavoil 2013):用单 pass + 加权混合,**近似**正确顺序,代价是颜色偏色(因为是近似,不是精确)。这是"工业界的妥协"。
- 真正精确的深度剥离用于**离线渲染**(电影特效)或**高保真实时场景**(医疗可视化、CAD)。
- HH 选精确版本,因为 Casey 要**正确性 > 性能**。

**游戏里你不会全场景用深度剥离**——只对**少数高价值的半透明物体**(玻璃、水晶)用。普通粒子继续用画家算法。

### 3.2 · 🎨 图形学视角

深度剥离属于 **OIT(Order-Independent Transparency,顺序无关透明)**算法家族。OIT 的核心目标:**让半透明渲染结果独立于三角形提交顺序**。

OIT 的几种主要方案对比:

| 算法 | 精确性 | 显存开销 | 速度 | 实现复杂度 |
|---|---|---|---|---|
| Painter's algorithm | 不精确(物体级排序) | 无 | 快 | 简单 |
| **Depth peeling** | **精确(K 层)** | **K×(color+depth)** | **慢(K 倍渲染)** | **中等** |
| A-buffer | 精确(全部层) | 不定(链表) | 中等 | 高 |
| WBOIT (weighted blended) | 近似 | 3× color | 快(单 pass) | 低 |
| Moment-based OIT | 近似(更好) | 几张纹理 | 快 | 高 |

**深度剥离在 OpenGL 实现的技术点**:

1. **Multiple Render Targets (MRT)**:fragment shader 一次写入多个颜色附件。Casey 用它把 `color` 和 `depth` 一起写到两张纹理里(GLSL `layout(location=0) out color; layout(location=1) out depth;`)。
2. **Floating-point depth texture**:`GL_DEPTH_COMPONENT32F`——24 位整数深度精度不够, Casey 用 32 位浮点。
3. **`gl_FragCoord.z`**:NDC(Normalized Device Coordinates)深度,范围 [0, 1]。Casey 在 Day 383 调试时反复用 RenderDoc 看 `gl_FragCoord.z` 的实际数值,确认它是不是按线性还是非线性插值。
4. **`texelFetch`**:按整数像素坐标采样纹理(不做滤波),用于"取上一层的深度"。比 `texture()`(带双线性滤波)更精确。

**深度精度陷阱**:OpenGL 默认深度是非线性的——`gl_FragCoord.z = (z_eye * f / (f - n) - f / (f - n) + 0.5)`,其中 n/f 是 near/far 平面。这导致**近处精度高、远处精度低**。深度剥离每层比较的是这个非线性值,**比较结果在数学上是对的**,但**精度**会让"几乎重合的两层"出现 z-fighting(深度冲突,闪烁)。

Casey 在 Day 383 修这个 bug 的核心:**给每层加一个 epsilon 容差**(`if (z <= prev_z + EPSILON) discard`)。

### 3.4 · 🦀 Rust 生态视角

在 Rust 里用 OpenGL 做深度剥离,主流 crate:

```toml
[dependencies]
glium = "0.34"        # OpenGL 安全封装
glam = "0.29"         # 数学库
```

或者更底层:

```toml
[dependencies]
gl = "0.14"           # 直接绑定 OpenGL
sdl2 = "0.36"         # 窗口和 OpenGL context
```

Casey 在 HH 里手写 OpenGL binding(` handmade_opengl.h`),Rust 翻译可以用 `gl` crate 或更高级的 `glium`。

**深度剥离的 Rust 代码骨架**(用 glium):

```rust
use glium::{glutin, Surface, Texture2d, DepthTexture2d, program, framebuffer};

// 1. 创建两个 framebuffer(每个含一个 color attachment 和 depth attachment)
let mut fbo_layer0 = framebuffer::SimpleFrameBuffer::with_depth_texture(
    &display, &color_tex0, &depth_tex0)?;
let mut fbo_layer1 = framebuffer::SimpleFrameBuffer::with_depth_texture(
    &display, &color_tex1, &depth_tex1)?;

// 2. Pass 0:渲染不透明 + 最近一层透明
fbo_layer0.clear_color_and_depth((0., 0., 0., 1.), 1.);
let params = glium::DrawParameters {
    depth: glium::Depth {
        test: glium::draw_parameters::DepthTest::IfLess,
        write: true,
        ..Default::default()
    },
    ..Default::default()
};
fbo_layer0.draw(&mesh, &indices, &program_normal, &uniforms, &params)?;

// 3. Pass 1:渲染比 depth_tex0 更远的透明 fragment
let mut target1 = fbo_layer1;
target1.clear_color_and_depth((0., 0., 0., 0.), 1.);  // alpha=0
let params1 = glium::DrawParameters {
    depth: glium::Depth {
        test: glium::draw_parameters::DepthTest::IfLess,
        write: true,
        ..Default::default()
    },
    ..Default::default()
};
// fragment shader 里采样 depth_tex0,做 if (z <= prev) discard;
let uniforms1 = uniforms.add("prev_depth", &depth_tex0);
target1.draw(&mesh, &indices, &program_peel, &uniforms1, &params1)?;

// 4. Pass 2:合成到默认 framebuffer
let mut screen = display.draw();
screen.clear_color(0., 0., 0., 1.);
let uniforms2 = uniforms.add("color0", &color_tex0).add("color1", &color_tex1);
screen.draw(&fullscreen_quad, &quad_indices, &program_composite, &uniforms2, &Default::default())?;
screen.finish()?;
```

**Rust 端关键概念**:

- `&mut fbo` — framebuffer 是 mutable,因为画到它需要修改状态
- `Surface` trait — `draw` 方法签名:`fn draw<V, I, P, U>(&mut self, vertex_buffer, indices, program, uniforms, params)`
- `program!` 宏 — 编译时嵌入 GLSL 源码,运行时编译为 program
- `uniforms.add` — 链式添加 uniform,因为 glium 用 builder pattern

**所有权**:纹理(`Texture2d`, `DepthTexture2d`)由 `display` 拥有,framebuffer 借用它们。不能在 framebuffer 还活着的时候删纹理。

**unsafe 边界**:glium 本身是 safe API,但底层 `gl` crate 全是 unsafe。如果你直接用 `gl`,每个 GL call 是 unsafe 的(因为编译器无法验证 OpenGL context 是 current 的)。

## 4 · 认知地图

### 4.1 上级(它属于哪个更大抽象?)

- **OIT(Order-Independent Transparency)** — 一类算法,目标"半透明渲染结果与提交顺序无关"
- **多 pass 渲染** — 深度剥离属于"用多 pass 提取信息"的模式;同模式还有 shadow mapping(2 pass)、deferred shading(2 pass)
- **GPU 算法设计** — 深度剥离体现"GPU 并行 + 全局状态有限 → 多 pass + 纹理传递"的设计范式

### 4.2 同级(并行方案对比)

| 方案 | 精确性 | 显存 | 速度 | 复杂度 | HH 选了哪个 |
|---|---|---|---|---|---|
| Painter's algorithm | 物体级,易错 | 无 | 快 | 简单 | 早期用过 |
| **Depth peeling (K pass)** | **精确(K 层)** | **K×** | **慢** | **中等** | **✅ Day 381+** |
| A-buffer | 精确(全层) | 不定 | 中等 | 高 | 不用 |
| WBOIT (single pass) | 近似 | 几张 | 快 | 低 | 不用 |
| Moment shadow / OIT | 近似 | 几张 | 快 | 高 | 不用 |

**详细**:
- **Painter's**:简单但**不可靠**,物体中心排序错时局部就崩。Casey 在 Day 261-380 一直在用,Day 381 决定换。
- **Depth peeling**:精确,但每层要渲染整个场景。Casey 选 K=2 起步。
- **A-buffer**:每像素存 fragment 链表,显存不可预测(可能爆)。优点是单 pass。Casey 不用,因为链表实现复杂、性能不稳定。
- **WBOIT**:用 weighted blended 近似,单 pass,但有**偏色**(权重函数让远处颜色偏深)。AAA 游戏常用。Casey 不用,因为追求精确。

### 4.3 下级(内部零件)

- **gl_FragCoord** — 内置 input,fragment 在 window space 的坐标(含 .z 深度)
- **depth texture** — 屏幕大小的纹理,存每像素的深度值(`GL_DEPTH_COMPONENT`)
- **MRT (Multiple Render Targets)** — 一次 fragment shader 输出多个颜色附件
- **fullscreen quad** — 覆盖整个屏幕的四边形,用于 post-processing / composite pass
- **α-blend 公式** — `final = src.rgb*src.a + dst.rgb*(1-src.a)`,非交换
- **z-fighting** — 深度几乎重合时画面闪烁,要 epsilon 容差

## 5 · 对照与变奏

### 同一问题在不同语境下的变体

**问题**:让多个半透明物体在屏幕上**正确混合**。

| 语境 | 方案 | 关键点 |
|---|---|---|
| 2D UI(PNG 叠图) | 按图层顺序 z-order | 简单,因为图层是显式的 |
| 2D 游戏(sprite) | 按 y 排序(画家算法) | 物体少时够用 |
| 3D 不透明 + 半透明混合 | 不透明 z-buffer + 半透明画家 | 工业标准,简单场景够用 |
| 3D 复杂半透明(玻璃 / 烟雾) | **深度剥离** / WBOIT | HH 在 Day 381 选了深度剥离 |
| 离线渲染(电影) | A-buffer / ray tracing | 追求质量,不计成本 |

### 历史演化

- **1984**:Carpenter 提出 **A-buffer**,每像素存 fragment 链表。但当时 GPU 不存在,CPU 实现。
- **2001**:Everitt 提出 **Depth peeling**,利用 GPU 多 pass + 深度纹理。SIGGRAPH paper。
- **2010s**:WBOIT、Moment-based OIT 出现,单 pass 近似方法流行。
- **2020s**:Vulkan / DX12 的 subpass、bindless 让 A-buffer 重新可行。

Casey 在 Day 381 选 2001 年的深度剥离,**因为它是基础算法,易理解、可教学**。后面他自己加 MSAA(Day 385+)和合成优化(Day 398)。

### GPU 算法设计模式

深度剥离体现一个重要的 **GPU 算法设计模式**:

> 当 GPU 的全局状态有限(只有 z-buffer 和纹理),要表达"每个像素存多个数据"的语义时,用**多 pass + 纹理传递**来模拟。

类似的模式:
- **Gaussian blur(模糊)**:横向 pass 写入临时纹理,纵向 pass 读取再写。两 pass。
- **Shadow mapping**:light 视角渲染深度纹理,camera 视角采样它做阴影。两 pass。
- **Deferred shading**:geometry pass 写 G-buffer(position, normal, albedo),lighting pass 读 G-buffer 算光照。两 pass。

记住这个模式,后面 Casey 每加一个"两 pass"算法,你都立刻认出它。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 α-blend 公式 `final = src*src.a + dst*(1-src.a)` **不满足交换律**?请用一个具体数值算例说明(给两个具体颜色和 alpha,展示两种顺序的不同结果)。

**参考解答**:取 `A = (1, 0, 0, 0.5)`(半透明红),`B = (0, 0, 1, 0.5)`(半透明蓝)。

**先 A 后 B**(背景假设 `(0,0,0)`):
- 画 A:`dst = 0.5*(1,0,0) + 0.5*(0,0,0) = (0.5, 0, 0)`
- 画 B 在 dst 上:`src=B=(0,0,1,0.5)`,`dst = (0.5,0,0)`。结果 = `0.5*(0,0,1) + 0.5*(0.5,0,0) = (0.25, 0, 0.5)`

**先 B 后 A**:
- 画 B:`dst = 0.5*(0,0,1) + 0.5*(0,0,0) = (0, 0, 0.5)`
- 画 A 在 dst 上:`src=A=(1,0,0,0.5)`,`dst = (0,0,0.5)`。结果 = `0.5*(1,0,0) + 0.5*(0,0,0.5) = (0.5, 0, 0.25)`

两个结果 `(0.25, 0, 0.5)` vs `(0.5, 0, 0.25)` 不同!说明 α-blend 不可交换,所以**必须保证顺序**。

### Lv2 · 动手实践

**题**:在 Rust 项目里实现一个最小化的"深度剥离 2-pass"概念 demo(不需要真的 OpenGL,用纯 Rust + Vec 模拟像素)。

完成标准:`cargo run` 打印两层像素,确认 Pass 2 的深度严格大于 Pass 1 的深度。

**参考解答**:

```rust
// 模拟"屏幕"——一个 4x4 像素的 framebuffer,每像素存 (color: f32x3, alpha: f32, depth: f32)
#[derive(Copy, Clone, Debug)]
struct Pixel { r: f32, g: f32, b: f32, a: f32, z: f32 }

const W: usize = 4;
const H: usize = 4;

// 模拟一个场景:在 (0,0)-(3,3) 的 4x4 屏幕上,有一些半透明 fragment
fn main() {
    // 场景定义:每个 fragment 有像素坐标、颜色、alpha、深度
    let fragments = vec![
        // (x, y, r, g, b, a, z)
        (0, 0, 1.0, 0.0, 0.0, 0.5, 0.1),  // 像素 (0,0) 上 z=0.1 红色半透明
        (0, 0, 0.0, 0.0, 1.0, 0.5, 0.3),  // 像素 (0,0) 上 z=0.3 蓝色半透明(更远)
        (1, 1, 0.0, 1.0, 0.0, 1.0, 0.2),  // 像素 (1,1) 上不透明绿
        (2, 2, 0.5, 0.5, 0.5, 0.5, 0.5),  // 像素 (2,2) 上半透明灰
    ];

    // Pass 1: 最近一层(普通 z-buffer)
    let mut layer0 = [[Pixel { r: 0., g: 0., b: 0., a: 0., z: f32::INFINITY }; W]; H];
    for &(x, y, r, g, b, a, z) in &fragments {
        if z < layer0[y][x].z {
            layer0[y][x] = Pixel { r, g, b, a, z };
        }
    }

    // Pass 2: 比 layer0 更远的一层
    let mut layer1 = [[Pixel { r: 0., g: 0., b: 0., a: 0., z: f32::INFINITY }; W]; H];
    for &(x, y, r, g, b, a, z) in &fragments {
        // 关键:严格大于 layer0 的深度才入选第二层
        if z > layer0[y][x].z && z < layer1[y][x].z {
            layer1[y][x] = Pixel { r, g, b, a, z };
        }
    }

    // 打印两层
    println!("Layer 0 (最近一层):");
    for y in 0..H {
        for x in 0..W {
            let p = layer0[y][x];
            if p.z.is_infinite() {
                print!("  .   ");
            } else {
                print!(" z={:.2}", p.z);
            }
        }
        println!();
    }

    println!("Layer 1 (第二层):");
    for y in 0..H {
        for x in 0..W {
            let p = layer1[y][x];
            if p.z.is_infinite() {
                print!("  .   ");
            } else {
                print!(" z={:.2}", p.z);
            }
        }
        println!();
    }

    // 验证:layer1[y][x].z > layer0[y][x].z 严格成立(当 layer1 非空时)
    for y in 0..H {
        for x in 0..W {
            if !layer1[y][x].z.is_infinite() {
                assert!(layer1[y][x].z > layer0[y][x].z,
                        "Layer 1 z must be strictly greater than layer 0 z");
            }
        }
    }
    println!("✓ Pass 2 深度严格大于 Pass 1 深度,验证通过");
}
```

**每行解释**:
- `Pixel` 结构体——把颜色 / alpha / 深度打包到一起,这是 framebuffer 的"原子单位"
- `f32::INFINITY`——表示"无穷远",初始化时所有像素都是无穷深,任何有限深度都比它近
- Pass 1 循环用普通 z-buffer 逻辑:`z < layer0[y][x].z` 才更新
- Pass 2 关键:`z > layer0[y][x].z`(`>` 严格大于),确保第二层比第一层远;同时 `z < layer1[y][x].z` 才更新(找"第二近"的)
- 最后的 assert:如果某个像素在两层都有数据,layer1 的 z 必须严格大于 layer0

### 完整 Rust + glium 2-pass 深度剥离骨架

```toml
# Cargo.toml
[package]
name = "depth_peel_demo"
version = "0.1.0"
edition = "2021"

[dependencies]
glium = "0.34"

```

```rust
// src/main.rs
// 最小化的 2-pass 深度剥离 demo:画两个半透明球(前后重叠),验证第二层可见

use glium::{glutin, Surface, implement_vertex, uniform, program, index, framebuffer, texture};
use glam::{Mat4, Vec3};

// 顶点格式:位置 + UV
#[derive(Copy, Clone)]
struct Vertex { position: [f32; 3], uv: [f32; 2] }
implement_vertex!(Vertex, position, uv);

fn main() {
    // 1. 创建 OpenGL context(glium 封装 glutin)
    let event_loop = glutin::event_loop::EventLoop::new();
    let wb = glutin::window::WindowBuilder::new()
        .with_title("Depth Peeling Demo")
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 600));
    let cb = glutin::ContextBuilder::new()
        .with_depth_buffer(24)              // 24 位深度(标准)
        .with_gl_profile(glutin::GlProfile::Core)
        .with_gl(glutin::GlRequest::Latest);
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    // 2. 顶点数据:一个 fullscreen quad 用于最后合成 pass
    let quad_verts = vec![
        Vertex { position: [-1., -1., 0.], uv: [0., 0.] },
        Vertex { position: [ 1., -1., 0.], uv: [1., 0.] },
        Vertex { position: [-1.,  1., 0.], uv: [0., 1.] },
        Vertex { position: [ 1.,  1., 0.], uv: [1., 1.] },
    ];
    let quad_vbuf = glium::VertexBuffer::new(&display, &quad_verts).unwrap();
    let quad_indices = index::NoIndices(index::PrimitiveType::TriangleStrip);

    // 3. 创建两个 color + depth 纹理对(深度剥离需要)
    let dims = (800u32, 600u32);
    let color_format = texture::UncompressedFloatFormat::F32F32F32F32; // RGBA32F
    let depth_format = texture::DepthFormat::F32;  // 32 位浮点深度

    let color_tex0 = texture::Texture2d::empty_with_format(
        &display, color_format, texture::MipmapsOption::NoMipmap, dims.0, dims.1).unwrap();
    let depth_tex0 = texture::DepthTexture2d::empty_with_format(
        &display, depth_format, texture::MipmapsOption::NoMipmap, dims.0, dims.1).unwrap();
    let color_tex1 = texture::Texture2d::empty_with_format(
        &display, color_format, texture::MipmapsOption::NoMipmap, dims.0, dims.1).unwrap();
    let depth_tex1 = texture::DepthTexture2d::empty_with_format(
        &display, depth_format, texture::MipmapsOption::NoMipmap, dims.0, dims.1).unwrap();

    // 4. 编译三个 shader program(不透明 / peel / composite)
    let normal_program = program!(&display,
        330 es => {
            vertex: r#"
                #version 330
                in vec3 position;
                uniform mat4 mvp;
                void main() { gl_Position = mvp * vec4(position, 1.0); }
            "#,
            fragment: r#"
                #version 330
                out vec4 frag_color;
                uniform vec3 albedo;
                void main() { frag_color = vec4(albedo, 1.0); }
            "#,
        }).unwrap();

    // ... (peel_program / composite_program 类似,见下方)

    // 5. 渲染循环
    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        if let Event::RedrawRequested(_) = event {
            // === Pass 0: 渲染场景到 layer 0 ===
            let mut fbo0 = framebuffer::SimpleFrameBuffer::with_depth_texture(
                &display, &color_tex0, &depth_tex0).unwrap();
            fbo0.clear_color(0., 0., 0., 1.);
            fbo0.clear_depth(1.);
            // (画几何,普通 z-buffer,这里省略场景几何)
            // fbo0.draw(&mesh, &indices, &normal_program, &uniforms, &params).unwrap();

            // === Pass 1: 渲染 layer 1(比 layer 0 远) ===
            let mut fbo1 = framebuffer::SimpleFrameBuffer::with_depth_texture(
                &display, &color_tex1, &depth_tex1).unwrap();
            fbo1.clear_color(0., 0., 0., 0.);
            fbo1.clear_depth(1.);
            // (画相同几何,但 fragment shader 用 depth_tex0 做 discard)

            // === Pass 2: 合成到默认 framebuffer ===
            let mut screen = display.draw();
            screen.clear_color(0., 0., 0., 1.);
            let uniforms = uniform! {
                color0: &color_tex0,
                color1: &color_tex1,
            };
            screen.draw(&quad_vbuf, &quad_indices,
                &composite_program, &uniforms,
                &Default::default()).unwrap();
            screen.finish().unwrap();
        }

        if let Event::WindowEvent { event: WindowEvent::CloseRequested, .. } = event {
            *control_flow = ControlFlow::Exit;
        }
    });
}

// composite_program GLSL:
//   uniform sampler2D color0;   // layer 0(近)
//   uniform sampler2D color1;   // layer 1(远)
//   in vec2 uv; out vec4 frag;
//   void main() {
//       vec4 c0 = texture(color0, uv);
//       vec4 c1 = texture(color1, uv);
//       // 远到近合成:先 c1, 再 c0
//       frag = c0 * c0.a + c1 * (1.0 - c0.a);
//   }
```

**每段解释**:
- `with_depth_buffer(24)` — 创建 OpenGL context 时申请 24 位深度(标准)。深度剥离需要单独的 depth texture,所以 context 的深度 buffer 可以不用,但申请无害。
- `UncompressedFloatFormat::F32F32F32F32` — RGBA32F,每通道 32 位浮点,精度足够。半透明颜色容易"被压暗",浮点 buffer 不会出现 LDR(低动态范围)的精度问题。
- `DepthFormat::F32` — 深度用 32 位浮点,精度比默认 24 位整数高,减少 z-fighting。
- `MipmapsOption::NoMipmap` — 不生成 mipmap(我们只采样最顶层,且 fullscreen composite 用 uv 直接采样)。
- `framebuffer::SimpleFrameBuffer::with_depth_texture` — 把一个 color texture + depth texture 绑成一个 framebuffer,作为渲染目标。
- composite shader 用 **fullscreen quad**(覆盖整个屏幕的四边形)+ uv 直接采样两层颜色,做 over 操作。

- `error: Failed creating OpenGL context` — 你的 GPU 驱动有问题。`glxinfo | grep "OpenGL renderer"` 看是不是 `llvmpipe`(软件渲染),是的话装 `mesa-vdpau` 或专有驱动。
- `FBO incomplete` — 检查 color_tex 和 depth_tex 尺寸是否一致(`dims` 必须完全相同)。
- 编译错误 `texture::UncompressedFloatFormat` 找不到 — glium 0.34 的 API 路径,旧版本可能不同。`cargo doc -p glium --open` 查最新。
- Pass 1 没有任何 fragment 通过 — fragment shader 的 `discard` 条件可能写反了。`if (gl_FragCoord.z <= prev_depth) discard;` 是对的(更近的 discard,更远的画)。
