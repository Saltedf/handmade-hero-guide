# Day 266 · 加顶级时钟性能视图

> 昨天的按钮里有一个 "Top Clocks",今天 Casey 真的实现它。柱状图告诉你"哪些帧慢",Top Clocks 视图告诉你"哪些函数慢"——把所有性能区段按累计耗时排序,显示前 N 名。这是工业级 profiler 的杀手级 view。

## 0 · 为什么要有这一天

你打开了 profiler,看到一个卡顿帧(柱状图上的一根红色尖峰)。点开它的火焰图,看到 80 多个 block 堆在一起。哪一个是元凶?

火焰图能告诉你"每个 block 多耗时",但是 80 个 block 里找出"最贵的 10 个"要肉眼扫描——而且这只是一帧。如果你想看"最近 64 帧里**累计**最贵的是哪些 block",火焰图直接帮不上。

Top Clocks 视图解决这个:把所有 block 按**累计耗时**排序,显示前 10 名。你一眼能看到:

```
Top 10 Clocks (last 64 frames):
1.  render_entity     482 ms   ████████████████
2.  update_physics    312 ms   ██████████
3.  load_texture      234 ms   ████████
4.  audio_mix         87 ms    ███
5.  debug_overlay     52 ms    ██
6.  ...
```

一行就能看到一个 block 的累计耗时,排序后高耗时一目了然。这是 `perf report`、`valgrind --tool=callgrind`、Unreal Insights、Visual Studio Profiler 全都有的视图。

实现这件事的工程挑战:

1. **聚合**:遍历 64 帧的所有 block,按 name 分组累加
2. **排序**:把聚合结果按总耗时排序
3. **格式化显示**:数字 + 文字 + 进度条
4. **实时更新**:每帧或每秒重算一次,不能太频繁(浪费 CPU)也不能太疏(看着像死数据)

心理锚点:做完这个,你的 profiler 终于能回答"我的 CPU 时间花在哪了"——这是性能优化的第一步。

## 1 · Casey 今天做了什么

Casey 实现了 Top Clocks 视图,具体步骤:

1. 把所有 frame 的所有 block 取出来,装到一个 Vec
2. 用一个"名称 → 累计耗时"的 hash table(或 BTreeMap)聚合
3. 把 hash table 转成 Vec,按累计耗时降序排序
4. 取前 N(N=10)名,画在屏幕上
5. 每个条目:排名 + 函数名 + 累计毫秒 + 横向进度条(长度按相对值算)
6. 视图通过 `current_view` 状态切换(昨天的 button 已经做好了)

Casey 在视频里展示了几个细节优化:

- **每秒刷新一次**而不是每帧(每帧聚合 64*256=16k 条目开销大)
- **保留上次的结果**作为"显示中",避免每次刷新时屏幕闪烁
- **进度条按最大值归一化**:第一条永远占满进度条宽度,其他按比例缩

## 2 · 心智模型

### 类比:超市小票

想象超市购物的小票。每个商品一行:名字 + 单价 + 数量 + 小计。小票末尾有"按小计排序"的统计——你最贵的 10 个商品,从贵到便宜排列。这就是 Top N 报告。

性能数据的 Top Clocks 完全一样:每个 block 一行(函数名 + 总耗时 + 调用次数 + 排名),按总耗时排序。

### 严谨原理:聚合 + 排序的两阶段算法

#### 阶段 1:聚合(Aggregation)

输入:64 帧的 16k 个 block,每个 block 有 `name` 和 `duration_ns`。
输出:一个 `Map<name, TotalClocks>`,其中 `TotalClocks = { total_ns: u64, count: u32 }`。

```
for frame in history:
    for block in frame.blocks:
        map[block.name].total_ns += block.duration_ns
        map[block.name].count += 1
```

聚合的复杂度是 O(N)(N 是总 block 数),对 16k 条数据是毫秒级。

#### 阶段 2:排序(Sorting)

把 `Map` 转成 `Vec<(name, TotalClocks)>`,按 `total_ns` 降序排序:

```
let mut sorted: Vec<_> = map.into_iter().collect();
sorted.sort_by(|a, b| b.1.total_ns.cmp(&a.1.total_ns));
let top10 = sorted.into_iter().take(10);
```

Rust 的 `sort_by` 是 Timsort(归并 + 插入排序的混合),稳定且 O(N log N)。对几百个 entry 来说是微秒级。

#### 阶段 3:显示

每个条目的进度条按"相对最大值"算:

```
max_total = top10[0].total_ns
for (rank, (name, clocks)) in top10.enumerate():
    bar_width = (clocks.total_ns as f32 / max_total as f32 * MAX_BAR_W) as i32
    draw_text(rank, name, clocks.total_ns)
    draw_rect(bar_x, bar_y, bar_width, 16, color)
```

这样第一条永远占满进度条宽度,其他按比例缩短,视觉对比强。

### Hash Table vs BTreeMap vs Vec

聚合用什么数据结构?三种选择:

**HashMap<String, TotalClocks>**:
- 查找 / 插入:O(1) 平均
- 遍历:无序,需要排序
- 适合:数据量大,只需要最终排序

**BTreeMap<String, TotalClocks>**:
- 查找 / 插入:O(log N)
- 遍历:按键有序
- 适合:需要按键排序时(name 字典序),但我们要的是按 value 排序

**Vec<(String, TotalClocks)> + 线性查找**:
- 查找:O(N)
- 插入:O(1)(追加)
- 适合:数据量极小(几十个 unique name)

Casey 在 HH 用手写 hash table(教学目的),我们 Rust 端可以用 `std::collections::HashMap`。如果 block name 只有几十种(典型情况),`Vec` 线性查找反而更快(cache 友好,无 hash 开销)。

### 实时刷新 vs 缓存

每帧聚合 + 排序对 16k 数据是几毫秒,放在主循环里会拖慢游戏。解决方案:

```rust
if frame_count % 60 == 0 {  // 每秒刷新
    cached_top_clocks = compute_top_clocks(&history);
}
// 显示时用 cached_top_clocks
```

每 60 帧刷新一次,平均开销 < 0.1ms。这是"非实时任务批处理"的典型模式——UI 不需要每帧反应。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Top Clocks 是游戏优化的核心工具。优化游戏性能的标准流程:

1. **测**:跑 profiler,记录 Top Clocks
2. **判**:看 Top 1-3 名(通常它们占 80% 时间)
3. **改**:针对 Top 1 优化算法 / SIMD 化 / 并行化
4. **再测**:重跑 profiler,确认 Top 1 下降,且没引入新瓶颈
5. **循环**:直到性能达标

游戏优化有个"20/80 法则":20% 的代码占 80% 的时间。Top Clocks 帮你找到那 20%。

业界还有几个变种:

- **Self time vs Inclusive time**:Self = 不包括子函数;Inclusive = 包括。Top Clocks 通常用 Self
- **Per-frame average**:不是总耗时,而是平均每帧耗时(更直观)
- **Call count**:配合耗时看(高耗时 + 高调用 = 真瓶颈)
- ** flame graph**:树形展示,今天不做,Day 270+ 可能涉及

### 3.2 · 🐧 Linux 系统编程视角

Linux 上几个工具的 Top N 思想:

**`perf report`**:perf record 录完后,运行 `perf report` 进入 TUI,默认就是按"累计 sample 数"排序的 Top N。

```bash
sudo perf record -F 99 -p $(pgrep your_game) -g -- sleep 5
sudo perf report --stdio | head -30
# 输出:
#   35.12%  your_game  your_game         [.] render_entity
#   22.43%  your_game  your_game         [.] update_physics
#   ...
```

**`valgrind --tool=callgrind` + `callgrind_annotate`**:类似 Top N,但更细(每条指令)。

**`gprof`**:老牌 profiling 工具,编译时加 `-pg`,运行后生成 `gmon.out`,`gprof` 解析就是 Top N。

**`flamegraph` 工具**(Brendan Gregg 做的):把 perf 数据可视化成火焰图,本质也是 Top N + 树形。

所有工具都用同样的"聚合 + 排序 + 显示"算法。Casey 自己写一遍,让你理解工业级工具背后是什么。

### 3.3 · 🦀 Rust 生态视角

Rust 实现聚合有几种风格:

#### 风格 1:HashMap + entry API

```rust
use std::collections::HashMap;

let mut map: HashMap<&str, (u64, u32)> = HashMap::new();
for frame in &history {
    for block in &frame.blocks[..frame.block_count] {
        let entry = map.entry(block.name).or_insert((0, 0));
        entry.0 += block.end_ns - block.start_ns;
        entry.1 += 1;
    }
}
```

`entry(key).or_insert(default)` 是 Rust 标准库的惯用法——"如果 key 不存在就插入 default,返回 entry 的可变引用"。比 C 的"先 find,如果没找到再 insert"更优雅。

#### 风格 2:函数式

```rust
let aggregated: HashMap<&str, (u64, u32)> = history.iter()
    .flat_map(|f| f.blocks[..f.block_count].iter())
    .fold(HashMap::new(), |mut acc, block| {
        let entry = acc.entry(block.name).or_insert((0, 0));
        entry.0 += block.end_ns - block.start_ns;
        entry.1 += 1;
        acc
    });
```

`flat_map` 把嵌套结构(帧 -> block)扁平化,`fold` 累积到一个值。优雅但抽象,初学者读起来吃力。

#### 风格 3:手写循环

```rust
let mut map: HashMap<&str, (u64, u32)> = HashMap::new();
for f in history.iter() {
    for i in 0..f.block_count {
        let block = &f.blocks[i];
        let e = map.entry(block.name).or_insert((0, 0));
        e.0 += block.end_ns - block.start_ns;
        e.1 += 1;
    }
}
```

最直白,性能和风格 1 一样。Casey 选这种(C 没有迭代器,Rust 端我们也可以走这条)。

#### 排序:sort_unstable_by

```rust
let mut sorted: Vec<_> = map.into_iter().collect();
sorted.sort_unstable_by(|a, b| b.1 .0.cmp(&a.1 .0));
```

`sort_unstable_by` 比 `sort_by` 快(不保持相等元素的相对顺序),性能敏感场景推荐。

#### Vec 还是 HashMap?

如果 unique name 数 < 100,Vec 线性查找更快:

```rust
let mut list: Vec<(&str, u64, u32)> = Vec::new();
for f in &history {
    for i in 0..f.block_count {
        let block = &f.blocks[i];
        if let Some(e) = list.iter_mut().find(|(n, _, _)| *n == block.name) {
            e.1 += block.end_ns - block.start_ns;
            e.2 += 1;
        } else {
            list.push((block.name, block.end_ns - block.start_ns, 1));
        }
    }
}
```

`find` 是 O(N),但 N=100 时只比 HashMap 慢几纳秒,而且没有 hash 计算 + 链表 / 开放地址遍历的开销。

### 3.4 · 数据结构:为什么是 Top N 而不是全部

理论上你可以显示所有 block 的累计耗时,但有 1000 个 block 怎么办?屏幕只能显示 30 行。

Top N 是**信息密度最高的选择**:用户最关心"哪些函数最值得优化",Top 10 已经覆盖 80% 的优化机会。剩下的 90% 函数加起来不到 20% 时间,不值得看。

这是"帕累托法则"(80/20)在性能分析的体现:集中精力优化 Top N,投入产出比最高。

## 5 · 对照与变奏

### 不同 profiler 的 Top N 实现

| 工具 | 聚合单位 | 排序方式 | 显示形式 |
|---|---|---|---|
| `perf report` | 函数符号 | sample 数 | TUI 表格 |
| `valgrind callgrind` | 指令地址 | 指令数 | 文本 + GUI |
| Unreal Insights | engine 函数 | 耗时 | UI 表格 |
| Visual Studio Profiler | 函数 | CPU 时间 | UI 表格 |
| HH profiler | block name | ns | 简单列表 |

实现都是"聚合 + 排序 + 显示",差异在数据源精度和 UI 复杂度。

### 时间维度 vs 空间维度

- **Top Clocks**(今天):时间维度——"哪些函数花的时间多"
- **Memory Profiler**(Day 270+):空间维度——"哪些对象占的内存多"

两个维度的算法一样(聚合 + 排序 + 显示),只是 metric 不同。学完一个,另一个秒会。

### Self time vs Inclusive time

| 指标 | 定义 | 适合 |
|---|---|---|
| Self time | 函数自身耗时,不包括子调用 | 找 CPU 重负载函数 |
| Inclusive time | 包括所有子调用 | 找调用链瓶颈 |

Casey 的 HH profiler 用的接近 Self time(每个 block 是一个计时器,不含子 block)。如果要算 Inclusive,要在 block 嵌套时减去子 block 的耗时。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Casey 选择"每 60 帧刷新一次 Top Clocks"而不是"每帧刷新"?给出至少 3 个理由。

**参考解答**:
1. **CPU 开销**:每帧聚合 64*256=16k 条目 + 排序,大约 2-3ms,放在 16ms 帧预算里占 12%,太多。每 60 帧(1秒)刷新一次,平均开销 0.05ms,可忽略
2. **数据稳定性**:Top Clocks 反映"长期趋势",1 秒内变化不大。每帧刷新反而让数字跳动,用户读不清
3. **视觉舒适**:每秒一次的更新节奏,眼睛能跟上。每帧刷新的话数字一直在变,看起来像"乱抖"
4. **优化逻辑**:优化是按"分钟级"思考的(找出 Top 1 → 优化算法 → 重测),不需要实时数据
5. **减少 GC 压力**(对有 GC 的语言):每帧创建 Vec / HashMap 增加 GC 压力,缓存一份复用更友好

### Lv2 · 动手实践

**题**:实现一个 `top_clocks(history: &[FrameProfile]) -> Vec<(&str, u64, u32)>` 函数,返回按总耗时降序排列的 (name, total_ns, count) 元组列表。

测试:构造 2 帧,每帧 3 个 block,验证聚合 + 排序正确。

完成标准:打印出按总耗时排序的列表,第一名是总耗时最大的。

**参考解答**:

```rust
use std::collections::HashMap;

#[derive(Clone, Debug)]
struct ProfileBlock {
    name: &'static str,
    duration_ns: u64,
}

#[derive(Clone, Default)]
struct FrameProfile {
    blocks: Vec<ProfileBlock>,
}

impl FrameProfile {
    fn new() -> Self { Self::default() }
    fn add(&mut self, name: &'static str, dur: u64) {
        self.blocks.push(ProfileBlock { name, duration_ns: dur });
    }
}

fn top_clocks(history: &[FrameProfile]) -> Vec<(&'static str, u64, u32)> {
    // 阶段 1: 聚合
    let mut map: HashMap<&'static str, (u64, u32)> = HashMap::new();
    for frame in history {
        for block in &frame.blocks {
            let entry = map.entry(block.name).or_insert((0, 0));
            entry.0 += block.duration_ns;
            entry.1 += 1;
        }
    }

    // 阶段 2: 转 Vec + 排序(降序)
    let mut sorted: Vec<_> = map.into_iter()
        .map(|(name, (total, count))| (name, total, count))
        .collect();
    // sort_unstable_by 比 sort_by 快,且我们不在乎相等元素的顺序
    sorted.sort_unstable_by(|a, b| b.1.cmp(&a.1));

    sorted
}

fn main() {
    let mut frame1 = FrameProfile::new();
    frame1.add("update", 2_000_000);
    frame1.add("render", 5_000_000);
    frame1.add("audio", 1_000_000);

    let mut frame2 = FrameProfile::new();
    frame2.add("update", 3_000_000);
    frame2.add("render", 4_000_000);
    frame2.add("io", 8_000_000);

    let history = vec![frame1, frame2];
    let top = top_clocks(&history);

    println!("Top Clocks:");
    for (i, (name, total, count)) in top.iter().enumerate() {
        println!(
            "  {}. {:15} {:>8.2} ms (count: {})",
            i + 1, name, *total as f64 / 1_000_000.0, count
        );
    }
    // 输出:
    //   1. render              9.00 ms (count: 2)
    //   2. io                  8.00 ms (count: 1)
    //   3. update              5.00 ms (count: 2)
    //   4. audio               1.00 ms (count: 1)
}
```

**每行解释**:
- `HashMap<&'static str, (u64, u32)>` 键是字符串字面量(零分配),值是 (total_ns, count) tuple
- `entry(name).or_insert((0, 0))` 是 Rust 标准 idiom:不存在则插入默认值,返回可变引用
- `sort_unstable_by` 不保证相等元素的相对顺序,但更快——对性能数据排序是合适的
- `b.1.cmp(&a.1)` 比较 tuple 的第二个元素(total),`b` 在前表示降序

## 8 · Rust / Arch 落地代码

### 完整可跑:profiler 含 Top Clocks 视图

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, MouseMode, MouseButton, Window, WindowOptions};
use std::collections::HashMap;
use std::time::{Duration, Instant};

const WIDTH: usize = 800;
const HEIGHT: usize = 600;

#[derive(Clone, Debug)]
struct ProfileBlock {
    name: &'static str,
    duration_ns: u64,
}

#[derive(Clone)]
struct FrameProfile {
    blocks: Vec<ProfileBlock>,
}

impl FrameProfile {
    fn new() -> Self { Self { blocks: Vec::with_capacity(64) } }
    fn add(&mut self, name: &'static str, dur: u64) {
        self.blocks.push(ProfileBlock { name, duration_ns: dur });
    }
}

fn top_clocks(history: &[FrameProfile]) -> Vec<(&'static str, u64, u32)> {
    let mut map: HashMap<&'static str, (u64, u32)> = HashMap::new();
    for frame in history {
        for block in &frame.blocks {
            let e = map.entry(block.name).or_insert((0, 0));
            e.0 += block.duration_ns;
            e.1 += 1;
        }
    }
    let mut sorted: Vec<_> = map.into_iter()
        .map(|(name, (total, count))| (name, total, count))
        .collect();
    sorted.sort_unstable_by(|a, b| b.1.cmp(&a.1));
    sorted
}

#[derive(Clone, Copy, Debug, PartialEq)]
enum ViewMode { BarChart, TopClocks, Memory }

#[derive(Clone, Copy, Debug)]
enum UiEvent {
    SwitchView(ViewMode),
    Reset,
    Save,
}

#[derive(Clone, Copy, Debug)]
struct Rect { x: i32, y: i32, w: i32, h: i32 }

impl Rect {
    fn new(x: i32, y: i32, w: i32, h: i32) -> Self { Self { x, y, w, h } }
    fn hit_test(&self, mx: i32, my: i32) -> bool {
        mx >= self.x && mx < self.x + self.w && my >= self.y && my < self.y + self.h
    }
}

fn draw_rect(buffer: &mut [u32], buf_w: usize, buf_h: usize, r: Rect, color: u32) {
    for py in r.y.max(0)..(r.y + r.h).min(buf_h as i32) {
        for px in r.x.max(0)..(r.x + r.w).min(buf_w as i32) {
            buffer[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

struct Button {
    rect: Rect,
    label: &'static str,
    event: UiEvent,
    is_pressed: bool,
    was_pressed_inside: bool,
}

impl Button {
    fn new(rect: Rect, label: &'static str, event: UiEvent) -> Self {
        Self { rect, label, event, is_pressed: false, was_pressed_inside: false }
    }
    fn handle_mouse_down(&mut self, mx: i32, my: i32) -> bool {
        if self.rect.hit_test(mx, my) {
            self.is_pressed = true;
            self.was_pressed_inside = true;
            true
        } else {
            self.is_pressed = false;
            self.was_pressed_inside = false;
            false
        }
    }
    fn handle_mouse_up(&mut self, mx: i32, my: i32) -> Option<UiEvent> {
        let triggered = self.is_pressed && self.was_pressed_inside && self.rect.hit_test(mx, my);
        self.is_pressed = false;
        self.was_pressed_inside = false;
        if triggered { Some(self.event) } else { None }
    }
    fn draw(&self, buffer: &mut [u32], buf_w: usize, buf_h: usize) {
        let color = if self.is_pressed { 0xFF606060 } else { 0xFF808080 };
        draw_rect(buffer, buf_w, buf_h, self.rect, color);
    }
}

fn main() {
    let mut window = Window::new(
        "Top Clocks Demo", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut current_view = ViewMode::TopClocks;

    // 历史数据
    let mut history: Vec<FrameProfile> = Vec::with_capacity(64);
    let mut last_time = Instant::now();
    let mut frame_count = 0u64;

    // Top Clocks 缓存
    let mut cached_top: Vec<(&'static str, u64, u32)> = Vec::new();

    // 模拟的 block 名字
    let block_names = ["update", "render", "audio", "io", "debug", "physics", "anim"];

    let buttons = vec![
        Button::new(Rect::new(20,  20, 100, 30), "Bar",    UiEvent::SwitchView(ViewMode::BarChart)),
        Button::new(Rect::new(130, 20, 100, 30), "Clocks", UiEvent::SwitchView(ViewMode::TopClocks)),
        Button::new(Rect::new(240, 20, 100, 30), "Mem",    UiEvent::SwitchView(ViewMode::Memory)),
        Button::new(Rect::new(350, 20, 100, 30), "Reset",  UiEvent::Reset),
        Button::new(Rect::new(460, 20, 100, 30), "Save",   UiEvent::Save),
    ];
    let mut buttons = buttons;

    let mut was_mouse_down = false;

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time);
        last_time = now;

        // 模拟一帧的 blocks
        let mut frame = FrameProfile::new();
        for name in block_names {
            // 随机一些耗时(基于 name 的 hash)
            let fake_dur = (name.len() as u64 * 100_000 + (frame_count % 5) * 50_000) as u64;
            frame.add(name, fake_dur);
        }
        history.push(frame);
        if history.len() > 64 { history.remove(0); }

        // 每 60 帧刷新 Top Clocks
        if frame_count % 60 == 0 {
            cached_top = top_clocks(&history);
        }
        frame_count += 1;

        // 鼠标
        let (mx_f, my_f) = window.get_mouse_pos(MouseMode::Discard).unwrap_or((-1.0, -1.0));
        let (mx, my) = (mx_f as i32, my_f as i32);
        let is_mouse_down = window.get_mouse_down(MouseButton::Left);
        let mouse_down_event = is_mouse_down && !was_mouse_down;
        let mouse_up_event = !is_mouse_down && was_mouse_down;
        was_mouse_down = is_mouse_down;

        if mouse_down_event {
            for b in buttons.iter_mut() { b.handle_mouse_down(mx, my); }
        }
        if mouse_up_event {
            for b in buttons.iter_mut() {
                if let Some(event) = b.handle_mouse_up(mx, my) {
                    match event {
                        UiEvent::SwitchView(v) => current_view = v,
                        UiEvent::Reset => { history.clear(); cached_top.clear(); }
                        UiEvent::Save => { std::fs::write("profile.json", "{}").unwrap(); }
                    }
                }
            }
        }

        // 清屏
        for px in buffer.iter_mut() { *px = 0xFF101010; }

        // 画按钮
        for b in &buttons { b.draw(&mut buffer, WIDTH, HEIGHT); }

        // 视图区域
        let view_rect = Rect::new(20, 70, WIDTH as i32 - 40, HEIGHT as i32 - 90);
        draw_rect(&mut buffer, WIDTH, HEIGHT, view_rect, 0xFF202020);

        match current_view {
            ViewMode::TopClocks => {
                // 画 Top Clocks
                if !cached_top.is_empty() {
                    let max_total = cached_top[0].1;
                    let bar_x = view_rect.x + 250;
                    let bar_max_w = view_rect.w - 270;
                    let line_h = 20;

                    for (i, (name, total, count)) in cached_top.iter().take(20).enumerate() {
                        let y = view_rect.y + 10 + i as i32 * line_h;
                        if y + line_h > view_rect.y + view_rect.h { break; }

                        // 排名
                        draw_rect(&mut buffer, WIDTH, HEIGHT,
                                  Rect::new(view_rect.x + 10, y, 30, line_h - 4), 0xFF4040A0);

                        // 文字区(简化,实际要画字体)
                        // 这里只画一个颜色块代表
                        draw_rect(&mut buffer, WIDTH, HEIGHT,
                                  Rect::new(view_rect.x + 50, y, 180, line_h - 4), 0xFF404040);

                        // 进度条
                        let bar_w = (*total as f32 / max_total as f32 * bar_max_w as f32) as i32;
                        let bar_color = if i < 3 { 0xFFFF4040 } else if i < 10 { 0xFFFFFF40 } else { 0xFF40FF40 };
                        draw_rect(&mut buffer, WIDTH, HEIGHT,
                                  Rect::new(bar_x, y, bar_w, line_h - 4), bar_color);
                    }
                } else {
                    // 等待数据
                    draw_rect(&mut buffer, WIDTH, HEIGHT,
                              Rect::new(view_rect.x + 100, view_rect.y + 100, 200, 30),
                              0xFF404040);
                }
            }
            ViewMode::BarChart => {
                // 简化的柱状图
                let n = history.len();
                if n > 0 {
                    let bar_w = view_rect.w / n as i32;
                    let scale = 5_000_000.0_f32;
                    for (i, f) in history.iter().enumerate() {
                        let total: u64 = f.blocks.iter().map(|b| b.duration_ns).sum();
                        let bx = view_rect.x + i as i32 * bar_w;
                        let top_y = view_rect.y + ((1.0 - (total as f32 / scale).min(1.0)) * view_rect.h as f32) as i32;
                        draw_rect(&mut buffer, WIDTH, HEIGHT,
                                  Rect::new(bx, top_y, bar_w, view_rect.y + view_rect.h - top_y),
                                  0xFF4040FF);
                    }
                }
            }
            ViewMode::Memory => {
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          Rect::new(view_rect.x + 100, view_rect.y + 100, 200, 30),
                          0xFF404040);
            }
        }

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `HashMap::entry` API:Rust 处理"不存在则插入"的标准方式
- `sort_unstable_by`:性能敏感场景的排序
- `cached_top: Vec<...>` 缓存,避免每帧重算
- `history.remove(0)` 不是最高效(O(N) 移动),但教学清晰;生产用 VecDeque 或环形数组
- `take(20)` 截取前 20 个,只画 20 行

**Troubleshooting**:

- Top Clocks 是空的 — 等待 60 帧(1 秒)缓存刷新
- 进度条全是满的 — max_total 取错了,应该是 `cached_top[0].1`(排序后第一条)
