# Day 368 · 在 OpenGL 中编译与链接 shader

> HH 此前用一个写死的简单 shader 画立方体。今天 Casey 把 shader 当作**真正的工程产物**——它会编译失败,会链接失败,会在运行时找不到 uniform,日志要看,错误要处理。Shader 编译是 OpenGL 里**第一次让 GPU 跑你写的代码**,这一步出错后面全废。

## 0 · 为什么要有这一天

你写了一个 GLSL shader 文件,双击运行——它什么都不做。因为 shader 不是程序,它是**给 GPU 的字节流片段**。它要经历四个阶段才能在你的渲染管线里跑起来:

1. **源码字符串**:你写的文本,存在 CPU 内存
2. **编译**:OpenGL 把源码交给 GPU 驱动,驱动调用 shader 编译器(NVIDIA 用自家 NVCC,AMD 用 LLVM 后端,Intel 用 ICE),生成 GPU 特定字节码
3. **链接**:把多个编译后的 shader(vertex + fragment + 可能的 geometry / tessellation)合并成一个 program object,解析 uniform / attribute 位置
4. **使用**:`glUseProgram(program_id)`,后续 draw call 用这个 program

这四步每一步都可能失败:
- 编译失败:语法错、用了不存在的 GLSL 函数、版本声明错误
- 链接失败:vertex shader 输出和 fragment shader 输入不匹配、缺 main 函数、uniform block 不一致
- 运行时失败:uniform 名字写错、attribute 位置和 `glVertexAttribPointer` 的 index 不匹配

**为什么必须懂 shader 编译链路**?因为后面 30 天(光照、法线贴图、深度剥离)Casey 要写大量 shader,每次都要看 InfoLog(OpenGL 的错误日志)。不懂编译链路,你看不懂错误,改不了 bug。

更深一层:理解 shader 编译让你理解 **OpenGL 是什么**——它是个**驱动层抽象**,把 GPU 命令包装成跨厂商 API。同一个 GLSL 源码在不同 GPU 上编译出的字节码完全不同,但 OpenGL 保证语义一致。这是抽象的力量,也是抽象的代价(性能调优时要打破抽象,用 vendor-specific 扩展)。

心理锚点:今天之后,你能写出"加载、编译、链接、报错、使用"的完整 shader 管线,看懂 OpenGL InfoLog,理解 shader 编译和 Rust 编译的异同,知道为什么 shader 错误信息那么模糊。

## 1 · Casey 今天做了什么(HH 脉络)

Day 367 启用 MSAA 后,Casey 决定**把 shader 管线工程化**。此前他的 shader 是硬编码字符串,出错就只有崩溃。今天他:

## 2 · 心智模型

### 类比:shader 编译就像 Rust 编译,但有四个区别

你写 Rust,`cargo build` 编译成机器码,链接成可执行文件。Shader 编译看起来一样,但有关键区别:

| 维度 | Rust 编译 | Shader 编译 |
|---|---|---|
| 编译时机 | 你 build 时 | 程序运行时调 OpenGL API |
| 编译器 | rustc(LLVM 后端) | GPU 驱动里的 vendor 编译器 |
| 错误信息 | 详细,行号 + snippet | 简短,行号可能错 |
| 链接器 | rustc 自带 | `glLinkProgram`,自己手写 |
| 字节码 | x86_64 / ARM 机器码 | GPU 特定字节码(NVIDIA SPIR-V 或私有格式) |

最大区别:**Shader 编译是运行时操作**。这意味着:
- 程序启动慢(要等驱动编译所有 shader)
- 玩家可能看到编译错误(如果驱动版本不匹配)
- 你可以做**热重载**(改 shader 文件,运行时重新编译,马上看效果)

### Shader 编译的四个阶段

**第 1 阶段:源码上传**

```rust
let shader_id = unsafe { gl::CreateShader(shader_type) };
unsafe {
    let src_ptr = source.as_ptr() as *const GLchar;
    let src_len = source.len() as GLint;
    gl::ShaderSource(shader_id, 1, &src_ptr, &src_len);
    // 第三个参数是 *const *const GLchar(指针数组),表示多段源码
    // 第四个参数是长度数组,null 表示每段以 null 结尾
}
```

OpenGL 拷贝源码到驱动内存,但还**没编译**。

**第 2 阶段:编译**

```rust
unsafe { gl::CompileShader(shader_id); }
```

调用 GPU 驱动的 shader 编译器。**这一步可能耗时几十毫秒**(大型 shader 数百毫秒)。编译完成后,查询状态:

```rust
let mut success = gl::FALSE as GLint;
unsafe { gl::GetShaderiv(shader_id, gl::COMPILE_STATUS, &mut success); }
if success == gl::FALSE as GLint {
    // 编译失败,读 InfoLog
    let mut log_len = 0;
    unsafe { gl::GetShaderiv(shader_id, gl::INFO_LOG_LENGTH, &mut log_len); }
    let mut log = vec![0u8; log_len as usize];
    unsafe {
        gl::GetShaderInfoLog(
            shader_id,
            log_len,
            std::ptr::null_mut(),
            log.as_mut_ptr() as *mut GLchar,
        );
    }
    let log_str = String::from_utf8_lossy(&log);
    panic!("Shader compile error:\n{}", log_str);
}
```

InfoLog 是 GPU 驱动写的人类可读错误信息。它的格式没有标准化,NVIDIA / AMD / Intel 给出的描述各不相同。例如同一个语法错误:

- NVIDIA: `0(12) : error C0000: syntax error, unexpected ')' at token ")"`
- AMD: `ERROR: 0:12: ')' : syntax error`
- Intel: `error: syntax error, unexpected ')' at line 12`

工业做法是**收集所有厂商的输出做 normalization**,但教学阶段直接打印就行。

**第 3 阶段:链接**

```rust
let program_id = unsafe { gl::CreateProgram() };
unsafe {
    gl::AttachShader(program_id, vs_id);
    gl::AttachShader(program_id, fs_id);
    gl::LinkProgram(program_id);
}
// 同样查 link status,失败读 program InfoLog
```

链接器把多个 shader 合并,解析它们之间的输入输出关系。例如 vertex shader 输出 `out vec3 v_normal`,fragment shader 输入 `in vec3 v_normal`——链接器把这两个绑定到同一个 varying(slot 编号)。

链接失败常见原因:
- vertex 输出和 fragment 输入名字不一致(变量名拼写错)
- 同一变量在两个 shader 里类型不同
- fragment shader 没有 `out` 声明(OpenGL 3.3+ 要求)
- 多个 shader 的 `layout(location = N)` 重复

**第 4 阶段:使用**

```rust
unsafe { gl::UseProgram(program_id); }
```

后续 draw call 用这个 program。Program 内部包含编译后的字节码,驱动把字节码加载到 GPU shader 核心。

### Uniform location:运行时查询

Shader 里有变量(uniform / attribute),CPU 要往里写值。OpenGL 用 **location**(整数)标识变量,而不是名字。Location 在链接后确定,必须运行时查询:

```rust
let model_loc = unsafe {
    gl::GetUniformLocation(program_id, b"u_model\0".as_ptr() as *const GLchar)
};
if model_loc < 0 {
    panic!("uniform u_model not found");
}
unsafe { gl::UniformMatrix4fv(model_loc, 1, gl::FALSE, model_matrix.as_ptr()); }
```

**关键陷阱**:
- 名字必须以 `\0` 结尾(C 字符串)。Rust 字符串没 `\0`,要手动加 `b"name\0"`
- 如果 uniform 在 shader 里声明了但**没使用**,OpenGL 编译器会优化掉它,`GetUniformLocation` 返回 -1
- 如果 uniform 在 if/else 死分支里被设值,也可能被优化掉

工业代码做 caching:程序启动时查询所有 uniform 一次,存到 HashMap,后续直接读。

### Rust 视角:把 shader 当资源管理

Shader 编译失败应该 panic 还是返回 Result?Casey 的选择:

- **教学阶段**:panic,崩溃比静默错误好
- **生产阶段**:Result,允许降级(fallback 到简单 shader)

Rust 表达 shader 资源:

```rust
pub struct Shader {
    program: GLuint,
}

impl Shader {
    pub fn new(vs_src: &str, fs_src: &str) -> Result<Self, ShaderError> {
        let vs = compile(vs_src, gl::VERTEX_SHADER)?;
        let fs = compile(fs_src, gl::FRAGMENT_SHADER)?;
        let program = link(vs, fs)?;
        // shader object 在链接后可删除(program 已持有字节码)
        unsafe {
            gl::DeleteShader(vs);
            gl::DeleteShader(fs);
        }
        Ok(Self { program })
    }

    pub fn use_program(&self) {
        unsafe { gl::UseProgram(self.program); }
    }

    pub fn uniform_loc(&self, name: &str) -> GLint {
        let c_name = std::ffi::CString::new(name).unwrap();
        unsafe { gl::GetUniformLocation(self.program, c_name.as_ptr()) }
    }
}

impl Drop for Shader {
    fn drop(&mut self) {
        unsafe { gl::DeleteProgram(self.program); }
    }
}

#[derive(Debug)]
pub enum ShaderError {
    Compile { shader_type: GLuint, log: String },
    Link { log: String },
}
```

**关键 Rust 概念**:
- `CString::new(name).unwrap()` — Rust string 转 C string(末尾加 `\0`)。如果 name 内含 `\0` 字节会失败(unwrap 会 panic),工业代码应处理 `Result`
- `Drop` trait — 程序退出时自动 `glDeleteProgram`,RAII
- `enum ShaderError` — Rust 用 enum 表达多种错误类型,比 C 的 int error code 表达力强

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业对 shader 编译的特殊处理:

**Shader 缓存**

每次游戏启动重新编译所有 shader,可能耗时几秒。工业方案:
- **SPIR-V**(Vulkan / OpenGL 4.2+):预编译 shader 到 SPIR-V 二进制,运行时让驱动"读取"而不是"编译"。Vulkan 直接用 SPIR-V,OpenGL 用 `glSpecializeShader` / `glShaderBinary`
- **Pipeline cache**(Vulkan):把整个 pipeline(含编译后的 shader 字节码)缓存到磁盘,下次启动直接加载
- **Background compilation**:主线程渲染简单 fallback shader,后台编译复杂 shader,完成后热替换

**Shader permutation(变体)**

同一份 shader 加不同 `#define` 编译多次,产生多个变体:
```glsl
// base.glsl
#if defined(ALPHA_TEST)
  if (tex.a < 0.5) discard;
#endif
#if defined(NORMAL_MAP)
  vec3 n = texture(normal_map, uv).xyz * 2.0 - 1.0;
#else
  vec3 n = vertex_normal;
#endif
```

游戏可能有数千个 shader permutation。例如 The Witcher 3 有 ~10000 个 shader 变体,只编译用到的几百个,缓存到磁盘。

**Hot reload(热重载)**

游戏开发神器:文件保存时,后台线程检测变化,重新编译 shader,通过 `glProgramBinary` 或重新 `glLinkProgram` 替换。开发者修改 shader 立刻看到效果,不用重启游戏。

Casey 后面会做这个(Phase 7)。

### 3.2 · 🎨 图形学视角

Shader 阶段不止 vertex / fragment。OpenGL 4.x 支持的可编程阶段:

| 阶段 | OpenGL 调用 | 作用 |
|---|---|---|
| Vertex | `glCreateShader(GL_VERTEX_SHADER)` | 顶点变换 |
| Tessellation Control | `GL_TESS_CONTROL_SHADER` | 细分控制(LOD) |
| Tessellation Eval | `GL_TESS_EVALUATION_SHADER` | 细分求值 |
| Geometry | `GL_GEOMETRY_SHADER` | 增删图元 |
| Fragment | `GL_FRAGMENT_SHADER` | 像素着色 |
| Compute | `GL_COMPUTE_SHADER` | 通用 GPU 计算 |

每个阶段都是独立 shader,要单独编译。Link 时所有启用的阶段都要 attach。Casey 现在(Phase 6)只用 vertex + fragment,后面光照可能用 compute shader 做后处理。

**GLSL 版本**

GLSL 源码第一行:`#version 330 core`。版本号对应 OpenGL 版本:
- `#version 130` — OpenGL 3.0,attribute / varying 旧语法
- `#version 330 core` — OpenGL 3.3,in / out 新语法,Core Profile
- `#version 460 core` — OpenGL 4.6,最新特性

Casey 用 `#version 330 core`(对应 Day 372 的 Core Profile),跨平台兼容性好。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上 shader 编译链路:

```
application → libGL.so → Mesa → LLVM → GPU 字节码 → DRM → GPU
```

Mesa 用 LLVM 作为 shader 编译后端(开源驱动 radeonsi / iris / nouveau)。LLVM 把 GLSL → LLVM IR → GPU 特定字节码。

**调试 shader 编译**:

```bash
# 1. 启用 Mesa shader 编译日志
MESA_SHADER_CACHE_DIR=/tmp/mesa_cache ./target/release/handmade_hero
MESA_SHADER_CACHE_SHOW_STATS=1 ./target/release/handmade_hero
# 输出:Shader cache hits: 5/8, misses: 3
# Mesa 缓存编译后的 shader 到磁盘,加速下次启动

MESA_DEBUG=context ./target/release/handmade_hero
# 启用 GL context 错误日志

MESA_LOG_FILE=/tmp/mesa.log ./target/release/handmade_hero
# Mesa 日志输出到文件

# 2. 抓取 shader 源码(apitrace)
sudo pacman -S apitrace
apitrace trace ./target/release/handmade_hero
# trace 文件里能看到所有 glShaderSource 调用,含源码

# 3. 用 GLSL playground 离线测试 shader
sudo pacman -S shaderc   # GLSL → SPIR-V 编译器
glslc --version
echo '#version 330 core
void main() { gl_Position = vec4(0,0,0,1); }' > test.vert
glslc test.vert -o test.spv
# 编译成功 → 输出 SPIR-V 文件 test.spv
# 编译失败 → 打印错误信息

# 4. 看 Mesa 的 shader cache
ls /tmp/mesa_cache/  # 如果设置了上面的环境变量
```

**Linux 平台特性**:

- **shader cache** — Mesa 把编译后的 shader 字节码缓存到 `~/.cache/mesa_shader_cache/`,下次启动加速
- **disk cache** — Mesa 4.0+ 支持 disk cache,即使重启机器也保留
- **Radv vs RadeonSI** — Vulkan 用 RADV(社区),OpenGL 用 RadeonSI(AMD 官方),shader 编译器不同

## 4 · 认知地图

### 4.1 上级

- **Render Pipeline(渲染管线)** —— GPU 的可编程 + 固定阶段序列,shader 是可编程阶段
- **Program Object** —— OpenGL 里多个 shader 链接后的可执行单元
- **SPIR-V** —— 跨平台 shader 二进制中间表示,Vulkan / OpenGL 4.2+ 支持

### 4.2 同级(并行方案)

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| Runtime GLSL compile | 运行时调 OpenGL 编译源码 | 灵活 / 简单 | ✅ Casey 选了 |
| SPIR-V precompiled | 离线编译到 SPIR-V,运行时加载二进制 | Vulkan / 启动优化 | 不用 |
| Shader binary | 厂商特定二进制(`glShaderBinary`) | 极致启动优化 | 不用(平台依赖) |
| Pipeline cache | 整 pipeline 缓存(Vulkan) | 现代 AAA 游戏 | 不用 |

### 4.3 下级

- **Shader Object** —— 单个 shader(vertex / fragment / ...)的容器
- **Program Object** —— 多 shader 链接后的可执行单元
- **InfoLog** —— OpenGL 写的人类可读日志(编译 / 链接错误)
- **Uniform Location** —— CPU 上传值时定位变量的整数 ID
- **Attribute Location** —— Vertex array 里顶点属性的槽位 ID

## 5 · 对照与变奏

### 同一问题在不同语境下的变体

**问题**:把 GLSL 源码变成可执行的 shader。

| 语境 | API | 错误处理 |
|---|---|---|
| OpenGL | `glCompileShader` / `glLinkProgram` | InfoLog 字符串 |
| Vulkan | `VkShaderModule` + SPIR-V | `VkValidationLayer` 详尽日志 |
| DirectX 11 | `D3DCompile` / `D3D11CreatePixelShader` | `ID3DBlob` 错误信息 |
| DirectX 12 | `D3DCompile` + PSO(管线状态对象) | 同上 |
| Metal | `MTLLibrary` 从源码 / 二进制 | `NSError` |
| WebGPU | `device.create_shader_module(WGSL)` | `device.push_error_scope` |

### 历史演化

- **2003 (OpenGL 1.5)**: ARB shader objects 扩展,首次有可编程 shader
- **2004 (OpenGL 2.0)**: GLSL 1.0 标准,内建 shader 语言
- **2008 (OpenGL 3.0)**: 几何 shader
- **2010 (OpenGL 4.0)**: 细分 shader
- **2013 (OpenGL 4.3)**: Compute shader
- **2016 (OpenGL 4.2)**: SPIR-V 二进制 shader 支持
- **2015 (Vulkan)**: 完全用 SPIR-V,放弃 GLSL runtime compile

Vulkan 抛弃 runtime GLSL 是因为厂商的 GLSL 编译器互不兼容,导致同一份 shader 在不同 GPU 行为微差。SPIR-V 是标准化二进制,语义严格定义。**未来方向**:所有现代 API 都走 SPIR-V 或类似二进制,GLSL runtime compile 慢慢边缘化。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:`glCreateShader` 和 `glCreateProgram` 各自做什么?为什么需要分开?

**参考解答**:
- `glCreateShader(type)` 创建一个 **shader object**,代表单个 shader 阶段(vertex / fragment / ...),状态包括源码、编译状态、InfoLog
- `glCreateProgram()` 创建一个 **program object**,代表多个 shader 链接后的可执行单元

分开的原因:**Shader 可以复用**。同一个 vertex shader 可以被多个 program attach。例如游戏里有 100 种材质,vertex shader 都一样(只做 MVP 变换),只有 fragment shader 不同。复用编译好的 vertex shader 节省 100 倍编译时间。

工业代码模式:维护一个 shader 缓存,key 是源码 hash,value 是编译后的 shader id。每次 `attach_shader` 前 query 缓存,hit 则复用。

### Lv2 · 动手实践

**题**:在 Rust + gl crate 项目里实现 `Shader::new(vs_src, fs_src) -> Result<Shader, ShaderError>`,要求:
- 编译失败时返回 `ShaderError::Compile { shader_type, log }`,log 是 InfoLog 字符串
- 链接失败时返回 `ShaderError::Link { log }`
- 成功时返回 `Shader`,Drop 自动 `glDeleteProgram`
- 提供 `use_program(&self)` 和 `uniform_loc(&self, name) -> GLint` 方法

**完成标准**:`cargo test shader` 通过,测试覆盖:正常 shader 编译成功、语法错误 shader 返回 Compile 错误、缺 main 的 shader 返回 Link 错误。

**参考解答**:

```rust
use gl::types::*;
use std::ffi::CString;

pub struct Shader {
    program: GLuint,
}

#[derive(Debug)]
pub enum ShaderError {
    Compile { shader_type: GLuint, log: String },
    Link { log: String },
}

impl std::fmt::Display for ShaderError {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        match self {
            ShaderError::Compile { shader_type, log } => write!(
                f, "Shader compile error (type {}):\n{}", shader_type, log
            ),
            ShaderError::Link { log } => write!(f, "Shader link error:\n{}", log),
        }
    }
}

impl std::error::Error for ShaderError {}

impl Shader {
    pub fn new(vs_src: &str, fs_src: &str) -> Result<Self, ShaderError> {
        let vs = Self::compile(vs_src, gl::VERTEX_SHADER)?;
        let fs = Self::compile(fs_src, gl::FRAGMENT_SHADER)?;
        let program = Self::link(vs, fs)?;

        // shader object 链接后可删除(program 持有字节码)
        unsafe {
            gl::DeleteShader(vs);
            gl::DeleteShader(fs);
        }

        Ok(Self { program })
    }

    fn compile(src: &str, shader_type: GLuint) -> Result<GLuint, ShaderError> {
        let shader_id = unsafe { gl::CreateShader(shader_type) };
        let c_src = CString::new(src).expect("Shader source contains NUL byte");

        unsafe {
            gl::ShaderSource(shader_id, 1, &c_src.as_ptr(), std::ptr::null());
            gl::CompileShader(shader_id);
        }

        let mut success = gl::FALSE as GLint;
        unsafe { gl::GetShaderiv(shader_id, gl::COMPILE_STATUS, &mut success); }

        if success == gl::FALSE as GLint {
            let log = Self::get_info_log(shader_id, true);
            unsafe { gl::DeleteShader(shader_id); }
            return Err(ShaderError::Compile { shader_type, log });
        }

        Ok(shader_id)
    }

    fn link(vs: GLuint, fs: GLuint) -> Result<GLuint, ShaderError> {
        let program = unsafe { gl::CreateProgram() };
        unsafe {
            gl::AttachShader(program, vs);
            gl::AttachShader(program, fs);
            gl::LinkProgram(program);
        }

        let mut success = gl::FALSE as GLint;
        unsafe { gl::GetProgramiv(program, gl::LINK_STATUS, &mut success); }

        if success == gl::FALSE as GLint {
            let log = Self::get_info_log(program, false);
            unsafe {
                gl::DeleteProgram(program);
            }
            return Err(ShaderError::Link { log });
        }

        Ok(program)
    }

    fn get_info_log(id: GLuint, is_shader: bool) -> String {
        let mut log_len = 0;
        unsafe {
            if is_shader {
                gl::GetShaderiv(id, gl::INFO_LOG_LENGTH, &mut log_len);
            } else {
                gl::GetProgramiv(id, gl::INFO_LOG_LENGTH, &mut log_len);
            }
        }

        if log_len == 0 {
            return String::new();
        }

        let mut log = vec![0u8; log_len as usize];
        unsafe {
            if is_shader {
                gl::GetShaderInfoLog(
                    id,
                    log_len,
                    std::ptr::null_mut(),
                    log.as_mut_ptr() as *mut GLchar,
                );
            } else {
                gl::GetProgramInfoLog(
                    id,
                    log_len,
                    std::ptr::null_mut(),
                    log.as_mut_ptr() as *mut GLchar,
                );
            }
        }

        // 去掉末尾的 NUL 字节
        if log[log_len as usize - 1] == 0 {
            log.pop();
        }
        String::from_utf8_lossy(&log).into_owned()
    }

    pub fn use_program(&self) {
        unsafe { gl::UseProgram(self.program); }
    }

    pub fn uniform_loc(&self, name: &str) -> GLint {
        let c_name = CString::new(name).expect("Uniform name contains NUL byte");
        unsafe { gl::GetUniformLocation(self.program, c_name.as_ptr()) }
    }
}

impl Drop for Shader {
    fn drop(&mut self) {
        unsafe { gl::DeleteProgram(self.program); }
    }
}
```

**关键解释**:
- `CString::new(src)` — Rust `&str` 转 C 字符串,自动加 `\0`。如果 src 含 `\0` 字节(罕见但可能),返回 Err,这里用 `expect` panic
- `GetShaderiv` 的 `iv` 后缀表示 "integer vector" — 返回多个 int 值到 buffer
- `INFO_LOG_LENGTH` 包含末尾的 `\0`,所以 buffer 多分配 1 字节
- `String::from_utf8_lossy` — InfoLog 理论是 ASCII,但有些驱动输出 UTF-8,lossy 转换安全
- 测试需要 GL context,这部分用 fixture 或者跳过(注释掉)

### Rust:完整 shader 管线 + 文件加载 + 热重载雏形

```rust
// Cargo.toml:
// [dependencies]
// gl = "0.14"
// glfw = "0.55"
// notify = "6.0"        # 文件监听
// parking_lot = "0.12"  # 高性能 Mutex

use gl::types::*;
use std::ffi::CString;
use std::path::{Path, PathBuf};
use std::sync::Arc;
use parking_lot::Mutex;
use notify::{Watcher, RecommendedWatcher, RecursiveMode, Event};

pub struct ShaderProgram {
    program: GLuint,
    uniform_cache: std::collections::HashMap<String, GLint>,
}

impl ShaderProgram {
    pub fn from_files(vs_path: &Path, fs_path: &Path) -> Result<Self, Box<dyn std::error::Error>> {
        let vs_src = std::fs::read_to_string(vs_path)?;
        let fs_src = std::fs::read_to_string(fs_path)?;
        let program = Self::build(&vs_src, &fs_src)?;
        Ok(Self {
            program,
            uniform_cache: Default::default(),
        })
    }

    fn build(vs_src: &str, fs_src: &str) -> Result<GLuint, ShaderError> {
        let vs = compile(vs_src, gl::VERTEX_SHADER)?;
        let fs = compile(fs_src, gl::FRAGMENT_SHADER)?;
        let program = link(vs, fs)?;
        unsafe {
            gl::DeleteShader(vs);
            gl::DeleteShader(fs);
        }
        Ok(program)
    }

    pub fn rebuild(&mut self, vs_src: &str, fs_src: &str) -> Result<(), ShaderError> {
        // 编译新 program,成功后替换旧的(原子操作)
        let new_program = Self::build(vs_src, fs_src)?;
        let old = std::mem::replace(&mut self.program, new_program);
        unsafe { gl::DeleteProgram(old); }
        self.uniform_cache.clear();  // uniform location 可能变
        Ok(())
    }

    pub fn use_program(&self) {
        unsafe { gl::UseProgram(self.program); }
    }

    pub fn set_uniform(&mut self, name: &str, value: &[f32; 16]) {
        // 缓存 uniform location,避免每次 glGetUniformLocation
        let loc = *self.uniform_cache
            .entry(name.to_string())
            .or_insert_with(|| {
                let c = CString::new(name.as_bytes()).unwrap();
                unsafe { gl::GetUniformLocation(self.program, c.as_ptr()) }
            });
        if loc >= 0 {
            unsafe {
                gl::UniformMatrix4fv(loc, 1, gl::FALSE, value.as_ptr());
            }
        }
    }
}

impl Drop for ShaderProgram {
    fn drop(&mut self) {
        unsafe { gl::DeleteProgram(self.program); }
    }
}

// 文件监听 + 热重载
pub struct ShaderHotReloader {
    watcher: RecommendedWatcher,
    pub pending_reload: Arc<Mutex<Option<PathBuf>>>,
}

impl ShaderHotReloader {
    pub fn new(shader_dir: &Path) -> std::io::Result<Self> {
        let pending = Arc::new(Mutex::new(None));
        let pending_clone = pending.clone();

        // notify 的回调
        let mut watcher = notify::recommended_watcher(
            move |res: std::result::Result<Event, _>| {
                if let Ok(event) = res {
                    if event.kind.is_modify() {
                        if let Some(path) = event.paths.first() {
                            *pending_clone.lock() = Some(path.clone());
                        }
                    }
                }
            }
        ).map_err(|e| std::io::Error::new(std::io::ErrorKind::Other, e))?;

        watcher.watch(shader_dir, RecursiveMode::NonRecursive)
            .map_err(|e| std::io::Error::new(std::io::ErrorKind::Other, e))?;

        Ok(Self {
            watcher,
            pending_reload: pending,
        })
    }

    pub fn take_pending(&self) -> Option<PathBuf> {
        self.pending_reload.lock().take()
    }
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // (init GLFW, OpenGL context)
    let shader_dir = Path::new("assets/shaders");
    let mut program = ShaderProgram::from_files(
        &shader_dir.join("cube.vert"),
        &shader_dir.join("cube.frag"),
    )?;
    let reloader = ShaderHotReloader::new(shader_dir)?;

    loop {
        // 处理热重载
        if let Some(changed_path) = reloader.take_pending() {
            println!("Reloading shader: {:?}", changed_path);
            match ShaderProgram::from_files(
                &shader_dir.join("cube.vert"),
                &shader_dir.join("cube.frag"),
            ) {
                Ok(new_program) => {
                    program = new_program;
                    println!("Shader reloaded successfully");
                }
                Err(e) => {
                    eprintln!("Shader reload failed: {}", e);
                    // 保留旧 program,继续渲染
                }
            }
        }

        program.use_program();
        // (rendering)
    }
}
```

**关键 Rust 特性解释**:
- `notify::recommended_watcher(callback)` — 跨平台文件监听,Linux 用 inotify,macOS 用 FSEvents,Windows 用 ReadDirectoryChangesW
- `Arc<Mutex<Option<PathBuf>>>` — 多线程共享状态,文件监听线程写,主线程读。`parking_lot::Mutex` 比 std::sync::Mutex 快 2-3 倍
- `std::mem::replace(&mut self.program, new)` — 原子替换字段值,返回旧值。先把新 program 替换进去,再 delete 旧的,避免渲染时 program 被释放
- `entry().or_insert_with()` — HashMap API,缓存 uniform location

**Troubleshooting**:

- **`gl::CreateShader returns 0`** — GL context 没初始化,检查 `window.make_current()`
- **InfoLog 是空的** — 调用顺序错,必须在 `CompileShader` 后查 `COMPILE_STATUS`,再读 InfoLog
- **uniform location 返回 -1** — uniform 名字写错,或者 shader 里声明但没用(被编译器优化掉)。检查 shader 里实际用了 uniform
- **shader 编译慢(数百 ms)** — 复杂 shader / 老驱动。Mesa cache 应自动缓存,第二次启动快
- **运行时崩溃,InfoLog 显示 driver bug** — 切换 Mesa backend:`MESA_LOADER_DRIVER_OVERRIDE=iris ./target/release/handmade_hero`
