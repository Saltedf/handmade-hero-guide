
# Day 264 · 性能分析器加按钮

> 昨天加了滑块,今天 Casey 把 profiler 的 UI 控件库从"只有滑块"扩到"滑块 + 按钮"。按钮看似简单——画个矩形、检测鼠标点击——但"什么时候算点击"涉及一个被无数初学者搞错的细节:**鼠标按下 vs 鼠标抬起**。

## 0 · 为什么要有这一天

你的 profiler 现在能显示柱状图 + 滑块,但是没法切换视图模式。你想要的:

- 点 "**Top Clocks**" 按钮 → 切换到顶级时钟视图(看哪些函数最耗时)
- 点 "**Memory**" 按钮 → 切换到内存查看器
- 点 "**Reset**" 按钮 → 清空历史数据
- 点 "**Save**" 按钮 → 把当前帧的 profile 导出 JSON

每个按钮都需要一个"被点击"事件。看起来 trivial,但实际写起来你会撞到三个常见坑:

**坑 1:点击时机不对**。新手写的代码往往在鼠标按下(mouse_down)时就触发点击。这有两个问题:(a) 用户按下后改变主意,把鼠标拖出按钮再松开,理应取消,但你已经触发了;(b) 如果按下时弹出一个新 UI 覆盖了按钮,松开事件不会发到这个按钮,但点击已经触发。

**坑 2:重复触发**。鼠标按住不放,每帧都会触发 mouse_down——如果你的代码在每帧检查 mouse_down,会触发 60 次/秒的点击。要在"按下"那一帧触发,而不是"按住"。

**坑 3:多按钮抢鼠标**。两个按钮重叠,鼠标同时点中两个,谁响应?需要"鼠标捕获"机制。

工业级 UI 框架(Qt / GTK / egui / Dear ImGui)都按统一规则解决这些问题:

- **点击 = 鼠标在按钮内按下 + 在按钮内抬起**(中间可以拖出去,但松开时必须在按钮上才算点击)
- **每次点击只触发一次**(检测"刚按下"而非"按住")
- **鼠标按下后捕获**:按下后即使拖到外面,后续 move/up 事件都只发给这个按钮,直到松开

今天 Casey 把这套规则实现出来。完成后你的 profiler 有了一个可扩展的按钮系统,后面加多少按钮都行。

心理锚点:做完这个,你能写出"在按钮上按下 → 拖到外面 → 松开,不触发点击"这种行为正确的按钮。

## 1 · Casey 今天做了什么

Casey 在 profiler overlay 上加了 3-4 个按钮(Top Clocks / Memory / Reset / Save),每个按钮做以下事情:

1. 在屏幕上画一个矩形 + 文字(按钮的视觉表示)
2. 维护一个 `is_pressed: bool` 字段,记录按钮当前是否被按下
3. 处理三种鼠标事件:Down / Move / Up
4. 在 Down 时如果鼠标在按钮内,设置 `is_pressed = true`,并标记"鼠标被此按钮捕获"
5. 在 Move 时无需特殊处理(只是更新 hover 状态)
6. 在 Up 时如果 `is_pressed == true` 且鼠标还在按钮内,触发 click 回调
7. 触发后清掉 `is_pressed`

Casey 在视频里演示了边界情况:按下后拖到按钮外松开,不触发;按下后拖回按钮内松开,触发——这就是"工业级"按钮的行为。

Casey 还把所有按钮组织成一个数组,用一个统一的 `ui_handle_mouse(buttons, event)` 函数处理,而不是每个按钮单独 handle。这是 UI 系统从"分散处理"走向"集中管理"的一步。

## 2 · 心智模型

### 类比:现实里的物理按钮

想象一个电梯按钮。你按下它(物理位移),它的电路接通——但电梯调度系统**不会**立即响应。它要等你**松开**才认为这是一次"完整的点击"。为什么?

因为按下后你可能会"想按但改主意"——比如发现按错了楼层。这时你按住不放,把手指拖到旁边(物理上不能,但你懂意思),松开时手指不在按钮感应区。电梯**不会**响应这次"按了一半"的操作。

UI 按钮的设计完全一样:**只有"按下 + 抬起"都在按钮上,才算一次点击**。这是 1980 年代 Apple Lisa / Macintosh 定下的 GUI 标准规范,沿用至今。

### 严谨原理:点击的状态机

按钮是一个 4 状态的有限状态机:

```
[Idle]
  |
  | mouse_down + hit_test
  v
[Pressed]
  |
  | mouse_up + hit_test
  v
[Clicked] (触发回调,瞬间回到 Idle)
```

或者按下后拖出按钮:

```
[Idle] -> [Pressed] (mouse_down)
[Pressed] -> [HoverOutside] (mouse_move, no longer in button)
[HoverOutside] -> [Pressed] (mouse_move, back in button)
[HoverOutside] -> [Idle] (mouse_up outside, no click)
```

实际上更简化:**只有"鼠标抬起时鼠标在按钮内 + 按钮 is_pressed"才算点击**。中间过程不重要,只看终态。

伪代码:

```
fn handle_event(event, button):
    if event == MouseDown:
        if hit_test(mouse_x, mouse_y):
            button.is_pressed = true
            captured_button = button  # 全局捕获标志
    elif event == MouseUp:
        if button.is_pressed and hit_test(mouse_x, mouse_y):
            button.on_click()
        button.is_pressed = false
        captured_button = None
    elif event == MouseMove:
        # 不影响点击判定,但可以更新 hover 状态
        button.is_hovered = hit_test(mouse_x, mouse_y)
```

### 多按钮的事件路由

多个按钮共存时,事件路由有两种策略:

**策略 1:Z-order 优先(从上层往下)**

```
for button in buttons.iter().rev():  # 反向遍历,最后画的在最上层
    if button.handle_event(event):
        break  # 事件被消费,不再传给下层
```

**策略 2:鼠标捕获独占**

```
if let Some(captured) = captured_button:
    # 事件只发给被捕获的按钮
    captured.handle_event(event)
else:
    # 没捕获时,Z-order 找第一个命中的
    for button in buttons.iter().rev():
        if button.hit_test(mx, my):
            button.handle_event(event)
            break
```

Casey 选了**策略 2**——一旦按下,后续事件归一个按钮独享。这避免了"按下后拖到下层按钮上,下层按钮触发"的混乱。

### 按钮 vs 滑块的事件模型差异

昨天的滑块和今天的按钮都是 UI 控件,但事件模型不同:

| 控件 | 何时算"激活" | 持续输出 |
|---|---|---|
| 按钮 | Up 时(且 Down 也在) | 单次(回调) |
| 滑块 | Down 后立即开始 | 持续(值变化) |
| 复选框 | Up 时 | 单次(切换状态) |
| 文本框 | Down 时聚焦 | 持续(键盘事件) |

理解这些差异是 UI 编程的核心。

### Immediate-mode 的简化

Immediate-mode GUI(我们用的范式)有一个观察:**很多 UI 状态其实可以"每帧重新计算"**。按钮的 `is_pressed` 状态可以不存,每帧检测:

```rust
fn button(id: &str, x: i32, y: i32, w: i32, h: i32, is_mouse_down: bool, mx: i32, my: i32) -> bool {
    let hovered = mx >= x && mx < x + w && my >= y && my < y + h;
    let was_pressed_last_frame = ui_state.last_pressed == Some(id);
    let clicked = hovered && is_mouse_down && !was_pressed_last_frame;

    if hovered && is_mouse_down {
        ui_state.last_pressed = Some(id);
    } else if !is_mouse_down {
        ui_state.last_pressed = None;
    }

    draw_rect(x, y, w, h, if hovered { HOVER_COLOR } else { NORMAL_COLOR });
    draw_text(x, y, id);

    clicked
}
```

每次调用 `button(...)` 都返回"这次是否被点击"。状态只在 `ui_state.last_pressed` 这一个全局字段里。这是 Dear ImGui 的核心 trick。

Casey 没完全用 immediate-mode(他的代码有 retained state),但思想是一致的:**把"按下 + 抬起"的逻辑用最小状态表达**。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏 UI 按钮有几个特殊考量:

1. **手柄支持**:不仅是鼠标,还要响应手柄 A 键。A 键按下 + 释放 = 点击
2. **键盘焦点**:Tab 键切换焦点,Enter 触发
3. **触摸支持**:手机上没有 hover 状态,只有 touch_down / touch_up
4. **触觉反馈**:控制器震动反馈按钮按下(次世代主机标配)

Casey 的 HH 是 PC-only,但他保留了 multi-input 接口(Phase 1 做的),后面可以扩展。

按钮的设计还有一个常被忽视的细节:**激活区不要等于视觉区**。视觉区可能比激活区小(为了好看),但激活区应该比视觉区大一点(防止边缘点击 miss)。这是 Fitts's Law(费茨定律)的应用——更大的可点击目标 = 更快的操作。

### 3.2 · 🐧 Linux 系统编程视角

Linux 上的 GUI 工具包(X11 / Wayland / GTK / Qt)有一套标准的事件分发机制。最底层是 **X11 event** 或 **Wayland event**,通过 socket 从显示服务器发到客户端。

```bash
# 看你正在用的 X11 还是 Wayland
echo $XDG_SESSION_TYPE
# 输出:x11 或 wayland

# 看当前窗口收到的事件(用 xev)
sudo pacman -S xorg-xev
xev
# 把鼠标移到打开的白框里,看终端输出的事件流:
# ButtonPress event, button 1, ...
# ButtonRelease event, button 1, ...
# MotionNotify event, ...
```

`xev` 是 X11 event viewer,你能看到鼠标按下、移动、抬起的每个事件。Casey 在 Windows 上的 `WM_LBUTTONDOWN` / `WM_LBUTTONUP` 对应 Linux 的 `ButtonPress` / `ButtonRelease`,语义完全一致——按钮事件模型是跨平台的。

Rust 生态用 `winit` crate 跨平台抽象这些事件:`WindowEvent::MouseInput { state: Pressed/Released, button: Left, ... }`。

### 3.3 · 🦀 Rust 生态视角

Rust 表达"按钮被点击的回调"有几种风格:

#### 风格 1:函数指针 `fn()`

```rust
struct Button {
    on_click: Option<fn()>,
}

impl Button {
    fn click(&self) {
        if let Some(f) = self.on_click {
            f();
        }
    }
}

fn do_save() { /* ... */ }

let b = Button { on_click: Some(do_save) };
b.click();
```

简单,但函数指针不能捕获环境(闭包不行)。

#### 风格 2:闭包 `Box<dyn Fn()>`

```rust
struct Button {
    on_click: Box<dyn Fn()>,
}

let data = save_path.clone();
let b = Button {
    on_click: Box::new(move || {
        std::fs::write(&data, "...").unwrap();
    }),
};
```

闭包可以捕获环境(`save_path`),灵活,但有堆分配(Box)。

#### 风格 3:枚举事件 + 中央处理

```rust
enum UiEvent {
    SaveClicked,
    ResetClicked,
    SwitchView(ViewType),
}

struct Button {
    label: &'static str,
    event: UiEvent,
}

// 在主循环里
for button in &buttons {
    if button.click_test(mx, my, is_down, is_up) {
        match button.event {
            UiEvent::SaveClicked => do_save(),
            UiEvent::ResetClicked => do_reset(),
            UiEvent::SwitchView(v) => switch_view(v),
        }
    }
}
```

没有闭包,没有堆分配,事件集中处理。Casey 选这种风格,因为 HH 是 C,没法用闭包。Rust 端我们也走这条路,因为它最 Rust-y(显式 match + 无分配)。

#### 风格 4:`egui` 的 immediate-mode

```rust
if ui.button("Save").clicked() {
    do_save();
}
```

一行搞定,但是背后是复杂的 immediate-mode 状态管理。适合"只关心结果"的项目,不适合学习阶段。

### 3.4 · UI 控件系统的演化

UI 控件从简单到复杂:

1. **1970s Xerox PARC**:第一个 GUI,按钮 = 矩形 + 鼠标按下事件
2. **1980s Macintosh**:规范化"按下 + 抬起"算点击
3. **1990s MFC / Win32**:消息循环 + WndProc,事件驱动
4. **2000s Qt / GTK**:signal / slot,信号槽抽象
5. **2010s Web DOM**:事件冒泡 + 捕获
6. **2010s+ Immediate GUI**:每帧重画,极简状态

每种都有 trade-off,但**"按下 + 抬起都在按钮上才算点击"是所有框架的共识**。

## 5 · 对照与变奏

### 不同 UI 框架的按钮行为差异

| 框架 | 拖出按钮再松开 | 拖入按钮再松开 | 长按重复 |

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:有人说"按钮在 mouse_down 时触发更敏捷,用户体验更好"。请反驳,给出至少 3 个理由说明为什么"在 mouse_up 时触发"才是正确的工业标准。

**参考解答**:
1. **可取消性**:用户按下后改主意(发现按错了 / 弹窗挡住了 / 不小心碰到),可以拖出按钮再松开来取消。down 时触发就没机会反悔
2. **防止误触**:触摸屏上手指落下时容易抖动一下,容易"按到旁边的按钮"。up 时鼠标 / 手指已经在用户真正想按的按钮上,更准确
3. **一致性**:所有主流 OS(macOS / Windows / Linux)都这么做,违反习惯会让用户困惑
4. **支持拖拽**:如果 button 是 DnD(drag-and-drop)源,down 时进入拖拽状态,up 时如果没拖远就触发点击——必须用 up 才能区分
5. **错误恢复**:down 时如果代码 panic 或弹错误对话框,用户还能"取消",up 时触发后用户能预览
6. **触摸优化**:触摸屏没有 hover 状态,必须用 up 来确认意图

### Lv2 · 动手实践

**题**:实现一个 `Button` 控件,完整支持"按下 + 抬起"点击语义。要求:

- `new(x, y, w, h, label)` 构造
- `handle_mouse_down(mx, my)` 返回 bool(是否被命中并开始按下)
- `handle_mouse_up(mx, my)` 返回 `Option<UiEvent>`(Some 表示点击触发,None 表示未触发)
- `draw(canvas)` 绘制按钮(按下时颜色变深)

测试:画 3 个按钮(Save / Load / Reset),模拟鼠标事件序列:
- 在 Save 上 down,Save 上 up → 触发 SaveClicked
- 在 Load 上 down,Reset 上 up → 不触发
- 在 Reset 上 down,Reset 上 up → 触发 ResetClicked

完成标准:三个测试都打印正确的事件。

**参考解答**:

```rust
#[derive(Debug, PartialEq)]
enum UiEvent {
    SaveClicked,
    LoadClicked,
    ResetClicked,
}

struct Button {
    x: i32, y: i32, w: i32, h: i32,
    label: &'static str,
    event: UiEvent,
    is_pressed: bool,    // 当前是否被按下
    was_pressed_inside: bool,  // 是否按下时在按钮内(避免按下后拖到这个按钮上也算)
}

impl Button {
    fn new(x: i32, y: i32, w: i32, h: i32, label: &'static str, event: UiEvent) -> Self {
        Self {
            x, y, w, h, label, event,
            is_pressed: false,
            was_pressed_inside: false,
        }
    }

    fn hit_test(&self, mx: i32, my: i32) -> bool {
        mx >= self.x && mx < self.x + self.w && my >= self.y && my < self.y + self.h
    }

    fn handle_mouse_down(&mut self, mx: i32, my: i32) -> bool {
        if self.hit_test(mx, my) {
            self.is_pressed = true;
            self.was_pressed_inside = true;
            true
        } else {
            // 别的按钮按下时,确保本按钮 is_pressed 是 false
            self.is_pressed = false;
            self.was_pressed_inside = false;
            false
        }
    }

    fn handle_mouse_up(&mut self, mx: i32, my: i32) -> Option<&UiEvent> {
        let triggered = self.is_pressed && self.was_pressed_inside && self.hit_test(mx, my);
        self.is_pressed = false;
        self.was_pressed_inside = false;
        if triggered {
            Some(&self.event)
        } else {
            None
        }
    }

    fn draw(&self, buffer: &mut [u32], buf_w: usize, buf_h: usize) {
        let color = if self.is_pressed { 0xFF606060 } else { 0xFF808080 };
        for py in self.y..(self.y + self.h) {
            for px in self.x..(self.x + self.w) {
                if (px as usize) < buf_w && (py as usize) < buf_h {
                    buffer[(py as usize) * buf_w + (px as usize)] = color;
                }
            }
        }
        // 实际项目还要画文字 label
    }
}

fn main() {
    let mut buttons = vec![
        Button::new(100, 100, 80, 30, "Save", UiEvent::SaveClicked),
        Button::new(200, 100, 80, 30, "Load", UiEvent::LoadClicked),
        Button::new(300, 100, 80, 30, "Reset", UiEvent::ResetClicked),
    ];

    // 测试 1:Save 上 down + up
    for b in buttons.iter_mut() { b.handle_mouse_down(140, 115); }
    for b in buttons.iter_mut() {
        if let Some(e) = b.handle_mouse_up(140, 115) {
            println!("Test 1 triggered: {:?}", e);
        }
    }

    // 测试 2:Load 上 down,Reset 上 up
    for b in buttons.iter_mut() { b.handle_mouse_down(240, 115); }
    for b in buttons.iter_mut() {
        if let Some(e) = b.handle_mouse_up(340, 115) {
            println!("Test 2 triggered: {:?}", e);
        }
    }
    // 应该什么都不打印

    // 测试 3:Reset 上 down + up
    for b in buttons.iter_mut() { b.handle_mouse_down(340, 115); }
    for b in buttons.iter_mut() {
        if let Some(e) = b.handle_mouse_up(340, 115) {
            println!("Test 3 triggered: {:?}", e);
        }
    }
}
```

**每行解释**:
- `event: UiEvent` 把"按钮被点击"事件抽象成数据,避免闭包和函数指针
- `is_pressed` 跟踪按钮当前是否处于"按下"状态
- `was_pressed_inside` 记录"按下时是否在本按钮内",这是处理"拖入按钮"的关键
- `handle_mouse_down` 同时清掉其他按钮的 is_pressed(全 mouse down 时只有一个按钮被按下)
- `handle_mouse_up` 用三个条件判断:is_pressed(本按钮被按下)+ was_pressed_inside(按下时在本按钮内)+ hit_test(松开时也在本按钮内)

### Lv3 · 迁移设计

**题**:实现一个 **toggle button**(切换按钮),点击切换 on/off 状态。和普通 button 不同:

- 视觉上有两个状态:On(高亮)/ Off(灰色)
- 点击切换状态(on → off,off → on)
- 状态需要保留,所以不能用 immediate-mode 的"每帧重算"

要求:
- `Toggle::new(initial: bool)`
- `click()` 切换状态,返回新状态
- `draw()` 根据 on 状态画不同颜色

提示:状态保留用 `&mut self.is_on`。和普通按钮的差异在于 click 后状态不归零。

## 8 · Rust / Arch 落地代码

### 完整可跑:profiler 带 4 个按钮

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, MouseMode, MouseButton, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;

#[derive(Clone, Copy, Debug, PartialEq)]
enum ViewMode {
    BarChart,
    TopClocks,
    Memory,
}

#[derive(Clone, Copy, Debug)]
enum UiEvent {
    SwitchView(ViewMode),
    Reset,
    Save,
}

struct Button {
    x: i32, y: i32, w: i32, h: i32,
    label: &'static str,
    event: UiEvent,
    is_pressed: bool,
    was_pressed_inside: bool,
}

impl Button {
    fn new(x: i32, y: i32, w: i32, h: i32, label: &'static str, event: UiEvent) -> Self {
        Self { x, y, w, h, label, event, is_pressed: false, was_pressed_inside: false }
    }

    fn hit_test(&self, mx: i32, my: i32) -> bool {
        mx >= self.x && mx < self.x + self.w && my >= self.y && my < self.y + self.h
    }

    fn handle_mouse_down(&mut self, mx: i32, my: i32) -> bool {
        if self.hit_test(mx, my) {
            self.is_pressed = true;
            self.was_pressed_inside = true;
            true
        } else {
            self.is_pressed = false;
            self.was_pressed_inside = false;
            false
        }
    }

    fn handle_mouse_up(&mut self, mx: i32, my: i32) -> Option<UiEvent> {
        let triggered = self.is_pressed && self.was_pressed_inside && self.hit_test(mx, my);
        self.is_pressed = false;
        self.was_pressed_inside = false;
        if triggered { Some(self.event) } else { None }
    }

    fn draw(&self, buffer: &mut [u32], buf_w: usize, buf_h: usize) {
        let color = if self.is_pressed { 0xFF606060 } else { 0xFF808080 };
        for py in self.y..(self.y + self.h) {
            for px in self.x..(self.x + self.w) {
                if (px as usize) < buf_w && (py as usize) < buf_h {
                    buffer[(py as usize) * buf_w + (px as usize)] = color;
                }
            }
        }
    }
}

fn draw_rect(buffer: &mut [u32], w: usize, h: usize, x: i32, y: i32, rw: i32, rh: i32, color: u32) {
    for py in y.max(0)..(y + rh).min(h as i32) {
        for px in x.max(0)..(x + rw).min(w as i32) {
            buffer[(py as usize) * w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Profiler Buttons Demo", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();
    let mut current_view = ViewMode::BarChart;
    let mut frame_history: [f32; 64] = [0.0; 64];
    let mut frame_head = 0usize;

    let buttons: Vec<Button> = vec![
        Button::new(20,  20, 100, 30, "Bar",  UiEvent::SwitchView(ViewMode::BarChart)),
        Button::new(130, 20, 100, 30, "Clocks", UiEvent::SwitchView(ViewMode::TopClocks)),
        Button::new(240, 20, 100, 30, "Mem",  UiEvent::SwitchView(ViewMode::Memory)),
        Button::new(350, 20, 100, 30, "Reset", UiEvent::Reset),
        Button::new(460, 20, 100, 30, "Save",  UiEvent::Save),
    ];
    let mut buttons = buttons;

    // 鼠标状态
    let mut was_mouse_down = false;

    while window.is_open() && !window.is_key_down(Key::Escape) {
        // 计时
        let now = Instant::now();
        let dt_ms = now.duration_since(last_time).as_secs_f32() * 1000.0;
        last_time = now;

        // 记录历史(只在 BarChart 视图)
        frame_history[frame_head] = dt_ms;
        frame_head = (frame_head + 1) % 64;

        // 鼠标状态
        let (mx_f, my_f) = window.get_mouse_pos(MouseMode::Discard).unwrap_or((-1.0, -1.0));
        let (mx, my) = (mx_f as i32, my_f as i32);
        let is_mouse_down = window.get_mouse_down(MouseButton::Left);

        // 检测"刚按下"和"刚抬起"
        let mouse_down_event = is_mouse_down && !was_mouse_down;
        let mouse_up_event = !is_mouse_down && was_mouse_down;
        was_mouse_down = is_mouse_down;

        // 路由事件
        if mouse_down_event {
            for b in buttons.iter_mut() {
                b.handle_mouse_down(mx, my);
            }
        }
        if mouse_up_event {
            for b in buttons.iter_mut() {
                if let Some(event) = b.handle_mouse_up(mx, my) {
                    println!("Event: {:?}", event);
                    match event {
                        UiEvent::SwitchView(v) => current_view = v,
                        UiEvent::Reset => {
                            frame_history = [0.0; 64];
                            frame_head = 0;
                        }
                        UiEvent::Save => {
                            std::fs::write("profile.json", "{\"view\":\"bar\"}").unwrap();
                            println!("Saved to profile.json");
                        }
                    }
                }
            }
        }

        // 清屏
        for px in buffer.iter_mut() { *px = 0xFF101010; }

        // 画按钮
        for b in &buttons {
            b.draw(&mut buffer, WIDTH, HEIGHT);
        }

        // 根据 view 画主内容
        match current_view {
            ViewMode::BarChart => {
                let chart_x = 50i32;
                let chart_y = 80i32;
                let chart_w = 700i32;
                let chart_h = 200i32;
                draw_rect(&mut buffer, WIDTH, HEIGHT, chart_x, chart_y, chart_w, chart_h, 0xFF202020);
                for (i, v) in frame_history.iter().enumerate() {
                    let bx = chart_x + (i as i32 * chart_w / 64);
                    let top_y = chart_y + ((1.0 - (*v / 50.0).max(0.0).min(1.0)) * chart_h as f32) as i32;
                    draw_rect(&mut buffer, WIDTH, HEIGHT, bx, top_y, chart_w / 64, chart_y + chart_h - top_y, 0xFF4040FF);
                }
            }
            ViewMode::TopClocks => {
                draw_rect(&mut buffer, WIDTH, HEIGHT, 50, 80, 700, 200, 0xFF202020);
                // 实际项目画 top clocks 排行榜
            }
            ViewMode::Memory => {
                draw_rect(&mut buffer, WIDTH, HEIGHT, 50, 80, 700, 200, 0xFF202020);
                // 实际项目画内存视图
            }
        }

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `was_mouse_down` 实现"边沿检测"——只在按下 / 抬起的瞬间触发事件,而不是每帧
- `Vec<Button>` 用 `iter_mut()` 遍历,可变借用所有按钮
- `match event` 强制覆盖所有 UiEvent 分支,加新事件编译器报错提醒
- `frame_history = [0.0; 64]` 重新初始化数组,Reset 功能
- `[f32; 64]` 是栈上定长数组,无堆分配

**Troubleshooting**:

- 点击没反应 — 检查 `was_mouse_down` 边沿检测逻辑,可能逻辑反了
- 按下后拖到另一按钮上,松开两个都触发 — 没正确清掉其他按钮的 is_pressed,确保 down 时只一个按钮 is_pressed=true
- Reset 没清掉柱状图 — frame_history 重新初始化,但 frame_head 也得归零,否则下一次 record 会写错位置
