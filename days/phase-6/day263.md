
# Day 263 · 加调试帧滑块

> 昨天的柱状图能看趋势,但是不能"暂停"看某一帧的细节。今天 Casey 给 profiler 加一个时间滑块——拖动它就能让游戏冻结在历史中的某一帧,所有调试视图都同步显示那一帧的数据。

## 0 · 为什么要有这一天

昨天的多帧柱状图能让你看到"第 50 帧附近有个尖峰"。但你想知道那个尖峰帧**到底为什么慢**——是 update 慢?render 慢?还是某个 entity 创建了 1000 个子 entity?要回答这个问题,你需要看那一帧的火焰图,而火焰图是"当前帧"的视图。

这就出现矛盾:

- 柱状图告诉你"哪些帧慢"——时间维度的概览
- 火焰图告诉你"哪些 block 慢"——单帧维度的细节

但你不能"在柱状图上选中第 50 帧,然后看它的火焰图"。游戏在实时跑,你看到第 50 帧的火焰图时它已经过去了。

Casey 今天的解决方案:**加一个帧滑块,让你能"穿越回过去"**。拖动滑块到第 50 帧,游戏暂停,所有 debug 视图(火焰图、实体查看器、内存查看器)都显示那一帧的快照。这是工业级 profiler(Unreal Insights / RenderDoc)的标准功能,叫 **scrubbing** 或 **timeline scrubbing**。

实现这件事的工程难点:

1. **冻结游戏逻辑**:不是真的"暂停游戏",而是"重放历史帧"。或者更简单的"暂停游戏但保留历史帧数据"
2. **UI 控件**:实现一个滑块(鼠标按下 + 拖动 = 选帧)
3. **状态机**:profiler 现在有两种模式——"实时跟随最新帧" vs "锁定到某帧"。需要明确状态切换
4. **联动**:滑块改变后,所有 debug 视图要重新查询数据

心理锚点:做完这个,你的 profiler 终于像个**真正的调试工具**,能让你"细查"任何一个历史帧。

## 1 · Casey 今天做了什么

Casey 在 profiler overlay 上加了一个 horizontal slider:

1. 在柱状图下方画一个长条矩形作为滑块背景
2. 画一个圆点(或小矩形)表示当前选中的位置
3. 检测鼠标在滑块区域内的按下 + 拖动事件,把鼠标 X 转换成 frame index
4. 引入一个 `selected_frame: Option<usize>` 字段,Some(i) 表示锁定到第 i 帧,None 表示跟随最新帧
5. 所有 debug 视图查询数据时,优先用 `selected_frame`,None 时回退到 head-1

Casey 在视频里演示了一个使用场景:看到柱状图一个尖峰,点一下对应位置,游戏画面冻结,火焰图显示那一帧的详细数据。他立即看到了某个 block "load_texture" 占了 12ms——卡顿原因找到了。

Casey 还加了一个**"播放"按钮**:点击后游戏从当前 selected_frame 继续跑,而不是从最新帧继续。这让"倒回 + 重放"成为可能,虽然 HH 没真做完整重放(需要 deterministic),但 UI 已经预留了。

## 2 · 心智模型

### 类比:视频播放器的进度条

你用过 YouTube / B 站的进度条吗?这就是 slider 的典型应用。视频播放器的状态机:

- **播放中**:进度条自动右移,选 None(自动跟随)
- **拖动进度条**:进度条跳到鼠标位置,视频跳到对应时间,选 Some(t)
- **暂停**:进度条不动,选 Some(t)(锁定)

游戏 profiler 的状态机一模一样:

- **跟随模式**(默认):selected = None,所有视图显示 head-1 这一帧
- **锁定模式**:selected = Some(i),所有视图显示 frames[i] 这一帧
- **切换**:用户点滑块 → 切到锁定;用户点"播放"按钮 → 切回跟随

### 严谨原理:UI 控件的事件处理

滑块是一个**有状态**的 UI 控件,有三种状态:

```
[Idle] --mouse_down_in_thumb--> [Dragging]
[Dragging] --mouse_up--> [Idle]
[Dragging] --mouse_move--> [Dragging, update value]
```

实现时需要一个布尔字段 `is_dragging: bool`,在 mouse down 时设为 true,mouse up 时设为 false。期间每帧检查鼠标 X,把它转换成滑块值。

#### 鼠标 X 到滑块值的映射

假设滑块的屏幕区域是 `[slider_x, slider_x + slider_w]`,数据范围是 `[0, N)`,那么:

```
normalized = (mouse_x - slider_x) / slider_w  // 0..1
frame_idx = (normalized * N) as usize          // 0..N-1
frame_idx = frame_idx.min(N - 1)               // clamp 防越界
```

注意三点:

1. **clamp 防越界**:鼠标可能拖到滑块外,要 clamp 到 [0, N-1]
2. **整数转换**:`as usize` 是 truncation,0.99 → 0,所以 `* N` 之后立即取整是合理的
3. **取模防止回绕**:如果 N=64 而 normalized 算成 1.0,frame_idx 会变成 64,超出索引——clamp 处理

#### 全局事件 vs 局部事件

UI 控件处理鼠标事件有个常见 bug:**多个控件抢同一个鼠标事件**。比如你的滑块和某个按钮重叠,鼠标按下时两个控件都响应。

解决方法是**事件捕获 + 传播**:

1. 鼠标按下时,找到最上层(最后画的、最上面的)控件
2. 把"按下"事件只发给这个控件,标记 `is_dragging = true`
3. 后续 mouse move / mouse up 事件只发给 `is_dragging = true` 的控件
4. mouse up 时清掉所有控件的 `is_dragging`

Casey 在 Day 264 处理按钮时会更详细做这套机制,今天先针对滑块单控件实现。

### 联动:所有视图查询数据时尊重 selected_frame

代码改造点:

```rust
impl Profiler {
    fn current_frame(&self) -> &FrameProfile {
        match self.selected_frame {
            Some(i) => &self.frames[i % FRAME_HISTORY],
            None => {
                // head 指向"下一帧要写的",所以最新已写的是 head-1(回绕后)
                let latest = if self.head == 0 { FRAME_HISTORY - 1 } else { self.head - 1 };
                &self.frames[latest]
            }
        }
    }
}
```

所有 debug 视图(UI 列表、火焰图、内存查看器)都改成调 `profiler.current_frame()` 而不是直接访问 `frames[head-1]`。这是一个**单一职责**的改造:`current_frame()` 封装了"实时 vs 锁定"的判断,视图代码完全不用关心。

### 状态机的可视化

把状态画在屏幕上对调试很有帮助。Casey 在滑块旁边画一个小图标:

- "▶" 表示跟随模式
- "⏸" 表示锁定模式

这是用户体验细节,但避免了"我刚才点了什么"的迷惑。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏开发里"scrubbing"是工业级调试器的核心功能。能 scrubbing 意味着游戏必须**保留足够的历史**,这有几个等级:

1. **Level 1(今天做的)**:只保留 profiler 数据,游戏画面 / 实体不保留。scrubbing 只能看火焰图
2. **Level 2**:保留实体快照(位置、状态),scrubbing 时画面也能回到那一帧的样子。需要 GB 级存储
3. **Level 3**:完整 deterministic replay——给定初始状态 + 输入序列,任意时刻都能重现。这是最严格的,需要确定性物理、确定性浮点、确定性随机
4. **Level 4(极限)**:time-travel debugging——任意时刻都能"修改"历史然后继续跑。这是 GDB 的 reverse-debugging 的游戏版

Unreal Insights、Unity Frame Debugger、RenderDoc 都是 Level 2-3。Casey 在 HH 走的是 Level 1 + 局部 Level 2,够教学用。

游戏 profiler 还有一个常见衍生:**snapshot 模式**。点一下"截帧"按钮,把当前帧的所有数据(JSON / 二进制)存到磁盘,然后离线用专门工具分析。这是 RenderDoc 的工作方式。

### 3.2 · 🐧 Linux 系统编程视角

Linux 上有现成的"录制 + 重放"工具:**`rr` debugger**(Mozilla 出的)。它能录一个程序的所有 syscall + 信号 + 内存访问,然后任意位置都能 scrub 重放。底层原理和 Level 3 deterministic replay 一样,但 rr 用了 CPU 的性能计数器和 syscall hook 实现低开销录制。

```bash
# Arch Linux 安装
sudo pacman -S rr

# 录制一个程序
rr record ./your_game

# 重放,任意时刻都能 scrub
rr replay
# 在 gdb 里用 reverse-continue / reverse-step
```

`rr` 是学习"状态机 + 时间维度"的最佳工具。游戏 profiler 是它的简化版。

另一个相关工具是 **`perf script`** + Python 脚本——`perf record` 录下来的事件流是按时间排序的,perf script 让你写脚本过滤 / 聚合事件。这相当于"命令行版的 profiler scrubbing"。

### 3.3 · 🦀 Rust 生态视角

Rust 表达"selected 状态"用 `Option<usize>` 是天然选择:

- `None` 表示"无选择,跟随最新"
- `Some(i)` 表示"锁定到 i"

比 C 的 `int selected = -1`(用 -1 表示 None)更安全——你不可能不小心把 -1 当成索引用,Rust 编译器强制你处理 None 分支。

#### 用 enum 表达状态机

更严谨的设计是用 enum:

```rust
enum ScrubState {
    Live,                       // 跟随最新帧
    Paused { frame_idx: usize },// 锁定到某帧
}
```

这比 `Option<usize>` 更显式地表达"这不是普通 Option,这是 UI 状态机"。但代码改动会大一些,Casey 选了简化版本(Option)。

#### 闭包封装事件处理

滑块的事件处理可以这样封装:

```rust
impl Slider {
    fn handle_event(&mut self, event: &MouseEvent) -> Option<usize> {
        // 返回 Some(new_value) 如果值变了,None 如果没变
        match event {
            MouseEvent::Down { x, y } if self.hit_test(*x, *y) => {
                self.is_dragging = true;
                Some(self.x_to_value(*x))
            }
            MouseEvent::Move { x, .. } if self.is_dragging => {
                Some(self.x_to_value(*x))
            }
            MouseEvent::Up { .. } => {
                self.is_dragging = false;
                None
            }
            _ => None,
        }
    }
}
```

返回 `Option<usize>` 让调用者决定要不要响应——这是 Rust 表达"可能有变化也可能没变"的标准方式。C 时代常用 `bool *changed` out parameter,丑且容易忘检查。

### 3.4 · 状态机理论

UI 控件本质是**有限状态机**(FSM,Finite State Machine)。形式定义:一个 FSM 是 `(Q, Σ, δ, q0, F)`:

- `Q`:状态集合(本例:{Idle, Dragging})
- `Σ`:输入字母表(本例:{MouseDown, MouseMove, MouseUp})
- `δ: Q × Σ → Q`:状态转移函数
- `q0 ∈ Q`:初始状态(本例:Idle)
- `F ⊆ Q`:终止状态集(本例:无,UI 控件一般无终止状态)

工程实现时,FSM 用 `enum State` + `match` 表达,Rust 编译器会强制你覆盖所有 `State × Event` 组合(用 `#[non_exhaustive]` 还能要求未来加新分支)。这比 C 的 `switch (state) { case ... }` 安全得多——Rust 会警告漏写的 case。

## 5 · 对照与变奏

### Immediate-mode vs Retained-mode GUI

| 范式 | 代表 | 状态保留 | 实现复杂度 |
|---|---|---|---|
| Immediate | Dear ImGui / egui / Casey HH | 不保留(每帧重算) | 低 |
| Retained | Qt / GTK / DOM | 保留控件树 | 高 |
| Hybrid | Flutter / SwiftUI | 框架代管 | 中 |

HH 走 Immediate 路线:每帧重新检测鼠标位置、重新画滑块、重新计算值。好处是没有"控件树同步"的复杂度,坏处是每次重画要小心性能。

Immediate GUI 的滑块代码非常短:

```rust
fn slider(value: &mut usize, min: usize, max: usize, x: i32, y: i32, w: i32, h: i32) {
    let thumb_x = x + (*value as f32 / max as f32 * w as f32) as i32;
    draw_rect(x, y, w, h, GRAY);
    draw_rect(thumb_x, y, 4, h, WHITE);

    if mouse_down_in(x, y, w, h) {
        let normalized = (mouse_x - x) as f32 / w as f32;
        *value = (normalized * max as f32) as usize;
    }
}
```

这 10 行在 Retained GUI 里要写一个 Slider 类、signal/slot、property、event handler,几百行起步。Immediate 的简洁性是 Casey 选它的原因。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Casey 用 `Option<usize>` 表示 selected_frame,而不是 `i32`(用 -1 表示"未选")?给出至少 3 个理由。

**参考解答**:
1. **类型安全**:`Option<usize>` 强制你处理 None 分支,不可能"忘记 -1 表示未选"。`i32` 的 -1 可能被误当成索引
2. **意图明确**:`Some(5)` 比 `5` 更清楚地表达"这是一个明确的选择"。`-1` 是个魔法数字,需要注释解释
3. **避免边界 bug**:`usize` 是无符号,无法表示 -1;`i32` 转 `usize` 时 -1 会变成 `usize::MAX`,导致越界 panic
4. **零开销**:Rust 的 Option 在内存里就是 `union { None: (), Some: usize }`,size_of 等于 usize + 1 字节(对齐到 8 字节),和 i32 一样
5. **API 友好**:`option.unwrap_or(default)` 表达"None 时用默认值",比 `if x == -1 { default } else { x }` 简洁

### Lv2 · 动手实践

**题**:实现一个独立的 `Slider` 控件,支持:

- `new(x, y, w, h, min, max)` 构造
- `handle_mouse(mouse_x, mouse_y, is_down)` 处理事件,返回 `Option<i32>`(新值)
- `draw(canvas)` 绘制

测试:在一个 800×600 窗口里画一个滑块(min=0, max=100, 初始=50),用鼠标拖动它,在屏幕上显示当前值。

完成标准:鼠标按下拖动滑块,值实时更新。

**参考解答**:

```rust
struct Slider {
    x: i32, y: i32, w: i32, h: i32,
    min: i32, max: i32,
    value: i32,
    is_dragging: bool,
}

impl Slider {
    fn new(x: i32, y: i32, w: i32, h: i32, min: i32, max: i32, initial: i32) -> Self {
        Self {
            x, y, w, h, min, max,
            value: initial,
            is_dragging: false,
        }
    }

    fn hit_test(&self, mx: i32, my: i32) -> bool {
        mx >= self.x && mx < self.x + self.w && my >= self.y && my < self.y + self.h
    }

    fn x_to_value(&self, mx: i32) -> i32 {
        // 鼠标 X 转成值
        let normalized = (mx - self.x) as f32 / self.w as f32;
        let v = self.min as f32 + normalized * (self.max - self.min) as f32;
        v.round() as i32
            .max(self.min)
            .min(self.max)
    }

    fn value_to_x(&self) -> i32 {
        let normalized = (self.value - self.min) as f32 / (self.max - self.min) as f32;
        self.x + (normalized * self.w as f32) as i32
    }

    fn handle_mouse(&mut self, mx: i32, my: i32, is_down: bool) -> Option<i32> {
        // 返回 Some(new_value) 如果值变了
        if is_down {
            if self.is_dragging {
                // 正在拖动,更新值
                let new_v = self.x_to_value(mx);
                if new_v != self.value {
                    self.value = new_v;
                    return Some(self.value);
                }
            } else if self.hit_test(mx, my) {
                // 鼠标在滑块上按下,开始拖动
                self.is_dragging = true;
                let new_v = self.x_to_value(mx);
                if new_v != self.value {
                    self.value = new_v;
                    return Some(self.value);
                }
            }
        } else {
            self.is_dragging = false;
        }
        None
    }

    fn draw(&self, buffer: &mut [u32], buf_w: usize, buf_h: usize) {
        // 滑块背景
        for py in self.y..(self.y + self.h) {
            for px in self.x..(self.x + self.w) {
                if (px as usize) < buf_w && (py as usize) < buf_h {
                    buffer[(py as usize) * buf_w + (px as usize)] = 0xFF404040;
                }
            }
        }
        // thumb(选中的位置)
        let thumb_x = self.value_to_x();
        for py in (self.y - 4)..(self.y + self.h + 4) {
            for px in (thumb_x - 3)..(thumb_x + 3) {
                if (px as usize) < buf_w && (py as usize) < buf_h {
                    buffer[(py as usize) * buf_w + (px as usize)] = 0xFFE0E0E0;
                }
            }
        }
    }
}

fn main() {
    // 假设你有 minifb 窗口,这里只展示逻辑
    let mut slider = Slider::new(100, 500, 600, 20, 0, 100, 50);
    println!("Initial value: {}", slider.value);

    // 模拟鼠标事件
    let _ = slider.handle_mouse(400, 510, true);  // 在中间按下
    println!("After drag to middle: {}", slider.value);

    let _ = slider.handle_mouse(700, 510, true);  // 拖到右边
    println!("After drag to right: {}", slider.value);

    let _ = slider.handle_mouse(0, 0, false);     // 松开
    println!("Final value: {}", slider.value);
}
```

**每行解释**:
- `hit_test` 检查鼠标是否在滑块矩形内,这是 UI 控件的标准接口
- `x_to_value` 把鼠标 X 转成滑块值,注意 clamp 防越界
- `value_to_x` 反向映射,画 thumb 用
- `handle_mouse` 返回 `Option<i32>`——只在值变化时返回 Some,避免无意义的重绘
- `is_down` 同时表达"鼠标按下"状态,简化事件模型(没有区分 left/right button)

### Lv3 · 迁移设计

**题**:设计一个**音量旋钮(rotary knob)**,不是水平滑块。旋钮的角度(0-270 度,留 90 度的死区)映射到音量(0-100)。

要求:
- 鼠标按下旋钮 + 上下拖动(垂直方向)调节
- 旋钮画成圆(用一系列填充矩形近似,或用三角函数算像素)
- 视觉反馈:旋钮上的指针随角度旋转

提示:角度到指针位置的映射用 `(cos(angle), sin(angle))`,画指针是从圆心画一条线段(用矩形近似)。

## 8 · Rust / Arch 落地代码

### 完整集成:profiler + slider scrubbing

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, MouseMode, MouseButton, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const HISTORY: usize = 64;

#[derive(Clone, Default)]
struct FrameProfile {
    dt_ms: f32,
    update_ms: f32,
    render_ms: f32,
}

struct Profiler {
    frames: Box<[FrameProfile; HISTORY]>,
    head: usize,
    initialized: usize,
    selected: Option<usize>,  // None = 实时跟随,Some(i) = 锁定到 i
    slider_dragging: bool,
}

impl Profiler {
    fn new() -> Self {
        Self {
            frames: Box::new(std::array::from_fn(|_| FrameProfile::default())),
            head: 0,
            initialized: 0,
            selected: None,
            slider_dragging: false,
        }
    }

    fn record(&mut self, dt: f32, update: f32, render: f32) {
        let slot = &mut self.frames[self.head];
        slot.dt_ms = dt;
        slot.update_ms = update;
        slot.render_ms = render;
        self.head = (self.head + 1) % HISTORY;
        if self.initialized < HISTORY { self.initialized += 1; }
    }

    fn current_index(&self) -> usize {
        // 返回当前应该显示的帧索引
        match self.selected {
            Some(i) => i % HISTORY,
            None => {
                // 最新已写的:head - 1
                if self.head == 0 { HISTORY - 1 } else { self.head - 1 }
            }
        }
    }

    fn current_frame(&self) -> &FrameProfile {
        &self.frames[self.current_index()]
    }

    fn handle_slider_mouse(&mut self, mx: i32, my: i32, is_down: bool, slider_x: i32, slider_w: i32) {
        let slider_y = (HEIGHT as i32) - 50;
        let slider_h = 20;

        let in_slider = mx >= slider_x && mx < slider_x + slider_w
                     && my >= slider_y && my < slider_y + slider_h;

        if is_down {
            if self.slider_dragging {
                // 拖动中:更新 selected
                let normalized = (mx - slider_x) as f32 / slider_w as f32;
                let idx = (normalized * HISTORY as f32) as usize;
                self.selected = Some(idx.min(HISTORY - 1));
            } else if in_slider {
                // 滑块上按下:开始拖动
                self.slider_dragging = true;
                let normalized = (mx - slider_x) as f32 / slider_w as f32;
                let idx = (normalized * HISTORY as f32) as usize;
                self.selected = Some(idx.min(HISTORY - 1));
            }
        } else {
            self.slider_dragging = false;
            // 鼠标松开后,selected 保留(不自动回到 Live)
        }
    }

    fn resume_live(&mut self) {
        self.selected = None;
    }
}

fn draw_rect(buffer: &mut [u32], w: usize, h: usize, x: i32, y: i32, rw: i32, rh: i32, color: u32) {
    for py in y.max(0)..(y + rh).min(h as i32) {
        for px in x.max(0)..(x + rw).min(w as i32) {
            buffer[(py as usize) * w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Profiler + Slider Demo",
        WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut profiler = Profiler::new();
    let mut last_time = Instant::now();
    let slider_x = 100;
    let slider_w = 600;

    while window.is_open() && !window.is_key_down(Key::Escape) {
        // 算 dt
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32() * 1000.0;
        last_time = now;

        // 模拟子任务
        let update_ms = dt * 0.3;
        let render_ms = dt * 0.5;

        // 只在 Live 模式下记录(Locked 模式下不写新数据,模拟"暂停")
        if profiler.selected.is_none() {
            profiler.record(dt, update_ms, render_ms);
        }

        // 处理鼠标
        let (mx, my) = window.get_mouse_pos(MouseMode::Discard).unwrap_or((0.0, 0.0));
        let is_down = window.get_mouse_down(MouseButton::Left);

        // 按 Space 切回 Live
        if window.is_key_pressed(Key::Space, minifb::KeyRepeat::No) {
            profiler.resume_live();
        }

        profiler.handle_slider_mouse(mx as i32, my as i32, is_down, slider_x, slider_w);

        // 清屏
        for px in buffer.iter_mut() { *px = 0xFF101010; }

        // 画柱状图(顶部 100px)
        let chart_x = 100i32;
        let chart_y = 50i32;
        let chart_w = 600i32;
        let chart_h = 100i32;
        let scale = 33.0_f32;

        draw_rect(&mut buffer, WIDTH, HEIGHT, chart_x, chart_y, chart_w, chart_h, 0xFF303030);

        let start = if profiler.initialized < HISTORY { 0 } else { profiler.head };
        for i in 0..profiler.initialized {
            let frame_idx = (start + i) % HISTORY;
            let v = profiler.frames[frame_idx].dt_ms;
            let bar_w = chart_w / HISTORY as i32;
            let bx = chart_x + (i as i32) * bar_w;
            let top_y = chart_y + ((1.0 - v / scale).max(0.0).min(1.0) * chart_h as f32) as i32;
            let color = if frame_idx == profiler.current_index() {
                0xFFFFFFFF  // 选中的帧白色高亮
            } else if v < 18.0 {
                0xFF4040FF
            } else if v < 25.0 {
                0xFFFF40
            } else {
                0xFFFF4040
            };
            draw_rect(&mut buffer, WIDTH, HEIGHT, bx, top_y, bar_w, chart_y + chart_h - top_y, color);
        }

        // 画滑块
        let slider_y = (HEIGHT as i32) - 50;
        let slider_h = 20;
        draw_rect(&mut buffer, WIDTH, HEIGHT, slider_x, slider_y, slider_w, slider_h, 0xFF404040);

        // 滑块 thumb
        let thumb_normalized = match profiler.selected {
            Some(i) => i as f32 / HISTORY as f32,
            None => 1.0,  // Live 模式下 thumb 在最右
        };
        let thumb_x = slider_x + (thumb_normalized * slider_w as f32) as i32;
        draw_rect(&mut buffer, WIDTH, HEIGHT, thumb_x - 3, slider_y - 4, 6, slider_h + 8, 0xFFE0E0E0);

        // 状态文字(简化,实际项目用 raster 字体)
        let state_label = if profiler.selected.is_some() { "LOCKED" } else { "LIVE" };
        let _ = state_label;  // 实际渲染文字需要字体

        // 显示当前选中帧的数据
        let cur = profiler.current_frame();
        let _ = (cur.dt_ms, cur.update_ms, cur.render_ms);

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `MouseMode::Discard` 让 minifb 在鼠标离开窗口时不报错,返回上次的位置
- `MouseButton::Left` 枚举,与 `Right` / `Middle` 区分
- `Option::is_none()` 比 `matches!(self.selected, None)` 更简洁
- `is_key_pressed(Key::Space, KeyRepeat::No)` 表示"按下不重复",松开后才能再按
- `frame_idx == profiler.current_index()` 实现"选中帧高亮"——一个简单的视觉关联

**Troubleshooting**:

- 拖动滑块时画面不动 — 检查 selected 是否真的被设置(加 `println!` 调试)
- 滑块拖出右边后崩溃 — 没做 clamp,`idx.min(HISTORY - 1)` 必须加
- Live 模式按 Space 没反应 — 检查 `KeyRepeat::No` 是否被 keypressed 错过了,可以用 `is_key_down` 替代
