# Day 321 · 多个 OpenGL 渲染目标

> 把多 target 概念从 CPU 软件渲染迁移到 OpenGL——用 FBO(Framebuffer Object)表达离屏渲染目标,用 shader 一次 draw 写到多个 target(MRT)。GPU 加速让 1080p 多 target 合成从 5ms 降到 0.5ms。

## 0 · 为什么要有这一天

前面 Day 316-318 你实现了 CPU 版的多 target 渲染,功能完整但性能受限于 CPU——1080p 合成要 5ms,占一帧 16ms 预算的 1/3。Casey 在 Day 176 之后已经在 OpenGL 上做了基础渲染,今天是时候把"多 target"也搬到 GPU。

GPU 的多 target 有两种方式:

1. **多个 FBO 顺序绘制**:每个 target 一个 FBO,绘制时 `glBindFramebuffer` 切换。简单但每个 target 要单独 draw,内存带宽高。
2. **MRT(Multiple Render Targets)**:fragment shader 一次 draw 同时写到多个颜色附件。复杂但只 draw 一次,带宽低。

```
方案 1(多 FBO):              方案 2(MRT):
draw to FBO 0 (BG)            draw once, write to
draw to FBO 1 (Game)            layout(location=0) out color_bg
draw to FBO 2 (UI)              layout(location=1) out color_game
composite to screen             layout(location=2) out color_ui
```

MRT 是 GPU 硬件特性,OpenGL 3.0+ 标准。它广泛用于**延迟渲染**(deferred shading)——一次 draw 把位置、法线、颜色分别写到 4 个 G-buffer,光照阶段读这些 buffer 计算光照,避免每个光源都重新画一遍几何。

今天 Casey 干的事:**用 OpenGL FBO + MRT 重写多 target 渲染**。原来的 CPU `RenderTarget` 改成 GPU `GLuint framebuffer`,合成 pass 用 shader 实现。

心理锚点:今天之后你的渲染管线在 GPU 上,1080p 多 target + 合成只要 1ms。这是工业级 3A 引擎的标准架构(延迟渲染的基础)。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_opengl.cpp`,做了一次大重构。原来的 CPU `render_target` 结构:

```c
struct render_target {
    void *Memory;       // CPU 内存
    int Width, Height;
    uint32 SortKeyBias;
};
```

今天改成 OpenGL 版:

```c
struct opengl_render_target {
    GLuint Framebuffer;       // FBO 句柄
    GLuint ColorTexture;      // 颜色附件(纹理)
    GLuint DepthTexture;      // 深度附件(可选)
    int Width, Height;
};
```

关键动作:

1. `glGenFramebuffers` 创建 FBO
2. `glGenTextures` 创建颜色纹理
3. `glBindFramebuffer` + `glFramebufferTexture2D` 把纹理绑到 FBO
4. 渲染时 `glBindFramebuffer` 切换到目标 FBO,正常 draw
5. 合成 pass 用一个特殊 shader,把多个纹理 input 合成到屏幕

Casey 在视频里讨论了 **FBO 完整性检查** —— `glCheckFramebufferStatus` 必须返回 `GL_FRAMEBUFFER_COMPLETE`,否则 FBO 不可用。这是新手最大的坑,常见错误:

- 颜色纹理和深度纹理尺寸不一致
- 颜色纹理格式不被支持(比如内部用 RGB 但绑到 FBO 期望 RGBA)
- 没绑任何附件就 draw

Casey 加了一个 assert,如果 FBO 不完整立刻 panic,不静默继续。

另一个关键点:**OpenGL 上下文单线程**。所有的 GL 调用必须在主线程,Rust 翻译时要注意 `glutin` / `glow` 的线程约束。Casey 的 CPU 渲染可以多线程,GPU 渲染回到单线程——这是 GPU 编程的固有约束。

## 2 · 心智模型

### 类比:GPU 是工厂,FBO 是工作台

把 GPU 想象成一个工厂,有大量工人(SIMD 单元)并行干活。FBO 是工人的"工作台"——可以放一张画布(颜色纹理),工人画完后交给仓库(显存)。

- **单 FBO**(默认):工厂只有一个工作台,所有工人轮流用
- **多 FBO**:工厂有多个工作台,但同一时刻一组工人只能用一个
- **MRT**:一个工作台有多个画布层,工人一笔能画到所有画布

MRT 的关键是"一笔多画"——fragment shader 计算 fragment 时,把结果同时写到多个 attachment。这对延迟渲染特别有用:算一次 fragment,把位置、法线、颜色分别写到 4 个纹理,后续光照阶段读这些纹理算光照。

### 严谨原理:FBO 数据结构

OpenGL FBO 是一个状态机,有这些组件:

```
┌─ Framebuffer Object (FBO) ──────────────────────┐
│                                                  │
│  Color attachment 0: ← Texture 0 (RGBA8)         │
│  Color attachment 1: ← Texture 1 (RGBA8)         │
│  Color attachment 2: ← Texture 2 (RGBA8)         │
│  ...                                             │
│  Color attachment 7: ← Texture 7 (RGBA8)         │
│                                                  │
│  Depth attachment:   ← Texture (Depth24)         │
│  Stencil attachment: ← Texture (Stencil8)        │
│                                                  │
└──────────────────────────────────────────────────┘
```

最多 8 个颜色附件(OpenGL 3.x 保证)。每个附件可以绑一个纹理或 renderbuffer。

绑定后,fragment shader 用 `layout(location = N) out vec4 fragColor_N` 写到第 N 个附件。

### MRT shader 示例

```glsl
#version 330 core

layout(location = 0) out vec4 out_bg;
layout(location = 1) out vec4 out_game;
layout(location = 2) out vec4 out_ui;

uniform sampler2D u_bg_tex;
uniform sampler2D u_game_tex;
uniform sampler2D u_ui_tex;

in vec2 v_uv;

void main() {
    vec4 bg = texture(u_bg_tex, v_uv);
    vec4 game = texture(u_game_tex, v_uv);
    vec4 ui = texture(u_ui_tex, v_uv);
    
    // 预乘 alpha 合成
    vec4 result = bg;
    result = vec4(game.rgb + result.rgb * (1.0 - game.a), 
                  game.a + result.a * (1.0 - game.a));
    result = vec4(ui.rgb + result.rgb * (1.0 - ui.a),
                  ui.a + result.a * (1.0 - ui.a));
    
    out_bg = result;
    out_game = vec4(0);  // 没用
    out_ui = vec4(0);
}
```

但实际上合成 pass 只需要 1 个 output,所以这不是真正的 MRT——MRT 用法是"一次 draw 同时算多个独立 output"。合成 pass 只是"多 input → 单 output"。

### 真正的 MRT 应用:G-buffer

延迟渲染的 G-buffer 才是 MRT 的标准用法:

```glsl
// 几何 pass:一次 draw,写 4 个 G-buffer
layout(location = 0) out vec3 g_position;
layout(location = 1) out vec3 g_normal;
layout(location = 2) out vec4 g_albedo_spec;
layout(location = 3) out vec3 g_emissive;

void main() {
    g_position = frag_pos;
    g_normal = normalize(normal);
    g_albedo_spec = vec4(albedo, specular);
    g_emissive = emissive;
}

// 光照 pass:读 G-buffer,算每个光源
uniform sampler2D g_position_tex;
uniform sampler2D g_normal_tex;
// ...

void main() {
    vec3 pos = texture(g_position_tex, v_uv).rgb;
    vec3 normal = texture(g_normal_tex, v_uv).rgb;
    // ... 算光照
    out_color = final_color;
}
```

Casey 今天只做"多 FBO 顺序绘制",MRT 完整实现留到 Phase 6 后期(光照阶段)。

### Linux 视角:OpenGL 上下文

OpenGL 在 Linux 上通过 GLX(OpenGL Extension to X)或 EGL(嵌入式)创建上下文。Wayland 时代主流是 EGL。

```rust
// 用 glutin 创建 OpenGL 上下文
use glutin::ContextBuilder;

let cb = ContextBuilder::new()
    .with_gl(glutin::GlRequest::Specific {
        api: glutin::Api::OpenGl,
        version: (3, 3),  // OpenGL 3.3+
    })
    .with_gl_profile(glutin::GlProfile::Core)
    .with_multisampling(4);  // MSAA 抗锯齿
```

OpenGL 3.3 Core 是 Casey 选的最低版本,因为 FBO + MRT 都需要 3.x+。

### Rust 表达

```rust
use glow::Context;

struct OpenGLRenderTarget {
    framebuffer: glow::Framebuffer,
    color_texture: glow::Texture,
    width: i32,
    height: i32,
}

impl OpenGLRenderTarget {
    fn new(gl: &Context, width: i32, height: i32) -> Self {
        // 1. 创建 FBO
        let framebuffer = unsafe { gl.create_framebuffer() }
            .expect("create_framebuffer failed");
        unsafe { gl.bind_framebuffer(glow::FRAMEBUFFER, Some(framebuffer)); }
        
        // 2. 创建颜色纹理
        let color_texture = unsafe { gl.create_texture() }
            .expect("create_texture failed");
        unsafe {
            gl.bind_texture(glow::TEXTURE_2D, Some(color_texture));
            gl.tex_image_2d(
                glow::TEXTURE_2D, 0, glow::RGBA8, width, height, 0,
                glow::RGBA, glow::UNSIGNED_BYTE, None,
            );
            gl.tex_parameter_i32(glow::TEXTURE_2D, glow::TEXTURE_MIN_FILTER, 
                                 glow::LINEAR as i32);
        }
        
        // 3. 把纹理绑到 FBO 的 color attachment 0
        unsafe {
            gl.framebuffer_texture_2d(
                glow::FRAMEBUFFER, glow::COLOR_ATTACHMENT0,
                glow::TEXTURE_2D, Some(color_texture), 0,
            );
        }
        
        // 4. 检查完整性
        let status = unsafe { gl.check_framebuffer_status(glow::FRAMEBUFFER) };
        assert_eq!(status, glow::FRAMEBUFFER_COMPLETE, "FBO incomplete");
        
        Self { framebuffer, color_texture, width, height }
    }
}
```

`unsafe` 是必须的——OpenGL 是 C API,Rust 包装层 `glow` 把每个调用标记为 unsafe。这是 FFI 的标准做法。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏行业 FBO 的几个典型用途:

1. **小地图**:从顶视角再渲染一遍到小地图 FBO
2. **后处理**:全屏 blur、bloom、color grading,先画到 FBO 再处理
3. **阴影贴图**(shadow map):从光源视角渲染深度到 FBO
4. **反射**(mirror/water):从镜面视角再渲染到 FBO
5. **延迟渲染**:G-buffer,多个 FBO 同时写

主流引擎(Unity / Unreal)的 FBO 抽象:

- Unity:`RenderTexture`
- Unreal:`UTextureRenderTarget2D`
- Godot:`ViewportTexture`

Casey 用裸 OpenGL,直接操作 GLuint。生产代码会用 `glow` 或 `wgpu`(更现代的 Vulkan 抽象)。

### 3.2 · 🎨 图形学视角

OpenGL 的 FBO 是 2005 年的扩展(`GL_EXT_framebuffer_object`),2008 年纳入 OpenGL 3.0 标准。在那之前,离屏渲染只能用 `pbuffer`(pixel buffer),极其难用。

FBO 的图形学意义:**让离屏渲染变成一等公民**。在那之前,纹理是"输入",只能从文件加载;FBO 让纹理可以"输出",GPU 可以"渲染到纹理"。这是 shader 链(post-processing chain)的基础。

OpenGL 4.3 引入 `glFramebufferTextureLayer`,可以绑纹理的某一 layer(对 texture array),进一步扩展。Vulkan 把这些功能拆得更细(VkRenderPass + VkFramebuffer),性能更可预测。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上 OpenGL 的几个层次:

- **Mesa**:开源 OpenGL 实现,几乎所有 Linux 发行版都用
- **DRM**(Direct Rendering Manager):内核的 GPU 驱动层,Mesa 通过 libdrm 调用
- **DRI**(Direct Rendering Infrastructure):让用户态直接访问 GPU,不通过 X server

调试 OpenGL 的 Linux 工具:

- `apitrace`:记录所有 GL 调用,可以重放和单步
- `RenderDoc`:开源的 frame debugger,业界标准
- `VOGL`:Valve 的 GL trace 工具(已弃用,但仍可参考)

```bash
# 用 apitrace 录制游戏一帧
apitrace trace ./my_game
# 生成 my_game.trace 文件,可以重放
qapitrace my_game.trace
# 在 GUI 里单步看每个 GL 调用
```

RenderDoc 更强大,可以看每个 draw call 的纹理、shader、uniform。

### 3.4 · 🦀 Rust 生态视角

Rust 的 OpenGL 生态:

- **`glow`**:轻量 OpenGL wrapper,Casey 用这个
- **`glutin`**:窗口 + 上下文管理,跨平台
- **`gl`**:更底层的 binding,`glow` 的前身
- **`wgpu`**:Vulkan/Metal/D3D12 抽象,现代替代 OpenGL

`glow` 设计简洁,API 直接对应 OpenGL C 函数。每个调用是 `unsafe`,标记"这是 FFI"。

```toml
[dependencies]
glow = "0.13"
glutin = "0.31"
```

更现代的选择是 `wgpu`(WebGPU 的 Rust 实现),自动跨平台(Vulkan on Linux, Metal on macOS, D3D12 on Windows)。但 wgpu 的概念层级比 OpenGL 高,Casey 用 OpenGL 是为了"贴近硬件"。Phase 8 之后可以试试 wgpu。

## 5 · 对照与变奏

- **1990s**:GPU 只有固定管线,不能离屏渲染(只能用 pbuffer)

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 GPU 渲染比 CPU 渲染快这么多?给出至少 3 个理由。

**参考解答**:

1. **大规模并行**:GPU 有几千个 SIMD 单元,CPU 只有几十个。1080p 207 万像素,GPU 一次处理几千,CPU 一次一个。
2. **专用硬件**:GPU 有 texture sampling 硬件(双线性插值、各向异性过滤)、blend 硬件(alpha 合成专门电路),CPU 用通用 ALU 算。
3. **显存带宽高**:GPU 用 GDDR6/HBM,带宽 1TB/s+;CPU 用 DDR4,~50 GB/s。像素读写快 20 倍。
4. **流水线深度**:GPU 的图形流水线有十几级,CPU 短流水线。GPU 可以一次处理多个 draw 重叠执行。

## 8 · Rust / Arch 落地代码

### Rust:最小 OpenGL FBO demo(简化版)

```rust
// Cargo.toml:
// [dependencies]
// glow = "0.13"
// glutin = "0.31"

// 这是简化版,实际跑需要完整窗口循环
// 完整代码参考 https://github.com/grovesNL/glow/tree/main/examples

use glow::*;

fn create_render_target(gl: &Context, width: i32, height: i32) -> (Framebuffer, Texture) {
    // 1. 创建 FBO
    let fbo = unsafe { gl.create_framebuffer() }.expect("FBO creation failed");
    
    // 2. 创建颜色纹理
    let tex = unsafe { gl.create_texture() }.expect("Texture creation failed");
    
    unsafe {
        // 3. 绑定 FBO
        gl.bind_framebuffer(FRAMEBUFFER, Some(fbo));
        
        // 4. 配置纹理(空,待渲染)
        gl.bind_texture(TEXTURE_2D, Some(tex));
        gl.tex_image_2d(
            TEXTURE_2D, 0, RGBA8,  // 内部格式 RGBA8
            width, height, 0,
            RGBA, UNSIGNED_BYTE,   // 输入格式 RGBA + u8
            None,                  // 不初始化数据
        );
        gl.tex_parameter_i32(TEXTURE_2D, TEXTURE_MIN_FILTER, LINEAR as i32);
        gl.tex_parameter_i32(TEXTURE_2D, TEXTURE_MAG_FILTER, LINEAR as i32);
        
        // 5. 把纹理绑到 FBO 的 color attachment 0
        gl.framebuffer_texture_2d(
            FRAMEBUFFER, COLOR_ATTACHMENT0,
            TEXTURE_2D, Some(tex), 0,
        );
        
        // 6. 完整性检查
        let status = gl.check_framebuffer_status(FRAMEBUFFER);
        if status != FRAMEBUFFER_COMPLETE {
            panic!("FBO incomplete: status = {:x}", status);
        }
        
        // 7. 解绑,回到默认 framebuffer
        gl.bind_framebuffer(FRAMEBUFFER, None);
    }
    
    (fbo, tex)
}

fn composite_to_screen(gl: &Context, textures: &[Texture]) {
    unsafe {
        // 切到默认 framebuffer(屏幕)
        gl.bind_framebuffer(FRAMEBUFFER, None);
        gl.clear_color(0.0, 0.0, 0.0, 1.0);
        gl.clear(COLOR_BUFFER_BIT);
        
        // 绑定所有 input texture
        for (i, tex) in textures.iter().enumerate() {
            gl.active_texture(TEXTURE0 + i as u32);
            gl.bind_texture(TEXTURE_2D, Some(*tex));
        }
        
        // 设置 uniform(假设 shader 已编译)
        // uniform sampler2D u_bg_tex;  // = 0
        // uniform sampler2D u_game_tex; // = 1
        // uniform sampler2D u_ui_tex;  // = 2
        
        // 画 fullscreen quad(假设 VAO/program 已设置)
        gl.draw_arrays(TRIANGLES, 0, 6);
    }
}
```

**Troubleshooting**:

- **FBO incomplete** — 检查纹理格式(RGBA8 而不是 RGB)、尺寸(非 0)、绑定(绑到 COLOR_ATTACHMENT0)
- **黑屏** — 检查是否 `bind_framebuffer(None)` 切回屏幕,清屏色是否黑色
- **崩溃在 GL 调用** — 检查 OpenGL 上下文是否在主线程,GL 函数是否加载完全

## 10 · 深度补充:工程视角

OpenGL FBO 的现代替代:Vulkan 把 FBO 概念拆为 RenderPass + Framebuffer,性能更可预测。wgpu(WebGPU)进一步简化,跨平台(Vulkan / Metal / D3D12)。Bevy 引擎默认用 wgpu,屏蔽底层差异。Casey 用 OpenGL 是因为简单,但 Phase 8 之后切到 wgpu 是 Rust 生态趋势。

### 跨领域的方向一致性

工程上很多抽象都跨领域通用。今天的概念在多个领域都有对应。

- **游戏引擎**:Core abstraction 表达
- **图形学**:GPU 硬件或软件算法实现
- **Linux 内核**:类似抽象在 OS 层
- **Rust 生态**:类型安全表达

理解一个抽象的多领域映射,你就能在不同技术栈间自由切换。

### 历史演化与未来趋势

每个技术都有演化历史和未来趋势。Casey 在 HH 系列展示的是 当下最佳实践,但技术会演进。学会识别 哪些是永恒原理(数据结构、算法)、哪些是时代选择(API 设计、语言特性),让你长期保持竞争力。

永恒原理:排序、矩阵乘法、alpha 合成、内存分配、并发原语。这些 50 年不变。

时代选择:OpenGL vs Vulkan vs WebGPU、Rust vs C++、ECS vs OOP。这些 5-10 年一变。

### 给读者的建议

1. **理解原理**:每个抽象都问 为什么这样设计
2. **多语言对比**:同一个抽象在 C / Rust / Python 各怎么表达
3. **历史视角**:看技术演化,理解 为什么现在这样做
4. **实践**:每个概念都写代码,不止看
5. **开源贡献**:看真实代码怎么用,提 PR 加深理解

Casey HH 系列是教学,但更是一种 工程师心态 训练——遇到问题怎么拆解、怎么实现、怎么优化、怎么修 bug。这种心态比具体知识更重要。

## 11 · 延伸讨论

FBO 在工业管线的角色:延迟渲染用 4-8 个 G-buffer FBO;forward rendering 用 1-2 个;post-processing 用 ping-pong 两个 FBO 交替。Unity URP 的 RenderTexture 就是 FBO 包装。Unreal 的 RTG(Render Target Group)管理 FBO 复用——同一 FBO 复用做多个 pass 减少 VRAM 占用。

### 工程决策的权衡

每个技术选择都涉及权衡。今天的主题在 Casey 的 HH 里选了某条路,但其他路也合理。理解权衡让你能在新场景做正确选择。

### Rust 生态的演进

Rust 生态每 6 个月一个 edition,API 和最佳实践会变。但核心原理(所有权 / 借用 / Send/Sync / Trait)稳定。学会识别'什么是稳定基础'vs'什么是流行 API',让你长期有效。

### 开源贡献的实践

今天的 Lv4 题目指向真实开源项目。实践建议:

1. **找 good-first-issue**:GitHub 上 label:'good first issue'
2. **读代码 + 文档**:理解项目架构
3. **fork + 改 + 测试**:本地验证
4. **写 PR 描述**:动机 / 改动 / 测试
5. **接受 review**:维护者反馈,可能要改
6. **merge**:成为项目 contributor

PR 不一定要大——文档改进、测试补充、小 bug 修复都是贡献。重要的是参与。

### 长期学习路径

完成 Phase 6 后,你应该能:

- 读 Casey 原版 C 代码,在 Rust 翻译
- 看懂 OpenGL / Vulkan 的 API
- 理解 ECS / DOD 设计哲学
- 自写基础工具(printf / mutex / parser)
- 修 bug、写测试、提 PR

Phase 7 / 8 会进入更高级话题(PNG 解码 / 编辑器 / 光照优化),但 Phase 6 的基础是关键。
