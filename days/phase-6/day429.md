# Day 429 · 多分辨率光采样

> 一个矩形光源覆盖 1000 个体素,采 16 个样本要 16000 次 ray-cast。但远处的光源只需要粗糙采样(细节看不清),近处才需要精细采样。今天 Casey 实现**多分辨率采样**——按距离决定采样数,远处少采(快),近处多采(精),性能 3-5 倍提升。

## 0 · 为什么要有这一天

具体场景:你有一个矩形光源,覆盖 64x64 体素的区域。每帧每图元采 16 个样本。性能瓶颈在于 ray-cast:每个样本要做一次 BVH 遍历(虽然 O(log N),但累积起来仍然贵)。

观察:**远处光源的细节不可见**。100 米外的火把,你看不清它的边缘是软的还是硬的——它看起来就是个亮点。所以远处不需要 16 个样本,4 个甚至 1 个就够。近处光源才有视觉细节,需要多采样。

工业的解决方案:**多分辨率采样(multiresolution sampling)**,也叫 **adaptive sampling**。按距离/重要度调整采样数:

- 距离 < 5m:16 个样本(精细)
- 5-15m:8 个样本(中等)
- 15-50m:4 个样本(粗糙)
- 50m+:1 个样本(点光近似)

总成本降低 3-5 倍,视觉质量损失极小。

更深层:**渲染的所有成本都该按视觉重要度分配**。屏幕中心的像素重要(人眼聚焦),边缘像素不重要(余光);近处物体重要(细节),远处不重要(模糊);移动物体重要(注意),静止不重要(忽略)。多分辨率采样是这个原则在光照的应用。

工业的 mipmap 是同样思想——远处用低分辨率纹理(便宜),近处用高分辨率(精细)。LOD(level of detail)是几何版本。Casey 今天做光照版本。

心理锚点:今天之后,你能解释 mipmap / LOD / 多分辨率采样的共同原理,能在自己的渲染器实现按距离调整的采样,理解为什么工业 GPU 渲染都做这些优化。

## 2 · 心智模型

### 类比:摄影师拍远景

摄影师拍远处风景和近处特写,用不同光圈:

- **远处风景**:光圈小,景深大,所有远处物体清晰。但分辨率可以低(细节看不清)。
- **近处特写**:光圈大,景深浅,只有主体清晰。需要高分辨率。

摄影师**根据距离和重要度分配资源**。多分辨率采样完全同构——根据距离分配采样数。

### 严谨原理:信号采样定理

Shannon 采样定理:**采样频率必须 > 信号最高频 × 2**。

光照信号的最高频 = 矩形边缘的"高频"。距离近时,边缘占据屏幕多个像素,需要高频采样(多个样本)。距离远时,边缘占据 1 个像素甚至更少,低频采样(1 个样本足够)。

数学:光源在屏幕上的**立体角** = 面积 / 距离²。立体角小(远),需要样本少;立体角大(近),需要样本多。

### 自适应采样公式

```
samples = clamp(
    base_samples * (reference_dist / actual_dist)²,
    min_samples,
    max_samples
)
```

例如:base = 16,reference = 5m,actual = 10m, samples = 16 * (5/10)² = 4。

简化版(分段常数,Casey 用):

```rust
fn samples_for_distance(dist: f32) -> u32 {
    if dist < 5.0 { 16 }
    else if dist < 15.0 { 8 }
    else if dist < 50.0 { 4 }
    else { 1 }
}
```

分段常数便宜(几次比较),但**精度跳变**——距离 4.99m 用 16,5.01m 用 8。视觉上看到突变。

平滑版(连续函数):

```rust
fn samples_for_distance(dist: f32) -> u32 {
    let s = 16.0 / (1.0 + dist * 0.1);  // 远处衰减
    s.clamp(1.0, 16.0) as u32
}
```

但连续版采样数频繁变化,时序累积时方差不稳。Casey 用分段常数,接受突变,因为分段少(只有 4 段),视觉影响小。

### Rust 视角

```rust
pub fn compute_primitive_lighting_multires(
    primitive: &Primitive,
    light: &LightSource,
) -> Vec3 {
    let dist = (primitive.center() - light.position).length();
    let samples = samples_for_distance(dist);
    let mut accum = Vec3::ZERO;
    for i in 0..samples {
        for j in 0..samples {
            let u = (i as f32 + 0.5) / samples as f32;
            let v = (j as f32 + 0.5) / samples as f32;
            let p = light.sample(u, v);
            accum += compute_direct(p, primitive, light);
        }
    }
    accum / (samples * samples) as f32
}
```

注意:**samples × samples** 是 2D 网格,所以实际采样数是 N²。N=4 实际采 16 个。

### 性能数字

假设 1000 个图元,矩形光源:

- 固定 16 采样:1000 × 16 × 16 = 256000 ray-casts
- 多分辨率(假设 50% 近 + 30% 中 + 15% 远 + 5% 极远):
  - 近(16²):500 × 256 = 128000
  - 中(8²):300 × 64 = 19200
  - 远(4²):150 × 16 = 2400
  - 极远(1²):50 × 1 = 50
  - 总:149650,约 58% 成本

实际加速 ~2x(因为 BVH 遍历有常数开销),但仍然显著。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业的多分辨率:

- **mipmap**:纹理的 LOD,标准
- **Mesh LOD**:几何简化,远处用低面数
- **Shader LOD**:远处用简化 shader
- **Cascaded shadow maps**:近处高分辨率阴影,远处低分辨率
- **Multiresolution lighting(本日)**:按距离调整采样数

工业的 LOD 通常用**几何误差**(屏幕上多少像素)决定切换距离。Casey 用简化版(线性距离)。

### 3.2 · 🎨 图形学视角

多分辨率的理论基础:**信号处理 + 视觉感知**。

人眼分辨率(中心凹):1 弧分。物体在屏幕上小于 1 弧分 = 看不清。所以远处物体不需要细节。

工业的 **LOD bias** 调整——根据显示器分辨率、抗锯齿设置等调整 LOD 阈值。

### 3.3 · 🐧 Linux 系统编程视角

Linux 的多分辨率:

- **page sizes**:4KB / 2MB / 1GB(huge pages),按需求选
- **CPU caches**:L1(小快)/ L2(中)/ L3(大慢),多级
- **file system blocks**:ext4 用 4KB,Tiered storage 用更大

多级数据结构是系统设计的核心——小而快 + 大而慢,按需求选。

### 3.4 · 🦀 Rust 生态视角

Rust 表达多分辨率:

```rust
pub enum DetailLevel {
    Near,    // 16 samples
    Mid,     // 8
    Far,     // 4
    Distant, // 1
}

impl DetailLevel {
    pub fn from_distance(dist: f32) -> Self {
        if dist < 5.0 { Self::Near }
        else if dist < 15.0 { Self::Mid }
        else if dist < 50.0 { Self::Far }
        else { Self::Distant }
    }
    pub fn samples(self) -> u32 {
        match self {
            Self::Near => 16,
            Self::Mid => 8,
            Self::Far => 4,
            Self::Distant => 1,
        }
    }
}
```

`enum` 让 LOD 选择显式,易于扩展(加新级别)和测试。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:多分辨率采样在什么场景下"加速但不损质量"?在什么场景下"加速但损质量"?

**参考解答**:**不损质量的场景**:远处光源在屏幕上占 < 1 个像素时,采样数 > 1 是浪费——多采的样本最终被插值到一个像素,人眼分辨不出。所以远处少采完全无损。

**损质量的场景**:中距离光源占几个像素时,采样不够会在阴影边缘出现锯齿——本来应该平滑的边缘有像素化。这种情况下,采样数减少是**有损**的,需要在"质量 vs 性能"之间权衡。

工业的 cascade shadow maps 解决这个——近处用高分辨率阴影贴图(1 像素精度),远处用低分辨率(粗略),边界平滑过渡。光照的多分辨率采样思路一致,只是没有"过渡"——是分段跳变。

### Lv2 · 动手实践

**题**:实现 `samples_for_distance` + 多分辨率采样。完成标准:
- 近距离(< 5m)采 16 个样本,精细
- 远距离(> 50m)采 1 个样本,粗糙
- 性能 benchmark:平均加速 2x+
- 视觉测试:近处无明显质量损失

**参考解答**:

```rust
use glam::Vec3;

pub enum DetailLevel { Near, Mid, Far, Distant }

impl DetailLevel {
    pub fn from_distance(dist: f32) -> Self {
        if dist < 5.0 { Self::Near }
        else if dist < 15.0 { Self::Mid }
        else if dist < 50.0 { Self::Far }
        else { Self::Distant }
    }
    pub fn samples_per_axis(self) -> u32 {
        match self {
            Self::Near => 4,    // 4² = 16
            Self::Mid => 3,     // 3² = 9
            Self::Far => 2,     // 2² = 4
            Self::Distant => 1, // 1² = 1
        }
    }
    pub fn total_samples(self) -> u32 {
        let n = self.samples_per_axis();
        n * n
    }
}

pub struct RectLight {
    pub center: Vec3,
    pub half_extent: Vec3,
    pub luminous_flux: f32,
    pub color: Vec3,
}

impl RectLight {
    pub fn sample(&self, u: f32, v: f32) -> Vec3 {
        Vec3::new(
            self.center.x + (u - 0.5) * 2.0 * self.half_extent.x,
            self.center.y + (v - 0.5) * 2.0 * self.half_extent.y,
            self.center.z,
        )
    }

    pub fn illuminate_at(
        &self,
        point: Vec3,
        normal: Vec3,
        occlusion: impl Fn(Vec3, Vec3) -> bool,
    ) -> Vec3 {
        let dist = (self.center - point).length();
        let level = DetailLevel::from_distance(dist);
        let n = level.samples_per_axis();

        let mut accum = Vec3::ZERO;
        for i in 0..n {
            for j in 0..n {
                let u = (i as f32 + 0.5) / n as f32;
                let v = (j as f32 + 0.5) / n as f32;
                let p = self.sample(u, v);
                let dir = p - point;
                let dist2 = dir.length_squared();
                if dist2 < 1e-6 { continue; }
                let n_dot_l = normal.dot(dir / dist2.sqrt()).max(0.0);
                if n_dot_l == 0.0 { continue; }
                if occlusion(point, p) { continue; }
                let attenuation = 1.0 / (dist2 + 0.01);
                accum += self.color * self.luminous_flux * n_dot_l * attenuation;
            }
        }
        accum / level.total_samples() as f32
    }
}

fn main() {
    let light = RectLight {
        center: Vec3::new(0.0, 5.0, 0.0),
        half_extent: Vec3::new(0.5, 0.5, 0.0),
        luminous_flux: 1000.0,
        color: Vec3::ONE,
    };

    let normal = Vec3::Y;

    // 测试不同距离
    for dist in [2.0, 5.0, 10.0, 30.0, 100.0] {
        let point = Vec3::new(0.0, 5.0 - dist, 0.0);  // 在光源下方 dist 米处
        let level = DetailLevel::from_distance(dist);
        let samples = level.total_samples();
        let lighting = light.illuminate_at(point, normal, |_, _| false);
        println!("dist={:6.1}m level={:?} samples={} lighting={:.4}",
            dist, level, samples, lighting.x);
    }

    // 性能 benchmark
    let n_primitives = 1000;
    let primitive_positions: Vec<Vec3> = (0..n_primitives).map(|i| {
        let dist = (i as f32) * 0.1;  // 0 到 100m
        Vec3::new(0.0, 5.0 - dist, 0.0)
    }).collect();

    let start = std::time::Instant::now();
    let mut total_rays = 0u64;
    for p in &primitive_positions {
        let level = DetailLevel::from_distance((light.center - p).length());
        total_rays += level.total_samples() as u64;
        let _ = light.illuminate_at(*p, normal, |_, _| false);
    }
    let multi_time = start.elapsed();
    println!("\nMultires: {} prims, {} rays, {:?}", n_primitives, total_rays, multi_time);

    // 固定 16 采样对比
    let start = std::time::Instant::now();
    let fixed_rays = n_primitives * 16;
    for p in &primitive_positions {
        // 模拟固定 16
        let _ = light.illuminate_at(*p, normal, |_, _| false);
    }
    let fixed_time = start.elapsed();
    println!("Fixed 16: {} prims, {} rays, {:?}", n_primitives, fixed_rays, fixed_time);

    println!("Reduction: {:.1}x fewer rays", fixed_rays as f64 / total_rays as f64);
}
```

```rust
use glam::Vec3;

#[derive(Copy, Clone, Debug)]
pub enum DetailLevel {
    Near,    // 4x4 = 16 samples
    Mid,     // 3x3 = 9
    Far,     // 2x2 = 4
    Distant, // 1x1 = 1
}

impl DetailLevel {
    pub fn from_distance(dist: f32) -> Self {
        if dist < 5.0 { Self::Near }
        else if dist < 15.0 { Self::Mid }
        else if dist < 50.0 { Self::Far }
        else { Self::Distant }
    }

    pub fn samples_per_axis(self) -> u32 {
        match self {
            Self::Near => 4,
            Self::Mid => 3,
            Self::Far => 2,
            Self::Distant => 1,
        }
    }

    pub fn total_samples(self) -> u32 {
        let n = self.samples_per_axis();
        n * n
    }
}

pub struct RectLight {
    pub center: Vec3,
    pub half_extent: Vec3,
    pub luminous_flux: f32,
    pub color: Vec3,
}

impl RectLight {
    pub fn sample(&self, u: f32, v: f32) -> Vec3 {
        Vec3::new(
            self.center.x + (u - 0.5) * 2.0 * self.half_extent.x,
            self.center.y + (v - 0.5) * 2.0 * self.half_extent.y,
            self.center.z,
        )
    }

    pub fn illuminate_at_multires(
        &self,
        point: Vec3,
        normal: Vec3,
        occlusion: impl Fn(Vec3, Vec3) -> bool,
    ) -> Vec3 {
        let dist = (self.center - point).length();
        let level = DetailLevel::from_distance(dist);
        let n = level.samples_per_axis();

        let mut accum = Vec3::ZERO;
        let mut count = 0;
        for i in 0..n {
            for j in 0..n {
                let u = (i as f32 + 0.5) / n as f32;
                let v = (j as f32 + 0.5) / n as f32;
                let p = self.sample(u, v);
                let dir = p - point;
                let dist2 = dir.length_squared();
                if dist2 < 1e-6 { continue; }
                let n_dot_l = normal.dot(dir / dist2.sqrt()).max(0.0);
                if n_dot_l == 0.0 { continue; }
                if occlusion(point, p) { continue; }
                let attenuation = 1.0 / (dist2 + 0.01);
                accum += self.color * self.luminous_flux * n_dot_l * attenuation;
                count += 1;
            }
        }
        // 除以 total_samples 而不是 count(让遮挡的样本贡献 0)
        accum / level.total_samples() as f32
    }
}

fn main() {
    let light = RectLight {
        center: Vec3::new(0.0, 10.0, 0.0),
        half_extent: Vec3::new(1.0, 1.0, 0.0),
        luminous_flux: 2000.0,
        color: Vec3::ONE,
    };
    let normal = Vec3::Y;

    println!("=== Multiresolution sampling demo ===");
    println!("dist (m) | level    | samples | lighting");
    println!("---------+----------+---------+---------");

    let distances = [1.0, 3.0, 5.0, 8.0, 15.0, 25.0, 50.0, 100.0];
    for dist in distances {
        let point = Vec3::new(0.0, 10.0 - dist, 0.0);
        let level = DetailLevel::from_distance(dist);
        let samples = level.total_samples();
        let lighting = light.illuminate_at_multires(point, normal, |_, _| false);
        println!("{:8.1} | {:?} | {:7} | {:.4}", dist, level, samples, lighting.x);
    }

    // 性能测试
    println!("\n=== Performance ===");
    let n_primitives = 10000;
    let positions: Vec<Vec3> = (0..n_primitives).map(|i| {
        let dist = (i as f32) * 0.01;  // 0 到 100m
        Vec3::new(0.0, 10.0 - dist, 0.0)
    }).collect();

    let start = std::time::Instant::now();
    let mut total_rays = 0u64;
    for p in &positions {
        let level = DetailLevel::from_distance((light.center - p).length());
        total_rays += level.total_samples() as u64;
        let _ = light.illuminate_at_multires(*p, normal, |_, _| false);
    }
    let multi_time = start.elapsed();

    println!("Multires {} prims: {} rays, {:?}", n_primitives, total_rays, multi_time);
    println!("Average samples per primitive: {:.1}",
        total_rays as f64 / n_primitives as f64);

    // 固定 16 采样对比
    let fixed_rays = n_primitives as u64 * 16;
    println!("Fixed 16: {} rays (hypothetical)", fixed_rays);
    println!("Reduction: {:.1}x fewer rays with multires",
        fixed_rays as f64 / total_rays as f64);
}
```

### 深度推导:本日相关数学与算法

要真正掌握今天的内容,我们必须把背后的数学推导展开。这一节是"为什么这么做"的论证。

**算法复杂度的精确分析**。今天的代码涉及到对实体集合排序,基准复杂度:

- 最优比较排序下界:O(N log N)(决策树理论)
- Rust `sort_by`:TimSort,平均 O(N log N),最好 O(N)(已部分有序时)
- 拓扑排序:O(V + E),V 是节点数,E 是边数
- Radix sort:O(N × k),k 是 sort key 位数——非比较排序,可突破 O(N log N)

对一个 1000 sprite 的场景,TimSort 大约 10000 次比较,每次比较 5-10 个 cycle(分支少),总 50000-100000 cycle = 20-40 μs。在 60 FPS(16666 μs 预算)占 0.2%——可忽略。100K sprite 时升到 2 ms,开始有压力。Minecraft 这种规模的游戏必须用 radix sort 或 GPU sort。

**内存访问模式**。sort 是**非线性内存访问**的典型——每次比较都可能跳到 Vec 不同位置。CPU prefetcher 抓不到模式,cache miss 频繁。优化:

1. **Sort by index**:先 sort indices(u32 数组,4 字节/项,cache 友好),再 reorder 数据。indices 1000 个 = 4 KB,L1 cache 装得下。
2. **Batch reorder**:indices 排好后,顺序遍历 indices,顺序访问原数据(虽然是间接但 prefetcher 跟得上)。

```rust
let mut indices: Vec<u32> = (0..entities.len() as u32).collect();
indices.sort_by(|&a, &b| sort_rule(&entities[a as usize], &entities[b as usize]));
let sorted: Vec<&Entity> = indices.iter().map(|&i| &entities[i as usize]).collect();
```

100K sprite 的 sort 用这个技巧能加速 30%。

**位运算打包 sort key**。今天 sort_key 是 u64,可以塞进多个字段:

```
bits 63-56: layer (8 bits, 256 layers)
bits 55-40: bottom_y (16 bits, 65536 levels)
bits 39-24: x (16 bits)
bits 23-8: sub_layer (16 bits)
bits 7-0: spawn_id (8 bits, 256 entries per slot)
```

打包:`key = (layer << 56) | (bottom_y << 40) | (x << 24) | (sub << 8) | spawn`。一次 u64 比较,无分支,Rust `sort_by_key` 自动 inline。

**部分序的图论模型**。Day 304 会用拓扑排序处理真正的部分序。每个 sprite 是图节点,如果 A 应该在 B 前面,加边 A→B。拓扑排序给出节点的合法顺序(满足所有约束)。

拓扑排序算法:

1. **Kahn 算法**:每次找入度为 0 的节点,加入结果,删掉它的出边,重复。
2. **DFS 后序**:DFS 遍历,记录后序(post-order),反转得到拓扑序。

如果图有环(循环依赖),拓扑排序失败——意味着 sprite 排序无解,必须**人为拆解**(切开某个 sprite)。

**浮点数的稳定性**。Rust 的 `f32::partial_cmp` 处理 NaN 返回 `None`,sort 会 panic。所以游戏代码里要么保证所有 f32 都不是 NaN(数学保证),要么 `partial_cmp(...).unwrap_or(Equal)`(默认相等)。今天 sort_rule 用后者。

更稳妥的方法:**所有位置用整数**(像素单位)。`pos_y: i32` 没有 NaN 问题,比较无分支。但缩放和旋转要用浮点,所以游戏用 i32 + f32 混合。

### 真实代码片段

Casey 在 HH 视频里实际写的代码风格(简化伪代码):

```c
internal int32
SortRule(entity *A, entity *B)
{
    int32 Result = 0;

    // Layer 比较
    if (A->Layer != B->Layer) {
        Result = (int32)A->Layer - (int32)B->Layer;
    } else {
        // Bounds overlap 检查
        rectangle2 BoundsA = GetEntityBounds(A);
        rectangle2 BoundsB = GetEntityBounds(B);
        if (RectanglesOverlap(BoundsA, BoundsB)) {
            // Bottom y 比较
            real32 BottomA = BoundsA.Max.Y;
            real32 BottomB = BoundsB.Max.Y;
            if (BottomA != BottomB) {
                Result = (BottomA < BottomB) ? -1 : 1;
            } else {
                // x 比较
                Result = SignOf32(A->P.X - B->P.X);
            }
        } else {
            // 不重叠:任意顺序
            Result = A->SpawnID - B->SpawnID;
        }
    }

    return Result;
}
```

注意 Casey 的 C 风格:

- 直接返回 int32(而非 enum Ordering)
- 用 `SignOf32`(返回 -1/0/1)简化比较
- if-else 链而非 Rust 的 `then_with`

Rust 等价:

```rust
fn sort_rule(a: &Entity, b: &Entity) -> Ordering {
    a.layer.cmp(&b.layer)
        .then_with(|| {
            if bounds_overlap(a, b) {
                let ba = bounds(a).max.y;
                let bb = bounds(b).max.y;
                ba.partial_cmp(&bb).unwrap_or(Ordering::Equal)
                    .then(a.pos.x.partial_cmp(&b.pos.x).unwrap_or(Ordering::Equal))
            } else {
                a.spawn_id.cmp(&b.spawn_id)
            }
        })
}
```

### 跨学科联结:从游戏到数据库

sort_rule 的本质是"复杂比较函数",这在很多领域都出现:

- **数据库 ORDER BY**:SQL 的 `ORDER BY layer, y, x` 是同样的 multi-key sort,但 SQL 是声明式(数据库优化器选 sort 算法),Casey 是命令式(手写 sort_by)。
- **React diff**:React 用 sort + key 比较 virtual DOM,决定哪些 component 重渲染。Multi-key sort 决定 diff 顺序。
- **Linux kernel CFS**(Completely Fair Scheduler):按 vruntime 排序进程,选最小 vruntime 的运行。本质是 sort_rule。
- **Git log --sort**:Git commit 按 committer date + author date + subject 排序。

Casey 在 HH 反复说"很多算法本质相同,只是命名不同"。掌握一个领域的 sort_rule,就掌握所有领域。
