
# Day 389 · 加简单光照

> MSAA 深度剥离搞定后,Casey 把目光转向一个全新的领域:**光照**。今天他从最简单的开始——**Lambert 漫反射**(基于点积的简单光照模型),让物体有"立体感"。这一集从数学到 shader,完整讲一遍光照的基础。

## 0 · 为什么要有这一天

到目前为止,你的 3D 物体看起来是"扁平的"——一个球渲染出来是个均匀颜色的圆盘,看不出是球。问题不在几何(几何是球),而在**没有光照**。光照让相同颜色的物体在不同朝向的表面**亮度不同**,大脑根据亮度推断出"这是个球"。

人眼和大脑对**亮度梯度**极度敏感。一个均匀红色的圆,你看到的是"平面圆";一个有亮度梯度的圆(从左上亮、右下暗),你看到的是"3D 球"。这个梯度来自光照——光从某个方向来,球的不同朝向的表面接收的光量不同,反射到眼睛的强度也不同。

**Lambert 漫反射**(Johann Heinrich Lambert, 1760)是最简单的光照模型:

- 假设物体表面是"理想漫反射体"(Lambertian surface)
- 任何方向的反射光强度 = 入射光强度 × cos(入射角)
- 入射角 = 表面法线和光源方向的夹角
- 用点积表达:`brightness = max(0, dot(normal, light_dir))`

这是个数学公式,但理解它需要从物理直觉出发:

- **光直射**(法线和光源方向同向,夹角 0°):cos = 1,最亮
- **光斜射**(夹角 45°):cos ≈ 0.707,亮度 71%
- **光掠过**(夹角 90°):cos = 0,最暗(边缘)
- **光在背面**(夹角 > 90°):cos < 0,clamp 到 0(全黑)

今天的产出:**渲染的球终于有立体感了**——光从右上角照下来,球的左上半亮,右下半暗,中间平滑过渡。从此画面"有质感"。

心理锚点:看完今天,你能(1)从物理直觉解释 Lambert 漫反射;(2)推导 `dot(N, L) = cos(θ)`;(3)在 GLSL 里实现 Lambert 光照;(4)理解为什么光照要在线性空间做。

## 2 · 心智模型

### 类比:太阳和墙

想象一面墙,太阳从某个角度照过来。

- **正对太阳**(墙面和阳光垂直):墙接收最多光,最亮
- **侧对太阳**(墙面和阳光夹角小):墙接收的光少,暗
- **背对太阳**(墙面在阴影里):墙不接收直射光,但有天空散射光,不黑

这就是 Lambert 漫反射的物理对应——**墙面接收的光量正比于阳光和墙面法线的夹角的余弦**。

**为什么是余弦(不是正切 / 正弦)?**

考虑一束"平行光"(太阳光),光通量是固定的(单位时间单位面积的能量)。墙面接收的光通量 = 光束横截面 × cos(θ),其中 θ 是墙面和光束的夹角。

```
        光束方向 →
        ━━━━━━━━━━━
        ━━━━━━━━━━━     ← 光束横截面 = A
        ━━━━━━━━━━━

            /         
           / θ        
          /           
         ─────────     ← 墙面(宽度 B = A / cos(θ))

墙面接收的光 = 光束密度 × 墙面投影面积
            = (光通量 / A) × A × cos(θ) / A  ← 投影到光束方向
            ∝ cos(θ)
```

但墙面接收的能量等于光束"穿过墙面投影"的能量。墙面在光束方向的投影面积 = `B × cos(θ) = (A/cos(θ)) × cos(θ) = A`。咦,这看起来是常数?

**关键修正**:墙面接收的能量 = 光通量 / 墙面**实际**面积 = `光束密度 × A / B = 光束密度 × cos(θ)`。所以**单位墙面面积**接收的能量 ∝ cos(θ)。

**这就是 Lambert 余弦定律**——单位面积接收的辐射通量 ∝ cos(θ)。

### 严谨推导:点积 = 余弦

向量点积定义:`a · b = |a| × |b| × cos(θ)`,θ 是 a 和 b 的夹角。

如果 a 和 b 都是**单位向量**(`|a| = |b| = 1`),则 `a · b = cos(θ)`。

在光照里:

- **N** = 表面法线(单位向量,垂直于表面)
- **L** = 指向光源的向量(单位向量)
- `N · L = cos(θ)`,θ 是法线和光源方向的夹角

** θ 是什么物理意义**?

- θ = 0:N 和 L 同向(光从正面来,沿法线方向射入)
- θ = 90°:N 和 L 垂直(光从侧面来,沿表面方向掠过)
- θ = 180°:N 和 L 反向(光从背面来,不在表面)

θ ∈ [0°, 90°] 是"光在表面正面",Lambert brightness = `cos(θ) = N · L`(正值)。
θ ∈ (90°, 180°] 是"光在表面背面",`N · L < 0`,clamp 到 0。

GLSL 实现:

```glsl
vec3 N = normalize(normal);  // 法线,确保单位长度
vec3 L = normalize(light_dir);  // 光源方向,确保单位长度
float brightness = max(0.0, dot(N, L));  // clamp 负值到 0
vec3 diffuse = albedo * light_color * brightness;
```

**为什么 `max(0.0, ...)`**?点积可能是负(光在背面),负的 brightness 无意义(物体不能"反发光"),clamp 到 0 表示"这个像素不接收光"。

### 完整 Lambert 光照公式

```
final_color = ambient + diffuse + specular(明天)
            = albedo * ambient_color
            + albedo * light_color * max(0, dot(N, L))
            + (明天加)
```

**Ambient**(环境光):常数,模拟"来自四面八方的散射光"。没有 ambient,光在背面的像素全黑,看起来很假。加 ambient 让"阴影里"也有微弱亮度。

```
ambient = albedo * vec3(0.1, 0.1, 0.1)  // 10% 环境光
```

**Diffuse**(漫反射):Lambert,上面讲过。

**Specular**(镜面反射):明天(Day 390)讲,Phong 高光。

### 光照的物理 vs 工程

Lambert 漫反射是个**理想模型**——真实物体表面有:

- **菲涅尔效应**(Fresnel):掠射角时反射率增大
- **微表面**(Microfacet):表面不是理想漫反射,是无数小镜面
- **次表面散射**(Subsurface scattering):光穿过物体(皮肤、蜡)
- **各向异性**(Anisotropic):金属拉丝等方向性反射

但 Lambert 是基础,90% 的渲染场景用 Lambert + Specular 就够。PBR(Physically Based Rendering,Day 391+ 介绍)是更精确的模型,但概念上是 Lambert 的扩展。

### Linear vs sRGB(再次强调)

光照计算**必须在线性空间**。如果 albedo 来自 sRGB PNG,采样后转 Linear:

```glsl
vec3 albedo_linear = pow(texture(albedo_tex, uv).rgb, vec3(2.2));
// 或更精确的 sRGB 解码公式
```

光照后,**输出时**再转 sRGB(由 `GL_FRAMEBUFFER_SRGB` 自动处理):

```glsl
frag_color.rgb = final_color;  // 假设 framebuffer 是 sRGB,自动转换
```

如果不做这个转换,**暗部变暗**(γ 错误累积),颜色失真。

### 法线空间(World / View / Tangent)

法线可以在不同空间表达:

- **World space**:世界坐标系,光照计算最常用
- **View space**:相机坐标系,某些光照算法用
- **Tangent space**:切线空间,法线贴图用(Day 392+)

Casey Day 389 用 world space,最直观。

### 法线的传递(Vertex → Fragment Shader)

Vertex shader 接收 model space normal,变换到 world space:

```glsl
// vertex shader
in vec3 normal;  // model space
uniform mat4 model_matrix;
uniform mat4 normal_matrix;  // = transpose(inverse(model_matrix))
out vec3 v_world_normal;

void main() {
    v_world_normal = (normal_matrix * vec4(normal, 0.0)).xyz;
    gl_Position = ...;
}
```

**为什么 normal_matrix 是 `transpose(inverse(model_matrix))`**?

如果 model_matrix 只有旋转 + 平移,inverse 然后 transpose 就是去掉平移(法线是方向,不要平移)+ 抵消旋转(因为旋转矩阵的逆是它的 transpose,所以两次 transpose = identity)。结果:法线也跟着旋转。

如果 model_matrix 有**非均匀缩放**(沿 x 轴放大 2 倍),直接用 model_matrix 变换法线会让法线**变形**(不再垂直于表面)。必须用 normal_matrix 修正。

数学证明较长,我们记结论:**法线变换用 `transpose(inverse(model))`**,position 变换用 `model`。

GLSL 提供 `inverse` 和 `transpose` 函数(GLSL 4.0+),CPU 端预计算更好(避免每 vertex 算)。

### Fragment Shader 完整光照

```glsl
#version 330

in vec3 v_world_normal;
in vec2 v_uv;

uniform sampler2D albedo_tex;
uniform vec3 light_dir;       // world space,指向光源
uniform vec3 light_color;     // RGB,光强
uniform vec3 ambient_color;   // 环境光

out vec4 frag_color;

void main() {
    // 1. 采样纹理(sRGB → Linear)
    vec3 albedo = texture(albedo_tex, v_uv).rgb;
    albedo = pow(albedo, vec3(2.2));  // sRGB → Linear

    // 2. 归一化法线(interpolation 后可能不单位)
    vec3 N = normalize(v_world_normal);
    vec3 L = normalize(light_dir);

    // 3. Lambert 漫反射
    float brightness = max(0.0, dot(N, L));
    vec3 diffuse = albedo * light_color * brightness;

    // 4. Ambient
    vec3 ambient = albedo * ambient_color;

    // 5. 合成
    vec3 final_color = ambient + diffuse;

    // 6. Linear → sRGB(假设 framebuffer 不是 sRGB,手动转)
    final_color = pow(final_color, vec3(1.0 / 2.2));

    frag_color = vec4(final_color, 1.0);
}
```

**每段解释**:

1. **采样 + sRGB 解码**:PNG 文件存 sRGB,采样后转 Linear。如果用 sRGB 纹理格式(`GL_SRGB8_ALPHA8`),OpenGL 自动转。
2. **normalize 法线**:vertex shader 输出的法线经过 rasterizer 的插值后**长度变化**,fragment shader 必须重新归一化。
3. **Lambert**:`dot(N, L)`,clamp 负值。
4. **Ambient**:固定低强度,模拟环境散射。
5. **合成**:ambient + diffuse(加法混合,不饱和)。可以做 HDR(颜色 > 1.0),最后 tone map。
6. **sRGB 编码**:如果 framebuffer 不是 sRGB,手动转。如果开了 `GL_FRAMEBUFFER_SRGB`,删掉这行。

### 光照的"颜色"

光的颜色 RGB 表达:

- 白光:`(1, 1, 1)`
- 红光:`(1, 0, 0)`
- 暖光(日落):`(1, 0.7, 0.4)`
- 冷光(阴天):`(0.8, 0.9, 1.0)`

光照颜色和表面 albedo **逐通道相乘**——红光照蓝色物体,结果是黑色(蓝物体不反射红光)。

```
red_light × blue_object = (1, 0, 0) × (0, 0, 1) = (0, 0, 0)
```

这是物理正确的——白光下的红苹果是红的,绿光下的红苹果是黑的(苹果只反射红光)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏里的光照层次:

- **Ambient**(环境):全局常数,模拟"天空 + 间接光"
- **Hemisphere light**(半球光):天空 vs 地面用不同颜色(天空蓝,地面棕)
- **Directional light**(方向光):模拟太阳,平行光,方向固定
- **Point light**(点光源):灯泡,光从一点向四面八方
- **Spot light**(聚光灯):手电筒,锥形光
- **Area light**(面光源):日光灯管,有面积

每种光源的数学公式不同:

- **Directional**:光源方向 L 固定,brightness = `max(0, dot(N, L))`
- **Point**:光源方向 L = `normalize(light_pos - surface_pos)`,brightness 还要除以距离平方(物理衰减)
- **Spot**:在 point 基础上加 cone 衰减

Casey Day 389 只做 directional light(最简单)。Day 392+ 加更多光源。

**多光源**:每帧 N 个光源,每个光源算一次光照,加起来。N 大时性能差,需要优化(light culling、cluster shading、tiled deferred)。

### 3.2 · 🎨 图形学视角

**BRDF**(Bidirectional Reflectance Distribution Function,双向反射分布函数):形式化光照模型的数学工具。BRDF `f(ωi, ωo)` 给出"从 ωi 入射的光,有多少反射到 ωo"。

Lambert 漫反射的 BRDF 是常数:`f = albedo / π`。意思是"光被均匀反射到所有方向"。

Phong / Blinn-Phong 的 BRDF 有镜面项:`f = albedo/π + specular_term`。

PBR(Blinn-Phong 的现代化)的 BRDF 更复杂,涉及微表面分布、菲涅尔、几何遮蔽,但**思想相同**——精确描述"光如何从表面反射"。

**Energy conservation**(能量守恒):真实 BRDF 满足"反射光总能量 ≤ 入射光能量"。Lambert 满足(常数 albedo / π 积分 = albedo)。Phong 不严格满足(specular 项可以超过入射)。

### 3.3 · 🐧 Linux 系统编程视角

光照不涉及系统编程(纯 GPU 算法)。但 Linux 上有**光照相关的硬件特性**:

- **GPU 的 SFU**(Special Function Unit):快速算 `sin`, `cos`, `pow` 等。GLSL 的 `pow(albedo, 2.2)` 编译为 SFU 指令。
- **FMA**(Fused Multiply-Add):`a*b + c` 一次运算。`albedo * light * brightness` 用 FMA。
- **Half-precision float**(fp16):某些 GPU 支持 fp16 光照,2 倍快(移动 GPU 主流)。

```bash
# 查 GPU 的特殊功能
clinfo | grep "Max clock frequency"
# OpenCL 提供硬件特性查询

# 看光照 shader 的汇编(AMD)
sudo pacman -S mesa-demos

```

### 3.4 · 🦀 Rust 生态视角

Rust 端光照的代码组织:

```rust
#[derive(Copy, Clone, Debug)]
pub struct DirectionalLight {
    pub direction: glam::Vec3,  // world space,指向光源
    pub color: glam::Vec3,      // RGB,光强
}

impl DirectionalLight {
    pub fn new(direction: glam::Vec3, color: glam::Vec3) -> Self {
        Self {
            direction: direction.normalize(),  // 确保单位长度
            color,
        }
    }
}

#[derive(Copy, Clone, Debug)]
pub struct Material {
    pub albedo: glam::Vec3,
    pub ambient: f32,
}

impl Material {
    pub fn lambert(&self, normal: glam::Vec3, light: &DirectionalLight) -> glam::Vec3 {
        let brightness = normal.dot(light.direction).max(0.0);
        let ambient = self.albedo * self.ambient;
        let diffuse = self.albedo * light.color * brightness;
        ambient + diffuse
    }
}
```

**glam** crate 提供 `Vec3::dot`、`normalize` 等数学操作,SIMD 优化。Casey HH 用手写数学,但 Rust 项目可以用 glam。

**Shader 端**:GLSL 没法直接用 Rust struct,需要把数据**展平**为 uniform:

```rust
let uniforms = glium::uniform! {
    light_dir: light.direction.to_array(),  // [f32; 3]
    light_color: light.color.to_array(),
    ambient_color: [ambient, ambient, ambient],
};
```

glam 的 `Vec3::to_array()` 返回 `[f32; 3]`,glium 能直接接收。

## 4 · 认知地图

### 4.1 上级

- **光照模型**(Lighting model)— 一类算法,描述光如何与表面交互
- **BRDF** — 光照模型的数学形式化
- **基于物理的渲染**(PBR)— 现代光照模型的标准

### 4.2 同级

| 模型 | 精度 | 复杂度 | 用途 |
|---|---|---|---|
| **Lambert 漫反射** | 漫反射,无镜面 | 极简 | 入门 / 漫反射物体 |
| Phong | 漫反射 + 镜面 | 简单 | 经典游戏 |
| Blinn-Phong | Phong 优化 | 简单 | 现代游戏基础 |
| PBR(Cook-Torrance) | 物理精确 | 中等 | AAA 游戏 |
| Ray tracing | 物理完美 | 极高 | 电影 / RTX |

### 4.3 下级

- **Surface normal**(法线)— 垂直于表面的单位向量
- **Light direction**(光源方向)— 指向光源的单位向量
- **Dot product**(点积)— 衡量方向对齐
- **Ambient light**(环境光)— 全局常数,模拟散射
- **Diffuse term**(漫反射项)— Lambert
- **Normal matrix**(`transpose(inverse(model))`)— 法线变换

## 5 · 对照与变奏

### 同一问题在不同语境下的变体

**问题**:计算"光对表面的照射强度"。

| 语境 | 模型 |
|---|---|
| 实时渲染 | Lambert + Phong |
| 离线渲染 | 完整 BRDF + ray tracing |

**核心模式**:**入射强度 ∝ cos(入射角) ∝ dot(normal, light)**。

- **2010s**:PBR(基于物理的渲染)成为 AAA 标杆

| | CPU | GPU |

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Lambert 漫反射的 `brightness = max(0, dot(N, L))`,为什么需要 `max(0, ...)`?不加会怎样?

**参考解答**:

不加 `max(0, ...)`:`brightness = dot(N, L)` 可能为负(当 N 和 L 夹角 > 90°,即光在表面背面)。

负面影响:

- `albedo × light × negative_brightness = negative_color`,颜色变负
- 写入 framebuffer(无符号)时 clamp 到 0,看起来"正常",但**插值时**会有伪影——边界处亮度突变,显示为黑色边缘
- 后续 post-processing(bloom、tone mapping)假设颜色非负,负值导致伪影

`max(0, ...)` 把背面亮度强制为 0,语义上"光在背面的表面不发光"。这是物理正确的——光不能"穿透"物体表面到达背面(不考虑透明物体)。

**注意**:有些光照模型(如双面光照)不 clamp,而是 `abs(dot(N, L))`,让背面也接收光(模拟"光从两面来")。具体取决于应用。

**题**:在 Day 388 的 demo 基础上加 Lambert 光照。给球加法线(指向外),光源在右上角 `(1, 1, 0)` 方向。

完成标准:球看起来有立体感(左上亮,右下暗)。

```rust
use glium::{glutin, Surface, implement_vertex, program, index, uniform};
use glam::{Vec3, Mat4};

#[derive(Copy, Clone)]
struct Vertex {
    position: [f32; 3],
    normal: [f32; 3],
}
implement_vertex!(Vertex, position, normal);

fn main() {
    let event_loop = glutin::event_loop::EventLoop::new();
    let wb = glutin::window::WindowBuilder::new()
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 600));
    let cb = glutin::ContextBuilder::new();
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    // 生成球体顶点(简化:6 个顶点构成 4 个三角形)
    // 真实球应该用面片化生成
    let verts = vec![
        // 三角形 1
        Vertex { position: [-0.5, -0.5, 0.0], normal: [0.0, 0.0, 1.0] },
        Vertex { position: [ 0.5, -0.5, 0.0], normal: [0.0, 0.0, 1.0] },
        Vertex { position: [ 0.0,  0.5, 0.0], normal: [0.0, 0.0, 1.0] },
    ];
    let vbuf = glium::VertexBuffer::new(&display, &verts).unwrap();
    let indices = index::NoIndices(index::PrimitiveType::TrianglesList);

    let program = program!(&display,
        330 es => {
            vertex: r#"#version 330
                in vec3 position;
                in vec3 normal;
                out vec3 v_normal;
                void main() {
                    v_normal = normal;
                    gl_Position = vec4(position, 1.0);
                }
            "#,
            fragment: r#"#version 330
                in vec3 v_normal;
                uniform vec3 light_dir;
                uniform vec3 light_color;
                uniform vec3 albedo;
                uniform vec3 ambient_color;
                out vec4 frag;
                void main() {
                    vec3 N = normalize(v_normal);
                    vec3 L = normalize(light_dir);
                    float brightness = max(0.0, dot(N, L));
                    vec3 diffuse = albedo * light_color * brightness;
                    vec3 ambient = albedo * ambient_color;
                    frag = vec4(ambient + diffuse, 1.0);
                }
            "#,
        }).unwrap();

    // 光源方向(右上角,从相机视角看)
    let light_dir = Vec3::new(1.0, 1.0, 1.0).normalize();

    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        if let Event::RedrawRequested(_) = event {
            let mut target = display.draw();
            target.clear_color(0., 0., 0., 1.0);

            let uniforms = uniform! {
                light_dir: light_dir.to_array(),
                light_color: [1.0f32, 1.0, 1.0],  // 白光
                albedo: [1.0f32, 0.3, 0.3],  // 红色物体
                ambient_color: [0.1f32, 0.1, 0.1],  // 10% 环境光
            };
            target.draw(&vbuf, &indices, &program, &uniforms,
                &Default::default()).unwrap();
            target.finish().unwrap();
        }

        if let Event::WindowEvent { event: WindowEvent::CloseRequested, .. } = event {
            *control_flow = ControlFlow::Exit;
        }
    });
}
```

**关键点**:

- Vertex 加 `normal` 字段——三角形面向 +Z(法线 (0,0,1))
- Fragment shader 接收 `v_normal`(插值后),`normalize` 保证单位长度
- `light_dir` 是 uniform,从外部传入
- 光源方向 `(1, 1, 1)` 归一化后传 shader
- `max(0, dot(N, L))` 计算 Lambert brightness
- ambient + diffuse 合成

**预期画面**:三角形看起来是平的(几何是平的),但有一边亮一边暗(因为法线和光源夹角不同)。如果把三角形改成球(用面片化生成法线指向球外),球就有立体感。

```toml
[package]

[dependencies]
```

```rust
// src/main.rs
use glium::{glutin, Surface, implement_vertex, program, index, uniform};
use glam::Vec3;

#[derive(Copy, Clone)]
struct Vertex {
    position: [f32; 3],
    normal: [f32; 3],
}
implement_vertex!(Vertex, position, normal);

#[derive(Copy, Clone)]
struct Light {
    direction: Vec3,
    color: Vec3,
}

impl Light {
    fn new(direction: Vec3, color: Vec3) -> Self {
        Self { direction: direction.normalize(), color }
    }
}

/// 生成 UV 球(简化:用经纬度球面)
fn make_sphere(radius: f32, segments: usize, rings: usize) -> Vec<Vertex> {
    let mut verts = Vec::new();
    for i in 0..rings {
        let theta1 = (i as f32 / rings as f32) * std::f32::consts::PI;
        let theta2 = ((i + 1) as f32 / rings as f32) * std::f32::consts::PI;
        for j in 0..segments {
            let phi1 = (j as f32 / segments as f32) * 2.0 * std::f32::consts::PI;
            let phi2 = ((j + 1) as f32 / segments as f32) * 2.0 * std::f32::consts::PI;

            // 四个顶点
            let p1 = spherical_to_cartesian(theta1, phi1, radius);
            let p2 = spherical_to_cartesian(theta1, phi2, radius);
            let p3 = spherical_to_cartesian(theta2, phi2, radius);
            let p4 = spherical_to_cartesian(theta2, phi1, radius);

            // 法线 = 顶点位置归一化(因为是球)
            let n1 = p1.normalize();
            let n2 = p2.normalize();
            let n3 = p3.normalize();
            let n4 = p4.normalize();

            // 两个三角形
            verts.push(Vertex { position: p1.to_array(), normal: n1.to_array() });
            verts.push(Vertex { position: p2.to_array(), normal: n2.to_array() });
            verts.push(Vertex { position: p3.to_array(), normal: n3.to_array() });

            verts.push(Vertex { position: p1.to_array(), normal: n1.to_array() });
            verts.push(Vertex { position: p3.to_array(), normal: n3.to_array() });
            verts.push(Vertex { position: p4.to_array(), normal: n4.to_array() });
        }
    }
    verts
}

fn spherical_to_cartesian(theta: f32, phi: f32, r: f32) -> Vec3 {
    Vec3::new(
        r * theta.sin() * phi.cos(),
        r * theta.cos(),
        r * theta.sin() * phi.sin(),
    )
}

fn main() {
    let event_loop = glutin::event_loop::EventLoop::new();
    let wb = glutin::window::WindowBuilder::new()
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 600))
        .with_title("Lambert Lighting");
    let cb = glutin::ContextBuilder::new().with_depth_buffer(24);
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    // 生成球
    let sphere_verts = make_sphere(0.7, 32, 16);
    let vbuf = glium::VertexBuffer::new(&display, &sphere_verts).unwrap();
    let indices = index::NoIndices(index::PrimitiveType::TrianglesList);

    // 简单的透视投影
    let aspect = 800.0 / 600.0;
    let projection = glam::Mat4::perspective_rh(std::f32::consts::PI / 4.0, aspect, 0.1, 100.0);
    let view = glam::Mat4::look_at_rh(
        Vec3::new(0.0, 0.0, 3.0),
        Vec3::new(0.0, 0.0, 0.0),
        Vec3::new(0.0, 1.0, 0.0),
    );
    let model = glam::Mat4::IDENTITY;
    let mvp = projection * view * model;

    let light = Light::new(Vec3::new(1.0, 1.0, 1.0), Vec3::new(1.0, 1.0, 1.0));

    let program = program!(&display,
        330 es => {
            vertex: r#"#version 330
                in vec3 position;
                in vec3 normal;
                uniform mat4 mvp;
                out vec3 v_normal;
                void main() {
                    v_normal = normal;
                    gl_Position = mvp * vec4(position, 1.0);
                }
            "#,
            fragment: r#"#version 330
                in vec3 v_normal;
                uniform vec3 light_dir;
                uniform vec3 light_color;
                uniform vec3 albedo;
                uniform vec3 ambient_color;
                out vec4 frag;
                void main() {
                    vec3 N = normalize(v_normal);
                    vec3 L = normalize(light_dir);
                    float brightness = max(0.0, dot(N, L));
                    vec3 diffuse = albedo * light_color * brightness;
                    vec3 ambient = albedo * ambient_color;
                    vec3 final = ambient + diffuse;
                    // 简单 tone map(防止过曝)
                    final = final / (final + vec3(1.0));
                    frag = vec4(final, 1.0);
                }
            "#,
        }).unwrap();

    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        if let Event::RedrawRequested(_) = event {
            let mut target = display.draw();
            target.clear_color_and_depth((0.05, 0.05, 0.1, 1.0), 1.0);

            let uniforms = uniform! {
                mvp: mvp.to_cols_array_2d(),
                light_dir: light.direction.to_array(),
                light_color: light.color.to_array(),
                albedo: [0.8f32, 0.3, 0.2],
                ambient_color: [0.1f32, 0.1, 0.15],
            };

            let params = glium::DrawParameters {
                depth: glium::Depth {
                    test: glium::draw_parameters::DepthTest::IfLess,
                    write: true,
                    ..Default::default()
                },
                ..Default::default()
            };

            target.draw(&vbuf, &indices, &program, &uniforms, &params).unwrap();
            target.finish().unwrap();
        }

        if let Event::WindowEvent { event: WindowEvent::CloseRequested, .. } = event {
            *control_flow = ControlFlow::Exit;
        }
    });
}
```

**每段解释**:

- `make_sphere` — 生成 UV 球(经纬度球面),每顶点位置 + 法线(法线 = 位置归一化,因为球)
- `spherical_to_cartesian` — 球坐标 (θ, φ, r) 转 (x, y, z)
- `perspective_rh` — 透视投影(right-handed),`PI/4` 是 45° 视场
- `look_at_rh` — 视图矩阵,相机在 (0, 0, 3) 看向原点,up 是 +Y
- Fragment shader 最后 `final / (final + 1)` 是 **Reinhard tone mapping**,防止亮度 > 1 时颜色爆炸
- `to_cols_array_2d()` — glam 的矩阵转 `[[f32; 4]; 4]`,glium uniform 接收

**Troubleshooting**:

- 球是黑色 — 检查 `light_dir` 是不是单位向量,或 `dot(N, L)` 是不是负值(法线方向反了)
- 颜色发暗 — 没开 `GL_FRAMEBUFFER_SRGB`,颜色被二次 gamma 编码。开 sRGB 或手动 `pow(color, 1/2.2)`
- 边缘锯齿 — 没开 MSAA,在 `ContextBuilder::new().with_multisampling(4)`
- 球变形 — 透视投影的 aspect 不对(`aspect = 800.0 / 600.0`)
