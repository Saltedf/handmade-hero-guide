
# Day 424 · 继续修改光照使用空间层次

> Day 423 实现了 BVH 的基础版本,但 Casey 跑游戏发现 bug——BVH 遍历返回的命中物体不对,有些应该命中的没命中(假负),有些不该命中的命中了(假正)。今天他系统调试 BVH,发现根源是**构建时叶节点判断错误**——把"已分割的内部节点"当成叶节点返回了空 objects。

## 0 · 为什么要有这一天

BVH 看起来简单(递归二分),但**实现极易出 bug**。常见错误:

1. **叶节点 vs 内部节点混淆**:递归时该返回叶却返回空内部,或反之
2. **AABB union 错**:漏掉某个轴,或 min/max 用反
3. **轴选择偏**:每次切同一轴,树退化成链表
4. **遍历顺序错**:应该先近后远,但代码写反,效率退化
5. **递归终止条件错**:objects.len() == 0 时 panic,或 == 1 时仍递归

每个 bug 都会让 BVH **结果错误**或**性能退化**。Day 423 的实现就踩了"叶节点判断"坑。

具体场景:Casey 跑游戏,看到墙面光照"漏"——某些应该被照亮的体素是黑的。他用 day417 的 debug draw 画出 BVH 节点,看到 BVH 树结构"不平衡"——某些内部节点只有 1 个子节点,或叶节点的 objects 是空的。

调试过程:

1. **打印 BVH 树**:`println!("{:#?}", bvh.root)` 看结构
2. **打印每个叶的 objects 数**:发现某些叶 objects 是 vec![]
3. **追溯**:objects.len() = 0 时如何处理?Casey 之前的代码 `if objects.is_empty() { return Leaf{ objects: vec![] } }`,但这个 Leaf 永远不会被 ray 命中(ray 命中 Leaf bounds 但 objects 空,返回 0 命中)
4. **修复**:objects.len() = 0 时返回一个**特殊"空节点"**,或合并到兄弟节点

更深一层 bug:Casey 用 `len() <= 4` 作为叶阈值,但当 `len() == 5` 时,`mid = 5/2 = 2`,sorted[0..2] 是 2 个,sorted[2..] 是 3 个,看起来正常。但 `len() == 1` 时,`mid = 0`,sorted[..0] 是空,sorted[0..] 是 1 个——空数组进入递归,build 返回空 Leaf。这是 bug。

修复:`len() <= 1` 时直接返回 Leaf(不再分割)。

心理锚点:今天之后,你能系统地调试 BVH(树打印 + 边界测试 + 性能验证),识别常见 BVH bug 模式,理解为什么工业 BVH 库(Embree、bvh crate)有那么多边界检查——每个边界都是血泪经验。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 的调试步骤:

1. **打印 BVH 树结构**:递归打印每个节点的类型、bounds、objects 数
2. **发现异常**:某些叶节点 objects 是 0,某些内部节点 left 或 right 是 None

Casey 强调:**数据结构的 bug 通常隐蔽**。程序不 panic,但结果错。必须**主动验证不变量(invariant)**——比如"每个叶节点至少 1 个 object"。

## 2 · 心智模型

### 类比:整理书架

想象你整理书架,按"作者姓首字母"分两半(A-M 一半,N-Z 一半)。如果只有 1 本书,你不用分——直接放到一个格子里。如果 0 本书,根本没有格子。

BVH 完全同构。`len() == 1` 时直接做叶,`len() == 0` 时返回空或 panic(看你的设计)。

### 严谨原理:BVH 不变量

一个正确的 BVH 满足这些**不变量**:

1. **每个叶节点至少 1 个 object**(否则无意义)
2. **每个内部节点有 2 个非空子节点**(否则浪费空间)
3. **每个 object 恰好在一个叶节点中**(不重复)
4. **内部节点的 bounds 包含所有子节点的 bounds**(包含性)
5. **根节点的 bounds 包含所有 objects**(全局)

这些不变量是**正确性的保证**。代码里必须主动检查。Rust 的 `debug_assert!` 在 debug 模式下检查,release 不检查(零成本)。

### Rust 视角:不变量验证

```rust
impl BvhNode {
    pub fn validate(&self, all_object_ids: &std::collections::HashSet<u32>) -> bool {
        match self {
            BvhNode::Leaf { objects, bounds } => {
                if objects.is_empty() { return false; }  // 不变量 1
                for o in objects {
                    if !all_object_ids.contains(o) { return false; }  // 不变量 3
                }
                true
            }
            BvhNode::Internal { bounds, left, right } => {
                // 不变量 2:两个子节点非空(Box 不可能 None,但要验证)
                // 不变量 4:bounds 包含子节点
                if !bounds.contains_box(&left.bounds()) { return false; }
                if !bounds.contains_box(&right.bounds()) { return false; }
                left.validate(all_object_ids) && right.validate(all_object_ids)
            }
        }
    }
}

impl AABB {
    pub fn contains_box(&self, other: &AABB) -> bool {
        self.min.x <= other.min.x && self.max.x >= other.max.x
            && self.min.y <= other.min.y && self.max.y >= other.max.y
            && self.min.z <= other.min.z && self.max.z >= other.max.z
    }
}
```

`validate` 在 build 后调用,验证不变量。如果失败,立刻 panic 或日志。

### 修复后的 build

```rust
pub fn build(objects: &[(u32, AABB)]) -> BvhNode {
    debug_assert!(!objects.is_empty(), "build called with empty objects");

    if objects.len() <= 4 {
        // 叶节点
        let bounds = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
        return BvhNode::Leaf {
            bounds,
            objects: objects.iter().map(|(i, _)| *i).collect(),
        };
    }

    let overall = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
    let ext = overall.extent();
    if ext == Vec3::ZERO {
        // 所有 AABB 重合,无法分割,直接做叶
        return BvhNode::Leaf {
            bounds: overall,
            objects: objects.iter().map(|(i, _)| *i).collect(),
        };
    }
    let axis = if ext.x >= ext.y && ext.x >= ext.z { 0 }
               else if ext.y >= ext.z { 1 } else { 2 };

    let mut sorted: Vec<_> = objects.to_vec();
    sorted.sort_by(|a, b| {
        a.1.center()[axis].partial_cmp(&b.1.center()[axis]).unwrap()
    });

    let mid = sorted.len() / 2;
    debug_assert!(mid >= 1 && mid < sorted.len(), "mid out of range");

    let left = Box::new(build(&sorted[..mid]));
    let right = Box::new(build(&sorted[mid..]));
    BvhNode::Internal { bounds: overall, left, right }
}
```

修复点:

- `debug_assert!(!objects.is_empty())` 防止空输入
- `if ext == Vec3::ZERO` 防止所有 AABB 重合时无法切分
- `debug_assert!(mid >= 1 && mid < sorted.len())` 防止 mid 越界

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业 BVH 的边界处理:

- **空场景**:根节点直接 Leaf(objects 空),ray 遍历返回 0 命中
- **单物体场景**:根节点 Leaf(1 object)
- **所有物体重叠**:无法按位置分割,用其他策略(随机分、按 ID 分)
- **动态场景**:物体移动后 BVH 失效,需要重构或 refit

工业的 refit BVH:物体移动时,只更新 AABB,不重新排序。树结构不变,但 bounds 变大,效率退化。每 N 帧重构一次。

### 3.2 · 🎨 图形学视角

BVH 的退化形式:

- **链表**:每次分割一个 object,树高 = N,O(N) 而不是 O(log N)
- **不平衡**:某些子树大,某些小,平均查找成本高
- **空叶**:浪费内存,虽然 ray 遍历跳过

工业的 SAH(Surface Area Heuristic)选择分割位置,最小化期望查找成本:

```
SAH(node, split) = SA(left) / SA(node) * cost(left)
                  + SA(right) / SA(node) * cost(right)
                  + traversal_cost
```

SA(surface area)是 AABB 表面积,代表"光线命中概率"。

### 3.3 · 🐧 Linux 系统编程视角

Linux 内核的层次数据结构也有边界:

- **空目录**:`readdir` 返回空,但 inode 存在
- **单文件目录**:仍是一个目录,不为单文件特化
- **链接环**:`find` 检测,避免无限递归

内核的平衡树(rbtree)有同样的"平衡 vs 不平衡"问题——退化成链表时性能 O(N)。内核用红黑树自动平衡。

### 3.4 · 🦀 Rust 生态视角

Rust 帮助发现 BVH bug:

- **`Box<T>` 不可能 None**:Rust 没有空指针,内部节点的 left/right 永远存在
- **ownership 保证**:每个 object 在一个叶,Rust 的 ownership 模型强制
- **`debug_assert!`**:运行时检查,release 零成本

但 Rust 不能消除所有 bug——逻辑错误(如 mid 越界)Rust 也无能为力,需要程序员自己检查。

### Lv1 · 概念辨析

**题**:为什么 Casey 用 `len() <= 4` 作为叶阈值,而不是 `len() <= 1`?各有什么权衡?

**参考解答**:`len() <= 1` 阈值意味着每个叶最多 1 个物体。优点:命中精确(只测试一个物体);缺点:树高更大,内部节点多,内存占用高。

`len() <= 4` 阈值意味着每个叶最多 4 个物体。优点:树高更小,内部节点少,内存紧凑;缺点:命中时要测试 4 个物体(虽然只是 4 次 ray-AABB,廉价)。

工业通常 `len() <= 4` 或 `<= 8`,平衡树高和叶测试成本。某些 SIMD 实现(一次测 4 个 ray-AABB)选 4,让叶测试正好填满 SIMD 寄存器。

use glam::Vec3;

#[derive(Copy, Clone, Debug)]
pub struct AABB { pub min: Vec3, pub max: Vec3 }

impl AABB {
    pub const EMPTY: Self = Self {
        min: Vec3::splat(f32::INFINITY),
        max: Vec3::splat(f32::NEG_INFINITY),
    };
    pub fn union(self, other: Self) -> Self {
        Self { min: self.min.min(other.min), max: self.max.max(other.max) }
    }
    pub fn center(&self) -> Vec3 { (self.min + self.max) * 0.5 }
    pub fn extent(&self) -> Vec3 { self.max - self.min }
}

#[derive(Debug)]
pub enum BvhNode {
    Empty,
    Leaf { bounds: AABB, objects: Vec<u32> },
    Internal { bounds: AABB, left: Box<BvhNode>, right: Box<BvhNode> },
}

impl BvhNode {
    pub fn build(objects: &[(u32, AABB)]) -> Self {
        if objects.is_empty() {
            return BvhNode::Empty;
        }
        if objects.len() <= 4 {
            let bounds = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
            return BvhNode::Leaf {
                bounds,
                objects: objects.iter().map(|(i, _)| *i).collect(),
            };
        }
        let overall = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
        let ext = overall.extent();
        // 所有 AABB 重合,无法分割
        if ext.x < 1e-6 && ext.y < 1e-6 && ext.z < 1e-6 {
            return BvhNode::Leaf {
                bounds: overall,
                objects: objects.iter().map(|(i, _)| *i).collect(),
            };
        }
        let axis = if ext.x >= ext.y && ext.x >= ext.z { 0 }
                   else if ext.y >= ext.z { 1 } else { 2 };
        let mut sorted: Vec<_> = objects.to_vec();
        sorted.sort_by(|a, b| a.1.center()[axis].partial_cmp(&b.1.center()[axis]).unwrap());
        let mid = sorted.len() / 2;
        debug_assert!(mid >= 1 && mid < sorted.len(), "mid out of range");
        let left = Box::new(Self::build(&sorted[..mid]));
        let right = Box::new(Self::build(&sorted[mid..]));
        BvhNode::Internal { bounds: overall, left, right }
    }

    pub fn validate(&self) -> bool {
        match self {
            BvhNode::Empty => true,
            BvhNode::Leaf { objects, .. } => !objects.is_empty(),
            BvhNode::Internal { bounds, left, right } => {
                // 验证子节点非空
                if matches!(**left, BvhNode::Empty) { return false; }
                if matches!(**right, BvhNode::Empty) { return false; }
                // 验证 bounds 包含(简化:不严格)
                let _ = (bounds, left, right);
                left.validate() && right.validate()
            }
        }
    }

    pub fn count_objects(&self) -> usize {
        match self {
            BvhNode::Empty => 0,
            BvhNode::Leaf { objects, .. } => objects.len(),
            BvhNode::Internal { left, right, .. } => left.count_objects() + right.count_objects(),
        }
    }

    pub fn count_leaves(&self) -> usize {
        match self {
            BvhNode::Empty => 0,
            BvhNode::Leaf { .. } => 1,
            BvhNode::Internal { left, right, .. } => left.count_leaves() + right.count_leaves(),
        }
    }
}

use glam::Vec3;

#[derive(Copy, Clone, Debug)]
pub struct AABB { pub min: Vec3, pub max: Vec3 }

impl AABB {
    pub const EMPTY: Self = Self {
        min: Vec3::splat(f32::INFINITY),
        max: Vec3::splat(f32::NEG_INFINITY),
    };
    pub fn union(self, other: Self) -> Self {
        Self { min: self.min.min(other.min), max: self.max.max(other.max) }
    }
    pub fn center(&self) -> Vec3 { (self.min + self.max) * 0.5 }
    pub fn extent(&self) -> Vec3 { self.max - self.min }
    pub fn contains(&self, p: Vec3) -> bool {
        p.x >= self.min.x && p.x <= self.max.x
            && p.y >= self.min.y && p.y <= self.max.y
            && p.z >= self.min.z && p.z <= self.max.z
    }
    pub fn contains_box(&self, other: &AABB) -> bool {
        self.min.x <= other.min.x && self.max.x >= other.max.x
            && self.min.y <= other.min.y && self.max.y >= other.max.y
            && self.min.z <= other.min.z && self.max.z >= other.max.z
    }
}

pub fn ray_vs_aabb(origin: Vec3, dir: Vec3, aabb: AABB) -> bool {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    for axis in 0..3 {
        let o = origin[axis]; let d = dir[axis];
        let lo = aabb.min[axis]; let hi = aabb.max[axis];
        if d.abs() < 1e-8 {
            if o < lo || o > hi { return false; }
        } else {
            let inv_d = 1.0 / d;
            let t1 = (lo - o) * inv_d;
            let t2 = (hi - o) * inv_d;
            let (te, tx) = if t1 < t2 { (t1, t2) } else { (t2, t1) };
            t_min = t_min.max(te);
            t_max = t_max.min(tx);
            if t_min > t_max { return false; }
        }
    }
    t_max >= 0.0
}

impl BvhNode {
    pub fn build(objects: &[(u32, AABB)]) -> Self {
        if objects.is_empty() { return BvhNode::Empty; }
        if objects.len() <= 4 {
            let bounds = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
            return BvhNode::Leaf {
                bounds,
                objects: objects.iter().map(|(i, _)| *i).collect(),
            };
        }
        let overall = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
        let ext = overall.extent();
        if ext.x < 1e-6 && ext.y < 1e-6 && ext.z < 1e-6 {
            return BvhNode::Leaf {
                bounds: overall,
                objects: objects.iter().map(|(i, _)| *i).collect(),
            };
        }
        let axis = if ext.x >= ext.y && ext.x >= ext.z { 0 }
                   else if ext.y >= ext.z { 1 } else { 2 };
        let mut sorted: Vec<_> = objects.to_vec();
        sorted.sort_by(|a, b| a.1.center()[axis].partial_cmp(&b.1.center()[axis]).unwrap());
        let mid = sorted.len() / 2;
        debug_assert!(mid >= 1 && mid < sorted.len());
        let left = Box::new(Self::build(&sorted[..mid]));
        let right = Box::new(Self::build(&sorted[mid..]));
        BvhNode::Internal { bounds: overall, left, right }
    }

    pub fn validate(&self) -> bool {
        match self {
            BvhNode::Empty => true,
            BvhNode::Leaf { objects, .. } => !objects.is_empty(),
            BvhNode::Internal { bounds, left, right } => {
                if matches!(**left, BvhNode::Empty) { return false; }
                if matches!(**right, BvhNode::Empty) { return false; }
                if !bounds.contains_box(&left.bounds()) { return false; }
                if !bounds.contains_box(&right.bounds()) { return false; }
                left.validate() && right.validate()
            }
        }
    }

    pub fn bounds(&self) -> AABB {
        match self {
            BvhNode::Empty => AABB::EMPTY,
            BvhNode::Leaf { bounds, .. } => *bounds,
            BvhNode::Internal { bounds, .. } => *bounds,
        }
    }

    pub fn count_objects(&self) -> usize {
        match self {
            BvhNode::Empty => 0,
            BvhNode::Leaf { objects, .. } => objects.len(),
            BvhNode::Internal { left, right, .. } => left.count_objects() + right.count_objects(),
        }
    }

    pub fn traverse(&self, origin: Vec3, dir: Vec3, visit: &mut impl FnMut(u32)) {
        match self {
            BvhNode::Empty => {}
            BvhNode::Leaf { objects, .. } => {
                for o in objects { visit(*o); }
            }
            BvhNode::Internal { bounds, left, right } => {
                if !ray_vs_aabb(origin, dir, *bounds) { return; }
                left.traverse(origin, dir, visit);
                right.traverse(origin, dir, visit);
            }
        }
    }

    pub fn depth(&self) -> usize {
        match self {
            BvhNode::Empty => 0,
            BvhNode::Leaf { .. } => 1,
            BvhNode::Internal { left, right, .. } => {
                1 + left.depth().max(right.depth())
            }
        }
    }
}

fn main() {
    // 测试不同输入规模
    for n in [0, 1, 2, 3, 5, 10, 100, 1000] {
        let objs: Vec<(u32, AABB)> = (0..n).map(|i| {
            let x = i as f32 * 2.0;
            let c = Vec3::new(x, 0.0, 0.0);
            let h = Vec3::splat(0.5);
            (i as u32, AABB { min: c - h, max: c + h })
        }).collect();
        let bvh = BvhNode::build(&objs);
        let valid = bvh.validate();
        let count = bvh.count_objects();
        let depth = bvh.depth();
        println!("n={:4}: valid={} objects={} depth={}", n, valid, count, depth);
        debug_assert_eq!(count, n);
        debug_assert!(valid);
    }
}

### 深度推导:本日相关数学与算法

要真正掌握今天的内容,我们必须把背后的数学推导展开。这一节是"为什么这么做"的论证。

**算法复杂度的精确分析**。今天的代码涉及到对实体集合排序,基准复杂度:

- 最优比较排序下界:O(N log N)(决策树理论)
- Rust `sort_by`:TimSort,平均 O(N log N),最好 O(N)(已部分有序时)
- 拓扑排序:O(V + E),V 是节点数,E 是边数
- Radix sort:O(N × k),k 是 sort key 位数——非比较排序,可突破 O(N log N)

对一个 1000 sprite 的场景,TimSort 大约 10000 次比较,每次比较 5-10 个 cycle(分支少),总 50000-100000 cycle = 20-40 μs。在 60 FPS(16666 μs 预算)占 0.2%——可忽略。100K sprite 时升到 2 ms,开始有压力。Minecraft 这种规模的游戏必须用 radix sort 或 GPU sort。

**内存访问模式**。sort 是**非线性内存访问**的典型——每次比较都可能跳到 Vec 不同位置。CPU prefetcher 抓不到模式,cache miss 频繁。优化:

1. **Sort by index**:先 sort indices(u32 数组,4 字节/项,cache 友好),再 reorder 数据。indices 1000 个 = 4 KB,L1 cache 装得下。
2. **Batch reorder**:indices 排好后,顺序遍历 indices,顺序访问原数据(虽然是间接但 prefetcher 跟得上)。

```rust
let mut indices: Vec<u32> = (0..entities.len() as u32).collect();
indices.sort_by(|&a, &b| sort_rule(&entities[a as usize], &entities[b as usize]));
let sorted: Vec<&Entity> = indices.iter().map(|&i| &entities[i as usize]).collect();
```

100K sprite 的 sort 用这个技巧能加速 30%。

**位运算打包 sort key**。今天 sort_key 是 u64,可以塞进多个字段:

```
bits 63-56: layer (8 bits, 256 layers)
bits 55-40: bottom_y (16 bits, 65536 levels)
bits 39-24: x (16 bits)
bits 23-8: sub_layer (16 bits)
bits 7-0: spawn_id (8 bits, 256 entries per slot)
```

打包:`key = (layer << 56) | (bottom_y << 40) | (x << 24) | (sub << 8) | spawn`。一次 u64 比较,无分支,Rust `sort_by_key` 自动 inline。

**部分序的图论模型**。Day 304 会用拓扑排序处理真正的部分序。每个 sprite 是图节点,如果 A 应该在 B 前面,加边 A→B。拓扑排序给出节点的合法顺序(满足所有约束)。

拓扑排序算法:

1. **Kahn 算法**:每次找入度为 0 的节点,加入结果,删掉它的出边,重复。
2. **DFS 后序**:DFS 遍历,记录后序(post-order),反转得到拓扑序。

如果图有环(循环依赖),拓扑排序失败——意味着 sprite 排序无解,必须**人为拆解**(切开某个 sprite)。

**浮点数的稳定性**。Rust 的 `f32::partial_cmp` 处理 NaN 返回 `None`,sort 会 panic。所以游戏代码里要么保证所有 f32 都不是 NaN(数学保证),要么 `partial_cmp(...).unwrap_or(Equal)`(默认相等)。今天 sort_rule 用后者。

更稳妥的方法:**所有位置用整数**(像素单位)。`pos_y: i32` 没有 NaN 问题,比较无分支。但缩放和旋转要用浮点,所以游戏用 i32 + f32 混合。

### 真实代码片段

Casey 在 HH 视频里实际写的代码风格(简化伪代码):

```c
internal int32
SortRule(entity *A, entity *B)
{
    int32 Result = 0;

    // Layer 比较
    if (A->Layer != B->Layer) {
        Result = (int32)A->Layer - (int32)B->Layer;
    } else {
        // Bounds overlap 检查
        rectangle2 BoundsA = GetEntityBounds(A);
        rectangle2 BoundsB = GetEntityBounds(B);
        if (RectanglesOverlap(BoundsA, BoundsB)) {
            // Bottom y 比较
            real32 BottomA = BoundsA.Max.Y;
            real32 BottomB = BoundsB.Max.Y;
            if (BottomA != BottomB) {
                Result = (BottomA < BottomB) ? -1 : 1;
            } else {
                // x 比较
                Result = SignOf32(A->P.X - B->P.X);
            }
        } else {
            // 不重叠:任意顺序
            Result = A->SpawnID - B->SpawnID;
        }
    }

    return Result;
}
```

注意 Casey 的 C 风格:

- 直接返回 int32(而非 enum Ordering)
- 用 `SignOf32`(返回 -1/0/1)简化比较
- if-else 链而非 Rust 的 `then_with`

Rust 等价:

```rust
fn sort_rule(a: &Entity, b: &Entity) -> Ordering {
    a.layer.cmp(&b.layer)
        .then_with(|| {
            if bounds_overlap(a, b) {
                let ba = bounds(a).max.y;
                let bb = bounds(b).max.y;
                ba.partial_cmp(&bb).unwrap_or(Ordering::Equal)
                    .then(a.pos.x.partial_cmp(&b.pos.x).unwrap_or(Ordering::Equal))
            } else {
                a.spawn_id.cmp(&b.spawn_id)
            }
        })
}
```

### 跨学科联结:从游戏到数据库

sort_rule 的本质是"复杂比较函数",这在很多领域都出现:

- **数据库 ORDER BY**:SQL 的 `ORDER BY layer, y, x` 是同样的 multi-key sort,但 SQL 是声明式(数据库优化器选 sort 算法),Casey 是命令式(手写 sort_by)。
- **React diff**:React 用 sort + key 比较 virtual DOM,决定哪些 component 重渲染。Multi-key sort 决定 diff 顺序。
- **Linux kernel CFS**(Completely Fair Scheduler):按 vruntime 排序进程,选最小 vruntime 的运行。本质是 sort_rule。
- **Git log --sort**:Git commit 按 committer date + author date + subject 排序。

Casey 在 HH 反复说"很多算法本质相同,只是命名不同"。掌握一个领域的 sort_rule,就掌握所有领域。
