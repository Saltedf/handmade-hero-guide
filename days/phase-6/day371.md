
# Day 371 · OpenGL 顶点数组

> Casey 此前用 36 个独立顶点画立方体(`glDrawArrays`)。今天他切到 **索引绘制(`glDrawElements` + VAO + EBO)**——顶点数据共享,索引指定三角形,内存省一半。这是工业 mesh 渲染的标准做法。

## 0 · 为什么要有这一天

你的游戏开始有 1000 个立方体。每个立方体按方案 A(每三角形独立顶点)是 36 顶点 × 32 字节 = 1152 字节,1000 个就是 1.1 MB。看起来不多,但当 mesh 升级到角色模型(5000 顶点 × 共享 6 倍),方案 A 浪费 6 倍内存,几十兆字节白白浪费。

**索引绘制(indexed drawing)** 是工业解决方案:顶点数据存一份(8 个立方体角点),索引数组存三角形(36 个 index 引用)。GPU 看 index 取对应顶点,**重复引用同一顶点只算一次变换**(GPU 有 post-transform cache 缓存最近 32 个顶点)。

但 Casey 切到索引绘制**不只是为了内存**。更深层的原因:**Vertex Array Object (VAO)** 的引入。VAO 是 OpenGL 3.0+ 的概念,**封装顶点 attribute 配置**——你不再每次绘制前调一次 `glVertexAttribPointer`,而是把这些配置存到 VAO,绘制时 `glBindVertexArray(vao)` 一行搞定。

为什么 VAO 重要?**降低 CPU 开销**。现代渲染瓶颈常常在 CPU 端(状态切换、driver validation),而不是 GPU。VAO 把"怎么读顶点"的状态缓存到对象,绑定时一次性应用,大幅减少 CPU/GPU 通信。

更深层:**VAO 是 OpenGL 状态管理的一次范式转移**。OpenGL 原本是"状态机"——`glEnableClientState(GL_VERTEX_ARRAY)` 启用顶点数组,后续 draw call 用这个状态。但这种全局状态容易出错(忘记 disable 残留)。VAO 把状态打包成对象,显式绑定/解绑,API 更清晰。这也是 OpenGL 3.0+ Core Profile 的强制要求:**没有 VAO 就没法画几何**。

心理锚点:今天之后,你能用 VAO + VBO + EBO 渲染复杂 mesh,理解每个对象的角色,知道为什么工业代码用 indexed drawing,能调试 vertex attribute 配置错误。

## 1 · Casey 今天做了什么(HH 脉络)

Day 368-370 shader 管线工程化后,Casey 决定**重做顶点数据组织**。此前立方体用 `glDrawArrays(GL_TRIANGLES, 0, 36)`,顶点数据 24 顶点(每面 4 顶点)。今天他切到 indexed drawing。

具体动作:

1. **立方体改为 8 顶点 + 36 索引**——位置数据共享,每个角点只存一次
2. **创建 VAO**:`glGenVertexArrays(1, &vao)` + `glBindVertexArray(vao)`,后续 vertex attribute 配置记录在 VAO 里
3. **创建 VBO**:`glGenBuffers(1, &vbo)` + `glBindBuffer(GL_ARRAY_BUFFER, vbo)` + `glBufferData` 上传顶点数据
4. **创建 EBO**(Element Buffer Object,也叫 IBO):`glGenBuffers(1, &ebo)` + `glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, ebo)` + `glBufferData` 上传索引数据
5. **绘制**:`glDrawElements(GL_TRIANGLES, 36, GL_UNSIGNED_INT, ptr::null())`,GPU 读 EBO 取三角形

Casey 反复强调:**EBO 必须绑在 VAO 内**。`glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, ebo)` 的状态记录在当前绑定的 VAO 里。VAO 解绑再绑回来,EBO 还在。这是 VAO 设计的核心封装。

但他还指出:**方案 B(8 顶点 + 索引)对立方体并不理想**,因为每个角的法线不同(3 个面共用一个角点,每面法线不同)。Casey 现在用 24 顶点 + 36 索引(每面 4 顶点独立,索引引用这些面级顶点)。**位置数据冗余但法线清晰**,这是真实工业 mesh 的做法。

## 2 · 心智模型

### 类比:VAO 是"绘图模板",VBO 是"颜料",EBO 是"涂色顺序"

想象你画一个填色游戏。三种东西:

- **填色模板(VAO)**:模板上规定每个区域的形状(圆/方/三角)和颜色编码。换个模板,形状完全不同
- **颜料(VBO)**:实际的颜色数据(红/绿/蓝)。同一个模板可以用不同颜料
- **涂色顺序(EBO)**:规定按什么顺序填哪些区域(先填红色区域,再填蓝色区域)

填色过程(VAO 绑定 + 绘制):
1. 选模板(`glBindVertexArray(vao)`)
2. 按涂色顺序(EBO)填区域(`glDrawElements`)

模板里已经规定好"颜色编码"(vertex attribute 配置),你不需要每次都重复告诉它"红色对应区域 1"。

### Vertex Array Object 详解

VAO 是 OpenGL 3.0+ 引入的对象,**封装顶点 attribute 配置**。具体它记录:

1. **每个 attribute 的状态**:`glEnableVertexAttribArray` 是否启用,`glVertexAttribPointer` 的 stride / offset / type / normalized
2. **每个 attribute 的 VBO 绑定**:attribute i 读哪个 VBO
3. **EBO 绑定**:当前 VAO 关联的 element buffer

**不记录**:VBO 本身的数据(数据在 VBO 里),shader program。

```rust
// 典型 VAO 配置流程
unsafe {
    // 1. 生成并绑定 VAO
    let mut vao = 0;
    gl::GenVertexArrays(1, &mut vao);
    gl::BindVertexArray(vao);

    // 2. 配置 VBO(这些状态会记到当前 VAO)
    let mut vbo = 0;
    gl::GenBuffers(1, &mut vbo);
    gl::BindBuffer(gl::ARRAY_BUFFER, vbo);
    gl::BufferData(...);
    // 上传顶点数据

    // 3. 配置 attribute(这些状态也记到 VAO)
    gl::VertexAttribPointer(0, 3, gl::FLOAT, gl::FALSE, stride, ptr::null());
    gl::EnableVertexAttribArray(0);
    // location 0 = position

    // 4. 绑定 EBO(状态记到 VAO)
    let mut ebo = 0;
    gl::GenBuffers(1, &mut ebo);
    gl::BindBuffer(gl::ELEMENT_ARRAY_BUFFER, ebo);
    gl::BufferData(...);

    // 5. 解绑 VAO(可选,但好习惯)
    gl::BindVertexArray(0);
}

// 绘制时:
unsafe {
    gl::BindVertexArray(vao);  // 一次性应用所有 attribute + EBO 配置
    gl::DrawElements(gl::TRIANGLES, 36, gl::UNSIGNED_INT, ptr::null());
    gl::BindVertexArray(0);
}
```

### 为什么 VAO 提速?

没有 VAO 时,每次绘制前:
- `glBindBuffer(GL_ARRAY_BUFFER, vbo)`
- `glVertexAttribPointer(0, ...)` × N 个 attribute
- `glEnableVertexAttribArray(0)` × N
- `glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, ebo)`
- `glDrawElements`

每次 draw call 大量状态切换,CPU 把状态送 GPU driver,driver 验证。这是 **draw call bottleneck**。

有 VAO 时:
- `glBindVertexArray(vao)` 一次性应用所有状态
- `glDrawElements`

CPU 只送 2 个命令。**这是 VAO 的核心价值**。

工业 benchmark:用 VAO 后 draw call CPU 开销降低 30-50%。这对万级 draw call 场景(复杂场景)至关重要。

### Indexed Drawing 详解

`glDrawElements` 用索引数组定义三角形:

```rust
let indices: &[u32] = &[
    0, 1, 2,  // 三角形 1:顶点 0, 1, 2
    0, 2, 3,  // 三角形 2:顶点 0, 2, 3
    4, 5, 6,  // 三角形 3
    4, 6, 7,  // 三角形 4
    // ... 共 36 个索引
];

unsafe {
    gl::DrawElements(
        gl::TRIANGLES,         // mode
        indices.len() as GLsizei,  // count
        gl::UNSIGNED_INT,      // index type(u32)
        ptr::null(),           // offset 到 EBO(0 = 从头开始)
    );
}
```

GPU 流程:
1. 读取 indices[i] = 5
2. 用 5 作为顶点 index,从 VBO 读第 5 个顶点
3. 应用 vertex shader
4. (transform cache:如果 5 最近处理过,直接用结果,不重跑 shader)
5. 每 3 个索引组成一个三角形

**Post-Transform Cache(变换后缓存)**

GPU 缓存最近 N 个顶点(NVIDIA 通常 16-32)的 vertex shader 结果。如果同一顶点在多个三角形里出现,第二次直接读 cache。

立方体 8 角点,每个角被 3 个面共享。如果不共享顶点(24 顶点方案),cache 用处不大。如果共享(8 顶点 + 索引),cache 让 vertex shader 跑次数从 36 × 3 = 108 次降到 8 次。**索引绘制 + 良好顶点顺序 = vertex shader 跑得更少**。

**顶点顺序优化**

工业工具(MeshOptimizer, TomF's vertex cache optimization)重排三角形顺序,让相邻三角形共享顶点,最大化 cache 命中。Casey 在 Phase 7+ 处理 mesh 加载时会涉及。

### Indexed Drawing 对立方体的特殊处理

理论上方案 B(8 顶点 + 索引)内存最小,但**立方体每个角的法线属于 3 个不同面**(3 个面共用角点,每面法线不同)。所以:

- 8 顶点(纯位置)+ 索引 = **每个顶点只能有一组法线,但需要 3 组**
- 解决:**顶点拆成 24 个**(每面 4 顶点),每面有自己的法线。位置数据冗余但法线正确

Casey 用 **24 顶点 + 36 索引**(方案 C,中间方案)。位置数据冗余 3 倍,但法线清晰,且仍然利用 GPU 的 transform cache(虽然 cache 帮助有限,因为顶点本来就独立)。

```
方案 A:36 顶点(每三角形独立)+ glDrawArrays
方案 B:8 顶点 + 36 索引(角点共享,但法线冲突)
方案 C:24 顶点 + 36 索引(面级顶点,法线正确,工业标准)
```

Casey 选 C。

### Rust 视角

```rust
pub struct IndexedMesh {
    vao: GLuint,
    vbo: GLuint,
    ebo: GLuint,
    index_count: GLsizei,
}

impl IndexedMesh {
    pub fn new<T: bytemuck::Pod>(
        vertices: &[T],
        indices: &[u32],
        attributes: &[(GLuint, GLint, GLsizei, usize)],  // (location, size, type, offset)
    ) -> Self {
        let mut vao = 0;
        let mut vbo = 0;
        let mut ebo = 0;

        unsafe {
            gl::GenVertexArrays(1, &mut vao);
            gl::BindVertexArray(vao);

            gl::GenBuffers(1, &mut vbo);
            gl::BindBuffer(gl::ARRAY_BUFFER, vbo);
            gl::BufferData(
                gl::ARRAY_BUFFER,
                (vertices.len() * std::mem::size_of::<T>()) as isize,
                vertices.as_ptr() as *const _,
                gl::STATIC_DRAW,
            );

            gl::GenBuffers(1, &mut ebo);
            gl::BindBuffer(gl::ELEMENT_ARRAY_BUFFER, ebo);
            gl::BufferData(
                gl::ELEMENT_ARRAY_BUFFER,
                (indices.len() * std::mem::size_of::<u32>()) as isize,
                indices.as_ptr() as *const _,
                gl::STATIC_DRAW,
            );

            let stride = std::mem::size_of::<T>() as GLsizei;
            for &(location, size, _ty, offset) in attributes {
                gl::VertexAttribPointer(
                    location, size, gl::FLOAT, gl::FALSE,
                    stride, offset as *const _,
                );
                gl::EnableVertexAttribArray(location);
            }

            gl::BindVertexArray(0);
        }

        Self { vao, vbo, ebo, index_count: indices.len() as GLsizei }
    }

    pub fn draw(&self) {
        unsafe {
            gl::BindVertexArray(self.vao);
            gl::DrawElements(
                gl::TRIANGLES, self.index_count,
                gl::UNSIGNED_INT, std::ptr::null(),
            );
            gl::BindVertexArray(0);
        }
    }
}

impl Drop for IndexedMesh {
    fn drop(&mut self) {
        unsafe {
            gl::DeleteVertexArrays(1, [self.vao].as_ptr());
            gl::DeleteBuffers(1, [self.vbo].as_ptr());
            gl::DeleteBuffers(1, [self.ebo].as_ptr());
        }
    }
}
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业的 mesh 数据:

- **静态 mesh**(地形、墙):VBO 标记 `GL_STATIC_DRAW`,GPU 把数据放在 VRAM 高速区
- **动态 mesh**(每帧重传的 mesh):`GL_DYNAMIC_DRAW`,GPU 在 PCIe 友好区
- **stream mesh**(粒子系统):`GL_STREAM_DRAW`,每帧 upload

**Multi-draw indirect**(MDI):一次 CPU 提交万级 draw call,GPU 自己分发。复杂场景(culling 后)常用。

**Bindless rendering**:不用 VAO / VBO 绑定,直接用 GPU address。NVIDIA 扩展,绕开 OpenGL 状态机,性能极致。

Casey 用静态 VAO / VBO / EBO,这是教学最优。Phase 7+ 处理动态 mesh 时会用 DYNAMIC_DRAW。

### 3.2 · 🎨 图形学视角

VAO 的图形学意义:

**Attribute 配置灵活性**

每个 attribute 独立配置 size / type / normalized / stride / offset:
```c
glVertexAttribPointer(
    location,
    3,                  // size: 1, 2, 3, 4
    GL_FLOAT,           // type: GL_FLOAT, GL_BYTE, GL_INT, GL_HALF_FLOAT, GL_DOUBLE
    GL_FALSE,           // normalized: 是否把整数归一化到 [-1, 1] 或 [0, 1]
    stride,
    offset
);
```

`normalized` 用于把整数顶点数据归一化(节省内存)。例如 packed normal 用 `GL_INT_2_10_10_10_REV`,4 字节存 3 个 10-bit 法线分量 + 2-bit 备用。`normalized = GL_TRUE` 让 GPU 自动归一化到 [-1, 1]。

**Instancing with vertex divisor**

```c
glVertexAttribDivisor(location, divisor);
```

`divisor = 0` 是默认(每顶点前进),`divisor = 1` 表示每实例(instance)前进。这用于 instanced rendering:每实例一组 attribute(如 instance matrix)。Casey 后面体素渲染可能用。

**Multiple VBOs per VAO**

VAO 不限制只用一个 VBO。可以一个 VBO 存 position,另一个 VBO 存 normal:
```rust
gl::BindBuffer(gl::ARRAY_BUFFER, pos_vbo);
gl::VertexAttribPointer(0, 3, gl::FLOAT, gl::FALSE, 12, ptr::null());
gl::BindBuffer(gl::ARRAY_BUFFER, normal_vbo);
gl::VertexAttribPointer(1, 3, gl::FLOAT, gl::FALSE, 12, ptr::null());
```

这是 **SoA(struct of arrays)** 布局,SIMD 友好。Casey 暂时用 AoS(array of structs)单 VBO,简单。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上 VAO / VBO 是 GPU 驱动管理。Mesa 把 VBO 数据上传到 GPU VRAM。

**VBO 上传路径**:

```
application CPU 内存 → glBufferData → DMA → GPU VRAM
```

`glBufferData` 是同步 API,但实际 DMA 是异步的。OpenGL 缓冲 DMA,后续命令排队。`glMapBuffer` 让 CPU 直接访问 GPU VRAM(pinned page),零拷贝。

```bash
# 查看 GPU 内存使用
sudo pacman -S radeontop  # AMD
radeontop
# vram 列显示已用 VRAM

# Intel:
sudo pacman -S intel-gpu-tools
intel_gpu_top

# NVIDIA(闭源):
nvidia-smi
```

**Mesa 的 buffer 放置策略**

Mesa 根据 `usage` 参数(GL_STATIC_DRAW / GL_DYNAMIC_DRAW)决定 VRAM 还是 GTT(GART,系统内存映射给 GPU):
- `STATIC_DRAW`:VRAM(高带宽,适合只读)
- `DYNAMIC_DRAW`:GTT(双向访问,适合每帧改)
- `STREAM_DRAW`:GTT(同 DYNAMIC,但暗示一次性用)

### 3.4 · 🦀 Rust 生态视角

Rust 表达 mesh 的 crate:

**`bytemuck`**:zero-copy buffer 上传

```rust
#[repr(C)]
#[derive(Copy, Clone, bytemuck::Pod, bytemuck::Zeroable)]
struct Vertex { pos: [f32; 3], normal: [f32; 3], uv: [f32; 2] }

let vertices: &[Vertex] = &[];
unsafe {
    gl::BufferData(gl::ARRAY_BUFFER,
        (vertices.len() * std::mem::size_of::<Vertex>()) as isize,

```

`bytemuck::Pod` 派生保证 Vertex 是 plain-old-data(可字节复制,无 Rust 特殊语义)。

**`glam`**:SIMD 数学库

```rust
use glam::Vec3;
#[repr(C)]
struct Vertex { pos: Vec3, ... }
// Vec3 内部是 [f32; 3],内存布局兼容
```

**`wgpu::BufferAddress`** + **vertex_buffer_layout**

wgpu 提供更类型安全的 API:

```rust
let vertex_buffer_layout = wgpu::VertexBufferLayout {
    array_stride: std::mem::size_of::<Vertex>() as wgpu::BufferAddress,
    step_mode: wgpu::VertexStepMode::Vertex,
    attributes: &[
        wgpu::VertexAttribute { offset: 0, shader_location: 0, format: wgpu::VertexFormat::Float32x3 },
        wgpu::VertexAttribute { offset: 12, shader_location: 1, format: wgpu::VertexFormat::Float32x3 },

```

wgpu 强制在 pipeline 创建时声明 attribute layout,OpenGL 在运行时配置(动态)。

## 5 · 对照与变奏

### 同一问题在不同 API 的表达

**问题**:配置顶点 attribute + 索引绘制。

| API | 配置 attribute | 绘制 |
|---|---|---|
| OpenGL 1.x (immediate) | `glVertexPointer` | `glDrawElements`(已存在) |
| OpenGL 2.x | `glVertexAttribPointer` + ARB VBO | `glDrawElements` |
| OpenGL 3.0+ | VAO + VBO + EBO | `glDrawElements` |
| OpenGL 4.3+ | 同上 + `glBindVertexBuffer` / `glVertexAttribFormat` / `glVertexAttribBinding` | 同上 |
| Vulkan | `VkPipelineVertexInputStateCreateInfo` | `vkCmdDrawIndexed` |
| DirectX 11 | `D3D11_INPUT_ELEMENT_DESC` + `IASetIndexBuffer` | `DrawIndexed` |
| DirectX 12 | `D3D12_INPUT_LAYOUT_DESC` + index buffer view | `DrawIndexedInstanced` |
| Metal | `MTLVertexDescriptor` | `drawIndexedPrimitives` |
| WebGPU | `VertexBufferLayout` + `IndexBuffer` | `draw_indexed` |

OpenGL 4.3 引入 `glBindVertexBuffer` 分离 attribute 的"格式"和"绑定",更接近 Vulkan / D3D12。这是 OpenGL 现代化的尝试,但普及度低,Casey 用 3.0 风格的 `glVertexAttribPointer`。

### 历史演化

- **1992 (OpenGL 1.0)**: 即时模式 `glBegin/glEnd`,每顶点单独传
- **1995 (OpenGL 1.1)**: vertex array 引入,可批量传顶点
- **2003 (OpenGL 1.5)**: VBO 引入,顶点数据常驻 GPU
- **2008 (OpenGL 3.0)**: VAO 强制(Core Profile)
- **2014 (OpenGL 4.3)**: `glBindVertexBuffer` 分离绑定 / 格式
- **2015 (Vulkan / DX12)**: 显式 pipeline state object

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:VAO 和 VBO 各自记录什么?为什么 VAO 解绑后,EBO 状态还在?

**参考解答**:
- **VBO**:存顶点数据(f32 数组),不记录 attribute 配置
- **VAO**:记录"怎么读 VBO"(attribute 配置)+ "用哪个 EBO"。VAO 不存数据,数据在 VBO / EBO 里
- **EBO 绑定记录在 VAO**:这是 OpenGL 设计。`glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, ebo)` 的状态属于当前 VAO,不是全局。VAO 解绑,EBO 也"解绑";VAO 重新绑定,EBO 状态恢复

这设计的好处:一个 VAO 对应一种 mesh 配置,绑定时一次性应用所有状态。坏处:容易混淆(忘记绑定 VAO 时调 `glBindBuffer(GL_ELEMENT_ARRAY_BUFFER)` 没效果)。

### Lv2 · 动手实践

```rust
#[derive(Copy, Clone, bytemuck::Pod, bytemuck::Zeroable)]
struct Vertex {

    0, 1, 2,  0, 2, 3,
    // 底面 (逆时针从 -y 看)

    16, 17, 18,  16, 18, 19,
    // 左面
    20, 22, 21,  20, 23, 22,

pub struct CubeMesh {
    vao: GLuint,
    vbo: GLuint,
    ebo: GLuint,
    index_count: GLsizei,
}

impl CubeMesh {
    pub fn new() -> Self {
        let mut vao = 0;
        let mut vbo = 0;
        let mut ebo = 0;

        unsafe {
            // VAO:记录 attribute 配置 + EBO 绑定
            gl::GenVertexArrays(1, &mut vao);
            gl::BindVertexArray(vao);

            // VBO:存顶点数据
            gl::GenBuffers(1, &mut vbo);
            gl::BindBuffer(gl::ARRAY_BUFFER, vbo);
            gl::BufferData(
                gl::ARRAY_BUFFER,
                (VERTICES.len() * std::mem::size_of::<Vertex>()) as isize,
                VERTICES.as_ptr() as *const _,
                gl::STATIC_DRAW,
            );

            // EBO:存索引数据,绑定到 GL_ELEMENT_ARRAY_BUFFER(状态记到 VAO)
            gl::GenBuffers(1, &mut ebo);
            gl::BindBuffer(gl::ELEMENT_ARRAY_BUFFER, ebo);
            gl::BufferData(
                gl::ELEMENT_ARRAY_BUFFER,
                (INDICES.len() * std::mem::size_of::<u32>()) as isize,
                INDICES.as_ptr() as *const _,
                gl::STATIC_DRAW,
            );

            // 配置 attribute(状态记到 VAO)
            let stride = std::mem::size_of::<Vertex>() as GLsizei;
            // location 0: position
            gl::VertexAttribPointer(0, 3, gl::FLOAT, gl::FALSE, stride, ptr::null());
            gl::EnableVertexAttribArray(0);
            // location 1: normal
            gl::VertexAttribPointer(
                1, 3, gl::FLOAT, gl::FALSE, stride,
                (std::mem::size_of::<[f32; 3]>()) as *const _,
            );
            gl::EnableVertexAttribArray(1);
            // location 2: uv
            gl::VertexAttribPointer(
                2, 2, gl::FLOAT, gl::FALSE, stride,
                (std::mem::size_of::<[f32; 3]>() * 2) as *const _,
            );
            gl::EnableVertexAttribArray(2);

            // 解绑 VAO(可选)
            gl::BindVertexArray(0);
        }

        Self {
            vao, vbo, ebo,
            index_count: INDICES.len() as GLsizei,
        }
    }

    pub fn draw(&self) {
        unsafe {
            gl::BindVertexArray(self.vao);
            gl::DrawElements(
                gl::TRIANGLES,
                self.index_count,
                gl::UNSIGNED_INT,
                ptr::null(),
            );
            gl::BindVertexArray(0);
        }
    }
}

impl Drop for CubeMesh {
    fn drop(&mut self) {
        unsafe {
            gl::DeleteVertexArrays(1, [self.vao].as_ptr());
            gl::DeleteBuffers(1, [self.vbo].as_ptr());
            gl::DeleteBuffers(1, [self.ebo].as_ptr());
        }
    }
}
```

**关键解释**:
- `gl::GenVertexArrays(1, &mut vao)` — 生成 1 个 VAO 名字。`1` 是 count,`&mut vao` 是输出参数
- `gl::BindVertexArray(vao)` — 绑定 VAO 到当前 context。后续 attribute 配置 + EBO 绑定记录在这个 VAO 里
- `gl::BindBuffer(gl::ELEMENT_ARRAY_BUFFER, ebo)` — EBO 必须在 VAO 绑定时绑定,绑定状态记录到 VAO
- 解绑 VAO(`gl::BindVertexArray(0)`)不会重置已记录的状态,重新绑定即可恢复
- offset 用字节,3 个 f32 = 12 字节

```rust
// Cargo.toml: gl = "0.14", glfw = "0.55", bytemuck = "1.14", glam = "0.29"

use gl::types::*;
use std::ptr;
use std::mem;

pub struct Mesh {
    vao: GLuint,
    _vbo: GLuint,        // 不需要单独存 vbo / ebo 句柄,DeleteVertexArrays 不删它们
    _ebo: GLuint,
    index_count: GLsizei,
}

impl Mesh {
    pub fn new_indexed<V: bytemuck::Pod>(
        vertices: &[V],
        indices: &[u32],
        attribs: &[(GLuint, GLint)],
    ) -> Self {
        let mut vao = 0;
        let mut vbo = 0;
        let mut ebo = 0;

        unsafe {
            // 创建 VAO + 绑定(后续状态进 VAO)
            gl::GenVertexArrays(1, &mut vao);
            gl::BindVertexArray(vao);

            // VBO
            gl::GenBuffers(1, &mut vbo);
            gl::BindBuffer(gl::ARRAY_BUFFER, vbo);
            gl::BufferData(
                gl::ARRAY_BUFFER,
                (vertices.len() * mem::size_of::<V>()) as isize,
                vertices.as_ptr() as *const _,
                gl::STATIC_DRAW,
            );

            // EBO(必须 VAO 绑定时!)
            gl::GenBuffers(1, &mut ebo);
            gl::BindBuffer(gl::ELEMENT_ARRAY_BUFFER, ebo);
            gl::BufferData(
                gl::ELEMENT_ARRAY_BUFFER,
                (indices.len() * mem::size_of::<u32>()) as isize,
                indices.as_ptr() as *const _,
                gl::STATIC_DRAW,
            );

            // 配置 attribute
            let stride = mem::size_of::<V>() as GLsizei;
            let mut offset_bytes = 0usize;
            for &(location, size) in attribs {
                gl::VertexAttribPointer(
                    location,
                    size,
                    gl::FLOAT,
                    gl::FALSE,
                    stride,
                    offset_bytes as *const _,
                );
                gl::EnableVertexAttribArray(location);
                offset_bytes += (size as usize) * mem::size_of::<f32>();
            }

            gl::BindVertexArray(0);
            gl::BindBuffer(gl::ARRAY_BUFFER, 0);
            // EBO 在 VAO 解绑后自动保持绑定状态(在 VAO 里)
        }

        Self {
            vao,
            _vbo: vbo,
            _ebo: ebo,
            index_count: indices.len() as GLsizei,
        }
    }

    pub fn draw(&self) {
        unsafe {
            gl::BindVertexArray(self.vao);
            gl::DrawElements(
                gl::TRIANGLES, self.index_count,
                gl::UNSIGNED_INT, ptr::null(),
            );
        }
    }
}

impl Drop for Mesh {
    fn drop(&mut self) {
        unsafe {
            gl::DeleteVertexArrays(1, [self.vao].as_ptr());
            gl::DeleteBuffers(1, [self._vbo].as_ptr());
            gl::DeleteBuffers(1, [self._ebo].as_ptr());
        }
    }
}
```

**Troubleshooting**:

- **画面空白** — VAO 没绑定,或 attribute 配置错。先 `glDisable(GL_CULL_FACE)` 排查 winding
- **`glDrawElements` 报 INVALID_OPERATION** — EBO 没绑定(可能 VAO 没绑就调 BindBuffer ELEMENT_ARRAY)
- **顶点看到的位置错乱** — stride 算错,或 attribute offset 错。用 RenderDoc 看 vertex input 是否正确解析
- **`VertexAttribPointer` 参数 size=3 但 stride=24** — 正常,size 是 attribute 内分量数,stride 是整个顶点字节数。stride 0 表示 attribute 紧密排列(不适用混合 attribute)
