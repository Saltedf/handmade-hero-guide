# Day 318 · 优化渲染目标混合与清除

> 昨天 Casey 引入了预乘 alpha 合成,但合成 pass 每帧要遍历几百万像素,性能吃紧。今天 Casey 做几个具体优化:跳过透明像素、合并 clear 和 composite、用 SIMD 一次处理多像素。

## 0 · 为什么要有这一天

昨天的合成代码大约是这样:

```rust
for src_pixel in &src.pixels {
    for dst_pixel in &mut dst.pixels {
        *dst_pixel = src_pixel.over(*dst_pixel);
    }
}
```

1080p 屏幕(207 万像素)× 3 个 target = 600 万次 over 调用,每次 over 是 ~8 条算术指令。总计 ~5000 万指令,单线程下要 ~30 ms——已经接近一帧 16 ms 预算的两倍。

业界的优化路径:

1. **跳过透明像素**:`src.alpha == 0` 时直接跳过(不修改 dst)。半透明 layer 通常大量像素完全透明,这步能省 60-80% 工作。
2. **整 target 不透明跳过**:如果整个 target 完全不透明(比如背景),合成时直接 memcpy 而不是逐像素 over。
3. **合并 clear 和 composite**:第一遍合成时不用先 clear,直接用 src 当作 dst 初始值。
4. **SIMD**:一条指令处理 8-16 像素,提速 4-8 倍。
5. **多线程**:把屏幕分块,每块一个线程合成。

今天的 Casey 工作:**实现前三个优化**——跳过透明、整 target 不透明 memcpy、合并 clear/composite。SIMD 和多线程留给后面 Day 431+。

心理锚点:今天之后你的合成 pass 从 30 ms 降到 5 ms 左右,60 FPS 流畅。这是工程上的"渐进优化"——先做简单优化拿大头收益,再考虑 SIMD/多线程。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_render.cpp`,做了三个具体优化。

**优化 1:跳过透明像素**

```c
void CompositePixel(uint32 *dst, uint32 src) {
    uint32 src_a = src >> 24;
    if (src_a == 0) return;          // 透明像素跳过
    if (src_a == 255) {              // 不透明像素直接覆盖
        *dst = src;
        return;
    }
    // 半透明才走完整 over 计算
    *dst = PremulOver(src, *dst);
}
```

`src_a == 0` 跳过最关键——半透明 UI layer 通常 80% 像素透明,这一跳省下大部分工作。`src_a == 255` 是 fast path,直接覆盖,不用 over。

**优化 2:整 target 不透明 memcpy**

```c
void CompositeTarget(uint32 *dst, render_target *src) {
    if (target_is_opaque(src)) {
        // 整 target 不透明,直接 memcpy
        memcpy(dst, src->memory, src->size);
    } else {
        // 逐像素 over
        for (...) CompositePixel(dst++, *src++);
    }
}
```

判断 `target_is_opaque`:遍历所有像素检查 alpha == 255,如果都是就不透明。这个检查本身有开销,但通常在 push bitmap 时记录——只要 push 的所有 bitmap 都不透明,target 就不透明。

**优化 3:合并 clear 和 first composite**

```c
void RenderGroupToOutput(...) {
    // 旧:先 clear backbuffer,再合成 target 0
    // 新:target 0 是 BG,通常不透明,直接 memcpy 而不用 clear
    if (targets[0].is_opaque) {
        memcpy(output.memory, targets[0].memory, ...);
    } else {
        clear_output(output);
        composite(output, &targets[0]);
    }
    for (int i = 1; i < target_count; i++) {
        composite(output, &targets[i]);
    }
}
```

这省了一次 clear 操作(207 万像素的 memset),省 1-2 ms。

Casey 在视频里强调:**优化前要测量(measure),不能盲目优化**。他用 `__rdtsc()` (Windows) / `clock_gettime` (Linux) 测量每个优化的效果:

- 跳过透明:30 ms → 8 ms(-73%)
- 整 target 不透明:8 ms → 6 ms(-25%)
- 合并 clear:6 ms → 5 ms(-17%)

总优化:30 ms → 5 ms,6 倍提速。

## 2 · 心智模型

### 类比:整理书架

把合成想成整理书架。原版本:每本书都重新摆放一次,即使位置没变也搬。优化版本:

- **跳过透明像素** = 跳过空位,空位不用动
- **整 target 不透明** = 一整排书都没变,直接拍照记录,不用一本一本搬
- **合并 clear** = 第一排书直接放到架子上,不用先擦架子再放

每个优化都是"识别无操作情况,提前 short-circuit"。这种"提前判断边界条件"是性能优化的最常见手段。

### 严谨原理:统计与分支预测

**跳过透明的收益**取决于 alpha 分布:

- UI layer:典型 90% 像素透明 → 跳过收益 90%
- Game layer:典型 50% 像素透明 → 收益 50%
- BG layer:0% 透明(完全不透明) → 不能跳过,但可以走"整 target 不透明"路径

现代 CPU 的**分支预测(branch prediction)**对这种"大量透明像素"场景非常友好——分支预测器学到"大部分时候 alpha=0 跳过",预测准确率 90%+,流水线不阻塞。所以 if 检查的开销几乎为 0,但跳过的工作是大头。

**整 target 不透明 memcpy** 的收益:`memcpy` 是 SIMD 加速的(glibc 用 AVX2 一次 32 字节),速度是逐像素 over 的 10 倍以上。207 万像素的 memcpy 只要 0.5 ms 左右。

**合并 clear** 的收益:`memset` 和 `memcpy` 速度差不多,省一次 0.5 ms。但更重要的是"少一次内存读写",cache 压力小。

### SIMD 预告

```rust
// 标量版(今天):
for (dst, src) in dst.iter_mut().zip(src.iter()) {
    if src.a == 0 { continue; }
    *dst = src.over(*dst);
}

// SIMD 版(Day 431 之后):
use std::simd::u8x32;
for chunk in dst.chunks_mut(32).zip(src.chunks(32)) {
    // 一次处理 32 像素
    let v_dst = u8x32::from_slice(chunk.0);
    let v_src = u8x32::from_slice(chunk.1);
    // 批量 alpha blend
    let result = simd_over(v_src, v_dst);
    result.copy_to_slice(chunk.0);
}
```

SIMD 版理论 8-32 倍提速,但实际受内存带宽限制(1080p × 4 byte × 60 fps = 500 MB/s,远低于内存带宽),实际 4-8 倍。

### Rust 表达

```rust
fn composite_premul_fast(dst: &mut [PremulPixel], src: &[PremulPixel]) {
    for (d, s) in dst.iter_mut().zip(src.iter()) {
        if s.a == 0 {
            // 完全透明,跳过
            continue;
        }
        if s.a == 255 {
            // 完全不透明,直接覆盖
            *d = *s;
            continue;
        }
        // 半透明,完整 over
        *d = s.over(*d);
    }
}

fn composite_or_memcpy(dst: &mut [PremulPixel], src: &[PremulPixel]) {
    // 检查 src 是否完全不透明
    if src.iter().all(|p| p.a == 255) {
        // memcpy fast path
        dst.copy_from_slice(src);
    } else {
        composite_premul_fast(dst, src);
    }
}
```

`slice::copy_from_slice` 内部用 `memcpy`,glibc 用 SIMD 实现,比逐元素赋值快 10 倍。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏行业的渲染优化经验:

1. **快速路径(fast path)** vs **慢速路径(slow path)**:大多数情况走 fast path(不透明 / 完全透明),慢速路径(半透明)只占少数。
2. **批处理(batching)**:把同类型 target 集中处理,减少分支切换。
3. **脏矩形(dirty rectangle)**:只重画变化的屏幕区域,不重画整个屏幕。Win32 GDI 经典技术。

游戏行业最重要的渲染优化是 **GPU draw call batching**——把多个同 shader 的 entity 合并到一个 draw call,减少 CPU→GPU 通信。Casey 的 CPU 渲染器没有 draw call 概念,但"批处理 + 跳过"的思路一致。

### 3.2 · 🎨 图形学视角

图形学的渲染优化技术:

- **Z-culling**:Z-buffer 提前剔除被遮挡像素,GPU 用 early-z 硬件实现。
- **Backface culling**:剔除背面朝向相机三角形,减少 50% 三角形。
- **Occlusion culling**:用低精度版本预渲染,确定哪些 entity 完全被遮挡,跳过它们。
- **Texture compression**:BC1-BC7 / ETC / ASTC 压缩纹理,节省带宽。
- **LOD(Level of Detail)**:远处用低模,近处用高模。

今天 Casey 的"跳过透明像素"对应图形学的 **alpha test**(`discard` 关键字)——shader 里 alpha < 阈值就丢弃像素,不写 depth/color。GPU 的 early-z 优化要求"无 discard",所以 alpha test 和 early-z 互斥,要选一个。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上的 memcpy 优化:

- **glibc `memcpy`**:用 AVX2 / AVX-512 SIMD,一次拷贝 32-64 字节。
- **`__builtin_memcpy`**:GCC/Clang 内置,编译器选择最佳实现。
- **non-temporal store**:`_mm_stream_si128` 写入绕过 cache,大块拷贝避免 cache 污染。

`perf stat -e cache-misses` 看你的 memcpy 命中率。如果 cache miss 高,考虑 non-temporal。

Rust 的 `slice::copy_from_slice` 在 release 模式下编译成 glibc memcpy(通过 intrinsic),性能等同 C 的 memcpy。

### 3.4 · 🦀 Rust 生态视角

Rust 的迭代器优化:

```rust
// 看似朴素,实际 Rust 编译器会自动 SIMD 化(autovectorize)
for (d, s) in dst.iter_mut().zip(src.iter()) {
    *d = s.over(*d);
}
```

`rustc` 在 release 模式下(+ opt-level=3)调用 LLVM,LLVM 的 autovectorize pass 会自动识别这种循环模式,生成 SIMD 指令。但**自动 SIMD 化依赖条件简单**——一旦加 if 分支(`if s.a == 0 continue`),自动 SIMD 失败。所以"快速路径 + 慢速路径分离"对 Rust 特别重要:

```rust
// 自动 SIMD 友好(无分支):
for (d, s) in dst.iter_mut().zip(src.iter()) {
    *d = s.over(*d);
}

// 自动 SIMD 失败(有分支):
for (d, s) in dst.iter_mut().zip(src.iter()) {
    if s.a == 0 { continue; }  // 分支打断 SIMD
    *d = s.over(*d);
}
```

工业级实现会做"两遍"——先 SIMD 处理无透明,再标量处理透明像素。今天 Casey 简化为标量版,Day 431 之后引入显式 SIMD。

## 5 · 对照与变奏

### 历史演化

- **1980s 软件渲染**:每像素都算,没有优化概念。
- **1990s 图形加速卡**:硬件 z-buffer、early-z、texture cache 等。
- **2000s GPU shader**:shader 让"跳过"变成 `discard` 关键字,但 early-z 受影响。
- **2010s 移动 GPU**:TBDR(Tile-Based Deferred Rendering),按 16×16 块渲染,cache 命中率高。
- **2020s Variable Rate Shading**:不同区域不同着色率,GPU 硬件支持。

### 工业级 vs 教学版

| 特性 | 教学版(今天) | 工业版(Unity URP) |
|---|---|---|
| 透明跳过 | 是 | GPU 自动(early-z) |
| memcpy fast path | 是 | 同 |
| SIMD | 无 | GPU shader |
| 多线程 | 无 | 多线程 render graph |
| 渲染图(render graph) | 无 | 自动排序 + 优化 pass |

工业级用 **render graph** 抽象——声明"我要 BG → Game → UI 合成",引擎自动决定每个 pass 的优化策略(memcpy / over / GPU shader),用户不用手写。Casey 手写每步,适合学习。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么"跳过透明像素"比"对所有像素都做 over"快?给出至少 2 个理由。

**参考解答**:

1. **减少计算量**:透明像素 over 等于无操作(`dst = src + dst * 1 = dst`),跳过直接省下 4 次乘加 + alpha 计算 = ~10 指令。
2. **分支预测友好**:连续透明像素的 if 分支预测准确率 95%+,流水线不阻塞,几乎零开销。
3. **cache 局部性**:透明区域往往集中(如 UI 边缘外),跳过这些区域不污染 cache,提高 cache 命中率。

代价:if 分支打断 SIMD 自动向量化,需要手动分离 fast/slow path。但收益远大于代价。

### Lv2 · 动手实践

**题**:在 Rust 里实现"跳过透明 + 不透明 memcpy"的优化合成。要求:

- `composite_fast(dst, src)`:透明跳过,不透明覆盖,半透明 over
- `composite_or_memcpy(dst, src)`:整 src 不透明时 memcpy
- benchmark:对一个 90% 透明的 target,对比朴素 vs 优化的速度差

**参考解答**:

```rust
use std::time::Instant;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct Pixel { r: u8, g: u8, b: u8, a: u8 }

impl Pixel {
    fn over(self, dst: Self) -> Self {
        let inv_a = 255 - self.a as u32;
        Self {
            r: (self.r as u32 + (dst.r as u32 * inv_a + 128) / 255).min(255) as u8,
            g: (self.g as u32 + (dst.g as u32 * inv_a + 128) / 255).min(255) as u8,
            b: (self.b as u32 + (dst.b as u32 * inv_a + 128) / 255).min(255) as u8,
            a: (self.a as u32 + (dst.a as u32 * inv_a + 128) / 255).min(255) as u8,
        }
    }
}

/// 朴素:所有像素都 over
fn composite_naive(dst: &mut [Pixel], src: &[Pixel]) {
    for (d, s) in dst.iter_mut().zip(src.iter()) {
        *d = s.over(*d);
    }
}

/// 优化:透明跳过,不透明覆盖
fn composite_fast(dst: &mut [Pixel], src: &[Pixel]) {
    for (d, s) in dst.iter_mut().zip(src.iter()) {
        if s.a == 0 { continue; }
        if s.a == 255 { *d = *s; continue; }
        *d = s.over(*d);
    }
}

/// 整 src 不透明 memcpy
fn composite_or_memcpy(dst: &mut [Pixel], src: &[Pixel]) {
    if src.iter().all(|p| p.a == 255) {
        dst.copy_from_slice(src);
    } else {
        composite_fast(dst, src);
    }
}

fn main() {
    let n = 1_000_000;
    let mut dst = vec![Pixel { r: 100, g: 100, b: 100, a: 255 }; n];
    // 90% 透明,10% 不透明
    let mut src = vec![Pixel { r: 0, g: 0, b: 0, a: 0 }; n];
    for i in 0..n/10 {
        src[i * 10] = Pixel { r: 255, g: 0, b: 0, a: 255 };
    }
    
    let start = Instant::now();
    composite_naive(&mut dst.clone(), &src);
    let t_naive = start.elapsed();
    
    let start = Instant::now();
    composite_fast(&mut dst.clone(), &src);
    let t_fast = start.elapsed();
    
    println!("Naive: {:?}", t_naive);
    println!("Fast:  {:?}", t_fast);
    println!("Speedup: {:.2}x", t_naive.as_secs_f64() / t_fast.as_secs_f64());
}
```

预期:Fast 比 Naive 快 3-5 倍(90% 像素跳过)。

## 8 · Rust / Arch 落地代码

### Rust:优化合成(完整可跑)

```rust
// Cargo.toml: 无依赖
// src/main.rs

use std::time::Instant;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct Pixel { r: u8, g: u8, b: u8, a: u8 }

impl Pixel {
    const TRANSPARENT: Self = Self { r: 0, g: 0, b: 0, a: 0 };
    const fn opaque(r: u8, g: u8, b: u8) -> Self {
        Self { r, g, b, a: 255 }
    }
    
    /// 预乘 alpha Over operator
    fn over(self, dst: Self) -> Self {
        let inv_a = 255 - self.a as u32;
        Self {
            r: (self.r as u32 + (dst.r as u32 * inv_a + 128) / 255).min(255) as u8,
            g: (self.g as u32 + (dst.g as u32 * inv_a + 128) / 255).min(255) as u8,
            b: (self.b as u32 + (dst.b as u32 * inv_a + 128) / 255).min(255) as u8,
            a: (self.a as u32 + (dst.a as u32 * inv_a + 128) / 255).min(255) as u8,
        }
    }
}

/// 朴素版:所有像素 over
fn composite_naive(dst: &mut [Pixel], src: &[Pixel]) {
    for (d, s) in dst.iter_mut().zip(src.iter()) {
        *d = s.over(*d);
    }
}

/// 优化版:透明跳过,不透明覆盖
fn composite_fast(dst: &mut [Pixel], src: &[Pixel]) {
    for (d, s) in dst.iter_mut().zip(src.iter()) {
        match s.a {
            0   => continue,            // 透明,跳过
            255 => { *d = *s; }         // 不透明,直接覆盖
            _   => { *d = s.over(*d); } // 半透明,完整 over
        }
    }
}

/// 终极版:整 src 不透明时 memcpy
fn composite_or_memcpy(dst: &mut [Pixel], src: &[Pixel]) {
    // 检查 src 是否完全不透明
    if src.iter().all(|p| p.a == 255) {
        dst.copy_from_slice(src);
    } else {
        composite_fast(dst, src);
    }
}

fn benchmark<F: Fn(&mut [Pixel], &[Pixel])>(name: &str, f: F, 
                                             dst: &mut [Pixel], src: &[Pixel]) {
    let start = Instant::now();
    f(dst, src);
    let elapsed = start.elapsed();
    println!("{:20}: {:?}", name, elapsed);
}

fn main() {
    let n: usize = 1920 * 1080;  // 1080p
    
    // 模拟 BG target(完全不透明)
    let mut bg = vec![Pixel::opaque(0, 0, 255); n];
    let dst_bg = vec![Pixel::opaque(0, 0, 0); n];
    
    // 模拟 Game target(50% 不透明,50% 半透明)
    let mut game = vec![Pixel::opaque(255, 0, 0); n];
    for i in 0..n/2 {
        game[i] = Pixel { r: 200, g: 0, b: 0, a: 128 };
    }
    let mut dst_game = bg.clone();
    
    // 模拟 UI target(90% 透明,10% 不透明)
    let mut ui = vec![Pixel::TRANSPARENT; n];
    for i in 0..n/10 {
        ui[i * 10] = Pixel::opaque(255, 255, 255);
    }
    let mut dst_ui = bg.clone();
    
    println!("=== 1080p composite benchmark ===");
    println!();
    
    println!("--- BG (100% opaque) ---");
    let mut d1 = dst_bg.clone();
    let mut d2 = dst_bg.clone();
    let mut d3 = dst_bg.clone();
    benchmark("naive",  composite_naive, &mut d1, &bg);
    benchmark("fast",   composite_fast, &mut d2, &bg);
    benchmark("memcpy", composite_or_memcpy, &mut d3, &bg);
    
    println!("\n--- Game (50% opaque, 50% semi) ---");
    let mut d1 = dst_game.clone();
    let mut d2 = dst_game.clone();
    let mut d3 = dst_game.clone();
    benchmark("naive",  composite_naive, &mut d1, &game);
    benchmark("fast",   composite_fast, &mut d2, &game);
    benchmark("memcpy", composite_or_memcpy, &mut d3, &game);
    
    println!("\n--- UI (90% transparent) ---");
    let mut d1 = dst_ui.clone();
    let mut d2 = dst_ui.clone();
    let mut d3 = dst_ui.clone();
    benchmark("naive",  composite_naive, &mut d1, &ui);
    benchmark("fast",   composite_fast, &mut d2, &ui);
    benchmark("memcpy", composite_or_memcpy, &mut d3, &ui);
}
```

**预期输出**(release 模式,数字因机器而异):

```
=== 1080p composite benchmark ===

--- BG (100% opaque) ---
naive              : 18.2 ms
fast               :  5.1 ms
memcpy             :  0.5 ms

--- Game (50% opaque, 50% semi) ---
naive              : 19.0 ms
fast               : 12.0 ms
memcpy             : 12.0 ms

--- UI (90% transparent) ---
naive              : 17.5 ms
fast               :  1.8 ms
memcpy             :  1.9 ms
```

解读:
- BG 100% 不透明:memcpy 比 naive 快 36 倍(memcpy 是 SIMD,naive 是逐像素)
- Game 50% 不透明:fast 比 naive 快 1.6 倍(只优化了不透明分支,半透明仍要 over)
- UI 90% 透明:fast 比 naive 快 10 倍(90% 像素跳过,但 all() 检查全 alpha 也耗时,所以 memcpy 没快多少)

### Arch 工具链验证

```bash
# memcpy 路径的 cache miss 率应该最低(连续访问)

ms_print massif.out.* | head
# 应该看到几个 8MB 的 Vec 分配(target 像素数据)
```

**Troubleshooting**:

- **优化后比朴素还慢** — 检查是不是 debug 模式(opt-level=0),release 模式才有 SIMD
- **memcpy 没快** — 检查 `src.iter().all(...)` 是否真的全部不透明,如果有半透明 pixel 会 fall through 到 fast 路径
- **结果颜色错** — 检查 fast path 的 `if s.a == 255` 直接覆盖,要保证 src 是预乘(255 alpha 对应预乘 = 原值)

## 11 · 延伸讨论
