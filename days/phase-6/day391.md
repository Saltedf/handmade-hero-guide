
# Day 391 · 规划更好的光照

> Phong 搞定后,Casey 站下来思考:**接下来怎么走?** 现有的简单光照有很多问题——半透明物体没光照、镜面反射过简单、没有间接光(物体之间的反射)。今天他不写代码,**做规划**——在 OBS 画板上画出接下来的光照架构。这是 HH 里少有的"纯设计"集,展示架构师思维。

## 0 · 为什么要有这一天

你已经有了 Lambert + Phong 简单光照,但**真实世界**远比这复杂:

1. **半透明物体没光照**:玻璃、水、粒子用 alpha-blending,光照公式假设不透明
2. **没有间接光**:真实世界里,红色墙壁会把光"反射"到旁边白色墙壁上,白墙微微泛红。这叫**间接光 / 全局光照**(Global Illumination, GI)。简单光照没有这个。
3. **光源没有方向分布**:Phong 假设"光源是一个无穷远点",但真实光源有面积(日光灯管)、有形状(窗户)
4. **阴影硬**(无 soft shadow):没有阴影或阴影是硬边,真实阴影有半影(soft shadow)
5. **环境光遮蔽缺失**:角落和缝隙应该更暗(因为接收的光被周围物体挡住),简单 ambient 是均匀的

每个问题都需要专门算法。Casey 今天**规划**:接下来的几十集要做什么、按什么顺序、用什么算法。

**架构师思维的核心**:

- **优先级**:哪个问题对玩家最显眼?先解决。
- **依赖关系**:某些算法依赖其他(soft shadow 依赖 shadow map)
- **性能预算**:每帧 16ms(60 FPS),光照占多少?
- **数据结构**:支持新光照需要什么数据(G-buffer、light buffer、voxel grid)
- **可调试性**:复杂光照难调,需要 debug 视图

**Casey 的规划**(接下来 20 集的方向):

1. **光照纹理**(Day 392):把光照结果存到纹理,而不是直接渲染到屏幕。这是 deferred shading 的基础。
2. **从深度剥离取光照数据**(Day 393):深度剥离存了几何信息(法线、位置),可以**复用**做光照。
3. **多网格光照传播**(Day 394-395):**核心算法**——把光照从粗到细传播,得到间接光。
4. **应用光照到深度剥离**(Day 396-398):光照纹理 -> 深度剥离的每层颜色。
5. **CPU 光照测试床**(Day 399):CPU 实现做单元测试,验证 GPU 实现。
6. **环境光遮蔽**(Day 400):角落和缝隙的暗化。
7. **光线投射**(Day 402+):用 raycasting 算可见性,实现软阴影。
8. **体素索引**(Day 404):把光照存到 3D 体素网格。
9. **平滑混合**(Day 409):消除光照计算的离散伪影。
10. **跟踪入射光**(Day 410):精确算光的能量分布。

这是一个**系统化的光照管线**,不是"加一个特效"。Casey 展示的是**真正的工程架构思维**。

心理锚点:看完今天,你能(1)说出简单光照的 5 个主要缺陷;(2)理解为什么需要 deferred shading / GI / voxel-based lighting;(3)画出接下来光照管线的架构图;(4)理解"规划"在大型项目中的价值。

### 严谨原理:为什么需要更好的光照

**简单 Phong 光照的 5 个缺陷**:

**缺陷 1:无间接光**

真实物理:**光的反射**。一束光打到红色墙壁,反射的光带着红色,打到旁边白墙,白墙**接收**了这个带红色的反射光,微微泛红。

Phong 简化:**只算直接光**——从光源 → 物体 → 眼睛。**不算物体之间的反射**。

后果:渲染的画面"扁平"——角落和缝隙看起来和开阔地一样亮,因为没考虑"光被挡住"。

**修法**:Global Illumination(GI)算法——光线追踪、辐射度(radiosity)、体素传播等。

**缺陷 2:无软阴影**

真实物理:**面光源**。日光灯管有面积,从一头看物体,物体的阴影**逐渐过渡**(全影 → 半影 → 无影)。

Phong 简化:**点光源 / 方向光源**。阴影要么没有(Phong 不算阴影),要么是硬边(用 shadow map)。

后果:物体浮在场景上,不像"在地面上"。

**修法**:Soft shadow(PCF filtering、PCSS、ray tracing)。

**缺陷 3:无环境光遮蔽**

真实物理:**角落和缝隙接收的环境光少**(因为被周围物体挡住天空散射光)。

Phong 简化:**均匀 ambient**。所有像素的 ambient 都一样。

后果:角落和开阔地一样亮,失去"凹凸感"。

**修法**:Screen-space ambient occlusion(SSAO)、ray-traced AO、voxel-based AO。

**缺陷 4:半透明物体没光照**

真实物理:**半透明物体的颜色取决于透射光**——玻璃后面的物体反射的光,经过玻璃吸收一部分,到达眼睛。

Phong 简化:**只算半透明物体的 alpha-blending**。光照只算表面 albedo,不算透射。

后果:玻璃看起来像贴纸,不是真玻璃。

**修法**:把光照应用到深度剥离的每层,按 alpha 合成。

**缺陷 5:无 HDR / Tone mapping**

真实物理:**光的强度跨越多个数量级**(太阳 100000 lux,室内灯 100 lux,月光 0.1 lux)。

Phong 简化:**LDR**(Low Dynamic Range,0-1 范围)。光照超过 1 直接 clamp。

后果:强光看起来和普通光一样(都是白色),失去"刺眼感"。

**修法**:HDR rendering(浮点 framebuffer)+ tone mapping(把 HDR 转 LDR 显示)。

### Casey 选择的解决方案

针对这 5 个缺陷,Casey 选择:

1. **GI**:Voxel-based multigrid lighting propagation(体素 + 多网格传播)
2. **Soft shadow**:Raycasting against voxel grid
3. **AO**:Voxel-based ambient occlusion
4. **半透明光照**:把光照纹理应用到深度剥离的每层
5. **HDR / Tone mapping**:已经用 Reinhard tone map(Day 389+)

**为什么选 voxel-based**?

- **GPU 友好**:3D 纹理是 GPU 原生支持
- **多网格传播**:用 coarse-to-fine 思路,逐级传播光照(类似 multigrid PDE solver)
- **支持间接光**:体素之间相互传播光照,模拟反射
- **支持 raycasting**:体素网格可以做快速的 ray-AABB 测试

代价:

- **离散化误差**:体素网格有分辨率限制,细节丢失
- **显存大**:128³ 体素 = 200 万 cells,每 cell 存 RGB 光照 = 24 MB
- **算法复杂**:实现 multigrid 不简单

**这就是 HH 全剧最复杂算法**(Day 394 multigrid 标 difficulty=5,4h)。

### 延迟渲染(Deferred Shading)

Phong 是**前向渲染**(forward rendering)——每物体在 fragment shader 里算光照。问题:**每物体 × 每光源** = 大量重复计算。

**延迟渲染**:

1. Geometry pass:把几何信息(position, normal, albedo, etc.)写到 G-buffer(Multiple Render Targets)
2. Lighting pass:读 G-buffer,每像素算一次光照(不再 per-object)

优点:光照成本和物体数无关,只和光源数 + 屏幕分辨率有关。

缺点:G-buffer 显存大(每像素几十字节),不支持 MSAA(需要 per-sample,贵)。

Casey 不完全用 deferred shading(深度剥离本身已经是某种几何 pass),而是用"**从深度剥离取数据**"——类似 deferred 的思路。

### 多网格光照传播(Multigrid Lighting Propagation)

经典 multigrid(多网格)是 PDE 求解器,用来加速线性方程组的迭代。Casey 把这个思路用到**光照传播**:

- **粗网格**:128³ 体素,每帧迭代 1 次,传播**长距离**间接光(快但不精确)
- **中网格**:64³ 体素,每帧迭代 4 次,传播**中距离**
- **细网格**:32³ 体素,每帧迭代 16 次,传播**短距离**(精细)

**思路**:光在场景里多次反射,每次反射"传播"一段距离。粗网格处理"几米外"的反射(1 次迭代),细网格处理"几十厘米"的反射(多次迭代)。两者结合得到全场景间接光。

这是数学上 **multigrid** 的应用——一种求解线性系统的 O(N) 算法(普通迭代是 O(N²))。Day 394 详细推导。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业界 GI 方案:

- **Light probes**(光照探针):场景中预放置若干探针,每探针记录该位置的间接光。运行时物体附近的探针插值。Unreal 用这个。
- **Voxel GI / VXGI**:NVIDIA 提出(2014),voxel 化场景 + 多次 cone tracing。CryEngine 用过。
- **DDGI**(Dynamic Diffuse Global Illumination):基于 irradiance volume 的动态 GI。EA / DICE 用。
- **RTX GI**(Ray Tracing GI):硬件光追,Vulkan / DX12 Ultimate 支持。最新 AAA 用。
- **Screen-space GI**(SSGI):基于 G-buffer,从屏幕信息推断间接光。便宜但不准确。

Casey 的 voxel multigrid 是 VXGI 的变体,不用 cone tracing 而用多网格传播(更简单)。

**性能预算**:1080p 60FPS = 16ms/帧。光照典型占 30%(5ms)。简单 Phong 0.5ms,完整 GI 4-5ms。多光源 deferred shading 2-3ms。

### 3.2 · 🎨 图形学视角

**Radiosity**(辐射度):1980s 的 GI 算法,把场景划分为 patch,每 patch 算到其他 patch 的"形状因子"(form factor),解线性方程组。代价 O(N²) for N patches。预计算 GI 用过(Quake 3 lightmap)。

**Photon mapping**:1995,Jensen。从光源射出光子,记录光子在场景中的"碰撞点",间接光从碰撞点采样。离线渲染主流。

**Path tracing**:Kajiya 1986,从相机射光线,每碰撞表面随机反射,直到命中光源。**物理精确**但慢。电影用(2000s 开始,2010s 实时化)。

**Voxel-based methods**:把场景体素化,体素之间传播光。Crassin 等 2011 提出 Voxel Cone Tracing,工业界演化出 VXGI / SVOGI。

Casey 的方法属于 voxel-based 一族,但用 multigrid 加速传播(原创思路)。

### 3.4 · 🦀 Rust 生态视角

Rust 端光照管线的设计模式:

```rust
pub trait LightingPass {
    fn process(&mut self, frame_data: &FrameData, output: &mut LightingOutput);
}

pub struct FrameData {
    pub layers: Vec<DepthPeelLayer>,
    pub voxel_grid: VoxelGrid,
    pub lights: Vec<DirectionalLight>,
}

pub struct DepthPeelLayer {
    pub color: Texture2D,
    pub depth: DepthTexture2D,
    pub position: Texture2D,    // G-buffer 扩展
    pub normal: Texture2D,
    pub albedo: Texture2D,
}

pub struct VoxelGrid {
    pub data: Vec<Voxel>,
    pub dimensions: (u32, u32, u32),
    pub voxel_size: f32,
}

pub struct Voxel {
    pub albedo: [f32; 3],
    pub emission: [f32; 3],
    pub normal: [f32; 3],
    pub incident_light: [f32; 3],  // 累积的间接光
}

pub struct LightingPipeline {
    passes: Vec<Box<dyn LightingPass>>,
}

impl LightingPipeline {
    pub fn run(&mut self, frame_data: &mut FrameData) -> LightingOutput {
        let mut output = LightingOutput::default();
        for pass in &mut self.passes {
            pass.process(frame_data, &mut output);
        }
        output
    }
}
```

**设计要点**:

- `trait LightingPass`:抽象每个 pass,可以独立测试和替换
- `Vec<Box<dyn LightingPass>>`:运行时组合 pass,灵活
- `FrameData`:每帧的全局数据(pass 之间共享)
- 每个 pass 有输入输出,可以序列化为 debug 数据

这是**面向数据设计**(DOD)和**面向对象**(OOP)的折衷——pass 用 OOP,但 frame 数据用 DOD(连续内存)。

## 4 · 认知地图

## 5 · 对照与变奏

### 同一问题在不同语境下的变体

**问题**:模拟"传播过程"(光、热、声音、流体)。

| 语境 | 算法 |
|---|---|
| 光照传播 | Radiosity / voxel multigrid |
| 热传导 | Finite element / finite difference |
| 声学 | FDTD / edge diffraction |
| 流体 | Smoothed particle hydrodynamics(SPH) |
| 神经网络 | Graph neural networks |

**核心模式**:**多网格 / 多尺度**——粗网格快速传播"长程",细网格精确算"短程"。

### 历史演化

- **1980s**:Radiosity(预计算 GI)
- **1990s**:Light mapping / precomputed lighting(Quake 3 等用)
- **2000s**:Real-time GI 探索(SSAO、SSAO+、SSIL)
- **2010s**:Voxel GI(VXGI、Crassin)、Light probes(Unreal)
- **2020s**:RTX 实时光追,DDGI,Neural radiance cache

Casey 的 multigrid voxel 思路接近 VXGI 但更简化,适合教学。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:简单 Phong 光照的 5 个主要缺陷是什么?各自如何修?

**参考解答**:

1. **无间接光**:物体之间的反射没算。修法:GI(radiosity、voxel multigrid、path tracing)。
2. **无软阴影**:点光源导致硬阴影。修法:面光源 + PCF / PCSS / ray tracing。
3. **无 AO**:ambient 均匀,角落不暗。修法:SSAO、ray-traced AO、voxel AO。
4. **半透明物体无光照**:alpha-blending 不算光照。修法:把光照应用到深度剥离每层。
5. **无 HDR**:颜色 clamp 到 0-1,强光不刺眼。修法:HDR framebuffer + tone mapping。

每个缺陷对应一类算法。Casey 接下来 20 集逐个解决。

**提示**:

- 细网格:终端节点到骨干(逐跳)
- 类比:光在体素之间传播,粗网格传播远距离,细网格传播近距离

### 光照管线骨架(可编译但功能简化)

```toml
[package]

version = "0.1.0"
edition = "2021"
[dependencies]

```

```rust
// src/main.rs
// 光照管线的设计骨架,展示 trait + pipeline 组合

use glam::Vec3;

/// 一帧的数据
pub struct FrameData {
    pub layers: Vec<DepthPeelLayer>,
    pub voxel_grid: VoxelGrid,
    pub lights: Vec<DirectionalLight>,
    pub camera_pos: Vec3,
}

pub struct DepthPeelLayer {
    pub color: Vec<(u32, u32, [f32; 4])>,  // 简化:CPU 端模拟纹理
    pub depth: Vec<(u32, u32, f32)>,
    pub position: Vec<(u32, u32, [f32; 3])>,
    pub normal: Vec<(u32, u32, [f32; 3])>,
    pub albedo: Vec<(u32, u32, [f32; 3])>,
}

pub struct VoxelGrid {
    pub data: Vec<Voxel>,
    pub dimensions: (u32, u32, u32),
    pub voxel_size: f32,
}

#[derive(Copy, Clone, Default)]
pub struct Voxel {
    pub albedo: [f32; 3],
    pub emission: [f32; 3],
    pub normal: [f32; 3],
    pub incident_light: [f32; 3],
}

pub struct DirectionalLight {
    pub direction: Vec3,
    pub color: Vec3,
}

/// Pass 抽象
pub trait LightingPass {
    fn name(&self) -> &str;
    fn process(&mut self, frame_data: &mut FrameData);
}

/// 创建光照纹理 pass
pub struct CreateLightingTexturesPass;
impl LightingPass for CreateLightingTexturesPass {
    fn name(&self) -> &str { "create_lighting_textures" }
    fn process(&mut self, frame_data: &mut FrameData) {
        // 从深度剥离抽 position / normal / albedo
        // 简化:占位
        println!("[{}] processing {} layers", self.name(), frame_data.layers.len());
    }
}

/// 多网格光照传播 pass
pub struct MultigridPropagationPass {
    pub iterations: usize,
}

impl LightingPass for MultigridPropagationPass {
    fn name(&self) -> &str { "multigrid_propagation" }
    fn process(&mut self, frame_data: &mut FrameData) {
        let dims = frame_data.voxel_grid.dimensions;
        let total = (dims.0 * dims.1 * dims.2) as usize;
        println!("[{}] {} iterations on {} voxels", self.name(), self.iterations, total);
        // 简化:实际算法在 Day 394 实现
        for iter in 0..self.iterations {
            // 模拟一次传播
            for v in &mut frame_data.voxel_grid.data {
                v.incident_light[0] += 0.001;
                v.incident_light[1] += 0.001;
                v.incident_light[2] += 0.001;
            }
        }
    }
}

/// 环境光遮蔽 pass
pub struct AmbientOcclusionPass;
impl LightingPass for AmbientOcclusionPass {
    fn name(&self) -> &str { "ambient_occlusion" }
    fn process(&mut self, _frame_data: &mut FrameData) {
        println!("[{}] processing", self.name());
    }
}

/// 光照管线
pub struct LightingPipeline {
    passes: Vec<Box<dyn LightingPass>>,
}

impl LightingPipeline {
    pub fn new() -> Self {
        Self {
            passes: vec![
                Box::new(CreateLightingTexturesPass),
                Box::new(MultigridPropagationPass { iterations: 4 }),
                Box::new(AmbientOcclusionPass),
            ],
        }
    }

    pub fn run(&mut self, frame_data: &mut FrameData) {
        for pass in &mut self.passes {
            pass.process(frame_data);
        }
    }
}

fn main() {
    let mut pipeline = LightingPipeline::new();
    let mut frame = FrameData {
        layers: vec![DepthPeelLayer {
            color: vec![], depth: vec![], position: vec![],
            normal: vec![], albedo: vec![],
        }],
        voxel_grid: VoxelGrid {
            data: vec![Voxel::default(); 32 * 32 * 32],
            dimensions: (32, 32, 32),
            voxel_size: 0.1,
        },
        lights: vec![DirectionalLight {
            direction: Vec3::new(1.0, 1.0, 1.0).normalize(),
            color: Vec3::ONE,
        }],
        camera_pos: Vec3::new(0.0, 0.0, 3.0),
    };

    println!("Running lighting pipeline...");
    pipeline.run(&mut frame);
    println!("Pipeline complete.");
}
```

**Troubleshooting**:

- `Voxel::default()` 编译错 — Voxel 没派生 Default。加 `#[derive(Default)]`。
- Lifetime 错误 — `&mut FrameData` 借用要小心,每 pass 独立借用,不能同时。
- 性能慢 — Vec 分配频繁,改用 arena 或预分配(后续 day 优化)。
