
# Day 284 · 重组头与身体代码

> 你的角色现在是"头 + 身体"两部分(头能独立旋转,身体 spring 弹动)。这两部分的代码在 player.rs 里混在一起,200+ 行的 update / render 函数。今天 Casey 把它们拆成独立模块,让代码组织反映概念结构。

## 0 · 为什么要有这一天

打开你的 Player struct,大概长这样:

```rust
struct Player {
    // 身体
    body_pos: Vec2,
    body_scale_x: Spring,
    body_scale_y: Spring,
    body_color: u32,
    // 头
    head_offset: Vec2,
    head_rotation: Spring,
    head_size: f32,
    head_color: u32,
    // 共用
    pos: Vec2,    // 玩家整体位置(身体的)
    facing: Direction,
    // ...
}

impl Player {
    fn update(&mut self, dt: f32) {
        // 100 行混合身体 + 头 + 共用逻辑
    }

    fn render(&self, buf: &mut [u32]) {
        // 80 行混合身体绘制 + 头绘制
    }
}
```

问题:

1. **关注点混杂**:身体的 spring 更新和头的 spring 更新交错,改一个可能影响另一个
2. **加新部分难**:想加"手臂"或"披风",要在 Player struct 加字段、update 加逻辑、render 加绘制——三处改动
3. **测试困难**:身体的逻辑不能单独测,必须 mock 整个 Player
4. **数据局部性差**:身体字段和头字段交错,spring 更新时 cache 不友好

重构目标:把"头"和"身体"拆成独立 struct,Player 持有它们:

```rust
struct Player {
    body: Body,
    head: Head,
    pos: Vec2,  // 整体位置(共用)
    // ...
}

struct Body {
    scale_x: Spring,
    scale_y: Spring,
    color: u32,
}

struct Head {
    offset: Vec2,
    rotation: Spring,
    size: f32,
    color: u32,
}

impl Body {
    fn update(&mut self, dt: f32) { ... }
    fn render(&self, buf: &mut [u32], pos: Vec2) { ... }
}

impl Head {
    fn update(&mut self, dt: f32) { ... }
    fn render(&self, buf: &mut [u32], body_pos: Vec2) { ... }
}
```

这样:

- 加新部分(手臂)只需加 `arms: Arms` 字段 + 实现 Arms struct
- 身体的逻辑可以单独测
- 数据局部性好(同一部分的数据连续存储)

心理锚点:做完这个,你的角色可以支持任意多个"身体部分",每个独立演化。

## 1 · Casey 今天做了什么

Casey 重构 Player:

1. 提取 `Body` struct(body 字段 + body 方法)
2. 提取 `Head` struct(head 字段 + head 方法)
3. Player 改成持有 body + head
4. Player::update 委托给 body.update + head.update

## 2 · 心智模型

### 类比:乐高积木

乐高小人由头 + 身体 + 腿 + 手组成,每部分是独立积木。你想换个颜色的身体?换那一块就行,不影响其他。

重构后的 Player 就像乐高——每个部分独立,可替换、可单独优化、可独立测试。

### 严谨原理:组合 vs 继承

#### 继承(经典 OOP)

C++ / Java 的做法:

```cpp
class BodyPart { virtual void update(float dt) = 0; ... };
class Body : public BodyPart { ... };
class Head : public BodyPart { ... };

class Player {
    std::vector<BodyPart*> parts;
};
```

问题:虚函数开销、深度继承层次难维护、Rust 不支持继承。

#### 组合(Rust 风格)

```rust
struct Player {
    body: Body,
    head: Head,
}

impl Player {
    fn update(&mut self, dt: f32) {
        self.body.update(dt);
        self.head.update(dt);
    }
}
```

字段是具体类型(不是 trait object),编译期已知所有调用,无虚函数。

Rust 社区共识:**"Prefer composition over inheritance"**——组合优于继承。

#### 部分作为 trait

如果想"任意部分",可以加 trait:

```rust
trait BodyPart {
    fn update(&mut self, dt: f32);
    fn render(&self, buf: &mut [u32], pos: Vec2);
}

struct Body { ... }
impl BodyPart for Body { ... }

struct Head { ... }
impl BodyPart for Head { ... }

struct Player {
    parts: Vec<Box<dyn BodyPart>>,
}
```

但这又回到 trait object 的开销。Casey 用具体类型(body, head),不抽象。

### 部分之间的依赖

头依赖身体(头的位置 = 身体位置 + 偏移)。表达方式:

#### 方式 1:render 时传 body_pos

```rust
impl Head {
    fn render(&self, buf: &mut [u32], body_pos: Vec2) {
        let head_pos = body_pos + self.offset;
        // 画
    }
}

// Player::render
fn render(&self, buf: &mut [u32]) {
    self.body.render(buf, self.pos);
    self.head.render(buf, self.pos);  // 传 body pos
}
```

简单,无内部依赖。

#### 方式 2:Head 持有 Body 引用

```rust
struct Head<'a> {
    body: &'a Body,
    // ...
}
```

生命周期复杂,不推荐。

#### 方式 3:World 持有 body 和 head,通过 ID 关联

```rust
struct World {
    parts: HashMap<PartId, Part>,
    relations: Vec<(PartId, PartId)>,  // (parent, child)
}
```

类似 ECS,过度工程化。

Casey 用方式 1,清晰简单。

### 部分的更新顺序

如果部分之间有依赖(头依赖身体),更新顺序很重要:

1. **先身体**:身体更新 pos(根据 spring)
2. **后头**:头根据身体新 pos 算自己 pos

```rust
fn update(&mut self, dt: f32) {
    self.body.update(dt);       // 先身体
    let body_pos = self.body.current_pos();
    self.head.update(dt, body_pos);  // 头用身体 pos
}
```

如果不按顺序,头用的是上一帧的 body_pos,有一帧延迟(虽然 60FPS 下看不出来)。

### 数据布局:SoA vs AoS

每个 Player 持有 body + head(AoS,array of structs):

```
Player 1: [Body1 Head1]
Player 2: [Body2 Head2]
```

如果有很多 Player,迭代时 body 数据和 head 数据交错。

更高效的是 SoA(struct of arrays):

```
bodies: [Body1 Body2 ...]
heads: [Head1 Head2 ...]
```

但 HH 只有 1 个 Player,AoS 够用。ECS 库(bevy)走 SoA 路线。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏角色经常被拆成多个部分:

- **Skeletal animation**:骨骼(头骨 / 脊柱 / 四肢),每个关节独立旋转
- **Equipment system**:角色穿装备(头盔、胸甲、护腿),每个装备是独立对象
- **Vehicle parts**:载具有引擎、轮胎、武器,每个可独立损坏

业界做法:

- **Unreal**:USkeletalMeshComponent + USceneComponent hierarchy
- **Unity**:SkinnedMeshRenderer + Bone hierarchy
- **Bevy**:Parent / Children 关系 + Transform

Casey 的 HH 简化:两个部分(头 + 身体),用组合表达。

### 3.2 · 🎨 图形学视角

角色渲染时的"部分"在 GPU 时代是 **mesh + material** 的组合:

- mesh:几何形状
- material:材质(颜色、贴图、shader)

一个角色可能有:身体 mesh + 头 mesh + 头发 mesh + 武器 mesh。每个 mesh 用自己的 material,合在一起画。

CPU 渲染(今天的 HH)简化:每个部分就是一个 sprite,自己处理像素。

#### 渲染顺序

部分之间有"前后"关系(头在身体前面)。渲染顺序:

1. 后面的部分先画(身体)
2. 前面的部分后画(头),覆盖身体的头部位置

```rust
fn render(&self, buf: &mut [u32]) {
    self.body.render(buf);  // 先
    self.head.render(buf);  // 后,覆盖身体头部
}
```

### 3.4 · 🦀 Rust 生态视角

Rust 表达"部分组合"几个风格:

#### 直接字段

```rust
struct Player {
    body: Body,
    head: Head,
}
```

简单,Casey 用这个。

#### Vec<Part>

```rust
struct Player {
    parts: Vec<Part>,
}

enum Part {
    Body(Body),
    Head(Head),
    Cape(Cape),
}
```

支持任意数量的部分,但 enum match 麻烦。

#### Trait object

```rust
struct Player {
    parts: Vec<Box<dyn Part>>,
}
```

完全动态,但虚函数开销。

#### ECS entity hierarchy

```rust
// Bevy 风格
commands.spawn((
    PlayerMarker,
    Transform::default(),
    Children::spawn((
        Spawn(Body::default()),
        Spawn(Head::default()),
    )),
));
```

每个部分是独立 entity,通过 parent / child 关系连接。最灵活但最复杂。

Casey 的 HH 选最简单的直接字段,Rust 端我们也走这条路。

### 3.5 · 软件工程:单一职责

每个 struct 应该有单一职责:

- `Body`:管身体的 scale / color / 物理
- `Head`:管头的 rotation / size / 动画

如果 Body 的代码里出现 `head_rotation`,就是越界——应该移到 Head 里。

这个原则(Single Responsibility Principle)让代码可维护性大幅提升。Casey 的重构正是为了达到这个目标。

### 4.1 上级

### OOP 继承 vs Rust 组合

| 维度 | 继承 | 组合 |
|---|---|---|
| 灵活性 | 编译期固定 | 运行时可变 |

| Rust 支持 | 不支持 | 原生支持 |

Rust 的设计哲学:**没有继承,只有组合**。这让代码更扁平、更可测试。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Casey 用"直接字段(body: Body, head: Head)"而不是"Vec<Box<dyn Part>>"?给出至少 3 个理由。

**参考解答**:
1. **性能**:直接字段是编译期已知类型,所有方法调用静态分派,无虚函数;Vec<Box<dyn>> 每次调用查 vtable,有间接寻址开销
2. **内存布局**:直接字段的 body 和 head 在 Player 结构内连续(同一分配);Vec<Box>> 每个元素是堆分配,数据分散,cache miss 多
3. **类型安全**:直接字段的字段类型明确,IDE 自动补全、编译器检查;dyn Part 只能调 trait 方法,丢失具体类型信息
4. **代码简洁**:Player.body.update() 比 Player.parts[0].as_body().unwrap().update() 简洁
5. **固定部分数**:HH 的角色就是头 + 身体,不需要"任意部分"的灵活性。trait object 是过度抽象
6. **测试**:Body 和 Head 可以独立构造和测试;trait object 测试要 mock trait

### Lv2 · 动手实践

**题**:把下面的混合 Player 拆成 Body + Head 两个独立 struct。

重构前:

```rust
struct Player {
    pos: Vec2,
    body_scale_x: Spring,
    body_scale_y: Spring,
    body_color: u32,
    head_offset: Vec2,
    head_rotation: Spring,
    head_color: u32,
}

impl Player {
    fn update(&mut self, dt: f32) {
        self.body_scale_x.update(dt);
        self.body_scale_y.update(dt);
        self.head_rotation.update(dt);
    }
}
```

完成标准:Player 拆成 Player + Body + Head 三个 struct,Player 持有 body 和 head。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 { fn new(x: f32, y: f32) -> Self { Self { x, y } } }

#[derive(Clone, Copy, Debug)]
struct Spring {
    value: f32,
    velocity: f32,
    target: f32,
    stiffness: f32,
    damping: f32,
}

impl Spring {
    fn new(initial: f32, k: f32, c: f32) -> Self {
        Self { value: initial, velocity: 0.0, target: initial, stiffness: k, damping: c }
    }
    fn set_target(&mut self, t: f32) { self.target = t; }
    fn update(&mut self, dt: f32) {
        let force = -self.stiffness * (self.value - self.target) - self.damping * self.velocity;
        self.velocity += force * dt;
        self.value += self.velocity * dt;
    }
}

// 拆出来的 Body
struct Body {
    scale_x: Spring,
    scale_y: Spring,
    color: u32,
}

impl Body {
    fn new(color: u32) -> Self {
        Self {
            scale_x: Spring::new(1.0, 120.0, 12.0),
            scale_y: Spring::new(1.0, 120.0, 12.0),
            color,
        }
    }
    fn update(&mut self, dt: f32) {
        self.scale_x.update(dt);
        self.scale_y.update(dt);
    }
}

// 拆出来的 Head
struct Head {
    offset: Vec2,
    rotation: Spring,  // 弧度
    color: u32,
}

impl Head {
    fn new(color: u32) -> Self {
        Self {
            offset: Vec2::new(0.0, -20.0),  // 在身体上方 20 像素
            rotation: Spring::new(0.0, 100.0, 10.0),
            color,
        }
    }
    fn update(&mut self, dt: f32) {
        self.rotation.update(dt);
    }
    fn look_at(&mut self, angle: f32) {
        self.rotation.set_target(angle);
    }
}

// 重构后的 Player
struct Player {
    pos: Vec2,
    body: Body,
    head: Head,
}

impl Player {
    fn new(pos: Vec2) -> Self {
        Self {
            pos,
            body: Body::new(0xFFFF6040),
            head: Head::new(0xFFFFE0A0),
        }
    }
    fn update(&mut self, dt: f32) {
        self.body.update(dt);
        self.head.update(dt);
    }
    fn look_at(&mut self, angle: f32) {
        self.head.look_at(angle);
    }
    fn squish(&mut self) {
        self.body.scale_x.set_target(0.7);
        self.body.scale_y.set_target(1.3);
    }
}

fn main() {
    let mut player = Player::new(Vec2::new(100.0, 200.0));

    // 玩家操作
    player.look_at(0.5);  // 头转向 0.5 弧度
    player.squish();       // 身体压扁

    // 模拟 1 秒
    let dt = 0.016;
    for _ in 0..60 {
        player.update(dt);
    }

    println!("Body scale: ({:.3}, {:.3})",
             player.body.scale_x.value, player.body.scale_y.value);
    println!("Head rotation: {:.3} rad", player.head.rotation.value);

    // 测试:body 和 head 独立
    let mut body = Body::new(0xFFFF0000);
    body.scale_x.set_target(2.0);
    body.update(0.1);
    println!("Standalone body scale_x: {:.3}", body.scale_x.value);
}
```

**每行解释**:
- Body 和 Head 各自有 new / update,逻辑封装
- Player 持有 body + head 字段,委托方法调用
- Body / Head 可以独立构造测试,不需要整个 Player
- "look_at" / "squish" 是高级 API,内部委托给具体部分

## 8 · Rust / Arch 落地代码

### 完整可跑:Player 拆分 + 头朝向鼠标

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, MouseMode, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
}

#[derive(Clone, Copy, Debug)]
struct Spring {
    value: f32,
    velocity: f32,
    target: f32,
    stiffness: f32,
    damping: f32,
}

impl Spring {
    fn new(initial: f32, k: f32, c: f32) -> Self {
        Self { value: initial, velocity: 0.0, target: initial, stiffness: k, damping: c }
    }
    fn set_target(&mut self, t: f32) { self.target = t; }
    fn update(&mut self, dt: f32) {
        let force = -self.stiffness * (self.value - self.target) - self.damping * self.velocity;
        self.velocity += force * dt;
        self.value += self.velocity * dt;
    }
}

// ---------- Body ----------

struct Body {
    scale_x: Spring,
    scale_y: Spring,
    color: u32,
    size: f32,
}

impl Body {
    fn new(color: u32, size: f32) -> Self {
        Self {
            scale_x: Spring::new(1.0, 120.0, 12.0),
            scale_y: Spring::new(1.0, 120.0, 12.0),
            color, size,
        }
    }
    fn update(&mut self, dt: f32) {
        self.scale_x.update(dt);
        self.scale_y.update(dt);
    }
    fn squish(&mut self) {
        self.scale_x.set_target(0.7);
        self.scale_y.set_target(1.3);
    }
    fn unsquish(&mut self) {
        self.scale_x.set_target(1.0);
        self.scale_y.set_target(1.0);
    }
    fn render(&self, buf: &mut [u32], buf_w: usize, buf_h: usize, pos: Vec2) {
        let w = self.size * self.scale_x.value;
        let h = self.size * self.scale_y.value;
        for py in ((pos.y - h/2.0) as i32).max(0)..((pos.y + h/2.0) as i32).min(buf_h as i32) {
            for px in ((pos.x - w/2.0) as i32).max(0)..((pos.x + w/2.0) as i32).min(buf_w as i32) {
                buf[(py as usize) * buf_w + (px as usize)] = self.color;
            }
        }
    }
}

// ---------- Head ----------

struct Head {
    offset: Vec2,  // 相对 body 的偏移
    rotation: Spring,
    color: u32,
    size: f32,
}

impl Head {
    fn new(color: u32, size: f32) -> Self {
        Self {
            offset: Vec2::new(0.0, -28.0),
            rotation: Spring::new(0.0, 80.0, 12.0),
            color, size,
        }
    }
    fn update(&mut self, dt: f32) {
        self.rotation.update(dt);
    }
    fn look_at(&mut self, angle: f32) {
        self.rotation.set_target(angle);
    }
    fn render(&self, buf: &mut [u32], buf_w: usize, buf_h: usize, body_pos: Vec2) {
        let head_pos = Vec2::new(body_pos.x + self.offset.x, body_pos.y + self.offset.y);
        let angle = self.rotation.value;
        let (sin_a, cos_a) = angle.sin_cos();

        // 画一个"箭头"形状的头部(显示朝向)
        let size = self.size;
        // 简化:画一个圆 + 一个朝向小三角形
        for py in ((head_pos.y - size) as i32).max(0)..((head_pos.y + size) as i32).min(buf_h as i32) {
            for px in ((head_pos.x - size) as i32).max(0)..((head_pos.x + size) as i32).min(buf_w as i32) {
                let dx = px as f32 - head_pos.x;
                let dy = py as f32 - head_pos.y;
                if dx * dx + dy * dy < size * size {
                    buf[(py as usize) * buf_w + (px as usize)] = self.color;
                }
            }
        }

        // 朝向指示(眼睛)
        let eye_dist = size * 0.5;
        let eye_offset_x = cos_a * eye_dist;
        let eye_offset_y = sin_a * eye_dist;
        // 双眼:垂直于朝向方向偏移
        let perp_x = -sin_a * size * 0.3;
        let perp_y = cos_a * size * 0.3;
        for eye_idx in 0..2 {
            let sign = if eye_idx == 0 { -1.0 } else { 1.0 };
            let eye_x = head_pos.x + eye_offset_x + perp_x * sign;
            let eye_y = head_pos.y + eye_offset_y + perp_y * sign;
            for py in ((eye_y - 1.0) as i32).max(0)..((eye_y + 2.0) as i32).min(buf_h as i32) {
                for px in ((eye_x - 1.0) as i32).max(0)..((eye_x + 2.0) as i32).min(buf_w as i32) {
                    buf[(py as usize) * buf_w + (px as usize)] = 0xFF000000;
                }
            }
        }
    }
}

// ---------- Player ----------

struct Player {
    pos: Vec2,
    body: Body,
    head: Head,
    velocity: Vec2,
}

impl Player {
    fn new(pos: Vec2) -> Self {
        Self {
            pos,
            body: Body::new(0xFFFF6040, 24.0),
            head: Head::new(0xFFFFE0A0, 10.0),
            velocity: Vec2::new(0.0, 0.0),
        }
    }
    fn update(&mut self, dt: f32) {
        // 先 body
        self.body.update(dt);
        // 后 head(头可能依赖 body 位置)
        self.head.update(dt);
    }
    fn render(&self, buf: &mut [u32], buf_w: usize, buf_h: usize) {
        // 先 body(下层)
        self.body.render(buf, buf_w, buf_h, self.pos);
        // 后 head(上层,覆盖 body 的头部位置)
        self.head.render(buf, buf_w, buf_h, self.pos);
    }
    fn look_at(&mut self, angle: f32) {
        self.head.look_at(angle);
    }
    fn squish(&mut self) {
        self.body.squish();
    }
    fn unsquish(&mut self) {
        self.body.unsquish();
    }
}

fn main() {
    let mut window = Window::new(
        "Head + Body Reorganization", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();
    let mut squish_timer = 0.0_f32;

    let mut player = Player::new(Vec2::new(WIDTH as f32 / 2.0, HEIGHT as f32 / 2.0));

    while window.is_open() && !window.is_key_down(minifb::Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32().min(0.05);
        last_time = now;

        // 鼠标控制头朝向
        let (mx, my) = window.get_mouse_pos(MouseMode::Discard).unwrap_or((WIDTH as f32 / 2.0, HEIGHT as f32 / 2.0));
        let to_mouse = Vec2::new(mx - player.pos.x, my - (player.pos.y - 28.0));  // 头部位置
        let angle = to_mouse.y.atan2(to_mouse.x);
        player.look_at(angle);

        // 按空格 squish
        if window.is_key_pressed(minifb::Key::Space, minifb::KeyRepeat::No) {
            player.squish();
            squish_timer = 0.3;
        }
        if squish_timer > 0.0 {
            squish_timer -= dt;
            if squish_timer <= 0.0 {
                player.unsquish();
            }
        }

        // 玩家移动(WASD)
        let speed = 200.0;
        let mut vx = 0.0;
        let mut vy = 0.0;
        if window.is_key_down(minifb::Key::A) { vx -= 1.0; }
        if window.is_key_down(minifb::Key::D) { vx += 1.0; }
        if window.is_key_down(minifb::Key::W) { vy -= 1.0; }
        if window.is_key_down(minifb::Key::S) { vy += 1.0; }
        let len = (vx*vx + vy*vy).sqrt();
        if len > 0.0 {
            player.pos.x += (vx / len) * speed * dt;
            player.pos.y += (vy / len) * speed * dt;
        }

        player.update(dt);

        // 渲染
        for px in buffer.iter_mut() { *px = 0xFF101010; }
        player.render(&mut buffer, WIDTH, HEIGHT);

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `Body` 和 `Head` 是独立 struct,各自管理数据和行为
- `Player` 持有 body 和 head(组合)
- `Player::update` 委托给 body 和 head
- `Player::render` 先 body 后 head(渲染顺序保证 head 覆盖 body 头部)
- `look_at / squish` 是高级 API,内部委托给具体部分
- 头的 rotation 用 spring,有平滑跟随效果
