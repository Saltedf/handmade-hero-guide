
# Day 431 · SIMD 光线投射

> rayon 让你用 8 个核心,但每个核心里 CPU 还有 **SIMD**(单指令多数据)能力——一条指令同时处理 4 个 f32。今天 Casey 用 SIMD 加速 ray-AABB,一条指令同时测 4 条光线,理论再快 4 倍。day422 的算法被重写成 `__m128` 版本,代码看起来"奇怪"但运行时飞快。

## 0 · 为什么要有这一天

回顾 day422 的 ray-AABB 算法:每条光线 6 次除法 + 几次比较,大约 10-20 个时钟周期。每帧 10 万次 ray-cast = 100-200 万周期 = 1ms。

能不能更快?CPU 有 **SIMD 寄存器**(__m128,128 位 = 4 个 f32),一条指令同时算 4 个值。理论上 ray-AABB 算法可以并行处理 4 条光线,加速 4 倍。

具体:把 4 条光线的 origin.x、origin.y、origin.z 分别打包成 3 个 `__m128`,用一条 `_mm_sub_ps` 同时算 4 条光线的 `min - origin`。用 `_mm_mul_ps` 同时算 4 条光线的 `(min - origin) / dir`。

但 SIMD 不是"自动加速"。要重写算法:

- 数据布局改成 **SoA**(结构数组):`origins_x: [f32; 4], origins_y: [f32; 4], origins_z: [f32; 4]` 而不是 `origins: [Ray; 4]`
- 用 SIMD intrinsics(`_mm_mul_ps` 等)替代标量运算
- 处理"水平操作"(取 4 个值中的 min/max)比标量贵

Casey 今天实现 **4-wide slab test**——一次测 4 条光线 vs 一个 AABB。这是工业 ray tracer 的标准热点。day432 完成 main loop 集成,day433 进一步优化。

实现难度:5/5。SIMD intrinsics 是 unsafe Rust(底层 CPU 指令),代码可读性差,调试困难。但性能收益巨大。

心理锚点:今天之后,你能写自己的 SIMD 代码,理解为什么工业 ray tracer 用 SIMD,知道 SoA vs AoS 的差别,能为 Rust 生态贡献 SIMD 优化代码。这是从"使用别人写的库"到"自己写底层优化"的跨越。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 在白板上画 4-wide 数据布局,然后写代码。具体步骤:

1. **Ray4 结构**:`origins_x: __m128, origins_y: __m128, origins_z: __m128`(4 条光线的 x/y/z 打包)
2. **AABB4 结构**:`mins: [__m128; 3], maxs: [__m128; 3]`(一个 AABB 的 3 轴 min/max 各重复 4 次)
3. **SIMD slab test**:

Casey 强调:**SIMD 优化是最后的优化**。先确保算法正确(day422)、数据结构高效(day423 BVH)、并行化(day430 rayon),最后才 SIMD。SIMD 调试困难,先有正确版本作为对照。

## 2 · 心智模型

### 类比:四个邮递员一起送信

想象 4 个邮递员送信。两种组织方式:

- **每个独立**(标量):每人有自己的路线,独立完成。简单,但 4 人独立调度成本。
- **同步行进**(SIMD):4 人同时去同一条街,每人送 1 家。一条指令控制 4 人,效率高。

SIMD 强制"同步行进"——4 条光线走**同一**算法路径,执行**同一**指令,只是数据不同。这就是"单指令多数据"(Single Instruction Multiple Data)。

### 严谨原理:SIMD 寄存器和指令

x86_64 的 SSE(SIMD Streaming Extensions):

- `__m128`:128 位寄存器,可装 4 个 f32 / 2 个 f64 / 16 个 i8 等
- `__m256`:256 位(AVX),8 个 f32
- `__m512`:512 位(AVX-512),16 个 f32

指令:

- `_mm_set1_ps(x)`:把 x 复制到 4 个 lane
- `_mm_set_ps(a, b, c, d)`:4 个不同值
- `_mm_add_ps(a, b)`:4 个 lane 各自相加
- `_mm_mul_ps(a, b)`:4 个 lane 各自相乘
- `_mm_min_ps(a, b)`:逐 lane min
- `_mm_max_ps(a, b)`:逐 lane max
- `_mm_movemask_ps(a)`:取 4 个 lane 的最高位,合成 4-bit 整数(用于条件判断)

### SoA vs AoS

**AoS**(Array of Structs):

```
origins = [{x, y, z}, {x, y, z}, {x, y, z}, {x, y, z}]
```

连续内存:`x y z x y z x y z x y z`。访问一条光线的 x/y/z 是连续的(缓存友好),但 SIMD 加载 4 条光线的 x 需要 4 次加载 + shuffle。

**SoA**(Struct of Arrays):

```
origins_x = [x, x, x, x]
origins_y = [y, y, y, y]
origins_z = [z, z, z, z]
```

连续内存:`x x x x y y y y z z z z`。访问一条光线的 x/y/z 是分散的(缓存不友好),但 SIMD 加载 4 条光线的 x 是 1 次加载(连续)。

SIMD **必须 SoA**。否则每次 SIMD 操作都要 shuffle,失去加速。

### 4-wide slab test 算法

```
4 条光线 vs 1 个 AABB:

t_x_min[4] = (aabb.min.x - origins_x[4]) / dirs_x[4]
t_x_max[4] = (aabb.max.x - origins_x[4]) / dirs_x[4]
// 用 SIMD 一次算 4 个

t_enter_axis_x[4] = min(t_x_min, t_x_max)  // SIMD
t_exit_axis_x[4] = max(t_x_min, t_x_max)

// 三轴取最大/最小
t_enter[4] = max(t_enter_axis_x, t_enter_axis_y, t_enter_axis_z)
t_exit[4] = min(t_exit_axis_x, t_exit_axis_y, t_exit_axis_z)

// hit[i] = t_enter[i] < t_exit[i]
mask = _mm_cmplt_ps(t_enter, t_exit)
result_mask = _mm_movemask_ps(mask)  // 4-bit,每位代表一条光线是否命中
```

`movemask` 提取 4 个 bool,合成一个 u8(只用低 4 位)。`0b0101` 表示光线 0 和 2 命中。

### Rust 视角:SIMD intrinsics

```rust
use core::arch::x86_64::*;

#[derive(Copy, Clone)]
pub struct Ray4 {
    pub origin_x: __m128,
    pub origin_y: __m128,
    pub origin_z: __m128,
    pub dir_x: __m128,
    pub dir_y: __m128,
    pub dir_z: __m128,
}

#[derive(Copy, Clone)]
pub struct AABB {
    pub min: [f32; 3],
    pub max: [f32; 3],
}

/// 4 条光线 vs 1 个 AABB,返回 4 位掩码
pub unsafe fn ray4_vs_aabb(rays: &Ray4, aabb: &AABB) -> u8 {
    // 把 AABB 的每个值复制到 4 个 lane
    let min_x = _mm_set1_ps(aabb.min[0]);
    let min_y = _mm_set1_ps(aabb.min[1]);
    let min_z = _mm_set1_ps(aabb.min[2]);
    let max_x = _mm_set1_ps(aabb.max[0]);
    let max_y = _mm_set1_ps(aabb.max[1]);
    let max_z = _mm_set1_ps(aabb.max[2]);

    let mut t_min = _mm_set1_ps(f32::NEG_INFINITY);
    let mut t_max = _mm_set1_ps(f32::INFINITY);

    // X 轴
    let inv_dx = _mm_set1_ps(1.0) / rays.dir_x;  // 注意:要保证 dir_x != 0
    let t1x = (min_x - rays.origin_x) * inv_dx;
    let t2x = (max_x - rays.origin_x) * inv_dx;
    let t_enter_x = _mm_min_ps(t1x, t2x);
    let t_exit_x = _mm_max_ps(t1x, t2x);
    t_min = _mm_max_ps(t_min, t_enter_x);
    t_max = _mm_min_ps(t_max, t_exit_x);

    // Y 轴
    let inv_dy = _mm_set1_ps(1.0) / rays.dir_y;
    let t1y = (min_y - rays.origin_y) * inv_dy;
    let t2y = (max_y - rays.origin_y) * inv_dy;
    let t_enter_y = _mm_min_ps(t1y, t2y);
    let t_exit_y = _mm_max_ps(t1y, t2y);
    t_min = _mm_max_ps(t_min, t_enter_y);
    t_max = _mm_min_ps(t_max, t_exit_y);

    // Z 轴
    let inv_dz = _mm_set1_ps(1.0) / rays.dir_z;
    let t1z = (min_z - rays.origin_z) * inv_dz;
    let t2z = (max_z - rays.origin_z) * inv_dz;
    let t_enter_z = _mm_min_ps(t1z, t2z);
    let t_exit_z = _mm_max_ps(t1z, t2z);
    t_min = _mm_max_ps(t_min, t_enter_z);
    t_max = _mm_min_ps(t_max, t_exit_z);

    // hit = (t_min <= t_max) & (t_max >= 0)
    let hit = _mm_cmple_ps(t_min, t_max);
    let in_front = _mm_cmpge_ps(t_max, _mm_set1_ps(0.0));
    let mask = _mm_and_ps(hit, in_front);
    _mm_movemask_ps(mask) as u8  // 低 4 位有效
}
```

`unsafe` 因为 `__m128` 是平台特定的(x86_64 才有 SSE)。Rust 不保证在其他平台编译。

### BVH 集成

4 条光线一起走 BVH:

```
fn traverse4(rays: Ray4, node: &BvhNode) -> [bool; 4] {
    let mask = ray4_vs_aabb(&rays, &node.bounds);
    if mask == 0 { return [false; 4]; }  // 全部不相交,跳过子树

    match node {
        Leaf(objects) => {
            let mut hits = [false; 4];
            for obj in objects {
                let obj_mask = ray4_vs_aabb(&rays, obj);
                for i in 0..4 {
                    if obj_mask & (1 << i) != 0 { hits[i] = true; }
                }
            }
            hits
        }
        Internal(left, right) => {
            let left_hits = traverse4(rays, left);
            let right_hits = traverse4(rays, right);
            // 合并(每条光线独立)
            [
                left_hits[0] || right_hits[0],
                left_hits[1] || right_hits[1],
                left_hits[2] || right_hits[2],
                left_hits[3] || right_hits[3],
            ]
        }
    }
}
```

如果 4 条光线发散(走不同子树),效率退化。所以最好 4 条光线方向相近(同图元的 4 个采样),让它们 BVH 路径一致。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业 SIMD 用法:

- **物理引擎**:多接触点同时解算
- **皮肤变形**:多顶点同时变换
- **ray tracing**:光线 bundle(SIMD 必备)
- **audio**:FFT、混音
- **video codec**:像素 SIMD 处理

NVidia RTX 用专用硬件(TU-Op)做 BVH 遍历,等效于"无限宽 SIMD"。CPU 上 4-wide SIMD 是这个思想的简化。

### 3.2 · 🎨 图形学视角

SIMD 在图形学的几个核心应用:

- **Matrix multiplication**:4x4 矩阵 SIMD 标配
- **Vertex transformation**:GPU 顶点着色器
- **Ray bundle**:4-16 条光线一起 BVH 遍历
- **Image filtering**:多像素同时卷积

` glam` crate 用 SIMD 实现 Vec3/Mat4 操作,但 ray-AABB 这种**自定义算法**要手写 SIMD。

### 3.3 · 🐧 Linux 系统编程视角

Linux 的 SIMD:

- **crypto**:AES-NI、SHA-NI,硬件加速
- **memcpy**:`rep movsb` 或 AVX,大块复制
- **string ops**:`strlen` / `strcmp` 用 SIMD
- **kernel SIMD**:`__kernel_fpu_begin/end` 保护 FPU 状态

Linux 内核慎用 SIMD(中断上下文不能 SIMD,要保存 FPU 状态),用户态自由用。

### 3.4 · 🦀 Rust 生态视角

Rust SIMD 选项:

- `core::arch::x86_64`:底层 intrinsics(本日)
- `std::simd`(nightly):可移植 SIMD,抽象更高
- `packed_simd` / `wide`:稳定 crate
- `glam`:`Mat4` 内部用 SIMD

`wide` crate 提供 `f32x4` 类型,跨平台(SSE / NEON / AVX 自动选择),代码比 `_mm_*` 易读:

```rust
use wide::f32x4;

let a = f32x4::from([1.0, 2.0, 3.0, 4.0]);
let b = f32x4::from([5.0, 6.0, 7.0, 8.0]);
let c = a + b;  // f32x4([6.0, 8.0, 10.0, 12.0])
```

Casey 用底层 intrinsics(学习目的),实际项目可以用 `wide`。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 SIMD 要求数据 SoA?用 AoS 能 SIMD 吗?如果能,有什么代价?

**参考解答**:SIMD 要求"4 个值连续存放"才能一条指令加载。AoS 的 `origins = [{x,y,z}, ...]` 内存布局是 `xyz xyz xyz xyz`,4 个 x 不连续。要 SIMD 加载 x,需要"horizontal load"——从 4 个不同位置 gather,效率极差。

SoA 的 `origins_x = [x,x,x,x]` 内存布局是 `xxxx`,4 个 x 连续,SIMD 加载 1 条指令。

AoS 可以 SIMD,但要先用 `_mm_shuffle_ps` 把数据"转置"成 SoA,处理完再转回去。转置本身就是 SIMD 操作,但有开销。如果算法本身要求 SoA 处理(如 ray-AABB),直接用 SoA 存储更高效。

pub struct Ray4 {

    pub origin_y: __m128,
    pub origin_z: __m128,
    pub dir_x: __m128,
    pub dir_y: __m128,

            Self {
                origin_x: _mm_set_ps(rays[3].origin.x, rays[2].origin.x, rays[1].origin.x, rays[0].origin.x),
                origin_y: _mm_set_ps(rays[3].origin.y, rays[2].origin.y, rays[1].origin.y, rays[0].origin.y),
                origin_z: _mm_set_ps(rays[3].origin.z, rays[2].origin.z, rays[1].origin.z, rays[0].origin.z),
                dir_x: _mm_set_ps(rays[3].dir.x, rays[2].dir.x, rays[1].dir.x, rays[0].dir.x),
                dir_y: _mm_set_ps(rays[3].dir.y, rays[2].dir.y, rays[1].dir.y, rays[0].dir.y),
                dir_z: _mm_set_ps(rays[3].dir.z, rays[2].dir.z, rays[1].dir.z, rays[0].dir.z),

        }

#[derive(Copy, Clone)]
pub struct Ray { pub origin: Vec3, pub dir: Vec3 }

#[derive(Copy, Clone)]
pub struct AABB { pub min: Vec3, pub max: Vec3 }

pub unsafe fn ray4_vs_aabb(rays: &Ray4, aabb: &AABB) -> u8 {
    let min_x = _mm_set1_ps(aabb.min.x);
    let min_y = _mm_set1_ps(aabb.min.y);
    let min_z = _mm_set1_ps(aabb.min.z);
    let max_x = _mm_set1_ps(aabb.max.x);
    let max_y = _mm_set1_ps(aabb.max.y);
    let max_z = _mm_set1_ps(aabb.max.z);
    let one = _mm_set1_ps(1.0);

    let mut t_min = _mm_set1_ps(f32::NEG_INFINITY);
    let mut t_max = _mm_set1_ps(f32::INFINITY);

    // X 轴
    let inv_dx = one / rays.dir_x;
    let t1x = (min_x - rays.origin_x) * inv_dx;
    let t2x = (max_x - rays.origin_x) * inv_dx;
    t_min = _mm_max_ps(t_min, _mm_min_ps(t1x, t2x));
    t_max = _mm_min_ps(t_max, _mm_max_ps(t1x, t2x));

    let inv_dy = one / rays.dir_y;
    let t1y = (min_y - rays.origin_y) * inv_dy;
    let t2y = (max_y - rays.origin_y) * inv_dy;
    t_min = _mm_max_ps(t_min, _mm_min_ps(t1y, t2y));
    t_max = _mm_min_ps(t_max, _mm_max_ps(t1y, t2y));

    let inv_dz = one / rays.dir_z;
    let t1z = (min_z - rays.origin_z) * inv_dz;
    let t2z = (max_z - rays.origin_z) * inv_dz;
    t_min = _mm_max_ps(t_min, _mm_min_ps(t1z, t2z));
    t_max = _mm_min_ps(t_max, _mm_max_ps(t1z, t2z));

    let hit = _mm_cmple_ps(t_min, t_max);
    let in_front = _mm_cmpge_ps(t_max, _mm_set1_ps(0.0));
    let mask = _mm_and_ps(hit, in_front);
    _mm_movemask_ps(mask) as u8 & 0x0F
}

// 标量版本对比
pub fn ray_vs_aabb_scalar(ray: &Ray, aabb: &AABB) -> bool {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    for axis in 0..3 {
        let o = ray.origin[axis]; let d = ray.dir[axis];
        let lo = aabb.min[axis]; let hi = aabb.max[axis];
        if d.abs() < 1e-8 {
            if o < lo || o > hi { return false; }
        } else {
            let inv_d = 1.0 / d;
            let t1 = (lo - o) * inv_d;
            let t2 = (hi - o) * inv_d;
            let (te, tx) = if t1 < t2 { (t1, t2) } else { (t2, t1) };
            t_min = t_min.max(te);
            t_max = t_max.min(tx);
            if t_min > t_max { return false; }
        }
    }
    t_max >= 0.0
}

fn main() {
    let aabb = AABB {
        min: Vec3::new(-1.0, -1.0, -1.0),
        max: Vec3::new(1.0, 1.0, 1.0),

    let rays = [
        Ray { origin: Vec3::new(-5.0, 0.0, 0.0), dir: Vec3::new(1.0, 0.0, 0.0) },  // hit
        Ray { origin: Vec3::new(-5.0, 5.0, 0.0), dir: Vec3::new(1.0, 0.0, 0.0) },  // miss
        Ray { origin: Vec3::new(0.0, -5.0, 0.0), dir: Vec3::new(0.0, 1.0, 0.0) },  // hit
        Ray { origin: Vec3::new(-5.0, 0.0, 5.0), dir: Vec3::new(1.0, 0.0, 0.0) },  // miss

    // 标量结果
    let scalar_results: Vec<bool> = rays.iter()
        .map(|r| ray_vs_aabb_scalar(r, &aabb))
        .collect();

    let mask = unsafe { ray4_vs_aabb(&ray4, &aabb) };
    let simd_results: Vec<bool> = (0..4).map(|i| mask & (1 << i) != 0).collect();
    println!("SIMD results:   {:?} (mask = 0b{:04b})", simd_results, mask);

    // 性能对比
    let n = 100_000;
    let start = std::time::Instant::now();
    for _ in 0..n {
        for r in &rays {
            std::hint::black_box(ray_vs_aabb_scalar(r, &aabb));
        }
    }

#[derive(Copy, Clone)]
pub struct Ray4 {
    pub origin_x: __m128,
    pub origin_y: __m128,
    pub origin_z: __m128,
    pub dir_x: __m128,
    pub dir_y: __m128,
    pub dir_z: __m128,
}

impl Ray4 {
    pub fn from_rays(rays: &[Ray; 4]) -> Self {
        unsafe {
            Self {
                origin_x: _mm_set_ps(rays[3].origin.x, rays[2].origin.x, rays[1].origin.x, rays[0].origin.x),
                origin_y: _mm_set_ps(rays[3].origin.y, rays[2].origin.y, rays[1].origin.y, rays[0].origin.y),
                origin_z: _mm_set_ps(rays[3].origin.z, rays[2].origin.z, rays[1].origin.z, rays[0].origin.z),
                dir_x: _mm_set_ps(rays[3].dir.x, rays[2].dir.x, rays[1].dir.x, rays[0].dir.x),
                dir_y: _mm_set_ps(rays[3].dir.y, rays[2].dir.y, rays[1].dir.y, rays[0].dir.y),
                dir_z: _mm_set_ps(rays[3].dir.z, rays[2].dir.z, rays[1].dir.z, rays[0].dir.z),
            }
        }
    }
}

#[derive(Copy, Clone)]
pub struct Ray { pub origin: Vec3, pub dir: Vec3 }

#[derive(Copy, Clone)]
pub struct AABB { pub min: Vec3, pub max: Vec3 }

/// 4-wide ray vs AABB,返回 4 位掩码(每位代表一条光线是否命中)
#[target_feature(enable = "sse2")]
pub unsafe fn ray4_vs_aabb(rays: &Ray4, aabb: &AABB) -> u8 {
    let min_x = _mm_set1_ps(aabb.min.x);
    let min_y = _mm_set1_ps(aabb.min.y);
    let min_z = _mm_set1_ps(aabb.min.z);
    let max_x = _mm_set1_ps(aabb.max.x);
    let max_y = _mm_set1_ps(aabb.max.y);
    let max_z = _mm_set1_ps(aabb.max.z);
    let one = _mm_set1_ps(1.0);
    let zero = _mm_set1_ps(0.0);
    let neg_inf = _mm_set1_ps(f32::NEG_INFINITY);
    let pos_inf = _mm_set1_ps(f32::INFINITY);

    let mut t_min = neg_inf;
    let mut t_max = pos_inf;

    // X
    let inv_dx = one / rays.dir_x;
    let t1x = (min_x - rays.origin_x) * inv_dx;
    let t2x = (max_x - rays.origin_x) * inv_dx;
    t_min = _mm_max_ps(t_min, _mm_min_ps(t1x, t2x));
    t_max = _mm_min_ps(t_max, _mm_max_ps(t1x, t2x));

    // Y
    let inv_dy = one / rays.dir_y;
    let t1y = (min_y - rays.origin_y) * inv_dy;
    let t2y = (max_y - rays.origin_y) * inv_dy;
    t_min = _mm_max_ps(t_min, _mm_min_ps(t1y, t2y));
    t_max = _mm_min_ps(t_max, _mm_max_ps(t1y, t2y));

    // Z
    let inv_dz = one / rays.dir_z;
    let t1z = (min_z - rays.origin_z) * inv_dz;
    let t2z = (max_z - rays.origin_z) * inv_dz;
    t_min = _mm_max_ps(t_min, _mm_min_ps(t1z, t2z));
    t_max = _mm_min_ps(t_max, _mm_max_ps(t1z, t2z));

    let hit = _mm_cmple_ps(t_min, t_max);
    let in_front = _mm_cmpge_ps(t_max, zero);
    let mask = _mm_and_ps(hit, in_front);
    _mm_movemask_ps(mask) as u8 & 0x0F
}

pub fn ray_vs_aabb_scalar(ray: &Ray, aabb: &AABB) -> bool {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    for axis in 0..3 {
        let o = ray.origin[axis]; let d = ray.dir[axis];
        let lo = aabb.min[axis]; let hi = aabb.max[axis];
        if d.abs() < 1e-8 {
            if o < lo || o > hi { return false; }
        } else {
            let inv_d = 1.0 / d;
            let t1 = (lo - o) * inv_d;
            let t2 = (hi - o) * inv_d;
            let (te, tx) = if t1 < t2 { (t1, t2) } else { (t2, t1) };
            t_min = t_min.max(te);
            t_max = t_max.min(tx);
            if t_min > t_max { return false; }
        }
    }
    t_max >= 0.0
}

fn main() {
    if !is_x86_feature_detected!("sse2") {
        eprintln!("SSE2 not supported");
        return;
    }

    let aabb = AABB {
        min: Vec3::new(-1.0, -1.0, -1.0),
        max: Vec3::new(1.0, 1.0, 1.0),
    };
    let rays = [
        Ray { origin: Vec3::new(-5.0, 0.0, 0.0), dir: Vec3::new(1.0, 0.0, 0.0) },
        Ray { origin: Vec3::new(-5.0, 5.0, 0.0), dir: Vec3::new(1.0, 0.0, 0.0) },
        Ray { origin: Vec3::new(0.0, -5.0, 0.0), dir: Vec3::new(0.0, 1.0, 0.0) },
        Ray { origin: Vec3::new(0.0, 0.0, -5.0), dir: Vec3::new(0.0, 0.0, 1.0) },
    ];

    let scalar_results: Vec<bool> = rays.iter()
        .map(|r| ray_vs_aabb_scalar(r, &aabb))
        .collect();

    println!("SIMD:   {:?} (mask 0b{:04b})", simd_results, mask);

    // 性能对比
    let n = 1_000_000;

**Troubleshooting**:

- **`_mm_set_ps` 参数顺序** — `set_ps(a, b, c, d)` 是 `[d, c, b, a]`(反向),`setr_ps` 是正向
- **mask 解读错** — bit 0 是 lane 0(第一个值),`movemask` 返回高位在前
- **`unsafe` 编译错误** — `core::arch::x86_64::*` 在非 x86_64 平台不存在,加 `#[cfg(target_arch = "x86_64")]`
- **SIMD 比 scalar 慢** — 没开 `--release`(debug 模式下 SIMD intrinsics 不优化)
- **AVX 不支持** — 加 `is_x86_feature_detected!("avx")` 检测
- **NaN 处理** — `_mm_cmple_ps` 处理 NaN 不一样(返回 false),要小心


### 深度推导:本日相关数学与算法

要真正掌握今天的内容,我们必须把背后的数学推导展开。这一节是"为什么这么做"的论证。

**算法复杂度的精确分析**。今天的代码涉及到对实体集合排序,基准复杂度:

- 最优比较排序下界:O(N log N)(决策树理论)
- Rust `sort_by`:TimSort,平均 O(N log N),最好 O(N)(已部分有序时)
- 拓扑排序:O(V + E),V 是节点数,E 是边数
- Radix sort:O(N × k),k 是 sort key 位数——非比较排序,可突破 O(N log N)

对一个 1000 sprite 的场景,TimSort 大约 10000 次比较,每次比较 5-10 个 cycle(分支少),总 50000-100000 cycle = 20-40 μs。在 60 FPS(16666 μs 预算)占 0.2%——可忽略。100K sprite 时升到 2 ms,开始有压力。Minecraft 这种规模的游戏必须用 radix sort 或 GPU sort。

**内存访问模式**。sort 是**非线性内存访问**的典型——每次比较都可能跳到 Vec 不同位置。CPU prefetcher 抓不到模式,cache miss 频繁。优化:

1. **Sort by index**:先 sort indices(u32 数组,4 字节/项,cache 友好),再 reorder 数据。indices 1000 个 = 4 KB,L1 cache 装得下。
2. **Batch reorder**:indices 排好后,顺序遍历 indices,顺序访问原数据(虽然是间接但 prefetcher 跟得上)。

```rust
let mut indices: Vec<u32> = (0..entities.len() as u32).collect();
indices.sort_by(|&a, &b| sort_rule(&entities[a as usize], &entities[b as usize]));
let sorted: Vec<&Entity> = indices.iter().map(|&i| &entities[i as usize]).collect();
```

100K sprite 的 sort 用这个技巧能加速 30%。

**位运算打包 sort key**。今天 sort_key 是 u64,可以塞进多个字段:

```
bits 63-56: layer (8 bits, 256 layers)
bits 55-40: bottom_y (16 bits, 65536 levels)
bits 39-24: x (16 bits)
bits 23-8: sub_layer (16 bits)
bits 7-0: spawn_id (8 bits, 256 entries per slot)
```

打包:`key = (layer << 56) | (bottom_y << 40) | (x << 24) | (sub << 8) | spawn`。一次 u64 比较,无分支,Rust `sort_by_key` 自动 inline。

**部分序的图论模型**。Day 304 会用拓扑排序处理真正的部分序。每个 sprite 是图节点,如果 A 应该在 B 前面,加边 A→B。拓扑排序给出节点的合法顺序(满足所有约束)。

拓扑排序算法:

1. **Kahn 算法**:每次找入度为 0 的节点,加入结果,删掉它的出边,重复。
2. **DFS 后序**:DFS 遍历,记录后序(post-order),反转得到拓扑序。

如果图有环(循环依赖),拓扑排序失败——意味着 sprite 排序无解,必须**人为拆解**(切开某个 sprite)。

**浮点数的稳定性**。Rust 的 `f32::partial_cmp` 处理 NaN 返回 `None`,sort 会 panic。所以游戏代码里要么保证所有 f32 都不是 NaN(数学保证),要么 `partial_cmp(...).unwrap_or(Equal)`(默认相等)。今天 sort_rule 用后者。

更稳妥的方法:**所有位置用整数**(像素单位)。`pos_y: i32` 没有 NaN 问题,比较无分支。但缩放和旋转要用浮点,所以游戏用 i32 + f32 混合。

### 真实代码片段

Casey 在 HH 视频里实际写的代码风格(简化伪代码):

```c
internal int32
SortRule(entity *A, entity *B)
{
    int32 Result = 0;

    // Layer 比较
    if (A->Layer != B->Layer) {
        Result = (int32)A->Layer - (int32)B->Layer;
    } else {
        // Bounds overlap 检查
        rectangle2 BoundsA = GetEntityBounds(A);
        rectangle2 BoundsB = GetEntityBounds(B);
        if (RectanglesOverlap(BoundsA, BoundsB)) {
            // Bottom y 比较
            real32 BottomA = BoundsA.Max.Y;
            real32 BottomB = BoundsB.Max.Y;
            if (BottomA != BottomB) {
                Result = (BottomA < BottomB) ? -1 : 1;
            } else {
                // x 比较
                Result = SignOf32(A->P.X - B->P.X);
            }
        } else {
            // 不重叠:任意顺序
            Result = A->SpawnID - B->SpawnID;
        }
    }

    return Result;
}
```

注意 Casey 的 C 风格:

- 直接返回 int32(而非 enum Ordering)
- 用 `SignOf32`(返回 -1/0/1)简化比较
- if-else 链而非 Rust 的 `then_with`

Rust 等价:

```rust
fn sort_rule(a: &Entity, b: &Entity) -> Ordering {
    a.layer.cmp(&b.layer)
        .then_with(|| {
            if bounds_overlap(a, b) {
                let ba = bounds(a).max.y;
                let bb = bounds(b).max.y;
                ba.partial_cmp(&bb).unwrap_or(Ordering::Equal)
                    .then(a.pos.x.partial_cmp(&b.pos.x).unwrap_or(Ordering::Equal))
            } else {
                a.spawn_id.cmp(&b.spawn_id)
            }
        })
}
```

### 跨学科联结:从游戏到数据库

sort_rule 的本质是"复杂比较函数",这在很多领域都出现:

- **数据库 ORDER BY**:SQL 的 `ORDER BY layer, y, x` 是同样的 multi-key sort,但 SQL 是声明式(数据库优化器选 sort 算法),Casey 是命令式(手写 sort_by)。
- **React diff**:React 用 sort + key 比较 virtual DOM,决定哪些 component 重渲染。Multi-key sort 决定 diff 顺序。
- **Linux kernel CFS**(Completely Fair Scheduler):按 vruntime 排序进程,选最小 vruntime 的运行。本质是 sort_rule。
- **Git log --sort**:Git commit 按 committer date + author date + subject 排序。

Casey 在 HH 反复说"很多算法本质相同,只是命名不同"。掌握一个领域的 sort_rule,就掌握所有领域。
