# Day 277 · 稀疏实体系统

> 现在的游戏里"实体"概念开始膨胀——玩家、怪物、可拾取物、传送门、各种触发器,每个都有自己的位置 + 状态 + 行为。今天 Casey 重构实体存储,从"每种实体一个 Vec"改成**稀疏实体系统**:一个统一的存储 + 多种 entity 类型 + 高效查询。这是 HH 最重要的架构演进之一。

## 0 · 为什么要有这一天

你的游戏目前大概有这些实体:

- Player:1 个
- Monsters:可能 5-10 个
- Pickups(血瓶、金币):可能 20 个
- Triggers(进入区域触发剧情):可能 10 个
- Particles:可能 100 个

每个实体需要存:位置、速度、状态、动画参数、AI 数据等等。你目前的做法可能是每种 entity 一个 struct + 一个 Vec:

```rust
struct GameState {
    player: Player,
    monsters: Vec<Monster>,
    pickups: Vec<Pickup>,
    triggers: Vec<Trigger>,
    particles: Vec<Particle>,
}
```

这种"按类型分 Vec"有几个问题:

**问题 1:跨类型查询难**。你想"找玩家附近所有可拾取物",要遍历 `pickups`、还要遍历 `monsters`(有些怪物掉落物品)。代码变成多个循环。

**问题 2:加新类型难**。加一个新 entity 类型"陷阱",要在 GameState 加字段、update 函数加循环、render 函数加循环。每加一种都改 5 处。

**问题 3:全局 ID 不统一**。玩家是 "player",怪物是 `monsters[3]`,拾取物是 `pickups[5]`——三种不同的"标识方式"。要表达"谁攻击谁"时,得加 enum 区分类型 + 索引,代码膨胀。

**问题 4:稀疏数据浪费内存**。pickups 最多 20 个,但只在玩家走过区域时才有。大部分时候 Vec 长度是 0,但你预分配了容量。或者反过来:Vec 不预分配,运行时 push/pop 频繁,内存碎片。

业界的解决方案:**Entity Component System (ECS)** 或 **稀疏实体系统**。

核心思想:

- **统一 ID**:每个 entity 一个 `EntityId(u32)`,不区分类型
- **稀疏存储**:用一个数组,每个 slot 可空可占
- **类型 mask**:每个 entity 有 bitmask 表示"有哪些组件"(position / health / AI / ...)
- **系统遍历**:每个 system(update / render / collision)按 mask 过滤

HH 不是严格的 ECS(Casey 用 C,没法做 trait object),但是"稀疏 + 类型 mask"思想。

心理锚点:做完这个,你的游戏可以支持几百种 entity,代码不爆炸,性能不下降。

## 1 · Casey 今天做了什么

Casey 重构实体存储:

1. 引入 `entity_id: u32`(或更大),每个 entity 唯一
2. 用一个大数组 `entities: Vec<Entity>` 存储,每个 slot 有 `Option<Entity>` 或 `Entity { active: bool, ... }`
3. Entity 内部用 enum 或 union 区分类型(monster / pickup / trigger / ...)
4. update / render / collision 函数遍历 `entities`,根据类型分发
5. 处理"创建 / 删除":删除时 `entity.active = false`,下次分配复用这个 slot
6. 加 free list 跟踪可用 slot,避免每次分配都扫描

Casey 演示了"创建一个新怪物"的流程:

1. 从 free list 取一个 slot index
2. 在 entities[index] 创建一个 Entity::Monster { ... }
3. 返回 entity_id = encode(index, generation)

generation 是为了"版本号"——防止持有旧 EntityId 的代码误用已删除的 entity。每次 slot 复用时 generation += 1,旧 ID 失效。

## 2 · 心智模型

### 类比:酒店房间管理

想象酒店有 100 个房间。每个房间:

- 房间号(0-99)对应 entity slot index
- 入住 / 退房对应 entity 创建 / 删除
- 退房后房间号不变,可以重新分配给新客人(但这是新客人,和上一个无关)
- 服务员(系统)按楼层 / 客人类型打扫:VIP 房先扫,标准房后扫

酒店管理:

- **房间号**:entity slot index
- **客人类型**:entity type(monster / pickup / ...)
- **退房后复用**:slot 复用
- **房间号 + 入住次数**:entity_id = (slot, generation),防止混淆新旧客人

如果只用房间号当 ID,会有问题:老客人留下了"我的房间是 305"的便条,新客人入住后,有人拿便条找 305,找到的是新客人——张冠李戴。**generation 解决这个**:便条写"305(本次入住)" ,新客人入住后便条失效。

### 严谨原理:稀疏数组 + free list

#### 数据结构

```rust
const MAX_ENTITIES: usize = 4096;

#[derive(Clone, Debug)]
struct Entity {
    active: bool,
    generation: u32,    // 这个 slot 复用了多少次
    kind: EntityKind,
    pos: Vec2,
    // 通用字段
}

#[derive(Clone, Debug)]
enum EntityKind {
    Player { health: f32, scale_x: f32, scale_y: f32 },
    Monster { health: f32, ai_state: AiState },
    Pickup { item: ItemType, amount: u32 },
    Trigger { script: u32 },
    Particle { life: f32, velocity: Vec2 },
    Empty,
}

struct World {
    entities: Vec<Entity>,  // 长度 MAX_ENTITIES
    free_slots: Vec<usize>, // 可用的 slot 索引
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct EntityId {
    index: u32,
    generation: u32,
}
```

#### 创建 entity

```rust
impl World {
    fn spawn(&mut self, kind: EntityKind, pos: Vec2) -> EntityId {
        // 从 free_slots 取一个
        if let Some(index) = self.free_slots.pop() {
            let slot = &mut self.entities[index];
            slot.active = true;
            slot.generation = slot.generation.wrapping_add(1);
            slot.kind = kind;
            slot.pos = pos;
            EntityId {
                index: index as u32,
                generation: slot.generation,
            }
        } else {
            panic!("Out of entity slots");
        }
    }
}
```

#### 删除 entity

```rust
impl World {
    fn despawn(&mut self, id: EntityId) {
        if self.is_valid(id) {
            let slot = &mut self.entities[id.index as usize];
            slot.active = false;
            slot.kind = EntityKind::Empty;
            self.free_slots.push(id.index as usize);
        }
    }

    fn is_valid(&self, id: EntityId) -> bool {
        let slot = &self.entities[id.index as usize];
        slot.active && slot.generation == id.generation
    }
}
```

#### 遍历特定类型

```rust
impl World {
    fn for_each_monster_mut(&mut self, mut f: impl FnMut(EntityId, &mut Entity)) {
        for (i, slot) in self.entities.iter_mut().enumerate() {
            if !slot.active { continue; }
            if matches!(slot.kind, EntityKind::Monster { .. }) {
                let id = EntityId {
                    index: i as u32,
                    generation: slot.generation,
                };
                f(id, slot);
            }
        }
    }
}
```

这是**类型 mask 过滤**的简化版(用 matches! 代替 bitmask)。如果实体类型很多,改用 bitmask 更高效。

#### ID 验证

每次拿到 EntityId,要先验证它"还有效"——防止旧引用访问已删除 / 复用的 slot。

```rust
let target_id = ...;  // 某个之前存的 ID
if !world.is_valid(target_id) {
    return;  // 已删除,跳过
}
let target = &world.entities[target_id.index as usize];
// 安全使用
```

这是 **generational index** 模式,是 ECS 标准做法。Rust 的 `slotmap` crate 提供了工业级实现。

### 为什么不用 `Vec<Box<dyn Entity>>`?

乍看 trait object 是 OOP 的优雅方案:

```rust
trait Entity {
    fn update(&mut self, dt: f32);
    fn render(&self, buf: &mut [u32]);
}

struct World {
    entities: Vec<Box<dyn Entity>>,
}
```

优点:多态漂亮,加新类型只加 struct + impl。
缺点:

1. **缓存不友好**:每个 entity 是堆分配,数据分散
2. **类型查询难**:从 `&dyn Entity` 反查具体类型要 `downcast`,运行时检查
3. **组件复用难**:Monster 和 Player 都有 health,不能"共享"health 字段
4. **性能**:虚函数调用 + 间接寻址,大数据量慢

Casey 用 enum + 稀疏数组,缓存友好 + 无虚函数。Rust 端走这条路。

### ECS 的极致版本

完整 ECS 进一步:不用 enum,把每种 component 独立存储:

```rust
struct World {
    positions: ComponentStorage<Position>,
    healths: ComponentStorage<Health>,
    ais: ComponentStorage<Ai>,
    // ...
}
```

每个 ComponentStorage 是一个稀疏数组,entity_id 作为索引。这样:

- **缓存极致友好**:遍历所有 Position 时只读 positions,不读其他数据
- **任意组合**:一个 entity 可以只有 Position 没有 Health(静态物)
- **system 并行**:不同的 system 读不同的 storage,无锁并行

业界 ECS 库(bevy_ecs / specs / EnTT)都用这种模式。HH 不完全到这一步,但是思想基础。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

ECS 是现代游戏引擎的标准:

- **Unity DOTS**:Unity 的 ECS 重构,性能 10x 提升
- **Unreal Mass Entity**:Unreal 5 的 ECS
- **Bevy ECS**:Rust 的 ECS,业界最活跃
- **Custom engines**:几乎所有现代引擎都用 ECS

ECS 的关键概念:

- **Entity**:只是 ID,无数据
- **Component**:纯数据(Position / Health / AI)
- **System**:操作特定 Component 组合的函数

Casey 的 HH 走的是"中间路线"——enum 表达 component 组合,比纯 ECS 简单,比传统 OOP 灵活。

### 3.2 · 🐧 Linux 系统编程视角

Linux 内核的"统一 ID"思想:

- **PID**:每个进程一个 `pid_t`,跨用户 / 跨进程统一
- **inode number**:每个文件一个,跨文件系统统一(在文件系统内)
- **file descriptor**:每个打开文件一个,跨进程内统一

这些"统一 ID"让系统调用接口简洁。Casey 的 EntityId 是同一思想在游戏里的应用。

#### 进程表的稀疏数组

Linux 的 task_struct(进程结构)也是稀疏数组——PID 可以复用(进程退出后 PID 给新进程),但有 generation 防混淆(实际 Linux 用 PID 增量,不严格 generation,但概念类似)。

```bash
# 看 Linux 进程表
ps -ef
# 注意 PID 不是连续的,有"空洞"——已退出进程的 PID

# 看 PID 复用
cat /proc/sys/kernel/pid_max
# 输出 4194304,即 PID 最大值
```

### 3.3 · 🦀 Rust 生态视角

Rust 表达 ECS / 稀疏存储几个选择:

#### 手写(教学)

```rust
struct World {
    entities: Vec<EntitySlot>,
    free_list: Vec<usize>,
}
```

简单,Casey 走这条。

#### slotmap crate

```rust
use slotmap::SlotMap;
slotmap::new_key_type! { struct EntityKey; }

let mut entities: SlotMap<EntityKey, Entity> = SlotMap::with_key();
let key = entities.insert(Entity::new(...));
// key 包含 index + generation
```

工业级,自动 generation 管理。安全 API,无 unsafe。

#### bevy_ecs

```rust
use bevy_ecs::prelude::*;

#[derive(Component)]
struct Position(Vec2);

#[derive(Component)]
struct Health(f32);

let mut world = World::new();
let id = world.spawn((Position(Vec2::new(0.0, 0.0)), Health(100.0))).id();

// Query 找所有有 Position 和 Health 的 entity
let mut query = world.query::<(&Position, &mut Health)>();
for (pos, health) in query.iter_mut(&mut world) {
    // ...
}
```

业界最先进的 ECS,query-based + 并行 + schedule。

#### 性能对比

| 方案 | 缓存友好 | 灵活性 | 实现复杂度 |
|---|---|---|---|
| 手写稀疏 | 中 | 中 | 简 |
| slotmap | 中 | 中 | 简(用 crate) |
| enum + 数组(今天) | 高 | 低(类型固定) | 简 |
| ECS(bevy) | 极高 | 极高 | 高(用 crate) |

Casey 用"enum + 数组",Rust 端我们沿用。生产项目用 bevy_ecs。

### 3.4 · 软件工程:generational index

generational index 是 Rust 生态常用模式:

- 解决" dangling reference"问题:旧 ID 在删除后自然失效
- 比 raw index 安全:不会访问到新 entity(误以为是旧的)
- 比 Rc / Arc 便宜:无引用计数开销

`slotmap` 论文(Silversten et al.)详细分析了这个模式,业界标准。

Rust 的 ownership 系统不直接支持 generational index(需要运行时检查),所以用 SlotMap / dense_map / generational_arena 等 crate。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 entity ID 用 `EntityId { index, generation }` 而不是简单的 `usize`?给出至少 3 个理由。

**参考解答**:
1. **防止 dangling**:`usize` 索引无法区分"原 entity"和"复用后的新 entity"。Entity A 在 slot 5 被删除,Entity B 复用了 slot 5——旧的 `usize = 5` 引用指向 B,误以为是 A。generation 区分新旧
2. **调试友好**:generation 让 ID 自带"版本号",日志里看到 `Entity(5, gen=3)` 立即知道是 slot 5 的第 3 代
3. **运行时检测**:`is_valid(id)` 检查 id.generation == slot.generation,失败说明引用过期。usize 没办法检测
4. **安全性**:`slotmap` 等库的整个安全模型建立在 generational index 上,允许 safe Rust API(否则要 unsafe 或 RefCell)
5. **支持并发**:多线程持有 entity ID 时,generation 让并发删除安全(旧 ID 失效而非野指针)

### Lv2 · 动手实践

**题**:实现 `World` struct(`entities: Vec<EntitySlot>` + `free_list: Vec<usize>`),以及 spawn / despawn / is_valid。

测试:

- spawn 3 个 entity,验证 ID 唯一
- despawn 第 2 个,验证 is_valid 返回 false
- 再 spawn 1 个,验证它复用了 slot 1(但 generation 不同)

完成标准:删除后 ID 失效,复用时 generation 增加。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct EntityId { index: u32, generation: u32 }

#[derive(Clone, Debug)]
enum EntityKind {
    Player,
    Monster,
    Pickup,
    Empty,
}

#[derive(Clone, Debug)]
struct EntitySlot {
    active: bool,
    generation: u32,
    kind: EntityKind,
}

impl Default for EntitySlot {
    fn default() -> Self {
        Self { active: false, generation: 0, kind: EntityKind::Empty }
    }
}

struct World {
    entities: Vec<EntitySlot>,
    free_list: Vec<usize>,
}

impl World {
    fn new(capacity: usize) -> Self {
        let entities = vec![EntitySlot::default(); capacity];
        let free_list = (0..capacity).rev().collect();  // 反向,从尾部开始用
        Self { entities, free_list }
    }

    fn spawn(&mut self, kind: EntityKind) -> Option<EntityId> {
        let index = self.free_list.pop()?;
        let slot = &mut self.entities[index];
        slot.active = true;
        slot.generation = slot.generation.wrapping_add(1);
        slot.kind = kind;
        Some(EntityId {
            index: index as u32,
            generation: slot.generation,
        })
    }

    fn despawn(&mut self, id: EntityId) {
        if self.is_valid(id) {
            let slot = &mut self.entities[id.index as usize];
            slot.active = false;
            slot.kind = EntityKind::Empty;
            self.free_list.push(id.index as usize);
        }
    }

    fn is_valid(&self, id: EntityId) -> bool {
        let idx = id.index as usize;
        if idx >= self.entities.len() { return false; }
        let slot = &self.entities[idx];
        slot.active && slot.generation == id.generation
    }
}

fn main() {
    let mut world = World::new(16);

    let p = world.spawn(EntityKind::Player).unwrap();
    let m1 = world.spawn(EntityKind::Monster).unwrap();
    let m2 = world.spawn(EntityKind::Monster).unwrap();

    println!("Spawned: player={:?}, m1={:?}, m2={:?}", p, m1, m2);

    // 三个 ID 唯一
    assert!(p != m1 && m1 != m2);

    // 全部有效
    assert!(world.is_valid(p));
    assert!(world.is_valid(m1));
    assert!(world.is_valid(m2));

    // 删除 m1
    world.despawn(m1);
    assert!(!world.is_valid(m1));  // m1 失效
    assert!(world.is_valid(p));
    assert!(world.is_valid(m2));
    println!("After despawn m1: m1 valid = {}", world.is_valid(m1));

    // 再 spawn,复用 slot 1(m1 的位置)
    let new_e = world.spawn(EntityKind::Pickup).unwrap();
    println!("Spawned new: {:?}, should reuse slot 1 with new generation", new_e);
    assert_eq!(new_e.index, m1.index);  // 复用 slot
    assert_ne!(new_e.generation, m1.generation);  // generation 不同
    assert!(!world.is_valid(m1));  // m1 仍然失效(generation 不匹配)
    assert!(world.is_valid(new_e));  // new_e 有效

    println!("All tests passed!");
}
```

**每行解释**:
- `EntityId` 是 Copy,可以按值传递
- `wrapping_add(1)` 防止 generation 溢出 panic(虽然实际很难溢出)
- `free_list.pop()` 后进先出,最近释放的 slot 先用(更好的 cache 局部性)
- `is_valid` 三重检查:边界 + active + generation
- 复用 slot 时,新 ID 的 generation 比 m1 的大 1,所以 m1 不再有效

### 完整可跑:稀疏实体系统 + 多种 entity 渲染

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, KeyRepeat, Window, WindowOptions};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const MAX_ENTITIES: usize = 1024;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct EntityId { index: u32, generation: u32 }

#[derive(Clone, Debug)]
enum EntityKind {
    Player,
    Monster { vx: f32, vy: f32 },
    Pickup { kind: u32 },  // 0=血瓶, 1=金币
    Empty,
}

#[derive(Clone, Debug)]
struct EntitySlot {
    active: bool,
    generation: u32,
    kind: EntityKind,
    x: f32, y: f32,
    color: u32,
    size: f32,
}

impl Default for EntitySlot {
    fn default() -> Self {
        Self {
            active: false, generation: 0,
            kind: EntityKind::Empty,
            x: 0.0, y: 0.0, color: 0, size: 0.0,
        }
    }
}

struct World {
    entities: Vec<EntitySlot>,
    free_list: Vec<usize>,
}

impl World {
    fn new() -> Self {
        let entities = vec![EntitySlot::default(); MAX_ENTITIES];
        let free_list = (0..MAX_ENTITIES).rev().collect();
        Self { entities, free_list }
    }

    fn spawn(&mut self, kind: EntityKind, x: f32, y: f32, color: u32, size: f32) -> Option<EntityId> {
        let index = self.free_list.pop()?;
        let slot = &mut self.entities[index];
        slot.active = true;
        slot.generation = slot.generation.wrapping_add(1);
        slot.kind = kind;
        slot.x = x;
        slot.y = y;
        slot.color = color;
        slot.size = size;
        Some(EntityId {
            index: index as u32,
            generation: slot.generation,
        })
    }

    fn despawn(&mut self, id: EntityId) {
        if self.is_valid(id) {
            let slot = &mut self.entities[id.index as usize];
            slot.active = false;
            slot.kind = EntityKind::Empty;
            self.free_list.push(id.index as usize);
        }
    }

    fn is_valid(&self, id: EntityId) -> bool {
        if id.index as usize >= self.entities.len() { return false; }
        let slot = &self.entities[id.index as usize];
        slot.active && slot.generation == id.generation
    }

    fn get(&self, id: EntityId) -> Option<&EntitySlot> {
        if self.is_valid(id) {
            Some(&self.entities[id.index as usize])
        } else {
            None
        }
    }

    fn get_mut(&mut self, id: EntityId) -> Option<&mut EntitySlot> {
        if self.is_valid(id) {
            Some(&mut self.entities[id.index as usize])
        } else {
            None
        }
    }

    fn active_count(&self) -> usize {
        self.entities.iter().filter(|s| s.active).count()
    }
}

fn draw_circle(buf: &mut [u32], buf_w: usize, buf_h: usize, cx: i32, cy: i32, radius: f32, color: u32) {
    let r2 = radius * radius;
    let r = radius as i32 + 1;
    for py in (cy - r).max(0)..(cy + r).min(buf_h as i32) {
        for px in (cx - r).max(0)..(cx + r).min(buf_w as i32) {
            let dx = px - cx;
            let dy = py - cy;
            if (dx * dx + dy * dy) as f32 <= r2 {
                buf[(py as usize) * buf_w + (px as usize)] = color;
            }
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Sparse Entity System", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();

    let mut world = World::new();

    // 初始化:1 个 player,5 个 monster,10 个 pickup
    let player_id = world.spawn(
        EntityKind::Player,
        400.0, 300.0,
        0xFFFF6040, 12.0,
    ).unwrap();

    for i in 0..5 {
        let x = 100.0 + i as f32 * 120.0;
        let y = 150.0;
        world.spawn(
            EntityKind::Monster { vx: 30.0 + i as f32 * 5.0, vy: 0.0 },
            x, y,
            0xFFA040FF, 10.0,
        );
    }

    for i in 0..10 {
        let x = 50.0 + (i as f32 * 70.0).min(700.0);
        let y = 500.0;
        let (color, kind) = if i % 2 == 0 {
            (0xFFFF4040, 0u32)  // 血瓶
        } else {
            (0xFFFFFF40, 1u32)  // 金币
        };
        world.spawn(
            EntityKind::Pickup { kind },
            x, y, color, 6.0,
        );
    }

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32().min(0.05);
        last_time = now;

        // 玩家移动
        let speed = 200.0;
        if let Some(player) = world.get_mut(player_id) {
            if window.is_key_down(Key::A) { player.x -= speed * dt; }
            if window.is_key_down(Key::D) { player.x += speed * dt; }
            if window.is_key_down(Key::W) { player.y -= speed * dt; }
            if window.is_key_down(Key::S) { player.y += speed * dt; }
            // clamp
            player.x = player.x.max(20.0).min((WIDTH - 20) as f32);
            player.y = player.y.max(20.0).min((HEIGHT - 20) as f32);
        }

        // 怪物移动 + 碰撞玩家
        let player_pos = world.get(player_id).map(|p| (p.x, p.y));
        if let Some((px, py)) = player_pos {
            let mut to_despawn = Vec::new();
            for (i, slot) in world.entities.iter_mut().enumerate() {
                if !slot.active { continue; }
                if let EntityKind::Monster { vx, vy } = &mut slot.kind {
                    slot.x += *vx * dt;
                    if slot.x < 50.0 || slot.x > (WIDTH - 50) as f32 {
                        *vx = -*vx;  // 反弹
                    }
                    // 碰撞玩家:距离 < 30
                    let dx = slot.x - px;
                    let dy = slot.y - py;
                    if dx * dx + dy * dy < 30.0 * 30.0 {
                        to_despawn.push(EntityId {
                            index: i as u32,
                            generation: slot.generation,
                        });
                    }
                }
            }
            for id in to_despawn {
                world.despawn(id);
                println!("Monster eaten! ID {:?}", id);
            }
        }

        // 清屏
        for px in buffer.iter_mut() { *px = 0xFF101010; }

        // 渲染所有 entity
        for slot in world.entities.iter() {
            if !slot.active { continue; }
            draw_circle(&mut buffer, WIDTH, HEIGHT,
                        slot.x as i32, slot.y as i32, slot.size, slot.color);
        }

        // 显示 entity 数量
        let count = world.active_count();
        let _ = count;
        // 画指示器(左上)
        for i in 0..10 {
            let color = if i < (count / 2) as i32 { 0xFF40FF40 } else { 0xFF404040 };
            draw_circle(&mut buffer, WIDTH, HEIGHT, 20 + i * 20, 20, 5.0, color);
        }

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }

    let _ = window.is_key_pressed(Key::Space, KeyRepeat::No);
}
```

**关键 Rust 特性解释**:

- `EntityId` 是 Copy 类型,8 字节,可以值传递
- `Option<EntityId>` 表达"可能不存在"(spawn 返回)
- `world.get_mut(id)` 用 Option 返回,强制处理"已删除"情况
- `to_despawn` 收集要删除的 ID,然后统一 despawn(避免遍历时修改)
- `EntityKind::Monster { vx, vy }` 模式匹配解构可变引用
