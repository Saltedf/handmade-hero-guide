
# Day 271 · 混合瓦片式移动

> 昨天定义了 Traversable 抽象,今天 Casey 真的开始改游戏移动:**角色物理仍是浮点连续,但目标位置是离散 tile**。这种"混合"模型让你既保留动作游戏的平滑感,又获得网格关卡设计的便利。

## 0 · 为什么要有这一天

昨天的代码有个明显缺陷:角色每次按方向键**瞬间跳到下一个 tile**。从 (3, 3) 到 (4, 3) 是一步切换,没有过渡。视觉上看就是"角色闪烁出现在新位置",完全不像动作游戏。

但完全自由移动(Phase 2 的方式)又回到"角色可能卡半个身子在墙里"的问题。

Casey 的解决方案是**混合**:

- **目标位置**:`destination_tile: TilePos`,角色"想去"的 tile
- **当前位置**:`current_pos: WorldPos (f32)`,角色"实际"在的像素位置
- **每帧**:current_pos 朝 destination_tile 的中心移动一段距离(基于速度 + dt)
- **到达后**:current_pos 等于 destination_tile 中心,等待下一个输入

这种模型的好处:

1. **平滑**:角色不是瞬移,而是滑过去(连续物理)
2. **网格对齐**:目标永远是 tile 中心,不会卡半个身子
3. **响应灵敏**:角色移动中按反方向,可以中途改向(不需要到达再改)
4. **关卡友好**:碰撞检查只看"目标 tile 是否 traversable",简单

实现工程难点:

1. **何时算"到达"**:浮点比较不能精确等于,要用 epsilon
2. **移动中的输入**:角色还在 A→B 过渡时,玩家按方向键,应该怎么响应?
3. **速度变化**:不同情境(走路/跑步)速度不同,模型要支持
4. **碰撞反馈**:撞墙时角色应该停在哪?继续滑还是立即停?

心理锚点:做完这个,角色移动从"瞬移"变成"流畅滑动",但底层目标仍是网格点。

## 1 · Casey 今天做了什么

Casey 把角色移动改成"目标导向"模型:

1. 引入 `destination_tile: TilePos`,角色想到达的 tile
2. 角色物理仍是 `current_pos: WorldPos (f32)` + `velocity: Vec2`
3. 每帧计算"指向 destination 的方向向量",把它设为 velocity
4. 用 Euler 积分更新 current_pos
5. 检查 current_pos 是否足够接近 destination(用 epsilon),若是则"到达",清空 destination
6. 玩家按方向键时,把 destination 设为相邻 tile(如果 traversable)
7. 角色仍在移动时,新输入会覆盖 destination(立即转向)

Casey 在视频里演示了关键细节:

- **速度归一化**:不管 destination 多远,速度大小恒定(走 / 跑速度)
- **到达 epsilon**:`epsilon = 0.5 像素`,小于这个距离就认为到达
- **超速保护**:如果某帧 dt 很大(卡顿),角色可能"冲过"destination,要 clamp

最后 Casey 加了一个**碰撞检查**:每次玩家按方向键时,先检查目标 tile 是否 traversable,如果是才设 destination;否则忽略输入(角色不动)。

## 2 · 心智模型

### 类比:GPS 导航

想象你用 GPS 导航开车。GPS 给你一个**目的地**(某个路口),你**当前**在某条路上。你不需要瞬间到达目的地,你按当前道路开过去,过程中 GPS 实时计算方向。

混合瓦片移动就是这个模型:

- **目的地** = `destination_tile`(GPS 给的下一个路口)
- **当前位置** = `current_pos`(你现在在哪)
- **速度** = `velocity`(你开多快)
- **到达** = `current_pos` 接近 `destination_tile` 中心(到达路口)

GPS 不关心你的物理细节(车的型号、加速能力),只关心"目的地 + 当前位置 → 方向"。Casey 的混合移动也是。

### 严谨原理:目标导向运动

#### 数学模型

每帧的更新:

```
direction = (destination - current_pos).normalized()
velocity = direction * speed
new_pos = current_pos + velocity * dt

if distance(new_pos, destination) < epsilon:
    # 到达,snap 到 destination
    current_pos = destination
    destination = None
else:
    current_pos = new_pos
```

关键操作:

1. **`destination - current_pos`**:从当前位置指向目的地的向量
2. **`normalized()`**:把向量长度变成 1,只留方向
3. **`* speed`**:方向乘以速度大小,得到 velocity
4. **`* dt`**:velocity 乘以这一帧的耗时,得到这一帧的位移
5. **`distance < epsilon`**:浮点比较用 epsilon,避免精度问题

#### Rust 实现

```rust
use glam::Vec2;

struct Player {
    pos: Vec2,
    destination: Option<Vec2>,
    speed: f32,
}

impl Player {
    fn update(&mut self, dt: f32) {
        if let Some(dest) = self.destination {
            let to_dest = dest - self.pos;
            let distance = to_dest.length();
            if distance < 1.0 {
                // 到达
                self.pos = dest;
                self.destination = None;
            } else {
                let velocity = to_dest / distance * self.speed;  // normalize + scale
                let new_pos = self.pos + velocity * dt;
                // 检查这一帧会不会"冲过"destination
                if (new_pos - self.pos).length() >= distance {
                    self.pos = dest;
                    self.destination = None;
                } else {
                    self.pos = new_pos;
                }
            }
        }
    }
}
```

注意 `(to_dest / distance)` 是手动 normalize——避免再调一次 length()。`to_dest / distance * speed` 等价于 `to_dest.normalized() * speed`。

#### "冲过 destination"保护

如果 dt 大(卡顿)或 speed 高,一帧的位移可能大于到 destination 的距离:

```
current_pos = (10.0, 10.0)
destination = (15.0, 10.0)
distance = 5.0
speed = 100.0
dt = 0.1  // 100ms 卡顿

new_pos = (10.0, 10.0) + (5.0, 0.0) * 100 * 0.1 / 5
        = (10.0, 10.0) + (10.0, 0.0)
        = (20.0, 10.0)
```

new_pos 在 destination 右边 5 像素——冲过了。如果不处理,角色会"穿过"destination 继续走,然后下一帧又被吸引回 destination,造成抖动。

解决:`if (new_pos - self.pos).length() >= distance` 检测冲过,直接 snap 到 destination。

#### 输入处理:移动中改向

```rust
fn handle_input(&mut self, input: &Input, map: &TileMap) {
    let next_tile = match input.direction {
        Some(Direction::Up)    => Some(TilePos(self.tile.x, self.tile.y - 1)),
        Some(Direction::Down)  => Some(TilePos(self.tile.x, self.tile.y + 1)),
        Some(Direction::Left)  => Some(TilePos(self.tile.x - 1, self.tile.y)),
        Some(Direction::Right) => Some(TilePos(self.tile.x + 1, self.tile.y)),
        None => None,
    };
    if let Some(t) = next_tile {
        if map.is_traversable(t) {
            // 即使正在过渡,也立即改向(覆盖旧 destination)
            self.destination = Some(tile_center(t));
        }
    }
}
```

注意:`self.tile` 是角色"当前所在"的 tile(由 world_to_tile(self.pos) 算出),不是 destination。这样:

- 角色在 (3, 3) 静止,按 D → destination = (4, 3) 中心,角色开始向右移
- 角色移动到 (3.4, 3.0)(还在过渡),按 S → 角色"当前所在" tile 还是 (3, 3),destination 改为 (3, 4) 中心
- 角色立即转向,从 (3.4, 3.0) 移到 (3.5, 3.5) 中心

这是"中途改向",玩家手感更灵敏。

### 速度模型的选择

Casey 用**恒定速度**(`speed = 4 像素/毫秒`)。变种:

1. **恒定**:简单,符合大部分类 Zelda 游戏
2. **加减速**:角色起步慢、停下慢,更真实但复杂
3. **缓动(easing)**:用 `ease_in_out` 让移动开始 / 结束慢,中间快,视觉柔和

Casey 选恒定,因为类 Zelda 不需要复杂的速度模型。如果做更精致的动画,Day 274(弹簧动画)会讲。

### "到达"检测的精度

`epsilon` 取多少?有几种考量:

- **太严(epsilon = 0.01)**:浮点误差可能让角色永远到不了
- **太松(epsilon = 5)**:角色还没到 tile 中心就停下,视觉错位
- **合理(epsilon = 0.5)**:浮点误差以内,人眼看不出 0.5 像素差异

Casey 选 `epsilon = 0.5`。但更严谨的做法是**snap to destination**:不管角色到哪,只要他"接近"了,直接 set pos = destination。这样无精度问题。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

混合移动是 2D 动作游戏的标准。变种:

- **Semi-lock movement**(早期 Zelda):方向键直接对应"想去的 tile",角色自动走过去
- **Click-to-move**(Diablo):鼠标点击 tile,角色寻路过去(中间可能有多个 tile)
- **Analog stick movement**(现代):摇杆方向决定 destination,松开摇杆角色停下
- **Grid-locked with override**(Pokemon):严格按格子,但跑步时可以"穿过"格子边缘

每种都有 trade-off。Casey 选最简单的"按键 = 想去相邻 tile",够教学用。

游戏设计上,网格移动还有几个考量:

- **"卡墙"反馈**:角色撞墙时,可以播放"撞墙音效"+ 角色精灵"撞墙姿势"
- **快速转向**:角色朝右移动时按上,角色立即朝上,没有"减速再加速"
- **过渡动画**:角色精灵的朝向应该跟着移动方向变(向右走时精灵面朝右)

### 3.2 · 🎨 图形学视角

混合移动的渲染涉及几个细节:

1. **子像素渲染**:角色精灵在浮点坐标,渲染时要四舍五入到整数像素(否则精灵抖动)
2. **朝向旋转**:如果精灵支持 8 方向,根据 velocity 选对应方向的图
3. **动画帧**:走 / 跑时精灵的腿要动,Day 273-274 讲
4. **阴影**:角色阴影可能在 tile 上(地板)或 tile 边缘(过渡),需要插值

子像素渲染有个 trick:**速度大时精灵偏移可以精确到 0.5 像素**,人眼分辨不出 0.5 像素差异,但 1 像素差异就明显。所以渲染前 `pos.x.round()` 是合理的。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上的"网格 + 过渡"思想在:

- **i3 WM 的窗口移动**:键盘按方向键,窗口在网格上移动,移动过程有 50ms 过渡动画
- **terminal 光标**:光标位置是字符网格,但闪烁 / 移动有动画
- **Vim 的 cursor 移动**:hjkl 跳字符,w 跳单词,都是离散跳

这些和 Casey 的混合移动同构:**离散目标 + 平滑过渡**。

### 3.4 · 🦀 Rust 生态视角

Rust 表达混合移动几个考量:

#### 用 Option 表达"是否有 destination"

```rust
struct Player {
    pos: Vec2,
    destination: Option<Vec2>,
}
```

`None` 表示静止,`Some(p)` 表示移动中。这是 Rust 处理"可空状态"的标准方式。

#### 用 enum 表达输入

```rust
enum Direction { Up, Down, Left, Right }

struct Input {
    direction: Option<Direction>,
    run: bool,
}
```

`Option<Direction>` 表示"无方向键按下"vs "按下了某方向"。

#### glam 的 Vec2

```rust
use glam::Vec2;

let pos = Vec2::new(10.0, 20.0);
let dest = Vec2::new(15.0, 20.0);
let to_dest = dest - pos;  // Vec2 重载了 Sub
let distance = to_dest.length();  // 长度
let dir = to_dest.normalize();  // 单位向量
```

glam 是 Bevy 用的数学库,API 简洁,SIMD 优化。Phase 6 我们可以用它。

#### 性能:缓存 length

```rust
let to_dest = dest - pos;
let distance = to_dest.length();
let dir = if distance > 0.0 { to_dest / distance } else { Vec2::ZERO };
let velocity = dir * speed;
```

不调 `normalize()` 而是手动 `to_dest / distance`,避免内部再算一次 length。glam 的 `normalize()` 其实是 `self / self.length()`,所以等价,但显式写出来更清晰。

### 3.5 · 数学:运动方程

混合移动的运动方程:

```
v(t) = speed * (dest - pos(t)).normalized()
pos(t+dt) = pos(t) + v(t) * dt
```

注意 `v(t)` 依赖 `pos(t)`,所以这是一个**反馈系统**——速度根据当前位置实时调整。

这种系统的特性:

- **渐进稳定**:pos 一定会收敛到 dest(在合理 speed / dt 下)
- **无超调**(恒定速度):角色不会冲过 dest 然后回来
- **响应即时**:改变 dest 立即改向

数学上,这等价于"在每一时刻朝目标做匀速直线运动"。和"恒定加速度 / 阻力"的物理模型不同——更"理想化"。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么混合移动比"纯自由移动"更适合类 Zelda 游戏?给出至少 3 个理由。

**参考解答**:
1. **关卡设计简化**:tile 是离散的,设计师画 tile map 即可,不需要配置每个物体的碰撞框;纯自由移动需要每个墙体配 AABB,工作量大
2. **AI 寻路简化**:tile-based A* 是标准算法,直接用;自由移动需要 navmesh 或 RVO,复杂得多
3. **战斗机制清晰**:"攻击范围 1 格"这种描述天然成立;自由移动要算"距离 < N 像素",数字不直观
4. **视觉一致**:角色永远对齐到 tile 中心,精灵图和 tile map 配合完美;自由移动可能让角色"半个身子在墙里"
5. **网络同步容易**:tile 坐标是整数,网络同步精度高;浮点位置同步有插值延迟问题
6. **保存 / 加载简单**:角色位置存 tile 即可(2 个 int),不需要存浮点

### Lv2 · 动手实践

**题**:实现一个完整的混合移动系统:

- Player 有 pos: Vec2、destination: Option<Vec2>、speed: f32
- 每帧 update(dt):朝 destination 移动,到达则 snap
- handle_input(direction):设置 destination 为相邻 tile 中心(如果 traversable)
- 渲染时画 player 精灵 + destination 高亮(如果有)

测试:

- 玩家在 (3, 3),按 D,player 应该平滑移到 (4, 3) 中心
- 移动中按 S,player 应立即改向(从当前 pos 移到 (3, 4) 中心)
- 撞墙时(destination tile 不可 traversable)player 不动

完成标准:键盘控制角色平滑移动,撞墙时停下,改向时立即响应。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self { x: self.x - o.x, y: self.y - o.y } }
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
    fn scale(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
    fn length(self) -> f32 { (self.x * self.x + self.y * self.y).sqrt() }
}

const TILE_SIZE: f32 = 32.0;

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

fn tile_center(t: TilePos) -> Vec2 {
    Vec2::new(
        (t.0 as f32 + 0.5) * TILE_SIZE,
        (t.1 as f32 + 0.5) * TILE_SIZE,
    )
}

fn world_to_tile(p: Vec2) -> TilePos {
    TilePos(
        (p.x / TILE_SIZE).floor() as i32,
        (p.y / TILE_SIZE).floor() as i32,
    )
}

#[derive(Clone, Copy, Debug)]
enum TileType { Floor, Wall }
impl TileType {
    fn is_traversable(self) -> bool { matches!(self, TileType::Floor) }
}

struct TileMap {
    width: usize,
    traversable: Vec<bool>,
}

impl TileMap {
    fn is_traversable(&self, t: TilePos) -> bool {
        if t.0 < 0 || t.1 < 0 { return false; }
        let (x, y) = (t.0 as usize, t.1 as usize);
        if x >= self.width || y >= self.traversable.len() / self.width { return false; }
        self.traversable[y * self.width + x]
    }
}

#[derive(Clone, Copy, Debug, PartialEq)]
enum Direction { Up, Down, Left, Right }

struct Player {
    pos: Vec2,
    destination: Option<Vec2>,
    speed: f32,  // pixels per second
}

impl Player {
    fn new(pos: Vec2) -> Self {
        Self { pos, destination: None, speed: 120.0 }
    }

    fn handle_input(&mut self, dir: Direction, map: &TileMap) {
        let current_tile = world_to_tile(self.pos);
        let next_tile = match dir {
            Direction::Up    => TilePos(current_tile.0, current_tile.1 - 1),
            Direction::Down  => TilePos(current_tile.0, current_tile.1 + 1),
            Direction::Left  => TilePos(current_tile.0 - 1, current_tile.1),
            Direction::Right => TilePos(current_tile.0 + 1, current_tile.1),
        };
        if map.is_traversable(next_tile) {
            self.destination = Some(tile_center(next_tile));
            println!("Set destination: tile {:?} center ({},{})", next_tile,
                     tile_center(next_tile).x, tile_center(next_tile).y);
        } else {
            println!("Blocked: tile {:?} not traversable", next_tile);
        }
    }

    fn update(&mut self, dt: f32) {
        if let Some(dest) = self.destination {
            let to_dest = dest.sub(self.pos);
            let distance = to_dest.length();

            if distance < 1.0 {
                // 到达
                self.pos = dest;
                self.destination = None;
                println!("Arrived at ({},{})", dest.x, dest.y);
                return;
            }

            // 归一化方向 * 速度
            let velocity = to_dest.scale(self.speed / distance);
            let displacement = velocity.scale(dt);
            let displacement_len = displacement.length();

            if displacement_len >= distance {
                // 这帧会冲过 destination,snap
                self.pos = dest;
                self.destination = None;
                println!("Arrived (snapped) at ({},{})", dest.x, dest.y);
            } else {
                self.pos = self.pos.add(displacement);
            }
        }
    }
}

fn main() {
    // 简单地图:5x5,全 Floor
    let map = TileMap {
        width: 5,
        traversable: vec![true; 25],
    };

    let mut player = Player::new(tile_center(TilePos(2, 2)));
    println!("Player start: ({},{})", player.pos.x, player.pos.y);

    // 按 Right
    player.handle_input(Direction::Right, &map);

    // 模拟 30 帧每帧 1/60 秒
    let dt = 1.0 / 60.0;
    for frame in 0..30 {
        player.update(dt);
        if frame % 5 == 0 {
            println!("  Frame {}: pos ({},{})",
                     frame, player.pos.x, player.pos.y);
        }
        if player.destination.is_none() {
            println!("  Stopped at frame {}", frame);
            break;
        }
    }

    // 按下(应该立即改向)
    player.handle_input(Direction::Down, &map);
    for frame in 0..30 {
        player.update(dt);
        if player.destination.is_none() {
            println!("  Stopped at frame {}", frame);
            break;
        }
    }
    println!("Final pos: ({},{})", player.pos.x, player.pos.y);
}
```

**每行解释**:
- `to_dest.scale(self.speed / distance)` 是 normalize + scale 一步完成
- `displacement_len >= distance` 是"冲过"检测,大 dt 时触发
- `world_to_tile(self.pos)` 在输入处理时算角色"当前所在 tile"——这和 destination 解耦,允许角色在过渡中改向
- 到达时用 `pos = dest` snap,避免浮点精度累积

### 完整可跑:混合移动 + tile map

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, KeyRepeat, Window, WindowOptions};

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const TILE_SIZE: f32 = 32.0;
const MAP_W: i32 = 25;
const MAP_H: i32 = 18;
const PLAYER_SPEED: f32 = 200.0;  // pixels per second
const EPSILON: f32 = 1.0;

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self { x: self.x - o.x, y: self.y - o.y } }
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
    fn scale(self, k: f32) -> Self { Self { x: self.x * k, y: self.y * k } }
    fn length(self) -> f32 { (self.x * self.x + self.y * self.y).sqrt() }
}

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

fn tile_center(t: TilePos) -> Vec2 {
    Vec2::new(
        (t.0 as f32 + 0.5) * TILE_SIZE,
        (t.1 as f32 + 0.5) * TILE_SIZE,
    )
}

fn world_to_tile(p: Vec2) -> TilePos {
    TilePos(
        (p.x / TILE_SIZE).floor() as i32,
        (p.y / TILE_SIZE).floor() as i32,
    )
}

struct TileMap {
    width: i32,
    height: i32,
    tiles: Vec<bool>,  // true = traversable
}

impl TileMap {
    fn new(width: i32, height: i32) -> Self {
        Self { width, height, tiles: vec![true; (width * height) as usize] }
    }
    fn is_traversable(&self, t: TilePos) -> bool {
        if t.0 < 0 || t.1 < 0 || t.0 >= self.width || t.1 >= self.height { return false; }
        self.tiles[(t.1 * self.width + t.0) as usize]
    }
    fn set(&mut self, t: TilePos, traversable: bool) {
        if t.0 >= 0 && t.1 >= 0 && t.0 < self.width && t.1 < self.height {
            self.tiles[(t.1 * self.width + t.0) as usize] = traversable;
        }
    }
}

#[derive(Clone, Copy, Debug, PartialEq)]
enum Direction { Up, Down, Left, Right }

struct Player {
    pos: Vec2,
    destination: Option<Vec2>,
    speed: f32,
}

impl Player {
    fn new(pos: Vec2) -> Self {
        Self { pos, destination: None, speed: PLAYER_SPEED }
    }

    fn handle_input(&mut self, dir: Direction, map: &TileMap) {
        let current_tile = world_to_tile(self.pos);
        let next_tile = match dir {
            Direction::Up    => TilePos(current_tile.0, current_tile.1 - 1),
            Direction::Down  => TilePos(current_tile.0, current_tile.1 + 1),
            Direction::Left  => TilePos(current_tile.0 - 1, current_tile.1),
            Direction::Right => TilePos(current_tile.0 + 1, current_tile.1),
        };
        if map.is_traversable(next_tile) {
            self.destination = Some(tile_center(next_tile));
        }
    }

    fn update(&mut self, dt: f32) {
        if let Some(dest) = self.destination {
            let to_dest = dest.sub(self.pos);
            let distance = to_dest.length();

            if distance < EPSILON {
                self.pos = dest;
                self.destination = None;
                return;
            }

            let velocity = to_dest.scale(self.speed / distance);
            let displacement = velocity.scale(dt);

            if displacement.length() >= distance {
                self.pos = dest;
                self.destination = None;
            } else {
                self.pos = self.pos.add(displacement);
            }
        }
    }
}

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, x: i32, y: i32, w: i32, h: i32, color: u32) {
    for py in y.max(0)..(y + h).min(buf_h as i32) {
        for px in x.max(0)..(x + w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Hybrid Movement Demo", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];

    // 构造地图:边界墙 + 中心障碍
    let mut map = TileMap::new(MAP_W, MAP_H);
    for x in 0..MAP_W {
        map.set(TilePos(x, 0), false);
        map.set(TilePos(x, MAP_H - 1), false);
    }
    for y in 0..MAP_H {
        map.set(TilePos(0, y), false);
        map.set(TilePos(MAP_W - 1, y), false);
    }
    // 几个内部墙
    for y in 5..10 {
        map.set(TilePos(10, y), false);
    }
    // 水池
    for y in 12..15 {
        for x in 15..19 {
            map.set(TilePos(x, y), false);
        }
    }

    let mut player = Player::new(tile_center(TilePos(3, 3)));
    let mut last_time = std::time::Instant::now();

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = std::time::Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32();
        last_time = now;

        // 输入
        if window.is_key_pressed(Key::W, KeyRepeat::No) {
            player.handle_input(Direction::Up, &map);
        }
        if window.is_key_pressed(Key::S, KeyRepeat::No) {
            player.handle_input(Direction::Down, &map);
        }
        if window.is_key_pressed(Key::A, KeyRepeat::No) {
            player.handle_input(Direction::Left, &map);
        }
        if window.is_key_pressed(Key::D, KeyRepeat::No) {
            player.handle_input(Direction::Right, &map);
        }

        // 更新
        player.update(dt);

        // 渲染
        for px in buffer.iter_mut() { *px = 0xFF000000; }

        // 画 tile map
        for y in 0..MAP_H {
            for x in 0..MAP_W {
                let traversable = map.is_traversable(TilePos(x, y));
                let color = if traversable { 0xFF404040 } else { 0xFF808080 };
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          x * TILE_SIZE as i32, y * TILE_SIZE as i32,
                          TILE_SIZE as i32, TILE_SIZE as i32, color);
            }
        }

        // 画 destination 高亮
        if let Some(dest) = player.destination {
            let tile = world_to_tile(dest);
            // 边框
            for offset in 0..4 {
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          tile.0 * TILE_SIZE as i32 + offset,
                          tile.1 * TILE_SIZE as i32 + offset,
                          TILE_SIZE as i32 - offset * 2, 1, 0xFFFFFF40);
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          tile.0 * TILE_SIZE as i32 + offset,
                          tile.1 * TILE_SIZE as i32 + TILE_SIZE as i32 - 1 - offset,
                          TILE_SIZE as i32 - offset * 2, 1, 0xFFFFFF40);
            }
        }

        // 画 player
        let px = player.pos.x as i32;
        let py = player.pos.y as i32;
        draw_rect(&mut buffer, WIDTH, HEIGHT, px - 8, py - 8, 16, 16, 0xFFFF4040);

        // 当前所在 tile 边框(蓝色)
        let current_tile = world_to_tile(player.pos);
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  current_tile.0 * TILE_SIZE as i32,
                  current_tile.1 * TILE_SIZE as i32,
                  TILE_SIZE as i32, 2, 0xFF4040FF);
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  current_tile.0 * TILE_SIZE as i32,
                  current_tile.1 * TILE_SIZE as i32 + TILE_SIZE as i32 - 2,
                  TILE_SIZE as i32, 2, 0xFF4040FF);

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `duration_since(last_time).as_secs_f32()` 把 Duration 转 f32 秒
- `KeyRepeat::No` 让 `is_key_pressed` 只在"刚按下"那一帧返回 true
- player.pos 是 `Vec2`(浮点),`as i32` 转 int 用于渲染
- destination 高亮用边框(画 4 条线),而不是填充,避免遮挡 player
- `current_tile` 是渲染时实时算的,基于 player.pos,显示"角色当前所在 tile"

**Troubleshooting**:
