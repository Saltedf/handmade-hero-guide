# Day 331 · 按大脑激活实体

> 游戏世界里有上万个 entity,但 99% 时间玩家只能看到附近几十个。Casey 今天实现"按 brain 类型激活/休眠 entity"——只更新玩家附近的怪物 AI,远处的怪物"睡觉"省 CPU。

## 0 · 为什么要有这一天

到目前为止你的游戏每帧遍历所有 entity 调用 `update`。如果世界有 10000 个怪物,每帧 10000 次 AI 计算,大部分浪费——玩家附近的怪物才需要"思考",远处的怪物可以"睡觉"。

业界叫这种技术 **LOD for simulation**(模拟的细节层次)或 **sleeping entities**。核心思路:

- **近处 entity**:完整 AI(寻路、攻击、躲避)
- **远处 entity**:简化 AI(只记录位置,不动)
- **超远 entity**:完全休眠(从更新列表移除)

游戏行业的标准实现:

- **玩家为中心**:玩家附近 N 米内 entity 活跃
- **相机为中心**:相机视野内 entity 活跃
- **brain 类型分级**:不同 entity 类型有不同激活半径

今天的 Casey 工作:**按 brain 类型激活**。每个 entity 有一个 "brain"(AI 类型),不同 brain 有不同的激活策略:

```
Brain::Player      → 永远激活(玩家自己)
Brain::Monster     → 玩家附近 30 米激活
Brain::Familiar    → 玩家附近 50 米激活(跟随玩家的宠物)
Brain::Quest       → 玩家附近 100 米激活(任务 NPC)
Brain::Ambient     → 永远激活(鸟、风等环境元素,但更新简单)
```

实现:每帧开始时遍历所有 entity,根据玩家位置和 brain 类型的激活半径,标记 active 或 dormant。然后只对 active entity 调用 `update`。

心理锚点:今天之后你的游戏支持大世界(几万 entity),只有附近的几十个真正"思考"。这是开放世界游戏的技术基础。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_entity.cpp` 和 `handmade_world.cpp`,实现 entity activation 系统。

具体动作:

1. 给 entity 加 `Brain` 字段(enum)
2. 给 brain 类型定义激活半径
3. 每帧开始时,遍历 entity,根据距离决定 active 或 dormant
4. dormant entity 不调用 update,但仍参与渲染

```c
typedef enum {
    Brain_Player,
    Brain_Monster,
    Brain_Familiar,
    Brain_Quest,
    Brain_Ambient,
    Brain_Count,
} brain_type;

float brain_activation_radius(brain_type brain) {
    switch (brain) {
        case Brain_Player:   return INFINITY;  // 永远激活
        case Brain_Monster:  return 30.0f;
        case Brain_Familiar: return 50.0f;
        case Brain_Quest:    return 100.0f;
        case Brain_Ambient:  return INFINITY;  // 永远(但更新简单)
    }
    return 0;
}

void update_entities(world *world, v2 player_pos, float dt) {
    for (int i = 0; i < world->entity_count; i++) {
        entity *e = &world->entities[i];
        float radius = brain_activation_radius(e->brain);
        float dist = length(e->pos - player_pos);
        bool active = dist <= radius;
        
        if (active) {
            update_entity(e, dt);  // 完整 AI
        } else {
            // dormant:不更新 AI,但仍记录时间(醒来时知道过了多久)
            e->dormant_time += dt;
        }
    }
}
```

Casey 在视频里讨论了几个细节:

1. **dormant 不渲染?**:不,仍然渲染——玩家远处能看到 entity,只是它们不动。激活只影响 AI 不影响渲染。
2. **dormant 时进入视野怎么处理**:每帧检查距离,距离变小自动激活。激活时记录 `dormant_time`,AI 可以"补"计算(比如睡眠期间饥饿值增加)。
3. **激活的副作用**:激活瞬间可能要做初始化(加载资源、播放音效),Casey 在 update 加 `is_first_update_after_dormant` 标志。

## 2 · 心智模型

### 类比:舞台剧

把游戏世界想象成舞台剧。

- **舞台中心**:玩家,聚光灯打在他身上
- **聚光灯范围**:激活的 entity,他们说话、动作
- **聚光灯外**:休眠的 entity,站在原地等

聚光灯随玩家移动,新的 entity 进入了光圈,开始动作;离开光圈的 entity 静止。观众(玩家)看不到光圈外的细节,所以节省表演资源(演员可以歇息)。

这种"聚光灯"模式是开放世界游戏的核心技术。GTA / 塞尔达 / 巫师 都用类似机制。

### 严谨原理:激活判定

每个 entity 每帧做一次距离判定:

```
distance = length(entity.pos - player.pos)
radius = brain_activation_radius(entity.brain)
is_active = distance <= radius
```

距离判定 O(1),1 万个 entity 总共 O(N) = 1 万次距离判定,几毫秒。这是性能上的"额外开销",但换来的是省下"完整 AI"的几十毫秒。

进一步优化:**空间分区**(spatial partitioning)。把世界切成网格,只检查玩家所在网格附近的 entity,避免遍历所有 entity。Day 055 的 hash-based world storage 就是这种结构。

### dormant entity 的状态

dormant entity 保留所有状态(位置、HP、装备),只是不调用 AI update。当它再次激活时:

```c
void activate_entity(entity *e) {
    e->is_active = true;
    e->dormant_time = 0;  // 重置休眠时间
    e->just_activated = true;  // AI update 检查这个 flag 做特殊处理
    
    // 可选:补足休眠期间的状态变化
    apply_dormant_effects(e);
}
```

`apply_dormant_effects` 的例子:

- 饥饿值:`hunger += dormant_time * hunger_rate`(睡眠期间继续饿)
- 体力:`stamina = max_stamina`(睡眠期间恢复)
- 位置:不动(dormant 期间位置不变)

游戏行业的术语叫 **time skip**——跳过一段时间,用公式快速算结果而不是逐步模拟。

### Rust 实现

```rust
#[derive(Clone, Copy, PartialEq, Debug)]
enum Brain {
    Player,
    Monster,
    Familiar,
    Quest,
    Ambient,
}

impl Brain {
    fn activation_radius(&self) -> f32 {
        match self {
            Self::Player   => f32::INFINITY,
            Self::Monster  => 30.0,
            Self::Familiar => 50.0,
            Self::Quest    => 100.0,
            Self::Ambient  => f32::INFINITY,
        }
    }
}

#[derive(Clone)]
struct Entity {
    pos: Vec2,
    brain: Brain,
    is_active: bool,
    dormant_time: f32,
    // ... 其他状态
}

impl Entity {
    fn check_activation(&mut self, player_pos: Vec2) {
        let radius = self.brain.activation_radius();
        let dist_sq = (self.pos - player_pos).length_squared();
        let was_active = self.is_active;
        self.is_active = dist_sq <= radius * radius;
        
        if was_active && !self.is_active {
            // 从 active → dormant
            self.dormant_time = 0.0;
        } else if !was_active && self.is_active {
            // 从 dormant → active
            self.dormant_time = 0.0;
            // 触发激活事件(可选)
        }
    }
    
    fn update(&mut self, dt: f32) {
        if !self.is_active {
            self.dormant_time += dt;
            return;
        }
        // 完整 AI 更新
        match self.brain {
            Brain::Monster => self.update_monster(dt),
            Brain::Familiar => self.update_familiar(dt),
            // ...
            _ => {}
        }
    }
}
```

`length_squared()` 比 `length()` 快(避免 sqrt),用于距离比较——半径平方后比较等价。这是 Day 047 教过的优化技巧。

### 3.1 · 🎮 游戏编程视角

主流游戏的 LOD for simulation:

- **GTA V**:城市里几百 NPC,玩家附近的 NPC 完整 AI,远处的简化
- **Skyrim**:所有 NPC 都有 schedule,玩家不在时他们的活动被简化

- **Cyberpunk 2077**:复杂的 LOD 系统,远处的车流简化

游戏行业的另一个技术是 **chunk-based loading**——世界切成块,玩家附近的块加载到内存,远处的块卸载。Minecraft / 7 Days to Die 等 voxel 游戏标配。

### 3.2 · 🐧 Linux 系统编程视角

Linux 内核的"激活"对应:

- **Swap**:不活跃的内存页换出到磁盘,活跃页留在 RAM
- **Page reclaim**:内核线程定期扫描页表,把 inactive 页标 inactive,准备换出
- **OOM killer**:内存满时杀进程,极端的"激活"决策

内核的 active/inactive list 是双向链表,类似今天的 entity active 列表。访问页时移到 active list,内核定期把 active list 尾部移到 inactive list。

```bash
# 看 Linux 的 active/inactive 内存
cat /proc/meminfo | grep -E "Active|Inactive"
# Active(memory): 1234567 kB
# Inactive(memory): 2345678 kB
```

### 3.3 · 🦀 Rust 生态视角

struct World {

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么用 `length_squared()` 比较,而不是 `length()`?

**参考解答**:

`length()` 要算 sqrt,而 `length_squared()` 只是 `(dx*dx + dy*dy)`。sqrt 慢(CPU 上的指令延迟 15-30 周期)。

距离比较时:`dist <= radius` 等价于 `dist² <= radius²`。所以可以两边平方,避免 sqrt。这是游戏编程的经典优化,Day 047 教过。

### Lv2 · 动手实践

**题**:在 Rust 里实现 entity activation 系统,要求:

- Brain 5 种,各自激活半径
- Entity 包含 pos、brain、is_active、dormant_time

**参考解答**:

```rust
#[derive(Clone, Copy, Debug, PartialEq)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn length_squared(self, other: Self) -> f32 {
        let dx = self.x - other.x;
        let dy = self.y - other.y;
        dx*dx + dy*dy
    }
}

#[derive(Clone, Copy, Debug, PartialEq)]
enum Brain { Player, Monster, Familiar, Quest, Ambient }

impl Brain {
    fn radius(self) -> f32 {
        match self {
            Self::Player   => f32::INFINITY,
            Self::Monster  => 30.0,
            Self::Familiar => 50.0,
            Self::Quest    => 100.0,
            Self::Ambient  => f32::INFINITY,
        }
    }
}

#[derive(Clone, Debug)]
struct Entity {
    pos: Vec2,
    brain: Brain,
    is_active: bool,
    dormant_time: f32,
}

impl Entity {
    fn check(&mut self, player_pos: Vec2) {
        let r = self.brain.radius();
        let dist_sq = self.pos.length_squared(player_pos);
        self.is_active = dist_sq <= r * r;
    }
}

struct World {
    entities: Vec<Entity>,
    player_pos: Vec2,
}

impl World {
    fn update(&mut self, dt: f32) {
        for e in &mut self.entities {
            e.check(self.player_pos);
        }
        for e in &mut self.entities {
            if e.is_active {
                e.dormant_time = 0.0;
                // 模拟 AI update
            } else {
                e.dormant_time += dt;
            }
        }
    }
    
    fn active_count(&self) -> usize {
        self.entities.iter().filter(|e| e.is_active).count()
    }
}

fn main() {
    let mut world = World {
        entities: vec![
            Entity { pos: Vec2 { x: 0.0, y: 0.0 },   brain: Brain::Player,   is_active: true, dormant_time: 0.0 },
            Entity { pos: Vec2 { x: 10.0, y: 0.0 },  brain: Brain::Monster,  is_active: false, dormant_time: 0.0 },
            Entity { pos: Vec2 { x: 100.0, y: 0.0 }, brain: Brain::Monster,  is_active: false, dormant_time: 0.0 },
            Entity { pos: Vec2 { x: 40.0, y: 0.0 },  brain: Brain::Familiar, is_active: false, dormant_time: 0.0 },
            Entity { pos: Vec2 { x: 200.0, y: 0.0 }, brain: Brain::Quest,    is_active: false, dormant_time: 0.0 },
        ],
        player_pos: Vec2 { x: 0.0, y: 0.0 },
    };
    
    world.update(0.016);
    println!("Player at origin: {} active", world.active_count());
    
    // 玩家移动
    world.player_pos = Vec2 { x: 100.0, y: 0.0 };
    world.update(0.016);
    println!("Player at (100, 0): {} active", world.active_count());
}
```

### Rust:entity activation 系统(完整可跑)

impl Vec2 {
    fn length_squared(self, other: Self) -> f32 {
        let dx = self.x - other.x;
        let dy = self.y - other.y;
        dx*dx + dy*dy
    }
}

#[derive(Clone, Copy, Debug, PartialEq)]
enum Brain {
    Player,
    Monster,
    Familiar,
    Quest,
    Ambient,
}

impl Brain {
    fn activation_radius(self) -> f32 {
        match self {
            Self::Player   => f32::INFINITY,
            Self::Monster  => 30.0,
            Self::Familiar => 50.0,
            Self::Quest    => 100.0,
            Self::Ambient  => f32::INFINITY,
        }
    }
    
    fn name(self) -> &'static str {
        match self {
            Self::Player   => "Player",
            Self::Monster  => "Monster",
            Self::Familiar => "Familiar",
            Self::Quest    => "Quest",
            Self::Ambient  => "Ambient",
        }
    }
}

#[derive(Clone, Debug)]
struct Entity {
    pos: Vec2,
    brain: Brain,
    is_active: bool,
    dormant_time: f32,
    name: &'static str,
}

    fn check_activation(&mut self, player_pos: Vec2) {
        let r = self.brain.activation_radius();
        let dist_sq = self.pos.length_squared(player_pos);
        let was_active = self.is_active;
        self.is_active = if r.is_infinite() { true }
                         else { dist_sq <= r * r };
        
        if was_active && !self.is_active {
            println!("  [{}] {} went dormant", self.brain.name(), self.name);

        if !self.is_active {
            self.dormant_time += dt;
            return;
        }
        // 模拟 AI(这里只是更新 dormant_time 表示"刚激活")
        if self.dormant_time > 0.0 {
            println!("  [{}] {} woke up after {:.1}s dormant",
                     self.brain.name(), self.name, self.dormant_time);
            self.dormant_time = 0.0;
        }
    }
}

            Entity { pos: Vec2 { x: 50.0, y: 0.0 },  brain: Brain::Quest,    is_active: false, dormant_time: 0.0, name: "Merchant" },
            Entity { pos: Vec2 { x: 200.0, y: 0.0 }, brain: Brain::Quest,    is_active: false, dormant_time: 0.0, name: "King" },
            Entity { pos: Vec2 { x: 10.0, y: 100.0 },brain: Brain::Ambient,  is_active: true,  dormant_time: 0.0, name: "Bird1" },
        ];
        Self {
            entities,
            player_pos: Vec2 { x: 0.0, y: 0.0 },
            time: 0.0,
        }
    }
    
    fn step(&mut self, dt: f32) {
        self.time += dt;
        for e in &mut self.entities {
            e.check_activation(self.player_pos);
        }
        for e in &mut self.entities {
            e.update(dt);
        }
    }
    
    fn active_count(&self) -> usize {
        self.entities.iter().filter(|e| e.is_active).count()
    }
    
    fn report(&self) {
        let active = self.active_count();
        let total = self.entities.len();
        println!("[t={:6.2}] player=({:5.1},{:5.1}) active={}/{} ({:.0}%)",
                 self.time, self.player_pos.x, self.player_pos.y,
                 active, total, 100.0 * active as f32 / total as f32);
    }
}

fn main() {
    println!("=== Day 331: 按 brain 激活 entity ===\n");
    
    let mut world = World::new();
    
    // 初始激活
    world.step(0.0);
    world.report();
    
    // 玩家向东走
    for step in 1..=10 {
        world.player_pos.x += 15.0;
        world.step(0.5);  // 每步 0.5 秒
        world.report();
    }
    
    // 玩家回头
    println!("\n--- 玩家回头 ---\n");
    for step in 1..=10 {
        world.player_pos.x -= 15.0;
        world.step(0.5);
        world.report();
    }
}

## 10 · 深度补充:工程视角

Entity activation 的高级优化:今天的实现 O(N) 遍历所有 entity 检查距离。10 万 entity 时性能瓶颈。优化:空间分区(grid / quadtree / BVH),只检查玩家附近网格的 entity,降到 O(K) K=附近 entity 数。Minecraft 的 chunk 系统就是这种思路——只加载玩家附近 16x16 的方块。Bevy ECS 的 spatial query 也支持。
