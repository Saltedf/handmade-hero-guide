
# Day 398 · 把光照应用回深度剥离

> V-cycle 算出体素光照,Day 396 把它采样到屏幕(单层)。但 Casey 用了深度剥离渲染半透明物体,有 K 层!每层都需要**单独应用光照**,然后按 alpha 合成。今天 Casey 写**逐层光照 + 合成** pass,让半透明物体(玻璃、水)也有正确的 GI。

## 0 · 为什么要有这一天

普通 GI 渲染只算**最近一层**(G-buffer 的 layer 0)。但 Casey 的深度剥离有 K 层(典型 2-4 层),每层是不同深度的几何。

**举例**:一面玻璃窗 + 玻璃后面的物体。

- Layer 0:玻璃前表面(法线朝相机)
- Layer 1:玻璃后表面(法线朝远处)
- Layer 2:玻璃后面的物体(墙)

每层都需要 GI——玻璃前表面接收环境光(可能很亮,因为玻璃透光),玻璃后表面较暗,后面的物体被玻璃部分遮挡。

**简单做法**(Day 396):只对 layer 0 算 GI。结果:玻璃看起来"贴"在屏幕上,没有立体感。

**正确做法**(今天):每层独立算 GI,然后按 alpha 合成。结果:玻璃真的"透"——你能看到玻璃后面的物体**带着它们各自的 GI**。

**工程挑战**:

1. **多层 G-buffer**:每层都有 position / normal / albedo,数据量 × K
2. **多层 GI 采样**:fragment shader 对每层采样 3D 纹理(增加计算)
3. **多层合成**:每层算完 Phong + GI,然后按 over operator 合成

**今天的产出**:玻璃 + 玻璃后面的物体都有正确 GI,合成顺序正确。这是 Day 381 深度剥离的**完整闭环**——GI 现在能正确处理半透明。

心理锚点:看完今天,你能(1)对每层独立算光照;(2)按 over 合成多层;(3)理解半透明 GI 的难点;(4)调试多层光照。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 流程:

1. **回顾 Day 396**:GI 采样只对 layer 0,半透明物体不正确。
2. **设计**:每层独立 Phong + GI + 合成。
3. **算法**:
   - For each layer k = K-1 downto 0:
     - 采样 voxel_light[layer k 的 position]
     - 计算 Phong + GI for layer k
     - Over 合成到 result
4. **GLSL 实现**:fragment shader 用 loop 遍历 layer
5. **性能**:K=2 时性能可接受(2x fragment shader 工作)
6. **debug**:每层独立显示,验证

这集是**深度剥离 + 光照的最终合成**——前面 17 集的工作汇总到这一步。

## 2 · 心智模型

### 类比:多层贴纸

想象你做一张照片,用多层贴纸叠出来:

- 底层(背景):天空
- 中层:山
- 上层:树

每层都是**完整的画面**(有自己的颜色、阴影、光照)。叠在一起时,**上层**的颜色混合到下层(透明部分让下层透出)。

正确做法:**每层独立算光照**,然后按 alpha 叠加。错误做法:**所有层一起算光照**(模糊),失去层次感。

### 严谨原理:逐层光照 + 合成

```
For k = K-1 downto 0:
    layer_k_lit = phong(layer_k.position, layer_k.normal, ...) + gi(layer_k.position)
    if k == K-1:
        result = layer_k_lit
    else:
        result = over(layer_k_lit, result)  # layer_k 在 result 之上
```

**关键**:

- **顺序**:从最远(K-1)开始,最近(0)最后
- **Over operator**:`over(top, bot) = top * top.a + bot * (1 - top.a)`
- **每层 GI 独立**:每层采样 voxel_light 在该层 position 处的值

### GLSL 实现

```glsl
#version 330

in vec2 v_uv;

// K 层 G-buffer
uniform sampler2D position_tex[K];
uniform sampler2D normal_tex[K];
uniform sampler2D albedo_tex[K];
uniform sampler2D alpha_tex[K];  // 每层的 alpha

// Voxel GI
uniform sampler3D voxel_light;
uniform vec3 grid_min;
uniform vec3 grid_extent;

// Phong 光源
uniform vec3 light_dir;
uniform vec3 light_color;
uniform vec3 camera_pos;
uniform vec3 specular_color;
uniform float shininess;
uniform vec3 ambient_color;

out vec4 frag;

vec3 compute_layer_color(int k) {
    vec3 position = texture(position_tex[k], v_uv).rgb;
    vec3 normal = normalize(texture(normal_tex[k], v_uv).rgb);
    vec3 albedo = texture(albedo_tex[k], v_uv).rgb;
    float alpha = texture(alpha_tex[k], v_uv).r;

    if (alpha < 0.01) discard;  // 该层此像素无几何

    // Phong
    vec3 L = normalize(light_dir);
    vec3 V = normalize(camera_pos - position);
    vec3 R = reflect(-L, normal);
    float diff = max(0.0, dot(normal, L));
    float spec = pow(max(0.0, dot(R, V)), shininess);
    vec3 ambient = albedo * ambient_color;
    vec3 diffuse = albedo * light_color * diff;
    vec3 specular = specular_color * light_color * spec;
    vec3 phong = ambient + diffuse + specular;

    // GI
    vec3 uvw = clamp((position - grid_min) / grid_extent, 0.0, 1.0);
    vec3 gi_light = texture(voxel_light, uvw).rgb;
    vec3 gi = albedo * gi_light;

    return phong + gi;
}

void main() {
    // 从最远层开始
    vec3 color = compute_layer_color(K - 1);
    float alpha = texture(alpha_tex[K - 1], v_uv).r;
    vec4 result = vec4(color * alpha, alpha);  // premultiplied

    // 逐层 over
    for (int k = K - 2; k >= 0; --k) {
        vec3 layer_color = compute_layer_color(k);
        float layer_alpha = texture(alpha_tex[k], v_uv).r;
        // over(premul): top.rgb + bot.rgb * (1 - top.a)
        result.rgb = layer_color * layer_alpha + result.rgb * (1.0 - layer_alpha);
        result.a = layer_alpha + result.a * (1.0 - layer_alpha);
    }

    // Tone map + sRGB
    vec3 final = result.rgb / max(result.a, 0.001);  // un-premul
    final = final / (final + vec3(1.0));
    frag = vec4(final, 1.0);
}
```

**每段**:

- 数组 uniform `position_tex[K]` — 多层 G-buffer
- `compute_layer_color(k)` — 对层 k 算 Phong + GI
- 循环 from K-1 downto 0 — 从远到近(正确 over 顺序)
- premultiplied alpha — 简化 over 公式
- 最后 un-premul + tone map + 输出

### 多层 GI 采样的性能

K 层 × GI 采样 = K 次 3D 纹理采样。3D 纹理采样有成本(~几十纳秒),K=4 时 4x4 = 几百纳秒 / 像素。1080p × 60 fps = 几亿次/秒,GPU 几 TFLOPS 可以。

**优化**:

- **早 exit**:`if (alpha < 0.01) break;` 跳过透明层
- **批量采样**:K 层 position 一起算 uvw,K 次 texture()
- **mipmap**:远处用低 LOD(自动)

### 合成的边缘情况

**全部层都透明**(`all layer alphas < 0.01`):result 是 (0, 0, 0, 0),显示背景。OK。

**K 层全不透明**:`over` 公式 degenerate 到 `result = layer_0_color`。OK。

**中间层透明**:over 正确混合。OK。

**alpha 累积**:多层层叠时,result.a 是"多少被覆盖"。背景(0) → 不透明层(1)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业界多层光照:

- **Forward+**:光源 culling 后,每像素只算覆盖该像素的光源
- **Deferred**:G-buffer 单层,半透明物体单独 forward pass
- **Decals**: decals 是"特殊半透明层",有自己的 GI 计算

Casey 的多层 GI 是教学示例,工业界简化为"opaque GI + transparent overlay"。

### 3.2 · 🎨 图形学视角

**K-buffer**(K-buffer):多层 G-buffer,但实现复杂。

**Per-pixel linked list**(A-buffer):每像素存 fragment 链表,层数无限。但 GPU 实现复杂(SSBO + atomic),性能不稳定。

**Stochastic K**:每像素随机选 K 层,跨帧累积(TAA 友好)。

### 3.4 · 🦀 Rust 生态视角

Rust 端处理多层:

```rust
pub struct MultiLayerGBuffer {
    pub layers: Vec<GBufferLayer>,  // K 层
}

pub struct GBufferLayer {
    pub position: Vec<Vec3>,
    pub normal: Vec<Vec3>,
    pub albedo: Vec<Vec3>,
    pub alpha: Vec<f32>,
}

pub fn apply_lighting_to_layers(
    gbuffer: &MultiLayerGBuffer,
    voxel_light: &VoxelGrid,
    light: &DirectionalLight,
    camera_pos: Vec3,
) -> Vec<[f32; 4]> {
    let pixel_count = gbuffer.layers[0].position.len();
    let mut result = vec![[0.0; 4]; pixel_count];

    for px in 0..pixel_count {
        // 从远到近(K-1 downto 0)
        let mut accumulated = [0.0f32; 4];  // premultiplied
        for k in (0..gbuffer.layers.len()).rev() {
            let layer = &gbuffer.layers[k];
            let alpha = layer.alpha[px];
            if alpha < 0.01 { continue; }

            let pos = layer.position[px];
            let nrm = layer.normal[px];
            let alb = layer.albedo[px];

            // Phong
            let phong = compute_phong(pos, nrm, alb, light, camera_pos);
            // GI
            let gi = sample_voxel_light(voxel_light, pos);
            let color = phong + gi * alb;

            // over
            accumulated[0] = color.x * alpha + accumulated[0] * (1.0 - alpha);
            accumulated[1] = color.y * alpha + accumulated[1] * (1.0 - alpha);
            accumulated[2] = color.z * alpha + accumulated[2] * (1.0 - alpha);
            accumulated[3] = alpha + accumulated[3] * (1.0 - alpha);
        }
        result[px] = accumulated;
    }

    result
}

fn compute_phong(pos: Vec3, nrm: Vec3, alb: Vec3, light: &DirectionalLight, camera: Vec3) -> Vec3 {
    let n = nrm.normalize();
    let l = light.direction.normalize();
    let v = (camera - pos).normalize();
    let r = 2.0 * n.dot(l) * n - l;
    let diff = n.dot(l).max(0.0);
    let spec = r.dot(v).max(0.0).powf(32.0);
    alb * light.color * diff + Vec3::ONE * light.color * spec + alb * 0.1
}

fn sample_voxel_light(grid: &VoxelGrid, pos: Vec3) -> Vec3 {
    let rel = (pos - grid.origin) / grid.voxel_size;
    if rel.x < 0.0 || rel.y < 0.0 || rel.z < 0.0 { return Vec3::ZERO; }
    let x = rel.x as usize;
    let y = rel.y as usize;
    let z = rel.z as usize;
    if x >= grid.dims.0 as usize || y >= grid.dims.1 as usize || z >= grid.dims.2 as usize {
        return Vec3::ZERO;
    }
    let idx = z * (grid.dims.0 * grid.dims.1) as usize + y * grid.dims.0 as usize + x;
    Vec3::new(
        grid.voxels[idx].albedo[0],
        grid.voxels[idx].albedo[1],
        grid.voxels[idx].albedo[2],
    )
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 per-layer GI 比 single-layer GI 准确?给一个具体场景。

**参考解答**:

具体场景:**玻璃球放在地板上,光从上方照下来**。

- **Single-layer GI**:只算最近一层(玻璃球前表面),GI 来自玻璃球前的体素(可能很亮,因为玻璃透光)。地板被忽略。
- **Per-layer GI**:玻璃球前表面 GI 来自前方的体素(亮),玻璃球后表面 GI 来自后方的体素(暗,被玻璃挡),地板 GI 来自地板附近的体素(中等)。

per-layer 的合成结果:玻璃前亮、玻璃后暗、地板中等,层次分明。single-layer 看起来是"平面",失去层次。

### Lv2 · 动手实践

**题**:在 Day 396 单层 GI 基础上,扩展为 2 层(K=2)。给玻璃(透明)和地板(不透明)分别算 GI,然后 over 合成。

完成标准:玻璃看起来透明,后面地板的 GI 可见。

**参考解答**:

```glsl
#version 330
in vec2 v_uv;

uniform sampler2D position_tex0;  // 玻璃前表面
uniform sampler2D normal_tex0;
uniform sampler2D albedo_tex0;
uniform sampler2D alpha_tex0;
uniform sampler2D position_tex1;  // 地板
uniform sampler2D normal_tex1;
uniform sampler2D albedo_tex1;
uniform sampler2D alpha_tex1;

uniform sampler3D voxel_light;
uniform vec3 grid_min;
uniform vec3 grid_extent;
uniform vec3 light_dir, light_color, camera_pos;
uniform vec3 specular_color;
uniform float shininess;
uniform vec3 ambient_color;

out vec4 frag;

vec3 shade_layer(vec3 position, vec3 normal, vec3 albedo) {
    vec3 N = normalize(normal);
    vec3 L = normalize(light_dir);
    vec3 V = normalize(camera_pos - position);
    vec3 R = reflect(-L, N);
    float diff = max(0.0, dot(N, L));
    float spec = pow(max(0.0, dot(R, V)), shininess);
    vec3 phong = albedo * ambient_color + albedo * light_color * diff
               + specular_color * light_color * spec;
    vec3 uvw = clamp((position - grid_min) / grid_extent, 0.0, 1.0);
    vec3 gi = albedo * texture(voxel_light, uvw).rgb;
    return phong + gi;
}

void main() {
    // Layer 1(地板,远)
    vec3 pos1 = texture(position_tex1, v_uv).rgb;
    vec3 nrm1 = texture(normal_tex1, v_uv).rgb;
    vec3 alb1 = texture(albedo_tex1, v_uv).rgb;
    float a1 = texture(alpha_tex1, v_uv).r;
    vec3 color1 = a1 > 0.01 ? shade_layer(pos1, nrm1, alb1) : vec3(0.0);

    // Layer 0(玻璃,近)
    vec3 pos0 = texture(position_tex0, v_uv).rgb;
    vec3 nrm0 = texture(normal_tex0, v_uv).rgb;
    vec3 alb0 = texture(albedo_tex0, v_uv).rgb;
    float a0 = texture(alpha_tex0, v_uv).r;
    vec3 color0 = a0 > 0.01 ? shade_layer(pos0, nrm0, alb0) : vec3(0.0);

    // Over:a0 over a1
    vec3 final_color = color0 * a0 + color1 * a1 * (1.0 - a0);
    float final_a = a0 + a1 * (1.0 - a0);

    if (final_a > 0.01) final_color /= final_a;  // un-premul
    final_color = final_color / (final_color + vec3(1.0));
    frag = vec4(final_color, 1.0);
}
```

### CPU 多层光照应用

```toml

[dependencies]
```

```rust
use glam::Vec3;

#[derive(Clone)]
pub struct Layer {
    pub positions: Vec<Vec3>,
    pub normals: Vec<Vec3>,
    pub albedos: Vec<Vec3>,
    pub alphas: Vec<f32>,
}

pub struct VoxelGrid {
    pub dims: (u32, u32, u32),
    pub voxel_size: f32,
    pub origin: Vec3,
    pub light: Vec<[f32; 3]>,
}

impl VoxelGrid {
    pub fn sample(&self, pos: Vec3) -> Vec3 {
        let rel = (pos - self.origin) / self.voxel_size;
        if rel.x < 0.0 || rel.y < 0.0 || rel.z < 0.0 { return Vec3::ZERO; }
        let x = rel.x as u32;
        let y = rel.y as u32;
        let z = rel.z as u32;
        if x >= self.dims.0 || y >= self.dims.1 || z >= self.dims.2 { return Vec3::ZERO; }
        let idx = (z * self.dims.0 * self.dims.1 + y * self.dims.0 + x) as usize;
        Vec3::from(self.light[idx])
    }
}

pub fn shade_layer(
    pos: Vec3, nrm: Vec3, alb: Vec3,
    light_dir: Vec3, light_color: Vec3, camera_pos: Vec3,
    grid: &VoxelGrid,
) -> Vec3 {
    let n = nrm.normalize();
    let l = light_dir.normalize();
    let v = (camera_pos - pos).normalize();
    let r = 2.0 * n.dot(l) * n - l;
    let diff = n.dot(l).max(0.0);
    let spec = r.dot(v).max(0.0).powf(32.0);
    let phong = alb * 0.1 + alb * light_color * diff + light_color * spec;
    let gi = alb * grid.sample(pos);
    phong + gi
}

pub fn apply_multilayer_lighting(
    layers: &[Layer],
    grid: &VoxelGrid,
    light_dir: Vec3,
    light_color: Vec3,
    camera_pos: Vec3,
) -> Vec<[f32; 4]> {
    let px_count = layers[0].positions.len();
    let mut result = vec![[0.0f32; 4]; px_count];

    for px in 0..px_count {
        let mut acc_rgb = Vec3::ZERO;
        let mut acc_a = 0.0;

        for k in (0..layers.len()).rev() {
            let layer = &layers[k];
            let alpha = layer.alphas[px];
            if alpha < 0.01 { continue; }
            let color = shade_layer(
                layer.positions[px], layer.normals[px], layer.albedos[px],
                light_dir, light_color, camera_pos, grid,
            );
            acc_rgb = color * alpha + acc_rgb * (1.0 - alpha);
            acc_a = alpha + acc_a * (1.0 - alpha);
        }

        let final_rgb = if acc_a > 0.01 { acc_rgb / acc_a } else { Vec3::ZERO };
        result[px] = [final_rgb.x, final_rgb.y, final_rgb.z, acc_a];
    }

    result
}

fn main() {
    let px_count = 10;
    let mut layers = vec![
        Layer {  // 玻璃(近)
            positions: vec![Vec3::new(0.0, 0.0, 1.0); px_count],
            normals: vec![Vec3::new(0.0, 0.0, 1.0); px_count],
            albedos: vec![Vec3::new(0.5, 0.5, 0.5); px_count],
            alphas: vec![0.4; px_count],
        },
        Layer {  // 地板(远)
            positions: vec![Vec3::new(0.0, -1.0, 2.0); px_count],
            normals: vec![Vec3::new(0.0, 1.0, 0.0); px_count],
            albedos: vec![Vec3::new(0.8, 0.5, 0.3); px_count],
            alphas: vec![1.0; px_count],
        },
    ];

    let mut grid = VoxelGrid {
        dims: (16, 16, 16),
        voxel_size: 0.2,
        origin: Vec3::new(-1.6, -1.6, -1.6),
        light: vec![[0.0; 3]; 16 * 16 * 16],
    };
    // 简化:填充一些光照
    for v in &mut grid.light {
        v[0] = 0.3; v[1] = 0.3; v[2] = 0.5;
    }

    let result = apply_multilayer_lighting(
        &layers, &grid,
        Vec3::new(1.0, 1.0, 1.0),
        Vec3::new(1.0, 1.0, 1.0),
        Vec3::new(0.0, 0.0, 3.0),
    );

    for (i, r) in result.iter().take(3).enumerate() {
        println!("Pixel {}: rgb=({}, {}, {}), a={}",
            i, r[0], r[1], r[2], r[3]);
    }
}
```

### 深度推导:本日相关数学与算法

要真正掌握今天的内容,我们必须把背后的数学推导展开。这一节是"为什么这么做"的论证。

**算法复杂度的精确分析**。今天的代码涉及到对实体集合排序,基准复杂度:

- 最优比较排序下界:O(N log N)(决策树理论)
- Rust `sort_by`:TimSort,平均 O(N log N),最好 O(N)(已部分有序时)
- 拓扑排序:O(V + E),V 是节点数,E 是边数
- Radix sort:O(N × k),k 是 sort key 位数——非比较排序,可突破 O(N log N)

对一个 1000 sprite 的场景,TimSort 大约 10000 次比较,每次比较 5-10 个 cycle(分支少),总 50000-100000 cycle = 20-40 μs。在 60 FPS(16666 μs 预算)占 0.2%——可忽略。100K sprite 时升到 2 ms,开始有压力。Minecraft 这种规模的游戏必须用 radix sort 或 GPU sort。

**内存访问模式**。sort 是**非线性内存访问**的典型——每次比较都可能跳到 Vec 不同位置。CPU prefetcher 抓不到模式,cache miss 频繁。优化:

1. **Sort by index**:先 sort indices(u32 数组,4 字节/项,cache 友好),再 reorder 数据。indices 1000 个 = 4 KB,L1 cache 装得下。
2. **Batch reorder**:indices 排好后,顺序遍历 indices,顺序访问原数据(虽然是间接但 prefetcher 跟得上)。

```rust
let mut indices: Vec<u32> = (0..entities.len() as u32).collect();
indices.sort_by(|&a, &b| sort_rule(&entities[a as usize], &entities[b as usize]));
let sorted: Vec<&Entity> = indices.iter().map(|&i| &entities[i as usize]).collect();
```

100K sprite 的 sort 用这个技巧能加速 30%。

**位运算打包 sort key**。今天 sort_key 是 u64,可以塞进多个字段:

```
bits 63-56: layer (8 bits, 256 layers)
bits 55-40: bottom_y (16 bits, 65536 levels)
bits 39-24: x (16 bits)
bits 23-8: sub_layer (16 bits)
bits 7-0: spawn_id (8 bits, 256 entries per slot)
```

打包:`key = (layer << 56) | (bottom_y << 40) | (x << 24) | (sub << 8) | spawn`。一次 u64 比较,无分支,Rust `sort_by_key` 自动 inline。

**部分序的图论模型**。Day 304 会用拓扑排序处理真正的部分序。每个 sprite 是图节点,如果 A 应该在 B 前面,加边 A→B。拓扑排序给出节点的合法顺序(满足所有约束)。

拓扑排序算法:

1. **Kahn 算法**:每次找入度为 0 的节点,加入结果,删掉它的出边,重复。
2. **DFS 后序**:DFS 遍历,记录后序(post-order),反转得到拓扑序。

如果图有环(循环依赖),拓扑排序失败——意味着 sprite 排序无解,必须**人为拆解**(切开某个 sprite)。

**浮点数的稳定性**。Rust 的 `f32::partial_cmp` 处理 NaN 返回 `None`,sort 会 panic。所以游戏代码里要么保证所有 f32 都不是 NaN(数学保证),要么 `partial_cmp(...).unwrap_or(Equal)`(默认相等)。今天 sort_rule 用后者。

更稳妥的方法:**所有位置用整数**(像素单位)。`pos_y: i32` 没有 NaN 问题,比较无分支。但缩放和旋转要用浮点,所以游戏用 i32 + f32 混合。

### 真实代码片段

Casey 在 HH 视频里实际写的代码风格(简化伪代码):

```c
internal int32
SortRule(entity *A, entity *B)
{
    int32 Result = 0;

    // Layer 比较
    if (A->Layer != B->Layer) {
        Result = (int32)A->Layer - (int32)B->Layer;
    } else {
        // Bounds overlap 检查
        rectangle2 BoundsA = GetEntityBounds(A);
        rectangle2 BoundsB = GetEntityBounds(B);
        if (RectanglesOverlap(BoundsA, BoundsB)) {
            // Bottom y 比较
            real32 BottomA = BoundsA.Max.Y;
            real32 BottomB = BoundsB.Max.Y;
            if (BottomA != BottomB) {
                Result = (BottomA < BottomB) ? -1 : 1;
            } else {
                // x 比较
                Result = SignOf32(A->P.X - B->P.X);
            }
        } else {
            // 不重叠:任意顺序
            Result = A->SpawnID - B->SpawnID;
        }
    }

    return Result;
}
```

注意 Casey 的 C 风格:

- 直接返回 int32(而非 enum Ordering)
- 用 `SignOf32`(返回 -1/0/1)简化比较
- if-else 链而非 Rust 的 `then_with`

Rust 等价:

```rust
fn sort_rule(a: &Entity, b: &Entity) -> Ordering {
    a.layer.cmp(&b.layer)
        .then_with(|| {
            if bounds_overlap(a, b) {
                let ba = bounds(a).max.y;
                let bb = bounds(b).max.y;
                ba.partial_cmp(&bb).unwrap_or(Ordering::Equal)
                    .then(a.pos.x.partial_cmp(&b.pos.x).unwrap_or(Ordering::Equal))
            } else {
                a.spawn_id.cmp(&b.spawn_id)
            }
        })
}
```

### 跨学科联结:从游戏到数据库

sort_rule 的本质是"复杂比较函数",这在很多领域都出现:

- **数据库 ORDER BY**:SQL 的 `ORDER BY layer, y, x` 是同样的 multi-key sort,但 SQL 是声明式(数据库优化器选 sort 算法),Casey 是命令式(手写 sort_by)。
- **React diff**:React 用 sort + key 比较 virtual DOM,决定哪些 component 重渲染。Multi-key sort 决定 diff 顺序。
- **Linux kernel CFS**(Completely Fair Scheduler):按 vruntime 排序进程,选最小 vruntime 的运行。本质是 sort_rule。
- **Git log --sort**:Git commit 按 committer date + author date + subject 排序。

Casey 在 HH 反复说"很多算法本质相同,只是命名不同"。掌握一个领域的 sort_rule,就掌握所有领域。
