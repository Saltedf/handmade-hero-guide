# Day 400 · 加环境光遮蔽 pass

> HH Day 400 是个里程碑——Casey 在多网格 GI 之上加 **Ambient Occlusion(AO)**。AO 让**角落和缝隙**暗化,这是真实世界"看不到天空"的位置该有的样子。没有 AO 的画面看起来"漂浮",加了 AO 立体感强。

## 0 · 为什么要有这一天

到 Day 399 为止,Casey 的渲染管线有:

- ✅ 深度剥离(半透明物体)
- ✅ Phong 光照(Lambert + specular)
- ✅ 多网格 GI(间接光)
- ✅ 多层 GI 应用

但有个**视觉问题**:角落和开阔地**一样亮**。真实世界里,角落应该暗(因为被周围物体挡住天空散射光),但简单 ambient 是均匀的,角落没暗化。

**Ambient Occlusion(AO)** 解决这个:

- **定义**:某点的 AO = 该点被周围几何"遮挡"的程度(0=完全遮挡,1=完全暴露)
- **效果**:角落 AO 低(暗),开阔地 AO 高(亮)
- **应用**:`final_light = (ambient + diffuse + specular + gi) × ao`

**AO 的物理对应**:想象你站在场景某点,抬头看天空。你能看到的"天空"比例就是 ambient 到达你的比例。在角落,周围墙挡住大半天空,AO 低;在开阔地,天空全可见,AO 高。

**AO 的算法分类**:

- **Precomputed AO**:离线烘焙到 lightmap,质量高但不动态
- **SSAO**(Screen Space AO):屏幕空间算法,基于 G-buffer,实时但只看到屏幕内几何
- **Ray-traced AO**:发射射线探测遮挡,RTX 支持,质量最高
- **Voxel-based AO**:从体素网格算,Casey 用这个

**Casey 的方案**:**Voxel-based AO**——从 Day 393 体素网格发射射线,统计被遮挡的比例。

**算法**:

1. 每个有几何的体素,从体素位置发射 N 条随机方向射线
2. 每条射线在体素网格里步进,如果撞到非空体素 → 被遮挡
3. AO = 未被遮挡的射线比例 / N

**性能**:64³ 体素 × N=16 射线 × 平均 10 步 = 100M 操作 / 帧。GPU compute shader 几毫秒。

**今天的产出**:画面有 AO——角落变暗,物体看起来"扎根"在地面上,不再漂浮。

心理锚点:看完今天,你能(1)解释 AO 的物理意义;(2)实现 voxel-based raycasting AO;(3)把 AO 应用到 Phong + GI 的结果;(4)调试 AO 的参数(射线数、最大距离)。

## 2 · 心智模型

### 类比:森林里的树荫

想象你站在森林里:

- **开阔地**:头顶全开,阳光直射,**亮**
- **大树下**:头顶有树叶挡,光散射,**中**
- **灌木丛下**:四周都挡,**很暗**

AO 衡量"头顶开敞程度"。在 3D 渲染里,不光头顶,四面八方都考虑——**球面积分**,"能看到天空"的立体角比例。

**AO 的物理**:`AO(x) = (1 / π) ∫ Ω V(x, ω) (n · ω) dω`,其中 Ω 是上半球,V 是可见性(0/1),n 是法线。

**简化**:发射 N 条射线代替积分。射线被挡 = V=0,否则 V=1。AO = 平均 V。

### 严谨原理:Raycasting AO

```rust
pub fn compute_ao(
    voxel_grid: &VoxelGrid,
    position: Vec3,
    normal: Vec3,
    ray_count: usize,
    max_distance: f32,
) -> f32 {
    let mut visible_count = 0;

    for i in 0..ray_count {
        // 随机方向(半球,围绕 normal)
        let ray_dir = random_hemisphere_direction(normal, i);

        // 在体素网格里步进,检测碰撞
        if !ray_hits_voxel(voxel_grid, position, ray_dir, max_distance) {
            visible_count += 1;
        }
    }

    visible_count as f32 / ray_count as f32
}
```

### DDA(Digital Differential Analyzer)射线步进

DDA 是经典的射线-网格相交算法。**3D DDA**(Amanatides & Woo, 1987)高效遍历射线穿过的体素:

```rust
pub fn ray_hits_voxel(
    grid: &VoxelGrid,
    origin: Vec3,
    dir: Vec3,
    max_distance: f32,
) -> bool {
    let dir = dir.normalize();

    // 转换到体素坐标
    let mut voxel = ((origin - grid.origin) / grid.voxel_size).floor();

    // 步进方向
    let step_x = if dir.x > 0.0 { 1 } else { -1 };
    let step_y = if dir.y > 0.0 { 1 } else { -1 };
    let step_z = if dir.z > 0.0 { 1 } else { -1 };

    // 到下一个体素边界的 t 参数
    let mut t_max_x = if dir.x != 0.0 {
        let next_x = if step_x > 0 { voxel.x.floor() + 1.0 } else { voxel.x.floor() };
        ((next_x - (origin.x - grid.origin.x) / grid.voxel_size) * grid.voxel_size) / dir.x
    } else { f32::INFINITY };

    let mut t_max_y = if dir.y != 0.0 {
        let next_y = if step_y > 0 { voxel.y.floor() + 1.0 } else { voxel.y.floor() };
        ((next_y - (origin.y - grid.origin.y) / grid.voxel_size) * grid.voxel_size) / dir.y
    } else { f32::INFINITY };

    let mut t_max_z = if dir.z != 0.0 {
        let next_z = if step_z > 0 { voxel.z.floor() + 1.0 } else { voxel.z.floor() };
        ((next_z - (origin.z - grid.origin.z) / grid.voxel_size) * grid.voxel_size) / dir.z
    } else { f32::INFINITY };

    // 步进
    let t_delta = grid.voxel_size;
    let mut t = 0.0;

    while t < max_distance {
        // 当前体素是否非空?
        if voxel.x >= 0.0 && voxel.x < grid.dims.0 as f32
            && voxel.y >= 0.0 && voxel.y < grid.dims.1 as f32
            && voxel.z >= 0.0 && voxel.z < grid.dims.2 as f32 {
            let idx = (voxel.z as u32 * grid.dims.0 * grid.dims.1
                + voxel.y as u32 * grid.dims.0 + voxel.x as u32) as usize;
            if grid.voxels[idx].coverage > 0 {
                return true;  // 碰撞
            }
        }

        // 步进到下一个体素
        if t_max_x < t_max_y && t_max_x < t_max_z {
            voxel.x += step_x as f32;
            t = t_max_x;
            t_max_x += t_delta / dir.x.abs();
        } else if t_max_y < t_max_z {
            voxel.y += step_y as f32;
            t = t_max_y;
            t_max_y += t_delta / dir.y.abs();
        } else {
            voxel.z += step_z as f32;
            t = t_max_z;
            t_max_z += t_delta / dir.z.abs();
        }
    }

    false  // 没碰撞,射线"逃出"
}
```

**DDA 算法**:

- 每次步进到下一个体素边界
- 三轴独立比较 `t_max`(到下一个 x/y/z 边界的距离)
- 选最小的 `t_max`,步进那个轴
- 每步检查当前体素是否非空

### 随机半球方向

AO 在法线方向的半球内发射射线:

```rust
pub fn random_hemisphere_direction(normal: Vec3, seed: usize) -> Vec3 {
    use std::f32::consts::PI;
    // 用 Halton 序列(确定性低差异序列,避免随机)
    let u = halton(seed as u32 + 1, 2);
    let v = halton(seed as u32 + 1, 3);

    // 球面坐标
    let phi = v * 2.0 * PI;
    let cos_theta = 1.0 - u;  // 上半球
    let sin_theta = (1.0 - cos_theta * cos_theta).sqrt();

    let local_dir = Vec3::new(
        sin_theta * phi.cos(),
        cos_theta,
        sin_theta * phi.sin(),
    );

    // 转换到 world space(用 normal 为 up)
    let up = if normal.y.abs() > 0.9 {
        Vec3::new(1.0, 0.0, 0.0)
    } else {
        Vec3::new(0.0, 1.0, 0.0)
    };
    let tangent = normal.cross(up).normalize();
    let bitangent = normal.cross(tangent).normalize();
    tangent * local_dir.x + normal * local_dir.y + bitangent * local_dir.z
}

fn halton(index: u32, base: u32) -> f32 {
    let mut f = 1.0;
    let mut r = 0.0;
    let mut i = index;
    while i > 0 {
        f /= base as f32;
        r += f * (i % base) as f32;
        i /= base;
    }
    r
}
```

**Halton 序列**:确定性低差异序列,比纯随机更均匀(覆盖整个半球)。

### GPU Compute Shader 实现

```glsl
#version 430

layout(local_size_x = 4, local_size_y = 4, local_size_z = 4) in;

layout(binding = 0, rgba32f) readonly uniform image3D voxel_data;
layout(binding = 1, r32f) writeonly uniform image3D ao_grid;

uniform ivec3 grid_dims;
uniform float voxel_size;
uniform int ray_count;
uniform float max_distance;

// DDA 射线检测
bool ray_hits_voxel(ivec3 start_voxel, vec3 dir) {
    ivec3 step = ivec3(sign(dir));
    vec3 t_max = vec3(0.0);  // 计算初始 t_max
    vec3 t_delta = abs(1.0 / dir) * voxel_size;
    
    ivec3 current = start_voxel;
    float t = 0.0;
    
    while (t < max_distance) {
        if (current.x < 0 || current.x >= grid_dims.x
            || current.y < 0 || current.y >= grid_dims.y
            || current.z < 0 || current.z >= grid_dims.z) {
            return false;  // 离开网格
        }
        vec4 data = imageLoad(voxel_data, current);
        if (data.a > 0.5) return true;  // 非空
        
        if (t_max.x < t_max.y && t_max.x < t_max.z) {
            current.x += step.x;
            t = t_max.x;
            t_max.x += t_delta.x;
        } else if (t_max.y < t_max.z) {
            current.y += step.y;
            t = t_max.y;
            t_max.y += t_delta.y;
        } else {
            current.z += step.z;
            t = t_max.z;
            t_max.z += t_delta.z;
        }
    }
    return false;
}

void main() {
    ivec3 idx = ivec3(gl_GlobalInvocationID);
    if (any(greaterThanEqual(idx, grid_dims))) return;
    
    vec4 voxel = imageLoad(voxel_data, idx);
    if (voxel.a < 0.5) {
        imageStore(ao_grid, idx, vec4(1.0));  // 空体素 AO=1
        return;
    }
    
    vec3 normal = voxel.rgb * 2.0 - 1.0;  // 解码法线(假设 [0,1] 编码)
    
    // 发射 N 条射线
    int visible = 0;
    for (int i = 0; i < ray_count; ++i) {
        vec3 dir = random_hemisphere_dir(normal, i);
        if (!ray_hits_voxel(idx, dir)) visible++;
    }
    
    float ao = float(visible) / float(ray_count);
    imageStore(ao_grid, idx, vec4(ao));
}
```

### AO 应用到光照

```glsl
// Lighting shader
uniform sampler3D ao_texture;  // AO 网格
uniform vec3 grid_min;
uniform vec3 grid_extent;

void main() {
    // Phong + GI(如前)
    vec3 phong = ambient + diffuse + specular;
    vec3 gi = albedo * texture(voxel_light, uvw).rgb;
    
    // 采样 AO
    vec3 ao_uvw = (world_position - grid_min) / grid_extent;
    float ao = texture(ao_texture, ao_uvw).r;
    
    // 应用 AO(只调制 ambient + GI,diffuse/specular 是直接光,不被 AO)
    vec3 final = (ambient + gi) * ao + diffuse + specular;
    
    // Tone map
    final = final / (final + vec3(1.0));
    frag = vec4(final, 1.0);
}
```

**关键**:AO 只调制 **ambient + GI**(间接光),**不调制 diffuse + specular**(直接光)——直接光来自明确的光源,不会被遮挡(遮挡 = shadow,是另一个算法)。

### AO 参数调优

| 参数 | 典型值 | 影响 |
|---|---|---|
| Ray count | 16-64 | 越多越准确但慢 |
| Max distance | 5-20 体素 | 越远 AO 范围越大 |
| Bias | 0.5 体素 | 防止"自遮挡"(射线起点偏移) |
| Falloff | smoothstep | AO 边界平滑 |

### Self-occlusion 问题

射线起点 = 体素中心,如果直接步进,第一个体素就是自己,**自遮挡**。修法:

- **起点偏移**:从 normal × 0.5 体素的位置开始(沿法线方向偏移)
- **跳过自身**:第一个体素不计

```glsl
vec3 origin = world_pos + normal * voxel_size * 0.5;
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业界 AO:

- **SSAO**(Crytek 2007):屏幕空间,基于深度 buffer,便宜但失真(屏幕外几何不算)
- **HBAO / HDAO**(NVIDIA / AMD):改进 SSAO,考虑法线
- **VXAO**(NVIDIA):voxel AO,VXGI 一部分
- **RTAO**(RTX):ray-traced AO,质量最高

**SSAO 的核心**:

- 对每像素,采样周围几个像素的深度
- 算"被周围几何遮挡"的比例
- 应用到 ambient

**SSAO 局限**:屏幕外几何不算(背向相机的角落 AO 错),只能屏幕空间。Voxel AO 没有,但需要体素化场景。

### 3.2 · 🎨 图形学视角

**AO 的数学**:

```
AO(x) = (1 / π) ∫_Ω V(x, ω) max(0, n · ω) dω
```

- Ω:上半球(法线方向)
- V(x, ω):可见性函数,1=可见,0=被挡
- n · ω:cos 项,法线方向权重

**Bent normal**:AO 的副产品——"未被遮挡的平均方向"。比 normal 更准确(指向开敞方向),用于光照计算更真实。

Rust 端 AO 计算:

```rust
use glam::Vec3;

pub fn compute_voxel_ao(
    grid: &VoxelGrid,
    position: Vec3,
    normal: Vec3,
    ray_count: usize,
    max_distance: f32,
) -> f32 {
    let mut visible = 0;
    let origin = position + normal * grid.voxel_size * 0.5;  // 防自遮挡

    for i in 0..ray_count {
        let dir = random_hemisphere_direction(normal, i);
        if !ray_hits_voxel(grid, origin, dir, max_distance) {
            visible += 1;
        }
    }
    visible as f32 / ray_count as f32
}

pub fn compute_ao_grid(
    voxel_grid: &VoxelGrid,
    ray_count: usize,
    max_distance: f32,
) -> Vec<f32> {
    let mut ao = vec![1.0; voxel_grid.voxels.len()];
    for k in 0..voxel_grid.dims.2 {
        for j in 0..voxel_grid.dims.1 {
            for i in 0..voxel_grid.dims.0 {
                let idx = (k * voxel_grid.dims.0 * voxel_grid.dims.1
                    + j * voxel_grid.dims.0 + i) as usize;
                if voxel_grid.voxels[idx].coverage == 0 { continue; }
                
                let pos = voxel_grid.origin + Vec3::new(i as f32, j as f32, k as f32) * voxel_grid.voxel_size;
                let normal = Vec3::from(voxel_grid.voxels[idx].normal);
                ao[idx] = compute_voxel_ao(voxel_grid, pos, normal, ray_count, max_distance);
            }
        }
    }
    ao
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:AO 为什么只调制 ambient + GI,不调制 diffuse + specular?

**参考解答**:

**Diffuse / Specular** 是**直接光**——来自明确的光源,有明确的方向。如果几何挡住光源到表面,**应该产生 shadow**(另一个算法,如 shadow map),不是 AO。

**Ambient / GI** 是**间接光**——来自四面八方的散射。如果几何挡住表面到周围环境的视线,间接光减弱,这就是 AO。

**简化**:AO 是"环境光的 shadow"。直接光的 shadow 用 shadow map / ray tracing 算,和 AO 分离。

如果用 AO 调制 diffuse / specular,会导致**两次 shadow**(AO + shadow map),过暗。所以分开。

### Lv2 · 动手实践

**题**:在 Rust 实现简化版 AO——给定 3D 网格(0/1 表示空/非空)和位置,发射 16 条射线,统计遮挡比例。

完成标准:角落 AO ≈ 0.3,开阔地 AO ≈ 1.0。

**参考解答**:

```rust
use glam::Vec3;

fn ray_hits_grid(grid: &Vec<bool>, dims: usize, origin: Vec3, dir: Vec3) -> bool {
    let dir = dir.normalize();
    let mut pos = origin;
    let step = 0.1;
    
    for _ in 0..50 {  // 最多 50 步
        pos += dir * step;
        let x = pos.x as i32;
        let y = pos.y as i32;
        let z = pos.z as i32;
        if x < 0 || x >= dims as i32 || y < 0 || y >= dims as i32 || z < 0 || z >= dims as i32 {
            return false;  // 离开
        }
        let idx = (z as usize * dims * dims + y as usize * dims + x as usize) as usize;
        if grid[idx] { return true; }
    }
    false
}

fn compute_ao(grid: &Vec<bool>, dims: usize, origin: Vec3, normal: Vec3) -> f32 {
    let mut visible = 0;
    for i in 0..16 {
        // 简化:固定 16 方向(球面均匀分布)
        use std::f32::consts::PI;
        let phi = (i as f32 / 16.0) * 2.0 * PI;
        let theta = (i as f32 / 16.0 + 0.5) * PI * 0.5;  // 上半球
        let local = Vec3::new(theta.sin() * phi.cos(), theta.cos(), theta.sin() * phi.sin());
        // 简化:不考虑 normal,直接用 world up
        let _ = normal;
        if !ray_hits_grid(grid, dims, origin, local) {
            visible += 1;
        }
    }
    visible as f32 / 16.0
}

fn main() {
    let dims = 16;
    let mut grid = vec![false; dims * dims * dims];
    
    // 设置一个 L 形角落:地面 + 一面墙
    for x in 0..dims {
        for z in 0..dims {
            grid[(0 * dims * dims + 0 * dims + x) as usize] = true;  // 地面 y=0
        }
    }
    for y in 0..dims {
        for z in 0..dims {
            grid[(y * dims * dims + z * dims + 0) as usize] = true;  // 墙 x=0
        }
    }
    
    // 角落位置(0, 1, 0):应该 AO 低(三面墙)
    let corner = Vec3::new(0.5, 1.5, 0.5);
    let ao_corner = compute_ao(&grid, dims, corner, Vec3::new(0.0, 1.0, 0.0));
    println!("AO at corner: {:.2}", ao_corner);
    
    // 开阔位置(8, 1, 8):应该 AO 高
    let open = Vec3::new(8.5, 1.5, 8.5);
    let ao_open = compute_ao(&grid, dims, open, Vec3::new(0.0, 1.0, 0.0));
    println!("AO at open: {:.2}", ao_open);
}
```

```rust
use glam::Vec3;
use std::f32::consts::PI;

pub struct VoxelGrid {
    pub dims: usize,
    pub voxel_size: f32,
    pub origin: Vec3,
    pub voxels: Vec<bool>,  // 简化:只存非空
}

impl VoxelGrid {
    pub fn new(dims: usize, voxel_size: f32, origin: Vec3) -> Self {
        Self {
            dims, voxel_size, origin,
            voxels: vec![false; dims.pow(3)],
        }
    }

    pub fn set(&mut self, x: usize, y: usize, z: usize, val: bool) {
        if x < self.dims && y < self.dims && z < self.dims {
            self.voxels[z * self.dims * self.dims + y * self.dims + x] = val;
        }
    }

    pub fn get(&self, x: i32, y: i32, z: i32) -> bool {
        if x < 0 || x >= self.dims as i32 || y < 0 || y >= self.dims as i32 || z < 0 || z >= self.dims as i32 {
            return false;
        }
        self.voxels[z as usize * self.dims * self.dims + y as usize * self.dims + x as usize]
    }
}

pub fn ray_hits_voxel(grid: &VoxelGrid, origin: Vec3, dir: Vec3, max_dist: f32) -> bool {
    let dir = dir.normalize();
    let mut pos = origin;
    let step = grid.voxel_size * 0.5;
    let mut t = 0.0;
    while t < max_dist {
        pos += dir * step;
        t += step;
        let rel = (pos - grid.origin) / grid.voxel_size;
        let x = rel.x.floor() as i32;
        let y = rel.y.floor() as i32;
        let z = rel.z.floor() as i32;
        if grid.get(x, y, z) { return true; }
    }
    false
}

pub fn compute_ao_at(
    grid: &VoxelGrid,
    world_pos: Vec3,
    normal: Vec3,
    ray_count: usize,
    max_dist: f32,
) -> f32 {
    let origin = world_pos + normal * grid.voxel_size * 0.5;  // 防自遮挡
    let mut visible = 0;
    for i in 0..ray_count {
        // Halton 半球采样
        let u = halton(i as u32 + 1, 2);
        let v = halton(i as u32 + 1, 3);
        let phi = v * 2.0 * PI;
        let cos_theta = 1.0 - u;
        let sin_theta = (1.0 - cos_theta * cos_theta).sqrt();
        let local = Vec3::new(sin_theta * phi.cos(), cos_theta, sin_theta * phi.sin());
        // 把 local 转到 normal 方向(简化:假设 normal 是 +y)
        let _ = normal;
        if !ray_hits_voxel(grid, origin, local, max_dist) {
            visible += 1;
        }
    }
    visible as f32 / ray_count as f32
}

fn halton(mut index: u32, base: u32) -> f32 {
    let mut f = 1.0;
    let mut r = 0.0;
    while index > 0 {
        f /= base as f32;
        r += f * (index % base) as f32;
        index /= base;
    }
    r
}

fn main() {
    let mut grid = VoxelGrid::new(16, 0.1, Vec3::new(-0.8, -0.8, -0.8));

    // 设置 L 形角落
    for x in 0..16 {
        for z in 0..16 {
            grid.set(x, 0, z, true);  // 地面
        }
    }
    for y in 0..16 {
        for z in 0..16 {
            grid.set(0, y, z, true);  // 墙
        }
    }

    // 测试角落
    let corner = Vec3::new(-0.7, -0.7, -0.7);
    let ao1 = compute_ao_at(&grid, corner, Vec3::new(0.0, 1.0, 0.0), 32, 1.0);
    println!("AO at corner: {:.2}", ao1);

    // 测试开阔
    let open = Vec3::new(0.0, -0.7, 0.0);
    let ao2 = compute_ao_at(&grid, open, Vec3::new(0.0, 1.0, 0.0), 32, 1.0);
    println!("AO at open: {:.2}", ao2);
}
```

### 深度推导:本日相关数学与算法

要真正掌握今天的内容,我们必须把背后的数学推导展开。这一节是"为什么这么做"的论证。

**算法复杂度的精确分析**。今天的代码涉及到对实体集合排序,基准复杂度:

- 最优比较排序下界:O(N log N)(决策树理论)
- Rust `sort_by`:TimSort,平均 O(N log N),最好 O(N)(已部分有序时)
- 拓扑排序:O(V + E),V 是节点数,E 是边数
- Radix sort:O(N × k),k 是 sort key 位数——非比较排序,可突破 O(N log N)

对一个 1000 sprite 的场景,TimSort 大约 10000 次比较,每次比较 5-10 个 cycle(分支少),总 50000-100000 cycle = 20-40 μs。在 60 FPS(16666 μs 预算)占 0.2%——可忽略。100K sprite 时升到 2 ms,开始有压力。Minecraft 这种规模的游戏必须用 radix sort 或 GPU sort。

**内存访问模式**。sort 是**非线性内存访问**的典型——每次比较都可能跳到 Vec 不同位置。CPU prefetcher 抓不到模式,cache miss 频繁。优化:

1. **Sort by index**:先 sort indices(u32 数组,4 字节/项,cache 友好),再 reorder 数据。indices 1000 个 = 4 KB,L1 cache 装得下。
2. **Batch reorder**:indices 排好后,顺序遍历 indices,顺序访问原数据(虽然是间接但 prefetcher 跟得上)。

```rust
let mut indices: Vec<u32> = (0..entities.len() as u32).collect();
indices.sort_by(|&a, &b| sort_rule(&entities[a as usize], &entities[b as usize]));
let sorted: Vec<&Entity> = indices.iter().map(|&i| &entities[i as usize]).collect();
```

100K sprite 的 sort 用这个技巧能加速 30%。

**位运算打包 sort key**。今天 sort_key 是 u64,可以塞进多个字段:

```
bits 63-56: layer (8 bits, 256 layers)
bits 55-40: bottom_y (16 bits, 65536 levels)
bits 39-24: x (16 bits)
bits 23-8: sub_layer (16 bits)
bits 7-0: spawn_id (8 bits, 256 entries per slot)
```

打包:`key = (layer << 56) | (bottom_y << 40) | (x << 24) | (sub << 8) | spawn`。一次 u64 比较,无分支,Rust `sort_by_key` 自动 inline。

**部分序的图论模型**。Day 304 会用拓扑排序处理真正的部分序。每个 sprite 是图节点,如果 A 应该在 B 前面,加边 A→B。拓扑排序给出节点的合法顺序(满足所有约束)。

拓扑排序算法:

1. **Kahn 算法**:每次找入度为 0 的节点,加入结果,删掉它的出边,重复。
2. **DFS 后序**:DFS 遍历,记录后序(post-order),反转得到拓扑序。

如果图有环(循环依赖),拓扑排序失败——意味着 sprite 排序无解,必须**人为拆解**(切开某个 sprite)。

**浮点数的稳定性**。Rust 的 `f32::partial_cmp` 处理 NaN 返回 `None`,sort 会 panic。所以游戏代码里要么保证所有 f32 都不是 NaN(数学保证),要么 `partial_cmp(...).unwrap_or(Equal)`(默认相等)。今天 sort_rule 用后者。

更稳妥的方法:**所有位置用整数**(像素单位)。`pos_y: i32` 没有 NaN 问题,比较无分支。但缩放和旋转要用浮点,所以游戏用 i32 + f32 混合。

### 真实代码片段

Casey 在 HH 视频里实际写的代码风格(简化伪代码):

```c
internal int32
SortRule(entity *A, entity *B)
{
    int32 Result = 0;

    // Layer 比较
    if (A->Layer != B->Layer) {
        Result = (int32)A->Layer - (int32)B->Layer;
    } else {
        // Bounds overlap 检查
        rectangle2 BoundsA = GetEntityBounds(A);
        rectangle2 BoundsB = GetEntityBounds(B);
        if (RectanglesOverlap(BoundsA, BoundsB)) {
            // Bottom y 比较
            real32 BottomA = BoundsA.Max.Y;
            real32 BottomB = BoundsB.Max.Y;
            if (BottomA != BottomB) {
                Result = (BottomA < BottomB) ? -1 : 1;
            } else {
                // x 比较
                Result = SignOf32(A->P.X - B->P.X);
            }
        } else {
            // 不重叠:任意顺序
            Result = A->SpawnID - B->SpawnID;
        }
    }

    return Result;
}
```

注意 Casey 的 C 风格:

- 直接返回 int32(而非 enum Ordering)
- 用 `SignOf32`(返回 -1/0/1)简化比较
- if-else 链而非 Rust 的 `then_with`

Rust 等价:

```rust
fn sort_rule(a: &Entity, b: &Entity) -> Ordering {
    a.layer.cmp(&b.layer)
        .then_with(|| {
            if bounds_overlap(a, b) {
                let ba = bounds(a).max.y;
                let bb = bounds(b).max.y;
                ba.partial_cmp(&bb).unwrap_or(Ordering::Equal)
                    .then(a.pos.x.partial_cmp(&b.pos.x).unwrap_or(Ordering::Equal))
            } else {
                a.spawn_id.cmp(&b.spawn_id)
            }
        })
}
```

### 跨学科联结:从游戏到数据库

sort_rule 的本质是"复杂比较函数",这在很多领域都出现:

- **数据库 ORDER BY**:SQL 的 `ORDER BY layer, y, x` 是同样的 multi-key sort,但 SQL 是声明式(数据库优化器选 sort 算法),Casey 是命令式(手写 sort_by)。
- **React diff**:React 用 sort + key 比较 virtual DOM,决定哪些 component 重渲染。Multi-key sort 决定 diff 顺序。
- **Linux kernel CFS**(Completely Fair Scheduler):按 vruntime 排序进程,选最小 vruntime 的运行。本质是 sort_rule。
- **Git log --sort**:Git commit 按 committer date + author date + subject 排序。

Casey 在 HH 反复说"很多算法本质相同,只是命名不同"。掌握一个领域的 sort_rule,就掌握所有领域。
