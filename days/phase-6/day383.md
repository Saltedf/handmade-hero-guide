# Day 383 · 修复深度剥离伪影

> Day 381-382 把深度剥离的雏形跑起来了,但**画面有伪影**(artifacts):某些半透明物体的边缘在闪烁,某些角度下两层颜色"完全相同"导致看不到深度剥离的效果。今天 Casey 用 RenderDoc 一帧帧检查,定位并修复这些 bug。这是个**调试集**——也是 HH 里少数让你看到"调试思路"而不是"完美代码"的集。

## 0 · 为什么要有这一天

你写了正确的算法,跑起来却发现**画面不对**。这是每个图形程序员的日常——GPU 代码不像 CPU 代码可以 `println!`,出了 bug 你只能:

1. 猜(基于经验)
2. 抓帧(用 RenderDoc / apitrace)
3. 改一行 shader 代码,重新跑

Day 381-382 的深度剥离有两个常见伪影:

### 伪影 1:Z-fighting(深度冲突)

**症状**:两个三角形几乎平行 / 距离极近时,**画面在两层之间快速闪烁**——一会儿显示这层,一会儿显示那层。

**原因**:浮点深度精度有限。如果 `z0` 和 `z1` 差距小于浮点 epsilon,`z1 > z0` 的比较结果**不稳定**——某帧是 true(显示 layer1),某帧是 false(不显示)。这个抖动导致视觉闪烁。

**修法**:加 epsilon 容差——`if (z1 > z0 + epsilon) discard`。epsilon 取多大?Casey 在 Day 383 试了几个值(1e-3、1e-4、1e-5),最后选了 1e-4(在 NDC 空间,深度范围 [0, 1],1e-4 大约是 1/10000 的精度)。

### 伪影 2:Depth comparison 错误

**症状**:某些角度下,layer1 **完全空白**(没有 fragment 通过),或 layer0 和 layer1 **完全相同**。

**原因**:fragment shader 里的 `if (gl_FragCoord.z <= prev_depth) discard` 写反了。如果写成 `<`(严格小于),边界情况(两个 fragment 深度完全相等)会**都被丢弃**,导致空白。正确写法是 `<=`(小于等于),只丢"近的或相等的",留"严格远的"。

但这样又有一个问题:**几何自身的两个面**(比如球的前面和后面)深度可能完全相同(球心穿过相机),`<=` 都丢弃,结果空白。

### 伪影 3:Texture filter 模糊

**症状**:layer0 / layer1 之间**过渡边缘模糊**,像隔了层雾。

**原因**:`texture()` 默认双线性插值,**在 layer 边界**采样时,4 个相邻像素混合,导致边缘颜色不准。

**修法**:用 `texelFetch`(按整数像素坐标取,不做插值)。Casey 在 Day 383 把 `prev_depth` 的采样改成 `texelFetch(prev_depth_tex, ivec2(gl_FragCoord.xy), 0)`。

### 伪影 4:色彩空间二次编码

**症状**:最终画面比"应该的颜色"暗。

**原因**:layer 纹理是 RGBA32F(linear),写入 sRGB framebuffer 时 OpenGL 自动做 `linear → sRGB`,但如果 shader 里手动做过一次 `pow(color, 1/2.2)`,就**编码了两次**,颜色变暗。

**修法**:关闭手动 sRGB 编码,只依赖 `GL_FRAMEBUFFER_SRGB`。

这四个伪影是**真实工程问题**——你写代码时不会想到,但跑起来必撞到。今天的产出:**画面终于"看着对"了**——半透明球后面真的能看到东西,颜色不闪,边缘清晰。

心理锚点:看完今天,你能(1)说出 z-fighting 的成因和 epsilon 修法;(2)区分 `texture()` 和 `texelFetch()` 何时用哪个;(3)用 RenderDoc 看 fragment shader 的 input / output 数值;(4)用 binary search 找到合适的 epsilon 值。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 流程:

1. **观察 bug**:在 demo 里把两个球重叠,**移动相机**到某些角度时**画面闪烁**。Casey 录屏,逐帧看,确定是 z-fighting。
2. **第一直觉**:开 RenderDoc,抓闪烁的那一帧。
3. **RenderDoc 分析**:
   - 看 layer0 的 depth texture(浮点)
   - 看 layer1 的 depth texture(浮点)
   - **对比**:发现某些像素两层的 z 差距极小(<1e-5)
4. **第一次修**:把 fragment shader 的 `if (z > prev) discard` 改成 `if (z > prev + 1e-3) discard`。结果闪烁消失,但 layer1 的"边缘"被吃掉了一圈(因为 epsilon 太大)。
5. **第二次调**:epsilon 改 1e-4,闪烁消失,边缘没被吃。
6. **第二个 bug**:发现 layer1 的颜色边缘模糊。Casey 把 fragment shader 里的 `texture(prev_depth, uv)` 改成 `texelFetch(prev_depth, ivec2(gl_FragCoord.xy), 0)`,边缘清晰了。
7. **第三个 bug**:Casey 发现合成的最终画面颜色暗。查 sRGB:发现 shader 里手动做了 `pow(color, 1.0 / 2.2)`(为了"看起来更亮"),但 OpenGL 默认 framebuffer 是 sRGB8 + `GL_FRAMEBUFFER_SRGB`,已经做了一次 sRGB 转换。Casey 删掉手动编码,依赖 OpenGL 自动转换。
8. **完整跑一遍**:画面正确,Casey 把 demo 录视频发到 HH Twitter。

这集教学价值:Casey **完整展示了"看到 bug → 抓帧 → 改一行 → 验证"的循环**,这是图形程序员的核心工作流。

## 2 · 心智模型

### 类比:调试 GPU 代码 = 在黑盒里写信

CPU 代码调试:你可以 `println!` 看每个变量,可以 `gdb` 设断点单步执行。**信息透明**。

GPU 代码调试:你写一个 fragment shader,**对每个像素执行一次**,GPU 同时执行几万个像素,**你无法 `println!`**(打印什么?哪个像素?)。**信息不透明**。

工具来帮忙:

- **RenderDoc**:抓一帧,看每个 draw call 的纹理、buffer、shader source。可以**选中一个像素**,看它的 fragment shader input / output。
- **apitrace**:录制所有 GL call,replay 时可以逐步执行。
- **printf debugging in shader**:把 `vec4 color = ...` 改成 `gl_FragColor = vec4(debug_value, 0, 0, 1)`,让某个值直接显示为红色——经典的"shader debug 大法"。
- **`glGetShaderInfoLog`**:看 shader 编译错误。
- **`glValidateProgram`**:验证 program 是否可执行。

**核心思路**:GPU 调试是"看纹理数值 + 改一行 shader + 重新跑"的循环。Casey 今天就是这种循环。

### 严谨原理:Z-fighting 的数学

OpenGL 的 `gl_FragCoord.z` 是 NDC(Normalized Device Coordinates)空间的深度,范围 [0, 1]。**这个值不是线性的**——经过透视投影后,远处精度高,近处精度低。具体公式:

```
z_ndc = (z_eye * (f + n) / (f - n) - 2 * f * n / (f - n)) / -z_eye
z_buffer = z_ndc * 0.5 + 0.5
```

其中 `z_eye` 是相机空间 z(负数),n / f 是 near / far 平面。

**精度问题**:24 位深度 buffer 在 z=0.5 时精度约 `0.5 / 2^24 ≈ 3e-8`,在 z=0.99 时精度约 `0.01 / 2^24 ≈ 6e-10`。看起来精度极高,但当两个 fragment **几乎重合**时(差距 < 1e-7),浮点比较**不稳定**。

具体看一个例子:

```
fragment A: z = 0.5000001
fragment B: z = 0.5000002
```

`z_buffer` 存的可能是 `0.50000017`(由于舍入)。比较 `B > A`:

- 某帧 GPU 算出 `0.5000002 > 0.5000001` = true(显示 B)
- 某帧 GPU 算出 `0.5000002 > 0.50000017` = false(B 被丢弃)

这种抖动**取决于 GPU 的浮点实现**(某些 GPU 用快速近似浮点),导致**闪烁**。

**Epsilon 修法**:把比较改成 `z > prev + epsilon`,epsilon 取 1e-4(在 NDC [0, 1] 空间,这相当于 1/10000 的精度)。这样 `0.5000002 > 0.5000001 + 1e-4 = 0.5001001` 是 false,B 被丢弃——稳定,不抖动。

代价:layer1 **吃掉**了 prev_z + epsilon 以内的所有 fragment,即"接近重合的两层"被合并成一层。视觉上影响小,因为本来人眼就分不清"差 1e-4 的两层"。

**epsilon 选择**:太小(zero)→ z-fighting;太大 → layer 信息丢失。Casey 试出来的 1e-4 是个折衷。生产代码里 1e-3 到 1e-5 都见过。

### 严谨原理:`texture()` vs `texelFetch()`

GLSL 里两种纹理采样函数:

```glsl
// texture():浮点坐标,默认双线性插值
vec4 c0 = texture(sampler, vec2(u, v));  // 4 个最近像素加权平均

// texelFetch():整数像素坐标,不做插值
vec4 c1 = texelFetch(sampler, ivec2(x, y), 0);  // 直接取一个像素
```

**何时用 `texture()`**:

- 采样连续信号(颜色梯度、法线贴图、噪声纹理)
- 需要 mipmap(自动选 detail level)
- UV 坐标在 [0, 1] 浮点

**何时用 `texelFetch()`**:

- 采样"逐像素数据"(深度、G-buffer、ID)
- 不允许插值(深度插值没意义)
- 像素级精确

**深度剥离的 `prev_depth`** 必须用 `texelFetch`——深度是"这个像素的最近一层深度",**不能插值**(插值后变成"周围像素的平均深度",导致判断错误)。

Casey 在 Day 383 把 shader 改成:

```glsl
// before(bug):
float prev = texture(prev_depth_tex, gl_FragCoord.xy / resolution).r;

// after(fix):
ivec2 px = ivec2(gl_FragCoord.xy);
float prev = texelFetch(prev_depth_tex, px, 0).r;
```

注意 `gl_FragCoord.xy` 是浮点(像素中心 +0.5 偏移),`ivec2(gl_FragCoord.xy)` 取整变成像素索引。

### 严谨原理:OpenGL 的 sRGB 自动转换

OpenGL 4.x 引入 `GL_FRAMEBUFFER_SRGB` 全局开关,行为:

- **开启**:fragment shader 输出的颜色(linear)写入 sRGB framebuffer 时,自动转换 `sRGB = pow(linear, 1/2.2)`(实际是更精确的 sRGB 曲线)
- **关闭**:fragment shader 输出直接写入,不做转换

**陷阱**:如果你在 shader 里手动做 `pow(color, 1/2.2)`,**又**开了 `GL_FRAMEBUFFER_SRGB`,会**编码两次**:颜色变暗两次方。

**正确做法**(选一种):

1. **自动**:shader 输出 linear,开 `GL_FRAMEBUFFER_SRGB`,framebuffer 是 sRGB8。OpenGL 自动转换。
2. **手动**:shader 输出 `pow(linear, 1/2.2)`,关 `GL_FRAMEBUFFER_SRGB`,framebuffer 是 RGB8(线性存储但实际显示是 sRGB)。开发者自己负责转换。

**Casey 的选择**:用自动模式,删掉 shader 里的 `pow(color, 1/2.2)`。这是工业界主流。

**调试 sRGB bug 的方法**:

- 抓帧,看 framebuffer 的颜色数值
- 在 linear 空间应该是 0.5(灰色),写入 sRGB framebuffer 后读出来应该是 ~0.735(`0.5^(1/2.2)`)
- 如果读出来是 0.5(没转换),说明 `GL_FRAMEBUFFER_SRGB` 没开
- 如果读出来是 0.35(转了两次),说明 shader 又手动做了转换

### RenderDoc 工作流(逐步)

RenderDoc 的核心工作流:

1. **Launch**:指定 executable,点 Launch 启动
2. **Capture**:程序运行后,按 F12(或点 Capture)抓一帧
3. **Event Browser**:看到抓帧里所有 GL / Vulkan 调用(draw call 顺序)
4. **Pipeline State**:选一个 draw call,看 vertex shader / fragment shader / 纹理 / uniform 的当前状态
5. **Texture Viewer**:看每个纹理(输入和输出),点像素看具体数值
6. **Mesh Viewer**:看 vertex buffer 数据
7. **Shader**:看 shader source,可以编辑后 hot-reload(实验性)

**定位 z-fighting 的流程**:

1. 抓闪烁的那一帧(连续抓 5-10 帧,看哪一帧不一样)
2. Event Browser 找到 layer1 的 draw call
3. Pipeline State 看 fragment shader 的 `prev_depth_tex` 绑定
4. Texture Viewer 看 `prev_depth_tex` 的数值,把光标放在闪烁的像素上,看具体 depth 值
5. 比较当前 fragment 的 `gl_FragCoord.z` 和 prev_depth,看差距
6. 如果差距 < 1e-5,确认是 z-fighting

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏开发里 z-fighting 是**经典 bug**:

- ** decals(贴花)**:地面上的血迹 / 弹痕,是贴在地形上的 quad。如果距离地形太近,会闪烁。
- **多 pass 阴影**:shadow map 和实际几何的深度比较,几乎重合时闪烁。
- ** decals for UI**:HUD 元素叠在 3D 场景上,如果 z 离场景太近,UI 元素会"扎进"场景。

工业界的 epsilon 取值经验:

- 不透明物体:`glPolygonOffset`(OpenGL 的"深度偏移"功能),按像素自动微调深度
- 半透明深度剥离:手动 epsilon,典型 1e-4
- shadow map:用 "bias" uniform,典型 1e-3 到 1e-2

**Casey 后面 Day 402+ 做光照时**,会再次遇到 z-fighting(raycasting 算可见性,射线起点几乎重合时也抖动)。

### 3.2 · 🎨 图形学视角

**Reversed-Z 技巧**:现代渲染引擎用 `glClipControl(GL_LOWER_LEFT, GL_ZERO_TO_ONE)` 把深度范围改成 [0, 1] 但**远=0, 近=1**(reversed),配合浮点深度 buffer(GL_DEPTH_COMPONENT32F)。这样**近处精度更高**(因为 1.0 附近的浮点精度最高),消除大部分 z-fighting。

**Logarithmic depth buffer**:WebGL 1 不支持浮点深度时,用对数编码深度(精度均匀分布)。代价是 fragment shader 要手动写深度(`gl_FragDepth = log(z)`),性能损失。

**Z-fighting 的不可消除性**:理论上 epsilon 是 hack,正确做法是**让几何不重合**(decals 偏移、shadow bias)。但在复杂场景下,epsilon 是不可避免的工程妥协。

### 3.3 · 🐧 Linux 系统编程视角

# RenderDoc(开源,跨平台)

### 3.4 · 🦀 Rust 生态视角

Rust 端调试 OpenGL:

```rust
// 在 glium / gl crate 里,启动时检查所有 GL 错误
fn check_gl_errors(label: &str) {
    let err = unsafe { gl::GetError() };
    while err != gl::NO_ERROR {
        eprintln!("[GL ERROR] {}: {}", label, err);
        let err = unsafe { gl::GetError() };
    }
}

// 用法
unsafe {
    gl::TexImage2D(...);
    check_gl_errors("after TexImage2D");
    gl::DrawArrays(...);
    check_gl_errors("after DrawArrays");
}
```

** glium 自动做这个**(每个 GL call 后检查 error,转成 Rust Result),所以 glium 用户一般不用手写。但用 `gl` crate 直接调用的话,必须手写。

**debugPrintf in GLSL**(GL_KHR_debug_string 扩展):

```glsl
#extension GL_KHR_debug_string : require

void main() {
    debugPrintfEXT("z=%f, prev=%f\n", gl_FragCoord.z, prev);
}
```

输出到 stderr 或 OpenGL debug callback。但**只有某些驱动支持**(NVIDIA 是,AMD / Intel 部分支持)。

**Rust 调试 Shader 的最佳实践**:把 debug 值编码为颜色,渲染到屏幕看。例如:

```glsl
// 调试深度:把 z 映射到 [0,1] 灰度
frag_color = vec4(vec3(gl_FragCoord.z), 1.0);

// 调试 prev_depth 差距:
float diff = gl_FragCoord.z - prev;
frag_color = vec4(diff > 0.0 ? vec3(1, 0, 0) : vec3(0, 0, 1), 1.0);
```

Casey 在 Day 383 就是用这种方法定位 bug 的——把每个 fragment 的"判断结果"显示为红/蓝,直接看出哪些像素错了。

## 5 · 对照与变奏

### 同一问题在不同语境下的变体

**问题**:两个数值几乎相等时,如何稳定比较?

| 语境 | 方案 | 典型 epsilon |
|---|---|---|
| GPU 深度比较 | `z > prev + epsilon` | 1e-4(NDC) |
| CPU 浮点相等 | `(a - b).abs() < epsilon` | 1e-6(f32) |
| 物理碰撞 | 距离 < radius + epsilon | 1e-3(米) |
| 几何运算(点在线上) | `cross.abs() < epsilon` | 1e-7(单位长度) |

**核心模式**:**永远不要用 `==` 比较浮点数**。这是初学者最常犯的错误,导致的 bug 极难定位。

### 历史演化

- **1980s**:浮点数标准 IEEE 754 确立,epsilon 的概念成形。
- **1990s**:GPU 浮点精度有限(16 位),z-fighting 极常见,工业界引入 `glPolygonOffset`。
- **2000s**:24 位深度成为标准,z-fighting 减少。
- **2010s**:32 位浮点深度 + reversed-z 普及,z-fighting 几乎消失(在高精度场景)。
- **2020s**:Vulkan / DX12 允许任意深度格式,但 z-fighting 在某些硬件 / 某些视角下仍然出现。

### OpenGL 的 sRGB 演化

- **OpenGL 2.0**:无 sRGB 自动转换,所有渲染假设 linear。
- **OpenGL 3.0**:引入 `GL_FRAMEBUFFER_SRGB` 和 sRGB 纹理格式。
- **OpenGL 4.0**:默认推荐 sRGB,所有 framebuffer 应明确指定。
- **Vulkan**:swapchain 创建时必须指定 sRGB 或 non-sRGB。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:z-fighting 为什么不能完全消除?epsilon 是"修复"还是"掩盖"?

**参考解答**:z-fighting 的**根因**是浮点精度有限——两个 fragment 的深度差距小于浮点 epsilon 时,比较结果不稳定。**完全消除**需要无限精度,物理上不可能。

epsilon 是**掩盖**:把"几乎相等的两层"合并成一层,消除抖动,代价是丢失"几乎相等的那一层"。这是**工程妥协**,不是数学修复。

理论上更"正确"的做法:

- 让几何不重合(decals 偏移一点距离,shadow bias)
- 用更高精度的深度(32 位浮点 + reversed-z)
- 用对数深度(logarithmic depth buffer)

但这些方法都有自己的代价,epsilon 仍然是最常见的折衷。

### Lv2 · 动手实践

**题**:在 Day 382 的合成 demo 里加一个"debug 视图"——按数字键 1/2/3 切换显示 layer0 / layer1 / 合成结果。这要求你写 3 个 fragment shader,运行时切换。

**参考解答**:

```rust
// 在 main 函数里加一个 atomic 状态
use std::sync::atomic::{AtomicUsize, Ordering};
static DEBUG_VIEW: AtomicUsize = AtomicUsize::new(2);  // 0=layer0, 1=layer1, 2=composite

// 加一个 keyboard handler
event_loop.run(move |event, _, control_flow| {
    use glutin::event::{Event, WindowEvent, KeyboardInput, ElementState, VirtualKeyCode};
    match event {
        Event::WindowEvent { event: WindowEvent::KeyboardInput {
            input: KeyboardInput { state: ElementState::Pressed, virtual_keycode: Some(key), .. },
            ..
        }, .. } => {
            match key {
                VirtualKeyCode::Key1 => DEBUG_VIEW.store(0, Ordering::Relaxed),
                VirtualKeyCode::Key2 => DEBUG_VIEW.store(1, Ordering::Relaxed),
                VirtualKeyCode::Key3 => DEBUG_VIEW.store(2, Ordering::Relaxed),
                _ => {}
            }
        }
        Event::RedrawRequested(_) => {
            let view = DEBUG_VIEW.load(Ordering::Relaxed);
            // 把 view 作为 uniform 传给 shader
            let uniforms = uniform! {
                layer0: &tex0,
                layer1: &tex1,
                debug_view: view as i32,
            };
            // ...
        }
        _ => {}
    }
});
```

GLSL 改:

```glsl
uniform int debug_view;
void main() {
    vec4 c0 = texture(layer0, v_uv);
    vec4 c1 = texture(layer1, v_uv);
    if (debug_view == 0) {
        frag = vec4(c0.rgb, 1.0);  // 显示 layer0,丢 alpha
    } else if (debug_view == 1) {
        frag = vec4(c1.rgb, 1.0);
    } else {
        // 合成(原来的逻辑)
        vec3 rgb = c0.rgb * c0.a + c1.rgb * c1.a * (1.0 - c0.a);
        float a = c0.a + c1.a * (1.0 - c0.a);
        if (a > 1e-6) rgb /= a;
        frag = vec4(rgb, 1.0);
    }
}
```

**关键点**:
- `AtomicUsize` — 多线程安全的 usize,事件循环用 atomic 避免 borrow checker 抱怨
- `Ordering::Relaxed` — 最弱的内存顺序,这里足够(单线程读写)
- GLSL 的 `if / else if` — shader 里也是 if-else,但 GPU 的分支预测开销大,**生产代码尽量用 `mix()` 替代 if**。Debug 时用 if 更清晰。

### 完整 Rust + glium 调试工具集成

```toml
# Cargo.toml
[package]
name = "depth_peel_debug"
version = "0.1.0"
edition = "2021"

[dependencies]
glium = "0.34"
bytemuck = "1.14"
```

```rust
// src/main.rs
// 带调试视图切换 + GL 错误检查的深度剥离 demo

use glium::{glutin, Surface, implement_vertex, uniform, program, index,
            texture, framebuffer, debug_message};
use std::sync::atomic::{AtomicUsize, Ordering};

#[derive(Copy, Clone)]
struct Vertex { position: [f32; 2], uv: [f32; 2] }
implement_vertex!(Vertex, position, uv);

static DEBUG_VIEW: AtomicUsize = AtomicUsize::new(2);

fn main() {
    let event_loop = glutin::event_loop::EventLoop::new();
    let wb = glutin::window::WindowBuilder::new()
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 600))
        .with_title("Depth Peel Debug (1/2/3 to switch view)");
    let cb = glutin::ContextBuilder::new()
        .with_depth_buffer(24);
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    // 启用 GL debug output(Mesa / NVIDIA 都支持)
    debug_message::enable_default_debug();

    // 加载一张 PNG 作为 layer0(用 image crate,这里简化为代码生成)
    let (tex0, tex1) = make_layer_textures(&display);

    let verts = vec![
        Vertex { position: [-1., -1.], uv: [0., 0.] },
        Vertex { position: [ 1., -1.], uv: [1., 0.] },
        Vertex { position: [-1.,  1.], uv: [0., 1.] },
        Vertex { position: [ 1.,  1.], uv: [1., 1.] },
    ];
    let vbuf = glium::VertexBuffer::new(&display, &verts).unwrap();
    let indices = index::NoIndices(index::PrimitiveType::TriangleStrip);

    // 关键:合成 shader 带 epsilon 修法和 texelFetch(虽然合成 pass 不直接用)
    // 这里合成 shader 显示 layer0/layer1,epsilon 主要在 peel shader
    let program = program!(&display,
        330 es => {
            vertex: r#"
                #version 330
                in vec2 position; in vec2 uv;
                out vec2 v_uv;
                void main() { v_uv = uv; gl_Position = vec4(position, 0., 1.); }
            "#,
            fragment: r#"
                #version 330
                in vec2 v_uv; out vec4 frag;
                uniform sampler2D layer0;
                uniform sampler2D layer1;
                uniform int debug_view;
                void main() {
                    vec4 c0 = texture(layer0, v_uv);
                    vec4 c1 = texture(layer1, v_uv);
                    if (debug_view == 0) {
                        frag = vec4(c0.rgb, 1.);
                    } else if (debug_view == 1) {
                        frag = vec4(c1.rgb, 1.);
                    } else {
                        vec3 rgb = c0.rgb * c0.a + c1.rgb * c1.a * (1.0 - c0.a);
                        float a = c0.a + c1.a * (1.0 - c0.a);
                        if (a > 1e-6) rgb /= a;
                        frag = vec4(rgb, 1.);
                    }
                }
            "#,
        }).unwrap();

    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent, KeyboardInput, ElementState, VirtualKeyCode};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        match event {
            Event::WindowEvent { event: WindowEvent::KeyboardInput {
                input: KeyboardInput {
                    state: ElementState::Pressed,
                    virtual_keycode: Some(key), ..
                }, ..
            }, .. } => {
                match key {
                    VirtualKeyCode::Key1 => { DEBUG_VIEW.store(0, Ordering::Relaxed); println!("View: layer0"); }
                    VirtualKeyCode::Key2 => { DEBUG_VIEW.store(1, Ordering::Relaxed); println!("View: layer1"); }
                    VirtualKeyCode::Key3 => { DEBUG_VIEW.store(2, Ordering::Relaxed); println!("View: composite"); }
                    VirtualKeyCode::Escape => *control_flow = ControlFlow::Exit,
                    _ => {}
                }
            }
            Event::RedrawRequested(_) => {
                let mut target = display.draw();
                target.clear_color(0.1, 0.1, 0.1, 1.0);
                let view = DEBUG_VIEW.load(Ordering::Relaxed);
                let uniforms = uniform! {
                    layer0: &tex0,
                    layer1: &tex1,
                    debug_view: view as i32,
                };
                target.draw(&vbuf, &indices, &program, &uniforms,
                    &Default::default()).unwrap();
                target.finish().unwrap();
            }
            Event::WindowEvent { event: WindowEvent::CloseRequested, .. } => {
                *control_flow = ControlFlow::Exit;
            }
            _ => {}
        }
    });
}

fn make_layer_textures(display: &glium::Display) -> (texture::Texture2d, texture::Texture2d) {
    let (w, h) = (256u32, 256u32);
    let p0: Vec<[f32; 4]> = (0..w*h).map(|i| {
        let x = (i % w) as f32 / w as f32;
        [x, 0.2, 0.2, 0.6]  // 半透明红色梯度
    }).collect();
    let p1: Vec<[f32; 4]> = (0..w*h).map(|i| {
        let y = (i / w) as f32 / h as f32;
        [0.2, 0.2, y, 0.6]  // 半透明蓝色梯度
    }).collect();
    let make = |pixels: Vec<[f32; 4]>| {
        let raw = texture::RawImage2d {
            data: std::borrow::Cow::Owned(bytemuck::cast_slice(&pixels).to_vec()),
            width: w, height: h,
            format: texture::ClientFormat::F32F32F32F32,
        };
        texture::Texture2d::with_format(display, raw,
            texture::UncompressedFloatFormat::F32F32F32F32,
            texture::MipmapsOption::NoMipmap).unwrap()
    };
    (make(p0), make(p1))
}
```

**关键点**:
- `debug_message::enable_default_debug()` — 启用 OpenGL 的 debug output,任何 GL 错误会打到 stderr
- `bytemuck::cast_slice` — 安全地把 `&[[f32; 4]]` 转为 `&[u8]`(字节切片)
- 按键切换用 `AtomicUsize`,事件回调里改值,渲染循环里读
