
# Day 285 · 可遍历物的事务性占据

> "两个 entity 想同时占据同一个 traversable"——这个看似简单的冲突,在并发 / 多 entity 场景下变得复杂。今天 Casey 用**事务**(transaction)模型解决:占据要么全部成功,要么全部失败,不会出现"半个占据"。

## 0 · 为什么要有这一天

你的游戏现在有 traversable 概念(Day 270)和 entity 系统(Day 277)。每个 entity 站在某个 traversable 上。但是:

- 玩家想走到 tile A,怪物也想走到 tile A
- 一个 pickup(血瓶)在 tile B,玩家想走过去捡
- 两个怪物同时想走到 tile C(它们 AI 都看到玩家在那里)

这些"目标冲突"怎么解决?

**朴素做法**:每个 entity 独立 update,各自决定下一步走到哪。问题:**race condition**(竞争条件)。Entity 1 update 时,看到 tile A 是空的,决定走过去。Entity 2 也 update,看到 tile A 是空的,也决定走过去。结果两个 entity 同时站在 tile A,逻辑错乱。

**强制顺序**:按 entity_id 顺序 update,前面的优先。问题:某些 entity 永远抢不到资源(饥饿)。

**事务模型**:**先全部提交意图,后统一判定冲突**。所有 entity 同时声明"我想走到 tile X",系统检查冲突,无冲突的全部接受,有冲突的回滚(留在原位)。

这就是数据库事务的 ACID 思想应用到游戏逻辑。今天 Casey 实现简化版本。

心理锚点:做完这个,你的游戏支持多 entity 并发移动,不会出现"两个 entity 卡在同一格"。

## 1 · Casey 今天做了什么

Casey 改 entity 移动模型:

1. 每个 entity 有 `current_tile` 和 `desired_tile`(想去的格子)
2. update 阶段 1:每个 entity 独立算 desired_tile(基于 AI / 输入)
3. update 阶段 2:系统收集所有 desired,检测冲突
4. update 阶段 3:无冲突的 commit(更新 current_tile);冲突的 rollback(保持 current_tile)
5. 标记 tile 占用状态:`occupied: HashSet<TilePos>`

Casey 演示了"两个怪物都想走到玩家"的场景:它们各自算 desired,系统发现 desired 重叠,只有一个成功,另一个停在原位(等下一帧重试)。

## 2 · 心智模型

### 类比:电影院选座

电影院在线选座:

1. 你看到 A1 座空着,选了
2. 同时另一人选了 A1
3. 系统判断:谁先点谁拿到,另一个收到"A1 已被占"

更复杂的版本:**预订系统**。所有用户先提交"我想要 A1",系统收集所有请求,统一处理冲突。

游戏的事务性占据是这个模型:**先全部声明意图,后统一判定**。

### 严谨原理:两阶段提交(2PC)

数据库事务的经典算法:

#### 阶段 1:准备(prepare)

每个参与者声明"我想做 X"。系统收集所有声明。

```rust
struct DesiredMove {
    entity_id: EntityId,
    from: TilePos,
    to: TilePos,
}

// 收集所有 entity 的 desired
let mut desired_moves: Vec<DesiredMove> = Vec::new();
for entity in &entities {
    if let Some(target) = entity.compute_desired_tile() {
        desired_moves.push(DesiredMove {
            entity_id: entity.id,
            from: entity.current_tile,
            to: target,
        });
    }
}
```

#### 阶段 2:冲突检测

检查:有没有两个 entity 想去同一个 tile?

```rust
let mut desired_to: HashMap<TilePos, Vec<EntityId>> = HashMap::new();
for m in &desired_moves {
    desired_to.entry(m.to).or_default().push(m.entity_id);
}

// 找冲突
let mut conflicts: HashSet<TilePos> = HashSet::new();
for (tile, entities) in &desired_to {
    if entities.len() > 1 {
        conflicts.insert(*tile);
    }
}
```

#### 阶段 3:提交(commit) / 回滚(rollback)

无冲突的提交,有冲突的回滚(或按某种策略选一个赢家):

```rust
for m in &desired_moves {
    if conflicts.contains(&m.to) {
        // 冲突:选第一个 entity 当赢家(简单策略)
        let winner = desired_to[&m.to][0];
        if m.entity_id == winner {
            // 提交
            commit_move(&mut entities, m);
        } else {
            // 回滚:保持原位
        }
    } else {
        // 无冲突:提交
        commit_move(&mut entities, m);
    }
}
```

#### tile 占用状态

为了避免下一帧的 entity 看到"已经有人走过去了",维护一个 `occupied: HashSet<TilePos>`:

```rust
struct World {
    occupied: HashSet<TilePos>,
    // ...
}

// 每帧开始:清空 occupied
self.occupied.clear();
// 阶段 3 后:更新 occupied
for entity in &entities {
    self.occupied.insert(entity.current_tile);
}

// entity.compute_desired_tile 时:
fn compute_desired_tile(&self, world: &World) -> Option<TilePos> {
    let target = ...;  // AI 决定
    if world.occupied.contains(&target) {
        return None;  // 已被占,放弃
    }
    Some(target)
}
```

这样下一帧的 entity 知道哪些 tile 已被占,不会再声明 desired。

### 冲突解决策略

冲突时选赢家,几种策略:

#### 1. 先到先得(按 ID 顺序)

```rust
entities.sort_by_key(|e| e.id);
```

低 ID 优先。简单,但高 ID entity 永远吃亏。

#### 2. 随机

```rust
let winner = entities.random_choice();
```

公平,但可能某个 entity 永远抢不到(运气问题)。

#### 3. 优先级

```rust
// 玩家 > NPC > 怪物
entities.sort_by_key(|e| e.priority);
```

玩家优先,然后 NPC,然后怪物。业界常用。

#### 4. 距离优先

```rust
// 离目标更近的优先
entities.sort_by_key(|e| distance(e.pos, target.pos));
```

合理(更近的更容易到达)。

#### 5. 速度优先

```rust
// 速度快的优先(它能先到)
entities.sort_by_key(|e| -e.speed);
```

Casey 用 ID 顺序(简单),后面可以改。

### 死锁避免

考虑循环冲突:

- Entity A 想从 tile 1 到 tile 2
- Entity B 想从 tile 2 到 tile 3
- Entity C 想从 tile 3 到 tile 1

如果三个都"互锁",谁也不能动。解决:

- **随机回退**:冲突时随机延迟 N 帧
- **优先级 + 重试**:低优先级退让,等下一帧
- **交换**:相邻 entity 互换位置(A 去 B 的位置,B 去 A 的位置)

Casey 用"随机延迟"(简化版:不加,直接冲突时双方都退)。

### 事务的边界

事务可以包含多个操作:

```rust
enum TransactionOp {
    Move { from: TilePos, to: TilePos },
    Pickup { item: EntityId },
    Drop { item: EntityId },
    Attack { target: EntityId },
}

struct Transaction {
    entity_id: EntityId,
    ops: Vec<TransactionOp>,
}
```

一个事务内的操作要么全部成功,要么全部失败。这保证了**原子性**(atomicity)。

Casey 的 HH 简化:一个事务只有一个 move op。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

事务性移动在策略游戏 / 回合制游戏很常见:

- **Civilization**:每个 unit 占一格,不能重叠
- **XCOM**:turn-based 移动,冲突时按 initiative 决定
- **Into the Breach**:完美信息,所有单位移动按玩家选择

实时游戏(A / RPG)通常允许重叠(碰撞由物理处理),不强制 tile 占据。Casey 的 HH 是 2D 动作 + tile 移动混合,需要事务。

#### 锁 vs 事务

游戏开发两种同步:

- **锁**:每个 tile 一个 lock,entity acquire 后才能进入。问题:deadlock(循环等待)
- **事务**(今天):无锁,统一处理冲突。简单,但每个 entity 可能要回滚

现代游戏倾向事务(更灵活)。

### 3.2 · 🐧 Linux 系统编程视角

Linux 内核大量用事务思想:

- **数据库**:PostgreSQL / MySQL 的 MVCC(Multi-Version Concurrency Control)
- **文件系统**:ext4 的 journal(日志)= write-ahead log 的 transaction
- **Rust std**:所有 atomic 操作是事务(原子 read-modify-write)

#### Linux 文件系统的 journal

ext4 写文件时:

1. 先把"我要做 X"写到 journal
2. 实际做 X
3. journal 标记 commit

如果第 2 步崩溃,启动时从 journal 恢复(要么 redo 要么 undo)。这就是 write-ahead log(WAL),和游戏事务一致。

```bash
# 看 ext4 journal
dumpe2fs /dev/sda1 | grep -i journal
# 输出 journal 的大小、inode

# 看 PostgreSQL WAL
ls /var/lib/postgres/data/pg_wal/
```

#### compare-and-swap(CAS)

Linux / Rust 的 atomic 操作用 CAS:

```rust
use std::sync::atomic::{AtomicU32, Ordering};
let counter = AtomicU32::new(0);

// 原子 +1
counter.fetch_add(1, Ordering::SeqCst);

// CAS:比较并交换
let old = counter.load(Ordering::SeqCst);
loop {
    let new = old + 1;
    match counter.compare_exchange(old, new, Ordering::SeqCst, Ordering::SeqCst) {
        Ok(_) => break,  // 成功
        Err(actual) => { old = actual; }  // 重试
    }
}
```

CAS 是事务的微观版本——"我希望值是 X,如果是就改成 Y"。游戏的事务是宏观版本。

### 3.3 · 🦀 Rust 生态视角

Rust 表达事务几个考量:

#### 两阶段用 Vec

```rust
let desired = collect_desired(&entities);
let conflicts = detect_conflicts(&desired);
commit_or_rollback(&mut entities, &desired, &conflicts);
```

简单,Casey 用这个。

#### Result + ?

```rust
fn try_move(entity: &mut Entity, target: TilePos, world: &World) -> Result<(), MoveError> {
    if world.occupied.contains(&target) {
        return Err(MoveError::Occupied);
    }
    entity.current_tile = target;
    Ok(())
}
```

每个 entity 独立 try_move,失败自动回滚(状态不变)。

#### STM(Software Transactional Memory)

Rust 的 stm / tokio STM 库提供高级事务:

```rust
use stm::stm;

stm(|| {
    let tile = world.occupied.read();
    if tile.contains(&target) {
        stm::abort(())
    }
    world.occupied.write().insert(target);
    Ok(())
}).unwrap();
```

事务自动 retry,但开销大。游戏开发很少用。

#### SQL-style ACID

如果你的游戏数据用 SQLite,可以直接用数据库事务:

```rust
let tx = conn.transaction()?;
tx.execute("UPDATE entities SET tile=? WHERE id=?", &[target, id])?;
// ... 其他操作
tx.commit()?;
```

完整 ACID 保证,但游戏数据通常不需要持久化这么严格。

### 3.4 · 软件工程:ACID 原则

事务的 ACID:

- **Atomicity**(原子性):全部成功或全部失败
- **Consistency**(一致性):事务前后数据满足约束
- **Isolation**(隔离性):并发事务互不干扰
- **Durability**(持久性):提交后不丢失

游戏的 tile 占据事务满足:

- A:entity 要么成功到新 tile,要么保持原位
- C:任何时刻一个 tile 只能一个 entity
- I:多 entity 并发 desired 互不破坏
- D:(简化,通常不做持久化)

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么用"两阶段提交"而不是"每个 entity acquire tile lock"?给出至少 3 个理由。

**参考解答**:
1. **避免 deadlock**:lock 系统 A 等 B,B 等 A,死锁。两阶段没有"等待",冲突直接回滚
2. **简化代码**:lock 要 try / fail / retry 逻辑,事务只要 desired + commit
3. **公平性**:lock 系统中先 acquire 的永远赢;事务可以按 ID / 优先级 / 随机决定赢家,更灵活
4. **批量优化**:事务收集所有 desired 后可以批量优化(按 chunk 处理),lock 是串行
5. **可恢复**:事务回滚简单(保持原状态);lock 失败要释放已 acquire 的部分,容易出错
6. **业界标准**:数据库 / 版本控制(git)/ 分布式系统都用事务,lock 用得越来越少

### Lv2 · 动手实践

**题**:实现两阶段提交的 entity 移动。

测试场景:

- 3 个 entity 都想走到 tile (5, 5)
- 应该只有一个成功,其他保持原位

完成标准:无冲突的全 commit,冲突的回滚。

**参考解答**:

```rust
use std::collections::{HashMap, HashSet};

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct EntityId(u32);

#[derive(Clone, Debug)]
struct Entity {
    id: EntityId,
    current: TilePos,
    desired: Option<TilePos>,
}

#[derive(Clone, Debug)]
struct DesiredMove {
    entity_id: EntityId,
    from: TilePos,
    to: TilePos,
}

struct World {
    entities: Vec<Entity>,
}

impl World {
    fn new() -> Self { Self { entities: Vec::new() } }

    fn add(&mut self, id: EntityId, tile: TilePos) {
        self.entities.push(Entity {
            id, current: tile, desired: None,
        });
    }

    fn set_desired(&mut self, id: EntityId, target: TilePos) {
        if let Some(e) = self.entities.iter_mut().find(|e| e.id == id) {
            e.desired = Some(target);
        }
    }

    /// 两阶段提交:resolve 所有 desired
    fn resolve_moves(&mut self) {
        // 阶段 1:收集 desired
        let desired_moves: Vec<DesiredMove> = self.entities.iter()
            .filter_map(|e| e.desired.map(|to| DesiredMove {
                entity_id: e.id,
                from: e.current,
                to,
            }))
            .collect();

        // 阶段 2:检测冲突
        let mut desired_to: HashMap<TilePos, Vec<EntityId>> = HashMap::new();
        for m in &desired_moves {
            desired_to.entry(m.to).or_default().push(m.entity_id);
        }

        // 阶段 3:解决冲突 + commit
        for m in &desired_moves {
            let entities_for_tile = &desired_to[&m.to];
            let should_commit = if entities_for_tile.len() == 1 {
                // 无冲突,直接 commit
                true
            } else {
                // 有冲突:按 ID 排序,最小 ID 赢
                let mut sorted = entities_for_tile.clone();
                sorted.sort();
                sorted[0] == m.entity_id
            };

            if should_commit {
                // 检查目标是否被"留在原位的 entity"占据
                // (entity A 想去 tile X,但 B 已经站在 tile X 且没移动)
                let occupied_by_static = self.entities.iter()
                    .any(|e| e.id != m.entity_id && e.current == m.to && e.desired.is_none());
                if !occupied_by_static {
                    if let Some(e) = self.entities.iter_mut().find(|e| e.id == m.entity_id) {
                        e.current = m.to;
                    }
                }
            }
            // rollback:什么都不做,desired 自动在下帧重置
        }

        // 清空所有 desired(下一帧重新声明)
        for e in &mut self.entities {
            e.desired = None;
        }
    }

    fn print(&self) {
        let mut sorted = self.entities.clone();
        sorted.sort_by_key(|e| e.id);
        for e in &sorted {
            println!("  Entity {:?}: current={:?} desired={:?}", e.id, e.current, e.desired);
        }
    }
}

fn main() {
    let mut world = World::new();

    // 3 个 entity 都想走到 (5, 5)
    world.add(EntityId(1), TilePos(0, 0));
    world.add(EntityId(2), TilePos(10, 10));
    world.add(EntityId(3), TilePos(20, 20));

    world.set_desired(EntityId(1), TilePos(5, 5));
    world.set_desired(EntityId(2), TilePos(5, 5));
    world.set_desired(EntityId(3), TilePos(5, 5));

    println!("Before resolve:");
    world.print();

    world.resolve_moves();

    println!("\nAfter resolve:");
    world.print();

    // 验证:只有一个 entity(最小 ID = 1)成功到 (5, 5)
    let at_target: Vec<_> = world.entities.iter()
        .filter(|e| e.current == TilePos(5, 5))
        .collect();
    assert_eq!(at_target.len(), 1);
    assert_eq!(at_target[0].id, EntityId(1));
    println!("\nEntity 1 won the conflict!");

    // 测试 2:无冲突的情况
    world.set_desired(EntityId(2), TilePos(11, 10));
    world.set_desired(EntityId(3), TilePos(21, 20));
    world.resolve_moves();

    println!("\nAfter non-conflicting moves:");
    world.print();

    let e2 = world.entities.iter().find(|e| e.id == EntityId(2)).unwrap();
    assert_eq!(e2.current, TilePos(11, 10));
    let e3 = world.entities.iter().find(|e| e.id == EntityId(3)).unwrap();
    assert_eq!(e3.current, TilePos(21, 20));
    println!("\nNon-conflicting moves all committed!");
}
```

**每行解释**:
- 阶段 1 收集 desired 是不可变借用,符合 Rust borrow 规则
- 阶段 2 用 HashMap 检测冲突,O(N)
- 阶段 3 按 ID 排序选赢家,简单确定
- `occupied_by_static` 检测:有 entity 已经站在目标位置(没移动),冲突
- resolve 后清空 desired,下帧重新声明

## 8 · Rust / Arch 落地代码

### 完整可跑:事务性占据 + 多 entity

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, KeyRepeat, Window, WindowOptions};
use std::collections::{HashMap, HashSet};
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const TILE_SIZE: f32 = 32.0;

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct EntityId(u32);

#[derive(Clone, Debug)]
struct Entity {
    id: EntityId,
    current: TilePos,
    desired: Option<TilePos>,
    color: u32,
}

#[derive(Clone, Debug)]
struct DesiredMove {
    entity_id: EntityId,
    from: TilePos,
    to: TilePos,
}

struct World {
    entities: Vec<Entity>,
    map_w: i32,
    map_h: i32,
    walls: HashSet<TilePos>,
}

impl World {
    fn new(map_w: i32, map_h: i32) -> Self {
        Self {
            entities: Vec::new(),
            map_w, map_h,
            walls: HashSet::new(),
        }
    }

    fn add_entity(&mut self, id: EntityId, tile: TilePos, color: u32) {
        self.entities.push(Entity { id, current: tile, desired: None, color });
    }

    fn is_traversable(&self, tile: TilePos) -> bool {
        if tile.0 < 0 || tile.1 < 0 || tile.0 >= self.map_w || tile.1 >= self.map_h {
            return false;
        }
        !self.walls.contains(&tile)
    }

    /// AI:朝玩家方向算 desired
    fn ai_desired_towards(&self, monster_id: EntityId, target: TilePos) -> Option<TilePos> {
        let monster = self.entities.iter().find(|e| e.id == monster_id)?;
        let dx = target.0 - monster.current.0;
        let dy = target.1 - monster.current.1;

        // 优先朝大方向走一步
        let candidates: Vec<TilePos> = if dx.abs() > dy.abs() {
            vec![
                TilePos(monster.current.0 + dx.signum(), monster.current.1),
                TilePos(monster.current.0, monster.current.1 + dy.signum()),
            ]
        } else {
            vec![
                TilePos(monster.current.0, monster.current.1 + dy.signum()),
                TilePos(monster.current.0 + dx.signum(), monster.current.1),
            ]
        };

        for c in candidates {
            if self.is_traversable(c) {
                return Some(c);
            }
        }
        None
    }

    /// 两阶段提交
    fn resolve_moves(&mut self) {
        let desired_moves: Vec<DesiredMove> = self.entities.iter()
            .filter_map(|e| e.desired.map(|to| DesiredMove {
                entity_id: e.id, from: e.current, to,
            }))
            .collect();

        // 检测冲突
        let mut desired_to: HashMap<TilePos, Vec<EntityId>> = HashMap::new();
        for m in &desired_moves {
            desired_to.entry(m.to).or_default().push(m.entity_id);
        }

        // 已被静态 entity 占据的 tile
        let static_occupied: HashSet<TilePos> = self.entities.iter()
            .filter(|e| e.desired.is_none())
            .map(|e| e.current)
            .collect();

        // 解决 + commit
        for m in &desired_moves {
            let entities_for_tile = &desired_to[&m.to];
            let should_commit = if entities_for_tile.len() == 1 {
                true
            } else {
                let mut sorted = entities_for_tile.clone();
                sorted.sort();
                sorted[0] == m.entity_id
            };

            if should_commit && !static_occupied.contains(&m.to) {
                if let Some(e) = self.entities.iter_mut().find(|e| e.id == m.entity_id) {
                    e.current = m.to;
                }
            }
        }

        // 清空 desired
        for e in &mut self.entities {
            e.desired = None;
        }
    }
}

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, x: i32, y: i32, w: i32, h: i32, color: u32) {
    for py in y.max(0)..(y + w).min(buf_h as i32) {
        for px in x.max(0)..(x + w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Transactional Occupation", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();

    let map_w = 25;
    let map_h = 18;
    let mut world = World::new(map_w, map_h);

    // 玩家在 (3, 3)
    let player_id = EntityId(1);
    world.add_entity(player_id, TilePos(3, 3), 0xFFFF6040);

    // 怪物在远处
    world.add_entity(EntityId(2), TilePos(15, 5), 0xFFA040FF);
    world.add_entity(EntityId(3), TilePos(15, 10), 0xFFA040FF);
    world.add_entity(EntityId(4), TilePos(20, 7), 0xFFA040FF);

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32().min(0.05);
        last_time = now;
        let _ = dt;

        // 玩家移动
        let player = world.entities.iter().find(|e| e.id == player_id).unwrap();
        let mut new_tile = player.current;
        if window.is_key_pressed(Key::W, KeyRepeat::No) { new_tile.1 -= 1; }
        if window.is_key_pressed(Key::S, KeyRepeat::No) { new_tile.1 += 1; }
        if window.is_key_pressed(Key::A, KeyRepeat::No) { new_tile.0 -= 1; }
        if window.is_key_pressed(Key::D, KeyRepeat::No) { new_tile.0 += 1; }

        if new_tile != player.current && world.is_traversable(new_tile) {
            if let Some(p) = world.entities.iter_mut().find(|e| e.id == player_id) {
                p.desired = Some(new_tile);
            }
        }

        // 怪物 AI:朝玩家走
        let player_tile = world.entities.iter().find(|e| e.id == player_id).unwrap().current;
        for monster_id in [EntityId(2), EntityId(3), EntityId(4)] {
            if let Some(target) = world.ai_desired_towards(monster_id, player_tile) {
                if let Some(m) = world.entities.iter_mut().find(|e| e.id == monster_id) {
                    m.desired = Some(target);
                }
            }
        }

        // 解决所有 desired
        world.resolve_moves();

        // 渲染
        for px in buffer.iter_mut() { *px = 0xFF000000; }

        // tile map
        for y in 0..map_h {
            for x in 0..map_w {
                let t = TilePos(x, y);
                let is_wall = !world.is_traversable(t);
                let color = if is_wall { 0xFF808080 } else { 0xFF303030 };
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          x * TILE_SIZE as i32, y * TILE_SIZE as i32,
                          TILE_SIZE as i32, TILE_SIZE as i32, color);
            }
        }

        // 显示 desired(黄色边框)
        for e in &world.entities {
            if let Some(d) = e.desired {
                let bx = d.0 * TILE_SIZE as i32;
                let by = d.1 * TILE_SIZE as i32;
                draw_rect(&mut buffer, WIDTH, HEIGHT, bx, by, TILE_SIZE as i32, 2, 0xFFFFFF40);
                draw_rect(&mut buffer, WIDTH, HEIGHT, bx, by + TILE_SIZE as i32 - 2, TILE_SIZE as i32, 2, 0xFFFFFF40);
                draw_rect(&mut buffer, WIDTH, HEIGHT, bx, by, 2, TILE_SIZE as i32, 0xFFFFFF40);
                draw_rect(&mut buffer, WIDTH, HEIGHT, bx + TILE_SIZE as i32 - 2, by, 2, TILE_SIZE as i32, 0xFFFFFF40);
            }
        }

        // entity
        for e in &world.entities {
            let cx = e.current.0 * TILE_SIZE as i32 + (TILE_SIZE / 2.0) as i32;
            let cy = e.current.1 * TILE_SIZE as i32 + (TILE_SIZE / 2.0) as i32;
            draw_rect(&mut buffer, WIDTH, HEIGHT, cx - 8, cy - 8, 16, 16, e.color);
        }

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- 两阶段:desired 收集(不可变借用)+ commit(可变借用)
- `desired_to.entry(key).or_default()` 简化 HashMap 操作
- `static_occupied` 防止 dynamic entity 移到 static entity 上
- 玩家 input 和 AI 都设 desired,resolve_moves 统一处理
- 黄色边框显示"想去的格子",直观看到冲突

**Troubleshooting**:

- 怪物互相穿过 — 检查 resolve_moves 是否正确处理冲突
- 玩家被怪物覆盖 — 玩家的 desired 也要参与 resolve,不能直接 commit
- 怪物卡住不动 — 多个怪物一直想去同一格,优先级低的永远失败。加随机延迟解决
