
# Day 278 · 实体存储移到世界区块

> 昨天的稀疏实体系统是全局的——所有 entity 在一个 `Vec<Entity>` 里。今天 Casey 把它**按地理位置分区**:每个世界 chunk 管自己内部的 entity。这是大世界游戏(开放世界 / 流式加载)的基础设施。

## 0 · 为什么要有这一天

你的游戏地图目前大概是一个屏(800×600)。entity 数量是几十个,全部存一个 Vec 没问题。

但想象你的游戏是一个**大世界**——比如 Zelda 的整个 Hyrule,地图 100×100 屏(80000×60000 像素)。这时:

- 总 entity 数可能上万(每屏几十个 NPC / 怪物 / 拾取物)
- 玩家一次只能看到周围 1-2 屏
- 远处的 entity 不需要 update / render
- 玩家移动时,新的 chunk 要加载,旧的 chunk 要卸载

如果把所有 entity 存一个 Vec:

1. **update 慢**:每帧遍历 1 万个 entity,大部分不在视野内,白费 CPU
2. **内存浪费**:存所有 entity 的状态,99% 时间玩家不在那里
3. **存档 / 读档**:保存整个 world 的 entity 数据,慢
4. **AI 路径搜索**:全地图 A* 在万级 entity 下不现实

解决:**按地理位置分区**。世界切成 chunk(比如 32×32 tile 一块),每个 chunk 管自己的 entity。玩家附近 chunk 的 entity 是 active 的(更新 / 渲染),远处 chunk 是 inactive 的(可能 unload 到磁盘)。

这就是 **streaming world** 架构,Zelda BOTW / Skyrim / Minecraft 都用。

今天 Casey 做第一步:把昨天的 `Vec<Entity>` 拆成"每 chunk 一个 entity 列表"。

心理锚点:做完这个,你的游戏支持无限大世界,内存占用只取决于"加载的 chunk 数",不取决于"总 entity 数"。

## 1 · Casey 今天做了什么

Casey 重构 world 结构:

1. 定义 `Chunk`:`{ tile_x: i32, tile_y: i32, entities: Vec<EntitySlot> }`
2. World 不再存全局 entities,改存 `HashMap<ChunkPos, Chunk>`
3. spawn / despawn 时先算 entity 在哪个 chunk,再插入对应 chunk 的 entities
4. update / render 时只遍历"加载的 chunk"(附近几个)
5. 远处 chunk 不加载(HashMap 不含),走到时按需加载

Casey 处理了"entity 跨 chunk 移动"的边界情况:

- entity 从 chunk A 移到 chunk B 的边界
- 当 entity 的 tile 坐标跨过 chunk 边界时,从 A 移除,插入 B
- 这个"移动 entity 跨 chunk"操作要小心,避免迭代时修改

最后 Casey 提到"加载 / 卸载"的简化:**目前所有 chunk 都加载**,只是结构上分了区。真正的"按需加载"在 Day 280 流式模拟做。

## 2 · 心智模型

### 类比:图书馆的书架

图书馆有几千本书,但读者一次只看几本。图书馆不会把所有书堆一个桌子上——按主题分区:小说区、历史区、科学区,每区一个书架。读者找小说,只去小说区。

游戏世界也是:玩家一次只在某个区域,只需要那个区域的 entity。其他区域的书架(entity)存在但不需要"展开"。

更精细:每个书架是一个 chunk,书是 entity。书架本身是稀疏的(没书的主题就没有书架),只有有书的主题才放书架。

### 严谨原理:Chunk-based 存储

#### Chunk 坐标

世界切成方格,每格是 chunk。Chunk 坐标和 tile 坐标的关系:

```rust
const CHUNK_SIZE: i32 = 32;  // 32x32 tile per chunk

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct ChunkPos(i32, i32);  // chunk 坐标

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);  // tile 坐标(world space)

fn tile_to_chunk(t: TilePos) -> ChunkPos {
    ChunkPos(
        t.0.div_euclid(CHUNK_SIZE),  // 欧几里得除法,处理负数
        t.1.div_euclid(CHUNK_SIZE),
    )
}

fn chunk_to_tile_origin(c: ChunkPos) -> TilePos {
    TilePos(c.0 * CHUNK_SIZE, c.1 * CHUNK_SIZE)
}
```

注意 `div_euclid`(欧几里得除法):对负数也返回正确的商。`-1.div_euclid(32) = -1`(因为 -1 = -1*32 + 31),而 `-1 / 32 = 0`(Rust 默认 truncate)。

#### World 结构

```rust
use std::collections::HashMap;

struct World {
    chunks: HashMap<ChunkPos, Chunk>,
    // ...
}

#[derive(Clone, Debug)]
struct Chunk {
    pos: ChunkPos,
    entities: Vec<EntitySlot>,  // 这个 chunk 里的 entity
}
```

`HashMap<ChunkPos, Chunk>` 让"没加载的 chunk"自然不存在(map 没那个 key)。

#### Spawn / despawn

```rust
impl World {
    fn spawn(&mut self, kind: EntityKind, tile_pos: TilePos) -> EntityId {
        let chunk_pos = tile_to_chunk(tile_pos);
        let chunk = self.chunks.entry(chunk_pos).or_insert_with(|| Chunk {
            pos: chunk_pos,
            entities: Vec::new(),
        });
        // ... 插入 entity 到 chunk.entities
    }
}
```

`entry(key).or_insert_with(closure)` 是 Rust HashMap 标准 idiom:不存在则插入默认值。

#### Entity 跨 chunk 移动

```rust
impl World {
    fn move_entity(&mut self, id: EntityId, new_tile: TilePos) {
        let old_chunk = self.find_entity_chunk(id);  // 找 entity 在哪个 chunk
        let new_chunk = tile_to_chunk(new_tile);

        if old_chunk != new_chunk {
            // 跨 chunk:从旧 chunk 移除,插入新 chunk
            let entity = self.chunks.get_mut(&old_chunk).unwrap()
                .remove_entity(id);
            self.chunks.entry(new_chunk).or_insert_with(...)
                .insert_entity(entity);
        } else {
            // 同 chunk:只更新位置
            self.chunks.get_mut(&old_chunk).unwrap()
                .update_entity_pos(id, new_tile);
        }
    }
}
```

跨 chunk 移动是**关键操作**,要小心:

1. 先从旧 chunk 取出 entity(移动语义,避免 clone)
2. 再插入新 chunk
3. EntityId 保持不变(generation 也保持)

#### 加载范围

```rust
impl World {
    fn loaded_chunk_range(&self, player_tile: TilePos, radius: i32) -> Vec<ChunkPos> {
        let player_chunk = tile_to_chunk(player_tile);
        let mut result = Vec::new();
        for dx in -radius..=radius {
            for dy in -radius..=radius {
                result.push(ChunkPos(player_chunk.0 + dx, player_chunk.1 + dy));
            }
        }
        result
    }

    fn update_active(&mut self, player_tile: TilePos) {
        let active_chunks = self.loaded_chunk_range(player_tile, 2);  // 5x5 chunks
        // 加载新进入范围的 chunk(从磁盘)
        for pos in &active_chunks {
            if !self.chunks.contains_key(pos) {
                self.load_chunk(*pos);
            }
        }
        // 卸载离开范围的 chunk(写回磁盘)
        let loaded: Vec<ChunkPos> = self.chunks.keys().copied().collect();
        for pos in loaded {
            if !active_chunks.contains(&pos) {
                self.unload_chunk(pos);
            }
        }
    }
}
```

`radius=2` 加载玩家周围 5x5 = 25 个 chunk。每 chunk 32x32 tile,共 80x80 tile 范围,够看到视野外的内容。

#### 边界处的特殊处理

实体在 chunk 边界附近时,要考虑:

- **碰撞检测**:不能只查本 chunk,要查相邻 chunk(物体可能跨边界)
- **AI 视野**:视野范围可能跨 chunk
- **渲染**:可见 chunk 加上边界 chunk

简单做法:**update 时多查 1 个 chunk 边界**(radius + 1)。

### 性能考量

#### Chunk 大小的选择

Chunk 大小影响:

- **太大**(64x64):加载 / 卸载开销大,内存碎片多
- **太小**(8x8):chunk 数量多,HashMap 开销大,跨 chunk 频繁
- **合理**(16x16 或 32x32):平衡点

Minecraft 用 16x16x16(3D),Zelda BOTW 用约 256x256,Casey 用 32x32。

#### HashMap 性能

`HashMap<ChunkPos, Chunk>` 的 lookup 是 O(1) 但常数大(hash 计算 + 链表 / 开放地址)。优化:

- 用 `Vec<Vec<Chunk>>` 2D 数组,固定大小(地图有限)
- 用 `BTreeMap` 替代(有序遍历快,但 lookup O(log N))
- 用稀疏数组 + offset(类似 GPU sparse texture)

Casey 用 HashMap,简单教学。生产项目可能用更复杂结构。

### Load / Unload 流程

#### Load chunk

```rust
fn load_chunk(&mut self, pos: ChunkPos) {
    // 从磁盘读(或程序生成)
    let chunk_data = self.load_from_disk(pos)
        .unwrap_or_else(|| self.generate_chunk(pos));
    self.chunks.insert(pos, chunk_data);
}
```

#### Unload chunk

```rust
fn unload_chunk(&mut self, pos: ChunkPos) {
    if let Some(chunk) = self.chunks.remove(&pos) {
        // 写回磁盘(保存 entity 状态)
        self.save_to_disk(pos, &chunk);
    }
}
```

今天的简化版本:load / unload 不真做磁盘 IO,留个 hook。Day 280+ 实现。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Chunk-based world 是大世界游戏标配:

- **Minecraft**:16x16 chunk,无限生成,玩家附近 always loaded
- **Skyrim**:大 world cell,~ 4x4 单元,内有 NPC / 物品
- **Zelda BOTW**:open world 切成"sector",streaming
- **GTA V**:城市 chunk,玩家穿越时按需加载

业界做法:

- **异步加载**:chunk 在后台线程加载,不卡主线程
- **LOD(level of detail)**:远处 chunk 用低精度模型
- **预生成 + 缓存**:chunk 数据程序生成后缓存,下次直接读
- **Determinate generation**:用 seed 生成,无需存盘(节省 IO)

### 3.2 · 🐧 Linux 系统编程视角

Linux 内核的"分区"思想:

- **页(page)**:4KB 内存一页,虚拟内存按页管理
- **swap area**:内存压力时把页 swap 到磁盘
- **inode 块**:文件系统按 block(4KB)分
- **mmap 区域**:文件按 chunk 映射到虚拟内存

这些和游戏 chunk 同构:**大对象按地理位置(或逻辑位置)分区,按需加载**。

#### Linux 的换页机制

Linux 的 page cache 是天然的 chunk 系统:

```bash
# 看系统的 page cache
free -h
# 输出:
#                total   used    free   shared  buff/cache
# Mem:           16Gi    4Gi     8Gi    0.5Gi   4Gi
# Swap:          8Gi     0Gi     8Gi

# buff/cache 就是 page cache,缓存最近读过的文件块
```

Linux 自动管理"哪些 chunk(页)在内存,哪些在磁盘"。Casey 的 chunk 系统是手工版,但思想一致。

### 3.3 · 🦀 Rust 生态视角

Rust 表达 chunk 几个考量:

#### HashMap

```rust
use std::collections::HashMap;
let chunks: HashMap<ChunkPos, Chunk> = HashMap::new();
```

简单,通用。ChunkPos 是 Hash + Eq。

#### BTreeMap

```rust
use std::collections::BTreeMap;
let chunks: BTreeMap<ChunkPos, Chunk> = BTreeMap::new();
```

有序遍历(可按 chunk 坐标顺序)。lookup 稍慢于 HashMap。

#### 固定大小 2D 数组

```rust
const WORLD_W: usize = 64;
const WORLD_H: usize = 64;
let chunks: [[Option<Chunk>; WORLD_W]; WORLD_H] = [[None; WORLD_W]; WORLD_H];
```

固定大小,索引 O(1)。但要求世界有限。

#### 环形缓冲(玩家移动时滚动)

```rust
let chunks: Vec<Option<Chunk>> = vec![None; (2*RADIUS+1).pow(2)];
fn chunk_index(player_chunk: ChunkPos, target: ChunkPos) -> usize {
    let dx = (target.0 - player_chunk.0 + RADIUS) as usize;
    let dy = (target.1 - player_chunk.1 + RADIUS) as usize;
    dy * (2*RADIUS+1) + dx
}
```

玩家移动时,数组"滚动"——丢弃最远的 row/col,加载新的。Cache 极友好,但实现复杂。

Casey 选 HashMap,够教学。

### 3.4 · 数据结构:稀疏 2D 存储的演化

| 方案 | 内存 | lookup | 适合 |
|---|---|---|---|
| 全 2D 数组 | O(W*H) | O(1) | 小世界 |
| HashMap | O(loaded) | O(1) | 大世界,稀疏 |
| BTreeMap | O(loaded) | O(log N) | 有序遍历 |
| Quad-tree | O(loaded) | O(log N) | 2D 空间索引 |
| Sparse set | O(loaded) | O(1) | ECS 业界 |

Casey 用 HashMap 是合理选择,平衡了简单性和性能。

### Chunk vs Cell

- **Chunk**:均匀方格,每格同大小
- **Cell**:可变大小,手工划分( Skyrim 用)

Chunk 更适合程序生成,Cell 更适合手工设计。

### 边界处理的难度

跨 chunk 操作是大世界游戏的永恒难题:

- **碰撞**:物体跨边界时碰撞检测要查相邻 chunk
- **路径**:A* 跨 chunk 要"边界节点"连接
- **多人游戏**:玩家跨边界要"主权威转移"
- **物理**:joint 约束跨边界

业界用"overlap zone"(相邻 chunk 各存一份边界数据)或"ghost entity"(临时镜像)等 trick。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Casey 用 `HashMap<ChunkPos, Chunk>` 而不是 `Vec<Vec<Chunk>>`?给出至少 3 个理由。

**参考解答**:
1. **稀疏存储**:大世界大部分 chunk 没加载(玩家远处),HashMap 不存这些 key,内存零占用;Vec<Vec> 必须预分配整个世界大小,内存爆炸
2. **支持无限世界**:HashMap key 可以是任意 i32 坐标,世界大小无上限;Vec<Vec> 索引必须非负且有上限
3. **简化 load/unload**:HashMap 用 insert / remove 表达"加载/卸载";Vec<Vec> 要用 Option<Chunk>,代码冗余
4. **可扩展**:HashMap 容易加 metadata(如 chunk 的修改时间),Vec<Vec> 改架构才能加
5. **运行时灵活**:玩家可以传送到任意位置(地图边界外),HashMap 直接支持;Vec<Vec> 拒绝

代价:HashMap 的 lookup 有 hash 开销,比 Vec 直接索引慢。但 chunk 数量少(几百)时,差异不显著。

### Lv2 · 动手实践

**题**:实现 `Chunk` + `World` 结构,带 `tile_to_chunk` 转换 + spawn 在指定 tile。

测试:

- spawn 3 个 entity 在不同 chunk
- 验证 chunks HashMap 有对应条目
- 验证同一 chunk 的两个 entity 在同一个 Vec 里

完成标准:HashMap 大小正确,entity 在对应 chunk。

**参考解答**:

```rust
use std::collections::HashMap;

const CHUNK_SIZE: i32 = 32;

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct ChunkPos(i32, i32);

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

fn tile_to_chunk(t: TilePos) -> ChunkPos {
    ChunkPos(t.0.div_euclid(CHUNK_SIZE), t.1.div_euclid(CHUNK_SIZE))
}

#[derive(Clone, Debug)]
struct EntitySlot {
    id_gen: u32,
    tile: TilePos,
    label: &'static str,
}

#[derive(Clone, Debug, Default)]
struct Chunk {
    entities: Vec<EntitySlot>,
}

struct World {
    chunks: HashMap<ChunkPos, Chunk>,
    next_id: u32,
}

impl World {
    fn new() -> Self {
        Self { chunks: HashMap::new(), next_id: 1 }
    }

    fn spawn(&mut self, tile: TilePos, label: &'static str) -> u32 {
        let chunk_pos = tile_to_chunk(tile);
        let chunk = self.chunks.entry(chunk_pos).or_default();
        let id = self.next_id;
        self.next_id += 1;
        chunk.entities.push(EntitySlot { id_gen: id, tile, label });
        id
    }

    fn print_summary(&self) {
        println!("World has {} chunks:", self.chunks.len());
        let mut sorted: Vec<_> = self.chunks.iter().collect();
        sorted.sort_by_key(|(pos, _)| (pos.0, pos.1));
        for (pos, chunk) in sorted {
            println!("  Chunk({:?}) (origin tile ({},{})): {} entities",
                     pos, pos.0 * CHUNK_SIZE, pos.1 * CHUNK_SIZE,
                     chunk.entities.len());
            for e in &chunk.entities {
                println!("    - id={} tile={:?} label={}", e.id_gen, e.tile, e.label);
            }
        }
    }
}

fn main() {
    let mut world = World::new();

    // spawn 3 个 entity 在不同 chunk
    let _ = world.spawn(TilePos(5, 5), "player");        // chunk (0, 0)
    let _ = world.spawn(TilePos(40, 10), "monster1");     // chunk (1, 0)
    let _ = world.spawn(TilePos(35, 35), "pickup");       // chunk (1, 1)
    let _ = world.spawn(TilePos(45, 38), "monster2");     // chunk (1, 1)(同一 chunk)

    world.print_summary();

    // 验证
    assert_eq!(world.chunks.len(), 3);  // 3 个 chunk
    assert_eq!(world.chunks.get(&ChunkPos(0, 0)).unwrap().entities.len(), 1);
    assert_eq!(world.chunks.get(&ChunkPos(1, 0)).unwrap().entities.len(), 1);
    assert_eq!(world.chunks.get(&ChunkPos(1, 1)).unwrap().entities.len(), 2);  // 同 chunk 两个 entity

    // 测试负坐标
    let _ = world.spawn(TilePos(-5, -5), "edge_monster");  // 应该在 chunk (-1, -1)
    let cp = tile_to_chunk(TilePos(-5, -5));
    assert_eq!(cp, ChunkPos(-1, -1));  // div_euclid 正确处理负数

    println!("\nAfter spawn edge_monster:");
    world.print_summary();
}
```

**每行解释**:
- `div_euclid` 处理负数:`-5.div_euclid(32) = -1`(因为 -5 = -1*32 + 27)
- `entry(key).or_default()` 不存在则用 Default::default() 插入
- Chunk 的 entities 是 Vec,可以装多个 entity
- `next_id` 全局递增,不重复

## 8 · Rust / Arch 落地代码

### 完整可跑:chunk-based world + 玩家移动

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, Window, WindowOptions};
use std::collections::HashMap;
use std::time::Instant;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const TILE_SIZE: f32 = 16.0;
const CHUNK_SIZE: i32 = 16;  // 16x16 tiles per chunk
const LOAD_RADIUS: i32 = 2;  // 加载玩家周围 5x5 chunks

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct ChunkPos(i32, i32);

fn tile_to_chunk(t: TilePos) -> ChunkPos {
    ChunkPos(t.0.div_euclid(CHUNK_SIZE), t.1.div_euclid(CHUNK_SIZE))
}

fn tile_to_world(t: TilePos) -> (f32, f32) {
    ((t.0 as f32 + 0.5) * TILE_SIZE, (t.1 as f32 + 0.5) * TILE_SIZE)
}

fn world_to_tile(x: f32, y: f32) -> TilePos {
    TilePos((x / TILE_SIZE).floor() as i32, (y / TILE_SIZE).floor() as i32)
}

#[derive(Clone, Debug)]
struct EntitySlot {
    id: u32,
    tile: TilePos,
    color: u32,
    size: f32,
    vx: f32,
    vy: f32,
}

#[derive(Clone, Default, Debug)]
struct Chunk {
    entities: Vec<EntitySlot>,
    is_wall: Vec<bool>,  // 16x16 = 256 个 tile
}

impl Chunk {
    fn new() -> Self {
        Self {
            entities: Vec::new(),
            is_wall: vec![false; (CHUNK_SIZE * CHUNK_SIZE) as usize],
        }
    }
    fn is_traversable(&self, local_x: i32, local_y: i32) -> bool {
        if local_x < 0 || local_y < 0 || local_x >= CHUNK_SIZE || local_y >= CHUNK_SIZE {
            return true;  // 边界外假设可走(让 chunk 边界无墙)
        }
        !self.is_wall[(local_y * CHUNK_SIZE + local_x) as usize]
    }
}

struct World {
    chunks: HashMap<ChunkPos, Chunk>,
    next_id: u32,
}

impl World {
    fn new() -> Self {
        Self { chunks: HashMap::new(), next_id: 1 }
    }

    fn ensure_chunk(&mut self, pos: ChunkPos) -> &mut Chunk {
        self.chunks.entry(pos).or_insert_with(|| {
            let mut c = Chunk::new();
            // 简单"程序生成":随机几个墙
            let hash = (pos.0 as u32).wrapping_mul(0x9E3779B9).wrapping_add((pos.1 as u32).wrapping_mul(0x85EBCA6B));
            for i in 0..8 {
                let idx = ((hash.wrapping_mul(i + 1)) as usize) % (CHUNK_SIZE * CHUNK_SIZE) as usize;
                c.is_wall[idx] = true;
            }
            c
        })
    }

    fn spawn_entity(&mut self, tile: TilePos, color: u32, size: f32) -> u32 {
        let chunk_pos = tile_to_chunk(tile);
        let id = self.next_id;
        self.next_id += 1;
        let local_x = tile.0.rem_euclid(CHUNK_SIZE);
        let local_y = tile.1.rem_euclid(CHUNK_SIZE);
        let _ = (local_x, local_y);
        let chunk = self.ensure_chunk(chunk_pos);
        chunk.entities.push(EntitySlot {
            id, tile, color, size, vx: 0.0, vy: 0.0,
        });
        id
    }

    fn is_traversable(&mut self, tile: TilePos) -> bool {
        let chunk_pos = tile_to_chunk(tile);
        let local_x = tile.0.rem_euclid(CHUNK_SIZE);
        let local_y = tile.1.rem_euclid(CHUNK_SIZE);
        let chunk = self.ensure_chunk(chunk_pos);
        chunk.is_traversable(local_x, local_y)
    }

    fn update(&mut self, dt: f32) {
        // 更新所有 entity(简化:不做跨 chunk 移动)
        for chunk in self.chunks.values_mut() {
            for e in chunk.entities.iter_mut() {
                e.tile.0 += (e.vx * dt).round() as i32;
                e.tile.1 += (e.vy * dt).round() as i32;
            }
        }
    }

    fn loaded_chunks(&self, player_chunk: ChunkPos) -> Vec<ChunkPos> {
        let mut result = Vec::new();
        for dx in -LOAD_RADIUS..=LOAD_RADIUS {
            for dy in -LOAD_RADIUS..=LOAD_RADIUS {
                let cp = ChunkPos(player_chunk.0 + dx, player_chunk.1 + dy);
                if self.chunks.contains_key(&cp) {
                    result.push(cp);
                }
            }
        }
        result
    }
}

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, x: i32, y: i32, w: i32, h: i32, color: u32) {
    for py in y.max(0)..(y + h).min(buf_h as i32) {
        for px in x.max(0)..(x + w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Chunked World Demo", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut last_time = Instant::now();

    let mut world = World::new();

    // 玩家从 tile (0, 0) 开始
    let mut player_tile = TilePos(0, 0);
    let _player_id = world.spawn_entity(player_tile, 0xFFFF6040, 12.0);

    // 一些 NPC
    for i in 0..10 {
        let t = TilePos(i * 5, 0);
        world.spawn_entity(t, 0xFFA040FF, 8.0);
    }

    while window.is_open() && !window.is_key_down(Key::Escape) {
        let now = Instant::now();
        let dt = now.duration_since(last_time).as_secs_f32().min(0.05);
        last_time = now;

        // 玩家输入
        let mut new_tile = player_tile;
        if window.is_key_pressed(Key::W, minifb::KeyRepeat::No) { new_tile.1 -= 1; }
        if window.is_key_pressed(Key::S, minifb::KeyRepeat::No) { new_tile.1 += 1; }
        if window.is_key_pressed(Key::A, minifb::KeyRepeat::No) { new_tile.0 -= 1; }
        if window.is_key_pressed(Key::D, minifb::KeyRepeat::No) { new_tile.0 += 1; }

        if new_tile != player_tile {
            if world.is_traversable(new_tile) {
                player_tile = new_tile;
            } else {
                println!("Blocked at {:?}", new_tile);
            }
        }

        world.update(dt);

        // 渲染
        for px in buffer.iter_mut() { *px = 0xFF000000; }

        // 算玩家所在 chunk
        let player_chunk = tile_to_chunk(player_tile);
        let loaded = world.loaded_chunks(player_chunk);

        // 画 loaded chunk 的 tile(简化:画 chunk 边界)
        let (cam_x, cam_y) = tile_to_world(player_tile);
        let cam_x = cam_x - WIDTH as f32 / 2.0;
        let cam_y = cam_y - HEIGHT as f32 / 2.0;

        for cp in &loaded {
            let origin_x = cp.0 * CHUNK_SIZE;
            let origin_y = cp.1 * CHUNK_SIZE;
            for ly in 0..CHUNK_SIZE {
                for lx in 0..CHUNK_SIZE {
                    let tile = TilePos(origin_x + lx, origin_y + ly);
                    let (wx, wy) = tile_to_world(tile);
                    let sx = wx - cam_x;
                    let sy = wy - cam_y;
                    if sx < 0.0 || sy < 0.0 || sx >= WIDTH as f32 || sy >= HEIGHT as f32 { continue; }

                    // 检查这个 tile 是不是墙
                    let chunk = world.chunks.get(cp).unwrap();
                    let is_wall = !chunk.is_traversable(lx, ly);
                    let color = if is_wall { 0xFF808080 } else { 0xFF303030 };
                    draw_rect(&mut buffer, WIDTH, HEIGHT,
                              (sx - TILE_SIZE/2.0) as i32, (sy - TILE_SIZE/2.0) as i32,
                              TILE_SIZE as i32, TILE_SIZE as i32, color);
                }
            }
        }

        // 画 chunk 边界(绿色细线)
        for cp in &loaded {
            let origin_x = cp.0 * CHUNK_SIZE;
            let origin_y = cp.1 * CHUNK_SIZE;
            let (ox, oy) = tile_to_world(TilePos(origin_x, origin_y));
            let sx = ox - cam_x - TILE_SIZE/2.0;
            let sy = oy - cam_y - TILE_SIZE/2.0;
            let w = CHUNK_SIZE as f32 * TILE_SIZE;
            // 4 条边
            draw_rect(&mut buffer, WIDTH, HEIGHT, sx as i32, sy as i32, w as i32, 1, 0xFF40FF40);
            draw_rect(&mut buffer, WIDTH, HEIGHT, sx as i32, (sy + w) as i32, w as i32, 1, 0xFF40FF40);
            draw_rect(&mut buffer, WIDTH, HEIGHT, sx as i32, sy as i32, 1, w as i32, 0xFF40FF40);
            draw_rect(&mut buffer, WIDTH, HEIGHT, (sx + w) as i32, sy as i32, 1, w as i32, 0xFF40FF40);
        }

        // 画 entity
        for cp in &loaded {
            let chunk = world.chunks.get(cp).unwrap();
            for e in &chunk.entities {
                let (wx, wy) = tile_to_world(e.tile);
                let sx = wx - cam_x;
                let sy = wy - cam_y;
                if sx < 0.0 || sy < 0.0 || sx >= WIDTH as f32 || sy >= HEIGHT as f32 { continue; }
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          (sx - e.size) as i32, (sy - e.size) as i32,
                          (e.size * 2.0) as i32, (e.size * 2.0) as i32, e.color);
            }
        }

        // 玩家(总是中心)
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  (WIDTH as i32 / 2) - 8, (HEIGHT as i32 / 2) - 8, 16, 16, 0xFFFF6040);

        // HUD:显示玩家位置
        let _ = (cam_x, cam_y);
        let _ = player_chunk;

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `div_euclid` / `rem_euclid` 处理负坐标(玩家去地图左上角时)
- `entry(pos).or_insert_with(|| {...})` 生成新 chunk 并插入
- 用 hash 函数(`wrapping_mul(0x9E3779B9)` 是黄金比例相关常量)生成"程序化"墙壁
- `loaded_chunks` 返回当前加载的 chunk 列表(在玩家附近的)
- 相机居中玩家,通过 cam_x / cam_y 把世界坐标转屏幕坐标

**Troubleshooting**:

- 玩家走很慢 — TILE_SIZE 默认 16,改大
- 内存持续增长 — chunk 没正确 unload(本简化版不做 unload,Day 280 加)
- chunk 边界出现"空洞" — 跨 chunk tile 的渲染可能漏掉,检查 origin 计算
