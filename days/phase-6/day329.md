# Day 329 · 简陋地打印浮点数

> 浮点打印是 printf 里最难的题目。IEEE 754 浮点的精度、舍入、边界(无穷、NaN)让无数工程师头秃。今天 Casey 教"简陋版"——足够好但不是完美,这是工程上的实用主义。

## 0 · 为什么要有这一天

浮点打印看似简单——`printf("%f", 3.14)` 输出 `3.140000`。但深入研究你会发现这是个**未完全解决的问题**,直到 2010s 才有真正高效的算法。

考虑这个难题:打印 `0.1`。

```
0.1 在 IEEE 754 double 里实际存储为: 0.1000000000000000055511151231257827021181583404541015625
```

`0.1` 不能用二进制精确表示,实际值是一个近似。打印时:

- 简陋版:`"0.100000"`(精度 6 位,不精确但够用)
- 完整版:`"0.1000000000000000055511151231257827021181583404541015625"`(精确)
- 短而准:`"0.1"`(最短字符串,parse 回来等于原 double)

业界最终选定第三种——叫 **shortest round-trip** representation。但实现复杂,需要大整数运算。Steele & White 1990 提出,2010 后有 Grisu / Ryū 等快速算法。

Casey 今天的目标不是实现 shortest round-trip,而是**简陋版**——足够 debug 用,知道精度不完美但接受。具体策略:

```
1. 把 double 拆成整数部分 + 小数部分
2. 整数部分用 itoa
3. 小数部分乘 10^precision 后取整,用 itoa
4. 拼起来
```

这种方式精度有限(6 位小数后开始误差累积),但简单可靠,代码 50 行。

心理锚点:今天之后你能"打印任意浮点数",接受精度限制。生产场景用 Rust `format!("{}", f64)` 内部是 Ryū 算法,完美但今天先简化。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_printf.cpp`,加 `%f` 支持。

核心算法:

```c
void print_float(format_spec *spec, double value, output_stream *out) {
    if (isnan(value)) { print_str("nan", out); return; }
    if (isinf(value)) { print_str(value < 0 ? "-inf" : "inf", out); return; }
    
    // 处理符号
    if (value < 0) {
        out_putc(out, '-');
        value = -value;
    } else if (spec->plus) {
        out_putc(out, '+');
    }
    
    // 默认精度 6
    int precision = spec->precision >= 0 ? spec->precision : 6;
    
    // 拆整数 + 小数
    uint64 int_part = (uint64)value;
    double frac_part = value - (double)int_part;
    
    // 整数部分(用 day 328 的 itoa)
    char int_buf[24];
    int int_len = itoa_dec(int_buf, int_part);
    out_puts(out, int_buf, int_len);
    
    // 小数点
    if (precision > 0 || spec->alt) {
        out_putc(out, '.');
    }
    
    // 小数部分:乘 10^precision 后取整
    // 注意:这个方法精度有限,但对于 6 位精度够用
    double frac_scaled = frac_part;
    for (int i = 0; i < precision; i++) frac_scaled *= 10.0;
    uint64 frac_int = (uint64)(frac_scaled + 0.5);  // 四舍五入
    
    // 处理进位(0.999... 变 1.000)
    // ... Casey 详细讨论
    
    char frac_buf[24];
    int frac_len = itoa_dec(frac_buf, frac_int);
    // 前面补 0 到 precision 位
    for (int i = frac_len; i < precision; i++) {
        out_putc(out, '0');
    }
    out_puts(out, frac_buf, frac_len);
}
```

Casey 在视频里讨论了几个浮点打印的经典坑:

1. **0.1 + 0.2 ≠ 0.3**:`printf("%f", 0.1 + 0.2)` 输出 `0.300000`,但实际值是 `0.30000000000000004`
2. **`-0.0`** 和 `+0.0`:IEEE 754 有两个 0,符号位不同
3. **NaN/Inf** 的处理:不同平台表示不同
4. **大数溢出**:`1e308` 的整数部分无法用 uint64 表示,需要科学计数法

Casey 的简陋版**不处理大数**(超过 uint64 范围的浮点输出错误),也不处理 shortest round-trip。生产代码用 Rust `format!` 内部的 Ryū 算法,完美。

## 2 · 心智模型

### 类比:卷尺量布

把浮点打印想象成卷尺量布。

- **整数部分**:用卷尺大量出多少米
- **小数部分**:卷尺下面的厘米、毫米

卷尺精度有限(毫米级),量不到纳米。简陋版浮点打印也一样——精度 6 位,后面的"亚纳米"看不到。

精确版(Steele-White / Ryū)用激光测距,精度无限,但设备复杂。今天的 Casey 用卷尺。

### 严谨原理:IEEE 754 浮点

double 的存储:

```
sign(1 bit) | exponent(11 bit) | mantissa(52 bit)
```

`value = (-1)^sign × 1.mantissa × 2^(exponent - 1023)`

例:`0.1` 的二进制表示:

```
sign = 0
exponent = 1019 (bias 1023,所以实际 exponent = -4)
mantissa = 1001100110011001100110011001100110011001100110011010

value = 1.1001100110011... × 2^-4
      = 0.0001100110011...
      ≈ 0.1000000000000000055511151231257827...
```

`0.1` 在二进制是无限循环小数,double 用 52 位 mantissa 截断,有微小误差。

### 简陋版算法的精度问题

Casey 的简陋版用 `frac_part * 10^precision` 取整,精度受限于:

1. **double 自身精度**:52 位 mantissa ≈ 15-16 位十进制精度
2. **乘法误差累积**:每次 `* 10.0` 引入舍入误差,6 位精度累积可接受,15 位开始严重
3. **整数部分大**:integer_part 接近 1e15 时,小数部分几乎没有精度

实例:

```
0.1:简陋版 "0.100000",实际 0.1000000000000000055...
0.1 + 0.2:简陋版 "0.300000",实际 0.30000000000000004
1e-7:简陋版 "0.000000"(被精度 6 截断),实际 0.0000001
1e15 + 0.5:简陋版 "1000000000000000.000000"(0.5 看不见),因为 1e15 已经占满 double 精度
```

对于游戏 debug 输出,这种精度足够。对于科学计算,需要 Ryū。

### 完整版算法:Ryū(2018)

Ryū 算法(2018 论文)是现代最快的 shortest round-trip 浮点打印。核心思路:

1. 把 double 的 mantissa 当大整数
2. 用大整数乘除法精确计算"最短十进制表示"
3. 保证 parse(print(x)) == x

Rust 的 `f64::to_string()` 用 Ryū 或类似算法。Casey 今天不实现 Ryū,这是 Phase 7+ 的内容。

### Rust 实现:简陋版

```rust
fn print_float_poor(value: f64, precision: usize) -> String {
    if value.is_nan() { return "nan".to_string(); }
    if value.is_infinite() {
        return if value < 0.0 { "-inf".to_string() } else { "inf".to_string() };
    }
    
    let mut s = String::new();
    let mut v = value;
    
    if v < 0.0 {
        s.push('-');
        v = -v;
    }
    
    // 整数部分
    let int_part = v.trunc() as u64;
    s.push_str(&int_part.to_string());
    
    if precision > 0 {
        s.push('.');
    }
    
    // 小数部分
    let mut frac = v.fract();
    for _ in 0..precision {
        frac *= 10.0;
        let digit = frac.trunc() as u32;
        s.push((b'0' + digit as u8) as char);
        frac = frac.fract();
    }
    
    s
}
```

每循环一次:`* 10` + 取整 + 取 fract。`fract()` 返回小数部分。

精度测试:

```
print_float_poor(0.1, 6) = "0.100000"  (实际 0.1000000000000000055)
print_float_poor(3.14159, 4) = "3.1415" (丢失了最后一位,精度问题)
print_float_poor(1.0/3.0, 8) = "0.33333333"
```

够 debug 用,不精确但简单。

### Rust 完整版:Ryū

Rust `format!("{}", 0.1)` 输出 `"0.1"`(shortest round-trip)。内部用 Ryū 算法:

```rust
let s = format!("{}", 0.1);     // "0.1"
let s = format!("{:.6}", 0.1);  // "0.100000" 显式精度
let s = format!("{:e}", 1e10);  // "1e10" 科学计数法
```

`format!` 是宏,编译期解析格式串,运行时调 Ryū。性能是简陋版的 2-3 倍,精度完美。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏行业浮点打印场景:

- **坐标 debug**:`pos = (1.234, 5.678)`(精度 3 够用)
- **物理量**:`velocity = 12.5 m/s`
- **百分比**:`health = 87.5%`
- **帧率**:`FPS = 60.0`(精度 0 或 1)

游戏行业接受精度损失——debug 输出 6 位足够,不需要 17 位精度。Casey 的简陋版正是这种工程实用主义。

游戏行业的另一个话题:**浮点确定性**。多人游戏要保证不同机器浮点运算结果一致(防止 desync),需要固定精度 + 禁用 fuse-multiply-add(FMA)。但今天不讲。

### 3.2 · 🎨 图形学视角

图形学的浮点精度问题:

- **深度精度**:Z-buffer 在远距离精度低(z-fighting),需要 reversed-Z
- **HDR 颜色**:亮度值范围 0.0001 ~ 10000,需要 fp16 或 fp32
- **物理光照**:光线追踪的反射率计算,精度敏感

浮点打印在图形学 debug 里重要——shader 计算 result 时,printf 出来看是否正确。简陋版够用,因为 shader 计算本身有误差累积。

### 3.3 · 🐧 Linux 系统编程视角

Linux 内核的浮点打印用 `vsnprintf` 的 `%f` 支持,但内核浮点很受限(浮点操作在内核态需要保存/恢复 FPU 状态)。

Linux 用户态的 printf 由 glibc 实现,内部用 **David Gay's algorithm**(1990 提出,快速但复杂)或 modern Grisu3(2010)/Ryū(2018)。

```bash
# 看 glibc printf 浮点的代码
apt source libc6  # Debian
# 或在 https://sourceware.org/git/?p=glibc.git 看源码
# 文件:stdio-common/printf_fp.c
```

glibc 的浮点打印 ~5000 行 C 代码,完整支持 IEEE 754 + locale + 精度控制。Casey 简陋版 50 行。

### 3.4 · 🦀 Rust 生态视角

Rust 的浮点打印用 Ryū(由 dtolnay 移植)。完美 shortest round-trip,性能是简陋版的 2-3 倍。


```rust

```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么"简陋版浮点打印"在精度 6 位以上开始出错?给出至少 2 个理由。

**参考解答**:

1. **double 自身精度限制**:52 bit mantissa ≈ 15-16 位十进制精度。前 15 位可靠,第 16 位开始有误差。
2. **乘法累积误差**:简陋版每次 `* 10.0` 引入舍入,6 次累积可接受,15 次累积严重误差。
3. **整数部分挤占精度**:`1000000000.0 + 0.0000001` 的整数部分占 10 位精度,小数部分只剩 5-6 位精度。

精确版(Ryū)用大整数运算避开浮点累积,得到任意精度。

## 8 · Rust / Arch 落地代码

### Rust:简陋版浮点打印 + 完整版对比(可跑)

```rust
// Cargo.toml: 无依赖
// src/main.rs

fn print_float_poor(value: f64, precision: usize) -> String {
    if value.is_nan() { return "nan".to_string(); }
    if value.is_infinite() {
        return if value < 0.0 { "-inf".to_string() } 
               else { "inf".to_string() };
    }
    
    let mut s = String::new();
    let mut v = value;
    
    // 符号(包括 -0.0)
    if v < 0.0 || (v == 0.0 && value.is_sign_negative()) {
        s.push('-');
        v = -v;
    }
    
    // 整数部分
    let int_part = v.trunc() as u64;
    s.push_str(&int_part.to_string());
    
    if precision > 0 {
        s.push('.');
    }
    
    // 小数部分:每次乘 10 取整
    let mut frac = v.fract();
    for _ in 0..precision {
        frac *= 10.0;
        let digit = frac.trunc() as u32;
        s.push((b'0' + (digit as u8)) as char);
        frac = frac.fract();
    }
    
    s
}

fn print_float_poor_with_rounding(value: f64, precision: usize) -> String {
    // 改进版:先四舍入再打印,避免最后一位误差
    if value.is_nan() { return "nan".to_string(); }
    if value.is_infinite() {
        return if value < 0.0 { "-inf".to_string() } else { "inf".to_string() };
    }
    
    let mut s = String::new();
    let mut v = value;
    
    if v < 0.0 { s.push('-'); v = -v; }
    
    // 先把 value 四舍入到 precision 位小数
    let scale = 10f64.powi(precision as i32);
    let rounded = (v * scale).round() / scale;
    
    let int_part = rounded.trunc() as u64;
    s.push_str(&int_part.to_string());
    
    if precision > 0 {
        s.push('.');
        let mut frac = rounded.fract();
        for _ in 0..precision {
            frac *= 10.0;
            let digit = frac.trunc() as u32;
            s.push((b'0' + digit as u8) as char);
            frac = frac.fract();
        }
    }
    
    s
}

fn main() {
    println!("=== Day 329: 简陋浮点打印 ===\n");
    
    // 基础测试
    println!("--- 基础测试 ---");
    let cases = [3.14, 0.1, 0.1 + 0.2, 1.0/3.0, -2.5, 0.0, -0.0, 
                 3.14159265358979323846];
    
    for val in cases {
        println!("\nValue: {}", val);
        println!("  简陋版 (6 位):    [{}]", print_float_poor(val, 6));
        println!("  简陋版+舍入 (6):  [{}]", print_float_poor_with_rounding(val, 6));
        println!("  Rust std (6 位):  [{}]", format!("{:.6}", val));
        println!("  Rust std (无):    [{}]", format!("{}", val));
        // Rust std 无精度 = shortest round-trip
    }
    
    // 边界情况
    println!("\n--- 边界情况 ---");
    println!("NaN:      [{}]", print_float_poor(f64::NAN, 6));
    println!("+Inf:     [{}]", print_float_poor(f64::INFINITY, 6));
    println!("-Inf:     [{}]", print_float_poor(f64::NEG_INFINITY, 6));
    println!("Max f64:  [{}]", print_float_poor(f64::MAX, 6));
    // 注意:f64::MAX 的整数部分超过 u64 范围,简陋版会出错
    println!("Min pos:  [{}]", print_float_poor(f64::MIN_POSITIVE, 6));
    // 简陋版精度不够,Min pos 几乎为 0
    
    // 精度对比
    println!("\n--- 精度对比 ---");
    let pi = std::f64::consts::PI;
    for prec in [2, 6, 10, 15, 17] {
        println!("pi, prec={:>2}: 简陋版 [{:<25}]  std [{:<25}]",
                 prec,
                 print_float_poor(pi, prec),
                 format!("{:.*}", prec, pi));
    }
    
    // 性能对比
    println!("\n--- 性能对比 ---");
    use std::time::Instant;
    
    let n = 1_000_000;
    let start = Instant::now();
    let mut sum_len = 0;
    for i in 0..n {
        let s = print_float_poor(i as f64 * 0.1, 6);
        sum_len += s.len();
    }
    let t_poor = start.elapsed();
    
    let start = Instant::now();
    let mut sum_len2 = 0;
    for i in 0..n {
        let s = format!("{:.6}", i as f64 * 0.1);
        sum_len2 += s.len();
    }
    let t_std = start.elapsed();
    
    println!("简陋版 (sum_len={}): {:?}", sum_len, t_poor);
    println!("Rust std (sum_len={}): {:?}", sum_len2, t_std);
    println!("std 比简陋版快 {:.1}x", 
             t_poor.as_secs_f64() / t_std.as_secs_f64());
}
```

## 10 · 深度补充:工程视角

浮点打印的算法演化:1970s 简陋版 / 1990 David Gay 大整数 / 2010 Grisu3 V8 / 2018 Ryu 完整正确 / 2020s Ryu Printf。Ryu 的核心思想:把 double 看作 64 bit 整数 + 指数,用大整数运算精确求出最短十进制表示。算法复杂但 O(1) 时间。Rust f64::to_string 用 Ryu,C++ std::to_chars 也用类似算法。
