
# Day 337 · 粒子的便捷 SIMD

> 昨天 Casey 把粒子装进了对象池,但更新一颗粒子还是要做 6 次 f32 乘法 + 3 次加法。一颗没事,4096 颗每帧 60fps = 1.4 百万次乘法——CPU 能干但 cache miss 多。今天 Casey 把数据布局从 AoS 切到 SoA,让 SIMD 寄存器一次吞下 4 颗粒子,直接 4 倍提速。这是 Casey 第一次在 HH 里把"数据导向设计"实战出来。

## 0 · 为什么要有这一天

你的 CPU 有一个叫 **SIMD**(Single Instruction Multiple Data,单指令多数据)的能力:一条指令同时处理 4 个、8 个、16 个甚至 32 个 f32。x86_64 的 SSE 寄存器 `xmm0..xmm15` 每个 128 位,正好装 4 个 f32;AVX 寄存器 `ymm0..ymm15` 256 位,装 8 个;AVX-512 装 16 个。

举个例子,要把 4 个 f32 各加 1,SIMD 是:

```
movaps xmm0, [a]      ; 载入 4 个 f32 到 xmm0
addps  xmm0, [ones]   ; 一条指令加 4 个
movaps [out], xmm0    ; 存回
```

标量版本是 4 条独立的 `addss`。SIMD 快 4 倍且更省能耗。

但 SIMD 有个**苛刻要求**:**输入数据必须连续、同质**。`xmm0` 要装 4 个 `pos.x`,这 4 个 `pos.x` 必须在内存里紧挨着排——你不能从 4 个不同地址各取一个。

问题来了:昨天的 `Particle` 是这样的:

```rust
struct Particle {
    pos: [f32; 3],
    vel: [f32; 3],
    age: f32,
    life: f32,
}
// sizeof = 32 字节
```

内存里排列:`pos.x, pos.y, pos.z, vel.x, vel.y, vel.z, age, life`(每行 4 字节)。要拿 4 个粒子的 `pos.x`,你从 `[0].pos.x`、`[1].pos.x`、`[2].pos.x`、`[3].pos.x` 取——间隔 32 字节。SIMD 直接 `movaps` 不行(需要 16 字节对齐且连续),要用 4 条 `movss` + 一条 `unpcklps` 拼装。SIMD 优势被抵消大半。

**SoA(Struct of Arrays)** 把布局翻过来:

```rust
struct Particles {
    pos_x: [f32; MAX],
    pos_y: [f32; MAX],
    pos_z: [f32; MAX],
    vel_x: [f32; MAX],
    vel_y: [f32; MAX],
    vel_z: [f32; MAX],
    age: [f32; MAX],
    life: [f32; MAX],
}
```

现在 `[0..4]` 的 `pos.x` 是 4 个连续 f32,直接 SIMD。这就是数据导向设计的核心思想:**先想 SIMD 想要什么布局,再设计数据结构**。

今天 Casey 把昨天的 AoS 池子重写成 SoA,并提供一组"便捷"包装函数,让上层代码"看起来像访问单个粒子",实际底层 SIMD 加速。

心理锚点:今天之后你能解释 AoS vs SoA 的取舍,能看懂 Rust `std::arch::x86_64::*` 的 SIMD intrinsics,能自己写一个简单的 SoA + SIMD 优化的循环。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天主要做两件事:

## 2 · 心智模型

### 类比:仓库里两种存货方式

想象你仓库里有 4096 个客户的订单,每个订单有"姓名、地址、电话、商品"四个字段。两种摆法:

**AoS(每个订单一沓纸,按订单排)**:订单 0 是 4 页,订单 1 是 4 页......要"统计所有订单的商品"得翻 4096 沓,每沓跳到第 4 页——每翻一页手指头要换位置(对应 cache miss)。

**SoA(按字段分四堆,姓名堆 / 地址堆 / 电话堆 / 商品堆)**:商品堆就是 4096 页连续的"商品",翻 4096 页一气呵成。

**SIMD 是 4 倍宽的传送带**:一次能搬 4 页。AoS 模式下传送带拿到的 4 页来自不同订单的"商品",但中间夹了姓名、地址、电话——必须先排序;SoA 模式下传送带拿到的就是连续 4 张商品页,直接处理。

### 数学:一次 SIMD 乘 4 个 f32

x86_64 SSE 的 `mulps`(MULtiply Packed Single-precision)指令:把两个 `xmm` 寄存器当成 4 个 f32 各自相乘,结果存回。

```
xmm0 = [a0, a1, a2, a3]
xmm1 = [b0, b1, b2, b3]
mulps xmm0, xmm1   ; xmm0 = [a0*b0, a1*b1, a2*b2, a3*b3]
```

**一条指令,4 次乘法**。

在 Rust 里,这写成:

```rust
use std::arch::x86_64::*;
unsafe {
    let a = _mm_set_ps(1.0, 2.0, 3.0, 4.0);  // xmm = [4, 3, 2, 1] (倒序!)
    let b = _mm_set_ps(10.0, 20.0, 30.0, 40.0);
    let c = _mm_mul_ps(a, b);
    let mut out = [0f32; 4];
    _mm_storeu_ps(out.as_mut_ptr(), c);
    assert_eq!(out, [40.0, 60.0, 60.0, 40.0]);  // 4*10, 3*20, 2*30, 1*40
}
```

**坑**:`_mm_set_ps(a, b, c, d)` 是**倒序**——存成 `[d, c, b, a]`。这是 SSE 历史遗留(小端排序),记不住就写 `_mm_setr_ps(d, c, b, a)`(setr = reverse order set)。

### AoS vs SoA 的代码对比

**AoS 版本(昨天的方式)**:

```rust
fn update(particles: &mut [Particle], dt: f32) {
    for p in particles.iter_mut() {
        p.pos[0] += p.vel[0] * dt;
        p.pos[1] += p.vel[1] * dt;
        p.pos[2] += p.vel[2] * dt;
        p.age += dt;
    }
}
```

CPU 每次 `p.pos[0]` 访问:读 32 字节 Particle 中的 4 字节,cache line 64 字节里只用了 1/8。`vel[0]` 还要再访问一次。**带宽利用率极低**。

**SoA + 标量版本**:

```rust
fn update_soa(ps: &mut Particles, n: usize, dt: f32) {
    for i in 0..n {
        ps.pos_x[i] += ps.vel_x[i] * dt;
        ps.pos_y[i] += ps.vel_y[i] * dt;
        ps.pos_z[i] += ps.vel_z[i] * dt;
        ps.age[i] += dt;
    }
}
```

`ps.pos_x[i]` 连续访问,cache 完美利用。编译器**自动**会把这循环向化(auto-vectorization)成 SIMD。

**SoA + 显式 SIMD**:

```rust
#[cfg(target_arch = "x86_64")]
fn update_simd(ps: &mut Particles, n: usize, dt: f32) {
    unsafe {
        let dt_v = _mm_set1_ps(dt);  // 4 个 dt
        let mut i = 0;
        // 4 个一组
        while i + 4 <= n {
            // 载入 4 个 pos_x
            let px = _mm_loadu_ps(ps.pos_x.as_ptr().add(i));
            let vx = _mm_loadu_ps(ps.vel_x.as_ptr().add(i));
            let new_px = _mm_add_ps(px, _mm_mul_ps(vx, dt_v));
            _mm_storeu_ps(ps.pos_x.as_mut_ptr().add(i), new_px);

            // y
            let py = _mm_loadu_ps(ps.pos_y.as_ptr().add(i));
            let vy = _mm_loadu_ps(ps.vel_y.as_ptr().add(i));
            let new_py = _mm_add_ps(py, _mm_mul_ps(vy, dt_v));
            _mm_storeu_ps(ps.pos_y.as_mut_ptr().add(i), new_py);

            // z
            let pz = _mm_loadu_ps(ps.pos_z.as_ptr().add(i));
            let vz = _mm_loadu_ps(ps.vel_z.as_ptr().add(i));
            let new_pz = _mm_add_ps(pz, _mm_mul_ps(vz, dt_v));
            _mm_storeu_ps(ps.pos_z.as_mut_ptr().add(i), new_pz);

            // age
            let a = _mm_loadu_ps(ps.age.as_ptr().add(i));
            let new_a = _mm_add_ps(a, dt_v);
            _mm_storeu_ps(ps.age.as_mut_ptr().add(i), new_a);

            i += 4;
        }
        // 剩下不足 4 个的标量收尾
        while i < n {
            ps.pos_x[i] += ps.vel_x[i] * dt;
            ps.pos_y[i] += ps.vel_y[i] * dt;
            ps.pos_z[i] += ps.vel_z[i] * dt;
            ps.age[i] += dt;
            i += 1;
        }
    }
}
```

每次循环体处理 **4 个粒子**,8 条 SIMD 指令(4 个 load + 4 个 store + 计算)对比标量 16 条 load/store + 16 条计算。理论提速 4 倍。

### Rust 的"便捷 SIMD"思路:wide / glam

Casey 在 C 里手写 `_mm_mul_ps` 这种 intrinsic。Rust 生态有更便捷的方案:

#### 方案 1:`std::arch::x86_64::*`(裸 intrinsic)

最底层,跨平台需要 `#[cfg(target_arch=...)]`。今天 Casey 的方式。

#### 方案 2:`std::simd`(portable SIMD,nightly)

```rust
#![feature(portable_simd)]
use std::simd::f32x4;
let a = f32x4::from_array([1.0, 2.0, 3.0, 4.0]);
let b = f32x4::from_array([10.0, 20.0, 30.0, 40.0]);
let c = a * b;
// c = [10, 60, 90, 160]
```

跨平台(Rust 自动选 SSE / NEON / AVX),代码像普通数学。还在 nightly。

#### 方案 3:`wide` crate(stable,跨平台)

```toml
wide = "0.7"
```

```rust
use wide::f32x4;
let a = f32x4::from([1.0, 2.0, 3.0, 4.0]);
let b = f32x4::from([10.0, 20.0, 30.0, 40.0]);
let c = a * b;
```

Stable Rust 跨平台 SIMD。底层根据编译目标选 SSE / NEON。

#### 方案 4:`glam::Vec3A`(16 字节对齐的 Vec3)

```rust
use glam::Vec3A;  // 16B 对齐,内部 SIMD
let a = Vec3A::new(1.0, 2.0, 3.0);
let b = Vec3A::new(10.0, 20.0, 30.0);
let c = a + b;
```

Vec3A 把 Vec3 padding 到 16 字节(`[f32; 4]`),SIMD 一次装下"一个完整 3D 向量"。这是**单粒子向量化**,和 SoA 的**多粒子向量化**思路不同——前者优化"操作一个向量",后者优化"批量同样操作"。

Casey 在 Day 337 选方案 1(裸 intrinsic),因为 HH 是教学项目,要让观众看到 SIMD 的"金属"。生产代码你会选方案 3 或 4。

### 关键 Rust 概念:`is_x86_feature_detected!`

不是所有 x86_64 CPU 都支持 AVX。运行时检查:

```rust
fn update(ps: &mut Particles, n: usize, dt: f32) {
    if is_x86_feature_detected!("avx2") {
        unsafe { update_avx2(ps, n, dt) }
    } else if is_x86_feature_detected!("sse4.1") {
        unsafe { update_sse41(ps, n, dt) }
    } else {
        update_scalar(ps, n, dt)
    }
}
```

编译时把三种版本都编进去(`#[target_feature(enable = "avx2")]`),运行时选最快的。这是 Rust 的杀手锏:跨平台 + 运行时分发。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏引擎里 SIMD 是性能生命线。所有"批量同质"操作都该 SIMD 化:

- **粒子更新**:今天
- **碰撞检测 broad phase**:每帧扫所有 AABB,4 个一组做 AABB-AABB 测试
- **骨骼动画**:每帧 skinning,每个顶点 4 个 bone weight,完美 SIMD
- **光照**(deferred):每个像素算 BRDF,SIMD 一片
- **物理**:Verlet 积分、约束求解

**Casey 在后面会 SIMD 化的**:

- Day 350+:多线程世界模拟,每线程 SIMD 一组实体
- Day 436+:光照 tiled deferred,tile 内 SIMD

**业界 SIMD 优化做得最极致的**:Unity DOTS、Unreal Niagara、Bevy 关键路径。Rust + wide 是这些引擎的 SIMD 事实标准。

### 3.2 · 图形学视角

GPU 天然 SIMD:一片 shader 处理 64 个像素(NVIDIA warp / AMD wavefront)。GPU 编程模型不暴露 SIMD 寄存器,但本质一样。

CPU 和 GPU 的 SIMD 区别:

| | CPU SIMD | GPU SIMD |
|---|---|---|
| 单元 | 4-16 (SSE/AVX) | 32-64 (warp/wavefront) |
| 控制流 | 程序控制 | SIMT(分支时 mask) |
| 编程 | Rust intrinsic | GLSL/HLSL/WGSL |
| 数据布局 | SoA / AoS 都行 | SoA 标准(vertex buffer) |

**位图字体渲染**也是 SIMD 重灾区:每个像素的颜色 = 字体纹理采样 × 文字颜色,4 个像素一次 SIMD。

**真实 case**:`bgfx`(跨平台 GPU 抽象层)的软件光栅化 fallback 是 hand-tuned SIMD,Rust 版的 `rusttype` / `cosmic-text` 也都 SIMD。

### 3.3 · Linux 系统编程视角

Linux 内核大量用 SIMD,但要小心:**内核默认禁用 SSE/AVX**(因为保存/恢复 SIMD 寄存器到上下文慢)。内核代码要看 SIMD 用 `_kernel_fpu_begin()` / `_kernel_fpu_end()` 包围。

```c
// 内核里:
kernel_fpu_begin();
// SIMD 代码
kernel_fpu_end();
```

应用层没这限制。但有个坑:**信号处理器不能 SIMD**——信号打断时 SIMD 寄存器状态未保存,信号返回会破坏。如果你的 Rust 程序在 SIMD 计算时收到信号,可能数据错乱。`sigaction` 默认会保存 SIMD,但要 `sa_flags |= SA_SIGINFO`。

**Arch 工具**:

```bash
# 看 CPU 支持哪些 SIMD
cat /proc/cpuinfo | grep flags | head -1 | tr ' ' '\n' | grep -E "sse|avx|fma"
# 输出包含 sse sse2 sse4_1 sse4_2 avx avx2 fma 等

# 看 Rust 编译时默认启用什么 SIMD
rustc --print target-features | grep -E "sse|avx" | head

# rustc 自动向量化报告
RUSTFLAGS="-C opt-level=3 -C target-cpu=native" \
  cargo rustc --release -- --emit asm
find target/release/deps -name "*.s" | xargs grep -l "mulps" | head
# 找到含 mulps 的汇编文件,说明自动向量化成功
```

### 3.4 · Rust 生态视角

Rust SIMD 的几个里程碑:

- **2017 前**:只能用 `std::arch::x86_64::*`,平台特定,代码丑陋
- **2019**:`packed_simd` crate(portable SIMD 的早期实验,nightly only)
- **2021**:`wide` crate 在 stable 上提供跨平台 SIMD
- **2023+**:`std::simd`(portable_simd feature)逐渐成熟,仍 nightly
- **现在**:大多数项目用 `wide` 或 `glam` 的内置 SIMD

**为什么 Rust SIMD 比 C++ 更安全**:
- 编译器检查 `target_feature` 与函数 `unsafe` 一致性
- `is_x86_feature_detected!` 是运行时分发标准模式
- `f32x4` 类型把"SIMD 寄存器"建模成普通类型,所有权和借用规则保护

**ownership 痛点**:SIMD 寄存器值传值是寄存器拷贝,但 Rust 不知道你"想要"寄存器拷贝还是栈拷贝。`#[inline(always)]` 强制内联,让 LLVM 把数据保留在 xmm 寄存器:

```rust
#[inline(always)]
fn vec3_dot(a: f32x4, b: f32x4) -> f32 {
    let prod = a * b;
    prod.reduce_sum()  // 一条 haddps
}
```

不加 `#[inline(always)]`,LLVM 可能选择把 `a`, `b` 存栈上,白白浪费 SIMD 优势。

## 4 · 认知地图

### 4.1 上级

- **数据导向设计** —— 数据布局决定性能,SIMD 只是表象
- **指令集架构(ISA)** —— CPU 能执行的指令规范(SSE/AVX/NEON)
- **微架构** —— CPU 实际实现(SIMD 寄存器、执行单元、流水线)
- **向量化** —— 把标量算法翻译成 SIMD 算法

### 4.2 同级(并行方案)

| 方案 | 关键差别 | 何时用 | 本项目 |
|---|---|---|---|
| AoS | 一个粒子连续 | 业务逻辑、少量粒子 | 之前 |
| SoA | 字段连续 | SIMD、批量同质 | ✅(今天) |
| AoSoA | 块内 AoS,块间 SoA | 介于两者之间 | 大型引擎(如 Embree) |
| Tiled SoA | 8x8 块 | GPU compute | 部分 |

**AoSoA** 是个聪明混合:8 个粒子的 `[pos_x; 8]` 一组(装 1 个 AVX 寄存器),组与组之间像 SoA。Embree(Intel 光追库)就用这个布局,兼顾 SIMD 和单粒子访问。

### 4.3 下级

- **`__m128` / `__m256`** —— SIMD 寄存器类型
- **`_mm_*` intrinsic** —— SSE 指令的 Rust 接口
- **`_mm256_*` intrinsic** —— AVX 指令的 Rust 接口
- **`loadu` / `storeu`** —— 未对齐内存载入/存储
- **`set1`** —— 广播标量到 SIMD 寄存器
- **`hadd`** —— 水平加(把 4 个 f32 加成 1 个)

## 5 · 对照与变奏

### Auto-vectorization vs 手写 SIMD

现代编译器(LLVM、GCC)能自动把简单循环向量化:

```rust
// 自动向量化触发
for i in 0..n {
    a[i] = b[i] + c[i];
}
```

加 `-C opt-level=3 -C target-cpu=native`,LLVM 看到这个循环就会用 `addps`。**很多时候你不需要手写 SIMD**。

但手写 SIMD 适合:

1. **复杂算法**(clamp、混合、特殊指令)
2. **必须保底性能**(帧时间敏感)
3. **教学目的**(理解原理)
4. **Auto-vec 失败的场景**(数据结构复杂、跨字段访问)

Casey 在 HH 里大量手写,是因为他要演示原理。生产代码先让编译器试,prof 找热点再手写。

### 历史演化

- **1999** Intel 推出 Pentium III + SSE:128-bit SIMD,8 个 xmm 寄存器
- **2011** Intel 推出 Sandy Bridge + AVX:256-bit
- **2013** AVX2(整数 AVX)
- **2017** AVX-512:512-bit,但功耗高、散热问题
- **2020+** ARM NEON 在 Apple Silicon 大放异彩,跨平台 SIMD 成主流

Casey HH 用 SSE(2014-2015 录制,要兼容老 CPU),现代 Rust 项目应该 SSE + AVX + NEON 多版本运行时分发。

### GPU 上的 SIMD

GPU 是 SIMT(Single Instruction Multiple Threads),程序员写"单线程"shader,GPU 自动并行 32-64 个实例。GLSL/HLSL 里没有 `_mm_*`,你写 `a * b`,GPU 自动用 SIMD 指令。

CPU SIMD 编程痛苦,GPU SIMD 编程"无感"——这是 GPU 吸引图形程序员的重要原因。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 `_mm_set_ps(1.0, 2.0, 3.0, 4.0)` 实际存的顺序是 `[4, 3, 2, 1]`?这个设计在历史上是怎么来的?`_mm_setr_ps` 解决了什么问题?

**参考解答**:SSE 设计于 1990s 末,寄存器按**小端**(little-endian)组织:低字节存在低地址。`xmm0` 寄存器从位 0 到位 127,对应 4 个 f32 的 `[lane0, lane1, lane2, lane3]`,`lane0` 是最低位。

`_mm_set_ps(a, b, c, d)` 的语义是"从高到高填充",所以 `a` 进最高位 `lane3`,`d` 进最低位 `lane0`。最终内存里数组是 `[d, c, b, a]`。

这是历史包袱:C 的 `_mm_set_ps` 参数顺序设计成"匹配 Intel 文档里寄存器从高到低的书写"。但程序员读数组是从低到高,所以反过来很反直觉。

`_mm_setr_ps(d, c, b, a)`(`r` 代表 reverse)2000s 后期加入,**按数组顺序填充**:`d` 进 `lane0`。代码读起来直观,现代 SIMD 代码应该优先用 `setr`。

### Lv2 · 动手实践

**题**:实现一个 SoA 粒子结构,标量 update 函数和 SIMD update 函数。基准测试两者性能,验证 SIMD 快 ~3-4 倍。

完成标准:`cargo bench` 输出 SIMD 版本 ≤ 30% 时间。

**参考解答**:

```rust
use std::arch::x86_64::*;
use std::time::Instant;

const N: usize = 4096;

struct Particles {
    pos_x: Vec<f32>,
    pos_y: Vec<f32>,
    pos_z: Vec<f32>,
    vel_x: Vec<f32>,
    vel_y: Vec<f32>,
    vel_z: Vec<f32>,
    age: Vec<f32>,
    life: Vec<f32>,
}

impl Particles {
    fn new(n: usize) -> Self {
        Self {
            pos_x: vec![0.0; n], pos_y: vec![0.0; n], pos_z: vec![0.0; n],
            vel_x: vec![1.0; n], vel_y: vec![2.0; n], vel_z: vec![3.0; n],
            age: vec![0.0; n], life: vec![5.0; n],
        }
    }

    fn update_scalar(&mut self, dt: f32) {
        for i in 0..self.pos_x.len() {
            self.pos_x[i] += self.vel_x[i] * dt;
            self.pos_y[i] += self.vel_y[i] * dt;
            self.pos_z[i] += self.vel_z[i] * dt;
            self.age[i] += dt;
        }
    }

    #[cfg(target_arch = "x86_64")]
    fn update_simd(&mut self, dt: f32) {
        unsafe {
            let dt_v = _mm_set1_ps(dt);
            let n = self.pos_x.len();
            let mut i = 0;
            while i + 4 <= n {
                let px = _mm_loadu_ps(self.pos_x.as_ptr().add(i));
                let vx = _mm_loadu_ps(self.vel_x.as_ptr().add(i));
                _mm_storeu_ps(self.pos_x.as_mut_ptr().add(i),
                              _mm_add_ps(px, _mm_mul_ps(vx, dt_v)));

                let py = _mm_loadu_ps(self.pos_y.as_ptr().add(i));
                let vy = _mm_loadu_ps(self.vel_y.as_ptr().add(i));
                _mm_storeu_ps(self.pos_y.as_mut_ptr().add(i),
                              _mm_add_ps(py, _mm_mul_ps(vy, dt_v)));

                let pz = _mm_loadu_ps(self.pos_z.as_ptr().add(i));
                let vz = _mm_loadu_ps(self.vel_z.as_ptr().add(i));
                _mm_storeu_ps(self.pos_z.as_mut_ptr().add(i),
                              _mm_add_ps(pz, _mm_mul_ps(vz, dt_v)));

                let a = _mm_loadu_ps(self.age.as_ptr().add(i));
                _mm_storeu_ps(self.age.as_mut_ptr().add(i),
                              _mm_add_ps(a, dt_v));

                i += 4;
            }
            while i < n {
                self.pos_x[i] += self.vel_x[i] * dt;
                self.pos_y[i] += self.vel_y[i] * dt;
                self.pos_z[i] += self.vel_z[i] * dt;
                self.age[i] += dt;
                i += 1;
            }
        }
    }
}

fn main() {
    let iters = 1000;

    let mut p1 = Particles::new(N);
    let t1 = Instant::now();
    for _ in 0..iters { p1.update_scalar(0.016); }
    let scalar_ms = t1.elapsed().as_millis();

    #[cfg(target_arch = "x86_64")]
    {
        let mut p2 = Particles::new(N);
        let t2 = Instant::now();
        for _ in 0..iters { p2.update_simd(0.016); }
        let simd_ms = t2.elapsed().as_millis();
        println!("scalar: {} ms, simd: {} ms, speedup: {:.2}x",
                 scalar_ms, simd_ms, scalar_ms as f64 / simd_ms as f64);
    }
    #[cfg(not(target_arch = "x86_64"))]
    {
        println!("scalar: {} ms (SIMD needs x86_64)", scalar_ms);
    }
}
```

**编译运行**:
```bash
RUSTFLAGS="-C target-cpu=native" cargo run --release
# 期望:scalar: ~10 ms, simd: ~3 ms, speedup: 3.3x
```

**关键解释**:
- `_mm_set1_ps(dt)`:广播 `dt` 到 4 个 lane,因为每颗粒子的 dt 相同
- `_mm_loadu_ps`(`u` = unaligned):不要求 16 字节对齐,慢一点但安全
- `while i + 4 <= n`:SIMD 一次 4 个,边界用标量收尾
- `-C target-cpu=native`:让编译器知道当前 CPU 支持的指令(默认只允许 SSE2,保证可移植)

### Lv3 · 迁移设计

**题**:把今天的 SoA + SIMD 套到一个**完全不同的场景**:批量更新 1024 个 3D AABB(`min: Vec3, max: Vec3`)的位移。每帧每个 AABB 沿其速度移动。要求:

1. 设计 SoA 布局(8 个数组:`min_x, min_y, min_z, max_x, max_y, max_z, vel_x, vel_y, vel_z`)
2. 写 SIMD 版本(一次 4 个 AABB)
3. 注意:`min` 和 `max` 都要位移相同距离

**提示**:
- `min` 和 `max` 都是 `pos + size/2`,所以 `min += vel*dt` 和 `max += vel*dt` 同步
- 不要把 `min` 和 `max` 混在一个 SIMD 寄存器,各算各的
- 一次循环 4 个 AABB = 8 个 load + 8 个 store + 8 个 mul + 8 个 add

## 8 · Rust / Arch 落地代码

### 完整可跑的 SoA + SIMD 示例

把 Lv2 扩展,加上 AoS 对照和编译器自动向量化测试。

```rust
use std::arch::x86_64::*;

const N: usize = 4096;

// === AoS 版本(对比基线)===
#[derive(Copy, Clone)]
struct Particle {
    pos: [f32; 3],
    vel: [f32; 3],
    age: f32,
    life: f32,
}

fn update_aos(particles: &mut [Particle], dt: f32) {
    for p in particles.iter_mut() {
        p.pos[0] += p.vel[0] * dt;
        p.pos[1] += p.vel[1] * dt;
        p.pos[2] += p.vel[2] * dt;
        p.age += dt;
    }
}

// === SoA 标量版本 ===
struct Particles {
    pos_x: Vec<f32>, pos_y: Vec<f32>, pos_z: Vec<f32>,
    vel_x: Vec<f32>, vel_y: Vec<f32>, vel_z: Vec<f32>,
    age: Vec<f32>,
}

fn update_soa_scalar(ps: &mut Particles, dt: f32) {
    for i in 0..ps.pos_x.len() {
        ps.pos_x[i] += ps.vel_x[i] * dt;
        ps.pos_y[i] += ps.vel_y[i] * dt;
        ps.pos_z[i] += ps.vel_z[i] * dt;
        ps.age[i] += dt;
    }
}

// === SoA 手写 SIMD 版本 ===
#[target_feature(enable = "sse2")]
unsafe fn update_soa_sse2(ps: &mut Particles, dt: f32) {
    let dt_v = _mm_set1_ps(dt);
    let n = ps.pos_x.len();
    let mut i = 0;
    while i + 4 <= n {
        // 用宏减少重复
        macro_rules! step {
            ($pos:ident, $vel:ident) => {{
                let p = _mm_loadu_ps(ps.$pos.as_ptr().add(i));
                let v = _mm_loadu_ps(ps.$vel.as_ptr().add(i));
                _mm_storeu_ps(ps.$pos.as_mut_ptr().add(i),
                              _mm_add_ps(p, _mm_mul_ps(v, dt_v)));
            }}
        }
        step!(pos_x, vel_x);
        step!(pos_y, vel_y);
        step!(pos_z, vel_z);

        let a = _mm_loadu_ps(ps.age.as_ptr().add(i));
        _mm_storeu_ps(ps.age.as_mut_ptr().add(i), _mm_add_ps(a, dt_v));
        i += 4;
    }
    while i < n {
        ps.pos_x[i] += ps.vel_x[i] * dt;
        ps.pos_y[i] += ps.vel_y[i] * dt;
        ps.pos_z[i] += ps.vel_z[i] * dt;
        ps.age[i] += dt;
        i += 1;
    }
}

// 运行时分发
fn update_dispatch(ps: &mut Particles, dt: f32) {
    if is_x86_feature_detected!("sse2") {
        unsafe { update_soa_sse2(ps, dt) }
    } else {
        update_soa_scalar(ps, dt)
    }
}

fn main() {
    use std::time::Instant;
    let iters = 10000;
    let dt = 0.016;

    // AoS
    let mut aos: Vec<Particle> = (0..N).map(|_| Particle {
        pos: [0.0; 3], vel: [1.0, 2.0, 3.0], age: 0.0, life: 5.0,
    }).collect();
    let t = Instant::now();
    for _ in 0..iters { update_aos(&mut aos, dt); }
    println!("AoS scalar:    {:>6} ms", t.elapsed().as_millis());

    // SoA scalar
    let mut ps = Particles {
        pos_x: vec![0.0; N], pos_y: vec![0.0; N], pos_z: vec![0.0; N],
        vel_x: vec![1.0; N], vel_y: vec![2.0; N], vel_z: vec![3.0; N],
        age: vec![0.0; N],
    };
    let t = Instant::now();
    for _ in 0..iters { update_soa_scalar(&mut ps, dt); }
    println!("SoA scalar:    {:>6} ms", t.elapsed().as_millis());

    // SoA SIMD
    let t = Instant::now();
    for _ in 0..iters { update_dispatch(&mut ps, dt); }
    println!("SoA SIMD:      {:>6} ms", t.elapsed().as_millis());
}
```

**关键 Rust 特性**:
- `#[target_feature(enable = "sse2")]`:函数标注,告诉 LLVM "这个函数会用 SSE2 指令"。调用方必须确保 CPU 支持,否则 UB,所以函数变 `unsafe`。
- `is_x86_feature_detected!`:运行时 CPU 特性检查宏,Rust 标准库提供。
- `macro_rules!`:在 SIMD 代码里减重复。注意宏不能"穿透"unsafe 块边界——上面 `step!` 宏在外层 `unsafe fn` 内调用,所以 OK。
- `Vec<f32>` 没保证 16 字节对齐,所以必须 `_mm_loadu_ps`(unaligned)。如果用 `Vec<f32>` + `align_to`,可以换成 `_mm_load_ps`(aligned),更快但要求严格对齐。

**Troubleshooting**:
- 编译器报 "SIMD intrinsics not available" — 你的 CPU 不支持目标特性,或没加 `#[target_feature]`
- SIMD 版本不快 — 检查 `--release`、`target-cpu=native`、循环长度是 4 的倍数
- `_mm_set_ps` 顺序乱 — 用 `_mm_setr_ps` 替代
- `cargo run` 报 SIMD 段错误 — 几乎肯定是 `_mm_load_ps`(要求对齐)用了未对齐指针,换成 `_mm_loadu_ps`
