# Day 268 · 合并调试链接与组

> profiler 的视图越加越多,UI 元素之间的关系也越来越复杂——"点这个按钮切到那个视图","hover 这个变量看它的源码"。今天 Casey 把这些关系抽象成**调试链接**(debug link)和**调试组**(debug group),让 UI 元素之间的连接可声明、可点击、可导航。

## 0 · 为什么要有这一天

你的 profiler 现在有柱状图、Top Clocks、Memory 三种视图。每个视图里都有很多元素:Top Clocks 里有 20 行条目,每行是一个函数名。你看着 "render_entity 482 ms" 这一行,想知道**这个函数的源码在哪、被谁调用、上一帧花的时间是多少**。

如果只是显示文字,你看完就过去了。但 Casey 想做的是:**让每个条目变成一个超链接**——点 "render_entity" 跳到源码,点 "482 ms" 跳到时间线视图,点 "+/- 50ms" 看变化趋势。

这就是 debug link:把 UI 元素和数据 / 视图 / 源码关联起来。HTML 里的 `<a href="...">` 是它的鼻祖。

同时,有的元素是相关的——多个 Top Clocks 条目属于"渲染"组,多个 Memory 条目属于"音频"组。Casey 引入 **debug group** 把它们组织起来,组可以折叠 / 展开,组内元素可以批量操作。

两个抽象加起来,你的 profiler 从"显示数据"升级到"可导航的数据浏览器",更像 Chrome DevTools 而不是简单面板。

实现工程难点:

1. **链接的目标**:跳到另一个视图?打开源码?高亮一个变量?需要统一的"目标"抽象
2. **组的嵌套**:组内可以再组,需要树形结构
3. **折叠状态**:每个组记录是否展开,需要持久状态
4. **点击 vs hover**:链接点击触发动作,hover 显示 tooltip,事件路由要分明

心理锚点:做完这个,你的 profiler 元素不再孤立,每个都能"点进去"看更多。

## 1 · Casey 今天做了什么

Casey 引入两个抽象:

1. **DebugLink**:`{ target: LinkTarget, hot_rect: Rect }`,LinkTarget 是 enum(SourceFile(line), SwitchView(ViewMode), FocusEntity(id), ...)
2. **DebugGroup**:`{ name, children: Vec<DebugNode>, is_expanded: bool }`,树形递归

每个 UI 元素绘制时可以注册一个 DebugLink,告诉系统"这个区域被点击时跳转到 target"。系统维护一个 links 数组,鼠标点击时遍历检查 hit_test。

DebugGroup 实现了嵌套渲染:展开时画所有 children,折叠时只画 header。展开状态用 `&mut bool` 在帧间保持。

Casey 演示了一个使用场景:Top Clocks 视图里每个条目注册一个 link,target 是"切换到 flame graph 视图并 focus 这个函数"。用户点击 "render_entity" 一行,直接跳到火焰图并定位。

## 2 · 心智模型

### 类比:网页里的超链接 + 折叠菜单

你打开 MDN 文档,左侧有侧边栏:顶级目录("CSS"、"HTML"、"JavaScript"),点击展开,里面有子目录("CSS Grid"、"CSS Flexbox"),再点击子目录跳到对应文章。

侧边栏有两层抽象:

- **超链接**(link):点一下跳到目标 URL
- **折叠菜单**(group):点 + / - 展开或折叠子项

Casey 的 debug link + debug group 就是这两层。实现上 link 和 group 可以组合(group 内可以有 link,link 可以指向 group 的展开操作)。

### 严谨原理:LinkTarget 的 enum 设计

链接的目标可以是多种类型,用 enum 表达最自然:

```rust
enum LinkTarget {
    SwitchView(ViewMode),              // 切换主视图
    OpenSource { file: &'static str, line: u32 },  // 打开源码
    FocusVariable { name_id: u32 },    // 高亮变量
    FocusEntity { entity_id: u32 },    // 跟踪实体
    ExpandGroup { group_id: u32 },     // 展开/折叠组
    ExternalUrl(&'static str),         // 外部链接(浏览器打开)
}

struct DebugLink {
    hot_rect: Rect,        // 可点击区域
    target: LinkTarget,
    tooltip: Option<&'static str>,
}
```

每个 view 在自己的 draw 函数里创建 links,系统每帧收集:

```rust
links.clear();  // 每帧重新生成
top_clocks_view.draw(&mut ctx, &mut links);
bar_chart_view.draw(&mut ctx, &mut links);
// ...
```

鼠标点击时遍历 links:

```rust
if mouse_up_event {
    for link in &links {
        if link.hot_rect.hit_test(mx, my) {
            match link.target {
                LinkTarget::SwitchView(v) => current_view = v,
                LinkTarget::OpenSource { file, line } => open_source(file, line),
                // ...
            }
            break;  // 只触发一个 link
        }
    }
}
```

### Debug Group 的树形结构

```rust
enum DebugNode {
    Leaf(DebugItem),       // 单个条目(文字 + 可选 link)
    Group(DebugGroup),     // 一组条目,可折叠
}

struct DebugGroup {
    name: &'static str,
    children: Vec<DebugNode>,
}

struct DebugItem {
    label: &'static str,
    link: Option<LinkTarget>,
}
```

递归渲染:

```rust
fn draw_node(ctx: &mut Ctx, node: &DebugNode, expanded_state: &mut HashMap<u32, bool>, depth: u32, id_gen: &mut u32) {
    let my_id = *id_gen;
    *id_gen += 1;

    match node {
        DebugNode::Leaf(item) => {
            // 画一行,缩进 depth
            draw_text(ctx, item.label, depth * 16, ...);
        }
        DebugNode::Group(group) => {
            let is_expanded = *expanded_state.entry(my_id).or_insert(true);
            // 画 header + 折叠箭头
            draw_text(ctx, if is_expanded { "v" } else { ">" }, depth * 16, ...);
            draw_text(ctx, group.name, depth * 16 + 16, ...);

            // 注册 link:点击 header 切换展开
            links.push(DebugLink {
                hot_rect: header_rect,
                target: LinkTarget::ExpandGroup { group_id: my_id },
                tooltip: None,
            });

            // 展开时递归画 children
            if is_expanded {
                for child in &group.children {
                    draw_node(ctx, child, expanded_state, depth + 1, id_gen);
                }
            }
        }
    }
}
```

**关键点**:`id_gen` 是一个全局计数器,给每个节点分配唯一 id。展开状态用 `HashMap<u32, bool>` 存,帧间保持。

### Immediate-mode 风格的简化

上面的设计有 retained-mode 的影子(显式状态 Map)。Immediate-mode 风格更简洁:

```rust
fn ui_tree(ui: &mut Ui, node: &DebugNode) {
    match node {
        DebugNode::Leaf(item) => {
            ui.label(item.label);
            // 注册 link 由 ui 系统自动处理
        }
        DebugNode::Group(group) => {
            // immediate-mode:每帧调用,内部用 id 自动跟踪展开状态
            if ui.collapsing_header(group.name, group.name as *const _ as usize) {
                for child in &group.children {
                    ui_tree(ui, child);
                }
            }
        }
    }
}
```

`ui.collapsing_header(name, id)` 接受一个 id(通常是字符串的指针或哈希),内部维护一个全局 HashMap<id, bool> 跟踪展开状态。每次调用就检查并更新。这是 Dear ImGui 的核心 trick。

Casey 走的是 retained 风格(C 的习惯),Rust 端可以用 immediate,但我们今天先走 retained,后面 Day 270+ 再考虑 immediate。

### Link 的事件处理

Link 的点击语义和 Button 不同:

| 控件 | 触发条件 |
|---|---|
| Button | 鼠标在按钮内 down + up |
| Link | 鼠标在 link 内 down + up,且没有拖动 |

为什么 link 多一个"没有拖动"条件?因为 link 通常用于文字,文字可能被选中复制。如果用户按下后拖动选中文字,松开时不应触发 link 跳转。

Casey 简化了这一行为:link 也是 down + up 触发,不支持文字选择。后面如果需要文字选择,再加这个条件。

### 3.3 · 🦀 Rust 生态视角

Rust 表达 link + group 有几个考量:

#### 用 enum 表达多态

`LinkTarget` 和 `DebugNode` 都是 enum,这是 Rust 处理"多种可能性"的标准方式。对比 C++ 的继承:

```cpp
// C++ 风格(继承)
class LinkTarget {
public:
    virtual void activate() = 0;
};
class SwitchViewTarget : public LinkTarget { ... };
class OpenSourceTarget : public LinkTarget { ... };
```

vs Rust 的 enum:

```rust
enum LinkTarget {
    SwitchView(ViewMode),
    OpenSource { file: &'static str, line: u32 },
    // ...
}
```

Rust 的 enum 更简洁、内存布局更好(无虚函数表),且 `match` 强制覆盖所有变体。

#### 用 id 而不是指针

`group_id: u32` 比 `group_ptr: *const DebugGroup` 安全得多:

- 指针可能悬空(group 被释放了)
- 指针可能在多线程下竞争
- u32 是 Copy,无所有权问题

Rust 倾向用 id(Handle / Index)代替指针表达"引用其他对象"。这是 ECS(Entity Component System)和 SlotMap 的核心思想。

#### 用 HashMap 跟踪展开状态

```rust
use std::collections::HashMap;
let mut expanded: HashMap<u32, bool> = HashMap::new();
```

简单,但每帧的 `entry(id).or_insert(default)` 有 hash 计算开销。对几百个节点来说可忽略,但如果树很大(几千节点),考虑用 `Vec<Option<bool>>`(id 直接做 index)。

### 3.4 · 软件工程:UI 抽象的层次

UI 抽象有几个层次,从低到高:

1. **绘制原语**(draw_rect / draw_text):最底层,直接画像素
2. **简单控件**(Button / Slider):组合原语,处理事件
3. **复合控件**(Tree / Table / Tab):组合简单控件,处理复杂交互
4. **Layout / Clip 系统**:跨控件的基础设施
5. **Link / Group 抽象**(今天):跨视图的导航和组织

每层抽象都让上层不必关心下层细节。今天 Casey 把层次从 3 推到 5,后面可以专注业务逻辑。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 LinkTarget 用 enum 而不是 trait object(`Box<dyn LinkTarget>`)?给出至少 3 个理由。

**参考解答**:
1. **静态分派**:enum 的 match 是编译期生成的跳转表,无虚函数调用开销;trait object 是动态分派,每次调用查 vtable
2. **内存布局**:enum 是定大小(sum type),可以放在数组里连续内存;trait object 是 Box(堆分配 + 指针 + vtable)
3. **穷尽检查**:Rust 的 match 强制覆盖所有 enum 变体,加新变体编译器报错;trait object 没这个保证
4. **值语义**:enum 是 Copy(如果内部都是 Copy 数据),传递无需借用;trait object 必须用 Box 或 &
5. **简单**:enum 的代码比 trait + impl 简洁得多,几十行 vs 几百行

什么时候用 trait object?当变体**只能在运行时确定**且**类型集合是开放的**(用户可以加新类型)。例如:插件系统、动态加载的模块。link target 的种类是固定的(SwitchView / OpenSource / ...),用 enum 最合适。

### Lv2 · 动手实践

**题**:实现 `LinkTarget` enum、`DebugLink` struct 和一个 `handle_link_click` 函数。

要求:

- LinkTarget 至少 4 种变体:SwitchView / OpenSource / FocusVariable / ExpandGroup
- DebugLink 有 hot_rect + target + tooltip
- handle_link_click 接受 links 列表和鼠标位置,返回 `Option<LinkTarget>`

测试:构造 3 个 link,模拟鼠标点击,验证返回正确的 target。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug, PartialEq)]
enum ViewMode { BarChart, TopClocks, Memory }

#[derive(Clone, Copy, Debug, PartialEq)]
enum LinkTarget {
    SwitchView(ViewMode),
    OpenSource { file: &'static str, line: u32 },
    FocusVariable { name_id: u32 },
    ExpandGroup { group_id: u32 },
}

#[derive(Clone, Copy, Debug)]
struct Rect { x: i32, y: i32, w: i32, h: i32 }

impl Rect {
    fn hit_test(&self, mx: i32, my: i32) -> bool {
        mx >= self.x && mx < self.x + self.w && my >= self.y && my < self.y + self.h
    }
}

#[derive(Clone, Copy, Debug)]
struct DebugLink {
    hot_rect: Rect,
    target: LinkTarget,
    tooltip: Option<&'static str>,
}

fn handle_link_click(links: &[DebugLink], mx: i32, my: i32) -> Option<LinkTarget> {
    // 从后往前遍历,后画的 link 在上层,优先响应
    for link in links.iter().rev() {
        if link.hot_rect.hit_test(mx, my) {
            return Some(link.target);
        }
    }
    None
}

fn main() {
    let links = vec![
        DebugLink {
            hot_rect: Rect { x: 100, y: 100, w: 80, h: 20 },
            target: LinkTarget::SwitchView(ViewMode::BarChart),
            tooltip: Some("Switch to bar chart view"),
        },
        DebugLink {
            hot_rect: Rect { x: 200, y: 100, w: 80, h: 20 },
            target: LinkTarget::OpenSource { file: "main.rs", line: 42 },
            tooltip: Some("Open source file"),
        },
        DebugLink {
            hot_rect: Rect { x: 300, y: 100, w: 80, h: 20 },
            target: LinkTarget::ExpandGroup { group_id: 1 },
            tooltip: None,
        },
    ];

    // 测试 1: 点第一个 link
    let result = handle_link_click(&links, 140, 110);
    assert_eq!(result, Some(LinkTarget::SwitchView(ViewMode::BarChart)));
    println!("Test 1 OK: {:?}", result);

    // 测试 2: 点第二个 link
    let result = handle_link_click(&links, 240, 110);
    assert_eq!(result, Some(LinkTarget::OpenSource { file: "main.rs", line: 42 }));
    println!("Test 2 OK: {:?}", result);

    // 测试 3: 点空白处
    let result = handle_link_click(&links, 500, 500);
    assert_eq!(result, None);
    println!("Test 3 OK: no link hit");
}
```

**每行解释**:
- `links.iter().rev()` 反向遍历——最后画的(上层)优先响应
- `Rect::hit_test` 检查鼠标是否在 hot_rect 内
- 返回 `Some(target)` 让调用者用 match 处理具体动作
- `tooltip: Option<&'static str>` 让某些 link 没有 tooltip(用 None)

## 8 · Rust / Arch 落地代码

### 完整可跑:profiler 带 link + group

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, MouseMode, MouseButton, Window, WindowOptions};
use std::collections::HashMap;

const WIDTH: usize = 800;
const HEIGHT: usize = 600;

#[derive(Clone, Copy, Debug, PartialEq)]
enum ViewMode { BarChart, TopClocks, Memory }

#[derive(Clone, Copy, Debug, PartialEq)]
enum LinkTarget {
    SwitchView(ViewMode),
    OpenSource { file: &'static str, line: u32 },
    FocusVariable { name_id: u32 },
    ToggleGroup { group_id: u32 },
}

#[derive(Clone, Copy, Debug)]
struct Rect { x: i32, y: i32, w: i32, h: i32 }

impl Rect {
    fn new(x: i32, y: i32, w: i32, h: i32) -> Self { Self { x, y, w, h } }
    fn hit_test(&self, mx: i32, my: i32) -> bool {
        mx >= self.x && mx < self.x + self.w && my >= self.y && my < self.y + self.h
    }
}

#[derive(Clone, Copy, Debug)]
struct DebugLink {
    hot_rect: Rect,
    target: LinkTarget,
    tooltip: Option<&'static str>,
}

// ---------- 树形数据 ----------

#[derive(Clone, Debug)]
enum DebugNode {
    Leaf { label: &'static str, link: Option<LinkTarget> },
    Group { name: &'static str, children: Vec<DebugNode> },
}

struct TreeState {
    expanded: HashMap<u32, bool>,
    next_id: u32,
}

impl TreeState {
    fn new() -> Self {
        Self { expanded: HashMap::new(), next_id: 1 }
    }
    fn gen_id(&mut self) -> u32 {
        let id = self.next_id;
        self.next_id += 1;
        id
    }
    fn is_expanded(&self, id: u32) -> bool {
        // 默认展开
        *self.expanded.get(&id).unwrap_or(&true)
    }
    fn toggle(&mut self, id: u32) {
        let current = self.is_expanded(id);
        self.expanded.insert(id, !current);
    }
}

// ---------- 绘制 ----------

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, r: Rect, color: u32) {
    for py in r.y.max(0)..(r.y + r.h).min(buf_h as i32) {
        for px in r.x.max(0)..(r.x + r.w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn draw_node(
    buf: &mut [u32],
    buf_w: usize,
    buf_h: usize,
    links: &mut Vec<DebugLink>,
    node: &DebugNode,
    state: &mut TreeState,
    depth: i32,
    y: &mut i32,
) {
    let indent = depth * 16;
    let line_h = 20;

    match node {
        DebugNode::Leaf { label, link } => {
            // 画一行
            draw_rect(buf, buf_w, buf_h,
                      Rect::new(indent, *y, 700 - indent, line_h - 2),
                      0xFF303030);
            // 注册 link(如果有)
            if let Some(target) = link {
                links.push(DebugLink {
                    hot_rect: Rect::new(indent, *y, 700 - indent, line_h - 2),
                    target: *target,
                    tooltip: Some(*label),
                });
            }
            *y += line_h;
        }
        DebugNode::Group { name, children } => {
            let my_id = state.gen_id();
            let is_expanded = state.is_expanded(my_id);

            // 画 header
            let arrow_color = 0xFFFFFFFF;
            let arrow = if is_expanded { "v" } else { ">" };
            let _ = arrow;  // 实际画字需要字体,这里用色块代替
            draw_rect(buf, buf_w, buf_h,
                      Rect::new(indent, *y, 16, line_h - 2),
                      arrow_color);
            draw_rect(buf, buf_w, buf_h,
                      Rect::new(indent + 16, *y, 700 - indent - 16, line_h - 2),
                      0xFF404040);

            // 注册 toggle link
            links.push(DebugLink {
                hot_rect: Rect::new(indent, *y, 700 - indent, line_h - 2),
                target: LinkTarget::ToggleGroup { group_id: my_id },
                tooltip: Some(*name),
            });

            *y += line_h;

            // 展开时递归
            if is_expanded {
                for child in children {
                    draw_node(buf, buf_w, buf_h, links, child, state, depth + 1, y);
                }
            }
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Debug Links + Groups", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];
    let mut current_view = ViewMode::BarChart;
    let mut tree_state = TreeState::new();

    // 构造调试树
    let tree = DebugNode::Group {
        name: "Root",
        children: vec![
            DebugNode::Group {
                name: "Render",
                children: vec![
                    DebugNode::Leaf {
                        label: "render_entity (go to source)",
                        link: Some(LinkTarget::OpenSource { file: "render.rs", line: 42 }),
                    },
                    DebugNode::Leaf {
                        label: "render_particle (go to source)",
                        link: Some(LinkTarget::OpenSource { file: "render.rs", line: 87 }),
                    },
                ],
            },
            DebugNode::Group {
                name: "View",
                children: vec![
                    DebugNode::Leaf {
                        label: "Switch to Bar Chart",
                        link: Some(LinkTarget::SwitchView(ViewMode::BarChart)),
                    },
                    DebugNode::Leaf {
                        label: "Switch to Top Clocks",
                        link: Some(LinkTarget::SwitchView(ViewMode::TopClocks)),
                    },
                    DebugNode::Leaf {
                        label: "Switch to Memory",
                        link: Some(LinkTarget::SwitchView(ViewMode::Memory)),
                    },
                ],
            },
            DebugNode::Leaf {
                label: "Focus player variable",
                link: Some(LinkTarget::FocusVariable { name_id: 0 }),
            },
        ],
    };

    let mut was_mouse_down = false;

    while window.is_open() && !window.is_key_down(Key::Escape) {
        // 清屏
        for px in buffer.iter_mut() { *px = 0xFF101010; }

        // 收集 links
        let mut links: Vec<DebugLink> = Vec::new();
        let mut y = 30;
        // 注意:tree_state.next_id 每帧重置,这样 id 稳定
        tree_state.next_id = 1;
        draw_node(&mut buffer, WIDTH, HEIGHT, &mut links, &tree, &mut tree_state, 0, &mut y);

        // 鼠标事件
        let (mx_f, my_f) = window.get_mouse_pos(MouseMode::Discard).unwrap_or((-1.0, -1.0));
        let (mx, my) = (mx_f as i32, my_f as i32);
        let is_down = window.get_mouse_down(MouseButton::Left);
        let click = is_down && !was_mouse_down;
        was_mouse_down = is_down;

        if click {
            // 反向遍历,后画的优先
            for link in links.iter().rev() {
                if link.hot_rect.hit_test(mx, my) {
                    match link.target {
                        LinkTarget::SwitchView(v) => {
                            current_view = v;
                            println!("Switched to {:?}", v);
                        }
                        LinkTarget::OpenSource { file, line } => {
                            println!("Would open {} at line {}", file, line);
                        }
                        LinkTarget::FocusVariable { name_id } => {
                            println!("Would focus variable {}", name_id);
                        }
                        LinkTarget::ToggleGroup { group_id } => {
                            tree_state.toggle(group_id);
                            println!("Toggled group {}", group_id);
                        }
                    }
                    break;
                }
            }
        }

        // 显示当前 view(右上角)
        let view_color = match current_view {
            ViewMode::BarChart => 0xFF4040FF,
            ViewMode::TopClocks => 0xFFFF4040,
            ViewMode::Memory => 0xFF40FF40,
        };
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  Rect::new(WIDTH as i32 - 100, 10, 80, 20),
                  view_color);

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }
}
```

**关键 Rust 特性解释**:

- `enum DebugNode` 用 enum 而不是 trait,递归数据结构 + 穷尽 match
- `Box<DebugNode>` 不需要——`Vec<DebugNode>` 已经管理堆,enum 本身在 Vec 里是定大小
- `tree_state.next_id = 1` 每帧重置,保证同一节点的 id 在帧间稳定(expanded state 正确)
- `links.iter().rev()` 反向遍历,后画的(上层)优先响应——和 z-order 一致
- `match link.target` 强制覆盖所有变体,加新 LinkTarget 编译器报错

**Troubleshooting**:

- 点击组没反应 — 检查 ToggleGroup 的 group_id 是否正确(应该等于 state.gen_id() 的返回值)
- 展开 / 折叠状态不持久 — 检查 tree_state.next_id 是否每帧重置
- 点击一个 link 触发多个动作 — 检查 break 是否漏写,应该找到第一个命中的 link 就退出
