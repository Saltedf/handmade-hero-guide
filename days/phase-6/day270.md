# Day 270 · 创建可遍历点

> 从今天起 Casey 开始把游戏的"自由移动"改成"瓦片式移动"(tile-based movement)的基础工作。第一步:**把游戏世界里的"位置"从连续坐标改成离散的"可遍历点"**(traversable point)。这看起来是个小改动,实际是游戏关卡设计范式的根本转变。

## 0 · 为什么要有这一天

到目前为止你的游戏里,小人可以在屏幕上**任意 2D 坐标**移动——`(x, y) = (3.14, 7.89)`,任何浮点位置都合法。这是 Phase 2 学的"自由物理":用 Euler 积分 + 碰撞检测,小人能在地图上任意滑动。

但是 Casey 现在要做的是**类 Zelda 的 2D 俯视动作游戏**(早期的"塞尔达传说:众神的三角力量"那种),这种游戏的角色移动有一个特点:**角色只能站在"格子点"上**。地图被切成 16×16 像素的格子,角色移动时:

- 从格子 A 移到相邻格子 B(上下左右)
- 移动过程中角色处于"过渡"状态,沿直线滑过去
- 到达 B 后,角色可以继续移到 C,或者停下来

这种移动有几个好处:

1. **关卡设计简化**:设计师只要标"哪些格子是地板,哪些是墙",不需要复杂碰撞
2. **AI 路径简单**:怪物按格子做 A* 寻路,标准算法
3. **战斗机制清晰":"攻击范围 1 格"这种描述天然成立
4. **视觉一致**:角色永远对齐到网格,不会出现"半个身子卡在墙里"

但是从"自由坐标"切到"网格点"是个大工程,涉及:

- 位置数据结构:从 `(x: f32, y: f32)` 改成 `TilePos(i32, i32)`
- 移动逻辑:从"持续移动"改成"格到格过渡"
- 碰撞:从"AABB vs AABB"改成"格子是否阻挡"
- 渲染:从"按浮点坐标画"改成"按格子中心 + 过渡偏移画"

Casey 没一集做完,他分了好几集:

- **今天(Day 270)**:定义 `Traversable` 抽象,表示"可站立的点"
- **Day 271**:混合瓦片式移动——角色物理仍是浮点,但目标点是离散
- **Day 272**:显式移动过渡——加状态机管理"静止 / 过渡"
- **Day 273**:动画概览
- **Day 274+**:弹簧动画让过渡更自然

今天先讲概念和基础数据结构,不动游戏逻辑。

心理锚点:看完今天,你能解释"自由移动 vs 网格移动"的本质差异,知道为什么类 Zelda 游戏选后者。

## 2 · 心智模型

### 类比:棋盘 vs 球场

想象两种空间:

**足球场(连续空间)**:球员可以站在任意位置——`((37.4, 12.8) m)`、`(41.0, 13.1) m` 都合法。规则(越位、犯规)依赖连续距离计算。

**国际象棋棋盘(离散空间)**:棋子只能站在格子上——"白兵从 e2 移到 e4"。"半个格子"这种位置不存在。规则(王车易位、将军)依赖格子坐标。

游戏世界对应:

| 游戏类型 | 空间模型 | 代表 |
|---|---|---|
| FPS | 连续(球场) | CS / Valorant |
| 类 Zelda 2D | 离散(棋盘)+ 过渡 | TLoZ / Hyper Light Drifter |
| 回合制 RPG | 完全离散 | 文明 /火焰纹章 |
| 物理沙盒 | 连续 | Angry Birds / 跨界 |

Casey 的 HH 是动作游戏,但 Casey 选"离散 + 过渡"——既保留动作游戏的流畅感,又享受网格带来的关卡设计便利。

### 严谨原理:从连续到离散的转换

#### 连续坐标(Tile-to-World)

```rust
struct WorldPos { x: f32, y: f32 }  // 像素坐标

fn world_to_tile(pos: WorldPos, tile_size: f32) -> TilePos {
    TilePos(
        (pos.x / tile_size).floor() as i32,
        (pos.y / tile_size).floor() as i32,
    )
}
```

`floor` 把浮点数取整到下方整数,例如 `3.7 / 16 = 0.23 → floor = 0`,所以像素 (3.7, 7.89) 落在 tile (0, 0)。

#### 离散坐标(Tile-to-World)

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

fn tile_to_world_center(tile: TilePos, tile_size: f32) -> WorldPos {
    WorldPos {
        x: (tile.0 as f32 + 0.5) * tile_size,
        y: (tile.1 as f32 + 0.5) * tile_size,
    }
}
```

`+ 0.5` 让坐标落在 tile 中心——如果 tile (0, 0) 覆盖像素 [0, 16)×[0, 16),那么中心是 (8, 8)。

#### "可遍历"概念

不是所有 tile 都能站。地图数据需要标记:

```rust
#[derive(Clone, Copy, Debug)]
enum TileType {
    Floor,    // 可站立
    Wall,     // 阻挡
    Water,    // 阻挡(或可游泳,根据游戏)
    Pit,      // 阻挡(掉下去)
}

impl TileType {
    fn is_traversable(self) -> bool {
        matches!(self, TileType::Floor)
    }
}

struct TileMap {
    tiles: Vec<TileType>,  // 一维数组,width * height
    width: usize,
    height: usize,
}

impl TileMap {
    fn get(&self, pos: TilePos) -> Option<TileType> {
        if pos.0 < 0 || pos.1 < 0 { return None; }
        let idx = pos.0 as usize + pos.1 as usize * self.width;
        self.tiles.get(idx).copied()
    }
    fn is_traversable(&self, pos: TilePos) -> bool {
        self.get(pos).map(|t| t.is_traversable()).unwrap_or(false)
    }
}
```

`is_traversable` 是核心查询:**给定一个 tile 坐标,角色能否站上去?**

#### "可遍历点"(Traversable Point)的抽象

Casey 进一步抽象:**不只 tile 中心,任何"角色可以站的位置"都是 Traversable Point**。这包括:

- Tile 中心(标准情况)
- Tile 边缘(用于"角色贴着墙走"的细节)
- 特殊点位(如门、楼梯、传送门的入口)

定义:

```rust
#[derive(Clone, Copy, Debug)]
struct Traversable {
    pos: WorldPos,        // 像素坐标
    tile: TilePos,        // 所属 tile
    kind: TraversableKind,  // 中心 / 边缘 / 特殊
}

#[derive(Clone, Copy, Debug)]
enum TraversableKind {
    TileCenter,
    TileEdge(Direction),
    Special(SpecialPointId),
}
```

每个 Traversable 是一个"角色可以稳定停留的位置",它和邻近的 Traversable 有"可达性"关系:

```rust
struct TraversableGraph {
    nodes: Vec<Traversable>,
    edges: Vec<Vec<usize>>,  // edges[i] = 邻接的 Traversable 索引列表
}
```

这就是一个**图**(Graph):节点是 Traversable,边表示"可以从 A 直接走到 B"。AI 寻路(A*)就在这个图上跑。

### 离散化的代价

从连续切到离散,失去几个能力:

1. **精细碰撞**:不能算"两个矩形相交多少"
2. **任意角度**:不能让小人朝任意方向走,只能上下左右(或 8 方向)
3. **物理真实**:不能做"惯性 / 加速度",因为目标是格子,不是连续位置

但是获得了:

1. **关卡设计简单**:设计师画 tile map,不用配碰撞框
2. **AI 简单**:A* 寻路直接用
3. **状态明确**:角色要么"在格子 A",要么"在过渡",没有模糊状态
4. **网络同步容易**:tile 坐标比浮点坐标同步精度高(整数 vs 浮点)

### Hybrid 方案(Casey 的选择)

完全离散会失去动作游戏的流畅感。Casey 选了**混合**:

- **目标位置是离散**(tile)
- **当前位置是连续**(浮点)
- **角色物理仍用 Euler 积分**,但目标定在 tile 中心
- **过渡过程用插值 / 弹簧**,让运动看起来平滑

具体在 Day 271-272 实现。今天先把概念和数据结构搭好。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

类 Zelda 2D 动作游戏的移动模型有几个变种:

1. **纯 4 方向**(早期 Zelda):只能上下左右,不能斜走
2. **8 方向**(Gauntlet):加上 4 个对角线
3. **任意方向但目标离散**(Diablo 2 风格):鼠标点到哪,角色寻路过去,移动平滑但目的地是 tile
4. **完全自由 + 战斗时锁定**(现代动作 RPG):平时自由,战斗时吸附到敌人

Casey 选**任意方向 + 目标离散**:按键时小人朝那个方向移动,直到下一个 tile 中心。如果按住方向键,继续到再下一个 tile。

业界还有几种实现细节:

- **Grid size**:Zelda 用 16×16,现代游戏常用 32×32 或 64×64
- **Pixel-perfect**:角色精灵对齐到 tile 时,像素级精确(避免视觉抖动)
- **Sub-tile collision**:虽然角色按 tile 移动,但碰撞用 sub-tile(更细的网格)做精细判断

### 3.2 · 🎨 图形学视角

离散坐标 + 过渡的渲染涉及几个图形学概念:

1. **Tile-based rendering**:地图用 tile 表表达,每个 tile 是一张小图
2. **Sprite alignment**:角色精灵的"脚"对齐到 tile 底部中心,这样站在 tile 上看起来自然
3. **Depth sorting**:多个角色在同一个 tile 时,谁画在上面(y 轴大的在下面)
4. **Animation interpolation**:过渡时角色精灵在两个 tile 之间线性插值

Tile-based rendering 是 1980-1990 年代主机(NES / SNES)的标准,因为内存小、硬件直接支持。现代游戏 GPU 不用 tile 表面,但概念仍在(纹理 atlas、UV 坐标)。

### 3.3 · 🐧 Linux 系统编程视角

Linux 的"网格"思想在几个地方:

1. **Terminal grid**:终端是字符网格(80×24 / 132×50),每个字符是一个"格子"
2. **Window tiling WM**(i3 / sway):窗口对齐到网格,键盘控制移动
3. **`tmux` / `screen`**:终端复用器,pane 划分基于网格

这些都是"网格化抽象"的实例。Casey 今天的 Traversable Point 抽象在精神上和它们相通:**把连续空间切成离散单元,简化推理**。

### 3.4 · 🦀 Rust 生态视角

Rust 表达"离散坐标"几个风格:

#### 风格 1:tuple struct

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);
```

简洁,直接。`derive(Eq, Hash)` 让它可以做 HashMap 的 key(后面 AI 寻路用)。

#### 风格 2:命名字段

```rust
struct TilePos { x: i32, y: i32 }
```

字段有名字,但写起来啰嗦。

#### 风格 3:newtype + 方法

```rust
struct TilePos(glm::IVec2);

impl TilePos {
    fn new(x: i32, y: i32) -> Self { Self(glm::ivec2(x, y)) }
    fn x(&self) -> i32 { self.0.x }
    fn y(&self) -> i32 { self.0.y }
}
```

复用 glam 的 IVec2,但封装一层提供"语义"——TilePos 和 ChunkPos 都是 IVec2,但混用会出 bug,newtype 让编译器区分。

#### 网格存储:1D Vec vs 2D Vec

```rust
// 1D Vec + 索引计算(推荐)
struct TileMap {
    tiles: Vec<TileType>,
    width: usize,
}

impl TileMap {
    fn get(&self, x: usize, y: usize) -> TileType {
        self.tiles[y * self.width + x]
    }
}

// 2D Vec(不推荐)
struct TileMap2 {
    tiles: Vec<Vec<TileType>>,  // 内层每行一个 Vec
}
```

1D Vec 更好:

- **内存连续**:整个地图在一个 buffer,cache 友好
- **分配少**:1 次分配 vs height 次分配
- **索引简单**:`y * width + x` 一步算

2D Vec 在 C++ / Python 常见(语法糖),但在性能敏感场景不推荐。

#### 整数 vs 浮点

`TilePos` 用 `i32` 而不是 `f32`:

- **精确**:整数无舍入误差
- **Hash 友好**:整数直接 hash,浮点不行
- **范围足够**:i32 可表示 ±20 亿 tile,远超任何游戏地图

`WorldPos` 用 `f32`,因为像素位置需要小数(过渡时)。

### 3.5 · 数学:离散几何

离散几何(Discrete Geometry)研究网格上的几何对象,和连续几何不同:

- **距离**:Manhattan(曼哈顿距离,|x1-x2| + |y1-y2|)vs Euclidean(欧氏距离)
- **直线**:Bresenham 算法(网格上的直线)vs 解析直线
- **圆**:离散圆(像素圆)vs 连续圆
- **路径**:网格 A* vs 导航网格(navmesh)

A* 在网格上常用 Manhattan 作启发式(因为只能上下左右走)。如果是 8 方向,用 Chebyshev 距离(`max(|dx|, |dy|)`)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Casey 在 `TilePos` 用 `i32` 而不是 `f32`?给出至少 3 个理由。

**参考解答**:
1. **精确性**:整数无舍入误差,两个相同的 tile 坐标用 `==` 比较永远成立。浮点的 `(0.1 + 0.2) == 0.3` 是 false,容易出 bug
2. **Hash 友好**:`i32` 直接 hash(整数 hash 简单),`f32` 的 hash 复杂(NaN != NaN, +0 == -0)
3. **范围匹配**:tile 坐标是整数,无小数意义。用 i32 表达更符合语义,阅读时不会误以为有"半个 tile"
4. **内存紧凑**:i32 是 4 字节,f32 也是 4 字节,但 i32 的语义清晰;Vec<TilePos> 紧凑排列
5. **整数运算快**:整数加减比浮点快(虽然现代 CPU 差距小),bit operation 更快
6. **类型安全**:TilePos 和 WorldPos 类型不同,编译器阻止混用(否则要写转换函数)

### Lv2 · 动手实践

**题**:实现 `TilePos` struct、`world_to_tile` / `tile_to_world_center` 转换函数,以及一个简单的 TileMap。

测试:

- `world_to_tile((10.5, 20.3), 16.0)` 应该返回 `TilePos(0, 1)`
- `tile_to_world_center(TilePos(2, 3), 16.0)` 应该返回 `(40.0, 56.0)`
- 一个 5×5 的 map,中心 (2, 2) 是 Floor,周围 8 个 tile 是 Wall,验证 `is_traversable((2, 2)) == true`、`is_traversable((0, 0)) == false`

完成标准:所有测试通过。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

#[derive(Clone, Copy, Debug)]
struct WorldPos { x: f32, y: f32 }

#[derive(Clone, Copy, Debug, PartialEq)]
enum TileType { Floor, Wall, Water }

impl TileType {
    fn is_traversable(self) -> bool {
        matches!(self, TileType::Floor)
    }
}

const TILE_SIZE: f32 = 16.0;

fn world_to_tile(pos: WorldPos) -> TilePos {
    // floor 把浮点向下取整,例如 10.5/16=0.656 → floor = 0
    TilePos(
        (pos.x / TILE_SIZE).floor() as i32,
        (pos.y / TILE_SIZE).floor() as i32,
    )
}

fn tile_to_world_center(tile: TilePos) -> WorldPos {
    WorldPos {
        x: (tile.0 as f32 + 0.5) * TILE_SIZE,
        y: (tile.1 as f32 + 0.5) * TILE_SIZE,
    }
}

struct TileMap {
    tiles: Vec<TileType>,
    width: usize,
    height: usize,
}

impl TileMap {
    fn new(width: usize, height: usize, fill: TileType) -> Self {
        Self {
            tiles: vec![fill; width * height],
            width, height,
        }
    }

    fn get(&self, pos: TilePos) -> Option<TileType> {
        if pos.0 < 0 || pos.1 < 0 { return None; }
        let (x, y) = (pos.0 as usize, pos.1 as usize);
        if x >= self.width || y >= self.height { return None; }
        Some(self.tiles[y * self.width + x])
    }

    fn set(&mut self, pos: TilePos, tile: TileType) {
        if pos.0 < 0 || pos.1 < 0 { return; }
        let (x, y) = (pos.0 as usize, pos.1 as usize);
        if x < self.width && y < self.height {
            self.tiles[y * self.width + x] = tile;
        }
    }

    fn is_traversable(&self, pos: TilePos) -> bool {
        self.get(pos).map(|t| t.is_traversable()).unwrap_or(false)
    }
}

fn main() {
    // 测试 1: 像素到 tile
    let p = WorldPos { x: 10.5, y: 20.3 };
    let t = world_to_tile(p);
    assert_eq!(t, TilePos(0, 1));
    println!("Test 1: {:?} -> {:?}", p, t);

    // 测试 2: tile 中心
    let c = tile_to_world_center(TilePos(2, 3));
    assert_eq!(c.x, 40.0);
    assert_eq!(c.y, 56.0);
    println!("Test 2: tile (2,3) center = {:?}", c);

    // 测试 3: 5x5 map,中心 Floor,周围 Wall
    let mut map = TileMap::new(5, 5, TileType::Wall);
    map.set(TilePos(2, 2), TileType::Floor);

    assert_eq!(map.is_traversable(TilePos(2, 2)), true);
    println!("Test 3a: tile (2,2) is_traversable = {}", map.is_traversable(TilePos(2, 2)));

    assert_eq!(map.is_traversable(TilePos(0, 0)), false);
    println!("Test 3b: tile (0,0) is_traversable = {}", map.is_traversable(TilePos(0, 0)));

    assert_eq!(map.is_traversable(TilePos(-1, 0)), false);  // 边界外
    println!("Test 3c: tile (-1,0) is_traversable = {}", map.is_traversable(TilePos(-1, 0)));
}
```

**每行解释**:
- `floor()` 在 Rust 里是 `f32::floor`,返回向下取整的 f32
- `as i32` 把 f32 转 i32,小数部分丢弃(本质是 truncation,但因为已经 floor,效果一致)
- `+ 0.5` 让坐标落在 tile 中心(tile (0,0) 的中心是像素 (8, 8))
- `vec![fill; n]` 创建长度为 n 的 Vec,初始全 fill
- `map.get` 返回 Option,边界外返回 None
- `unwrap_or(false)` 把 None 变成 false(默认不可站立)

## 8 · Rust / Arch 落地代码

### 完整可跑:tile map + Traversable 概念演示

```rust
// Cargo.toml:
// [dependencies]
// minifb = "0.27"

use minifb::{Key, Window, WindowOptions};

const WIDTH: usize = 800;
const HEIGHT: usize = 600;
const TILE_SIZE: i32 = 32;
const MAP_W: usize = 25;
const MAP_H: usize = 18;

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TilePos(i32, i32);

#[derive(Clone, Copy, Debug, PartialEq)]
enum TileType { Floor, Wall, Water }

impl TileType {
    fn is_traversable(self) -> bool { matches!(self, TileType::Floor) }
    fn color(self) -> u32 {
        match self {
            TileType::Floor => 0xFF404040,
            TileType::Wall  => 0xFF808080,
            TileType::Water => 0xFF2020A0,
        }
    }
}

struct TileMap {
    tiles: Vec<TileType>,
    width: usize,
    height: usize,
}

impl TileMap {
    fn new(width: usize, height: usize) -> Self {
        Self {
            tiles: vec![TileType::Floor; width * height],
            width, height,
        }
    }
    fn get(&self, pos: TilePos) -> Option<TileType> {
        if pos.0 < 0 || pos.1 < 0 { return None; }
        let (x, y) = (pos.0 as usize, pos.1 as usize);
        if x >= self.width || y >= self.height { return None; }
        Some(self.tiles[y * self.width + x])
    }
    fn set(&mut self, pos: TilePos, t: TileType) {
        if pos.0 < 0 || pos.1 < 0 { return; }
        let (x, y) = (pos.0 as usize, pos.1 as usize);
        if x < self.width && y < self.height {
            self.tiles[y * self.width + x] = t;
        }
    }
    fn is_traversable(&self, pos: TilePos) -> bool {
        self.get(pos).map(|t| t.is_traversable()).unwrap_or(false)
    }
}

fn tile_to_world_center(tile: TilePos) -> (f32, f32) {
    (
        (tile.0 as f32 + 0.5) * TILE_SIZE as f32,
        (tile.1 as f32 + 0.5) * TILE_SIZE as f32,
    )
}

fn world_to_tile(x: f32, y: f32) -> TilePos {
    TilePos(
        (x / TILE_SIZE as f32).floor() as i32,
        (y / TILE_SIZE as f32).floor() as i32,
    )
}

fn draw_rect(buf: &mut [u32], buf_w: usize, buf_h: usize, x: i32, y: i32, w: i32, h: i32, color: u32) {
    for py in y.max(0)..(y + h).min(buf_h as i32) {
        for px in x.max(0)..(x + w).min(buf_w as i32) {
            buf[(py as usize) * buf_w + (px as usize)] = color;
        }
    }
}

fn main() {
    let mut window = Window::new(
        "Traversable Points Demo", WIDTH, HEIGHT,
        WindowOptions::default(),
    ).expect("Failed to open window");

    let mut buffer = vec![0u32; WIDTH * HEIGHT];

    // 构造一个简单地图:大部分 Floor,边界 Wall,中心一个 Water 池
    let mut map = TileMap::new(MAP_W, MAP_H);
    // 边界墙
    for x in 0..MAP_W {
        map.set(TilePos(x as i32, 0), TileType::Wall);
        map.set(TilePos(x as i32, (MAP_H - 1) as i32), TileType::Wall);
    }
    for y in 0..MAP_H {
        map.set(TilePos(0, y as i32), TileType::Wall);
        map.set(TilePos((MAP_W - 1) as i32, y as i32), TileType::Wall);
    }
    // 中心水
    for y in 8..12 {
        for x in 10..15 {
            map.set(TilePos(x, y), TileType::Water);
        }
    }

    // 角色起始位置:tile (3, 3)
    let mut player_tile = TilePos(3, 3);
    let mut player_world = tile_to_world_center(player_tile);

    while window.is_open() && !window.is_key_down(Key::Escape) {
        // 移动逻辑(简化:每按一次方向键,尝试移到相邻 tile)
        let target_tile = if window.is_key_pressed(Key::W, minifb::KeyRepeat::No) {
            Some(TilePos(player_tile.0, player_tile.1 - 1))
        } else if window.is_key_pressed(Key::S, minifb::KeyRepeat::No) {
            Some(TilePos(player_tile.0, player_tile.1 + 1))
        } else if window.is_key_pressed(Key::A, minifb::KeyRepeat::No) {
            Some(TilePos(player_tile.0 - 1, player_tile.1))
        } else if window.is_key_pressed(Key::D, minifb::KeyRepeat::No) {
            Some(TilePos(player_tile.0 + 1, player_tile.1))
        } else {
            None
        };

        if let Some(t) = target_tile {
            // 检查目标是否可遍历
            if map.is_traversable(t) {
                player_tile = t;
                player_world = tile_to_world_center(t);
                println!("Moved to tile {:?}", t);
            } else {
                println!("Can't move to tile {:?} - not traversable", t);
            }
        }

        // 渲染
        for px in buffer.iter_mut() { *px = 0xFF000000; }

        // 画 tile map
        for y in 0..MAP_H {
            for x in 0..MAP_W {
                let tile = map.tiles[y * MAP_W + x];
                draw_rect(&mut buffer, WIDTH, HEIGHT,
                          x as i32 * TILE_SIZE, y as i32 * TILE_SIZE,
                          TILE_SIZE, TILE_SIZE,
                          tile.color());
            }
        }

        // 高亮当前 tile(显示"站立位置")
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  player_tile.0 * TILE_SIZE, player_tile.1 * TILE_SIZE,
                  TILE_SIZE, TILE_SIZE,
                  0x60FFFFFF);  // 半透明白

        // 画角色(在 tile 中心)
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  (player_world.0 - 8.0) as i32, (player_world.1 - 8.0) as i32,
                  16, 16,
                  0xFFFF4040);

        // 显示鼠标所在 tile 的可遍历性
        let (mx_f, my_f) = window.get_mouse_pos(minifb::MouseMode::Clamp).unwrap_or((0.0, 0.0));
        let mouse_tile = world_to_tile(mx_f, my_f);
        let traversable = map.is_traversable(mouse_tile);

        // 鼠标 tile 加边框
        let border_color = if traversable { 0xFF40FF40 } else { 0xFFFF4040 };
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  mouse_tile.0 * TILE_SIZE, mouse_tile.1 * TILE_SIZE,
                  TILE_SIZE, 2, border_color);
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  mouse_tile.0 * TILE_SIZE, mouse_tile.1 * TILE_SIZE + TILE_SIZE - 2,
                  TILE_SIZE, 2, border_color);
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  mouse_tile.0 * TILE_SIZE, mouse_tile.1 * TILE_SIZE,
                  2, TILE_SIZE, border_color);
        draw_rect(&mut buffer, WIDTH, HEIGHT,
                  mouse_tile.0 * TILE_SIZE + TILE_SIZE - 2, mouse_tile.1 * TILE_SIZE,
                  2, TILE_SIZE, border_color);

        window.update_with_buffer(&buffer, WIDTH, HEIGHT).unwrap();
    }

    println!("Final player position: tile {:?}", player_tile);
}
```

**关键 Rust 特性解释**:

- `TilePos` 派生 `Eq + Hash + PartialEq`,可以当 HashMap key
- `matches!(self, TileType::Floor)` 是 macro,等价于 `if let TileType::Floor = self { true } else { false }`
- `KeyRepeat::No` 防止按住方向键时连续触发(每次按下只移动一格)
- `MouseMode::Clamp` 让鼠标坐标 clamp 到窗口内,不会出 (-1, -1)
- 颜色编码:`0xFF404040` 是 ARGB,半透明白用 `0x60FFFFFF`(alpha = 0x60)

**Troubleshooting**:

- 角色卡在墙里 — `is_traversable` 检查在 set player_tile 之前,确认逻辑正确
