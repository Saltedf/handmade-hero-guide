
# Day 410 · 跟踪入射光

> Day 409 让多层 LPV 平滑混合,画面接缝消失了。但 Casey 发现**新问题**:**墙面接受的光照来自哪个方向**没被记录——LPV 体素只存了"总光量"(`vec3 rgb`),没有"光来自哪个方向"。这导致**镜面反射(specular)无法计算**——Phong specular 需要"指向光源的方向"做反射,LPV 没这信息。今天 Casey 给 LPV 加上**入射光方向跟踪(incident light direction)**:每个体素不只存总光量,还存"光的主要方向"。这一步是从"漫反射 GI"升级到"全 GI"的关键,数学工具是**球谐函数(Spherical Harmonics)**的简化版——**2-分量方向编码**。

## 0 · 为什么要有这一天

回到那个具体场景。Day 409 的 LPV 渲染在画面上看起来已经不错:墙面有间接光(从附近物体反弹过来的光),地面有 ambient,角落较暗。但**镜头转一转,有些角度下墙面完全失去高光(specular highlight)**——本来一面带金属质感的墙,在某个角度看应该有亮斑,但你渲染出来是哑光的。

为什么漫反射 OK 但 specular 不行?因为两者需要的信息不同。**漫反射(Lambert)** 只需要"总光量"——墙面接受多少光,就反射多少,和方向无关(假设墙面是 Lambertian)。公式:`final = N · L_total`,只要 L_total 是 RGB 向量就行。

但**镜面反射(Phong / Blinn-Phong)** 需要**指向光源的方向**——墙面像镜子,反射光的方向取决于光源的位置。公式:`specular = (R · V)^n`,R 是入射光 L 关于法线 N 的反射向量。**如果不知道 L 的方向,就不知道 R,就无法算 specular**。

LPV 体素只存了 L_total(RGB 总光量),**没有方向**。墙面采到 LPV 后,知道"墙面接收的总量",但不知道"光从哪个方向来"——无法做 specular。

工业渲染器的解决方案:**给 LPV 体素加上方向信息**。最简单的方案是存"主要方向"(dominant direction)——体素内光的平均方向,用一个 vec3 表示。但**这丢失了多方向信息**——如果体素内的光来自两个相反方向(比如墙的两面都有窗),只存"平均"会抵消成 0,完全丢失。

更高级的方案是**球谐函数(Spherical Harmonics, SH)**——把球面上的方向分布用一组正交基函数展开。SH 是图形学的核心数学工具,**PBR 渲染、IBL(Image-Based Lighting)、 irradiance volume** 都用它。Casey 在 Day 410 不直接用完整 SH(那需要 9 个或更多系数),而是用**2-分量简化版**——存"主要方向 + 各向同性强度",够支持基本 specular。

为什么这件事重要?因为**任何"重建光照方向分布"的技术**都涉及这个问题——LPV、Irradiance Volume、Probe-based GI、Reflection Probe。学会 Day 410 的方向编码,**你看 Unreal、Unity、Godot 的 GI 实现都能秒理解**。这是图形学 GI 的**核心数学**之一。

心理锚点:今天之后,你能:(1) 解释为什么 LPV 需要方向信息;(2) 理解球谐函数的基本思想(用正交基展开球面函数);(3) 在 LPV 体素里加 2-分量方向(主导方向 + 各向同性强度);(4) 用 LPV 方向信息算 Phong specular,让金属材质在所有角度都有高光。

## 1 · Casey 今天做了什么(HH 脉络)

Day 409 让 LPV 平滑混合后,Casey 测试金属材质,**注意到 specular 缺失**。他做了三件事:

1. **诊断根因**:他在 fragment shader 里把 specular 项的输出可视化(把 `specular` 当颜色输出),发现 specular 几乎全是 0。他追踪到 LPV 采样得到 `vec3 light = texture(uVoxel, uvw).rgb` 是 RGB 光量,**不是方向**——shader 里没有方向可用,只能用主光源方向,所以**只有主光源照亮的位置有 specular**,间接光位置全无 specular。

2. **设计方向存储**:Casey 给体素加一个 `vec3 direction` 字段,存"主导方向"——光从哪里来。光照传播时,每步迭代更新这个方向(加权平均入射方向)。具体:
   - 体素初始 `direction = vec3(0,0,0)`(无入射光)
   - 直接光照注入时,体素的 `direction = normalize(光源 - 体素位置)`
   - Gauss-Seidel 扩散时,neighbor 体素传播光时也传播方向(用光强做权重)

3. **shader 用方向算 specular**:fragment shader 从 LPV 采 `vec4 light = texture(uVoxel, uvw)`(RGB + 方向 alpha),用方向做 Phong specular:

```glsl
vec4 light_sample = texture(uVoxel, uvw);
vec3 light_rgb = light_sample.rgb;
vec3 light_dir = light_sample.a > 0 ? decode_direction(light_sample.a) : vec3(0);

vec3 R = reflect(-light_dir, N);  // 反射方向
float spec = pow(max(0.0, dot(R, V)), 32.0);  // Phong specular
final = light_rgb * (diffuse + spec * specular_color);
```

到 Day 410 结束,LPV 升级为"全 GI"——同时支持漫反射和镜面反射,金属材质在所有角度都有高光。

## 2 · 心智模型

### 类比:LPV 体素是"光子计数器 + 方向指示器"

想象你在墙角放一个传感器,它要做两件事:

1. **数光子**:这个传感器统计每秒接收到的光子总数,按 R/G/B 分通道记录(像 RGB 计数器)。
2. **记方向**:这个传感器还要记录"光主要从哪个方向来"——比如窗户那边有 90% 的光,门那边有 10%。

**漫反射墙面**:墙面是哑光,无论光从哪个方向来,反射强度都一样。墙面只需要"总光量",**方向不重要**。

**镜面墙面**:墙面是镜子,反射方向严格遵循反射定律。墙面**必须知道光的方向**,才能算反射方向,得到 specular。

Day 409 之前的 LPV 只做"数光子",**方向被丢失**。Day 410 加上"记方向",**LPV 体素升级为完整的 GI 探针**。

### 严谨原理:方向编码

#### 2.1 简化方案:主导方向

最简单的方向编码:**每个体素存一个单位向量 `D`**,表示光的主要方向。光照传播时:

```
注入: 体素的 D = normalize(光源位置 - 体素位置)
扩散: 体素的 D = normalize(neighbor1_D * neighbor1_intensity +
                            neighbor2_D * neighbor2_intensity + ...)
```

**问题**:如果体素的入射光来自两个相反方向,weighted average 会**抵消**,D = 0,**丢失所有方向信息**。

**举例**:体素 A 在两堵墙之间,左墙反射红光(方向 +x),右墙反射蓝光(方向 -x)。如果只存主导方向,weighted average: `D = normalize(+x * 0.5 + -x * 0.5) = normalize(0) = ???`——无定义。

#### 2.2 进阶方案:球谐函数

工业级的解决方案是**球谐函数(SH)**。SH 是球面上的一组正交基函数,把任意球面函数 `f(θ, φ)` 展开成 SH 系数。

**SH 的层次**:
- SH order 0:**1 个系数**,只表示"总光量"(各向同性)
- SH order 1:**4 个系数**(1 + 3),增加 3 个方向系数(对应 x, y, z 三个轴)
- SH order 2:**9 个系数**,增加 5 个二次项(各向异性,如"上下方向多,左右少")
- SH order 3:**16 个系数**,更复杂

工业渲染器(Precomputed Radiance Transfer、Irradiance Volume)通常用 **order 2(9 系数)**——足够表示 diffuse GI,开销可控。

**SH order 1 的物理意义**:
- 第 0 系数:`Y_0^0 = 常数`(总光量)
- 第 1 系数:`Y_1^{-1} = y 分量`(光的 y 方向偏移)
- 第 2 系数:`Y_1^0 = z 分量`
- 第 3 系数:`Y_1^1 = x 分量`

4 个系数可以重建"光的总强度 + 主导方向"。这等价于"RGB + vec3 方向",**正好是 Casey Day 410 的方案**。Casey 不显式叫 SH,但数学上是 SH order 1。

#### 2.3 数据布局

LPV 体素加方向后,数据布局变化:

```rust
// Day 409 之前:每体素 12 字节
#[derive(Copy, Clone, Pod, Zeroable)]
#[repr(C)]
struct Voxel {
    r: f32, g: f32, b: f32,  // RGB 光量
}

// Day 410:每体素 24 字节(RGBA16F × 2 texels)
// 或者用 16 字节:RGB(光量) + 打包方向到 alpha
#[derive(Copy, Clone, Pod, Zeroable)]
#[repr(C)]
struct Voxel {
    r: f32, g: f32, b: f32,    // 光量
    dx: f32, dy: f32, dz: f32, // 方向(单位向量)
    intensity: f32,            // 方向强度(0=无方向,1=有方向)
}
```

**优化**:用 texture 数组,一个 texel 存 RGB,另一个存方向(打包)。这样能利用 GPU 的 RGBA texture 单元,不用自定义格式。

#### 2.4 方向重建

从 LPV 采样后,fragment shader 用方向做 specular:

```glsl
// 采样
vec4 sample0 = texture(uVoxelRGB, uvw);   // RGB 光量,可能 A 是强度
vec4 sample1 = texture(uVoxelDir, uvw);   // 方向 xyz,A 是强度

vec3 light_rgb = sample0.rgb;
vec3 light_dir = sample1.xyz;
float dir_strength = sample1.a;

// Specular(只在 dir_strength > 0 时算)
vec3 R = reflect(-light_dir, N);
float spec = pow(max(0.0, dot(R, V)), shininess) * dir_strength;

vec3 final = light_rgb * (diffuse_factor + spec * specular_color);
```

**关键**:用 `dir_strength` 控制 specular 强度。如果 `dir_strength = 0`(无方向),specular 项为 0,退化为纯漫反射。

### 光照传播更新

加上方向后,**Gauss-Seidel 迭代**也要更新——不仅要传播光量,还要传播方向。

```rust
// 旧版(Day 405):只传播光量
fn propagate_light(grid: &mut VoxelGrid) {
    for each cell (x, y, z) {
        let mut sum = Vec3::ZERO;
        for neighbor in 6_neighbors(x, y, z) {
            sum += neighbor.rgb;
        }
        cell.rgb = sum / 6.0;
    }
}

// 新版(Day 410):传播光量 + 方向
fn propagate_light_with_dir(grid: &mut VoxelGrid) {
    for each cell (x, y, z) {
        let mut sum_rgb = Vec3::ZERO;
        let mut weighted_dir = Vec3::ZERO;
        let mut total_intensity = 0.0;

        for neighbor in 6_neighbors(x, y, z) {
            // 光量传播(无方向加权和)
            sum_rgb += neighbor.rgb;

            // 方向传播(用光强做权重)
            let intensity = neighbor.rgb.length();
            weighted_dir += neighbor.direction * intensity;
            total_intensity += intensity;
        }

        cell.rgb = sum_rgb / 6.0;
        // 主导方向:加权平均后归一化
        if total_intensity > 1e-6 {
            cell.direction = weighted_dir.normalize();
            cell.dir_strength = weighted_dir.length() / total_intensity;  // [0, 1]
        } else {
            cell.direction = Vec3::ZERO;
            cell.dir_strength = 0.0;
        }
    }
}
```

**关键**:
- 方向用光强加权(`weighted_dir += neighbor.direction * intensity`)——亮的体素对方向贡献大
- `dir_strength` 表示方向一致性(0=光来自各方向,1=光来自单一方向)
- 退化情况:光来自两相反方向,weighted_dir 抵消,`dir_strength → 0`

### 球谐函数的直觉

完整理解 SH 需要数学背景,但**直觉**可以这样:

SH 是球面上的"傅里叶基"——任何球面上的函数(方向分布)都能用 SH 系数展开。

- **Order 0**(1 系数):常数,代表"总光量"。比如体素接受 100 单位光。
- **Order 1**(3 系数):线性,代表"光偏向哪个方向"。比如光主要来自 +x。
- **Order 2**(5 系数):二次,代表"光的二次各向异性"。比如"光在 xy 平面比 z 方向多"。
- ...

**类比音频 EQ**:音频是 1D 信号(时间),傅里叶展开得到频谱(bass、mid、treble)。SH 是 2D 信号(球面),展开得到"方向频谱"——0 阶是各向同性(像 DC 分量),1 阶是方向偏移(像低频),2 阶是方向二阶矩(像中频)。

**为什么 SH 用得多**?因为它**正交、紧凑、易计算**:
- 正交:不同 SH 基函数内积为 0,系数独立
- 紧凑:9 系数(order 2)足够 diffuse GI
- 易计算:重建时是 `sum(coefficient_i * basis_i(direction))`,简单的点积

工业渲染器(Unreal、Unity)的 IBL、Lightmap、Probe 都是 SH。**学会 SH 你看 GI 不再是黑盒**。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏开发里"光照方向跟踪"的几种实现:

| 方案 | 数据 | 优点 | 缺点 |
|---|---|---|---|
| LPV with direction(本日) | RGB + vec3 dir | 紧凑、易实现 | 单方向,多光源丢失 |
| SH order 1(4 系数) | vec4 | 4 系数包含方向 | 不能表示二次各向异性 |
| SH order 2(9 系数) | vec9(打包) | diffuse GI 标准 | 内存大,shader 重 |
| Reflection Probe | 立方体贴图 | specular 完美 | 静态,只能预设位置 |
| Sparse Voxel Octree | 体素 + SH | 完整 GI | 极复杂,实现成本高 |

**工业 GI 方案对比**:
- **Unity Enlighten**:Precomputed Realtime GI,基于 SH
- **Unreal LPV**:Casey 的方案,基于 LPV with direction
- **Unreal GFRT**(Global Illumination via Ray Tracing):用 GPU RT cores,基于 SH 或 Radiances
- **Godot 4 SDFGI**:Signed Distance Field GI,基于 SDF + SH

**共性**:**都用某种形式存储方向信息**——SH 系数、vec3 方向、立方体贴图。差别只在精度和开销。

### 3.2 · 🎨 图形学视角

光照的**辐射度量学(radiometry)** 数学:

- **Radiance L(p, ω)**:在点 p 沿方向 ω 的光强。单位:W/(sr·m²)
- **Irradiance E(p)**:点 p 接受的总光强,所有方向积分。单位:W/m²
- **关系**:`E(p) = ∫ L(p, ω) cos(θ) dω`,θ 是表面法线和 ω 的夹角

**漫反射(纯 irradiance)**:`outgoing = E(p) / π`,与方向无关。**只存 E**(标量或 RGB)就够。

**镜面反射(需要 radiance)**:`outgoing(ω_o) = ∫ L(p, ω_i) f_r(ω_i, ω_o) cos(θ_i) dω`,`f_r` 是 BRDF。**需要存 L(p, ω)**(球面函数)。SH 是这个球面函数的紧凑表示。

**Casey Day 410 的简化**:存"主方向 + 总强度",近似 SH order 1。**精度足够 specular highlight**(主光源方向决定),但**对多次反射(角落里两个面的反射)**效果有限。

**SH 在工业渲染的用法**:

1. **Precomputed Radiance Transfer(PRT)**:离线预算 SH 系数存到 lightmap,运行时用 SH 重建。
2. **Irradiance Volume**:把空间离散成网格,每格存 SH 系数,fragment shader 采 SH 重建 irradiance。
3. **Light Probe**:在场景几个位置采 SH 系数(动态或静态),fragment shader 按距离插值。
4. **Image-Based Lighting(IBL)**:从环境贴图(cube map)积分得到 SH 系数,用于物体反射环境光。

**SH 数学**(简略):

```
SH 系数:c_l^m = ∫ f(ω) Y_l^m(ω) dω
重建:f(ω) ≈ Σ c_l^m Y_l^m(ω)
```

`Y_l^m` 是 SH 基函数,前 9 个:

```
Y_0^0 = 1/2 √(1/π)
Y_1^{-1} = y √(3/(4π))
Y_1^0 = z √(3/(4π))
Y_1^1 = x √(3/(4π))
Y_2^{-2} = xy √(15/(4π))
Y_2^{-1} = yz √(15/(4π))
Y_2^0 = (3z²-1)/2 √(5/(16π))
Y_2^1 = xz √(15/(4π))
Y_2^2 = (x²-y²)/2 √(15/(16π))
```

**重建 diffuse irradiance** 用 SH order 2 系数:简单的 9 个点积。这是 Precomputed GI 的标准做法。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上做 SH 计算的开源库:

- **Intel Open Image Denoise**:用 SH 表示方向光,做降噪
- **Blender Cycles**:Path tracer 用 SH 表示 irradiance cache
- **Mitsuba 3**:科研渲染器,SH 是基础工具

**性能层面**:SH order 2(9 系数)重建 diffuse,每像素 9 次 multiply-add,GPU 上**几乎免费**。但如果每个体素都存 9 系数 × RGB = 27 floats,32³ LPV 要 27 × 32³ × 4 = 3.5 MB——可接受。但 128³ 是 226 MB,不现实。

**SIMD 友好**:SH 系数是密集浮点数组,SIMD 化(4-wide SSE / 8-wide AVX)几乎完美并行。

**多线程光照传播**:Gauss-Seidel 串行,但 **Red-Black Gauss-Seidel** 可以并行——把网格分成红黑两色(像国际象棋棋盘),红色格子只依赖黑色,黑色只依赖红色。两个 pass 可并行。Day 415+ Casey 把光照传播改用 compute shader 多线程。

### 3.4 · 🦀 Rust 生态视角

Rust 实现 LPV with direction:

```rust
// src/lpv/voxel.rs
use bytemuck::{Pod, Zeroable};
use glam::Vec3;

#[derive(Copy, Clone, Pod, Zeroable)]
#[repr(C)]
pub struct Voxel {
    pub r: f32,
    pub g: f32,
    pub b: f32,
    pub dx: f32,
    pub dy: f32,
    pub dz: f32,
    pub dir_strength: f32,
    // 总共 28 字节,加 padding 到 32 字节(SIMD 友好)
    pub _pad: f32,
}

impl Voxel {
    pub const ZERO: Self = Self {
        r: 0.0, g: 0.0, b: 0.0,
        dx: 0.0, dy: 0.0, dz: 0.0,
        dir_strength: 0.0, _pad: 0.0,
    };

    pub fn rgb(&self) -> Vec3 {
        Vec3::new(self.r, self.g, self.b)
    }

    pub fn direction(&self) -> Vec3 {
        Vec3::new(self.dx, self.dy, self.dz)
    }
}

pub struct VoxelGrid {
    pub cells: Vec<Voxel>,
    pub width: usize,
    pub height: usize,
    pub depth: usize,
}

impl VoxelGrid {
    pub fn new(w: usize, h: usize, d: usize) -> Self {
        Self {
            cells: vec![Voxel::ZERO; w * h * d],
            width: w, height: h, depth: d,
        }
    }

    pub fn idx(&self, x: usize, y: usize, z: usize) -> usize {
        x + y * self.width + z * self.width * self.height
    }

    /// 注入光源:在光源位置最近的体素存光强 + 方向
    pub fn inject_light(&mut self, light_pos: Vec3, light_color: Vec3, grid_min: Vec3, voxel_size: f32) {
        let voxel_coord = ((light_pos - grid_min) / voxel_size);
        let x = voxel_coord.x as usize;
        let y = voxel_coord.y as usize;
        let z = voxel_coord.z as usize;
        if x < self.width && y < self.height && z < self.depth {
            let i = self.idx(x, y, z);
            self.cells[i].r = light_color.x;
            self.cells[i].g = light_color.y;
            self.cells[i].b = light_color.z;
            // 方向:光向外辐射,这里设为 0(各向同性),后续传播时算
            self.cells[i].dir_strength = 0.0;
        }
    }

    /// 光照传播(一步 Gauss-Seidel,带方向)
    pub fn propagate_step(&mut self) {
        let w = self.width;
        let h = self.height;
        let d = self.depth;
        let mut new_cells = self.cells.clone();

        for z in 0..d {
            for y in 0..h {
                for x in 0..w {
                    let mut sum_rgb = Vec3::ZERO;
                    let mut weighted_dir = Vec3::ZERO;
                    let mut total_intensity = 0.0f32;

                    let neighbors = [
                        (x>0).then(|| (x-1, y, z)),
                        (x<w-1).then(|| (x+1, y, z)),
                        (y>0).then(|| (x, y-1, z)),
                        (y<h-1).then(|| (x, y+1, z)),
                        (z>0).then(|| (x, y, z-1)),
                        (z<d-1).then(|| (x, y, z+1)),
                    ];

                    for n_opt in neighbors.iter() {
                        if let Some((nx, ny, nz)) = n_opt {
                            let n = &self.cells[self.idx(*nx, *ny, *nz)];
                            let intensity = n.rgb().length();
                            sum_rgb += n.rgb();
                            weighted_dir += n.direction() * intensity;
                            total_intensity += intensity;
                        }
                    }

                    let cell = &mut new_cells[self.idx(x, y, z)];
                    cell.r = sum_rgb.x / 6.0;
                    cell.g = sum_rgb.y / 6.0;
                    cell.b = sum_rgb.z / 6.0;
                    if total_intensity > 1e-6 {
                        let dir = weighted_dir / total_intensity;
                        let len = dir.length();
                        if len > 1e-6 {
                            cell.dx = dir.x / len;
                            cell.dy = dir.y / len;
                            cell.dz = dir.z / len;
                            cell.dir_strength = len.min(1.0);
                        }
                    }
                }
            }
        }

        self.cells = new_cells;
    }
}
```

### Fragment Shader 用 LPV 方向

```glsl
// src/shaders/lpv_specular.frag
#version 430
in vec3 vWorldPos;
in vec3 vNormal;
out vec4 fragColor;

uniform sampler3D uVoxelTex;       // RGB=光量,A=强度
uniform sampler3D uVoxelDirTex;    // RGB=方向,A=方向强度
uniform vec3 uGridMin, uGridMax;
uniform vec3 uCameraPos;
uniform vec3 uSpecularColor;
uniform float uShininess;

void main() {
    vec3 uvw = (vWorldPos - uGridMin) / (uGridMax - uGridMin);

    // 采样
    vec4 light_sample = texture(uVoxelTex, uvw);
    vec4 dir_sample = texture(uVoxelDirTex, uvw);

    vec3 light_rgb = light_sample.rgb;
    vec3 light_dir = dir_sample.rgb;
    float dir_strength = dir_sample.a;

    // 漫反射
    vec3 N = normalize(vNormal);
    vec3 V = normalize(uCameraPos - vWorldPos);
    float diffuse = max(0.0, dot(N, light_dir)) * 0.5 + 0.5;  // wrap light

    // Specular(只在有方向时算)
    vec3 R = reflect(-light_dir, N);
    float spec_base = max(0.0, dot(R, V));
    float spec = pow(spec_base, uShininess) * dir_strength;

    vec3 final = light_rgb * (diffuse + spec * uSpecularColor);
    fragColor = vec4(final, 1.0);
}
```

## 5 · 对照与变奏

### 漫反射 GI vs 镜面 GI

| 维度 | 漫反射 GI | 镜面 GI |
|---|---|---|
| 物理量 | Irradiance E(p) | Radiance L(p, ω) |
| 维度 | 3D 空间 + RGB | 3D 空间 + RGB + 2D 方向 = 5D |
| 存储 | RGB per voxel | RGB + SH per voxel |
| 计算复杂度 | O(N³) | O(N³ × SH_count) |
| 视觉效果 | 软阴影、颜色溢出 | 镜面反射、清晰的反射 |
| 工业方案 | Lightmap、LPV、SDFGI | Reflection Probe、RTX |

**核心差别**:**漫反射 GI 是 3D 问题,镜面 GI 是 5D 问题**。5D 数据无法直接存,**SH 等正交基压缩**是唯一可行方案。

### SH order 0 vs 1 vs 2

| Order | 系数数 | 表示能力 | 内存(RGB) |
|---|---|---|---|
| 0 | 1 | 总光量 | 12 字节 |
| 1 | 4 | 总光量 + 方向 | 48 字节 |
| 2 | 9 | 总光量 + 方向 + 二次各向异性 | 108 字节 |
| 3 | 16 | 更精细的方向分布 | 192 字节 |

**典型工程选择**:
- Order 0:太弱,不能 specular
- Order 1(Casey Day 410):够 specular highlight,内存可控
- Order 2:工业标准,高质量 GI
- Order 3+:科研用,实时太重

### 历史演化

- **1998:Sillion 等人提出 Irradiance Volume**,用 SH 存光照分布
- **2001:Sloan 提出 Precomputed Radiance Transfer**(PRT),SH 用于动态光照
- **2010:Crytek LPV** —— 把 SH 思路简化为"主导方向"
- **2014:Unreal Engine 4** 整合 LPV / SVO GI
- **2018+:RTX / DXR** —— 硬件 ray tracing 让 GI 不再需要 SH 近似
- **2024+:Path Tracing in Games**(Alan Wake 2、Cyberpunk 2077),完全跳过 SH

Casey Day 410 是 LPV 演化中"加方向"的关键一步,**核心思想 30 年没变**:用紧凑表示存方向分布。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 LPV 体素只存 RGB 光量无法做 specular?具体说出 specular 计算公式,标出"哪个量缺失"。

**参考解答**:

Phong specular 公式:

```
specular = (R · V)^n × light_color × material_specular
```

其中:
- `R = reflect(-L, N)` — 反射方向
- `V` — 视线方向(从片元到相机)
- `L` — **指向光源的方向**
- `N` — 表面法线
- `n` — shininess(镜面指数)

**缺失的量**:`L`(指向光源的方向)。LPV 体素存的是 RGB 光量(总光强),**没有 L**。所以 `R` 无法计算,`(R · V)^n` 无法计算,specular 项为 0 或退化为主光源方向。

Day 410 加上"主导方向 D"后,用 D 替代 L,specular 可以计算。但 D 是"平均方向",多光源会失真。

### 完整带方向的 LPV 系统

```rust
// src/lpv/mod.rs
use bytemuck::{Pod, Zeroable};
use glam::Vec3;

pub mod voxel;
pub mod propagation;
pub mod shading;

pub use voxel::{Voxel, VoxelGrid};

/// LPV 渲染管线
pub struct LpvPipeline {
    pub coarse_grid: VoxelGrid,  // 32³
    pub medium_grid: VoxelGrid,  // 64³
    pub fine_grid: VoxelGrid,    // 128³

    // GPU 资源
    pub coarse_tex_rgb: <glow::Context as HasContext>::Texture,
    pub coarse_tex_dir: <glow::Context as HasContext>::Texture,
    // ... medium, fine 也类似
}

impl LpvPipeline {
    /// 每帧更新光照
    pub fn update(&mut self, lights: &[Light], dt: f32) {
        // 1. 清空体素(衰减)
        for grid in [&mut self.coarse_grid, &mut self.medium_grid, &mut self.fine_grid] {
            for cell in grid.cells.iter_mut() {
                cell.r *= 0.95;  // 衰减 5%
                cell.g *= 0.95;
                cell.b *= 0.95;
            }
        }

        // 2. 注入光源
        for light in lights {
            self.coarse_grid.inject_light(light.pos, light.color, Vec3::ZERO, 1.0);
            self.medium_grid.inject_light(light.pos, light.color, Vec3::ZERO, 0.5);
            self.fine_grid.inject_light(light.pos, light.color, Vec3::ZERO, 0.25);
        }

        // 3. 光照传播(几步 Gauss-Seidel)
        for _ in 0..8 {
            self.coarse_grid.propagate_step();
        }
        for _ in 0..6 {
            self.medium_grid.propagate_step();
        }
        for _ in 0..4 {
            self.fine_grid.propagate_step();
        }
    }

    /// 上传到 GPU
    pub fn upload_to_gpu(&self, gl: &glow::Context) {
        // 拆分 RGB 和方向到两个 texture
        let (rgb_data, dir_data) = split_rgb_dir(&self.coarse_grid);
        unsafe {
            gl.bind_texture(glow::TEXTURE_3D, Some(self.coarse_tex_rgb));
            gl.tex_sub_image_3d(
                glow::TEXTURE_3D, 0, 0, 0, 0,
                self.coarse_grid.width as i32,
                self.coarse_grid.height as i32,
                self.coarse_grid.depth as i32,
                glow::RGBA, glow::FLOAT,
                glow::PixelUnpackData::Slice(Some(bytemuck::cast_slice(&rgb_data))),
            );
            gl.bind_texture(glow::TEXTURE_3D, Some(self.coarse_tex_dir));
            gl.tex_sub_image_3d(
                glow::TEXTURE_3D, 0, 0, 0, 0,
                self.coarse_grid.width as i32,
                self.coarse_grid.height as i32,
                self.coarse_grid.depth as i32,
                glow::RGBA, glow::FLOAT,
                glow::PixelUnpackData::Slice(Some(bytemuck::cast_slice(&dir_data))),
            );
        }
    }
}

#[derive(Copy, Clone, Pod, Zeroable)]
#[repr(C)]
struct GpuRgb { r: f32, g: f32, b: f32, intensity: f32 }

#[derive(Copy, Clone, Pod, Zeroable)]
#[repr(C)]
struct GpuDir { dx: f32, dy: f32, dz: f32, strength: f32 }

fn split_rgb_dir(grid: &VoxelGrid) -> (Vec<GpuRgb>, Vec<GpuDir>) {
    let rgb: Vec<GpuRgb> = grid.cells.iter().map(|c| {
        let intensity = (c.r * c.r + c.g * c.g + c.b * c.b).sqrt();
        GpuRgb { r: c.r, g: c.g, b: c.b, intensity }
    }).collect();
    let dir: Vec<GpuDir> = grid.cells.iter().map(|c| {
        GpuDir { dx: c.dx, dy: c.dy, dz: c.dz, strength: c.dir_strength }
    }).collect();
    (rgb, dir)
}

pub struct Light {
    pub pos: Vec3,
    pub color: Vec3,
}
```
