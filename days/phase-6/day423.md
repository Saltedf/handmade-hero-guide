
# Day 423 · 修改光照使用空间层次

> Day 422 实现了 ray-AABB,但每帧 N 个图元 × M 个采样 × L 个光源 = N×M×L 次 ray-cast,每次遍历所有遮挡物。如果场景有 1000 个遮挡物,成本爆炸。今天 Casey 引入**空间加速结构(Spatial Acceleration Structure)**——**BVH(Bounding Volume Hierarchy)**,把 ray-cast 从 O(N) 降到 O(log N)。

## 0 · 为什么要有这一天

具体算账:场景 1000 个遮挡物(墙、家具),每个图元 4 个采样,16 个图元,1 个光源。可见性测试次数:`16 × 4 × 1 × 1000 = 64000` 次 ray-AABB。每次 ray-AABB 是 ~10ns,总 640 微秒,占 16ms 帧预算的 4%。还能接受。

但如果光源数变 8 个,图元数变 1000 个,采样数变 16 次:`1000 × 16 × 8 × 1000 = 1.28 亿`次 ray-AABB,1.28 秒!不可接受。

问题在于:**每个 ray 都遍历所有 AABB**,但大部分 AABB 离 ray 很远,根本不可能相交。这是浪费。

工业的解决方案:**空间层次结构**。把 AABB 组织成一棵树:

- 叶节点:单个 AABB
- 内部节点:子节点的合并 AABB

光线遍历时,先和根节点(整个场景的 AABB)测试;不相交就立刻 return,跳过整个场景。相交则递归子节点,把搜索空间每次减半。

复杂度从 O(N) 降到 O(log N)——1000 个遮挡物,大概 10 次比较就够(2^10 = 1024)。

这种数据结构叫 **BVH(Bounding Volume Hierarchy)** 或 **BSP / k-d tree**。所有现代 ray tracer(pbrt、Mitsuba、OptiX、Embree)都用 BVH。

Casey 今天做 HH 的 BVH,实现 ray 遍历 BVH 的核心算法。这一步是 day431 SIMD raycasting 的前提——SIMD 加速的是单次 ray-AABB,BVH 加速的是"哪个 AABB 值得测试",两者正交但都需要。

心理锚点:今天之后,你能从零写一个 BVH,理解工业 ray tracer 的核心数据结构,知道为什么 ray tracing 能实时(O(log N) 的力量),能为 Rust 生态贡献 BVH crate。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 在白板上画了一棵 BVH 树:

```
              [Root AABB]
              /         \
        [Left AABB]    [Right AABB]
        /     \          /        \
     [A]    [B]       [C]        [D]
     叶     叶          叶         叶
```

每个内部节点的 AABB 是子节点 AABB 的并集。光线从 root 进入,递归遍历:

```
fn ray_traverse(node):
    if not ray_vs_aabb(node.bounds): return  # 不相交,跳过子树
    if node is leaf:
        for object in node.objects:
            test ray vs object
    else:
        ray_traverse(node.left)
        ray_traverse(node.right)
```

Casey 实现 BVH 的两个阶段:

1. **构建**:给定 N 个 AABB,递归二分(选最长的轴,按中心点排序,前一半给 left,后一半给 right)
2. **遍历**:ray 走 BVH,找到最近相交

构建是离线过程(场景变化时重建),遍历是运行时(每帧每 ray 一次)。

Casey 强调**优化重点**:遍历是热路径,构建是冷路径。构建可以慢(场景加载时一次),遍历必须快(每帧百万次)。

## 2 · 心智模型

### 类比:电话簿找人

想象你在电话簿找一个名字。电话簿按字母排序:

- 翻到中间 → 在 M 段
- 你要找的姓是 S → 比 M 大,翻后半本
- 翻后半本中间 → 在 R 段
- 你找的 S 比 R 大,翻后半本
- 几次后定位

这是**二分查找**,O(log N)。

如果电话簿没排序,你只能从头翻到尾,O(N)。1000 页电话簿,二分 10 次,顺序 1000 次。

BVH 完全同构。N 个 AABB,BVH 树高 log N。Ray 遍历 BVH = 二分查找相交对象,每次减半。

### 严谨原理:BVH 构建

输入:N 个物体(每个有 AABB)。
输出:BVH 树。

**Top-down 构建**(最常用):

```
fn build(objects):
    if len(objects) <= leaf_threshold:
        return Leaf(objects)
    # 选最长轴
    axis = longest_axis(objects)
    # 按轴中心排序
    sort objects by center[axis]
    # 取中位数,前一半给 left,后一半给 right
    mid = len(objects) / 2
    left_child = build(objects[..mid])
    right_child = build(objects[mid..])
    bounds = union(left_child.bounds, right_child.bounds)
    return Internal(bounds, left_child, right_child)
```

复杂度:O(N log N)(排序主导)。

**最长轴选择**:让分割平面垂直于场景最长的轴,通常让子树更均衡。例如场景是长走廊(X 方向长),按 X 切分。

**SAH(Surface Area Heuristic)**:更高级,选择让"光线索引成本"最小的切分。复杂但更优,工业 pbrt 用。Casey 用简单的 longest-axis,够用。

### BVH 遍历

两种遍历方式:

**递归**(简单):

```
fn traverse(ray, node):
    if not ray_vs_aabb(ray, node.bounds): return None
    match node:
        Leaf(objects) => {
            for obj in objects: test ray vs obj
        }
        Internal(left, right) => {
            // 通常先遍历近的(early-out 优化)
            let near = if ray.dir[node.split_axis] > 0 { left } else { right }
            let far = the other
            let hit = traverse(ray, near)
            if hit and hit.t < current_best: update best
            if far.bounds could contain closer hit: traverse(ray, far)
        }
}
```

**迭代 + 栈**(避免递归开销):

```
fn traverse_iterative(ray, root):
    stack = [root]
    while stack not empty:
        node = stack.pop()
        if not ray_vs_aabb(ray, node.bounds): continue
        match node:
            Leaf(objects) => { test all objects }
            Internal(left, right) => {
                stack.push(right)
                stack.push(left)
            }
    }
```

迭代版用显式栈,Rust 的 `Vec<Node>` 当栈。比递归快(无函数调用开销),且避免栈溢出(深 BVH)。

### Rust 视角:BVH 表达

```rust
#[derive(Debug)]
pub enum BvhNode {
    Leaf {
        bounds: AABB,
        objects: Vec<u32>,  // 物体索引
    },
    Internal {
        bounds: AABB,
        left: Box<BvhNode>,
        right: Box<BvhNode>,
    },
}

impl BvhNode {
    pub fn bounds(&self) -> AABB {
        match self {
            BvhNode::Leaf { bounds, .. } => *bounds,
            BvhNode::Internal { bounds, .. } => *bounds,
        }
    }
}

pub struct Bvh {
    pub root: BvhNode,
}

impl Bvh {
    pub fn build(objects: &[(u32, AABB)]) -> Self {
        Self { root: Self::build_recursive(objects) }
    }

    fn build_recursive(objects: &[(u32, AABB)]) -> BvhNode {
        if objects.len() <= 4 {
            // 叶节点
            let bounds = objects.iter()
                .map(|(_, a)| *a)
                .fold(AABB::EMPTY, |a, b| a.union(b));
            return BvhNode::Leaf {
                bounds,
                objects: objects.iter().map(|(i, _)| *i).collect(),
            };
        }
        // 找最长轴
        let overall_bounds = objects.iter()
            .map(|(_, a)| *a)
            .fold(AABB::EMPTY, |a, b| a.union(b));
        let extent = overall_bounds.max - overall_bounds.min;
        let axis = if extent.x >= extent.y && extent.x >= extent.z { 0 }
                   else if extent.y >= extent.z { 1 }
                   else { 2 };

        // 按 axis 中心排序
        let mut sorted = objects.to_vec();
        sorted.sort_by(|a, b| {
            let ca = (a.1.min[axis] + a.1.max[axis]) * 0.5;
            let cb = (b.1.min[axis] + b.1.max[axis]) * 0.5;
            ca.partial_cmp(&cb).unwrap()
        });

        let mid = sorted.len() / 2;
        let left = Box::new(Self::build_recursive(&sorted[..mid]));
        let right = Box::new(Self::build_recursive(&sorted[mid..]));

        BvhNode::Internal {
            bounds: overall_bounds,
            left,
            right,
        }
    }
}
```

`Box<BvhNode>` 是堆分配的递归类型——Rust 不允许递归 enum 不带 Box(编译期大小未知)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

工业 BVH 用法:

- **Ray tracing**:每个像素发射 ray,BVH 加速场景遍历
- **视锥剔除**:相机视锥 vs BVH,跳过不可见区域
- **碰撞检测**:子弹 vs 场景,BVH 加速
- **Occlusion culling**:HiZ(Hierarchical Z-buffer),BVH 思想

NVidia RTX 硬件原生支持 BVH 遍历(TU-Op in shader),GPU 端跑 BVH 比软件快 10 倍。

### 3.2 · 🎨 图形学视角

BVH 的几个变种:

- **LBVH(Linear BVH)**:基于 Morton 码构建,并行友好
- **SBVH(Spatial Split BVH)**:允许 AABB 重叠,更紧凑
- **HLBVH(Hierarchical Linear BVH)**:结合 LBVH 和 SAH
- **Treelets**:局部重构,适配动态场景

工业的 **Embree**(Intel)和 **OptiX**(NVIDIA)都实现了多个 BVH 变种,自动选择最优。

### 3.3 · 🐧 Linux 系统编程视角

Linux 内核的层次结构同构:

- **页表(page table)**:4 层,虚拟地址 → 物理地址,O(1)(深度固定)
- **ext4 extent tree**:文件块索引,O(log N)
- **rbtree / xarray**:内核通用查找,O(log N)

页表本质上是个 4 层的 BVH——每层 9 位,共 36 位地址,每次减半搜索空间。和 BVH 思路一致。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:BVH 和 k-d tree 都用空间分割加速,有什么本质区别?为什么 ray tracer 偏好 BVH?

**参考解答**:**BVH** 按物体分割——每个叶节点存若干物体的引用,内部节点的 AABB 是子节点 AABB 的并。物体不重复出现(每个物体在一个叶)。

**k-d tree** 按空间分割——每个内部节点是一个平面(垂直某轴),空间被切成两半。一个物体可能跨多个区域(需要切分或复制)。

本质区别:**BVH 适合动态**(物体移动,只需更新 AABB);**k-d tree 适合静态**(切分固定,无法轻易更新)。

Ray tracer 偏好 BVH 因为:
1. 现代游戏场景动态(角色、物体移动)
2. BVH 重构便宜(物体 AABB 变,递归更新)
3. GPU RTX 硬件原生 BVH

### Lv2 · 动手实践

**题**:实现 BVH 构建 + ray 遍历,验证 O(log N)。完成标准:
- 1000 个随机 AABB,BVH 构建 < 50ms
- Ray 遍历 BVH 比线性遍历快 10x+

**参考解答**:

```rust
use glam::Vec3;

#[derive(Copy, Clone, Debug)]
pub struct AABB { pub min: Vec3, pub max: Vec3 }

impl AABB {
    pub const EMPTY: Self = Self {
        min: Vec3::splat(f32::INFINITY),
        max: Vec3::splat(f32::NEG_INFINITY),
    };
    pub fn union(self, other: Self) -> Self {
        Self {
            min: self.min.min(other.min),
            max: self.max.max(other.max),
        }
    }
    pub fn center(&self) -> Vec3 { (self.min + self.max) * 0.5 }
    pub fn extent(&self) -> Vec3 { self.max - self.min }
}

pub fn ray_vs_aabb(origin: Vec3, dir: Vec3, aabb: AABB) -> bool {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    for axis in 0..3 {
        let o = origin[axis]; let d = dir[axis];
        let lo = aabb.min[axis]; let hi = aabb.max[axis];
        if d.abs() < 1e-8 {
            if o < lo || o > hi { return false; }
        } else {
            let inv_d = 1.0 / d;
            let t1 = (lo - o) * inv_d;
            let t2 = (hi - o) * inv_d;
            let (te, tx) = if t1 < t2 { (t1, t2) } else { (t2, t1) };
            t_min = t_min.max(te);
            t_max = t_max.min(tx);
            if t_min > t_max { return false; }
        }
    }
    t_max >= 0.0
}

#[derive(Debug)]
pub enum BvhNode {
    Leaf { bounds: AABB, objects: Vec<u32> },
    Internal { bounds: AABB, left: Box<BvhNode>, right: Box<BvhNode> },
}

impl BvhNode {
    pub fn bounds(&self) -> AABB {
        match self {
            BvhNode::Leaf { bounds, .. } => *bounds,
            BvhNode::Internal { bounds, .. } => *bounds,
        }
    }
}

pub fn build(objects: &[(u32, AABB)]) -> BvhNode {
    if objects.len() <= 4 {
        let bounds = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
        return BvhNode::Leaf {
            bounds,
            objects: objects.iter().map(|(i, _)| *i).collect(),
        };
    }
    let overall = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
    let ext = overall.extent();
    let axis = if ext.x >= ext.y && ext.x >= ext.z { 0 }
               else if ext.y >= ext.z { 1 } else { 2 };
    let mut sorted: Vec<_> = objects.to_vec();
    sorted.sort_by(|a, b| {
        let ca = a.1.center()[axis];
        let cb = b.1.center()[axis];
        ca.partial_cmp(&cb).unwrap()
    });
    let mid = sorted.len() / 2;
    let left = Box::new(build(&sorted[..mid]));
    let right = Box::new(build(&sorted[mid..]));
    BvhNode::Internal { bounds: overall, left, right }
}

pub fn traverse(origin: Vec3, dir: Vec3, node: &BvhNode) -> Vec<u32> {
    if !ray_vs_aabb(origin, dir, node.bounds()) {
        return vec![];
    }
    match node {
        BvhNode::Leaf { objects, .. } => objects.clone(),
        BvhNode::Internal { left, right, .. } => {
            let mut hits = traverse(origin, dir, left);
            hits.extend(traverse(origin, dir, right));
            hits
        }
    }
}

fn main() {
    // 1000 个随机 AABB
    let mut rng_state = 42u32;
    let mut next = || {
        rng_state = rng_state.wrapping_mul(1664525).wrapping_add(1013904223);
        rng_state
    };
    let objects: Vec<(u32, AABB)> = (0..1000).map(|i| {
        let x = (next() as f32 / u32::MAX as f32 - 0.5) * 100.0;
        let y = (next() as f32 / u32::MAX as f32 - 0.5) * 100.0;
        let z = (next() as f32 / u32::MAX as f32 - 0.5) * 100.0;
        let s = (next() as f32 / u32::MAX as f32) * 2.0 + 0.5;
        let center = Vec3::new(x, y, z);
        let half = Vec3::splat(s);
        (i, AABB { min: center - half, max: center + half })
    }).collect();

    let start = std::time::Instant::now();
    let bvh = build(&objects);
    let build_time = start.elapsed();
    println!("BVH build: {:?} for {} objects", build_time, objects.len());

    let ray_origin = Vec3::new(-200.0, 0.0, 0.0);
    let ray_dir = Vec3::new(1.0, 0.0, 0.0);

    let start = std::time::Instant::now();
    let hits = traverse(ray_origin, ray_dir, &bvh);
    let bvh_time = start.elapsed();
    println!("BVH traverse: {:?}, {} hits", bvh_time, hits.len());

    // 线性遍历对比
    let start = std::time::Instant::now();
    let linear_hits: Vec<u32> = objects.iter()
        .filter(|(_, a)| ray_vs_aabb(ray_origin, ray_dir, *a))
        .map(|(i, _)| *i)
        .collect();
    let linear_time = start.elapsed();
    println!("Linear traverse: {:?}, {} hits", linear_time, linear_hits.len());

    let speedup = linear_time.as_nanos() as f64 / bvh_time.as_nanos() as f64;
    println!("Speedup: {:.1}x", speedup);
}
```

pub enum BvhNode {
    Leaf { bounds: AABB, objects: Vec<u32> },
    Internal { bounds: AABB, left: Box<BvhNode>, right: Box<BvhNode> },
}

impl BvhNode {
    pub fn bounds(&self) -> AABB {
        match self {
            BvhNode::Leaf { bounds, .. } => *bounds,
            BvhNode::Internal { bounds, .. } => *bounds,
        }
    }

    pub fn build(objects: &[(u32, AABB)]) -> Self {
        if objects.is_empty() {
            return BvhNode::Leaf { bounds: AABB::EMPTY, objects: vec![] };
        }
        if objects.len() <= 4 {
            let bounds = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
            return BvhNode::Leaf {
                bounds,
                objects: objects.iter().map(|(i, _)| *i).collect(),
            };
        }
        let overall = objects.iter().fold(AABB::EMPTY, |acc, (_, a)| acc.union(*a));
        let ext = overall.extent();
        let axis = if ext.x >= ext.y && ext.x >= ext.z { 0 }
                   else if ext.y >= ext.z { 1 } else { 2 };
        let mut sorted: Vec<_> = objects.to_vec();
        sorted.sort_by(|a, b| {
            a.1.center()[axis].partial_cmp(&b.1.center()[axis]).unwrap()
        });
        let mid = sorted.len() / 2;
        let left = Box::new(Self::build(&sorted[..mid]));
        let right = Box::new(Self::build(&sorted[mid..]));
        BvhNode::Internal { bounds: overall, left, right }
    }

    pub fn traverse(&self, origin: Vec3, dir: Vec3, visit: &mut impl FnMut(u32)) {
        if !ray_vs_aabb(origin, dir, self.bounds()) { return; }
        match self {
            BvhNode::Leaf { objects, .. } => {
                for o in objects { visit(*o); }
            }
            BvhNode::Internal { left, right, .. } => {
                left.traverse(origin, dir, visit);
                right.traverse(origin, dir, visit);
            }
        }
    }

    pub fn count_nodes(&self) -> usize {
        match self {
            BvhNode::Leaf { .. } => 1,
            BvhNode::Internal { left, right, .. } => {
                1 + left.count_nodes() + right.count_nodes()
            }
        }
    }
}

fn main() {
    let objects: Vec<(u32, AABB)> = (0..100).map(|i| {
        let x = (i as f32) * 1.5 - 75.0;
        let half = Vec3::splat(0.5);
        let center = Vec3::new(x, 0.0, 0.0);
        (i, AABB { min: center - half, max: center + half })
    }).collect();

    let bvh = BvhNode::build(&objects);
    println!("BVH has {} nodes for {} objects",
        bvh.count_nodes(), objects.len());

    let ray_origin = Vec3::new(-100.0, 0.0, 0.0);
    let ray_dir = Vec3::new(1.0, 0.0, 0.0);

    let mut hits = Vec::new();
    bvh.traverse(ray_origin, ray_dir, &mut |i| hits.push(i));
    println!("Ray hit {} objects", hits.len());

    // BVH 应该高效剪枝
    let ray_dir_miss = Vec3::new(0.0, 1.0, 0.0);
    let mut hits_miss = Vec::new();
    bvh.traverse(ray_origin, ray_dir_miss, &mut |i| hits_miss.push(i));
    println!("Ray miss hit {} objects (should be 0)", hits_miss.len());
}

### 深度推导:本日相关数学与算法

要真正掌握今天的内容,我们必须把背后的数学推导展开。这一节是"为什么这么做"的论证。

**算法复杂度的精确分析**。今天的代码涉及到对实体集合排序,基准复杂度:

- 最优比较排序下界:O(N log N)(决策树理论)
- Rust `sort_by`:TimSort,平均 O(N log N),最好 O(N)(已部分有序时)
- 拓扑排序:O(V + E),V 是节点数,E 是边数
- Radix sort:O(N × k),k 是 sort key 位数——非比较排序,可突破 O(N log N)

对一个 1000 sprite 的场景,TimSort 大约 10000 次比较,每次比较 5-10 个 cycle(分支少),总 50000-100000 cycle = 20-40 μs。在 60 FPS(16666 μs 预算)占 0.2%——可忽略。100K sprite 时升到 2 ms,开始有压力。Minecraft 这种规模的游戏必须用 radix sort 或 GPU sort。

**内存访问模式**。sort 是**非线性内存访问**的典型——每次比较都可能跳到 Vec 不同位置。CPU prefetcher 抓不到模式,cache miss 频繁。优化:

1. **Sort by index**:先 sort indices(u32 数组,4 字节/项,cache 友好),再 reorder 数据。indices 1000 个 = 4 KB,L1 cache 装得下。
2. **Batch reorder**:indices 排好后,顺序遍历 indices,顺序访问原数据(虽然是间接但 prefetcher 跟得上)。

```rust
let mut indices: Vec<u32> = (0..entities.len() as u32).collect();
indices.sort_by(|&a, &b| sort_rule(&entities[a as usize], &entities[b as usize]));
let sorted: Vec<&Entity> = indices.iter().map(|&i| &entities[i as usize]).collect();
```

100K sprite 的 sort 用这个技巧能加速 30%。

**位运算打包 sort key**。今天 sort_key 是 u64,可以塞进多个字段:

```
bits 63-56: layer (8 bits, 256 layers)
bits 55-40: bottom_y (16 bits, 65536 levels)
bits 39-24: x (16 bits)
bits 23-8: sub_layer (16 bits)
bits 7-0: spawn_id (8 bits, 256 entries per slot)
```

打包:`key = (layer << 56) | (bottom_y << 40) | (x << 24) | (sub << 8) | spawn`。一次 u64 比较,无分支,Rust `sort_by_key` 自动 inline。

**部分序的图论模型**。Day 304 会用拓扑排序处理真正的部分序。每个 sprite 是图节点,如果 A 应该在 B 前面,加边 A→B。拓扑排序给出节点的合法顺序(满足所有约束)。

拓扑排序算法:

1. **Kahn 算法**:每次找入度为 0 的节点,加入结果,删掉它的出边,重复。
2. **DFS 后序**:DFS 遍历,记录后序(post-order),反转得到拓扑序。

如果图有环(循环依赖),拓扑排序失败——意味着 sprite 排序无解,必须**人为拆解**(切开某个 sprite)。

**浮点数的稳定性**。Rust 的 `f32::partial_cmp` 处理 NaN 返回 `None`,sort 会 panic。所以游戏代码里要么保证所有 f32 都不是 NaN(数学保证),要么 `partial_cmp(...).unwrap_or(Equal)`(默认相等)。今天 sort_rule 用后者。

更稳妥的方法:**所有位置用整数**(像素单位)。`pos_y: i32` 没有 NaN 问题,比较无分支。但缩放和旋转要用浮点,所以游戏用 i32 + f32 混合。

### 真实代码片段

Casey 在 HH 视频里实际写的代码风格(简化伪代码):

```c
internal int32
SortRule(entity *A, entity *B)
{
    int32 Result = 0;

    // Layer 比较
    if (A->Layer != B->Layer) {
        Result = (int32)A->Layer - (int32)B->Layer;
    } else {
        // Bounds overlap 检查
        rectangle2 BoundsA = GetEntityBounds(A);
        rectangle2 BoundsB = GetEntityBounds(B);
        if (RectanglesOverlap(BoundsA, BoundsB)) {
            // Bottom y 比较
            real32 BottomA = BoundsA.Max.Y;
            real32 BottomB = BoundsB.Max.Y;
            if (BottomA != BottomB) {
                Result = (BottomA < BottomB) ? -1 : 1;
            } else {
                // x 比较
                Result = SignOf32(A->P.X - B->P.X);
            }
        } else {
            // 不重叠:任意顺序
            Result = A->SpawnID - B->SpawnID;
        }
    }

    return Result;
}
```

注意 Casey 的 C 风格:

- 直接返回 int32(而非 enum Ordering)
- 用 `SignOf32`(返回 -1/0/1)简化比较
- if-else 链而非 Rust 的 `then_with`

Rust 等价:

```rust
fn sort_rule(a: &Entity, b: &Entity) -> Ordering {
    a.layer.cmp(&b.layer)
        .then_with(|| {
            if bounds_overlap(a, b) {
                let ba = bounds(a).max.y;
                let bb = bounds(b).max.y;
                ba.partial_cmp(&bb).unwrap_or(Ordering::Equal)
                    .then(a.pos.x.partial_cmp(&b.pos.x).unwrap_or(Ordering::Equal))
            } else {
                a.spawn_id.cmp(&b.spawn_id)
            }
        })
}
```

### 跨学科联结:从游戏到数据库

sort_rule 的本质是"复杂比较函数",这在很多领域都出现:

- **数据库 ORDER BY**:SQL 的 `ORDER BY layer, y, x` 是同样的 multi-key sort,但 SQL 是声明式(数据库优化器选 sort 算法),Casey 是命令式(手写 sort_by)。
- **React diff**:React 用 sort + key 比较 virtual DOM,决定哪些 component 重渲染。Multi-key sort 决定 diff 顺序。
- **Linux kernel CFS**(Completely Fair Scheduler):按 vruntime 排序进程,选最小 vruntime 的运行。本质是 sort_rule。
- **Git log --sort**:Git commit 按 committer date + author date + subject 排序。

Casey 在 HH 反复说"很多算法本质相同,只是命名不同"。掌握一个领域的 sort_rule,就掌握所有领域。
