# Day 327 · 解析 printf 格式串

> 昨天 Casey 理解了 vararg 机制,今天开始手写 printf 的核心——格式串解析器。一个字符一个字符地走,识别 `%d`、`%s` 等格式 specifier,构造一个"格式描述"数据结构。

## 0 · 为什么要有这一天

printf 的核心难点不是"打印",而是"解析格式串"。看这个调用:

```c
printf("Name: %-20s Age: %5d\n", name, age);
```

格式串 `"Name: %-20s Age: %5d\n"` 包含三种内容:

1. **字面量**:`Name: `、` Age: `、`\n` —— 直接输出
2. **格式 specifier**:`%-20s`、`%5d` —— 对应参数,有特殊语义
3. ** specifier 内部的 flag/width**:`-`(左对齐)、`20`(宽度)、`5`(宽度)

格式 specifier 的语法:`%[flags][width][.precision][length]specifier`

- `flags`:`-`(左对齐)、`+`(显示正号)、` `(空格填充)、`0`(零填充)、`#`(alt 形式)
- `width`:最小宽度(数字或 `*`)
- `.precision`:精度(`.数字`)
- `length`:`h`(short)、`l`(long)、`ll`(long long)、`z`(size_t)
- `specifier`:`d`、`s`、`f`、`x`、`o`、`c`、`p` 等

今天 Casey 实现"格式串解析"——把 `"%-20s"` 这样的字符串解析成一个数据结构:

```c
struct format_spec {
    bool left_align;
    int width;
    int precision;
    char length;
    char specifier;
};
```

后续根据这个 spec 决定怎么打印对应参数。

心理锚点:今天之后你能写自己的字符串解析器,理解 printf 内部工作。明天(day328)实现具体打印(整数、字符串)。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_printf.cpp`,实现格式串解析器。

具体步骤:

1. 定义 `format_spec` 结构
2. 写 `parse_format_spec(fmt, &spec)` 函数,从 `%` 后开始解析
3. 实现每个字段(flags / width / precision / length / specifier)的解析
4. 处理错误(未知 specifier、截断)

Casey 的解析器是"递归下降式"——一个字符一个字符看,根据当前状态决定下一步:

```c
const char *parse_format_spec(const char *p, format_spec *spec) {
    // 假设 *p == '%',已经跳过
    p++;
    
    // 1. flags
    spec->left_align = false;
    spec->plus = false;
    spec->zero_pad = false;
    while (*p == '-' || *p == '+' || *p == ' ' || *p == '0' || *p == '#') {
        switch (*p) {
            case '-': spec->left_align = true; break;
            case '+': spec->plus = true; break;
            case '0': spec->zero_pad = true; break;
            // ...
        }
        p++;
    }
    
    // 2. width
    spec->width = 0;
    if (*p == '*') {
        // width 从参数取(va_arg)
        spec->width_from_arg = true;
        p++;
    } else {
        while (*p >= '0' && *p <= '9') {
            spec->width = spec->width * 10 + (*p - '0');
            p++;
        }
    }
    
    // 3. precision
    spec->precision = -1;
    if (*p == '.') {
        p++;
        spec->precision = 0;
        while (*p >= '0' && *p <= '9') {
            spec->precision = spec->precision * 10 + (*p - '0');
            p++;
        }
    }
    
    // 4. length
    spec->length = 0;
    if (*p == 'h' || *p == 'l' || *p == 'z' || *p == 'j') {
        spec->length = *p;
        p++;
        // 处理 hh, ll
        if (*p == spec->length) p++;  
    }
    
    // 5. specifier
    spec->specifier = *p;
    p++;
    
    return p;
}
```

Casey 强调几个细节:

1. **数字解析**:`while (*p >= '0' && *p <= '9') spec->width = spec->width * 10 + (*p - '0')` 是经典手写数字解析
2. **`*` 处理**:width/precision 可以是 `*`,表示从参数取。但 Casey 今天先不支持,简化
3. **错误处理**:未知 specifier 直接输出原字符(`%x` 不认识就输出 `%x`)

## 2 · 心智模型

### 类比:阅读菜谱

把格式串解析想象成读菜谱。

菜谱有:
- **步骤描述**(字面量):"加入 200g 面粉"
- **食材引用**(`%s` 之类):"(参见食材清单 1)"
- **食材描述**:`%s` 的 `s` 表示"是字符串",`%-20s` 的 `-20` 表示"用 20 字符宽度"

解析器读菜谱时,识别"步骤描述"和"食材引用",为每个食材引用构造一个描述(食材编号、宽度、对齐)。

### 严谨原理:状态机视角

格式串解析可以看作状态机:

```
状态:LITERAL(字面量) → 见到 '%' → SPEC_START → FLAGS → WIDTH → PRECISION → LENGTH → SPECIFIER → LITERAL
```

每个状态根据当前字符决定下一步:

- LITERAL 状态:`%` 转 SPEC_START,其他字符输出
- SPEC_START 状态:`%` 转义、flag 字符转 FLAGS、数字转 WIDTH
- FLAGS 状态:flag 字符继续,数字转 WIDTH
- ...

Casey 的实现是"线性解析"(不是显式状态机),但概念等价。

### printf 格式 specifier 完整语法

```
%[flags][width][.precision][length]specifier

flags:
  -     左对齐(默认右对齐)
  +     强制显示正号
  (space)  正数前填空格(代替 +)
  0     数字前填 0(代替 space)
  #     alt 形式(八进制前 0,十六进制前 0x)

width:
  数字     最小宽度
  *        从参数取

.precision:
  .数字    精度(字符串最大长度,浮点小数位)
  .*       从参数取

length:
  hh    char / unsigned char
  h     short / unsigned short
  (无)  int / unsigned int
  l     long / unsigned long
  ll    long long / unsigned long long
  z     size_t
  j     intmax_t
  t     ptrdiff_t

specifier:
  d, i  有符号十进制
  u     无符号十进制
  o     八进制
  x, X  十六进制
  f, F  浮点
  e, E  科学计数法
  g, G  自动选择 %f 或 %e
  c     字符
  s     字符串
  p     指针
  %     字面的 %(转义)
```

Casey 的实现先做核心:`d`、`s`、`x`、`c`、`%`,其他后续 day 加。

### Rust 实现

```rust
#[derive(Default, Debug)]
struct FormatSpec {
    left_align: bool,
    plus: bool,
    zero_pad: bool,
    alt: bool,
    space: bool,
    width: usize,
    width_from_arg: bool,
    precision: i32,  // -1 = 无精度
    precision_from_arg: bool,
    length: char,    // 'h', 'l', 'z' 等
    specifier: char, // 'd', 's', 'f' 等
}

fn parse_format_spec(fmt: &[u8], pos: &mut usize) -> FormatSpec {
    // 假设 fmt[*pos] == '%',已跳过
    *pos += 1;
    let mut spec = FormatSpec {
        precision: -1,
        ..Default::default()
    };
    
    // flags
    while *pos < fmt.len() {
        match fmt[*pos] {
            b'-' => spec.left_align = true,
            b'+' => spec.plus = true,
            b'0' => spec.zero_pad = true,
            b'#' => spec.alt = true,
            b' ' => spec.space = true,
            _ => break,
        }
        *pos += 1;
    }
    
    // width
    if *pos < fmt.len() && fmt[*pos] == b'*' {
        spec.width_from_arg = true;
        *pos += 1;
    } else {
        while *pos < fmt.len() && fmt[*pos].is_ascii_digit() {
            spec.width = spec.width * 10 + (fmt[*pos] - b'0') as usize;
            *pos += 1;
        }
    }
    
    // precision
    if *pos < fmt.len() && fmt[*pos] == b'.' {
        *pos += 1;
        spec.precision = 0;
        if *pos < fmt.len() && fmt[*pos] == b'*' {
            spec.precision_from_arg = true;
            *pos += 1;
        } else {
            while *pos < fmt.len() && fmt[*pos].is_ascii_digit() {
                spec.precision = spec.precision * 10 + (fmt[*pos] - b'0') as i32;
                *pos += 1;
            }
        }
    }
    
    // length
    if *pos < fmt.len() && matches!(fmt[*pos], b'h' | b'l' | b'z' | b'j' | b't') {
        spec.length = fmt[*pos] as char;
        *pos += 1;
        // hh, ll
        if *pos < fmt.len() && fmt[*pos] as char == spec.length {
            *pos += 1;
        }
    }
    
    // specifier
    if *pos < fmt.len() {
        spec.specifier = fmt[*pos] as char;
        *pos += 1;
    }
    
    spec
}
```

### 3.2 · 🐧 Linux 系统编程视角

Linux 内核 printk 的格式扩展:

- `%pK`:内核指针(屏蔽非特权用户)
- `%pOF`:device tree 节点
- `%pU`:UUID
- `%pI4`:IPv4 地址
- `%pS`:内核符号名

这些 `%p` 扩展是内核特有,标准 printf 没有。内核的 vsnprintf 实现也自写,不依赖 libc。

Linux 用户态 strace 解析系统调用参数也类似——解析格式串 + 取参数,但解析更复杂(每个 syscall 有不同参数 schema)。

### 3.3 · 🦀 Rust 生态视角

Rust 标准库 `format_args!` + `Arguments` 类型在编译期解析格式串:

```rust
// 编译期解析 "Hello {}"
let args = format_args!("Hello {}, count = {}", name, count);
// args 是 Arguments 类型,延迟格式化

// 运行时按 args 的格式描述打印
println!("{}", args);
```

`format_args!` 的好处:

1. **编译期检查**:`format_args!("Hello {}", name)` 编译器检查 name 的类型可 Display
2. **零分配**:Arguments 不分配 String,直接流式输出
3. **延迟格式化**:可以传给多个目标(终端、文件、网络)

Rust 的 `fmt::Arguments` 内部就是个格式描述数据结构,和今天的 `FormatSpec` 概念一致。

### 3.4 · 数学/算法视角

格式串解析是经典的 **recursive descent parsing**(递归下降解析)。这种解析技术广泛用于:

- **编译器前端**:解析 C / Rust 源代码
- **JSON / XML / YAML 解析器**:解析数据格式
- **HTTP / SMTP 解析器**:解析网络协议
- **正则表达式编译器**:解析正则语法

理解 printf 格式串解析,你看任何 parser 都能秒懂。Casey 今天教的是 parser 的最简版。

## 5 · 对照与变奏

### 历史演化

- **1970s C printf**:原始格式串,specifier 简单
- **1980s ANSI C**:标准化 flags / width / precision
- **1990s C99**:加 `%ll`(long long)、`%z`(size_t)
- **2010s Rust**:`{:?}` 调试格式、`{:#?}` 美化、`{:x}` 十六进制
- **2020s Python f-string**:嵌入表达式,超越 printf

### 工业级 vs 教学版

| 特性 | 教学版(今天) | 工业版(glibc) |
|---|---|---|
| specifier 数 | 5-10 | 30+ |
| locale 支持 | 无 | 完整 |
| 参数位置 | 顺序 | `$`(指定位置) |
| unicode | ASCII | wchar / UTF-8 |

### 跨语言变体

| 语言 | 格式化方式 |
|---|---|
| C | printf(`%d %s`) |
| Rust | `{} {:?}` |
| Python 3 | f-string(`{name}`)、% |
| C# | `$"{name}"`、`string.Format` |
| JavaScript | `${name}`(模板字符串) |

C# 的 `$"{name}"` 和 Python 的 f-string 是"现代格式化"——在格式串里直接写表达式,编译期或运行时求值。比 C printf 类型更安全。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:printf 格式 specifier 的语法 `%[flags][width][.precision][length]specifier` 中,flags 和 length 都是"单字符",为什么 length 要单独归类?

**参考解答**:

1. **语义不同**:flags 修饰"输出样式"(对齐、填充),length 修饰"参数类型"(short/long)。两者正交。
2. **顺序固定**:flags 在 width 前,length 在 specifier 前,不能互换。如果合并归类,顺序模糊。
3. **历史**:C89 标准化了 specifier 语法,各字段独立有意义。

### Lv2 · 动手实践

**题**:在 Rust 里实现 printf 格式串解析器,要求:

- 解析 `%[flags][width][.precision]specifier`
- 输出 FormatSpec 结构
- 测试几种格式:`%d`、`%-20s`、`%+08.2f`、`%llx`

**参考解答**:

```rust
#[derive(Default, Debug, PartialEq)]
struct FormatSpec {
    left_align: bool,
    plus: bool,
    zero_pad: bool,
    alt: bool,
    space: bool,
    width: usize,
    precision: i32,
    length: char,
    specifier: char,
}

fn parse(fmt: &str) -> Vec<(String, Option<FormatSpec>)> {
    let mut result = Vec::new();
    let bytes = fmt.as_bytes();
    let mut i = 0;
    let mut literal = String::new();
    
    while i < bytes.len() {
        if bytes[i] == b'%' {
            // 保存之前的 literal
            if !literal.is_empty() {
                result.push((literal.clone(), None));
                literal.clear();
            }
            
            i += 1;  // 跳过 %
            let mut spec = FormatSpec {
                precision: -1,
                ..Default::default()
            };
            
            // flags
            while i < bytes.len() {
                match bytes[i] {
                    b'-' => spec.left_align = true,
                    b'+' => spec.plus = true,
                    b'0' => spec.zero_pad = true,
                    b'#' => spec.alt = true,
                    b' ' => spec.space = true,
                    _ => break,
                }
                i += 1;
            }
            
            // width
            while i < bytes.len() && bytes[i].is_ascii_digit() {
                spec.width = spec.width * 10 + (bytes[i] - b'0') as usize;
                i += 1;
            }
            
            // precision
            if i < bytes.len() && bytes[i] == b'.' {
                i += 1;
                spec.precision = 0;
                while i < bytes.len() && bytes[i].is_ascii_digit() {
                    spec.precision = spec.precision * 10 + (bytes[i] - b'0') as i32;
                    i += 1;
                }
            }
            
            // length
            if i < bytes.len() && matches!(bytes[i], b'h' | b'l' | b'z' | b'j' | b't') {
                spec.length = bytes[i] as char;
                i += 1;
                if i < bytes.len() && bytes[i] as char == spec.length {
                    i += 1;  // hh, ll
                }
            }
            
            // specifier
            if i < bytes.len() {
                spec.specifier = bytes[i] as char;
                i += 1;
            }
            
            result.push((String::new(), Some(spec)));
        } else {
            literal.push(bytes[i] as char);
            i += 1;
        }
    }
    
    if !literal.is_empty() {
        result.push((literal, None));
    }
    
    result
}

fn main() {
    let cases = ["%d", "%-20s", "%+08.2f", "%llx", "Hello %s, count = %d\n"];
    for case in cases {
        println!("\n=== {:?} ===", case);
        for (lit, spec) in parse(case) {
            if let Some(spec) = spec {
                println!("  Spec: {:?}", spec);
            } else {
                println!("  Literal: {:?}", lit);
            }
        }
    }
}
```

## 8 · Rust / Arch 落地代码

### Rust:printf 格式串解析器(完整可跑)

```rust
// Cargo.toml: 无依赖
// src/main.rs

#[derive(Default, Debug, PartialEq)]
struct FormatSpec {
    left_align: bool,
    plus: bool,
    zero_pad: bool,
    alt: bool,
    space: bool,
    width: usize,
    precision: i32,    // -1 = 无精度
    length: String,    // "h", "l", "ll", "z", ...
    specifier: char,   // 'd', 's', 'f', ...
}

impl FormatSpec {
    fn describe(&self) -> String {
        let mut s = String::new();
        if self.left_align { s.push('-'); }
        if self.plus { s.push('+'); }
        if self.zero_pad { s.push('0'); }
        if self.alt { s.push('#'); }
        if self.space { s.push(' '); }
        if self.width > 0 { s.push_str(&self.width.to_string()); }
        if self.precision >= 0 {
            s.push('.');
            s.push_str(&self.precision.to_string());
        }
        s.push_str(&self.length);
        s.push(self.specifier);
        s
    }
}

enum FormatPart {
    Literal(String),
    Spec(FormatSpec),
}

fn parse_format(fmt: &str) -> Vec<FormatPart> {
    let mut result = Vec::new();
    let bytes = fmt.as_bytes();
    let mut i = 0;
    let mut literal = String::new();
    
    while i < bytes.len() {
        if bytes[i] == b'%' {
            // flush literal
            if !literal.is_empty() {
                result.push(FormatPart::Literal(literal.clone()));
                literal.clear();
            }
            
            i += 1;
            
            // %% 转义
            if i < bytes.len() && bytes[i] == b'%' {
                literal.push('%');
                i += 1;
                continue;
            }
            
            let mut spec = FormatSpec {
                precision: -1,
                ..Default::default()
            };
            
            // flags
            while i < bytes.len() {
                match bytes[i] {
                    b'-' => spec.left_align = true,
                    b'+' => spec.plus = true,
                    b'0' => spec.zero_pad = true,
                    b'#' => spec.alt = true,
                    b' ' => spec.space = true,
                    _ => break,
                }
                i += 1;
            }
            
            // width
            while i < bytes.len() && bytes[i].is_ascii_digit() {
                spec.width = spec.width * 10 + (bytes[i] - b'0') as usize;
                i += 1;
            }
            
            // precision
            if i < bytes.len() && bytes[i] == b'.' {
                i += 1;
                spec.precision = 0;
                while i < bytes.len() && bytes[i].is_ascii_digit() {
                    spec.precision = spec.precision * 10 + (bytes[i] - b'0') as i32;
                    i += 1;
                }
            }
            
            // length
            while i < bytes.len() && matches!(bytes[i], b'h' | b'l' | b'z' | b'j' | b't' | b'L') {
                spec.length.push(bytes[i] as char);
                i += 1;
            }
            
            // specifier
            if i < bytes.len() {
                spec.specifier = bytes[i] as char;
                i += 1;
            }
            
            result.push(FormatPart::Spec(spec));
        } else {
            literal.push(bytes[i] as char);
            i += 1;
        }
    }
    
    if !literal.is_empty() {
        result.push(FormatPart::Literal(literal));
    }
    
    result
}

fn main() {
    println!("=== Day 327: printf 格式串解析 ===\n");
    
    let test_cases = [
        "%d",
        "%-20s",
        "%+08.2f",
        "%llx",
        "Hello %s, count = %d, pi = %.3f\n",
        "%5d|%-5d|%05d",
        "%c%c%c",
        "100%% done",
    ];
    
    for case in test_cases {
        println!("解析 {:?}", case);
        let parts = parse_format(case);
        for part in &parts {
            match part {
                FormatPart::Literal(s) => println!("  Literal: {:?}", s),
                FormatPart::Spec(spec) => {
                    println!("  Spec: {} → {:?}", spec.describe(), spec);
                }
            }
        }
        println!();
    }
    
    // 验证解析后重组等于原串
    println!("=== 往返验证 ===\n");
    for case in test_cases {
        let parts = parse_format(case);
        let rebuilt: String = parts.iter().map(|p| match p {
            FormatPart::Literal(s) => s.clone(),
            FormatPart::Spec(s) => format!("%{}", s.describe()),
        }).collect();
        println!("{:?} → rebuilt: {:?}", case, rebuilt);
    }
}
```

## 10 · 深度补充:工程视角

Parser 设计的深度话题:今天的 printf parser 是最简版。工业级 parser 处理:错误恢复(unknown token 不崩)/ 位置追踪(报错时给出 line:col)/ 流式处理(大文件不全加载)/ UTF-8 / Unicode。Rust 生态的 nom 是 parser combinator 库,适合复杂语法。winnow 是 nom 的简化 fork。Casey 手写 parser 因为 printf 语法简单。
