# Day 346 · 合并内存块头部

> 五天的内存系统重构(341-345)给 HH 装上了动态 arena、临时内存、内存页保护。但 Casey 留了一屁股代码债:每个 arena 有两个头部结构(`memory_block_header` 和 `arena_block_info`),字段重复、维护成本翻倍。今天 Casey 把它们合并成一个统一的 `memory_block`,让代码"减肥"30%。这是"清理"专题的延续。

## 0 · 为什么要有这一天

软件工程有个**熵增原理**:代码会自然变乱。每加一个特性,你就引入一点重复、一点不一致。十次之后,你有 5 个结构体干同样的事,8 个函数做同样的逻辑——但每个都有微妙差别。

HH 的内存系统就是这种状态:

- `memory_block_header`: Casey 老版的块头,有 `prev`, `next` 指针(链表)
- `arena_block_info`: Day 341 加动态 arena 时引入的新头,有 `size`, `used` 字段
- `temp_block_marker`: Day 342 加临时内存时的标记

实际功能重叠:三个结构都在描述"一块内存的元信息"。维护三份是技术债务——改字段要改三处,bug 容易漏。

**今天的任务**:把三个结构合并成一个 `memory_block`,字段统一、代码减少、bug surface 减小。

这种"合并重复"叫**Divergent Change → Single Responsibility**反模式处理,出自 Martin Fowler 的《重构》一书。Casey 在 HH 里反复演示:**先写能跑的代码,等模式浮现后再重构**。

心理锚点:今天之后你能识别"代码重复"的坏味道,知道怎么用"提取公共结构"消除重复,理解 Casey 为什么坚持"字段必须统一,接口必须单一"。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_memory.cpp`,看见三个相似但不同的结构体:

```c
typedef struct memory_block_header {
    memory_index Size;
    memory_index Used;
    memory_block_header *Prev;
} memory_block_header;

typedef struct arena_block_info {
    memory_index TotalSize;
    memory_index UsedSize;
    u64 Generation;
} arena_block_info;

typedef struct temp_block_marker {
    memory_arena *Arena;
    memory_index SavedUsed;
} temp_block_marker;
```

Casey 把它们合成:

```c
typedef struct memory_block {
    memory_index Size;       // 这块的总大小
    memory_index Used;       // 已用多少
    memory_block *Prev;      // 链表前驱
    memory_block *Next;      // 链表后继(新加)
    u32 Generation;          // 世代(防悬垂)
    u32 Flags;               // 标志位:is_temp / is_protected
} memory_block;
```

之后:

- 所有 arena 用同一个 `memory_block` 链表
- 临时内存用 `Flags |= TEMP_MARKER` 标记
- 下溢检测(Day 345)用 `Flags |= GUARD_PAGE` 标记

代码行数从 ~600 行降到 ~420 行,功能不变,bug surface 减小。

## 2 · 心智模型

### 类比:把多个抽屉合并成一个有标签的盒子

想象你桌上有三个抽屉:

- 抽屉 A:装"作业本",每本写"作业序号、上次写到第几页"
- 抽屉 B:装"笔记本",每本写"总页数、用过的页数"
- 抽屉 C:装"草稿纸",每张写"上次到哪、何时存的"

三个抽屉管理的对象重叠(都是"纸"),但元信息字段不统一。每加一种新纸,你要决定放哪个抽屉,记什么字段——决策疲劳。

**合并方案**:用统一的"档案盒",每盒装一份纸,盒外贴标签:`总页数`、`已用页数`、`上次更新`、`类型(作业/笔记/草稿)`。一种结构,所有纸通用。

这就是 Casey 今天做的:**用一份 metadata 描述所有内存块**。

### 字段统一的好处

**1. 减少认知负担**

读代码时只有一个 `memory_block` 结构,所有块用同样字段描述。不用记"Arena 用 TotalSize,Header 用 Size"这种碎片。

**2. 通用函数**

```rust
fn block_remaining(b: &MemoryBlock) -> usize {
    b.size - b.used
}
```

一个函数适用所有块,不需要 `header_remaining()` / `arena_remaining()` / `temp_remaining()` 三个版本。

**3. 链表统一**

所有块用同一个双向链表,遍历简单:

```rust
let mut cur = arena.first_block;
while let Some(b) = cur {
    println!("size={}, used={}", b.size, b.used);
    cur = b.next;
}
```

而不是"先遍历 headers,再遍历 infos,再遍历 markers"。

**4. 序列化简单**

保存游戏状态时,所有块用同一格式写盘。Day 343 的"保存恢复"代码今天简化了一半。

### Casey 的合并原则

Casey 重构时遵循几个原则:

**原则 1:不丢信息**

合并前 `arena_block_info` 有 `Generation`,合并后必须有等价字段(放到 `Flags` 或单独的 `Generation` 字段)。不能为了"简化"删功能。

**原则 2:字段名清晰**

```rust
struct MemoryBlock {
    size: usize,        // 这块总大小
    used: usize,        // 已用字节
    prev: *mut MemoryBlock,  // 链表前驱
    next: *mut MemoryBlock,  // 链表后继
    generation: u32,    // 世代计数(防悬垂)
    flags: u32,         // 标志位
}
```

每个字段一行注释。读者看注释就知道含义。

**原则 3:标志位用 bit flags**

`flags: u32` 是 32 个 bool 的紧凑表示:

```rust
const FLAG_TEMP: u32      = 1 << 0;
const FLAG_GUARDED: u32   = 1 << 1;
const FLAG_COMPRESSED: u32 = 1 << 2;

if block.flags & FLAG_TEMP != 0 {
    // 这是临时块
}
```

而不是 `is_temp: bool, is_guarded: bool, is_compressed: bool` 三个独立 bool(占用更多空间,扩展性差)。

Rust 社区有 `bitflags` crate 自动生成:

```rust
bitflags::bitflags! {
    struct BlockFlags: u32 {
        const TEMP = 1 << 0;
        const GUARDED = 1 << 1;
        const COMPRESSED = 1 << 2;
    }
}

let f = BlockFlags::TEMP | BlockFlags::GUARDED;
if f.contains(BlockFlags::TEMP) { ... }
```

### Rust 表达:用 trait 还是 enum?

合并几个结构体到统一结构,有两种 Rust 风格:

**风格 1:统一 struct + flags**

```rust
struct MemoryBlock {
    size: usize,
    used: usize,
    flags: BlockFlags,
    // ... 通用字段
    // 类型由 flags 区分
}
```

优点:同质,可以放一个 `Vec<MemoryBlock>`,链表统一。
缺点:有些字段对某些类型无意义(如 `TEMP` 块不需要 `generation`)。

**风格 2:enum + 变体**

```rust
enum MemoryBlock {
    Normal { size: usize, used: usize },
    Temp { size: usize, used: usize, saved_used: usize },
    Guarded { size: usize, used: usize, guard_offset: usize },
}
```

优点:类型安全,无效字段编译期消除。
缺点:变体多时 enum 大小 = 最大变体,内存浪费;不同变体不能直接放同一链表。

**风格 3:trait + dyn**

```rust
trait MemoryBlock {
    fn size(&self) -> usize;
    fn used(&self) -> usize;
}

struct NormalBlock { size: usize, used: usize }
struct TempBlock { size: usize, used: usize, saved_used: usize }

let blocks: Vec<Box<dyn MemoryBlock>> = vec![...];
```

优点:多态,扩展性好。
缺点:vtable 开销,cache 不友好。

**Casey 选风格 1**:游戏开发看重 cache,统一 struct + flags 最快。HH 是 C 风格,自然走这条路。Rust 翻译也用风格 1。

### 实际重构步骤

Step 1:定义新结构(不删旧)

```rust
struct MemoryBlock {
    size: usize,
    used: usize,
    prev: Option<Box<MemoryBlock>>,
    next: Option<Box<MemoryBlock>>,
    generation: u32,
    flags: u32,
}
```

Step 2:让 arena 持有新结构

```rust
struct MemoryArena {
    first_block: Option<Box<MemoryBlock>>,
    // 旧字段保留,逐步迁移
}
```

Step 3:逐个迁移功能

- `arena.alloc()` 改用新块结构
- `temp_memory_save()` 改用 `flags |= TEMP` 标记
- `arena_protect_page()` 改用 `flags |= GUARDED`

Step 4:删旧字段、旧结构

Step 5:跑测试,确认行为不变

### Rust 所有权和 Box

Casey 在 C 里用裸指针 `*mut memory_block`。Rust 翻译用 `Box<MemoryBlock>`(堆分配,独占所有权)或自定义 arena 分配。

```rust
// 方案 A:Box,简单
let block = Box::new(MemoryBlock::new(size));
block.next = Some(Box::new(...));

// 方案 B:arena 内指针
struct Arena {
    storage: *mut u8,
    blocks: *mut MemoryBlock,  // arena 内
}
// 需要 unsafe,因为绕过 Rust 借检查
```

HH 风格是方案 B(arena 内自管),Casey 要"看到每个字节"。Rust 教学翻译通常先方案 A(简单),性能优化阶段才换方案 B。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏引擎的内存系统是性能生命线。Casey 在 HH 里完全自管内存(不用 malloc),所以每行内存代码都很重要。

**业界内存系统对比**:

- **Unreal Engine**:GMalloc 全局分配器 + 各种 arena(FMemory::Malloc)
- **Unity**:Mono heap + native heap,GC 管托管对象
- **Bevy**:`bevy_tasks::Parallel` + 用户自管(没有内置 arena)
- **Godot**:自管内存,reference counting

所有引擎都有自己的"块头"概念,字段大同小异:`size`, `used`, `next`, `flags`。Casey 今天的合并是业界通用做法。

**真实 case**:**Electronic Arts 的 EASTL**(EA 标准模板库)的 `EASTLAllocator` 就有统一的 `block_header` 结构,所有 allocator 共用。Casey 的思路和 EASTL 一致。

### 3.2 · 图形学视角

图形 API 自己有内存管理(Vulkan / DirectX 12):

- `VkDeviceMemory`:大块 GPU 内存
- `VkBuffer` / `VkImage`:从大块里 sub-allocate
- sub-allocation 由 `VMA`(Vulkan Memory Allocator)库管理

VMA 内部就是 Casey 风格的"块头 + 自由链表 + 标志位"。读 VMA 源码:https://github.com/GPUOpen-LibrariesAndSDK/VulkanMemoryAllocator

GPU 内存比 CPU 紧张(8GB vs 32GB),管理更精细。Casey 在 Day 460+ 切到 OpenGL 后,会用类似的"块头"管 vertex buffer。

### 3.3 · Linux 系统编程视角

Linux 用户态内存管理的演化:

- **ptmalloc**(glibc):每线程一个 arena,arena 内分 heap,heap 内 chunks。chunk header 有 size/flags/prev_size。
- **tcmalloc**(Google):每 CPU 一个 cache,central heap 分大块。
- **jemalloc**(Facebook):类似 tcmalloc,但 ext-frag 更优。
- **mimalloc**(Microsoft):2020 后起之秀,小对象超快。

所有 allocator 内部都有 Casey 风格的"块头"。ptmalloc 的 `malloc_chunk` 是经典:

```c
struct malloc_chunk {
    INTERNAL_SIZE_T prev_size;  // 前一个 chunk 大小(用于合并)
    INTERNAL_SIZE_T size;       // 这个 chunk 大小(含头)
    struct malloc_chunk* fd;     // 前向指针(free list)
    struct malloc_chunk* bk;     // 后向指针(free list)
};
```

Casey 的 `memory_block` 几乎一样——内存管理的根本需求没变。

**自管内存 vs glibc**:

```bash
# 查进程的内存映射
cat /proc/$(pidof your_game)/maps | head -20
# 看到很多 [heap] 段 + 共享库映射

# 用 strace 看 syscall
strace -e trace=brk,mmap,munmap ./your_game 2>&1 | head
# 看你的游戏什么时候向 OS 要内存
```

自管内存后,game 启动时一次 mmap 一大块(比如 1GB),之后所有 alloc/free 在 1GB 内进行,brk / mmap syscall 极少——这就是性能来源。

### 3.4 · Rust 生态视角

Rust 标准库不暴露"块头"——`Box<T>` / `Vec<T>` 把分配细节隐藏。但要写 arena,必须自己管块头。

**相关 crate**:

- **`bumpalo`**:arena allocator,简单(无个体 free)
- **`typed-arena`**:类型固定 arena,带类型安全
- **`generational_arena`**:带世代的 arena(类似 slotmap)
- **`slab`**:类似 slotmap,API 略不同

读 `bumpalo` 源码看一个工业级 arena:

struct ChunkHeader {

### 同一模式在不同语言的实现

**C**:`struct + bit flags` + 裸指针。Casey 的方式。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Casey 用 `flags: u32` 而不是 3 个独立 `bool` 字段?

**参考解答**:

3 个原因:
1. **空间**:`u32` 4 字节,32 个 bool 压缩。3 个 bool 至少 3 字节,但 Rust 默认 padding 到 4 字节,差不多。但**扩展性好**:32 个 flag 还是 4 字节,而 30 个 bool 要 30 字节。
2. **原子操作**:多线程时,改 flags 用一条 `atomic_or` / `atomic_and`,不可分割。多个 bool 改要用锁。
3. **集合操作**:`flags & ALL_TEMP_BLOCKS == 0` 可以一次判断多个标志,而 bool 要写 3 个 `&&`。

代价:可读性差,需要 `bitflags` crate 帮助。 Casey 用裸位操作,因为 C 习惯;Rust 推荐 `bitflags`。

### Lv2 · 动手实践

**题**:实现合并后的 `MemoryBlock` 结构,以及 `arena.alloc()` 和 `arena.dealloc()`。要求:

1. 块头:`size`, `used`, `prev`, `next`, `generation`, `flags`
2. flags 至少包含:`FLAG_TEMP`, `FLAG_GUARDED`
3. alloc 时新块 generation +=1
4. dealloc 时校验 generation(防悬垂)

完成标准:`cargo run` 测试 alloc/dealloc 一致性,使用错误 generation dealloc 时返回 Err。

**参考解答**:

```rust
use std::cell::Cell;
use std::ptr::NonNull;

const FLAG_TEMP: u32    = 1 << 0;
const FLAG_GUARDED: u32 = 1 << 1;

struct MemoryBlock {
    size: usize,
    used: Cell<usize>,  // 内部可变,简化借用
    prev: Option<NonNull<MemoryBlock>>,
    next: Option<NonNull<MemoryBlock>>,
    generation: Cell<u32>,
    flags: Cell<u32>,
    // 实际数据在 block 之后(柔性数组)
    data: [u8; 0],
}

impl MemoryBlock {
    fn new(size: usize, flags: u32) -> Box<Self> {
        let layout = std::alloc::Layout::from_size_align(
            std::mem::size_of::<MemoryBlock>() + size,
            8,
        ).unwrap();
        unsafe {
            let raw = std::alloc::alloc(layout);
            let nonnull = NonNull::new(raw).expect("OOM");
            let block_ptr = nonnull.as_ptr() as *mut MemoryBlock;
            std::ptr::write(block_ptr, MemoryBlock {
                size,
                used: Cell::new(0),
                prev: None,
                next: None,
                generation: Cell::new(1),
                flags: Cell::new(flags),
                data: [],
            });
            Box::from_raw(block_ptr)
        }
    }
}

// 简化版:用一个 Vec 模拟,不用真 unsafe
struct SimpleArena {
    blocks: Vec<SimpleBlock>,
    next_generation: u32,
}

#[derive(Clone)]
struct SimpleBlock {
    size: usize,
    used: usize,
    generation: u32,
    flags: u32,
    data: Vec<u8>,
}

impl SimpleBlock {
    fn new(size: usize, gen: u32, flags: u32) -> Self {
        Self { size, used: 0, generation: gen, flags, data: vec![0; size] }
    }
}

impl SimpleArena {
    fn new() -> Self {
        Self { blocks: vec![], next_generation: 1 }
    }

    fn alloc(&mut self, size: usize, flags: u32) -> (usize, u32) {
        let gen = self.next_generation;
        self.next_generation += 1;
        let block = SimpleBlock::new(size, gen, flags);
        let idx = self.blocks.len();
        self.blocks.push(block);
        (idx, gen)
    }

    fn dealloc(&mut self, idx: usize, gen: u32) -> Result<(), &'static str> {
        let block = self.blocks.get(idx).ok_or("invalid index")?;
        if block.generation != gen {
            return Err("generation mismatch - stale handle");
        }
        // swap-remove
        let last = self.blocks.len() - 1;
        self.blocks.swap(idx, last);
        self.blocks.pop();
        Ok(())
    }

    fn write(&mut self, idx: usize, gen: u32, offset: usize, byte: u8) -> Result<(), &'static str> {
        let block = self.blocks.get_mut(idx).ok_or("invalid index")?;
        if block.generation != gen {
            return Err("generation mismatch");
        }
        if offset >= block.size {
            return Err("out of bounds");
        }
        block.data[offset] = byte;
        block.used = block.used.max(offset + 1);
        Ok(())
    }
}

fn main() {
    let mut arena = SimpleArena::new();

    // alloc 两个块
    let (idx1, gen1) = arena.alloc(1024, 0);
    let (idx2, gen2) = arena.alloc(2048, FLAG_TEMP);
    println!("Allocated: idx1={} gen1={}, idx2={} gen2={}", idx1, gen1, idx2, gen2);

    // 写数据
    arena.write(idx1, gen1, 0, 0xAB).unwrap();
    arena.write(idx1, gen1, 1, 0xCD).unwrap();

    // dealloc idx1
    arena.dealloc(idx1, gen1).unwrap();
    println!("Deallocated idx1");

    // 旧 handle 失效
    let result = arena.write(idx1, gen1, 0, 0xFF);
    println!("Stale handle write: {:?}", result);  // Err

    // 当前块数
    println!("Remaining blocks: {}", arena.blocks.len());
}
```

**关键解释**:
- `generation: u32`:每次 alloc 自增,handle 携带 gen,dealloc/write 时校验
- `flags: u32`:bit flag,常用 `FLAG_TEMP`, `FLAG_GUARDED`
- `swap_remove`:O(1) 删除,会改顺序——这就是为什么要用 (idx, gen) 而不是只用 idx

## 8 · Rust / Arch 落地代码

### 完整可跑示例

扩展 Lv2,加上 bitflags crate 和保护页检测。

```rust
// Cargo.toml:
// [dependencies]
// bitflags = "2.4"

use bitflags::bitflags;

bitflags! {
    #[derive(Copy, Clone, Debug, PartialEq, Eq)]
    struct BlockFlags: u32 {
        const TEMP     = 1 << 0;
        const GUARDED  = 1 << 1;
        const PINNED   = 1 << 2;  // 不能被回收
    }
}

struct MemoryBlock {
    size: usize,
    used: usize,
    generation: u32,
    flags: BlockFlags,
    data: Vec<u8>,
}

impl MemoryBlock {
    fn new(size: usize, gen: u32, flags: BlockFlags) -> Self {
        Self { size, used: 0, generation: gen, flags, data: vec![0; size] }
    }

    fn write(&mut self, offset: usize, byte: u8) -> Result<(), &'static str> {
        if self.flags.contains(BlockFlags::GUARDED) && offset == 0 {
            // 模拟"保护页"——offset 0 是保护页,不能写
            return Err("write to guard page");
        }
        if offset >= self.size {
            return Err("out of bounds");
        }
        self.data[offset] = byte;
        self.used = self.used.max(offset + 1);
        Ok(())
    }

    fn is_temp(&self) -> bool {
        self.flags.contains(BlockFlags::TEMP)
    }
}

struct Arena {
    blocks: Vec<MemoryBlock>,
    next_gen: u32,
}

impl Arena {
    fn new() -> Self { Self { blocks: vec![], next_gen: 1 } }

    fn alloc(&mut self, size: usize, flags: BlockFlags) -> (usize, u32) {
        let gen = self.next_gen;
        self.next_gen += 1;
        let idx = self.blocks.len();
        self.blocks.push(MemoryBlock::new(size, gen, flags));
        (idx, gen)
    }

    fn dealloc(&mut self, idx: usize, gen: u32) -> Result<(), &'static str> {
        let block = self.blocks.get(idx).ok_or("invalid index")?;
        if block.generation != gen {
            return Err("stale handle");
        }
        if block.flags.contains(BlockFlags::PINNED) {
            return Err("pinned block cannot be freed");
        }
        self.blocks.swap_remove(idx);
        Ok(())
    }

    fn block(&self, idx: usize, gen: u32) -> Result<&MemoryBlock, &'static str> {
        let block = self.blocks.get(idx).ok_or("invalid index")?;
        if block.generation != gen {
            return Err("stale handle");
        }
        Ok(block)
    }

    fn block_mut(&mut self, idx: usize, gen: u32) -> Result<&mut MemoryBlock, &'static str> {
        let block = self.blocks.get_mut(idx).ok_or("invalid index")?;
        if block.generation != gen {
            return Err("stale handle");
        }
        Ok(block)
    }
}

fn main() {
    let mut arena = Arena::new();

    // 普通块
    let (a, ga) = arena.alloc(1024, BlockFlags::empty());
    // 临时块
    let (b, gb) = arena.alloc(2048, BlockFlags::TEMP);
    // 保护页块
    let (c, gc) = arena.alloc(512, BlockFlags::GUARDED);
    // 钉住块
    let (d, gd) = arena.alloc(256, BlockFlags::PINNED);

    println!("allocated 4 blocks");

    // 写普通块
    arena.block_mut(a, ga).unwrap().write(0, 0xAB).unwrap();
    arena.block_mut(a, ga).unwrap().write(1, 0xCD).unwrap();
    println!("wrote to block A");

    // 写保护页块 → 错
    let result = arena.block_mut(c, gc).unwrap().write(0, 0xFF);
    println!("write to guard page: {:?}", result);  // Err

    // 释放钉住块 → 错
    let result = arena.dealloc(d, gd);
    println!("dealloc pinned: {:?}", result);  // Err

    // 释放普通块
    arena.dealloc(a, ga).unwrap();
    println!("dealloc normal: ok");

    // 旧 handle 失效
    let result = arena.block(a, ga);
    println!("stale read: {:?}", result.map(|_| ()).map_err(|e| e));  // Err

    // 临时块统计
    let temp_count = arena.blocks.iter().filter(|b| b.is_temp()).count();
    println!("temp blocks remaining: {}", temp_count);
}
```
