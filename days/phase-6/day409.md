# Day 409 · 更平滑的光照样本混合

> Day 407-408 你修好了 volume texture 的 upload bug,现在 GPU 端能正确采到体素光照。但画面**还有问题**:多层 LPV(粗网格 32³、中网格 64³、细网格 128³)之间有**接缝**——粗网格采样和细网格采样在同一空间位置给出**不同的光照值**,因为两层网格在边界附近用不同 voxel 离散化。今天 Casey 解决这个**采样融合**问题:**用平滑权重在多层之间过渡**,让画面看不到"网格切换"的接缝。这一集是数据插值与信号处理的精华课,核心数学是 Hermite 平滑和距离权重。

## 0 · 为什么要有这一天

把你拉回到一个具体场景。Day 408 结束后,你的渲染管线是这样工作的:fragment shader 拿到世界坐标 `p`,计算三层 LPV 的 uvw,各采一次得到三个光照向量 `L_coarse`、`L_medium`、`L_fine`。然后你想做"按距离选层"——离观察者近用细层(64³ 或 128³),远用粗层(32³)——但**切换是硬的**:距离 5 米用细层,5.01 米突然用粗层,**画面在切换距离上会出现一条明显的接缝**,两个网格在那里的采样值不一样。

这种"硬切换"的视觉表现是**flicker**——摄像机移动时,接缝位置变化,你看到画面上的亮斑"跳"过去。这是工业渲染管线**不可接受**的视觉缺陷。

为什么多层 LPV 会有这种问题?因为每层 LPV 的 voxel **尺寸不同**。32³ 网格在 32 米世界里每个 voxel 是 1 米,64³ 网格每个 voxel 是 0.5 米,128³ 每个 0.25 米。同一个世界位置(比如 (10, 5, 3))在三层上落到不同的 voxel 内,voxel 内的值是 Gauss-Seidel 迭代得到的离散光照——迭代结果**取决于网格分辨率**,所以三层在同一点的光照值略有差异。差异在网格切换时会**突变**,产生接缝。

**解决方案**:**平滑混合**。不要硬切换,而是在切换距离附近**用平滑函数过渡**权重。距离 4-6 米之间,权重从"全用细层"平滑过渡到"全用粗层"。这一段过渡用数学函数(`smoothstep` 或 Hermite 多项式)实现,**保证过渡单调且导数连续**。

工业界这个方法叫 **trilinear blend** 或 **mip blend**,是从 2D texture 的 mipmap 推广到 3D 光照体积的。Casey 在 Day 409 把它具体化,不仅按距离混合,还**按法线方向混合**——细网格存"高频方向变化",粗网格存"低频全局场",两者按 surface 法线和采样方向的夹角加权。

为什么这个细节重要?因为**任何"用多层离散数据重建连续场"的场景都需要它**。这不是 HH 特有的优化,而是从 1960 年代的多重网格求解器(multigrid solver)到现代 PBR 引擎(Unreal 的 LPV、Crytek 的 SVOTree)都用到的通用技术。学会它,你看任何 GI 方案都能秒理解"为什么这么混合"。

心理锚点:今天之后,你能:(1) 解释为什么多层 LPV 有接缝;(2) 写 `smoothstep` 函数并知道它的数学性质;(3) 用三轴权重(距离、法线、频率)混合多层采样;(4) 调试"接缝 flicker"——把权重可视化当颜色输出,看分布是否符合预期。

## 1 · Casey 今天做了什么(HH 脉络)

Day 408 修完 volume texture bug 后,Casey 继续看画面,**注意到**接缝问题。他做了三件事:

1. **可视化权重**:他在 fragment shader 里加了一个 debug mode,把当前使用的"层权重"当颜色输出。屏幕上出现了清晰的**同心圆环**——每环对应一层 LPV 主导。环之间的边界是**硬的**,对应画面上的接缝。

2. **加入平滑过渡**:Casey 把原来的硬切换函数(距离 `d` < 5 用细层,`d >= 5` 用粗层)替换成 **smoothstep**:

```glsl
// 硬切换(原版)
float w_fine = (d < 5.0) ? 1.0 : 0.0;

// 平滑切换(新)
float w_fine = 1.0 - smoothstep(4.0, 6.0, d);
```

`smoothstep(edge0, edge1, x)` 在 x < edge0 时返回 0,x > edge1 时返回 1,中间用 Hermite 多项式平滑过渡。Casey 用它做"反"权重(距离小时权重 1,大时权重 0)。

3. **三轴权重**:Casey 不仅按距离混合,还**按法线方向混合**。粗网格存低频(场变化平滑方向)的光照,细网格存高频(场变化剧烈方向)。表面法线和采样方向的夹角决定**取高频还是低频**。这进一步消除接缝。

到 Day 409 结束,画面**几乎看不出网格切换**,LPV 渲染管线达到第一个"视觉合格"状态。

## 2 · 心智模型

### 类比:多层地图的"无缝缩放"

想象你在用 Google Maps。缩小到国家级别,看到的是大洲、国家、大城市的轮廓(粗网格);放大到城市级别,看到的是街道、建筑物(细网格)。Google Maps 的关键技术是**不同缩放级别之间的平滑过渡**——你滚动鼠标时,下一级别的内容**淡入**,当前级别的内容**淡出**,你完全感觉不到切换。

LPV 的多层混合完全是这个原理。粗 LPV = 国家地图,提供整体光照分布;细 LPV = 街道地图,提供局部细节。画面上每个像素**根据它的位置(离观察者多远)决定看哪一层**,在切换距离附近**两层都看,按平滑权重混合**。

**关键概念**:**信号处理里的"频带混合"**。粗网格代表低频信号(变化慢,空间尺度大),细网格代表高频信号(变化快,空间尺度小)。混合它们等于**重建完整的频谱**——低频来自粗网格,高频来自细网格。这是 Fourier 分析在工程上的简化版。

### 严谨原理:smoothstep 与 Hermite 多项式

`smoothstep` 是 GLSL 内置函数,数学定义:

```
smoothstep(edge0, edge1, x) = t² · (3 - 2t),  其中 t = clamp((x - edge0) / (edge1 - edge0), 0, 1)
```

性质:
- `x ≤ edge0` 时返回 0
- `x ≥ edge1` 时返回 1
- 中间用 `t² · (3 - 2t)` 这个三次多项式过渡
- 在 `x = edge0` 和 `x = edge1` 处**导数为 0**(C¹ 连续),这是关键——避免视觉突变

`smoothstep` 是 Hermite 多项式的特殊形式。Hermite 多项式 `H(t) = t²(3-2t)` 是**两端导数为 0 的最低次多项式**。它的导数 `H'(t) = 6t(1-t)`,在 `t=0` 和 `t=1` 都是 0,所以函数从"水平"开始过渡,到"水平"结束,**没有突变**。

**为什么导数连续重要**?想象你站在切换距离的边界上。摄像机稍微移动,权重从 0% 变到 5%——如果**导数大**,这 5% 变化很急,画面上的亮斑**跳**;如果**导数为 0**(像 smoothstep 那样),5% 变化很缓,亮斑**平滑滑动**。

更平滑的版本是 `smootherstep`(GLSL 没内置,要自己写):

```
smootherstep(t) = t³ · (t · (6t - 15) + 10) = 6t⁵ - 15t⁴ + 10t³
```

它的二阶导数也是 0(C² 连续),更平滑。Perlin 噪声里用的就是 smootherstep。Casey 在 Day 409 用 smoothstep 就够,**C¹ 已经消除视觉突变**。

### 多层 LPV 的混合公式

三层 LPV(粗 32³、中 64³、细 128³)的混合公式:

```glsl
vec3 uvw0 = (worldPos - grid0Min) / (grid0Max - grid0Min);
vec3 uvw1 = (worldPos - grid1Min) / (grid1Max - grid1Min);
vec3 uvw2 = (worldPos - grid2Min) / (grid2Max - grid2Min);

vec3 L0 = texture(uVoxel0, uvw0).rgb;  // 粗网格光照
vec3 L1 = texture(uVoxel1, uvw1).rgb;  // 中网格光照
vec3 L2 = texture(uVoxel2, uvw2).rgb;  // 细网格光照

// 按距离算权重(假设 camera_pos 是相机位置)
float d = length(worldPos - camera_pos);

// 细层权重:近处用,远处不用
float w2 = 1.0 - smoothstep(2.0, 4.0, d);
// 中层权重:中间距离用
float w1 = (1.0 - w2) * (1.0 - smoothstep(5.0, 8.0, d));
// 粗层权重:远处用
float w0 = 1.0 - w2 - w1;

vec3 final_light = w0 * L0 + w1 * L1 + w2 * L2;
```

**关键设计**:`w0 + w1 + w2 = 1`(权重归一化)。这保证混合后的光照**不会比单层更亮**——否则多层叠加会出现"在切换距离处亮斑加倍"的 bug。

### 三轴权重

只按距离混合不够。Casey 还**按法线方向**混合——这处理"细网格在角落看不到,粗网格在角落更准"的情况。

具体地,假设我们采样一个墙面。墙面法线 `N` 朝南。从墙面看向光源,有两种采样方向:**沿墙面**(平行墙面)和**垂直墙面**(进入墙体)。沿墙面采样,**细网格更准**(因为光照在墙面附近变化剧烈);垂直墙面采样,**粗网格更准**(因为光照在远离墙面后变化平缓)。

数学化:用 N 和"墙面到相机"的方向 V 的夹角。夹角接近 0(视线和法线对齐)→ 用细网格;夹角接近 90°(视线掠过墙面)→ 用粗网格。

```glsl
// 法线和视线夹角余弦
float cos_theta = abs(dot(N, normalize(camera_pos - worldPos)));

// 法线权重(对齐时用细,掠射时用粗)
float w_normal_fine = smoothstep(0.0, 0.5, cos_theta);
```

**总权重** = 距离权重 × 法线权重(再归一化)。

### 为什么不能"全用细层"

如果只细网格质量最好,**为什么不全部用 128³**?两个工程理由:

1. **内存**:128³ RGBA16F = 128³ × 8 字节 = 16 MB。看似不大,但每层都要(粗 + 中 + 细 = 21 MB),加上其他 texture 总开销巨大。移动端 128³ 不现实。

2. **光照传播开销**:每层 LPV 每帧要跑 Gauss-Seidel 迭代把光扩散开。迭代复杂度 O(N³)——32³ 是 32k 个 cell,128³ 是 2M 个 cell,**64 倍**。如果全用 128³,光照传播每帧几十毫秒,达不到 60 FPS。

所以工程上的最优解是**多层混合**:用粗网格覆盖远处(高频细节反正看不清),用细网格覆盖近处(细节重要)。这是**信号处理里的"细节按可见性分配"**原则的具象化。

### 数值稳定性:权重为零时的处理

如果一个采样的**所有权重都是 0**(极端边界),`final_light` 是 0——画面会**变黑**。要避免:

```glsl
// 安全版本:确保至少有一个权重非零
float total = w0 + w1 + w2;
if (total < 1e-6) {
    final_light = vec3(0.0);  // 完全没有 LPV 光
} else {
    final_light = (w0 * L0 + w1 * L1 + w2 * L2) / total;  // 归一化
}
```

**注意**:实际工程里 `total` 几乎总是接近 1(只要 smoothstep 边界设对),但加保险无害。

### 接缝 flicker 的另一种修法

如果**接缝不在固定距离**,而是**和摄像机角度有关**(摄像机转一转接缝位置变),这是另一种 bug——**pixel 偏差导致 voxel 不同**。比如像素中心 (5.0, 0, 0) 落在 voxel 5,像素边缘 (5.001, 0, 0) 落在 voxel 6,**两个像素采到不同 voxel**。摄像机移动时,像素中心略微漂移,**整个画面 flicker**。

修法:**MSAA(多重采样抗锯齿)**——每个像素采 4 次(在像素内 4 个不同位置),平均。这能消除 flicker,但开销 4 倍。Casey 在 Day 410 会做这个。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏开发里"多层细节"(Level of Detail,LOD)是**核心优化技术**,不仅用于 LPV:

- **Mesh LOD**:远处的角色用低多边形,近处用高多边形。模型加载时分多个 LOD 层级。
- **Texture Mipmapping**:远处的纹理用低分辨率 mipmap,近处用高分辨率。
- **Shader LOD**:远处的物体用简化 shader(无 specular),近处用完整 shader。
- **Animation LOD**:远处角色用低帧数动画,近处用全帧。

**所有 LOD 都面临同一个问题**:**切换接缝**。如果硬切换,玩家看到画面"跳"。标准解决方案都是**平滑混合**(smoothstep / crossfade / dithering)。

**Crossfade**:两个 LOD 同时渲染,在切换距离附近 alpha 混合。这需要两次 draw call,但视觉完美。Unreal Engine 用这个。

**Dithering**:用蓝噪声(blue noise)在两个 LOD 之间随机选,**像素级别**看不出切换,但整体看平滑。噪声在屏幕空间稳定(避免 flicker),所以叫 **temporally stable dithering**。

LPV 的多层混合属于"在 shader 里 mix",开销最低(已经采了多层,只是混合系数不同)。

### 3.2 · 🎨 图形学视角

光照体积的混合是**信号采样理论**的直接应用。理论基础是 Nyquist-Shannon 采样定理:**信号的频率不能超过采样频率的一半**,否则出现 aliasing(锯齿、flicker)。

**多层 LPV 是多采样率采样**:粗网格(32³)采样率低,只能重建低频;细网格(128³)采样率高,能重建高频。混合它们等于**多频带采样**——低频来自粗网格(避免高频噪声),高频来自细网格(提供细节)。

这和 **audio EQ(Equalizer)**完全一样。Bass 频段(20-200 Hz)用大喇叭(低采样率),Treble 频段(2k-20k Hz)用小喇叭(高采样率)。声学工程师把不同频段分到不同喇叭,**避免互相干扰**。LPV 混合也是这个思路。

**Casey 的具体策略**:三层 LPV 各管一个频段:
- 粗(32³):空间波长 > 4 米(整体光照分布)
- 中(64³):空间波长 1-4 米(中等细节)
- 细(128³):空间波长 < 1 米(角落、缝隙)

权重按"距离 / 法线"决定,**信号处理的频带划分**在 fragment shader 里实时做。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上和 LPV 混合相关的几个性能层面:

**SIMD 友好的混合**:三层 LPV 各采一次 = 3 次 texture sample + 3 次 vec3 mix。SIMD 化的话,**用 `_mm_fmadd_ps`**(融合乘加)做 `a*x + b`,3 层混合可以并行。

```rust
// 假设有 SSE 4.1
use std::arch::x86_64::*;
unsafe {
    let l0 = _mm_set_ps(0.0, l0_b, l0_g, l0_r);  // 第 0 层 (RGBA, A=0)
    let l1 = _mm_set_ps(0.0, l1_b, l1_g, l1_r);
    let l2 = _mm_set_ps(0.0, l2_b, l2_g, l2_r);
    let w0 = _mm_set1_ps(w0);  // 广播权重
    let w1 = _mm_set1_ps(w1);
    let w2 = _mm_set1_ps(w2);
    // result = w0*l0 + w1*l1 + w2*l2
    let r01 = _mm_fmadd_ps(w0, l0, _mm_mul_ps(w1, l1));
    let r = _mm_fmadd_ps(w2, l2, r01);
    // 提取 r 的 rgb
}
```

**SIMD 在 CPU 上做**——但如果混合在 fragment shader 里做,GPU 已经 SIMD 化了,你不用管。

**内存对齐**:LPV 体素数组每个 voxel 是 RGB(12 字节)或 RGBA(16 字节)。SIMD 读取要求 16 字节对齐,所以**用 RGBA 比 RGB 更 SIMD 友好**(虽然多 4 字节浪费)。Casey Day 409 之后的版本都用 RGBA。

**cacheline 利用**:32³ LPV 的总字节 = 32³ × 16 = 524288 = 512 KB。CPU L2 cache 通常 256KB-1MB,**整个 LPV 可以装进 L2**!如果遍历顺序正确(row-major),cache miss 极低。Casey 在 Day 405+ 优化光照传播时把循环顺序改成 cache-friendly。

### 3.4 · 🦀 Rust 生态视角

Rust 实现 smoothstep:

```rust
#[inline]
pub fn smoothstep(edge0: f32, edge1: f32, x: f32) -> f32 {
    let t = ((x - edge0) / (edge1 - edge0)).clamp(0.0, 1.0);
    t * t * (3.0 - 2.0 * t)
}

#[inline]
pub fn smootherstep(edge0: f32, edge1: f32, x: f32) -> f32 {
    let t = ((x - edge0) / (edge1 - edge0)).clamp(0.0, 1.0);
    t * t * t * (t * (t * 6.0 - 15.0) + 10.0)
}
```

**`#[inline]`** 是 Rust 的内联提示——告诉编译器"把这个函数直接嵌入调用处,避免函数调用开销"。`smoothstep` 在 hot loop 里每像素调用一次,内联后几乎零开销。

**clamp** 是 Rust 标准库方法(`f32::clamp`),等价于 GLSL `clamp(x, min, max)`。

**glam crate** 的 smoothstep 实现:

```rust
use glam::Vec3;

let weights = Vec3::new(
    1.0 - smoothstep(2.0, 4.0, d),
    smoothstep(2.0, 4.0, d) * (1.0 - smoothstep(5.0, 8.0, d)),
    smoothstep(5.0, 8.0, d),
);
```

**所有权角度**:权重计算是纯函数,输入 f32 输出 f32,**没有所有权问题**。Vec3 是 Copy 类型(12 字节),按值传递。

**测试 smoothstep 的性质**(单测):

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_smoothstep_edges() {
        assert_eq!(smoothstep(0.0, 1.0, -1.0), 0.0);  // x < edge0
        assert_eq!(smoothstep(0.0, 1.0, 0.0), 0.0);   // x = edge0
        assert!((smoothstep(0.0, 1.0, 0.5) - 0.5).abs() < 1e-6);  // 中点 = 0.5
        assert_eq!(smoothstep(0.0, 1.0, 1.0), 1.0);   // x = edge1
        assert_eq!(smoothstep(0.0, 1.0, 2.0), 1.0);   // x > edge1
    }

    #[test]
    fn test_smoothstep_derivative_at_edges() {
        // 导数在 edge0 和 edge1 处为 0(数值验证)
        let eps = 1e-4;
        let d_low = (smoothstep(0.0, 1.0, eps) - smoothstep(0.0, 1.0, 0.0)) / eps;
        let d_high = (smoothstep(0.0, 1.0, 1.0) - smoothstep(0.0, 1.0, 1.0 - eps)) / eps;
        assert!(d_low.abs() < 1e-3);
        assert!(d_high.abs() < 1e-3);
    }
}
```

测试驱动开发是 Rust 社区的强项,**给数学函数写单测**是基本要求——你能保证 smoothstep 的数学性质正确。

- **数据插值** — 线性 / 双线性 / 三线性 / Hermite / Cubic spline

## 5 · 对照与变奏

### 2D Mipmap vs 3D LPV 混合

| 维度 | 2D Mipmap | 3D LPV 混合 |
|---|---|---|
| 应用对象 | 2D texture(表面纹理) | 3D 光照体积 |
| 多层结构 | mipmap chain(1/2, 1/4, ...) | LPV 多层(32³, 64³, 128³) |
| 自动生成 | glGenerateMipmap(自动) | 手动每层 LPV 迭代 |
| 混合策略 | OpenGL 自动 trilinear | 手动 smoothstep 权重 |
| 控制参数 | `GL_TEXTURE_MIN_FILTER` | 距离 / 法线权重 |
| 调试 | RenderDoc texture viewer | fragment shader debug mode |

**核心共性**:**都是用低分辨率覆盖远距离,高分辨率覆盖近距离**。这是任何离散数据可视化的通用策略。

### 历史演化

- **1983:Lance Williams 提出 Mipmap**(论文 "Pyramidal Parametrics"),是 texture LOD 的开创性工作
- **1990s:Mipmap 进入 OpenGL 1.0**(1992),`glGenerateMipmap` API
- **2000s:多重网格(multigrid)PDE 求解器**进入图形学,用于流体模拟
- **2010:Crytek 提出 Light Propagation Volume**(论文 "Cascaded Light Propagation Volumes"),把 mipmap 思路用到光照
- **2014:Unreal Engine 4** 整合 LPV 作为 GI 方案之一
- **2020+:Sparse Voxel Octree (SVOTree)、Virtual Shadow Maps** 等后续 GI 方案,**都基于多层混合思路**

Casey Day 409 是这条演化链上的一个具体实现,**核心数学和 1983 年 Williams 的工作几乎一样**。

### 数学插值族

| 插值 | 数学 | 平滑度 | 用途 |
|---|---|---|---|
| Nearest | `floor(x)` | 不连续 | 像素艺术 |
| Linear | `lerp(a, b, t) = a + (b-a)t` | C⁰ | 双线性纹理 |
| Cosine | `(1 - cos(πt)) / 2` | C¹ | Perlin noise |
| Smoothstep | `t²(3-2t)` | C¹ | LOD 混合(本日) |
| Smootherstep | `6t⁵-15t⁴+10t³` | C² | Perlin noise(高质) |
| Cubic Hermite | 取决于切线 | C¹ | Catmull-Rom spline |
| Natural Cubic Spline | 解三对角矩阵 | C² | 工程曲线 |

**Casey Day 409 选 smoothstep 的原因**:C¹ 已经消除视觉突变,实现简单(1 行 GLSL),开销低。C²(smootherstep)虽然更平滑但收益边际递减,且要算 5 次多项式。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 `smoothstep` 比 linear blend(`lerp`)在 LOD 混合里更好?具体到**视觉表现**和**数学性质**两个维度。

**参考解答**:

**视觉表现**:
- Linear blend 在切换距离两端**有突变**——权重从 0 突然开始增长,摄像机移动时画面有"加速"感
- Smoothstep 在两端**水平过渡**——权重缓慢从 0 开始增长,缓慢到 1 停止,画面**没有突变**

**数学性质**:
- Linear: `f(t) = t`,导数 `f'(t) = 1`,**在 t=0 和 t=1 处导数为 1**(不是 0,突变)
- Smoothstep: `f(t) = t²(3-2t)`,导数 `f'(t) = 6t(1-t)`,**在 t=0 和 t=1 处导数为 0**(连续)

**关键**:视觉对**导数的连续性**敏感。一阶导数突变 → 画面突变;一阶导数连续 → 画面平滑。这是为什么所有工业 LOD 都用 smoothstep 或 smootherstep。

- smootherstep 在 t=0 和 t=1 处的一阶导数和二阶导数都接近 0

```rust
#[inline]
pub fn smoothstep(edge0: f32, edge1: f32, x: f32) -> f32 {
    let t = ((x - edge0) / (edge1 - edge0)).clamp(0.0, 1.0);
    t * t * (3.0 - 2.0 * t)
}

#[inline]
pub fn smoothstep_derivative(edge0: f32, edge1: f32, x: f32) -> f32 {
    let t = ((x - edge0) / (edge1 - edge0)).clamp(0.0, 1.0);
    6.0 * t * (1.0 - t) / (edge1 - edge0)  // 链式法则
}

#[inline]
pub fn smootherstep(edge0: f32, edge1: f32, x: f32) -> f32 {
    let t = ((x - edge0) / (edge1 - edge0)).clamp(0.0, 1.0);
    t * t * t * (t * (t * 6.0 - 15.0) + 10.0)
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn smoothstep_zero_at_edges() {
        assert_eq!(smoothstep(0.0, 1.0, 0.0), 0.0);
        assert_eq!(smoothstep(0.0, 1.0, 1.0), 1.0);
    }

    #[test]
    fn smoothstep_derivative_zero_at_edges() {
        // 在 t=0 附近的数值导数应该接近 0
        let eps = 1e-4;
        let d_at_0 = (smoothstep(0.0, 1.0, eps) - smoothstep(0.0, 1.0, 0.0)) / eps;
        let d_at_1 = (smoothstep(0.0, 1.0, 1.0) - smoothstep(0.0, 1.0, 1.0 - eps)) / eps;
        assert!(d_at_0.abs() < 1e-2, "d_at_0 = {}", d_at_0);
        assert!(d_at_1.abs() < 1e-2, "d_at_1 = {}", d_at_1);
    }

    #[test]
    fn smootherstep_zero_at_edges() {
        assert_eq!(smootherstep(0.0, 1.0, 0.0), 0.0);
        assert_eq!(smootherstep(0.0, 1.0, 1.0), 1.0);
    }
}

fn main() {
    // 画 ASCII 曲线
    println!("t    smoothstep  smootherstep");
    let mut t = 0.0f32;
    while t <= 1.0 {
        let s = smoothstep(0.0, 1.0, t);
        let ss = smootherstep(0.0, 1.0, t);
        println!("{:.2}  {:.4}      {:.4}", t, s, ss);
        t += 0.05;
    }
    // 输出曲线在 t=0.5 处 smoothstep=0.5,smootherstep=0.5(对称)
    // 但 smootherstep 在中间更"陡",两端更"平"(C² 连续的代价)
}
```

### 完整多层 LPV 混合 Rust 实现

```rust
// src/lpv/blending.rs
use glow::HasContext;

/// 多层 LPV 混合的权重参数
#[derive(Copy, Clone, Debug)]
pub struct BlendParams {
    /// 细层(zoom-in)距离边界
    pub fine_near: f32,
    pub fine_far: f32,
    /// 中层距离边界
    pub medium_near: f32,
    pub medium_far: f32,
}

impl Default for BlendParams {
    fn default() -> Self {
        Self {
            fine_near: 2.0,
            fine_far: 4.0,
            medium_near: 5.0,
            medium_far: 8.0,
        }
    }
}

/// 算三层 LPV 权重,基于距离
/// 返回 (w_coarse, w_medium, w_fine),保证和为 1
pub fn compute_distance_weights(distance: f32, params: BlendParams) -> (f32, f32, f32) {
    // 细层权重:近处 1,远处 0
    let w_fine = 1.0 - smoothstep(params.fine_near, params.fine_far, distance);
    // 中层权重:中间距离 1,两端 0
    let w_medium = smoothstep(params.fine_near, params.fine_far, distance)
        * (1.0 - smoothstep(params.medium_near, params.medium_far, distance));
    // 粗层权重:远处 1,近处 0
    let w_coarse = smoothstep(params.medium_near, params.medium_far, distance);

    // 归一化(理论上已经归一化,但加保险)
    let total = w_fine + w_medium + w_coarse;
    if total > 1e-6 {
        (w_coarse / total, w_medium / total, w_fine / total)
    } else {
        (1.0, 0.0, 0.0)  // fallback:全用粗层
    }
}

#[inline]
fn smoothstep(edge0: f32, edge1: f32, x: f32) -> f32 {
    let t = ((x - edge0) / (edge1 - edge0)).clamp(0.0, 1.0);
    t * t * (3.0 - 2.0 * t)
}

/// 法线权重:法线和视线对齐时用细层,掠射时用粗层
/// N: 表面法线(单位向量)
/// V: 视线方向(从片元到相机,单位向量)
/// 返回细层权重增量(0=用粗层,1=用细层)
pub fn compute_normal_weight(n: glam::Vec3, v: glam::Vec3) -> f32 {
    let cos_theta = n.dot(v).abs();
    smoothstep(0.0, 0.5, cos_theta)
}

/// 混合三层 LPV 采样
pub fn blend_lpv_samples(
    l_coarse: glam::Vec3,
    l_medium: glam::Vec3,
    l_fine: glam::Vec3,
    distance: f32,
    normal: glam::Vec3,
    view_dir: glam::Vec3,
    params: BlendParams,
) -> glam::Vec3 {
    let (w_c, w_m, w_f) = compute_distance_weights(distance, params);
    let n_w = compute_normal_weight(normal, view_dir);

    // 法线权重调整:细层 + 法线权重,粗层 - 法线权重
    let w_f_adjusted = w_f * n_w;
    let w_c_adjusted = w_c + w_f * (1.0 - n_w);  // 法线偏离时,细层权重转给粗层
    let w_m_adjusted = w_m;

    // 归一化
    let total = w_c_adjusted + w_m_adjusted + w_f_adjusted;
    if total > 1e-6 {
        (l_coarse * w_c_adjusted + l_medium * w_m_adjusted + l_fine * w_f_adjusted) / total
    } else {
        glam::Vec3::ZERO
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn weights_sum_to_one() {
        let params = BlendParams::default();
        for d in [0.0, 1.0, 3.0, 5.0, 7.0, 10.0, 100.0] {
            let (w_c, w_m, w_f) = compute_distance_weights(d, params);
            let sum = w_c + w_m + w_f;
            assert!((sum - 1.0).abs() < 1e-5, "distance={} sum={}", d, sum);
        }
    }

    #[test]
    fn near_uses_fine() {
        let params = BlendParams::default();
        let (w_c, w_m, w_f) = compute_distance_weights(1.0, params);  // 近距离
        assert!(w_f > 0.9, "近处应该用细层,w_f={}", w_f);
        assert!(w_c < 0.1);
    }

    #[test]
    fn far_uses_coarse() {
        let params = BlendParams::default();
        let (w_c, w_m, w_f) = compute_distance_weights(20.0, params);  // 远距离
        assert!(w_c > 0.9, "远处应该用粗层,w_c={}", w_c);
        assert!(w_f < 0.1);
    }
}
```

### Fragment Shader 混合实现

```glsl
// src/shaders/lpv_blend.frag
#version 430
in vec3 vWorldPos;
in vec3 vNormal;
out vec4 fragColor;

uniform sampler3D uVoxelCoarse;
uniform sampler3D uVoxelMedium;
uniform sampler3D uVoxelFine;
uniform vec3 uGrid0Min, uGrid0Max;  // 粗网格边界
uniform vec3 uGrid1Min, uGrid1Max;  // 中网格边界
uniform vec3 uGrid2Min, uGrid2Max;  // 细网格边界
uniform vec3 uCameraPos;
uniform int uDebugMode;

float smoothstep_c(float e0, float e1, float x) {
    float t = clamp((x - e0) / (e1 - e0), 0.0, 1.0);
    return t * t * (3.0 - 2.0 * t);
}

void main() {
    // 三层采样
    vec3 uvw0 = (vWorldPos - uGrid0Min) / (uGrid0Max - uGrid0Min);
    vec3 uvw1 = (vWorldPos - uGrid1Min) / (uGrid1Max - uGrid1Min);
    vec3 uvw2 = (vWorldPos - uGrid2Min) / (uGrid2Max - uGrid2Min);

    vec3 L0 = texture(uVoxelCoarse, uvw0).rgb;
    vec3 L1 = texture(uVoxelMedium, uvw1).rgb;
    vec3 L2 = texture(uVoxelFine,   uvw2).rgb;

    // 距离权重
    float d = length(vWorldPos - uCameraPos);
    float w_f = 1.0 - smoothstep_c(2.0, 4.0, d);
    float w_m = smoothstep_c(2.0, 4.0, d) * (1.0 - smoothstep_c(5.0, 8.0, d));
    float w_c = smoothstep_c(5.0, 8.0, d);

    // 法线权重
    vec3 N = normalize(vNormal);
    vec3 V = normalize(uCameraPos - vWorldPos);
    float cos_theta = abs(dot(N, V));
    float n_w = smoothstep_c(0.0, 0.5, cos_theta);

    // 调整后权重
    float w_f_adj = w_f * n_w;
    float w_c_adj = w_c + w_f * (1.0 - n_w);
    float w_m_adj = w_m;

    float total = w_c_adj + w_m_adj + w_f_adj;
    vec3 final_light = (L0 * w_c_adj + L1 * w_m_adj + L2 * w_f_adj) / max(total, 1e-6);

    if (uDebugMode == 0) {
        // 正常输出
        fragColor = vec4(final_light, 1.0);
    } else if (uDebugMode == 1) {
        // 显示距离权重(粗红、中绿、细蓝)
        fragColor = vec4(w_c_adj, w_m_adj, w_f_adj, 1.0);
    } else if (uDebugMode == 2) {
        // 显示法线权重
        fragColor = vec4(vec3(n_w), 1.0);
    } else if (uDebugMode == 3) {
        // 显示 uvw0(粗网格)
        fragColor = vec4(uvw0, 1.0);
    }
}
```

**Troubleshooting**:

- 接缝仍在:`smoothstep` 的边界设得太窄(比如 4.0-4.5),过渡不够。扩大到 2.0-6.0。
