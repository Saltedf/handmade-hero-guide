
# Day 326 · 可变参数函数

> printf 这种"参数数量可变"的函数叫 vararg。Casey 不满意标准 printf 在游戏里的性能和灵活性,决定从零手写自己的 printf。今天是第一篇——理解 vararg 的底层机制。

## 0 · 为什么要有这一天

到目前为止你用过的函数都是固定参数数量。`fn add(a: i32, b: i32) -> i32` 永远是 2 个参数。但有些函数天生需要可变参数:

- `printf(format, ...)` —— 格式串 + 任意数量参数
- `max(a, b, c, d, ...)` —— 求多个数的最大值
- `sum(1, 2, 3, 4, ...)` —— 任意数量求和

C 语言用 `...` 语法支持 vararg,叫"可变参数函数"。今天的 Casey 工作:**理解 vararg 在底层怎么实现**,为明天手写 printf 做准备。

为什么 Casey 要手写 printf?C 标准库的 printf 有几个问题:

1. **代码体积大**:glibc 的 printf 完整支持 %f、%g、%e、各种 flag,编译后 ~50 KB,游戏 console 不需要
2. **性能差**:printf 内部要解析格式串、变体处理、locale,游戏 debug 输出要更快
3. **格式扩展难**:Casey 想加 `%v2`(向量 2)之类的自定义格式,glibc printf 不能扩展
4. **浮点支持差**(早期):Casey 想要简单可靠的浮点打印,不想踩 printf 浮点的坑

游戏行业普遍自写 printf——Unreal 的 `FString::Printf`、Unity 的内部 `Printf`、Casey 的 HH 都是。今天 Casey 干的是这件事的第一步——理解 vararg。

心理锚点:今天之后你能"自己实现 vararg 函数",并理解 C 调用约定(calling convention)怎么处理可变参数。明天(day327)开始手写 printf 解析器。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_printf.cpp`(新文件),开始研究 vararg。

C 的 vararg 用 `<stdarg.h>` 头文件的宏:

```c
#include <stdarg.h>

int sum(int count, ...) {
    va_list args;
    va_start(args, count);  // 初始化,从 count 之后开始
    
    int total = 0;
    for (int i = 0; i < count; i++) {
        int val = va_arg(args, int);  // 取下一个 int
        total += val;
    }
    
    va_end(args);  // 清理
    return total;
}

// 调用
int s = sum(3, 10, 20, 30);  // = 60
```

关键宏:

- `va_list`:变参指针,内部是个 char*
- `va_start(list, last_named)`:初始化 list,从 last_named(最后一个有名参数)之后开始
- `va_arg(list, type)`:取下一个参数,假设类型是 type
- `va_end(list)`:清理(某些平台需要)

Casey 在视频里深入探讨了这些宏的实现:

- **x86-64 System V ABI**:`va_list` 是个结构,包含寄存器保存区 + 栈指针。前 6 个整数参数在寄存器,第 7 个开始入栈
- **x86(老 32 位)**:`va_list` 就是 char*,所有参数都在栈上,va_arg 简单递增指针
- **ARM**:类似 x86-64,前几个参数在寄存器

Casey 还指出一个**关键陷阱**:va_arg 不知道参数实际类型,调用方必须告诉它。如果调用方传 `double`,va_arg 取 `int`,结果完全错乱。这就是为什么 printf 需要 `%d`、`%f`、`%s` 格式串——格式串告诉 va_arg 类型。

## 2 · 心智模型

### 类比:传送带上的包裹

把函数调用想象成传送带上的包裹。

- **固定参数**:每个包裹有标签,接收方知道每个包裹的尺寸(int = 4 字节,double = 8 字节)
- **可变参数**:包裹没标签,接收方只看到一个 char* 指针,自己猜每个包裹多大

va_arg 的本质:**调用方和被调用方约定"猜"的规则**。如果规则对(类型一致),传送带正常工作;规则错(类型不一致),东西损坏。

printf 的格式串就是这个"规则"——`%d` 告诉 va_arg 取 4 字节,`%f` 告诉它取 8 字节,`%s` 告诉它取指针。

### 严谨原理:x86-64 调用约定

x86-64 System V ABI(Linux/macOS)的参数传递:

| 参数序号 | 整数类型 | 浮点类型 |
|---|---|---|
| 1 | rdi | xmm0 |
| 2 | rsi | xmm1 |
| 3 | rdx | xmm2 |
| 4 | rcx | xmm3 |
| 5 | r8 | xmm4 |
| 6 | r9 | xmm5 |
| 7+ | 栈 | 栈 |

可变参数函数的复杂性:**前 6 个参数在寄存器,va_arg 要从寄存器或栈取**。`va_list` 内部是个结构:

```c
typedef struct {
    unsigned int gp_offset;     // 下一个整数寄存器参数的偏移
    unsigned int fp_offset;     // 下一个浮点寄存器参数的偏移
    void *overflow_arg_area;    // 栈参数区
    void *reg_save_area;        // 寄存器保存区
} va_list[1];
```

函数 prologue 把所有可能用到的寄存器保存到栈上的"寄存器保存区",va_arg 根据 `gp_offset` / `fp_offset` 决定从哪取。

```c
// va_arg(list, int) 展开为类似:
int value = *(int*)(list->reg_save_area + list->gp_offset);
list->gp_offset += 8;  // 寄存器槽位 8 字节
```

这是为什么 vararg 比固定参数稍慢——有额外指针解引用和偏移更新。

### Rust 没有 vararg

Rust 故意**不支持 C 风格 vararg**,因为它**类型不安全**(va_arg 不检查类型,运行时崩)。Rust 的替代方案:

1. **Macro**:`println!`、`format!`、`vec!` 都是宏,编译期展开,类型安全
2. **泛型 + Trait**:`fn sum<T: Add>(values: &[T])` 接受切片
3. **Builder pattern**:`fn args(self, arg) -> Self` 链式调用

```rust
// Rust 用 macro 实现类似 vararg
macro_rules! sum {
    ($($x:expr),*) => {
        {
            let total = 0;
            $( let total = total + $x; )*
            total
        }
    };
}

let s = sum!(1, 2, 3, 4);  // 编译期展开,类型安全
```

Rust 的 macro 在编译期展开,所有参数类型在编译期已知,不存在 va_arg 的运行时猜类型问题。

### 与 C FFI

Rust 可以**调用** C 的 vararg 函数(FFI):

```rust
extern "C" {
    fn printf(format: *const c_char, ...) -> c_int;
}

fn main() {
    unsafe {
        printf(b"Hello %s!\n\0".as_ptr() as *const _, b"World\0".as_ptr());
    }
}
```

但 Rust 自己**不能定义** C vararg 函数(只能在 unsafe extern "C" 里声明)。需要 vararg 时,用 macro 或泛型。

### Casey 的 C 实现

```c
int my_printf(const char *fmt, ...) {
    va_list args;
    va_start(args, fmt);
    
    int count = 0;
    while (*fmt) {
        if (*fmt == '%') {
            fmt++;
            switch (*fmt) {
                case 'd': {
                    int val = va_arg(args, int);
                    count += print_int(val);
                    break;
                }
                case 's': {
                    char *str = va_arg(args, char*);
                    count += print_str(str);
                    break;
                }
                // ...
            }
        } else {
            print_char(*fmt);
            count++;
        }
        fmt++;
    }
    
    va_end(args);
    return count;
}
```

`va_arg(args, int)` 取下一个 int,`va_arg(args, char*)` 取下一个指针。每个格式 specifier 对应一次 va_arg。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏行业自写 printf 的例子:

- **Unreal Engine**:`FString::Printf`,扩展支持 Unreal 类型(FString、FName)
- **Id Tech**:`Com_Printf`,游戏 console 输出
- **Casey HH**:今天的 `handmade_printf`,自写最小版

游戏行业的"为什么自写":

1. **代码体积**:console 游戏机 flash 有限,要最小
2. **格式扩展**:加 `%v3`(向量)、`%m4`(矩阵)等游戏特有类型
3. **性能**:debug 输出热路径,避免标准库开销
4. **可移植性**:跨平台编译时,标准 printf 行为不完全一致

### 3.2 · 🐧 Linux 系统编程视角

Linux 内核没有 libc,所以不能用标准 printf。内核有自己的 `printk`、`pr_info`、`pr_err`,实现类似 vararg 但用 `vsnprintf`。

```c
// Linux 内核的 printk
printk(KERN_INFO "Hello %s, count = %d\n", name, count);
```

printk 的特点:

1. **中断安全**:可以从中断上下文调用,无锁
2. **ring buffer**:输出到内核环形缓冲,dmesg 读取
3. **格式扩展**:`%pK`(内核指针屏蔽)、`%pOF`(device tree 节点)

Linux 用户态工具 strace/ltrace 也用 vararg 风格 API。vararg 是系统编程的基础设施。

### 3.3 · 🦀 Rust 生态视角

Rust 的可变参数方案对比:

| 方案 | 类型安全 | 性能 | 灵活度 | 例 |
|---|---|---|---|---|
| Macro | ✓ 编译期 | ✓ | ✓ | `println!`, `format!` |
| 切片参数 | ✓ | ✓ | 中 | `fn sum(vals: &[i32])` |
| Builder | ✓ | ✓ | 中 | `Args::new().add(1).add(2)` |
| C FFI vararg | ✗ 运行时 | 差 | 高 | `printf` |

Rust 的 macro 是最优雅的——编译期展开,类型安全,无运行时开销。`println!` 实际是个 declarative macro:

```rust
// println! 宏的简化展开
macro_rules! println {
    ($fmt:literal $(, $arg:expr)*) => {
        $crate::io::_print(format_args!($fmt $(, $arg)*));
    };
}

// 调用 println!("Hello {}", name)
// 编译期展开为:
std::io::_print(format_args!("Hello {}", name));
```

`format_args!` 是 Rust 编译器内置宏,生成 `Arguments` 类型,延迟格式化(只在 print 时实际格式化)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Rust 故意不支持 C 风格 vararg?

**参考解答**:

C vararg 的核心问题是**类型不安全**——va_arg 取参数时,调用方必须告诉它类型,如果类型对不上,运行时崩(读越界、解析错误)。

```c
printf("%d\n", "hello");  // 编译过,运行时崩(va_arg 把 char* 当 int 读)
```

Rust 设计哲学:**类型安全编译期保证**。vararg 绕过编译器,违反 Rust 的核心承诺。Rust 用 macro(编译期展开)或泛型实现同样功能,但编译期类型检查。

## 8 · Rust / Arch 落地代码

### Rust:理解 vararg + Rust macro 替代

```rust
// Cargo.toml: 无依赖
// src/main.rs

// ============ 1. 通过 FFI 调用 C printf(展示 vararg) ============
use std::os::raw::{c_char, c_int};

extern "C" {
    fn printf(format: *const c_char, ...) -> c_int;
}

fn c_printf_demo() {
    println!("=== 1. C printf via FFI ===");
    unsafe {
        // 注意:Rust 字符串字面量需要 \0 结尾(C 风格)
        printf(b"Hello %s! count = %d\n\0".as_ptr() as *const _,
               b"World\0".as_ptr(),
               42);
        // 输出:Hello World! count = 42
    }
    println!();
}

// ============ 2. Rust macro 实现类型安全 "vararg" ============

/// 求和宏,接受任意数量整数
macro_rules! sum {
    () => { 0 };
    ($first:expr $(, $rest:expr)*) => {
        $first $(+ $rest)*
    };
}

/// 自定义 print 宏,展示 macro 比 vararg 安全
macro_rules! my_print {
    // {} 模式:用 Display trait
    ($($arg:expr),*) => {
        {
            let mut parts = Vec::new();
            $(
                parts.push(format!("{}", $arg));
            )*
            println!("{}", parts.join(", "));
        }
    };
}

/// 类似 vec! 的宏
macro_rules! my_vec {
    ($($x:expr),+ $(,)?) => {
        {
            let mut v = Vec::new();
            $( v.push($x); )+
            v
        }
    };
}

fn macro_demo() {
    println!("=== 2. Rust macro(类型安全 vararg) ===");
    
    // sum! 接受任意数量
    println!("sum!(1, 2, 3) = {}", sum!(1, 2, 3));
    println!("sum!(10, 20, 30, 40) = {}", sum!(10, 20, 30, 40));
    println!("sum!(5) = {}", sum!(5));
    println!("sum!() = {}", sum!());
    
    // my_print!
    my_print!("hello", 42, 3.14);
    
    // my_vec!
    let v = my_vec!(1, 2, 3, 4, 5);
    println!("my_vec!(1..5) = {:?}", v);
    
    println!();
}

// ============ 3. Rust 用 trait object 模拟 vararg ============

trait Printable {
    fn to_display_string(&self) -> String;
}

impl Printable for i32 {
    fn to_display_string(&self) -> String { self.to_string() }
}
impl Printable for &str {
    fn to_display_string(&self) -> String { self.to_string() }
}
impl Printable for f64 {
    fn to_display_string(&self) -> String { self.to_string() }
}

/// 接受任意数量的 `&dyn Printable`,有点像 vararg 但类型安全
fn print_all(items: &[&dyn Printable]) {
    let parts: Vec<_> = items.iter().map(|i| i.to_display_string()).collect();
    println!("{}", parts.join(", "));
}

fn trait_object_demo() {
    println!("=== 3. Trait object 模拟 vararg ===");
    
    let a: i32 = 10;
    let b: &str = "hello";
    let c: f64 = 3.14;
    
    print_all(&[&a, &b, &c]);
    println!();
}

// ============ 4. Rust println! 实际是格式串 macro(类 printf) ============

fn rust_format_demo() {
    println!("=== 4. Rust format 串(类 printf) ===");
    
    // Rust 的 {} 等价于 C 的通用格式(类型自动选)
    let name = "World";
    let count = 42;
    let pi = 3.14159;
    println!("Hello {}, count = {}, pi = {:.2}", name, count, pi);
    
    // Rust 的 {:?} 等价于 C 没有的"调试格式"
    let vec = vec![1, 2, 3];
    println!("Vec = {:?}", vec);
    
    // Rust 的 {:x} 等价于 C 的 %x
    let num = 255;
    println!("255 in hex = {:#x}", num);
    
    println!();
}

// ============ 5. 自实现简化 printf(展示 vararg 思想) ============

/// Rust 版本的简化 printf
/// 用 enum 表达"参数类型",模拟 C 的 va_arg
#[derive(Clone, Debug)]
enum PrintfArg {
    Int(i64),
    Str(String),
    Float(f64),
}

fn my_printf(format: &str, args: &[PrintfArg]) -> String {
    let mut result = String::new();
    let mut arg_iter = args.iter();
    let mut chars = format.chars().peekable();
    
    while let Some(c) = chars.next() {
        if c == '%' {
            match chars.next() {
                Some('d') => {
                    if let Some(PrintfArg::Int(n)) = arg_iter.next() {
                        result.push_str(&n.to_string());
                    }
                }
                Some('s') => {
                    if let Some(PrintfArg::Str(s)) = arg_iter.next() {
                        result.push_str(s);
                    }
                }
                Some('f') => {
                    if let Some(PrintfArg::Float(f)) = arg_iter.next() {
                        result.push_str(&format!("{:.6}", f));
                    }
                }
                Some(c) => {
                    result.push('%');
                    result.push(c);
                }
                None => {
                    result.push('%');
                    break;
                }
            }
        } else {
            result.push(c);
        }
    }
    
    result
}

fn simplified_printf_demo() {
    println!("=== 5. 自实现简化 printf(Rust enum 版) ===");
    
    let output = my_printf("Hello %s, count = %d, pi = %f\n", &[
        PrintfArg::Str("World".to_string()),
        PrintfArg::Int(42),
        PrintfArg::Float(3.14159),
    ]);
    print!("{}", output);
    
    // 注意:Rust 用 enum 表达"多种可能类型",比 C 的 va_arg 类型安全
    // 编译器在 arg_iter.next() 时检查 enum variant
}

fn main() {
    c_printf_demo();
    macro_demo();
    trait_object_demo();
    rust_format_demo();
    simplified_printf_demo();
}
```

## 10 · 深度补充:工程视角

vararg 的现代替代方案:Rust macro / Zig comptime / C++ variadic template 都是 vararg 的现代替代,类型安全 + 编译期展开。C vararg 是历史遗留,新项目应避免。Rust println! 是 macro,编译期解析格式串,运行时类型安全。Zig 的 printf 用 comptime 推导类型,完全消除运行时开销。C++17 的 std::format 是类型安全的 printf。

### 跨领域的方向一致性

工程上很多抽象都跨领域通用。今天的概念在多个领域都有对应。

- **游戏引擎**:Core abstraction 表达
- **图形学**:GPU 硬件或软件算法实现
- **Linux 内核**:类似抽象在 OS 层
- **Rust 生态**:类型安全表达

理解一个抽象的多领域映射,你就能在不同技术栈间自由切换。

### 历史演化与未来趋势

每个技术都有演化历史和未来趋势。Casey 在 HH 系列展示的是 当下最佳实践,但技术会演进。学会识别 哪些是永恒原理(数据结构、算法)、哪些是时代选择(API 设计、语言特性),让你长期保持竞争力。

永恒原理:排序、矩阵乘法、alpha 合成、内存分配、并发原语。这些 50 年不变。

时代选择:OpenGL vs Vulkan vs WebGPU、Rust vs C++、ECS vs OOP。这些 5-10 年一变。

## 11 · 延伸讨论

可变参数的安全性:Rust 拒绝 vararg 不是固执,是数据驱动决策——C 代码库的安全审计显示 ~30% 漏洞是 vararg 类型混淆导致。Rust 用 macro + trait 完全消除这类问题。Zig 走得更远——用 comptime 完全替代 vararg,编译期生成类型安全代码。Rust macro 的局限:declarative macro 宏 hygiene 难, procedural macro 学习曲线陡。Casey 的 C vararg 虽然不安全,但简单。Rust 选择'安全 + 复杂'是工程权衡。

### 工程决策的权衡

每个技术选择都涉及权衡。今天的主题在 Casey 的 HH 里选了某条路,但其他路也合理。理解权衡让你能在新场景做正确选择。

### Rust 生态的演进

Rust 生态每 6 个月一个 edition,API 和最佳实践会变。但核心原理(所有权 / 借用 / Send/Sync / Trait)稳定。学会识别'什么是稳定基础'vs'什么是流行 API',让你长期有效。

### 开源贡献的实践

今天的 Lv4 题目指向真实开源项目。实践建议:

1. **找 good-first-issue**:GitHub 上 label:'good first issue'
2. **读代码 + 文档**:理解项目架构
3. **fork + 改 + 测试**:本地验证
4. **写 PR 描述**:动机 / 改动 / 测试
5. **接受 review**:维护者反馈,可能要改
6. **merge**:成为项目 contributor

PR 不一定要大——文档改进、测试补充、小 bug 修复都是贡献。重要的是参与。
