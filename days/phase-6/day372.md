# Day 372 · 严格使用 OpenGL 核心配置文件

> OpenGL 有两种 profile:**Compatibility Profile(兼容配置)**保留 1992 年的旧 API(`glBegin/glEnd`,固定管线),**Core Profile(核心配置)**只保留现代 API(VAO + VBO + shader)。今天 Casey 切到严格 Core Profile,**移除所有"兼容"残留**,逼自己用现代 API。

## 0 · 为什么要有这一天

你的游戏一直在用 OpenGL,但你可能没意识到:**OpenGL 有两套 API**。

**Compatibility Profile(兼容配置)**:
- 包括 OpenGL 1.x 的 `glBegin/glEnd`(立即模式)
- 固定函数管线(`glRotatef`, `glLightfv` 等内建光照)
- `glVertexPointer` 等老式顶点 API
- 默认 VAO(可以不绑定 VAO 就画几何)
- **可以混合使用**:你写一段 `glBegin/glEnd` 然后切 shader,都不会报错

**Core Profile(核心配置)**:
- 强制 VAO(没绑定就画几何会报错)
- 强制 shader(没 program 会报错)
- 完全去掉固定函数管线(没有 `glLightfv` 等)
- 必须自己写 MVP 变换、自己写光照
- **不能混合**:任何兼容 API 调用立即报错

**为什么要用 Core**?

第一,**性能**。Compatibility Profile 保留所有旧状态,driver 每次调用都要验证大量状态机,慢。Core Profile 状态简化,driver 验证开销小,实际性能高 10-30%。

第二,**学习**。Compatibility 让你"偷懒"——`glRotatef` 一行完成旋转,但你不理解背后发生了什么。Core Profile 逼你写矩阵、shader、attribute 配置,理解每一步。

第三,**跨平台**。macOS 上的 OpenGL 4.1 只支持 Core Profile(苹果 2010 年后放弃 OpenGL,只保留 Core)。**如果你的代码在 Windows / Linux 用 Compatibility,在 Mac 不能跑**。

第四,**Vulkan / DX12 准备**。下一代 API(Vulkan / DX12 / Metal)都是"显式"风格,概念上接近 Core Profile。学 Core 是为未来铺路。

Casey 今天做的是**清理**——他原本在 Compatibility 跑(因为有些初始化代码用了旧 API),现在切到严格 Core,所有几何渲染必须显式 VAO + shader。这一步让代码更现代,也是后面所有 advanced OpenGL 技术的前提。

心理锚点:今天之后,你能区分 Core / Compatibility Profile,知道为什么工业用 Core,能在 macOS 上跑 OpenGL 代码(必须 Core)。

## 1 · Casey 今天做了什么(HH 脉络)

Day 371 引入 VAO 后,Casey 决定彻底切到 Core Profile。他的代码此前可能在某些地方用了 Compatibility API(如默认 VAO、固定管线光照等),今天清理:

- 默认 VAO 不存在,必须 `glGenVertexArrays`
- 没 program 时 `glDrawElements` 报错
- `glPushAttrib` / `glPopAttrib`(状态 push/pop)被删除

修复后,代码更严谨,后续 bug 减少。

## 2 · 心智模型

### 类比:Core Profile 是"软件包管理"

想象你用 Linux 包管理器(`pacman`)。两种模式:

- **Compatibility Profile**(像 Arch Linux 装了一堆 AUR 老包):你能跑旧软件,但系统状态混乱,各种"为什么这个文件在这里"的问题。新软件可能依赖老库,老库可能被升级破坏
- **Core Profile**(像 Arch Linux 最小安装):系统干净,只有现代软件。你显式声明依赖,所有包版本清晰。问题少,但学习曲线陡

游戏渲染一样:**Compatibility Profile 让你"跑起来"快**(glBegin/glEnd 简单),但**长期维护痛苦**(状态机臃肿,bug 难调)。**Core Profile 起步难**(理解 VAO/shader),但长期清爽。

工业 100% 用 Core(或更激进的 Vulkan / DX12)。教学项目从 Compatibility 起步可以,但 Casey 切到 Core 是正确选择。

### OpenGL Profile 的版本和组合

OpenGL Profile 不是单一开关,而是组合:

| Profile 组合 | 含义 |
|---|---|
| Core Profile | 现代 API,无旧特性 |
| Compatibility Profile | 现代 + 旧特性 |
| Forward Compatible | 删除"deprecated but still works"的特性 |

具体差异:

```
Core Profile:
  - 必须 VAO
  - 必须自己 shader(无 fixed function)
  - 没有 glBegin/glEnd
  - 没有 glRotatef / glTranslatef / glLightfv
  - 没有 glVertexPointer(用 glVertexAttribPointer)
  - 没有 display list
  - 没有 glPushAttrib / glPopAttrib

Compatibility Profile:
  - 包括 Core 全部
  - 加上所有上面的旧特性
  - 默认 VAO(0)可用
```

**Forward Compatible** 是另一个轴:
- `GLFW_OPENGL_FORWARD_COMPAT = GL_TRUE`:不使用任何 deprecated 特性
- macOS 必需(苹果只支持 Core + Forward Compatible)

实际操作:通常要求 `Core Profile` + `Forward Compatible`,这是最严格的现代 OpenGL。

### 版本号和 Profile

OpenGL 版本号(3.3, 4.0, 4.6)代表 API 演进。Profile 是版本内的子集:

- OpenGL 3.3 Core:VAO + shader 强制
- OpenGL 4.0 Core:+ Tessellation shader
- OpenGL 4.3 Core:+ Compute shader
- OpenGL 4.6 Core:+ SPIR-V / Anisotropic filtering standard

Casey 用 OpenGL 3.3 Core,跨平台兼容性好(几乎所有 GPU 都支持)。

### 切到 Core 后的常见错误

**1. 默认 VAO 不存在**

```rust
// Compatibility Profile 可以这样画(用默认 VAO 0):
unsafe {
    gl::BindBuffer(gl::ARRAY_BUFFER, vbo);
    gl::VertexAttribPointer(0, 3, gl::FLOAT, gl::FALSE, 0, ptr::null());
    gl::EnableVertexAttribArray(0);
    gl::DrawArrays(gl::TRIANGLES, 0, 3);
}

// Core Profile 必须先创建并绑定 VAO:
unsafe {
    gl::GenVertexArrays(1, &mut vao);
    gl::BindVertexArray(vao);   // ← 必需
    gl::BindBuffer(gl::ARRAY_BUFFER, vbo);
    gl::VertexAttribPointer(0, 3, gl::FLOAT, gl::FALSE, 0, ptr::null());
    gl::EnableVertexAttribArray(0);
    gl::DrawArrays(gl::TRIANGLES, 0, 3);
}
```

**2. 固定函数变换矩阵不存在**

```c
// Compatibility:
glMatrixMode(GL_MODELVIEW);
glLoadIdentity();
glTranslatef(0, 0, -5);

// Core:必须自己写 shader 接收 uniform mat4
shader.use_program();
let model = Mat4::IDENTITY * Mat4::from_translation(Vec3::new(0, 0, -5));
shader.set_uniform("u_model", &model);
```

**3. `glPushAttrib` / `glPopAttrib` 不存在**

```c
// Compatibility:
glPushAttrib(GL_DEPTH_BUFFER_BIT);
glDisable(GL_DEPTH_TEST);
draw_something();
glPopAttrib();   // 恢复

// Core:手动管理状态
let prev_depth = gl::IsEnabled(gl::DEPTH_TEST);
gl::Disable(gl::DEPTH_TEST);
draw_something();
if prev_depth != 0 {
    gl::Enable(gl::DEPTH_TEST);
}
```

工业代码常用 RAII 包装:

```rust
struct GlStateGuard<F: FnOnce()> {
    restore: F,
}

impl<F: FnOnce()> Drop for GlStateGuard<F> {
    fn drop(&mut self) {
        (self.restore)();
    }
}

// 使用:
let prev = unsafe { gl::IsEnabled(gl::DEPTH_TEST) };
unsafe { gl::Disable(gl::DEPTH_TEST); }
let _guard = GlStateGuard {
    restore: move || unsafe {
        if prev != 0 { gl::Enable(gl::DEPTH_TEST); }
    },
};
// 在此 scope 内 depth test 关闭,scope 结束自动恢复
```

### Rust 视角:Profile 检测

```rust
pub struct GLContext {
    pub version: (u8, u8),
    pub profile: GLProfile,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum GLProfile {
    Core,
    Compatibility,
    Unknown,
}

impl GLContext {
    pub fn detect() -> Self {
        let version_str = unsafe {
            let ptr = gl::GetString(gl::VERSION) as *const i8;
            std::ffi::CStr::from_ptr(ptr).to_string_lossy().into_owned()
        };
        // 解析 "3.3.0 NVIDIA 525.x" 等
        let version = parse_version(&version_str);

        let mut profile_mask = 0;
        unsafe { gl::GetIntegerv(gl::CONTEXT_PROFILE_MASK, &mut profile_mask); }
        let profile = if profile_mask & gl::CONTEXT_CORE_PROFILE_BIT as i32 != 0 {
            GLProfile::Core
        } else if profile_mask & gl::CONTEXT_COMPATIBILITY_PROFILE_BIT as i32 != 0 {
            GLProfile::Compatibility
        } else {
            GLProfile::Unknown
        };

        Self { version, profile }
    }
}

fn parse_version(s: &str) -> (u8, u8) {
    let nums: Vec<u8> = s.split('.')
        .filter_map(|p| p.parse().ok())
        .collect();
    (nums.first().copied().unwrap_or(0), nums.get(1).copied().unwrap_or(0))
}
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业的 OpenGL 使用:

- **macOS**:只支持 OpenGL 4.1 Core(苹果 2010 年后停止更新 OpenGL,推动 Metal)。Mac 版游戏必须 Core
- **Linux**:OpenGL 4.6 Core / Vulkan / DXVK(通过 Proton)
- **Windows**:OpenGL 4.6(厂商驱动)或 DirectX 11/12
- **WebGL / Web**:WebGL 2 ≈ OpenGL ES 3.0,接近 Core 现代风格

**实际工业几乎不用 OpenGL**:
- AAA 游戏用 DirectX(Windows)+ Vulkan(Linux)+ Metal(Mac)
- 移动用 OpenGL ES / Metal / Vulkan
- Web 用 WebGL / WebGPU

**OpenGL 现在的角色**:教学(简单易懂)、跨平台工具(Blender, CAD)、轻量游戏(独立游戏)。Casey 用 OpenGL 是教学取舍。

### 3.2 · 🎨 图形学视角

Core Profile 在图形学上的影响:

**Shader-only 渲染**

Core Profile 强制所有渲染走 shader。这意味着:
- 没有内建的光照(`glLightfv` 删除)
- 没有内建的雾(`glFog` 删除)
- 没有内建的纹理坐标生成(`glTexGen` 删除)
- 所有这些必须自己写 shader

**学习曲线**:Core 让光照、雾、纹理坐标生成都从"开关 API"变成"shader 算法"。这让你必须理解原理。

**性能**:Core Profile 的 driver 状态机简化,状态切换更便宜。特别是:
- 没有 `glPushAttrib` 后,driver 不再维护 attrib stack
- 没有 fixed function pipeline,driver 不必为兼容旧管线做处理

**Modern OpenGL 的"现代"程度**:

| OpenGL 版本 | 引入 | "现代"程度 |
|---|---|---|
| 3.0 (2008) | VAO, Core Profile | ★★★ |
| 3.3 (2010) | 标准化 layout 语法 | ★★★★ |
| 4.0 (2010) | Tessellation shader | ★★★★ |
| 4.3 (2012) | Compute shader, SSBO | ★★★★★ |
| 4.6 (2017) | SPIR-V, anisotropic | ★★★★★ |

Casey 用 3.3 Core,够用于教学和 HH 所有需求。

```rust
unsafe extern "system" fn debug_callback(
    source: GLenum, type_: GLenum, id: GLuint, severity: GLenum,
    length: GLsizei, message: *const GLchar, _user: *mut std::ffi::c_void,
) {
    let msg = std::ffi::CStr::from_ptr(message).to_string_lossy();
    eprintln!("GL debug [{:?}]: {}", severity, msg);
}

// 创建 context 时启用 debug
glfw.window_hint(glfw::WindowHint::OpenGlDebugContext(true));

// 注册 callback
unsafe {
    gl::Enable(gl::DEBUG_OUTPUT);
    gl::DebugMessageCallback(Some(debug_callback), std::ptr::null_mut());
}
```

## 4 · 认知地图

### 4.1 上级

- **OpenGL Context** —— 一组 OpenGL 状态,profile 决定哪些 API 可用
- **Graphics API Generation** —— 一代代演进,Core Profile 是现代版本
- **Driver Implementation** —— Mesa(NVIDIA / AMD / Intel 私有)具体实现 OpenGL spec

### 4.2 同级(并行方案)

| Profile | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| Compatibility Profile | 包含 1992-2008 所有 API | 遗留代码 / 旧软件 | ✕ |
| Core Profile | 仅现代 API | 现代游戏 / 教学 | ✅ |
| Forward Compatible | 进一步去 deprecated | macOS 必需 | ✅ |
| OpenGL ES | 嵌入式 / 移动 | 手机 / Web | 不用 |

### 4.3 下级

- **`glfwWindowHint`** —— GLFW 设置,决定 driver 创建哪种 context
- **GLFW_OPENGL_PROFILE** —— Core / Compatibility 选择
- **GLFW_OPENGL_FORWARD_COMPAT** — Forward Compatible 开关
- **GLFW_CONTEXT_VERSION_MAJOR / MINOR** — OpenGL 版本
- **GLFW_OPENGL_DEBUG_CONTEXT** — Debug context(KHR_debug callback)

## 5 · 对照与变奏

### 同一问题在不同 API 的表达

**问题**:创建现代 GL context。

| API | 现代风格 |
|---|---|
| OpenGL 3.3+ | Core Profile + Forward Compatible |
| OpenGL ES 3.0 | 默认就是"现代",无 profile 区分 |
| Vulkan | 显式 `VkInstance` + `VkDevice`,无 profile 概念 |
| DirectX 11 | 默认"现代",feature level 决定能力 |
| DirectX 12 | 同上 |
| Metal | 默认"现代",苹果独占 |
| WebGPU | 默认"现代",无 profile |

### 历史演化

- **1992**: OpenGL 1.0,只有现在所谓的 Compatibility
- **2008 (OpenGL 3.0)**: 引入 Core / Compatibility 区分,但还能用旧 API
- **2010 (OpenGL 3.3 / 4.0)**: ARB 决定彻底分家,Core 强制现代
- **2010 (Apple)**: 在 macOS 上只支持 OpenGL 4.1 Core,推动"Core only"
- **2015+**: Vulkan 抛弃 OpenGL,完全显式设计

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Core Profile 和 Compatibility Profile 的关键 API 差别是什么?为什么 macOS 只支持 Core?

**参考解答**:

差别:
- **Core Profile**:强制 VAO + shader,删除固定函数管线(`glRotatef`, `glLightfv`, `glPushAttrib`),删除立即模式(`glBegin/glEnd`),删除 display list
- **Compatibility Profile**:包含 Core 全部 + 旧 API

为什么 macOS 只支持 Core:
- 苹果 2010 年宣布 OpenGL 4.1 是 Mac 最后版本,推动自家 Metal API
- 苹果只实现了 Core Profile(因为只关心现代游戏),没实现 Compatibility
- 这迫使 macOS 上的 OpenGL 程序必须用现代 API

历史背景:苹果认为 OpenGL 不再值得投入(2010 年后工业转向 DirectX,Mac 游戏少),Metal 是战略选择。今天 macOS 上的"现代图形"是 Metal,OpenGL 是遗留支持。

### Lv2 · 动手实践

**题**:在 Rust + GLFW 项目里:
1. 设置 OpenGL 3.3 Core + Forward Compatible
2. 启用 Debug Context
3. 注册 KHR_debug callback
4. 故意触发一个 GL 错误(如 `glDrawElements` 没 VAO),看 callback 是否打印错误

**完成标准**:callback 打印 "GL_INVALID_OPERATION" 之类的错误码和描述。

**参考解答**:

```rust
use glfw::{Context, Glfw, Window, WindowEvent, FailOnError};
use gl::types::*;
use std::ffi::CString;

unsafe extern "system" fn debug_callback(
    _source: GLenum,
    type_: GLenum,
    id: GLuint,
    severity: GLenum,
    _length: GLsizei,
    message: *const GLchar,
    _user: *mut std::ffi::c_void,
) {
    let msg = std::ffi::CStr::from_ptr(message).to_string_lossy();
    let type_str = match type_ {
        gl::DEBUG_TYPE_ERROR => "ERROR",
        gl::DEBUG_TYPE_DEPRECATED_BEHAVIOR => "DEPRECATED",
        gl::DEBUG_TYPE_UNDEFINED_BEHAVIOR => "UNDEFINED",
        gl::DEBUG_TYPE_PORTABILITY => "PORTABILITY",
        gl::DEBUG_TYPE_PERFORMANCE => "PERFORMANCE",
        gl::DEBUG_TYPE_OTHER => "OTHER",
        _ => "UNKNOWN",
    };
    let severity_str = match severity {
        gl::DEBUG_SEVERITY_HIGH => "HIGH",
        gl::DEBUG_SEVERITY_MEDIUM => "MEDIUM",
        gl::DEBUG_SEVERITY_LOW => "LOW",
        gl::DEBUG_SEVERITY_NOTIFICATION => "NOTIFY",
        _ => "?",
    };
    eprintln!("GL {} [{} id={}]: {}", type_str, severity_str, id, msg);
}

fn main() {
    let mut glfw = glfw::init(FailOnError).unwrap();

    // OpenGL 3.3 Core + Forward Compatible + Debug
    glfw.window_hint(glfw::WindowHint::ContextVersion(3, 3));
    glfw.window_hint(glfw::WindowHint::OpenGlProfile(
        glfw::OpenGlProfileHint::Core,
    ));
    glfw.window_hint(glfw::WindowHint::OpenGlForwardCompat(true));
    glfw.window_hint(glfw::WindowHint::OpenGlDebugContext(true));
    glfw.window_hint(glfw::WindowHint::Samples(Some(4)));

    let (mut window, events) = glfw
        .create_window(1920, 1080, "Handmade Hero", glfw::WindowMode::Windowed)
        .expect("Failed to create window");
    window.make_current();
    gl::load_with(|s| window.get_proc_address(s) as *const _);

    // 验证 profile
    let mut profile_mask = 0;
    unsafe { gl::GetIntegerv(gl::CONTEXT_PROFILE_MASK, &mut profile_mask); }
    if profile_mask & gl::CONTEXT_CORE_PROFILE_BIT as i32 != 0 {
        println!("Got Core Profile");
    }

    // 注册 debug callback
    unsafe {
        gl::Enable(gl::DEBUG_OUTPUT);
        gl::Enable(gl::DEBUG_OUTPUT_SYNCHRONOUS);
        gl::DebugMessageCallback(Some(debug_callback), std::ptr::null_mut());
        gl::DebugMessageControl(gl::DONT_CARE, gl::DONT_CARE, gl::DONT_CARE,
            0, std::ptr::null(), gl::TRUE);
    }

    // 故意触发错误:DrawElements 不绑定 VAO
    unsafe {
        gl::DrawElements(gl::TRIANGLES, 6, gl::UNSIGNED_INT, std::ptr::null());
        // 应该看到 GL_INVALID_OPERATION callback 打印
    }

    while !window.should_close() {
        glfw.poll_events();
        window.swap_buffers();
    }
}
```

**关键解释**:
- `extern "system"` — Rust ABI,匹配 OpenGL callback 约定(Windows 是 stdcall,其他平台是 cdecl,`system` 自动适配)
- `gl::DEBUG_OUTPUT_SYNCHRONOUS` — 让 callback 在 GL 命令调用时同步触发,而不是延迟。调试时有用,生产关闭(异步快)
- `DebugMessageControl(DONT_CARE, ...)` — 接收所有类型的消息
- callback 里不要做重活(可能在高频调用)

### Rust:完整 Core Profile + Debug Context

```rust
// Cargo.toml: gl = "0.14", glfw = "0.55"

use glfw::{Context, FailOnError, Glfw, Window, WindowEvent};
use gl::types::*;
use std::ffi::CString;
use std::sync::mpsc::Receiver;

unsafe extern "system" fn gl_debug_callback(
    source: GLenum,
    type_: GLenum,
    id: GLuint,
    severity: GLenum,
    _length: GLsizei,
    message: *const GLchar,
    _user: *mut std::ffi::c_void,
) {
    let msg = if message.is_null() {
        String::from("(null)")
    } else {
        std::ffi::CStr::from_ptr(message).to_string_lossy().into_owned()
    };
    let source_str = match source {
        gl::DEBUG_SOURCE_API => "API",
        gl::DEBUG_SOURCE_WINDOW_SYSTEM => "WINDOW_SYSTEM",
        gl::DEBUG_SOURCE_SHADER_COMPILER => "SHADER_COMPILER",
        gl::DEBUG_SOURCE_THIRD_PARTY => "THIRD_PARTY",
        gl::DEBUG_SOURCE_APPLICATION => "APPLICATION",
        _ => "OTHER",
    };
    let type_str = match type_ {
        gl::DEBUG_TYPE_ERROR => "ERROR",
        gl::DEBUG_TYPE_DEPRECATED_BEHAVIOR => "DEPRECATED",
        gl::DEBUG_TYPE_UNDEFINED_BEHAVIOR => "UNDEFINED",
        gl::DEBUG_TYPE_PORTABILITY => "PORTABILITY",
        gl::DEBUG_TYPE_PERFORMANCE => "PERFORMANCE",
        gl::DEBUG_TYPE_MARKER => "MARKER",
        _ => "OTHER",
    };
    let severity_str = match severity {
        gl::DEBUG_SEVERITY_HIGH => "HIGH",
        gl::DEBUG_SEVERITY_MEDIUM => "MEDIUM",
        gl::DEBUG_SEVERITY_LOW => "LOW",
        gl::DEBUG_SEVERITY_NOTIFICATION => "NOTIFY",
        _ => "?",
    };
    eprintln!(
        "GL callback [source={} type={} severity={} id={}]: {}",
        source_str, type_str, severity_str, id, msg
    );
}

pub struct GLWindow {
    glfw: Glfw,
    window: Window,
    events: Receiver<(f64, WindowEvent)>,
    version: (u8, u8),
}

impl GLWindow {
    pub fn new(width: u32, height: u32, title: &str) -> Self {
        let mut glfw = glfw::init(FailOnError).unwrap();

        // OpenGL 3.3 Core Profile + Forward Compatible + Debug
        glfw.default_window_hints();
        glfw.window_hint(glfw::WindowHint::ContextVersion(3, 3));
        glfw.window_hint(glfw::WindowHint::OpenGlProfile(
            glfw::OpenGlProfileHint::Core,
        ));
        glfw.window_hint(glfw::WindowHint::OpenGlForwardCompat(true));
        glfw.window_hint(glfw::WindowHint::OpenGlDebugContext(true));
        glfw.window_hint(glfw::WindowHint::Samples(Some(4)));
        glfw.window_hint(glfw::WindowHint::SRgbCapable(true));
        glfw.window_hint(glfw::WindowHint::DoubleBuffer(true));

        let (window, events) = glfw
            .create_window(width, height, title, glfw::WindowMode::Windowed)
            .expect("Failed to create GLFW window");

        window.make_current();
        window.set_key_polling(true);
        gl::load_with(|s| window.get_proc_address(s) as *const _);

        // 验证版本
        let version_str = unsafe {
            std::ffi::CStr::from_ptr(gl::GetString(gl::VERSION) as *const i8)
                .to_string_lossy()
                .into_owned()
        };
        println!("GL Version: {}", version_str);

        let mut profile_mask = 0;
        unsafe { gl::GetIntegerv(gl::CONTEXT_PROFILE_MASK, &mut profile_mask); }
        let is_core = profile_mask & gl::CONTEXT_CORE_PROFILE_BIT as i32 != 0;
        println!("Profile: {}", if is_core { "Core" } else { "Compatibility" });

        // 注册 debug callback
        unsafe {
            gl::Enable(gl::DEBUG_OUTPUT);
            gl::Enable(gl::DEBUG_OUTPUT_SYNCHRONOUS);
            gl::DebugMessageCallback(Some(gl_debug_callback), std::ptr::null_mut());
            gl::DebugMessageControl(
                gl::DONT_CARE, gl::DONT_CARE, gl::DONT_CARE,
                0, std::ptr::null(), gl::TRUE,
            );
        }

        Self {
            glfw, window, events,
            version: (3, 3),
        }
    }

    pub fn poll(&mut self) -> impl Iterator<Item = WindowEvent> {
        self.glfw.poll_events();
        self.events.try_iter().map(|(_, e)| e)
    }

    pub fn swap(&mut self) {
        self.window.swap_buffers();
    }

    pub fn should_close(&self) -> bool {
        self.window.should_close()
    }
}

fn main() {
    let mut gl_window = GLWindow::new(1920, 1080, "Handmade Hero - Core Profile");

    // 初始化时检查状态
    unsafe {
        gl::Enable(gl::DEPTH_TEST);
        gl::Enable(gl::CULL_FACE);
        gl::CullFace(gl::BACK);
        gl::FrontFace(gl::CCW);
    }

    println!("Entering render loop");

    while !gl_window.should_close() {
        for event in gl_window.poll() {
            if let glfw::WindowEvent::Key(glfw::Key::Escape, _, _, _) = event {
                gl_window.window.set_should_close(true);
            }
        }

        unsafe {
            gl::ClearColor(0.1, 0.1, 0.15, 1.0);
            gl::Clear(gl::COLOR_BUFFER_BIT | gl::DEPTH_BUFFER_BIT);
            // 渲染立方体等
        }

        gl_window.swap();
    }
}
```

**Troubleshooting**:

- **`glfwCreateWindow returned NULL`** — 要求的 OpenGL 版本/profile 不支持。降低版本(3.3 → 3.0)或检查驱动
- **运行时错误 "no VAO bound"** — Core Profile 必须 VAO,加 `glBindVertexArray`
- **macOS 黑屏** — Forward Compatible 没开,Mac 拒绝 context
- **Debug callback 没触发** — `glEnable(gl::DEBUG_OUTPUT)` 漏了,或 driver 不支持(KHR_debug 是 4.3+ 才有,可能要扩展)
- **程序运行慢** — Debug context 比 Release 慢 10-30%(driver 做额外验证),发布版本关闭
