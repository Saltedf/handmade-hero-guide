# Day 334 · 加加速板

> 玩家踩到地上的特殊方块(boost pad)时被加速,这是 platformer / 赛车游戏的经典机制。今天 Casey 实现这种"触发式方块"——entity 走过时修改其速度。

## 0 · 为什么要有这一天

到目前为止你的游戏世界里 entity 自由移动,没有"地形影响移动"的机制。但很多游戏需要:

- **加速板**(boost pad):踩到时玩家速度增加(Mario Kart 的加速带)
- **减速板**(slow pad):踩到时减速(Mario 的泥地)
- **传送门**(portal):踩到时瞬移到另一位置
- **跳跃板**(jump pad):踩到时弹起
- **冰面**(ice):踩到时摩擦力低

这些都是 **"trigger volume"** —— 玩家进入某区域时触发效果。今天的 Casey 实现 boost pad,作为 trigger volume 的最简单例子。

实现思路:

1. 给世界加"特殊方块"tile type
2. 玩家每帧检查脚下 tile 是否是 boost pad
3. 是则修改玩家速度(加上 boost 方向 × boost 力)

```c
void update_player(entity *player, world *world, float dt) {
    // 移动(正常物理)
    player->pos += player->vel * dt;
    
    // 检查脚下 tile
    tile_id tile = get_tile_at(world, player->pos);
    if (tile == TILE_BOOST_PAD) {
        // 加速:把 vel 加上 boost 方向
        v2 boost_dir = get_boost_dir(world, player->pos);
        float boost_force = 50.0;  // 加速度
        player->vel += boost_dir * boost_force * dt;
    }
}
```

这种"每帧检查 + 应用效果"的设计是 trigger volume 的核心。今天 Casey 实现完整版,包括:

- boost pad tile 的视觉(箭头纹理)
- boost 方向(8 个方向:上下左右 + 对角)
- 持续加速 vs 一次性加速

心理锚点:今天之后你的游戏支持"地形影响移动",可以设计跳跃谜题、加速赛道等。这是 platformer 的核心机制。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_world.cpp` 和 `handmade_entity.cpp`,加 boost pad 支持。

具体动作:

1. 给 tile 类型加 `TILE_BOOST_PAD`
2. 每个 boost pad tile 存一个"boost 方向"(2D 向量)
3. 玩家 update 时检查脚下 tile,是 boost pad 则应用加速度

```c
typedef enum {
    TILE_EMPTY,
    TILE_WALL,
    TILE_FLOOR,
    TILE_BOOST_PAD,
    // ...
} tile_type;

typedef struct {
    tile_type type;
    v2 boost_direction;  // 只对 boost pad 有效
    // ... 其他 per-tile 数据
} tile;

void update_player(entity *player, world *world, float dt) {
    // 应用玩家输入
    v2 input = get_player_input();
    player->vel += input * PLAYER_ACCEL * dt;
    
    // 移动
    player->pos += player->vel * dt;
    
    // 碰撞(撞墙停止)
    handle_collisions(player, world);
    
    // 检查 boost pad
    tile *t = get_tile_at(world, (int)player->pos.x, (int)player->pos.y);
    if (t && t->type == TILE_BOOST_PAD) {
        // 持续加速(玩家在 pad 上时每帧加 boost)
        float boost_force = 200.0;  // 加速度
        player->vel += t->boost_direction * boost_force * dt;
    }
    
    // 摩擦(地面阻力)
    player->vel *= 0.95;  // 简化摩擦
}
```

Casey 在视频里讨论了几个细节:

1. **持续 vs 一次性**:持续(每帧加 boost)适合长加速带;一次性(进入瞬间 boost)适合跳板。Casey 选持续。
2. **boost 方向**:可以指向任意方向(8 个方向 + 中间),boost pad 视觉显示方向(箭头)
3. **限制最大速度**:防止 boost 无限加速,加 `MAX_SPEED` clamp

```c
float speed = length(player->vel);
if (speed > MAX_SPEED) {
    player->vel = player->vel * (MAX_SPEED / speed);
}
```

Casey 还讨论了**视觉反馈**——玩家在 boost pad 上时显示粒子特效,让玩家清楚"我在加速"。这是游戏 feel 的重要细节。

## 2 · 心智模型

### 类比:机场传送带

把 boost pad 想象成机场的加速传送带。

- 普通地面:你自己走,速度 = 走速
- 加速带:你在带上,带子额外推动你,速度 = 走速 + 带速

每帧玩家在 boost pad 上时,带子加一个推力,玩家速度变快。离开带子,推力消失,玩家逐渐减速(摩擦)。

### 严谨原理:物理力学

boost pad 应用加速度(不是直接设速度):

```
F = m × a          (牛顿第二定律)
a = F / m          (加速度 = 力 / 质量)

每帧速度变化:
v_new = v_old + a × dt
```

在 boost pad 上时,a = boost_direction × boost_force,所以:

```
v_new = v_old + boost_direction × boost_force × dt
```

这种"应用力"而非"直接设速度"的好处:

1. **物理真实**:玩家速度不能瞬变,需要时间累积
2. **叠加自然**:多个 boost pad 同时作用,效果叠加
3. **摩擦抵抗**:地面摩擦让玩家不会无限加速

### 8 方向 boost

boost_direction 通常是 8 个方向之一(水平 + 垂直 + 对角):

```c
v2 BOOST_DIRECTIONS[8] = {
    { 1,  0}, {-1,  0},   // 左右
    { 0,  1}, { 0, -1},   // 上下
    { 1,  1}, {-1,  1},   // 右上,左上
    { 1, -1}, {-1, -1},   // 右下,左下
};
```

每个方向归一化(长度 1),乘以 boost_force 得到实际加速度。

### Rust 实现

```rust
#[derive(Clone, Copy, PartialEq)]
enum TileType {
    Empty,
    Wall,
    Floor,
    BoostPad,
}

#[derive(Clone, Copy)]
struct Tile {
    tile_type: TileType,
    boost_dir: Vec2,  // 只在 BoostPad 时有意义
}

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn length(self) -> f32 {
        (self.x*self.x + self.y*self.y).sqrt()
    }
    fn normalize(self) -> Self {
        let len = self.length();
        if len > 0.0 { Self { x: self.x/len, y: self.y/len } }
        else { Self { x: 0.0, y: 0.0 } }
    }
}

impl std::ops::Add for Vec2 {
    type Output = Self;
    fn add(self, o: Self) -> Self { Self { x: self.x+o.x, y: self.y+o.y } }
}

impl std::ops::Mul<f32> for Vec2 {
    type Output = Self;
    fn mul(self, s: f32) -> Self { Self { x: self.x*s, y: self.y*s } }
}

impl std::ops::AddAssign for Vec2 {
    fn add_assign(&mut self, o: Self) { self.x += o.x; self.y += o.y; }
}

struct World {
    tiles: Vec<Tile>,  // 二维 grid 展平
    width: usize,
    height: usize,
}

impl World {
    fn get_tile(&self, x: i32, y: i32) -> Option<&Tile> {
        if x < 0 || y < 0 { return None; }
        let (x, y) = (x as usize, y as usize);
        if x >= self.width || y >= self.height { return None; }
        Some(&self.tiles[y * self.width + x])
    }
}

struct Player {
    pos: Vec2,
    vel: Vec2,
}

const PLAYER_ACCEL: f32 = 50.0;
const BOOST_FORCE: f32 = 200.0;
const FRICTION: f32 = 0.95;
const MAX_SPEED: f32 = 100.0;

impl Player {
    fn update(&mut self, world: &World, input: Vec2, dt: f32) {
        // 输入加速度
        self.vel += input * PLAYER_ACCEL * dt;
        
        // 移动
        self.pos += self.vel * dt;
        
        // Boost pad
        let tile_x = self.pos.x as i32;
        let tile_y = self.pos.y as i32;
        if let Some(tile) = world.get_tile(tile_x, tile_y) {
            if tile.tile_type == TileType::BoostPad {
                self.vel += tile.boost_dir * BOOST_FORCE * dt;
            }
        }
        
        // 摩擦
        self.vel = self.vel * FRICTION.powf(dt * 60.0);  // 帧率独立
        
        // 限制最大速度
        let speed = self.vel.length();
        if speed > MAX_SPEED {
            self.vel = self.vel * (MAX_SPEED / speed);
        }
    }
}
```

`FRICTION.powf(dt * 60.0)` 是"帧率独立摩擦" —— `0.95` 在 60 fps 下每帧 ×0.95。如果 dt = 1/120(120 fps),则 `0.95^(1/120 × 60) = 0.95^0.5 ≈ 0.974`,所以 120 fps 每帧 ×0.974,效果等同。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

trigger volume 的几个变体:

- **trigger area**:进入区域触发(今天的 boost pad)
- **trigger direction**:必须从特定方向触发(单向门)
- **trigger condition**:有特定 item 才触发(锁着的门)
- **trigger repeat**:可重复 vs 一次性(陷阱)

主流游戏的 trigger volume:

- Mario:各种 tile 类型(冰、沙、加速、跳板)
- Sonic:loop-de-loop 触发器(从特定方向冲过)
- Portal:传送门触发(进入 = 瞬移)

游戏行业用 **collision layer** 区分"物理碰撞"和"trigger":

- 物理层:撞墙停止
- Trigger 层:进入触发,不阻挡移动

Unity / Unreal 都有 trigger 概念,今天 Casey 的实现是手写版。

### 3.2 · 🐧 Linux 系统编程视角

Linux 的 "trigger" 概念:

- **inotify**:文件变化触发回调
- **udev events**:设备插拔触发
- **timerfd**:定时触发
- **signal**:进程间触发

```c
// Linux inotify:监听文件变化(类似 trigger)
int fd = inotify_init();
inotify_add_watch(fd, "/path", IN_MODIFY);
// 文件被修改时,read fd 得到事件
```

这些机制都和今天的 boost pad 同构——"某种条件触发动作"。区别只是 trigger 在 OS 层(文件变化)还是游戏层(玩家位置)。

### 3.3 · 🦀 Rust 生态视角

Rust 表达 trigger volume:

```rust
// 用 trait 表达"可触发的 tile"
trait TileEffect {
    fn apply(&self, player: &mut Player, dt: f32);
}

struct BoostPad { dir: Vec2, force: f32 }
impl TileEffect for BoostPad {
    fn apply(&self, player: &mut Player, dt: f32) {
        player.vel += self.dir * self.force * dt;
    }
}

struct Ice { friction: f32 }
impl TileEffect for Ice {
    fn apply(&self, player: &mut Player, dt: f32) {
        // 降低摩擦
    }
}

// tile 存 Box<dyn TileEffect>
struct Tile {
    effect: Option<Box<dyn TileEffect>>,
}
```

`Box<dyn Trait>` 是 Rust 的动态分发——运行时根据具体类型调用对应方法。代价是 vtable 查找(几纳秒),但代码简洁。

更高效的方式是 **enum dispatch**:

```rust
enum TileEffect {
    BoostPad { dir: Vec2, force: f32 },
    Ice { friction: f32 },
    None,
}

impl TileEffect {
    fn apply(&self, player: &mut Player, dt: f32) {
        match self {
            Self::BoostPad { dir, force } => player.vel += *dir * *force * dt,
            Self::Ice { friction } => { /* ... */ },
            Self::None => {}
        }
    }
}
```

`match` 编译成跳表,比 vtable 快。Casey 在 C 里用 enum,Rust 翻译也推荐 enum。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 boost pad 应用"加速度"而不是直接"设速度"?给出至少 2 个理由。

**参考解答**:

1. **物理真实**:加速度让速度逐渐增加,玩家感觉到"被推动"而非"瞬移"。直接设速度会突兀。
2. **叠加自然**:多个 boost pad 同时作用时,加速度叠加。直接设速度需要决定哪个胜出。
3. **摩擦抵抗**:加速度 + 摩擦力平衡后达到稳定速度,玩家不会无限加速。直接设速度会忽略摩擦。
4. **方向冲突**:玩家向右走 + boost 向左推,加速度让玩家减速→停止→反向。直接设速度需要"哪种方向胜出"决策。

### Lv2 · 动手实践

**题**:在 Rust 里实现 boost pad 系统,要求:

- World 是 16×16 tile grid,有 BoostPad tile
- Player 移动 + boost + 摩擦
- 测试:玩家踩 boost pad 后速度逐渐增加

**参考解答**:

```rust
#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn length(self) -> f32 { (self.x*self.x + self.y*self.y).sqrt() }
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
}

impl std::ops::AddAssign for Vec2 {
    fn add_assign(&mut self, o: Self) { self.x += o.x; self.y += o.y; }
}
impl std::ops::Add for Vec2 {
    type Output = Self;
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
}
impl std::ops::Mul<f32> for Vec2 {
    type Output = Self;
    fn mul(self, s: f32) -> Self { Self { x: self.x * s, y: self.y * s } }
}

#[derive(Clone, Copy)]
enum Tile { Floor, BoostPad(Vec2) }

struct World {
    tiles: Vec<Tile>,
    width: usize,
}

impl World {
    fn new() -> Self {
        let mut tiles = vec![Tile::Floor; 16 * 16];
        // 放几个 boost pad
        tiles[5 * 16 + 5] = Tile::BoostPad(Vec2::new(1.0, 0.0));  // 向右 boost
        tiles[5 * 16 + 6] = Tile::BoostPad(Vec2::new(1.0, 0.0));
        tiles[5 * 16 + 7] = Tile::BoostPad(Vec2::new(1.0, 0.0));
        Self { tiles, width: 16 }
    }
    
    fn get(&self, x: usize, y: usize) -> Tile {
        self.tiles[y * self.width + x]
    }
}

struct Player { pos: Vec2, vel: Vec2 }

const DT: f32 = 1.0 / 60.0;
const BOOST_FORCE: f32 = 100.0;
const FRICTION: f32 = 0.95;
const MAX_SPEED: f32 = 50.0;

impl Player {
    fn update(&mut self, world: &World) {
        // Boost
        let tx = self.pos.x as usize;
        let ty = self.pos.y as usize;
        if tx < 16 && ty < 16 {
            if let Tile::BoostPad(dir) = world.get(tx, ty) {
                self.vel += dir * BOOST_FORCE * DT;
            }
        }
        
        // 摩擦
        self.vel = self.vel * FRICTION;
        
        // 限速
        let speed = self.vel.length();
        if speed > MAX_SPEED {
            self.vel = self.vel * (MAX_SPEED / speed);
        }
        
        // 移动
        self.pos += self.vel * DT;
    }
}

fn main() {
    let world = World::new();
    let mut player = Player { 
        pos: Vec2::new(5.5, 5.5),  // 在 boost pad 上
        vel: Vec2::new(0.0, 0.0),
    };
    
    for frame in 0..120 {
        player.update(&world);
        if frame % 10 == 0 {
            println!("[{:3}] pos=({:6.2},{:6.2}) vel=({:7.2},{:7.2}) speed={:6.2}",
                     frame, player.pos.x, player.pos.y, 
                     player.vel.x, player.vel.y, player.vel.length());
        }
    }
}
```

预期:玩家速度逐渐增加(每帧 +100/60 ≈ 1.67),直到 MAX_SPEED=50 后保持。

## 8 · Rust / Arch 落地代码

### Rust:完整 boost pad 系统(可跑)

```rust
// Cargo.toml: 无依赖
// src/main.rs

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn length(self) -> f32 { (self.x*self.x + self.y*self.y).sqrt() }
    fn normalized(self) -> Self {
        let len = self.length();
        if len > 1e-9 { Self { x: self.x/len, y: self.y/len } }
        else { Self { x: 0.0, y: 0.0 } }
    }
}

impl std::ops::Add for Vec2 {
    type Output = Self;
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
}
impl std::ops::AddAssign for Vec2 {
    fn add_assign(&mut self, o: Self) { self.x += o.x; self.y += o.y; }
}
impl std::ops::Mul<f32> for Vec2 {
    type Output = Self;
    fn mul(self, s: f32) -> Self { Self { x: self.x * s, y: self.y * s } }
}

#[derive(Clone, Copy)]
enum Tile {
    Floor,
    Wall,
    BoostPad(Vec2),  // 加速方向
    Ice,
}

struct World {
    tiles: Vec<Tile>,
    width: usize,
    height: usize,
}

impl World {
    fn new(width: usize, height: usize) -> Self {
        let mut tiles = vec![Tile::Floor; width * height];
        // 加一面墙
        for y in 0..height {
            tiles[y * width + 0] = Tile::Wall;
            tiles[y * width + width - 1] = Tile::Wall;
        }
        // 加 boost pad(向右)
        let by = height / 2;
        for bx in 3..6 {
            tiles[by * width + bx] = Tile::BoostPad(Vec2::new(1.0, 0.0));
        }
        // 加冰面
        let iy = height / 2 + 2;
        for ix in 8..12 {
            tiles[iy * width + ix] = Tile::Ice;
        }
        Self { tiles, width, height }
    }
    
    fn get(&self, x: i32, y: i32) -> Tile {
        if x < 0 || y < 0 || x as usize >= self.width || y as usize >= self.height {
            return Tile::Wall;
        }
        self.tiles[y as usize * self.width + x as usize]
    }
}

struct Player {
    pos: Vec2,
    vel: Vec2,
    on_boost: bool,
    on_ice: bool,
}

const DT: f32 = 1.0 / 60.0;
const MOVE_ACCEL: f32 = 30.0;
const BOOST_FORCE: f32 = 80.0;
const NORMAL_FRICTION: f32 = 0.85;
const ICE_FRICTION: f32 = 0.99;
const MAX_SPEED: f32 = 30.0;

impl Player {
    fn update(&mut self, world: &World, input: Vec2) {
        // 输入加速
        self.vel += input * MOVE_ACCEL * DT;
        
        // 当前 tile
        let tx = self.pos.x as i32;
        let ty = self.pos.y as i32;
        let tile = world.get(tx, ty);
        
        // 应用 tile 效果
        self.on_boost = false;
        self.on_ice = false;
        match tile {
            Tile::BoostPad(dir) => {
                self.vel += dir * BOOST_FORCE * DT;
                self.on_boost = true;
            }
            Tile::Ice => {
                self.on_ice = true;
            }
            _ => {}
        }
        
        // 摩擦
        let friction = if self.on_ice { ICE_FRICTION } else { NORMAL_FRICTION };
        self.vel = self.vel * friction;
        
        // 限速
        let speed = self.vel.length();
        if speed > MAX_SPEED {
            self.vel = self.vel * (MAX_SPEED / speed);
        }
        
        // 移动
        self.pos += self.vel * DT;
    }
}

fn main() {
    println!("=== Day 334: 加速板系统 ===\n");
    
    let world = World::new(20, 10);
    let mut player = Player { 
        pos: Vec2::new(3.5, 5.5),  // 在 boost pad 上
        vel: Vec2::new(0.0, 0.0),
        on_boost: false,
        on_ice: false,
    };
    
    // 模拟玩家不输入(纯 boost 推)
    let no_input = Vec2::new(0.0, 0.0);
    
    println!("初始: pos={:?} vel={:?}", player.pos, player.vel);
    println!();
    
    for frame in 0..180 {
        player.update(&world, no_input);
        if frame % 20 == 0 {
            let state = if player.on_boost { "[BOOST]" } 
                        else if player.on_ice { "[ICE]" } 
                        else { "" };
            println!("[{:3}] pos=({:6.2},{:6.2}) vel=({:7.2},{:7.2}) speed={:6.2} {}",
                     frame, player.pos.x, player.pos.y, 
                     player.vel.x, player.vel.y, player.vel.length(), state);
        }
    }
    
    println!("\n--- 测试玩家手动加速离开 boost pad ---");
    
    // 玩家持续向右输入(模拟)
    let right_input = Vec2::new(1.0, 0.0);
    for frame in 180..240 {
        player.update(&world, right_input);
        if frame % 10 == 0 {
            let state = if player.on_boost { "[BOOST]" } 
                        else if player.on_ice { "[ICE]" } 
                        else { "" };
            println!("[{:3}] pos=({:6.2},{:6.2}) speed={:6.2} {}",
                     frame, player.pos.x, player.pos.y, player.vel.length(), state);
        }
    }
}
```

## 10 · 深度补充:工程视角

Trigger volume 的物理引擎实现:Box2D / Rapier / PhysX 都有 sensor volume 概念。Sensor 是 只检测碰撞但不响应物理 的物体。Casey 的 boost pad 等价于 sensor——检测玩家进入但不阻挡。物理引擎优化:broad phase(AABB 树快速剔除远物体)+ narrow phase(精确碰撞检测)。Casey 用 tile grid 做 broad phase,简单高效。
