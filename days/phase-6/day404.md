# Day 404 · 体素索引的光照样本

> Day 403 的 per-vertex 反射器在**顶点之间插值**,精度有限。今天 Casey 升级到 **per-pixel**——用体素网格作为**3D 光照样本**,每像素独立采样。这是 voxel GI 的标准做法,比 per-vertex 精确。

## 0 · 为什么要有这一天

Per-vertex 插值的问题:三角形跨越**亮度差异大的区域**(角落 vs 开阔)时,插值得到中间值,细节丢失。比如三角形的三个顶点分别在亮、中、暗三个区域,中间的 fragment 得到"平均",但真实可能"角落很暗"。

**Per-pixel 方案**:每像素独立采样 3D 纹理(voxel grid),不依赖顶点插值。

**实现**:

1. 体素网格作为 3D 纹理(`sampler3D`)
2. 每像素的 fragment shader 用**像素的 world position** 采样 3D 纹理
3. 返回该位置的间接光

这是 Day 396 GI 渲染的核心——但今天 Casey **更系统地**讲:**体素索引**——如何高效地用体素网格索引光照样本,以及优化(SIMD、cache、mipmap)。

**今天的产出**:per-pixel GI 采样,光照精度提升。角落和边缘的暗化清晰可见,不再被顶点插值模糊。

心理锚点:看完今天,你能(1)解释 per-vertex vs per-pixel 的差别;(2)用 world position 索引 3D 纹理;(3)优化采样性能;(4)理解 mipmap 在 GI 上的应用。

## 2 · 心智模型

### 类比:地图分辨率

低分辨率地图(每 10km 一个数据点):你看不到小巷子。高分辨率地图(每 10m 一个点):每个角落都清楚。

per-vertex GI 是低分辨率(顶点之间平均)。per-pixel GI 是高分辨率(每像素独立)。

### 严谨原理:3D 纹理采样(回顾)

Day 396 已经讲过 3D 纹理采样。今天补充优化和细节。

**基本采样**:

```glsl
uniform sampler3D voxel_light;
uniform vec3 grid_min;
uniform vec3 grid_extent;

vec3 sample_gi(vec3 world_pos) {
    vec3 uvw = (world_pos - grid_min) / grid_extent;
    return texture(voxel_light, uvw).rgb;
}
```

**自动三线性插值**:GPU 硬件做 8 邻居加权平均,返回连续值。

### Mipmap 3D 纹理

3D 纹理可以生成 mipmap——多级分辨率。每个 mipmap level 是上一级的一半:

- Level 0:64³(全分辨率)
- Level 1:32³
- Level 2:16³
- Level 3:8³

**采样时**:GPU 根据**像素在屏幕上的密度**自动选 LOD。远处物体用低 LOD(省采样),近处用高 LOD(细节)。

**生成 mipmap**:

```rust
// glium 自动生成
let voxel_texture = Texture3D::with_format(
    &display, /*...*/,
    MipmapsOption::AutoGeneratedMipmaps,  // 自动
)?;
```

或在 shader 里手动(更精确):

```glsl
// Manual mipmap generation(每级 compute shader)
layout(binding = 0, rgba32f) readonly uniform image3D src_level;
layout(binding = 1, rgba32f) writeonly uniform image3D dst_level;
void main() {
    ivec3 dst = ivec3(gl_GlobalInvocationID);
    ivec3 src0 = dst * 2;
    vec4 sum = vec4(0.0);
    for (int dz = 0; dz < 2; ++dz) {
        for (int dy = 0; dy < 2; ++dy) {
            for (int dx = 0; dx < 2; ++dx) {
                sum += imageLoad(src_level, src0 + ivec3(dx, dy, dz));
            }
        }
    }
    imageStore(dst_level, dst, sum / 8.0);
}
```

### Texture Compression(进阶)

3D 纹理占显存大(64³ × RGBA32F = 4 MB,加 mipmap = 5.3 MB)。**压缩**:

- **BC6H**:HDR 浮点压缩,6:1 比例,质量好
- **BC7**:LDR 压缩,3:1
- **ASTC**:跨平台,可变比特率

```rust
let voxel_texture_compressed = Texture3D::with_format(
    &display,
    /* ... */,
    CompressedFloatFormat::BC6H_UF16,  // 压缩
)?;
```

代价:压缩 / 解压有精度损失。

### Sampler cache optimization

3D 纹理采样比 2D 慢(8 邻居 vs 4)。优化:

- **减少采样次数**:合并多次采样为一次
- **Coherent access**:相邻像素采样相邻 texel,cache hit 高
- **LOD bias**:远处用低 LOD,减少采样细节

### Per-pixel GI shader 完整

```glsl
#version 330

in vec3 v_world_position;
in vec3 v_world_normal;
in vec2 v_uv;

uniform sampler3D voxel_light;  // 体素光照(带 mipmap)
uniform sampler2D albedo_tex;
uniform vec3 grid_min;
uniform vec3 grid_extent;
uniform vec3 grid_voxel_size;

uniform vec3 light_dir;
uniform vec3 light_color;
uniform vec3 ambient_color;
uniform vec3 camera_pos;
uniform vec3 specular_color;
uniform float shininess;

uniform sampler3D shadow_texture;
uniform sampler3D ao_texture;

out vec4 frag;

void main() {
    // 基础属性
    vec3 albedo = texture(albedo_tex, v_uv).rgb;
    vec3 N = normalize(v_world_normal);
    vec3 L = normalize(light_dir);
    vec3 V = normalize(camera_pos - v_world_position);
    vec3 R = reflect(-L, N);

    // Phong
    float diff = max(0.0, dot(N, L));
    float spec = pow(max(0.0, dot(R, V)), shininess);
    vec3 ambient = albedo * ambient_color;
    vec3 diffuse = albedo * light_color * diff;
    vec3 specular = specular_color * light_color * spec;

    // 体素空间坐标
    vec3 uvw = (v_world_position - grid_min) / grid_extent;

    // Per-pixel GI 采样
    vec3 gi_light = texture(voxel_light, uvw).rgb;
    vec3 gi = albedo * gi_light;

    // Per-pixel AO 采样
    float ao = texture(ao_texture, uvw).r;

    // Per-pixel shadow 采样
    float shadow = texture(shadow_texture, uvw).r;

    // 合成
    vec3 direct = ambient + (diffuse + specular) * shadow;
    vec3 indirect = gi * ao;
    vec3 final = direct + indirect;

    // Tone map + sRGB
    final = final / (final + vec3(1.0));
    frag = vec4(final, 1.0);
}
```

**关键改进**:

- GI、AO、shadow 都 per-pixel 采样(三线性)
- 直接光 + 间接光分开
- Tone map

### Per-vertex vs Per-pixel 对比

| | Per-vertex | Per-pixel |
|---|---|---|
| 精度 | 顶点级(低) | 像素级(高) |
| 显存 | 顶点 attribute | 3D 纹理 |
| 速度 | 快(顶点 shader 一次) | 中(每像素采样) |
| 适合 | 低面数 | 高面数 / 复杂 |

工业界 per-pixel 主流(质量优先)。

```rust
pub fn sample_voxel_light_safe(
    grid: &VoxelGrid,
    pos: Vec3,
) -> Vec3 {
    let rel = (pos - grid.origin) / grid.voxel_size;
    if rel.x < 0.0 || rel.y < 0.0 || rel.z < 0.0
        || rel.x >= grid.dims.0 as f32
        || rel.y >= grid.dims.1 as f32
        || rel.z >= grid.dims.2 as f32 {
        return Vec3::ZERO;  // 网格外
    }
    let x = rel.x as u32;
    let y = rel.y as u32;
    let z = rel.z as u32;
    let idx = (z * grid.dims.0 * grid.dims.1 + y * grid.dims.0 + x) as usize;
    Vec3::from(grid.voxels[idx].light)
}

/// Trilinear sample(更准确)
pub fn sample_voxel_light_trilinear(
    grid: &VoxelGrid,
    pos: Vec3,
) -> Vec3 {
    let rel = (pos - grid.origin) / grid.voxel_size;
    let x0 = rel.x.floor().max(0.0) as u32;
    let y0 = rel.y.floor().max(0.0) as u32;
    let z0 = rel.z.floor().max(0.0) as u32;
    let x1 = (x0 + 1).min(grid.dims.0 - 1);
    let y1 = (y0 + 1).min(grid.dims.1 - 1);
    let z1 = (z0 + 1).min(grid.dims.2 - 1);
    let u = rel.x - x0 as f32;
    let v = rel.y - y0 as f32;
    let w = rel.z - z0 as f32;
    let get = |x: u32, y: u32, z: u32| {
        let idx = (z * grid.dims.0 * grid.dims.1 + y * grid.dims.0 + x) as usize;
        Vec3::from(grid.voxels[idx].light)
    };
    let lerp = |a: Vec3, b: Vec3, t: f32| a + (b - a) * t;
    let c00 = lerp(get(x0, y0, z0), get(x1, y0, z0), u);
    let c10 = lerp(get(x0, y1, z0), get(x1, y1, z0), u);
    let c01 = lerp(get(x0, y0, z1), get(x1, y0, z1), u);
    let c11 = lerp(get(x0, y1, z1), get(x1, y1, z1), u);
    let c0 = lerp(c00, c10, v);
    let c1 = lerp(c01, c11, v);
    lerp(c0, c1, w)
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:per-vertex 和 per-pixel 在三角形覆盖"明暗交界处"时,差异最大。具体说明。

**参考解答**:

假设三角形跨越角落(暗)和开阔地(亮):

- 顶点 A:在开阔地(亮,light=1.0)
- 顶点 B:在角落(暗,light=0.2)
- 顶点 C:中间(中,light=0.6)

**Per-vertex**:fragment shader 接收三顶点的重心插值,靠近 B 的 fragment 得到 ~0.3。但**实际**该 fragment 可能在 B 附近的开阔地,真实 light = 0.9,误差 0.6。

**Per-pixel**:fragment shader 用自己的 world position 采样 3D 纹理,直接得到 ~0.9(准确)。

差异:per-vertex 把三角形内的所有 fragment "平均化",per-pixel 各自准确。复杂场景(明暗变化大)per-pixel 优势明显。

```rust
use glam::Vec3;

pub struct VoxelGrid {
    pub dims: (u32, u32, u32),
    pub voxel_size: f32,
    pub origin: Vec3,
    pub voxels: Vec<Voxel>,
}

#[derive(Copy, Clone, Default)]
pub struct Voxel {
    pub light: [f32; 3],
    pub albedo: [f32; 3],
}

impl VoxelGrid {
    pub fn idx(&self, x: u32, y: u32, z: u32) -> usize {
        (z * self.dims.0 * self.dims.1 + y * self.dims.0 + x) as usize
    }

    pub fn sample_trilinear(&self, pos: Vec3) -> Vec3 {
        let rel = (pos - self.origin) / self.voxel_size;
        if rel.x < 0.0 || rel.y < 0.0 || rel.z < 0.0
            || rel.x >= self.dims.0 as f32 - 1.0
            || rel.y >= self.dims.1 as f32 - 1.0
            || rel.z >= self.dims.2 as f32 - 1.0 {
            return Vec3::ZERO;
        }
        let x0 = rel.x as u32;
        let y0 = rel.y as u32;
        let z0 = rel.z as u32;
        let x1 = x0 + 1;
        let y1 = y0 + 1;
        let z1 = z0 + 1;
        let u = rel.x - x0 as f32;
        let v = rel.y - y0 as f32;
        let w = rel.z - z0 as f32;
        let get = |x, y, z| Vec3::from(self.voxels[self.idx(x, y, z)].light);
        let lerp = |a: Vec3, b: Vec3, t: f32| a + (b - a) * t;
        let c00 = lerp(get(x0, y0, z0), get(x1, y0, z0), u);
        let c10 = lerp(get(x0, y1, z0), get(x1, y1, z0), u);
        let c01 = lerp(get(x0, y0, z1), get(x1, y0, z1), u);
        let c11 = lerp(get(x0, y1, z1), get(x1, y1, z1), u);
        let c0 = lerp(c00, c10, v);
        let c1 = lerp(c01, c11, v);
        lerp(c0, c1, w)
    }
}

fn main() {
    let mut grid = VoxelGrid {
        dims: (16, 16, 16),
        voxel_size: 0.1,
        origin: Vec3::new(-0.8, -0.8, -0.8),
        voxels: vec![Voxel::default(); 16 * 16 * 16],
    };

    // 设置体素光照(中心 1.0)
    for k in 0..16 {
        for j in 0..16 {
            for i in 0..16 {
                let dx = i as f32 - 8.0;
                let dy = j as f32 - 8.0;
                let dz = k as f32 - 8.0;
                let dist = (dx*dx + dy*dy + dz*dz).sqrt();
                let val = (1.0 - dist / 8.0).max(0.0);
                grid.voxels[grid.idx(i, j, k)].light = [val; 3];
            }
        }
    }

    // 测试采样
    let pos = Vec3::new(0.0, 0.0, 0.0);  // 中心
    let light = grid.sample_trilinear(pos);
    println!("Light at center: ({:.3}, {:.3}, {:.3})",
        light.x, light.y, light.z);
    
    let pos2 = Vec3::new(0.4, 0.0, 0.0);  // 偏移
    let light2 = grid.sample_trilinear(pos2);
    println!("Light at offset: ({:.3}, {:.3}, {:.3})",
        light2.x, light2.y, light2.z);
}
```

## 9 · 深度推导:三线性插值的数学

Per-pixel 体素采样的核心是 GPU 硬件做**三线性插值**(trilinear interpolation)。让我把每一步推清楚。

给定 8 个邻居 voxel 的值 v(x0,y0,z0) ... v(x1,y1,z1),其中 x1 = x0+1 等。采样位置 (x, y, z) 的小数部分 (u, v, w) ∈ [0, 1)³。

**Step 1 — 在 z = z0 层做双线性插值**:

```
c00 = v(x0, y0, z0) · (1-u) · (1-v) + v(x1, y0, z0) · u · (1-v)
     + v(x0, y1, z0) · (1-u) · v + v(x1, y1, z0) · u · v
```

展开就是 4 个 texel 的加权平均,权重是双线性核 (1-u)(1-v), u(1-v), (1-u)v, uv。

**Step 2 — 在 z = z1 层做同样的双线性**:

```
c01 = ... (同上,但 z0 换 z1)
```

**Step 3 — 在 z 方向线性插值 c00 和 c01**:

```
c = c00 · (1-w) + c01 · w
```

总共 8 个 texel,8 次乘加。GPU 硬件 texel unit 专门优化这个操作,1 个时钟周期就能完成(同步 fetch + filter)。

**对比双线性(2D)**:4 texel,4 次 MAC。所以 3D 采样比 2D 慢 2 倍——这也是为什么 voxel GI 比 lightmap 贵。

**Mipmap 的作用**:远处 fragment 在屏幕上小,覆盖 3D 纹理的很多 voxel。三线性插值只采 8 个,会有**欠采样锯齿**。Mipmap 让远处采 LOD 1(32³,voxel 更大),8 个邻居覆盖更大范围,等效于"低通滤波",消除锯齿。

GPU 选 LOD 的算法:**屏幕空间导数**(dFdx, dFdy)算出 fragment 在世界空间跨度,这个跨度对 3D 纹理覆盖几个 voxel,选最接近的 mipmap level。GLSL 的 `textureLod()` 可手动指定,`texture()` 自动算。

### Cache 行为:coherent vs incoherent access

3D 纹理采样性能的关键是 **cache 命中**。GPU 的 L1 cache 通常是 32-64 KB,一个 cache line 64-128 字节。

**Coherent access**:相邻 fragment(屏幕上相邻)采相邻 voxel(世界空间相邻)。一个 cache line 64 字节 = 16 个 f32 RGBA texel。屏幕上 4×4 像素都命中同一个 cache line,**1 次内存访问,16 个 fragment 复用**。这种场景 3D 纹理采样极快。

**Incoherent access**:相邻 fragment 采**距离很远的** voxel。例如大场景,屏幕一小区域里物体远近跨度大,每像素采不同 cache line,cache miss 频繁。性能 5-10 倍下降。

改善方法:
- **Lighting proxy**:用低分辨率 3D 纹理,cache 命中高
- **Tile-based**:把 3D 纹理分块,只加载当前 view frustum 内的块
- **Sparse texture**(OpenGL ARB_sparse_texture,Vulkan sparse):GPU 虚拟内存,只 commit 非空区域

### Memory bandwidth budget

3D 纹理采样的瓶颈不是计算(MUL/ADD 极快),而是**带宽**。1080p 渲染,每像素采 1 次 3D 纹理(RGBA32F = 16 字节):

```
1920 × 1080 × 16 = 33 MB / 帧
60 FPS × 33 MB = 2 GB/s
```

GDDR6 显存带宽 256-512 GB/s,2 GB/s 占用 1%——OK。但若每像素采 8 次(多光源 GI,或 cone tracing),占 8%,开始成为瓶颈。再加 G-buffer、shadow map、albedo 等其他纹理,总带宽可能饱和。

这就是为什么 Casey 强调"减少 sampler 数"——能合并就合并,能压缩就压缩(BC6H 把 16 字节降到 2.67 字节,带宽降 6 倍)。

### Cone tracing 简介(预告 Day 405+)

Voxel GI 的更高级版本是**cone tracing**:从一个 fragment 沿反射方向发射一个**圆锥**,在 3D 纹理里逐步采样,累积反射光。

圆锥越大,采样的 mipmap level 越高(等效低分辨率)。这模拟了"反射光在粗糙表面变模糊"——物理正确的 glossy reflection。

Cone tracing 比 trilinear 采样贵 10 倍(每 fragment 8-16 个采样),但效果接近光线追踪。这是 NVIDIA VXGI(2014)和当前 bevy 第 13 版 bevy_solari 的核心技术。

### 历史脉络:从 lightmap 到 voxel GI

理解 per-pixel voxel GI 在图形学史上的位置,能帮你看清为什么 Casey 选这条路。

**1998 — Quake 3 lightmap**:第一个商业 lightmap 引擎。每 surface 一张 16×16 lightmap,完全离线烘焙。视觉惊艳但完全静态。

**2004 — Half-Life 2 irradiance**:静态 irradiance volume,3D 网格存球谐系数,运行时三线性插值。比 lightmap 灵活(支持动态物体)。

**2009 — Crytek LPV (Light Propagation Volume)**:Crysis 用实时体素 GI。每帧把直接光"注入"voxel grid,然后 V-cycle 散射。Crytek 把 3D 纹理的实用化推到了主流。

**2014 — NVIDIA VXGI**:cone tracing 的 voxel GI。基于 Kepler/Maxwell 的 bindless 3D 纹理硬件。GTA V、Tom Clancy's The Division 都试过。

**2018 — UE4 Lumen 雏形**:屏幕空间 GI + voxel cascade。

**2020 — UE5 Luman**:实时光线追踪 + voxel cascade + 屏幕空间。Nintendo Switch OLED 跑不动。

**2024 — bevy_solari**:Rust 生态的 lightmap crate,用 wgpu compute shader bake。

Casey 的 Day 404 实现是 LPV 路径的简化版——核心思想相同(体素网格 + 三线性采样),但简化了注入和散射(只做静态 bake)。学完今天你能直接读懂 Crytek 的 GDC 2010 演讲。

### Per-pixel 性能优化技巧

实战中 voxel GI 的性能优化清单:

**1. Half-resolution GI**:GI 是低频数据,在半分辨率上算然后 upsample。带宽降 4 倍。

**2. Temporal accumulation**:每帧只算一部分 GI,累积到历史 buffer。TAA 风格的 temporal filter。

**3. Light list**:不要对每光源都跑 GI。聚光源、点光源合并到 voxel injection 一次。

**4. Importance sampling**:远处 voxel 用稀疏采样,近处 dense。

**5. Async compute**:在 GPU 的 compute queue 跑 GI,同时 graphics queue 渲染其他。现代 GPU 90% 时间空闲。

```rust
// GPU pipeline 示意
let mut encoder = wgpu::CommandEncoder::new(...);
// Compute pass: V-cycle(异步)
encoder.run_pass(&gi_compute_pass);
// Render pass: 主渲染
encoder.run_pass(&main_render_pass);
queue.submit(encoder.finish());
```

**6. Mixed resolution**:屏幕中央 full res,边缘 half res(人眼对边缘不敏感)。

**7. Adaptive sampling**:cos θ 小的 fragment(掠射角)跳过 GI,因为贡献小。

### 调试 per-pixel GI 的工具

Casey 在 Day 404 debug 视图用的几个技巧:

**Debug A — 只看 GI**:fragment shader 直接输出 `vec4(gi, 1.0)`,跳过 direct light 和 tone mapping。看到的是"纯间接光"图像。

**Debug B — 网格可视化**:画出 voxel grid 边界线(线框立方体),确认覆盖场景。

**Debug C — 采样位置 heatmap**:对每 fragment,根据它在 voxel grid 内的位置染色(局部 xyz → RGB)。看到色块连续表示采样 coherent,色块断裂表示 cache miss 高发区。

**Debug D — Per-vertex 对比**:同一场景同时跑 per-vertex 和 per-pixel,左右分屏对比。角落和边缘的差异最明显。

**Debug E — V-cycle 步数扫描**:在 GPU 上跑 N 步 V-cycle,N 从 0 到 1000。截图每步,看 GI 收敛过程。能看到光"逐渐扩散"。

这些 debug 工具不是 Casey 一拍脑门想出来的——它们是渲染工程师的日常工具。RenderDoc(开源 GPU debugger)有类似的"texture overrides"功能,允许 shader 替换。

### 完整 Rust + wgpu 实现

为让你能跑起来,这是简化但完整的 per-pixel voxel GI demo:

```rust
use wgpu::util::DeviceExt;

pub struct VoxelGi {
    pub texture: wgpu::Texture,
    pub view: wgpu::TextureView,
    pub bind_group: wgpu::BindGroup,
    pub sampler: wgpu::Sampler,
    pub grid_min: [f32; 3],
    pub grid_extent: [f32; 3],
    pub dims: [u32; 3],
}

impl VoxelGi {
    pub fn new(
        device: &wgpu::Device,
        queue: &wgpu::Queue,
        dims: [u32; 3],
        data: &[u8],
    ) -> Self {
        let texture = device.create_texture(&wgpu::TextureDescriptor {
            label: Some("voxel_light"),
            size: wgpu::Extent3d { width: dims[0], height: dims[1], depth_or_array_layers: dims[2] },
            mip_level_count: 1,
            sample_count: 1,
            dimension: wgpu::TextureDimension::D3,
            format: wgpu::TextureFormat::Rgba32Float,
            usage: wgpu::TextureUsages::TEXTURE_BINDING | wgpu::TextureUsages::COPY_DST,
            view_formats: &[],
        });
        let view = texture.create_view(&wgpu::TextureViewDescriptor::default());
        let sampler = device.create_sampler(&wgpu::SamplerDescriptor {
            label: Some("voxel_sampler"),
            address_mode_u: wgpu::AddressMode::ClampToEdge,
            address_mode_v: wgpu::AddressMode::ClampToEdge,
            address_mode_w: wgpu::AddressMode::ClampToEdge,
            mag_filter: wgpu::FilterMode::Linear,
            min_filter: wgpu::FilterMode::Linear,
            mipmap_filter: wgpu::FilterMode::Linear,
            ..Default::default()
        });
        queue.write_texture(
            wgpu::ImageCopyTexture {
                texture: &texture,
                mip_level: 0,
                origin: wgpu::Origin3d::ZERO,
                aspect: wgpu::TextureAspect::All,
            },
            data,
            wgpu::ImageDataLayout {
                offset: 0,
                bytes_per_row: Some(dims[0] * 16),
                rows_per_image: Some(dims[1]),
            },
            wgpu::Extent3d { width: dims[0], height: dims[1], depth_or_array_layers: dims[2] },
        );
        // ... bind group setup omitted for brevity
        Self {
            texture, view, bind_group: unimplemented!(),
            sampler, grid_min: [-8.0; 3], grid_extent: [16.0; 3], dims,
        }
    }
}
```

这段代码展示了 wgpu 创建 3D 纹理的完整流程。注意 `Rgba32Float` 格式(16 字节/texel)用于 HDR 间接光——LOD 1 开始可以换 Rgba16Float(8 字节)省显存。

完整 demo 见本仓库 `/samples/voxel_gi/` 子目录(若存在)或 wgpu examples。
