
# Day 335 · 实体在加速方块上移动

> 昨天只让玩家用 boost pad。今天 Casey 把 boost pad 推广到所有 entity——怪物也走 boost pad,被加速。这是 trigger volume 的"通用化"。

## 0 · 为什么要有这一天

昨天的 boost pad 只影响玩家,逻辑写死在 `update_player` 里。但实际游戏场景:

1. **怪物追玩家**:怪物踩 boost pad 也加速,玩家需要更聪明逃跑
2. **物理对象**:可推动的箱子被 boost pad 推着走(解谜)
3. **NPC**:盟友 NPC 跟随玩家,也走 boost pad
4. **粒子**:在 boost pad 上发射的粒子被加速(视觉一致)

如果每种 entity 都写一遍 boost 逻辑,代码重复。业界的做法是**统一 trigger 系统**——所有 entity 走过 boost pad 都触发,而不仅仅是玩家。

```c
void update_entity(entity *e, world *world, float dt) {
    // 移动 + 物理(通用)
    apply_physics(e, dt);
    
    // Tile 效果(通用,不再针对玩家)
    tile *t = get_tile_at(world, e->pos);
    if (t) {
        apply_tile_effect(e, t, dt);
    }
}
```

`apply_tile_effect` 根据 tile 类型应用不同效果:

- BoostPad:加速 entity
- Ice:降低摩擦
- Spike:扣血/伤害
- Water:减速

这种"数据驱动 + 统一接口"的设计是 ECS 架构的核心——所有 entity 共享通用逻辑,差异由数据(tile 类型)决定。

心理锚点:今天之后你的游戏所有 entity 都受 boost pad 影响,世界更"一致"。这是 ECS 思想的入门。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 今天打开 `handmade_entity.cpp`,把昨天写死在 `update_player` 的 boost 逻辑重构到 `apply_tile_effect`。

具体动作:

1. 创建 `apply_tile_effect(entity *e, tile *t, float dt)` 通用函数
2. `update_entity` 调用它,不管 entity 是玩家还是怪物
3. 把所有 entity update 统一成 `update_entity`(不再有 `update_player` vs `update_monster`)

```c
void apply_tile_effect(entity *e, tile *t, float dt) {
    switch (t->type) {
        case TILE_BOOST_PAD:
            e->vel += t->boost_direction * BOOST_FORCE * dt;
            break;
        case TILE_ICE:
            e->friction_override = 0.99;  // 低摩擦
            break;
        case TILE_LAVA:
            e->take_damage(LAVA_DAMAGE * dt);
            break;
        default:
            break;
    }
}

void update_entity(entity *e, world *world, float dt) {
    // 通用物理
    apply_input(e, dt);  // 输入(玩家有,怪物 AI 算)
    apply_physics(e, dt);
    
    // Tile 效果(统一)
    tile *t = get_tile_at(world, (int)e->pos.x, (int)e->pos.y);
    if (t) apply_tile_effect(e, t, dt);
    
    // AI(怪物用)
    if (e->brain == BRAIN_MONSTER) {
        update_monster_ai(e, dt);
    }
}
```

Casey 在视频里讨论了一个**关键设计**:entity 的"输入"从哪里来?

- 玩家:从手柄/键盘
- 怪物:从 AI
- 物理对象(箱子):无输入(被动)

这种"输入是数据,不是函数"的设计让所有 entity 共享 `update_entity` 主体,差异只在"输入来源"。Casey 引入 `entity_input` 数据结构,玩家和 AI 都填它。

```c
struct entity_input {
    v2 desired_movement;  // 玩家或 AI 想往哪走
    bool want_jump;
    bool want_attack;
};

entity_input get_player_input() {
    entity_input input = {0};
    if (key_pressed(KEY_W)) input.desired_movement.y += 1;
    if (key_pressed(KEY_S)) input.desired_movement.y -= 1;
    // ...
    return input;
}

entity_input get_monster_input(entity *monster, world *world) {
    entity_input input = {0};
    entity *player = find_player(world);
    if (player) {
        v2 to_player = player->pos - monster->pos;
        input.desired_movement = normalize(to_player);
    }
    return input;
}
```

`get_player_input` 和 `get_monster_input` 都返回 `entity_input`,统一接口。`update_entity` 只关心 input 内容,不关心来源。

## 2 · 心智模型

### 类比:同一份菜谱,不同食材

把游戏 update 想象成烹饪。

- **食材**(entity 类型):玩家、怪物、NPC、物体
- **菜谱**(`update_entity`):统一的烹饪步骤——切、炒、调味
- **调味**(输入):玩家用手动按钮,怪物用 AI 决策,但都是"调味"

统一的菜谱让厨师(代码)不用学 N 种烹饪方式,只要会一种,食材变了烹饪不变。今天 Casey 把玩家和怪物的 update 合并成"统一菜谱"。

### 严谨原理:ECS 思想

ECS(Entity-Component-System)的核心:

- **Entity**:只是一个 ID,没有逻辑
- **Component**:数据片段(Position、Velocity、Health、AI)
- **System**:处理特定 Component 组合的逻辑(MovementSystem、AISystem)

Casey 的 HH 不是完整 ECS,但今天的重构体现了 ECS 精神——把"通用逻辑"(物理、tile 效果)从"特定 entity 逻辑"(玩家输入、怪物 AI)分离。

```rust
// ECS 风格
fn movement_system(query: Query<(&mut Position, &Velocity)>) {
    for (mut pos, vel) in &mut query {
        pos.0 += vel.0 * dt;
    }
}

fn tile_effect_system(query: Query<(&Position, &mut Velocity)>, world: Res<World>) {
    for (pos, mut vel) in &mut query {
        let tile = world.get_tile_at(pos.0);
        match tile {
            Tile::BoostPad(dir) => vel.0 += dir * BOOST_FORCE * dt,
            _ => {}
        }
    }
}
```

每个 system 处理"特定 Component 组合",不关心 entity 是玩家还是怪物。Bevy ECS 的 Query 自动找到所有有这些 Component 的 entity。

### 数据驱动 vs 代码驱动

- **代码驱动**(原版):每种 entity 一个 update 函数,逻辑硬编码
- **数据驱动**(今天):所有 entity 一个 update,差异由数据(tile、input)决定

数据驱动的好处:

1. **加新 entity 容易**:新 entity 加 Component,system 自动处理
2. **测试简单**:测试 system 而不是测试 entity
3. **可序列化**:数据可存盘,逻辑固定

代价:抽象层多,代码"间接"。但长期收益大于代价,所以 ECS 成为现代引擎主流。

### Rust 实现

```rust
struct World {
    tiles: Vec<Tile>,
    width: usize,
}

struct Entity {
    pos: Vec2,
    vel: Vec2,
    brain: Brain,
    hp: i32,
    // ... 其他通用字段
}

#[derive(Clone, Copy)]
enum Brain {
    Player,
    Monster,
    NPC,
    Object,
}

impl Brain {
    /// 返回这个 entity 的"输入"(移动意图)
    fn compute_input(self, e: &Entity, world: &World) -> Vec2 {
        match self {
            Self::Player => get_player_input(),
            Self::Monster => get_monster_input(e, world),
            Self::NPC => Vec2::ZERO,  // NPC 静止
            Self::Object => Vec2::ZERO,  // 物体无 AI
        }
    }
}

fn update_entity(e: &mut Entity, world: &World, dt: f32) {
    // 1. 输入
    let input = e.brain.compute_input(e, world);
    
    // 2. 应用输入
    e.vel += input * MOVE_ACCEL * dt;
    
    // 3. 物理
    e.pos += e.vel * dt;
    
    // 4. Tile 效果(通用)
    let tile = world.get_tile_at(e.pos);
    apply_tile_effect(e, tile, dt);
    
    // 5. 摩擦
    e.vel *= FRICTION;
    
    // 6. 限速
    let speed = e.vel.length();
    if speed > MAX_SPEED {
        e.vel *= MAX_SPEED / speed;
    }
}

fn apply_tile_effect(e: &mut Entity, tile: Tile, dt: f32) {
    match tile {
        Tile::BoostPad(dir) => {
            e.vel += dir * BOOST_FORCE * dt;
        }
        Tile::Ice => {
            // 冰面摩擦低(简化:每帧不应用默认摩擦)
        }
        Tile::Lava => {
            e.hp -= 1;
        }
        _ => {}
    }
}
```

`update_entity` 对所有 entity 统一,差异只在 `compute_input`(玩家 vs AI)和 `apply_tile_effect`(tile 类型)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

主流游戏的 ECS 实现:

- **Unity DOTS**:ECS 重写,性能 10-100 倍
- **Unreal Mass Entity**:UE5 引入的 ECS
- **Bevy ECS**:Rust 原生 ECS,设计优雅
- **Casey HH**:不是完整 ECS,但精神类似

游戏行业的另一个概念是 **"shared simulation"** ——所有 entity 共享同一个物理模拟,没有"玩家物理 vs 怪物物理"。这种设计避免 bug(玩家能跳墙,怪物也能跳墙?如果代码分开,容易不一致)。

### 3.2 · 🐧 Linux 系统编程视角

Linux 内核的"统一接口"思想:

- **everything is a file**:文件、socket、device 都用 file API
- **everything is a process**:进程、线程统一调度
- **everything is a fd**:file descriptor 抽象所有资源

这种"统一接口 + 数据差异"的设计哲学和今天的 ECS 完全一致——通用逻辑 + 数据区分,而不是每种类型一套代码。

### 3.3 · 🦀 Rust 生态视角

Rust 的 ECS:

- **`bevy_ecs`**:Bevy 核心,最流行
- **`legion`**:独立 ECS crate,高性能
- **`specs`**:经典 ECS crate,并行化好

```rust
use bevy_ecs::prelude::*;

#[derive(Component)]
struct Position(Vec2);

#[derive(Component)]
struct Velocity(Vec2);

#[derive(Component)]
struct Brain(BrainType);

fn update_system(
    mut query: Query<(&mut Position, &mut Velocity, &Brain)>,
    world: Res<World>,
    time: Res<Time>,
) {
    let dt = time.delta_seconds();
    for (mut pos, mut vel, brain) in &mut query {
        let input = brain.0.compute_input(&pos, &world);
        vel.0 += input * MOVE_ACCEL * dt;
        pos.0 += vel.0 * dt;
        // Tile 效果
        let tile = world.get_tile_at(pos.0);
        if let Tile::BoostPad(dir) = tile {
            vel.0 += dir * BOOST_FORCE * dt;
        }
    }
}
```

Bevy ECS 自动并行化 system(用 Rayon),200000 entity 的 update 在多核 CPU 上几毫秒。Casey 的 HH 单线程,但概念一致。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么把 `update_player` 和 `update_monster` 合并成 `update_entity`?给出至少 3 个理由。

**参考解答**:

1. **避免代码重复**:物理、tile 效果、摩擦等逻辑在所有 entity 都一样,合并后只写一次。
2. **保证一致性**:所有 entity 用同一套规则,不会出现"玩家能做但怪物不能做"的不一致 bug。
3. **扩展容易**:加新 entity 类型(Object、Particle)时不用写新 update,直接复用。
4. **测试简单**:测试一个 `update_entity`,覆盖所有 entity。

### Lv2 · 动手实践

**题**:在 Rust 里实现统一 update + boost pad 通用化。

**参考解答**:

```rust
#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn length(self) -> f32 { (self.x*self.x + self.y*self.y).sqrt() }
}
impl std::ops::AddAssign for Vec2 {
    fn add_assign(&mut self, o: Self) { self.x += o.x; self.y += o.y; }
}
impl std::ops::Add for Vec2 {
    type Output = Self;
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
}
impl std::ops::Mul<f32> for Vec2 {
    type Output = Self;
    fn mul(self, s: f32) -> Self { Self { x: self.x * s, y: self.y * s } }
}

#[derive(Clone, Copy)]
enum Tile { Floor, BoostPad(Vec2) }

#[derive(Clone, Copy, PartialEq)]
enum Brain { Player, Monster, Object }

struct Entity {
    pos: Vec2,
    vel: Vec2,
    brain: Brain,
    name: &'static str,
}

impl Entity {
    fn compute_input(&self, player_pos: Vec2) -> Vec2 {
        match self.brain {
            Brain::Player => Vec2::new(0.0, 0.0),  // 假设无输入
            Brain::Monster => {
                // 怪物朝玩家方向
                let dx = player_pos.x - self.pos.x;
                let dy = player_pos.y - self.pos.y;
                let len = (dx*dx + dy*dy).sqrt();
                if len > 0.0 { Vec2::new(dx/len, dy/len) }
                else { Vec2::new(0.0, 0.0) }
            }
            Brain::Object => Vec2::new(0.0, 0.0),
        }
    }
}

fn update_entity(e: &mut Entity, tile: Tile, dt: f32, player_pos: Vec2) {
    let input = e.compute_input(player_pos);
    e.vel += input * 30.0 * dt;  // 输入加速
    
    // Boost pad(通用)
    if let Tile::BoostPad(dir) = tile {
        e.vel += dir * 80.0 * dt;
    }
    
    // 摩擦
    e.vel = e.vel * 0.95;
    
    // 限速
    let speed = e.vel.length();
    if speed > 20.0 {
        e.vel = e.vel * (20.0 / speed);
    }
    
    // 移动
    e.pos += e.vel * dt;
}

fn main() {
    let boost_tile = Tile::BoostPad(Vec2::new(1.0, 0.0));
    let player_pos = Vec2::new(10.0, 0.0);
    
    let mut entities = vec![
        Entity { pos: Vec2::new(5.0, 0.0),  vel: Vec2::new(0.0, 0.0), brain: Brain::Player,  name: "Player" },
        Entity { pos: Vec2::new(0.0, 0.0),  vel: Vec2::new(0.0, 0.0), brain: Brain::Monster, name: "Goblin" },
        Entity { pos: Vec2::new(2.0, 0.0),  vel: Vec2::new(0.0, 0.0), brain: Brain::Object,  name: "Box" },
    ];
    
    let dt = 1.0 / 60.0;
    for frame in 0..60 {
        for e in &mut entities {
            update_entity(e, boost_tile, dt, player_pos);
        }
    }
    
    for e in &entities {
        println!("{}: pos=({:.2},{:.2}) vel=({:.2},{:.2})",
                 e.name, e.pos.x, e.pos.y, e.vel.x, e.vel.y);
    }
}
```

### Rust:统一 update + boost 通用(完整可跑)

```rust
// Cargo.toml: 无依赖
// src/main.rs

#[derive(Clone, Copy, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn length(self) -> f32 { (self.x*self.x + self.y*self.y).sqrt() }
}

impl std::ops::Add for Vec2 {
    type Output = Self;
    fn add(self, o: Self) -> Self { Self { x: self.x + o.x, y: self.y + o.y } }
}
impl std::ops::AddAssign for Vec2 {
    fn add_assign(&mut self, o: Self) { self.x += o.x; self.y += o.y; }
}
impl std::ops::Mul<f32> for Vec2 {
    type Output = Self;
    fn mul(self, s: f32) -> Self { Self { x: self.x * s, y: self.y * s } }
}
impl std::ops::MulAssign<f32> for Vec2 {
    fn mul_assign(&mut self, s: f32) { self.x *= s; self.y *= s; }
}

#[derive(Clone, Copy)]
enum Tile {
    Floor,
    Wall,
    BoostPad(Vec2),
}

struct World {
    tiles: Vec<Tile>,
    width: usize,
    height: usize,
}

impl World {
    fn new(w: usize, h: usize) -> Self {
        let mut tiles = vec![Tile::Floor; w * h];
        // 放 boost pad(向右)
        let by = h / 2;
        for bx in 3..6 {
            tiles[by * w + bx] = Tile::BoostPad(Vec2::new(1.0, 0.0));
        }
        Self { tiles, width: w, height: h }
    }
    
    fn get_tile_at(&self, x: f32, y: f32) -> Tile {
        let xi = x as i32;
        let yi = y as i32;
        if xi < 0 || yi < 0 || xi as usize >= self.width || yi as usize >= self.height {
            return Tile::Wall;
        }
        self.tiles[yi as usize * self.width + xi as usize]
    }
}

#[derive(Clone, Copy, PartialEq, Debug)]
enum Brain {
    Player,
    Monster,
    Object,
}

impl Brain {
    fn name(self) -> &'static str {
        match self {
            Self::Player => "Player",
            Self::Monster => "Monster",
            Self::Object => "Object",
        }
    }
}

#[derive(Clone, Debug)]
struct Entity {
    pos: Vec2,
    vel: Vec2,
    brain: Brain,
    name: &'static str,
}

impl Entity {
    fn compute_input(&self, player_pos: Vec2) -> Vec2 {
        match self.brain {
            Self_brain if self.brain == Brain::Player => {
                // 模拟:玩家无输入(让 boost 自己推)
                Vec2::new(0.0, 0.0)
            }
            Brain::Monster => {
                // 怪物追玩家
                let dx = player_pos.x - self.pos.x;
                let dy = player_pos.y - self.pos.y;
                let len = (dx*dx + dy*dy).sqrt();
                if len > 0.1 { Vec2::new(dx/len * 0.5, dy/len * 0.5) }
                else { Vec2::new(0.0, 0.0) }
            }
            Brain::Object => Vec2::new(0.0, 0.0),
        }
    }
}

const DT: f32 = 1.0 / 60.0;
const MOVE_ACCEL: f32 = 30.0;
const BOOST_FORCE: f32 = 80.0;
const FRICTION: f32 = 0.92;
const MAX_SPEED: f32 = 25.0;

/// 统一 entity update
fn update_entity(e: &mut Entity, world: &World, player_pos: Vec2) {
    // 1. 输入(由 brain 决定)
    let input = e.compute_input(player_pos);
    e.vel += input * MOVE_ACCEL * DT;
    
    // 2. Tile 效果(通用!)
    let tile = world.get_tile_at(e.pos.x, e.pos.y);
    if let Tile::BoostPad(dir) = tile {
        e.vel += dir * BOOST_FORCE * DT;
    }
    
    // 3. 摩擦
    e.vel *= FRICTION;
    
    // 4. 限速
    let speed = e.vel.length();
    if speed > MAX_SPEED {
        e.vel *= MAX_SPEED / speed;
    }
    
    // 5. 移动
    e.pos += e.vel * DT;
}

fn main() {
    println!("=== Day 335: 统一 update + boost 通用 ===\n");
    
    let world = World::new(20, 10);
    
    let player_pos = Vec2::new(15.0, 5.0);  // 玩家初始位置
    
    let mut entities = vec![
        Entity { 
            pos: Vec2::new(3.5, 5.0),  // 在 boost pad 上
            vel: Vec2::new(0.0, 0.0),
            brain: Brain::Player,
            name: "Player",
        },
        Entity { 
            pos: Vec2::new(4.0, 5.0),  // 也在 boost pad 上
            vel: Vec2::new(0.0, 0.0),
            brain: Brain::Monster,
            name: "Goblin",
        },
        Entity { 
            pos: Vec2::new(5.0, 5.0),  // boost pad 上
            vel: Vec2::new(0.0, 0.0),
            brain: Brain::Object,
            name: "Box",
        },
    ];
    
    // 模拟 60 帧
    for frame in 0..120 {
        // 注意:每帧 player_pos 应该是 entities[0].pos,但我们简化为固定
        let p_pos = entities[0].pos;
        for e in &mut entities {
            update_entity(e, &world, p_pos);
        }
        
        if frame % 30 == 0 {
            println!("--- Frame {} ---", frame);
            for e in &entities {
                let on_boost = matches!(world.get_tile_at(e.pos.x, e.pos.y), Tile::BoostPad(_));
                let boost_str = if on_boost { "[BOOST]" } else { "" };
                println!("  {:10} ({:6.2},{:6.2}) speed={:6.2} {}",
                         e.name, e.pos.x, e.pos.y, e.vel.length(), boost_str);
            }
        }
    }
    
    println!("\n--- 最终状态 ---");
    for e in &entities {
        println!("{}: pos=({:.2},{:.2}) speed={:.2}",
                 e.name, e.pos.x, e.pos.y, e.vel.length());
    }
}
```

## 10 · 深度补充:工程视角

ECS 的深度哲学:ECS 不仅是一种架构,是 组合优于继承 的极致表达。传统 OOP 用继承表达 IS-A 关系(Eagle IS-A Bird IS-A Animal),导致层次深、修改难。ECS 用组合表达 HAS-A 关系(Eagle HAS Position + Velocity + Wing + AI Component)。新功能 = 新 Component + 新 System,不改现有代码。

### 跨领域的方向一致性

工程上很多抽象都跨领域通用。今天的概念在多个领域都有对应。

- **游戏引擎**:Core abstraction 表达
- **图形学**:GPU 硬件或软件算法实现
- **Linux 内核**:类似抽象在 OS 层
- **Rust 生态**:类型安全表达

理解一个抽象的多领域映射,你就能在不同技术栈间自由切换。

### 历史演化与未来趋势

每个技术都有演化历史和未来趋势。Casey 在 HH 系列展示的是 当下最佳实践,但技术会演进。学会识别 哪些是永恒原理(数据结构、算法)、哪些是时代选择(API 设计、语言特性),让你长期保持竞争力。

永恒原理:排序、矩阵乘法、alpha 合成、内存分配、并发原语。这些 50 年不变。

时代选择:OpenGL vs Vulkan vs WebGPU、Rust vs C++、ECS vs OOP。这些 5-10 年一变。

### 给读者的建议

1. **理解原理**:每个抽象都问 为什么这样设计
2. **多语言对比**:同一个抽象在 C / Rust / Python 各怎么表达
3. **历史视角**:看技术演化,理解 为什么现在这样做
4. **实践**:每个概念都写代码,不止看
5. **开源贡献**:看真实代码怎么用,提 PR 加深理解

Casey HH 系列是教学,但更是一种 工程师心态 训练——遇到问题怎么拆解、怎么实现、怎么优化、怎么修 bug。这种心态比具体知识更重要。
