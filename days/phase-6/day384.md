
# Day 384 · 动态响应渲染设置

> Casey 现在有一个工作的深度剥离渲染器,但**只能在编译时开关**——开 / 关深度剥离要重新编译。今天他加一个**运行时渲染设置**(render settings)系统:游戏运行时按 F1 切换深度剥离开关,按 F2 调节层数。这是"配置驱动渲染"的工程实战。

## 0 · 为什么要有这一天

游戏开发里"渲染设置"是个**反复出现的需求**:

- **画质档位**:Low / Medium / High / Ultra,玩家在菜单里选
- **debug 视图**:开发者按 F1 / F2 / F3 切换"显示深度 / 显示法线 / 显示线框 / 显示原色"
- **抗锯齿开关**:MSAA on/off,从控制台输入
- **分辨率缩放**:动态分辨率(性能不够时降分辨率,够时升)
- **颜色分级**:实时调亮度 / 对比度 / 色调

这些设置都**不能在编译时固定**,因为:

1. 玩家机器性能不同,需要在运行时调
2. 开发期需要快速切换调试视图,重新编译太慢
3. 玩家通过菜单改设置,游戏必须**响应**

**Casey 今天的工作**:加一个全局的 `RenderSettings` 结构,游戏代码读它决定渲染路径。每个渲染 pass 的 shader 通过 uniform 接收这些设置。键盘 / 菜单修改 `RenderSettings`,下一帧立即生效。

**关键技术问题**:

1. **shader 切换**:某些设置(如"开 / 关深度剥离")需要**完全不同的 shader**,不能只改 uniform。需要在 CPU 端选择 shader program。
2. **资源管理**:不同 shader 需要不同 uniform / 纹理绑定。需要重新设计 uniform 上传逻辑。
3. **响应延迟**:设置改了,**最多 1 帧**就要生效(玩家按 F1 后下一帧就是新设置)。
4. **状态一致性**:不要"渲染中改设置"——一帧内设置应该稳定。

**今天的产出**:一个支持运行时切换的深度剥离渲染器。按 F1 切换深度剥离,按 F2 调层数(2 / 4 / 8)。屏幕上显示当前设置(HUD 文本)。

心理锚点:看完今天,你能(1)设计一个全局 `RenderSettings` 结构;(2)解释为什么 shader 切换需要 CPU 端选择而不是 GLSL 里 if-else;(3)实现键盘响应 + HUD 显示;(4)理解"配置 vs 代码"的边界。

## 2 · 心智模型

### 类比:厨房的"菜单驱动"

想象你开了一家餐厅。最初你只有一道菜,菜单写死:"今日只有牛肉面"。顾客进门就知道吃什么。

后来你想加菜:**红烧肉饭**、**炒青菜**、**蛋花汤**。顾客进门问"今天有什么?"你**根据菜单决定**做什么菜。

这是"配置驱动"——你不再写死"做牛肉面",而是写"看菜单,做对应菜"。菜单(配置)可以**随时改**,不需要换厨师(代码)。

游戏渲染也一样:最初只有一种渲染路径(普通不透明),写死就行。后来加深度剥离、加 MSAA、加后处理,这些是"渲染路径"——根据设置选哪个。

### 严谨原理:配置驱动的代码结构

最简单(坏)的代码:

```rust
fn render(scene: &Scene, framebuffer: &mut Framebuffer) {
    // 硬编码:总是用深度剥离 2 层
    render_opaque(scene, framebuffer);
    render_depth_peel(scene, framebuffer, 2);
    composite(framebuffer, 2);
}
```

要改层数,改代码 + 重新编译。

**配置驱动**的代码:

```rust
struct RenderSettings {
    enable_depth_peel: bool,
    depth_peel_layers: usize,
    enable_msaa: bool,
    msaa_samples: u32,
}

fn render(scene: &Scene, settings: &RenderSettings, framebuffer: &mut Framebuffer) {
    render_opaque(scene, framebuffer);
    if settings.enable_depth_peel {
        render_depth_peel(scene, framebuffer, settings.depth_peel_layers);
        composite(framebuffer, settings.depth_peel_layers);
    }
}
```

设置由调用者传,渲染代码"看菜单做事"。

### Shader 选择:CPU vs GPU 分支

设置改变 shader 行为有两种方式:

**方式 1:GPU 分支(GLSL if-else)**

```glsl
uniform bool enable_peel;
void main() {
    if (enable_peel) {
        // 深度剥离逻辑
    } else {
        // 普通渲染逻辑
    }
}
```

**问题**:

1. **GPU 分支开销大**:GPU 是 SIMD(单指令多数据),一个 warp / wave 里所有 fragment 执行同一指令。如果 if 分支不同,某些 fragment 在等,某些在算,**利用率下降**。
2. **代码冗余**:shader 里有大量"如果 A 模式 / 如果 B 模式"的分支,可读性差。
3. **uniform 上传开销**:每次 draw 都要上传所有设置。

**方式 2:CPU 端 shader 选择**

```rust
let program = if settings.enable_depth_peel {
    &peel_program
} else {
    &normal_program
};
target.draw(&mesh, &indices, program, ...);
```

**优点**:

1. shader 各自简洁,无分支
2. GPU 完全并行,无浪费
3. CPU 端选择 program 几乎零开销(就是指针比较)

**缺点**:

1. 多个 program 占用更多显存
2. 改设置需要重新绑定 program(state switch,有少量开销)

**何时选哪个**:

- 简单切换(开 / 关):CPU 选择更好
- 复杂参数(亮度 / 对比度):GPU if-else 更好(因为没有"多 program"的选择,只是一个参数)

**深度剥离的开关用 CPU 端选择**——开 / 关是完全不同的渲染路径。

### Shader 变体:Specialization Constants(Vulkan)

Vulkan / WebGPU 引入了 **Specialization Constants**:shader 编译时把常量"特化"为具体值,生成多个变体。例如:

```glsl
// GLSL
layout(constant_id = 0) const uint LAYER_COUNT = 2;
void main() {
    for (uint i = 0; i < LAYER_COUNT; ++i) {
        // ...
    }
}
```

Vulkan 创建 pipeline 时指定 `LAYER_COUNT = 4`,编译成"展开循环 4 次"的特化版本。

这是介于 CPU 选择和 GPU 分支之间的方案——**shader 写一份,但编译时特化**。WGPU(Rust)支持这个特性。

**Casey 在 OpenGL 里用 CPU 端选择**(OpenGL 没有官方 specialization constant)。

### 响应延迟与帧一致性

设置改了,**什么时候生效**?

**理想**:玩家按 F1 后,**下一帧**就显示新设置。延迟 ≤ 1 帧(60Hz 时约 16ms)。

**实现**:键盘事件 → 改 `RenderSettings` → 下一帧的 render() 读到新设置。事件处理和渲染在同一帧内,设置变更在帧末生效。

**陷阱**:如果渲染中**修改**设置,会出现**部分 fragment 用旧设置、部分用新设置**的不一致画面。所以:

```rust
// 正确:帧开头读一次,帧内不再改
fn frame() {
    let settings_snapshot = settings.read();
    render(&settings_snapshot);
    handle_input(&mut settings);  // 输入改设置,下一帧生效
}
```

`settings_snapshot` 是当前帧的"冻结视图",渲染期间不能改。

### HUD(Heads-Up Display)

显示当前设置的最简单方式:

```rust
fn render_hud(settings: &RenderSettings, framebuffer: &mut Framebuffer) {
    let text = format!("Depth Peel: {} ({} layers)",
        if settings.enable_depth_peel { "ON" } else { "OFF" },
        settings.depth_peel_layers);
    draw_text(&text, 10, 10, color::WHITE);
}
```

`draw_text` 需要**字体渲染**(freetype / fontdue)+ **图集纹理**(glyph atlas)。Casey 在 HH 早期写过 bitmap font(手画字符),Day 384 直接用。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**RenderSettings 在真实游戏里的复杂度**:

- **质量档位**(`GraphicsQuality`):Low / Medium / High / Ultra,影响 shadow resolution / texture quality / shader complexity
- **后处理开关**(Bloom / SSAO / DoF / Motion Blur / TAA):每个都是独立开关
- **抗锯齿**(MSAA / FXAA / SMAA / TAA):多选一
- **画质参数**(shadow bias / bloom intensity):浮点 slider
- **VSync on/off**:影响 frame pacing

**Unreal Engine 的 scalability system**:把所有设置组织成 `sg.PostProcessQuality`、`sg.ShadowQuality` 等层级,玩家在菜单改 → 引擎切换 cvar → 渲染代码读 cvar。

**Bevy 的 `Msaa` resource**:全局资源,改后下一帧生效。这是 Rust 生态的"配置驱动"标准模式。

### 3.2 · 🎨 图形学视角

**Shader permutation 问题**:大游戏有**几千个 shader 变体**(因为不同材质、不同光照模式、不同 quality level 的组合)。编译所有变体需要几分钟到几小时,占用几百 MB 显存。

工业界的解决方案:

- **Uber shader**:一个超长 shader,用 `#ifdef` / `if` 分支处理所有情况。编译快,运行时有 if 开销。
- **Shader permutation matrix**:每个设置一个维度,N 个设置 → N 维空间,每点是一个 shader。
- **Specialization constants**:Vulkan / WebGPU 的特化机制。
- **Pipeline state object (PSO)**:Vulkan / DX12 的"预编译渲染管线",包含 shader + blend mode + depth test 等。

Casey 选最简单的方式:**多个独立 shader**,CPU 端选择。这对 demo 够用,但生产级游戏要更精细。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上**配置驱动**的经典模式:

- **环境变量**:启动时读,运行时不变
- **配置文件**(`~/.config/mygame/settings.toml`):启动时读,可以热重载
- **D-Bus / IPC**:其他进程通过 IPC 改设置(桌面集成)
- **CLI flags**(`--high-quality`):启动参数

游戏内的 RenderSettings 一般是**配置文件 + 运行时改**,启动时读配置文件,玩家在菜单改 → 写回配置文件。

```bash
# 看游戏读什么配置文件
strace -e openat ./your_game 2>&1 | grep settings
# 输出类似:openat(..., "/home/user/.config/mygame/settings.toml", ...)

# 用 inotify 监控配置文件变化(热重载基础)
inotifywait -m ~/.config/mygame/settings.toml &
# 文件被改时打印事件
```

### 3.4 · 🦀 Rust 生态视角

Rust 表达"全局可变状态"的几种方式:

**方式 1:`RwLock<RenderSettings>`**

```rust
use std::sync::RwLock;

static RENDER_SETTINGS: RwLock<RenderSettings> = RwLock::new(RenderSettings::default());

fn read_settings() -> RenderSettings { *RENDER_SETTINGS.read().unwrap() }
fn write_settings(f: impl FnOnce(&mut RenderSettings)) {
    let mut s = RENDER_SETTINGS.write().unwrap();
    f(&mut s);
}
```

**优点**:多线程安全。
**缺点**:RwLock 有开销,锁竞争时阻塞。

**方式 2:`Arc<AtomicPtr<RenderSettings>>`**(lock-free)

```rust
use std::sync::Arc;
use std::sync::atomic::{AtomicPtr, Ordering};

struct SettingsHandle(Arc<AtomicPtr<RenderSettings>>);

impl SettingsHandle {
    fn read(&self) -> Arc<RenderSettings> {
        let ptr = self.0.load(Ordering::Acquire);
        // ... unsafe 包装,略
    }
    fn write(&self, new: RenderSettings) {
        let new_arc = Arc::into_raw(Arc::new(new)) as *mut _;
        let old = self.0.swap(new_arc, Ordering::AcqRel);
        // ... 释放 old,略
    }
}
```

**优点**:lock-free,读无开销。
**缺点**:unsafe 多,复杂。

**方式 3:消息传递(channel)**

```rust
use std::sync::mpsc;

let (tx, rx) = mpsc::channel::<RenderSettings>();

// 输入线程
tx.send(new_settings).unwrap();

// 渲染线程
let settings = rx.try_recv().unwrap_or(previous_settings);
```

**优点**:无锁,清晰。
**缺点**:多线程通信开销,适合"少量改设置"的场景。

**Casey 的选择**(单线程渲染):直接 `Cell<RenderSettings>` 或 `RefCell<RenderSettings>`,事件循环里改,渲染里读。

```rust
use std::cell::Cell;

let settings = Cell::new(RenderSettings::default());

// 事件
settings.set(RenderSettings { enable_depth_peel: true, .. });

// 渲染
let s = settings.get();
render(&s);
```

`Cell` 是**单线程内部可变**,无锁,开销极小。Rust 编译器保证不会被多线程访问(否则编译错误)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 GPU shader 里的 if-else 不能完全替代 CPU 端 shader 选择?给两个具体场景说明。

**参考解答**:

1. **复杂路径分歧**:如果一个 warp 内 32 个 fragment,16 个走 if 分支,16 个走 else 分支,GPU 实际执行**两个分支都跑**,然后 mask 掉不需要的结果。性能 = max(if_cost, else_cost) 而不是 avg。CPU 端选择则只有一种 shader,完全并行。

2. **shader 编译期常量展开**:某些优化(constant folding、loop unrolling)需要编译时知道常量值。GPU 端 if-else 用 uniform,**运行时**才知道值,无法编译期优化。例如:
   ```glsl
   for (int i = 0; i < layer_count; ++i) { ... }  // layer_count 是 uniform
   ```
   GPU 不能展开循环(因为不知道 layer_count),每次循环都有判断。Specialization constants 让 layer_count 在编译时特化,可以展开。

### Lv2 · 动手实践

**题**:在 Day 383 的 demo 基础上加 `RenderSettings` 结构 + 键盘响应。F1 切换 "Composite" / "Layer 0" / "Layer 1" 视图,F2 调节 epsilon(0 → 1e-5 → 1e-4 → 1e-3 循环)。

完成标准:按键立即生效,屏幕显示当前 epsilon 值。

**参考解答**:

```rust
use std::cell::Cell;

#[derive(Copy, Clone)]
struct RenderSettings {
    debug_view: usize,    // 0=layer0, 1=layer1, 2=composite
    epsilon: f32,
}

impl Default for RenderSettings {
    fn default() -> Self {
        Self { debug_view: 2, epsilon: 1e-4 }
    }
}

fn main() {
    let settings = Cell::new(RenderSettings::default());

    event_loop.run(move |event, _, control_flow| {
        match event {
            Event::WindowEvent { event: WindowEvent::KeyboardInput {
                input: KeyboardInput { state: ElementState::Pressed,
                                       virtual_keycode: Some(key), .. }, ..
            }, .. } => {
                let mut s = settings.get();
                match key {
                    VirtualKeyCode::F1 => {
                        s.debug_view = (s.debug_view + 1) % 3;
                        println!("Debug view: {}", s.debug_view);
                    }
                    VirtualKeyCode::F2 => {
                        // 在几个 epsilon 值之间循环
                        s.epsilon = match s.epsilon {
                            x if x < 1e-9 => 1e-5,
                            x if (x - 1e-5).abs() < 1e-10 => 1e-4,
                            x if (x - 1e-4).abs() < 1e-9 => 1e-3,
                            _ => 0.0,
                        };
                        println!("Epsilon: {}", s.epsilon);
                    }
                    _ => {}
                }
                settings.set(s);
            }
            Event::RedrawRequested(_) => {
                let s = settings.get();
                let uniforms = uniform! {
                    layer0: &tex0,
                    layer1: &tex1,
                    debug_view: s.debug_view as i32,
                    epsilon: s.epsilon,
                };
                // draw ...
            }
            _ => {}
        }
    });
}
```

**关键点**:
- `Cell::get` / `Cell::set` — 单线程内部可变,无锁
- `match s.epsilon` — 用模式匹配在几个值之间循环,优雅
- 输入 handler 改设置 → 渲染读设置,通过 `Cell` 共享

### 完整 RenderSettings 系统

```toml
# Cargo.toml

[dependencies]
```

```rust
// src/main.rs
use glium::{glutin, Surface, implement_vertex, uniform, program, index};
use std::cell::Cell;

#[derive(Copy, Clone, Debug)]
struct RenderSettings {
    debug_view: u32,      // 0=normal, 1=layer0, 2=layer1
    epsilon: f32,
    show_hud: bool,
}

impl Default for RenderSettings {
    fn default() -> Self {
        Self { debug_view: 0, epsilon: 1e-4, show_hud: true }
    }
}

#[derive(Copy, Clone)]
struct Vertex { position: [f32; 2], uv: [f32; 2] }
implement_vertex!(Vertex, position, uv);

fn main() {
    let event_loop = glutin::event_loop::EventLoop::new();
    let wb = glutin::window::WindowBuilder::new()
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 600))
        .with_title("Render Settings Demo");
    let cb = glutin::ContextBuilder::new();
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    let settings = Cell::new(RenderSettings::default());

    // (省略 layer0 / layer1 纹理创建,见 Day 383)

    let program = program!(&display,
        330 es => {
            vertex: r#"#version 330
                in vec2 position; in vec2 uv;
                out vec2 v_uv;
                void main() { v_uv = uv; gl_Position = vec4(position, 0., 1.); }
            "#,
            fragment: r#"#version 330
                in vec2 v_uv; out vec4 frag;
                uniform sampler2D layer0;
                uniform sampler2D layer1;
                uniform int debug_view;
                uniform float epsilon;
                void main() {
                    vec4 c0 = texture(layer0, v_uv);
                    vec4 c1 = texture(layer1, v_uv);
                    if (debug_view == 1) {
                        frag = vec4(c0.rgb, 1.);
                    } else if (debug_view == 2) {
                        frag = vec4(c1.rgb, 1.);
                    } else {
                        vec3 rgb = c0.rgb * c0.a + c1.rgb * c1.a * (1.0 - c0.a);
                        float a = c0.a + c1.a * (1.0 - c0.a);
                        if (a > epsilon) rgb /= a;
                        frag = vec4(rgb, 1.);
                    }
                }
            "#,
        }).unwrap();

    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent, KeyboardInput, ElementState, VirtualKeyCode};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        match event {
            Event::WindowEvent { event: WindowEvent::KeyboardInput {
                input: KeyboardInput { state: ElementState::Pressed,
                                       virtual_keycode: Some(key), .. }, ..
            }, .. } => {
                let mut s = settings.get();
                match key {
                    VirtualKeyCode::F1 => {
                        s.debug_view = (s.debug_view + 1) % 3;
                        println!("debug_view: {}", s.debug_view);
                    }
                    VirtualKeyCode::F2 => {
                        s.epsilon = match s.epsilon {
                            x if x == 0.0 => 1e-5,
                            x if (x - 1e-5).abs() < 1e-10 => 1e-4,
                            x if (x - 1e-4).abs() < 1e-9 => 1e-3,
                            _ => 0.0,
                        };
                        println!("epsilon: {}", s.epsilon);
                    }
                    VirtualKeyCode::F3 => {
                        s.show_hud = !s.show_hud;
                    }
                    VirtualKeyCode::Escape => *control_flow = ControlFlow::Exit,
                    _ => {}
                }
                settings.set(s);
            }
            Event::RedrawRequested(_) => {
                let s = settings.get();
                let mut target = display.draw();
                target.clear_color(0.1, 0.1, 0.1, 1.0);

                // (省略纹理创建,实际需要先创建 tex0 / tex1)
                // let uniforms = uniform! {
                //     layer0: &tex0, layer1: &tex1,
                //     debug_view: s.debug_view as i32,
                //     epsilon: s.epsilon,
                // };
                // target.draw(&vbuf, &indices, &program, &uniforms, &Default::default()).unwrap();

                if s.show_hud {
                    // HUD:在左上角显示当前设置(用文本渲染,这里简化为 println)
                    println!("HUD: view={}, eps={}", s.debug_view, s.epsilon);
                }
                target.finish().unwrap();
            }
            Event::WindowEvent { event: WindowEvent::CloseRequested, .. } => {
                *control_flow = ControlFlow::Exit;
            }
            _ => {}
        }
    });
}
```
