# Day 385 · 尝试多重采样深度剥离

> 深度剥离渲染器工作正常,但**边缘有锯齿**(jaggies)——三角形边缘像素的"半填充"显示为锯齿状。Casey 想用 **MSAA**(Multi-Sample Anti-Aliasing,多重采样抗锯齿)修这个。今天他**尝试**给深度剥离加 MSAA,结果发现一堆问题——是"尝试"而不是"成功"的一天。

## 0 · 为什么要有这一天

**锯齿**(aliasing)是图形学的根本问题。屏幕是离散像素,三角形是连续几何,采样时如果三角形边缘"半个像素在三角形内、半个在外",那个像素的颜色是"全画"还是"不画"?如果**全画**,边缘看起来锯齿;如果**不画**,边缘出现裂缝。

**MSAA**(多重采样抗锯齿)是工业标准:每个像素**采样多次**(2 / 4 / 8 / 16 个采样点),按"采样点有多少在三角形内"决定颜色权重。4x MSAA 意味着每个像素采 4 次,边缘像素的颜色 = 4 个采样的平均,看起来平滑。

**为什么 MSAA 对深度剥离很难**?

普通渲染的 MSAA 流程:

1. 在 multisample framebuffer 上渲染(每像素多个采样)
2. 用 `glBlitFramebuffer` 把 multisample 解析(resolve)成单采样 framebuffer
3. 显示单采样 framebuffer

**深度剥离的难题**:

- 每层有**独立的 multisample depth texture**(每个采样点都有自己的深度)
- 合成时需要把多层 multisample 数据 resolve 后再合成,或**在 multisample 空间合成**后再 resolve
- `glBlitFramebuffer` 的 default resolve 是**盒式平均**(box filter),对**深度**没有意义(深度不能平均,平均深度 = 不存在的层)

**Casey 今天的尝试**:

1. 把 framebuffer 改成 multisample(4x MSAA)
2. 渲染深度剥离到 multisample texture
3. 用 `glBlitFramebuffer` resolve,得到 single-sample texture
4. 合成

**结果**:画面有 MSAA 抗锯齿,但**深度信息丢失**(resolve 平均了深度),导致第二层位置不对。Casey 试了几种方法都不对,决定**明天(Day 386)写自定义 resolve**。

心理锚点:看完今天,你能(1)解释 MSAA 的工作原理;(2)知道为什么深度不能"盒式平均";(3)理解 OpenGL 的 multisample texture 和 resolve 机制;(4)面对"标准方法不工作"时知道要写自定义。

## 1 · Casey 今天做了什么(HH 脉络)

Casey 流程:

1. **观察**:深度剥离渲染器跑起来,但半透明球的边缘锯齿明显(每帧锯齿位置不变,因为 MSAA off)。
2. **试 MSAA on**:把 context 的 `with_multisampling(4)` 打开,期望边缘平滑。

5. **再跑**:边缘平滑了!但深度剥离的第二层位置不对——透过玻璃看到的玻璃**位置漂移**(因为 `glBlitFramebuffer` 把深度"平均"了)。

8. **状态**:今天**没有完整工作的 MSAA 深度剥离**,只有"普通 MSAA"(无深度剥离)和"深度剥离"(无 MSAA)两个版本。Casey 在视频里展示两者的差异,明天再合并。

## 2 · 心智模型

### 类比:用放大镜看马赛克

想象你看一面马赛克墙:每个色块是一像素,边缘锯齿明显。你拿放大镜看,每个"色块"实际上有**多个小点**(采样),颜色按"小点在三角形内的比例"决定。**这就是 MSAA**——每个像素位置不变(还是那个色块),但内部多采样,显示时取平均。

**关键理解**:MSAA 的"多采样"不是"多像素",而是"每个像素多采样"。1080p + 4x MSAA 还是 1080p 像素,但每个像素内有 4 个采样点,计算时按 4 个采样的平均。

### 严谨原理:采样与抗锯齿

**Nyquist-Shannon 采样定理**:连续信号的采样频率必须 ≥ 信号最高频率的 2 倍,才能无失真重建。屏幕像素间距是 1/N(每行 N 像素),最高可表示频率是 N/2 周期/行。三角形边缘有"高频"(从内部到外部的突变),超过这个频率,所以**锯齿**。

**修法**:**提高采样频率**或**前滤波**(pre-filter)。

- **SSAA(Super-Sample AA)**:渲染到 2x 分辨率,下采样到 1x。每像素 4 个采样,**几何和 shader 都执行 4 次**。最高质量,最贵。
- **MSAA(Multi-Sample AA)**:每像素 4 个采样,**几何(边缘测试)执行 4 次,但 fragment shader 只执行 1 次**(在像素中心)。中等质量,中等开销。
- **FXAA(Fast AA)**:后处理,在最终图像上检测边缘,blur 掉锯齿。便宜,但模糊。
- **TAA(Temporal AA)**:每帧用不同的采样位置,几帧累加。便宜,但运动时有"鬼影"(ghosting)。

**MSAA 的工业地位**:2000-2015 的标准,后期被 TAA 取代。但**深度剥离等需要"几何精确"的场景**仍然用 MSAA。

### MSAA 的实现细节

OpenGL 的 MSAA:

1. **Context 创建**:`with_multisampling(4)`( glium)或 `SDL_GL_SetAttribute(SDL_GL_MULTISAMPLESAMPLES, 4)`。
2. **Multisample texture**:`glTexImage2DMultisample(GL_TEXTURE_2D_MULTISAMPLE, 4, GL_RGBA8, w, h, GL_TRUE)`。
3. **Multisample FBO**:绑 multisample renderbuffer 或 texture。
4. **Sample shading**(可选):`glMinSampleShadingARB(1.0)` 让 fragment shader 每采样执行一次(默认是每像素一次)。
5. **Resolve**:`glBlitFramebuffer` 从 multisample FBO blit 到 single-sample FBO,自动 box-filter resolve。

**关键**:OpenGL 的 default resolve 是**盒式平均**——对颜色 RGB 取平均,对 alpha 也取平均。对**深度**会取平均,**但深度平均无意义**(因为深度是"最近的",平均后变成"中间"的)。

### 深度剥离 + MSAA 的核心矛盾

深度剥离需要每层"最近的深度"。MSAA 让每像素 4 个采样,**4 个采样可能各自属于不同的层**(比如采样 0 在 layer 0,采样 1 在 layer 1)。深度 buffer 存的是**每个采样的深度**(4 个浮点数,不是 1 个)。

**问题**:第二层 peel shader 怎么比较?

- 选项 A:每个采样独立比较(对 4 个采样做 4 次 "z > prev_z?")
- 选项 B:像素中心一次比较,4 个采样用同一结果

选项 A 是"per-sample 深度剥离",**正确**但实现复杂(需要 GLSL 的 `gl_SampleID`)。选项 B 是"per-pixel 深度剥离",**不正确**(边缘采样的层判断错误)。

**Casey 今天的尝试**用 `glBlitFramebuffer` 默认 resolve(选项 B 的变体),结果错。

**正确方法**(Day 386+ 实现):per-sample 比较 + 自定义 resolve。

### Box-filter Resolve 的问题

OpenGL 默认 resolve:`out_pixel = avg(samples)`。

**对颜色**:4 个采样的颜色平均,边缘像素的颜色 = "三角形内的采样数 / 4" * 三角形颜色 + "三角形外的采样数 / 4" * 背景色。这就是抗锯齿。

**对深度**:4 个采样的深度平均,得到"4 个采样的中间深度"。但**深度是单调函数**(最近 / 最远),平均深度无意义。

举例:4 个采样的深度是 `[0.1, 0.1, 0.9, 0.9]`(前两个采样在不透明物体表面,后两个在玻璃后面)。平均 = 0.5,但 0.5 这个深度**没有任何物体**。第二层 peel 用 0.5 做基准,得到错误结果。

**修法**:不要平均深度。要么用 per-sample 比较(Day 386),要么用某个采样(比如 sample 0)的深度。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**MSAA 在工业游戏里的应用**:

- **deferred shading(延迟渲染)**:G-buffer 不支持 MSAA(因为每像素多采样,G-buffer 显存爆炸)。所以延迟渲染几乎不用 MSAA,改用 TAA / FXAA。
- **forward rendering(前向渲染)**:支持 MSAA,每像素多采样,fragment shader 每像素执行 1 次。AAA 游戏如 DOOM(2016)用 forward + MSAA。
- **forward+ / clustered forward**:现代前向渲染,支持 MSAA + 多光源,工业标准。

**MSAA 性能开销**:

- 4x MSAA:几何测试 4 倍,显存 4 倍(深度 + 颜色),fragment shader 不变
- 8x MSAA:几何测试 8 倍,显存 8 倍
- 16x MSAA:几何测试 16 倍,显存 16 倍,几乎所有 GPU 都吃力

**典型选择**:4x MSAA(性能 + 质量平衡),或 EQAA(AMD 的"颜色 4 采样,深度 8 采样",节省显存)。

**MSAA 和半透明**:

MSAA 只对**几何边缘**做抗锯齿(三角形边缘的"半像素"),**不影响** shader 内部计算的边缘(如 alpha-tested texture 的边缘)。所以 MSAA + 半透明物体,**纹理边缘仍锯齿**,除非用 alpha-to-coverage。

### 3.2 · 🎨 图形学视角

**Sample positions**:MSAA 的采样位置不是均匀分布,而是**精心设计的低差异序列**(low-discrepancy sequence),让采样覆盖像素的各个区域。OpenGL 标准没指定具体位置,各 GPU 厂商自己定(AMD / NVIDIA / Intel 不同)。

**Sample shading**(`glMinSampleShadingARB`):默认 fragment shader 每像素执行一次(在像素中心)。`glMinSampleShadingARB(1.0)` 让 shader 每采样执行一次——开销 4 倍,但 shader 内的边缘(如 noise)也被抗锯齿。

**Alpha to coverage**:把 fragment 的 alpha 映射到 sample mask——`alpha=0.5` 时只让 2/4 采样通过。这是 MSAA 处理 alpha-tested texture 的方法。

**Coverage**:每个像素有一个 coverage mask(N 位,N 是采样数),每一位代表"该采样是否在三角形内"。Resolve 时用 coverage 决定颜色权重。

### 3.4 · 🦀 Rust 生态视角

Rust + glium 的 MSAA:

```rust
// Context 启用 MSAA
let cb = glutin::ContextBuilder::new()
    .with_multisampling(4);  // 4x MSAA
let display = glium::Display::new(wb, cb, &event_loop).unwrap();

// 创建 multisample framebuffer
let color_tex = glium::texture::Texture2DMultisample::new(
    &display, glium::texture::UncompressedFloatFormat::F32F32F32F32,
    800, 600, 4,  // 4 samples
    true  // fixed sample locations
)?;
let depth_tex = glium::texture::DepthTexture2DMultisample::new(
    &display, glium::texture::DepthFormat::F32,
    800, 600, 4, true
)?;

// 用 multisample texture 作为 FBO 附件
let fbo = glium::framebuffer::MultiOutputFrameBuffer::with_depth_texture(
    &display, &[("color0", &color_tex)], &depth_tex)?;

// 渲染到 fbo(每像素 4 采样)
fbo.draw(...)?;

// Resolve:glium 的 BlitTarget 或自己写
// glium 提供 fbo.blit_color_to_simple_framebuffer() 或类似
```

**关键 API**:

- `Texture2DMultisample` — multisample 颜色纹理
- `DepthTexture2DMultisample` — multisample 深度纹理
- `with_multisampling(4)` — context 创建时启用 4x MSAA

**自定义 resolve** 的 Rust 实现(Day 386+):写一个 fullscreen shader,在 fragment shader 里用 `texelFetch(ms_texture, pixel_coord, sample_id)` 取每个采样的值,手动做"per-sample 比较"或"per-sample 合成"。

## 4 · 认知地图

### 4.1 上级

- **抗锯齿**(Anti-Aliasing)— 一类技术,目标消除锯齿
- **过采样**(Supersampling)— 用高于显示的采样率,再下采样
- **GPGPU 算法设计** — 当标准 API 不够时,自己写 shader

### 4.2 同级

| 方案 | 开销 | 质量 | 适用 |
|---|---|---|---|
| SSAA | 高(渲染到高分辨率) | 最高 | 离线渲染 |
| **MSAA** | 中(几何 4x,shader 1x) | 高 | 实时渲染 |
| FXAA | 极低(后处理) | 中 | 性能优先 |
| SMAA | 低(后处理) | 中高 | 平衡 |
| TAA | 低(每帧 1 采样,累积) | 高 | 现代游戏 |
| **自定义 resolve** | 中 | 高 | MSAA + 自定义算法 |

### 4.3 下级

- **Sample position** — 像素内的采样位置(由 GPU 厂商决定)
- **Coverage mask** — N 位,每采样一位
- **Per-sample shader** — fragment shader 每采样执行一次
- **`glBlitFramebuffer`** — OpenGL 标准 resolve API(盒式平均)
- **`gl_SampleID`** — GLSL 内置,shader 里知道当前是哪个采样
- **Alpha to coverage** — alpha → sample mask 映射

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 MSAA 比 SSAA 快?它们的根本差别是什么?

**参考解答**:

**SSAA**(Super-Sample):渲染到 2x 分辨率(每像素 4 个采样),**fragment shader 执行 4 次**(每采样一次),geometry 测试 4 次。最后下采样到 1x。开销 = 4 倍 fragment shader + 4 倍几何 + 4 倍显存。

**MSAA**(Multi-Sample):每像素 4 个采样,**fragment shader 执行 1 次**(在像素中心),geometry 测试 4 次(每采样决定是否在三角形内)。Resolve 时按"采样在三角形内的比例"加权。开销 = 1 倍 fragment shader + 4 倍几何 + 4 倍显存。

**根本差别**:**fragment shader 执行次数**。SSAA 每采样一次,MSAA 每像素一次。MSAA 假设 shader 在像素内变化平缓(gradient 不大),所以像素中心的 shader 结果可以代表整个像素。

代价:MSAA 不能抗"shader 内的边缘"(如 alpha-tested texture 的边缘,因为 shader 在像素中心算一次,内部边缘的细节被忽略)。SSAA 可以,因为 shader 在 4 个位置各算一次。

### Lv2 · 动手实践

**题**:写一个最小化 MSAA demo——渲染一个三角形,左半边用 1x MSAA,右半边用 4x MSAA,直接对比。

完成标准:能看到左半边锯齿明显,右半边平滑。

**参考解答**:

```rust
use glium::{glutin, Surface, implement_vertex, program, index};

#[derive(Copy, Clone)]
struct Vertex { position: [f32; 2] }
implement_vertex!(Vertex, position);

fn main() {
    let event_loop = glutin::event_loop::EventLoop::new();

    // MSAA 4x context
    let wb = glutin::window::WindowBuilder::new()
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 400));
    let cb = glutin::ContextBuilder::new().with_multisampling(4);
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    // 三角形:左半边(不依赖 MSAA,因为是大块)和右半边
    let verts = vec![
        Vertex { position: [-1.0, -1.0] },
        Vertex { position: [ 0.0,  1.0] },
        Vertex { position: [ 1.0, -1.0] },
    ];
    let vbuf = glium::VertexBuffer::new(&display, &verts).unwrap();
    let indices = index::NoIndices(index::PrimitiveType::TrianglesList);

    let program = program!(&display,
        330 es => {
            vertex: r#"#version 330
                in vec2 position;
                void main() { gl_Position = vec4(position, 0., 1.); }
            "#,
            fragment: r#"#version 330
                out vec4 frag;
                void main() { frag = vec4(1., 0., 0., 1.); }
            "#,
        }).unwrap();

    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        if let Event::RedrawRequested(_) = event {
            let mut target = display.draw();
            target.clear_color(0., 0., 0., 1.);
            // glium 默认开启 GL_MULTISAMPLE(context 设了 with_multisampling)
            target.draw(&vbuf, &indices, &program, &glium::uniforms::EmptyUniforms,
                &Default::default()).unwrap();
            target.finish().unwrap();
        }

        if let Event::WindowEvent { event: WindowEvent::CloseRequested, .. } = event {
            *control_flow = ControlFlow::Exit;
        }
    });
}
```

**关键**:glium 的 `with_multisampling(4)` 自动启用 OpenGL 的 `GL_MULTISAMPLE`,渲染时自动做 MSAA。三角形的边缘应该平滑。

**对比测试**:把 `with_multisampling(4)` 改成 `with_multisampling(0)`(关闭),重新跑,边缘锯齿明显。

### MSAA + 深度剥离(失败版)

```toml
[package]
name = "msaa_attempt"

[dependencies]
```

```rust
use glium::{glutin, Surface, implement_vertex, program, index, texture, framebuffer};

#[derive(Copy, Clone)]
struct Vertex { position: [f32; 2], uv: [f32; 2] }
implement_vertex!(Vertex, position, uv);

fn main() {
    let event_loop = glutin::event_loop::EventLoop::new();
    let wb = glutin::window::WindowBuilder::new()
        .with_inner_size(glutin::dpi::LogicalSize::new(800, 600))
        .with_title("MSAA + Depth Peel (Attempt)");
    let cb = glutin::ContextBuilder::new()
        .with_multisampling(4);  // 关键:4x MSAA
    let display = glium::Display::new(wb, cb, &event_loop).unwrap();

    // 创建 multisample 颜色和深度纹理
    let msaa_samples = 4u32;
    let (w, h) = (800u32, 600u32);
    let color_ms = texture::Texture2DMultisample::new(
        &display,
        texture::UncompressedFloatFormat::F32F32F32F32,
        w, h, msaa_samples, true).unwrap();
    let depth_ms = texture::DepthTexture2DMultisample::new(
        &display, texture::DepthFormat::F32,
        w, h, msaa_samples, true).unwrap();

    // 普通 single-sample 纹理(用于 resolve 后)
    let color_ss = texture::Texture2d::empty_with_format(
        &display, texture::UncompressedFloatFormat::F32F32F32F32,
        texture::MipmapsOption::NoMipmap, w, h).unwrap();
    let depth_ss = texture::DepthTexture2d::empty_with_format(
        &display, texture::DepthFormat::F32,
        texture::MipmapsOption::NoMipmap, w, h).unwrap();

    // FBO 1:multisample
    let mut fbo_ms = framebuffer::SimpleFrameBuffer::with_depth_texture(
        &display, &color_ms, &depth_ms).unwrap();
    // FBO 2:single-sample(用于 resolve 目标)
    let fbo_ss = framebuffer::SimpleFrameBuffer::with_depth_texture(
        &display, &color_ss, &depth_ss).unwrap();

    // 三角形几何(简化)
    let verts = vec![
        Vertex { position: [-0.5, -0.5], uv: [0., 0.] },
        Vertex { position: [ 0.5, -0.5], uv: [1., 0.] },
        Vertex { position: [ 0.0,  0.5], uv: [0.5, 1.] },
    ];
    let vbuf = glium::VertexBuffer::new(&display, &verts).unwrap();
    let indices = index::NoIndices(index::PrimitiveType::TrianglesList);

    let program = program!(&display,
        330 es => {
            vertex: r#"#version 330
                in vec2 position;
                void main() { gl_Position = vec4(position, 0., 1.); }
            "#,
            fragment: r#"#version 330
                out vec4 frag;
                void main() { frag = vec4(1., 0., 0., 0.5); }  // 半透明红
            "#,
        }).unwrap();

    event_loop.run(move |event, _, control_flow| {
        use glutin::event::{Event, WindowEvent};
        use glutin::event_loop::ControlFlow;
        *control_flow = ControlFlow::Wait;

        if let Event::RedrawRequested(_) = event {
            // === Pass: 渲染到 multisample FBO ===
            fbo_ms.clear_color(0., 0., 0., 1.);
            fbo_ms.clear_depth(1.);
            fbo_ms.draw(&vbuf, &indices, &program, &glium::uniforms::EmptyUniforms,
                &Default::default()).unwrap();

            // === Resolve:glBlitFramebuffer ===
            // glium 的 SimpleFrameBuffer 提供 blit_from / blit_color_from
            // 这里手动:从 fbo_ms blit 到 fbo_ss
            // 注意:glium API 可能略不同,核心是 glBlitFramebuffer(GL_COLOR_BUFFER_BIT)
            // ...
            // 简化:直接显示 multisample(window 自动 resolve)

            // 实际:Window 的 framebuffer 自动 resolve(因为是 MSAA context)
            let mut target = display.draw();
            target.clear_color(0.1, 0.1, 0.1, 1.0);
            target.draw(&vbuf, &indices, &program, &glium::uniforms::EmptyUniforms,
                &Default::default()).unwrap();
            target.finish().unwrap();
        }

        if let Event::WindowEvent { event: WindowEvent::CloseRequested, .. } = event {
            *control_flow = ControlFlow::Exit;
        }
    });
}
```
