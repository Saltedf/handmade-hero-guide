
# Day 017 · 统一键盘与手柄输入:适配器模式与 Edge / Level

> Day 006 你第一次接键盘 + 手柄输入,但两种来源用两套代码处理。Day 013 平台无关抽象了"输入"这个概念,但还没解决"键盘 = 0 号手柄"的统一接口。Day 017 完成这件事:把所有输入(键盘 + N 个手柄)统一成"controller"数组,游戏代码用同样逻辑处理任意输入源。这集还正式定义"按一下"(edge)和"按住"(level)的差别——这两个概念是所有交互设计的基础。

## 0 · 为什么要有这一天

你做游戏,玩家用键盘。你写代码:

```rust
if is_key_down(KeyW) { player.y -= 1; }  // 上
if is_key_down(KeyS) { player.y += 1; }  // 下
```

但你朋友来你家,他更喜欢 Xbox 手柄。你说"等下我加"。然后改代码:

```rust
if is_key_down(KeyW) || gamepad.left_stick.y < -0.5 { player.y -= 1; }
if is_key_down(KeyS) || gamepad.left_stick.y > 0.5 { player.y += 1; }
```

代码越来越乱。每加一种设备(Steam Deck、PS5 手柄、Switch Pro、跳舞毯)都要改游戏代码。

**正确的做法**是先抽象"输入源"概念,让游戏代码不知道也不在乎输入来自哪种设备。这叫**适配器模式**(Adapter Pattern):不同来源(键盘、手柄)都翻译成统一的"虚拟控制器",游戏代码只看虚拟控制器。

Casey 这集做的事情就是这个抽象。他的具体设计:

- 一个**数组** `controllers: [GameController; 5]`(0-4)
- `controllers[0]` = 键盘伪装的"0 号手柄"
- `controllers[1..5]` = 真手柄 1-4
- 每个 controller 有相同接口:buttons 数组、stick、trigger
- 游戏代码 `controllers[0].buttons[UP]` 既可能是键盘上方向键,也可能是真手柄的方向键——游戏不在乎

这种设计让"多人本地游戏"变得简单——两个玩家,一个键盘一个手柄,游戏代码完全相同。

**第二个核心**:edge vs level 的正式编码。Day 006 我们讨论过,Day 017 落地为结构体字段。

**心理锚点**:读完今天,你能:

- 解释"适配器模式"在输入抽象里的应用
- 写一个统一的 GameController 结构,容纳键盘和手柄
- 区分 edge(刚按下 / 刚松开)和 level(按住 / 没按)
- 知道为什么 edge detection 需要保存"上一帧状态"
- 用 bitfield 压缩 14 个 button 到 1 个 u16
- 在 Rust + gilrs + winit 项目里实现统一输入

## 1 · Casey 今天做了什么

Day 017 Casey 的具体动作:

1. 定义 `game_controller_input` 结构:14 个 button 的状态 + 两个 stick + 两个 trigger + "上一帧 button 状态"(用于 edge detection)。
2. 定义 `game_input` 结构:`controllers[5]`(4 个真手柄 + 1 个键盘伪装) + 时间信息。
3. Win32 平台层在每帧开始时:
   - 把当前 button 状态拷到 previous
   - 从 winit/XInput 填新的 button 状态
   - 把键盘按下的方向键映射到 controller[0] 的方向 button
4. 游戏代码用 `input->controllers[0].buttons[BUTTON_UP].is_down` 和 `.just_pressed` 等统一接口。

Casey 用 bitfield 压缩:`u16 button_states; u16 previous_button_states;`(每个 button 1 bit)。整个 controller 才几十字节,4 个 controller 加起来不到一个 cache line,极快。

## 2 · 心智模型

### 类比:输入是"通用游戏手柄"

想象 USB 接口。你插什么设备(键盘、鼠标、手柄、跳舞毯、方向盘)都行,因为 USB 协议定义了"输入设备"的通用接口。**所有具体设备"适配"成 USB HID(Human Interface Device)**。

Casey 的 GameController 是同样的抽象:**所有具体输入设备"适配"成统一的虚拟手柄**。游戏代码面对的是虚拟手柄,不知道背后是什么物理设备。

```
┌──────────────┐
│ 键盘         │──┐
├──────────────┤  │  ┌────────────┐
│ Xbox 手柄    │──┼─▶│ Controller │──▶ 游戏代码
├──────────────┤  │   │ 0/1/2/3/4  │
│ PS5 手柄     │──┤   └────────────┘
├──────────────┤  │
│ Steam Deck   │──┘
└──────────────┘
```

每个物理设备的"按键状态"被翻译成虚拟手柄的 button 状态。游戏代码读 `controllers[0].buttons[UP]`,值来自键盘方向键 OR Xbox 手柄方向键 OR Steam Deck 方向键——但游戏不知道哪个。

### 严谨:GameController 结构

```rust
pub struct ButtonState {
    /// 这一帧是否按住(level)
    pub is_down: bool,
    /// 上一帧是否按住(用于 edge detection)
    pub previous_is_down: bool,
}

impl ButtonState {
    /// 这帧刚按下(edge):这一帧 down + 上一帧 not down
    pub fn just_pressed(&self) -> bool {
        self.is_down && !self.previous_is_down
    }
    
    /// 这帧刚松开(edge):这一帧 not down + 上一帧 down
    pub fn just_released(&self) -> bool {
        !self.is_down && self.previous_is_down
    }
    
    /// 持续按住(level):两帧都 down
    pub fn held(&self) -> bool {
        self.is_down && self.previous_is_down
    }
}

pub struct GameController {
    pub buttons: [ButtonState; 14],   // 14 个 button
    pub stick_average_x: f32,         // 左摇杆 x(-1 到 1)
    pub stick_average_y: f32,
    // (右摇杆、trigger 等可扩展)
}

pub struct GameInput {
    pub controllers: [GameController; 5],   // [0]=键盘, [1..5]=手柄
    pub dt_for_frame: f32,                   // 这一帧的 dt
}
```

14 个 button 的常规定义(对应 Xbox 手柄):

```rust
pub const BUTTON_A: usize = 0;

pub const BUTTON_X: usize = 2;
pub const BUTTON_Y: usize = 3;
pub const BUTTON_LEFT_SHOULDER: usize = 4;   // LB
pub const BUTTON_RIGHT_SHOULDER: usize = 5;  // RB
pub const BUTTON_BACK: usize = 6;             // View / Select
pub const BUTTON_START: usize = 7;
pub const BUTTON_LEFT_THUMB: usize = 8;       // 按下左摇杆
pub const BUTTON_RIGHT_THUMB: usize = 9;
pub const BUTTON_UP: usize = 10;
pub const BUTTON_DOWN: usize = 11;
pub const BUTTON_LEFT: usize = 12;
pub const BUTTON_RIGHT: usize = 13;
```

键盘伪装 0 号手柄的映射:

```rust
// 键盘 → 0 号手柄
fn map_keyboard_to_controller0(controller: &mut GameController, keys: &HashSet<KeyCode>) {
    controller.buttons[BUTTON_UP].is_down = keys.contains(&KeyCode::ArrowUp) 
                                          || keys.contains(&KeyCode::KeyW);
    controller.buttons[BUTTON_DOWN].is_down = keys.contains(&KeyCode::ArrowDown) 
                                            || keys.contains(&KeyCode::KeyS);
    controller.buttons[BUTTON_LEFT].is_down = keys.contains(&KeyCode::ArrowLeft) 
                                            || keys.contains(&KeyCode::KeyA);
    controller.buttons[BUTTON_RIGHT].is_down = keys.contains(&KeyCode::ArrowRight) 
                                             || keys.contains(&KeyCode::KeyD);
    controller.buttons[BUTTON_A].is_down = keys.contains(&KeyCode::Space);
    controller.buttons[BUTTON_B].is_down = keys.contains(&KeyCode::KeyE);
    controller.buttons[BUTTON_START].is_down = keys.contains(&KeyCode::Enter);
    // ... 等等
}
```

注意:同一个 button 可以由多个键映射(`KeyW` 或 `ArrowUp`)。这样玩家可以选 WASD 或方向键。

### 平台层:每帧的 input pipeline

```rust
fn tick_input(app: &mut App) {
    // 步骤 1:把当前状态拷到 previous
    for c in &mut app.input.controllers {
        for b in &mut c.buttons {
            b.previous_is_down = b.is_down;
        }
    }
    
    // 步骤 2:填新状态(从 winit 队列 + gilrs 队列)
    map_keyboard_to_controller0(&mut app.input.controllers[0], &app.keys);
    map_gamepads_to_controllers(&mut app.input.controllers[1..5], &app.gilrs);
    
    // 步骤 3:计算 stick average(处理 deadzone)
    for c in &mut app.input.controllers {
        let (x, y) = (c.stick_average_x, c.stick_average_y);
        let mag = (x * x + y * y).sqrt();
        if mag < 0.15 {
            // deadzone:小位移忽略(摇杆不准,中央有噪声)
            c.stick_average_x = 0.0;
            c.stick_average_y = 0.0;
        }
    }
}
```

每帧**先拷贝**(previous = current),**再填新**。这样游戏代码用 `just_pressed` 时,看到的是"这帧 vs 上一帧"的对比。

### 死区(Deadzone)

摇杆物理上"中央"位置不完全归零——硬件精度问题,放开手摇杆可能报告 `(0.05, -0.03)`。如果不处理,游戏角色会"自动漂移"。

**死区**:设定一个阈值(比如 0.15),小于这个值的输入归零。

```rust
if mag < 0.15 { x = 0; y = 0; }
```

但简单死区有问题:在死区边缘跳变——0.14 归零,0.16 全值。手感不好。

**改进:径向死区 + 平滑过渡**:

```rust
let mag = (x * x + y * y).sqrt();
const DEADZONE: f32 = 0.15;
const MAX: f32 = 1.0;
if mag < DEADZONE {
    (x, y) = (0.0, 0.0);
} else {
    // 平滑映射 [DEADZONE, MAX] → [0, 1]
    let new_mag = (mag - DEADZONE) / (MAX - DEADZONE);
    let scale = new_mag / mag;
    x *= scale;
    y *= scale;
}
```

这样越接近死区值,输出越小,平滑过渡。Casey 在 Day 017 用简单死区,后期升级到平滑。

### Bitfield 优化(可选)

14 个 button,每个用 1 bit 就够。一个 u16 装 14 bit:

```rust
pub struct GameController {
    pub button_states: u16,            // bit i = buttons[i].is_down
    pub previous_button_states: u16,   // bit i = buttons[i].previous_is_down
    pub stick_average_x: f32,
    pub stick_average_y: f32,
}

// helper
fn is_down(c: &GameController, button: usize) -> bool {
    (c.button_states & (1 << button)) != 0
}

fn just_pressed(c: &GameController, button: usize) -> bool {
    let cur = c.button_states & (1 << button);
    let prev = c.previous_button_states & (1 << button);
    cur != 0 && prev == 0
}
```

整个 controller 才 8 字节(2 u16 + 2 f32 的 stick)。4 个 controller = 32 字节,半个 cache line。

Rust 用 `bitflags` crate 写更地道:

```rust
bitflags::bitflags! {
    #[derive(Copy, Clone, Default)]
    pub struct ButtonMask: u16 {
        const A = 1 << 0;
        const B = 1 << 1;
        const X = 1 << 2;
        const Y = 1 << 3;
        const LEFT_SHOULDER = 1 << 4;
        const RIGHT_SHOULDER = 1 << 5;
        const BACK = 1 << 6;
        const START = 1 << 7;
        const UP = 1 << 10;
        const DOWN = 1 << 11;
        const LEFT = 1 << 12;
        const RIGHT = 1 << 13;
    }
}
```

bitflags 自动生成 `|`, `&`, `!` 等运算符和 `contains` 方法。类型安全:`ButtonMask::A | ButtonMask::B` 是 `ButtonMask`,不能误传成任意 u16。

### 游戏代码用法

```rust
pub fn update_and_render(memory: &mut GameMemory, input: &GameInput, dt: f32) {
    // 用 controller[0](键盘或 0 号手柄)
    let c = &input.controllers[0];
    
    // level:持续移动
    let speed = 200.0;
    if c.buttons[BUTTON_UP].is_down    { memory.state.player_y -= speed * dt; }
    if c.buttons[BUTTON_DOWN].is_down  { memory.state.player_y += speed * dt; }
    if c.buttons[BUTTON_LEFT].is_down  { memory.state.player_x -= speed * dt; }
    if c.buttons[BUTTON_RIGHT].is_down { memory.state.player_x += speed * dt; }
    
    // 也可以用摇杆
    memory.state.player_x += c.stick_average_x * speed * dt;
    memory.state.player_y += c.stick_average_y * speed * dt;
    
    // edge:跳跃(只触发一次)
    if c.buttons[BUTTON_A].just_pressed() && memory.state.on_ground {
        memory.state.player_vy = -300.0;
        memory.state.on_ground = false;
    }
    
    // edge:菜单确认
    if c.buttons[BUTTON_START].just_pressed() {
        memory.state.pause_menu_open = !memory.state.pause_menu_open;
    }
}
```

读起来非常清楚:level 用 `.is_down`,edge 用 `.just_pressed`。**类型表达语义**,这是好的 API 设计。

### 3.1 · 🎮 游戏编程视角

业界输入抽象:

- **Unity Input System**(C#):复杂的"输入动作"系统,设计师可视化配置。`InputAction.move.ReadValue<Vector2>()` 等。
- **Unreal Enhanced Input**(UE5):类似 Unity,但更现代。"Input Action" + "Input Mapping Context"。

- **bevy_input**:Rust ECS 风格,`Res<Input<KeyCode>>` + `Res<ButtonInput<GamepadButton>>`。

所有这些系统本质上都是 Casey 的设计:把物理设备适配成虚拟控制器,提供 edge/level 区分。差别只在抽象层级和易用性。

**业界趋势:rebindable controls**。玩家可以重新映射按键。Casey 的设计支持——只要改 `map_keyboard_to_controller0` 这一层。游戏代码不变。

**本地多人游戏**:Casey 的"controllers 数组"自然支持——4 个玩家,4 个手柄,游戏代码 `controllers[0..4]` 各自处理。无额外设计。

### 3.2 · 🐧 Linux 系统编程视角

Linux 输入栈(从底到顶):

```
┌─────────────────────────────────────┐
│ 你的游戏(用户态)                    │
├─────────────────────────────────────┤
│ winit / gilrs(Rust 抽象)            │
├─────────────────────────────────────┤
│ libinput(Wayland 时代统一抽象)      │
├─────────────────────────────────────┤
│ evdev(Linux 内核事件接口)            │
├─────────────────────────────────────┤
│ 输入驱动(USB HID / PS/2 / Bluetooth)│
├─────────────────────────────────────┤
│ 硬件(键盘 / 鼠标 / 手柄)             │
└─────────────────────────────────────┘
```

- **evdev**:Linux 内核的通用输入事件接口。每个输入设备在 `/dev/input/eventN`,读它得到 `struct input_event`。
- **libinput**:Wayland 时代的输入抽象层(替代 X11 时代的 XInput2 / synaptics)。处理触摸板手势、加速度、按钮映射等。
- **winit**:在 Linux 上用 libinput(通过 Wayland)或 X11 XInput2。
- **gilrs**:游戏手柄专用,直接走 evdev(绕过 libinput,因为 libinput 对手柄支持弱)。

实战命令:

```bash
# 1. 列出所有输入设备
cat /proc/bus/input/devices
# 输出每个设备的 name、phys、capabilities

# 2. 看 evdev 设备
ls -la /dev/input/
# event0, event1, ...

# 3. 实时看一个设备的输入事件(比如 event3)
sudo pacman -S evtest
sudo evtest /dev/input/event3
# 按键时打印事件:type / code / value

# 4. 看你的手柄被识别成什么
udevadm info /dev/input/event15
# 看厂商 ID、产品 ID

# 5. 用 evtest 找 Xbox 手柄
for dev in /dev/input/event*; do
    echo "=== $dev ==="
    sudo evtest --query "$dev" 2>/dev/null | head -1
done
```

### 3.3 · 🦀 Rust 生态视角

Rust 输入相关 crate:

- **winit**:窗口 + 键盘 + 鼠标。我们用。
- **gilrs**:游戏手柄(支持 Xbox / PS / Switch / 任意)。
- **gilrs-core**:gilrs 的底层,更轻。
- **device_query**:全局键盘鼠标监听(不依赖窗口)。
- **wgpu**:图形,也带一些输入概念(主要是窗口事件转发)。
- **bevy_input**:ECS 风格,集成进 Bevy 引擎。
- **ash**:Vulkan FFI,不直接处理输入。

**gilrs 的设计**:

```rust
let mut gilrs = gilrs::Gilrs::new().unwrap();

// 主循环里
while let Some(event) = gilrs.next_event() {
    // 事件驱动(可选)
    match event.event {
        gilrs::EventType::ButtonPressed(gilrs::Button::South, _) => { /* A 按下 */ }
        _ => {}
    }
}

// 状态查询(主用)
for (id, gamepad) in gilrs.gamepads() {
    let a_pressed = gamepad.is_pressed(gilrs::Button::South);
    let left_stick = gamepad.state().left_stick();  // Vec2 { x, y }
    let trigger_left = gamepad.state().value(gilrs::Axis::LeftZ);  // -1 to 1
}
```

gilrs 自动检测设备插入 / 拔出。每个手柄有 stable ID(即使拔插后 ID 保留)。

**winit + gilrs 集成**:

```rust
use std::collections::HashSet;
use winit::keyboard::KeyCode;

struct App {
    keys: HashSet<KeyCode>,           // 键盘状态
    gilrs: gilrs::Gilrs,              // gilrs 状态
    input: GameInput,                  // 统一 GameInput
}

impl App {
    fn tick_input(&mut self) {
        // 1. previous = current
        for c in &mut self.input.controllers {
            for b in &mut c.buttons {
                b.previous_is_down = b.is_down;
            }
        }
        
        // 2. 键盘 → controllers[0]
        let c0 = &mut self.input.controllers[0];
        c0.buttons[BUTTON_UP].is_down = self.keys.contains(&KeyCode::ArrowUp) 
                                      || self.keys.contains(&KeyCode::KeyW);
        // ... 其他键
        
        // 3. 处理 gilrs 事件(更新内部状态)
        while let Some(_) = self.gilrs.next_event() {}
        
        // 4. 手柄 → controllers[1..5]
        let mut gamepad_idx = 1;
        for (_id, gamepad) in self.gilrs.gamepads() {
            if gamepad_idx >= 5 { break; }
            let c = &mut self.input.controllers[gamepad_idx];
            c.buttons[BUTTON_A].is_down = gamepad.is_pressed(gilrs::Button::South);
            c.buttons[BUTTON_B].is_down = gamepad.is_pressed(gilrs::Button::East);
            c.buttons[BUTTON_UP].is_down = gamepad.is_pressed(gilrs::Button::DPadUp);
            // ...
            let stick = gamepad.state().left_stick();
            c.stick_average_x = stick.x;
            c.stick_average_y = stick.y;
            gamepad_idx += 1;
        }
    }
}
```

**Rust 所有权 + 输入**:winit 的事件回调闭包持有 `&mut App`,改 `keys` 集合。借用检查器保证不会"边迭代边改"(常见 panic 源)。Rust 的 `HashSet` 不能边迭代边改,要先 collect 要改的,再统一改。

### 3.4 · 适配器模式(软件工程)

Casey 的设计是经典**适配器模式**(Adapter Pattern):

```
                Target(GameController 接口)
                     ▲
                     │ implements
        ┌────────────┼────────────┐
   KeyboardAdapter  GamepadAdapter  ...
```

适配器模式的好处:
1. **解耦**:游戏代码不知道具体设备
2. **扩展**:加新设备(Steam Deck、PS6)只加新 adapter,游戏代码不改
3. **测试**:可以写"假适配器"模拟输入,跑单元测试(无需真手柄)

业界广泛使用:
- JDBC(Java 数据库):不同数据库 → 统一接口
- ODBC(C 数据库):同上
- libc 文件 IO:不同文件系统 → 统一 read/write
- HAL(硬件抽象层):不同硬件 → 统一驱动接口

Casey 的输入抽象是适配器模式的最小教学版。

## 5 · 对照与变奏

### Edge vs Level 跨领域

edge / level 区分在电子工程、网络、状态机里都有:

| 领域 | edge | level |
|---|---|---|
| 数字电路 | 时钟上升沿触发 | 高电平持续有效 |
| 网络 | TCP FIN(连接关闭事件) | TCP ESTABLISHED(连接状态) |
| UI | onclick(点击事件) | :hover(悬停状态) |
| 游戏 | just_pressed(按键瞬间) | is_down(按住) |
| React useEffect | mount / unmount(组件生命周期事件) | render(每次状态) |

为什么所有领域都区分?因为人类思考就是"状态 vs 变化"二分。物理:位置 vs 速度。经济:存量 vs 流量。**用对的抽象解决对的问题**——这是优秀工程师的核心能力。

### 历史演化:输入抽象

- **1980s PC**:每个游戏自己处理 BIOS 键盘。`int 16h` 读键盘缓冲区。无抽象。
- **1990s**:DirectInput(Windows) / X11 XInput。平台级抽象。
- **2000s**:XInput(Xbox 360 手柄标准)。设备级抽象(所有 Xbox 兼容手柄用同一 API)。
- **2010s**:Steam Input。游戏级抽象(玩家可重映射)。
- **2020s**:SDL3 Gamepad API / WGI(Windows Gaming Input)。跨平台 + 自动适配。

Casey 在 Day 017 自己实现这个抽象,2014 年的事。今天有 Steam Input / SDL3 这种工业级方案,但 Casey 教学目的——让你理解每一行。

### Multi-touch / 触摸输入

触摸屏的输入抽象:每个手指 = 1 个"虚拟摇杆 + button"。多点触控 = 多个虚拟控制器。Casey 在 HH 全剧不涉及触摸(Windows PC 项目),但你做跨平台时要考虑。

Rust `winit` 支持 touch event:

```rust
WindowEvent::Touch(t) => { /* t.location, t.phase (Started/Moved/Ended) */ }
```

把 touch 适配到 controller 是另一个 adapter。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Casey 把 14 个 button 压缩到 1 个 u16 bitfield,而不是 `[bool; 14]`。压缩的好处和代价各 3 条。

**参考解答**:

**好处**:
1. **内存小**:2 字节 vs 14 字节(7×)。多 controller 时累积明显。
2. **cache 友好**:整个 controller 几十字节,几个 controller 在一个 cache line。
3. **序列化简单**:存档直接写 u16,不用逐 bool。
4. **批量操作**:重置 = `= 0`,比 for-loop 快。
5. **网络同步**:多人游戏,2 字节 vs 14 字节差 7× 带宽。

**代价**:
1. **可读性差**:`c.buttons & BUTTON_UP` 比 `c.buttons[UP]` 难懂。
2. **类型安全弱**:u16 可以是任意值,容易传错。`bitflags` 缓解。
3. **调试难**:调试器看 u16 数字,要心算二进制。
4. **扩展难**:超过 16 个 button 换 u32,改动大。
5. **不支持边缘值**:bool 可以是 true/false,bitfield 只能是 0/1,无法表达"half-pressed"(trigger 的中间值)。

**实战**:Rust 用 `bitflags` crate,兼顾性能和类型安全。trigger 用单独 f32 字段。

### Lv2 · 动手实践

**题**:在你的 Rust + winit 项目里实现统一 input 系统。要求:

1. GameInput + GameController + ButtonState 结构
2. 平台层每帧:`previous = current`,然后从 winit 键盘填 `controllers[0]`
3. 游戏代码用 `is_down` 控制方块移动(level),`just_pressed` 控制跳跃(edge)
4. 跑起来 WASD 移动方块,空格跳跃(跳跃时方块上升 + 重力下落)

完成标准:按住 W 方块持续上升一段距离,松开停止。连按空格跳跃两次(每次按只跳一次,因为 edge)。

**参考解答**:

```rust
use std::collections::HashSet;
use winit::keyboard::KeyCode;

#[derive(Copy, Clone, Default)]
pub struct ButtonState {
    pub is_down: bool,
    pub previous_is_down: bool,
}

impl ButtonState {
    pub fn just_pressed(&self) -> bool { self.is_down && !self.previous_is_down }
}

#[derive(Copy, Clone)]
pub struct GameController {
    pub buttons: [ButtonState; 14],
    pub stick_average_x: f32,
    pub stick_average_y: f32,
}

impl Default for GameController {
    fn default() -> Self {
        Self { buttons: [ButtonState::default(); 14], stick_average_x: 0.0, stick_average_y: 0.0 }
    }
}

pub const BUTTON_UP: usize = 10;
pub const BUTTON_DOWN: usize = 11;
pub const BUTTON_LEFT: usize = 12;
pub const BUTTON_RIGHT: usize = 13;
pub const BUTTON_A: usize = 0;

pub struct GameInput {
    pub controllers: [GameController; 5],
    pub dt: f32,
}

impl Default for GameInput {
    fn default() -> Self {
        Self { controllers: [GameController::default(); 5], dt: 0.0 }
    }
}

pub struct App {
    pub keys: HashSet<KeyCode>,
    pub input: GameInput,
    pub player: Player,
}

#[derive(Copy, Clone)]
pub struct Player {
    pub x: f32, pub y: f32,
    pub vy: f32,
    pub on_ground: bool,
}

impl App {
    pub fn tick_input(&mut self) {
        // previous = current
        for c in &mut self.input.controllers {
            for b in &mut c.buttons {
                b.previous_is_down = b.is_down;
            }
        }
        // 键盘 → controllers[0]
        let c = &mut self.input.controllers[0];
        c.buttons[BUTTON_UP].is_down = self.keys.contains(&KeyCode::KeyW) || self.keys.contains(&KeyCode::ArrowUp);
        c.buttons[BUTTON_DOWN].is_down = self.keys.contains(&KeyCode::KeyS) || self.keys.contains(&KeyCode::ArrowDown);
        c.buttons[BUTTON_LEFT].is_down = self.keys.contains(&KeyCode::KeyA) || self.keys.contains(&KeyCode::ArrowLeft);
        c.buttons[BUTTON_RIGHT].is_down = self.keys.contains(&KeyCode::KeyD) || self.keys.contains(&KeyCode::ArrowRight);
        c.buttons[BUTTON_A].is_down = self.keys.contains(&KeyCode::Space);
    }
    
    pub fn update(&mut self, dt: f32) {
        self.input.dt = dt;
        let c = self.input.controllers[0];
        
        // level: 移动
        let speed = 200.0;
        if c.buttons[BUTTON_LEFT].is_down { self.player.x -= speed * dt; }
        if c.buttons[BUTTON_RIGHT].is_down { self.player.x += speed * dt; }
        // (UP/DOWN 留给跳跃逻辑,2D 平面游戏水平移动)
        
        // edge: 跳跃
        if c.buttons[BUTTON_A].just_pressed() && self.player.on_ground {
            self.player.vy = -400.0;
            self.player.on_ground = false;
        }
        
        // 重力
        self.player.vy += 800.0 * dt;
        self.player.y += self.player.vy * dt;
        
        // 落地
        if self.player.y > 400.0 {
            self.player.y = 400.0;
            self.player.vy = 0.0;
            self.player.on_ground = true;
        }
    }
}
```

跑起来:按 D 方块右移,按 Space 跳跃,松开 Space 在空中不会二段跳(edge),落地后再按可以再跳。

```rust
// src/input_demo.rs
use winit::application::ApplicationHandler;
use winit::event::{WindowEvent, ElementState, KeyEvent};
use winit::event_loop::EventLoop;
use winit::keyboard::{KeyCode, PhysicalKey};
use winit::window::Window;
use std::collections::HashSet;
use std::sync::Arc;
use std::time::Instant;

const WIDTH: u32 = 960;
const HEIGHT: u32 = 540;
const GROUND_Y: f32 = 400.0;

#[derive(Copy, Clone, Default)]
pub struct ButtonState {
    pub is_down: bool,
    pub previous_is_down: bool,
}

impl ButtonState {
    pub fn just_pressed(&self) -> bool { self.is_down && !self.previous_is_down }
}

#[derive(Copy, Clone, Default)]
pub struct GameController {
    pub buttons: [ButtonState; 14],
}

pub const BUTTON_A: usize = 0;
pub const BUTTON_LEFT: usize = 12;
pub const BUTTON_RIGHT: usize = 13;

struct App {
    window: Option<Arc<Window>>,
    surface: Option<softbuffer::Surface<Arc<Window>, Arc<Window>>>,
    keys: HashSet<KeyCode>,
    controllers: [GameController; 1],  // 简化,只用 1 个 controller
    player_x: f32,
    player_y: f32,
    player_vy: f32,
    on_ground: bool,
    last_time: Instant,
}

impl App {
    fn new() -> Self {
        Self {
            window: None, surface: None,
            keys: HashSet::new(),
            controllers: [GameController::default()],
            player_x: 100.0, player_y: GROUND_Y,
            player_vy: 0.0, on_ground: true,
            last_time: Instant::now(),
        }
    }
    
    fn tick_input(&mut self) {
        for b in &mut self.controllers[0].buttons {
            b.previous_is_down = b.is_down;
        }
        let c = &mut self.controllers[0];
        c.buttons[BUTTON_LEFT].is_down = self.keys.contains(&KeyCode::KeyA) 
                                       || self.keys.contains(&KeyCode::ArrowLeft);
        c.buttons[BUTTON_RIGHT].is_down = self.keys.contains(&KeyCode::KeyD) 
                                        || self.keys.contains(&KeyCode::ArrowRight);
        c.buttons[BUTTON_A].is_down = self.keys.contains(&KeyCode::Space);
    }
    
    fn update(&mut self, dt: f32) {
        let c = self.controllers[0];
        let speed = 300.0;
        if c.buttons[BUTTON_LEFT].is_down { self.player_x -= speed * dt; }
        if c.buttons[BUTTON_RIGHT].is_down { self.player_x += speed * dt; }
        
        if c.buttons[BUTTON_A].just_pressed() && self.on_ground {
            self.player_vy = -500.0;
            self.on_ground = false;
        }
        
        self.player_vy += 1000.0 * dt;
        self.player_y += self.player_vy * dt;
        if self.player_y >= GROUND_Y {
            self.player_y = GROUND_Y;
            self.player_vy = 0.0;
            self.on_ground = true;
        }
    }
    
    fn render(&mut self) {
        if let Some(surface) = &mut self.surface {
            if let Ok(mut buf) = surface.buffer_mut() {
                // 清屏(蓝)
                for px in buf.iter_mut() { *px = 0xFF_FF_00_00; }  // 假设 BGRA 顺序
                
                // 画地面
                let ground_start = (GROUND_Y as u32 * WIDTH) as usize;
                for px in &mut buf[ground_start..] { *px = 0xFF_00_66_00; }  // 绿
                
                // 画玩家(50x50 红方块)
                let px = self.player_x as i32;
                let py = self.player_y as i32 - 50;  // 方块底在 player_y
                for dy in 0..50 {
                    for dx in 0..50 {
                        let xi = px + dx;
                        let yi = py + dy;
                        if xi >= 0 && (xi as u32) < WIDTH && yi >= 0 && (yi as u32) < HEIGHT {
                            buf[(yi as usize * WIDTH as usize) + xi as usize] = 0xFF_00_00_FF;
                        }
                    }
                }
                
                let _ = buf.present();
            }
        }
    }
}

impl ApplicationHandler for App {
    fn resumed(&mut self, event_loop: &winit::event_loop::ActiveEventLoop) {
        let window = Arc::new(event_loop.create_window(
            Window::default_attributes()
                .with_title("Day 017 Input")
                .with_inner_size(winit::dpi::LogicalSize::new(WIDTH, HEIGHT))
        ).unwrap());
        let context = softbuffer::Context::new(window.clone()).unwrap();
        let mut surface = softbuffer::Surface::new(&context, window.clone()).unwrap();
        let _ = surface.resize(
            std::num::NonZeroU32::new(WIDTH).unwrap(),
            std::num::NonZeroU32::new(HEIGHT).unwrap(),
        );
        self.window = Some(window);
        self.surface = Some(surface);
    }
    
    fn window_event(&mut self, event_loop: &winit::event_loop::ActiveEventLoop,
                    _id: winit::window::WindowId, event: WindowEvent) {
        match event {
            WindowEvent::CloseRequested => event_loop.exit(),
            WindowEvent::KeyboardInput { event: KeyEvent {
                state, physical_key: PhysicalKey::Code(code), ..
            }, .. } => {
                match state {
                    ElementState::Pressed => { self.keys.insert(code); }
                    ElementState::Released => { self.keys.remove(&code); }
                }
                if code == KeyCode::Escape { event_loop.exit(); }
            }
            WindowEvent::RedrawRequested => {
                let now = Instant::now();
                let dt = (now - self.last_time).as_secs_f32().min(0.1);
                self.last_time = now;
                
                self.tick_input();
                self.update(dt);
                self.render();
                
                if let Some(w) = &self.window { w.request_redraw(); }
            }
            _ => ()
        }
    }
}

fn main() {
    let event_loop = EventLoop::new().unwrap();
    let mut app = App::new();
    event_loop.run_app(&mut app).unwrap();
}
```
