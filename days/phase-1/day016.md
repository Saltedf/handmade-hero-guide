# Day 016 · 粒子与特效基础:从单像素到群体动力学

> Day 004 我们让一个绿色方块在屏幕上动起来。Day 016 让**几千个**方块同时动起来——这就是粒子系统(particle system)。爆炸的火花、烟雾、雨滴、星空、魔法光效,本质都是"大量小对象遵循简单物理规则"。理解粒子系统你就理解了"游戏引擎如何处理海量同类实体"——这是后面 Day 175+(SIMD 优化)、Day 305+(内存布局)的入门钥匙。

## 0 · 为什么要有这一天

你想象做一个爆炸效果。最直观的做法:

```rust
struct Spark {
    x: f32, y: f32,
    vx: f32, vy: f32,
    color: u32,
    life: f32,  // 剩余秒数
}
let mut sparks: Vec<Spark> = Vec::new();
// 爆炸时 spawn 500 个
for _ in 0..500 {
    sparks.push(random_spark());
}
// 每帧 update
for s in &mut sparks {
    s.x += s.vx * dt;
    s.y += s.vy * dt;
    s.life -= dt;
}
sparks.retain(|s| s.life > 0.0);
```

听起来没毛病,跑起来——CPU 飙到 30%,帧率掉到 30 FPS。为什么?

**问题 1:每帧分配**。爆炸时 `Vec::push` 500 次,Vec 内部可能 realloc 几次(扩容时复制所有元素)。Vec 增长策略是 2 倍,从空到 500 元素要 realloc 大约 9 次。每帧爆炸 = 每帧 realloc = 慢。

**问题 2:heap 分散**。多个爆炸 = 多个 Vec,内存碎片。CPU cache 上下文切换频繁,每次访问 sparks 都 miss。

**问题 3:retain 触发 memcpy**。`retain` 内部是"过滤 + 移动",保留的元素要往前挪。如果 1000 个里 500 死,要 memcpy 500 个元素。

**问题 4:逐个 update 不 SIMD 友好**。一个 Spark 是 24 字节(x,y,vx,vy = 16 字节 + color 4 字节 + life 4 字节)。CPU SIMD 一次能处理 4 个 f32,但你访问 `s.x` 时实际加载的是 24 字节的 Spark,只用了前 4 字节——SIMD 利用率 25%。

这些问题在"少量粒子"时无所谓(50 个 spark 你看不出差别),但**专业游戏粒子数量级是几千到几万**(爆炸 1000+、雨滴 5000+、烟雾 10000+)。这时优化与否决定 60 FPS 还是 5 FPS。

Casey 在 Day 016(对应教学扩展)讲粒子系统的**基础架构**:怎么 spawn、update、render 大量小对象。重点不是 SIMD(那是 Day 175+),而是**数据布局**——让数据"对 CPU 友好"。

**心理锚点**:读完今天,你能:

- 解释为什么"每个粒子一个 struct + Vec"在大量粒子时慢
- 写一个最简单的粒子系统(spawn / update / render / cleanup)
- 知道 SoA(struct of arrays)和 AoS(array of structs)的差别
- 理解对象池(object pool)为什么比 Vec 更适合粒子
- 在 Rust 项目里实现一个 1000 粒子不掉帧的爆炸效果
- 解释"structure of arrays"为什么是 SIMD 的前提

## 1 · Casey 今天做了什么

Casey 在 HH 早期(Day 16+)引入粒子系统的雏形,虽然他真正大改在 Day 175+(SIMD marathon)。具体动作:

1. 在游戏状态里加一个**粒子数组**—— Casey 用固定大小数组(比如 `Particle particles[1024]`),不用 Vec。这是 Day 014 Arena 思想的应用——预分配固定大小,避免运行时 alloc。
2. 每个粒子有 `position`, `velocity`, `color`, `life`(剩余秒数)等字段。
3. spawn 时找第一个 `life <= 0` 的"槽位"复用——这是**对象池**模式。
4. update 时遍历所有粒子,`life > 0` 的更新位置和速度,`life -= dt`。
5. render 时遍历,`life > 0` 的画到 framebuffer。

Casey 用固定大小数组 + 槽位复用的核心原因:**零分配**。1024 个粒子在游戏启动时就分配好(在 GameMemory 里),运行时不再 alloc/dealloc。这彻底消除了"每帧 alloc"的问题。

Day 175+ Casey 把这个数组改成 SoA 布局(SIMD 友好),那是一年后的事。Phase 1 我们先做最简单的"AoS + 对象池",够用。

## 2 · 心智模型

### 类比:粒子是"萤火虫群"

想象夏夜一群萤火虫。每只萤火虫:
- 有位置(在空中某点)
- 有速度(向某方向飞)
- 有亮度(随时间衰减)
- 有寿命(几秒后熄灭)

你**不需要指挥每一只**——你只需要给每只一个简单规则(随机方向飞、亮度衰减),群体涌现出"流动光点"的视觉。

粒子系统就是这种"群体涌现"的计算化表达:**每个粒子遵守简单规则,群体产生复杂视觉**。

爆炸、烟雾、雨滴、星空、火花、血溅、魔法光效——所有这些都是粒子系统的应用,区别只是粒子的初始分布、速度范围、颜色变化、寿命分布。

### 严谨:粒子的数据布局

最简单的粒子 struct:

```rust
#[derive(Copy, Clone)]
struct Particle {
    x: f32, y: f32,        // 位置
    vx: f32, vy: f32,      // 速度
    color: u32,             // ARGB
    life: f32,              // 剩余秒数,<=0 表示死亡
    max_life: f32,          // 初始寿命(用于 alpha 衰减)
}
```

8 个字段,每个 4 字节,共 32 字节。**正好一个 cache line 的 1/2**(cache line 是 64 字节)。

**AoS(Array of Structs)**:

```rust
struct ParticleSystem {
    particles: Vec<Particle>,  // [Particle; N]
}
```

`particles[0]`, `particles[1]`, `particles[2]`……每个 Particle 是连续 32 字节。

**SoA(Struct of Arrays)**:

```rust
struct ParticleSystem {
    xs: Vec<f32>,        // [x0, x1, x2, ...]
    ys: Vec<f32>,        // [y0, y1, y2, ...]
    vxs: Vec<f32>,
    vys: Vec<f32>,
    colors: Vec<u32>,
    lives: Vec<f32>,
    max_lives: Vec<f32>,
}
```

每个字段独立数组。

**两者对比**:

| | AoS | SoA |
|---|---|---|
| 访问一个粒子的所有字段 | 一次 cache load 拿全部 | 7 次独立 load |
| 访问所有粒子的同一字段(比如 update x) | 每个粒子浪费 28 字节(只用了 4) | 100% 利用 |
| SIMD 友好 | 差(数据间隔 32 字节) | 好(数据连续) |
| 编程方便 | 好(自然) | 麻烦(分散) |

**结论**:少量粒子 + 频繁访问单粒子全部字段 → AoS。大量粒子 + SIMD 批量处理 → SoA。

Casey 在 Day 016 用 AoS(简单,够用)。Day 175+ 切 SoA(性能需求)。Phase 1 我们用 AoS。

### 对象池(Object Pool)

最简单的对象池:`Vec<Particle>` 预分配固定大小,死掉的粒子用 `life <= 0` 标记,**不删除**。spawn 时找第一个 `life <= 0` 的槽位覆盖。

```rust
pub struct ParticleSystem {
    particles: Vec<Particle>,
}

impl ParticleSystem {
    pub fn new(capacity: usize) -> Self {
        Self {
            particles: vec![Particle::dead(); capacity],
        }
    }
    
    /// 找一个死槽位,spawn 新粒子
    pub fn spawn(&mut self, p: Particle) {
        for slot in &mut self.particles {
            if slot.life <= 0.0 {
                *slot = p;
                return;
            }
        }
        // 池满了,丢弃(生产代码可能扩展或用 LRU)
    }
    
    /// 每帧 update
    pub fn update(&mut self, dt: f32) {
        for p in &mut self.particles {
            if p.life > 0.0 {
                p.x += p.vx * dt;
                p.y += p.vy * dt;
                p.life -= dt;
                // 可选:重力、阻力
                p.vy += 200.0 * dt;  // 重力
            }
        }
    }
    
    /// 每帧 render 到 framebuffer
    pub fn render(&self, buffer: &mut [u32], width: usize) {
        for p in &self.particles {
            if p.life > 0.0 {
                let alpha_factor = (p.life / p.max_life).max(0.0);
                let xi = p.x as i32;
                let yi = p.y as i32;
                if xi >= 0 && (xi as usize) < width 
                    && yi >= 0 && (yi as usize) < buffer.len() / width {
                    let idx = yi as usize * width + xi as usize;
                    // 简化:alpha 衰减用亮度模拟(实际更复杂)
                    buffer[idx] = scale_color(p.color, alpha_factor);
                }
            }
        }
    }
}

#[derive(Copy, Clone)]
pub struct Particle {
    pub x: f32, pub y: f32,
    pub vx: f32, pub vy: f32,
    pub color: u32,
    pub life: f32,
    pub max_life: f32,
}

impl Particle {
    pub fn dead() -> Self {
        Self { x: 0.0, y: 0.0, vx: 0.0, vy: 0.0, color: 0, life: 0.0, max_life: 0.0 }
    }
}

fn scale_color(c: u32, factor: f32) -> u32 {
    let r = ((c >> 16) & 0xFF) as f32 * factor;
    let g = ((c >> 8) & 0xFF) as f32 * factor;
    let b = (c & 0xFF) as f32 * factor;
    0xFF_00_00_00 | ((r as u32) << 16) | ((g as u32) << 8) | (b as u32)
}
```

逐行解释:

- `vec![Particle::dead(); capacity]`——预分配 capacity 个"死"粒子。这一行只发生一次(初始化),运行时不再 alloc。
- `for slot in &mut self.particles { if slot.life <= 0.0 { *slot = p; return; } }`——线性找第一个死槽位。O(N) 但 N=1024 时几微秒,无所谓。
- `if p.life > 0.0 { ... }`——update 时跳过死粒子。这是对象池的核心——**死粒子不删,留着复用**。
- `p.life -= dt`——寿命递减,到 0 自动"死"。
- `scale_color` 把 RGB 按比例缩放,模拟 alpha 衰减(粒子越接近死亡越暗)。

### 为什么不用 `Vec::retain` 删死粒子?

两种做法对比:

**做法 A:对象池(本日)**——粒子死标记 `life <= 0`,不删除。spawn 时复用。

**做法 B:retain 删除**——`particles.retain(|p| p.life > 0.0)`,真删。

| | 对象池 | retain |
|---|---|---|
| 内存稳定 | 是(始终 capacity) | 否(增减) |
| Alloc/Free | 零 | 频繁 |
| Cache | 稳定 | 数据搬移 |
| 实现 | 稍复杂 | 简单 |

粒子系统**强烈推荐对象池**——粒子大量生死,频繁 alloc/dealloc 是性能杀手。

### Rust 所有权 + 粒子

粒子是 `Copy`(32 字节,小)。这意味着:

```rust
let p = particles[0];  // copy,不 move
particles[0].x = 5.0;   // 改的是 original
```

`Copy` 类型可以"按值复制"而不会让原值失效。对粒子这种小数据,`Copy` 让代码简单——不用担心"我已经 move 了所以原位置无效"。

如果粒子大(几百字节),不要 `Copy`,改用引用。

### SIMD 友好的预览

虽然 Phase 1 不写 SIMD,但理解为什么 SoA 友好:

AoS 布局 `[Particle; 4]` 在内存里:

```
[x0,y0,vx0,vy0,color0,life0,maxlife0,pad0,  ← 32 字节
 x1,y1,vx1,vy1,color1,life1,maxlife1,pad1,  ← 32 字节
 ...]
```

如果你要 update 所有粒子的 x(`p.x += p.vx * dt`),SIMD 一次 load 4 个 f32,但实际加载的是 `[x0,y0,vx0,vy0]`——不是 4 个 x。要拿到 4 个 x 要 gather 操作(慢)。

SoA 布局:

```
xs:   [x0,x1,x2,x3,x4,...]  ← SIMD load 一次拿 4 个 x
ys:   [y0,y1,y2,y3,y4,...]
vxs:  [vx0,vx1,vx2,vx3,...]
...
```

SIMD load 一次拿 4 个 x,4 个 vx,直接相加。**4 倍加速**。

Casey 在 Day 175 把粒子改成 SoA 后,1080p 渲染 10000 粒子从 30ms 降到 8ms。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏里粒子系统无处不在,分类:

**视觉效果**:
- 爆炸(火花向外辐射)
- 烟雾(粒子上升 + 扩散)
- 火焰(粒子向上 + 颜色从红到黄到暗)
- 雨/雪(粒子下落 + 风偏移)
- 魔法光效(粒子环绕 + 衰减)

**反馈效果**:
- 受击喷血(方向性粒子)
- 拾取闪光(从物体向外辐射)
- 升级粒子(围绕角色)

**环境效果**:
- 落叶(飘动)
- 萤火虫(随机移动 + 闪烁)
- 星空(缓慢移动)

每种效果本质都是"粒子 + 不同的初始参数 + 不同的 update 规则"。引擎(Unity / Unreal)提供"粒子编辑器",设计师可视化调参。Casey 在 HH Day 700+ 才有类似的工具,前期都是代码 hardcode。

**粒子系统的"工业标准"**:
- **GPU 粒子**(modern)——粒子数据在 GPU 显存,compute shader update,vertex shader render。允许百万级粒子。
- **CPU 粒子**(classic)——Casey 走这条。简单,但 CPU 限制几千到几万。

GPU 粒子需要 Day 235+ 的 OpenGL / wgpu 基础,所以 Phase 1-5 都是 CPU 粒子。

### 3.2 · 🎨 图形学视角

粒子渲染的本质是**点 sprite**——每个粒子是一个小图像(可能是单像素,可能是一张小贴图)。渲染算法:

**算法 1:像素直接画**(本日)——每个粒子在 framebuffer 上画 1 个像素。最简单,但视觉是"小点",不够"光晕"。

**算法 2:小矩形**——每个粒子画 8x8 矩形,中间亮边缘暗。看起来像光点。

**算法 3:billboard sprite**(后期)——每个粒子是一张小贴图(比如模糊的圆),始终面向相机。3D 游戏标准。

**算法 4:additive blending**(后期)——粒子重叠时颜色相加,产生明亮中心。爆炸 / 火焰效果的关键。

**算法 5:GPU instancing**(Day 235+)——GPU 一次画所有粒子,几千粒子开销极小。

Phase 1 我们用算法 1 或 2(像素 / 小矩形)。算法 3-5 后期再做。

### 3.3 · 🦀 Rust 生态视角

Rust 表达粒子系统的几个层次:

**层次 1:朴素 Vec**——最简单,适合学习。

```rust
struct World { particles: Vec<Particle> }
```

**层次 2:对象池**(本日)

```rust
struct World { particles: Vec<Particle> /* dead = life <= 0 */ }
```

**层次 3:`slotmap` crate**——代际索引,解决"删除后索引失效"问题。

```rust
use slotmap::SlotMap;
slotmap::new_key! { ParticleKey; }
let mut particles: SlotMap<ParticleKey, Particle> = SlotMap::new();
let k = particles.insert(Particle::new());
// k 是"带版本号的索引",即使删除复用也能区分
```

**层次 4:`bevy_ecs`**(ECS)——大量实体的高性能方案。

```rust
#[derive(Component)]
struct Particle { x: f32, y: f32, vx: f32, vy: f32, life: f32 }

fn update_particles(mut q: Query<&mut Particle>, time: Res<Time>) {
    for mut p in q.iter_mut() {
        p.x += p.vx * time.delta_seconds();
        p.life -= time.delta_seconds();
    }
}
```

ECS 自动用 SoA 布局,SIMD 友好。Bevy 引擎核心。

**层次 5:`nanostat` / `particles-rs`**——专门的粒子 crate。

**Phase 1 推荐**:层次 2(对象池)。理解原理,不依赖外部 crate。Phase 4+ 考虑 slotmap,ECS 留到 Day 200+。

### 3.4 · 数据导向设计(DOD)

粒子系统是 **Data-Oriented Design**(DOD)的最佳教学案例。DOD 的核心思想:

1. **先想数据**——粒子的内存布局是 SoA 还是 AoS?cache 怎么走?
2. **再想代码**——根据数据布局写代码

对比 **Object-Oriented Design**(OOD):

1. **先想对象**——Particle 是个 class,有 update() / render() 方法
2. **再想数据**——数据是对象的"内部状态"

DOD 比 OOD 在性能关键代码上**快几倍到几十倍**,因为 DOD 的数据布局 cache / SIMD 友好。游戏开发圈(尤其 Casey、Mike Acton、Eddie Smith)是 DOD 的强力倡导者。

OOD 粒子:

```rust
// OOD
impl Particle {
    fn update(&mut self, dt: f32) { self.x += self.vx * dt; ... }
    fn render(&self, buf: &mut [u32]) { ... }
}
for p in &mut particles { p.update(dt); }
for p in &particles { p.render(buf); }
```

DOD 粒子:

```rust
// DOD
fn update_particles(xs: &mut [f32], ys: &mut [f32], vxs: &[f32], vys: &[f32], dt: f32) {
    for i in 0..xs.len() {
        xs[i] += vxs[i] * dt;
        ys[i] += vys[i] * dt;
    }
}
```

DOD 函数**不绑定到具体粒子**,而是处理"一堆 x、一堆 y"。看似不优雅,但快得多——所有 x 连续,SIMD 友好,cache 命中率高。

Casey 在 HH Day 175+ 把代码从 OOD 改成 DOD,这是 Phase 4 性能优化的核心。

## 5 · 对照与变奏

### 同一问题:OOP vs DOP vs DOD

| | OOP | DOP(Data-Oriented Programming) | DOD(Data-Oriented Design) |
|---|---|---|---|
| 重点 | 对象 + 行为 | 数据 + 转换 | 数据布局 + 性能 |
| 单位 | object | data structure | memory layout |
| 性能 | 一般 | 好 | 极好 |
| 灵活 | 好 | 中 | 差(优化特定场景) |
| 例子 | Java / Python class | Clojure / 函数式 | C++ 游戏引擎 |

Casey 是 DOD 派(也带一点 DOP)。Java 风格游戏(Minecraft)是 OOP。现代 Rust 游戏倾向 DOD+ECS(Bevy)。

### 历史演化:粒子系统 40 年

- **1980s**:粒子概念提出(William Reeves, 1982 论文 "Particle Systems—a Technique for Modeling a Class of Fuzzy Objects")。电影《星际迷航 II》的"创世纪效果"首次用粒子系统。
- **1990s**:3D 游戏开始用粒子(雷神之锤的爆炸)。
- **2000s**:GPU 普及,粒子搬到 shader。但是 CPU 仍主流。
- **2010s**:compute shader 允许 GPU update 粒子。GPU 粒子普及。
- **2020s**:AI 加持,粒子可以根据场景动态调整(粒子神经网络生成)。

Casey 在 HH Day 016 走 1980s 路线(纯 CPU),Phase 5+ 走 2000s(GPU shader),Phase 7+ 可能尝试 2010s(GPU compute)。

### CPU 粒子 vs GPU 粒子

| | CPU | GPU |
|---|---|---|
| 数据位置 | 主存 | 显存 |
| Update | CPU 循环 | Compute shader |
| Render | 主存拷贝到 framebuffer | Vertex shader 直接画 |
| 数量上限 | ~10000 | ~1000000 |
| 编程复杂度 | 简单 | 复杂 |
| 延迟 | 几 ms | 几 μs(GPU 内部) |

Casey Phase 1-5 用 CPU。Day 235 切 OpenGL 后可考虑 GPU,但 HH 全剧都用 CPU 粒子(教学目的)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:粒子系统用"对象池"而不是 `Vec::retain` 删死粒子。对象池的两个核心好处是什么?各给一个具体场景。

**参考解答**:

**好处 1:零 alloc**。`retain` 内部触发元素移动(memcpy),频繁 retain 产生内存压力。对象池从不 alloc/dealloc,只是覆盖数据。

场景:战场游戏,每秒 100 次爆炸,每次 spawn 500 粒子。`retain` 方案每秒 alloc/dealloc 50000 次,通用分配器累死。对象池方案零 alloc。

**好处 2:cache 稳定**。对象池数据始终在同一块内存,CPU cache 训练得好(predictor 知道访问模式)。`retain` 后数据搬移,cache 失效。

场景:60 FPS 游戏,每帧访问 10000 粒子。对象池的 10000 粒子总在固定地址,cache 持续命中。retain 后内存碎片,新粒子可能分散,cache 频繁 miss。

**参考解答**:

```rust
use std::time::Instant;

const WIDTH: usize = 960;
const HEIGHT: usize = 540;
const PARTICLE_CAP: usize = 1000;

#[derive(Copy, Clone)]
struct Particle {
    x: f32, y: f32,
    vx: f32, vy: f32,
    color: u32,
    life: f32,
    max_life: f32,
}

impl Particle {
    const DEAD: Particle = Particle {
        x: 0.0, y: 0.0, vx: 0.0, vy: 0.0, color: 0, life: 0.0, max_life: 0.0,
    };
}

struct World {
    particles: Vec<Particle>,
    rng_state: u32,
}

impl World {
    fn new() -> Self {
        Self {
            particles: vec![Particle::DEAD; PARTICLE_CAP],
            rng_state: 12345,
        }
    }
    
    // 简单 LCG 伪随机数生成器
    fn rand(&mut self) -> f32 {
        self.rng_state = self.rng_state.wrapping_mul(1103515245).wrapping_add(12345);
        (self.rng_state >> 8) as f32 / 0x00FF_FFFF as f32
    }
    
    fn spawn_explosion(&mut self, cx: f32, cy: f32) {
        for _ in 0..500 {
            let angle = self.rand() * std::f32::consts::TAU;
            let speed = 100.0 + self.rand() * 200.0;
            let life = 1.0 + self.rand() * 1.0;
            let r = (200.0 + self.rand() * 55.0) as u32;
            let g = (100.0 + self.rand() * 100.0) as u32;
            let b = (self.rand() * 50.0) as u32;
            let color = 0xFF_00_00_00 | (r << 16) | (g << 8) | b;
            
            let new_p = Particle {
                x: cx, y: cy,
                vx: angle.cos() * speed,
                vy: angle.sin() * speed,
                color,
                life,
                max_life: life,
            };
            
            // 找死槽位
            for slot in &mut self.particles {
                if slot.life <= 0.0 {
                    *slot = new_p;
                    break;
                }
            }
        }
    }
    
    fn update(&mut self, dt: f32) {
        for p in &mut self.particles {
            if p.life > 0.0 {
                p.x += p.vx * dt;
                p.y += p.vy * dt;
                p.vy += 400.0 * dt;  // 重力
                p.life -= dt;
            }
        }
    }
    
    fn render(&self, buf: &mut [u32]) {
        for p in &self.particles {
            if p.life > 0.0 {
                let xi = p.x as i32;
                let yi = p.y as i32;
                if xi >= 0 && (xi as usize) < WIDTH 
                    && yi >= 0 && (yi as usize) < HEIGHT {
                    let factor = (p.life / p.max_life).max(0.0);
                    let idx = yi as usize * WIDTH + xi as usize;
                    let r = ((p.color >> 16) & 0xFF) as f32 * factor;
                    let g = ((p.color >> 8) & 0xFF) as f32 * factor;
                    let b = (p.color & 0xFF) as f32 * factor;
                    buf[idx] = 0xFF_00_00_00 
                        | ((r as u32) << 16) 
                        | ((g as u32) << 8) 
                        | (b as u32);
                }
            }
        }
    }
}
```

注意:

- `wrapping_mul` / `wrapping_add`——Rust 整数运算默认 debug 模式 panic on overflow,release wrap。显式 `wrapping_*` 在两种模式都 wrap,适合伪随机算法。
- `0x00FF_FFFF as f32`——24 位最大值,归一化到 [0, 1)。
- LCG(linear congruential generator)——最简单的伪随机算法。生产用 `rand` crate。

```rust
// src/particle_demo.rs
use winit::application::ApplicationHandler;
use winit::event::{WindowEvent, ElementState, KeyEvent};
use winit::event_loop::EventLoop;
use winit::keyboard::{KeyCode, PhysicalKey};
use winit::window::Window;
use std::sync::Arc;
use std::time::Instant;

const WIDTH: u32 = 960;
const HEIGHT: u32 = 540;

#[derive(Copy, Clone)]
struct Particle {
    x: f32, y: f32,
    vx: f32, vy: f32,
    color: u32,
    life: f32,
    max_life: f32,
}

impl Particle {
    const DEAD: Self = Self {
        x: 0.0, y: 0.0, vx: 0.0, vy: 0.0, color: 0, life: 0.0, max_life: 0.0,
    };
}

struct App {
    window: Option<Arc<Window>>,
    surface: Option<softbuffer::Surface<Arc<Window>, Arc<Window>>>,
    back_buffer: Vec<u32>,
    particles: Vec<Particle>,
    rng: u32,
    last_time: Instant,
    space_pressed: bool,
}

impl App {
    fn new() -> Self {
        Self {
            window: None, surface: None,
            back_buffer: vec![0u32; (WIDTH * HEIGHT) as usize],
            particles: vec![Particle::DEAD; 1000],
            rng: 12345,
            last_time: Instant::now(),
            space_pressed: false,
        }
    }
    
    fn rand(&mut self) -> f32 {
        self.rng = self.rng.wrapping_mul(1103515245).wrapping_add(12345);
        (self.rng >> 8) as f32 / 0x00FF_FFFF as f32
    }
    
    fn spawn_explosion(&mut self) {
        let cx = WIDTH as f32 / 2.0;
        let cy = HEIGHT as f32 / 2.0;
        for _ in 0..200 {
            let angle = self.rand() * std::f32::consts::TAU;
            let speed = 100.0 + self.rand() * 200.0;
            let life = 1.0 + self.rand();
            let r = 200 + (self.rand() * 55.0) as u32;
            let g = 100 + (self.rand() * 100.0) as u32;
            let b = (self.rand() * 50.0) as u32;
            let p = Particle {
                x: cx, y: cy,
                vx: angle.cos() * speed,
                vy: angle.sin() * speed,
                color: 0xFF_00_00_00 | (r << 16) | (g << 8) | b,
                life, max_life: life,
            };
            for slot in &mut self.particles {
                if slot.life <= 0.0 { *slot = p; break; }
            }
        }
    }
    
    fn update(&mut self, dt: f32) {
        for p in &mut self.particles {
            if p.life > 0.0 {
                p.x += p.vx * dt;
                p.y += p.vy * dt;
                p.vy += 400.0 * dt;
                p.life -= dt;
            }
        }
    }
    
    fn render(&mut self) {
        // 清屏
        for px in &mut self.back_buffer { *px = 0xFF_00_00_00; }  // 黑
        
        // 画粒子
        for p in &self.particles {
            if p.life > 0.0 {
                let xi = p.x as i32;
                let yi = p.y as i32;
                if xi >= 0 && (xi as u32) < WIDTH && yi >= 0 && (yi as u32) < HEIGHT {
                    let factor = (p.life / p.max_life).max(0.0);
                    let r = ((p.color >> 16) & 0xFF) as f32 * factor;
                    let g = ((p.color >> 8) & 0xFF) as f32 * factor;
                    let b = (p.color & 0xFF) as f32 * factor;
                    let idx = yi as usize * WIDTH as usize + xi as usize;
                    self.back_buffer[idx] = 0xFF_00_00_00 
                        | ((r as u32) << 16) | ((g as u32) << 8) | (b as u32);
                }
            }
        }
        
        // 显示
        if let Some(surface) = &mut self.surface {
            if let Ok(mut buf) = surface.buffer_mut() {
                buf.copy_from_slice(&self.back_buffer);
                let _ = buf.present();
            }
        }
    }
}

impl ApplicationHandler for App {
    fn resumed(&mut self, event_loop: &winit::event_loop::ActiveEventLoop) {
        let window = Arc::new(event_loop.create_window(
            Window::default_attributes()
                .with_title("Day 016 Particles")
                .with_inner_size(winit::dpi::LogicalSize::new(WIDTH, HEIGHT))
        ).unwrap());
        let context = softbuffer::Context::new(window.clone()).unwrap();
        let mut surface = softbuffer::Surface::new(&context, window.clone()).unwrap();
        let _ = surface.resize(
            std::num::NonZeroU32::new(WIDTH).unwrap(),
            std::num::NonZeroU32::new(HEIGHT).unwrap(),
        );
        self.window = Some(window);
        self.surface = Some(surface);
    }
    
    fn window_event(&mut self, event_loop: &winit::event_loop::ActiveEventLoop,
                    _id: winit::window::WindowId, event: WindowEvent) {
        match event {
            WindowEvent::CloseRequested => event_loop.exit(),
            WindowEvent::KeyboardInput { event: KeyEvent {
                state, physical_key: PhysicalKey::Code(code), ..
            }, .. } => {
                if code == KeyCode::Escape { event_loop.exit(); }
                if code == KeyCode::Space && state == ElementState::Pressed {
                    self.spawn_explosion();
                }
            }
            WindowEvent::RedrawRequested => {
                let now = Instant::now();
                let dt = (now - self.last_time).as_secs_f32().min(0.1);
                self.last_time = now;
                self.update(dt);
                self.render();
                if let Some(w) = &self.window { w.request_redraw(); }
            }
            _ => ()
        }
    }
}

fn main() {
    let event_loop = EventLoop::new().unwrap();
    let mut app = App::new();
    event_loop.run_app(&mut app).unwrap();
}
```
