# Day 007 · 音频入门:从 DirectSound 到 cpal

> 今天进入新世界:**声音**。Casey 在 Windows 上用 DirectSound(微软的旧版低延迟音频 API)。我们在 Linux 上用 `cpal` crate,跨平台音频抽象。音频和图形不同——它是**实时流式**(每秒持续生成几千个样本),错过一个样本就"咔嗒"杂音。今天先让程序发出**第一个声音**(方波蜂鸣),后面 Day 8-10 渐渐变成正弦波、变调、漂亮的音效。

## 0 · 为什么要有这一天

你已经能让画面动了,但游戏没声音是个哑巴游戏。要做声音,先理解几个核心概念:

- **声音是什么**:空气中压力的快速变化,人耳听到就是声音
- **数字音频怎么存**:每秒采样 N 次(44100 次/秒 = CD 质量),每次一个振幅值
- **怎么发声**:程序持续给声卡"喂"样本,声卡转成模拟电信号给喇叭
- **为什么"实时"**:不能像图片一样一帧一帧丢——必须**持续不间断**地喂样本,否则喇叭出杂音

这听起来抽象,具体到 Casey Day 7 的目标:**让程序发出 440Hz 蜂鸣**(电话响铃那种声音)。方法:每秒 48000 次给声卡一个数字,数字按方波规律在 +振幅 / -振幅跳变,喇叭震动 440 次/秒,听起来就是 440Hz 蜂鸣(La 音)。

我们用 `cpal` 替代 DirectSound。cpal 的 API 模型完全不同(DirectSound 是"环形缓冲 + 自己写",cpal 是"回调 + 库拉")。今天先把 cpal 跑通,Day 8 详细对比两种模型。

**心理锚点**:读完今天,你能:

- 解释声音数字化的原理:采样率 / 位深 / 声道
- 写出方波的数学公式,生成一段方波样本
- 用 cpal 创建一个输出流,听到 440Hz 蜂鸣
- 解释为什么音频必须用独立线程(不能在主循环里画一帧的时间挤出音频时间)
- 用 `cargo add cpal` 跑通最小音频例子

## 1 · Casey 今天做了什么

Casey Day 7 的核心动作:

1. 加载 DirectSound DLL:`DirectSoundCreate8` 拿到 `LPDIRECTSOUND8` 设备对象
2. 设合作级别 `SetCooperativeLevel(hwnd, DSSCL_PRIORITY)`(告诉 Windows"我要中级优先级",免得独占声卡)
3. 创建"主缓冲"(primary buffer,声卡硬件直接播放):`CreateSoundBuffer(&buffer_desc, &primary_buffer, NULL)`,`buffer_desc.dwFlags = DSBCAPS_PRIMARYBUFFER`
4. 设置主缓冲格式(`SetFormat(&wave_format)`):采样率 48000,16-bit,立体声(2 通道)
5. 创建"副缓冲"(secondary buffer,我们写入的缓冲):大小 48000 * 2 * 2 = 192000 字节(1 秒音频)
6. **当天不写声音**,只是把管道搭好

DirectSound 的"主缓冲 + 副缓冲"设计有点怪:用户写副缓冲,DirectSound 自己 mix 到主缓冲,主缓冲送给声卡。这是 1990s 设计,后来被 WASAPI 取代。

我们 cpal 这边**不需要主缓冲**,直接给 cpal 一个回调函数,它替你管。

## 2 · 心智模型

### 类比:音频是"水龙头"

想象一个水龙头:

- **水**:样本(数字)
- **水流**:采样率(每秒流多少)
- **水管粗细**:位深(每个样本多少 bit)
- **多管道**:声道(1 个 = 单声道,2 个 = 立体声)
- **水龙头必须持续流**:不然空气进入水管(= 杂音)

你的程序是**水源**,cpal/声卡是**水管 + 水龙头**。你必须**持续**给 cpal 样本,不能停。

### 声音的物理基础

声音 = 空气压力的快速变化。人耳能听 20Hz - 20000Hz(每秒震动 20-20000 次)。

- 440Hz:La 音(中央 A)
- 261.63Hz:中央 C(do)
- 越高频越"尖"(鸟叫),越低频越"闷"(雷声)

**音量**:压力变化幅度。振幅大 = 声音响。
**音高**:频率。频率高 = 音高高。
**音色**:波形形状。方波 = 蜂鸣,正弦波 = 纯音,锯齿波 = 弦乐感。

### 数字音频:采样定理

**Nyquist-Shannon 采样定理**:要重建最高频率 F 的信号,采样率必须 > 2F。

- 人耳最高 20000Hz
- 采样率至少 40000Hz
- CD 用 44100Hz(留 10% 余量)
- 游戏 / 视频常用 48000Hz
- 高质量音频用 96000Hz 或 192000Hz

**位深**(每个样本多少 bit):

- 8-bit:256 级,质量差(老游戏)
- 16-bit:65536 级,CD 质量
- 24-bit:16777216 级,工作室
- 32-bit float:专业处理

游戏用 **16-bit 或 32-bit float**(后者更方便计算,无溢出)。

**声道**:

- mono:1 通道(老电话)
- stereo:2 通道(左 + 右)
- 5.1 / 7.1:多通道(影院)

游戏一般 stereo。

### 采样数 = 采样率 × 时长 × 声道

1 秒 48kHz stereo 16-bit = 48000 × 2 × 2 = 192000 字节。
1 帧(1/60 秒)48kHz stereo float = 48000/60 × 2 × 4 = 6400 字节。

游戏每帧 60 FPS,音频每帧需要 800 个样本(每声道 800 个 float)。

### 方波公式

方波是最简单的"蜂鸣"声:

```rust
// 440Hz 方波,采样率 48000,持续 1 秒
let freq = 440.0;
let sample_rate = 48000.0;
let samples_per_cycle = sample_rate / freq;  // 109.09
for i in 0..48000 {
    let t = i as f32 / sample_per_cycle;  // 当前是第几个"周期内位置"
    let sample = if (i as f32 % samples_per_cycle) < samples_per_cycle / 2.0 {
        1.0
    } else {
        -1.0
    };
    // sample 是 ±1.0,放大成 ±0.5 写到声卡
}
```

简化:

```rust
fn square_wave(i: usize, freq: f32, sample_rate: f32) -> f32 {
    let period = sample_rate / freq;
    if (i as f32 % period) < period / 2.0 { 1.0 } else { -1.0 }
}
```

**听觉效果**:刺耳的"嘀——"。电话听筒拿起来的声音。

### 正弦波公式(预告)

```rust
fn sine_wave(i: usize, freq: f32, sample_rate: f32) -> f32 {
    let t = i as f32 / sample_rate;            // 秒
    (2.0 * std::f32::consts::PI * freq * t).sin()
}
```

更"圆滑"的纯音,像音叉。Casey 在 Day 9 切到正弦。

### cpal 的 API 模型

cpal 是**回调风格**:

```rust
use cpal::{Stream, traits::*};

// 1. 创建设备枚举器
let host = cpal::default_host();
let device = host.default_output_device().unwrap();

// 2. 创建输出流配置
let config = device.default_output_config().unwrap();
let sample_rate = config.sample_rate().0;
let channels = config.channels();

// 3. 创建流(回调里写样本)
let stream = device.build_output_stream(
    &config.into(),
    move |data: &mut [f32], _: &cpal::OutputCallbackInfo| {
        // cpal 给你一段 data(比如 1024 个样本),你填进去
        for sample in data.iter_mut() {
            *sample = 0.0;  // 这里写音频样本
        }
    },
    |err| eprintln!("audio error: {}", err),
    None,
).unwrap();

// 4. 启动流
stream.play().unwrap();

// 5. 流必须保持 alive(它在独立线程跑)
std::mem::forget(stream);  // 或保持持有
```

**关键概念**:

- **Host**:cpal 的平台后端抽象(Linux ALSA / PulseAudio / JACK / Wasapi / CoreAudio)
- **Device**:具体音频设备(默认输出 / 蓝牙耳机 / HDMI)
- **Stream**:持续的音频流,有自己的线程
- **Callback**:cpal 调你的回调,参数 `data: &mut [f32]` 是要填的样本

cpal **自己有一个音频线程**,你给它回调,它在音频线程调你。你的主线程专心做游戏逻辑 + 渲染。

### 为什么音频要独立线程

声卡硬件每隔一段时间(比如 10ms)要新一批样本,否则喇叭出杂音。如果你在主线程 60 FPS 渲染,某帧卡了(20ms),声卡拿不到样本 → 杂音。

cpal 的音频线程优先级高,操作系统保证它定时跑。主线程慢一点没关系。

### 音量和钳制

cpal 的样本是 `f32`,范围 `-1.0 ~ 1.0`。超出会被声卡**钳制**(clamp)到 ±1.0,产生失真。

```rust
let sample = (sample * 0.5).clamp(-1.0, 1.0);  // 音量 50%,防失真
```

游戏里"主音量"+"音效音量"+"音乐音量"叠加,要保证不溢出。

### cpal 的 sample format

cpal 默认 sample format 可能是 `f32` / `i16` / `u16`。`f32` 最方便计算,大多数现代后端支持。

```rust
match config.sample_format() {
    cpal::SampleFormat::F32 => device.build_output_stream::<f32, _, _>(...),
    cpal::SampleFormat::I16 => device.build_output_stream::<i16, _, _>(...),
    cpal::SampleFormat::U16 => device.build_output_stream::<u16, _, _>(...),
    _ => panic!("unsupported"),
}
```

我们用 `f32`。

## 3 · 四域深入

### 3.1 · 🐧 Linux 系统编程视角

#### Linux 音频栈层次

```
应用
 │
 ├─ cpal ──→ ALSA / PulseAudio / JACK / PipeWire
 │             │
 │             ├─ ALSA(libasound)──→ 内核 ALSA 子系统 ──→ 声卡驱动 ──→ 硬件
 │             │
 │             ├─ PulseAudio(网络/桌面音频服务器)
 │             │
 │             ├─ JACK(专业音频,低延迟)
 │             │
 │             └─ PipeWire(2020s 统一 Pulse + JACK)
 │
 └─ (应用也可以直接调 ALSA,但 cpal 已经包了)
```

**ALSA**(Advanced Linux Sound Architecture):

- 内核子系统,直接管声卡
- 用户库 `libasound`
- 延迟最低,但 API 复杂
- 通常不直接用,被 Pulse/JACK/PipeWire 包

**PulseAudio**(2004-):

- 桌面音频服务器
- 网络透明(可远程音频)
- 抽象 ALSA,允许程序混合(多个程序同时出声)
- 缺点:延迟较高(几十 ms)

**JACK**(2002-):

- 专业音频(音乐制作)
- 低延迟(< 5ms)
- 复杂的图路由(程序间连音频)

**PipeWire**(2015-,2020s 主流):

- 统一 PulseAudio + JACK
- Wayland 推荐默认
- 现代设计,支持视频流

cpal 在 Linux 上可以选不同后端(通过 feature):

```toml
[dependencies]
cpal = { version = "0.15", features = ["asio"] }  # Windows ASIO
# Linux 默认 ALSA
```

#### 验证你的音频栈

```bash
# 看当前用什么音频服务器
ps aux | grep -iE "pulseaudio|pipewire|jackd" | head

# PipeWire 通常是
ps aux | grep pipewire
# 也可能看到 wireplumber(PipeWire 的会话管理器)

# 看声卡(ALSA 层)
aplay -l
# 输出:card 0: PCH [HDA Intel PCH], device 0: ...
# 列出所有播放设备

# 看默认设备
pacmd list-sinks | grep name  # PulseAudio
pw-dump | grep name  # PipeWire

# 测试声音
speaker-test -t sine -f 440 -l 1
# 应该听到 1 秒 440Hz 正弦
```

#### cpal 默认用哪个后端?

```bash
# 看 cpal 编译时启用了哪个后端
cargo build -vv 2>&1 | grep cpal | grep -E "feature" | head
# 通常默认 ALSA(Linux)

# 强制指定后端(在 Cargo.toml)
[dependencies]
cpal = { version = "0.15", default-features = false, features = ["jack"] }
# 这样用 JACK,不用 ALSA

# PipeWire 通过 JACK 兼容层支持,所以 cpal 选 jack 也能用 pipewire-pulse
```

### 3.2 · 🦀 Rust 生态视角

#### cpal 的 trait 设计

```rust
// 设备 trait
pub trait DeviceTrait {
    type Stream: StreamTrait;
    fn default_output_config(&self) -> Result<SupportedStreamConfig, ...>;
    fn build_output_stream<T, D, E>(...) -> Result<Self::Stream, ...>;
    // ...
}

// 流 trait
pub trait StreamTrait {
    fn play(&self) -> Result<()>;
    fn pause(&self) -> Result<()>;
}
```

为什么用 trait 而不是 struct?因为不同平台(Linux ALSA / Windows WASAPI / macOS CoreAudio)的 Stream 类型不同。trait 让 cpal 的 API 跨平台。

使用:

```rust
use cpal::traits::{DeviceTrait, HostTrait, StreamTrait};
```

每次用 cpal 都要 `use traits::*`。这是 Rust 生态"trait 接口"模式。

#### 流的所有权

```rust
let stream = device.build_output_stream(...).unwrap();
stream.play().unwrap();
// stream 在这里 drop → 流停止!
```

**关键陷阱**:Stream drop 时音频流也停。所以你要么:

1. 把 stream 保存在长生命周期 struct 里
2. 用 `std::mem::forget(stream)`(永不 drop,泄漏但有意的)
3. 用 `parking_lot::Mutex<Option<Stream>>` 之类

我们的 App 里:`audio_stream: Option<cpal::Stream>`。

#### 回调的 Send 要求

```rust
device.build_output_stream(
    &config,
    move |data, info| { /* 回调 */ },
    |err| { /* 错误处理 */ },
    None,
)
```

回调闭包必须 `Send`(可能跨线程)。如果你在闭包里捕获了 `&mut App`,App 必须 `Send`。

但 App 里有 winit 的 Window,**Window 不 Send**(窗口操作必须在主线程)!怎么办?

**解决**:用 channel 通信。主线程把"当前游戏状态"塞进 channel,音频线程从 channel 读:

```rust
use crossbeam_channel::{unbounded, Sender, Receiver};

let (tx, rx) = unbounded::<AudioCommand>();
// 主线程:tx.send(...)
// 音频线程:rx.try_recv()

let stream = device.build_output_stream(
    &config,
    move |data, _| {
        // 这里能用 rx
        let freq = match rx.try_recv() {
            Ok(AudioCommand::SetFreq(f)) => f,
            Err(_) => 0.0,  // 没新命令,保持
        };
        for sample in data.iter_mut() {
            *sample = ...;
        }
    },
    |err| eprintln!("audio err: {}", err),
    None,
).unwrap();
```

这个模式贯穿整个 Rust 并发编程。

#### f32 SIMD-friendly

`f32` 数组是 SIMD 优化的最佳对象。我们生成音频样本时:

```rust
for sample in data.iter_mut() {
    *sample = compute_sample();
}
```

Rust 编译器会自动向量化(如果 `compute_sample` 简单)。

### 3.3 · 🎮 游戏编程视角

#### 游戏音频的两大类

1. **音效(SFX)**:跳跃、攻击、爆炸。短(几百 ms),按事件触发
2. **背景音乐(BGM)**:循环的长音乐(几分钟),持续播放

实现方式不同:

- SFX:在内存里存 WAV/OGG 数据,触发时 mix 到输出流
- BGM:流式解码(从磁盘读一部分,解码,送声卡),避免占用太多内存

Casey 在 Day 8-10 做"程序化音效"(方波 / 正弦波),Day 100+ 才涉及 WAV 加载和 BGM。

#### 音频延迟(Latency)

延迟 = 你"做某事"(按键)到"听到对应声音"的时间。

- 100ms+:明显延迟,玩家觉得"反应慢"
- 50ms:可接受
- < 20ms:专业音频
- < 5ms:乐器演奏级

游戏目标:< 50ms。瓶颈:

- 缓冲大小:大缓冲 = 延迟高 + 稳定;小缓冲 = 延迟低 + 可能杂音
- 操作系统调度:音频线程要按时被调度
- 采样率:48kHz 比 44.1kHz 延迟略低

cpal 默认缓冲大小由系统决定,可以指定(`StreamConfig::buffer_size`)。

#### 实时音频编程的禁忌

音频回调里**绝对不能**做:

- 分配内存(`Vec::new`、`Box::new`)— 分配器锁,阻塞
- 锁(`Mutex::lock`)— 可能死锁
- IO(文件 / 网络)— 阻塞
- 复杂计算 — 可能超过回调时长

回调里只能:

- 写样本(算术)
- 从预分配的 ring buffer 读
- 从 lock-free channel 收消息(`try_recv`,不能 `recv`)

违反规则 → 杂音 / 卡顿。

### 3.4 · 🎨 图形学视角

不直接涉及。但有一个类比:**音频流 = 像素流的"时间版"**。

- 渲染:每帧画一屏像素,60 帧/秒
- 音频:每秒流 48000 个样本,持续不断

差别:渲染可以丢帧(玩家可能察觉,但游戏继续),音频不能丢样本(杂音立即可听)。所以音频优先级比渲染高。

## 4 · 认知地图

### 4.1 上级

- **数字信号处理**(DSP)— 处理时间序列数据(音频是典型)
- **实时系统**(Real-time System)— 必须在截止时间前响应

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|

| WASAPI | Windows 现代低延迟 | Windows-only 专业 | 不用 |
| Core Audio | macOS / iOS | macOS-only | 不用 |
| ALSA | Linux 内核级 | Linux-only 极致 | cpal 后端 |
| JACK | Linux 专业音频 | 音乐制作 | 不用 |
| `rodio` | cpal 的高级封装,支持 WAV/MP3 | 简单播放文件 | 不用(我们手写) |
| `kira` | 游戏音频库 | 商业游戏 | 不用 |

### 4.3 下级

- `Host` — cpal 平台后端

- `Channel` — 声道(左 / 右)

## 5 · 对照与变奏

### DirectSound vs cpal

| 概念 | DirectSound(Casey) | cpal(Rust) |
|---|---|---|
| 初始化 | `DirectSoundCreate8` + `SetCooperativeLevel` | `cpal::default_host()` |
| 主缓冲 | 必须创建 + 设置格式 | (隐藏,库自动) |
| 副缓冲 | 用户创建,大小固定 | cpal 自己管,你填回调 |
| 写样本 | `Lock` + memcpy + `Unlock`(环形缓冲) | 回调里直接写 `&mut [f32]` |
| 主循环位置 | `GetCurrentPosition` | (隐藏,回调自动调) |
| 缓冲模型 | push(你写,库读) | pull(库调你,你填) |

cpal 的 pull 模型更现代:你不用算"现在该写哪段",库定时调你,你填就好。

### Linux 音频栈历史

- **1990s**:OSS(Open Sound System),Unix 早期音频
- **2000s**:ALSA 取代 OSS,更灵活
- **2004**:PulseAudio 出现,做桌面音频混合
- **2002**:JACK 出现,专业音频
- **2015**:PipeWire 项目开始
- **2020+**:PipeWire 成为发行版默认(GNOME / KDE 都切了)

cpal 在 ALSA 后端可以同时和 PulseAudio / PipeWire 工作(它们提供 ALSA 兼容接口)。

### Lv1 · 概念辨析

**题**:为什么音频回调里不能分配内存?如果分配了会怎样?

**参考解答**:

音频回调运行在**实时音频线程**,每 N 毫秒被调用一次(N 由缓冲大小决定,通常 5-20ms)。回调必须**保证在 N 毫秒内返回**,否则声卡拿不到样本,产生"咔嗒"杂音或音频断续。

如果回调里分配内存(`Vec::new`、`Box::new`):

1. **分配器锁**:大多数 Rust allocator(jemalloc / mimalloc / 系统 malloc)是线程安全的,通过 mutex 保护内部状态。音频线程锁 wait,可能等几十 ms(如果其他线程持锁)
2. **不可预测**:分配可能触发系统调用(`mmap`),延迟不确定
3. **碎片化**:频繁分配释放导致堆碎片,长期影响性能

**正确做法**:

- 回调外预分配所有缓冲
- 回调内只做算术 / 读写预分配内存
- 用 lock-free channel(`crossbeam_channel` `try_recv`)传消息,**不阻塞**

Cpal 的回调签名要求 `Send + 'static`,但内部仍可能在你不知情下分配。要严格审查。

### Lv2 · 动手实践

**题**:用 cpal 让程序发出 440Hz 方波蜂鸣,持续 3 秒后自动停止。完成标准:跑程序后听到 3 秒蜂鸣,然后程序退出。

**参考解答**:

```bash
# 加依赖
cargo add cpal
```

```rust
// src/main.rs(单独的音频测试程序,不和 winit 混)

use cpal::traits::{DeviceTrait, HostTrait, StreamTrait};
use cpal::{SampleFormat, StreamConfig};
use std::sync::{Arc, Mutex};
use std::time::{Duration, Instant};

fn main() {
    // 1. 获取默认 host 和设备
    let host = cpal::default_host();
    let device = host.default_output_device()
        .expect("no output device available");
    println!("Using device: {}", device.name().unwrap());

    // 2. 获取默认配置
    let supported_config = device.default_output_config()
        .expect("no default config");
    let sample_format = supported_config.sample_format();
    let config: StreamConfig = supported_config.into();
    let sample_rate = config.sample_rate.0 as f32;
    let channels = config.channels() as usize;
    println!("Sample rate: {}, channels: {}, format: {:?}",
             sample_rate, channels, sample_format);

    // 3. 共享状态:音频用
    let start_time = Arc::new(Mutex::new(Instant::now()));
    let start_for_callback = start_time.clone();

    // 4. 创建流(根据 sample format)
    let stream = match sample_format {
        SampleFormat::F32 => device.build_output_stream(
            &config,
            move |data: &mut [f32], _: &cpal::OutputCallbackInfo| {
                let start = *start_for_callback.lock().unwrap();
                let elapsed = start.elapsed().as_secs_f32();
                
                // 超过 3 秒,输出静音
                if elapsed > 3.0 {
                    for s in data.iter_mut() { *s = 0.0; }
                    return;
                }
                
                // 生成方波
                let freq = 440.0;
                let period = sample_rate / freq;
                let samples_so_far = (elapsed * sample_rate) as usize;
                
                for (i, frame) in data.chunks_mut(channels).enumerate() {
                    let global_i = samples_so_far + i;
                    let sample_val = if (global_i as f32 % period) < period / 2.0 {
                        0.2  // 音量 20%(防止炸耳朵)
                    } else {
                        -0.2
                    };
                    for s in frame.iter_mut() {
                        *s = sample_val;
                    }
                }
            },
            |err| eprintln!("stream error: {}", err),
            None,
        ).unwrap(),
        _ => panic!("Unsupported sample format"),
    };

    stream.play().unwrap();
    println!("Playing 440Hz square wave for 3 seconds...");

    // 5. 等 3.5 秒,确保所有缓冲播完
    std::thread::sleep(Duration::from_millis(3500));
    println!("Done");
    
    // stream 在这里 drop,自动停止
}
```

跑:

```bash
cargo run --release
# 输出:
# Using device: Built-in Audio Analog Stereo
# Sample rate: 48000, channels: 2, format: F32
# Playing 440Hz square wave for 3 seconds...
# (3 秒蜂鸣声)
# Done
```

**注意**:

- 音量设 0.2(20%),方波已经很刺耳,1.0 会损伤耳朵
- `chunks_mut(channels)` 是因为一个 frame 有多个声道,我们对每个声道写同样的样本
- `start.elapsed()` 算经过时间,3 秒后输出静音(不是停止流——停止需要 `stream.pause()`)

### Rust 模式:`Send + 'static` 闭包

```rust
// cpal 回调要求闭包 Send + 'static
// 因为它在另一个线程跑

// 这能用(闭包不捕获不 Send 的东西):
let v = Arc::new(Mutex::new(0u32));
let v_clone = v.clone();
device.build_output_stream(
    &config,
    move |data, _| {
        let n = *v_clone.lock().unwrap();
        for s in data.iter_mut() { *s = n as f32 / 100.0; }
    },
    |err| (),
    None,
).unwrap();

// 这不能用(闭包捕获 &App,App 不 Send,因为含 Window):
let app_ref = &app;
device.build_output_stream(
    &config,
    move |data, _| {
        app_ref.do_something();  // 编译错误!
    },
    |err| (),
    None,
).unwrap();
// error: closure may outlive ..., but it borrows `app_ref`
```

**解决**:用 channel 通信(见 Lv3 提示)。

### Troubleshooting

- **无声**:检查音量(系统 + 程序),检查默认输出设备
- **杂音**:回调里耗时太长,可能分配了内存
- **panic "no output device"**:ALSA 没找到设备,确认 `aplay -l` 有输出
- **`error creating stream: DeviceUnavailable`**:设备被独占(某些程序锁了),关掉它们
- **cpal 编译错误**:装 `alsa-lib`,`sudo pacman -S alsa-lib`
- **延迟高**:试 JACK 后端或调缓冲大小
