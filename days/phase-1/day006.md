
# Day 006 · 键盘输入:从按键到状态机

> Day 4 让画面动起来了,但游戏世界只按时间变,玩家无法干预。今天加**键盘输入**:按住方向键改变滚动方向,按空格暂停。重点不是"调哪个 API",而是理解**事件(event)vs 状态(state)** —— 这是输入系统的核心抽象,后面所有游戏输入都建立在这上面。

## 0 · 为什么要有这一天

你以为"读键盘"很容易:`get_key()` 返回当前按下的键。但实际游戏里有这些需求:

- "按住右方向键,小人往右走" —— 关心**持续按下**(state)
- "按空格,跳跃" —— 关心**按下瞬间**(press event),按住不算跳
- "松开 E 键时,丢出物品" —— 关心**松开瞬间**(release event)
- "短按 vs 长按区分":短按 1 是攻击,长按 1 是蓄力 —— 需要**按住时长**
- "组合键:Ctrl+S 保存" —— 同时按住 Ctrl + S

这些需求是**不同维度**的。事件适合"瞬间动作",状态适合"持续行为"。混淆它们,你的游戏会出 bug:

- 用 event 实现移动:每帧收到一次 KeyDown,小人**瞬移**(因为只在事件那一帧移动)
- 用 state 实现跳跃:小人**一直跳**(因为按住空格 = state true)

今天 Casey 把这两者分开。Casey Day 6 的核心:**累积键盘事件到状态数组**,主循环用 state 决定行为。我们用 winit 的 `KeyboardInput` 事件,做一样的事。

**心理锚点**:读完今天,你能:

- 解释"事件" vs "状态",各适合什么场景
- 写一个 `KeyboardState` struct,记录每个键的当前按下状态
- 实现"按下瞬间" / "松开瞬间" / "持续按下"三种语义
- 解释 winit 的 `KeyEvent`、`ElementState`(Pressed/Released)、`PhysicalKey`
- 让方向键控制 Day 4 的渐变滚动方向,空格暂停

## 1 · Casey 今天做了什么

Casey Day 6 的核心动作:

1. 在 `WindowProc` 的 `WM_SYSKEYDOWN` / `WM_KEYDOWN` 分支里设 `KeyCode[VK] = true`
2. `WM_SYSKEYUP` / `WM_KEYUP` 设 `KeyCode[VK] = false`
3. 主循环里读 `KeyCode[VK_LEFT]` 等,决定行为
4. Casey 强调:不要在事件处理里直接做事(比如看到 W 按下就让小人走),而要**记录到状态数组,主循环用状态**

Casey 还预告了 Day 6+ 的手柄处理(XInput),但当天只讲了键盘。

我们这边 winit 直接给 `KeyboardInput` 事件,有 `state: ElementState`(Pressed/Released)和 `physical_key: PhysicalKey`。比 Win32 的 `wParam`(virtual key code)更清晰。

## 2 · 心智模型

### 类比:键盘是"两组灯"

想象你的键盘有两组灯:

1. **当前状态灯**:每个键一个 LED,按下亮,松开灭。**任何时候你都能看一眼知道哪个键亮着**——这就是**状态**。
2. **事件日志**:每次按键 / 松键打印一条"X 在 12:34:56 被按下"。如果你不读日志,就错过这条——这就是**事件**。

游戏需要两者:

- 状态:`is_key_down(KeyW)` 每帧检查,持续按下持续走
- 事件:`on_key_press(KeySpace)` 单次触发,跳跃只跳一次

### 状态 vs 事件:对照表

| 维度 | 状态(State) | 事件(Event) |
|---|---|---|
| 持续性 | 持续,直到改变 | 瞬间,过去了就过去 |
| 查询方式 | 任何时候查 | 必须订阅 / 缓存 |
| 数据形式 | `bool` / `enum` | 队列 / 回调 |
| 游戏例子 | 移动(按住 W 走) | 跳跃(按一下空格) |
| 防误触 | 容易持续触发 | 单次触发 |

### winit 怎么报键盘事件

```rust
WindowEvent::KeyboardInput {
    device_id: _,
    event,           // KeyEvent
    is_synthetic: _, // 是否 winit 合成的事件(焦点切换时)
} => {
    use winit::event::{ElementState, KeyCode};
    match event.state {
        ElementState::Pressed => {
            if let KeyCode::KeyW = event.physical_key.as_keycode().unwrap() {
                // ...
            }
        }
        ElementState::Released => { /* ... */ }
    }
}
```

关键字段:

- `event.state: ElementState` — `Pressed` 或 `Released`(没有 `Repeat`,但 winit 提供 `event.repeat: bool` 标识)
- `event.physical_key: PhysicalKey` — 物理按键(按位置),不受键盘布局影响
- `event.logical_key: Key<...>` — 逻辑按键(按当前输入法布局),比如 Dvorak 用户按 Dvorak 的位置但实际想输入 "Q"
- `event.repeat: bool` — 是否系统自动重复(按住时持续触发)
- `event.text: Option<...>` — 文本输入(用于输入框,游戏一般不用)

游戏通常用 `physical_key`,因为"WASD" 应该是**位置固定**(美式键盘 QWERTY 那个位置),不管用户切换到 Dvorak 还是 AZERTY。

### 累积状态到数组

Casey 的设计(我们沿用):

```rust
struct KeyboardState {
    /// 256 个键的当前按下状态
    /// 索引是 KeyCode 的 u32 值
    keys: [bool; 256],
}

impl KeyboardState {
    fn set(&mut self, code: KeyCode, pressed: bool) {
        let idx = code as u32 as usize;
        if idx < 256 {
            self.keys[idx] = pressed;
        }
    }

    fn is_down(&self, code: KeyCode) -> bool {
        let idx = code as u32 as usize;
        idx < 256 && self.keys[idx]
    }
}
```

主循环:

```rust
// 事件处理(在 window_event 里)
WindowEvent::KeyboardInput { event, .. } => {
    if let Some(code) = event.physical_key.as_keycode() {
        match event.state {
            ElementState::Pressed => self.keyboard.set(code, true),
            ElementState::Released => self.keyboard.set(code, false),
        }
    }
}

// 主循环里
if self.keyboard.is_down(KeyCode::ArrowRight) {
    self.x_offset += dt * 100.0;
}
if self.keyboard.is_down(KeyCode::ArrowLeft) {
    self.x_offset -= dt * 100.0;
}
```

**关键洞察**:`is_down` 每帧检查,**持续按下持续移动**。这是 state 的力量。

### "按下瞬间" / "松开瞬间"语义

对于跳跃(单次触发),你需要知道"这一帧从松到按"。两种实现:

**实现 1:保存上一帧状态,比较差异**

```rust
struct App {
    current: KeyboardState,
    previous: KeyboardState,
}

fn was_just_pressed(&self, code: KeyCode) -> bool {
    self.current.is_down(code) && !self.previous.is_down(code)
}

// 主循环开头
self.previous = self.current;  // 注意:在事件处理前
// ... 处理事件更新 self.current
// ... 渲染前
if self.was_just_pressed(KeyCode::Space) {
    self.player.jump();
}
```

**实现 2:用事件队列**

```rust
struct App {
    events: Vec<KeyEvent>,
}

// 事件处理
WindowEvent::KeyboardInput { event, .. } => {
    self.events.push(event);
}

// 主循环开头:处理这一帧的所有事件
let frame_events = std::mem::take(&mut self.events);
for e in frame_events {
    if e.state == ElementState::Pressed && e.physical_key == KeyCode::Space.into() {
        self.player.jump();
    }
}
```

实现 2 更清晰,但实现 1 性能好(不用 Vec 分配)。Casey 用实现 1。我们教学也用实现 1。

### winit 事件 vs Win32 事件对照

| 概念 | Win32 | winit 0.30 |
|---|---|---|
| 按下 | `WM_KEYDOWN` / `WM_SYSKEYDOWN` | `KeyboardInput { state: Pressed }` |
| 松开 | `WM_KEYUP` / `WM_SYSKEYUP` | `KeyboardInput { state: Released }` |
| 键码 | `wParam`(VK_LEFT 等) | `physical_key: PhysicalKey`(KeyCode::ArrowLeft) |
| 字符输入 | `WM_CHAR` | `event.text: Option<SmolStr>` |
| 自动重复 | 同一 VK 多次 WM_KEYDOWN | `event.repeat == true` |
| 焦点丢失 | `WM_KILLFOCUS` | `WindowEvent::Focused(false)` |

注意 Win32 区分 `WM_KEYDOWN`(普通键)和 `WM_SYSKEYDOWN`(系统键,如 F10、Alt+X)。这是因为 Alt 是修饰键,Win32 对它有特殊处理。winit 把它们合并,简化了。

### 输入抽象的演化方向

今天的实现是"硬编码键盘"。但游戏要支持:

- 键盘

## 3 · 四域深入

### 3.1 · 🐧 Linux 系统编程视角

#### evdev:Linux 输入设备的底层

Linux 的所有输入设备(键盘 / 鼠标 / 手柄)在 `/dev/input/` 暴露为 **evdev** 设备:

```bash
ls /dev/input/
# event0  event1  event2 ... eventN  mice  mouse0  js0 ...

# 看每个 event 是什么设备
cat /proc/bus/input/devices | grep -E "^N: Name"
# N: Name="AT Translated Set 2 keyboard"
# N: Name="Logitech M500 mouse"
# N: Name="Microsoft X-Box One pad"

# 抓键盘事件
sudo pacman -S evtest
sudo evtest /dev/input/event0
# 按几个键,输出:
# Event: type 4 (EV_MSC), code 4 (MSC_SCAN), value 1e
# Event: type 1 (EV_KEY), code 30 (KEY_A), value 1     ← A 按下
# Event: type 1 (EV_KEY), code 30 (KEY_A), value 0     ← A 松开
# Event: type 0 (EV_SYN)
```

evdev 是 Linux 内核的统一输入协议。所有输入事件都是 `(type, code, value)` 三元组。X11 / Wayland / libinput 都从 evdev 读,然后给你的程序。

#### libinput:X11/Wayland 的输入抽象

**libinput** 是 systemd/Freedesktop 的输入抽象,处理:

- 设备发现 / 热插拔
- 多点触摸
- 手势识别
- 加速度曲线(鼠标)
- 按键映射

X11 通过 `xf86-input-libinput` 用 libinput。Wayland compositor 直接用 libinput。

winit 不直接调 libinput,而是通过 X11 / Wayland 拿事件。但底层就是 libinput + evdev。

#### 验证键盘事件流

```bash
# 看 evdev 的 keycode
sudo evtest /dev/input/event0
# 按下空格,看:
# Event: time ..., type 1 (EV_KEY), code 57 (KEY_SPACE), value 1

# KEY_SPACE = 57,这是 Linux 内核 keycode
# winit 把它转成 KeyCode::Space
```

Linux keycode 表:https://www.kernel.org/doc/html/latest/input/event-codes.html

### 3.2 · 🦀 Rust 生态视角

#### `KeyCode` 是个庞大枚举

```rust
pub enum KeyCode {
    KeyA, KeyB, ..., KeyZ,
    Digit1, Digit2, ..., Digit0,
    F1, F2, ..., F24,
    ArrowUp, ArrowDown, ArrowLeft, ArrowRight,
    Space, Enter, Escape, Tab, Backspace,
    ShiftLeft, ShiftRight,
    ControlLeft, ControlRight,
    AltLeft, AltRight,
    MetaLeft, MetaRight,
    // ... 几百个
}
```

winit 的 `KeyCode` 来自 USB HID Usage Table 标准,跨平台一致。Casey 在 Win32 用 `VK_*`(virtual key),是 Windows 专属。

#### `as_keycode()` 和转换

```rust
let physical_key: PhysicalKey = event.physical_key;
match physical_key {
    PhysicalKey::Code(code) => {
        // code 是 KeyCode
        match code {
            KeyCode::Space => { /* ... */ }
            _ => ()
        }
    }
    PhysicalKey::Unidentified(_) => {
        // 无法识别的键
    }
}
```

`PhysicalKey` 是个枚举,有 `Code(KeyCode)` 和 `Unidentified(NativeKeyCode)` 两个变体。后者处理"非标准键"(有些老键盘有特殊按键)。

#### `as u32 as usize` 的细节

```rust
let idx = code as u32 as usize;
```

`KeyCode` 不是直接 `as usize`(Rust 不允许 enum 直接 as 整数,除非 `#[repr(...)]` 帮你)。但 winit 给 `KeyCode` 加了 `#[repr(u32)]`,所以可以 `as u32`。然后 `as usize` 是为了索引数组。

**教训**:Rust 类型系统强迫你显式做类型转换,避免隐式 bug。

#### Bitflags / 数组 vs HashMap

```rust
// 选项 A: 数组(快)
keys: [bool; 256]

// 选项 B: HashSet<KeyCode>(灵活,慢)
keys: std::collections::HashSet<KeyCode>

// 选项 C: bitflags(最省内存)
keys: u256  // 假设有,实际用 [u64; 4]
```

数组最快(O(1) 索引),但固定大小。KeyCode 数量超过 256 就溢出。

Casey 用数组(Win32 VK 是 0-255)。我们这边 winit KeyCode 数量超过 256(几百个),要用 HashMap 或 `[bool; 512]`。教学简单起见用数组。

### 3.3 · 🎮 游戏编程视角

#### 输入延迟(Input Lag)

按下按键到看到反应的时间。组成:

1. **键盘扫描延迟**:键盘内部扫描矩阵,5-20ms(廉价键盘可能更多)
2. **USB 轮询**:USB 协议的轮询间隔,1-8ms
3. **内核 → 窗口系统**:几乎 0
4. **窗口系统 → 应用事件**:几乎 0
5. **应用更新 + 渲染**:这一帧到下一帧,最多 16ms(60 FPS)
6. **显示延迟**:显示器响应时间,1-10ms

总和 30-60ms。电竞游戏要把它压到 < 30ms。Casey 在 Day 18+ 详细讨论。

#### 输入和帧率的解耦

输入事件**异步**产生(键盘想按就按),游戏循环**同步**处理(每帧看一次)。所以一帧可能收到 0 个事件,也可能 10 个事件(快速连按)。

正确做法:**累积事件到状态,主循环只看状态**。这样不管多少事件,行为一致。

错误做法:**在事件回调里直接改变游戏状态**。因为多个事件可能互相覆盖(按下立即松开,只看到松开)。

#### 输入死区(Deadzone)

手柄摇杆 / 鼠标移动有"噪声"——静止时也报微小数值。游戏加"死区":

```rust
let deadzone = 0.1;
let axis = raw_axis;
let axis = if axis.abs() < deadzone { 0.0 } else { axis };
```

键盘没这个问题(数字输入),但概念在 Day 17(手柄)会遇到。

### 3.4 · 🎨 图形学视角

今天不直接涉及图形学。但有一个相关概念:**输入和帧的同步**。

游戏循环 60 FPS,每帧读一次输入。但显示器可能 144 Hz / 60 Hz,键盘事件频率高得多。winit 内部有个事件队列,主循环每次进来"消费一批"。这种"异步输入 + 同步消费"是实时系统的标准模式。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:winit 的 `event.repeat: bool` 是什么意思?在什么情况下为 true?为什么游戏一般忽略它?

**参考解答**:

`repeat: true` 表示这条 Pressed 事件是**系统自动重复**——用户按住键不动,OS 每隔几百毫秒自动再触发一次 Pressed 事件(模拟"快速连按")。

这是 OS 的"打字"行为。你在文本编辑器按住 A,会出现 AAAA,就是 repeat 在工作。

游戏一般**忽略 repeat 事件**,因为:

1. 游戏看 state,不看 event。state 数组里 key 一直是 true,自动 repeat 不影响 state
2. 如果游戏按 event 处理(比如按一次 A 攻击一次),repeat 会让玩家按住就疯狂攻击

所以常见做法:`if event.state == Pressed && !event.repeat { ... }`——只处理真按下,跳过自动重复。

### Lv2 · 动手实践

**题**:在 Day 4 代码上加键盘:方向键控制渐变滚动方向,空格暂停 / 恢复,Escape 退出。完成标准:

- 按住 Left:渐变向左滚
- 按住 Right:渐变向右滚
- 不按:停止滚动
- 按空格:暂停(再按恢复)
- 按 Escape:退出程序

**参考解答**:

```rust
// src/main.rs(基于 Day 4,加键盘)

use raw_window_handle::HasWindowHandle;
use softbuffer::Surface;
use std::num::NonZeroU32;
use std::time::Instant;
use winit::application::ApplicationHandler;
use winit::event::{ElementState, KeyCode, KeyEvent, WindowEvent};
use winit::event_loop::{ActiveEventLoop, ControlFlow, EventLoop};
use winit::keyboard::PhysicalKey;
use winit::window::{Window, WindowId};

/// 键盘状态:记录每个键的按下状态
#[derive(Clone)]
struct KeyboardState {
    /// 数组索引 = KeyCode 的 u32 表示(简化:只支持 0-511)
    keys: [bool; 512],
}

impl KeyboardState {
    fn new() -> Self {
        Self { keys: [false; 512] }
    }

    fn set(&mut self, code: KeyCode, pressed: bool) {
        let idx = code as u32 as usize;
        if idx < self.keys.len() {
            self.keys[idx] = pressed;
        }
    }

    fn is_down(&self, code: KeyCode) -> bool {
        let idx = code as u32 as usize;
        idx < self.keys.len() && self.keys[idx]
    }
}

struct App {
    window: Option<Window>,
    surface: Option<Surface>,
    last_time: Option<Instant>,
    /// 当前键盘状态
    keyboard: KeyboardState,
    /// 上一帧键盘状态(用于"按下瞬间"检测)
    prev_keyboard: KeyboardState,
    /// 当前 X 偏移(渐变相位)
    x_offset: f32,
    /// 是否暂停
    paused: bool,
}

impl ApplicationHandler for App {
    fn resumed(&mut self, event_loop: &ActiveEventLoop) {
        let attrs = Window::default_attributes()
            .with_title("Handmade Hero — Day 6")
            .with_inner_size(winit::dpi::LogicalSize::new(1280, 720));
        let window = event_loop.create_window(attrs).unwrap();

        let context = unsafe {
            softbuffer::Context::new(event_loop.display_handle().unwrap().clone())
        }.unwrap();
        let surface = unsafe {
            context.create_surface(window.window_handle().unwrap().unwrap().clone())
        }.unwrap();

        self.window = Some(window);
        self.surface = Some(surface);
        self.last_time = Some(Instant::now());

        event_loop.set_control_flow(ControlFlow::Poll);
    }

    fn window_event(
        &mut self,
        event_loop: &ActiveEventLoop,
        _id: WindowId,
        event: WindowEvent,
    ) {
        match event {
            WindowEvent::CloseRequested => event_loop.exit(),

            // 关键:键盘事件
            WindowEvent::KeyboardInput {
                event: KeyEvent { state, physical_key, .. },
                ..
            } => {
                if let PhysicalKey::Code(code) = physical_key {
                    match state {
                        ElementState::Pressed => {
                            // "按下瞬间"语义:处理单次动作
                            // 这里检测 prev 状态,如果 prev=false 说明刚按下
                            if !self.keyboard.is_down(code) {
                                self.on_key_press(code);
                            }
                            // 持续状态更新
                            self.keyboard.set(code, true);
                        }
                        ElementState::Released => {
                            self.keyboard.set(code, false);
                        }
                    }
                }
            }

            WindowEvent::RedrawRequested => {
                self.render();
            }
            WindowEvent::Resized(size) => {
                if let Some(surface) = &mut self.surface {
                    if size.width > 0 && size.height > 0 {
                        surface.resize(
                            NonZeroU32::new(size.width).unwrap(),
                            NonZeroU32::new(size.height).unwrap(),
                        ).unwrap();
                    }
                }
            }
            _ => ()
        }
    }

    fn about_to_wait(&mut self, _event_loop: &ActiveEventLoop) {
        let now = Instant::now();
        let dt = self.last_time.map(|t| now.duration_since(t).as_secs_f32()).unwrap_or(0.0);
        self.last_time = Some(now);
        let dt = dt.min(0.1);

        // 用 state 决定行为(持续按下持续移动)
        let speed = 200.0;  // 像素/秒
        if !self.paused {
            if self.keyboard.is_down(KeyCode::ArrowRight) {
                self.x_offset += dt * speed;
            }
            if self.keyboard.is_down(KeyCode::ArrowLeft) {
                self.x_offset -= dt * speed;
            }
        }

        // 持续状态保存为下一帧的 prev
        // (注意:上一帧的 prev 已在事件处理中用过,这里更新)
        // 实际上,在事件处理里我们用的是"当前 + 即将更新",简化版

        if let Some(window) = &self.window {
            window.request_redraw();
        }
    }
}

impl App {
    /// "按下瞬间"语义:单次触发
    fn on_key_press(&mut self, code: KeyCode) {
        match code {
            KeyCode::Space => {
                self.paused = !self.paused;
                println!("Paused: {}", self.paused);
            }
            KeyCode::Escape => {
                println!("Escape pressed, exiting");
                std::process::exit(0);
            }
            _ => ()
        }
    }

    fn render(&mut self) {
        let surface = self.surface.as_mut().unwrap();
        let window = self.window.as_ref().unwrap();
        let size = window.inner_size();
        let (w, h) = (size.width, size.height);
        if w == 0 || h == 0 { return; }

        surface.resize(NonZeroU32::new(w).unwrap(), NonZeroU32::new(h).unwrap()).unwrap();
        let mut buffer = surface.buffer_mut().unwrap();

        let offset = self.x_offset;
        let w_f = w as f32;
        let h_f = h as f32;
        for y in 0..h {
            for x in 0..w {
                let phase = ((x as f32 + offset).rem_euclid(w_f)) / w_f;
                let blue = (phase * 255.0) as u32;
                let red = ((y as f32 / h_f) * 255.0) as u32 / 2;
                buffer[(y * w + x) as usize] = (red << 16) | blue;
            }
        }

        buffer.present().unwrap();
    }
}

fn main() {
    let event_loop = EventLoop::new().unwrap();
    let mut app = App {
        window: None,
        surface: None,
        last_time: None,
        keyboard: KeyboardState::new(),
        prev_keyboard: KeyboardState::new(),
        x_offset: 0.0,
        paused: false,
    };
    event_loop.run_app(&mut app).unwrap();
}
```

**注意 `rem_euclid`**:Rust 的 `%` 在负数时有坑(`-1 % 10 = -1`),`rem_euclid` 保证返回非负(`-1.0 rem_euclid 10.0 = 9.0`)。处理偏移循环时用它。

### Rust 模式:用 macro 简化按键检查

```rust
// 一个宏,把 KeyCode 转成数组索引
macro_rules! key_idx {
    ($code:expr) => {
        $code as u32 as usize
    };
}

// 使用:
let idx = key_idx!(KeyCode::Space);
self.keyboard.keys[idx]
```

但 Rust 里宏定义稍复杂,我们一般直接写 `code as u32 as usize`。

### Troubleshooting

- **键盘事件不触发**:窗口没焦点,点击窗口让它获得焦点
- **按方向键窗口移动**:焦点在 winit 之外的"窗口装饰"上(标题栏),点窗口内部
- **事件延迟**:某些 IME(输入法)会拦截键盘事件,关掉它
- **Escape 不退出**:检查 `on_key_press` 里 Escape 分支是否真的执行(加 println)
- **暂停不响应**:Space 可能被某些 IME 占用,试别的键(如 KeyP)
