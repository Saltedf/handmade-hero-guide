> 你的玩家有个朝向——面朝北。他手上的武器相对玩家有个朝向(右前方)。这两个朝向怎么组合?Casey 今天引入 **base**(基底)概念——一个 base = 位置 + 朝向(旋转)。entity 在 base 的局部坐标里定义,渲染时通过 base 变换到世界坐标。这是 3D 渲染的数学基础——后面所有旋转、缩放、变换都建立在 base 之上。Day 361+ 的 3D 旋转矩阵是 base 的数学化。

## 0 · 为什么要有这一天

考虑你的玩家。他的位置是 `(100, 50, 0)`。他**面朝北**(0 度,北是 +y 方向)。他手上拿着剑,剑相对玩家的位置是 `(10, 5, 30)`(右前方,腰部高度)。

**剑的世界位置**是什么?

直觉上:玩家面朝北时,剑在玩家的「右前方」,世界位置 ≈ 玩家 + `(10, 5, 30)` = `(110, 55, 30)`。

但如果玩家**面朝东**(90 度)呢?「右前方」变成世界坐标的「下方」。剑的世界位置变成 `(100, 50, 30) + (5, -10, 30)` = `(105, 40, 30)`——因为旋转 90 度。

**这是 base 的核心**——一个 base 是「**位置 + 朝向**」,entity 在 base 局部坐标里定义,通过 base 变换到世界坐标。

数学上,base 变换 = **旋转 + 平移**:

```
world_pos = rotate(local_pos, base.rotation) + base.position
```

这就是 Casey HH Day 090 引入的「base」概念。它是:

- **2D 渲染**:旋转矩形的数学基础
- **3D 渲染**:camera、entity、bone 全部用 base
- **物理**:刚体的位置 + 旋转
- **动画**:骨骼动画每个 bone 是一个 base

心理锚点:看完今天,你能向队友解释「玩家的剑为什么跟着玩家旋转」。你能用 Rust 写 base 变换。你能用 30 秒说清「局部坐标 vs 世界坐标」。

## 2 · 心智模型

### 费曼类比:地球仪和地标

想象地球仪。地球本身是个 base——位置(太阳系坐标)+ 旋转(自转角度)。

北京是个**地标**——在地球的局部坐标里固定(东经 116°,北纬 40°)。北京的世界位置(太阳系坐标)随地球的旋转而变化。

游戏里:
- **base** = 地球(位置 + 旋转)。
- **entity** = 北京(局部坐标)。
- **世界位置** = base 变换后的结果。

玩家旋转时,所有「玩家身上的东西」(剑、帽子、宠物)跟着旋转——因为它们都在玩家的 base 里。

### 严谨原理

#### 2.1 Base struct

```rust
#[derive(Copy, Clone, Debug)]
struct Base {
    position: Vec3,  // 世界位置
    rotation: f32,   // 绕 z 轴的旋转角度(弧度)
}
```

2.5D 用单角度表达旋转(绕 z 轴)。真 3D 用四元数(quaternion)或欧拉角,Day 361+。

#### 2.2 2D 旋转公式

绕原点旋转 θ 角度的点 (x, y):

```
x' = x * cos(θ) - y * sin(θ)
y' = x * sin(θ) + y * cos(θ)
```

推导:复数乘法 `(x + iy) * (cos θ + i sin θ) = (x cos θ - y sin θ) + i(x sin θ + y cos θ)`。

```rust
fn rotate_2d(x: f32, y: f32, theta: f32) -> (f32, f32) {
    let cos_t = theta.cos();
    let sin_t = theta.sin();
    (x * cos_t - y * sin_t, x * sin_t + y * cos_t)
}
```

#### 2.3 Base 变换

```rust
impl Base {
    fn transform_point(&self, local_pos: Vec3) -> Vec3 {
        // 1. 旋转(2.5D 只旋转 x/y)
        let (rx, ry) = rotate_2d(local_pos.x, local_pos.y, self.rotation);
        // 2. 平移
        Vec3::new(rx + self.position.x, ry + self.position.y, local_pos.z + self.position.z)
    }
}
```

注意 z 不旋转——2.5D 中 z 是高度,旋转只在水平面。

#### 2.4 玩家 + 武器示例

```rust
let player_base = Base {
    position: Vec3::new(100., 50., 0.),
    rotation: std::f32::consts::PI / 2.0,  // 90 度,面朝东
};

let sword_local = Vec3::new(10., 5., 30.);  // 相对玩家
let sword_world = player_base.transform_point(sword_local);

// 算:
// theta = π/2,cos = 0,sin = 1
// rx = 10 * 0 - 5 * 1 = -5
// ry = 10 * 1 + 5 * 0 = 10
// sword_world = (100 + (-5), 50 + 10, 0 + 30) = (95, 60, 30)
```

玩家面朝东时,剑(局部右前方)在世界坐标变成「左前方」——因为旋转 90 度。

#### 2.5 反向变换:world_to_base

有时需要反向——把世界坐标变到 base 局部。比如「玩家在哪个位置看 world_pos?」:

```rust
impl Base {
    fn inverse_transform(&self, world_pos: Vec3) -> Vec3 {
        // 1. 反向平移
        let p = world_pos.sub(self.position);
        // 2. 反向旋转(-theta)
        let (rx, ry) = rotate_2d(p.x, p.y, -self.rotation);
        Vec3::new(rx, ry, p.z)
    }
}
```

应用:**视线检测**——世界中的某个点,在玩家局部坐标里是哪个方向?如果在前方(`local.y > 0`),玩家能看到。

#### 2.6 Base 链(嵌套)

考虑相机 + 玩家 + 武器:

- 相机 base:位置 (0, 0, 100),朝下看。
- 玩家 base:位置 (100, 50, 0),朝北。
- 武器:在玩家 base 内,局部 (10, 5, 30)。

武器的**最终屏幕位置** = camera_to_screen(player_to_world(weapon_in_player))。这是「**base 链**」——多个 base 嵌套。

3D 渲染里的 MVP(Model-View-Projection)矩阵就是 base 链:

- Model matrix:entity 局部 → 世界
- View matrix:世界 → 相机
- Projection matrix:相机 → 屏幕

每个 matrix 是一个 base 的数学表达。

#### 2.7 Base vs Transform vs Matrix

术语同义词:

- **Base**(Casey HH 用):位置 + 旋转。
- **Transform**:Unity 用,含义类似(位置 + 旋转 + 缩放)。
- **Frame** / **Coordinate Frame**:图形学术语。
- **Matrix**:数学表达,4×4 矩阵编码位置 + 旋转 + 缩放。

Casey HH 先用 struct,Day 361+ 切矩阵。

#### 2.8 缩放和旋转的结合

完整变换包括旋转 + 缩放 + 平移:

```
world = rotate(scale(local)) + position
```

Casey HH 在 2.5D 简化,通常没缩放(所有 entity 1:1)。Day 109 加「分辨率无关」时引入缩放。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Base 是游戏开发的核心抽象:

- **Unity Transform**:每个 GameObject 都有 Transform(位置 + 旋转 + 缩放)。子对象继承父 Transform。
- **Unreal Actor**:类似 Transform。
- **Godot Node2D**:Transform2D,2D 版本。
- **Casey HH Base**:简化版,只有位置 + 旋转。

#### 父子 hierarchy

Unity 等引擎支持「**parent-child hierarchy**」——子对象的 transform 是相对父对象的。这是 base 链的体现。

```
Player (transform: pos=(100, 50, 0), rot=90)
  └─ Right Hand (transform: pos=(15, 0, 30), rot=0)
       └─ Sword (transform: pos=(0, 20, 0), rot=45)
```

剑的世界位置 = player.transform × hand.transform × sword.transform。

Casey HH 简化,玩家身上的子对象直接在玩家 base 里定义(不嵌套)。

### 3.2 · 🎨 图形学视角

3D 渲染里的 base 数学化:

#### 2D 旋转矩阵

```
R(θ) = | cos θ  -sin θ |
       | sin θ   cos θ |
```

旋转矩阵作用在向量 `(x, y)` 上:`R(θ) * (x, y) = (x cos θ - y sin θ, x sin θ + y cos θ)`——就是 2D 旋转公式。

#### 3D 旋转矩阵

绕 x、y、z 轴各一个矩阵:

```
Rx(θ) = | 1    0       0     |
        | 0  cos θ  -sin θ  |
        | 0  sin θ   cos θ  |

Ry(θ) = |  cos θ  0  sin θ |
        |   0     1   0    |
        | -sin θ  0  cos θ |

Rz(θ) = | cos θ  -sin θ  0 |
        | sin θ   cos θ  0 |
        |   0      0     1 |
```

任意 3D 旋转 = Rx × Ry × Rz(欧拉角)或四元数(quaternion)。Day 361+ 详细。

#### 4×4 变换矩阵

把旋转 + 缩放 + 平移统一:

```
M = | R(3x3)  T(3x1) |
    | 0(1x3)    1    |
```

4×4 矩阵乘法 = 变换复合。M = T × R × S = 先缩放,再旋转,再平移。

为什么 4×4 而不是 3×3?因为平移不是线性变换(是仿射),需要加 w 维(齐次坐标)才能统一。Day 101 详细。

### 3.3 · 🐧 Linux 系统编程视角

「**局部 vs 全局**」是 Linux 系统编程的常见概念:

- **进程的 cwd vs 绝对路径**:每个进程有自己的 cwd,相对路径是局部,绝对路径是全局。
- **chroot**:改变进程的「文件系统根」,所有路径在这个 base 里。
- **network namespace**:每个 namespace 有自己的网络栈,IP 是局部,需要变换到主机视角。

base 概念类似——**坐标系是相对的**,需要变换才能跨坐标系比较。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写 base

```rust
#[derive(Copy, Clone, Debug)]
pub struct Base {
    pub position: Vec3,
    pub rotation: f32,  // 2D 旋转角度(绕 z 轴)
}

impl Base {
    pub fn new(position: Vec3, rotation: f32) -> Self {
        Self { position, rotation }
    }

    pub fn identity() -> Self {
        Self { position: Vec3::new(0., 0., 0.), rotation: 0. }
    }

    pub fn transform_point(&self, local: Vec3) -> Vec3 {
        let cos_t = self.rotation.cos();
        let sin_t = self.rotation.sin();
        let rx = local.x * cos_t - local.y * sin_t;
        let ry = local.x * sin_t + local.y * cos_t;
        Vec3::new(
            rx + self.position.x,
            ry + self.position.y,
            local.z + self.position.z,
        )
    }

    pub fn inverse_transform(&self, world: Vec3) -> Vec3 {
        let p = Vec3::new(
            world.x - self.position.x,
            world.y - self.position.y,
            world.z - self.position.z,
        );
        let cos_t = (-self.rotation).cos();
        let sin_t = (-self.rotation).sin();
        let rx = p.x * cos_t - p.y * sin_t;
        let ry = p.x * sin_t + p.y * cos_t;
        Vec3::new(rx, ry, p.z)
    }

    // 组合两个 base:先 child 后 self
    pub fn combine(&self, child: &Base) -> Base {
        let new_pos = self.transform_point(child.position);
        let new_rot = self.rotation + child.rotation;
        Base { position: new_pos, rotation: new_rot }
    }
}
```

#### Rust 的 Deref / Child pattern

```rust
struct Player {
    base: Base,
    health: i32,
    // ...
}

impl std::ops::Deref for Player {
    type Target = Base;
    fn deref(&self) -> &Base { &self.base }
}

// 这样可以写 player.transform_point(...) 而不是 player.base.transform_point(...)
```

`Deref` 让 struct「**借用**」内部字段的方法。Casey HH 风格可能不这么做(显式更清晰),但 Rust 习惯用法。

#### Rust 的 glam crate

```rust
use glam::{Vec3, Quat, Affine3A};

let base = Affine3A::from_rotation_translation(
    Quat::from_rotation_z(90.0_f32.to_radians()),
    Vec3::new(100., 50., 0.),

let world = base.transform_point3(Vec3::new(10., 5., 30.));
```

`glam` 提供工业级 base 实现。Affine3A 是 3D 仿射变换,SIMD 优化。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 base 用「位置 + 旋转」两个数据,而不是「位置 + 前向向量」?

**参考解答**:

**位置 + 旋转**的优势:
- **数据紧凑**:1 个 Vec3 + 1 个 f32(2.5D)= 16 字节。前向向量是 Vec3(12 字节)+ position(12)= 24 字节。
- **插值友好**:旋转是单个数,线性插值简单(虽然大角度需要 SLERP)。前向向量插值要归一化,易出 bug。
- **复合直观**:两个 base 复合 = 位置相加(变换后)+ 旋转相加。前向向量复合复杂。
- **可表达任意旋转**:0-2π 范围,无奇异点。

**位置 + 前向向量**的优势:
- **不需要查表**:方向直接是向量。
- **3D 中四元数就是类似的**——四元数本质是个编码旋转的「向量」。

2D 用「位置 + 旋转角度」更简洁。3D 用四元数(本质是位置 + 旋转向量)。

### Lv2 · 动手实践

**题**:实现 Base,验证玩家旋转时武器位置正确变化。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y, self.z - o.z) }
}

#[derive(Copy, Clone, Debug)]
struct Base {
    position: Vec3,
    rotation: f32,
}

impl Base {
    fn transform_point(&self, local: Vec3) -> Vec3 {
        let cos_t = self.rotation.cos();
        let sin_t = self.rotation.sin();
        let rx = local.x * cos_t - local.y * sin_t;
        let ry = local.x * sin_t + local.y * cos_t;
        Vec3::new(
            rx + self.position.x,
            ry + self.position.y,
            local.z + self.position.z,
        )
    }
}

fn main() {
    let sword_local = Vec3::new(10., 5., 30.);  // 局部右前方

    for &deg in &[0.0_f32, 90.0, 180.0, 270.0] {
        let player = Base {
            position: Vec3::new(100., 50., 0.),
            rotation: deg.to_radians(),
        };
        let sword_world = player.transform_point(sword_local);
        println!("玩家朝 {:.0} 度: 剑世界位置 = ({:.2}, {:.2}, {:.2})",
            deg, sword_world.x, sword_world.y, sword_world.z);
    }
}
```

**预期输出**:
```

玩家朝 90 度: 剑世界位置 = (95.00, 60.00, 30.00)      ← 东,剑在前左
玩家朝 180 度: 剑世界位置 = (90.00, 45.00, 30.00)     ← 南,剑在左后
玩家朝 270 度: 剑世界位置 = (105.00, 40.00, 30.00)    ← 西,剑在后右
```

可以看到旋转 90 度时,剑的相对位置(右前方)变成了不同的世界方向。

## 8 · Rust / Arch 落地代码

```rust
#[derive(Copy, Clone, Debug)]
pub struct Vec3 { pub x: f32, pub y: f32, pub z: f32 }

impl Vec3 {
    pub fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }

    pub fn sub(self, o: Self) -> Self {
        Self::new(self.x - o.x, self.y - o.y, self.z - o.z)
    }

    pub fn add(self, o: Self) -> Self {
        Self::new(self.x + o.x, self.y + o.y, self.z + o.z)
    }

    pub fn length(self) -> f32 {
        self.x.mul_add(self.x, self.y.mul_add(self.y, self.z * self.z)).sqrt()
    }
}

impl std::ops::Add for Vec3 {
    type Output = Self;
    fn add(self, o: Self) -> Self { Self::new(self.x+o.x, self.y+o.y, self.z+o.z) }
}

impl std::ops::Sub for Vec3 {
    type Output = Self;
    fn sub(self, o: Self) -> Self { Self::new(self.x-o.x, self.y-o.y, self.z-o.z) }
}

pub struct Base {

        Self { position, rotation }
    }

        Self { position: Vec3::new(0., 0., 0.), rotation: 0. }
    }

    #[inline]
    pub fn transform_point(&self, local: Vec3) -> Vec3 {
        let cos_t = self.rotation.cos();
        let sin_t = self.rotation.sin();
        let rx = local.x * cos_t - local.y * sin_t;
        let ry = local.x * sin_t + local.y * cos_t;
        Vec3::new(
            rx + self.position.x,
            ry + self.position.y,
            local.z + self.position.z,
        )
    }

    #[inline]
    pub fn inverse_transform(&self, world: Vec3) -> Vec3 {
        let p = world - self.position;
        let cos_t = (-self.rotation).cos();
        let sin_t = (-self.rotation).sin();
        let rx = p.x * cos_t - p.y * sin_t;
        let ry = p.x * sin_t + p.y * cos_t;
        Vec3::new(rx, ry, p.z)
    }

    pub fn combine(&self, child: &Base) -> Base {
        Base {
            position: self.transform_point(child.position),
            rotation: self.rotation + child.rotation,
        }
    }

    pub fn forward(&self) -> Vec3 {
        // 2D:朝北 = (0, 1, 0),旋转后
        self.transform_point(Vec3::new(0., 1., 0.)) - self.position
    }
}

fn main() {
    println!("=== Base 变换示例 ===\n");

    let player = Base::new(Vec3::new(100., 50., 0.), std::f32::consts::FRAC_PI_2);
    println!("玩家 base: position={:?}, rotation=π/2 (90°)", player.position);

    let sword_local = Vec3::new(10., 5., 30.);
    println!("剑的局部位置(相对玩家): {:?}", sword_local);

    let sword_world = player.transform_point(sword_local);
    println!("剑的世界位置(变换后): {:?}", sword_world);

    let inv = player.inverse_transform(sword_world);
    println!("反变换(应该等于 local): {:?}", inv);
    println!();

    println!("=== 玩家朝向(前向向量) ===");
    println!("玩家面朝: {:?}", player.forward());
    println!();

    println!("=== Base 链 ===");
    let world = Base::identity();
    let room = Base::new(Vec3::new(100., 50., 0.), 0.5);
    let table = Base::new(Vec3::new(10., 5., 0.), 0.3);
    let cup_local = Vec3::new(2., 1., 0.);

    let world_table = world.combine(&room).combine(&table);
    let cup_world = world_table.transform_point(cup_local);
    println!("世界 → 房间 → 桌子 上的杯子: {:?}", cup_world);

    println!();

    println!("=== 不同朝向的玩家 ===");
    for deg in [0.0_f32, 45.0, 90.0, 135.0, 180.0, 270.0] {
        let p = Base::new(Vec3::new(0., 0., 0.), deg.to_radians());
        let f = p.forward();
        println!("玩家朝 {:3.0}°: 前向 = ({:+.3}, {:+.3}, 0)", deg, f.x, f.y);
    }
}
```

**Troubleshooting**:
- 旋转方向反 — 检查 cos/sin 符号,2D 旋转公式是 `x cos - y sin, x sin + y cos`(标准数学约定,逆时针)
- 反变换错 — 检查 `-self.rotation` 不是 `self.rotation`
- 链式变换错 — combine 的顺序:`parent.combine(child)`,先 parent 后 child
