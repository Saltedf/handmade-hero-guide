# Day 096 · 光照入门

> 你的 sprite 现在能旋转、有纹理、半透明混合正确。但它看起来「**平**」——像个剪纸贴在屏幕上。现实世界不是这样的:物体朝着光的面亮,背光的面暗,光从某个角度照过来时表面有明暗变化。**这就是光照**。今天 Casey 引入**Phong 光照模型**——游戏和图形学最经典的光照模型,把「光的方向、表面朝向、视线方向」结合起来,算出每个像素应该多亮。

## 0 · 为什么要有这一天

考虑你画一个 3D 立方体在屏幕上。立方体有 6 个面,每个面贴一张纹理(一样的砖墙图)。没有光照,所有面看起来一样亮——立方体像个**纸折的盒子**,没有立体感。

加上光照后:
- 朝光的面**亮**
- 背光的面**暗**
- 侧光的面**有从亮到暗的渐变**
- 立刻看起来是**立体的**

这就是光照的魔法。具体怎么做?

观察现实世界:**光照强度取决于光的方向和表面朝向的夹角**。
- 光**直射**表面(垂直)→ 100% 光照
- 光**斜射**(45°)→ ~70% 光照(`cos 45° = 0.707`)
- 光**平行掠过**表面(0°)→ 0% 光照
- 光**从背面**来 → 0%(表面没受光)

数学上,**光向量和表面法线(垂直于表面的向量)的点积**告诉你光强:

```
diffuse = max(0, N · L)
```

N 是法线,L 是指向光源的向量(都归一化)。这就是 **Lambert 漫反射**(Lambert's cosine law),图形学最古老也最重要的光照公式。

Lambert 解释了**漫反射**(matte 表面)——但没解释**高光**(specular highlights,金属/塑料的反光)。Phong 1975 年加上一个 specular 项:

```
specular = pow(max(0, R · V), shininess)
```

R 是反射光向量,V 是视线向量。`pow(..., shininess)` 让高光集中在反射方向附近。

完整 Phong 模型:

```
final = ambient + diffuse * tex_color + specular * spec_color
```

ambient 是「环境光」(常数,模拟间接光),diffuse 是 Lambert,specular 是 Phong。三部分加起来就是 1975-2010 年代游戏的标准光照。

心理锚点:看完今天,你能向队友解释「为什么 3D 物体需要光照才有立体感」。你能用 Rust 写 Phong 光照。你能用 30 秒说清「点积在光照里的角色」。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. 在白板上画**光照几何**——光源 L、表面法线 N、视线 V、反射 R 四个向量
2. 推导 Lambert 漫反射:`diffuse = max(0, N · L)`
3. 推导 Phong 镜面反射:`specular = pow(max(0, R · V), n)`,其中 `R = reflect(-L, N)`
4. 介绍 Blinn-Phong 优化:`specular = pow(max(0, N · H), n)`,H 是半角向量 `(L + V) / |L + V|`——更快,质量接近
5. 把光照整合到 sprite 渲染:每个 sprite 的每个像素查「表面法线」,算光照,加到颜色上
6. 强调:**所有光照在 linear 空间做**(Day 094 的预备)

Casey 强调,光照的**几何直觉**比公式更重要——你必须能在脑子里画出 N、L、V 的关系。这是后面 Day 097 法线贴图、Day 200+ PBR 的基础。

## 2 · 心智模型

### 费曼类比:正午太阳 vs 日落

中午太阳当头(光从上方来),地面(法线朝上)被**直射**——光强最大。

日落时太阳在地平线(光从侧面来),地面被**斜射**——同样面积的光散到更大区域,光强减弱(实际是 `cos θ`,θ 是光和法线的夹角)。

这就是 Lambert 余弦定律:**单位面积接收的光强 = 光强 × cos(入射角)**。

游戏里:你可以让一个表面的法线朝任意方向,N·L 自动算出光强。这就是为什么 3D 模型的每个面有不同的法线——它们决定了面在光照下的亮度。

### 严谨原理

#### 2.1 法线 (Normal)

**定义**:法线是垂直于表面的**单位向量**(长度为 1)。平面有 2 个法线方向(正面 / 背面),约定选「朝外的」那个。

2D 平面的法线:旋转 90°。`(1, 0)` 的法线是 `(0, 1)` 或 `(0, -1)`。

3D 三角形的法线:用叉积 `cross(v1 - v0, v2 - v0)`,然后归一化。叉积给出垂直于两个向量的第三个向量(右手定则)。

#### 2.2 Lambert 漫反射

**几何**:光源 L,法线 N,夹角 θ。光照强度:

```
intensity = max(0, cos θ) = max(0, N · L)  (假设 N 和 L 都是单位向量)
```

`max(0, ...)` 因为负数意味着光在背面,不应贡献光强。

```
final_diffuse = light_color × surface_color × max(0, N · L)
```

每个分量(R, G, B)独立算。`light_color` 是光的颜色(比如红色光源 = `(1, 0, 0)`),`surface_color` 是材质颜色(从纹理采样)。

#### 2.3 Phong 镜面反射

漫反射模拟的是**粗糙表面**(磨砂、墙壁、木头)。光滑表面(金属、玻璃)有**镜面高光**(specular highlight)——光从某个角度看,表面反射出一团亮斑。

**Phong 模型**:
1. 算反射光向量:`R = reflect(-L, N) = 2(N·L)N - L`
2. 算视线向量 V(从表面指向相机)
3. 镜面反射 = `pow(max(0, R · V), shininess)`

`shininess` 是「光滑度」——金属 ~100,塑料 ~10,磨砂 ~2。

**问题**:`R · V` 计算需要先算 R,涉及一次反射变换。**Blinn 1977 年优化**:

```
H = normalize(L + V)  # 半角向量
specular = pow(max(0, N · H), shininess)
```

H 是 L 和 V 的「中间」方向——它代表「如果表面绕 H 法线转一点,刚好让 L 反射到 V」。Blinn-Phong 用 N·H 代替 R·V,**少算一次反射**。质量几乎一样,速度快。今天 GPU 标准都用 Blinn-Phong。

#### 2.4 环境光 (Ambient)

Lambert + Phong 模拟直射光。但现实里有**间接光**——光被环境反射,照亮背光面。完全模拟间接光需要「全局光照」(Global Illumination, GI),计算量巨大。

**简化**:加一个常数环境光 `ambient`,模拟「背光面也能看见一点东西」。

```
final = ambient_constant + diffuse + specular
```

ambient 通常很小(0.1-0.2),只为了让背光面不是纯黑。

#### 2.5 完整 Phong 公式

```
final_color = ambient
            + diffuse_intensity * light_color * surface_color * max(0, N · L)
            + specular_intensity * light_color * spec_color * pow(max(0, N · H), shininess)
```

每个 RGB 通道独立计算。所有颜色在 linear 空间。

#### 2.6 实现要点

**1. 法线来源**:
- 2D 矩形:法线固定 (0, 0, 1) 朝相机(因为 2D)
- 3D 三角形:用顶点法线插值(平滑表面),或面法线(平面表面)
- 法线贴图(Day 097):每像素查纹理得到法线

**2. 归一化**:`N`、`L`、`V`、`H` 都必须是单位向量。**插值后归一化**——线性插值破坏单位长度。

**3. Linear 空间**:`light_color * surface_color` 必须在 linear 空间做(见 Day 094)。

**4. 半向量优化**:`H = (L + V) / |L + V|`。如果 L 和 V 都单位,`L + V` 的长度可计算,但归一化需要 `1 / |L+V|`。

### Rust 实现

```rust
#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
    fn add(self, o: Self) -> Self { Self::new(self.x+o.x, self.y+o.y, self.z+o.z) }
    fn sub(self, o: Self) -> Self { Self::new(self.x-o.x, self.y-o.y, self.z-o.z) }
    fn scale(self, k: f32) -> Self { Self::new(self.x*k, self.y*k, self.z*k) }
    fn length(self) -> f32 { self.dot(self).sqrt() }
    fn normalized(self) -> Self {
        let l = self.length();
        if l > 1e-6 { self.scale(1.0 / l) } else { Self::new(0.0, 0.0, 0.0) }
    }
}

#[derive(Copy, Clone)]
struct Color { r: f32, g: f32, b: f32 }  // linear, 0..1+

#[derive(Copy, Clone)]
struct Light {
    direction: Vec3,  // 指向光源(单位向量)
    color: Color,
    intensity: f32,
}

fn reflect(incident: Vec3, normal: Vec3) -> Vec3 {
    // R = I - 2(I·N)N
    let d = incident.dot(normal);
    incident.sub(normal.scale(2.0 * d))
}

fn phong_lighting(
    surface_color: Color,
    normal: Vec3,
    view_dir: Vec3,    // 指向相机(单位向量)
    light: Light,
    ambient: Color,
    shininess: f32,
) -> Color {
    let n = normal;  // 假设已归一化
    let l = light.direction;
    let v = view_dir;
    let h = l.add(v).normalized();  // Blinn-Phong 半角

    let ndotl = n.dot(l).max(0.0);
    let ndoth = n.dot(h).max(0.0);
    let specular = ndoth.powf(shininess);

    Color {
        r: ambient.r
            + light.intensity * light.color.r * surface_color.r * ndotl
            + light.intensity * light.color.r * specular,
        g: ambient.g
            + light.intensity * light.color.g * surface_color.g * ndotl
            + light.intensity * light.color.g * specular,
        b: ambient.b
            + light.intensity * light.color.b * surface_color.b * ndotl
            + light.intensity * light.color.b * specular,
    }
}

fn main() {
    // 表面:红色,法线朝相机 (0,0,1)
    let surface = Color { r: 1.0, g: 0.0, b: 0.0 };
    let normal = Vec3::new(0.0, 0.0, 1.0);
    let view = Vec3::new(0.0, 0.0, 1.0);

    // 光从右上方斜照下来
    let light = Light {
        direction: Vec3::new(0.7, 0.3, 0.7).normalized(),
        color: Color { r: 1.0, g: 1.0, b: 1.0 },
        intensity: 1.0,
    };
    let ambient = Color { r: 0.1, g: 0.1, b: 0.1 };

    let result = phong_lighting(surface, normal, view, light, ambient, 50.0);
    println!("final color: r={:.3} g={:.3} b={:.3}", result.r, result.g, result.b);
    // 红通道应该有 N·L + specular 的贡献
    // N·L = (0,0,1) · (0.7,0.3,0.7)/|...| = 0.7/sqrt(0.49+0.09+0.49) ≈ 0.662
    // 预期:r ≈ 0.1 + 0.662 + specular
}
```

**逐行解释**:
- `Vec3` — 3D 向量,跟 Day 041 介绍的 Vec2 类似,加一个 z
- `dot` — 点积,光照的核心运算
- `normalized` — 归一化,除零保护
- `reflect` — 反射公式 `I - 2(I·N)N`(同 Day 044 的 2D 版本,3D 同理)
- `powf(shininess)` — `^n`,控制高光锐度
- `max(0.0, ...)` — Lambert 定律要求光强非负

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

光照在游戏里的实际应用:

1. **静态光照**(预计算):地图设计时烘焙(bake)光照到纹理。运行时无开销,但不能动态改
2. **动态光照**(实时):每帧重算。开销大,但光源可以动(火把、手电筒、子弹)
3. **多光源**:每个光源独立算 Phong,最后加起来。性能 N 倍
4. **光照衰减**:光强随距离减弱 `1/d²`(物理)。但游戏常简化成线性 `1 - d/range`(更可控)

**坑:法线必须归一化**。插值破坏单位长度,光照结果错。每个像素都要 `normalize()`。

**坑:Half-vector 在 view 接近表面平行时**:`L+V` 接近 0,归一化爆炸。加 epsilon 保护。

### 3.2 · 🎨 图形学视角

光照模型演化:

| 模型 | 年代 | 复杂度 | 何时用 |
|---|---|---|---|
| Lambert | 1760 | 极简 | 漫反射(纸张、墙壁) |
| Phong | 1975 | 简单 | 高光(塑料、玻璃) |
| Blinn-Phong | 1977 | 简单 | Phong 的优化版(主流) |
| Cook-Torrance | 1982 | 复杂 | PBR(金属、生锈) |
| Oren-Nayar | 1994 | 中等 | 粗糙表面(月球、黏土) |
| PBR (Disney) | 2012 | 复杂 | 现代 3D 游戏/电影 |

**BRDF**(Bidirectional Reflectance Distribution Function):双向反射分布函数,所有光照模型的数学框架。给定入射光 L、出射方向 V、法线 N,BRDF 返回「这个方向反射多少光」。Phong 是 BRDF 的一个特例。

**全局光照 (Global Illumination, GI)**:考虑光的多次反射。完整 GI 需要 path tracing(光线追踪),慢得吓人。游戏用各种近似(SSAO、SSGI、Light Propagation Volumes、Voxel GI)。Day 600+ Casey 会讨论。

### 3.3 · 🐧 Linux 系统编程视角

光照计算本身是纯数学,但性能上 Linux 相关:

1. **SIMD**:Vec3 dot / add / mul 是 3 个 f32 独立运算,SIMD `_mm_mul_ps` 一次算 4 个像素(把每个像素的 RGB 打包)。Casey Day 112+ 大量用。
2. **多线程**:每个光源独立,可以并行算。或者按屏幕分块(tile-based),每块独立。
3. **GPU 计算光照**:Day 235+ 切 OpenGL 后,光照搬到 fragment shader,GPU 几千核心并行算。

## 5 · 对照与变奏

### Lambert 余弦定律的物理推导

考虑光从 L 方向来,照射表面。光的能量流过某面积 A。如果表面法线和 L 同向,光「正好打在」A 上——光强最大。如果表面斜着,L 方向上的光散到更大面积 `A / cos θ`(投影原理)——单位面积光强变弱 `cos θ`。

这就是 Lambert 余弦定律——简单几何,深刻结果。

### 2D 光照 vs 3D 光照

2D 游戏通常**不用真实光照**——sprite 是预渲染的(美术已经画好阴影)。Casey HH 是 2.5D,所以他需要光照。2D 游戏「fake 3D 光照」的方法:
- 全屏 normal map(描述 sprite 表面朝向)
- 在 sprite 上算光照
- 这就是 Day 097 法线贴图的思想

### CPU vs GPU 光照

CPU 光照慢——单核几千万光照计算/秒,1920×1080 屏幕约 2M 像素,每像素一次光照 = 几十帧/秒极限。

GPU 光照是 fragment shader 的一部分,几千核心并行,每秒几十亿光照计算,完全免费(对现代 GPU 是小菜一碟)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Blinn-Phong 比 Phong 快?给出 2 个理由。

**参考解答**:
1. **少算反射向量**。Phong 要 `R = reflect(-L, N)`,涉及一次点积和两次向量乘加。Blinn-Phong 直接 `H = (L + V).normalized()`,只需一次加法 + 一次归一化。
2. **`N·H` 比 `R·V` 更稳定**。当 V 接近表面平行时,`R·V` 变化剧烈;`N·H` 平滑过渡。所以 Blinn-Phong 用更低的 shininess 就能达到同样效果,实际工作量更少。

### Lv3 · 迁移设计

**题**:你的游戏是 2D 俯视角,玩家在地图上走。你想做一个**手电筒**——玩家朝向方向的锥形光。算法是什么?

提示:
- 手电筒是「有方向的光源」(directional light 的一种)
- 锥形光:除了 Lambert,还要算「光的方向和手电筒方向的夹角」
- 夹角小于某阈值(比如 30°)才有光,大于的全黑
- 平滑边缘:`smoothstep` 函数让边缘渐变

### 完整 Phong 光照演示

```rust
// [Vec3 / Color / Light / reflect / phong_lighting 同 §2]

fn render_sphere_with_lighting(width: usize, height: usize) -> Vec<u8> {
    let mut bytes = vec![0u8; width * height * 4];
    let cx = width as f32 / 2.0;
    let cy = height as f32 / 2.0;
    let radius = width as f32 * 0.3;

    let light = Light {
        direction: Vec3::new(0.7, -0.3, 0.7).normalized(),
        color: Color { r: 1.0, g: 1.0, b: 1.0 },
        intensity: 1.0,
    };
    let ambient = Color { r: 0.1, g: 0.1, b: 0.1 };
    let view = Vec3::new(0.0, 0.0, 1.0);  // 视线朝相机
    let surface_color = Color { r: 0.7, g: 0.2, b: 0.2 };  // 暗红

    for y in 0..height {
        for x in 0..width {
            let dx = x as f32 - cx;
            let dy = y as f32 - cy;
            let r2 = dx*dx + dy*dy;
            if r2 < radius * radius {
                // 球面投影:Z = sqrt(r^2 - x^2 - y^2)
                let z = (radius * radius - r2).sqrt();
                let normal = Vec3::new(dx, dy, z).scale(1.0 / radius);  // 法线 = (dx, dy, dz) / r
                let lit = phong_lighting(surface_color, normal, view, light, ambient, 50.0);
                // Clamp + 转 sRGB
                let s = |c: f32| -> u8 {
                    let l = if c <= 0.0031308 { c * 12.92 } else { 1.055 * c.powf(1.0/2.4) - 0.055 };
                    (l * 255.0).round().clamp(0.0, 255.0) as u8
                };
                let idx = (y * width + x) * 4;
                bytes[idx]     = s(lit.r);
                bytes[idx + 1] = s(lit.g);
                bytes[idx + 2] = s(lit.b);
                bytes[idx + 3] = 255;
            }
        }
    }
    bytes
}

fn main() {
    let bytes = render_sphere_with_lighting(400, 400);
    // 写出 PPM(无依赖)
    // 或用 image crate 写 PNG
    println!("rendered sphere");
}
```

### Troubleshooting

- **球看起来扁** — 法线计算错。检查 `dx, dy, z` 是否正确归一化
- **没有高光** — `view_dir` 必须指向相机,不是表面到光源
- **暗部全黑** — ambient 太小或为 0
- **色彩失真** — 没 linear 空间计算,或 sRGB 转换错
