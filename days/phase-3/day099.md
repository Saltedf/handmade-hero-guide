
# Day 099 · 测试环境贴图

> Phong 光照给你**直接光**——光从光源直线到达表面。但现实里还有**间接光**——光被环境(天空、墙壁、其他物体)反射后才到达表面。比如金属球反射出蓝天白云,玻璃杯折射出后面的图案。这就是**环境贴图**(environment map)。今天 Casey 加上环境贴图,让 sprite 表面反射出周围环境——立体感和真实感立刻上一个台阶。

## 0 · 为什么要有这一天

考虑一个抛光金属球。它**反射**周围环境——你看到球上有蓝天、有地面、有你自己的倒影。Phong 模型算不出这个——Phong 只算「光从光源直线到达」,不算「光被周围反射到达」。

**环境贴图**(environment map,也叫 reflection map 或 cube map)的思想:
1. 用一张图存储「**周围 360° 的全景**」(可以是 cube map 6 面或 equirectangular 全景图)
2. 渲染时,根据表面**反射向量**查这张图
3. 反射向量指向哪,就从图上采哪个像素

举例:球面上一点的反射向量指向天空 → 查到蓝天色;指向地面 → 查到棕色;指向相机 → 查到你的脸(如果有)。

这就是**环境反射**(environment reflection),让金属/玻璃/水面看起来真实。

今天 Casey 还不做完整 cube map(那需要 6 张图,Day 200+ 加),他先做简化版:
- 一张**球面环境贴图**(sphere map)——把 360° 环境压成一张 2D 图
- 用 Day 096 的反射向量 + 简单 uv 变换采样

这给你 80% 视觉效果,20% 工作量。是教学经典做法。

心理锚点:看完今天,你的 sprite 有了**反射感**——光照时表面闪出环境色,不再是「哑光」的。你能向队友解释「环境贴图让金属像金属」。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. 加载一张测试用的环境贴图(简单的 256×256,程序化生成的「天空 + 地面」图案)
2. 计算**反射向量** `R = reflect(-V, N)`(V 是视线,N 是法线)。R 指向「视线被反射的方向」
3. 把 R 转换成 uv 坐标——`u = 0.5 + R.x * 0.5`、`v = 0.5 - R.y * 0.5`(把 [-1, 1] 范围映射到 [0, 1])
4. 采样环境贴图,得到**反射色**
5. 把反射色加到 Phong 结果上(简单加,或按材质 reflectivity 混合)

Casey 强调这只是「**测试**」——明天 Day 100 会写更精确的反射向量(尤其是法线贴图下的),Day 200+ 切 cube map。今天是「让流程跑通」。

## 2 · 心智模型

### 费曼类比:镜子 vs 鸡蛋盒

**镜子**(完美反射):你站在镜子前,镜子把你的影像反射回你眼睛。这就是「视线被反射」——入射方向 V,反射方向 R = reflect(-V, N),N 是镜面法线。

**金属球**(部分反射):不是完美镜子,但表面光滑度足够反射环境——只是反射被「**模糊**」了一些。Phong 高光其实是一种环境反射——只不过把整个环境简化成一个「光源点」。

**环境贴图** = 把镜子里的图像预先存好,渲染时按反射方向查表。这样不需要真正去渲染周围的物体(那需要 ray tracing,贵得多)。

### 严谨原理

#### 2.1 反射向量

回顾 Day 044 / Day 096 的反射公式:

```
R = I - 2(I · N) N
```

I 是入射方向(从光源 / 相机指向表面)。**但环境反射里,I 是视线**,而且**反向**——从表面指向相机。

约定:`V` = view direction(从表面指向相机),那么入射 = -V。反射:
```
R = reflect(-V, N) = -V - 2(-V · N) N = 2(V·N)N - V
```

R 是「视线被法线反射后的方向」。指向「如果你是相机,你能看到的反射方向」。

#### 2.2 反射向量到环境贴图 uv

Sphere map(球面贴图)约定:把 360° 环境投影到一张 2D 图。常见映射:

```
M = 2 * sqrt((R.x + 1)²/8 + (R.z + 1)²/8 + (R.y + 1)²/8 * ...)
# 太复杂,简化版:
u = 0.5 + R.x * 0.5  # 把 R.x ∈ [-1, 1] 映射到 [0, 1]
v = 0.5 - R.y * 0.5  # 注意 y 取反(因为图像 v 朝下)
```

简化版忽略 z(深度),只用 xy 平面投影。**不严格正确**,但视觉效果接近。

#### 2.3 Cube map(简介)

真正的环境贴图用 **cube map**——6 张图代表立方体 6 面。反射向量 R 直接当 3D 方向,选最大分量的轴对应的面,再从那张图采样。

```
fn sample_cube(cube: &CubeMap, r: Vec3) -> Color {
    let abs_x = r.x.abs();
    let abs_y = r.y.abs();
    let abs_z = r.z.abs();
    let (face, u, v) = if abs_x >= abs_y && abs_x >= abs_z {
        if r.x > 0 { (Face::PosX, r.z, -r.y) } else { (Face::NegX, -r.z, -r.y) }
    } else if abs_y >= abs_x && abs_y >= abs_z {
        // 类似
    } else {
        // 类似
    };
    cube.faces[face].sample_uv(u, v)
}
```

复杂但严格正确。Casey HH Day 200+ 切 cube map。

#### 2.4 加入 Phong

完整公式:

```
final = ambient
      + diffuse * surface * max(0, N · L)
      + specular * pow(max(0, R · V), shininess)
      + env_color * reflectivity   # 新增
```

`reflectivity` 是材质的「反射率」——金属 0.8,塑料 0.1,木头 0.0。`env_color` 是环境贴图采样结果。

**注意**:env_color 也在 linear 空间。

#### 2.5 实现

```rust
struct EnvMap {
    bitmap: LinearBitmap,
}

impl EnvMap {
    fn sample_reflection(&self, reflect_dir: Vec3) -> Color {
        // 简化 sphere map 映射
        let u = 0.5 + reflect_dir.x * 0.5;
        let v = 0.5 - reflect_dir.y * 0.5;
        let texel = self.bitmap.sample(u.clamp(0.0, 1.0), v.clamp(0.0, 1.0));
        Color { r: texel[0], g: texel[1], b: texel[2] }
    }
}

#[derive(Copy, Clone)]
struct Material {
    diffuse_color: Color,
    shininess: f32,
    reflectivity: f32,  // 0..1, 0 = 不反射, 1 = 完全反射
}

fn shade_with_env(
    surface_normal: Vec3,
    view_dir: Vec3,
    light: Light,
    material: Material,
    env: &EnvMap,
    ambient: Color,
) -> Color {
    // Phong(同 Day 096)
    let n = surface_normal;
    let v = view_dir;
    let l = light.direction;
    let h = l.add(v).normalized();
    let ndotl = n.dot(l).max(0.0);
    let ndoth = n.dot(h).max(0.0);
    let specular = ndoth.powf(material.shininess);

    let diffuse_color = material.diffuse_color;
    let phong = Color {
        r: ambient.r + light.intensity * light.color.r * (diffuse_color.r * ndotl + specular),
        g: ambient.g + light.intensity * light.color.g * (diffuse_color.g * ndotl + specular),
        b: ambient.b + light.intensity * light.color.b * (diffuse_color.b * ndotl + specular),
    };

    // 环境反射
    let r = reflect_vector(v, n);
    let env_color = env.sample_reflection(r);

    // 混合:phong + env_color * reflectivity
    let refl = material.reflectivity;
    Color {
        r: phong.r * (1.0 - refl) + env_color.r * refl,
        g: phong.g * (1.0 - refl) + env_color.g * refl,
        b: phong.b * (1.0 - refl) + env_color.b * refl,
    }
}

fn reflect_vector(v: Vec3, n: Vec3) -> Vec3 {
    // R = 2(V·N)N - V
    let d = v.dot(n);
    n.scale(2.0 * d).sub(v)
}

fn main() {
    // 测试环境贴图:简单的 1x1 蓝色
    let env_bytes = vec![0, 100, 200, 255];
    let env_bitmap = LinearBitmap::from_srgba_straight(1, 1, &env_bytes);
    let env = EnvMap { bitmap: env_bitmap };

    let mat = Material {
        diffuse_color: Color { r: 0.5, g: 0.5, b: 0.5 },
        shininess: 30.0,
        reflectivity: 0.5,
    };
    let normal = Vec3::new(0.0, 0.0, 1.0);
    let view = Vec3::new(0.0, 0.0, 1.0);
    let light = Light {
        direction: Vec3::new(0.0, 0.0, 1.0),
        color: Color { r: 1.0, g: 1.0, b: 1.0 },
        intensity: 0.0,  // 暂时关闭,看 env 反射
    };
    let ambient = Color { r: 0.0, g: 0.0, b: 0.0 };

    let lit = shade_with_env(normal, view, light, mat, &env, ambient);
    println!("lit color: r={:.3} g={:.3} b={:.3}", lit.r, lit.g, lit.b);
    // diffuse 是灰,reflectivity 0.5,env 是蓝(0, 100, 200 的 linear)
    // 预期:lit 应该有一定蓝分量
}
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

环境贴图在游戏的应用:

1. **金属 / 玻璃物体**:剑、盾、汽车漆面、水面
2. **湿润表面**:雨后街道、湿润石头
3. **眼睛**:角色眼睛的角膜反射(让眼睛「活」起来)
4. **汽车 / 飞机 simulator**:整个车体 / 机身的反射

**坑:静态 vs 动态环境贴图**:
- **静态**:预渲染的 cube map(美术做),运行时不变。简单快,但物体移到别处还反射原来环境(假)
- **动态**:每帧重渲染 cube map(从物体中心 6 个方向)。真,但慢 6 倍
- **屏幕空间反射 (SSR)**:用当前 framebuffer 做近似反射。中等质量,中等开销

工业做法:**静态 cube map + 局部 SSR**——大部分环境用 cube map,附近的物体用 SSR 增强。

### 3.2 · 🎨 图形学视角

环境贴图的几种格式:

1. **Sphere map**:2D,1998 PlayStation 时代。简单,但有 singularity(极点)。Casey HH 用这个。
2. **Cube map**:6 张 2D,OpenGL 3.0+ 标准。最常见。
3. **Dual paraboloid**:2 张 2D,各自半球。比 sphere map 好,但少用。
4. **Equirectangular**:1 张 2D,全景图(经纬度展开)。HDR 全景图常用。

**Prefilter environment map**:PBR 用法——预先对 cube map 做不同 roughness 的模糊版本,运行时按材质 roughness 采样。这是 PBR IBL(image-based lighting)的核心。Casey HH Day 200+ 详细讲。

### 3.5 · 🐧 Linux 系统编程视角(内核空间 / 硬件加速)

Linux 系统里"碰撞 / 相交检测"的核心思想在多处出现,理解这些能让你看 Casey 的 2D / 3D collision 算法在更广的语境里。

**内核的 page fault 处理**。虚拟内存到物理内存的映射,本质是"地址空间相交检测"。CPU 访问虚拟地址,MMU 查 page table,如果地址不在已映射范围内 → page fault。内核接 fault,检查(1)地址合法吗(进程的 VMA 区间)、(2)权限对吗(read / write / exec)、(3)page 在物理内存还是 swap。这套检查就是"区间相交 + 属性匹配",和 Casey 在 day 050 的 Minkowski collision 在抽象上一致——"用几何空间判断两个东西是否接触"。

```bash
# 看你进程的 VMA(虚拟内存区域)
cat /proc/$$/maps
# 输出形如:
# 56001234-56005678 r-xp ...  /usr/bin/bash
# 7f1234560000-7f1234780000 r--p ... /usr/lib/libc.so.6

# 触发 page fault(故意访问非法地址)
python3 -c "import ctypes; ctypes.cast(0xdeadbeef, ctypes.POINTER(ctypes.c_int))[0] = 0"
# 输出:Segmentation fault (core dumped)
```

**epoll / poll / select** 是 IO 多路复用,本质是"时间区间相交"。你给内核 N 个 fd,内核检查"哪个 fd 当前可读 / 可写"。这是 N 路并行等待,内核用红黑树 + ready list 高效管理。和 collision detection 的 broad phase 类似——快速排除不可能相交的对,只在 narrow phase 详细检查。

**文件锁(flock / fcntl)**。Linux 文件锁检测"两个进程是否同时持有冲突锁"——这是"锁区间相交"。flock 用 inode-level 锁,fcntl 用 byte-range 锁(`fcntl(F_SETLK, F_WRLCK, {100..200})` 锁字节 100-200)。内核维护锁列表,新锁请求时遍历检查冲突——这就是 interval intersection 检测。

**网络栈的 TCP / IP header 校验**。每个 TCP/IP 包带 checksum,内核收到包校验——本质是"数据完整性检测"。和 collision detection 不直接相关,但**思想相同**——"用一个数学函数快速判断数据是否合法"。

**cgroup 的资源限制**。`cpu.max = 50000 100000` 表示 cgroup 在每 100ms 周期内最多用 50ms CPU。内核定期检查"当前周期已用多少 CPU",超了 throttle。这是"时间区间累积 + 阈值检测",和 Casey 的"span duration + frame budget"逻辑相同。

**netfilter / iptables** 用 BPF 风格的规则匹配,检查每个网络包。"规则匹配"本质是"包属性 vs 规则区间"——"src IP in 192.168.0.0/16 && dst port == 22"是区间检测。BPF (Berkeley Packet Filter) 让用户写过滤器,内核执行——这种"用户定义函数 + 内核执行"模式是 eBPF 的基础。

**kernel scheduling**。Linux CFS(Completely Fair Scheduler)维护红黑树 of runnable tasks,按 vruntime 排序。每个 tick(1ms / 4ms),CFS 检查当前 task 是否该让出 CPU——"时间片用完了吗"。这是"时间累积 + 阈值切换",和游戏 update 循环的 frame budget 检查同构。

### 3.6 · 🦀 Rust 生态视角

Rust 在游戏物理 / 碰撞领域有几个值得关注的 crate 和模式。

**`rapier`** 是 Rust 的 2D / 3D 物理引擎,由 Dimforge 开发。Rapier 提供 rigid body dynamics、collision detection、joints、rays、sensors——是 Bevy 生态的物理默认选项。Rapier 用 ECS 风格 API,内部用 SOA(struct of arrays)布局,cache 友好。

```rust
use rapier3d::prelude::*;

let mut rigid_body_set = RigidBodySet::new();
let mut collider_set = ColliderSet::new();

let rigid_body = RigidBodyBuilder::dynamic().translation(vector![0.0, 5.0, 0.0]).build();
let handle = rigid_body_set.insert(rigid_body);
let collider = ColliderBuilder::ball(0.5).build();
collider_set.insert_with_parent(collider, handle, &mut rigid_body_set);
```

Rapier 内部用 **broad phase(AABB tree)+ narrow phase(GJK / SAT)**,和工业 C++ 引擎(Box2D、Bullet、PhysX)思路一致。Casey HH 手写简化版,Rapier 是 production-grade。

**`parry`** 是 Rapier 抽出来的纯 collision detection 库。parry 提供 shape(ball、cuboid、convex hull、triangle mesh)、ray cast、point projection、pair collision——不涉及 dynamics。如果你只想要碰撞不想物理,parry 是答案。

**`nalgebra`** 是 Rust 的线性代数库,Dimforge 出品(同 Rapier / parry)。`Vector3`、`Matrix4`、`Quaternion`、`Isometry3`——3D 游戏需要的所有数学类型。比 `cgmath` 现代、比 `euclid` 全面。

**Rust ECS 的 collision pattern**。Bevy + Rapier 的典型代码:

```rust
use bevy::prelude::*;
use bevy_rapier3d::prelude::*;

fn setup(mut commands: Commands) {
    commands.spawn((
        RigidBody::Dynamic,
        Collider::ball(1.0),
        Transform::from_translation(Vec3::new(0.0, 5.0, 0.0)),
    ));
}

fn on_collision(
    mut events: EventReader<CollisionEvent>,
    query: Query<&Name>,
) {
    for event in events.read() {
        if let CollisionEvent::Started(e1, e2, _) = event {
            println!("{:?} collided with {:?}", query.get(*e1), query.get(*e2));
        }
    }
}
```

ECS 风格——entity 加 Collider component,系统处理 CollisionEvent。这是 Rust 风格的 collision 设计——数据导向、零成本、类型安全。Casey HH 用 OOP 风格(`struct Player { collider: Collider }`),简单但不够通用。

**Rust 的 zero-cost abstraction** 让 collision detection 可以既高级又快:

```rust
// 高级 API
let hits = colliders.iter()
    .filter(|c| c.aabb_intersects(&target_aabb))
    .filter(|c| c.shape_intersects(&target_shape))
    .collect::<Vec<_>>();

// LLVM 把这优化成手写 C 的等价代码
```

Rust 的 iterator chain + 闭包,被 LLVM inline + vectorize,生成和手写循环一样快的代码。这是 Rust 在性能敏感领域的杀手锏。

**Rust 的 SIMD** 对 collision 特别有用。AABB 测试 8 个浮点比较,用 SIMD 一次处理 4-8 个 AABB。Rust 的 `std::simd`(unstable)或 `wide` crate(stable)提供 SIMD API。Rapier 内部用 SIMD 加速 broad phase。

**Rust 的多线程 collision**。collision detection 是 embarrassingly parallel——N 个 object pair 互相独立。Rust 的 `rayon` 提供 parallel iterator,`colliders.par_iter().filter(...)` 自动并行。Bevy 用 ECS 的 `query.par_iter()` 同样效果。

**Rust 的 `Send + Sync`**。collision data 跨线程共享,要 `Send + Sync`。Rust 编译时检查——如果你的 Collider 包含 `Rc<...>`,编译失败,因为 Rc 不是 Send。这种类型系统保证的多线程安全,是 Rust 比 C++ 优势的地方。

**Rust 的 `smallvec`** 在 collision 里有用。pair list 经常是空的或只有 1-2 个 pair,用 `SmallVec<[Pair; 4]>` 避免堆分配,大部分情况栈上。

**Rust 的 `ahash`** 在 spatial hash 里替代 `DefaultHasher`——3-5 倍速度。Casey HH 的 hash chunk storage(Phase 2)用 `DefaultHasher`,Rust 版应该用 `ahash` 或 `fxhash`。


### 3.7 · 🎮 游戏开发实践中的 collision edge case

实际游戏开发中,collision detection 有几个 Casey HH 没展开但工业级必须处理的 edge case:

**高速物体的 tunneling**。子弹 1000 m/s 飞过 1m 厚的墙——一帧 16ms 内子弹移动 16m,完全穿过墙。常规 collision 检测只在每个时刻检查位置,可能"上一帧子弹在墙左,这一帧子弹在墙右,中间从未检测到碰撞"。这叫 **tunneling** 或 **continuous collision detection failure**。解决方案:

1. **Continuous Collision Detection (CCD)**:不只在 t 和 t+dt 检查,而是在 [t, t+dt] 区间检查 swept volume(扫掠体)。子弹变成胶囊(从 prev_pos 到 curr_pos 的圆角线段),墙还是 AABB,测胶囊 vs AABB 相交。
2. **Substepping**:把帧切成小步(如 1ms × 16 步),每步检测一次。简单但 CPU 重。
3. **Ray cast**:从 prev_pos 射线到 curr_pos,看路径上有没有墙。

Rapier / Box2D / PhysX 都内置 CCD。Casey HH 不做(简化),所以 HH 子弹慢(玩家近战为主)。

**多次接触的稳定性**。一个 box 落到地上,理论上有 4 个角都接触地面。如果 collision 系统每帧解决一个 penetration,box 会"抖动"——一帧一个角抬起,下一帧另一个角抬起。解决方案:

1. **Sequential impulse**:每次 solve 同时考虑所有 contact point,求全局最优。
2. **Baumgarte stabilization**:penetration resolution 加 bias 项,缓慢修正而非瞬间。
3. **Split impulse**:分离 velocity 修正和 position 修正,避免能量注入。

这些是物理引擎的内部黑魔法。Box2D / Bullet 的 solver 几千行代码,核心就是稳定地解决多接触。

**Stacking**(堆叠)。10 个箱子叠起来,每个箱子受重力 + 上面箱子压力 + 下面箱子支撑。物理引擎要稳定地保持 stack——任何数值误差会让 stack "爆炸"或"沉下去"。这是物理引擎的 benchmark 测试之一。Casey HH 不做堆叠(玩家不堆箱子),商业引擎必须稳定。

**Sleeping**。一个箱子掉到地上静止了,后续每帧检测它和地的碰撞是浪费 CPU。Sleeping 标记这种"长期不动 + 不被影响"的物体,跳过它的 collision / dynamics,只在被触碰时唤醒。Box2D / Rapier 都支持 sleeping,大型场景(10000 物体)性能关键。

**Broad phase 的选择**。N 个物体,O(N²) 配对检测太慢。Broad phase 快速排除不可能相交的对。三种主流算法:

1. **Sweep and Prune (SAP)**:按 AABB 的 min.x 排序,扫一遍,只在重叠区间内检测。O(N·K),K 是平均重叠数。Box2D 默认。
2. **Bounding Volume Hierarchy (BVH)**:树形 AABB 包围盒,自顶向下检查。O(N·log N)。Bullet / PhysX 默认。
3. **Spatial Hash**:把空间分网格,物体归入格子,只检测同格物体。Casey HH 用这个(day 055 hash chunk storage 的延伸)。

每种的取舍:SAP 适合动态场景、BVH 适合静态 + 动态混合、Spatial Hash 适合均匀分布的场景。Rapier 内部允许多种切换。

**Collision filtering**(碰撞过滤)。子弹不应该撞到玩家自己,玩家不应该穿过墙但应该能拿到 coin。每种 collision pair 决定"该不该测",用 **bitmask** 或 **callback**:

```rust
// Rapier 风格
let collision_groups = Group::GROUP_1 | Group::GROUP_2;
let solver_groups = Group::GROUP_1;
collider.set_collision_groups(collision_groups);
collider.set_solver_groups(solver_groups);
```

GROUP_1 = player、GROUP_2 = enemy、GROUP_3 = wall...通过 bitmask 组合快速过滤。比 callback 快(位运算 vs 函数调用)。Casey HH 不做过滤(简化),N 个物体全配对测;商业游戏必须过滤。

**Trigger volume**(触发区)。玩家进入某个区域触发事件——开门、播放音效、AI 触发战斗。这种"sensor" 不解决 penetration,只检测 overlap。Box2D / Rapier 有 `Sensor` 标记。Casey HH 用 manual AABB 检测(玩家 AABB vs trigger AABB),简单但够用。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Phong 的 specular 和环境贴图有什么关系?

**参考解答**:Phong 的 specular 本质上是**环境反射的特例**——把整个环境简化成一个「光源点」。环境贴图是 specular 的「**升级**」——把单一光源扩展成整个环境的图像。

数学上,Phong specular = 「环境贴图所有方向积分,但只算反射方向的高斯权重」——而完整环境贴图 = 「积分整个环境贴图,按 BRDF 权重」。PBR 把这个关系严格化。

## 8 · Rust / Arch 落地代码

完整 sprite + env 渲染(片段):

```rust
// [Vec3 / Color / Light / Material / EnvMap / shade_with_env / reflect_vector 同 §2]

fn render_sprite_with_env(
    fb: &mut LinearFramebuffer,
    sprite: &Sprite,
    env: &EnvMap,
    material: Material,
    origin: Vec2,
    m: Mat2,
    light: Light,
    view: Vec3,
    config: RenderConfig,
) {
    let inv = m.inverse();
    let (min_x, max_x, min_y, max_y) = compute_aabb(&origin, &m, fb.width, fb.height);
    for py in min_y..=max_y {
        for px in min_x..=max_x {
            let (u, v) = match pixel_to_uv(PixelCoord { px, py }, origin, inv) {
                Some(uv) => uv,
                None => continue,
            };
            let sample = sprite.sample_surface(u, v);
            if sample.alpha < config.alpha_threshold { continue; }
            // 用 material(注意:surface_color 从 sprite.diffuse 来,但 reflectivity 是 sprite 属性)
            let mut mat = material;
            mat.diffuse_color = sample.color;
            let lit = shade_with_env(sample.normal, view, light, mat, env, config.ambient);
            let bg = fb.pixels[py * fb.width + px];
            fb.pixels[py * fb.width + px] = blend_premul_linear(bg, lit, sample.alpha);
        }
    }
}
```
