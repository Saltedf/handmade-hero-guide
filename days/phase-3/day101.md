# Day 101 · 逆矩阵与转置矩阵

> 今天 Casey 做一件「明天(Day 102)才用得上,但必须先讲清楚」的事:**矩阵的逆 (inverse) 和转置 (transpose)**。这两个运算表面简单,但在图形学里有个反直觉的细节——**变换法线不能用原矩阵,必须用逆的转置**。这是无数初学者踩过的坑,Casey 决定花一整集讲透。

## 0 · 为什么要有这一天

考虑你有一个 3D 模型(比如球),你想旋转它。旋转用矩阵 R,顶点位置直接乘 R 就行:`v' = R · v`。

但你还要变换**法线**(用于光照)。直觉上,「法线也乘 R 不就行了?」——错!

反例:考虑非均匀缩放矩阵 `S = diag(2, 1, 1)`(x 方向拉 2 倍)。一个球变成椭圆。球面法线 `(1, 0, 0)` 直接乘 S 得 `(2, 0, 0)`——**这个法线不再垂直于椭圆表面**!椭圆表面在那个点的真实法线还是 `(1, 0, 0)`(因为是单位球被拉成椭圆,顶点位置改变但表面方向不变)。

正确做法:**法线乘 `(S⁻¹)ᵀ`**(S 的逆的转置)。`S⁻¹ = diag(0.5, 1, 1)`,转置后还是 `diag(0.5, 1, 1)`(对角矩阵转置不变)。法线 `(1, 0, 0)` 乘它得 `(0.5, 0, 0)`——长度变了,但**方向正确**。归一化后还是 `(1, 0, 0)`——对!

这就是「**变换法线用逆的转置**」的原因。今天 Casey 把这个数学原理讲透,明天 Day 102 应用到法线贴图变换。

心理锚点:看完今天,你能向队友解释「为什么变换法线不能用原矩阵」。你能用 Rust 实现 3×3 矩阵的逆和转置。你能用 30 秒说清「逆的转置」的几何意义。

## 2 · 心智模型

### 费曼类比:_undo 操作 _

想象你在用 Photoshop 编辑图片,做了一系列操作:缩放、旋转、平移。每个操作是一个矩阵。

**矩阵的逆 (inverse)**:就是「**undo 操作**」。如果你做了变换 M,那么 `M⁻¹ · M · v = v`(对任意 v)——**先做 M,再 undo,等于什么都没做**。

**矩阵的转置 (transpose)**:就是「**行列交换**」。把矩阵第 i 行第 j 列的元素,放到第 j 行第 i 列。视觉上就是沿主对角线翻转。

**正交矩阵的妙处**:旋转矩阵的转置 = 逆(`Rᵀ = R⁻¹`)。所以「**旋转的 undo 等于反向旋转**」——直觉上对。这意味着旋转矩阵的逆**免费**(转置比一般逆快得多)。

**法线变换的特殊性**:法线必须**垂直于表面**。普通矩阵变换保证「顶点位置变换正确」,但不保证法线方向正确。逆的转置 `(M⁻¹)ᵀ` 是经过数学推导得出的「**保证法线垂直性的变换**」。

### 严谨原理

#### 2.1 矩阵的转置

转置就是把行列交换。3×3 矩阵:

```
M = | a b c |          Mᵀ = | a d g |
    | d e f |                | b e h |
    | g h i |                | c f i |
```

第 (i, j) 位置的元素,在 Mᵀ 里在第 (j, i) 位置。

#### 2.2 矩阵的逆

逆矩阵 M⁻¹ 满足 `M · M⁻¹ = I`(I 是单位矩阵)。

**2×2 矩阵逆**:

```
M = | a b |    M⁻¹ = (1/det) · | d -b |
    | c d |                     | -c a |
det(M) = ad - bc
```

**3×3 矩阵逆**:用**伴随矩阵 / 行列式**法。3×3 行列式:

```
det(M) = a(ei - fh) - b(di - fg) + c(dh - eg)
```

逆矩阵:

```
M⁻¹ = (1/det) · adj(M)
```

`adj(M)` 是**伴随矩阵**(adjugate),由余子式构成。3×3 公式:

```
M = | a b c |
    | d e f |
    | g h i |

adj(M) = | (ei-fh)  (ch-bi)  (bf-ce) |
         | (fg-di)  (ai-cg)  (cd-af) |
         | (dh-eg)  (bg-ah)  (ae-bd) |
```

注意符号和位置(伴随矩阵是余子式矩阵的转置)。

#### 2.3 正交矩阵 (orthogonal matrix)

如果矩阵的列向量(或行向量)是**单位长度**且**互相垂直**,这个矩阵是正交的。正交矩阵满足:

```
Mᵀ · M = I    ⟺    Mᵀ = M⁻¹
```

**旋转矩阵是正交的**(列向量是旋转后的基向量,长度不变,互相垂直)。
**缩放矩阵一般不是正交的**(除非缩放是 1)。
**镜像矩阵是正交的**(行列式 = -1,但列向量仍正交)。

#### 2.4 法线变换:为什么用 `(M⁻¹)ᵀ`

考虑一个三角形,边向量 `e1 = v1 - v0` 和 `e2 = v2 - v0`。法线 `n = cross(e1, e2)`,满足:

```
n · e1 = 0
n · e2 = 0
```

(法线垂直于边)

对三角形做变换 M,新边向量 `e1' = M · e1`,`e2' = M · e2`。我们想找新法线 `n'`,满足 `n' · e1' = 0` 和 `n' · e2' = 0`。

设 `n' = G · n`(G 是某个矩阵,我们要找)。代入:

```
(G·n) · (M·e1) = 0
```

用矩阵性质 `(G·n) · (M·e1) = n · (Gᵀ · M · e1)`,所以:

```
n · (Gᵀ · M · e1) = 0
```

原本 `n · e1 = 0`,所以 `Gᵀ · M = I`,即 `G = (Mᵀ)⁻¹ = (M⁻¹)ᵀ`。

**结论**:法线变换矩阵 `G = (M⁻¹)ᵀ`——M 的逆的转置。

**特殊情况**:如果 M 是正交的(旋转),`M⁻¹ = Mᵀ`,所以 `G = (Mᵀ)ᵀ = M`——可以直接用 M!这就是为什么**旋转法线可以直接乘 R**(没有非均匀缩放时)。

#### 2.5 实际应用

3D 渲染管线里:
- 顶点位置:`world_pos = Model · local_pos`
- 顶点法线:`world_normal = (Model⁻¹)ᵀ · local_normal`(如果 Model 有非均匀缩放)

GPU shader 里通常是 `mat3 normal_matrix = transpose(inverse(mat3(model)))`,然后 `world_normal = normal_matrix * local_normal`。

### Rust 完整实现

```rust
#[derive(Copy, Clone, Debug)]
struct Mat3 {
    // 列主序:m_ij = 第 j 列第 i 行
    m00: f32, m10: f32, m20: f32,   // 第 0 列
    m01: f32, m11: f32, m21: f32,   // 第 1 列
    m02: f32, m12: f32, m22: f32,   // 第 2 列
}

impl Mat3 {
    fn identity() -> Self {
        Self {
            m00: 1.0, m10: 0.0, m20: 0.0,
            m01: 0.0, m11: 1.0, m21: 0.0,
            m02: 0.0, m12: 0.0, m22: 1.0,
        }
    }

    fn from_scale(sx: f32, sy: f32, sz: f32) -> Self {
        Self {
            m00: sx, m10: 0.0, m20: 0.0,
            m01: 0.0, m11: sy, m21: 0.0,
            m02: 0.0, m12: 0.0, m22: sz,
        }
    }

    /// 转置:行列交换
    fn transpose(self) -> Self {
        Self {
            m00: self.m00, m10: self.m01, m20: self.m02,
            m01: self.m10, m11: self.m11, m21: self.m12,
            m02: self.m20, m12: self.m21, m22: self.m22,
        }
    }

    /// 行列式
    fn determinant(self) -> f32 {
        self.m00 * (self.m11 * self.m22 - self.m12 * self.m21)
            - self.m01 * (self.m10 * self.m22 - self.m12 * self.m20)
            + self.m02 * (self.m10 * self.m21 - self.m11 * self.m20)
    }

    /// 逆矩阵:用伴随矩阵法
    fn inverse(self) -> Option<Self> {
        let det = self.determinant();
        if det.abs() < 1e-9 { return None; }
        let inv_det = 1.0 / det;

        // 伴随矩阵(余子式矩阵的转置)
        let c00 =  (self.m11 * self.m22 - self.m12 * self.m21);
        let c01 = -(self.m10 * self.m22 - self.m12 * self.m20);
        let c02 =  (self.m10 * self.m21 - self.m11 * self.m20);
        let c10 = -(self.m01 * self.m22 - self.m02 * self.m21);
        let c11 =  (self.m00 * self.m22 - self.m02 * self.m20);
        let c12 = -(self.m00 * self.m21 - self.m01 * self.m20);
        let c20 =  (self.m01 * self.m12 - self.m02 * self.m11);
        let c21 = -(self.m00 * self.m12 - self.m02 * self.m10);
        let c22 =  (self.m00 * self.m11 - self.m01 * self.m10);

        Some(Self {
            m00: c00 * inv_det, m10: c01 * inv_det, m20: c02 * inv_det,
            m01: c10 * inv_det, m11: c11 * inv_det, m21: c12 * inv_det,
            m02: c20 * inv_det, m12: c21 * inv_det, m22: c22 * inv_det,
        })
    }

    /// 法线变换矩阵:(M⁻¹)ᵀ
    fn normal_matrix(self) -> Option<Self> {
        self.inverse().map(|inv| inv.transpose())
    }

    fn mul_vec(self, v: Vec3) -> Vec3 {
        Vec3::new(
            self.m00 * v.x + self.m01 * v.y + self.m02 * v.z,
            self.m10 * v.x + self.m11 * v.y + self.m12 * v.z,
            self.m20 * v.x + self.m21 * v.y + self.m22 * v.z,
        )
    }
}

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
    fn length(self) -> f32 { self.dot(self).sqrt() }
    fn normalized(self) -> Self {
        let l = self.length();
        if l > 1e-6 { Self::new(self.x/l, self.y/l, self.z/l) } else { Self::new(0.0, 0.0, 1.0) }
    }
}

fn main() {
    // 测试 1:对角缩放矩阵的逆
    let s = Mat3::from_scale(2.0, 4.0, 0.5);
    let s_inv = s.inverse().unwrap();
    let n = Vec3::new(1.0, 0.0, 0.0);
    let n_transformed = s_inv.mul_vec(n);
    println!("normal after (S⁻¹)ᵀ: {:?}", n_transformed);
    // 预期:对角矩阵的逆的转置还是对角(沿对角线对称)
    // (S⁻¹)ᵀ = diag(0.5, 0.25, 2.0)
    // n_transformed = (0.5, 0, 0),归一化后 (1, 0, 0)——正确!

    // 测试 2:正交矩阵的逆 = 转置
    // 旋转矩阵绕 z 轴 30°
    let (sin, cos) = 30.0_f32.to_radians().sin_cos();
    let r = Mat3 {
        m00: cos, m10: sin, m20: 0.0,
        m01: -sin, m11: cos, m21: 0.0,
        m02: 0.0, m12: 0.0, m22: 1.0,
    };
    let r_inv = r.inverse().unwrap();
    let r_t = r.transpose();
    // 应该相等(旋转矩阵的逆 = 转置)
    let diff = (r_inv.m00 - r_t.m00).abs()
             + (r_inv.m01 - r_t.m01).abs()
             + (r_inv.m10 - r_t.m10).abs()
             + (r_inv.m11 - r_t.m11).abs();
    println!("orthogonal: inv vs transpose diff: {}", diff);
    assert!(diff < 1e-5);

    // 测试 3:法线变换矩阵
    let normal_mat = s.normal_matrix().unwrap();
    let n_world = normal_mat.mul_vec(n);
    let n_world_unit = n_world.normalized();
    println!("world normal (normalized): {:?}", n_world_unit);
    // 预期 (1, 0, 0)——垂直性保持
}
```

**关键点**:
- `transpose` — 简单的行列交换,9 个赋值
- `determinant` — 3×3 行列式,展开公式
- `inverse` — 用伴随矩阵 + 行列式,返回 `Option`(det=0 时不可逆)
- `normal_matrix` — `(M⁻¹)ᵀ`——法线变换专用

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

逆矩阵的应用:

1. **法线变换**(今天主题):非均匀缩放时必须用 `(M⁻¹)ᵀ`
2. **View matrix**:相机变换的逆。`view = inverse(camera_world)`
3. **反投影 (unproject)**:屏幕坐标 → 世界坐标,需要 projection 的逆。Day 110 详细讲。
4. **光线追踪**:射线变换到模型空间,需要 Model 的逆。

**坑**:每个 mesh 的 Model 矩阵不同,所以每个 mesh 都要算 `(Model⁻¹)ᵀ`。但 CPU 可以预算一次,shader 直接用 uniform 传入。

**坑**:浮点精度。多次矩阵乘法累积误差,法线变换矩阵可能不再是单位长度。shader 里要重新归一化。

### 3.2 · 🎨 图形学视角

数学延伸:

1. **正交矩阵 (orthogonal)**:`Mᵀ·M = I`,逆 = 转置。旋转、镜像、置换。
2. **对称矩阵 (symmetric)**:`Mᵀ = M`。惯量张量、协方差矩阵。
3. **可逆 (invertible)**:`det ≠ 0`。否则「丢信息」,无法还原。
4. **奇异值分解 (SVD)**:任意矩阵 = 正交 × 对角 × 正交。图形学不常用,但有理论意义。

GPU shader 里:
```glsl
mat3 normal_matrix = transpose(inverse(mat3(model)));
vec3 world_normal = normalize(normal_matrix * local_normal);
```

GLSL 有内置 `inverse()` 和 `transpose()`,但**性能考虑**:CPU 预算更稳。

### 3.3 · 🐧 Linux 系统编程视角

逆矩阵本身是数学,但性能上:

1. **3×3 行列式** = 9 次乘 + 5 次加减。CPU 1 cycle 内。
2. **3×3 逆矩阵** = 1 次行列式 + 9 次余子式(每个 4 次乘 + 2 加减) + 9 次乘 = ~50 ops,几个 ns
3. **SIMD**:`_mm_mul_ps` + `_mm_sub_ps` 加速,Casey Day 112+ 大量用

### 3.5 · 🐧 Linux 系统编程视角(内核空间 / 硬件加速)

Linux 系统里"碰撞 / 相交检测"的核心思想在多处出现,理解这些能让你看 Casey 的 2D / 3D collision 算法在更广的语境里。

**内核的 page fault 处理**。虚拟内存到物理内存的映射,本质是"地址空间相交检测"。CPU 访问虚拟地址,MMU 查 page table,如果地址不在已映射范围内 → page fault。内核接 fault,检查(1)地址合法吗(进程的 VMA 区间)、(2)权限对吗(read / write / exec)、(3)page 在物理内存还是 swap。这套检查就是"区间相交 + 属性匹配",和 Casey 在 day 050 的 Minkowski collision 在抽象上一致——"用几何空间判断两个东西是否接触"。

```bash
# 看你进程的 VMA(虚拟内存区域)
cat /proc/$$/maps
# 输出形如:
# 56001234-56005678 r-xp ...  /usr/bin/bash
# 7f1234560000-7f1234780000 r--p ... /usr/lib/libc.so.6

# 触发 page fault(故意访问非法地址)
python3 -c "import ctypes; ctypes.cast(0xdeadbeef, ctypes.POINTER(ctypes.c_int))[0] = 0"
# 输出:Segmentation fault (core dumped)
```

**epoll / poll / select** 是 IO 多路复用,本质是"时间区间相交"。你给内核 N 个 fd,内核检查"哪个 fd 当前可读 / 可写"。这是 N 路并行等待,内核用红黑树 + ready list 高效管理。和 collision detection 的 broad phase 类似——快速排除不可能相交的对,只在 narrow phase 详细检查。

**文件锁(flock / fcntl)**。Linux 文件锁检测"两个进程是否同时持有冲突锁"——这是"锁区间相交"。flock 用 inode-level 锁,fcntl 用 byte-range 锁(`fcntl(F_SETLK, F_WRLCK, {100..200})` 锁字节 100-200)。内核维护锁列表,新锁请求时遍历检查冲突——这就是 interval intersection 检测。

**网络栈的 TCP / IP header 校验**。每个 TCP/IP 包带 checksum,内核收到包校验——本质是"数据完整性检测"。和 collision detection 不直接相关,但**思想相同**——"用一个数学函数快速判断数据是否合法"。

**cgroup 的资源限制**。`cpu.max = 50000 100000` 表示 cgroup 在每 100ms 周期内最多用 50ms CPU。内核定期检查"当前周期已用多少 CPU",超了 throttle。这是"时间区间累积 + 阈值检测",和 Casey 的"span duration + frame budget"逻辑相同。

**netfilter / iptables** 用 BPF 风格的规则匹配,检查每个网络包。"规则匹配"本质是"包属性 vs 规则区间"——"src IP in 192.168.0.0/16 && dst port == 22"是区间检测。BPF (Berkeley Packet Filter) 让用户写过滤器,内核执行——这种"用户定义函数 + 内核执行"模式是 eBPF 的基础。

**kernel scheduling**。Linux CFS(Completely Fair Scheduler)维护红黑树 of runnable tasks,按 vruntime 排序。每个 tick(1ms / 4ms),CFS 检查当前 task 是否该让出 CPU——"时间片用完了吗"。这是"时间累积 + 阈值切换",和游戏 update 循环的 frame budget 检查同构。

### 3.6 · 🦀 Rust 生态视角

Rust 在游戏物理 / 碰撞领域有几个值得关注的 crate 和模式。

**`rapier`** 是 Rust 的 2D / 3D 物理引擎,由 Dimforge 开发。Rapier 提供 rigid body dynamics、collision detection、joints、rays、sensors——是 Bevy 生态的物理默认选项。Rapier 用 ECS 风格 API,内部用 SOA(struct of arrays)布局,cache 友好。

```rust
use rapier3d::prelude::*;

let mut rigid_body_set = RigidBodySet::new();
let mut collider_set = ColliderSet::new();

let rigid_body = RigidBodyBuilder::dynamic().translation(vector![0.0, 5.0, 0.0]).build();
let handle = rigid_body_set.insert(rigid_body);
let collider = ColliderBuilder::ball(0.5).build();
collider_set.insert_with_parent(collider, handle, &mut rigid_body_set);
```

Rapier 内部用 **broad phase(AABB tree)+ narrow phase(GJK / SAT)**,和工业 C++ 引擎(Box2D、Bullet、PhysX)思路一致。Casey HH 手写简化版,Rapier 是 production-grade。

**`parry`** 是 Rapier 抽出来的纯 collision detection 库。parry 提供 shape(ball、cuboid、convex hull、triangle mesh)、ray cast、point projection、pair collision——不涉及 dynamics。如果你只想要碰撞不想物理,parry 是答案。

**`nalgebra`** 是 Rust 的线性代数库,Dimforge 出品(同 Rapier / parry)。`Vector3`、`Matrix4`、`Quaternion`、`Isometry3`——3D 游戏需要的所有数学类型。比 `cgmath` 现代、比 `euclid` 全面。

**Rust ECS 的 collision pattern**。Bevy + Rapier 的典型代码:

```rust
use bevy::prelude::*;
use bevy_rapier3d::prelude::*;

fn setup(mut commands: Commands) {
    commands.spawn((
        RigidBody::Dynamic,
        Collider::ball(1.0),
        Transform::from_translation(Vec3::new(0.0, 5.0, 0.0)),
    ));
}

fn on_collision(
    mut events: EventReader<CollisionEvent>,
    query: Query<&Name>,
) {
    for event in events.read() {
        if let CollisionEvent::Started(e1, e2, _) = event {
            println!("{:?} collided with {:?}", query.get(*e1), query.get(*e2));
        }
    }
}
```

ECS 风格——entity 加 Collider component,系统处理 CollisionEvent。这是 Rust 风格的 collision 设计——数据导向、零成本、类型安全。Casey HH 用 OOP 风格(`struct Player { collider: Collider }`),简单但不够通用。

**Rust 的 zero-cost abstraction** 让 collision detection 可以既高级又快:

```rust
// 高级 API
let hits = colliders.iter()
    .filter(|c| c.aabb_intersects(&target_aabb))
    .filter(|c| c.shape_intersects(&target_shape))
    .collect::<Vec<_>>();

// LLVM 把这优化成手写 C 的等价代码
```

Rust 的 iterator chain + 闭包,被 LLVM inline + vectorize,生成和手写循环一样快的代码。这是 Rust 在性能敏感领域的杀手锏。

**Rust 的 SIMD** 对 collision 特别有用。AABB 测试 8 个浮点比较,用 SIMD 一次处理 4-8 个 AABB。Rust 的 `std::simd`(unstable)或 `wide` crate(stable)提供 SIMD API。Rapier 内部用 SIMD 加速 broad phase。

**Rust 的多线程 collision**。collision detection 是 embarrassingly parallel——N 个 object pair 互相独立。Rust 的 `rayon` 提供 parallel iterator,`colliders.par_iter().filter(...)` 自动并行。Bevy 用 ECS 的 `query.par_iter()` 同样效果。

**Rust 的 `Send + Sync`**。collision data 跨线程共享,要 `Send + Sync`。Rust 编译时检查——如果你的 Collider 包含 `Rc<...>`,编译失败,因为 Rc 不是 Send。这种类型系统保证的多线程安全,是 Rust 比 C++ 优势的地方。

**Rust 的 `smallvec`** 在 collision 里有用。pair list 经常是空的或只有 1-2 个 pair,用 `SmallVec<[Pair; 4]>` 避免堆分配,大部分情况栈上。

**Rust 的 `ahash`** 在 spatial hash 里替代 `DefaultHasher`——3-5 倍速度。Casey HH 的 hash chunk storage(Phase 2)用 `DefaultHasher`,Rust 版应该用 `ahash` 或 `fxhash`。

## 4 · 认知地图

### 4.1 上级

- **线性代数 (linear algebra)** — 矩阵 / 向量 / 线性变换的数学分支
- **群论 (group theory)** — 「可逆元素」构成群的代数结构
- **几何变换 (geometric transformation)** — 平移、旋转、缩放、错切的数学表达

### 4.2 同级

| 运算 | 公式 | 性质 |
|---|---|---|
| 转置 Mᵀ | 行列交换 | (M·N)ᵀ = Nᵀ·Mᵀ |
| 逆 M⁻¹ | M·M⁻¹ = I | (M·N)⁻¹ = N⁻¹·M⁻¹ |
| 行列式 det(M) | 标量 | det(M·N) = det(M)·det(N) |
| 伴随 adj(M) | 余子式转置 | M · adj(M) = det(M)·I |

### 4.3 下级

- **余子式 (cofactor)** — 划掉一行一列后的子矩阵行列式
- **代数余子式 (signed cofactor)** — 余子式 × (-1)^(i+j)
- **正交矩阵** — Mᵀ·M = I
- **法线变换** — `(M⁻¹)ᵀ`

## 5 · 对照与变奏

### 2×2 vs 3×3 vs 4×4 矩阵逆

- **2×2**:`det = ad - bc`,`inv = 1/det · [[d,-b],[-c,a]]`。4 次乘。
- **3×3**:余子式法,~50 ops
- **4×4**:高斯消元法,~200 ops。图形学最常用。

4×4 矩阵逆通常用高斯-若尔当消元,而不是伴随矩阵法(伴随矩阵 16 个余子式,每个 9 次乘,太多)。

### 旋转矩阵的特殊优化

旋转矩阵 `R(θ)` 是正交的:`R⁻¹ = Rᵀ = R(-θ)`。所以**法线变换可以直接用 R**(无需算逆的转置)。

但**只要加一个非均匀缩放**,就要重新算 `(M⁻¹)ᵀ`。Casey HH 因为大量用缩放(角色装备大小不同),所以法线变换必须用 `(M⁻¹)ᵀ`。

### 历史

矩阵逆的算法有 200+ 年历史:
- 1700s Gauss-Jordan 消元
- 1800s Laplace 行列式展开
- 1900s 余子式法
- 2000s SIMD 优化

游戏开发的 4×4 矩阵逆通常用定制算法(利用稀疏性 / 单位子矩阵),比通用算法快 5-10 倍。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么旋转矩阵的逆等于转置?给出几何解释。

**参考解答**:旋转矩阵 R(θ) 的列向量是「旋转后的基向量」:
- 第 0 列:`(cos θ, sin θ, 0)` — 旋转后的 x 轴
- 第 1 列:`(-sin θ, cos θ, 0)` — 旋转后的 y 轴
- 第 2 列:`(0, 0, 1)` — 旋转后的 z 轴(不变)

这些列向量**单位长度**且**互相垂直**——所以 R 是正交矩阵。正交矩阵的性质:`Rᵀ · R = I`(因为 Rᵀ 的行向量 = R 的列向量,互相垂直的点积 = 0,自己点积 = 1)。

所以 `Rᵀ = R⁻¹`。**几何意义**:旋转的逆就是反向旋转——转 +θ 然后转 -θ 等于不转。`R(-θ)` 在矩阵形式上等于 `R(θ)ᵀ`。

### Lv2 · 动手实践

**题**:实现 4×4 矩阵的逆(用高斯-若尔当消元)。测试:对随机生成的可逆矩阵,M·M⁻¹ ≈ I。

**参考解答关键片段**(高斯-若尔当):

```rust
fn mat4_inverse(m: [[f32; 4]; 4]) -> Option<[[f32; 4]; 4]> {
    // 创建增广矩阵 [m | I]
    let mut aug = [[0.0f32; 8]; 4];
    for i in 0..4 {
        for j in 0..4 { aug[i][j] = m[i][j]; }
        aug[i][i + 4] = 1.0;
    }

    // 高斯消元
    for col in 0..4 {
        // 找主元
        let mut pivot = col;
        for r in col+1..4 {
            if aug[r][col].abs() > aug[pivot][col].abs() { pivot = r; }
        }
        if aug[pivot][col].abs() < 1e-9 { return None; }
        // 交换
        if pivot != col { aug.swap(col, pivot); }
        // 归一化主元行
        let p = aug[col][col];
        for j in 0..8 { aug[col][j] /= p; }
        // 消元其他行
        for r in 0..4 {
            if r != col {
                let factor = aug[r][col];
                for j in 0..8 { aug[r][j] -= factor * aug[col][j]; }
            }
        }
    }

    // 提取右半作为逆
    let mut inv = [[0.0f32; 4]; 4];
    for i in 0..4 {
        for j in 0..4 { inv[i][j] = aug[i][j + 4]; }
    }
    Some(inv)
}
```

## 8 · Rust / Arch 落地代码

### 完整可跑示例

```rust
// [Mat3 / Vec3 同 §2]

fn main() {
    // 演示:非均匀缩放下的法线变换
    let scale = Mat3::from_scale(2.0, 1.0, 1.0);  // x 方向拉 2 倍

    // 错误做法:直接用 scale 变换法线
    let original_normal = Vec3::new(1.0, 1.0, 0.0).normalized();  // ≈ (0.707, 0.707, 0)
    let wrong_normal = scale.mul_vec(original_normal);  // (1.414, 0.707, 0)
    println!("wrong (use M directly): {:?}, length={}", wrong_normal, wrong_normal.length());

    // 正确做法:用 (M⁻¹)ᵀ
    let normal_mat = scale.normal_matrix().unwrap();
    let right_normal = normal_mat.mul_vec(original_normal);
    let right_normal_unit = right_normal.normalized();
    println!("right (use (M⁻¹)ᵀ): {:?}, normalized: {:?}", right_normal, right_normal_unit);

    // 验证:正确变换后的法线应该垂直于变换后的表面
    // 假设原切线 (1, 0, 0),变换后 (2, 0, 0)
    let tangent = Vec3::new(1.0, 0.0, 0.0);
    let tangent_world = scale.mul_vec(tangent);
    let dot_with_tangent = right_normal_unit.dot(tangent_world);
    println!("dot(normal, transformed tangent) = {}", dot_with_tangent);
    // 应该接近 0(垂直)
    assert!(dot_with_tangent.abs() < 1e-5);
}
```

### Troubleshooting

- **逆矩阵返回 None** — det = 0,矩阵不可逆。检查是否有零缩放或重复行
- **法线变换后方向不对** — 检查 transpose 和 inverse 顺序。正确是 `(M⁻¹)ᵀ`,不是 `(Mᵀ)⁻¹`(虽然两者代数相等,但实现上可能不同)
- **数值不稳定** — det 很小但非零,逆矩阵元素很大。加 epsilon 检查
