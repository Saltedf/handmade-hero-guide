
# Day 085 · 暂时地面缓冲

> 你的地面是永久的——画完就锁死。但游戏里有**临时效果**:爆炸的焦痕、魔法的光圈、流过的水。这些效果不能永久改地面,也不能每帧重新画。Casey 今天加一层「**暂时地面缓冲**」——临时效果叠在永久地面之上,有过期时间。这是粒子系统、特效、动态环境的核心架构。

## 0 · 为什么要有这一天

你的玩家扔了一颗炸弹。爆炸!

- **永久修改地面**(挖个坑):炸弹每次都改地面,玩家走出区域回来发现地面变焦——不对,炸弹只应该一次性。
- **每帧重新画爆炸效果**:60 帧的爆炸动画 × 几百像素 = 浪费。
- **画一个临时焦痕 + 过期删除**:最佳方案。

Casey 的解法:**分层渲染**。
- **底层**:永久地面(草地)。
- **特效层**:暂时效果(爆炸痕迹、弹孔、魔法阵),有过期时间。

每个特效是一个**transient buffer**(暂时缓冲),独立维护生命周期。渲染时按 z-order 叠加。

这种「分层 + 过期」的模式在游戏开发里到处用:
- **粒子系统**:每个粒子是个 transient。
- **战斗特效**:剑光、火花。
- **环境变化**:雪地脚印、湿地水痕。
- **AI 视觉提示**:玩家被发现的感叹号。

心理锚点:看完今天,你能向队友解释「为什么我们的爆炸痕迹自动消失」。你能用 Rust 写一个简单的 transient 系统。你能用 30 秒说清「永久层 + 暂时层」的渲染架构。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. **定义 TransientEffect**:有 bitmap、位置、过期时间。
2. **Vec<TransientEffect>**:全部活跃特效。
3. **每帧更新**:更新剩余时间,过期的删除。
4. **渲染**:先画永久地面,再画所有 transient(按 z 排序)。
5. **触发接口**:`spawn_explosion(pos)` 创建一个爆炸特效。

Casey 强调「**生命周期管理**」——每个 transient 自己负责自己的死亡,主循环只查询 active。

## 2 · 心智模型

### 费曼类比:舞台道具

想象一个舞台剧。背景是大画布(永久),演员在前面表演。某些场景里有「道具」——画在地上的血迹、烟雾、火焰。

道具的特点:
- **临时**:这一场戏结束就撤掉。
- **可重复**:每场戏可以有多个相同道具(多个血迹)。
- **独立**:每个道具有自己的位置和状态。

游戏里的 transient effect 就是舞台道具——**临时、独立、自管理**。

### 严谨原理

#### 2.1 数据结构

```rust
struct TransientEffect {
    bitmap: Bitmap,
    pos: Vec2,           // 世界坐标
    spawn_time: f32,     // 生成时间(秒)
    duration: f32,       // 持续时间(秒)
}

impl TransientEffect {
    fn is_expired(&self, current_time: f32) -> bool {
        current_time > self.spawn_time + self.duration
    }

    fn alpha(&self, current_time: f32) -> f32 {
        // 渐隐效果:接近过期时 alpha 减小
        let elapsed = current_time - self.spawn_time;
        let t = (elapsed / self.duration).clamp(0.0, 1.0);
        // 用 smoothstep 让渐隐自然
        1.0 - t * t * (3.0 - 2.0 * t)
    }
}
```

#### 2.2 EffectManager

```rust
struct EffectManager {
    effects: Vec<TransientEffect>,
}

impl EffectManager {
    fn new() -> Self { Self { effects: Vec::new() } }

    fn spawn(&mut self, bitmap: Bitmap, pos: Vec2, duration: f32, current_time: f32) {
        self.effects.push(TransientEffect {
            bitmap,
            pos,
            spawn_time: current_time,
            duration,
        });
    }

    fn update(&mut self, current_time: f32) {
        // 删除过期
        self.effects.retain(|e| !e.is_expired(current_time));
    }

    fn render(&self, framebuffer: &mut Framebuffer, current_time: f32) {
        for e in &self.effects {
            let alpha = e.alpha(current_time);
            // 用 alpha 渐隐 blit
            blit_with_alpha(framebuffer, e.pos, &e.bitmap, alpha);
        }
    }
}
```

`retain` 是 Rust Vec 的方法——保留满足条件的元素,删除其他。

#### 2.3 渐隐的数学

`alpha()` 函数返回当前透明度(0-1):

```rust
fn alpha(&self, current_time: f32) -> f32 {
    let elapsed = current_time - self.spawn_time;
    let t = (elapsed / self.duration).clamp(0.0, 1.0);
    // Smoothstep: 1 → 0,平滑过渡
    1.0 - smoothstep(0.0, 1.0, t)
}

fn smoothstep(edge0: f32, edge1: f32, x: f32) -> f32 {
    let t = ((x - edge0) / (edge1 - edge0)).clamp(0.0, 1.0);
    t * t * (3.0 - 2.0 * t)
}
```

**为什么用 smoothstep 而不是线性?** Smoothstep 在两端导数为 0,渐入渐出自然。线性过渡在开始和结束有「跳变」,不自然。

#### 2.4 触发特效

```rust
fn explode(effects: &mut EffectManager, pos: Vec2, current_time: f32) {
    // 生成爆炸特效(简化:用一个圆形 bitmap)
    let explosion_bmp = make_explosion_bitmap();
    effects.spawn(explosion_bmp, pos, 1.0, current_time);  // 1 秒后过期

    // 可选:生成焦痕(永久或长时间)
    let scorch_bmp = make_scorch_bitmap();
    effects.spawn(scorch_bmp, pos, 30.0, current_time);  // 30 秒后过期
}
```

#### 2.5 分层渲染

```rust
fn render_frame(world: &World, ground_buf: &GroundBuffer, effects: &EffectManager,
                framebuffer: &mut Framebuffer, current_time: f32) {
    // 1. 永久地面
    framebuffer.blit_from(ground_buf);

    // 2. 暂时效果
    effects.render(framebuffer, current_time);

    // 3. 玩家、怪等
    for e in &world.entities {
        render_entity(framebuffer, e);
    }

    // 4. UI
    render_ui(framebuffer);
}
```

每层独立维护,互不干扰。

#### 2.6 性能考量

每个 transient 每帧渲染一次。100 个 transient × 60 帧 = 6000 次 blit/秒——快。

但过期检查是 O(N)。如果有 10000 个 transient,每帧 retain 跑 10000 次。优化:**用堆(优先队列)按过期时间排序**,只查堆顶。

```rust
use std::collections::BinaryHeap;
use std::cmp::Reverse;

struct EffectManager {
    // 用 BinaryHeap 按 spawn_time + duration 排序
    effects: BinaryHeap<Reverse<(f32, TransientEffect)>>,
}
```

Casey HH 简化用 Vec + retain,大多数游戏 transient 数量小(< 100),够用。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

特效系统是游戏开发的标配:

#### 粒子系统

每个粒子是一个 micro-transient:

```rust
struct Particle {
    pos: Vec2,
    vel: Vec2,
    spawn_time: f32,
    duration: f32,
    color: Color,
}
```

爆炸 = 100 个粒子,各自飞散 + 衰减。Day 085 的 transient 是粒子系统的「大颗粒」版本。

#### 战斗特效

- **剑光**:攻击时生成的弧形特效,0.2 秒消失。
- **击中火花**:攻击命中时,0.3 秒消失。
- **闪电**:连接两个 entity 的电光,0.5 秒消失。

都是 transient。

#### 环境交互

- **脚印**:玩家在雪地走,留下脚印,5 分钟消失(或永久)。
- **弹孔**:枪击墙,墙上留弹孔。
- **血迹**:怪死亡,地上留血迹。

可以是 transient(会消失)或永久(写入地面 buffer)。

### 3.2 · 🎨 图形学视角

特效渲染的几个层次:

#### CPU 软渲染(今天)

每个 transient 是个 bitmap,blit 到屏幕。简单但慢。

#### GPU shader(后期)

每个 transient 是个 textured quad,fragment shader 算最终颜色。支持:
- **发光**(bloom):高亮像素扩散到周围
- **形变**:shader 改变 UV 让特效拉伸
- **混合模式**:additive(发光)/ multiply(阴影)

#### Compute shader(高级)

GPU 上模拟粒子,几百万粒子并行。Casey HH 不用,但工业级用(Nvidia Flex、AMD Particle)。

#### 后处理

特效渲染到 offscreen buffer,再做后处理(模糊、bloom),最后贴到屏幕。这是现代特效的标准流程。

### 3.3 · 🐧 Linux 系统编程视角

### 3.4 · 🦀 Rust 生态视角

#### Rust 的 Vec::retain

```rust
let mut v = vec![1, 2, 3, 4, 5];
v.retain(|&x| x > 2);
// v 现在是 [3, 4, 5]
```

`retain` 删除不满足条件的元素。比 `iter().filter().collect()` 高效(原地修改)。

#### Rust 的 BinaryHeap

```rust
use std::collections::BinaryHeap;
use std::cmp::Reverse;

let mut heap: BinaryHeap<Reverse<(f32, &str)>> = BinaryHeap::new();
heap.push(Reverse((3.0, "third")));
heap.push(Reverse((1.0, "first")));
heap.push(Reverse((2.0, "second")));

// pop 返回最小的(min-heap,因为用 Reverse)
assert_eq!(heap.pop().unwrap().0, (1.0, "first"));
```

Rust 的 BinaryHeap 默认 max-heap。用 `Reverse` 包装得到 min-heap。

#### Rust 的生命周期:spawn-and-forget

```rust
impl EffectManager {
    fn spawn(&mut self, ...) {
        self.effects.push(...);
        // 不返回引用,避免借用问题
    }

    fn update_and_render(&mut self, framebuffer: &mut Framebuffer) {
        // 同时修改和渲染,可以——都借用的 self
        self.effects.retain(...);
        for e in &self.effects {
            // 借用 self.effects.iter(),framebuffer 是另一个对象
            framebuffer.blit(e.bitmap);
        }
    }
}
```

Rust 的借用规则让你写「自管理」结构时不会出 dangling reference。


### 3.5 · 🐧 Linux 系统编程视角(内核空间 / 硬件加速)

Linux 系统里"碰撞 / 相交检测"的核心思想在多处出现,理解这些能让你看 Casey 的 2D / 3D collision 算法在更广的语境里。

**内核的 page fault 处理**。虚拟内存到物理内存的映射,本质是"地址空间相交检测"。CPU 访问虚拟地址,MMU 查 page table,如果地址不在已映射范围内 → page fault。内核接 fault,检查(1)地址合法吗(进程的 VMA 区间)、(2)权限对吗(read / write / exec)、(3)page 在物理内存还是 swap。这套检查就是"区间相交 + 属性匹配",和 Casey 在 day 050 的 Minkowski collision 在抽象上一致——"用几何空间判断两个东西是否接触"。

```bash
# 看你进程的 VMA(虚拟内存区域)
cat /proc/$$/maps
# 输出形如:
# 56001234-56005678 r-xp ...  /usr/bin/bash
# 7f1234560000-7f1234780000 r--p ... /usr/lib/libc.so.6

# 触发 page fault(故意访问非法地址)
python3 -c "import ctypes; ctypes.cast(0xdeadbeef, ctypes.POINTER(ctypes.c_int))[0] = 0"
# 输出:Segmentation fault (core dumped)
```

**epoll / poll / select** 是 IO 多路复用,本质是"时间区间相交"。你给内核 N 个 fd,内核检查"哪个 fd 当前可读 / 可写"。这是 N 路并行等待,内核用红黑树 + ready list 高效管理。和 collision detection 的 broad phase 类似——快速排除不可能相交的对,只在 narrow phase 详细检查。

**文件锁(flock / fcntl)**。Linux 文件锁检测"两个进程是否同时持有冲突锁"——这是"锁区间相交"。flock 用 inode-level 锁,fcntl 用 byte-range 锁(`fcntl(F_SETLK, F_WRLCK, {100..200})` 锁字节 100-200)。内核维护锁列表,新锁请求时遍历检查冲突——这就是 interval intersection 检测。

**网络栈的 TCP / IP header 校验**。每个 TCP/IP 包带 checksum,内核收到包校验——本质是"数据完整性检测"。和 collision detection 不直接相关,但**思想相同**——"用一个数学函数快速判断数据是否合法"。

**cgroup 的资源限制**。`cpu.max = 50000 100000` 表示 cgroup 在每 100ms 周期内最多用 50ms CPU。内核定期检查"当前周期已用多少 CPU",超了 throttle。这是"时间区间累积 + 阈值检测",和 Casey 的"span duration + frame budget"逻辑相同。

**netfilter / iptables** 用 BPF 风格的规则匹配,检查每个网络包。"规则匹配"本质是"包属性 vs 规则区间"——"src IP in 192.168.0.0/16 && dst port == 22"是区间检测。BPF (Berkeley Packet Filter) 让用户写过滤器,内核执行——这种"用户定义函数 + 内核执行"模式是 eBPF 的基础。

**kernel scheduling**。Linux CFS(Completely Fair Scheduler)维护红黑树 of runnable tasks,按 vruntime 排序。每个 tick(1ms / 4ms),CFS 检查当前 task 是否该让出 CPU——"时间片用完了吗"。这是"时间累积 + 阈值切换",和游戏 update 循环的 frame budget 检查同构。

### 3.6 · 🦀 Rust 生态视角

Rust 在游戏物理 / 碰撞领域有几个值得关注的 crate 和模式。

**`rapier`** 是 Rust 的 2D / 3D 物理引擎,由 Dimforge 开发。Rapier 提供 rigid body dynamics、collision detection、joints、rays、sensors——是 Bevy 生态的物理默认选项。Rapier 用 ECS 风格 API,内部用 SOA(struct of arrays)布局,cache 友好。

```rust
use rapier3d::prelude::*;

let mut rigid_body_set = RigidBodySet::new();
let mut collider_set = ColliderSet::new();

let rigid_body = RigidBodyBuilder::dynamic().translation(vector![0.0, 5.0, 0.0]).build();
let handle = rigid_body_set.insert(rigid_body);
let collider = ColliderBuilder::ball(0.5).build();
collider_set.insert_with_parent(collider, handle, &mut rigid_body_set);
```

Rapier 内部用 **broad phase(AABB tree)+ narrow phase(GJK / SAT)**,和工业 C++ 引擎(Box2D、Bullet、PhysX)思路一致。Casey HH 手写简化版,Rapier 是 production-grade。

**`parry`** 是 Rapier 抽出来的纯 collision detection 库。parry 提供 shape(ball、cuboid、convex hull、triangle mesh)、ray cast、point projection、pair collision——不涉及 dynamics。如果你只想要碰撞不想物理,parry 是答案。

**`nalgebra`** 是 Rust 的线性代数库,Dimforge 出品(同 Rapier / parry)。`Vector3`、`Matrix4`、`Quaternion`、`Isometry3`——3D 游戏需要的所有数学类型。比 `cgmath` 现代、比 `euclid` 全面。

**Rust ECS 的 collision pattern**。Bevy + Rapier 的典型代码:

```rust
use bevy::prelude::*;
use bevy_rapier3d::prelude::*;

fn setup(mut commands: Commands) {
    commands.spawn((
        RigidBody::Dynamic,
        Collider::ball(1.0),
        Transform::from_translation(Vec3::new(0.0, 5.0, 0.0)),
    ));
}

fn on_collision(
    mut events: EventReader<CollisionEvent>,
    query: Query<&Name>,
) {
    for event in events.read() {
        if let CollisionEvent::Started(e1, e2, _) = event {
            println!("{:?} collided with {:?}", query.get(*e1), query.get(*e2));
        }
    }
}
```

ECS 风格——entity 加 Collider component,系统处理 CollisionEvent。这是 Rust 风格的 collision 设计——数据导向、零成本、类型安全。Casey HH 用 OOP 风格(`struct Player { collider: Collider }`),简单但不够通用。

**Rust 的 zero-cost abstraction** 让 collision detection 可以既高级又快:

```rust
// 高级 API
let hits = colliders.iter()
    .filter(|c| c.aabb_intersects(&target_aabb))
    .filter(|c| c.shape_intersects(&target_shape))
    .collect::<Vec<_>>();

// LLVM 把这优化成手写 C 的等价代码
```

Rust 的 iterator chain + 闭包,被 LLVM inline + vectorize,生成和手写循环一样快的代码。这是 Rust 在性能敏感领域的杀手锏。

**Rust 的 SIMD** 对 collision 特别有用。AABB 测试 8 个浮点比较,用 SIMD 一次处理 4-8 个 AABB。Rust 的 `std::simd`(unstable)或 `wide` crate(stable)提供 SIMD API。Rapier 内部用 SIMD 加速 broad phase。

**Rust 的多线程 collision**。collision detection 是 embarrassingly parallel——N 个 object pair 互相独立。Rust 的 `rayon` 提供 parallel iterator,`colliders.par_iter().filter(...)` 自动并行。Bevy 用 ECS 的 `query.par_iter()` 同样效果。

**Rust 的 `Send + Sync`**。collision data 跨线程共享,要 `Send + Sync`。Rust 编译时检查——如果你的 Collider 包含 `Rc<...>`,编译失败,因为 Rc 不是 Send。这种类型系统保证的多线程安全,是 Rust 比 C++ 优势的地方。

**Rust 的 `smallvec`** 在 collision 里有用。pair list 经常是空的或只有 1-2 个 pair,用 `SmallVec<[Pair; 4]>` 避免堆分配,大部分情况栈上。

**Rust 的 `ahash`** 在 spatial hash 里替代 `DefaultHasher`——3-5 倍速度。Casey HH 的 hash chunk storage(Phase 2)用 `DefaultHasher`,Rust 版应该用 `ahash` 或 `fxhash`。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么用 transient buffer 而不是永久修改地面?

**参考解答**:

理由 1:**可撤销**。永久修改不可逆,如果想撤销(比如重启关卡),需要重画整个地面。Transient 自然消失,无需撤销。

理由 2:**性能**。永久修改要写回 tile cache(失效 + 重新合成)。Transient 只是叠加层,不影响 cache。

理由 3:**多 transient 叠加**。一个位置可以同时有焦痕 + 弹孔 + 火焰——三层 transient 各自管理。永久修改只能一层。

理由 4:**生命周期控制**。每个 transient 有独立 duration——5 秒消失的火焰 vs 30 秒的焦痕 vs 永久的脚印。永久修改没有这种灵活性。

#[derive(Clone)]
struct Bitmap { width: usize, height: usize, pixels: Vec<u32> }

#[derive(Clone)]
struct TransientEffect {
    name: &'static str,
    bitmap: Bitmap,
    spawn_time: f32,
    duration: f32,
}

impl TransientEffect {
    fn is_expired(&self, current_time: f32) -> bool {
        current_time > self.spawn_time + self.duration
    }

    fn remaining(&self, current_time: f32) -> f32 {
        (self.spawn_time + self.duration - current_time).max(0.0)
    }
}

struct EffectManager {
    effects: Vec<TransientEffect>,
}

impl EffectManager {
    fn new() -> Self { Self { effects: Vec::new() } }

    fn spawn(&mut self, name: &'static str, duration: f32, current_time: f32) {
        self.effects.push(TransientEffect {
            name,
            bitmap: Bitmap { width: 32, height: 32, pixels: vec![0xFFFFFFFF; 32*32] },
            spawn_time: current_time,
            duration,
        });
    }

    fn update(&mut self, current_time: f32) {
        self.effects.retain(|e| !e.is_expired(current_time));
    }

    fn count(&self) -> usize { self.effects.len() }

    fn list(&self, current_time: f32) {
        for e in &self.effects {
            let r = e.remaining(current_time);
            if e.duration == f32::INFINITY {
                println!("  {} (永久)", e.name);
            } else {
                println!("  {} (剩余 {:.1}s)", e.name, r);
            }
        }
    }
}

fn main() {
    let mut mgr = EffectManager::new();
    let mut current_time = 0.0f32;
    let dt = 1.0;  // 1 秒一帧

    // t=0 触发三个特效
    println!("=== t=0 触发三个特效 ===");
    mgr.spawn("爆炸", 1.0, current_time);
    mgr.spawn("焦痕", 30.0, current_time);
    mgr.spawn("弹孔", f32::INFINITY, current_time);
    mgr.list(current_time);

    // 每秒打印一次
    for t in 1..=35 {
        current_time = t as f32;
        mgr.update(current_time);
        if t == 1 || t == 5 || t == 15 || t == 30 || t == 31 {
            println!("\n=== t={} === 活跃: {}", t, mgr.count());
            mgr.list(current_time);
        }
    }
}

## 8 · Rust / Arch 落地代码

```rust
#[derive(Clone)]
struct Bitmap {
    width: usize,
    height: usize,
    pixels: Vec<u32>,
}

#[derive(Clone)]
struct TransientEffect {
    name: &'static str,
    bitmap: Bitmap,
    pos_x: f32,
    pos_y: f32,
    spawn_time: f32,
    duration: f32,
}

impl TransientEffect {
    fn is_expired(&self, current_time: f32) -> bool {
        current_time > self.spawn_time + self.duration
    }

    fn alpha(&self, current_time: f32) -> f32 {
        let elapsed = current_time - self.spawn_time;
        let t = (elapsed / self.duration).clamp(0.0, 1.0);
        // Smoothstep fade-out
        1.0 - t * t * (3.0 - 2.0 * t)
    }
}

struct EffectManager {
    effects: Vec<TransientEffect>,
    total_ever_spawned: u64,
}

impl EffectManager {
    fn new() -> Self {
        Self { effects: Vec::new(), total_ever_spawned: 0 }
    }

    fn spawn(&mut self, name: &'static str, duration: f32, current_time: f32) {
        self.effects.push(TransientEffect {
            name,
            bitmap: Bitmap { width: 32, height: 32, pixels: vec![0xFFFFFFFF; 32*32] },
            pos_x: 0.0, pos_y: 0.0,
            spawn_time: current_time,
            duration,
        });
        self.total_ever_spawned += 1;
        println!("[t={:.1}] spawn {} (duration={:.1}s)", current_time, name, duration);
    }

    fn update(&mut self, current_time: f32) {
        let before = self.effects.len();
        self.effects.retain(|e| !e.is_expired(current_time));
        let removed = before - self.effects.len();
        if removed > 0 {
            println!("[t={:.1}] {} 个特效过期", current_time, removed);
        }
    }
}

fn main() {
    let mut mgr = EffectManager::new();
    let mut t = 0.0f32;
    let dt = 0.1;

    // 模拟:在 t=0 触发爆炸,t=0.5 触发焦痕,t=1.5 触发另一个爆炸
    let events = [
        (0.0, "爆炸", 0.8),
        (0.0, "闪光", 0.3),
        (0.5, "焦痕", 5.0),
        (1.5, "爆炸2", 0.8),
        (2.0, "弹孔", f32::INFINITY),
    ];

    for step in 0..60 {
        t = step as f32 * dt;
        // 触发事件
        for &(et, en, ed) in &events {
            if (et - t).abs() < dt / 2.0 {
                mgr.spawn(en, ed, t);
            }
        }
        mgr.update(t);
    }

    println!("\n=== 最终 ===");
    println!("活跃特效数: {}", mgr.effects.len());
    println!("总共生成过: {}", mgr.total_ever_spawned);
    println!("存活: ");
    for e in &mgr.effects {
        let a = e.alpha(t);
        println!("  {} (alpha={:.2}, 剩余 {:.1}s)",
            e.name, a, e.duration - (t - e.spawn_time));
    }
}
```
