
# Day 087 · 无缝地面纹理

> 你的 chunk 边界对齐了,但**两种地面的视觉接缝仍然可见**——左边草地右边石头,中间一条明显的线。Casey 今天教你消除这条缝:边缘 alpha blend 过渡。这是程序化生成的经典问题(tile 边缘自然过渡),后面 Day 130 的 seamless bilinear tiling 进一步深化。掌握它,你的游戏世界看起来不再像「网格拼接」,而像真实地形。

## 0 · 为什么要有这一天

你的世界由 tile 组成:

- (0, 0):草地
- (1, 0):草地
- (2, 0):石头
- (3, 0):石头

在 tile (1, 0) 和 (2, 0) 之间,**草地突然变成石头**——视觉上是一条明显的线。这条线不是 bug,但**视觉上很丑**——破坏沉浸感。

真实世界的地形是**渐变**的——草地慢慢变成灌木丛,再变成石头。没有「突然」的分界线。

Casey 的解法:**边缘过渡区**。在 tile 边界的 5-10 像素宽度内,做 alpha blend,从 100% 草地渐变到 100% 石头。视觉上是平滑过渡,不是突变。

更高级方案:**Wang tiles**——一种特殊的 tile 集,边缘有多种变体,可以任意拼接不重复。Casey HH Day 087 用 alpha blend,Day 130+ 用 Wang tiles。

心理锚点:看完今天,你的游戏世界看起来「自然」。你能向队友解释「为什么我们的地形没有 tile 边界线」。你能用 Rust 实现 alpha 边缘过渡。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. **定义过渡规则**:tile 边界做 alpha blend。
2. **过渡宽度**:5-10 像素(可调)。
3. **过渡计算**:tile 中心 100% 自身,边缘渐变到邻居。
4. **测试**:两种 tile(草地、石头)相邻,边缘自然过渡。

Casey 强调「**视觉欺骗**」——技术上 tile 是离散的,但视觉上让玩家觉得是连续的。游戏开发的核心技巧。

## 2 · 心智模型

### 费曼类比:画家的笔触

画家画一片草地,边缘画「稀疏的草」——草越来越少,石头越来越多。最终完全变石头。这种「**渐变笔触**」让两种地形自然过渡。

游戏里:
- 离散 tile = 画家的「一格色块」。
- alpha 过渡 = 画家的「渐变笔触」。

Casey HH 用 alpha blend 实现这种笔触——边缘像素同时画两种 tile,按距离权重 blend。

### 严谨原理

#### 2.1 简单边缘 alpha blend

考虑两个 tile 相邻:

```
草地 tile (0, 0)    石头 tile (1, 0)
   [64x64]            [64x64]
   0...63            64...127
```

它们的边界在 x=63/64。在边界附近(假设 5 像素宽),做 alpha blend。

```rust
fn blend_edge(left: &Bitmap, right: &Bitmap, edge_width: usize) -> Bitmap {
    let w = left.width + right.width;
    let h = left.height;
    let mut result = Bitmap::new(w, h);

    // 复制 left 的左部分(不变)
    for y in 0..h {
        for x in 0..(left.width - edge_width) {
            result.set(x, y, left.get(x, y));
        }
    }

    // 边缘过渡区
    for y in 0..h {
        for i in 0..edge_width {
            let x_left = left.width - edge_width + i;
            let x_right = i;
            let alpha = i as f32 / edge_width as f32;  // 0 → 1
            let blended = blend_pixels(
                left.get(x_left, y),
                right.get(x_right, y),
                alpha,  // alpha 越大越偏 right
            );
            result.set(left.width - edge_width + i, y, blended);
        }
    }

    // 复制 right 的右部分(不变)
    for y in 0..h {
        for x in edge_width..right.width {
            result.set(left.width + x, y, right.get(x, y));
        }
    }

    result
}
```

**关键**:`alpha = i / edge_width`,从 0(完全 left)渐变到 1(完全 right)。在边缘的中间(0.5),50% left + 50% right。


#### 2.3 Wang Tiles(高级)

Wang tiles 是数学家 Wang 发明的 tile 系统:

- 每个 tile 有 4 条边(上、下、左、右)。
- 每条边有「颜色」(可以是任意标识)。
- **拼接规则**:相邻 tile 的接触边**必须同色**。

通过精心设计 tile 集(每种边色组合一个 tile),可以实现「**任何拼接都无缝**」。

经典案例:**Corner Wang tiles**——每条边有 2 种颜色(总 2^4 = 16 个 tile,但通过旋转减少到 ~5 个)。

Casey HH Day 130 用 Wang tiles,Day 087 用简单 alpha blend。

#### 2.4 噪点(Noise)过渡

更自然的过渡:用 Perlin noise / Simplex noise 决定每个像素的 alpha。

```rust
fn blend_with_noise(
    pos_x: f32, pos_y: f32,
    left: Pixel, right: Pixel,
) -> Pixel {
    let n = perlin_noise(pos_x * 0.1, pos_y * 0.1);  // [-1, 1]
    let alpha = (n + 1.0) / 2.0;  // [0, 1]
    blend_pixels(left, right, alpha)
}
```

这样过渡边缘**不规则**(像海岸线),更自然。Day 130 详细讲。

#### 2.5 实现完整流程

```rust
struct TileTransition {
    tile_size: usize,
    edge_width: usize,
}

impl TileTransition {
    fn composite(&self, tiles: &[&[Tile]]) -> Bitmap {
        let cols = tiles[0].len();
        let rows = tiles.len();
        let w = cols * self.tile_size;
        let h = rows * self.tile_size;
        let mut result = Bitmap::new(w, h);

        for row in 0..rows {
            for col in 0..cols {
                let tile = &tiles[row][col];
                let left = if col > 0 { Some(&tiles[row][col-1]) } else { None };
                let right = if col + 1 < cols { Some(&tiles[row][col+1]) } else { None };
                let top = if row > 0 { Some(&tiles[row-1][col]) } else { None };
                let bottom = if row + 1 < rows { Some(&tiles[row+1][col]) } else { None };

                for y in 0..self.tile_size {
                    for x in 0..self.tile_size {
                        let mut color = tile.at(x, y);
                        // 边缘 blend
                        if x < self.edge_width {
                            if let Some(l) = left {
                                let alpha = 1.0 - (x as f32 / self.edge_width as f32);
                                color = blend_pixels(l.at(self.tile_size - self.edge_width + x, y), color, alpha);
                            }
                        }
                        // 类似处理 right, top, bottom
                        result.set(col * self.tile_size + x, row * self.tile_size + y, color);
                    }
                }
            }
        }
        result
    }
}
```

这个版本同时处理 4 边。完整版还需要处理 4 个角(双线性)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

无缝地形是 2D / 2.5D 游戏的核心:

- **RTS**(星际、AOE):地形过渡是关键视觉元素。
- **4X**(文明):不同地形(平原、丘陵、山地)边缘过渡。
- **Warcraft 3**:精心设计的 tile 集,无缝拼接。
- **Stardew Valley**:简单的 tile,边缘用 alpha blend。

#### 程序化地形过渡

工业级方案:

1. **Heightmap + material map**:每个像素有高度(决定丘陵)+ 材质 ID(决定草地 / 沙地 / 石头)。
2. **渲染时**:fragment shader 算每个像素的最终颜色,根据 material map blend。
3. **过渡宽度**:可调,通常 2-8 像素。

### 3.2 · 🎨 图形学视角

无缝纹理是图形学的核心话题:

#### Tileable texture

一张纹理可以「无缝重复」——边缘像素接缝处一致。摄影师拍草地时,会专门拍 tileable 版本。

#### Procedural tileable

用 Perlin noise 生成的纹理天然 tileable(因为 noise 本身是周期函数)。

#### Wang tiles

数学化的 tile 系统,保证无缝。游戏开发大量用。

#### Texture bombing

每个 tile 在网格内随机偏移 + 不同贴图,打破重复感。SIGGRAPH 论文经典。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写无缝过渡

```rust
struct TileMap {
    tiles: Vec<Vec<TileType>>,
    tile_size: usize,
    edge_width: usize,
}

impl TileMap {
    fn render(&self, x: usize, y: usize) -> Pixel {
        let tile_x = x / self.tile_size;
        let tile_y = y / self.tile_size;
        let local_x = x % self.tile_size;
        let local_y = y % self.tile_size;

        let center_color = self.tile_color(tile_x, tile_y, local_x, local_y);

        // 边缘 blend
        let mut color = center_color;
        if local_x < self.edge_width && tile_x > 0 {
            let neighbor = self.tile_color(tile_x - 1, tile_y,
                self.tile_size - self.edge_width + local_x, local_y);
            let alpha = 1.0 - local_x as f32 / self.edge_width as f32;
            color = blend(color, neighbor, alpha);
        }
        // 类似处理 right, top, bottom
        color
    }
}
```

### 3.5 · 🐧 Linux 系统编程视角(内核空间 / 硬件加速)

Linux 系统里"碰撞 / 相交检测"的核心思想在多处出现,理解这些能让你看 Casey 的 2D / 3D collision 算法在更广的语境里。

**内核的 page fault 处理**。虚拟内存到物理内存的映射,本质是"地址空间相交检测"。CPU 访问虚拟地址,MMU 查 page table,如果地址不在已映射范围内 → page fault。内核接 fault,检查(1)地址合法吗(进程的 VMA 区间)、(2)权限对吗(read / write / exec)、(3)page 在物理内存还是 swap。这套检查就是"区间相交 + 属性匹配",和 Casey 在 day 050 的 Minkowski collision 在抽象上一致——"用几何空间判断两个东西是否接触"。

```bash
# 看你进程的 VMA(虚拟内存区域)
cat /proc/$$/maps
# 输出形如:
# 56001234-56005678 r-xp ...  /usr/bin/bash
# 7f1234560000-7f1234780000 r--p ... /usr/lib/libc.so.6

# 触发 page fault(故意访问非法地址)
python3 -c "import ctypes; ctypes.cast(0xdeadbeef, ctypes.POINTER(ctypes.c_int))[0] = 0"
# 输出:Segmentation fault (core dumped)
```

**epoll / poll / select** 是 IO 多路复用,本质是"时间区间相交"。你给内核 N 个 fd,内核检查"哪个 fd 当前可读 / 可写"。这是 N 路并行等待,内核用红黑树 + ready list 高效管理。和 collision detection 的 broad phase 类似——快速排除不可能相交的对,只在 narrow phase 详细检查。

**文件锁(flock / fcntl)**。Linux 文件锁检测"两个进程是否同时持有冲突锁"——这是"锁区间相交"。flock 用 inode-level 锁,fcntl 用 byte-range 锁(`fcntl(F_SETLK, F_WRLCK, {100..200})` 锁字节 100-200)。内核维护锁列表,新锁请求时遍历检查冲突——这就是 interval intersection 检测。

**网络栈的 TCP / IP header 校验**。每个 TCP/IP 包带 checksum,内核收到包校验——本质是"数据完整性检测"。和 collision detection 不直接相关,但**思想相同**——"用一个数学函数快速判断数据是否合法"。

**cgroup 的资源限制**。`cpu.max = 50000 100000` 表示 cgroup 在每 100ms 周期内最多用 50ms CPU。内核定期检查"当前周期已用多少 CPU",超了 throttle。这是"时间区间累积 + 阈值检测",和 Casey 的"span duration + frame budget"逻辑相同。

**netfilter / iptables** 用 BPF 风格的规则匹配,检查每个网络包。"规则匹配"本质是"包属性 vs 规则区间"——"src IP in 192.168.0.0/16 && dst port == 22"是区间检测。BPF (Berkeley Packet Filter) 让用户写过滤器,内核执行——这种"用户定义函数 + 内核执行"模式是 eBPF 的基础。

**kernel scheduling**。Linux CFS(Completely Fair Scheduler)维护红黑树 of runnable tasks,按 vruntime 排序。每个 tick(1ms / 4ms),CFS 检查当前 task 是否该让出 CPU——"时间片用完了吗"。这是"时间累积 + 阈值切换",和游戏 update 循环的 frame budget 检查同构。

### 3.6 · 🦀 Rust 生态视角

Rust 在游戏物理 / 碰撞领域有几个值得关注的 crate 和模式。

**`rapier`** 是 Rust 的 2D / 3D 物理引擎,由 Dimforge 开发。Rapier 提供 rigid body dynamics、collision detection、joints、rays、sensors——是 Bevy 生态的物理默认选项。Rapier 用 ECS 风格 API,内部用 SOA(struct of arrays)布局,cache 友好。

```rust
use rapier3d::prelude::*;

let mut rigid_body_set = RigidBodySet::new();
let mut collider_set = ColliderSet::new();

let rigid_body = RigidBodyBuilder::dynamic().translation(vector![0.0, 5.0, 0.0]).build();
let handle = rigid_body_set.insert(rigid_body);
let collider = ColliderBuilder::ball(0.5).build();
collider_set.insert_with_parent(collider, handle, &mut rigid_body_set);
```

Rapier 内部用 **broad phase(AABB tree)+ narrow phase(GJK / SAT)**,和工业 C++ 引擎(Box2D、Bullet、PhysX)思路一致。Casey HH 手写简化版,Rapier 是 production-grade。

**`parry`** 是 Rapier 抽出来的纯 collision detection 库。parry 提供 shape(ball、cuboid、convex hull、triangle mesh)、ray cast、point projection、pair collision——不涉及 dynamics。如果你只想要碰撞不想物理,parry 是答案。

**`nalgebra`** 是 Rust 的线性代数库,Dimforge 出品(同 Rapier / parry)。`Vector3`、`Matrix4`、`Quaternion`、`Isometry3`——3D 游戏需要的所有数学类型。比 `cgmath` 现代、比 `euclid` 全面。

**Rust ECS 的 collision pattern**。Bevy + Rapier 的典型代码:

```rust
use bevy::prelude::*;
use bevy_rapier3d::prelude::*;

fn setup(mut commands: Commands) {
    commands.spawn((
        RigidBody::Dynamic,
        Collider::ball(1.0),
        Transform::from_translation(Vec3::new(0.0, 5.0, 0.0)),
    ));
}

fn on_collision(
    mut events: EventReader<CollisionEvent>,
    query: Query<&Name>,
) {
    for event in events.read() {
        if let CollisionEvent::Started(e1, e2, _) = event {
            println!("{:?} collided with {:?}", query.get(*e1), query.get(*e2));
        }
    }
}
```

ECS 风格——entity 加 Collider component,系统处理 CollisionEvent。这是 Rust 风格的 collision 设计——数据导向、零成本、类型安全。Casey HH 用 OOP 风格(`struct Player { collider: Collider }`),简单但不够通用。

**Rust 的 zero-cost abstraction** 让 collision detection 可以既高级又快:

```rust
// 高级 API
let hits = colliders.iter()
    .filter(|c| c.aabb_intersects(&target_aabb))
    .filter(|c| c.shape_intersects(&target_shape))
    .collect::<Vec<_>>();

// LLVM 把这优化成手写 C 的等价代码
```

Rust 的 iterator chain + 闭包,被 LLVM inline + vectorize,生成和手写循环一样快的代码。这是 Rust 在性能敏感领域的杀手锏。

**Rust 的 SIMD** 对 collision 特别有用。AABB 测试 8 个浮点比较,用 SIMD 一次处理 4-8 个 AABB。Rust 的 `std::simd`(unstable)或 `wide` crate(stable)提供 SIMD API。Rapier 内部用 SIMD 加速 broad phase。

**Rust 的多线程 collision**。collision detection 是 embarrassingly parallel——N 个 object pair 互相独立。Rust 的 `rayon` 提供 parallel iterator,`colliders.par_iter().filter(...)` 自动并行。Bevy 用 ECS 的 `query.par_iter()` 同样效果。

**Rust 的 `Send + Sync`**。collision data 跨线程共享,要 `Send + Sync`。Rust 编译时检查——如果你的 Collider 包含 `Rc<...>`,编译失败,因为 Rc 不是 Send。这种类型系统保证的多线程安全,是 Rust 比 C++ 优势的地方。

**Rust 的 `smallvec`** 在 collision 里有用。pair list 经常是空的或只有 1-2 个 pair,用 `SmallVec<[Pair; 4]>` 避免堆分配,大部分情况栈上。

**Rust 的 `ahash`** 在 spatial hash 里替代 `DefaultHasher`——3-5 倍速度。Casey HH 的 hash chunk storage(Phase 2)用 `DefaultHasher`,Rust 版应该用 `ahash` 或 `fxhash`。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 alpha blend 边缘过渡比 Wang tiles 简单?Wang tiles 比_alpha blend_ 高级在哪?

**参考解答**:

**alpha blend 简单**:
- 实现简单(就是 blend 公式)
- 不需要美术资源(任何 tile 都能 blend)
- 过渡均匀(直线分界)

**Wang tiles 高级**:
- **不重复**:同样边缘的 tile 可以有多个变体,玩家看不出重复
- **不规则边缘**:tile 内部可以有「伸进邻居」的部分(草丛伸进石头区)
- **更自然**:alpha blend 仍是直线过渡,Wang tiles 可以有曲线/有机过渡

**取舍**:alpha blend 适合快速开发,99% 的游戏够用。Wang tiles 适合追求极致的视觉品质(大厂 AAA)。

```rust
#[derive(Copy, Clone, Debug)]
struct Pixel { r: u8, g: u8, b: u8, a: u8 }

const TILE_SIZE: usize = 16;
const EDGE_WIDTH: usize = 4;

fn grass_color(x: usize, y: usize) -> Pixel {
    // 简化:绿色
    let noise = ((x * 7 + y * 13) % 8) as u8;
    Pixel { r: 30 + noise / 2, g: 120 + noise, b: 30, a: 255 }
}

fn stone_color(x: usize, y: usize) -> Pixel {
    let noise = ((x * 11 + y * 5) % 16) as u8;
    Pixel { r: 100 + noise, g: 100 + noise, b: 100 + noise, a: 255 }
}

fn blend(a: Pixel, b: Pixel, t: f32) -> Pixel {
    Pixel {
        r: (a.r as f32 * (1.0 - t) + b.r as f32 * t) as u8,
        g: (a.g as f32 * (1.0 - t) + b.g as f32 * t) as u8,
        b: (a.b as f32 * (1.0 - t) + b.b as f32 * t) as u8,
        a: 255,
    }
}

fn main() {
    // 渲染 2x1 tile(草地 + 石头)
    let total_width = 2 * TILE_SIZE;
    println!("P3\n{} {}\n255", total_width, TILE_SIZE);

    for y in 0..TILE_SIZE {
        for x in 0..total_width {
            let tile_x = x / TILE_SIZE;
            let local_x = x % TILE_SIZE;
            let local_y = y;

            // 中心颜色
            let center = if tile_x == 0 {
                grass_color(local_x, local_y)
            } else {
                stone_color(local_x, local_y)
            };

            // 边缘 blend(在 tile 0 的右 4 像素 和 tile 1 的左 4 像素)
            let color = if tile_x == 0 && local_x >= TILE_SIZE - EDGE_WIDTH {
                // 草地右边缘:blend 到石头
                let t = (local_x - (TILE_SIZE - EDGE_WIDTH)) as f32 / EDGE_WIDTH as f32;
                let stone = stone_color(0, local_y);  // 石头的左边缘
                blend(center, stone, t * 0.5)  // 最多 50% blend
            } else if tile_x == 1 && local_x < EDGE_WIDTH {
                // 石头左边缘:blend 到草地
                let t = 1.0 - local_x as f32 / EDGE_WIDTH as f32;
                let grass = grass_color(TILE_SIZE - 1, local_y);
                blend(center, grass, t * 0.5)
            } else {
                center
            };

            print!("{} {} {}  ", color.r, color.g, color.b);
        }
        println!();
    }
}
```

## 8 · Rust / Arch 落地代码

```rust
#[derive(Copy, Clone, Debug)]
struct Pixel { r: u8, g: u8, b: u8 }

impl Pixel {
    fn new(r: u8, g: u8, b: u8) -> Self { Self { r, g, b } }
}

const TILE_SIZE: usize = 16;
const EDGE_WIDTH: usize = 4;

fn tile_color(kind: u8, x: usize, y: usize) -> Pixel {
    let noise = ((x as u32 * 7 + y as u32 * 13) % 16) as u8;
    match kind {
        0 => Pixel::new(30, 120 + noise, 30),    // 草地(绿)
        1 => Pixel::new(100 + noise, 100, 80),   // 沙地(黄)
        2 => Pixel::new(100 + noise, 100 + noise, 100 + noise),  // 石头(灰)
        _ => Pixel::new(50, 50, 200),             // 水(蓝)
    }
}

fn blend(a: Pixel, b: Pixel, t: f32) -> Pixel {
    Pixel::new(
        (a.r as f32 * (1.0 - t) + b.r as f32 * t) as u8,
        (a.g as f32 * (1.0 - t) + b.g as f32 * t) as u8,
        (a.b as f32 * (1.0 - t) + b.b as f32 * t) as u8,
    )
}

// 4 邻居过渡
fn render_pixel(
    tiles: &[Vec<u8>], tile_cols: usize, tile_rows: usize,
    px: usize, py: usize,
) -> Pixel {
    let tile_x = px / TILE_SIZE;
    let tile_y = py / TILE_SIZE;
    let local_x = px % TILE_SIZE;
    let local_y = py % TILE_SIZE;

    let kind = tiles[tile_y][tile_x];
    let mut color = tile_color(kind, local_x, local_y);

    // 左边缘
    if local_x < EDGE_WIDTH && tile_x > 0 {
        let n_kind = tiles[tile_y][tile_x - 1];
        if n_kind != kind {
            let n_color = tile_color(n_kind, TILE_SIZE - EDGE_WIDTH + local_x, local_y);
            let t = 1.0 - local_x as f32 / EDGE_WIDTH as f32;
            color = blend(color, n_color, t * 0.5);
        }
    }
    // 右边缘
    if local_x >= TILE_SIZE - EDGE_WIDTH && tile_x + 1 < tile_cols {
        let n_kind = tiles[tile_y][tile_x + 1];
        if n_kind != kind {
            let n_color = tile_color(n_kind, local_x - (TILE_SIZE - EDGE_WIDTH), local_y);
            let t = (local_x - (TILE_SIZE - EDGE_WIDTH)) as f32 / EDGE_WIDTH as f32;
            color = blend(color, n_color, t * 0.5);
        }
    }
    // (上下边缘类似,略)

    color
}

fn main() {
    // 4x1 tile:草地-沙地-石头-水
    let tiles: Vec<Vec<u8>> = vec![vec![0, 1, 2, 3]];
    let tile_cols = tiles[0].len();
    let tile_rows = tiles.len();

    let total_w = tile_cols * TILE_SIZE;
    let total_h = tile_rows * TILE_SIZE;

    println!("P3");
    println!("{} {}", total_w, total_h);
    println!("255");

    for y in 0..total_h {
        for x in 0..total_w {
            let c = render_pixel(&tiles, tile_cols, tile_rows, x, y);
            print!("{} {} {}  ", c.r, c.g, c.b);
        }
        println!();
    }
}
```
