# Day 107 · Z 层渐隐

> Day 071 我们把 entity 升级到 3D 坐标(Vec3),支持了「**多楼层**」。但有一个用户体验问题——玩家站在一楼时,看不到二楼发生了什么(被二楼地板挡住)。今天 Casey 给出一个优雅解法:**离玩家所在楼层越远的 Z 层越透明**,这样玩家可以「**透过上层看到下层**」。这件事在技术上并不复杂(给 push 命令乘一个 alpha),但它涉及的设计原则——「**信息可见性优先于真实感**」——值得花一天好好讲。

## 0 · 为什么要有这一天

考虑你正在做一个 RPG 游戏,玩家进入了一座多层塔。塔有 3 层楼,玩家站在 1 楼大厅。物理上,2 楼地板会挡住玩家看到 1 楼天花板以上的内容。但游戏玩家需要回答「**2 楼有没有怪在跑下来抓我**」——如果完全按物理真实渲染,玩家看不到 2 楼,就被偷袭了。

这不是 bug,这是**设计失败**。游戏渲染的最高目标不是「**真实**」,而是「**让玩家做出有信息支持的决策**」。如果真实感和可玩性冲突,游戏设计师通常选择可玩性。今天 Casey 做的就是这种取舍:**让上层楼半透明,牺牲一点真实感换取战术信息**。

这种「**信息可见性**」的取舍在游戏设计中随处可见。《暗黑破坏神》的「**墙体半透明**」让你看到墙后的怪;《星际争霸》的「**战争迷雾**」让你知道哪里有探索过但当前看不见;《Hades》的「**屋顶消失**」让你进入房间时看到自己。所有这些设计背后的核心都是「**让玩家看到他需要看到的东西**」。

技术实现上,Z 层渐隐需要解决三个问题。第一,**怎么计算每个 entity 的透明度**——离玩家 z 越远越透明,但要保证不太远(否则看不见)也不太近(否则没效果)。第二,**怎么避免「**叠加太多透明层 = 看不清任何东西**」**——如果同时有 5 层半透明,底层完全被稀释。第三,**怎么和 push buffer / sort key 整合**——透明物体必须**从后向前**渲染,顺序错了就有视觉 bug。

完成今天后,你将掌握「**深度相关的透明度**」这一通用技术,可以应用到游戏以外的任何可视化场景(比如建筑剖面图、医学 CT 三视图、CAD 装配图)。

## 1 · Casey 今天做了什么(HH 脉络,简述)

Casey 在视频里做的事可以归纳为三步。

第一步,他在游戏里加一个变量 `player_z_layer: i32`(玩家当前所在楼层,0=1 楼,1=2 楼,2=3 楼)。每帧根据玩家位置更新。

第二步,他在渲染每个 entity 时计算一个 `fade_alpha: f32`。公式大致是:entity 在玩家楼层 → alpha=1.0(完全不透明);在玩家上方一层 → alpha=0.5;上两层 → alpha=0.25;以此类推。下方楼层通常全不画(玩家看不到脚下)。

第三步,他把 `fade_alpha` 乘到 push 命令的 tint color 的 alpha 通道上。原本 `push_bitmap(tint = [1,1,1,1])` 变成 `push_bitmap(tint = [1,1,1, fade_alpha])`。Day 083 的 premultiplied alpha 让这个混合正确无黑边。

视频里 Casey 还做了个细节:在 z 层切换时(玩家上楼梯),fade alpha 做**线性插值平滑过渡**,避免「**上楼瞬间半透明跳变**」这种突兀视觉。

## 2 · 心智模型

**费曼类比**。想象你看一栋**玻璃摩天大楼**的剖面。你在 5 楼。5 楼的墙完全不透明(你能清楚看到自己楼层的同事)。6 楼的墙是淡色玻璃(你能模糊看到楼上的会议)。7 楼是更淡的玻璃。10 楼已经几乎透明(只是淡淡一层蓝)。15 楼完全看不见。

每层的透明度不是「**物理真实**」(玻璃摩天大楼不会这样设计),而是「**为观察者服务**」——你在 5 楼,你最关心 5 楼发生什么,所以 5 楼最实;楼上越远越不重要,所以越透明。这就是 Z 层渐隐的核心思想。

**严谨原理**。设玩家 z = `player_z`,某个 entity 的 z = `entity_z`。Casey 的 fade 公式大致是:

```
delta_z = entity_z - player_z
if delta_z <= 0:            # 在玩家下方或同层
    alpha = 1.0             # 完全不透明(或完全不画,如果太远下方)
else:                       # 在玩家上方
    alpha = 1.0 / (1.0 + delta_z * k)    # k 控制衰减速度,Casey 用 k≈0.5
```

公式 `1.0 / (1 + delta_z × k)` 是「**调和衰减**」——delta_z=0 时 alpha=1,delta_z=1 时 alpha=0.67,delta_z=2 时 alpha=0.5,delta_z=10 时 alpha=0.17。这个曲线**比线性衰减(1 - delta_z × k)更柔和**——线性衰减很快到 0,调和衰减渐近但永不到 0,所以远楼层还能看到模糊影子。

如果你想要更尖锐的衰减(远楼层几乎全透明),用指数衰减:`alpha = exp(-delta_z × k)`。delta_z=0 时 1.0,delta_z=1 时 0.37,delta_z=2 时 0.14,delta_z=5 时 0.007。Casey HH 用的是调和衰减的变体,你也可以实验指数看效果。

**为什么必须从后向前渲染**。透明物体叠加的物理顺序很重要。考虑两个透明物体 A(z=10) 和 B(z=5),玩家从 z=0 向 z 增大方向看。光从 z=∞ 经过 A 再经过 B 到达玩家。所以渲染顺序应该是 A 先画(远),B 后画(近),B 的 alpha 和 A 已经画的混合。

如果顺序反了(B 先画),A 后画时 A 的混合公式 `out = src*A_a + dst*(1-A_a)` 里 `dst` 是 B,但物理上 A 应该先和背景混合再被 B 遮挡,顺序错了颜色就错。这就是为什么 Day 089 的 sort key 把 z depth 放高位——排序后从后向前画,透明物体混合正确。

我们看一下 Rust 实现:

```rust
pub fn fade_alpha(player_z: f32, entity_z: f32, k: f32) -> f32 {
    let delta = entity_z - player_z;
    if delta <= 0.0 {
        1.0                                  // 同层或下层,不透明
    } else {
        1.0 / (1.0 + delta * k)              // 上层,调和衰减
    }
}

// 渲染时:
let a = fade_alpha(player.z, entity.z, 0.7);
renderer.push_bitmap(
    Rect { x: entity.x, y: entity.y, w: 1.0, h: 2.0 },
    entity.bitmap_id,
    [1.0, 1.0, 1.0, a],                       // tint,只调整 alpha
);
```

注意几点 Rust 设计:**纯函数 `fade_alpha`** 易测试——传 player_z, entity_z 直接看输出,不依赖任何状态。**tint 的 RGB 都 1.0**,表示「**不调色,只调透明度**」。如果你想区分楼层颜色(2 楼偏蓝),改成 `[0.8, 0.8, 1.0, a]`。

**Linear 空间 alpha 的重要性**。Day 094 我们强调过「光照必须在 linear 空间算」。alpha 混合同样必须在 linear 空间——sRGB 空间做 alpha 会让暗部权重过大、半透明物体边缘出现黑边。Day 095 的「gamma-correct premultiplied alpha」就是解决这个。Casey 的 push buffer 在 linear 空间存 tint,submit 时统一转 sRGB 输出,所以 `fade_alpha` 直接用 linear 空间的 0..1 就对。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Z 层渐隐在游戏业界有几种变体,知道这些能让你看到别人的实现不陌生。

**《暗黑破坏神 2》的「roof fade」**。当玩家进入建筑,屋顶自动消失。D2 用「**精确的几何检测**」——根据玩家位置和墙体几何决定哪些墙半透明。Casey 的做法是基于 Z 层的粗粒度版,简单但够用。

**《模拟人生》的「cutaway view」**。游戏自动隐藏挡住相机的墙。Maxis 用的是「**wall at camera**」算法——计算墙到相机的距离,挡视线的墙淡出。

**《Hades》的「detailed occlusion」**。Supergiant Games 用了非常精细的房间遮挡——根据玩家在房间的位置,精确淡出挡住玩家的「**墙面卡片**」。这是基于 Casey Z 层渐隐思路的极致版。

**通用术语**。游戏业界管这种技术叫「**occlusion fading**」、「**depth-based transparency**」、「**layer visibility**」。Casey 的极简 Z 层 fade 是教学版,生产代码可能更复杂(考虑视线遮挡、物体优先级、UI 提示)。

### 3.2 · 🎨 图形学视角

图形学里 Z 层渐隐对应到几个 GPU 概念。

**Alpha Blending**。GPU 的标准 blend 公式:`out = src * src_a + dst * (1 - src_a)`。Casey 用 premultiplied 版:`out = src + dst * (1 - src_a)`。两者在 src.rgb 已经乘了 src_a 时等价。OpenGL 的 blend mode:`glBlendFunc(GL_ONE, GL_ONE_MINUS_SRC_ALPHA)` 就是 premultiplied。

**Depth Buffer 与 Transparency**。GPU 的 depth test 和透明物体天生不友好——透明物体不写 depth buffer(否则会挡住后面的透明物体),但又要按 depth 顺序画。Casey 的 CPU 软渲染**没有这个问题**——他完全靠 sort key 排序,没有 depth buffer。Day 235 切 OpenGL 后要分两 pass:先画不透明(开 depth test),再画透明(关 depth write,从后向前)。

**Order-Independent Transparency(OIT)**。GPU 高级技术,用 per-pixel linked list 或 depth peeling 实现透明物体顺序无关。Casey 不用——CPU 软渲染排序成本极低。但你在 Day 235+ 的 OpenGL 路径如果遇到透明排序性能问题,OIT 是工业解法。

### 3.3 · 🐧 Linux 系统编程视角

Linux 桌面也有「**透明叠加**」的概念。Wayland compositor 处理多个 client 的 surface 时,每个 surface 有 alpha 通道,compositor 按某种顺序(z-order)合成。 weston 的 `weston_surface` 有 `alpha` 字段,效果和 Casey 的 fade alpha 概念一致。

Linux 工具链里看透明叠加效果:

- `weston-simple-dmabuf-egl` 演示多个透明 surface 叠加。
- `xcompmgr` 是 X11 的 compositing manager,处理透明窗口。
- `picom` 是 X11 现代合成器,配置文件里可以调透明度规则。

这些工具背后都是同一个数学:`out = src * src_a + dst * (1 - src_a)`。Casey HH 的软渲染让你**从底层**理解这个公式,而不是黑盒调用 GPU API。

### 3.4 · 🦀 Rust 生态视角

Rust 里写 fade alpha 的 hot loop 有几个 SIMD 优化机会。

```rust
// 标量版:
fn fade_alpha_scalar(deltas: &[f32], k: f32, out: &mut [f32]) {
    for (d, o) in deltas.iter().zip(out.iter_mut()) {
        *o = if *d <= 0.0 { 1.0 } else { 1.0 / (1.0 + d * k) };
    }
}

// portable_simd 版(Nightly):
fn fade_alpha_simd(deltas: &[f32], k: f32, out: &mut [f32]) {
    use std::simd::*;
    let k = f32x4::splat(k);
    let one = f32x4::splat(1.0);
    for (chunk, o) in deltas.chunks_exact(4).zip(out.chunks_exact_mut(4)) {
        let d = f32x4::from_slice(chunk);
        let faded = one / (one + d * k);
        // 把 d <= 0 的位置强制设为 1.0
        let mask = d.lanes_le(f32x4::splat(0.0));
        let result = faded.lanes_select(mask, one);
        o.copy_from_slice(result.as_array());
    }
}
```

`std::simd` 在 Nightly 上可用,稳定版用 `core::arch::x86_64::_mm_*`。Casey HH 在 Day 121+ 大量使用 `_mm_*` intrinsics,届时我们会展开讲。

Rust 生态里相关 crate:`wide` 提供 `f32x4` 这种类型简化 SIMD;`polar` 提供 premultiplied alpha blend 函数;`rgb` crate 提供 premultiplied 像素格式。Casey HH 不依赖外部 crate,自己手写,目的是教学透明。

## 4 · 认知地图

### 4.1 上级(它属于哪个更大抽象?)

- **Occlusion Culling(遮挡剔除)** —— 决定「哪些物体不该画」的通用技术,Z 层 fade 是「**不剔除而是淡化**」的变体。
- **Level of Detail(LOD)** —— 远距离物体用简化模型,Z 层 fade 是「**视觉 LOD**」(信息量随距离衰减)。
- **Visibility Information Design(可见性信息设计)** —— 游戏设计原则「玩家应该看到他需要的」,Z 层 fade 是这个原则的渲染实现。

### 4.2 同级(并行方案对比)

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| **Z 层 fade(Casey)** | 按楼层整数衰减 | 多层 2.5D 游戏 | ✅ |
| **基于距离的 fade** | 按相机距离连续衰减 | 3D 透视 | Day 108+ |
| **基于视线遮挡** | 计算精确挡视线的墙 | 真实感强的游戏 | 不用 |
| **完全隐藏** | 远楼层 entity 不画 | 极致性能 | 不用(玩家失去信息) |
| **小地图替代** | 主画面真实,小地图显示 | RTS 类 | 不用 |

这张表的关键洞察:**没有「最好」的方案,只有「最匹配设计目标」的方案**。Casey 选 Z 层 fade 因为它简单(一行代码)、信息充分(看到上下层)、性能好(无几何计算)。其他方案的 trade-off 各不同。

### 4.3 下级(内部零件)

- **`fade_alpha` 函数** —— 计算 entity 的 alpha 值。
- **`player_z_layer`** —— 跟踪玩家当前楼层。
- **`tint` 的 alpha 通道** —— 乘到 push 命令上。
- **sort key 的 z depth 位** —— Day 089 sort key 含 z 信息,保证透明物体从后向前画。
- **premultiplied alpha blend** —— Day 083 引入,保证半透明无黑边。

## 5 · 对照与变奏

**整数楼层 vs 连续 z**。Casey HH 的 fade 用「**整数楼层**」衰减——同层 alpha=1,上一层 alpha=0.5。但物理上 z 是连续的(玩家上楼梯时 z 从 0 平滑变到 32)。Casey 在 Day 107 的实现里其实用了连续 z:`fade_alpha = 1 / (1 + (entity_z - player_z) * k)`,entity_z 和 player_z 都是 f32。所以玩家从 1 楼走到 2 楼的过程中,2 楼的 entity 会从 alpha=0.5 渐渐变成 alpha=1.0,过渡自然。

**完全淡出 vs 保留可见**。一个设计选择:远楼层是「**完全透明(看不见)**」还是「**淡淡影子(还能看)**」。Casey 选后者——`1 / (1 + d*k)` 永远不到 0,保证远楼层始终可见。如果你想完全淡出,用 `max(0, 1 - d * k)`,超过某距离 alpha=0 不画。

**Z 层 fade vs 雾效(fog)**。雾效是「**远处物体颜色趋向雾色**」,本质也是深度衰减。区别:雾效改变 RGB,Z 层 fade 只改 A。Casey Day 408+ 会实现雾效。两者可以叠加——既改 A 又改 RGB,做出「**远楼层既淡又雾蒙蒙**」的效果。

**多玩家不同的 fade**。合作游戏里两个玩家分别在 1 楼和 3 楼,各自的视角 fade 应该不同。这需要**分屏渲染**或**网络同步视角**。Casey HH 是单玩家,简化了这个问题。

**历史演化**。1990 年代早期 2D 游戏(《塞尔达:链接的过去》)用「**进入建筑屋顶消失**」实现多楼层,但只能全开/全关。1996 年《超级马里奥 64》3D 渲染允许「**半透明屋顶**」。2000 年代实时透明成为标配。Casey Day 107 的实现是这两个时代的折中——粗粒度楼层 fade,简单稳定。

## 7 · 变式训练

### Lv1 · 概念辨析(读懂)

**题**:Casey 用调和衰减 `alpha = 1 / (1 + delta_z * k)` 而不是线性衰减 `alpha = max(0, 1 - delta_z * k)`。请回答:(a) 调和衰减 delta_z=10 时 alpha 是多少(k=0.5)?线性衰减呢?(b) 哪种衰减让玩家「**永远不会完全看不到**远楼层」?为什么这是 Casey 想要的?(c) 如果设计师希望「**3 层以上完全淡出**」,该用哪种衰减?

**参考解答**:(a) 调和:`1 / (1 + 10*0.5) = 1/6 ≈ 0.167`。线性:`1 - 10*0.5 = -4`,clamp 到 0。(b) 调和衰减永远 > 0(渐近 0 但不到 0),所以远楼层始终有淡淡影子可见。Casey 想要这种——「**信息保留**」,玩家能模糊看到远处的怪。线性衰减会瞬间变 0,玩家「**失明**」。(c) 线性衰减 + 适当的 k。比如 `max(0, 1 - delta_z * 0.33)`,delta_z=3 时 alpha=0,delta_z=2 时 alpha=0.33。或者用阶跃函数:`if delta_z >= 3 { 0 } else { 1 }`。Casey 的调和衰减做不出「完全淡出」效果,这是设计取舍。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现一个最简的 Z 层 fade 演示。Renderer 持 `player_z: f32`,push 命令时根据 entity 的 z 和 player_z 计算 fade alpha 乘到 tint。画 5 个方块代表 5 个楼层(z = 0, 1, 2, 3, 4),每个 1 米高。玩家从 z=0 开始,按上下方向键调整 player_z(每次 0.1),观察 fade 变化。要求:(a) 玩家所在楼层完全不透明;(b) 上方楼层按调和衰减淡出;(c) 下方楼层完全不画。

**参考解答**:

```rust
pub struct Renderer {
    pub width: u32,
    pub height: u32,
    pub framebuffer: Vec<u32>,
    pub player_z: f32,
    pub world_scale: f32,
}

#[derive(Clone, Copy)]
pub struct Entity { pub x: f32, pub y: f32, pub z: f32, pub w: f32, pub h: f32 }

fn fade_alpha(player_z: f32, entity_z: f32) -> f32 {
    let d = entity_z - player_z;
    if d <= 0.0 { 1.0 } else { 1.0 / (1.0 + d * 0.5) }
}

impl Renderer {
    pub fn draw_floor(&mut self, e: Entity, color: [f32; 4]) {
        let a = fade_alpha(self.player_z, e.z);
        if a <= 0.01 { return; }            // 完全淡出就不画

        let s = self.world_scale;
        // 在屏幕上:z 越大画得越靠上(模拟 2.5D 透视)
        let screen_x = (e.x * s) as i32;
        let screen_y = self.height as i32 - ((e.z + e.h) * s) as i32; // 上层在上方
        let screen_w = (e.w * s) as i32;
        let screen_h = (e.h * s) as i32;

        // 用 fade alpha 乘 tint 的 alpha 通道
        let argb = pack_argb([color[0], color[1], color[2], color[3] * a]);
        for ry in screen_y.max(0)..(screen_y + screen_h).min(self.height as i32) {
            for rx in screen_x.max(0)..(screen_x + screen_w).min(self.width as i32) {
                let i = (ry as u32 * self.width + rx as u32) as usize;
                // 简化:直接覆盖(实际应该 alpha blend)
                self.framebuffer[i] = blend(self.framebuffer[i], argb);
            }
        }
    }
}

fn blend(dst: u32, src: u32) -> u32 {
    let sa = ((src >> 24) & 0xFF) as f32 / 255.0;
    let dr = ((dst >> 16) & 0xFF) as f32 / 255.0;
    let dg = ((dst >> 8) & 0xFF) as f32 / 255.0;
    let db = (dst & 0xFF) as f32 / 255.0;
    let sr = ((src >> 16) & 0xFF) as f32 / 255.0;
    let sg = ((src >> 8) & 0xFF) as f32 / 255.0;
    let sb = (src & 0xFF) as f32 / 255.0;
    let or = (sr * sa + dr * (1.0 - sa)) * 255.0;
    let og = (sg * sa + dg * (1.0 - sa)) * 255.0;
    let ob = (sb * sa + db * (1.0 - sa)) * 255.0;
    (0xFFu32 << 24) | ((or as u32) << 16) | ((og as u32) << 8) | (ob as u32)
}
```

完成后,玩家在 z=0 时,5 层楼的颜色从下到上 alpha 是 1.0, 0.67, 0.5, 0.4, 0.33——上层楼看起来淡。玩家 z=2 时,alpha 变成 1.0(2 楼), 0.67(3 楼), 0.5(4 楼),0.4(5 楼),1 楼是 1.0(下方不画或全实)。

## 8 · Rust / Arch 落地代码

完整可跑的 Z 层 fade 演示。

```rust
// Cargo.toml:
// [dependencies]
// image = "0.25"
// bytemuck = { version = "1", features = ["extern_crate_alloc"] }

pub struct Renderer {
    pub width: u32,
    pub height: u32,
    pub framebuffer: Vec<u32>,
    pub player_z: f32,
    pub world_scale: f32,
}

#[derive(Clone, Copy)]
pub struct Floor { pub z: f32, pub color: [f32; 4] }

fn fade_alpha(player_z: f32, entity_z: f32) -> f32 {
    let d = entity_z - player_z;
    if d <= 0.0 { 1.0 } else { 1.0 / (1.0 + d * 0.5) }
}

impl Renderer {
    pub fn new(w: u32, h: u32) -> Self {
        Self {
            width: w, height: h,
            framebuffer: vec![0xFF181820; (w * h) as usize],
            player_z: 0.0,
            world_scale: 64.0,
        }
    }

    // 画一个矩形代表楼层,带 fade alpha
    pub fn draw_floor(&mut self, f: Floor, x: f32, w_world: f32) {
        let a = fade_alpha(self.player_z, f.z);
        if a < 0.01 { return; }

        let s = self.world_scale;
        let screen_x = (x * s) as i32;
        let screen_w = (w_world * s) as i32;
        let floor_height_world = 0.3;            // 视觉上每层楼 0.3 米厚
        // z 越大越靠屏幕上方(模拟俯视带高度感)
        let screen_y = self.height as i32 - ((f.z + floor_height_world) * s) as i32;
        let screen_h = (floor_height_world * s) as i32;

        let src_argb = pack_argb([f.color[0], f.color[1], f.color[2], f.color[3] * a]);

        for ry in screen_y.max(0)..(screen_y + screen_h).min(self.height as i32) {
            for rx in screen_x.max(0)..(screen_x + screen_w).min(self.width as i32) {
                let i = (ry as u32 * self.width + rx as u32) as usize;
                self.framebuffer[i] = alpha_blend(self.framebuffer[i], src_argb);
            }
        }
    }
}

fn alpha_blend(dst: u32, src: u32) -> u32 {
    // premultiplied alpha blend: out = src + dst * (1 - src_a)
    let sa = ((src >> 24) & 0xFF) as f32 / 255.0;
    let inv = 1.0 - sa;
    let dr = ((dst >> 16) & 0xFF) as f32;
    let dg = ((dst >> 8) & 0xFF) as f32;
    let db = (dst & 0xFF) as f32;
    let sr = ((src >> 16) & 0xFF) as f32;
    let sg = ((src >> 8) & 0xFF) as f32;
    let sb = (src & 0xFF) as f32;
    // src 假设已经 premultiplied:实际我们要再乘 sa(简化版未严格 premultiplied)
    let or = sr * sa + dr * inv;
    let og = sg * sa + dg * inv;
    let ob = sb * sa + db * inv;
    let oa = sa + (((dst >> 24) & 0xFF) as f32 / 255.0) * inv;
    pack_argb([or / 255.0, og / 255.0, ob / 255.0, oa])
}

fn pack_argb(c: [f32; 4]) -> u32 {
    let to_u = |v: f32| (v.clamp(0.0, 1.0) * 255.0) as u32;
    (to_u(c[3]) << 24) | (to_u(c[0]) << 16) | (to_u(c[1]) << 8) | to_u(c[2])
}

fn save_png(r: &Renderer, path: &str) {
    let bytes: Vec<u8> = r.framebuffer.iter().flat_map(|p| p.to_le_bytes()).collect();
    let img: image::ImageBuffer<image::Rgba<u8>, _> =
        image::ImageBuffer::from_raw(r.width, r.height, bytes).unwrap();
    img.save(path).unwrap();
}

fn main() {
    let floors = [
        Floor { z: 0.0, color: [0.8, 0.2, 0.2, 1.0] },   // 1F 红
        Floor { z: 1.0, color: [0.8, 0.5, 0.2, 1.0] },   // 2F 橙
        Floor { z: 2.0, color: [0.8, 0.8, 0.2, 1.0] },   // 3F 黄
        Floor { z: 3.0, color: [0.2, 0.8, 0.2, 1.0] },   // 4F 绿
        Floor { z: 4.0, color: [0.2, 0.2, 0.8, 1.0] },   // 5F 蓝
    ];

    // 玩家在 1 楼
    let mut r = Renderer::new(800, 600);
    r.player_z = 0.0;
    for f in &floors {
        r.draw_floor(*f, 1.0, 10.0);    // 从世界 x=1 开始,10 米宽
    }
    save_png(&r, "day107_player_at_0.png");

    // 玩家在 3 楼
    let mut r = Renderer::new(800, 600);
    r.player_z = 2.0;
    for f in &floors {
        r.draw_floor(*f, 1.0, 10.0);
    }
    save_png(&r, "day107_player_at_2.png");

    println!("对比两张图:player_at_0 上层楼半透明,player_at_2 中间楼层最实");
}
```

**出错怎么办(troubleshooting)**:

- **所有楼层一样实** —— `fade_alpha` 的 `if d <= 0` 永远成立(你的 entity.z 总小于 player_z)。检查 entity.z 数据。
- **半透明物体有黑边** —— Day 083 的 premultiplied 没应用。确保 `src_argb` 的 RGB 已乘 alpha,或用正确的 blend 公式。
- **上层楼看不到** —— `screen_y = height - (z+h)*scale`,如果 z* scale > height,screen_y 是负的,矩形在屏幕外。降 world_scale 或缩 world z 范围。
- **楼层颜色错误** —— pack_argb 顺序错。Casey HH 用 `0xAARRGGBB`,有的库用 `0xAABBGGRR`。试试两种。
