
# Day 091 · 基底 第二部分:完整 2D 旋转矩阵

> 昨天(Day 090)我们用一个角度 `rotation: f32` 表达「玩家面朝哪」。今天 Casey 把这个角度展开成真正的 **2×2 旋转矩阵**——一个数字方阵,作用是「把局部坐标转成旋转后的世界坐标」。这一步是从「概念上的 base」走到「代码里的矩阵运算」的桥梁。后面 Day 100 的反射、Day 102 的法线变换、Day 108 的透视投影,全部建立在今天写的这个矩阵框架之上。

## 0 · 为什么要有这一天

昨天的 base 看起来很美:一个 `position + rotation` 描述「在哪 + 朝哪」。可是当你要真的把局部坐标 `(10, 5)` 变换成世界坐标时,你写出来的代码长什么样?

最直觉的做法是分两步:
1. 用 `sin`/`cos` 把 `(10, 5)` 旋转 `rotation` 弧度
2. 加上 `position`

代码大致是这样:

```rust
let cos = rotation.cos();
let sin = rotation.sin();
let world_x = cos * local.x - sin * local.y + base.position.x;
let world_y = sin * local.x + cos * local.y + base.position.y;
```

写一次没问题。但当你的渲染管线变成下面这样:

```
模型局部坐标 ─→ entity base 变换 ─→ camera base 变换 ─→ 屏幕投影
```

每一步都涉及旋转 + 平移 + 缩放,每一步都写 4 行 `sin/cos` 公式,代码立刻变成意大利面条。**矩阵就是用来把这些「一堆数字操作」打包成一种统一格式**的工具。

引入矩阵后,整条变换链变成「**矩阵乘法**」一种操作:

```
M_total = M_camera · M_entity · M_model
world_pos = M_total · local_pos
```

你只需要存一个矩阵,做一次乘法,就能完成「全部变换的复合」。这是 Day 105+ 「清理渲染器 API」的核心动机,也是 Phase 6+ 「GPU shader 里光速算 MVP」的根源。

心理锚点:看完今天,你能向队友解释「为什么游戏引擎里所有变换都用矩阵而不是分散的 sin/cos」,你能用 Rust 写一个 2×2 矩阵库,能用矩阵表达任意 2D 旋转,能把「先旋转再平移」这种组合写成两个矩阵的乘积。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. 把 Day 090 的 `Base { position, rotation }` 升级成 `Base { position, x_axis, y_axis }`——其中 `x_axis` 和 `y_axis` 是两个 2D 向量,代表 base 旋转后的 **x 轴方向**和 **y 轴方向**。
2. 写出 `basis_vector(local, x_axis, y_axis)` 函数:把局部坐标 `(lx, ly)` 解释为「沿 x_axis 走 lx 步,沿 y_axis 走 ly 步」,即 `world_offset = lx * x_axis + ly * y_axis`。这就是**线性组合**(linear combination)。
3. 把这个表达式重写成矩阵形式,得到 2×2 旋转矩阵。
4. 用 `base_to_world(local, base)` 一次完成「旋转 + 平移」。

Casey 特别强调:`x_axis, y_axis` 不一定非要是单位向量——如果它们长度是 2,那 base 自带 2 倍缩放。这种「基底向量 + 缩放因子」的设计让 base 同时表达旋转和缩放,Day 106 的世界缩放就是改这两个向量的长度。

## 2 · 心智模型

### 费曼类比:你站在客厅,描述沙发在哪

想象你站在客厅中央,你定义了一套「**自身坐标系**」:
- 你的**右**是 +x
- 你的**前**是 +y
- 你的**位置**是原点 (0, 0)

你说「沙发在我前方 2 米,右边 1 米」——这是**局部坐标** `(1, 2)`。

但你的朋友站在门口,他不知道你面朝哪。你必须把「沙发」的位置翻译成**世界坐标**(比如「沙发在客厅东北角,门东南方 3 米」)。

怎么做?你需要两个信息:
1. **你的世界位置**(把你这个坐标系原点放到世界哪里)
2. **你的 x 轴方向、y 轴方向**(世界坐标系里,你的「右」和「前」分别朝哪)

这就是 base 的本质——「**一组基底向量 + 一个原点**」。Base 不直接存「角度」,而是存「**旋转后的 x 轴和 y 轴在世界坐标里指向哪里**」。

```
base = {
    origin: Vec2(100, 50),     // 你站在客厅 (100, 50)
    x_axis: Vec2(0, 1),        // 你面朝北,所以你的「右」(原 +x)在世界里朝北 (+y)
    y_axis: Vec2(-1, 0),       // 你的「前」(原 +y)在世界里朝西 (-x)
}
```

沙发的世界位置 = `origin + lx * x_axis + ly * y_axis = (100, 50) + 1 * (0, 1) + 2 * (-1, 0) = (98, 51)`。

### 严谨原理

#### 2.1 基底向量 (basis vectors)

**定义**:一个 2D 坐标系由两个不共线的向量 `x_axis` 和 `y_axis` 定义,称为这个坐标系的**基底**(basis)。「不共线」意思是它们不能平行(否则无法张成 2D 平面)。

**任何局部坐标 `(lx, ly)` 在这个 base 里的世界位置**:

```
world = origin + lx * x_axis + ly * y_axis
```

这就是「**线性组合**」——用两个基底向量的标量倍数相加。这是整个线性代数的核心操作。

#### 2.2 标准基底 vs 任意基底

**标准基底**:`x_axis = (1, 0)`,`y_axis = (0, 1)`。这是没有任何旋转、没有缩放的 base,所有局部坐标和世界坐标一致。

**旋转 90° 的基底**:`x_axis = (0, 1)`(原 x 朝北了),`y_axis = (-1, 0)`(原 y 朝西了)。

**带缩放的基底**:`x_axis = (2, 0)`(x 方向放大 2 倍),`y_axis = (0, 3)`(y 方向放大 3 倍)。

#### 2.3 旋转矩阵的诞生

当 base 只旋转(不缩放),`x_axis` 和 `y_axis` 必须是单位向量,而且互相垂直。设旋转角度是 θ(逆时针为正),那么:

```
x_axis = (cos θ, sin θ)
y_axis = (-sin θ, cos θ)
```

**为什么?** 想象原 x 轴 (1, 0) 旋转 θ 后指向哪。三角函数定义告诉我们:

- 旋转后的 x 分量 = cos θ
- 旋转后的 y 分量 = sin θ

同理,原 y 轴 (0, 1) 旋转 θ 后指向 `(-sin θ, cos θ)`。

**验证**:θ = 0 时,`x_axis = (1, 0)`、`y_axis = (0, 1)`——没旋转,标准基底,正确。θ = 90° 时,`x_axis = (0, 1)`、`y_axis = (-1, 0)`——转 90°,正确。

把这些数字写成 2×2 矩阵:

```
R(θ) = | cos θ   -sin θ |
       | sin θ    cos θ |
```

**矩阵乘法**:矩阵 `M = [x_axis | y_axis]`(列向量拼起来)乘以列向量 `v = (lx, ly)` 的结果就是 `lx * x_axis + ly * y_axis`。展开:

```
| world_x |   | cos θ   -sin θ |   | lx |   | cos θ * lx - sin θ * ly |
| world_y | = | sin θ    cos θ | · | ly | = | sin θ * lx + cos θ * ly |
```

这就是高中数学里见过的 2D 旋转公式。**矩阵没有引入新东西,只是把公式打包**。

#### 2.4 复合变换:矩阵乘法

矩阵的真正威力在于**复合**。两个变换先做 A 再做 B,等价于「先乘 A 再乘 B」的矩阵——但你可以**预先把 A·B 算出来**,运行时只乘一次。

举例:相机视角 = 「先按相机角度旋转,再按相机位置平移」。这两个操作可以预先合成一个「view matrix」,渲染时对每个顶点只乘一次。

**矩阵乘法公式**(2×2 乘 2×2):

```
C = A · B
C[i][j] = Σ_k A[i][k] * B[k][j]
```

即 C 的第 i 行第 j 列,是 A 的第 i 行和 B 的第 j 列做点积。

```rust
fn mat2_mul(a: Mat2, b: Mat2) -> Mat2 {
    Mat2 {
        m00: a.m00*b.m00 + a.m01*b.m10,
        m01: a.m00*b.m01 + a.m01*b.m11,
        m10: a.m10*b.m00 + a.m11*b.m10,
        m11: a.m10*b.m01 + a.m11*b.m11,
    }
}
```

#### 2.5 2D 旋转的代数性质

- **可结合**:`R(α)·R(β) = R(α+β)`(连续两个旋转等价于一次合成旋转)。
- **可逆**:`R(θ)⁻¹ = R(-θ)`(反向旋转)。
- **保长**:旋转不改变向量长度(只是改变方向)。
- **保角**:两个向量之间的夹角旋转后不变。
- **行列式 = 1**:`det(R(θ)) = cos²θ + sin²θ = 1`。

**行列式 (determinant)** 简单说就是「这个矩阵变换把面积放大了多少倍」。旋转不改变面积,所以 det = 1。缩放 2 倍的矩阵 det = 4(2D 里)。如果 det = -1,说明有镜像翻转。

### Rust 实现

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn add(self, o: Self) -> Self { Self::new(self.x + o.x, self.y + o.y) }
    fn scale(self, k: f32) -> Self { Self::new(self.x * k, self.y * k) }
}

#[derive(Copy, Clone, Debug)]
struct Mat2 {
    // 列主序 (column-major),OpenGL/Vulkan 风格
    // m00 = 第 0 列第 0 行,m10 = 第 0 列第 1 行
    m00: f32, m10: f32,   // 第 0 列 (x_axis)
    m01: f32, m11: f32,   // 第 1 列 (y_axis)
}

impl Mat2 {
    fn from_angle(theta: f32) -> Self {
        let (s, c) = theta.sin_cos();
        Self { m00: c, m10: s, m01: -s, m11: c }
    }
    fn mul_vec(self, v: Vec2) -> Vec2 {
        Vec2::new(
            self.m00 * v.x + self.m01 * v.y,
            self.m10 * v.x + self.m11 * v.y,
        )
    }
}

#[derive(Copy, Clone, Debug)]
struct Base2D {
    origin: Vec2,
    rot: Mat2,    // 直接存旋转矩阵,不再存角度
}

impl Base2D {
    fn from_position_angle(pos: Vec2, theta: f32) -> Self {
        Self { origin: pos, rot: Mat2::from_angle(theta) }
    }
    fn to_world(self, local: Vec2) -> Vec2 {
        self.origin.add(self.rot.mul_vec(local))
    }
}

fn main() {
    let base = Base2D::from_position_angle(Vec2::new(100.0, 50.0), 90.0_f32.to_radians());
    let sword_local = Vec2::new(10.0, 5.0);
    let sword_world = base.to_world(sword_local);
    // 预期:旋转 90° 后 (10, 5) → (-5, 10),加上 origin (100, 50) = (95, 60)
    println!("sword world pos: {:?}", sword_world);
    assert!((sword_world.x - 95.0).abs() < 1e-3);
    assert!((sword_world.y - 60.0).abs() < 1e-3);
}
```

**逐行解释**:
- `m00, m10, m01, m11` — 用列主序存 2×2 矩阵。`m_ij` 表示「第 j 列第 i 行」。列主序是 OpenGL/Vulkan/glsl 的约定,Rust 数学界可能用行主序,我们跟图形学约定。
- `from_angle(theta)` — 用 `sin_cos()` 一次性拿到 `(sin, cos)`(比分别调用快——CPU 有 `fsincos` 指令同时算两个)。
- `mul_vec` — 矩阵乘向量。注意公式是 `M · v`,结果是列向量。
- `to_world` — 「旋转 + 平移」复合。先旋转局部坐标,再加 origin。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏里 base 的实际使用场景:

1. **角色装备**:玩家的剑、帽子、宠物都在玩家的 base 里。玩家旋转,所有装备跟着旋转——因为它们都通过 `player_base.to_world(local)` 计算世界位置。
2. **相机跟随**:相机本身是个 base。相机的「位置 + 朝向」定义了 view matrix。
3. **骨骼动画**:每根骨头是一个 base,骨头之间存在父子关系,父子 base 通过矩阵乘法复合。
4. **载具**:坦克的炮塔是一个 base(相对车体),炮管是另一个 base(相对炮塔)。它们层层组合。

**坑 1:浮点累积漂移**。如果你的 base 是「每帧旋转一点」累积得到,经过 1 小时后 `rotation` 浮点误差可能让基底向量不再正交(长度不再是 1)。**修复**:每帧用 `Vec2::normalized()` 重新归一化,或定期重建。

**坑 2:旋转顺序**。3D 里旋转有 3 个轴,顺序不同结果不同(绕 x 转 90° 再绕 y 转 90° ≠ 反过来)。**约定**:右手坐标系 + XYZ 顺序(Euler angles),或更稳的**四元数**(Day 200+ Casey 会讲)。

### 3.2 · 🎨 图形学视角

矩阵在图形学里几乎是**唯一**的变换表达方式。GPU 的 vertex shader 第一行通常是:

```glsl
gl_Position = projection * view * model * vec4(pos, 1.0);
```

这就是 3 个矩阵复合一次乘到顶点上。GPU 硬件专门优化了 4×4 矩阵乘法(通常 1 个 cycle 算完)。

**齐次坐标 (homogeneous coordinates)**:为了用矩阵表达「平移」(纯平移不是线性变换,2D 平移不能用 2×2 矩阵表达),图形学引入「**加一个维度**」的技巧。

2D 平移 `(tx, ty)` 写成 3×3 矩阵:

```
| 1  0  tx |
| 0  1  ty |
| 0  0  1  |
```

把 2D 点 `(x, y)` 加个 `1` 变成 `(x, y, 1)`,然后做矩阵乘法,结果是 `(x + tx, y + ty, 1)`,丢掉最后的 `1` 就得到平移后的点。最后的 `1` 叫 **w 分量**(w component),它让你用矩阵同时表达线性变换 + 平移。

3D 同理:用 4×4 矩阵 + `(x, y, z, 1)` 齐次坐标,可以表达任意 3D 旋转 + 缩放 + 平移的复合。Day 108 透视投影用这个 `w` 分量做透视除法。

**法线变换的特殊性**:Day 102 Casey 会发现法线不能直接用 model matrix 变换——必须用 `(M⁻¹)ᵀ`(model matrix 的逆的转置)。原因是法线必须始终垂直于表面,普通矩阵变换不保证这一点。

### 3.3 · 🐧 Linux 系统编程视角

矩阵本身是纯数学,但有几个 Linux 相关的边角:

1. **CPU 的浮点三角函数**:`sin`/`cos` 在 x86_64 上是硬件指令(`fsincos`)。Rust 的 `f32::sin_cos()` 在 release 模式编译成这条指令。Debug 模式可能调用 libm。
2. **SIMD 优化**:2×2 矩阵乘法可以用 SSE `_mm_mul_ps` 一次算 4 个 float。Casey Day 112+ 大量使用。
3. **`libm` 是 glibc 的一部分**:

```bash
# 看 libm 提供的三角函数
nm -D /usr/lib/libm.so.6 | grep -E " T (sinf|cosf|sincosf)"
# 输出:00000000000xxxx T sincosf
```

`sincosf` 是 C99 加的「一次算 sin 和 cos」的函数,Rust 的 `sin_cos()` 底层就是它。

### 3.4 · 🦀 Rust 生态视角

Rust 写矩阵库有几个设计选择:

**选择 1:数组 vs 命名字段**

```rust
struct Mat2 { m: [f32; 4] }          // 数组版本
struct Mat2 { m00: f32, m01: f32, m10: f32, m11: f32 }  // 命名字段
```

数组版本访问 `m.0` 没名字,但可以用 `m[idx]` 动态索引。命名字段更清晰但啰嗦。**Casey 选中间方案**:用 `[[f32; 2]; 2]`(二维数组),`m[row][col]` 访问。

**选择 2:列主序 vs 行主序**

图形学传统(GLSL、Vulkan、OpenGL)是**列主序**。CPU 数学库(如 Eigen、DirectX Math)常是**行主序**。两个约定混用是经典 bug 源。

Rust 生态主流 crate `glam` 用列主序(对齐 GPU)。`nalgebra` 用列主序(对齐科学计算惯例)。

**选择 3:是否 SIMD**

```rust
// 标量版本(易读)
struct Mat2 { m00: f32, m01: f32, m10: f32, m11: f32 }

// SIMD 版本(快,4 个 f32 打包成 __m128)
#[cfg(target_arch = "x86_64")]
struct Mat2Simd { cols: [__m128; 2] }
```

`glam` 在内部根据目标平台自动选 SIMD 或标量。教学阶段建议手写标量版本,完全理解后再上 SIMD。

**选择 4:const generics 表达任意维度**

```rust
struct Mat<const M: usize, const N: usize> { data: [[f32; N]; M] }
```

Rust 1.51+ 支持 const generics。这让你写一份代码同时支持 `Mat<2,2>`、`Mat<3,3>`、`Mat<4,4>`。`nalgebra` 大量使用。

**实际推荐**:
- 教学阶段:手写 `Mat2`、`Mat3`、`Mat4` 三个独立 struct,理解每个的语义
- 工程阶段:用 `glam::Mat2/Mat3/Mat4`,工业级 SIMD 优化
- 科学计算:用 `nalgebra::SMatrix<f32, 4, 4>`,完全泛型

## 5 · 对照与变奏

### 同一变换在不同表达下的差异

**旋转 30° 后再旋转 60°**(总效果 = 旋转 90°):

- **角度表达**:`angle = 30 + 60 = 90`——一行加法。
- **矩阵表达**:`R(30)·R(60) = R(90)`——4 次乘法 + 3 次加法。
- **四元数表达**:`q1 * q2`——16 次乘法 + 12 次加法,但 3D 下无歧义。

为什么矩阵比角度「慢」还要用?因为矩阵可以表达任意线性变换(缩放、错切、镜像),角度只能表达旋转。**矩阵是统一的容器**,代价是稍慢。

### 列向量 vs 行向量约定

```
列向量(图形学惯例):   行向量(DirectX 数学惯例):
v' = M · v             v' = v · M
|vx'|   |m00 m01| |vx|    |vx' vy'| = |vx vy| |m00 m01|
|vy'| = |m10 m11| |vy|                       |m10 m11|
```

两个约定等价,但矩阵的存储顺序相反!OpenGL 用列向量(Day 105 Casey 跟这个),DirectX 用行向量。**bug 来源**:从 OpenGL 教程抄的矩阵直接用在 DirectX 项目里,会发现物体横向镜像了。

### CPU 矩阵 vs GPU 矩阵

CPU 上矩阵乘法是「循环展开 + 浮点运算」。GPU 上有专门的矩阵-矩阵乘法单元(tensor core),4×4 矩阵乘法 1 个 cycle 完成。这是为什么 GPU 渲染快——变换在 GPU 上几乎免费。

### Lv1 · 概念辨析

**题**:有人问你「为什么 Casey 用矩阵而不是直接存角度 + sin/cos?」用 3 个具体的工程理由回答,每个理由配一个具体场景。

**参考解答**:
1. **可复合** — 多次变换可以预先合成一个矩阵,运行时只乘一次。场景:渲染管线里「model → view → projection」三步变换,如果用角度,每个顶点要算 3 次 sin/cos;用矩阵,只需一次 4×4 矩阵乘向量。
2. **统一表达** — 矩阵可以表达任意线性变换(旋转、缩放、错切、镜像),代码统一,而角度只能表达旋转。场景:Day 106 世界缩放,如果用角度,需要额外加 `scale` 字段;用矩阵,直接改基底向量长度。
3. **GPU 友好** — 硬件专门优化了矩阵乘法。场景:GLSL shader 里 `mat4 * vec4` 一条指令;如果用角度,GPU 要算 sin/cos 反而慢。

### Lv2 · 动手实践

**题**:扩展 `Mat2`,加入:矩阵乘法 `mul_mat`、矩阵的转置 `transpose`、矩阵的逆 `inverse`(2×2 矩阵逆公式:`1/det * |d -b|-c a|`)。写测试:

- `R(θ)·R(-θ) = I`(验证可逆)

**参考解答**:

```rust
impl Mat2 {
    fn identity() -> Self {
        Self { m00: 1.0, m10: 0.0, m01: 0.0, m11: 1.0 }
    }
    fn determinant(self) -> f32 {
        self.m00 * self.m11 - self.m01 * self.m10
    }
    fn transpose(self) -> Self {
        Self { m00: self.m00, m10: self.m01, m01: self.m10, m11: self.m11 }
    }
    fn inverse(self) -> Option<Self> {
        let det = self.determinant();
        if det.abs() < 1e-9 { return None; }  // 不可逆(退化)
        let inv_det = 1.0 / det;
        Some(Self {
            m00:  self.m11 * inv_det,
            m10: -self.m10 * inv_det,
            m01: -self.m01 * inv_det,
            m11:  self.m00 * inv_det,
        })
    }
    fn mul_mat(self, o: Self) -> Self {
        Self {
            m00: self.m00*o.m00 + self.m01*o.m10,
            m10: self.m10*o.m00 + self.m11*o.m10,
            m01: self.m00*o.m01 + self.m01*o.m11,
            m11: self.m10*o.m01 + self.m11*o.m11,
        }
    }
}

fn approx_eq(a: Mat2, b: Mat2, eps: f32) -> bool {
    (a.m00 - b.m00).abs() < eps && (a.m01 - b.m01).abs() < eps &&
    (a.m10 - b.m10).abs() < eps && (a.m11 - b.m11).abs() < eps
}

fn main() {
    let eps = 1e-5;
    let r30 = Mat2::from_angle(30.0_f32.to_radians());
    let r60 = Mat2::from_angle(60.0_f32.to_radians());
    let r90 = Mat2::from_angle(90.0_f32.to_radians());
    // 测试 1:R(30)·R(60) ≈ R(90)
    assert!(approx_eq(r30.mul_mat(r60), r90, eps), "R(30)*R(60) != R(90)");
    // 测试 2:R(θ)·R(-θ) = I
    let r_neg = Mat2::from_angle(-30.0_f32.to_radians());
    assert!(approx_eq(r30.mul_mat(r_neg), Mat2::identity(), eps), "R*R^-1 != I");
    // 测试 3:R(θ).transpose() = R(-θ)
    assert!(approx_eq(r30.transpose(), r_neg, eps), "transpose != inverse");
    println!("All matrix tests passed!");
}
```

**关键点**:
- 行列式 `det = ad - bc`,2×2 矩阵的面积缩放因子。`det = 0` 说明矩阵退化(不能逆)。
- 逆矩阵公式 `M⁻¹ = (1/det) · adjugate(M)`,其中 adjugate 是「主对角线互换 + 副对角线取反」。
- 旋转矩阵的转置 = 逆(`R^T = R^-1`),这种矩阵叫**正交矩阵 (orthogonal matrix)**。

## 8 · Rust / Arch 落地代码

### Rust 完整可跑示例

把 §7 Lv2 扩展,加上「base 嵌套」(子 base 在父 base 里)演示:

```rust
// Cargo.toml:空即可

#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn add(self, o: Self) -> Self { Self::new(self.x + o.x, self.y + o.y) }
}

#[derive(Copy, Clone, Debug)]
struct Mat2 { m00: f32, m10: f32, m01: f32, m11: f32 }
impl Mat2 {
    fn identity() -> Self { Self { m00:1.0, m10:0.0, m01:0.0, m11:1.0 } }
    fn from_angle(t: f32) -> Self {
        let (s, c) = t.sin_cos();
        Self { m00: c, m10: s, m01: -s, m11: c }
    }
    fn mul_vec(self, v: Vec2) -> Vec2 {
        Vec2::new(self.m00*v.x + self.m01*v.y, self.m10*v.x + self.m11*v.y)
    }
    fn mul_mat(self, o: Self) -> Self {
        Self {
            m00: self.m00*o.m00 + self.m01*o.m10,
            m10: self.m10*o.m00 + self.m11*o.m10,
            m01: self.m00*o.m01 + self.m01*o.m11,
            m11: self.m10*o.m01 + self.m11*o.m11,
        }
    }
}

#[derive(Copy, Clone, Debug)]
struct Base { origin: Vec2, rot: Mat2 }
impl Base {
    fn new(pos: Vec2, theta: f32) -> Self { Self { origin: pos, rot: Mat2::from_angle(theta) } }
    fn to_world(self, local: Vec2) -> Vec2 { self.origin.add(self.rot.mul_vec(local)) }
    /// 子 base 在父 base 里的复合变换
    fn compose(parent: Base, child: Base) -> Base {
        Base {
            origin: parent.to_world(child.origin),
            rot: parent.rot.mul_mat(child.rot),
        }
    }
}

fn main() {
    // 玩家在世界 (100, 50),面朝 45°
    let player = Base::new(Vec2::new(100.0, 50.0), 45.0_f32.to_radians());
    // 剑相对玩家在 (10, 0),剑本身又旋转 30°(挥剑动画)
    let sword_base = Base::new(Vec2::new(10.0, 0.0), 30.0_f32.to_radians());
    // 复合:剑在世界里的 base
    let sword_world = Base::compose(player, sword_base);
    // 剑尖(剑 base 里 (5, 0) 的点)的世界位置
    let tip_local = Vec2::new(5.0, 0.0);
    let tip_world = sword_world.to_world(tip_local);
    println!("sword tip world: {:?}", tip_world);
    // 手动验证:玩家(100,50)+45° + 剑(10,0)+30° = 玩家 + 剑(转45°后位置) + 剑尖(转75°后)
    // 剑在玩家 base 里:转 45° 后 (10, 0) → (10*cos45, 10*sin45) ≈ (7.07, 7.07)
    // 剑尖相对剑:转 75° 后 (5, 0) → (5*cos75, 5*sin75) ≈ (1.29, 4.83)
    // 总:origin (100,50) + (7.07, 7.07) + (1.29, 4.83) ≈ (108.36, 61.9)
}
```

**关键 Rust 特性**:
- `#[derive(Copy, Clone, Debug)]` — Vec2/Mat2/Base 都是 16/16/24 字节小类型,Copy 让它们按值传递(无所有权问题)
- `sin_cos()` 返回元组 `(f32, f32)`,Rust 模式匹配 `(s, c)` 解构
- `mul_mat` 的内联展开 — Rust 编译器在 release 模式会自动 SIMD 化这 8 个乘加运算
