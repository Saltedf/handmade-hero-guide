
# Day 084 · 滚动地面缓冲

> 你昨天缓存了 tile,但每帧还是要 blit 1000 个 tile 到屏幕——blit 也要时间。Casey 今天给一个更大的优化:**滚动地面缓冲**。一块比屏幕大的缓冲跟着相机走,大部分像素复用,只边缘重新生成。这种「**滚动 + 部分更新**」是游戏渲染的经典技巧,从超级马里奥的卷轴到 Minecraft 的 chunk 都是这个思路。

## 0 · 为什么要有这一天

你的渲染循环:

```rust
fn render_frame(world: &World, framebuffer: &mut Framebuffer) {
    for tile in visible_tiles(world.camera) {
        let bmp = tile_cache.get_or_composite(tile.x, tile.y);
        blit(framebuffer, tile.screen_x, tile.screen_y, bmp);
    }
}
```

1000 tile × 4096 像素 = 400 万像素 blit/帧。即使 blit 很快(O(N)),也是毫秒级开销。

**问题**:每帧 1000 个 tile 都 blit,但**大部分像素和上一帧一样**!玩家移动 1 像素,tile 内容没变,只是位置略偏。为什么重新 blit 所有 tile?

**Casey 的解法**:**滚动地面缓冲**。

- 一块比屏幕大(2× 屏幕)的离屏 buffer。
- 相机移动时,**整体平移 buffer**(便宜,memcpy)。
- 缓冲边缘接近屏幕边缘时,**异步生成新区域**(只在边缘 blit 新 tile)。

这样每帧只有「新出现的边缘」需要 blit,大部分像素已经在 buffer 里。**blit 量从 1000 tile 降到 ~50 tile**。

心理锚点:看完今天,你能向队友解释「为什么我们的渲染比隔壁游戏快」。你能用 Rust 写一个滚动 buffer。你能用 30 秒说清「**为什么相机移动时画面不闪烁**」(因为 buffer 复用)。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. **定义 GroundBuffer**:`width × height × pixels`,比屏幕大(比如 1920×1080 屏幕,buffer 用 2560×1440)。
2. **维护 buffer_offset**:buffer 当前对应世界坐标的偏移。
3. **每帧检查相机**:相机移动到 buffer 边缘时,**平移 buffer 内容** + **生成新边缘**。
4. **渲染**:从 buffer blit 到 framebuffer(简单矩形 blit,快)。

Casey 强调:「**部分更新**」是优化的关键——只算变化的部分,其他复用。

## 2 · 心智模型

### 费曼类比:长卷胶片

想象你拍长卷胶片(老式照相机)。胶片很宽(2× 屏幕宽),你能看到的内容只是胶片中间的一部分(1× 屏幕宽)。

相机移动时,你**滚动胶片**(移动胶片位置),看到的内容自然滑动。胶片本身不重画,只是窗口移动。

当滚到胶片边缘,你**续一段新胶片**(曝光新内容)——这是「边缘重新生成」。

游戏里的 GroundBuffer 就是这个胶片——一块大画布,相机在画布上滑动。

### 严谨原理

#### 2.1 GroundBuffer 数据结构

```rust
struct GroundBuffer {
    pixels: Vec<u32>,        // 像素数据
    width: usize,
    height: usize,
    world_offset: Vec2,      // buffer 左上角对应的世界坐标
}
```

buffer 比 screen 大,比如 `width = screen_width + 2 * MARGIN`,`height = screen_height + 2 * MARGIN`。MARGIN 决定相机能移动多少才需要重新生成。

#### 2.2 渲染流程

```rust
fn render(world: &World, ground_buf: &GroundBuffer, framebuffer: &mut Framebuffer) {
    // 1. 算相机在 buffer 内的偏移
    let cam_in_buf = world.camera.pos.sub(ground_buf.world_offset);

    // 2. 从 buffer blit 屏幕大小的区域到 framebuffer
    blit_region(
        framebuffer,
        ground_buf,
        src_x = cam_in_buf.x as usize,
        src_y = cam_in_buf.y as usize,
        width = SCREEN_WIDTH,
        height = SCREEN_HEIGHT,
    );
}
```

blit 是 memcpy——非常快。每帧 ~5ms,稳定。

#### 2.3 相机移动时的更新

```rust
fn update_ground_buffer(world: &World, ground_buf: &mut GroundBuffer, cache: &mut TileCache) {
    // 算相机在 buffer 内的位置
    let cam_in_buf = world.camera.pos.sub(ground_buf.world_offset);

    // 检查是否接近边缘(MARGIN = 100 像素)
    const MARGIN: f32 = 100.0;
    let need_recenter = cam_in_buf.x < MARGIN
        || cam_in_buf.y < MARGIN
        || cam_in_buf.x + SCREEN_WIDTH as f32 > ground_buf.width as f32 - MARGIN
        || cam_in_buf.y + SCREEN_HEIGHT as f32 > ground_buf.height as f32 - MARGIN;

    if need_recenter {
        recenter_buffer(world, ground_buf, cache);
    }
}

fn recenter_buffer(world: &World, buf: &mut GroundBuffer, cache: &mut TileCache) {
    // 新的世界偏移(把 buffer 居中于相机)
    let new_offset = Vec2::new(
        world.camera.pos.x - buf.width as f32 / 2.0,
        world.camera.pos.y - buf.height as f32 / 2.0,
    );

    // 1. 把 buffer 内的旧内容平移(如果还有重叠)
    let dx = new_offset.x - buf.world_offset.x;
    let dy = new_offset.y - buf.world_offset.y;
    if dx.abs() < buf.width as f32 && dy.abs() < buf.height as f32 {
        shift_buffer(buf, dx as isize, dy as isize);
    }

    buf.world_offset = new_offset;

    // 2. 重新生成边缘区域(新出现的 tile)
    let tiles_x = buf.width as f32 / TILE_SIZE as f32;
    let tiles_y = buf.height as f32 / TILE_SIZE as f32;
    for ty in 0..tiles_y as i32 {
        for tx in 0..tiles_x as i32 {
            let world_tx = (buf.world_offset.x / TILE_SIZE as f32) as i32 + tx;
            let world_ty = (buf.world_offset.y / TILE_SIZE as f32) as i32 + ty;
            // 如果这个位置是新出现的(不在旧 buffer 内),blit 它
            if !was_in_old_buffer(buf, world_tx, world_ty) {
                let bmp = cache.get_or_composite(world_tx, world_ty);
                blit_to_buffer(buf, tx * TILE_SIZE, ty * TILE_SIZE, bmp);
            }
        }
    }
}
```

recenter 不常发生——只有相机移动到 buffer 边缘时触发。平均下来每帧 < 1ms。

#### 2.4 shift_buffer(memcpy 平移)

```rust
fn shift_buffer(buf: &mut GroundBuffer, dx: isize, dy: isize) {
    // 把 buffer 内的像素整体平移 (dx, dy)
    // 这是 memcpy 操作
    if dx == 0 && dy == 0 { return; }

    let w = buf.width;
    let h = buf.height;
    let mut new_pixels = vec![0u32; w * h];

    for y in 0..h {
        for x in 0..w {
            let src_x = x as isize - dx;
            let src_y = y as isize - dy;
            if src_x >= 0 && src_x < w as isize && src_y >= 0 && src_y < h as isize {
                new_pixels[y * w + x] = buf.pixels[src_y as usize * w + src_x as usize];
            }
            // 否则保持 0(稍后 blit 新内容)
        }
    }
    buf.pixels = new_pixels;
}
```

这是 O(N) memcpy,但 N 是 buffer 大小(几百万像素),仍然快(memcpy 是硬件加速的)。

#### 2.5 性能对比

| 方案 | blit 量/帧 | 时间/帧 |
|---|---|---|
| 直接 blit 1000 tile | 400 万像素 | ~10ms |
| GroundBuffer + 缓存 | 1 屏幕像素 memcpy | ~3ms |
| GroundBuffer + recenter 帧 | + 边缘 tile | ~6ms(峰值)|

平均下来 60 FPS 稳定。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

滚动 buffer 是游戏开发的经典技术:

- **2D 卷轴游戏**(超级马里奥、魂斗罗):背景缓冲跟着相机走。
- **RTS**(星际争霸、AOE):大地图,相机滚动。
- **Minecraft**:chunk 加载,buffer 是每个 chunk 一块。
- **Open world**(GTA、塞尔达 BOTW):超大世界,流式加载,buffer 分块管理。

#### 卷轴优化历史

- **1980s NES**:硬件 scrolling(PPU 支持),游戏代码不参与。
- **1990s**:PC 游戏用软件 scrolling,buffer 技术成熟。
- **2000s**:GPU 普及,scrolling 用 texture streaming。
- **2010s+**:超大世界用 chunked streaming,buffer 概念演化为 chunk。

### 3.2 · 🎨 图形学视角

GPU 上的「buffer」是 **texture**。GPU 的「scrolling」是 texture coordinates 偏移——fragment shader 自动处理。

```glsl
// Fragment shader:scroll ground texture
uniform vec2 camera_offset;
uniform sampler2D ground_texture;

void main() {
    vec2 uv = (gl_FragCoord.xy + camera_offset) / textureSize;
    vec4 color = texture(ground_texture, uv);
    // ...
}
```

GPU 的「scrolling」几乎免费——只是 uniform 变量。但 texture streaming(超大世界)仍需要复杂的 chunk 管理。

#### Texture atlas

多个小 tile 拼成一张大 texture(atlas),GPU 一次绑定,反复采样。比每次切换 texture 快得多。

#### Mipmap + scrolling

远处 tile 用低 mipmap,近处用高 mipmap。scrolling 时 mipmap 选择跟随相机距离。Day 109 的分辨率无关是另一种相关技术。

### 3.3 · 🐧 Linux 系统编程视角

滚动 buffer 概念在 Linux 里有几个对应:

- **terminal 滚动**:终端的 scrollback buffer,和你滚动 GroundBuffer 一样。
- **tmux pane**:每个 pane 有自己的 buffer,滚动时部分更新。
- **X11 / Wayland damage tracking**:窗口部分更新,只重画变化区域。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写 GroundBuffer

```rust
pub struct GroundBuffer {
    pub pixels: Vec<u32>,
    pub width: usize,
    pub height: usize,
    pub world_offset_x: f32,
    pub world_offset_y: f32,
}

impl GroundBuffer {
    pub fn new(width: usize, height: usize) -> Self {
        Self {
            pixels: vec![0; width * height],
            width,
            height,
            world_offset_x: 0.0,
            world_offset_y: 0.0,
        }
    }

    pub fn shift(&mut self, dx: isize, dy: isize) {
        if dx == 0 && dy == 0 { return; }
        let w = self.width;
        let h = self.height;
        let mut new_pixels = vec![0u32; w * h];
        for y in 0..h {
            // 用 memcpy 加速整行复制
            let src_y = y as isize - dy;
            if src_y < 0 || src_y >= h as isize { continue; }
            let src_x_start = (0 - dx).max(0) as usize;
            let src_x_end = ((w as isize - dx).min(w as isize)).max(0) as usize;
            let dst_x_start = (src_x_start as isize + dx) as usize;
            let count = src_x_end - src_x_start;
            if count > 0 {
                let src_base = src_y as usize * w + src_x_start;
                let dst_base = y * w + dst_x_start;
                new_pixels[dst_base..dst_base + count]
                    .copy_from_slice(&self.pixels[src_base..src_base + count]);
            }
        }
        self.pixels = new_pixels;
    }
}
```

`copy_from_slice` 是 Rust 的 memcpy——快。

#### Rust 的所有权:buffer 不能借用给两个地方

```rust
// 错误:同时借用 buf 给 shift 和 recenter
fn update(buf: &mut GroundBuffer) {
    buf.shift(dx, dy);          // 借用结束
    recenter(buf);              // 再借用,OK
}

// 错误:在 shift 内部又借用 buf
fn shift(&mut self, dx: isize, dy: isize) {
    let new_pixels = ...;
    self.pixels = new_pixels;  // OK,只有 self.pixels,不冲突
}
```

Rust 借用规则让你写安全的代码,但有时候需要绕——用 `std::mem::take` 或 `std::mem::swap`。

#### Rust 的 vec! vs Box<[_]>

```rust
let v: Vec<u32> = vec![0; 1920 * 1080];  // 堆分配
let b: Box<[u32]> = vec![0; 1920 * 1080].into_boxed_slice();  // 固定大小,无 realloc
```

固定大小的 buffer 用 `Box<[u32]>`,避免 Vec 的容量管理开销。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 GroundBuffer 比屏幕大?

**参考解答**:**容忍相机移动**。

如果 buffer 和屏幕一样大,相机移动 1 像素就需要重新生成所有 tile(因为 buffer 完全在屏幕外)。慢。

buffer 比屏幕大 2 倍时,相机在 buffer 内有 1× 屏幕的移动空间——只有相机接近 buffer 边缘时才 recenter。这样大部分帧不需要 recenter,只是 blit 不同区域。

MARGIN 是「相机距 buffer 边缘的安全距离」,通常 100-200 像素。

### Lv2 · 动手实践

**题**:实现 GroundBuffer 和 shift。模拟相机从 (0, 0) 移动到 (500, 0),每 50 像素打印 buffer_offset 和是否触发 recenter。

完成标准:相机在 buffer 内移动时不 recenter,接近边缘时 recenter。

**参考解答**:

```rust
struct GroundBuffer {
    pixels: Vec<u32>,
    width: usize,
    height: usize,
    world_offset_x: f32,
    world_offset_y: f32,
}

const SCREEN_W: usize = 1280;
const SCREEN_H: usize = 720;
const BUFFER_MARGIN: f32 = 200.0;

impl GroundBuffer {
    fn new() -> Self {
        let w = SCREEN_W + 2 * BUFFER_MARGIN as usize;
        let h = SCREEN_H + 2 * BUFFER_MARGIN as usize;
        Self {
            pixels: vec![0; w * h],
            width: w,
            height: h,
            world_offset_x: 0.0,
            world_offset_y: 0.0,
        }
    }

    fn needs_recenter(&self, cam_x: f32, cam_y: f32) -> bool {
        let in_buf_x = cam_x - self.world_offset_x;
        let in_buf_y = cam_y - self.world_offset_y;
        in_buf_x < BUFFER_MARGIN
            || in_buf_y < BUFFER_MARGIN
            || in_buf_x + SCREEN_W as f32 > self.width as f32 - BUFFER_MARGIN
            || in_buf_y + SCREEN_H as f32 > self.height as f32 - BUFFER_MARGIN
    }

    fn recenter(&mut self, cam_x: f32, cam_y: f32) {
        let new_offset_x = cam_x - self.width as f32 / 2.0;
        let new_offset_y = cam_y - self.height as f32 / 2.0;
        let dx = (new_offset_x - self.world_offset_x) as isize;
        let dy = (new_offset_y - self.world_offset_y) as isize;
        // shift
        let w = self.width;
        let h = self.height;
        let mut new_pixels = vec![0u32; w * h];
        for y in 0..h {
            let src_y = y as isize - dy;
            if src_y < 0 || src_y >= h as isize { continue; }
            for x in 0..w {
                let src_x = x as isize - dx;
                if src_x >= 0 && src_x < w as isize {
                    new_pixels[y * w + x] = self.pixels[src_y as usize * w + src_x as usize];
                }
            }
        }
        self.pixels = new_pixels;
        self.world_offset_x = new_offset_x;
        self.world_offset_y = new_offset_y;
    }
}

fn main() {
    let mut buf = GroundBuffer::new();
    buf.recenter(0.0, 0.0);  // 初始

    for cam_x in (0..=500).step_by(50) {
        let cam_x = cam_x as f32;
        let need = buf.needs_recenter(cam_x, 0.0);
        println!("相机 x={:4.0}: offset=({:6.1}, {:6.1}) need_recenter={}",
            cam_x, buf.world_offset_x, buf.world_offset_y, need);
        if need {
            buf.recenter(cam_x, 0.0);
        }
    }
}
```

## 8 · Rust / Arch 落地代码

```rust
pub struct GroundBuffer {
    pub pixels: Vec<u32>,
    pub width: usize,
    pub height: usize,
    pub world_offset_x: f32,
    pub world_offset_y: f32,
}

const SCREEN_W: usize = 1280;
const SCREEN_H: usize = 720;
const MARGIN: usize = 200;

impl GroundBuffer {
    pub fn new() -> Self {
        let w = SCREEN_W + 2 * MARGIN;
        let h = SCREEN_H + 2 * MARGIN;
        Self {
            pixels: vec![0; w * h],
            width: w,
            height: h,
            world_offset_x: 0.0,
            world_offset_y: 0.0,
        }
    }

    pub fn needs_recenter(&self, cam_x: f32, cam_y: f32) -> bool {
        let in_buf_x = cam_x - self.world_offset_x;
        let in_buf_y = cam_y - self.world_offset_y;
        in_buf_x < MARGIN as f32
            || in_buf_y < MARGIN as f32
            || in_buf_x + SCREEN_W as f32 > self.width as f32 - MARGIN as f32
            || in_buf_y + SCREEN_H as f32 > self.height as f32 - MARGIN as f32
    }

    pub fn recenter(&mut self, cam_x: f32, cam_y: f32) {
        let new_ox = cam_x - self.width as f32 / 2.0;
        let new_oy = cam_y - self.height as f32 / 2.0;
        let dx = (new_ox - self.world_offset_x) as isize;
        let dy = (new_oy - self.world_offset_y) as isize;

        if dx != 0 || dy != 0 {
            let w = self.width;
            let h = self.height;
            let mut new_pixels = vec![0u32; w * h];

            // 用 copy_from_slice 加速行复制
            for y in 0..h {
                let src_y = y as isize - dy;
                if src_y < 0 || src_y >= h as isize { continue; }

                let src_x_start = (0isize - dx).max(0).min(w as isize) as usize;
                let src_x_end = ((w as isize - dx).max(0).min(w as isize)) as usize;
                if src_x_start >= src_x_end { continue; }

                let dst_x_start = (src_x_start as isize + dx) as usize;
                let count = src_x_end - src_x_start;

                let src_base = src_y as usize * w + src_x_start;
                let dst_base = y * w + dst_x_start;
                new_pixels[dst_base..dst_base + count]
                    .copy_from_slice(&self.pixels[src_base..src_base + count]);
            }
            self.pixels = new_pixels;
        }

        self.world_offset_x = new_ox;
        self.world_offset_y = new_oy;
    }
}

fn main() {
    let mut buf = GroundBuffer::new();
    println!("Buffer 大小: {}x{}", buf.width, buf.height);
    println!("初始 offset: ({}, {})", buf.world_offset_x, buf.world_offset_y);

    buf.recenter(0.0, 0.0);
    println!("recenter(0,0) 后 offset: ({}, {})", buf.world_offset_x, buf.world_offset_y);

    let mut recenter_count = 0;
    let mut max_in_buf = 0.0f32;
    for step in 0..1000 {
        let cam_x = step as f32 * 5.0;  // 相机每帧移动 5 像素
        let cam_y = 0.0;

        let in_buf_x = cam_x - buf.world_offset_x;
        max_in_buf = max_in_buf.max(in_buf_x);

        if buf.needs_recenter(cam_x, cam_y) {
            buf.recenter(cam_x, cam_y);
            recenter_count += 1;
        }
    }

    println!("\n相机移动 5000 像素(1000 帧):");
    println!("  recenter 次数: {}", recenter_count);
    println!("  最近一次 offset: ({}, {})", buf.world_offset_x, buf.world_offset_y);
    println!("  (大部分帧不需要 recenter,只是 blit 不同区域)");
}
```

**预期输出**(大概):
```
Buffer 大小: 1680x1120
初始 offset: (0, 0)
recenter(0,0) 后 offset: (-840, -560)

相机移动 5000 像素(1000 帧):
  recenter 次数: 5
  最近一次 offset: (3160, -560)
  (大部分帧不需要 recenter,只是 blit 不同区域)
```

1000 帧只 recenter 5 次,平均 995 帧「免费」(只 blit)。
