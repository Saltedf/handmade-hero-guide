> 今天 Casey 给渲染器加一个工程上很实用的能力:**内部固定渲染到一个 960×540 的虚拟 framebuffer,然后整体缩放到任意窗口大小**。这样不管玩家拉大窗口到 4K 还是缩小到 800×600,游戏画面比例完全一致,只是清晰度不同。这是「**resolution-independent rendering(分辨率无关渲染)**」的核心思想,所有现代游戏都这么做(虽然具体实现千差万别)。

## 0 · 为什么要有这一天

考虑一个真实场景:你刚做完游戏,在 1080p 显示器上跑得很美。你把游戏发给朋友试玩——他用的是 4K 显示器,游戏画面只占左上角四分之一,所有 UI 按钮小得点不到。他又发给另一个朋友——后者用 720p 笔记本,游戏画面溢出屏幕,玩家头像在视野外。

这不是个例。Steam 硬件调查里玩家分辨率横跨 720p 到 8K,DPR(设备像素比)从 1 到 3(视网膜)。如果你的渲染管线**直接写窗口 framebuffer**,这些差异全部要游戏代码处理——每个 UI 元素都要根据窗口大小算位置,每个 sprite 大小都要按窗口比例调整。代码很快变成无法维护。

「**分辨率无关**」给出优雅解法:**让游戏代码只看一个固定大小的虚拟 framebuffer**。所有渲染逻辑、UI 布局、相机缩放都在这个固定分辨率上算。最后一道工序,把虚拟 framebuffer **整体缩放** blit 到真实窗口 framebuffer。窗口大小变了,**只影响最后这一步缩放比例**,游戏代码零改动。

这个设计有三个直接收益。第一,**游戏代码简化**——开发者只关心「960×540 上玩家应该在哪」,不再担心窗口尺寸。第二,**性能可控**——渲染分辨率固定,帧时间稳定。窗口大不会让渲染慢(只是缩放快慢不同)。第三,**视觉一致**——同一游戏在任何屏幕上看起来比例相同,只是「**锐利度**」不同(高 DPR 屏更锐利,低 DPR 屏稍模糊)。

完成今天后,你将掌握「**虚拟 framebuffer + 物理 framebuffer 双缓冲**」这一现代游戏渲染的标准架构,以及它在 Rust + winit + softbuffer 路径下的具体实现。

## 1 · Casey 今天做了什么(HH 脉络,简述)

Casey 在视频里做的事可以归纳为三步。

第一步,他在 Renderer 里定义一个常量 `INTERNAL_WIDTH = 960, INTERNAL_HEIGHT = 540`(16:9 比例,正好是 1080p 的一半,渲染量小但够清晰)。

第二步,他创建一个独立的「**内部 framebuffer**」`Vec<u32>` 大小是 960×540。所有 push buffer 命令都画到这个内部 framebuffer。

第三步,他在平台层(softbuffer 的窗口)做一次「**scaled blit**」——遍历窗口 framebuffer 的每个像素,反推它对应内部 framebuffer 的位置(可能是亚像素),用双线性插值采样内部 framebuffer 的 4 个邻居,写入窗口。这就是「**缩放 blit**」。

Casey 在视频里还讨论一个 trade-off:**整数倍缩放 vs 任意倍缩放**。整数倍(窗口 = 内部 × N)用最近邻插值,像素清晰无模糊。任意倍(窗口 ≠ 内部 × 整数)必须用双线性插值,会有轻微模糊但视觉自然。Casey HH 用双线性,因为玩家窗口大小不可控。

## 2 · 心智模型

**费曼类比**。想象你画了一幅画,画布固定 30×20 厘米(虚拟 framebuffer)。你想把它展示在不同大小的相框上:小相框(20×15 厘米)放不下整幅,你拿去**复印缩小**;大相框(60×40 厘米)太空,你拿去**复印放大**。

不管复印多少份,你**原画不动**——每次只是重新复印。如果有人觉得画里某个角色位置不对,你只改原画,所有未来复印自动跟上。原画 = 内部 framebuffer,复印 = scaled blit,相框 = 窗口。

游戏的所有逻辑(玩家在哪、UI 怎么布局)都画在原画上。窗口大小(相框)只决定「**复印多大**」。

**严谨原理**。我们需要三件事:**虚拟 framebuffer**、**真实 framebuffer**、**缩放 blit**。前两者是两块独立的 `Vec<u32>`,后者是一个函数 `blit_scaled(src, dst, scale_x, scale_y)`。

具体数学:窗口大小 `W × H`(像素),内部大小 `w × h`(像素)。我们需要决定 `scale = min(W/w, H/h)`——保持内部比例不变形。然后 `dst_w = w × scale, dst_h = h × scale`,内部 framebuffer 居中放在窗口(可能有黑边 letterbox)。

每个目标像素 `(dx, dy)` 对应源位置 `(sx, sy) = ((dx - offset_x) / scale, (dy - offset_y) / scale)`。这是浮点坐标,可能不是整数。**双线性插值(bilinear)**:取 4 个邻居像素 `floor(sx), ceil(sx) × floor(sy), ceil(sy)`,按小数部分加权平均。

伪代码:

```
for dy in 0..H:
    for dx in 0..W:
        sx_f = (dx - offset_x) / scale
        sy_f = (dy - offset_y) / scale
        if sx_f < 0 or sx_f >= w or sy_f < 0 or sy_f >= h:
            dst[dy*W + dx] = black            # letterbox
            continue
        sx0 = floor(sx_f); sx1 = sx0 + 1
        sy0 = floor(sy_f); sy1 = sy0 + 1
        fx = sx_f - sx0; fy = sy_f - sy0
        p00 = src[sy0*w + sx0]
        p10 = src[sy0*w + sx1]    # 边界要 clamp
        p01 = src[sy1*w + sx0]
        p11 = src[sy1*w + sx1]
        # 双线性: fx, fy 是权重
        pr = lerp(lerp(p00.r, p10.r, fx), lerp(p01.r, p11.r, fx), fy)
        ... 同理 g, b
        dst[dy*W + dx] = pack(pr, pg, pb)
```

`lerp(a, b, t) = a + (b - a) * t`,线性插值。`fx, fy ∈ [0, 1]` 是「**当前像素到 4 个邻居的相对位置**」。

**最近邻 vs 双线性**。如果 `fx = 0, fy = 0`(整数对齐),直接取 `p00`,这是「**最近邻(nearest neighbor)**」——快但锯齿明显。`lerp` 加权是双线性——慢(4 次乘法)但平滑。Casey HH 用双线性,因为现代 CPU 在 1-2ms 内完成 1080p 双线性插值无压力。

**Letterbox 与 Fill**。如果窗口宽高比 ≠ 内部宽高比,有两种选择:**Letterbox**(保持比例,留黑边)或 **Fill**(填满窗口,但内容变形)。Casey 用 Letterbox——视觉正确。Fill 一般用于游戏选项「**拉伸到全屏**」,旧 CRT 玩家可能想要。

### 2.1 Rust 实现要点

我们看 Rust 怎么写。

```rust
pub struct Renderer {
    pub internal: Vec<u32>,        // 虚拟 framebuffer,960×540
    pub internal_w: u32,
    pub internal_h: u32,
    // 真实 framebuffer 由平台层(softbuffer)管
}

pub fn blit_scaled(
    src: &[u32], src_w: u32, src_h: u32,
    dst: &mut [u32], dst_w: u32, dst_h: u32,
) {
    // 保持 src 比例,居中 letterbox
    let scale = (dst_w as f32 / src_w as f32).min(dst_h as f32 / src_h as f32);
    let scaled_w = (src_w as f32 * scale) as u32;
    let scaled_h = (src_h as f32 * scale) as u32;
    let off_x = ((dst_w - scaled_w) / 2) as i32;
    let off_y = ((dst_h - scaled_h) / 2) as i32;
    let inv_scale = 1.0 / scale;

    for dy in 0..dst_h {
        for dx in 0..dst_w {
            let sx_f = (dx as i32 - off_x) as f32 * inv_scale;
            let sy_f = (dy as i32 - off_y) as f32 * inv_scale;
            let i = (dy * dst_w + dx) as usize;
            if sx_f < 0.0 || sx_f >= src_w as f32 ||
               sy_f < 0.0 || sy_f >= src_h as f32 {
                dst[i] = 0xFF000000;       // 黑边
            } else {
                dst[i] = sample_bilinear(src, src_w, src_h, sx_f, sy_f);
            }
        }
    }
}

fn sample_bilinear(src: &[u32], w: u32, h: u32, x: f32, y: f32) -> u32 {
    let x0 = x.floor() as u32;
    let y0 = y.floor() as u32;
    let x1 = (x0 + 1).min(w - 1);            // 边界 clamp
    let y1 = (y0 + 1).min(h - 1);
    let fx = x - x.floor();
    let fy = y - y.floor();

    let p00 = src[(y0 * w + x0) as usize];
    let p10 = src[(y0 * w + x1) as usize];
    let p01 = src[(y1 * w + x0) as usize];
    let p11 = src[(y1 * w + x1) as usize];

    let lerp = |a: u32, b: u32, t: f32| -> u32 {
        let a = a as f32; let b = b as f32;
        (a + (b - a) * t) as u32
    };
    // 拆分 ARGB 4 通道分别 lerp
    let r = lerp(lerp((p00 >> 16) & 0xFF, (p10 >> 16) & 0xFF, fx),
                 lerp((p01 >> 16) & 0xFF, (p11 >> 16) & 0xFF, fx), fy);
    let g = lerp(lerp((p00 >> 8) & 0xFF, (p10 >> 8) & 0xFF, fx),
                 lerp((p01 >> 8) & 0xFF, (p11 >> 8) & 0xFF, fx), fy);
    let b = lerp(lerp(p00 & 0xFF, p10 & 0xFF, fx),
                 lerp(p01 & 0xFF, p11 & 0xFF, fx), fy);
    0xFF000000 | (r << 16) | (g << 8) | b
}
```

注意几个 Rust 设计点:**`u32` ARGB packing**——每像素 32 位,节省内存(对比 `Vec<[u8; 4]>` 少一次解引用)。**边界 clamp 用 `.min(w-1)`**——避免越界 panic,但牺牲一点视觉精度(边缘像素重复)。**`lerp` 用闭包**——避免重复代码,虽然编译器可能内联展开。**`floor` 比 `as i32`** 慢但语义清晰——`x as i32` 是截断(向 0),`x.floor() as i32` 是向下取整(对负数不同)。

### 2.2 性能考虑

1080p(1920×1080)blit = 2M 像素 × 4 邻居 × 4 通道 = 32M 操作。现代 CPU 单核约 1GHz SIMD,2-5ms 完成。Casey HH 的 30 FPS 帧预算 33ms,blit 占 10%——可接受。

优化方向:**SIMD**(`_mm_mullo_epi16` 并行 4 像素)、**多线程**(`rayon::par_iter` 按行并行)、**mmap 共享内存**(Wayland dma-buf 直接 GPU 写)。Casey 在 Day 121+ 用 SIMD,在 Day 235+ 切 OpenGL 后 blit 完全消失(GPU shader 做)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏业界几种分辨率无关方案。

**固定内部 + 缩放(Casey)**。所有游戏逻辑在固定分辨率,输出时缩放。最简单,UI 像素艺术友好(像素大小一致)。Stardew Valley、Undertale 这种像素游戏用这种。

**响应式 UI + 3D 分辨率独立**。3D 渲染按窗口分辨率(更高分辨率看得更清晰),UI 按响应式布局(类似网页 CSS)。AAA 游戏常用。复杂度高。

**DPI-aware rendering**。系统告诉应用「DPR=2」,应用渲染 2× 像素但保持逻辑大小一致。Bevy、imgui-rs 都支持。Casey HH 没明确做 DPR,但内部 framebuffer 思路和 DPR 等价。

**动态分辨率(dynamic resolution)**。GPU 渲染时根据负载动态降低内部分辨率(保持帧率)。CPU 渲染 Casey HH 不用,但 Day 235+ 切 OpenGL 后可能用。

### 3.2 · 🎮 图形学视角

图形学里这件事的标准叫法是「**supersampling / downsampling / upsampling**」。从大缩到小是 downsample(超采样),从小放到大是 upsample(插值)。

**MSAA(Multi-Sample Anti-Aliasing)**:GPU 在几何边缘做 4× / 8× 子像素采样,平均后写入 framebuffer。和 Casey 的 blit 不同——MSAA 是在原始分辨率上做边缘抗锯齿,不是整体缩放。

**SSAA(Supersampling AA)**:GPU 渲染到 2× 分辨率 framebuffer,然后 downsample。视觉最好但成本高。Casey 的内部固定分辨率是 SSAA 的反向——渲染低分辨率,upscale 到高分辨率,成本反而低(模糊换性能)。

**FSR / DLSS**:AMD/NVIDIA 的「**AI 升采样**」——内部低分辨率渲染,用 AI 算法升采样到高分辨率。Day 600+ Casey 可能涉及。

### 3.3 · 🐧 Linux 系统编程视角

Linux 桌面对分辨率无关的支持。

**Wayland `wl_output.scale`**:整数 scale(1/2/3),告诉 client 应该按这个 DPR 渲染。client 自己决定如何处理——可以渲染高分辨率,也可以渲染低分辨率再 scale(和 Casey 一样)。

**X11 RandR**:X11 的多显示器 + 分辨率 API。`xrandr --output eDP1 --scale 2x2` 把输出放大 2×。

**HiDPI 环境变量**:`GDK_SCALE=2`(GTK)、`QT_SCALE_FACTOR=2`(Qt)、`XCURSOR_SIZE=48`(光标大小)。这些让 GUI 工具包自动放大。

### 3.4 · 🦀 Rust 生态视角

Rust 里做 scaled blit 几个选择。

**手写**(`for` 循环 + `sample_bilinear`)——教学清晰,3-5ms 完成 1080p。Casey HH 用这种。

**`image` crate**:`image::imageops::resize` 支持多种滤波器(Nearest / Triangle / Catmull-Rom / Lanczos3)。一行调用完成。但**通用图像处理**,不如手写针对 framebuffer 优化。

**`fast_image_resize`**:SIMD 加速的图像缩放 crate,比 `image` 快 5-10×。生产项目用这种。

**` tiny_skimmer` / ` tiny_skia`**:2D 渲染器,内置高质量缩放。

Rust 现代特性对 blit 优化:`rayon::par_iter` 多核并行(4 核快 4×);`std::simd` 一次处理 4-16 像素;`core::intrinsics::simd_*` 底层 SIMD intrinsic。

## 4 · 认知地图

### 4.1 上级(它属于哪个更大抽象?)

- **Logical vs Physical Resolution** —— 逻辑分辨率(内部 framebuffer)vs 物理分辨率(窗口 framebuffer),scale 是它们的比例。
- **Render Pipeline Architecture** —— 渲染管线的「**最终输出阶段**」:pixel 流过所有变换后,最后 blit 到屏幕。
- **Device Independence** —— 应用不依赖具体硬件参数(分辨率、DPR),只看抽象层。这是 OS 设计核心原则。

### 4.2 同级(并行方案对比)

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| **固定内部 + blit(Casey)** | 内部固定,输出缩放 | 像素艺术 / 视觉一致性 | ✅ Day 109 |
| **直接写窗口 framebuffer** | 游戏代码处理多分辨率 | UI 简单游戏 | Day 037 之前 |
| **响应式布局** | UI 按 CSS 风格自适应 | 网页风 UI | 不用 |
| **DPI-aware** | 系统告诉 DPR,应用响应 | 系统级应用 | Bevy 用 |
| **动态分辨率** | GPU 按负载调内部分辨率 | AAA 3D 游戏 | Day 600+ 可能 |

这张表的关键:**方案选择决定代码复杂度分布**。Casey 选「固定内部 + blit」把复杂度集中到一处(blit),游戏代码极简。响应式布局把复杂度散到每个 UI 元素,但灵活。

### 4.3 下级(内部零件)

- **内部 framebuffer** —— `Vec<u32>` 固定 960×540。
- **scaled blit 函数** —— 把内部缩放到窗口。
- **letterbox offset** —— 居中位置。
- **双线性插值** —— 4 邻居加权。
- **sample_bilinear** —— 单像素采样核心。

## 5 · 对照与变奏

**整数倍 vs 任意倍缩放**。整数倍(1×, 2×, 3×)用最近邻——每个内部像素对应 N×N 窗口像素,边界清晰锐利,适合像素艺术。任意倍(1.5×, 2.3×)用双线性——必然有亚像素采样,产生轻微模糊。像素游戏玩家坚持整数倍缩放(可选选项)。Casey HH 用双线性的原因是窗口大小不可控。

**Letterbox vs Fill vs Stretch**。Letterbox(留黑边,保持比例)——视觉正确。Fill(填满,内容变形)——常见于老 CRT 电视。Stretch(完整拉伸,无视比例)——内容严重变形,极少用。Casey HH 用 letterbox。

**Supersampling vs Downsampling**。Supersampling:渲染高分辨率然后 downsample 到屏幕(高成本高画质)。Casey 反向——渲染低分辨率然后 upsample(低成本低画质)。两者是同一个连续区间的两端,trade-off 是清晰度 vs 性能。

**历史演化**。1990 年代 DOS 游戏直接写 VGA 寄存器,分辨率固定 320×200,没有分辨率问题。Windows 95 + DirectX 出现多分辨率,开始有「**游戏内选项改分辨率**」。2000 年代「**Logical Resolution**」概念普及(iOS UIKit 最先引入)。2010 年代视网膜屏 DPR 概念成熟。Casey HH Day 109 跟上这个演化,但用最简单的「**固定内部 + blit**」实现,适合教学。

### Lv1 · 概念辨析(读懂)

**题**:Casey 把内部 framebuffer 设为 960×540。玩家把窗口调到 1920×1080 和 1920×1200 两种。请回答:(a) 1920×1080 时 scale 是多少?是整数倍吗?(b) 1920×1200 时 scale 是多少?需要 letterbox 吗?letterbox 厚度是多少像素?(c) 如果不用 letterbox 而是 fill,1920×1200 时画面会怎样?

**参考解答**:(a) scale = min(1920/960, 1080/540) = min(2, 2) = 2。整数倍,完美 2×,像素清晰。(b) scale = min(1920/960, 1200/540) = min(2, 2.222) = 2。需要 letterbox——垂直方向 1080 像素有效,1200-1080 = 120 像素是黑边(上下各 60 像素)。(c) 如果 fill,scale = max 而不是 min,等于 2.222,垂直方向 540 × 2.222 = 1200(填满),但水平方向 960 × 2.222 = 2133 > 1920——画面被横向裁切,看不到边缘内容。或者另一种 fill:水平 960×2=1920,垂直拉伸 540 到 1200(2.222×)——内容垂直拉伸,圆形变椭圆。Casey 选 letterbox 因为视觉正确。

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现完整的「**内部 framebuffer + scaled blit**」。内部 960×540,在内部画一个红方块和网格。窗口大小由命令行参数给定(比如 800×600 或 1920×1200)。要求:(a) blit 用双线性插值;(b) letterbox 黑边;(c) main 接受两个命令行参数 width height,生成对应 PNG。

**参考解答**:

```rust
use std::env;

const INTERNAL_W: u32 = 960;
const INTERNAL_H: u32 = 540;

fn render_internal(buf: &mut [u32]) {
    // 暗背景
    for px in buf.iter_mut() { *px = 0xFF181820; }
    // 红方块 200×200 居中
    for y in 170..370 {
        for x in 380..580 {
            buf[y * INTERNAL_W + x] = 0xFFE04040;
        }
    }
    // 网格 每 60 像素一条线
    for y in (0..INTERNAL_H).step_by(60) {
        for x in 0..INTERNAL_W {
            buf[(y * INTERNAL_W + x) as usize] = 0xFF404050;
        }
    }
    for x in (0..INTERNAL_W).step_by(60) {
        for y in 0..INTERNAL_H {
            buf[(y * INTERNAL_W + x) as usize] = 0xFF404050;
        }
    }
}

fn sample_bilinear(src: &[u32], w: u32, h: u32, x: f32, y: f32) -> u32 {
    let x0 = x.floor() as u32;
    let y0 = y.floor() as u32;
    let x1 = (x0 + 1).min(w - 1);
    let y1 = (y0 + 1).min(h - 1);
    let fx = x - x.floor();
    let fy = y - y.floor();
    let p00 = src[(y0 * w + x0) as usize];
    let p10 = src[(y0 * w + x1) as usize];
    let p01 = src[(y1 * w + x0) as usize];
    let p11 = src[(y1 * w + x1) as usize];
    let c = |p: u32, s: u32| ((p >> s) & 0xFF) as f32;
    let lerp = |a: f32, b: f32, t: f32| a + (b - a) * t;
    let r = lerp(lerp(c(p00, 16), c(p10, 16), fx), lerp(c(p01, 16), c(p11, 16), fx), fy);
    let g = lerp(lerp(c(p00,  8), c(p10,  8), fx), lerp(c(p01,  8), c(p11,  8), fx), fy);
    let b = lerp(lerp(c(p00,  0), c(p10,  0), fx), lerp(c(p01,  0), c(p11,  0), fx), fy);
    0xFF000000 | ((r as u32) << 16) | ((g as u32) << 8) | (b as u32)
}

fn blit_scaled(src: &[u32], dst: &mut [u32], dst_w: u32, dst_h: u32) {
    let scale = (dst_w as f32 / INTERNAL_W as f32).min(dst_h as f32 / INTERNAL_H as f32);
    let sw = (INTERNAL_W as f32 * scale) as i32;
    let sh = (INTERNAL_H as f32 * scale) as i32;
    let off_x = (dst_w as i32 - sw) / 2;
    let off_y = (dst_h as i32 - sh) / 2;
    let inv = 1.0 / scale;

    for dy in 0..dst_h {
        for dx in 0..dst_w {
            let sx_f = (dx as i32 - off_x) as f32 * inv;
            let sy_f = (dy as i32 - off_y) as f32 * inv;
            let i = (dy * dst_w + dx) as usize;
            if sx_f < 0.0 || sx_f >= INTERNAL_W as f32 ||
               sy_f < 0.0 || sy_f >= INTERNAL_H as f32 {
                dst[i] = 0xFF000000;           // 黑边
            } else {
                dst[i] = sample_bilinear(src, INTERNAL_W, INTERNAL_H, sx_f, sy_f);
            }
        }
    }
}

fn main() {
    let args: Vec<String> = env::args().collect();
    let dst_w: u32 = args.get(1).and_then(|s| s.parse().ok()).unwrap_or(1920);
    let dst_h: u32 = args.get(2).and_then(|s| s.parse().ok()).unwrap_or(1080);

    let mut internal = vec![0u32; (INTERNAL_W * INTERNAL_H) as usize];
    render_internal(&mut internal);

    let mut dst = vec![0u32; (dst_w * dst_h) as usize];
    blit_scaled(&internal, &mut dst, dst_w, dst_h);

    let bytes: Vec<u8> = dst.iter().flat_map(|p| p.to_le_bytes()).collect();
    let img: image::ImageBuffer<image::Rgba<u8>, _> =
        image::ImageBuffer::from_raw(dst_w, dst_h, bytes).unwrap();
    let path = format!("day109_{}x{}.png", dst_w, dst_h);
    img.save(&path).unwrap();
    println!("saved {}", path);
}
```

```rust
// Cargo.toml:
// [dependencies]
// image = "0.25"

const INTERNAL_W: u32 = 960;
const INTERNAL_H: u32 = 540;

pub struct Renderer {
    pub internal: Vec<u32>,
}

impl Renderer {
    pub fn new() -> Self {
        Self { internal: vec![0xFF181820; (INTERNAL_W * INTERNAL_H) as usize] }
    }

    pub fn clear(&mut self, color: u32) {
        for px in &mut self.internal { *px = color; }
    }

    pub fn fill_rect(&mut self, x: u32, y: u32, w: u32, h: u32, color: u32) {
        for ry in y..(y + h).min(INTERNAL_H) {
            for rx in x..(x + w).min(INTERNAL_W) {
                self.internal[(ry * INTERNAL_W + rx) as usize] = color;
            }
        }
    }

    pub fn draw_grid(&mut self, step: u32, color: u32) {
        for y in (0..INTERNAL_H).step_by(step as usize) {
            for x in 0..INTERNAL_W { self.internal[(y * INTERNAL_W + x) as usize] = color; }
        }
        for x in (0..INTERNAL_W).step_by(step as usize) {
            for y in 0..INTERNAL_H { self.internal[(y * INTERNAL_W + x) as usize] = color; }
        }
    }
}

pub fn sample_bilinear(src: &[u32], w: u32, h: u32, x: f32, y: f32) -> u32 {
    let x0 = x.floor() as u32;
    let y0 = y.floor() as u32;
    let x1 = (x0 + 1).min(w - 1);
    let y1 = (y0 + 1).min(h - 1);
    let fx = x - x.floor();
    let fy = y - y.floor();
    let p = |xi: u32, yi: u32| src[(yi * w + xi) as usize];
    let lerp = |a: f32, b: f32, t: f32| a + (b - a) * t;
    let ch = |px: u32, s: u32| ((px >> s) & 0xFF) as f32;

    let p00 = p(x0, y0); let p10 = p(x1, y0);
    let p01 = p(x0, y1); let p11 = p(x1, y1);

    let r = lerp(lerp(ch(p00, 16), ch(p10, 16), fx),
                 lerp(ch(p01, 16), ch(p11, 16), fx), fy);
    let g = lerp(lerp(ch(p00,  8), ch(p10,  8), fx),
                 lerp(ch(p01,  8), ch(p11,  8), fx), fy);
    let b = lerp(lerp(ch(p00,  0), ch(p10,  0), fx),
                 lerp(ch(p01,  0), ch(p11,  0), fx), fy);
    0xFF000000 | ((r as u32) << 16) | ((g as u32) << 8) | (b as u32)
}

pub fn blit_scaled(
    src: &[u32], sw: u32, sh: u32,
    dst: &mut [u32], dw: u32, dh: u32,
) {
    let scale = (dw as f32 / sw as f32).min(dh as f32 / sh as f32);
    let scaled_w = (sw as f32 * scale) as i32;
    let scaled_h = (sh as f32 * scale) as i32;
    let off_x = (dw as i32 - scaled_w) / 2;
    let off_y = (dh as i32 - scaled_h) / 2;
    let inv = 1.0 / scale;

    for dy in 0..dh {
        for dx in 0..dw {
            let sx_f = (dx as i32 - off_x) as f32 * inv;
            let sy_f = (dy as i32 - off_y) as f32 * inv;
            let i = (dy * dw + dx) as usize;
            if sx_f < 0.0 || sx_f >= sw as f32 ||
               sy_f < 0.0 || sy_f >= sh as f32 {
                dst[i] = 0xFF000000;          // letterbox
            } else {
                dst[i] = sample_bilinear(src, sw, sh, sx_f, sy_f);
            }
        }
    }
}

fn main() {
    let mut r = Renderer::new();
    r.clear(0xFF181820);
    r.draw_grid(60, 0xFF303040);
    r.fill_rect(380, 170, 200, 200, 0xFFE04040);   // 红方块
    r.fill_rect(100, 100, 80, 80, 0xFF40E040);     // 绿方块(左上)
    r.fill_rect(780, 360, 80, 80, 0xFF4040E0);     // 蓝方块(右下)

    for &(dw, dh, name) in &[
        (1920_u32, 1080_u32, "1080p"),
        (1920, 1200, "1200p_letterbox"),
        (800, 600, "800x600"),
        (2560, 1440, "1440p"),
    ] {
        let mut dst = vec![0u32; (dw * dh) as usize];
        blit_scaled(&r.internal, INTERNAL_W, INTERNAL_H, &mut dst, dw, dh);
        let bytes: Vec<u8> = dst.iter().flat_map(|p| p.to_le_bytes()).collect();
        let img: image::ImageBuffer<image::Rgba<u8>, _> =
            image::ImageBuffer::from_raw(dw, dh, bytes).unwrap();
        let path = format!("day109_{}.png", name);
        img.save(&path).unwrap();
        println!("saved {} ({}x{})", path, dw, dh);
    }
}
```

**出错怎么办(troubleshooting)**:

- **画面闪烁 / 像素错乱** —— src 和 dst 大小写反了,或者索引算错。检查 `(dy * dw + dx) vs (sy * sw + sx)`。
- **黑边太大** —— letterbox 算错。`scale = min(...)` 不是 `max(...)`,后者变成 fill。
- **方块位置不对** —— 内部 framebuffer 渲染时坐标算错。检查 `INTERNAL_W`/`INTERNAL_H`。
- **像素抖动** —— `floor` vs `as i32` 在负数边界不同。统一用 `floor`。
- **运行慢(>50ms)** —— 内层循环没优化。考虑用 `rayon::par_iter` 并行 `for dy`。
