
# Day 110 · 屏幕边界反投影:从屏幕到世界

> Day 108 我们学了「**投影**」——把世界点 `(x, y, z)` 变到屏幕点 `(sx, sy)`。今天 Casey 学「**反投影(unprojection)**」——把屏幕点变回世界。为什么需要反投影?一个具体场景:**剔除(culling)**——你想知道「屏幕 4 个角对应世界的哪些位置」,只渲染在那个范围内的 entity,屏幕外的根本不画。这是 Phase 3 的最后一块拼图,完成了「**世界 ↔ 屏幕**」的双向变换能力。

## 0 · 为什么要有这一天

考虑你的游戏有 10000 个 entity(怪物、金币、装饰)。每帧渲染时,如果傻乎乎地把 10000 个全部 push 到渲染队列,但屏幕上实际只能显示 50 个(其他都在视野外),你浪费了 99% 的渲染工作量。在大世界游戏(GTA、Minecraft)里这种浪费是致命的——一台 10000 entity 的世界只渲染屏幕可见的几十个,需要从屏幕反向找世界范围。

「**Frustum Culling(视锥剔除)**」是工业标准方案。Frustum 是相机视锥——一个被 near / far / left / right / top / bottom 6 个平面切出的几何体。视锥内的物体可见,视锥外的不可见。视锥的 8 个角点是把屏幕 4 个角反投影到 3D 得到的——这就是今天要学的「**unproject screen corners**」。

具体怎么用?流程是:取屏幕 4 个角 `(0, 0)` / `(W, 0)` / `(W, H)` / `(0, H)`,每个角反投影到世界得到 2 个点(near 平面上 + far 平面上,共 8 个点),构成视锥的 8 个顶点。然后对每个 entity,检查它的 bounding volume 是否在视锥内——是就 push 渲染,否则跳过。

这件事不只是性能优化,也是**正确性保证**。屏幕外的 entity 渲染了不可见但消耗资源;某些边角情况(屏幕外 entity 的「**拖尾效果**」延伸到屏幕内)需要特殊处理。理解 unproject 让你掌控「**游戏世界和屏幕的完整映射**」,这是 Phase 3 收官的核心能力。

完成今天后,你将拥有「**世界 ↔ 屏幕双向变换**」的完整能力,可以回答「**屏幕这个像素对应世界的哪个点**」、「**世界这个范围对应屏幕哪个矩形**」这类问题。这是 Day 111 开始的 Phase 4(性能优化)的基础——视锥剔除就是性能优化第一刀。

## 2 · 心智模型

### 2.1 费曼类比:逆向投影

**费曼类比**。想象你在看电影。屏幕上有一只奔跑的老虎——你想知道「**这只老虎在世界里实际在哪**」。但电影屏幕是 2D 的,你只能反推「**老虎的世界位置在屏幕那条光线方向上**」——具体多远你不知道。

电影院的相机(投影机)投射光线穿过画面上的老虎像素。如果你反向追踪这条光线,从屏幕老虎像素穿回电影摄影机,然后继续延伸到电影世界——老虎**可能**在光线上任意一点。屏幕像素只告诉你「**光线方向**」,深度(老虎离相机多远)需要别的信息。

游戏里就是这种「**光线 + 深度**」模式。Unproject 给定屏幕点 + 已知深度,反推世界点。

### 2.2 严谨推导

回顾 Day 108 的投影矩阵 `M` 和它的变换:

```
world (x, y, z, 1) --M--> clip (x', y', z', w') --÷w'--> NDC (nx, ny, nz) --viewport--> screen (sx, sy)
```

unproject 是反向走这条链路:

```
screen (sx, sy) --viewport_inv--> NDC (nx, ny, ?) --×w--> clip (x', y', ?, w') --M^-1--> world (x, y, z, 1)
```

两个 `?` 是问题:从 screen 反推 NDC 时,深度 nz 未知(屏幕只有 x, y);从 NDC 反推 clip 时,w' 未知。

**深度问题**。Casey 的解法是「**给定 z_world**」——不从屏幕反推深度,而是直接给一个深度。这样 unproject 输入是 `(sx, sy, z_world)`,输出是 `(wx, wy)`。但 z_world 也要预先知道——Casey 通常给一个有意义的平面,比如「**玩家所在楼层的 z**」。

**更通用的解法**是返回「**光线(Ray)**」而不是点。Ray = 起点(相机位置) + 方向(从相机穿过屏幕点的方向)。然后用 Ray 和场景中的几何体求交,得到具体的世界点。这是「**鼠标拾取(mouse picking)**」的标准做法——3D 游戏里鼠标点击一个物体,实际是构造一条 ray,求 ray 和场景物体的最近交点。

我们看具体公式。Day 108 的投影(简化版,假设 focal=1,center=0):

```
sx = X / (-Z) + cx      (假设 focal=1)
sy = Y / (-Z) + cy
```

反推 X, Y(给定 sx, sy, Z):

```
X = (sx - cx) * (-Z)
Y = (sy - cy) * (-Z)
```

这就是 unproject 的简化版。Casey HH 的实际代码用矩阵实现(`M^-1`),更通用。

### 2.3 矩阵版 unproject

矩阵版 unproject 步骤:

1. 把 screen `(sx, sy)` 转 NDC `(nx, ny)`:`nx = 2*sx/W - 1`,`ny = 1 - 2*sy/H`(Y 翻转)。
2. 给定 NDC 深度 `nz`(从已知的 z_world 反推:`nz` 是投影矩阵 m22, m23 应用后的结果)。
3. 构造 NDC 向量 `(nx, ny, nz, 1)`。
4. 乘 `viewport_inverse × projection_inverse × view_inverse` 得到世界 `(wx, wy, wz, 1)`。

或者更简洁:把 world `z = target_z` 写到 clip 的 w 通道,让 projection inverse 把 nx, ny 也按 z 缩放。

Rust 代码:

```rust
fn unproject(
    screen: [f32; 2], target_z: f32,
    proj: Mat4, view: Mat4,
    viewport_w: f32, viewport_h: f32,
) -> [f32; 3] {
    // screen → NDC
    let nx = 2.0 * screen[0] / viewport_w - 1.0;
    let ny = 1.0 - 2.0 * screen[1] / viewport_h;     // Y 翻转

    // 我们想反推 X, Y,让结果 z = target_z。
    // 思路:先构造 NDC 点 (nx, ny, 0, 1),乘 (proj × view)^-1 得到世界点,
    // 然后从相机位置发射一条 ray 到这个点,沿 ray 找 z = target_z 的位置。

    let inv_mvp = inverse(mat_mul(proj, view));
    let near_point_world = mat_vec(inv_mvp, [nx, ny, -1.0, 1.0]);
    // w 除法
    let np = [
        near_point_world[0] / near_point_world[3],
        near_point_world[1] / near_point_world[3],
        near_point_world[2] / near_point_world[3],
    ];
    // 相机位置(假设 view 是 translate(0,0,-5),相机在 (0,0,-5))
    let camera = [0.0, 0.0, -5.0];
    // ray 方向
    let dir = [np[0] - camera[0], np[1] - camera[1], np[2] - camera[2]];
    // 沿 ray 找 z = target_z:camera.z + t*dir.z = target_z → t = (target_z - camera.z) / dir.z
    let t = (target_z - camera[2]) / dir[2];
    [
        camera[0] + t * dir[0],
        camera[1] + t * dir[1],
        target_z,
    ]
}
```

这个版本先反推 near 平面上的点,然后构造 ray,沿 ray 找 z=target_z 的点。适用于任意投影矩阵,通用。

### 2.4 视锥剔除(Frustum Culling)

把 unproject 应用到屏幕 4 角,得到视锥 4 条边在 far 平面的 4 个点。这 4 个点 + 相机位置 + near 平面,构成 6 面体(视锥)。

视锥剔除两种实现:

**AABB 剔除**(简单):把视锥的 8 个角点求 AABB(轴对齐 bounding box),entity 的 AABB 和视锥 AABB 求交。简单但有 false positive(视锥外但 AABB 内的 entity 被错误地画)。

**平面剔除**(精确):视锥 6 个面,每个 entity 检查是否在所有 6 个面的内侧。精确但每个 entity 要做 6 次平面测试。

Casey HH 用简化版——投影到 2D 后用 AABB 剔除。够用且快。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏业界几个 unproject 应用。

**鼠标拾取(mouse picking)**:RTS 选单位、RPG 点 NPC。构造 ray,求 ray 和 entity bounding box 的最近交点,最近的 entity 是被点的。

**3D 拖拽**:在 3D 编辑器里拖动一个物体到地面,鼠标 unproject 到地面平面(z=0),物体跟着移动。

**FPS 射击**:枪口方向 = 相机位置 + forward vector;子弹 ray 和敌人碰撞检测。

**视锥剔除**:本日重点。Minecraft / GTA 这种大世界游戏,每帧 99% entity 被剔除。

**屏幕空间反射(SSR)**:像素 ray marching,反射光在屏幕空间的 unproject。

### 3.2 · 🎨 图形学视角

图形学把 unproject 叫「**screen space → world space**」变换,标准管线之外的反向操作。GPU 没有原生 unproject 指令,需要在 CPU 或 shader 里手算。

**gluUnProject**(老 OpenGL API)就是做这件事——给定 window coord,返回 world coord。Modern OpenGL 删除了 glu 库,但数学保留。

**Depth Buffer 是另一种 unproject**。每个像素除了 RGB 还存深度,深度可以直接反推 NDC z,再反推 world z。这是「**重建世界位置**」的标准做法,在 deferred shading / SSR 里大量使用。

**Ray Casting**:Ray 是 unproject 的几何抽象——起点 + 方向。所有 ray-based 算法(ray tracing, ray marching, collision detection)都建立在 ray 上。Casey HH Day 110 教的 unproject 是 ray 的入口。

### 3.3 · 🐧 Linux 系统编程视角

Linux 工具链里 unproject 的对应物。

**X11 / Wayland pick(拾取)**:点击屏幕上的窗口,系统告诉你点的哪个窗口。系统维护「**窗口栈 z-order**」,逆向查找。这是 2D 版本的 unproject。

**`xdotool getmouselocation`**:命令行获取鼠标位置(screen space)。要进一步知道在哪个窗口/哪个像素,需要应用自己 unproject。

**`libinput` 事件**:Linux 输入子系统,鼠标事件直接给 screen 坐标(由 compositor 翻译)。应用收到的就是 screen space,需要自己 unproject 到 game space。

理解 unproject 后,你看 Wayland compositor 处理点击事件的代码(weston 的 `weston_surface_pick`)就知道在做什么——「**从屏幕坐标反查窗口**」,本质就是 unproject。

### 3.4 · 🦀 Rust 生态视角

Rust 里写 unproject 的几个注意点。

**矩阵求逆(inverse)**:Rust `[[f32; 4]; 4]` 手写求逆要 30+ 行(伴随矩阵法 / 高斯消元)。推荐用 `glam::Mat4::inverse()` 或 `nalgebra::Matrix4::try_inverse()`。Casey HH 教学版手写,生产用 crate。

**f32 精度**:unproject 涉及多次除法,精度损失累积。考虑 `f64` 做内部计算,最后转 `f32` 输出。Casey HH 用 f32 够教学用。

**SIMD 加速**:`glam::Mat4` 内部 SIMD,4×4 矩阵乘法 1 个时钟周期完成 4 个 f32 操作。unproject 一次 = 几次矩阵乘 + 几次向量操作 = ~50ns。每帧 1000 次 unproject = 50μs,可忽略。

**Ray 求交**:Rust crate `bvh` 提供 Bounding Volume Hierarchy,高效 ray-mesh 求交。Day 440+ 的 3D 碰撞会用。

## 4 · 认知地图

### 4.1 上级(它属于哪个更大抽象?)

- **Inverse Transforms(逆变换)** —— 投影的逆,所有变换的逆。数学上 `M · M^-1 = I`(单位矩阵)。
- **Ray Casting** —— 射线和几何体求交,unproject 是构造 ray 的入口。
- **Visibility Determination(可见性判定)** —— 决定哪些物体应该渲染的通用技术,frustum culling 是其中一种。

### 4.2 同级(并行方案对比)

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| **Unproject 给 z(Casey)** | 已知 z,反推 x, y | 2.5D / 已知平面 | ✅ Day 110 |
| **Unproject 到 Ray** | 返回 ray,后续求交 | 3D 拾取 / 射击 | Day 235+ |
| **Depth buffer 读回** | 从 GPU 读深度,反推 world z | deferred shading | Day 600+ |
| **2D AABB 直接剔除** | 投影所有 entity AABB 到屏幕,做交集 | 简单 2D | Day 110 简化版 |

这张表的关键:**unproject 的精度和「深度信息」的获取方式有关**。Casey 简化版假设已知 z(world),最实用;Ray 版灵活但要做求交;Depth buffer 读回最精确但有 GPU↔CPU 数据传输开销。

### 4.3 下级(内部零件)

- **inverse matrix** —— 投影矩阵的逆,4×4。
- **screen → NDC** —— viewport transform 的逆。
- **ray construction** —— 起点 + 方向。
- **ray-plane intersection** —— 求 ray 和已知平面(z=target_z)的交点。

## 5 · 对照与变奏

**2D vs 3D unproject**。Casey HH 是 2.5D,unproject 简化——已知 z 求 x, y。纯 3D unproject 要返回 ray,后续用 ray 和场景求交。Day 235+ 切到 OpenGL 后会用 ray 版做鼠标拾取。

**CPU vs GPU unproject**。Casey CPU 软渲染,unproject 在 CPU。GPU 渲染时,某些场景(如 deferred shading)需要在 fragment shader 里 unproject——读 depth buffer,反推 world position。GPU shader 一个像素一个 thread,unproject 4 个矩阵乘法每个 thread 独立完成。

**离线 vs 在线**。视锥剔除每帧都做(online),不剔除的 entity 数据可以离线预计算 bounding sphere/hierarchy 加速 online 测试。Casey HH 用最简 AABB,够教学。

**历史演化**。1990 年代 2D 游戏 unproject 是简单除法(直接 sx × 1/scale)。2000 年代 3D 渲染 unproject 进 matrix inverse。2010 年代 GPU shader 让 unproject 进 fragment shader(deferred shading)。每次升级让 unproject 更通用,但核心数学不变。

**题**:Casey 的 unproject 需要给定 `target_z`(已知世界 z)。请回答:(a) 为什么不能从屏幕坐标直接反推 z?(b) 如果不指定 z,unproject 能返回什么?(c) 在 2.5D 游戏中,你想点击屏幕上的一个怪物——怪物在不同楼层(z 不同),鼠标点击怎么知道点的哪一层的怪?

### Lv2 · 动手实践(改/写 Rust 代码)

**题**:实现完整的 unproject + 视锥剔除。给定一组世界 entity(随机位置),剔除屏幕外的,只渲染屏幕内的。要求:(a) 实现 `unproject(screen, target_z, mvp_inv)` 返回世界点;(b) 把屏幕 4 角 unproject 到 far 平面,得到视锥梯形;(c) 遍历 entity,检查是否在梯形内,只画在梯形内的;(d) 在屏幕外放 50 个方块(可见 5 个),验证剔除后 FPS 提升。

**参考解答**:

```rust
// 4×4 矩阵求逆(简化版,假设没有奇异)
fn inverse(m: Mat4) -> Mat4 {
    let mut inv = [[0.0_f32; 4]; 4];
    // ... 用伴随矩阵法求逆(代码略,glam::Mat4::inverse() 已经做了)
    // 这里假设有 glam 或自己实现
    glam_inverse(m)
}

fn unproject(screen: [f32; 2], target_z: f32, mvp: Mat4, w: f32, h: f32) -> [f32; 3] {
    let inv = inverse(mvp);
    let nx = 2.0 * screen[0] / w - 1.0;
    let ny = 1.0 - 2.0 * screen[1] / h;

    // Near 平面(z_ndc = -1)和 Far 平面(z_ndc = 1)各 unproject 一次
    let near_clip = mat_vec(inv, [nx, ny, -1.0, 1.0]);
    let far_clip = mat_vec(inv, [nx, ny, 1.0, 1.0]);
    let near_w = near_clip[3];
    let far_w = far_clip[3];
    let near = [near_clip[0]/near_w, near_clip[1]/near_w, near_clip[2]/near_w];
    let far = [far_clip[0]/far_w, far_clip[1]/far_w, far_clip[2]/far_w];

    // 沿 ray 找 z = target_z
    let dir = [far[0] - near[0], far[1] - near[1], far[2] - near[2]];
    let t = (target_z - near[2]) / dir[2];
    [near[0] + t * dir[0], near[1] + t * dir[1], target_z]
}

fn main() {
    // ... 设置 mvp(同 Day 108)
    // ... 50 个随机 entity

    let screen_corners = [[0.0, 0.0], [800.0, 0.0], [800.0, 450.0], [0.0, 450.0]];
    let far_z = -50.0;
    let world_corners: Vec<[f32; 3]> = screen_corners.iter()
        .map(|&s| unproject(s, far_z, mvp, 800.0, 450.0))
        .collect();
    // 把 4 个世界角围成梯形,检查 entity 是否在梯形内
    for entity in &entities {
        if point_in_polygon([entity.x, entity.y],
                            &world_corners.iter().map(|c| [c[0], c[1]]).collect::<Vec<_>>()) {
            // 在视锥内,渲染
            renderer.draw_entity(entity);
        }
    }
}
```

完成后,你应该看到只有少数 entity 被画(视锥内),FPS 显著提升。

### Lv3 · 迁移设计(换场景用同一原理)

**题**:你在做「**地图应用**」(类似 Google Maps)。地图用墨卡托投影(地球球面 → 2D 平面),用户拖动 / 缩放时,需要知道「**屏幕当前可见的地理范围**」。设计 `MapView` struct,持 `center_lat, center_lon, zoom_level`。要求:(a) `screen_to_geo(screen_x, screen_y)` 返回 `(lat, lon)`;(b) `get_visible_bounds()` 返回屏幕 4 角的地理坐标;(c) 用 bounds 查询 POI 数据库只取可见范围。给出墨卡托投影 / 反投影公式、z level 影响 scale 的关系。

**提示**:墨卡托投影:`x = R * lon * cos(lat0), y = R * ln(tan(π/4 + lat/2))`。反投影:`lon = x / (R * cos(lat0)), lat = 2 * atan(exp(y/R)) - π/2`。Zoom level 影响 R(虚拟地球半径)。

## 8 · Rust / Arch 落地代码

完整可跑的 unproject + frustum culling 演示。

```rust
// Cargo.toml:
// [dependencies]
// image = "0.25"
// glam = "0.29"     # 用 glam 做矩阵运算

use glam::{Mat4, Vec3, Vec4};

fn unproject_to_z(
    screen: [f32; 2],
    target_z: f32,
    mvp: Mat4,
    viewport_w: f32,
    viewport_h: f32,
) -> Vec3 {
    let inv = mvp.inverse();
    let nx = 2.0 * screen[0] / viewport_w - 1.0;
    let ny = 1.0 - 2.0 * screen[1] / viewport_h;

    let near = inv * Vec4::new(nx, ny, -1.0, 1.0);
    let far = inv * Vec4::new(nx, ny, 1.0, 1.0);
    let near = near.truncate() / near.w;
    let far = far.truncate() / far.w;

    let dir = far - near;
    let t = (target_z - near.z) / dir.z;
    Vec3::new(near.x + t * dir.x, near.y + t * dir.y, target_z)
}

fn point_in_polygon(p: [f32; 2], poly: &[[f32; 2]]) -> bool {
    let mut inside = false;
    let n = poly.len();
    let mut j = n - 1;
    for i in 0..n {
        let (xi, yi) = (poly[i][0], poly[i][1]);
        let (xj, yj) = (poly[j][0], poly[j][1]);
        if ((yi > p[1]) != (yj > p[1])) &&
           (p[0] < (xj - xi) * (p[1] - yi) / (yj - yi) + xi) {
            inside = !inside;
        }
        j = i;
    }
    inside
}

pub struct Renderer {
    pub width: u32,
    pub height: u32,
    pub framebuffer: Vec<u32>,
}

impl Renderer {
    pub fn new(w: u32, h: u32) -> Self {
        Self { width: w, height: h, framebuffer: vec![0xFF101015; (w * h) as usize] }
    }

    pub fn fill_circle(&mut self, cx: i32, cy: i32, r: i32, color: u32) {
        for dy in -r..r {
            for dx in -r..r {
                if dx*dx + dy*dy <= r*r {
                    let x = cx + dx; let y = cy + dy;
                    if x >= 0 && y >= 0 && (x as u32) < self.width && (y as u32) < self.height {
                        self.framebuffer[(y as u32 * self.width + x as u32) as usize] = color;
                    }
                }
            }
        }
    }
}

fn main() {
    let viewport_w = 800.0_f32;
    let viewport_h = 450.0_f32;

    let proj = Mat4::perspective_rh_gl(60.0_f32.to_radians(), viewport_w / viewport_h, 0.1, 100.0);
    let view = Mat4::from_translation(Vec3::new(0.0, 0.0, -5.0));
    let mvp = proj * view;

    // 100 个随机 entity
    let mut rng_state: u32 = 42;
    let mut rand = || {
        rng_state = rng_state.wrapping_mul(1664525).wrapping_add(1013904223);
        (rng_state as f32 / u32::MAX as f32) * 2.0 - 1.0   // [-1, 1]
    };
    let entities: Vec<Vec3> = (0..100).map(|_| {
        Vec3::new(rand() * 4.0, rand() * 4.0, rand() * 4.0)
    }).collect();

    // 屏幕 4 角反投影到 far 平面(z = -8)
    let screen_corners = [[0.0, 0.0], [viewport_w, 0.0], [viewport_w, viewport_h], [0.0, viewport_h]];
    let far_z = -8.0;
    let world_frustum: Vec<[f32; 2]> = screen_corners.iter()
        .map(|&s| {
            let p = unproject_to_z(s, far_z, mvp, viewport_w, viewport_h);
            [p.x, p.y]
        })
        .collect();

    let mut r = Renderer::new(viewport_w as u32, viewport_h as u32);
    let mut visible_count = 0;
    for e in &entities {
        let visible = point_in_polygon([e.x, e.y], &world_frustum);
        if visible {
            visible_count += 1;
            // 把 entity 投到屏幕
            let clip = mvp * Vec4::new(e.x, e.y, e.z, 1.0);
            let sx = ((clip.x / clip.w + 1.0) * 0.5 * viewport_w) as i32;
            let sy = ((1.0 - clip.y / clip.w) * 0.5 * viewport_h) as i32;
            r.fill_circle(sx, sy, 5, 0xFFE0E040);
        }
    }
    println!("可见 entity 数:{}/100", visible_count);

    let bytes: Vec<u8> = r.framebuffer.iter().flat_map(|p| p.to_le_bytes()).collect();
    let img: image::ImageBuffer<image::Rgba<u8>, _> =
        image::ImageBuffer::from_raw(r.width, r.height, bytes).unwrap();
    img.save("day110_culling.png").unwrap();
}
```

**出错怎么办(troubleshooting)**:

- **可见 entity 数为 0 或 100** —— unproject 的 z 方向反了,或者 mvp 矩阵符号错。试试 `target_z = 0` 或 `target_z = 5`。
- **画出的点在屏幕外** —— project 时 w 除法漏了,或者 viewport Y 翻转错。检查 `(1.0 - ny) × 0.5 × h`。
- **point_in_polygon 永远 false** —— 多边形顶点顺序错(顺时针 vs 逆时针)。两种顺序算法都支持,但实现可能有 bug。
- **`glam::Mat4::perspective_rh_gl` 找不到** —— glam 不同版本函数名不同,试试 `perspective_lh / perspective_rh / perspective_infinite_reverse_rh`。Casey HH 用 OpenGL RH(right-handed)。
