# Day 088 · 推送缓冲渲染

> 你的游戏代码直接写 framebuffer 像素:`framebuffer.set(x, y, color)`。这看起来直接,但有个致命问题——以后想换渲染后端(从软件光栅到 OpenGL),游戏代码要全改。Casey 今天给你 HH 渲染架构的里程碑:**push buffer**(推送缓冲)。游戏代码 push 高层命令(PushBitmap、PushRect),渲染器消费。这一抽象让你在 Day 235 切 OpenGL 时**游戏代码几乎不改**——只换渲染器后端。

## 0 · 为什么要有这一天

你的渲染代码(Phase 2 + Phase 3 至今):

```rust
fn render_game(state: &GameState, framebuffer: &mut Framebuffer) {
    // 画背景
    framebuffer.blit(0, 0, &state.background);
    // 画玩家
    framebuffer.blit(state.player.x, state.player.y, &state.player.sprite);
    // 画怪
    for m in &state.monsters {
        framebuffer.blit(m.x, m.y, &m.sprite);
    }
    // 画 UI
    draw_text(framebuffer, 10, 10, &format!("Score: {}", state.score));
}
```

问题:**游戏代码直接耦合 framebuffer**。具体问题:

1. **换后端痛苦**:Day 235 要切 OpenGL。OpenGL 没有 `framebuffer.set(x, y, color)`,只有 vertex buffer + shader。游戏代码每一行都要重写。
2. **测试难**:渲染输出是像素,测试要扫整个 framebuffer。慢、不准。
3. **重排序难**:透明物体要按深度排序,游戏代码里直接 blit 没法重排序。
4. **多 pass 难**:阴影 pass、光照 pass、最后渲染 pass——直接 framebuffer 不好做。

**Casey 的解法**:**Push buffer**。

游戏代码不直接写 framebuffer,而是 push 命令到 buffer:

```rust
fn render_game(state: &GameState, push_buf: &mut PushBuffer) {
    push_buf.clear(BLACK);
    push_buf.bitmap(0, 0, &state.background);
    push_buf.bitmap(state.player.x, state.player.y, &state.player.sprite);
    for m in &state.monsters {
        push_buf.bitmap(m.x, m.y, &m.sprite);
    }
    push_buf.text(10, 10, &format!("Score: {}", state.score));
}
```

渲染器**消费** push buffer,翻译成具体操作(软件 blit 或 OpenGL draw call):

```rust
fn render_to_framebuffer(push_buf: &PushBuffer, framebuffer: &mut Framebuffer) {
    for cmd in &push_buf.commands {
        match cmd {
            Command::Clear(c) => framebuffer.fill(*c),
            Command::Bitmap(x, y, bmp) => framebuffer.blit(*x, *y, bmp),
            Command::Text(x, y, s) => draw_text(framebuffer, *x, *y, s),
        }
    }
}
```

**关键**:`render_game` 不知道后端是软渲染还是 OpenGL。**只换消费者**就能换后端。

这是 Day 026(平台/游戏分离)和 Day 088 的 **Day 026 update/render 分离** 的红利。Casey 在 Day 088 把这个分离做到极致——**抽象层完全解耦游戏和渲染后端**。

心理锚点:看完今天,你能向队友解释「为什么我们的引擎能从软渲染切到 OpenGL 而游戏代码不改」。你能用 Rust 写一个 push buffer 系统。你能用 30 秒说清「命令模式」(command pattern)的设计。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. **定义 RenderCommand enum**:所有渲染命令的类型(Clear、Bitmap、Rect、Text)。
2. **PushBuffer struct**:Vec<RenderCommand> + 元信息(投影矩阵、相机)。
3. **Push API**:`push_buffer.clear()` / `push_buffer.bitmap(...)` 等。
4. **Submit API**:`renderer.submit(&push_buffer)`——渲染器消费。
5. **重构游戏代码**:把所有 `framebuffer.blit(...)` 改成 `push_buffer.bitmap(...)`。

这是一次**大型重构**,但一劳永逸。Day 235 切 OpenGL 时,游戏代码零改动,只换渲染器后端。

Casey 强调:「**这是 HH 最重要的一次架构升级**」。从 Day 088 起,渲染层和游戏层彻底解耦。

## 2 · 心智模型

### 费曼类比:餐厅点菜

你去餐厅吃饭。两种模式:

**模式 1(直接耦合)**:你进厨房,自己炒菜。——直接但混乱,你想换厨房就要重学。

**模式 2(点单)**:你看菜单,**写订单**给服务员。服务员把订单送厨房,厨房做菜。

Push buffer 就是订单——**游戏代码写订单**(push commands),**渲染器是厨房**(consume commands)。游戏代码不关心厨房是电炉还是煤气灶,只关心订单被正确执行。

切换「厨房」(软渲染 → OpenGL)时,订单(游戏代码)不变。

### 严谨原理

#### 2.1 RenderCommand enum

```rust
#[derive(Clone, Debug)]
enum RenderCommand {
    Clear { color: u32 },
    Bitmap {
        dst_x: f32, dst_y: f32,
        bitmap_id: BitmapId,
        tint: u32,
    },
    Rect {
        dst_x: f32, dst_y: f32,
        width: f32, height: f32,
        color: u32,
    },
    Text {
        dst_x: f32, dst_y: f32,
        text: String,
        color: u32,
    },
}
```

每个命令是个 enum variant,带必要数据。

#### 2.2 PushBuffer struct

```rust
#[derive(Default)]
struct PushBuffer {
    commands: Vec<RenderCommand>,
}

impl PushBuffer {
    fn clear(&mut self) {
        self.commands.clear();
    }

    fn push_clear(&mut self, color: u32) {
        self.commands.push(RenderCommand::Clear { color });
    }

    fn push_bitmap(&mut self, x: f32, y: f32, id: BitmapId, tint: u32) {
        self.commands.push(RenderCommand::Bitmap {
            dst_x: x, dst_y: y, bitmap_id: id, tint,
        });
    }

    fn push_rect(&mut self, x: f32, y: f32, w: f32, h: f32, color: u32) {
        self.commands.push(RenderCommand::Rect {
            dst_x: x, dst_y: y, width: w, height: h, color,
        });
    }

    fn push_text(&mut self, x: f32, y: f32, text: String, color: u32) {
        self.commands.push(RenderCommand::Text {
            dst_x: x, dst_y: y, text, color,
        });
    }
}
```

#### 2.3 Renderer(消费者)

```rust
struct Renderer {
    bitmaps: HashMap<BitmapId, Bitmap>,  // 资源管理
    framebuffer: Framebuffer,
}

impl Renderer {
    fn submit(&mut self, push_buf: &PushBuffer) {
        for cmd in &push_buf.commands {
            match cmd {
                RenderCommand::Clear { color } => {
                    self.framebuffer.fill(*color);
                }
                RenderCommand::Bitmap { dst_x, dst_y, bitmap_id, tint } => {
                    let bmp = &self.bitmaps[bitmap_id];
                    self.framebuffer.blit(*dst_x, *dst_y, bmp, *tint);
                }
                RenderCommand::Rect { dst_x, dst_y, width, height, color } => {
                    self.framebuffer.fill_rect(*dst_x, *dst_y, *width, *height, *color);
                }
                RenderCommand::Text { dst_x, dst_y, text, color } => {
                    self.draw_text(*dst_x, *dst_y, text, *color);
                }
            }
        }
    }
}
```

#### 2.4 游戏代码

```rust
fn render_game(state: &GameState, push_buf: &mut PushBuffer) {
    push_buf.push_clear(0x00000000);
    push_buf.push_bitmap(0., 0., state.background_id, 0xFFFFFFFF);
    push_buf.push_bitmap(state.player.x, state.player.y, state.player.sprite_id, 0xFFFFFFFF);
    for m in &state.monsters {
        push_buf.push_bitmap(m.x, m.y, m.sprite_id, 0xFFFFFFFF);
    }
    push_buf.push_text(10., 10., format!("Score: {}", state.score), 0xFFFFFFFF);
}

fn game_loop(state: &mut GameState, renderer: &mut Renderer) {
    let mut push_buf = PushBuffer::default();
    loop {
        update_game(state);
        push_buf.clear();
        render_game(state, &mut push_buf);
        renderer.submit(&push_buf);
        renderer.present();
    }
}
```

**关键**:`render_game` 不知道 renderer 是软渲染还是 OpenGL。它只 push 命令。renderer 怎么消费命令,游戏代码不关心。

#### 2.5 切换后端

Day 235 切 OpenGL 时,只需要写一个 OpenGLRenderer:

```rust
struct OpenGLRenderer {
    gl: GlContext,
    textures: HashMap<BitmapId, TextureId>,
}

impl OpenGLRenderer {
    fn submit(&mut self, push_buf: &PushBuffer) {
        for cmd in &push_buf.commands {
            match cmd {
                RenderCommand::Clear { color } => {
                    self.gl.clear_color(...);
                }
                RenderCommand::Bitmap { dst_x, dst_y, bitmap_id, tint } => {
                    let tex = self.textures[bitmap_id];
                    self.gl.draw_textured_quad(*dst_x, *dst_y, tex, *tint);
                }
                // 类似
            }
        }
    }
}
```

游戏代码 0 改动。这就是 push buffer 的价值。

#### 2.6 性能考量

每帧 push 几百到几千个命令。Vec<RenderCommand> 增长开销小。提交时遍历一次。

**潜在瓶颈**:
- `String` clone:`RenderCommand::Text { text: String }` 每次创建 String(堆分配)。

解决:用 `Rc<str>` 或字符串池。或用 `&'a str` 借用(生命周期复杂)。

#### 2.7 命令模式的本质

Push buffer 是 **Command Pattern**(命令模式)的应用:

- 把「请求」(渲染一个 sprite)封装成对象(RenderCommand)。
- 调用者(游戏)不关心接收者(渲染器)怎么执行。
- 可以排队、撤销(undo)、重做(redo)、记录(log)、序列化(save)。

Day 089 加 sort key 后,可以**重排序**命令(透明物体按深度排序)。Day 229+ 加序列化后,可以**录制回放**(debug 录制)。

### 3.2 · 🎨 图形学视角

GPU 本身就是「命令消费者」——你给它命令(glDraw、glBindTexture),它执行。

GPU 的 **command buffer**:

- CPU 写命令到 buffer
- GPU 异步读取并执行
- CPU/GPU 并行

Vulkan 的 command buffer 是显式的——你 record 一系列命令,然后 submit,可以重复 submit(同一组命令多次执行)。这跟 Casey HH 的 push buffer 几乎一样,只是 GPU 端。

#### Display list

老式 OpenGL 有 **display list**——一组预录制的命令,可以重复执行。已经废弃,但思想跟 push buffer 一样。

### 3.3 · 🐧 Linux 系统编程视角

「**生产者-消费者**」是 Linux 系统的核心模式:

- **管道(pipe)**:一个进程写,另一个读。
- **消息队列**:多个进程异步通信。
- **Unix 哲学**:小工具组合,每个工具读 stdin 写 stdout。
- **Wayland 协议**:client 写命令到 buffer,compositor 消费。

Push buffer 是同样的模式——**游戏生产命令,渲染器消费**。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写 push buffer

```rust
use std::collections::HashMap;

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
pub struct BitmapId(pub u32);

#[derive(Clone, Debug)]
pub enum RenderCommand {
    Clear(u32),
    Bitmap { x: f32, y: f32, id: BitmapId, tint: u32 },
    Rect { x: f32, y: f32, w: f32, h: f32, color: u32 },
    Text { x: f32, y: f32, text: String, color: u32 },
}

#[derive(Default)]
pub struct PushBuffer {
    pub commands: Vec<RenderCommand>,
}

impl PushBuffer {
    pub fn push(&mut self, cmd: RenderCommand) {
        self.commands.push(cmd);
    }

    pub fn clear(&mut self) {
        self.commands.clear();
    }

    // 便捷方法
    pub fn push_clear(&mut self, c: u32) { self.push(RenderCommand::Clear(c)); }
    pub fn push_bitmap(&mut self, x: f32, y: f32, id: BitmapId, tint: u32) {
        self.push(RenderCommand::Bitmap { x, y, id, tint });
    }
}

pub trait Renderer {
    fn submit(&mut self, push_buf: &PushBuffer);
}

pub struct SoftwareRenderer {
    pub framebuffer: Vec<u32>,
    pub width: usize,
    pub height: usize,
    pub bitmaps: HashMap<BitmapId, Vec<u32>>,
}

impl Renderer for SoftwareRenderer {
    fn submit(&mut self, push_buf: &PushBuffer) {
        for cmd in &push_buf.commands {
            match cmd {
                RenderCommand::Clear(c) => {
                    self.framebuffer.fill(*c);
                }
                RenderCommand::Bitmap { x, y, id, tint } => {
                    let bmp = self.bitmaps.get(id).unwrap();
                    self.blit(*x as usize, *y as usize, bmp, *tint);
                }
                _ => { /* 其他 */ }
            }
        }
    }
}

impl SoftwareRenderer {
    fn blit(&mut self, dst_x: usize, dst_y: usize, src: &[u32], tint: u32) {
        // 简化:假设 src 大小 = 64x64
        const SIZE: usize = 64;
        for y in 0..SIZE {
            for x in 0..SIZE {
                let dx = dst_x + x;
                let dy = dst_y + y;
                if dx < self.width && dy < self.height {
                    self.framebuffer[dy * self.width + dx] = src[y * SIZE + x];
                }
            }
        }
    }
}
```

Trait 让你**注入不同后端**——生产用 OpenGL,测试用 Mock,简化调试。

#### Rust 的 enum 优势

```rust
match cmd {
    RenderCommand::Clear(c) => ...,
    RenderCommand::Bitmap { x, y, .. } => ...,  // .. 忽略其他字段
    _ => ...,
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 push buffer 让 Day 235 切 OpenGL 时游戏代码不改?

**参考解答**:游戏代码只 push 高层命令(`PushBitmap(x, y, id, tint)`),**不知道**后端是软件 framebuffer 还是 OpenGL。命令到后端时:

- 软渲染后端:`framebuffer.blit(x, y, bmp)`。
- OpenGL 后端:`glDrawTexturedQuad(x, y, texture)`。

游戏代码只关心「画一个 bitmap 在 (x, y)」,**不关心**怎么画。换后端时,游戏代码的 `push_bitmap` 调用完全一样,只是 Renderer 实现换了。

这就是 **依赖倒置**(Dependency Inversion)——高层(游戏)不依赖低层(渲染后端),两者都依赖抽象(RenderCommand + Renderer trait)。

### Lv2 · 动手实践

**题**:实现 PushBuffer + SoftwareRenderer + MockRenderer。游戏代码 push 几个命令,验证两种 renderer 都能消费。

完成标准:MockRenderer 收到正确数量的命令,SoftwareRenderer 实际画图。

**参考解答**:

```rust
use std::collections::HashMap;

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
pub struct BitmapId(pub u32);

#[derive(Clone, Debug)]
pub enum RenderCommand {
    Clear(u32),
    Bitmap { x: f32, y: f32, id: BitmapId, tint: u32 },
    Rect { x: f32, y: f32, w: f32, h: f32, color: u32 },
}

#[derive(Default)]
pub struct PushBuffer {
    pub commands: Vec<RenderCommand>,
}

impl PushBuffer {
    pub fn push_clear(&mut self, c: u32) {
        self.commands.push(RenderCommand::Clear(c));
    }
    pub fn push_bitmap(&mut self, x: f32, y: f32, id: BitmapId, tint: u32) {
        self.commands.push(RenderCommand::Bitmap { x, y, id, tint });
    }
    pub fn push_rect(&mut self, x: f32, y: f32, w: f32, h: f32, color: u32) {
        self.commands.push(RenderCommand::Rect { x, y, w, h, color });
    }
}

pub trait Renderer {
    fn submit(&mut self, push_buf: &PushBuffer);
}

pub struct SoftwareRenderer {
    pub framebuffer: Vec<u32>,
    pub width: usize,
    pub height: usize,
    pub bitmaps: HashMap<BitmapId, Vec<u32>>,
}

impl Renderer for SoftwareRenderer {
    fn submit(&mut self, push_buf: &PushBuffer) {
        for cmd in &push_buf.commands {
            match cmd {
                RenderCommand::Clear(c) => self.framebuffer.fill(*c),
                RenderCommand::Rect { x, y, w, h, color } => {
                    for py in (*y as usize)..((*y + *h) as usize).min(self.height) {
                        for px in (*x as usize)..((*x + *w) as usize).min(self.width) {
                            self.framebuffer[py * self.width + px] = *color;
                        }
                    }
                }
                RenderCommand::Bitmap { x, y, id, .. } => {
                    // 简化:不真画,只标记
                    let bmp = self.bitmaps.get(id);
                    if let Some(bmp) = bmp {
                        // blit 略
                        let _ = bmp;
                    }
                }
            }
        }
    }
}

pub struct MockRenderer {
    pub received: Vec<RenderCommand>,
}

impl Renderer for MockRenderer {
    fn submit(&mut self, push_buf: &PushBuffer) {
        self.received.extend(push_buf.commands.iter().cloned());
    }
}

fn render_game(push_buf: &mut PushBuffer, score: i32) {
    push_buf.push_clear(0x000000FF);
    push_buf.push_rect(10., 10., 100., 20., 0xFFFFFFFF);
    push_buf.push_bitmap(50., 50., BitmapId(1), 0xFFFFFFFF);
    push_buf.push_rect(10., 10., score as f32, 5., 0xFFFF0000);
}
```

```rust
use std::collections::HashMap;

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
pub struct BitmapId(pub u32);

#[derive(Clone, Debug)]
pub enum RenderCommand {
    Clear(u32),
    Bitmap { x: f32, y: f32, id: BitmapId, tint: u32 },
    Rect { x: f32, y: f32, w: f32, h: f32, color: u32 },
    Line { x1: f32, y1: f32, x2: f32, y2: f32, color: u32 },
}

#[derive(Default)]
pub struct PushBuffer {
    pub commands: Vec<RenderCommand>,
    pub stats: PushBufferStats,
}

#[derive(Default, Copy, Clone)]
pub struct PushBufferStats {
    pub bitmap_count: usize,
    pub rect_count: usize,
    pub line_count: usize,
}

impl PushBuffer {
    pub fn clear(&mut self) {
        self.commands.clear();
        self.stats = PushBufferStats::default();
    }

    pub fn push_clear(&mut self, c: u32) {
        self.commands.push(RenderCommand::Clear(c));
    }

    pub fn push_bitmap(&mut self, x: f32, y: f32, id: BitmapId, tint: u32) {
        self.commands.push(RenderCommand::Bitmap { x, y, id, tint });
        self.stats.bitmap_count += 1;
    }

    pub fn push_rect(&mut self, x: f32, y: f32, w: f32, h: f32, color: u32) {
        self.commands.push(RenderCommand::Rect { x, y, w, h, color });
        self.stats.rect_count += 1;
    }

    pub fn push_line(&mut self, x1: f32, y1: f32, x2: f32, y2: f32, color: u32) {
        self.commands.push(RenderCommand::Line { x1, y1, x2, y2, color });
        self.stats.line_count += 1;
    }
}

pub trait Renderer {
    fn submit(&mut self, push_buf: &PushBuffer);
}

pub struct SoftwareRenderer {
    pub framebuffer: Vec<u32>,
    pub width: usize,
    pub height: usize,
    pub bitmaps: HashMap<BitmapId, Vec<u32>>,
}

impl Renderer for SoftwareRenderer {
    fn submit(&mut self, push_buf: &PushBuffer) {
        for cmd in &push_buf.commands {
            match cmd {
                RenderCommand::Clear(c) => self.framebuffer.fill(*c),
                RenderCommand::Bitmap { x, y, id, tint: _ } => {
                    if let Some(bmp) = self.bitmaps.get(id) {
                        for (i, &pixel) in bmp.iter().enumerate() {
                            let bx = i % 64;
                            let by = i / 64;
                            let dx = (*x as usize).saturating_add(bx);
                            let dy = (*y as usize).saturating_add(by);
                            if dx < self.width && dy < self.height {
                                self.framebuffer[dy * self.width + dx] = pixel;
                            }
                        }
                    }
                }
                RenderCommand::Rect { x, y, w, h, color } => {
                    for py in (*y as usize)..=((*y + *h) as usize).min(self.height.saturating_sub(1)) {
                        for px in (*x as usize)..=((*x + *w) as usize).min(self.width.saturating_sub(1)) {
                            self.framebuffer[py * self.width + px] = *color;
                        }
                    }
                }
                RenderCommand::Line { x1, y1, x2, y2, color } => {
                    // Bresenham 简化
                    let dx = (*x2 - *x1).abs() as usize;
                    let dy = (*y2 - *y1).abs() as usize;
                    let steps = dx.max(dy);
                    for s in 0..=steps {
                        let t = s as f32 / steps.max(1) as f32;
                        let px = *x1 + (*x2 - *x1) * t;
                        let py = *y1 + (*y2 - *y1) * t;
                        if (px as usize) < self.width && (py as usize) < self.height {
                            self.framebuffer[(py as usize) * self.width + (px as usize)] = *color;
                        }
                    }
                }
            }
        }
    }
}

fn render_game(push: &mut PushBuffer) {
    push.push_clear(0xFF000000);  // 黑底
    push.push_rect(50., 50., 100., 100., 0xFFFF0000);  // 红方块
    push.push_rect(150., 50., 50., 50., 0xFF00FF00);   // 绿方块
    push.push_bitmap(200., 100., BitmapId(1), 0xFFFFFFFF);  // 玩家
    push.push_line(0., 0., 320., 200., 0xFFFFFFFF);  // 对角线
}

fn main() {
    let mut push_buf = PushBuffer::default();
    render_game(&mut push_buf);

    println!("Push buffer 统计:");
    println!("  总命令: {}", push_buf.commands.len());
    println!("  bitmap: {}", push_buf.stats.bitmap_count);
    println!("  rect:   {}", push_buf.stats.rect_count);
    println!("  line:   {}", push_buf.stats.line_count);

    let mut bmp_data = vec![0xFFFFFFFF; 64 * 64];  // 白色 64x64
    let mut bitmaps = HashMap::new();
    bitmaps.insert(BitmapId(1), bmp_data.clone());

    let mut renderer = SoftwareRenderer {
        framebuffer: vec![0; 320 * 200],
        width: 320, height: 200,
        bitmaps,
    };
    renderer.submit(&push_buf);

    // 数 framebuffer 的非黑像素
    let non_black = renderer.framebuffer.iter().filter(|&&p| p != 0xFF000000).count();
    println!("\nSoftwareRenderer: {} 个非黑像素", non_black);

    println!("\n(在真实游戏里,这里会把 framebuffer 送屏幕)");
}
```
