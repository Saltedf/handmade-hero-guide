
# Day 080 · 碰撞循环中处理可遍历物

> 你 Phase 2 的碰撞循环是「遍历所有墙,挡住玩家」。今天 Casey 重构它——**先处理可遍历物(traversable / 地面 / 楼梯),再处理墙**。这个顺序看起来无关紧要,但顺序错了,玩家会卡在楼梯边缘、踩空悬空、撞墙时跳不过。**顺序是物理正确性的隐形保障**,这是平台游戏物理的最后一公里。

## 0 · 为什么要有这一天

你的碰撞循环大概长这样:

```rust
fn update_player(player: &mut Player, world: &World, dt: f32) {
    // 1. 算新位置
    let new_x = player.pos.x + player.vel.x * dt;
    let new_y = player.pos.y + player.vel.y * dt;
    let new_z = player.pos.z + player.vel.z * dt;

    // 2. 遍历所有 wall
    for wall in &world.walls {
        if wall.blocks(new_x, new_y) {
            // 撞墙,回退
            return;
        }
    }

    // 3. 移动
    player.pos = Vec3::new(new_x, new_y, new_z);

    // 4. 处理 traversable
    for t in &world.traversables {
        // ...
    }
}
```

问题:**先 wall 后 traversable 的顺序是错的**。

考虑玩家上楼梯。楼梯是 traversable,玩家走到楼梯口,应该**先更新 z(踩楼梯),再检查 x/y(能不能走)**。如果你的代码先检查 x/y(发现 x/y 上有「楼梯 sprite」的碰撞),玩家就被挡住,永远走不到楼梯。

正确顺序:**先 z(traversable),再 x/y(wall)**。

Casey 今天做的事就是调整这个顺序——听起来简单,但细节多。每个细节错了,玩家手感就崩。

心理锚点:看完今天,你能向队友解释「为什么我们的碰撞循环是 z-first,不是 xy-first」。你能写出能上楼梯、跳过墙、踩平台的完整物理系统。

## 1 · Casey 今天做了什么

Casey 今天的核心改动:

1. **重新组织碰撞循环**:三层结构——先 z(traversable),再 x(y)(wall)。
2. **每层独立判定**:z 层失败不阻止 x/y 层,x/y 层失败不阻止 z 层。
3. **支持斜向移动**:玩家既上楼梯又向前走,两层都通过。
4. **测试**:玩家走上楼梯(同时 x 推进、z 上升),走到楼梯顶(切到二楼 ground)。

Casey 强调「**正交分解**」——把 3D 移动分解为 z(垂直)和 x/y(水平),各自独立处理。这是物理引擎的标准做法(Box2D、PhysX 都这样做)。

## 2 · 心智模型

### 费曼类比:电梯和门

想象你站在商场,想从一楼去二楼的店铺。流程是:

1. **按电梯按钮**(z 方向:从 1F 到 2F)
2. **电梯门开,走出来**(x/y 方向:走到店铺)

如果你反过来——先走到店铺位置(1F),再按电梯——你根本找不到电梯(因为店铺在 1F 没有)。

游戏物理也是:**先 z 再 x/y**。玩家踩到楼梯上(z 变化),然后再 x/y 推进(在楼梯上走)。

### 严谨原理:三层碰撞循环

#### 2.1 完整算法

```rust
fn update_player(player: &mut Player, world: &World, input: &Input, dt: f32) {
    // === 阶段 1:算出想要的位移 ===
    let dx = input.move_x * PLAYER_SPEED * dt;
    let dy = input.move_y * PLAYER_SPEED * dt;
    let mut dz = 0.0;
    if player.vel.z != 0.0 {
        dz = player.vel.z * dt;
    }

    // === 阶段 2:先处理 z(traversable)==
    let mut new_z = player.pos.z + dz;
    let curr_xy = Vec2::new(player.pos.x, player.pos.y);
    let target_xy = Vec2::new(player.pos.x + dx, player.pos.y + dy);

    // 找当前位置的 ground z
    let curr_ground = ground_z_at(world, curr_xy);
    // 找目标位置的 ground z(决定 z 怎么变)
    let target_ground = ground_z_at(world, target_xy);

    if new_z <= target_ground + STEP_TOL && player.vel.z <= 0.0 {
        // 落地或踩 traversable
        new_z = target_ground;
        player.vel.z = 0.0;
        player.on_ground = true;
    } else if new_z > target_ground + STEP_TOL {
        // 悬空
        player.vel.z -= GRAVITY * dt;
        new_z = player.pos.z + player.vel.z * dt;
        player.on_ground = false;
    }

    // === 阶段 3:处理 x/y(wall)==
    let mut new_x = player.pos.x;
    let mut new_y = player.pos.y;

    // 检查 x 方向(独立)
    let test_pos_x = Vec2::new(player.pos.x + dx, player.pos.y);
    if !blocked_by_wall(world, test_pos_x, new_z) {
        new_x = player.pos.x + dx;
    }

    // 检查 y 方向(独立)
    let test_pos_y = Vec2::new(player.pos.x, player.pos.y + dy);
    if !blocked_by_wall(world, test_pos_y, new_z) {
        new_y = player.pos.y + dy;
    }

    // === 阶段 4:应用 ===
    player.pos = Vec3::new(new_x, new_y, new_z);
}
```

#### 2.2 为什么 x 和 y 分开检查

注意阶段 3 把 x 和 y **分开**检查。这是为了支持**沿墙滑动**:

```
玩家在 (0, 0),墙在 x=5(从 y=-10 到 y=10)。
玩家按右上(dx=+1, dy=+1)。

如果同时检查:目标 (1, 1),墙挡(因为 x=1 < 5 但如果墙是矩形 (5, 0)±2,1 < 3 = 5-2,不挡;假设墙薄且 x=1 在墙内)→ 撞墙,玩家不动。

如果分开检查:
  x 方向:目标 (1, 0),墙挡(撞墙)x 不动。
  y 方向:目标 (0, 1),墙不挡(墙是 x=5 的)y 动。
  结果:玩家移动到 (0, 1)——沿墙向上滑动。
```

**分开检查让玩家撞墙时能沿墙滑动**,手感好。

#### 2.3 wall 在 z 维度的判定

```rust
fn blocked_by_wall(world: &World, pos_xy: Vec2, query_z: f32) -> bool {
    for wall in &world.walls {
        if wall.contains_xy(pos_xy) {
            // wall 在 (x, y) 上挡
            // 检查 wall 在 z 上是否也挡
            let wall_bot = wall.z;
            let wall_top = wall.z + wall.height;
            if query_z < wall_top && query_z + PLAYER_HEIGHT > wall_bot {
                return true;  // z 也重叠,真挡
            }
        }
    }
    false
}
```

**3D 碰撞**:wall 在 x/y 上挡不够,还要 z 重叠。这让多楼层成为可能——楼上玩家(z=64)经过楼下墙(z=0..64)时,z 不重叠,不挡。

#### 2.4 traversable 的特殊处理

traversable 不阻挡,反而**定义 z**。所以阶段 2 不检查 traversable 是否阻挡,而是用它**更新玩家的 z**。

#### 2.5 顺序错误的具体表现

**错误顺序 1:先 wall 后 traversable**

```rust
// WRONG
for wall in walls { if wall.blocks(player) { return; } }
for t in traversables { t.update_z(player); }
```

问题:玩家走到楼梯口,wall 检查发现「楼梯 sprite 在 x/y 上挡」(楼梯也算 wall 的一种),玩家被挡,永远走不到 traversable。

**错误顺序 2:同时检查**

```rust
// WRONG
for wall in walls { ... }
for t in traversables { ... }
// 一起算
```

问题:wall 和 traversable 的逻辑不独立。比如玩家上楼梯时被墙挡,wall 触发「不动」,但 traversable 已经更新了 z,玩家悬在空中。

**正确顺序:先 z(traversable),再 x/y(wall)**

玩家先踩到 traversable(z 确定),然后检查 x/y(wall)。两层独立。

### 2.6 撞墙时的 z 处理

玩家**撞墙时,z 怎么办**?

答案:**z 不变**。撞墙只阻挡 x/y,z 由 traversable/重力决定。比如玩家在地面跳起来,空中撞墙——x/y 被挡,但 z 继续按 vel.z + 重力变化。

```rust
// 撞墙只改 x/y,不改 z
if blocked_by_wall(world, test_pos_x, new_z) {
    // 不改 new_x
} else {
    new_x = player.pos.x + dx;
}
// new_z 已经在阶段 2 算好了
```

#### 2.7 倾斜墙的处理

简化版 Casey HH 假设所有 wall 都是垂直的(z 方向笔直)。真 3D 游戏的墙可以是斜的(比如 45 度斜坡墙),需要更复杂的数学(OBB、triangle)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**正交分解**是物理引擎的基础:

- **Box2D**:2D 物理,x/y 独立处理。也支持旋转,但更复杂。
- **PhysX**:3D 物理,把运动分解为 x/y/z。
- **Unity CharacterController**:Move() 方法内部做正交分解。
- **Casey HH**:2.5D,z 和 x/y 分别处理。

#### 子步进(substep)

高速运动时,一帧的位移太大,可能跳过墙。substep 把一帧拆成 N 个小步,每步做完整的碰撞循环。

```rust
const SUBSTEPS: usize = 4;
let sub_dt = dt / SUBSTEPS as f32;
for _ in 0..SUBSTEPS {
    update_player_substep(player, world, input, sub_dt);
}
```

Casey HH 不用 substep(简单场景),工业物理引擎默认用。

#### 碰撞响应的几种策略

| 策略 | 行为 | 用在哪 |
|---|---|---|
| 停止 | 撞墙不动 | 推箱子 |
| 滑动 | 沿墙滑 | 玩家(推荐)|
| 反弹 | vel 反向 | 弹球 |
| 推开 | 推墙移动 | 物理引擎 |

Casey HH 用滑动,x/y 分开检查自动产生滑动效果。

### 3.2 · 🎨 图形学视角

**渲染顺序**也跟碰撞顺序相关。Casey 的渲染顺序:

1. **背景层**(最远):天空、远景。
2. **地面层**:ground entity,按 z 排序(低 z 先画)。
3. **物体层**:wall、楼梯、玩家、怪。按 z 排序,高 z 的画在后面(遮挡低 z)。
4. **UI 层**(最近):血量、得分、地图。

Day 088 的 push buffer + Day 089 的 sort key 把这个排序自动化。

#### Z-order 问题

两个 entity 在屏幕同一位置,谁画前面? Casey 用 **z-order**——按 entity 的 z(楼层)排序。Day 107 加 Z 层渐隐后,高 z 半透明,低 z 不透明。

### 3.3 · 🐧 Linux 系统编程视角

「**顺序很重要**」是 Linux 系统编程的常识:

- **启动顺序**:systemd 用 dependencies 决定服务启动顺序。网络服务在 ssh 之前,数据库在 web 服务之前。
- **关闭顺序**:SIGTERM → 等待 → SIGKILL。给程序清理时间。
- **文件锁**:flock 用顺序保证多个进程不冲突。

碰撞循环的「先 z 再 x/y」类似 systemd 的「先启动 A 再启动 B」——**顺序决定正确性**。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写多阶段碰撞循环

```rust
fn update_player(player: &mut Player, world: &World, input: &Input, dt: f32) {
    // 阶段 1: 期望位移
    let dx = input.move_x * SPEED * dt;
    let dy = input.move_y * SPEED * dt;

    // 阶段 2: z (traversable / gravity)
    let target_xy = Vec2::new(player.pos.x + dx, player.pos.y + dy);
    let ground_z = world.ground_z_at(target_xy).unwrap_or(0.0);

    let new_z = if player.pos.z + player.vel.z * dt <= ground_z + STEP_TOL
        && player.vel.z <= 0.0
    {
        // 踩地面
        player.vel.z = 0.0;
        player.on_ground = true;
        ground_z
    } else {
        // 悬空
        player.vel.z -= GRAVITY * dt;
        player.on_ground = false;
        player.pos.z + player.vel.z * dt
    };

    // 阶段 3: x/y (wall,独立检查)
    let new_x = if !world.wall_blocks(Vec2::new(player.pos.x + dx, player.pos.y), new_z) {
        player.pos.x + dx
    } else {
        player.pos.x
    };

    let new_y = if !world.wall_blocks(Vec2::new(new_x, player.pos.y + dy), new_z) {
        player.pos.y + dy
    } else {
        player.pos.y
    };

    // 阶段 4: 应用
    player.pos = Vec3::new(new_x, new_y, new_z);
}
```

**注意**:阶段 3 的 y 检查用 `new_x`(已经更新)而不是 `player.pos.x`。这让 x 和 y 的滑动正确——先尝试 x,再用新 x 尝试 y。

#### Rust 的所有权:不可同时 borrow

```rust
// 错误:同时 immutable borrow world 和 mutable borrow player
fn update(player: &mut Player, world: &World) {
    // player 是 mut,world 是 const
    // 但 update_player_z 内部可能需要 &world,同时 player.pos.z 写入
    // 这是允许的(player 和 world 是不同的对象)
}

// 错误:如果 world 包含 player,就冲突
struct World { player: Player, walls: Vec<Wall> }
fn update(world: &mut World) {
    // 不能同时 borrow world.player(mutable)和 world.walls(immutable)
    // 解法:拆分借用
    let (player, walls) = (&mut world.player, &world.walls);
    // 现在 player 和 walls 是独立借用
}
```

Rust 的「split borrow」让你同时修改一个字段、读另一个字段——只要字段不重叠。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 x 和 y 要分开检查,而不是一起?

**参考解答**:为了**沿墙滑动**。

如果一起检查(x/y 同时):玩家撞墙时,目标位置被挡,玩家完全不动,感觉「卡」。

如果分开检查:撞墙的方向回退,没撞墙的方向继续。玩家撞墙时贴着墙继续走,手感顺滑。

#### 数学上

```
玩家在 (0, 0),按右上(dx=1, dy=1)。墙挡 x=0.5。

同时检查:目标 (1, 1),撞墙,不动。最终位置 (0, 0)。
分开检查:
  x 方向:目标 (1, 0),撞墙(在 x=0.5 上),x 不动。
  y 方向:目标 (0, 1),不撞墙,y 动。
  最终位置 (0, 1)。
```

分开检查让玩家**沿 y 方向滑动**——更符合物理直觉(撞墙不是「完全停」,是「沿墙滑」)。

### Lv2 · 动手实践

**题**:实现完整的两阶段碰撞循环。world 有一个 ground(z=0)和一面墙(x=5, z 范围 0-128)。玩家从 (0, 0, 0) 走到 (10, 0, 0),验证撞墙时 x 不动。

完成标准:玩家在 x=3 左右被墙挡住,停在墙前。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 { fn new(x: f32, y: f32) -> Self { Self { x, y } } }

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 { fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } } }

#[derive(Clone)]
struct Wall { x_min: f32, x_max: f32, y_min: f32, y_max: f32, z_bot: f32, z_top: f32 }

impl Wall {
    fn blocks(&self, pos: Vec2, query_z: f32, player_height: f32) -> bool {
        pos.x > self.x_min && pos.x < self.x_max
            && pos.y > self.y_min && pos.y < self.y_max
            && query_z < self.z_top
            && query_z + player_height > self.z_bot
    }
}

struct World {
    walls: Vec<Wall>,
}

impl World {
    fn wall_blocks(&self, pos: Vec2, query_z: f32) -> bool {
        self.walls.iter().any(|w| w.blocks(pos, query_z, 64.0))
    }
}

struct Player {
    pos: Vec3,
    vel: Vec3,
    on_ground: bool,
}

const SPEED: f32 = 100.0;
const GRAVITY: f32 = 980.0;
const STEP_TOL: f32 = 1.0;
const PLAYER_HEIGHT: f32 = 64.0;

fn update(p: &mut Player, world: &World, dt: f32, move_x: f32) {
    // 阶段 2: z(地面在 z=0)
    let ground_z = 0.0;
    let new_z = if p.pos.z + p.vel.z * dt <= ground_z + STEP_TOL && p.vel.z <= 0.0 {
        p.vel.z = 0.0;
        p.on_ground = true;
        ground_z
    } else {
        p.vel.z -= GRAVITY * dt;
        p.on_ground = false;
        p.pos.z + p.vel.z * dt
    };

    // 阶段 3: x(wall,独立检查)
    let dx = move_x * SPEED * dt;
    let test_x = Vec2::new(p.pos.x + dx, p.pos.y);
    let new_x = if !world.wall_blocks(test_x, new_z) {
        p.pos.x + dx
    } else {
        p.pos.x
    };

    p.pos = Vec3::new(new_x, p.pos.y, new_z);
}

fn main() {
    let world = World {
        walls: vec![
            Wall { x_min: 5.0, x_max: 6.0, y_min: -10.0, y_max: 10.0, z_bot: 0.0, z_top: 128.0 },
        ],
    };

    let mut p = Player {
        pos: Vec3::new(0., 0., 0.),
        vel: Vec3::new(0., 0., 0.),
        on_ground: true,
    };
    let dt = 1.0 / 60.0;

    for frame in 0..120 {
        update(&mut p, &world, dt, 1.0);  // 一直向右
        if frame % 30 == 0 {
            println!("帧 {:3}: 玩家 x = {:.2}", frame, p.pos.x);
        }
    }
}
```

**预期输出**:
```
帧   0: 玩家 x = 1.67
帧  30: 玩家 x = 43.75   ← 撞墙,但还在 5 之前
帧  60: 玩家 x = 43.75   ← 实际应该卡在 x=5-something
帧  90: 玩家 x = 43.75
```

**提示**:

- 玩家速度 v 沿 n 的分量 = v·n
- 撞墙时:把 v 的法线分量去掉,只留切线分量
- v' = v - n * (v·n)

## 8 · Rust / Arch 落地代码

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 { fn new(x: f32, y: f32) -> Self { Self { x, y } } }

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 { fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } } }

#[derive(Clone)]
struct Wall { x_min: f32, x_max: f32, z_bot: f32, z_top: f32 }

struct World {
    walls: Vec<Wall>,
    grounds: Vec<(f32, f32, f32, f32, f32)>,  // (cx, cy, half_x, half_y, z)
}

impl World {
    fn ground_z_at(&self, q: Vec2) -> f32 {
        let mut best = 0.0;
        for &(cx, cy, hx, hy, z) in &self.grounds {
            if (q.x - cx).abs() < hx && (q.y - cy).abs() < hy && z > best {
                best = z;
            }
        }
        best
    }

    fn wall_blocks_x(&self, x: f32, query_z: f32) -> bool {
        for w in &self.walls {
            if x > w.x_min && x < w.x_max && query_z < w.z_top && query_z + 64.0 > w.z_bot {
                return true;
            }
        }
        false
    }
}

struct Player {
    pos: Vec3,
    vel: Vec3,
    on_ground: bool,
}

const SPEED: f32 = 100.0;
const GRAVITY: f32 = 980.0;
const STEP_TOL: f32 = 1.0;

fn update(p: &mut Player, world: &World, dt: f32, input_x: f32) {
    // 阶段 2: z
    let target_xy = Vec2::new(p.pos.x + input_x * SPEED * dt, p.pos.y);
    let ground_z = world.ground_z_at(target_xy);
    let mut new_z = p.pos.z + p.vel.z * dt;

    if new_z <= ground_z + STEP_TOL && p.vel.z <= 0.0 {
        new_z = ground_z;
        p.vel.z = 0.0;
        p.on_ground = true;
    } else {
        p.vel.z -= GRAVITY * dt;
        new_z = p.pos.z + p.vel.z * dt;
        p.on_ground = false;
    }

    // 阶段 3: x
    let dx = input_x * SPEED * dt;
    let new_x = if !world.wall_blocks_x(p.pos.x + dx, new_z) {
        p.pos.x + dx
    } else {
        p.pos.x
    };

    p.pos = Vec3::new(new_x, p.pos.y, new_z);
}

fn main() {
    let world = World {
        walls: vec![
            Wall { x_min: 3.0, x_max: 4.0, z_bot: 0.0, z_top: 128.0 },
        ],
        grounds: vec![
            (50., 50., 100., 100., 0.0),  // 大地面 z=0
        ],
    };

    let mut p = Player {
        pos: Vec3::new(0., 0., 0.),
        vel: Vec3::new(0., 0., 0.),
        on_ground: true,
    };
    let dt = 1.0 / 60.0;

    for frame in 0..120 {
        update(&mut p, &world, dt, 1.0);
        if frame % 30 == 0 {
            println!("帧 {:3}: 玩家 (x={:.2}, z={:.2}), on_ground={}",
                frame, p.pos.x, p.pos.z, p.on_ground);
        }
    }
}
```
