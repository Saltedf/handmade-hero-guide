
# Day 075 · 基于台阶高度的条件移动

> 你昨天写好了 traversable,玩家能走楼梯了。但游戏里除了「正式楼梯」,还有「小台阶」——5 像素高的小石头、地上的砖头。玩家遇到这些应该**自动跨过**,而不是被挡住或要按跳跃键。Casey 今天写的就是这条规则:**前方地面高度差 < max_step 自动跨,>= max_step 被挡**。这是 Celeste、超级马里奥等所有平台游戏的核心手感来源。

## 0 · 为什么要有这一天

你的游戏地图上有这些「地形细节」:

- 地面 tile 高度 0
- 一块小石头,高度 4
- 一段正式楼梯,每级高度 16
- 一面墙,高度 64

玩家走到小石头前:你想让他**自动跨过去**(小台阶不影响),不需要按跳跃。
玩家走到楼梯前:你想让他**走上楼梯**(用 Day 074 的 traversable)。
玩家走到墙前:你想让他**被挡住**(撞墙)。

这三种情况,玩家**遇到的 x/y 障碍都是「不能走」**(从 Day 029 的 tile 碰撞视角看)。怎么区分?

Casey 的解法:**碰撞时多检查一个数据**——目标位置的**地面高度**。算「当前位置地面高度」和「目标位置地面高度」的差。差小(< max_step)= 自动跨,差大(>= max_step)= 挡。

`max_step` 是一个**关键游戏参数**——通常是 4-8 像素,决定玩家「能跨多高的台阶」。Mario 是 1 像素(几乎任何台阶都挡),Celeste 是 8 像素(轻松跨小坑),Dark Souls 是 32 像素(几乎能跳过任何东西)。

心理锚点:看完今天,你能在自己的项目里调出**好的手感**。你能解释为什么 Mario 走路感觉「丝滑」(小台阶自动跨),而某些游戏感觉「卡顿」(任何台阶都挡)。你知道这条规则的数学有多简单。

## 1 · Casey 今天做了什么

Casey 今天的代码改动很小:

1. **定义 max_step**:一个常量,比如 `MAX_STEP: f32 = 8.0`。
2. **改碰撞循环**:在 x/y 碰撞响应之前,先算「目标位置地面 z」和「当前位置地面 z」的差。
3. **分支处理**:
   - 差 < MAX_STEP:允许移动(玩家自动跨)
   - 差 >= MAX_STEP:阻挡(普通墙响应)
4. **测试**:地图上放各种高度的小台阶,玩家走过去:小的跨,大的挡。

Casey 强调这是个**简单的工程规则**,但效果巨大——游戏立刻感觉「专业」。Phase 2 你的 tile 碰撞是「撞墙就停」,今天起,小台阶不再卡玩家。

## 2 · 心智模型

### 费曼类比:人在野外走路

你走在山路上。地上有各种「小起伏」——3 厘米的石头、5 厘米的树根、30 厘米的台阶、1 米的悬崖。

- 3 厘米、5 厘米:你的脚自动跨过,你甚至感觉不到。
- 30 厘米:你需要「抬脚」,但仍能走上去。
- 1 米:你必须「跳」或「爬」。

人脑里有一套「自动判定」——视觉看到障碍高度,无意识决定「跨 / 上 / 挡」。

游戏里没有视觉,只有数字。Casey 的 `max_step` 就是「玩家跨过的能力阈值」——比如 8 像素,任何 ≤ 8 像素的高度差,玩家自动跨;> 8 像素的,要么走 traversable(楼梯),要么被挡(墙)。

### 严谨原理:台阶判定的算法

#### 2.1 算目标位置的地面 z

```rust
fn ground_z_at(world: &World, query: Vec2) -> f32 {
    // 遍历所有 traversable,找玩家位置最高的那个
    let mut max_z = f32::NEG_INFINITY;
    for t in &world.traversables {
        if let Some(z) = t.z_at(query) {
            if z > max_z {
                max_z = z;
            }
        }
    }
    if max_z == f32::NEG_INFINITY {
        0.0  // 默认地面 z=0
    } else {
        max_z
    }
}
```

每个位置可能有多个 traversable(比如玩家在两层楼的同一 (x, y)),取**最高的**作为「地面」。

#### 2.2 算高度差

```rust
fn try_move(player: &mut Player, world: &World, dx: f32, dy: f32) -> bool {
    // 当前位置地面 z
    let curr_ground = ground_z_at(world, Vec2::new(player.pos.x, player.pos.y));

    // 试探目标位置(还没移动)
    let target_x = player.pos.x + dx;
    let target_y = player.pos.y + dy;
    let target_ground = ground_z_at(world, Vec2::new(target_x, target_y));

    // 高度差
    let diff = target_ground - curr_ground;

    // 判定
    if diff.abs() < MAX_STEP {
        // 自动跨
        player.pos.x = target_x;
        player.pos.y = target_y;
        player.pos.z = target_ground + player.half_z;  // z 跟随地面
        true
    } else if diff > 0.0 && diff < BIG_WALL_HEIGHT {
        // 上楼梯(traversable),交给 Day 074 的逻辑
        false  // 让 traversable 系统处理
    } else {
        // 撞墙
        false
    }
}
```

**每个分支的语义**:
- `diff < MAX_STEP`:小台阶,玩家自动跨,z 跟随地面变化。
- `0 < diff < BIG_WALL_HEIGHT`:中等到大台阶,玩家走 traversable(楼梯系统接管)。
- 否则(diff 太大或负数大):撞墙,普通碰撞响应。

#### 2.3 MAX_STEP 的取值

```rust
const MAX_STEP: f32 = 8.0;  // 8 像素
```

这是 Casey HH 的取值。考虑这些参考:

- **玩家身高 64 像素**:8 / 64 = 12.5%,即玩家能跨身高 1/8 的台阶。物理直觉。
- **马里奥(身高约 32 像素)**:MAX_STEP = 1,任何台阶都挡。
- **Celeste(身高约 24 像素)**:MAX_STEP = 6,跨过小坑。
- **Dark Souls**:角色约 180 cm,跨 30 cm(1/6)= MAX_STEP ≈ 30 像素(若 1 米 = 180 像素)。

`MAX_STEP` 不是固定值,**根据游戏感觉调**。

#### 2.4 三个分支的视觉化

```
玩家走到位置 P。前方地面有三种情况:

情况 A:小台阶(高 4)
   ┌──┐
   │  │  <- 4 高
___│  │___
   P  →  目标

diff = 4 < MAX_STEP(8)→ 自动跨


情况 B:楼梯(高 16,但是 traversable)
   ┌──┐
   │  │
   │  │  <- 16 高
___│  │___
   P  →  目标

diff = 16 ≥ MAX_STEP(8)→ 不自动跨
但如果目标是 traversable,走 traversable 系统


情况 C:墙(高 64)
   ┌──┐
   │  │
   │  │
   │  │  <- 64 高
   │  │
___│  │___
   P  →  目标

diff = 64 ≥ MAX_STEP 且不是 traversable → 撞墙
```

**三种情况代码上几乎一样**(都算 diff),但**响应不同**。这是工程逻辑的典型——同一个数据,不同上下文响应。

#### 2.5 速度处理:碰撞时 vs 平滑过渡

`MAX_STEP` 自动跨时,玩家**z 突然变化**(从 0 到 4)。如果碰撞前 z=0,碰撞后 z=4,**视觉上玩家会瞬间抬高**。

Casey 的优化:**z 平滑过渡**。玩家从 P 移到 target 时,z 不是瞬间跳,而是按移动距离 lerp。

```rust
// 简化版:z 渐变
let target_z = target_ground + player.half_z;
let alpha = 0.2;  // 平滑系数
player.pos.z = lerp(player.pos.z, target_z, alpha);
```

这给玩家「跨台阶时身体微微上抬」的视觉感,而不是僵硬的瞬移。

或者更简单:z 直接设置,但加一个**视觉 sprite offset**——sprite 画在 z 上,慢慢追上 player.pos.z。这就是「平台游戏手感」的经典技巧。

#### 2.6 重力 vs max_step

玩家自动跨台阶时,如果**重力还在作用**,玩家可能瞬间又被拉回 z=0。Casey 的处理:

- 当玩家「在地面」(踩 traversable 或踩 z=0)时,**重力不作用**。
- 当玩家「悬空」(没踩到)时,**重力作用**,z 下降。

```rust
fn update_player_z(player: &mut Player, world: &World, dt: f32) {
    let ground_z = ground_z_at(world, Vec2::new(player.pos.x, player.pos.y));
    let feet = player.pos.z - player.half_z;

    if feet <= ground_z + STEP_TOL {
        // 踩地面
        player.pos.z = ground_z + player.half_z;
        player.vel.z = 0.0;
        player.is_on_ground = true;
    } else {
        // 悬空,施加重力
        player.vel.z -= GRAVITY * dt;
        player.pos.z += player.vel.z * dt;
        player.is_on_ground = false;
    }
}
```

`STEP_TOL` 是个小值(比如 1 像素),允许玩家「脚刚好在地面 ± 1 像素」算踩到。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

`max_step` 是平台游戏的**手感核心**。几个经典游戏的对比例子:

**Mario 1(NES)**:MAX_STEP ≈ 0,任何小台阶都挡。玩家必须按跳跃键。手感「精确但严格」。

**Mario 64(3D)**:MAX_STEP 较大(约 1/5 身高),玩家能跨过小石头。手感「丝滑」。

**Celeste**:MAX_STEP = 6(身高约 24),跨小坑。结合「dash」机制,实现精确平台跳跃。

**Hollow Knight**:MAX_STEP 中等,跨低台阶,挡高墙。

**Dark Souls**:MAX_STEP 大(约 1/6 身高),角色能跨很多障碍。但有些「陷阱」需要精确跳。

Casey HH 用 MAX_STEP = 8,接近 Celeste 的手感。

#### 工程实现:tile-based vs traversable-based

Casey 的实现是 **traversable-based**——所有可走表面是 traversable 线段。另一种是 **tile-based**——每个 tile 有 `walkable: bool` 和 `height: f32`。

**tile-based 的优势**:简单,数据局部性好(cache-friendly)。

**tile-based 的劣势**:斜坡、楼梯这种「高度连续变化」的形状表达不好。

**混合方案**:大面积用 tile,细节(楼梯、斜坡)用 traversable。这是大多数工业引擎的做法。

### 3.2 · 🎨 图形学视角

`max_step` 概念在图形学里也有出现:

**地形细节(terrain LOD)**:远处地形 mesh 简化,但「关键高度差」要保留(否则远处山脉看不出形状)。算法类似——`height_diff > threshold` 时保留细节,否则简化。

**法线贴图**:像素的法线方向决定光照,小高度差(< 1 像素)用法线贴图模拟,大高度差用真 mesh。

**阴影贴图(shadow map)**:shadow acne(阴影出现奇怪条纹)的原因就是 shadow bias 太小。Shadow bias 类似 max_step——允许的 z 误差阈值。

### 3.3 · 🐧 Linux 系统编程视角

跟 Linux 没直接关系。但 `max_step` 概念在 Linux 内核里有类似的:

**TCP 拥塞控制的 cwnd(congestion window)**:每次 RTT,cwnd 增加 1(slow start 阶段是指数,但概念类似)。如果检测到丢包,cwnd 减半。这就是一个「步进」过程——每步小幅变化,避免震荡。

**Linux CFS 调度器**:每个进程的 vruntime 随时间增加。CFS 优先调度 vruntime 小的进程。**vruntime 的「步进」类似 max_step**——增量固定,不会瞬间大幅跳变。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写台阶判定

```rust
const MAX_STEP: f32 = 8.0;

fn try_move_with_step(
    player: &mut Player,
    world: &World,
    dx: f32,
    dy: f32,
) -> MoveResult {
    let curr_ground = ground_z_at(world, player.pos.x, player.pos.y);
    let target_x = player.pos.x + dx;
    let target_y = player.pos.y + dy;
    let target_ground = ground_z_at(world, target_x, target_y);
    let diff = target_ground - curr_ground;

    if diff.abs() < MAX_STEP {
        // 自动跨
        player.pos.x = target_x;
        player.pos.y = target_y;
        player.pos.z = target_ground + player.half_z;
        MoveResult::AutoStepped
    } else if diff > 0.0 {
        // 上台阶,交给 traversable 系统
        MoveResult::NeedsTraversal
    } else {
        // 下台阶或墙
        MoveResult::Blocked
    }
}

enum MoveResult {
    AutoStepped,
    NeedsTraversal,
    Blocked,
}
```

**Rust 的 enum 是 sum type**,可以承载不同意义的结果。C 里要返回 int 错误码,Rust 用 enum 更安全。

#### Rust 的常量定义

```rust
// 模块级常量(全局)
const MAX_STEP: f32 = 8.0;
const GRAVITY: f32 = -980.0;  // 像素/秒²,负号表示向下
const STEP_TOL: f32 = 1.0;

// 或者用 const fn(常量函数)
const fn half_height(total: f32) -> f32 { total / 2.0 }
const PLAYER_HALF_Z: f32 = half_height(64.0);
```

`const` 在编译期求值,无运行时开销。

#### Rust 测试驱动

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn small_step_autocross() {
        let mut world = World::new();
        world.add_step(Vec2::new(5., 0.), 4.0);  // 在 (5,0) 有 4 高小台阶
        let mut player = Player::at(0., 0., 0.);
        let result = try_move_with_step(&mut player, &world, 5., 0.);
        assert!(matches!(result, MoveResult::AutoStepped));

    }

    #[test]
    fn big_wall_blocked() {
        let mut world = World::new();
        world.add_step(Vec2::new(5., 0.), 64.0);  // 64 高墙
        let mut player = Player::at(0., 0., 0.);
        let result = try_move_with_step(&mut player, &world, 5., 0.);
        assert!(matches!(result, MoveResult::Blocked));
    }
}
```

`matches!` 宏让 enum 比较简洁。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:玩家走到一个**向下**的台阶(diff = -10),MAX_STEP = 8。会发生什么?

**参考解答**:`diff = -10`,`diff.abs() = 10 > MAX_STEP`。所以**不会自动跨**。

但 `-10` 是「向下」,物理上玩家**应该掉下去**(重力作用),不是被挡住。正确的处理:
- `diff > MAX_STEP`(向上大台阶)→ 撞墙或走 traversable
- `diff < -MAX_STEP`(向下大台阶)→ 不阻挡,但触发重力下落
- `|diff| < MAX_STEP`(小台阶)→ 自动跨

Casey HH 的简化:向下大台阶也允许(不阻挡),靠重力下落。所以代码可以简化为:

```rust
if diff > MAX_STEP {
    // 向上大台阶:撞墙或 traversable
    MoveResult::BlockedOrTraversal
} else {
    // 其他:允许移动(自动跨或重力下落)
    MoveResult::AutoStepped
}
```

### Lv2 · 动手实践

**题**:在 Rust 项目里实现 try_move_with_step。写 main:
- 创建几个台阶:高 4(小)、16(中)、64(墙)
- 玩家从 x=0 走到 x=30,每次走 1
- 每次打印遇到的台阶高度和移动结果

完成标准:小台阶自动跨(z=4),中台阶触发 traversable(简化为「不自动跨」),大台阶被挡。

**参考解答**:

```rust
const MAX_STEP: f32 = 8.0;

#[derive(Debug)]
enum MoveResult {
    AutoStepped(f32),  // 跨过的台阶高度
    Blocked(f32),      // 被挡的台阶高度
}

fn ground_z_at(steps: &[(f32, f32)], x: f32) -> f32 {
    // 找 x 处的最高台阶
    let mut max_z = 0.0;
    for &(sx, sz) in steps {
        if (x - sx).abs() < 1.0 && sz > max_z {
            max_z = sz;
        }
    }
    max_z
}

fn try_move(
    player_x: &mut f32,
    player_z: &mut f32,
    steps: &[(f32, f32)],
    dx: f32,
) -> MoveResult {
    let curr = ground_z_at(steps, *player_x);
    let target = ground_z_at(steps, *player_x + dx);
    let diff = target - curr;

    if diff.abs() < MAX_STEP {
        *player_x += dx;
        *player_z = target + 32.0;  // half_z = 32
        MoveResult::AutoStepped(diff)
    } else if diff > 0.0 {
        // 向上大台阶:挡
        MoveResult::Blocked(diff)
    } else {
        // 向下大台阶:允许(重力)
        *player_x += dx;
        *player_z = target + 32.0;
        MoveResult::AutoStepped(diff)
    }
}

fn main() {
    // 几个台阶
    let steps = [
        (10.0, 4.0),    // x=10 有 4 高小台阶
        (20.0, 16.0),   // x=20 有 16 高中台阶
        (30.0, 64.0),   // x=30 有 64 高墙
    ];

    let mut px = 0.0;
    let mut pz = 32.0;  // half_z=32,中心 z=32,脚 z=0

    for target_x in [10.0, 20.0, 30.0] {
        let dx = target_x - px;
```

## 8 · Rust / Arch 落地代码

### 完整可跑代码

```rust
const MAX_STEP: f32 = 8.0;
const STEP_TOL: f32 = 1.0;

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
}

#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }

#[derive(Debug)]
enum MoveResult { AutoStepped(f32), Blocked(f32), Fell }

struct World {
    // 简化:一个高度图,每个 (x, y) 位置有一个 ground_z
    // 实际项目用 traversable 数组
    steps: Vec<(Vec2, f32)>,  // (位置, 该位置的台阶高度)
}

impl World {
    fn new() -> Self { Self { steps: Vec::new() } }

    fn add_step(&mut self, pos: Vec2, height: f32) {
        self.steps.push((pos, height));
    }

    fn ground_z_at(&self, q: Vec2) -> f32 {
        let mut max_z = 0.0;
        for &(p, h) in &self.steps {
            if (p.x - q.x).abs() < 1.0 && (p.y - q.y).abs() < 1.0 {
                if h > max_z { max_z = h; }
            }
        }
        max_z
    }
}

struct Player {
    pos: Vec3,
    vel: Vec3,
    half_z: f32,
    is_on_ground: bool,
}

impl Player {
    fn new(x: f32, y: f32) -> Self {
        Self {
            pos: Vec3::new(x, y, 32.0),
            vel: Vec3::new(0., 0., 0.),
            half_z: 32.0,
            is_on_ground: true,
        }
    }

    fn try_move(&mut self, world: &World, dx: f32, dy: f32) -> MoveResult {
        let curr_ground = world.ground_z_at(Vec2 { x: self.pos.x, y: self.pos.y });
        let target = Vec2 { x: self.pos.x + dx, y: self.pos.y + dy };
        let target_ground = world.ground_z_at(target);
        let diff = target_ground - curr_ground;

        if diff.abs() < MAX_STEP || diff < 0.0 {
            // 自动跨 或 向下
            self.pos.x = target.x;
            self.pos.y = target.y;
            self.pos.z = target_ground + self.half_z;
            MoveResult::AutoStepped(diff)
        } else {
            MoveResult::Blocked(diff)
        }
    }
}

fn main() {
    let mut world = World::new();
    world.add_step(Vec2 { x: 10., y: 0. }, 4.0);    // 小台阶
    world.add_step(Vec2 { x: 20., y: 0. }, 16.0);   // 中台阶
    world.add_step(Vec2 { x: 30., y: 0. }, 64.0);   // 墙

    let mut player = Player::new(0., 0.);
    for target_x in [5., 10., 15., 20., 25., 30.] {
        let dx = target_x - player.pos.x;
        let result = player.try_move(&world, dx, 0.);
        println!("尝试走到 x={:4.0}: {:20?} | 玩家 (x={:4.0}, z={:.1})",
            target_x, result, player.pos.x, player.pos.z);
    }
}
```

**预期输出**:
```
尝试走到 x=   5: AutoStepped(0.0)       | 玩家 (x=   5, z=32.0)
尝试走到 x=  10: AutoStepped(4.0)       | 玩家 (x=  10, z=36.0)
尝试走到 x=  15: AutoStepped(-4.0)      | 玩家 (x=  15, z=32.0)
尝试走到 x=  20: Blocked(16.0)          | 玩家 (x=  15, z=32.0)
尝试走到 x=  25: Blocked(16.0)          | 玩家 (x=  15, z=32.0)
尝试走到 x=  30: Blocked(16.0)          | 玩家 (x=  15, z=32.0)
```
