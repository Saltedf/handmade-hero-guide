## 0 · 为什么要有这一天

让我们从一个真实的视觉 bug 说起。

你做完 Day 099 的环境贴图反射,看起来还不错——金属面板有天空倒影,水洼反射路灯。但你仔细看,**反射效果"平"**——所有像素的反射颜色几乎一样,不跟随表面细节变化。

具体场景:一面砖墙,带法线贴图(模拟砖缝)。Day 099 你用简化映射:`u = 0.5 + R.x * 0.5`,v 类似。R 是反射向量。问题:**法线被法线贴图扰动后,反射向量 R 也应该跟着变**,但简化映射只看 R.xy,丢失了 R.z 的信息。

具体后果:砖缝处的法线 (0.3, 0, 0.95)——向右倾。视线 (0, 0, 1)——朝相机。反射 R = 2(V·N)N - V = 2(0.95)(0.3, 0, 0.95) - (0, 0, 1) = (0.57, 0, 0.8)。R.x = 0.57,简化映射 `u = 0.5 + 0.57*0.5 = 0.785`。

但平地法线 (0, 0, 1),反射 R = (0, 0, 1)。R.x = 0,简化映射 `u = 0.5 + 0*0.5 = 0.5`。

两个 uv (0.5, 0.5) vs (0.785, 0.5) 差异 0.285。在 1024×1024 环境贴图上,差 ~290 像素——可见差异。看起来 Day 099 的工作得通?

**问题藏在 R.z**。砖缝反射的 R.z = 0.8,平地 R.z = 1.0。但简化映射**忽略 R.z**——它只用 xy。这意味着两个不同的反射方向(一个朝右上略前,一个朝正前),如果 xy 接近,映射到同一 uv——**丢失了 z 信息**。

更糟:在 sphere map 里,R.z 决定"圆盘上多远"。两个反射方向 (0.5, 0, 0.87) 和 (0.5, 0, -0.87)——一个朝前一个朝后,简化映射给同一 uv (0.75, 0.5)。但它们采样**完全不同的环境方向**(一个看天空,一个看地面)。**视觉 bug**。

**精确反射向量**要正确算:
1. 反射向量 R 的 3 个分量都参与(不只是 xy)
2. R 到 uv 的映射更准确(考虑 z 的方向)——Blinn-Newell sphere map 公式
3. 法线变化时,R 也跟着变,反射**有立体感**

数学上没有新东西——还是 Day 044 的反射公式。今天 Casey 把这个公式和环境贴图采样**严格**结合,确保反射效果最大化。

**学完今天,你应该能**:

- **推导反射公式 `R = 2(V·N)N - V`**——从向量分解到反射公式
- **解释 sphere map 的极点问题**——为什么 R.z 接近 -1 时映射失真
- **用法线贴图改变反射**——每像素的 N 不同,R 也不同
- **看懂 industrial shader 的 `reflect(I, N)`**——它是这个公式的 builtin
- **理解 cube map 为什么取代 sphere map**——避免极点压缩

## 2 · 心智模型

### 2.1 费曼类比:打台球

我打个比方。台球桌的库边(边缘)就像镜子——球碰到库边后弹开,弹开的角度等于入射角度(相对库边法线)。这就是**反射定律**(law of reflection):

- **入射角 = 反射角**(相对法线)
- **入射方向、反射方向、法线三向量共面**

物理上,光也是这样——光子打到表面,反射角度等于入射角度。镜面反射(specular reflection)是这个定律的完美实现,漫反射(diffuse reflection)是模糊版(光随机散射)。

数学上,给入射方向 I 和法线 N:

```
R = I - 2(I · N) N
```

如果 I 指向表面(从光源指向物体),那么 R 是弹开方向。

**视觉反射**:你的视线 V 从相机出发指向表面。在表面上,视线被反射回 R 方向。R 指向哪里,你就从那里看到环境——所以采样 R 方向对应的环境色。这就是环境贴图反射的本质。

### 2.2 反射公式推导:从向量分解到公式

让我把推导展开,你会看到 `R = 2(V·N)N - V` 不是魔法,是几何必然。

考虑入射向量 I(指向表面),法线 N(单位向量)。

把 I 分解成「沿法线方向」和「垂直法线方向」两个分量:
- **垂直分量**:`I_par = I - (I·N)N`(平行于表面,不被反射改变)
- **法线分量**:`I_perp = (I·N)N`(垂直于表面,被反射反向)

反射:**垂直分量不变,法线分量反向**。

```
R = I_par - I_perp
  = (I - (I·N)N) - (I·N)N
  = I - 2(I·N)N
```

这就是经典反射公式 `R = I - 2(I·N)N`。

**注意**:如果 V 是视线(从表面指向相机),那么入射 I = -V。代入:

```
R = -V - 2(-V · N) N
  = -V + 2(V·N)N
  = 2(V·N)N - V
```

所以两种等价形式:
- `R = I - 2(I·N)N`(I 指向表面)
- `R = 2(V·N)N - V`(V 指向相机,V = -I)

GPU shader 的 `reflect(I, N)` 用第一种形式,GLSL 文档定义 `reflect(I, N) = I - 2*dot(N, I)*N`。

### 2.3 法线贴图下的反射:为什么细节会"跟随"

每像素的 N 来自法线贴图(扰动后的法线)。反射公式不变,只是 N 不同。这就是「**法线变化 → 反射变化 → 反射跟随细节**」的根源。

**举例**:平面的法线 (0, 0, 1),视线 (0, 0, 1),反射 R = 2(0·0 + 0·0 + 1·1)(0, 0, 1) - (0, 0, 1) = (0, 0, 1)。反射方向就是视线方向——你看自己。

**砖缝处的法线** (0.3, 0, 0.95)(向右倾)。同样的视线,反射 R = 2(0.95)(0.3, 0, 0.95) - (0, 0, 1) = (0.57, 0, 0.8)。反射方向偏右——这就是砖缝处反射偏移的来源。视觉上:砖缝处你看到的不是自己的脸,而是右侧的墙面。

**精确映射让这种偏移可见**——简化映射把 R.z 丢掉,砖缝和平地的 uv 都接近 (0.5, 0.5),反射差异被压缩。精确映射用 R.z 当分母,差异放大。

### 2.4 反射向量到环境 uv:Blinn-Newell 公式

让我详细对比简化映射和精确映射。

**简化版**(Day 099 用):

```
u = 0.5 + R.x * 0.5
v = 0.5 - R.y * 0.5
```

只用 xy。问题:R 的 z 信息丢了。两个反射方向(R1=(0.5, 0, 0.87) 和 R2=(0.5, 0, -0.87))映射到同一个 uv——错误。R1 看天空,R2 看地面,但简化映射给同一颜色。

**Sphere map 公式**(Blinn & Newell 1976):

```
u = R.x / (2 * (1 + R.z)) + 0.5
v = R.y / (2 * (1 + R.z)) + 0.5
```

注意 R.z 在分母——z 越接近 -1(反射朝向相机背面),分母越小,u/v 跑到无穷(极点)。这是 sphere map 的固有问题(极点压缩)。

**几何解释**:Sphere map 是把 3D 方向投影到 2D 圆盘。圆盘中心对应 R.z = 1(朝前),边缘对应 R.z = 0(侧面),圆盘外(无穷远)对应 R.z = -1(朝后)。所以"朝后"的方向都映射到圆盘边缘——压缩成一点。

**Cube map**(最准确):6 张图,每张对应一个轴方向。R 的最大分量决定面,其他两个分量是该面内的 uv。无极点压缩,但存储 6 倍。

Casey HH Day 100 用 sphere map(更简单),Day 200+ 切 cube map。

**为什么 sphere map 极点是问题**?考虑玩家站在水面边缘看(掠射角)。反射方向 R.z 接近 -1(几乎朝后)。Sphere map 把这个方向压缩到边缘——大量方向映射到几个像素,**反射看起来扭曲**。Cube map 用独立的面,每个方向独立采样,无压缩。

### 2.5 实现对比:简化 vs 精确

**简化版**:

```rust
fn reflect_to_uv_simple(r: Vec3) -> (f32, f32) {
    (0.5 + r.x * 0.5, 0.5 - r.y * 0.5)
}
```

**精确版**(Blinn-Newell):

```rust
fn reflect_to_uv_blinn(r: Vec3) -> (f32, f32) {
    let denom = 2.0 * (1.0 + r.z).max(1e-6);  // 防 div by zero
    let u = r.x / denom + 0.5;
    let v = r.y / denom + 0.5;
    (u.clamp(0.0, 1.0), v.clamp(0.0, 1.0))
}
```

精确版用 R.z 当分母。R.z 接近 1(反射朝向相机),分母接近 4,u/v 越接近圆心 (0.5, 0.5);R.z 接近 -1(反射背向相机),分母接近 0,u/v 跑到极点(无穷,被 clamp 到边缘)。

`.max(1e-6)` 防止 div by zero——浮点除零产生 inf 或 NaN,会污染整个画面。

## 3 · 四域深入

### 3.1 · 游戏编程视角

精确反射向量的应用极其广泛。让我列几个工业场景。

**法线贴图 + env map 结合**——让 sprite 反射跟随表面细节。Casey HH Day 100 的直接需求。砖墙的砖缝、地板的木纹、金属的刮痕,所有法线贴图都需要精确反射才能让细节"活"。

**角色眼睛反射环境**——眼睛看起来"活"。Unreal Engine 的角色 shader 专门有 "Eye Fresnel"——眼睛角膜反射环境,瞳孔内的虹膜不反射。这需要精确反射 + Fresnel。

**金属装备反射周围**——剑身上有天空的倒影。Frostbite 引擎的金属 shader 用 IBL(image-based lighting)+ 精确反射,模拟真实金属。

**湿润路面反射路灯**——雨水 + 沥青。GTA 5 的 wet road shader 用法线贴图(模拟涟漪)+ 精确反射 + Fresnel,达到电影级效果。

**坑:Cube map vs Sphere map 的边界**。Sphere map 在极点(z=-1)处压缩,反射看起来扭曲。Day 200+ 切 cube map 解决。**Cube map 是工业标准**——所有现代引擎(Unreal / Unity HDRP / Godot 3+)都用 cube map,只有 Casey HH 用 sphere map(简化,教学目的)。

**坑:env map 的 capture**。Sphere map / cube map 都需要预先 capture 环境到纹理。Static env map(预 capture)用于静态环境,dynamic env map(实时 capture)用于动态环境(玩家移动时环境变化)。后者代价大——每帧 capture 整个场景 6 次。

### 3.2 · 图形学视角

反射向量的高级应用:

**Fresnel 反射**:反射强度随入射角变化。**Fresnel 公式**:`F = F0 + (1-F0)(1-V·N)^5`。站在水面边缘看(掠射角,V·N 接近 0),反射强度接近 1(强反射);站在桥头直射看(V·N 接近 1),反射强度接近 F0(材料的固有反射率,水 ~0.02)。这是水、玻璃、塑料的视觉特征来源。

**Schlick 近似**:`F = F0 + (1-F0)(1-V·N)^5` 是 Schlick 1994 年的近似,实际 Fresnel 公式更复杂(涉及光的偏振)。但 Schlick 近似在 graphics 足够,99% 引擎用。Casey HH Day 200+ 用。

**Roughness 模糊**:粗糙表面反射被模糊(微表面理论 microfacet theory)。光滑金属精确反射,粗糙金属反射模糊。预过滤 env map——按 roughness 等级预渲染几个模糊版本,运行时按 material roughness 采样对应版本。Unreal 的 PBR 用这个。

**Refraction(折射)**:玻璃透镜、水面透视。Snell 定律:`n1·sin θ1 = n2·sin θ2`,n1/n2 是介质折射率(空气 1.0,水 1.33,玻璃 1.5)。折射向量公式:`T = (n1/n2)I + (n1/n2 · cos θ1 - cos θ2)N`。Casey HH Day 110+ 用。

**Dispersion(色散)**:玻璃对不同颜色光折射不同(彩虹)。物理上,n(折射率)随波长变化。Graphics 通常忽略(简化),少数电影级 shader(如Pixar RenderMan)实现。

### 3.3 · Linux 系统编程视角

反射向量本身是纯数学,但有几个 Linux 相关的优化。

**SIMD**:Vec3 的 dot、scale 是 3 个 f32 运算,可以用 SSE/AVX 单指令完成。CPU 编译器(auto-vectorization)通常能优化简单循环,但显式 SIMD intrinsic(如 `_mm_dp_ps`)更可靠。Rust 的 `wide` crate 或 `std::simd` 提供 SIMD API。

```rust
use std::simd::f32x4;
let v = f32x4::from_array([1.0, 2.0, 3.0, 0.0]);
let dot = (v * v).reduce_sum();  // SIMD 点积
```

**常量预计算**:View 向量通常固定(整个场景一个相机),预算一次重用。Casey HH 每帧的 view_dir 算一次,所有像素共享。100 万像素共享一个 view,节省 100 万次 normalize。

**GPU 硬件反射**:GLSL/HLSL 有内置 `reflect(I, N)` 函数,1 cycle 完成。GPU 的 SFU (Special Function Unit) 硬件实现,比 CPU 反射快得多。

```glsl
// GLSL
vec3 R = reflect(-V, N);  // 注意 GLSL reflect 接受 incident,不是 view
vec4 env_color = texture(env_sampler, R);  // cube map 直接用 R
// 或 sphere map
vec2 uv = R.xy / (2.0 * (1.0 + R.z)) + 0.5;
vec4 env_color = texture(env_sampler, uv);
```

**Linux 工具链**:

```bash
# 看你的 GPU 支持哪些 shader 指令
glxinfo | grep "GL_ARB_shading_language"

# 用 apitrace 抓 OpenGL
sudo pacman -S apitrace
apitrace trace ./my_game
qapitrace my_game.trace  # GUI 看
```

### 3.4 · Rust 生态视角

Rust 的 `glam` 提供 `Vec3::reflect`:

```rust
use glam::Vec3;
let r = v.reflect(n);  // 等价于 v - 2 * v.dot(n) * n
```

**注意**:`glam` 的 reflect 是 `incident - 2(I·N)N`,所以传 incident(从光源/相机指向表面),不是 view。这和 GLSL 的 reflect 一致,但和 Casey HH 的 "view 反射" 相反。Casey 用 `R = 2(V·N)N - V`(view 形式),glam 用 `R = I - 2(I·N)N`(incident 形式)。两者等价(I = -V),但参数方向不同,容易出错。

**正确用法**:

```rust
let view = Vec3::new(0.0, 0.0, 1.0);  // 从表面指向相机
let normal = Vec3::new(0.0, 0.0, 1.0);
let incident = -view;  // 从相机指向表面
let reflect_dir = incident.reflect(normal);
// 等价于 Casey 的 reflect_view(view, normal)
```

**nalgebra** 是 Rust 的另一个 math crate,更通用(线性代数)但稍慢。glam 专为 graphics 优化,默认选 glam。

## 5 · 对照与变奏

### 5.1 简化 vs 精确反射的视觉差异

简化映射只看 xy,R.z 不同的两个反射方向映射到同一 uv。视觉上:
- 法线略微变化时,反射几乎不变(因为 xy 变化小)
- 法线大幅变化时,反射变化明显

精确映射让 R.z 也参与,**法线小幅变化也能反映到反射上**。这是法线贴图反射看起来「跟随细节」的关键。

具体数值:法线从 (0, 0, 1) 变到 (0.1, 0, 0.995)(微小倾斜):
- 简化:R.xy 从 (0, 0) 变到 (0.2, 0)(M=identity, R = 2(V·N)N - V),uv 从 (0.5, 0.5) 变到 (0.6, 0.5)
- 精确:R = (0.199, 0, 0.98),uv = (0.199/(2*1.98)+0.5, 0.5) = (0.55, 0.5)

两个映射接近——因为 R.z 接近 1,分母接近 4,uv 接近 R.xy/4 + 0.5。在 R.z 大时(反射朝前),简化版和精确版结果接近。

但当法线大变,(0.3, 0.4, 0.87)(更斜):
- 简化:R = (0.6, 0.8, 0.74),uv = (0.8, 0.1)
- 精确:R = (0.6, 0.8, 0.74),uv = (0.6/(2*1.74)+0.5, 0.8/(2*1.74)+0.5) = (0.67, 0.73)

差异巨大。简化版的 v = 0.1(底部),精确版的 v = 0.73(顶部)。视觉上,简化版看到环境底部(地面),精确版看到环境上部(天空)。**完全不同**。

### 5.2 Sphere map 极点问题

R.z 接近 -1 时,sphere map 映射跑到无穷。视觉上:**极点处反射失真**(压缩成一点)。

具体:R.z = -0.99,分母 2*(1+(-0.99)) = 0.02。R.x = 0.5,u = 0.5/0.02 + 0.5 = 25.5。被 clamp 到 1.0。所有 R.z 接近 -1 + R.x 接近 0.5 的反射方向都被 clamp 到边缘一点——视觉上是"一条线"。

Cube map 用 6 张图分别处理不同方向,避免这个压缩。每个面负责一个轴方向(R.x 最大用 +X 面,R.y 最大用 +Y 面,...),面内 uv 由其他两个分量决定。

### 5.3 历史背景

- **1976 Blinn-Newell sphere map 论文**——第一个 env map 技术。Blinn 后来发明 bump mapping,Newell 发明 polygon tessellation(Newell's algorithm)。
- **1986 Greene cube map 概念**——cube map 论文,理论提出。
- **1998 DirectX 7 cube map 硬件支持**——GPU 硬件开始支持 cube map。
- **2000s cube map 成主流**——所有 GPU 都支持 cube map,sphere map 被淘汰。
- **2018+ RTX 实时光追反射**——NVIDIA RTX 用 BVH 做光线追踪,反射物理正确(包括自反射、阴影)。

Casey HH Day 100 用 sphere map(1990 年代技术),教学目的。Day 200+ 切 cube map(2000 年代技术),production 用。

### 5.4 反射向量的右手 vs 左手坐标系

HH 用**左手坐标系**(z 朝屏幕里)。OpenGL 用**右手坐标系**(z 朝屏幕外)。反射公式在两个坐标系下符号不同。

**左手**:R = 2(V·N)N - V,V 是从表面指向相机,z 朝里(相机看 -z 方向)。
**右手**:R = 2(V·N)N - V,V 是从表面指向相机,z 朝外(相机看 +z 方向)。

公式相同,但实际数值不同——因为 V 和 N 的 z 分量符号不同。切换坐标系时(从 HH 到 OpenGL),要翻转所有 z 分量。这是常见的 port bug 来源。

Casey 强调:**统一一个坐标系**。HH 一致用左手,避免混乱。OpenGL/GLSL 默认右手,但可以配置成左手(`glDepthRange` 反转)。DirectX 默认左手。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 sphere map 在 R.z 接近 -1 时失真?

**参考解答**:Sphere map 的映射公式 `u = R.x / (2(1+R.z)) + 0.5`,分母 `(1 + R.z)`。当 R.z → -1,分母 → 0,u/v → 无穷大。这意味着「反射方向接近背面」的所有方向都映射到 sphere map 的边缘(被压缩)。

物理直觉:sphere map 是把 3D 方向投影到 2D 圆盘。背面方向的投影长度趋于无穷(就像从侧面看一个点,它「跑」到无穷远)。Cube map 用 6 张图分别处理不同方向,避免这个压缩。

fn shade_with_env_precise(
    surface_normal: Vec3,
    view_dir: Vec3,
    light: Light,
    material: Material,
    env: &LinearBitmap,
    ambient: Color,

    let n = surface_normal;
    let v = view_dir;
    let l = light.direction;
    let h = l.add(v).normalized();

### 8.2 完整 sprite + 法线贴图 + 精确反射(详细注释)

```rust
// 完整 sprite + 法线贴图 + env map 反射 + Fresnel
fn shade_card_with_env(
    surface_normal: Vec3,  // 单位向量,世界空间
    view_dir: Vec3,        // 单位向量,从表面指向相机
    light: Light,
    material: Material,
    env: &LinearBitmap,
    ambient: Color,
) -> Color {
    let n = surface_normal;
    let v = view_dir;
    let l = light.direction;
    let h = l.add(v).normalized();  // Blinn-Phong half vector

    let ndotl = n.dot(l).max(0.0);
    let ndoth = n.dot(h).max(0.0);
    let ndotv = n.dot(v).max(0.0);
    let specular = ndoth.powf(material.shininess);

    // Phong diffuse + specular
    let diffuse_intensity = light.intensity * ndotl;
    let phong = Color {
        r: ambient.r + diffuse_intensity * light.color.r * (material.diffuse_color.r + specular),
        g: ambient.g + diffuse_intensity * light.color.g * (material.diffuse_color.g + specular),
        b: ambient.b + diffuse_intensity * light.color.b * (material.diffuse_color.b + specular),
    };

    // 精确反射 R = 2(V·N)N - V
    let r = reflect_view(v, n);
    let env_color = sample_env(env, r);  // Blinn-Newell sphere map

    // Schlick Fresnel:掠射角反射增强
    let fresnel = material.f0 + (1.0 - material.f0) * (1.0 - ndotv).powi(5);

    // Fresnel-modulated reflectivity
    let refl = material.reflectivity * fresnel;
    Color {
        r: phong.r * (1.0 - refl) + env_color.r * refl,
        g: phong.g * (1.0 - refl) + env_color.g * refl,
        b: phong.b * (1.0 - refl) + env_color.b * refl,
    }
}
```

### Troubleshooting

- **反射方向反** — 检查 V 是从表面指向相机,不是反过来
- **极点处失真** — Sphere map 固有问题,接受或切 cube map
- **法线贴图反射不明显** — shininess 太高,法线变化小,反射看不出。增大法线扰动幅度
- **反射在边缘错误** — uv 在边界 clamp 不对,检查 `clamp(0, 1)`
