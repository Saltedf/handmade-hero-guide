# Day 093 · 纹理四边形

> 昨天你画了一个能旋转、能缩放的**实心**矩形——所有像素都是同一种颜色。今天 Casey 加上最后一个魔法:**纹理**(texture)——让矩形每个像素显示不同的颜色,这些颜色来自一张预先画好的图。这就是 sprite 渲染的本质——你的小人、怪物、地面、墙壁,全部是「带纹理的旋转矩形」。今天把这一步做完,你就有一个**完整 2D sprite 渲染器**了。

## 0 · 为什么要有这一天

到目前为止,你的所有渲染对象都是「色块」——纯红、纯绿、纯蓝。但游戏里没有纯色小人——小人是个有头有手有脚的复杂图案。这个图案**怎么从磁盘进到屏幕**?

完整链路:

```
1. 美术画一张 PNG/BMP 图(存在磁盘)
2. 游戏加载它到内存(一个 u8 数组)
3. 渲染时,根据像素的 (u, v) 坐标查这个数组,得到颜色
4. 颜色写到 framebuffer
```

**步骤 3** 是今天要做的核心:**纹理采样**(texture sampling)——给定一个 `[0, 1] × [0, 1]` 的 uv 坐标,从纹理图里查到对应的颜色。

回想 Day 092,我们已经有 `(u, v) ∈ [0, 1]²` 的局部坐标!今天只需要把「填上固定颜色」改成「填上纹理在 (u, v) 处的颜色」。

听起来只多了一步,但这里有几个深度问题:

1. **纹理坐标的方向**:纹理图的 `(0, 0)` 在左上角还是左下角?游戏坐标系的 `(0, 0)` 又在哪?这两个不一致会导致 sprite 颠倒。
2. **整数 vs 浮点 uv**:纹理像素是离散网格(整数索引),uv 是浮点。当 uv = 0.37 时,取哪个像素?最简单的是**最近邻**(取最近整数),但会产生锯齿。高级做法是**双线性插值**(bilinear interpolation)。
3. **透明像素**:PNG 支持 alpha 通道,但「透明像素」在渲染时怎么处理?完全透明不画,半透明混色。这是 Day 095 的核心。
4. **超出 [0, 1] 的 uv**:如果 base 缩放让 uv 跑到 `[0, 2]`,纹理应该平铺(wrap)还是裁剪(clamp)?

这些问题的答案,决定你 sprite 的视觉质量。今天 Casey 把核心做完(最近邻 + clamp),Day 095 补透明处理,Day 109+ 补 mipmapping。

心理锚点:看完今天,你的渲染器能画一张 sprite 图——能加载 BMP/PNG,根据 sprite 的位置、旋转、缩放渲染到 framebuffer。这是一个**完整 2D 渲染器**。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. 在 `Bitmap` 结构体里加上 `width`, `height`, `pixels`(数据),还有 `width_over_2` 等「预计算的倒数」常量(避免每像素除法)。
2. 修改 Day 092 的像素循环:不再填固定颜色,而是用 `(u, v)` 从纹理图查颜色。
3. 处理纹理坐标转换:`uv_to_texel(u, v) = (u * tex_width, v * tex_height)`,然后取整。
4. 处理透明像素:如果纹理的 alpha 是 0,跳过(完全不画);其他情况暂时全部当作不透明(明天 Day 095 补 alpha 混合)。

## 2 · 心智模型

### 费曼类比:把一张贴纸贴到变形的纸上

想象你有一张方形贴纸(纹理),图案是只小猫。你想把它**贴在一个变形的纸上**——这张纸被旋转、缩放、扭曲过。贴完后,纸上的每个位置对应贴纸上的某个点。

你怎么知道纸上位置 `(x, y)` 该显示贴纸上哪个点?

**就是昨天的逆变换!**
1. 算纸上 `(x, y)` 在贴纸坐标系里的位置 `(u, v)`(逆变换)
2. 如果 `(u, v)` 在 `[0, 1] × [0, 1]` 内,贴上贴纸这个点的颜色
3. 如果在外,不贴(或者 wrap,看你设计)

贴纸的「颜色」怎么取?贴纸也是网格图(像素矩阵),`(u, v) ∈ [0, 1]` 对应像素 `(u * tex_w, v * tex_h)`,取最近整数索引的颜色。

### 严谨原理

#### 2.1 纹理在内存里的表示

一张 256×256 的 RGBA 纹理,在内存里就是 `256 * 256 * 4 = 262144` 个字节,每 4 字节一个像素(RGBA),按行优先排列:

```
pixels[y * width + x] = (r, g, b, a)  // 4 个 u8
```

Rust 结构体:

```rust
struct Bitmap {
    width: u32,
    height: u32,
    pixels: Vec<[u8; 4]>,  // 或 Vec<u32>(打包),或 Vec<u8>(连续)
}
```

打包成 u32(`0xAABBGGRR` 在小端序机器上)更高效,因为 CPU 处理 u32 比 4 个 u8 快。

#### 2.2 纹理坐标到像素索引

uv 坐标是 `[0, 1]` 范围内的浮点数。把它转换成像素索引:

```
texel_x = u * tex_width       // 浮点像素坐标
texel_y = v * tex_height
texel_x_int = texel_x as u32  // 取整(最近邻)
texel_y_int = texel_y as u32
pixel = texture.pixels[texel_y_int * tex_width + texel_x_int]
```

**坑:`(0.0, 0.0)` 在哪?** 行业里有两种约定:
- **OpenGL**:纹理 (0, 0) 在**左下角**(y 向上)
- **Direct3D / 大多数图片格式**(PNG/BMP/JPEG):纹理 (0, 0) 在**左上角**(y 向下)

如果你的游戏坐标系 y 向上,纹理 y 向下,渲染时 sprite 会上下颠倒。**修复**:渲染时把 v 取反 `v = 1.0 - v`。

Casey HH 用 y 向下的纹理(跟 BMP 一致),所以纹理 (0,0) 是左上角。

#### 2.3 最近邻采样 vs 双线性插值

**最近邻 (nearest neighbor)**:uv 取最近整数索引,直接查颜色。
- 优点:快,1 次内存访问
- 缺点:放大时像素感强(马赛克),缩小时摩尔纹

**双线性插值 (bilinear interpolation)**:uv 取周围 4 个像素,按 uv 的小数部分插值。

```
fx = texel_x - texel_x_int     // 小数部分(权重)
fy = texel_y - texel_y_int
// 4 个像素
p00 = tex[texel_x_int,     texel_y_int]
p10 = tex[texel_x_int + 1, texel_y_int]
p01 = tex[texel_x_int,     texel_y_int + 1]
p11 = tex[texel_x_int + 1, texel_y_int + 1]
// 双线性插值
top = lerp(p00, p10, fx)       // 上面两个像素水平插值
bot = lerp(p01, p11, fx)       // 下面两个像素水平插值
final = lerp(top, bot, fy)     // 上下垂直插值
```

`lerp(a, b, t) = a + (b - a) * t` 是线性插值。

**今天 Casey 只做最近邻**——足够教学,效率高。Day 109 加双线性。

#### 2.4 边界处理

uv 超出 `[0, 1]` 时(比如 sprite 缩放让 uv 跑到 `[-0.1, 1.1]`)怎么办?

- **clamp**(钳制):把 uv 限制到 `[0, 1]`。边缘像素被拉伸。
- **wrap / repeat**(重复):`u = u - floor(u)`,纹理平铺。地砖、墙纸用这个。
- **mirror**:像镜子一样反弹。少见。

Casey HH 用 clamp(更简单),地砖之类需要 wrap 的 Day 200+ 加。

#### 2.5 完整像素循环

```rust
fn draw_textured_quad(fb: &mut Framebuffer, tex: &Bitmap, origin: Vec2, m: Mat2) {
    // m 已经包含旋转 + 缩放(列向量就是 x_axis 和 y_axis)
    let inv = m.inverse();
    // AABB 略,同 Day 092
    // ...
    let tex_w_f = tex.width as f32;
    let tex_h_f = tex.height as f32;
    for py in min_y..=max_y {
        for px in min_x..=max_x {
            let wx = px as f32 + 0.5;
            let wy = py as f32 + 0.5;
            let dx = wx - origin.x;
            let dy = wy - origin.y;
            let (u, v) = inv.mul_vec(dx, dy);
            if u >= 0.0 && u <= 1.0 && v >= 0.0 && v <= 1.0 {
                // 纹理采样(最近邻)
                let tx = (u * tex_w_f) as u32;
                let ty = (v * tex_h_f) as u32;
                let texel = tex.pixels[(ty * tex.width + tx) as usize];
                if texel[3] > 0 {  // alpha > 0,有内容
                    // 简化版:直接覆盖(明天 Day 095 做 alpha 混合)
                    let color = ((texel[0] as u32) << 16)
                              | ((texel[1] as u32) << 8)
                              | (texel[2] as u32);
                    fb.put(px, py, color);
                }
            }
        }
    }
}
```

**逐行**:
- `inv.mul_vec(dx, dy)` — 像素到局部 uv 的逆变换(同 Day 092)
- `u * tex_w_f` — uv 到纹理像素坐标的转换
- `as u32` — 浮点取整(Rust 向 0 截断,等同于 floor 对正数)。这是**最近邻**——直接丢小数部分
- `texel[3] > 0` — alpha 通道(第 4 字节)大于 0 才画。**今天是硬阈值**(完全透明跳过,其他全部当不透明),明天 Day 095 改成按比例混色
- 颜色打包 `<< 16 | << 8 |` — 把 3 个 u8 拼成 u32(0xRRGGBB)

### Rust 完整实现

```rust
struct Bitmap {
    width: u32,
    height: u32,
    pixels: Vec<[u8; 4]>,  // 每像素 RGBA
}

impl Bitmap {
    fn new_solid(w: u32, h: u32, color: [u8; 4]) -> Self {
        Self { width: w, height: h, pixels: vec![color; (w * h) as usize] }
    }
    fn sample_nearest(&self, u: f32, v: f32) -> [u8; 4] {
        let tx = (u.clamp(0.0, 1.0) * (self.width - 1) as f32) as u32;
        let ty = (v.clamp(0.0, 1.0) * (self.height - 1) as f32) as u32;
        self.pixels[(ty * self.width + tx) as usize]
    }
}

// [Framebuffer / Mat2 / Vec2 同 Day 092]

fn draw_textured_quad(fb: &mut Framebuffer, tex: &Bitmap, origin: Vec2, m: Mat2) {
    let inv = m.inverse();
    // AABB(同 Day 092)
    let corners_local = [(0.0, 0.0), (1.0, 0.0), (1.0, 1.0), (0.0, 1.0)];
    let corners_world: Vec<(f32, f32)> = corners_local.iter().map(|(u, v)| {
        let (dx, dy) = m.mul_vec(*u, *v);
        (origin.x + dx, origin.y + dy)
    }).collect();
    let min_x = corners_world.iter().map(|p| p.0).fold(f32::INFINITY, f32::min).floor() as i32;
    let max_x = corners_world.iter().map(|p| p.0).fold(f32::NEG_INFINITY, f32::max).ceil() as i32;
    let min_y = corners_world.iter().map(|p| p.1).fold(f32::INFINITY, f32::min).floor() as i32;
    let max_y = corners_world.iter().map(|p| p.1).fold(f32::NEG_INFINITY, f32::max).ceil() as i32;
    let min_x = min_x.max(0) as usize;
    let max_x = (max_x as usize).min(fb.width - 1);
    let min_y = min_y.max(0) as usize;
    let max_y = (max_y as usize).min(fb.height - 1);

    for py in min_y..=max_y {
        for px in min_x..=max_x {
            let wx = px as f32 + 0.5;
            let wy = py as f32 + 0.5;
            let (u, v) = inv.mul_vec(wx - origin.x, wy - origin.y);
            if u >= 0.0 && u <= 1.0 && v >= 0.0 && v <= 1.0 {
                let texel = tex.sample_nearest(u, v);
                if texel[3] > 0 {
                    let color = ((texel[0] as u32) << 16) | ((texel[1] as u32) << 8) | (texel[2] as u32);
                    fb.put(px, py, color);
                }
            }
        }
    }
}

fn main() {
    let mut fb = Framebuffer::new(400, 400);
    // 创建一个 4x4 红绿棋盘格纹理
    let mut tex_pixels = Vec::with_capacity(16);
    for y in 0..4 {
        for x in 0..4 {
            let red = if (x + y) % 2 == 0 { [255, 0, 0, 255] } else { [0, 255, 0, 255] };
            tex_pixels.push(red);
        }
    }
    let tex = Bitmap { width: 4, height: 4, pixels: tex_pixels };
    // 在 (50, 50) 画一个 100x100 不旋转的纹理矩形
    let m = Mat2 { m00: 100.0, m10: 0.0, m01: 0.0, m11: 100.0 };
    draw_textured_quad(&mut fb, &tex, Vec2 { x: 50.0, y: 50.0 }, m);
    // 验证:画完后 framebuffer 里应该有红绿交替像素
    let red_count = fb.pixels.iter().filter(|&&p| p == 0xFF0000).count();
    let green_count = fb.pixels.iter().filter(|&&p| p == 0x00FF00).count();
    println!("red: {}, green: {}", red_count, green_count);
    assert!(red_count > 0 && green_count > 0);
    assert!((red_count - green_count).abs() <= 100);  // 接近相等(棋盘格)
}
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

带纹理的旋转矩形(sprite 渲染)是 2D 游戏的**绝对核心**:

1. **角色 sprite**:小人、怪、NPC——每帧动画一张图,根据动画帧索引切纹理
2. **tile 地图**:地砖、墙、装饰物——大量小纹理四边形
3. **粒子效果**:火花、烟雾、爆炸——很多小 sprite
4. **UI 元素**:按钮、血条、图标

**关键概念:sprite sheet / atlas**。多张小图拼成一张大图(减少 GPU 状态切换),渲染时用不同的 uv 范围从同一张图采样。Casey Day 200+ 详细讲。

**性能**。一个商业 2D 游戏一帧可能画 10000+ sprite。每个 sprite 走一遍今天的循环 = 几千万像素操作。优化方法:
- **批处理(batching)**:把多个 sprite 的几何合并成一个大 draw call
- **GPU 化**:Day 235+ 切到 OpenGL,一次 draw call 画上千 sprite
- **dirty rectangle**:只重画屏幕变化的区域

### 3.2 · 🎨 图形学视角

纹理采样是图形学的核心操作。GPU 有专门的**纹理采样单元**(texture sampling unit),硬件实现双线性/三线性/各向异性过滤。

**mipmap**(Day 109+):为了解决「sprite 缩小时摩尔纹」问题,预生成纹理的多个缩小版本(1/2、1/4、1/8...),采样时根据 sprite 在屏幕的大小选合适的层级。

**纹理压缩**(Day 400+):GPU 不能用 JPEG/PNG(解压太慢),用专门的**块压缩格式**(BC1-BC7 / ETC / ASTC)。Casey HH Day 425+ 详细讲。

**sRGB vs Linear**(Day 094-095):纹理图通常存 sRGB(非线性),光照计算必须 Linear。今天 Casey 还没处理这个,Day 094 会专门讲。

### 3.3 · 🐧 Linux 系统编程视角

纹理加载涉及**文件 IO**:

```bash
# Linux 上加载 BMP 的最底层方式
# 1. open(2) 系统调用打开文件
# 2. read(2) 读字节
# 3. close(2) 关闭

strace -e openat,read,close ./your_game 2>&1 | head -20
# 看到 openat("/path/to/sprite.bmp", O_RDONLY) 等系统调用
```

**性能优化:内存映射 (mmap)**。把文件直接映射到进程地址空间,跳过 read 系统调用:

```rust
use std::fs::File;
use memmap2::Mmap;
let f = File::open("sprite.bmp")?;
let mmap = unsafe { Mmap::map(&f)? };
// mmap[..] 就是文件内容,无需 read
```

Casey HH 用 mmap 加载大文件(Day 200+)。Rust 的 `memmap2` crate 是工业标准。

### 3.4 · 🦀 Rust 生态视角

Rust 加载纹理的几个 crate:

1. **`image`** — 通用图像库,支持 PNG/JPEG/BMP/GIF/TGA 等
   ```rust
   use image::GenericImageView;
   let img = image::open("sprite.png")?;
   let rgba = img.to_rgba8();
   let (w, h) = img.dimensions();
   ```
2. **`png`** — 仅 PNG,轻量
3. **`stb_image`**(Rust binding:`stb_image_rust`)— C 库 binding,极快
4. **`zune-png`** — Rust 原生 PNG 解码器,比 `png` 快 2-3 倍

**所有权考虑**:`Bitmap` 持有 `Vec<[u8; 4]>`,这是**独占所有权**。如果你想在多个地方共享同一张纹理(比如 100 个敌人共享一张 sprite),需要:
- `Rc<Bitmap>`(单线程)或 `Arc<Bitmap>`(多线程)—— 引用计数共享
- 或更高级的「资产系统」(Day 200+ Casey 自己写),用代际索引引用纹理

**`unsafe` 边界**:把 `Vec<u8>` 转成 `Vec<[u8; 4]>` 需要 `unsafe`(因为编译器不知道长度是 4 的倍数):

```rust
fn bytes_to_rgba(bytes: Vec<u8>) -> Vec<[u8; 4]> {
    assert!(bytes.len() % 4 == 0);
    let mut result = bytes.into_boxed_slice();
    let ptr = result.as_mut_ptr() as *mut [u8; 4];
    let len = result.len() / 4;
    let capacity = result.len() / 4;
    unsafe {
        std::mem::forget(result);
        Vec::from_raw_parts(ptr, len, capacity)
    }
}
```

`bytemuck` crate 提供安全的 cast 函数,避免手写 unsafe。

## 4 · 认知地图

### 4.1 上级

- **纹理映射 (texture mapping)** — 把 2D 图像贴到几何表面的整套技术
- **采样理论 (sampling theory)** — 离散信号(纹理)和连续信号(uv)之间的转换
- **资产管线 (asset pipeline)** — 从磁盘文件到屏幕像素的完整流水线

### 4.2 同级

| 采样方法 | 质量 | 性能 | 何时用 |
|---|---|---|---|
| 最近邻 | 低(锯齿/摩尔纹) | 极快 | 像素艺术 |
| 双线性 | 中 | 中 | 一般 2D 游戏 |
| 三线性 | 高 | 慢 | mip 层之间插值 |
| 各向异性 | 最高 | 最慢 | 倾斜表面(地面) |

### 4.3 下级

- **uv 坐标** — 纹理空间的 2D 坐标
- **texel** — texture pixel,纹理图的单个像素
- **采样器 (sampler)** — 给定 uv 返回颜色的对象/函数
- **mipmap** — 多层级纹理,防止缩小时摩尔纹
- **alpha 通道** — 第 4 字节,表示透明度

## 5 · 对照与变奏

### CPU 纹理采样 vs GPU 纹理采样

| | CPU | GPU |
|---|---|---|
| 单位 | 1 个像素 / 1 cycle | 几千像素并行 / 1 cycle |
| 缓存 | L1/L2,程序员控制 | 专用 texture cache,2KB-8KB |
| 过滤 | 手写代码 | 硬件单元(TMUs) |
| 适合 | 教学、小分辨率 | 大规模 3D 场景 |

GPU 的纹理采样单元(TMUs)有专门的 cache 和硬件插值器,数十 GB/s 带宽。Casey 在 Day 235+ 切 OpenGL 后,纹理采样从 CPU 软件循环变成 GPU 硬件操作,性能提升 100 倍以上。

### 整数像素 vs 子像素 uv

uv 是连续浮点,但纹理是离散网格。这个不匹配是所有锯齿/摩尔纹的根源。**Nyquist 采样定理**:要无失真重建信号,采样频率必须大于信号最高频率的 2 倍。当 sprite 在屏幕上 < 1 像素时,采样频率不够,产生混叠(aliasing,摩尔纹)。mipmap 是解决方案。

### 历史:纹理映射的发明

1974 年 Ed Catmull(后来 Pixar 创始人)在犹他大学博士论文里发明了纹理映射。当时只用于静态图。1970s 末飞行模拟器开始用。1990s PC 游戏全面采用(Doom 是早期经典)。2000s GPU 把它硬件化。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:如果你的 sprite 在屏幕上是 100×100 像素,但纹理图是 200×200 像素,会出现什么问题?为什么?怎么解决?

**参考解答**:**摩尔纹/锯齿**。sprite 缩小到 50%,每个 sprite 像素覆盖了纹理上 4 个像素(`2×2`)的区域,但最近邻采样只取其中一个,丢失了 75% 的信息。结果是某些 sprite 像素刚好采到亮色,某些采到暗色,产生闪烁的摩尔纹。

**解决**:
1. **双线性插值**:把 4 个像素按位置加权平均,质量提升但慢 4 倍
2. **mipmap**:预算好缩小版本(100×100 的直接采 100×100 那一层),质量最好
3. **简单 box filter**:快速近似——采样时取 2×2 平均

### Lv2 · 动手实践

**题**:实现 `sample_bilinear(&self, u: f32, v: f32) -> [u8; 4]`,在最近邻基础上加双线性插值。测试:对 4×4 棋盘格纹理,uv (0.5, 0.5)(正好在 4 个像素中心)采样,应该是这 4 个像素的平均色。

**参考解答**:

```rust
impl Bitmap {
    fn sample_bilinear(&self, u: f32, v: f32) -> [u8; 4] {
        let xf = u.clamp(0.0, 1.0) * (self.width as f32 - 1.0);
        let yf = v.clamp(0.0, 1.0) * (self.height as f32 - 1.0);
        let x0 = xf.floor() as u32;
        let y0 = yf.floor() as u32;
        let x1 = (x0 + 1).min(self.width - 1);
        let y1 = (y0 + 1).min(self.height - 1);
        let fx = xf - x0 as f32;
        let fy = yf - y0 as f32;
        let p00 = self.pixels[(y0 * self.width + x0) as usize];
        let p10 = self.pixels[(y0 * self.width + x1) as usize];
        let p01 = self.pixels[(y1 * self.width + x0) as usize];
        let p11 = self.pixels[(y1 * self.width + x1) as usize];
        let lerp = |a: u8, b: u8, t: f32| -> u8 {
            (a as f32 + (b as f32 - a as f32) * t).round() as u8
        };
        [
            lerp(lerp(p00[0], p10[0], fx), lerp(p01[0], p11[0], fx), fy),
            lerp(lerp(p00[1], p10[1], fx), lerp(p01[1], p11[1], fx), fy),
            lerp(lerp(p00[2], p10[2], fx), lerp(p01[2], p11[2], fx), fy),
            lerp(lerp(p00[3], p10[3], fx), lerp(p01[3], p11[3], fx), fy),
        ]
    }
}
```

**关键点**:
- 4 次 texture fetch(可能 cache miss,所以比最近邻慢)
- `fx, fy` 是权重——uv 落在像素中心时 fx=0.5
- `lerp` 用浮点算再 round 回 u8(精度损失可接受)
- 边界处理:`x1 = (x0+1).min(width-1)`——防止索引越界

### Lv3 · 迁移设计

**题**:你的渲染器现在只能画矩形 sprite。你想加**三角形 sprite**(比如斜的 roof、地形片段)。三角形和矩形的核心差别是什么?算法该怎么改?

提示:
- 矩形有 4 个角,三角形 3 个
- 矩形的局部坐标是 `(u, v) ∈ [0,1]²`,三角形呢?
- 矩形的逆矩阵是 2×2(假设仿射),三角形同样是 2×2
- 关键:**包含测试**——`(u, v)` 在三角形里 vs 在矩形里,用什么算法?

**提示答案**:
- 三角形定义在它自己的局部坐标里(3 个顶点 `(0,0), (1,0), (0,1)`)
- 局部坐标到 uv 的转换可以用**重心坐标**(barycentric coordinates)
- 包含测试:重心坐标 3 个分量都在 [0, 1] 之间且和 = 1
- Day 200+ 三角形光栅化会详细讲

### 完整可跑示例(用真实 PNG 文件)

```rust
// Cargo.toml
// [dependencies]
// image = "0.25"

use image::GenericImageView;

struct Bitmap {
    width: u32,
    height: u32,
    pixels: Vec<[u8; 4]>,
}

impl Bitmap {
    fn from_image(img: &image::DynamicImage) -> Self {
        let rgba = img.to_rgba8();
        let (w, h) = rgba.dimensions();
        let pixels = rgba.chunks(4).map(|c| [c[0], c[1], c[2], c[3]]).collect();
        Self { width: w, height: h, pixels }
    }
}

fn main() {
    let img = image::open("assets/player.png")
        .expect("需要先放一张 PNG 在 assets/player.png");
    let tex = Bitmap::from_image(&img);
    println!("loaded: {}x{}", tex.width, tex.height);
    // ... 然后用 draw_textured_quad 渲染
}
```

### Troubleshooting

- **sprite 颠倒** — 检查纹理坐标系。BMP/PNG 的 (0,0) 在左上角,如果你按 OpenGL 习惯(y 上)写代码,需要 `v = 1.0 - v`
- **颜色通道错乱** — `0xRRGGBB` vs `0xBBGGGRRR` 取决于端序。x86_64 小端序,`u32` 在内存里是低字节在前
- **sprite 有黑边** — alpha < 255 的像素被当成完全不透明。Day 095 加 alpha 混合解决
- **性能差** — 检查 `tex.pixels[(ty * tex.width + tx) as usize]` 在循环最里层,如果 `tex.pixels` 是 `Vec<[u8;4]>`,每像素一次下标。SIMD 化可以快 4 倍
