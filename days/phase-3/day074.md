# Day 074 · 实体沿楼梯上下移动

> 你 Phase 2 写的「跳跃」只是改 y,把玩家从地板「拉起」到空中,再「落下」。今天 Casey 给你真正的 3D 立体感:让玩家**沿楼梯连续上升**,从一楼走到二楼。这听起来简单,但背后是一个全新的实体类型——**可遍历物(traversable)**——以及一整套「z 插值」的数学。这一节是 2.5D 游戏从「平面」走向「立体」的关键转折。

## 0 · 为什么要有这一天

你 Phase 2 的地图只有一种结构:**平面 tile**。地板是 z=0 的 tile,墙是「不能走」的 tile。玩家要么站在地板上(z=0),要么跳起来(z>0)。这就是全部。

但你想加一个**楼梯**——玩家从一楼(z=0)走到二楼(z=64)。怎么做?

**方案 1(错误):传送门**。玩家走到「楼梯 tile」时,触发脚本:`player.z = 64`。但玩家看到的是「瞬间消失再出现」——毫无立体感。

**方案 2(错误):离散台阶**。把楼梯拆成 5 个 tile,每个 tile 有固定 z。玩家走 tile 1 时 z=0,tile 2 时 z=16,tile 3 时 z=32……玩家看到「跳一下、跳一下」的僵硬移动。

**方案 3(正确):连续插值**。楼梯是一个**斜面**,玩家在楼梯上时,z **连续地**随 x/y 位置变化。玩家走楼梯的感觉就像现实里——一步一步往上,平滑过渡。

Casey 给的解法就是方案 3,核心是一个新的实体类型:**traversable**(可遍历物)。它记录两个端点的 z,玩家在 traversable 上时,z = 两个端点的**线性插值**。

这个抽象非常强大——它不只用于楼梯,还用于:
- **斜坡**:不是 90 度的斜坡
- **台阶**:多个 traversable 串起来
- **电梯**:z 随时间变化(动态 traversable)
- **移动平台**:x/y/z 都随时间变化

心理锚点:看完今天,你能向队友解释「为什么我们的楼梯没有跳跃感」。你能用 Rust 写一个 traversable 系统。你能用 30 秒说清「线性插值」在游戏里的几种应用。

## 1 · Casey 今天做了什么

Casey 在 Day 074 做的事情:

1. **引入 traversable 概念**:一个新的 entity 类型,记录两个端点(start 和 end),每个端点有 (x, y, z)。traversable 是一条 3D 线段,表示「玩家在这条线段上时,z 随线段插值」。
2. **碰撞判定升级**:玩家碰到 traversable 时,**不是阻挡**,而是「踩上去」——玩家的 z 被设置为 traversable 在该位置的插值 z。
3. **写 lerp 函数**:`lerp(a, b, t) = a + (b - a) * t`,t ∈ [0, 1]。这是线段插值的核心。
4. **测试**:玩家走到楼梯入口,z 从 0 平滑变到 64,无卡顿。

具体代码上,Casey 给 entity 加了一个新字段 `traversable: Option<Traversable>`,如果有,玩家踩到时按 traversable 更新 z。

楼梯在游戏里的视觉表现:Casey 在 sprite 上画了一系列「台阶」sprite,看起来像真的楼梯。但游戏逻辑层只是 traversable 线段——视觉是骗你的,逻辑是数学的。这就是游戏开发的经典套路:**视觉用美术表达,逻辑用数学表达**。

## 2 · 心智模型

### 费曼类比:滑梯

想象一个滑梯——从地上到一个小平台。你站在滑梯的任意位置,你的高度由「你在滑梯上的位置」决定。在滑梯底部,高度 0;在滑梯顶部,高度 1 米;在中间,高度 0.5 米。

楼梯就是「双向的滑梯」——你能上去也能下来。每一步都是滑梯的一部分,你的高度严格跟随你的位置。

**Traversable** 就是这个滑梯的**数学化**——两个端点连成的线段,你的高度 = 起点高度 + (终点高度 - 起点高度) × t,t 是你在线段上的位置(0 = 起点,1 = 终点)。

### 严谨原理:线性插值与 traversable

#### 2.1 线性插值(lerp)

`lerp(a, b, t) = a + (b - a) * t`,t ∈ [0, 1]。

- t=0:返回 a
- t=1:返回 b
- t=0.5:返回 (a+b)/2,即中点

`lerp` 是**所有动画和过渡**的基础。Rust 实现:

```rust
fn lerp(a: f32, b: f32, t: f32) -> f32 {
    // 用 mul_add 更精确:`a + (b-a)*t` 等价 `(b-a)*t + a`
    (b - a).mul_add(t, a)
}
```

**为什么用 mul_add?** `a + b * c` 用浮点算的话,先算 `b*c`(一次舍入),再加 `a`(又一次舍入)。`mul_add` 是单条硬件指令 `vfmadd`,只一次舍入,更精确也更快。

#### 2.2 Traversable 的数据结构

```rust
struct Traversable {
    start: Vec3,  // 起点(世界坐标)
    end: Vec3,    // 终点(世界坐标)
    // 通常还有 width: f32(楼梯宽度,可选)
}
```

例:一段从 (0, 0, 0) 到 (0, 10, 32) 的楼梯,玩家在 (0, 5, ?) 时,z 应该是多少?

楼梯方向向量:`end - start = (0, 10, 32) - (0, 0, 0) = (0, 10, 32)`。
玩家在 y=5 的位置,t = (5 - 0) / (10 - 0) = 0.5。
玩家 z = lerp(0, 32, 0.5) = 16。

代码:

```rust
fn traversable_z_at(t: &Traversable, query_pos: Vec2) -> Option<f32> {
    // 1. 算 query_pos 在线段上的投影(用 x/y)
    let start2 = Vec2::new(t.start.x, t.start.y);
    let end2 = Vec2::new(t.end.x, t.end.y);
    let seg = end2.sub(start2);
    let seg_len_sq = seg.dot(seg);  // 线段长度的平方(避免 sqrt)

    if seg_len_sq < 1e-6 {
        return Some(t.start.z);  // 退化情况:起点等于终点
    }

    // 2. 算 query_pos 相对起点的位移
    let d = query_pos.sub(start2);

    // 3. 算 t(线段参数,0 到 1)
    let t_param = d.dot(seg) / seg_len_sq;

    // 4. clamp 到 [0, 1](超出线段范围)
    let t_clamped = t_param.clamp(0.0, 1.0);

    // 5. 线性插值 z
    Some(lerp(t.start.z, t.end.z, t_clamped))
}
```

**每行解释**:
- `seg_len_sq` = `seg.x² + seg.y²`,不取 sqrt 是因为后面只用比例,省一次 sqrt。
- `d.dot(seg) / seg_len_sq` 是「d 在 seg 方向上的投影长度比」——向量投影公式。
- `clamp(0, 1)` 确保玩家超出线段时,仍然算起点或终点(不是外推)。
- `lerp` 算 z。

**这段代码就是「玩家在楼梯上时 z 是多少」的全部数学**。

#### 2.3 玩家踩 traversable 的判定

```rust
fn player_on_traversable(player: &Entity, t: &Traversable) -> bool {
    // 1. 玩家的 x/y 在 traversable 的「走廊」内
    let query = Vec2::new(player.pos.x, player.pos.y);
    let z_at_player = traversable_z_at(t, query);

    if let Some(z_at_player) = z_at_player {
        // 2. 玩家的脚(player.pos.z - half.z) 接近 z_at_player
        let player_feet = player.pos.z - player.half.z;
        (player_feet - z_at_player).abs() < STEP_TOLERANCE
    } else {
        false
    }
}
```

`STEP_TOLERANCE` 是个小值(比如 2-5 px),允许玩家「稍微悬空」也算踩到。这避免浮点误差导致的「踩空」。

#### 2.4 应用 traversable 更新 z

每帧更新玩家时:

```rust
for t in traversables_in_sim_region {
    if player_on_traversable(&player, t) {
        // 玩家踩在 traversable 上,设置 z 为 traversable 在该位置的 z
        let query = Vec2::new(player.pos.x, player.pos.y);
        if let Some(z) = traversable_z_at(t, query) {
            player.pos.z = z + player.half.z;  // z + 半高 = 中心 z
            player.vel.z = 0.0;  // 在 traversable 上时 z 速度归零(不滑下)
            break;
        }
    }
}
```

**关键点**:`player.vel.z = 0.0` 让玩家不会因为重力滑下楼梯。这是楼梯和斜坡的关键差别——楼梯是「梯子」,玩家踩上去就停;斜坡是「滑梯」,可能下滑。

#### 2.5 多个 traversable 串成楼梯

Casey HH 的楼梯通常不是一条线段,而是多条短线段(每个台阶一条)。比如 5 级台阶,5 个 traversable,从 z=0 到 z=64:

```
t0: (0, 0, 0)  → (0, 2, 0)
t1: (0, 2, 0)  → (0, 4, 16)
t2: (0, 4, 16) → (0, 6, 32)
t3: (0, 6, 32) → (0, 8, 48)
t4: (0, 8, 48) → (0, 10, 64)
```

玩家走过去时,先踩 t0(z=0),走到 t1 范围时 z 渐变到 16,再到 t2 时 z=32……每段 traversable 都是平滑过渡。

这就是为什么 Casey 用「多 traversable 串联」而不是「一条 traversable」——视觉上每个台阶之间有「高度突变」(实际是 traversable 之间的边界),玩家走起来感觉「一步一步」。

#### 2.6 为什么 traversable 是「可遍历物」

「traversable」字面意思是「可以走过去的」。在游戏里:

- **不可遍历物(wall)**:玩家撞上就停(或弹回)。
- **可遍历物(traversable)**:玩家可以走上去,不阻挡,反而定义 z。

这两类实体一起组成了 2.5D 世界的几何:

- 墙、岩石、树 → wall
- 楼梯、斜坡、平台 → traversable
- 地面 → 一种特殊的 traversable(z 恒为 0)

Casey 在 Day 079 把「地面」也定义为 traversable,统一抽象。

#### 2.7 数学补充:向量投影

`d.dot(seg) / seg_len_sq` 这个公式来自**向量投影**。

向量 v 在方向 u 上的投影长度 = `v · u / |u|`。如果 u 不是单位向量,要先除以 `|u|`,所以 = `v · u / |u|² = v · u / (u · u)`。

而我们要的是「相对长度比」(0 到 1),所以再除以 `|u|`(线段长度),即 `v · u / |u|²`。

这就是为什么 `seg_len_sq = seg.dot(seg)`,然后 `d.dot(seg) / seg_len_sq` 是「玩家在线段上的参数 t」。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

楼梯和斜坡是 2.5D / 3D 游戏的核心几何元素。Casey 的 traversable 抽象对应业界几个术语:

- **NavMesh 的「link」**:AI 寻路时,楼梯 / 斜坡 / 跳跃点是「特殊的连接」。
- **Unity 的「Terrain」**:连续高度图,玩家 z 由地形决定。
- **Unreal 的「NavModifier」**:特殊区域(楼梯、水、不可走)。
- **Source 引擎的「func_door」/「func_tracktrain」**:动态 elevators 和平台。

Casey 的 traversable 是这些工业方案的最简版,但抓住了核心:**z 是位置的函数**。

**应用场景**:

- **平台跳跃(Celeste、Mario)**:平台是 traversable,玩家从平台跳到平台。
- **暗黑破坏神**:俯视角度,有楼梯到地下城。
- **Dark Souls**:复杂的室内外过渡,大量 traversable。
- **Hollow Knight**:2D 平台,本质是 traversable 的特殊情况(y 是高度的 2D 版本)。

#### 关键决策:踩 vs 撞

玩家碰到 traversable 时,游戏要做**踩**还是**撞**?

- 踩:玩家在 traversable 上方(z 高于 traversable 顶面),更新 z 到 traversable。
- 撞:玩家在 traversable 下方(从下面钻楼梯),阻挡。

判定:**看玩家 z 和 traversable z 的差**。如果玩家脚 z > traversable z + tolerance → 踩。如果玩家头 z < traversable z → 撞(玩家在楼梯下方)。

Casey HH 简化为「只踩不撞」,因为大多数楼梯玩家从上面走。后期(Day 380+)才加完整的「踩 / 撞」分支。

### 3.2 · 🎨 图形学视角

`lerp` 在图形学里**无处不在**:

- **纹理采样**:双线性插值 = 两次 lerp(横向 + 纵向)。
- **顶点颜色**:Gouraud 着色,顶点颜色在三角形内 lerp。
- **法线插值**:Phong 着色,法线在像素间 lerp。
- **深度插值**:光栅化时,三角形顶点的 z 在像素间 lerp(透视校正后)。
- **动画**:骨骼动画的关键帧之间 lerp(或 slerp,球面 lerp)。
- **Tween**:UI 动画的 ease-in / ease-out,本质是 lerp + 非线性 t。

**ease 函数**:lerp 的 t 不是线性,而是经过 ease 函数变换:

```rust
fn ease_in_out(t: f32) -> f32 {
    // Smoothstep: 3t² - 2t³
    t * t * (3.0 - 2.0 * t)
}
```

UI 动画里,lerp(a, b, ease_in_out(linear_t)) 给出平滑的「缓入缓出」效果。

#### Traversable 在 3D 渲染里

真 3D 游戏里,**地形(mesh)本身就是 traversable**。每个三角形是一个 traversable 面,玩家踩上去时算「点到平面」的投影。

```rust
// 点 P 到三角形 (A, B, C) 的高度
fn triangle_height_at(p: Vec2, a: Vec3, b: Vec3, c: Vec3) -> Option<f32> {
    // 重心坐标(barycentric)
    let ab = b.sub(a);
    let ac = c.sub(a);
    let ap = Vec3::new(p.x - a.x, p.y - a.y, 0.0);
    // ... 计算 (u, v),u 是 AB 方向权重,v 是 AC 方向权重
    // 如果 u >= 0 && v >= 0 && u + v <= 1,P 在三角形内
    // z = a.z + u * (b.z - a.z) + v * (c.z - a.z)
}
```

这是 3D 地形系统的核心。Casey HH 仍然是 2.5D(只有 traversable 线段),但数学思路一致。

### 3.3 · 🐧 Linux 系统编程视角

跟 Linux 没直接关系。但 traversable 概念在 Linux 里有类似的「投影」:

**管道(pipe)的环形缓冲区**——读写指针是「在缓冲区上的位置」,buffer 长度固定,读写循环。这跟 traversable 的「线段 + t 参数」类似——一个一维空间。

**文件偏移(file offset)**:`lseek(fd, offset, SEEK_SET)` 设置文件偏移。文件是一个「一维 traversable」,每个 offset 对应一个 byte。

#### Linux 调试技巧:可视化 traversable

### 3.4 · 🦀 Rust 生态视角

#### Rust 写 traversable 系统

```rust
#[derive(Copy, Clone, Debug)]
struct Traversable {
    start: Vec3,
    end: Vec3,
}

impl Traversable {
    fn new(start: Vec3, end: Vec3) -> Self { Self { start, end } }

    // 玩家在 x/y 位置时,traversable 上的 z
    fn z_at(&self, query: Vec2) -> Option<f32> {
        let start2 = Vec2::new(self.start.x, self.start.y);
        let end2 = Vec2::new(self.end.x, self.end.y);
        let seg = end2.sub(start2);
        let seg_len_sq = seg.dot(seg);
        if seg_len_sq < 1e-6 {
            return Some(self.start.z);
        }
        let d = query.sub(start2);
        let t = (d.dot(seg) / seg_len_sq).clamp(0.0, 1.0);
        Some(lerp(self.start.z, self.end.z, t))
    }
}

#[inline]
fn lerp(a: f32, b: f32, t: f32) -> f32 {
    (b - a).mul_add(t, a)
}
```

#### Rust 的所有权:traversable 数组

```rust
struct World {
    traversables: Vec<Traversable>,  // 所有楼梯、斜坡
    entities: Vec<Entity>,           // 玩家、怪
}

impl World {
    fn update_player_on_traversable(&mut self, player_idx: usize) {
        // 注意:不能同时 immutable_borrow self.traversables 和 mutable_borrow self.entities
        // 用索引避免
        let player_pos = self.entities[player_idx].pos;
        let player_half_z = self.entities[player_idx].half.z;

        for t in &self.traversables {
            let query = Vec2::new(player_pos.x, player_pos.y);
            if let Some(z) = t.z_at(query) {
                let feet = player_pos.z - player_half_z;
                if (feet - z).abs() < STEP_TOLERANCE {
                    self.entities[player_idx].pos.z = z + player_half_z;
                    self.entities[player_idx].vel.z = 0.0;
                    return;
                }
            }
        }
    }
}
```

**注意**:Rust 借用规则让你**不能同时遍历 traversables(immutable)和修改 entities(mutable)**。常见解法是「先读再写」——读阶段只读不改,把要改的 entity 信息暂存;写阶段才修改。Casey HH 在 C 里没这种限制,但 Rust 强迫你写出更安全的代码。

#### Rust 的 enum 表达「可能是 traversable,可能是 wall」

```rust
enum Volume {
    Wall(AABB3),         // 阻挡
    Traversable(Trav),   // 可踩
}

struct Entity {
    pos: Vec3,
    vel: Vec3,
    half: Vec3,
    volume: Volume,
}
```

这是 Rust enum 的**典型用法**——表达「这个 entity 是某一种」,每种有不同数据。C 里要用 tagged union,Rust 自动。

#### Rust 的 iter 工具

```rust
// 找玩家踩到的第一个 traversable
let on_trav = world.traversables.iter().find_map(|t| {
    let q = Vec2::new(player.pos.x, player.pos.y);
    t.z_at(q).and_then(|z| {
        let feet = player.pos.z - player.half.z;
        if (feet - z).abs() < STEP_TOL { Some(z) } else { None }
    })
});
```

`find_map` 是 Rust iterator 的一个组合子——遍历、对每个元素做返回 Option 的闭包,返回第一个 Some。**一行代码替代三行 for 循环**。

## 5 · 对照与变奏

### 不同插值方法

| 方法 | 公式 | 用在哪 |
|---|---|---|
| lerp(线性)| `a + (b-a)*t` | 颜色、位置、UI |
| slerp(球面)| 球面插值 | 旋转(四元数)|
| Smoothstep | `t²(3-2t)` | ease-in-out |
| Cubic Bezier | 4 控制点 | 曲线路径 |
| Catmull-Rom | 样条 | 平滑路径 |

### 历史:从 sprite 楼梯到 mesh 楼梯

- **1980s**:sprite 楼梯——一张图,玩家走到「楼梯 tile」就触发脚本改 z。视觉是 sprite,逻辑是 hard-coded。
- **1990s**:BSP 楼梯——真 3D,但开发者要手动搭 brush。
- **2000s**:Terrain + NavMesh——大世界,自动寻路。
- **2020s**:程序化生成 + ML 寻路。

Casey HH 用的是 1980s 风格(traversable 线段),但**思想**和现代引擎一致——z 是位置的函数。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Casey 用「多段 traversable」表示楼梯,而不是「一条 traversable」?

**参考解答**:视觉效果。一条 traversable 表示「完美斜面」,玩家走上去感觉是滑梯,没有「一步一步」的台阶感。多段 traversable 每段是一个台阶,玩家在段与段之间有**短暂的高度突变**(其实是边界)——视觉上看起来像真楼梯,玩家心理上是「踩到台阶」。

技术上,一条 traversable 也能工作(z 平滑变化),但**手感**差。游戏开发经常这样:**视觉和手感**比技术简洁性更重要。

### Lv2 · 动手实践

**题**:在 Rust 项目里实现 Traversable 和 z_at 函数。写一个 main,模拟玩家沿楼梯移动:
- 楼梯:从 (0, 0, 0) 到 (0, 10, 32)
- 玩家从 y=0 走到 y=10,每步 1,共 11 步
- 每步打印玩家 y 和当前 z

完成标准:看到 z 从 0 平滑变到 32。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
    fn dot(self, o: Self) -> f32 { self.x * o.x + self.y * o.y }
}

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }

#[derive(Copy, Clone, Debug)]
struct Traversable { start: Vec3, end: Vec3 }

impl Traversable {
    fn z_at(&self, query: Vec2) -> Option<f32> {
        let s2 = Vec2::new(self.start.x, self.start.y);
        let e2 = Vec2::new(self.end.x, self.end.y);
        let seg = e2.sub(s2);
        let len_sq = seg.dot(seg);
        if len_sq < 1e-6 { return Some(self.start.z); }
        let d = query.sub(s2);
        let t = (d.dot(seg) / len_sq).clamp(0.0, 1.0);
        // lerp(start.z, end.z, t)
        Some(self.start.z + (self.end.z - self.start.z) * t)
    }
}

fn main() {
    let stair = Traversable {
        start: Vec3 { x: 0.0, y: 0.0, z: 0.0 },
        end:   Vec3 { x: 0.0, y: 10.0, z: 32.0 },
    };
    println!(" y  |  z");
    println!("----+----");
    for step in 0..=10 {
        let y = step as f32;
        let z = stair.z_at(Vec2::new(0.0, y)).unwrap();
        println!("{:2.0}  | {:5.2}", y, z);
    }
}
```

----+----

 3  |  9.60

## 8 · Rust / Arch 落地代码

### 完整可跑代码

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
    fn dot(self, o: Self) -> f32 { self.x.mul_add(o.x, self.y * o.y) }
}

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }

#[inline]
fn lerp(a: f32, b: f32, t: f32) -> f32 { (b - a).mul_add(t, a) }

#[derive(Copy, Clone, Debug)]
struct Traversable { start: Vec3, end: Vec3 }

impl Traversable {
    fn z_at(&self, query: Vec2) -> Option<f32> {
        let s2 = Vec2::new(self.start.x, self.start.y);
        let e2 = Vec2::new(self.end.x, self.end.y);
        let seg = e2.sub(s2);
        let len_sq = seg.dot(seg);
        if len_sq < 1e-6 { return Some(self.start.z); }
        let d = query.sub(s2);
        let t = (d.dot(seg) / len_sq).clamp(0.0, 1.0);
        Some(lerp(self.start.z, self.end.z, t))
    }
}

const STEP_TOL: f32 = 5.0;

#[derive(Copy, Clone, Debug)]
struct Player { pos: Vec3, vel: Vec3, half_z: f32 }

fn main() {
    let stair = Traversable {
        start: Vec3 { x: 0.0, y: 0.0, z: 0.0 },
        end:   Vec3 { x: 0.0, y: 10.0, z: 32.0 },
    };

    let mut player = Player {
        pos: Vec3 { x: 0.0, y: 0.0, z: 32.0 },  // half_z=32,脚 z=0
        vel: Vec3 { x: 0.0, y: 1.0, z: 0.0 },   // y 方向移动
        half_z: 32.0,
    };

    let dt = 1.0 / 60.0;
    for frame in 0..10 * 60 {
        // 玩家按 y 方向移动
        player.pos.y += player.vel.y * dt;
        // 检查 traversable
        let q = Vec2::new(player.pos.x, player.pos.y);
        if let Some(z_ground) = stair.z_at(q) {
            let feet = player.pos.z - player.half_z;
            if (feet - z_ground).abs() < STEP_TOL {
                player.pos.z = z_ground + player.half_z;
                player.vel.z = 0.0;
            }
        }
        // 每 60 帧打印一次
        if frame % 60 == 0 {
            println!("帧 {:3}: 玩家 (x={:.2}, y={:.2}, z={:.2})",
                frame, player.pos.x, player.pos.y, player.pos.z);
        }
        if player.pos.y > 10.0 { break; }
    }
}
```

**预期输出**(节选):
```
帧   0: 玩家 (x=0.00, y=0.00, z=32.00)
帧  60: 玩家 (x=0.00, y=1.00, z=35.20)
帧 120: 玩家 (x=0.00, y=2.00, z=38.40)
...
帧 540: 玩家 (x=0.00, y=9.00, z=60.80)
帧 600: 玩家 (x=0.00, y=10.00, z=64.00)
```

可以看到 z 从 32(中心 z,脚 z=0)平滑变化到 64(脚 z=32)。
