# Day 077 · 实体接地点

> 你 Phase 2 的玩家「站在地板上」是什么意思?当时的代码是 `if player.y >= floor_y { /* 站着 */ }`——简单粗暴。但今天 Casey 把它正式化:每个 entity 有一个**接地点(ground point)**,就是它的「脚底中心」,通过这点判断它是否踩在地面上。这个抽象让你能优雅处理「站在平台」「站在楼梯」「悬空下落」三种状态,是平台游戏物理的核心。

## 0 · 为什么要有这一天

你的玩家在 2.5D 世界里跳了一下。他**怎么知道何时落地**?

最朴素的做法:每帧检查 `pos.z` 是否 `<= ground_z`,如果是,设 `pos.z = ground_z`,`vel.z = 0`。但「ground_z」是什么?

- 一楼地板的 z?0。
- 二楼地板的 z?64。
- 楼梯上某位置的 z?lerp 后的值。
- 一个移动平台的 z?平台的当前 z。

玩家**踩在哪里**取决于脚下有什么——可能是地板、楼梯、平台。这就是**接地点**的概念:**玩家脚下的那一点,以及那一点对应的支持物(support)**。

Casey 今天把这个概念正式化:
- 接地点 = `(pos.x, pos.y, pos.z)`(因为 pos.z 是脚)
- 每帧从所有 traversable 里找「玩家 (x, y) 位置上最高的 z」作为 ground_z
- 玩家是否踩着 = `pos.z >= ground_z - STEP_TOL`(脚等于或略低于地面)

这个抽象让你能:
- 跳跃后准确落地
- 上楼梯时连续更新脚 z
- 站在移动平台上时随平台移动
- 走出平台边缘时进入悬空状态

心理锚点:看完今天,你能用 30 秒解释「玩家踩着」的判定算法。你能用 Rust 实现重力下落 + 落地。你知道平台游戏所有「踩 / 悬空 / 下落」状态的代码逻辑。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. **定义接地点**:`(pos.x, pos.y, pos.z)`,因为 Casey 的 pos.z 是脚(见 Day 076)。
2. **写 ground_z_at 函数**:遍历所有 traversable,找玩家 (x, y) 位置上的最高 z。
3. **写 update_player_z**:每帧根据玩家状态(踩着 / 悬空)更新 z。踩着 → z 跟随地面;悬空 → 重力下落。
4. **加 is_on_ground 标志**:玩家状态机的一部分。

这是平台游戏物理的核心,**所有平台游戏**(Mario、Celeste、Hollow Knight、Ori)都做这件事。Casey 的实现极简但完整。

## 2 · 心智模型

### 费曼类比:踩着 vs 悬空

想象你站在地板上。你的脚感觉地板的反作用力——你知道你**踩着**。

现在你跳起来。你的脚感觉不到任何东西——你**悬空**。重力把你往下拉。

你落到地板——脚再次感觉到反作用力——你**又踩着了**。

游戏里玩家没有「感觉」,但我们可以**算**:

- **踩着** = 脚 z(`pos.z`)≥ 地面 z(`ground_z_at(x, y)`)- 容忍
- **悬空** = 脚 z < 地面 z - 容忍

`STEP_TOL` 是容忍值(比如 1 像素),允许浮点误差。

### 严谨原理

#### 2.1 ground_z_at:找脚下地面的 z

```rust
fn ground_z_at(world: &World, x: f32, y: f32) -> f32 {
    let mut max_z = 0.0;  // 默认地面 z=0
    for t in &world.traversables {
        if let Some(z) = t.z_at(Vec2::new(x, y)) {
            if z > max_z {
                max_z = z;
            }
        }
    }
    max_z
}
```

**为什么取 max?** 玩家可能在两层楼的同一 (x, y)——一楼 z=0 和二楼 z=64。物理上,玩家**踩在更高的那个**(因为他不能穿过地板)。

**默认 z=0**:如果没有 traversable,认为是「无限大的地面在 z=0」,玩家踩 z=0。

#### 2.2 玩家状态:踩着 vs 悬空

```rust
#[derive(Copy, Clone, Debug, PartialEq)]
enum PlayerState {
    OnGround,    // 踩着
    InAir,       // 悬空
}

fn update_player_z(player: &mut Player, world: &World, dt: f32) {
    let ground_z = ground_z_at(world, player.pos.x, player.pos.y);

    if player.pos.z >= ground_z - STEP_TOL {
        // 踩着(脚等于或略低于地面)
        player.pos.z = ground_z;
        player.vel.z = 0.0;
        player.state = PlayerState::OnGround;
    } else {
        // 悬空,施加重力
        player.vel.z -= GRAVITY * dt;  // GRAVITY = 980 px/s²
        player.pos.z += player.vel.z * dt;
        player.state = PlayerState::InAir;
    }
}
```

**关键点**:
- `player.pos.z >= ground_z - STEP_TOL`:允许玩家脚 z 略低于地面(浮点误差或刚落地)算踩着。
- 踩着时 `vel.z = 0`:防止「累积速度」(如果踩着时仍有向下速度,落地时被设为 0)。
- 悬空时 `vel.z -= GRAVITY * dt`:重力是加速度,z 方向减(向下)。

#### 2.3 跳跃

```rust
fn jump(player: &mut Player) {
    if player.state == PlayerState::OnGround {
        player.vel.z = JUMP_VELOCITY;  // 比如 +500 px/s
        player.state = PlayerState::InAir;
    }
}
```

**只能在地面跳**。这是平台游戏的经典约定——「空中跳」是某些游戏(超级马里奥 2)的特殊能力,但 Casey 默认不允许。

**为什么 JUMP_VELOCITY 是正值?** 因为 z 向上是正。`vel.z = +500` 表示「向上 500 px/s」,然后重力让 `vel.z` 减少,直到玩家到达最高点(`vel.z = 0`),然后下落(`vel.z < 0`)。

#### 2.4 跳跃高度的计算

跳跃高度公式(初速度 v0,重力 g):

```
最高点时 vel.z = 0:
0 = v0 - g * t_to_apex
t_to_apex = v0 / g

跳跃高度 h:
h = v0 * t_to_apex - 0.5 * g * t_to_apex²
  = v0 * (v0/g) - 0.5 * g * (v0/g)²
  = v0²/g - 0.5 * v0²/g
  = 0.5 * v0² / g
```

代入 v0=500, g=980:
```
h = 0.5 * 500² / 980 = 0.5 * 250000 / 980 = 127.55 像素
```

约 127 像素的跳跃高度——能跳过普通墙(64 像素),跳不上高墙(128 像素)。这就是游戏感的「跳跃高度」决定方式。

#### 2.5 二段跳

```rust
fn jump(player: &mut Player) {
    match player.state {
        PlayerState::OnGround => {
            player.vel.z = JUMP_VELOCITY;
            player.state = PlayerState::InAir;
            player.jumps_remaining = 1;  // 还能跳一次
        }
        PlayerState::InAir if player.jumps_remaining > 0 => {
            player.vel.z = JUMP_VELOCITY * 0.8;  // 二段跳力度小一点
            player.jumps_remaining -= 1;
        }
        PlayerState::InAir => {
            // 空中且没二段跳,不能跳
        }
    }
}
```

`jumps_remaining` 是状态机的一部分,落地时重置。

#### 2.6 多个支持物:standing on

玩家可能踩在不同东西上:

- 踩地板(ground z=0)
- 踩楼梯(traversable)
- 踩平台(移动 traversable)
- 踩另一个 entity 的头(高级玩法)

Casey HH 简化:踩 traversable(包括地板、楼梯、平台)。**踩另一个 entity**是高级玩法,需要 entity 互相感知,Day 380+ 才做。

#### 2.7「穿过平台」的边缘情况

如果玩家从平台下方跳起,头碰到平台底面,会发生什么?

简化版:平台是个 traversable,玩家从下面碰时,**撞墙响应**(阻挡)。

完整版:某些平台是「单向」(one-way)——只能从上踩,可以从下穿过。Casey 在 Day 380+ 加这个特性。判定:**只有玩家脚 z 接近平台顶 z(从上往下接近)才算踩,玩家头在平台下面时不算撞**。

```rust
fn check_one_way_platform(player: &Player, platform_z: f32) -> bool {
    let feet = player.pos.z;
    let feet_prev = player.pos.z - player.vel.z * dt;  // 上一帧的脚 z
    // 玩家从上方接近(脚从高于 platform_z 降到 platform_z 附近)
    feet_prev >= platform_z - STEP_TOL && feet <= platform_z + STEP_TOL
}
```

`feet_prev >= platform_z` 保证玩家上一帧在平台上方(不是从下方钻)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**接地点是平台游戏的灵魂**。每个平台游戏都解决这五个问题:

1. **何时算踩着**?(ground detection)
2. **跳跃高度多少**?(jump arc tuning)
3. **空中能否改变方向**?(air control)
4. **跳跃按键长按 vs 短按高度不同**?(variable jump height)
5. **coyote time 多长**?(走出平台后仍可跳)

这五个问题合起来叫**游戏手感(game feel)**。Casey HH 的接地点 + 简单跳跃是「最小可用」,真实平台游戏(Celeste、Hollow Knight)在这些细节上投入大量调参时间。

#### Coyote time(土狼时间)

```rust
const COYOTE_TIME: f32 = 0.1;  // 100ms

struct Player {
    // ...
    time_since_left_ground: f32,
}

fn update(player: &mut Player, dt: f32) {
    if player.state == PlayerState::OnGround {
        player.time_since_left_ground = 0.0;
    } else {
        player.time_since_left_ground += dt;
    }
}

fn jump(player: &mut Player) {
    let can_jump = player.state == PlayerState::OnGround
        || player.time_since_left_ground < COYOTE_TIME;
    if can_jump {
        player.vel.z = JUMP_VELOCITY;
    }
}
```

#### Variable jump height

```rust
// 跳跃键松开时,如果还在上升,把 vel.z 减半
fn release_jump(player: &mut Player) {
    if player.vel.z > 0.0 {
        player.vel.z *= 0.5;
    }
}
```

让玩家「短按跳低,长按跳高」。

#### Jump buffer

```rust
const JUMP_BUFFER: f32 = 0.1;  // 100ms

// 玩家按跳跃时,如果还不能跳(在空中),记录「想跳」
fn press_jump(player: &mut Player) {
    if player.state == PlayerState::OnGround {
        do_jump(player);
    } else {
        player.jump_buffer_timer = JUMP_BUFFER;
    }
}

// 落地时,如果 jump_buffer 还没过期,自动跳
fn on_land(player: &mut Player) {
    if player.jump_buffer_timer > 0.0 {
        do_jump(player);
        player.jump_buffer_timer = 0.0;
    }
}
```

让玩家「提前按跳,落地立刻跳」,感觉响应快。

### 3.2 · 🎨 图形学视角

**接地点在 3D 渲染里**:每个 entity 都有「ground point」,渲染时 sprite 的底边对齐 ground point。

**阴影渲染**:阴影画在 ground point 的 (x, y) 位置,大小根据 entity 距 ground 的距离变化(悬空越高,阴影越小越淡)。

```rust
fn draw_shadow(entity: &Entity, ground_z: f32) {
    let height_above_ground = entity.pos.z - ground_z;
    let shadow_scale = 1.0 - height_above_ground / 100.0;  // 越高阴影越小
    let shadow_alpha = 1.0 - height_above_ground / 200.0;  // 越高越淡
    draw_ellipse_at(entity.pos.x, entity.pos.y, shadow_scale, shadow_alpha);
}
```

这是 3D 游戏的**必备**技巧——让玩家直觉感知高度。

**Billboard 阴影**:真 3D 游戏里,阴影是「物体在地面上的投影」。渲染时把物体的 silhouette 投影到地面,生成阴影 mesh。Phase 5 切 OpenGL 后会用到。

### 3.3 · 🐧 Linux 系统编程视角

跟 Linux 没直接关系。但**「状态机」是 Linux 内核的核心模式**:

- **进程状态**:R / S / D / Z / T(running / sleeping / disk wait / zombie / stopped)。
- **网络连接状态**:TCP 的 11 个状态(ESTABLISHED / TIME_WAIT / ...),`netstat -an` 看。
- **文件描述符**:open / read / write / close 的状态机。

接地点 + PlayerState 是同样的模式——**有限状态机**(FSM)。理解游戏里的状态机,你看 Linux 内核代码也会更顺。

#### Linux 工具:状态可视化

```bash

# 看 TCP 状态

```

### 3.4 · 🦀 Rust 生态视角

#### Rust 写状态机

Rust 的 enum 是表达状态机的完美工具:

```rust
enum PlayerState {
    OnGround,
    InAir { jumps_remaining: u32 },  // 带数据的状态
    WallSliding { wall_normal: Vec2 },
    Dashing { timer: f32 },
}

fn update(player: &mut Player, dt: f32) {
    match player.state {
        PlayerState::OnGround => { /* ... */ }
        PlayerState::InAir { jumps_remaining } => { /* ... */ }
        PlayerState::WallSliding { wall_normal } => { /* ... */ }
        PlayerState::Dashing { timer } => { /* ... */ }
    }
}
```

Rust 编译器强制你**match 所有分支**——漏一个就编译失败。这就是「make invalid state unrepresentable」的精髓。

#### Rust 的 `enum` + `match` 优势对比

| 语言 | 状态机表达 |
|---|---|
| Rust | enum + match,编译期检查穷尽性 |
| C | enum + switch,运行时可能漏分支 |
| C++ | std::variant + std::visit,接近 Rust |
| Python | 字符串字段 + if/elif,无类型保证 |
| Go | iota + switch,接近 C |

Rust 的 enum 是 sum type,**正确性最高**。

#### Rust 工具:状态变化追踪

```rust
#[derive(Debug)]
struct Player {
    pos: Vec3,
    vel: Vec3,
    state: PlayerState,
    state_changed_at: f32,  // 进入当前状态的时间
}

impl Player {
    fn transition_to(&mut self, new_state: PlayerState, current_time: f32) {
        println!("[{:6.3}] state: {:?} -> {:?}", current_time, self.state, new_state);
        self.state = new_state;
        self.state_changed_at = current_time;
    }
}
```

调试时打印状态转换,像 log 一样追溯玩家行为。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:`STEP_TOL` 为什么不设为 0(完全精确)?

**参考解答**:浮点误差。玩家落地时,`pos.z` 可能是 0.0001 或 -0.0001(因为重力下落 + 碰撞修正的浮点运算)。如果 `STEP_TOL = 0`,判定 `pos.z >= ground_z - 0` 可能误判为悬空(因为 pos.z 略小于 ground_z)。设 `STEP_TOL = 1`(像素),允许 ±1 像素误差,玩家稳定踩着。

### Lv2 · 动手实践

**题**:实现完整的玩家跳跃:
- GRAVITY = 980 px/s²
- JUMP_VELOCITY = 500 px/s
- 模拟 1 秒(60 帧),玩家从地面跳起
- 每帧打印 z 和 state

完成标准:看到 z 上升到 ~127,然后下落回 0,state 切换 OnGround → InAir → OnGround。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 { fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } } }

#[derive(Copy, Clone, Debug, PartialEq)]
enum State { OnGround, InAir }

const GRAVITY: f32 = 980.0;
const JUMP_VEL: f32 = 500.0;
const STEP_TOL: f32 = 1.0;

struct Player {
    pos: Vec3,
    vel: Vec3,
    state: State,
}

impl Player {
    fn update(&mut self, ground_z: f32, dt: f32) {
        if self.pos.z >= ground_z - STEP_TOL && self.vel.z <= 0.0 {
            self.pos.z = ground_z;
            self.vel.z = 0.0;
            self.state = State::OnGround;
        } else {
            self.vel.z -= GRAVITY * dt;
            self.pos.z += self.vel.z * dt;
            self.state = State::InAir;
        }
    }

    fn jump(&mut self) {
        if self.state == State::OnGround {
            self.vel.z = JUMP_VEL;
            self.state = State::InAir;
        }
    }
}

fn main() {
    let mut p = Player {
        pos: Vec3::new(0., 0., 0.),
        vel: Vec3::new(0., 0., 0.),
        state: State::OnGround,
    };
    let dt = 1.0 / 60.0;

    p.jump();
    for frame in 0..60 {
        p.update(0.0, dt);
        println!("帧 {:2}: z = {:6.2}, vel.z = {:6.2}, state = {:?}",
            frame, p.pos.z, p.vel.z, p.state);
        if p.state == State::OnGround { break; }
    }
}
```

## 8 · Rust / Arch 落地代码

```rust
#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 { fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } } }

#[derive(Copy, Clone, Debug, PartialEq)]
enum State { OnGround, InAir }

const GRAVITY: f32 = 980.0;
const JUMP_VEL: f32 = 500.0;
const STEP_TOL: f32 = 1.0;

struct Player {
    pos: Vec3,
    vel: Vec3,
    state: State,
    time_since_left_ground: f32,
}

impl Player {
    fn update(&mut self, ground_z: f32, dt: f32) {
        let was_on_ground = self.state == State::OnGround;

        if self.pos.z >= ground_z - STEP_TOL && self.vel.z <= 0.0 {
            self.pos.z = ground_z;
            self.vel.z = 0.0;
            self.state = State::OnGround;
            self.time_since_left_ground = 0.0;
        } else {
            self.vel.z -= GRAVITY * dt;
            self.pos.z += self.vel.z * dt;
            self.state = State::InAir;
            if was_on_ground {
                self.time_since_left_ground = 0.0;
            } else {
                self.time_since_left_ground += dt;
            }
        }
    }

    fn jump(&mut self) {
        // Coyote time: 离开地面后 100ms 仍可跳
        let coyote_ok = self.state == State::OnGround
            || self.time_since_left_ground < 0.1;
        if coyote_ok {
            self.vel.z = JUMP_VEL;
            self.state = State::InAir;
            self.time_since_left_ground = 1.0;  // 防止重复触发
        }
    }
}

fn main() {
    let mut p = Player {
        pos: Vec3::new(0., 0., 0.),
        vel: Vec3::new(0., 0., 0.),
        state: State::OnGround,
        time_since_left_ground: 0.0,
    };
    let dt = 1.0 / 60.0;

    p.jump();
    let mut max_z = 0.0;
    for frame in 0..120 {
        p.update(0.0, dt);
        max_z = max_z.max(p.pos.z);
        if p.state == State::OnGround && frame > 0 {
            println!("落地于帧 {}:最高点 z = {:.2}", frame, max_z);
            break;
        }
    }
}
```

**Troubleshooting**:
- 玩家不落地 — 检查 ground_z 算的对不对
- 玩家穿透地面 — 检查 STEP_TOL,以及落地判定 `vel.z <= 0.0`(下落时才检查)
- 跳跃无限高 — vel.z 没限制,可以加 `vel.z = vel.z.max(-1500.0)`(终止速度)
