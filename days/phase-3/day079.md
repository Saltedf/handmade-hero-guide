
# Day 079 · 定义地面

> 你 Phase 2 的「地面」是什么?是 z=0 这个隐含假设——所有 entity 默认站在 z=0。今天 Casey 把这个隐含假设**正式化**:地面也是一个 entity,有 z、有材质、有面积。这一抽象让多楼层建筑成为现实——一楼地面 z=0,二楼地面 z=64,各自独立。把「地面」从隐含规则变成显式数据,是游戏引擎架构的成熟标志。

## 0 · 为什么要有这一天

让我们从一个让你抓狂的 bug 开始,看「地面」这件事在你的代码里是怎么变复杂的。

你的 Phase 2 游戏跑得不错——玩家在草地上走来走去,撞怪、捡道具、过关。整个世界建立在一条隐含规则上:**「地面就是 z=0」**。玩家 pos.z 一直是 0,重力让玩家「贴」在 z=0 上。这条规则在你的代码里到处都是:

```rust
if player.pos.z == 0.0 {
    // 站在地面
    player.vel_z = 0.0;
}
```

直到有一天你决定加一个**两层的副本**——一楼是石板地,玩家踩着一楼走到中央有个楼梯,沿着楼梯上到二楼木地板,二楼有 Boss。你坐下来开始写代码:

```rust
// 玩家在 (50, 50),踩在一楼
player.pos.z = 0.0;  // 草地
// 玩家走楼梯到 (60, 60)
// 二楼在 z=64
player.pos.z = ???;  // 这里该写多少?
```

**你愣住了**。你代码里**没有「二楼」这个概念**。你的世界假设 z=0 是唯一地面。如果你想加二楼,你必须改三件事:
1. `player.pos.z = 64.0`——但这只是个数字,没有「二楼是个 floor」的概念
2. 玩家从二楼边缘走出时怎么知道要掉下来?你的代码假设 z 永远等于「当前 ground z」,但「当前 ground z」根本不是变量,是硬编码 0
3. 不同材质(一楼石、二楼木)怎么影响音效?你的 step sound 写死成 grass

**问题的本质是**:**「地面」是一个隐含的全局常量,但你真正需要的是一个局部的、可变的、带属性的 entity**。

工业界的解法是把地面**正式化**(formalize)为 entity:**每个 ground 是一个独立的 entity,有自己的 z 高度、自己的 (x, y) 范围、自己的材质属性**。玩家踩在哪个 ground 上,他的「地面 z」就是那个 ground 的 z。多层 stacking 自然支持——一楼 ground z=0、二楼 ground z=64,玩家在某个 (x, y),`ground_z_at(x, y)` 返回这个位置最高的 ground 的 z。

这个抽象的**力量**在于:**把隐式规则变成显式数据**。隐式规则只能表达「单一情况」(只有 z=0);显式数据可以表达「任意情况」(任意数量的 ground,任意高度,任意材质)。

落地之后你立刻能做:
- **多楼层建筑**:一楼地板、二楼地板、三楼地板,玩家自由上下
- **移动平台**:platform 是 ground,它移动时,玩家站在上面跟着移动
- **临时坑洞**:玩家挖地,挖掉的地方 ground 移除,玩家掉下去
- **材质影响**:踩草地音效沙沙、踩石头音效咚咚、踩冰面滑(减速慢)、踩岩浆受伤
- **天气变化**:下雨时草地变湿(改 material),玩家走得更慢
- **动态生成**:Minecraft 风格的世界,新 chunk 加载时动态创建 ground

**心理锚点**:学完今天,你应该能:
- 向队友解释「为什么我们的地面不是 z=0 而是/entity」,以及这个抽象带来的解耦价值
- 用 Rust 写出多楼层建筑系统,玩家在二楼边缘走下时正确掉到一楼
- 解释「数据驱动设计」——把硬编码改成 enum + match + 数据字段,后续扩展无需改代码
- 用 30 秒说清「**一切都是 entity**」这个游戏引擎设计哲学,以及它的代价
- 设计 material 系统,新材质只加 enum variant + match 分支,不改既有代码

这是从「能写单层关卡」到「能做开放世界」的关键一步。把隐式变显式,把全局变局部,把硬编码变数据驱动——这是软件抽象的胜利,也是游戏引擎架构成熟的标志。

## 2 · 心智模型

### 2.1 费曼类比:乐高积木

想象你用乐高搭一个多层停车场。每层地板是一块大积木——一块在底层(z=0),一块在二层(z=64),一块在三层(z=128)。每块积木都是**独立的实体**,有自己的位置、颜色、材质。

车(玩家)在哪一层,取决于车在哪块积木上。这不是「车的全局 z」,是「车踩的那块积木」。

**地面 entity 就是乐高积木**。每个 ground 是独立的,有自己的属性。玩家踩在不同的 ground 上,体验完全不同(草地走慢、冰面滑、岩浆死)。

让我们把类比推得更精确。**乐高积木还有材质**:红色积木、灰色积木、透明积木。车在红色积木上行驶(对应草地)和灰色积木上行驶(对应石头),手感不同——红色光滑(滑),灰色粗糙(摩擦大)。Ground 的 `material` 字段对应乐高积木的「颜色 / 材质」。

乐高的另一个特性:**可以拆装**。你拿走一块积木(地面消失),上面的车立刻掉到下一层。这在游戏里就是「**临时坑洞**」——挖地机制、陷阱门、可破坏地形。Ground 是 entity,可以增删,游戏世界动态变化。

### 2.2 严谨原理:从隐式 z=0 到显式 ground entity

先回顾隐式 z=0 是怎么工作的。Phase 2 的玩家代码:
```rust
fn update_player(p: &mut Player, dt: f32) {
    p.vel_z -= GRAVITY * dt;
    p.pos.z += p.vel_z * dt;
    if p.pos.z < 0.0 {
        p.pos.z = 0.0;
        p.vel_z = 0.0;
    }
}
```

`if p.pos.z < 0.0` 这行就是隐式 z=0——地面是 z=0,玩家 z 不能小于 0。整个游戏里**只有一个地面**,在 z=0。

**第一步抽象**:把「z=0」变成变量 `ground_z`:
```rust
fn update_player(p: &mut Player, ground_z: f32, dt: f32) {
    p.vel_z -= GRAVITY * dt;
    p.pos.z += p.vel_z * dt;
    if p.pos.z < ground_z {
        p.pos.z = ground_z;
        p.vel_z = 0.0;
    }
}
```
现在 ground_z 是个参数。但参数从哪来?如果游戏里只有一个 ground_z,那它还是全局常量。

**第二步抽象**:ground_z 是位置的函数——`ground_z_at(x, y)`:
```rust
fn update_player(p: &mut Player, world: &World, dt: f32) {
    let ground_z = ground_z_at(world, p.pos.xy());
    p.vel_z -= GRAVITY * dt;
    p.pos.z += p.vel_z * dt;
    if let Some(z) = ground_z {
        if p.pos.z < z {
            p.pos.z = z;
            p.vel_z = 0.0;
        }
    }
    // 如果 ground_z 是 None,玩家下方没地面 → 永远下落(掉出世界)
}
```
现在「地面」是 (x, y) 的函数——玩家在哪个 (x, y),就有对应的 ground_z。多楼层、坑洞、平台——全部自然支持。

**第三步抽象**:`ground_z_at` 不仅返回 z,还返回材质(material),因为材质影响音效、粒子、移动速度:
```rust
fn ground_at(world: &World, query: Vec2) -> Option<(f32, Material)> { ... }
```
返回元组 `(z, material)`——位置信息 + 属性信息。这是「**数据驱动**」的核心——同一个查询接口返回所有相关信息。

### 2.3 数据结构:GroundEntity

```rust
#[derive(Copy, Clone, Debug, PartialEq)]
enum Material {
    Grass,
    Stone,
    Wood,
    Water,
    Ice,
    Lava,
}

#[derive(Clone, Debug)]
struct GroundEntity {
    pos: Vec2,       // 地面在 x/y 平面的位置(中心)
    size: Vec2,      // 地面的宽高(矩形面积)
    z: f32,          // 地面的高度
    material: Material,
}

impl GroundEntity {
    fn contains(&self, query: Vec2) -> bool {
        // query 是否在 ground 的 x/y 范围内
        let dx = (query.x - self.pos.x).abs();
        let dy = (query.y - self.pos.y).abs();
        dx < self.size.x / 2.0 && dy < self.size.y / 2.0
    }
}
```

Ground 是个**2D 矩形 + 一个 z 高度**。它在 (x, y) 平面上有面积,在 z 上是平的(单个 z 值)。`contains` 检查查询点是否在矩形内——简单的 AABB 2D 包含测试。

为什么 Ground 不带 width × depth × height(3D 体积)?因为 Ground 是「**无限薄的地板**」——玩家踩在板上,板只有「上表面」可踩,没有厚度。如果以后想做可破坏的地板(玩家穿过板到下面),再加厚度字段。

### 2.4 ground_z_at:遍历所有 ground 找最高的

```rust
fn ground_z_at(world: &World, query: Vec2) -> Option<(f32, Material)> {
    let mut best: Option<(f32, Material)> = None;
    for g in &world.grounds {
        if g.contains(query) {
            // query 在这块地面上
            // 取 z 最高的(玩家踩在上面而不是下面那层)
            if best.is_none() || g.z > best.unwrap().0 {
                best = Some((g.z, g.material));
            }
        }
    }
    best
}
```

返回 `Option<(z, material)>`——既给 z 也给材质。游戏代码用 z 更新玩家位置,用材质决定音效/速度。

**关键设计:取最高的**。为什么?考虑一个 (x, y) 上叠了三个 ground:一楼 z=0、二楼 z=64、三楼 z=128。玩家踩在哪层?**物理上踩在最高那层**(他不可能穿过三楼到达二楼)。所以 `ground_z_at` 返回最高的 ground。

**反例**:如果游戏支持「**穿墙**」(鬼魂、阴影形态),需要返回所有 ground 列表,让玩家自己决定。但 99% 游戏不允许穿墙,所以最高优先足够。

### 2.5 多楼层建筑的实现

```rust
let world = World {
    grounds: vec![
        // 一楼地板(覆盖整个 100×100 区域,z=0)
        GroundEntity {
            pos: Vec2::new(50., 50.),
            size: Vec2::new(100., 100.),
            z: 0.,
            material: Material::Stone,
        },
        // 二楼地板(只覆盖 30×30 区域,z=64)
        GroundEntity {
            pos: Vec2::new(50., 50.),
            size: Vec2::new(30., 30.),
            z: 64.,
            material: Material::Wood,
        },
        // 三楼地板(更小,更高)
        GroundEntity {
            pos: Vec2::new(50., 50.),
            size: Vec2::new(15., 15.),
            z: 128.,
            material: Material::Grass,
        },
    ],
    // ...
};

// 玩家在 (50, 50):
let q = Vec2::new(50., 50.);
let ground = ground_z_at(&world, q);
// 返回 (128, Grass)——三楼最高
// 玩家在三楼,z=128

// 玩家在 (80, 80)(三楼范围外,二楼范围内):
let q = Vec2::new(80., 80.);
let ground = ground_z_at(&world, q);
// 返回 (64, Wood)——只有一楼和二楼,二楼更高
```

**多层 stacking 的关键**:`ground_z_at` 返回**最高的** ground,因为玩家物理上踩在最高那层。

注意三块 ground **共享 (50, 50) 中心**但 size 不同——一楼 100×100、二楼 30×30、三楼 15×15。这是「**金字塔结构**」——底层最大,上层越来越小,模拟「上层是露台」的样式。你可以设计任何形状——三块不重叠的 ground(三个独立小岛)、完全重叠(三层楼同一坐标)、半重叠(L 形走廊)。

### 2.6 玩家从二楼掉下来

```rust
// 玩家在 (50, 50), z=64,在二楼
// 玩家移动到 (80, 80)(二楼范围外)
let q = Vec2::new(80., 80.);
let new_ground = ground_z_at(&world, q);
// 返回 (0, Stone)——一楼
// 玩家的「地面 z」从 64 突变到 0
// 玩家现在悬空(z=64 > ground_z=0),进入下落状态
```

这是**走出平台边缘**的物理——玩家从二楼走到边缘外,地面 z 突变,玩家悬空,重力让他下落到一楼。

**注意一个微妙之处**:玩家走到边缘的瞬间,`ground_z_at` 返回 0(一楼),玩家 z 还是 64。下一帧的重力让玩家开始下落,z 从 64 减到 63、62、...直到 z=0 接触一楼。这是「**自由落体**」状态——ground_z 是 0 但玩家 z 大于 0,中间是空气,玩家不受 ground 支撑。

如果游戏要支持「**平台边缘抓 hold**」(玩家走到边缘按住键不掉),需要额外状态机:`on_ground` vs `falling` vs `clinging_edge`。Casey HH 简化,直接自由落体。

### 2.7 材质的影响:数据驱动

```rust
fn player_speed_on_material(material: Material) -> f32 {
    match material {
        Material::Grass => 1.0,    // 正常速度
        Material::Stone => 1.0,    // 正常
        Material::Wood => 1.0,     // 正常
        Material::Water => 0.5,    // 半速
        Material::Ice => 1.5,      // 加速(滑)
        Material::Lava => 0.0,     // 不能走(受伤)
    }
}

fn player_step_sound(material: Material) -> &'static str {
    match material {
        Material::Grass => "sfx/step_grass.wav",
        Material::Stone => "sfx/step_stone.wav",
        // ...
    }
}
```

每帧玩家踩在某种材质上,游戏代码用这个材质查表决定速度和音效。**数据驱动设计**——添加新材质不需要改代码,只加 enum variant 和 match 分支。

数据驱动的对立面是「**代码驱动**」——硬编码 `if tile_type == 3 { speed = 0.5; }`。每次加新 tile,你都要改这个 if-else 链,改多了变成 if 噩梦。数据驱动让数据成为 source of truth,代码只是查表。

工业级数据驱动更进一步:把 material 的属性(speed、sound、friction、damage_per_second)放到**配置文件**(TOML / JSON),运行时加载。关卡设计师改配置,程序员不用重编译。这是 Unity / Unreal 的核心思路——所有 component 属性都暴露给 editor 编辑。

### 2.8 Ground 作为 Traversable 的特例

Day 074 的 Traversable 是「线段」(楼梯)。Ground 是「矩形 + 单 z」。其实 Ground 可以视作**特殊的 Traversable**——一个 z 恒定的面。

Casey 的简化:Day 079 之前 ground 和 traversable 是两套系统。Day 079 之后,ground 也是 traversable(矩形 traversable,而不是线段 traversable)。Day 080 把这两套合并到碰撞循环。

```rust
enum Traversable {
    Segment(SegTrav),   // 线段(楼梯、斜坡)
    Rect(RectTrav),     // 矩形(地面、平台)
}

impl Traversable {
    fn z_at(&self, query: Vec2) -> Option<f32> {
        match self {
            Traversable::Segment(s) => s.z_at(query),
            Traversable::Rect(r) => r.z_at(query),
        }
    }
}
```

统一抽象的好处:碰撞循环只需要遍历 `Vec<Traversable>`,不管具体类型。这是**多态**(polymorphism)的 Rust 表达——enum + match 是 ad-hoc 多态,每种 variant 有自己的实现。

工业引擎更进一步:Traversable 是 trait,segment / rect / mesh 各自实现。但 Rust enum dispatch 比 trait object(`Box<dyn Traversable>`)快——避免虚函数调用 + vtable 间接。Casey HH 倾向 enum dispatch,这是性能优先的选择。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**「一切都是 entity」**是现代游戏引擎的核心理念:

- **Unity**:GameObject 是万物基础。地面、玩家、灯光、相机都是 GameObject。
- **Unreal**:Actor 是万物基础。场景里所有东西都是 Actor。
- **Bevy**:Entity 是 ECS 的核心。Component 加在 Entity 上表达不同类型。
- **Casey HH**:entity 是统一概念,用 enum 区分类型。

这种统一让引擎简单——一套系统(service locator、事件、序列化)服务所有 entity。

#### Ground 在不同引擎里的对应

| 引擎 | Ground 概念 |
|---|---|
| Unity | Terrain / Plane GameObject |
| Unreal | Landscape / Static Mesh Actor |
| Minecraft | Block(每个 block 是 ground 的一种) |
| Casey HH | GroundEntity |

#### 多楼层的实现方式

| 游戏 | 实现方式 |
|---|---|
| Zelda ALTTP | 「Layer」字段,entity 有 layer 属性 |
| Diablo | 多层 mesh,按 z 切换 |
| Casey HH | ground entity + 玩家 z |

Casey 的方案最简洁——多楼层 = 多 ground entity,玩家踩哪个 ground 决定他在哪层。

### 3.2 · 🎨 图形学视角

**Ground 渲染**:每个 ground 是一个矩形 sprite。Casey HH 用 sprite 表达 ground,玩家从上往下看。

**Material 渲染**:不同材质用不同 sprite。草地是绿色噪点,石头是灰色纹理,水面是半透明蓝色 + 波纹动画。

**材质过渡**:两种 ground 相邻处(草 vs 石头),如何画? Casey Day 087 用 alpha blend 过渡,让边缘自然。

#### Shader 里的 ground

3D 游戏里,ground 是 mesh + material + shader。Shader 决定:
- **颜色**:纹理采样
- **光照**:Lambert / PBR
- **法线**:法线贴图模拟凹凸
- **反射**:金属感、水反射

Casey HH Day 096+ 进入光照后,ground 也用 shader 算光照。

### 3.3 · 🐧 Linux 系统编程视角

「Ground」概念在 Linux 里类似「**默认值**」或「**base layer**」:

- **进程的 cwd**(current working directory):每个进程有自己的 cwd,默认是启动时所在目录。
- **用户的 HOME**:每个用户有 HOME,作为默认起始 ground。
- **网络默认路由**:0.0.0.0/0 是默认网关,所有未匹配的流量走这里。

这些「default ground」概念和游戏里的 ground 类似——**基础的、隐含的、可覆盖的**。

### 3.4 · 🦀 Rust 生态视角

#### Rust 写数据驱动的 ground 系统

```rust
use serde::Deserialize;

#[derive(Copy, Clone, Debug, Deserialize, PartialEq)]
enum Material {
    Grass, Stone, Wood, Water, Ice, Lava,
}

#[derive(Clone, Debug, Deserialize)]
struct GroundDef {
    pos: (f32, f32),
    size: (f32, f32),
    z: f32,
    material: Material,
}

#[derive(Deserialize)]
struct WorldDef {
    grounds: Vec<GroundDef>,
}

fn load_world(path: &str) -> WorldDef {
    let s = std::fs::read_to_string(path).unwrap();
    toml::from_str(&s).unwrap()
}

fn main() {
    let world = load_world("world.toml");
    // world 是数据驱动的,改 toml 改世界,不用重编译
}
```

加 `serde` + `toml` crate,让世界数据从代码里独立出来。这是工业级做法——关卡设计师改 toml,程序员只维护引擎。

`Default` trait 让「默认值」概念正式化。

#### Rust 的 ECS(Bevy 风格)

```rust
// Bevy 风格的 entity + component
#[derive(Component)]
struct Ground;

#[derive(Component)]
struct Material(pub GroundMaterial);

#[derive(Component)]
struct Z(pub f32);

fn ground_z_at(
    query: Query<(&Z, &Material, &Transform), With<Ground>>,
    player_pos: Vec2,
) -> Option<(f32, GroundMaterial)> {
    let mut best = None;
    for (z, mat, tf) in query.iter() {
        if rectangle_contains(tf.translation.xy(), tf.scale.xy(), player_pos) {
            if best.is_none() || z.0 > best.unwrap().0 {
                best = Some((z.0, mat.0));
            }
        }
    }
    best
}
```

Bevy ECS 的 query 系统让你**只查有特定 component 的 entity**。这是工业级 ECS 的方式。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Casey 把「地面」从隐式规则改成显式 entity?给两个理由。

**参考解答**:

理由 1:**多楼层支持**。隐式 z=0 只能单层。显式 ground entity 让多层建筑成为现实——一楼 ground z=0,二楼 ground z=64,各自独立。

理由 2:**材质数据化**。隐式规则下,材质是硬编码(每种 tile 一种材质)。显式 entity 让材质成为数据字段,可以动态变化(冰面融化成水、岩浆凝固成石头),不需要改代码。

### Lv2 · 动手实践

**题**:实现多楼层 world。玩家从一楼走到二楼(踩楼梯),从二楼边缘走出后掉回一楼。模拟 5 秒,每秒打印玩家 z。

完成标准:看到 z 从 0 → 64(上楼)→ 悬空(走出边缘)→ 落回 0。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
    fn abs(self) -> Self { Self::new(self.x.abs(), self.y.abs()) }
}

#[derive(Clone, Debug)]
struct Ground { pos: Vec2, size: Vec2, z: f32 }

impl Ground {
    fn contains(&self, q: Vec2) -> bool {
        let d = q.sub(self.pos).abs();
        d.x < self.size.x / 2.0 && d.y < self.size.y / 2.0
    }
}

fn ground_z_at(grounds: &[Ground], q: Vec2) -> Option<f32> {
    grounds.iter()
        .filter(|g| g.contains(q))
        .map(|g| g.z)
        .max_by(|a, b| a.partial_cmp(b).unwrap())
}

struct Player {
    pos: Vec2,
    z: f32,
    vel_z: f32,
}

fn main() {
    let grounds = vec![
        Ground { pos: Vec2::new(50., 50.), size: Vec2::new(100., 100.), z: 0.0 },
        Ground { pos: Vec2::new(50., 50.), size: Vec2::new(30., 30.), z: 64.0 },
    ];

    let mut p = Player { pos: Vec2::new(50., 50.), z: 64.0, vel_z: 0.0 };
    let dt = 1.0 / 60.0;
    let gravity = 980.0;

    // 模拟玩家从 (50, 50, 64) 移动到 (80, 80) 然后超出二楼
    for frame in 0..300 {
        // 移动 x/y(每帧 0.3)
        p.pos.x += 0.3;
        p.pos.y += 0.3;

        // 找当前 ground
        let ground_z = ground_z_at(&grounds, p.pos).unwrap_or(0.0);

        // 物理:重力 / 落地
        if p.z >= ground_z - 1.0 && p.vel_z <= 0.0 {
            p.z = ground_z;
            p.vel_z = 0.0;
        } else {
            p.vel_z -= gravity * dt;
            p.z += p.vel_z * dt;
        }

        if frame % 30 == 0 {
            println!("帧 {:3}: 玩家 (x={:.1}, y={:.1}, z={:.2}), ground_z={}",
                frame, p.pos.x, p.pos.y, p.z, ground_z);
        }
    }
}
```

```

帧  30: 玩家 (x=59.0, y=59.0, z=64.00), ground_z=64   ← 还在二楼
帧  60: 玩家 (x=68.0, y=68.0, z=64.00), ground_z=64   ← 二楼边缘
帧  66: 玩家 (x=69.8, y=69.8, z=64.00), ground_z=0    ← 超出二楼
帧  67: 玩家 (x=70.1, y=70.1, z=62.71), ground_z=0    ← 开始下落
帧  90: 玩家 (x=77.0, y=77.0, z= 0.00), ground_z=0    ← 落地一楼
帧 120: 玩家 (x=86.0, y=86.0, z= 0.00), ground_z=0    ← 一楼走
```

## 8 · Rust / Arch 落地代码

```rust
#[derive(Copy, Clone, Debug)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
    fn abs(self) -> Self { Self::new(self.x.abs(), self.y.abs()) }
}

#[derive(Copy, Clone, Debug, PartialEq)]
enum Material { Grass, Stone, Wood, Water, Ice }

#[derive(Clone, Debug)]
struct Ground {
    pos: Vec2,
    size: Vec2,
    z: f32,
    material: Material,
}

impl Ground {
    fn contains(&self, q: Vec2) -> bool {
        let d = q.sub(self.pos).abs();
        d.x < self.size.x / 2.0 && d.y < self.size.y / 2.0
    }
}

fn ground_at<'a>(grounds: &'a [Ground], q: Vec2) -> Option<&'a Ground> {
    let mut best: Option<&Ground> = None;
    for g in grounds {
        if g.contains(q) {
            if best.is_none() || g.z > best.unwrap().z {
                best = Some(g);
            }
        }
    }
    best
}

fn speed_multiplier(m: Material) -> f32 {
    match m {
        Material::Grass | Material::Stone | Material::Wood => 1.0,
        Material::Water => 0.5,
        Material::Ice => 1.5,
    }
}

fn main() {
    let grounds = vec![
        Ground { pos: Vec2::new(50., 50.), size: Vec2::new(100., 100.), z: 0.0,
                 material: Material::Stone },
        Ground { pos: Vec2::new(50., 50.), size: Vec2::new(30., 30.), z: 64.0,
                 material: Material::Wood },
        Ground { pos: Vec2::new(80., 80.), size: Vec2::new(20., 20.), z: 0.0,
                 material: Material::Ice },
    ];

    for (px, py) in [(50., 50.), (75., 75.), (80., 80.), (10., 10.)] {
        match ground_at(&grounds, Vec2::new(px, py)) {
            Some(g) => println!("({:3},{:3}): z={}, material={:?}, speed={:.1}",
                px, py, g.z, g.material, speed_multiplier(g.material)),
            None => println!("({:3},{:3}): 无地面(坑?)", px, py),
        }
    }
}
```

**预期输出**:
```
( 50, 50): z=64, material=Wood, speed=1.0    ← 二楼
( 75, 75): z=64, material=Wood, speed=1.0    ← 还在二楼
( 80, 80): z=0, material=Ice, speed=1.5      ← 一楼冰面(更高优先)
( 10, 10): z=0, material=Stone, speed=1.0    ← 一楼石头
```
