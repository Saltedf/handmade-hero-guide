
# Day 086 · 地面缓冲对齐世界区块

> 你昨天的 GroundBuffer 跟相机走——相机移动就 recenter。但 recenter 时**浮点误差**让两块 buffer 拼接处出现可见的缝。Casey 今天换一个思路:**buffer 固定在世界网格上**(256×256 的倍数位置),不跟相机走。相机在哪个网格就用哪个网格的 buffer。这种「**chunk-aligned**」是 Minecraft 的核心架构——区块固定,相机选择加载。

## 0 · 为什么要有这一天

你的 GroundBuffer 跟相机走:

```rust
buf.world_offset = camera.pos - buf.size / 2;
```

每次 recenter,world_offset 是个**浮点数**——可能是 (123.45, 678.91)。下次 recenter 又变,变成 (345.67, 891.12)。每次的浮点位置不同,导致:

1. **像素对不齐**:tile 的边界(64 像素)和 buffer 的边界(浮点)不一致。blit 时有些 tile 是「在 buffer 边缘的一半」——拼接处出现撕裂。
2. **缓存失效**:buffer 跟相机走,tile 的 buffer 内位置每帧变化。如果用「tile 坐标 → buffer 内像素位置」做缓存,每帧 cache miss。
3. **多 buffer 拼接缝**:recenter 时新 buffer 和旧 buffer 在边界处可能有 1 像素误差(浮点),可见的缝。

Casey 的解法:**chunk 对齐**。Buffer 固定在世界网格上——world_offset 是 chunk 大小的倍数(256×256),整数值。

- 相机在世界坐标 (300, 500)
- Chunk 大小 256
- 相机在 chunk (1, 1)(因为 300/256=1.17,500/256=1.95)
- 加载 chunk (1, 1)、(0, 1)、(2, 1)、(1, 0)、(1, 2) 等(周围的)

**好处**:
- Buffer 边界**永远在世界 chunk 边界**,拼接无缝。
- 同一 chunk 的 buffer **位置永远一样**——缓存友好。
- 多个 chunk buffer 可以并行生成。

这就是 Minecraft 的核心——「**chunk 系统**」。

心理锚点:看完今天,你能向队友解释「为什么我们的世界没有拼接缝」。你能用 Rust 写一个 chunk 系统。你能用 30 秒说清「chunk-aligned 比 camera-relative 好在哪」。

## 1 · Casey 今天做了什么

Casey 今天做的事情:

1. **定义 CHUNK_SIZE**:256(常量)。
2. **ChunkId**:世界坐标 (x, y) → chunk 坐标 (x / 256, y / 256)。
3. **chunk_cache**:HashMap<ChunkId, GroundBuffer>。
4. **加载策略**:相机周围 3×3 个 chunk 保留,远处 chunk 卸载。
5. **拼接无缝**:两个 chunk buffer 的边界在整数像素,blit 完美对齐。

Casey 强调「**网格对齐**」是游戏开发的核心架构——所有大世界游戏都这么做。

## 2 · 心智模型

### 费曼类比:棋盘和棋子

国际象棋棋盘是 8×8 网格。棋子放在网格点上,不在网格中间。这样棋子之间的相对位置**永远是整数格**——不会出现「棋子在 A1 和 B1 之间」的奇怪状态。

游戏里的 chunk 系统就是棋盘——世界分成 256×256 的 chunk,entity 和 buffer 都在 chunk 边界对齐。**整数对齐消除浮点误差**。

### 严谨原理

#### 2.1 ChunkId

```rust
const CHUNK_SIZE: i32 = 256;

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
struct ChunkId {
    cx: i32,
    cy: i32,
}

impl ChunkId {
    fn from_world(world_x: i32, world_y: i32) -> Self {
        // 用 floor 除法处理负数
        Self {
            cx: world_x.div_euclid(CHUNK_SIZE),
            cy: world_y.div_euclid(CHUNK_SIZE),
        }
    }

    fn world_origin(&self) -> (i32, i32) {
        (self.cx * CHUNK_SIZE, self.cy * CHUNK_SIZE)
    }
}
```

**注意 `div_euclid`**:Rust 的整数除法对负数是「向零取整」,但游戏世界可能跨原点(world x < 0)。`div_euclid` 是「向下取整」除法,对负数也正确。

#### 2.2 ChunkManager

```rust
use std::collections::HashMap;

struct ChunkManager {
    chunks: HashMap<ChunkId, Chunk>,
}

struct Chunk {
    id: ChunkId,
    pixels: Vec<u32>,         // CHUNK_SIZE × CHUNK_SIZE
    is_generated: bool,
}

impl ChunkManager {
    fn new() -> Self { Self { chunks: HashMap::new() } }

    fn get_or_generate(&mut self, id: ChunkId) -> &Chunk {
        self.chunks.entry(id).or_insert_with(|| {
            let mut chunk = Chunk {
                id,
                pixels: vec![0; (CHUNK_SIZE as usize) * (CHUNK_SIZE as usize)],
                is_generated: false,
            };
            generate_chunk(&mut chunk);
            chunk
        });
        self.chunks.get(&id).unwrap()
    }

    fn unload_far(&mut self, camera_chunk: ChunkId, radius: i32) {
        let to_unload: Vec<ChunkId> = self.chunks.keys()
            .filter(|id| {
                (id.cx - camera_chunk.cx).abs() > radius
                    || (id.cy - camera_chunk.cy).abs() > radius
            })
            .copied()
            .collect();
        for id in to_unload {
            self.chunks.remove(&id);
        }
    }
}
```

#### 2.3 渲染:从 chunk 到屏幕

```rust
fn render(chunk_mgr: &ChunkManager, camera_pos: Vec2, framebuffer: &mut Framebuffer) {
    // 算屏幕上能看到哪些 chunk
    let cam_chunk = ChunkId::from_world(camera_pos.x as i32, camera_pos.y as i32);
    let view_radius = 2;  // 5x5 chunks
    for cy in (cam_chunk.cy - view_radius)..=(cam_chunk.cy + view_radius) {
        for cx in (cam_chunk.cx - view_radius)..=(cam_chunk.cx + view_radius) {
            let id = ChunkId { cx, cy };
            if let Some(chunk) = chunk_mgr.chunks.get(&id) {
                // chunk 在世界坐标 (cx*256, cy*256) 到 (cx*256+255, cy*256+255)
                // 转屏幕坐标:减 camera_pos
                let screen_x = (cx * CHUNK_SIZE) as f32 - camera_pos.x;
                let screen_y = (cy * CHUNK_SIZE) as f32 - camera_pos.y;
                blit_chunk(framebuffer, screen_x, screen_y, chunk);
            }
        }
    }
}
```

每个 chunk blit 时**整数边界对齐**——无缝拼接。

#### 2.4 无缝拼接的关键

```
Chunk (0, 0) 在世界 (0, 0) 到 (255, 255)
Chunk (1, 0) 在世界 (256, 0) 到 (511, 255)

两 chunk 在 x=255 和 x=256 相邻——整数像素,无浮点误差。
```

如果 chunk 是「跟相机走」(camera-relative),chunk 1 在屏幕的位置 = (256 - cam_offset_x, 0 - cam_offset_y)。`cam_offset_x` 是浮点,导致 chunk 1 和 chunk 0 之间可能有 0.5 像素的缝。

**Chunk-aligned**:chunk 1 和 chunk 0 永远在整数像素边界。即使相机在 (123.45, 0),chunk 0 在屏幕 (0 - 123.45, 0),chunk 1 在屏幕 (256 - 123.45, 0)——两者差 256(整数),无相对误差。

#### 2.5 加载策略

相机移动时,需要加载新 chunk,卸载旧 chunk。策略:

```rust
fn update_loaded_chunks(chunk_mgr: &mut ChunkManager, camera_pos: Vec2) {
    let cam_chunk = ChunkId::from_world(camera_pos.x as i32, camera_pos.y as i32);
    let radius = 2;  // 5x5 = 25 chunks

    // 1. 加载附近的
    for cy in (cam_chunk.cy - radius)..=(cam_chunk.cy + radius) {
        for cx in (cam_chunk.cx - radius)..=(cam_chunk.cx + radius) {
            let id = ChunkId { cx, cy };
            chunk_mgr.get_or_generate(id);  // 如果没加载,生成
        }
    }

    // 2. 卸载远的
    chunk_mgr.unload_far(cam_chunk, radius + 1);
}
```

每帧调用一次。`get_or_generate` 内部用 HashMap entry API,已生成的秒返。

#### 2.6 异步生成(高级)

chunk 生成可能慢(几毫秒)。如果同步生成,玩家移动到新区域时会卡顿。

工业级方案:**异步生成**——主线程请求,工作线程生成,完成后通知主线程。

```rust
// 简化:用 channel 通信
use std::sync::mpsc;
use std::thread;

let (tx, rx) = mpsc::channel();
thread::spawn(move || {
    // 工作线程:接收生成请求,生成 chunk
    while let Ok(request) = rx.recv() {
        let chunk = generate_chunk_blocking(request);
        tx.send(chunk).unwrap();
    }
});
```

Casey HH 简化用同步生成,Day 200+ 才异步。

#### 2.7 Chunk 内的 tile

每个 chunk 包含 (CHUNK_SIZE / TILE_SIZE) × (CHUNK_SIZE / TILE_SIZE) 个 tile。比如 CHUNK_SIZE=256, TILE_SIZE=64,每 chunk 是 4×4 = 16 个 tile。

```rust
fn generate_chunk(chunk: &mut Chunk) {
    let tiles_per_chunk = CHUNK_SIZE / TILE_SIZE;  // 4
    for ty in 0..tiles_per_chunk {
        for tx in 0..tiles_per_chunk {
            let world_tx = chunk.id.cx * tiles_per_chunk + tx;
            let world_ty = chunk.id.cy * tiles_per_chunk + ty;
            let tile_bmp = composite_tile(world_tx, world_ty);
            // blit 到 chunk buffer
            blit_tile(&mut chunk.pixels, tx, ty, &tile_bmp);
        }
    }
    chunk.is_generated = true;
}
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Chunk 系统是大世界游戏的标配:

- **Minecraft**:16×16×256 chunk,玩家周围加载,远处卸载。
- **GTA V**:超大世界,chunk + LOD(Level of Detail)。
- **塞尔达 BOTW**:Hyrule 王国,分块加载。
- **No Man's Sky**:程序化 chunk,无限世界。

#### Chunk 大小的选择

| 大小 | 优点 | 缺点 |
|---|---|---|
| 64×64(小) | 加载快,精细 | chunk 多,管理开销 |
| 256×256(中) | 平衡 | Casey 选 |
| 1024×1024(大)| chunk 少 | 加载慢 |

Minecraft 用 16×16(很细),因为单个 chunk 包含 256 高度,需要精细管理。

#### Chunk 的 LOD

远处 chunk 用低精度渲染(少 tile,小贴图)。近处 chunk 用高精度。这种 LOD 是大世界游戏的必备。

### 3.2 · 🎨 图形学视角

GPU 上的 chunk 是 texture atlas 的一块。chunk-aligned 让 texture 边界对齐 tile 边界,避免 artifact。

#### Texture streaming

GPU 显存有限(8-24GB)。超大世界不能全部加载到 GPU。Texture streaming:

1. 附近 chunk 的 texture 上传到 GPU(高精度)。
2. 远处 chunk 用低精度替代。
3. 玩家移动时,新 chunk 上传,老 chunk 卸载。

这是 PS4/Xbox One 时代发展起来的技术。Casey HH 不需要(软渲染)。

#### Virtual Texture

更高级:把超大 texture 切成 128×128 的小 page,只把可见的 page 加载到 GPU。这是「Virtual Texture」技术,id Software 在 Rage(2011)首次大规模用。

### 3.3 · 🐧 Linux 系统编程视角

「**整数对齐 + 网格**」是 Linux 系统的常见模式:

- **页面(page)**:Linux 内存按 4KB page 管理。所有内存分配按 page 对齐。
- **磁盘块(block)**:文件系统按 4KB block。所有 IO 按 block 对齐。
- **CPU cache line**:64 字节。优化数据布局让 hot data 在同 cache line。

chunk 系统是同样的思想——**所有 buffer 按 chunk 边界对齐**,消除跨边界问题。

### 3.4 · 🦀 Rust 生态视角

#### Rust 的 HashMap for chunk

```rust
use std::collections::HashMap;

let chunks: HashMap<ChunkId, Chunk> = HashMap::new();
```

但 HashMap 的 cache 局部性差。游戏开发常用 **2D 数组 + offset**:

```rust
struct ChunkGrid {
    chunks: Vec<Option<Chunk>>,  // 一维数组模拟二维
    width: usize,
    height: usize,
    origin_cx: i32,  // 数组(0, 0)对应的 chunk
    origin_cy: i32,
}

impl ChunkGrid {
    fn get(&self, cx: i32, cy: i32) -> Option<&Chunk> {
        let idx_x = (cx - self.origin_cx) as usize;
        let idx_y = (cy - self.origin_cy) as usize;
        if idx_x >= self.width || idx_y >= self.height { return None; }
        self.chunks[idx_y * self.width + idx_x].as_ref()
    }
}
```

数组访问比 HashMap 快 10 倍。但需要管理「相机移动时 grid 重新对齐」。

#### Rust 的 entry API

```rust
self.chunks.entry(id).or_insert_with(|| generate_chunk(id));
```

Casey 风格——简洁、零开销(已存在则不调闭包)。

#### Rust 的并发 chunk 生成

```rust
use rayon::prelude::*;

let chunks_to_generate: Vec<ChunkId> = needed_chunks();
let new_chunks: Vec<Chunk> = chunks_to_generate
    .par_iter()  // 并行迭代
    .map(|&id| generate_chunk(id))
    .collect();
```

`rayon` crate 让并行化简单——`iter()` 换 `par_iter()`。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 chunk-aligned 比 camera-relative 好?

**参考解答**:

理由 1:**整数对齐消除浮点误差**。Chunk-aligned 的 chunk 边界永远在世界整数像素(256 的倍数)。两个相邻 chunk 之间的相对位置永远是整数像素差,无浮点误差。Camera-relative 的 buffer 跟相机走,浮点位置变化导致拼接缝。

理由 2:**缓存友好**。Chunk-aligned 的 chunk 内 tile 位置永远一样(同 chunk 内 tile (1, 2) 永远在 chunk 的 (64, 128) 像素位置)。可以做二级缓存。Camera-relative 的 tile 在 buffer 内位置随相机变,缓存失效频繁。

理由 3:**并行生成**。Chunk-aligned 的不同 chunk 之间无依赖,可以并行生成(多线程)。Camera-relative 的 buffer 是一整块,生成时需要锁。

理由 4:**卸载简单**。Chunk-aligned 的卸载 = 删 HashMap entry,独立。Camera-relative 的卸载要考虑「相机可能瞬间跳回去」。

### Lv2 · 动手实践

**题**:实现 ChunkManager,模拟相机移动,打印每帧加载的 chunk 数。

完成标准:相机静止时 chunk 数稳定,相机移动时新 chunk 加载。

**参考解答**:

```rust
use std::collections::HashMap;

const CHUNK_SIZE: i32 = 256;
const VIEW_RADIUS: i32 = 1;  // 3x3 = 9 chunks

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
struct ChunkId { cx: i32, cy: i32 }

impl ChunkId {
    fn from_world(wx: i32, wy: i32) -> Self {
        Self { cx: wx.div_euclid(CHUNK_SIZE), cy: wy.div_euclid(CHUNK_SIZE) }
    }
}

struct Chunk { pixels: Vec<u32> }

struct ChunkManager {
    chunks: HashMap<ChunkId, Chunk>,
}

impl ChunkManager {
    fn new() -> Self { Self { chunks: HashMap::new() } }

    fn update(&mut self, camera_x: i32, camera_y: i32) -> (usize, usize) {
        let cam = ChunkId::from_world(camera_x, camera_y);
        let mut loaded = 0;
        for cy in (cam.cy - VIEW_RADIUS)..=(cam.cy + VIEW_RADIUS) {
            for cx in (cam.cx - VIEW_RADIUS)..=(cam.cx + VIEW_RADIUS) {
                let id = ChunkId { cx, cy };
                if !self.chunks.contains_key(&id) {
                    self.chunks.insert(id, Chunk {
                        pixels: vec![0; (CHUNK_SIZE as usize) * (CHUNK_SIZE as usize)],
                    });
                    loaded += 1;
                }
            }
        }
        let before = self.chunks.len();
        self.chunks.retain(|id| {
            (id.cx - cam.cx).abs() <= VIEW_RADIUS + 1
                && (id.cy - cam.cy).abs() <= VIEW_RADIUS + 1
        });
        let unloaded = before - self.chunks.len();
        (loaded, unloaded)
    }

    fn count(&self) -> usize { self.chunks.len() }
}

fn main() {
    let mut mgr = ChunkManager::new();
    let steps = [(0, 0), (100, 0), (200, 0), (256, 0), (300, 0),
                 (1000, 0), (1500, 0), (1500, 500)];
    for (cx, cy) in steps.iter() {
        let (l, u) = mgr.update(*cx, *cy);
        println!("相机 ({:4}, {:3}): 加载 {}, 卸载 {}, 总共 {}",
            cx, cy, l, u, mgr.count());
    }
}
```

**预期输出**:
```
相机 (   0,   0): 加载 9, 卸载 0, 总共 9      ← 初始 9 个
相机 ( 100,   0): 加载 0, 卸载 0, 总共 9      ← 同 chunk
相机 ( 200,   0): 加载 0, 卸载 0, 总共 9      ← 同 chunk
相机 ( 256,   0): 加载 3, 卸载 3, 总共 9      ← 跨 chunk 边界
相机 ( 300,   0): 加载 0, 卸载 0, 总共 9
相机 (1000,   0): 加载 6, 卸载 6, 总共 9      ← 多 chunk 远
相机 (1500,   0): 加载 3, 卸载 3, 总共 9
相机 (1500, 500): 加载 3, 卸载 3, 总共 9      ← y 方向跨 chunk
```

总数稳定在 9(3x3),只是不同 chunk。

## 8 · Rust / Arch 落地代码

```rust
use std::collections::HashMap;

const CHUNK_SIZE: i32 = 256;
const VIEW_RADIUS: i32 = 1;

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
struct ChunkId { cx: i32, cy: i32 }

impl ChunkId {
    fn from_world(wx: i32, wy: i32) -> Self {
        Self {
            cx: wx.div_euclid(CHUNK_SIZE),
            cy: wy.div_euclid(CHUNK_SIZE),
        }
    }

    fn world_origin(&self) -> (i32, i32) {
        (self.cx * CHUNK_SIZE, self.cy * CHUNK_SIZE)
    }
}

struct Chunk {
    pixels: Vec<u32>,
}

impl Chunk {
    fn new(id: ChunkId) -> Self {
        // 简化:用 chunk id 做种子生成颜色
        let base_r = ((id.cx * 30) as u32 % 256) as u8;
        let base_g = ((id.cy * 50) as u32 % 256) as u8;
        let base_b = (((id.cx + id.cy) * 20) as u32 % 256) as u8;
        let color = (255u32 << 24)
            | ((base_r as u32) << 16)
            | ((base_g as u32) << 8)
            | (base_b as u32);
        let size = (CHUNK_SIZE as usize) * (CHUNK_SIZE as usize);
        Self { pixels: vec![color; size] }
    }
}

struct ChunkManager {
    chunks: HashMap<ChunkId, Chunk>,
    cache_hits: u64,
    cache_misses: u64,
}

impl ChunkManager {
    fn new() -> Self {
        Self { chunks: HashMap::new(), cache_hits: 0, cache_misses: 0 }
    }

    fn update(&mut self, cam_x: i32, cam_y: i32) {
        let cam = ChunkId::from_world(cam_x, cam_y);
        // 加载附近
        for cy in (cam.cy - VIEW_RADIUS)..=(cam.cy + VIEW_RADIUS) {
            for cx in (cam.cx - VIEW_RADIUS)..=(cam.cx + VIEW_RADIUS) {
                let id = ChunkId { cx, cy };
                if self.chunks.contains_key(&id) {
                    self.cache_hits += 1;
                } else {
                    self.cache_misses += 1;
                    self.chunks.insert(id, Chunk::new(id));
                }
            }
        }
        // 卸载远的
        self.chunks.retain(|id| {
            (id.cx - cam.cx).abs() <= VIEW_RADIUS + 1
                && (id.cy - cam.cy).abs() <= VIEW_RADIUS + 1
        });
    }

    fn get(&self, id: ChunkId) -> Option<&Chunk> {
        self.chunks.get(&id)
    }
}

fn main() {
    let mut mgr = ChunkManager::new();
    let dt = 1.0 / 60.0;
    let mut cam_x = 0.0f32;
    let mut cam_y = 0.0f32;
    let mut frame = 0;

    while frame < 600 {
        // 模拟玩家移动
        cam_x += 5.0;  // 每帧 5 像素
        if frame == 300 { cam_y += 200.0; }  // 一半时转弯

        mgr.update(cam_x as i32, cam_y as i32);

        if frame % 60 == 0 {
            let cam_chunk = ChunkId::from_world(cam_x as i32, cam_y as i32);
            println!("帧 {:3}: 相机=({:.0}, {:.0}),chunk=({}, {}), 加载的 chunk={}",
                frame, cam_x, cam_y, cam_chunk.cx, cam_chunk.cy, mgr.chunks.len());
        }

        frame += 1;
    }

    println!("\n缓存命中: {}, 缓存未命中: {}", mgr.cache_hits, mgr.cache_misses);
    println!("命中率: {:.1}%",
        mgr.cache_hits as f32 / (mgr.cache_hits + mgr.cache_misses) as f32 * 100.0);
}
```
