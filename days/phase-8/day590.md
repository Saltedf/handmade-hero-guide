
# Day 590 · 开始光线投射优化

> GI 系统跑通了,视觉对了,但帧率从 60 FPS 掉到 30 FPS。瓶颈在哪?profile 一看,80% 时间花在"光线投射"——判断"从这个体素朝这个方向射光,会不会撞到墙"。这是几何查询,数据量大、计算重。今天 Casey 开始优化光线投射,这一集是 Day 590-609 的开端,持续 20 天的优化之旅。

## 0 · 为什么要有这一天

回顾 GI 数据流:

```
[阶段 2: 间接光 propagate]
  for each voxel A:
    for each direction d:
      ray = A.pos along d
      find nearest voxel B hit by ray  ← 光线投射
      B.atlas.accumulate(-d, color)
```

每个体素 256 个方向,每个方向一次光线投射。1000 个体素 = 25.6 万次光线投射 / 帧。每次光线投射遍历所有 1000 个体素(朴素版本),所以总计算量 = 1000 × 256 × 1000 = 2.56 亿次几何查询 / 帧。

**这跑不动**。60 FPS = 16 ms / 帧,2.56 亿次查询 / 16 ms = 1600 万查询 / ms,即 16000 / µs。每个查询几个纳秒,根本不可能。

**优化方向**:
1. **空间加速结构**(Spatial Acceleration Structure):不用遍历所有体素,通过 BVH / k-d tree / 八叉树快速找交点
2. **早期终止**(Early Termination):光撞到第一个体素就停,不要继续
3. **批量光线**(Packet Tracing):一次处理多条光线,SIMD 友好
4. **体素光栅化**(Voxel Raycasting):用 DDA 算法直接遍历网格,不查体素列表

Casey 这一天**开始**这个优化之旅——他选择"网格光线投射"(Grid Raycasting),基于 DDA(Digital Differential Analyzer)算法。这种方案对"网格化场景"(Casey 的体素网格)特别合适。

心理锚点:看完这集,你能识别"为什么朴素光线投射慢",理解 DDA 算法的几何直觉,能解释为什么 k-d tree(Day 595)和 Grid DDA 是不同选择。

## 2 · 心智模型

### 类比:走迷宫

你想从一个房间走到另一个房间,路上要避开墙壁。两种走法:

**走法 1(朴素)**:列所有房间,逐个检查"我有没有进这个房间"。检查 1000 个房间,最后才发现"我进了第 837 个房间"。慢。

**走法 2(网格步进)**:你站在房间 A,知道要去房间 B 的方向。沿着这个方向走,每跨过一面墙就进一个新房间。检查这面墙是新房间的哪一面,继续走。最多走 D 步(D 是 A 到 B 的房间数)。

DDA(Digital Differential Analyzer)就是走法 2 的算法。它沿着光线方向,一格一格地"跨过"网格,每次只检查一个格子,而不是遍历所有格子。

### 严谨原理:DDA 算法

考虑 2D 网格(便于画图,3D 类似)。光线从 `(x0, y0)` 出发,方向 `(dx, dy)`,要找第一个相交的"实心格子"(墙)。

**算法**(简化):

```
当前格 (cx, cy) = floor((x0, y0) / cell_size)
while (cx, cy) 在网格内:
    if grid[cx, cy] 是墙:
        return (cx, cy)  # 找到了
    # 算下一个格子的边界
    if (cx, cy) 是水平边界先到:
        cx += sign(dx)
    else:
        cy += sign(dy)
return None  # 光走出网格
```

**关键**:"哪个边界先到"用 DDA 算。设当前格 `(cx, cy)`,光在格内的位置 `(fx, fy)`(0 到 1)。沿方向 `dx, dy` 走,撞水平边界需要的 t = `(1 - fx) / dx`(如果 dx > 0)或 `fx / -dx`(如果 dx < 0)。撞垂直边界需要的 t = `(1 - fy) / dy`(类似)。比较两个 t,小的那个先到。

**3D 版本**:多一个 z 轴,逻辑相同。三个 t 比较,最小的胜出。

**伪代码**:

```rust
fn dda_raycast(grid: &Grid, origin: Vec3, dir: Vec3) -> Option<Vec3> {
    let cell_size = grid.cell_size;
    let mut cx = (origin.x / cell_size).floor() as i32;
    let mut cy = (origin.y / cell_size).floor() as i32;
    let mut cz = (origin.z / cell_size).floor() as i32;
    
    let dx = dir.x;
    let dy = dir.y;
    let dz = dir.z;
    
    let step_x = if dx > 0.0 { 1 } else { -1 };
    let step_y = if dy > 0.0 { 1 } else { -1 };
    let step_z = if dz > 0.0 { 1 } else { -1 };
    
    let mut t_max_x = ((cx + if dx > 0 { 1 } else { 0 }) as f32 * cell_size - origin.x) / dx;
    let mut t_max_y = ((cy + if dy > 0 { 1 } else { 0 }) as f32 * cell_size - origin.y) / dy;
    let mut t_max_z = ((cz + if dz > 0 { 1 } else { 0 }) as f32 * cell_size - origin.z) / dz;
    
    let t_delta_x = (cell_size / dx).abs();
    let t_delta_y = (cell_size / dy).abs();
    let t_delta_z = (cell_size / dz).abs();
    
    loop {
        if !grid.in_bounds(cx, cy, cz) {
            return None;  // 走出网格
        }
        if grid.is_solid(cx, cy, cz) {
            return Some(Vec3 { x: cx as f32, y: cy as f32, z: cz as f32 });
        }
        // 找最小的 t_max,跨过那条边
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            t_max_x += t_delta_x;
        } else if t_max_y < t_max_z {
            cy += step_y;
            t_max_y += t_delta_y;
        } else {
            cz += step_z;
            t_max_z += t_delta_z;
        }
    }
}
```

**每行解释**:
- `cx = floor(origin.x / cell_size)` — 起点所在格子。
- `step_x = sign(dx)` — x 方向步进(±1)。
- `t_max_x = ...` — 当前光位置到下一条 x 边界的"光线参数" t。t 是光线参数化的参数(`P(t) = origin + t * dir`)。
- `t_delta_x = |cell_size / dx|` — 跨一格 x 需要的 t 步长。
- 每次循环找最小 t_max,跨过那条边(进下一个格子)。

**复杂度**:O(D),D 是光线穿过的格子数。对 16×16×16 网格,D ≤ 48(三方向各最多 16 格)。比朴素 O(N = 4096)快 85 倍。

### DDA 的几何直觉

光在网格里"穿",每跨过一个格子的边界,进入新格子。DDA 不"扫描所有格子",只"沿光线方向走"。

**类比**:在地铁地图上,从 A 站到 B 站,你只看沿途经过的站,不看所有站。DDA 是"光线版的地铁线路查找"。

### 为什么 DDA 适合 Casey 的场景

Casey 的体素网格是**规则的**(每格 1m × 1m × 1m,固定大小)。规则网格让 DDA 的"边界距离"计算简单(整数倍 cell_size)。

如果网格**不规则**(八叉树、BVH),DDA 不能直接用,需要递归下降。Day 595 k-d tree 就是不规则结构。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,光线投射是基础工具:
- **光线追踪**(Ray Tracing):像素 → 世界,渲染
- **视线检测**(Line of Sight):NPC 能否看到玩家
- **子弹检测**(Hitscan):FPS 射击判定
- **鼠标拾取**(Picking):鼠标点中哪个物体

不同场景用不同加速结构:
- **静态场景**:预计算 BVH
- **动态场景**:k-d tree(每帧重建)或 Grid DDA(网格更新容易)
- **极简场景**:朴素遍历(几十个物体)

Casey 的 HH 用 Grid DDA,因为体素网格就是规则网格。

**踩过的坑**:
- **DDA 边界精度**:浮点误差让光"卡在边界"。解决:用 epsilon 偏移
- **斜 45 度光**:t_max_x = t_max_y 时,选哪个?约定固定选一个(避免抖动)
- **空网格 vs 实心网格**:Grid DDA 必须能区分,如果所有格子都"实心",DDA 立即返回

### 3.2 · 🎨 图形学视角

光线投射是图形学的核心算法之一。**Amanatides-Woo 算法**(1987)是 Grid DDA 的标准实现,Casey 用的就是这个。

**光线投射 vs 光线追踪**:
- **光线投射**:光从光源 → 一点,只算一次
- **光线追踪**:光从眼睛 → 世界,遇物体反弹,递归

光线追踪需要空间加速结构(BVH、k-d tree),Grid DDA 通常不够(因为光线追踪要追踪反射光,反射方向任意,Grid DDA 不一定快)。

**Voxel Raycasting**:专门针对体素场景的光线投射,Grid DDA 是核心。Minecraft 的体积云、积水效果都用 Voxel Raycasting。

### 3.4 · 🦀 Rust 生态视角

Rust 实现 DDA 的几个细节:

**整数 vs 浮点坐标**:`cx` 用 `i32`(支持负值,网格可能延伸到负坐标)。

**安全除零**:`t_max_x = ... / dx`,如果 `dx == 0`,除零。Rust 的 f32 除零返回 `+inf` 或 `-inf`,不 panic,但要处理:

```rust
let t_max_x = if dx.abs() > 1e-10 {
    ((cx + if dx > 0 { 1 } else { 0 }) as f32 * cell_size - origin.x) / dx
} else {
    f32::INFINITY  // 光线不沿 x 方向,永不撞 x 边界
};
```

**unsafe 边界检查**:在内循环里 `grid.is_solid(cx, cy, cz)` 需要边界检查。可以用 `unsafe` 跳过(Rust 默认每次数组访问检查越界):

```rust
// 安全版本(每帧几百万次边界检查)
fn is_solid(&self, x: i32, y: i32, z: i32) -> bool {
    if x < 0 || y < 0 || z < 0 || x >= self.dim || y >= self.dim || z >= self.dim {
        return false;
    }
    self.cells[(z * self.dim * self.dim + y * self.dim + x) as usize]
}

// 不安全版本(假设 caller 已经检查)
unsafe fn is_solid_unchecked(&self, x: i32, y: i32, z: i32) -> bool {
    self.cells.get_unchecked((z * self.dim * self.dim + y * self.dim + x) as usize)
}
```

`get_unchecked` 跳过边界检查,加速 10-20%。Casey 在 DDA 内循环用 unchecked(已经在外层检查)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Grid DDA 的复杂度是 O(N^(1/3)),N 是体素总数。请用具体数字解释这个复杂度的含义。

**参考解答**:对 16×16×16 = 4096 体素的网格,N = 4096,N^(1/3) ≈ 16。一条光线最多穿过 3 × 16 = 48 个格子(三方向各最多 16 个)。Grid DDA 每条光线检查 48 次,朴素遍历检查 4096 次。加速 85 倍。

如果网格扩到 64×64×64 = 262144,N^(1/3) = 64,DDA 每光 192 次,朴素 262144 次。加速 1365 倍。网格越大,DDA 优势越大。

### Lv2 · 动手实践

**题**:实现一个简化 2D Grid DDA,在 16×16 网格里找第一个实心格子。测试:
- 网格里某个格子是墙
- 从 (0.5, 0.5) 朝 (1, 1) 方向射光,应该穿过对角格子,撞到墙

完成标准:`cargo run` 打印光穿过的格子序列 + 最终命中。

**参考解答**:

```rust
struct Grid2D {
    dim: usize,
    cells: Vec<bool>,
}

impl Grid2D {
    fn new(dim: usize) -> Self {
        Self { dim, cells: vec![false; dim * dim] }
    }
    fn set_solid(&mut self, x: usize, y: usize) {
        self.cells[y * self.dim + x] = true;
    }
    fn is_solid(&self, x: i32, y: i32) -> bool {
        if x < 0 || y < 0 || x >= self.dim as i32 || y >= self.dim as i32 {
            return false;
        }
        self.cells[y as usize * self.dim + x as usize]
    }
    fn in_bounds(&self, x: i32, y: i32) -> bool {
        x >= 0 && y >= 0 && (x as usize) < self.dim && (y as usize) < self.dim
    }
}

fn dda_raycast_2d(grid: &Grid2D, ox: f32, oy: f32, dx: f32, dy: f32) -> Vec<(i32, i32)> {
    let cell_size = 1.0;
    let mut cx = (ox / cell_size).floor() as i32;
    let mut cy = (oy / cell_size).floor() as i32;
    
    let step_x = if dx > 0.0 { 1 } else { -1 };
    let step_y = if dy > 0.0 { 1 } else { -1 };
    
    let mut t_max_x = if dx.abs() > 1e-10 {
        (((cx + if dx > 0 { 1 } else { 0 }) as f32) * cell_size - ox) / dx
    } else { f32::INFINITY };
    let mut t_max_y = if dy.abs() > 1e-10 {
        (((cy + if dy > 0 { 1 } else { 0 }) as f32) * cell_size - oy) / dy
    } else { f32::INFINITY };
    
    let t_delta_x = if dx.abs() > 1e-10 { (cell_size / dx).abs() } else { f32::INFINITY };
    let t_delta_y = if dy.abs() > 1e-10 { (cell_size / dy).abs() } else { f32::INFINITY };
    
    let mut path = vec![(cx, cy)];
    
    for _ in 0..1000 {  // 限制迭代次数防爆
        if !grid.in_bounds(cx, cy) {
            break;
        }
        if grid.is_solid(cx, cy) {
            return path;
        }
        if t_max_x < t_max_y {
            cx += step_x;
            t_max_x += t_delta_x;
        } else {
            cy += step_y;
            t_max_y += t_delta_y;
        }
        path.push((cx, cy));
    }
    path
}

fn main() {
    let mut grid = Grid2D::new(16);
    grid.set_solid(10, 10);  // 在 (10, 10) 放墙
    grid.set_solid(5, 5);    // (5, 5) 放墙
    
    let path = dda_raycast_2d(&grid, 0.5, 0.5, 1.0, 1.0);
    println!("Ray path (size {}):", path.len());
    for (i, (x, y)) in path.iter().enumerate() {
        println!("  step {}: ({}, {})", i, x, y);
    }
}
```

**每行解释**:
- `cell_size = 1.0` — 每格 1m。
- `t_max_x` — 光到下一条 x 边界的参数。
- `t_delta_x = |cell_size / dx|` — 跨一格 x 需要的 t 增量。
- 限制 1000 次循环防爆 — 万一逻辑错,不会无限循环。

```rust
    let path = dda_raycast_2d(&grid, 0.5, 0.5, 1.0, 0.7);
    println!("Single ray path size: {}", path.len());
    
    // 批量投射(性能测试)
    let n_rays = 100_000;
    let dirs: Vec<(f32, f32)> = (0..n_rays).map(|i| {
        let t = i as f32 * 0.001;
        (t.sin(), t.cos())
    }).collect();
    
    let start = std::time::Instant::now();
    let mut total_steps = 0;
    for &(dx, dy) in &dirs {
        let path = dda_raycast_2d(&grid, 0.5, 0.5, dx, dy);
        total_steps += path.len();
    }
    let elapsed = start.elapsed();
    
    println!("\n{} rays in {:?}", n_rays, elapsed);
    println!("Per ray: {:.2} µs", elapsed.as_micros() as f64 / n_rays as f64);
    println!("Average path length: {:.1}", total_steps as f64 / n_rays as f64);
}
```

### A.2 Voxel lighting 的工程挑战

Voxel lighting 是计算机图形学的难点,因为:

**1. 数据量大**:
- 大场景(100m × 100m × 100m)有几百万 voxel
- 每 voxel 存光照值(RGB 或 SH)
- 总数据 GB 级

**2. 实时性要求**:
- 玩家挖 / 改 voxel,光照立即变化
- 16.67 ms 帧预算(60 FPS)
- 不能阻塞玩家操作

**3. 物理准确性**:
- 直接光(sun)
- 间接光(bounce)
- 阴影(hard / soft)
- 反射(diffuse / specular)
- 折射(glass / water)

工业方案在物理准确性和实时性之间权衡。

### A.3 工业级实现的层次

**Layer 1:Brute force**
- 每 voxel × 每方向 raycast
- 准确但极慢
- 适合离线渲染(movie)

**Layer 2:Grid DDA**
- 快速 raycast(穿格子)
- 适合简单场景
- Casey 的 HH 用这层

**Layer 3:Precomputed**
- 离线算光照 cache
- 运行时查表
- 适合静态场景(Minecraft baked)

**Layer 4:Real-time approximation**
- LPV / SVOGI / Voxel Cone Tracing
- 实时但近似
- Crytek / Unreal 用

**Layer 5:Hardware ray tracing**
- RTX / RDNA2 核心
- 真实光传播
- Minecraft RTX / Teardown

每代技术对硬件要求递增。Casey 的 HH 在 Layer 2(教学优先)。

### A.4 性能 profile 的实战

Casey 在 phase-8 多次 profile:

**Profile 工具**:
- Linux:perf、Valgrind、flamegraph

### A.7 Voxel lighting 算法的核心循环

让我写一个简化的 voxel lighting 主循环:

```rust
fn update_lighting(world: &mut World, sun_dir: Vec3) {
    let direct = compute_direct_lighting(world, sun_dir);
    let indirect = compute_indirect_lighting(world, &direct, 3);  // 3 bounce
    let final_light = combine(&direct, &indirect);
    world.light_atlas = final_light;
}

fn compute_direct_lighting(world: &World, sun_dir: Vec3) -> LightAtlas {
    let mut atlas = LightAtlas::new(world.dims());
    for each voxel {
        if voxel.is_solid() && !is_occluded(world, voxel_pos, sun_dir) {
            let lambert = compute_normal(world, x, y, z).dot(sun_dir).max(0.0);
            atlas.set(x, y, z, sun_color * lambert);
        }
    }
    atlas
}

fn compute_indirect_lighting(world: &World, direct: &LightAtlas, bounces: usize) -> LightAtlas {
    let mut current = direct.clone();
    for _ in 0..bounces {
        let mut next = current.clone();
        for each voxel {
            let bounce = average_neighbors(&current, x, y, z) * 0.15;
            next.set(x, y, z, current.get(x, y, z) + bounce);
        }
        current = next;
    }
    current
}
```

这是 Casey phase-8 的简化核心。工业实现更复杂(SH、GPU、并行)。


### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
