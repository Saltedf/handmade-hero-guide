
# Day 600 · 更好的 AABB 法线推导

> Day 599 实现了 Grid DDA postamble,法线只能 ±x / ±y / ±z。今天 Casey 探讨"能不能从 ray-AABB 相交结果推导更精确的法线"——这是 Day 594 ray-AABB 的延伸。

## 0 · 为什么要有这一天

Day 599 的 Grid DDA 法线:
- 优点:简单(轴对齐)
- 缺点:斜墙体的法线"跳变"——光在 ±x 和 ±y 之间频繁切换,光照计算出现伪影

**问题**:能不能从 ray-AABB 相交结果推导"更精确"的法线?

回顾 Day 594 的 ray-AABB(Slab method):

```rust
fn ray_aabb_intersect(ray: &Ray, aabb: &AABB) -> Option<f32> {
    let mut t_min = -INFINITY;
    let mut t_max = INFINITY;
    
    for axis in 0..3 {
        let t1 = (aabb.min[axis] - ray.origin[axis]) / ray.dir[axis];
        let t2 = (aabb.max[axis] - ray.origin[axis]) / ray.dir[axis];
        let (t1, t2) = if t1 < t2 { (t1, t2) } else { (t2, t1) };
        
        t_min = t_min.max(t1);  // 最后一个 t1 是"入射面"
        t_max = t_max.min(t2);
    }
    
    Some(t_min)
}
```

`t_min` 是"光线进入 AABB 的 t 值"。最后一次 `t_min.max(t1)` 的 `t1` 来自哪个 axis?**那个 axis 就是法线方向**。

这就是 Day 600 的核心——从 ray-AABB 内部状态推导法线。

心理锚点:看完这集,你能从 ray-AABB 相交推导法线,理解"为什么 ray-AABB 比朴素 DDA 更精确",能在自己写代码时利用"算法副产品"(副产品 = 内部状态)。

## 1 · Casey 今天做了什么

Casey 这一天的几个动作:

1. **复习 Slab method**:回看 Day 594 的 ray-AABB,识别"哪个 axis 决定 t_min"。
2. **改 ray-aabb 签名**:从返回 `Option<f32>` 改成返回 `Option<(f32, Vec3)>`(t + normal)。
3. **比较**:Grid DDA vs ray-AABB 在不同场景的精度。
4. **决定**:Grid DDA 用于"粗筛选"(找哪些体素被光穿过),ray-AABB 用于"精确求交"(在该体素内求 wall 的精确法线)。

这一天的工程产出大约 80 行 Rust 代码,价值在于**让法线推导更精确**——为后续高质量 GI 做准备。

## 2 · 心智模型

### 类比:更精细的 GPS

简单 GPS 只给你"哪个街区"(Grid DDA 法线 = 街区方向)。精细 GPS 给你"哪条街 + 哪个车道"(ray-AABB 法线 = 精确面)。

ray-AABB 的 Slab method 在内部计算了"光从哪个面进入 AABB"——这个信息一直存在,只是 Day 594 的返回值没暴露。Day 600 把这个内部状态变成输出。

### 严谨原理:Slab method 内部状态

```rust
fn ray_aabb_with_normal(ray: &Ray, aabb: &AABB) -> Option<(f32, Vec3)> {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    let mut normal_axis = 0u8;
    let mut normal_sign = 1.0f32;
    
    for axis in 0..3 {
        let dir = ray.dir[axis];
        let origin = ray.origin[axis];
        let mn = aabb.min[axis];
        let mx = aabb.max[axis];
        
        if dir.abs() < 1e-10 {
            if origin < mn || origin > mx {
                return None;
            }
        } else {
            let mut t1 = (mn - origin) / dir;
            let mut t2 = (mx - origin) / dir;
            let mut sign1 = -1.0;  // mn 面的法线(指向 -axis)
            let mut sign2 = 1.0;   // mx 面的法线(指向 +axis)
            
            if t1 > t2 {
                std::mem::swap(&mut t1, &mut t2);
                std::mem::swap(&mut sign1, &mut sign2);
            }
            
            if t1 > t_min {
                t_min = t1;
                normal_axis = axis as u8;
                normal_sign = sign1;
            }
            
            t_max = t_max.min(t2);
            if t_min > t_max {
                return None;
            }
        }
    }
    
    if t_max < 0.0 {
        return None;
    }
    
    let t = t_min.max(0.0);
    let normal = match normal_axis {
        0 => Vec3::new(normal_sign, 0.0, 0.0),
        1 => Vec3::new(0.0, normal_sign, 0.0),
        _ => Vec3::new(0.0, 0.0, normal_sign),
    };
    
    Some((t, normal))
}
```

**关键改动**:
- 跟踪 `normal_axis` 和 `normal_sign`。
- 在 Slab 内循环里更新 t_min 时,记录 axis 和 sign。

**几何直觉**:
- `t1 = (min - origin) / dir` — 光线到达 min 面的 t。
- `t2 = (max - origin) / dir` — 光线到达 max 面的 t。
- 如果 t1 > t2,光线"反向"穿过(min 面在后,max 面在前),swap 两个 + swap 法线符号。
- 最后 t_min = max(所有 t1)。"最大的 t1" 决定光实际进入 AABB 的面。

### 与 Grid DDA 比较

Grid DDA 法线:
- 跟踪 last_axis 和 last_step
- 输出 ±x / ±y / ±z

ray-AABB 法线:
- 跟踪 normal_axis 和 normal_sign
- 输出 ±x / ±y / ±z

**两者输出格式相同**,但 ray-AABB 的精度可能更高——因为 Slab method 在"轴对齐面"上精确,Grid DDA 在"体素边界"上近似。

**实际差别**:对**轴对齐墙体**(墙的法线就是 ±x / ±y / ±z),两者完全相同。对**斜墙**或**非规则墙体**(实际不存在于体素网格),两者仍只能给轴对齐法线。

**真正改进**:如果墙体是 AABB(不是体素),ray-AABB 能精确求交。Grid DDA 是"体素近似 AABB"。

### 二者结合:混合方案

Casey 决定**混合**:
- 用 Grid DDA 找"光穿过哪些体素"
- 在每个体素内,如果该体素有 AABB(精确墙体),用 ray-AABB 求精确交点

```rust
fn hybrid_raycast(world: &World, ray: &Ray, max_dist: f32) -> Option<HitInfo> {
    // 1. Grid DDA 找光穿过的体素
    let path = grid_dda_path(world, ray, max_dist);
    
    // 2. 对每个体素,检查其中的 AABB
    for voxel_pos in path {
        if let Some(aabb) = world.voxel_aabb(voxel_pos) {
            if let Some((t, normal)) = ray_aabb_with_normal(ray, aabb) {
                // 验证 t 在体素范围内
                let voxel_min = world.voxel_origin(voxel_pos);
                let voxel_max = voxel_min + world.voxel_size;
                let hit_point = ray.origin + ray.dir * t;
                if aabb.contains(hit_point) {
                    return Some(HitInfo {
                        point: hit_point,
                        normal,
                        distance: t,
                        voxel: voxel_pos,
                    });
                }
            }
        }
    }
    None
}
```

**关键**:Grid DDA 给"光穿过哪些体素"(粗筛选),ray-AABB 给"精确交点"(细查)。这样保留了 Grid DDA 的速度,又有 ray-AABB 的精度。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,"混合加速结构"很常见:
- **粗 + 细**:Grid → BVH(网格粗筛,BVH 细查)
- **空间 + 物体**:BVH → Triangle(AABB 测试 + 三角形精确求交)
- **GPU RTX**:TLAS → BLAS(顶层实例 + 底层三角形)

**Casey 的混合方案**:Grid DDA(粗)+ ray-AABB(细)。简单实用。

**踩过的坑**:
- **重叠 AABB**:多个 AABB 在同一体素内,需要测所有
- **边界 AABB**:AABB 跨越多个体素,光可能在"非该 AABB 体素"内击中它
- **法线翻转**:从外部 vs 内部看 AABB,法线方向相反

### 3.2 · 🎨 图形学视角

**法线推导的数学**:ray-AABB 的法线推导是几何计算。"光线最先撞到的面" = "光从哪个面进入 AABB"。Slab method 在算法过程中已经计算了这个信息,只需暴露。

**Implicit surfaces**:对于非 AABB 的物体(球、圆柱),法线推导类似——算"光线最先撞到的点",法线 = 该点的表面梯度。

**Normal interpolation**:对三角形网格,顶点有法线,三角形内的法线用**重心坐标插值**。这让低多边形看起来平滑(每三角形法线 vs 顶点法线插值)。

### 3.3 · 🐧 Linux 系统编程视角

这一集主要是数学,Linux 系统调用面没什么。但**性能分析**值得一提。

ray-AABB-with-normal 比简单 ray-AABB 多 1-2 个变量维护,性能差异 < 5%。

```bash
sudo perf stat -e instructions,cycles ./raytracer
# 比较两个版本的 IPC 和指令数
```

### 3.4 · 🦀 Rust 生态视角

Rust 实现法线推导的几个细节:

**1. 元组 vs struct**:返回 `(f32, Vec3)` 简洁,但容易混淆。struct 更清晰:

```rust
struct RayHit {
    t: f32,
    normal: Vec3,
}

fn ray_aabb(...) -> Option<RayHit> { ... }
```

**2. 编译器优化**:Slab method 内的 if/swap 容易阻碍 SIMD 化。Rust 编译器有时能自动向量化,有时不能。手写 branchless 版本:

```rust
let t1 = (mn - origin) / dir;
let t2 = (mx - origin) / dir;
let t_near = t1.min(t2);
let t_far = t1.max(t2);
let sign_near = if t1 < t2 { -1.0 } else { 1.0 };
// 无 swap 分支
```

更难读但更快。

## 5 · 对照与变奏

### 同一法线问题在不同语境下的变体

| 语境 | 法线 |
|---|---|
| Grid DDA | ±x/±y/±z(轴对齐)|
| ray-AABB | ±x/±y/±z(轴对齐)|
| Triangle(平面)| 三角形平面法线 |
| Sphere | 球心到点的方向 |
| Mesh(顶点法线)| 重心插值 |
| Normal map | 纹理 lookup |

每种都是"垂直于表面的向量"。

### 历史演化

- **1970s**:光线追踪用平面法线
- **1980s**:顶点法线插值(Phong shading)
- **1990s**:Normal map(bump map 的进化)
- **2000s+**:PBR 法线 + 微表面

Casey 在 Day 600 用最基础 ray-AABB 法线,后面加 normal map。

### 法线方向约定

**外部 vs 内部**:对 ray-AABB,光从外部进入。法线朝外(指向光来源)。

**左手 vs 右手**:不同坐标系(OpenGL 右手,DirectX 左手)的法线叉积方向不同。Casey 用右手坐标系。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Slab method 在算 t_min 时能顺便得到法线信息?具体是哪一步暴露的?

**参考解答**:Slab method 对每个 axis 计算 t1(进入 min 面的 t)和 t2(进入 max 面的 t)。t_min 是"所有 axis 的 t1 的最大值"——这个最大值来自哪个 axis,那个 axis 就是光线"最后进入的面",也就是"最先撞到的面"(从光来源方向看)。

具体:t_min = max(t1_x, t1_y, t1_z)。如果 t1_x 是最大的,光在 x 方向"最晚进入"——意味着 x 方向是"瓶颈",光最先撞到 x 面。该面的法线 = ±x(根据 t1 是 min 还是 max 面决定)。

### Lv2 · 动手实践

**题**:扩展 day594 的 ray_aabb_intersect,返回 `Option<(f32, Vec3)>`(t + normal)。测试:
- 光从 (0, 0, -1) 朝 +z,AABB = (-1, -1, 0) - (1, 1, 1)
- 应该 t=1.0,normal=(0, 0, -1)

完成标准:`cargo run` 测试通过。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug, PartialEq)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
}

struct AABB { min: Vec3, max: Vec3 }
struct Ray { origin: Vec3, dir: Vec3 }

fn ray_aabb_normal(ray: &Ray, aabb: &AABB) -> Option<(f32, Vec3)> {
    let mut t_min = f32::NEG_INFINITY;
    let mut t_max = f32::INFINITY;
    let mut normal = Vec3::new(0.0, 0.0, 0.0);
    
    let axes = [
        (ray.origin.x, ray.dir.x, aabb.min.x, aabb.max.x, Vec3::new(1.0, 0.0, 0.0)),
        (ray.origin.y, ray.dir.y, aabb.min.y, aabb.max.y, Vec3::new(0.0, 1.0, 0.0)),
        (ray.origin.z, ray.dir.z, aabb.min.z, aabb.max.z, Vec3::new(0.0, 0.0, 1.0)),
    ];
    
    for (origin, dir, mn, mx, axis_normal) in axes.iter() {
        if dir.abs() < 1e-10 {
            if *origin < *mn || *origin > *mx {
                return None;
            }
        } else {
            let t1 = (*mn - *origin) / dir;
            let t2 = (*mx - *origin) / dir;
            let (t_near, t_far, n_near) = if t1 < t2 {
                (t1, t2, axis_normal.scale(-1.0))
            } else {
                (t2, t1, *axis_normal)
            };
            
            if t_near > t_min {
                t_min = t_near;
                normal = n_near;
            }
            t_max = t_max.min(t_far);
            if t_min > t_max {
                return None;
            }
        }
    }
    
    if t_max < 0.0 {
        None
    } else {
        Some((t_min.max(0.0), normal))
    }
}

impl Vec3 {
    fn scale(self, k: f32) -> Self {
        Self::new(self.x * k, self.y * k, self.z * k)
    }
}

fn main() {
    let aabb = AABB {
        min: Vec3::new(-1.0, -1.0, 0.0),
        max: Vec3::new(1.0, 1.0, 1.0),
    };
    let ray = Ray {
        origin: Vec3::new(0.0, 0.0, -1.0),
        dir: Vec3::new(0.0, 0.0, 1.0),
    };
    
    if let Some((t, n)) = ray_aabb_normal(&ray, &aabb) {
        println!("Hit at t={}, normal=({},{},{})", t, n.x, n.y, n.z);
        assert_eq!(t, 1.0);
        assert_eq!(n, Vec3::new(0.0, 0.0, -1.0));
        println!("OK");
    }
}
```

## 10 · 补充材料:Voxel 系统的基础

### A.1 Voxel 数据结构

Voxel(volumetric pixel)是 3D 像素。基础数据结构:

```rust
struct Voxel {
    material: u8,  // 0=air, 1=stone, 2=wood, ...
    color: [u8; 3],
    // 或更复杂:light, normal, etc.
}

struct VoxelWorld {
    voxels: Vec<Voxel>,  // 紧凑 1D 数组
    width: u32,
    height: u32,
    depth: u32,
}

impl VoxelWorld {
    fn idx(&self, x: u32, y: u32, z: u32) -> usize {
        (z * self.height * self.width + y * self.width + x) as usize
    }
    
    fn get(&self, x: u32, y: u32, z: u32) -> &Voxel {
        &self.voxels[self.idx(x, y, z)]
    }
}
```

紧凑数组是最简单的实现。Minecraft-like 游戏用 chunked storage(每个 chunk 32^3,world 是 chunk 的 hash map)。

### A.2 Voxel 编辑

Voxel 编辑是核心交互:

```rust
fn set_voxel(world: &mut VoxelWorld, x: i32, y: i32, z: i32, voxel: Voxel) {
    if x < 0 || y < 0 || z < 0 { return; }
    if (x as u32) >= world.width || (y as u32) >= world.height || (z as u32) >= world.depth {
        return;
    }
    let idx = world.idx(x as u32, y as u32, z as u32);
    world.voxels[idx] = voxel;
}

fn dig_voxel(world: &mut VoxelWorld, x: i32, y: i32, z: i32) {
    // 把 voxel 设为 air
    set_voxel(world, x, y, z, Voxel::air());
    
    // 触发 lighting 重新计算(挖掉后光线进来)
    relight_region(world, x, y, z);
}
```

每次编辑要触发 lighting 更新,这是 voxel 游戏的核心性能挑战。

### A.3 Mesh extraction(greedy meshing)

Voxel world 渲染:把 voxel grid 转成三角形 mesh。简单方案:每 voxel 6 个面 × 2 三角形 = 12 三角形。但 100^3 voxel = 100 万 voxel × 12 三角形 = 1200 万三角形。太多。

**Greedy meshing**:合并相邻同 material voxel 的面,大幅减少三角形。

```
原始(5 个 voxel 的面):
  □ □ □ □ □    ← 5 个 quad = 10 三角形

Greedy:
  □ □ □ □ □    ← 1 个长 quad = 2 三角形
```

100 万 voxel greedy meshing 后可能只剩几万三角形,可渲染。

实现见 Mikola Lysenko 的博客"Meshing in a Voxel Game"。

### A.4 Chunk streaming

Voxel 大世界用 chunked streaming:

```
World = HashMap<ChunkCoord, Chunk>

Chunk:
  coord: (i32, i32, i32)  // chunk 网格坐标
  voxels: 32^3 Voxel
  mesh: Option<Mesh>  // 渲染 mesh
  light_atlas: LightAtlas  // 32^3 光照
```

玩家移动:
1. 计算可见 chunk(基于 camera frustum + 距离)
2. 异步加载 / 卸载 chunk
3. 生成 mesh
4. 渲染

这是 Minecraft / 7 Days to Die 的架构。

### A.5 Voxel lighting 的特殊挑战

Voxel lighting 比 mesh lighting 难:
- 玩家挖 voxel → 光线传播改变 → 重新计算
- 玩家放 voxel → 阴影改变 → 重新计算
- 实时性:几毫秒内完成更新

工业方案:
- **Flood fill lighting**:从光源 BFS 传播,适合简单 diffuse
- **Photon mapping**:从光源发射光子,记录命中点
- **Voxel cone tracing**:GPU 实时
- **Precomputed + delta update**:大部分 precomputed,变化部分增量更新

Casey 的 HH 用 flood fill / propagation,基础但够教学。

### A.6 Voxel physics(碰撞)

Voxel 世界的物理碰撞:

```rust
fn collide_player(world: &VoxelWorld, player: &mut Player) {
    let player_aabb = player.aabb();
    
    // 找 player AABB 范围内的所有 voxel
    let min_x = player_aabb.min.x.floor() as i32;
    let max_x = player_aabb.max.x.floor() as i32;
    // ... y, z 类似
    
    for z in min_z..=max_z {
        for y in min_y..=max_y {
            for x in min_x..=max_x {
                if let Some(voxel) = world.get_opt(x, y, z) {
                    if voxel.is_solid() {
                        let voxel_aabb = AABB::new(x, y, z, 1, 1, 1);
                        if player_aabb.intersects(voxel_aabb) {
                            // 推开 player
                            resolve_collision(player, voxel_aabb);
                        }
                    }
                }
            }
        }
    }
}
```

这是 swept AABB collision。Minecraft / Cube World 的物理基础。

### A.9 Voxel 渲染的 GPU 实现

Voxel GPU 渲染关键:

**Vertex shader**:每 voxel 一个 instance,shader 内计算位置。

**Geometry shader**:输入 voxel data,输出 6 个面(或更少,根据邻居)。

**Compute shader**:parallel meshing,GPU 上跑 greedy meshing。

**Indirect draw**:CPU 计算 draw indirect 参数,GPU 直接执行,无 CPU/GPU 同步。

工业 voxel 渲染 GPU pipeline:

```
1. Compute shader:determine visible voxels
2. Compute shader:greedy meshing on visible voxels
3. Compute shader:write draw indirect params
4. Vertex shader:render mesh
5. Fragment shader:shade + lighting
```

每步 GPU 完成,CPU 只发起 indirect dispatch。极快。

### A.10 Voxel 容量规划

Voxel 内存占用估算:

```
每 voxel:
  - material: 1 byte
  - light level: 1 byte(Minecraft 风格)
  - 或更复杂:color(3 byte) + light(3 byte) + flags(1 byte) = 8 byte

100^3 voxel = 1M voxel
  - 简单(2 byte):2 MB
  - 复杂(8 byte):8 MB

1000^3 voxel = 1B voxel
  - 简单:2 GB
  - 复杂:8 GB

太大。所以工业用 streaming,只加载附近。
```

Minecraft 默认 render distance 12 chunk(= 384 block),内存占用约 100-200 MB。Teardown 整个游戏 1 km³ voxel,占 8+ GB RAM。
