
# Day 610 · 移除错误体素-体素反射

> Day 609 降低了不可达体素的贡献,但还有一个相关 bug:某些"相邻体素"的辐射场互相影响,产生"虚假反射"。今天 Casey 修这个 bug——检查两个体素之间是否有"墙体阻挡",如果有,不能互相贡献。

## 0 · 为什么要有这一天

回顾 GI 数据流:

```
体素 A 的辐射场 ← 接收所有其他体素 B 的辐射
```

这个"所有其他体素"假设了"A 能看见 B"。但如果 A 和 B 之间有墙,A 实际不能"看见"B,代码不应该让 B 贡献 A。

**Bug 现象**:墙两边的体素互相贡献辐射场,光"穿过墙"。墙后亮,前墙也变亮(因为吸收了墙后的"虚假光")。

**解决**:
1. **检测遮挡**:对每对(A, B),raycast 从 A 到 B,如果中间有墙,标记"遮挡"
2. **跳过遮挡对的贡献**:如果 A 和 B 互相遮挡,不计入对方的辐射场

这是 Day 609 的扩展——Day 609 处理"单个体素的可达性",Day 610 处理"两个体素之间的可见性"。

心理锚点:看完这集,你能识别"数据间关系"的合理性(哪些数据应该互相影响),能用算法过滤"虚假关系",能在自己写系统时考虑"数据之间的可见性 / 连通性"。

## 1 · Casey 今天做了什么

Casey 这一天的几个动作:

1. **可视化发现问题**:Day 608 的 heatmap 模式显示,墙两边的 atlas 有"对称亮斑"——墙后亮,墙前对应位置也亮。这是"虚假反射"。

## 2 · 心智模型

### 类比:两人对话被墙挡

你和朋友分别在墙两边。物理上,你们的声音穿不过墙——你听不到他,他听不到你。

但代码模拟时,如果不考虑墙,你们的声音互相"听到"——这就是"虚假反射"。修复:墙挡了,就不互相听。

GI 完全一样——墙两边的体素互相"看不见",代码不该让它们贡献。

### 严谨原理:可见性矩阵

对 N 个体素,N × N 的可见性矩阵 `V`,其中 `V[A][B]` = true 表示 A 能看见 B(中间无遮挡)。

```rust
struct VisibilityMatrix {
    matrix: Vec<Vec<bool>>,  // matrix[A][B]
    n: usize,
}

impl VisibilityMatrix {
    fn compute(world: &World) -> Self {
        let n = world.voxels.len();
        let mut matrix = vec![vec![false; n]; n];
        
        for a in 0..n {
            for b in (a+1)..n {
                let pos_a = world.voxels[a].pos;
                let pos_b = world.voxels[b].pos;
                let dir = (pos_b - pos_a).normalize();
                let dist = (pos_b - pos_a).length();
                let ray = Ray { origin: pos_a, dir };
                
                // 射线从 A 到 B,如果中间没墙,可见
                let hit = raycast(world, &ray, dist - 0.01);
                let visible = hit.is_none();
                matrix[a][b] = visible;
                matrix[b][a] = visible;  // 对称
            }
            matrix[a][a] = true;  // 自己可见自己
        }
        
        Self { matrix, n }
    }
    
    fn visible(&self, a: usize, b: usize) -> bool {
        self.matrix[a][b]
    }
}
```

**关键**:
- `dist - 0.01` — 略小于实际距离,避免命中 B 自己。
- 对称:`matrix[a][b] = matrix[b][a]`(可见性对称)。
- 对角线:`matrix[a][a] = true`(自己可见自己)。

**复杂度**:O(N²) 空间,O(N² × raycast) 时间。N=1000 时:100 万 raycast,太慢。

**优化**:**稀疏可见性**——只存 visible 的对(用 HashSet),或**分块可见性**——只对相邻体素算可见性(远处的不影响)。

### 修改 propagate

```rust
fn gather_incoming_light(world: &World, vis: &VisibilityMatrix, target_idx: usize) -> LightAtlas {
    let mut incoming = LightAtlas::new(16);
    let target_pos = world.voxels[target_idx].pos;
    
    for (i, voxel) in world.voxels.iter().enumerate() {
        if i == target_idx { continue; }
        
        // 可见性检查
        if !vis.visible(target_idx, i) {
            continue;  // 不可见,跳过贡献
        }
        
        let dir = (voxel.pos - target_pos).normalize();
        let color = voxel.atlas.sample(-dir);
        // ... 衰减、accumulate
        incoming.accumulate(dir, color);
    }
    
    incoming
}
```

**关键**:加 `if !vis.visible(target_idx, i) { continue; }`。不可见的体素跳过。

### 离线计算 vs 在线计算

**离线**(场景不变,启动时算一次):

```rust
let visibility = VisibilityMatrix::compute(&world);  // 启动时
// 运行时直接查表
```

**优点**:启动后查询 O(1)。
**缺点**:场景变化要重算。

**在线**(每次 propagate 时算):

```rust
fn gather_incoming_light(world: &World, target_idx: usize) -> LightAtlas {
    for (i, voxel) in &world.voxels {
        // 在线 raycast 检查可见性
        let dir = (voxel.pos - target_pos).normalize();
        let dist = (voxel.pos - target_pos).length();
        if raycast(world, ray, dist - 0.01).is_some() {
            continue;  // 中间有墙,跳过
        }
        // ... 贡献
    }
}
```

**优点**:动态场景。
**缺点**:每帧大量 raycast,慢。

Casey 在 Day 610 用离线(场景静态),后续动态场景需要在线。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里"可见性"是核心概念:
- **Potentially Visible Set(PVS)**:预计算"哪些区域可能看见哪些"
- **Occlusion Culling**:运行时遮挡剔除
- **Portal Rendering**:用"门户"(门、窗)划分可见区域

**PVS 示例**:Quake 用 PVS——把地图分 cells,预计算每个 cell 能看见哪些其他 cell。运行时只渲染可见 cells。

**踩过的坑**:
- **PVS 内存爆**:N² 矩阵太大。解决:稀疏表示或 cell-based
- **动态场景**:PVS 假设静态,动态物体需另算
- **可见性突变**:玩家走动时可见性突变,渲染跳变。解决:渐变过渡

### 3.2 · 🎨 图形学视角

**Visibility** 在图形学有多种形式:
- **Direct visibility**:点对点能否直接看见
- **Cell-to-cell visibility**:区域对区域(更粗粒度)
- **Ray-based visibility**:具体光线的可见性

**Ray coherence**:相邻光线的可见性接近(因为几何结构相似)。利用这个可以批量处理。

**Probabilistic visibility**:蒙特卡洛采样,统计估计可见性概率。常用于路径追踪的"shadow ray"。

### 3.4 · 🦀 Rust 生态视角

Rust 实现"对称矩阵"的几种方式:

**1. Vec<Vec<bool>>**:简单,但浪费(对称矩阵只存一半)。

**2. 三角矩阵**:只存上三角。

```rust
struct SymmetricMatrix {
    data: Vec<bool>,  // n*(n-1)/2 个元素
    n: usize,
}

impl SymmetricMatrix {
    fn get(&self, a: usize, b: usize) -> bool {
        if a == b { return true; }
        let (a, b) = if a < b { (a, b) } else { (b, a) };
        let idx = a * self.n + b - a * (a + 1) / 2 - a - 1;
        self.data[idx]
    }
}
```

省 50% 内存,但访问复杂。

**3. HashSet**:

```rust
struct SparseVisibility {
    pairs: HashSet<(usize, usize)>,
}

impl SparseVisibility {
    fn get(&self, a: usize, b: usize) -> bool {
        let key = if a < b { (a, b) } else { (b, a) };
        self.pairs.contains(&key)
    }
}
```

稀疏场景(大部分不可见),省 90%+ 内存。但 hash 查询慢(O(1) 但常数大)。

Casey 在 Day 610 用 `Vec<Vec<bool>>`,简单。生产代码可能用稀疏。

### Lv1 · 概念辨析

**题**:Day 609 的"可达性"和 Day 610 的"可见性"有什么本质区别?

**参考解答**:
- **Day 609 可达性**:单个体素的属性——它能不能从场景外部访问(逃出去)。二元:可达 / 不可达
- **Day 610 可见性**:两个体素之间的关系——它们之间有没有遮挡。成对:A 看得见 B 吗

可达性是"自己 vs 全部"的关系,可见性是"A vs B"的关系。

具体差别:
- 一个被半围的体素可能"可达"(部分方向可逃),但与某些远处体素"不可见"(中间被墙挡)
- 一个开放体素一定"可达",但可能与远处体素"不可见"(中间有山)

**参考解答**:

```rust
struct World2D {
    dim: usize,
    cells: Vec<bool>,
    voxels: Vec<(i32, i32)>,
}

impl World2D {
    fn is_wall(&self, x: i32, y: i32) -> bool {
        if x < 0 || y < 0 || x >= self.dim as i32 || y >= self.dim as i32 { return true; }
        self.cells[y as usize * self.dim + x as usize]
    }
}

fn bresenham_blocked(world: &World2D, x0: i32, y0: i32, x1: i32, y1: i32) -> bool {
    // Bresenham 直线,检查中间点是否墙
    let dx = (x1 - x0).abs();
    let dy = (y1 - y0).abs();
    let sx = if x0 < x1 { 1 } else { -1 };
    let sy = if y0 < y1 { 1 } else { -1 };
    let mut err = dx - dy;
    let mut x = x0;
    let mut y = y0;
    loop {
        if (x, y) != (x0, y0) && (x, y) != (x1, y1) && world.is_wall(x, y) {
            return true;  // 中间有墙
        }
        if x == x1 && y == y1 { break; }
        let e2 = 2 * err;
        if e2 > -dy { err -= dy; x += sx; }
        if e2 < dx { err += dx; y += sy; }
    }
    false
}

fn compute_visibility(world: &World2D) -> Vec<Vec<bool>> {
    let n = world.voxels.len();
    let mut matrix = vec![vec![false; n]; n];
    for a in 0..n {
        for b in 0..n {
            if a == b {
                matrix[a][b] = true;
            } else {
                let (ax, ay) = world.voxels[a];
                let (bx, by) = world.voxels[b];
                matrix[a][b] = !bresenham_blocked(world, ax, ay, bx, by);
            }
        }
    }
    matrix
}

fn main() {
    let mut world = World2D {
        dim: 16,
        cells: vec![false; 16 * 16],
        voxels: vec![(2, 2), (2, 8), (8, 2), (8, 8), (14, 2), (14, 8), (8, 14), (14, 14)],
    };
    // 在 (5, 0) - (5, 15) 放一面墙(分隔左右)
    for y in 0..16 {
        world.cells[y * 16 + 5] = true;
    }
    
    let vis = compute_visibility(&world);
    
    println!("Visibility matrix (8 voxels):");
    print!("    ");
    for j in 0..8 { print!("{} ", j); }
    println!();
    for (i, row) in vis.iter().enumerate() {
        print!("{}: ", i);
        for &v in row {
            print!("{} ", if v { "1" } else { "0" });
        }
        println!();
    }
    
    // 统计
    let n_visible: usize = vis.iter().map(|r| r.iter().filter(|&&v| v).count()).sum();
    println!("\nTotal visible pairs: {} / {} ({:.0}%)",
        n_visible, 8 * 8, n_visible as f32 / (8 * 8) as f32 * 100.0);
}
```

    let mut world = World2D {
        dim: 16,
        cells: vec![false; 16 * 16],
        voxels: vec![(2, 2), (2, 14), (8, 8), (14, 2), (14, 14)],

    println!("\n=== Performance ===");

        let _ = compute_visibility(&big_world);
        let elapsed = start.elapsed();
        println!("N={}: {:?} ({:.1} µs/pair)", n, elapsed, 
            elapsed.as_micros() as f64 / (n * n) as f64);
    }
}

## 10 · 补充材料:VoxelUtility 的设计哲学

### A.1 VoxelUtility 是什么

Day 610 引入 VoxelUtility——一组 voxel 操作的工具函数集合。本质是"通用 voxel query/update API"。

```rust
mod voxel_utility {
    /// 查 voxel 是否 solid
    pub fn is_solid(world: &World, x: i32, y: i32, z: i32) -> bool {
        world.get(x, y, z).map(|v| v.is_solid()).unwrap_or(false)
    }
    
    /// 查 voxel 的"邻居数"(用于 greedy meshing)
    pub fn count_solid_neighbors(world: &World, x: i32, y: i32, z: i32) -> u8 {
        let mut count = 0;
        for (dx, dy, dz) in NEIGHBORS_6 {
            if is_solid(world, x + dx, y + dy, z + dz) {
                count += 1;
            }
        }
        count
    }
    
    /// AABB vs voxel 碰撞
    pub fn aabb_vs_voxels(world: &World, aabb: AABB) -> Vec<(i32, i32, i32)> {
        let mut hits = vec![];
        let min = aabb.min.floor() as IVec3;
        let max = aabb.max.ceil() as IVec3;
        for z in min.z..max.z {
            for y in min.y..max.y {
                for x in min.x..max.x {
                    if is_solid(world, x, y, z) {
                        let voxel_aabb = AABB::new(x, y, z, 1, 1, 1);
                        if aabb.intersects(voxel_aabb) {
                            hits.push((x, y, z));
                        }
                    }
                }
            }
        }
        hits
    }
    
    /// Ray vs voxel
    pub fn ray_vs_voxels(world: &World, ray: &Ray, max_dist: f32) -> Option<Hit> {
        grid_dda(world, ray, max_dist)
    }
}
```

### A.2 Utility module 的设计原则

VoxelUtility 体现"helper module"的设计模式:

**原则 1:无状态**。所有函数纯 query,无内部状态。

**原则 2:小函数**。每函数做一件事,签名清晰。

**原则 3:可组合**。其他模块用 utility 组合复杂操作。

**原则 4:零开销抽象**。Rust 的 inline / generic 让 utility 没运行时成本。

### A.4 工业级 utility 的边界

什么时候加 utility?
- **3+ 处使用相同代码** → 抽出 utility
- **复杂逻辑(20+ 行)** → 抽出
- **跨模块共享** → utility
- **测试覆盖** → utility 容易单测

什么时候 NOT 加 utility?
- **只 1 处用** → 内联
- **强耦合特定场景** → 留在原地
- **utility 互相依赖太多** → 考虑 trait / struct

Casey 的 Day 610 是"够了就抽 utility"的实践。

### A.7 Casey 的 VoxelUtility 真实场景

Casey 在 Day 610 引入 VoxelUtility 的具体动机:之前 grid DDA / light propagation / collision 各有自己的 voxel 操作代码,重复且不一致。抽 VoxelUtility 后,所有 voxel 操作统一入口。

具体重构前:

```rust
// grid_dda.rs
fn grid_dda(world: &World, ...) {
    let cx = ...;
    let voxel = world.voxels[cx...];  // 直接访问
    if voxel.material != 0 { ... }
}

// collision.rs
fn collide(world: &World, ...) {
    let cx = ...;
    let voxel = &world.voxels[cx...];  // 又一次直接访问
    if voxel.is_solid() { ... }
}
```

两处都直接访问 world.voxels,但语义不同(grid_dda 检查 material,collision 检查 is_solid)。

重构后:

```rust
// voxel_utility.rs
pub fn is_solid(world: &World, x: i32, y: i32, z: i32) -> bool {
    world.get(x, y, z).map(|v| v.is_solid()).unwrap_or(false)
}

// grid_dda.rs
fn grid_dda(world: &World, ...) {
    let cx = ...;
    if voxel_utility::is_solid(world, cx, ...) { ... }  // 统一
}

// collision.rs
fn collide(world: &World, ...) {
    let cx = ...;
    if voxel_utility::is_solid(world, cx, ...) { ... }  // 统一
}
```

代码量减少 30%,语义一致,bug 减少。

### A.8 VoxelUtility 的边界 case

VoxelUtility 函数要处理各种边界 case:

**1. 越界访问**(coord 超出 world 范围):
```rust
pub fn is_solid(world: &World, x: i32, y: i32, z: i32) -> bool {
    if x < 0 || y < 0 || z < 0 { return false; }  // 负坐标 = 空
    let (x, y, z) = (x as u32, y as u32, z as u32);
    if x >= world.width || y >= world.height || z >= world.depth {
        return false;  // 超出 = 空(假设外部世界是空气)
    }
    let voxel = &world.voxels[(z * world.height * world.width + y * world.width + x) as usize];
    voxel.is_solid()
}
```

返回 false(空气)而不是 panic,让调用方不用每处都边界检查。

**2. 边界 voxel**(恰好在 world 边界):
```rust
// (0, 0, 0) 或 (width-1, height-1, depth-1) 是合法 voxel
let voxel = is_solid(world, 0, 0, 0);  // OK
```

**3. 负坐标**:
```rust
// (-1, 0, 0) 越界,返回 false(空气)
let voxel = is_solid(world, -1, 0, 0);  // false
```

工业实现假设"world 外部是空气",简化调用方逻辑。

### A.9 VoxelUtility 的性能

VoxelUtility 函数被频繁调用(每帧几百万次)。性能优化:

**1. Inlining**:
```rust
#[inline]
pub fn is_solid(world: &World, x: i32, y: i32, z: i32) -> bool {
    // ...
}
```

`#[inline]` 让编译器内联,消除函数调用开销。

**2. Bounds check elimination**:
```rust
pub fn is_solid_unchecked(world: &World, x: u32, y: u32, z: u32) -> bool {
    // 假设 coord 合法,无边界检查
    // unsafe { world.voxels.get_unchecked(...) }
    world.voxels[(z * world.height * world.width + y * world.width + x) as usize].is_solid()
}
```

调用方保证 coord 合法,utility 跳过边界检查。Rust 编译器能消除部分边界检查,但不能完全。

**3. Cache-friendly access**:
```rust
// 顺序访问(同一 row)cache 命中
for x in 0..width {
    is_solid(world, x, y, z);  // 顺序内存
}

// 跳跃访问(stride = width)cache miss
for z in 0..depth {
    is_solid(world, x, y, z);  // 每次跨 width × height 字节
}
```

Utility 不解决 cache 问题(取决于调用方),但好的 API 设计鼓励 cache-friendly 使用。
