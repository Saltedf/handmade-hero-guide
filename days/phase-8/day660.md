# Day 660 · 随机主世界布局

> Day 659 加了 immediate-mode 关卡生成。今天 Casey 用它生成 **overworld**(主世界)——一个大地图,玩家可以探索多个房间 / 区域。Roguelike 风格:每次新游戏,世界布局不同。

## 0 · 为什么要有这一天

回顾游戏类型:

- **线性关卡**(Super Mario Bros):玩家从起点到终点,固定顺序
- **开放世界**(Zelda BOTW):一个大地图,玩家自由探索
- **Roguelike**(Hades、Binding of Isaac):每次新游戏,世界布局随机

HH 现在要做 roguelike 元素:**overworld** 是一组房间,每次启动游戏重新生成。

为什么 roguelike 这么吸引人?

- **重玩性**:每次都不同,100 小时不腻
- **惊喜**:玩家不知道下一个房间有什么
- **平衡**:开发者不用调"关卡难度曲线",程序自然出难度

但 roguelike 难做:

- 房间要"连通"(不能孤立)
- 难度要"递进"(后面房间比前面难)
- 视觉要"多样"(不要每个房间一样)

今天 Casey 实现"房间布局生成":随机放房间,确保连通。

心理锚点:看完今天,你能:

- 实现房间布局生成器
- 处理"房间不重叠"约束
- 确保"全连通"(所有房间可达)

## 1 · Casey 今天做了什么

1. 设计 OverworldGen 算法:随机放房间 + 走廊连接
2. 防房间重叠:`intersects(existing_rooms)` 检查
3. 用"主房间 + 副房间"结构:主房间用走廊串联,副房间随机分布
4. 加 spawn 点:玩家在第一个房间,敌人在最后一个房间
5. 加"种子"可复现,不同 seed 不同布局
6. 写测试:跑 100 个 seed,所有都生成全连通图

## 2 · 心智模型

### 类比:酒店平面图

设计酒店平面图:

- 客房不能重叠(不能两个房间占同一空间)
- 所有客房要连通(走廊连接)
- 入口大堂在中央
- 各种房型随机分布

游戏房间布局同构。算法核心:**随机放,检查不重叠,确保连通**。

### 算法:Random Room Placement

经典算法步骤:

1. 随机生成房间 rect(x, z, w, h)
2. 检查是否与已有房间重叠——重叠则丢弃
3. 不重叠则接受,加入房间列表
4. 重复直到 N 个房间
5. 用走廊连接相邻房间(按距离排序)

### 房间重叠检测

两个矩形重叠的判定:

```
rect1: (x1, z1, w1, h1) — 左下角 (x1, z1),右上角 (x1+w1, z1+h1)
rect2: (x2, z2, w2, h2)

重叠 ⟺ NOT (x1+w1 < x2 OR x2+w2 < x1 OR z1+h1 < z2 OR z2+h2 < z1)
```

代码:

```rust
fn intersects(a: Rect, b: Rect) -> bool {
    !(a.x + a.w < b.x || b.x + b.w < a.x || a.z + a.h < b.z || b.z + b.h < a.z)
}
```

可以加"padding":让房间之间至少间隔 1 格。Padding = 1:把每个房间扩展 1 格再判重叠。

### 连通性保证

放完所有房间,要保证都连通。两种思路:

**思路 1**:每个新房间和"最近的已有房间"用走廊连接。这保证连通(每个新房间都连到老网络)。

**思路 2**:全部放完后,跑最小生成树(MST),用走廊连接 MST 边。

Casey 选思路 1——简单,实时连通。

```rust
fn place_room(rooms: &mut Vec<Rect>, new_room: Rect) {
    // 检查重叠
    for r in rooms.iter() {
        if intersects_padded(*r, new_room, 1) {
            return; // 重叠,放弃
        }
    }
    // 找最近房间
    if let Some(nearest) = find_nearest(rooms, &new_room) {
        connect(nearest, &new_room); // 加走廊
    }
    rooms.push(new_room);
}
```

### 走廊生成

两个房间用 L 形或 Z 形走廊连接:

```rust
fn corridor_between(world: &mut World, room1: Rect, room2: Rect) {
    let c1 = room1.center();
    let c2 = room2.center();
    // 先水平后垂直
    for x in c1.0.min(c2.0)..=c1.0.max(c2.0) {
        world.set(x, c1.1, Voxel::Floor);
    }
    for z in c1.1.min(c2.1)..=c1.1.max(c2.1) {
        world.set(c2.0, z, Voxel::Floor);
    }
}
```

Z 形走廊比直线走廊更"自然"(避免规则感)。

### 房间类型多样化

不同房间类型:

- **start**:玩家出生
- **treasure**:有宝箱
- **combat**:有敌人
- **boss**:Boss 房(最大)
- **shop**:有商人

类型分配:随机 shuffle 房间,前 1 个是 start,最后 1 个是 boss,中间随机分配。

### 视觉多样性

每个房间有自己的"主题":

- 主题 = (颜色, 材质, 装饰物)
- 主题按房间 index 选,避免连续相同主题

```rust
const THEMES: &[Theme] = &[stone, wood, brick, marble];

fn theme_for(room_idx: usize) -> &'static Theme {
    &THEMES[room_idx % THEMES.len()]
}
```

### 3.1 · 游戏编程视角

### 3.2 · 图形学视角

图形里"布局生成":

- **treemap layout**:矩形递归切分,UI 布局
- **Voronoi diagram**:点集生成 cell
- **BSP tree**:递归二分空间

每种适合不同场景。HH 的"房间 + 走廊"是 treemap 的特例。

### 3.3 · Linux 系统编程视角

Linux 里"布局":

- **window manager**:tile 算法,i3 / sway 把屏幕切分给窗口
- **filesystem**:block allocation,B+ 树布局
- **memory allocator**:free list / buddy system,堆布局

每个都是"空间分配 + 防冲突"。

### 3.4 · Rust 生态视角

Rust 里房间生成的优雅写法:

```rust
#[derive(Clone, Copy, Debug)]
struct Rect { x: i32, z: i32, w: i32, h: i32 }

impl Rect {
    fn center(&self) -> (i32, i32) { (self.x + self.w / 2, self.z + self.h / 2) }
    fn padded(&self, p: i32) -> Rect {
        Rect { x: self.x - p, z: self.z - p, w: self.w + 2 * p, h: self.h + 2 * p }
    }
    fn intersects(&self, other: Rect) -> bool {
        !(self.x + self.w < other.x || other.x + other.w < self.x
          || self.z + self.h < other.z || other.z + other.h < self.z)
    }
}
```

`padded(p)` 用 transform 模式——返回新 Rect,不改原对象。函数式风格。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么"先放房间,后连接走廊"比"边放边连"更稳定?

**参考解答**:边放边连,每个新房间都连最近的已有房间。但最近的不一定是"最适合"——可能两个房间靠太近,走廊过短,看起来怪。先放完房间,可以跑 MST 算法选最优连接,布局更合理。但 Casey 选边放边连是因为简单,够用。

### Lv2 · 动手实践

**题**:实现 §2 的房间放置 + 走廊连接,生成 5 个房间的随机布局。

**参考解答**:

```rust
use rand::{Rng, SeedableRng};
use rand_xoshiro::Xoshiro256PlusPlus;

#[derive(Clone, Copy, Debug)]
struct Rect { x: i32, z: i32, w: i32, h: i32 }

impl Rect {
    fn center(&self) -> (i32, i32) { (self.x + self.w / 2, self.z + self.h / 2) }
    fn padded(&self, p: i32) -> Rect {
        Rect { x: self.x - p, z: self.z - p, w: self.w + 2 * p, h: self.h + 2 * p }
    }
    fn intersects(&self, other: Rect) -> bool {
        !(self.x + self.w < other.x || other.x + other.w < self.x
          || self.z + self.h < other.z || other.z + other.h < self.z)
    }
}

#[derive(Clone, Copy, PartialEq)]
enum Voxel { Empty, Wall, Floor }

struct World {
    w: usize, h: usize,
    voxels: Vec<Voxel>,
}

impl World {
    fn new(w: usize, h: usize) -> Self {
        Self { w, h, voxels: vec![Voxel::Empty; w * h] }
    }
    fn set(&mut self, x: i32, z: i32, v: Voxel) {
        if x < 0 || z < 0 { return; }
        let (xu, zu) = (x as usize, z as usize);
        if xu >= self.w || zu >= self.h { return; }
        self.voxels[zu * self.w + xu] = v;
    }
    fn render(&self) {
        for z in 0..self.h {
            let mut line = String::new();
            for x in 0..self.w {
                line.push(match self.voxels[z * self.w + x] {
                    Voxel::Empty => ' ',
                    Voxel::Wall => '#',
                    Voxel::Floor => '.',
                });
            }
            println!("{}", line);
        }
    }
}

fn carve_room(world: &mut World, r: Rect) {
    for dx in 0..r.w {
        for dz in 0..r.h {
            let is_edge = dx == 0 || dx == r.w - 1 || dz == 0 || dz == r.h - 1;
            world.set(r.x + dx, r.z + dz, if is_edge { Voxel::Wall } else { Voxel::Floor });
        }
    }
}

fn carve_corridor(world: &mut World, (x1, z1): (i32, i32), (x2, z2): (i32, i32)) {
    for x in x1.min(x2)..=x1.max(x2) {
        world.set(x, z1, Voxel::Floor);
    }
    for z in z1.min(z2)..=z1.max(z2) {
        world.set(x2, z, Voxel::Floor);
    }
}

fn main() {
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let mut world = World::new(60, 30);
    let mut rooms: Vec<Rect> = Vec::new();

    for _ in 0..30 {  // 尝试 30 次,放 5 个房间
        if rooms.len() >= 5 { break; }
        let w = rng.gen_range(5..=10);
        let h = rng.gen_range(5..=8);
        let x = rng.gen_range(1..(world.w as i32 - w - 1));
        let z = rng.gen_range(1..(world.h as i32 - h - 1));
        let new_room = Rect { x, z, w, h };
        let padded = new_room.padded(1);
        if rooms.iter().any(|r| r.intersects(padded)) { continue; }
        // 找最近房间连接
        if let Some(nearest) = rooms.iter().min_by_key(|r| {
            let dx = r.center().0 - new_room.center().0;
            let dz = r.center().1 - new_room.center().1;
            dx * dx + dz * dz
        }) {
            carve_corridor(&mut world, nearest.center(), new_room.center());
        }
        carve_room(&mut world, new_room);
        rooms.push(new_room);
    }
    println!("Placed {} rooms", rooms.len());
    world.render();
}
```

## 8 · Rust / Arch 落地代码

完整 overworld 生成器:

```rust
// Cargo.toml:
// [dependencies]
// rand = "0.8"
// rand_xoshiro = "0.6"

use rand::{Rng, SeedableRng};
use rand_xoshiro::Xoshiro256PlusPlus;

#[derive(Clone, Copy, Debug)]
struct Rect { x: i32, z: i32, w: i32, h: i32 }

impl Rect {
    fn center(&self) -> (i32, i32) { (self.x + self.w / 2, self.z + self.h / 2) }
    fn padded(&self, p: i32) -> Self {
        Self { x: self.x - p, z: self.z - p, w: self.w + 2 * p, h: self.h + 2 * p }
    }
    fn intersects(&self, other: Self) -> bool {
        !(self.x + self.w < other.x || other.x + other.w < self.x
          || self.z + self.h < other.z || other.z + other.h < self.z)
    }
}

#[derive(Clone, Copy, PartialEq, Debug)]
enum Voxel { Empty, Wall, Floor, Door }

#[derive(Clone, Copy, PartialEq, Debug)]
enum RoomType { Start, Combat, Treasure, Boss, Shop }

struct Room {
    rect: Rect,
    room_type: RoomType,
}

struct World {
    w: usize, h: usize,
    voxels: Vec<Voxel>,
}

impl World {
    fn new(w: usize, h: usize) -> Self {
        Self { w, h, voxels: vec![Voxel::Empty; w * h] }
    }
    fn set(&mut self, x: i32, z: i32, v: Voxel) {
        if x < 0 || z < 0 { return; }
        let (xu, zu) = (x as usize, z as usize);
        if xu >= self.w || zu >= self.h { return; }
        self.voxels[zu * self.w + xu] = v;
    }
    fn get(&self, x: i32, z: i32) -> Voxel {
        if x < 0 || z < 0 { return Voxel::Empty; }
        let (xu, zu) = (x as usize, z as usize);
        if xu >= self.w || zu >= self.h { return Voxel::Empty; }
        self.voxels[zu * self.w + xu]
    }
    fn render(&self) {
        for z in 0..self.h {
            let mut line = String::new();
            for x in 0..self.w {
                line.push(match self.voxels[z * self.w + x] {
                    Voxel::Empty => ' ',
                    Voxel::Wall => '#',
                    Voxel::Floor => '.',
                    Voxel::Door => '+',
                });
            }
            println!("{}", line);
        }
    }
}

fn carve_room(world: &mut World, r: Rect) {
    for dx in 0..r.w {
        for dz in 0..r.h {
            let edge = dx == 0 || dx == r.w - 1 || dz == 0 || dz == r.h - 1;
            world.set(r.x + dx, r.z + dz, if edge { Voxel::Wall } else { Voxel::Floor });
        }
    }
}

fn carve_corridor(world: &mut World, a: (i32, i32), b: (i32, i32)) {
    for x in a.0.min(b.0)..=a.0.max(b.0) {
        if world.get(x, a.1) == Voxel::Wall {
            world.set(x, a.1, Voxel::Door);
        } else {
            world.set(x, a.1, Voxel::Floor);
        }
    }
    for z in a.1.min(b.1)..=a.1.max(b.1) {
        if world.get(b.0, z) == Voxel::Wall {
            world.set(b.0, z, Voxel::Door);
        } else {
            world.set(b.0, z, Voxel::Floor);
        }
    }
}

fn generate_overworld(seed: u64) -> (World, Vec<Room>) {
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(seed);
    let mut world = World::new(60, 30);
    let mut rooms: Vec<Room> = Vec::new();
    let target = 8;

    let mut attempts = 0;
    while rooms.len() < target && attempts < 200 {
        attempts += 1;
        let w = rng.gen_range(5..=10);
        let h = rng.gen_range(5..=8);
        let x = rng.gen_range(1..(world.w as i32 - w - 1));
        let z = rng.gen_range(1..(world.h as i32 - h - 1));
        let rect = Rect { x, z, w, h };
        let padded = rect.padded(1);
        if rooms.iter().any(|r| r.rect.intersects(padded)) { continue; }
        if let Some(nearest) = rooms.iter().min_by_key(|r| {
            let c1 = r.rect.center();
            let c2 = rect.center();
            let dx = c1.0 - c2.0;
            let dz = c1.1 - c2.1;
            dx * dx + dz * dz
        }) {
            carve_corridor(&mut world, nearest.rect.center(), rect.center());
        }
        carve_room(&mut world, rect);
        rooms.push(Room { rect, room_type: RoomType::Combat });
    }

    // 分配类型:第一个 Start, 最后一个 Boss, 中间随机
    if !rooms.is_empty() {
        rooms[0].room_type = RoomType::Start;
        if rooms.len() > 1 {
            rooms[rooms.len() - 1].room_type = RoomType::Boss;
        }
        for r in rooms.iter_mut().skip(1).take(rooms.len().saturating_sub(2)) {
            r.room_type = match rng.gen_range(0..3) {
                0 => RoomType::Combat,
                1 => RoomType::Treasure,
                _ => RoomType::Shop,
            };
        }
    }

    (world, rooms)
}

fn main() {
    println!("=== Overworld with seed=42 ===");
    let (world, rooms) = generate_overworld(42);
    world.render();
    println!("\nRooms:");
    for (i, r) in rooms.iter().enumerate() {
        println!("  {}: {:?} at {:?}", i, r.room_type, r.rect);
    }

    println!("\n=== Same seed, should match ===");
    let (world2, _) = generate_overworld(42);
    world2.render();
}
```

## 10 · 工程反思

Day 660 传达的核心工程教训:**procedural generation 是"无限内容"的钥匙**。

新手以为"游戏内容 = 美术手做",资深工程师知道很多内容是**算法生成**——Minecraft 的地形、Spelunky 的关卡、No Man's Sky 的星球、Civilization 的地图。每个都是 PCG(Procedural Content Generation)。

PCG 的核心是"用算法代替人工"。优势:

- **无限内容**:玩家每次玩不同地图
- **小包体**:不存预做资产,运行时生成
- **可扩展**:调参改全局,不需重做

劣势:

- **质量不稳定**:有时生成"烂"地图
- **难调试**:bug 复现需要相同种子
- **失去艺术家手感**:PCG 看起来"机械"

资深 PCG 工程师平衡两者——PCG + 人工修饰,生成基础内容,艺术家微调。

**PCG 算法分类**:

- **Noise-based**:Perlin / Simplex / Worley noise。生成自然地形
- **L-system**:形式语法。生成植物 / 街道
- **Cellular automata**:Conway's Game of Life 类。生成洞穴
- **Agent-based**:模拟"挖矿者"行为。生成 dungeon
- **Grammar-based**:Wave Function Collapse。生成结构化内容
- **ML-based**:训练模型生成

每种有自己的 niche。Casey 在 HH 用 noise + agent-based,够用。

**第二条教训**:**seed 控制 = reproducibility**。

PCG 用 PRNG,种子决定输出。同种子同输出,这是 reproducibility 的基础:

- 玩家分享种子,别人玩同世界(Minecraft)
- bug 复现用同种子

## N0 • 深度教学补充

### 核心概念重新梳理

Day 660 涉及的核心概念需要在多个层次上理解:

**第一层:直观理解**

新手第一次接触概念,需要建立直觉。例如 voxel collision 是"虚拟物体不能穿过虚拟墙"——这个直觉每个人都能从现实经验获得。

**第二层:数学理解**

把直觉形式化。collision = "两个几何体的体积有交集"。对于 AABB,这等价于"三轴投影都重叠"。

**第三层:工程理解**

数学正确不等于工程实现正确。要考虑:

- 浮点精度边界
- 性能(每帧 N 个查询)
- 内存(数据结构紧凑)
- 边角 case(无穷大、NaN、负数)

**第四层:工业理解**

工业级要再加:

- 多线程安全
- SIMD 优化
- 网络同步(多人游戏)
- 跨平台(Windows/Mac/Linux/Mobile)
- 可访问性(色盲友好)
- 反作弊

每层理解都让代码更鲁棒。资深工程师在所有层次同时思考。

### 实际工程的细节

工业代码 80% 是"边角 case 处理",20% 是"核心算法"。Casey 在 HH 演示核心,工业代码加大量边角处理。

**边角 case 类型**:

1. 空输入(空 Vec、null pointer)
2. 极端输入(NaN、无穷大、超大数)
3. 并发竞争(多线程同时访问)
4. 资源不足(内存满、磁盘满)
5. 网络异常(超时、断连、包丢失)
6. 版本不兼容(老配置 / 新代码)
7. 权限错误(只读文件、无网络)
8. 用户误操作(连点、撤销重做)

每个 case 都要单独处理。这是工业代码 50%+ 行数的原因。

### 优化思路

性能优化有顺序:

1. **算法**:O(N²) → O(N log N),最大提升
2. **数据结构**:Vec → HashMap / BTreeMap,常数提升
3. **Cache**:AoS → SoA,cache 命中提升
4. **SIMD**:4-16 元素并行,巨大常数提升
5. **GPU**:数千核并行,极致性能
6. **分布式**:多机器,无限扩展

每级提升都需要更复杂的代码。先优化低级,够用再升级。

- **完成 > 完美**:能跑 > 能优化

Day 660 用 C 写,但 Rust 版本会更安全 / 更高效:

每条都让代码更鲁棒。Rust 是游戏开发的新趋势(bevy / wgpu / rend3),学习 Rust 让你未来 10 年受益。
