# Day 596 · 充实 K-d 树遍历

> Day 595 草拟了 k-d tree 的遍历循环,但只是骨架。今天 Casey 把遍历"充实"——处理边界情况、优化内循环、加 early-out(提前终止)。

## 0 · 为什么要有这一天

Day 595 的迭代遍历循环能跑,但有未处理的细节:

1. **Early-out**:如果已经找到比当前节点 t_max 更近的命中,没必要继续遍历

## 2 · 心智模型

### 类比:送外卖的最短路径

外卖员要送 10 单。Day 595 版本是"按订单顺序送",不管地点远近。Day 596 版本是"按距离排序送"——送完一单后,优先去最近的下一单,而且如果发现"绕远路了"立即回头。

**Early-out** = "如果发现已经走远了,回头"。比如已经送了 5 单,发现第 6 单的地址在反方向 10 公里外,放弃第 6 单(已经被前面送的覆盖),继续下一单。

### 严谨原理:Early-out

维护 `t_best`:已经找到的最近命中的 t 值。初始 `t_best = infinity`。

遍历时,push 到 stack 之前检查:

```rust
if t_min >= t_best {
    continue;  // 这个节点不可能有更近的命中,跳过
}
```

每找到一个命中,更新 t_best:

```rust
if let Some(hit) = test_triangle(...) {
    if hit.t < t_best {
        t_best = hit.t;
        best_hit = Some(hit);
    }
}
```

**收益**:对光线穿过深 k-d tree,early-out 可以省 30-50% 的节点访问。

### Stack 预分配

```rust
// Day 595: Vec,每次 push 可能 realloc
let mut stack = vec![(0, 0.0, f32::INFINITY)];

// Day 596: 预分配容量
let mut stack = Vec::with_capacity(64);
stack.push((0, 0.0, f32::INFINITY));
```

k-d tree 深度通常 < 30(2^30 = 10 亿节点),预分配 64 足够。避免运行时 realloc。

### Möller-Trumbore ray-triangle 相交

经典算法,10 次乘加,6 个变量。

```rust
fn ray_triangle(ray: &Ray, v0: Vec3, v1: Vec3, v2: Vec3) -> Option<f32> {
    let edge1 = v1 - v0;
    let edge2 = v2 - v0;
    let h = ray.dir.cross(edge2);
    let a = edge1.dot(h);
    
    if a.abs() < 1e-10 {
        return None;  // 光平行于三角形
    }
    
    let f = 1.0 / a;
    let s = ray.origin - v0;
    let u = f * s.dot(h);
    
    if u < 0.0 || u > 1.0 {
        return None;
    }
    
    let q = s.cross(edge1);
    let v = f * ray.dir.dot(q);
    
    if v < 0.0 || u + v > 1.0 {
        return None;
    }
    
    let t = f * edge2.dot(q);
    if t > 1e-10 {
        Some(t)
    } else {
        None
    }
}
```

**每行解释**:
- `edge1 = v1 - v0`, `edge2 = v2 - v0` — 三角形两条边。
- `h = ray.dir × edge2` — 光方向与 edge2 的叉积。
- `a = edge1 · h` — 行列式(判断光是否平行)。
- `s = ray.origin - v0` — 三角形顶点到光原点。
- `u = f * s · h` — 重心坐标 u。
- `q = s × edge1` — s 与 edge1 的叉积。
- `v = f * ray.dir · q` — 重心坐标 v。
- `t = f * edge2 · q` — 光线参数。

**u, v 是重心坐标**:三角形内点 = `(1-u-v) * v0 + u * v1 + v * v2`。u >= 0, v >= 0, u+v <= 1 表示在三角形内。

### 完整遍历

```rust
fn raycast(tree: &KdTree, ray: &Ray) -> Option<Hit> {
    let mut stack: Vec<(u32, f32, f32)> = Vec::with_capacity(64);
    stack.push((0, 0.0, f32::INFINITY));
    
    let mut best_hit: Option<Hit> = None;
    let mut t_best = f32::INFINITY;
    
    while let Some((node_idx, t_min, t_max)) = stack.pop() {
        // Early-out
        if t_min >= t_best {
            continue;
        }
        
        let node = &tree.nodes[node_idx as usize];
        
        if node.axis == 3 {  // leaf
            for &tri_idx in &node.triangles {
                let tri = &tree.triangles[tri_idx];
                if let Some(t) = ray_triangle(ray, tri.v0, tri.v1, tri.v2) {
                    if t < t_best {
                        t_best = t;
                        best_hit = Some(Hit { t, triangle: tri_idx });
                    }
                }
            }
        } else {
            // internal
            let axis = node.axis as usize;
            let split = node.split;
            
            let dir_axis = ray.dir[axis];
            let origin_axis = ray.origin[axis];
            
            let t_split = if dir_axis.abs() > 1e-10 {
                (split - origin_axis) / dir_axis
            } else if origin_axis < split {
                f32::NEG_INFINITY
            } else {
                f32::INFINITY
            };
            
            let (near, far) = if origin_axis < split {
                (node.left, node.right)
            } else {
                (node.right, node.left)
            };
            
            // 决定压哪些
            if t_split < 0.0 || t_split >= t_max {
                // 只在 near
                if near != u32::MAX {
                    stack.push((near, t_min, t_max));
                }
            } else if t_split <= t_min {
                // 只在 far
                if far != u32::MAX {
                    stack.push((far, t_min, t_max));
                }
            } else {
                // 两边都要访问,先压 far(后处理),再压 near(先处理)
                if far != u32::MAX {
                    stack.push((far, t_split, t_max));
                }
                if near != u32::MAX {
                    stack.push((near, t_min, t_split));
                }
            }
        }
    }
    
    best_hit
}
```

**关键改进**:
- `if t_min >= t_best { continue; }` — early-out。
- `if near != u32::MAX` — 跳过空子节点。
- `Vec::with_capacity(64)` — 预分配 stack。
- `dir_axis.abs() > 1e-10` — 处理平行光。

### 性能基准

```rust
fn benchmark_raycast(tree: &KdTree, rays: &[Ray]) -> f32 {
    let start = std::time::Instant::now();
    let mut hits = 0;
    for ray in rays {
        if tree.raycast(ray).is_some() {
            hits += 1;

             rays.len(), elapsed, per_ray_ns, hits);

}
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里 k-d tree / BVH 遍历有标准优化:

**Packet tracing**:同时追踪 4-8 条光线(SIMD),共享 stack 和 t_best。8 条光线共享一次节点遍历,效率高。

**Ray coherence**:相邻像素的光线方向接近,访问相同的 k-d tree 节点。利用这个共享访问。

**Frustum culling**:在 k-d tree 节点级做 frustum 测试,跳过相机看不到的节点。

**Multilevel k-d tree**:大场景分多层,顶层粗粒度,叶子细粒度。Lumen / RTX 用类似结构。

### 3.2 · 🎨 图形学视角

**Möller-Trumbore 算法**(1997):光-三角形相交的标准算法。简单、稳定、SIMD 友好。

**替代算法**:
- **Waterson-Watt**:更早,稍微复杂
- **Barycentric precompute**:预算三角形信息,运行时更快(但需要预存)
- **Branchless**:用条件传送替代 if-else,SIMD 友好

Möller-Trumbore 的优势:简单、内存少(三角形只需 3 个顶点)、足够快。

**SIMD 优化**:Möller-Trumbore 可以一次测 4 个三角形(SSE),或 8 个(AVX)。GPU shader 一次测 32 个(warp)。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上分析 k-d tree 遍历性能:

### 3.4 · 🦀 Rust 生态视角

Rust 实现 Möller-Trumbore 的细节:

**Vec3 运算符重载**:

```rust
impl std::ops::Sub for Vec3 {
    type Output = Vec3;
    fn sub(self, other: Vec3) -> Vec3 {
        Vec3::new(self.x - other.x, self.y - other.y, self.z - other.z)
    }
}

impl Vec3 {
    fn dot(self, other: Vec3) -> f32 {
        self.x * other.x + self.y * other.y + self.z * other.z
    }
    fn cross(self, other: Vec3) -> Vec3 {
        Vec3::new(
            self.y * other.z - self.z * other.y,
            self.z * other.x - self.x * other.z,
            self.x * other.y - self.y * other.x,
        )
    }
}
```

让 `v1 - v0` / `a.dot(b)` / `a.cross(b)` 语法工作。

**避免分配**:Vec::with_capacity + 一直复用(不重新创建):

```rust
// 每帧 raycast 时,复用 stack
struct Raycaster {
    stack: Vec<(u32, f32, f32)>,
}

impl Raycaster {
    fn raycast(&mut self, tree: &KdTree, ray: &Ray) -> Option<Hit> {
        self.stack.clear();
        self.stack.push((0, 0.0, f32::INFINITY));
        // ... 不需要重新 with_capacity
    }
}
```

**关键 Rust 特性**:
- `&mut self.stack` — 复用同 Vec,避免每帧 alloc。
- `Option<Hit>` — 显式表达"可能没命中"。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Early-out 在什么情况下不起作用?给一个具体例子。

**参考解答**:Early-out 依赖"已经找到的最近命中"。如果光线**没有命中任何物体**(射向天空),`t_best` 始终是 infinity,early-out 永远不触发,所有节点都访问。

具体例子:玩家仰望天空,发射的光线穿过整个 k-d tree,但没撞到任何三角形。这种情况下 early-out 无效,需要遍历所有节点(直到 t_max 截断)。

优化:对天空光,可以用环境贴图直接采样,不走 k-d tree。

```rust
#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }

impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
    fn cross(self, o: Self) -> Self {
        Self::new(
            self.y*o.z - self.z*o.y,
            self.z*o.x - self.x*o.z,
            self.x*o.y - self.y*o.x,
        )
    }
}

impl std::ops::Sub for Vec3 {
    type Output = Self;
    fn sub(self, o: Self) -> Self {
        Self::new(self.x - o.x, self.y - o.y, self.z - o.z)
    }
}

struct Ray { origin: Vec3, dir: Vec3 }

fn ray_triangle(ray: &Ray, v0: Vec3, v1: Vec3, v2: Vec3) -> Option<f32> {
    let edge1 = v1 - v0;
    let edge2 = v2 - v0;
    let h = ray.dir.cross(edge2);
    let a = edge1.dot(h);
    if a.abs() < 1e-10 { return None; }
    let f = 1.0 / a;
    let s = ray.origin - v0;
    let u = f * s.dot(h);
    if u < 0.0 || u > 1.0 { return None; }
    let q = s.cross(edge1);
    let v = f * ray.dir.dot(q);
    if v < 0.0 || u + v > 1.0 { return None; }
    let t = f * edge2.dot(q);
    if t > 1e-10 { Some(t) } else { None }
}

fn main() {
    let ray = Ray {
        origin: Vec3::new(0.0, 0.0, -1.0),
        dir: Vec3::new(0.0, 0.0, 1.0),
    };
    let v0 = Vec3::new(1.0, 0.0, 0.0);
    let v1 = Vec3::new(-1.0, 0.0, 0.0);
    let v2 = Vec3::new(0.0, 1.0, 0.0);
    
    if let Some(t) = ray_triangle(&ray, v0, v1, v2) {
        println!("Hit at t = {}", t);
    } else {
        println!("No hit");
    }
}
```

## 8 · Rust / Arch 落地代码

完整可跑示例:

```rust
// (Vec3, Ray, ray_triangle 同 Lv2)

#[derive(Clone)]
struct Triangle { v0: Vec3, v1: Vec3, v2: Vec3 }

fn main() {
    // 100 个随机三角形
    let triangles: Vec<Triangle> = (0..100).map(|i| {
        let t = i as f32 * 0.1;
        Triangle {
            v0: Vec3::new(t.sin(), 0.0, t),
            v1: Vec3::new(t.sin() + 1.0, 0.0, t),
            v2: Vec3::new(t.sin(), 1.0, t),
        }
    }).collect();
    
    // 测试 1000 条光线
    let rays: Vec<Ray> = (0..1000).map(|i| {
        let t = i as f32 * 0.01;
        Ray {
            origin: Vec3::new(t.sin(), 0.5, -5.0),
            dir: Vec3::new(0.0, 0.0, 1.0),
        }
    }).collect();
    
    // 朴素遍历(无 k-d tree,测所有三角形)
    let start = std::time::Instant::now();
    let mut hits = 0;
    for ray in &rays {
        let mut best_t = f32::INFINITY;
        for tri in &triangles {
            if let Some(t) = ray_triangle(ray, tri.v0, tri.v1, tri.v2) {
                if t < best_t {
                    best_t = t;
                    hits += 1;
                }
            }
        }
    }
    let elapsed = start.elapsed();
    println!("Naive: {} rays × {} tris, {} hits in {:?} ({:.1} ns/ray)",
             rays.len(), triangles.len(), hits, elapsed,
             elapsed.as_nanos() as f64 / rays.len() as f64);
}
```

### A.3 性能优化的实际流程

工业性能优化的标准流程:

**Step 1:测量**(cargo flamegraph / perf)
- 找最慢的函数
- 不要猜,要测

**Step 2:分析**(为什么慢)
- 算法?(O(N²) vs O(N log N))
- 内存?(cache miss)
- 同步?(锁等待)
- 分支?(branch mispredict)

**Step 3:优化**(对症下药)
- 算法:换数据结构
- 内存:SoA / prefetch
- 同步:细化锁
- 分支:branchless

**Step 4:验证**(再测)
- 看新 profile
- 性能提升 vs 代码复杂度
- 不值得就回滚

**Step 5:文档**(给后人)
- commit message 解释为什么
- 注释 hot path 的考量

### A.5 Voxel lighting 的未来

学术 / 工业前沿:

**1. Real-time path tracing on RTX**:
- RTX 核心加速 voxel raycast
- 真实光传播(无简化)
- Minecraft RTX、Teardown 已经实现

**2. Neural voxel lighting**:
- 神经网络压缩 SH 数据
- 推理时光照实时算
- 研究(NeRF、Neural radiance cache)

**3. Differentiable rendering**:
- 光照对几何的偏导
- 反向传播到材质 / 几何
- 应用:材质反推、自动优化

**4. Wavelet voxel**:
- Wavelet 变换替代 SH
- 多分辨率,更适合稀疏数据
- 研究(Wavelet GVT)

这些是未来 5-10 年的方向。

### A.11 完整 Rust voxel lighting 实现

让我提供一个完整的 Rust voxel lighting 实现示例,综合前面所有概念:

```rust
use std::collections::HashMap;

const CHUNK_SIZE: u32 = 32;

struct Voxel {
    material: u8,
    color: [u8; 3],
}

struct Chunk {
    voxels: Vec<Voxel>,
    light: Vec<[u8; 4]>,  // RGBE
}

struct World {
    chunks: HashMap<(i32, i32, i32), Chunk>,
    sun_dir: Vec3,
    sun_color: [f32; 3],
}

impl World {
    fn get_voxel(&self, x: i32, y: i32, z: i32) -> Option<&Voxel> {
        let (cx, cy, cz) = (x.div_euclid(CHUNK_SIZE as i32), 
                            y.div_euclid(CHUNK_SIZE as i32),
                            z.div_euclid(CHUNK_SIZE as i32));
        let chunk = self.chunks.get(&(cx, cy, cz))?;
        let (lx, ly, lz) = (x.rem_euclid(CHUNK_SIZE as i32) as usize,
                            y.rem_euclid(CHUNK_SIZE as i32) as usize,
                            z.rem_euclid(CHUNK_SIZE as i32) as usize);
        let idx = lz * (CHUNK_SIZE as usize).pow(2) + ly * CHUNK_SIZE as usize + lx;
        Some(&chunk.voxels[idx])
    }
    
    fn is_solid(&self, x: i32, y: i32, z: i32) -> bool {
        self.get_voxel(x, y, z).map(|v| v.material != 0).unwrap_or(false)
    }
}

fn grid_dda(world: &World, start: Vec3, dir: Vec3, max_dist: f32) -> bool {
    let mut cx = start.x.floor() as i32;
    let mut cy = start.y.floor() as i32;
    let mut cz = start.z.floor() as i32;
    
    let step_x = if dir.x > 0.0 { 1 } else { -1 };
    let step_y = if dir.y > 0.0 { 1 } else { -1 };
    let step_z = if dir.z > 0.0 { 1 } else { -1 };
    
    let t_delta_x = if dir.x.abs() > 1e-10 { 1.0 / dir.x.abs() } else { f32::INFINITY };
    let t_delta_y = if dir.y.abs() > 1e-10 { 1.0 / dir.y.abs() } else { f32::INFINITY };
    let t_delta_z = if dir.z.abs() > 1e-10 { 1.0 / dir.z.abs() } else { f32::INFINITY };
    
    let mut t_max_x = if dir.x.abs() > 1e-10 {
        (((cx + if dir.x > 0 { 1 } else { 0 }) as f32) - start.x) / dir.x
    } else { f32::INFINITY };
    let mut t_max_y = /* similar */;
    let mut t_max_z = /* similar */;
    
    let mut t = 0.0;
    while t < max_dist {
        if world.is_solid(cx, cy, cz) {
            return true;  // occluded
        }
        
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            t = t_max_x;
            t_max_x += t_delta_x;
        } else if t_max_y < t_max_z {
            cy += step_y;
            t = t_max_y;
            t_max_y += t_delta_y;
        } else {
            cz += step_z;
            t = t_max_z;
            t_max_z += t_delta_z;
        }
    }
    false
}

fn compute_direct_lighting(world: &World, x: i32, y: i32, z: i32) -> [f32; 3] {
    let voxel_pos = Vec3::new(x as f32 + 0.5, y as f32 + 0.5, z as f32 + 0.5);
    
    // 是否被遮挡
    if grid_dda(world, voxel_pos, world.sun_dir, 100.0) {
        return [0.0; 3];  // 阴影
    }
    
    // Lambert 光照
    let normal = compute_normal(world, x, y, z);
    let lambert = normal.dot(world.sun_dir).max(0.0);
    
    [
        world.sun_color[0] * lambert,
        world.sun_color[1] * lambert,
        world.sun_color[2] * lambert,
    ]
}

fn compute_normal(world: &World, x: i32, y: i32, z: i32) -> Vec3 {
    let dx = if world.is_solid(x-1, y, z) { 1.0 } else { 0.0 } 
           - if world.is_solid(x+1, y, z) { 1.0 } else { 0.0 };
    let dy = if world.is_solid(x, y-1, z) { 1.0 } else { 0.0 }
           - if world.is_solid(x, y+1, z) { 1.0 } else { 0.0 };
    let dz = if world.is_solid(x, y, z-1) { 1.0 } else { 0.0 }
           - if world.is_solid(x, y, z+1) { 1.0 } else { 0.0 };
    
    Vec3::new(dx, dy, dz).normalize()
}
```
