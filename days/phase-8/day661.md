## 0 · 为什么要有这一天

回顾 Day 660 的连接算法:

```rust
for new_room in all_rooms {
    let nearest = find_nearest(existing_rooms, new_room);

}
```

贪心:每个新房间连最近的已有房间。问题:

- 假设房间 A、B、C 已连接,新房间 D 离 B 最近
- D 连 B
- 但 D 可能也"接近" A 和 C,只是 B 更近一点
- 结果:D-B 连,A 和 C 没直接连 D
- 玩家从 A 走到 D,要 A → B → D,绕路

**最小生成树**(Minimum Spanning Tree,MST)的解法:把所有房间看作图节点,所有可能的连接是边(权重 = 距离),MST 给出"连接所有节点的最小总权重边集"。

MST 保证:全连通(任意两节点有路径)+ 总走廊长度最短(避免冗余)。

心理锚点:看完今天,你能:

- 解释 MST 算法
- 实现 Kruskal 或 Prim
- 用 MST 优化房间连接

## 2 · 心智模型

### 类比:城市间修高速

国家有 10 个城市,要修高速连接。要求:每个城市可达,总修路成本最低。

- **贪心**(Day 660):每个新城市连最近的已有城市——可能绕远
- **MST**:全局看所有城市对,选最小总长度的高速网

MST 是经典的"网络设计"问题。

### 图论复习

**图**(Graph):节点 + 边。例:房间 = 节点,走廊 = 边。

**生成树**(Spanning Tree):连接所有节点的子图,无环,N 个节点有 N-1 条边。

**最小生成树**(MST):所有生成树中,边权重和最小的那个。

### Kruskal 算法

最直观的 MST 算法:

1. 把所有边按权重排序(升序)
2. 从最小边开始,如果两端点不在同一连通分量(用 union-find 检查),加入 MST
3. 重复直到 N-1 条边

**Union-Find**(并查集):快速判断"两个节点是否在同一集合"。

```rust
struct UnionFind {
    parent: Vec<usize>,
    rank: Vec<u8>,
}

impl UnionFind {
    fn new(n: usize) -> Self {
        Self {
            parent: (0..n).collect(),
            rank: vec![0; n],
        }
    }
    fn find(&mut self, x: usize) -> usize {
        if self.parent[x] != x {
            self.parent[x] = self.find(self.parent[x]); // path compression
        }
        self.parent[x]
    }
    fn union(&mut self, x: usize, y: usize) -> bool {
        let (rx, ry) = (self.find(x), self.find(y));
        if rx == ry { return false; } // already same set
        if self.rank[rx] < self.rank[ry] {
            self.parent[rx] = ry;
        } else if self.rank[rx] > self.rank[ry] {
            self.parent[ry] = rx;
        } else {
            self.parent[ry] = rx;
            self.rank[rx] += 1;
        }
        true
    }
}

fn kruskal(n: usize, mut edges: Vec<(usize, usize, f32)>) -> Vec<(usize, usize)> {
    edges.sort_by(|a, b| a.2.partial_cmp(&b.2).unwrap());
    let mut uf = UnionFind::new(n);
    let mut mst = Vec::new();
    for (a, b, _) in edges {
        if uf.union(a, b) {
            mst.push((a, b));
            if mst.len() == n - 1 { break; }
        }
    }
    mst
}
```

`path compression` 和 `union by rank` 让 union-find 几乎是 O(1) per op。

### 完全图构造

N 个房间,所有可能连接 = N*(N-1)/2 条边(完全图)。N=10 → 45 边。

```rust
fn build_complete_graph(rooms: &[Rect]) -> Vec<(usize, usize, f32)> {
    let mut edges = Vec::new();
    for i in 0..rooms.len() {
        for j in (i + 1)..rooms.len() {
            let c1 = rooms[i].center();
            let c2 = rooms[j].center();
            let dx = (c1.0 - c2.0) as f32;
            let dz = (c1.1 - c2.1) as f32;
            let dist = (dx * dx + dz * dz).sqrt();
            edges.push((i, j, dist));
        }
    }
    edges
}
```

MST 算法处理这 N*(N-1)/2 边,选 N-1 条。

### 加额外环路(可选)

MST 是树,只有一条路径从 A 到 B。游戏地图通常**有环路**(让玩家有多条路)。加 5-10% 的"额外连接":

```rust
fn mst_with_loops(rooms: &[Rect], extra_ratio: f32) -> Vec<(usize, usize)> {
    let edges = build_complete_graph(rooms);
    let mst = kruskal(rooms.len(), edges.clone());
    let extra_count = (rooms.len() as f32 * extra_ratio) as usize;
    // 从剩余边里随机选 extra_count 个
    let mut remaining: Vec<_> = edges.into_iter()
        .filter(|(a, b, _)| !mst.contains(&(*a, *b)))
        .collect();
    // 简化:取前 extra_count
    mst.into_iter().chain(remaining.drain(..extra_count.min(remaining.len()))).collect()
}
```

### 算法复杂度

- 完全图构造:O(N²)
- 排序:O(N² log N²) = O(N² log N)
- Kruskal:O(N² α(N))(α 是反 Ackermann,几乎 1)

N=10:100 操作,瞬间。N=100:1 万操作,几毫秒。N=1000:100 万,可接受。

游戏房间数通常 < 50,完全够快。

### 3.4 · Rust 生态视角

Rust 里 union-find:

```rust
struct UnionFind { parent: Vec<usize>, rank: Vec<u8> }

impl UnionFind {
    fn new(n: usize) -> Self {
        Self { parent: (0..n).collect(), rank: vec![0; n] }
    }
    fn find(&mut self, x: usize) -> usize {
        // iterative 版本(避免 stack overflow on deep recursion)
        let mut root = x;
        while self.parent[root] != root {
            root = self.parent[root];
        }
        let mut current = x;
        while self.parent[current] != root {
            let next = self.parent[current];
            self.parent[current] = root;
            current = next;
        }
        root
    }
    fn union(&mut self, x: usize, y: usize) -> bool {
        let (rx, ry) = (self.find(x), self.find(y));
        if rx == ry { return false; }
        if self.rank[rx] < self.rank[ry] { self.parent[rx] = ry; }
        else if self.rank[rx] > self.rank[ry] { self.parent[ry] = rx; }
        else { self.parent[ry] = rx; self.rank[rx] += 1; }
        true
    }
}
```

迭代版 find 避免大集合 stack overflow。Casey 在 HH 里用迭代版。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 MST 比贪心连接更好?给一个具体例子。

**参考解答**:考虑 4 个房间 A、B、C、D,组成正方形,边长 1,对角线长 √2 ≈ 1.41。贪心:先放 A,放 B(B 离 A 最近,距离 1),放 C(C 离 A 和 B 都是距离 1,假设选 A),放 D(D 离 B 和 C 都是 1,假设选 B)。结果:A-B,A-C,B-D。总长 3。MST 也给同样的解(总长 3)。但如果房间位置不对称,贪心可能产生"额外长边"。例:A(0,0), B(1,0), C(2,0), D(0,10)。贪心放 D 时最近是 A,距离 10。MST 选 A-D(10),A-B(1),B-C(1),总 12。两者相同。但如果 D 离 A=10, B=11, C=9,贪心选 B(因为 B 是"最近的已有",但 B 离 D 是 11),MST 选 C-D(9),省 2。

## 8 · Rust / Arch 落地代码

完整 MST + 地图连接:

```rust
// Cargo.toml:
// [dependencies]
// rand = "0.8"
// rand_xoshiro = "0.6"

use rand::{Rng, SeedableRng};
use rand_xoshiro::Xoshiro256PlusPlus;

#[derive(Clone, Copy, Debug)]
struct Room { x: i32, z: i32, w: i32, h: i32 }

impl Room {
    fn center(&self) -> (i32, i32) { (self.x + self.w / 2, self.z + self.h / 2) }
}

struct UnionFind { parent: Vec<usize>, rank: Vec<u8> }

impl UnionFind {
    fn new(n: usize) -> Self {
        Self { parent: (0..n).collect(), rank: vec![0; n] }
    }
    fn find(&mut self, x: usize) -> usize {
        let mut root = x;
        while self.parent[root] != root { root = self.parent[root]; }
        let mut cur = x;
        while self.parent[cur] != root {
            let next = self.parent[cur];
            self.parent[cur] = root;
            cur = next;
        }
        root
    }
    fn union(&mut self, x: usize, y: usize) -> bool {
        let (rx, ry) = (self.find(x), self.find(y));
        if rx == ry { return false; }
        if self.rank[rx] < self.rank[ry] { self.parent[rx] = ry; }
        else if self.rank[rx] > self.rank[ry] { self.parent[ry] = rx; }
        else { self.parent[ry] = rx; self.rank[rx] += 1; }
        true
    }
}

fn build_edges(rooms: &[Room]) -> Vec<(usize, usize, f32)> {
    let mut edges = Vec::new();
    for i in 0..rooms.len() {
        for j in (i + 1)..rooms.len() {
            let (c1, c2) = (rooms[i].center(), rooms[j].center());
            let dx = (c1.0 - c2.0) as f32;
            let dz = (c1.1 - c2.1) as f32;
            edges.push((i, j, (dx * dx + dz * dz).sqrt()));
        }
    }
    edges
}

fn mst(n: usize, edges: &[(usize, usize, f32)]) -> Vec<(usize, usize)> {
    let mut sorted: Vec<_> = edges.to_vec();
    sorted.sort_by(|a, b| a.2.partial_cmp(&b.2).unwrap_or(std::cmp::Ordering::Equal));
    let mut uf = UnionFind::new(n);
    let mut result = Vec::new();
    for (a, b, _) in sorted {
        if uf.union(a, b) {
            result.push((a, b));
            if result.len() == n - 1 { break; }
        }
    }
    result
}

fn connect_with_extra_loops(
    n: usize,
    edges: &[(usize, usize, f32)],
    mst_edges: &[(usize, usize)],
    extra_ratio: f32,
    rng: &mut impl Rng,
) -> Vec<(usize, usize)> {
    let mut result = mst_edges.to_vec();
    let mst_set: std::collections::HashSet<_> = mst_edges.iter().cloned().collect();
    let extras: Vec<_> = edges.iter()
        .filter(|(a, b, _)| !mst_set.contains(&(*a, *b)) && !mst_set.contains(&(*b, *a)))
        .map(|(a, b, _)| (*a, *b))
        .collect();
    let extra_count = ((n as f32) * extra_ratio) as usize;
    let mut chosen = vec![false; extras.len()];
    for _ in 0..extra_count.min(extras.len()) {
        let idx = rng.gen_range(0..extras.len());
        if !chosen[idx] {
            chosen[idx] = true;
            result.push(extras[idx]);
        }
    }
    result
}

fn main() {
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let rooms = vec![
        Room { x: 2, z: 2, w: 5, h: 5 },
        Room { x: 15, z: 3, w: 5, h: 5 },
        Room { x: 3, z: 15, w: 5, h: 5 },
        Room { x: 18, z: 18, w: 5, h: 5 },
        Room { x: 10, z: 10, w: 5, h: 5 },
    ];
    let edges = build_edges(&rooms);
    println!("All edges: {}", edges.len());
    for (a, b, d) in &edges {
        println!("  {}-{}: {:.2}", a, b, d);
    }

    let mst_edges = mst(rooms.len(), &edges);
    println!("\nMST: {} edges", mst_edges.len());
    let total_mst: f32 = mst_edges.iter()
        .map(|(a, b)| edges.iter().find(|(ea, eb, _)| (ea, eb) == (a, b)).unwrap().2)
        .sum();
    println!("MST total length: {:.2}", total_mst);

    let connected = connect_with_extra_loops(rooms.len(), &edges, &mst_edges, 0.2, &mut rng);
    println!("\nFinal connections: {} edges", connected.len());
    for (a, b) in &connected {
        let c1 = rooms[*a].center();
        let c2 = rooms[*b].center();
        println!("  Room {} {:?} - Room {} {:?}", a, c1, b, c2);
    }
}
```

## 10 · 工程反思

Day 661 传达的核心工程教训:**图算法是 spatial PCG 的工具**。

新手以为"PCG = noise",资深工程师知道复杂结构(连通房间 / 树状世界)需要**图算法**——MST / BFS / DFS / Dijkstra / A*。每个算法解决一类问题。

**经典图算法在游戏的应用**:

- **MST(Minimum Spanning Tree)**:连通所有房间,最少走廊
- **Dijkstra**:最短路径(加权图)
- **A***:启发式最短路径(快)
- **BFS / DFS**:遍历(找连通分量)
- **Max flow**:资源分配(罕见但有用)
- **Topological sort**:依赖排序(技能树)

每个算法都有自己的 game dev 应用。Casey 在 Day 661 用 MST 做 dungeon 连通,这是经典用法。

**为什么 MST 适合 dungeon?**

Dungeon 的房间是节点,房间之间可能的走廊是边(权重 = 距离)。MST 给出"连通所有房间 + 总走廊最短"的方案——既保证所有房间可达,又节省走廊面积。

工业实例:

- **Spelunky**:用 MST 保证 level 可通关
- **Binding of Isaac**:类似 MST 保证连通
- **Hades**:用 MST + 额外边产生"循环"路径

每个 procedural dungeon 都用类似算法。这是 PCG 工程师的核心工具。

**第二条教训**:**Union-Find 是稀疏图的利器**。

MST 的 Kruskal 算法需要"判断两个节点是否在同一连通分量"。Union-Find(并查集)做这个最优——平均 O(α(N)),α 是反 Ackermann 函数(几乎是常数)。

Union-Find 在游戏开发多处可用:

- **区域连通**:玩家访问的房间归为一组
- **物体组合**:多个物体合并为一个 compound
- **Network**:packet 归属(同 source)
- **AI faction**:NPC 阵营管理

学懂 Union-Find,你解决一类"分组 + 合并"问题。

**第三条教训**:**图算法实现要小心**。

图算法看似简单(BFS 5 行),但工业级实现要处理:

- **大图**:百万节点,内存/性能考虑
- **稀疏 vs 稠密**:不同数据结构(adjacency list vs matrix)
- **加权 vs 无权**:不同算法
- **有向 vs 无向**:语义不同
- **负权**:Dijkstra 不支持负权,Bellman-Ford 支持

每个细节都可能让算法失效。`petgraph` crate 是 Rust 工业级图库,推荐使用而非自己实现。

## N0 • 深度教学补充

### 核心概念重新梳理

Day 661 涉及的核心概念需要在多个层次上理解:

**第一层:直观理解**

新手第一次接触概念,需要建立直觉。例如 voxel collision 是"虚拟物体不能穿过虚拟墙"——这个直觉每个人都能从现实经验获得。

**第二层:数学理解**

把直觉形式化。collision = "两个几何体的体积有交集"。对于 AABB,这等价于"三轴投影都重叠"。

**第三层:工程理解**

数学正确不等于工程实现正确。要考虑:

- 浮点精度边界
- 性能(每帧 N 个查询)
- 内存(数据结构紧凑)
- 边角 case(无穷大、NaN、负数)

**第四层:工业理解**

工业级要再加:

- 多线程安全
- SIMD 优化
- 网络同步(多人游戏)
- 跨平台(Windows/Mac/Linux/Mobile)
- 可访问性(色盲友好)
- 反作弊

每层理解都让代码更鲁棒。资深工程师在所有层次同时思考。

### 实际工程的细节

工业代码 80% 是"边角 case 处理",20% 是"核心算法"。Casey 在 HH 演示核心,工业代码加大量边角处理。

**边角 case 类型**:

1. 空输入(空 Vec、null pointer)
2. 极端输入(NaN、无穷大、超大数)
3. 并发竞争(多线程同时访问)
4. 资源不足(内存满、磁盘满)
5. 网络异常(超时、断连、包丢失)
6. 版本不兼容(老配置 / 新代码)
7. 权限错误(只读文件、无网络)
8. 用户误操作(连点、撤销重做)

每个 case 都要单独处理。这是工业代码 50%+ 行数的原因。

### 优化思路

性能优化有顺序:

1. **算法**:O(N²) → O(N log N),最大提升
2. **数据结构**:Vec → HashMap / BTreeMap,常数提升
3. **Cache**:AoS → SoA,cache 命中提升
4. **SIMD**:4-16 元素并行,巨大常数提升
5. **GPU**:数千核并行,极致性能
6. **分布式**:多机器,无限扩展

每级提升都需要更复杂的代码。先优化低级,够用再升级。

- **完成 > 完美**:能跑 > 能优化

这些哲学跨技术领域通用。学完 HH,你不只会写游戏,你**理解工程**。这是 HH 最大的价值。

Day 661 用 C 写,但 Rust 版本会更安全 / 更高效:

- **fearless concurrency**:多线程安全

每条都让代码更鲁棒。Rust 是游戏开发的新趋势(bevy / wgpu / rend3),学习 Rust 让你未来 10 年受益。
