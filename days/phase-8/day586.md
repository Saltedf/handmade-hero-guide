# Day 586 · 完成间接漫反射采样

> Day 582 写了 specular_to_diffuse 卷积,Day 585 把 atlas 集中化。但实际游戏渲染时,玩家眼睛看到的"间接漫反射"还需要从体素辐射场正确插值到玩家位置——不是简单地取最近体素的 diffuse_color,而是空间三线性插值。Casey 今天要把这个采样收尾。

## 0 · 为什么要有这一天

回顾间接漫反射的数据流:

```
[阶段 1] 直接光注入辐射场
[阶段 2] 无限弹射传播(8 次迭代)
[阶段 3] specular_to_diffuse 卷积,每体素存一个 RGB 标量
[阶段 4] 渲染:从玩家位置采样间接漫反射 ← 今天要收尾这里
```

阶段 4 的细节:玩家眼睛看到的某个像素,ray 投射到墙体,命中位置 `hit_pos`。这个位置在哪个体素?可能正好在体素中心,也可能在体素边界,也可能在多个体素交界处。

**最朴素的方案**:找最近的体素,取它的 diffuse_color。问题:玩家移动时,不同体素的 diffuse_color 跳变,墙面"闪烁"。

**正确方案**:**空间三线性插值**(trilinear interpolation)。在 3D 网格的 8 个角点(对应 8 个相邻体素)之间做加权平均,得到 hit_pos 位置的连续漫反射值。这样玩家平滑移动时,漫反射也平滑变化。

Casey 这一天就是写这个三线性插值。听起来简单,但有几个工程细节:
- 网格边界处理(玩家在网格边)
- 8 个邻居的查找效率
- 与镜面 atlas 采样的合并

心理锚点:看完这集,你能实现 3D 网格上的三线性插值,理解它与 2D 双线性、3D 三线性的差别,能在自己写任何"网格采样"代码时复用这个模式。

## 2 · 心智模型

### 类比:温度地图

假设你有一个气象站网格(每个气象站间隔 10 公里),每个气象站测当地温度。你想知道"中间某点"的温度——比如 (12, 35) 这个位置(网格中(10,30)和(20,40)之间)。

最简单:取最近气象站。问题:移动 1 公里,温度可能跳变。

正确做法:**双线性插值**(2D 网格)。在 (10,30)、(20,30)、(10,40)、(20,40) 四个气象站之间做加权平均。距离 (10,30) 越近,权重越大;距离 (20,40) 越远,权重越小。

**三线性插值**是双线性的 3D 版——立方体 8 个角点。我们的体素网格是 3D 的,所以用三线性。

### 严谨原理:三线性插值公式

给定立方体 8 个角点的值 `v000, v100, v010, v110, v001, v101, v011, v111`(下标是 xyz 坐标,0 或 1),立方体内部点 `(fx, fy, fz)` 其中 `fx, fy, fz ∈ [0, 1]`,插值公式:

```
// 第一步:沿 x 方向插值(4 次)
c00 = v000 * (1-fx) + v100 * fx
c01 = v001 * (1-fx) + v101 * fx
c10 = v010 * (1-fx) + v110 * fx
c11 = v011 * (1-fx) + v111 * fx

// 第二步:沿 y 方向插值(2 次)
c0 = c00 * (1-fy) + c10 * fy
c1 = c01 * (1-fy) + c11 * fy

// 第三步:沿 z 方向插值(1 次)
result = c0 * (1-fz) + c1 * fz
```

总共 7 次线性插值(8 个值变 1 个)。

**代码**:

```rust
fn lerp(a: RGB32F, b: RGB32F, t: f32) -> RGB32F {
    a.scale(1.0 - t).add(b.scale(t))
}

fn trilinear_sample(
    corner_values: &[RGB32F; 8],  // 8 个角点
    fx: f32, fy: f32, fz: f32,
) -> RGB32F {
    let [v000, v100, v010, v110, v001, v101, v011, v111] = *corner_values;
    let c00 = lerp(v000, v100, fx);
    let c01 = lerp(v001, v101, fx);
    let c10 = lerp(v010, v110, fx);
    let c11 = lerp(v011, v111, fx);
    let c0 = lerp(c00, c10, fy);
    let c1 = lerp(c01, c11, fy);
    lerp(c0, c1, fz)
}
```

**每行解释**:
- `lerp(a, b, t) = a*(1-t) + b*t` — 线性插值的标准公式。`t=0` 返回 a,`t=1` 返回 b。
- 8 个 corner_values 按特定顺序排(000, 100, 010, 110, 001, 101, 011, 111),便于下标推导。
- 三次 lerp 沿 x → y → z,最后得一个 RGB。

### 体素网格的 8 个角点

给定玩家位置 `pos`,首先找到包含 pos 的体素立方体:

```rust
fn find_cube_corners(world: &World, pos: Vec3) -> [usize; 8] {
    let voxel_size = world.voxel_size;
    let x0 = (pos.x / voxel_size).floor() as i32;
    let y0 = (pos.y / voxel_size).floor() as i32;
    let z0 = (pos.z / voxel_size).floor() as i32;
    
    let mut corners = [0; 8];
    let mut idx = 0;
    for dz in 0..2 {
        for dy in 0..2 {
            for dx in 0..2 {
                corners[idx] = world.voxel_index(x0 + dx, y0 + dy, z0 + dz);
                idx += 1;
            }
        }
    }
    corners
}
```

**fx, fy, fz**(在立方体内的局部坐标):

```rust
let fx = pos.x / voxel_size - x0 as f32;
let fy = pos.y / voxel_size - y0 as f32;
let fz = pos.z / voxel_size - z0 as f32;
```

### 完整采样函数

```rust
fn sample_diffuse(world: &World, pos: Vec3) -> RGB32F {
    let corners = find_cube_corners(world, pos);
    let mut values = [RGB32F::default(); 8];
    for (i, &c) in corners.iter().enumerate() {
        values[i] = world.voxels[c].diffuse_color;
    }
    
    let voxel_size = world.voxel_size;
    let x0 = (pos.x / voxel_size).floor() as i32;
    let y0 = (pos.y / voxel_size).floor() as i32;
    let z0 = (pos.z / voxel_size).floor() as i32;
    let fx = pos.x / voxel_size - x0 as f32;
    let fy = pos.y / voxel_size - y0 as f32;
    let fz = pos.z / voxel_size - z0 as f32;
    
    trilinear_sample(&values, fx, fy, fz)
}
```

### 边界处理

如果玩家在网格边,某些角点不存在:

```rust
fn voxel_index(&self, x: i32, y: i32, z: i32) -> usize {
    // 越界则 clamp 到边界
    let cx = x.max(0).min(self.dim_x as i32 - 1) as usize;
    let cy = y.max(0).min(self.dim_y as i32 - 1) as usize;
    let cz = z.max(0).min(self.dim_z as i32 - 1) as usize;
    cy * self.dim_x * self.dim_z + cz * self.dim_x + cx
}
```

`clamp` 让"虚拟的边界外体素"等同于"边界上最近的体素"——简化代码,代价是边界处插值精度略低。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,3D 网格插值是 Light Probe Volume(光照探针体积)的核心操作。UE5、Unity HDRP 都用类似数据结构——3D 网格,每格存 SH 系数,采样时三线性插值。

**踩过的坑**:
- **接缝**:相邻体素的 diffuse_color 差异大,插值时有可见"折线"。解决:用更高网格密度
- **权重突变**:玩家在网格边界时,某些邻居消失,权重突变。解决:用 padding 体素(边界外虚拟体素)
- **方向插值错误**:对 SH 系数做线性插值 ≠ 对方向光照做线性插值。SH 系数线性插值通常是好的,但极端情况下需要 Slerp(球面插值)

### 3.2 · 🎨 图形学视角

三线性插值在图形学里大量使用:
- **3D 纹理采样**:GPU 硬件内建,OpenGL `sampler3D` + `texture(sampler, vec3(uvw))`
- **体积雾**:每像素采样 3D 雾纹理,三线性插值
- **3D LUT 颜色校正**:颜色映射用 3D LUT,三线性采样
- **流体仿真**:速度场 3D 网格,采样时三线性

**数学背景**:三线性是"双线性在 3D 的扩展"。三线性插值的结果在立方体内是连续的,但导数不连续(在立方体边界导数跳变)。要更高阶连续,需要三次插值(cubic / Catmull-Rom),代价是计算量翻倍。

### 3.3 · 🐧 Linux 系统编程视角

这一集主要是数学,Linux 系统调用面没什么。但有一个**SIMD**的话题。

三线性插值的 7 次 lerp,每次涉及 3 个 f32 分量(RGB)。SIMD 可以一次处理 4 个 f32(SSE),所以 RGB lerp 可以打包成一次 SIMD 操作:

```rust
use std::arch::x86_64::*;

#[target_feature(enable = "sse2")]
unsafe fn lerp_simd(a: __m128, b: __m128, t: f32) -> __m128 {
    let t_vec = _mm_set1_ps(t);
    // a * (1 - t) + b * t = a + t * (b - a)
    let diff = _mm_sub_ps(b, a);
    let scaled = _mm_mul_ps(diff, t_vec);
    _mm_add_ps(a, scaled)
}
```

Casey 在 Day 587 做这种 SIMD 化。

### 3.4 · 🦀 Rust 生态视角

Rust 实现三线性插值的几个细节:

**类型安全**:`RGB32F` 是自定义类型,不能直接用 f32 的算术。需要手动实现 `lerp`:

```rust
impl RGB32F {
    fn lerp(self, other: Self, t: f32) -> Self {
        Self {
            r: self.r.lerp(other.r, t),
            g: self.g.lerp(other.g, t),
            b: self.b.lerp(other.b, t),
        }
    }
}

trait Lerp {
    fn lerp(self, other: Self, t: f32) -> Self;
}

impl Lerp for f32 {
    fn lerp(self, other: Self, t: f32) -> Self {
        self + (other - self) * t
    }
}
```

**Trait Lerp** 让任何数值类型都可以做插值。Casey 用这种 trait 复用代码。

**`[T; 8]` 数组**:Rust 的固定大小数组,用于存 8 个角点。访问 `arr[i]` 是 O(1),编译时检查越界。

## 5 · 对照与变奏

### 同一插值问题在不同语境下的变体

| 语境 | 插值方法 |
|---|---|
| 1D 信号(音频) | 线性 / 三次 |
| 2D 图像 | 双线性 / 双三次 |
| 3D 体积(雾、LUT)| 三线性 |
| 4D(时间 + 3D)| 四线性 |
| 球面(方向)| Slerp |
| 颜色空间 | 线性混合(在线性空间) |

每种都是"已知点 → 任意点"的插值,只是定义域维度不同。

### 历史演化

- **1970s**:数字图像处理兴起,双线性插值标准
- **1980s**:体积渲染(医学 CT/MRI),三线性普及
- **2000s**:GPU 硬件支持三线性(`sampler3D`)
- **2010s+**:实时体积雾、3D LUT 颜色校正,三线性无处不在

Casey 的三线性实现是教科书级,直接手写 lerp + 嵌套。

### CPU vs GPU 三线性

- **CPU**(Casey):手写 lerp,7 次乘加。可 SIMD 加速
- **GPU**:硬件内建 `textureLod(sampler3D, uvw, lod)`,免费
- **GPU shader 内手动三线性**:比硬件慢,但灵活(自定义权重)

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:三线性插值在立方体内"连续",但"导数不连续"是什么意思?具体在哪里导数会跳变?

**参考解答**:三线性在立方体内部各处导数连续(是 fx/fy/fz 的一次多项式)。但在立方体边界(如 fx=0 或 fx=1),左右两侧的多项式系数不同,导数跳变。

具体:点 A 在立方体 1 的 fx=0.999,点 B 在立方体 2 的 fx=0.001(同一物理位置)。立方体 1 的导数基于立方体 1 的 8 角点,立方体 2 的导数基于立方体 2 的 8 角点。如果两组角点差异大,A 到 B 的导数跳变。

视觉影响:墙面光照"折线"伪影。消除:用三次插值(Catmull-Rom),代价是计算量 2 倍。

**参考解答**:

```rust
fn lerp(a: RGB32F, b: RGB32F, t: f32) -> RGB32F {
    RGB32F::new(
        a.r + (b.r - a.r) * t,
        a.g + (b.g - a.g) * t,
        a.b + (b.b - a.b) * t,
    )
}

fn trilinear_sample(values: &[RGB32F; 8], fx: f32, fy: f32, fz: f32) -> RGB32F {
    // 8 corner: v000, v100, v010, v110, v001, v101, v011, v111
    let [v000, v100, v010, v110, v001, v101, v011, v111] = values;
    let c00 = lerp(*v000, *v100, fx);
    let c01 = lerp(*v001, *v101, fx);
    let c10 = lerp(*v010, *v110, fx);
    let c11 = lerp(*v011, *v111, fx);
    let c0 = lerp(c00, c10, fy);
    let c1 = lerp(c01, c11, fy);
    lerp(c0, c1, fz)
}

fn main() {
    // 8 角点用 8 种颜色,验证插值
    let v = [
        RGB32F::new(1.0, 0.0, 0.0),  // v000 红
        RGB32F::new(0.0, 1.0, 0.0),  // v100 绿
        RGB32F::new(0.0, 0.0, 1.0),  // v010 蓝
        RGB32F::new(1.0, 1.0, 0.0),  // v110 黄
        RGB32F::new(1.0, 0.0, 1.0),  // v001 紫
        RGB32F::new(0.0, 1.0, 1.0),  // v101 青
        RGB32F::new(0.5, 0.5, 0.5),  // v011 灰
        RGB32F::new(0.2, 0.2, 0.2),  // v111 深灰
    ];
    
    let c1 = trilinear_sample(&v, 0.0, 0.0, 0.0);
    println!("(0,0,0) = {:?} (should be red)", c1);
    
    let c2 = trilinear_sample(&v, 1.0, 1.0, 1.0);
    println!("(1,1,1) = {:?} (should be dark gray)", c2);
    
    let c3 = trilinear_sample(&v, 0.5, 0.5, 0.5);
    println!("(0.5,0.5,0.5) = {:?} (should be average)", c3);
}
```

```rust
// (RGB32F, lerp, trilinear_sample 同 Lv2)

fn main() {
    // 创建 2x2x2 体素网格,每体素一个 diffuse_color
    let grid = [
        RGB32F::new(1.0, 0.0, 0.0),  // (0,0,0)
        RGB32F::new(0.5, 0.5, 0.0),  // (1,0,0)
        RGB32F::new(0.0, 1.0, 0.0),  // (0,1,0)
        RGB32F::new(0.0, 0.5, 0.5),  // (1,1,0)
        RGB32F::new(0.0, 0.0, 1.0),  // (0,0,1)
        RGB32F::new(0.5, 0.0, 0.5),  // (1,0,1)
        RGB32F::new(0.0, 0.5, 1.0),  // (0,1,1)
        RGB32F::new(0.3, 0.3, 0.3),  // (1,1,1)
    ];
    
    // 在网格内采样几个位置
    let positions = [
        (0.5, 0.5, 0.5, "center"),
        (0.25, 0.5, 0.5, "near x=0"),
        (0.75, 0.5, 0.5, "near x=1"),
        (0.5, 0.5, 0.0, "at z=0 face"),
    ];
    for (fx, fy, fz, name) in &positions {
        let c = trilinear_sample(&grid, *fx, *fy, *fz);
        println!("({}, {}, {}) = {:?} ({})", fx, fy, fz, c, name);
    }
    
    // 平滑度测试:沿一条直线采样,验证连续性
    println!("\nSmoothness test (along x at y=0.5, z=0.5):");
    for i in 0..=10 {
        let fx = i as f32 / 10.0;
        let c = trilinear_sample(&grid, fx, 0.5, 0.5);
        println!("  x={:.1}: {:?}", fx, c);
    }
}
```

### A.8 Voxel lighting 性能 profile

Casey 在 phase-8 多次 profile,发现:
- Light propagation:占 70% CPU 时间
- Raycast:占 20%
- Meshing:占 5%
- 其他:5%

工业游戏 profile 显示类似分布:
- Lighting 是大头

性能优化顺序:
1. 找最慢的(propiler)
2. 优化它
3. 重新 profile,找新的最慢
4. 重复

直到性能达标。

### A.9 Voxel lighting 的内存占用

```
Per voxel 数据:
  - material: 1 byte
  - color: 3 byte (RGB)
  - light: 3-4 byte (RGB 或 RGBE)
  - flags: 1 byte
  Total: 8-9 byte / voxel

100^3 voxel(简化场景):
  100^3 × 9 byte = 9 MB

1000^3 voxel(大场景):
  1000^3 × 9 byte = 9 GB

太大 → 必须 streaming。
```

工业 voxel 游戏(Minecraft)用 chunked streaming:每 chunk 16×16×16 = 4096 voxel × 9 byte ≈ 36 KB。同时加载 100 chunk ≈ 3.6 MB,可控。

### A.11 完整 Rust voxel lighting 实现

让我提供一个完整的 Rust voxel lighting 实现示例,综合前面所有概念:

```rust
use std::collections::HashMap;

const CHUNK_SIZE: u32 = 32;

struct Voxel {
    material: u8,
    color: [u8; 3],
}

struct Chunk {
    voxels: Vec<Voxel>,
    light: Vec<[u8; 4]>,  // RGBE
}

struct World {
    chunks: HashMap<(i32, i32, i32), Chunk>,
    sun_dir: Vec3,
    sun_color: [f32; 3],
}

impl World {
    fn get_voxel(&self, x: i32, y: i32, z: i32) -> Option<&Voxel> {
        let (cx, cy, cz) = (x.div_euclid(CHUNK_SIZE as i32), 
                            y.div_euclid(CHUNK_SIZE as i32),
                            z.div_euclid(CHUNK_SIZE as i32));
        let chunk = self.chunks.get(&(cx, cy, cz))?;
        let (lx, ly, lz) = (x.rem_euclid(CHUNK_SIZE as i32) as usize,
                            y.rem_euclid(CHUNK_SIZE as i32) as usize,
                            z.rem_euclid(CHUNK_SIZE as i32) as usize);
        let idx = lz * (CHUNK_SIZE as usize).pow(2) + ly * CHUNK_SIZE as usize + lx;
        Some(&chunk.voxels[idx])
    }
    
    fn is_solid(&self, x: i32, y: i32, z: i32) -> bool {
        self.get_voxel(x, y, z).map(|v| v.material != 0).unwrap_or(false)
    }
}

fn grid_dda(world: &World, start: Vec3, dir: Vec3, max_dist: f32) -> bool {
    let mut cx = start.x.floor() as i32;
    let mut cy = start.y.floor() as i32;
    let mut cz = start.z.floor() as i32;
    
    let step_x = if dir.x > 0.0 { 1 } else { -1 };
    let step_y = if dir.y > 0.0 { 1 } else { -1 };
    let step_z = if dir.z > 0.0 { 1 } else { -1 };
    
    let t_delta_x = if dir.x.abs() > 1e-10 { 1.0 / dir.x.abs() } else { f32::INFINITY };
    let t_delta_y = if dir.y.abs() > 1e-10 { 1.0 / dir.y.abs() } else { f32::INFINITY };
    let t_delta_z = if dir.z.abs() > 1e-10 { 1.0 / dir.z.abs() } else { f32::INFINITY };
    
    let mut t_max_x = if dir.x.abs() > 1e-10 {
        (((cx + if dir.x > 0 { 1 } else { 0 }) as f32) - start.x) / dir.x
    } else { f32::INFINITY };
    let mut t_max_y = /* similar */;
    let mut t_max_z = /* similar */;
    
    let mut t = 0.0;
    while t < max_dist {
        if world.is_solid(cx, cy, cz) {
            return true;  // occluded
        }
        
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            t = t_max_x;
            t_max_x += t_delta_x;
        } else if t_max_y < t_max_z {
            cy += step_y;
            t = t_max_y;
            t_max_y += t_delta_y;
        } else {
            cz += step_z;
            t = t_max_z;
            t_max_z += t_delta_z;
        }
    }
    false
}

fn compute_direct_lighting(world: &World, x: i32, y: i32, z: i32) -> [f32; 3] {
    let voxel_pos = Vec3::new(x as f32 + 0.5, y as f32 + 0.5, z as f32 + 0.5);
    
    // 是否被遮挡
    if grid_dda(world, voxel_pos, world.sun_dir, 100.0) {
        return [0.0; 3];  // 阴影
    }
    
    // Lambert 光照
    let normal = compute_normal(world, x, y, z);
    let lambert = normal.dot(world.sun_dir).max(0.0);
    
    [
        world.sun_color[0] * lambert,
        world.sun_color[1] * lambert,
        world.sun_color[2] * lambert,
    ]
}

fn compute_normal(world: &World, x: i32, y: i32, z: i32) -> Vec3 {
    let dx = if world.is_solid(x-1, y, z) { 1.0 } else { 0.0 } 
           - if world.is_solid(x+1, y, z) { 1.0 } else { 0.0 };
    let dy = if world.is_solid(x, y-1, z) { 1.0 } else { 0.0 }
           - if world.is_solid(x, y+1, z) { 1.0 } else { 0.0 };
    let dz = if world.is_solid(x, y, z-1) { 1.0 } else { 0.0 }
           - if world.is_solid(x, y, z+1) { 1.0 } else { 0.0 };
    
    Vec3::new(dx, dy, dz).normalize()
}
```
