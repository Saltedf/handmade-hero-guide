# Day 628 · 大脑与围裙 · 实体行为系统

> Day 627 实现机关门(被动响应玩家)。今天 Casey 实现主动行为的实体——NPC 怪物。Casey 用一个生动的比喻:**Brain**(大脑)和 **Apron**(围裙)。Brain 是"决策系统"(想什么),Apron 是"执行系统"(做什么)。这是行为系统(Behavior System)的经典设计模式。

## 0 · 为什么要有这一天

HH 的怪物(NPC)在 Phase 2 已经有"简单 AI"——朝玩家走、攻击、扣血。但代码很乱:

```rust
// 旧代码:逻辑全混在一起
fn update_monster(monster: &mut Monster, player: &Player) {
    // 移动逻辑
    let dir = player.pos - monster.pos;
    monster.pos += dir.normalized() * monster.speed;

    // 攻击逻辑
    if monster.pos.distance(player.pos) < 1.0 {
        player.take_damage(monster.damage);
    }

    // 死亡逻辑
    if monster.hp <= 0 {
        monster.dead = true;
        drop_loot(monster);
    }

    // 状态机
    match monster.state {
        Idle => { ... }
        Chasing => { ... }
        Attacking => { ... }
    }

    // 动画
    monster.sprite = match monster.state { ... };
}
```

**问题**:

1. **职责混乱**:移动、攻击、状态、动画全在一个函数
2. **难扩展**:加新行为要改这个函数
3. **难复用**:不同怪物类型复制粘贴代码

**今天的解决方案**:**Brain + Apron 模式**:

- **Brain**(决策):决定"该做什么"(攻击 / 追逐 / 逃跑)
- **Apron**(执行):做具体的事(移动、播放动画、播放音效)
- Brain 和 Apron 解耦,各自独立演化

### 类比

 Casey 用了一个生活化的比喻:

- **Brain**(大脑):你思考"我饿了"——决策
- **Apron**(围裙):你做饭——执行

你换 Brain(从"饿"变"渴"),不换 Apron(还是用围裙做饭 + 喝水)。或者换 Apron(从"做饭"变"叫外卖"),不换 Brain(还是因为饿)。

**核心**:**决策和执行分离**,各自独立变化。

**心理锚点**:看完这集,你能:
- 设计 Brain + Apron 模式的实体行为系统
- 把混合逻辑拆成决策 + 执行
- 扩展行为不改老代码

## 2 · 心智模型

### 类比:公司的决策层与执行层

公司有"决策层"和"执行层":

- **决策层(CEO / 经理)**:决定"我们要做 X 产品"
- **执行层(工程师 / 设计师)**:做 X 产品的具体工作

决策层不写代码,执行层不决定做什么。各自专精。

**Brain + Apron 完全一样**:

- **Brain**:"该攻击玩家了"——决策
- **Apron**:执行攻击动画 + 造成伤害——具体动作

加新决策(AggressiveBrain → DefensiveBrain)不改 Apron。加新执行(MeleeApron → MagicApron)不改 Brain。**两者独立演化**。

### 严谨:Brain + Apron 架构

#### 2.1 定义

```rust
// 上下文:Brain 和 Apron 共享的游戏状态
struct Context<'a> {
    world: &'a World,
    player: &'a Player,
    self_pos: Vec3,
    self_hp: f32,
    // ... Brain 决策需要的信息
}

// Action:Brain 的输出,Apron 的输入
enum Action {
    Idle,
    MoveTo(Vec3),
    Attack,
    Flee,
    CastSpell(u32),  // spell_id
}

// Brain:决策
trait Brain {
    fn decide(&self, ctx: &Context) -> Action;
}

// Apron:执行
trait Apron {
    fn execute(&mut self, action: Action, ctx: &Context, dt: f32, world: &mut World);
}

// Monster:持有 Brain 和 Apron
struct Monster {
    pos: Vec3,
    hp: f32,
    brain: Box<dyn Brain>,
    apron: Box<dyn Apron>,
}
```

#### 2.2 决策 Brain

```rust
struct AggressiveBrain;

impl Brain for AggressiveBrain {
    fn decide(&self, ctx: &Context) -> Action {
        let to_player = ctx.player.pos - ctx.self_pos;
        let dist = to_player.length();

        if dist < 2.0 {
            Action::Attack
        } else if dist < 10.0 {
            Action::MoveTo(ctx.player.pos)
        } else {
            Action::Idle
        }
    }
}

struct CowardBrain;

impl Brain for CowardBrain {
    fn decide(&self, ctx: &Context) -> Action {
        let to_player = ctx.player.pos - ctx.self_pos;
        let dist = to_player.length();

        if dist < 5.0 && ctx.self_hp < 0.3 {
            Action::Flee
        } else if dist < 10.0 {
            Action::Flee
        } else {
            Action::Idle
        }
    }
}
```

#### 2.3 执行 Apron

```rust
struct MeleeApron { attack_cooldown: f32 }

impl Apron for MeleeApron {
    fn execute(&mut self, action: Action, ctx: &Context, dt: f32, world: &mut World) {
        self.attack_cooldown -= dt;
        match action {
            Action::Idle => {
                // 播放 idle 动画
            }
            Action::MoveTo(target) => {
                let dir = (target - ctx.self_pos).normalized();
                world.move_monster(dir * 5.0 * dt);  // 5 m/s
            }
            Action::Attack => {
                if self.attack_cooldown <= 0.0 {
                    world.damage_player(10.0);
                    self.attack_cooldown = 1.0;
                    // 播放攻击动画
                }
            }
            Action::Flee => {
                let away = (ctx.self_pos - ctx.player.pos).normalized();
                world.move_monster(away * 8.0 * dt);  // 逃跑更快
            }
            _ => {}
        }
    }
}

struct RangedApron { attack_cooldown: f32 }

impl Apron for RangedApron {
    fn execute(&mut self, action: Action, ctx: &Context, dt: f32, world: &mut World) {
        self.attack_cooldown -= dt;
        match action {
            Action::Attack => {
                if self.attack_cooldown <= 0.0 {
                    world.spawn_projectile(ctx.self_pos, ctx.player.pos);
                    self.attack_cooldown = 2.0;
                }
            }
            Action::Flee => {
                let away = (ctx.self_pos - ctx.player.pos).normalized();
                world.move_monster(away * 5.0 * dt);
                // 边跑边射
                if self.attack_cooldown <= 0.0 {
                    world.spawn_projectile(ctx.self_pos, ctx.player.pos);
                    self.attack_cooldown = 2.0;
                }
            }
            _ => {}
        }
    }
}
```

#### 2.5 更新流程

```rust
fn update_monster(monster: &mut Monster, player: &Player, world: &mut World, dt: f32) {
    let ctx = Context {
        world,
        player,
        self_pos: monster.pos,
        self_hp: monster.hp,
    };

    let action = monster.brain.decide(&ctx);  // 决策
    monster.apron.execute(action, &ctx, dt, world);  // 执行
}
```

每个 Monster 每帧:**决策 → 执行**。两步分离,清晰。

### 2.6 扩展

加新 Brain(PatrolBrain):

```rust
struct PatrolBrain { waypoints: Vec<Vec3>, current: usize }

impl Brain for PatrolBrain {
    fn decide(&self, ctx: &Context) -> Action {
        let to_player = ctx.player.pos - ctx.self_pos;
        if to_player.length() < 5.0 {
            return Action::Flee;  // 看到玩家就逃
        }
        let target = self.waypoints[self.current];
        Action::MoveTo(target)
    }
}
```

不改 Apron,新行为立刻可用。**Open-Closed Principle**(对扩展开放,对修改封闭)。

加新 Apron(MagicApron):

```rust
struct MagicApron;

impl Apron for MagicApron {
    fn execute(&mut self, action: Action, ctx: &Context, dt: f32, world: &mut World) {
        match action {
            Action::CastSpell(spell_id) => {
                world.cast_spell(ctx.self_pos, ctx.player.pos, spell_id);
            }
            _ => {}
        }
    }
}
```

不改 Brain,新执行立刻可用。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Brain + Apron 是游戏 AI 的经典模式:

- **Unreal Engine**:`AIController`(Brain) + `CharacterMovement`(Apron)
- **Unity**:`NavMeshAgent`(Apron) + 自定义 Brain 逻辑
- **Overwatch / Valorant**:决策系统(decision tree)+ 执行系统(animation + physics)

**变体**:

- **Behavior Tree**:更结构化的 Brain(BT 节点)
- **GOAP**:Goal-Oriented Action Planning,Fallout 3 用
- **Utility AI**:每个动作有 utility 分数,选最高,The Sims 用

每种都解决类似问题(Brain / Apron 分离),只是 Brain 内部不同。

### 3.2 · 🎨 图形学视角

图形学也有"决策 / 执行"分离:

- **LOD selection**(Brain):决定用哪个 LOD level
- **Mesh rendering**(Apron):渲染选定的 LOD

加新 LOD 算法不改渲染。加新渲染技术(Vulkan / ray tracing)不改 LOD。

### 3.3 · 🐧 Linux 系统编程视角

Linux 的"决策 / 执行"分离:

- **Scheduler**(Brain):决定哪个进程跑
- **Process**(Apron):执行代码

加新调度算法(CFS → EEVDF)不改进程。加新系统调用不改调度器。

#### CFS Scheduler

Completely Fair Scheduler(Linux 默认):

- **Brain**:维护红黑树,选 vruntime 最小的进程
- **Apron**:context switch 到该进程

完全分离,调度算法可替换。

### 3.4 · 🦀 Rust 生态视角

Rust 表达 Brain + Apron:

#### 模式 1:trait + Box<dyn>(本日)

```rust
trait Brain { ... }
trait Apron { ... }

struct Monster {
    brain: Box<dyn Brain>,
    apron: Box<dyn Apron>,
}
```

灵活,但 dynamic dispatch 有性能开销。

#### 模式 2:enum

```rust
enum BrainKind { Aggressive, Coward, Patrol }
enum ApronKind { Melee, Ranged, Magic }

impl BrainKind {
    fn decide(&self, ctx) -> Action { ... }
}

struct Monster {
    brain: BrainKind,
    apron: ApronKind,
}
```

无 dynamic dispatch,但加新类型要改 enum。

#### 模式 3:ECS Component

```rust
#[derive(Component)]
struct BrainComponent(BrainKind);

#[derive(Component)]
struct ApronComponent(ApronKind);
```

Bevy ECS 风格。完全解耦,大型项目用。

#### 模式 4:宏生成

```rust
define_brain! {
    Aggressive => |ctx| { ... },
    Coward => |ctx| { ... },
}
```

减少样板。但宏复杂。

**Casey 选择**:模式 1(trait)。HH 性能不紧张,dynamic dispatch 可接受。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Brain 和 Apron 应该分开,而不是一个 trait `fn think_and_act()`?

**参考解答**:

1. **复用**:4 Brain × 4 Apron = 16 组合,只写 8 个 struct。合并写法要 16 个
2. **职责单一**:Brain 专注决策,Apron 专注执行,各自测试容易
3. **独立演化**:加新决策不改执行,反之亦然(Open-Closed)

```rust
#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn sub(self, o: Self) -> Self { Self::new(self.x-o.x, self.y-o.y, self.z-o.z) }
    fn add(self, o: Self) -> Self { Self::new(self.x+o.x, self.y+o.y, self.z+o.z) }
    fn scale(self, k: f32) -> Self { Self::new(self.x*k, self.y*k, self.z*k) }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
    fn length(self) -> f32 { self.dot(self).sqrt() }
    fn normalized(self) -> Self {
        let l = self.length();
        if l > 1e-9 { self.scale(1.0/l) } else { Self::new(0.0, 0.0, 0.0) }
    }
}

#[derive(Clone, Debug)]
enum Action { Idle, MoveTo(Vec3), Attack, Flee }

struct Context {
    player_pos: Vec3,
    self_pos: Vec3,
    self_hp: f32,
}

trait Brain {
    fn decide(&self, ctx: &Context) -> Action;
}

trait Apron {
    fn execute(&mut self, action: Action, ctx: &Context, dt: f32) -> (Vec3, f32);  // 返回 (新位置, 玩家伤害)
}

struct AggressiveBrain;
impl Brain for AggressiveBrain {
    fn decide(&self, ctx: &Context) -> Action {
        let to_player = ctx.player_pos.sub(ctx.self_pos);
        let dist = to_player.length();
        if dist < 2.0 { Action::Attack }
        else if dist < 10.0 { Action::MoveTo(ctx.player_pos) }
        else { Action::Idle }
    }
}

struct CowardBrain;
impl Brain for CowardBrain {
    fn decide(&self, ctx: &Context) -> Action {
        let dist = ctx.player_pos.sub(ctx.self_pos).length();
        if dist < 8.0 { Action::Flee }
        else { Action::Idle }
    }
}

struct MeleeApron { cooldown: f32 }
impl Apron for MeleeApron {
    fn execute(&mut self, action: Action, ctx: &Context, dt: f32) -> (Vec3, f32) {
        self.cooldown -= dt;
        match action {
            Action::MoveTo(target) => {
                let dir = target.sub(ctx.self_pos).normalized();
                (ctx.self_pos.add(dir.scale(5.0 * dt)), 0.0)
            }
            Action::Attack => {
                if self.cooldown <= 0.0 {
                    self.cooldown = 1.0;
                    (ctx.self_pos, 10.0)
                } else { (ctx.self_pos, 0.0) }
            }
            Action::Flee => {
                let away = ctx.self_pos.sub(ctx.player_pos).normalized();
                (ctx.self_pos.add(away.scale(5.0 * dt)), 0.0)
            }
            _ => (ctx.self_pos, 0.0)
        }
    }
}

struct RangedApron { cooldown: f32 }
impl Apron for RangedApron {
    fn execute(&mut self, action: Action, ctx: &Context, dt: f32) -> (Vec3, f32) {
        self.cooldown -= dt;
        match action {
            Action::Flee => {
                let away = ctx.self_pos.sub(ctx.player_pos).normalized();
                if self.cooldown <= 0.0 {
                    self.cooldown = 2.0;
                    (ctx.self_pos.add(away.scale(5.0 * dt)), 5.0)
                } else {
                    (ctx.self_pos.add(away.scale(5.0 * dt)), 0.0)
                }
            }
            Action::Attack => {
                if self.cooldown <= 0.0 {
                    self.cooldown = 2.0;
                    (ctx.self_pos, 5.0)
                } else { (ctx.self_pos, 0.0) }
            }
            _ => (ctx.self_pos, 0.0)
        }
    }
}

struct Monster {
    pos: Vec3,
    hp: f32,
    brain: Box<dyn Brain>,
    apron: Box<dyn Apron>,
}

impl Monster {
    fn update(&mut self, player_pos: Vec3, dt: f32) -> f32 {
        let ctx = Context {
            player_pos,
            self_pos: self.pos,
            self_hp: self.hp,
        };
        let action = self.brain.decide(&ctx);
        let (new_pos, damage) = self.apron.execute(action, &ctx, dt);
        self.pos = new_pos;
        damage
    }
}

fn main() {

    let dt = 0.5;

    let mut monsters = [

            pos: Vec3::new(5.0, 0.0, 0.0),
            hp: 100.0,
            brain: Box::new(AggressiveBrain),
            apron: Box::new(MeleeApron { cooldown: 0.0 }),
        }),
        ("Coward Archer", Monster {
            pos: Vec3::new(5.0, 0.0, 0.0),
            hp: 60.0,
            brain: Box::new(CowardBrain),
            apron: Box::new(RangedApron { cooldown: 0.0 }),
        }),
    ];

    for step in 0..6 {
        println!("\n=== Step {} ===", step);
        for (name, monster) in monsters.iter_mut() {
            let damage = monster.update(player_pos, dt);
            let dist = monster.pos.sub(player_pos).length();
            println!("{}: pos=({:.2},{:.2},{:.2}) dist={:.2} damage={}", name, monster.pos.x, monster.pos.y, monster.pos.z, dist, damage);
        }
    }
}
```

## 附录 · Brain + Apron 与 SOLID 原则

Day 628 的设计完美体现 SOLID 五原则:

### S - Single Responsibility(单一职责)

- **Brain** 只负责决策
- **Apron** 只负责执行

每个 trait 一个职责,代码清晰。

### O - Open-Closed(开闭)

- 加新 Brain(开)不改老 Brain(闭)
- 加新 Apron(开)不改老 Apron(闭)
- 加新组合不改组件

### L - Liskov Substitution(里氏替换)

- 任何 `Box<dyn Brain>` 都能替换成另一个 Brain
- AggressiveBrain 替换 CowardBrain,Monster 行为变化但不崩溃

### I - Interface Segregation(接口隔离)

- Brain 和 Apron 是独立 trait,不强迫一个对象同时实现
- 不会出现"我只需要决策但被迫也实现执行"的问题

### D - Dependency Inversion(依赖倒置)

- Monster 依赖 `Brain` trait,不依赖具体 `AggressiveBrain`
- 高层(Monster)不依赖低层(AggressiveBrain),都依赖抽象(trait)

**Brain + Apron 是 SOLID 的教科书案例**。

### 与 ECS 的对比

ECS(Entity-Component-System)是另一个游戏架构:

- Entity:ID
- Component:数据(Position, HP, Brain)
- System:逻辑(MovementSystem, CombatSystem)

Brain + Apron 是 OOP 风格,ECS 是 DOD(Data-Oriented Design)风格。

**对比**:

| 维度 | Brain + Apron(OOP) | ECS(DOD) |
|---|---|---|
| 抽象 | 接口 | 数据 + system |
| 性能 | 中(dynamic dispatch) | 高(cache-friendly) |
| 灵活度 | 中 | 高 |
| 复杂度 | 中 | 高 |

**HH 选 Brain + Apron**(OOP),因为简单且性能可接受。大型项目选 ECS(性能 + 灵活)。

### 何时该用 Brain + Apron

- 中小项目(几百实体):OOP 足够
- 教学项目:OOP 概念清晰
- 单人 / 小团队:OOP 实现简单

### 何时该用 ECS

- 大型项目(几千实体):ECS cache-friendly
- 团队项目:ECS 易并行
- 性能敏感:ECS 数据布局优化

### HH 的演进路径

Casey 在 Phase 2-7 用 OOP 风格(`struct Monster { ... }` + `impl Monster`)。Phase 8 引入 Brain + Apron(更结构化的 OOP)。**未来 Phase 9 可能切 ECS**(如果性能需要)。

每个阶段都是工程权衡。

## 附录 II · Brain + Apron 的实战陷阱

Day 628 设计很优雅,但实战中有陷阱:

### 陷阱 1:过度抽象

新手学了 Brain + Apron,所有 NPC 都用。结果简单 NPC(只有"朝玩家走")也搞 trait + Box<dyn>。

**修复**:**简单 NPC 用直接逻辑**。Brain + Apron 适合"行为复杂、可复用"的 NPC。

```rust
// 简单 NPC:直接逻辑
fn update_simple_npc(npc: &mut NPC, player: &Player) {
    let dir = (player.pos - npc.pos).normalized();
    npc.pos += dir * npc.speed;
}

// 复杂 NPC:Brain + Apron
fn update_complex_npc(npc: &mut Monster, ...) {
    let action = npc.brain.decide(...);
    npc.apron.execute(action, ...);
}
```

**判断标准**:如果 NPC 只有 1 个行为,直接逻辑;如果有 3+ 行为,Brain + Apron。

### 陷阱 2:Box<dyn> 性能

`Box<dyn Brain>` 是 dynamic dispatch,每次调用查 vtable。在 1000 NPC × 60 FPS 下,~60K 次/秒。

**测试**:

```rust
let monsters: Vec<Box<dyn Brain>> = ...;
for m in &monsters {
    m.decide(&ctx);  // dynamic dispatch
}
```

性能 ~5-10ns/次,通常可接受。但 hot path 上 100 万次时,~5-10ms。

**修复**:

- 改成 enum(无 dynamic dispatch)
- 用 ECS(数据连续,cache-friendly)
- 内联关键 trait method

### 陷阱 3:Context 太大

`Context` 包含 Brain 需要的所有信息。如果 Brain 需要很多信息,Context 很大,每次拷贝慢。

**修复**:

```rust
struct Context<'a> {
    world: &'a World,  // 用引用,不拷贝
    player: &'a Player,
    // ...
}
```

用引用 + lifetime,零拷贝。

### 陷阱 4:状态共享

Brain 决策需要"全局状态"(如所有怪物位置),Context 怎么提供?

**修复**:Context 包含 `&World`,Brain 通过 `world` 查全局状态。

### 陷阱 5:并发

多线程 update 1000 NPC,每个 NPC 有 Box<dyn Brain>,共享 World。怎么并发?

**修复**:

- 用 rayon(数据并行)
- 每个 NPC update 独立(无共享状态)
- World 用 `&World`(immutable),修改用 command buffer

```rust
monsters.par_iter_mut().for_each(|m| {
    let action = m.brain.decide(&ctx);
    let cmd = m.apron.execute(action, &ctx, dt);  // 返回命令,不直接改 World
    commands.push(cmd);  // 收集命令
});
// 串行 apply commands
for cmd in commands {
    world.apply(cmd);
}
```

### 陷阱 6:测试困难

Box<dyn Brain> 难 mock。怎么测试?

**修复**:

```rust
#[cfg(test)]
struct MockBrain { action: Action }
impl Brain for MockBrain {
    fn decide(&self, _: &Context) -> Action { self.action.clone() }
}

#[test]
fn test_melee_apron_attacks() {
    let brain = MockBrain { action: Action::Attack };
    let mut apron = MeleeApron { cooldown: 0.0 };
    let ctx = Context { ... };
    let (_, damage) = apron.execute(Action::Attack, &ctx, 0.1);
    assert_eq!(damage, 10.0);
}
```

用 Mock 替换 Brain,只测 Apron。反之亦然。**单测解耦的关键**。
