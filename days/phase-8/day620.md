
# Day 620 · 世界生成器中的资产标签

> Day 619 把游戏代码里的硬编码 ID 改成 tag 查找。今天 Casey 把改造延伸到**世界生成器**——程序化生成关卡时,生成器从一堆候选资产里随机选一个(例如生成"石头墙"时,从所有 `wall + stone` 标签的精灵里随机选)。这让程序化生成的关卡有**视觉多样性**,而不是每面墙都一样。

## 0 · 为什么要有这一天

HH 的世界生成器在 Phase 2-7 不断演进:从硬编码 tile,到 noise 生成,到房间 + 走廊,再到 dungeon algorithm。但生成的关卡有个问题:**视觉单调**。例如:

- 所有"石头墙"tile 用同一个精灵
- 所有"草地"tile 用同一个精灵
- 关卡看起来像"贴纸墙",没有真实世界的纹理变化

真实世界的石头墙不是每块石头都一样——有的有裂纹,有的颜色深,有的长青苔。**程序化生成的关卡应该有这种多样性**。

今天的方案:**资产标签 + 多候选**。生成器不再问"给我石头墙精灵",而是问"给我所有标签为 `wall + stone` 的精灵",然后**随机选一个**。每个 tile 独立选,自然产生纹理变化。

**今天的核心概念**:**程序化多样性**(procedural variety)。这是程序化生成(procedural generation)的核心——**用规则 + 随机性产生看起来手工设计的场景**。

**心理锚点**:看完这集,你能:
- 实现一个"按 tag 集合查找多个候选"的 API
- 用随机选择产生程序化多样性
- 解释为什么多样性让游戏世界更可信

## 1 · Casey 今天做了什么

Casey 这一天的具体动作:

1. **扩展 AssetStore**:`get_all_with_tag(tag) -> Vec<AssetId>`,返回所有匹配 tag 的资产
2. **修改世界生成器**:每个 tile 生成时调用 `get_all_with_tag`,随机选一个
3. **加更多资产**:为每种 tile 加 3-4 个变体(如 4 种石头墙精灵,3 种草地精灵)

5. **加 seeded RNG**:用 seed 控制随机,可重现同样的关卡

## 2 · 心智模型

### 类比:街边咖啡馆的菜单

你去街边咖啡馆,菜单写"咖啡 - $5"。你点了一杯,可能是:
- 小杯
- 中杯
- 大杯
- 不同豆子
- 不同糖度

每杯咖啡不一样,但都叫"咖啡"。这就是**菜单多样性**——同一个语义("咖啡")对应多个具体实例。

游戏资产完全一样:

- "石头墙"这个 tag 对应 4 个精灵变体
- 生成器选哪个变体,产生不同视觉

### 严谨:多候选资产系统

#### 2.1 扩展 AssetStore

```rust
impl AssetStore {
    /// 返回所有匹配 tag 的资产 ID
    fn get_all_with_tag(&self, tag: &str) -> Vec<AssetId> {
        let h = fnv1a(tag);
        // 注意:现在需要"反向查找":hash → 所有匹配的 ID
        // 一个 hash 可能对应多个 ID(因为是 tag,不是唯一 key)
        // 设计:by_hash 改成 HashMap<u64, Vec<AssetId>>
        self.by_hash.get(&h).cloned().unwrap_or_default()
    }

    /// 随机选一个
    fn get_random_with_tag(&self, tag: &str, rng: &mut Rng) -> Option<AssetId> {
        let candidates = self.get_all_with_tag(tag);
        if candidates.is_empty() { None }
        else {
            let idx = rng.gen_range(0..candidates.len());
            Some(candidates[idx])
        }
    }
}
```

**关键变化**:
- 之前:`HashMap<u64, AssetId>`(单值)
- 现在:`HashMap<u64, Vec<AssetId>>`(多值)
- 新 API:`get_all_with_tag` 返回 Vec,`get_random_with_tag` 随机选一个

#### 2.2 tag 集合查询

更强大的 API:支持复合 tag 查询。例如查"所有 wall + stone"资产:

```rust
fn get_with_tags(&self, tags: &[&str]) -> Vec<AssetId> {
    // 每个资产有 tag 集合(如 {"wall", "stone", "outdoor"})
    // 查询 tags ⊆ 资产 tags 的所有资产
    let tag_hashes: Vec<u64> = tags.iter().map(|t| fnv1a(t)).collect();
    self.assets.iter()
        .filter(|(_, asset_tags)| {
            tag_hashes.iter().all(|th| asset_tags.contains(th))
        })
        .map(|(id, _)| *id)
        .collect()
}
```

这是 SQL `WHERE tag IN (...) AND tag IN (...)` 的内存版本。

#### 2.3 资产元数据

每个资产现在有一组 tags:

```rust
struct Asset {
    id: AssetId,
    sprite_data: SpriteData,
    tags: Vec<u64>,  // FNV hash of tag strings
}

struct AssetStore {
    assets: HashMap<AssetId, Asset>,
    by_tag: HashMap<u64, Vec<AssetId>>,  // tag hash → asset IDs
}
```

**注册**:

```rust
fn register(&mut self, tags: &[&str], sprite: SpriteData) -> AssetId {
    let id = self.next_id;
    self.next_id += 1;
    let tag_hashes: Vec<u64> = tags.iter().map(|t| fnv1a(t)).collect();
    let asset = Asset { id, sprite_data: sprite, tags: tag_hashes.clone() };
    self.assets.insert(id, asset);
    for th in tag_hashes {
        self.by_tag.entry(th).or_default().push(id);
    }
    id
}
```

#### 2.4 随机选 + seed

```rust
use rand::{Rng, SeedableRng};
use rand::rngs::StdRng;

struct WorldGenerator {
    rng: StdRng,
}

impl WorldGenerator {
    fn new(seed: u64) -> Self {
        Self { rng: StdRng::seed_from_u64(seed) }
    }

    fn gen_tile(&mut self, assets: &AssetStore, x: i32, y: i32) -> Tile {
        let tag = if x % 5 == 0 { "wall_stone" } else { "floor_stone" };
        let sprite_id = assets.get_random_with_tag(tag, &mut self.rng)
            .expect("missing tag");
        Tile { x, y, sprite_id }
    }
}
```

**关键点**:
- `StdRng::seed_from_u64(seed)` — 用 seed 初始化 RNG,可重现
- 同 seed 总生成同关卡,便于调试和分享
- 不同 seed 生成不同关卡,玩家每次玩新关卡

#### 2.5 完整世界生成

```rust
fn generate_world(assets: &AssetStore, seed: u64, w: usize, h: usize) -> World {
    let mut gen = WorldGenerator::new(seed);
    let mut tiles = Vec::with_capacity(w * h);

    for y in 0..h {
        for x in 0..w {
            // 简单规则:边缘是墙,内部是地板
            let tag = if x == 0 || y == 0 || x == w-1 || y == h-1 {
                "wall_stone"
            } else {
                "floor_stone"
            };
            let sprite_id = assets.get_random_with_tag(tag, &mut gen.rng).unwrap();
            tiles.push(Tile { x: x as i32, y: y as i32, sprite_id });
        }
    }
    World { tiles, width: w, height: h }
}
```

每个 tile 独立随机选,产生纹理多样性。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

程序化多样性是程序化生成(procedural generation)的核心。常见应用:

1. **Spelunky**:每个关卡随机生成,玩家每次玩不一样
2. **Minecraft**:地形 procedural,每个 seed 不同
3. **Diablo**:`dungeon` 是程序化生成,玩家反复刷
4. **No Man's Sky**:整个宇宙 procedural,有 10^18 颗星球
5. **HH(本日)**:tile 视觉多样性

**关键概念**:

- **Seed**:随机数生成器种子。同 seed 同结果
- **RNG**:随机数生成器,如 LCG、Mersenne Twister、PCG
- **Distribution**:分布,如均匀分布、高斯分布
- **Constraint**:约束,如"不能两个 wall 相邻"

**坑**:

- **过多随机性 → 杂乱**:每个 tile 完全独立随机会看起来杂乱无章。解决:加 coherence(同区域倾向同变体)
- **过少随机性 → 单调**:所有 tile 一样。解决:本日的方法,多候选随机
- **不可重现**:不加 seed,每次运行关卡不同,bug 难复现。解决:固定 seed 调试

### 3.2 · 🎨 图形学视角

程序化多样性在图形学里有几个变种:

1. **Texture variation**(本日):同 tag 多个 sprite
2. **Geometry variation**:同模型多个 mesh LOD
3. **Material variation**:同 material 多个纹理变体
4. **Color variation**:同材质用不同 tint
5. **Wear & tear**:同物体不同破损程度

**工业实现**:

- **Substance Designer**:程序化生成纹理,可输出多个变体
- **Houdini**:程序化生成场景,大量变体
- **SpeedTree**:程序化树,每棵不一样
- **World Creator**:程序化地形

这些工具核心思想相同:**用规则 + 随机产生无限变体**,但每个变体看起来"自然"。

### 3.3 · 🐧 Linux 系统编程视角

Linux 也用"程序化生成"思想:

1. **`/dev/urandom`**:内核 entropy pool + DRNG,生成随机数
2. **`uuidgen`**:程序化生成 UUID
3. **`mktemp`**:程序化生成临时文件名
4. **systemd unit name**:动态生成的服务名

**RNG 实现**:

```bash
# Linux 内核 RNG
cat /dev/urandom | head -c 8 | xxd
# 输出 8 字节随机数

# 用户态 getrandom(2)
python3 -c "import os; print(os.urandom(8).hex())"

# Rust 的 rand crate 用 getrandom(2)
```

`getrandom(2)` 是 Linux 3.17+ 的系统调用,从内核 entropy pool 读随机字节。比 `/dev/urandom` 安全(避免 fd 耗尽)。

### 3.4 · 🦀 Rust 生态视角

Rust 的随机数生态:

| Crate | 特点 | 用途 |
|---|---|---|
| `rand` | 标准 RNG 框架 | 通用 |
| `rand_chacha` | ChaCha20 RNG | 密码学安全 |
| `pcg` | PCG family | 高质量 + 快 |
| `smallrng` | 小状态 RNG | 嵌入式 |
| `tinyrand` | 极小 RNG | 极端资源限制 |

**Cargo.toml**:

```toml
[dependencies]
rand = "0.8"

```

**代码**:

```rust
use rand::SeedableRng;
use rand_pcg::Pcg64;

let mut rng = Pcg64::seed_from_u64(42);

```

PCG family 是 2014 年提出的高质量 RNG,状态小(16 或 32 字节)、周期长、统计性质好。比 Mersenne Twister 更适合游戏。

**HH 的选择**:Casey 不用 crate,自己写 LCG(线性同余生成器)。代码 5 行:

```rust
struct Lcg(u64);
impl Lcg {
    fn next(&mut self) -> u64 {
        self.0 = self.0.wrapping_mul(6364136223846793005).wrapping_add(1442695040888963407);
        self.0
    }
}
```

Knuth 推荐的常数,统计性质足够。**够用就是最好**。

### Lv2 · 动手实践

**题**:实现一个完整的世界生成器,要求:
- 多候选资产:每种 tile 有 3 个 sprite 变体
- seeded RNG:同 seed 同关卡
- 渲染:用 ASCII 表示,不同变体用 `1/2/3` 区分

完成标准:`cargo run -- --seed 42` 多次运行,输出一致;换 seed 输出不同。

**参考解答**:

```rust
use std::collections::HashMap;
use std::env;

const FNV_OFFSET: u64 = 0xcbf29ce484222325;
const FNV_PRIME: u64 = 0x100000001b3;

fn fnv1a(s: &str) -> u64 {
    let mut h = FNV_OFFSET;
    for b in s.bytes() {
        h ^= b as u64;
        h = h.wrapping_mul(FNV_PRIME);
    }
    h
}

// 简单 LCG
struct Lcg(u64);
impl Lcg {
    fn new(seed: u64) -> Self { Self(seed) }
    fn next_u32(&mut self) -> u32 {
        self.0 = self.0.wrapping_mul(6364136223846793005).wrapping_add(1442695040888963407);
        (self.0 >> 32) as u32
    }
    fn gen_range(&mut self, n: usize) -> usize {
        (self.next_u32() as usize) % n
    }
}

struct AssetStore {
    by_tag: HashMap<u64, Vec<u32>>,
}

impl AssetStore {
    fn new() -> Self { Self { by_tag: HashMap::new() } }
    fn register(&mut self, tag: &str, id: u32) {
        let h = fnv1a(tag);
        self.by_tag.entry(h).or_default().push(id);
    }
    fn get_random(&self, tag: &str, rng: &mut Lcg) -> u32 {
        let h = fnv1a(tag);
        let candidates = self.by_tag.get(&h).expect("missing tag");
        candidates[rng.gen_range(candidates.len())]
    }
}

fn main() {
    let seed: u64 = env::args().nth(1)
        .and_then(|s| s.strip_prefix("--seed=").map(|x| x.parse().unwrap()))
        .unwrap_or(42);

    let mut assets = AssetStore::new();
    // 每种 tile 3 个变体
    for i in 0..3 {
        assets.register("wall_stone", 100 + i);
        assets.register("floor_stone", 200 + i);
    }

    let mut rng = Lcg::new(seed);
    let w = 20;
    let h = 10;

    for y in 0..h {
        for x in 0..w {
            let tag = if x == 0 || y == 0 || x == w-1 || y == h-1 {
                "wall_stone"
            } else {
                "floor_stone"
            };
            let id = assets.get_random(tag, &mut rng);
            // 把 ID 转成 1/2/3(变体编号)
            let variant = (id % 10) + 1;
            print!("{}", variant);
        }
        println!();
    }
}
```

**预期**:
- 同 seed 多次运行,输出完全一致
- 边缘是 1/2/3 随机(墙变体),内部也是 1/2/3 随机(地板变体)
- 不同 seed 输出不同

## 8 · Rust / Arch 落地代码

### 完整可跑的世界生成器

```rust
// Cargo.toml: 空

use std::collections::HashMap;
use std::env;
use std::time::Instant;

const FNV_OFFSET: u64 = 0xcbf29ce484222325;
const FNV_PRIME: u64 = 0x100000001b3;

#[inline]
fn fnv1a(s: &str) -> u64 {
    let mut h = FNV_OFFSET;
    for b in s.bytes() {
        h ^= b as u64;
        h = h.wrapping_mul(FNV_PRIME);
    }
    h
}

struct Lcg(u64);
impl Lcg {
    fn new(seed: u64) -> Self { Self(seed.max(1)) }  // seed 0 会让 LCG 退化,确保 >= 1
    fn next_u32(&mut self) -> u32 {
        // Knuth MMIX 推荐常数
        self.0 = self.0.wrapping_mul(6364136223846793005).wrapping_add(1442695040888963407);
        (self.0 >> 32) as u32
    }
    fn gen_range(&mut self, n: usize) -> usize {
        if n == 0 { 0 } else { (self.next_u32() as usize) % n }
    }
}

struct AssetStore {
    by_tag: HashMap<u64, Vec<u32>>,
}

impl AssetStore {
    fn new() -> Self { Self { by_tag: HashMap::new() } }
    fn register(&mut self, tag: &str, id: u32) {
        let h = fnv1a(tag);
        self.by_tag.entry(h).or_default().push(id);
    }
    #[inline]
    fn get_random(&self, tag: &str, rng: &mut Lcg) -> Option<u32> {
        let h = fnv1a(tag);
        let candidates = self.by_tag.get(&h)?;
        Some(candidates[rng.gen_range(candidates.len())])
    }
}

fn main() {
    let seed: u64 = env::args()
        .find_map(|s| s.strip_prefix("--seed=").and_then(|x| x.parse().ok()))
        .unwrap_or(42);

    let mut assets = AssetStore::new();
    // 注册多种 tile 变体
    for i in 0..4 {
        assets.register("wall_stone", 100 + i);
    }
    for i in 0..3 {
        assets.register("floor_stone", 200 + i);
    }
    for i in 0..2 {
        assets.register("door_wood", 300 + i);
    }

    let mut rng = Lcg::new(seed);
    let w = 30;
    let h = 15;

    println!("=== World (seed={}) ===", seed);
    for y in 0..h {
        for x in 0..w {
            let tag = if x == 0 || y == 0 || x == w-1 || y == h-1 {
                "wall_stone"
            } else if (x + y*7) % 23 == 5 {
                "door_wood"
            } else {
                "floor_stone"
            };
            let id = assets.get_random(tag, &mut rng).unwrap_or(0);
            let variant = (id % 10) + 1;
            let c = match tag {
                "wall_stone" => char::from_digit(variant, 10).unwrap(),
                "floor_wood" => '.',
                "door_wood" => '+',
                _ => {
                    print!("{}", variant);
                    continue;
                }
            };
            print!("{}", c);
        }
        println!();
    }

    // 验证可重现性
    let t0 = Instant::now();
    let mut rng1 = Lcg::new(seed);
    let seq1: Vec<u32> = (0..1000).map(|_| rng1.next_u32()).collect();
    let mut rng2 = Lcg::new(seed);
    let seq2: Vec<u32> = (0..1000).map(|_| rng2.next_u32()).collect();
    assert_eq!(seq1, seq2);
    println!("\nReproducibility: OK ({:?})", t0.elapsed());
}
```

## 附录 · 程序化生成的"三难困境"

程序化生成有一个著名的"三难"(类似项目管理的"快/便宜/好"):

1. **多样性**(variety):生成的关卡每次不一样
2. **可控性**(control):设计师能控制某些方面(如难度、风格)
3. **质量**(quality):生成结果好看、好玩、有逻辑

**三难**:

- 多样性 + 质量(无控制):随机生成出杂乱关卡
- 多样性 + 控制(无质量):规则死板,生成结果无聊
- 控制 + 质量(无多样性):手工设计,本质不是 procedural

**HH 的位置**:Day 620 的"按 tag 随机"偏向多样性 + 部分控制(tag 限定 = 控制),但质量取决于资产本身。如果资产好看(美术做好),生成结果好看。

### 程序化生成的"谱"

从纯随机到纯设计:

```
纯随机 → noise → tile-based → grammar → wave function collapse → 纯设计
```

- **纯随机**:每 tile 独立,杂乱
- **Noise**(Perlin/Simplex):有 coherence,但缺少"游戏逻辑"
- **Tile-based**(本日):tile 集合 + 规则,适合 dungeon
- **Grammar**(L-system):形式文法,适合树/植物
- **WFC**(Wave Function Collapse):约束传播,适合复杂场景
- **纯设计**:手工,质量高但成本高

**HH 的演进**:Phase 2 用 tile-based,Phase 8 加随机变体(本日),未来可能用 WFC 做 dungeon。

### 程序化生成的"陷阱"

新手常踩:

1. **过度随机**:每个像素独立随机 → 噪点。解决:加 coherence(perlin noise、Markov chain)
2. **过度规则**:每个房间必须 5x5 → 死板。解决:加随机变化(尺寸 ±2)
3. **不一致**:同 seed 不同平台结果不同。解决:用确定性 RNG(LCG),不用系统时间
4. **难复现 bug**:bug 出现在特定 seed,但代码改了无法重现。解决:种子管理 + 版本控制

### 程序化生成的"未来趋势"

- **ML 辅助生成**:用 GAN/Transformer 生成关卡,设计师做微调
- **Player-adaptive**:根据玩家行为调整生成(玩家强 → 怪多)
- **Community-driven**:玩家分享 seed,形成 meta-game(Spelunky 是典范)

### 今天的认知收获

完成 Day 620,你应该理解:

- **多样性 + 可控性是程序化生成的核心**:tag 限定 + RNG 随机是基础组合
- **seed 是程序化生成的灵魂**:同 seed 同结果,可重现 + 可分享
- **资产和生成器解耦**:资产加变体不改生成器代码
- **程序化生成不是"自动化设计"**:是"用规则 + 随机辅助设计师"

带着这些认知,你后面看任何 procedural content 生成,都能问出**正确的问题**:
- 有 seed 吗?可重现吗?
- 多样性来源是 RNG、noise 还是 grammar?
- 设计师能控制什么?不能控制什么?

这些问题,day620 之前你不会问。day620 之后,它们成为你的本能。

## 附录 II · Noise-based 多样性(进阶)

Day 620 用"RNG + tag"产生多样性,但每个 tile 完全独立——选 1 号变体和选 2 号变体无关。这会让世界看起来"杂乱"——同一片区域里墙的变体完全随机。

**改进**:用 **noise-based coherence**——相邻 tile 倾向同变体。

### Perlin Noise 基础

Perlin noise(Ken Perlin, 1985,获得奥斯卡技术奖)是一种**连续随机函数**:

- 输入:任意维度的坐标(如 `(x, y)`)
- 输出:`-1 到 1` 之间的浮点
- 性质:**相邻输入 → 相似输出**(coherent),远距离输入 → 无关输出

### 用 Perlin 选变体

```rust
fn gen_tile_with_noise(assets: &AssetStore, seed: u64, x: i32, y: i32, tag: &str) -> u32 {
    let candidates = assets.get_all_with_tag(tag);
    let n = candidates.len();
    if n == 0 { panic!("missing tag"); }

    // 用 Perlin noise 决定选哪个变体
    let noise = perlin2(seed, x as f32 * 0.1, y as f32 * 0.1);  // -1 到 1
    let normalized = (noise + 1.0) * 0.5;  // 0 到 1
    let idx = (normalized * n as f32) as usize % n;
    candidates[idx]
}
```

效果:相邻 tile(x, y 和 x+1, y)的 noise 值相近,选的变体相近。**视觉上形成"区域"**:一片区域是变体 1,过渡到另一片是变体 2,过渡到变体 3。看起来更像"自然磨损"。

### Perlin vs RNG 的差异

| 维度 | 纯 RNG | Perlin |
|---|---|---|
| Tile 独立性 | 完全独立 | 相邻相关 |
| 视觉效果 | 杂乱 | 有"区域感" |
| 控制参数 | 仅 seed | seed + scale(频率) |
| 算法复杂度 | O(1) | O(1) 但常数大 |

Casey 在 Day 620 用纯 RNG。**未来 Day 可能加 Perlin**(如果视觉杂乱成问题)。

### Simplex Noise(Perlin 的改进)

Perlin noise 在 2001 年被 Ken Perlin 自己改进为 **Simplex noise**:

- 更快(O(N) 而不是 O(2^N))
- 更少方向性伪影
- 更适合高维(N=4, 5, ...)

Simplex 是 simplex(三角形/四面体)而不是 grid(方形/立方体)。计算时把输入转到 simplex 空间。

Rust 生态:`noise-rs` crate 提供 Perlin/Simplex:

```toml
[dependencies]
noise = "0.9"
```

```rust
use noise::{NoiseFn, Perlin};

```

### 多 octave noise(fBm)

更复杂的效果用**多 octave 叠加**:

```rust
fn fbm(x: f32, y: f32, octaves: u32) -> f32 {
    let mut sum = 0.0;
    let mut amp = 1.0;
    let mut freq = 1.0;
    let mut max = 0.0;
    for _ in 0..octaves {
        sum += perlin(x * freq, y * freq) * amp;
        max += amp;
        amp *= 0.5;
        freq *= 2.0;
    }
    sum / max
}
```

每个 octave 频率翻倍、振幅减半,叠加产生"分形"(fractal)效果。这就是 minecraft 的地形生成原理。
