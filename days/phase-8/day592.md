
# Day 592 · 捕获全部光照数据

> Day 591 做了 benchmark,只测时间。但 Casey 想更深入——他想看光照计算过程中的"中间数据":每个体素每个 texel 的辐射值、每次迭代后的状态变化。这是"详细 trace"——不只测时间,还测"数据演化"。

## 0 · 为什么要有这一天

Benchmark 告诉你"光照耗时 4 ms",但不告诉你:
- 哪个体素更新最慢?
- 哪个迭代轮次耗时?
- 中间数据是否合理(没有溢出、没有 NaN)?

要回答这些,需要**捕获中间数据**。这比单纯测时间复杂——需要:
1. 在代码各处插入"探针"(probe),记录当前状态
2. 把探针数据存到磁盘,事后分析
3. 可视化数据(如时间轴、热力图)

游戏工业里这种"详细 trace"叫 **Instrumentation** 或 **Profiling with data capture**。商业工具(RenderDoc、Tracy、Optick)都做这种事。

Casey 这一天实现一个简易的 trace 系统——记录光照计算的每一步,存到文件,事后分析。

心理锚点:看完这集,你能写一个 Rust instrumentation 系统,理解"为什么只测时间不够",能在自己代码里加 trace 探针,事后分析性能。

## 1 · Casey 今天做了什么

Casey 这一天的几个动作:

1. **定义 trace 数据结构**:每个 trace event 包含时间戳、函数名、payload(如体素 idx、当前辐射值)。
2. **加探针**:在光照代码关键位置(开始 propagate、每体素更新、每迭代结束)加 `trace_event(...)` 调用。
3. **持久化**:把 trace events 序列化到 JSON 文件,事后能用工具分析。
4. **分析工具**:写一个小脚本读 JSON,打印每体素耗时、每迭代耗时。

这一天的工程产出大约 150 行 Rust 代码,价值在于**让光照计算"可观察"**——不只是黑盒测时间。

## 2 · 心智模型

### 类比:医院的心电监护

医生想了解病人心脏情况。两种方法:

**方法 1(集成测)**:看病人能不能跑 1000 米,跑完后测心率。问题:只知道"整体心脏能不能支持运动",不知道"哪个时刻心率多少"。

**方法 2(trace)**:给病人戴心电监护,24 小时记录心电波形。事后能看"哪个时刻心率高、哪个时刻异常"。

trace 完全一样——给光照代码戴"心电监护",记录每一步状态。

### 严谨原理:Trace 数据结构

**Trace event**:

```rust
struct TraceEvent {
    timestamp_ns: u64,           // 纳秒时间戳
    category: &'static str,      // 类别("lighting", "raycast", ...)
    name: &'static str,          // 事件名("propagate_indirect_start", ...)
    payload: TracePayload,       // 数据
}

enum TracePayload {
    Empty,
    VoxelIdx(usize),
    AtlasBrightness(f32),
    IterationComplete { iter: usize, max_brightness: f32 },
}
```

**Trace recorder**:

```rust
struct TraceRecorder {
    events: Vec<TraceEvent>,
    start_time: Instant,
}

impl TraceRecorder {
    fn new() -> Self {
        Self {
            events: Vec::new(),
            start_time: Instant::now(),
        }
    }
    
    fn record(&mut self, category: &'static str, name: &'static str, payload: TracePayload) {
        let timestamp_ns = self.start_time.elapsed().as_nanos() as u64;
        self.events.push(TraceEvent {
            timestamp_ns,
            category,
            name,
            payload,
        });
    }
}
```

**用法**:

```rust
fn propagate_infinite_bounces(world: &mut World, iterations: usize, recorder: &mut TraceRecorder) {
    recorder.record("lighting", "propagate_start", TracePayload::Empty);
    
    for iter in 0..iterations {
        recorder.record("lighting", "iteration_start", TracePayload::VoxelIdx(iter));
        
        for i in 0..world.voxels.len() {
            // ... propagate
            if i % 100 == 0 {
                let brightness = world.voxels[i].atlas.max_brightness();
                recorder.record("lighting", "voxel_update", TracePayload::AtlasBrightness(brightness));
            }
        }
        
        let max_b = world.atlases.iter().map(|a| a.max_brightness()).fold(0.0, f32::max);
        recorder.record("lighting", "iteration_end", 
            TracePayload::IterationComplete { iter, max_brightness: max_b });
    }
    
    recorder.record("lighting", "propagate_end", TracePayload::Empty);
}
```

**每行解释**:
- `start_time.elapsed().as_nanos()` — 从 recorder 创建到现在的纳秒数。
- `category` + `name` — 事件分类(便于过滤分析)。
- `payload` — 事件携带的数据(如当前辐射亮度,看是否 NaN / inf)。
- `i % 100 == 0` — 不要每体素都记录(否则 events 太多),每 100 个记一次。

### 持久化

```rust
impl TraceRecorder {
    fn save_to_json(&self, path: &str) -> std::io::Result<()> {
        use std::io::Write;
        let mut f = std::fs::File::create(path)?;
        writeln!(f, "[")?;
        for (i, event) in self.events.iter().enumerate() {
            let comma = if i + 1 < self.events.len() { "," } else { "" };
            writeln!(f, "  {{\"t\": {}, \"cat\": \"{}\", \"name\": \"{}\"}}{}",
                event.timestamp_ns, event.category, event.name, comma)?;
        }
        writeln!(f, "]")?;
        Ok(())
    }
}
```

**JSON 格式**便于其他工具读(Python、R、浏览器可视化)。

### 分析

写一个简单的 Python 脚本分析 trace:

```python
import json

events = json.load(open("trace.json"))

# 找 iteration_end 事件,看每轮最大亮度
iter_ends = [e for e in events if e["name"] == "iteration_end"]
print(f"Total iterations: {len(iter_ends)}")

# 找最慢的体素更新
voxel_updates = [e for e in events if e["name"] == "voxel_update"]
max_brightness = max(e["payload"]["brightness"] for e in voxel_updates)
print(f"Max brightness seen: {max_brightness}")

# 时间分析
print("\nTime per iteration:")
prev_t = 0
for e in iter_ends:
    print(f"  Iter {e['payload']['iter']}: {e['t'] - prev_t} ns")
    prev_t = e['t']
```

Linux 上 trace 的工具:

```bash

```

**4. LTTng**(Linux Trace Toolkit):

```bash
sudo lttng create my_session
sudo lttng enable-event --kernel --syscall
sudo lttng start
./your_game
sudo lttng stop
sudo lttng view
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Trace 和 Benchmark 有什么本质区别?为什么有时只用 benchmark 不够?

**参考解答**:Benchmark 测"整体性能"(耗时多少 ms),Trace 记录"详细事件流"(哪个时刻发生了什么)。Benchmark 是聚合统计(平均、p95),Trace 是事件序列。

只用 benchmark 不够的场景:
1. **性能抖动原因**:benchmark 告诉你"平均 4 ms",但有时 8 ms 偶发,为什么?需要 trace 看那一刻发生了什么
2. **正确性检查**:benchmark 只测时间,不测数据正确性。trace 可以记录每步数据,事后检查 NaN / 异常
3. **回归定位**:benchmark 告诉你"新版变慢了",不告诉你"哪行代码变慢"。trace 可以定位到函数级

struct TraceEvent {
    timestamp_ns: u64,
    name: &'static str,
}

struct TraceRecorder {
    events: Vec<TraceEvent>,
    start: Instant,
}

impl TraceRecorder {
    fn new() -> Self {
        Self { events: Vec::new(), start: Instant::now() }
    }
    
    fn record(&mut self, name: &'static str) {
        let t = self.start.elapsed().as_nanos() as u64;
        self.events.push(TraceEvent { timestamp_ns: t, name });
    }
    
    fn save_json(&self, path: &str) -> std::io::Result<()> {
        use std::io::Write;
        let mut f = std::fs::File::create(path)?;
        writeln!(f, "[")?;
        for (i, e) in self.events.iter().enumerate() {
            let comma = if i + 1 < self.events.len() { "," } else { "" };
            writeln!(f, "  {{\"t\": {}, \"name\": \"{}\"}}{}",
                e.timestamp_ns, e.name, comma)?;
        }
        writeln!(f, "]")?;
        Ok(())
    }
}

fn main() {
    let mut recorder = TraceRecorder::new();
    recorder.record("start");
    for i in 0..1000 {
        if i % 100 == 0 {
            recorder.record("milestone");
        }
        std::hint::black_box(i * i);
    }
    recorder.record("end");
    
    println!("Total events: {}", recorder.events.len());
    recorder.save_json("/tmp/trace.json").unwrap();
    println!("Saved /tmp/trace.json");
}

## 8 · Rust / Arch 落地代码

完整可跑示例:

```rust
use std::time::Instant;
use std::io::Write;

#[derive(Clone)]
struct TraceEvent {
    timestamp_ns: u64,
    category: &'static str,
    name: &'static str,
    payload: String,
}

struct TraceRecorder {
    events: Vec<TraceEvent>,
    start: Instant,
}

impl TraceRecorder {
    fn new() -> Self {
        Self { events: Vec::new(), start: Instant::now() }
    }
    
    fn record(&mut self, category: &'static str, name: &'static str) {
        self.record_with_payload(category, name, String::new());
    }
    
    fn record_with_payload(&mut self, category: &'static str, name: &'static str, payload: String) {
        let t = self.start.elapsed().as_nanos() as u64;
        self.events.push(TraceEvent {
            timestamp_ns: t,
            category,
            name,
            payload,
        });
    }
    
    fn save_json(&self, path: &str) -> std::io::Result<()> {
        let mut f = std::fs::File::create(path)?;
        writeln!(f, "[")?;
        for (i, e) in self.events.iter().enumerate() {
            let comma = if i + 1 < self.events.len() { "," } else { "" };
            let payload_json = if e.payload.is_empty() {
                String::new()
            } else {
                format!(", \"payload\": \"{}\"", e.payload)
            };
            writeln!(f, "  {{\"t\": {}, \"cat\": \"{}\", \"name\": \"{}\"{}}}{}",
                e.timestamp_ns, e.category, e.name, payload_json, comma)?;
        }
        writeln!(f, "]")?;
        Ok(())
    }
    
    fn report_categories(&self) {
        use std::collections::HashMap;
        let mut counts: HashMap<&str, usize> = HashMap::new();
        for e in &self.events {
            *counts.entry(e.name).or_insert(0) += 1;
        }
        println!("Event counts:");
        for (name, count) in counts.iter() {
            println!("  {}: {}", name, count);
        }
    }
}

fn compute_work(n: usize, recorder: &mut TraceRecorder) -> f32 {
    recorder.record("compute", "compute_start");
    let mut sum = 0.0f32;
    for i in 0..n {
        sum += (i as f32).sin();
        if i % 1000 == 0 {
            recorder.record_with_payload("compute", "milestone", format!("i={}, sum={:.4}", i, sum));
        }
    }
    recorder.record("compute", "compute_end");
    sum
}

fn main() {
    let mut recorder = TraceRecorder::new();
    recorder.record("main", "program_start");
    
    let result = compute_work(10_000, &mut recorder);
    println!("Result: {}", result);
    
    recorder.record("main", "program_end");
    
    println!("\nTotal events: {}", recorder.events.len());
    recorder.report_categories();
    
    recorder.save_json("/tmp/compute_trace.json").unwrap();
    println!("\nSaved to /tmp/compute_trace.json");
    println!("View with: python3 -m json.tool /tmp/compute_trace.json | head");
}
```

### A.3 性能优化的实际流程

工业性能优化的标准流程:

**Step 1:测量**(cargo flamegraph / perf)
- 找最慢的函数
- 不要猜,要测

**Step 2:分析**(为什么慢)
- 算法?(O(N²) vs O(N log N))
- 内存?(cache miss)
- 同步?(锁等待)
- 分支?(branch mispredict)

**Step 3:优化**(对症下药)
- 算法:换数据结构
- 内存:SoA / prefetch
- 同步:细化锁
- 分支:branchless

### A.5 Voxel lighting 的未来

学术 / 工业前沿:

**1. Real-time path tracing on RTX**:
- RTX 核心加速 voxel raycast
- 真实光传播(无简化)

**2. Neural voxel lighting**:
- 神经网络压缩 SH 数据
- 推理时光照实时算
- 研究(NeRF、Neural radiance cache)

**3. Differentiable rendering**:
- 光照对几何的偏导
- 反向传播到材质 / 几何
- 应用:材质反推、自动优化

**4. Wavelet voxel**:
- Wavelet 变换替代 SH
- 多分辨率,更适合稀疏数据
- 研究(Wavelet GVT)

这些是未来 5-10 年的方向。

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
