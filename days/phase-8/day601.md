
# Day 601 · 草拟步进表生成器

> Grid DDA 在内循环里要算 t_max 和 t_delta,这些值取决于光线方向。Casey 突然想到——能不能把"哪些格子被光穿过"预先算好?这就是"步进表"(walk table)。

## 0 · 为什么要有这一天

Grid DDA 内循环:

```rust
while t < max_dist {
    if t_max_x < t_max_y && t_max_x < t_max_z {
        cx += step_x;
        t = t_max_x;
        t_max_x += t_delta_x;
    }
    // ...
}
```

每步:
- 3 个比较(t_max_x/y/z 谁小)
- 1 个整数加(cx += step_x)
- 1 个浮点加(t_max_x += t_delta_x)
- 1 个边界检查

**问题**:对**固定方向的光**,这些计算每次都一样。能不能预先算好"光从 (0,0,0) 朝 (1,1,1) 出发,依次穿过哪些格子"?

**Walk table**:对每个方向(或方向的 bin),预计算"光线穿过的格子序列"。运行时查表,不再算 t_max。

**优势**:
- 内循环简化(查表)
- 可以 SIMD 化(8 条光线一起查表)

**劣势**:
- 表大小爆炸(所有方向?)—— 解决:bin 化,只对 16×16×16 个方向 bin 预算
- 表存哪里 —— 内存(几百 KB)

Casey 在 Day 601 草拟这个表生成器。Day 603 完整实现。

心理锚点:看完这集,你能理解"预计算"(pre-computation)的工程价值,能识别哪些计算可以预先做,能在自己写代码时主动考虑"运行时 vs 预计算"的权衡。

## 2 · 心智模型

### 类比:查表 vs 现算

你想知道 1-100 所有数的平方。

**方法 1(现算)**:每次问"X 的平方是多少",算 X * X。

**方法 2(查表)**:预先算 1-100 的平方,存到表里。问的时候直接查。

方法 1 简单,方法 2 快(查表比算快)。代价是预计算时间 + 内存。

Walk table 完全一样:对每个方向 bin,预先算"光穿过格子序列",运行时查表。

### 严谨原理:方向 bin 化

3D 方向空间无限。直接预算所有方向不可能。

**Bin 化**:把方向空间量化成离散 bin。例如:
- 球面分成 32×32 = 1024 个 bin(等距矩形或八面体编码)
- 每个 bin 代表一个方向范围
- 每个 bin 预计算"该方向光线穿过的格子序列"

bin 数 = 1024,每个 walk table 大约 64 步(Grid DDA 平均步数),所以总内存 = 1024 × 64 × 8 字节(每步 2 个 i32:cx 和 cy 变化)= 512 KB。可接受。

### Walk table 结构

```rust
struct WalkTable {
    // 每个方向 bin 对应一个 WalkStep 序列
    tables: Vec<Vec<WalkStep>>,
}

#[derive(Copy, Clone)]
struct WalkStep {
    delta_x: i8,  // -1, 0, +1(光线跨哪个轴)
    delta_y: i8,
    delta_z: i8,
    t_to_next: f32,  // 到下一步的 t 增量
}
```

**WalkStep** 表示"跨一步"——哪几个轴变(其实只一个变,因为是 Slab method),到下一步的 t 增量。

### 生成器

```rust
fn generate_walk_table(dir: Vec3, max_steps: usize) -> Vec<WalkStep> {
    let mut table = Vec::with_capacity(max_steps);
    
    // Grid DDA 模拟,记录每步
    let mut cx = 0i32;
    let mut cy = 0i32;
    let mut cz = 0i32;
    
    let dx = dir.x;
    let dy = dir.y;
    let dz = dir.z;
    
    let step_x = if dx > 0.0 { 1 } else { -1 };
    let step_y = if dy > 0.0 { 1 } else { -1 };
    let step_z = if dz > 0.0 { 1 } else { -1 };
    
    let mut t_max_x = if dx.abs() > 1e-10 { 1.0 / dx.abs() } else { f32::INFINITY };
    let mut t_max_y = if dy.abs() > 1e-10 { 1.0 / dy.abs() } else { f32::INFINITY };
    let mut t_max_z = if dz.abs() > 1e-10 { 1.0 / dz.abs() } else { f32::INFINITY };
    
    let t_delta_x = if dx.abs() > 1e-10 { 1.0 / dx.abs() } else { f32::INFINITY };
    let t_delta_y = if dy.abs() > 1e-10 { 1.0 / dy.abs() } else { f32::INFINITY };
    let t_delta_z = if dz.abs() > 1e-10 { 1.0 / dz.abs() } else { f32::INFINITY };
    
    let mut prev_t = 0.0;
    
    for _ in 0..max_steps {
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            let t = t_max_x;
            t_max_x += t_delta_x;
            table.push(WalkStep {
                delta_x: step_x as i8,
                delta_y: 0,
                delta_z: 0,
                t_to_next: t - prev_t,
            });
            prev_t = t;
        } else if t_max_y < t_max_z {
            cy += step_y;
            let t = t_max_y;
            t_max_y += t_delta_y;
            table.push(WalkStep {
                delta_x: 0,
                delta_y: step_y as i8,
                delta_z: 0,
                t_to_next: t - prev_t,
            });
            prev_t = t;
        } else {
            cz += step_z;
            let t = t_max_z;
            t_max_z += t_delta_z;
            table.push(WalkStep {
                delta_x: 0,
                delta_y: 0,
                delta_z: step_z as i8,
                t_to_next: t - prev_t,
            });
            prev_t = t;
        }
    }
    
    table
}
```

**每行解释**:
- 每个 WalkStep 记录"哪轴变 + t 增量"。
- `max_steps` 限制步数(Grid DDA 平均 50 步,设 64 安全)。
- 模拟 Grid DDA,记录每步。

### 运行时查表

```rust
fn raycast_with_walk_table(
    world: &World,
    origin: Vec3,
    table: &[WalkStep],
) -> Option<(i32, i32, i32)> {
    let mut cx = (origin.x).floor() as i32;
    let mut cy = (origin.y).floor() as i32;
    let mut cz = (origin.z).floor() as i32;
    
    let mut t = 0.0;
    
    for step in table {
        cx += step.delta_x as i32;
        cy += step.delta_y as i32;
        cz += step.delta_z as i32;
        t += step.t_to_next;
        
        if world.is_solid(cx, cy, cz) {
            return Some((cx, cy, cz));
        }
    }
    
    None
}
```

**关键**:
- 内循环只有"3 个整数加 + 1 个浮点加 + 边界检查"。比 Day 590 的 DDA 简单。
- t 用于"光距离",可后续算 hit_point。

### 用法

```rust
// 启动时:对所有方向 bin 生成 walk table
let mut tables = Vec::with_capacity(N_BINS);
for dir in all_direction_bins() {
    tables.push(generate_walk_table(dir, 64));
}

// 运行时:对每条光线
let bin_idx = direction_to_bin(ray.dir);
let table = &tables[bin_idx];
let hit = raycast_with_walk_table(world, ray.origin, table);
```

**优势**:
- 内循环极简
- 多线程 / SIMD 友好(8 条光线用同一表)

**劣势**:
- 表内存:512 KB(可接受)
- 离散化误差:方向 bin 量化,精度损失

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里"预计算"无处不在:
- **Light map**:预计算静态光照
- **Texture**:预计算像素
- **Animation**:预计算关键帧
- **Walk table / DDA table**:预计算路径

**踩过的坑**:
- **表太大**:bin 数过多,内存爆。解决:bin 数选 32×32 ~ 128×128
- **离散化误差**:bin 之间的方向"跳变"。解决:bin 内做插值
- **场景变化**:预计算数据基于固定场景,场景变化要重新预算

### 3.2 · 🎨 图形学视角

**Lookup Table (LUT)** 是图形学常用优化:
- **SH LUT**:球谐函数预算
- **BRDF LUT**:Cook-Torrance BRDF 预算
- **Color Grading LUT**:颜色校正预算
- **3D LUT**:立体颜色映射

Walk table 是 LUT 在"空间查询"上的应用。

**优劣**:
- **优**:运行时 O(1) 查表,极快
- **劣**:预计算耗时 + 内存

**适用场景**:同一方向被大量光查询(每帧几千次以上),预算成本被摊薄。

### 3.3 · 🐧 Linux 系统编程视角

这一集主要是预计算,Linux 系统调用面没什么。但**内存布局**值得一提。

Walk table 512 KB,放 L2 cache(几 MB)够。但跨 L3 / 主存就慢。

**优化**:
- 把表压缩(每步只用 4 字节,不用 16 字节)
- 用 SIMD 一次处理多个表
- 表按访问频率排(常用方向在前)

```bash
# 测 cache 命中
sudo perf stat -e cache-misses,L1-dcache-load-misses ./raytracer
```

### 3.4 · 🦀 Rust 生态视角

Rust 实现预计算表的几个细节:

**1. `lazy_static` 或 `OnceLock`**:表只生成一次。

```rust
use std::sync::OnceLock;

static WALK_TABLES: OnceLock<Vec<Vec<WalkStep>>> = OnceLock::new();

fn get_tables() -> &'static Vec<Vec<WalkStep>> {
    WALK_TABLES.get_or_init(|| {
        let mut tables = Vec::with_capacity(N_BINS);
        for dir in all_direction_bins() {
            tables.push(generate_walk_table(dir, 64));
        }
        tables
    })
}
```

**2. `Box<[T]>` 替代 `Vec<T>`**:固定大小,内存更紧凑。

```rust
let tables: Box<[Vec<WalkStep>]> = ...;
```

**3. `const generics`**:固定 bin 数。

```rust
struct WalkTable<const N: usize> {
    tables: Vec<WalkStep>,  // N 个方向,每个 K 步
}
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Walk table 的内存成本是 1024 × 64 × 8 = 512 KB。如果方向 bin 数翻倍到 4096,内存成本多少?是否仍可接受?

**参考解答**:4096 × 64 × 8 = 2 MB。仍然可接受(现代 CPU L3 cache 几 MB 到几十 MB),但跨 L3 cache line 的访问会变慢。需要测实际 cache 命中率,如果 < 80%,bin 数应该减少。

**Trade-off**:bin 多,精度高,但内存大、cache miss 多。bin 少,内存小、cache 命中高,但精度低。Casey 选 1024 是经验权衡。

struct WalkStep2D {
    delta_x: i8,
    delta_y: i8,
    t_to_next: f32,
}

fn generate_walk_table_2d(dir_x: f32, dir_y: f32, max_steps: usize) -> Vec<WalkStep2D> {
    let mut table = Vec::with_capacity(max_steps);
    
    let step_x = if dir_x > 0.0 { 1 } else { -1 };
    let step_y = if dir_y > 0.0 { 1 } else { -1 };
    
    let mut t_max_x = if dir_x.abs() > 1e-10 { 1.0 / dir_x.abs() } else { f32::INFINITY };
    let mut t_max_y = if dir_y.abs() > 1e-10 { 1.0 / dir_y.abs() } else { f32::INFINITY };
    
    let t_delta_x = t_max_x;
    let t_delta_y = t_max_y;
    
    let mut prev_t = 0.0;
    
    for _ in 0..max_steps {
        if t_max_x < t_max_y {
            let t = t_max_x;
            t_max_x += t_delta_x;
            table.push(WalkStep2D {
                delta_x: step_x as i8,
                delta_y: 0,
                t_to_next: t - prev_t,
            });
            prev_t = t;
        } else {
            let t = t_max_y;
            t_max_y += t_delta_y;
            table.push(WalkStep2D {
                delta_x: 0,
                delta_y: step_y as i8,
                t_to_next: t - prev_t,
            });
            prev_t = t;
        }
    }
    
    table
}

fn main() {
    let table = generate_walk_table_2d(1.0, 1.0, 16);
    
    println!("Walk table for direction (1, 1):");
    let mut cx = 0i32;
    let mut cy = 0i32;
    let mut t = 0.0;
    println!("  Start: ({}, {})", cx, cy);
    for (i, step) in table.iter().enumerate() {
        cx += step.delta_x as i32;
        cy += step.delta_y as i32;
        t += step.t_to_next;
        println!("  Step {:2}: ({}, {}) t={:.2}", i + 1, cx, cy, t);
    }
}

## 10 · 补充材料:Grid DDA 的工业实现细节

### A.1 Amanatides-Woo 算法

Grid DDA 的经典算法是 Amanatides & Woo 1987 论文。核心思想:每步选"最近的下一个 grid 边界",而不是固定步长。

```
当前格 (cx, cy, cz)
方向 (dx, dy, dz)
每轴的"下一个边界"参数 tMaxX, tMaxY, tMaxZ
每轴的"跨格距离"参数 tDeltaX = 1 / dx, tDeltaY = 1 / dy, tDeltaZ = 1 / dz

每步:
  找 tMaxX / tMaxY / tMaxZ 中最小的
  沿该轴跨一格
  更新该轴的 tMax += tDelta
```

Rust 实现:

```rust
fn grid_dda(start: Vec3, dir: Vec3, max_dist: f32, world: &World) -> Option<HitInfo> {
    let mut cx = start.x.floor() as i32;
    let mut cy = start.y.floor() as i32;
    let mut cz = start.z.floor() as i32;
    
    let step_x = if dir.x > 0.0 { 1 } else { -1 };
    let step_y = if dir.y > 0.0 { 1 } else { -1 };
    let step_z = if dir.z > 0.0 { 1 } else { -1 };
    
    // tMax:光线到达下一个 grid 边界的参数
    let t_max_x = if dir.x.abs() > 1e-10 {
        (((cx + if dir.x > 0 { 1 } else { 0 }) as f32) - start.x) / dir.x
    } else { f32::INFINITY };
    let t_max_y = /* 类似 */;
    let t_max_z = /* 类似 */;
    
    // tDelta:跨一格的 t 增量
    let t_delta_x = if dir.x.abs() > 1e-10 { 1.0 / dir.x.abs() } else { f32::INFINITY };
    let t_delta_y = /* 类似 */;
    let t_delta_z = /* 类似 */;
    
    let mut t = 0.0;
    while t < max_dist {
        if let Some(voxel) = world.get(cx, cy, cz) {
            if voxel.is_solid() {
                return Some(HitInfo { distance: t, voxel });
            }
        }
        
        // 跨到下一个格
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            t = t_max_x;
            t_max_x += t_delta_x;
        } else if t_max_y < t_max_z {
            cy += step_y;
            t = t_max_y;
            t_max_y += t_delta_y;
        } else {
            cz += step_z;
            t = t_max_z;
            t_max_z += t_delta_z;
        }
    }
    
    None
}
```

复杂度:O(N) where N = 光线穿过的格子数。比 brute force(检查每个 voxel)快几个量级。

### A.2 边界情况

Grid DDA 有几个边界情况要小心:

**1. 方向含 0**:`dir.x = 0` 时,光线不沿 x 轴前进,tMaxX = ∞。代码用 `if dir.x.abs() > 1e-10` 判断,避免除 0。

**2. 起点恰在格边界**:浮点比较可能误判。用 `start.x.floor()` 而不是 `start.x as i32`,前者更精确处理边界。

**3. 负方向**:`dir.x < 0` 时,光线向左走,step_x = -1。tMaxX 计算用 `cx + 0`(下一个边界是当前格的左边),不是 `cx + 1`。

**4. 起点在 solid voxel**:如果光线起点已经在墙里,立刻返回 hit(t=0)。

### A.3 性能优化

工业级 Grid DDA 的优化:

**Branchless**:用 bit hack 替代 if-else。x86 上分支预测失败代价大,branchless 消除分支。

```rust
// branchless min
let smallest_x = (t_max_x <= t_max_y) && (t_max_x <= t_max_z);
let smallest_y = !smallest_x && (t_max_y <= t_max_z);
// 用 mask 加到 cx/cy/cz
cx += smallest_x as i32 * step_x;
cy += smallest_y as i32 * step_y;
cz += (!smallest_x && !smallest_y) as i32 * step_z;
```

**SIMD**:同时处理 4 条或 8 条光线。Rust 用 `wide` crate 或 `_mm_*` intrinsics。

```rust
use wide::f32x4;

let t_max_x = f32x4::from([t1, t2, t3, t4]);  // 4 条光线的 tMaxX
// 同时算 4 条光线的下一步
```

**Coherent rays**:相邻像素的光线方向相似,跨格模式相似。一起处理减少分支。

### A.4 工业级 raycaster 对比

| 算法 | 复杂度 | 适用场景 |
|---|---|---|
| Brute force | O(V) V=voxel 数 | 小场景,极慢 |
| Grid DDA | O(N) N=穿越格数 | 均匀 voxel |
| k-d tree | O(log V) | 三角形 mesh |
| BVH | O(log V) | 通用 |
| Sphere tree | O(log V) | 球形几何 |
| SDF tracing | O(N) | GPU distance field |
| Walk table | O(1) per step | 预算加速 |

Casey 的 HH 走:Grid DDA → k-d tree → Walk table,演示了不同算法的演化。

### A.5 Walk table 的进一步解释

Walk table 是 phase-8 的"加速 trick":
- 预计算每个方向的"步序"
- 运行时查表,避免每步的 DDA 计算

但 walk table 有精度问题(Day 606-607 讨论的)。

工业替代方案:
- **DDA + ray differentials**:更精确,但更慢
- **Hardware ray tracing**:RTX / RDNA2,GPU 上极快
- **SDF tracing**:GPU shader 里实时 trace

Casey 的 walk table 是教学方案,演示"预计算加速"的思路。

Grid DDA 是 voxel raycast 的标准算法。Casey 的 phase-8 是简化版,工业实现有 SIMD、branchless、coherent rays 等优化。

**关键概念**:
- Grid DDA:每步到下一个边界
- Amanatides-Woo:经典算法
- Walk table:预算加速

### A.7 k-d tree 简介

k-d tree 是另一种 raycast 加速结构。把空间递归切分:

```
根节点 = 整个 scene
   ↓ 按 x 中位切分
左子树 / 右子树
   ↓ 按 y 中位切分
...
叶节点 = 1 个三角形 / voxel
```

Raycast:从根递归,先访问光线进入的子树。

```rust
struct KdNode {
    split_axis: Axis,  // X / Y / Z
    split_pos: f32,
    left: Box<KdNode>,
    right: Box<KdNode>,
    // 或叶节点:
    triangles: Vec<TriangleId>,
}

fn raycast(node: &KdNode, ray: &Ray) -> Option<Hit> {
    // 计算光线进入哪个子树
    let t_split = (node.split_pos - ray.origin[node.split_axis]) / ray.dir[node.split_axis];
    
    let (near, far) = if ray.origin[node.split_axis] < node.split_pos {
        (&node.left, &node.right)
    } else {
        (&node.right, &node.left)
    };
    
    if t_split >= 0.0 {
        // 先 near,后 far
        if let Some(hit) = raycast(near, ray) { return Some(hit); }
        if t_split < max_dist {
            return raycast(far, ray);
        }
    } else {
        // 只访问一边
        return raycast(near, ray);
    }
    None
}
```

k-d tree 比 Grid DDA 快几倍(更智能的剪枝),但构建慢(O(N log N))。适合静态场景(三角形 mesh)。

### A.8 BVH(Bounding Volume Hierarchy)

BVH 类似 k-d tree,但用 bounding box 而非 axis 切分:

```
根节点:整个 scene 的 AABB
   ↓ 分成两个子 AABB
左 / 右 AABB
   ↓ 继续递归
叶 AABB:包含少量三角形
```

GPU ray tracing(RTX)用 BVH。每射线测试 AABB 是否相交,相交才深入。

```rust
struct BVHNode {
    aabb: AABB,
    left: Option<Box<BVHNode>>,
    right: Option<Box<BVHNode>>,
    triangles: Vec<TriangleId>,  // 仅叶节点
}
```

NVIDIA RTX 核心(硬件)加速 BVH 遍历,每秒几亿条光线。

### A.9 SDF tracing(distance field)

SDF tracing 是 GPU 渲染的方案:

```glsl
// Fragment shader
float dist = 0.0;
vec3 pos = camera_pos;
for (int i = 0; i < MAX_STEPS; i++) {
    float d = sdf_texture(pos);  // 查 SDF 纹理
    if (d < 0.01) {  // 命中
        return shade(pos);
    }
    pos += dir * d;  // 前进 d 距离
    dist += d;
    if (dist > max_dist) break;
}
return background;
```

SDF:每点的"到最近表面的距离"。预计算每 voxel 的 SDF,存到 3D 纹理。

SDF tracing 极快(每步前进距离 = SDF,不像 Grid DDA 每步一格)。Sebastian McKenzie 的 Slisesix / Shadertoy demo 经典。

工业应用:Sebastian Beardsley 的"clay book"、Demoutil GPU raymarching。

### A.10 总结

不同 raycast 算法有不同 trade-off:
- **Grid DDA**:简单,适合 voxel
- **k-d tree**:静态 mesh,剪枝强
- **BVH**:GPU RTX 标配
- **SDF tracing**:GPU shader 实时
- **Walk table**:CPU 预算加速

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
