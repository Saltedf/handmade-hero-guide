## 2 · 心智模型

### 类比:不同衣柜整理方案

你的衣服很多。两种整理方案:

**方案 1(精细分类)**:每件衣服按"季节 + 颜色 + 类型"分到不同抽屉。找衣服快(直接打开对应抽屉)。但整理慢(每件衣服要分到正确抽屉)。

**方案 2(简单按颜色)**:每件衣服按"颜色"分到 5 个抽屉。找衣服稍慢(打开抽屉后还要翻)。但整理快(只要选 5 个之一)。

衣服少时,方案 1 和方案 2 差不多。衣服多时,方案 1 找得快但整理久。

k-d tree = 方案 1(精细)。Grid DDA = 方案 2(简单)。哪个好取决于"衣服数量"和"找衣服频率"。

### 严谨原理:体素网格 raycast

每个体素格是 1m³。光穿过场景,DDA 逐格扫。每格检查"是否有墙":

```rust
fn voxel_raycast(world: &World, ray: &Ray, max_dist: f32) -> Option<VoxelHit> {
    let cell_size = 1.0;
    let mut cx = (ray.origin.x / cell_size).floor() as i32;
    let mut cy = (ray.origin.y / cell_size).floor() as i32;
    let mut cz = (ray.origin.z / cell_size).floor() as i32;
    
    let dx = ray.dir.x;
    let dy = ray.dir.y;
    let dz = ray.dir.z;
    
    let step_x = if dx > 0.0 { 1 } else { -1 };
    let step_y = if dy > 0.0 { 1 } else { -1 };
    let step_z = if dz > 0.0 { 1 } else { -1 };
    
    let mut t_max_x = if dx.abs() > 1e-10 {
        ((cx + if dx > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin.x) / dx
    } else { f32::INFINITY };
    let mut t_max_y = if dy.abs() > 1e-10 {
        ((cy + if dy > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin.y) / dy
    } else { f32::INFINITY };
    let mut t_max_z = if dz.abs() > 1e-10 {
        ((cz + if dz > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin.z) / dz
    } else { f32::INFINITY };
    
    let t_delta_x = if dx.abs() > 1e-10 { (cell_size / dx).abs() } else { f32::INFINITY };
    let t_delta_y = if dy.abs() > 1e-10 { (cell_size / dy).abs() } else { f32::INFINITY };
    let t_delta_z = if dz.abs() > 1e-10 { (cell_size / dz).abs() } else { f32::INFINITY };
    
    let mut t = 0.0;
    while t < max_dist {
        if world.is_solid_voxel(cx, cy, cz) {
            return Some(VoxelHit { x: cx, y: cy, z: cz, t });
        }
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            t = t_max_x;
            t_max_x += t_delta_x;
        } else if t_max_y < t_max_z {
            cy += step_y;
            t = t_max_y;
            t_max_y += t_delta_y;
        } else {
            cz += step_z;
            t = t_max_z;
            t_max_z += t_delta_z;
        }
    }
    None
}
```

**和 Day 590 几乎相同**,差别:
- Day 590 用 2D,Day 598 用 3D
- Day 598 加 `max_dist` 提前终止

### k-d tree raycast 复杂度

- Grid DDA:O(D),D 是光线穿过的体素数。对 32³ 网格,D ≤ 96
- k-d tree:O(log N + K),N 是三角形数,K 是命中三角形数

**比较**:
- 1000 个三角形,Grid DDA 96 步,k-d tree ~ 10 步 + 8 三角形测试 = 18 步。k-d tree 快 5 倍
- 100 个三角形,Grid DDA 96 步,k-d tree ~ 7 步 + 4 测试 = 11 步。k-d tree 快 9 倍
- 10 个三角形,Grid DDA 96 步,k-d tree ~ 4 步 + 1 测试 = 5 步。k-d tree 快 19 倍

**结论**:三角形多,k-d tree 优势大。但**只考虑三角形数**,忽略了"墙体几何"——如果墙体跨越多个体素,k-d tree 的三角形可能比体素多。

### 实验结果

Casey 跑实验:
- 场景:1000 个体素,其中 200 个是墙
- 光线:10000 条随机
- Grid DDA:平均 50 步 / 光,总时间 50 ms
- k-d tree:平均 15 步 / 光,总时间 15 ms

**结果**:k-d tree 快 3 倍。Casey 决定保留 k-d tree(虽然复杂)。

但 Grid DDA 有一个 k-d tree 没有的优势:**自然支持"格子里的 atlas"**。光穿过某格,可以直接用该格的 atlas 做光照查询。k-d tree 不行。

**结论**:不同结构适合不同需求。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,空间加速结构的选择不是"哪个最好",而是"哪个适合":
- **Minecraft 风格体素游戏**:Grid DDA,因为场景就是体素网格
- **3D 模型场景**:BVH / k-d tree,因为三角形分布不均
- **超大世界**:Cascaded grid + BVH
- **GPU 光追**:BVH(TLAS/BLAS)

**Casey 的选择困境**:Handmade Hero 场景介于体素和三角形之间——有体素网格(光场存这里),也有墙体三角形(碰撞 / raycast)。

工业级方案:**双层结构**——Grid DDA 做粗筛选(找到光进入的体素),然后该体素内有 BVH(细查墙体)。Casey 倾向简化,用单层 k-d tree。

### 3.2 · 🎨 图形学视角

**体素化(Voxelization)**:把三角形场景转成体素表示。优点:统一格式(体素 vs 体素),容易做 raycast。缺点:精度损失(墙体边界有锯齿)。

**Sparse Voxel Octree(SVO)**:稀疏体素八叉树,Crytek 提出。场景完全体素化,光追极快。但内存大,适合静态场景。

**Sparse Voxel Directed Acyclic Graph(DAG)**:SVO 压缩版,重复体素共享节点。内存小 100 倍。

**Voxel Cone Tracing**:Crassin 2011,在体素八叉树上做 cone tracing(锥形追踪),近似 GI。Lumen 的灵感来源。

### 3.4 · 🦀 Rust 生态视角

Rust 表达"探索性 benchmark"的几个模式:

**1. 条件编译**:

```rust
#[cfg(feature = "grid_dda")]
fn raycast_grid(...) { ... }

#[cfg(feature = "kdtree")]
fn raycast_kdtree(...) { ... }

// Cargo.toml: [features] grid_dda = [] kdtree = []
```

可以在编译时选择实现,对比性能。

**2. Trait 抽象**:

```rust
trait Raycaster {
    fn raycast(&self, ray: &Ray) -> Option<Hit>;
}

impl Raycaster for GridDda { ... }
impl Raycaster for KdTree { ... }

fn benchmark<R: Raycaster>(r: &R, rays: &[Ray]) {
    for ray in rays {
        r.raycast(ray);
    }
}
```

抽象让 benchmark 通用,可对比任意实现。

**3. Criterion 比较组**:

```rust
fn bench(c: &mut Criterion) {
    let mut group = c.benchmark_group("raycast");
    group.bench_function("grid_dda", |b| b.iter(|| ...));
    group.bench_function("kdtree", |b| b.iter(|| ...));
    group.finish();
}
```

Criterion 自动对比两个实现的性能,生成可视化报告。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么"墙体密集"场景 Grid DDA 比 k-d tree 慢得没那么明显?

**参考解答**:墙体密集意味着"光穿过的体素里大部分是墙",Grid DDA 早早终止(光撞墙就停)。所以 Grid DDA 的实际步数 < 96(理论上限)。

k-d tree 在这种场景下查询仍然快(log N),但构造慢(三角形密集,SAH 选 split 难)。

总结:
- 墙稀疏:Grid DDA 慢(光穿过很多空格),k-d tree 显著快
- 墙密集:Grid DDA 加速(早终止),k-d tree 优势缩小

**参考解答**:

```rust
struct World {
    dim: usize,
    cells: Vec<bool>,
}

impl World {
    fn new(dim: usize) -> Self {
        Self { dim, cells: vec![false; dim * dim * dim] }
    }
    fn set_solid(&mut self, x: usize, y: usize, z: usize) {
        self.cells[z * self.dim * self.dim + y * self.dim + x] = true;
    }
    fn is_solid(&self, x: i32, y: i32, z: i32) -> bool {
        if x < 0 || y < 0 || z < 0 { return false; }
        let x = x as usize;
        let y = y as usize;
        let z = z as usize;
        if x >= self.dim || y >= self.dim || z >= self.dim { return false; }
        self.cells[z * self.dim * self.dim + y * self.dim + x]
    }
}

struct Ray { origin_x: f32, origin_y: f32, origin_z: f32, dir_x: f32, dir_y: f32, dir_z: f32 }

fn voxel_raycast(world: &World, ray: &Ray, max_dist: f32) -> (Option<(i32, i32, i32)>, usize) {
    let cell_size = 1.0;
    let mut cx = (ray.origin_x / cell_size).floor() as i32;
    let mut cy = (ray.origin_y / cell_size).floor() as i32;
    let mut cz = (ray.origin_z / cell_size).floor() as i32;
    
    let (dx, dy, dz) = (ray.dir_x, ray.dir_y, ray.dir_z);
    let step_x = if dx > 0.0 { 1 } else { -1 };
    let step_y = if dy > 0.0 { 1 } else { -1 };
    let step_z = if dz > 0.0 { 1 } else { -1 };
    
    let mut t_max_x = if dx.abs() > 1e-10 {
        ((cx + if dx > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin_x) / dx
    } else { f32::INFINITY };
    let mut t_max_y = if dy.abs() > 1e-10 {
        ((cy + if dy > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin_y) / dy
    } else { f32::INFINITY };
    let mut t_max_z = if dz.abs() > 1e-10 {
        ((cz + if dz > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin_z) / dz
    } else { f32::INFINITY };
    
    let t_delta_x = if dx.abs() > 1e-10 { (cell_size / dx).abs() } else { f32::INFINITY };
    let t_delta_y = if dy.abs() > 1e-10 { (cell_size / dy).abs() } else { f32::INFINITY };
    let t_delta_z = if dz.abs() > 1e-10 { (cell_size / dz).abs() } else { f32::INFINITY };
    
    let mut t = 0.0;
    let mut steps = 0;
    while t < max_dist {
        steps += 1;
        if world.is_solid(cx, cy, cz) {
            return (Some((cx, cy, cz)), steps);
        }
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            t = t_max_x;
            t_max_x += t_delta_x;
        } else if t_max_y < t_max_z {
            cy += step_y;
            t = t_max_y;
            t_max_y += t_delta_y;
        } else {
            cz += step_z;
            t = t_max_z;
            t_max_z += t_delta_z;
        }
    }
    (None, steps)
}

fn main() {
    let mut world = World::new(16);
    // 放一些墙
    for i in 0..16 {
        world.set_solid(i, 8, 8);
        world.set_solid(8, i, 8);
    }
    
    // 1000 条随机光线
    let mut total_steps = 0;
    let mut hits = 0;
    for i in 0..1000 {
        let t = i as f32 * 0.01;
        let ray = Ray {
            origin_x: 0.5, origin_y: 0.5, origin_z: 0.5,
            dir_x: t.sin(), dir_y: t.cos(), dir_z: (t * 1.7).sin(),
        };
        let (hit, steps) = voxel_raycast(&world, &ray, 100.0);
        total_steps += steps;
        if hit.is_some() { hits += 1; }
    }
    println!("1000 rays: {} hits, avg {} steps/ray", hits, total_steps as f32 / 1000.0);
}
```

### A.1 性能优化的层次

工业性能优化的层次:

**L1:算法选择**
- O(N²) → O(N log N) → O(N) → O(log N) → O(1)
- 例子:Grid DDA(O(N))vs brute force(O(V))

**L2:数据结构**
- Array → HashMap → BTreeMap → 特殊结构
- 例子:chunked voxel storage 替代 flat array

**L3:Micro-optimization**
- Inline / branchless / SIMD / prefetch
- 例子:`#[inline]`, `core::arch::x86_64::__m256`

**L4:并行化**
- Single thread → multi-thread → SIMD → GPU
- 例子:rayon / crossbeam / GPU shader

**L5:架构**
- 重新设计避免 bottleneck
- 例子:streaming 替代 load-all

每层收益递减,但难度递增。Casey phase-8 主要在 L1-L2,L3 偶尔,L4 在 phase 5+ 才大规模。

### A.2 Cache-friendly 数据布局

```
Array of Structures(AoS):
struct Voxel { material, color, light }  // 每 voxel 一组
Vec<Voxel>  // 内存布局:mat col lit mat col lit ...

Structure of Arrays(SoA):
struct VoxelData {
    materials: Vec<u8>,
    colors: Vec<[u8; 3]>,
    lights: Vec<[u8; 3]>,
}
// 内存布局:mat mat mat ... col col col ... lit lit lit ...
```

SoA 在批量操作(只处理 materials)时 cache 友好。AoS 在访问 voxel 全字段时 cache 友好。

游戏开发混合用:
- 频繁批量操作的字段 → SoA
- 频繁整 voxel 访问的字段 → AoS

### A.4 工业级 voxel physics

Voxel 物理碰撞的核心:Swept AABB

```rust
fn swept_aabb_vs_voxels(
    world: &World,
    aabb_start: AABB,
    velocity: Vec3,
    dt: f32,
) -> (AABB, Vec<Collision>) {
    let aabb_end = aabb_start + velocity * dt;
    
    // 沿 velocity 方向 step,每 step 检查 voxel 碰撞
    let steps = (velocity.length() * dt / 0.1).ceil() as i32 + 1;
    let step_velocity = velocity * dt / steps as f32;
    
    let mut current = aabb_start;
    let mut collisions = vec![];
    
    for _ in 0..steps {
        current.center += step_velocity;
        
        // 检查 AABB 范围内的 voxel
        let hit_voxels = voxel_utility::aabb_vs_voxels(world, current);
        if !hit_voxels.is_empty() {
            // 推回
            for voxel_pos in &hit_voxels {
                let voxel_aabb = AABB::new(voxel_pos, Vec3::ONE);
                let correction = current.push_out_of(voxel_aabb);
                current.center += correction;
                collisions.push(Collision { ... });
            }
        }
    }
    
    (current, collisions)
}
```

swept AABB 处理高速移动(避免穿透)。Minecraft、Teardown 的物理基础。
