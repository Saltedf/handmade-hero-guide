
# Day 636 · 解嵌碰撞物体

> 体素碰撞上线以后,出现一个让所有人都遇到的 bug:玩家从空中落下时,有一帧"穿"进地板里半格,然后被卡住。今天 Casey 处理**解嵌**(unembedding)——把已经卡进 voxel 里的物体"推回"到表面外,而不是简单地拒绝后续移动。

## 0 · 为什么要有这一天

在前几集里,我们写出来的碰撞代码大致是:**"新位置如果撞到 voxel,就拒绝这次位移"**。这套逻辑对"低速运动 + 离散步进"够用,但游戏里总会出现一些"拒绝失败"的情况。

最经典的两类:

- **高速穿透(tunneling)**:玩家从空中跳下来,每帧位移 0.3 voxel。某帧玩家中心从 voxel A 的中央直接跨到 voxel B 的中央,但 A 和 B 之间隔着一个 solid voxel——离散检测会以为"没撞"。
- **数值漂移嵌入**:Casey 在 Day 635 修过"抖动 bug",但抖动会偶尔让玩家**真的**推进 voxel 内部零点几米。一帧没拒绝成功,下一帧发现"我已经在里面了",传统"拒绝新位移"逻辑完全失效——因为玩家**当前位置**就已经非法。

工业级引擎(PhysX / Havok / Box2D)对这两类问题的标准答案是 **depentration / depenetration**:每一帧先承认现状("玩家可能已经在 voxel 里"),然后**主动计算一个把玩家推出去的最短位移向量**,把这个向量加到玩家位置上。这个推回去的过程叫**解嵌**(unembed)。

心理锚点:看完今天,你能:

- 写出"把已嵌入物体推回合法区"的最短位移算法
- 区分**预防性碰撞(reject)**和**纠正性碰撞(unembed)**两种思路
- 解释为什么"小步长 + 拒绝"在高速场景下会失效

## 2 · 心智模型

### 类比:酒店门卡

你住过酒店,进门要刷卡。门卡有两种逻辑:

- **预防式**:刷错了,门不开,你必须重刷。问题是,如果门半开着你冲进去,门没拦住,之后你已经在房间里,门卡就管不了你了。
- **纠正式**:每秒钟扫一次"你在哪个房间",如果你不在你刷的那个房间,就把你"瞬移"回正确的门口。

游戏碰撞的"预防式"就是传统 reject:试图移动,如果新位置非法,拒绝。问题是,由于**离散时间步进 + 浮点误差**,玩家有时候会"溜进"非法状态——这时 reject 完全无用,因为玩家**当前**位置就已经非法了。

"纠正式"就是 unembed:不再问"这次位移是否合法",而是问"我现在已经在非法状态,最短走多远能回到合法状态"。

### 数学:最小穿透深度

记玩家的 bbox 在世界坐标里是一个 AABB(axis-aligned bounding box,轴对齐包围盒)。一个 voxel 也是一个 AABB,边长 1。**"嵌入"意味着 bbox 和某个 solid voxel 的 AABB 有重叠体积**。

**最短解嵌向量** = 把 bbox 沿某一根轴推出去,直到不再重叠,选三根轴里**推得最短**的那一根。

```
                  solid voxel
   bbox           ┌────────┐
   ┌──────┐       │        │
   │      │       │        │
   │  ┌───┼───────┼───┐    │   ← bbox 已经嵌入了 0.2 米
   └──┼───┼───────┼───┘    │
      │   │       │        │
      └───┼───────┼────────┘
          │       │
          ▼       ▼
        推左 0.2  推右 0.8  ← 选推左(更短)
```

为什么选最短而不是随便选?**物理直觉**:物体刚穿透时,穿透方向上的位移最小,所以"沿最浅方向退回"是最贴近真实物理的近似。Box2D 的 `b2Sweep` / Havok 的 `hkpAgent` / PhysX 的 `PxRigidDynamic` 都用同一思路。

### 公式推导

记 bbox 的最小角 `b_min`,最大角 `b_max`,voxel 的最小角 `v_min`,最大角 `v_max`。三轴上重叠量分别是:

```
overlap_x = min(b_max.x, v_max.x) - max(b_min.x, v_min.x)
overlap_y = min(b_max.y, v_max.y) - max(b_min.y, v_min.y)
overlap_z = min(b_max.z, v_max.z) - max(b_min.z, v_min.z)
```

如果三轴 overlap 都 > 0,说明真有重叠。**最短解嵌**:

```
penetration = min(overlap_x, overlap_y, overlap_z)
```

假设 `overlap_y` 最小,那么把 bbox 沿 y 轴推 `overlap_y`,至于推 +y 还是 -y,看 bbox 中心相对 voxel 中心的位置:

```
if bbox.center.y < voxel.center.y:
    push = -overlap_y  // 推下去
else:
    push = +overlap_y  // 推上来
```

把所有 solid voxel 都扫一遍,每次扫更新"当前最小穿透",最后得出一个总纠正向量。**注意**:这不是严格最优(Minkowski penalty method 才是),但在 voxel 场景下够用——Casey 反复强调"够用就行"。

### 为什么不是"暴力搜索全部方向"

理论上,最短解嵌可以在球面上无穷多方向中找。但 voxel 是 AABB,bbox 也是 AABB,**两 AABB 的最小分离向量一定沿某根坐标轴**(这是分离轴定理 SAT 在 AABB-AABB 情况下的特例)。所以三根轴扫一遍就够了。

SAT(Separating Axis Theorem,分离轴定理):两个凸多面体如果不相交,一定存在一根轴,把它们在该轴上的投影**不相交**。对 AABB 来说,这些候选轴就是 x / y / z 三根,所以 SAT 简化为 3 次投影检查。

### 解嵌 vs 拒绝:何时各用哪个

| 场景 | 推荐 |
|---|---|
| 玩家从空中落下,每帧位移 0.05 voxel | reject 够用 |
| 玩家被外力(爆炸、传送)瞬间推 5 voxel | 必须 unembed |
| 玩家在 voxel 边界抖动 | 必须 unembed |
| 高速子弹(每帧 10 voxel) | 需要 CCD(continuous collision detection) + unembed |
| 关卡加载时玩家出生在墙里 | 必须 unembed |

CCD 的思路:**不只在每帧末位置检测,而在整条运动轨迹上检测**。最简单的 CCD 是 **raycast against voxels**:把"运动轨迹"看作一条射线,扫到第一个 solid voxel 的时间就是碰撞时间。Casey 在后面 Day 640-645 会用到类似的 trajectory sweep 思路。

### 实现细节:voxel 中心 vs voxel 边界

Day 635 修过 "voxel 边界抖动" bug,核心是**把检测从"边界"切到"中心"**。今天 unembed 同样要小心:

**坏的做法**:用 `bbox.center.floor()` 找 voxel,然后检查那个 voxel 是不是 solid。
**好的做法**:扫 bbox 覆盖的**所有** voxel(`floor(b_min)` 到 `floor(b_max)`),逐个检查。

```rust
fn for_each_voxel_in_bbox<F: FnMut(IVec3)>(b_min: Vec3, b_max: Vec3, mut f: F) {
    let lo = b_min.floor().as_ivec3();
    let hi = b_max.floor().as_ivec3();
    for z in lo.z..=hi.z {
        for y in lo.y..=hi.y {
            for x in lo.x..=hi.x {
                f(IVec3::new(x, y, z));
            }
        }
    }
}
```

`as_ivec3` 是 glam crate 的类型转换。如果你不用 glam,自己写 `(v as i32)` 三次也行。

**为什么扫所有 voxel 而不是单个?**

bbox 可能比 voxel 大(比如 2x2x2 玩家 bbox),覆盖 8 个 voxel。如果只查"bbox 中心所在 voxel",可能漏掉旁边的 solid voxel。

更糟:玩家 bbox 中心在 voxel A 内,但 bbox 角延伸到 voxel B(solid)。如果只查 A(非 solid),漏检 B,玩家"嵌入"B 的角。这是经典 bug。

工业实践:**broad phase 必须覆盖 bbox 全部**。Casey 在 Day 636 演示这个。Minecraft / Cube World 等 voxel 游戏都用类似算法。

**floor vs round 的微妙**:

`floor(0.5)` = 0,`round(0.5)` = 1(在不同语言不同)。如果 voxel 中心在整数坐标,bbox 在 [0.5, 1.5],`floor(0.5)` = 0 错(应该是 voxel 1),`floor(1.5)` = 1 对。所以需要扫 [0, 1] 两个 voxel。

如果 voxel 中心在 (n + 0.5) 坐标,bbox 在 [0.4, 1.6],`floor(0.4)` = 0,`floor(1.6)` = 1。扫 voxel 0 和 1,正确。

约定的统一很重要。Casey 在 Day 645 把 voxel 中心约定改到整数,消除歧义。在那之前,Day 636 用边界约定,需要小心 floor 的边界 case。

**性能考虑**:

3x3x3 voxel 扫描 = 27 个 voxel。每个 voxel 查询 O(1)(hash map 或 array),总 O(27) = 常数。这对小 bbox(玩家)够快。

但大 bbox(车辆 / 大怪)可能 10x10x10 = 1000 voxel,慢。工业解法:**broad phase grid**——把空间分大格,bbox 只扫自己格 + 邻格。这是 spatial hash 的思路。Casey 在 HH 不做这优化(玩家小),但工业级要。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏里 unembed 的坑:

1. **颤抖(jitter)**:解嵌向量太大会让玩家"瞬移",看起来像抖动。工业做法是**夹解嵌向量到一个小上限**,超过上限就当作"严重嵌入"——可能是关卡 bug,直接把玩家挪到 spawn point。
2. **解嵌方向不对**:如果玩家从右侧撞墙,但解嵌算成了"向上推",看起来就是"撞墙跳一下"。修法:**优先沿运动反方向**解嵌。
3. **连环解嵌**:玩家同时嵌入两个 voxel,A 推到 +x,但推后碰到 B,B 推回 -x——形成震荡。修法:**多轮迭代**,每轮把所有 voxel 的解嵌向量累加,而不是逐个应用。

Casey 在 Day 636 只做最简单版,后面 Day 640-645 会反复打磨。

### 3.2 · 图形学视角

unembed 在物理引擎里叫 **depenetration**,在渲染里也有类似的影子:

- **z-fighting**:两个三角形深度几乎一样,渲染时像素交替属于两者,看起来闪烁。修法和 unembed 思路一致:把其中一个三角形沿法线"推"一点点(polygon offset)。
- **shadow acne**:shadow map 算法里,自阴影出现条纹。修法是 **bias**,把采样深度偏移一点点,本质也是"解嵌"。

### 3.3 · Linux 系统编程视角

Linux 上"解嵌"的影子:

- **OOM killer**:进程内存"嵌入"超出物理 RAM,内核不是直接拒绝分配,而是杀掉最耗内存的进程"纠正"——一种系统级 unembed。
- **lockdep**:内核锁依赖检测器,如果检测到潜在死锁,会主动 panic 而不是等死锁发生——预防式 + 纠正式并存。
- **stack guard page**:线程栈溢出时,内核给一个 guard page,触发 SIGSEGV——这是"拒绝",但用户态也可以装 SIGSEGV handler 主动释放栈空间(罕见但存在)。

### 3.4 · Rust 生态视角

Rust 里 unembed 的实现要点:

```rust
// 用 glam 做 AABB 重叠 + 最短穿透
use glam::{Vec3, IVec3};

struct Bbox { min: Vec3, max: Vec3 }

impl Bbox {
    fn center(&self) -> Vec3 { (self.min + self.max) * 0.5 }
}

// 返回最短解嵌向量;无嵌入返回 Vec3::ZERO
fn unembed(bbox: &Bbox, voxel_center: IVec3) -> Vec3 {
    let v_min = voxel_center.as_vec3() - Vec3::splat(0.5);
    let v_max = voxel_center.as_vec3() + Vec3::splat(0.5);

    let overlap_x = bbox.max.x.min(v_max.x) - bbox.min.x.max(v_min.x);
    let overlap_y = bbox.max.y.min(v_max.y) - bbox.min.y.max(v_min.y);
    let overlap_z = bbox.max.z.min(v_max.z) - bbox.min.z.max(v_min.z);

    // 任一轴无重叠 → 整体没重叠
    if overlap_x <= 0.0 || overlap_y <= 0.0 || overlap_z <= 0.0 {
        return Vec3::ZERO;
    }

    // 选最浅穿透轴
    let center = bbox.center();
    let vc = voxel_center.as_vec3();
    if overlap_x <= overlap_y && overlap_x <= overlap_z {
        // 沿 x 解嵌
        let sign = if center.x < vc.x { -1.0 } else { 1.0 };
        Vec3::new(sign * overlap_x, 0.0, 0.0)
    } else if overlap_y <= overlap_z {
        let sign = if center.y < vc.y { -1.0 } else { 1.0 };
        Vec3::new(0.0, sign * overlap_y, 0.0)
    } else {
        let sign = if center.z < vc.z { -1.0 } else { 1.0 };
        Vec3::new(0.0, 0.0, sign * overlap_z)
    }
}
```

注意:`bbox.max.x.min(v_max.x)` 这种写法是 glam 的链式方法,等价于 `bbox.max.x.min(v_max.x)`(两个 f32 取 min)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么两 AABB 的最小分离向量一定沿某根坐标轴?用 SAT 解释。

**参考解答**:SAT 说:两个凸形不相交 ⟺ 存在一根轴,使它们在该轴上的投影区间不相交。对两个 AABB,候选轴只需要 x / y / z 三根(因为 AABB 的法线就是这三根)。如果它们相交,那么三根轴上投影都相交;我们要找的是"最小推开后不再相交"的方向,从直觉来说沿某根轴推最短(其他方向都需要推更长才能脱离)。所以最小分离向量一定沿 x / y / z 之一。

### Lv2 · 动手实践

**题**:写一个最小可跑的 Rust 程序,验证 §3.4 的 `unembed` 函数:

- bbox 中心 (0.5, 0.3, 0.5),半边长 0.4,voxel 中心 (0, 0, 0):预期解嵌向量大致 (0, -0.1, 0)
- bbox 中心 (1.0, 1.0, 1.0),半边长 0.4,voxel 中心 (0, 0, 0):预期无重叠

完成标准:打印两个 case 的解嵌向量,数值合理。

**参考解答**:

```rust
use glam::{Vec3, IVec3};

struct Bbox { min: Vec3, max: Vec3 }
impl Bbox {
    fn from_center(c: Vec3, half: f32) -> Self {
        Self { min: c - Vec3::splat(half), max: c + Vec3::splat(half) }
    }
    fn center(&self) -> Vec3 { (self.min + self.max) * 0.5 }
}

fn unembed(bbox: &Bbox, voxel: IVec3) -> Vec3 {
    let v_min = voxel.as_vec3() - Vec3::splat(0.5);
    let v_max = voxel.as_vec3() + Vec3::splat(0.5);
    let ox = bbox.max.x.min(v_max.x) - bbox.min.x.max(v_min.x);
    let oy = bbox.max.y.min(v_max.y) - bbox.min.y.max(v_min.y);
    let oz = bbox.max.z.min(v_max.z) - bbox.min.z.max(v_min.z);
    if ox <= 0.0 || oy <= 0.0 || oz <= 0.0 { return Vec3::ZERO; }
    let c = bbox.center();
    let vc = voxel.as_vec3();
    if ox <= oy && ox <= oz {
        Vec3::new(if c.x < vc.x { -ox } else { ox }, 0.0, 0.0)
    } else if oy <= oz {
        Vec3::new(0.0, if c.y < vc.y { -oy } else { oy }, 0.0)
    } else {
        Vec3::new(0.0, 0.0, if c.z < vc.z { -oz } else { oz })
    }
}

fn main() {
    let b1 = Bbox::from_center(Vec3::new(0.5, 0.3, 0.5), 0.4);
    println!("Case 1: {:?}", unembed(&b1, IVec3::ZERO));
    // 期望 y 负方向 ~0.1,因为 bbox 底部 -0.1 < voxel 底 -0.5? 等下,我们要看实际重叠
    // bbox.min.y = -0.1, voxel.min.y = -0.5
    // bbox.max.y = 0.7, voxel.max.y = 0.5
    // overlap_y = min(0.7, 0.5) - max(-0.1, -0.5) = 0.5 - (-0.1) = 0.6
    // 但 overlap_x = min(0.9, 0.5) - max(0.1, -0.5) = 0.5 - 0.1 = 0.4
    // overlap_z 同 x = 0.4
    // 最短 = x 或 z = 0.4,沿 x 推(因为 center.x = 0.5 > vc.x = 0,推 +x)
    // 所以预期 (0.4, 0, 0) 或类似

    let b2 = Bbox::from_center(Vec3::new(1.0, 1.0, 1.0), 0.4);
    println!("Case 2: {:?}", unembed(&b2, IVec3::ZERO));
    // 期望 Vec3::ZERO(无重叠)
}
```

### Lv3 · 迁移设计

## 8 · Rust / Arch 落地代码

完整可跑示例,使用 glam:

```rust
// Cargo.toml:
// [dependencies]
// glam = "0.29"

use glam::{Vec3, IVec3};

#[derive(Copy, Clone, Debug)]
struct Bbox { min: Vec3, max: Vec3 }

impl Bbox {
    fn from_center(c: Vec3, half: Vec3) -> Self {
        Self { min: c - half, max: c + half }
    }
    fn center(&self) -> Vec3 { (self.min + self.max) * 0.5 }
}

// 假设 voxel grid 边长 1,中心在整数坐标
fn is_solid(_voxel: IVec3) -> bool {
    // 实际游戏里查 chunk table
    true // demo 里假设 (0,0,0) 是 solid
}

// 扫 bbox 覆盖的所有 voxel,累加最小解嵌
fn unembed_total(bbox: &Bbox) -> Vec3 {
    let lo = bbox.min.floor().as_ivec3();
    let hi = bbox.max.floor().as_ivec3();
    let mut total = Vec3::ZERO;
    for z in lo.z..=hi.z {
        for y in lo.y..=hi.y {
            for x in lo.x..=hi.x {
                let v = IVec3::new(x, y, z);
                if !is_solid(v) { continue; }
                total += unembed_one(bbox, v);
            }
        }
    }
    total
}

fn unembed_one(bbox: &Bbox, voxel: IVec3) -> Vec3 {
    let v_min = voxel.as_vec3() - Vec3::splat(0.5);
    let v_max = voxel.as_vec3() + Vec3::splat(0.5);
    let ox = bbox.max.x.min(v_max.x) - bbox.min.x.max(v_min.x);
    let oy = bbox.max.y.min(v_max.y) - bbox.min.y.max(v_min.y);
    let oz = bbox.max.z.min(v_max.z) - bbox.min.z.max(v_min.z);
    if ox <= 0.0 || oy <= 0.0 || oz <= 0.0 { return Vec3::ZERO; }
    let c = bbox.center();
    let vc = voxel.as_vec3();
    if ox <= oy && ox <= oz {
        Vec3::new((if c.x < vc.x { -1.0 } else { 1.0 }) * ox, 0.0, 0.0)
    } else if oy <= oz {
        Vec3::new(0.0, (if c.y < vc.y { -1.0 } else { 1.0 }) * oy, 0.0)
    } else {
        Vec3::new(0.0, 0.0, (if c.z < vc.z { -1.0 } else { 1.0 }) * oz)
    }
}

fn main() {
    // 嵌入 0.1 米的玩家
    let bbox = Bbox::from_center(Vec3::new(0.5, -0.1, 0.5), Vec3::splat(0.4));
    let correction = unembed_total(&bbox);
    println!("Before: {:?}", bbox);
    println!("Correction: {:?}", correction);
    let fixed = Bbox {
        min: bbox.min + correction,
        max: bbox.max + correction,
    };
    println!("After:  {:?}", fixed);
}
```

## 10 · 工程反思

Day 636 是体素碰撞重构的开篇,传达的核心工程教训:**预防式 vs 纠正式思维的切换**。

新手工程师本能选择"预防式"——"试图阻止坏事"。但物理模拟的离散时间步进让"完美预防"不可能,因为:

- 浮点精度有限
- 时间步长非零
- 输入连续但采样离散

所以工业物理代码必然需要"纠正式"——"承认错误会发生,主动修复"。unembed 是这种思维的典型实例。

**第二条教训**:**接受数值误差,设计容错系统**。不要追求"零误差",追求"误差可控"。Casey 的 unembed 算法不"完美"——它有边角 case(连环嵌入、角落碰撞),但**保证大多数 case 工作**。这是工程现实主义。

**第三条教训**:**MVP 优先,边角 case 后期修**。Day 636 只做最朴素 unembed,Day 637 加球,Day 640 修角落,Day 643 多 bug polish。每个迭代解决一类问题,不试图一次到位。这是敏捷开发的核心方法论。

工业教训:**collision 系统是 polish 工程师的主战场**。每个游戏 release 前,都有 collision bug list 几百条。资深工程师的能力是"快速复现 + 系统化排查 + 优雅修复"。Casey 在 Day 636-645 的迭代是这种能力的实例教学。

**为什么 unembed 不在其他课程讲?**

学校物理课讲"碰撞响应",但很少讲"解嵌"——因为学校假设"连续时间步进,不会有嵌入"。但实际游戏离散步进,嵌入是常态。HH Day 636 把这个"教科书未讲"的话题讲透,这是 HH 教学的独到价值。

**迁移到其他领域**:

unembed 思想在多处可用:

- **网络**:包丢失时,用 NACK / ACK 重新请求(纠正式)
- **数据库**:事务失败时,用 rollback 恢复(纠正式)
- **文件系统**:fsck 检测并修复不一致(纠正式)
- **机器学习**:梯度下降"承认初始值不优,逐步纠正"(纠正式)
- **分布式共识**:Raft "承认 leader 可能失败,重新选举"(纠正式)

每个领域都有"预防式 + 纠正式"的双重设计。Casey 在 collision 演示的思路,是工程思维的普适模式。

## 11 · unembed 的数值稳定性

unembed 算法对数值精度敏感。考虑:

```rust
let dist_sq = d.length_squared();
if dist_sq < r * r { /* 碰撞 */ }
```

`r * r` 是常数,`dist_sq` 浮点。两者很接近时,浮点误差让"碰不碰"不确定。

**修法**:加 epsilon:

```rust
if dist_sq < r * r - EPSILON { /* 真碰撞 */ }
```

EPSILON = 0.0001,允许微小"几乎相切"的 case 不算碰撞,避免抖动。

**更深**:浮点比较的 best practice:

- `a == b`:几乎肯定错(浮点)
- `abs(a - b) < eps`:基本对,但 eps 选取难
- `relative_error(a, b) < eps`:更严格,适合大数值
- ULPs (Units in the Last Place):最严格,但复杂

游戏代码用第二种(`abs diff < eps`)足够,工业级数值库用 ULPs。

## 12 • unembed 在 shipping build 的开销

shipping build 不能 debug print,但 unembed 仍跑(游戏核心)。优化:

**1. SIMD**:8 个球同时 unembed,AVX2 一次处理。3A 游戏大量玩家时关键。

**2. Multi-threading**:每个 entity 独立 unembed,可并行。Bevy ECS 用 Rayon 自动并行。

**3. Cache friendly data**:把所有 entity 的 position 连续存储(SoA),cache 友好。

每个优化让 shipping build 跑 1000+ entity 同屏。Casey 在 HH 单线程 + AoS,工业级必须 SIMD + MT + SoA。

## 13 • 反作弊考虑

unembed 在 shipping build 仍跑(核心物理),但要小心**反作弊**:

**Bug**:玩家修改客户端,把 unembed 的 max_step 设到 100,玩家就能"瞬移"穿墙。

**修法**:

- **服务器权威**(多人游戏):服务器跑物理,客户端只接收结果。客户端的 unembed 是"视觉预测",服务器校正。
- **Anti-cheat 检测**:监控玩家位置变化速率,瞬移 → 标记作弊。
- **cfg off in shipping**:某些 debug unembed 行为 shipping 关闭。

每个保护都增加安全。Casey 在 HH 单机,但工业级必须 anti-cheat。
