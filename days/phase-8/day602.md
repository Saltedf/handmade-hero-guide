
# Day 602 · 网格光线追踪器的提前终止

> Grid DDA 内循环里,如果光已经"走出场景"或"撞到墙",应该立即终止。Day 590 简单实现有 `t < max_dist` 检查,但还可以更精细——比如检测"光永远不会撞任何墙"(完全朝天空)。

## 0 · 为什么要有这一天

Grid DDA 在没墙的方向上,光会"无限走"直到 `t < max_dist`。如果场景大、光距离远(如阳光),循环会跑几千次,浪费。

**Early termination** 的几种场景:
1. **撞墙**:已实现,返回
2. **走出场景边界**:已实现(`is_solid` 检查越界返回 false)
3. **光永远不撞墙**(朝天空):光走出场景边界后,永远走不回来。一旦出界,立即终止

第 3 种是 Day 602 的重点。Day 590 实现的"出界后继续循环"是浪费——一旦光走出场景,后面所有循环都是越界检查,可以立即终止。

心理锚点:看完这集,你能优化 Grid DDA 的循环,理解"early termination"的多个层次,能在自己写循环代码时主动考虑"哪些情况可以提前退出"。

## 1 · Casey 今天做了什么

Casey 这一天的几个动作:

1. **观察**:profile 发现 30% 的 Grid DDA 时间花在"光走出场景后的越界检查"。
2. **加边界检测**:每步检查"当前 cx/cy/cz 是否在场景内",越界立即 return None。

## 2 · 心智模型

### 类比:外卖员送餐

外卖员送餐,有几种终止条件:
1. **送达**(找到目标地址):正常终止
2. **超出范围**(地址不在服务区):立即终止
3. **永远找不到**(地址不存在):外卖员一直找,直到下班 —— **Day 590 的 bug**

第 3 种的修复:外卖员出发前看"地址在不在服务区",不在直接说"找不到"。

Grid DDA 完全一样——光朝天空射,场景外是"空",光永远不会撞墙。Day 590 的实现继续循环(浪费),Day 602 加"一旦出界立即终止"。

### 严谨原理:场景边界

```rust
fn is_in_bounds(&self, x: i32, y: i32, z: i32) -> bool {
    x >= 0 && y >= 0 && z >= 0 &&
    x < self.dim_x as i32 &&
    y < self.dim_y as i32 &&
    z < self.dim_z as i32
}
```

每步检查 `is_in_bounds`。如果越界,return None。

**实现**:

```rust
fn voxel_raycast_early_terminate(world: &World, ray: &Ray, max_dist: f32) -> Option<HitInfo> {
    // ... 初始化(Day 599)
    
    let mut t = 0.0;
    while t < max_dist {
        // 1. 边界检查
        if !world.is_in_bounds(cx, cy, cz) {
            return None;  // 走出场景,光朝天空
        }
        
        // 2. 实心检查
        if world.is_solid(cx, cy, cz) {
            // ... 返回 HitInfo
        }
        
        // 3. 跨格
        // ... 同 Day 599
    }
    None
}
```

**关键改动**:
- 把 `is_in_bounds` 放在循环开头(每次循环检查)。
- 越界立即 return,不继续。

**vs Day 599**:Day 599 的 `is_solid` 在越界时返回 false,所以越界后继续循环,直到 `t >= max_dist`。Day 602 显式检查,越界立即终止。

### 更激进的 early termination

除了"场景边界",还可以:

1. **最大距离**:光线参数 t > max_dist 时终止。Day 590 已有。
2. **阴影射线**:光从墙面反射,如果只想知道"是否在阴影",撞到第一个墙就返回(不需要最近)。
3. **Occlusion culling**:如果已经知道"光在某个范围内被挡",直接 return。

```rust
// 阴影射线:任何遮挡就返回 true

    let dir = (target - light_pos).normalize();
    let ray = Ray { origin: light_pos, dir };
    let mut cx = ...;
    // ...
    while t < max_dist {
        if !world.is_in_bounds(cx, cy, cz) { return false; }  // 出界,没遮挡
        if world.is_solid(cx, cy, cz) { return true; }  // 撞到 = 有遮挡

    }
    false
}
```

阴影射线不需要"最近命中",所以**第一个墙**就够,提前 return。比完整 raycast 快 2-3 倍。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里 early termination 是标准优化:
- **视锥剔除**:物体不在相机视锥内,不渲染
- **遮挡剔除**:物体被墙挡住,不渲染
- **LOD**:远处用低精度,提前停止细节计算
- **AI 视野**:超出视野角度,NPC 看不到玩家

**Shadow ray**(阴影射线):光追的优化。计算"点 P 是否在光源 L 的阴影里",射一条 ray 从 P 到 L,撞到任何墙就是阴影。

**Coherent ray**:相邻像素的光线方向接近,共享 early termination 决策(一条光线确定朝天空,邻居也朝天空)。

### 3.2 · 🎨 图形学视角

**Early ray termination**(ERT):光追领域的标准优化。

**Branchless ERT**:用条件传送(`select`)替代 if,避免分支预测错误。SIMD 友好。

**Adaptive ray termination**:根据"剩余场景复杂度"决定何时终止。例如"已经穿过的格子全空,后面密度低,提前停"。

**Russian Roulette**(俄罗斯轮盘):路径追踪的概率终止——以一定概率 p 终止,(1-p) 继续,继续时乘以 1/(1-p) 补偿。能量守恒。

### 3.3 · 🐧 Linux 系统编程视角

Early termination 在 Linux 上的几个例子:
- `find` 命令的 `-exec` 短路:`-exec` 返回非 0 立即停
- `grep -l`:找到匹配文件立即停
- `sort -k` 的 stable sort:已稳定就不重排

**Linux 工具**:`timeout` 命令强制终止长时间运行的程序。

```bash
timeout 5s ./long_running_program
# 5 秒后强制 kill
```

**perf 分析 early termination**:

```bash
sudo perf stat -e branches,branch-misses ./raytracer
# branch-misses 多说明分支预测失败
# early termination 的 if 判断可能让分支预测更难
```

### 3.4 · 🦀 Rust 生态视角

Rust 表达 early termination 的几种方式:

**1. `return` 直接退出**:

```rust
while ... {
    if !in_bounds { return None; }
    // ...
}
```

**2. `break` 退出循环**:

```rust
let mut result = None;
while ... {
    if !in_bounds { break; }
    if solid { result = Some(...); break; }
}
result
```

**3. `?` 操作符**(对 `Option` / `Result`):

```rust
fn raycast(...) -> Option<HitInfo> {
    let cx = ...?;
    // 如果 cx 是 None,整个函数立即返回 None
}
```

**4. `try_fold` / `try_for_each`**:函数式 early termination。

```rust
(0..N).try_fold(0, |acc, i| {
    if condition { None } else { Some(acc + i) }
});
```

Casey 用方式 1(直接 return),最清晰。

## 4 · 认知地图

### 4.1 上级

- **Early Termination** — 提前终止的所有方法
- **短路求值**(Short-circuit)— 满足条件立即停
- **优化**:不做无用功

### 4.2 同级(并行方案)

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| max_dist | t 上限 | 通用 | Day 590 |
| 边界检查 | 越界停 | 场景有限 | ✅ Day 602 |
| Shadow ray | 撞到即停 | 阴影测试 | 不用 |
| Coherent ray | 共享决策 | 大批量 | 不用 |

### 4.3 下级

- **is_in_bounds** — 边界检查
- **return None** — 退出函数
- **shadow ray** — 任何遮挡就停
- **branchless** — 用 select 替代 if

## 5 · 对照与变奏

### 同一 early termination 问题在不同语境下的变体

| 语境 | termination |
|---|---|
| 光线追踪 | 撞墙、出界、max_dist |
| 搜索算法 | 找到目标、超时 |
| 数据库查询 | LIMIT、short-circuit |
| 物理仿真 | 物体出界、能量耗尽 |
| 网络 | 连接断开、超时 |

每种都是"满足条件就停"。

### 历史演化

- **1970s**:光线追踪 max_dist
- **1980s**:Shadow ray
- **1990s**:Branchless ERT
- **2000s+**:Adaptive / Probabilistic termination

Casey 的 Day 602 是 1970-1980s 风格。

### CPU 分支预测 vs Early Termination

Early termination 加 if 分支,可能让 CPU 分支预测失败(50% 准确率 → 慢)。但"避免无用循环"的收益通常大于"分支预测失败"的代价。

实际测试:加 early termination,平均快 20-30%。

### Lv1 · 概念辨析

**题**:Early termination 的"边界检查"和"max_dist"有什么本质区别?为什么两者都需要?

**参考解答**:
- **边界检查**:检查光是否在场景内。一旦出界,光永远不会撞墙(场景外是空)。
- **max_dist**:检查光的累积距离。即使光在场景内,如果走得太远(超出光照影响范围),也应该终止。

两者都需要因为:
- 光在场景内,但走太远(max_dist 触发,边界检查未触发)
- 光出界,但 max_dist 未到(边界检查触发,max_dist 未触发)

只有两者结合才能覆盖所有"应该终止"的情况。

**参考解答**:

```rust
fn voxel_raycast_early_term(world: &World, ray: &Ray, max_dist: f32) -> Option<(i32, i32, i32, usize)> {
    let cell_size = 1.0;
    let mut cx = (ray.origin.x / cell_size).floor() as i32;
    let mut cy = (ray.origin.y / cell_size).floor() as i32;
    let mut cz = (ray.origin.z / cell_size).floor() as i32;
    
    let (dx, dy, dz) = (ray.dir.x, ray.dir.y, ray.dir.z);
    let step_x = if dx > 0.0 { 1 } else { -1 };
    let step_y = if dy > 0.0 { 1 } else { -1 };
    let step_z = if dz > 0.0 { 1 } else { -1 };
    
    let mut t_max_x = if dx.abs() > 1e-10 {
        ((cx + if dx > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin.x) / dx
    } else { f32::INFINITY };
    let mut t_max_y = if dy.abs() > 1e-10 {
        ((cy + if dy > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin.y) / dy
    } else { f32::INFINITY };
    let mut t_max_z = if dz.abs() > 1e-10 {
        ((cz + if dz > 0 { 1 } else { 0 }) as f32 * cell_size - ray.origin.z) / dz
    } else { f32::INFINITY };
    
    let t_delta_x = if dx.abs() > 1e-10 { (cell_size / dx).abs() } else { f32::INFINITY };
    let t_delta_y = if dy.abs() > 1e-10 { (cell_size / dy).abs() } else { f32::INFINITY };
    let t_delta_z = if dz.abs() > 1e-10 { (cell_size / dz).abs() } else { f32::INFINITY };
    
    let mut t = 0.0;
    let mut steps = 0;
    while t < max_dist {
        // Early termination:边界检查
        if !world.is_in_bounds(cx, cy, cz) {
            return None;
        }
        
        if world.is_solid(cx, cy, cz) {
            return Some((cx, cy, cz, steps));
        }
        
        steps += 1;
        
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            t = t_max_x;
            t_max_x += t_delta_x;
        } else if t_max_y < t_max_z {
            cy += step_y;
            t = t_max_y;
            t_max_y += t_delta_y;
        } else {
            cz += step_z;
            t = t_max_z;
            t_max_z += t_delta_z;
        }
    }
    None
}

// 给 World 加 is_in_bounds
impl World {
    fn is_in_bounds(&self, x: i32, y: i32, z: i32) -> bool {
        x >= 0 && y >= 0 && z >= 0 &&
        (x as usize) < self.dim && (y as usize) < self.dim && (z as usize) < self.dim
    }
}

fn main() {
    let world = World::new(32);  // 32x32x32 场景,没墙
    
    // 光朝场景外(从 (0,0,0) 朝 -x)
    let ray = Ray {
        origin: Vec3::new(0.5, 0.5, 0.5),
        dir: Vec3::new(-1.0, 0.0, 0.0),
    };
    
    let start = std::time::Instant::now();
    let result = voxel_raycast_early_term(&world, &ray, 1000.0);
    let elapsed = start.elapsed();
    println!("Out-of-bounds ray: {:?} in {:?}", result, elapsed);
    // 应该立即返回 None(< 1 µs)
}
```

## 8 · Rust / Arch 落地代码

完整可跑示例:

```rust
// (Vec3, World, Ray 同前几日)

fn benchmark_with_vs_without_early_term(world: &World) {
    // 1000 条朝天空的光线
    let n = 10000;
    let rays: Vec<Ray> = (0..n).map(|i| {
        let t = i as f32 * 0.001;
        Ray {
            origin: Vec3::new(0.5, 0.5, 0.5),
            dir: Vec3::new(t.sin() - 1.0, t.cos(), 0.5),  // 朝 -x 方向(出界)
        }
    }).collect();
    
    // 没 early term(模拟 day599 行为,假设 is_in_bounds 总 true)
    let start = std::time::Instant::now();
    let mut calls = 0;
    for ray in &rays {
        let mut cx = 0i32;
        let mut t = 0.0;
        while t < 1000.0 {
            // 不做边界检查,继续走
            cx -= 1;
            t += 1.0;
            calls += 1;
        }
        std::hint::black_box(cx);
    }
    let without_early = start.elapsed();
    println!("Without early-term: {:?} ({} calls)", without_early, calls);
    
    // 有 early term
    let start = std::time::Instant::now();
    let mut calls2 = 0;
    for ray in &rays {
        let mut cx = 0i32;
        let mut t = 0.0;
        loop {
            if cx < 0 || cx >= world.dim as i32 {
                break;  // early term
            }
            cx -= 1;
            t += 1.0;
            calls2 += 1;
            if t > 1000.0 { break; }
        }
        std::hint::black_box(cx);
    }
    let with_early = start.elapsed();
    println!("With early-term: {:?} ({} calls)", with_early, calls2);
    
    println!("Speedup: {:.1}x", without_early.as_secs_f64() / with_early.as_secs_f64());
}

fn main() {
    let world = World::new(32);
    benchmark_with_vs_without_early_term(&world);
}
```

## 10 · 补充材料:Light atlas 的工业级实现

### A.1 Light atlas 数据结构

Light atlas 是"3D 网格的光照值缓存"。Casey 在 phase-8 大量用,核心是:

```
World(3D voxel grid)
   ↓
For each voxel: 存 RGBE 光照值(4 字节)
   ↓
Light Atlas: Vec<u8>,尺寸 width × height × depth × 4
```

RGBE 编码:RGB + shared exponent。3 个 RGB 值 + 1 个 exponent 字节,共 4 字节。比 RGB float(12 字节)省 67%。

```rust
struct LightAtlas {
    width: u32,
    height: u32,
    depth: u32,
    data: Vec<u8>,  // RGBE 紧凑存储
}

impl LightAtlas {
    fn new(w: u32, h: u32, d: u32) -> Self {
        Self {
            width: w, height: h, depth: d,
            data: vec![0; (w * h * d * 4) as usize],
        }
    }
    
    fn get(&self, x: u32, y: u32, z: u32) -> [f32; 3] {
        let idx = ((z * self.height * self.width + y * self.width + x) * 4) as usize;
        let r = self.data[idx] as f32 / 255.0;
        let g = self.data[idx + 1] as f32 / 255.0;
        let b = self.data[idx + 2] as f32 / 255.0;
        let e = self.data[idx + 3] as i32;
        let scale = 2.0_f32.powi(e - 128);
        [r * scale, g * scale, b * scale]
    }
    
    fn set(&mut self, x: u32, y: u32, z: u32, rgb: [f32; 3]) {
        // 找最大通道,作为 exponent
        let max = rgb[0].max(rgb[1]).max(rgb[2]).max(1e-6);
        let e = (max.log2().ceil() as i32 + 128).clamp(0, 255) as u8;
        let scale = 1.0 / 2.0_f32.powi(e as i32 - 128);
        
        let idx = ((z * self.height * self.width + y * self.width + x) * 4) as usize;
        self.data[idx] = (rgb[0] * scale * 255.0) as u8;
        self.data[idx + 1] = (rgb[1] * scale * 255.0) as u8;
        self.data[idx + 2] = (rgb[2] * scale * 255.0) as u8;
        self.data[idx + 3] = e;
    }
}
```

### A.2 内存占用估算

32^3 voxel:
- RGB float(12 字节):32³ × 12 = 393 KB
- RGBE(4 字节):32³ × 4 = 131 KB
- RGBE + mipmap:131 KB × 1.33 ≈ 175 KB

64^3 voxel:
- RGBE:64³ × 4 = 1 MB
- 完整场景(256^3 voxel):256³ × 4 = 64 MB

工业游戏(Minecraft-like)用 32^3 chunk + streaming,避免一次加载整个场景。

### A.3 Light propagation 的算法

Casey 的 phase-8 是"light propagation"——光从光源向外传播。

**Direct light**:从太阳 / 灯直接照到的 voxel。
**Indirect light**:光从直接照到的 voxel 反弹到其他 voxel。
**Bounced light**:多次反弹的间接光。

实现:
```rust
fn propagate_light(world: &mut World, sun_dir: Vec3) {
    // 1. Direct light:对每个 voxel,从 voxel 向 sun 方向 raycast
    for z in 0..world.depth {
        for y in 0..world.height {
            for x in 0..world.width {
                let ray = Ray::new(voxel_center(x, y, z), sun_dir);
                if world.raycast_to_sun(ray).is_none() {
                    // 没被遮挡,直接被太阳照
                    world.light.set(x, y, z, sun_color);
                }
            }
        }
    }
    
    // 2. Indirect light:bounce propagation
    for bounce in 0..N_BOUNCES {
        let mut new_light = LightAtlas::clone(&world.light);
        for each voxel {
            // 累加邻居的光
            let neighbor_light = average_neighbors(&world.light, x, y, z);
            new_light.set(x, y, z, neighbor_light * bounce_factor);
        }
        world.light = new_light;
    }
}
```

这是 simplified irradiance propagation,真实实现更复杂(hemisphere sampling、visibility check 等)。

### A.4 Spherical harmonics(球谐函数)

每个 voxel 存"从所有方向来的光"是无穷维。简化用 Spherical Harmonics(SH):

- SH 是"球面函数的正交基",类似 Fourier 但在球面
- L2 SH = 9 个系数(3 RGB × 3 = 27 floats)
- 足够表达"低频光照"(漫反射)

```rust
struct SHLight {
    coeffs: [[f32; 9]; 3],  // RGB × 9 SH 系数
}
```

工业游戏(Halo 3、The Last of Us)用 SH light。Casey 的 HH 用简单的 RGB atlas,不用 SH。

### A.5 Lightmap baking

"baking"指预先计算光照,存到 atlas,运行时只查表。

```
开发期:
  Lightmap baking(几小时)
  → 生成 LightAtlas(几百 MB)
  → 打包到游戏

运行时:
  玩家走到 voxel (x,y,z)
  → 查 LightAtlas.get(x,y,z)
  → 用这个值渲染
```

优势:运行时极快(O(1) 查表)。劣势:场景静态,不能改光源位置。

动态光源(火把、闪光弹)用单独的"realtime lighting"系统,叠加到 baked light。

### A.6 Voxel cone tracing

Cone tracing 是 voxel lighting 的高级技术(Crytek 2010 论文):

```
对每个像素:
  从相机发射"光线"
  光线遇到 voxel → 查 atlas 取光照
  
但每像素 1000 条光线太慢。
改:用"cone"(锥)代替"ray",cone 半径随距离增长。
每个 cone 的"覆盖率"用 voxel mipmap 算。
```

Cone tracing 让"实时全局光照(GI)"成为可能。Unreal Engine 4 的 SVOGI(Sparse Voxel Octree GI)就是这个思路。

### A.9 Octahedral mapping(八面体编码)

Casey 在 phase-8 用 octahedral mapping——把 3D 单位向量(方向)映射到 2D 平面,用于 walk table 等数据结构。

```
3D 单位向量 (x, y, z),其中 x²+y²+z²=1
   ↓
2D 八面体坐标 (u, v),范围 [-1, 1]²
```

转换公式:

```rust
fn vec3_to_oct(v: Vec3) -> (f32, f32) {
    let n = v / (v.x.abs() + v.y.abs() + v.z.abs());
    if n.z >= 0.0 {
        (n.x, n.y)
    } else {
        let sign_x = if n.x >= 0.0 { 1.0 } else { -1.0 };
        let sign_y = if n.y >= 0.0 { 1.0 } else { -1.0 };
        ((1.0 - n.y.abs()) * sign_x, (1.0 - n.x.abs()) * sign_y)
    }
}

fn oct_to_vec3(u: f32, v: f32) -> Vec3 {
    let z = 1.0 - u.abs() - v.abs();
    if z < 0.0 {
        let sign_u = if u >= 0.0 { 1.0 } else { -1.0 };
        let sign_v = if v >= 0.0 { 1.0 } else { -1.0 };
        Vec3::new((1.0 - v.abs()) * sign_u, (1.0 - u.abs()) * sign_v, z)
    } else {
        Vec3::new(u, v, z)
    }.normalize()
}
```

优势:
- 双射(一一对应)
- 各向同性(球面均匀采样)
- 简单计算(加 / 减 / abs)

劣势:
- 上下半球切换有 singularity(z=0)
- 边界处理稍微复杂

Octahedral mapping 是 Engielhardt 2012 论文提出的,工业 GPU 渲染(IBL、precomputed radiance transfer)大量用。

### A.10 Precomputed Radiance Transfer(PRT)

PRT 是工业级 precomputed lighting:
- 离线计算每个 voxel 的"光传输函数"(如何接收各方向光)
- 用 SH 系数表达
- 运行时根据实际光源方向,用 SH 系数快速算 voxel 收到多少光

```
离线:
  for each voxel:
    sample N directions(蒙特卡洛)
    for each direction:
      raycast,记录是否被遮挡
    SH projection:把 visibility 函数转 SH 系数
  → 每 voxel 存 SH visibility(9 个 float × 3 RGB)

运行时:
  for each voxel:
    sky_light_SH = compute_sky_light_sh(sun_dir)  // 实时计算
    received_light = SH_dot(visibility_SH, sky_light_SH)  // SH 内积
    voxel.light = received_light
```

PRT 让"实时变化光源方向"成为可能——只需修改 sun_dir,所有 voxel 实时更新光照。代价:预计算耗时(几小时)、内存大(每 voxel 27 floats)。

Halo 3 是第一个商业 PRT 游戏(2007)。后续 Crysis、The Last of Us 都用变体。

### A.11 Lumen(Unreal Engine 5)

Lumen 是 Unreal 5 的 GI 系统,自动检测场景,组合多种技术:
- **Software ray tracing**(基于 SDF / voxel)
- **Hardware ray tracing**(RTX / RDNA2)
- **Screen-space GI**
- ** irradiance probes**

Lumen 自动选择最适合的技术,提供"real-time GI without baking"。但要求 GPU 强,且某些场景质量不如 baked。

 Casey 的 HH 是 CPU 实现,完全没法和 Lumen 比。但理解 Lumen 的"组合技术"思路重要。

### A.12 Voxel 数据的 streaming

大场景(几百万 voxel)不能一次加载。streaming 方案:

```
Chunked voxel world:
  world = hash_map<(i32, i32, i32), VoxelChunk>
  
  VoxelChunk = 32^3 voxel + light atlas
  
  玩家移动:
    加载附近 chunk
    卸载远处 chunk(LRU)
```

每 chunk 独立处理(light propagation、culling),避免一次算整个世界。这是 Minecraft、7 Days to Die 等 voxel 游戏的标准架构。

Casey 的 HH 是 single chunk(整个世界一个 atlas),适合教学。生产 voxel 游戏 streaming 必须。

### A.13 总结

Light atlas / voxel lighting 是工业级 GI 的基础。技术谱系:

```
基础(Casey HH):
  RGB atlas + direct + few bounces
  → 简单,慢但够教学

中端(Halo 3、Crysis):
  SH atlas + PRT
  → 预计算 + 实时方向光

高端(Unreal Lumen):
  实时 SDF / voxel ray tracing
  → 实时 GI,无 baking

极致(Minecraft RTX):
  Full path tracing on RTX
  → 真实光传播,极致画质
```

每代技术对硬件要求递增。Casey 教基础,你看高清游戏时能理解"为什么那样实现"。
