# Day 579 · 调试八面体着色

> 八面体编码、采样、边界 wrap 都写完了,接进游戏后墙角仍然出现奇怪的暗斑和接缝。Casey 这一天不开新主题——他演示"如何用系统化方法定位渲染 bug"。这一集的价值不在"修一个 bug",而在"修 bug 的方法论"。

## 0 · 为什么要有这一天

你已经写了 1000 多行 Rust 代码、跑了 unit test、做了边界 wrap,按理说该 work 了。但接进游戏,你看到的是这样的画面:墙上有一道明亮的接缝,从左到右贯穿整面墙;天花板角落有黑色斑点;玩家转身时,墙面光照"闪烁"。

这些是渲染领域最阴险的 bug 类型:**视觉伪影(visual artifact)**。它们的恶心之处在于:
- **不是崩溃**:没有 panic,没有 assert,程序跑得好好的
- **不是计算错误**:每个数值看起来都对(误差在 1e-6 以内)
- **是数据组合错误**:某个 texel 的值在某些采样方向下看起来不对,但你单独检查每个 texel 都是合理的
- **是边界条件**:bug 只在"方向贴着边界"或"恰好穿过赤道"时出现

修这类 bug 的关键不是"写更多代码",而是"用工具把抽象数据变成可见的"。Casey 这一天演示了**渲染调试的标准方法**:

1. **可视化数据**:不要看数字,看图。把每个体素的辐射场渲染成一个小球,贴到 3D 场景里。
2. **逐通道检查**:把 RGB 拆开,只看红通道。如果红通道有 bug,绿蓝都好,问题就锁定在红通道。
3. **二分查找**:把游戏时间倒带,找到 bug 第一次出现的帧。
4. **简化复现**:把"完整游戏"裁剪成"最小复现 demo",能 100% 触发 bug 的最小场景。

这一天的工程产出是一个 debug overlay 渲染器,价值是**让你看到光照数据**。

心理锚点:看完这集,你能在游戏里加一个 debug overlay,按 F1 显示所有体素的辐射场可视化,按 F2 切换到 R/G/B 单通道。能解释"为什么数字看起来对、画面却错"的几种原因。修渲染 bug 不再是"瞎猜"。

## 1 · Casey 今天做了什么

Casey 这一天做的几件事:

1. **观察问题**:他注意到游戏里墙角有暗斑,玩家转身有闪烁。他知道这是八面体采样的 bug,但不知道具体哪个 texel 出错。
2. **加 debug overlay**:他在游戏渲染循环里加一段代码——对每个体素,在 3D 场景对应位置画一个小立方体,小立方体的 6 个面用八面体贴图采样照亮。
3. **可视化辐射场**:更狠的一招——他把每个体素的辐射场"球面可视化":在体素位置画一个半径 0.1m 的小球,球的每个 texel 颜色 = 该方向采样的辐射值。这样他能直接"看到"八面体贴图长什么样。
4. **定位 bug**:看到可视化球后,他立刻发现某个体素的辐射场有"突变"——某个 texel 是亮的,周围全是黑。这表明采样时该 texel 被错位采到了对面的方向。
5. **修 bug**:问题在 `wrap_uv` 函数的 4 条边处理逻辑里,某条边的镜像规则写错了。修一行代码,bug 消失。

这一天的工程产出大约 60 行 Rust 代码(主要是 debug overlay),价值在于**让不可见的数据变得可见**。

## 2 · 心智模型

### 类比:医生看 X 光

医生看病人说"胸口疼",他能听到主诉,但看不到内部。他开 X 光单,机器照出一张图,他指着图说"这里有一团阴影,可能是肿瘤"。X 光把"内部不可见的状态"映射到"可见的图像",诊断才有可能。

渲染调试完全一样。玩家看到"墙角闪烁"是主诉,但程序内部每个 texel 的数值是"不可见的状态"。要把它们变成图像,需要"渲染调试工具":

- **辐射场可视化球**(Casey 用):每个体素一个小球,球面颜色 = 辐射场
- **热力图**:把每个 texel 的某个标量(如亮度)映射到颜色梯度,亮 = 红,暗 = 蓝
- **单通道显示**:只看 R 通道,把 G/B 强制为 0。这样能定位"是不是某个通道出问题"
- **线框模式**:把三角形画成线框,看几何是否正确

### 严谨原理:渲染调试工具箱

**工具 1:可视化球**。对每个体素中心位置 `pos`,画一个半径 `r` 的小球。球的每个像素位置对应的"方向"`dir = (pixel - pos).normalize()`,从该体素的辐射场采样 `atlas.sample(dir)`,作为像素颜色。

```rust
fn render_debug_sphere(atlas: &LightAtlas, pos: Vec3, framebuffer: &mut Framebuffer) {
    let r = 0.1;  // 小球半径,世界坐标
    // 对每个像素,检查它是否在小球上
    for py in 0..framebuffer.height() {
        for px in 0..framebuffer.width() {
            let ray = framebuffer.camera_pixel_ray(px, py);
            let hit = ray_sphere_intersect(ray, pos, r);
            if let Some(t) = hit {
                let hit_pos = ray.origin + ray.dir * t;
                let normal = (hit_pos - pos).normalize();
                let color = atlas.sample(normal);
                framebuffer.put(px, py, color);
            }
        }
    }
}
```

**工具 2:热力图**。把标量(如辐射场平均亮度)映射到颜色梯度:

```rust
fn scalar_to_heatmap(v: f32) -> RGB32F {
    // v ∈ [0, 1]
    if v < 0.25 {
        // 蓝 → 青
        RGB32F::new(0.0, v * 4.0, 1.0)
    } else if v < 0.5 {
        // 青 → 绿
        RGB32F::new(0.0, 1.0, 1.0 - (v - 0.25) * 4.0)
    } else if v < 0.75 {
        // 绿 → 黄
        RGB32F::new((v - 0.5) * 4.0, 1.0, 0.0)
    } else {
        // 黄 → 红
        RGB32F::new(1.0, 1.0 - (v - 0.75) * 4.0, 0.0)
    }
}
```

**工具 3:二分查找 bug 帧**。如果 bug 是"玩家转身时出现",你不知道是哪一帧产生的:

```rust
// 在 main loop 里,每 60 帧存一次"游戏状态快照"

}

// 发现 bug 后,二分查找:
// 1. 加载 snapshots[N/2],从那里跑到出现 bug
// 2. bug 在前半段还是后半段?
// 3. 递归
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,渲染调试是一门独立学问。商业引擎都内置工具:

- **Unreal Engine**:GBuffer Visualization(M、Roughness、Specular、Normal 各一张图)
- **Unity**:Frame Debugger(逐 draw call 看渲染过程)
- **RenderDoc**:开源,几乎业界标准,抓一帧 → 看 shader 输入输出 → 找 bug

Casey 用的是"手写 debug overlay",因为他在做教学,要让你看到原理。生产代码不会自己写 overlay——直接接 RenderDoc。

游戏开发圈修 bug 的常见思路:

1. **Bisect**:用 `git bisect` 二分查找代码改动,哪个 commit 引入 bug
2. **Print debugging**:打 `eprintln!`,看变量值。简单粗暴但有效
3. **Assertions**:在游戏循环里加 `assert!(check_invariant());`,违反不变量立刻 panic
4. **Visualizations**:本节讲的 debug overlay

Casey 用 1+4,前者定位时间,后者定位空间。

### 3.2 · 🎨 图形学视角

图形学调试的关键挑战:**数据量太大**。一帧 1080p 画面有 200 万像素,每像素几十个中间值(位置、法线、UV、颜色、深度),总量上亿。直接看数字不可能,必须可视化。

**标准可视化技术**:
- **Normal 可视化**:法线 `(x, y, z)` 映射到颜色 `((x+1)/2, (y+1)/2, (z+1)/2)`,这样 +x 是红,+y 是绿,+z 是蓝。看图立刻知道哪些面朝哪。
- **Depth 可视化**:深度 `z` 线性映射到灰度,近 = 白,远 = 黑。能看出 clipping 问题。
- **UV 可视化**:UV `(u, v)` 映射到红绿,看 UV 是否合理铺开。

Casey 这一天做的是"辐射场可视化"——一种领域特定的可视化(只用在光照探针调试)。

### 3.4 · 🦀 Rust 生态视角

Rust 表达"调试可视化"有几个 Rust 特有的优雅方式:

**方式 1:Trait-driven**。定义 `trait DebugVisualizable`,任何实现了它的类型都能被渲染到 debug overlay:

```rust
trait DebugVisualizable {
    fn render_debug(&self, ctx: &mut DebugContext);
}

impl DebugVisualizable for LightAtlas {
    fn render_debug(&self, ctx: &mut DebugContext) {
        // 在 ctx 里画一个可视化球
        ctx.draw_sphere_with_lighting(self);
    }
}
```

这样游戏代码里加一个 `if debug_mode { atlas.render_debug(&mut ctx); }`,所有可调试类型都自动支持。

**方式 2:Derive macro**。用 `#[derive(Debug)]` 类似的方式,自动生成可视化代码。但 Rust 标准库的 `Debug` 只生成字符串,不画图。需要第三方 macro crate。Casey 不用,因为他的可视化逻辑太定制。

**方式 3:Conditional compilation**。用 `#[cfg(feature = "debug_visuals")]` 让 debug 代码只在 debug build 里编译:

```rust
#[cfg(feature = "debug_visuals")]
fn render_debug_sphere(...) { ... }

// Cargo.toml:
// [features]
// debug_visuals = []
```

发布 build 不编译 debug 代码,二进制更小、运行更快。Casey 在 day579 用 cfg 控制。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:渲染 bug 和"计算 bug"(如算错账)有什么本质不同?为什么渲染 bug 需要可视化工具,而计算 bug 用 print 就够?

**参考解答**:计算 bug 通常涉及少量数值(几个浮点),print 出来肉眼看就能发现"这里应该 1.0 怎么是 0.99"。渲染 bug 涉及大量数据(百万像素、上千 texel),print 不出来——即使 print 出来,人眼看不出规律。可视化把"大量数据"映射到"二维图像",人眼擅长识别图像中的"模式"和"突变",这是数据维度降到适合人脑处理的形式。

更深一层:渲染 bug 往往不是"算错",而是"组合错"——每个数值单独看都对,但放在特定采样方向、特定 texel 邻居下,视觉效果错。这种 bug 必须在"完整数据集"上才能定位,单个数值检查无用。

### Lv2 · 动手实践

**题**:在 day578 的基础上,加一个 `render_debug_sphere(atlas, framebuffer, pos)`,把 atlas 的辐射场画到 framebuffer 上。具体步骤:
- 实现一个简化的"球面投影":对每个屏幕像素,假设对应一个方向 `dir = pixel_to_dir(px, py)`,采 atlas,写回 framebuffer
- 给定一个 atlas,在屏幕上画一张 16×16 的"贴图直出"(把 atlas 直接当成贴图显示)

完成标准:运行后看到 16×16 的彩色贴图显示在屏幕一角,或看到一张球面化的可视化。

**参考解答**:

```rust
// 简化:把 atlas 当成 16×16 的彩色贴图直接显示
fn render_atlas_direct(atlas: &LightAtlas, framebuffer: &mut Framebuffer, x0: usize, y0: usize) {
    for ty in 0..atlas.dim {
        for tx in 0..atlas.dim {
            let color = atlas.texels[ty * atlas.dim + tx];
            // RGB32F → 屏幕 RGB888
            let r = (color.r.clamp(0.0, 1.0) * 255.0) as u8;
            let g = (color.g.clamp(0.0, 1.0) * 255.0) as u8;
            let b = (color.b.clamp(0.0, 1.0) * 255.0) as u8;
            framebuffer.put_pixel(x0 + tx, y0 + ty, r, g, b);
        }
    }
}

// 球面可视化:每个屏幕像素对应一个方向
fn render_atlas_on_sphere(atlas: &LightAtlas, framebuffer: &mut Framebuffer, cx: f32, cy: f32, r: f32) {
    for py in 0..framebuffer.height() {
        for px in 0..framebuffer.width() {
            let dx = (px as f32 - cx) / r;
            let dy = (py as f32 - cy) / r;
            let r2 = dx * dx + dy * dy;
            if r2 > 1.0 { continue; }  // 球外
            // 投影到球面:z = sqrt(1 - x² - y²)
            let z = (1.0 - r2).sqrt();
            let dir = Vec3 { x: dx, y: -dy, z };  // 屏幕 y 反向(下为正)
            let color = atlas.sample_with_wrap(dir.normalize());
            let r = (color.r.clamp(0.0, 1.0) * 255.0) as u8;
            let g = (color.g.clamp(0.0, 1.0) * 255.0) as u8;
            let b = (color.b.clamp(0.0, 1.0) * 255.0) as u8;
            framebuffer.put_pixel(px, py, r, g, b);
        }
    }
}
```

**每行解释**:
- `clamp(0.0, 1.0)` — 把辐射值钳到 [0, 1],因为辐射可能 > 1(HDR)。转 8 位时再 * 255。
- `(1.0 - r2).sqrt()` — 球面投影:在屏幕上的圆盘到球面 z 坐标。这是正交投影(不是透视)。
- `dir.y = -dy` — 屏幕 y 朝下为正,3D y 朝上为正,反向。

// Cargo.toml:无依赖

#[derive(Copy, Clone, Debug, Default)]
struct RGB32F { r: f32, g: f32, b: f32 }
impl RGB32F {
    fn new(r: f32, g: f32, b: f32) -> Self { Self { r, g, b } }
    fn add(self, o: Self) -> Self { Self::new(self.r+o.r, self.g+o.g, self.b+o.b) }
    fn scale(self, k: f32) -> Self { Self::new(self.r*k, self.g*k, self.b*k) }
}

struct Framebuffer {
    width: usize,
    height: usize,
    pixels: Vec<(u8, u8, u8)>,
}

impl Framebuffer {
    fn new(w: usize, h: usize) -> Self {
        Self { width: w, height: h, pixels: vec![(0, 0, 0); w * h] }
    }
    fn put_pixel(&mut self, x: usize, y: usize, r: u8, g: u8, b: u8) {
        if x < self.width && y < self.height {
            self.pixels[y * self.width + x] = (r, g, b);
        }
    }
    fn save_ppm(&self, path: &str) {
        // PPM 是最简单的图像格式,首行 P3,然后宽高和最大值,然后 RGB 三元组
        use std::io::Write;
        let mut f = std::fs::File::create(path).unwrap();
        writeln!(f, "P3\n{} {}\n255", self.width, self.height).unwrap();
        for (r, g, b) in &self.pixels {
            write!(f, "{} {} {}\n", r, g, b).unwrap();
        }
    }
}

// (Vec3, encode_octahedral, wrap_uv, LightAtlas 同 day578)

fn main() {
    // 创建 atlas,放几个测试光
    let mut atlas = LightAtlas::new(16);
    atlas.accumulate(Vec3 { x: 0.0, y: 0.0, z: 1.0 }.normalize(), RGB32F::new(1.0, 0.0, 0.0));
    atlas.accumulate(Vec3 { x: 1.0, y: 0.0, z: 0.0 }.normalize(), RGB32F::new(0.0, 1.0, 0.0));
    atlas.accumulate(Vec3 { x: 0.0, y: 1.0, z: 0.0 }.normalize(), RGB32F::new(0.0, 0.0, 1.0));
    atlas.accumulate(Vec3 { x: -1.0, y: 0.0, z: 0.0 }.normalize(), RGB32F::new(1.0, 1.0, 0.0));
    atlas.accumulate(Vec3 { x: 0.0, y: -1.0, z: 0.0 }.normalize(), RGB32F::new(1.0, 0.0, 1.0));

    // 1. 直接把 atlas 当贴图显示
    let mut fb1 = Framebuffer::new(16, 16);
    for ty in 0..16 {
        for tx in 0..16 {
            let c = atlas.texels[ty * 16 + tx];
            let r = (c.r.clamp(0.0, 1.0) * 255.0) as u8;
            let g = (c.g.clamp(0.0, 1.0) * 255.0) as u8;
            let b = (c.b.clamp(0.0, 1.0) * 255.0) as u8;
            fb1.put_pixel(tx, ty, r, g, b);
        }
    }
    fb1.save_ppm("/tmp/atlas_direct.ppm");
    println!("Saved atlas_direct.ppm (open with `feh /tmp/atlas_direct.ppm`)");

    // 2. 把 atlas 投到球面上显示
    let mut fb2 = Framebuffer::new(200, 200);
    for py in 0..200 {
        for px in 0..200 {
            let dx = (px as f32 - 100.0) / 100.0;
            let dy = (py as f32 - 100.0) / 100.0;
            let r2 = dx * dx + dy * dy;
            if r2 > 1.0 { continue; }
            let z = (1.0 - r2).sqrt();
            let dir = Vec3 { x: dx, y: -dy, z };
            let c = atlas.sample_with_wrap(dir.normalize());
            let r = (c.r.clamp(0.0, 1.0) * 255.0) as u8;
            let g = (c.g.clamp(0.0, 1.0) * 255.0) as u8;
            let b = (c.b.clamp(0.0, 1.0) * 255.0) as u8;
            fb2.put_pixel(px, py, r, g, b);
        }
    }
    fb2.save_ppm("/tmp/atlas_sphere.ppm");
    println!("Saved atlas_sphere.ppm");
}

### A.11 完整 Rust voxel lighting 实现

让我提供一个完整的 Rust voxel lighting 实现示例,综合前面所有概念:

```rust
use std::collections::HashMap;

const CHUNK_SIZE: u32 = 32;

struct Voxel {
    material: u8,
    color: [u8; 3],
}

struct Chunk {
    voxels: Vec<Voxel>,
    light: Vec<[u8; 4]>,  // RGBE
}

struct World {
    chunks: HashMap<(i32, i32, i32), Chunk>,
    sun_dir: Vec3,
    sun_color: [f32; 3],
}

impl World {
    fn get_voxel(&self, x: i32, y: i32, z: i32) -> Option<&Voxel> {
        let (cx, cy, cz) = (x.div_euclid(CHUNK_SIZE as i32), 
                            y.div_euclid(CHUNK_SIZE as i32),
                            z.div_euclid(CHUNK_SIZE as i32));
        let chunk = self.chunks.get(&(cx, cy, cz))?;
        let (lx, ly, lz) = (x.rem_euclid(CHUNK_SIZE as i32) as usize,
                            y.rem_euclid(CHUNK_SIZE as i32) as usize,
                            z.rem_euclid(CHUNK_SIZE as i32) as usize);
        let idx = lz * (CHUNK_SIZE as usize).pow(2) + ly * CHUNK_SIZE as usize + lx;
        Some(&chunk.voxels[idx])
    }
    
    fn is_solid(&self, x: i32, y: i32, z: i32) -> bool {
        self.get_voxel(x, y, z).map(|v| v.material != 0).unwrap_or(false)
    }
}

fn grid_dda(world: &World, start: Vec3, dir: Vec3, max_dist: f32) -> bool {
    let mut cx = start.x.floor() as i32;
    let mut cy = start.y.floor() as i32;
    let mut cz = start.z.floor() as i32;
    
    let step_x = if dir.x > 0.0 { 1 } else { -1 };
    let step_y = if dir.y > 0.0 { 1 } else { -1 };
    let step_z = if dir.z > 0.0 { 1 } else { -1 };
    
    let t_delta_x = if dir.x.abs() > 1e-10 { 1.0 / dir.x.abs() } else { f32::INFINITY };
    let t_delta_y = if dir.y.abs() > 1e-10 { 1.0 / dir.y.abs() } else { f32::INFINITY };
    let t_delta_z = if dir.z.abs() > 1e-10 { 1.0 / dir.z.abs() } else { f32::INFINITY };
    
    let mut t_max_x = if dir.x.abs() > 1e-10 {
        (((cx + if dir.x > 0 { 1 } else { 0 }) as f32) - start.x) / dir.x
    } else { f32::INFINITY };
    let mut t_max_y = /* similar */;
    let mut t_max_z = /* similar */;
    
    let mut t = 0.0;
    while t < max_dist {
        if world.is_solid(cx, cy, cz) {
            return true;  // occluded
        }
        
        if t_max_x < t_max_y && t_max_x < t_max_z {
            cx += step_x;
            t = t_max_x;
            t_max_x += t_delta_x;
        } else if t_max_y < t_max_z {
            cy += step_y;
            t = t_max_y;
            t_max_y += t_delta_y;
        } else {
            cz += step_z;
            t = t_max_z;
            t_max_z += t_delta_z;
        }
    }
    false
}

fn compute_direct_lighting(world: &World, x: i32, y: i32, z: i32) -> [f32; 3] {
    let voxel_pos = Vec3::new(x as f32 + 0.5, y as f32 + 0.5, z as f32 + 0.5);
    
    // 是否被遮挡
    if grid_dda(world, voxel_pos, world.sun_dir, 100.0) {
        return [0.0; 3];  // 阴影
    }
    
    // Lambert 光照
    let normal = compute_normal(world, x, y, z);
    let lambert = normal.dot(world.sun_dir).max(0.0);
    
    [
        world.sun_color[0] * lambert,
        world.sun_color[1] * lambert,
        world.sun_color[2] * lambert,
    ]
}

fn compute_normal(world: &World, x: i32, y: i32, z: i32) -> Vec3 {
    let dx = if world.is_solid(x-1, y, z) { 1.0 } else { 0.0 } 
           - if world.is_solid(x+1, y, z) { 1.0 } else { 0.0 };
    let dy = if world.is_solid(x, y-1, z) { 1.0 } else { 0.0 }
           - if world.is_solid(x, y+1, z) { 1.0 } else { 0.0 };
    let dz = if world.is_solid(x, y, z-1) { 1.0 } else { 0.0 }
           - if world.is_solid(x, y, z+1) { 1.0 } else { 0.0 };
    
    Vec3::new(dx, dy, dz).normalize()
}
```
