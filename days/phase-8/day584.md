# Day 584 · 启用无限弹射光照

> 这是 Phase 8 的里程碑日。八天的工作——八面体编码、采样、卷积、重构——今天汇成一件事:让光在场景里无限次弹射。这是 Handmade Hero 的核心 GI 功能,完成后游戏的视觉品质从"扁平"跃升到"有空间感"。

## 0 · 为什么要有这一天

光在真实世界中是**无限弹射**的——阳光照到地板,地板反射一部分到墙,墙反射到天花板,天花板反射到玩家眼睛。每一次反射都改变光的方向和颜色,经过无数次后,场景中每个角落都有"间接光"贡献。

之前 Casey 的光照系统做了 **0-1 bounce**:
- 0 bounce:只有直接光(光源 → 物体 → 眼睛),墙角是黑的
- 1 bounce:直接光 + 一次间接(光源 → 物体 A → 物体 B → 眼睛),墙角有微弱亮度

但真实场景需要 **多 bounce**——阳光照到地板,地板反射到墙,墙再反射到墙角,墙角才够亮。数学上,无限弹射的解是辐射度方程的不动点(fixed point):

```
B = E + ρ × Σ F_ij × B_j
```

其中 `B_i` 是面 i 的辐射度,`E_i` 是面 i 的自发光,`ρ` 是反射率,`F_ij` 是形状因子(面 i 看见面 j 的比例)。解这个方程的标准方法是**迭代**(Gauss-Seidel / Jacobi):

```
B^(n+1) = E + ρ × Σ F_ij × B^(n)
```

迭代到收敛(变化 < ε),得到无限弹射的近似解。Casey 这一天**启用**这个迭代——让游戏循环每帧跑 N 次迭代,逐步收敛到"接近无限弹射"的视觉效果。

**为什么这是里程碑?** 0-1 bounce 渲染看起来"还行"——你能看到场景,有阴影,有光照。但无限弹射让场景"有空间感"——墙角自然变暗,光线穿过窗户自然散开,白色房间比黑色房间更"亮"(反射光的累积)。这是 GI 的核心,没有 GI 的游戏看起来"假"。

心理锚点:看完这集,你能用 Rust 实现一个迭代辐射度求解器,知道每次迭代做什么、收敛条件是什么、为什么 8-16 次迭代就够。能解释 0 bounce、1 bounce、N bounce、无限 bounce 的视觉差别。

## 1 · Casey 今天做了什么

Casey 这一天的几个动作:

1. **从 0-1 bounce 切换到 N bounce**:之前 `propagate_indirect` 每帧跑一次(1 bounce)。Casey 改成跑 N 次(N 是迭代数),每次都用上一次的结果作为输入。
2. **加收敛检测**:如果两次迭代的最大差值 < ε,提前终止。但 Casey 实际发现"固定 8 次"已经够收敛,加检测反而增加复杂度,所以用固定 8 次。
3. **解决数据竞争**:迭代需要"读上一次结果 + 写这一次结果"。Casey 用 double-buffering——两个 atlas 数组,读 buffer A 写 buffer B,下一次反过来。
4. **测试**:加一个 debug overlay 显示"bounce count"——按 F1 显示 1 bounce,按 F2 显示 2 bounce,...,按 F9 显示 9 bounce。玩家能直观看到不同弹射数的视觉差别。

这一天的工程产出大约 200 行 Rust 代码(包括 double-buffering、迭代循环、debug overlay),是 Phase 8 的核心里程碑。

## 2 · 心智模型

### 类比:池塘里的涟漪

你扔一颗石头到池塘里,水面起涟漪。涟漪向四周扩散,遇到岸边反射回来,反射的涟漪再反射……理论上无穷多次。

每次涟漪经过,水面"状态"都变。我们用计算机模拟时,不可能真做无穷多次——做有限次,看水面状态逼近最终稳定状态。每次模拟叫"一次迭代",迭代次数越多,越接近最终状态。

光照的"无限弹射"完全一样——光在场景里弹射无穷多次,场景的"光照状态"逐步逼近稳定。我们做有限次迭代(8-16),让视觉接近稳定。

### 严谨原理:辐射度方程

**完整方程**(对所有面 i):

```
B_i = E_i + ρ_i × Σ_j F_ij × B_j
```

**每项解释**:
- `B_i` — 面 i 的辐射度(每平方米每秒辐射能量)。这是我们要求的未知数。
- `E_i` — 面 i 的自发光(光源的发光量)。已知(由场景的灯光决定)。
- `ρ_i` — 面 i 的反射率(0 到 1)。已知(由材质决定)。
- `F_ij` — 形状因子(form factor),从面 i 看见面 j 的比例。已知(由几何决定)。
- `Σ_j F_ij` — 对所有其他面 j 求和。

**关键观察**:这是一个**线性方程组**(N 个未知数,N 个方程)。N 等于场景面数,通常几万到几百万。直接求解(Gauss 消元)O(N³) 不现实。

**迭代求解**(Gauss-Seidel):

```
for each iteration:
    for each face i:
        B_i_new = E_i + ρ_i × Σ_j F_ij × B_j_old
    B_old = B_new
```

每次迭代用旧的 B 算新的 B。**收敛性**:对于物理合理的场景(所有 ρ_i < 1),Gauss-Seidel 必然收敛到方程的真解。

**收敛速度**:取决于最大反射率 ρ_max。ρ_max = 0.5 收敛快(几次迭代),ρ_max = 0.9 收敛慢(几十次)。游戏场景一般 ρ_max ≤ 0.8,8-16 次迭代够。

### Casey 的实现

Casey 不是直接用辐射度方程——他用**体素化辐射场**(每个体素一个 atlas)。每个 atlas 等价于"一群面"(对应于该体素周围的所有方向)。Casey 的迭代:

```rust
fn propagate_infinite_bounces(world: &mut World, iterations: usize) {
    // Double-buffering:read_buffer 和 write_buffer
    let mut read_buffer = world.atlases.clone();
    let mut write_buffer = world.atlases.clone();

    propagate_direct_light(&mut write_buffer);  // E_i 项

    for _ in 0..iterations {
        std::mem::swap(&mut read_buffer, &mut write_buffer);
        // write_buffer 现在是旧数据,要被覆盖
        for i in 0..world.voxels.len() {
            let incoming = gather_incoming_light(&read_buffer, i);
            write_buffer[i] = incoming;
        }
    }

    world.atlases = write_buffer;
}
```

**每行解释**:
- `propagate_direct_light(&mut write_buffer)` — 初始化,把直接光注入辐射场。对应方程里的 `E_i`。
- `std::mem::swap` — 高效交换两个 buffer,read 变 write,write 变 read。这是 double-buffering 的核心。
- `gather_incoming_light(&read_buffer, i)` — 从其他体素的 atlas 采样到体素 i。对应方程里的 `Σ_j F_ij × B_j`。
- `iterations` — 8 或 16,工程权衡。

**注意**:这里没显式 `ρ_i`(反射率),它在 `gather_incoming_light` 内部——采样的光颜色已经乘了反射率(因为材质的 albedo 在采样时混合)。

### Double-buffering 的必要性

为什么需要两个 buffer?考虑单 buffer:

```rust
for i in 0..N {
    let incoming = gather_incoming(&world.atlases, i);
    world.atlases[i] = incoming;  // 覆盖了!
}
```

问题:当 i=5 时,我们读 atlas[0..N] 算 atlas[5]。但 atlas[0..4] 已经被这一轮迭代更新了——我们读的是"新值"和"旧值"的混合!这是 Jacobi 迭代(同步)和 Gauss-Seidel 迭代(异步)的差别。

Jacobi(同步,Casey 用):

```
读所有旧值,算所有新值,统一覆盖
需要两个 buffer
```

Gauss-Seidel(异步):

```
读"部分新部分旧"的值,算一个新值,立即覆盖
只需一个 buffer,收敛快 2 倍
```

Gauss-Seidel 看起来"更优",但**不能并行**(因为更新顺序影响结果)。Casey 想并行(后面 Day 590+ 用 rayon),所以选 Jacobi。这是工程权衡。

### 迭代次数 vs 视觉效果

```rust
fn render(world: &World, bounces: usize) {
    let mut atlases = world.atlases.clone();
    propagate_direct(&mut atlases);
    for _ in 0..bounces {
        let mut new_atlases = atlases.clone();
        for i in 0..atlases.len() {
            new_atlases[i] = gather_incoming(&atlases, i);
        }
        atlases = new_atlases;
    }
    draw_screen(atlases);
}
```

**视觉差别**:
- 0 bounce:只有直接光,墙角全黑
- 1 bounce:墙角有微弱亮度,但仍然偏暗
- 2 bounce:墙角明显亮一些
- 4 bounce:接近最终效果
- 8+ bounce:肉眼看不出差别

Casey 用 8 bounce 作为最终质量标准,调试时用 debug overlay 比较。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,无限弹射 GI 是商业引擎的核心卖点。UE5 的 Lumen、Unity 的 Enlighten 都是 GI 解决方案。

**实时 vs 离线 GI**:
- **离线**(Enlighten、Lightmapper):预先计算(几分钟到几小时),运行时只采样
- **实时**(Lumen、DDGI):每帧重算,代价大但响应动态场景

Casey 的实现是**实时 GI 简化版**——每帧迭代 8 次,但不是每帧全部更新(用 round-robin 调度)。

**踩过的坑**:
- **收敛抖动**:如果迭代次数变化(有时 8 次有时 9 次),画面会闪烁。解决:固定迭代次数
- **能量泄漏**:浮点累加让总能量逐渐增大(超出物理范围)。解决:加能量归一化
- **多重 bounce 重复**:同一条光线在两个相邻 atlas 间反复弹射,可能形成"光线陷阱"。解决:限制迭代次数

### 3.2 · 🎨 图形学视角

辐射度方法(Radiosity)是 1984 年由 Goral 等人从热传导方程借用过来的。它假设所有面是 Lambert(漫反射),没有镜面。优点:数学清晰、收敛确定。缺点:不能处理镜面、动态场景难。

**Radiosity vs Path Tracing**:
- **Radiosity**:解线性方程组,精确求解漫反射 GI,慢
- **Path Tracing**:蒙特卡洛采样,统计近似所有 GI 类型(漫反射、镜面、焦散),需要大量样本

Path Tracing 是电影工业标准(《阿凡达》《玩具总动员 4》都用),但游戏不能实时跑。Casey 用 Radiosity 是教学选择——算法清晰、能实时。

**Path Tracing 视角**:Casey 的"迭代 8 次"等价于 Path Tracing 的"8 个 bounce 深度"。差别在于 Path Tracing 用随机采样(每像素 N 条路径),Radiosity 用全方向确定性积分(每个 atlas texel 一条路径)。

### 3.3 · 🐧 Linux 系统编程视角

无限弹射 GI 在 Linux 上的几个性能点:

**内存带宽**:每帧 8 次迭代 × 1000 个体素 × 256 texel × 12 字节 = 24 MB/帧。60 FPS = 1.4 GB/s。这超过 L3 cache,主存带宽紧张。优化:用 RGB16F(每 texel 6 字节,带宽减半)。

**多线程**:Jacobi 迭代可完美并行(每个体素独立更新)。Casey 在 Day 590+ 用 rayon:

```rust
use rayon::prelude::*;

let new_buffer: Vec<_> = read_buffer.par_iter().enumerate().map(|(i, _)| {
    gather_incoming_light(&read_buffer, i)
}).collect();
```

8 核 CPU 加速约 6-7 倍(理论 8 倍,实际有同步开销)。

Linux 上验证并行:

```bash
sudo pacman -S htop

# 跑游戏时看 CPU 利用率

```

### 3.4 · 🦀 Rust 生态视角

Rust 实现 double-buffering 时,有个所有权陷阱:

```rust
// 错误:不能同时 &mut 两次 self
fn swap_buffers(&mut self) {
    let tmp = self.buffer_a;
    self.buffer_a = self.buffer_b;
    self.buffer_b = tmp;  // 错误!
}
```

Rust 的借用检查拒绝"同时 &mut 多个字段"。解决:

```rust
// 方案 1:std::mem::swap
fn swap_buffers(&mut self) {
    std::mem::swap(&mut self.buffer_a, &mut self.buffer_b);
}

// 方案 2:解构 self
fn swap_buffers(&mut self) {
    let Self { buffer_a, buffer_b, .. } = self;
    std::mem::swap(buffer_a, buffer_b);
}

// 方案 3:用 tuple
struct World {
    buffers: (Vec<LightAtlas>, Vec<LightAtlas>),
}
fn swap_buffers(&mut self) {
    std::mem::swap(&mut self.buffers.0, &mut self.buffers.1);
}
```

Casey 用方案 1。

**性能**:Vec<LightAtlas> 的 `clone()` 在每帧调用代价大。优化:

```rust
// 不要 clone,用 swap
let mut read = std::mem::take(&mut world.atlases);  // 把 atlases 移出
let mut write = Vec::with_capacity(read.len());

// 迭代
for _ in 0..iters {
    write = gather_all(&read);
    std::mem::swap(&mut read, &mut write);
}

world.atlases = read;
```

`std::mem::take` 不复制数据,只移动所有权。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 Jacobi 迭代(用 double-buffering)能并行,Gauss-Seidel(单 buffer)不能?用具体场景说明。

**参考解答**:Jacobi 读所有旧值算所有新值——所有计算互相独立,可并行(8 个线程同时算 8 个体素的新值)。Gauss-Seidel 读"部分新部分旧"——体素 5 的新值依赖体素 0-4 的新值,必须等体素 0-4 算完才能算 5。所以 Gauss-Seidel 严格串行。

具体场景:8 核 CPU。Jacobi 8 个体素同时算,8 倍加速。Gauss-Seidel 一个一个算,1 倍速度。Gauss-Seidel 收敛快 2 倍,但单次慢 8 倍,实际 Jacobi 并行后快 4 倍。

### Lv2 · 动手实践

**题**:实现 `propagate_infinite_bounces(world: &mut World, iterations: usize)`,用 double-buffering。测试:
- 100 个体素,每个 atlas 16×16
- 跑 8 次迭代
- 验证最终 atlas 不全黑(光被传播了)

完成标准:`cargo run` 打印"8 iterations done",最终 atlas 有非零 texel。

**参考解答**:

```rust
fn propagate_infinite_bounces(world: &mut World, iterations: usize) {
    let n = world.voxels.len();
    let mut read: Vec<LightAtlas> = world.voxels.iter().map(|v| v.atlas.clone()).collect();
    let mut write: Vec<LightAtlas> = read.clone();

    // 初始化:注入直接光
    for i in 0..n {
        inject_direct_light(&mut write[i], &world.voxels[i]);
    }

    for iter in 0..iterations {
        std::mem::swap(&mut read, &mut write);
        for i in 0..n {
            write[i] = gather_incoming_light(&read, i, &world.voxels[i]);
        }
        let max_val = write.iter()
            .flat_map(|a| a.texels.iter())
            .map(|c| c.r.max(c.g).max(c.b))
            .fold(0.0f32, f32::max);
        println!("Iteration {}: max brightness = {:.4}", iter, max_val);
    }

    // 写回
    for i in 0..n {
        world.voxels[i].atlas = std::mem::take(&mut write[i]);
    }
}
```

**每行解释**:
- `world.voxels.iter().map(|v| v.atlas.clone())` — 克隆所有 atlas 到 read buffer。
- `inject_direct_light` — 把直接光源注入 atlas(对应 E_i 项)。
- `std::mem::swap` — 双 buffer 交换。
- `gather_incoming_light` — 从其他 atlas 采样到本 atlas(对应 Σ F_ij × B_j)。
- `max brightness` — 监控每轮迭代后的最大亮度,看是否收敛(应该逐步稳定)。
- `std::mem::take(&mut write[i])` — 移动 atlas 到 world,避免再 clone。

### Lv3 · 迁移设计

**题**:你被要求做一个**PageRank 迭代求解器**(给定网页链接图,迭代计算每个网页的"重要性")。请设计:
- 数据结构(类比 atlas)
- 迭代公式(类比辐射度方程)
- 收敛条件

**提示**:
- PageRank 方程:`PR(i) = (1-d)/N + d × Σ_{j→i} PR(j)/L(j)`
- d 是阻尼系数(通常 0.85)
- L(j) 是网页 j 的出链数
- 收敛:两次迭代的最大差值 < ε

```rust
// (Vec3, RGB32F, LightAtlas, encode/decode, wrap_uv 同前几日)

#[derive(Clone)]
struct Voxel {
    pos: Vec3,
    atlas: LightAtlas,
    albedo: RGB32F,
}

struct World {
    voxels: Vec<Voxel>,
}

fn inject_direct_light(atlas: &mut LightAtlas, voxel: &Voxel) {
    // 模拟一个直接光源
    let light_pos = Vec3 { x: 5.0, y: 5.0, z: 5.0 };
    let dir = (light_pos.x - voxel.pos.x, light_pos.y - voxel.pos.y, light_pos.z - voxel.pos.z);
    let dir = Vec3 { x: dir.0, y: dir.1, z: dir.2 };
    let dist = (dir.x * dir.x + dir.y * dir.y + dir.z * dir.z).sqrt();
    let dir_n = Vec3 { x: dir.x / dist, y: dir.y / dist, z: dir.z / dist };
    let color = RGB32F::new(10.0, 10.0, 8.0).scale(1.0 / (dist * dist));
    atlas.accumulate(dir_n, color);
}

fn gather_incoming_light(read: &[LightAtlas], idx: usize, voxel: &Voxel) -> LightAtlas {
    let mut atlas = LightAtlas::new(16);
    for (j, other) in read.iter().enumerate() {
        if j == idx { continue; }
        let dir = Vec3 {
            x: voxel.pos.x - voxel.pos.x * 0.0 + (j as f32 - idx as f32) * 1.0,  // 模拟方向
            y: 0.0,
            z: 0.0,
        };
        let dir = if dir.x == 0.0 && dir.y == 0.0 && dir.z == 0.0 {
            Vec3 { x: 0.0, y: 1.0, z: 0.0 }
        } else {
            Vec3 { x: dir.x.signum(), y: 0.0, z: 0.0 }
        };
        let color = other.sample_with_wrap(dir);
        let attenuated = RGB32F::new(
            color.r * voxel.albedo.r * 0.1,
            color.g * voxel.albedo.g * 0.1,
            color.b * voxel.albedo.b * 0.1,
        );
        atlas.accumulate(dir, attenuated);
    }
    atlas
}

fn propagate_infinite_bounces(world: &mut World, iterations: usize) {
    let n = world.voxels.len();
    let mut read: Vec<LightAtlas> = world.voxels.iter().map(|v| v.atlas.clone()).collect();
    let mut write: Vec<LightAtlas> = read.iter().map(|a| LightAtlas::new(a.dim)).collect();
    for i in 0..n {
        inject_direct_light(&mut write[i], &world.voxels[i]);
    }
    for iter in 0..iterations {
        std::mem::swap(&mut read, &mut write);
        for i in 0..n {
            write[i] = gather_incoming_light(&read, i, &world.voxels[i]);
        }
        let max_brightness = write.iter()
            .flat_map(|a| a.texels.iter())
            .map(|c| c.r.max(c.g).max(c.b))
            .fold(0.0f32, f32::max);
        println!("Iter {}: max = {:.6}", iter, max_brightness);
    }
    for i in 0..n {
        world.voxels[i].atlas = std::mem::take(&mut write[i]);
    }
}

fn main() {
    let mut world = World {
        voxels: (0..50).map(|i| Voxel {
            pos: Vec3 { x: i as f32, y: 0.0, z: 0.0 },
            atlas: LightAtlas::new(16),
            albedo: RGB32F::new(0.5, 0.5, 0.5),
        }).collect(),
    };
    propagate_infinite_bounces(&mut world, 8);
    println!("Done. Final atlas[0] sample at +x: {:?}",
             world.voxels[0].atlas.sample_with_wrap(Vec3 { x: 1.0, y: 0.0, z: 0.0 }));
}
```

### A.1 该 Day 在 phase-8 的位置

Phase 8(day576-667)是 voxel lighting 系统的工业级实现。本日是其中一天。

### A.2 Voxel lighting 的工程挑战

Voxel lighting 是计算机图形学的难点,因为:

**1. 数据量大**:
- 大场景(100m × 100m × 100m)有几百万 voxel
- 每 voxel 存光照值(RGB 或 SH)
- 总数据 GB 级

**2. 实时性要求**:
- 玩家挖 / 改 voxel,光照立即变化
- 16.67 ms 帧预算(60 FPS)
- 不能阻塞玩家操作

**3. 物理准确性**:
- 直接光(sun)
- 间接光(bounce)
- 阴影(hard / soft)
- 反射(diffuse / specular)
- 折射(glass / water)

工业方案在物理准确性和实时性之间权衡。

### A.3 工业级实现的层次

**Layer 1:Brute force**
- 每 voxel × 每方向 raycast
- 准确但极慢
- 适合离线渲染(movie)

**Layer 2:Grid DDA**
- 快速 raycast(穿格子)
- 适合简单场景
- Casey 的 HH 用这层

**Layer 3:Precomputed**
- 离线算光照 cache
- 运行时查表
- 适合静态场景(Minecraft baked)

**Layer 4:Real-time approximation**
- LPV / SVOGI / Voxel Cone Tracing
- 实时但近似
- Crytek / Unreal 用

**Layer 5:Hardware ray tracing**
- RTX / RDNA2 核心
- 真实光传播
- Minecraft RTX / Teardown

每代技术对硬件要求递增。Casey 的 HH 在 Layer 2(教学优先)。

### A.4 性能 profile 的实战

Casey 在 phase-8 多次 profile:

**Profile 工具**:
- Linux:perf、Valgrind、flamegraph
- Windows:Superluminal、VTune
- 跨平台:Tracy

**典型发现**:
- Raycast 占 50%+
- Propagation 占 20%+
- Meshing 占 10%+
- 其他占 20%

**优化顺序**:
1. 最慢函数 → 算法优化
2. Cache miss → 数据布局优化
3. 锁等待 → 并发优化

每优化一个,重新 profile 找下一个。

### A.5 Casey 的 phase-8 工程决策

Casey 在 phase-8 做的关键工程决策:

**1. CPU 渲染**:简单,跨平台,教学优先
**2. Voxel grid(非 octree)**:简单,固定大小
**3. RGBE atlas(非 SH)**:内存小,够教学
**4. Precomputed + delta update**:平衡实时性和准确性

这些决策让 HH 代码可读、可教学。生产游戏可能选 GPU + SH + realtime(更复杂)。

### A.7 Voxel lighting 算法的核心循环

让我写一个简化的 voxel lighting 主循环:

```rust
fn update_lighting(world: &mut World, sun_dir: Vec3) {
    let direct = compute_direct_lighting(world, sun_dir);
    let indirect = compute_indirect_lighting(world, &direct, 3);  // 3 bounce
    let final_light = combine(&direct, &indirect);
    world.light_atlas = final_light;
}

fn compute_direct_lighting(world: &World, sun_dir: Vec3) -> LightAtlas {
    let mut atlas = LightAtlas::new(world.dims());
    for each voxel {
        if voxel.is_solid() && !is_occluded(world, voxel_pos, sun_dir) {
            let lambert = compute_normal(world, x, y, z).dot(sun_dir).max(0.0);
            atlas.set(x, y, z, sun_color * lambert);
        }
    }
    atlas
}

fn compute_indirect_lighting(world: &World, direct: &LightAtlas, bounces: usize) -> LightAtlas {
    let mut current = direct.clone();
    for _ in 0..bounces {
        let mut next = current.clone();
        for each voxel {
            let bounce = average_neighbors(&current, x, y, z) * 0.15;
            next.set(x, y, z, current.get(x, y, z) + bounce);
        }
        current = next;
    }
    current
}
```

这是 Casey phase-8 的简化核心。工业实现更复杂(SH、GPU、并行)。
