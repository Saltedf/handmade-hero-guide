# Day 662 · 从布局生成实体

> Day 660/661 生成房间布局。今天 Casey 给房间**填充内容**——根据房间类型(Combat / Treasure / Boss / Shop)生成对应实体(敌人、宝箱、Boss、商人)。

## 0 · 为什么要有这一天

回顾 Day 660:房间有 `room_type: RoomType` 字段,但**没有实际效果**——所有房间都"空"。今天根据 room_type **生成实体**:

- Start:玩家出生
- Combat:3-5 个敌人
- Treasure:1 个宝箱
- Boss:1 个 Boss
- Shop:1 个商人

每个类型有自己的生成规则。游戏越深,room_type 越多——HH 选 5 个基础。

心理锚点:看完今天,你能:

- 设计"布局→实体"的转换层
- 根据类型差异化生成
- 处理生成时的边角(房间太小放不下)

## 1 · Casey 今天做了什么

1. 设计 `populate_room(room: &Room) -> Vec<EntitySpawn>`
2. 根据 room_type 分发:Start 生成玩家,Combat 生成敌人,等
3. 实体位置:房间内随机点(避开墙)
4. 数量平衡:Combat 房间敌人数量根据进度增加
5. 测试:跑 5 个 seed,每个 seed 看生成的实体分布
6. 加难度参数:`difficulty: f32`,影响敌人血量 / 数量

## 2 · 心智模型

### 类比:拍电影选角

电影导演看剧本——这段是战斗戏,选 5 个武行;那段是商业戏,选 1 个商人演员。**剧本(房间类型)决定选角(实体生成)**。

游戏房间布局 = 剧本。populate = 选角。每个 room_type 触发对应实体生成。

### EntitySpawn 抽象

为什么不直接生成 Entity?因为 populate 是"规划阶段",实际生成可能延后(等加载完成 / 玩家进入房间)。

```rust
enum EntitySpawn {
    Player { pos: Vec3 },
    Enemy { pos: Vec3, kind: EnemyKind, hp: f32 },
    Treasure { pos: Vec3, content: Item },
    Boss { pos: Vec3, hp: f32 },
    Shopkeeper { pos: Vec3, inventory: Vec<Item> },
}

fn populate_room(room: &Room, difficulty: f32, rng: &mut impl Rng) -> Vec<EntitySpawn> {
    match room.room_type {
        RoomType::Start => vec![EntitySpawn::Player {
            pos: room.center_world(),
        }],
        RoomType::Combat => {
            let count = (3.0 + difficulty * 2.0) as usize;
            (0..count).map(|_| {
                EntitySpawn::Enemy {
                    pos: room.random_interior_point(rng),
                    kind: EnemyKind::Goblin,
                    hp: 10.0 + difficulty * 5.0,
                }
            }).collect()
        }
        RoomType::Treasure => vec![EntitySpawn::Treasure {
            pos: room.center_world(),
            content: Item::random(rng),
        }],
        RoomType::Boss => vec![EntitySpawn::Boss {
            pos: room.center_world(),
            hp: 100.0 + difficulty * 50.0,
        }],
        RoomType::Shop => vec![EntitySpawn::Shopkeeper {
            pos: room.center_world(),
            inventory: vec![Item::random(rng), Item::random(rng), Item::random(rng)],
        }],
    }
}
```

`match room.room_type` 是 Rust 的 pattern matching,每个分支返回 `Vec<EntitySpawn>`。所有分支类型一致(都是 Vec),编译通过。

### 房间内随机点

```rust
impl Room {
    fn random_interior_point(&self, rng: &mut impl Rng) -> Vec3 {
        let x = rng.gen_range((self.x + 1)..(self.x + self.w - 1));
        let z = rng.gen_range((self.z + 1)..(self.z + self.h - 1));
        Vec3::new(x as f32 + 0.5, 0.5, z as f32 + 0.5)
    }
    fn center_world(&self) -> Vec3 {
        Vec3::new(
            (self.x + self.w / 2) as f32 + 0.5,
            0.5,
            (self.z + self.h / 2) as f32 + 0.5,
        )
    }
}
```

注意 +1 / -1 避开墙。+0.5 让位置在 voxel 中心(中心约定,见 Day 645)。

### 难度递增

```rust
fn populate_world(rooms: &[Room], base_difficulty: f32) -> Vec<EntitySpawn> {
    let mut all_spawns = Vec::new();
    for (i, room) in rooms.iter().enumerate() {
        // 离 start 房间越远,难度越高
        let difficulty = base_difficulty + i as f32 * 0.1;
        let mut rng = rand::thread_rng();
        all_spawns.extend(populate_room(room, difficulty, &mut rng));
    }
    all_spawns
}
```

线性难度递增。可以更复杂:基于房间到 start 的"图距离"(MST 跳数)。

### 实体生成时机

两种思路:

1. **预生成**:关卡初始化时,所有房间一次性生成所有实体。简单,但内存大
2. **懒生成**:玩家进入房间时才生成。节省内存,但加载卡顿

HH 选预生成——房间数 < 20,实体数 < 100,内存够。大型游戏(开放世界)选懒生成。

### 实体存储

```rust
struct World {
    voxels: ...,
    entities: Vec<Entity>,
}

impl World {
    fn spawn(&mut self, spawn: EntitySpawn) {
        match spawn {
            EntitySpawn::Player { pos } => {
                self.entities.push(Entity::new_player(pos));
            }
            EntitySpawn::Enemy { pos, kind, hp } => {
                let mut e = Entity::new_enemy(pos);
                e.hp = hp;
                e.kind = kind;
                self.entities.push(e);
            }
            // ...
        }
    }
}
```

`EntitySpawn` 是数据,`World::spawn` 是消费数据创建 Entity。两层抽象让生成逻辑和实体构造解耦。

### 3.2 · 图形学视角

图形里"按类型生成":

- **particle system**:不同 emitter 类型生成不同粒子
- **foliage system**:不同 biome 生成不同植被
- **crowd simulation**:不同区域 NPC 密度不同

每个都是"规则化生成"的实例。

### 3.3 · Linux 系统编程视角

Linux 里"按类型 spawn":

- **systemd**:不同 unit 类型(Service / Socket / Mount / Timer)生成不同进程 / 资源
- **udev**:不同设备类型(块 / 字符 / 网络)生成不同设备节点
- **package manager**:不同包类型(binary / source / debug)生成不同安装结果

`match type { ... }` 是工程通用模式。

## 5 · 对照与变奏

不同难度曲线:

```
线性:     diff = base + i * 0.1
指数:     diff = base * 1.1^i
对数:     diff = base * log(i+1)
阶梯:     diff = base * (i / 5 + 1)
S-curve:  diff = base / (1 + e^(-i))
```

HH 选线性,简单可调。

### Lv1 · 概念辨析

**题**:为什么用 EntitySpawn 而不是直接生成 Entity?

**参考解答**:分离关注点——populate_room 只关心"应该生成什么",不关心"怎么创建"。EntitySpawn 是数据,可以序列化、网络传输、调试查看。Entity 是运行时对象,有状态、有引用、有生命周期。两层解耦让生成逻辑可以独立测试、调参、A/B 测试。

```rust
use rand::{Rng, SeedableRng};
use rand_xoshiro::Xoshiro256PlusPlus;

#[derive(Clone, Copy, Debug)]
enum RoomType { Start, Combat, Treasure, Boss, Shop }

#[derive(Clone, Copy, Debug)]
struct Room { x: i32, z: i32, w: i32, h: i32, room_type: RoomType }

impl Room {
    fn center(&self) -> (i32, i32) { (self.x + self.w / 2, self.z + self.h / 2) }
    fn random_interior(&self, rng: &mut impl Rng) -> (i32, i32) {
        let x = rng.gen_range((self.x + 1)..(self.x + self.w - 1));
        let z = rng.gen_range((self.z + 1)..(self.z + self.h - 1));
        (x, z)
    }
}

#[derive(Clone, Debug)]
enum EntitySpawn {
    Player { x: i32, z: i32 },
    Enemy { x: i32, z: i32, hp: f32 },
    Treasure { x: i32, z: i32, gold: u32 },
    Boss { x: i32, z: i32, hp: f32 },
    Shopkeeper { x: i32, z: i32 },
}

fn populate_room(room: &Room, difficulty: f32, rng: &mut impl Rng) -> Vec<EntitySpawn> {
    let (cx, cz) = room.center();
    match room.room_type {
        RoomType::Start => vec![EntitySpawn::Player { x: cx, z: cz }],
        RoomType::Combat => {
            let count = (3.0 + difficulty * 2.0) as usize;
            (0..count).map(|_| {
                let (x, z) = room.random_interior(rng);
                EntitySpawn::Enemy { x, z, hp: 10.0 + difficulty * 5.0 }
            }).collect()
        }
        RoomType::Treasure => vec![EntitySpawn::Treasure {
            x: cx, z: cz, gold: rng.gen_range(10..100),
        }],
        RoomType::Boss => vec![EntitySpawn::Boss {
            x: cx, z: cz, hp: 100.0 + difficulty * 50.0,
        }],
        RoomType::Shop => vec![EntitySpawn::Shopkeeper { x: cx, z: cz }],
    }
}

fn populate_world(rooms: &[Room], base_difficulty: f32) -> Vec<EntitySpawn> {
    let mut spawns = Vec::new();
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    for (i, room) in rooms.iter().enumerate() {
        let diff = base_difficulty + i as f32 * 0.1;
        spawns.extend(populate_room(room, diff, &mut rng));
    }
    spawns
}

fn main() {
    let rooms = vec![
        Room { x: 2, z: 2, w: 8, h: 8, room_type: RoomType::Start },
        Room { x: 15, z: 3, w: 6, h: 6, room_type: RoomType::Combat },
        Room { x: 3, z: 15, w: 6, h: 6, room_type: RoomType::Treasure },
        Room { x: 18, z: 18, w: 8, h: 8, room_type: RoomType::Boss },
        Room { x: 10, z: 10, w: 5, h: 5, room_type: RoomType::Shop },
    ];
    let spawns = populate_world(&rooms, 0.5);
    println!("Total spawns: {}", spawns.len());
    for s in &spawns {
        println!("  {:?}", s);
    }
}
```

## 8 · Rust / Arch 落地代码

完整实体生成系统:

```rust
// Cargo.toml:
// [dependencies]
// rand = "0.8"
// rand_xoshiro = "0.6"

use rand::{Rng, SeedableRng};
use rand_xoshiro::Xoshiro256PlusPlus;
use std::collections::HashSet;

#[derive(Clone, Copy, Debug, PartialEq)]
enum RoomType { Start, Combat, Treasure, Boss, Shop }

#[derive(Clone, Copy, Debug)]
struct Room {
    x: i32, z: i32, w: i32, h: i32,
    room_type: RoomType,
}

impl Room {
    fn center(&self) -> (i32, i32) { (self.x + self.w / 2, self.z + self.h / 2) }
    fn random_interior(&self, rng: &mut impl Rng, occupied: &HashSet<(i32, i32)>) -> (i32, i32) {
        for _ in 0..20 {
            let x = rng.gen_range((self.x + 1)..(self.x + self.w - 1));
            let z = rng.gen_range((self.z + 1)..(self.z + self.h - 1));
            if !occupied.contains(&(x, z)) { return (x, z); }
        }
        self.center() // fallback
    }
}

#[derive(Clone, Debug)]
enum EntitySpawn {
    Player { x: i32, z: i32 },
    Enemy { x: i32, z: i32, hp: f32 },
    Treasure { x: i32, z: i32, gold: u32 },
    Boss { x: i32, z: i32, hp: f32 },
    Shopkeeper { x: i32, z: i32, items: u32 },
}

fn populate_room(
    room: &Room,
    difficulty: f32,
    rng: &mut impl Rng,
    occupied: &mut HashSet<(i32, i32)>,
) -> Vec<EntitySpawn> {
    let (cx, cz) = room.center();
    match room.room_type {
        RoomType::Start => {
            occupied.insert((cx, cz));
            vec![EntitySpawn::Player { x: cx, z: cz }]
        }
        RoomType::Combat => {
            let count = (3.0 + difficulty * 2.0) as usize;
            (0..count).map(|_| {
                let (x, z) = room.random_interior(rng, occupied);
                occupied.insert((x, z));
                EntitySpawn::Enemy { x, z, hp: 10.0 + difficulty * 5.0 }
            }).collect()
        }
        RoomType::Treasure => {
            occupied.insert((cx, cz));
            vec![EntitySpawn::Treasure {
                x: cx, z: cz, gold: rng.gen_range(10..100),
            }]
        }
        RoomType::Boss => {
            occupied.insert((cx, cz));
            vec![EntitySpawn::Boss {
                x: cx, z: cz, hp: 100.0 + difficulty * 50.0,
            }]
        }
        RoomType::Shop => {
            occupied.insert((cx, cz));
            vec![EntitySpawn::Shopkeeper {
                x: cx, z: cz, items: rng.gen_range(2..5),
            }]
        }
    }
}

fn populate_world(rooms: &[Room], base_difficulty: f32) -> Vec<EntitySpawn> {
    let mut spawns = Vec::new();
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let mut occupied = HashSet::new();
    for (i, room) in rooms.iter().enumerate() {
        let diff = base_difficulty + i as f32 * 0.1;
        spawns.extend(populate_room(room, diff, &mut rng, &mut occupied));
    }
    spawns
}

fn main() {
    let rooms = vec![
        Room { x: 2, z: 2, w: 8, h: 8, room_type: RoomType::Start },
        Room { x: 15, z: 3, w: 6, h: 6, room_type: RoomType::Combat },
        Room { x: 3, z: 15, w: 6, h: 6, room_type: RoomType::Treasure },
        Room { x: 18, z: 18, w: 8, h: 8, room_type: RoomType::Boss },
        Room { x: 10, z: 10, w: 5, h: 5, room_type: RoomType::Shop },
    ];
    let spawns = populate_world(&rooms, 0.5);

    let mut by_type = std::collections::HashMap::new();
    for spawn in &spawns {
        let kind = match spawn {
            EntitySpawn::Player { .. } => "Player",
            EntitySpawn::Enemy { .. } => "Enemy",
            EntitySpawn::Treasure { .. } => "Treasure",
            EntitySpawn::Boss { .. } => "Boss",
            EntitySpawn::Shopkeeper { .. } => "Shopkeeper",
        };
        *by_type.entry(kind).or_insert(0) += 1;
    }
    println!("Spawn summary:");
    for (k, v) in &by_type {
        println!("  {}: {}", k, v);
    }

    println!("\nAll spawns:");
    for s in &spawns {
        println!("  {:?}", s);
    }
}
```

## 10 · 工程反思

Day 662 传达的核心工程教训:**实体生成 = 数据驱动设计**。

新手用"硬编码"——`let goblin = Goblin::new();`,资深工程师用"数据驱动"——`spawn_entity(goblin_template)`,模板从 JSON / TOML 读。区别是:

- **硬编码**:每加新怪物改代码、重编译
- **数据驱动**:每加新怪物改数据、不重编译

工业级游戏 100% 数据驱动。设计师加新怪物 / 关卡 / 武器,工程师不参与。这是大型游戏团队的必备架构。

**ECS 和数据驱动**:

ECS(Entity-Component-System)天然适合数据驱动——每个 entity 是组件集合,组件是数据。从 JSON 加载:

```json
{
  "name": "goblin",
  "components": {
    "Position": {},
    "Health": { "max": 50 },
    "AI": { "type": "aggressive" },
    "Render": { "mesh": "goblin.gltf" }
  }
}
```

运行时反序列化成 entity,直接进 ECS world。这是 bevy / Unity DOTS / Unreal Mass 的核心。

**Casey 在 HH 的演化**:

- Day 1-100:硬编码实体(if-else 处理类型)
- Day 200+:tagged union(更灵活)
- Day 600+:ECS 风格(component 集合)
- Day 662:数据驱动(JSON 模板)

每一步都是抽象升级。最终达到"设计师独立工作"的水平。

**第二条教训**:**prefab 是工业级实体管理**。

Prefab(预置)是"实体模板"——保存组件配置,可实例化多个。Unity / Unreal 都有 prefab 系统。

Prefab 的优势:

- **复用**:同一 prefab 实例化多个,改 prefab 全更新
- **嵌套**:prefab 包含 prefab(角色 + 武器)
- **变体**:prefab 继承,小修改(红色 goblin / 蓝色 goblin)

这是工业游戏开发的标配。Casey 在 HH 演示最简版本(单模板),工业级是 prefab 系统。

**第三条教训**:**实体序列化 = savegame**。

游戏存档 = 把所有 entity 序列化到磁盘。读档 = 反序列化恢复。这要求:

- 所有组件支持序列化(serde in Rust)
- 引用关系正确(entity ID 重新映射)
- 资源引用正确(mesh / texture 路径)

这是大型游戏开发的复杂工程。Casey 在 HH Day 662 演示基础,工业级需要完整序列化框架。

**迁移到其他领域**:

"实体生成"思路在多处通用:

- **Web**:React component 实例化
- **数据库**:ORM model 实例化
- **OOP**:class 实例化
- **配置管理**:Kubernetes manifest
- **工厂模式**:GoF factory pattern

每个领域都有"模板 → 实例"的思想。Casey 在 HH 演示的是 ECS 版本。

## N0 • 深度教学补充

### 核心概念重新梳理

Day 662 涉及的核心概念需要在多个层次上理解:

**第一层:直观理解**

新手第一次接触概念,需要建立直觉。例如 voxel collision 是"虚拟物体不能穿过虚拟墙"——这个直觉每个人都能从现实经验获得。

**第二层:数学理解**

把直觉形式化。collision = "两个几何体的体积有交集"。对于 AABB,这等价于"三轴投影都重叠"。

**第三层:工程理解**

数学正确不等于工程实现正确。要考虑:

- 浮点精度边界
- 性能(每帧 N 个查询)
- 内存(数据结构紧凑)
- 边角 case(无穷大、NaN、负数)

**第四层:工业理解**

工业级要再加:

- 多线程安全
- SIMD 优化
- 网络同步(多人游戏)
- 跨平台(Windows/Mac/Linux/Mobile)
- 可访问性(色盲友好)
- 反作弊

每层理解都让代码更鲁棒。资深工程师在所有层次同时思考。

### 实际工程的细节

工业代码 80% 是"边角 case 处理",20% 是"核心算法"。Casey 在 HH 演示核心,工业代码加大量边角处理。

**边角 case 类型**:

1. 空输入(空 Vec、null pointer)
2. 极端输入(NaN、无穷大、超大数)
3. 并发竞争(多线程同时访问)
4. 资源不足(内存满、磁盘满)
5. 网络异常(超时、断连、包丢失)
6. 版本不兼容(老配置 / 新代码)
7. 权限错误(只读文件、无网络)
8. 用户误操作(连点、撤销重做)

每个 case 都要单独处理。这是工业代码 50%+ 行数的原因。

### 优化思路

性能优化有顺序:

1. **算法**:O(N²) → O(N log N),最大提升
2. **数据结构**:Vec → HashMap / BTreeMap,常数提升
3. **Cache**:AoS → SoA,cache 命中提升
4. **SIMD**:4-16 元素并行,巨大常数提升
5. **GPU**:数千核并行,极致性能
6. **分布式**:多机器,无限扩展

每级提升都需要更复杂的代码。先优化低级,够用再升级。

- **完成 > 完美**:能跑 > 能优化

### Rust 视角

Day 662 用 C 写,但 Rust 版本会更安全 / 更高效:

- **所有权**:消除 use-after-free / double-free
- **borrow check**:消除 data race
- **match exhaustive**:case 漏写编译错
- **Result<T, E>**:错误显式处理
- **no null**:Option<T> 强制 null 检查
- **fearless concurrency**:多线程安全

每条都让代码更鲁棒。Rust 是游戏开发的新趋势(bevy / wgpu / rend3),学习 Rust 让你未来 10 年受益。

### Arch / Linux 视角

Arch Linux 是 HH 教学的隐含平台——一切从命令行开始,理解底层。这对学习极有价值:

- 包管理(pacman)清晰

Arch 用户天然理解 HH 的从零搭起来哲学。其他 distro(Ubuntu)用户要补这部分。
