# Day 659 · 即时模式关卡生成

> HH 之前的关卡是手工编辑(编辑器里画 voxel)或脚本生成(代码里写)。今天 Casey 加新方式:**immediate-mode 程序生成**——运行时用 immediate-mode API 描述关卡,引擎现场生成。这就像 Dear ImGui 之于 UI,但用在关卡设计上。

## 0 · 为什么要有这一天

回顾关卡生成方法:

- **手工编辑**:Casey 的 Day 535-570 编辑器,鼠标点击放 voxel
- **脚本生成**:代码 `for x in 0..10 { place_voxel(x, 0, 0); }`
- **数据驱动**:JSON / 关卡文件描述,加载时构造
- **procedural**:算法生成(perlin noise / cellular automata)

每种适合不同场景。**immediate-mode** 是新维度:

```rust
fn generate_dungeon(gen: &mut LevelGen) {
    gen.room(0, 0, 10, 10);
    gen.room(15, 0, 8, 5);
    gen.corridor(10, 5, 15, 5);
    gen.spawn_player(5, 5);
    gen.spawn_enemy(20, 2);
}
```

像写 immediate-mode UI——每行描述一个动作,引擎现场执行。这给设计者**算法和手放的混合**——既能用代码批量放,又能精准控制每个元素。

心理锚点:看完今天,你能:

- 设计 immediate-mode 关卡生成 API
- 区分"声明式"和"命令式"关卡生成
- 用 immediate-mode 快速 prototype 关卡

## 1 · Casey 今天做了什么

1. 设计 `LevelGen` struct,带 immediate-mode API:`room / corridor / spawn / place`
2. 每个 API 调用立即修改世界状态(写 voxel / 加实体)
3. 写几个关卡生成函数:简单房间、复杂地下城
4. 加 keyboard hotkey:F1 重新生成当前关卡,看变化
5. 设计"random seed"——同一种子生成同一关卡,可复现
6. 加 procedural 元素:`gen.random_room(rng)` 自动选位置和大小

## 2 · 心智模型

### 类比:厨师做菜

厨师做菜有几种风格:

- **遵循食谱**:严格按书做,成品固定
- **即兴**:看食材现场决定做什么,每次不同
- **半即兴**:食谱 + 个人调整

关卡生成同理:

- **手工编辑**:食谱(每个 voxel 精确)
- **procedural**:即兴(perlin noise 自动生成)
- **immediate-mode**:半即兴(代码框架 + 随机点缀)

### Immediate-mode 范式

immediate-mode(立即模式)vs retained mode(保留模式):

**Retained**(传统关卡编辑):你创建 Room 对象,引擎持有;之后修改 Room,引擎更新。

**Immediate**(立即):你每帧重新调用 `gen.room(...)`,引擎现场执行,不持有对象。

immediate-mode 的优势:

- 无状态,bug 少
- 数据流可见
- 容易版本控制(代码即数据)
- 容易"重新生成"(F1 重跑)

immediate-mode 是 Casey 风格 UI 的核心,他用同样思路做关卡。

### LevelGen API 设计

```rust
struct LevelGen<'a> {
    world: &'a mut World,
    rng: &'a mut Rng,
}

impl<'a> LevelGen<'a> {
    fn room(&mut self, x: i32, z: i32, w: i32, h: i32) {
        for dx in 0..w {
            for dz in 0..h {
                if dx == 0 || dx == w - 1 || dz == 0 || dz == h - 1 {
                    self.world.set(x + dx, 0, z + dz, VoxelType::Wall);
                } else {
                    self.world.set(x + dx, 0, z + dz, VoxelType::Floor);
                }
            }
        }
    }
    fn corridor(&mut self, x1: i32, z1: i32, x2: i32, z2: i32) {
        // 简单 L 形走廊
        for x in x1.min(x2)..=x1.max(x2) {
            self.world.set(x, 0, z1, VoxelType::Floor);
        }
        for z in z1.min(z2)..=z1.max(z2) {
            self.world.set(x2, 0, z, VoxelType::Floor);
        }
    }
    fn spawn_player(&mut self, x: i32, z: i32) {
        self.world.add_entity(Entity::new_player(Vec3::new(x as f32, 0.5, z as f32)));
    }
    fn spawn_enemy(&mut self, x: i32, z: i32) {
        self.world.add_entity(Entity::new_enemy(Vec3::new(x as f32, 0.5, z as f32)));
    }
    fn random_room(&mut self, min: i32, max: i32) -> (i32, i32, i32, i32) {
        let w = self.rng.gen_range(min..max);
        let h = self.rng.gen_range(min..max);
        let x = self.rng.gen_range(0..30);
        let z = self.rng.gen_range(0..30);
        self.room(x, z, w, h);
        (x, z, w, h)
    }
}
```

每个 API 立即修改 world,无延迟。

### 用 immediate-mode 描述关卡

```rust
fn generate_level_1(gen: &mut LevelGen) {
    gen.room(0, 0, 10, 10);
    gen.room(15, 5, 8, 8);
    gen.corridor(9, 4, 15, 9);
    gen.spawn_player(5, 5);
    gen.spawn_enemy(20, 10);
    gen.spawn_item(8, 8, ItemType::Sword);
}

fn generate_level_2(gen: &mut LevelGen) {
    // 程序生成 5 个随机房间
    let mut rooms = vec![];
    for _ in 0..5 {
        rooms.push(gen.random_room(5, 10));
    }
    // 用走廊连接
    for w in rooms.windows(2) {
        let (x1, z1, _, _) = w[0];
        let (x2, z2, _, _) = w[1];
        gen.corridor(x1, z1, x2, z2);
    }
    gen.spawn_player(rooms[0].0 + 1, rooms[0].1 + 1);
}
```

像写代码一样写关卡,清晰可调。

### 随机种子可复现

fn main() {

### Immediate-mode 编辑器集成

immediate-mode 让"编辑关卡"变成"写代码 + F1 重生成"。优势:

- Git 友好(代码 diff,不是二进制文件)
- 可读(看到代码就知道关卡长啥样)
- 可参数化(改一个 const 就改全部房间大小)
- 可组合(关卡函数调用关卡函数)

劣势:

- 不能可视化编辑(看不到鼠标点击效果)
- 设计师(非程序员)难用

HH 是程序员主导,immediate-mode 适合。

- **NetworkManager config**:动态生成连接配置

每个都是"代码描述结构,系统现场生成"。

## 5 · 对照与变奏

不同 procedural 关卡算法:

- **BSP**(Binary Space Partitioning):递归切分空间,生成房间
- **Cellular automata**:从随机噪声演化出洞穴
- **Wave function collapse**:从约束生成(Minecraft 的某些结构)
- **Grammar-based**:规则系统(街道布局)
- **Perlin noise**:高度图(地形)

每种适合不同类型关卡。HH 选简单的"房间 + 走廊",易理解。

### Lv1 · 概念辨析

**题**:immediate-mode 关卡生成相比 JSON 关卡文件,优势在哪?

### Lv2 · 动手实践

**题**:实现 §2 的 LevelGen API,生成两个房间 + 走廊的关卡,打印 ASCII。

**参考解答**:

```rust
use rand::{Rng, SeedableRng};
use rand_xoshiro::Xoshiro256PlusPlus;

#[derive(Clone, Copy, PartialEq, Debug)]
enum Voxel { Empty, Wall, Floor }

struct World {
    w: usize,
    h: usize,
    voxels: Vec<Voxel>,
}

impl World {
    fn new(w: usize, h: usize) -> Self {
        Self { w, h, voxels: vec![Voxel::Empty; w * h] }
    }
    fn set(&mut self, x: i32, z: i32, v: Voxel) {
        if x < 0 || z < 0 { return; }
        let (x, z) = (x as usize, z as usize);
        if x >= self.w || z >= self.h { return; }
        self.voxels[z * self.w + x] = v;
    }
    fn render(&self) {
        for z in 0..self.h {
            let mut line = String::new();
            for x in 0..self.w {
                let c = match self.voxels[z * self.w + x] {
                    Voxel::Empty => ' ',
                    Voxel::Wall => '#',
                    Voxel::Floor => '.',
                };
                line.push(c);
            }
            println!("{}", line);
        }
    }
}

struct LevelGen<'a, R: Rng> {
    world: &'a mut World,
    rng: &'a mut R,
}

impl<'a, R: Rng> LevelGen<'a, R> {
    fn room(&mut self, x: i32, z: i32, w: i32, h: i32) {
        for dx in 0..w {
            for dz in 0..h {
                let is_edge = dx == 0 || dx == w - 1 || dz == 0 || dz == h - 1;
                let v = if is_edge { Voxel::Wall } else { Voxel::Floor };
                self.world.set(x + dx, z + dz, v);
            }
        }
    }
    fn corridor(&mut self, x1: i32, z1: i32, x2: i32, z2: i32) {
        let (x_lo, x_hi) = (x1.min(x2), x1.max(x2));
        let (z_lo, z_hi) = (z1.min(z2), z1.max(z2));
        for x in x_lo..=x_hi {
            self.world.set(x, z1, Voxel::Floor);
        }
        for z in z_lo..=z_hi {
            self.world.set(x2, z, Voxel::Floor);
        }
    }
}

fn main() {
    let mut world = World::new(30, 15);
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let mut gen = LevelGen { world: &mut world, rng: &mut rng };
    gen.room(2, 2, 8, 8);
    gen.room(18, 5, 8, 5);
    gen.corridor(9, 5, 18, 5);
    world.render();
}
```

## 8 · Rust / Arch 落地代码

完整 immediate-mode 关卡生成:

```rust
// Cargo.toml:
// [dependencies]
// rand = "0.8"
// rand_xoshiro = "0.6"

use rand::{Rng, SeedableRng};
use rand_xoshiro::Xoshiro256PlusPlus;

#[derive(Clone, Copy, PartialEq, Debug)]
enum Voxel { Empty, Wall, Floor, Door }

struct World {
    w: usize,
    h: usize,
    voxels: Vec<Voxel>,
}

impl World {
    fn new(w: usize, h: usize) -> Self {
        Self { w, h, voxels: vec![Voxel::Empty; w * h] }
    }
    fn set(&mut self, x: i32, z: i32, v: Voxel) {
        if x < 0 || z < 0 { return; }
        let (xu, zu) = (x as usize, z as usize);
        if xu >= self.w || zu >= self.h { return; }
        self.voxels[zu * self.w + xu] = v;
    }
    fn get(&self, x: i32, z: i32) -> Voxel {
        if x < 0 || z < 0 { return Voxel::Empty; }
        let (xu, zu) = (x as usize, z as usize);
        if xu >= self.w || zu >= self.h { return Voxel::Empty; }
        self.voxels[zu * self.w + xu]
    }
    fn render(&self) {
        for z in 0..self.h {
            let mut line = String::new();
            for x in 0..self.w {
                let c = match self.voxels[z * self.w + x] {
                    Voxel::Empty => ' ',
                    Voxel::Wall => '#',
                    Voxel::Floor => '.',
                    Voxel::Door => '+',
                };
                line.push(c);
            }
            println!("{}", line);
        }
    }
}

struct LevelGen<'a, R: Rng> {
    world: &'a mut World,
    rng: &'a mut R,
}

impl<'a, R: Rng> LevelGen<'a, R> {
    fn room(&mut self, x: i32, z: i32, w: i32, h: i32) -> (i32, i32) {
        for dx in 0..w {
            for dz in 0..h {
                let edge = dx == 0 || dx == w - 1 || dz == 0 || dz == h - 1;
                let v = if edge { Voxel::Wall } else { Voxel::Floor };
                self.world.set(x + dx, z + dz, v);
            }
        }
        (x + w / 2, z + h / 2) // 返回中心
    }
    fn corridor(&mut self, x1: i32, z1: i32, x2: i32, z2: i32) {
        let (x_lo, x_hi) = if x1 < x2 { (x1, x2) } else { (x2, x1) };
        let (z_lo, z_hi) = if z1 < z2 { (z1, z2) } else { (z2, z1) };
        for x in x_lo..=x_hi {
            if self.world.get(x, z1) == Voxel::Wall {
                self.world.set(x, z1, Voxel::Door);
            } else {
                self.world.set(x, z1, Voxel::Floor);
            }
        }
        for z in z_lo..=z_hi {
            if self.world.get(x2, z) == Voxel::Wall {
                self.world.set(x2, z, Voxel::Door);
            } else {
                self.world.set(x2, z, Voxel::Floor);
            }
        }
    }
    fn random_room(&mut self, min_size: i32, max_size: i32) -> (i32, i32, i32, i32) {
        let w = self.rng.gen_range(min_size..=max_size);
        let h = self.rng.gen_range(min_size..=max_size);
        let x = self.rng.gen_range(1..(self.world.w as i32 - w - 1));
        let z = self.rng.gen_range(1..(self.world.h as i32 - h - 1));
        self.room(x, z, w, h);
        (x, z, w, h)
    }
}

fn main() {
    println!("=== Level 1: Hand-placed ===");
    let mut world = World::new(30, 15);
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let mut gen = LevelGen { world: &mut world, rng: &mut rng };
    let r1 = gen.room(2, 2, 8, 8);
    let r2 = gen.room(18, 5, 8, 6);
    gen.corridor(r1.0, r1.1, r2.0, r2.1);
    world.render();

    println!("\n=== Level 2: Random rooms with seed=42 ===");
    let mut world = World::new(40, 20);
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let mut gen = LevelGen { world: &mut world, rng: &mut rng };
    let mut rooms = vec![];
    for _ in 0..5 {
        rooms.push(gen.random_room(5, 8));
    }
    for w in rooms.windows(2) {
        let center1 = (w[0].0 + w[0].2 / 2, w[0].1 + w[0].3 / 2);
        let center2 = (w[1].0 + w[1].2 / 2, w[1].1 + w[1].3 / 2);
        gen.corridor(center1.0, center1.1, center2.0, center2.1);
    }
    world.render();

    println!("\n=== Level 2 rerun with same seed (should match) ===");
    let mut world = World::new(40, 20);
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let mut gen = LevelGen { world: &mut world, rng: &mut rng };
    let mut rooms = vec![];
    for _ in 0..5 { rooms.push(gen.random_room(5, 8)); }
    for w in rooms.windows(2) {
        let center1 = (w[0].0 + w[0].2 / 2, w[0].1 + w[0].3 / 2);
        let center2 = (w[1].0 + w[1].2 / 2, w[1].1 + w[1].3 / 2);
        gen.corridor(center1.0, center1.1, center2.0, center2.1);
    }
    world.render();
    // 两次输出相同
}
```

## 10 · 工程反思

Day 659 传达的核心工程教训:**编辑器是 game development 的 force multiplier**。

新手以为"游戏 = 运行时",资深工程师知道**"工具链决定团队效率"**。好的编辑器让设计师效率 10x,坏的编辑器拖累整个团队。Unreal / Unity 的成功 50% 是编辑器优秀。

**编辑器功能**:

- **场景编辑**:拖拽放置物体
- **属性编辑**:实时调参数
- **资产管理**:浏览 / 搜索 / 导入
- **预览**:运行 + 暂停 + 单步
- **构建**:一键打包发布

每个功能节省团队大量时间。Casey 在 HH 演示的是简化版本,工业级编辑器几十万行代码。

**为什么 Casey 自研编辑器?**

因为 HH 的需求特殊(voxel 编辑),Unity / Unreal 的编辑器不直接适用。资深游戏程序员的能力:**评估"自研 vs 用现成"**——大多数情况用现成,特殊需求才自研。

**第二条教训**:**immediate-mode UI 适合编辑器**。

编辑器需要快速迭代——加新控件、改布局、可视化数据。Immediate-mode UI(ImGui)让这些简单——每帧重新构造 UI,无需 retained state。Casey 在 HH 用 immediate-mode 做 debug overlay 和编辑器,这是工业级编辑器的标准选择。

Unity / Unreal 的编辑器用 retained-mode(因为历史),但新编辑器(bevy_editor / rend3_imagem)用 immediate-mode。

**第三条教训**:**编辑器 = 数据 + UI + 序列化**。

编辑器的本质是:

- **数据**:场景 / 物体 / 属性(结构化)
- **UI**:让用户编辑数据(可视化)
- **序列化**:存盘 / 加载(persistence)

每个部分都要做好。Casey 在 HH 把这三部分串起来,演示完整编辑器。

**迁移到其他领域**:

"编辑器思维"在多处通用:

- **数据库**:phpMyAdmin / DBeaver
- **音乐**:DAW(Digital Audio Workstation)

每个领域都有"编辑器"作为核心工具。Casey 在 HH 演示的是游戏版本,但思路普适。

## N0 • 深度教学补充

### 核心概念重新梳理

Day 659 涉及的核心概念需要在多个层次上理解:

**第一层:直观理解**

新手第一次接触概念,需要建立直觉。例如 voxel collision 是"虚拟物体不能穿过虚拟墙"——这个直觉每个人都能从现实经验获得。

**第二层:数学理解**

把直觉形式化。collision = "两个几何体的体积有交集"。对于 AABB,这等价于"三轴投影都重叠"。

**第三层:工程理解**

数学正确不等于工程实现正确。要考虑:

- 浮点精度边界
- 性能(每帧 N 个查询)
- 内存(数据结构紧凑)
- 边角 case(无穷大、NaN、负数)

**第四层:工业理解**

工业级要再加:

- 多线程安全
- SIMD 优化
- 网络同步(多人游戏)
- 跨平台(Windows/Mac/Linux/Mobile)
- 可访问性(色盲友好)
- 反作弊

每层理解都让代码更鲁棒。资深工程师在所有层次同时思考。

### 实际工程的细节

工业代码 80% 是"边角 case 处理",20% 是"核心算法"。Casey 在 HH 演示核心,工业代码加大量边角处理。

**边角 case 类型**:

1. 空输入(空 Vec、null pointer)
2. 极端输入(NaN、无穷大、超大数)
3. 并发竞争(多线程同时访问)
4. 资源不足(内存满、磁盘满)
5. 网络异常(超时、断连、包丢失)
6. 版本不兼容(老配置 / 新代码)
7. 权限错误(只读文件、无网络)
8. 用户误操作(连点、撤销重做)

每个 case 都要单独处理。这是工业代码 50%+ 行数的原因。

### 优化思路

性能优化有顺序:

1. **算法**:O(N²) → O(N log N),最大提升
2. **数据结构**:Vec → HashMap / BTreeMap,常数提升
3. **Cache**:AoS → SoA,cache 命中提升
4. **SIMD**:4-16 元素并行,巨大常数提升
5. **GPU**:数千核并行,极致性能
6. **分布式**:多机器,无限扩展

每级提升都需要更复杂的代码。先优化低级,够用再升级。
