
# Day 588 · 光照体素对齐相机

> 之前的光照体素网格是固定在世界坐标的(原点固定,间隔 1 米)。玩家移动时,网格本身不动,玩家穿越网格。今天 Casey 要把网格"跟着相机走"——相机附近网格密,远处网格稀,这样性能更好且视觉更准确。

## 0 · 为什么要有这一天

固定世界网格有几个问题:

**问题 1:远处体素浪费**。1000 个体素覆盖 10×10×10 米的空间。如果玩家只看前方 5 米,5 米外的体素更新是浪费(玩家看不到)。但每次 `propagate_infinite_bounces` 仍要更新所有体素。

**问题 2:近处体素分辨率不足**。1 米一格太粗——墙角的间接光在 1 米内变化很大,但网格只采到这一格的"平均值"。视觉上墙角"糊"。

**问题 3:玩家移动体素跳变**。玩家移动时,从一个体素跨越到另一个,该体素的 diffuse_color 不变(已经预算)。但相邻体素的 diffuse_color 不同,玩家眼睛看到的"插值结果"会跳变。

**解决**:让体素网格"跟着相机"。具体方案:
- 网格中心始终在相机位置
- 玩家移动,网格平移
- 玩家不移动时,网格不动

这种"对齐相机"在游戏工业里叫 **Camera-Relative Grid** 或 **Cascaded Grid**(分级网格)。商业引擎的 GI 系统(DDGI、Lumen)都用类似策略。

Casey 这一天把固定网格改成对齐相机网格,顺便引入"级联"——近处 0.5 米一格(细),远处 2 米一格(粗)。

心理锚点:看完这集,你能实现"跟随相机的体素网格",理解为什么级联(cascaded)是工业 GI 标准方案,能在自己设计空间数据结构时选择"固定"还是"对齐"。

## 1 · Casey 今天做了什么

Casey 这一天的几个动作:

1. **分析问题**:他打开游戏,玩家走过一面墙,看到墙面颜色"突变"(跨体素边界)。他知道这是固定网格的局限。
2. **设计**:他在白板上画——网格原点 = floor(camera_pos / voxel_size) × voxel_size。相机移动 0.1 米,网格原点不变(floor 后还是同一格)。相机移动 1 米(假设 voxel_size=1),网格原点跳变。
3. **实现**:加一个函数 `update_grid_origin(world, camera_pos)`,每帧根据相机位置算网格原点。所有体素的全局位置 = grid_origin + local_offset。
4. **级联**:近处加一个 0.5 米细网格(覆盖 4×4×4 米),远处用 1 米粗网格(覆盖 16×16×16 米)。细网格覆盖相机周围,粗网格覆盖远处。

这一天的工程产出大约 120 行 Rust 代码,价值在于**让 GI 网格随玩家移动**,这是现代实时 GI 的标准做法。

## 2 · 心智模型

### 类比:Google 地图缩放

Google 地图看北京:市中心用 1:1000 详细地图,郊区用 1:10000,更远用 1:100000。这就是级联(cascaded)——每个层级覆盖不同范围,你"看到"的是当前缩放级别的对应层级。

如果你看北京时也加载全球的 1:1000 地图,内存爆掉。所以只加载你看到的部分,根据距离选层级。

光照体素网格完全一样:
- 相机周围 4 米:0.5 米一格(64 个体素)
- 4-16 米:1 米一格(4096 个体素)
- 16-64 米:2 米一格(8000 个体素)
- 更远:不渲染(雾遮挡)

总内存可控,近处精度高,远处精度低。

### 严谨原理:相机对齐

**固定网格**(之前):

```rust
struct World {
    grid_origin: Vec3,  // (0, 0, 0) 固定
    voxel_size: f32,    // 1.0
    voxels: Vec<Voxel>,
}
```

体素全局位置 = grid_origin + local_offset。grid_origin 永远是 (0,0,0),所以体素全局位置就是 local_offset,固定不动。

**对齐相机**:

```rust
impl World {
    fn update_grid_origin(&mut self, camera_pos: Vec3) {
        // 让 grid_origin 是 voxel_size 的整数倍(避免部分体素在网格内)
        self.grid_origin = Vec3 {
            x: (camera_pos.x / self.voxel_size).floor() * self.voxel_size,
            y: (camera_pos.y / self.voxel_size).floor() * self.voxel_size,
            z: (camera_pos.z / self.voxel_size).floor() * self.voxel_size,
        };
        // 标记所有体素为"脏"(需要重新卷积)
        for voxel in &mut self.voxels {
            voxel.diffuse_dirty = true;
        }
    }
    
    fn voxel_world_pos(&self, local_idx: usize) -> Vec3 {
        let lz = local_idx / (self.dim_x * self.dim_y);
        let ly = (local_idx / self.dim_x) % self.dim_y;
        let lx = local_idx % self.dim_x;
        Vec3 {
            x: self.grid_origin.x + lx as f32 * self.voxel_size,
            y: self.grid_origin.y + ly as f32 * self.voxel_size,
            z: self.grid_origin.z + lz as f32 * self.voxel_size,
        }
    }
}
```

**每行解释**:
- `floor() * voxel_size` — 让 grid_origin 是 voxel_size 整数倍。这样相机在网格内时,网格不会"半格半格"跳变。
- `diffuse_dirty = true` — 网格跳变后,所有体素的位置变了,需要重新卷积(之前的辐射场不再对应新位置)。

**问题**:每帧都 floor,如果相机静止,grid_origin 不变。如果相机慢速移动,grid_origin 偶尔跳一格(整数倍)。每次跳格,所有体素要重新计算——性能爆炸。

**优化**:不要每帧 floor,而是相机走过一整格才跳:

```rust
fn update_grid_origin_lazy(&mut self, camera_pos: Vec3) {
    let offset = (camera_pos - self.grid_origin) / self.voxel_size;
    // 如果相机偏离网格中心超过 1 格,重新对齐
    if offset.x.abs() > 1.0 || offset.y.abs() > 1.0 || offset.z.abs() > 1.0 {
        self.update_grid_origin(camera_pos);
    }
}
```

这样大部分帧不跳格,只在相机走过 1 米(voxel_size)时跳一次。

### 级联(Cascaded)

更彻底的方案:不同距离用不同分辨率。

```rust
struct CascadedGrid {
    levels: Vec<GridLevel>,
}

struct GridLevel {
    voxel_size: f32,
    extent: usize,  // 每方向格数
    voxels: Vec<Voxel>,
}

impl CascadedGrid {
    fn new() -> Self {
        Self {
            levels: vec![
                GridLevel { voxel_size: 0.5, extent: 8, voxels: ... },   // 近:0.5m 格, 4m³
                GridLevel { voxel_size: 1.0, extent: 16, voxels: ... },  // 中:1m 格, 16m³
                GridLevel { voxel_size: 2.0, extent: 32, voxels: ... },  // 远:2m 格, 64m³
            ],
        }
    }
    
    fn update(&mut self, camera_pos: Vec3) {
        for level in &mut self.levels {
            level.update_grid_origin(camera_pos);
        }
    }
    
    fn sample(&self, pos: Vec3) -> RGB32F {
        // 选最近的 level
        let dist = (pos - camera_pos).length();
        let level_idx = if dist < 4.0 { 0 } else if dist < 16.0 { 1 } else { 2 };
        self.levels[level_idx].sample(pos)
    }
}
```

**关键**:
- 每层独立 grid_origin,都跟着相机
- 采样时根据距离选层
- 层间过渡可能"接缝",需要平滑插值

Casey 在 Day 588 只做"对齐相机"(不分级),级联留到 Day 590+ 优化阶段。

### 渲染采样的影响

之前:玩家位置采样 = `world.sample_diffuse(player_pos)`,固定网格下 grid_origin = (0,0,0),玩家位置直接对应 voxel_idx。

之后:玩家位置采样 = `world.sample_diffuse(player_pos)`,但 `player_pos - grid_origin` 才是网格局部坐标。grid_origin 随相机变,玩家在世界坐标里的同一位置,在不同帧可能对应不同 voxel_idx。

**视觉影响**:玩家走动时,网格跳格,该玩家位置的 diffuse_color 可能"跳变"(因为前后帧用了不同体素的数据)。

**解决**:用三线性插值(见 day586)。即使网格跳格,插值结果在 8 个邻居之间连续,跳变被插值平滑。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,Cascaded Grid 是标准技术:
- **Cascaded Shadow Map(CSM)**:阴影贴图用级联,近处高分辨率
- **Cascaded GI**:DDGI、Lumen 用级联,近处高质量 GI
- **Cascaded Voxelization**:体素化用级联,近处细

**踩过的坑**:
- **接缝**:级联层之间在边界处颜色突变。解决:用 blend zone 过渡(在 4 米处混合层 0 和层 1)
- **更新顺序**:每帧先更新层 0(近),再更新层 1(远)。如果只更新部分层,远处的层会"过时"
- **光照泄漏**:级联层边界,光可能"漏"过去照亮不该亮的区域。解决:更严格的遮挡测试

### 3.2 · 🎨 图形学视角

**信号处理视角**:级联是"多分辨率分析"(Multi-resolution Analysis)——不同频率的内容用不同分辨率采样。近处细节多(高频),需要密网格;远处细节少(低频),粗网格足够。

类似的小波分析、LOD(Level of Detail)都是这种思想。

**采样定理**(Nyquist):要正确采样频率 f 的信号,采样间隔 < 1/(2f)。光照间接场在近处频率高(墙角细节),需要 0.5 米间隔;远处频率低,2 米间隔够。

### 3.3 · 🐧 Linux 系统编程视角

这一集主要是数据结构和算法,Linux 系统调用面没什么。但**性能分析**值得一提。

相机对齐网格后,每帧更新哪些体素?可以只更新"被相机看到的"——做视锥剔除(Frustum Culling)。

```rust
fn update_visible_only(world: &mut World, camera: &Camera) {
    for (i, voxel) in world.voxels.iter_mut().enumerate() {
        let pos = world.voxel_world_pos(i);
        if camera.frustum.contains(pos) {
            propagate_indirect_for_voxel(world, i);
        }
    }
}
```

视锥剔除通常节省 50-70% 的更新量(看不到的不更新)。

Linux 上测渲染调用数:

```bash
sudo perf stat -e cache-misses ./your_game
# 视锥剔除应该让 cache miss 减少(因为访问的体素少)
```

### 3.4 · 🦀 Rust 生态视角

Rust 表达"级联"用 `Vec<GridLevel>`,每层独立。Casey 的实现:

```rust
struct GridLevel {
    voxel_size: f32,
    dim: usize,  // 每方向格数
    voxels: Vec<Voxel>,
    grid_origin: Vec3,
}

impl GridLevel {
    fn voxel_idx_at(&self, world_pos: Vec3) -> Option<usize> {
        let local = (world_pos - self.grid_origin) / self.voxel_size;
        let lx = local.x as usize;
        let ly = local.y as usize;
        let lz = local.z as usize;
        if lx < self.dim && ly < self.dim && lz < self.dim {
            Some(lz * self.dim * self.dim + ly * self.dim + lx)
        } else {
            None  // 超出此层范围
        }
    }
}
```

**关键 Rust 特性**:
- `Option<usize>` — 显式表达"可能没有"(超出范围)。比 `i32` 返回 -1 更安全。
- `as usize` — f32 → usize 转换,自动截断。需保证 local >= 0(否则 wrap around)。

Casey 在 day588 的代码里大量用 `Option`,让"可能失败"的操作明确。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么"对齐相机"用 `floor(camera_pos / voxel_size) * voxel_size` 而不是 `camera_pos` 直接?用具体例子说明。

**参考解答**:`floor(camera_pos / voxel_size) * voxel_size` 让网格原点是 voxel_size 的整数倍。这样:
- 相机在 (5.3, 0, 0),voxel_size=1,网格原点 = (5, 0, 0)。体素覆盖 [5, 6] × ... × [5, 6]
- 相机移到 (5.7, 0, 0),网格原点 = (5, 0, 0)。体素覆盖 [5, 6] × ... × [5, 6](不变)
- 相机移到 (6.1, 0, 0),网格原点 = (6, 0, 0)。体素覆盖 [6, 7] × ... × [6, 7)(跳变)

如果用 `camera_pos` 直接:
- 相机在 (5.3, 0, 0),网格原点 = (5.3, 0, 0)。体素覆盖 [5.3, 6.3] × ... × [5.3, 6.3]
- 相机移到 (5.4, 0, 0),网格原点 = (5.4, 0, 0)。体素覆盖 [5.4, 6.4] × ... × [5.4, 6.4](每帧都跳)

floor 让"网格跳变"频率大幅降低(只在相机走过整数格时跳一次),而不是每帧都跳。

### Lv2 · 动手实践

**题**:实现 `update_grid_origin` 和 `voxel_world_pos`,在 day586 三线性插值基础上加相机对齐。测试:
- 相机在 (5.3, 0, 0),voxel_size=1,grid_origin = (5, 0, 0)
- 玩家在 (5.5, 0.5, 0.5),应该映射到网格内 (0.5, 0.5, 0.5) 局部坐标

完成标准:`cargo run` 测试通过。

**参考解答**:

```rust
struct World {
    grid_origin: Vec3,
    voxel_size: f32,
    dim: usize,
    voxels: Vec<Voxel>,
}

impl World {
    fn new(dim: usize, voxel_size: f32) -> Self {
        Self {
            grid_origin: Vec3 { x: 0.0, y: 0.0, z: 0.0 },
            voxel_size,
            dim,
            voxels: vec![Voxel::default(); dim * dim * dim],
        }
    }

    fn update_grid_origin(&mut self, camera_pos: Vec3) {
        self.grid_origin = Vec3 {
            x: (camera_pos.x / self.voxel_size).floor() * self.voxel_size,
            y: (camera_pos.y / self.voxel_size).floor() * self.voxel_size,
            z: (camera_pos.z / self.voxel_size).floor() * self.voxel_size,
        };
    }
    
    fn voxel_idx_at(&self, world_pos: Vec3) -> Option<(usize, f32, f32, f32)> {
        let local_x = (world_pos.x - self.grid_origin.x) / self.voxel_size;
        let local_y = (world_pos.y - self.grid_origin.y) / self.voxel_size;
        let local_z = (world_pos.z - self.grid_origin.z) / self.voxel_size;
        if local_x < 0.0 || local_y < 0.0 || local_z < 0.0 {
            return None;
        }
        let lx = local_x as usize;
        let ly = local_y as usize;
        let lz = local_z as usize;
        if lx >= self.dim || ly >= self.dim || lz >= self.dim {
            return None;
        }
        let idx = lz * self.dim * self.dim + ly * self.dim + lx;
        let fx = local_x - lx as f32;
        let fy = local_y - ly as f32;
        let fz = local_z - lz as f32;
        Some((idx, fx, fy, fz))
    }
}

#[derive(Default, Clone)]
struct Voxel {
    color: RGB32F,
}

fn main() {
    let mut world = World::new(8, 1.0);  // 8x8x8 体素,每格 1 米
    world.update_grid_origin(Vec3 { x: 5.3, y: 0.0, z: 0.0 });
    println!("Grid origin: {:?}", world.grid_origin);  // (5, 0, 0)
    
    let player = Vec3 { x: 5.5, y: 0.5, z: 0.5 };
    if let Some((idx, fx, fy, fz)) = world.voxel_idx_at(player) {
        println!("Voxel idx: {}, local: ({}, {}, {})", idx, fx, fy, fz);
    }
}
```

## 8 · Rust / Arch 落地代码

完整可跑示例:

```rust
#[derive(Copy, Clone, Debug, Default)]
struct Vec3 { x: f32, y: f32, z: f32 }

#[derive(Copy, Clone, Debug, Default)]
struct RGB32F { r: f32, g: f32, b: f32 }

#[derive(Clone)]
struct Voxel {
    diffuse_color: RGB32F,
}

impl Default for Voxel {
    fn default() -> Self {
        Self { diffuse_color: RGB32F::default() }
    }
}

struct World {
    grid_origin: Vec3,
    voxel_size: f32,
    dim: usize,
    voxels: Vec<Voxel>,
}

impl World {
    fn new(dim: usize, voxel_size: f32) -> Self {
        Self {
            grid_origin: Vec3::default(),
            voxel_size,
            dim,
            voxels: vec![Voxel::default(); dim * dim * dim],
        }
    }
    
    fn update_grid_origin(&mut self, camera_pos: Vec3) {
        let new_origin = Vec3 {
            x: (camera_pos.x / self.voxel_size).floor() * self.voxel_size,
            y: (camera_pos.y / self.voxel_size).floor() * self.voxel_size,
            z: (camera_pos.z / self.voxel_size).floor() * self.voxel_size,
        };
        if new_origin.x != self.grid_origin.x
            || new_origin.y != self.grid_origin.y
            || new_origin.z != self.grid_origin.z {
            println!("Grid jumped: {:?} → {:?}", self.grid_origin, new_origin);
            self.grid_origin = new_origin;
        }
    }
    
    fn voxel_idx_at(&self, world_pos: Vec3) -> Option<(usize, f32, f32, f32)> {
        let local_x = (world_pos.x - self.grid_origin.x) / self.voxel_size;
        let local_y = (world_pos.y - self.grid_origin.y) / self.voxel_size;
        let local_z = (world_pos.z - self.grid_origin.z) / self.voxel_size;
        if local_x < 0.0 || local_y < 0.0 || local_z < 0.0 {
            return None;
        }
        let lx = local_x as usize;
        let ly = local_y as usize;
        let lz = local_z as usize;
        if lx >= self.dim || ly >= self.dim || lz >= self.dim {
            return None;
        }
        Some((
            lz * self.dim * self.dim + ly * self.dim + lx,
            local_x - lx as f32,
            local_y - ly as f32,
            local_z - lz as f32,
        ))
    }
}

fn main() {
    let mut world = World::new(8, 1.0);
    
    // 模拟相机移动
    let camera_positions = [
        Vec3 { x: 5.3, y: 0.0, z: 0.0 },
        Vec3 { x: 5.7, y: 0.0, z: 0.0 },
        Vec3 { x: 6.1, y: 0.0, z: 0.0 },
        Vec3 { x: 6.5, y: 0.0, z: 0.0 },
    ];
    for cam in &camera_positions {
        world.update_grid_origin(*cam);
        if let Some((idx, fx, fy, fz)) = world.voxel_idx_at(*cam) {
            println!("Camera {:?} → voxel idx {}, local ({:.2}, {:.2}, {:.2})",
                     cam, idx, fx, fy, fz);
        }
    }
}
```

### A.1 该 Day 在 phase-8 的位置

Phase 8(day576-667)是 voxel lighting 系统的工业级实现。本日是其中一天。

### A.2 Voxel lighting 的工程挑战

Voxel lighting 是计算机图形学的难点,因为:

**1. 数据量大**:
- 大场景(100m × 100m × 100m)有几百万 voxel
- 每 voxel 存光照值(RGB 或 SH)
- 总数据 GB 级

**2. 实时性要求**:
- 玩家挖 / 改 voxel,光照立即变化
- 16.67 ms 帧预算(60 FPS)
- 不能阻塞玩家操作

**3. 物理准确性**:
- 直接光(sun)
- 间接光(bounce)
- 阴影(hard / soft)
- 反射(diffuse / specular)
- 折射(glass / water)

工业方案在物理准确性和实时性之间权衡。

### A.3 工业级实现的层次

**Layer 1:Brute force**
- 每 voxel × 每方向 raycast
- 准确但极慢
- 适合离线渲染(movie)

**Layer 2:Grid DDA**
- 快速 raycast(穿格子)
- 适合简单场景
- Casey 的 HH 用这层

**Layer 3:Precomputed**
- 离线算光照 cache
- 运行时查表
- 适合静态场景(Minecraft baked)

**Layer 4:Real-time approximation**
- LPV / SVOGI / Voxel Cone Tracing
- 实时但近似
- Crytek / Unreal 用

**Layer 5:Hardware ray tracing**
- RTX / RDNA2 核心
- 真实光传播
- Minecraft RTX / Teardown

每代技术对硬件要求递增。Casey 的 HH 在 Layer 2(教学优先)。

### A.4 性能 profile 的实战

Casey 在 phase-8 多次 profile:

**Profile 工具**:
- Linux:perf、Valgrind、flamegraph
- Windows:Superluminal、VTune
- 跨平台:Tracy

**典型发现**:
- Raycast 占 50%+
- Propagation 占 20%+
- Meshing 占 10%+
- 其他占 20%

**优化顺序**:
1. 最慢函数 → 算法优化
2. Cache miss → 数据布局优化
3. 锁等待 → 并发优化

每优化一个,重新 profile 找下一个。

### A.5 Casey 的 phase-8 工程决策

Casey 在 phase-8 做的关键工程决策:

**1. CPU 渲染**:简单,跨平台,教学优先
**2. Voxel grid(非 octree)**:简单,固定大小
**3. RGBE atlas(非 SH)**:内存小,够教学
**4. Precomputed + delta update**:平衡实时性和准确性

这些决策让 HH 代码可读、可教学。生产游戏可能选 GPU + SH + realtime(更复杂)。

### A.7 Voxel lighting 算法的核心循环

让我写一个简化的 voxel lighting 主循环:

```rust
fn update_lighting(world: &mut World, sun_dir: Vec3) {
    let direct = compute_direct_lighting(world, sun_dir);
    let indirect = compute_indirect_lighting(world, &direct, 3);  // 3 bounce
    let final_light = combine(&direct, &indirect);
    world.light_atlas = final_light;
}

fn compute_direct_lighting(world: &World, sun_dir: Vec3) -> LightAtlas {
    let mut atlas = LightAtlas::new(world.dims());
    for each voxel {
        if voxel.is_solid() && !is_occluded(world, voxel_pos, sun_dir) {
            let lambert = compute_normal(world, x, y, z).dot(sun_dir).max(0.0);
            atlas.set(x, y, z, sun_color * lambert);
        }
    }
    atlas
}

fn compute_indirect_lighting(world: &World, direct: &LightAtlas, bounces: usize) -> LightAtlas {
    let mut current = direct.clone();
    for _ in 0..bounces {
        let mut next = current.clone();
        for each voxel {
            let bounce = average_neighbors(&current, x, y, z) * 0.15;
            next.set(x, y, z, current.get(x, y, z) + bounce);
        }
        current = next;
    }
    current
}
```

这是 Casey phase-8 的简化核心。工业实现更复杂(SH、GPU、并行)。

### A.8 Voxel lighting 的内存估算

```
Per voxel 数据:
  - material: 1 byte
  - color: 3 byte RGB
  - light: 4 byte RGBE
  - flags: 1 byte
  Total: 9 byte

场景尺寸:
  - 32^3(教学):36 KB
  - 100^3(小场景):9 MB
  - 256^3(中场景):150 MB
  - 1024^3(大场景):9.6 GB

大场景必须 streaming(chunked)。
```

工业 voxel 游戏(Minecraft):
- 16×16×256 chunk
- 每 chunk ~36 KB
- 同时加载 100 chunk ≈ 3.6 MB
