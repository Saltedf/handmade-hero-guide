
# Day 637 · 加碰撞球

> 体素碰撞到现在一直用 AABB(axis-aligned bounding box,轴对齐包围盒)。今天 Casey 给玩家额外加一个 **碰撞球**——为什么?因为玩家在窄道拐角时,AABB 的"对角线"会让"看起来不该撞"的位置撞上。球没有"对角线"概念,拐角手感更顺。

## 0 · 为什么要有这一天

如果你玩过早期 RPG(《塞尔达传说:众神的三角力量》),你会注意到:林克在墙角拐弯时,**贴着墙滑动**特别顺滑,不会有"卡角"的感觉。但如果你写过 AABB 碰撞,你会发现:**玩家很容易卡在墙角**——只要 bbox 对角线和墙角重叠一点点,就被拒了。

原因:AABB 的"有效碰撞区域"是它的整个矩形,包括对角线角落。当玩家斜着靠近墙角时,AABB 的右上角先碰到墙,触发"拒绝位移",玩家被卡。可实际上,玩家**视觉上**还没碰到墙——视觉 sprite 通常比 bbox 小一圈,或者视觉是圆形(球的角色)。

工业做法:**bbox 做粗扫(broad phase),球做细扫(narrow phase)**。先用便宜的 AABB 检查"附近有哪些 voxel 可能撞",再用球(更贴合玩家手感)做精确判定。Casey 今天做的就是这个组合。

为什么是球?几个原因:

- **各向同性**:球对方向不敏感,玩家从任何角度接近墙,碰撞距离都一样
- **便宜**:球-voxel 距离只需要算球心到 voxel AABB 的最近点距离,3 个 min/max + 1 个 sqrt
- **手感顺**:玩家在拐角时,球会"滚"过去,不像 AABB 那样"撞角"

**更深层的"为什么球"——直觉 vs 数学**:

球的"手感顺"来自**法线连续性**。AABB 的法线只有 6 个方向(±x, ±y, ±z),拐角处法线"跳变"——上一帧朝 +x 推,下一帧朝 +y 推,玩家感受"颠簸"。球的法线连续——从墙正面到墙侧面,法线平滑过渡,玩家感受"顺滑"。

数学上,球-AABB 接触点的法线 = `(球心 - 最近点).normalized()`。这个向量是连续函数 of 球心位置——球心平滑移动,法线平滑变化。AABB 法线是 discontinuous function——球心穿过特定位置,法线突变。

**人类感知对 discontinuity 敏感**——电影 24 FPS 看起来流畅,但 frame stutter 让人难受,因为时间 discontinuity。同样,玩家移动"smooth"是连续,但碰撞响应 discontinuity 让人难受。

球 vs AABB 选择本质是 **continuity vs simplicity** 的权衡:

- 球:连续,但只能表达一个 blob
- AABB:不连续,但能表达矩形 / 房间
- 胶囊:连续(像球),能表达细长(像 AABB)

资深工程师按需求选——玩家用胶囊(连续 + 细长),静态 voxel 用 AABB(简单),物体用 convex(灵活)。

心理锚点:看完今天,你能:

- 实现 sphere-AABB 距离算法
- 理解 broad phase / narrow phase 的双层碰撞架构
- 解释为什么球比 AABB 手感好
- 区分 collision shape 的"continuity vs simplicity"
- 选合适的形状针对不同场景

## 1 · Casey 今天做了什么

1. 在玩家结构体里加一个 `collision_radius: f32` 字段,值大约 0.4(voxel 的一半)
2. 把原来的"扫 bbox 覆盖的 voxel"改成"扫球覆盖的 voxel"——球覆盖的 voxel 范围是 `floor(center - r)` 到 `floor(center + r)`
3. 对每个候选 voxel,用 sphere-AABB 最近点距离判断是否相交:距离 < r 即相交
4. 如果相交,做 unembed(沿球心到 voxel AABB 最近点反方向推)
5. 删掉旧的 AABB-only 碰撞代码
6. 测试:玩家在墙角拐弯不再卡顿,但留下一些 false negative(球太"圆",直角墙看起来有些"穿透")

Casey 没引入新的数学结构,只是把"AABB 重叠检测"换成"球-AABB 距离检测"。

## 2 · 心智模型

### 类比:篮球滚过积木

想象你拿一个篮球(玩家),在地板上滚,地板上散落一些方形积木(voxel)。篮球碰到积木时:

- 如果篮球**正对**积木,接触点在篮球正面中央
- 如果篮球**斜着**靠近积木角,接触点在篮球侧面
- 不管篮球从哪个方向靠近,接触点的**法线**都指向"从积木某面指向篮球中心"——这是球的核心优点

而如果是 AABB(方块)碰方块,接触点的法线**只有 6 个方向**(±x, ±y, ±z),所以 AABB 撞墙角时,玩家要么被推回 +x,要么被推回 +y,不会有"沿对角线滑出去"的中间状态。这就是为什么 AABB 拐角卡顿。

### 数学:球-AABB 距离

球心 C,半径 r;AABB 由 min/max 定义。**球心到 AABB 的最近点** = 把 C "clamp" 到 AABB 里:

```
closest.x = clamp(C.x, box.min.x, box.max.x)
closest.y = clamp(C.y, box.min.y, box.max.y)
closest.z = clamp(C.z, box.min.z, box.max.z)
```

`clamp(v, lo, hi) = max(lo, min(hi, v))` —— 把 v 限制在 [lo, hi] 范围。

**球到 AABB 的有符号距离**:

```
distance = |C - closest| - r
```

- `distance > 0`:不相交
- `distance = 0`:相切
- `distance < 0`:相交,穿透深度 `-distance`

**球-voxel 碰撞判定**:`distance < 0` ⟺ 球心到 voxel 的最近距离 < r。

如果相交,**unembed 方向** = `(C - closest).normalized()`,unembed 距离 = `-distance`。

```
correction = (C - closest).normalized() * (-distance)
            = (C - closest) / |C - closest| * (r - |C - closest|)
```

简化:令 `d = C - closest`,如果 `|d| < r`,则 correction = `d * (r / |d| - 1)` —— 但更直接是 `d + (-d.normalized() * r)`。或者最简洁:**把球心直接移到 `closest + d.normalized() * r`**。

### 公式推导:为什么 clamp 给出最近点

考虑 1D 情况。区间 [a, b],点 x:

- 如果 x < a,最近点是 a
- 如果 x ∈ [a, b],最近点是 x 本身(已经在区间里)
- 如果 x > b,最近点是 b

这就是 `clamp(x, a, b) = max(a, min(b, x))`。

3D 情况下,AABB 是三根轴上区间的"笛卡尔积",所以**最近点 = 三个 1D 最近点的组合**。这是个一般定理:**轴对齐形状的最近点 = 每根轴独立求最近点,然后组合**。

### Broad phase / Narrow phase 架构

工业级碰撞系统分两层:

**Broad phase(粗扫)**:从全部 N 个物体里,快速筛出"可能相交"的候选对。常用算法:

- **Sweep and prune**:三根轴上排序,扫描区间重叠
- **Uniform grid**:把世界切成格子,只检查同格 + 邻格
- **BVH**(bounding volume hierarchy):层次包围盒树,场景图标准
- **Quadtrees / Octrees**:空间分割树

**Narrow phase(细扫)**:对候选对做精确的形状-形状相交检测。常用算法:

- **GJK**(Gilbert-Johnson-Keerthi):任意凸形
- **SAT**(Separating Axis Theorem):多面体
- **球-AABB / AABB-AABB / 球-球**:专项代码

Casey 在 voxel 场景下,broad phase 是 trivial 的(只扫玩家 bbox 覆盖的 voxel,不超过 8 个),narrow phase 是球-AABB。这是 voxel 引擎的优势——**网格本身就是 broad phase**。

### 球的局限性

球很顺,但有局限:

- **不能精确表示细长物体**:剑、鞭子、长枪——这些用胶囊(capsule)更好
- **不能表示有方向的物体**:车、箭——这些用 OBB(oriented bounding box)
- **不能精确贴墙**:球贴墙时,接触点只有一点,玩家在墙边时会"晃"

Casey 用球是因为玩家形状接近一个 blob,圆球够用。如果将来要加细长武器,会再加胶囊。

### 胶囊简述

胶囊 = 两端球 + 中间圆柱。胶囊-AABB 距离 = 球心线段到 AABB 最近点的距离 - 半径。这是 3D 角色碰撞的标准(Unity / Unreal 默认角色碰撞体是胶囊)。

```rust
struct Capsule { a: Vec3, b: Vec3, r: f32 } // a, b 是两端球心

fn capsule_aabb_dist(c: &Capsule, box_min: Vec3, box_max: Vec3) -> f32 {
    let closest_on_segment = closest_point_on_segment(c.a, c.b, /* AABB 中心 */);
    // ... 把球心当成 closest_on_segment 做球-AABB 距离
}
```

**胶囊为什么是角色标准?**

人形角色大致是"细长 + 头"。胶囊完美匹配:

- 上端球 = 头
- 中间圆柱 = 身体
- 下端球 = 脚(平滑接触地面)

球 vs 胶囊 vs AABB 的"上下楼梯"对比:

- **AABB**:撞楼梯一级,卡住,无法上
- **球**:撞楼梯,球面"滑过"边,可以上,但脚下感觉"飘"
- **胶囊**:撞楼梯,胶囊下端球"卡入"边,推动胶囊向上,自然上楼

所以人形角色用胶囊。胶囊是工业级角色碰撞的标准。

**胶囊算法详解**:

胶囊的"轴"是线段 a → b。求胶囊到任意点 P 的距离:

1. 求 P 在线段 ab 上的投影 t(clamp 到 [0, 1])
2. 最近点 = a + t * (b - a)
3. 距离 = |P - 最近点| - 半径

AABB 的扩展:

1. 对 AABB 的 8 个角,分别求到胶囊的距离
2. 对胶囊两端球,分别求到 AABB 的距离
3. 取最小值

这种"组合"算法对凸形通用。但工业级物理引擎用 GJK(Gilbert-Johnson-Keerthi)——更通用,任意凸形。

**Casey 不用胶囊的智慧**:

HH 玩家形状简单(blob),球够用。胶囊复杂(线段 + 球 + 距离),不必要。资深工程师的能力是"识别最简方案"。如果未来 HH 加角色 / 武器,再切胶囊。

工业教训:**用最简单的够用方案,不要 over-engineer**。Unity / Unreal 默认胶囊因为它们是通用引擎,适用各种角色。HH 是单游戏,球就够。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏里"用球还是用 AABB 还是胶囊"是个经典选择题:

| 形状 | 优点 | 缺点 | 适合 |
|---|---|---|---|
| AABB | 最便宜,内存 6 个 float | 拐角卡顿,无方向 | 静态物体、Tile |
| 球 | 最便宜,内存 4 个 float | 不能细长 | 子弹、blob 角色 |
| 胶囊 | 角色手感好,贴墙顺 | 略贵 | 主角、人形 NPC |
| OBB | 有方向 | 最贵 | 车、家具 |
| Convex hull | 任意凸形 | 最贵 + GJK | 复杂物体 |

Casey 选球,因为 HH 玩家形状简单。但你后面如果做自己的 RPG,主角通常用胶囊。

### 3.2 · 图形学视角

球-AABB 距离在 shader 里也有用:

- **raymarching**(SDF 渲染):用球、盒子等基本 SDF 组合出复杂场景。球 SDF = `|p - c| - r`,AABB SDF 是 `length(max(abs(p - c) - h, 0))`。两者组合可以做出有机形状。
- **粒子碰撞**:GPU 粒子系统每帧百万粒子,用球-球或球-AABB 做 SIMD 批量检测。
- **阴影**:球谐光照(spherical harmonics)近似辐照度,本质也是球的函数。

**raymarching 详解**:

raymarching 是 SDF 渲染的核心算法。每个像素从相机发射射线,沿射线方向"行进"。每步:

1. 在当前点查 SDF,得到"到最近表面的距离"
2. 沿射线方向前进 SDF 距离(不会穿过表面,因为 SDF 是 signed distance)
3. 重复,直到 SDF < epsilon(到达表面)或超过 max_steps

球 SDF 是最简单的——`length(p - c) - r`。AABB SDF:`length(max(abs(p - c) - h, 0))`。

球-AABB 距离(球扫过的体积和 AABB 的距离)= `max(0, sdAABB - r)`。这在 raymarching 里表达"球形状的射线被 AABB 挡"。

Inigo Quilez(Shadertoy 创始人)的 SDF 网站列了几百个 SDF 公式。每个都是"球 / 盒 / 圆柱"基础形状的代数组合。学懂球-AABB 距离,你打开了 SDF 渲染的大门。

**粒子 collision 详解**:

GPU 粒子(Unity VFX Graph / Unreal Niagra)每帧百万粒子。每个粒子是球(球心 + 半径),场景是 voxel grid(AABB)。

SIMD 优化:GPU SIMD lane 一次处理 4-16 个粒子。每粒子:

1. 找球覆盖的 voxel(同 Casey 的算法)
2. 对每个 voxel 算球-AABB 距离
3. 如果距离 < 半径,做 unembed

这个算法在 GPU 上跑 100M+ 粒子 / 秒。CPU 上跑 1M 都难。这是 GPU 粒子系统的核心。

**球谐(Spherical Harmonics, SH)详解**:

SH 是球面上的正交函数基。前 9 个系数(L0, L1, L2)足够表示"低频"光分布——天空光、ambient。

工业用法:**Irradiance volume**。场景分成 3D grid,每格存 SH 系数(9 个 vec3 = 108 bytes)。运行时查询所在格的 SH,重建入射光分布。

SH 是"球"的代数表示。学懂 SH,你看 Unity / Unreal 的 GI 系统就不神秘。

工业教训:**球是图形学的"基础形状"**。从 collision 到 SDF 到 SH,球无处不在。Casey 在 HH Day 637 用球做 collision,但球的工业应用远不止 collision。

### 3.3 · Linux 系统编程视角

Linux 上的"球 vs AABB"对应概念:

- **进程亲和性(affinity)**:`sched_setaffinity` 把进程"绑定"到某 CPU 集合——CPU 集合是 bitmask,类似 voxel 占用,AABB 检测
- **NUMA 亲和**:进程内存"绑"到某 NUMA 节点,跨节点访问慢——类似 broad phase 决定"哪些 CPU 离内存近"
- **cgroup**:层级 cgroup 树类似 BVH,每个节点是子树的 bounding box

### 3.4 · Rust 生态视角

Rust 里球-AABB 的优雅写法:

```rust
use glam::Vec3;

#[derive(Copy, Clone, Debug)]
struct Sphere { center: Vec3, radius: f32 }

#[derive(Copy, Clone, Debug)]
struct Aabb { min: Vec3, max: Vec3 }

impl Aabb {
    fn closest_point(&self, p: Vec3) -> Vec3 {
        p.clamp(self.min, self.max) // glam 内置 clamp
    }
}

fn sphere_aabb_unembed(s: &Sphere, b: &Aabb) -> Option<Vec3> {
    let closest = b.closest_point(s.center);
    let d = s.center - closest;
    let dist_sq = d.length_squared();
    if dist_sq >= s.radius * s.radius {
        return None; // 不相交
    }
    let dist = dist_sq.sqrt();
    if dist < 1e-6 {
        // 球心在 AABB 内,选最浅轴推出(罕见)
        let to_center = (b.min + b.max) * 0.5 - s.center;
        return Some(to_center.normalized() * s.radius);
    }
    // 推到球面 = closest + d.normalized() * radius
    let correction = d * (s.radius / dist - 1.0);
    Some(correction)
}
```

注意 `clamp` 在 glam 里是方法 `Vec3::clamp(self, min, max)`,内部就是三个 `max(min(hi, x), lo)`。

`length_squared()` 比 `length()` 便宜(不开根号),适合做"先比较平方,必要时才开根号"。

## 6.5 · 工业实例:球-AABB 距离的工业应用

球-AABB 距离不仅在游戏 collision 用,工业多处用:

**SDF 渲染**(signed distance field):

Inigo Quilez 的 SDF 网站(iquilezles.org)列出几百个 SDF 公式。球 SDF 最简单:`sdSphere(p, c, r) = length(p - c) - r`。AABB SDF:`sdBox(p, b) = length(max(abs(p) - b, 0))`。

球-AABB 距离 = `max(0, sdAABB - r)`(球的 SDF 减去球半径)。这是 raymarching 的基础——每像素 raycast,用 SDF 决定射线行进距离。

**GPU 粒子 collision**:

GPU 粒子(每帧百万粒子)用球-AABB 批量 collision。每个粒子是球(球心 + 半径),场景是 voxel grid(AABB)。SIMD 一次处理 4-16 个粒子,性能 10x CPU。

**Spatial hash**:

球查询 spatial hash —— 把空间分成 grid,每个 cell 存 entity。球查询 = "扫球覆盖的 cell"。这正是 Casey 在 Day 637 做的。

**Spherical harmonic(球谐函数)**:

球谐是球面上的函数展开。光照用 SH 存入射光分布(9 个系数表示)。这是 ambient / GI 的基础。

每个应用都用球的"各向同性"——球没有"主方向",适合表达"无方向"的概念(光分布、辐射、噪声)。

**数学的统一**:

球-AABB 距离 = `length(sphere_center - clamp(sphere_center, aabb_min, aabb_max)) - sphere_radius`

这是非常简洁的公式。简洁性来自:

- clamp 函数(点到区间最近点)
- length 函数(向量长度)
- 减法(扣除半径)

每个操作都是基础数学。组合起来给出精确的几何结果。这是数学之美的体现——复杂概念(距离)用简单操作(clamp + length)表达。

工业教训:**好算法 = 简洁 + 正确 + 高效**。球-AABB 距离三者满足,所以是工业标准。资深工程师的标志是能识别"好算法",而非"看起来聪明"的复杂算法。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么球贴墙时玩家可以"斜着滑",而 AABB 不行?用接触点法线解释。

**参考解答**:球的接触点法线 = 球心到接触点的方向,这个方向可以是任意角度。玩家斜着靠近墙时,法线指向"球心到墙最近点"——可能是 45 度,玩家被推斜上方,自然"滑过"。AABB 的接触法线只能沿 ±x/y/z,玩家斜着靠近时,AABB 被推回纯 x 或纯 y,看起来就是"卡角"。

### Lv2 · 动手实践

**题**:实现 §3.4 的 `sphere_aabb_unembed`,写测试:

- 球心 (0, 0, 0),半径 1,AABB [0.5, 0.5, 0.5] - [1.5, 1.5, 1.5]:预期相交,解嵌向 (-1, -1, -1).normalized() * something
- 球心 (5, 5, 5),半径 1,AABB [0,0,0]-[1,1,1]:预期不相交

**参考解答**:

```rust
use glam::Vec3;

#[derive(Copy, Clone, Debug)]
struct Sphere { center: Vec3, radius: f32 }
#[derive(Copy, Clone, Debug)]
struct Aabb { min: Vec3, max: Vec3 }

impl Aabb {
    fn closest_point(&self, p: Vec3) -> Vec3 {
        p.clamp(self.min, self.max)
    }
}

fn sphere_aabb_unembed(s: &Sphere, b: &Aabb) -> Option<Vec3> {
    let closest = b.closest_point(s.center);
    let d = s.center - closest;
    let dist_sq = d.length_squared();
    if dist_sq >= s.radius * s.radius { return None; }
    let dist = dist_sq.sqrt();
    if dist < 1e-6 {
        let to_center = (b.min + b.max) * 0.5 - s.center;
        return Some(to_center.normalize_or_zero() * s.radius);
    }
    Some(d * (s.radius / dist - 1.0))
}

fn main() {
    let s1 = Sphere { center: Vec3::ZERO, radius: 1.0 };
    let b1 = Aabb { min: Vec3::splat(0.5), max: Vec3::splat(1.5) };
    println!("Case 1: {:?}", sphere_aabb_unembed(&s1, &b1));
    // 球心 (0,0,0) 到 AABB 最近点 (0.5, 0.5, 0.5),d = (-0.5,-0.5,-0.5),dist = 0.866
    // 解嵌: d * (1/0.866 - 1) = d * 0.155 ≈ (-0.077, -0.077, -0.077)

    let s2 = Sphere { center: Vec3::splat(5.0), radius: 1.0 };
    let b2 = Aabb { min: Vec3::ZERO, max: Vec3::splat(1.0) };
    println!("Case 2: {:?}", sphere_aabb_unembed(&s2, &b2));
    // 预期 None
}
```

注意 glam 的 `normalize_or_zero()` 在零向量时返回零向量,避免 NaN。

## 8 · Rust / Arch 落地代码

完整可跑示例:

```rust
// Cargo.toml:
// [dependencies]
// glam = "0.29"

use glam::{Vec3, IVec3};

#[derive(Copy, Clone, Debug)]
struct Player {
    pos: Vec3,
    radius: f32,
}

// 假设的 voxel solidity 查询
fn is_solid(v: IVec3) -> bool {
    // demo: y < 0 都是 solid(地板)
    v.y < 0
}

fn collide_and_unembed(player: &mut Player) {
    // broad phase: 球覆盖的 voxel
    let lo = (player.pos - Vec3::splat(player.radius)).floor().as_ivec3();
    let hi = (player.pos + Vec3::splat(player.radius)).floor().as_ivec3();

    for _iter in 0..4 { // 多轮迭代,防连环嵌入
        let mut any = false;
        for z in lo.z..=hi.z {
            for y in lo.y..=hi.y {
                for x in lo.x..=hi.x {
                    let v = IVec3::new(x, y, z);
                    if !is_solid(v) { continue; }
                    let v_min = v.as_vec3() - Vec3::splat(0.5);
                    let v_max = v.as_vec3() + Vec3::splat(0.5);
                    let closest = player.pos.clamp(v_min, v_max);
                    let d = player.pos - closest;
                    let dist_sq = d.length_squared();
                    if dist_sq < player.radius * player.radius && dist_sq > 1e-12 {
                        let dist = dist_sq.sqrt();
                        let push = d * (player.radius / dist - 1.0);
                        player.pos += push;
                        any = true;
                    }
                }
            }
        }
        if !any { break; }
    }
}

fn main() {
    let mut p = Player { pos: Vec3::new(0.0, -0.2, 0.0), radius: 0.4 };
    println!("Before: pos = {:?}", p.pos);
    collide_and_unembed(&mut p);
    println!("After:  pos = {:?}", p.pos);
    // 预期 y 从 -0.2 → ~0.0(球被推到地板上)
}
```

## 10 · 工程反思

Day 637 传达的核心工程教训:**碰撞形状的选择是"用户体验"决定,不是"物理正确"决定**。

新手工程师按"物理真实"选形状——人形角色用 OBB(矩形),球用球。但资深工程师按"手感"选形状——玩家在墙角要顺滑,所以人形角色用胶囊(球 + 圆柱)。

**为什么球比 AABB 手感好?**

AABB 有 8 个角,玩家撞角时法线只有 ±x / ±y / ±z 6 种,看起来"卡角"。球没有角,玩家撞墙时法线连续变化,看起来"滑过"。**视觉上玩家看到的不是几何形状,是"反馈平滑性"**。

工业教训:**碰撞形状 ≠ 视觉形状**。玩家碰撞体通常比视觉模型小一圈(避免"看起来撞了实际没撞"),形状选最简单(避免性能损失)。Unity / Unreal 默认用胶囊碰撞体,这是行业共识。

**第二条教训**:**简单形状优于复杂形状,如果简单够用**。Casey 用球不用胶囊,因为 HH 玩家形状简单。如果加复杂武器 / 装备,再切到胶囊。

过早用复杂形状是过度工程。Casey 反复强调:**先简单,够用就行,不够再升级**。

**第三条教训**:**球-AABB 距离是图形学基础**。这个算法不仅用于 collision,还用于:

- **Raymarching SDF**:球 SDF = `|p - c| - r`,AABB SDF = `length(max(abs(p-c) - h, 0))`
- **Particle collision**:GPU 粒子用球-AABB 批量检测
- **BVH 加速结构**:每个 BVH 节点是 AABB,球查询走 BVH

学懂球-AABB,你打开了 SDF / particle / BVH 等多个图形学话题的钥匙。Inigo Quilez 的 SDF 网站(iquilezles.org)是工业级 SDF 资源,推荐学习。

**迁移到其他领域**:

"选择最简单的够用方案"在所有工程领域通用:

- **数据库**:PostgreSQL 起步,够用就行,不要 MongoDB / Cassandra(over-engineered)
- **编程语言**:Python 写脚本,Rust 写系统,不要每个项目用 C++
- **构建工具**:Cargo / npm / pip,够用就行,不要 conan / vcpkg / bazel 复杂
- **游戏引擎**:Unity 起步,够用就行,不要自研引擎(除非 Casey Muratori)

每个领域都有"简单优先"的智慧。Casey 在 HH Day 637 演示的就是这种智慧。
