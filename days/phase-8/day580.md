
# Day 580 · 调查八面体插值

> 昨天修了边界 wrap bug,墙角闪烁消失。但 Casey 发现一个新问题:墙体光照在两帧之间有"轻微抖动"——不是闪烁,而是"颤抖",像低分辨率贴图被微移动。他知道这是八面体插值的精度问题,今天他要追根究底。

## 0 · 为什么要有这一天

八面体编码是一个**几何映射**——它把球面方向 `dir` 映射到 UV 平面 `(u, v)`。这个映射**不是线性的**——球面上等距的两个方向,在 UV 平面上不一定等距;反之亦然。

你在 UV 平面上做"双线性插值"(bl)时,假设的是"UV 空间里相邻的 4 个 texel 对应球面上也相邻"。这个假设在 UV 空间中心(对应球面北极)近似成立,但在 UV 空间边缘(对应球面赤道)严重失真——UV 平面上一对相邻 texel,可能对应球面上几乎相反的两个方向。

具体表现:玩家面朝南走,看到墙面光照"颤抖"。原因是玩家面朝方向的微小变化,经过 `encode_octahedral` 后,UV 坐标在贴图边界附近"剧烈跳动"——因为编码函数在边界附近斜率很大,方向的小变化导致 UV 的大变化,双线性采样的结果就不稳定。

**这个问题的本质**:八面体映射是连续的,但不是**等距的**(isometric)。等距意味着"球面距离 = UV 距离",但八面体做不到。失真最大的地方是"翻折线"附近——上下半球被翻折,UV 平面上"一墙之隔"对应球面"赤道对面"。

Casey 这一天不彻底解决这个问题(彻底解决需要重写编码方案),他要做的是:
1. **量化失真**:用代码测量"在不同 UV 区域,方向变化引起的 UV 变化有多大"
2. **找出最坏点**:找到失真最大的位置
3. **决定取舍**:是接受失真(用更高分辨率贴图抵消),还是改用其他编码

心理锚点:看完这集,你能用 Rust 画一张"八面体编码失真图",看到哪些区域失真最大,理解"为什么墙体光照会颤抖"。你能在自己写编码函数时**主动检测失真**,而不是等到玩家看到伪影才发现。

## 1 · Casey 今天做了什么

Casey 这一天做的:

1. **构建失真测试**:他在 UV 平面 `[0, 1]²` 上铺一个细网格(256×256),每个格点解码出方向 `dir = decode(u, v)`,然后给方向加一个微小扰动 `dir + ε`,重新编码 `encode(dir)`,看 UV 偏移了多少。
2. **可视化失真**:把失真量映射到颜色(蓝=小,红=大),画成 256×256 的热力图。
3. **分析结果**:热力图清楚地显示——UV 平面中心(对应球面北极)失真最小,UV 平面 4 条边和 4 个角失真最大。Casey 解释这个分布的原因:编码函数在边界附近做了"翻折",翻折是非线性变换,雅可比矩阵(Jacobian)在边界附近奇异。
4. **决定**:接受当前失真,通过提高贴图分辨率到 32×32 抵消(把"颤抖"的尺度降到亚像素)。

这一天的工程产出大约 50 行 Rust 代码,价值在于**把"我直觉觉得编码精度不均"变成"我有数据证明,失真在这 4 个角最大"**。

## 2 · 心智模型

### 类比:把橘子皮贴到方砖上

你把橘子皮(球面)贴到方砖(平面)上。橘子皮的赤道部分本来是个大圆,贴到方砖上后被切成 4 段,分别贴到方砖的 4 条边上。这 4 条边附近的橘子皮被"拉伸"——因为赤道的弧长被压缩到了直线上,几何变形最大。

而方砖中心(对应橘子皮的北极点)几乎没有拉伸——极点附近的橘子皮是个小圆,贴到方砖中心只是简单地"平铺"。

**失真分布**:中心小,边界大。这是所有"球面铺到平面"问题的共性——球面和平面不同胚,必然有失真,失真最严重的位置取决于具体编码方案。

### 严谨原理:雅可比矩阵与失真

**雅可比矩阵**(Jacobian matrix)是衡量"输入微小变化导致输出多少变化"的数学工具。对于编码函数 `f: dir → UV`,雅可比矩阵是:

```
J = | ∂u/∂dir_x   ∂u/∂dir_y   ∂u/∂dir_z |
    | ∂v/∂dir_x   ∂v/∂dir_y   ∂v/∂dir_z |
```

(2×3 矩阵,因为输入是 3D 方向,输出是 2D UV。)

雅可比矩阵的"范数"(norm)衡量"整体失真"。例如 Frobenius 范数:

```
||J||_F = sqrt(Σ J_ij²)
```

失真大意味着 ||J||_F 大。Casey 在代码里**数值计算** J(给 dir 加微小扰动,看 UV 变化):

```rust
fn measure_distortion(encode: impl Fn(Vec3) -> (f32, f32), dir: Vec3) -> f32 {
    let eps = 1e-4;
    let (u0, v0) = encode(dir);
    // 3 个方向上各扰动
    let mut total = 0.0;
    for axis in 0..3 {
        let mut dir_perturbed = dir;
        let delta = match axis {
            0 => Vec3 { x: eps, y: 0.0, z: 0.0 },
            1 => Vec3 { x: 0.0, y: eps, z: 0.0 },
            2 => Vec3 { x: 0.0, y: 0.0, z: eps },
            _ => unreachable!(),
        };
        dir_perturbed = (Vec3 {
            x: dir.x + delta.x,
            y: dir.y + delta.y,
            z: dir.z + delta.z,
        }).normalize();
        let (u1, v1) = encode(dir_perturbed);
        total += (u1 - u0).powi(2) + (v1 - v0).powi(2);
    }
    total.sqrt()
}
```

**每行解释**:
- `eps = 1e-4` — 数值微分的步长,通常 1e-4 到 1e-6 之间。太小浮点误差大,太大非线性误差大。
- 给方向加微小扰动后必须重新 `normalize()`(否则不再是单位向量,编码可能跑出八面体)。
- `(u1-u0)² + (v1-v0)²` — UV 平面上两点的距离平方。三个方向相加,得雅可比矩阵 Frobenius 范数平方的近似。

### 失真可视化

把 UV 平面铺成 256×256 网格,每个格点解码出方向,测失真:

```rust
fn visualize_distortion() -> Vec<f32> {
    let mut heatmap = vec![0.0; 256 * 256];
    for iy in 0..256 {
        for ix in 0..256 {
            let u = (ix as f32 / 255.0) * 2.0 - 1.0;  // [-1, 1]
            let v = (iy as f32 / 255.0) * 2.0 - 1.0;
            let dir = decode_octahedral(u, v);
            let d = measure_distortion(encode_octahedral, dir);
            heatmap[iy * 256 + ix] = d;
        }
    }
    heatmap
}
```

**结果**:
- 中心(u=0, v=0,对应北极)失真最小,~1.0
- 边缘(u 或 v 接近 ±1)失真大,~3-5
- 4 个角(u=v=±1)失真最大,~10+

 Casey 在视频里画出热力图,蓝(中心)到红(角落)的渐变非常清楚。

### 怎么减少失真

**方法 1:增加贴图分辨率**。失真意味着"方向的小变化引起 UV 大变化",意味着相邻方向被映射到相距较远的 texel。如果贴图分辨率高,texel 密,这种"相距较远"仍然是亚像素的,采样不会察觉。Casey 选 32×32 而不是 16×16,失真影响减半。

**方法 2:改进编码**。八面体编码不是唯一选择。例如 "Equal-Area Octahedral" 编码(由 Clarberg 等人 2020 提出)在保持双射的同时让"面积失真"为零,代价是编码解码公式更复杂。

**方法 3:自适应分辨率**。失真大的区域用更多 texel(类似 mipmap 思路,但反向——给角点更多 texel)。复杂,Casey 不做。

**方法 4:球面插值**。采样时不在 UV 空间做双线性,而是在球面上找最近 4 个 texel,在球面做插值。准确但贵 10 倍。

Casey 选方法 1——简单有效,32×32 在视觉上消除颤抖。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,"编码失真"是一个被广泛研究的问题。光照探针存储用 SH(球谐)就是因为它"频率分布均匀"——每个 SH 基函数在球面上覆盖的"频率"是均匀的,所以重建没有局部失真。但 SH 是"频率参数化",不是"方向参数化"——它不能存高频细节。

**主流方案的失真对比**:

| 方案 | 失真分布 | 高频能力 | 内存 |
|---|---|---|---|
| CubeMap | 均匀(6 张图各贡献 1/6) | 强 | 6× |
| 八面体编码 | 中心小,角大 | 强 | 1× |
| Equal-Area Octahedral | 均匀 | 强 | 1× |
| SH(L2) | 无(频率空间) | 弱(低频) | 9 个系数 |
| 等距矩形 | 极点退化 | 强(赤道附近) | 1× (2:1) |

游戏工业最新趋势是用 Equal-Area Octahedral(失真均匀),Casey 没切换是因为它在视频拍摄时(2017)还不普及。

### 3.2 · 🎨 图形学视角

球面参数化的失真由两个量衡量:

**面积失真**(Area distortion):球面上的一小块面积,映射到 UV 平面上变大或变小。
**角度失真**(Angle distortion / Conformal):球面上两正交方向,映射到 UV 平面上是否仍然正交。

完美无失真 = 等距(isometric),数学上不可能(球面和平面不同胚)。
等角(conformal)= 角度无失真,面积有失真。
等面积(equi-area / equal-area)= 面积无失真,角度有失真。

CubeMap、八面体编码都是**两者都有失真**,但都不算特别糟糕。Clarberg 的 Equal-Area Octahedral 是**等面积**,适合光照探针(光照积分是球面积分,等面积让积分权重均匀)。

**雅可比矩阵的奇异值分解**(SVD):两个奇异值 σ₁, σ₂ 对应"两个正交方向的拉伸率"。σ₁ = σ₂ 表示等角,σ₁σ₂ = 1 表示等面积。完美无失真需要 σ₁ = σ₂ = 1。

### 3.4 · 🦀 Rust 生态视角

Rust 表达"数值微分"很优雅,但有一个常被忽视的细节:** closures 和 Fn trait**。

```rust
// 错误版本:用函数指针,不能内联
fn measure_distortion(encode: fn(Vec3) -> (f32, f32), dir: Vec3) -> f32 { ... }

// 正确版本:用泛型 Fn,编译器能内联
fn measure_distortion<F: Fn(Vec3) -> (f32, f32)>(encode: F, dir: Vec3) -> f32 { ... }
```

差异:`fn` 指针是动态调用,每次调用都通过函数指针间接跳转,无法内联。泛型 `F: Fn` 在编译时单态化,`encode` 调用被内联到 measure_distortion 内部,性能差 2-5 倍。

Casey 在 Phase 8 大量用泛型 Fn,因为他的光照代码到处是"传入一个采样函数"的模式。

**Closure 捕获**:

```rust
let encode = |dir: Vec3| { /* closure body */ };
measure_distortion(encode, dir);
```

闭包捕获环境变量(如果有)用 `&` / `&mut` / `move`。这里 encode 不捕获任何变量,等价于函数。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么"UV 平面中心"对应"球面北极",而不是某个赤道方向?如果改成"UV 中心对应赤道",失真分布会怎么变?

**参考解答**:八面体编码的约定是:`encode((0, 0, 1)) = (0, 0)`,即北极映射到 UV 中心。这个约定来自编码公式:当 `z >= 0` 时,直接返回 `(x, y)`,而单位向量北极的 x, y 都是 0。这是 Engelhardt 论文里的原始约定。

如果改成"UV 中心对应赤道",编码公式要改:把 z 轴换成某个赤道方向作为"上"。失真分布会跟着旋转——失真最大的位置从 4 个角(对应"赤道对面"4 个方向)变到另一组 4 个方向。整体失真总量不变,只是分布"平移"。

### Lv2 · 动手实践

**题**:实现 `measure_distortion(encode, dir) -> f32` 和 `visualize_distortion() -> Vec<f32>`,生成 64×64 失真热力图。验证:
- 中心(0, 0, 1)的失真应该接近 1.0
- 4 个角的失真应该 > 5.0

**参考解答**:

```rust
fn measure_distortion<F: Fn(Vec3) -> (f32, f32)>(encode: F, dir: Vec3) -> f32 {
    let eps = 1e-3;
    let (u0, v0) = encode(dir);
    let mut total = 0.0f32;
    let perturbations = [
        Vec3 { x: eps, y: 0.0, z: 0.0 },
        Vec3 { x: 0.0, y: eps, z: 0.0 },
        Vec3 { x: 0.0, y: 0.0, z: eps },
    ];
    for p in &perturbations {
        let dir_p = Vec3 {
            x: dir.x + p.x,
            y: dir.y + p.y,
            z: dir.z + p.z,
        }.normalize();
        let (u1, v1) = encode(dir_p);
        total += (u1 - u0).powi(2) + (v1 - v0).powi(2);
    }
    total.sqrt()
}

fn main() {
    // 测几个特定方向的失真
    let test_dirs = [
        Vec3 { x: 0.0, y: 0.0, z: 1.0 },       // 北极(中心)
        Vec3 { x: 1.0, y: 0.0, z: 0.0 },       // +x 赤道
        Vec3 { x: 0.0, y: 0.0, z: -1.0 },      // 南极(角)
        Vec3 { x: 1.0, y: 1.0, z: -1.0 }.normalize(), // 对角(角附近)
    ];
    for dir in &test_dirs {
        let d = measure_distortion(encode_octahedral, dir.normalize());
        println!("dir={:?} distortion={:.3}", dir, d);
    }
}
```

**每行解释**:
- `eps = 1e-3` — 步长 1e-3,比 1e-4 更稳健(浮点精度更高)。
- `total += (u1-u0)² + (v1-v0)²` — 累加 3 个方向的"输出位移平方"。
- `total.sqrt()` — Frobenius 范数近似。

预期输出:中心失真 ~1.0,角附近失真 ~3-5。

```rust
            let v = (iy as f32 / (size - 1) as f32) * 2.0 - 1.0;
            let dir = decode_octahedral(u, v);
            let d = measure_distortion(encode_octahedral, dir);
            heatmap[iy * size + ix] = d;
            if d > max_d { max_d = d; }
        }
    }
    println!("Max distortion: {}", max_d);
    println!("Center distortion: {}", heatmap[(size/2) * size + (size/2)]);

    // 写 PPM 热力图
    use std::io::Write;
    let mut f = std::fs::File::create("/tmp/distortion.ppm").unwrap();
    writeln!(f, "P3\n{} {}\n255", size, size).unwrap();
    for &d in &heatmap {
        // 失真映射到颜色:0 = 蓝,max_d = 红
        let t = (d / max_d).clamp(0.0, 1.0);
        let r = (t * 255.0) as u8;
        let b = ((1.0 - t) * 255.0) as u8;
        writeln!(f, "{} 0 {}", r, b).unwrap();
    }
    println!("Saved /tmp/distortion.ppm");
}
```

### A.2 Voxel lighting 的核心问题

工业级 voxel lighting 解决以下核心问题:

**1. 计算量**:
- 大场景(几百万 voxel)
- 每 voxel 要算多方向光
- 每方向要 raycast(检查遮挡)

**2. 实时性**:
- 玩家编辑 voxel(挖 / 放)
- 光照要立即更新
- 16.67 ms 帧预算

**3. 内存**:
- 每 voxel 存光照值(RGB 或 SH)
- 大场景内存爆炸
- 需要 streaming

**4. 准确性**:
- 直接光(sun)
- 间接光(bounce)
- 阴影(soft / hard)
- 反射(diffuse / specular)

工业方案在这些问题之间权衡。Casey 的 HH 教基础权衡。

### A.3 性能优化的具体技术

**Spatial partitioning**:
- Grid:固定大小 voxel,直接索引
- Octree:稀疏,只存有内容的节点
- BVH:bounding volume hierarchy,GPU 友好
- k-d tree:递归 axis-aligned split

**Temporal coherence**:
- 帧间复用(上一帧光照 + 增量)
- TAA(temporal anti-aliasing)
- 时序累积(低噪点)

**Level of detail**:
- 远处 voxel 粗采样
- 近处 voxel 精细
- mipmap voxel atlas

**GPU compute**:
- Vulkan / DX12 / Metal compute shader
- 自定义 ray tracing shader
- RTX 核心加速

### A.8 Voxel lighting 算法的具体实现细节

让我深入讲讲 voxel lighting 算法的实现细节:

**Direct lighting**(直接光):

```rust
fn compute_direct_lighting(
    world: &World,
    sun_dir: Vec3,
    sun_color: RGB,
) -> LightAtlas {
    let mut atlas = LightAtlas::new(world.width, world.height, world.depth);
    
    for z in 0..world.depth {
        for y in 0..world.height {
            for x in 0..world.width {
                if world.get(x, y, z).is_air() { continue; }
                
                // 检查是否被遮挡(从 voxel 到 sun 方向)
                let voxel_pos = Vec3::new(x as f32 + 0.5, y as f32 + 0.5, z as f32 + 0.5);
                let ray = Ray::new(voxel_pos, sun_dir);
                let occluded = grid_dda(world, ray, 100.0).is_some();
                
                if !occluded {
                    // 计算法线(根据邻居)
                    let normal = compute_normal(world, x, y, z);
                    let lambert = normal.dot(sun_dir).max(0.0);
                    let light = sun_color * lambert;
                    atlas.set(x, y, z, light);
                }
            }
        }
    }
    
    atlas
}
```

**Indirect lighting**(间接光 / bounce):

```rust
fn compute_indirect_lighting(
    world: &World,
    direct: &LightAtlas,
    bounces: usize,
) -> LightAtlas {
    let mut current = direct.clone();
    
    for _ in 0..bounces {
        let mut next = current.clone();
        
        for z in 0..world.depth {
            for y in 0..world.height {
                for x in 0..world.width {
                    if world.get(x, y, z).is_air() { continue; }
                    
                    // 累加 6 邻居的光(简化 diffuse)
                    let mut accumulated = RGB::black();
                    for (dx, dy, dz) in NEIGHBORS_6 {
                        let nx = x as i32 + dx;
                        let ny = y as i32 + dy;
                        let nz = z as i32 + dz;
                        if nx >= 0 && ny >= 0 && nz >= 0 {
                            let n_light = current.get(nx as u32, ny as u32, nz as u32);
                            accumulated += n_light * 0.15;  // bounce factor
                        }
                    }
                    
                    let cur = current.get(x, y, z);
                    next.set(x, y, z, cur + accumulated);
                }
            }
        }
        
        current = next;
    }
    
    current
}
```

### A.9 Voxel 法线计算

Voxel 表面法线计算:

```rust
fn compute_normal(world: &World, x: u32, y: u32, z: u32) -> Vec3 {
    // Sobel filter 算法线(类似图像边缘检测)
    let mut sx = 0.0; let mut sy = 0.0; let mut sz = 0.0;
    
    for dz in -1i32..=1 {
        for dy in -1i32..=1 {
            for dx in -1i32..=1 {
                let nx = x as i32 + dx;
                let ny = y as i32 + dy;
                let nz = z as i32 + dz;
                let density = if in_bounds(world, nx, ny, nz) && world.get(nx, ny, nz).is_solid() {
                    1.0
                } else { 0.0 };
                sx += dx as f32 * density;
                sy += dy as f32 * density;
                sz += dz as f32 * density;
            }
        }
    }
    
    Vec3::new(sx, sy, sz).normalize()
}
```

法线用于 Lambert / Phong 光照计算。
