### 物理直觉:为什么角落暗

想象你站在房间的正中央。你抬头看天花板,四周看墙——大部分方向都是"开放空间",能看到天花板和墙。光从这些方向反射过来,照亮你。

现在你蹲在房间角落(墙与地板接缝)。你看天花板——墙挡住了你"上方一侧"的视线。你侧看——地板和墙都挡住你一半方向。**你的半球视野里有很大一部分被遮挡**,所以接收的间接光少 30-50%,角落自然暗。

这是 **geometry-driven 的光照现象**,不是数值 bug。它的物理名称是 **ambient occlusion**——环境光被几何"遮蔽"。

**今天的核心概念**:**Ambient Occlusion**(环境光遮蔽,AO)。这是图形学的一个重要现象,从 1990s 开始被游戏工业广泛应用。

**心理锚点**:看完这集,你能:
- 区分"角落变暗"(物理)和"数值 bug"
- 解释 AO 的几何原理
- 知道何时该"修",何时该"留着"

## 2 · 心智模型

### 类比:你的衣柜里的角落

打开你的衣柜,你站在中间,灯光(外面的灯)从衣柜门照进来。你周围的衣物反射光,你能看清。

现在你蹲到衣柜的角落。你看到的:

- 头顶:衣柜顶板,挡住一半视野
- 一侧:衣柜侧板,挡住另一侧
- 另一侧:另一面侧板,又挡住
- 你只剩下方一小块"看向衣柜门"的视野

光只能从这一小块视野进来,所以**角落明显比中央暗**。

这是物理,不是衣柜坏了。游戏世界的角落完全一样——**几何遮挡减少了间接光,角落必然暗**。

### 严谨推导:Ambient Occlusion 数学

#### 2.1 Ambient Occlusion 定义

某点 P 的 ambient occlusion:

```
AO(P) = (1 / π) × ∫_Ω visibility(P, ω) × cos(θ_ω) dω
```

- `Ω` — P 的上半球
- `visibility(P, ω)` — P 沿 ω 方向是否可见天空(1 = 可见,0 = 遮挡)
- `cos(θ_ω)` — N · ω,方向投影
- `1/π` — 归一化

AO 取值 0 到 1:

- `AO = 1`:上半球完全开放(平面中央),全亮
- `AO = 0`:上半球完全遮挡(洞里),全暗

角落的 AO 约 0.5(半球被遮挡一半)。

#### 2.2 间接光计算

```
L_indirect(P) = albedo × AO(P) × L_ambient
```

- `albedo` — P 的反射率
- `AO(P)` — 遮蔽因子
- `L_ambient` — 环境光强度(假设全方向均匀)

角落 AO = 0.5,所以间接光是中央的 50%——这正是测试者看到的"角落变暗"。

#### 2.3 现代引擎的 AO

工业界 AO 算法:

1. **SSAO**(Screen Space AO, Crytek 2007):屏幕空间,基于 depth buffer
2. **HBAO**(Horizon-Based AO, NVIDIA 2008):改进 SSAO,更准
3. **VXAO**(Voxel AO, NVIDIA):体素化,更准但慢
4. **Ray Traced AO**(DXR / RTX):光追投射多条光线,最准

HH 的 diffuse GI 自然产生 AO(本日现象),不需要专门算法。

#### 2.4 AO vs 直接光阴影

- **直接光阴影**:点光源 + 几何遮挡,锐利边缘
- **AO**:半球环境光 + 几何遮挡,柔和的角落变暗

两者都是"几何遮挡导致暗",但直接光是**单一方向**被遮挡(锐利),AO 是**多方向平均**被遮挡(柔和)。

### 2.6 是 feature 不是 bug

Casey 得出结论:

1. **物理正确**:角落变暗是 geometry-driven 的必然结果
2. **视觉上重要**:AO 提供深度感,让场景"立体"
3. **不是数值 bug**:不是浮点误差、不是 raycast 失败、不是 tag 错
4. **不该"修"**:如果"修"成角落和中央一样亮,反而**违反物理**,看起来"假"

**正确做法**:**留着**。如果测试者坚持,提供"AO 强度"参数,允许美术微调(但默认 1.0)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

AO 是现代游戏的核心技术:

- **Crysis(2007)**:第一个用 SSAO 的游戏,革命性视觉提升
- **Battlefield 3**:用 HBAO,角色在墙边的遮挡明显
- **The Last of Us**:用 VXAO,高质量角落遮蔽
- **Control**:用 Ray Traced AO,极致真实

**为什么重要**:

1. **深度感**:AO 让场景"立体",2D 平面有 3D 感
2. **细节感**:小裂纹、接缝的遮蔽让物体"真"
3. **艺术感**:暗角落聚焦视线,引导玩家

**坑**:

- **过强 AO**:角落太暗,玩家看不见,影响玩法
- **过弱 AO**:场景扁平,没深度
- **SSAO 噪声**:屏幕空间算法有 noise,需要 temporal filter

### 3.2 · 🎨 图形学视角

AO 的工业算法演进:

| 算法 | 年代 | 思路 | 优缺点 |
|---|---|---|---|
| Ray traced AO | 1980s | 投射多条光线 | 最准,但慢 |
| SSAO | 2007 | 屏幕空间采样 | 快,但有 noise 和 edge artifacts |
| HBAO | 2008 | 改进 SSAO | 更准,但仍屏幕空间 |
| VXAO | 2014 | 体素化 | 准,但慢 |
| RTAO | 2018 | DXR 硬件光追 | 准,需要 RTX |

**核心物理都是 AO 定义**(上半球积分),区别在**如何高效近似**。

### 3.4 · 🦀 Rust 生态视角

Rust 的 AO 实现:

```rust
fn compute_ao(world: &World, p: Vec3, n: Vec3, samples: usize) -> f32 {
    let mut visible = 0;
    for i in 0..samples {
        let dir = sample_hemisphere_cos(n, i as f32 / samples as f32);
        if world.raycast(p + n * 0.001, dir, 10.0).is_none() {
            visible += 1;
        }
    }
    visible as f32 / samples as f32
}

fn sample_hemisphere_cos(n: Vec3, u: f32) -> Vec3 {
    // cos-weighted hemisphere sampling
    let phi = u * 2.0 * std::f32::consts::PI;
    let theta = (1.0 - u).sqrt().acos();
    let local = Vec3::new(
        theta.sin() * phi.cos(),
        theta.cos(),
        theta.sin() * phi.sin(),
    );
    tangent_to_world(local, n)
}
```

`tangent_to_world` 把局部坐标转到世界(用 N 作 up 构造 tangent space)。这是 cos-weighted sampling,概率密度与 `cos(θ)` 成正比,积分时不用额外乘 `cos`。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么房间角落必然比中央暗?给出基于 AO 公式的论证。

**参考解答**:

AO 定义:`AO(P) = (1/π) ∫ visibility(P, ω) cos(θ) dω`

角落 P 的半球有一部分被墙 / 地板遮挡,所以 `visibility(P, ω)` 在某些方向为 0,积分减少。

具体:房间角落(墙-地板接缝),墙和地板各挡住半球的 ~1/4,所以 AO ≈ 1 - 0.25 - 0.25 = 0.5。

间接光 `L_indirect = albedo × AO × L_ambient`,角落 = 中央的 50%。

### Lv2 · 动手实践

**题**:实现一个简单的 2D AO 计算器。要求:
- 2D 网格世界

**参考解答**:

```rust
#[derive(Copy, Clone)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn length(self) -> f32 { (self.x*self.x + self.y*self.y).sqrt() }
    fn normalized(self) -> Self {
        let l = self.length();
        if l > 1e-9 { Self::new(self.x/l, self.y/l) } else { Self::new(0.0, 0.0) }
    }
}

struct World2D {
    walls: Vec<(Vec2, Vec2)>,  // 墙的线段(a, b)
}

impl World2D {
    fn segment_blocks(&self, p: Vec2, dir: Vec2, max_dist: f32) -> bool {
        for &(a, b) in &self.walls {
            if ray_segment_intersect(p, dir, a, b, max_dist) {
                return true;
            }
        }
        false
    }
    fn ao_2d(&self, p: Vec2, up: Vec2, samples: usize) -> f32 {
        let mut visible = 0;
        for i in 0..samples {
            let theta = std::f32::consts::FRAC_PI_2 * (i as f32 + 0.5) / samples as f32;
            // 半圆方向(theta 从 0 到 π/2,扫半圆)
            let angle = theta - std::f32::consts::FRAC_PI_2;  // -π/2 到 π/2
            let dir = Vec2::new(
                up.x * angle.cos() - up.y * angle.sin(),
                up.x * angle.sin() + up.y * angle.cos(),
            );
            if !self.segment_blocks(p, dir, 5.0) {
                visible += 1;
            }
        }
        visible as f32 / samples as f32
    }
}

fn ray_segment_intersect(ro: Vec2, rd: Vec2, a: Vec2, b: Vec2, max_t: f32) -> bool {
    let v1 = (b.x - a.x) * (ro.y - a.y) - (b.y - a.y) * (ro.x - a.x);
    let v2 = (b.x - a.x) * rd.y - (b.y - a.y) * rd.x;
    let v3 = rd.x * (ro.y - a.y) - rd.y * (ro.x - a.x);
    let v4 = (b.x - a.x) * rd.y - (b.y - a.y) * rd.x;
    if v4.abs() < 1e-9 { return false; }
    let t = v1 / v2;
    let s = v3 / v4;
    t >= 0.0 && t <= max_t && s >= 0.0 && s <= 1.0
}

fn main() {
    // 房间:四面墙
    let world = World2D {
        walls: vec![
            (Vec2::new(0.0, 0.0), Vec2::new(10.0, 0.0)),  // 下墙
            (Vec2::new(0.0, 0.0), Vec2::new(0.0, 10.0)),  // 左墙
            (Vec2::new(10.0, 0.0), Vec2::new(10.0, 10.0)),  // 右墙
            (Vec2::new(0.0, 10.0), Vec2::new(10.0, 10.0)),  // 上墙
        ]
    };

    let up = Vec2::new(0.0, 1.0);

    // 中央
    let center_ao = world.ao_2d(Vec2::new(5.0, 0.5), up, 64);
    println!("Center AO: {:.2}", center_ao);  // ~1.0

    // 角落
    let corner_ao = world.ao_2d(Vec2::new(0.5, 0.5), up, 64);
    println!("Corner AO: {:.2}", corner_ao);  // ~0.5
}
```

## 8 · Rust / Arch 落地代码

### 完整 3D AO 计算器

```rust
// Cargo.toml: 空

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn add(self, o: Self) -> Self { Self::new(self.x+o.x, self.y+o.y, self.z+o.z) }
    fn sub(self, o: Self) -> Self { Self::new(self.x-o.x, self.y-o.y, self.z-o.z) }
    fn scale(self, k: f32) -> Self { Self::new(self.x*k, self.y*k, self.z*k) }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
    fn length(self) -> f32 { self.dot(self).sqrt() }
    fn normalized(self) -> Self {
        let l = self.length();
        if l > 1e-9 { self.scale(1.0/l) } else { Self::new(0.0, 0.0, 0.0) }
    }
    fn cross(self, o: Self) -> Self {
        Self::new(
            self.y*o.z - self.z*o.y,
            self.z*o.x - self.x*o.z,
            self.x*o.y - self.y*o.x,
        )
    }
}

// 简化世界:用 box(盒子)代表墙
struct World {
    boxes: Vec<(Vec3, Vec3)>,  // (min, max)
}

impl World {
    fn ray_hits_box(&self, ro: Vec3, rd: Vec3, max_t: f32) -> bool {
        for &(min, max) in &self.boxes {
            if ray_box_intersect(ro, rd, min, max, max_t) {
                return true;
            }
        }
        false
    }
    fn ao(&self, p: Vec3, n: Vec3, samples: usize) -> f32 {
        let mut visible = 0;
        let up_tangent = if n.y.abs() < 0.99 {
            Vec3::new(0.0, 1.0, 0.0)
        } else {
            Vec3::new(1.0, 0.0, 0.0)
        };
        let t1 = n.cross(up_tangent).normalized();
        let t2 = n.cross(t1).normalized();

        for i in 0..samples {
            // Halton sequence for low-discrepancy
            let u = halton(i as u32 + 1, 2);
            let v = halton(i as u32 + 1, 3);
            // cos-weighted hemisphere
            let r = u.sqrt();
            let phi = 2.0 * std::f32::consts::PI * v;
            let local = Vec3::new(r * phi.cos(), r * phi.sin(), (1.0 - u).sqrt());
            // tangent -> world
            let dir = t1.scale(local.x).add(t2.scale(local.y)).add(n.scale(local.z)).normalized();

            // 微微偏移避免自相交
            let p_offset = p.add(n.scale(0.001));

            if !self.ray_hits_box(p_offset, dir, 5.0) {
                visible += 1;
            }
        }
        visible as f32 / samples as f32
    }
}

fn halton(index: u32, base: u32) -> f32 {
    let mut f = 1.0;
    let mut r = 0.0;
    let mut i = index;
    while i > 0 {
        f /= base as f32;
        r += f * (i % base) as f32;
        i /= base;
    }
    r
}

fn ray_box_intersect(ro: Vec3, rd: Vec3, min: Vec3, max: Vec3, max_t: f32) -> bool {
    let mut tmin = f32::MIN;
    let mut tmax = f32::MAX;
    for axis in 0..3 {
        let ro_a = [ro.x, ro.y, ro.z][axis];
        let rd_a = [rd.x, rd.y, rd.z][axis];
        let min_a = [min.x, min.y, min.z][axis];
        let max_a = [max.x, max.y, max.z][axis];

        if rd_a.abs() < 1e-9 {
            if ro_a < min_a || ro_a > max_a { return false; }
        } else {
            let t1 = (min_a - ro_a) / rd_a;
            let t2 = (max_a - ro_a) / rd_a;
            let (t1, t2) = if t1 < t2 { (t1, t2) } else { (t2, t1) };
            tmin = tmin.max(t1);
            tmax = tmax.min(t2);
            if tmin > tmax { return false; }
        }
    }
    tmin >= 0.0 && tmin <= max_t
}

fn main() {
    // 房间:四面墙 + 地板(用 box 表示)
    let world = World {
        boxes: vec![
            // 地板
            (Vec3::new(-10.0, -1.0, -10.0), Vec3::new(10.0, 0.0, 10.0)),
            // 左墙
            (Vec3::new(-1.0, 0.0, -10.0), Vec3::new(0.0, 10.0, 10.0)),
            // 后墙
            (Vec3::new(-10.0, 0.0, -1.0), Vec3::new(10.0, 10.0, 0.0)),
        ]
    };

    let n_up = Vec3::new(0.0, 1.0, 0.0);

    let center = Vec3::new(5.0, 0.001, 5.0);
    let corner = Vec3::new(0.001, 0.001, 0.001);

    let center_ao = world.ao(center, n_up, 128);
    let corner_ao = world.ao(corner, n_up, 128);

    println!("Center AO: {:.3}", center_ao);
    println!("Corner AO: {:.3}", corner_ao);
    println!("Corner darkening: {:.1}%", (1.0 - corner_ao / center_ao) * 100.0);
}
```

## 附录 · "Feature Not Bug" 决策树

Day 623 的核心是**决策**:看到"奇怪现象",如何系统化判断是 feature 还是 bug。

### 决策树

```
现象:看起来不对
│
├── 1. 能用理论解释吗?
│   ├── 是 → feature,跳到 4
│   └── 否 → 跳到 2
│
├── 2. 测量是否符合预期?
│   ├── 实测 = 理论 → feature
│   ├── 实测 ≠ 理论(< 10%)→ feature(数值误差)
│   └── 实测 ≠ 理论(> 50%)→ bug,跳到 3
│
├── 3. 调查 bug 根因
│   ├── 浮点精度 → 可能 feature,可能 bug
│   ├── 算法错误 → bug,修
│   ├── 数据错误 → bug,修
│   └── 标签 / 命名 → bug(类似 day622),修
│
└── 4. 是 feature,但用户接受吗?
    ├── 接受 → 留着
    └── 不接受 → 加参数让用户调整,但默认保持物理正确
```

### Day 623 的决策

应用决策树到"角落变暗":

1. **理论解释**:角落的半球被遮挡,接收到更少间接光 → 物理必然
2. **实测**:`debug_visualize_ao` 返回角落 0.5,中央 1.0,符合理论
3. **结论**:feature
4. **用户接受**:测试者反馈"看起来像 bug",但 Casey 坚持物理正确
5. **可选**:加"AO 强度"参数,默认 1.0,允许美术调暗

### 历史上的"假 bug"案例

游戏行业大量"以为是 bug 其实是 feature":

1. **Doom 3 的"塑料感"**:玩家觉得太反光,以为是 shader bug。实际是 Blinn-Phong + 不正确 fresnel。改 PBR 后消失(从 feature 到 fix)
2. **Minecraft 的"条纹幻觉"**:玩家看到远处有条纹,以为是渲染 bug。实际是 Moiré pattern(采样定理)。加 mip mapping 后减弱
3. **Crysis 的"角落变暗"**:SSAO 引入,玩家觉得角落"太黑"。Crytek 加"AO 强度"参数
4. **GTA 5 的"色彩失真"**:玩家觉得某些场景颜色怪。实际是色调映射(tone mapping)的结果,美术 intentional

每个案例都经过了"以为是 bug → 调查 → 确认 feature"的过程。** Casey 在 Day 623 做的就是这个过程的简化版**。

### 何时"修 feature"

虽然 Day 623 是"留着 feature",但有时候 feature 应该被修:

1. **违背直觉**:玩家普遍反馈"不自然"
2. **影响玩法**:角落太暗,玩家看不见敌人
3. **艺术需求**:美术想要"卡通渲染",不要"真实物理"

**修法**:

- **加参数**:让美术调节(推荐)
- **替换算法**:从物理准确换到风格化
- **post-process**:加亮度补偿

### 工程师的判断力

完成 Day 623,你应该建立这样的判断力:

- **看到现象,先问"是 feature 吗?"**
- **能用理论解释 → 大概率 feature**
- **修 feature 之前先验证测试者反馈**
- **保留物理正确 + 加调节参数**

**这是工程师 vs 码农的核心区别**。码农看到现象就改,工程师先理解。

## 附录 II · AO 工业实现深度对比

Day 623 用了最朴素的 AO 计算(ray casting 多条光线)。工业级实现有几种:

### 1. SSAO(Screen Space Ambient Occlusion)

Crytek 2007 提出,革命性算法。

**思路**:

- 在屏幕空间操作,每个像素一个 AO 值
- 取该像素周围的 depth buffer 采样
- 算"周围 depth 比当前高"的样本数,作为 AO

**优点**:快(GPU shader),易实现。

**缺点**:

- **屏幕空间**:只能用屏幕上看得到的几何,角色背后/物体背面无 AO
- **edge artifacts**:屏幕边缘奇怪
- **noise**:需要 temporal filter

**Rust 伪代码**:

```glsl
// fragment shader
float depth_p = texture(depth_buffer, uv).r;
vec3 pos_p = reconstruct_position(uv, depth_p);
vec3 normal_p = reconstruct_normal(pos_p);

float occlusion = 0.0;
for (int i = 0; i < KERNEL_SIZE; i++) {
    vec3 sample_dir = kernel[i];  // 半球采样
    vec3 sample_pos = pos_p + sample_dir * RADIUS;
    vec2 sample_uv = project_to_screen(sample_pos);
    float depth_sample = texture(depth_buffer, sample_uv).r;
    if (depth_sample < sample_pos.z - BIAS) {
        occlusion += smoothstep(0.0, 1.0, RADIUS / length(sample_pos - pos_p));
    }
}
float ao = 1.0 - occlusion / KERNEL_SIZE;
```

### 2. HBAO(Horizon-Based AO)

NVIDIA 2008 改进 SSAO。

**思路**:

- 不用随机采样,用"地平线"角度
- 在每个方向找最高的 depth,算 angle
- AO = 平均 horizon angle

**优点**:更准,无 random noise。

**缺点**:计算更复杂。

### 3. VXAO(Voxel AO)

NVIDIA 2014。

**思路**:

- 把场景体素化(类似 HH)
- 在体素空间做 cone tracing
- 每个 cone 算一次遮挡

**优点**:质量极高,无屏幕空间 artifacts。

**缺点**:慢,需要 GPU compute shader。

### 4. RTAO(Ray Traced AO)

DXR 2018+。

**思路**:

- 用 RTX 硬件投射多条光线
- 直接物理计算 AO

**优点**:完全准确,无 artifacts。

**缺点**:需要 RTX 显卡,~5ms/frame。

### HH 的位置

Casey 的实现 = "穷人版 VXAO + Diffuse GI":

- 用 voxel grid(已有)
- 用 ray casting(已有)
- 半球积分自然产生 AO

没有专门 AO shader,但 diffuse GI 自然给 AO。**这是 "free AO"**——本质是 GI 算法的副产品。

### 何时升级 AO

如果 HH 想要"更明显"的 AO(类似 AAA 游戏):

1. **加 SSAO post-process**:在 diffuse GI 之上加屏幕空间 AO
2. **加专门 voxel AO pass**:用更高分辨率 voxel 算 AO
3. **加 RTAO**:用 RTX 硬件

每种升级都是工程权衡。Casey 选最简单的——**保留 diffuse GI 自然 AO**,因为已经够好。

- **HH 的"自然 AO"是 diffuse GI 的副产品**,免费但有效
