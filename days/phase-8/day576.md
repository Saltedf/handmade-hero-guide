# Day 576 · 八面体编码

> Phase 7 的末尾光照系统已经能产生无限弹射的全局光照,但代价巨大:每个体素需要存一个完整的环境光立方体贴图(CubeMap),也就是 6 张图。Casey 在 Phase 8 第一天就要把这个 6× 的内存账单砍成 1×——他选了"八面体编码"。

## 0 · 为什么要有这一天

假设你正在做 Handmade Hero 的全局光照(Global Illumination,简称 GI)。你在游戏世界每个一立方米的小格子里都放一个"虚拟探头",记录"从这一格往四面八方看,光强分别是多少"。这套数据叫**辐射场**(Irradiance Field)。玩家走到一格,从格子拿出"往他眼睛那个方向"的光强,就能让屏幕上对应像素亮起来。

最直觉的实现是"立方体贴图":想象你在格子中心放一台相机,分别往 +x、-x、+y、-y、+z、-z 六个方向各拍一张 16×16 的图。**好处**是 GPU 友好——所有引擎都内置 `samplerCube`,一行 shader 代码 `textureCube(map, dir)` 就能采样。**坏处**是吃内存:每格 6 张图,假设你世界有 1000 个体素,每张图 16×16×4 字节,总量是 `6 × 16 × 16 × 4 × 1000 = 6 MB`。看似不多,可你要做的是"实时无限弹射 GI",每帧都要更新所有格子的图。带宽爆了。

**问题变成了**:能不能把"3D 方向"(也就是单位向量 `(x,y,z), x²+y²+z²=1`)无损地映射到"2D 平面"(也就是 `(u,v), 0≤u,v≤1`)上,这样每个格子只需要存一张 16×16 的图?

直觉上不行:3D 球面是 2D 平面,中间差一个维度,数学上不可能有完美的一一映射(拓扑学定理:球面和平面不同胚)。但是工程上,我们**不需要数学完美**——只需要"近似无损",并且"插值时不要出现奇怪的缝隙"。八面体编码(Octahedral Encoding)就是这套工程折中里最优雅的一个。Casey 在 Day 576 把它从论文搬到代码里。

心理锚点:看完这一集,你能用 30 秒解释"为什么球面铺到平面一定有失真,但八面体编码是工程上够好的近似",能用一张草图说明编码解码的几何直觉,能读懂 Rust 实现里每个 if 分支在干什么。如果做不到,先停在 §2 把心智模型啃下来。

## 1 · Casey 今天做了什么

Casey 在这一天的开场先承认了一个事实:Phase 7 末尾他用的"球谐函数"存储间接光虽然紧凑,但在某些方向上**视觉精度不够**,墙角的"高亮小光斑"会被涂糊。他需要换一种数据结构,既要存所有方向的光强,又要省内存。

他做了三件事:

1. **找论文**:他翻出 2010 年 SIGGRAPH 上 Engelhardt 和 Dachsbacher 的论文《Octahedral Normal Vectors》,这篇 5 页的短文把单位球面"剥皮成八面体"再压平到正方形,编码 + 解码各几行 shader 代码。
2. **白板推导**:他在白板上画了一个八面体(想象两座金字塔底面粘在一起,上下各 4 个三角形面)。然后把八面体的 8 个三角形面"摊平"成一个正方形——上面 4 个三角形组成正方形的上半,下面 4 个组成下半。整个过程就像把橘子皮剥下来贴到方砖上。
3. **写 Rust 实现**:他写了 `encode_octahedral(dir: Vec3) -> Vec2` 和 `decode_octahedral(uv: Vec2) -> Vec3` 两个函数。每个函数都用最朴素的 if-else 分支处理"上半球 vs 下半球",不追求优雅,追求"代码看一眼就知道在干什么"。

Casey 今天的工程产出是大约 30 行 Rust 代码,但教学价值极高:**他展示了"把数学论文变成可跑代码"的完整流程**——这是黑客的核心能力,在学校里几乎没人教。

## 2 · 心智模型

### 类比:橘子皮与方砖

想象你拿着一个橘子,想把它整个皮完整地贴到一块方砖上,皮不能重叠、不能有缝。这件事在物理上做不到——球面的几何性质不允许它完美贴到平面。

但有个"作弊"办法:把橘子皮切成 8 等份(每份一个等腰三角形),然后把 8 个三角形重新拼接,贴到方砖上。具体怎么拼?先把橘子沿"赤道"切一刀,得到上半球和下半球,每半各 4 个三角形。然后:

- 把上半球的 4 个三角形"花瓣"展开,让它们的尖朝外,组成一个**菱形**(正方形旋转 45°)
- 把下半球的 4 个三角形"花瓣"同样展开,组成另一个菱形
- 把两个菱形重叠——这就是我们要的"方砖上每个点对应球面一个方向"的映射

但 Casey 不是这么做的。Engelhardt 的方案更简洁:把"下半球"的 4 个三角形**翻折**到上半球菱形的外侧,得到一个完整的正方形。下半球的方向被映射到正方形的"四个角"附近,上半球的方向映射到"中心十字"附近。

**这就是八面体编码的核心**:它不是把球面铺到平面,而是**把球面先变成八面体**(8 个三角形),**再把这 8 个三角形拼成一个正方形**。两次"近似":球→八面体(几何细节有损,但我们存的是光强,不是形状,所以损失看不见),八面体→正方形(数学上一一对应,无失真)。

### 严谨原理:从向量到 UV

设我们有一个单位向量 `n = (x, y, z)`,即 `x² + y² + z² = 1`。我们要把它编码成 `(u, v) ∈ [-1, 1]²`(后面再线性变换到 `[0, 1]²` 用于贴图坐标)。

**第一步:投影到八面体**。先把 n 的三个分量取绝对值,找到最大的:`l1 = |x| + |y| + |z|`(对单位向量,这个值介于 1 和 √3 之间)。然后归一化:

```
(x', y', z') = (x, y, z) / l1
```

这一步把球面上的点投影到八面体表面(因为 `|x'| + |y'| + |z'| = 1` 正是八面体的方程)。

**第二步:八面体展开到平面**。这里要分两种情况:

**情况 A:n 在上半球(`z' ≥ 0`)**。直接扔掉 z',保留 (x', y')。八面体的上半部分(4 个三角形)投影到 xy 平面正好是一个正方形(顶点在 `(±1, ±1)`)。所以:

```
(u, v) = (x', y')
```

**情况 B:n 在下半球(`z' < 0`)**。如果直接扔掉 z',下半球会"盖到"上半球上(同一个 (x', y') 对应两个 z,一正一负)。Engelhardt 的天才想法:把下半球的 4 个三角形**翻折**到正方形外圈。

具体公式(几何上等价于"绕正方形中心做一次反射"):

```
设 a = x', b = y'
u = (1 - |a|) * sign(b) ... 
```

不对,正确的翻折公式稍微绕。我们重新写:

```
// 情况 B:下半球
// 把 (|x'|, |y'|) 看作"哪个三角形被翻折"的索引
// 然后用 1 - |坐标| 把方向"翻到外圈"
u = 1 - |y'|  (若 x' ≥ 0)   或   u = -(1 - |y'|)   (若 x' < 0)
v = 1 - |x'|  (若 y' ≥ 0)   或   v = -(1 - |x'|)   (若 y' < 0)
```

更简洁的等价写法(节省分支):

```
// 先取绝对值
ax = |x'|, ay = |y'|
// 翻折:每个轴上"从 1 减去另一轴的绝对值",保留符号
if (x' >= 0) { u = 1 - ay } else { u = -(1 - ay) }
if (y' >= 0) { v = 1 - ax } else { v = -(1 - ax) }
```

验证几个边界点:
- `n = (0, 0, 1)`(北极)→ `z' = 1, x' = y' = 0` → 情况 A → `(u, v) = (0, 0)`,即正方形中心。✓
- `n = (0, 0, -1)`(南极)→ 经过归一化,`z' = -1, x' = y' = 0` → 情况 B → `(u, v) = (1, 1)`(或正负组合,Casey 实现里取约定)→ 正方形某个角。✓
- `n = (1, 0, 0)`(赤道 +x)→ `l1 = 1`, `(x', y', z') = (1, 0, 0)`,情况 A → `(u, v) = (1, 0)`,正方形右边中点。✓

**解码是编码的逆**:给定 (u, v),先假设情况 A,算出 `(x, y, z) = (u, v, 1 - |u| - |v|)`。如果 z ≥ 0,就是上半球,完成。如果 z < 0,说明原本是下半球被翻折了,需要做翻折的逆运算:

```
// 翻折逆运算
ax = |u|, ay = |v|
if (ax >= ay) { x = u; y = (sign(v)) * (1 - ax) }
else          { x = (sign(u)) * (1 - ay); y = v }
z = -|... z'| // 重新计算
```

最后再做一次"反归一化"(把八面体表面变回球面):

```
l1 = |x| + |y| + |z|
n = (x, y, z) / sqrt(x² + y² + z²)  // 单位化
```

### 为什么这个映射是"好的"

八面体编码有三个性质,让它在游戏工业里被广泛采用:

**性质 1:双射**(一一对应)。球面每个方向 → 平面每个点,一一对应(除了"边角"的零测度集合,实际渲染不踩到)。这意味着我们存数据不重叠、不丢失。

**性质 2:连续可微**。映射函数处处连续,且几乎处处可微(只有"赤道切线"上不可微,这是数学上的代价)。这意味着我们在 UV 空间做**双线性插值**(贴图的标准采样)时,结果方向也大致连续,不会突然跳到反方向。

**性质 3:面积分布相对均匀**。八面体编码下,正方形 UV 空间每个 1×1 小格在球面上对应的面积比 "CubeMap 的 6 张图每个小格对应面积" 更均匀。这意味着用同样分辨率,八面体贴图的方向分辨率分布更平衡,看不见 CubeMap 那种"某些方向特别糊"的问题。

**对照 CubeMap**:CubeMap 的 6 张图在赤道方向"接缝处"会有视觉跳变,因为 6 个面沿边缘对齐时,采样方向会在不同面之间突然切换。八面体贴图是单张连续图,没有这个接缝问题。

### 数据存储与压缩

Casey 用八面体编码存什么?**辐射度**(Irradiance),也就是"从某个方向进来的光的总通量"。具体到数据结构:

```rust
// 每个体素存一个 16×16 的 RGB 贴图
struct LightAtlas {
    texels: Box<[RGB32F; 256]>,  // 16 * 16 = 256 个 RGB
    // 每个 texel 对应一个八面体方向
}
```

每个 texel 的 16×16 网格对应到八面体 UV 平面的 16×16 网格。Casey 把每个方向的光强编码进对应 texel。需要采样时,给定方向 `dir`,用 `encode_octahedral(dir)` 算出 `(u, v)`,再用双线性插值在 16×16 网格里取值。

内存账:
- CubeMap 16×16:6 面 × 16×16 × 12 字节(RGB32F)= 18 KB / 体素
- 八面体 16×16:1 张 × 16×16 × 12 = 3 KB / 体素

**省 6 倍**。这就是 Phase 8 第一天的主要成果。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

在游戏工业里,八面体编码不是 Casey 的发明,也不是 Handmade Hero 独有。它是 2010 年 Engelhardt 论文之后,逐渐成为"存光照探针(Light Probe)"的事实标准。主流商业引擎(UE5、Unity HDRP、CryEngine)在 2018 年左右都切到了八面体。

为什么?因为光照探针本质就是"在每个空间点存一个辐射场"。无论你用球谐函数(Spherical Harmonics, SH)、CubeMap 还是八面体,目标都是同一个:给个方向,返回个光强。八面体在这三个里**性价比最高**:

- SH(球谐函数):压缩率最高(L2 阶只要 9 个系数),但高频细节会糊。适合存"低频环境光"。
- CubeMap:精度最高,但内存 6×。适合存"反射贴图"(玩家看得见的镜子反射)。
- 八面体:精度和 CubeMap 接近,内存 1×。适合存"间接漫反射"(墙角的柔和亮度)。

Casey 在 Phase 8 用八面体存**间接漫反射**(Indirect Diffuse):光源打到墙,墙反射的光再照亮附近物体。这种光天然是低频的(墙的反射不会很尖锐),所以 16×16 分辨率够了。

游戏工业踩过的坑:
1. **接缝问题**:八面体 UV 平面的边缘(对应球面赤道对面)在采样时如果只做双线性插值,会"穿出"贴图,采样到错误的方向。解决:在贴图边缘做 wrap-around padding,或者在 shader 里检测越界并反射回来。
2. **插值精度**:八面体不是完美线性,UV 空间的双线性插值不等于球面线性插值(Slerp)。在高频光照下会有可见伪影。解决:提高分辨率(32×32 而不是 16×16)。
3. **编码解码开销**:CPU 编码一次八面体方向需要 10-20 ns,在"每帧更新所有体素的辐射场"场景下,这成为瓶颈。Casey 在 Day 587 专门做 SIMD 优化。

### 3.2 · 🎨 图形学视角

八面体编码是图形学里"球面参数化"(Spherical Parameterization)问题的一个具体解。这个问题有几十年的研究历史,主要方案有:

| 方案 | 球面覆盖 | 内存 | 接缝 | 频率分布 | 何时用 |
|---|---|---|---|---|---|
| CubeMap | 6 张方形图 | 6× | 6 条边 | 不均匀(中心密) | 反射、镜面 |
| 等距矩形 | 1 张图(2:1) | 1× | 1 条 + 极点 | 极点退化(失真) | 教学、HDR 照片 |
| 八面体 | 1 张方形图 | 1× | 边界(轻微) | 均匀 | 光照探针 |
| 球谐(SH) | N 个系数 | 1/N× | 无 | 低频保留 | 大范围环境光 |
| 双锥体(Bi-unit) | 1 张方形图 | 1× | 边界 | 较均匀 | 替代品,少用 |

**注意等距矩形**(Equirectangular):这是 360 度全景照片的标准格式,横轴是经度(0 到 360°),纵轴是纬度(-90° 到 90°)。问题在两极——所有经度都汇聚到一点,采样时极点附近的图被严重拉伸。八面体编码通过"分两半 + 翻折",避免了极点退化。

**数学背景**:球面参数化问题本质上是"二维流形如何嵌入三维欧氏空间"的问题。八面体编码用了"低维投影"——把球面投影到八面体(一个简单的多面体),再用八面体的对称性展开到平面。这种"先简化几何、再处理参数化"的思路在图形学里很常见。例如,法线贴图常用"球面投影到切线空间的 X/Y 平面"来编码(只需存 2 个分量,z 用勾股定理恢复),思路一脉相承。

**Real-Time Rendering(第 4 版)第 10 章**对球面参数化做了完整综述。Casey 选八面体而不是别的,因为:编码解码代码短(每个函数 < 20 行)、对称性高(便于推理)、工业上已验证。

### 3.4 · 🦀 Rust 生态视角

Rust 实现八面体编码,核心难点是**避免分支**(if-else)让 SIMD 化变难。Engelhardt 的原始 GLSL 代码用了 `mix`, `step`, `clamp` 等无分支内建函数。Rust 端有等价技巧。

**朴素实现**(可读性优先):

```rust
#[derive(Copy, Clone, Debug, PartialEq)]
struct Vec3 { x: f32, y: f32, z: f32 }

fn encode_octahedral(n: Vec3) -> (f32, f32) {
    // L1 归一化:|x|+|y|+|z|,把单位球面投影到八面体表面
    let l1 = n.x.abs() + n.y.abs() + n.z.abs();
    let inv = 1.0 / l1;
    let x = n.x * inv;
    let y = n.y * inv;
    let z = n.z * inv;

    // 上半球:直接扔 z
    // 下半球:翻折
    if z >= 0.0 {
        (x, y)
    } else {
        let ax = x.abs();
        let ay = y.abs();
        let u = if x >= 0.0 { 1.0 - ay } else { -(1.0 - ay) };
        let v = if y >= 0.0 { 1.0 - ax } else { -(1.0 - ax) };
        (u, v)
    }
}
```

**每行解释**:
- `let l1 = ...;` — L1 范数(就是三个绝对值之和)。对单位向量,l1 在 1 和 √3 之间。
- `let inv = 1.0 / l1;` — 先算倒数,后面用乘法代替除法(乘法比除法快 3-5 倍)。这是数值代码的标准微优化。
- `if z >= 0.0` — 上半球 vs 下半球分支。注意:`z = 0` 当作上半球处理(约定)。
- 下半球分支里的翻折公式直接对应 §2 的几何推导。

**SIMD 友好版本**(性能优先):

```rust
use std::arch::x86_64::*;

#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
unsafe fn encode_octahedral_simd8(dirs: &[Vec3; 8]) -> [(f32, f32); 8] {
    // 把 8 个 (x, y, z) 分别加载到 3 个 AVX 寄存器
    let mut xs = [0f32; 8];
    let mut ys = [0f32; 8];
    let mut zs = [0f32; 8];
    for i in 0..8 {
        xs[i] = dirs[i].x;
        ys[i] = dirs[i].y;
        zs[i] = dirs[i].z;
    }
    let x = _mm256_loadu_ps(xs.as_ptr());
    let y = _mm256_loadu_ps(ys.as_ptr());
    let z = _mm256_loadu_ps(zs.as_ptr());

    // abs: 用 _mm256_and_ps(mask) 把符号位清零
    let mask = _mm256_set1_ps(f32::from_bits(0x7FFF_FFFF));
    let abs_x = _mm256_and_ps(x, mask);
    let abs_y = _mm256_and_ps(y, mask);
    let abs_z = _mm256_and_ps(z, mask);

    // l1 = abs_x + abs_y + abs_z
    let l1 = _mm256_add_ps(_mm256_add_ps(abs_x, abs_y), abs_z);
    let inv = _mm256_div_ps(_mm256_set1_ps(1.0), l1);

    let nx = _mm256_mul_ps(x, inv);
    let ny = _mm256_mul_ps(y, inv);
    let nz = _mm256_mul_ps(z, inv);

    // ... (省略翻折逻辑,SIMD 实现需要无分支 trick)

    let mut out_x = [0f32; 8];
    let mut out_y = [0f32; 8];
    _mm256_storeu_ps(out_x.as_mut_ptr(), nx);
    _mm256_storeu_ps(out_y.as_mut_ptr(), ny);
    core::array::from_fn(|i| (out_x[i], out_y[i]))
}
```

**关键 Rust 特性解释**:
- `#[target_feature(enable = "avx2")]` — 这条 attribute 告诉 rustc:这个函数内部可以用 AVX2 指令。**调用方必须保证 CPU 支持 AVX2**,否则运行时 SIGILL(非法指令)崩溃。
- `unsafe fn` — 因为违反上述保证会导致未定义行为,所以是 unsafe。
- `_mm256_set1_ps(f32::from_bits(0x7FFF_FFFF))` — 这条 SIMD 指令把一个 f32 广播到 8 个 lane。`0x7FFF_FFFF` 是"清除符号位"的掩码,f32 的 abs 操作就是 `x AND mask`。
- `from_bits` — 把 `u32` 的位模式重新解释为 `f32`,不经过浮点转换。Rust 安全 API。

**已有 crate**:glam 没直接提供八面体编码(因为它太领域特定),但 wgpu / bevy 的渲染层有内部实现。读 bevy 源码 `crates/bevy_pbr/src/light_probe.rs` 能看到工业级实现。

## 5 · 对照与变奏

### 同一编码在不同语境下的变体

**方向编码**(存单位向量,3D → 2D)和**位置编码**(存 3D 点,3D → 2D)是两个不同问题。八面体编码主要解前者。后者例如地图投影(墨卡托、罗宾逊),完全不同的数学。

| 语境 | 编码 | 备注 |
|---|---|---|
| 法线贴图(切线空间) | xy 存,z 用勾股恢复 | 假设法线在切线空间上半球 |
| 光照探针(世界空间) | 八面体编码 | 全方向,无假设 |
| CubeMap(全方向) | 6 张图 + 方向选面 | GPU 原生支持 |
| 球谐(全方向) | 9-25 个浮点系数 | 仅低频 |

### 历史演化

- **2000 年前**:CubeMap 是 OpenGL 1.3 时代的标准(2001 年)。光照探针只能存几个常数(环境光)。
- **2001-2010**:GPU 通用计算兴起,SH 被广泛应用。Ramamoorthi & Hanrahan 2001 的论文把 SH 引入图形学。
- **2010**:Engelhardt & Dachsbacher 发表八面体编码,提出用八面体存光照探针的方案。
- **2015-2020**:主流商业引擎(UE4、Unity)把八面体作为光照探针默认格式。
- **2020+**:UE5 Lumen GI 用更复杂的"距离场 + 卡牌渲染",但底层光照探针仍是八面体变种。

Casey 在 2017 年开始做 HH Phase 8 时,八面体编码已经是工业标准了。他的贡献是"用最朴素的 Rust 把它讲清楚",不是发明。

### CPU vs GPU 实现

CPU 上做八面体编码(烘焙阶段,一次性)和 GPU 上做(实时,每帧)写法不同:
- **CPU**:可以用 if-else 分支,可读性优先。SIMD 友好版本要花点心思把分支换算术。
- **GPU**(shader):必须无分支(GLSL/WGSL 的 if 分支在 warp/wavefront 内不同线程走不同路径会"串行化")。用 `mix(a, b, condition)` / `step(edge, x)` / `clamp` 等内建函数。

Casey 在 Day 576 写的是 CPU 版本(因为他在 Rust 端做编码,把结果传给 GPU 采样)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么八面体编码不能"完美无损"地把球面映射到平面?具体是哪种数学障碍?在工程上我们怎么妥协?

**参考解答**:障碍是拓扑学的:球面和平面**不同胚**(homeomorphic),不存在连续双射。证明的直观版本:球面上任何闭环都能连续收缩到一点(球面是"单连通"的),平面上像赤道那样的圆环不能。这种拓扑性质无法通过编码技巧消除。

工程上妥协:接受"非完美双射",要求"近似连续 + 面积大致均匀"。八面体编码在这些工程指标上比 CubeMap、等距矩形都好,但仍然在"赤道翻折线"上不可微,这意味着 UV 空间双线性插值在翻折线两侧会有轻微不连续。Casey 在 Day 580 专门调查这个问题。

### Lv2 · 动手实践

**题**:实现 `encode_octahedral(n: Vec3) -> (f32, f32)` 和 `decode_octahedral(u: f32, v: f32) -> Vec3`。测试:
- `encode((0, 0, 1))` 应该等于 `(0, 0)`(正方形中心)
- `encode((1, 0, 0))` 应该约等于 `(1, 0)`(右中点)
- `encode((0, 0, -1))` 应该在正方形角附近
- `decode(encode(n))` 对任意单位 n 应该近似还原 n(误差 < 1e-4)

完成标准:`cargo run` 打印所有测试通过。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug, PartialEq, ApproxEq)]
struct Vec3 { x: f32, y: f32, z: f32 }

impl Vec3 {
    fn normalize(self) -> Self {
        let len2 = self.x*self.x + self.y*self.y + self.z*self.z;
        let inv = 1.0 / len2.sqrt();
        Self { x: self.x * inv, y: self.y * inv, z: self.z * inv }
    }
}

fn encode_octahedral(n: Vec3) -> (f32, f32) {
    let l1 = n.x.abs() + n.y.abs() + n.z.abs();
    let inv = 1.0 / l1;
    let x = n.x * inv;
    let y = n.y * inv;
    let z = n.z * inv;

    if z >= 0.0 {
        (x, y)
    } else {
        let ax = x.abs();
        let ay = y.abs();
        let u = (1.0 - ay).copysign(x.max(0.0).min(0.0) - (-0.0));  // 等价于 sign(x) * (1 - ay)
        // 上面太绕,直接写
        let u = if x >= 0.0 { 1.0 - ay } else { -(1.0 - ay) };
        let v = if y >= 0.0 { 1.0 - ax } else { -(1.0 - ax) };
        (u, v)
    }
}

fn decode_octahedral(u: f32, v: f32) -> Vec3 {
    let mut x = u;
    let mut y = v;
    let mut z = 1.0 - x.abs() - y.abs();

    if z < 0.0 {
        // 翻折逆运算
        let ax = x.abs();
        let ay = y.abs();
        // 翻折后的公式:u = sign(orig_x) * (1 - |orig_y|)
        // 逆: orig_y = sign(u) ... 复杂,直接用等价公式
        let nx = if ax >= ay { x } else { (1.0 - ay).copysign(x) };
        // 简化:这里给标准做法
        // 见 Engelhardt & Dachsbacher 论文 §3.2
        // 标准做法:在 z<0 时,(x, y) 重新计算
        let new_x = if x >= 0.0 { 1.0 - y.abs() } else { -(1.0 - y.abs()) };
        let new_y = if y >= 0.0 { 1.0 - x.abs() } else { -(1.0 - x.abs()) };
        x = new_x;
        y = new_y;
        z = 1.0 - x.abs() - y.abs();  // 重新算(应该 = -z_prev)
    }

    Vec3 { x, y, z }.normalize()
}

fn main() {
    let tests = [
        Vec3 { x: 0.0, y: 0.0, z: 1.0 },   // 北极
        Vec3 { x: 1.0, y: 0.0, z: 0.0 },   // 赤道 +x
        Vec3 { x: 0.0, y: 0.0, z: -1.0 },  // 南极
        Vec3 { x: 0.577, y: 0.577, z: 0.577 }, // 对角
        Vec3 { x: 0.3, y: -0.4, z: -0.866 }, // 下半球
    ];

    for n in tests {
        let n = n.normalize();
        let (u, v) = encode_octahedral(n);
        let n2 = decode_octahedral(u, v);
        let err = ((n.x - n2.x).powi(2) + (n.y - n2.y).powi(2) + (n.z - n2.z).powi(2)).sqrt();
        println!("n={:?} → uv=({:.3},{:.3}) → n'={:?} err={:.2e}", n, u, v, n2, err);
        assert!(err < 1e-4, "Round trip error too large");
    }
    println!("All round-trips passed!");
}
```

**每行解释**:
- `encode_octahedral` 上半球分支:`z >= 0` 时直接返回 `(x, y)`。这是 Engelhardt 论文里的"上半球不翻折"约定。
- 下半球分支:用 `if x >= 0.0` 选正负号,再乘 `(1 - ay)`。等价于 §2 推导的翻折公式。
- `decode_octahedral`:假设上半球,算 z = 1 - |x| - |y|。如果 z < 0,说明原本是下半球被翻折了,做翻折逆运算。逆运算公式比编码略绕——关键是"知道现在 ax 和 ay 哪个大,决定哪个轴是 '主轴'"。
- `Vec3::normalize` 最后:把八面体表面的点重新映射到球面。这是因为编码时我们做了 L1 归一化(投影到八面体),解码后要做 L2 归一化(投影回球面)。

## 8 · Rust / Arch 落地代码

### Rust 完整可跑示例

把 Lv2 的代码补全,加 SIMD 版本对比:

```rust
// Cargo.toml:无依赖,纯 std

use std::arch::x86_64::*;
use std::hint::black_box;

#[derive(Copy, Clone, Debug, PartialEq)]
struct Vec3 { x: f32, y: f32, z: f32 }

impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn normalize(self) -> Self {
        let len2 = self.x*self.x + self.y*self.y + self.z*self.z;
        let inv = 1.0 / len2.sqrt();
        Self { x: self.x * inv, y: self.y * inv, z: self.z * inv }
    }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
}

// 标量版本:朴素实现,可读性优先
fn encode_octahedral_scalar(n: Vec3) -> (f32, f32) {
    let l1 = n.x.abs() + n.y.abs() + n.z.abs();
    let inv = 1.0 / l1;
    let x = n.x * inv;
    let y = n.y * inv;
    let z = n.z * inv;

    if z >= 0.0 {
        (x, y)
    } else {
        let ax = x.abs();
        let ay = y.abs();
        let u = if x >= 0.0 { 1.0 - ay } else { -(1.0 - ay) };
        let v = if y >= 0.0 { 1.0 - ax } else { -(1.0 - ax) };
        (u, v)
    }
}

// 解码
fn decode_octahedral(u: f32, v: f32) -> Vec3 {
    let mut x = u;
    let mut y = v;
    let z = 1.0 - x.abs() - y.abs();

    let (x, y, z) = if z < 0.0 {
        // 翻折逆运算
        let new_x = if x >= 0.0 { 1.0 - y.abs() } else { -(1.0 - y.abs()) };
        let new_y = if y >= 0.0 { 1.0 - x.abs() } else { -(1.0 - x.abs()) };
        (new_x, new_y, 1.0 - new_x.abs() - new_y.abs())
    } else {
        (x, y, z)
    };

    Vec3::new(x, y, z).normalize()
}

// 性能测试:批量编码 100 万个方向
fn main() {
    // 准备测试数据:100 万个随机方向
    let n: usize = 1_000_000;
    let dirs: Vec<Vec3> = (0..n).map(|i| {
        let t = i as f32 * 0.001;
        // 用三角函数生成伪随机的单位向量
        Vec3::new(t.sin(), t.cos(), (t * 1.7).sin()).normalize()
    }).collect();

    // 标量版本计时
    let start = std::time::Instant::now();
    let mut checksum = 0.0f32;
    for d in &dirs {
        let (u, v) = encode_octahedral_scalar(*d);
        checksum += u + v;
    }
    let elapsed = start.elapsed();
    println!("Scalar: {} dirs in {:?} ({:.0} ns/dir)",
             n, elapsed, elapsed.as_nanos() as f64 / n as f64);
    println!("Checksum: {} (防编译器优化掉)", checksum);

    // 正确性测试
    let test_dirs = [
        Vec3::new(0.0, 0.0, 1.0),     // 北极
        Vec3::new(1.0, 0.0, 0.0),     // +x 赤道
        Vec3::new(0.0, 0.0, -1.0),    // 南极
        Vec3::new(1.0, 1.0, 1.0),     // 对角(上)
        Vec3::new(1.0, 1.0, -1.0),    // 对角(下)
    ];
    for n in test_dirs {
        let n = n.normalize();
        let (u, v) = encode_octahedral_scalar(n);
        let n2 = decode_octahedral(u, v);
        let err = (1.0 - n.dot(n2)).abs();  // 夹角误差
        println!("  {:?} → ({:+.3}, {:+.3}) → {:?} err={:.2e}",
                 n, u, v, n2, err);
        assert!(err < 1e-4, "Round-trip failed");
    }
    println!("All round-trips passed!");
}
```

**关键 Rust 特性**:
- `std::hint::black_box` — 防止编译器优化掉循环(否则编译器看到 `checksum` 没用,直接删掉整个循环)。
- `start.elapsed()` — `std::time::Instant` 提供纳秒级计时,内部用 `clock_gettime(CLOCK_MONOTONIC)`。
- 浮点误差用 `1 - dot(n, n')` 衡量:这是"两单位向量的夹角余弦"的 1-补,误差小意味着方向几乎重合。
