# Day 652 · 随机光线起点

> 光照模拟里有个细微问题:**所有光线从同一个点出发**(voxel 中心),导致**走样**(aliasing)——同一方向所有光线要么全过要么全挡,出现尖锐边界。今天 Casey 引入**随机起点**——光线起点在小范围随机抖动,平均后边界平滑。

## 0 · 为什么要有这一天

考虑一个边界 case:两堵墙之间一条窄缝,光从缝里穿过。从 surface 中心出发的光线:

- 角度 A 时穿过缝(可见)
- 角度 A+0.001 时被挡(不可见)

这两个角度的差别在浮点级别。结果:surface 在某些角度"闪烁"(光一会有,一会无)。

更糟:整面墙的 surface,如果所有 voxel 中心都在"光能照到"的位置,墙全亮;但只要光源移动 0.01 米,所有 voxel 中心突然都在"被挡"位置,墙全黑。**极端走样**。

**走样**(aliasing)是采样理论的核心问题。Nyquist-Shannon 定理告诉我们:**采样频率必须 ≥ 信号最高频率的 2 倍**,否则会走样。光照的"信号"是空间上的光强变化——墙边缘频率无限高(突变),所以无论怎么采样都会走样。

数学上,一个像素内的光强应该是:

```
L_pixel = ∫∫ L(x, y) dx dy   // 在像素面积上积分
```

但实际我们只取像素中心一个采样:

```
L_pixel ≈ L(center_x, center_y)
```

如果 L 在像素内变化剧烈(边缘),中心采样可能"恰好"在亮区或暗区,导致"黑白翻转"。这就是 shimmering / flickering 的根因。

**随机光线起点**(stochastic ray origins)的思路:**不在 voxel 中心发射光线,而在 voxel 表面随机点发射**。多次采样,平均结果。这是 **Monte Carlo**(蒙特卡洛)方法在光照的应用。

Monte Carlo 的核心洞察:**随机采样 + 平均 → 收敛到积分**。例如,你想计算面积 A 上的积分:

```
∫∫_A f(x, y) dx dy ≈ (1/N) Σ f(x_i, y_i) * |A|
```

其中 (x_i, y_i) 是 A 上的均匀随机点。当 N → ∞ 时,这个估计收敛到真值。

光照里的应用:每个 surface 的"亮度"是"光线从光源能否到达 surface"的积分。在 surface 上随机采样 N 个点,每个点做 raycast,统计通过比例,就是这个积分的 Monte Carlo 估计。

**优点**:

- 边界平滑过渡(50% 通过 = 50% 亮度)
- 噪声可通过累积减少(每帧不同种子,人眼平均)
- 灵活——可加任何概率分布

**缺点**:

- 计算量增加(N 次采样 vs 1 次)
- 单帧有噪声(需要时间平均)

工业图形大量用 Monte Carlo:soft shadow、ambient occlusion、global illumination、depth of field、motion blur。每个都是"采样多次取平均"。

心理锚点:看完今天,你能:

- 解释走样的成因
- 用 Monte Carlo 采样平滑边界
- 实现随机抖动采样
- 理解 Monte Carlo 收敛速度(O(1/sqrt(N)))
- 应用 stochastic sampling 到其他图形问题

## 1 · Casey 今天做了什么

1. 看到 bug:光源移动时,surface 亮度"闪烁"
2. 录制器画每个 surface 的光线,确认"全过 / 全挡"二值
3. 引入随机抖动:`surface.pos + random_offset_in_voxel_face`
4. 每帧用不同随机种子,多次采样
5. 平均 4 次/帧,4 帧后稳定
6. 调参:抖动范围 ±0.4(voxel 半径),采样次数 4-16

## 2 · 心智模型

### 类比:手机拍照

手机摄像头每个像素只采集一次光,会有"摩尔纹"——规则图案重叠出现干涉条纹。

修法:**多采样**(multi-sampling)——每个像素采集多次,平均。或者**抖动采样**(jittered sampling)——每次采样位置略随机,平均后规则图案消失。

游戏光照同理:**光线只采一次,会有规则走样;多次随机采样,平均平滑**。

### 走样(aliasing)数学

Nyquist 采样定理:**采样频率 > 信号最高频率 2 倍**,才能完美重建。光照函数在"光被挡"边界处是高频(突变 0 → 1),单次采样无法重建,出现走样。

**反走样**(anti-aliasing)方法:

- **SSAA**(supersampling):每个像素 4-16 次采样,平均——质量高,慢
- **MSAA**(multisampling):只在几何边界多次采样,内部 1 次——快
- **FXAA**(fast approximation):后处理,检测边缘模糊——便宜
- **TAA**(temporal AA):跨帧多次采样——现代标准

Casey 的随机光线起点 = SSAA 在光照里的版本。

### Monte Carlo 积分

光照计算本质是积分:

```
L_out = ∫_Ω f(ω) * L_in(ω) * cos(θ) dω
```

积分在球面 Ω 上,解析解难。Monte Carlo 方法:**随机采样几个方向,取平均 * 球面积**:

```
L_out ≈ (1/N) * Σ f(ω_i) * L_in(ω_i) * cos(θ_i) * (4π / pdf(ω_i))
```

`pdf` 是采样概率密度函数。如果均匀采样球面,pdf = 1/(4π),公式简化。

N 越大,方差越小,结果越准。但 N 大 = 计算贵。

**Monte Carlo 收敛速度** 是 O(1/√N)。也就是说:

- N = 1 时误差 ~100%
- N = 100 时误差 ~10%
- N = 10000 时误差 ~1%

这意味着:**误差减半需要 4 倍样本**。从 1% 到 0.1% 需要 100 倍样本。

这是 Monte Carlo 的根本限制——收敛慢。但它的**优势是维度无关**:无论积分是 1D 还是 100D,收敛速度都是 O(1/√N)。对高维积分(如 path tracing 的多 bounce 光传输),Monte Carlo 是唯一可行方案。

工业实践:**Importance Sampling**(重要性采样)能加速收敛。如果我们采样的方向"接近光的方向"(高 L_in),采样效率高。具体:

```
pdf(ω) ∝ f(ω) * L_in(ω) * cos(θ)
```

按这个分布采样,N=10 的效果可能等价于均匀采样 N=100。这是 path tracing 的核心技术。

Casey 在 HH 不做 importance sampling——他用简单的"surface 上均匀采样"。这是因为 HH 光源少(单光源),简单采样够。但对多光源场景,importance sampling 是必须。

**Quasi-Monte Carlo**(准蒙特卡洛)用低差异序列(low-discrepancy sequence)代替随机数:

- **Halton sequence**:数论构造,均匀分布
- **Sobol sequence**:更均匀,LDS 经典
- **Blue noise**:视觉上"友好"的噪声分布

这些序列收敛速度 O((log N)^d / N),比纯 Monte Carlo 快。工业级 path tracer (Pixar RenderMan / Disney Hyperion) 都用 QMC。

### 随机起点 vs 随机方向

Casey 的修法是**随机起点**(随机化 raycast 起点),不是随机方向。差别:

- 随机方向:每条光线从同一起点出发,朝随机方向——这是 path tracing
- 随机起点:每条光线朝固定方向(到光源),从随机起点出发——这是 Casey 选的

随机起点更便宜(方向固定,不用 importance sampling),适合"光源远、表面近"的场景。

### 实现

```rust
fn sample_lighting(surface: &Surface, light: &Light, samples: usize) -> [f32; 3] {
    let mut total = [0.0; 3];
    for i in 0..samples {
        // 在 surface 的 voxel 面上随机点
        let jitter = random_in_unit_disk() * 0.4;
        let ray_origin = surface.pos + surface.tangent * jitter.x + surface.bitangent * jitter.y;
        if !raycast_blocked(ray_origin, light.pos) {
            // Lambert 计算
            let contribution = ...;
            total[0] += contribution * light.color[0];
            // ...
        }
    }
    [total[0] / samples as f32, total[1] / samples as f32, total[2] / samples as f32]
}

fn random_in_unit_disk() -> Vec2 {
    let angle = random_f32() * std::f32::consts::TAU;
    let radius = random_f32().sqrt(); // sqrt 让分布在圆内均匀
    Vec2::new(radius * angle.cos(), radius * angle.sin())
}
```

注意 `radius.sqrt()`——直接用 `random()` 会让点集中在中心,平方根让分布均匀。

### 随机数生成

游戏里"随机"分两类:

- **真随机**(crypto-grade):不可预测,慢,不用
- **伪随机**(pseudo):种子确定,可重复,快,适合
- **蓝噪声**(blue noise):高质量低差异序列,适合 Monte Carlo

Casey 用伪随机(Xorshift 或 PCG),种子固定(可重复调试)。

**Rust 里的随机数生态**:

```rust
// 标准库不提供(避免 std 重)。用 rand crate。
use rand::Rng;

let mut rng = rand::thread_rng();
let n: f32 = rng.gen();  // [0, 1)
```

但 `thread_rng()` 不是确定性的——每次运行不同。游戏要可重复调试,需要确定性 PRNG:

```rust
use rand::{SeedableRng, Rng};
use rand_pcg::Pcg64;

let mut rng = Pcg64::seed_from_u64(42);  // 固定种子
let n: f32 = rng.gen();
// 每次运行,n 都一样
```

**PCG**(Permuted Congruential Generator)是现代 PRNG,统计性质好,速度快。Casey 在 HH 应该用类似算法。

**Xorshift** 更简单,4 个 xor/shift 操作:

```rust
fn xorshift32(state: &mut u32) -> u32 {
    let mut x = *state;
    x ^= x << 13;
    x ^= x >> 17;
    x ^= x << 5;
    *state = x;
    x
}
```

只需 1 个 u32 状态,3 个运算,超快。但统计性质不如 PCG。

工业里游戏代码用 PCG / Xoshiro256 / Philox(Counter-based)。Crypto 用 Chacha20。每个场景选合适 PRNG。

**蓝噪声** 是另一类——不是 PRNG,而是预计算的"低差异"点集。蓝噪声在频域上"高频为主"(名字来源),视觉上比白噪声"友好"。工业用蓝噪声做 stochastic sampling,噪点不那么明显。

工业实践:**给每个像素一个独立的 PRNG 种子**(基于 pixel coord),这样每像素独立采样,不会"群体走样"。这是 GPU ray tracing 的标准。

### 随机起点 vs 随机方向

### 跨帧累积(TAA 思路)

每帧采 4 个样本,跨 16 帧累积,等效 64 采样。但物体移动时要"reproject"(找上一帧对应位置),复杂。Casey 简化:每帧独立,16 个样本,一次性平均。

**TAA(Temporal Anti-Aliasing)** 是现代游戏标配。原理:

1. 每帧用不同的 sub-pixel jitter(子像素偏移)
2. 渲染到 G-buffer
3. 下一帧时,用 motion vector 把上一帧像素 reprojection 到当前位置
4. 平均当前帧 + history buffer
5. 更新 history buffer

效果:每帧 1 sample,但跨帧累积 N sample,等效 SSAA 但快 N 倍。

TAA 的难点:

- **Fast-moving 物体**:reprojection 错误,产生拖尾
- **新增物体**:history 没有数据,产生 ghosting
- **Transparency**:半透明物体不能简单累积

工业级 TAA(Unreal / UE5)用大量启发式解决这些 case。这是资深图形程序员的工作。

## 2.5 · 工业级 stochastic sampling 案例

游戏工业大量用 stochastic sampling:

**Soft shadows**(软阴影):point light → area light。从 area light 上随机点做 raycast,平均。这是 stochastic shadow。

**Ambient occlusion**(AO):对每个像素,在半球内随机方向 raycast,统计"被挡比例"。SSAO(屏幕空间 AO)是简化版。

**Global illumination**(GI):path tracing 每像素随机方向,反弹多次,采样光源。这是离线渲染的标准。

**Depth of field**(景深):相机镜头不能同时聚焦远近,渲染时根据光圈大小随机偏移采样方向,模拟镜头模糊。

**Motion blur**(运动模糊):快速运动物体在快门时间内经过多个位置,渲染时累积多个位置。

**所有这些技术都是 Monte Carlo 的应用**——随机采样 + 平均 = 积分估计。Casey 在 HH 只做一个(随机 raycast 起点),但思路相同。

**为什么 Monte Carlo 是图形学的核心?**

因为图形学的本质是"解渲染方程"——一个无限维积分:

```
L_out(x, ω_o) = L_emit(x, ω_o) + ∫ f_r(x, ω_i, ω_o) * L_in(x, ω_i) * cos(θ_i) dω_i
```

L_in 本身又是 L_out(从其他表面来),递归。没有解析解,只能数值。Monte Carlo 是数值方法里最灵活、最适合高维的。所以**所有高级图形算法都是 Monte Carlo 的变体**。

学懂 Monte Carlo,你看 path tracing / photon mapping / irradiance caching / ML GI 都是同一思想的不同实例化。这是图形学的"大一统理论"。

### 实现细节:抖动范围与采样数

抖动范围是 voxel 半径(±0.4 米)。如果太小(±0.01),效果近似单点采样,走样不消除。如果太大(±1.0),采样点超出 voxel,可能"穿过"薄墙。

采样数 N 是性能 trade-off:

- N=1:无 stochastic,走样严重
- N=4:走样减轻,有噪声
- N=16:基本干净
- N=64:高质量,但 4x 性能成本

工业实践:**N=4 + TAA 跨帧累积** = 等效 N=64,这是现代游戏标配。但 TAA 复杂,Casey 简化为 N=16 单帧。

**进阶技巧:Importance Sampling for area lights**

如果光源是 area light(不是 point light),采样应该在 light surface 上随机,而不是 surface 上随机。数学:

```
L_out ∝ Σ BRDF * L_emit * cos(θ_surface) * cos(θ_light) / r² / pdf
```

按 BRDF * cos(θ_surface) 分布采样,效率高。这是现代 PBR 渲染器 (Disney Hyperion / Pixar RenderMan) 的标准。

Casey 简化:点光源 + surface 抖动。够 HH 用,但工业级要更复杂的 sampling。

### "随机"在游戏的特殊应用

游戏里随机性不只是 anti-aliasing:

- **Particle system**:每个粒子初始位置 / 速度 / 颜色随机
- **AI NPC**:决策树里有 random branching(模拟"不确定")
- **Procedural generation**:用 noise function(Perlin / Simplex)生成地形 / 纹理
- **Loot drop**:怪物掉率随机
- **Matchmaking**:多玩家匹配"随机化"避免连续撞同一对手
- **Shuffling**:卡牌游戏洗牌
- **Spawning**:敌人刷新位置随机

每个场景都要"可重复 + 高效 + 统计良好"的 PRNG。Casey 在 HH Day 652 演示的 PRNG 选择,是这个通用需求的实例。

工业教训:**PRNG 不是"随便选"的**。统计性质差的 PRNG(Marsaglia effect,即在 n 维空间取 n 个连续值会落在少数超平面上)会让 Monte Carlo 收敛变慢。统计性质好的(PCG / Xoshiro)是首选。Crypto 性质好的(Chacha20)对游戏 overkill,但安全。

### 3.1 · 游戏编程视角

游戏里随机采样的著名用例:

这些是现代渲染管线的标配。

### 3.2 · 图形学视角

Monte Carlo 在图形学的演化:

- **1986 Kajiya**:渲染方程,提出 path tracing
- **1990s**:Metropolis light transport、bidirectional path tracing
- **2000s**:MLT、photon mapping
- **2010s**:BDPT、VCM、MLT variants
- **2020s**:neural radiance cache,ML 估计辐射度

理论核心都是 Monte Carlo 积分。

### 3.3 · Linux 系统编程视角

Linux 上的随机数:

- `/dev/random`:熵池阻塞,适合 crypto
- `/dev/urandom`:非阻塞,伪随机,适合大多数应用
- `getrandom()` syscall:内核 CSPRNG,推荐
- `rand()` (libc):简单 LCG,慢且低质量

游戏用 PCG / Xorshift,几十纳秒一次,比 libc rand 快 10 倍。

### 3.4 · Rust 生态视角

Rust 随机数生态:

- `rand`:标准 crate,多种算法
- `rand_xoshiro`:更快,适合游戏
- `pcg`:高质量 + 快
- `smallrng`(rand 内):小状态,快

```rust
use rand::Rng;
use rand_xoshiro::Xoshiro256PlusPlus;
use rand::SeedableRng;

let mut rng = Xoshiro256PlusPlus::seed_from_u64(42); // 确定性种子
let r: f32 = rng.gen(); // [0, 1)
```

`Xoshiro256PlusPlus` 状态 32 字节,适合 SIMD,游戏首选。

## 5 · 对照与变奏

不同抖动模式:

```
No jitter        Random jitter     Blue noise
(degenerate)     (high variance)   (low variance)

+ + + +          +   +             +     +
+ + + +            +    +            +
+ + + +              +                 +
+ + + +          +      +          +     +
规则栅格,        随机分布,        蓝噪声,
完全走样         方差大但快       方差小,质量好
```

蓝噪声(computed once)质量最好,但要预计算。

**蓝噪声详解**:蓝噪声在频域上"高频为主",意味着空间上"均匀但不规则"。预计算蓝噪声纹理(256x256 tile,repeat 使用),每次抖动查纹理。

蓝噪声的好处:

- 单帧噪声"友好"——人眼不敏感于高频噪声
- 方差比纯随机低 ~30%
- 可 tile,无边界 artifact

工业级 TAA / DLSS 都用蓝噪声 jitter。这是现代图形学的细节。

**对比不同 anti-aliasing 方法的工业实践**:

| 方法 | 采样数 | 噪声 | 性能 | 适用 |
|---|---|---|---|---|
| No AA | 1 | 走样 | 100% | 老 game |
| SSAA 4x | 4 | 低 | 25% | 高端 GPU |
| MSAA 4x | 1-4 | 低 | 50% | 现代 baseline |
| FXAA | 1 | 中(后处理) | 95% | low-end |
| TAA | 1 | 中(时间累积) | 90% | 现代主流 |
| Stochastic + TAA + Denoiser | 1 | 中 | 85% | RTX / DLSS |

每个时代都有"主流"。Casey 在 HH 用 stochastic single-frame,是 1990s 的方案——教学清晰。现代游戏用 stochastic + TAA + denoiser,质量高但代码复杂。

**为什么 Casey 不用 TAA?**

TAA 需要 motion vector、history buffer、reprojection heuristic。HH 教这些就跑题了。教学项目要"清晰 > 先进"。

但学懂 HH 的 stochastic,你看 TAA 就是"HH + reprojection"。这是从教学到工业的桥梁。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 `radius = random().sqrt()` 比 `radius = random()` 在圆内分布更均匀?

**参考解答**:random() 给均匀分布在 [0, 1] 的值,但圆面积 ∝ r^2。如果 r 均匀分布,小 r 处密度高(因为同样比例的 r 范围在小 r 处覆盖面积更小)。要让面积均匀,需要 `r^2` 均匀分布——`r = sqrt(uniform())`。这样小 r 处密度降低,大 r 处密度升高,整体面积均匀。

### Lv2 · 动手实践

**题**:实现 `random_in_unit_disk`,验证均匀分布。采样 10000 个点,统计 4 个象限的数量,应大致相等(2500 each)。

**参考解答**:

```rust
use rand::Rng;
use rand::SeedableRng;
use rand_xoshiro::Xoshiro256PlusPlus;

fn random_in_unit_disk(rng: &mut impl Rng) -> [f32; 2] {
    let angle: f32 = rng.gen_range(0.0..std::f32::consts::TAU);
    let r: f32 = rng.gen::<f32>().sqrt();
    [r * angle.cos(), r * angle.sin()]
}

fn main() {
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let mut quadrants = [0u32; 4];
    for _ in 0..10000 {
        let [x, y] = random_in_unit_disk(&mut rng);
        let q = match (x >= 0.0, y >= 0.0) {
            (true, true) => 0,
            (false, true) => 1,
            (false, false) => 2,
            (true, false) => 3,
        };
        quadrants[q] += 1;
    }
    println!("Quadrants: {:?}", quadrants);
    // 应该接近 [2500, 2500, 2500, 2500]

    // 也统计 r 分布
    let mut r_bins = [0u32; 10];
    for _ in 0..10000 {
        let r: f32 = rng.gen::<f32>().sqrt();
        let bin = (r * 10.0) as usize;
        if bin < 10 { r_bins[bin] += 1; }
    }
    println!("r bins: {:?}", r_bins);
    // 应该接近均匀(每个 bin ~1000)
}
```

## 8 · Rust / Arch 落地代码

随机起点的光照采样:

```rust
// Cargo.toml:
// [dependencies]
// glam = "0.29"
// rand = "0.8"
// rand_xoshiro = "0.6"

use glam::{Vec2, Vec3};
use rand::{Rng, SeedableRng};
use rand_xoshiro::Xoshiro256PlusPlus;

fn random_in_disk(rng: &mut impl Rng) -> Vec2 {
    let angle: f32 = rng.gen_range(0.0..std::f32::consts::TAU);
    let r: f32 = rng.gen::<f32>().sqrt();
    Vec2::new(r * angle.cos(), r * angle.sin())
}

struct Surface {
    pos: Vec2,
    tangent: Vec2,  // 沿 voxel 表面的切线
}

struct Light {
    pos: Vec2,
    intensity: f32,
}

fn sample_light(
    solid: &dyn Fn(i32, i32) -> bool,
    s: &Surface,
    light: &Light,
    rng: &mut impl Rng,
    samples: usize,
) -> f32 {
    let mut sum = 0.0;
    for _ in 0..samples {
        let jitter = random_in_disk(rng) * 0.4;
        let ray_origin = s.pos + s.tangent * jitter.x + Vec2::new(-s.tangent.y, s.tangent.x) * jitter.y;
        let dir = light.pos - ray_origin;
        let len = dir.length();
        if len < 1e-6 { continue; }
        // 2D DDA(简化:只用 x 坐标判断)
        let mut x = ray_origin.x.floor() as i32;
        let mut y = ray_origin.y.floor() as i32;
        let dx = dir.x / len;
        let dy = dir.y / len;
        let step_x = if dx > 0.0 { 1 } else { -1 };
        let step_y = if dy > 0.0 { 1 } else { -1 };
        let tdx = (1.0 / dx.abs()).max(1e-6);
        let tdy = (1.0 / dy.abs()).max(1e-6);
        let mut tx = if dx > 0.0 { (x as f32 + 1.0 - ray_origin.x) / dx }
                     else { (x as f32 - ray_origin.x) / dx };
        let mut ty = if dy > 0.0 { (y as f32 + 1.0 - ray_origin.y) / dy }
                     else { (y as f32 - ray_origin.y) / dy };
        let mut blocked = false;
        let mut t = 0.0;
        while t < len {
            if solid(x, y) { blocked = true; break; }
            if tx < ty { t = tx; tx += tdx; x += step_x; }
            else { t = ty; ty += tdy; y += step_y; }
        }
        if !blocked {
            let atten = light.intensity / (1.0 + len * len);
            sum += atten;
        }
    }
    sum / samples as f32
}

fn main() {
    let mut rng = Xoshiro256PlusPlus::seed_from_u64(42);
    let solid = |x: i32, _y: i32| -> bool { x == 5 };
    let surface = Surface {
        pos: Vec2::new(2.0, 2.0),
        tangent: Vec2::new(1.0, 0.0),
    };
    let light = Light { pos: Vec2::new(10.0, 2.0), intensity: 10.0 };

    let result = sample_light(&solid, &surface, &light, &mut rng, 16);
    println!("Stochastic lighting: {:.4}", result);
    // 应该是 0.0(墙 x=5 挡住)

    // 测试光没被挡:
    let solid2 = |_: i32, _: i32| -> bool { false };
    let result2 = sample_light(&solid2, &surface, &light, &mut rng, 16);
    println!("Unblocked lighting: {:.4}", result2);
    // 应该非 0
}
```

## 10 · 工程反思

Day 652 传达三个长期受益的工程教训:

**教训一:走样是采样的本质问题**。任何"采样 + 重建"过程都有走样——音频、视频、光照、AI 训练。Nyquist 定理是普适的:**采样频率必须 ≥ 信号频率的 2 倍**。理解这条,你看 JPEG、MP3、TAA、DLSS 都是同一思想的不同实例。

**教训二:Monte Carlo 是工程万能钥匙**。高维积分、复杂概率、不可解析系统——Monte Carlo 都能跑。它慢(O(1/√N)),但**维度无关**,这是关键优势。学懂 Monte Carlo,你打开了从图形学到机器学习的整个数值世界。

**教训三:随机性是 feature,不是 bug**。新手觉得"确定性 = 好",但工业里**刻意引入随机**(stochastic sampling、dropout、SGD)反而提升质量。原因是随机打破"规则走样",让结果更"自然"。这是反直觉的智慧。

工业教训:**所有"高质量图形"都是 stochastic + denoiser**。RTX 用 stochastic ray tracing,然后用 ML denoiser 去噪。DLSS 用 stochastic TAA + ML upscale。这套"采样 + 去噪"是 2020s 图形学的核心架构。

Casey 在 HH 只演示最简单的 stochastic ray origin,但思路同 RTX。学懂 HH,你看 RTX 就是"HH + ML denoiser + 更多样本"。这是从教学到工业的平滑过渡。
