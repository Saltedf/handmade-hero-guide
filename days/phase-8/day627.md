# Day 627 · 用瓦片开门

> Day 626 清理 `traversable` 概念,引入 `solid / walkable` 二元组。今天 Casey 用这套新概念实现**机关门**:玩家走到门附近,按交互键,门从 `solid=true, walkable=false` 切换到 `solid=false, walkable=true`。这是清理后立刻用新概念做的第一个功能,验证清理的价值。

## 0 · 为什么要有这一天

HH 的关卡设计需要**机关门**:

- 玩家进入房间,门关闭(`solid=true`),玩家被困
- 玩家找到开关 / 击败 boss,门打开(`solid=false`),玩家可以继续

Phase 2-7 没实现这个,因为 `traversable` 单 bool 表达不了"开门 / 关门"状态切换——开门需要 `walkable=true`,关门需要 `walkable=false`,但几何上都需要 `solid=true`(关)→ `solid=false`(开)。**单 bool 只能表达一维状态**。

Day 626 的 `solid + walkable` 二元组刚好解决:`solid` 控制几何(关门碰撞),`walkable` 控制逻辑(玩家可走)。今天用这个能力实现门。

**今天的核心概念**:**状态切换**(state transition)——对象在多个状态间转换,每个状态对应不同的物理 / 逻辑属性。

**心理锚点**:看完这集,你能:
- 用 Day 626 的二元组实现状态切换
- 设计事件系统(玩家交互 → 门打开)
- 理解为什么"清晰的语义"对游戏逻辑至关重要

## 2 · 心智模型

### 类比:电梯的"运行 / 停止"状态

电梯有多个状态:

- **Open**:门开,人可进出。但电梯不能运行(危险)
- **Closed**:门关,人不能进出。但电梯可以运行
- **Moving**:运行中,门必须关

状态间转换有**规则**:

- Open → Closed:门关上(机械动作)
- Closed → Open:门打开
- Closed → Moving:电梯启动(只有 closed 才能 moving)
- Moving → Closed:到达,但不能直接 Open(必须先停止)

游戏机关门完全一样:

- **Closed**:`solid=true, walkable=false`(挡住玩家)
- **Open**:`solid=false, walkable=true`(玩家可走)
- 切换:玩家交互 / 时间 / 触发器

**清晰的状态 + 清晰的转换规则**是游戏对象的核心。

### 严谨:状态机

#### 2.1 State Machine

```rust
enum DoorState {
    Closed,
    Opening,  // 动画过渡
    Open,
    Closing,  // 动画过渡
}

struct Door {
    state: DoorState,
    progress: f32,  // 0.0 - 1.0,用于 Opening / Closing 动画
    associated_tile: (i32, i32),
}
```

**为什么用 enum 而不是 bool**:enum 表达多个互斥状态,bool 只能两个。门有 4 个状态,必须 enum。

#### 2.2 状态转换

```rust
impl Door {
    fn interact(&mut self) {
        match self.state {
            DoorState::Closed => {
                self.state = DoorState::Opening;
                self.progress = 0.0;
            }
            DoorState::Open => {
                self.state = DoorState::Closing;
                self.progress = 0.0;
            }
            _ => {}  // 过渡中,忽略
        }
    }

    fn update(&mut self, dt: f32) {
        match self.state {
            DoorState::Opening => {
                self.progress += dt * 2.0;  // 2 秒开完
                if self.progress >= 1.0 {
                    self.state = DoorState::Open;
                    self.progress = 1.0;
                    self.apply_to_tile();
                }
            }
            DoorState::Closing => {
                self.progress += dt * 2.0;
                if self.progress >= 1.0 {
                    self.state = DoorState::Closed;
                    self.progress = 1.0;
                    self.apply_to_tile();
                }
            }
            _ => {}
        }
    }

    fn apply_to_tile(&self, world: &mut World) {
        let tile = world.tile_mut(self.associated_tile);
        match self.state {
            DoorState::Closed | DoorState::Closing => {
                tile.solid = true;
                tile.walkable = false;
            }
            DoorState::Open | DoorState::Opening => {
                tile.solid = false;
                tile.walkable = true;
            }
        }
    }
}
```

#### 2.3 玩家交互

```rust
fn player_interact(world: &mut World, player: &Player) {
    // Raycast 找前方的 door
    let interact_dir = player.facing;
    let interact_range = 2.0;
    let origin = player.position + Vec3::new(0.0, 0.5, 0.0);

    // Cast 一条短光线
    if let Some(hit) = world.raycast(origin, interact_dir, interact_range) {
        if let Some(door_id) = world.tile(hit.pos).door {
            world.doors[door_id].interact();
            // 触发音效
            let sound_tag = match world.doors[door_id].state {
                DoorState::Opening => "door_open",
                DoorState::Closing => "door_close",
                _ => return,
            };
            play_sound(world.assets.get_random_with_tag(sound_tag, &mut world.rng));
        }
    }
}
```

#### 2.4 完整流程

```
玩家按 E 键
→ player_interact 调用
→ raycast 找前方对象
→ 如果是 door,调用 door.interact()
→ door 状态切换(Closed → Opening)
→ 每帧 update,progress 增加
→ progress 达 1.0,状态变 Open
→ apply_to_tile:solid=false, walkable=true
→ 玩家可以走过
```

#### 2.5 多个门的协调

复杂场景:多个门联动(开一个,关另一个)。Casey 用 **door group**:

```rust
struct DoorGroup {
    doors: Vec<DoorId>,
    rule: GroupRule,
}

enum GroupRule {
    AllOrNothing,  // 要么全开,要么全关
    Toggle,        // 一个开,其他关
    Sequence,      // 顺序开关
}
```

boss 房间:开门需要打败 boss → 触发 group 全开。这是关卡设计的核心机制。

### 2.6 事件系统(进阶)

工业级引擎用**事件系统**(event system)解耦:

```rust
enum Event {
    PlayerInteract { entity_id: EntityId },
    DoorOpen { door_id: DoorId },
    DoorClose { door_id: DoorId },
    BossDefeated { boss_id: EntityId },
}

struct EventQueue {
    events: Vec<Event>,
}

impl EventQueue {
    fn emit(&mut self, event: Event) {
        self.events.push(event);
    }
    fn drain(&mut self) -> Vec<Event> {
        std::mem::take(&mut self.events)
    }
}

// 处理事件
for event in event_queue.drain() {
    match event {
        Event::DoorOpen { door_id } => {
            world.doors[door_id].set_state(DoorState::Opening);
        }
        Event::BossDefeated { .. } => {
            // 打开所有 boss 房间门
            for door in &mut world.doors {
                if door.group == "boss_room" {
                    door.set_state(DoorState::Opening);
                }
            }
        }
        _ => {}
    }
}
```

事件系统让**触发逻辑**和**响应逻辑**解耦,大型项目必备。Casey 在 Day 627 简化版没用事件系统,但未来可能扩展。

### 3.4 · 🦀 Rust 生态视角

Rust 表达状态机:

#### 模式 1:enum + match(本日)

```rust
enum State { Closed, Opening, Open, Closing }

match state {
    State::Closed => { ... }
    State::Opening => { ... }
    // ...
}
```

简单,但状态多时 match arm 多。

#### 模式 2:typestate pattern

```rust
struct Closed;
struct Opening { progress: f32 }
struct Open;
struct Closing { progress: f32 }

trait DoorState {}
impl DoorState for Closed {}
impl DoorState for Opening {}
impl DoorState for Open {}
impl DoorState for Closing {}

struct Door<S: DoorState> {
    _state: PhantomData<S>,
}

impl Door<Closed> {
    fn open(self) -> Door<Opening> {
        Door { _state: PhantomData }
    }
}
```

编译期保证状态转换合法。复杂但极安全。

#### 模式 3:状态机 crate

```toml
[dependencies]
statig = "0.2"  # 或 smlang, rifles17
```

```rust
#[statig::state_machine(initial = "State::Closed()")]
impl Door {
    #[state]
    fn closed(event: &Event) -> Response<State> {
        match event {
            Event::Interact => Transition(State::opening()),
            _ => Superstate::closed(event),
        }
    }
}
```

声明式定义状态机,自动生成代码。工业级用。

**Casey 选择**:模式 1(简单)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么机关门需要 `solid + walkable` 两个 bool,而不是单一 `passable`?

**参考解答**:

- 关门:`solid=true`(挡住物品), `walkable=false`(挡住玩家)
- 开门:`solid=false`, `walkable=true`
- 但**过渡中(Opening)**:`solid=false`(几何已开), `walkable=true`(玩家可走),但视觉上还有半个 sprite

如果用单 bool,过渡中表达不了"半开半关"。

更复杂的机关:`solid=true, walkable=false`(玩家不能走)→ 玩家有钥匙 → `solid=false, walkable=true`(可走)。单 bool 表达不了"有钥匙后状态"。

### Lv2 · 动手实践

**题**:实现一个简单的机关门。要求:

- Door 有 4 个状态(Closed/Opening/Open/Closing)
- 玩家交互(toggle)切换 Closed ↔ Opening → Open
- 每帧 update 推进 progress
- progress 达 1.0 时状态切换
- 状态切换时打印 tile 的 solid/walkable

完成标准:`cargo run` 模拟 4 次交互,看到状态正确切换。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug, PartialEq)]
enum DoorState { Closed, Opening, Open, Closing }

#[derive(Copy, Clone, Debug)]
struct Tile {
    solid: bool,
    walkable: bool,
}

struct Door {
    state: DoorState,
    progress: f32,
}

impl Door {
    fn new() -> Self {
        Self { state: DoorState::Closed, progress: 0.0 }
    }

    fn interact(&mut self) {
        match self.state {
            DoorState::Closed => {
                self.state = DoorState::Opening;
                self.progress = 0.0;
                println!("  → Door starts opening");
            }
            DoorState::Open => {
                self.state = DoorState::Closing;
                self.progress = 0.0;
                println!("  → Door starts closing");
            }
            _ => println!("  → Door busy, ignoring"),
        }
    }

    fn update(&mut self, dt: f32) -> Option<Tile> {
        let mut tile_change = None;
        match self.state {
            DoorState::Opening => {
                self.progress += dt * 2.0;
                if self.progress >= 1.0 {
                    self.state = DoorState::Open;
                    self.progress = 1.0;
                    tile_change = Some(Tile { solid: false, walkable: true });
                    println!("  → Door fully open");
                }
            }
            DoorState::Closing => {
                self.progress += dt * 2.0;
                if self.progress >= 1.0 {
                    self.state = DoorState::Closed;
                    self.progress = 1.0;
                    tile_change = Some(Tile { solid: true, walkable: false });
                    println!("  → Door fully closed");
                }
            }
            _ => {}
        }
        tile_change
    }
}

fn main() {
    let mut door = Door::new();
    let dt = 0.5;  // 每帧 0.5 秒

    println!("Initial state: {:?}", door.state);

    // 玩家交互
    door.interact();

    // 多帧 update,直到状态稳定
    for frame in 0..5 {
        println!("Frame {}: state={:?} progress={:.2}", frame, door.state, door.progress);
        if let Some(tile) = door.update(dt) {
            println!("  Tile updated: solid={} walkable={}", tile.solid, tile.walkable);
        }
    }

    // 再次交互(关)
    door.interact();
    for frame in 0..5 {
        println!("Frame {}: state={:?} progress={:.2}", frame, door.state, door.progress);
        if let Some(tile) = door.update(dt) {
            println!("  Tile updated: solid={} walkable={}", tile.solid, tile.walkable);
        }
    }
}
```

## 8 · Rust / Arch 落地代码

### 完整可跑的门 + 状态机

```rust
// Cargo.toml: 空

#[derive(Copy, Clone, Debug, PartialEq)]
enum DoorState { Closed, Opening, Open, Closing }

#[derive(Copy, Clone, Debug)]
struct Tile {
    solid: bool,
    walkable: bool,
}

impl Tile {
    fn wall() -> Self { Self { solid: true, walkable: false } }
    fn floor() -> Self { Self { solid: false, walkable: true } }
}

struct Door {
    state: DoorState,
    progress: f32,
    open_speed: f32,
}

impl Door {
    fn new() -> Self {
        Self { state: DoorState::Closed, progress: 0.0, open_speed: 2.0 }
    }

    fn interact(&mut self) {
        match self.state {
            DoorState::Closed => {
                self.state = DoorState::Opening;
                self.progress = 0.0;
            }
            DoorState::Open => {
                self.state = DoorState::Closing;
                self.progress = 0.0;
            }
            _ => {}  // 过渡中
        }
    }

    fn update(&mut self, dt: f32) -> Option<Tile> {
        match self.state {
            DoorState::Opening => {
                self.progress += dt * self.open_speed;
                if self.progress >= 1.0 {
                    self.state = DoorState::Open;
                    self.progress = 1.0;
                    return Some(Tile::floor());
                }
            }
            DoorState::Closing => {
                self.progress += dt * self.open_speed;
                if self.progress >= 1.0 {
                    self.state = DoorState::Closed;
                    self.progress = 1.0;
                    return Some(Tile::wall());
                }
            }
            _ => {}
        }
        None
    }
}

fn main() {
    let mut door = Door::new();
    let mut current_tile = Tile::wall();
    let dt = 0.4;

    println!("=== Door state machine demo ===\n");

    for cycle in 0..3 {
        println!("--- Cycle {} ---", cycle + 1);

        // 初始状态
        println!("Initial: state={:?}, tile={:?}", door.state, current_tile);

        // 玩家交互
        println!("Player interacts...");
        door.interact();

        // 多帧 update
        for frame in 0..10 {
            if let Some(new_tile) = door.update(dt) {
                current_tile = new_tile;
                println!("  Frame {}: state → {:?}, tile → {:?}", frame, door.state, current_tile);
                break;
            }
            println!("  Frame {}: state={:?} progress={:.2}", frame, door.state, door.progress);
        }

        // 反向
        println!("Player interacts again...");
        door.interact();
        for frame in 0..10 {
            if let Some(new_tile) = door.update(dt) {
                current_tile = new_tile;
                println!("  Frame {}: state → {:?}, tile → {:?}", frame, door.state, current_tile);
                break;
            }
            println!("  Frame {}: state={:?} progress={:.2}", frame, door.state, door.progress);
        }

        println!();
    }
}
```

**Troubleshooting**:

- 状态卡死 — 检查 update 是否在所有 case 都推进 progress
- progress 超过 1.0 — 用 `min(1.0)` clamp
- 状态不一致 — 加 debug assert 验证

## 附录 · 状态机的工业实现深入

Day 627 用最朴素的 enum + match 实现状态机。工业级实现有更多深度。

### HFSM(Hierarchical Finite State Machine)

普通 FSM 状态多了难管理。HFSM 允许**状态嵌套**:

```
Door
├── Closed
│   ├── Locked
│   └── Unlocked
├── Opening
├── Open
└── Closing
```

Locked 和 Unlocked 共享 Closed 父状态的属性(`solid=true`),但 Locked 多了"需要钥匙"。

HFSM 的 transition 更智能:`Locked → Opening`(玩家有钥匙)而不是 `Locked → Closed → Opening`。

### Behavior Tree

游戏 AI 不用 FSM,用 Behavior Tree(BT):

```
Selector
├── Sequence [Attack]
│   ├── Condition [Enemy in range]
│   └── Action [Attack]
├── Sequence [Chase]
│   ├── Condition [Enemy visible]
│   └── Action [Move to enemy]
└── Action [Wander]
```

BT 比 FSM 灵活,适合复杂 AI。但简单的机关门用 FSM 足够。

### ECS + Event Bus

现代引擎(Bevy)用 ECS + event:

```rust
#[derive(Component)]
struct Door { state: DoorState, ... }

#[derive(Event)]
struct DoorInteract { entity: Entity }

fn door_system(
    mut doors: Query<&mut Door>,
    mut events: EventReader<DoorInteract>,
) {
    for event in events.read() {
        if let Ok(mut door) = doors.get_mut(event.entity) {
            door.interact();
        }
    }
}
```

完全解耦,大型项目用。Casey 不用 ECS(他偏好直接 struct),但思想值得了解。

### State Machine 编译期验证

Rust 的 typestate pattern:

```rust
struct Door<S> { _state: PhantomData<S> }

struct Closed;
struct Open;

impl Door<Closed> {
    fn open(self) -> Door<Open> {
        Door { _state: PhantomData }
    }
}

impl Door<Open> {
    fn close(self) -> Door<Closed> {
        Door { _state: PhantomData }
    }
}

// 编译期:Door<Closed>::close() 不存在,无法调用
```

零运行时开销,编译期保证转换合法。复杂但极安全。

### 状态持久化

游戏存档需要序列化状态机:

```rust
#[derive(Serialize, Deserialize)]
enum DoorState { Closed, Opening { progress: f32 }, Open, Closing { progress: f32 } }

let json = serde_json::to_string(&door.state).unwrap();
let restored: DoorState = serde_json::from_str(&json).unwrap();
```

注意:状态机的内部不变量(progress 在 [0, 1])需要序列化后验证。

### 状态机的可视化工具

工业项目用 graphviz 可视化状态机:

```bash
dot -Tsvg state_machine.dot -o state_machine.svg
```

辅助理解复杂状态转换。HH 状态简单,不需要。

### 网络同步

多人游戏的状态机需要网络同步:

- **Authoritative server**:服务器维护权威状态,客户端预测
- **State synchronization**:状态变化广播给所有客户端
- **Conflict resolution**:多个 interact 同时到达,服务器仲裁

复杂。HH 单机,不考虑。
