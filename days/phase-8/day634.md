## 2 · 心智模型

### 类比:撞墙后的反应

你跑步撞墙,几种反应:

- **Stop**:整个人停下,倒地。疼,且不会继续跑
- **Bounce**:像橡皮球,弹回去。不真实
- **Slide**:贴着墙继续滑。自然,流畅
- **Stuck**:卡在墙里。bug

游戏角色完全一样:

- Stop:撞墙就停,玩家挫败
- Bounce:弹来弹去,无法控制
- **Slide**(最佳):沿墙滑,玩家感觉"贴墙也能走"

### 严谨:Collision Response 算法

#### 2.1 Stop(完全停止)

```rust
fn move_player(world: &World, pos: &mut Vec3, vel: &mut Vec3, dt: f32) {
    let new_pos = *pos + *vel * dt;
    if is_player_collide(world, new_pos) {
        *vel = Vec3::zero();  // 完全停止
        // pos 不变
    } else {
        *pos = new_pos;
    }
}
```

**问题**:斜向撞墙时,所有方向速度归零,玩家卡住。

#### 2.2 Bounce(反弹)

```rust
fn move_player(...) {
    let new_pos = *pos + *vel * dt;
    if is_player_collide(world, new_pos) {
        *vel = -*vel * 0.5;  // 反向 + 衰减
    } else {
        *pos = new_pos;
    }
}
```

**问题**:像橡皮球,不真实。

#### 2.3 Slide(沿墙滑行,HH 选)

```rust
fn move_player(...) {
    // 分轴 + 步进(同 Day 632)
    let dx = vel.x * dt;
    let new_x = *pos + Vec3::new(dx, 0, 0);
    if !is_player_collide(world, new_x) {
        *pos = new_x;
    } else {
        vel.x = 0;  // 仅 X 方向归零
    }

    let dy = vel.y * dt;
    let new_y = *pos + Vec3::new(0, dy, 0);
    if !is_player_collide(world, new_y) {
        *pos = new_y;
    } else {
        vel.y = 0;
    }

    let dz = vel.z * dt;
    let new_z = *pos + Vec3::new(0, 0, dz);
    if !is_player_collide(world, new_z) {
        *pos = new_z;
    } else {
        vel.z = 0;
    }
}
```

**优势**:

- 斜向撞墙:撞 X 就 X 停,Y/Z 继续 → 沿墙滑行
- 手感自然
- 实现简单

**这是 HH 的最终选择**。

#### 2.4 地面检测(Ground Detection)

玩家是否站在地面?决定:

- 重力是否生效
- 跳跃是否可用

```rust
fn is_on_ground(world: &World, pos: Vec3) -> bool {
    let foot = pos;
    let below = pos - Vec3::new(0, 0.1, 0);  // 脚下 0.1m
    // 如果脚在空中,但脚下 0.1m 有 voxel → 站在地面
    !is_player_collide(world, foot) && is_player_collide(world, below)
}
```

#### 2.5 完整 Player Update

```rust
fn update_player(world: &World, player: &mut Player, input: Input, dt: f32) {
    // 1. 输入 → wish_dir
    let mut wish_dir = Vec3::zero();
    if input.w { wish_dir.z -= 1; }
    if input.s { wish_dir.z += 1; }
    if input.a { wish_dir.x -= 1; }
    if input.d { wish_dir.x += 1; }
    wish_dir = wish_dir.normalized();

    // 2. 重力
    let on_ground = is_on_ground(world, player.pos);
    if on_ground {
        if input.jump {
            player.vel.y = JUMP_SPEED;  // 跳
        } else {
            player.vel.y = 0;
        }
    } else {
        player.vel.y -= GRAVITY * dt;  // 重力
    }

    // 3. 水平移动(wish_dir 速度)
    let horizontal_vel = wish_dir * player.speed;
    player.vel.x = horizontal_vel.x;
    player.vel.z = horizontal_vel.z;

    // 4. 移动 + 碰撞响应(分轴 + 步进)
    let total_move = player.vel * dt;
    let n_steps = ((total_move.length() / STEP_SIZE).ceil() as usize).max(1);
    let step = total_move / n_steps as f32;

    for _ in 0..n_steps {
        // Slide response
        let dx = Vec3::new(step.x, 0, 0);
        if !is_player_collide(world, player.pos + dx) {
            player.pos += dx;
        } else {
            player.vel.x = 0;
        }
        let dy = Vec3::new(0, step.y, 0);
        if !is_player_collide(world, player.pos + dy) {
            player.pos += dy;
        } else {
            player.vel.y = 0;
        }
        let dz = Vec3::new(0, 0, step.z);
        if !is_player_collide(world, player.pos + dz) {
            player.pos += dz;
        } else {
            player.vel.z = 0;
        }
    }
}
```

## 附录 · Collision Response 的工业级实现

Day 634 用 Slide response。工业级物理引擎更复杂,值得理解。

### Sequential Impulse Solver

Box2D / Rapier 用 Sequential Impulse:

```
1. 检测所有碰撞对
2. 对每对:
   - 计算相对速度
   - 算出需要的 impulse(冲量) 让它们分开
3. 应用 impulse,更新速度
4. 重复 N 次(迭代收敛)
```

**优点**:多体碰撞稳定(堆叠箱子)。
**缺点**:复杂,慢。

### Constraint-based Solver

更精确,用 Lagrange multiplier:

```
对每个 constraint(碰撞、铰链、弹簧),
列方程:constraint_force × jacobian = 0
解联立方程。
```

**优点**:精确。
**缺点**:解线性方程,慢。

### HH 的简化

HH 用 Slide response:

- 不解联立方程
- 不迭代
- 简单"撞了就停"

**够用**:玩家 + 简单 NPC,不需要多体碰撞。

### 物理 engine 的"接触点"

工业级算法算"contact manifold"(接触流形):

```
两个 box 碰撞 → 一条边或一个面接触
算接触点的法线、深度、摩擦
```

HH 简化为"是否 collide",忽略接触点细节。

### 摩擦力

工业级:

- **Static friction**:静摩擦(物体不动)
- **Kinetic friction**:动摩擦(物体在动)
- 每个接触点独立算

HH:

- 简单"撞了停",忽略摩擦细节
- 玩家在地面有"摩擦"(立刻停)
- 玩家在空中无摩擦(惯性)

### 弹性

工业级:每个对象有 restitution(弹性系数):

- 0:完全非弹(泥)
- 1:完全弹(橡皮)
- 中间:部分弹

HH:restitution=0,所有物体完全非弹。

### HH 与工业级的差距

| 特性 | HH(本日) | Rapier |
|---|---|---|
| 多体碰撞 | 不支持 | 支持 |
| 接触点详细 | 忽略 | 精确 |
| 摩擦 | 简化 | 完整 |
| 弹性 | 固定 0 | 可调 |
| 关节 | 无 | hinge / spring |
| Ragdoll | 无 | 支持 |

**HH 简化版**,但游戏够用。

### 何时升级

HH 未来可能升级到物理引擎如果:

- 加多人(玩家间碰撞)
- 加复杂机关(铰链 / 弹簧)
- 加物理 puzzle(推箱子、堆叠)

**目前**:简单 voxel collision 足够。

## 附录 II · Game Feel 中的 Collision Response

Day 634 是 collision response 设计。Game Feel 的核心。

### Collision Response 决定手感

不同 response → 不同手感:

- **Stop**(早期 8-bit 游戏):机械感
- **Bounce**(弹球游戏):弹跳感
- **Slide**(Quake / Mario 64):流畅感
- **Momentum-based**(现代化):重量感

每个时代的游戏用不同 response,反映当时技术和审美。

### "重量感"vs"敏捷感"

现代游戏的两种 trend:

- **重量感**(Dark Souls, RDR2):动量 + 慢响应 → 角色感觉"重"
- **敏捷感**(Celeste, Mario):快速响应 → 角色"灵巧"

HH 偏敏捷——玩家 5 m/s,响应立刻。

### 跳跃的 response

跳跃是 collision response 的特殊 case:

- **Variable jump height**:按住跳得高,松开跳得低
- **Coyote time**:离开平台 0.1s 仍可跳
- **Jump buffer**:落地前 0.1s 按跳跃,落地立刻跳
- **Double jump**:空中再跳一次

每个都让跳跃手感更好。HH 部分实现。

### Collision 的"反馈"

碰撞发生时,玩家应该感受到:

- **视觉**:屏幕轻微震动
- **听觉**:撞击音效
- **动画**:角色撞击姿势
- **手柄**:震动(haptic)

每个反馈让碰撞从"机械"变"有感"。

### HH 的 collision 反馈

- 撞墙:小屏震 + 音效
- 跳跃落地:尘土粒子 + 音效

每个都是"juice"。

2. **A/B**:不同参数,让玩家选哪个手感好

4. **高速录像**:60 FPS / 240 FPS 录屏看细节

## 附录 III · "Coyote Time" 等 Game Feel 技巧

Day 634 提到 coyote time。这是 game feel 的经典技巧,值得深入。

### Coyote Time

**问题**:玩家从平台边缘走下,1 帧后按跳跃——已经掉下去了,不能跳。

**解决**:Coyote time —— 离开平台 0.1s 内仍可跳。

```rust
const COYOTE_TIME: f32 = 0.1;
let mut last_on_ground: f32 = 0.0;

fn update(player: &mut Player, dt: f32) {
    if is_on_ground(player.pos) {
        last_on_ground = 0.0;
    } else {
        last_on_ground += dt;
    }

    let can_jump = last_on_ground <= COYOTE_TIME;
    if input.jump && can_jump {
        player.vel.y = JUMP_SPEED;
    }
}
```

**为什么叫 coyote**:卡通里 coyote(狼)跑出悬崖不会立刻掉,有 1-2 秒"反应时间"。Coyote time 模拟这个。

### Jump Buffer

**问题**:玩家在落地前 0.1s 按跳跃——落地时按键已结束,不能跳。

**解决**:Jump buffer —— 落地前 0.1s 内按跳跃,缓存,落地立刻跳。

```rust
const JUMP_BUFFER: f32 = 0.1;
let mut jump_pressed_ago: f32 = f32::INFINITY;

fn update(player: &mut Player, dt: f32) {
    if input.jump_just_pressed {
        jump_pressed_ago = 0.0;
    } else {
        jump_pressed_ago += dt;
    }

    if is_on_ground(player.pos) && jump_pressed_ago <= JUMP_BUFFER {
        player.vel.y = JUMP_SPEED;
        jump_pressed_ago = f32::INFINITY;
    }
}
```

### Variable Jump Height

**问题**:跳跃固定高度,无法精细控制。

**解决**:按住跳得高,松开跳得低。

```rust
fn update(player: &mut Player) {
    if input.jump_just_pressed && is_on_ground(player.pos) {
        player.vel.y = JUMP_SPEED;
    }

    // 松开跳跃键 → 立刻减半 Y 速度(短跳)
    if !input.jump_held && player.vel.y > JUMP_SPEED * 0.5 {
        player.vel.y = JUMP_SPEED * 0.5;
    }
}
```

### Apex Hang Time

**问题**:跳跃顶点太短,玩家来不及反应。

**解决**:跳跃顶点附近,重力减半 → 顶点持续更久。

```rust
fn update(player: &mut Player, dt: f32) {
    let gravity = if player.vel.y.abs() < 1.0 {
        GRAVITY * 0.5  // 顶点附近,半重力
    } else {
        GRAVITY
    };
    player.vel.y -= gravity * dt;
}
```

### Air Control

**问题**:空中无法控制,玩家挫败。

**解决**:空中仍可微调方向。

```rust
fn update(player: &mut Player, input: Input, dt: f32) {
    if !is_on_ground(player.pos) {
        // 空中:微调
        let air_control = 0.3;
        let wish_x = (input.d as f32 - input.a as f32) * air_control * AIR_ACCEL * dt;
        player.vel.x += wish_x;
        player.vel.x = player.vel.x.clamp(-MAX_AIR_SPEED, MAX_AIR_SPEED);
    }
}
```

- 加 5 个技巧:跳跃丝滑,玩家感觉"我想跳就跳"
