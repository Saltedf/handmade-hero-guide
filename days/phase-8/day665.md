
# Day 665 · 改变实体打包解包方式

> Day 664 优化了 Entity 存储。今天 Casey 改 **serialization**(序列化)——把 Entity 存到磁盘 / 读出来的方式。新存储分桶了,序列化也要相应优化。

## 0 · 为什么要有这一天

游戏要"存盘"。玩家退出时,所有 Entity 状态写文件;载入时,读回 Entity。这叫 save / load。

老 Entity(单 struct)的序列化简单:`serde::serialize(&entity)`,serde 自动处理。

新 Entity(分桶 + tagged union)需要:

- 把每个桶单独序列化(players Vec 单独,enemies Vec 单独)
- 维护 EntityId 跨会话一致(存 id,加载时重建 id_to_index 索引)
- 处理版本(老存档可能不兼容新代码)

今天 Casey 改序列化,适应新存储。

心理锚点:看完今天,你能:

- 设计分桶序列化
- 处理 EntityId 持久化
- 实现版本兼容

## 1 · Casey 今天做了什么

1. 给每个 XxxData struct 加 `Serialize / Deserialize`
2. 给每个 TypedStorage 加 `serialize / deserialize`

## 2 · 心智模型

### 类比:搬家打包

搬家时你不会把所有东西堆一箱——易碎的玻璃杯一箱,书一箱,衣服一箱。每个箱子标签清晰,到新家按箱拆。

游戏存档同构——每桶 Entity 单独打包,加载时按桶解包。

### Serde 框架

Rust 的 serde 是序列化标准。`#[derive(Serialize, Deserialize)]` 自动给 struct 加序列化能力。

```rust
#[derive(Serialize, Deserialize)]
struct PlayerData {
    pos: Vec3,
    hp: f32,
    inventory: Vec<Item>,
}
```

`serde_json::to_string(&data)` 转 JSON,`bincode::serialize(&data)` 转二进制。

### 分桶序列化

```rust
#[derive(Serialize, Deserialize)]
struct SaveFile {
    version: u32,
    players: Vec<(EntityId, PlayerData)>,
    enemies: Vec<(EntityId, EnemyData)>,
    treasures: Vec<(EntityId, TreasureData)>,
    // ...
}

fn save(world: &World) -> SaveFile {
    SaveFile {
        version: 1,
        players: world.players.iter().map(|(id, p)| (*id, p.clone())).collect(),
        enemies: world.enemies.iter().map(|(id, e)| (*id, e.clone())).collect(),
        // ...
    }
}

fn load(file: SaveFile) -> World {
    let mut world = World::new();
    for (id, p) in file.players {
        world.players.insert(id, p);
    }
    for (id, e) in file.enemies {
        world.enemies.insert(id, e);
    }
    // ...
    world
}
```

每个桶单独序列化,加载时按桶插入。`EntityId` 跨会话保留——加载后玩家 id 仍是原来的。

### 处理 dead slot

TypedStorage 有 generation 和 dead slot(被删除但 slot 还在)。序列化时**跳过 dead slot**——不浪费空间。

```rust
impl<T: Serialize> Serialize for TypedStorage<T> {
    fn serialize<S: Serializer>(&self, s: S) -> Result<S::Ok, S::Error> {
        let active: Vec<_> = self.iter().collect(); // iter 已经跳过 dead
        active.serialize(s)
    }
}
```

### 版本兼容

老存档可能不兼容新代码——加字段后,老存档反序列化失败。

解法:

```rust
#[derive(Serialize, Deserialize)]
struct SaveFile {
    version: u32,
    #[serde(flatten)]
    data: SaveData,
}

#[derive(Serialize, Deserialize)]
enum SaveData {
    V1(SaveDataV1),
    V2(SaveDataV2),
}
```

加载时 match version,调用对应迁移函数。

Casey 简化:只支持当前版本。老存档报错。

### 玩家数据 vs 世界数据

游戏状态分两部分:

- **玩家数据**:玩家进度(等级、装备)——存玩家本地
- **世界数据**:关卡、敌人位置——存世界

两者可以分离。玩家从 level 1 到 level 2,level 1 世界数据丢弃,加载 level 2;玩家数据保留。

Casey 选**整体存档**(player + world 一起),简单。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏序列化的设计模式:

- **checkpoint**:特定点存档,玩家死亡回到 checkpoint
- **autosave**:每隔 N 分钟自动存,防丢失
- **save slots**:多存档(玩家 1 / 玩家 2 各一份)
- **cloud sync**:Steam Cloud 同步存档到云端

每个都需要可靠的序列化。

### 3.2 · 图形学视角

图形里序列化:

- **3D 模型**:glTF / OBJ 格式,几何 + 材质 + 动画
- **texture**:KTX / DDS 格式,GPU 友好
- **shader**:SPIR-V 中间格式,跨平台
- **scene**:USD / FBX,场景图

每个都是"复杂数据 → 文件"。

### 3.3 · Linux 系统编程视角

Linux 的序列化:

- **进程 state**:core dump(ELF 格式),debugger 加载
- **VM snapshot**:KVM / QEMU 把 VM 状态 dump 到文件
- **CRIU**:Checkpoint/Restore In Userspace,容器热迁移

每个都是"运行时状态 → 文件 → 重建状态"。

### 3.4 · Rust 生态视角

Rust 序列化生态:

- `serde`:框架,几乎所有 Rust 库依赖它
- `bincode`:二进制,快,小,但只在 Rust 间用
- `serde_json`:JSON,跨语言
- `rmp-serde`:MessagePack,跨语言 + 紧凑
- `postcard`:no_std + 嵌入式友好
- `ciborium`:CBOR,IETF 标准

```rust
#[derive(Serialize, Deserialize)]
struct SaveFile {
    version: u32,
    #[serde(with = "time_compat")]
    timestamp: u64,
    data: WorldData,
}
```

`#[serde(with = ...)]` 自定义序列化,处理特殊类型(如时间)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 generational index 的 generation 不存到存档?

**参考解答**:generation 是为了"检测旧 ref 是否失效"——存档时,所有 dead slot 不存,加载后 generation 从 0 开始。这是"压缩"——存档里只有活的 Entity,加载后重建索引,generation 信息不丢失(因为没有"旧 ref 跨 session"),省了存储空间。

### Lv2 · 动手实践

**题**:实现 §2 的 SaveFile + save + load,测试往返(round-trip)。

**参考解答**:

```rust
use serde::{Serialize, Deserialize};
use glam::Vec3;

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
struct EntityId(u64);

#[derive(Clone, Debug, Serialize, Deserialize)]
struct PlayerData { pos: Vec3, hp: f32, inventory: Vec<String> }

#[derive(Clone, Debug, Serialize, Deserialize)]
struct EnemyData { pos: Vec3, hp: f32, ai_state: u8 }

#[derive(Clone, Debug, Serialize, Deserialize)]
struct SaveFile {
    version: u32,
    players: Vec<(EntityId, PlayerData)>,
    enemies: Vec<(EntityId, EnemyData)>,
}

struct World {
    players: Vec<(EntityId, PlayerData)>,
    enemies: Vec<(EntityId, EnemyData)>,
    next_id: u64,
}

impl World {
    fn new() -> Self { Self { players: Vec::new(), enemies: Vec::new(), next_id: 1 } }
    fn new_id(&mut self) -> EntityId {
        let id = EntityId(self.next_id);
        self.next_id += 1;
        id
    }
    fn save(&self) -> SaveFile {
        SaveFile {
            version: 1,
            players: self.players.clone(),
            enemies: self.enemies.clone(),
        }
    }
    fn load(file: SaveFile) -> Self {
        let max_id = file.players.iter().chain(file.enemies.iter())
            .map(|(id, _)| id.0).max().unwrap_or(0);
        Self {
            players: file.players,
            enemies: file.enemies,
            next_id: max_id + 1,
        }
    }
}

fn main() {
    let mut world = World::new();
    let p1 = world.new_id();
    world.players.push((p1, PlayerData {
        pos: Vec3::new(5.0, 0.0, 5.0), hp: 100.0,
        inventory: vec!["sword".into(), "potion".into()],
    }));
    let e1 = world.new_id();
    let e2 = world.new_id();
    world.enemies.push((e1, EnemyData { pos: Vec3::new(10.0, 0.0, 10.0), hp: 30.0, ai_state: 0 }));
    world.enemies.push((e2, EnemyData { pos: Vec3::new(15.0, 0.0, 15.0), hp: 30.0, ai_state: 1 }));

    let save = world.save();
    let json = serde_json::to_string_pretty(&save).unwrap();
    println!("Serialized (JSON, {} chars):", json.len());
    println!("{}", json);

    let loaded: SaveFile = serde_json::from_str(&json).unwrap();
    let new_world = World::load(loaded);

    println!("\nLoaded back:");
    println!("  Players: {}", new_world.players.len());
    println!("  Enemies: {}", new_world.enemies.len());
    println!("  Next id: {}", new_world.next_id);

    // 验证往返
    assert_eq!(world.players.len(), new_world.players.len());
    assert_eq!(world.enemies.len(), new_world.enemies.len());
    println!("\nRound-trip OK!");
}
```

## 8 · Rust / Arch 落地代码

完整存档系统:

```rust
// Cargo.toml:
// [dependencies]
// serde = { version = "1", features = ["derive"] }
// serde_json = "1"
// bincode = "1"
// glam = { version = "0.29", features = ["serde"] }

use serde::{Serialize, Deserialize};
use glam::Vec3;
use std::collections::HashMap;
use std::fs::File;
use std::io::{BufReader, BufWriter};

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
struct EntityId(u64);

#[derive(Clone, Debug, Serialize, Deserialize)]
struct PlayerData {
    pos: Vec3,
    vel: Vec3,
    hp: f32,
    inventory: Vec<String>,
}

#[derive(Clone, Debug, Serialize, Deserialize)]
struct EnemyData {
    pos: Vec3,
    vel: Vec3,
    hp: f32,
    ai_state: u8,
    damage: f32,
}

#[derive(Clone, Debug, Serialize, Deserialize)]
struct TreasureData {
    pos: Vec3,
    gold: u32,
    opened: bool,
}

const SAVE_VERSION: u32 = 1;

#[derive(Serialize, Deserialize)]
struct SaveFile {
    version: u32,
    next_id: u64,
    players: Vec<(EntityId, PlayerData)>,
    enemies: Vec<(EntityId, EnemyData)>,
    treasures: Vec<(EntityId, TreasureData)>,
}

struct World {
    players: HashMap<EntityId, PlayerData>,
    enemies: HashMap<EntityId, EnemyData>,
    treasures: HashMap<EntityId, TreasureData>,
    next_id: u64,
}

impl World {
    fn new() -> Self {
        Self {
            players: HashMap::new(),
            enemies: HashMap::new(),
            treasures: HashMap::new(),
            next_id: 1,
        }
    }
    fn new_id(&mut self) -> EntityId {
        let id = EntityId(self.next_id);
        self.next_id += 1;
        id
    }
    fn spawn_player(&mut self, pos: Vec3) -> EntityId {
        let id = self.new_id();
        self.players.insert(id, PlayerData {
            pos, vel: Vec3::ZERO, hp: 100.0,
            inventory: vec!["starter_sword".into()],
        });
        id
    }
    fn spawn_enemy(&mut self, pos: Vec3) -> EntityId {
        let id = self.new_id();
        self.enemies.insert(id, EnemyData {
            pos, vel: Vec3::ZERO, hp: 30.0, ai_state: 0, damage: 5.0,
        });
        id
    }
    fn save_to_file(&self, path: &str) -> std::io::Result<()> {
        let file = SaveFile {
            version: SAVE_VERSION,
            next_id: self.next_id,
            players: self.players.iter().map(|(k, v)| (*k, v.clone())).collect(),
            enemies: self.enemies.iter().map(|(k, v)| (*k, v.clone())).collect(),
            treasures: self.treasures.iter().map(|(k, v)| (*k, v.clone())).collect(),
        };
        let f = File::create(path)?;
        let mut w = BufWriter::new(f);
        bincode::serialize_into(&mut w, &file)
            .map_err(|e| std::io::Error::new(std::io::ErrorKind::Other, e))?;
        Ok(())
    }
    fn load_from_file(path: &str) -> std::io::Result<Self> {
        let f = File::open(path)?;
        let mut r = BufReader::new(f);
        let file: SaveFile = bincode::deserialize_from(&mut r)
            .map_err(|e| std::io::Error::new(std::io::ErrorKind::Other, e))?;
        if file.version != SAVE_VERSION {
            return Err(std::io::Error::new(
                std::io::ErrorKind::InvalidData,
                format!("Save version {} != current {}", file.version, SAVE_VERSION),
            ));
        }
        Ok(Self {
            players: file.players.into_iter().collect(),
            enemies: file.enemies.into_iter().collect(),
            treasures: file.treasures.into_iter().collect(),
            next_id: file.next_id,
        })
    }
}

fn main() {
    let mut world = World::new();
    let _p = world.spawn_player(Vec3::new(5.0, 0.0, 5.0));
    let _e1 = world.spawn_enemy(Vec3::new(10.0, 0.0, 10.0));
    let _e2 = world.spawn_enemy(Vec3::new(15.0, 0.0, 15.0));
    println!("Created world: {} players, {} enemies",
        world.players.len(), world.enemies.len());

    let path = "/tmp/hh_save.bin";
    world.save_to_file(path).unwrap();
    println!("Saved to {}", path);

    let loaded = World::load_from_file(path).unwrap();
    println!("Loaded: {} players, {} enemies",
        loaded.players.len(), loaded.enemies.len());
    println!("Next id: {}", loaded.next_id);

    // 验证数据
    assert_eq!(world.players.len(), loaded.players.len());
    assert_eq!(world.enemies.len(), loaded.enemies.len());
    assert_eq!(world.next_id, loaded.next_id);
    println!("Round-trip verified!");

    // JSON 选项
    let json_save = SaveFile {
        version: SAVE_VERSION,
        next_id: world.next_id,
        players: world.players.iter().map(|(k, v)| (*k, v.clone())).collect(),
        enemies: world.enemies.iter().map(|(k, v)| (*k, v.clone())).collect(),
        treasures: world.treasures.iter().map(|(k, v)| (*k, v.clone())).collect(),
    };
    let json = serde_json::to_string_pretty(&json_save).unwrap();
    println!("\nJSON save ({} chars):", json.len());
    println!("{}", &json[..200.min(json.len())]);
}
```

## 10 · 工程反思

Day 665 传达的核心工程教训:**序列化是软件工程的"隐形基础设施"**。

新手以为"序列化 = 保存数据",资深工程师知道序列化是**软件集成的基础**——savegame、网络协议、配置加载、IPC 通信、数据库存储、cache、message queue、API contract——全部需要序列化。

每个使用场景都有自己的需求:

- **savegame**:人类可读 + 版本兼容(JSON / TOML)
- **网络**:紧凑 + 快(binary / protobuf)
- **配置**:人类可写(TOML / YAML)
- **cache**:任意格式,但要快(bincode)
- **IPC**:跨语言(JSON / msgpack)

Rust 的 serde 库统一所有格式——`#[derive(Serialize, Deserialize)]`,一行代码,所有格式支持。这是 Rust 工程能力的杀手锏。

**为什么 serde 这么强?**

serde 用 trait + derive 宏自动生成代码:

```rust
#[derive(Serialize, Deserialize)]
struct Player {
    name: String,
    hp: i32,
    pos: Vec3,
}
// 自动支持 JSON / TOML / bincode / msgpack / ...
```

无需手写"to_json" / "from_json"。这是 Rust 类型系统的胜利。

**序列化的 trade-off**:

| 格式 | 大小 | 速度 | 人类可读 | 版本兼容 |
|---|---|---|---|---|
| JSON | 大 | 慢 | 是 | 好 |
| TOML | 大 | 慢 | 是(配置友好) | 好 |
| YAML | 中 | 慢 | 是 | 好(但复杂) |
| bincode | 小 | 快 | 否 | 差 |
| MessagePack | 小 | 快 | 否 | 好 |
| Protobuf | 小 | 快 | 否 | 好(schema) |
| CBOR | 小 | 中 | 否 | 好 |

每种 trade-off 不同。游戏 savegame 用 JSON / TOML(玩家可编辑),网络用 bincode(快),配置用 TOML(人类可写)。

**第二条教训**:**版本兼容是序列化的难题**。

游戏更新后,旧 savegame 还能加载吗?如果结构改了(`Player.name: String` → `name + display_name`),旧 savegame 失败。

工业解法:

- **Optional fields**:`#[serde(default)]`,旧数据缺字段用默认值
- **Migration script**:旧版本转新版本(运行一次性)
- **Schema versioning**:`version: u32` 字段,根据版本走不同解析
- **Protobuf / FlatBuffers**:天生支持版本演化

资深工程师设计序列化时**预先考虑版本**。Casey 在 HH 简化,但工业级是工程难点。

**第三条教训**:**序列化失败 = 灾难**。

玩家玩 100 小时,savegame 损坏 = 失去所有进度 = 退游 + 差评。所以工业级 savegame 系统:

- **Atomic write**:先写到临时文件,fsync 后 rename(防写到一半断电)
- **Multiple slots**:多存档点,一个损坏还有其他
- **Cloud sync**:自动备份到云,本地损坏可恢复
- **Validation**:加载时校验,失败 fallback 到 last good

每个机制都重要。Casey 在 HH 演示最简版本,工业级是数十人月工程。

**迁移到其他领域**:

"序列化"思路在多处通用:

- **数据库**:row format / WAL
- **网络**:protocol buffer / Thrift / Cap'n Proto
- **Web**:JSON / GraphQL schema
- **配置**:YAML / TOML / INI / XML
- **API**:OpenAPI / gRPC

每个领域都有"对象 → bytes → 对象"的需求。Casey 在 HH 演示的是游戏 savegame 版本。

## N0 • 深度教学补充

### 核心概念重新梳理

Day 665 涉及的核心概念需要在多个层次上理解:

**第一层:直观理解**

新手第一次接触概念,需要建立直觉。例如 voxel collision 是"虚拟物体不能穿过虚拟墙"——这个直觉每个人都能从现实经验获得。

**第二层:数学理解**

把直觉形式化。collision = "两个几何体的体积有交集"。对于 AABB,这等价于"三轴投影都重叠"。

**第三层:工程理解**

数学正确不等于工程实现正确。要考虑:

- 浮点精度边界
- 性能(每帧 N 个查询)
- 内存(数据结构紧凑)
- 边角 case(无穷大、NaN、负数)

**第四层:工业理解**

工业级要再加:

- 多线程安全
- SIMD 优化
- 网络同步(多人游戏)
- 跨平台(Windows/Mac/Linux/Mobile)
- 可访问性(色盲友好)
- 反作弊

每层理解都让代码更鲁棒。资深工程师在所有层次同时思考。

### 实际工程的细节

工业代码 80% 是"边角 case 处理",20% 是"核心算法"。Casey 在 HH 演示核心,工业代码加大量边角处理。

**边角 case 类型**:

1. 空输入(空 Vec、null pointer)
2. 极端输入(NaN、无穷大、超大数)
3. 并发竞争(多线程同时访问)
4. 资源不足(内存满、磁盘满)
5. 网络异常(超时、断连、包丢失)
6. 版本不兼容(老配置 / 新代码)
7. 权限错误(只读文件、无网络)
8. 用户误操作(连点、撤销重做)

每个 case 都要单独处理。这是工业代码 50%+ 行数的原因。

### 优化思路

性能优化有顺序:

1. **算法**:O(N²) → O(N log N),最大提升
2. **数据结构**:Vec → HashMap / BTreeMap,常数提升
3. **Cache**:AoS → SoA,cache 命中提升
4. **SIMD**:4-16 元素并行,巨大常数提升
5. **GPU**:数千核并行,极致性能
6. **分布式**:多机器,无限扩展

每级提升都需要更复杂的代码。先优化低级,够用再升级。

- **完成 > 完美**:能跑 > 能优化
- **持续学习**:技术永远在演化

这些哲学跨技术领域通用。学完 HH,你不只会写游戏,你**理解工程**。这是 HH 最大的价值。

### Rust 视角

Day 665 用 C 写,但 Rust 版本会更安全 / 更高效:

- **所有权**:消除 use-after-free / double-free
- **borrow check**:消除 data race
- **match exhaustive**:case 漏写编译错
- **Result<T, E>**:错误显式处理
- **no null**:Option<T> 强制 null 检查
- **fearless concurrency**:多线程安全

每条都让代码更鲁棒。Rust 是游戏开发的新趋势(bevy / wgpu / rend3),学习 Rust 让你未来 10 年受益。
