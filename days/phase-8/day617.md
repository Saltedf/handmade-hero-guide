# Day 617 · 分析漫反射模糊

> 优化告一段落(DDA + 半分辨率把 hot path 砍到 5ms)。但 Casey 发现间接光在场景里看起来"有点糊"——角落的阴影边缘不像直接光那么锐利。今天的主题不是优化,是**分析**:为什么 diffuse 间接光看起来糊?这是 bug 还是 feature?Casey 用一系列可视化对比实验,**证明这是 feature**——它符合物理(间接光本来就应该比直接光柔和)。

## 0 · 为什么要有这一天

经过 Day 611-616 的 raycast 优化,性能从 9ms 降到 5ms,Casey 终于有时间停下来观察效果。他注意到一个现象:**间接光(diffuse bounce)投射出的阴影边缘非常模糊,而直接光的阴影边缘锐利**。

第一反应可能是:这是不是 bug?是不是 DDA 步进或半分辨率引入的精度问题?要不要排查?

但 Casey 没急着写代码,**先做物理推导**:

1. **直接光**:从光源到表面的光线**没被遮挡**的部分是被照亮的,**被遮挡**的部分是阴影。这是**二值**——一条光线要么到、要么不到。所以阴影边缘锐利
2. **间接光(diffuse bounce)**:表面某点 P 接收的光来自**整个上半球方向**的间接光(被其他表面反射回来的)。要"算阴影",就要看 P 的上半球**有多少方向被遮挡**。这不是二值——是**软阴影**,从"完全可见"(0% 遮挡)到"完全遮挡"(100% 遮挡)渐变。所以阴影边缘模糊

**这是 feature,不是 bug**。间接光的"模糊"是物理正确的行为——这就是**软阴影**(soft shadow)的本质。

但 Casey 仍然要**验证**这个理论,因为:
- 看到的模糊程度可能"过度"(理论上应该是 5% 软,实际看起来 50% 软,那就是 bug)
- 想量化"模糊半径",看是不是合理
- 想知道半分辨率引入了多少"额外模糊"

今天的主题是**性能优化完成后的科学验证**——光跑得快不够,还要确认结果对。

**心理锚点**:看完这集,你能:
- 区分"软阴影"(物理正确)和"模糊 bug"(数值错误)
- 用可视化对比实验量化模糊程度
- 在 profile 之外,用"科学方法"验证渲染效果

## 2 · 心智模型

### 类比:直射灯 vs 漫射灯

打开你房间的两种灯:

- **直射灯**(spotlight,聚光灯):灯泡小,光线集中,投射的阴影边缘锐利。因为光源可以近似为"一个点",从物体边缘到地面阴影的过渡是突然的
- **漫射灯**(softbox,柔光箱):灯泡外面包了大的柔光罩,光线从大面积区域发出。阴影边缘软。因为光源是一个**面**,物体边缘不同位置遮挡不同方向的光

游戏里的"直接光"和"间接光"完全一样:

- **直接光**(太阳/点光源):近似点光源,阴影边缘锐利
- **间接光**(diffuse bounce):每个表面都向其法线方向的半球反射光,**等效于一个面光源**。阴影边缘必然软

**关键洞察**:**模糊是物理正确的间接光特征**。一个"完美的"diffuse GI 实现应该自然产生软阴影。如果你的 diffuse GI 投射出锐利阴影,**那是 bug**(可能是只采了几个固定方向,没采整个半球)。

### 严谨推导:为什么 diffuse GI 必然模糊

#### 2.1 Rendering Equation 回顾

表面点 P 的出射光:

```
L_out(P, ω_out) = L_emit(P) + ∫ BRDF(P, ω_in, ω_out) × L_in(P, ω_in) × cos(θ_in) dω_in
```

- `L_emit` — 自发光(P 是光源时)
- `BRDF` — 双向反射分布函数,diffuse 时是常数 `albedo / π`
- `L_in(P, ω_in)` — 从 ω_in 方向入射到 P 的光
- `cos(θ_in)` — N · ω_in,入射方向的投影
- `∫ ... dω_in` — 对整个上半球积分

**直接光**:`L_in` 只有"指向光源的方向"非零,其他方向都是 0。积分退化成有限个 delta 函数,结果是点乘 `N·L`(锐利)。

**间接光**:`L_in` 在整个半球都有非零值(其他表面反射回来的光)。积分是真的"积分",结果是平均的、软的。

#### 2.2 半球积分的"低通滤波"效应

把积分看成**对方向的低通滤波**(low-pass filter):

- 直接光:只取一个方向,相当于 **delta 函数**(全频带,锐利)
- 间接光:对整个半球平均,相当于 **box filter**(低频,模糊)

**几何上**:P 点的间接光来自 P 上方所有可见的方向。如果某个方向被柱子遮挡,但柱子只挡了 P 上半球的一小部分,P 仍然接收到大部分间接光——所以阴影是"软的"(亮度从 100% 缓慢降到 70% 而不是 0%)。

#### 2.3 模糊半径公式

设柱子高度 `h`,柱子离地面 `d`。点 P 在柱子旁边,距离柱子水平距离 `x`。P 点的"间接光可见性"取决于柱子遮挡 P 上半球多少角度。

**简单几何**(2D 截面):柱子顶端在 P 看的仰角 `α = atan(h/x)`。柱子遮挡 P 上半球的"角度范围"是 `α`(粗略)。

- `x = 0`(P 在柱子正下方):仰角 90°,柱子完全遮挡上半球的一边,间接光几乎为 0(深阴影)
- `x = h`:仰角 45°,柱子遮挡半球的 1/4,间接光降到 ~75%(中阴影)
- `x = ∞`:仰角 0°,无遮挡,间接光 100%

所以**模糊半径**(从深阴影到无阴影的过渡距离)是 `~h`(柱子高度)。这就是物理上的"软阴影半径"。

#### 2.4 量化验证

Casey 在场景里放一个高度 `h = 2` 的柱子,把"间接光贡献"可视化。沿柱子底部水平方向采样:

```
距离 x:    0    0.5    1    1.5    2    3    5
间接光强:  0.1  0.3    0.5  0.7    0.85 0.95 1.0
```

模糊过渡从 `x=0` 到 `x≈h=2` 处亮度恢复到 85%——**符合理论**。这是物理正确的软阴影。

#### 2.5 半分辨率的额外模糊

Day 616 的半分辨率引入了**额外的 1 体素模糊**(因为粗网格命中点是 2×2×2 范围的代表)。Casey 测了一下:

- 全分辨率:模糊半径 = 2.0(纯物理)
- 半分辨率:模糊半径 = 2.5(额外 0.5 来自粗网格)

**结论**:半分辨率引入的模糊在 acceptable 范围内(< 25% 额外)。这是合理的 trade-off——20% 性能换 25% 模糊。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**软阴影 vs 硬阴影在游戏里的取舍**:

- **AAA 游戏**:用 PCSS(Percentage-Closer Soft Shadows)或 ray tracing 计算真实的软阴影,根据遮挡距离动态调整模糊半径
- **Indie 游戏**:用 PCF(Percentage-Closer Filtering)在 shadow map 上做模糊,固定模糊半径
- **HH**:由 diffuse GI 自然产生软阴影,无需额外算法

**坑**:

- **半分辨率引入的"漏光"**:细柱子(1 体素宽)在粗网格里消失,间接光直接穿过,产生"光线穿透柱子"的 bug。Casey 在 Day 616 已经注意,权衡是接受(性能优先)
- **噪点**:Monte Carlo 间接光采样有 noise,需要多帧累积(TAA)或足够多样本。Casey 用 octahedral filter + 多个方向,降噪效果一般
- **颜色 bleeding**:红色墙边的间接光会带红色(物理正确),但有时看起来"脏"。这是 color bleeding,正确性毋庸置疑,美术可能不喜欢

### 3.2 · 🎨 图形学视角

**软阴影的算法谱**:

| 算法 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| PCF | shadow map + 邻域 filter | 简单,快 | 固定模糊半径,物理不准 |
| PCSS | PCF + 动态估算模糊半径 | 物理更准 | 慢 |
| Ray tracing | 直接投射多条光线 | 真实物理 | 慢(RTX 加速) |
| Voxel cone tracing | 体素 + cone | 实时 GI 用 | 模糊(Crassin 2011) |
| Diffuse GI(本日) | 全半球积分 | 自然软阴影 | 需要足够样本 |

**HH 的位置**:Diffuse GI 投射出软阴影是**积分的副产品**——本来积分是为了算"间接光强度",但积分本身就是低通滤波,所以阴影软。这是物理的"免费午餐"。

#### 软阴影的物理本质

太阳实际是面光源(直径 ~1.4M km,但从地球看角直径 ~0.5°)。日全食时月球的阴影边缘是"半影"(penumbra)——亮到暗渐变。这就是软阴影。

游戏里的"点光源"是抽象——实际没有点光源,所有光源都有面积。所以**所有物理正确的阴影都是软的**。游戏为了性能简化成硬阴影,这是"工程妥协",不是物理。

```rust
    let mut in_dark = false;
    let mut transition_start = 0;
    let mut transition_end = 0;
    for x in x_start..image.width {
        let b = image.brightness(x, y);
        if b < 50.0 && !in_dark {

            transition_start = x;
        } else if b > 200.0 && in_dark {

            break;
        }
    }

}
```

## 5 · 对照与变奏

### 同一现象在不同领域的解释

**现象**:积分导致模糊(平滑)。

| 领域 | 表现 | 数学 |
|---|---|---|
| 渲染(本日) | 软阴影 | 半球积分 |
| 图像处理 | 抗锯齿 | box filter / Gaussian |
| 信号处理 | 低通滤波 | 卷积 |
| 数学 | 模糊化算子 | 卷积核 |
| 量子力学 | 测不准原理 | Fourier 对偶 |
| 概率论 | 期望 | 积分 |

数学家会说"这些都是卷积的不同实例"。工程师会说"积分让尖锐的东西变钝"。

### 何时模糊是 bug

虽然"diffuse GI 必然模糊"是物理正确的,但下面这些情况模糊是 bug:

1. **采样数太少**:Monte Carlo 噪声呈现为"斑点模糊",这是数值误差,不是物理
2. **半分辨率过度合并**:1 体素柱子消失,光线穿透——这是数据简化过度
3. **过早的 spatial filter**:在低样本数下做空间 filter,模糊半径被放大
4. **错误的 BRDF**:把 diffuse 当 specular 处理,或反之

Casey 逐一检查这些,确认 Day 616 引入的"额外模糊"在合理范围内。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:"直接光投射硬阴影,间接光投射软阴影"——为什么?给出基于 rendering equation 的论证。

**参考解答**:

直接光 `L_in` 在 P 上半球只有"指向光源方向"非零,其他方向为零。积分退化为 delta 函数求值 → `L_direct = N·L`(标量,二值遮挡,硬阴影)。

间接光 `L_in` 在整个半球都有非零值(其他表面反射回来的光)。积分是真正的半球积分 → 平均效应 → 软阴影。

**直觉**:直接光是"窄光束",遮挡二值;间接光是"宽光束",遮挡渐变。

### Lv2 · 动手实践

**参考解答**:

```rust
#[derive(Copy, Clone)]
struct Vec2 { x: f32, y: f32 }
impl Vec2 {
    fn new(x: f32, y: f32) -> Self { Self { x, y } }
    fn sub(self, o: Self) -> Self { Self::new(self.x - o.x, self.y - o.y) }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y }
    fn length(self) -> f32 { self.dot(self).sqrt() }
    fn normalized(self) -> Self {
        let l = self.length();
        if l > 1e-9 { Self::new(self.x/l, self.y/l) } else { Self::new(0.0, 0.0) }
    }
}

// 2D 光线-线段相交
fn ray_segment_intersects(ro: Vec2, rd: Vec2, a: Vec2, b: Vec2) -> bool {
    let v1 = ro.sub(a);
    let v2 = b.sub(a);
    let v3 = Vec2::new(-rd.y, rd.x);
    let dot = v3.dot(v2);
    if dot.abs() < 1e-9 { return false; }
    let t1 = (v2.x * v1.y - v2.y * v1.x) / dot;
    let t2 = v1.dot(v3) / dot;
    t1 >= 0.0 && t2 >= 0.0 && t2 <= 1.0
}

fn shadow_factor(p: Vec2, light_pos: Vec2, light_w: f32, column_x: f32, column_h: f32) -> f32 {
    let column_top = Vec2::new(column_x, column_h);
    let column_bottom = Vec2::new(column_x, 0.0);
    let samples = 32;
    let mut visible = 0;
    for i in 0..samples {
        let t = i as f32 / (samples - 1) as f32;
        let lx = light_pos.x + (t - 0.5) * light_w;
        let sample_pos = Vec2::new(lx, light_pos.y);
        let dir = sample_pos.sub(p).normalized();
        if !ray_segment_intersects(p, dir, column_bottom, column_top) {
            visible += 1;
        }
    }
    visible as f32 / samples as f32
}

fn main() {
    let light_pos = Vec2::new(5.0, 10.0);
    let light_w = 4.0;  // 面光源宽度
    let column_x = 3.0;
    let column_h = 2.0;  // 模糊半径应该约等于这个

    println!("x\tbrightness\tASCII");
    let mut x = -2.0;
    while x <= 8.0 {
        let p = Vec2::new(x, 0.0);
        let s = shadow_factor(p, light_pos, light_w, column_x, column_h);
        let bars = (s * 40.0) as usize;
        let ascii: String = std::iter::repeat('#').take(bars).collect();
        println!("{:.1}\t{:.2}\t{}", x, s, ascii);
        x += 0.5;
    }
}
```

**预期**:在 `x = 3`(柱子位置)附近亮度最低(深阴影),两侧渐变到 1.0(全亮)。过渡宽度约 `column_h = 2.0`,符合理论。

```rust
// Cargo.toml: 空,纯 std

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn add(self, o: Self) -> Self { Self::new(self.x+o.x, self.y+o.y, self.z+o.z) }
    fn sub(self, o: Self) -> Self { Self::new(self.x-o.x, self.y-o.y, self.z-o.z) }
    fn scale(self, k: f32) -> Self { Self::new(self.x*k, self.y*k, self.z*k) }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
    fn length(self) -> f32 { self.dot(self).sqrt() }
    fn normalized(self) -> Self {
        let l = self.length();
        if l > 1e-9 { self.scale(1.0/l) } else { Self::new(0.0, 0.0, 0.0) }
    }
}

// 量化模糊半径:取一张亮度图,沿水平线找亮度过渡
fn measure_blur_radius(brightness: &[f32], width: usize, y: usize) -> f32 {
    let row_start = y * width;
    let mut first_dark = None;
    let mut first_bright = None;
    for x in 0..width {
        let b = brightness[row_start + x];
        if b < 0.2 && first_dark.is_none() {
            first_dark = Some(x);
        } else if b > 0.8 && first_dark.is_some() && first_bright.is_none() {
            first_bright = Some(x);
            break;
        }
    }
    match (first_dark, first_bright) {
        (Some(a), Some(b)) => (b - a) as f32,
        _ => -1.0,
    }
}

// 模拟软阴影:点 P 接收来自天空半球的光,被柱子遮挡
fn soft_shadow_factor(p: Vec3, column_pos: Vec3, column_height: f32, samples: usize) -> f32 {
    let mut visible = 0;
    for i in 0..samples {
        let theta = std::f32::consts::FRAC_PI_2 * (i as f32 + 0.5) / samples as f32;
        let phi = 0.0;  // 简化:固定方位
        let dir = Vec3::new(theta.cos() * phi.cos(), theta.sin(), theta.cos() * phi.sin());
        // 检查柱子是否遮挡这条光线
        // (简化版,只看仰角)
        let to_column = column_pos.sub(p);
        let column_angle = to_column.y.atan2(to_column.length());
        if column_angle > theta {
            // 这条光线被柱子遮挡
            continue;
        } else {
            visible += 1;
        }
    }
    visible as f32 / samples as f32
}

fn main() {
    // 场景:柱子在原点,高度 2
    let column_pos = Vec3::new(0.0, 0.0, 0.0);
    let column_height = 2.0_f32;

    // 沿水平线采样
    let mut brightness: Vec<f32> = Vec::new();
    let width = 50;
    for x in 0..width {
        let px = (x as f32 - 25.0) * 0.2;  // -5 到 5
        let p = Vec3::new(px, 0.0, 0.0);
        let s = soft_shadow_factor(p, column_pos, column_height, 32);
        brightness.push(s);
    }

    // 打印 ASCII 可视化
    println!("=== Soft shadow profile ===");
    for (x, b) in brightness.iter().enumerate() {
        let bars = (*b * 40.0) as usize;
        let ascii: String = std::iter::repeat('#').take(bars).collect();
        println!("x={:>5.2}  {:>5.2}  {}", (x as f32 - 25.0) * 0.2, b, ascii);
    }

    // 量化模糊半径
    let radius = measure_blur_radius(&brightness, width, 0);
    println!("\nMeasured blur radius: {:.2} (理论值 ~{:.2})", radius * 0.2, column_height);
}
```

## 附录 · Day 617 的科学方法

今天的本质是**科学方法**(scientific method)在游戏开发里的应用:

1. **观察**:间接光看起来糊
2. **假设**:可能是 bug,也可能是物理正确
3. **理论推导**:从 rendering equation 推出"积分必然模糊"
4. **实验验证**:用可视化 + 量化测量,对比理论与实测
5. **结论**:模糊半径符合理论 → feature,不是 bug

这套方法是工程师 vs 码农的分水岭。**码农看到现象就改代码,工程师先理解现象**。Casey 在 Day 617 花了 1 小时纯思考 + 验证,没写一行生产代码,但产出价值远超 1 小时的"优化代码"——他**避免了 6-12 个月的"修复 feature"陷阱**(很多团队会反复尝试"修复"软阴影,反而引入真 bug)。

### 历史教训:软阴影的"假 bug"

游戏行业有大量"开发者以为是 bug 但其实是物理正确"的案例:

- **Doom 3 的硬阴影**:id Tech 4 用 stencil shadow volume,只支持硬阴影。开发者一直不满意,后来加 PCF filter 模拟软阴影。**实际是补丁**,不是物理正确
- **Crysis 的 SSAO**:屏幕空间环境光遮蔽,边缘锐利不自然,玩家抱怨"看起来奇怪"。**实际是 SSAO 算法的限制**,不是 bug
- **PBR 流行前的"塑料感"**:游戏角色看起来反光太强,美术觉得是"shader bug"。**实际是 Blinn-Phong + 不正确的 fresnel**,改用 PBR 后消失

教训:**先理解,再修**。否则会陷入"调参数无止境"的怪圈。

### 工程实践:feature vs bug 决策树

当你看到一个"奇怪现象",问自己:

1. **能不能用理论解释**?能 → feature
2. **理论上应该是什么样**?写下来
3. **实测符合理论**?符合 → feature,不符合 → bug
4. **不符合的程度多大**?< 10% → feature(数值误差);> 50% → bug(算法错误)

Casey 的模糊半径实测 2.5,理论 2.0,差异 25% → acceptable(半分辨率引入)。如果实测 5.0,差异 150%,那一定是 bug。

### 今天的认知收获

完成 Day 617 后,你应该建立这些心智模型:

- **半球积分 = 低通滤波 = 软阴影**:这三件事是一回事
- **物理正确的渲染必然模糊**:不模糊反而是 bug(用了点光源近似)
- **科学方法可以避免"假 bug"陷阱**:理解 > 调参
