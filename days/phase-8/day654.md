
# Day 654 · 自发光地砖

> 今天 Casey 给关卡加一个新元素:**自发光地砖**(self-illuminating floor tiles)。某些特殊地砖自己发光(不需要外部光源),照亮周围。这是手游 / RPG 常见设计——"魔法符文"、"传送阵"、"陷阱警告"。

## 0 · 为什么要有这一天

回顾光照系统:

- **直接光**:从一个 explicit 光源位置(灯泡)发出
- **间接光**:光从直接光反弹
- **自发光**:表面本身发光,作为光源

自发光让游戏设计更丰富:

- 解谜游戏:踩到符文触发机关,符文发光提示
- RPG:传送阵用自发光标记
- 动作游戏:陷阱警告用自发光红色
- 沙盒游戏:玩家放火把,周围自发光

自发光在渲染上有两种思路:

1. **PBR emissive material**:在 shader 里,把 emissive 颜色直接加到 fragment 输出,不走 Lambert
2. **当光源**:把自发光 voxel 当作 light source,影响周围 voxel

Casey 选思路 2——把自发光地砖当作一个 area light(面光源),照亮周围 voxel。这样光照表里就有"地砖作为光源"的贡献。

心理锚点:看完今天,你能:

- 实现自发光材质
- 把 voxel 当作 area light 处理
- 区分 emissive material 和 light source 两种概念

## 1 · Casey 今天做了什么

1. 在 voxel type 枚举里加 `SelfIlluminating { color: [f32; 3], intensity: f32 }`
2. 在光表生成时,扫所有 voxel,把自发光 voxel 加入光源列表
3. 自发光地砖作为面光源(不只一个点,而是 voxel 顶面的多个采样点)
4. 渲染时,自发光 voxel 的 fragment 颜色 = `max(Lambert, emissive_color)`,保证视觉上"亮"
5. 测试:踩到符文,周围照亮
6. 加调参:emissive intensity 在 debug overlay 里可调

## 2 · 心智模型

### 类比:夜店 LED 地板

夜店地板有 LED 灯,既是装饰(自己发光)又是照明(照亮周围)。两者兼用。

游戏自发光地砖同构:**自己看起来亮**(渲染时直接 emissive)+ **照亮周围**(作为光源影响其他 voxel)。

### Emissive material vs light source

两个概念要分清:

**Emissive material**(发光材质):渲染时,**这个 voxel 本身的颜色**就是亮色,不走 Lambert 计算。

```glsl
// fragment shader
vec3 color = albedo * lambert + emissive;
// emissive 是材质属性,RGB 颜色,不受光照影响
```

**Light source**(光源):影响**其他 voxel** 的光照计算。

```rust
for each surface:
    for each light_source:
        if visible:
            color += lambert_contribution(light, surface)
```

**两者兼用**(Casey 的自发光地砖):

- 自身渲染:fragment 输出包含 emissive,看起来亮
- 其他 voxel 光照:把自发光 voxel 当 light,照亮邻居

### Area light(面光源)

普通光源是 point light(点光源),只有一个位置。但自发光地砖**占据整个 voxel 表面**——不是一个点,是 1×1 米的正方形。

Area light 比点光源更真实:

- 阴影边缘是**柔和的**(penumbra),不是硬边
- 离 surface 近时光照分布"展开",不是单点

实现:对 area light,采样 N 个点(蒙特卡洛),每个点做 point light 计算,平均。这是 Day 652 stochastic sampling 的应用。

### 自发光 voxel 影响范围

自发光 voxel 的光"射程"取决于:

- emissive intensity(强度)
- 衰减公式(1/(1+d²) 还是别的)
- 阴影(被其他 voxel 挡)

Casey 用 `intensity / (1 + d²)` 衰减,衰减很快——d=2 时强度只剩 1/5,d=5 时只剩 1/26。所以自发光地砖只照亮周围 3-5 米。

### 实现:扫所有 voxel 找自发光

```rust
fn find_emissive_voxels(world: &World) -> Vec<(IVec3, [f32; 3], f32)> {
    let mut result = Vec::new();
    for chunk in world.chunks() {
        for (idx, voxel) in chunk.voxels.iter().enumerate() {
            if let VoxelType::SelfIlluminating { color, intensity } = voxel {
                let coord = chunk.voxel_index_to_world(idx);
                result.push((coord, *color, *intensity));
            }
        }
    }
    result
}
```

把这些 voxel 当作光源,加入光表计算。

### 渲染时的 emissive

```rust
fn render_voxel(voxel_type: &VoxelType, base_light: &[f32; 3]) -> [u8; 3] {
    match voxel_type {
        VoxelType::SelfIlluminating { color, .. } => {
            // emissive 直接加到最终颜色
            let r = (base_light[0] + color[0]).min(1.0);
            let g = (base_light[1] + color[1]).min(1.0);
            let b = (base_light[2] + color[2]).min(1.0);
            [(r * 255.0) as u8, (g * 255.0) as u8, (b * 255.0) as u8]
        }
        _ => {
            // 普通 voxel,用 base_light
            [(base_light[0] * 255.0) as u8,
             (base_light[1] * 255.0) as u8,
             (base_light[2] * 255.0) as u8]
        }
    }
}
```

`base_light` 已经包含自发光地砖作为光源的贡献(给邻居的)。

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏里自发光的著名用例:

- **Diablo III**:法术效果,玩家踩到的火焰地砖
- **Portal**:传送门边缘自发光,引导玩家
- **Hades**:战斗效果,危险区域警告
- **Minecraft**:glowstone(萤石)、sea lantern(海晶灯),既是光源也是装饰

每个游戏的 emissive 系统都有特色。

### 3.2 · 图形学视角

PBR 渲染管线里 emissive 是材质属性:

```glsl
struct Material {
    vec3 albedo;
    float metallic;
    float roughness;
    vec3 emissive;     // 自发光
    float emissive_strength;
};

vec3 final_color = PBR_BRDF(...) + material.emissive * material.emissive_strength;
```

`emissive` 不参与 BRDF(BRDF 只算反射光),直接加在最终颜色里。这就是"自己发光"的语义。

### 3.3 · Linux 系统编程视角

Linux 上"自发光"的对应概念:

- **LED class driver**:`/sys/class/leds/`,每个 LED 是一个目录,brightness 文件控制亮度
- **RGB keyboard**:每个键的 LED 独立控制
- **oled display**:自发光屏幕,每个像素是发光二极管

游戏里的 emissive 和 OLED 屏幕的像素类似——**像素本身就是光源**,不依赖背光。

### 3.4 · Rust 生态视角

Rust 里 emissive voxel 的实现:

```rust
#[derive(Clone, Copy, Debug)]
enum VoxelType {
    Air,
    Solid { albedo: [u8; 3] },
    SelfIlluminating { albedo: [u8; 3], emissive: [u8; 3], intensity: f32 },
}

impl VoxelType {
    fn is_emissive(&self) -> bool {
        matches!(self, VoxelType::SelfIlluminating { .. })
    }
    fn emissive_color(&self) -> Option<([f32; 3], f32)> {
        match self {
            VoxelType::SelfIlluminating { emissive, intensity, .. } => {
                Some((
                    [emissive[0] as f32 / 255.0, emissive[1] as f32 / 255.0, emissive[2] as f32 / 255.0],
                    *intensity,
                ))
            }
            _ => None,
        }
    }
}
```

`matches!` 是 Rust 简洁的 pattern match 判断宏,返回 bool。

## 5 · 对照与变奏

不同自发光设计模式:

```
纯 emissive(自身亮,不照亮周围):
   ██ ← 看 voxel,亮
   ░░ ← 邻居不亮
   ░░

emissive + area light(自身亮,照亮周围):
   ██ ← 看 voxel,亮
   ▓▓ ← 邻居被照亮
   ░░ ← 远处正常

emissive + bloom(加辉光后处理):
   ✦✦ ← bloom 让光"溢出" voxel 边界
   ██
   ▓▓
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:emissive material 和 light source 有什么区别?为什么自发光地砖要"两者兼用"?

**参考解答**:emissive material 影响**自身**的颜色——fragment shader 里直接加到输出,不受外部光照影响。light source 影响**其他**物体的光照——通过光表 / 实时光照计算传递给邻居。自发光地砖两者兼用是因为:玩家视觉上要看到地砖"亮"(emissive),地砖周围的物体也要"被照亮"(source),这才符合"地砖发光"的真实直觉。

## 8 · Rust / Arch 落地代码

完整自发光地砖系统:

```rust
// Cargo.toml: 无依赖

#[derive(Clone, Copy, Debug)]
enum VoxelType {
    Air,
    Solid { albedo: [u8; 3] },
    SelfIlluminating { albedo: [u8; 3], emissive: [u8; 3], intensity: f32 },
}

impl VoxelType {
    fn is_solid(&self) -> bool { !matches!(self, VoxelType::Air) }
    fn is_emissive(&self) -> bool { matches!(self, VoxelType::SelfIlluminating { .. }) }
    fn emissive(&self) -> Option<([f32; 3], f32)> {
        match self {
            VoxelType::SelfIlluminating { emissive, intensity, .. } => Some((
                [emissive[0] as f32 / 255.0, emissive[1] as f32 / 255.0, emissive[2] as f32 / 255.0],
                *intensity,
            )),
            _ => None,
        }
    }
    fn albedo_f32(&self) -> [f32; 3] {
        match self {
            VoxelType::Air => [0.0; 3],
            VoxelType::Solid { albedo } => [albedo[0] as f32 / 255.0, albedo[1] as f32 / 255.0, albedo[2] as f32 / 255.0],
            VoxelType::SelfIlluminating { albedo, .. } => [albedo[0] as f32 / 255.0, albedo[1] as f32 / 255.0, albedo[2] as f32 / 255.0],
        }
    }
}

// 简单 grid world
struct World {
    voxels: Vec<VoxelType>,
    w: usize,
    h: usize,
}

impl World {
    fn new(w: usize, h: usize) -> Self {
        Self { voxels: vec![VoxelType::Air; w * h], w, h }
    }
    fn get(&self, x: i32, y: i32) -> VoxelType {
        if x < 0 || y < 0 || x as usize >= self.w || y as usize >= self.h {
            return VoxelType::Air;
        }
        self.voxels[y as usize * self.w + x as usize]
    }
    fn set(&mut self, x: i32, y: i32, v: VoxelType) {
        if x < 0 || y < 0 || x as usize >= self.w || y as usize >= self.h { return; }
        self.voxels[y as usize * self.w + x as usize] = v;
    }
    fn find_emissive(&self) -> Vec<(i32, i32, [f32; 3], f32)> {
        let mut out = Vec::new();
        for y in 0..self.h {
            for x in 0..self.w {
                let v = self.voxels[y * self.w + x];
                if let Some((c, i)) = v.emissive() {
                    out.push((x as i32, y as i32, c, i));
                }
            }
        }
        out
    }
}

fn light_at(world: &World, x: i32, y: i32) -> [f32; 3] {
    let mut total = [0.05; 3]; // ambient
    let emissive_voxels = world.find_emissive();
    for (ex, ey, color, intensity) in emissive_voxels {
        let dx = ex as f32 - x as f32;
        let dy = ey as f32 - y as f32;
        let dist_sq = dx * dx + dy * dy;
        if dist_sq > 100.0 { continue; } // 太远,跳过
        let atten = intensity / (1.0 + dist_sq);
        // 简化:不做 raycast
        total[0] += color[0] * atten;
        total[1] += color[1] * atten;
        total[2] += color[2] * atten;
    }
    total
}

fn render(world: &World) {
    for y in 0..world.h {
        let mut line = String::new();
        for x in 0..world.w {
            let v = world.voxels[y * world.w + x];
            let c = match v {
                VoxelType::Air => ' ',
                VoxelType::Solid { .. } => '#',
                VoxelType::SelfIlluminating { .. } => '*',
            };
            line.push(c);
        }
        println!("{}", line);
    }
}

fn render_lighting(world: &World) {
    for y in 0..world.h {
        let mut line = String::new();
        for x in 0..world.w {
            let v = world.voxels[y * world.w + x];
            match v {
                VoxelType::Air => line.push(' '),
                VoxelType::SelfIlluminating { .. } => line.push('*'),
                VoxelType::Solid { .. } => {
                    let l = light_at(world, x as i32, y as i32);
                    let avg = (l[0] + l[1] + l[2]) / 3.0;
                    let c = if avg > 0.5 { '#' }
                            else if avg > 0.2 { '+' }
                            else if avg > 0.05 { '.' }
                            else { ' ' };
                    line.push(c);
                }
            }
        }
        println!("{}", line);
    }
}

fn main() {
    let mut w = World::new(20, 10);
    // 围墙
    for x in 0..20 {
        w.set(x, 0, VoxelType::Solid { albedo: [180, 180, 180] });
        w.set(x, 9, VoxelType::Solid { albedo: [180, 180, 180] });
    }
    for y in 0..10 {
        w.set(0, y, VoxelType::Solid { albedo: [180, 180, 180] });
        w.set(19, y, VoxelType::Solid { albedo: [180, 180, 180] });
    }
    // 地板
    for x in 1..19 {
        for y in 1..9 {
            w.set(x, y, VoxelType::Solid { albedo: [100, 100, 100] });
        }
    }
    // 自发光地砖
    w.set(5, 5, VoxelType::SelfIlluminating { albedo: [50, 50, 50], emissive: [255, 100, 0], intensity: 8.0 });
    w.set(15, 5, VoxelType::SelfIlluminating { albedo: [50, 50, 50], emissive: [0, 200, 255], intensity: 8.0 });

    println!("=== Map ===");
    render(&w);
    println!("\n=== Lighting ===");
    render_lighting(&w);
    // 应看到两个发光地砖 '*'
    // 它们周围有亮度衰减:近处 '#',中等 '+',远处 '.'
}
```

## 10 · 工程反思

Day 654 传达的核心工程教训:** emissive material 是"光源 + 视觉"的统一**。

新手以为"光源"和"物体"是不同概念——光源发光,物体反射。但工业图形把这两者统一:**任何物体都可以 emissive**(发光),区别只是"emit 多少"。地砖 emissive 弱(微亮),灯泡 emissive 强(亮瞎眼)。

这种统一让渲染管线简单——一个 shader 处理所有物体,emissive 是材质参数。

**PBR(Physically Based Rendering)的 emissive model**:

```
L_out = emissive + BRDF * L_in * cos(θ)
```

`emissive` 是物体自身发光,BRDF 是反射模型,L_in 是入射光。如果 emissive > 0,物体是"光源 + 反射体"。这是物理正确的——所有物体都有黑体辐射(温度高于绝对零度),只是常温下辐射红外不可见。

**Bloom effect**:emissive 强的物体周围出现"光晕"。这是后处理——亮的像素 blur 后叠加到自己,产生"溢光"效果。Crysis 引入,后续所有 AAA 游戏用。

**第二条教训**:**emissive 是 cheap 的"假光源"**。

真正计算光照昂貴(每个光源每像素多次采样)。emissive 物体只"显示亮",不参与实际光照计算(默认)。这让设计师能加大量 emissive 物体(灯笼、地砖、屏幕)而不爆性能。

如果要让 emissive 物体真的"照亮周围",需要 GI(global illumination)。Unity / Unreal 用 real-time GI(Enlighten / Lumen),贵。Casey 在 HH 不做 GI,emissive 物体只是"视觉亮",不真发光。

**第三条教训**:**emissive 在 game design 的作用**。

设计师用 emissive:

- **引导玩家**:亮的物体吸引注意(关键道具 emissive,装饰物不)
- **氛围**:暗场景里的 emissive 灯,营造气氛
- **风格**:cyberpunk 用大量 emissive 霓虹,黑暗魂用 emissive 火把
- **反馈**:HP 低时血条 emissive 闪烁

每个用法都需要美术和工程协作。资深图形程序员理解"emissive 不只是技术,是设计语言"。

**迁移到其他领域**:

"emissive / 自发光"概念在多处通用:

- **UI**:hover state 按钮"发光"(CSS box-shadow)
- **Data viz**:图表中突出数据点(高亮)
- **Web**:active link 下划线 / 颜色
- **Mobile**:notification badge 红色 emissive

每个领域都用"发光 = 突出"的设计语言。Casey 在 HH 演示的是图形版本。

## 11 · emissive 材质的工业实现

Unity / Unreal 的 emissive 材质:

**Unity URP / HDRP**:

```hlsl
// Fragment shader
half3 albedo = tex2D(_MainTex, uv).rgb;
half3 emissive = tex2D(_EmissionMap, uv).rgb * _EmissionColor.rgb;
half3 finalColor = albedo * diffuseLight + emissive;
```

`_EmissionMap` 是 emissive 纹理(黑的区域不发光,亮的区域发光)。`_EmissionColor` 是倍数(可 HDR,> 1 触发 bloom)。

**Unreal Engine**:

```hlsl
// Material editor: Emissive Color input
// 自动连接到 bloom + tone mapping
float3 EmissiveColor = ...;
return EmissiveColor;
```

Unreal 的 material editor 有"Emissive Color"输入,直接拖纹理到这个 pin 就行。

**Bevy**:

```rust
// Standard material
material: StandardMaterial {
    base_color: Color::rgb(0.5, 0.5, 0.5),
    emissive: Color::rgb(2.0, 1.0, 0.5),  // HDR emissive
    ..default()
}
```

Bevy 的 StandardMaterial 有 emissive 字段。简单清晰。

## 12 · Bloom 后处理

emissive 的视觉效果离不开 bloom——亮的像素"溢出"到周围。

**Bloom 算法**:

1. **Bright pass**:原画面中 > threshold(如 1.0)的像素保留,其他黑
2. **Downsample**:连续降采样(bright texture 缩小一半,4-6 次)
3. **Gaussian blur**:每层 blur
4. **Upsample + combine**:升采样回原尺寸,叠加到画面

效果:亮像素周围出现"光晕"。

工业实现:

- **Unity URP**:Bloom Volume override
- **Unreal**:Post Process Volume > Bloom
- **bevy**:BloomSettings component

Casey 在 HH 不实现 bloom(简化),但 emissive 物体配合 bloom 是现代游戏的标配。

## 13 · 颜色溢出(color bleeding)

emissive 物体的光会"染"周围物体——红灯笼周围的墙是粉红色。这是 indirect lighting 的结果。

物理正确实现需要 GI(global illumination)。Casey 在 HH 不做 GI(简化),emissive 只"自己亮",不照亮周围。但工业级(Unity / Unreal)都支持。

实现方法:

- **Light probe**:emissive 物体周围放 light probe,采样入射光
- **Real-time GI**(Enlighten / Lumen):emissive 物体作为光源参与 GI
- **Ray tracing**(RTX):emissive 物体的光通过 ray tracing 自然照亮周围

每种方法 trade-off 不同。资深图形程序员按项目需求选。

## N0 • 深度教学补充

### 核心概念重新梳理

Day 654 涉及的核心概念需要在多个层次上理解:

**第一层:直观理解**

新手第一次接触概念,需要建立直觉。例如 voxel collision 是"虚拟物体不能穿过虚拟墙"——这个直觉每个人都能从现实经验获得。

**第二层:数学理解**

把直觉形式化。collision = "两个几何体的体积有交集"。对于 AABB,这等价于"三轴投影都重叠"。

**第三层:工程理解**

数学正确不等于工程实现正确。要考虑:

- 浮点精度边界
- 性能(每帧 N 个查询)
- 内存(数据结构紧凑)
- 边角 case(无穷大、NaN、负数)

**第四层:工业理解**

工业级要再加:

- 多线程安全
- SIMD 优化
- 网络同步(多人游戏)
- 跨平台(Windows/Mac/Linux/Mobile)
- 可访问性(色盲友好)
- 反作弊

每层理解都让代码更鲁棒。资深工程师在所有层次同时思考。

### 实际工程的细节

工业代码 80% 是"边角 case 处理",20% 是"核心算法"。Casey 在 HH 演示核心,工业代码加大量边角处理。

**边角 case 类型**:

1. 空输入(空 Vec、null pointer)
2. 极端输入(NaN、无穷大、超大数)
3. 并发竞争(多线程同时访问)
4. 资源不足(内存满、磁盘满)
5. 网络异常(超时、断连、包丢失)
6. 版本不兼容(老配置 / 新代码)
7. 权限错误(只读文件、无网络)
8. 用户误操作(连点、撤销重做)

每个 case 都要单独处理。这是工业代码 50%+ 行数的原因。

### 优化思路

性能优化有顺序:

1. **算法**:O(N²) → O(N log N),最大提升
2. **数据结构**:Vec → HashMap / BTreeMap,常数提升
3. **Cache**:AoS → SoA,cache 命中提升
4. **SIMD**:4-16 元素并行,巨大常数提升
5. **GPU**:数千核并行,极致性能
6. **分布式**:多机器,无限扩展

每级提升都需要更复杂的代码。先优化低级,够用再升级。
