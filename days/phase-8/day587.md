# Day 587 · 优化镜面到漫反射变换

> Day 582 写了 `specular_to_diffuse` 卷积,Day 586 完成了采样。但 `specular_to_diffuse` 在生产环境每帧调用 1000 个体素 × 256 texel = 256K 次卷积,大约 4-5 ms。今天 Casey 要把它 SIMD 化,降到 1 ms 以内。

## 0 · 为什么要有这一天

游戏 60 FPS = 16 ms / 帧。这 16 ms 要分配给:
- 游戏逻辑(AI、物理):3-5 ms
- 渲染(光栅化、像素着色):8-10 ms
- **光照更新(GI 卷积):2-4 ms** ← 这是 Casey 今天要优化的

如果光照卷积占 5 ms,剩下渲染只有 11 ms,可能跑不到 60 FPS。降到 1 ms 后,渲染有 13-15 ms 余地。

**SIMD**(Single Instruction Multiple Data)是 CPU 一次性处理多个数据的指令集。x86_64 上 AVX2 可以一次处理 8 个 f32(256 位寄存器 / 32 位 f32)。理论加速 8 倍,实际 4-6 倍(因为数据加载和指令调度开销)。

Casey 这一天把 `specular_to_diffuse` 从标量版本改成 AVX2 版本,基准测试加速 5 倍。

心理锚点:看完这集,你能用 Rust 的 `std::arch::x86_64` 写 SIMD 代码,理解为什么 SIMD 要求数据布局对齐(SoA),能自己测 SIMD 加速比。

## 1 · Casey 今天做了什么

Casey 这一天的几个动作:

1. **基准测试**:他先用 `criterion` crate 测当前版本:`specular_to_diffuse` 一次调用平均 8 µs。1000 个体素每帧 = 8 ms,跑不快。
2. **瓶颈分析**:展开代码看,内循环 256 次,每次 decode + dot + 乘加。其中 dot 是 3 次乘 + 2 次加,decode 是分支处理。
3. **SIMD 重写**:把内循环改成一次处理 8 个 texel 的 AVX2 版本。需要预计算所有 256 个方向的 decode 结果(SoA 排布),不能每次 decode。
4. **对比测试**:SIMD 版本一次调用平均 1.5 µs,加速 5.3 倍。Casey 满意。

这一天的工程产出大约 100 行 Rust 代码(SIMD + 基准测试),价值在于**把抽象数学公式变成 SIMD 友好的代码**——这是高性能系统程序员的核心技能。

## 2 · 心智模型

### 类比:流水线打包

工厂里有 1000 个盒子要装饼干。标量做法:一个人拿一个盒子,放一块饼干,封口;然后下一个盒子。一次一个。

SIMD 做法:8 个盒子并排放,一台机器有 8 个机械臂,同时给 8 个盒子放饼干、封口。一次 8 个。

要 SIM D 工作,8 个盒子必须**并排放**(数据连续),机械臂必须**同时动作**(指令一致,没有分支)。

应用到 `specular_to_diffuse`:256 个 texel 是 256 个盒子。SIMD 一次处理 8 个 texel。要求:
- 8 个 texel 的数据连续(它们本来就是 atlas.texels 的连续 8 个)
- 处理逻辑无分支(decode、dot、accumulate 都不能有 if)

### 严谨原理:SIMD 数据布局

SIMD 指令操作的是**向量寄存器**(256 位 = 32 字节)。对 f32,一个寄存器装 8 个。

**加载**:`_mm256_loadu_ps(ptr)` 把 ptr 起始的 8 个 f32 加载到寄存器。要求 ptr 指向 32 字节连续数据。

**计算**:`_mm256_add_ps(a, b)` 两个寄存器逐 lane 相加,结果还是寄存器。

**存储**:`_mm256_storeu_ps(ptr, x)` 把寄存器存回内存。

**关键限制**:
- 加载必须连续(不能跨非连续索引)
- 计算必须无分支(if 会让 SIMD 退化到标量)
- 数据最好 32 字节对齐(否则 loadu 比 load 慢一点,但不致命)

### 把 specular_to_diffuse 改 SIMD 友好

**原标量版本**:

```rust
fn specular_to_diffuse(atlas: &LightAtlas, normal: Vec3) -> RGB32F {
    let mut sum = RGB32F::default();
    for ty in 0..atlas.dim {
        for tx in 0..atlas.dim {
            let u = (tx as f32 / (atlas.dim - 1) as f32) * 2.0 - 1.0;
            let v = (ty as f32 / (atlas.dim - 1) as f32) * 2.0 - 1.0;
            let dir = decode_octahedral(u, v);  // 有分支
            let color = atlas.texels[ty * atlas.dim + tx];
            let cos_theta = dir.dot(normal).max(0.0);
            sum += color * cos_theta * d_omega;
        }
    }
    sum / std::f32::consts::PI
}
```

**问题**:
1. `decode_octahedral` 有 if 分支,SIMD 不友好
2. `dir.dot(normal).max(0.0)` 有 `max(0.0)`,可以用 SIMD 但需要 `_mm256_max_ps`
3. `color * cos_theta * d_omega` 是 RGB 乘法,SIMD 友好

**SIMD 友好版本**:

预计算所有 256 个方向的 decode 结果(SoA):

```rust
struct PrecomputedDirs {
    xs: Vec<f32>,  // 256 个方向 x 分量
    ys: Vec<f32>,
    zs: Vec<f32>,
}

impl PrecomputedDirs {
    fn new(dim: usize) -> Self {
        let mut xs = Vec::with_capacity(dim * dim);
        let mut ys = Vec::with_capacity(dim * dim);
        let mut zs = Vec::with_capacity(dim * dim);
        for ty in 0..dim {
            for tx in 0..dim {
                let u = (tx as f32 / (dim - 1) as f32) * 2.0 - 1.0;
                let v = (ty as f32 / (dim - 1) as f32) * 2.0 - 1.0;
                let dir = decode_octahedral(u, v);
                xs.push(dir.x);
                ys.push(dir.y);
                zs.push(dir.z);
            }
        }
        Self { xs, ys, zs }
    }
}
```

**SIMD 卷积**:

```rust
#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
unsafe fn specular_to_diffuse_simd(
    atlas: &LightAtlas,
    dirs: &PrecomputedDirs,
    normal: Vec3,
) -> RGB32F {
    use std::arch::x86_64::*;
    
    let d_omega = std::f32::consts::PI * 4.0 / (atlas.dim * atlas.dim) as f32;
    let inv_pi = 1.0 / std::f32::consts::PI;
    
    // 累加器:sum_r, sum_g, sum_b(各 8 lane)
    let mut sum_r = _mm256_setzero_ps();
    let mut sum_g = _mm256_setzero_ps();
    let mut sum_b = _mm256_setzero_ps();
    
    // normal 广播
    let nx = _mm256_set1_ps(normal.x);
    let ny = _mm256_set1_ps(normal.y);
    let nz = _mm256_set1_ps(normal.z);
    let d_omega_v = _mm256_set1_ps(d_omega);
    
    let n = atlas.dim * atlas.dim;
    let mut i = 0;
    while i + 8 <= n {
        // 加载 8 个 dir
        let dx = _mm256_loadu_ps(dirs.xs.as_ptr().add(i));
        let dy = _mm256_loadu_ps(dirs.ys.as_ptr().add(i));
        let dz = _mm256_loadu_ps(dirs.zs.as_ptr().add(i));
        
        // dot(dir, normal) = dx*nx + dy*ny + dz*nz
        let dot = _mm256_add_ps(
            _mm256_add_ps(_mm256_mul_ps(dx, nx), _mm256_mul_ps(dy, ny)),
            _mm256_mul_ps(dz, nz),
        );
        
        // max(0, dot)
        let cos_theta = _mm256_max_ps(dot, _mm256_setzero_ps());
        
        // 加载 8 个 color(每 8 个 color 的 r/g/b 分别连续)
        let cr = _mm256_loadu_ps(atlas.texels.as_ptr().cast::<f32>().add(i * 3));
        let cg = _mm256_loadu_ps(atlas.texels.as_ptr().cast::<f32>().add(i * 3 + 1));
        let cb = _mm256_loadu_ps(atlas.texels.as_ptr().cast::<f32>().add(i * 3 + 2));
        // 注意:这要求 atlas.texels 的内存布局是 r,g,b,r,g,b,...(AoS)
        // 如果是 SoA(rrrrrgggggbbbbb),需要不同加载
        
        // weighted = color * cos_theta * d_omega
        let weight = _mm256_mul_ps(cos_theta, d_omega_v);
        let wr = _mm256_mul_ps(cr, weight);
        let wg = _mm256_mul_ps(cg, weight);
        let wb = _mm256_mul_ps(cb, weight);
        
        // 累加
        sum_r = _mm256_add_ps(sum_r, wr);
        sum_g = _mm256_add_ps(sum_g, wg);
        sum_b = _mm256_add_ps(sum_b, wb);
        
        i += 8;
    }
    
    // 把 8 lane 水平相加
    let reduce = |v: __m256| -> f32 {
        // 提取 8 个 f32 求和
        let mut buf = [0f32; 8];
        _mm256_storeu_ps(buf.as_mut_ptr(), v);
        buf.iter().sum()
    };
    
    RGB32F::new(
        reduce(sum_r) * inv_pi,
        reduce(sum_g) * inv_pi,
        reduce(sum_b) * inv_pi,
    )
}
```

**每行解释**:
- `_mm256_set1_ps(x)` — 把 x 广播到 8 lane。
- `_mm256_loadu_ps(ptr)` — 加载 8 个 f32(不要求对齐)。注意"不要求对齐"但仍建议 32 字节对齐性能最优。
- `_mm256_mul_ps`, `_mm256_add_ps`, `_mm256_max_ps` — 逐 lane 操作。
- 水平 reduce — SIMD 寄存器内的 8 个 lane 求和。`_mm256_hadd_ps` 可以做水平加,但通常 `_mm256_storeu_ps` + 数组求和更简单。
- `while i + 8 <= n` — 处理 8 个一组,末尾不到 8 的部分用标量补(省略)。

### 性能对比

```rust
// 标量:8 µs / 调用
// SIMD AVX2:1.5 µs / 调用
// 加速 5.3 倍
```

加速没到理论 8 倍,因为:

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

SIMD 在游戏工业里是标配。所有数学库(glam、cgmath、nalgebra)都用 SIMD 优化向量运算。游戏引擎核心循环(物理、AI、渲染)到处 SIMD。

**SIMD 编程流派**:
1. **手写 intrinsic**(Casey 用):直接调 `_mm256_*` 函数,完全控制
2. **编译器自动向量化**:写普通 `for` 循环,编译器(LLVM)自动 SIMD 化。简单,但不总能识别
3. **库封装**:glam 等库提供"看起来是普通 Vec3,实际 SIMD"的类型

Casey 选 1,因为他要完全控制。生产代码可能选 3(用 glam)省心。

**Rust portable-simd crate**:Rust 官方的可移植 SIMD 抽象,跨架构(x86、ARM、WASM)。



### 3.2 · 🎨 图形学视角

图形学里 SIMD 是绝对核心:
- **GPU**:本质就是大规模 SIMD(成千上万 lane)
- **CPU 光栅化**:三角形 setup、像素填充都用 SIMD
- **物理仿真**:粒子系统、布料模拟大量 SIMD
- **图像处理**:卷积、滤波 SIMD

**SIMD vs GPU**:
- SIMD:CPU 上,几十 lane,灵活,缓存友好
- GPU:几十万 lane,极度并行,但数据传输开销

游戏开发典型分工:CPU SIMD 做少量复杂数据(几百个),GPU 做大量简单数据(几百万个)。

Casey 的 specular_to_diffuse 是 256 个 texel × 1000 个体素 = 256K 个数据点,CPU SIMD 合适。GPU 会有数据传输开销。

### 3.4 · 🦀 Rust 生态视角

Rust SIMD 的关键特性:

**特性 1:`#[target_feature]`**。让一个函数只在使用特定 SIMD 时编译:

```rust
#[target_feature(enable = "avx2")]
unsafe fn foo_avx2() { ... }

fn foo_dispatch() {
    if is_x86_feature_detected!("avx2") {
        unsafe { foo_avx2() }
    } else {
        foo_scalar()
    }
}
```

**特性 2:`is_x86_feature_detected!`**。运行时检测 CPU 支持。

**特性 3:`#[cfg(target_arch = "x86_64")]`**。条件编译,只在 x86_64 编译 SIMD 代码。

**特性 4:`unsafe`**。所有 `_mm256_*` 都是 unsafe,因为:
- 可能 CPU 不支持(SIGILL 崩溃)
- 编译器不能验证内存安全(越界访问)

Casey 的 SIMD 代码全部 unsafe,但通过 `target_feature` + `is_x86_feature_detected!` 保证运行时安全。

- **2011**:Intel Sandy Bridge 引入 AVX(256 位)

- **CPU SIMD**:8-16 lane,低延迟,适合复杂数据

游戏代码 CPU SIMD 处理 AI、物理(少量复杂数据),GPU 处理渲染(大量简单像素)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 SIMD 加速比理论 8 倍实际只有 5 倍?列出 3 个原因。

**参考解答**:
1. **末尾标量处理**:256 个 texel / 8 = 32 组完整,无剩余。但如果数据量不是 8 的倍数,末尾标量部分无加速
2. **加载存储开销**:SIMD 计算快,但 `_mm256_loadu_ps` 把数据从内存搬到寄存器需要时间。如果数据不在 L1 cache,加载就是瓶颈
3. **水平 reduce 开销**:最后把 8 lane 求和需要 `_mm256_storeu_ps` + 数组求和,这步不是 SIMD 加速的

次要原因:指令调度(流水线气泡)、分支预测错误(即使代码无分支,编译器生成的中间代码可能引入)。

### Lv2 · 动手实践

**题**:实现 `specular_to_diffuse_simd`(AVX2 版本),与标量版本对比正确性和性能。测试:
- 标量和 SIMD 结果相同(误差 < 1e-4)
- SIMD 版本快 3 倍以上

完成标准:`cargo run --release` 打印两种版本的时间和正确性对比。

**参考解答**:

```rust
use std::arch::x86_64::*;

#[derive(Copy, Clone, Debug, Default, PartialEq)]
struct RGB32F { r: f32, g: f32, b: f32 }

// 标量版本(简化,只用 R 通道示例)
fn sum_r_scalar(atlas_r: &[f32]) -> f32 {
    atlas_r.iter().sum()
}

// SIMD 版本
#[target_feature(enable = "avx2")]
unsafe fn sum_r_simd(atlas_r: &[f32]) -> f32 {
    let mut sum = _mm256_setzero_ps();
    let mut i = 0;
    while i + 8 <= atlas_r.len() {
        let chunk = _mm256_loadu_ps(atlas_r.as_ptr().add(i));
        sum = _mm256_add_ps(sum, chunk);
        i += 8;
    }
    let mut buf = [0f32; 8];
    _mm256_storeu_ps(buf.as_mut_ptr(), sum);
    let mut total = buf.iter().sum::<f32>();
    // 剩余部分
    while i < atlas_r.len() {
        total += atlas_r[i];
        i += 1;
    }
    total
}

fn main() {
    let data: Vec<f32> = (0..256).map(|i| i as f32 * 0.1).collect();
    
    let s = sum_r_scalar(&data);
    let p = if is_x86_feature_detected!("avx2") {
        unsafe { sum_r_simd(&data) }
    } else {
        s
    };
    
    println!("Scalar: {}", s);
    println!("SIMD: {}", p);
    println!("Diff: {}", (s - p).abs());
    
    // 计时
    let n_iter = 100_000;
    let start = std::time::Instant::now();
    for _ in 0..n_iter {
        std::hint::black_box(sum_r_scalar(&data));
    }
    let scalar_time = start.elapsed();
    
    let start = std::time::Instant::now();
    for _ in 0..n_iter {
        std::hint::black_box(unsafe { sum_r_simd(&data) });
    }
    let simd_time = start.elapsed();
    
    println!("Scalar: {:?} ({:.2} ns/iter)", scalar_time, scalar_time.as_nanos() as f64 / n_iter as f64);
    println!("SIMD: {:?} ({:.2} ns/iter)", simd_time, simd_time.as_nanos() as f64 / n_iter as f64);
    println!("Speedup: {:.2}x", scalar_time.as_secs_f64() / simd_time.as_secs_f64());
}
```

**每行解释**:
- `#[target_feature(enable = "avx2")]` — 函数内部用 AVX2 指令。
- `is_x86_feature_detected!("avx2")` — 运行时检测,不支持的 CPU 走标量。
- `std::hint::black_box` — 防止编译器优化掉循环。

## 8 · Rust / Arch 落地代码

完整可跑示例(基于 Lv2):

```rust
use std::arch::x86_64::*;
use std::hint::black_box;

const N: usize = 256;

fn sum_scalar(data: &[f32]) -> f32 {
    let mut s = 0.0f32;
    for &v in data {
        s += v;
    }
    s
}

#[target_feature(enable = "avx2")]
unsafe fn sum_avx2(data: &[f32]) -> f32 {
    let mut sum = _mm256_setzero_ps();
    let mut i = 0;
    let n_full = data.len() & !7;  // 最大的 8 的倍数
    while i < n_full {
        let chunk = _mm256_loadu_ps(data.as_ptr().add(i));
        sum = _mm256_add_ps(sum, chunk);
        i += 8;
    }
    // reduce
    let mut buf = [0f32; 8];
    _mm256_storeu_ps(buf.as_mut_ptr(), sum);
    let mut total: f32 = buf.iter().sum();
    while i < data.len() {
        total += data[i];
        i += 1;
    }
    total
}

fn main() {
    let data: Vec<f32> = (0..N).map(|i| (i as f32) * 0.01).collect();
    
    // 正确性
    let s = sum_scalar(&data);
    let p = if is_x86_feature_detected!("avx2") {
        unsafe { sum_avx2(&data) }
    } else {
        s
    };
    println!("Scalar sum: {}", s);
    println!("SIMD sum:   {}", p);
    println!("Diff: {:.e}", (s - p).abs());
    assert!((s - p).abs() < 1e-2);
    
    // 性能
    let n_iter = 1_000_000;
    let t1 = std::time::Instant::now();
    for _ in 0..n_iter {
        black_box(sum_scalar(&data));
    }
    let scalar_elapsed = t1.elapsed();
    
    let t2 = std::time::Instant::now();
    for _ in 0..n_iter {
        if is_x86_feature_detected!("avx2") {
            black_box(unsafe { sum_avx2(&data) });
        }
    }
    let simd_elapsed = t2.elapsed();
    
    println!("\nPerformance ({} iters of {} floats):", n_iter, N);
    println!("Scalar: {:?} ({:.1} ns/iter)", scalar_elapsed, scalar_elapsed.as_nanos() as f64 / n_iter as f64);
    println!("SIMD:   {:?} ({:.1} ns/iter)", simd_elapsed, simd_elapsed.as_nanos() as f64 / n_iter as f64);
    println!("Speedup: {:.2}x", scalar_elapsed.as_secs_f64() / simd_elapsed.as_secs_f64());
}
```

### A.1 该 Day 在 phase-8 的位置

Phase 8(day576-667)是 voxel lighting 系统的工业级实现。本日是其中一天。

### A.2 Voxel lighting 的工程挑战

Voxel lighting 是计算机图形学的难点,因为:

**1. 数据量大**:
- 大场景(100m × 100m × 100m)有几百万 voxel
- 每 voxel 存光照值(RGB 或 SH)
- 总数据 GB 级

**2. 实时性要求**:
- 玩家挖 / 改 voxel,光照立即变化
- 16.67 ms 帧预算(60 FPS)
- 不能阻塞玩家操作

**3. 物理准确性**:
- 直接光(sun)
- 间接光(bounce)
- 阴影(hard / soft)
- 反射(diffuse / specular)
- 折射(glass / water)

工业方案在物理准确性和实时性之间权衡。

### A.3 工业级实现的层次

**Layer 1:Brute force**
- 每 voxel × 每方向 raycast
- 准确但极慢
- 适合离线渲染(movie)

**Layer 2:Grid DDA**
- 快速 raycast(穿格子)
- 适合简单场景
- Casey 的 HH 用这层

**Layer 3:Precomputed**
- 离线算光照 cache
- 运行时查表
- 适合静态场景(Minecraft baked)

**Layer 4:Real-time approximation**
- LPV / SVOGI / Voxel Cone Tracing
- 实时但近似
- Crytek / Unreal 用

**Layer 5:Hardware ray tracing**
- RTX / RDNA2 核心
- 真实光传播
- Minecraft RTX / Teardown

每代技术对硬件要求递增。Casey 的 HH 在 Layer 2(教学优先)。

### A.4 性能 profile 的实战

Casey 在 phase-8 多次 profile:

**Profile 工具**:
- Linux:perf、Valgrind、flamegraph
- Windows:Superluminal、VTune
- 跨平台:Tracy

**典型发现**:
- Raycast 占 50%+
- Propagation 占 20%+
- Meshing 占 10%+
- 其他占 20%

**优化顺序**:
1. 最慢函数 → 算法优化
2. Cache miss → 数据布局优化
3. 锁等待 → 并发优化

每优化一个,重新 profile 找下一个。

### A.5 Casey 的 phase-8 工程决策

Casey 在 phase-8 做的关键工程决策:

**1. CPU 渲染**:简单,跨平台,教学优先
**2. Voxel grid(非 octree)**:简单,固定大小
**3. RGBE atlas(非 SH)**:内存小,够教学
**4. Precomputed + delta update**:平衡实时性和准确性

这些决策让 HH 代码可读、可教学。生产游戏可能选 GPU + SH + realtime(更复杂)。

### A.7 Voxel lighting 算法的核心循环

让我写一个简化的 voxel lighting 主循环:

```rust
fn update_lighting(world: &mut World, sun_dir: Vec3) {
    let direct = compute_direct_lighting(world, sun_dir);
    let indirect = compute_indirect_lighting(world, &direct, 3);  // 3 bounce
    let final_light = combine(&direct, &indirect);
    world.light_atlas = final_light;
}

fn compute_direct_lighting(world: &World, sun_dir: Vec3) -> LightAtlas {
    let mut atlas = LightAtlas::new(world.dims());
    for each voxel {
        if voxel.is_solid() && !is_occluded(world, voxel_pos, sun_dir) {
            let lambert = compute_normal(world, x, y, z).dot(sun_dir).max(0.0);
            atlas.set(x, y, z, sun_color * lambert);
        }
    }
    atlas
}

fn compute_indirect_lighting(world: &World, direct: &LightAtlas, bounces: usize) -> LightAtlas {
    let mut current = direct.clone();
    for _ in 0..bounces {
        let mut next = current.clone();
        for each voxel {
            let bounce = average_neighbors(&current, x, y, z) * 0.15;
            next.set(x, y, z, current.get(x, y, z) + bounce);
        }
        current = next;
    }
    current
}
```

这是 Casey phase-8 的简化核心。工业实现更复杂(SH、GPU、并行)。

### A.8 Voxel lighting 的内存估算

```
Per voxel 数据:
  - material: 1 byte
  - color: 3 byte RGB
  - light: 4 byte RGBE
  - flags: 1 byte
  Total: 9 byte

场景尺寸:
  - 32^3(教学):36 KB
  - 100^3(小场景):9 MB
  - 256^3(中场景):150 MB
  - 1024^3(大场景):9.6 GB

大场景必须 streaming(chunked)。
```

工业 voxel 游戏(Minecraft):

- 每 chunk ~36 KB
- 同时加载 100 chunk ≈ 3.6 MB
