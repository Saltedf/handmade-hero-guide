# Day 616 · 半分辨率网格采样

> DDA 已经把 hot path 砍到 6.3ms。今天的优化更激进:**采样时只遍历一半分辨率的体素网格**。每两个体素合并成一个"粗体素",DDA 步进次数减半。代价是精度损失(细小物体可能漏检),但在 diffuse blur 这种容差大的光照任务里,半分辨率足够了。这一招工业上叫 **multi-resolution sampling** 或 **mip raycasting**,是 GPU 早已普及但 CPU 实现罕见的技术。

## 0 · 为什么要有这一天

Casey 在 Day 615 把 walk table 换成 DDA 后,profile 显示 **DDA 循环本身仍然占 6.3ms 的大头**——循环跑了 2000 万次(对应每帧 ~100k 条光线,每条平均 ~200 个体素步进)。能不能减少步进次数?

观察光照采样的特点:

1. **diffuse 表面光照是低频的**——Lambert diffuse `max(0, N·L)` 在表面附近的梯度很小,光线路径偏一两格不会显著改变结果
2. **大部分光线用来算"间接光 bounce"**——这些 bounce 的目的是"采样半球方向的入射光强",分辨率要求低
3. **半分辨率合并相邻 8 个体素(2×2×2)成 1 个粗体素**——DDA 步进数减少 ~50%(因为每个粗体素跨 2 倍距离)
4. **粗体素的"实体性"取 max**:8 个体素里只要有一个实体,粗体素就视为实体。这是保守合并,宁可多算不要漏检

**风险**:细小物体(如 1 个体素宽的柱子)在粗网格里"消失",导致光线穿透——这是 trade-off。Casey 选择**只在 diffuse bounce 阶段用半分辨率**,直接光照仍用全分辨率,平衡精度和性能。

**今天的核心概念**:**Multi-resolution 层级**。把数据组织成多个 lod(level of detail),按任务精度选合适的层。GPU 的 mip mapping、clipmap、geometry lod 都是同一思想。CPU raycast 用得少,因为传统上 CPU 算力有限,不值得花在层级管理上——但 HH 的间接光计算正是适合的场景。

心理锚点:看完这集,你能:
- 解释为什么 diffuse 光照适合半分辨率(低频),specular 不适合(高频)
- 实现一个 mip 化的体素网格
- 在不同任务上选择不同的分辨率

## 2 · 心智模型

### 类比:Google Maps 缩放

打开 Google Maps,你看到整个中国时,每个城市是一个"点"(粗分辨率)。放大到省,城市变成圆圈(中分辨率)。放大到街,看到每栋楼(细分辨率)。

地图服务商**预生成多个分辨率版本**——叫 pyramid 或 mip pyramid:
- mip 0:全分辨率(最高细节)
- mip 1:1/2 分辨率
- mip 2:1/4 分辨率
- ...
- mip N:1×1 像素(整个图一个颜色)

**为什么预生成**:不同缩放级别需要不同细节。每帧实时降采样太慢,所以**预先算好所有层级**,显示时查表。GPU 的 texture 单元硬件支持 trilinear mip 采样,几乎免费。

DDA 的半分辨率同理:**预先生成粗分辨率体素网格,DDA 在粗网格上步进,步进次数减半**。

### 严谨推导:Multi-resolution 体素

#### 2.1 体素 mip 定义

给定全分辨率体素网格 `V_full[W][H][D]`,定义 mip 1(半分辨率):

```
V_half[i][j][k] = max(
    V_full[2i  ][2j  ][2k  ],
    V_full[2i+1][2j  ][2k  ],
    V_full[2i  ][2j+1][2k  ],
    V_full[2i+1][2j+1][2k  ],
    V_full[2i  ][2j  ][2k+1],
    V_full[2i+1][2j  ][2k+1],
    V_full[2i  ][2j+1][2k+1],
    V_full[2i+1][2j+1][2k+1]
)
```

`max` 是保守合并:8 个里只要有一个实体(=1),整个粗体素视为实体。这保证**不会漏检**——光线在粗网格上命中,意味着一定有实体;光线在粗网格上 miss,意味着 8 个里都没实体。

**为什么不是 average**:average 会产生 0.5 这种"半实体"值,失去二值意义,光照计算时模糊。max 保持二值。

**为什么不是 min**:min 会漏检(8 个里 7 个实体,但 min=0)。max 是**保守 upper bound**。

#### 2.2 内存占用

mip pyramid 总内存 = 原图 + 1/8 + 1/64 + ... = `原 × 1/(1 - 1/8) ≈ 原 × 1.143`。**只比原图多 14.3%**——这是 mip 的优雅之处,层级管理几乎免费。

具体到 HH 的体素网格(假设 128×128×128 = 2M 体素):

- mip 0(全):128³ = 2.0 MB
- mip 1(半):64³ = 256 KB
- mip 2(1/4):32³ = 32 KB
- mip 3(1/8):16³ = 4 KB
- ...

总和 ~2.3 MB。Casey 目前只用 mip 0 和 mip 1,扩展到 mip 2/3 也几乎免费。

#### 2.3 DDA 在粗网格上跑

DDA 算法本身不变(看 Day 615),只是:

- `cell = (2.0, 2.0, 2.0)` 而不是 `(1.0, 1.0, 1.0)`
- `i, j, k` 索引在粗网格坐标
- `world.is_solid(idx)` 查粗网格

效果:每步 t_max 增加 2 倍(因为 cell 大 2 倍),所以**步进次数减少 2 倍**。

#### 2.4 命中后的精细查询

粗网格命中后,**回到全分辨率精查命中点附近的 2×2×2 体素**:

```
1. DDA 在粗网格跑,命中粗体素 (I, J, K) at t_hit
2. 在全分辨率查 (2I, 2J, 2K) 到 (2I+1, 2J+1, 2K+1) 这 8 个体素
3. 用精细 DDA 找出真正命中的体素
```

这是 **two-level raycast**——先用粗找大致位置,再用细找精确命中。GPU 的稀疏体素八叉树(sparse voxel octree)就是这个思想的极致版本。

Casey 在 Day 616 没做到这一步——他直接用粗网格的命中点,接受精度损失。Day 617 可能补上。

#### 2.5 完整算法

```rust
struct World {
    voxels: Vec<u8>,        // mip 0, 全分辨率
    voxels_half: Vec<u8>,   // mip 1, 半分辨率
    // 维度信息
    w: usize, h: usize, d: usize,
}

impl World {
    fn build_half_resolution(&mut self) {
        let hw = self.w.div_ceil(2);
        let hh = self.h.div_ceil(2);
        let hd = self.d.div_ceil(2);
        self.voxels_half = vec![0; hw * hh * hd];

        for k in 0..hd {
            for j in 0..hh {
                for i in 0..hw {
                    let mut max_v = 0u8;
                    // 2x2x2 邻域取 max
                    for dk in 0..2 {
                        for dj in 0..2 {
                            for di in 0..2 {
                                let fi = 2*i + di;
                                let fj = 2*j + dj;
                                let fk = 2*k + dk;
                                if fi < self.w && fj < self.h && fk < self.d {
                                    let idx = fi + fj*self.w + fk*self.w*self.h;
                                    max_v = max_v.max(self.voxels[idx]);
                                }
                            }
                        }
                    }
                    let hidx = i + j*hw + k*hw*hh;
                    self.voxels_half[hidx] = max_v;
                }
            }
        }
    }
}
```

**注释**:
- `div_ceil(2)` — 整数除法向上取整。`5.div_ceil(2) = 3`(因为 5 = 2*2 + 1)。保证奇数维度也能完整覆盖
- `for dk in 0..2 for dj in 0..2 for di in 0..2` — 遍历 2×2×2 = 8 个全分辨率体素
- `if fi < self.w ...` — 边界检查(奇数维度时,最后那个粗体素只覆盖到 1 个全分辨率体素)
- `max_v.max(...)` — Rust 的 `u8::max` 内联,等价于 `if x > max_v { x } else { max_v }`

### 2.7 为什么 diffuse 容忍低分辨率

回顾 Lambert 漫反射公式:

```
L_diffuse = albedo × light_color × max(0, N·L) / π
```

`N·L` 是 cos(θ),θ 是表面法线 N 和光源方向 L 的夹角。**当 N 或 L 微微抖动 1-2 度时,cos 变化 < 0.05**,光照变化肉眼几乎看不出。

所以**间接光 bounce**(diffuse 反射)用半分辨率,效果几乎一致,但快 2 倍。

**Specular 高光**则不同:`(R·V)^n`,n 是 phong exponent(可能 50-200),`(R·V)` 微变会被 n 次方放大,高光位置对精度极敏感。**Specular 必须用全分辨率**。

这就是为什么 Casey 选择**只在 diffuse bounce 用半分辨率**——精度需求不同。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

Multi-resolution 在游戏里无处不在:

1. **Mipmap texture**:GPU 硬件支持,几乎所有游戏都开
2. **LOD mesh**:远处用低面数模型(Day 410+ HH 会讲)
3. **Cascaded shadow map**:近处高分辨率阴影、远处低分辨率,合并成一个无缝阴影
4. **Impostor / billboard**:远处角色用 2D sprite 替代 3D 模型
5. **Multi-resolution GI**(本日):间接光用低分辨率,直接光用全分辨率

**通用原则**:**人眼对低频信号(颜色、亮度)不敏感,对高频信号(边缘、 specular 高光)敏感**。所以低频任务可以用低分辨率,高频任务必须高分辨率。

**坑**:

- **边界泄漏**:粗网格命中点可能"擦边"穿过细网格的实体,导致光线漏检
- **细物体丢失**:1 体素宽的柱子在粗网格里消失,光照把它当空气。Casey 的解决:粗网格用 max 合并,但仍然可能 1 体素柱子被一个空气体素"包围"——这只能算 trade-off
- **可视化检查**:加 debug overlay 显示粗网格命中,人眼对比确认

### 3.2 · 🎨 图形学视角

#### Mip mapping 原理

GPU texture 单元硬件支持 mip:

- **Trilinear filtering**:在两个 mip 层之间线性插值
- **Anisotropic filtering**:不同方向不同 mip,适合斜视角地面
- **Texture LOD bias**:手动调整 mip 选择,可控制"清晰 vs 平滑"

#### Multi-resolution raycast 历史

- **1990s**:CVG(cone voxel grid)用于 ray tracing
- **2000s**:Sparse Voxel Octree(Crassin et al., 2009,GigaVoxels)
- **2010s**:Sparse Voxel DAG(Directed Acyclic Graph,2014),内存更省
- **2020s**:Hardware ray tracing + multi-resolution,RTX 的官方推荐做法

#### Multi-resolution 光照特例

- **Irradiance volume**:在 3D 网格上预计算每个格子的入射光(类似 SH 系数),运行时三线性插值。HL2 的 Cuba map 是其简化版
- **Voxel AO**:体素化的环境光遮蔽,粗网格算远距离遮挡
- **Voxel GI (Crassin 2011)**:real-time diffuse GI 用体素 cone tracing

Casey 的方法本质是 GigaVoxels 的"穷人版"——只用两层 mip,不做 cone tracing,但思想完全相同。

### 3.4 · 🦀 Rust 生态视角

Rust 写 mip pyramid 有几种风格:

**1. 直接两个 Vec**:

```rust
struct World {
    voxels: Vec<u8>,
    voxels_half: Vec<u8>,
}
```

简单,但每加一层 mip 都要加字段。

**2. `Vec<Vec<u8>>` 表示所有 mip**:

```rust
struct World {
    mips: Vec<Vec<u8>>,  // mips[0] = full, mips[1] = half, ...
}
```

可扩展,但索引计算需要每层维护维度信息。

**3. Trait 抽象**:

```rust
trait Grid {
    fn dimensions(&self) -> (usize, usize, usize);
    fn is_solid(&self, i: usize, j: usize, k: usize) -> bool;
}

struct FullGrid { voxels: Vec<u8>, w: usize, h: usize, d: usize }
struct HalfGrid { voxels: Vec<u8>, w: usize, h: usize, d: usize, parent: usize }

impl Grid for FullGrid { ... }
impl Grid for HalfGrid { ... }

// DDA 泛型化
fn dda_walk<G: Grid>(grid: &G, ...) { ... }
```

最干净,但泛型可能影响编译时间和 inline。Casey 不用 trait(他更喜欢具体类型 + manual inlining)。

**4. Const generics 表示 mip level**:

```rust
struct VoxelGrid<const MIP: u32> {
    voxels: Vec<u8>,
}
// VoxelGrid<0> = full, VoxelGrid<1> = half
```

简洁但 const generics 在 Rust 还在演进中。

**生产代码的选择**:大型引擎用 enum + tag,如 `enum Grid { Full(...), Half(...) }`。HH 用具体字段(`voxels` + `voxels_half`),最简单。

## 4 · 认知地图

### 4.1 上级

- **Multi-resolution representation** — 同一数据多个细节层次的总称
- **Hierarchical data structure** — 树 / 金字塔 / 八叉树 都是层级结构
- **Level of detail (LOD)** — 游戏里用得多,根据距离 / 重要度选细节层

### 4.2 同级

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| Mip pyramid(本日) | 均匀降采样 | 各处精度均匀 | ✅ diffuse bounce |
| Octree | 非均匀,空区域合并 | 场景有空旷区 | Day 595 k-d tree 接近 |
| Sparse Voxel DAG | 共享子树 | 大量重复结构 | HH 不用(场景不够大) |
| Distance field | 存距离不是实体 | sphere tracing | Day 660+ 可能 |
| Brick map | 大块 + 细节贴图 | Pixar RenderMan 用 | HH 不用 |

**详细对比**:

- **Mip vs Octree**:Mip 是均匀降采样(每个粗格子大小一样),Octree 是非均匀(空区域合并成大格)。Octree 内存更省但实现复杂
- **Mip vs DAG**:DAG 共享重复子树(两面相同的墙只存一份),内存极省但构建慢
- **Mip vs Distance field**:Distance field 存"最近实体距离",sphere tracing 用它加速。Casey 没用,因为 DDA 已经够快

### 4.3 下级

- **2×2×2 max kernel** — 粗体素生成核
- **`div_ceil`** — 整数向上取整
- **`u8::max`** — 保守合并算子
- **two-level raycast** — 粗查 + 精查
- **DDA + cell size 参数** — 同算法不同分辨率

## 5 · 对照与变奏

### 同一思想在不同语境下的变体

**问题**:用低分辨率近似一个高分辨率数据,加速查询。

| 语境 | 方案 | 加速比 | 精度损失 |
|---|---|---|---|
| Texture 过滤 | Mip mapping | 4-16x | 远处轻微模糊 |
| Shadow map | Cascaded shadow | 4x | 远处分辨率低 |
| Mesh | LOD | 10-100x | 远处面数少 |
| GI(本日) | Multi-res voxel | 2x | 细物体丢失 |
| Audio | Downsample | 2-4x | 高频丢失 |
| Image pyramid (CV) | Gaussian pyramid | 可变 | 每层不同 |

### 历史演化

- **1970s**:图像金字塔出现,用于计算机视觉
- **1983**:Williams 提出 mip mapping for texture(SIGGRAPH)
- **1990s**:GPU 硬件支持 mip,texture filtering 接近免费
- **2000s**:Sparse Voxel Octree 出现(应用于医学体渲染)
- **2009**:GigaVoxels(Crassin)—— GPU 上稀疏体素 + raycast
- **2014**:Sparse Voxel DAG —— 内存压缩
- **2020s**:硬件 ray tracing + mip,Demagogue 等引擎标配

Casey 在 Day 616 实现的是最朴素的 mip pyramid——两层、CPU、无稀疏化。但对一个单人项目,这是"够用的最优"。

### Multi-resolution 的两个方向

1. **降低细节**(本日):用粗网格近似细网格,加速查询
2. **增加细节**(Voxel cone tracing):从粗网格反推细网格,但要细节用插值

**注意**:增加细节是"猜",不保证正确。降低细节是"保守",保证不漏检(用 max 合并)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么用 max 合并粗体素,而不是 average 或 min?给出三个理由。

**参考解答**:

1. **正确性(upper bound)**:max 保证粗体素"实体 ⟹ 至少一个细体素实体",所以粗网格 miss ⟹ 8 个细体素都空。这是 conservative upper bound,光线在粗网格 miss 时一定 miss 细网格,不会漏检
2. **二值性**:average 会产生 0.5 这种"半实体",失去二值语义,光照计算时模糊;max 保持二值(0 或 1),逻辑清晰
3. **速度**:`max` 是单个比较指令,比 average(两次加法 + 一次除法)快得多。在 200 万体素的网格上,每秒调用千万次,效率差异显著

### Lv2 · 动手实践

**题**:实现一个 2D 版本的 mip pyramid(更简单,容易调试)。要求:
- 全分辨率 8×8 网格,有 1 个实体格子在 (3, 3)
- 生成 mip 1(4×4)、mip 2(2×2)、mip 3(1×1)
- 打印每一层的 ASCII 表示(`.` = 空,`#` = 实体)

完成标准:`cargo run` 输出四层 mip,验证 mip 1 在 (1, 1) 是 `#`(因为 (3,3) 在 (1,1) 的覆盖区),mip 3 是 `#`(整个网格有一个实体)。

**参考解答**:

```rust
struct Grid2D {
    data: Vec<u8>,
    w: usize,
    h: usize,
}

impl Grid2D {
    fn new(w: usize, h: usize) -> Self {
        Self { data: vec![0; w*h], w, h }
    }
    fn set(&mut self, x: usize, y: usize, v: u8) {
        self.data[y * self.w + x] = v;
    }
    fn downsample(&self) -> Self {
        let nw = self.w.div_ceil(2);
        let nh = self.h.div_ceil(2);
        let mut out = Self::new(nw, nh);
        for j in 0..nh {
            for i in 0..nw {
                let mut m = 0u8;
                for dj in 0..2 {
                    for di in 0..2 {
                        let fx = 2*i + di;
                        let fy = 2*j + dj;
                        if fx < self.w && fy < self.h {
                            m = m.max(self.data[fy * self.w + fx]);
                        }
                    }
                }
                out.data[j * nw + i] = m;
            }
        }
        out
    }
    fn print(&self, label: &str) {
        println!("=== {} ({}x{}) ===", label, self.w, self.h);
        for j in 0..self.h {
            for i in 0..self.w {
                let c = if self.data[j*self.w + i] != 0 { '#' } else { '.' };
                print!("{}", c);
            }
            println!();
        }
    }
}

fn main() {
    let mut full = Grid2D::new(8, 8);
    full.set(3, 3, 1);
    full.print("mip 0");

    let mip1 = full.downsample();
    mip1.print("mip 1");

    let mip2 = mip1.downsample();
    mip2.print("mip 2");

    let mip3 = mip2.downsample();
    mip3.print("mip 3");
}
```

**预期输出**(mip 1 应该在 (1, 1) 有 `#`,因为 (3,3) 在粗网格的 (1, 1) 块):

```
=== mip 0 (8x8) ===
........
........
........
...#....
........
........
........
........
=== mip 1 (4x4) ===
....
.#..
....
....
=== mip 2 (2x2) ===
.#
..
=== mip 3 (1x1) ===
#
```

(实际 mip 1 的位置可能是 (1, 1) 或 (1, 1) 的偏移,根据坐标约定)

## 8 · Rust / Arch 落地代码

### 完整可跑的 3D Multi-resolution Voxel

```rust
// Cargo.toml: 空,纯 std

#[derive(Copy, Clone, Debug)]
struct Vec3 { x: f32, y: f32, z: f32 }
impl Vec3 {
    fn new(x: f32, y: f32, z: f32) -> Self { Self { x, y, z } }
    fn dot(self, o: Self) -> f32 { self.x*o.x + self.y*o.y + self.z*o.z }
    fn length(self) -> f32 { self.dot(self).sqrt() }
    fn normalized(self) -> Self {
        let l = self.length();
        if l > 1e-9 { Self::new(self.x/l, self.y/l, self.z/l) } else { Self::new(0.0, 0.0, 0.0) }
    }
}

struct World {
    voxels: Vec<u8>,         // mip 0
    voxels_half: Vec<u8>,    // mip 1
    w: usize, h: usize, d: usize,
    hw: usize, hh: usize, hd: usize,
}

impl World {
    fn new(w: usize, h: usize, d: usize) -> Self {
        Self {
            voxels: vec![0; w*h*d],
            voxels_half: Vec::new(),
            w, h, d,
            hw: w.div_ceil(2), hh: h.div_ceil(2), hd: d.div_ceil(2),
        }
    }
    fn set_full(&mut self, i: usize, j: usize, k: usize, v: u8) {
        self.voxels[i + j*self.w + k*self.w*self.h] = v;
    }
    fn build_half(&mut self) {
        self.voxels_half = vec![0; self.hw * self.hh * self.hd];
        for k in 0..self.hd {
            for j in 0..self.hh {
                for i in 0..self.hw {
                    let mut m = 0u8;
                    for dk in 0..2 {
                        for dj in 0..2 {
                            for di in 0..2 {
                                let fi = 2*i + di;
                                let fj = 2*j + dj;
                                let fk = 2*k + dk;
                                if fi < self.w && fj < self.h && fk < self.d {
                                    m = m.max(self.voxels[fi + fj*self.w + fk*self.w*self.h]);
                                }
                            }
                        }
                    }
                    self.voxels_half[i + j*self.hw + k*self.hw*self.hh] = m;
                }
            }
        }
    }
}

/// 通用 DDA,根据 use_half 切换网格和 cell size
#[inline]
fn dda_walk(world: &World, origin: Vec3, dir: Vec3, use_half: bool, max_steps: usize) -> Option<(usize, f32)> {
    let dir = dir.normalized();
    let cell = if use_half { 2.0 } else { 1.0 };
    let (grid_w, grid_h, grid_d, grid_data);
    if use_half {
        grid_w = world.hw; grid_h = world.hh; grid_d = world.hd;
        grid_data = &world.voxels_half;
    } else {
        grid_w = world.w; grid_h = world.h; grid_d = world.d;
        grid_data = &world.voxels;
    }

    let mut i = (origin.x / cell).floor() as i32;
    let mut j = (origin.y / cell).floor() as i32;
    let mut k = (origin.z / cell).floor() as i32;

    let step_x = if dir.x > 0.0 { 1 } else if dir.x < 0.0 { -1 } else { 0 };
    let step_y = if dir.y > 0.0 { 1 } else if dir.y < 0.0 { -1 } else { 0 };
    let step_z = if dir.z > 0.0 { 1 } else if dir.z < 0.0 { -1 } else { 0 };

    let t_delta_x = if dir.x != 0.0 { cell / dir.x.abs() } else { f32::INFINITY };
    let t_delta_y = if dir.y != 0.0 { cell / dir.y.abs() } else { f32::INFINITY };
    let t_delta_z = if dir.z != 0.0 { cell / dir.z.abs() } else { f32::INFINITY };

    let nb_x = if step_x > 0 { (i + 1) as f32 * cell } else { i as f32 * cell };
    let nb_y = if step_y > 0 { (j + 1) as f32 * cell } else { j as f32 * cell };
    let nb_z = if step_z > 0 { (k + 1) as f32 * cell } else { k as f32 * cell };

    let mut t_max_x = if dir.x != 0.0 { (nb_x - origin.x) / dir.x } else { f32::INFINITY };
    let mut t_max_y = if dir.y != 0.0 { (nb_y - origin.y) / dir.y } else { f32::INFINITY };
    let mut t_max_z = if dir.z != 0.0 { (nb_z - origin.z) / dir.z } else { f32::INFINITY };

    let mut t = 0.0;
    let mut steps = 0;
    for _ in 0..max_steps {
        if i < 0 || j < 0 || k < 0 || i as usize >= grid_w || j as usize >= grid_h || k as usize >= grid_d {
            return None;
        }
        let idx = (i as usize) + (j as usize)*grid_w + (k as usize)*grid_w*grid_h;
        if unsafe { *grid_data.get_unchecked(idx) } != 0 {
            return Some((idx, t));
        }
        steps += 1;

        if t_max_x <= t_max_y && t_max_x <= t_max_z {
            i += step_x;
            t = t_max_x;
            t_max_x += t_delta_x;
        } else if t_max_y <= t_max_z {
            j += step_y;
            t = t_max_y;
            t_max_y += t_delta_y;
        } else {
            k += step_z;
            t = t_max_z;
            t_max_z += t_delta_z;
        }
    }
    println!("DDA exhausted after {} steps", steps);
    None
}

fn main() {
    let mut world = World::new(16, 16, 16);
    // 在 (10, 10, 10) 放一个实体体素
    world.set_full(10, 10, 10, 1);
    world.build_half();

    let origin = Vec3::new(0.5, 0.5, 0.5);
    let dir = Vec3::new(1.0, 1.0, 1.0);

    // 全分辨率
    let t0 = std::time::Instant::now();
    let hit_full = dda_walk(&world, origin, dir, false, 200);
    let dt_full = t0.elapsed();

    // 半分辨率
    let t1 = std::time::Instant::now();
    let hit_half = dda_walk(&world, origin, dir, true, 200);
    let dt_half = t1.elapsed();

    println!("Full: {:?} in {:?}", hit_full.map(|(_, t)| t), dt_full);
    println!("Half: {:?} in {:?}", hit_half.map(|(_, t)| t), dt_half);
    // 半分辨率应该 t 距离接近但略小(因为 cell 大 2 倍,精度低)
    // 时间应该约一半
}
```

**关键 Rust 特性**:

- `div_ceil` — 整数除法向上取整(`usize::div_ceil` stable Rust 1.73+)
- 元组赋值 `let (a, b, c, d);` + `if ... { a = ...; }` — Rust 允许在不同分支给元组变量赋不同引用类型,因为引用是 `Copy`
- `unsafe { *grid_data.get_unchecked(idx) }` — 跳过 bounds check,hot path 必备
