# Day 608 · 可视化光照值

> Day 576-607 把光照系统搭好了,但 Casey 发现"看不见光照数据"——atlas 里存的是浮点 RGB,数字看不出问题。今天他加一个 debug overlay,把光照值"画"到屏幕上,让数据可见。

## 0 · 为什么要有这一天

光照系统跑通了,但有时画面"看起来怪"——某面墙太亮、某角落太暗。数字看不出来(每个 texel 的 RGB 在合理范围),但视觉不对。

**问题**:抽象数据(atlas 的 RGB 数组)和视觉表现之间的关系不直接。需要"可视化"——把数据变成图像。

**可视化方法**:
1. **atlas 直出**:把 atlas 当贴图,16×16 直接画到屏幕角,看辐射场长什么样
2. **热力图**:把每 texel 的标量(亮度)映射到颜色梯度(蓝→红),高对比看分布
3. **法线着色**:用法线作为颜色(法线 = 颜色),看墙体朝向是否正确
4. **路径可视化**(Day 606):看光线路径

Casey 这一天实现 1 和 2,在游戏里按 F1-F4 切换不同可视化模式。

心理锚点:看完这集,你能用多种方式可视化光照数据,理解"每种可视化揭示不同问题",能在自己写系统时主动加可视化验证。

### 严谨原理:可视化模式

**模式 1:Atlas Direct**

```rust
fn draw_atlas_direct(atlas: &LightAtlas, fb: &mut Framebuffer, x0: usize, y0: usize, scale: usize) {
    for ty in 0..atlas.dim {
        for tx in 0..atlas.dim {
            let color = atlas.texels[ty * atlas.dim + tx];
            let r = (color.r.clamp(0.0, 1.0) * 255.0) as u8;
            let g = (color.g.clamp(0.0, 1.0) * 255.0) as u8;
            let b = (color.b.clamp(0.0, 1.0) * 255.0) as u8;
            // 画到 scale × scale 区域(放大显示)
            for dy in 0..scale {
                for dx in 0..scale {
                    fb.put_pixel(x0 + tx * scale + dx, y0 + ty * scale + dy, r, g, b);
                }
            }
        }
    }
}
```

**每行解释**:
- `clamp(0, 1)` — HDR 数值可能 > 1,clamp 到 [0, 1] 才能 8 位显示。
- `scale × scale` — 把 16×16 atlas 放大到 64×64 或更大,肉眼看清楚。

**模式 2:Heatmap**

```rust
fn draw_atlas_heatmap(atlas: &LightAtlas, fb: &mut Framebuffer, x0: usize, y0: usize, scale: usize) {
    // 找最大值(用于归一化)
    let max_v: f32 = atlas.texels.iter()
        .map(|c| c.r.max(c.g).max(c.b))
        .fold(0.0, f32::max)
        .max(1e-6);
    
    for ty in 0..atlas.dim {
        for tx in 0..atlas.dim {
            let color = atlas.texels[ty * atlas.dim + tx];
            let v = color.r.max(color.g).max(color.b) / max_v;
            let heat = scalar_to_heatmap(v);  // 见 day579
            let r = (heat.r * 255.0) as u8;
            let g = (heat.g * 255.0) as u8;
            let b = (heat.b * 255.0) as u8;
            for dy in 0..scale {
                for dx in 0..scale {
                    fb.put_pixel(x0 + tx * scale + dx, y0 + ty * scale + dy, r, g, b);
                }
            }
        }
    }
}
```

**关键**:
- 归一化:用最大值除,让所有值在 [0, 1]。
- 颜色梯度:蓝(低)→ 青 → 绿 → 黄 → 红(高)。

**模式 3:Normal Colored**

```rust
fn draw_normal_colored(normal: Vec3) -> RGB {
    RGB::new(
        (normal.x + 1.0) * 0.5,  // [-1, 1] → [0, 1]
        (normal.y + 1.0) * 0.5,
        (normal.z + 1.0) * 0.5,
    )
}
```

法线方向 → RGB 颜色。+x = 红,+y = 绿,+z = 蓝。墙面渲染时用法线作为颜色,直接看朝向。

**模式 4:Lighting Difference**

比较"直接光"vs"完整 GI":

```rust
fn draw_lighting_diff(direct_only: RGB32F, full_gi: RGB32F) -> RGB {
    let diff = RGB32F::new(
        (full_gi.r - direct_only.r).abs(),
        (full_gi.g - direct_only.g).abs(),
        (full_gi.b - direct_only.b).abs(),
    );
    // 差异大 → 红,差异小 → 蓝
    ...
}
```

### 3.1 · 🎮 游戏编程视角

游戏工业里 debug 可视化是商业引擎标配:

- Albedo:基础颜色
- Normal:法线
- Roughness:粗糙度
- Metallic:金属度
- Depth:深度
- Lighting:光照
- Specular:镜面

**踩过的坑**:
- 可视化覆盖正常画面:用 PIP(picture-in-picture),在角落显示
- 可视化太密:用半透明叠加,不是替换
- 可视化性能:debug 模式可以慢,release 不能开

### 3.2 · 🎨 图形学视角

**Color Mapping** 是图形学的标准技术:
- **Linear**:[0, 1] → 黑到白
- **Heatmap**:[0, 1] → 蓝到红(感知梯度)
- **Tone mapping**:HDR [0, ∞] → [0, 1] 显示(Reinhard、ACES 等)

**Normal as Color**:法线 → 颜色是图形学调试的标准技巧。让法线可视化,立刻看出"哪面墙朝哪"。

**False Color**:用"假色"(不真实颜色)表达数据。例如温度图、压力图。Casey 的 heatmap 就是 false color。

Linux 上数据可视化的工具:
- **matplotlib**(Python):通用绘图
- **gnuplot**:经典绘图
- **perf report**:性能数据可视化
- **flamegraph**:火焰图

### 3.4 · 🦀 Rust 生态视角

Rust 实现可视化的模式:

**1. Enum + match**:

```rust
enum OverlayMode { Off, Heatmap, Normal }

fn render_overlay(fb: &mut FB, mode: OverlayMode, ...) {
    match mode {
        OverlayMode::Off => {},
        OverlayMode::Heatmap => { ... },
        OverlayMode::Normal => { ... },
    }
}
```

清晰,编译器强制 match 完整。

**2. Trait 抽象**:

```rust
trait Overlay {
    fn render(&self, fb: &mut FB);
}

struct HeatmapOverlay;
impl Overlay for HeatmapOverlay { ... }
```

灵活,但简单场景用 enum 更直接。

**3. Closure / fn pointer**:

```rust
let overlay: fn(&mut FB, ...) = match mode {
    Heatmap => draw_heatmap,
    Normal => draw_normal,
};
overlay(fb, ...);
```

最少代码,但不够灵活(closure 不能简单 switch)。

Casey 用 enum + match,清晰。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Heatmap 和 Atlas Direct 各自揭示什么不同的问题?

**参考解答**:
- **Atlas Direct**:看辐射场的"真实颜色"。揭示:整体色调、色彩平衡、HDR 数值范围。但相邻 texel 数值差小,看不出"细节分布"。
- **Heatmap**:看亮度分布(归一化后)。揭示:亮斑、暗角、空间分布。色彩被替换为"感知梯度"(蓝 → 红),让人眼快速识别高 / 低区域。

具体场景:
- Atlas Direct 发现"光照颜色偏冷"(整体偏蓝)
- Heatmap 发现"角落某个 texel 异常亮"(亮斑)

两者互补。

### Lv2 · 动手实践

**题**:实现 Atlas Direct 和 Heatmap 两种可视化,生成 PPM 文件。测试:
- 16×16 atlas,每个 texel 不同值
- 输出 atlas_direct.ppm 和 atlas_heatmap.ppm,用 feh 看

完成标准:`cargo run` 生成两个 PPM。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug, Default)]
struct RGB { r: f32, g: f32, b: f32 }
impl RGB { fn new(r: f32, g: f32, b: f32) -> Self { Self { r, g, b } } }

struct Atlas {
    texels: Vec<RGB>,
    dim: usize,
}

fn scalar_to_heatmap(v: f32) -> RGB {
    let v = v.clamp(0.0, 1.0);
    if v < 0.25 {
        RGB::new(0.0, v * 4.0, 1.0)
    } else if v < 0.5 {
        RGB::new(0.0, 1.0, 1.0 - (v - 0.25) * 4.0)
    } else if v < 0.75 {
        RGB::new((v - 0.5) * 4.0, 1.0, 0.0)
    } else {
        RGB::new(1.0, 1.0 - (v - 0.75) * 4.0, 0.0)
    }
}

fn save_ppm(path: &str, atlas: &Atlas, mode: &str) {
    use std::io::Write;
    let mut f = std::fs::File::create(path).unwrap();
    writeln!(f, "P3\n{} {}\n255", atlas.dim, atlas.dim).unwrap();
    
    let max_v: f32 = atlas.texels.iter()
        .map(|c| c.r.max(c.g).max(c.b))
        .fold(0.0, f32::max)
        .max(1e-6);
    
    for texel in &atlas.texels {
        let (r, g, b) = match mode {
            "direct" => (
                (texel.r.clamp(0.0, 1.0) * 255.0) as u8,
                (texel.g.clamp(0.0, 1.0) * 255.0) as u8,
                (texel.b.clamp(0.0, 1.0) * 255.0) as u8,
            ),
            "heatmap" => {
                let v = texel.r.max(texel.g).max(texel.b) / max_v;
                let h = scalar_to_heatmap(v);
                ((h.r * 255.0) as u8, (h.g * 255.0) as u8, (h.b * 255.0) as u8)
            },
            _ => (0, 0, 0),
        };
        writeln!(f, "{} {} {}", r, g, b).unwrap();
    }
}

fn main() {
    let mut atlas = Atlas { texels: vec![RGB::default(); 16 * 16], dim: 16 };
    // 填充:中心亮,边缘暗
    for y in 0..16 {
        for x in 0..16 {
            let dx = (x as f32 - 7.5) / 8.0;
            let dy = (y as f32 - 7.5) / 8.0;
            let d = (dx*dx + dy*dy).sqrt().min(1.0);
            let v = 1.0 - d;  // 中心 1,边缘 0
            atlas.texels[y * 16 + x] = RGB::new(v, v * 0.8, v * 0.6);
        }
    }
    
    save_ppm("/tmp/atlas_direct.ppm", &atlas, "direct");
    save_ppm("/tmp/atlas_heatmap.ppm", &atlas, "heatmap");
    println!("Saved 2 PPMs. View with: feh /tmp/atlas_direct.ppm");
}
```

```rust
// (RGB, Atlas, scalar_to_heatmap, save_ppm 同 Lv2)

fn main() {
    let mut atlas = Atlas { texels: vec![RGB::default(); 32 * 32], dim: 32 };
    
    // 填充多种模式
    for y in 0..32 {
        for x in 0..32 {
            let i = y * 32 + x;
            // 创造一个有趣的 pattern:多个光斑
            let lights = [
                (8.0, 8.0, RGB::new(1.0, 0.3, 0.3)),
                (24.0, 8.0, RGB::new(0.3, 1.0, 0.3)),
                (16.0, 24.0, RGB::new(0.3, 0.3, 1.0)),
                (16.0, 16.0, RGB::new(0.5, 0.5, 0.5)),
            ];
            let mut sum = RGB::default();
            for (lx, ly, c) in &lights {
                let dx = x as f32 - lx;
                let dy = y as f32 - ly;
                let d2 = dx*dx + dy*dy;
                let falloff = 1.0 / (1.0 + d2 * 0.1);
                sum = RGB::new(
                    sum.r + c.r * falloff,
                    sum.g + c.g * falloff,
                    sum.b + c.b * falloff,
                );
            }
            atlas.texels[i] = sum;
        }
    }
    
    save_ppm("/tmp/lighting_direct.ppm", &atlas, "direct");
    save_ppm("/tmp/lighting_heatmap.ppm", &atlas, "heatmap");
    
    println!("Generated lighting visualization:");
    println!("  /tmp/lighting_direct.ppm  - 真实颜色");
    println!("  /tmp/lighting_heatmap.ppm - 热力图(亮度分布)");
    println!("\nView with: feh /tmp/lighting_direct.ppm");
}
```

## 10 · 补充材料:光照可视化的方法学

### A.1 可视化光照值

Day 608 的主题是"可视化光照值"。光照值是浮点 RGB,不能直接看。可视化方案:

**False color mapping**:把光强度映射到颜色梯度。
- 0.0:深蓝
- 0.5:绿色
- 1.0:红色
- > 1.0(HDR):白炽

```rust
fn light_to_false_color(intensity: f32) -> RGB {
    let i = intensity.clamp(0.0, 1.0);
    if i < 0.25 {
        // 深蓝到青
        let t = i / 0.25;
        RGB::new(0, (t * 255.0) as u8, 128 + (t * 127.0) as u8)
    } else if i < 0.5 {
        // 青到绿
        let t = (i - 0.25) / 0.25;
        RGB::new(0, 255, (255.0 - t * 255.0) as u8)
    } else if i < 0.75 {
        // 绿到黄
        let t = (i - 0.5) / 0.25;
        RGB::new((t * 255.0) as u8, 255, 0)
    } else {
        // 黄到红
        let t = (i - 0.75) / 0.25;
        RGB::new(255, (255.0 - t * 255.0) as u8, 0)
    }
}
```

这样在 debug overlay 里直接看到"哪里亮哪里暗",而不只是模糊的灰度图。

**Contour lines**:等高线,标"亮度 = X"的曲线。

**Heatmap**:整体场景的热力图,显示亮度分布。

### A.3 Tone mapping

光强度是 HDR(可能 > 1.0),屏幕是 LDR(0-255)。Tone mapping 把 HDR 转 LDR。

**Reinhard**:
```rust
let mapped = intensity / (1.0 + intensity);
```

**ACES**(电影级,Unreal 默认):
```rust
fn aces_tonemap(x: f32) -> f32 {
    let a = 2.51;
    let b = 0.03;
    let c = 2.43;
    let d = 0.59;
    let e = 0.14;
    ((x * (a * x + b)) / (x * (c * x + d) + e)).clamp(0.0, 1.0)
}
```

ACES 比 Reinhard 对比度更好,色彩更"电影感"。Unreal、Unity 都默认 ACES。

### A.4 HDR 显示

HDR 显示器支持 > 1.0 亮度(直接发光,不通过 LDR 压缩)。PQ / scRGB 编码。

HDR rendering pipeline:
```
HDR linear lighting → 直接送到 HDR 显示器
无需 tone mapping(显示器自己处理)
```

HDR 显示在 PS4 Pro / Xbox One X / PS5 / Xbox Series X 普及,游戏要支持。

**3D point cloud**:每个 voxel 一个点,颜色 = 光值。

```rust
fn draw_atlas_3d(atlas: &LightAtlas, camera: &Camera, framebuffer: &mut Framebuffer) {
    for z in 0..atlas.depth {
        for y in 0..atlas.height {
            for x in 0..atlas.width {
                let light = atlas.get(x, y, z);
                if light[0] + light[1] + light[2] > 0.1 {
                    // 有光的 voxel 才画
                    let world_pos = Vec3::new(x as f32, y as f32, z as f32);
                    let screen_pos = camera.world_to_screen(world_pos);
                    framebuffer.draw_point(screen_pos, light_to_color(light));
                }
            }
        }
    }
}
```

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
