
# Day 582 · 镜面贴图转漫反射

> Phase 6 末尾 Casey 做了镜面反射(直接看光源,有尖锐高光)。Day 576+ 用八面体贴图存光照时,默认存的是"镜面光照"(Specular)——每个方向都很尖锐。但间接漫反射(Indirect Diffuse)需要"模糊版",今天 Casey 要把镜面贴图"卷积"成漫反射贴图。

## 0 · 为什么要有这一天

回顾光照模型:
- **漫反射(Diffuse / Lambert)**:光打到墙,墙朝所有方向均匀反射。视觉上墙面是均匀的颜色,无论从哪个角度看都一样。
- **镜面反射(Specular / Phong)**:光打到镜面,只朝反射方向反射。视觉上有尖锐的高光点,移动视角高光会跑。

直接光(光源 → 墙)可以分开做漫反射和镜面反射——漫反射用 Lambert `N·L` 公式,镜面用 Phong `(R·V)^n` 公式。

**间接光**(墙 → 墙)更复杂:第二次弹射的"光"已经是从一个面发出,但这个面有镜面分量(尖锐)和漫反射分量(均匀)。

Casey 在 Day 576 存到 atlas 的是"未区分的辐射场"——既包含镜面方向信息,也包含漫反射信息。但渲染采样时:
- 如果想采**间接漫反射**(墙朝所有方向反射的光),应该**平均所有方向**——给漫反射,而不是某个尖锐方向
- 如果想采**间接镜面**(墙的反射),应该**只采反射方向**——给镜面

**问题**:Casey 的辐射场 atlas 是 16×16 分辨率,直接存"每方向光强"。采样时如果是漫反射用,应该把所有方向"加权平均"——但每次采样都平均,代价大。

**解决**:预先把镜面 atlas **转换**成漫反射 atlas——把每个方向的"入射光"和法线做 Lambert 积分,得到"漫反射贡献"。这样漫反射采样 O(1) 一次,不用每次积分。

Casey 这一天写的就是这个转换函数。

心理锚点:看完这集,你能用 Rust 写一个"镜面 → 漫反射"贴图卷积,理解为什么漫反射是"球面余弦加权平均",能在自己写 BRDF 时区分"入射光场"和"出射光场"。

## 1 · Casey 今天做了什么

Casey 这一天做的:

1. **复习物理**:漫反射的物理是 Lambert 模型——光以角度 θ 打到表面,被表面朝所有方向均匀反射。出射光强 = 入射光强 × cos(θ) × 反射率。
2. **写卷积函数**:给定镜面 atlas(全方向光强),用法线 `n` 做"Lambert 余弦加权平均":

   ```
   diffuse = ∫ atlas(dir) × max(0, dir · n) dω
   ```

   离散化:对每个 atlas texel,乘以 max(0, dir·n),求和,除以 π(归一化)。
3. **存结果**:对每个 atlas 中的"主方向"(法线 n,Casey 用 atlas 自己代表的体素的法线),算漫反射贡献,存到一个新的 1×1 scalar atlas(每体素一个标量,因为漫反射是各向同性的)。
4. **接入渲染**:把渲染采样改成"漫反射从 scalar atlas,镜面从 16×16 atlas"。

这一天的工程产出大约 100 行 Rust 代码,价值在于**区分了镜面和漫反射数据流**。

## 2 · 心智模型

### 类比:激光笔 vs 灯泡

激光笔发出的光是**镜面**——所有光子朝同一方向,直射眼睛非常亮,偏一点就看不见。
灯泡发出的光是**漫反射**——光子朝所有方向均匀发射,从任何角度看都一样亮。

**转化**:如果你只有激光笔,想"模拟"灯泡,需要做的是——把激光笔在所有方向上转一圈,记录每个方向的亮度,然后求平均。得到的"平均亮度"就是灯泡的等效亮度。

**Casey 的转换**就是这种"把尖锐镜面转成均匀漫反射"——把所有方向的光强做加权平均(权重是 cos θ,因为 Lambert 漫反射是 cos 加权)。

### 严谨原理:Lambert 漫反射

Lambert 漫反射模型:对于一个表面法线为 `n` 的微元,从方向 `dir` 入射的光强 `L_i(dir)`,被反射成"朝所有方向的均匀光"。具体:

```
L_o(out_dir) = ρ_d / π × ∫_Ω L_i(dir) × max(0, dir · n) dω
```

**每项解释**:
- `L_o(out_dir)` — 出射光强(朝 out_dir 方向)。注意对 Lambert,这个值**与 out_dir 无关**——这就是"漫反射各向同性"。
- `ρ_d` — 表面反射率(0 到 1)。深色墙面 ρ_d ≈ 0.2,白色 ≈ 0.8。
- `/π` — 归一化因子,因为积分面积 = π(上半球立体角)。
- `∫_Ω` — 在上半球 Ω(法线朝向的那一半)上积分。
- `L_i(dir)` — 从 dir 方向入射的光强。
- `max(0, dir·n)` — Lambert 余弦因子。光直射(dir = n,θ=0)时为 1(最亮),光掠射(θ=90°)时为 0(无贡献)。
- `dω` — 立体角微元。

**关键**:漫反射的出射光强只取决于"法线方向 n"和"入射光场 L_i",不取决于"观察方向"。这就是为什么漫反射可以**预计算成一个标量**——给定法线,算一个数,存起来。

### 离散化

Casey 的 atlas 是 16×16,代表 256 个方向。Lambert 积分离散化:

```rust
fn specular_to_diffuse(atlas: &LightAtlas, normal: Vec3) -> RGB32F {
    let mut sum = RGB32F::default();
    // 遍历所有 texel,每个 texel 代表一个方向 + 立体角
    for ty in 0..atlas.dim {
        for tx in 0..atlas.dim {
            let u = (tx as f32 / (atlas.dim - 1) as f32) * 2.0 - 1.0;
            let v = (ty as f32 / (atlas.dim - 1) as f32) * 2.0 - 1.0;
            let dir = decode_octahedral(u, v);
            let color = atlas.texels[ty * atlas.dim + tx];
            let cos_theta = dir.dot(normal).max(0.0);
            // 立体角 dω ≈ (4π / N) where N = atlas.dim²
            let d_omega = 4.0 * std::f32::consts::PI / (atlas.dim * atlas.dim) as f32;
            sum = sum.add(color.scale(cos_theta * d_omega));
        }
    }
    // / π
    sum.scale(1.0 / std::f32::consts::PI)
}
```

**每行解释**:
- `u = (tx / (dim-1)) * 2 - 1` — texel 索引转 UV 坐标。
- `decode_octahedral(u, v)` — UV 转方向。
- `cos_theta = dir.dot(normal).max(0.0)` — Lambert 余弦因子。`max(0)` 截断下半球(背面无光)。
- `d_omega = 4π / N` — 每个 texel 对应的立体角近似(假设均匀分布)。N = 256。
- `sum += color * cos_theta * d_omega` — 黎曼和。
- `sum / π` — Lambert 归一化。

**结果**:给定一个 16×16 atlas(辐射场)和一个法线,输出一个 RGB 颜色——这就是该法线方向的漫反射贡献。

### 存到新 atlas

漫反射是各向同性,不需要存 16×16。Casey 存成 1×1 atlas(单 RGB):

```rust
struct Voxel {
    specular_atlas: LightAtlas,   // 16×16,有方向
    diffuse_color: RGB32F,        // 1 个 RGB,各向同性
    normal: Vec3,                 // 体素的法线
}

impl Voxel {
    fn update_diffuse(&mut self) {
        self.diffuse_color = specular_to_diffuse(&self.specular_atlas, self.normal);
    }
}
```

每帧更新辐射场后,跑一遍 `update_diffuse`,把"镜面辐射场"折叠成"漫反射标量"。

### 渲染采样

```rust
fn render_pixel(ray: Ray, world: &World) -> RGB32F {
    let hit = world.raycast(ray);
    if let Some((voxel, hit_pos, normal)) = hit {
        let direct = compute_direct_light(hit_pos, normal, world);
        // 间接漫反射:从体素的预计算 diffuse_color 取
        let indirect_diffuse = voxel.diffuse_color.scale(voxel.albedo);
        // 间接镜面:从 specular atlas 采反射方向(高频细节)
        let refl_dir = ray.dir.reflect(normal);
        let indirect_specular = voxel.specular_atlas.sample(refl_dir);
        direct + indirect_diffuse + indirect_specular
    } else {
        RGB32F::default()
    }
}
```

**关键**:
- 间接漫反射用预计算的 `diffuse_color`,O(1)。
- 间接镜面用 atlas `sample(reflect_dir)`,O(1)(用八面体编码)。
- 直接光每像素算(可能多次阴影 ray)。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,这种"把辐射场折叠成漫反射"是**Irradiance Map**(辐射度图)的标准做法。每个法线方向对应一个 RGB 颜色。如果存所有法线方向,需要 16×16 atlas(每个法线一个漫反射值),大小和镜面 atlas 一样。

**优化**:漫反射只取决于法线 n,可以用更紧凑的方式存——例如 SH(L2 阶 9 个系数足够)。这就是为什么 SH 在工业上流行:9 个 f32 = 36 字节 vs 16×16 RGB = 768 字节。

但 Casey 选 1×1 标量——他假设每个体素的法线**固定**(就是该体素代表的"墙的朝向"),所以漫反射也是固定的标量。代价是:如果一面墙跨越多个体素,不同体素的法线不同(因为是 3D 网格法线),边界会有微突变。

游戏工业的工业实践:
- **Irradiance Volume**:3D 网格,每格存 SH 系数(代表所有方向的漫反射)
- **DDGI**(Dynamic Diffuse Global Illumination):每格存两个 atlas,一个辐照度(Irradiance),一个距离(Distance)

### 3.2 · 🎨 图形学视角

**BRDF 概念**(Bidirectional Reflectance Distribution Function):BRDF 描述"给定入射方向和出射方向,反射多少光"。对 Lambert 漫反射,BRDF = `ρ_d / π`(常数,与方向无关)。

**卷积观点**:`specular_to_diffuse` 函数本质是**BRDF 卷积**——把"方向辐射场" `L_i(dir)` 和 BRDF `f(dir, out) = (ρ_d/π) cos(θ)` 在所有方向上做加权积分。结果就是出射光场 `L_o(out)`。

对于 Lambert BRDF,卷积结果与 out 无关(各向同性)。对于 Phong 镜面 BRDF,卷积结果依赖 out(镜面方向)。

**PBR 视角**:在基于物理的渲染(PBR)里,BRDF 通常更复杂(Cook-Torrance 模型,涉及微表面、菲涅尔、几何遮蔽)。预卷积(convolution)的复杂度更高,常常用 split-sum approximation 把 BRDF 拆成两部分分别预算。Casey 在 Phase 8 用的是简化 Lambert,不做 PBR 级别精度。

### 3.4 · 🦀 Rust 生态视角

Rust 实现卷积时,有个常被忽视的细节:**循环展开**和**累加顺序**影响浮点结果。

```rust
// 版本 A:顺序累加
let mut sum = RGB32F::default();
for ty in 0..dim {
    for tx in 0..dim {
        sum = sum.add(...);
    }
}

// 版本 B:并行分段累加再合并(rayon)
let partial: Vec<RGB32F> = (0..dim).into_par_iter().map(|ty| {
    let mut s = RGB32F::default();
    for tx in 0..dim {
        s = s.add(...);
    }
    s
}).collect();
let sum = partial.iter().copied().fold(RGB32F::default(), |a, b| a.add(b));
```

A 和 B 的浮点结果**不完全相同**——浮点加法不满足结合律(`(a+b)+c ≠ a+(b+c)` 一般)。差异通常在 1e-6 以内,但 unit test 用 `==` 比较会失败。

**Rust 解决**:`approx` crate 提供 `assert_relative_eq!`,允许误差范围比较。

```toml
[dev-dependencies]
approx = "0.5"
```

```rust
use approx::assert_relative_eq;
assert_relative_eq!(sum.r, expected.r, epsilon = 1e-4);
```

## 5 · 对照与变奏

### 同一卷积在不同语境下的变体

| 语境 | 卷积 | 结果 |
|---|---|---|
| Lambert 漫反射 | cos 加权球面积分 | 各向同性 RGB |
| Phong 镜面 | cos^n 加权球面积分 | 镜面 atlas |

| CNN(神经网络)| 学到的核卷积 | 特征图 |

数学上都是"加权积分",只是权重和定义域不同。

### 历史演化

- **1760**:Lambert 发表余弦律
- **1970s**:Phong 模型,计算机图形学 BRDF 标准化
- **1990s**:Irradiance Map 普及(预计算漫反射)
- **2010s**:PBR 兴起(Cook-Torrance BRDF),split-sum approximation 让实时 PBR 成为可能
- **2020s**:Path-Traced GI 替代预卷积(更准,但需要硬件加速)

### CPU vs GPU 卷积

- **CPU 上预算**(Casey 用):每帧 1-2 ms,可接受
- **GPU 上预算**(shader):几毫秒完成所有体素的卷积,更快
- **GPU 上运行时**(shader):每次采样实时积分,质量高但贵

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么漫反射卷积用"余弦加权"而不是"均匀加权"?用物理直觉解释。

**参考解答**:余弦加权的物理来源是"Lambert 余弦律"——一束光以角度 θ 打到表面,这束光的能量分散到一个更大的"投影面积"上(=原面积 / cos θ),所以单位面积接收到的能量正比于 cos θ。直射(θ=0)最亮,掠射(θ=90°)最暗。

均匀加权假设"所有方向光同等贡献"——这是错的。如果你想的是"半球的总光通量"(物理量单位是流明),均匀加权对的;但如果你想的是"墙面的反射亮度"(物理量单位是尼特),必须用余弦加权。

```rust
fn specular_to_diffuse(atlas: &LightAtlas, normal: Vec3) -> RGB32F {
    let mut sum = RGB32F::default();
    let d_omega = 4.0 * std::f32::consts::PI / (atlas.dim * atlas.dim) as f32;
    for ty in 0..atlas.dim {
        for tx in 0..atlas.dim {
            let u = (tx as f32 / (atlas.dim - 1) as f32) * 2.0 - 1.0;
            let v = (ty as f32 / (atlas.dim - 1) as f32) * 2.0 - 1.0;

            let color = atlas.texels[ty * atlas.dim + tx];
            let cos_theta = dir.dot(normal).max(0.0);
            sum = sum.add(color.scale(cos_theta * d_omega));
        }
    }
    sum.scale(1.0 / std::f32::consts::PI)
}

fn main() {
    let mut atlas = LightAtlas::new(16);
    let light_dir = Vec3 { x: 0.0, y: 0.0, z: 1.0 };
    atlas.accumulate(light_dir, RGB32F::new(1.0, 0.0, 0.0));
```

```rust
    atlas.accumulate(Vec3 { x: 0.0, y: 1.0, z: 0.0 }, RGB32F::new(1.0, 0.95, 0.9));
    // 加一些环境光(所有方向少量)
    for i in 0..32 {
        let t = i as f32 * 0.196;
        let dir = Vec3 {
            x: t.sin(),
            y: (t * 1.3).sin(),
            z: (t * 2.7).sin(),
        }.normalize();
        atlas.accumulate(dir, RGB32F::new(0.05, 0.05, 0.06));
    }

    // 测试几个法线方向的漫反射
    let normals = [
        (Vec3 { x: 0.0, y: 1.0, z: 0.0 }, "up"),
        (Vec3 { x: 0.0, y: -1.0, z: 0.0 }, "down"),
        (Vec3 { x: 1.0, y: 0.0, z: 0.0 }, "+x"),
        (Vec3 { x: 0.0, y: 0.0, z: 1.0 }, "+z"),
    ];
    for (n, name) in &normals {
        let d = specular_to_diffuse(&atlas, *n);
        println!("Normal={}: diffuse={:?}", name, d);
    }
}
```

### A.2 Voxel lighting 的工程挑战

Voxel lighting 是计算机图形学的难点,因为:

**1. 数据量大**:
- 大场景(100m × 100m × 100m)有几百万 voxel
- 每 voxel 存光照值(RGB 或 SH)
- 总数据 GB 级

**2. 实时性要求**:
- 玩家挖 / 改 voxel,光照立即变化
- 16.67 ms 帧预算(60 FPS)
- 不能阻塞玩家操作

**3. 物理准确性**:
- 直接光(sun)
- 间接光(bounce)
- 阴影(hard / soft)
- 反射(diffuse / specular)
- 折射(glass / water)

工业方案在物理准确性和实时性之间权衡。

### A.3 工业级实现的层次

**Layer 1:Brute force**
- 每 voxel × 每方向 raycast
- 准确但极慢
- 适合离线渲染(movie)

**Layer 2:Grid DDA**
- 快速 raycast(穿格子)
- 适合简单场景
- Casey 的 HH 用这层

**Layer 3:Precomputed**
- 离线算光照 cache
- 运行时查表
- 适合静态场景(Minecraft baked)

**Layer 4:Real-time approximation**
- LPV / SVOGI / Voxel Cone Tracing
- 实时但近似
- Crytek / Unreal 用

**Layer 5:Hardware ray tracing**
- RTX / RDNA2 核心
- 真实光传播
- Minecraft RTX / Teardown

每代技术对硬件要求递增。Casey 的 HH 在 Layer 2(教学优先)。

### A.4 性能 profile 的实战

Casey 在 phase-8 多次 profile:

**Profile 工具**:
- Linux:perf、Valgrind、flamegraph
- Windows:Superluminal、VTune
- 跨平台:Tracy

**典型发现**:
- Raycast 占 50%+
- Propagation 占 20%+
- Meshing 占 10%+
- 其他占 20%

**优化顺序**:
1. 最慢函数 → 算法优化

### A.7 Voxel lighting 算法的核心循环

让我写一个简化的 voxel lighting 主循环:

```rust
fn update_lighting(world: &mut World, sun_dir: Vec3) {
    let direct = compute_direct_lighting(world, sun_dir);
    let indirect = compute_indirect_lighting(world, &direct, 3);  // 3 bounce
    let final_light = combine(&direct, &indirect);
    world.light_atlas = final_light;
}

fn compute_direct_lighting(world: &World, sun_dir: Vec3) -> LightAtlas {
    let mut atlas = LightAtlas::new(world.dims());
    for each voxel {
        if voxel.is_solid() && !is_occluded(world, voxel_pos, sun_dir) {
            let lambert = compute_normal(world, x, y, z).dot(sun_dir).max(0.0);
            atlas.set(x, y, z, sun_color * lambert);
        }
    }
    atlas
}

fn compute_indirect_lighting(world: &World, direct: &LightAtlas, bounces: usize) -> LightAtlas {
    let mut current = direct.clone();
    for _ in 0..bounces {
        let mut next = current.clone();
        for each voxel {
            let bounce = average_neighbors(&current, x, y, z) * 0.15;
            next.set(x, y, z, current.get(x, y, z) + bounce);
        }
        current = next;
    }
    current
}
```

这是 Casey phase-8 的简化核心。工业实现更复杂(SH、GPU、并行)。

### A.8 Voxel lighting 的内存估算

```
  - light: 4 byte RGBE

场景尺寸:
  - 32^3(教学):36 KB
  - 100^3(小场景):9 MB
  - 256^3(中场景):150 MB
  - 1024^3(大场景):9.6 GB

```

### A.16 性能优化的层次(L1-L5)

**L1: 算法选择**
- O(N²) → O(N log N)
- 例: bubble sort → quicksort

**L2: 数据布局**
- AoS → SoA
- 例: Vec<Voxel> → struct { Vec<u8> materials, ... }

**L3: Micro**
- inline、branchless、SIMD
- 例: SIMD 4-wide float

**L4: 并行**
- multi-thread、SIMD、GPU
- 例: rayon par_iter

**L5: 架构**
- streaming、incremental、async
- 例: chunked world

每层收益递减难度递增。Proflier 决定优化哪层。
