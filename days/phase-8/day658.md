
# Day 658 · 处理手套碰撞

> HH 玩家装备一个"手套"(glove)——既是攻击武器也是拾取工具。手套有自己的碰撞体(独立于玩家球),需要单独处理。今天 Casey 把"多碰撞体实体"集成到体素碰撞系统。

## 0 · 为什么要有这一天

回顾 Day 637:玩家用一个球做碰撞体。但游戏里玩家有时有"装备"——剑、枪、手套。装备**不是玩家身体的一部分**,有自己的形状和碰撞需求。

- 玩家碰到墙,墙挡玩家
- 手套碰墙,墙挡手套,但**不影响玩家**(手套可能缩回)
- 手套碰到敌人,触发攻击效果
- 手套碰到物品,触发拾取

这就要求"多碰撞体"——一个 Entity 有多个 collision shape,各自独立碰撞,但共享 Entity 的位置。

工业游戏的标准做法:**主碰撞体**(玩家球)+ **辅助碰撞体**(手套、剑、盾)。主碰撞体决定移动,辅助碰撞体检测交互(攻击、拾取)。

心理锚点:看完今天,你能:

- 实现多碰撞体实体
- 区分"碰撞阻挡"和"碰撞检测"
- 设计装备的 hitbox 系统

## 1 · Casey 今天做了什么

1. 在 Entity 结构里加 `secondary_shapes: Vec<CollisionShape>`
2. 玩家主碰撞体(球)参与 unembed
3. 手套碰撞体(小球,偏移在玩家前方)只做 hit detection(查 overlap),不做 unembed
4. 手套 hit detection:每帧扫手套覆盖的 voxel / 实体,触发对应效果
5. 加"手套状态":缩回 / 伸出。缩回时不参与碰撞
6. 测试:玩家伸出手套,碰到敌人,敌人受伤;碰到墙,手套"卡在墙里",玩家不卡
7. 处理边角:手套穿墙时缩回(避免视觉错位)

## 2 · 心智模型

### 类比:打伞

你打伞时,伞的"占用空间"远大于你的身体:

- 伞碰到树枝——伞可能挂住,但你不会(你站在树下不卡)
- 你碰到墙——你卡住,但伞没事
- 别人碰到伞——可能戳到别人(交互!)

伞 vs 身体的关系,就是手套 vs 玩家的关系。**两者各自有碰撞规则,但共享位置**。

### 主碰撞体 vs 辅助碰撞体

| 类型 | 作用 | 影响 pos |
|---|---|---|
| 主碰撞体 | 决定移动 / unembed | ✅ |
| 辅助碰撞体 | 检测交互(攻击、拾取) | ❌ |

辅助碰撞体只读"碰到了什么",不写"位置应该怎样"。

### 实现:CollisionShape 列表

```rust
struct Entity {
    pos: Vec3,
    main_shape: CollisionShape,  // 主碰撞体
    aux_shapes: Vec<AuxShape>,   // 辅助碰撞体
}

struct CollisionShape {
    shape: Shape, // Sphere / AABB / Capsule
    offset: Vec3,
}

struct AuxShape {
    shape: CollisionShape,
    active: bool,    // 当前是否激活
    tag: ShapeTag,   // 用途:Glove / Weapon / Pickup
}

enum ShapeTag { Glove, Sword, Pickup, Hitbox }
```

每帧 update:

1. 用 main_shape 做 collision + unembed,更新 pos
2. 对每个 active 的 aux_shape,扫描覆盖区域,找碰撞物
3. 根据 tag 触发对应行为

### Hit detection 实现

```rust
fn check_aux_hits(world: &World, e: &Entity) -> Vec<HitEvent> {
    let mut events = Vec::new();
    for aux in &e.aux_shapes {
        if !aux.active { continue; }
        let world_pos = e.pos + aux.shape.offset;
        match aux.shape.shape {
            Shape::Sphere { radius } => {
                // 扫球覆盖的 voxel
                for_each_voxel_near(world_pos, radius, |v| {
                    if world.is_solid(v) {
                        events.push(HitEvent::Wall(aux.tag, v));
                    }
                });
                // 扫其他实体
                for other in world.entities() {
                    if other.id == e.id { continue; }
                    if sphere_overlap(world_pos, radius, other) {
                        events.push(HitEvent::Entity(aux.tag, other.id));
                    }
                }
            }
            Shape::AABB { half } => { /* similar */ }
        }
    }
    events
}
```

`HitEvent` 是事件流,游戏逻辑消费触发效果。

### 手套状态机

手套有状态:

- **Retracted**(收回):默认状态,aux_shape.active = false
- **Extending**(伸出中):动画 0.1 秒,active = true,offset 逐渐增加
- **Extended**(完全伸出):持续 0.3 秒
- **Retracting**(收回中):offset 减少
- **Retracted**(回到默认)

状态机用 enum:

```rust
enum GloveState {
    Retracted,
    Extending { t: f32 },  // t 是动画进度 0-1
    Extended { t: f32 },   // t 是持续时间
    Retracting { t: f32 },
}
```

每次按攻击键,触发 Retracted → Extending → Extended → Retracting → Retracted。

### 手套"穿墙"

手套可能穿墙(因为它只 hit detection,不 collision)。这视觉上奇怪——手套从墙里伸出来。

修法:**手套伸出前 raycast**。如果手要伸到的位置被墙挡,**手套伸出距离缩短**(只伸到墙前)。

```rust
fn extend_glove(player: &Entity, max_distance: f32) -> f32 {
    let dir = player.facing;
    let from = player.pos + player.facing * 0.5; // 玩家边缘
    // raycast 防穿墙
    if let Some(t) = raycast_solid(from, dir, max_distance) {
        t * 0.9 // 留一点余量
    } else {
        max_distance
    }
}
```

这就是 Day 650 shadow bias 的另一种应用——光线起点离玩家边缘一点,防 self-collision。

### 3.4 · Rust 生态视角

Rust 里多碰撞体:

```rust
use glam::Vec3;

#[derive(Clone, Debug)]
enum Shape {
    Sphere { radius: f32 },
    AABB { half: Vec3 },
}

#[derive(Clone, Debug)]
struct CollisionShape {
    shape: Shape,
    offset: Vec3,
}

#[derive(Clone, Debug)]
struct Entity {
    pos: Vec3,
    main: CollisionShape,
    aux: Vec<CollisionShape>,
}

impl Entity {
    fn all_shapes(&self) -> impl Iterator<Item = (Vec3, &Shape)> {
        std::iter::once((self.pos + self.main.offset, &self.main.shape))
            .chain(self.aux.iter().map(|s| (self.pos + s.offset, &s.shape)))
    }
}
```

`std::iter::once(x).chain(iter)` 把单个值和迭代器链起来,优雅。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么手套不做 unembed,只做 hit detection?

**参考解答**:手套是"工具",不是玩家身体的一部分。如果手套 unembed(把玩家推开),玩家会因为"手套碰墙"被推飞,这不合理——手套应该缩回,而不是把玩家推开。所以手套只检测"碰到了什么",触发交互(攻击 / 拾取),不参与位置纠正。主碰撞体(玩家球)做 unembed,保证玩家不卡墙。

```rust
use glam::Vec3;

#[derive(Clone, Debug)]
enum Shape {
    Sphere { radius: f32 },
    AABB { half: Vec3 },
}

#[derive(Clone, Debug)]
struct CollisionShape {
    shape: Shape,
    offset: Vec3,
}

#[derive(Clone, Debug)]
struct Entity {
    pos: Vec3,
    main: CollisionShape,
    aux: Vec<CollisionShape>,
}

impl Entity {
    fn all_shapes(&self) -> Vec<(Vec3, &Shape)> {
        let mut v = vec![(self.pos + self.main.offset, &self.main.shape)];
        for s in &self.aux {
            v.push((self.pos + s.offset, &s.shape));
        }
        v
    }
}

fn main() {
    let e = Entity {
        pos: Vec3::ZERO,
        main: CollisionShape { shape: Shape::Sphere { radius: 0.4 }, offset: Vec3::ZERO },
        aux: vec![
            CollisionShape { shape: Shape::Sphere { radius: 0.2 }, offset: Vec3::new(1.0, 0.0, 0.0) },
        ],
    };
    for (p, s) in e.all_shapes() {
        println!("Shape at {:?}: {:?}", p, s);
    }
}
```

## 8 · Rust / Arch 落地代码

完整手套碰撞系统:

```rust
// Cargo.toml:
// [dependencies]
// glam = "0.29"

use glam::{Vec3, IVec3};

#[derive(Clone, Debug, PartialEq)]
enum Shape {
    Sphere { radius: f32 },
}

#[derive(Clone, Debug)]
struct CollisionShape {
    shape: Shape,
    offset: Vec3,
}

#[derive(Clone, Debug, PartialEq)]
enum GloveState {
    Retracted,
    Extending { t: f32 },
    Extended { t: f32 },
    Retracting { t: f32 },
}

#[derive(Clone, Debug)]
struct Entity {
    pos: Vec3,
    facing: Vec3,
    main: CollisionShape,
    glove_state: GloveState,
    glove_max_reach: f32,
}

impl Entity {
    fn new() -> Self {
        Self {
            pos: Vec3::ZERO,
            facing: Vec3::new(1.0, 0.0, 0.0),
            main: CollisionShape {
                shape: Shape::Sphere { radius: 0.4 },
                offset: Vec3::ZERO,
            },
            glove_state: GloveState::Retracted,
            glove_max_reach: 1.5,
        }
    }
    fn trigger_glove(&mut self) {
        if self.glove_state == GloveState::Retracted {
            self.glove_state = GloveState::Extending { t: 0.0 };
        }
    }
    fn current_glove_offset(&self) -> Option<Vec3> {
        let reach = match &self.glove_state {
            GloveState::Retracted => return None,
            GloveState::Extending { t } => *t * self.glove_max_reach,
            GloveState::Extended { .. } => self.glove_max_reach,
            GloveState::Retracting { t } => (1.0 - *t) * self.glove_max_reach,
        };
        Some(self.facing * (0.5 + reach))
    }
    fn update_glove(&mut self, dt: f32, solid: &dyn Fn(IVec3) -> bool) {
        // raycast 防穿墙(简化:只看 facing 方向第一格)
        let check_pos = self.pos + self.facing * 0.5;
        let check_voxel = check_pos.round().as_ivec3();
        let blocked = solid(check_voxel);

        let speed = 5.0; // 状态推进速度
        match &mut self.glove_state {
            GloveState::Retracted => {}
            GloveState::Extending { t } => {
                *t += dt * speed;
                if *t >= 1.0 || blocked {
                    *t = 1.0;
                    self.glove_state = GloveState::Extended { t: 0.0 };
                }
            }
            GloveState::Extended { t } => {
                *t += dt;
                if *t >= 0.3 {
                    self.glove_state = GloveState::Retracting { t: 0.0 };
                }
            }
            GloveState::Retracting { t } => {
                *t += dt * speed;
                if *t >= 1.0 {
                    self.glove_state = GloveState::Retracted;
                }
            }
        }
    }
    fn check_glove_hits(&self, targets: &[Vec3]) -> Vec<usize> {
        let Some(glove_offset) = self.current_glove_offset() else { return vec![]; };
        let glove_pos = self.pos + glove_offset;
        let glove_radius = 0.2;
        let mut hits = vec![];
        for (i, target) in targets.iter().enumerate() {
            let d = (glove_pos - *target).length();
            if d < glove_radius + 0.3 { // 0.3 = target radius
                hits.push(i);
            }
        }
        hits
    }
}

fn main() {
    let mut player = Entity::new();
    let targets = vec![
        Vec3::new(2.0, 0.0, 0.0),
        Vec3::new(5.0, 0.0, 0.0),
    ];
    let no_solid = |_v: IVec3| false;

    player.trigger_glove();
    for frame in 0..30 {
        player.update_glove(1.0 / 60.0, &no_solid);
        let hits = player.check_glove_hits(&targets);
        if !hits.is_empty() {
            println!("Frame {}: state={:?}, hits={:?}", frame, player.glove_state, hits);
        }
    }

    // 测试穿墙:把 facing 方向设为 solid
    let wall_solid = |v: IVec3| -> bool { v.x == 1 && v.y == 0 && v.z == 0 };
    player.pos = Vec3::ZERO;
    player.facing = Vec3::new(1.0, 0.0, 0.0);
    player.glove_state = GloveState::Retracted;
    player.trigger_glove();
    player.update_glove(1.0 / 60.0, &wall_solid);
    println!("After 1 frame in wall: state={:?}", player.glove_state);
    // 应该立刻进入 Extended(被墙挡)
}
```

## 10 · 工程反思

Day 658 传达的核心工程教训:**复合形状(compound shape)是 collision 的实用主义**。

新手以为"每个物体一个形状",资深工程师知道复杂物体(角色 / 车 / 家具)需要**多个形状组合**。比如人形角色:

- 头:球
- 身体:胶囊
- 四肢:胶囊
- 武器:OBB

每个部分单独 collision,组合成"复合形状"。这给精确 collision,但代价是性能(N 个形状 vs 1 个)。

**复合形状的设计**:

```rust
struct CompoundShape {
    parts: Vec<(Transform, Shape)>,  // 每个 part 的局部 transform + 形状
}

impl CompoundShape {
    fn collide(&self, other: &Shape) -> Option<Contact> {
        for (t, s) in &self.parts {
            if let Some(c) = s.collide(other, t) {
                return Some(c);
            }
        }
        None
    }
}
```

简单循环。性能优化:broad phase 跳过不重叠的 part。

**工业级实现**:

- **Box2D**:b2CompoundShape
- **Bullet**:btCompoundShape
- **PhysX**:PxCompoundShape
- **rapier**:SharedShape::compound

每个物理引擎都有。Casey 在 HH 用 simplified 版本(hand-authored hitbox 列表)。

**第二条教训**:**hitbox 设计是格斗游戏的核心**。

街头霸王 / 铁拳 / 任天堂明星大乱斗的每个角色,有几百个 hitbox:

- **idle 站立**:1 个 capsule(身体)
- **走路**:2 个 capsule(双腿动态)
- **攻击**:5-10 个 hitbox(拳头 / 脚 / 武器,每帧不同)
- **受击**:3-5 个 hurtbox(头 / 身 / 腿)

设计师逐帧调整 hitbox,平衡游戏。这是工业级 hitbox 工程的复杂度。

**第三条教训**:**hitbox 可视化是必需**。

设计师看不到 hitbox 就无法调参。所以每个格斗游戏 dev mode 都有 hitbox overlay——画每个 hitbox,设计师实时调整。

Casey 在 HH Day 638 录制器扩展就能做这个。Day 658 演示的是这个思路的最简版本。

**迁移到其他领域**:

"复合形状"思路在多处通用:

- **机器学习**:ensemble model(多个 model 投票)
- **数据库**:composite index(多列索引)
- **UI**:composite widget(多个 widget 组合)
- **设计**:design system(component 组合)
- **编程**:composite pattern(GoF 设计模式)

每个领域都有"组合简单件成复杂件"的需求。Casey 在 HH 演示的是 collision 版本。

## 11 · Hitbox 数据驱动设计

工业级 hitbox 系统是**数据驱动**——设计师编辑 hitbox 数据,工程师实现加载 + 应用。

**数据格式**:

```json
{
  "entity_type": "player",
  "hitboxes": [
    {
      "name": "body",
      "shape": "capsule",
      "a": [0, -0.5, 0],
      "b": [0, 0.5, 0],
      "radius": 0.3
    },
    {
      "name": "head",
      "shape": "sphere",
      "center": [0, 0.6, 0],
      "radius": 0.15
    }
  ],
  "animations": {
    "attack": {
      "frame_5": {
        "hitboxes": [
          {"name": "fist", "shape": "sphere", "center": [0.8, 0, 0], "radius": 0.1, "damage": 50}
        ]
      }
    }
  }
}
```

设计师调整 JSON,无需改代码。运行时加载 JSON,实例化 hitbox。

**Animation-driven hitbox**:

每个动画帧有自己的 hitbox 集合:

- 站立时:body + head
- 走路时:body + head + 上臂 + 下臂 + 大腿 + 小腿
- 攻击第 5 帧:body + head + fist(攻击 hitbox)

这是格斗游戏的精细度。资深工程师的实现:**skeletal animation 系统 + hitbox 绑定到骨骼**。

## 12 • Hitbox 的性能优化

复杂角色 50+ hitbox,每帧测试 N 个 hitbox vs M 个 hurtbox,N*M 复杂度爆炸。优化:

**1. Broad phase**:

- AABB 包围所有 hitbox,只测 hurtbox 在 AABB 内的
- Spatial hash 加速

**2. Frame skipping**:

- 攻击 hitbox 只在 active 帧激活,其他帧不测
- 节省 90% 计算

**3. LOD**:

- 远离相机的角色用简化 hitbox(单胶囊)
- 近景才用完整 hitbox

**4. Multithreading**:

- 每个角色独立测试,可并行
- 大型战斗游戏(战神、对马岛之魂)用 ECS + data parallel

每个优化让 hitbox 系统跑百角色同屏。Casey 在 HH 单角色,工业级是 100+ 角色。

## N0 • 深度教学补充

### 核心概念重新梳理

Day 658 涉及的核心概念需要在多个层次上理解:

**第一层:直观理解**

新手第一次接触概念,需要建立直觉。例如 voxel collision 是"虚拟物体不能穿过虚拟墙"——这个直觉每个人都能从现实经验获得。

**第二层:数学理解**

把直觉形式化。collision = "两个几何体的体积有交集"。对于 AABB,这等价于"三轴投影都重叠"。

**第三层:工程理解**

数学正确不等于工程实现正确。要考虑:

- 浮点精度边界
- 性能(每帧 N 个查询)
- 内存(数据结构紧凑)
- 边角 case(无穷大、NaN、负数)

**第四层:工业理解**

工业级要再加:

- 多线程安全
- SIMD 优化
- 网络同步(多人游戏)
- 跨平台(Windows/Mac/Linux/Mobile)
- 可访问性(色盲友好)
- 反作弊

每层理解都让代码更鲁棒。资深工程师在所有层次同时思考。

### 实际工程的细节

工业代码 80% 是"边角 case 处理",20% 是"核心算法"。Casey 在 HH 演示核心,工业代码加大量边角处理。

**边角 case 类型**:

1. 空输入(空 Vec、null pointer)
2. 极端输入(NaN、无穷大、超大数)
3. 并发竞争(多线程同时访问)
4. 资源不足(内存满、磁盘满)
5. 网络异常(超时、断连、包丢失)
6. 版本不兼容(老配置 / 新代码)
7. 权限错误(只读文件、无网络)
8. 用户误操作(连点、撤销重做)

每个 case 都要单独处理。这是工业代码 50%+ 行数的原因。

### 优化思路

性能优化有顺序:

1. **算法**:O(N²) → O(N log N),最大提升
2. **数据结构**:Vec → HashMap / BTreeMap,常数提升
3. **Cache**:AoS → SoA,cache 命中提升
4. **SIMD**:4-16 元素并行,巨大常数提升
5. **GPU**:数千核并行,极致性能
6. **分布式**:多机器,无限扩展

每级提升都需要更复杂的代码。先优化低级,够用再升级。

Day 658 用 C 写,但 Rust 版本会更安全 / 更高效:
