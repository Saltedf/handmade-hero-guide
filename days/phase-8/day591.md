# Day 591 · 制作独立光照性能测试

> Day 590 起草了 DDA 优化,但 Casey 担心优化效果"无法量化"。游戏里的帧率受很多因素影响(渲染、AI、音频),光照改进的 1-2 ms 可能被其他模块抖动盖住。今天他做一个独立的 benchmark——只跑光照,精确测量。

## 0 · 为什么要有这一天

游戏里跑 60 FPS,你能说"光照优化让帧率从 30 升到 60"吗?不能。因为帧率受多个因素影响:
- 渲染:8-10 ms
- 光照:2-4 ms
- AI / 物理:3-5 ms
- 操作系统调度:1-2 ms

如果光照从 4 ms 降到 2 ms,理论帧时间从 16-18 ms 降到 14-16 ms。但实际帧率可能没明显变化(其他因素占主导)。

**问题**:如何精确测量光照本身的性能?

**解决**:做一个独立的 benchmark——程序只跑光照,不渲染、不读输入、不播音频。所有时间都花在光照上,可以精确测量。

这是工程化的"性能验证"方法。游戏工业里,所有性能优化都要先写 benchmark,证明优化真的有效,再合并到主代码。

Casey 这一天做的是 Handmade Hero 的"光照 benchmark harness"——一个独立的 main 函数,加载场景数据,跑 N 次光照更新,报告时间。

心理锚点:看完这集,你能写一个 Rust benchmark 程序,理解"为什么 game-loop 内测性能不可靠",能用 `criterion` / 手写计时器精确测量代码性能。

## 1 · Casey 今天做了什么

Casey 这一天的几个动作:

1. **创建独立 binary**:在 `Cargo.toml` 加 `[[bin]]` 段,新增 `lighting_bench` binary,与主游戏分开编译。
2. **加载测试场景**:从文件读一个固定的"测试场景"(墙体布局、光源位置),保证每次 benchmark 一致。
3. **跑光照**:不渲染,只跑 `propagate_infinite_bounces`。1000 帧。
4. **报告统计**:总时间、平均每帧、最慢帧、95% 分位。

这一天的工程产出大约 100 行 Rust 代码,价值在于**让光照性能可量化、可复现**。

## 2 · 心智模型

### 类比:跑步测速

你想测一辆车开得多快。两种方法:

**方法 1(集成测)**:让车在城市里开,记录总时间。问题:红绿灯、堵车、限速影响车速,测出来是"城市平均速度",不是"车的最大速度"。

**方法 2(独立测)**:把车开到测试场,只有车,没有红绿灯、没有其他车。测出来是"车的真实最大速度"。

光照 benchmark 完全一样:
- 集成测(在游戏里测帧率):受其他模块影响,不准
- 独立测(benchmark 程序):只有光照,精确

### 严谨原理:benchmark 方法论

**好 benchmark 的标准**:

1. **可复现**:每次跑结果一致(用固定场景数据,不随机)
2. **可比较**:有"基线版本"和"优化版本",对比看加速比
3. **可解释**:报告多个指标(平均、最慢、95%),不只看平均
4. **足够长**:跑几秒到几分钟,避免抖动
5. **预热**:先跑几次 warm-up(填满 cache),再正式测

**关键指标**:
- **平均时间**(mean):总体性能
- **中位数**(median):不受 outlier 影响
- **95% / 99% 分位**:看"大部分帧"和"最坏帧"的差别
- **标准差**(stdev):稳定性

### Rust 实现

**方法 1:手写计时器**(Casey 用):

```rust
use std::time::Instant;

fn benchmark_lighting(world: &mut World, n_frames: usize) {
    // 预热
    for _ in 0..10 {
        propagate_infinite_bounces(world, 8);
    }
    
    // 正式测
    let mut frame_times = Vec::with_capacity(n_frames);
    for _ in 0..n_frames {
        let start = Instant::now();
        propagate_infinite_bounces(world, 8);
        frame_times.push(start.elapsed());
    }
    
    // 统计
    let total: std::time::Duration = frame_times.iter().sum();
    let mean = total / n_frames as u32;
    let mut sorted: Vec<_> = frame_times.clone();
    sorted.sort();
    let median = sorted[n_frames / 2];
    let p95 = sorted[(n_frames as f32 * 0.95) as usize];
    let p99 = sorted[(n_frames as f32 * 0.99) as usize];
    
    println!("Mean:   {:?}", mean);
    println!("Median: {:?}", median);
    println!("P95:    {:?}", p95);
    println!("P99:    {:?}", p99);
}
```

**每行解释**:
- `Instant::now()` — 纳秒级计时器,Linux 上用 `clock_gettime(CLOCK_MONOTONIC)`。
- `start.elapsed()` — 返回 Duration。
- `n_frames / 2` — 中位数(排序后中间值)。
- `0.95 as usize` — 95% 分位(排序后第 95% 位置的值)。

**方法 2:用 `criterion` crate**(工业标准):


### 测试场景加载

```rust
fn load_test_scene() -> World {
    let mut world = World::new();
    // 从 JSON / RON / 自定义格式加载
    let data = std::fs::read_to_string("test_scene.json").unwrap();
    let scene: SceneData = serde_json::from_str(&data).unwrap();
    for voxel_data in scene.voxels {
        world.add_voxel(voxel_data.pos, voxel_data.albedo);
    }
    for light_data in scene.lights {
        world.add_light(light_data.pos, light_data.color);
    }
    world
}
```

**关键**:
- 场景数据固定(每次跑一样)
- 不依赖游戏状态(完全独立)

### 报告格式

```rust
fn report_stats(frame_times: &[std::time::Duration]) {
    let total: std::time::Duration = frame_times.iter().sum();
    let n = frame_times.len();
    let mean_ns = total.as_nanos() as f64 / n as f64;
    
    let mut sorted: Vec<_> = frame_times.to_vec();
    sorted.sort();
    let median_ns = sorted[n / 2].as_nanos() as f64;
    let p95_ns = sorted[(n as f32 * 0.95) as usize].as_nanos() as f64;
    let p99_ns = sorted[(n as f32 * 0.99) as usize].as_nanos() as f64;
    
    let mean_ms = mean_ns / 1e6;
    let median_ms = median_ns / 1e6;
    let p95_ms = p95_ns / 1e6;
    let p99_ms = p99_ns / 1e6;
    
    println!("=== Lighting Benchmark ===");
    println!("Frames: {}", n);
    println!("Mean:   {:.3} ms ({:.1} fps equivalent)", mean_ms, 1000.0 / mean_ms);
    println!("Median: {:.3} ms", median_ms);
    println!("P95:    {:.3} ms", p95_ms);
    println!("P99:    {:.3} ms", p99_ms);
}
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,benchmark 是性能优化的核心。商业引擎都内置 profiling 工具:
- **Unreal Engine**:Session Frontend,实时显示各模块耗时
- **Unity**:Profiler,逐帧时间分解
- **自研引擎**:类似 Casey 的独立 benchmark

**Benchmark 类型**:
- **Microbenchmark**:测单个函数(如 specular_to_diffuse)
- **Macrobenchmark**:测整个系统(如光照)
- **End-to-end**:测整帧(游戏循环)

Casey 在 Day 591 做 Macrobenchmark(光照系统),Day 587 已经做过 Microbenchmark(specular_to_diffuse)。

**踩过的坑**:
- **缓存污染**:第一次跑时数据不在 cache,慢。解决:预热
- **编译器优化**:迭代内容相同,编译器只算一次。解决:`black_box`
- **操作系统调度**:其他进程抢占 CPU,帧时间抖动。解决:多次测量取中位数
- **CPU 频率调节**:Turbo Boost 让 CPU 时钟波动。解决:固定频率(`cpupower frequency-set -g performance`)

### 3.2 · 🎨 图形学视角

图形学的 benchmark 有特殊性——需要考虑 GPU。GPU benchmark 不能像 CPU 那样简单"调用前后计时",需要:
- **GPU Timer Query**:OpenGL / Vulkan 有 `glQueryCounter`,GPU 端计时
- **Pipeline Stall**:GPU pipeline 阶段,数据传输开销
- **Async Compute**:GPU 可以并行计算不同 pass

Casey 在 CPU 端做光照,CPU benchmark 就够。GPU 渲染部分(Phase 5+)需要 GPU timer。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上做 benchmark 的几个工具:

**1. CPU 固定频率**(避免 Turbo Boost 抖动):

```bash
sudo cpupower frequency-set -g performance
# 把 CPU 调度策略设为 performance(始终最高频)
# 测完后恢复:
sudo cpupower frequency-set -g powersave
```

**2. 进程优先级**(避免被其他进程抢占):

```bash
sudo nice -n -20 ./lighting_bench
# nice 值 -20 是最高优先级(只有 root 能给负值)
```

**3. CPU 亲和性**(绑定到固定核,避免迁移):

```bash
taskset -c 0 ./lighting_bench
# 只在 CPU 0 跑
```

**4. perf 多次测量**(自动统计):

```bash
sudo perf stat -r 10 ./lighting_bench
# -r 10 = 跑 10 次,输出平均值和标准差
# 输出:
#  1.234 ms +- 0.045 ms (10 runs)
```

**5. 火焰图**(看函数热点):

```bash
sudo perf record -F 99 -g ./lighting_bench
sudo perf script | flamegraph.pl > flame.svg
# 浏览器打开 flame.svg,看哪个函数占时间最多
```

**6. 限制内存带宽**(测 cache 行为):

```bash
sudo perf stat -e cache-misses,cache-references,L1-dcache-load-misses ./lighting_bench
```

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 benchmark 需要"预热"?预热具体做什么?

**参考解答**:预热让程序运行几次后,把数据填到 CPU cache。第一次跑时,数据在主存(慢,几百 ns / 访问);预热后,数据在 L1 / L2 cache(快,几 ns / 访问)。

具体:
- 预热前:第一帧光照,所有 atlas 数据从主存读,慢
- 预热后:数据在 cache,后续帧快

如果不预热,第一帧的"冷"数据会拉低平均时间,不准。

预热次数:通常 5-10 次足够(数据量 1-10 MB,缓存足够放下)。

### Lv2 · 动手实践

**题**:写一个 benchmark 函数,测试某个简单计算(如 `sum_atlas_brightness`)。报告 mean / median / p95。

完成标准:`cargo run --release` 打印统计。

**参考解答**:

```rust
use std::time::{Duration, Instant};

fn sum_atlas_brightness(atlas: &[f32]) -> f32 {
    let mut sum = 0.0;
    for &v in atlas {
        sum += v;
    }
    sum
}

fn benchmark(atlas: &[f32], n_iters: usize) {
    // 预热
    for _ in 0..5 {
        std::hint::black_box(sum_atlas_brightness(atlas));
    }
    
    // 测量
    let mut times: Vec<Duration> = Vec::with_capacity(n_iters);
    for _ in 0..n_iters {
        let start = Instant::now();
        let result = sum_atlas_brightness(atlas);
        times.push(start.elapsed());
        std::hint::black_box(result);
    }
    
    // 统计
    let total: Duration = times.iter().sum();
    let mean = total / n_iters as u32;
    let mut sorted = times.clone();
    sorted.sort();
    let median = sorted[n_iters / 2];
    let p95 = sorted[(n_iters as f32 * 0.95) as usize];
    
    println!("Iters: {}", n_iters);
    println!("Mean:   {:?}", mean);
    println!("Median: {:?}", median);
    println!("P95:    {:?}", p95);
}

fn main() {
    let atlas: Vec<f32> = (0..256).map(|i| i as f32 * 0.01).collect();
    benchmark(&atlas, 10_000);
}
```

## 8 · Rust / Arch 落地代码

完整可跑示例:

```rust
use std::time::{Duration, Instant};

fn compute_something(n: usize) -> f32 {
    let mut sum = 0.0f32;
    for i in 0..n {
        sum += (i as f32).sin() * (i as f32).cos();
    }
    sum
}

struct BenchmarkResult {
    mean: Duration,
    median: Duration,
    p95: Duration,
    p99: Duration,
    min: Duration,
    max: Duration,
    n_samples: usize,
}

fn benchmark<F: Fn()>(n_warmup: usize, n_measure: usize, f: F) -> BenchmarkResult {
    // 预热
    for _ in 0..n_warmup {
        f();
    }
    
    // 测量
    let mut times: Vec<Duration> = Vec::with_capacity(n_measure);
    for _ in 0..n_measure {
        let start = Instant::now();
        f();
        times.push(start.elapsed());
    }
    
    // 统计
    times.sort();
    let total: Duration = times.iter().sum();
    let mean = total / n_measure as u32;
    let median = times[n_measure / 2];
    let p95 = times[(n_measure as f32 * 0.95) as usize];
    let p99 = times[(n_measure as f32 * 0.99) as usize];
    let min = times[0];
    let max = times[n_measure - 1];
    
    BenchmarkResult {
        mean, median, p95, p99, min, max, n_samples: n_measure,
    }
}

impl BenchmarkResult {
    fn report(&self, name: &str) {
        println!("=== {} ===", name);
        println!("Samples: {}", self.n_samples);
        println!("  Mean:   {:?}", self.mean);
        println!("  Median: {:?}", self.median);
        println!("  Min:    {:?}", self.min);
        println!("  Max:    {:?}", self.max);
        println!("  P95:    {:?}", self.p95);
        println!("  P99:    {:?}", self.p99);
    }
}

fn main() {
    let result = benchmark(10, 10_000, || {
        let r = compute_something(1000);
        std::hint::black_box(r);
    });
    result.report("compute_something(1000)");
}
```

## 10 · 补充材料:Phase 8 深度主题

Phase 8(day576-667)是 voxel lighting 系统的完整构建,涉及多个深度主题。

### A.2 Voxel lighting 的核心问题

工业级 voxel lighting 解决以下核心问题:

**1. 计算量**:
- 大场景(几百万 voxel)
- 每 voxel 要算多方向光
- 每方向要 raycast(检查遮挡)

**2. 实时性**:
- 玩家编辑 voxel(挖 / 放)
- 光照要立即更新
- 16.67 ms 帧预算

**3. 内存**:
- 每 voxel 存光照值(RGB 或 SH)
- 大场景内存爆炸
- 需要 streaming

**4. 准确性**:
- 直接光(sun)
- 间接光(bounce)
- 阴影(soft / hard)
- 反射(diffuse / specular)

工业方案在这些问题之间权衡。Casey 的 HH 教基础权衡。

### A.3 性能优化的具体技术

**Spatial partitioning**:
- Grid:固定大小 voxel,直接索引
- Octree:稀疏,只存有内容的节点
- BVH:bounding volume hierarchy,GPU 友好
- k-d tree:递归 axis-aligned split

**Temporal coherence**:
- 帧间复用(上一帧光照 + 增量)
- TAA(temporal anti-aliasing)
- 时序累积(低噪点)

**Level of detail**:
- 远处 voxel 粗采样
- 近处 voxel 精细
- mipmap voxel atlas

**GPU compute**:
- Vulkan / DX12 / Metal compute shader
- 自定义 ray tracing shader
- RTX 核心加速

### A.4 Rust 实现的 voxel 引擎

Rust 生态的 voxel 引擎:

### A.8 Voxel lighting 算法的具体实现细节

让我深入讲讲 voxel lighting 算法的实现细节:

**Direct lighting**(直接光):

```rust
fn compute_direct_lighting(
    world: &World,
    sun_dir: Vec3,
    sun_color: RGB,
) -> LightAtlas {
    let mut atlas = LightAtlas::new(world.width, world.height, world.depth);
    
    for z in 0..world.depth {
        for y in 0..world.height {
            for x in 0..world.width {
                if world.get(x, y, z).is_air() { continue; }
                
                // 检查是否被遮挡(从 voxel 到 sun 方向)
                let voxel_pos = Vec3::new(x as f32 + 0.5, y as f32 + 0.5, z as f32 + 0.5);
                let ray = Ray::new(voxel_pos, sun_dir);
                let occluded = grid_dda(world, ray, 100.0).is_some();
                
                if !occluded {
                    // 计算法线(根据邻居)
                    let normal = compute_normal(world, x, y, z);
                    let lambert = normal.dot(sun_dir).max(0.0);
                    let light = sun_color * lambert;
                    atlas.set(x, y, z, light);
                }
            }
        }
    }
    
    atlas
}
```

**Indirect lighting**(间接光 / bounce):

```rust
fn compute_indirect_lighting(
    world: &World,
    direct: &LightAtlas,
    bounces: usize,
) -> LightAtlas {
    let mut current = direct.clone();
    
    for _ in 0..bounces {
        let mut next = current.clone();
        
        for z in 0..world.depth {
            for y in 0..world.height {
                for x in 0..world.width {
                    if world.get(x, y, z).is_air() { continue; }
                    
                    // 累加 6 邻居的光(简化 diffuse)
                    let mut accumulated = RGB::black();
                    for (dx, dy, dz) in NEIGHBORS_6 {
                        let nx = x as i32 + dx;
                        let ny = y as i32 + dy;
                        let nz = z as i32 + dz;
                        if nx >= 0 && ny >= 0 && nz >= 0 {
                            let n_light = current.get(nx as u32, ny as u32, nz as u32);
                            accumulated += n_light * 0.15;  // bounce factor
                        }
                    }
                    
                    let cur = current.get(x, y, z);
                    next.set(x, y, z, cur + accumulated);
                }
            }
        }
        
        current = next;
    }
    
    current
}
```

### A.9 Voxel 法线计算

Voxel 表面法线计算:

```rust
fn compute_normal(world: &World, x: u32, y: u32, z: u32) -> Vec3 {
    // Sobel filter 算法线(类似图像边缘检测)
    let mut sx = 0.0; let mut sy = 0.0; let mut sz = 0.0;
    
    for dz in -1i32..=1 {
        for dy in -1i32..=1 {
            for dx in -1i32..=1 {
                let nx = x as i32 + dx;
                let ny = y as i32 + dy;
                let nz = z as i32 + dz;
                let density = if in_bounds(world, nx, ny, nz) && world.get(nx, ny, nz).is_solid() {
                    1.0
                } else { 0.0 };
                sx += dx as f32 * density;
                sy += dy as f32 * density;
                sz += dz as f32 * density;
            }
        }
    }
    
    Vec3::new(sx, sy, sz).normalize()
}
```

法线用于 Lambert / Phong 光照计算。
