## 2 · 心智模型

### 类比:自来水管网

间接光照可以类比自来水管网:

- **水源**(直接光):阳光照到屋顶
- **管道节点**(辐射场):每个节点存储"我这里有水,能向哪些方向流出多少"
- **水流**(光传播):水从屋顶流到管道节点,再从节点流到下一级节点
- **用户**(屏幕像素):最终用户打开水龙头,从最近的节点取水

**关键点**:水管的每个节点不能"自己生水",它只能"接收上游的水,再向下游分发"。间接光照也是一样——每个体素的辐射场不是"自己发光",而是"接收来自其他方向的光,再向其他方向反射"。

整个系统需要解决两个问题:
1. **水流计算**(propagate):给定直接光源,算每个节点的辐射场
2. **水流取用**(sample):给定用户位置和方向,从最近的节点取辐射值

### 严谨原理:数据流

Casey 的间接光照数据流:

```
[阶段 1: 直接光 propagate]
  for each light source:
    for each visible voxel:
      ray = light_pos → voxel_pos
      if no occlusion:
        direction = -ray.dir
        color = light.color * attenuation
        voxel.atlas.accumulate(direction, color)

[阶段 2: 间接光 propagate(一次弹射)]
  for each voxel A:
    for each direction d in A.atlas:
      color = A.atlas.sample(d)
      ray = A.pos along d
      find nearest voxel B hit by ray
      B.atlas.accumulate(-d, color * reflectance)

[阶段 3: 渲染采样]
  for each screen pixel:
    ray = camera → pixel
    hit voxel V at hit_pos with normal n
    color = direct_light + V.atlas.sample(-ray.dir) * albedo
    framebuffer.put(pixel, color)
```

**阶段 1** 把直接光"注入"到辐射场。**阶段 2** 让辐射场之间互相"传递"(光的弹射)。**阶段 3** 渲染时从辐射场采样。

**问题**:阶段 2 一次只算"一次弹射"。要算"无限弹射"(光在场景里弹无限次),需要**迭代**——多次跑阶段 2,每次都是"上次结果的再弹射"。

```rust
// 无限弹射 GI(伪代码)
fn propagate_infinite_bounces(world: &mut World, iterations: usize) {
    propagate_direct(world);  // 阶段 1
    for _ in 0..iterations {
        propagate_indirect(world);  // 阶段 2,重复
    }
}
```

iterations 越多,光弹越多,光照越准。Casey 在 Day 584 用 8-16 次迭代,基本收敛。

### 调度:不要每帧全更新

每帧跑 `propagate_infinite_bounces` 1000 个体素 × 16 次迭代 × 256 个方向 = 400 万次操作,可能 30-50 ms 一帧,跑不到 60 FPS。

**调度策略**:不是每帧跑所有体素,而是分批。每帧只跑 1/16 的体素,16 帧覆盖所有体素。

```rust
struct World {
    atlases: Vec<LightAtlas>,
    voxels: Vec<Voxel>,
    update_index: usize,  // 下一个要更新的体素
    update_batch_size: usize,
}

impl World {
    fn update_one_frame(&mut self) {
        let start = self.update_index;
        let end = (start + self.update_batch_size).min(self.voxels.len());
        for i in start..end {
            self.propagate_indirect_for_voxel(i);
        }
        self.update_index = end % self.voxels.len();
    }
}
```

**每行解释**:
- `update_index` — round-robin 指针,记录下一个要更新的体素。
- `update_batch_size` — 每帧更新多少个。1000 个体素 / 60 帧 = 16 个 / 帧。
- `end % self.voxels.len()` — 循环回到开头。

**代价**:每个体素的辐射场不是每帧最新,有 16 帧(0.27 秒)的延迟。Casey 在 Day 588 优化时把"对齐相机"——相机附近的体素更新频率高,远处更新频率低——降低视觉影响。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业里,这种"分批更新辐射场"叫 **Amortized Lighting Update**。商业引擎(Unreal、Unity)的 Light Propagation Volume、Irradiance Volume 都用类似策略——分批更新避免每帧开销爆炸。

**工业上更复杂的优化**:
- **重要性采样**:玩家视野内的体素优先更新(因为玩家能看到)
- **时间一致性**:用上一帧的辐射场做"预测",这一帧只更新变化部分(temporal coherence)
- **级联分辨率**:近处体素 32×32,远处 8×8(类似 cascaded shadow map)

Casey 在 Day 581 用最简单的 round-robin,Day 588 加"相机对齐",Day 590+ 加性能测试。

**踩坑**:
- **更新太频繁**:每帧全更新,跑不到 30 FPS
- **更新太稀疏**:每个体素 30 帧才更新一次,场景动态变化(光源移动)时玩家看到"延迟响应"
- **更新抖动**:round-robin 顺序固定,玩家观察到"扫描"伪影。解决:加抖动,让更新顺序随机化

### 3.2 · 🎨 图形学视角

间接光照的物理本质是**全局光照**(Global Illumination, GI)。完整 GI 解法是**辐射度方法**(Radiosity):

```
对于场景所有面元 A_i, A_j:
  F_ij = 形状因子(从 A_i 看见 A_j 的比例)
求解线性方程组 B_i = E_i + ρ_i * Σ F_ij * B_j
```

辐射度方法是 1980s 的算法,假设所有面是 Lambert(漫反射),解线性方程组得到每个面的"辐射度"。优点:精确、收敛后无闪烁。缺点:场景大就 explode(面数 N² 的形状因子),不能做镜面反射。

Casey 的"迭代传播"是辐射度方法的**松弛求解**(Gauss-Seidel iteration)——不一次解方程,而是反复迭代逼近。每次迭代让每个 atlas 从邻居采样、累积,逐步收敛到平衡。

**收敛性**:理论上收敛,但收敛速度取决于"光在场景里传播的难度"——开阔场景快,密集遮挡场景慢。Casey 在 Day 584 实验 8 次迭代够不够,不够再加。

### 3.3 · 🐧 Linux 系统编程视角

这一集主要是数据流和调度,Linux 系统调用面没什么。但有一个**多线程**的话题值得提。

阶段 2 的"每个体素独立采样所有方向"是**可并行**的——多个体素同时更新,没有数据竞争(只要不同体素的 atlas 不重叠)。Linux 上用 pthread / Rust 的 `rayon`:

```rust
// 串行版本(慢)
for i in 0..voxels.len() {
    propagate_indirect_for_voxel(i);
}

// 并行版本(用 rayon)
use rayon::prelude::*;
voxels.par_iter_mut().enumerate().for_each(|(i, voxel)| {
    propagate_indirect_for_voxel(i, voxel);
});
```

Casey 在 Day 590+ 性能测试阶段会考虑多线程。Day 581 还是串行,先把逻辑跑通。

Linux 上验证并行加速:

```bash

./your_game_parallel &
top -p $!
# 如果 CPU 利用率 < 100%,说明只用 1 核,多线程没启用
# 如果 800%(8 核满载),说明 rayon 工作正常
```

### 3.4 · 🦀 Rust 生态视角

Rust 表达"分批更新"很优雅,因为所有权系统保证"主循环不会意外全跑":

```rust
struct FrameBudget {
    update_batch_size: usize,  // 每帧最多更新多少体素
}

impl World {
    fn update_within_budget(&mut self, budget: &FrameBudget) {
        let mut updated = 0;
        while updated < budget.update_batch_size {
            let i = self.next_update_index();
            self.propagate_indirect_for_voxel(i);
            updated += 1;
        }
    }
}
```

**关键 Rust 特性**:
- `&mut self` — 独占借用,保证 update 期间没有其他代码改 world 状态。
- `next_update_index()` — 一个内部方法,封装 round-robin 指针管理。

Casey 的代码里充满这种"小封装",让函数职责单一,易测试。

**rayon crate**:

```toml
# Cargo.toml
[dependencies]
rayon = "1.10"
```

```rust
use rayon::prelude::*;

// 把 par_iter 换成 iter 就是串行

    let atlases = std::mem::take(&mut world.atlases);  // 取走避免借用冲突
    atlases.par_iter().enumerate().for_each(|(i, atlas)| {
        // 注意:这里只能读 atlas,不能写(因为是 &T)

```

**所有权陷阱**:多个线程同时写 `Vec<LightAtlas>` 需要每个 atlas 互相独立(没有共享邻居)。Casey 的"每个体素独立更新辐射场"满足这个条件——只要不同体素的 atlas 不互相影响(实际有影响,因为体素之间要传光)。Day 590+ 会处理这个数据竞争问题。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么"分批更新"(每帧只跑 1/16 的体素)能节省时间?具体是哪部分的开销被分摊掉了?

**参考解答**:开销分摊的是**计算量**——每帧跑 1/16 体素,每帧计算量是全跑的 1/16。但**内存开销**没省(每个体素的 atlas 仍要存),**延迟增加了**(每个体素的最新数据延迟 16 帧)。这种"用延迟换算力"的工程权衡在实时渲染里很常见,叫 **Amortized** 或 **Time-Sliced**。

### Lv2 · 动手实践

**题**:实现一个最小的 `LightingPipeline` 结构,包含:
- `update_one_frame(world: &mut World, budget: usize)` — 每帧更新 budget 个体素
- round-robin 调度

测试:
- 1000 个体素,每帧更新 16 个
- 模拟 100 帧,验证每个体素至少被更新过一次

完成标准:`cargo run` 打印每个体素被更新的次数,所有体素至少被更新 1 次。

**参考解答**:

```rust
struct Voxel {
    pos: Vec3,
    atlas: LightAtlas,
    update_count: usize,
}

struct World {
    voxels: Vec<Voxel>,
    next_update: usize,
}

impl World {
    fn new(n_voxels: usize) -> Self {
        Self {
            voxels: (0..n_voxels).map(|_| Voxel {
                pos: Vec3 { x: 0.0, y: 0.0, z: 0.0 },
                atlas: LightAtlas::new(16),
                update_count: 0,
            }).collect(),
            next_update: 0,
        }
    }

    fn update_one_frame(&mut self, budget: usize) {
        let n = self.voxels.len();
        for _ in 0..budget {
            let i = self.next_update;
            self.voxels[i].update_count += 1;
            // 实际 propagate 在这里(本练习省略)
            self.next_update = (self.next_update + 1) % n;
        }
    }
}

fn main() {
    let mut world = World::new(1000);
    for _ in 0..100 {
        world.update_one_frame(16);
    }
    // 验证每个体素至少更新 1 次
    let min_count = world.voxels.iter().map(|v| v.update_count).min().unwrap();
    let max_count = world.voxels.iter().map(|v| v.update_count).max().unwrap();
    println!("Min updates: {}, Max updates: {}", min_count, max_count);
    assert!(min_count >= 1);
    // 1000 个体素,100 帧 × 16 = 1600 次更新,平均 1.6 次/体素
}
```

**每行解释**:
- `next_update` — round-robin 指针。
- `(self.next_update + 1) % n` — 循环回卷。模运算代价低(几个时钟周期)。
- 测试 100 帧 × 16 = 1600 次更新 / 1000 体素 = 1.6 次/体素,所以 min ≥ 1。

### A.2 Voxel lighting 的核心问题

工业级 voxel lighting 解决以下核心问题:

**1. 计算量**:
- 大场景(几百万 voxel)
- 每 voxel 要算多方向光
- 每方向要 raycast(检查遮挡)

**2. 实时性**:
- 玩家编辑 voxel(挖 / 放)
- 光照要立即更新
- 16.67 ms 帧预算

**3. 内存**:
- 每 voxel 存光照值(RGB 或 SH)
- 大场景内存爆炸
- 需要 streaming

**4. 准确性**:
- 直接光(sun)
- 间接光(bounce)
- 阴影(soft / hard)
- 反射(diffuse / specular)

工业方案在这些问题之间权衡。Casey 的 HH 教基础权衡。

### A.3 性能优化的具体技术

**Spatial partitioning**:
- Grid:固定大小 voxel,直接索引
- Octree:稀疏,只存有内容的节点
- BVH:bounding volume hierarchy,GPU 友好
- k-d tree:递归 axis-aligned split

**Temporal coherence**:
- 帧间复用(上一帧光照 + 增量)
- TAA(temporal anti-aliasing)
- 时序累积(低噪点)

**Level of detail**:
- 远处 voxel 粗采样
- 近处 voxel 精细
- mipmap voxel atlas

**GPU compute**:
- Vulkan / DX12 / Metal compute shader
- 自定义 ray tracing shader
- RTX 核心加速

### A.8 Voxel lighting 算法的具体实现细节

让我深入讲讲 voxel lighting 算法的实现细节:

**Direct lighting**(直接光):

```rust
fn compute_direct_lighting(
    world: &World,
    sun_dir: Vec3,
    sun_color: RGB,
) -> LightAtlas {
    let mut atlas = LightAtlas::new(world.width, world.height, world.depth);
    
    for z in 0..world.depth {
        for y in 0..world.height {
            for x in 0..world.width {
                if world.get(x, y, z).is_air() { continue; }
                
                // 检查是否被遮挡(从 voxel 到 sun 方向)
                let voxel_pos = Vec3::new(x as f32 + 0.5, y as f32 + 0.5, z as f32 + 0.5);
                let ray = Ray::new(voxel_pos, sun_dir);
                let occluded = grid_dda(world, ray, 100.0).is_some();
                
                if !occluded {
                    // 计算法线(根据邻居)
                    let normal = compute_normal(world, x, y, z);
                    let lambert = normal.dot(sun_dir).max(0.0);
                    let light = sun_color * lambert;
                    atlas.set(x, y, z, light);
                }
            }
        }
    }
    
    atlas
}
```

**Indirect lighting**(间接光 / bounce):

```rust
fn compute_indirect_lighting(
    world: &World,
    direct: &LightAtlas,
    bounces: usize,
) -> LightAtlas {
    let mut current = direct.clone();
    
    for _ in 0..bounces {
        let mut next = current.clone();
        
        for z in 0..world.depth {
            for y in 0..world.height {
                for x in 0..world.width {
                    if world.get(x, y, z).is_air() { continue; }
                    
                    // 累加 6 邻居的光(简化 diffuse)
                    let mut accumulated = RGB::black();
                    for (dx, dy, dz) in NEIGHBORS_6 {
                        let nx = x as i32 + dx;
                        let ny = y as i32 + dy;
                        let nz = z as i32 + dz;
                        if nx >= 0 && ny >= 0 && nz >= 0 {
                            let n_light = current.get(nx as u32, ny as u32, nz as u32);
                            accumulated += n_light * 0.15;  // bounce factor
                        }
                    }
                    
                    let cur = current.get(x, y, z);
                    next.set(x, y, z, cur + accumulated);
                }
            }
        }
        
        current = next;
    }
    
    current
}
```

### A.9 Voxel 法线计算

Voxel 表面法线计算:

```rust
fn compute_normal(world: &World, x: u32, y: u32, z: u32) -> Vec3 {
    // Sobel filter 算法线(类似图像边缘检测)
    let mut sx = 0.0; let mut sy = 0.0; let mut sz = 0.0;
    
    for dz in -1i32..=1 {
        for dy in -1i32..=1 {
            for dx in -1i32..=1 {
                let nx = x as i32 + dx;
                let ny = y as i32 + dy;
                let nz = z as i32 + dz;
                let density = if in_bounds(world, nx, ny, nz) && world.get(nx, ny, nz).is_solid() {
                    1.0
                } else { 0.0 };
                sx += dx as f32 * density;
                sy += dy as f32 * density;
                sz += dz as f32 * density;
            }
        }
    }
    
    Vec3::new(sx, sy, sz).normalize()
}
```

法线用于 Lambert / Phong 光照计算。
