# Day 242 · OpenGL 上下文升级

> Day 241 你启用了 sRGB 和 VSync,但有些 GL 函数报"invalid operation"——因为你的 context 太旧。OpenGL 有"版本"概念,context 创建时定版本,后续不能改。今天 Casey 升级 context 到 3.3+,解锁现代 API。

## 0 · 为什么要有这一天

OpenGL 从 1992 年到现在演化了 30 多年,API 变化巨大:

- **OpenGL 1.x**(1992-2003)—— 固定管线,`glVertex` 逐顶点
- **OpenGL 2.x**(2004)—— 引入 GLSL shader
- **OpenGL 3.0**(2008)—— 废弃固定管线(deprecation),但保留兼容
- **OpenGL 3.2**(2009)—— 引入 **Core Profile**(只现代 API)和 **Compatibility Profile**(包含 deprecated)
- **OpenGL 3.3**(2010)—— 现代基础,主流起点
- **OpenGL 4.x**(2010+)—— tessellation、compute shader、indirect draw 等

context 创建时你选 profile + version,driver 据此给你 context。不同 profile 下,API 行为不同:

- Core Profile:VAO 强制,`glVertexPointer` 不可用,只能 shader
- Compatibility Profile:`glBegin/glEnd` 还能用(老式)

Day 235 你创建了 OpenGL 3.3 Core context,但有些扩展(Day 241 的 sRGB)在老 context 上不存在。Day 242 升级 context,确保所有现代功能可用。

**为什么这件事重要**:context 是 OpenGL 的"运行环境"。理解它的版本 / profile / 扩展加载,是排查"为什么这函数报错"的基础。

**心理锚点**:看完今天,你能用 `glGetString(GL_VERSION)` 打印 context 信息,知道你的程序支持什么特性。

## 1 · Casey 今天做了什么

Casey 发现 Day 241 的 sRGB 在某些机器上失效,因为 context 默认 2.0,没有 sRGB 扩展。他重写 context 创建:

1. 用 `wglCreateContextAttribsARB`(Windows)/ `glXCreateContextAttribsARB`(Linux)创建 context
2. 显式指定 version 3.3 + Core Profile
3. 请求 sRGB capable + debug context
4. 验证 `glGetString(GL_VERSION)` 返回 "3.3"
5. 重新测试 sRGB,工作正常

**关键决策**:**debug context** —— OpenGL 提供 debug output 扩展,driver 主动 push 警告/错误到 callback。开发时启用,发布时关掉。

## 2 · 心智模型

### 类比:操作系统版本

你装的软件需要 OS 版本(Windows 10 / Ubuntu 22.04)。OpenGL context 一样:不同版本支持不同特性。低版本 OS 装不了新版软件,低版本 context 用不了新 GL 函数。

升级 context 就是"换更高版本的 OS"——一旦创建不能改,要重建。

### 2.1 context 创建参数

```rust
let attrs = glutin::context::ContextAttributesBuilder::new()
    .with_context_api(glutin::context::ContextApi::OpenGl(
        glutin::context::Version::new(3, 3)  // OpenGL 3.3
    ))
    .with_profile(glutin::context::GlProfile::Core)  // Core Profile
    .with_debug(true)  // 启用 debug context(可选)
    .with_srgb(true)   // 请求 sRGB capable(可选)
    .build(Some(window_handle));  // Some = window context,None = offscreen
```

**关键参数**:

- **version** —— `Version::new(3, 3)` 或 `Version::new(4, 6)`,越高功能越多
- **profile** —— Core(纯现代)或 Compatibility(含 deprecated)
- **debug** —— 开发用,driver 主动报错。生产关掉(性能影响)
- **srgb** —— 请求 sRGB capable pixel format,Day 241 sRGB 必须
- **forward_compatible** —— 严格拒绝 deprecated 函数(更纯净)

### 2.2 上下文创建失败的处理

老 GPU / 老驱动不支持 OpenGL 3.3。你要 fallback:

```rust
let context = try_create_gl_46()
    .or_else(|_| try_create_gl_33())
    .or_else(|_| try_create_gles_30())
    .expect("GPU 不支持任何现代 OpenGL");
```

策略:

1. 先试最高版本(4.6)
2. 失败则降到 3.3(广泛支持)
3. 失败则试 GLES 3.0(移动端 OpenGL ES,某些老 GPU 支持)

跟 HH 学只考虑 3.3,够用。

### 2.3 GL 扩展加载

OpenGL 是"最小核心 + 扩展"模型。driver 可能支持超出 core 的扩展(如 `GL_NV_raytracing`)。检查扩展:

```rust
unsafe {
    let num_extensions = {
        let mut n = 0;
        gl.get_integer_iv(glow::NUM_EXTENSIONS, &mut n);
        n as usize
    };
    let mut extensions = Vec::with_capacity(num_extensions);
    for i in 0..num_extensions {
        let name = gl.get_string_indexed(glow::EXTENSIONS, i as u32);
        if let Some(s) = name {
            extensions.push(s.to_string());
        }
    }

    if !extensions.contains(&"GL_EXT_framebuffer_sRGB".to_string()) {
        eprintln!("警告:不支持 framebuffer sRGB");
    }
}
```

glow 提供 `supported_extensions()` 直接拿 set:

```rust
unsafe {
    let exts: HashSet<String> = gl.supported_extensions();
    if !exts.contains("GL_EXT_framebuffer_sRGB") {
        // ...
    }
}
```

**Core in version** —— OpenGL 3.0+ 把很多扩展并入 core。如 `GL_EXT_framebuffer_sRGB` 在 3.0+ 是 core,不再需要查扩展。但旧 driver 可能仍按扩展名报。

### 2.4 Debug Context

```rust
unsafe {
    gl.enable(glow::DEBUG_OUTPUT);
    gl.debug_message_callback(|source, ty, id, severity, msg| {
        let src_str = match source {
            glow::DEBUG_SOURCE_API => "API",
            glow::DEBUG_SOURCE_SHADER_COMPILER => "Shader",
            glow::DEBUG_SOURCE_THIRD_PARTY => "3rd party",
            glow::DEBUG_SOURCE_APPLICATION => "App",
            _ => "Other",
        };
        let ty_str = match ty {
            glow::DEBUG_TYPE_ERROR => "ERROR",
            glow::DEBUG_TYPE_DEPRECATED_BEHAVIOR => "DEPRECATED",
            glow::DEBUG_TYPE_UNDEFINED_BEHAVIOR => "UNDEFINED",
            glow::DEBUG_TYPE_PERFORMANCE => "PERFORMANCE",
            glow::DEBUG_TYPE_OTHER => "OTHER",
            _ => "?",
        };
        eprintln!("[GL {} {} {}] {}", src_str, ty_str, id, msg);
    });
}
```

任何 GL 错误(用错 enum、shader 警告、性能提示)都会 callback。**生产强烈推荐开发时开**。

glow 的 callback 是 `Fn`,不能捕获环境。要传上下文用 `unsafe { static mut STATE: ... }` 或 `AtomicUsize`。

### 2.5 context 信息查询

```rust
unsafe {
    let vendor = gl.get_parameter_string(glow::VENDOR);
    let renderer = gl.get_parameter_string(glow::RENDERER);
    let version = gl.get_parameter_string(glow::VERSION);
    let glsl_version = gl.get_parameter_string(glow::SHADING_LANGUAGE_VERSION);

    println!("Vendor: {}", vendor);
    println!("Renderer: {}", renderer);
    println!("OpenGL version: {}", version);
    println!("GLSL version: {}", glsl_version);
}
```

输出类似:

```
Vendor: Intel
Renderer: Mesa Intel(R) UHD Graphics (IRL GT2)
OpenGL version: 4.6 (Compatibility Profile) Mesa 24.2.7
GLSL version: 4.60
```

**关键检查**:

- `version` 里的 `4.6` 是实际支持的最高版本,不一定是你的 context 版本
- `renderer` 显示真 GPU;如果是 `llvmpipe`,你在软件渲染(慢)
- `GLSL version` 决定 shader 能写什么

### 2.6 Wayland / X11 / EGL

Linux 上 context 创建有两套 API:

- **GLX**(OpenGL Extension to X)—— X11 原生
- **EGL**(Embedded-system Graphics Library)—— Wayland / 嵌入式用

glutin 自动选:Wayland 用 EGL,X11 用 GLX(或 EGL,看你 build flag)。

```bash
# 看你装的 GL 实现
ls /usr/lib/libGL* /usr/lib/libEGL*
# 输出:libGL.so.1  libEGL.so.1

# 看 EGL 实现
eglinfo  # 工具
# 没装:sudo pacman -S mesa-utils
```

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**多 GPU 系统**(笔记本双显卡:Intel 集显 + NVIDIA 独显):

Linux 用 **PRIME** 切换 GPU。context 创建在哪个 GPU 上,渲染就跑哪个 GPU。

```bash
# 看系统有几个 GPU
lspci | grep -i vga
# 输出:
# 00:02.0 VGA compatible controller: Intel ...
# 01:00.0 VGA compatible controller: NVIDIA ...

# 强制 NVIDIA:
__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia ./game
# 强制 Intel(默认):
./game
```

游戏启动时检测 GPU,选合适的渲染质量(独显高、集显低)。

**Mesa 软件 fallback** —— 没有 GPU 加速时,Mesa 提供 `swrast` / `llvmpipe` 软件渲染。游戏能跑但慢(几 FPS)。你检测到 `renderer` 含 `llvmpipe` 时,警告用户。

### 3.2 · 🎨 图形学视角

**OpenGL 各版本特性**:

| 版本 | 年份 | 关键特性 |
|---|---|---|
| 1.0 | 1992 | 固定管线 |
| 1.5 | 2003 | VBO |
| 2.0 | 2004 | GLSL |
| 3.0 | 2008 | FBO, deprecated 固定管线 |
| 3.2 | 2009 | Core/Compat Profile, Geometry shader |
| 3.3 | 2010 | 现代基础 |
| 4.0 | 2010 | Tessellation shader |
| 4.3 | 2012 | Compute shader, debug output |
| 4.6 | 2017 | SPIR-V, anisotropic filter core |

跟 HH 学 OpenGL 3.3,够你做 2D 和简单 3D。后面要 compute shader 或 indirect draw 升 4.3+。

**GLSL 版本**:

```glsl
#version 330 core  // 对应 OpenGL 3.3
#version 430 core  // 对应 OpenGL 4.3
#version 460 core  // 对应 OpenGL 4.6
```

GLSL 版本必须 ≤ context 版本。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上 OpenGL 实现的层次:

```
应用 (glutin/glow)
   ↓ dlopen
libGL.so.1 (用户态 loader)
   ↓ dlopen
libGLX_mesa.so.0 或 libnvidia-glcore.so
   ↓ ioctl
DRM 内核驱动
   ↓
GPU 硬件
```

**Mesa** 是开源实现,Intel / AMD / 一些 NVIDIA 配置用它。**NVIDIA 闭源驱动**提供自己的 libGL,绕过 Mesa。

```bash
# 看你用的实现
ls -la /usr/lib/libGL.so.1
# 输出:lrwxrwxrwx ... libGL.so.1 -> /usr/lib/libGL.so.525.60.13 (NVIDIA)
# 或:libGL.so.1 -> /usr/lib/libGLX_mesa.so.0 (Mesa)

# 装 NVIDIA 驱动
sudo pacman -S nvidia nvidia-utils
# 卸载 NVIDIA 用回 Mesa:
sudo pacman -Rdd nvidia nvidia-utils libnvidia-gl
```

**EGL vs GLX**:

```bash
# EGL 在 Wayland / 嵌入式用
ls /usr/lib/libEGL*
# GLX 是 X11 协议扩展
# 看 GLX 版本
glxinfo | grep "GLX version"
```

Wayland 上 glutin 用 EGL,context 创建参数略不同。但应用层 API 一致,glutin 封装。

### 3.4 · 🦀 Rust 生态视角

**glutin context 创建完整签名**:

```rust
use glutin::context::{ContextApi, ContextAttributesBuilder, GlProfile, Version};
use glutin::display::GetGlDisplay;
use glutin::prelude::*;

let gl_display = gl_config.display();

let context_attrs = ContextAttributesBuilder::new()
    .with_profile(GlProfile::Core)
    .with_context_api(ContextApi::OpenGl(Version::new(3, 3)))
    .with_debug(true)
    .build(Some(window_handle));

let current_context = unsafe {
    gl_display.create_context(&gl_config, &context_attrs)
        .expect("create_context 失败")
        .make_current()
        .expect("make_current 失败")
};
```

**glow 加载**:

```rust
let gl = unsafe {
    glow::Context::from_loader_function_cstr(|s| {
        gl_display.get_proc_address(s) as *const _
    })
};
```

`get_proc_address` 是 platform-specific(X11 用 glXGetProcAddress,Wayland 用 eglGetProcAddress)。glutin 提供 `GlDisplay::get_proc_address` 统一接口。

**Rust 检查 OpenGL 错误**:

```rust
fn check_gl(gl: &glow::Context, context: &str) {
    unsafe {
        let err = gl.get_error();
        if err != glow::NO_ERROR {
            error!("GL error in {}: 0x{:x}", context, err);
        }
    }
}

// 每次重要 GL 调用后调
gl.bind_texture(glow::TEXTURE_2D, Some(tex));
check_gl(&gl, "bind_texture");
```

Debug context 开启后,不需要手动 check,driver 自动 callback。

## 4 · 认知地图

### 4.1 上级

- **API 版本管理** —— 所有大型 API 都有版本演化(C / C++ / Python / GL / Vulkan)

### 4.2 同级(并行方案对比)

| 方案 | 关键差别 | 何时用 | 本项目选了哪个 |
|---|---|---|---|
| OpenGL 2.0 context | 兼容老硬件 | 老机 | 不用 |
| OpenGL 3.3 Core | 现代基础 | 主流 | ✅ Day 242+ |
| OpenGL 4.6 | 最新特性 | AAA | 后续可选 |
| OpenGL ES 3.0 | 移动端 / 嵌入式 | 树莓派 / Android | 不走 |
| Vulkan | 显式一切 | 极致性能 | 不走 |

### 4.3 下级

- **ContextApi** —— GL / GLES / Vulkan
- **GlProfile** —— Core / Compatibility
- **Version** —— (major, minor) 元组
- **debug output callback** —— driver 主动报错
- **extension loading** —— 函数指针查询

## 5 · 对照与变奏

### 不同 context 的 API 行为

| | OpenGL 1.x Compat | OpenGL 3.3 Core | Vulkan |
|---|---|---|---|
| `glBegin/glEnd` | ✓ | ✗(deprecated) | 不存在 |
| `glVertexPointer` | ✓ | ✗ | 不存在 |
| VAO | 2.0+ 扩展 | 强制 | 必须 |
| shader | 1.5 拓展 | 必须 | 必须 |
| 内存管理 | driver 自动 | driver 自动 | 显式 |
| 同步 | 自动 | 自动 | 显式 fence |

OpenGL 3.3 Core 是"现代" OpenGL——必须 shader,必须 VAO。这是 Casey 用的版本,也是教学推荐。

### Linux 上 GL 栈的历史

- **1990s**:Direct Rendering Infrastructure(DRI)项目,Mesa 起步
- **2000s**:DRI2,Gallium3D 架构,Mesa 支持 OpenGL 2.x
- **2010s**:DRI3,Mesa 支持 OpenGL 3.x-4.x,Zink(OpenGL over Vulkan)
- **2020s**:Mesa 支持 OpenGL 4.6,接近 NVIDIA 闭源性能

你跟 HH 学的 OpenGL 3.3 在 Mesa 24+ 完全支持,所有 Arch 系统都能跑。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Core Profile 和 Compatibility Profile 的区别?为什么 Casey 选 Core?

**参考解答**:

- **Compatibility Profile** —— 包含所有 deprecated 函数(`glBegin/glEnd`、固定管线)。允许老代码跑,但容易学坏习惯
- **Core Profile** —— 只现代 API,deprecated 函数完全不可用。强制用 VAO + shader

Casey 选 Core 是因为:

1. 学正确的现代 OpenGL(deprecated 函数在新 API 里完全消失)
2. 性能更好(driver 不需要支持 deprecated 路径)
3. 跨平台更一致(MacOS 只支持 Core,Compatibility 在 macOS 完全没有)

### Lv2 · 动手实践

**题**:在 Day 241 的程序里加 context 信息打印 + debug output callback。完成标准:启动时打印 Vendor / Renderer / Version,GL 调用错时 stderr 打印详细错误。

**参考解答**:

```rust
unsafe {
    // 启用 debug output
    gl.enable(glow::DEBUG_OUTPUT);
    gl.enable(glow::DEBUG_OUTPUT_SYNCHRONOUS);  // 立刻 callback,方便调试
    gl.debug_message_callback(|source, ty, id, severity, msg| {
        let sev_str = match severity {
            glow::DEBUG_SEVERITY_HIGH => "HIGH",
            glow::DEBUG_SEVERITY_MEDIUM => "MEDIUM",
            glow::DEBUG_SEVERITY_LOW => "LOW",
            glow::DEBUG_SEVERITY_NOTIFICATION => "NOTIFY",
            _ => "?",
        };
        eprintln!("[GL {} id={}] {}", sev_str, id, msg);
    });

    // 打印 context 信息
    println!("Vendor:    {}", gl.get_parameter_string(glow::VENDOR));
    println!("Renderer:  {}", gl.get_parameter_string(glow::RENDERER));
    println!("Version:   {}", gl.get_parameter_string(glow::VERSION));
    println!("GLSL:      {}", gl.get_parameter_string(glow::SHADING_LANGUAGE_VERSION));
}
```

**测试**:故意写一个 GL 错误(比如 `gl.bind_texture(glow::TEXTURE_2D, None)` 后立刻 `gl.tex_image_2d(...)`),看 stderr 是否打印错误。

## 8 · Rust / Arch 落地代码

### Rust 完整 context 升级 + debug

```rust
use glow::HasContext;
use glutin::context::{ContextApi, ContextAttributesBuilder, GlProfile, Version};
use glutin::display::GetGlDisplay;
use glutin::prelude::*;
use glutin::surface::SwapInterval;

fn main() {
    let event_loop = winit::event_loop::EventLoop::new().unwrap();

    let window_builder = winit::window::WindowBuilder::new()
        .with_title("Day 242 context escalation")
        .with_inner_size(winit::dpi::PhysicalSize::new(800, 600));

    // 模板:试不同 OpenGL 版本
    let try_versions: &[ContextApi] = &[
        ContextApi::OpenGl(Version::new(4, 6)),
        ContextApi::OpenGl(Version::new(4, 3)),
        ContextApi::OpenGl(Version::new(3, 3)),
        ContextApi::Gles(Version::new(3, 0)),  // fallback
    ];

    let (window, gl_config, window_context) = (0..try_versions.len())
        .find_map(|i| {
            let api = &try_versions[i];
            let attrs = ContextAttributesBuilder::new()
                .with_profile(GlProfile::Core)
                .with_context_api(*api)
                .with_debug(true)
                .build(None);

            glutin::GlutinWindowBuilder::new(window_builder.clone())
                .with_gl_api(match api {
                    ContextApi::OpenGl(_) => glutin::config::GlApi::OpenGl,
                    ContextApi::Gles(_) => glutin::config::GlApi::Gles,
                    _ => glutin::config::GlApi::OpenGl,
                })
                .with_gl_profile(GlProfile::Core)
                .build(&event_loop)
                .ok()
                .map(|w| w.split())
        })
        .expect("无法创建 OpenGL context");

    let gl_display = gl_config.display();

    // 启用 VSync
    // ...

    let _ = unsafe { window_context.make_current() }.unwrap();

    let gl = unsafe {
        glow::Context::from_loader_function_cstr(|s| {
            gl_display.get_proc_address(s) as *const _
        })
    };

    // 打印 context 信息
    unsafe {
        println!("==== OpenGL Context ====");
        println!("Vendor:    {}", gl.get_parameter_string(glow::VENDOR));
        println!("Renderer:  {}", gl.get_parameter_string(glow::RENDERER));
        println!("Version:   {}", gl.get_parameter_string(glow::VERSION));
        println!("GLSL:      {}", gl.get_parameter_string(glow::SHADING_LANGUAGE_VERSION));

        // 启用 debug output
        gl.enable(glow::DEBUG_OUTPUT);
        gl.enable(glow::DEBUG_OUTPUT_SYNCHRONOUS);
        gl.debug_message_callback(|src, ty, id, sev, msg| {
            eprintln!("[GL id={} src={} ty={} sev={}] {}",
                      id, src, ty, sev,
                      std::str::from_utf8(msg).unwrap_or("?"));
        });

        // 测试:故意触发错误
        // gl.bind_texture(glow::TEXTURE_2D, None);
        // gl.tex_image_2d(...);  // 应该报错
    }

    // 主循环...
}
```

## 10 · 深入:OpenGL context 升级的工程

casey 在 day242 升级 OpenGL context——从旧版本切到新版本,以使用更现代的 API。这是 GPU 渲染的常见维护任务。

### 10.1 context 升级的原因

为什么要升级 OpenGL context?

1. **使用新特性**:compute shader 需要 4.3+,bindless texture 需要 4.5+
2. **性能优化**:新版本的 driver overhead 更小
3. **bug 修复**:driver 在新版本更稳定
4. **debug callback**:4.3+ 才支持 KHR_debug

casey 升级主要是为了 debug callback——错误信息更清晰,debug 效率高。

### 10.2 升级的风险

context 升级的潜在问题:

1. **不兼容性**:新版本可能移除老特性(core profile vs compatibility)
2. **driver bug**:不同 GPU vendor 的实现不一致
3. **平台限制**:macOS 只支持到 4.1,无法用 4.2+ 特性
4. **测试成本**:升级后要重新测试所有渲染功能

casey 在 day242 详细权衡这些风险,选择升级到 4.3(支持 KHR_debug 但不过分激进)。

### 10.3 升级的步骤

```rust
// 1. 创建临时 context(老版本)
let temp_ctx = wglCreateContext(hdc);
wglMakeCurrent(hdc, temp_ctx);

// 2. 用临时 context 获取 wglCreateContextAttribsARB
let wgl_create_context_attribs = wglGetProcAddress("wglCreateContextAttribsARB");

// 3. 用 wglCreateContextAttribsARB 创建新 context
let attrs = [
    wgl::CONTEXT_MAJOR_VERSION_ARB, 4,
    wgl::CONTEXT_MINOR_VERSION_ARB, 3,
    wgl::CONTEXT_PROFILE_MASK_ARB, wgl::CONTEXT_CORE_PROFILE_BIT_ARB,
    wgl::CONTEXT_FLAGS_ARB, wgl::CONTEXT_DEBUG_BIT_ARB,
    0,
];
let new_ctx = wglCreateContextAttribsARB(hdc, ptr::null(), attrs);

// 4. 删除临时 context,用新 context
wglDeleteContext(temp_ctx);
wglMakeCurrent(hdc, new_ctx);
```

casey 在 day242 反复讨论"为什么要临时 context"——wglCreateContextAttribsARB 是新 API,需要先用老 API 创建 context 才能获取它的函数指针。鸡生蛋问题。

### 10.4 Linux 上的等价操作

Linux 用 GLX 或 EGL:

```rust
// GLX 1.4+
let attrs = [
    glx::CONTEXT_MAJOR_VERSION_ARB, 4,
    glx::CONTEXT_MINOR_VERSION_ARB, 3,
    glx::CONTEXT_PROFILE_MASK_ARB, glx::CONTEXT_CORE_PROFILE_BIT_ARB,
    0,
];
let ctx = glx.CreateContextAttribsARB(display, fb_config, None, true, attrs);

// EGL
let ctx = egl.create_context(display, config, None, Some(&attrs));
```

Linux 比 Windows 简单(无需临时 context hack),但概念一致。

### 10.5 debug context

4.3+ 支持 debug context:

```rust
unsafe {
    gl.enable(glow::DEBUG_OUTPUT);
    gl.enable(glow::DEBUG_OUTPUT_SYNCHRONOUS);
    gl.debug_message_callback(|source, ty, id, severity, msg| {
        eprintln!("[GL {}] {:?} #{}: {}", source, severity, id, 
                  std::str::from_utf8(msg).unwrap());
    });
}
```

每个 GL 错误自动调 callback,带详细错误信息。casey 在 day242 启用,debug 效率提升 10 倍。

### 10.6 debug message 的分级

GL debug message 有 severity:

- **HIGH**:GPU 错误(无效 enum、shader compile fail)
- **MEDIUM**:性能警告(texture not in mipmap)
- **LOW**:提示信息(shader recompile)
- **NOTIFICATION**:普通信息(driver info)

casey 在 debug callback 里按 severity 过滤——只显示 HIGH / MEDIUM,LOW 太多噪音。

### 10.7 工业级 debug pipeline

商业游戏的 GPU debug pipeline:

1. **GL debug callback**:运行时错误
2. **RenderDoc**:抓帧、逐 draw call 分析
3. **Nsight Graphics**:NVIDIA GPU 专门工具
4. **apitrace**:trace 所有 GL call,replay
5. **Spector / Xcode GPU frame capture**:macOS

casey HH 用 GL debug callback + apitrace(开源、跨平台)。商业项目加 RenderDoc。

### 10.8 教学总结

day242 的核心要点:

1. **context 升级**:用新版本支持新特性
2. **临时 context hack**:Windows wgl 的特殊机制
3. **debug context**:4.3+ 自动错误 callback
4. **severity 分级**:HIGH / MEDIUM / LOW / NOTIFICATION
5. **debug 工具链**:GL callback + RenderDoc + apitrace

day242 让 casey HH 的 GPU debug 效率大幅提升。这是 OpenGL 集成的关键工程优化。
