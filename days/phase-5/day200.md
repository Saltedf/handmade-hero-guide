# Day 200 · 调试元素布局

> Day 199 的 widget 都用绝对坐标,看 100 个 widget 就乱。今天 Casey 加 layout 系统:horizontal / vertical / grid,自动算坐标。

## 0 · 为什么要有这一天

手写坐标的痛苦:

```rust
btn1.x = 10.0; btn1.y = 10.0;
```

## 1 · Casey 今天做了什么

Casey 设计 layout:

1. `Ui` struct 加 `cursor_x / cursor_y / current_layout`
2. `ui.vertical(|ui| { ... })` 进入垂直布局
3. widget 添加时,根据 layout 决定 cursor 推进方向
4. 自动算最大高度 / 宽度(用于 padding)

## 2 · 心智模型

### 2.0 Layout 系统的核心抽象

Layout 系统解决:"给一组 widget,自动算每个的位置"。三大模式:

**Box model**(传统):每个 widget 有 margin / border / padding / content。CSS 用这个。

**Flexbox**(CSS3):一维布局(horizontal 或 vertical),自动分配空间,处理 wrap / align。React Native 用这个。

**Grid**:二维布局,行 + 列。CSS Grid。

**Casey 的 day 200** 用最简单的 box model + horizontal / vertical stack:

```rust
enum Layout {
    Horizontal { spacing: f32 },
    Vertical { spacing: f32 },
}

struct LayoutContext {
    current_pos: Vec2,
    layout_stack: Vec<Layout>,
}

impl LayoutContext {
    fn begin_horizontal(&mut self, spacing: f32) {
        self.layout_stack.push(Layout::Horizontal { spacing });
    }

    fn end_horizontal(&mut self) {
        self.layout_stack.pop();
    }

    fn allocate(&mut self, size: Vec2) -> Rect {
        let rect = Rect::new(self.current_pos, size);
        match self.layout_stack.last() {
            Some(Layout::Horizontal { spacing }) => {
                self.current_pos.x += size.x + spacing;
            }
            Some(Layout::Vertical { spacing }) => {
                self.current_pos.y += size.y + spacing;
            }
            None => {}
        }
        rect
    }
}
```

### 2.0.1 控制流布局(flow layout)

immediate-mode 的 layout 是**控制流驱动**——你写 `ui.begin_horizontal(); ui.button(...); ui.button(...); ui.end_horizontal();`,button 顺序排列。代码顺序 = 视觉顺序。

retained-mode(Qt)用 anchor 或 box layout 对象:

```cpp
auto* layout = new QVBoxLayout;
layout->addWidget(btn1);
layout->addWidget(btn2);
window->setLayout(layout);
```

immediate-mode 更直接(无 layout 对象),retained-mode 更解耦(layout 与 widget 分离)。

### 2.0.2 flex / grid 的复杂度

真正强大的 flex / grid 实现:

- **flex**:grow / shrink 比例,baseline 对齐,wrap 时重新流式计算
- **grid**:span,row / column template,named areas

实现复杂(浏览器布局引擎几万行)。Casey day 200 不做这些,只做最朴素的 horizontal / vertical stack。够 debug UI 用,但比 CSS flex 弱很多。

### 2.0.3 layout 的嵌套

```rust
ui.begin_vertical();
    ui.begin_horizontal();
        ui.button("A");
        ui.button("B");
    ui.end_horizontal();
    ui.button("C");  // 在 horizontal 下面
ui.end_vertical();
```

Layout stack 支持嵌套。每次 begin_X push, end_X pop。`allocate()` 看栈顶决定如何推进 cursor。

### 2.0.4 size negotiation

widget 怎么知道自己的 size?两种:

**固定 size**:`button("Save", Vec2::new(80.0, 24.0))`。简单但不灵活。

**自适应 size**:根据内容算(text 长度决定 button 宽)。复杂但灵活。

```rust
fn button_auto(&mut self, label: &str) -> bool {
    let text_w = measure_text_width(label, FONT_SIZE);
    let padding = 8.0;
    let size = Vec2::new(text_w + padding * 2.0, 24.0);
    let rect = self.allocate(size);
    self.draw_button(rect, label)
}
```

casey 用半自适应——文字宽度算,高度固定。

### 2.0.5 scroll view

UI 内容超出视口要 scroll:

```rust
ui.begin_scroll_view("main_scroll", Vec2::new(800.0, 600.0));
    for i in 0..1000 {
        ui.button(&format!("Button {}", i));
    }
ui.end_scroll_view();
```

内部维护 scroll offset,渲染时 clip 到 viewport,鼠标 wheel 改 offset。这是 list view / tree view 的基础。

## 3 · 四域深入

### 类比:打字机的回车换行

打字机一行打完,纸往上一格,字头回左边。layout 系统一模一样:

- 横向 layout:打完一个字,字头右移
- 满了一行:回车换行(纵向 layout)
- vertical layout:每打完一个 widget,y 推进

### 2.1 cursor-based layout

```rust
pub enum Layout { Vertical, Horizontal }

pub struct Ui {
    pub cursor_x: f32,
    pub cursor_y: f32,
    pub layout: Layout,
    pub max_in_perpendicular: f32,  // vertical 模式记录 max width
    // ...
}

impl Ui {
    pub fn alloc_rect(&mut self, w: f32, h: f32) -> (f32, f32) {
        let x = self.cursor_x;
        let y = self.cursor_y;
        match self.layout {
            Layout::Vertical => {
                self.cursor_y += h;
                self.max_in_perpendicular = self.max_in_perpendicular.max(w);
            }
            Layout::Horizontal => {
                self.cursor_x += w;
                self.max_in_perpendicular = self.max_in_perpendicular.max(h);
            }
        }
        (x, y)
    }
}
```

### 2.2 layout stack

```rust
pub fn vertical<F: FnOnce(&mut Ui)>(&mut self, f: F) {
    self.layout_stack.push((self.cursor_x, self.cursor_y, self.layout, self.max_in_perpendicular));
    self.layout = Layout::Vertical;
    self.max_in_perpendicular = 0.0;

    f(self);

    // restore
    let (x, y, l, m) = self.layout_stack.pop().unwrap();
    self.cursor_x = x;
    self.cursor_y = y + self.max_in_perpendicular;  // 推进
    self.layout = l;
    self.max_in_perpendicular = m.max(self.max_in_perpendicular);
}
```

### 2.3 使用

```rust
ui.vertical(|ui| {
    ui.button("Save");      // y=10
    ui.button("Load");      // y=35
    ui.button("Quit");      // y=60

    ui.horizontal(|ui| {
        ui.button("OK");    // x=10 (在 vertical 里嵌套 horizontal)
        ui.button("Cancel"); // x=90
    });
});
```

### 2.4 padding / spacing

```rust
pub struct LayoutOptions {

impl Ui {

        self.cursor_y += match self.layout { Layout::Vertical => self.options.item_spacing, _ => 0.0 };
```

### 2.5 grid layout

```rust
pub fn grid<F: FnOnce(&mut Ui)>(&mut self, cols: usize, f: F) {
    let saved_x = self.cursor_x;
    let mut count = 0;
    let _guard = LayoutGuard::new(self);  // 保存 / 恢复

    self.layout = Layout::Horizontal;
```

## 5 · 对照与变奏

**Layout 系统的演化**:

| 时代 | 系统 | 特点 |
|---|---|---|
| 1990s | absolute / table | 手算坐标或 HTML table |
| 2000s | anchor / grid bag(Java Swing) | 相对父 / 兄弟定位 |
| 2010s | flexbox / grid(CSS) | 自动 flex / 二维 |
| 2015+ | constraint-based(Compose / SwiftUI) | 声明式约束 |

每代解决前代的痛点。Casey day 200 用最古老的 absolute + stack,够用但远不如现代方案。

### Flexbox 算法

Flexbox 看似简单,实现复杂——SpaceX 工程师写"flexbox is hard"博客详细讲。核心算法:

1. 算每个 child 的 preferred size(content-based)
2. 如果总和 > container,按 flex-shrink 比例缩
3. 如果总和 < container,按 flex-grow 比例扩
4. 按 align-items 对齐次轴
5. 按 justify-content 对齐主轴

5 步,每步都有 edge case。Rust 的 `taffy` crate 是 Rust 版 flexbox 实现,几千行代码。

### TUI / Web / Native 的 layout 比较

| 平台 | 默认 layout |
|---|---|
| Web | CSS flow + flex + grid |
| iOS | Auto Layout(constraint) |
| Android | LinearLayout / ConstraintLayout |
| Flutter | Flex / Row / Column |
| Qt | QVBoxLayout / QGridLayout |
| Win32 | absolute(老)/ XAML(新) |

每个平台都重写一遍 layout 系统。**Web 的 CSS layout 最灵活但最复杂**(浏览器实现几十万行)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 immediate-mode layout 用 cursor,retained-mode 用 layout manager?

**参考解答**:
- immediate-mode 每帧重新声明 widget,顺序固定 → cursor 自然推进
- retained-mode 创建 widget 后位置不变,layout manager 一次性算
- cursor 模式简单(无 layout 算法),但功能弱
- layout manager 复杂(flex / grid / constraint),但灵活
- 两者哲学不同:immediate 简单优先,retained 灵活优先

### Lv2 · 动手实践

**题**:实现 vertical layout,3 个 button 自动堆叠。

**参考解答**:

```rust
struct Ui {
    cursor_x: f32,
    cursor_y: f32,
    layout_stack: Vec<(f32, f32, f32)>,  // x, y, max_w
}

impl Ui {
    fn new() -> Self { Self { cursor_x: 0.0, cursor_y: 0.0, layout_stack: Vec::new() } }

    fn vertical<F: FnOnce(&mut Ui)>(&mut self, f: F) {
        self.layout_stack.push((self.cursor_x, self.cursor_y, 0.0));
        let start_y = self.cursor_y;
        f(self);
        let (_, _, max_w) = self.layout_stack.pop().unwrap();
        let (_, _, _) = (start_y, max_w, ());
    }

    fn button(&mut self, label: &str) -> (f32, f32) {
        let (x, y) = (self.cursor_x, self.cursor_y);
        println!("button '{}' at ({}, {})", label, x, y);
        self.cursor_y += 25.0;
        (x, y)
    }
}

fn main() {
    let mut ui = Ui::new();
    ui.cursor_x = 10.0;
    ui.cursor_y = 10.0;
    ui.vertical(|ui| {
        ui.button("Save");
        ui.button("Load");
        ui.button("Quit");
    });
}
```

**预期输出**:

```
button 'Save' at (10, 10)
button 'Load' at (10, 35)
button 'Quit' at (10, 60)
```
