# Day 227 · 在元游戏模式之间切换

> Day 226 定义了 mode 概念,今天 casey 处理切换的细节:异步加载、状态保留、UI 反馈。一个简单 InGame → MainMenu 切换背后其实是"卸载关卡资源 + 回主菜单 + 显示进度"。

## 0 · 为什么要有这一天

Day 226 的 transition_to 看起来简单:

```rust
fn transition_to(state: &mut State, new_mode: Mode) {
    cleanup(state, old_mode);
    init(state, new_mode);
    state.mode = new_mode;
}
```

但实际:

- **InGame → MainMenu**:卸载关卡 100MB 资源,需要时间。如果同步卸载,游戏卡住几秒
- **MainMenu → InGame**:加载关卡 100MB,同样卡顿
- **切换中显示什么?**:用户看黑屏 3 秒不专业

casey 今天的方案:

1. **异步切换**:加 Loading 中间 mode
2. **进度反馈**:Loading mode 显示进度条
3. **状态保留**:某些数据跨 mode 保留(玩家分数从 InGame 带回 MainMenu)

完整切换流程:

```
InGame → (用户选 "Exit to Menu") → Loading(卸载关卡) → Loading(加载菜单) → MainMenu
```

中间 Loading mode 显示进度条,告诉用户在做什么。

心理锚点:看完今天,你能解释"为什么 AAA 游戏切场景有 loading screen"。

## 1 · Casey 今天做了什么

1. **加 Loading mode**:专门处理过渡
2. **加异步卸载 / 加载**:worker thread 做资源
3. **加进度条 UI**:Loading mode 显示
4. **加跨 mode 数据**:某些数据从 InGame 保留到 MainMenu(玩家成绩)

## 2 · 心智模型

### 类比:接力赛交接棒

接力赛中,运动员 A 跑完一段不能立即变 B——要在交接区把棒递给 B,B 才能开始跑。交接区就是"Loading mode"。

casey 的 Loading mode 就是交接区:卸 A 的资源,加 B 的资源,中间显示进度。

### 2.1 三段切换

```
[源 mode] → [Loading] → [目标 mode]
```

Loading mode 自身有状态:

```rust
struct LoadingState {
    source: Mode,         // 从哪来
    target: Mode,         // 到哪去
    progress: f32,        // 0.0 - 1.0
    unload_done: bool,
    load_done: bool,
}
```

Loading update:

```rust
fn update_loading(state: &mut GameState, dt: f32) {
    let loading = &mut state.loading;
    if !loading.unload_done {
        // 卸载源 mode 资源
        unload_next_chunk(state);
        loading.progress += 0.5 * dt;  // 卸载阶段占 50%
        if loading.progress >= 0.5 {
            loading.unload_done = true;
        }
    } else if !loading.load_done {
        // 加载目标 mode 资源
        load_next_chunk(state);
        loading.progress += 0.5 * dt;  // 加载阶段占 50%
        if loading.progress >= 1.0 {
            loading.load_done = true;
        }
    } else {
        // 完成,切到 target
        transition_to(state, loading.target);
    }
}
```

每帧只卸载 / 加载一小块,避免长时间卡帧。

### 2.2 进度反馈

UI 显示:

```
Loading...
[==========          ] 50%
Loading level 3...
```

```rust
fn render_loading(state: &GameState) {
    let loading = &state.loading;
    draw_text(&format!(
        "{}...",
        if !loading.unload_done { "Unloading" }
        else if !loading.load_done { "Loading" }

}
```

### 2.3 跨 mode 数据

某些数据不应该被 cleanup 清掉。例如:

- 玩家分数(InGame 玩到 1000,回 MainMenu 还应该看到)
- 全局设置(音量、分辨率)
- 解锁的关卡

casey 加 "persistent data":

```rust
struct GameState {
    mode: Mode,
    persistent: PersistentData,  // 不被 cleanup 清
    mode_specific: ModeData,     // 被 cleanup 清
}

struct PersistentData {
    high_score: u32,
    unlocked_levels: u32,
    settings: Settings,
}

enum ModeData {
    None,
    InGame(InGameData),
    MainMenu(MainMenuData),
    ...
}
```

cleanup 只清 `mode_specific`,不动 `persistent`。

### 2.4 异步加载细节

worker thread 加载资源:

```rust
struct LoadJob {
    target_mode: Mode,
    resources_to_load: Vec<ResourceId>,
    loaded: Vec<ResourceId>,
}

impl LoadJob {
    fn run(mut self, state_arc: Arc<Mutex<GameState>>) {
        for res in self.resources_to_load.clone() {
            let data = load_from_disk(res);
            let mut s = state_arc.lock().unwrap();
            s.resource_cache.insert(res, data);
            self.loaded.push(res);
            s.loading.progress += 0.5 / self.resources_to_load.len() as f32;
        }
    }
}
```

主线程每帧从 resource_cache 检查加载情况,更新进度。

### Lv1 · 概念辨析

**题**:为什么不直接 InGame → MainMenu 同步切换?

**参考解答**:同步切换主线程要"卸载 100MB 关卡资源 + 加载 10MB 菜单资源",几百毫秒到几秒,期间游戏不响应输入、不渲染新帧,用户看到画面冻结。异步切换加 Loading 中间状态,主线程每帧做一小块工作,画面持续更新(显示进度条),用户感知流畅。

### Lv2 · 动手实践

**题**:实现 LoadingState + update_loading + 切换流程。

**参考解答**:

```rust
#[derive(Copy, Clone, Debug, PartialEq, Eq)]
enum Mode { InGame, Loading, MainMenu }

struct GameState {
    mode: Mode,
    loading: Option<LoadingData>,
    high_score: u32,  // persistent
    level_data: Option<String>,  // mode-specific
}

struct LoadingData {
    target: Mode,
    progress: f32,
    phase: LoadPhase,
}

#[derive(Copy, Clone, Debug, PartialEq, Eq)]
enum LoadPhase { Unloading, Loading, Done }

impl GameState {
    fn new() -> Self {
        Self {
            mode: Mode::InGame,
            loading: None,
            high_score: 1000,
            level_data: Some("level 3 data".to_string()),
        }
    }

    fn request_exit_to_menu(&mut self) {
        self.mode = Mode::Loading;
        self.loading = Some(LoadingData {
            target: Mode::MainMenu,
            progress: 0.0,
            phase: LoadPhase::Unloading,
        });
    }

    fn update(&mut self, dt: f32) {
        if self.mode != Mode::Loading { return; }
        let loading = self.loading.as_mut().unwrap();
        match loading.phase {
            LoadPhase::Unloading => {
                loading.progress += 0.5 * dt;
                if loading.progress >= 0.5 {
                    self.level_data = None;  // 真正卸载
                    loading.phase = LoadPhase::Loading;
                    println!("Unloaded level data");
                }
            }
            LoadPhase::Loading => {
                loading.progress += 0.5 * dt;
                if loading.progress >= 1.0 {
                    loading.phase = LoadPhase::Done;
                    println!("Loaded menu data");
                }
            }
            LoadPhase::Done => {
                self.mode = loading.target;
                self.loading = None;
                println!("Transitioned to {:?}", self.mode);
            }
        }
    }
}

fn main() {
    let mut s = GameState::new();
    println!("Initial mode: {:?}, high_score: {}", s.mode, s.high_score);

    s.request_exit_to_menu();
    println!("\nRequested exit, mode: {:?}", s.mode);

    let mut t = 0.0;
    while s.mode == Mode::Loading {
        t += 0.1;
        s.update(0.1);
        if let Some(l) = &s.loading {
            println!("  t={:.1}, progress={:.2}, phase={:?}", t, l.progress, l.phase);
        }
    }

    println!("\nFinal mode: {:?}, high_score: {}", s.mode, s.high_score);
    println!("Level data preserved? {}", s.level_data.is_some());
}
```

## 10 · 深入:模式切换的工程细节

casey 在 day226 引入 meta-mode,day227 完善"切换"——这是工程上比"声明 mode"复杂得多的部分。让我们把所有切换相关问题剖析。

### 10.1 切换的时机问题

mode 切换不是瞬时的——需要:

1. 旧 mode 清理(save data、释放资源、播放退出动画)
2. 加载新 mode 资源(asset streaming)
3. 新 mode 初始化(player spawn、UI 创建)
4. 进入新 mode(开始 update)

casey 在 day227 处理这个时序——什么时候显示 loading screen,什么时候开始 update 新 mode。

```rust
enum TransitionState {
    Idle,
    FadeOut(Mode),  // 退出动画
    Loading(Mode),  // 加载资源
    FadeIn(Mode),   // 进入动画
    Done,
}

fn update_transition(state: &mut GameState, dt: f32) {
    loop {
        match &mut state.transition {
            TransitionState::Idle => break,
            TransitionState::FadeOut(new_mode) => {
                state.fade_alpha += dt / 0.5;
                if state.fade_alpha >= 1.0 {
                    state.fade_alpha = 1.0;
                    state.transition = TransitionState::Loading(*new_mode);
                    continue;
                }
            }
            TransitionState::Loading(new_mode) => {
                // 推进加载
                if state.asset_loader.poll().is_ready() {
                    state.transition = TransitionState::FadeIn(*new_mode);
                    continue;
                }
            }
            // ... FadeIn 类似
        }
        break;
    }
}
```

casey 用一个状态机管理切换本身。这是**状态机的元状态机**——管理状态机状态的状态机。

### 10.2 资源加载的协调

mode 切换时,资源加载是主要瓶颈。casey 在 day227:

1. **预取**(day224):新 mode 启动前预取所有 asset
2. **streaming**:asset 加载分散到多帧
3. **同步 fallback**:加载未完成时,显示 placeholder

```rust
fn start_transition(state: &mut GameState, new_mode: Mode) {
    let assets_needed = compute_assets_for_mode(new_mode);
    for asset in assets_needed {
        if !state.cache.contains(&asset) {
            state.asset_loader.request_load(asset);
        }
    }
    state.transition = TransitionState::Loading(new_mode);
}
```

casey 在 day224 已经做了预取基础,day227 是上层应用。

### 10.3 退出动画 vs 立即切换

切换有两种 UX 风格:

**立即切换**:用户按"Pause",立即显示 Pause Menu。响应快,但突兀。

**带动画切换**:Pause Menu 从屏幕边缘滑入,200ms 动画。响应慢,但优雅。

casey 在 day227 选带动画,因为 HH 项目是叙事向游戏,优雅重要。竞技游戏(LOL、CS)选立即切换,响应优先。

实现带动画切换:

```rust
struct ModeTransition {
    from: Mode,
    to: Mode,
    progress: f32,    // 0..1
    duration: f32,    // 秒
}

fn update(state: &mut GameState, dt: f32) {
    if let Some(t) = &mut state.transition {
        t.progress += dt / t.duration;
        if t.progress >= 1.0 {
            state.mode = t.to;
            state.transition = None;
        }
    } else {
        update_mode(state, dt);
    }
}

fn render(state: &GameState) {
    if let Some(t) = &state.transition {
        // 同时渲染 from 和 to,按 progress 插值
        render_mode_with_alpha(state, t.from, 1.0 - t.progress);
        render_mode_with_alpha(state, t.to, t.progress);
    } else {
        render_mode(state, state.mode);
    }
}
```

### 10.4 切换中的输入处理

切换过程中,输入如何处理?

**选项 A**:完全丢弃。用户按 ESC 触发切换,过程中所有输入丢弃。
**选项 B**:队列化。输入进队列,切换完成后处理。
**选项 C**:即时处理。新模式立即响应输入。

casey 选 A,简单。生产系统可能选 C(更快响应)或 B(避免输入丢失)。

```rust
fn handle_input(state: &mut GameState, input: Input) {
    if state.transition.is_some() {
        return;  // 切换中,丢弃
    }
    // 正常处理
    handle_input_mode(state, input);
}
```

### 10.5 跨模式的状态保存

mode 切换时,某些状态要保留(player 进度、设置),某些要重置(临时 buff、UI 焦点)。

casey 的设计:

```rust
struct GameState {
    persistent: PersistentState,  // 永远保留(save 数据、设置)
    mode_data: ModeData,           // 当前 mode 的状态
}

enum ModeData {
    Title(TitleData),
    Playing(PlayingData),
    // ...
}

fn transition(state: &mut GameState, new_mode: Mode) {
    // persistent 不变
    // 旧 mode_data 丢弃
    // 新 mode_data 初始化
    state.mode_data = match new_mode {
        Mode::Title => ModeData::Title(TitleData::new()),
        Mode::Playing => ModeData::Playing(PlayingData::load(&state.persistent.save_file)),
        // ...
    };
}
```

casey 在 day227 反复强调:**只保留真正需要持久化的数据**。其他都重置,避免 mode 之间状态污染。

## 11 · 深入:游戏 UX 切换的真实体验

### 11.5 真实案例:Unity 的 SceneManager 异步加载

Unity 的异步 scene 切换:

```csharp
using UnityEngine.SceneManagement;
using UnityEngine.UI;

public class ModeSwitcher : MonoBehaviour {
    public Slider loadingBar;
    
    public void SwitchToGame() {
        StartCoroutine(LoadSceneAsync("GameScene"));
    }
    
    IEnumerator LoadSceneAsync(string sceneName) {
        AsyncOperation op = SceneManager.LoadSceneAsync(sceneName);
        op.allowSceneActivation = false;  // 等加载完
        
        while (op.progress < 0.9f) {
            loadingBar.value = op.progress;
            yield return null;
        }
        
        // 加载完,激活
        loadingBar.value = 1.0f;
        op.allowSceneActivation = true;
    }
}
```

Unity 用 Coroutine 实现异步加载,进度条反映加载进度。激活场景由代码控制(allowSceneActivation)。

casey 的 HH Rust 翻译版用类似模式:

```rust
async fn switch_mode(state: &mut State, new_mode: Mode) {
    let assets = compute_assets_for(new_mode);
    let loader = state.asset_loader.load_all(assets);
    while !loader.is_ready() {
        state.ui.show_loading_screen(loader.progress());
        tokio::time::sleep(Duration::from_millis(16)).await;
    }
    state.ui.hide_loading_screen();
    state.mode = new_mode;
}
```

casey 不在 HH 视频里直接展示这种 async 风格,但 Rust 翻译版会涉及。学完 day227 的基础,你看 Unity / Unreal / bevy 的异步加载 API 都能秒懂。

### 11.6 切换失败的恢复

切换过程中可能失败:磁盘满、asset 损坏、OOM。生产系统要 graceful degrade:

```rust
async fn switch_mode(state: &mut State, new_mode: Mode) -> Result<(), SwitchError> {
    let loader = state.asset_loader.load_all(compute_assets_for(new_mode));
    while !loader.is_ready() {
        if loader.has_failed() {
            return Err(SwitchError::AssetLoadFailed);
        }
        tokio::time::sleep(Duration::from_millis(16)).await;
    }
    state.mode = new_mode;
    Ok(())
}

// 调用方
match switch_mode(state, Mode::Playing).await {
    Ok(()) => {},
    Err(e) => {
        // 显示错误 UI,停留当前 mode
        state.ui.show_error(&format!("Failed: {:?}", e));
    }
}
```

casey 简化版不处理失败,假设切换总是成功。生产项目必须有错误恢复。

### 11.8 mode 切换的状态保存细节

casey 在 day227 也讨论:**mode 切换时,某些状态要"软保留"**(下次进 mode 时恢复)。

例子:玩家在 Inventory mode 时打开了某个装备的详情面板,切回 Playing,再切回 Inventory。**Inventory 是否还显示那个详情?**

casey 的设计:每个 mode 有"软状态"——上次的状态保留。重新进 mode 时恢复。

```rust
struct InventoryData {
    selected_item: Option<ItemId>,    // 软状态,保留
    filter: InventoryFilter,           // 软状态,保留
}

// 切换到 Playing 时,InventoryData 保留(只是不 update)
// 切换回 Inventory 时,InventoryData 还在,selected_item 不变
```

casey 的 HH 实现用这种方式。生产 UI 框架(retained mode)自动支持,immediate mode 要手写。

Title → Playing:    500ms(加载关卡,无 loading screen → 优化目标)
