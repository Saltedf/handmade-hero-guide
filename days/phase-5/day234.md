
# Day 234 · 实现基数排序(radix sort)

> HH Phase 5 的巅峰算法日。Casey 手写 radix sort,用 LSD(least significant digit)策略,8 pass 排 u64 sort key。结果是 O(n) 排序,比 O(n log n) 的 quicksort 快几倍——这就是为什么渲染排序用 radix 而不是 std sort。

## 0 · 为什么要有这一天

Day 229-230 引入了 sort key(u64)。每帧 N 千个 element 排序,N 越大排序成本越高。

- **Quicksort**:100K element ≈ 5ms
- **Radix sort**:100K element ≈ 1ms

5 倍速度差。144 FPS 下每帧 6.9ms,排序省 4ms = 大头节省。

**为什么 radix 这么快?**

1. **非比较**:不用比较元素大小,直接用 key 的 bit 模式定位
2. **Cache 友好**:顺序扫描 + 顺序写
3. **可向量化**:SIMD 加速 counting pass
4. **稳定**:相等 key 保持原序(对 sort key 重要——同 key 的 element 可能是 sprite / UI,顺序保留)

casey 今天手写 LSD radix sort:

```
8 pass(每个 byte 一次 pass)
每 pass:
  1. counting:统计每个桶(0-255)的 element 数
  2. prefix sum:算每个桶的起始位置
  3. scatter:把 element 按桶位置写到 output
最后 output 是排好的
```

心理锚点:看完今天,你能从零实现 radix sort,理解为什么这是工业标准(渲染排序、数据库 GROUP BY、文件系统 dir 排序)。

## 2 · 心智模型

### 类比:卡片分类机

旧时邮局分拣信件按邮编(6 位数字):

- 第一遍:按邮编最后一位(个位)分到 10 个盒子
- 第二遍:按邮编倒数第二位(十位)分到 10 个盒子(注意:这次从第一遍的盒子按顺序拿,保持稳定)
- ...
- 第六遍:按第一位分到 10 个盒子

6 遍后,信件按邮编完全排好。每遍 O(n),总共 O(6n) = O(n)。

radix sort 就是这个,只是把"十进制位"换成"byte"(256 个盒子,不是 10)。

### 2.1 LSD vs MSD

- **LSD (Least Significant Digit)**:从最低位(右)开始排。稳定。Casey 用这个
- **MSD (Most Significant Digit)**:从最高位(左)开始排。可能需要递归,可能不稳定

LSD 简单稳定,适合 sort key。

### 2.2 Radix sort 步骤

```rust
fn radix_sort(arr: &mut [u64]) {
    let n = arr.len();
    let mut temp = vec![0u64; n];  // 双 buffer

    for pass in 0..8 {
        let shift = pass * 8;
        // 1. Counting: 数每个桶
        let mut counts = [0usize; 256];
        for &v in arr.iter() {
            let bucket = ((v >> shift) & 0xFF) as usize;
            counts[bucket] += 1;
        }
        // 2. Prefix sum: 算每个桶的起始位置
        let mut offsets = [0usize; 256];
        let mut sum = 0;
        for i in 0..256 {
            offsets[i] = sum;
            sum += counts[i];
        }
        // 3. Scatter: 按桶位置写到 temp
        for &v in arr.iter() {
            let bucket = ((v >> shift) & 0xFF) as usize;
            temp[offsets[bucket]] = v;
            offsets[bucket] += 1;
        }
        // 4. Swap: temp 成为下一轮的输入
        arr.copy_from_slice(&temp);
    }
}
```

每 pass 4 步,8 pass 完成。总操作 ~32n(couting n + scatter n,8 pass)。

### 2.3 为什么是 stable

counting + prefix sum + scatter 保持稳定性:

```
input:  [(0x01, "A"), (0x01, "B"), (0x00, "C")]
                       ^ 同 key(0x01)

scatter:
- "A"(key=0x01) → offset[1]=1,然后 offset[1]=2
- "B"(key=0x01) → offset[1]=2,然后 offset[1]=3
- "C"(key=0x00) → offset[0]=0,然后 offset[0]=1

output: [(0x00, "C"), (0x01, "A"), (0x01, "B")]
                              ^^^^  ^^^^
        "A" 在 "B" 前(原序)
```

每个桶内,先到的写前面(offset 小),后到的写后面。原序保留。

### 2.4 复杂度分析

- **时间**:8 pass × O(n) = O(8n) = O(n)
- **空间**:O(n) temp buffer
- **稳定性**:稳定

对比 quicksort:

- **时间**:O(n log n),n = 100k 时 ≈ 1.7M 操作
- **空间**:O(log n) 递归栈
- **稳定性**:不稳定

radix 8n = 800k 操作,少于 quicksort 1.7M。**但 radix 操作是简单整数运算,quicksort 是分支预测重的比较**,实际差距更大。

### 2.5 SIMD 优化

counting pass 可以 SIMD 加速:

```rust
// 标量版本
for &v in arr {
    counts[((v >> shift) & 0xFF) as usize] += 1;
}

// SIMD 版本(伪代码,实际更复杂)
let counts_v = [0u32; 8];  // 8 lanes 各自累加
for chunk in arr.chunks(8) {
    let v = simd_load(chunk);
    let buckets = (v >> shift) & 0xFF;
    for i in 0..8 {
        counts_v[i] += if buckets[i] == b { 1 } else { 0 };
    }
}
// 最后 horizontal sum counts_v 进 counts[b]
```

SIMD 让 counting 快 4-8 倍。casey 在 Day 234 不上 SIMD,留作未来优化。Rust 视角下用 `std::simd`(nightly)或 `wide` crate。

## 4 · 认知地图

### 4.1 上级

- **Non-comparison sort** — 非比较排序
- **Distribution sort** — 分布式排序(按 key 分布)
- **Linear-time sort** — 线性时间排序

### 4.2 同级

| 算法 | 时间 | 空间 | 限制 |
|---|---|---|---|
| Radix (LSD) | O(dn) | O(n+b) | key 整数 |
| Counting | O(n+k) | O(k) | key 范围小 |
| Bucket | O(n+k) | O(n+k) | key 均匀分布 |
| Pigeonhole | O(n+N) | O(N) | key 有限 |

### 4.3 下级

- **counting pass** — 桶计数
- **prefix sum** — 起始位置
- **scatter** — 分发
- **stable 关键** — 同 key 保持原序

## 5 · 对照与变奏

radix 不同变种:

- **LSD**:右到左,稳定。本文
- **MSD**:左到右,可能递归
- **American flag sort**:MSD 原地版
- **Forward vs backward**:写方向影响 cache
- **Parallel radix**:多线程,每 pass 分桶并行

工业通常 LSD + parallel + SIMD。

### Lv1 · 概念辨析

**题**:为什么 radix sort 是 O(n) 而不是 O(n log n)?突破了什么限制?

**参考解答**:Day 231 的下界证明是**针对比较排序**:每次比较得 1 bit,需要 N log N 次。Radix 不是比较排序——它用 key 的 byte 直接定位(每 pass 一个 byte = 8 bit 信息),所以不受"1 bit per comparison"限制。8 pass 给 64 bit 信息,足够区分所有 key。前提:key 是整数(可分解 bit)。

### Lv2 · 动手实践

**题**:实现 LSD radix sort for u64,加 benchmark 对比 std sort_unstable。

**参考解答**:

```rust
use std::time::Instant;

fn radix_sort(arr: &mut [u64]) {
    let n = arr.len();
    if n <= 1 { return; }
    let mut temp = vec![0u64; n];

    for pass in 0..8 {
        let shift = pass * 8;
        let mut counts = [0usize; 256];
        for &v in arr.iter() {
            let b = ((v >> shift) & 0xFF) as usize;
            counts[b] += 1;
        }
        let mut offsets = [0usize; 256];
        let mut sum = 0;
        for i in 0..256 {
            offsets[i] = sum;
            sum += counts[i];
        }
        for &v in arr.iter() {
            let b = ((v >> shift) & 0xFF) as usize;
            temp[offsets[b]] = v;
            offsets[b] += 1;
        }
        arr.copy_from_slice(&temp);
    }
}

fn bench(name: &str, mut data: Vec<u64>) {
    let t = Instant::now();
    let f: fn(&mut [u64]) = match name {
        "radix" => radix_sort,
        "std_stable" => |v| v.sort(),
        "std_unstable" => |v| v.sort_unstable(),
        _ => unreachable!(),
    };
    f(&mut data);
    let elapsed = t.elapsed();
    let sorted = data.windows(2).all(|w| w[0] <= w[1]);
    println!("{}: {:?} (sorted={}, n={})", name, elapsed, sorted, data.len());
}

fn main() {
    for &n in &[10_000, 100_000, 1_000_000] {
        let mut rng_seed = 12345u32;
        let data: Vec<u64> = (0..n).map(|_| {
            rng_seed ^= rng_seed << 13;
            rng_seed ^= rng_seed >> 17;
            rng_seed ^= rng_seed << 5;
            rng_seed as u64
        }).collect();

        println!("\n=== n = {} ===", n);
        bench("radix       ", data.clone());
        bench("std_stable  ", data.clone());
        bench("std_unstable", data.clone());
    }
}
```

预期输出:radix 比 std_unstable 快 2-5 倍(取决于硬件)。std_stable 更慢。

## 10 · 深入:radix sort 的工业级实现

casey 在 day234 实现 radix sort,达到 O(n) 排序。让我把 radix sort 的所有细节讲透。

### 10.1 radix sort 的核心思想

radix sort 不是比较元素,而是**按位**(digit)处理:

- LSD(Least Significant Digit)radix:从最低位开始,逐位 sorting
- MSD(Most Significant Digit)radix:从最高位开始,递归 sorting

casey 用 LSD,因为实现简单且稳定。

### 10.2 LSD radix sort 的步骤

u64 key,8 个 byte,8 次 pass:

```
Pass 1: 按 byte 0(最低位)counting sort
Pass 2: 按 byte 1 counting sort
...
Pass 8: 按 byte 7(最高位)counting sort
```

每次 pass 是 O(n + 256)(256 是 byte 取值范围)。总 O(8 × (n + 256)) = O(n)。

### 10.3 counting sort 的实现

counting sort 是 radix 的核心:

```rust
fn counting_sort(arr: &[u64], output: &mut [u64], shift: u32) {
    let mut count = [0usize; 256];
    
    // 1. 计数
    for &v in arr {
        let byte = ((v >> shift) & 0xFF) as usize;
        count[byte] += 1;
    }
    
    // 2. 累加得到 offset
    let mut offset = [0usize; 256];
    let mut sum = 0;
    for i in 0..256 {
        offset[i] = sum;
        sum += count[i];
    }
    
    // 3. 分散到 output
    let mut pos = offset;
    for &v in arr {
        let byte = ((v >> shift) & 0xFF) as usize;
        output[pos[byte]] = v;
        pos[byte] += 1;
    }
}
```

每步 O(n + 256)。三步合起来 O(n)。

### 10.4 casey 的优化

casey 在 day234 实现做了几个优化:

**优化 1:in-place 替换为 ping-pong buffer**

```rust
fn radix_sort(arr: &mut [u64]) {
    let mut temp = vec![0; arr.len()];
    let (mut src, mut dst) = (arr, &mut temp[..]);
    
    for byte_pos in 0..8u32 {
        let shift = byte_pos * 8;
        counting_sort(src, dst, shift);
        std::mem::swap(&mut src, &mut dst);
    }
    
    // 最后 src 是结果
    if src.as_ptr() != arr.as_ptr() {
        arr.copy_from_slice(src);
    }
}
```

两个 buffer 交替,避免每 pass 都分配。

**优化 2:跳过全 0 byte**

如果某 byte 的所有元素都是 0(例如低 byte 全 0),这 pass 不改变顺序,可以跳过。

```rust
// 检测是否所有元素这个 byte 都是 0
let all_zero = arr.iter().all(|&v| ((v >> shift) & 0xFF) == 0);
if all_zero { continue; }  // 跳过
```

**优化 3:11-bit chunks(更少 pass)**

不按 byte(8 bit),按 11 bit chunks。u64 有 6 个 11-bit chunk(64 / 11 ≈ 6),所以 6 pass 而非 8。每个 chunk 的 counting sort 用 2048 大小的 count 数组,但 cache 友好性可能差。

trade-off:pass 数 vs cache 行为。casey 用 8-bit byte,简单且 cache 友好。

### 10.5 radix sort 的稳定性

LSD radix sort 是稳定的——同 key 的元素相对顺序保留。

```
Input:  [(5, A), (3, B), (5, C), (3, D)]
After sort: [(3, B), (3, D), (5, A), (5, C)]
                            ↑           ↑
                       (5, A) 在 (5, C) 前,顺序保留
```

casey 的实现稳定。对渲染排序重要——同 sort key 的元素需要稳定顺序。

### 10.6 radix sort 的限制

radix sort 不是银弹:

1. **只对整数 key 适用**:浮点、字符串要先转整数
2. **空间 O(n)**:ping-pong buffer 需要额外 O(n) 内存
3. **小 n 不划算**:n < 100 时,常数大于 quicksort
4. **cache miss**:counting sort 的 pos 数组随机写,cache 不友好

casey 的 day234 radix 适合 n > 1000 的 u64 排序。其他场景用 std。

### 10.7 浮点 key 的处理

casey 的 sort key 是 u64,但如果要排浮点呢?

技巧:把 IEEE 754 float 的 bit pattern 当 u32,做 sign-magnitude 到 two's complement 的转换:

```rust
fn float_to_sortable_u32(f: f32) -> u32 {
    let bits = f.to_bits();
    let mask = ((bits >> 31) as i32 | 0x80000000i32) as u32;
    bits ^ mask
}
```

转换后,u32 排序等价于 float 排序。然后 radix sort。casey 不展开,但生产项目要懂。

### 10.8 工业级 radix sort 库

- `voracious_radix_sort`:多线程 + SIMD
- `rdst`:radix sort 工具集

### 11.9 完整的 Rust radix sort 实现

casey 的 day234 完整代码:

```rust
fn radix_sort(arr: &mut [u64]) {
    let n = arr.len();
    if n <= 1 { return; }
    
    let mut temp = vec![0u64; n];
    
    // 8 pass,每 pass 处理一个 byte
    let mut src_is_arr = true;
    
    for byte_pos in 0..8u32 {
        let shift = byte_pos * 8;
        let mask = 0xFFu64 << shift;
        
        let (src, dst): (&[u64], &mut [u64]) = if src_is_arr {
            (arr, &mut temp)
        } else {
            (&temp, arr)
        };
        
        // Counting sort
        let mut count = [0usize; 256];
        for &v in src {
            let byte = ((v & mask) >> shift) as usize;
            count[byte] += 1;
        }
        
        // Prefix sum
        let mut prefix = [0usize; 256];
        let mut sum = 0;
        for i in 0..256 {
            prefix[i] = sum;
            sum += count[i];
        }
        
        // Scatter
        let mut pos = prefix;
        for &v in src {
            let byte = ((v & mask) >> shift) as usize;
            dst[pos[byte]] = v;
            pos[byte] += 1;
        }
        
        src_is_arr = !src_is_arr;
    }
    
    // 如果最后 src 是 temp,copy 回 arr
    if !src_is_arr {
        arr.copy_from_slice(&temp);
    }
}

fn main() {
    let mut arr = vec![5, 2, 8, 1, 9, 3, 7, 4, 6];
    println!("Before: {:?}", arr);
    radix_sort(&mut arr);
    println!("After:  {:?}", arr);
}
```

输出:

```
Before: [5, 2, 8, 1, 9, 3, 7, 4, 6]
After:  [1, 2, 3, 4, 5, 6, 7, 8, 9]
```
