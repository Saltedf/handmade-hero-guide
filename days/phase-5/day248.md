# Day 248 · 清理数据块显示

> Day 208 你加了 data blocks(二进制 blob 存任意调试数据),Day 247 简化了 debug value。今天 Casey 清理 data block 的 UI 显示代码——之前为了快速实现,显示逻辑分散在多个函数,bug 多。今天重构。

## 0 · 为什么要有这一天

Day 208 的 data block 用于:profiler 显示某帧的内存 dump,或 entity introspection 显示 struct 字段。Day 220 加了层级显示,Day 247 简化 value。

但 data block 显示代码本身乱:

- 4 个函数重叠(`draw_data_block` / `draw_blob` / `render_blob_field` / `inspect_blob`)
- 类型 dispatch 写死在 if-else 链
- 字体 / 颜色 / padding 硬编码
- 行宽溢出处理没有

Day 248 Casey 把 4 个函数合并成 1 个,用 match dispatch,加可配置样式:

```rust
// 之前
fn draw_data_block(...) { ... }
fn draw_blob(...) { ... }
fn render_blob_field(...) { ... }
fn inspect_blob(...) { ... }

// 之后
fn draw_data_block(ctx: &mut DrawCtx, block: &DataBlock) { ... }
```

代码量从 800 行降到 300 行,bug 减少。

**为什么这件事重要**:**重构(refactor)** 是软件工程核心技能。会写代码不等于会维护代码,会维护代码必须会重构。

**心理锚点**:看完今天,你能审视自己代码,识别"代码气味(code smell)",动手重构。

## 1 · Casey 今天做了什么

Casey 应用代码气味(code smell)原则重构 data block 显示:

1. **重复代码(Duplicated Code)** —— 4 函数有 70% 重复 → 合并
2. **过长函数(Long Method)** —— 某函数 200 行 → 拆成 5 个 40 行
3. **硬编码魔法数(Magic Number)** —— padding=10 / font_size=14 → 命名常量
4. **类型 dispatch 用 if-else 链** —— 改用 match
5. **缺乏样式抽象** —— 加 `DrawStyle` struct 统一

**关键决策**:重构**不改行为**。每步重构跑测试,确保渲染像素一致。

## 2 · 心智模型

### 类比:厨房整理

厨房用久了:

- 同样工具有 5 把(重复)
- 桌上堆 200 个东西(过长函数)
- 调料瓶没标签(魔法数)
- 找东西靠记忆没分类(if-else 链)

整理(重构)后:

- 每种工具 1 把,挂墙上(去重)
- 桌面整洁,分区(拆函数)
- 调料瓶贴标签(命名常量)
- 调料分架放(match dispatch)

行为(做菜)不变,但效率提高。

### 2.1 代码气味(Code Smells)

Martin Fowler 经典书《Refactoring》列 22 种代码气味,常见:

- **Duplicated Code** —— 同一段代码 ≥ 2 处
- **Long Method** —— 函数 > 50 行
- **Large Class** —— struct > 10 字段
- **Long Parameter List** —— 函数 > 4 参数
- **Divergent Change** —— 一个类被多种原因改
- **Shotgun Surgery** —— 改一处要动很多文件
- **Feature Envy** —— 方法大量用别的类字段
- **Data Clumps** —— 同样几个数据总一起出现

Day 248 处理前 4 个。

### 2.2 重构手法

对应的"重构手法"(refactoring techniques):

- **Extract Method** —— 从长函数提取子函数
- **Inline Method** —— 删除只调一次的简单函数
- **Move Method** —— 把方法移到合适的类
- **Replace Conditional with Polymorphism** —— if-else 链改 trait / enum dispatch
- **Introduce Parameter Object** —— 多参数合成 struct
- **Replace Magic Number with Symbolic Constant** —— 命名常量

之后(Day 248):

```rust
const DEBUG_FONT_SIZE: f32 = 14.0;

#[derive(Copy, Clone)]
pub struct DrawStyle {
    pub font_size: f32,
    pub color: Color,
    pub padding: f32,
}

impl Default for DrawStyle {
    fn default() -> Self {
        Self {
            font_size: DEBUG_FONT_SIZE,
            color: Color::WHITE,
            padding: 4.0,
        }
    }
}

fn draw_data_block(ctx: &mut DrawCtx, block: &DataBlock, x: f32, y: f32) {
    let text = block.format();
    ctx.draw_text(&text, x, y, ctx.style.font_size, ctx.style.color);
}

impl DataBlock {
    fn format(&self) -> String {
        match &self.value {
            Value::F32(f) => format!("{:.3}", f),
            Value::Bool(b) => format!("{}", b),
            Value::Vec3(v) => format!("({:.2}, {:.2}, {:.2})", v[0], v[1], v[2]),
            Value::Color(c) => format!("#{:02X}{:02X}{:02X}", c[0], c[1], c[2]),
            Value::String(s) => s.clone(),
        }
    }
}
```

改进:

- 1 个函数(之前 4 个)
- 样式集中在 `DrawStyle`
- match 替代 if-else 链
- format 逻辑放在 DataBlock 自己(对象方法,不是外部函数)

### 2.4 测试驱动重构

重构铁律:**不改行为**。每步:

1. 跑测试,确保绿
2. 改一小步
3. 跑测试,确保仍绿
4. 继续

如果没有自动化测试,先加"特征测试"(characterization test):用当前代码生成"参考输出",重构后对比:

```rust
#[test]
fn data_block_format_unaffected() {
    let block = DataBlock::f32(3.14159);
    assert_eq!(block.format(), "3.142");

    let block = DataBlock::vec3([1.0, 2.0, 3.0]);
    assert_eq!(block.format(), "(1.00, 2.00, 3.00)");
}
```

### 2.5 Rust idiom:enum + match

Rust enum + match 是消除 if-else 链的最佳工具:

```rust
// 不好
fn get_type_name(v: &Value) -> &'static str {
    if let Value::F32(_) = v { "f32" }
    else if let Value::Bool(_) = v { "bool" }
    else if let Value::Vec3(_) = v { "vec3" }
    // ...
}

// 好
fn get_type_name(v: &Value) -> &'static str {
    match v {
        Value::F32(_) => "f32",
        Value::Bool(_) => "bool",
        Value::Vec3(_) => "vec3",
        Value::Color(_) => "color",
        Value::String(_) => "string",
    }
}
```

match 强制 exhaustive —— 加新 enum variant 时,所有 match 都要更新,编译器帮检查。if-else 没这个保护。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:重构(Refactoring)和重写(Rewriting)的区别?什么时候用哪个?

**参考解答**:

- **重构** —— 不改外部行为,改内部结构。小步、增量、测试守护
- **重写** —— 从头写,替换全部代码。大风险、长周期

何时用:

- **重构** —— 大多数情况。代码可工作但乱
- **重写** —— 极少。代码无法工作 + 修起来比写新还贵

Joel Spolsky 著名文章"Things You Should Never Do":Netscape 2000 年代重写,损失几年时间,被 IE 反超。重写是大公司常见陷阱。

```rust
mod old {
    pub fn draw_data_block(block: &DataBlock, x: f32, y: f32) {
        // 100 行...
    }

    }

// === 之后(Day 248,300 行) ===
mod new {
    use std::fmt;

    #[derive(Clone, Debug)]
    pub enum Value {
        F32(f32),
        Bool(bool),
        Vec3([f32; 3]),
        Color([u8; 4]),
        String(Box<str>),
    }

    pub struct DataBlock {
        pub name: &'static str,
        pub value: Value,
    }

    impl fmt::Display for Value {
        fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
            match self {
                Value::F32(v) => write!(f, "{:.3}", v),
                Value::Bool(b) => write!(f, "{}", b),
                Value::Vec3(v) => write!(f, "({:.2}, {:.2}, {:.2})", v[0], v[1], v[2]),
                Value::Color(c) => write!(f, "#{:02X}{:02X}{:02X}{:02X}",
                    c[0], c[1], c[2], c[3]),
                Value::String(s) => write!(f, "{}", s),
            }
        }
    }

    #[derive(Copy, Clone)]
    pub struct DrawStyle {
        pub font_size: f32,
        pub color: [f32; 4],
        pub padding: f32,
    }

    impl Default for DrawStyle {
        fn default() -> Self {
            Self { font_size: 14.0, color: [1.0; 4], padding: 4.0 }
        }
    }

    pub struct DrawCtx {
        pub style: DrawStyle,
        pub font: (),
        // ...
    }

    impl DrawCtx {
        pub fn draw_text(&mut self, _text: &str, _x: f32, _y: f32,
                         _size: f32, _color: [f32; 4]) {
            // 实际渲染
        }
    }

    pub fn draw_data_block(ctx: &mut DrawCtx, block: &DataBlock, x: f32, y: f32) {
        let text = format!("{}: {}", block.name, block.value);
        ctx.draw_text(&text, x, y, ctx.style.font_size, ctx.style.color);
    }
}

fn main() {
    use new::*;
    let mut ctx = DrawCtx { style: DrawStyle::default(), font: () };
    let blocks = vec![
        DataBlock { name: "speed", value: Value::F32(3.14159) },
        DataBlock { name: "position", value: Value::Vec3([1.5, 2.0, 3.5]) },
        DataBlock { name: "alive", value: Value::Bool(true) },
    ];
    for (i, b) in blocks.iter().enumerate() {
        draw_data_block(&mut ctx, b, 10.0, 10.0 + i as f32 * 20.0);
        println!("{}: {}", b.name, b.value);
    }
}
```

## 10 · 深入:data block 显示的清理

casey 在 day248 清理 data block 显示——debug UI 中展示结构化数据的部分。

### 10.1 data block 的概念

debug 系统里的"data block"——可视化结构化数据的 UI 组件:

```
Player Position:    (128.5, 64.3, 0.0)
Health:             100 / 100
Inventory:          [Sword, Shield, Potion]
Current State:      Attacking (frame 23 / 60)
```

每个 data block 显示一组相关数据。

### 10.2 简化前的状态

casey 在 day248 之前的 data block 系统:

```rust
struct DataBlock {
    fields: Vec<DataField>,
    layout: Layout,        // 自定义布局
    formatter: Formatter,  // 格式化
    tooltip: Option<String>,
    click_handler: Option<ClickHandler>,
    // ... 多个字段
}
```

每个 data block 有自己的 layout、formatter、tooltip、click handler。代码量大,维护复杂。

### 10.3 简化后的状态

```rust
struct DataBlock {
    label: String,
    value: String,  // 预格式化字符串
}

// 数据 → string 的格式化在外部做
```

字段从 5+ 降到 2,代码量大幅减少。

### 10.4 简化的代价

简化去除了:

- 自定义 layout(改用统一布局)
- formatter(外部完成)
- tooltip(临时去掉)
- click handler(临时去掉)

代价:某些高级功能失去。casey 选择"先简化,需要时再加回"。

### 10.5 工程模式:YAGNI

YAGNI(You Aren't Gonna Need It)原则:**不预先实现"可能用"的功能**。需要时再加。

casey 在 day248 实践 YAGNI:

- 实际只用了 data block 的 label + value
- 自定义 layout 没人用,删
- formatter 改外部,简化
- tooltip 没人看,删
- click handler 没人点,删

代码量减少 60%,可读性提升。

### 10.6 casey 的工程判断

casey 在 day248 反复讨论:"什么时候坚持 YAGNI,什么时候预防性实现?"

- **YAGNI 适用**:UX 细节、UI 装饰
- **预防性适用**:架构层抽象(过早抽象 vs 过晚重构)

casey 的判断:UX 细节 YAGNI,架构层预防性。data block 是 UX,简化合理。
