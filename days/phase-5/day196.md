# Day 196 · UI 交互入门

> Day 195 写了零散的交互代码,今天 Casey 把这些抽象成统一的 immediate-mode UI 框架。从这天起,UI 不再是"画几个矩形 + 手动命中测试",而是一套声明式 API:`ui.button("click")`,框架自动处理 hit-test、state、render。

## 0 · 为什么要有这一天

回顾 Day 188-195 写的 UI 代码,你会发现**每个交互都重复**:

```rust
// 每个 button 都要:
let in_rect = is_mouse_in_rect(mouse, x, y, w, h);
let clicked = mouse.just_pressed && in_rect;
let hover = in_rect;
draw_rect(x, y, w, h, if hover { hover_color } else { normal_color });
draw_text(label, x + 4, y + 4);
if clicked { action(); }
```

100 个 button 就重复 100 次。Casey 的优化:**抽象成函数 / 框架**:

```rust
if ui.button("click") {
    action();  // 只在 click 时执行
}
```

这就是 **immediate-mode UI 框架**。Dear ImGui 是这个模式的祖师爷(2014 年开源)。egui、Nuklear、Conrod 都是 Rust 实现。

今天 Casey 实现最简版的 immediate-mode UI 框架。教学价值极高,因为它展示了一种**完全不同于传统 GUI 的设计**。

心理锚点:看完今天,你能解释 immediate-mode vs retained-mode 的本质区别,并能写出 immediate-mode button / slider / checkbox。

## 1 · Casey 今天做了什么

Casey 设计 immediate-mode UI 框架:

1. `Ui` struct,持有 mouse state、render list、ID stack
2. `ui.button(label)` 函数返回 `bool`(click?)
3. `ui.checkbox(label, &mut value)` 函数返回 `bool`(changed?)
4. ID 通过"调用顺序"自动分配(Day 199+ 用字符串 hash 显式)

## 2 · 心智模型

### 2.0 Immediate-mode 的设计哲学

immediate-mode GUI(简称 ImGui)是 Omar Cornut 2014 年发明,基于 Casey Muratori 2005 年的演讲。核心思想:

> "UI is a function of state, not a set of objects."

每帧调用 `ui.button("Save")`,函数返回 `bool`(是否点击)。**没有 button 对象持续存在**——下一帧再调,逻辑重新执行。

对比 retained-mode:

```cpp
// Qt(retained)
auto* btn = new QPushButton("Save");
QObject::connect(btn, &QPushButton::clicked, this, &App::onSave);
// btn 持续存在,Qt 派发 QMouseEvent 给它
```

```rust
// Dear ImGui(immediate)
if ui.button("Save") {
    self.save();  // 每帧调一次,只在点击 frame 返回 true
}
```

immediate-mode 代码更短、状态更少、数据驱动。代价:每帧 CPU 重画 UI(60 fps × 100 widgets = 6000 calls/sec,但每个 < 1 μs,总开销 < 6 ms / 秒,可忽略)。

### 2.0.1 ID 与 state

immediate-mode 没有对象,但 state 必须跨帧保留——expanded、scroll position、edit buffer 等。怎么存?

**用 ID 索引**。每个 UI 元素调用时给一个唯一 ID(label + 父 ID hash),state map 按 ID 存:

```rust
struct Ui {
    state: HashMap<u64, WidgetState>,
}

impl Ui {
    fn button(&mut self, label: &str) -> bool {
        let id = hash(label);  // 简化,实际要带父 ID
        let hovered = ...;
        let clicked = ...;
        self.state.insert(id, WidgetState { hovered });
        // draw
        clicked
    }
}
```

下一帧调同一 ID 的 button,state 取出。

### 2.0.2 Dear ImGui vs egui

两个主流 Rust immediate-mode 库:

**Dear ImGui**(C++,ocornut):成熟,大量游戏用。binding:`imgui-rs`。API:

```rust
ui.button("Save", [80.0, 20.0]);
```

**egui**(Rust 原生,emilk):更现代,API 更 Rusty:

```rust
if ui.button("Save").clicked() {
    save();
}
```

egui 优势:纯 Rust,wasm 友好,生态丰富(浏览器 demo)。Dear ImGui 优势:成熟,大量教程。

Casey 自己手写 ImGui(简化版),不依赖第三方。教学价值高,功能受限。

### 2.0.3 Immediate-mode 的性能

每帧重画 UI:
- 100 widgets × 1 μs/widget = 100 μs / 帧 = 6 ms / 秒(60 fps)
- 对游戏(< 16 ms / 帧 预算),0.6% 用于 UI

完全可接受。如果 UI 复杂(1000 widgets),1% 开销。除非真的优化紧张,否则 immediate-mode 总是够。

但**如果 UI 数据驱动频繁变**(每帧 frame 数据变 1000 次),invalidate 整个 UI tree,retained 反而慢。这是 immediate-mode 在游戏 / 实时 UI 上的根本优势。

### 2.0.4 immediate-mode 的局限

不适合的场景:
- **传统桌面应用**:文本编辑器、IDE,控件多、状态复杂,retained 更好
- **移动 app**:动画 / 多点触摸复杂,immediate-mode 表达吃力
- **复杂 widget**(如富文本编辑器):需要 persistent state

immediate-mode 是工具 / debug UI 的甜点。Casey HH 全用 immediate-mode,因为 debug UI 简单。

### 2.0.5 鼠标 / 键盘事件统一

immediate-mode 处理输入:每帧把鼠标 / 键盘状态塞进 Ui struct:

```rust
struct Ui {
    mouse_x: i32,
    mouse_y: i32,
    mouse_down: [bool; 3],  // left, middle, right
    mouse_pressed: [bool; 3],  // 边沿
    mouse_released: [bool; 3],  // 边沿
    wheel: f32,
    keys_pressed: Vec<KeyCode>,
    typed_chars: Vec<char>,
}

impl Ui {
    fn button(&mut self, label: &str, rect: Rect) -> bool {
        let hovered = point_in_rect(self.mouse_x, self.mouse_y, rect);
        let active = hovered && self.mouse_down[0];
        let clicked = hovered && self.mouse_released[0];
        // draw
        clicked
    }
}
```

每帧 main loop 更新 Ui 的输入字段,UI 函数读。简单一致。

## 3 · 四域深入

### 类比:填表格 vs 写即时贴

**retained-mode**(传统 GUI):你创建一个表格对象(Form),里面有 5 个输入框(InputBox 对象),3 个按钮(Button 对象)。你维护这些对象的生命周期,设置回调。每次输入触发回调,你 update 状态。

**immediate-mode**:你每分钟写一张即时贴:"现在我要看到 5 个输入框和 3 个按钮,数据如下..."。如果某分钟你没写,那些 UI 就消失。**UI 完全反映当前状态**。

immediate-mode 的"魔法":**状态怎么记住?**(输入框里的字符)。答:**用 ID 哈希**。每次声明 `ui.input("name")`,框架给这个 input 分配 ID(hash 字符串),状态存在 `state::HashMap<id, ...>`。

### 2.1 Ui struct

```rust
pub struct Ui {
    pub mouse: MouseState,
    pub text_input: Vec<char>,
    pub cursor_x: f32,
    pub cursor_y: f32,
    pub next_id: u64,
    pub state: HashMap<u64, UiElementState>,
}

#[derive(Default)]
pub struct UiElementState {
    pub hover: bool,
    pub active: bool,    // pressed
    pub text_buffer: Option<String>,  // 文本输入框
}

impl Ui {
    pub fn new() -> Self { /* ... */ }

    pub fn begin(&mut self) {
        self.next_id = 0;  // 每帧重置 ID 计数
    }

    fn alloc_id(&mut self) -> u64 {
        let id = self.next_id;
        self.next_id += 1;
        id
    }

    pub fn button(&mut self, label: &str, x: f32, y: f32, w: f32, h: f32) -> bool {
        let id = self.alloc_id();
        let in_rect = is_in_rect(self.mouse.x, self.mouse.y, x, y, w, h);
        let clicked = self.mouse.left_just_pressed && in_rect;
        let hover = in_rect;
        // 渲染(假设有 draw list)
        draw_rect(x, y, w, h, if hover { 0xFF888888 } else { 0xFF444444 });
        draw_text(label, x + 4, y + 4);
        clicked
    }
}
```

### 2.2 immediate-mode 的 ID

上面用 `alloc_id` 顺序分配,但**顺序不稳定**——如果某帧多了一个 button,后面所有 button 的 ID 都偏移。

解决:**用字符串 hash 作为 ID**:

```rust
pub fn button(&mut self, label: &str) -> bool {
    let id = hash(label);
    // ...
}
```

或者用 stack 显式 push path:

```rust
ui.push_id("player");
ui.button("name");   // id = hash("player/name")
ui.button("hp");     // id = hash("player/hp")
ui.pop_id();
```

### 2.3 checkbox(双向数据)

```rust
pub fn checkbox(&mut self, label: &str, checked: &mut bool) -> bool {
    let id = hash(label);
    let in_rect = is_in_rect(self.mouse.x, self.mouse.y, ...);
    if self.mouse.left_just_pressed && in_rect {
        *checked = !*checked;
        true  // changed
    } else {
        false
    }
}

// 用法
let mut show_fps = false;
// 每帧
ui.checkbox("show_fps", &mut show_fps);
```

### 2.4 slider(连续值)

```rust
pub fn slider(&mut self, label: &str, value: &mut f32, min: f32, max: f32) -> bool {
    let id = hash(label);
    // 检测点击 + 拖拽
    let knob_x = (*value - min) / (max - min);
    let clicked = self.mouse.left_just_pressed && is_in_rect(...);
    if self.mouse.left_pressed && (self.state[&id].active || clicked) {
        self.state.entry(id).or_default().active = true;
        let rel = (self.mouse.x - x) / w;
        *value = min + rel.clamp(0.0, 1.0) * (max - min);
        true
    } else {
        self.state.entry(id).or_default().active = false;
        false
    }
}
```

### 2.5 布局(cursor)

每个 widget 自己算坐标太烦。immediate-mode 用**布局 cursor**:

```rust
impl Ui {
    pub fn button(&mut self, label: &str) -> bool {
        let x = self.cursor_x;
        let y = self.cursor_y;
        let w = 100.0;
        let h = 20.0;
        // ...
        self.cursor_y += h + 2.0;  // 自动推进
        clicked
    }
}

// 用法
ui.button("A");  // 自动布局
ui.button("B");  // 紧接在 A 下面
ui.button("C");
```

casey 后面 Day 200+ 加更多布局(horizontal / vertical / padding)。

## 3 · 四域深入

### 3.1 · 游戏编程视角

immediate-mode UI 的优缺点:

**优点**:
- **简单**——无 widget tree,无回调
- **自动同步**——状态改了 UI 自动变
- **数据驱动**——UI 反映当前数据
- **无 sync bug**——retained mode 经常忘了 update widget

**缺点**:
- **每帧重画**——大量元素时慢
- **无动画**——retained mode 容易加 transition
- **可访问性差**——屏幕阅读器难解析
- **layout 复杂**——retained mode 有 flexbox / grid

游戏 debug UI 用 immediate-mode 完美(数据驱动 + 简单)。生产 UI(玩家面前的菜单)用 retained-mode(Qt / web)。

### 3.2 · Rust 生态视角

Rust 的 immediate-mode UI 库:

| crate | 特点 |
|---|---|
| `egui` | 最流行,跨后端 |
| `iced` | retained + Elm-like |
| `conrod` | immediate,老 |
| `deer鹿` | 国产 |
| `tauri` | web frontend + Rust backend |

egui 是 Casey 风格的 Rust 实现。读 egui 源码学 immediate-mode 实现。

### 3.3 · immediate-mode 的关键技术

1. **ID hash** —— 状态跨帧保留
2. **layout cursor** —— 自动布局
3. **draw list** —— 收集 draw call,一次性渲染
4. **input state** —— 鼠标 / 键盘每帧快照
5. **stack-based ID** —— 嵌套 widget 唯一 ID

## 5 · 对照与变奏

**UI 范式的演化**:

| 时代 | 范式 | 代表 |
|---|---|---|
| 1980s | retained + 事件回调 | Macintosh Toolbox, Win32 |
| 1990s | retained + OOP | MFC, Qt |
| 2000s | XAML / declarative | WPF, Flex |
| 2010s | reactive / functional | Elm, React |
| 2015+ | immediate-mode for games | Dear ImGui, egui |
| 2020+ | declarative everywhere | SwiftUI, Jetpack Compose |

每个范式解决的问题:
- retained:控件持久(性能 + 复用)
- reactive:数据驱动 UI 自动同步
- immediate-mode:实时数据 + 简单 API

### Immediate-mode 的两次兴起

immediate-mode 不是新——1980 年代早期 GUI 都是 immediate-mode(`MoveTo(hDC, x, y); LineTo(hDC, x2, y2);`)。1990 年代 OOP 浪潮下被 retained 取代。

Casey Muratori 2005 演讲"Immediate-Mode GUI"重新点燃兴趣,2014 年 Dear ImGui 实现,游戏 / debug 圈普及。**第二次兴起的核心驱动力是数据驱动 UI 的需求**——retained 在动态 UI 上太笨重。

### Elm / React 的虚拟 DOM

Elm / React 用"声明式 + diff",看似 retained 实则不同:

```jsx
// React
function App() {
    return <div>
        <button onClick={save}>Save</button>
    </div>;
}
```

每帧 render 返回新的 vdom tree,React diff 旧 vdom,只更新变化的部分。**性能尚可,API 友好**,但 diff 开销在游戏 60 fps 下太重。

| 维度 | immediate-mode | vdom |
|---|---|---|
| 渲染开销 | O(widgets) | O(diff) |
| 数据同步 | 显式 | 自动 |
| 学习曲线 | 低 | 中 |
| 生态 | 游戏圈大 | Web 主流 |

### Flutter 的 imperative 内核

Flutter 看似 declarative(Widget tree),但内部**用 immediate-mode 风格的 Element rebuild**——每次 setState 重建 Element tree,diff 后更新渲染。这是 React 思路 + 高性能实现。

Casey 的 day 196 是这条演化链的最简版,**理解它能更好理解现代 UI 框架**。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:immediate-mode button 函数返回 bool(clicked)。retained-mode button 怎么通知 click?

**参考解答**:
- immediate-mode:`if ui.button("X") { /* 立即执行 */ }`
- retained-mode:`button.set_on_click(|| { /* callback */ })`
- immediate-mode 的好处:控制流和数据流一起(代码读起来"如果点了 X 就 Y")
- retained-mode 的好处:解耦(callback 可以后注册)
- immediate-mode 的"callback"就是函数返回值后面的 if block,无注册,无需 unregister

### Lv2 · 动手实践

**题**:写一个最小 immediate-mode 框架,有 button 和 checkbox。用 stdin 模拟鼠标和键盘。

**参考解答**:

```rust
use std::collections::HashMap;
use std::io::{self, BufRead};

struct Ui {
    mouse_x: f32,
    mouse_y: f32,
    left_pressed: bool,
    left_just_pressed: bool,
    state: HashMap<u64, bool>,  // checkbox 状态
    draw_list: Vec<String>,
}

fn hash_str(s: &str) -> u64 {
    let mut h = 0xcbf29ce484222325u64;
    for b in s.bytes() { h ^= b as u64; h = h.wrapping_mul(0x100000001b3); }
    h
}

impl Ui {
    fn new() -> Self {
        Self {
            mouse_x: 0.0, mouse_y: 0.0,
            left_pressed: false, left_just_pressed: false,
            state: HashMap::new(), draw_list: Vec::new(),
        }
    }

    fn in_rect(&self, x: f32, y: f32, w: f32, h: f32) -> bool {
        self.mouse_x >= x && self.mouse_x < x + w
            && self.mouse_y >= y && self.mouse_y < y + h
    }

    fn button(&mut self, label: &str, x: f32, y: f32) -> bool {
        let w = 100.0; let h = 20.0;
        let hover = self.in_rect(x, y, w, h);
        let clicked = self.left_just_pressed && hover;
        self.draw_list.push(format!(
            "[{}] button '{}' at ({}, {}) {}",
            if hover { "HOVER" } else { "     " }, label, x, y,
            if clicked { " <- CLICKED" } else { "" }
        ));
        clicked
    }

    fn checkbox(&mut self, label: &str, x: f32, y: f32) -> bool {
        let w = 100.0; let h = 20.0;
        let id = hash_str(label);
        let hover = self.in_rect(x, y, w, h);
        let checked = *self.state.entry(id).or_insert(false);
        let mut changed = false;
        if self.left_just_pressed && hover {
            self.state.insert(id, !checked);
            changed = true;
        }
        self.draw_list.push(format!(
            "[{}] checkbox '{}' {} {}",
            if hover { "HOVER" } else { "     " }, label,
            if checked { "[X]" } else { "[ ]" },
            if changed { " <- CHANGED" } else { "" }
        ));
        changed
    }
}

fn main() {
    let mut ui = Ui::new();
    let mut prev_pressed = false;
    let stdin = io::stdin();
    for line in stdin.lock().lines() {
        let line = line.unwrap();
        let parts: Vec<&str> = line.split_whitespace().collect();
        if parts.len() < 3 { continue; }
        ui.mouse_x = parts[0].parse().unwrap_or(0.0);
        ui.mouse_y = parts[1].parse().unwrap_or(0.0);
        ui.left_pressed = parts[2] == "1";
        ui.left_just_pressed = ui.left_pressed && !prev_pressed;
        prev_pressed = ui.left_pressed;

        ui.draw_list.clear();

        // "声明" UI
        if ui.button("Save", 10.0, 10.0) { println!(">>> SAVE clicked!"); }
        if ui.button("Load", 10.0, 35.0) { println!(">>> LOAD clicked!"); }
        if ui.checkbox("enable_sound", 10.0, 60.0) { println!(">>> sound toggled"); }

        for line in &ui.draw_list { println!("{}", line); }
    }
}
```

测试:`echo "20 10 1\n20 10 0\n20 60 1\n20 60 0" | cargo run`
