## 2 · 心智模型

### 类比:电路调试

电子工程师搭新电路板,先断开所有传感器 / 显示,只测主芯片供电。供电稳定后,一个一个连传感器,每连一个测一次。这样如果哪步出问题,立刻知道是哪个传感器。

软件一样。新后端引入,先开核心功能,稳定后再加其他。

### 2.3 坐标系转换

Day 204 你做了"鼠标光标反投影"——把屏幕鼠标坐标反推到世界坐标,做实体 pick。在软件渲染时代,鼠标坐标和 framebuffer 像素一一对应。

OpenGL 后:

- **framebuffer 是物理像素**(800x600)
- **窗口大小是 logical 像素**(HiDPI 下可能 800x600 但物理 1600x1200)
- **鼠标坐标是 logical 像素**

转换:

```rust
let mouse_logical = input.mouse_pos;  // (200.0, 150.0)
let scale = window.scale_factor();    // 2.0
let mouse_physical = mouse_logical * scale;  // (400.0, 300.0)

// framebuffer 用 physical
let fb_x = mouse_physical.x;
let fb_y = mouse_physical.y;
```

漏掉 scale,pick 错位。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**渐进集成(Progressive Integration)** 是工程最佳实践:

- **Feature Flag** —— 每个功能 `#[cfg(feature = "...")]` 或运行时 flag
- **Canary Release** —— 小流量先上,观察再全量
- **Dark Launch** —— 功能代码部署但不暴露 UI,测稳定性

游戏开发同样:

- 新功能加 `debug_assertions` 或 `cfg(debug)` flag
- 内部测试通过后 release 启用
- 出 bug 立刻 disable

### 3.2 · 🎨 图形学视角

OpenGL 后端下不同 debug UI 需要不同渲染策略:

- **2D overlay**(profiler 图表)—— 用正交投影 quad
- **3D gizmo**(实体 pick 高亮)—— 用 3D pipeline,深度测试 disable
- **线条渲染**(碰撞 box 可视化)—— `glDrawArrays(LINES, ...)`
- **文字**—— 用 bitmap font texture quad

每个类型一个 shader / pipeline。Day 240 三层架构的好处:加新 overlay 不影响其他。

### Lv1 · 概念辨析

**题**:为什么 Day 235 要禁用部分 debug UI,而不是一次切全部?

**参考解答**:风险控制。Day 235 切 OpenGL 是大改动,如果一次启用所有功能,出 bug 难定位(可能是 OpenGL 本身、可能是某个 UI 功能、可能是它们的交互)。

### Lv2 · 动手实践

**题**:在 Day 252 的程序里加一个简单的 profiler overlay(画帧时间小图)。完成标准:F4 切换显示,曲线在屏幕左下角,实时滚动。

**参考解答**:

```rust
pub struct GameState {
    pub show_profiler: bool,
    pub frame_times: std::collections::VecDeque<f32>,  // 最近 100 帧
    pub frame_time: f32,
}

impl GameState {
    pub fn new() -> Self {
        Self {
            show_profiler: false,
            frame_times: std::collections::VecDeque::with_capacity(100),
            frame_time: 16.7,
        }
    }

    pub fn update_frame_time(&mut self, dt: f32) {
        self.frame_time = dt * 1000.0;  // ms
        self.frame_times.push_back(self.frame_time);
        if self.frame_times.len() > 100 {
            self.frame_times.pop_front();
        }
    }

    pub fn draw_profiler(&self) {
        if !self.show_profiler { return; }

        println!("\n=== Profiler ===");
        println!("Frame: {:.2}ms ({:.1} FPS)",
            self.frame_time, 1000.0 / self.frame_time.max(0.01));

        // ASCII 图表
        let max_ft = self.frame_times.iter().cloned().fold(0.0f32, f32::max).max(16.7);
        print!("[");
        for &ft in &self.frame_times {
            let bar_len = ((ft / max_ft) * 20.0) as usize;
            let c = if ft > 20.0 { '#' } else if ft > 16.7 { '*' } else { '.' };
            for _ in 0..bar_len { print!("{}", c); }
        }
        println!("]");
    }
}

fn main() {
    let mut state = GameState::new();
    let mut frame = 0u64;

    loop {
        let dt = 0.016 + (frame as f32 % 10.0) * 0.001;  // 模拟波动
        state.update_frame_time(dt);

        if frame % 30 == 0 {
            state.show_profiler = !state.show_profiler;
            state.draw_profiler();
        }

        frame += 1;
        if frame > 200 { break; }
        std::thread::sleep(std::time::Duration::from_millis(16));
    }
}
```

### Rust 完整多 debug UI

```rust
use std::collections::VecDeque;

#[derive(Default)]
pub struct GameState {
    pub show_profiler: bool,
    pub show_inspector: bool,
    pub show_explorer: bool,
    pub selected_entity: Option<u32>,
    pub frame_times: VecDeque<f32>,
    pub fps: f32,
}

impl GameState {
    pub fn new() -> Self {
        Self {
            show_profiler: true,
            ..Default::default()
        }
    }

    pub fn push_frame_time(&mut self, dt_ms: f32) {
        self.frame_times.push_back(dt_ms);
        if self.frame_times.len() > 100 { self.frame_times.pop_front(); }
        self.fps = 1000.0 / dt_ms.max(0.01);
    }

    pub fn toggle(&mut self, key: &str) {
        match key {
            "F2" => self.show_explorer = !self.show_explorer,
            "F3" => self.show_inspector = !self.show_inspector,
            "F4" => self.show_profiler = !self.show_profiler,
            _ => {}
        }
    }
}

fn draw_world(state: &GameState) {
    println!("[World] 渲染游戏画面 (FPS: {:.1})", state.fps);
}

fn draw_profiler_overlay(state: &GameState) {
    if !state.show_profiler { return; }
    let avg = state.frame_times.iter().sum::<f32>()
        / state.frame_times.len().max(1) as f32;
    let max = state.frame_times.iter().cloned().fold(0.0f32, f32::max);

    print!("[Profiler] ");
    for &ft in &state.frame_times {
        let c = if ft > 20.0 { '#' } else if ft > 16.7 { '*' } else { '.' };
        print!("{}", c);
    }
    println!(" (avg {:.2}ms, max {:.2}ms)", avg, max);
}

fn draw_entity_inspector(state: &GameState) {
    if !state.show_inspector { return; }
    if let Some(id) = state.selected_entity {
        println!("[Inspector] Entity #{}: pos=(100, 200), health=80", id);
    } else {
        println!("[Inspector] (未选中实体,点击实体选中)");
    }
}

fn draw_variable_explorer(state: &GameState) {
    if !state.show_explorer { return; }
    println!("[Explorer] player.speed=5.0, gravity=9.8, ...");
}

fn game_update_and_render(state: &mut GameState) {
    draw_world(state);
    draw_profiler_overlay(state);
    draw_entity_inspector(state);
    draw_variable_explorer(state);
}

fn main() {
    let mut state = GameState::new();

    for frame in 0..50u64 {
        let dt_ms = 16.0 + (frame as f32 % 7.0);
        state.push_frame_time(dt_ms);

        // 模拟按键
        if frame == 10 { state.toggle("F3"); }
        if frame == 20 { state.toggle("F2"); }
        if frame == 30 { state.selected_entity = Some(42); }

        println!("\n--- Frame {} ---", frame);
        game_update_and_render(&mut state);
    }
}
```

补充:工业级 debug UI 的渲染管线:

```
1. 游戏主渲染(GPU)
2. Game → UI 合成
3. Debug UI 渲染(独立 pass)
4. Debug overlay 绘制(text、line、quad)
5. swap buffer
```

Debug UI 在游戏渲染之上,作为独立 pass。这种设计让 debug UI 与游戏渲染解耦,OpenGL 升级时 debug UI 影响最小。
