## 2 · 心智模型

### 类比:整理扑克牌

牌堆 → 整理手里的牌:

- **Insertion**:一张一张接,接到手里时插到正确位置
- **Bubble**:反复扫,大数往后冒泡
- **Merge**:分成两半,各自整理,再合并
- **Quick**:选一张作 pivot,小的放左、大的放右,递归两边

每种思路不同,各有适用场景。

### 2.1 Insertion Sort

```rust
fn insertion_sort<T: Ord>(arr: &mut [T]) {
    for i in 1..arr.len() {
        let mut j = i;
        while j > 0 && arr[j - 1] > arr[j] {
            arr.swap(j - 1, j);
            j -= 1;
        }
    }
}
```

**思路**:第 i 次循环后,arr[0..=i] 排好序。下次拿 arr[i+1],往左插到正确位置。

**复杂度**:

- 最坏 O(n²)(逆序)
- 最好 O(n)(已排序)
- 平均 O(n²)

**适用**:n < 100 的小数组、几乎已排序的大数组。

### 2.2 Bubble Sort

```rust
fn bubble_sort<T: Ord>(arr: &mut [T]) {
    let n = arr.len();
    for i in 0..n {
        for j in 0..(n - i - 1) {
            if arr[j] > arr[j + 1] {
                arr.swap(j, j + 1);
            }
        }
    }
}
```

**思路**:每轮把最大元素"冒泡"到末尾。n 轮完成。

**复杂度**:O(n²) 各情况。**实际很少用**,因为常数大于 insertion sort。教学价值。

### 2.3 Merge Sort

```rust
fn merge_sort<T: Ord + Clone>(arr: &mut [T]) {
    let n = arr.len();
    if n <= 1 { return; }
    let mid = n / 2;
    merge_sort(&mut arr[..mid]);
    merge_sort(&mut arr[mid..]);

    let mut merged = Vec::with_capacity(n);
    let (mut i, mut j) = (0, mid);
    while i < mid && j < n {
        if arr[i] <= arr[j] {
            merged.push(arr[i].clone());
            i += 1;
        } else {
            merged.push(arr[j].clone());
            j += 1;
        }
    }
    while i < mid { merged.push(arr[i].clone()); i += 1; }
    while j < n { merged.push(arr[j].clone()); j += 1; }
    arr.copy_from_slice(&merged);
}
```

**思路**:分治。分成两半各自排,再合并两个有序序列。

**复杂度**:O(n log n) 最坏、平均、最好。**稳定**(相等元素保持原序)。

**适用**:大数据、需要稳定性。代价:O(n) 额外空间。

### 2.4 Quicksort

```rust
fn quick_sort<T: Ord>(arr: &mut [T]) {
    if arr.len() <= 1 { return; }
    let pivot_idx = partition(arr);
    let (left, right) = arr.split_at_mut(pivot_idx);
    quick_sort(left);
    quick_sort(&mut right[1..]);
}

fn partition<T: Ord>(arr: &mut [T]) -> usize {
    let len = arr.len();
    let pivot = len - 1;  // 简化:取最后元素
    let mut i = 0;
    for j in 0..pivot {
        if arr[j] <= arr[pivot] {
            arr.swap(i, j);
            i += 1;
        }
    }
    arr.swap(i, pivot);
    i
}
```

**思路**:选 pivot,小的放左、大的放右,递归左右两边。

**复杂度**:

- 平均 O(n log n)
- 最坏 O(n²)(pivot 总是选到极值,如已排序数组 + 取最后元素)

**适用**:通用排序,通常最快。Rust `Vec::sort_unstable` 是 pattern-defeating quicksort。

### 2.5 性能对比

100,000 随机整数排序:

```
insertion_sort: 2.5s (O(n²))
bubble_sort:    12s (O(n²),常数大)
merge_sort:     25ms (O(n log n))
quick_sort:     15ms (O(n log n),常数小)
```

理论 vs 实际:quick_sort > merge_sort > insertion >> bubble,符合 O(n log n) < O(n²) 预期。

排序演化:

- **1950s**:bubble / insertion(简单,慢)
- **1960s**:quicksort(Hoare)、merge sort(von Neumann)

## 10 · 深入:排序算法的实现选择

casey 在 day232 展示几个具体排序算法。让我把它们彻底讲透,理解每种算法的适用场景。

### 10.1 五种主流排序算法

**1. Insertion sort**(简单,n²)

```rust
fn insertion_sort<T: Ord>(arr: &mut [T]) {
    for i in 1..arr.len() {
        let mut j = i;
        while j > 0 && arr[j-1] > arr[j] {
            arr.swap(j-1, j);
            j -= 1;
        }
    }
}
```

- 平均 O(n²),最坏 O(n²)
- 空间 O(1)
- 稳定
- 优点:n < 32 时最快,cache 完美
- 缺点:n 大时慢

**2. Quicksort**(分治,n log n)

```rust
fn quicksort<T: Ord>(arr: &mut [T]) {
    if arr.len() <= 1 { return; }
    let pivot = partition(arr);
    let (left, right) = arr.split_at_mut(pivot);
    quicksort(left);
    quicksort(&mut right[1..]);
}

fn partition<T: Ord>(arr: &mut [T]) -> usize {
    let len = arr.len();
    let pivot = len - 1;
    let mut i = 0;
    for j in 0..pivot {
        if arr[j] <= arr[pivot] {
            arr.swap(i, j);
            i += 1;
        }
    }
    arr.swap(i, pivot);
    i
}
```

- 平均 O(n log n),最坏 O(n²)(bad pivot)
- 空间 O(log n)(递归栈)
- 不稳定
- 优点:平均最快,cache 友好
- 缺点:最坏 case 慢

**3. Merge sort**(分治,稳定 n log n)

```rust
fn merge_sort<T: Ord + Clone>(arr: &mut [T]) {
    let len = arr.len();
    if len <= 1 { return; }
    let mid = len / 2;
    merge_sort(&mut arr[..mid]);
    merge_sort(&mut arr[mid..]);
    
    let mut merged = Vec::with_capacity(len);
    let mut i = 0; let mut j = mid;
    while i < mid && j < len {
        if arr[i] <= arr[j] {
            merged.push(arr[i].clone());
            i += 1;
        } else {
            merged.push(arr[j].clone());
            j += 1;
        }
    }
    while i < mid { merged.push(arr[i].clone()); i += 1; }
    while j < len { merged.push(arr[j].clone()); j += 1; }
    arr.copy_from_slice(&merged);
}
```

- O(n log n) 平均 / 最坏
- 空间 O(n)(临时数组)
- 稳定
- 优点:稳定,可外部排序
- 缺点:O(n) 额外空间

**4. Heapsort**(原地,n log n)

```rust
fn heapsort<T: Ord>(arr: &mut [T]) {
    // Build heap
    for i in (1..arr.len()).rev() {
        sift_up(arr, i);
    }
    // Extract max
    for end in (1..arr.len()).rev() {
        arr.swap(0, end);
        sift_down(&mut arr[..end], 0);
    }
}
```

- O(n log n) 平均 / 最坏
- 空间 O(1)
- 不稳定
- 优点:原地,最坏 O(n log n)(比 quicksort 强)
- 缺点:cache 不友好(随机访问),常数大

**5. Radix sort**(整数,O(n))

```rust
fn radix_sort(arr: &mut [u64]) {
    let mut temp = vec![0; arr.len()];
    for byte_pos in 0..8 {
        let shift = byte_pos * 8;
        let mask = 0xFFu64 << shift;
        
        // Counting sort on this byte
        let mut count = [0usize; 256];
        for &v in arr.iter() {
            let byte = ((v & mask) >> shift) as usize;
            count[byte] += 1;
        }
        let mut prefix = [0usize; 256];
        for i in 1..256 {
            prefix[i] = prefix[i-1] + count[i-1];
        }
        for &v in arr.iter() {
            let byte = ((v & mask) >> shift) as usize;
            temp[prefix[byte]] = v;
            prefix[byte] += 1;
        }
        std::mem::swap(arr, &mut temp);
    }
}
```

- O(8n) = O(n)(u64 key)
- 空间 O(n)(temp array)
- 稳定(LSD)
- 优点:线性时间
- 缺点:只对整数 key

### 10.3 Rust 标准库的实现:pdqsort

Rust `slice::sort` 用 pdqsort(pattern-defeating quicksort):

- n < 24:insertion sort
- 大部分情况:quicksort + 三向切分
- 检测 bad pattern:切到 heapsort(避免 O(n²))
- 大量相同元素:counting sort

实际比单纯 quicksort 快 2-3 倍,且无 O(n²) 风险。

### 10.4 算法选择的决策树

```
n < 32?        → Insertion sort
n 大,key 是整数? → Radix sort
n 大,需要稳定?   → Merge sort / pdqsort stable
n 大,内存紧?    → Heapsort
其他            → Quicksort / pdqsort
```

casey 的 day234 radix sort 因为 HH 的 sort key 是 u64,完美适用。

## 11 · 深入:排序算法的工程实战

排序不仅是算法问题,还是工程问题。让我把工程实战中的细节讲清楚。

### 11.1 比较函数的陷阱

Rust 的 sort 接受 `Fn(&T, &T) -> Ordering`。错误的比较函数会导致:

```rust
// 错误:不是 total order
fn bad_compare(a: &f32, b: &f32) -> Ordering {
    if a < b { Less }
    else if a > b { Greater }
    else { Equal }
}
// NaN 处理错误,sort 结果未定义
```

Rust `f32` 没实现 Ord(因为 NaN),要用 `total_cmp`(Rust 1.62+):

```rust
let mut arr = [3.0, 1.0, f32::NAN, 2.0];
arr.sort_by(|a, b| a.total_cmp(b));
// 正确处理 NaN,NAN 排在最后
```

casey 的 HH 不用 f32 排序(sort key 是 u64),但生产项目要小心。

### 11.2 部分排序

某些场景只需要"前 K 个最小元素",不需要全排:

```rust
// Rust:select_nth_unstable
let mut arr = vec![5, 1, 4, 2, 3];
let (smaller, median, larger) = arr.select_nth_unstable(2);
// 现在 arr[2] 是第 3 小,smaller 都更小,larger 都更大
```

性能:O(n) 平均,比全排 O(n log n) 快。

casey 不在 HH 演示,但商业游戏 AI(找最近敌人)常用。

### 11.3 外部排序

数据超过内存,用**外部排序**:

1. 分块读入内存,sort,写到临时文件
2. 多个临时文件归并(merge sort 的 merge 阶段)
3. 输出最终排序结果

Linux 的 `sort` 命令自动用外部排序:

```bash
# 排序 10GB 文件
sort --parallel=4 -S 1G huge.txt > sorted.txt
```

casey 的 HH 不涉及大数据,但生产项目要知道。

### 11.4 并行排序

多核排序:

- **parallel merge sort**:递归并行
- **parallel quicksort**:partition 串行,递归并行
- **sample sort**:bucket by samples,并行各 bucket

Rust 的 `rayon` 提供并行迭代:

```rust
use rayon::prelude::*;

let mut arr = vec![5, 1, 4, 2, 3];
arr.par_sort();  // 并行排序
```

casey 单线程,但 Rust 翻译版可以用 rayon。

### 11.5 排序的 cache 行为

排序的 cache 影响:

- **顺序访问**(merge sort,radix sort):cache 友好
- **随机访问**(quicksort partition):cache 中等
- **远距离访问**(heapsort sift down):cache 不友好

casey 的 radix sort cache 极佳,实际性能比理论 O(n) 更快。

### 11.6 排序的稳定性 vs 性能

Rust 提供 `sort`(稳定)和 `sort_unstable`(不稳定):

```rust
arr.sort();          // 稳定,merge sort 变种
arr.sort_unstable(); // 不稳定,pdqsort
```

`sort_unstable` 通常快 2x。casey 在 day232 推荐:**只要不需要稳定性,用 sort_unstable**。

### 11.7 casey 的选择:radix sort for sort key
