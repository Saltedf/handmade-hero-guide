# Day 250 · 清理调试 GUID

> Day 218 你加了 debug 元素哈希,GUID(Globally Unique Identifier)用作唯一 ID。回头看,GUID 生成方式过于复杂——`atomic counter + thread id + random salt + hash combine`,5 个字段 16 字节。今天 Casey 简化:GUID = 64 位 hash(name),8 字节,生成快 10x。

## 0 · 为什么要有这一天

GUID 用于 debug 系统里唯一标识每个变量 / 事件。Day 218 设计:

```rust
struct Guid {
    counter: u32,        // 全局递增计数
    thread_id: u32,      // 线程 ID
    salt: u32,           // 随机盐
    hash: u64,           // 名字 hash
}
// 共 16 字节
```

为什么这么复杂?Casey 当时担心:

- 多线程同时生成 → 加 thread id 区分
- 重启程序同名字变量冲突 → 加 salt
- 全局排序 → 加 counter

但**实际**:

- thread id 不需要(变量名已包含调用点信息)
- salt 不需要(同 frame 内 GUID 不冲突就行)
- counter 不需要(hash(name) 已经够唯一)

Day 250 简化:`Guid = u64`,等于 hash(name + file + line)。8 字节,生成 10ns(之前 100ns)。

**为什么这件事重要**:简化是连续的——Day 247 简化 value,Day 249 简化宏,Day 250 简化 GUID。每一步看一个数据结构,**减字段,保功能**。

**心理锚点**:看完今天,你能审视每个数据结构,问"这个字段真有必要吗"。

## 1 · Casey 今天做了什么

Casey 重写 Guid:

1. 删 `counter` / `thread_id` / `salt`,只留 `hash: u64`
2. hash 输入:`file!() + line!() + name`,编译时已知
3. 用 FNV-1a hash(简单 / 快 / 够散列)
4. 测试:重启程序同名字变量得相同 GUID(debug 数据能跨重启一致)
5. 验证:profiler 仍工作

**关键决策**:**确定性 GUID**——同一变量重启后 GUID 相同。这让"上次运行的 debug 数据"和"本次"能对比。

## 2 · 心智模型

### 类比:身份证号

中国身份证 18 位,包含:

- 地区码(6 位)
- 生日(8 位)
- 顺序码(3 位)
- 校验码(1 位)

设计复杂,但实际查询只用"姓名 + 生日"就能唯一确定。

GUID 也一样:**简单 hash 就够唯一**,不需要复合字段。

### 2.1 FNV-1a hash

Fowler-Noll-Vo hash,简单快速:

```rust
fn fnv1a_hash(data: &[u8]) -> u64 {
    let mut hash: u64 = 0xcbf29ce484222325;  // FNV offset basis
    for &b in data {
        hash ^= b as u64;
        hash = hash.wrapping_mul(0x100000001b3);  // FNV prime
    }
    hash
}

// 用法
let guid = fnv1a_hash(b"player_pos");
```

**特点**:

- 简单(10 行代码)
- 快(~1 GB/s)
- 散列好(冲突率低)
- **非加密安全**(攻击者能制造冲突,但 debug 不需要安全)

适合 debug GUID,不适合 HashMap key(用 SipHash,Day 55)或加密(用 SHA-256)。

### 2.2 确定性 GUID

```rust
pub struct Guid(pub u64);

impl Guid {
    pub fn from_name(name: &'static str) -> Self {
        Self(fnv1a_hash(name.as_bytes()))
    }

    pub fn from_location(name: &'static str, file: &'static str, line: u32) -> Self {
        let mut data = Vec::new();
        data.extend_from_slice(file.as_bytes());
        data.extend_from_slice(b":");
        data.extend_from_slice(&line.to_le_bytes());
        data.extend_from_slice(b":");
        data.extend_from_slice(name.as_bytes());
        Self(fnv1a_hash(&data))
    }
}

macro_rules! guid {
    ($name:expr) => {
        $crate::Guid::from_location($name, file!(), line!())
    };
}

// 调用
let g = guid!("player_pos");  // 编译时填 file 和 line
```

每次重新编译,同一行 `guid!("player_pos")` 生成相同 GUID。**确定性**意味着:

- 上次运行存的 debug 数据,本次能对比
- 多人协作时,大家看到同一 GUID 是同一变量
- 跨平台一致(不像 counter 受线程调度影响)

### 2.3 GUID 冲突处理

64 位 hash,冲突概率约 `1/2^64`。即便 1 百万个变量,冲突概率仍 `1/2^44`(微小)。但万一冲突?

```rust
// 启动时检查
fn verify_no_collision(guids: &HashMap<Guid, &str>) {
    let mut seen = HashMap::new();
    for (g, name) in guids {
        if let Some(prev) = seen.insert(*g, *name) {
            if prev != *name {
                panic!("GUID 冲突:{} 和 {} 都是 {:?}", prev, name, g);
            }
        }
    }
}
```

如果真冲突(从未实际发生),panic 让你立刻知道,改名字。

### 2.4 GUID 用途

```rust
// 1. debug 变量注册
fn debug_var(name: &'static str, value: Value) {
    let guid = guid!(name);
    DEBUG_STORE.lock().insert(guid, DebugValue { name, value, ... });
}

// 2. profiler 事件
struct ProfileEvent {
    guid: Guid,
    start: Instant,
    end: Instant,
}

// 3. 跨帧数据关联
let last_frame_guid = guid!("frame_data");
let last = DEBUG_STORE.get(last_frame_guid);
```

### 2.5 Rust 所有权 + GUID

GUID 是 `Copy`(8 字节),函数传值无开销。对比 `Arc<String>`(引用计数,原子操作)或 `&'static str`(lifetime 约束),GUID 简单:

```rust
fn process(guid: Guid) {  // Copy,无 lifetime 约束
    // ...
}

let g = guid!("foo");
process(g);  // Copy
process(g);  // 还能用
```

### 3.4 · 🦀 Rust 生态视角

Rust 标准库的 `Hash` trait:

```rust
pub trait Hash {
    fn hash<H: Hasher>(&self, state: &mut H);
}

// 实现
impl Hash for Guid {
    fn hash<H: Hasher>(&self, state: &mut H) {
        self.0.hash(state);
    }
}
```

`Hasher` trait 让你换算法(DefaultHasher 用 SipHash,FxHash 用 FxHash,FnvHash 用 FNV)。

## 5 · 对照与变奏

### Hash 函数谱系

| 用途 | 算法 | 速度 | 安全性 |
|---|---|---|---|
| debug GUID | FNV-1a | 极快 | 无 |
| HashMap | SipHash / FxHash | 中 | 防 DoS |
| 文件指纹 | SHA-1 / SHA-256 | 中 | 加密安全 |
| 密码 | bcrypt / argon2 | 慢(故意) | 极强 |

跟 HH 用 FNV-1a 起步,需要时换 SipHash。

### 确定性 ID 的优劣

**优点**:

- 跨运行一致(对比历史数据)
- 跨平台一致(同代码)
- 不需要持久化(下次运行算出来一样)

**缺点**:

- 重命名后 ID 变(历史数据失效)
- 同名变量冲突(需 location 消歧)

跟 HH 接受缺点,debug 用 ID 重命名是小事。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 debug GUID 用确定性 hash,而 UUID 用随机数?各自适用场景?

**参考解答**:

- **debug GUID 用确定性 hash** —— 同一变量多次运行 GUID 相同,方便对比 / 关联数据。debug 数据不需要绝对唯一,需要"我能找到上次同名变量"
- **UUID 用随机数** —— 跨机器绝对唯一,数据库主键 / 文件 ID 等。不关心"上次生成的是什么"

两者都是"唯一标识",但**需求不同**——确定性 vs 全局唯一。

## 8 · Rust / Arch 落地代码

### Rust 完整 GUID 实现

```rust
use std::collections::HashMap;

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
pub struct Guid(pub u64);

const FNV_OFFSET: u64 = 0xcbf29ce484222325;
const FNV_PRIME: u64 = 0x100000001b3;

fn fnv1a(data: &[u8]) -> u64 {
    let mut h = FNV_OFFSET;
    for &b in data {
        h ^= b as u64;
        h = h.wrapping_mul(FNV_PRIME);
    }
    h
}

impl Guid {
    pub fn from_name(name: &str) -> Self {
        Self(fnv1a(name.as_bytes()))
    }

    pub fn from_location(name: &str, file: &str, line: u32) -> Self {
        let mut data = Vec::with_capacity(file.len() + name.len() + 8);
        data.extend_from_slice(file.as_bytes());
        data.push(b':');
        data.extend_from_slice(&line.to_le_bytes());
        data.push(b':');
        data.extend_from_slice(name.as_bytes());
        Self(fnv1a(&data))
    }
}

#[macro_export]
macro_rules! guid {
    ($name:expr) => {
        $crate::Guid::from_location($name, file!(), line!())
    };
}

pub struct DebugStore {
    values: HashMap<Guid, DebugValue>,
}

pub struct DebugValue {
    pub name: &'static str,
    pub value: f32,
}

impl DebugStore {
    pub fn new() -> Self {
        Self { values: HashMap::new() }
    }

    pub fn set(&mut self, guid: Guid, name: &'static str, value: f32) {
        self.values.insert(guid, DebugValue { name, value });
    }

    pub fn get(&self, guid: Guid) -> Option<f32> {
        self.values.get(&guid).map(|v| v.value)
    }

    pub fn verify_no_collision(&self) {
        let mut seen: HashMap<&str, Guid> = HashMap::new();
        for (g, v) in &self.values {
            if let Some(prev_g) = seen.insert(v.name, *g) {
                if prev_g != *g {
                    eprintln!("警告:同名变量 {} 有不同 GUID", v.name);
                }
            } else if seen.iter().any(|(n, gg)| *gg == *g && *n != v.name) {
                eprintln!("警告:不同名变量 GUID 冲突");
            }
        }
    }
}

fn main() {
    let mut store = DebugStore::new();

    // 模拟多处设置
    let g1 = Guid::from_location("player_speed", "game.rs", 42);
    let g2 = Guid::from_location("player_speed", "game.rs", 100);
    let g3 = Guid::from_location("gravity", "physics.rs", 10);

    store.set(g1, "player_speed", 5.0);
    store.set(g2, "player_speed", 6.0);  // 覆盖(同 file:line)
    store.set(g3, "gravity", 9.8);

    println!("player_speed (game.rs:42) = {:?}", store.get(g1));
    println!("player_speed (game.rs:100) = {:?}", store.get(g2));
    println!("gravity = {:?}", store.get(g3));

    store.verify_no_collision();

    // 测试确定性
    let g1_again = Guid::from_location("player_speed", "game.rs", 42);
    println!("GUID 一致:{} (g1 == g1_again)", g1 == g1_again);
}
```

## 10 · 深入:debug GUID 的清理

casey 在 day250 清理 debug GUID 系统——这是 day218 引入的 GUID 系统的简化。

### 10.1 GUID 系统回顾

day218 用 FNV-1a hash 给 debug 字符串分配 u64 GUID:

```rust
const fn guid(s: &str) -> u64 {
    let mut h = FNV_OFFSET;
    let bytes = s.as_bytes();
    let mut i = 0;
    while i < bytes.len() {
        h ^= bytes[i] as u64;
        h = h.wrapping_mul(FNV_PRIME);
        i += 1;
    }
    h
}

// 使用
let guid = guid("debug/player/health");
```

day250 简化 GUID 系统,清理之前积累的复杂度。

### 10.2 GUID 简化的方向

casey 在 day250 简化:

1. **去掉冗余字段**:debug var 不再存原始 string
2. **统一 hash 函数**:从多个 hash 改成 FNV-1a
3. **简化生成 API**:从多个函数改成单个 const fn
4. **删除未用 API**:debug GUID 系统之前有"GUID 比较"等 API,实际未用

### 10.3 const fn 的重要性

GUID 生成是 const fn,编译时计算。好处:

- **零运行时开销**:hash 在编译时算好
- **编译时检查**:同 string 永远 hash 同值
- **优化友好**:编译器看到 const,可以深度优化

Rust 1.31+ 支持 const fn,casey 在 day218 / 250 充分利用。

### 10.4 GUID 冲突的处理

casey 在 day218 已经讨论过:加运行时 assert 检测冲突。day250 简化时保留这个机制——debug build 检测冲突,release build 跳过(性能)。

### 10.5 教学总结

day250 的核心要点:

1. **GUID 系统简化**:删除冗余
2. **const fn 编译时计算**:零开销
3. **运行时检测冲突**:debug build 必需
4. **casey 工程纪律**:技术债必还
5. **保持行为不变**:简化不改功能

day250 是清理系列的第四集,继续简化 debug 系统。

### 10.6 GUID 的工业级应用

GUID(Globally Unique Identifier)在工业界无处不在:

**1. Unity asset GUID**:128-bit UUID,跨进程稳定
**2. Unreal asset GUID**:类似 Unity
**3. Steam app ID**:每个 Steam 游戏 ID
**4. UUID v4**:随机 128-bit,Web API 常用
**5. Snowflake ID**:Twitter 的分布式 ID(时间戳 + 机器 ID + sequence)

casey HH 的 64-bit FNV hash 是简化版——确定性、内部用、无冲突保护。生产项目根据需求选不同 GUID 系统。

### 10.7 Rust 的 GUID 实现

Rust 生态的 GUID crate:

- **uuid**:标准 UUID v1-v5
- **guid**:Windows GUID 兼容
- **ulid**:lexicographically sortable UUID
- **nanoid**:短 URL 友好

casey HH 不用这些(自实现 FNV),但生产项目根据需求选。

### 10.8 GUID 的 trade-off

不同 GUID 系统的 trade-off:

| 系统 | 长度 | 确定性 | 跨进程稳定 | 适用 |
|---|---|---|---|---|
| FNV hash(casey) | 64 bit | 是 | 是(同 string) | 内部 ID |
| UUID v4 | 128 bit | 否(随机) | 是 | 通用 |
| Snowflake | 64 bit | 部分(时间) | 是 | 分布式 |
| NanoID | 80 bit(可调) | 否 | 是 | URL |

```rust
const FNV_OFFSET: u64 = 0xcbf29ce484222325;
const FNV_PRIME: u64 = 0x100000001b3;

pub const fn guid(s: &str) -> u64 {
    let mut h = FNV_OFFSET;
    let bytes = s.as_bytes();
    let mut i = 0;
    while i < bytes.len() {
        h ^= bytes[i] as u64;
        h = h.wrapping_mul(FNV_PRIME);
        i += 1;
    }
    h
}

#[cfg(debug_assertions)]
fn verify_no_collisions(ids: &[(u64, &str)]) {
    use std::collections::HashSet;
    let mut seen_guids: HashSet<u64> = HashSet::new();
    let mut seen_strings: HashSet<&str> = HashSet::new();
    for (g, s) in ids {
        if seen_guids.contains(g) && !seen_strings.contains(s) {
            panic!("GUID collision: {} -> {}", s, g);
        }
        seen_guids.insert(*g);
        seen_strings.insert(*s);
    }
}

// 使用
const GUID_HEALTH: u64 = guid("debug/player/health");

fn main() {
    #[cfg(debug_assertions)]
    verify_no_collisions(&[
        (guid("debug/player/health"), "debug/player/health"),
        (guid("debug/player/mana"), "debug/player/mana"),
    ]);
    
    println!("GUID: {}", GUID_HEALTH);
}
```
