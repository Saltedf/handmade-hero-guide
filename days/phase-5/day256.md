
# Day 256 · XBox 控制器卡顿与修复 GL 位块 gamma

> Day 255 你的 profiler 能用了,立刻发现两个 bug:(1) XBox 控制器偶发卡顿(50ms 一帧);(2) GL blit 路径颜色比软渲染略偏。今天 Casey 用 profiler 定位 + 修这两个 bug。

## 0 · 为什么要有这一天

profiler 的价值在于**找 bug**。Day 256 是真实 bug 修复案例:

**Bug 1: 控制器卡顿**

玩家报告:XBox 手柄连接后,游戏每秒卡一次,持续 50ms。

用 Day 255 profiler 看:

```
frame (60ms)  ← 异常
├── input (52ms)  ← 罪魁祸首

```

`poll_controller` 平时 0.1ms,偶尔 52ms。罪魁祸首:XBox 无线手柄休眠,需要唤醒,driver 重连耗时。

**Bug 2: GL blit gamma**

**为什么这件事重要**:profiler 让"凭感觉找 bug"变成"看数据找 bug"。这是工业级游戏开发必备技能。

**心理锚点**:看完今天,你能用 profiler 定位偶发性能 bug + 渲染颜色 bug。

### 2.1 Bug 1: 控制器卡顿

```rust
// Day 113 时代的输入代码
fn poll_controller(state: &mut GameState) {
    let events = gilrs.next_events();  // 偶发 50ms
    for event in events {
        // 处理事件
    }
}
```

`gilrs.next_events()` 内部查 driver。XBox 无线手柄休眠后,driver 需要唤醒,GILRS 同步等待。

**profiler 数据**:

```
frame 1: input 0.1ms  (正常)
frame 2: input 0.1ms
...
frame 60: input 52.3ms  ← 卡顿!
frame 61: input 0.1ms
```

**修复**:

```rust
// 异步 poll:用 thread 单独 poll
fn poll_controller_async(state: &mut GameState) {
    if let Some(events) = state.input_rx.try_recv() {
        // 非阻塞拿事件
        for event in events {
            // 处理
        }
    }
}

// 后台线程
fn input_thread(tx: Sender<Vec<Event>>) {
    let mut gilrs = Gilrs::new().unwrap();
    loop {
        let events: Vec<_> = gilrs.next_events().collect();
        if !events.is_empty() {
            tx.send(events).unwrap();
        }
        std::thread::sleep(Duration::from_millis(1));
    }
}
```

后台线程同步阻塞,主线程 try_recv 非阻塞。卡顿不传到主线程。

### 2.2 Bug 2: GL blit gamma

Day 241 你启用 sRGB framebuffer,GPU 自动 linear→sRGB 转换。但 `glBlitFramebuffer` 直接拷贝像素,**绕过 shader**,也绕过 sRGB 转换。

```rust
// 之前的代码
unsafe {
    gl.bind_framebuffer(glow::READ_FRAMEBUFFER, Some(src));
    gl.bind_framebuffer(glow::DRAW_FRAMEBUFFER, Some(dst));
    gl.blit_framebuffer(
        0, 0, w, h, 0, 0, w, h,
        glow::COLOR_BUFFER_BIT, glow::NEAREST,
    );
}
```

如果 src 是 sRGB(线性值),dst 也是 sRGB,blit 直接拷贝,正确。但如果中间过一帧 linear 处理,blit 出错。

**修复**:blit 用 textured quad(走 fragment shader,经过 sRGB 转换):

```rust
fn srgb_correct_blit(gl: &Context, src_texture: Texture, dst_framebuffer: FB) {
    unsafe {
        gl.bind_framebuffer(glow::FRAMEBUFFER, Some(dst_framebuffer));
        gl.use_program(Some(blit_program));
        gl.bind_vertex_array(Some(quad_vao));
        gl.bind_texture(glow::TEXTURE_2D, Some(src_texture));
        gl.draw_arrays(glow::TRIANGLES, 0, 6);
    }
}
```

shader 显式管理 sRGB。

### 2.5 控制器 driver 的特殊性

不同 OS / 平台 controller driver:

| OS | API |
|---|---|
| Linux | evdev / libinput |
| Windows | XInput / DirectInput |
| macOS | GameController framework |

gilrs 抽象这些。但每个 driver 行为不同:

- Linux evdev 通常快(直接读 /dev/input/event*)
- Windows XInput 偶尔卡(休眠唤醒)
- macOS GameController framework 类似 Windows

跨平台游戏要测每个 OS。

### 2.6 异步输入的本质

输入系统本质是**事件队列**:

```
[Controller] ─[USB/Bluetooth]→ [Kernel driver]
    ↓
[/dev/input/event*] ─→ [gilrs] ─→ [Event channel] ─→ [Game]
```

driver 偶尔慢,但事件**已经产生**,在 kernel 队列里。你的 game 可以异步消费:

```rust
// 后台线程同步读 driver
input_thread_tx.send(gilrs.next_events());

// 主线程非阻塞收
match input_rx.try_recv() {
    Ok(events) => process(events),
    Err(TryRecvError::Empty) => { /* 没事件,正常 */ },
    Err(TryRecvError::Disconnected) => panic!(),
}
```

主线程永远不阻塞。

### 3.1 · 🎮 游戏编程视角

**输入系统设计**:

- **Poll-based** —— 每帧查(简单但可能卡)
- **Event-based** —— 事件队列(主流)
- **Hybrid** —— 后台 poll + 主线程 event(性能 + 简单)

主流引擎用 hybrid。Casey 修后也用 hybrid。

**帧时间 budget**:

```
16.67ms (60 FPS)
├── input:   0.5ms
├── update:  3ms
├── render:  10ms
├── audio:   0.5ms
└── OS/misc: 2ms
```

任何一段超过 budget,FPS 掉。profiler 必须分别测每段。

### 3.2 · 🎨 图形学视角

**Gamma pipeline 完整传播**:

```
纹理(sRGB)→ GPU 自动 sRGB→linear → shader(linear 计算)
   → framebuffer(自动 linear→sRGB)→ 显示器(sRGB)
```

中间任何环节错:

- 纹理没标 SRGB → shader 拿到 sRGB 当 linear,光照错
- shader 输出 linear 但 framebuffer 没 SRGB → 显示器看到 linear 当 sRGB,偏暗
- blit 直接拷贝 sRGB → 跳过转换,如果两端格式不一致就错

Day 241 + Day 256 完整覆盖了 gamma pipeline。

### 3.4 · 🦀 Rust 生态视角

**gilrs** crate:

```rust
use gilrs::{Gilrs, Event, EventType};

let mut gilrs = Gilrs::new().unwrap();

loop {
    while let Some(Event { event, .. }) = gilrs.next_event() {
        match event {
            EventType::ButtonPressed(button, _) => { /* ... */ }
            EventType::AxisChanged(axis, value, _) => { /* ... */ }
            _ => {}
        }
    }
}
```

`next_event()` 是同步的,会阻塞。`next_events()` 迭代器批量取。

异步包装:

```rust
use std::sync::mpsc;
use std::thread;

let (tx, rx) = mpsc::channel();
thread::spawn(move || {
    let mut gilrs = Gilrs::new().unwrap();
    loop {
        let events: Vec<_> = gilrs.next_events().collect();
        if !events.is_empty() {
            tx.send(events).unwrap();
        }
        thread::sleep(std::time::Duration::from_millis(1));
    }
});

// 主线程
match rx.try_recv() {
    Ok(events) => { /* 处理 */ }
    Err(_) => { /* 没事件 */ }
}
```

### Lv2 · 动手实践

**题**:在 Day 255 profiler 基础上,加历史记录(最近 1000 帧)+ 找异常帧。完成标准:打印所有 >30ms 的帧,每帧打印调用树。

**参考解答**:

```rust
pub struct ProfilerHistory {
    pub frames: Vec<Vec<Node>>,  // 每帧一棵树(扁平节点)
}

impl ProfilerHistory {
    pub fn add(&mut self, profiler: &Profiler) {
        self.frames.push(profiler.nodes.clone());
        if self.frames.len() > 1000 {
            self.frames.remove(0);
        }
    }

    pub fn find_slow_frames(&self, threshold_ms: f64) {
        for (i, frame_nodes) in self.frames.iter().enumerate() {
            // 找根节点
            if let Some(root) = frame_nodes.iter().find(|n| n.parent.is_none()) {
                if let Some(end) = root.end {
                    let ms = end.duration_since(root.start).as_secs_f64() * 1000.0;
                    if ms > threshold_ms {
                        println!("=== Frame {} ({:.2}ms) ===", i, ms);
                        print_tree(frame_nodes, 0);
                    }
                }
            }
        }
    }
}
```

## 8 · Rust / Arch 落地代码

### Rust 异步输入 + sRGB blit

```rust
use std::sync::mpsc::{self, TryRecvError};
use std::thread;
use std::time::Duration;

// 模拟 gilrs Event
#[derive(Debug, Clone)]
pub struct InputEvent {
    pub button: u32,
    pub pressed: bool,
}

pub struct AsyncInput {
    rx: mpsc::Receiver<Vec<InputEvent>>,
}

impl AsyncInput {
    pub fn new() -> Self {
        let (tx, rx) = mpsc::channel();
        thread::spawn(move || {
            // 模拟 gilrs.next_events() 偶尔慢
            let mut frame = 0u64;
            loop {
                let events = if frame % 60 == 0 {
                    // 每 60 帧模拟"driver 重连"
                    thread::sleep(Duration::from_millis(50));
                    vec![InputEvent { button: 1, pressed: true }]
                } else {
                    thread::sleep(Duration::from_millis(1));
                    vec![]
                };
                if !events.is_empty() {
                    let _ = tx.send(events);
                }
                frame += 1;
            }
        });
        Self { rx }
    }

    pub fn poll(&self) -> Vec<InputEvent> {
        let mut all = vec![];
        loop {
            match self.rx.try_recv() {
                Ok(events) => all.extend(events),
                Err(TryRecvError::Empty) => break,
                Err(TryRecvError::Disconnected) => break,
            }
        }
        all
    }
}

fn main() {
    let input = AsyncInput::new();

    for frame in 0..200u64 {
        let start = std::time::Instant::now();

        // 同步 poll(异步后台线程)
        let events = input.poll();
        let input_time = start.elapsed();

        // 模拟游戏工作
        thread::sleep(Duration::from_micros(500));
        let total = start.elapsed();

        let total_ms = total.as_secs_f64() * 1000.0;
        if total_ms > 30.0 {
            println!("[Frame {}] 异常:{:.2}ms (input={:?})", frame, total_ms, input_time);
        }

        if !events.is_empty() {
            println!("[Frame {}] 事件:{:?}", frame, events);
        }
    }
}
```

预期输出(注意没有 50ms 异常,因为输入异步):

```
[Frame 60] 事件:[InputEvent { button: 1, pressed: true }]
[Frame 120] 事件:[InputEvent { button: 1, pressed: true }]
...
```

如果没有异步包装,会看到:

```
[Frame 60] 异常:50.42ms (input=50.1ms)
[Frame 120] 异常:50.42ms (input=50.1ms)
```

## 10 · 深入:控制器卡顿与 gamma 修复

casey 在 day256 修复两个 bug:Xbox 控制器卡顿 + gamma 渲染错。

### 10.1 Xbox 控制器卡顿

Xbox 控制器输入处理:

```rust
fn poll_controller(state: &mut State) {
    let input = xinput_get_state(0);  // 同步 polling
    state.input = process(input);
}
```

如果 xinput_get_state 偶尔慢(USB polling 卡顿),FPS 抖动。casey 改成异步:

```rust
fn poll_controller_async(state: &mut State) {
    // 后台线程 poll controller,通过 channel 发送
    let input = controller_rx.try_recv().unwrap_or(state.input);
    state.input = input;
}

// 启动时
std::thread::spawn(|| {
    loop {
        let input = xinput_get_state(0);
        controller_tx.send(input).unwrap();
        std::thread::sleep(Duration::from_millis(1));
    }
});
```

后台线程 1ms poll,主线程非阻塞读。frame rate 稳定。

### 10.2 gamma 修复

casey 在 day241 启用 sRGB,但 GL_BIT_BLIT gamma 没处理。day256 修复:

```rust
// 错误:GL_BIT_BLIT 时,sRGB 自动转换被绕过
gl.blit_framebuffer(...);  // 数据原样复制,double gamma

// 修复:手动 gamma 校正
gl.enable(glow::FRAMEBUFFER_SRGB);  // 启用 sRGB conversion
gl.blit_framebuffer(...);
```

GL_BIT_BLIT 是 OpenGL 的快速 framebuffer 复制,默认不应用 sRGB 转换。casey 在 day256 修复。
