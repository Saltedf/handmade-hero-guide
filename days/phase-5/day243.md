# Day 243 · 异步纹理下载

> Day 210 你做了 debug data store,其中"截图"功能要把 framebuffer 从 GPU 拉回 CPU。最直接的 `glReadPixels` 是同步的——立刻 stall GPU 等数据,主循环卡 1-10ms。今天 Casey 引入 **PBO(Pixel Buffer Object)** + **glFenceSync**,做真正的异步回读。

## 0 · 为什么要有这一天

游戏需要 GPU → CPU 数据回读的场景:

- **截图** —— 按 F12 存 PNG,要拿 framebuffer 像素
- **debug overlay** —— 看 profiler 时小图显示某 texture 内容
- **CPU-side collision** —— GPU 渲染的 heightmap,CPU 要读做物理
- **video recording** —— 每帧回读存视频

直接用 `glReadPixels`:

```rust
let mut pixels = vec![0u8; w * h * 4];
unsafe {
    gl.read_pixels(0, 0, w, h, glow::RGBA, glow::UNSIGNED_BYTE, &mut pixels);
}
```

这个调用**阻塞 CPU**,直到 GPU 把所有 draw 跑完才能拿到 framebuffer。如果 GPU 还在算 5ms 帧的内容,这 5ms CPU 干等。每帧 16ms 预算,5ms 浪费在等 = 30% 性能损失。

**异步方案**:

1. 用 PBO(packet buffer object)—— 一块 GPU buffer,告诉 GPU"把 framebuffer 复制到 PBO"
2. 用 fence—— 一个标记,告诉 GPU"PBO 复制完成后通知我"
3. CPU 不等,继续下一帧
4. 下一帧开始时,检查上一帧的 fence。完成了就读 PBO(此时无 stall,数据已在 PCIe 上)

代价:**延迟 1 帧**(你看到的是上一帧的截图)。但 CPU 不阻塞,主循环流畅。

**为什么这件事重要**:GPU-CPU 同步是现代渲染器的核心难题。Vulkan / D3D12 整个 API 设计都是围绕"显式同步"——OpenGL 帮你自动同步,但你必须理解原理才能高效用。Day 243 是你第一次正经处理 GPU 同步。

**心理锚点**:看完今天,你能写 `AsyncReadback` 类,每帧 fetch 上一帧的截图(0 stall)。

## 1 · Casey 今天做了什么

Casey 加异步截图系统:

1. 创建 N 个 PBO(N = 帧延迟 + 1,通常 2-3)
2. 每帧:`glReadPixels` 到 PBO(不阻塞,只是 enqueue 命令)
3. 每个 PBO 关联一个 fence
4. 下一帧检查 fence,完成才 `glGetBufferSubData` 真读 PBO
5. 验证:截图延迟 1 帧,但 CPU 0 stall

**关键决策**:Casey 用**轮换 PBO**——N 个 PBO 循环用,每帧用最老的那个读(那时数据保证到 CPU 了)。这是经典的 "N-frame delay" pattern。

## 2 · 心智模型

### 类比:快递系统

GPU 是仓库,CPU 是客户。你要从仓库取货。

**同步** —— 你说"我要这货",仓库员停下手中活去找,找到给你。你等。

**异步** —— 你说"我要这货",仓库员**记下来**,继续干手头活。第二天来送货。你晚一天拿到,但**没等**。

PBO + fence 就是快递系统:

- PBO = 包裹(GPU 端 buffer)
- fence = 送货单(标记"包裹准备好了")
- 你今天寄(今天 read_pixels 到 PBO)
- 你今天查昨天的快递(读昨天 PBO,数据已到)

### 2.1 PBO 是什么

**Pixel Buffer Object(PBO)** —— 一种特殊的 GPU buffer,用于像素数据传输。

和 VBO 区别:

- **VBO** —— 存顶点数据,draw 时 GPU 读
- **PBO** —— 存像素数据,`glReadPixels` / `glTexImage2D` 时做"中转"

PBO 的关键特性:**它和 GPU 内部 framebuffer 之间的拷贝是 GPU 内部操作,不阻塞 CPU**。

```
传统同步:
    framebuffer ─────[DMA,阻塞 CPU]────→ CPU 内存

PBO 异步:
    framebuffer ─[GPU 内部]→ PBO ─[DMA,异步]→ CPU 内存
                              ↑
                         GPU 后台搬,不阻塞 CPU
```

### 2.2 PBO 工作流程

```rust
// 创建 N 个 PBO(双缓冲)
let pbos: Vec<Buffer> = (0..2).map(|_| {
    unsafe {
        let b = gl.create_buffer().unwrap();
        gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(b));
        // 分配 size,但不上传数据(NULL pointer)
        gl.buffer_data_size(
            glow::PIXEL_PACK_BUFFER,
            (w * h * 4) as usize,
            std::ptr::null(),
            glow::STREAM_READ,  // 提示:GPU 写,CPU 读
        );
        b
    }
}).collect();

// 每帧 read
let pbo_idx = frame % 2;
let pbo = pbos[pbo_idx];
unsafe {
    // 把 framebuffer 复制到 PBO(异步!不阻塞)
    gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(pbo));
    gl.read_pixels(
        0, 0, w, h, glow::RGBA, glow::UNSIGNED_BYTE,
        std::ptr::null_mut(),  // 关键:null,告诉 GL 写到当前绑定的 PBO
    );

    // 放 fence(标记这个 PBO 何时完成)
    let fence = gl.fence_sync(glow::SYNC_GPU_COMMANDS_COMPLETE, 0).unwrap();
    fences[pbo_idx] = Some(fence);
}

// 同时,检查上一帧的 PBO 是否完成
let prev_pbo_idx = (frame + 1) % 2;  // N=2 时,上一帧是另一个 PBO
if let Some(fence) = &fences[prev_pbo_idx] {
    let mut signaled = 0;
    unsafe {
        // 不阻塞检查 fence
        let status = gl.get_sync_status(*fence);
        if status == glow::SIGNALED {
            // 完成了!读 PBO(此时无 stall)
            let pbo = pbos[prev_pbo_idx];
            gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(pbo));
            let mut pixels = vec![0u8; (w * h * 4) as usize];
            gl.get_buffer_sub_data(
                glow::PIXEL_PACK_BUFFER, 0,
                bytemuck::cast_slice_mut(&mut pixels),
            );
            // 用 pixels(存盘 / debug)
            fences[prev_pbo_idx] = None;
            gl.delete_sync(*fence);
        }
    }
}
```

### 2.3 glFenceSync 详解

**Fence** —— 一个同步对象,表示"GPU 命令队列中某个点"。GPU 跑到这个点,fence 变 SIGNALED。

```rust
let fence = unsafe {
    gl.fence_sync(glow::SYNC_GPU_COMMANDS_COMPLETE, 0).unwrap()
};
// fence 现在插在 GPU 命令队列里,在它前面的命令(包括 read_pixels)完成后 signaled
```

查询 fence 状态(不阻塞):

```rust
unsafe {
    let mut result = 0;
    gl.get_sync_iv(
        fence,
        glow::SYNC_STATUS,
        std::slice::from_mut(&mut result),
    );
    if result == glow::SIGNALED as i32 {
        // 完成了
    } else if result == glow::UNSIGNALED as i32 {
        // 还没
    }
}
```

或者**阻塞等**(不要这样做):

```rust
unsafe {
    let _ = gl.client_wait_sync(
        fence,
        glow::SYNC_FLUSH_COMMANDS_BIT,
        1_000_000_000,  // 超时 1 秒(ns)
    );
}
```

`client_wait_sync` 阻塞 CPU,违背异步初衷。只在初始化等关键资源时用。

### 2.4 N-frame 延迟分析

```
Frame 0:
  - 发 read 命令到 PBO[0]
  - 放 fence[0]
  - 检查 fence[1](不存在,跳过)

Frame 1:
  - 发 read 命令到 PBO[1]
  - 放 fence[1]
  - 检查 fence[0]:完成?读 PBO[0] 拿 frame 0 数据

Frame 2:
  - 发 read 命令到 PBO[0](覆盖)
  - 放 fence[0]
  - 检查 fence[1]:完成?读 PBO[1] 拿 frame 1 数据
```

N=2 时,延迟 1 帧(60 FPS = 16.7ms)。N=3 延迟 2 帧,适合 GPU 特别慢的场景。

### 2.5 用 readback 干什么

**截图**:

```rust
fn screenshot(readback: &mut AsyncReadback, frame: u64) -> Option<Vec<u8>> {
    readback.poll(frame)
}

// 用户按 F12
if input.key_pressed(Key::F12) {
    if let Some(pixels) = screenshot(&mut readback, frame) {
        save_png("screenshot.png", &pixels, w, h);
    }
}
```

**Debug overlay**:

```rust
// profiler 显示某 texture 内容
let mini_preview = readback.poll_last();
draw_mini_quad(overlay_x, overlay_y, 100, 100, mini_preview);
```

**Video recording**:

```rust
let mut encoder = VideoEncoder::new("output.mp4", w, h);
loop {
    if let Some(frame) = readback.poll(frame) {
        encoder.push(&frame);
    }
}
```

### 2.6 常见陷阱

1. **PBO size 不匹配** —— framebuffer 800x600 RGBA = 1.92MB,PBO 要分配一样大,否则 read 越界
2. **fence 泄漏** —— fence 是 GPU 资源,用完要 `glDeleteSync`,否则 driver 内存涨
3. **修改 PBO 时还有 read 在跑** —— N=2 时,你写 PBO[0],可能 read 上一帧 PBO[0] 还没完成,数据破坏。要等 fence signaled 才能重用 PBO
4. **glPixelStorei 参数** —— `glPixelStorei(glow::PACK_ALIGNMENT, 1)` 设置 pack 对齐。默认 4 字节对齐,如果你的行字节不是 4 倍数(如 RGB 800 宽 = 2400 字节 = 4 倍数,但 RGBA 是 4 倍数本身),会读错

---

**总结**:PBO + fence 实现 GPU → CPU 异步数据传输。N 个 PBO 轮换,延迟 N-1 帧,CPU 0 stall。这是处理任何 GPU → CPU 数据回读的标准方案。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**截图 / 视频录制** 是游戏必备功能。Steam 用内置 screenshot manager,独立游戏用 sdl2_image / image crate 自己实现。

**readback 的代价**:

- 即使异步,PCIe 带宽有限(~32 GB/s)。1080p RGBA = 8MB,读完要 0.25ms
- 每帧 readback 会让 GPU driver 维护多个 PBO,fence 数量增加
- 实测:每帧 readback 一帧,性能损失约 1-3%

**优化策略**:

- **降采样** —— 不需要原分辨率,缩小一半(800x600 → 400x300)
- **只读子区域** —— profiler 只关心画面右上角的小预览
- **按需读** —— 不要每帧 read,只在需要时(用户按截图键)

**现代引擎**用 NVIDIA Reflex / AMD Anti-Lag 进一步优化,但本质都是 fence + 多 buffer 轮换。

### 3.2 · 🎨 图形学视角

**fence / semaphore 区别**:

- **Fence** —— CPU-GPU 同步(GPU 完成,通知 CPU)
- **Semaphore** —— GPU-GPU 同步(一个 queue 等另一个 queue 完成)

OpenGL 只有 fence,Vulkan 两者都有。多 queue(图形 + 计算 + 传输)Vulkan 必须 semaphore 协调。

**Persistent Mapped Buffers(PMB)** —— OpenGL 4.4+ 的优化,buffer 一直 mapped,CPU 直接读写 GPU 内存(零拷贝)。但需要 GPU 支持 residency(显存常驻),老 GPU 不行。

```rust
// OpenGL 4.4+
unsafe {
    gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(pbo));
    gl.buffer_storage(
        glow::PIXEL_PACK_BUFFER,
        size,
        std::ptr::null(),
        glow::MAP_READ_BIT | glow::MAP_PERSISTENT_BIT | glow::MAP_COHERENT_BIT,
    );
    let ptr = gl.map_buffer_range(
        glow::PIXEL_PACK_BUFFER,
        0, size,
        glow::MAP_READ_BIT | glow::MAP_PERSISTENT_BIT | glow::MAP_COHERENT_BIT,
    );
    // ptr 一直有效,可随时读
}
```

跟 HH 不用 PMB,简单 PBO + fence 够。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上 GPU 内存传输的底层:

```
CPU 程序 ─[mmap]→ /dev/dri/renderD128 ─[DMA]→ GPU 显存
```

**DMA(Direct Memory Access)** —— 硬件直接搬内存,不经过 CPU。GPU 通过 DMA 把数据从系统内存搬到显存。

**显式 fence** —— Linux DRM 提供 `drmSyncobjCreate` / `drmSyncobjWait`,直接和 Vulkan / OpenGL fence 对应。

```bash

# 或 NVIDIA
nvidia-smi --query-gpu=memory.used --format=csv
```


### 3.4 · 🦀 Rust 生态视角

**AsyncReadback 类设计**:

```rust
use glow::HasContext;
use std::collections::VecDeque;

pub struct AsyncReadback {
    gl: glow::Context,
    pbos: Vec<<glow::Context as glow::HasContext>::Buffer>,
    fences: Vec<Option<<glow::Context as glow::HasContext>::Fence>>,
    width: u32,
    height: u32,
    next_idx: usize,
}

impl AsyncReadback {
    pub fn new(gl: glow::Context, width: u32, height: u32, n_frames: usize) -> Self {
        let size = (width * height * 4) as usize;
        let pbos: Vec<_> = (0..n_frames).map(|_| unsafe {
            let b = gl.create_buffer().unwrap();
            gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(b));
            gl.buffer_data_size(
                glow::PIXEL_PACK_BUFFER, size,
                std::ptr::null(), glow::STREAM_READ,
            );
            b
        }).collect();

        let fences = (0..n_frames).map(|_| None).collect();

        Self {
            gl, pbos, fences, width, height, next_idx: 0,
        }
    }

    /// 帧末调用:enqueue 一帧 readback
    pub fn enqueue(&mut self) {
        let idx = self.next_idx;
        self.next_idx = (self.next_idx + 1) % self.pbos.len();

        unsafe {
            // 删旧 fence(如果还在)
            if let Some(f) = self.fences[idx].take() {
                self.gl.delete_sync(f);
            }

            // 触发 read 到 PBO
            self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(self.pbos[idx]));
            self.gl.read_pixels_into_cpu_buffer(
                0, 0, self.width as i32, self.height as i32,
                glow::RGBA, glow::UNSIGNED_BYTE,
            );

            // 放新 fence
            let fence = self.gl.fence_sync(glow::SYNC_GPU_COMMANDS_COMPLETE, 0).unwrap();
            self.fences[idx] = Some(fence);
        }
    }

    /// 下一帧开始时调用:检查最老的 PBO 是否完成,返回数据
    pub fn poll_oldest(&mut self) -> Option<Vec<u8>> {
        // 最老的是 next_idx(刚刚 enqueue 的是新的前一个)
        let oldest_idx = (self.next_idx + 1) % self.pbos.len();

        let fence = self.fences[oldest_idx]?;
        unsafe {
            let mut status = 0;
            self.gl.get_sync_iv(
                fence,
                glow::SYNC_STATUS,
                std::slice::from_mut(&mut status),
            );
            if status != glow::SIGNALED as i32 {
                return None;
            }

            // 完成了,读 PBO
            self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(self.pbos[oldest_idx]));
            let size = (self.width * self.height * 4) as usize;
            let mut pixels = vec![0u8; size];
            self.gl.get_buffer_sub_data(
                glow::PIXEL_PACK_BUFFER, 0,
                &mut pixels,
            );

            self.gl.delete_sync(fence);
            self.fences[oldest_idx] = None;

            Some(pixels)
        }
    }
}

impl Drop for AsyncReadback {
    fn drop(&mut self) {
        unsafe {
            for f in self.fences.iter().flatten() {
                self.gl.delete_sync(*f);
            }
            for b in &self.pbos {
                self.gl.delete_buffer(*b);
            }
        }
    }
}
```

**Rust 所有权陷阱**:

- `glow::Context` 不是 `Clone` —— AsyncReadback 不能 own context,要用引用 + lifetime。实际工程用 `Rc<RefCell<glow::Context>>` 或把 GL 调用推到外面
- `Fence` / `Buffer` 是 NonZeroU32 句柄,Drop 必须显式释放

## 5 · 对照与变奏

### 同步 vs 异步数据流

| | 同步(read_pixels 直接) | 异步(PBO + fence) |
|---|---|---|
| CPU 等待 | 1-10ms stall | 0 |
| 延迟 | 0(立刻有数据) | N 帧 |
| 代码复杂度 | 低 | 高 |
| 适用 | 调试、单次截图 | 实时录制、debug overlay |

**结论**:主循环必须异步。调试 / 单次可以同步。

### 历史演化

- **1990s**:OpenGL 只有 `glReadPixels`,无 PBO,只能同步
- **2005**:GL_ARB_pixel_buffer_object,PBO 引入
- **2010**:OpenGL 4.0+,fence sync 完备
- **2016**:OpenGL 4.4,PMB(persistent mapped buffer)
- **2016+**:Vulkan 把同步完全暴露给应用

Day 243 的 PBO + fence 是 OpenGL 3.3+ 的标配,够用。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 N=2 的 PBO 轮换就够?N=1 会发生什么?

**参考解答**:

- **N=1** —— 一个 PBO。你 enqueue 后,fence 还没 signaled,你立刻想读。但 read 命令刚发,GPU 还没执行,你读到的是**上一帧的数据**或垃圾数据。N=1 等于同步(必须等 fence,违背异步)。
- **N=2** —— 两个 PBO 交替。你 enqueue 当前帧到 PBO[A],同时读 PBO[B](上一帧 enqueue 的)。PBO[B] 的 fence 大概率已 signaled(经过一帧的 GPU 工作时间)。N=2 是最低 viable。
- **N=3** —— 更安全(GPU 抖动时仍能跟上),但延迟更长。一般 N=2 够用。

### Lv2 · 动手实践

**题**:在 Day 242 的程序里加 AsyncReadback。完成标准:每秒打一次 FPS,按 F12 保存上一帧 framebuffer 为 PPM 文件。

**参考解答**:

```rust
// 主循环
let mut readback = AsyncReadback::new(gl.clone(), 800, 600, 2);
let mut last_frame_pixels: Option<Vec<u8>> = None;

event_loop.run(move |event, target| {
    if let winit::event::Event::AboutToWait = event {
        // 渲染...

        // 帧末:enqueue readback
        readback.enqueue();

        // 检查上一帧
        if let Some(pixels) = readback.poll_oldest() {
            last_frame_pixels = Some(pixels);
        }

        // F12 截图
        if input.key_pressed(Key::F12) {
            if let Some(p) = &last_frame_pixels {
                save_ppm("screenshot.ppm", p, 800, 600);
                println!("Saved screenshot.ppm");
            }
        }

        window.swap_buffers().unwrap();
    }
});

fn save_ppm(path: &str, pixels: &[u8], w: u32, h: u32) {
    use std::io::Write;
    let mut f = std::fs::File::create(path).unwrap();
    writeln!(f, "P6").unwrap();
    writeln!(f, "{} {}", w, h).unwrap();
    writeln!(f, "255").unwrap();
    // RGBA → RGB
    for chunk in pixels.chunks_exact(4) {
        f.write_all(&chunk[..3]).unwrap();
    }
}
```

PPM 格式简单(无压缩的 RGB),ImageMagick 可以转 PNG:`convert screenshot.ppm screenshot.png`。

### Lv3 · 迁移设计

**题**:你的游戏需要**屏幕空间反射(SSR)** —— 反射用上一帧的 framebuffer 作为输入。GPU 端怎么访问上一帧?提示:texture_feedback + 立刻用,或 readback + 重新上传。

**提示**:
- GPU 端最直接:复制 framebuffer 到一个 texture 用作 SSR 输入。`glBlitFramebuffer` 或 `glCopyImageSubData`,全在 GPU 内存,不涉及 CPU
- readback + 上传:把上一帧 readback 到 CPU,然后 `glTexImage2D` 重新上传——这是 CPU 浪费,不推荐
- 现代 API:Vulkan `vkCmdBlitImage` 是 GPU 内拷贝,零 CPU 开销
- SSR 实际就是 GPU-only path,Day 243 的 readback 不相关

### Rust 完整 AsyncReadback 测试程序

```rust
use glow::HasContext;

pub struct AsyncReadback {
    gl: glow::Context,
    pbos: Vec<<glow::Context as glow::HasContext>::Buffer>,
    fences: Vec<Option<<glow::Context as glow::HasContext>::Fence>>,
    width: i32,
    height: i32,
    next_idx: usize,
}

impl AsyncReadback {
    pub fn new(gl: glow::Context, width: i32, height: i32, n: usize) -> Self {
        let size = (width * height * 4) as usize;
        let pbos: Vec<_> = (0..n).map(|_| unsafe {
            let b = gl.create_buffer().unwrap();
            gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(b));
            gl.buffer_data_size(
                glow::PIXEL_PACK_BUFFER, size,
                std::ptr::null(), glow::STREAM_READ,
            );
            b
        }).collect();

        Self {
            gl,
            pbos,
            fences: (0..n).map(|_| None).collect(),
            width, height, next_idx: 0,
        }
    }

    pub fn enqueue(&mut self) {
        let idx = self.next_idx;
        self.next_idx = (self.next_idx + 1) % self.pbos.len();

        unsafe {
            if let Some(f) = self.fences[idx].take() {
                self.gl.delete_sync(f);
            }

            self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(self.pbos[idx]));
            self.gl.read_pixels_into_cpu_buffer(
                0, 0, self.width, self.height,
                glow::RGBA, glow::UNSIGNED_BYTE,
            );

            let fence = self.gl.fence_sync(glow::SYNC_GPU_COMMANDS_COMPLETE, 0).unwrap();
            self.fences[idx] = Some(fence);
        }
    }

    pub fn poll_oldest(&mut self) -> Option<Vec<u8>> {
        let oldest = (self.next_idx + 1) % self.pbos.len();
        let fence = self.fences[oldest]?;

        unsafe {
            let mut status = 0;
            self.gl.get_sync_iv(
                fence,
                glow::SYNC_STATUS,
                std::slice::from_mut(&mut status),
            );
            if status != glow::SIGNALED as i32 {
                return None;
            }

            self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(self.pbos[oldest]));
            let size = (self.width * self.height * 4) as usize;
            let mut pixels = vec![0u8; size];
            self.gl.get_buffer_sub_data(
                glow::PIXEL_PACK_BUFFER, 0, &mut pixels,
            );

            self.gl.delete_sync(fence);
            self.fences[oldest] = None;
            Some(pixels)
        }
    }
}

impl Drop for AsyncReadback {
    fn drop(&mut self) {
        unsafe {
            for f in self.fences.iter().flatten() {
                self.gl.delete_sync(*f);
            }
            for b in &self.pbos {
                self.gl.delete_buffer(*b);
            }
        }
    }
}
```

### 10.1 PBO 下载的应用场景

2. **GPU 计算结果回读**:compute shader 结果回 CPU
3. **视频录制**:实时录游戏画面

5. **机器学习推理**:GPU 推理结果回 CPU 处理

### 10.2 同步下载 vs 异步下载

```rust
// 同步:CPU 等 GPU 完成
gl.read_pixels(0, 0, w, h, RGBA, UNSIGNED_BYTE, &mut buffer);
// 阻塞 ~5ms(GPU flush pipeline)

// 异步:PBO
let pbo = gl.create_buffer();
gl.bind_buffer(PIXEL_PACK_BUFFER, pbo);
gl.read_pixels(...);  // 写到 PBO,不阻塞
// 下一帧用 fence sync 等
```

异步让 CPU / GPU 并行。

### 10.3 fence sync 的工作

```rust
let fence = gl.fence_sync(SYNC_GPU_COMMANDS_COMPLETE, 0);
// GPU 完成 read_pixels 后,fence signaled

let status = gl.client_wait_sync(fence, 0, 0);
match status {
    ALREADY_SIGNALED | CONDITION_SATISFIED => {
        // 完成,可以读 PBO
    }
    TIMEOUT_EXPIRED => { /* 还没完成 */ }
}
```

casey HH day243 用类似逻辑。

### 10.4 ping-pong PBO

完全隐藏下载延迟,用两个 PBO:

```
Frame N:GPU 写 PBO_A
Frame N+1:CPU 读 PBO_A(GPU 已经完成)
         GPU 写 PBO_B
Frame N+2:CPU 读 PBO_B(GPU 已经完成)
         GPU 写 PBO_A(重用)
```

每帧交替,延迟 1 帧但无等待。
