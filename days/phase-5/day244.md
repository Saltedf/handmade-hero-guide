# Day 244 · 完成异步纹理下载

> Day 243 你搭好 AsyncReadback 骨架,但有几个 corner case 没处理:窗口大小变化、连续多次 poll、fence 等不到时的 fallback。今天 Casey 把这些坑填上,代码生产可用。

## 0 · 为什么要有这一天

Day 243 的代码在"理想情况"下工作:固定窗口大小、稳定 60 FPS、fence 总在下一帧前 signaled。但实际游戏:

- **用户拖窗口大小** —— 你的 PBO 是按旧尺寸分配的,新尺寸 read 越界
- **GPU 偶尔卡顿** —— 某帧 GPU 跑了 50ms,fence 在 N 帧后才 signaled,你 stale 了
- **多次 poll** —— 一帧 poll 多次,只有第一次返回数据,后续 None
- **Drop 时 fence 还在 pending** —— 删 fence 前要等或丢弃

每个 corner case 都可能让游戏崩溃或泄漏资源。今天 Casey 系统性处理:

1. 窗口 resize 时重建 PBO
2. fence 超时丢弃(readback 失败,但游戏不崩)
3. Drop 安全清理(等所有 fence 或强删)
4. 调整 N(默认 3,稳一点)

**心理锚点**:看完今天,你能写一个**生产可用**的 AsyncReadback,边界情况都处理。

## 1 · Casey 今天做了什么

Casey 把 Day 243 的代码加固:

1. 加 resize 支持:窗口大小变了,删旧 PBO,用新尺寸创建
2. 加 fence 超时:`client_wait_sync` 最多等 0 时间(纯 poll),超时跳过

4. Drop 实现:`delete_sync` 所有未完成 fence

## 2 · 心智模型

### 类比:快递系统的异常处理

Day 243 的"理想快递"假设每天有货到。现实:

- **客户搬家**(窗口 resize)—— 旧地址用不了,记新地址
- **快递延迟**(fence 超时)—— 不死等,放弃这单
- **重复查询**(多次 poll)—— 第二次查询应该返回"已读过",不是再读一次
- **公司倒闭**(Drop)—— 处理所有未完成订单(删 fence)

工程化的关键:**异常情况优雅退化**,而不是崩溃。

### 2.1 窗口 resize 处理

```rust
pub fn resize(&mut self, new_width: i32, new_height: i32) {
    if new_width == self.width && new_height == self.height {
        return;  // 没变化
    }

    // 删所有旧资源
    unsafe {
        for f in self.fences.iter_mut().flatten() {
            self.gl.delete_sync(*f);
        }
        for b in &self.pbos {
            self.gl.delete_buffer(*b);
        }
    }

    // 重建
    self.width = new_width;
    self.height = new_height;
    self.pbos = (0..self.pbos.len()).map(|_| unsafe {
        let b = self.gl.create_buffer().unwrap();
        self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(b));
        self.gl.buffer_data_size(
            glow::PIXEL_PACK_BUFFER,
            (new_width * new_height * 4) as usize,
            std::ptr::null(),
            glow::STREAM_READ,
        );
        b
    }).collect();
    self.fences = (0..self.pbos.len()).map(|_| None).collect();
    self.next_idx = 0;
}
```

**关键**:resize 是"全清重建",最简单也最稳。增量调整(只改大小不同的 PBO)复杂且易错,生产代码也用全清。

### 2.2 fence 超时 / 丢弃

```rust
pub fn poll_oldest(&mut self) -> Option<Vec<u8>> {
    let oldest = (self.next_idx + 1) % self.pbos.len();
    let fence = match self.fences[oldest] {
        Some(f) => f,
        None => return None,  // 这个槽没在用
    };

    unsafe {
        // 纯 poll,不阻塞
        let mut status = 0;
        self.gl.get_sync_iv(
            fence,
            glow::SYNC_STATUS,
            std::slice::from_mut(&mut status),
        );

        if status != glow::SIGNALED as i32 {
            // 还没好,跳过(下一帧再 poll)
            return None;
        }

        // 完成了,读
        self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(self.pbos[oldest]));
        let size = (self.width * self.height * 4) as usize;
        let mut pixels = vec![0u8; size];
        self.gl.get_buffer_sub_data(
            glow::PIXEL_PACK_BUFFER, 0, &mut pixels,
        );

        self.gl.delete_sync(fence);
        self.fences[oldest] = None;
        Some(pixels)
    }
}
```

**关键**:`get_sync_iv` 是**纯查询**(不阻塞),和 `client_wait_sync`(阻塞)不同。

### 2.3 连续 poll

Day 243 的 `poll_oldest` 在第一次返回 Some 后,标记 fences[oldest] = None,后续 poll 自然返回 None(因为 fence 已经删了)。所以**不会重复读**。这是 Day 243 的实现已经正确。

但有个隐藏 bug:你 enqueue 帧 A 到 PBO[0],fence[0] 标记。然后**没**调 poll_oldest,直接 enqueue 帧 B 到 PBO[1]。

- N=2,PBO[0] 和 PBO[1] 交替
- 帧 A 的 fence[0] 还在
- 帧 B enqueue 时检查 PBO[1],fence[1] 是 None(没 enqueue 过),OK
- 但帧 C 来了,要 enqueue 到 PBO[0],但 fence[0] 还 signaled 没 delete

**修复**:enqueue 时如果 fence[old] 还在,先删(丢弃未读数据):

```rust
pub fn enqueue(&mut self) {
    let idx = self.next_idx;
    self.next_idx = (self.next_idx + 1) % self.pbos.len();

    unsafe {
        // 如果上一轮 fence 还在(说明没被 poll),删掉
        if let Some(f) = self.fences[idx].take() {
            self.gl.delete_sync(f);
        }
        // ... enqueue read ...
    }
}
```

这样 N=2 的语义清晰:PBO[0] 和 PBO[1] 交替,每帧要么被 poll(返回数据),要么被下一轮 enqueue 覆盖。

### 2.4 Drop 时清理

```rust
impl Drop for AsyncReadback {
    fn drop(&mut self) {
        unsafe {
            for f in self.fences.iter().flatten() {
                self.gl.delete_sync(*f);
            }
            for b in &self.pbos {
                self.gl.delete_buffer(*b);
            }
        }
    }
}
```

`delete_sync` 不需要等 fence 完成,直接丢弃。GPU 命令队列里相关命令会被取消或继续跑(取决于 driver),但 CPU 端不会泄漏资源。

### 2.5 状态机视图

AsyncReadback 每个槽有 3 个状态:

```
[Empty] ──enqueue──> [Pending] ──poll/signaled──> [Ready]
   ↑                                                    │
   └──────────────────poll/consumed────────────────────┘
```

- **Empty** —— fence = None,可以 enqueue
- **Pending** —— fence = Some,等待 signaled
- **Ready** —— fence signaled 但还没读(标记 Ready 用单独的标志,或者就让 fence 留着,poll 时 read)

实际实现简化:fence = None 是 Empty,fence = Some 是 Pending 或 Ready(poll 时检查 status 区分)。

### 2.6 N 的选择

- **N=2** —— 最低 viable,延迟 1 帧。GPU 稳定时够用
- **N=3** —— 推荐,延迟 2 帧。GPU 抖动有缓冲
- **N=4+** —— 过度,延迟更大没明显好处

Casey Day 244 选 N=3,稳。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**资源生命周期**是游戏引擎核心问题。Day 244 的 N-buffer rotation 是通用模式:

- **frame data**(profiler ring buffer)—— 帧数据 N 帧保留
- **command buffer**(Vulkan / D3D12)—— N 个 command buffer 轮换
- **descriptors** —— N 套 descriptor set
- **constant buffers** —— N 个 uniform buffer

N-buffer rotation 的核心:**写和读不冲突**,延迟 N-1 帧换无 stall。

**调试 tip**:开发时把 N 设大(N=5),日志能看到更长的历史。发布时 N=2 减延迟。

### 3.2 · 🎨 图形学视角

**double buffering / triple buffering** 是图形学通用术语:

- **双缓冲(double buffer)** —— front buffer 显示 + back buffer 渲染,VSync 时交换。Day 244 的 swap_buffers 就是
- **三缓冲(triple buffer)** —— 加一个"中间 buffer",GPU 可以提前算下一帧。Vulkan / D3D12 显式 triple buffer
- **N-buffer** —— 推广到任意 N,readback / command buffer 用

OpenGL 默认双缓冲,Vulkan 通常三缓冲。三缓冲延迟稍高但 FPS 更稳。

### 3.3 · 🐧 Linux 系统编程视角

Linux 内核 DRM 子系统也是 N-buffer:

```bash
# 看 DRM framebuffer 数
sudo cat /sys/kernel/debug/dri/0/state 2>/dev/null | grep -E "fb|plane"
```

每个 plane(显示层)有多个 framebuffer 关联,compositor 切换它们。

**fence 在内核里**对应 `drm_syncobj`,Vulkan / GL 的 fence 通过 ioctl 映射到内核 syncobj。

### 3.4 · 🦀 Rust 生态视角

**Rust Drop trait 的 GL 资源清理**:

```rust
impl Drop for GlTexture {
    fn drop(&mut self) {
        unsafe {
            self.gl.delete_texture(self.id);
        }
    }
}
```

这是 Rust idiom:RAII 包装 GL 资源。问题是:

- `gl` 字段需要引用,生命周期复杂
- 多个资源同时 Drop,顺序敏感(如 framebuffer 先删,attached texture 后删)

工程方案:**arena allocator**——所有 GL 资源放进一个 `GpuArena`,Drop arena 时统一清理。Bevy 引擎就用这种模式。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 enqueue 时要检查"上一轮 fence 还在就删"?如果不删会发生什么?

**参考解答**:N=2 时,PBO 轮换用。每帧 enqueue 到 PBO[idx],idx 在 0 和 1 间交替。

如果不检查:fence[idx] 还 signaled 没 delete,你直接 enqueue 新 read,driver 可能:

1. 等旧 fence 完成(同步,违背异步)
2. 覆盖旧 PBO 数据(丢上一帧的 readback)
3. 报错(GL_INVALID_OPERATION)

正确做法是 enqueue 前 delete fence(明确丢弃未读数据),然后 enqueue 新 read。语义清晰:PBO 是轮换的,过 N-1 帧必读,不读就丢。

## 8 · Rust / Arch 落地代码

### Rust 完整生产级 AsyncReadback

```rust
use glow::HasContext;

pub struct AsyncReadback {
    gl: glow::Context,
    pbos: Vec<<glow::Context as glow::HasContext>::Buffer>,
    fences: Vec<Option<<glow::Context as glow::HasContext>::Fence>>,
    width: i32,
    height: i32,
    next_idx: usize,
}

impl AsyncReadback {
    pub fn new(gl: glow::Context, width: i32, height: i32, n: usize) -> Self {
        assert!(n >= 2, "N 必须 ≥ 2");
        let size = (width * height * 4) as usize;
        let pbos: Vec<_> = (0..n).map(|_| unsafe {
            let b = gl.create_buffer().expect("create_buffer");
            gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(b));
            gl.buffer_data_size(
                glow::PIXEL_PACK_BUFFER, size,
                std::ptr::null(), glow::STREAM_READ,
            );
            b
        }).collect();

        Self {
            gl, pbos,
            fences: (0..n).map(|_| None).collect(),
            width, height, next_idx: 0,
        }
    }

    pub fn resize(&mut self, w: i32, h: i32) {
        if w == self.width && h == self.height { return; }
        unsafe {
            for f in self.fences.iter().flatten() { self.gl.delete_sync(*f); }
            for b in &self.pbos { self.gl.delete_buffer(*b); }
        }
        self.width = w;
        self.height = h;
        let n = self.pbos.len();
        self.pbos = (0..n).map(|_| unsafe {
            let b = self.gl.create_buffer().unwrap();
            self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(b));
            self.gl.buffer_data_size(
                glow::PIXEL_PACK_BUFFER,
                (w * h * 4) as usize,
                std::ptr::null(), glow::STREAM_READ,
            );
            b
        }).collect();
        self.fences = (0..n).map(|_| None).collect();
        self.next_idx = 0;
    }

    pub fn enqueue(&mut self) {
        let idx = self.next_idx;
        self.next_idx = (self.next_idx + 1) % self.pbos.len();

        unsafe {
            // 上一轮 fence 还在就丢弃
            if let Some(f) = self.fences[idx].take() {
                self.gl.delete_sync(f);
            }

            self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(self.pbos[idx]));
            self.gl.read_pixels_into_cpu_buffer(
                0, 0, self.width, self.height,
                glow::RGBA, glow::UNSIGNED_BYTE,
            );

            let fence = self.gl.fence_sync(glow::SYNC_GPU_COMMANDS_COMPLETE, 0)
                .expect("fence_sync");
            self.fences[idx] = Some(fence);
        }
    }

    pub fn poll_oldest(&mut self) -> Option<Vec<u8>> {
        let oldest = (self.next_idx + 1) % self.pbos.len();
        let fence = self.fences[oldest]?;

        unsafe {
            let mut status = 0;
            self.gl.get_sync_iv(
                fence, glow::SYNC_STATUS,
                std::slice::from_mut(&mut status),
            );
            if status != glow::SIGNALED as i32 { return None; }

            self.gl.bind_buffer(glow::PIXEL_PACK_BUFFER, Some(self.pbos[oldest]));
            let size = (self.width * self.height * 4) as usize;
            let mut pixels = vec![0u8; size];
            self.gl.get_buffer_sub_data(glow::PIXEL_PACK_BUFFER, 0, &mut pixels);

            self.gl.delete_sync(fence);
            self.fences[oldest] = None;
            Some(pixels)
        }
    }
}

impl Drop for AsyncReadback {
    fn drop(&mut self) {
        unsafe {
            for f in self.fences.iter().flatten() { self.gl.delete_sync(*f); }
            for b in &self.pbos { self.gl.delete_buffer(*b); }
        }
    }
}
```

## 10 · 深入:异步纹理下载的工业级实现

casey 在 day243-244 实现 PBO 异步纹理下载——这是 GPU 资源管理的核心技术。让我把它讲透。

### 10.1 PBO (Pixel Buffer Object) 的概念

PBO 是 OpenGL 的"像素缓冲对象"。用于异步传输纹理数据。

```
传统纹理上传:
  CPU 准备数据 → glTexImage2D → GPU 直接接收
  特点:同步,GPU 等 CPU

PBO 纹理上传:
  CPU 写数据到 PBO → 异步传输到 GPU → GPU 用 PBO 更新纹理
  特点:异步,GPU 不等 CPU
```

PBO 让 CPU 和 GPU 并行工作,提升性能。

### 10.2 PBO 的工作流程

```rust
// 1. 创建 PBO
let pbo = gl.create_buffer().unwrap();
gl.bind_buffer(glow::PIXEL_UNPACK_BUFFER, Some(pbo));
gl.buffer_data_u8_slice(glow::PIXEL_UNPACK_BUFFER, &data, glow::STREAM_DRAW);

// 2. 用 PBO 更新纹理(异步)
gl.bind_texture(glow::TEXTURE_2D, Some(texture));
gl.tex_sub_image_2d(
    glow::TEXTURE_2D, 0, 0, 0, w, h,
    glow::RGBA, glow::UNSIGNED_BYTE,
    glow::PixelUnpackData::BufferOffset(0),  // 从 PBO offset 0
);

// 3. 立即返回,GPU 在后台传输
```

CPU 不阻塞,可以继续做其他事。

### 10.3 fence 同步

PBO 是异步的,怎么知道传输完成?

```rust
// 提交 PBO 后,创建 fence
let fence = gl.fence_sync(glow::SYNC_GPU_COMMANDS_COMPLETE, 0);

// 后续帧检查 fence
let status = gl.client_wait_sync(fence, 0, 0);  // non-blocking
match status {
    glow::ALREADY_SIGNALED | glow::CONDITION_SATISFIED => {
        // 完成,可以重用 PBO
    }
    glow::TIMEOUT_EXPIRED => {
        // 还没完成
    }
    _ => panic!("fence error"),
}
```

fence 让 CPU 知道 GPU 进度,避免覆盖未读完的 PBO。

### 10.4 ping-pong PBO 策略

为了完全隐藏延迟,用两个 PBO 交替:

```rust
struct PboStreamer {
    pbos: [u32; 2],
    fences: [Option<glow::Fence>; 2],
    current: usize,
}

impl PboStreamer {
    fn upload(&mut self, data: &[u8]) -> usize {
        let pbo = self.pbos[self.current];
        
        // 等当前 PBO 的 fence(应该上一帧已经完成)
        if let Some(f) = self.fences[self.current].take() {
            gl.client_wait_sync(f, 0, glow::TIMEOUT_IGNORED);
            gl.delete_sync(f);
        }
        
        // 写新数据
        gl.bind_buffer(glow::PIXEL_UNPACK_BUFFER, Some(pbo));
        gl.buffer_data_u8_slice(glow::PIXEL_UNPACK_BUFFER, data, glow::STREAM_DRAW);
        
        // 提交到 GPU
        // ...
        
        // 创建新 fence
        self.fences[self.current] = Some(gl.fence_sync(...));
        
        // 切到下一个 PBO
        self.current = 1 - self.current;
        pbo
    }
}
```

每帧用不同 PBO,让 GPU 工作时 CPU 准备下一帧。完美并行。

### 10.6 PBO 的应用场景

PBO 不仅用于纹理上传,还用于:

1. **纹理下载**(GPU → CPU):截图、compute shader 结果回读
2. **视频帧上传**:实时视频流(网络会议、直播)
3. **大纹理 streaming**:开放世界的 asset 流式加载
4. **GPGPU 结果回读**:compute shader 计算结果回 CPU

casey HH 用 PBO 主要是纹理上传(day243-244)。

### 10.7 GPU driver 内部

PBO 的 driver 内部行为:

- **DMA 传输**:GPU 用 DMA 引擎,异步从 RAM 到 VRAM
- **PCIe bandwidth**:8-16 GB/s(NVMe 4.0)
- **GPU pipeline**:传输时 GPU 可以继续渲染

理解这些细节帮你优化 PBO 使用。

### 10.8 现代替代:D3D12 / Vulkan 的 resource heap

D3D12 / Vulkan 没有 PBO,用 **resource heap** + **upload heap**:

```
1. CPU 写数据到 upload heap(系统 RAM,GPU 可见)
2. GPU 复制 upload heap → default heap(VRAM)
3. 用 default heap 渲染
```

概念类似 PBO,但更灵活(支持任意资源类型)。casey 不深入 D3D12/Vulkan,HH 用 OpenGL 就够。

### 10.10 完整 Rust 实现

完整的 ping-pong PBO 实现:

```rust
use glow::Context;

pub struct AsyncTextureUploader {
    pbos: [glow::Buffer, 2],
    fences: [Option<glow::Fence>, 2],
    current: usize,
}

impl AsyncTextureUploader {
    pub unsafe fn new(gl: &Context) -> Self {
        let pbo0 = gl.create_buffer().unwrap();
        let pbo1 = gl.create_buffer().unwrap();
        Self {
            pbos: [pbo0, pbo1],
            fences: [None, None],
            current: 0,
        }
    }
    
    pub unsafe fn upload(
        &mut self, gl: &Context, texture: glow::Texture,
        data: &[u8], width: i32, height: i32,
    ) {
        let pbo = self.pbos[self.current];
        
        // Wait for previous fence
        if let Some(fence) = self.fences[self.current].take() {
            gl.client_wait_sync(fence, 0, glow::TIMEOUT_IGNORED);
            gl.delete_sync(fence);
        }
        
        // Upload data to PBO
        gl.bind_buffer(glow::PIXEL_UNPACK_BUFFER, Some(pbo));
        gl.buffer_data_u8_slice(
            glow::PIXEL_UNPACK_BUFFER,
            data,
            glow::STREAM_DRAW,
        );
        
        // Update texture from PBO
        gl.bind_texture(glow::TEXTURE_2D, Some(texture));
        gl.tex_sub_image_2d(
            glow::TEXTURE_2D, 0, 0, 0, width, height,
            glow::RGBA, glow::UNSIGNED_BYTE,
            glow::PixelUnpackData::BufferOffset(0),
        );
        gl.bind_buffer(glow::PIXEL_UNPACK_BUFFER, None);
        
        // Create new fence
        self.fences[self.current] = Some(gl.fence_sync(
            glow::SYNC_GPU_COMMANDS_COMPLETE, 0,
        ));
        
        // Switch
        self.current = 1 - self.current;
    }
    
    pub unsafe fn delete(self, gl: &Context) {
        for pbo in self.pbos {
            gl.delete_buffer(pbo);
        }
        for fence in self.fences.into_iter().flatten() {
            gl.delete_sync(fence);
        }
    }
}
```

完整可用的异步纹理上传。casey HH Rust 翻译版的 texture streaming 基础。
