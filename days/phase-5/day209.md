# Day 209 · 显示缓冲的调试数据

> Day 208 加了 data block。今天 Casey 在 UI 上显示这些数据——不是简单 print,而是结构化的图表 / 列表 / watch 窗口。

## 0 · 为什么要有这一天

让我们把镜头拉到一个具体的开发场景。

Day 208 你加了 data block——event 不只记时间,还记任意数据。你在游戏代码里散布了 `debug_data("player_pos", pos)`、`debug_data("enemy_count", enemies.len())`、`debug_data("ai_state", state)`。每帧产生几百条 data block,存在 ring buffer 里。

但你打开 profiler UI,看到的是什么?**一行行 raw 数据**——`cycle=120 player_pos=Vec2(150.0, 200.0)`、`cycle=121 player_pos=Vec2(155.0, 200.0)`、`cycle=122 ...`。

每帧滚屏,眼花缭乱。你盯了 30 秒,眼睛花了,**根本看不出"玩家速度变快了"或"敌人数稳定在 5"**。raw data 是对的,但**人脑不能从一串数字瞬间看出趋势**。

这是 data block 的 UI 局限——存了数据,但没"可视化"。你需要的不是 raw log,而是:

- **Watch window**:像 IDE debugger,持续显示"我关心的几个变量"的最新值
- **Plot over time**:某 float 变量随时间的曲线图——一眼看出趋势
- **Bar chart**:某 range-bound 变量的当前值占 range 的比例——一眼看出"接近 max 了"
- **Filter**:只看某 channel 的 data(只看 player 相关,只看 network 相关)
- **Last value table**:所有变量的最新值表格——一眼扫遍游戏状态

这是 profiler UI 的"数据可视化"部分。Day 180 画过 cycle 曲线图(simple line plot),今天把它扩展到任意 DebugValue。

**为什么这件事不平凡?**

技术上,可视化看起来简单——画几条线就完了。但工程上要考虑:

**第一,数据生命周期**。watch entry 的"history"不能无限长——每秒 60 帧 × 100 变量 = 6000 数据点/秒,几分钟就几百万。ring buffer 限制(最近 300 帧),超出覆盖。

**第二,UI dispatch**。不同 DebugValue variant 要不同 widget——Float 用 plot,Vec2 用 (x,y) 双线 + circle,String 用文本,Array 用列表。每帧 UI 看 type_guid,dispatch 到对应 renderer。这是 introspection-driven UI(Day 207)的另一个应用。

**第三,实时更新**。watch window 每帧重画——这是 immediate-mode UI 的优势。但要保证 UI 不卡(每帧画 300 点折线 ~12μs,可接受;画 30000 点要 batch render)。

**第四,数据流**。游戏代码 push data → ring buffer → collate 到 FrameSummary → WatchWindow.update → UI render。每个环节的 API 和数据结构要清晰。

**第五,交互**。用户怎么"添加 watch"?右键菜单 / 拖拽 / 手动输入变量名。watch 怎么持久化(下次启动保留)?这些都是 UX 设计。

今天 Casey 实现完整的 watch window 系统。Day 210 把 data block + watch 整合成统一存储。

**学完今天,你应该能**:
- 设计 watch window,持续显示任意变量
- 实现 plot over time(某 float 变量的历史曲线)
- dispatch 不同 DebugValue variant 到不同 widget 类型
- 用 ring buffer 限制 history 大小
- 看懂 Visual Studio Watch window / Unreal Visual Logger 在结构上和 Casey 的方案一致
- 知道 Grafana / Prometheus 是这套模式的"web 团队版"

## 1 · Casey 今天做了什么

Casey 这一天设计 watch window UI:

1. **抽象 WatchWindow 状态**。维护 `Vec<WatchEntry>`,每个 entry 是一个被 watch 的变量。Entry 持有 name、display mode(Last / Plot / Bar)、history(ring buffer)。

2. **每帧 update**。从 FrameSummary.data_blocks 找匹配 name 的最新 data block,push 到对应 entry 的 history。

3. **渲染 dispatch**。每帧 draw_watch——遍历 watched entries,根据 display_kind 选 widget——LastValue 显示一个数字,Plot 画折线图,Bar 画进度条。

4. **添加 / 删除 watch**。inspector 里右键变量,菜单 "Add to watch" → 创建 WatchEntry 加到 WatchWindow。

5. **持久化(简化)**。watch list 写到 config 文件,下次启动加载。

6. **plot 实现**。300 点折线——遍历 history,逐对相邻点画线。类似 Day 180 的曲线图,但数据源是 watch entry 而非 frame cycle 数。

7. **反思边界**。Casey 提到 watch 太多会卡——每帧画 100 个 watch × 300 点折线 = 30000 draw_line,~12 ms,占 frame budget 大头。优化:batch render(一次 vertex buffer submit)或减少 watch 数。

这集产出可视化层,Day 210 把 data block + watch + introspection 整合成统一存储。

## 2 · 心智模型

### 2.1 费曼类比:股票交易终端

想象一个股票交易终端。屏幕上有几个区域:

- **实时报价区**:你关心的几只股票的最新价——"AAPL 178.32, MSFT 380.15, GOOG 142.50"。这是 watch window。
- **K 线图区**:AAPL 的过去 30 天走势,阴阳线 + 成交量柱状图。这是 plot over time。
- **自选股列表**:你定制的股票清单,只有你关心的股票。这是 user-curated list。
- **Filter**:输入"科技股",列表只显示科技股。这是 filter。
- **Alert**:AAPL 跌破 170 时闪烁。这是 threshold alert。

股票交易员每天盯这种终端——**实时数据 + 历史可视化 + 用户筛选**。这是金融工业 100 年的标准 dashboard。

游戏 watch window 完全一样:
- 实时报价区 = watch entry 的 LastValue 显示
- K 线图 = plot over time(history 折线)
- 自选股 = watched 变量列表
- Filter = channel filter(只看 player 相关)
- Alert = threshold watch(HP < 10 时闪烁,后面 Day 211+ 加)

这个类比的关键洞察:**实时数据可视化是工业级 dashboard 的核心**。股票终端、游戏 profiler、运维 dashboard(Grafana)、监控工具(htop)——都是同一抽象:**用户选关心的数据 + 系统实时显示 + 历史趋势可视化**。

### 2.2 从零推导:watch window 的设计

**Step 0:raw 数据流**。游戏每帧 push data block,UI 显示一行行 raw 数据。

```
cycle=120 player_pos=Vec2(150.0, 200.0)
cycle=121 player_pos=Vec2(155.0, 200.0)
cycle=122 player_pos=Vec2(160.0, 200.0)
```

人眼看不出趋势。需要"挑关心的 + 画图"。

**Step 1:last value 表**。把每个变量的最新值列表显示。

```
player_pos = (160.0, 200.0)
enemy_count = 5
ai_state = Chase
```

像 IDE debugger 的 Locals 窗口。但只有当前值,没历史。

**Step 2:加 history**。每个 watch 存最近 N 帧的值。UI 显示当前值 + sparkline(迷你图)。

```
player_pos = (160.0, 200.0)   ╱─
enemy_count = 5              ────
ai_state = Chase             ────
```

sparkline 让你"扫一眼就知道趋势"——曲线向上 = 数值在增长。

**Step 3:dispatch 不同类型**。Float 用 sparkline,Vec2 用双线(x 和 y 各一条),String 用文本,Enum 用 timeline(每个 state 不同颜色)。

```rust
fn draw_watch(entry: &WatchEntry) {
    match entry.value_type {
        Type::Float => draw_sparkline(&entry.history),
        Type::Vec2 => draw_xy_plot(&entry.history),  // x 和 y 双线
        Type::String => draw_text(&entry.last_value),
        Type::Enum => draw_state_timeline(&entry.history),
    }
}
```

introspection-driven UI——type_guid 自动决定 widget。

**Step 4:filter**。1000 个 data block,用户只看 10 个 watch。filter by name。

```rust
for entry in &watch.watched {
    let history: Vec<_> = frame.data_blocks.iter()
        .filter(|(_, n, _)| *n == entry.name)
        .map(|(_, _, v)| v.clone())
        .collect();
    draw_watch(entry, &history);
}
```

每帧 filter,~50μs(N=1000 data blocks × W=10 watch)。

**Step 5:ring buffer 限制 history**。

```rust
struct WatchEntry {
    name: &'static str,
    history: RingBuffer<f32, 300>,  // 最近 300 帧 = 5 秒 @ 60fps
}
```

300 帧 = 5 秒。够看清短期趋势。如果要更长时间,换 sparse sampling(每 10 帧记一次)。

**Step 6:plot 实现**。300 点折线。

```rust
fn draw_plot(history: &RingBuffer<f32, 300>) {
    let max = history.iter().copied().fold(0.0f32, f32::max).max(1e-6);
    let mut prev: Option<(f32, f32)> = None;
    for (i, v) in history.iter().enumerate() {
        let x = i as f32 * 2.0;  // 2 pixels per sample
        let y = 50.0 - (*v / max) * 50.0;  // 50px tall plot
        if let Some((px, py)) = prev {
            draw_line(px, py, x, y, COLOR_YELLOW);
        }
        prev = Some((x, y));
    }
}
```

300 个 draw_line × 100 cycle = 30000 cycle = ~12μs。每帧画 10 个 watch = 120μs。可接受。

```
| Entity | x     | y     | HP  | State     |
```

### 2.4 时间序列 vs 实时值

watch 有两种显示模式:

**Last value**:只显示当前值。
- 优点:简洁。
- 缺点:看不出趋势。
- 适合:String、Enum(状态值)。

**Plot over time**:显示历史曲线。
- 优点:趋势一眼看出。
- 缺点:占 UI 空间。
- 适合:Float(连续数值)、Int(计数)。

用户根据变量类型选 display mode。Float 默认 Plot,String 默认 Last value。可以手动切换。

### 2.5 多帧暂停 / 单步

游戏暂停时(单步 debug),data block 流停。watch 显示停在最后一帧的值。

实现:game state 提供 snapshot 给 UI,UI 看 snapshot 而非 live state。snapshot 可以是历史任何一帧——用户在 timeline 上拖动,看任意时刻的状态。

```rust
struct GameState {
    frames: RingBuffer<FrameSummary, 300>,  // 历史帧
    current_view_frame: usize,  // UI 看的帧 index
}

impl GameState {
    fn ui_watch_data(&self) -> &FrameSummary {
        &self.frames[self.current_view_frame]
    }
}
```

这是 Unreal Visual Logger、Tracy frame scrub 的核心——**时间维度上的随机访问**。

### 2.6 sparkline:嵌入表格的迷你图

sparkline 是 Edward Tufte 推广的"word-sized 图表"——非常小,可以嵌入文本行。

```
HP: 75  ▁▂▃▅▆▇█▇▆▅▄▃▂▁  (趋势下降)
Speed: 5.0  ▆▆▆▆▆▆▆▆▆▆▆▆▆▆  (稳定)
```

用 Unicode block character(`▁▂▃▄▅▆▇█`)画。Rust crate:`sparklines`。

```rust
fn sparkline(history: &[f32]) -> String {
    let blocks = "▁▂▃▄▅▆▇█";
    let max = history.iter().copied().fold(0.0f32, f32::max).max(1e-6);
    let min = history.iter().copied().fold(f32::INFINITY, f32::min);
    let range = (max - min).max(1e-6);
    history.iter().map(|v| {
        let normalized = ((v - min) / range * 7.0) as usize;
        blocks.chars().nth(normalized).unwrap()
    }).collect()
}
```

30 字符宽,显示 30 个数据点的趋势。极简的可视化。

### 2.7 性能优化:per-name index

每帧 watch update 遍历 data_blocks × watched entries。N=1000 × W=10 = 10000 ops/frame,~50μs。可接受但可以优化。

**优化**:维护 per-name index——`HashMap<name, Vec<&DataBlock>>`。collate 时构建一次,watch 查询 O(1)。

```rust
struct FrameSummary {
    data_blocks: Vec<DataBlock>,
    by_name: HashMap<&'static str, Vec<usize>>,  // name → indices
}

impl FrameSummary {
    fn get_history(&self, name: &str) -> impl Iterator<Item = &DebugValue> {
        self.by_name.get(name)
            .into_iter()
            .flatten()
            .map(|&i| &self.data_blocks[i].value)
    }
}
```

每帧 collate 后构建 by_name(~10μs for 1000 blocks)。watch 查询 O(1)。总开销下降 10x。

### 类比:股票交易终端

### 2.1 watch state

```rust
pub struct WatchWindow {
    pub watched: Vec<WatchEntry>,
}

pub struct WatchEntry {
    pub name: &'static str,
    pub display_kind: WatchDisplay,  // Last / Plot / Bar
    pub history: RingBuffer<f32, 300>,  // 历史值(取一个 scalar)
}

pub enum WatchDisplay {
    LastValue,
    Plot,
    Bar { min: f32, max: f32 },
}

impl WatchWindow {
    pub fn add(&mut self, name: &'static str) {
        self.watched.push(WatchEntry {
            name, display_kind: WatchDisplay::LastValue,
            history: RingBuffer::new(),
        });
    }

    pub fn update(&mut self, frame: &FrameSummary) {
        for entry in &mut self.watched {
            // 从 frame.data_blocks 找最新值
            let latest = frame.data_blocks.iter()
                .filter(|(_, n, _)| *n == entry.name)
                .last();
            if let Some((_, _, value)) = latest {
                let scalar = match value {
                    DebugValue::Float(f) => *f,
                    DebugValue::Int(i) => *i as f32,
                    _ => continue,
                };
                entry.history.push(scalar);
            }
        }
    }
}
```

### 2.2 渲染

```rust
fn draw_watch(ui: &mut Ui, watch: &WatchWindow) {
    ui.label("Watch window");
    for entry in &watch.watched {
        ui.label(&format!("{}:", entry.name));
        match entry.display_kind {
            WatchDisplay::LastValue => {
                let last = entry.history.iter_recent().last().copied();
                if let Some(v) = last {
                    ui.label(&format!("  {:.2}", v));
                } else {
                    ui.label("  (no data)");
                }
            }
            WatchDisplay::Plot => {
                draw_plot(ui, &entry.history);
            }
            WatchDisplay::Bar { min, max } => {
                let last = entry.history.iter_recent().last().copied().unwrap_or(min);
                let frac = (last - min) / (max - min).max(1e-6);
                draw_bar(ui, frac.clamp(0.0, 1.0));
            }
        }
    }
}
```

### 3.3 · plot 性能

每帧画 300 点的折线:

- 300 次 `draw_line`
- 每条 ~100 cycle
- 总 30000 cycle = ~12 μs

可接受。优化:batch draw(1 次 vertex buffer submit)。

**batch render 的具体做法**:不用 `draw_line` 一条条画,而是把所有线段塞进一个 `Vec<Vertex>`,一次 `glDrawArrays(GL_LINES, ...)` 提交。GPU 批量处理,draw call 数从 300 降到 1。

```rust
struct LineBatch {
    vertices: Vec<Vertex>,  // 每两个 vertex 一条线段
}

impl LineBatch {
    fn add_line(&mut self, x1: f32, y1: f32, x2: f32, y2: f32, color: u32) {
        self.vertices.push(Vertex { x: x1, y: y1, color });
        self.vertices.push(Vertex { x: x2, y: y2, color });
    }

    fn flush(&mut self, gpu: &mut Gpu) {
        gpu.upload_line_vertices(&self.vertices);
        gpu.draw_lines(self.vertices.len() / 2);
        self.vertices.clear();
    }
}
```

每帧画 10 个 watch × 300 点 = 3000 vertices,batch 一次提交。draw call 从 3000 降到 1。GPU 队列处理 0.1 ms 内完成。

**性能数字对比**(60 FPS frame budget 16 ms):
- 单 line draw_line:300 line × 10 watch = 3000 calls × 1 μs = 3 ms(占 frame 19%)
- batch render:1 call × 3000 line = 0.1 ms(占 frame 0.6%)

**30x 加速**。这是 immediate-mode UI 在大型 dashboard 里必须做的优化。

工业图表库(implot、egui_plot、tracy)都用 batch render。Casey HH 教学版用单 draw_line,Day 215+ 切 OpenGL 后会切 batch。

**参考解答**:

### Lv2 · 动手实践

**题**:实现最小 WatchWindow,带 3 个 watched 变量,模拟 5 帧数据,打印 watch 内容。

**参考解答**:

```rust
#[derive(Clone, Debug)]
enum DebugValue { Float(f32), Int(i64) }

struct WatchEntry {
    name: &'static str,
    history: Vec<f32>,
}

struct WatchWindow {
    watched: Vec<WatchEntry>,
}

impl WatchWindow {
    fn new() -> Self { Self { watched: Vec::new() } }

    fn add(&mut self, name: &'static str) {
        self.watched.push(WatchEntry { name, history: Vec::new() });
    }

    fn update(&mut self, frame_data: &[(&'static str, DebugValue)]) {
        for entry in &mut self.watched {
            for (n, v) in frame_data {
                if *n == entry.name {
                    let scalar = match v { DebugValue::Float(f) => *f, DebugValue::Int(i) => *i as f32 };
                    entry.history.push(scalar);
                }
            }
        }
    }

    fn print(&self) {
        for entry in &self.watched {
            let last = entry.history.last().copied();
            let last_str = match last { Some(v) => format!("{:.2}", v), None => "(none)".to_string() };
            let avg = if entry.history.is_empty() { 0.0 }
                      else { entry.history.iter().sum::<f32>() / entry.history.len() as f32 };
            println!("{}: last={} avg={:.2} samples={}", entry.name, last_str, avg, entry.history.len());
        }
    }
}

fn main() {
    let mut watch = WatchWindow::new();
    watch.add("player_hp");
    watch.add("player_speed");
    watch.add("enemy_count");

    // 模拟 5 帧
    for frame in 0..5 {
        let data = vec![
            ("player_hp", DebugValue::Int((100 - frame as i64 * 5) as i64)),
            ("player_speed", DebugValue::Float(5.0 + frame as f32 * 0.1)),
            ("enemy_count", DebugValue::Int((10 - frame as i64) as i64)),
        ];
        watch.update(&data);
    }

    println!("=== Watch window ===");
    watch.print();
}
```
