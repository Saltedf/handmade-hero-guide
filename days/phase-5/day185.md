## 2 · 心智模型

### 类比:博物馆的展览整理

博物馆每天收一批新藏品(event 流),整理过程:

1. **按日切分**(frame marker)— 周一收的归周一,周二归周二
2. **分类归档**(collation)— 同类的放一起(同 GUID 的 spans)
3. **写日总结**(aggregate)— 周一瓷器 5 件、青铜 3 件
4. **存入档案室**(ring buffer)— 最近 30 天的总结,旧的扔

profiler 一模一样:按帧切分、按 GUID 聚合、写到 ring buffer。

### 2.1 Frame Marker

```rust
const MARKER_FRAME_BEGIN: u64 = 0xFFFF_FFFF_FFFF_FF00;
const MARKER_FRAME_END: u64 = 0xFFFF_FFFF_FFFF_FF01;

pub fn frame_begin(frame_index: u64) {
    push_event(Event {
        cycle: rdtsc(),
        guid: MARKER_FRAME_BEGIN,
        kind: Kind::Begin,
        payload: frame_index,
    });
}

pub fn frame_end(frame_index: u64) {
    push_event(Event {
        cycle: rdtsc(),
        guid: MARKER_FRAME_END,
        kind: Kind::End,
        payload: frame_index,
    });
}
```

每帧主循环开头 / 结尾调一次。

**注意 marker GUID**:Casey 用接近 u64::MAX 的"保留区"做 marker,避免和普通 span GUID 冲突。FNV-1a hash 不会产生这种高位的值。

### 2.2 按 marker 切分

```rust
pub fn collate_per_frame(events: &[Event]) -> Vec<Vec<Event>> {
    let mut frames = Vec::new();
    let mut current = Vec::new();
    for e in events {
        if e.guid == MARKER_FRAME_BEGIN {
            current = Vec::new();
            current.push(e.clone());
        } else if e.guid == MARKER_FRAME_END {
            current.push(e.clone());
            frames.push(std::mem::take(&mut current));
        } else {
            current.push(e.clone());
        }
    }
    frames
}
```

然后对每段调 `collate` + `aggregate`,得到一个 FrameSummary。

**优化**:`e.clone()` 对 Copy 类型是廉价,但可以更精简——直接传 slice:`events.iter().skip(begin_idx).take(end_idx - begin_idx)`。Casey 的 C 版本用指针 + length,Rust 用 iterator 更自然。

### 2.3 FrameSummary 结构

```rust
#[derive(Clone, Default)]
pub struct FrameSummary {
    pub frame_index: u64,
    pub begin_cycle: u64,
    pub end_cycle: u64,
    pub total_cycles: u64,
    pub stats: HashMap<u64, SpanStats>,
}
```

每帧 collation 后构造一个 FrameSummary,推到 ring buffer。

### 2.4 完整 collation pipeline

```rust
pub fn process_frame(events: &[Event]) -> Option<FrameSummary> {
    // 切分(假设 events 已经按 cycle 排序)
    let frame_events: Vec<&Event> = events.iter().collect();
    if frame_events.is_empty() { return None; }

    let begin = frame_events.first()?.cycle;
    let end = frame_events.last()?.cycle;

    // collate spans
    let spans = collate(&frame_events);

    // aggregate
    let stats = aggregate(&spans);

    Some(FrameSummary {
        frame_index: 0,  // 由调用方填
        begin_cycle: begin,
        end_cycle: end,
        total_cycles: end - begin,
        stats,
    })
}
```

### 2.5 Profiler API 封装

```rust
pub struct Profiler {
    state: Rc<RefCell<ProfilerState>>,
}

struct ProfilerState {
    events: Vec<Event>,
    frames: RingBuffer<FrameSummary, 300>,
    current_frame_index: u64,
}
```

**为什么用 Rc<RefCell<>> 而不是全局 static?** 全局 static 简单但有几个问题:

1. 多实例没法测试(全局 state 污染单测)
2. 初始化顺序复杂(`Lazy` / `OnceLock` 都各有 trade-off)
3. 不能在测试中替换 mock

`Rc<RefCell<>>` 让 profiler 成为"对象"——可以创建多个,可以传引用,可以测试。

**为什么不用 trait object**?profiler 内部不需要多态(只有一个实现)。trait object 加 vtable overhead,profiler 这种 hot path 不需要。Generics 也可以,但会污染调用方代码。

Casey 在 C 里就是全局 static,简单但难测试。Rust 翻译版用 Rc 更"Rust 风格"。

impl Profiler {
    pub fn new() -> Self {
        Self { state: Rc::new(RefCell::new(ProfilerState {
            events: Vec::new(),
            frames: RingBuffer::new(),
            current_frame_index: 0,
        }))}
    }

    pub fn enter(&self, name: &'static str) -> ProfileSpan {
        ProfileSpan::enter(name, &self.state)
    }

    pub fn begin_frame(&self) {
        let mut s = self.state.borrow_mut();
        push_internal(&mut s, frame_begin_event(s.current_frame_index));
    }

    pub fn end_frame(&self) {
        let mut s = self.state.borrow_mut();
        push_internal(&mut s, frame_end_event(s.current_frame_index));

        // collate 本帧
        let events = std::mem::take(&mut s.events);
        if let Some(mut summary) = process_frame(&events) {
            summary.frame_index = s.current_frame_index;
            s.frames.push(summary);
        }

        s.current_frame_index += 1;
    }
}
```

**Rust 注释**:
- `Rc<RefCell<...>>` — 单线程"内部可变性"。多线程要 `Arc<Mutex<>>`
- `borrow_mut()` — 运行时借用检查
- `std::mem::take(&mut vec)` — 把 Vec 取空,返回原 Vec(O(1))

### 2.6 Rc<RefCell<>> 的 ownership 图

`Rc<RefCell<ProfilerState>>` 在内存里:

```
stack frame                heap
+------------+             +-------------------+
| Profiler { | --Rc-----> | RefCell {         |
|   state    |             |   borrow: None,   |
| }          |             |   value: ProfilerState { ... }
+------------+             | }                 |
                           +-------------------+
                                ^
                                | (Rc clone)
                           +----+----+
                           | span    |
                           | guard   |
                           +---------+
```

`Rc` 是引用计数(单线程),允许多个 owner。`RefCell` 提供 `borrow_mut`——运行时检查"现在能不能 mut"。Span guard 持有 Rc clone,所以即便 profiler 离开作用域,guard 还能用。

**Arc<Mutex<>>** 是多线程版:`Arc` = atomic Rc,`Mutex` = lock-based RefCell。多线程时换成这个。

### 2.7 测试 collation 的正确性

profiler 数据正确性怎么验证?**单元测试 + property-based testing**:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_simple_pair() {
        let events = vec![
            Event { cycle: 100, guid: 1, kind: Kind::Begin, payload: 0 },
            Event { cycle: 200, guid: 1, kind: Kind::End, payload: 0 },
        ];
        let summary = collate_and_aggregate(&events);
        assert_eq!(summary.stats.get(&1).unwrap().total_cycles, 100);
    }

    #[test]
    fn test_nested() {
        let events = vec![
            Event { cycle: 0, guid: 1, kind: Kind::Begin, payload: 0 },
            Event { cycle: 100, guid: 2, kind: Kind::Begin, payload: 0 },
            Event { cycle: 200, guid: 2, kind: Kind::End, payload: 0 },
            Event { cycle: 300, guid: 1, kind: Kind::End, payload: 0 },
        ];
        let summary = collate_and_aggregate(&events);
        assert_eq!(summary.stats.get(&1).unwrap().total_cycles, 300);
        assert_eq!(summary.stats.get(&2).unwrap().total_cycles, 100);
    }

    #[test]
    fn test_unmatched() {
        let events = vec![
            Event { cycle: 0, guid: 1, kind: Kind::Begin, payload: 0 },
            // 没有 end
        ];
        let summary = collate_and_aggregate(&events);
        assert!(summary.stats.get(&1).is_none());  // 没配对成功
    }
}
```

## 3 · 四域深入

### 3.1 · 游戏编程视角

帧隔离的重要性:

- 没切分:`begin update_frame`(帧 100)+ `end update_frame`(帧 101)→ 配对错,算出"百万 cycle"的假数据
- 切分后:每帧独立,不会混淆

商业引擎的 frame marker:
- Unreal:`TRACE_BOOKMARK("FrameEnd")`
- Unity:`Profiler.EndSample` after frame
- Casey:`MARKER_FRAME_END`

### 3.2 · Rust 生态视角

Rust 的"内部可变性"模式:

| 类型 | 单/多线程 | 借用检查 |
|---|---|---|
| `&mut T` | 任意 | 编译期 |
| `Cell<T>` | 单线程 | 编译期(运行时无开销,Copy only) |
| `RefCell<T>` | 单线程 | 运行时 |
| `Mutex<T>` | 多线程 | 运行时 + lock |
| `RwLock<T>` | 多线程 | 运行时 + 读/写锁 |
| `AtomicU32` 等 | 多线程 | 硬件原子 |

profiler 单线程版用 RefCell,跨线程切 Arc<Mutex> 或 thread_local。

### 3.3 · Linux 系统编程视角

Linux perf 的 frame marker 用 `perf_event_open` + `PERF_RECORD_LOST` / `PERF_RECORD_THROTTLE` 等。Casey 自己用 `MARKER_*` GUID 简化。

## 5 · 对照与变奏

** profiler 状态的不同 ownership 模式**:

| 模式 | 适合 |
|---|---|
| 全局 static | 简单,线程不安全 |
| Rc<RefCell> | 单线程,共享 |
| Arc<Mutex> | 多线程,简单 |
| thread_local | 多线程,每线程独立 |
| 传引用 | 显式,但侵入式 |

Casey 在 day 183 用"平台层分配 + 指针",等价"传引用"。

### 与 Unreal Insights / Tracy 的 frame marker 对比

工业级 profiler 的 frame marker 各有特色:

- **Unreal Insights**:`TRACE_BOOKMARK("Frame", frame_number)` — 字符串名 + payload,灵活
- **Tracy**:`TracyCFrameMark` — C API,自动用调用位置
- **Chrome Trace**:`Tracing.started("Frame")` + `Tracing.complete("Frame")` — 显式 begin/end
- **Casey**:`MARKER_FRAME_BEGIN/END` — 自定义 GUID,极简

Casey 的设计**最简单**,但限制是只有一个 frame 概念。如果想加"logic frame" / "render frame"两个层级,要扩展 marker 类型。

### Rc<RefCell<>> vs Arc<Mutex<>> 的取舍

Rust 的"内部可变性"有两套:

| 维度 | Rc<RefCell<>> | Arc<Mutex<>> |
|---|---|---|
| 线程 | 单 | 多 |
| 性能 | ~5 ns/access | ~50 ns/access(锁) |
| 死锁风险 | 无(运行时 panic) | 有 |
| 内存 | 引用计数非原子 | 引用计数原子 |

**profiler 单线程版**用 Rc<RefCell<>>,**多线程版**切 Arc<Mutex<>>。Casey 的游戏主线程单线程跑 profiler,工作线程用 thread_local——避免 Arc<Mutex<>> 的开销。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么要在 collation 前按 frame marker 切分,而不是直接配对所有 event?

**参考解答**:
- 直接配对会"跨帧"配:帧 100 的 begin 配到帧 101 的 end,数据错
- collation 假设输入是"一段连续时间"内的 event
- 切分保证每段是"一帧内的事件"
- 性能上,切分是 O(N),不增加额外开销

### Lv2 · 动手实践

**题**:基于 day 184 的代码,加:
1. frame marker
2. FrameSummary 结构
3. process_frame pipeline
4. main 里跑 5 帧,每帧有 3 个 span,打印每帧 summary

**参考解答**:

```rust
use std::collections::HashMap;

#[derive(Clone, Copy, Debug)]
enum Kind { Begin, End }

#[derive(Clone, Copy, Debug)]
struct Event { cycle: u64, guid: u64, kind: Kind, payload: u64 }

const MARKER_BEGIN: u64 = u64::MAX - 1;
const MARKER_END: u64 = u64::MAX - 2;

#[derive(Clone, Debug, Default)]
struct SpanStats { count: u32, total_cycles: u64 }

#[derive(Clone, Debug, Default)]
struct FrameSummary {
    frame_index: u64,
    total_cycles: u64,
    stats: HashMap<u64, SpanStats>,
}

fn collate_and_aggregate(events: &[Event]) -> FrameSummary {
    let mut stack: Vec<(u64, u64)> = Vec::new();
    let mut summary = FrameSummary::default();
    let mut frame_cycles = 0u64;

    for e in events {
        match e.kind {
            Kind::Begin => {
                if e.guid == MARKER_BEGIN {
                    summary.frame_index = e.payload;
                    continue;
                }
                stack.push((e.guid, e.cycle));
            }
            Kind::End => {
                if e.guid == MARKER_END {
                    continue;
                }
                if let Some((guid, begin)) = stack.pop() {
                    if guid == e.guid {
                        let dur = e.cycle - begin;
                        let s = summary.stats.entry(guid).or_default();
                        s.count += 1;
                        s.total_cycles += dur;
                        frame_cycles += dur;
                    }
                }
            }
        }
    }
    summary.total_cycles = frame_cycles;
    summary
}

fn main() {
    let mut all_events: Vec<Event> = Vec::new();
    let mut cycle = 1000u64;

    for frame in 0..5 {
        all_events.push(Event { cycle, guid: MARKER_BEGIN, kind: Kind::Begin, payload: frame });
        cycle += 10;

        for span_guid in 1..=3u64 {
            all_events.push(Event { cycle, guid: span_guid, kind: Kind::Begin, payload: 0 });
            cycle += 50 + span_guid * 10;  // 假耗时
            all_events.push(Event { cycle, guid: span_guid, kind: Kind::End, payload: 0 });
            cycle += 5;
        }

        all_events.push(Event { cycle, guid: MARKER_END, kind: Kind::End, payload: frame });
        cycle += 100;
    }

    // 切分 + collate
    let mut current: Vec<Event> = Vec::new();
    let mut summaries = Vec::new();
    for e in &all_events {
        current.push(e.clone());
        if e.guid == MARKER_END {
            summaries.push(collate_and_aggregate(&current));
            current.clear();
        }
    }

    for s in &summaries {
        println!("=== Frame {} (total {} cycles) ===", s.frame_index, s.total_cycles);
        for (guid, st) in &s.stats {
            println!("  guid={}: count={} avg={}", guid, st.count, st.total_cycles / st.count as u64);
        }
    }
}
```
