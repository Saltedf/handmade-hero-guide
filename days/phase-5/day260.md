
# Day 260 · 性能分析器实现下钻(Phase 5 收官)

> Day 255 你做了 profiler,Day 258 修了跨 reload 的 bug。但 profiler 还是平铺的 —— 它告诉你"`game_update` 花了 5ms"却不告诉你"这 5ms 里哪 2ms 是物理、哪 1ms 是路径搜索、哪 0.5ms 是音频"。今天 Casey 给 profiler 加**下钻(drill-down)**:点 `game_update` → 展开看到子块时间。这是 Phase 5 收官,也是 Casey 用 60+ 集做的 debug 系统的高潮。

## 0 · 为什么要有这一天

平铺 profiler 能告诉你"哪个函数慢",但游戏不是这么组织的。游戏一帧里:`update` 调 `physics`,physics 调 `broadphase` 和 `narrowphase`,broadphase 调 `spatial_hash`... 如果 profiler 只说"spatial_hash 慢",你不知道是谁调的 —— 是 AI 路径搜索?是物理碰撞?是渲染剔除?

**drill-down** 解决的就是这个"调用上下文"问题。它把性能数据组织成**树**:

```
game_update (5.0ms)
├─ physics (2.0ms)
│  ├─ broadphase (1.2ms)
│  │  ├─ spatial_hash (0.9ms)
│  │  └─ rebuild_grid (0.3ms)
│  └─ narrowphase (0.8ms)
├─ render (1.5ms)
│  ├─ sort_by_depth (0.4ms)
│  └─ draw_quads (1.1ms)
├─ audio (0.5ms)
└─ misc (1.0ms)
```

你看到 `spatial_hash` 占 0.9ms,沿树向上能找到它是被 `physics → broadphase` 调的。改 physics 算法时知道影响哪些子块。

Casey 在 Day 260 做的是**层级 profiler**(hierarchical profiler) —— 跟 [Tracy](https://github.com/wolfpld/tracy)、[optick](https://github.com/bombomby/optick)、[Remotery](https://github.com/Celtoys/Remotery) 同类。这一类工具的共同特征是**记录 begin/end 配对**,自动构建调用栈,渲染成火焰图(flamegraph)。

**为什么层级 profiler 比平铺强**:

1. **看见调用路径** —— 不只看函数 X 慢,还看 X 是被谁调的慢
2. **inclusive vs exclusive 时间** —— "physics 总耗时"vs "physics 自己耗时(减去子调用)"
3. **重复调用归并** —— 同一函数被调 1000 次,层级 profiler 显示总和 + 平均 + 最大
4. **可视化火焰图** —— 一眼看出"最宽的塔"是最热的代码路径

**为什么这件事重要**:任何写性能敏感代码的人都需要这种工具。Linux 上有 `perf`、`valgrind --tool=callgrind`、`flamegraph`(Brendan Gregg 的 Rust 工具),但它们是**采样式 profiler**(每隔 N 微秒抓一次栈),有精度损失。Casey 这种**插桩式 profiler**(代码里手动标 begin/end)精度 100%,但要改源码。两者各有适用场景。

**心理锚点**:Phase 5 结束你能做到 —— 在 debug overlay 上看到火焰图,鼠标悬停看每块耗时,点击下钻看子块。改一段代码,hot reload,新代码的 profile 立刻显示。这是个完整的游戏开发工具链雏形。

## 1 · Casey 今天做了什么

Casey 给 profiler 加 drill-down:

1. **TIMED_BLOCK 宏记录 parent 指针** —— 每个块知道自己上层是谁
2. **begin_block() 压栈,end_block() 弹栈** —— 自动维护"当前栈顶"
3. **profile frame 结束后构建树** —— 把平铺的事件列表按 parent/child 串成树
4. **debug UI 里画展开/折叠** —— 点父块,展开看子块
5. **inclusive 和 exclusive 时间分别显示** —— total(含子)vs self(不含子)
6. **测试** —— 故意写 nested block,验证树结构正确

**关键决策**:**用 thread-local "current block" 指针**。每个线程有自己的栈,block 进栈时记 parent,出栈时恢复 parent。这跟函数调用栈天然对齐 —— 函数进入 push,函数退出 pop,层级 profiler 的栈自动维护。

**Casey 没做的事**:**多线程聚合**(看几个线程的 profile 合并)。HH 是单线程 game loop,不需要。多线程 profiler 比单线程复杂得多(线程间同步、锁等待时间统计),商业工具才做。

## 2 · 心智模型

### 类比:嵌套的俄罗斯套娃

想象你打开一套俄罗斯套娃。最外层娃娃叫 `game_update`。你打开它,里面是 `physics` 和 `render` 两个娃娃。打开 `physics`,里面是 `broadphase` 和 `narrowphase`...

drill-down profiler 就是**给每个娃娃贴个时间标签**,然后让你按需"打开"任何一个娃娃看里面。最外层的标签是 inclusive 时间(整个 game_update 花了多久),最内层标签是 exclusive 时间(那个具体函数自己花多久,不含子调用)。

### 2.1 层级 profiler 的数据模型

**核心数据结构:有向树**

```rust
struct ProfileBlock {
    guid: u64,             // 块标识(Day 250)
    name: Box<str>,        // host 拥有(Day 258)
    start_ns: u64,         // 开始时间
    end_ns: u64,           // 结束时间
    parent: Option<usize>, // 父块索引(数组下标,不用指针)
    children: Vec<usize>,  // 子块索引列表
}
```

**注意**:用**数组下标**不用指针。原因:

1. Vec 扩容会失效所有指针 → 安全性
2. 数组下标可以序列化、跨 DLL 传递(指针不行)
3. 缓存友好(连续内存)

### 2.2 thread-local 栈自动维护父子关系

```rust
use std::cell::RefCell;

thread_local! {
    static CURRENT_BLOCK: RefCell<Option<usize>> = RefCell::new(None);
    static BLOCKS: RefCell<Vec<ProfileBlock>> = RefCell::new(vec![]);
}

pub fn begin_block(guid: u64, name: &str) -> usize {
    let idx = BLOCKS.with(|b| {
        let mut b = b.borrow_mut();
        let idx = b.len();
        b.push(ProfileBlock {
            guid,
            name: Box::from(name),
            start_ns: now_ns(),
            end_ns: 0,
            parent: None,
            children: vec![],
        });
        idx
    });

    // 链接父子
    CURRENT_BLOCK.with(|c| {
        let mut cur = c.borrow_mut();
        if let Some(parent_idx) = *cur {
            // 当前栈顶是新块的 parent
            BLOCKS.with(|b| {
                let mut b = b.borrow_mut();
                b[idx].parent = Some(parent_idx);
                b[parent_idx].children.push(idx);
            });
        }
        // 新块成为栈顶
        *cur = Some(idx);
    });

    idx
}

pub fn end_block(idx: usize) {
    BLOCKS.with(|b| {
        let mut b = b.borrow_mut();
        b[idx].end_ns = now_ns();
    });

    // 弹栈:恢复 parent 为栈顶
    BLOCKS.with(|b| {
        let b = b.borrow();
        CURRENT_BLOCK.with(|c| {
            *c.borrow_mut() = b[idx].parent;
        });
    });
}
```

**使用**(配合 RAII guard):

```rust
pub struct ProfileGuard { idx: usize }

impl Drop for ProfileGuard {
    fn drop(&mut self) { end_block(self.idx); }
}

#[macro_export]
macro_rules! timed_block {
    ($name:expr) => {{
        let _idx = $crate::begin_block($crate::guid!(), $name);
        $crate::ProfileGuard { idx: _idx }
    }};
}

// 用
fn game_update() {
    let _g = timed_block!("game_update");  // begin

    physics();
    render();

    // _g drop 时 end_block 自动调
}

fn physics() {
    let _g = timed_block!("physics");
    // ...
}
```

**关键**:`_g` 的生命周期跟 lexical scope 一致。Drop 自动调 end。这就跟函数调用栈天然对齐。

### 2.3 inclusive vs exclusive

```
game_update: 5.0ms total(含子调用)
  physics: 2.0ms total
    spatial_hash: 0.9ms total
    ...
  render: 1.5ms total
  ...
```

- **inclusive(总时间)**:`game_update` 的 5.0ms,包含 physics + render + audio
- **exclusive(自时间)**:`game_update` 的 self time = 5.0 - 2.0 - 1.5 - 0.5 - 1.0 = 0ms

`exclusive = end - start - sum(children.duration)`

这告诉你"函数自己做了多少工作"(不算子调用)。一个函数 inclusive 高但 exclusive 低,说明它在等子调用 —— 优化点在子调用。exclusive 高,说明函数自己慢 —— 优化点在函数体。

### 2.4 火焰图可视化

火焰图把树画成横向堆叠的色块:

```
┌────────────────────────────────────────────────────────┐
│                    game_update (5ms)                    │
├──────────────┬─────────────┬──────────┬─────────────────┤
│   physics    │   render    │  audio   │   (self 0ms)    │
│    (2ms)     │   (1.5ms)   │  (0.5ms) │                 │
├─────────────┐├────────────┐│          │                 │
│broad│narrow ││sort│draw   ││          │                 │
│1.2  │0.8    ││0.4 │1.1    ││          │                 │
└─────┴───────┘└────┴───────┘│          │                 │
                             │          │                 │
```

宽度 = 时间占比,颜色 = 调用栈深度(可选)。最宽的"塔"是最热的代码路径。

### 2.5 chrome tracing 格式

Chrome 浏览器自带 `chrome://tracing`,能加载 JSON 格式的 profile 数据:

```json
{
  "traceEvents": [
    {"name": "game_update", "cat": "game", "ph": "B", "ts": 0,   "pid": 0, "tid": 0},
    {"name": "physics",     "cat": "game", "ph": "B", "ts": 100, "pid": 0, "tid": 0},
    {"name": "physics",     "cat": "game", "ph": "E", "ts": 200, "pid": 0, "tid": 0},
    {"name": "game_update", "cat": "game", "ph": "E", "ts": 500, "pid": 0, "tid": 0}
  ]
}
```

- `ph: "B"` = begin,`ph: "E"` = end
- `ts` 单位微秒
- 浏览器加载后画时间轴 + 调用栈

这是 cross-tool 标准 —— 任何能输出 chrome tracing 的 profiler 都能跨工具对比。Casey 的 profiler 也输出这个格式,Rust 端用 `serde_json` 序列化即可。

### 3.2 · 🎨 图形学视角

GPU profile 跟 CPU profile 不同:

- **CPU**:函数调用,即时返回
- **GPU**:命令队列,异步执行。GPU 慢一帧才知道

GPU profile 工具:

- **GL**:timer query(`glQueryCounter`)
- **Vulkan**:timestamp query
- **RenderDoc**:抓帧后离线分析

```rust
// GL timer query(简化)
let mut query = 0;
unsafe {
    gl.gen_queries(1, &mut query);
    gl.begin_query(glow::TIME_ELAPSED, query);
    // 画一些东西
    gl.end_query(glow::TIME_ELAPSED);
    // 下一帧才能读结果(异步)
    let mut done = 0;
    while done == 0 {
        gl.get_query_object_iv(query, glow::QUERY_RESULT_AVAILABLE, &mut done);
    }
    let mut ns = 0;
    gl.get_query_object_64iv(query, glow::QUERY_RESULT, &mut ns);
    println!("GPU 时间: {} ns", ns);
}
```

GPU / CPU profile 联合看 —— CPU 提交命令快,但 GPU 执行慢,瓶颈在 GPU。Casey 在 Day 260 专注 CPU,GPU profile 后面 Days 才补。

### 3.4 · 🦀 Rust 生态视角

Rust 表达层级 profiler 的几个特性:

**thread_local!**

```rust
use std::cell::RefCell;

thread_local! {
    static STACK: RefCell<Vec<usize>> = RefCell::new(vec![]);
}
```

Rust 的 `thread_local!` 宏自动保证每个线程独立变量。无需锁,无线程间同步开销。

**Drop trait**

```rust
struct ProfileGuard { idx: usize }
impl Drop for ProfileGuard {
    fn drop(&mut self) { end_block(self.idx); }
}
```

RAII 资源管理。C 里要手动配对 begin/end,Rust 用 Drop 自动化,**避免忘 end 的 bug**(经典内存泄漏源)。

**panic safety**

```rust
fn game_update() {
    let _g = begin_block("game_update");
    might_panic();  // panic 时 _g drop 还是调
    end_block(_g.idx);  // 不会执行
}
```

panic 时 Drop 还是跑,profiler 数据完整。这是 Rust 相对 C 的优势 —— panic 安全。

**puffin egg crate**

`puffin` 是 Rust 生态的层级 profiler,API 风格类似 Casey:

```rust
fn game_update() {
    puffin::profile_function!();  // 自动 begin/end
    puffin::profile_scope!("physics");  // 命名 scope
}
```

`puffin_egui` 提供火焰图 UI。商业项目推荐 puffin + egui。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:inclusive 和 exclusive 时间的区别是什么?如果一个函数 inclusive 是 10ms,exclusive 是 0ms,说明什么?

**参考解答**:

- **inclusive(总时间)**:函数从 begin 到 end 的总时间,包含所有子调用
- **exclusive(自时间)**:函数自己执行的时间 = inclusive - 所有子调用的 inclusive 时间之和

如果一个函数 inclusive 10ms、exclusive 0ms,说明:**它自己什么都没做,所有时间都在等子调用返回**。这是典型的"调度函数"(dispatcher) —— 它只负责调用子函数,自己几乎没逻辑。

优化时,exclusive 0ms 的函数本身不是瓶颈,看它的子调用。exclusive 高的函数才是优化目标。

### Lv2 · 动手实践

**题**:用 thread_local + RAII 实现最小层级 profiler,测量 3 层嵌套函数耗时。完成标准:打印树形结构,每块显示 inclusive 和 exclusive 时间。

**参考解答**:

```rust
use std::cell::RefCell;
use std::time::Instant;

struct Block {
    name: &'static str,
    start: Instant,
    end: Option<Instant>,
    parent: Option<usize>,
    children: Vec<usize>,
}

thread_local! {
    static BLOCKS: RefCell<Vec<Block>> = RefCell::new(vec![]);
    static CURRENT: RefCell<Option<usize>> = RefCell::new(None);
}

fn begin(name: &'static str) -> usize {
    BLOCKS.with(|b| {
        let mut b = b.borrow_mut();
        let idx = b.len();
        let parent = CURRENT.with(|c| *c.borrow());
        b.push(Block {
            name, start: Instant::now(), end: None,
            parent, children: vec![],
        });
        if let Some(p) = parent {
            b[p].children.push(idx);
        }
        idx
    }).inspect(|&idx| {
        CURRENT.with(|c| *c.borrow_mut() = Some(idx));
    }).unwrap()
}

fn end(idx: usize) {
    BLOCKS.with(|b| {
        let mut b = b.borrow_mut();
        b[idx].end = Some(Instant::now());
        let parent = b[idx].parent;
        CURRENT.with(|c| *c.borrow_mut() = parent);
    });
}

struct Guard(usize);
impl Drop for Guard { fn drop(&mut self) { end(self.0); } }

#[macro_export]
macro_rules! profile {
    ($name:expr) => {
        let _g = $crate::Guard($crate::begin($name));
    };
}

    profile!("outer");
    std::thread::sleep(std::time::Duration::from_millis(10));
    middle();
    std::thread::sleep(std::time::Duration::from_millis(10));
}

fn middle() {
    profile!("middle");
    std::thread::sleep(std::time::Duration::from_millis(5));
    inner();
}

fn inner() {
    profile!("inner");
    std::thread::sleep(std::time::Duration::from_millis(3));
}

fn print_tree(idx: usize, depth: usize) {
    BLOCKS.with(|b| {
        let b = b.borrow();
        let blk = &b[idx];
        let dur = blk.end.unwrap().duration_since(blk.start).as_secs_f64() * 1000.0;
        let child_total: f64 = blk.children.iter()
            .map(|&c| b[c].end.unwrap().duration_since(b[c].start).as_secs_f64() * 1000.0)
            .sum();
        let self_time = dur - child_total;
        let indent = "  ".repeat(depth);
        println!("{}{}: total={:.2}ms self={:.2}ms", indent, blk.name, dur, self_time);
        for &c in &blk.children {
            print_tree(c, depth + 1);
        }
    });
}

fn main() {
    outer();

    println!("=== Profile Tree ===");
    BLOCKS.with(|b| {
        let b = b.borrow();
        for i in 0..b.len() {
            if b[i].parent.is_none() {
                print_tree(i, 0);
            }
        }
    });
}
```

```rust
// src/profiler.rs
use std::cell::RefCell;
use std::sync::Mutex;
use std::time::Instant;

pub struct Block {
    pub name: Box<str>,           // host 拥有(Day 258)
    pub guid: u64,                // 块标识(Day 250)
    pub start_ns: u64,
    pub end_ns: u64,
    pub parent: Option<usize>,    // 数组下标,Vec 扩容安全
    pub children: Vec<usize>,
    pub tid: u32,                 // 线程 id
}

thread_local! {
    /// 当前线程的"栈顶"块索引
    static CURRENT_BLOCK: RefCell<Option<usize>> = const { RefCell::new(None) };
}

/// 全局 frames 集合(host 拥有,跨 reload 保留)
lazy_static::lazy_static! {
    static ref FRAMES: Mutex<Vec<Vec<Block>>> = Mutex::new(vec![]);
}

/// 当前正在记录的 frame(每个线程一份)
thread_local! {
    static CURRENT_FRAME: RefCell<Vec<Block>> = RefCell::new(vec![]);
}

pub fn begin_frame() {
    CURRENT_FRAME.with(|f| f.borrow_mut().clear());
    CURRENT_BLOCK.with(|c| *c.borrow_mut() = None);
}

pub fn end_frame() {
    CURRENT_FRAME.with(|f| {
        let frame = std::mem::take(&mut *f.borrow_mut());
        FRAMES.lock().unwrap().push(frame);
        // 保留最近 120 帧(2 秒 @ 60fps)
        let mut frames = FRAMES.lock().unwrap();
        if frames.len() > 120 {
            frames.remove(0);
        }
    });
}

pub fn begin_block(guid: u64, name: &str) -> usize {
    let tid = unsafe { libc::syscall(libc::SYS_gettid) as u32 };
    CURRENT_FRAME.with(|f| {
        let mut f = f.borrow_mut();
        let idx = f.len();
        let parent = CURRENT_BLOCK.with(|c| *c.borrow());
        f.push(Block {
            name: Box::from(name),
            guid,
            start_ns: now_ns(),
            end_ns: 0,
            parent,
            children: vec![],
            tid,
        });
        if let Some(p) = parent {
            f[p].children.push(idx);
        }
        CURRENT_BLOCK.with(|c| *c.borrow_mut() = Some(idx));
        idx
    })
}

pub fn end_block(idx: usize) {
    CURRENT_FRAME.with(|f| {
        let mut f = f.borrow_mut();
        f[idx].end_ns = now_ns();
        let parent = f[idx].parent;
        CURRENT_BLOCK.with(|c| *c.borrow_mut() = parent);
    });
}

pub struct BlockGuard(pub usize);
impl Drop for BlockGuard {
    fn drop(&mut self) {
        end_block(self.0);
    }
}

#[macro_export]
macro_rules! profile_scope {
    ($name:expr) => {
        let _guard = $crate::profiler::BlockGuard(
            $crate::profiler::begin_block(
                $crate::guid!($name, file!(), line!()),
                $name,
            )
        );
    };
}

fn now_ns() -> u64 {
    let now = Instant::now();
    let elapsed = now.elapsed();
    // 简化:实际应该用 Instant::now() - EPOCH,但 Instant 不能减全局 EPOCH
    // 用 SystemTime 或 thread-local start 替代
    elapsed.as_nanos() as u64
}

// === 下钻查询 ===

pub fn get_latest_frame() -> Vec<Block> {
    FRAMES.lock().unwrap().last().cloned().unwrap_or_default()
}

pub fn block_duration_ns(b: &Block) -> u64 {
    b.end_ns.saturating_sub(b.start_ns)
}

pub fn block_self_ns(b: &Block, frame: &[Block]) -> u64 {
    let total = block_duration_ns(b);
    let child_total: u64 = b.children.iter()
        .map(|&c| block_duration_ns(&frame[c]))
        .sum();
    total.saturating_sub(child_total)
}

// === chrome tracing 导出 ===

pub fn export_chrome_tracing(path: &str) -> std::io::Result<()> {
    use std::io::Write;
    let frames = FRAMES.lock().unwrap();
    let mut f = std::fs::File::create(path)?;
    writeln!(f, "{{\"traceEvents\":[")?;

    let mut first = true;
    for (frame_idx, frame) in frames.iter().enumerate() {
        for b in frame {
            if !first { writeln!(f, ",")?; }
            first = false;
            let dur = block_duration_ns(b) / 1000;  // ns → us
            let ts = b.start_ns / 1000;
            write!(f, "{{\"name\":\"{}\",\"cat\":\"game\",\"ph\":\"X\",\"ts\":{},\"dur\":{},\"pid\":0,\"tid\":{}}}",
                b.name, ts, dur, b.tid)?;
        }
        let _ = frame_idx;
    }
    writeln!(f, "]}}")?;
    Ok(())
}
```

```rust
// src/main.rs
mod profiler;

fn physics() {
    profiler::profile_scope!("physics");
    std::thread::sleep(std::time::Duration::from_millis(2));
}

fn render() {
    profiler::profile_scope!("render");
    std::thread::sleep(std::time::Duration::from_millis(1));
}

fn game_update() {
    profiler::profile_scope!("game_update");
    physics();
    render();
    std::thread::sleep(std::time::Duration::from_millis(1));
}

fn main() {
    for _ in 0..3 {
        profiler::begin_frame();
        game_update();
        profiler::end_frame();
    }

    // 打印最后一帧
    let frame = profiler::get_latest_frame();
    println!("=== Last frame: {} blocks ===", frame.len());

    for (i, b) in frame.iter().enumerate() {
        let total = profiler::block_duration_ns(b);
        let self_ns = profiler::block_self_ns(b, &frame);
        let indent = "  ".repeat(parent_depth(i, &frame));
        println!("{}{}: total={:.2}ms self={:.2}ms",
            indent, b.name,
            total as f64 / 1e6, self_ns as f64 / 1e6);
    }

    // 导出 chrome tracing
    profiler::export_chrome_tracing("trace.json").unwrap();
    println!("导出: trace.json,加载方式: 打开 chrome://tracing → Load");
}

fn parent_depth(idx: usize, frame: &[profiler::Block]) -> usize {
    let mut depth = 0;
    let mut cur = frame[idx].parent;
    while let Some(p) = cur {
        depth += 1;
        cur = frame[p].parent;
    }
    depth
}
```

**Troubleshooting**:

- **profiler overhead 太高** —— release 模式编译,检查 Instant::now() 调用频率(每次几 ns,但百万次累积)
- **`libc::SYS_gettid` 找不到** —— `cargo add libc` 或改用 `std::thread::current().id()`
- **chrome tracing 显示空** —— 检查 JSON 格式,`ph: "X"` 是 complete event(需要 ts + dur),`ph: "B"/"E"` 配对用
- **flamegraph 没看到 game 函数** —— release 模式去符号了,改用 debug = true 或 debug = "limited"
- **panic 后 profiler 没数据** —— panic 时 Drop 还是跑,但 FRAMES.lock() 可能 poison,改用 `lock().unwrap_or_else(|e| e.into_inner())`
