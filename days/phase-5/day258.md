# Day 258 · 修复跨代码重载的性能分析

> Day 192 你做了 hot reload(热重载)—— 改代码自动重新编译,游戏不停。Day 255 你做了 profiler。但今天发现:**hot reload 后 profiler 数据错乱**——所有 TIMED_BLOCK 名字变成乱码,GUID 冲突。今天 Casey 修复跨 reload 的 profiler 持久性。

## 0 · 为什么要有这一天

hot reload 是开发期提速利器。但 hot reload 时:

1. **新 DLL 加载到不同地址** —— 静态字符串(`&'static str`)的指针变了
2. **profiler 用 `&'static str` 引用** —— 旧指针指向旧 DLL 的字符串,新代码的字符串在新地址
3. **profiler 的全局 state** 可能在 DLL 里,重载后丢失或双份

具体表现:

```
Hot reload 前:
  profiler data: { name: "game_update", ns: 2100000 }

改代码 → 自动重新编译 → DLL 重载

Hot reload 后:
  profiler data: { name: <garbage>, ns: 0 }
  // 或
  profiler data: { name: "game_update", ns: 2100000 }  ← 但指向新 DLL 的字符串
                                                  (旧 profiler state 引用旧字符串地址)
```

**修复策略**:

1. **profiler state 放 host(主可执行文件)** —— 不在 hot-reload 的 DLL 里
2. **跨 DLL 边界传值,不传引用** —— 复制 string 到 host 内存
3. **GUID 用 hash,不用指针** —— Day 250 的 GUID 设计正确

**为什么这件事重要**:hot reload + 任何全局 state 都会撞这个 bug。理解"什么在 host,什么在 reload 模块",是动态库架构的核心。

**心理锚点**:看完今天,你的 hot reload profiler 数据一致,改代码后 profile 立刻反映新版本。

## 1 · Casey 今天做了什么

Casey 修复跨 reload 的 profiler:

1. **profiler state 移到 platform layer**(host,不 hot reload)
2. **TIMED_BLOCK 宏把 name 复制**(不传 &'static str 引用)
3. **GUID 算法保证跨 reload 一致**(hash name + file + line)
4. **DLL reload 时,profiler state 不动**(继续累计)

**关键决策**:**清晰边界**——reload 的代码不持 state,state 在 host。Casey 的三明治架构(Day 026)本来就这样设计,只是 profiler 当时放错地方。

## 2 · 心智模型

### 类比:换大脑不换身体

人换大脑:记忆丢失。换身体:记忆保留。

DLL reload 是"换代码"(大脑)。如果 profiler state 跟着 DLL 走,记忆丢失。如果 state 留在 host(身体),记忆保留。

设计:**state 留 host,代码 reload 时 state 不动**。

### 2.1 三明治架构回顾

```
Platform Layer (host, EXE)
  ├─ Window / Input / Audio
  ├─ Renderer
  ├─ Profiler (← 应该在这)
  └─ Loads Game DLL
                ↓
                Game DLL (reloadable)
                  ├─ game_update_and_render
                  └─ 用 host 提供的 services
```

DLL 通过函数指针调 host 的 service(host 提供 `record_profile_event(name: &str, ns: u64)`)。

### 2.2 字符串所有权

```rust
// 错误:引用 DLL 的 &'static str
struct ProfileEvent {
    name: &'static str,  // ← DLL 卸载后悬空
    ns: u64,
}

// 正确:host 拥有字符串
struct ProfileEvent {
    name: Box<str>,  // ← host heap 拥有,DLL 卸载不影响
    ns: u64,
}
```

或更高效:`Rc<str>` 共享,多事件同名只一份字符串。

### 2.3 hot reload 流程

```
1. 改代码 → cargo build
2. 编译出 game.dll(或 .so)
3. host 检测文件变化(stat mtime)
4. host 卸载旧 DLL(libloading::Library::close)
5. host 加载新 DLL(libloading::Library::new)
6. host 拿函数指针(lib.get(...))
7. 继续主循环
```

Step 4 卸载时,DLL 内存释放。如果 profiler 引用 DLL 字符串,悬空。

### 2.4 GUID 跨 reload 一致性

Day 250 的 GUID:

```rust
let guid = Guid::from_location(name, file!(), line!());
```

`file!()` 和 `line!()` 编译时填入,**同一代码行下次编译 GUID 相同**(假设代码没动)。

但如果改了代码:

- 行号变了 → GUID 变了
- 改名字 → GUID 变了

这是预期。profiler 知道"上次 game_update"和"本次 game_update"是不同事件(因为代码改了),不混。

### 2.5 host 提供的 service

DLL 通过"shared services" struct 调 host:

```rust
// shared.h(DLL 和 host 都 include)
#[repr(C)]
pub struct PlatformServices {
    pub record_profile_event: extern "C" fn(name: *const u8, len: usize, ns: u64),
    pub get_debug_value: extern "C" fn(guid: u64) -> f32,
    pub set_debug_value: extern "C" fn(guid: u64, value: f32),
    pub log: extern "C" fn(level: u32, msg: *const u8, len: usize),
    // ...
}

// host 实现
extern "C" fn record_profile_event(name: *const u8, len: usize, ns: u64) {
    let name = unsafe { std::slice::from_raw_parts(name, len) };
    let name = std::str::from_utf8(name).unwrap();
    PROFILER.lock().record(name, ns);  // profiler 在 host
}

// DLL 调用
fn game_update(services: &PlatformServices) {
    let start = Instant::now();
    // ... 工作 ...
    let ns = start.elapsed().as_nanos() as u64;
    (services.record_profile_event)("game_update".as_ptr(), 11, ns);
}
```

**关键**:`services` 是 host 提供的,DLL 调函数指针。函数指针指向 host 代码,**reload DLL 不影响 host 函数**。

### 2.6 Rust 实际简化

Rust 的 hot reload 不像 C 那么"native"。常用方案:

- **cargo watch + 重启进程** —— 不是真 hot reload
- **abi_stable + libloading** —— 真 hot reload,但有 ABI 限制
- **dynamic reload crate** —— 包装 libloading

跟 HH 学简化:profiler 在主二进制(`src/main.rs`),不在 reload 模块(`lib.rs`)。reload 模块只发"事件"(纯数据),不持 state。

---

**总结**:Day 258 修复跨 reload 的 profiler。state 放 host,DLL 通过 service 函数指针通信。字符串所有权在 host。GUID 跨 reload 一致(确定性 hash)。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上 DLL 是 `.so`(shared object),用 `dlopen` / `dlsym`:

```rust
use libloading::{Library, Symbol};

let lib = unsafe { Library::new("target/release/libgame.so") }?;
let game_update: Symbol<unsafe extern "C" fn(...) -> ...> =
    unsafe { lib.get(b"game_update") }?;

// reload

let lib = unsafe { Library::new("target/release/libgame.so") }?;
```

`dlopen` 加载,`dlclose` 卸载。如果还有指针指向 DLL 内的符号,卸载后访问 → segfault。

## 5 · 对照与变奏

### DLL reload vs 进程重启

| | DLL reload | 进程重启 |
|---|---|---|
| 启动开销 | < 1s | 5-10s |
| State 保留 | 是(设计好) | 否 |
| 内存泄漏 | 累积 | 清零 |
| 实现复杂度 | 高 | 低 |
| 调试难度 | 高(reload 后 buggy) | 低 |

跟 HH 用 DLL reload,开发期提速。

### Hot reload 的 state preservation 谱系

| 级别 | 保留什么 | 实现 |
|---|---|---|
| L0 全重启 | 无 | exit + restart |
| L1 代码 reload | state 在 host | Casey 风格 |
| L2 数据持久化 | state + 选中 / camera 位置 | 序列化 |
| L3 完整 | 全部 + undo history | 复杂(Unity Domain Reload) |

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 hot reload 后,&'static str 引用可能悬空?

**参考解答**:`&'static str` 在 Rust 里通常指程序生命周期的字符串字面量。但编译进 DLL 的字面量存在 DLL 的 `.rodata` 段。当 DLL 卸载(`dlclose`),那块内存释放。如果 host 还持有指向那段内存的 `&'static str`,访问就是 segfault。

Rust 类型系统不知道"DLL 卸载",认为 `'static` 真的一生有效。这是 unsafe 行为,程序员要保证不在卸载后访问。

修复:跨 DLL 边界**复制字符串**到 host 内存(host 拥有 Box<str> 或 String)。

### Lv2 · 动手实践

**题**:写一个简单 hot reload 系统:host 加载 .so,调 `print_message()`。修改 .so 不停 host 看新版本生效。完成标准:改 print_message 内容,host 重新加载,下次调用打印新内容。

**参考解答**:

```rust
// Cargo.toml:
// [workspace]
// members = ["host", "lib"]

// lib/Cargo.toml:
// [lib]
// crate-type = ["cdylib"]
//
// [dependencies]

// lib/src/lib.rs:
#[no_mangle]
pub extern "C" fn print_message() {
    println!("Hello from lib v1");
}

// host/Cargo.toml:
// [dependencies]
// libloading = "0.8"

// host/src/main.rs:
use libloading::{Library, Symbol};
use std::time::SystemTime;

fn main() {
    let mut last_mtime = None;

    loop {
        let mtime = std::fs::metadata("target/release/liblib.so")
            .unwrap().modified().unwrap();

        if Some(mtime) != last_mtime {
            // 重载
            println!("=== Reloading lib ===");
            unsafe {
                let lib = Library::new("target/release/liblib.so").unwrap();
                let print_message: Symbol<extern "C" fn()> =
                    lib.get(b"print_message").unwrap();
                print_message();
                // 注意:lib drop 时 dlclose
                std::mem::forget(lib);  // 不 close,或保持 lib 不 drop
            }
            last_mtime = Some(mtime);
        }

        std::thread::sleep(std::time::Duration::from_secs(1));
    }
}
```

测试:跑 host,改 lib 的 print 内容,cargo build,host 自动检测 + 重载 + 调新版本。

## 8 · Rust / Arch 落地代码

### Rust 跨 reload profiler

```rust
use std::sync::Mutex;
use std::collections::HashMap;
use std::time::Instant;

// === HOST 端(state 持久) ===
lazy_static::lazy_static! {
    static ref PROFILER: Mutex<Profiler> = Mutex::new(Profiler::new());
}

pub struct Profiler {
    events: Vec<ProfileEvent>,
}

pub struct ProfileEvent {
    pub name: Box<str>,  // host 拥有
    pub ns: u64,
    pub timestamp: Instant,
}

impl Profiler {
    fn new() -> Self { Self { events: vec![] } }

    fn record(&mut self, name: &str, ns: u64) {
        self.events.push(ProfileEvent {
            name: Box::from(name),  // 复制到 host
            ns,
            timestamp: Instant::now(),
        });
    }

    fn print(&self) {
        let mut totals: HashMap<&str, u64> = HashMap::new();
        let mut counts: HashMap<&str, u32> = HashMap::new();
        for e in &self.events {
            *totals.entry(&e.name).or_default() += e.ns;
            *counts.entry(&e.name).or_default() += 1;
        }
        for (name, total) in totals.iter() {
            let avg = *total as f64 / counts[name] as f64 / 1e6;
            println!("{}: {:.2}ms avg ({} 次)", name, avg, counts[name]);
        }
    }
}

// === HOST 提供的 service(DLL 通过函数指针调) ===
#[no_mangle]
pub extern "C" fn record_profile_event(name: *const u8, len: usize, ns: u64) {
    let name = unsafe { std::slice::from_raw_parts(name, len) };
    let name = std::str::from_utf8(name).unwrap_or("<invalid>");
    PROFILER.lock().unwrap().record(name, ns);
}

// === DLL 端(reloadable) ===
// 用函数指针,不持 state
pub fn game_update(record: extern "C" fn(*const u8, usize, u64)) {
    let start = Instant::now();
    // ... 工作 ...
    std::thread::sleep(std::time::Duration::from_millis(1));
    let ns = start.elapsed().as_nanos() as u64;

    let name = "game_update";
    (record)(name.as_ptr(), name.len(), ns);
}

// === HOST 主循环 ===
fn main() {
    // 模拟多次 reload + 调用
    for _ in 0..5 {
        game_update(record_profile_event);
    }

    println!("=== Profiler (跨 reload 一致) ===");
    PROFILER.lock().unwrap().print();
}
```

输出:

```
=== Profiler (跨 reload 一致) ===
game_update: 1.05ms avg (5 次)
```

字符串 `Box::from(name)` 复制到 host,DLL 卸载不影响。

## 10 · 深入:跨代码重载的 profiler 修复

casey 在 day258 修复跨代码重载(hot reload)的 profiler bug——HH 项目的标志性功能。

### 10.1 HH 的 hot reload 架构

HH 用三明治架构(platform → game → platform):

- **platform layer**:稳定,启动时加载,从不重载
- **game layer**:动态,可热重载(.dll / .so / .dylib)

```rust
// platform.cpp
int main() {
    void* game_dll = dlopen("game.so", RTLD_NOW);
    auto update_and_render = dlsym(game_dll, "update_and_render");
    
    while (running) {
        update_and_render(&state);
        if (state.hot_reload_requested) {
            dlclose(game_dll);
            game_dll = dlopen("game.so", RTLD_NOW);  // 重新加载
            update_and_render = dlsym(game_dll, "update_and_render");
        }
    }
}
```

开发者改 game 代码,编译后游戏自动重载,几秒内看到效果。

### 10.2 profiler 跨重载的 bug

profiler state 在 game layer,但跨重载时丢失:

```rust
// game.rs(被 hot reload)
static mut PROFILER_STATE: ProfilerState = ProfilerState::new();

// 重载后,PROFILER_STATE 重置
// 之前的 profile 数据丢失
```

casey 在 day258 修复:**profiler state 移到 platform layer**。

```rust
// platform.cpp(从不重载)
ProfilerState profiler_state;

extern "C" void profiler_begin_event(const char* name) {
    profiler_state.begin(name);
}
```

game layer 通过函数指针调用 platform 的 profiler,数据在 platform 持久保存。

### 10.3 跨层通信

跨 platform / game layer 的 API:

```rust
// platform.rs
pub struct PlatformApi {
    pub profiler_begin: extern "C" fn(name: *const u8),
    pub profiler_end: extern "C" fn(),
    pub allocator: extern "C" fn(size: usize) -> *mut u8,
    // ...
}

// game.rs(被 hot reload)
pub fn update_and_render(state: &mut State, platform: &PlatformApi) {
    (platform.profiler_begin)(b"update\0".as_ptr());
    // ...
    (platform.profiler_end)();
}
```

game 通过 platform 提供的函数指针访问持久状态。

### 10.4 Rust 翻译版的实现

```rust
// platform crate
pub struct PlatformApi {
    pub profiler: &'static ProfilerState,
}

static PROFILER: ProfilerState = ProfilerState::new();

#[no_mangle]
pub extern "C" fn get_platform_api() -> PlatformApi {
    PlatformApi { profiler: &PROFILER }
}

// game crate(被 hot reload)
#[no_mangle]
pub extern "C" fn update_and_render(state: &mut State, platform: &PlatformApi) {
    let _g = platform.profiler.scope("update");
    // ...
}
```

Rust 的 extern "C" + static 让 hot reload 安全。

### 10.5 hot reload 的限制

hot reload 不是万能:

- **数据结构变化**:state 内存布局变,旧 state 不兼容
- **API 变化**:platform API 变,game 要适配
- **全局状态重置**:static 变量重置,profiler / debug state 丢失

casey HH day258 处理第三点。

### 10.6 工业级 hot reload

商业项目的 hot reload:

- **Unity**:C# hot reload(script 改动即时生效)
- **Unreal**:Hot Reload Module(C++ 部分支持)
- **bevy**:bevy_inspector + reload(Cargo workspace)
