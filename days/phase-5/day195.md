# Day 195 · 实现交互式树视图

> Day 194 把变量组织成树,但只是数据结构。今天 Casey 给树加交互:点击节点 expand / collapse、双击编辑值、右键 context menu。

## 0 · 为什么要有这一天

树光显示不够,要能**操作**:

- 点击 expand 图标 → 折叠 / 展开
- 点击变量值 → 编辑(数字键盘输入)
- 右键 → context menu(reset / copy / paste)
- 拖拽变量 → 拖到图表上实时显示

每个交互都要:

1. **检测鼠标事件**(down / up / move / 双击)
2. **命中测试**(鼠标在哪个节点上)
3. **更新状态**(expand / 编辑值)
4. **重绘**

这是 immediate-mode UI 的精髓:**所有交互每帧重算**。

今天 Casey 实现最基础的:点击 expand / collapse + 点击编辑值。

心理锚点:看完今天,你能写出"双击文字进入编辑模式"的 immediate-mode 模式。

## 1 · Casey 今天做了什么

Casey 给 tree view 加交互:

1. expand 状态存在 TreeState
2. 每个节点 draw 时检查命中
3. 鼠标 left button down + 命中 expand → toggle
4. 鼠标 left button down + 命中变量值 → 进入 edit mode
5. edit mode 时键盘输入改值

## 2 · 心智模型

### 2.0 Immediate-mode tree view 的核心难点

retained-mode tree(Qt / WPF)每个节点是对象,有 expanded 字段。点击改对象状态,下次重画自动反映。

immediate-mode 没有持久对象,**每帧重建**。怎么记 expanded 状态?**外部 state**:

```rust
struct UiState {
    expanded: HashSet<String>,  // path -> is_expanded
}

fn tree_node(ui: &mut Ui, state: &mut UiState, path: &str, label: &str) -> bool {
    let is_expanded = state.expanded.contains(path);
    let clicked = ui.clickable_label(label, /*with_expand_icon=*/ true);

    if clicked {
        if is_expanded { state.expanded.remove(path); }
        else { state.expanded.insert(path.to_string()); }
    }

    is_expanded
}

// 用法
fn draw_tree(ui: &mut Ui, state: &mut UiState, node: &Node, parent_path: &str) {
    for (name, child) in &node.children {
        let path = format!("{}/{}", parent_path, name);
        if tree_node(ui, state, &path, name) {
            draw_tree(ui, state, child, &path);  // 递归子树
        }
    }
}
```

state 用 `&mut UiState` 显式传递,跨帧保留。**path 字符串作为唯一 ID**——稳定,跨帧一致。

### 2.0.1 双击编辑的实现

双击需要**边沿检测**:第二次 click 在第一次后 < 300ms 算双击。

```rust
struct ClickState {
    last_click_time: Option<Instant>,
    last_click_path: Option<String>,
}

fn is_double_click(state: &mut ClickState, path: &str, now: Instant) -> bool {
    if let (Some(t), Some(p)) = (state.last_click_time, &state.last_click_path) {
        if p == path && now.duration_since(t) < Duration::from_millis(300) {
            state.last_click_time = None;  // 重置
            return true;
        }
    }
    state.last_click_time = Some(now);
    state.last_click_path = Some(path.to_string());
    false
}
```

300ms 是工业标准(Windows / macOS 默认)。游戏 UI 可能更短(150ms),因为玩家反应快。

### 2.0.2 数字输入框

点击值 → 进入编辑模式 → 键盘输入 → Enter 确认。

```rust
struct EditState {
    editing_path: Option<String>,
    buffer: String,
}

fn edit_value(ui: &mut Ui, state: &mut EditState, path: &str, value: &mut f32) {
    if let Some(p) = &state.editing_path {
        if p == path {
            // 编辑模式
            for c in &ui.typed_chars {
                state.buffer.push(*c);
            }
            if ui.enter_pressed {
                if let Ok(v) = state.buffer.parse() {
                    *value = v;
                }
                state.editing_path = None;
            }
            ui.text_input(&state.buffer);
            return;
        }
    }
    // 显示模式
    if ui.double_click_label(&format!("{}", value)) {
        state.editing_path = Some(path.to_string());
        state.buffer = format!("{}", value);
    }
}
```

state 用 `&mut EditState`,跨帧保留 editing 状态。

### 2.0.3 context menu 实现

右键点击变量 → 弹 menu(reset / copy / paste)。

immediate-mode context menu:

```rust
struct ContextMenuState {
    target_path: Option<String>,
    menu_pos: Option<(i32, i32)>,
}

fn draw_context_menu(ui: &mut Ui, state: &mut ContextMenuState) {
    if let (Some(path), Some(pos)) = (&state.target_path, state.menu_pos) {
        // 弹 menu
        if ui.menu_item_at(pos, "Reset to default") {
            reset_var(path);
            state.target_path = None;
        }
        if ui.menu_item_at(pos, "Copy value") {
            copy_to_clipboard(get_var(path));
            state.target_path = None;
        }
        // 点击外部关闭
        if ui.mouse_clicked_outside_menu {
            state.target_path = None;
        }
    }
}
```

每次右键,设 target_path,下一帧渲染时弹 menu。

### 2.1 鼠标事件追踪

winit 鼠标事件:

```rust
enum Event {
    MouseInput { state: Pressed/Released, button: Left/Right/Middle },
    CursorMoved { x, y },
    KeyboardInput { ... },
}
```

主循环维护"鼠标状态":

```rust
pub struct MouseState {
    pub x: f32,
    pub y: f32,
    pub left_pressed: bool,    // 当前 down?
    pub left_just_pressed: bool,  // 这一帧刚 down?
    pub left_just_released: bool,
    pub prev_left_pressed: bool,
}

impl MouseState {
    pub fn update(&mut self) {
        self.left_just_pressed = self.left_pressed && !self.prev_left_pressed;
        self.left_just_released = !self.left_pressed && self.prev_left_pressed;
        self.prev_left_pressed = self.left_pressed;
    }
}
```

每帧结束调 `update()`。这样任何代码都能查 `just_pressed`(瞬时事件)和 `pressed`(持续状态)。

### 2.2 命中测试

```rust
fn is_mouse_in_rect(mouse: &MouseState, x: f32, y: f32, w: f32, h: f32) -> bool {
    mouse.x >= x && mouse.x < x + w
        && mouse.y >= y && mouse.y < y + h
}
```

### 2.3 expand/collapse 交互

```rust
fn draw_tree_node(
    ui: &mut Ui, mouse: &MouseState, tree_state: &mut TreeState,
    path: &str, node: &DebugNode, x: f32, y: &mut f32,
) {
    // expand 三角形
    let expand_x = x;
    let expand_size = 12.0;
    let is_expanded = tree_state.is_expanded(path);

    draw_triangle(ui, expand_x, *y, expand_size, is_expanded);

    if mouse.left_just_pressed && is_mouse_in_rect(mouse, expand_x, *y, expand_size, expand_size) {
        tree_state.toggle(path);
    }

    // 名字
    draw_text(ui, node.name, expand_x + expand_size + 4, *y);
    *y += 16.0;

    if is_expanded {
        for (child_name, child) in &node.children {
            let child_path = format!("{}/{}", path, child_name);
            draw_tree_node(ui, mouse, tree_state, &child_path, child, x + 16, y);
        }
    }
}
```

### 2.4 编辑模式

```rust
pub struct EditState {
    pub editing: Option<(u64 /* guid */, String /* buffer */)>,
}

fn draw_debug_value(
    ui: &mut Ui, mouse: &MouseState, edit: &mut EditState,
    guid: u64, value: &mut DebugValue, x: f32, y: f32,
) {
    let display = match value { DebugValue::Float(f) => format!("{:.2}", f), /* ... */ };

    let in_edit = edit.editing.as_ref().map(|(g, _)| *g == guid).unwrap_or(false);

    if in_edit {
        let (_, buf) = edit.editing.as_mut().unwrap();
        draw_text(ui, buf, x, y);
        // 鼠标点击别处或 Enter → 确认
        if mouse.left_just_pressed && !is_mouse_in_rect(mouse, x, y, 100, 16) {
            // 解析 buf
            if let Ok(f) = buf.parse::<f32>() {
                *value = DebugValue::Float(f);
            }
            edit.editing = None;
        }
        // TODO: 处理键盘输入
    } else {
        draw_text(ui, &display, x, y);
        if mouse.left_just_pressed && is_mouse_in_rect(mouse, x, y, 100, 16) {
            edit.editing = Some((guid, display.clone()));
        }
    }
}
```

## 3 · 四域深入

### 3.1 · 游戏编程视角

游戏 UI 的"focused element"概念:

- 一个时刻只有一个 element focused(接收键盘)
- 点击 element → 它 focused
- 点击别处 → 它 unfocused
- Tab 键 → 切换 focus

immediate-mode UI 的 focus 用 ID hash 管理。

### 3.2 · Rust 生态视角

Rust UI 库的 input handling:

- egui:`ctx.input()` 返回 InputState,有 keys / mouse / text
- iced:事件订阅 + update 模式
- crossterm / winit:跨平台 input 抽象

### 3.3 · immediate-mode 的"focus 持久化"

immediate-mode 每帧重算,但 focus / edit buffer 要"跨帧保留"。怎么存?

- 一个全局 `FocusState`(或叫 `InteractionState`)
- 用 element ID 作为 key
- 每帧 render 时 update

## 5 · 对照与变奏

**Tree view 的工业实现**:

- **VS Code File Explorer**:retained-mode,使用 tree-data-structure
- **Unity Hierarchy**:retained-mode,带 prefab 引用
- **Unreal World Outliner**:retained-mode,带 actor 引用
- **Inspector**:选中对象的字段,immediate-mode 风格
- **egui Tree**:immediate-mode,简洁

不同模式的 trade-off:

| 模式 | 状态管理 | 性能 | 适合 |
|---|---|---|---|
| retained | 控件对象持久 | 慢(对象多) | 桌面应用 |
| immediate | 每帧重建 | 快(数据驱动) | 游戏 / debug |

Casey 选 immediate-mode,因为游戏数据每帧变,retained 要同步太麻烦。

### Tree view 的虚拟化

10 万个节点的 tree,如果都画出来,UI 渲染几秒。**虚拟化**(virtualization):只画可见部分(展开 + 在视口内)。

```rust
fn draw_tree_virtualized(ui: &mut Ui, tree: &Tree, scroll: i32, viewport_h: i32) {
    let visible_start = scroll;
    let visible_end = scroll + viewport_h;
    let mut y = 0;
    for node in tree.iter_dfs() {
        if y + ROW_H < visible_start { y += ROW_H; continue; }
        if y > visible_end { break; }
        draw_node(ui, node, y);
        y += ROW_H;
    }
}
```

VS Code / IDE 的 file explorer 都虚拟化(项目几万文件仍流畅)。Casey day 195 不虚拟化(假设变量 < 100),Day 200+ 可能加。

### 与 Outliner / Hierarchy 的对比

游戏 editor 的 **Outliner**(Unreal)/ **Hierarchy**(Unity)是 tree view 的变种:

- 每个节点是 actor / GameObject(不只是变量)
- 拖拽重排父子关系
- 显示 visibility / lock icon
- 多选 + 批量操作

Casey 的 debug tree 是 Outliner 简化版——只显示 + 编辑值,不支持拖拽。但**核心数据结构相同**(树 + 鼠标交互)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:`pressed` 和 `just_pressed` 的差别?为什么 immediate-mode UI 同时要这两个?

**参考解答**:
- `pressed`:**当前状态**——鼠标左键现在被按住?
- `just_pressed`:**这一帧**——左键在上一帧 up、本帧 down(边沿事件)
- immediate-mode UI 每帧重算,不能依赖事件队列
- 按钮 click:`just_pressed`(瞬时)
- 拖拽:`pressed`(持续)
- 两者都要,API 设计上保留

### Lv2 · 动手实践

**题**:写一个最小交互 demo:
- 一个矩形
- 鼠标 click 它 → 矩形 toggle 颜色(白/黑)
- 用 stdin 模拟鼠标事件

**参考解答**:

```rust
use std::io::{self, BufRead};

fn main() {
    let mut color = 0;  // 0 = 黑,1 = 白
    let mut prev_click = false;

    let stdin = io::stdin();
    for line in stdin.lock().lines() {
        let line = line.unwrap();
        let parts: Vec<&str> = line.split_whitespace().collect();
        if parts.len() < 3 { continue; }
        let mx: i32 = parts[0].parse().unwrap_or(0);
        let my: i32 = parts[1].parse().unwrap_or(0);
        let click: bool = parts[2] == "1";

        let just_clicked = click && !prev_click;
        prev_click = click;

        let in_rect = mx >= 10 && mx < 30 && my >= 5 && my < 15;

        if just_clicked && in_rect {
            color = 1 - color;
            println!("toggled to {}", if color == 1 { "white" } else { "black" });
        } else {
            println!("state: {} (mouse at {}, {})", if color == 1 { "white" } else { "black" }, mx, my);
        }
    }
}
```

测试:`echo "20 10 1\n20 10 0\n20 10 1\n0 0 0\n20 10 1" | cargo run`
