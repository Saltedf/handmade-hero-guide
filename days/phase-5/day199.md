# Day 199 · 复用调试交互

> Day 195-198 写了 click / drag / hover 等交互。今天 Casey 把这些抽象成**可复用 trait**,任何 widget 都能 plug in。

## 0 · 为什么要有这一天

回顾代码:

- button 有 click 逻辑
- slider 有 drag 逻辑
- tree node 有 expand + drag 逻辑
- checkbox 有 toggle 逻辑

每个 widget 都重写交互逻辑,代码重复。OOP 的解法是 **继承**(基类 Widget,派生 Button)。Rust 没有 inheritance,但能用 **trait + composition**。

今天 Casey 设计:

1. `Interaction` trait:定义"如何处理鼠标"
2. 不同 widget 实现 trait(button 是 Clickable,slider 是 Draggable)
3. UI 框架统一调 trait 方法

心理锚点:看完今天,你能用 Rust trait 设计可扩展 UI 系统。

## 1 · Casey 今天做了什么

Casey 抽象交互:

1. 定义 `trait Clickable { fn on_click(&mut self); }`
2. 定义 `trait Draggable { fn on_drag(&mut self, dx, dy); }`
3. 每个 widget 实现需要的 trait
4. UI 框架主循环遍历 widget,调用 trait method

## 2 · 心智模型

### 2.0 OOP inheritance vs Rust trait composition

OOP 经典模式:Widget 基类有 click / hover / drag 通用方法,Button / Slider / Tree 派生并特化:

```cpp
// C++
class Widget {
public:
    bool hovered() const;
    bool clicked();
    virtual void draw() = 0;  // 派生类实现
};

class Button : public Widget {
    void draw() override { /* button 特化 */ }
};
```

Rust 没有 inheritance,**用 trait composition**:

```rust
trait Widget {
    fn rect(&self) -> Rect;
    fn draw(&mut self, ui: &mut Ui);
}

trait Clickable: Widget {
    fn clicked(&self, ui: &Ui) -> bool {
        ui.is_hovered(self.rect()) && ui.mouse_just_released(MouseButton::Left)
    }
}

struct Button { rect: Rect, label: String }

impl Widget for Button {
    fn rect(&self) -> Rect { self.rect }
    fn draw(&mut self, ui: &mut Ui) { /* draw button */ }
}

impl Clickable for Button {}  // 默认实现,自动获得 clicked()
```

trait `Clickable: Widget` 要求实现 Widget 才能实现 Clickable,并提供 `clicked()` 默认实现。Button 只需 `impl Clickable for Button {}`(空),继承默认行为。

### 2.0.1 组合优于继承(Composition over Inheritance)

GoF 1994 年的设计模式书第一原则:**组合优于继承**。继承是 IS-A 关系(Button IS-A Widget),组合是 HAS-A(Button HAS-A ClickBehavior)。

Rust 强制组合:
- 没有 inheritance,只有 trait
- 字段不能继承(只能组合)
- 行为可以"借"(trait 方法)

这种限制让 Rust 代码**更模块化**——每个职责一个 trait,自由组合。

```rust
struct Button {
    rect: Rect,
    label: String,
    click_behavior: ClickBehavior,  // 组合
    drag_behavior: Option<DragBehavior>,
}
```

### 2.0.2立即模式的 widget trait

Casey 的 day 199 widget trait:

```rust
trait Widget {
    fn draw(&mut self, ui: &mut Ui, ctx: &Context);
}

trait Clickable {
    fn clicked(&self, ui: &Ui) -> bool;
}

trait Draggable {
    fn drag_start(&self, ui: &Ui) -> bool;
    fn dragging(&self, ui: &Ui) -> Option<(i32, i32)>;
    fn dropped(&self, ui: &Ui) -> bool;
}

trait Editable {
    fn start_edit(&mut self);
    fn commit_edit(&mut self) -> String;
}
```

每个职责一个 trait。Button 实现 Widget + Clickable。Slider 实现 Widget + Draggable。Tree node 实现 Widget + Clickable + Draggable + Editable。

### 2.0.3 generic widget vs trait object

两种 trait 用法:

```rust
// Generic(编译期 dispatch,0 开销)
fn draw_widget<W: Widget>(w: &mut W, ui: &mut Ui) {
    w.draw(ui);
}

// Trait object(运行时 dispatch,vtable)
fn draw_widget(w: &mut dyn Widget, ui: &mut Ui) {
    w.draw(ui);
}
```

generic 快但代码膨胀(每种类型生成一份)。trait object 慢(几十 cycle / call)但二进制小。

immediate-mode UI 通常 generic——编译期 monomorphize 所有 widget 类型,运行时 0 dispatch。代价:编译时间长。Casey 选这条。

## 3 · 四域深入

### 类比:乐高积木的标准接口

乐高积木每块顶部 4 个圆凸起,底部 4 个圆孔。**接口统一**,任何积木都能拼任何积木。

UI widget 的交互一样:**trait 是接口**,任何 widget 都能 plug 进框架。

### 2.1 trait 设计

```rust
pub trait Widget {
    fn draw(&self, ui: &mut Ui);
    fn handle_input(&mut self, ui: &mut Ui);
    fn bounding_box(&self) -> (f32, f32, f32, f32);  // x, y, w, h
}

pub trait Clickable: Widget {
    fn is_clicked(&self, ui: &Ui) -> bool {
        let (x, y, w, h) = self.bounding_box();
        ui.mouse.left_just_pressed
            && ui.mouse.x >= x && ui.mouse.x < x + w
            && ui.mouse.y >= y && ui.mouse.y < y + h
    }
}

pub trait Draggable: Widget {
    fn is_being_dragged(&self, ui: &Ui) -> bool;
}
```

**Rust 注释**:
- `trait Widget` — 基础 widget 接口
- `trait Clickable: Widget` — Clickable 要求 super-trait Widget(类似继承)
- 默认方法 `fn is_clicked(&self, ui: &Ui) -> bool` — 子类不需要重写,默认命中测试

### 2.2 widget 实现

```rust
pub struct Button {
    pub label: String,
    pub x: f32, pub y: f32, pub w: f32, pub h: f32,
}

impl Widget for Button {
    fn draw(&self, ui: &mut Ui) {
        draw_rect(self.x, self.y, self.w, self.h, 0xFF444444);
        draw_text(&self.label, self.x + 4, self.y + 4);
    }
    fn handle_input(&mut self, ui: &mut Ui) {
        // 不需要,button 用 is_clicked
    }
    fn bounding_box(&self) -> (f32, f32, f32, f32) {
        (self.x, self.y, self.w, self.h)
    }
}

impl Clickable for Button {}  // 用默认实现
```

### 2.3 使用

```rust
let mut btn = Button { label: "Save".into(), x: 10.0, y: 10.0, w: 80.0, h: 20.0 };
btn.draw(&mut ui);
if btn.is_clicked(&ui) {
    println!("Save clicked");
}
```

### 2.4 slider 实现

```rust
pub struct Slider {
    pub label: String,
    pub x: f32, pub y: f32, pub w: f32, pub h: f32,
    pub min: f32, pub max: f32,
    pub value: f32,
    pub dragging: bool,
}

impl Widget for Slider {
    fn draw(&self, ui: &mut Ui) { /* */ }
    fn handle_input(&mut self, ui: &mut Ui) {
        let (x, y, w, h) = self.bounding_box();
        let in_rect = ui.mouse.x >= x && ui.mouse.x < x + w
                   && ui.mouse.y >= y && ui.mouse.y < y + h;
        if ui.mouse.left_just_pressed && in_rect {
            self.dragging = true;
        }
        if !ui.mouse.left_pressed {
            self.dragging = false;
        }
        if self.dragging {
            let rel = (ui.mouse.x - x) / w;
            self.value = self.min + rel.clamp(0.0, 1.0) * (self.max - self.min);
        }
    }
    fn bounding_box(&self) -> (f32, f32, f32, f32) {
        (self.x, self.y, self.w, self.h)
    }
}

impl Draggable for Slider {
    fn is_being_dragged(&self, _ui: &Ui) -> bool { self.dragging }
}
```

### 2.5 UI 框架主循环

```rust
struct Framework {
    widgets: Vec<Box<dyn Widget>>,
}

impl Framework {
    fn run_frame(&mut self, ui: &mut Ui) {
        for w in &mut self.widgets {
            w.handle_input(ui);
        }
        for w in &self.widgets {
            w.draw(ui);
        }
    }
}
```

`Box<dyn Widget>` 是 trait object,允许异构集合。代价:vtable 间接调用(每次 method call 多一次访存)。但 UI 不密集,这点开销可接受。


### 3.1 · Rust 生态视角

Rust trait 的两种用法:

- **静态分发**(impl Trait / 泛型):编译期已知类型,inline,快
- **动态分发**(dyn Trait):运行期多态,有 vtable

UI 框架用 dyn,因为 widget 类型异构(各种 widget 混在一个 list)。

```rust
// 静态(泛型)
fn draw<W: Widget>(w: &W) { w.draw(); }

// 动态(trait object)
fn draw(w: &dyn Widget) { w.draw(); }
```

### 3.2 · vs OOP 继承

OOP(Java / C++)用继承:

```java
abstract class Widget {
    abstract void draw();
    boolean isClicked() { /* */ }
}
class Button extends Widget { void draw() { /* */ } }
```

Rust 用 trait + composition:

```rust
trait Widget { fn draw(&self); }
trait Clickable: Widget { /* default is_clicked */ }
struct Button { ... }
impl Widget for Button { /* */ }
impl Clickable for Button {}
```

差别:
- Rust 无菱形继承问题
- Rust 数据和行为分离(struct 和 impl)
- Rust 显式(composition over inheritance)

### 3.3 · 工程实践

trait 抽象的好处:

- **新加 widget 不改老代码**(开闭原则)
- **测试性**(mock trait)
- **可替换**(egui / iced 替换底层)


### 3.4 · 🐧 Linux 系统编程视角

Linux 桌面环境的 UI 工具栈,从底到顶是这套:内核 evdev(输入事件)→ libinput(输入归一化)→ Wayland compositor / X server(display server)→ toolkit(GTK / Qt / egui)→ 应用。每一层都为 UI 加抽象。

**evdev** 是内核的输入事件接口。键盘、鼠标、触摸屏的硬件事件,通过 `/dev/input/event*` 字符设备暴露。每个事件是 `struct input_event`——时间戳、类型(EV_KEY / EV_ABS / EV_REL)、code(BTN_LEFT / ABS_X)、value(0/1/2)。用户态进程读这个字符设备流,拿到原始硬件事件。

```bash
# 看 evdev 设备
sudo pacman -S evtest
sudo evtest /dev/input/event0   # 看你鼠标的事件流
# 移动鼠标、点击,看 event 输出
```

**libinput** 抽象 evdev——它处理多个设备、做去抖动、合成 tap-to-click、trackpad gesture、acceleration profile。toolkit 不直接读 evdev,而是用 libinput,这样跨设备统一。Casey HH 不用 libinput,直接用 SDL 的抽象,SDL 内部在 Linux 用 libinput。

**Wayland** 是现代 Linux display server 协议(替代 X11)。Wayland 用 `wl_seat` 协议传递输入事件给应用。应用注册 listener,Wayland server 把 pointer/keyboard event 推过来。Casey HH 用 SDL/winit,SDL/winit 内部在 Wayland 上对接 wl_seat。

**X11** 是 1980 年代的 display server,至今仍广泛用。X11 协议复杂(XCreateWindow、XMapWindow、XSelectInput、XNextEvent...),但它有 30+ 年的稳定 ABI。Wayland 替代 X11 的进程已 10+ 年,但仍未完成。

**GTK / Qt** 是 Linux 桌面两大 UI toolkit。GTK 用 C 写但支持多语言绑定;Qt 用 C++ 写也有多语言绑定。它们的 widget 系统、layout 系统、事件分发,是工业级 UI 实现的范本。Rust 的 gtk-rs 给 GTK Rust 绑定,qt-rs 给 Qt 绑定。

**systemd / D-Bus / XDG** 是 Linux 桌面的服务/IPC/规范层。systemd 管理服务,D-Bus 跨进程通信,XDG 规范桌面环境目录(`/usr/share/applications`、`~/.config`)。这些都和 UI 间接相关——你的应用通过 D-Bus 通知桌面,通过 XDG 找到图标资源。

**clipboards(X11 selection)** 是 Linux 跨进程 UI 的经典案例。Linux 有三个 selection:PRIMARY(选中即复制,中键粘贴)、CLIPBOARD(Ctrl+C / Ctrl+V)、SECONDARY(几乎没人用)。每个 selection 当前 owner 是某个窗口,数据存在 owner 进程。复制时数据**不立刻传给 server**,而是 owner 记录"我有这个 selection",target 窗口粘贴时向 owner 请求数据——这种延迟传输(称为 "selection transfer protocol")避免大数据复制两次。

```bash
# X11 看剪贴板 owner
xclip -o -selection clipboard
xclip -o -selection primary

# Wayland
wl-paste --primary

# 看 X11 clients
xlsclients
```

**fontconfig / freetype / harfbuzz / pango / cairo / pixman** 是 Linux 字体和渲染栈。fontconfig 找字体文件(/usr/share/fonts、~/.fonts),freetype 解析 TTF/OTF,harfbuzz 做 text shaping(组合字符、连字、复杂脚本如阿拉伯文),pango 把文字组织成 layout,cairo/pixman 把 layout 渲染成像素。这套栈在 1990-2010 年代由 Red Hat 主导开发,是 Linux 桌面的基础设施。Rust 的 piet、cosmic-text、swash 是新一代实现,但要追平这套栈还要多年。

**XKB / evdev** 处理键盘布局。XKB(X Keyboard Extension)是 X11 的键盘映射系统——你按物理键 KeyA,XKB 根据 layout(US / Dvorak / 中文)把它映射到 keysym(XK_a),toolkit 把 keysym 映射到字符 "a"。Wayland 用 `xkbcommon` 库,逻辑相同。

### 3.5 · 🦀 Rust 生态视角

Rust UI 生态在 2024 年是个活跃领域,有几十个库,各有取舍。

**`egui`** 是 immediate-mode UI 的事实标准。每帧重新声明 widget,API 简洁:

```rust
egui::CentralPanel::default().show(&ctx, |ui| {
    ui.heading("Debug");
    ui.separator();
    ui.horizontal(|ui| {
        ui.label("Speed:");
        ui.add(egui::Slider::new(&mut speed, 0.0..=10.0));
    });
    if ui.button("Reset").clicked() {
        speed = 5.0;
    }
});
```

egui 适合 debug UI、工具 UI、原型 UI——上手快、代码短。劣势是不适合发布 UI(无 accessibility、不够精美)。

**`iced`** 是 Elm 风格 UI——你写 model + update + view 三件套,框架处理 message 流。Iced 用 taffy layout 引擎,支持完整 flexbox。Iced 适合应用 UI(类浏览器、编辑器),代码结构清晰但比 egui 啰嗦。

**`tauri`** 是 web UI + Rust 后端。前端用 React/Vue/Svelte,后端用 Rust,通过 IPC 通信。Tauri 适合桌面应用——你享受 web 生态(NPM、CSS、HTML),但 binary 小、性能好(不嵌 Chromium,用系统 webview)。

**`slint`** 是商业 UI 框架,有自己的 DSL。Slint DSL 类似 QML:

```slint
export component MainWindow inherits Window {
    property <float> speed;
    Text { text: "Speed: " + speed; }
    Slider { value <=> speed; }
}
```

Slint DSL 编译成 Rust 代码,运行时零开销。Slint 适合嵌入式 UI(汽车仪表盘、家电面板)——binary 小、启动快、内存可控。

**`bevy_ui`** 是 Bevy ECS 的 UI 子系统。每个 widget 是 Entity,有 Component,系统遍历 Component 树渲染。这是 Rust 风格的 ECS UI——数据导向、cache 友好。Bevy UI 适合游戏内 UI(HUD、菜单)。

**`druid`** 已停止维护,但它的理念——data + lens + widget——影响了后来的库。Lens 是函数式编程的概念,让"嵌套数据的访问"变成可组合的 first-class value。

**`taffy`** 是 layout 引擎,被多个 UI 库共用。taffy 实现 CSS flexbox + grid spec,纯 Rust,性能极高(每帧 layout 10000 节点 < 1ms)。这是 Rust 在 UI 底层的杀手锏——同样功能 C++ 实现(Chrome Blink layout)慢 2-3 倍。

**`cosmic-text`** 是 Rust 的 text shaping + 布局引擎,由 System76 开发(用于 Pop!_OS COSMIC 桌面)。它整合了 Rust 的字体库(rustybuzz、swash、ab_glyph),提供完整文字渲染流水线。这是 Rust 替代 pango/freetype/harfbuzz 的尝试,目前可用。

**Rust 的 trait object vs monomorphization**。UI 库要支持任意 widget 类型,有两种方式:`Box<dyn Widget>`(trait object,动态分发)或 `impl Widget`(泛型,单态化)。egui 用 trait object(灵活)、iced 用泛型(性能)、bevy 用 ECS Component(数据导向)。每种方案的取舍反映在 API 设计上。

**Rust UI 的 accessibility**。Linux 的 AT-SPI(Assistive Technology Service Provider Interface)是 accessibility 标准——screen reader(Orca)通过 AT-SPI 朗读 UI 元素。Rust 的 `accesskit` crate 提供 UI accessibility 抽象,让 UI 库一次实现、跨平台(Linux AT-SPI / Windows UIA / macOS AXUIElement)。egui / iced / druid 都接 accesskit,这是 Rust UI 生态对 accessibility 的认真承诺。

**Rust 的 async UI**。iced 用 async,handler 是 async fn,处理事件可 await。Rust 的 async/await 让 UI 不阻塞——长时间任务(网络请求、文件 IO)async,UI thread 继续响应。这是 Rust UI 比 JS UI 优势的地方——零成本异步,不是单线程事件循环。

### 3.7 · 🦀 Rust 生态视角(综合)

Rust UI 生态在 2024 年是个活跃领域,有几十个库,各有取舍。

**`egui`** 是 immediate-mode UI 的事实标准。每帧重新声明 widget,API 简洁:

```rust
egui::CentralPanel::default().show(&ctx, |ui| {
    ui.heading("Debug");
    ui.separator();
    ui.horizontal(|ui| {
        ui.label("Speed:");
        ui.add(egui::Slider::new(&mut speed, 0.0..=10.0));
    });
    if ui.button("Reset").clicked() {
        speed = 5.0;
    }
});
```

egui 适合 debug UI、工具 UI、原型 UI——上手快、代码短。劣势是不适合发布 UI(无 accessibility、不够精美)。

**`iced`** 是 Elm 风格 UI——你写 model + update + view 三件套,框架处理 message 流。Iced 用 taffy layout 引擎,支持完整 flexbox。Iced 适合应用 UI(类浏览器、编辑器),代码结构清晰但比 egui 啰嗦。

**`tauri`** 是 web UI + Rust 后端。前端用 React/Vue/Svelte,后端用 Rust,通过 IPC 通信。Tauri 适合桌面应用——你享受 web 生态(NPM、CSS、HTML),但 binary 小、性能好(不嵌 Chromium,用系统 webview)。

**`slint`** 是商业 UI 框架,有自己的 DSL。Slint DSL 类似 QML:

```slint
export component MainWindow inherits Window {
    property <float> speed;
    Text { text: "Speed: " + speed; }
    Slider { value <=> speed; }
}
```

Slint DSL 编译成 Rust 代码,运行时零开销。Slint 适合嵌入式 UI(汽车仪表盘、家电面板)——binary 小、启动快、内存可控。

**`bevy_ui`** 是 Bevy ECS 的 UI 子系统。每个 widget 是 Entity,有 Component,系统遍历 Component 树渲染。这是 Rust 风格的 ECS UI——数据导向、cache 友好。Bevy UI 适合游戏内 UI(HUD、菜单)。

**`druid`** 已停止维护,但它的理念——data + lens + widget——影响了后来的库。Lens 是函数式编程的概念,让"嵌套数据的访问"变成可组合的 first-class value。

**`taffy`** 是 layout 引擎,被多个 UI 库共用。taffy 实现 CSS flexbox + grid spec,纯 Rust,性能极高(每帧 layout 10000 节点 < 1ms)。这是 Rust 在 UI 底层的杀手锏——同样功能 C++ 实现(Chrome Blink layout)慢 2-3 倍。

**`cosmic-text`** 是 Rust 的 text shaping + 布局引擎,由 System76 开发(用于 Pop!_OS COSMIC 桌面)。它整合了 Rust 的字体库(rustybuzz、swash、ab_glyph),提供完整文字渲染流水线。这是 Rust 替代 pango/freetype/harfbuzz 的尝试,目前可用。

**Rust 的 trait object vs monomorphization**。UI 库要支持任意 widget 类型,有两种方式:`Box<dyn Widget>`(trait object,动态分发)或 `impl Widget`(泛型,单态化)。egui 用 trait object(灵活)、iced 用泛型(性能)、bevy 用 ECS Component(数据导向)。每种方案的取舍反映在 API 设计上。

**Rust UI 的 accessibility**。Linux 的 AT-SPI(Assistive Technology Service Provider Interface)是 accessibility 标准——screen reader(Orca)通过 AT-SPI 朗读 UI 元素。Rust 的 `accesskit` crate 提供 UI accessibility 抽象,让 UI 库一次实现、跨平台(Linux AT-SPI / Windows UIA / macOS AXUIElement)。egui / iced / druid 都接 accesskit,这是 Rust UI 生态对 accessibility 的认真承诺。

**Rust 的 async UI**。iced 用 async,handler 是 async fn,处理事件可 await。Rust 的 async/await 让 UI 不阻塞——长时间任务(网络请求、文件 IO)async,UI thread 继续响应。这是 Rust UI 比 JS UI 优势的地方——零成本异步,不是单线程事件循环。

## 4 · 认知地图

### 4.1 上级

- **Polymorphism** — 多态
- **Composition over Inheritance** — 组合优于继承
- **SOLID** — 开闭 / 里氏替换等设计原则

### 4.2 同级

| 多态方式 | 实现 |
|---|---|
| Rust trait + dyn | vtable |
| Rust trait + 泛型 | monomorphization |
| C++ virtual | vtable |
| Java interface | vtable |
| Go interface | struct + method implicit |

### 4.3 下级

- `trait Widget` — 基础接口
- `trait Clickable: Widget` — 扩展(super-trait)
- 默认方法 — 子类不重写就用
- `Box<dyn Widget>` — trait object

## 5 · 对照与变奏

**不同语言的 widget 抽象**:

| 语言 | 抽象机制 |
|---|---|
| C++ | virtual function + inheritance |
| Rust | trait + composition |
| Go | interface(structural typing) |
| Swift | protocol + extension |
| Java | interface + default method |
| Python | duck typing(magic method) |

Go 的 interface 最像 Rust trait,但 Go 用**structural typing**——只要 struct 有 interface 要求的方法,自动实现。Rust 要显式 `impl Trait for Type`,更严格。

### ECS 中的 widget

Bevy ECS 不用 widget 对象——所有 UI 是 **Component** 组合:

```rust
#[derive(Component)]
struct Button;

#[derive(Component)]
struct Hoverable;

#[derive(Component)]
struct Draggable;
```

system 处理所有带 Button + Hoverable 的 entity。比 trait composition 更数据驱动,但 boilerplate 多。

### React Hooks:函数式组合

React Hooks 是另一种抽象:

```jsx
function Button({ label, onClick }) {
    const [hovered, setHovered] = useState(false);
    return <button
        onMouseEnter={() => setHovered(true)}
        onMouseLeave={() => setHovered(false)}
        onClick={onClick}
        style={{ background: hovered ? 'blue' : 'gray' }}
    >{label}</button>;
}
```

`useState` / `useEffect` 是 hook 函数,组件用 hook 组合行为。函数式风格,无对象。和 Rust trait 不同但解决同样问题——**行为复用**。

## 6 · 关联 Day

**trait object 的代价**:

```rust
let widgets: Vec<Box<dyn Widget>> = vec![/* ... */];
for w in &widgets {
    w.draw();  // vtable 查找,~3ns
}
```

vtable 查找每次 ~3ns。1000 个 widget × 60fps = 180 μs。可接受。

如果性能关键,**泛型 + monomorphization** 0 开销:

```rust
fn draw_all<W: Widget>(widgets: &[W]) {
    for w in widgets { w.draw(); }  // 编译期 inline
}
```

但要求所有 widget 同类型,失去多态。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:Rust 的 `Box<dyn Widget>` 和 Java 的 `Widget` 引用差别?

**参考解答**:
- 都是 trait / interface 的运行期多态
- Java 引用是 GC 管理,无 ownership 概念
- `Box<dyn Widget>` 是 Rust 的"独占所有权 trait object",Box drop 时自动 free
- vtable 实现略不同(Java 的 vtable 在 object header,Rust 的 vtable 在 Box 里)
- 性能:Java JIT 可以 devirtualize,Rust 编译期 devirtualize 较弱

### Lv2 · 动手实践

**题**:实现 Widget trait + Clickable trait + 一个 Button 实现。

**参考解答**:

```rust
trait Widget {
    fn draw(&self);
    fn bbox(&self) -> (f32, f32, f32, f32);
}

trait Clickable: Widget {
    fn is_clicked(&self, mouse_x: f32, mouse_y: f32, just_pressed: bool) -> bool {
        let (x, y, w, h) = self.bbox();
        just_pressed
            && mouse_x >= x && mouse_x < x + w
            && mouse_y >= y && mouse_y < y + h
    }
}

struct Button {
    label: String,
    x: f32, y: f32, w: f32, h: f32,
}

impl Widget for Button {
    fn draw(&self) {
        println!("drawing button '{}' at ({},{})", self.label, self.x, self.y);
    }
    fn bbox(&self) -> (f32, f32, f32, f32) { (self.x, self.y, self.w, self.h) }
}

impl Clickable for Button {}

fn main() {
    let btn = Button {
        label: "Save".to_string(),
        x: 10.0, y: 10.0, w: 80.0, h: 20.0,
    };
    btn.draw();
    assert!(btn.is_clicked(20.0, 15.0, true));   // 命中
    assert!(!btn.is_clicked(20.0, 15.0, false)); // 没 just_pressed
    assert!(!btn.is_clicked(200.0, 15.0, true)); // 不命中
    println!("OK");
}
```
