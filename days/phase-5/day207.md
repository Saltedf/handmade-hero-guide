## 0 · 为什么要有这一天

让我们把镜头拉到一个具体的开发场景。

Day 206 你实现了 introspection——一个 `Inspectable` trait + `inspect()` 方法。每个游戏类型自动枚举字段。你能在 debug inspector 里显示任意 entity 的所有字段。你以为大功告成。

但第二天你发现:introspection 这份元数据,**可以做远不止 inspector**。

**场景 1**:你给游戏加存盘功能。玩家退出游戏,要保存所有 entity 状态到磁盘。下次启动恢复。传统做法:每个 entity 类型写一份 `serialize()`,几十个类型几十份样板代码。但你刚刚写过 `inspect()`——它已经枚举了所有字段!**直接基于 inspect 结果生成 JSON,无需额外代码**。

**场景 2**:你给游戏加多人模式。Server 要把 entity 状态发给 client。每个 entity 有 30 个字段,每帧只变了 3 个——发全部 30 个浪费带宽。但你刚刚写过 `inspect()`——**对比 server 当前和上次发送的 inspect 结果,只发变化字段**。带宽省 90%。

**场景 3**:你在 debug 一个"血量莫名减少"的 bug。你怀疑某个 frame HP 从 100 突变到 50。你想看 entity 的"帧间 diff"——这一帧和上一帧哪些字段变了。传统做法:手写 print 语句跟踪每个字段。但你刚刚写过 `inspect()`——**对比两帧的 inspect 结果,自动列出所有变化**。

**场景 4**:你加新的字段属性——"speed 字段是 0-100 范围","hp 字段是 0-1000 范围"。你想让 inspector 自动用合适的 slider 范围。增强 introspection metadata——加 `min`/`max` 字段,inspector 自动用。

**场景 5**:你的游戏支持 hot reload(Day 183)。重新编译 game.so 后,要恢复之前的状态。基于 introspection 的序列化让你"序列化旧 state → 加载新 game.so → 反序列化新 state",自动迁移。

这些场景有一个共同模式:**同一份 introspection metadata,驱动多个不同功能**。这是软件工程里 DRY(Don't Repeat Yourself)原则的极致体现——"字段信息"是真相,所有依赖字段的功能都从这份真相派生。

工业级 introspection 系统都这样设计:
- **Unreal UPROPERTY**:一份 metadata 驱动 inspector、网络复制、序列化、Blueprint。
- **Unity SerializeField**:一份 metadata 驱动 inspector、序列化、 prefab。
- **serde Serialize**:一份 derive 驱动 JSON、Binary、TOML、MessagePack 等多种格式。

## 1 · Casey 今天做了什么

Casey 这一天用 Day 206 的 introspection 做 3 件事:

1. **Inspector UI 自动布局**。inspect 返回 `Vec<DebugValueView>`,UI 根据 variant 自动选 widget——Float 用 slider、Int 用 input、Bool 用 checkbox、Color 用 color picker、Enum 用 dropdown。加新字段无需改 inspector 代码。

## 2 · 心智模型

### 2.1 费曼类比:数据库 schema 的多用途

想象一个数据库管理员。他设计了一张"员工"表,有字段:姓名、年龄、薪水、部门。这张表的 **schema** (字段定义)是数据本身之外的"元信息"。

但 schema 不仅仅用来存数据。同一份 schema 驱动多个工具:

- **录入表单**:schema 说"年龄是 int",表单自动用 number input
- **导出 CSV**:schema 说有哪些字段,导出时自动列全
- **数据校验**:schema 说"薪水 ≥ 0",插入时自动验证
- **ORM 映射**:schema 说字段名,代码自动生成 `employee.salary` 属性
- **API 文档**:schema 自动生成 OpenAPI spec
- **报表生成**:schema 自动列出所有可分组维度

**一份 schema,五个工具**。这是 metadata-driven design 的精髓——字段定义只写一次,所有依赖字段的工具自动派生。

程序的 introspection 完全一样。Day 206 你写了 `inspect()` 返回字段元数据。今天我们用这份元数据驱动多个工具:inspector UI、序列化、diff。同一份"字段列表",三个 consumer。

这个类比的关键洞察:**写元数据是一次性投入,享受多次回报**。手写 introspection 看起来"繁琐"(每个 struct 写 inspect),但每个 inspect 函数支撑多个功能,总体代码量比"每个功能各写一份"少得多。

### 2.2 从零推导:inspect 结果作为通用 currency

让我们看 inspect 返回的数据怎么变成多个工具的输入。

**Day 206 的 inspect**:

```rust
fn inspect(&self) -> Vec<DebugValueView> {
    vec![
        DebugValueView::Int { name: "hp", value: 75 },
        DebugValueView::Float { name: "speed", value: 5.5, min: 0.0, max: 20.0 },
        DebugValueView::String { name: "name", value: "Hero".into() },
    ]
}
```

**Consumer 1:Inspector UI**

```rust
fn draw_inspector(ui: &mut Ui, item: &dyn Inspectable) {
    for view in item.inspect() {
        match view {
            DebugValueView::Float { name, value, min, max, .. } => {
                ui.slider(name, *min, *max, *value);
            }
            DebugValueView::Int { name, value, .. } => {
                ui.input(name, *value);
            }
            DebugValueView::String { name, value } => {
                ui.text_input(name, value);
            }
        }
    }
}
```

类型决定 widget——Float 用 slider,Int 用 input,String 用 text field。**通用函数,任何 Inspectable 都能用**。

**Consumer 2:JSON 序列化**

```rust
fn to_json(item: &dyn Inspectable) -> String {
    let mut s = String::from("{");
    let mut first = true;
    for view in item.inspect() {
        if !first { s.push(','); }
        first = false;
        match view {
            DebugValueView::Float { name, value, .. } => {
                s.push_str(&format!("\"{}\":{}", name, value));
            }
            DebugValueView::Int { name, value, .. } => {
                s.push_str(&format!("\"{}\":{}", name, value));
            }
            DebugValueView::String { name, value } => {
                s.push_str(&format!("\"{}\":\"{}\"", name, value));
            }
        }
    }
    s.push('}');
    s
}
```

每个 view variant 对应一种 JSON 类型。**通用函数,任何 Inspectable 都能序列化**。

**Consumer 3:Diff**

```rust
fn diff(a: &dyn Inspectable, b: &dyn Inspectable) -> Vec<String> {
    let va = a.inspect();
    let vb = b.inspect();
    let mut out = Vec::new();
    for ((na, xa), (_, xb)) in paired(&va, &vb) {
        if !view_equal(xa, xb) {
            out.push(format!("{}: {:?} -> {:?}", na, xa, xb));
        }
    }
    out
}
```

逐字段比较。**通用函数,任何 Inspectable 都能 diff**。

三个 consumer 都从同一 `inspect()` 出发。**这就是 metadata-driven design 的力量**。

### 2.3 增强元数据:UI hint

Day 206 的 inspect 返回基础信息(name + value + type)。但 inspector 想要"smart widget"——比如 Float 默认 slider 范围 0-1,但 speed 应该是 0-100,hp 应该是 0-1000。怎么办?

**增强 metadata**:给 Float 加 min/max,加 Hint enum:

```rust
#[derive(Clone, Debug)]
pub enum DebugValueView {
    Float {
        name: &'static str,
        value: f32,
        min: f32,
        max: f32,
        hint: Hint,
    },
    Int {
        name: &'static str,
        value: i64,
        min: i64,
        max: i64,
    },
    Color { name: &'static str, value: u32 },
    String { name: &'static str, value: String },
    Enum {
        name: &'static str,
        value: i64,
        variants: &'static [&'static str],
    },
}

#[derive(Clone, Debug)]
pub enum Hint {
    None,
    Speed,    // 0-100
    Health,   // 0-1000
    Angle,    // 0-360,degree
    Distance, // 0-10000
}
```

Inspector 根据 hint 进一步定制:

```rust
match view {
    DebugValueView::Float { name, value, min, max, hint } => {
        match hint {
            Hint::Angle => ui.angle_dial(name, *value),  // 圆形拨号 widget
            Hint::Speed => ui.labeled_slider(name, *min, *max, *value, "m/s"),
            _ => ui.slider(name, *min, *max, *value),
        }
    }
}
```

Hint 让 UI 更"懂"数据。但要注意——hint 是 UI 专属信息,**不该污染 schema**(序列化时不需要)。Casey 把 hint 放在 DebugValueView 里,只 debug 用,release build cfg 掉(Day 201)。

### 2.4 序列化:从 introspection 到 JSON

序列化是 introspection 的经典应用。我们已经看到了简化版 to_json。工业级序列化要考虑:

1. **嵌套 struct**:Player 里的 pos 字段是 Vec2,要递归序列化。
2. **集合**:Vec、HashMap 要遍历序列化。
3. **可选字段**:Option<T> 要 emit null 或字段。
4. **枚举**:Rust enum 要带 tag 序列化(`{"type":"Attack","data":...}`)。
5. **自定义**:某些字段不序列化(transient),或自定义格式。

serde 处理所有这些。`#[derive(Serialize)]` 在编译期生成 `serialize` 方法,自动遍历字段、处理嵌套、应用属性:

```rust
#[derive(Serialize)]
struct Player {
    id: u32,
    pos: Vec2,
    hp: i32,
    #[serde(skip)]
    cached_value: f32,  // 不序列化
}

#[derive(Serialize)]
struct Vec2 { x: f32, y: f32 }
```

序列化时自动递归——`Player.pos` 是 Vec2,Vec2 也有 Serialize,递归调用。

serde 的 derive 是 introspection 的**通用版**——支持嵌套、属性、多种格式。Casey 手写的 introspection 是**简化版**——只支持平铺字段、单一格式。教学 vs 工业的区别。

### 2.5 Diff 算法的细节

Diff 看起来简单,但有几个坑:

**坑 1:字段顺序**。inspect 返回的 Vec 有顺序。如果 a 和 b 的 inspect 顺序不同(不太可能,但理论上),zip 配对错乱。修复:按 name 排序后配对。

```rust
fn paired<'a>(va: &'a [DebugValueView], vb: &'a [DebugValueView])
    -> Vec<(&'a DebugValueView, &'a DebugValueView)>
{
    // 假设顺序一致(同 struct 类型,inspect 实现一致)
    va.iter().zip(vb.iter()).collect()
}
```

如果两个 struct 类型不同,inspect 顺序可能不同。这种情况下 diff 应该按 name 配对,而非按 index。但 diff 跨类型不常见(通常 diff 同类型实例)。

**坑 2:类型不匹配**。a.hp 是 Int,b.hp 也是 Int——OK。但如果手写错,a.inspect 写 Int,b.inspect 写 Float,type mismatch。修复:Diff 时假设 inspect 实现一致(同 struct 共享 inspect 实现)。

**坑 3:浮点数比较**。Float 比较用 `==`——但浮点精度问题让两个"看起来一样"的 Float 不等(0.1 + 0.2 ≠ 0.3)。修复:用 `abs(a - b) < epsilon`。

```rust
fn float_eq(a: f32, b: f32) -> bool {
    (a - b).abs() < 1e-6
}
```

Casey HH 用精确 ==,因为他知道哪些字段会有浮点问题,手动避免。生产代码用 epsilon。

### 2.6 网络同步:delta compression

多人游戏的网络同步是 introspection 的杀手级应用。

**朴素方案**:Server 每帧把所有 entity 的所有字段发给 client。N=100 entity × 30 field × 4 byte = 12 KB/帧。60 FPS 下 720 KB/秒——宽带用户撑得住,但移动网络会卡。

**优化方案**:**Delta compression**——只发变化字段。

```rust
fn sync_delta(server: &Entity, last_sent: &Entity) -> Vec<FieldUpdate> {
    let mut updates = Vec::new();
    let sv = server.inspect();
    let lv = last_sent.inspect();
    for (i, (s, l)) in sv.iter().zip(lv.iter()).enumerate() {
        if !view_equal(s, l) {
            updates.push(FieldUpdate {
                field_index: i,
                new_value: s.clone(),
            });
        }
    }
    updates
}
```

每帧 server 算"自上次发送以来的 diff",只发 diff。Client 收到 diff,按 field_index 应用到本地 entity。带宽从 720 KB/秒降到 5 KB/秒(99% 节省)。

这就是 Unreal Replication、Unity Network Transform 的核心——基于 introspection 的 delta compression。Casey Day 211+ 详细讲。

### 2.7 metadata-driven design 的边界

introspection 不是银弹。有些场景不适合:

**Hot path**:物理 update、渲染每帧跑几百万次。introspection 通过 trait dispatch + Vec 分配,每次 ~50 ns。几百万次累加是几十 ms。**hot path 用直接字段访问**(`entity.x`),不用 introspection。

**类型安全**:introspection 用类型擦除(DebugValueView enum)。`get_field::<f32>("speed")` 如果实际是 i32,runtime panic。编译期类型检查失效。**类型安全要求高的场景用泛型 + derive**(bevy_reflect 提供)。

**跨进程**:introspection 元数据是 in-process 的。跨进程通信要序列化(JSON / Protobuf)。introspection 不能直接跨进程。

**版本兼容**:旧版本的 inspect 返回 5 个字段,新版本加了一个字段变成 6 个。Diff 时 index 错位。**长期项目要 schema versioning**。

这些边界是工业级 introspection 系统的设计考虑。Casey HH 的教学版简化处理,生产用 serde + bevy_reflect 已经解决。

### 2.0 内省数据的多功能性

Day 206 实现了 introspection,得到一份 `member_def[]` 列表。这份 metadata 能驱动:

1. **Debug Inspector**:UI 显示每个字段
2. **序列化**:存盘 / 网络(JSON / binary)
3. **Diff**:对比两 struct,显示变化
4. **Clone / Copy**:深拷贝(某些字段是引用)
5. **Hash / Eq**:基于字段值算 hash

每个应用都是同一份 metadata 的不同 consumer。

### 2.0.1 序列化的实现

```rust
fn serialize_struct(ptr: *const u8, members: &[MemberDef]) -> String {
    let mut s = String::from("{");
    for (i, m) in members.iter().enumerate() {
        if i > 0 { s.push_str(", "); }
        s.push_str(&format!("\"{}\": ", m.name));
        s.push_str(&read_field_as_json(ptr, m));
    }
    s.push('}');
    s
}

fn read_field_as_json(ptr: *const u8, m: &MemberDef) -> String {
    unsafe {
        match m.ty {
            Type::F32 => (*(ptr.add(m.offset) as *const f32)).to_string(),
            Type::I32 => (*(ptr.add(m.offset) as *const i32)).to_string(),
            Type::String => format!("\"{}\"", *(ptr.add(m.offset) as *const String)),
            // ...
        }
    }
}
```

`serde::Serialize` 用类似逻辑,但更通用、类型安全。

### 2.0.2 Diff 算法

对比两 struct,生成 field-by-field diff:

```rust
fn diff(a: *const u8, b: *const u8, members: &[MemberDef]) -> Vec<FieldDiff> {
    let mut diffs = Vec::new();
    for m in members {
        if !fields_equal(a, b, m) {
            diffs.push(FieldDiff {
                name: m.name,
                old: read_field(a, m),
                new: read_field(b, m),
            });
        }
    }
    diffs
}
```

UI 显示:`HP: 100 → 50`,高亮变化字段。这是 Unreal 的 Diff tool、Git 的 word-diff 的核心。

### 2.0.4 hot reload 兼容

Day 183 提到 cdylib 热重载时 state 要保留。introspection 让"state 序列化到字符串"自动化:


### 2.0.5 网络同步

多人游戏,server 把 entity state 发给 client。每个 entity 有 introspection,自动同步:

```rust
fn network_serialize(entity: &Entity) -> Vec<u8> {
    let mut buf = Vec::new();
    for m in Entity::members() {
        buf.extend_from_slice(unsafe { read_field_bytes(entity as *const _ as *const u8, m) });
    }
    buf
}
```

client 反序列化,直接 memcpy 到 entity。无手写 pack/unpack 代码。

### 2.3 自动 diff

```rust
fn diff_inspectable(a: &dyn Inspectable, b: &dyn Inspectable) -> Vec<String> {
    let va = a.inspect();
    let vb = b.inspect();
    let mut diffs = Vec::new();
    for (i, (xa, xb)) in va.iter().zip(vb.iter()).enumerate() {
        if !view_equal(xa, xb) {
            diffs.push(format!("field {}: {:?} -> {:?}", i, xa, xb));
        }
    }
    diffs
}

fn view_equal(a: &DebugValueView, b: &DebugValueView) -> bool {
    // 比较两个字段值
    match (a, b) {
        (DebugValueView::Float { value: va, .. }, DebugValueView::Float { value: vb, .. }) => va == vb,
        (DebugValueView::Int { value: va, .. }, DebugValueView::Int { value: vb, .. }) => va == vb,
        // ...
        _ => false,
    }
}
```

### 2.4 序列化(轻量)

```rust
fn to_json(item: &dyn Inspectable) -> String {
    let mut out = String::from("{");
    let mut first = true;
    for v in item.inspect() {
        if !first { out.push(','); }
        first = false;
        match v {
            DebugValueView::Float { name, value, .. } => {
                out.push_str(&format!("\"{}\":{}", name, value));
            }
            DebugValueView::Int { name, value, .. } => {
                out.push_str(&format!("\"{}\":{}", name, value));
            }
            DebugValueView::String { name, value } => {
                out.push_str(&format!("\"{}\":\"{}\"", name, value));
            }
            _ => {}
        }
    }
    out.push('}');
    out
}
```

实际工程用 `serde_json`,这是教学版。

### 2.5 网络同步(预告)

```rust
fn sync_changed(server: &dyn Inspectable, last: &dyn Inspectable) -> Vec<FieldUpdate> {
    // 对比,只发变化字段
    let mut updates = Vec::new();
    for (i, (sv, lv)) in server.inspect().iter().zip(last.inspect().iter()).enumerate() {
```

### serde 生态

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么不直接用 serde 做 inspector,而要自己写 Inspectable?

**参考解答**:
- serde 是**为序列化设计**,信息有限(类型 + 名)
- inspector 需要**UI 专属信息**(min/max/hint/widget type)
- 例如:`Float { name: "speed", value: 5.0, min: 0.0, max: 100.0, hint: Speed }` 这些 serde 没有
- 用 serde 的 `#[serde(rename = "...")]` 等勉强能塞,但污染 schema
- 工业实践:写专门的 Inspectable derive macro(类似 bevy_reflect)
- 教学版:手写 Inspectable,清楚但繁琐

### Lv2 · 动手实践

**题**:基于 Day 206 的 introspection,实现 diff 函数。

**参考解答**:

```rust
#[derive(Debug)]
enum View {
    Int(i64),
    Float(f32),
    Str(String),
}

trait Inspectable {
    fn inspect(&self) -> Vec<(&'static str, View)>;
}

struct Player { hp: i32, speed: f32, name: String }

impl Inspectable for Player {
    fn inspect(&self) -> Vec<(&'static str, View)> {
        vec![
            ("hp", View::Int(self.hp as i64)),
            ("speed", View::Float(self.speed)),
            ("name", View::Str(self.name.clone())),
        ]
    }
}

fn view_eq(a: &View, b: &View) -> bool {
    match (a, b) {
        (View::Int(x), View::Int(y)) => x == y,
        (View::Float(x), View::Float(y)) => x == y,
        (View::Str(x), View::Str(y)) => x == y,
        _ => false,
    }
}

fn diff(a: &dyn Inspectable, b: &dyn Inspectable) -> Vec<String> {
    let va = a.inspect();
    let vb = b.inspect();
    let mut out = Vec::new();
    for ((na, xa), (nb, xb)) in va.iter().zip(vb.iter()) {
        if !view_eq(xa, xb) {
            out.push(format!("{}: {:?} -> {:?}", na, xa, xb));
        }
        let _ = nb;
    }
    out
}

fn main() {
    let p1 = Player { hp: 100, speed: 5.0, name: "A".to_string() };
    let p2 = Player { hp: 80, speed: 5.0, name: "B".to_string() };
    let d = diff(&p1, &p2);
    for line in &d { println!("{}", line); }
    // 输出: hp: Int(100) -> Int(80)
    //       name: Str("A") -> Str("B")
}
```
