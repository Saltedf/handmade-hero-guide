# Day 240 · 把渲染器移到第三层

> Day 026 你建立了三明治架构:平台层 / 游戏层 / 共享头。Day 239 你把渲染切到 OpenGL,但 push buffer 的"执行器"还在平台层里——平台层既处理窗口事件,又翻译 draw 命令,职责太重。今天 Casey 把渲染器拆出来:**第三层独立模块**,平台层只管窗口和输入。

## 0 · 为什么要有这一天

回看 Day 239 的代码,平台层大概长这样:

```rust
fn main() {
    // 1. 初始化 winit 窗口
    let window = ...;
    // 2. 初始化 glutin GL context
    let gl_context = ...;
    // 3. 初始化 glow + 编译 shader + 创建 VAO/VBO
    let gl_resources = ...;
    // 4. 主循环
    loop {
        // 4a. 处理 winit 事件
        process_events();
        // 4b. 调游戏更新
        game_update_and_render(&mut state, &mut push_buffer);
        // 4c. 执行 push buffer,调 GL
        opengl_execute(&gl, &gl_resources, &push_buffer);
        // 4d. swap buffers
        window.swap_buffers();
    }
}
```

问题:

1. **职责混淆** —— 平台层既管窗口(系统调用、事件),又管 GL(shader、buffer、texture)。一个文件几千行,改一处容易踩另一处。
2. **不能换后端** —— 如果你要加 Vulkan 后端,要重写整个平台层。
3. **测试难** —— 平台层依赖 winit + GL,单测要起窗口,慢且脆。

**第三层**:把"渲染器"拆成独立模块,只负责"翻译 push buffer 到具体图形 API"。平台层只剩"窗口 + 事件 + 调游戏 + 调渲染器"。

```
┌─────────────────────────────────────┐
│ 平台层(Platform Layer)              │
│ - winit 窗口                       │
│ - 事件处理                          │
│ - 调用 game_update_and_render      │
└────────────┬────────────────────────┘
             │ push buffer 命令
             ↓
┌─────────────────────────────────────┐
│ 渲染器层(Renderer Layer) 第三层     │
│ - OpenGL 后端:glutin + glow        │
│ - Vulkan 后端(将来):ash           │
│ - 软件后端(保留):framebuffer      │
└─────────────────────────────────────┘
             ↑ 共享的命令类型
┌─────────────────────────────────────┐
│ 游戏层(Game Layer)                  │
│ - 游戏逻辑                          │
│ - push 渲染命令                     │
└─────────────────────────────────────┘
```

**为什么这件事重要**:这是大型软件的**模块化**经典案例。任何超过 5000 行的程序都要做这种拆分,否则维护成本指数级上升。你跟 Casey 学的不只是"游戏怎么写",更是"大型软件怎么组织"。

**心理锚点**:看完今天,你能写一个 trait `Renderer`,用 `struct OpenGLRenderer` 和 `struct SoftwareRenderer` 两个实现,游戏代码和平台层都不用改,通过 trait object 切换。

### 2.1 渲染器接口设计

```rust
// 渲染器抽象 trait
pub trait Renderer {
    /// 初始化:编译 shader、创建 VAO/VBO、上传初始纹理
    fn init(&mut self, context: &dyn GlContext) -> Result<(), RenderError>;

    /// 执行 push buffer
    fn execute(&mut self, queue: &RenderQueue, proj: &[f32; 16]);

    /// 关闭:清理 GPU 资源
    fn shutdown(&mut self);

    /// 上传纹理,返回 ID
    fn upload_texture(&mut self, width: u32, height: u32, pixels: &[u8]) -> TextureId;

    /// 释放纹理
    fn free_texture(&mut self, id: TextureId);
}

// 具体后端
pub struct OpenGLRenderer {
    gl: glow::Context,
    program: Program,
    vao: VertexArray,
    vbo: Buffer,
    textures: HashMap<TextureId, Texture>,
}

impl Renderer for OpenGLRenderer {
    fn init(&mut self, ctx: &dyn GlContext) -> Result<(), RenderError> { ... }
    fn execute(&mut self, queue: &RenderQueue, proj: &[f32; 16]) { ... }
    // ...
}

pub struct SoftwareRenderer {
    framebuffer: Vec<u32>,
    width: u32,
    height: u32,
}

                }
```

### 2.2 平台层简化后

```rust
fn main() {
    let event_loop = winit::event_loop::EventLoop::new().unwrap();
    let window = ...;
    let gl_context = ...;

    // 选渲染器(运行时切换)
    let mut renderer: Box<dyn Renderer> = if use_opengl {
        Box::new(OpenGLRenderer::new(gl))

    let mut queue = RenderQueue::new();

    event_loop.run(move |event, target| {
        match event {

                game_update_and_render(&mut state, &mut queue);

```

平台层只剩 50 行,所有 GL 细节都藏在 `OpenGLRenderer` 里。

### 2.3 trait object vs 泛型

Rust 选 trait object(`Box<dyn Renderer>`)还是泛型(`fn run<R: Renderer>(renderer: R)`)?:

| | `Box<dyn Renderer>` | 泛型 `<R: Renderer>` |
|---|---|---|
| 性能 | 间接调用(vtable) | 静态分派(内联) |
| 编译时间 | 快 | 慢(monomorphization) |
| 切换 | 运行时 | 编译时 |
| 二进制大小 | 小 | 大 |

游戏渲染每帧调几百次,trait object 间接调用对性能影响微乎其微(< 1µs/帧)。推荐 trait object,简单灵活。

### 2.4 渲染器生命周期

```
启动:
   platform init window
   platform init GL context
   platform create renderer:
       renderer.init(context)
           - 编译 shader
           - 创建 VAO/VBO
           - 创建空 texture map

每帧:
   game_update_and_render(state, queue)
       - push draw 命令
   renderer.execute(queue, proj)
       - 遍历命令,调 GL

退出:
   renderer.shutdown()
       - 删除 shader / program / VAO / VBO
       - 释放所有 texture
   platform shutdown
```

`init` 和 `shutdown` 必须配对,GL 资源泄漏会让 driver 内存涨。

### 2.5 渲染器状态(state)管理

OpenGL 是**状态机**——你 set 一个 state(纹理绑定、blend mode、深度测试等),它持续到你下次 set。命令执行时要管:

```rust
fn execute(&mut self, queue: &RenderQueue, proj: &[f32; 16]) {
    unsafe {
        self.gl.use_program(Some(self.program));
        // ... 设置不变的 uniform

        let mut last_texture: Option<TextureId> = None;

        for cmd in &queue.cmds {
            match cmd {
                RenderCmd::DrawBitmap { texture_id, .. } => {
                    if Some(*texture_id) != last_texture {
                        // 切纹理(状态变更)
                        let tex = self.textures.get(texture_id).unwrap();
                        self.gl.bind_texture(glow::TEXTURE_2D, Some(*tex));
                        last_texture = Some(*texture_id);
                    }
                    // ... 画
                }
                _ => {}
            }
        }
    }
}
```

**状态缓存(state caching)** 是 OpenGL 优化核心。`bind_texture` 每次都是 driver 开销,缓存"上次绑了什么"避免重复。

### 2.6 错误处理

GL 错误是异步的——你调 `glBufferData` 失败,可能要等几帧才报。开启 `glGetError` 同步检查(慢,debug 用):

```rust
#[cfg(debug_assertions)]
fn check_gl_error(gl: &glow::Context, context: &str) {
    unsafe {
        let err = gl.get_error();
        if err != glow::NO_ERROR {
            panic!("GL error in {}: 0x{:x}", context, err);
        }
    }
}
```

生产用 `GL_KHR_debug` 扩展,driver 主动 push 错误到 callback。Day 242 上下文升级会开启。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

**主流引擎都这样分层**:

- **Unreal** —— `FRHI`(Render Hardware Interface)抽象,后端可以是 Vulkan / D3D12 / Metal / OpenGL
- **Unity** —— 同样多后端,游戏代码用 `Graphics.DrawMeshNow` 等高层 API
- **Bevy** —— `RenderDevice` trait,后端 wgpu(它自己再抽象 Vulkan/Metal/D3D)

游戏引擎架构的核心抽象层:

```
Game Logic Layer      (你的游戏代码)
       ↓
High-level Renderer   (Mesh / Material / Camera 抽象)
       ↓
Render Queue / Pass   (push buffer)
       ↓
Low-level Backend     (RHI: OpenGL / Vulkan / D3D)
       ↓
GPU Driver
       ↓
Hardware
```

每一层只关心自己的抽象,层间通过明确接口沟通。Casey 的 Day 240 是把 Low-level Backend 拆出,后面 Day 259 还会进一步清理。

### 3.2 · 🎨 图形学视角

**渲染抽象(Render Hardware Interface, RHI)** 是图形学工程化的关键。RHI 把不同 API 的差别(OpenGL / Vulkan / D3D)藏在统一接口下。

不同 API 的概念对应:

| 概念 | OpenGL | Vulkan | D3D12 |
|---|---|---|---|
| Shader program | `glCreateProgram` | `VkShaderModule` + `VkPipeline` | `ID3D12PipelineState` |
| Vertex buffer | `glGenBuffers` + `glBufferData` | `VkBuffer` + `VkDeviceMemory` | `ID3D12Resource` |
| Texture | `glGenTextures` + `glTexImage2D` | `VkImage` + `VkImageView` | `ID3D12Resource` |
| Draw call | `glDrawArrays` | `vkCmdDraw` (in command buffer) | `DrawInstanced` |

可见**Vulkan 的概念粒度更细**(VkBuffer 和 VkDeviceMemory 分开,要手动绑定),OpenGL 最粗粒度。RHI 抽象这些差异。

### 3.3 · 🐧 Linux 系统编程视角

Linux 上类似分层:

- **应用层**(游戏)—— push 命令
- **Mesa driver**(renderer)—— 翻译命令
- **DRM**(low-level)—— 内核 GPU 命令提交
- **GPU**

DRM 本身就是 Linux 的"RHI"——把不同厂商的 GPU 命令差异藏在统一 ioctl 后面。

```bash
# 看 DRM 设备
ls /dev/dri/
# 输出:by-path  card0  renderD128

# card0 = 主显示设备
# renderD128 = 无显示的 compute 节点(给 OpenCL / Vulkan compute)

# 看 DRM 客户端(谁在用 GPU)
sudo cat /sys/kernel/debug/dri/0/clients
```

### 3.4 · 🦀 Rust 生态视角

Rust 的 trait 系统特别适合做 RHI。一个 trait 多个实现,trait object 动态切换:

```rust
pub trait Renderer {
    fn execute(&mut self, queue: &RenderQueue, proj: &[f32; 16]);
    // ...
}

pub struct OpenGLRenderer { /* ... */ }
impl Renderer for OpenGLRenderer { /* ... */ }

pub struct WgpuRenderer { /* ... */ }
impl Renderer for WgpuRenderer { /* ... */ }

// 运行时选
let renderer: Box<dyn Renderer> = match backend {
    "gl" => Box::new(OpenGLRenderer::new()),
    "wgpu" => Box::new(WgpuRenderer::new()),
    _ => panic!("unknown backend"),
};
```

**wgpu crate 本身就是 RHI** —— 它把 Vulkan / Metal / D3D12 / OpenGL 藏在统一接口下。你跟 HH 学 OpenGL 是为了理解原理,后面 Phase 7+ 可以切 wgpu。

**Rust 生态主流 RHI**:

- **wgpu** —— Rust 写的 WebGPU 实现,主流选择
- **ash** —— Vulkan 底层 binding
- **glow** —— OpenGL 薄封装,跨平台
- **rend3** —— 高层 renderer(基于 wgpu)

跟 HH 学用 glow,够简单。后面升级 wgpu 时,你已经懂 RHI 抽象,切得很快。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:trait object(`Box<dyn Renderer>`)和泛型(`fn f<R: Renderer>(r: R)`)在渲染器抽象里有什么取舍?

**参考解答**:

- **trait object** —— 运行时多态,通过 vtable 间接调用。每次 `renderer.execute()` 多一次指针查找(~几纳秒)。优点:可以在运行时切换后端(配置文件决定)。缺点:无法内联优化。
- **泛型** —— 编译时单态化,每个具体类型生成一份代码。优点:零开销(可内联)。缺点:二进制变大,无法运行时切换。

渲染器每帧调几百次,trait object 的几纳秒开销可忽略。推荐 trait object。如果性能 critical 内层循环用泛型(比如 `Vec<f32>` vs `Vec<u8>`)。

## 8 · Rust / Arch 落地代码

### Rust 完整三层架构示例

```rust
use glow::HasContext;

// === 共享层 ===
#[derive(Debug, Clone, Copy)]
pub struct TextureId(pub u32);

#[derive(Debug)]
pub enum RenderCmd {
    Clear { color: [f32; 4] },
    DrawBitmap {
        x: f32, y: f32, w: f32, h: f32,
        tex: TextureId,
    },
}

pub struct RenderQueue {
    pub cmds: Vec<RenderCmd>,
}

impl RenderQueue {
    pub fn new() -> Self { Self { cmds: Vec::new() } }
    pub fn reset(&mut self) { self.cmds.clear(); }
    pub fn clear(&mut self, color: [f32; 4]) {
        self.cmds.push(RenderCmd::Clear { color });
    }
    pub fn draw_bitmap(&mut self, x: f32, y: f32, w: f32, h: f32, tex: TextureId) {
        self.cmds.push(RenderCmd::DrawBitmap { x, y, w, h, tex });
    }
}

// === 渲染器 trait(第三层抽象) ===
pub trait Renderer {
    fn execute(&mut self, queue: &RenderQueue, proj: &[f32; 16]);
    fn upload_texture(&mut self, w: u32, h: u32, pixels: &[u8]) -> TextureId;
}

// === OpenGL 后端 ===
pub struct OpenGLRenderer {
    gl: glow::Context,
    program: <glow::Context as glow::HasContext>::Program,
    vao: <glow::Context as glow::HasContext>::VertexArray,
    vbo: <glow::Context as glow::HasContext>::Buffer,
    proj_loc: Option<<glow::Context as glow::HasContext>::UniformLocation>,
    textures: std::collections::HashMap<u32, <glow::Context as glow::HasContext>::Texture>,
    next_texture_id: u32,
}

impl OpenGLRenderer {
    pub fn new(gl: glow::Context) -> Self {
        // 编译 shader / 创建 VAO VBO(代码同 Day 237-238)
        // ...
        Self {
            gl, program, vao, vbo, proj_loc, textures: HashMap::new(),
            next_texture_id: 1,
        }
    }
}

impl Renderer for OpenGLRenderer {
    fn execute(&mut self, queue: &RenderQueue, proj: &[f32; 16]) {
        unsafe {
            self.gl.use_program(Some(self.program));
            self.gl.uniform_matrix_4_f32_slice(self.proj_loc, false, proj);
            self.gl.bind_vertex_array(Some(self.vao));

            let mut last_tex: Option<u32> = None;

            for cmd in &queue.cmds {
                match cmd {
                    RenderCmd::Clear { color } => {
                        self.gl.clear_color(color[0], color[1], color[2], color[3]);
                        self.gl.clear(glow::COLOR_BUFFER_BIT);
                    }
                    RenderCmd::DrawBitmap { x, y, w, h, tex } => {
                        if last_tex != Some(tex.0) {
                            let t = self.textures.get(&tex.0).unwrap();
                            self.gl.bind_texture(glow::TEXTURE_2D, Some(*t));
                            last_tex = Some(tex.0);
                        }
                        let vertices: [f32; 24] = [
                            *x, *y, 0.0, 0.0, x+w, *y, 1.0, 0.0,
                            *x, y+h, 0.0, 1.0, x+w, *y, 1.0, 0.0,
                            x+w, y+h, 1.0, 1.0, *x, y+h, 0.0, 1.0,
                        ];
                        self.gl.bind_buffer(glow::ARRAY_BUFFER, Some(self.vbo));
                        self.gl.buffer_sub_data_u8_slice(
                            glow::ARRAY_BUFFER, 0, bytemuck::cast_slice(&vertices));
                        self.gl.draw_arrays(glow::TRIANGLES, 0, 6);
                    }
                }
            }
        }
    }

    fn upload_texture(&mut self, w: u32, h: u32, pixels: &[u8]) -> TextureId {
        let id = self.next_texture_id;
        self.next_texture_id += 1;
        unsafe {
            let tex = self.gl.create_texture().unwrap();
            self.gl.bind_texture(glow::TEXTURE_2D, Some(tex));
            self.gl.tex_image_2d(
                glow::TEXTURE_2D, 0, glow::RGBA as i32,
                w as i32, h as i32, 0,
                glow::RGBA, glow::UNSIGNED_BYTE, Some(pixels),
            );
            self.gl.tex_parameter_i32(
                glow::TEXTURE_2D, glow::TEXTURE_MIN_FILTER, glow::LINEAR as i32);
            self.textures.insert(id, tex);
        }
        TextureId(id)
    }
}
```

**Troubleshooting**:

- **trait object 编译错** —— trait 必须 object-safe。不能有 `fn foo() -> Self` 之类
- ** borrow checker 报"借用 renderer 又借用 queue"** —— 用 `&mut self` 不要 `&self`,queue 不属于 renderer
- **GL 资源泄漏** —— `OpenGLRenderer::drop` 里释放所有 texture 和 buffer
