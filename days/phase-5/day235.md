## 0 · 为什么要有这一天

软渲染的现实极限:

- **像素吞吐**:1920×1080 = 200 万 pixel / 帧,60 FPS = 1.2 亿 pixel / 秒。CPU 单核做不到
- **复杂度**:Phong 光照、shadow、bloom 后处理,每 pixel 几十次浮点运算,CPU 1000 GFLOPS 远不够
- **平行性**:GPU 几千个 SIMT core,远超 CPU 8 核

CPU 软渲染适合教学,实际游戏必须用 GPU。Casey 前 234 集刻意软渲染——让学习者**理解渲染管线每一步**。Day 235 之后用 GPU,**让 GPU 执行同样的管线**。

**今天的任务**:把 OpenGL 上下文接到窗口上。完成后窗口里画的是 GPU 渲染的像素,不再是 softbuffer 上传的 CPU 像素。

**Casey 在 Windows 上做**:Win32 API + WGL(Windows GL)。**Rust 学习者做**:glutin + glow,跨平台。架构差异:

```
Casey:
Win32 CreateWindow → wglCreateContext → wglMakeCurrent → glClearColor → SwapBuffers

Rust:
winit WindowBuilder → glutin ContextBuilder → glow Context → gl.clear → window.swap_buffers
```

底层完全一致(winit/glutin 内部调 WGL / GLX / EGL),但 Rust API 抽象掉平台差异。

心理锚点:做完今天,你的窗口里画的是 GPU 像素。这是后面 100+ 集 OpenGL 渲染的起点。

## 2 · 心智模型

### 类比:换发动机

软渲染像开 4 缸轿车——能跑,但慢。GPU 像换 V12 发动机——快 100 倍,但接线和控制完全不同。

换发动机步骤:

1. 卸下旧发动机(关掉 softbuffer)
2. 安装新发动机(GL context)
3. 接线(加载 GL 函数指针)
4. 启动测试(画一个三角形)

每步都有适配工作,但完成后整个性能上限完全不同。

### 2.1 OpenGL 是什么

**OpenGL**:跨平台图形 API 规范。定义一组函数(`glClearColor`、`glDrawArrays`、...)。每个 OS 的实现:

- **Windows**:WGL + GPU 厂商驱动(NVIDIA / AMD / Intel)
- **Linux**:**GLX**(X11)或 **EGL**(Wayland)+ Mesa / 厂商驱动
- **macOS**:CGL(已废弃,Apple 推 Metal)

API 一致,后端不同。Khronos 维护规范,版本从 1.0(1992)到 4.6(2017)。

### 2.2 GL Context 的本质

**OpenGL context**:GPU 渲染状态的容器。包含:

- 当前 shader 程序
- 当前绑定的 buffer / texture
- viewport / scissor 设置
- depth test / blend mode
- error 状态

context 是**线程局部**的:每个线程一次只能有一个 current context。所有 GL 调用作用于该 context。

```c
wglMakeCurrent(hdc, hglrc);  // Windows:把 context 绑到线程
// 之后所有 gl* 调用作用于 hglrc
```

### 2.3 函数指针加载

GL 函数不是编译时链接——是运行时查的。原因:

- 不同 OS 函数地址不同
- 不同驱动版本函数集不同
- 扩展(extensions)数量巨大,不可能全链接

加载方式:

```c
// Windows
PFNGLCLEARCOLORPROC glClearColor = (PFNGLCLEARCOLORPROC)wglGetProcAddress("glClearColor");
// 然后调用
glClearColor(1.0f, 0.0f, 0.0f, 1.0f);
```

每个 GL 函数都要这样查。**glow crate**(Rust)自动做这件事。

### 2.4 双缓冲(double buffering)

OpenGL 窗口默认**双缓冲**:

- **Back buffer**:GPU 渲染的目标
- **Front buffer**:显示器读取的源

渲染时画到 back buffer,完整一帧后 `SwapBuffers` 把 back 和 front 交换,显示新帧。**避免撕裂**(tearing,上半帧旧下半帧新)。

```c
// 渲染
glClearColor(0, 0, 0, 1);
glClear(GL_COLOR_BUFFER_BIT);
// 画游戏...
SwapBuffers(hdc);  // 把 back buffer 交换到屏幕
```

### 2.5 VSync

VSync(垂直同步):SwapBuffers 等显示器刷新才交换。60Hz 显示器每秒 60 次,SwapBuffers 同步到这 60 次,避免撕裂。

```c
wglSwapIntervalEXT(1);  // 开 VSync
wglSwapIntervalEXT(0);  // 关 VSync,可能撕裂但 FPS 高
```

casey 在 Day 241 详细讲 VSync 和 sRGB。

## 3 · 四域深入

### 3.1 · 游戏编程视角

OpenGL 在游戏开发的位置:

- **PC 游戏**:OpenGL / Vulkan / DirectX 11/12 / Metal
- **Mobile**:OpenGL ES / Vulkan / Metal
- **Web**:WebGL / WebGPU
- **Console**:厂商专用(PS5 的 GNM,Xbox 的 DX12)

OpenGL 是教学和跨平台首选。Vulkan / DX12 是 AAA 性能首选。casey 选 OpenGL 因为:

- 简单(比 Vulkan 简单 10 倍)
- 教学清晰(状态机模型)
- 跨平台(同一代码跑 Windows / Linux / macOS)

### 3.2 · 图形学视角

OpenGL 是 **immediate-mode API**(已废弃概念)或 **retained-mode with state**:

```
// 设置状态
glEnable(GL_DEPTH_TEST);
glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);

// 提交 draw call
glDrawArrays(GL_TRIANGLES, 0, 3);

// 状态持续到下次改变
```

现代 OpenGL(3.3+)是 **core profile**:

- 必须用 VAO(Vertex Array Object)+ VBO(Vertex Buffer Object)
- 必须用 GLSL shader(没有 fixed function pipeline)
- 没有 glBegin / glEnd(immediate mode 已删)

casey 用 core profile 3.3。

### 3.3 · Linux 系统编程视角

Linux 上 OpenGL 的层次:

```
应用
↓
glutin(Rust 封装)
↓
GLX(X11)/ EGL(Wayland)
↓
libGL.so(Mesa 实现 或 厂商)
↓
DRM(Direct Rendering Manager,kernel)
↓
GPU 硬件
```

`libGL.so` 提供 OpenGL API 入口点。Mesa 是开源实现,支持软渲染(LLVMpipe)和硬件加速。

```bash
# Arch Linux 查 OpenGL 实现
glxinfo | grep "OpenGL renderer"
# 输出类似:OpenGL renderer string: AMD Radeon RX 6800
# 或软件渲染:OpenGL renderer string: llvmpipe (LLVM 15.0.7, 256 bits)
```

### 3.4 · Rust 生态视角

Rust OpenGL 栈:

```toml
[dependencies]
winit = "0.29"      # 窗口 / 事件
glutin = "0.31"     # OpenGL context(基于 winit)
glow = "0.13"       # GL 函数加载 wrapper,跨 desktop/GLES/WebGL
```

代码骨架:

```rust
use winit::event_loop::EventLoop;
use winit::window::WindowBuilder;
use glutin::{ContextBuilder, Api, GlProfile, GlRequest};
use glow::HasContext;

let event_loop = EventLoop::new();
let window = WindowBuilder::new()
    .with_title("OpenGL Window")
    .build(&event_loop)?;

let gl_context = ContextBuilder::new()
    .with_gl(GlRequest::Specific(Api::OpenGl, (3, 3)))
    .with_gl_profile(GlProfile::Core)
    .build_windowed(window, &event_loop)?;

let gl_context = unsafe { gl_context.make_current().unwrap() };

let gl = glow::Context::from_loader_function(|s| {
    gl_context.get_proc_address(s) as *const _
});

unsafe {
    gl.clear_color(0.0, 0.5, 1.0, 1.0);
    gl.clear(glow::COLOR_BUFFER_BIT);
}
gl_context.swap_buffers()?;
```

`unsafe` 因为 GL 调用本质是 FFI 到 C。

## 5 · 对照与变奏

OpenGL 不同版本的演化:

- **GL 1.x**(1992):fixed function,immediate mode
- **GL 2.x**(2004):GLSL shader 引入
- **GL 3.x**(2008-2010):core profile,移除 fixed function,VAO/VBO 强制
- **GL 4.x**(2010-2017): tessellation,compute shader,indirect draw
- **Vulkan**(2016):explicit GPU control,替代 GL 的高端市场

casey 选 GL 3.3 core,因为:

- 跨平台兼容(Linux/macOS 支持到 4.1)
- 现代 API(必须 shader,符合现代 GPU 编程)
- 文档 / 教程丰富(LearnOpenGL 等基于 3.3)

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么必须创建 dummy OpenGL context 才能拿到现代 pixel format?Win32 设计的什么缺陷导致?

**参考解答**:WGL 的 pixel format 选择(`ChoosePixelFormat` / `SetPixelFormat`)是老 API,只能选老格式(无 sRGB / MSAA)。要选现代格式必须用扩展 `wglChoosePixelFormatARB`。但**扩展查询本身需要 GL context**(用 `wglGetProcAddress`)。鸡和蛋问题。

解决:先创建 dummy context(老 API + 老格式),用它查扩展,然后用扩展 API 选现代 pixel format,**再创一个真 context**(现代格式)。dummy 删除。Win32 历史包袱。

Linux(EGL / GLX)没这问题,API 设计更现代。glutin crate 跨平台统一,内部封装平台差异。

## 10 · 深入:OpenGL 初始化的工业级流程

casey 在 day235 完成 OpenGL 初始化——这是从软件渲染切到 GPU 渲染的里程碑。让我把整个 OpenGL 初始化流程讲透。

### 10.1 OpenGL 初始化的步骤

OpenGL 初始化涉及:

1. **创建 OS 窗口**(Win32 / X11 / Wayland)
2. **获取像素格式**(pixel format / framebuffer config)
3. **创建 OpenGL context**
4. **make context current**(绑定到当前线程)
5. **加载 GL extension**(GLAD / gl_bindings)
6. **设置初始 state**(viewport、clear color)
7. **创建渲染资源**(shader、buffer、texture)

casey 在 day235 主要做 1-6,7 在 day237+。

### 10.2 创建 OS 窗口

```rust
// Windows
use windows::Win32::UI::WindowsAndMessaging::*;
let hwnd = unsafe {
    CreateWindowExW(
        WINDOW_EX_STYLE::default(),
        w!("HandmadeHeroClass"),
        w!("Handmade Hero"),
        WS_OVERLAPPEDWINDOW | WS_VISIBLE,
        CW_USEDEFAULT, CW_USEDEFAULT,
        1280, 720,
        None, None, hinstance, None,
    )
};

// Linux X11
use x11rb::connection::Connection;
let (conn, screen_num) = x11rb::connect(None).unwrap();
let window = conn.generate_id().unwrap();
conn.create_window(COPY_DEPTH_FROM_PARENT, window, screen.root, 0, 0, 1280, 720, 0, ...).unwrap();
```

不同 OS 不同 API,Rust 用 `winit` crate 跨平台抽象。

### 10.3 获取像素格式

OpenGL context 需要窗口有"支持 OpenGL 的像素格式":

```rust
// Windows:PIXELFORMATDESCRIPTOR
let pfd = PIXELFORMATDESCRIPTOR {
    nVersion: 1,
    dwFlags: PFD_DRAW_TO_WINDOW | PFD_SUPPORT_OPENGL | PFD_DOUBLEBUFFER,
    iPixelType: PFD_TYPE_RGBA,
    cColorBits: 32,
    cDepthBits: 24,
    cStencilBits: 8,
    ...Default::default()
};
let pf_id = unsafe { ChoosePixelFormat(hdc, &pfd) };
unsafe { SetPixelFormat(hdc, pf_id, &pfd) };
```

像素格式决定颜色位深、depth/stencil、双缓冲、抗锯齿等。

### 10.4 创建 OpenGL context

```rust
// Windows
let hglrc = unsafe { wglCreateContext(hdc) };
unsafe { wglMakeCurrent(hdc, hglrc) };
```

现代 OpenGL 用 `wglCreateContextAttribsARB`,指定 GL version、profile(core / compatibility):

```rust
let attrs = [
    wgl::CONTEXT_MAJOR_VERSION_ARB, 4,
    wgl::CONTEXT_MINOR_VERSION_ARB, 6,
    wgl::CONTEXT_PROFILE_MASK_ARB, wgl::CONTEXT_CORE_PROFILE_BIT_ARB,
    0,
];
let hglrc = unsafe { wglCreateContextAttribsARB(hdc, ptr::null(), attrs.as_ptr()) };
```

### 10.5 加载 GL extension

OpenGL 的 extension 函数指针不是 link 时绑定,要运行时获取:

```rust
// 用 glow crate 加载
let gl = glow::Context::from_loader_function(|s| {
    get_proc_address(s) as *const _
});

// 或 raw bindings
let gl_clear = unsafe {
    std::mem::transmute(get_proc_address("glClear"))
};
```

不同 OS 的 `get_proc_address` 不同(Windows: wglGetProcAddress, Linux: glXGetProcAddress)。`glow` crate 跨平台抽象。

### 10.6 设置初始 state

```rust
unsafe {
    gl.Viewport(0, 0, 1280, 720);
    gl.ClearColor(0.0, 0.0, 0.0, 1.0);
    gl.Enable(glow::DEPTH_TEST);
    gl.Enable(glow::BLEND);
    gl.BlendFunc(glow::SRC_ALPHA, glow::ONE_MINUS_SRC_ALPHA);
}
```

初始 state 决定渲染基础行为。

### 10.7 Linux OpenGL 初始化的差异

Linux 用 GLX(X11)或 EGL(Wayland / 现代 OpenGL):

```rust
// GLX
use glx::Glx;
let visual_info = unsafe { glx.ChooseVisual(display, screen, attrs) };
// 创建窗口后:
let ctx = unsafe { glx.CreateContext(display, visual_info, ptr::null(), true) };
unsafe { glx.MakeCurrent(display, window, ctx) };

// EGL
let display = egl.get_display(EGL_DEFAULT_DISPLAY);
egl.initialize(display);
let config = egl.choose_config(display, attrs);
let surface = egl.create_window_surface(display, config, window, None);
let context = egl.create_context(display, config, None, None);
egl.make_current(display, surface, surface, context);
```

Linux 的 OpenGL 初始化比 Windows 复杂(多套 API 选择),但 winit + glow 抽象后简化。

## 11 · 深入:OpenGL context 的版本与 profile

OpenGL 有多个版本(1.0 到 4.6)和 profile(core / compatibility / ES)。选择正确的版本/profile 是开发基础。

### 11.1 OpenGL 版本演化

- **OpenGL 1.x**(1992-2003):固定管线,glBegin/glEnd
- **OpenGL 2.0**(2004):GLSL shader
- **OpenGL 3.0**(2008):deprecated 固定管线
- **OpenGL 3.3**(2010):core profile 强制,VAO/VBO 必需
- **OpenGL 4.0**(2010):tessellation shader
- **OpenGL 4.3**(2012):compute shader
- **OpenGL 4.6**(2017):最新,现代特性完整

casey 的 HH 用 OpenGL 3.3+ core profile。这是现代 OpenGL 的最低标准。

### 11.2 Core vs Compatibility profile

**Core profile**:移除所有 deprecated 功能。必须用 VAO、VBO、shader。学习曲线陡,但高效。

**Compatibility profile**:保留 1.x 固定管线。简单,但不推荐新项目。

casey 选 core profile,因为:
- 学习现代 OpenGL 概念(VAO、shader)
- 性能更好(driver 优化 core)
- 跨平台一致(compatibility profile 在 Mac 不存在)

### 11.3 OpenGL ES

OpenGL ES 是嵌入式版本(手机、WebAssembly):

- ES 2.0(2007):基础 shader
- ES 3.0(2012):类似桌面 GL 3.3
- ES 3.2(2015):类似桌面 GL 4.x

如果你的游戏要发 WebAssembly,必须用 ES(浏览器只支持 WebGL,基于 ES)。

### 11.4 Vulkan / Direct3D 12 / Metal

现代 GPU API(Vulkan / D3D12 / Metal)更底层、更高效,但代码复杂:

- OpenGL:易用,但 driver overhead 大
- Vulkan:显式控制,极致性能,但 1000+ 行初始化
- D3D12:Windows only,类似 Vulkan
- Metal:Apple only,iOS / macOS 推荐

casey 用 OpenGL 因为易学。生产项目可以根据目标平台选 API。

### 11.5 Rust 的 GPU 生态

Rust 的 GPU 抽象:

- **glow**:OpenGL 跨平台 wrapper
- **wgpu**:基于 WebGPU,跨平台(Vulkan / Metal / D3D12 / WebGL)
- **vulkano**:Vulkan safe wrapper
- **ash**:Vulkan raw bindings
- **wgpu-core**:bevy 用的核心

casey 的 HH Rust 翻译版推荐 **wgpu**——现代、跨平台、安全。但 casey 教学用 OpenGL 因为概念更简单。

### 11.6 casey 用 OpenGL 的理由

casey 在 day235 选 OpenGL,理由:

1. **教学**:OpenGL 简单,易于讲解 GPU 概念
2. **跨平台**:Windows / Linux / macOS 都支持
3. **工具链成熟**:RenderDoc、Nsight 等支持好
4. **HH 项目规模**:不需要 Vulkan 的极致性能

casey 在 HH 视频里讨论过用 Direct3D vs OpenGL。最终选 OpenGL 因为跨平台(WebAssembly 友好)。

### 11.9 OpenGL 初始化的真实代码

完整的 Rust OpenGL 初始化代码(用 winit + glow):

```rust
use winit::window::WindowBuilder;
use winit::event_loop::EventLoop;
use glow::Context;

fn main() {
    let event_loop = EventLoop::new();
    let window = WindowBuilder::new()
        .with_title("Handmade Hero")
        .with_inner_size(winit::dpi::PhysicalSize::new(1280, 720))
        .build(&event_loop)
        .unwrap();
    
    // 创建 GL context(winit + glutin)
    let glutin_ctx = glutin::ContextBuilder::new()
        .with_vsync(true)
        .build_windowed(winit::window::WindowBuilder::new(), &event_loop)
        .unwrap();
    let glutin_ctx = unsafe { glutin_ctx.make_current().unwrap() };
    
    // 加载 GL 函数
    let gl = unsafe {
        Context::from_loader_function(|s| glutin_ctx.get_proc_address(s) as *const _)
    };
    
    // 设置初始 state
    unsafe {
        gl.viewport(0, 0, 1280, 720);
        gl.clear_color(0.0, 0.0, 0.0, 1.0);
    }
    
    // 主循环
    event_loop.run(move |event, target| {
        match event {
            winit::event::Event::MainEventsCleared => {
                unsafe {
                    gl.clear(glow::COLOR_BUFFER_BIT);
                }
                glutin_ctx.swap_buffers().unwrap();
                window.request_redraw();
            }
            winit::event::Event::WindowEvent { event, .. } => {
                if let winit::event::WindowEvent::CloseRequested = event {
                    target.exit();
                }
            }
            _ => {}
        }
    });
}
```

完整可运行的最小 OpenGL 程序。casey 的 HH Rust 翻译版从类似代码开始。
