# Day 191 · 实现环形菜单

> profiler 后端定型、状态清理完。今天 Casey 开始做 UI 的第一个组件:**环形菜单**(ring menu)。鼠标右键弹出,选项围绕鼠标呈圆形。这是 Casey 的 debug UI 风格签名之一。

## 0 · 为什么要有这一天

游戏 debug UI 不像桌面应用——你不能用一个固定菜单栏占屏幕顶部(遮挡游戏画面)。Casey 想要的体验:

- 不按任何键:UI 不可见,看纯游戏画面
- 按某键(或鼠标右键):**在鼠标位置**弹出菜单
- 选完菜单消失

这种"动态弹出 + 鼠标位置"的菜单叫 **pie menu / ring menu**。优点:

- 鼠标移动距离短(选项围绕鼠标,鼠标不动也能选)
- 视觉记忆(位置 = 功能,不读字)
- 不占永久屏幕空间

工业级例子:Photoshop 的右键菜单(虽然不是 pie)、Blender 的 pie menu、Maya 的 hotbox。

今天 Casey 实现最基础版:N 个选项围绕鼠标成圆环,鼠标移动到选项上高亮,点击选中。

心理锚点:看完今天,你能写"圆环上 N 个均匀分布的点的坐标"算法,并实现鼠标命中测试。

## 1 · Casey 今天做了什么

Casey 设计 ring menu:

1. 鼠标右键 down → 进入 menu 状态,记录鼠标位置(menu 中心)
2. UI 渲染时,在中心周围画 N 个扇形
3. 鼠标移动时,算鼠标相对中心的角度,定位到哪个扇形(highlight)
4. 鼠标右键 up → 选中 highlight 的扇形,触发回调,关闭菜单

他强调:**所有交互用 immediate-mode**——每帧重算,无持久 widget。

## 2 · 心智模型

### 类比:厨房的香料转盘

厨房有个圆形转盘,上面 8 个香料罐均匀分布。厨师伸手转一下,要哪个就转到面前。pie menu 一样:**功能围绕中心,鼠标"指"过去选**。

### 2.1 圆环上 N 等分点

```
N=6,半径 r,中心
角度 θ_i = i × 360/N 度(i=0..N-1)

点 i:
  x_i = cx + r × cos(θ_i)
  y_i = cy + r × sin(θ_i)
```

```rust
fn pie_menu_items(cx: f32, cy: f32, r: f32, n: usize) -> Vec<(f32, f32)> {
    (0..n).map(|i| {
        let angle = i as f32 * std::f32::consts::TAU / n as f32;
        (cx + r * angle.cos(), cy + r * angle.sin())
    }).collect()
}
```

**Rust 注释**:
- `std::f32::consts::TAU` — 2π,Rust 1.47+
- `i as f32 * TAU / n` — 等分角度
- `cos / sin` — 弧度制

### 2.2 鼠标命中测试

鼠标相对中心 (cx, cy) 的角度:

```rust
fn angle_to_center(mx: f32, my: f32, cx: f32, cy: f32) -> f32 {
    let dx = mx - cx;
    let dy = my - cy;
    dy.atan2(dx)  // 返回 -π..π
}
```

`atan2` 返回 [-π, π] 弧度,负数表示鼠标在中心下方/左侧。规范化到 [0, 2π):

```rust
fn angle_normalized(mx: f32, my: f32, cx: f32, cy: f32) -> f32 {
    let mut a = (my - cy).atan2(mx - cx);
    if a < 0.0 { a += std::f32::consts::TAU; }
    a
}
```

然后映射到扇形索引:`sector = (angle / TAU * n) as usize`。

```rust
fn pie_menu_sector(mx: f32, my: f32, cx: f32, cy: f32, n: usize) -> usize {
    let angle = angle_normalized(mx, my, cx, cy);
    ((angle / std::f32::consts::TAU) * n as f32) as usize % n
}
```

**注意**:鼠标**在中心**(dx=0, dy=0)时 `atan2(0, 0) = 0`,默认选第 0 扇形。Casey 加阈值——鼠标距离中心 < 5 像素时不选(允许"取消"——右键松开时不小心选了菜单)。

### 2.2.1 atan2 的精确语义

`atan2(y, x)` 不是 `atan(y / x)`。差别:

- `atan(y/x)`:x=0 时除零;x<0 时返回角度错(atan 只给 [-π/2, π/2])
- `atan2(y, x)`:接受两个参数,处理全部象限

```
atan2(1, 1)  = π/4   (第一象限,右上)
atan2(1, -1) = 3π/4  (第二象限,左上)
atan2(-1, -1)= -3π/4 (第三象限,左下)
atan2(-1, 1) = -π/4  (第四象限,右下)
atan2(0, 0)  = 0     (约定)
```

**性能**:atan2 在 x86_64 是 FPU 指令,~50 cycle。pie menu 每帧调一次,无影响。

### 2.2.2 pie menu 的视觉

每个扇形是 **pie slice**(扇形)。画扇形用三角形扇(filled triangle fan):

```rust
fn draw_pie_slice(fb: &mut FB, cx: i32, cy: i32, r: i32, start_angle: f32, end_angle: f32, color: u32) {
    let steps = 16;  // 用 16 个三角形近似扇形
    let mut prev = (cx + (r as f32 * start_angle.cos()) as i32,
                    cy + (r as f32 * start_angle.sin()) as i32);
    for i in 1..=steps {
        let t = i as f32 / steps as f32;
        let a = start_angle + (end_angle - start_angle) * t;
        let next = (cx + (r as f32 * a.cos()) as i32, cy + (r as f32 * a.sin()) as i32);
        draw_triangle_filled(fb, cx, cy, prev.0, prev.1, next.0, next.1, color);
        prev = next;
    }
}
```

16 步够圆滑(每段约 22.5°,人眼看不出折)。Steps 越多越圆,但耗 CPU。

鼠标位置,相对中心,角度:

```rust
fn angle_to_index(mx: f32, my: f32, cx: f32, cy: f32, n: usize) -> usize {
    let dx = mx - cx;
    let dy = my - cy;
    let angle = dy.atan2(dx);  // [-π, π]
    let normalized = if angle < 0.0 { angle + std::f32::consts::TAU } else { angle };
    // [0, TAU]
    let segment_size = std::f32::consts::TAU / n as f32;
    // 第 i 段对应 angle in [i*segment, (i+1)*segment)
    ((normalized / segment_size).floor() as usize) % n
}
```

**Rust 注释**:
- `atan2(y, x)` — 算 (x, y) 的极坐标角度,注意是 y,x 参数顺序
- `if angle < 0 { + TAU }` — 把 [-π, π] 归一到 [0, 2π]
- `% n` — 防止 angle 接近 TAU 时溢出

### 2.3 画扇形

每个扇形是一个"披萨片"。画法:从中心出发,沿圆弧描点,连回中心。

```rust
fn draw_pie_segment(
    fb: &mut Framebuffer,
    cx: i32, cy: i32, r: i32,
    start_angle: f32, end_angle: f32,
    color: u32,
) {
    // 中心到 start
    let x0 = cx + (r as f32 * start_angle.cos()) as i32;
    let y0 = cy + (r as f32 * start_angle.sin()) as i32;
    draw_line(fb, cx, cy, x0, y0, color);

    // 沿弧描 30 个点
    let steps = 30;
    for i in 0..steps {
        let t0 = start_angle + (end_angle - start_angle) * (i as f32 / steps as f32);
        let t1 = start_angle + (end_angle - start_angle) * ((i+1) as f32 / steps as f32);
        let x0 = cx + (r as f32 * t0.cos()) as i32;
        let y0 = cy + (r as f32 * t0.sin()) as i32;
        let x1 = cx + (r as f32 * t1.cos()) as i32;
        let y1 = cy + (r as f32 * t1.sin()) as i32;
        draw_line(fb, x0, y0, x1, y1, color);
    }

    // 中心到 end
    let x1 = cx + (r as f32 * end_angle.cos()) as i32;
    let y1 = cy + (r as f32 * end_angle.sin()) as i32;
    draw_line(fb, cx, cy, x1, y1, color);
}
```

### 2.4 状态管理

```rust
pub struct RingMenu {
    pub open: bool,
    pub center_x: f32,
    pub center_y: f32,
    pub items: Vec<&'static str>,
    pub hovered: Option<usize>,
}

impl RingMenu {
    pub fn open_at(&mut self, x: f32, y: f32) {
        self.open = true;
        self.center_x = x;
        self.center_y = y;
        self.hovered = None;
    }

    pub fn close(&mut self) {
        self.open = false;
    }

    pub fn update(&mut self, mouse_x: f32, mouse_y: f32) {
        if !self.open { return; }
        self.hovered = Some(angle_to_index(mouse_x, mouse_y, self.center_x, self.center_y, self.items.len()));
    }

    pub fn selected(&self) -> Option<usize> {
        if self.open { self.hovered } else { None }
    }
}
```

### 2.5 immediate-mode 集成

每帧调用:

```rust
fn frame(ui_state: &mut UiState, mouse: &Mouse, menu: &mut RingMenu) -> Option<usize> {
    if mouse.right_pressed && !menu.open {
        menu.open_at(mouse.x, mouse.y);
    }
    if mouse.right_released && menu.open {
        let sel = menu.selected();
        menu.close();
        return sel;
    }

    menu.update(mouse.x, mouse.y);

    if menu.open {
        draw_ring_menu(menu);
    }

    None
}
```

### 3.4 · 🐧 Linux 系统编程视角

Linux 桌面环境的 UI 工具栈,从底到顶是这套:内核 evdev(输入事件)→ libinput(输入归一化)→ Wayland compositor / X server(display server)→ toolkit(GTK / Qt / egui)→ 应用。每一层都为 UI 加抽象。

**evdev** 是内核的输入事件接口。键盘、鼠标、触摸屏的硬件事件,通过 `/dev/input/event*` 字符设备暴露。每个事件是 `struct input_event`——时间戳、类型(EV_KEY / EV_ABS / EV_REL)、code(BTN_LEFT / ABS_X)、value(0/1/2)。用户态进程读这个字符设备流,拿到原始硬件事件。

```bash
# 看 evdev 设备
sudo pacman -S evtest
sudo evtest /dev/input/event0   # 看你鼠标的事件流
# 移动鼠标、点击,看 event 输出
```

**libinput** 抽象 evdev——它处理多个设备、做去抖动、合成 tap-to-click、trackpad gesture、acceleration profile。toolkit 不直接读 evdev,而是用 libinput,这样跨设备统一。Casey HH 不用 libinput,直接用 SDL 的抽象,SDL 内部在 Linux 用 libinput。

**Wayland** 是现代 Linux display server 协议(替代 X11)。Wayland 用 `wl_seat` 协议传递输入事件给应用。应用注册 listener,Wayland server 把 pointer/keyboard event 推过来。Casey HH 用 SDL/winit,SDL/winit 内部在 Wayland 上对接 wl_seat。

**X11** 是 1980 年代的 display server,至今仍广泛用。X11 协议复杂(XCreateWindow、XMapWindow、XSelectInput、XNextEvent...),但它有 30+ 年的稳定 ABI。Wayland 替代 X11 的进程已 10+ 年,但仍未完成。

**GTK / Qt** 是 Linux 桌面两大 UI toolkit。GTK 用 C 写但支持多语言绑定;Qt 用 C++ 写也有多语言绑定。它们的 widget 系统、layout 系统、事件分发,是工业级 UI 实现的范本。Rust 的 gtk-rs 给 GTK Rust 绑定,qt-rs 给 Qt 绑定。

**systemd / D-Bus / XDG** 是 Linux 桌面的服务/IPC/规范层。systemd 管理服务,D-Bus 跨进程通信,XDG 规范桌面环境目录(`/usr/share/applications`、`~/.config`)。这些都和 UI 间接相关——你的应用通过 D-Bus 通知桌面,通过 XDG 找到图标资源。

**clipboards(X11 selection)** 是 Linux 跨进程 UI 的经典案例。Linux 有三个 selection:PRIMARY(选中即复制,中键粘贴)、CLIPBOARD(Ctrl+C / Ctrl+V)、SECONDARY(几乎没人用)。每个 selection 当前 owner 是某个窗口,数据存在 owner 进程。复制时数据**不立刻传给 server**,而是 owner 记录"我有这个 selection",target 窗口粘贴时向 owner 请求数据——这种延迟传输(称为 "selection transfer protocol")避免大数据复制两次。

```bash
# X11 看剪贴板 owner
xclip -o -selection clipboard
xclip -o -selection primary

# Wayland
wl-paste --primary

# 看 X11 clients
xlsclients
```

**fontconfig / freetype / harfbuzz / pango / cairo / pixman** 是 Linux 字体和渲染栈。fontconfig 找字体文件(/usr/share/fonts、~/.fonts),freetype 解析 TTF/OTF,harfbuzz 做 text shaping(组合字符、连字、复杂脚本如阿拉伯文),pango 把文字组织成 layout,cairo/pixman 把 layout 渲染成像素。这套栈在 1990-2010 年代由 Red Hat 主导开发,是 Linux 桌面的基础设施。Rust 的 piet、cosmic-text、swash 是新一代实现,但要追平这套栈还要多年。

**XKB / evdev** 处理键盘布局。XKB(X Keyboard Extension)是 X11 的键盘映射系统——你按物理键 KeyA,XKB 根据 layout(US / Dvorak / 中文)把它映射到 keysym(XK_a),toolkit 把 keysym 映射到字符 "a"。Wayland 用 `xkbcommon` 库,逻辑相同。

### 3.5 · 🦀 Rust 生态视角

Rust UI 生态在 2024 年是个活跃领域,有几十个库,各有取舍。

**`egui`** 是 immediate-mode UI 的事实标准。每帧重新声明 widget,API 简洁:

```rust
egui::CentralPanel::default().show(&ctx, |ui| {
    ui.heading("Debug");
    ui.separator();
    ui.horizontal(|ui| {
        ui.label("Speed:");
        ui.add(egui::Slider::new(&mut speed, 0.0..=10.0));
    });
    if ui.button("Reset").clicked() {
        speed = 5.0;
    }
});
```

egui 适合 debug UI、工具 UI、原型 UI——上手快、代码短。劣势是不适合发布 UI(无 accessibility、不够精美)。

**`iced`** 是 Elm 风格 UI——你写 model + update + view 三件套,框架处理 message 流。Iced 用 taffy layout 引擎,支持完整 flexbox。Iced 适合应用 UI(类浏览器、编辑器),代码结构清晰但比 egui 啰嗦。

**`tauri`** 是 web UI + Rust 后端。前端用 React/Vue/Svelte,后端用 Rust,通过 IPC 通信。Tauri 适合桌面应用——你享受 web 生态(NPM、CSS、HTML),但 binary 小、性能好(不嵌 Chromium,用系统 webview)。

**`slint`** 是商业 UI 框架,有自己的 DSL。Slint DSL 类似 QML:

```slint
export component MainWindow inherits Window {
    property <float> speed;
    Text { text: "Speed: " + speed; }
    Slider { value <=> speed; }
}
```

Slint DSL 编译成 Rust 代码,运行时零开销。Slint 适合嵌入式 UI(汽车仪表盘、家电面板)——binary 小、启动快、内存可控。

**`bevy_ui`** 是 Bevy ECS 的 UI 子系统。每个 widget 是 Entity,有 Component,系统遍历 Component 树渲染。这是 Rust 风格的 ECS UI——数据导向、cache 友好。Bevy UI 适合游戏内 UI(HUD、菜单)。

**`druid`** 已停止维护,但它的理念——data + lens + widget——影响了后来的库。Lens 是函数式编程的概念,让"嵌套数据的访问"变成可组合的 first-class value。

**`taffy`** 是 layout 引擎,被多个 UI 库共用。taffy 实现 CSS flexbox + grid spec,纯 Rust,性能极高(每帧 layout 10000 节点 < 1ms)。这是 Rust 在 UI 底层的杀手锏——同样功能 C++ 实现(Chrome Blink layout)慢 2-3 倍。

**`cosmic-text`** 是 Rust 的 text shaping + 布局引擎,由 System76 开发(用于 Pop!_OS COSMIC 桌面)。它整合了 Rust 的字体库(rustybuzz、swash、ab_glyph),提供完整文字渲染流水线。这是 Rust 替代 pango/freetype/harfbuzz 的尝试,目前可用。

**Rust 的 trait object vs monomorphization**。UI 库要支持任意 widget 类型,有两种方式:`Box<dyn Widget>`(trait object,动态分发)或 `impl Widget`(泛型,单态化)。egui 用 trait object(灵活)、iced 用泛型(性能)、bevy 用 ECS Component(数据导向)。每种方案的取舍反映在 API 设计上。

**Rust UI 的 accessibility**。Linux 的 AT-SPI(Assistive Technology Service Provider Interface)是 accessibility 标准——screen reader(Orca)通过 AT-SPI 朗读 UI 元素。Rust 的 `accesskit` crate 提供 UI accessibility 抽象,让 UI 库一次实现、跨平台(Linux AT-SPI / Windows UIA / macOS AXUIElement)。egui / iced / druid 都接 accesskit,这是 Rust UI 生态对 accessibility 的认真承诺。

**Rust 的 async UI**。iced 用 async,handler 是 async fn,处理事件可 await。Rust 的 async/await 让 UI 不阻塞——长时间任务(网络请求、文件 IO)async,UI thread 继续响应。这是 Rust UI 比 JS UI 优势的地方——零成本异步,不是单线程事件循环。


### 3.6 · 🐧 Linux 系统编程视角(perf / ftrace / eBPF)

Linux 内核自带一整套 profiling 基础设施,工业 Linux 性能分析的所有工具都基于它。理解这套设施能让你看 Casey 的 profiler 处于什么位置。

**perf** 是 Linux 内核的标准 profiling 接口。`perf record ./my_game` 跑游戏,perf 通过 `perf_event_open(2)` 系统调用,让内核每隔 N 个 CPU cycle 采样一次指令指针(IP)。采到 N 万个样本后,`perf report` 显示每个函数被采到多少次——按比例还原 CPU 时间分布。这是**统计 sampling**——不记录每次调用,而是按概率采样。

```bash
# 在 Arch 上跑 perf(需要内核 CONFIG_PERF_EVENTS=y,默认开)
sudo pacman -S perf
sudo perf record ./target/release/my_game
sudo perf report --stdio | head -30
# 输出形如:
#   35.00%  my_game  my_game         [.] update_physics
#   18.00%  my_game  my_game         [.] render_geometry
#    8.00%  my_game  libc-2.31.so    [.] memcpy
```

**perf 的两种模式**:
- **Sample-based**:每 N cycle 采样,适合找 hot spot。优点开销小(1% CPU),缺点错过短函数。
- **Trace-based**:每次事件都记录,精确。Casey HH 的 profiler 是 trace-based——每条 begin/end event 都记,精确度高但开销大(~5% CPU)。

**ftrace** 是内核函数级 trace。`/sys/kernel/debug/tracing/` 暴露 trace 点:

```bash
# 启用 sched_switch trace
echo sched_switch > /sys/kernel/debug/tracing/set_event
echo 1 > /sys/kernel/debug/tracing/tracing_on
# 等几秒
cat /sys/kernel/debug/tracing/trace | head
# 看每个 context switch
```

ftrace 是内核 hook——你 enable `sched_switch`,内核每次 context switch 都写一条记录到 ring buffer。这就是 Casey HH profiler 的"内核版"——同样的 ring buffer 数据结构,同样的"事件流"思维。

**eBPF** 是 Linux 内核的革命性技术。eBPF 让你在内核运行安全的 bytecode,自定义 profiling / monitoring 逻辑。eBPF 程序用 C 子集写,编译成 BPF bytecode,加载到内核 hook 点(系统调用、网络包、trace point)。这是内核版"插件"——比 ftrace 灵活,比内核模块安全。

```bash
# 用 bpftrace 做 profiling
sudo pacman -S bpftrace
sudo bpftrace -e 'profile:hz:99 @[stack] = count();'
# 每秒采样 99 次,记录 call stack
```

**bpftrace** 一个脚本 = 一个 profiler。你可以一分钟内写"统计 malloc 调用"、"看哪个进程 IO 最多"、"找 page fault 来源"——这是 Linux 性能分析的现代化武器。

**/proc/[pid]/stat / status / maps** 暴露进程运行时状态:

```bash
# 看你当前进程的 stat(进程的运行时统计)
cat /proc/$$/stat
# 第 14 字段:utime(user CPU time)
# 第 15 字段:stime(kernel CPU time)

# 看 memory mapping
cat /proc/$$/maps
# 输出:地址范围 权限 偏移 设备 inode 文件名
```

工业 profiler 读这些文件得到 cross-process 信息。Casey HH 的 profiler 是 in-process 的(只看自己),不读 /proc——这简化了实现,但看不到 OS 视角。

**Tracy / OPTICK / Superluminal** 是工业 C++ profiler,都用类似架构:ring buffer + thread-local + sample/trace 混合。Tracy 是开源,有 WebSocket UI 跨机器查看;Superluminal 是商业,以"超低 overhead + 时间线视图"著名。Casey HH 的 profiler 简化,但**架构相同**——理解 Casey 的,你就懂了 Tracy 的核心。

### 3.7 · 🦀 Rust 生态视角

Rust 的 profiling 生态有几条主线。

**`tracing` crate** 是 Rust 应用的事实标准 logging / tracing 框架。它结合了 log(级别)和 OpenTracing(span):

```rust
use tracing::{span, info, instrument};

#[instrument]
fn update_physics(dt: f32) {
    // tracing 自动在函数 entry/exit 创建 span
    info!(dt, "physics step");
}

let _span = span!(tracing::Level::INFO, "frame").entered();
update_physics(0.016);
```

`#[instrument]` 是 derive macro——编译时生成 span 创建/退出代码。`tracing` 的 subscriber 决定如何处理 span——log 到文件、发到 tracing UI、profile 等。

**`tracing-tracy`** crate 把 tracing span 转成 Tracy 协议事件。你的 Rust 应用加 tracing + tracing-tracy,就能用 Tracy UI 看 profile。这是 Rust 生态接工业 profiler 的标准方式。

**`puffin`** 是 Rust-native profiler,immediate-mode UI 风格,专为游戏设计:

```rust
puffin::profile_scope!("physics");
update_physics(dt);
// 自动 entry/exit

// 在 egui UI 里
puffin_egui::profiler_window(egui_ctx);
```

puffin 的设计哲学和 Casey HH profiler 几乎一致——in-process、ring buffer、immediate-mode UI。Puffin 是开源,代码可读,是看"Rust 风格 profiler"的范本。

**`measureme`** 是 rustc 用的 profiler,分析 rustc 自己的编译性能。measureme 的设计原则是"低 overhead + 可序列化 + 跨工具分析"——Rust 团队用它优化 rustc。

**Rust 的 `Instant`** 是 std 提供的高精度计时器:

```rust
let start = std::time::Instant::now();
expensive_op();
let elapsed = start.elapsed();
// elapsed 是 Duration,纳秒精度
```

底层在 Linux 是 `clock_gettime(CLOCK_MONOTONIC)`,Windows 是 `QueryPerformanceCounter`,macOS 是 `mach_absolute_time`。这是跨平台高精度时间的标准答案。Casey HH 在不同平台用不同 API(Linux rdtsc、Windows QPC、macOS mach),用 Rust 应该用 `Instant` 抽象。

**Rust 的 atomic 计数**。profiler 多线程时,event push 可能从多个线程同时来。用 `Arc<Mutex<Profiler>`> 是简单方案,但有锁开销。Rust 的 `crossbeam-queue` 提供 lock-free queue,适合高并发 event push。或者用 thread-local buffer + 定期 flush,完全无锁。Tracy 用 thread-local buffer,每线程独立,profiler thread 用 lock-free merge 合并。

**Rust SIMD** 可以加速 collation。如果有 100 万 event 要 collate,用 SIMD(`std::simd` 或 `wide` crate)一次处理 4-8 条 event,duration 计算用 SIMD 减法 + 累加。Tracy 在 collation hot loop 用 AVX2 优化。Rust 的 SIMD 还在稳定化中(unstable `std::simd`),但 `wide` crate 提供稳定的 wrapper。

**Rust 的 `Bytes` / `Arc<[u8]>`** 让 event buffer 零拷贝共享。如果 event buffer 要被 UI thread 读取(同时被游戏 thread 写),用 `Bytes` 引用计数——读 thread 拷贝 Arc,写 thread 替换 Arc 指向新 buffer。这是 lock-free 数据交换的标准模式。

**Rust profiler 的内存安全优势**。C/C++ profiler 大量 ring buffer + 原子操作,容易写错(数据竞争、use-after-free)。Rust 的 borrow checker + Send/Sync + atomic API 让这些错误编译时被捕获。Puffin / measureme 的代码,你可以放心读——Rust 保证内存安全。

## 5 · 对照与变奏

pie menu 的变体:
- **Traditional pie**:N 个等分扇形(Casey)
- **Marking menu**:鼠标画手势(方向)选——Maya 风格
- **Radial menu**:同心圆层级菜单——更多选项
- **Flower menu**:扇形大小不等(常用的大)

**pie menu vs 传统下拉菜单的 UX 对比**:

| 维度 | pie menu | 下拉菜单 |
|---|---|---|
| 鼠标移动距离 | 短(原地) | 长(到下拉项) |
| 视觉搜索时间 | 快(位置记忆) | 慢(读字) |
| 选项数限制 | 4-12(更多需分页) | 无限(滚动) |
| 层级支持 | 弱(嵌套难) | 强(子菜单) |
| 学习曲线 | 高(位置记忆) | 低(读字即可) |

pie menu 适合**高频 + 固定选项**(Photoshop 工具),下拉菜单适合**低频 + 多选项**(File 菜单)。

**参考解答**:

```rust
fn angle_to_index(mx: f32, my: f32, cx: f32, cy: f32, n: usize) -> usize {
    let dx = mx - cx;
    let dy = my - cy;
    let angle = dy.atan2(dx);
    let normalized = if angle < 0.0 { angle + std::f32::consts::TAU } else { angle };
    let seg = std::f32::consts::TAU / n as f32;
    ((normalized / seg).floor() as usize) % n
}

fn main() {
    let n = 6;
    let (cx, cy) = (100.0f32, 100.0f32);

    // 测右方向(angle=0):item 0
    assert_eq!(angle_to_index(150.0, 100.0, cx, cy, n), 0);
    // 测下方向(angle=π/3):item 1
    let r = 50.0;
    let angle = std::f32::consts::TAU / 6.0;
    let test_x = cx + r * angle.cos();
    let test_y = cy + r * angle.sin();
    assert_eq!(angle_to_index(test_x, test_y, cx, cy, n), 1);
    // 测反向(angle=π):item 3
    assert_eq!(angle_to_index(cx - 50.0, cy, cx, cy, n), 3);

    println!("OK");
}
```

## 8 · Rust / Arch 落地代码

完整可跑(扩展 Lv2,带 draw):

```rust
const W: usize = 400;
const H: usize = 400;

struct Framebuffer { pixels: Vec<u32> }
impl Framebuffer {
    fn new() -> Self { Self { pixels: vec![0xFF000000; W * H] } }
    fn set(&mut self, x: i32, y: i32, c: u32) {
        if x >= 0 && y >= 0 && (x as usize) < W && (y as usize) < H {
            self.pixels[(y as usize) * W + (x as usize)] = c;
        }
    }
    fn save_ppm(&self, path: &str) -> std::io::Result<()> {
        use std::io::Write;
        let mut f = std::fs::File::create(path)?;
        writeln!(f, "P3\n{} {}\n255", W, H)?;
        for p in &self.pixels {
            writeln!(f, "{} {} {}", (p >> 16) & 0xFF, (p >> 8) & 0xFF, p & 0xFF)?;
        }
        Ok(())
    }
}

fn draw_line(fb: &mut Framebuffer, x0: i32, y0: i32, x1: i32, y1: i32, c: u32) {
    let (mut x, mut y) = (x0, y0);
    let dx = (x1 - x0).abs();
    let sx = if x0 < x1 { 1 } else { -1 };
    let dy = -(y1 - y0).abs();
    let sy = if y0 < y1 { 1 } else { -1 };
    let mut err = dx + dy;
    loop {
        fb.set(x, y, c);
        if x == x1 && y == y1 { break; }
        let e2 = 2 * err;
        if e2 >= dy { err += dy; x += sx; }
        if e2 <= dx { err += dx; y += sy; }
    }
}

fn draw_pie(fb: &mut Framebuffer, cx: i32, cy: i32, r: i32, n: usize, c: u32) {
    // 画圆弧
    let steps = 60;
    for i in 0..steps {
        let t0 = (i as f32 / steps as f32) * std::f32::consts::TAU;
        let t1 = ((i+1) as f32 / steps as f32) * std::f32::consts::TAU;
        let x0 = cx + (r as f32 * t0.cos()) as i32;
        let y0 = cy + (r as f32 * t0.sin()) as i32;
        let x1 = cx + (r as f32 * t1.cos()) as i32;
        let y1 = cy + (r as f32 * t1.sin()) as i32;
        draw_line(fb, x0, y0, x1, y1, c);
    }
    // 画径向线(分扇形)
    for i in 0..n {
        let angle = (i as f32 / n as f32) * std::f32::consts::TAU;
        let x = cx + (r as f32 * angle.cos()) as i32;
        let y = cy + (r as f32 * angle.sin()) as i32;
        draw_line(fb, cx, cy, x, y, 0xFF888888);
    }
}

fn main() {
    let mut fb = Framebuffer::new();
    let cx = 200;
    let cy = 200;
    draw_pie(&mut fb, cx, cy, 100, 6, 0xFFFFFF00);
    fb.save_ppm("/tmp/pie.ppm").unwrap();
    println!("saved /tmp/pie.ppm");
}
```
