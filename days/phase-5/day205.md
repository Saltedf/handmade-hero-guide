
# Day 205 · 用鼠标拾取实体

> Day 204 加了反投影,今天 Casey 把它用起来:鼠标点击屏幕 → 反投影到世界 → 找最近实体 → 在 UI 里显示该实体所有字段。

## 0 · 为什么要有这一天

让我们把镜头拉到一个具体的开发场景。

你跟着 HH 走到 Day 204。你的游戏有一堆 entity——玩家、敌人、NPC、子弹、道具。每个 entity 有几十个字段:位置、速度、HP、AI 状态、动画帧、碰撞半径、所属阵营、技能列表。开发时你**经常**需要看某个 entity 的所有数据。

**没有 picking 之前**:你在 debug overlay 里手写"列出所有 entity 的 ID",看 ID 列表,选一个输 1,看那个 entity 的字段。再选下一个输 2。这种方式慢、不直观,而且**没有视觉关联**——你看到 entity 5 的 HP 是 80,但你不知道 entity 5 在地图上的哪个位置。

**有了 picking 之后**:你直接鼠标点屏幕上的怪物,debug UI 立刻显示"你选了 monster_3,HP 80,位置 (200, 150),AI 状态:追击玩家"。**视觉和数据立刻关联**——你看着屏幕上的怪物,UI 显示它的字段,所见即所查。

这是工业级游戏 debug 工具的标配。Unity Inspector、Unreal Actor Details、Blender Outliner 都基于 picking——点选一个对象,详细查看。

**为什么这件事不平凡?**

技术上,"鼠标选实体"涉及一个完整 pipeline:

1. **输入处理**:鼠标点击产生屏幕坐标事件
2. **反投影**(Day 204):屏幕坐标 → 世界坐标
3. **空间查询**:在世界坐标周围找最近的 entity
4. **状态管理**:记住"当前选中的 entity",跨帧持久化
5. **UI 反馈**:inspector 显示选中 entity 的数据;渲染时高亮它

每一步都有坑。**反投影**错了,鼠标点的不是你以为的位置。**空间查询**的"最近"如果用 sqrt(距离) 而非距离平方,性能差 5x。**状态管理**忘了清空,entity 删除后 inspector 还显示它的旧数据(Ghost entity)。**UI 反馈**忘了高亮,玩家无法视觉确认选中了谁。

今天 Casey 把这整个 pipeline 串起来。Day 206 加 introspection(自动枚举字段),Day 207 加字段编辑——这样你最终能"点选 entity,看所有字段,改任何字段",像 Unity Inspector 一样。

**学完今天,你应该能**:
- 写出 pick_entity 算法,找鼠标最近的 entity
- 解释为什么用 `dist² < threshold²` 而非 `sqrt(dist²) < threshold`(避免 sqrt)
- 处理"entity 被删除后 selection 失效"的边界
- 设计扩展:框选(多个 entity)、shift 加选、ctrl 反选
- 看懂 Unity Editor / Unreal Editor 的 selection 系统在做什么
- 知道 N=1000 时用线性扫描,N=10000 时换 quadtree / BVH

## 1 · Casey 今天做了什么

Casey 这一天串起 picking pipeline:

1. **维护 selected_entity 状态**。GameState 加 `selected: Option<EntityId>` 字段,跨帧记住选中谁。

2. **鼠标点击 handler**。鼠标按下时,先反投影到世界坐标,然后调 `pick_entity(world, mouse_world)` 找最近的 entity。命中就更新 `selected`。

3. **pick_entity 算法**。线性扫描所有 entity,算鼠标到 entity 中心的距离平方。如果距离 < entity.radius + threshold,记为候选。最后选最近的(dist² 最小)。

4. **inspector UI**。每帧看 `selected`,如果 Some(id) 就找那个 entity 的所有字段,显示在 debug overlay 上。如果 None 显示 "(nothing selected)"。

5. **高亮渲染**。render 阶段,如果 entity 的 id == selected,画一个高亮颜色(黄色 outline / 不同 sprite)。让玩家视觉确认选中谁。

6. **失效处理**。如果 selected 的 entity 被删除(游戏逻辑清场、entity 死亡),自动清空 selected——下一帧 inspector 显示 "(nothing selected)"。

这集产出几十行新代码,但解锁了"鼠标点选 → 详细查看"的核心能力。

## 2 · 心智模型

### 2.1 费曼类比:地图上的 POI 详情卡

想象 Google 地图。地图上有许多 POI(point of interest)——餐厅、加油站、景点。每个 POI 在地图坐标有位置。

你点击屏幕上一个 POI 图标。背后发生什么?

1. 你点屏幕坐标 (640, 360)
2. Google 把屏幕坐标反投影成经纬度(39.9, 116.4)
3. Google 查数据库:"在 (39.9, 116.4) 附近的 POI",找最近的"天安门"
4. 弹出详情卡:名字、地址、营业时间、评分

游戏 entity picking 一模一样:
1. 玩家点屏幕坐标
2. 反投影到世界坐标
3. 在世界坐标附近找最近的 entity
4. UI inspector 显示那个 entity 的所有字段

唯一的区别:Google 地图的 POI 是静态的(存数据库),游戏的 entity 是动态的(每帧位置变)。但 picking 算法相同——**找鼠标位置最近的、在范围内的对象**。

这个类比的关键洞察:picking 的本质是**空间查询(spatial query)**。"哪些 entity 在这个点附近"——这是地理信息系统(GIS)、数据库、物理引擎的通用问题。

### 2.2 从零推导 pick_entity 算法

让我们一步步推。

**Step 0:精确点击**。鼠标必须点中 entity 的中心点才算选中。

```rust
fn pick_entity_precise(entities: &[Entity], mouse: Vec2) -> Option<u32> {
    for e in entities {
        if e.pos.x == mouse.x && e.pos.y == mouse.y {
            return Some(e.id);
        }
    }
    None
}
```

这个方案实际不可用——鼠标几乎不可能精确点到 entity 中心(f32 相等比较),玩家会 frustration。

**Step 1:在范围内**。点中 entity 半径内即可。

```rust
fn pick_entity_in_radius(entities: &[Entity], mouse: Vec2) -> Option<u32> {
    for e in entities {
        let dx = e.pos.x - mouse.x;
        let dy = e.pos.y - mouse.y;
        let dist = (dx * dx + dy * dy).sqrt();
        if dist < e.radius {
            return Some(e.id);
        }
    }
    None
}
```

问题:多个 entity 都在范围内时,选谁?当前算法返回"第一个找到的",不稳定。

**Step 2:选最近的**。如果多个候选,选最近的。

```rust
fn pick_entity_nearest(entities: &[Entity], mouse: Vec2) -> Option<u32> {
    let mut best: Option<(u32, f32)> = None;
    for e in entities {
        let dx = e.pos.x - mouse.x;
        let dy = e.pos.y - mouse.y;
        let dist = (dx * dx + dy * dy).sqrt();
        if dist < e.radius {
            if best.map(|(_, d)| dist < d).unwrap_or(true) {
                best = Some((e.id, dist));
            }
        }
    }
    best.map(|(id, _)| id)
}
```

每次算 sqrt 慢。能否避免?

**Step 3:用距离平方代替距离**。dist² 和 dist 都是单调递增函数(`dist² < threshold²` ⇔ `dist < threshold`)。比较时不需要算 sqrt。

```rust
fn pick_entity_dist_sq(entities: &[Entity], mouse: Vec2) -> Option<u32> {
    let mut best: Option<(u32, f32)> = None;
    for e in entities {
        let dx = e.pos.x - mouse.x;
        let dy = e.pos.y - mouse.y;
        let dist_sq = dx * dx + dy * dy;  // 不 sqrt
        let r = e.radius;
        if dist_sq < r * r {  // 比较 dist² < r²
            if best.map(|(_, d)| dist_sq < d).unwrap_or(true) {
                best = Some((e.id, dist_sq));
            }
        }
    }
    best.map(|(id, _)| id)
}
```

**性能差异**:sqrt 大约 20 cycle,比较是 1 cycle。N=1000 时,每帧省 19000 cycle,即 ~6μs。看起来小,但热路径里累加。

**Step 4:加 user-friendly threshold**。鼠标点击精度有限,即便玩家瞄准了 entity 边缘也可能 miss。加一个 max_dist 容差:

```rust
fn pick_entity(entities: &[Entity], mouse: Vec2, max_dist: f32) -> Option<u32> {
    let mut best: Option<(u32, f32)> = None;
    for e in entities {
        let dx = e.pos.x - mouse.x;
        let dy = e.pos.y - mouse.y;
        let dist_sq = dx * dx + dy * dy;
        let threshold = e.radius + max_dist;  // 容差
        if dist_sq < threshold * threshold {
            if best.map(|(_, d)| dist_sq < d).unwrap_or(true) {
                best = Some((e.id, dist_sq));
            }
        }
    }
    best.map(|(id, _)| id)
}
```

这就是 Casey 的最终方案。**简单、正确、性能合理**。

### 2.3 什么时候需要空间索引?

N=100 时,线性扫描每帧 ~1μs,完全可忽略。
N=1000 时,~10μs,可接受。
N=10000 时,~100μs,占 frame budget 大头(60 FPS 下 16ms 的 0.6%)。
N=100000 时,~1ms,开始影响性能。

工业级游戏(RTS、MMO)经常有 N=10000+ entity。这时需要**空间索引**——把世界分成网格,查询只扫鼠标所在网格的 entity。

**Quadtree**:2D 递归四分。查询 O(log N)。

```rust
struct Quadtree {
    bounds: Rect,
    entities: Vec<Entity>,
    children: Option<Box<[Quadtree; 4]>>,
}
```

**Octree**:3D 版 quadtree,八分。

**BVH**(Bounding Volume Hierarchy):hierarchical AABB。Ray tracing 必学。Intel Embree / NVIDIA RTX 都基于 BVH。

**Uniform grid**:把世界均匀分网格,每个网格存 entity 列表。查询只查鼠标所在网格 + 邻居网格。简单高效,适合均匀分布。

**KD-tree**:轴对齐分割。静态场景最优(构建慢,查询快)。

每种数据结构适合不同场景。Casey HH 用线性扫描(教学简化),工业项目用 quadtree / BVH。

### 2.4 selection state 的生命周期

`selected: Option<EntityId>` 是跨帧状态。它的生命周期有几个关键点:

**初始**:None。游戏开始没选任何 entity。

**点击命中**:鼠标点 entity,设为 Some(id)。

**点击空白**:鼠标点空地,设为 None。

**entity 删除**:如果 selected 的 entity 被删除,selection 失效。要清空。

```rust
fn update_selection(state: &mut GameState) {
    if let Some(id) = state.selected {
        // 检查 entity 是否还存在
        if !state.world.entities.iter().any(|e| e.id == id) {
            state.selected = None;  // 失效,清空
        }
    }
}
```

**entity 死亡**:怪物 HP 归零被移除。如果它被 selected,要清空。

**切换场景**:新关卡加载,所有 entity 删除。selection 要清空。

这些边界条件容易漏。Casey 在 HH 里特别强调"每帧 verify selected 的 entity 仍存在"。Unity / Unreal 的 selection 系统都做这件事——selected object 失效时 inspector 显示 "(null)"。

### 2.5 多选模式

工业级 picking 支持多种选择模式:

**Single click**:单击单选。点击不同 entity 切换 selection。
**Shift + click**:加选。点击新 entity 加到 selection set。
**Ctrl + click**:toggle 选。已选 → 取消,未选 → 加。
**Drag box**:鼠标拖出矩形,选矩形内所有 entity(框选)。
**Lasso**:鼠标画自由曲线,选曲线包围的 entity。

实现上,selection 变成 `HashSet<EntityId>` 而非 `Option<EntityId>`。Casey Day 205 只做 single click,但代码结构允许扩展。

### 2.6 拾取的"hit box" vs "visual"

UX 角度,hit box 通常比 visual 大——便于点中。Nintendo 设计指南推荐 hit box ≥ 44 像素(手指触控)。

```
实体 visual:圆形(半径 50 像素)
实体 hit box:更大圆形(半径 60 像素)
```

这样玩家"瞄准不太准"也能点中。手机游戏特别重要——手指触摸精度比鼠标差。

Casey Day 205 用 visual 当 hit box(简化),但留 hook 让游戏 dev 调整。

### 2.7 完整 picking pipeline

下面是 Casey 设计在 Rust 里的完整落地:

```rust
#[derive(Copy, Clone, Debug)]
pub struct Vec2 { pub x: f32, pub y: f32 }

#[derive(Clone, Debug)]
pub struct Entity {
    pub id: u32,
    pub pos: Vec2,
    pub radius: f32,
    pub hp: i32,
    pub kind: String,
}

pub struct World { pub entities: Vec<Entity> }

pub struct GameState {
    pub world: World,
    pub camera: Camera,
    pub selected: Option<u32>,
}

pub fn pick_entity(world: &World, mouse: Vec2, max_dist: f32) -> Option<u32> {
    let mut best: Option<(u32, f32)> = None;
    for e in &world.entities {
        let dx = e.pos.x - mouse.x;
        let dy = e.pos.y - mouse.y;
        let dist_sq = dx * dx + dy * dy;
        let threshold = e.radius + max_dist;
        if dist_sq < threshold * threshold {
            if best.map(|(_, d)| dist_sq < d).unwrap_or(true) {
                best = Some((e.id, dist_sq));
            }
        }
    }
    best.map(|(id, _)| id)
}

impl GameState {
    pub fn on_mouse_click(&mut self, mouse_screen: Vec2) {
        let mouse_world = self.camera.screen_to_world(mouse_screen);
        self.selected = pick_entity(&self.world, mouse_world, 10.0);
    }

    pub fn update(&mut self) {
        // 失效处理:selection 对应的 entity 已被删除
        if let Some(id) = self.selected {
            if !self.world.entities.iter().any(|e| e.id == id) {
                self.selected = None;
            }
        }
    }
}

fn draw_inspector(world: &World, selected: Option<u32>) {
    print!("Inspector: ");
    match selected {
        Some(id) => {
            if let Some(e) = world.entities.iter().find(|e| e.id == id) {
                println!("Entity {} ({}) pos=({:.0},{:.0}) hp={}",
                    e.id, e.kind, e.pos.x, e.pos.y, e.hp);
            } else {
                println!("(entity gone)");
            }
        }
        None => println!("(nothing selected)"),
    }
}
```

**关键观察**:
- `pick_entity` 是纯函数,只读 world。易于测试。
- `on_mouse_click` 串联反投影 + pick + update selection。状态变化最小。
- `update` 里的失效检查每帧执行,保证 selected 始终 valid 或 None。
- `draw_inspector` 只读 world 和 selected,不修改状态——pure rendering。

### 2.8 高亮选中的实体

渲染时,如果实体被选中,画一个高亮圆:

```rust
fn render_world(fb: &mut Framebuffer, world: &World, camera: &Camera, selected: Option<u32>) {
    for e in &world.entities {
        let screen = camera.world_to_screen(e.pos);
        let color = if Some(e.id) == selected {
            0xFFFFFF00  // 黄色高亮
        } else {
            0xFFFF0000  // 红色普通
        };
        draw_circle(fb, screen, e.radius * camera.zoom, color);
    }
}
```

**视觉反馈**对 picking UX 极重要——玩家看到黄色就知道选了谁,不会怀疑是不是漏点。

## 3 · 四域深入

### 3.1 · 🎮 游戏编程视角

游戏工业的 picking 实现各不相同,根据 entity 数和复杂度选。

**Unity Editor**:Editor 用 GPU picking——每个 object 渲染到 offscreen buffer 时分配唯一颜色,鼠标位置读像素。适合任意复杂 mesh。Inspector 显示选中 object 的所有 component。

**Unreal Editor**:用 ray casting + BVH。点击屏幕产生射线,与场景的 BVH 求交,最近 hit 的 actor 选中。Details panel 显示属性。

**Blender**:3D picking 用 ray casting + mesh triangle 精确求交。这是为什么 Blender 能"选 polygon 的单个面"——射线不只命中 bounding box,还精确命中 triangle。

**Maya**:同 Blender,射线 + triangle 精确。Maya 的 pick walk(arrow key 切换 neighbor)是层级 picking——选中后用方向键切到相邻 object。

**游戏内 picking(real-time)**:
- **StarCraft**:鼠标按下 → 拖动 → 释放,框选所有 unit。Box test 算法。
- **Diablo**:点击敌人攻击,点击地面走。两套 picking——entity pick + tile pick。
- **Sims**:点击家具交互。OBB picking(家具是矩形,可旋转)。
- **Legend of Zelda**:点击 NPC 对话。Simple radius test。

每个游戏的 picking 核心都是"鼠标 → 反投影 → 找最近",但细节(框选、OBB、tile、polygon)千差万别。

**Casey Day 205** 是最简单版——单 click,圆形 hit box,线性扫描。这是教学起点,后面 Day 206+ 扩展。

### 3.2 · 🐞 Debug 工具视角(本日核心域)

Debug 工具行业的 picking 标准做法是 **selected object 的 inspector**。这是 Casey 正在实现的。

**Unity Inspector**:选中 GameObject 后,Inspector 显示所有 component 及其字段。每个字段可编辑、有 type-aware UI(slider / color picker / object reference)。

**Unreal Details Panel**:类似 Unity Inspector,但更强大——支持 C++ 反射(UProperty)、live edit、batch edit。

**Blender Properties**:右键属性面板,显示选中 object 的所有 property。

**Visual Studio debugger**:虽然不是游戏工具,但 Debugger 的"Watch window"和 picking 同构——选中变量,查看 / 编辑值。

所有这些工具的核心 pipeline 一样:**用户选中 → 系统记住 selection → UI 渲染 selection 详情**。Casey 在 Day 205 实现的就是这个 pipeline 的最小版。

**工业 debug 工具的额外特性**:
- **Multi-select**:Shift+click 多选,Inspector 显示共通字段
- **Drag-edit**:拖 slider 实时改字段,游戏立刻反映(像 Casey 在 Day 202 的 GUID 表)
- **Undo/redo**:编辑字段后能撤销。Unity 用 serialize + snapshot 实现。
- **Copy/paste**:选中 A,Ctrl+C,选中 B,Ctrl+V,A 的字段复制到 B。
- **Pin**:把常用字段"钉"在面板顶部。

这些特性 Casey 后面 Day 206-207 逐步加。

### 3.3 · 🐧 Linux 系统编程视角

Linux 桌面的 picking 无处不在。

**Window manager**:鼠标点击屏幕,要确定"哪个窗口被点中"。Mutter (GNOME)、KWin (KDE) 用 stack-based picking——窗口按 z-order 叠加,从上到下找第一个包含鼠标点的窗口。

```bash
# 看当前鼠标位置和窗口
xdotool getmouselocation
# x:1234 y:567 screen:0 window:12345678
```

`window:12345678` 就是 picking 结果——鼠标在哪个窗口上。

**Widget tree**:GTK/Qt 的 widget 树 picking。点击 (x, y),递归从根 widget 开始找:
- 当前 widget 不包含点 → 跳过
- 当前 widget 包含点 → 递归 children
- 最深的 child 包含点 → 它是 picked widget

```c
// GTK 内部
GtkWidget* picked = gtk_widget_pick(root, x, y, GTK_PICK_DEFAULT);
```

**Wayland compositor**:compositor 决定鼠标在哪个 surface 上。Surface 可能来自不同进程(浏览器、终端、文件管理器),compositor 做 layer-based picking。

```bash
# 看 wayland compositor 的输入处理
busctl introspect org.freedesktop.wayland / \
    org.freedesktop.wayland.Compositor
```

**File manager**:文件图标也是 picking。点击文件图标选中,双击打开。Nautilus、Dolphin、Thunar 都用 similar picking。

Linux 桌面的 picking 本质和游戏一样——**从屏幕坐标 → 底层对象**。区别是 Linux 桌面 picking 的是 widget / window,游戏 picking 的是 world entity。

### 3.4 · 🦀 Rust 生态视角

Rust 的 picking 生态围绕 Bevy 展开。

**bevy_mod_picking**:社区维护的 Bevy picking 插件。支持各种 picking 后端(ray casting、sprite bounds、mesh triangle)。GitHub: https://github.com/aevyrie/bevy_mod_picking

```rust
use bevy_mod_picking::*;

app.add_plugins(DefaultPickingPlugins);

// 任何 entity 加 PickableTarget 就能被 pick
commands.entity(my_entity)
    .insert(PickableBundle::default());
```

**bevy_mod_raycast**:ray casting 插件。3D mesh 精确 picking。Day 71+ 3D 后用得上。

**Bevy Change Detection**:Bevy ECS 用 archetype-based storage,有特定组件的 entity 在内存中连续。picking query 高效 cache:

```rust
fn pick(
    mouse: Res<MouseWorld>,
    query: Query<(Entity, &Transform, &HitBox), Changed<HitBox>>,
) {
    for (e, t, hb) in query.iter() {
        if hb.contains(mouse.world - t.pos) {
            // picked e
        }
    }
}
```

`Changed<HitBox>` filter 只遍历变化的 component——cache 友好。

**Rust 空间索引库**:
- `rstar`:R*-tree,2D/3D,适合动态场景。
- `kd-tree`:KD-tree,适合静态场景。
- `octree`:八叉树,3D。
- `aqtree`:quadtree,2D。

**手写 vs 库**。Casey HH 手写 picking 算法(教学)。工业项目用 bevy_mod_picking + rstar。手写适合学习,库适合 production。

**反模式警告**:
- ❌ 用 `Vec<Entity>` + 线性扫描做 10000 entity picking——每帧 100μs,占 frame budget 大头。
- ❌ 用 `sqrt` 比较——慢 5x。
- ❌ selected state 不做失效检查——entity 删了 selection 还在,显示 ghost entity。
- ❌ selection 存指针(`Rc<RefCell<Entity>>`)——entity 删除后指针 dangling。

fn pick(
    mouse: Res<MouseWorld>,
    mut selected: ResMut<Selected>,
    query: Query<(Entity, &Transform, &HitBox)>,
) {
    for (e, t, hb) in query.iter() {
        if hb.contains(mouse.world - t.translation) {
            selected.0 = Some(e);
            return;
        }
    }
    selected.0 = None;
}

### 5.3 3D 拾取的复杂度

3D 中,鼠标是 **ray**(射线),要找射线和实体的交点:

```rust
struct Ray { origin: Vec3, dir: Vec3 }

fn ray_sphere_intersect(ray: &Ray, sphere: &Sphere) -> Option<f32> {
    let oc = ray.origin - sphere.center;
    let a = ray.dir.dot(ray.dir);
    let b = 2.0 * oc.dot(ray.dir);
    let c = oc.dot(oc) - sphere.radius * sphere.radius;
    let d = b * b - 4.0 * a * c;
    if d < 0.0 { return None; }
    let t = (-b - d.sqrt()) / (2.0 * a);
    if t > 0.0 { Some(t) } else { None }
}
```

球体相交是解析解(公式)。Mesh 相交要 BVH + triangle test,复杂得多。Ray tracing 整本书都讲这个。

Casey Day 71+ 进入 3D 后会用 ray casting。今天 2D 是预备课——理解 picking pipeline,3D 时算法变复杂但 pipeline 不变。

### 5.5 Spatial partitioning 深度比较

| 数据结构 | 构建 | 查询 | 适合 |
|---|---|---|---|
| 线性 Vec | O(1) | O(N) | < 1000 entity,静态或动态 |
| Uniform grid | O(N) | O(1) 平均 | 静态 + 均匀分布(粒子) |
| Quadtree | O(N log N) | O(log N) | 动态 2D |
| Octree | O(N log N) | O(log N) | 动态 3D |
| BVH | O(N log N) | O(log N) | Ray tracing,3D |
| KD-tree | O(N log² N) | O(log N) | 静态场景 |
| R-tree(rstar) | O(N log N) | O(log N) | GIS、动态 |
| Hash grid | O(N) | O(1) | 网游 MMO |

每种适合不同场景。Casey Day 205 用线性(简单),生产用 quadtree(BVH for 3D, rstar for Rust)。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么用 `dist² < threshold²` 而不是 `sqrt(dist²) < threshold`?

**参考解答**:

两者数学等价——dist² 是 dist 的单调函数(都 ≥ 0),所以 `dist² < threshold²` ⇔ `dist < threshold`。

性能差异:
- `sqrt`:CPU 指令大约 20 cycle(x86 `sqrtss`)
- `dist²`:两次 mul + 一次 add,大约 4 cycle
- `dist² < threshold²`:加一次 mul(threshold * threshold),5 cycle 总
- `sqrt(dist²) < threshold`:20 + 1 = 21 cycle

每实体比较一次,N=1000 时每帧省 16000 cycle ≈ 5μs。看起来小,但热路径里累加。

工程优化原则:**能用平方比较就别 sqrt**。这是 graphics 程序员的反射。

### Lv2 · 动手实践

**题**:实现 pick_entity,加 5 个实体,验证几个鼠标位置返回正确 id。

```rust
#[derive(Copy, Clone, Debug)]
pub struct Vec2 { pub x: f32, pub y: f32 }
impl Vec2 { pub fn new(x: f32, y: f32) -> Self { Self { x, y } } }

#[derive(Clone, Debug)]
pub struct Entity {
    pub id: u32,
    pub pos: Vec2,
    pub radius: f32,
}

pub fn pick_entity(entities: &[Entity], mouse: Vec2, max_dist: f32) -> Option<u32> {
    let mut best: Option<(u32, f32)> = None;
    for e in entities {
        let dx = e.pos.x - mouse.x;
        let dy = e.pos.y - mouse.y;
        let dist_sq = dx * dx + dy * dy;
        let threshold = e.radius + max_dist;
        if dist_sq < threshold * threshold {
            if best.map(|(_, d)| dist_sq < d).unwrap_or(true) {
                best = Some((e.id, dist_sq));
            }
        }
    }
    best.map(|(id, _)| id)
}

fn main() {
    let entities = vec![
        Entity { id: 1, pos: Vec2::new(0.0,   0.0),   radius: 5.0 },
        Entity { id: 2, pos: Vec2::new(10.0,  0.0),   radius: 5.0 },
        Entity { id: 3, pos: Vec2::new(20.0,  0.0),   radius: 5.0 },
        Entity { id: 4, pos: Vec2::new(0.0,   10.0),  radius: 5.0 },
        Entity { id: 5, pos: Vec2::new(100.0, 100.0), radius: 5.0 },
    ];

    // 测试 1:点 (1, 0),实体 1 最近(距离 1)
    assert_eq!(pick_entity(&entities, Vec2::new(1.0, 0.0), 3.0), Some(1));

    // 测试 2:点 (5, 0),实体 1 和 2 都在阈值(5)
    // 实体 1 距离 5,实体 2 距离 5——tie,选先找到的(entity 1)
    let result = pick_entity(&entities, Vec2::new(5.0, 0.0), 3.0);
    assert!(result == Some(1) || result == Some(2), "tie: {:?}", result);

    // 测试 3:点 (200, 200),无实体在范围内
    assert_eq!(pick_entity(&entities, Vec2::new(200.0, 200.0), 3.0), None);

    // 测试 4:点 (15, 0),实体 2 距离 5,实体 3 距离 5,选先找到的(entity 2)
    assert_eq!(pick_entity(&entities, Vec2::new(15.0, 0.0), 3.0), Some(2));

    println!("All picking tests passed!");
}
```

### Lv3 · 迁移设计(框选)

**题**:实现"框选"——鼠标拖出矩形,选中所有在矩形内的实体。

**设计思路**:

1. 鼠标按下记录 start_pos。
2. 拖动时实时计算 selection box(start_pos 到 current_mouse 的矩形)。
3. 释放时对所有 entity 做 AABB overlap 测试——entity 的 bounding box 和 selection box 重叠则选中。
4. 选中结果存 `Vec<EntityId>`。

**参考实现**:

```rust
#[derive(Copy, Clone, Debug)]
pub struct Rect { pub x: f32, pub y: f32, pub w: f32, pub h: f32 }

impl Rect {
    pub fn from_corners(a: Vec2, b: Vec2) -> Self {
        let x = a.x.min(b.x);
        let y = a.y.min(b.y);
        let w = (a.x - b.x).abs();
        let h = (a.y - b.y).abs();
        Rect { x, y, w, h }
    }

    pub fn contains(&self, p: Vec2) -> bool {
        p.x >= self.x && p.x <= self.x + self.w &&
        p.y >= self.y && p.y <= self.y + self.h
    }

    pub fn overlaps_circle(&self, center: Vec2, radius: f32) -> bool {
        // 找 rectangle 上离 center 最近的点
        let cx = center.x.clamp(self.x, self.x + self.w);
        let cy = center.y.clamp(self.y, self.y + self.h);
        let dx = center.x - cx;
        let dy = center.y - cy;
        (dx * dx + dy * dy) < radius * radius
    }
}

pub fn box_select(
    entities: &[Entity],
    start: Vec2, end: Vec2,
) -> Vec<u32> {
    let rect = Rect::from_corners(start, end);
    entities.iter()
        .filter(|e| rect.overlaps_circle(e.pos, e.radius))
        .map(|e| e.id)
        .collect()
}

fn main() {
    let entities = vec![
        Entity { id: 1, pos: Vec2::new(0.0,  0.0), radius: 1.0 },
        Entity { id: 2, pos: Vec2::new(10.0, 0.0), radius: 1.0 },
        Entity { id: 3, pos: Vec2::new(20.0, 0.0), radius: 1.0 },
        Entity { id: 4, pos: Vec2::new(0.0, 10.0), radius: 1.0 },
    ];

    // 框 (-5, -5) 到 (15, 5),应该选中 1, 2(实体 3 太远,4 在 y=10 不在框内)
    let selected = box_select(&entities, Vec2::new(-5.0, -5.0), Vec2::new(15.0, 5.0));
    assert!(selected.contains(&1));
    assert!(selected.contains(&2));
    assert!(!selected.contains(&3));
    assert!(!selected.contains(&4));
    println!("Box select test passed!");
}
```

**关键点**:
- `Rect::from_corners` 处理 start/end 顺序无关——鼠标从左上拖到右下,或从右下拖到左上,矩形一样。
- `overlaps_circle` 是 circle-vs-rectangle 测试。算法:找 rectangle 上离 circle center 最近的点,如果那个点在 circle 内,则 overlap。
- 选中多个 entity 时,inspector 显示共通字段(简化:只显示选中的数量 + 列表)。

#[derive(Copy, Clone, Debug)]
pub struct Vec2 { pub x: f32, pub y: f32 }
impl Vec2 { pub fn new(x: f32, y: f32) -> Self { Self { x, y } } }

pub struct Camera {
    pub pos: Vec2,
    pub zoom: f32,
    pub screen_size: Vec2,
}

impl Camera {
    pub fn screen_to_world(&self, screen: Vec2) -> Vec2 {
        Vec2::new(
            (screen.x - self.screen_size.x / 2.0) / self.zoom + self.pos.x,
            (screen.y - self.screen_size.y / 2.0) / self.zoom + self.pos.y,
        )
    }
}

#[derive(Clone, Debug)]
pub struct Entity {
    pub id: u32,
    pub pos: Vec2,
    pub radius: f32,
    pub name: &'static str,
    pub hp: i32,
}

pub struct World { pub entities: Vec<Entity> }

pub struct GameState {
    pub world: World,
    pub camera: Camera,
    pub selected: Option<u32>,
}

pub fn pick_entity(world: &World, mouse: Vec2, max_dist: f32) -> Option<u32> {
    let mut best: Option<(u32, f32)> = None;
    for e in &world.entities {
        let dx = e.pos.x - mouse.x;
        let dy = e.pos.y - mouse.y;
        let dist_sq = dx * dx + dy * dy;
        let threshold = e.radius + max_dist;
        if dist_sq < threshold * threshold {
            if best.map(|(_, d)| dist_sq < d).unwrap_or(true) {
                best = Some((e.id, dist_sq));
            }
        }
    }
    best.map(|(id, _)| id)
}

impl GameState {
    pub fn on_click(&mut self, screen_mouse: Vec2) {
        let world_mouse = self.camera.screen_to_world(screen_mouse);
        self.selected = pick_entity(&self.world, world_mouse, 10.0);
    }
}

fn main() {
    let mut state = GameState {
        world: World {
            entities: vec![
                Entity { id: 1, pos: Vec2::new(100.0, 100.0), radius: 20.0, name: "player", hp: 100 },
                Entity { id: 2, pos: Vec2::new(200.0, 100.0), radius: 20.0, name: "goblin", hp: 30 },
                Entity { id: 3, pos: Vec2::new(300.0, 100.0), radius: 20.0, name: "ogre",   hp: 80 },
            ],
        },
        camera: Camera {
            pos: Vec2::new(200.0, 100.0),
            zoom: 1.0,
            screen_size: Vec2::new(1280.0, 720.0),
        },
        selected: None,
    };

    // 模拟点击屏幕(640, 360)— 应该反投影到 (200, 100),即 goblin
    state.on_click(Vec2::new(640.0, 360.0));
    assert_eq!(state.selected, Some(2));
    println!("Click 1: selected = {:?}", state.selected);

    // 点击屏幕(800, 360)— 应该反投影到 (360, 100),接近 ogre
    state.on_click(Vec2::new(800.0, 360.0));
    assert_eq!(state.selected, Some(3));
    println!("Click 2: selected = {:?}", state.selected);

    // 点击空白
    state.on_click(Vec2::new(0.0, 0.0));
    assert_eq!(state.selected, None);
    println!("Click 3: selected = {:?}", state.selected);

    println!("All picking tests passed!");
}

### 8.3 Troubleshooting

**问题1**:pick 选错。
原因:`max_dist` 阈值太小,鼠标稍微偏一点就 miss。
修复:增大 max_dist(10.0 → 20.0)。或者用 entity.radius 当 threshold,不要额外 max_dist。

**问题2**:框选漏 entity。
原因:AABB 测试只测 entity 中心 vs selection box——entity 半径大时,中心在 box 外但 entity 仍 overlap box。
修复:用 `overlaps_circle` 而非 `contains`(已在上文 Lv3 答案实现)。

**问题3**:selected 显示 ghost entity。
原因:entity 删除后 selected 未清空。
修复:每帧 verify——`if !world.entities.iter().any(|e| e.id == id) { selected = None; }`。

**问题4**:picking 慢(N > 10000)。
诊断:profiler 显示 `pick_entity` 占 frame 时间 30%+。
修复:换 quadtree。`rstar` crate 直接可用。

**问题5**:高 DPI 屏幕上 pick 偏移。
诊断:点击屏幕坐标和反投影结果偏差几个像素。
修复:统一 logical vs physical 坐标。`window.scale_factor()` 乘 logical mouse。

### 8.4 性能基线

| N(entity 数) | 算法 | 时间 | 占 16ms 帧的 |
|---|---|---|---|
| 100 | 线性 | 100ns | 0.001% |
| 1000 | 线性 | 10μs | 0.06% |
| 10000 | 线性 | 100μs | 0.6% |
| 10000 | Quadtree | 1μs | 0.006% |
| 100000 | Quadtree | 10μs | 0.06% |

N=10000 是临界点——线性 100μs 还能接受但开始占 frame budget。N > 10000 必须用空间索引。
