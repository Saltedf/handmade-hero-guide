# Day 254 · 重新启用性能分析

> Day 253 你重新启用 4 个 debug UI。但 profiler(性能分析)功能还在禁用——切 OpenGL 时它坏了,timer 数据不准。今天 Casey 修复 + 启用 profiler,让你能精确测量 OpenGL 后各函数耗时。

## 0 · 为什么要有这一天

Day 177 你写了 `TIMED_BLOCK()` 宏 + rdtsc 计数器,记录每个函数的 cycle 数。Day 178 加线程安全,Day 181 改 log-based。

切到 OpenGL 后,profiler 数据**不对了**:

- `game_update` 显示 5ms,但实际帧时间 16ms(OpenGL draw call 异步,延迟到 GPU 完成才计入)
- 各个 draw 函数显示 0ms,因为 GL 命令只是 enqueue,不阻塞
- 总和加起来不到 16ms,但 FPS 只有 60

**根本原因**:rdtsc 测的是 CPU 时间,OpenGL 是异步的——你 enqueue 10 个 draw call,每个 1 微秒,CPU 看上去 10 微秒。但 GPU 还在跑,swap_buffers 时才阻塞等。

Day 254 Casey 加 **GPU timer query**——OpenGL 提供的 GPU 端计时,测量实际 GPU 耗时:

```rust
let query = gl.create_query();
gl.begin_query(glow::TIME_ELAPSED, query);
// ... draw calls ...
gl.end_query(glow::TIME_ELAPSED);
// 下一帧(异步):
let result = gl.get_query_object_u64(query, glow::QUERY_RESULT);
// result 是 GPU 实际跑这段命令的纳秒
```

CPU 时间 + GPU 时间两套一起看,完整 profile。

**心理锚点**:看完今天,你能精确测量"这个 draw call 在 GPU 跑了多久",定位 GPU 瓶颈。

## 2 · 心智模型

### 类比:厨房两个计时器

CPU 时间像厨师"我开始处理这道菜"的标记——记录厨师在做什么。
GPU 时间像烤箱"我烤这道菜用了多久"——记录烤箱实际工作时间。

两个不重叠:厨师 1 分钟准备食材,烤箱烤 10 分钟。总菜做好需要 11 分钟(假设烤箱不并行)。

游戏一样:CPU 准备 draw call 1ms,GPU 实际画 5ms。两个都要测。

### 2.1 OpenGL timer query

```rust
let query = unsafe { gl.create_query().unwrap() };

unsafe {
    gl.begin_query(glow::TIME_ELAPSED, Some(query));
    // ... 多个 draw calls ...
    gl.end_query(glow::TIME_ELAPSED);
}

// 此时 query 还没结果(GPU 还在跑)

// 下一帧检查
let mut available = 0;
unsafe {
    gl.get_query_object_iv(
        query,
        glow::QUERY_RESULT_AVAILABLE,
        std::slice::from_mut(&mut available),
    );
}

if available != 0 {
    let mut time_ns: u64 = 0;
    unsafe {
        gl.get_query_object_u64(
            query,
            glow::QUERY_RESULT,
            std::slice::from_mut(&mut time_ns),
        );
    }
    println!("GPU 时间: {} ns = {:.2} ms", time_ns, time_ns as f64 / 1_000_000.0);

    unsafe { gl.delete_query(query); }
}
```

**关键**:

- `begin_query` / `end_query` 标记 GPU 命令范围
- `QUERY_RESULT_AVAILABLE` 检查是否完成(异步)
- `QUERY_RESULT` 读结果(ns)

### 2.2 N-frame 延迟

像 Day 244 的 readback,query 也是异步。CPU 发 query,GPU 跑到了才 signaled。所以:

- Frame 0:begin_query / end_query / 提交 GPU 命令
- Frame 1:检查 Frame 0 query 完成没(通常完成),读结果
- Frame 2:如果 Frame 1 还没完成,继续等

N=2 帧延迟,基本无 stall。

### 2.3 多 query 池

每个测量点用一个 query,frame 末可能积累几十个 query。重复用:

```rust
pub struct QueryPool {
    queries: Vec<Query>,
    next: usize,
}

impl QueryPool {
    pub fn new(gl: &Context, n: usize) -> Self {
        let queries = (0..n).map(|_| unsafe {
            gl.create_query().unwrap()
        }).collect();
        Self { queries, next: 0 }
    }

    pub fn acquire(&mut self) -> Query {
        let q = self.queries[self.next];
        self.next = (self.next + 1) % self.queries.len();
        q
    }
}
```

每帧用 N 个 query,frame 末复位 next,循环用。

### 2.4 命名 query

每个测量点有名字("frame" / "draw_player" / "draw_enemies"):

```rust
pub struct NamedQuery {
    pub name: &'static str,
    pub query: Query,
    pub started: bool,
}

pub struct Profiler {
    pub pool: Vec<NamedQuery>,
}

impl Profiler {
    pub fn begin(&mut self, name: &'static str, gl: &Context) {
        let q = self.acquire();
        unsafe { gl.begin_query(glow::TIME_ELAPSED, Some(q)); }
        self.pool.push(NamedQuery { name, query: q, started: true });
    }

    pub fn end(&mut self, gl: &Context) {
        unsafe { gl.end_query(glow::TIME_ELAPSED); }
    }

    pub fn poll_results(&mut self, gl: &Context) -> Vec<(&'static str, u64)> {
        let mut results = vec![];
        for nq in &mut self.pool {
            if !nq.started { continue; }
            let mut avail = 0;
            unsafe {
                gl.get_query_object_iv(
                    nq.query, glow::QUERY_RESULT_AVAILABLE,
                    std::slice::from_mut(&mut avail),
                );
            }
            if avail != 0 {
                let mut ns: u64 = 0;
                unsafe {
                    gl.get_query_object_u64(
                        nq.query, glow::QUERY_RESULT,
                        std::slice::from_mut(&mut ns),
                    );
                }
                results.push((nq.name, ns));
                nq.started = false;
            }
        }
        results
    }
}
```

### 2.5 CPU + GPU 双重 profile

```rust
fn frame() {
    profiler_cpu.begin("frame_total");
    profiler_gpu.begin("frame_total_gpu", gl);

    profiler_cpu.begin("update");
    game_update(...);
    profiler_cpu.end();  // CPU 时间:game_update

    profiler_cpu.begin("render");
    opengl_render(...);
    profiler_cpu.end();  // CPU 时间:enqueue 命令

    profiler_gpu.end(gl);  // GPU query:整个 frame
    profiler_cpu.end();

    // 上一帧的 GPU 结果
    for (name, ns) in profiler_gpu.poll_results(gl) {
        println!("GPU {}: {:.2}ms", name, ns as f64 / 1e6);
    }

    for (name, cycles) in profiler_cpu.results() {
        let ms = cycles as f64 / 3_000_000_000.0 * 1000.0;  // 假设 3GHz
        println!("CPU {}: {:.2}ms", name, ms);
    }
}
```

输出:

```
GPU frame_total_gpu: 9.32 ms
CPU update: 2.10 ms
CPU render: 0.80 ms (enqueue)
CPU frame_total: 3.05 ms
```

3ms CPU + 9ms GPU,GPU 是瓶颈。优化 shader 而不是 game_update。

### 2.6 找瓶颈

profiler 显示 CPU 和 GPU 时间,**总和**才是帧时间:

```
frame_time = max(cpu_time, gpu_time) + overhead
```

通常 overhead < 1ms,所以:

- `cpu_time ≈ gpu_time` —— 平衡,任何一边优化都有效
- `cpu_time >> gpu_time` —— CPU-bound,优化 game_update / draw call 数
- `gpu_time >> cpu_time` —— GPU-bound,优化 shader / 减少像素 / 减少三角形

跟 HH 学的 2D 游戏通常 CPU-bound(大量 sprite 实体)。3D 游戏 GPU-bound。

### 3.2 · 🎨 图形学视角

**GPU 时间 ≠ CPU 时间** 的原因:

- **异步** —— GPU 命令 enqueue,CPU 立刻返回
- **并行** —— GPU 几千核,工作量大但 wall-clock 时间短
- **driver 开销** —— CPU 验证 / 转换命令,这部分是 CPU 时间

举例:

- CPU enqueue 1000 个 draw call,每个 10 微秒 CPU 时间
- GPU 跑 1000 个 draw call,每个 100 微秒 GPU 时间
- 总 CPU 时间:10ms(不阻塞)
- 总 GPU 时间:100ms(瓶颈)
- FPS:10(瓶颈在 GPU)

不加 GPU profile,你看 CPU 10ms 以为没事,实际 100ms GPU 拖累。

## 7 · 变式训练

### Lv1 · 概念辨析

**题**:为什么 GPU 时间和 CPU 时间不同步?如何同时测两个?

**参考解答**:CPU 调 `glDrawArrays` 是 enqueue 命令到 driver,GPU 在后台异步执行。CPU 立刻继续往下跑,所以 CPU 时间只反映"enqueue 多快",不是 GPU 实际多久。

同时测:

- CPU 时间:`rdtsc` 或 `Instant::now()` 包裹 CPU 代码
- GPU 时间:`glQuery(TIME_ELAPSED)` 包裹 GPU 命令
- 两者独立记录,profiler UI 同时显示

### Lv2 · 动手实践

**题**:在 Day 253 的 profiler overlay 里加 GPU 时间。完成标准:同时显示 CPU 帧时间 + GPU 帧时间,看两者是否平衡。

**参考解答**:

```rust
use glow::HasContext;

pub struct GpuProfiler {
    queries: Vec<<glow::Context as glow::HasContext>::Query>,
    results: Vec<(&'static str, u64)>,  // ns
    pending: Vec<(&'static str, <glow::Context as glow::HasContext>::Query)>,
}

impl GpuProfiler {
    pub fn new() -> Self {
        Self { queries: vec![], results: vec![], pending: vec![] }
    }

    pub fn begin(&mut self, gl: &glow::Context, name: &'static str) {
        let q = unsafe { gl.create_query().unwrap() };
        unsafe { gl.begin_query(glow::TIME_ELAPSED, Some(q)); }
        self.pending.push((name, q));
    }

    pub fn end(&mut self, gl: &glow::Context) {
        unsafe { gl.end_query(glow::TIME_ELAPSED); }
    }

    pub fn poll(&mut self, gl: &glow::Context) -> Vec<(&'static str, u64)> {
        let mut done = vec![];
        let mut still_pending = vec![];
        for (name, q) in self.pending.drain(..) {
            let mut avail = 0;
            unsafe {
                gl.get_query_object_iv(
                    q, glow::QUERY_RESULT_AVAILABLE,
                    std::slice::from_mut(&mut avail),
                );
            }
            if avail != 0 {
                let mut ns = 0u64;
                unsafe {
                    gl.get_query_object_u64(
                        q, glow::QUERY_RESULT,
                        std::slice::from_mut(&mut ns),
                    );
                    gl.delete_query(q);
                }
                done.push((name, ns));
            } else {
                still_pending.push((name, q));
            }
        }
        self.pending = still_pending;
        self.results.extend(done.iter().cloned());
        done
    }
}
```

## 8 · Rust / Arch 落地代码

### Rust 完整 CPU + GPU profiler

```rust
use glow::HasContext;
use std::time::Instant;

pub struct CpuProfiler {
    current: Vec<(&'static str, Instant)>,
    results: Vec<(&'static str, u64)>,  // ns
}

impl CpuProfiler {
    pub fn new() -> Self {
        Self { current: vec![], results: vec![] }
    }

    pub fn begin(&mut self, name: &'static str) {
        self.current.push((name, Instant::now()));
    }

    pub fn end(&mut self) {
        if let Some((name, start)) = self.current.pop() {
            let ns = start.elapsed().as_nanos() as u64;
            self.results.push((name, ns));
        }
    }

    pub fn drain_results(&mut self) -> Vec<(&'static str, u64)> {
        std::mem::take(&mut self.results)
    }
}

pub struct GpuProfiler {
    pending: Vec<(&'static str, <glow::Context as glow::HasContext>::Query)>,
    results: Vec<(&'static str, u64)>,
}

impl GpuProfiler {
    pub fn new() -> Self {
        Self { pending: vec![], results: vec![] }
    }

    pub fn begin(&mut self, gl: &glow::Context, name: &'static str) {
        let q = unsafe { gl.create_query().expect("create_query") };
        unsafe { gl.begin_query(glow::TIME_ELAPSED, Some(q)); }
        self.pending.push((name, q));
    }

    pub fn end(&mut self, gl: &glow::Context) {
        unsafe { gl.end_query(glow::TIME_ELAPSED); }
    }

    pub fn poll(&mut self, gl: &glow::Context) {
        let mut still = vec![];
        for (name, q) in self.pending.drain(..) {
            let mut avail = 0;
            unsafe {
                gl.get_query_object_iv(
                    q, glow::QUERY_RESULT_AVAILABLE,
                    std::slice::from_mut(&mut avail),
                );
            }
            if avail != 0 {
                let mut ns = 0u64;
                unsafe {
                    gl.get_query_object_u64(
                        q, glow::QUERY_RESULT,
                        std::slice::from_mut(&mut ns),
                    );
                    gl.delete_query(q);
                }
                self.results.push((name, ns));
            } else {
                still.push((name, q));
            }
        }
        self.pending = still;
    }

    pub fn drain_results(&mut self) -> Vec<(&'static str, u64)> {
        std::mem::take(&mut self.results)
    }
}

fn main() {
    // 简化:不真创建 GL context,只演示 API
    println!("=== 双 profiler 设计 ===");
    println!("CPU profiler:Instant::now() 包裹");
    println!("GPU profiler:glQuery(TIME_ELAPSED) 包裹");
    println!("\n典型输出:");
    println!("  CPU update:      2.1 ms");
    println!("  CPU draw enqueue: 0.8 ms");
    println!("  GPU frame total: 9.3 ms  ← 瓶颈");
    println!("  → 优化 GPU shader 而不是 game_update");
}
```
